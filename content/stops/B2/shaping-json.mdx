## What it is

Almost every automation and AI application moves data between apps, and that data almost always travels as **JSON** (JavaScript Object Notation): a text format apps use to exchange structured data. If you can read and reshape JSON, you can connect almost anything to anything.

JSON has three building blocks:

| Building block | Looks like | Example |
| --- | --- | --- |
| **Object** | Named fields in curly braces | A customer with name, phone and city |
| **Array** (list) | Items in square brackets | A list of order lines |
| **Value** | Text in quotes, a number, true or false, or null (empty) | "Mysuru", 2, true, null |

Objects and arrays nest inside each other. A payment webhook might contain an object for the payment, inside it an object for the customer, and inside that an array of notes.

```text
  order                         (object)
   |-- id: "ORD-88213"
   |-- customer                 (object)
   |     |-- name: "Nisha Rao"
   |     |-- phone: "9845012345"
   |     +-- email: null
   |-- lines                    (array)
   |     |-- [0] sku, qty, price
   |     +-- [1] sku, qty, price
   +-- shipping                 (object)
         |-- city: "Mysuru"
         +-- pin: "570001"
```

This lesson follows an online tea store's order webhook as it becomes rows in a dispatch sheet and an SMS to the customer. By the end you will be able to take an unfamiliar JSON payload and pull out exactly what a workflow needs.

## How it works

### Reading a path

To reach a nested field, follow the names from the outside in, joined by dots. Array items are numbered from **0** in square brackets.

| What you want | Path |
| --- | --- |
| The order id | `order.id` |
| The customer's phone | `order.customer.phone` |
| The first line's price | `order.lines[0].price` |
| The second line's SKU | `order.lines[1].sku` |
| The delivery PIN code | `order.shipping.pin` |

### Inspect real samples

Never guess a path from documentation alone. Trigger a real or test event and look at the exact JSON received. In n8n, the output panel shows each item as a table, as raw JSON or as a schema; use it to find the exact path and copy it.

### Pick and rename

Most workflows need only a handful of fields from a large payload. Use an "Edit Fields" or "Set" step to pick them and give them clear names: `customer_phone` instead of `payment.notes.contact_no`. Later steps become much easier to read and maintain.

### Lists to items, and back

If a field holds a list, such as order lines or attachments, **split** it so each element becomes its own item for later steps. Then each line can become its own sheet row. To go back, **aggregate** items into a single list.

```text
  1 item: order with lines [A, B]
           |
        split lines
           v
  2 items: {order id, line A}   {order id, line B}
           |
        one sheet row each
```

Keep the fields you still need, such as the order id and city, on every split item.

### Types

Values often arrive as the wrong type:

| Value received | Problem | Fix |
| --- | --- | --- |
| `"1,250.00"` | Text with a comma, not a number | Remove commas, then convert to a number |
| `"03/11/2026"` | Is it 3 November or 11 March? | Parse with the format the provider documents |
| `9845012345` as a number | Fine, but `0123` as a number loses its zero | Keep phone numbers, PIN codes and ids as text |
| `"true"` | Text, not true or false | Compare as text, or convert |

### Missing values

Fields may be absent or `null` for some records. Decide in advance: use a default, skip a step, or route the record to a person. "If `customer.email` is null, skip the email step and send an SMS instead" is a rule; a workflow that crashes is not.

### Building JSON for APIs and AI steps

When you send data to an API or an AI step, you build the exact shape it expects. A **JSON schema** describes that shape: which fields, their types and which are required. Check your output against the API's documentation, and for AI structured outputs, against the schema you give the model.

### Power tools

`jq` and JSONata are small languages for querying and reshaping JSON. Many automation tools support similar expressions. You do not need them to start, but they help with complicated payloads.

## A worked example

An online tea store in Bengaluru gets this webhook (shortened) when an order is placed:

```json
{
  "order": {
    "id": "ORD-88213",
    "created_at": "2026-11-03T10:42:00+05:30",
    "customer": { "name": "Nisha Rao", "phone": "9845012345", "email": null },
    "lines": [
      { "sku": "TEA-ASSAM-250", "qty": 2, "price": "349.00" },
      { "sku": "MUG-STEEL", "qty": 1, "price": "1,199.00" }
    ],
    "shipping": { "city": "Mysuru", "pin": "570001" }
  }
}
```

The goal: one row per order line in the dispatch sheet, and an SMS to the customer.

1. **Split** `order.lines` into items, keeping `order.id`, `customer.name`, `shipping.city` and `shipping.pin` on each.
2. **Convert** `price` from text to a number by removing commas, then compute line total = qty × price.
3. **Keep** `pin` as text, so "570001" stays exactly as it is.
4. **SMS:** use `customer.phone` with +91 added. Because `email` is `null`, skip the email step for this order.

The dispatch sheet gets two rows:

| Order | Customer | SKU | Qty | Price | Line total | City | PIN |
| --- | --- | --- | --- | --- | --- | --- | --- |
| ORD-88213 | Nisha Rao | TEA-ASSAM-250 | 2 | 349 | 698 | Mysuru | 570001 |
| ORD-88213 | Nisha Rao | MUG-STEEL | 1 | 1,199 | 1,199 | Mysuru | 570001 |

Before the conversion step, the second line's total showed as an error because "1,199.00" was text. Before the null check, the workflow failed for every customer without an email, about one order in five.

## Common mistakes

- **Guessing paths.** Inspect real samples and copy the exact path.
- **Assuming one item when there is a list.** Split lists into items.
- **Leaving numbers as text.** "1,199.00" will not add up until converted.
- **Dropping leading zeros.** Keep PIN codes, phone numbers and ids as text.
- **Failing on missing fields.** Plan for null and absent fields with a rule.
- **Forgetting the array starts at 0.** The first item is `[0]`, not `[1]`.
