## What it is

**n8n** (said "n-eight-n") is a workflow automation tool. You build automations on a visual canvas by connecting **nodes**. Each node does one thing: watch for a new email, read a spreadsheet, call an API, ask an AI model, send a message. Data flows from one node to the next.

It is like Zapier or Make, with two differences people value. You can **self-host** it on your own server, which keeps data in your hands and costs little at volume, and it has strong **AI nodes**, including an AI Agent node that can reason, use tools and remember a conversation.

**Workflow automation** is the business use: a small team gets hours back each week by letting software move data between the apps they already use.

```flow
Trigger: form enquiry | a webhook -> AI Agent | classify and draft a reply
Memory: past chats -> AI Agent
Model, prompt and tools -> AI Agent
AI Agent -> About fees?
About fees? -[yes]-> Sheet: log it -> Gmail: a draft for approval
About fees? -[no]-> Slack: alert the staff
```

## How it works

**Triggers start everything.** Common ones are a schedule (every day at 9 a.m.), a webhook (another app calls a URL), app triggers (new Gmail message, new row in Google Sheets) and a chat trigger for chatbots.

**Nodes do the work.** n8n has hundreds of integrations: Google Workspace, Slack, Notion, Airtable, HubSpot, databases, HTTP requests to any API, and WhatsApp through the official Business API. **Logic nodes** such as IF, Switch, Merge and Loop control the flow.

**Data moves as JSON.** Every node outputs items. Later nodes read them with **expressions** like `{{ $json.email }}`. You can see the exact data at each step, which makes debugging much easier than in code.

**AI nodes.** The AI Agent node combines a chat model (Claude, GPT, Gemini or a local model), a system prompt, **memory** and **tools**. Tools can be other nodes, such as "search this sheet" or "create a calendar event", so the agent can act, not just talk. There are also simpler nodes for classifying text, extracting fields into structured data, and summarising.

**Credentials** are stored once and reused, so API keys never sit inside workflows.

**Running it.** Use n8n Cloud to start quickly, or self-host with Docker on a small server. Test with sample data, then activate the workflow so it runs on its own.

| Building block | What it is for | Example |
|---|---|---|
| Schedule trigger | run at set times | daily sales summary at 8 a.m. |
| Webhook | react instantly to another app | payment gateway success event |
| HTTP Request | call any API | fetch exchange rates |
| IF / Switch | branch on conditions | route enquiries by type |
| AI Agent | reason and act with tools | answer FAQs using a price sheet |
| Information Extractor | turn text into fields | read amount and date from an invoice |
| Wait / approval | pause for a human | approve before a reply is sent |
| Error workflow | catch failures | alert on Slack when a run fails |

**Testing before you trust it.** n8n lets you run a workflow by hand, pin sample data to a trigger so every test uses the same input, and step through each node's output. Test with real-looking messy data: an enquiry in Hinglish, an empty field, an email with three attachments. Most automation bugs come from inputs nobody tried.

**Costs to watch.** Each AI step costs a small amount per call, and n8n Cloud plans limit how many workflow runs you get each month. Check the current limits and model prices on the providers' sites before you promise a client a monthly cost.

## A worked example

Arvind runs a coaching institute in Jaipur with 600 students. Enquiries arrive through a Google Form at all hours, and the front desk replies the next day, by which time many parents have called a competitor.

He builds one workflow in an afternoon:

1. **Google Forms trigger** on every new enquiry.
2. **AI Agent** with a prompt containing the batch timings, fees and demo-class schedule. It classifies the enquiry as fees, timings, demo or other, and drafts a reply in the language the parent used, Hindi or English.
3. **IF node:** demo requests go straight to a Google Calendar tool that books the next free slot.
4. **Google Sheets** logs every enquiry, its category and the draft.
5. **Gmail** creates a draft, not a sent mail. The front-desk manager approves it from her phone.

In the first month, median reply time drops from 14 hours to 25 minutes, and demo bookings rise by a third. After two weeks of approving drafts with almost no edits, Arvind lets the "timings" category send automatically and keeps approval for fees, where mistakes are expensive.

When the Sheets API briefly fails one night, his error workflow sends a Slack alert and the run is retried, so no enquiry is lost.

## Common mistakes

**Automating a messy process.** Write the steps down and simplify them first; automation makes a bad process fail faster.

**Letting AI send without review at first.** Start with drafts and human approval. Remove approval only for categories with a long record of good output.

**No error handling.** APIs fail. Add retries, an error workflow and alerts, or failures go unnoticed for weeks.

**Hard-coding keys and values.** Use credentials for keys and a settings node or sheet for values like prices that change.

**One giant workflow.** Split big automations into smaller workflows that call each other. They are easier to test and fix.

**Ignoring data protection.** Customer data in prompts and logs is personal data. Collect only what you need and know where each service stores it.
