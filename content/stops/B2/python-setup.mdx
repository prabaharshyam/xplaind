## What it is

Before you can write programs, you need a place to write them and a way to run them. Every Python programmer, from a first-year student to an AI engineer at a large company, works with the same three tools:

| Tool | What it is | Example |
| --- | --- | --- |
| **Python** | The program that reads and runs your code (the **interpreter**) | Python 3, from python.org |
| **A code editor** | Where you write code; it colours your code, spots slips and helps you type | Visual Studio Code (VS Code), free |
| **A terminal** | A text window where you type commands, including the one that runs your file | The terminal inside VS Code |

Setup is done when all three **agree**: the terminal can find Python, the editor uses that same Python, and the terminal is open in the folder that holds your file. Almost every beginner problem is one of these not agreeing.

Once they agree, you start the loop every programmer lives in:

```flow
dir: LR
Write a file -> Save it
Save it -> Run it in the terminal
Run it in the terminal -> Read the output or the error
Read the output or the error -> Fix
Fix -[again]-> Write a file
```

This lesson follows Karthik, a commerce graduate in Madurai, as he sets up Python on his Windows laptop and hits the problems beginners hit most. Its check is a small project: your own first file, run from the terminal and shared online.

## How it works

### Pick a version

Install the newest Python 3. Python 3.15.0 came out on 9 October 2026, bugfix releases 3.15.1 and 3.15.2 followed in October, and more come about every two months, so the last number you see may be higher. Python 3.14 is also fine. Three rules:

- **Python 3, never Python 2.** If a tutorial writes `print "hello"` without brackets, it is for Python 2; find a newer one.
- **One Python is enough.** Installing several "to be safe" is the quickest way to make the editor and terminal disagree.
- **Heavy libraries can lag.** Some large data and AI libraries take weeks to support a new version. If one refuses to install, use 3.14 for that project.

### Install Python

| Computer | How |
| --- | --- |
| Windows 10 or 11 | Install the **Python install manager** from python.org/downloads or the Microsoft Store. It gives you the `python` and `py` commands. The first time you run Python with nothing installed, it downloads the latest release; you can also type `py install 3.15`. |
| Mac | Download the macOS installer from python.org and run it. Use the `python3` command. |
| Linux | Python 3 is usually already there. Use `python3`; on many systems a plain `python` command does not exist. |

The install manager is now the official way to install Python on Windows. The older full installer (a single `.exe`) still exists for Python 3.15, but python.org will stop offering it from Python 3.16. If you use it, tick **"Add python.exe to PATH"** on its first screen. **PATH** is the list of folders Windows searches when you type a command. If Python's folder is not on that list, typing `python` fails even though Python is installed.

### Check the install

Open a **new** terminal and type:

```text
python --version
```

On Mac and Linux, type `python3 --version`. You should see a version starting with 3, such as `Python 3.15.0`. On Windows, `py list` shows every Python the install manager knows about.

Why a new terminal? A terminal reads PATH once, when it opens. A terminal that was open during the install still has the old list and cannot find Python. The VS Code terminal copies PATH from VS Code itself, so close VS Code completely and reopen it, not just the terminal tab.

### When Windows cannot find Python

These are the three messages Windows learners meet most:

| You see | What it means | Fix |
| --- | --- | --- |
| `The term 'python' is not recognized...` (PowerShell) or `'python' is not recognized as an internal or external command` (Command Prompt) | Python is not installed, or its folder is not on PATH | Install the install manager, or rerun the old installer with the PATH box ticked. Then open a new terminal. |
| `Python was not found; run without arguments to install from the Microsoft Store...`, or the Store app opens | Python is not installed. Windows ships a shortcut called an **app execution alias** that sends `python` to the Store. | Install Python properly. If you used the old installer, search the Start menu for "Manage app execution aliases" and turn off the two App Installer entries for python.exe and python3.exe. |
| A version you did not expect | More than one Python is installed, and the first one on PATH wins | `py list` and `where.exe python` show them all. Uninstall the extras. |

```flow
title: The terminal cannot find Python
Type python --version -[shows Python 3]-> Ready to write code
Type python --version -[not recognized]-> Install it or fix PATH
Type python --version -[Microsoft Store opens]-> Install it or turn off the alias
Install it or fix PATH -> Close and reopen VS Code
Install it or turn off the alias -> Close and reopen VS Code
Close and reopen VS Code -> Type python --version
```

### On a Mac: make sure you run the right python3

macOS has its own `python3` at `/usr/bin/python3`. It belongs to Apple's developer tools and is usually older; calling it may ask you to install the Command Line Tools. The python.org installer makes its own `python3` come first. To check, open a new terminal and type `which python3`. A path under `/Library/Frameworks/Python.framework` or `/usr/local/bin` is the python.org one; `/usr/bin/python3` is Apple's.

### Install an editor and point it at Python

Install VS Code and its **Python extension** (by Microsoft). Make a folder for your work, such as `python-practice`, and open it with File, Open Folder. Keeping each project in its own folder avoids a lot of confusion later.

Then tell VS Code which Python to use. Press Ctrl+Shift+P (Cmd+Shift+P on a Mac), type **Python: Select Interpreter** and pick the Python you just installed. The chosen version then shows in the status bar at the bottom. If VS Code picked a different Python, you get strange results: the file runs in the terminal, but the editor underlines your imports in red, or the Run button uses a version you did not install on purpose. Changing the interpreter does not change terminals that are already open, so open a new one afterwards.

Last, turn on **File, Auto Save**. A dot on a file's tab means it has unsaved changes. Python runs the file on disk, not what is on your screen, so an unsaved fix does nothing.

### Write your first file

Create a file called `hello.py` in that folder:

```python
from datetime import date

name = "Priya"
print("Hello, my name is", name)
print("Today is", date.today())
```

Line 1 brings in `date` from Python's built-in `datetime` module. Line 3 stores text in a variable called `name`. Lines 4 and 5 print, and `date.today()` asks your computer for today's date.

The `.py` ending tells Python and your editor that this is Python code. Windows hides file endings by default, so a file you think is `hello.py` can really be `hello.py.txt`. In File Explorer, open the View menu and turn on file name extensions so you can see the truth.

### Run it from the terminal

Open the terminal inside VS Code with View, Terminal. The terminal always works "in" one folder, and the prompt usually shows which one, such as `PS C:\Users\karthik\python-practice>`. Make sure it is the folder with your file:

| Command | Windows | Mac and Linux |
| --- | --- | --- |
| Where am I? | `pwd` in PowerShell (the VS Code default), `cd` in Command Prompt | `pwd` |
| List files here | `dir` | `ls` |
| Go into a folder | `cd python-practice` | `cd python-practice` |
| Go up one folder | `cd ..` | `cd ..` |
| Run a file | `python hello.py` | `python3 hello.py` |

Type `python hello.py` and press Enter. The output appears below. Tip: Tab completes file names, and the Up arrow repeats the last command.

VS Code's Run button (the triangle at the top right) types the same command for you. Learn the typed command anyway: servers, options and remote machines all need it.

### The `>>>` prompt is a different place

If you type just `python` (or `python3`) with no file name, you enter the **interactive shell**, which shows a `>>>` prompt. It runs one line of Python at a time, which is handy for quick experiments such as `2 + 3` or `len("Madurai")`. But it only understands Python, not terminal commands. Typing `python hello.py` there gives:

```text
>>> python hello.py
  File "<python-input-0>", line 1
    python hello.py
           ^^^^^
SyntaxError: invalid syntax
```

Type `exit()` and press Enter to go back to the terminal, then run your file from there.

### Read error messages

When something is wrong, Python prints an error message, often in red. Read the **last line first**: it names the error. Then look at the file name and line number above it, and the copy of your code with `^` marks under the part Python is pointing at.

Suppose you delete the last bracket on line 5. Python checks the whole file before running anything, so no output appears at all, not even line 4's:

```text
  File "C:\Users\priya\python-practice\hello.py", line 5
    print("Today is", date.today()
         ^
SyntaxError: '(' was never closed
```

The `^` sits under the bracket that was opened and never closed. Other mistakes appear only while the program runs. If you type `date.todya()` on line 5, line 4 has already printed when Python stops. The full report is called a **traceback**:

```text
Hello, my name is Priya
Traceback (most recent call last):
  File "C:\Users\priya\python-practice\hello.py", line 5, in <module>
    print("Today is", date.todya())
                      ^^^^^^^^^^
AttributeError: type object 'datetime.date' has no attribute 'todya'. Did you mean '.today' instead of '.todya'?
```

That is Python 3.15's wording; older versions word the hint a little differently. Python often suggests the fix, so read to the end of the line. One gotcha: the line number is where Python **noticed** the problem, which is not always where the slip is. A missing indent after an `if` line, for example, is reported on the line below it, so look one line up too.

| Error | Usual cause |
| --- | --- |
| `SyntaxError` | A missing bracket, quote or colon, or a terminal command typed at `>>>` |
| `IndentationError` | A line indented when it should not be, or mixed tabs and spaces |
| `NameError` | A misspelt variable, or a variable used before it was created |
| `AttributeError` | A misspelt function or method name after a dot |
| `ModuleNotFoundError` | A package that is not installed in the Python you are running |
| `can't open file` | The terminal is in the wrong folder, or the file name is wrong |

### Installing packages: one habit now

Soon you will install packages such as `requests` or `pandas`. Install them through the same Python that runs your files:

```text
python -m pip install requests
```

On a Mac, use `python3 -m pip`. A bare `pip install` can belong to a different Python, which is why learners see `ModuleNotFoundError` for a package they "just installed". On recent Ubuntu and Debian versions, installing into the system Python stops with `error: externally-managed-environment`. Do not force past it; the fix is a virtual environment, covered in the "Packages and virtual environments" lesson (B3). The "Project tooling" lesson (B3) later shows uv, which creates environments and can even install Python for you. Your `hello.py` needs no packages.

### Other ways to run Python

Online notebooks such as **Google Colab** and **Kaggle** run Python in a browser with nothing to install. They help when your computer is locked down, old or shared. Two cautions: files you create there can disappear when the session ends, so download your work; and a notebook hides the terminal and folder skills every real project needs. Use them to start, not instead of a local setup.

## A worked example

Karthik, a commerce graduate in Madurai, sets up Python on his Windows 11 laptop one evening.

**Step 1: the Store surprise.** Before installing anything, he opens PowerShell and types `python`. The Microsoft Store opens. He recognises the Windows shortcut from this lesson, closes the Store and installs Python properly instead.

**Step 2: install.** From python.org/downloads he installs the Python install manager, opens a new PowerShell window and types `py install 3.15`. It downloads and installs the latest Python 3.15.

**Step 3: check, in a new terminal.** He installs VS Code and its Python extension. In the VS Code terminal, `python --version` prints `Python 3.15.2`. He creates a `python-practice` folder, opens it with File, Open Folder, and uses Python: Select Interpreter to pick 3.15.

**Step 4: the first error.** He writes `hello.py` with his own name in `C:\Users\karthik\python-practice`. To run it, he types `python hello.py` in the separate PowerShell window from Step 2, which opened in his home folder, and it fails. The end of the message reads:

```text
can't open file 'C:\\Users\\karthik\\hello.py': [Errno 2] No such file or directory
```

The doubled backslashes are just how Python prints a Windows path. The path tells him where Python looked: his home folder, not `python-practice`. He types `cd python-practice`, then `dir` to confirm `hello.py` is there, and runs the command again:

```text
Hello, my name is Karthik
Today is 2026-11-03
```

**Step 5: the unsaved change.** He adds a line that prints his name in Tamil script and runs the file. The output is unchanged. Then he notices the dot on the `hello.py` tab: he never saved. He presses Ctrl+S, runs it again, and the Tamil line appears, because VS Code saves files as UTF-8, which can hold any script. He turns on Auto Save.

**Step 6: break and fix.** On purpose, he deletes the last bracket on line 5 and runs the file. No output appears; the last line says `SyntaxError: '(' was never closed` and the `^` points at the bracket after `print`. He puts the bracket back and it runs.

**Step 7: share.** He creates a GitHub account and pastes `hello.py` into a new gist, which gives him a link to share. That link is this lesson's check.

In one evening he met the Store shortcut, the wrong folder and an unsaved file, and fixed each by reading the message instead of reinstalling.

## Common mistakes

- **Reinstalling at the first error.** Most errors are about the folder, PATH or an unsaved file, not a broken install. Read the last line first.
- **Testing in an old terminal.** After installing Python or changing PATH, close VS Code completely and open a new terminal.
- **Taking the Store shortcut for Python, or skipping the PATH tick in the older installer.** Use the install manager.
- **Running from the wrong folder.** Check with `pwd` and `dir` or `ls` before running.
- **Running an unsaved file.** Watch for the dot on the tab, or turn on Auto Save.
- **Typing terminal commands at the `>>>` prompt.** Type `exit()` first.
- **Saving the file as `hello.py.txt`.** Turn on file name extensions in File Explorer.
- **Several Pythons, and VS Code using a different one.** Keep one Python and choose it with Python: Select Interpreter.
- **Using a bare `pip install`.** Use `python -m pip install`, so the package goes into the Python that runs your code.
