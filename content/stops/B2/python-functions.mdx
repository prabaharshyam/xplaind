## What it is

A **function** is a named block of code that does one job. You give it inputs (**parameters**), it does its work, and it **returns** a result. Functions let you:

- reuse code instead of copying it;
- break a big problem into small, testable pieces;
- give steps meaningful names, so programs read like instructions.

## How it works

**Defining and calling.**

```python
def gst_amount(price, rate=0.18):
    return price * rate

print(gst_amount(1000))         # 180.0, uses the default rate
print(gst_amount(1000, 0.05))   # 50.0
```

`def` starts the definition; `price` and `rate` are parameters; `rate=0.18` gives a default used when the caller does not pass one.

**Return versus print.** `return` hands a value back to whoever called the function, so it can be stored or used in more calculations: `total = price + gst_amount(price)`. `print` only shows text on the screen; the function then returns `None`. Functions that compute something should return it; leave printing to the code that calls them.

**Arguments by position and by name.** `gst_amount(1000, 0.05)` passes by position; `gst_amount(price=1000, rate=0.05)` by name, which is clearer for functions with several parameters.

**Scope.** Variables created inside a function exist only inside it. Pass in what the function needs and return what it produces, rather than relying on variables from outside.

**One job each.** A good function does one thing and its name says what: `clean_phone_number`, `monthly_emi`, `is_valid_pin`. If you need "and" to describe it, consider splitting it.

**Docstrings and type hints.** A one-line description and type hints help readers and tools:

```python
def monthly_emi(principal: float, annual_rate: float, months: int) -> float:
    """Equated monthly instalment for a loan."""
    r = annual_rate / 12
    return principal * r * (1 + r) ** months / ((1 + r) ** months - 1)
```

## A worked example

Imran processes a list of customer phone numbers from a form, written in every possible way: "98450 12345", "+91-9845012345", "09845012345".

He writes small functions, each with one job:

```python
def digits_only(text):
    return "".join(ch for ch in text if ch.isdigit())

def normalise_mobile(raw):
    d = digits_only(raw)
    if d.startswith("91") and len(d) == 12:
        d = d[2:]
    if d.startswith("0") and len(d) == 11:
        d = d[1:]
    return "+91" + d if len(d) == 10 else None

for raw in ["98450 12345", "+91-9845012345", "09845012345", "12345"]:
    print(raw, "->", normalise_mobile(raw))
```

Three numbers become `+919845012345`; the last returns `None`, so he can list invalid ones. Because the logic lives in functions, he reuses `normalise_mobile` in two other scripts the following week.

## Common mistakes

- **Printing instead of returning.** The caller then gets `None`.
- **Forgetting to call the function.** `gst_amount` without brackets does nothing.
- **Functions that do too much.** Split them.
- **Relying on outside variables.** Pass inputs as parameters.
- **Mutable defaults** such as `def add(item, items=[])`. The same list is shared between calls; use `None` and create a new list inside.
