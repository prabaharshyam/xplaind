## What it is

As your programs grow, you start copying the same few lines: working out GST in three places, cleaning phone numbers in two scripts. Copying causes bugs, because when you fix one copy you forget the others. A **function** solves this.

A function is a named block of code that does **one job**. You give it inputs, called **parameters**, it does its work, and it **returns** a result.

```text
          inputs                function                  output
   +-----------------+   +-------------------------+   +-----------+
   | price = 1000    |-->| def gst_amount(price,   |-->|  180.0    |
   | rate  = 0.18    |   |      rate=0.18):        |   |           |
   +-----------------+   |   return price * rate   |   +-----------+
                         +-------------------------+
```

Functions let you:

- **reuse** code instead of copying it;
- **break** a big problem into small pieces you can test one at a time;
- **name** steps, so programs read like instructions: `clean_phone_number`, `monthly_emi`, `send_reminder`.

This lesson follows Imran, who cleans customer phone numbers from a form, as he turns a messy script into small reusable functions. By the end you will write functions that return results and can be reused across programs.

## How it works

### Defining and calling

```python
def gst_amount(price, rate=0.18):
    return price * rate

print(gst_amount(1000))         # 180.0, uses the default rate
print(gst_amount(1000, 0.05))   # 50.0
```

- `def` starts the definition.
- `price` and `rate` are **parameters**.
- `rate=0.18` is a **default**, used when the caller does not pass one.
- `return` hands the result back.

Calling needs brackets: `gst_amount(1000)`. Writing `gst_amount` without brackets refers to the function itself and does not run it.

### Return versus print

This is the most common beginner confusion:

| | `return` | `print` |
| --- | --- | --- |
| What it does | Hands a value back to the caller | Shows text on screen |
| Can the caller use the value? | Yes: `total = price + gst_amount(price)` | No: the function returns `None` |
| When to use | Functions that compute something | Only in the code that shows results |

Functions that compute something should return it, and leave printing to the code that calls them. Then the same function works in a report, a web app or a test.

### Arguments by position and by name

```python
gst_amount(1000, 0.05)               # by position
gst_amount(price=1000, rate=0.05)    # by name: clearer with several parameters
```

### Scope

Variables created inside a function exist only inside it:

```python
def tax(amount):
    total = amount * 1.18
    return total

result = tax(100)     # 118.0
print(total)          # NameError: total only existed inside tax
```

Pass in what the function needs and return what it produces, rather than relying on variables from outside. Functions that only use their inputs are easy to test and reuse.

### One job each

A good function does one thing, and its name says what. If you need "and" to describe it, such as "cleans the number and sends the SMS", split it into two.

```text
   One big function                    Small functions
 +-------------------------+       +-------------------+
 | process_customers():    |       | digits_only()     |
 |   read file             |       | normalise_mobile()|
 |   clean numbers         |  -->  | is_valid_email()  |
 |   check emails          |       | read_customers()  |
 |   write report          |       | write_report()    |
 +-------------------------+       +-------------------+
   hard to test or reuse              each testable alone
```

### Docstrings and type hints

A one-line description and type hints help readers and tools such as your editor:

```python
def monthly_emi(principal: float, annual_rate: float, months: int) -> float:
    """Equated monthly instalment for a loan."""
    r = annual_rate / 12
    return principal * r * (1 + r) ** months / ((1 + r) ** months - 1)

print(round(monthly_emi(500000, 0.09, 60)))   # about 10379 rupees a month
```

### A trap: mutable defaults

```python
def add_order(order, orders=[]):      # bug: the same list every call
    orders.append(order)
    return orders
```

The default list is created once and shared between calls, so orders pile up. Use `None` and create a new list inside:

```python
def add_order(order, orders=None):
    if orders is None:
        orders = []
    orders.append(order)
    return orders
```

## A worked example

Imran works at a small marketing agency in Hyderabad. A client's form collected 3,000 customer phone numbers, written in every possible way: "98450 12345", "+91-9845012345", "09845012345", "9845012345 ". The SMS tool needs them as `+91` followed by ten digits.

His first script was one long block of code, copied and slightly changed in two other scripts. He rewrites it as small functions, each with one job:

```python
def digits_only(text: str) -> str:
    """Keep only the digits in text."""
    return "".join(ch for ch in text if ch.isdigit())

def normalise_mobile(raw: str) -> str | None:
    """Return +91 and ten digits, or None if it is not a valid mobile number."""
    d = digits_only(raw)
    if d.startswith("91") and len(d) == 12:
        d = d[2:]
    if d.startswith("0") and len(d) == 11:
        d = d[1:]
    return "+91" + d if len(d) == 10 else None

for raw in ["98450 12345", "+91-9845012345", "09845012345", "12345"]:
    print(raw, "->", normalise_mobile(raw))
```

| Input | After digits_only | After the rules | Result |
| --- | --- | --- | --- |
| `98450 12345` | 9845012345 | 10 digits | +919845012345 |
| `+91-9845012345` | 919845012345 | drop leading 91 | +919845012345 |
| `09845012345` | 09845012345 | drop leading 0 | +919845012345 |
| `12345` | 12345 | too short | None |

Three numbers become `+919845012345`; the last returns `None`, so he can list the invalid ones for the client. Because the logic lives in functions, he imports `normalise_mobile` into the two other scripts the following week instead of copying it, and when the client asks to accept landline numbers too, he changes one function in one place.

## Common mistakes

- **Printing instead of returning.** The caller gets `None`.
- **Forgetting to call the function.** `gst_amount` without brackets does nothing.
- **Functions that do too much.** Split them until each has one job.
- **Relying on outside variables.** Pass inputs as parameters and return results.
- **Mutable defaults** such as `def add(item, items=[])`. Use `None` and create a new list inside.
- **Vague names.** `process()` and `do_stuff()` tell the reader nothing.
