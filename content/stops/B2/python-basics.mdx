## What it is

Python is the main language of AI work: data cleaning, automation scripts, calling AI APIs and building applications all use it. You do not need to learn all of Python to be useful. Five building blocks let you write most short programs:

| Building block | What it does | Example |
| --- | --- | --- |
| **Variables** | Store a value under a name | `price = 250` |
| **Conditions** | Choose what to do | `if price > 200:` |
| **Loops** | Repeat steps | `for item in cart:` |
| **Functions** | Package steps you can reuse | `def total(cart):` |
| **Lists and dictionaries** | Hold many values | a list of prices, a dictionary of a student's details |

```text
   data in            your program                         result out
 +----------+   +---------------------------------+   +-------------+
 | orders,  |-->| variables hold values           |-->| bills,      |
 | prices,  |   | loops go through each order     |   | totals,     |
 | marks    |   | conditions choose a price       |   | reports     |
 |          |   | functions do the sum            |   |             |
 +----------+   +---------------------------------+   +-------------+
```

This lesson follows Divya, who runs a tiffin service in Bengaluru, as she writes her first useful program to work out her customers' bills. By the end you will write and explain a 20-line program of your own.

## How it works

### Values and types

Python has a few basic kinds of value:

| Type | Examples | Notes |
| --- | --- | --- |
| Whole numbers (`int`) | `250`, `-3` | For counts and rupees without paise |
| Decimal numbers (`float`) | `18.5`, `0.18` | For rates, averages |
| Text (`str`) | `"Chennai"`, `'Asha'` | Always in quotes |
| True or false (`bool`) | `True`, `False` | Results of comparisons |

Python works out the type from the value. Convert between types with `int("42")`, `float("3.5")` and `str(42)`.

### Variables

A variable is a label for a value. Assigning again changes what it points to:

```python
monthly_rent = 15000
monthly_rent = monthly_rent + 500    # now 15500
```

Use clear names like `monthly_rent`, not `x`. You will thank yourself next month.

### Conditions

```python
marks = 72
if marks >= 75:
    print("Distinction")
elif marks >= 60:
    print("First class")
else:
    print("Pass")
```

Indentation, four spaces, shows which lines belong to each branch. Python takes it seriously: wrong indentation is an error or, worse, changes what the program does.

Comparisons use `==` (equal), `!=` (not equal), `>`, `>=`, `<` and `<=`. A single `=` assigns; it does not compare.

### Loops

A `for` loop runs once for each item:

```python
for city in ["Pune", "Kochi", "Jaipur"]:
    print("Delivering to", city)

for i in range(3):
    print(i)        # prints 0, then 1, then 2
```

`range(3)` gives 0, 1 and 2: it starts at 0 and stops **before** 3. A `while` loop repeats while a condition stays true, which is useful when you do not know in advance how many times to repeat.

### Functions

A function takes inputs, does some work and `return`s a result:

```python
def gst(amount, rate=0.18):
    return amount * rate

print(gst(1000))         # 180.0
print(gst(1000, 0.05))   # 50.0
```

`rate=0.18` is a default: used when you do not pass a rate. Write a function whenever you find yourself copying the same few lines.

### Lists

Ordered collections:

```python
cities = ["Pune", "Kochi"]
cities.append("Jaipur")     # add to the end
print(cities[0])            # Pune: counting starts at 0
print(len(cities))          # 3
```

### Dictionaries

Look up values by a key instead of a position:

```python
profile = {"name": "Asha", "age": 24}
profile["city"] = "Pune"     # add or change a key
print(profile["name"])       # Asha
```

A **list of dictionaries** is how most real data looks in Python: each dictionary is one record, like one row of a spreadsheet.

### Reading error messages

When something goes wrong, Python prints a **traceback**. Read it from the bottom up: the last line names the error, and the line above it shows where it happened.

```text
Traceback (most recent call last):
  File "bill.py", line 12, in <module>
    total = total + amount
TypeError: unsupported operand type(s) for +: 'int' and 'str'
```

This says: on line 12, you tried to add a number and a piece of text. The fix is to convert the text with `int()` where the value was read. Errors are normal; reading them calmly is half of programming.

## A worked example

Divya runs a small tiffin service in Bengaluru and used to keep orders in her head. Veg meals cost ₹90 and non-veg ₹120. She writes her first useful program:

```python
orders = [
    {"customer": "Ravi", "meals": 2, "veg": True},
    {"customer": "Sana", "meals": 1, "veg": False},
    {"customer": "Arun", "meals": 3, "veg": True},
]
PRICE_VEG = 90
PRICE_NONVEG = 120

def bill(order):
    price = PRICE_VEG if order["veg"] else PRICE_NONVEG
    return order["meals"] * price

total = 0
for order in orders:
    amount = bill(order)
    total = total + amount
    print(order["customer"], "owes Rs", amount)

print("Today's total: Rs", total)
```

Here is what happens, step by step:

| Loop pass | Customer | Veg? | Price | Meals | Bill | Running total |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | Ravi | yes | 90 | 2 | 180 | 180 |
| 2 | Sana | no | 120 | 1 | 120 | 300 |
| 3 | Arun | yes | 90 | 3 | 270 | 570 |

The program prints each customer's bill and the day's total of ₹570. When prices change, she edits two lines at the top. The prices are in capital letters as a reminder that they are settings, not values the program changes.

Next she plans to read orders from a CSV file instead of typing them into the program, which the lesson on files covers.

## Common mistakes

- **Wrong indentation.** Lines inside `if`, `for` and `def` must be indented consistently, usually four spaces.
- **Off-by-one with `range`.** `range(3)` is 0, 1, 2, not 1, 2, 3.
- **Mixing text and numbers.** `"5" + 3` fails; convert first with `int()` or `str()`.
- **Using `=` in a condition.** Comparison is `==`.
- **`print` instead of `return` in a function.** Printing shows a value; returning hands it back for use.
- **Unclear names.** `a`, `b` and `temp` make programs hard to read; name things for what they hold.
