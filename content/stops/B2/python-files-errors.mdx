## What it is

The programs you have written so far kept their data inside the code. Real programs read data from files and write results back. And real data is messy: a missing file, a badly formatted row, "NA" where a number should be. Two skills cover this:

- **File input and output:** opening, reading and writing text and CSV files safely.
- **Error handling:** catching **exceptions** so one bad input does not crash the whole program, and reporting problems clearly.

```text
  input file            your program                          output files
 +-------------+   +---------------------------------+   +-----------------+
 | payments.csv|-->| for each row:                   |-->| summary         |
 | 412 rows    |   |   try:  convert, add to total   |   | total collected |
 |  3 are bad  |   |   except: note the bad row,     |   +-----------------+
 +-------------+   |           keep going            |-->| problems.csv    |
                   +---------------------------------+   | 3 rows to check |
                                                         +-----------------+
```

This lesson follows Sana, who manages fees at a music school in Mysuru, as she turns a script that crashed on the first bad row into one that finishes the job and lists what needs checking. By the end you will process a messy CSV safely.

## How it works

### Opening files with `with`

```python
with open("notes.txt", encoding="utf-8") as f:
    text = f.read()
```

`with` closes the file automatically when the block ends, even if an error happens inside it. Always set `encoding="utf-8"`, especially for Indian language text and symbols like ₹. Without it, a file that works on your laptop can fail on a colleague's.

### File modes

| Mode | Meaning | Danger |
| --- | --- | --- |
| `"r"` | Read (the default) | Fails if the file does not exist |
| `"w"` | Write, **replacing** everything already in the file | Opening an existing report with `"w"` wipes it |
| `"a"` | Append to the end | Safe for logs |
| `"x"` | Create a new file, fail if it already exists | Useful to avoid overwriting |

### Reading line by line

```python
with open("big_log.txt", encoding="utf-8") as f:
    for line in f:
        print(line.strip())     # strip removes the newline at the end
```

This handles very large files without loading everything into memory at once.

### CSV files

A CSV file is a table saved as text, one row per line, with commas between fields. Use the `csv` module instead of splitting on commas yourself, because fields can contain commas inside quotes, like an address:

```text
name,address,amount
Asha,"12, MG Road, Mysuru",1500
```

```python
import csv
with open("orders.csv", newline="", encoding="utf-8") as f:
    for row in csv.DictReader(f):
        print(row["customer"], row["amount"])
```

`csv.DictReader` gives each row as a dictionary keyed by the header. `csv.DictWriter` writes rows from dictionaries. Note that every value arrives as **text**: "1500", not 1500. Convert before doing maths.

### Exceptions

When something fails, Python **raises an exception**: an error object with a type and a message. Common ones:

| Exception | Typical cause |
| --- | --- |
| `FileNotFoundError` | The file name or folder is wrong |
| `ValueError` | `int("twenty")` or `float("NA")`: the text is not a number |
| `KeyError` | A dictionary or CSV row has no such key or column |
| `ZeroDivisionError` | Dividing by zero, for example an average of an empty list |
| `TypeError` | Adding text to a number |

Catch the specific exceptions you expect and decide what to do:

```python
try:
    age = int("twenty")
except ValueError:
    age = -1          # mark as invalid instead of crashing
print(age)            # -1
```

Catch specific exceptions, not everything. A bare `except:` also hides real bugs, such as a misspelt variable name. Use `finally` for clean-up that must always run, and `raise` to signal your own errors with a clear message:

```python
if amount < 0:
    raise ValueError(f"Negative amount on line {line_no}")
```

### Bad rows: collect, do not crash

When processing many rows, handle each row's errors separately, collect the failures with their line numbers, and report them at the end. One bad row out of 400 should not stop the other 399.

## A worked example

Sana manages fees at a music school in Mysuru. Each month the bank sends `payments.csv`. She needs the total collected and a list of rows to check by hand. Her first script crashed on the first "NA" and she had to find the bad row by scrolling. Her new script:

```python
import csv

total = 0
problems = []
try:
    with open("payments.csv", newline="", encoding="utf-8") as f:
        for line_no, row in enumerate(csv.DictReader(f), start=2):
            try:
                amount = float(row["amount"].replace(",", ""))
                total += amount
            except (ValueError, KeyError) as e:
                problems.append((line_no, row.get("student", "?"), str(e)))
except FileNotFoundError:
    print("payments.csv not found. Download it from the bank portal first.")
    raise SystemExit(1)

with open("problems.csv", "w", newline="", encoding="utf-8") as out:
    writer = csv.writer(out)
    writer.writerow(["line", "student", "error"])
    writer.writerows(problems)

print(f"Collected Rs {total:,.2f}; {len(problems)} rows need checking")
```

`enumerate(..., start=2)` numbers rows from 2, because line 1 of the file is the header, so the line numbers match what Sana sees when she opens the file.

| Run | Rows | Converted | Problems | Result |
| --- | --- | --- | --- | --- |
| Old script | 412 | Stopped at row 37 | Crashed | No total, row found by hand |
| New script | 412 | 409 | 3 ("NA" twice, one blank) | Total plus problems.csv |

This month she fixes three rows in five minutes instead of losing half an hour.

## Common mistakes

- **Forgetting `with`.** Files can stay open or lose data.
- **Using `"w"` when you meant `"a"`.** The old content is gone for good.
- **Splitting CSV lines on commas.** Use the `csv` module; quoted commas will break your split.
- **Forgetting that CSV values are text.** Convert with `int()` or `float()` before doing maths.
- **Catching everything with a bare `except`.** Catch the specific exceptions you expect.
- **Stopping at the first bad row.** Collect failures and continue.
