## What it is

Real programs read data from files and write results back, and they must cope when things go wrong: a missing file, a badly formatted row, text where a number should be. Two skills cover this:

- **File input and output**: opening, reading and writing text and CSV files safely.
- **Error handling**: catching **exceptions** so one bad input does not crash the whole program, and reporting problems clearly.

## How it works

**Opening files with `with`.**

```python
with open("notes.txt", encoding="utf-8") as f:
    text = f.read()
```

`with` closes the file automatically, even if an error happens inside the block. Always set `encoding="utf-8"`, especially for Indian language text.

**Modes.** `"r"` reads (default). `"w"` writes and **replaces** everything already in the file. `"a"` appends to the end. Opening an existing report with `"w"` by mistake wipes it.

**Reading line by line.** `for line in f:` handles large files without loading everything into memory. `line.strip()` removes the newline.

**CSV files.** Use the `csv` module instead of splitting on commas yourself, because fields can contain commas inside quotes:

```python
import csv
with open("orders.csv", newline="", encoding="utf-8") as f:
    for row in csv.DictReader(f):
        print(row["customer"], row["amount"])
```

`csv.DictWriter` writes rows from dictionaries.

**Exceptions.** When something fails, Python raises an exception such as `FileNotFoundError` or `ValueError`. Catch the specific ones you expect and decide what to do:

```python
try:
    age = int("twenty")
except ValueError:
    age = -1          # mark as invalid instead of crashing
print(age)            # -1
```

Catch specific exceptions, not everything; a bare `except:` hides real bugs. Use `finally` for clean-up that must always run, and `raise` to signal your own errors with a clear message.

**Bad rows.** When processing many rows, handle each row's errors separately, collect the failures and report them at the end, rather than stopping at the first problem.

## A worked example

Sana manages fees at a music school in Mysuru. Each month she gets `payments.csv` from the bank and needs the total collected and a list of problem rows.

```python
import csv

total = 0
problems = []
with open("payments.csv", newline="", encoding="utf-8") as f:
    for line_no, row in enumerate(csv.DictReader(f), start=2):
        try:
            amount = float(row["amount"].replace(",", ""))
            total += amount
        except (ValueError, KeyError) as e:
            problems.append((line_no, row, str(e)))

with open("problems.csv", "w", newline="", encoding="utf-8") as out:
    writer = csv.writer(out)
    writer.writerow(["line", "row", "error"])
    for p in problems:
        writer.writerow(p)

print(f"Collected Rs {total:,.2f}; {len(problems)} rows need checking")
```

This month the file has 412 rows. Three have "NA" as the amount; the program records them in `problems.csv` and still reports the total for the other 409. Before error handling, the script crashed on the first bad row and she had to find it by hand.

## Common mistakes

- **Forgetting `with`.** Files can stay open or lose data.
- **Using `"w"` when you meant `"a"`.** The old content is gone.
- **Splitting CSV lines on commas.** Use the `csv` module.
- **Catching everything with a bare `except`.** Catch specific exceptions.
- **Stopping at the first bad row.** Collect failures and continue.
