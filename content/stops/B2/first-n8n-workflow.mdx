## What it is

**n8n** (pronounced "n-eight-n") is a workflow automation tool with a visual editor. You place **nodes** on a canvas and connect them with arrows. A **trigger** node starts the workflow, and each following node does one thing: read a sheet, call an app, transform data, branch on a condition or call an AI model.

Data flows from node to node as a list of **items**. Each item is a small JSON record, like one row of a spreadsheet:

```text
  [Trigger: new sheet row]
        |  items: [ { name: "Rohan", phone: "98xx", course: "JEE" } ]
        v
  [Edit Fields: tidy data]
        |  items: [ { name: "Rohan", phone: "+9198xx", course: "JEE" } ]
        v
  [If: course is JEE?]
     yes |                         no |
         v                            v
  [Gmail: JEE welcome]        [Gmail: NEET welcome]
         \                           /
          v                         v
        [Telegram: tell counsellors]
```

You can use n8n's hosted cloud version or run it yourself, for example with Docker, which many companies prefer so their data stays on their own servers.

This lesson follows Shalini, who manages admissions at a coaching institute in Jaipur, as she builds her first workflow. By the end you will build, test and publish one of your own.

## How it works

### Triggers

Every workflow starts with a trigger. A workflow can hold more than one, but each run starts from just one of them. Common ones:

| Trigger | Fires when | Example use |
| --- | --- | --- |
| Schedule | A set time arrives | Send a daily report at 9 am |
| Webhook | Another app calls a URL | A payment app reports a new payment |
| Email (IMAP or Gmail) | A new email arrives | Process invoices sent to accounts@ |
| Form or Sheets | A new submission or row appears | New admission enquiry |
| Manual | You click "Execute workflow" | Building and testing |

### Nodes

Nodes come in three families:

- **App nodes:** Gmail, Google Sheets, Slack, Telegram, WhatsApp Business, HubSpot and hundreds more.
- **Core nodes:** HTTP Request for any API, Code for small scripts, Edit Fields (also called Set) to change data, If and Switch to branch, Merge to combine, Loop to process in batches.
- **AI nodes:** call a language model to extract, classify, summarise or draft, or build an agent.

### Credentials

Each app node needs a **credential**: saved access to that app, usually by signing in with OAuth or pasting an API key. n8n stores credentials encrypted and lets you reuse them across workflows. Use a dedicated account with only the access the workflow needs, not your personal admin account.

### Mapping data between nodes

In a node's settings you choose which data from earlier nodes to use. You can drag a field from the input panel, or write an **expression** in double curly braces, such as `{{ $json.email }}` for the current item's email field. The output panel shows exactly what each node produced, which makes mistakes easy to see.

### Testing

Run the workflow from the editor with sample data. Click each node to see its input and output, and fix mapping problems one node at a time. **Pin** the trigger's test data so you can rerun the whole workflow without sending a new email or adding a new row each time.

### Publishing

When it works, **publish** the workflow. (Before n8n 2.0 this was an Active toggle.) Production triggers then run on their own. The **executions list** shows every run with its data and any errors.

```text
   Build  -->  Test with pinned data  -->  Fix  -->  Publish   -->  Watch executions
     ^                                     |
     +-------------------------------------+
```

## A worked example

Shalini manages admissions for a coaching institute in Jaipur. Enquiries arrive through a Google Form whose responses go into a sheet. Today, counsellors check the sheet once a day and call students the next morning. She builds her first workflow:

| # | Node | What it does |
| --- | --- | --- |
| 1 | Google Sheets trigger | Fires when a new row is added to the responses sheet |
| 2 | Edit Fields | Trims spaces, formats the phone with +91, capitalises the name |
| 3 | If | Is the course "JEE" or "NEET"? |
| 4 | Gmail (two branches) | Sends a course-specific welcome email with the brochure link, using the student's name |
| 5 | Telegram | Posts "New JEE enquiry: Rohan Sharma, +91 98xxxxxx45, prefers evening batch" to the counsellors' group |

**Testing.** She pins three sample rows and runs the workflow. Two go through correctly. The third, where a student typed "jee" in lower case, goes down the wrong branch and gets the NEET email. She changes the If node to compare in lower case, and all three pass.

She also tries an empty phone number. The Telegram message says "phone: undefined", which would confuse counsellors. She adds a default: "phone not given, reply by email".

**Publishing.** She publishes the workflow. The next morning the executions list shows 14 successful runs, and counsellors called new students within an hour instead of the next day.

| Measure | Before | After |
| --- | --- | --- |
| Time from enquiry to welcome email | Next day, by hand | Under a minute |
| Time to a counsellor's call | Next morning | Within an hour |
| Enquiries missed | A few a week | None in the first week |

## Common mistakes

- **Testing only the happy path.** Try empty fields, unusual spellings, extra spaces and duplicates.
- **Using your personal admin account for credentials.** Use a dedicated account with limited access.
- **Hard-coding values that change.** Keep email templates, chat IDs and prices in one place you can edit.
- **Forgetting to publish.** A workflow that only runs in test mode does nothing for anyone.
- **No error alert.** Add an error workflow that messages you when a run fails, before you rely on it.
- **Ignoring item counts.** A node that suddenly outputs zero items is a common silent failure; check the counts.

## Practise

Do n8n's quickstart, then its N8N101 Essentials course linked below.

1. **Build.** Build a workflow with a trigger, at least one data-tidying node, a branch and two app actions, using pinned test data.
2. **Break it.** Feed it three bad inputs: a missing field, an odd spelling and a duplicate. Fix each.
3. **Publish.** Publish it and check the executions list after a few real or simulated runs.

**You are done when you can** explain each node's input and output in your workflow and show a successful automatic run.
