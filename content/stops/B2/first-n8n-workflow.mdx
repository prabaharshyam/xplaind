## What it is

**n8n** (said "n-eight-n") is a workflow automation tool with a visual editor. You place **nodes** on a canvas and join them with arrows. A **trigger** node starts each run, and every node after it does one job: read a sheet, tidy data, branch on a condition, send an email.

Data moves from node to node as a list of **items**. Each item is a small JSON record, like one row of a spreadsheet. Most nodes run once for each item they receive. So if a trigger outputs three new rows, a Gmail node after it sends three emails. Keep that rule in mind, because most beginner surprises come from it.

```flow
title: Shalini's admissions workflow
New form row | Google Sheets trigger -> Tidy enquiry | Edit Fields
Tidy enquiry -> Drop repeats | Remove Duplicates
Drop repeats -> Course is JEE?
Course is JEE? -[yes]-> JEE welcome | Gmail
Course is JEE? -[no]-> NEET welcome | Gmail
JEE welcome -> Alert counsellors | Telegram
NEET welcome -> Alert counsellors
Any failure -> Error workflow | message to Shalini
```

This lesson is about the mechanics: getting n8n running, items, expressions, testing and publishing. The lesson "Automation with n8n" builds on it with AI steps. You will follow Shalini, who runs admissions at a coaching institute in Jaipur, as she builds the workflow above.

Two facts before you start. First, n8n is **not open source**. It uses its own **Sustainable Use License**, which lets you use and change it for your own internal business, or for personal and non-commercial use. Building workflows for paying clients is fine. Hosting n8n so clients can build their own workflows on it needs a commercial agreement with n8n. Second, since **n8n 2.0**, saving (now automatic) only keeps a draft. You click **Publish** to make the triggers run. Many older tutorials still show an Active toggle.

## How it works

### Get n8n running

You have three realistic choices:

| Option | How you start | What it costs | Google sign-in | Best for |
| --- | --- | --- | --- | --- |
| n8n Cloud | Sign up for the free trial | Trial, as of November 2026: 14 days, Pro features, 1,000 executions; then a paid plan | One click, "Sign in with Google" | Your first workflow, fastest |
| Docker on your laptop | One command, below | Free software; runs only while the laptop is on | Your own Google OAuth client | Learning, keeping data local |
| Docker on a rented server | Docker Compose | Server rent, plus your time | Your own OAuth client and a domain | Self-hosted production |

Cloud plans are priced by **executions**, meaning whole workflow runs, not single nodes. Check n8n's pricing page for the current plans before you quote anyone.

To run n8n locally, install Docker Desktop, then run:

```bash
docker volume create n8n_data
docker run -it --rm --name n8n -p 5678:5678 \
  -e GENERIC_TIMEZONE="Asia/Kolkata" -e TZ="Asia/Kolkata" \
  -v n8n_data:/home/node/.n8n \
  n8nio/n8n
```

Open `http://localhost:5678` and create the owner account. The volume keeps your workflows and credentials when the container stops. The time zone matters: without it, a self-hosted instance uses America/New_York, and a "9 am" schedule fires in the Indian evening. Older tutorials start n8n with `npx n8n`. n8n 3.0, in early access as of November 2026, drops that route and supports only Docker, so learn the Docker way.

One limit of a laptop: apps on the internet cannot reach `localhost`. Triggers that **poll**, such as the Google Sheets trigger, still work, because n8n does the asking. Triggers that wait for a call, such as a Webhook, need a public address (see the lesson "Webhooks").

### Triggers

Every workflow starts with a trigger. A workflow can hold several, but each run starts from one.

| Trigger | Fires when | How it knows |
| --- | --- | --- |
| Manual | You click "Execute workflow" | You, while building |
| Schedule | A set time arrives | n8n's clock, in the workflow's time zone |
| Webhook or Form Trigger | Another app or a person submits data to a URL | Instant: the sender calls n8n |
| Google Sheets, Gmail | A new row or email appears | Polling: n8n checks every minute by default |

There is no Google Forms trigger node. If you use a Google Form, its answers go into a responses sheet, and you trigger on new rows in that sheet.

The Sheets trigger has three habits worth knowing. It counts rows. The first check after you publish only records how many rows exist, so older responses never fire. Deleting or sorting rows in the responses sheet confuses the count, so leave that sheet alone and work in a copy. And when you click "Execute workflow" in the editor, it returns **every** row in the sheet, not just the newest.

### Nodes

Nodes come in three families:

- **App nodes:** Google Sheets, Gmail, Telegram, Slack, HubSpot and hundreds more.
- **Core nodes:** **Edit Fields** (also called Set) to rename and tidy fields, **If** and **Switch** to branch, **Remove Duplicates**, **Merge** to combine two inputs, **HTTP Request** for any API, and **Code** for short scripts.
- **AI nodes:** call a language model to classify, extract or draft. These are the subject of "Automation with n8n".

### Credentials

Each app node needs a **credential**: saved access to that app, through OAuth sign-in or an API key. n8n stores credentials encrypted and lets several workflows reuse one. Use an account made for the automation, with only the access it needs, rather than your personal admin account.

On n8n Cloud, Google credentials are one click. On self-hosted n8n, this is the step where most beginners get stuck, because you must create your own **OAuth client**:

1. In Google Cloud Console, create a project and enable the APIs you need. The Google Sheets node needs both the Sheets API and the Drive API; Gmail needs the Gmail API.
2. Set up the OAuth consent screen. Choose **Internal** if you use Google Workspace, otherwise **External**. An External app starts in testing, so add your own Google account as a **test user**. Without that, Google shows "access denied".
3. Create an OAuth client ID of type **Web application**. Paste in the **OAuth Redirect URL** that the n8n credential screen shows. On a laptop it looks like `http://localhost:5678/rest/oauth2-credential/callback`.
4. Copy the Client ID and Client Secret into n8n, then click Sign in with Google.

A trap: n8n's docs warn that for an External app still in testing, consent and tokens expire after seven days. If the workflow stops reading the sheet a week later, reconnect the credential, or read Google's guidance on moving the app out of testing.

### Expressions: the current item and earlier nodes

In a node's settings you can drag a field from the input panel, or type an **expression** inside double curly braces. Expressions are small pieces of JavaScript.

- `{{ $json.email }}` reads the email field of the **current item**, as this node's direct input sees it.
- `{{ $json['Phone number'] }}` reads a field whose name has a space. Google Form sheets use the question text as column names, which is one reason to rename fields early.
- `{{ $('Tidy enquiry').item.json.name }}` reads the name from the item in the node called "Tidy enquiry" that this item came from.

The second form matters more than it looks. Every node replaces `$json` with its own output. After a Gmail node, `$json` holds details of the email it just sent, such as a message id, not the student's row. So a Telegram node placed after Gmail must name the earlier node. Give nodes clear names, because the name is part of the expression; if you rename a node, check the expressions that use it.

Two more defaults trip people up. **Edit Fields** outputs only the fields you set, unless you turn on **Include Other Input Fields**, so any field you forget disappears. And a new **If** node compares text case-sensitively: "neet" is not equal to "NEET" until you add the **Ignore Case** option.

### Testing with pinned data

Run the workflow from the editor and click each node to see its input and output. Fix problems one node at a time, starting from the first node whose output looks wrong.

**Pin** the trigger's output so every test run reuses the same sample items instead of fetching new ones. Production runs ignore pinned data. Pinning also protects you from the Sheets trigger habit above: an unpinned test run on a sheet of 300 old responses would push all 300 items through, and the Gmail node would email 300 real students. Pin three or four rows, or point the trigger at a test copy of the sheet, before you connect any node that sends messages.

### Publishing, alerts and duplicates

When every node passes its tests, click **Publish**. From then on the trigger runs by itself, and the **executions list** shows each run with its data and any error. Two more pieces make the workflow safe to leave alone:

- **An error workflow.** Create a separate workflow that starts with an **Error Trigger** node and sends you a message. The Error Trigger receives the failed workflow's name in `workflow.name`, the last node that ran in `execution.lastNodeExecuted`, the error in `execution.error.message` and a link in `execution.url`. Publish it, then select it under **Error workflow** in the main workflow's settings. It fires only for automatic runs, not for runs you start in the editor, so test it with a published workflow you break on purpose.
- **Duplicate protection.** Students double-submit forms, and parents fill one in for a child who already did. A **Remove Duplicates** node set to **Remove Items Processed in Previous Executions**, keeping items where the **Value Is New**, remembers values from earlier runs and drops repeats. It does not compare items within one run, so two copies caught by the same poll both pass; for double-clicks, put a second Remove Duplicates set to **Remove Items Repeated Within Current Input** in front of it. Dedupe on a value you have already normalised. "+91 98765 43210" and "09876543210" are the same phone, but only after tidying.

```flow
dir: LR
Build -> Pin awkward samples -> Run and inspect -> Fix
Fix -[test again]-> Run and inspect
Run and inspect -[all pass]-> Publish -> Watch executions
```

## A worked example

Shalini runs admissions for a coaching institute in Jaipur. Enquiries come through a Google Form with the questions "Full name", "Phone number", "Email" and "Course". Google writes each answer as a row in a responses sheet, with a Timestamp column first. Today, counsellors read the sheet once a day and call students the next morning, and some enquiries are missed.

She signs up for the n8n Cloud trial, so Google sign-in is one click, and builds:

| # | Node | What it does |
| --- | --- | --- |
| 1 | Google Sheets trigger, Row Added | Checks the responses sheet every minute for new rows |
| 2 | Edit Fields, named "Tidy enquiry" | Sets name, phone, email and course with simple names |
| 3 | Remove Duplicates | Drops a phone or email already seen in an earlier run |
| 4 | If | Course is JEE, with Ignore Case added |
| 5 | Gmail, one per branch | Course-specific welcome email with the brochure link |
| 6 | Telegram | Posts the enquiry to the counsellors' group |

The fields in "Tidy enquiry":

```text
name    {{ $json['Full name'].trim().toTitleCase() }}
phone   {{ $json['Phone number'] ? '+91' + String($json['Phone number']).replace(/\D/g, '').slice(-10) : '' }}
email   {{ $json['Email'].trim().toLowerCase() }}
course  {{ $json['Course'].trim() }}
```

The phone line keeps only digits, takes the last ten and adds +91, so "98765 43210", "+91 9876543210" and "09876543210" all become "+919876543210". `String()` is there because the trigger can deliver an all-digit cell as a number. If the cell is empty, the result is empty, not a lonely "+91". For a number written with fewer than ten digits, a later If check on the phone's length would catch it; Shalini notes that for version two.

In Remove Duplicates, the value to dedupe on is `{{ $json.phone || $json.email }}`. Deduping on phone alone would treat every student who left the phone blank as the same person, and drop all but the first.

**Testing.** Shalini pins four sample rows, chosen to be awkward, and runs the workflow from the editor:

1. **"jee" in lower case.** Before she added Ignore Case, this row went down the NEET branch. Now it goes to JEE.
2. **No phone number.** The phone is empty, as planned. But the Telegram message read "Phone: " with nothing after it. She changes that line to `{{ $('Tidy enquiry').item.json.phone || 'not given, reply by email' }}`.
3. **Blank names in Telegram.** All four alerts showed an empty name. Telegram sits after Gmail, so `$json.name` was reading Gmail's output. Naming "Tidy enquiry", as in the line above, fixed every field.
4. **The same student twice,** once as "98765 43210" and once as "+91 9876543210". Remove Duplicates only remembers values from previous runs, so she tests this by sending the two rows in two separate runs. The second is dropped. Editor runs record values too, so a rerun of the same pinned rows drops them all as repeats. For the other tests she empties the node's memory before each rerun with its **Clear Deduplication History** operation, and she uses made-up numbers in her samples so no real student is ever blocked.

**Publishing.** She builds an error workflow, Error Trigger then Telegram to herself, publishes it and selects it in the admissions workflow's settings. Then she publishes the admissions workflow. Rows already in the sheet do not fire, which is what she wants: those students were called already.

For example, suppose the first week looks like this. The numbers are an illustration of what to measure, not a measured result:

| Measure | Before | After |
| --- | --- | --- |
| Enquiry to welcome email | Next day, by hand | Within a minute or two |
| Enquiry to a counsellor's call | Next morning | Same day, in working hours |
| Repeat enquiries emailed twice | Often | Rare: repeats from earlier runs are dropped |
| Silent failures | Not noticed | Each one alerts Shalini with a link |

The trade-off she accepts: a student who genuinely enquires twice, say for JEE and then for NEET, is dropped the second time. If counsellors want to see those, she can send the duplicates to a "repeat enquiry" Telegram message instead of dropping them, by checking a log sheet before the If node.

## Common mistakes

- **Testing on the live responses sheet without pinning.** An editor run of the Sheets trigger returns every row, and the Gmail node emails them all. Pin samples or use a copy.
- **Reading `$json` after a node that replaced it.** After Gmail or Telegram, name the earlier node: `$('Tidy enquiry').item.json`.
- **Forgetting that Edit Fields drops what you do not set.** Set every field later nodes need, or turn on Include Other Input Fields.
- **Case-sensitive comparisons.** Add the If node's Ignore Case option, or compare tidied, lower-case values.
- **Deduping before tidying, or on a field that can be empty.** Normalise first, and fall back to a second field.
- **Editing the responses sheet.** Deleting or sorting rows breaks the trigger's row count, so new enquiries can be missed.
- **Saving instead of publishing.** In n8n 2.0, a saved workflow is a draft. If no production runs appear, check that you clicked Publish.
- **No error workflow.** Without one, a failed run waits in the executions list until someone happens to look.
- **Leaving the time zone on the default** on a self-hosted instance. Set Asia/Kolkata.

## Practice

Watch the Kevin Stratvert beginner video in the Watch & learn panel, do n8n's "Build your first workflow" quickstart, then take n8n's free N8N101 Essentials course, linked below.

1. **Run it.** Start n8n, either the Cloud trial or the Docker command above, and connect one Google account.
2. **Build.** Make a Google Form and build Shalini's workflow, or one for your own case: a trigger, an Edit Fields node, Remove Duplicates, an If branch and two app actions. Name every node.
3. **Break it.** Pin four awkward rows: a lower-case course, an empty phone, a phone with spaces and a repeat. Predict each node's output, run, and fix each failure, clearing the Remove Duplicates history before you rerun the same rows.
4. **Publish safely.** Add an error workflow, publish both, then break the main workflow on purpose and confirm the alert arrives with a working link.

**You are done when you can** explain each node's input and output, show one automatic run in the executions list, and show the alert from a failed run.
