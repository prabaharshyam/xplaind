## What it is

**n8n** (pronounced "n-eight-n") is a workflow automation tool with a visual editor. You place **nodes** on a canvas and connect them: a trigger node starts the workflow, and each following node does one thing, such as reading a sheet, calling an app, transforming data, branching on a condition or calling an AI model. Data flows from node to node as a list of **items**, each a small JSON record.

You can use n8n's hosted cloud version or run it yourself (for example with Docker), which many companies prefer for data control.

## How it works

**Triggers.** Common ones: a schedule (every day at 9 am), a webhook (another app calls a URL), a new email, a new form submission, a new row in Google Sheets, a manual trigger for testing.

**Nodes.** App nodes (Gmail, Google Sheets, Slack, Telegram, HubSpot, hundreds more), core nodes (HTTP Request for any API, Code, Set or Edit Fields, If, Switch, Merge, Loop), and AI nodes.

**Credentials.** Each app node needs a credential, usually by signing in with OAuth or pasting an API key. n8n stores them encrypted and reuses them across workflows. Use accounts with only the access the workflow needs.

**Mapping data.** In a node's settings you pick fields from earlier nodes, either by dragging them in or with expressions such as `{{ $json.email }}`. The output panel shows exactly what each node produced, which makes debugging easy.

**Testing.** Run the workflow step by step with sample data, inspect each node's input and output, and fix mapping problems. Pin test data on the trigger so you can rerun without sending a new email each time.

**Activating.** When it works, turn the workflow on. Production triggers then run automatically. The executions list shows every run with its data and any errors.

## A worked example

Shalini, who manages admissions for a coaching institute in Jaipur, gets enquiries through a Google Form. She builds her first workflow:

1. **Google Sheets trigger**: fires when a new row is added to the form's response sheet.
2. **Edit Fields node**: tidies the data: trims spaces, formats the phone number with +91, capitalises the name.
3. **If node**: is the course "JEE" or "NEET"?
4. **Gmail node** on each branch: sends a course-specific welcome email with the brochure link, using the student's name.
5. **Telegram node**: posts "New JEE enquiry: Rohan Sharma, +91 98xxxxxx45, prefers evening batch" to the counsellors' group.

She tests with three sample rows, notices the If node fails when students write "jee" in lower case, and fixes it by comparing in lower case. She activates the workflow. The next morning, the executions list shows 14 successful runs, and counsellors called new students within the hour instead of the next day.

## Common mistakes

- **Testing only the happy path.** Try empty fields, unusual spellings and duplicates.
- **Using your personal admin account for credentials.** Use a dedicated account with limited access.
- **Hard-coding values that change.** Keep things like email templates or team chat IDs in one place you can edit.
- **Forgetting to activate.** A workflow that only runs in test mode does nothing for users.
- **No error alert.** Add one before relying on it (covered in later lessons).

## Practise

Do n8n's quickstart, then the Level one text course.

1. Build a workflow with a trigger, at least one data-tidying node, a branch and two app actions, using test data.
2. Break it on purpose with three bad inputs (missing field, odd spelling, duplicate) and fix each.
3. Activate it and check the executions list after a few real or simulated runs.

**You are done when you can** explain each node's input and output in your workflow and show a successful automatic run.
