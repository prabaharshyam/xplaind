## What it is

When you automate a workflow for yourself or a client, the first real decision is **which tool**. Four tools cover most of the automation work you will meet in Indian businesses:

| Tool | In one line | Counts usage in | Typical user |
| --- | --- | --- | --- |
| **Zapier** | The best-known no-code tool: very easy, a huge catalogue of app connectors, workflows ("Zaps") mostly in a straight line with some branching | Tasks (each action step) | Small businesses and non-technical teams |
| **Make** (formerly Integromat) | A visual canvas with more control over data, routers, loops and error handling, still no-code | Credits (each module, per item) | Operations teams who outgrow Zapier |
| **n8n** | A visual tool for more technical users, with code nodes, an HTTP node for any API and strong AI agent features. Source-available and self-hostable | Executions (each whole run) | Developers, startups, companies with strict data rules |
| **Microsoft Power Automate** | Part of Microsoft's Power Platform, tied closely to Microsoft 365, Teams and SharePoint, with desktop RPA for old Windows apps | User and bot licences | Companies already on Microsoft with an IT team |

**A licence fact that matters for consultants.** n8n is often called open source. It is not. It uses n8n's own **Sustainable Use License** (n8n calls this "fair-code"): you can see and change the code and use it for your own business. Building workflows for a paying client is allowed. Hosting n8n so that clients log in and build on it, or selling it under your own brand, needs a commercial agreement with n8n. Read the current licence before you design a service around it.

Others exist, such as Google's tools for Workspace and enterprise integration platforms, but these four come up most often.

There is no best tool in general. There is a best tool **for a given client**, and the skill this lesson teaches is choosing it on evidence rather than habit.

```flow
title: First questions to ask a client
Start -> Already on Microsoft 365 with an IT team?
Already on Microsoft 365 with an IT team? -[yes]-> Power Automate
Already on Microsoft 365 with an IT team? -[no]-> Must data stay in your own servers?
Must data stay in your own servers? -[yes, and developers]-> Self-hosted n8n
Must data stay in your own servers? -[no]-> Who will maintain it?
Who will maintain it? -[non-technical staff]-> Zapier
Who will maintain it? -[no-code operations person]-> Make
Who will maintain it? -[developers]-> n8n Cloud
```

Treat this as a first sketch, not a rule. Volume and cost, below, can overturn it.

## How it works

Compare tools on seven factors. The first three decide how pleasant the build is. The last four decide whether the client is still happy in a year.

### 1. Ease of use

Zapier is easiest to start. Make is a step up in flexibility with a moderate learning curve. n8n suits people comfortable with JSON (the text format apps use to pass data) and a little code. Power Automate is easy for simple Microsoft 365 flows and becomes complex for advanced ones.

### 2. Connectors

A **connector** is a ready-made integration with an app. Zapier and Make have the widest catalogues for popular SaaS apps. n8n has many, plus an HTTP Request node that can talk to anything with an API. Power Automate is strongest with Microsoft products; it has connectors for many others, but some are **premium** connectors that need a paid Power Automate licence.

**Gotcha.** Check the exact action you need, not just the app's logo. A connector may exist but lack the one action the client needs, such as "update a row" or "attach a file".

### 3. AI features

All four now offer AI steps: calling models, extracting data, classifying and agent-like features. n8n is particularly strong for building custom AI agents. Power Automate links to Microsoft's AI services and Copilot.

**Gotcha.** An AI step sends the data to a model provider. A client who says "data must stay with us" usually means the model call too, not just the workflow tool.

### 4. Pricing model: count in each tool's unit

Each tool counts usage in a different unit, so first turn one run of the workflow into that unit:

| Tool | Unit | One run of a trigger plus four actions | Watch out for |
| --- | --- | --- | --- |
| Zapier | Task: each successful action step | 4 tasks (the trigger, Filter and Formatter steps are free) | Long Zaps multiply the count |
| Make | Credit: each module, for each item it handles | 5 credits (the trigger uses one too) | Loops over items, AI modules, and polling triggers |
| n8n | Execution: one whole run, however many steps | 1 execution | Many short workflows add up |
| Power Automate | Licence per user or per bot | Covered by the user's licence, within daily action limits | Premium connectors and desktop RPA need paid licences |

**The polling trap in Make.** A **polling** trigger checks an app on a timer for new items. Make charges one credit for every check, even when nothing is new. A trigger that checks every 15 minutes runs 4 × 24 × 30 = 2,880 times in a 30-day month, so it uses 2,880 credits before any work is done. An **instant** trigger (a webhook, where the app sends the data the moment it arrives) avoids this.

**Prices change.** Always take prices from the live price pages, in the currency shown, and write down the date you checked. Zapier lists prices in US dollars, n8n in euros, and Microsoft India in rupees with GST extra. Convert at one stated exchange rate before you compare.

### 5. Data control

Know where each tool keeps the data that passes through it:

| Tool | Where data is processed, as the vendor describes it |
| --- | --- |
| Zapier | On Amazon servers in the United States; you cannot choose another region |
| Make | In a US or EU data centre that you choose per organisation and cannot change later; some AI features route elsewhere |
| n8n Cloud | n8n's site says hosted plans store data in Frankfurt, Germany |
| Self-hosted n8n | Wherever you run it, including a cloud region in India |
| Power Automate | In the region of the client's Power Platform environment; India is one of the regions |

**In India.** The Digital Personal Data Protection Act, 2023 (DPDP Act) makes the client a **Data Fiduciary** for its customers' personal data. Any tool that processes that data for the client is a **Data Processor**, and the Act lets a fiduciary use a processor only under a valid contract. So for Zapier, Make or n8n Cloud, the client should accept the vendor's data processing agreement and keep a copy. The DPDP Rules were notified in November 2025, with most duties applying from May 2027. The Act does not, in general, demand that data stay in India, but a sector regulator, such as the Reserve Bank of India for payment data, or the client's own contracts may. Ask the client's compliance team which applies; do not decide it yourself.

### 6. Lock-in and debugging

**Lock-in.** A workflow built in one tool cannot be moved to another. n8n and Make can save a workflow as a JSON file, and Power Automate as a .zip package, but each file only imports back into the same tool. Switching later means a rebuild, so choose as if the choice will last.

**Debugging.** Workflows fail: an API is down, a field is empty, a password expires. All four keep a run history showing each step's input and output, and each can retry failed runs in some way. Zapier can replay failed steps. Make can store an **incomplete execution** so you can fix the data and resume it. n8n lets you attach an **error workflow** that alerts someone when a run fails. Power Automate shows run history and lets you resubmit a run. Before you hand over, set up an alert that reaches a named person; a failure nobody sees is the most common way automations quietly die.

### 7. Fit and maintenance

The strongest factor is often what the client already has. A company on Microsoft 365 with IT governance will usually prefer Power Automate and may already pay for it. A startup that lives in SaaS apps may prefer Zapier or Make. A company with strict data rules or heavy AI needs may prefer self-hosted n8n.

And always ask: **who will maintain it when you leave?** The best tool is one the client's own people can keep running.

### Total cost of ownership

Add it all up as **TCO**, total cost of ownership:

```text
  TCO per month = licence or usage fees
                + servers (if self-hosted)
                + setup time, spread over the first year
                + maintenance hours each month x hourly cost
                + training for the people who will run it
```

A tool with no licence fee can have the highest TCO if nobody on the client's side can maintain it.

## A worked example

Three clients, three different choices, and one full cost check.

**A chartered accountancy firm in Chennai.** Twenty-five staff, Gmail, Google Sheets and a few SaaS tools. When a new client fills in the intake form, the workflow creates a Drive folder, creates a task, adds a row to the client sheet and sends a welcome email: one trigger and four actions. About 150 runs a month. No technical staff. **Choice: Zapier.** It is the fastest to build and the easiest for their office manager to maintain.

**A manufacturer in Pune.** On Microsoft 365, with a five-person IT team. They need purchase approvals in Teams, and data copied into an old Windows inventory application that has no API. **Choice: Power Automate.** Cloud flows handle the approvals in Teams, and desktop RPA handles the inventory app. Everything sits under existing Microsoft governance.

**A health-tech startup in Bengaluru.** It processes 20,000 patient intake forms a month with AI extraction, and its data rules say patient data must stay in its own cloud account. Its developers like to extend tools with code. **Choice: self-hosted n8n** in their own cloud account, with the AI model also running inside that account. There are no per-run fees, data stays in their environment, and developers can add custom nodes.

| Factor | Chennai CA firm | Pune manufacturer | Bengaluru health-tech |
| --- | --- | --- | --- |
| Volume | About 150 runs a month | About 2,000 runs a month | About 20,000 runs a month |
| Apps | Google Workspace, SaaS | Microsoft 365, old Windows app | Own cloud, custom apps |
| Data rules | Normal | Company IT policy | Patient data must stay in-house |
| Maintainer | Office manager | IT team | Developers |
| Tool | Zapier | Power Automate | Self-hosted n8n |

### Step 1: count units for the Chennai workflow

Using the unit table above, one run is 4 Zapier tasks, 5 Make credits (with an instant trigger) or 1 n8n execution. Now multiply by volume:

| Runs a month | Zapier tasks | Make credits | n8n executions |
| --- | --- | --- | --- |
| 150 (today) | 600 | 750 | 150 |
| 2,000 | 8,000 | 10,000 | 2,000 |
| 20,000 | 80,000 | 100,000 | 20,000 |

### Step 2: find the plan that fits (prices as of 28 November 2026)

- **Zapier.** The Professional plan starts at $19.99 a month, billed yearly, for 750 tasks. Today's 600 tasks fit.
- **n8n Cloud.** The Starter plan is €20 a month, billed yearly, for 2,500 executions. Today's 150 executions fit, and so would 2,000.
- **Make.** Make's plans and credit tiers were changing when we checked, and published figures disagreed, so we quote no Make price here. Read make.com's price page on the day you quote.

At 150 runs, the two entry plans cost about the same, so the decision rests on who maintains it, and Zapier wins. At 2,000 runs the picture changes: Zapier needs more than ten times its entry task allowance, while n8n's Starter plan still fits. At 20,000 runs, check n8n's larger cloud plans against self-hosting. This is why you count units before you compare prices.

### Step 3: the Pune licence choice

The Teams approvals use standard connectors (Teams, Approvals, SharePoint, Outlook), which the staff's Microsoft 365 licences already cover. The RPA part is where the money is, and it depends on one distinction:

- **Attended RPA** runs on a computer where a person is signed in, usually started by them while they work.
- **Unattended RPA** runs on its own on a machine with nobody signed in, for example every night at 11 p.m.

Microsoft India's list prices, billed yearly, GST extra, checked 28 November 2026:

| Option | Licence | Cost |
| --- | --- | --- |
| Three storekeepers each click "run" after entering a purchase | Power Automate Premium (includes attended RPA), ₹1,250 per user a month | 3 × ₹1,250 = ₹3,750 a month, ₹45,000 a year |
| One bot copies the day's entries every night on the client's own PC | Power Automate Process (unattended), ₹12,480 per bot a month | ₹1,49,760 a year |
| The same bot on a virtual machine that Microsoft runs | Power Automate Hosted Process, ₹17,885 per bot a month | ₹2,14,620 a year |

If the storekeepers do not mind clicking "run", attended RPA is far cheaper. If the copy must happen without anyone present, budget for a Process licence. Microsoft says prices shown are for marketing and the real price appears at checkout, so confirm with the client's Microsoft partner.

### Step 4: the Bengaluru TCO

Self-hosted n8n has no fee per run, but it is not free. Suppose, only as an illustration, a cloud server costs ₹3,000 a month and a developer spends 4 hours a month on updates, backups and failed runs at ₹1,000 an hour. TCO is about ₹3,000 + ₹4,000 = ₹7,000 a month, before setup and the AI model's own cost. People-time is already the larger part, and it is the part clients forget.

For each client you then write a one-page recommendation: the tool, cost at expected volume with the date you checked each price, where data is processed, and who maintains it.

## Common mistakes

- **Choosing by personal preference.** Choose by the client's apps, skills, volume and data rules.
- **Comparing headline prices instead of units.** Convert one run into tasks, credits or executions first, then find the plan.
- **Forgetting that Make's polling triggers use credits.** A 15-minute check costs about 2,880 credits a month with zero new items. Use an instant trigger where you can.
- **Calling n8n open source.** It is source-available. Hosting it for clients to use needs a deal with n8n.
- **Forgetting the AI step's data path.** Self-hosting the workflow does not help if the model call sends the data outside.
- **Buying unattended RPA when attended would do.** A per-bot licence costs about ten times a per-user one.
- **Overlooking existing licences.** Many business Microsoft 365 plans already include cloud flows with standard connectors.
- **Self-hosting without an owner.** Servers need security updates, backups and monitoring.
- **No failure alert.** If a failed run does not reach a named person, the automation will quietly stop working.
- **Quoting old prices.** Check current price pages and record the date.

## Practice

Do one Microsoft Learn module on Power Automate, linked below, and browse Zapier's guides; compare with what you know of n8n.

1. **Build twice.** Build the same simple workflow, such as form to sheet to email, in two tools. Note the time taken, any difficulties, and how a failed run is shown to you.
2. **Count, then cost it.** Take a workflow with one trigger and five actions. Convert one run into Zapier tasks, Make credits and n8n executions. Then find the plan that fits at 200, 2,000 and 20,000 runs a month on two tools, using today's price pages. Write down the date you checked.
3. **Recommend.** Write a one-page recommendation for a client of your choice, covering fit, cost at expected volume, where data is processed, lock-in and who will maintain it.

**You are done when you can** recommend a tool for a described client and defend the choice on cost, data and maintenance, with a dated price for every number you quote.
