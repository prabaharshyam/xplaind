## What it is

When you automate a workflow for yourself or a client, the first real decision is **which tool**. Four tools cover most of the automation work you will meet in Indian businesses:

| Tool | In one line | Typical user |
| --- | --- | --- |
| **Zapier** | The best-known no-code tool: very easy, huge catalogue of app connectors, workflows ("Zaps") mostly linear with some branching | Small businesses and non-technical teams |
| **Make** (formerly Integromat) | A visual canvas with more control over data, branching and loops, still no-code | Operations teams who outgrow Zapier |
| **n8n** | A visual tool for more technical users, open source and self-hostable, with code nodes and strong AI and agent features | Developers, startups, companies with strict data rules |
| **Microsoft Power Automate** | Part of Microsoft's Power Platform, deeply tied to Microsoft 365, Teams, SharePoint and Dynamics, with desktop RPA | Companies already on Microsoft with an IT team |

Others exist, such as Google's tools for Workspace, enterprise integration platforms and other open-source options, but these four come up most often.

There is no best tool in general. There is a best tool **for a given client**, and the skill this lesson teaches is choosing it on evidence rather than habit.

```text
   Client's situation                         Tool that usually fits
 +---------------------------------+       +----------------------+
 | SaaS apps, low volume, no IT    | ----> | Zapier or Make       |
 | Microsoft 365, IT rules, old    | ----> | Power Automate       |
 |   Windows apps                  |       |                      |
 | High volume, strict data rules, | ----> | Self-hosted n8n      |
 |   developers, heavy AI          |       |                      |
 +---------------------------------+       +----------------------+
```

This lesson follows three clients, in Chennai, Pune and Bengaluru, each with a different best answer.

## How it works

Compare tools on six factors.

### 1. Ease of use

Zapier is easiest to start. Make is a step up in flexibility with a moderate learning curve. n8n suits people comfortable with JSON and a little code. Power Automate is easy for simple Microsoft 365 flows and more complex for advanced ones.

### 2. Connectors

A **connector** is a ready-made integration with an app. Zapier and Make have the widest catalogues for popular SaaS apps. n8n has many, plus an HTTP Request node that can talk to anything with an API. Power Automate is strongest with Microsoft products and has connectors for many others, some only at premium licence levels.

### 3. AI features

All four now offer AI steps: calling models, extracting data, classifying and agent-like features. n8n is particularly strong for building custom AI agents. Power Automate links to Microsoft's AI services and Copilot.

### 4. Pricing model

Each tool counts usage differently:

| What is counted | Meaning | Watch out for |
| --- | --- | --- |
| Tasks or actions | Each successful step in a run | Long workflows multiply the count |
| Operations or credits | Each module action, including loops (Make now bills in credits) | Loops over many items add up fast |
| Executions | Each full run of a workflow | Cheap for long workflows, pricier for many short ones |
| User and flow licences | Per person or per flow, often within Microsoft 365 | Premium connectors may need a higher licence |
| Self-hosting | Your own server and maintenance | No usage fee, but real people-time |

A workflow that is cheap at 100 runs a day can be expensive at 10,000 on one tool and cheap on another. Always estimate at expected volume using the current price pages, and write down the date you checked, because prices change.

### 5. Data control

Zapier and Make are cloud services, so check where data is processed and stored. n8n can run entirely on the client's own servers or cloud account. Power Automate runs within the client's Microsoft tenant and its governance. For health, finance or government clients this can decide the choice on its own.

### 6. Fit and maintenance

The strongest factor is often what the client already has. A company on Microsoft 365 with IT governance will usually prefer Power Automate and may already pay for it. A startup living in SaaS apps may prefer Zapier or Make. A company with strict data rules or heavy AI needs may prefer self-hosted n8n.

And always ask: **who will maintain it when you leave?** The best tool is one the client's own people can keep running.

### Total cost of ownership

Add it all up as **TCO**, total cost of ownership:

```text
  TCO = licence or usage fees
      + servers (if self-hosted)
      + setup time
      + maintenance time each month
      + training for the people who will run it
```

A tool with no licence fee can have the highest TCO if nobody on the client's side can maintain it.

## A worked example

Three clients, three different choices.

**A chartered accountancy firm in Chennai.** Twenty-five staff, Gmail, Google Sheets and a few SaaS tools. They want automatic reminders to clients for missing documents, and an intake form that creates a folder and a task for each new client. About 150 runs a month. No technical staff. **Choice: Zapier.** It is the fastest to build and the easiest for their office manager to maintain.

**A manufacturer in Pune.** On Microsoft 365, with a five-person IT team. They need purchase approvals in Teams, and data copied into an old Windows inventory application that has no API. **Choice: Power Automate.** Cloud flows handle the approvals in Teams; desktop RPA (robotic process automation, which clicks and types in the old app's screens like a person) handles the inventory app. Everything sits under existing Microsoft governance. Cloud flows with standard connectors are covered by most Microsoft 365 plans, but running desktop RPA from a cloud flow needs a Power Automate Premium or process licence, so cost that too.

**A health-tech startup in Bengaluru.** It processes 20,000 patient intake forms a month with AI extraction, and its data rules say patient data must stay in its own cloud account. Its developers like to extend tools with code. **Choice: self-hosted n8n** in their own cloud account. No per-task fees at that volume, data stays in their environment, and developers can add custom nodes.

| Factor | Chennai CA firm | Pune manufacturer | Bengaluru health-tech |
| --- | --- | --- | --- |
| Volume | ~150 runs a month | ~2,000 runs a month | ~20,000 runs a month |
| Apps | Google Workspace, SaaS | Microsoft 365, old Windows app | Own cloud, custom apps |
| Data rules | Normal | Company IT policy | Patient data must stay in-house |
| Maintainer | Office manager | IT team | Developers |
| Tool | Zapier | Power Automate | Self-hosted n8n |

## Common mistakes

- **Choosing by personal preference.** Choose by the client's apps, skills, volume and data rules.
- **Ignoring pricing at scale.** Estimate at real volume, not the free tier.
- **Forgetting maintenance.** Who will fix it when you leave?
- **Overlooking existing licences.** Many Microsoft 365 plans already include Power Automate for flows with standard connectors.
- **Self-hosting without an owner.** Servers need updates, backups and monitoring.
- **Quoting old prices.** Check current price pages and record the date.

## Practise

Do one Microsoft Learn module on Power Automate, linked below, and browse Zapier's guides; compare with what you know of n8n.

1. **Build twice.** Build the same simple workflow, such as form to sheet to email, in two tools. Note the time taken and any difficulties.
2. **Cost it.** For a workflow at 200, 2,000 and 20,000 runs a month, estimate the cost on two tools using their current price pages. Write down the date you checked.
3. **Recommend.** Write a one-page recommendation for a client of your choice, covering fit, cost, data and maintenance.

**You are done when you can** recommend a tool for a described client and defend the choice on cost, data and maintenance.
