## What it is

A cyber attack is any attempt to misuse a computer system: to read what you should not, change what you should not, or stop it working. Before you can defend, you need a shared vocabulary for three questions: **what are we protecting**, **who are we protecting it from**, and **how do attacks actually unfold**.

**What we protect: the CIA triad.** Security has three goals.

- **Confidentiality**: only the right people can see the data. A leak of Aadhaar numbers from a hospital database breaks confidentiality.
- **Integrity**: data and systems are not changed without permission. An attacker quietly editing the beneficiary account on a UPI payout file breaks integrity.
- **Availability**: systems work when people need them. A railway booking site knocked offline by a flood of traffic during Tatkal hours breaks availability.

Every control you will learn protects one or more of these. When you assess a risk, ask which of the three it threatens.

**Who attacks: threat actors.** A threat actor is a person or group that may attack you. Their motive shapes what they do.

| Threat actor | Usual motive | Typical behaviour |
| --- | --- | --- |
| Criminal groups | Money | Phishing, ransomware, selling stolen data, payment fraud |
| Insiders | Grudge, money or carelessness | Misusing their access, or leaking data by mistake |
| Hacktivists | A cause or protest | Defacing websites, leaking documents, flooding sites |
| State-backed groups | Espionage or disruption | Patient, well-funded, long campaigns against government and infrastructure |
| Opportunists | Curiosity or easy wins | Running public tools against anything exposed to the internet |

Most organisations in India deal mainly with criminals, insiders and opportunists. Assume automated scanners will find any server you put online, often quickly.

**Where they get in: the attack surface.** The attack surface is every place an attacker could try. For a typical company it includes internet-facing servers and open ports, login pages, APIs, file uploads, staff email and phones, laptops, cloud accounts, suppliers and the open-source libraries in your code. AI apps add new entries: every prompt, every document the model reads, and every tool an agent can call. **Shrinking the attack surface** (closing unused ports, removing old accounts, deleting unused features) is one of the cheapest defences there is.

## How it works

**Vulnerability, exploit, CVE.** Three words people mix up:

- A **vulnerability** is a weakness: a bug in code, a misconfiguration, a default password, or a process gap such as "anyone who calls the helpdesk can reset a password".
- An **exploit** is code or a technique that takes advantage of a vulnerability to make the system do something it should not.
- A **CVE** (Common Vulnerabilities and Exposures) is a public ID for a known vulnerability in a product, such as CVE-2021-44228, the Log4j flaw ("Log4Shell"). The CVE Program assigns the IDs; databases such as the US National Vulnerability Database add a severity score (CVSS, 0 to 10) and links to fixes.

A vulnerability with a public exploit and an internet-facing target is urgent. That is why teams watch advisories from vendors and from CERT-In, India's national computer emergency response team, and patch the riskiest items first.

**The attack lifecycle.** Real attacks are rarely one step. Lockheed Martin's **cyber kill chain** describes seven stages. Other models exist (MITRE ATT&CK, covered later in this roadmap, is more detailed), but the kill chain is the easiest way to start thinking like a defender.

```flow
title: The cyber kill chain, with a defence at each stage
1 Reconnaissance | attacker studies staff, domains, open ports -> 2 Weaponisation
2 Weaponisation | builds a malicious file or fake login page -> 3 Delivery
3 Delivery | phishing email, infected download, exposed service -> 4 Exploitation
4 Exploitation | a vulnerability or a tricked user runs the code -> 5 Installation
5 Installation | malware or a backdoor account for persistence -> 6 Command and control
6 Command and control | the implant calls home for instructions -> 7 Actions on objectives
7 Actions on objectives | steal data, encrypt files, move to other systems -> Impact on confidentiality, integrity or availability
```

| Stage | What the defender can do |
| --- | --- |
| Reconnaissance | Reduce what is public, close unused ports, watch for scanning |
| Weaponisation | Little direct control; threat intelligence helps you prepare |
| Delivery | Email filtering, blocking risky attachments, staff awareness |
| Exploitation | Patching, MFA, secure configuration, input validation |
| Installation | Endpoint protection, application allow-lists, least privilege |
| Command and control | Outbound firewall rules, DNS filtering, alerts on beaconing |
| Actions on objectives | Data loss prevention, backups, segmentation, monitoring |

The lesson of the kill chain is that **the defender gets several chances**. You do not need to stop every stage; you need to stop one, and the earlier the better. This is **defence in depth**: layers of independent controls so that one failure does not become a breach.

**Why AI changes the game a little.** The basics above do not change, but AI shifts the balance in a few ways:

- **Cheaper, better lures.** Language models write fluent phishing in English, Hindi, Tamil or any language, without the spelling mistakes people were taught to look for. Voice cloning makes "your CEO on the phone" scams more believable.
- **Faster reconnaissance and coding.** Attackers can summarise public information and adapt known exploit code more quickly.
- **New targets.** Models, prompts, training data, vector databases and AI agents with tools are now part of the attack surface. Prompt injection, data poisoning and model theft are covered in later stages.
- **Defenders get AI too.** The same tools help triage alerts, read logs and spot anomalies, which is half of this roadmap.

Treat AI as an amplifier of existing attacks plus a new set of assets to protect, not as magic.

## A worked example

A hypothetical online sweet shop in Indore sells across India. It has a website with customer accounts, a WordPress blog, an admin panel and a payments integration with a gateway. Its owner asks a security-minded friend: "Where would someone attack us?"

They list the attack surface:

```text
shop.example.com        web store, customer login, order history
blog.example.com        WordPress, 14 plugins, 3 not updated in a year
admin.example.com       admin panel, reachable from the internet, password only
203.0.113.25:22        SSH on the server, password login allowed
staff email            4 people, no MFA
```

Then they think through one likely attack using the kill chain. An opportunist's scanner finds the old WordPress plugin (reconnaissance). The plugin has a published CVE and a public exploit (weaponisation is already done for them). The scanner sends the exploit to the blog (delivery, exploitation). It installs a web shell (installation) that waits for commands (command and control). From there the attacker reads the database password from the blog's config file and copies customer addresses and phone numbers (actions on objectives: a confidentiality breach).

Their fixes, cheapest first: update or remove the old plugins, put the admin panel behind a VPN or IP allow-list, turn on MFA for staff email and the admin panel, switch SSH to keys only, and give the blog its own database user that cannot read the shop's tables. Five changes, and the most likely path is closed at several stages.

## Common mistakes

- **Thinking "we are too small to be attacked".** Many attacks are automated and opportunistic; scanners do not care how big you are.
- **Mixing up vulnerability and exploit.** A scanner finding is a possible weakness; whether it can be exploited, and how badly, is a separate question.
- **Ranking only by CVSS score.** A medium-severity flaw on an internet-facing login page can matter more than a critical one on an isolated test machine.
- **Relying on one control.** A firewall alone, or antivirus alone, is a single point of failure.
- **Forgetting availability.** Backups and recovery plans are security controls too; ransomware is an availability attack.
- **Treating AI threats as separate from security basics.** Many AI incidents still involve stolen credentials, exposed keys or missing access checks.
