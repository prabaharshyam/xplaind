## What it is

Programs rarely work with one value at a time. A day has many orders, a class has many students, a shop has many products. Python's two workhorse collections hold many values:

- **Lists** are ordered sequences, reached by position. Good for "many of the same kind of thing, in order": a day's orders, a list of marks.
- **Dictionaries** are key and value lookups. Good for "find the value for this key quickly": marks by roll number, a customer's details by field name.

Two more come up often:

- **Tuples** are fixed, unchangeable sequences, like a latitude and longitude pair.
- **Sets** are unordered collections of unique items, handy for removing duplicates.

```text
  list        ["Pune", "Kochi", "Jaipur"]          by position: [0] [1] [2]
  dict        {"K101": 78, "K102": 64}             by key:      ["K101"]
  tuple       (18.52, 73.86)                       fixed pair, cannot change
  set         {"a@x.in", "b@y.in"}                 unique, no order
```

Nesting them models most real data. A list of dictionaries is a table; each dictionary is one row. That is exactly the shape of the **JSON** that APIs and AI models send back, so being comfortable with nested lists and dictionaries is a core AI skill.

This lesson follows the office of a coaching centre in Kota as it turns a list of test results into instant answers for parents. By the end you will choose the right structure for a task and read nested data with ease.

## How it works

### Lists

```python
nums = [3, 1, 2]
nums.append(5)            # [3, 1, 2, 5]
print(len(nums))          # 4
print(nums[0], nums[-1])  # 3 5   (first and last)
print(sorted(nums))       # [1, 2, 3, 5]
print(nums[1:3])          # [1, 2]  (a slice: from position 1 up to, not including, 3)
```

Loop with `for n in nums:`. Build new lists with a **list comprehension**, a compact loop that makes a list:

```python
doubled_big = [n * 2 for n in nums if n > 1]    # [6, 4, 10]
```

### Dictionaries

```python
marks = {"asha": 80, "ravi": 72}
marks["meena"] = 91              # add a new key
print(marks["asha"])             # 80
print(marks.get("john", 0))      # 0: a default instead of an error
for name, score in marks.items():
    print(name, score)
```

Looking up a missing key with square brackets raises a `KeyError`; `get` returns a default instead. Lookups by key are fast even with millions of entries, because a dictionary jumps straight to the key instead of searching.

### Choosing the right one

| You need | Use | Example |
| --- | --- | --- |
| Order, or reach things by position | List | A queue of customers |
| Find things by an identifier | Dictionary | Price by product code |
| Unique items, fast "is it in here?" | Set | Unique email addresses |
| A small fixed group of values | Tuple | A shop's coordinates |
| A table of records | List of dictionaries | Today's sales |
| Values grouped by a category | Dictionary of lists | Students by city |

### Why searching a list is slow

```text
  Find roll "K9000" in a list of 10,000 records:
    check [0]? no  check [1]? no  ...  check [8999]? yes   -> up to 10,000 checks

  Find roll "K9000" in a dictionary keyed by roll:
    jump straight to "K9000"                               -> about 1 step
```

If you look up the same kind of identifier many times, build a dictionary once and reuse it.

### Nesting

```python
cities = {
    "Pune":   [{"name": "Asha", "marks": 80}],
    "Nagpur": [{"name": "Ravi", "marks": 72}, {"name": "Meena", "marks": 91}],
}
print(cities["Nagpur"][1]["name"])     # Meena
```

Read nested access from left to right: the "Nagpur" list, its second item, that item's "name".

### From JSON to Python and back

When an API or an AI model returns JSON, Python's `json` module turns it into lists and dictionaries, and back again:

```python
import json
text = '{"city": "Pune", "pins": ["411001", "411002"]}'
data = json.loads(text)          # now a dictionary
print(data["pins"][0])           # 411001
print(json.dumps(data, indent=2))  # back to neatly formatted JSON text
```

JSON objects become dictionaries, JSON arrays become lists, `true` and `false` become `True` and `False`, and `null` becomes `None`.

### Copying

`b = a` does **not** copy a list. Both names point to the same list, so changing one changes what the other sees:

```python
a = [1, 2]
b = a
b.append(3)
print(a)          # [1, 2, 3]  surprise!
c = a.copy()      # a real copy
```

## A worked example

A coaching centre in Kota keeps test results as a list of records, one per student:

```python
results = [
    {"roll": "K101", "name": "Asha",  "physics": 78, "chem": 85},
    {"roll": "K102", "name": "Ravi",  "physics": 64, "chem": 70},
    {"roll": "K103", "name": "Meena", "physics": 91, "chem": 88},
]

# 1. Look up by roll number quickly: build a dictionary once
by_roll = {r["roll"]: r for r in results}
print(by_roll["K102"]["name"])            # Ravi

# 2. Average per subject with a list comprehension
physics = [r["physics"] for r in results]
print(round(sum(physics) / len(physics), 1))   # 77.7

# 3. Group students by grade band
bands = {}
for r in results:
    total = r["physics"] + r["chem"]
    band = "A" if total >= 160 else "B"
    bands.setdefault(band, []).append(r["name"])
print(bands)                               # {'A': ['Asha', 'Meena'], 'B': ['Ravi']}
```

| Question from the office | Structure that answers it | Code |
| --- | --- | --- |
| "How did roll K102 do?" | Dictionary keyed by roll | `by_roll["K102"]` |
| "What is the physics average?" | List of physics marks | `sum(physics) / len(physics)` |
| "Who is in band A?" | Dictionary of lists | `bands["A"]` |

`setdefault(band, [])` returns the list for that band, creating an empty one the first time. It saves writing an `if` every time.

The office now answers parent calls like "how did roll K102 do?" instantly, instead of scrolling through a sheet of 600 students.

## Common mistakes

- **Searching a list repeatedly for an id.** Build a dictionary keyed by the id once.
- **`KeyError` on missing keys.** Use `get` with a default when a key may be absent.
- **Index out of range.** Lists start at 0; the last item is `[-1]`.
- **Accidental shared lists.** `b = a` is not a copy; use `a.copy()`.
- **Changing a list while looping over it.** Build a new list instead, for example with a comprehension.
- **Expecting sets to keep order.** If order matters, sort the result: `sorted(set(items))`.
