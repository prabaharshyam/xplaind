## What it is

Programs rarely work with one value at a time. Python's two workhorse collections are:

- **Lists**: ordered sequences, reached by position. Good for "many of the same kind of thing in order": a day's orders, a list of marks.
- **Dictionaries**: key-value lookups. Good for "find the value for this key quickly": marks by roll number, a customer's details by field name.

Two more come up often: **tuples** (fixed, unchangeable sequences, like a latitude-longitude pair) and **sets** (unordered, unique items, handy for removing duplicates). Nesting them, such as a list of dictionaries, models most real data, and it is exactly the shape of JSON that APIs and AI models return.

## How it works

**Lists.**

```python
nums = [3, 1, 2]
nums.append(5)          # [3, 1, 2, 5]
print(len(nums))        # 4
print(nums[0], nums[-1])  # 3 5  (first and last)
print(sorted(nums))     # [1, 2, 3, 5]
print(nums[1:3])        # [1, 2]  (a slice)
```

Loop with `for n in nums:`. Build new lists with comprehensions: `[n * 2 for n in nums if n > 1]`.

**Dictionaries.**

```python
marks = {"asha": 80, "ravi": 72}
marks["meena"] = 91              # add
print(marks["asha"])             # 80
print(marks.get("john", 0))      # 0, a default instead of an error
for name, score in marks.items():
    print(name, score)
```

Looking up a missing key with square brackets raises a `KeyError`; `get` returns a default instead. Lookups by key are fast even with millions of entries.

**Choosing.** Need order or position? A list. Need to find things by an identifier (roll number, PIN code, product code)? A dictionary. Need uniqueness? A set: `set(emails)` removes duplicates.

**Nesting.** A list of dictionaries is a table: each dictionary is a row. A dictionary of lists groups values: `{"Pune": [...], "Nagpur": [...]}`.

**Copying.** `b = a` does not copy a list; both names point to the same list, so changing one changes "both". Use `a.copy()` or `list(a)`.

## A worked example

A coaching centre in Kota has test results as a list of records:

```python
results = [
    {"roll": "K101", "name": "Asha", "physics": 78, "chem": 85},
    {"roll": "K102", "name": "Ravi", "physics": 64, "chem": 70},
    {"roll": "K103", "name": "Meena", "physics": 91, "chem": 88},
]

# Look up by roll number quickly: build a dictionary once
by_roll = {r["roll"]: r for r in results}
print(by_roll["K102"]["name"])          # Ravi

# Averages per subject with a list comprehension
physics = [r["physics"] for r in results]
print(sum(physics) / len(physics))      # 77.66...

# Group students by grade band
bands = {}
for r in results:
    total = r["physics"] + r["chem"]
    band = "A" if total >= 160 else "B"
    bands.setdefault(band, []).append(r["name"])
print(bands)                             # {'A': ['Asha', 'Meena'], 'B': ['Ravi']}
```

The office now answers parent calls ("how did roll K102 do?") instantly instead of scrolling through a sheet.

## Common mistakes

- **Searching a list repeatedly for an id.** Build a dictionary keyed by the id.
- **`KeyError` on missing keys.** Use `get` with a default when a key may be absent.
- **Index out of range.** Lists start at 0; the last item is `[-1]`.
- **Accidental shared lists.** `b = a` is not a copy.
- **Changing a list while looping over it.** Build a new list instead.
