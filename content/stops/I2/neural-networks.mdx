## What it is

A **neural network** is a stack of layers. Each layer takes numbers in, multiplies them by weights, adds a bias, and passes the result through a simple non-linear function called an **activation** (such as ReLU, which turns negatives into zero). The output of one layer is the input of the next. The final layer produces the prediction: a number, or probabilities for each class.

With enough layers and units, networks can represent very complex patterns. **Deep learning** means networks with many layers.

```text
   inputs          hidden layer 1      hidden layer 2       output
   (64 features)   128 units, ReLU     64 units, ReLU       5 units, softmax

     x1 --\          o                   o                  healthy     0.05
     x2 ---+-------> o --------+-------> o ------+-------->  leaf spot   0.81
     ...  /          o         |         o       |           rust        0.08
     x64 /           ...      weights    ...    weights      blight      0.04
                                                             mildew      0.02

   forward pass  ------------------------------------------>  prediction, loss
   backpropagation  <--------------------------------------   gradient for every weight
```

This lesson follows an agritech startup in Bengaluru that classifies leaf photos by disease.

## How it works

**Forward pass.** Input features flow through the layers to produce a prediction.

**Loss.** A loss function measures how wrong the prediction is: mean squared error for numbers, cross-entropy for classes.

**Backpropagation.** Using the chain rule, the network computes how much each weight contributed to the loss, layer by layer from the output backwards. This gives the gradient for every weight.

**Gradient descent.** Each weight moves a small step against its gradient. Variants such as Adam adapt the step size per weight and usually train faster. Training happens in **batches** of examples; one pass through all the data is an **epoch**.

**Why non-linearity matters.** Without activations, stacked layers collapse into one linear model. Activations let networks bend and combine features.

**Overfitting and regularisation.** Networks with many weights can memorise training data. Watch training and validation loss together: if training loss keeps falling while validation loss rises, the network is overfitting. Remedies: more data, data augmentation, dropout (randomly switching off units during training), weight decay, smaller networks and early stopping.

**Practical settings.** Learning rate (the most important), batch size, number of layers and units, epochs. Start from known good defaults for your problem type.

**When to use them.** For images, audio, text and very large datasets, neural networks dominate. For ordinary tabular business data, gradient-boosted trees usually match or beat them with less effort.

**Counting weights.** Each connection between layers has one weight, and each unit has one bias. In the leaf network, the first hidden layer has 64 × 128 weights plus 128 biases, which is 8,320 numbers. The second has 128 × 64 + 64 = 8,256, and the output layer 64 × 5 + 5 = 325. That totals 16,901 numbers learned from data. Modern language models have billions, but the arithmetic in each layer is the same.

**Reading loss curves:**

| What you see | What it means | What to try |
| --- | --- | --- |
| Loss jumps around or grows | Learning rate too high | Lower it by a factor of 10 |
| Loss falls very slowly | Learning rate too low, or inputs unscaled | Raise it; standardise inputs |
| Training falls, validation rises | Overfitting | Dropout, weight decay, early stopping, more data |
| Both stay high | Underfitting | A bigger network, more epochs, better features |
| Both fall and level off together | Healthy | Stop at the best validation epoch |

**A training loop in words.** For each epoch, shuffle the data and split it into batches. For each batch, run the forward pass, compute the loss, run backpropagation to get gradients, and let the optimiser update the weights. After each epoch, compute the validation loss without updating weights, and save the model if it is the best so far. Every deep learning library, from PyTorch to Keras, follows this pattern.

## A worked example

A Bengaluru agritech startup classifies leaf photos as healthy or as one of four diseases. As a first step, they build a small fully connected network on 64-number features extracted from each image (colour and texture statistics) to learn the mechanics:

- input layer of 64 features → hidden layer of 128 units with ReLU → hidden layer of 64 units with ReLU → output layer of 5 units with softmax (probabilities for 5 classes);
- cross-entropy loss, Adam optimiser, learning rate 0.001, batches of 32, up to 50 epochs.

The loss curves show training loss falling steadily, while validation loss bottoms at epoch 14 and rises after. Adding dropout of 0.3 and stopping early at the best validation epoch gives 78% validation accuracy. Gradient-boosted trees on the same 64 features reach 80%.

The lesson they draw: on hand-made tabular features, the network has no edge. Their next step is a convolutional network on the raw images, which learns its own features and usually does much better. The CNN lesson covers how.

| Model | Validation accuracy |
| --- | --- |
| Network, no regularisation, 50 epochs | 74% |
| Network with dropout 0.3 and early stopping at epoch 14 | 78% |
| Gradient-boosted trees on the same 64 features | 80% |
| Convolutional network on raw images (their next step) | Expected to be much higher |

## Common mistakes

- **Learning rate too high or too low.** Watch the loss curve; it is the first thing to tune.
- **Watching only training loss.** Overfitting shows in validation loss.
- **Unscaled inputs.** Normalise features; training becomes unstable otherwise.
- **Neural networks for small tabular datasets by default.** Try boosted trees first.
- **Not fixing random seeds when comparing.** Results vary between runs; compare fairly.
