## What it is

A RAG system retrieves passages and asks a model to answer from them. Nothing forces the model to stay inside those passages. It may blend in what it learned in training, fill gaps with plausible detail, or answer a question the documents never cover. **Grounding** is the set of techniques that keep the answer tied to the sources:

- instructions that say to use only the provided passages;
- **citations** that link each claim to the passage supporting it;
- a clear **refusal** path when the passages do not contain the answer;
- a check, automatic or human, that the answer is **faithful** to its sources.

```flow
Question -> Retrieve passages | [1] Leave Policy v4, 3.2, p.6; [2] Leave Policy v4, 3.4, p.7; [3] Travel Policy v2, 1.1, p.2
Retrieve passages -> Prompt | use only these, cite ids, refuse with a next step
Prompt -> Answer | "Earned leave carries forward up to 45 days [1]. The policies do not cover sick leave carry-forward; ask hr-help."
Answer -> Checks | ids exist? quotes match? every claim supported?
```

This lesson follows an HR assistant pilot at an IT services firm in Bengaluru.

## How it works

**Mark the sources.** Put each retrieved passage in the prompt with an id and its origin, for example `[3] Leave Policy v4, section 2.1, page 6`. Ids make citations possible and debugging easy.

**Instruct precisely.** Tell the model: answer only from the passages; cite the id after each sentence that uses one; if the passages do not answer the question, say so and suggest who to ask. Show one short example of a cited answer and one of a refusal. Models follow examples better than rules.

**Use built-in citations where available.** Several model APIs can return citations as structured data: the exact quoted span and which document it came from. This is more reliable than asking for bracketed numbers in text, because the API guarantees the quote exists in the source.

**Check after generation.** Three practical checks, from cheap to thorough:

1. Every cited id exists among the passages sent. Drop or flag answers that cite `[7]` when only five passages were sent.
2. Quoted spans actually appear in the source text (a string match).
3. A faithfulness score: a second model, or an eval library such as RAGAS, splits the answer into claims and checks each against the passages. Run this offline on your golden set, and on a sample of live traffic.

**Design the refusal.** "I could not find this in the HR policies. For leave encashment questions, contact hr-help@..." is useful. "I don't know" alone is not. Track the refusal rate: too high means retrieval is failing; near zero on a hard golden set means the model is guessing.

**Checks and what they catch:**

| Check | Cost | Catches |
| --- | --- | --- |
| Cited ids exist | Free, code only | Made-up citation numbers |
| Quotes appear in source | Free, string match | Invented or altered quotes |
| Every sentence has a citation | Free, code only | Unsupported sentences |
| Faithfulness score by a second model | One extra call | Claims a citation does not actually support |
| Human review of a sample | Staff time | Subtle errors and tone problems |

**Showing sources to users.** Put the citation next to the sentence it supports, and make it open the quoted passage with its section and page. Users then check answers that matter to them, such as leave rules before a long holiday, and they report mismatches, which feed back into the golden set.

**Built-in citations in code.** Anthropic's API can cite passed documents directly. Send each passage as a document with citations turned on:

```python
import anthropic

client = anthropic.Anthropic()

def cited_answer(question, passages):
    docs = [{"type": "document",
             "source": {"type": "text", "media_type": "text/plain", "data": p["text"]},
             "title": f"{p['title']}, section {p['section']}, page {p['page']}",
             "citations": {"enabled": True}} for p in passages]
    reply = client.messages.create(
        model="claude-sonnet-5-5", max_tokens=600,          # check the docs for current names
        system="Answer only from the documents. If they do not answer the question, say so "
               "and suggest who to contact.",
        messages=[{"role": "user", "content": docs + [{"type": "text", "text": question}]}])
    parts = []
    for block in reply.content:
        if block.type != "text":
            continue
        cites = [f'{passages[c.document_index]["title"]}: "{c.cited_text}"' for c in (block.citations or [])]
        parts.append({"text": block.text, "sources": cites})
    return parts
```

Each piece of the answer comes with the exact text it relied on, ready to show next to the sentence. Pieces with no citations are the ones to look at: either general wording or an unsupported claim.

**Checks for bracket-style citations.** When you ask for `[n]` markers in plain text, check them in code:

```python
import re

def check_citations(answer, n_passages, passages_text):
    problems = []
    sentences = [s for s in re.split(r"(?<=[.!?])\s+", answer.strip()) if s]
    for s in sentences:
        ids = [int(x) for x in re.findall(r"\[(\d+)\]", s)]
        if not ids and len(s.split()) > 5:
            problems.append(f"no citation: {s[:60]}")
        for i in ids:
            if not 1 <= i <= n_passages:
                problems.append(f"cites [{i}] but only {n_passages} passages were sent")
    for quote in re.findall(r'"([^"]{12,})"', answer):
        if not any(quote in p for p in passages_text):
            problems.append(f"quote not in any passage: {quote[:40]}")
    return problems
```

Answers with problems can be regenerated once, shown with a warning, or sent to review, depending on the stakes.

**Grounding is not truth.** A perfectly cited answer can still be wrong if the source is outdated or wrong. Filter superseded documents at retrieval, show the document's date with each citation, and let users report a wrong source.

**Faithfulness at scale.** For a golden set and a sample of live traffic, split each answer into claims and check each against the cited passages with a judge model. Track the share of unsupported claims over time, by topic.

## A worked example

A Bengaluru IT services firm wants an HR assistant over its leave, travel and reimbursement policies. In the pilot, an employee asks: "Can I carry forward unused sick leave?"

The retrieved passages cover earned leave carry-forward (up to 45 days) but say nothing about sick leave. The first version answered: "Yes, you can carry forward up to 45 days of leave." That is wrong for sick leave, and stated as fact.

You change three things. The prompt now requires a citation per sentence and includes a refusal example. You switch to the API's citation feature so every claim comes with a quoted span. And you add a check that flags answers whose claims have no citation.

The new answer: "The policies I have cover carry-forward of earned leave: up to 45 days [Leave Policy v4, 3.2]. They do not say whether sick leave can be carried forward. Please check with HR at hr-help." The employee can click the citation and read the clause.

On the 80-question golden set, faithfulness rises from 0.81 to 0.96 and the share of unanswerable questions answered with a refusal goes from 30% to 85%. Correct answers to answerable questions barely change. You report all three numbers to the client.

| Measure on 80 questions | Before | After |
| --- | --- | --- |
| Faithfulness | 0.81 | 0.96 |
| Unanswerable questions refused | 30% | 85% |
| Answerable questions answered correctly | 88% | 87% |

## Common mistakes

- **Citing the document, not the passage.** "Source: HR Policies.pdf" cannot be checked. Cite section and page.
- **No unanswerable questions in the golden set.** Then you never measure guessing. Make at least a fifth of the set unanswerable from the documents.
- **Trusting model-written citation numbers.** Models sometimes cite a passage that does not support the claim. Check citations automatically.
- **Refusals with no next step.** Point the user to a person, a team or a form.
- **Hiding sources from users.** Showing the quoted passage builds trust and lets users catch mistakes the system missed.
- **Parsing citations with no checks.** Verify ids exist and quotes match.
- **Hiding uncited sentences.** They are the most likely to be unsupported.
- **Citing outdated documents.** Show dates and filter superseded versions.

## When citations matter less

- **Creative or drafting tasks** where the model is not stating facts from documents.
- **Answers from a database or tool**, such as an order status, where the tool result is the source.
- **Internal brainstorming**, where people treat the output as ideas, not facts.

Citations are essential whenever users act on facts: policies, prices, eligibility, health, legal and financial information.

## From demo to production

- **Use built-in citations** where your provider offers them, and log them.
- **Run citation checks on every answer**, and faithfulness checks on a sample.
- **Show sources with dates** next to each sentence.
- **Track refusal and unsupported-claim rates** by topic.
- **Let users report wrong sources** and route reports to document owners.
