## What it is

**PyTorch** is an open-source Python library for building and training neural networks. Its building blocks:

- **Tensors**: multi-dimensional arrays, like NumPy arrays, that can live on a CPU or GPU and track gradients.
- **Autograd**: records operations on tensors and computes gradients automatically.
- **nn.Module**: the base class for models; layers and models are modules.
- **Dataset** and **DataLoader**: load data and serve it in shuffled batches.
- **Optimisers**: update weights from gradients (SGD, Adam).

```text
   CSV of images + labels
          |
          v
   [Dataset]  __getitem__(i) -> (tensor 3x224x224, label 4)
          |
          v
   [DataLoader]  batches of 64, shuffled  --> .to(device)
          |
          v
   [nn.Module]  forward(x) -> scores for 6 classes
          |
          v
   [loss_fn] --> loss.backward() --> opt.step()     repeat per batch
          |
          v
   each epoch: model.eval() + no_grad() -> validation -> save best checkpoint
```

This lesson follows an engineer at a textile manufacturer in Pune building a fabric-defect classifier as a first PyTorch project.

## How it works

**Tensors and devices.** Create tensors from data, check `.shape` and `.dtype`, and move both the model and the data to the same device (`"cuda"` for a GPU, `"cpu"` otherwise). Mismatched devices are a top beginner error.

**Data.** A `Dataset` returns one example and its label by index; a `DataLoader` batches and shuffles them. Apply the same preprocessing at training and prediction time.

**Model.** Subclass `nn.Module`, define layers in `__init__`, and the forward computation in `forward`.

**Training loop.** The heart of PyTorch:

```python
model.to(device)
opt = torch.optim.AdamW(model.parameters(), lr=1e-3)
loss_fn = nn.CrossEntropyLoss()

for epoch in range(epochs):
    model.train()
    for x, y in train_loader:
        x, y = x.to(device), y.to(device)
        opt.zero_grad()              # clear old gradients
        loss = loss_fn(model(x), y)  # forward pass and loss
        loss.backward()              # backpropagation
        opt.step()                   # update weights

    model.eval()                     # switch off dropout etc.
    with torch.no_grad():            # no gradients needed for evaluation
        val_loss = evaluate(model, val_loader)
    save_if_best(model, val_loss)
```

**Evaluation mode.** `model.eval()` changes layers such as dropout and batch normalisation to their inference behaviour; `torch.no_grad()` saves memory and time. Forgetting `eval()` gives wrong validation numbers; forgetting `no_grad()` wastes memory.

**Saving.** Save the model's `state_dict` (its weights) along with the settings and preprocessing needed to rebuild it. Save the best checkpoint by validation score, not just the last.

**Reproducibility.** Set random seeds, log settings and library versions.

**Higher-level tools.** Libraries such as PyTorch Lightning or fastai wrap the loop with logging, checkpoints and multi-GPU support. Learn the plain loop first so you can debug the wrappers.

**A minimal model and dataset:**

```python
import torch
from torch import nn
from torch.utils.data import Dataset, DataLoader

class DefectData(Dataset):
    def __init__(self, rows, label_map, transform):
        self.rows, self.label_map, self.transform = rows, label_map, transform
    def __len__(self):
        return len(self.rows)
    def __getitem__(self, i):
        path, label = self.rows[i]
        return self.transform(load_image(path)), self.label_map[label]

class SmallNet(nn.Module):
    def __init__(self, classes=6):
        super().__init__()
        self.body = nn.Sequential(
            nn.Conv2d(3, 16, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
            nn.Conv2d(16, 32, 3, padding=1), nn.ReLU(), nn.AdaptiveAvgPool2d(1),
        )
        self.head = nn.Linear(32, classes)
    def forward(self, x):
        return self.head(self.body(x).flatten(1))
```

The `label_map` is built once and passed to both the training and validation datasets, which is exactly the fix the worked example needed.

**Checking shapes as you go.** Many PyTorch errors are shape errors. Pass one batch through the model and print the shape after each layer before training. A batch of 64 colour images at 224 pixels has shape `[64, 3, 224, 224]`, and the model's output should be `[64, 6]`. When an error mentions "mat1 and mat2 shapes cannot be multiplied", a layer expected a different number of inputs than it received.

**Using a GPU.** Check `torch.cuda.is_available()` and set `device = "cuda" if torch.cuda.is_available() else "cpu"` once at the top of the script, then use `device` everywhere. Free GPUs on Google Colab or Kaggle notebooks are enough for the projects in this path. A GPU speeds up the large matrix multiplications in each layer, often ten times or more, but it does nothing for slow data loading. If the GPU sits idle while the loop runs, raise `num_workers` on the DataLoader so images are read and resized in parallel.

**From a loop to a habit.** Write the loop once by hand and keep it as a template: seeds and device at the top, datasets and loaders, model, optimiser and loss, then the epoch loop with validation and checkpoint saving. Most new projects only change the dataset and the model.

## A worked example

A Pune textile manufacturer wants to classify fabric defect images into six types. As a first PyTorch project, an engineer builds the pipeline end to end:

- a `Dataset` reading images and labels from a CSV, resizing to 224 × 224 and normalising;
- a `DataLoader` with batch size 64, shuffling for training only;
- a small model (in the next lesson they swap in a pre-trained CNN);
- the training loop above with AdamW, 20 epochs, saving the best checkpoint by validation accuracy;
- a prediction script that loads the checkpoint, applies the same preprocessing and returns the class and probability.

First run: validation accuracy stuck at 17%, about chance for six classes. The bug: labels were read as strings and mapped differently in the training and validation datasets. After fixing the mapping in one shared place, accuracy rises to 71% with the small model, before moving to transfer learning.

| Run | Validation accuracy | Cause and fix |
| --- | --- | --- |
| 1 | 17% | Labels mapped differently in train and validation sets |
| 2 | 71% | One shared label map; best checkpoint saved |
| Next lesson | Much higher | Pre-trained CNN through transfer learning |

## Common mistakes

- **Model and data on different devices.**
- **Forgetting `zero_grad()`.** Gradients accumulate across batches.
- **Forgetting `model.eval()` and `torch.no_grad()` during validation.**
- **Different preprocessing in training and prediction.**
- **Saving only the last epoch.** Keep the best checkpoint by validation.
- **Never printing shapes.** One batch through the model, with shapes printed, saves an hour of reading error messages.
