## What it is

**Sorting** puts items in order. Once data is sorted, many questions become easy: duplicates sit next to each other, the smallest and largest are at the ends, and you can find anything quickly.

**Binary search** finds an item in sorted data by checking the middle and throwing away the half that cannot contain it. Each step halves what is left, so it needs about log₂ n steps: 20 for 10 lakh items.

**Two pointers** walk two positions through an array, often from both ends or one behind the other, to solve pair and range problems in one pass instead of with nested loops. A **sliding window** is the two-pointer pattern for finding the best contiguous stretch.

```text
 BINARY SEARCH for 42 in a sorted list
 [ 3  8  15  21  27  33  42  50  61  77 ]
   lo              mid              hi       27 < 42 → search right half
                       [ 33  42  50  61  77 ]
                         lo  mid       hi    42 found in 2 steps

 TWO POINTERS for a pair summing to 50 (sorted)
 [ 5  12  18  25  30  38  45 ]
   L→                     ←R      5+45=50 ✓  (too small: L→ , too big: ←R)
```

## How it works

**Sorting algorithms** differ in speed and behaviour:

| Algorithm | Average time | Extra space | Notes |
|---|---|---|---|
| Bubble / insertion sort | O(n²) | O(1) | simple; insertion sort is fast on nearly sorted data |
| Merge sort | O(n log n) | O(n) | splits in halves, merges sorted halves; stable |
| Quicksort | O(n log n), worst O(n²) | O(log n) | picks a pivot and partitions; fast in practice |
| Heap sort | O(n log n) | O(1) | uses a heap; not stable |
| Timsort (Python's `sorted`) | O(n log n) | O(n) | merge sort plus insertion sort; very fast on real data |

In practice you call the built-in sort. You should still know that comparison sorting cannot beat O(n log n) on average, and be able to explain merge sort or quicksort in an interview.

**Binary search** keeps a range `lo` to `hi`. It looks at the middle; if the target is bigger, it moves `lo` past the middle; if smaller, it moves `hi` before it. It stops when it finds the target or the range is empty. The same idea works on any **monotonic** yes/no question, such as "have cumulative sales reached the target by day d?", which is called **binary search on the answer**.

**Two pointers** use the sorted order. To find a pair that sums to a target, start at both ends: if the sum is too small, move the left pointer right to increase it; if too big, move the right pointer left. Each move rules out many pairs at once, so it is O(n).

A **sliding window** keeps a left and right edge. Move the right edge to grow the window; when it breaks a rule, such as going over budget, move the left edge to shrink it. Track the best window as you go.

**In interviews**, listen for clues. "Sorted array", "find the first or last position", or "minimum value that works" point to binary search. "Pair", "triplet" or "subarray with a sum" in sorted data point to two pointers. "Longest or shortest contiguous stretch" points to a sliding window. Say the pattern out loud before you code; it shows the interviewer how you think.

## A worked example

Sneha runs analytics for an online coaching platform in Hyderabad. She has daily spend on ads for a year and a monthly budget question: what is the longest run of consecutive days where total ad spend stayed within ₹1 lakh?

Trying every start and end day is O(n²). A sliding window does it in one pass:

```python
def longest_within(spend, budget):
    best = total = left = 0
    for right, amount in enumerate(spend):
        total += amount                   # grow the window
        while total > budget:             # shrink until within budget
            total -= spend[left]
            left += 1
        best = max(best, right - left + 1)
    return best
```

Each day enters the window once and leaves at most once, so it is O(n).

Next, finance asks: on which day did cumulative sign-ups first reach 50,000? Cumulative totals only go up, so the question "reached by day d?" is false, false, ..., then true for every later day. That is monotonic, so she binary searches the answer:

```python
from itertools import accumulate

def first_day_reaching(daily, target):
    totals = list(accumulate(daily))
    lo, hi = 0, len(totals) - 1
    answer = -1
    while lo <= hi:
        mid = (lo + hi) // 2
        if totals[mid] >= target:
            answer, hi = mid, mid - 1     # works; look for an earlier day
        else:
            lo = mid + 1
    return answer
```

For a year of data that is about 9 checks instead of up to 365. On 10 years of hourly data it is about 17 checks instead of nearly 90,000. Python's `bisect` module does the same thing in one call: `bisect.bisect_left(totals, target)`.

## Common mistakes

**Binary searching unsorted data.** It silently returns wrong answers. Sort first, or make sure the yes/no question is monotonic.

**Off-by-one bounds.** Mixing inclusive and exclusive `hi`, or writing `lo = mid` instead of `mid + 1`, causes infinite loops. Pick one convention and test with lists of length 0, 1 and 2.

**Writing your own sort for real work.** Built-in sorts are well tested and fast. Write your own only to learn, or in an interview when asked.

**Re-sorting inside a loop.** Sort once outside the loop. Sorting inside makes O(n log n) work happen n times.

**Using two pointers on unsorted data for pair sums.** The method relies on order. Without sorting, use a hash map instead.

**Shrinking the window with if instead of while.** One step may not be enough to get back within the rule. Keep shrinking while the rule is broken.
