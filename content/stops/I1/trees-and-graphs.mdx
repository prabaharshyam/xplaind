## What it is

A **graph** is a set of **nodes** joined by **edges**. Metro stations joined by tracks, people joined by friendships and web pages joined by links are all graphs. Edges can have a direction (a one-way street) and a weight (a distance or price).

A **tree** is a special graph: connected, with no cycles, so there is exactly one path between any two nodes. It usually has a **root** at the top and **children** below. Folders on your laptop, a company org chart and the HTML of a web page are trees. A **binary tree** gives each node at most two children; a **binary search tree** keeps smaller values on the left and larger on the right.

```text
 TREE (no cycles)                  GRAPH (cycles allowed)
          CEO                      Rajiv Chowk ──── Kashmere Gate
         /    \                        │    \             │
      CTO      CFO                 Mandi House  Central   Civil Lines
     /   \       \                     │      Secretariat     │
  Dev1  Dev2    Fin1               ITO ──────────┘       Vishwavidyalaya
 one path between any two nodes     many paths; must track "visited"
```

Two ways to explore them come up again and again: **breadth-first search** (BFS) and **depth-first search** (DFS).

## How it works

In code, a graph is usually an **adjacency list**: a dict from each node to its neighbours.

```python
metro = {
    "Rajiv Chowk": ["Kashmere Gate", "Mandi House", "Central Secretariat"],
    "Kashmere Gate": ["Rajiv Chowk", "Civil Lines"],
    "Mandi House": ["Rajiv Chowk", "ITO"],
    "Central Secretariat": ["Rajiv Chowk", "ITO"],
    "ITO": ["Mandi House", "Central Secretariat"],
    "Civil Lines": ["Kashmere Gate", "Vishwavidyalaya"],
    "Vishwavidyalaya": ["Civil Lines"],
}
```

**BFS** explores in rings. It starts at a node, visits all its neighbours, then all their neighbours, and so on, using a **queue** so nodes are handled in the order they were found. Because it moves outward one edge at a time, the first time BFS reaches a node is by the fewest edges. That makes it the right tool for "fewest stops" or "degrees of separation".

**DFS** goes as deep as it can along one path, then backs up and tries the next branch. It uses a **stack**, often the call stack through recursion. DFS is natural for exploring everything reachable, detecting cycles, and walking trees in a particular order.

Both need a **visited** set on graphs, because cycles would otherwise send them round forever. Both take O(V + E) time, where V is the number of nodes and E the number of edges.

| Question | Use | Why |
|---|---|---|
| Fewest hops between two nodes, unweighted | BFS | explores by distance in edges |
| Everything reachable from a node | DFS or BFS | either visits all; DFS is shorter to write |
| Detect a cycle, or order tasks with dependencies | DFS | its back-tracking reveals cycles; gives topological order |
| Connected groups in a network | DFS or BFS from each unvisited node | each run marks one group |
| Cheapest path with weighted edges | Dijkstra's algorithm | BFS ignores weights |
| Find a value in a sorted tree | binary search tree walk | halves the search each step |

## A worked example

Kabir is building a route helper for commuters in Delhi. A user picks two stations and the app shows the route with the fewest stops. Every hop between adjacent stations counts the same, so BFS fits.

```python
from collections import deque

def fewest_stops(graph, start, goal):
    queue = deque([[start]])          # each item is a path so far
    visited = {start}
    while queue:
        path = queue.popleft()
        station = path[-1]
        if station == goal:
            return path
        for nxt in graph[station]:
            if nxt not in visited:
                visited.add(nxt)
                queue.append(path + [nxt])
    return None
```

From "Mandi House" to "Civil Lines", BFS first finds Rajiv Chowk and ITO (one stop away), then Kashmere Gate and Central Secretariat (two away), then Civil Lines (three away). It returns `Mandi House → Rajiv Chowk → Kashmere Gate → Civil Lines`, and no shorter route exists, because BFS checked every two-stop route first.

The app also needs to warn when a station is cut off during maintenance. Kabir removes the closed station from the graph and runs DFS from a major interchange to list every station still reachable:

```python
def reachable(graph, start, seen=None):
    seen = seen if seen is not None else set()
    seen.add(start)
    for nxt in graph[start]:
        if nxt not in seen:
            reachable(graph, nxt, seen)
    return seen
```

Any station not in the result is unreachable and gets a warning banner.

When the team later adds fares, routes with the fewest stops are not always cheapest. That is a weighted graph, and Kabir switches to Dijkstra's algorithm, which is BFS with a priority queue ordered by total cost.

## Common mistakes

**No visited set.** On a graph with cycles, BFS and DFS loop forever. Mark nodes visited when you add them to the queue, not when you take them out, or you will add the same node many times.

**Using DFS for shortest paths.** DFS finds a path, not the shortest one. For fewest edges, use BFS.

**Using BFS on weighted graphs.** BFS counts edges, not cost. Use Dijkstra's algorithm when edges have different weights.

**Deep recursion limits.** Recursive DFS on a long chain can exceed Python's recursion limit of about 1,000. Use an explicit stack for very deep graphs.

**Assuming every tree is balanced.** A binary search tree built from already-sorted data becomes a long chain, and searches drop to O(n). Real systems use self-balancing trees.

**Forgetting edge direction.** A follow on Instagram is one-way. Store directed edges only in the direction they go.
