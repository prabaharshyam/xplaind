## What it is

These three structures are about **how items go in and come out**.

A **stack** is like a pile of plates: you add to the top and take from the top. The last item in is the first out, called **LIFO**. Undo buttons, browser back buttons and the way programs track function calls are all stacks.

A **queue** is like a line at a railway ticket counter: people join at the back and leave from the front. The first item in is the first out, called **FIFO**. Print jobs, customer support tickets and background tasks are queues.

A **linked list** is a chain of nodes. Each node holds a value and a pointer to the next node. You can add or remove a node anywhere by changing a couple of pointers, without shifting the rest.

```text
 STACK (LIFO)          QUEUE (FIFO)                    LINKED LIST
   push ↓  ↑ pop       enqueue → [ C | B | A ] → dequeue   head
      +-----+                back        front          [ 5 | •]→[ 9 | •]→[ 2 | ∅]
      |  C  | ← top
      |  B  |                                          insert 7 after 9:
      |  A  |                                          [ 9 | •]→[ 7 | •]→[ 2 | ∅]
      +-----+                                          only two pointers change
```

## How it works

**Stacks** need two operations: `push` (add to the top) and `pop` (remove from the top). In Python a normal list works well: `append` pushes and `pop()` pops, both O(1). You can also `peek` at the top item without removing it.

**Queues** need `enqueue` (add at the back) and `dequeue` (remove from the front). A Python list is a poor queue, because `pop(0)` shifts every item, O(n). Use `collections.deque`, a double-ended queue, whose `append` and `popleft` are both O(1). For work shared between threads or programs, you use a queue library or a message queue service, which you will meet in the system design track.

**Linked lists** store each item in its own node object that points to the next. To insert after a node you already hold, you point the new node at the old next node and point the old node at the new one: O(1). The cost is reading by position. To reach item 500 you must follow 500 pointers, O(n). Python has no built-in linked list type because lists and deques cover most needs, but the idea appears in interview problems and inside other structures.

| Structure | Add | Remove | Read item k | Use it for |
|---|---|---|---|---|
| Stack (list) | push O(1) | pop O(1) | top only | undo, bracket matching, DFS |
| Queue (deque) | append O(1) | popleft O(1) | front only | tasks in order, BFS |
| Linked list | O(1) at a known node | O(1) at a known node | O(n) | frequent middle edits, LRU caches |
| Array (list) | O(1) at end | O(n) at front | O(1) | reading by position |

**In interviews**, these structures hide inside other questions. "Most recent", "undo", "nested" or "matching pairs" suggest a stack. "In order of arrival", "level by level" or "process tasks fairly" suggest a queue. Linked list questions usually test pointer care: reversing a list, finding its middle with a slow and a fast pointer, or detecting a loop. Draw the nodes and arrows on paper first; most linked list bugs are lost pointers that a quick sketch would have caught.

## A worked example

Ananya is building a small expression checker for a maths quiz app used in coaching centres in Kota. Students type answers such as `(2+3)*[4-(1+1)]`, and the app should reject answers with unbalanced brackets before trying to evaluate them.

A stack fits perfectly. Every opening bracket must be closed by the matching closing bracket, and the most recently opened one must close first, which is exactly LIFO.

```python
PAIRS = {")": "(", "]": "[", "}": "{"}

def balanced(text):
    stack = []
    for ch in text:
        if ch in "([{":
            stack.append(ch)                 # push
        elif ch in PAIRS:
            if not stack or stack.pop() != PAIRS[ch]:
                return False                 # nothing to close, or wrong type
    return not stack                         # anything left open?
```

Tracing `[(])`: push `[`, push `(`, then `]` pops `(`, which does not match `[`, so it returns `False`. For `{[()()]}` every pop matches and the stack ends empty, so it returns `True`. The function makes one pass: O(n) time and up to O(n) space.

Next, the app must mark submitted answers in the order they arrived during a live test, even when hundreds come in at once. Ananya uses a queue:

```python
from collections import deque
pending = deque()
pending.append("answer-101")       # enqueue
pending.append("answer-102")
first = pending.popleft()          # "answer-101", O(1)
```

Fairness comes for free: no student's answer jumps the line.

## Common mistakes

**Using list.pop(0) as a queue.** It works on small data and becomes O(n²) over a long run. Use `deque.popleft()`.

**Popping an empty stack.** Calling `pop()` on an empty list raises an error. Check `if stack` first, as the bracket checker does.

**Forgetting the final check.** A bracket string like `((` never fails a pop, but it is not balanced. Always check that the stack is empty at the end.

**Reaching for a linked list by habit.** In Python, lists and deques are faster for almost everything. Use a linked list when you truly need cheap inserts and removals at nodes you already hold.

**Losing the rest of a linked list.** When inserting, point the new node at the next node before you change the old node's pointer, or you cut the chain.

**Mixing up stack and queue in graph search.** Depth-first search uses a stack (or recursion); breadth-first search uses a queue. Swap them and you get a different traversal.
