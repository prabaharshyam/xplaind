## What it is

A public cloud rents you computers, storage, networks and ready-made services by the hour or by use. The three big providers, AWS, Microsoft Azure and Google Cloud, offer nearly the same building blocks under different names. Indian enterprises often follow a group-wide choice; banks and government-linked clients may also require Indian regions or a specific provider's sovereign offering.

You do not need every service. An AI deployment uses about six kinds:

- **Compute**: where your code runs.
- **Storage**: files and documents.
- **Databases**: structured data, often PostgreSQL with pgvector.
- **Networking**: private networks, load balancers, DNS.
- **Identity and access**: who can do what.
- **Managed AI**: hosted model APIs from the cloud, which may matter for data agreements.

## How it works

**Regions and zones.** Each region (Mumbai, Hyderabad, Pune, Delhi and others in India, depending on the provider) has several zones, separate data centres. Spread instances across zones for resilience. Pick the region by latency to users, by data residency rules and by which models are offered there.

**Compute choices**, from most to least managed: serverless containers (Cloud Run, Azure Container Apps, AWS App Runner or ECS Fargate) where you give an image and get a URL; managed Kubernetes (EKS, AKS, GKE) when the client's platform team runs one; virtual machines when you need GPUs or full control. For most AI APIs, serverless containers are the fastest safe start.

**Storage and databases.** Object storage (S3, Blob Storage, Cloud Storage) for documents. Managed PostgreSQL for relational data and vectors. Use managed services: backups, patches and failover come built in.

**Networking.** Resources sit in a virtual network with private subnets. Databases should have no public address; your app reaches them privately. Outside traffic arrives through a load balancer with HTTPS.

**Identity.** Give each service its own identity (a role or managed identity) with only the permissions it needs, rather than storing long-lived access keys. People sign in through the company's single sign-on.

**Managed models.** Each cloud resells major models (Amazon Bedrock, Azure OpenAI and AI Foundry, Google Vertex AI). Clients often prefer these because the data stays under their existing cloud contract and region.

**Cost.** Compute, managed databases, data transfer out and model tokens make up most bills. Use the provider's pricing calculator before you build, and set a budget alert on day one.

## A worked example

A Hyderabad pharma company on Azure wants a document assistant for its regulatory team. Requirements: data stays in India, no public database, sign-in with company accounts.

Your design:

- **Region**: Central India for everything, after checking the required model is offered there through the company's Azure AI agreement.
- **Compute**: Azure Container Apps running your FastAPI image, scaling from 1 to 5 instances.
- **Storage**: Blob Storage for source PDFs; Azure Database for PostgreSQL with pgvector for chunks, reachable only from the app's private network.
- **Identity**: the app uses a managed identity with read access to one storage container and the database, and no stored keys. Users sign in with Microsoft Entra ID.
- **Cost**: the calculator estimates about ₹55,000 a month before model tokens, with tokens estimated separately from expected usage. A budget alert is set at 80%.

The client's cloud team approves in one review, mainly because every choice matches their existing patterns.

## Common mistakes

- **Learning three clouds shallowly.** Learn one properly; translating names to another takes a day.
- **Public databases.** A database with a public address is the most common serious cloud mistake.
- **Long-lived access keys in code.** Use service identities and short-lived credentials.
- **Ignoring data transfer and model costs.** They can exceed compute. Estimate them.
- **Picking a region for latency alone.** Check residency rules and model availability first.

## Practise

Complete Microsoft Learn's cloud concepts modules, then the architecture and services path for Azure, or Google's getting-started path if you prefer Google Cloud.

1. On a free account, deploy your containerised API to a serverless container service in an Indian region.
2. Add object storage and a managed PostgreSQL that is reachable only privately, and give the app a service identity instead of keys.
3. Price the set-up for 50,000 requests a month with the provider's calculator and set a budget alert.

**You are done when you can** draw your deployment with region, network boundaries and identities, and explain each line of its estimated monthly bill.
