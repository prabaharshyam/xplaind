## What it is

People use three words for "smart software" as if they meant the same thing: **artificial intelligence**, **machine learning** and **large language model**. They do not mean the same thing, and knowing the difference is the first thing an interviewer, a client or your manager will test.

Think of three circles, one inside the other:

```text
+-------------------------------------------------------+
|  Artificial intelligence (AI)                         |
|  Software that does tasks we thought needed people    |
|                                                       |
|   +-----------------------------------------------+   |
|   |  Machine learning (ML)                        |   |
|   |  Learns the rules from examples               |   |
|   |                                               |   |
|   |   +---------------------------------------+   |   |
|   |   |  Large language models (LLMs)         |   |   |
|   |   |  Learn from text, write text          |   |   |
|   |   +---------------------------------------+   |   |
|   +-----------------------------------------------+   |
+-------------------------------------------------------+
```

- **Artificial intelligence (AI)** is the broad goal: software that does tasks we used to think needed human judgement. Recognising a face, translating Tamil to English, recommending a song and answering a question are all AI tasks.
- **Machine learning (ML)** is the main way AI is built today. Instead of a person writing every rule, you show a program many examples and it learns the pattern itself.
- A **large language model (LLM)** is one kind of machine learning model, trained on a huge amount of text to predict what comes next. ChatGPT, Claude and Gemini are products built on LLMs.

So every LLM is machine learning, and all machine learning is AI. The reverse is not true. The fraud alert on your UPI app is machine learning but not a language model, and a chess program from the 1990s that followed hand-written search rules was AI without any machine learning.

This lesson follows one person, Asha, who runs HR for a 200-person company in Pune, through a normal working day. By the end you will be able to sort every "AI" thing she meets into the right circle, explain how a language model writes, and say why it sometimes gets things wrong.

## How it works

### Rules versus learning

Before machine learning, software followed rules a person wrote. Asha's company has an expense system with a rule like this:

```text
IF amount > 5,000 rupees AND receipt missing
THEN send to manager for approval
```

Rules are clear and predictable, but someone has to think of every case. Fraud, faces and language have too many cases for anyone to write down.

Machine learning turns the job around. You collect examples where you already know the answer, and the program finds the pattern:

```text
 Examples with answers         Training             A model
+----------------------+     +-----------+     +------------------+
| payment 1 -> genuine |     |           |     | new payment in   |
| payment 2 -> fraud   | --> |  learn    | --> | "fraud: 0.93"    |
| payment 3 -> genuine |     |  pattern  |     | out              |
|  ... 1 crore more    |     |           |     |                  |
+----------------------+     +-----------+     +------------------+
```

The result is a **model**: a file of learned numbers that turns an input into an output. A bank's fraud model has never seen your exact payment, but it has seen millions like it, so it can make a good guess. It is only as good as its examples. If the examples never included a certain kind of fraud, the model will miss it.

| | Rule-based software | Machine learning |
| --- | --- | --- |
| Who decides the logic | A person writes it | Learned from examples |
| Good at | Clear, stable rules like tax slabs | Fuzzy patterns like faces, fraud, language |
| When it is wrong | The rule was wrong; fix the rule | The examples were missing or biased; fix the data |
| Explaining a decision | Easy: point to the rule | Harder: the pattern is spread across many numbers |

### How a language model writes

A large language model is machine learning applied to text. During training it reads an enormous amount of writing: books, websites, code, forum posts. Its only task is to guess the next small piece of text, called a **token**. A token is often a whole short word ("the"), sometimes part of a longer one ("under" + "stand" + "ing").

After training, when you ask a question, the model writes the answer one token at a time:

```text
Prompt: "The capital of Karnataka is"

Step 1: likely next tokens ->  " Bengaluru" 0.86 | " Bangalore" 0.12 | " Mysuru" 0.01
Step 2: picks " Bengaluru", adds it, and asks again ->  "." 0.71 | "," 0.20 ...
Step 3: keeps going until the answer is complete
```

That is all generation is: predict, pick, append, repeat. With enough data and a large enough model, this simple skill produces summaries, translations, emails, code and step-by-step explanations, because human writing contains all of those patterns.

### What it does not do

Three limits matter every day:

1. **It does not look facts up.** Unless the product connects the model to web search or your documents, it answers from patterns learned in training. There is no database of true facts inside it.
2. **It has a knowledge cut-off.** It does not know what happened after its training data was collected, unless the product gives it newer information.
3. **It cannot check itself.** It writes what is likely, not what is verified. So it can produce fluent, confident text that is false. This is called a **hallucination**.

### Model versus product

One more distinction trips people up. The **model** is the trained file of numbers. The **product** is the app around it: the chat window, the search tool, the memory feature, the safety filters. When a chat assistant "searches the web", that is the product calling a search tool and feeding results to the model. When people compare "ChatGPT and Claude", they are comparing products built on different models.

## A worked example

Here is Asha's Monday, with each piece of AI sorted into its circle.

**8:40 am, spam filter (machine learning, not an LLM).** Her inbox moves a fake job offer, "Earn ₹50,000 a week from home!", into spam. The filter learned from millions of emails people marked as spam or not spam. It outputs a label, not text.

**9:05 am, face unlock (machine learning, not an LLM).** Her phone recognises her even with new glasses. A model trained on images learned which features matter.

**10:15 am, payroll formula (not AI).** A spreadsheet adds up overtime. A person wrote the exact formula; nothing was learned.

**11:00 am, chat assistant (an LLM).** Asha asks: "Draft a friendly announcement of our new hybrid work policy: three office days a week, starting 1 December."

The draft is good. It is warm, clear and well structured. It also contains this sentence: "As required under the Shops and Establishments Act, employees must receive 30 days' notice of any policy change."

It sounds official. Asha checks with the company's lawyer, who says the claim is not right for Maharashtra and the company does not need to cite any law here. Asha deletes the sentence.

| Task | Time without AI | Time with AI |
| --- | --- | --- |
| Writing the first draft | about 45 minutes | 2 minutes |
| Checking facts and tone | 5 minutes | 10 minutes |
| Total | about 50 minutes | about 12 minutes |

The assistant saved her more than half an hour, but only because she checked it. That split, fast drafting plus careful checking, is how professionals use language models.

**3:30 pm, fraud alert (machine learning, not an LLM).** Her bank app pauses a ₹49,000 payment to a new account and asks for an OTP. The fraud model scored the payment as unusual. It was genuine, so this was a false positive, not a hallucination: the model made a wrong yes-or-no call rather than inventing text.

## Common mistakes

- **Using AI, ML and LLM as the same word.** They nest. When a vendor says "our AI", ask which kind. A rules engine, a fraud model and a chat assistant need very different data, testing and budgets.
- **Thinking a language model looks things up.** Unless the product says it searches or uses your documents, it is generating from patterns. "It said so" is not a source.
- **Trusting confidence.** Fluent tone tells you nothing about accuracy. Be most careful with numbers, laws, names, dates and anything recent.
- **Calling every mistake a hallucination.** A hallucination is invented content from a generative model. A fraud model blocking a genuine payment is a false positive; a spam filter missing spam is a false negative.
- **Assuming the model understands like a person.** It can explain a hard idea well and then fail a simple question that is worded oddly. Test it on your real task before relying on it.
- **Confusing the model with the product.** The same model can behave very differently in two apps because of the tools, instructions and safety settings around it.

## Practise

Watch the introduction to large language models linked below; it explains training and generation clearly without maths. Then do these three tasks.

1. **Sort your own week.** List five AI features you used in the last week: maps, a spam filter, a payment app, voice typing, a recommendation, a chat assistant. For each, write which circle it belongs in and what it outputs (a label, a score, a route, text).
2. **Catch a hallucination.** Ask a chat assistant for three facts with numbers about your city or your field, such as population, a founding year and a statistic. Check each against an official source. Note which were wrong and how confident the wording was.
3. **Explain it out loud.** In two minutes, explain to a friend how a language model writes an answer, using the words token, predict and hallucination. Record yourself and listen back.

**You are done when you can** explain the difference between AI, machine learning and a language model in plain words, give one everyday example of each, and say why a language model can be confidently wrong.
