## What it is

Two tools every developer uses daily:

- The **terminal**: a text window for running commands. You navigate folders, run programs, install packages and use tools such as Git from it.
- **Git**: a version control system that records snapshots of your project (**commits**) so you can see what changed, undo mistakes and share code. **GitHub** hosts Git repositories online so others can see and collaborate on them.

Employers look at GitHub profiles. A repository with clear commits and a README is the simplest proof that you can write and organise code.

## How it works

**Terminal basics.**

```bash
pwd                 # where am I?
ls                  # list files (dir on Windows Command Prompt)
cd projects         # go into a folder
cd ..               # go up one level
mkdir python-practice
python hello.py     # run a program
```

The up arrow repeats earlier commands; Tab completes file names.

**Git basics.** Install Git, then set your name and email once:

```bash
git config --global user.name "Priya Raman"
git config --global user.email "priya@example.com"
```

Start a repository and make commits:

```bash
cd python-practice
git init
git status                       # what has changed?
git add hello.py
git commit -m "Add hello script that prints name and date"
git log --oneline                # history
```

`git add` chooses which changes go into the next commit; `git commit` saves the snapshot with a message.

**Good commit messages** say what changed and why, in the present tense: "Add expense totals by category", not "update" or "fixed stuff".

**Pushing to GitHub.** Create an empty repository on GitHub, then connect and push:

```bash
git remote add origin https://github.com/priya-raman/python-practice.git
git branch -M main
git push -u origin main
```

GitHub will ask you to sign in; follow its prompts or set up an SSH key.

**README.** A `README.md` file explains what the project is and how to run it. GitHub shows it on the repository's front page.

**.gitignore.** List files Git should ignore: `.venv/`, `__pycache__/`, `.env` (which may hold secrets).

## A worked example

Ravi, learning Python in Nagpur, has a folder of exercise scripts. He turns it into a GitHub portfolio:

1. `git init` in the folder, and a `.gitignore` with `.venv/` and `.env`.
2. Three commits as he tidies the work: "Add expense tracker with category totals", "Handle missing amounts in expense CSV", "Add README with usage examples".
3. A README with a one-line summary, how to run each script, and a sample of the output.
4. `git push` to a new public repository.

When he later breaks the expense tracker while adding a feature, `git diff` shows exactly what he changed, and `git restore expense.py` brings back the last committed version. In an interview the next month, the panel opens his repository and asks him about one of his commits.

## Common mistakes

- **One giant commit at the end.** Commit small, meaningful steps.
- **Messages like "update".** Say what changed.
- **Committing secrets.** Keep keys in `.env` and list it in `.gitignore`; if a key is ever pushed, revoke it.
- **Committing virtual environments and caches.** Ignore them.
- **No README.** Visitors cannot tell what the project does.
