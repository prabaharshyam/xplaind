## What it is

**Robotic process automation (RPA)** uses software "robots" that operate applications through their user interface, as a person would: opening programs, clicking buttons, typing into fields, copying values from screens, downloading reports. It is used where systems have no API or where building an integration would take too long.

Leading RPA tools include UiPath, Automation Anywhere and Microsoft Power Automate Desktop. They record or let you design the steps, then run them on a schedule or on demand, on a desktop or a server.

## How it works

**Attended and unattended.** Attended robots run on a person's computer when they start them, helping with part of their task. Unattended robots run on their own on dedicated machines, processing queues of work.

**How robots find things.** Good RPA does not click at fixed screen positions. It identifies elements by their properties (a button's name, a field's label, a web page's structure) so small layout changes do not break it. For old applications or remote desktops, it may fall back on image matching or OCR, which is more fragile.

**Where it fits.**

- Legacy desktop applications (older ERPs, banking back-office screens) and portals without APIs.
- High-volume, stable, rule-based tasks: copying data from one system to another, generating and downloading daily reports, entering orders.
- As a bridge while a proper integration is built.

**Where it does not fit.** Systems with good APIs (use the API; it is faster and sturdier). Processes that change often. Tasks needing judgement on varied inputs (pair RPA with AI steps or keep a person).

**RPA plus AI.** RPA moves data through screens; AI reads documents, classifies emails or decides the next step. Together they cover processes neither handles alone. AI computer-use agents, which operate screens from screenshots, are newer and more flexible but slower, costlier and less predictable than designed RPA steps; a common pattern uses RPA for stable steps and AI only where variation needs judgement.

**Running costs.** Robots break when screens change, passwords expire or pop-ups appear. Budget for monitoring, maintenance and licences. Keep a list of every robot, its owner, the systems it touches and the credentials it uses (with least privilege, stored in a vault).

## A worked example

A Kolkata general insurer's claims team copies details from its email-based claim intimations into an old desktop claims system with no API: about 300 claims a day, each taking 6 minutes.

The solution:

- An AI extraction step reads each intimation email and attachment and produces structured fields (policy number, vehicle number, date and place of loss, description), validated against the policy database.
- An unattended RPA robot opens the claims system, navigates to "New intimation", fills the validated fields, saves, and records the claim number back in the tracking sheet.
- Failed validations and screens the robot does not recognise go to a person's queue with screenshots.

The team's data entry time falls by about 80%. Twice in the first quarter, a system update moved fields and the robot stopped; monitoring alerted the RPA developer, who fixed the selectors within a day. The insurer plans to replace the robot with an API integration when the claims system is upgraded next year.

## Common mistakes

- **RPA where an API exists.** APIs are faster and sturdier.
- **Fixed screen positions.** Use element properties so small changes do not break robots.
- **Automating unstable processes.** Robots break whenever the process or screens change.
- **No monitoring or owner.** Broken robots fail silently.
- **Robots with admin credentials.** Use least-privilege accounts stored in a vault.

## Practise

Take a free beginner course at UiPath Academy, or the Power Automate desktop modules on Microsoft Learn.

1. Build a simple robot that opens a website or desktop app, fills a form from a spreadsheet row and saves a confirmation.
2. Change the layout slightly (resize the window or move to a different screen resolution) and see whether it still works; fix it with better selectors.
3. Write down for one process in your organisation whether RPA, an API integration or an AI agent fits best, and why.

**You are done when you can** explain when you would choose RPA over an API or an AI agent, and show a robot that survives a small layout change.
