## What it is

**Rust** is a programming language for building fast, reliable software: operating systems, browsers, databases, web servers, command-line tools and, more and more, the engines underneath AI. It compiles to machine code, so it runs about as fast as C and C++. The difference is safety. Rust's compiler checks how your program uses memory and threads, and refuses to build code that could crash, leak memory or let two threads corrupt the same data.

It does this without a **garbage collector**. Languages like Java, Go and Python pause now and then to clean up memory. Rust instead tracks who **owns** each value. When the owner is finished, the memory is freed at that exact point. The result is speed you can predict, which matters for things like payment systems, games and model inference.

Rust is young compared with C (1972) or Python (1991). Its first stable version came out in 2015. It has been voted the "most admired" language in the Stack Overflow developer survey year after year; in 2025, 72% of developers who used it wanted to keep using it.

```flow
dir: LR
title: From slower to faster
Python | easy, flexible -> Java, Go | a garbage collector manages memory
Java, Go -> C, C++ | fast, but unsafe by default
C, C++ -> Rust | fast, and the compiler blocks memory bugs
```

## How it works

Three ideas carry most of Rust.

- **Ownership.** Every value has one owner, a variable. When the variable goes out of scope, the value is dropped. You can move a value to a new owner, after which the old name can no longer use it.
- **Borrowing.** Instead of moving, you can lend a value with a reference. The **borrow checker** enforces a simple rule: at any moment you can have many readers or one writer, never both. This single rule rules out data races and many memory bugs.
- **Zero-cost abstractions.** Rust gives you high-level tools such as iterators, closures, generics and pattern matching, and compiles them down to code as fast as a hand-written loop.

You work with Rust through **Cargo**. `cargo new` creates a project, `cargo build` compiles it, `cargo run` runs it, `cargo test` runs tests, and `cargo add` pulls in a library, called a **crate**, from crates.io.

Why are big companies moving to it? Most serious security bugs in large C and C++ codebases are memory-safety bugs. Rust removes most of them by design.

**Rust next to Python.** The two work well together. Python is where you explore, train and glue things together; Rust is where you make a slow, hot piece fast and safe. Many Python tools you already use are Rust underneath: Polars (data frames), Hugging Face tokenizers, pydantic-core and the Ruff linter.

## A worked example

Ananya works at an e-commerce company in Hyderabad. Her team's Python service checks every search query against a list of 20 lakh banned phrases before it reaches the recommendation model. At festival-sale peaks it falls behind, and the queue grows.

She profiles the service. 80% of the time goes into one function that scans the phrase list. The rest, calling the model and returning results, is fine in Python.

Rather than rewrite everything, she rewrites only that function in Rust:

```rust
use std::collections::HashSet;

pub fn is_blocked(query: &str, banned: &HashSet<String>) -> bool {
    query
        .to_lowercase()
        .split_whitespace()
        .any(|word| banned.contains(word))
}
```

The `&str` and `&HashSet` are borrows: the function reads the data without taking ownership, and the compiler guarantees nothing else changes it at the same moment. She wraps the function with **PyO3** so Python can call it like any other module, then builds it with `maturin`. The Python code changes by one import line.

The scan becomes about fifteen times faster and the queue disappears. Just as important, the team did not have to learn a whole new stack. Rust went where it paid off and nowhere else.

## Common mistakes

**Rewriting everything in Rust.** Most code is not the bottleneck. Profile first, then move the slow, critical parts. Keep exploration and glue in Python.

**Fighting the borrow checker instead of listening to it.** Its errors are long but precise. Read the whole message; it usually tells you the fix. Most beginners hit the same few errors in their first two weeks, then rarely again.

**Expecting C++ habits to work.** Shared mutable pointers everywhere do not compile in Rust. Prefer owned values, clear ownership, and passing references down rather than storing them.

**Using `unwrap()` everywhere.** It turns any error into a crash. Fine while learning; in real code handle the `Result` or use `?`.

**Choosing Rust for a two-day prototype.** The learning curve is real. Rust shines in code that will run for years under load.

**Thinking Rust is only for systems programmers.** Web back ends (Axum, Actix), command-line tools, WebAssembly in the browser and data tools are all common Rust work today. Many learners in India come to it from Python or JavaScript, not C.
