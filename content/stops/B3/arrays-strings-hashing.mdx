## What it is

Three structures do most of the work in everyday code.

An **array** keeps items in order, side by side in memory. In Python, a `list` is an array. Because items are next to each other, reading item 5 or item 5 lakh takes the same time. Adding to the end is cheap; inserting at the front means shifting everything along.

A **string** is an array of characters. In Python and Java strings cannot be changed once made, so every edit creates a new string.

A **hash map** stores pairs of a key and a value and finds a value from its key in about the same time however many pairs it holds. Python's `dict` and `set` are hash maps. They are the main tool for counting, deduplicating and matching.

```text
 ARRAY (list)                         HASH MAP (dict)
 index:  0      1      2      3        key           hash()   slot   value
       +------+------+------+------+   "Pune"   --->  7  ---> [7]   1,240 orders
       | Pune | Goa  | Agra | Pune |   "Goa"    --->  2  ---> [2]   310 orders
       +------+------+------+------+   "Agra"   --->  5  ---> [5]   95 orders
 read by position: O(1)               read by key: O(1) on average
 search by value:  O(n)               no order by position
```

## How it works

**Arrays** store items in one block of memory. The computer works out where item i lives with simple arithmetic, which is why reading by position is O(1). Searching for a value still means looking at items one by one, O(n), unless the array is sorted.

Python lists grow automatically. When the block fills up, Python allocates a bigger one and copies everything over. That copy is O(n), but it happens rarely enough that appending stays O(1) on average.

**Hash maps** use a **hash function** that turns a key, such as the text "Pune", into a number. That number picks a slot in an internal array, and the value is stored there. To read it back, the map hashes the key again and jumps straight to the slot. Sometimes two keys land in the same slot, a **collision**; the map stores both and compares keys to find the right one. With a good hash function and enough slots, lookups, inserts and deletes are O(1) on average.

The trade-off is memory and order. A hash map uses more memory than a list, and it is not for reading by position.

| Operation | List (array) | Dict / set (hash map) |
|---|---|---|
| Read by position | O(1) | not supported |
| Find a value or key | O(n) | O(1) on average |
| Add at the end / insert a key | O(1) on average | O(1) on average |
| Insert or delete at the front | O(n) | O(1) on average |
| Keeps insertion order | yes | yes in Python 3.7+ |

Most interview problems on arrays use one of a few patterns: a **frequency count** (count items in a dict), a **seen set** (remember what you have met to spot repeats), **complement lookup** (store values so you can check for "target minus this" instantly), and **grouping** (map a computed key, such as sorted letters, to a list of items).

## A worked example

Rahul is preparing for interviews and practising on order data from a small Jaipur bakery. He has a list of order amounts for one day and wants to know whether any two orders add up exactly to ₹1,000, because the bakery offers a combo at that price.

The obvious answer tries every pair:

```python
def pair_for(amounts, target):
    for i in range(len(amounts)):
        for j in range(i + 1, len(amounts)):
            if amounts[i] + amounts[j] == target:
                return i, j
    return None
```

That is O(n²). Fine for 20 orders, slow for 2 lakh.

The hash map version scans once. For each amount it asks: have I already seen the amount that would complete ₹1,000?

```python
def pair_for(amounts, target):
    seen = {}                     # amount -> position
    for i, a in enumerate(amounts):
        need = target - a
        if need in seen:          # O(1) on average
            return seen[need], i
        seen[a] = i
    return None
```

With amounts `[250, 400, 600, 120]` and a target of 1,000: at 250 it needs 750 (not seen); at 400 it needs 600 (not seen); at 600 it needs 400, which it has seen at position 1, so it returns `(1, 2)`. One pass, O(n) time and O(n) space.

Next he counts the most popular item. Rather than sorting, he uses a frequency count:

```python
from collections import Counter
items = ["bun", "cake", "bun", "puff", "bun", "cake"]
Counter(items).most_common(1)   # [('bun', 3)]
```

`Counter` is a dict underneath: one pass, O(n).

## Common mistakes

**Checking membership in a list inside a loop.** `if x in some_list` is O(n) each time. Inside a loop over n items that is O(n²). Convert to a set first.

**Building strings with += in a loop.** Each `+=` copies the whole string. Collect pieces in a list and call `"".join(pieces)` once.

**Using unhashable keys.** Lists cannot be dict keys in Python because they can change. Use a tuple, or a string such as the sorted letters of a word.

**Forgetting to normalise keys.** "+91 98450 12345" and "9845012345" are the same customer but different keys. Clean keys before you count or match.

**Assuming dicts are always O(1).** They are O(1) on average. With very poor hashing, or an attacker choosing keys, they can slow down. In interviews, say "O(1) on average".

**Mutating a list while looping over it.** Removing items as you iterate skips some. Build a new list instead.
