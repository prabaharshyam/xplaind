## What it is

Claude can make **animated explainer videos**: titles that slide in, diagrams that build step by step, charts that grow, icons that move along a path. It does this by **writing code** that draws and animates each element. It does not film anything or generate camera footage. That makes it ideal for **motion graphics**, which means animated text, shapes and charts that explain an idea, a process or some numbers.

Because the video is code, it behaves like a document, not a recording: change one word, number or timing and render again. You can also feed it data and get a hundred versions.

### Three routes, as of November 2026

- **A Claude artifact.** In an ordinary chat, ask for an animated HTML, CSS or SVG scene. It plays in the chat straight away. To get a video file, you screen-record it or move it into Remotion. Best for one scene or a quick test of an idea.
- **Claude Code with Remotion.** Remotion is a framework for making videos with React code. Claude Code (included in paid Claude plans such as Pro, not the Free plan) writes the project on your computer, and Remotion renders a real MP4. Best for anything longer than one scene, anything with narration, and series or data-driven videos.
- **Claude Motion.** Anthropic announced it in beta on 8 October 2026. You describe the explainer, or paste a report or data, and Claude builds a short animation you can edit and download as an MP4. It is only on **Team and Enterprise plans**; it is not on Free, Pro, Max or Ultra. Team workspaces have it on by default, and on Enterprise an owner must switch it on. Longer animations use more of your plan's usage limit.

Most learners use a personal plan, so this lesson builds with **Claude Code and Remotion** and uses artifacts for quick tests. If your employer gives you Motion, the scripting, style and accessibility advice applies to it unchanged.

**Licence check before work use.** Remotion is free for individuals, non-profit organisations and for-profit companies with up to 3 employees, including commercial work. A bigger for-profit company needs a paid company licence, and the count is the company's total headcount, not the number of people who use Remotion. Prices change, so check the licence and pricing pages on remotion.dev before you use it at work.


## How it works

### 1. Start from a script, not a prompt

Write each scene on one line: its length in seconds, what appears, what moves, and the words on screen or in the narration. Thirty to ninety seconds is plenty for one idea. A one-line prompt makes Claude guess every one of these choices, and the guesses are generic.

Two checks before you prompt. Read the narration aloud with a timer: if a 12-second scene takes 17 seconds to say, fix the script now. And give each scene one job; if it needs "and" twice to describe, split it.

### 2. Set a visual style once

Name two or three colours (with hex codes if you have brand colours), one font, the background, and the motion style, such as "smooth ease-in-out, 0.4 s moves, no bouncing". Ask Claude to put these in one style file or constants block. Every scene then reads from it, so changing the brand colour later is one edit.

### 3. Pick a route

| Your situation | Route | Plan you need | What you get |
|---|---|---|---|
| One scene, or testing whether an idea animates well | Claude artifact | any Claude plan | HTML that plays in chat; screen-record it |
| A full video with narration, on a personal plan | Claude Code + Remotion | a paid plan with Claude Code | rendered MP4, reusable project |
| Many versions from a sheet or a list | Claude Code + Remotion | a paid plan with Claude Code | one MP4 per row, from one template |
| A quick explainer from a report, at a company that has Motion | Claude Motion | Team or Enterprise | editable animation, MP4 download |
| Realistic people, places or products | a video model such as Veo | see the Veo and Flow guide | generated clips |

A simple rule: if you will touch it more than once, or it must match a voice-over, use Remotion. If you only want to see whether an idea works as animation, use an artifact.

### 4. What Claude Code writes, and how to read it

You can ask Claude Code to "create a new Remotion project with one component per scene", and it will set one up (the official starter is `npx create-video@latest`). You do not have to write React yourself, but you should be able to read it, because that is how you spot a wrong number or ask for a precise change. Four ideas cover most of it:

- **Frames and fps.** A video is a series of still pictures called frames. At 30 frames per second (fps), a 5-second scene is 150 frames.
- **The current frame.** `useCurrentFrame()` gives the number of the frame being drawn. Inside a scene it counts from that scene's start, so every scene can begin its animation at 0.
- **Interpolate.** `interpolate()` maps a frame range to a value range: "between frame 0 and frame 15, go from invisible to fully visible".
- **The composition.** A `Composition` sets the video's width, height, fps and length in frames (`durationInFrames`).

Here is Sneha's title card from the worked example below, a 5-second scene on its own:

```tsx
import { AbsoluteFill, Composition, interpolate, useCurrentFrame, useVideoConfig } from "remotion";

// Scene 6, the title card: the text fades in and rises over half a second.
export const TitleCard = ({ text }: { text: string }) => {
  const frame = useCurrentFrame(); // 0, 1, 2 ... counted from the start of this scene
  const { fps } = useVideoConfig(); // 30 in this project
  const opacity = interpolate(frame, [0, 0.5 * fps], [0, 1], { extrapolateRight: "clamp" });
  const y = interpolate(frame, [0, 0.5 * fps], [40, 0], { extrapolateRight: "clamp" });
  return (
    <AbsoluteFill style={{ backgroundColor: "#ffffff", justifyContent: "center", alignItems: "center", padding: 80 }}>
      <h1 style={{ fontSize: 96, color: "#5b2a86", textAlign: "center", opacity, transform: `translateY(${y}px)` }}>
        {text}
      </h1>
    </AbsoluteFill>
  );
};

// The video's settings: size, frame rate and length in frames.
export const RemotionRoot = () => (
  <Composition
    id="TitleCard"
    component={TitleCard}
    width={1080}
    height={1920}
    fps={30}
    durationInFrames={150} // 5 seconds x 30 fps
    defaultProps={{ text: "RAG = search first, then answer" }}
  />
);
```

Read it line by line. Half a second is `0.5 * fps`, which is 15 frames, so `opacity` goes from 0 to 1 over frames 0 to 15. The second `interpolate` moves the text up from 40 pixels below its place. `extrapolateRight: "clamp"` means "after frame 15, stay at the final value"; without it the text would keep rising off the screen, a common bug in Remotion code. The `Composition` says the video is 1080 wide, 1920 tall (a phone screen), 30 fps and 150 frames long.

Notice that timing is written as seconds times `fps`, not as raw frame numbers. Ask Claude to keep it that way. Then changing the frame rate later does not break every animation.

### 5. Sync to the narration with timestamps

Claude cannot hear your audio, so "match the voice-over" is not something it can do by itself. Give it numbers instead:

1. Record the narration first and save it as one file.
2. Get the second at which each sentence starts. A transcription tool that outputs timestamps does this, for example Whisper; Remotion has helper packages for it. For six scenes, you can also play the file and write the times down.
3. Give Claude Code the list and ask it to convert seconds to frames and set each scene's length from it.

```tsx
// Second at which each narration sentence starts, from the transcript, then the end.
const cues = [0, 6.2, 18.5, 30.9, 46.0, 55.4, 60.0];
const fps = 30;
const starts = cues.map((s) => Math.round(s * fps)); // [0, 186, 555, 927, 1380, 1662, 1800]
const lengths = starts.slice(1).map((f, i) => f - starts[i]); // [186, 369, 372, 453, 282, 138]
```

Each scene then goes inside a `Series.Sequence` with `durationInFrames` set to its length, and the narration plays under all of them. The full video is a second `Composition`, with id `RagVideo` and `durationInFrames={1800}`. One expert detail: round the **start times** to frames, then subtract. If you round each scene's length separately, small rounding errors add up and the last scenes drift away from the voice.

### 6. Refine by talking

Because the video is code, precise changes are cheap: "make the arrows in scene 3 come from the left", "change 38% to 41%". Only that element changes. Two habits help:

- **Ask for stills.** Claude Code cannot watch the video either. Ask it to render still frames of key moments with `npx remotion still` and look at them, or check them yourself, before a full render.
- **Preview in Remotion Studio** (`npx remotion studio`). It plays the video in your browser and lets you scrub frame by frame.

### 7. Add sound and captions

Narration does the explaining; on-screen text should only be key words. Add captions for people watching on mute. A good rule of thumb: keep each caption on screen for at least one second per three words, and never shorter than about one and a half seconds. Put a quiet music track under the voice only if it helps, and fade it out at the end.

### 8. Render and export

Remotion renders on your computer with the CLI, for example `npx remotion render RagVideo out/rag.mp4`. It needs Node.js installed and draws each frame in a headless browser (one with no window) that Remotion sets up for you. How long it takes depends on your computer and how much each frame draws, so time your first render before you plan a batch of a hundred.

| Where it will play | Size (width x height) | Frame rate | Minimum text size |
|---|---|---|---|
| WhatsApp, Reels, Shorts (phone first) | 1080 x 1920 (9:16) | 30 fps | about 48 px |
| Classroom projector, YouTube, slides | 1920 x 1080 (16:9) | 30 fps | about 36 px |
| A feed post that must work both ways | 1080 x 1080 (1:1) | 30 fps | about 44 px |

These are sensible defaults, not platform rules. Thirty fps is plenty for motion graphics; 60 fps doubles the render work and rarely looks better for text. Messaging apps often compress videos again, which blurs small text, so send a test to your own phone. Length and size limits differ by app and change, so check the current limit where you will post.

### Videos from data

A Remotion video is a program, so it can take data as props, the inputs a component receives. A sales team can render one personalised video per region from a spreadsheet; a teacher can render one video per chapter from a list of scripts. Claude Code can write the loop that reads each row and renders a file. Before rendering 40 versions, render the two hardest rows (the longest name, the biggest number) and check that nothing overflows.

## A worked example

Sneha teaches computer science at a college in Nagpur. Her students find RAG (retrieval-augmented generation, where a chatbot first searches documents and then answers) confusing, so she wants a 60-second animation for her class WhatsApp group. She is making it herself, as an individual teacher, and Remotion's free licence is meant for individuals. If the college wanted to use it officially, the college would check whether it qualifies for the free licence or needs a company licence.

She writes a script, with planned timings that add up to 60 seconds:

1. (6 s) A student types "What is the exam syllabus?" into a chat box.
2. (12 s) The question turns into a row of numbers, an "embedding", and moves to a stack of documents.
3. (12 s) Three matching paragraphs light up and slide out of the stack.
4. (15 s) The question and the three paragraphs flow into a box labelled "LLM".
5. (10 s) An answer appears, with the source document's name underneath.
6. (5 s) Title card: "RAG = search first, then answer".

She reads the narration aloud with a timer; it fits. She records it on her phone in a quiet room and runs it through a transcription tool that gives timestamps. Her real sentences start at 0, 6.2, 18.5, 30.9, 46.0 and 55.4 seconds, and the file ends at 60.0. (These are example numbers for this lesson, not a measurement.) So her real scene lengths are 6.2, 12.3, 12.4, 15.1, 9.4 and 4.6 seconds, close to the plan but not equal.

Her prompt to Claude Code:

```text
Create a Remotion project for a 60-second explainer, 1080 x 1920, 30 fps.
Six scenes, one component each, following the attached script.
Narration: public/narration.mp3. Scene start times in seconds:
0, 6.2, 18.5, 30.9, 46.0, 55.4; the video ends at 60.0.
Round start times to frames, then take differences for scene lengths.
Style: flat, white background, purple #5b2a86, one sans-serif font,
0.4 s ease-in-out moves, no bouncing. Text at least 48 px.
Captions under each scene with the key words only.
Keep all colours and sizes in one style file.
```

Claude Code builds it, and she previews it in Remotion Studio. The first draft is close. She asks for two changes. In scene 2, the numbers of the embedding flew in within half a second, too fast to follow, so she asks for them to appear one by one over 3 seconds. In scene 3, she asks for each paragraph to show its document's name. Each change touches one component.

She renders `out/rag.mp4`, sends it to herself on WhatsApp to check the captions are still sharp, then posts it to the class group.

Next semester she reuses the project: a new script, new narration and new start times for each topic, with the same style file and scene structure.

## Common mistakes

**Guessing the audio sync.** Asking Claude to "match my voice-over" fails because it cannot hear the file. Give it sentence start times and let it convert them to frames.

**Forgetting to clamp.** An `interpolate` without `extrapolateRight: "clamp"` keeps moving after its range ends, so text drifts off the screen or fades past zero.

**Too much text on screen.** People cannot read a paragraph and listen at the same time. Keep on-screen text to a few key words per scene and let narration carry the detail.

**Captions that vanish too fast.** Hold each caption for at least one second per three words. Check it by reading along at normal speed.

**Low contrast and flashing.** Pale grey on white is unreadable on a phone in sunlight; use dark text on a light background or the reverse. Never make anything flash more than three times in one second; fast flashing can trigger seizures in people with photosensitive epilepsy.

**Motion for its own sake.** Spinning and bouncing distract. Build a diagram in the order you explain it, and animate nothing else.

**The wrong shape.** A 16:9 video on WhatsApp shows as a thin strip with tiny text. Decide 9:16 or 16:9 before the first prompt, because changing it later means re-laying out every scene.

**Not checking the numbers.** Claude can mistype a figure from your table. Before you publish a data video, pause on every number and compare it with the source.

**Using it for realistic scenes.** For people, places and products on camera, use a video model such as Veo.

**Ignoring licences.** Use royalty-free music and your own or licensed images. At a company with more than 3 employees, check Remotion's company licence first.
