## What it is

Your AI application works on your laptop. Then it goes to a server, and one evening the client calls: "The assistant stopped answering." Nearly every server your AI system runs on is **Linux**, and you reach it through a text **shell**, usually Bash, over **SSH**. There is no desktop, no mouse and no File Explorer.

You do not need to be a Linux expert. You need a small, reliable set of skills:

| Skill | Commands |
| --- | --- |
| Moving around and reading files | `pwd`, `ls -la`, `cd`, `cat`, `less`, `head`, `tail`, `grep` |
| Seeing what is running and what it uses | `ps aux`, `top` or `htop`, `df -h`, `du -sh`, `free -h` |
| Reading logs as they arrive | `tail -f`, `journalctl -u`, `docker logs -f` |
| Settings and scripts | `export`, `env`, `chmod +x`, `set -euo pipefail` |
| Connecting securely | `ssh-keygen`, `ssh`, `~/.ssh/config`, `ssh -J` |

```text
   Your laptop                 Bastion (jump host)          App server
 +--------------+   SSH key   +-------------------+   SSH   +------------------+
 | private key  | ----------> | checks your       | ------> | ai-assistant     |
 | stays here   |             | public key        |         | service, logs,   |
 +--------------+             +-------------------+         | disk, memory     |
                                                            +------------------+
```

This lesson follows you through a real outage for a logistics client in Pune: from connecting, to finding the cause, to fixing it and writing it up. By the end you will diagnose a full disk and connect with SSH keys confidently.

## How it works

### Navigation and files

`pwd` shows where you are. `ls -la` lists files, including hidden ones. `cd` moves. `cat` prints a short file; `less` lets you scroll a long one; `head` and `tail` show the start and end.

`grep -i "timeout" app.log` finds matching lines, ignoring case; `grep -c` counts them.

**Pipes** (`|`) join small tools into powerful ones:

```bash
grep ERROR app.log | sort | uniq -c | sort -rn | head
```

This finds error lines, groups identical ones, counts each, sorts by count and shows the top ten: the most common errors in one line.

### Processes and resources

| Question | Command |
| --- | --- |
| Is my service running? | `ps aux \| grep uvicorn` or `systemctl status ai-assistant` |
| What is using CPU and memory right now? | `top` or `htop` |
| How full are the disks? | `df -h` |
| Which folders are large? | `du -sh *` or `sudo du -sh /var/* \| sort -h` |
| How much memory is free? | `free -h` |

A full disk is a top cause of mystery outages: logs, temporary files and model downloads quietly fill it until the service cannot write anything.

### Logs

- `tail -f app.log` follows a log file as it grows.
- Services run by **systemd** log to the journal: `journalctl -u ai-assistant --since "1 hour ago"`.
- Containers: `docker logs -f container-name`.

### Environment variables

Programs read settings such as `DATABASE_URL` and API keys from the **environment**. `export NAME=value` sets one for your session; `env` lists them. Keep secrets in the environment or a secret manager, never in code or in shell history.

### Scripts

A shell script is a file of commands. Start every script with:

```bash
#!/usr/bin/env bash
set -euo pipefail
```

`set -euo pipefail` makes the script stop at the first failed command, at any unset variable and at any failed step in a pipe, instead of carrying on with half-done work. Make it executable with `chmod +x script.sh`.

### SSH and keys

1. `ssh-keygen -t ed25519` creates a key pair on your machine.
2. You give the server your **public** key. The **private** key never leaves your machine.
3. `ssh deploy@10.0.4.12` logs you in without a password.

A `~/.ssh/config` entry gives servers short names. Many companies route SSH through a **jump host** or **bastion**: `ssh -J bastion app-server` hops through it.

### Permissions

Each file has permissions for owner, group and others: read, write and execute. A private key needs `chmod 600`, or SSH refuses to use it. Use `sudo` only for single commands that need it, and think twice before pressing Enter after `rm -rf`.

## A worked example

A logistics client in Pune reports that their delivery-query assistant stopped answering at 19:05. You connect through their bastion:

```bash
ssh -J bastion.client.in deploy@assistant-01
systemctl status ai-assistant        # active, but restarting every 30 seconds
journalctl -u ai-assistant --since "19:00" | tail -50
```

The log shows `OSError: [Errno 28] No space left on device`. You check the disk:

```bash
df -h /                                # 100% used
sudo du -sh /var/* | sort -h | tail -3
```

`/var/log/ai-assistant` holds 38 GB. Debug logging was left on after a test two weeks ago, and the logs were never rotated.

| Time | Step | Finding |
| --- | --- | --- |
| 19:08 | `systemctl status` | Service restarting every 30 seconds |
| 19:09 | `journalctl` | "No space left on device" |
| 19:10 | `df -h` | Disk 100% full |
| 19:11 | `du -sh` | 38 GB of debug logs |
| 19:15 | Compress and remove old logs, set level to INFO, add logrotate rule, restart | Disk at 34% |
| 19:20 | Test a query | Assistant answering again |

In your incident note you write the cause, the fix and two follow-ups: a disk-space alert at 80%, and a check in CI that the log level is not DEBUG in production.

## Common mistakes

- **Working as root by habit.** Mistakes become disasters. Use a normal user and `sudo` for single commands.
- **Pasting secrets on the command line.** They land in shell history. Use environment files with restricted permissions or the client's secret manager.
- **Editing production by hand and telling nobody.** The next deploy overwrites your fix. Put the change in code or config and write it down.
- **Scripts without `set -euo pipefail`.** A failed step goes unnoticed and later steps damage data.
- **Sharing private keys.** Each person and each machine gets its own key, so access can be removed cleanly.
- **Deleting files you do not understand to free space.** Find what is large and why first.

## Practise

Watch or read the Missing Semester lectures on the shell and the command-line environment, linked below.

1. **Top errors.** On any Linux machine, such as a free cloud VM, WSL on Windows or a Docker container, create a 500-line fake log with some ERROR lines, and list the top three error messages with one pipeline.
2. **Keys.** Generate an SSH key, add it to a server or to GitHub, and connect without a password.
3. **A script.** Write a script with `set -euo pipefail` that checks disk usage and prints a warning above 80%.

**You are done when you can** find which process or folder is filling a disk, and explain why the private key never leaves your machine.
