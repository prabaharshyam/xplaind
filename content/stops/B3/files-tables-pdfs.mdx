## What it is

Clients rarely hand you a clean database. They send a shared folder: Excel sheets with merged headers, CSVs exported from an old billing system, JSON from a vendor's API, and hundreds of PDFs, some digital and some scanned. Getting reliable text and numbers out of these is called **document parsing**, and it is the first real task on most AI projects. If this step is wrong, every answer built on it is wrong too.

The work splits by file type:

| File type | What usually goes wrong | Main tool |
| --- | --- | --- |
| **CSV and Excel** | Encodings, lost leading zeros, Indian number and date formats, banner rows | pandas |
| **JSON** | Deep nesting, lists inside records | `json`, `pd.json_normalize` |
| **Digital PDF** | Columns interleave, headers and footers repeat, words split | pypdf, pdfplumber |
| **Scanned PDF** | No text at all, only images | OCR, such as Tesseract or a cloud service |
| **PDF tables** | Table comes out as a jumbled line | pdfplumber, Camelot, or a vision-capable model |

```text
   Client folder
        |
        +-- .csv / .xlsx --> pandas with explicit options --> clean table
        |
        +-- .json -------> json + json_normalize ----------> flat table
        |
        +-- .pdf --------> extract text per page
                              |
                              +-- enough text? --> keep, with page numbers
                              |
                              +-- almost none? --> OCR --> spot-check
                              |
                              +-- has tables? --> table tool --> check rows
```

This lesson follows a hospital chain in Madurai whose policies and pharmacy price list must feed an assistant. By the end you will load messy tables correctly and detect which PDFs need OCR.

## How it works

### CSV and Excel

`pd.read_csv` and `pd.read_excel` do most of the work, but their defaults assume tidy data. Real files need options:

| Problem | Option |
| --- | --- |
| Tamil or Hindi names come out garbled | `encoding="utf-8"`, or `"utf-8-sig"` for an Excel byte-order mark. Garbling usually means UTF-8 was read as `cp1252`, which cannot hold Indian scripts |
| Item codes, branch codes and landline numbers lose leading zeros | `dtype={"item_code": str}` for id-like columns |
| Dates like 05/11/2026 | `parse_dates` with `dayfirst=True` |
| Banner rows above the header | `skiprows` |
| Broken rows crash the load | `on_bad_lines="warn"` to see them |

Indian number formats such as "1,25,000" need the commas removed before converting to numbers.

### Excel quirks

Excel files add their own surprises. A workbook can hold several sheets: read one with `sheet_name="Rates"` or all of them with `sheet_name=None`, which gives a dictionary of tables. Merged header cells come out as one filled cell and several empty ones, so rebuild the header by hand or with `header=[0, 1]` for two header rows. Hidden rows and columns are still read, and formulas arrive as their last saved values, not as formulas. When in doubt, open the file and look at it before you write any code.

### JSON

`json.load` gives nested dictionaries and lists. `pd.json_normalize` flattens a list of records into a table, with dotted column names such as `customer.city` for nested fields.

### PDFs

A PDF is a set of drawing instructions, not a document with paragraphs. Libraries such as pypdf or pdfplumber recover text from digital PDFs, but columns may interleave, headers and footers repeat on every page, and words can split oddly.

A PDF that returns **no text at all** is probably a scan: it holds only images, so you need **OCR** (optical character recognition). For Indian languages, install the right OCR language pack. Tables need a table-aware tool or a vision-capable model.

Always record the **page number** with every piece of text. Citations and debugging later depend on it.

### Checks

After every extraction, count and compare: rows in versus rows out, pages with no text, totals that should match. Then print five random samples and read them. Five minutes of reading finds problems no count will.

## A worked example

A hospital chain in Madurai wants an assistant over its policies and its pharmacy price list. They send a ZIP file.

**The price list CSV.** Tamil drug names come out garbled, because the old loading script set `encoding="cp1252"`. The file is really UTF-8 with a byte-order mark added by Excel, so `encoding="utf-8-sig"` fixes it. Item codes like "000412" lost their zeros; `dtype={"item_code": str}` keeps them. Prices such as "1,250.00" become numbers after removing commas.

**The policy PDFs.** Of 140 PDFs, pypdf extracts text from 122. A quick check flags the 18 that return almost nothing:

```python
from pathlib import Path
from pypdf import PdfReader

pdfs = sorted(Path("policies").glob("*.pdf"))
needs_ocr, records = [], []

for path in pdfs:
    reader = PdfReader(path)
    pages = [p.extract_text() or "" for p in reader.pages]
    chars = sum(len(p) for p in pages)
    if chars < 200 * len(pages):
        needs_ocr.append(path)       # probably scanned
    else:
        for n, text in enumerate(pages, 1):
            records.append({"file": path.name, "page": n, "text": text})
```

The 18 are scanned circulars. OCR reads them, and a spot-check of three against the images shows the Tamil headers are wrong until the Tamil OCR language pack is added.

| Item | Count | Problem | Fix |
| --- | --- | --- | --- |
| Price list rows | 4,812 | Garbled names, lost zeros, text prices | `utf-8-sig`, `dtype=str`, remove commas |
| Digital PDFs | 122 | Repeated headers and footers | Strip lines that repeat on most pages |
| Scanned PDFs | 18 | No text | OCR with English and Tamil packs |
| Pages that still failed | 6 | Faint photocopies | Listed for the client to resend |

The notes for the client list exactly which files needed OCR and which pages failed, so nobody is surprised when an answer about one faint circular is weaker.

## Common mistakes

- **Trusting defaults.** pandas guesses types and will turn item codes like 000412 into numbers, dropping the leading zeros. Set types for id-like columns.
- **Ignoring encodings.** Garbled names in Indian scripts nearly always mean the wrong encoding, not a broken file.
- **Assuming every PDF has text.** Scans return empty strings silently. Measure characters per page.
- **Losing the page number.** Without it you cannot cite a source or debug a wrong answer.
- **Reading dates month-first.** 05/11/2026 is 5 November in India; set `dayfirst=True`.
- **Never reading the output.** Counts miss problems that five random samples reveal.
