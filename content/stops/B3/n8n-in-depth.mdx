## What it is

Real business automations go beyond a trigger and three nodes. They process many records, call APIs with limits, combine data from several sources, include AI steps, and must keep running when something fails. n8n has the building blocks for this:

- **Sub-workflows**: reusable workflows called from others, like functions.
- **Loops and batches**: process items in groups to respect API limits.
- **Merge and split**: combine data from two sources or split lists into items.
- **Code nodes**: small JavaScript or Python snippets for logic the visual nodes do not cover.
- **AI nodes**: model calls, structured output parsers and agent nodes with tools.
- **Error workflows**: run when any workflow fails, to alert someone.

## How it works

**Structure.** Keep each workflow focused. Put shared logic, such as "look up a customer" or "send an alert", in sub-workflows. Name nodes clearly ("Get open orders from Shopify", not "HTTP Request 3").

**Volume and limits.** Use Loop Over Items with a batch size and a Wait node to stay within API rate limits. For large jobs, page through results rather than fetching everything at once.

**Merging data.** The Merge node combines items from two branches by position or by a matching field (for example, matching sheet rows to CRM contacts by email).

**Code nodes.** Useful for parsing unusual formats, date maths or Indian number formatting. Keep them short and commented; complex logic is harder to maintain here than in a proper service.

**AI steps.** Use a model node with a clear prompt and a structured output parser so later nodes get reliable fields. Agent nodes can call tools (other nodes or sub-workflows) for multi-step tasks; apply the same caution as any agent: limited tools, limits on steps, and approval for risky actions.

**Reliability.** Set retries on flaky nodes. Make writes idempotent (check whether a record already exists before creating it) so reruns do not create duplicates. Attach an error workflow that posts to your team chat with the workflow name, the failing node and a link to the execution.

**Maintainability.** Export workflows as JSON into Git, or use n8n's source control features where available. Keep separate development and production instances or projects. Store credentials per environment.

**Self-hosting basics.** Running n8n yourself with Docker gives data control. You then own backups of its database, updates, security and scaling (queue mode with workers for high volume).

## A worked example

A Bengaluru D2C skincare brand automates daily order reconciliation between its Shopify store, its payment gateway and its accounting sheet, about 1,500 orders a day.

- **Main workflow**, scheduled at 6 am: fetch yesterday's orders from Shopify in pages of 250; fetch settlements from the payment gateway's API in batches with a 1-second wait to respect its limit.
- **Merge** orders and settlements on order id.
- **Code node**: flag mismatches (amount differs, settlement missing, refund not recorded) and format amounts in Indian style.
- **Sub-workflow** "write to accounting sheet": checks if a row for the order exists before adding, so reruns are safe.
- **AI node**: for each mismatch, write a one-line explanation for the finance team from the order and settlement data.
- **Slack message** with totals and a link to the mismatch sheet.
- **Error workflow**: any failure alerts the finance-ops channel with the execution link.

The finance team's two hours of morning reconciliation becomes 15 minutes of reviewing flagged cases. When the payment gateway's API was down one morning, the error alert fired, and a rerun at 9 am completed without duplicates.

## Common mistakes

- **One giant workflow.** Split it into sub-workflows with clear names.
- **Ignoring rate limits.** Batch and wait.
- **Non-idempotent writes.** Reruns create duplicates.
- **Logic buried in big code nodes.** Keep code small; move complex logic to a service.
- **No version control or test instance.** Changes to production break things silently.

Complete n8n's Level two text course and read the hosting overview.

1. Build a workflow that processes at least 100 items from an API or sheet in batches, with a wait between batches.
2. Add a merge of two data sources, a sub-workflow for writing records that checks for existing rows, and an AI step with structured output.

**You are done when you can** rerun your workflow twice in a row without creating duplicates, and show an error alert with a link to the failed execution.
