## What it is

A **web API** lets your program ask another service for data or actions over the internet. You send an HTTP request to a URL; the service replies with a **status code** (did it work?) and usually a body in **JSON** (the data).

Weather, maps, payments, government open data and every AI model provider work this way. Calling an API from Python is the core skill behind calling language models later.

## How it works

**The requests library.**

```python
import requests

r = requests.get("https://api.example.com/weather",
                 params={"city": "Chennai"}, timeout=10)
print(r.status_code)
data = r.json()          # JSON text becomes Python dictionaries and lists
print(data["temperature"])
```

**Status codes.**

- `200` OK: it worked.
- `400` bad request: something about your request is wrong.
- `401` or `403`: not signed in, or not allowed.
- `404` not found: the URL or the item does not exist.
- `429` too many requests: slow down.
- `500` to `504`: the server failed; often temporary.

Check before using the data: `r.raise_for_status()` raises an error for 4xx and 5xx codes.

**JSON in Python.** `r.json()` turns the reply into dictionaries (for JSON objects) and lists (for arrays). Read nested values step by step: `data["current"]["temp_c"]`. Print the whole reply first to see its shape.

**Parameters, headers and bodies.** Query parameters go in `params`. API keys usually go in headers: `headers={"Authorization": "Bearer ..."}`. Sending data uses `requests.post(url, json={...})`.

**Timeouts.** Without `timeout=`, a request to a slow or broken server can hang forever, freezing your program. Always set one.

**Keys and secrets.** Never write API keys in code you share. Read them from an environment variable: `os.environ["WEATHER_API_KEY"]`.

**Limits.** Most APIs limit requests per minute and may charge per call. Read the documentation's limits section.

## A worked example

Anita is building a small dashboard of air quality for her city. She uses a free public API that returns current readings for a location.

```python
import os, requests

url = "https://api.openaq.example/v3/latest"
r = requests.get(url, params={"city": "Delhi"},
                 headers={"X-API-Key": os.environ["AQ_KEY"]}, timeout=10)

if r.status_code == 200:
    for reading in r.json()["results"][:5]:
        print(reading["location"], reading["parameter"], reading["value"])
elif r.status_code == 429:
    print("Rate limited; try again in a minute")
else:
    print("Request failed:", r.status_code, r.text[:200])
```

The first run returns 401: she had not exported her key in the new terminal. After `export AQ_KEY=...` it returns 200 and five readings. She prints the full JSON once to discover that some locations lack a `value` field, and adds a check for it.

## Common mistakes

- **Not checking the status code.** Code then fails confusingly on error replies.
- **No timeout.** A slow server can hang your program.
- **Guessing the JSON shape.** Print it and read it first.
- **API keys in code.** Use environment variables.
- **Ignoring rate limits.** Respect them, or you get blocked.
