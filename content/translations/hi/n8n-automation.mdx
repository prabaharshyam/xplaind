## ये क्या है

**n8n** ("n-eight-n" बोला जाता है) एक workflow automation tool है। आप visual canvas पर **nodes** जोड़कर automations बनाते हो। हर node एक काम करता है: नए email पर नज़र रखना, spreadsheet पढ़ना, API call करना, AI model से पूछना, message भेजना। Data एक node से अगले node तक बहता है।

ये Zapier या Make जैसा है, दो फ़र्कों के साथ जो लोग पसंद करते हैं। आप इसे अपने server पर **self-host** कर सकते हो, जिससे data आपके हाथ में रहता है और volume पर खर्च कम आता है, और इसमें मज़बूत **AI nodes** हैं, जिनमें AI Agent node भी है जो reason कर सकता है, tools use कर सकता है और बातचीत याद रख सकता है।

**Workflow automation** इसका business use है: एक छोटी team हर हफ़्ते घंटे वापस पा लेती है, क्योंकि software उन्हीं apps के बीच data ले जाता है जो वो पहले से use करते हैं।

```flow
Trigger: form enquiry | एक webhook -> AI Agent | classify करो और reply draft करो
Memory: पुरानी chats -> AI Agent
Model, prompt और tools -> AI Agent
AI Agent -> Fees के बारे में?
Fees के बारे में? -[हाँ]-> Sheet: log करो -> Gmail: approval के लिए draft
Fees के बारे में? -[नहीं]-> Slack: staff को alert करो
```

## ये काम कैसे करता है

**Triggers सब कुछ शुरू करते हैं।** आम हैं schedule (रोज़ सुबह 9 बजे), webhook (कोई दूसरा app किसी URL को call करे), app triggers (नया Gmail message, Google Sheets में नई row) और chatbots के लिए chat trigger।

**Nodes काम करते हैं।** n8n में सैकड़ों integrations हैं: Google Workspace, Slack, Notion, Airtable, HubSpot, databases, किसी भी API को HTTP requests, और official Business API से WhatsApp। **Logic nodes** जैसे IF, Switch, Merge और Loop flow को control करते हैं।

**Data JSON की तरह चलता है।** हर node items output करता है। बाद के nodes उन्हें `{{ $json.email }}` जैसे **expressions** से पढ़ते हैं। आप हर step पर ठीक-ठीक data देख सकते हो, जिससे debugging code के मुकाबले बहुत आसान हो जाती है।

**AI nodes।** AI Agent node एक chat model (Claude, GPT, Gemini या local model), एक system prompt, **memory** और **tools** को जोड़ता है। Tools दूसरे nodes हो सकते हैं, जैसे "इस sheet में ढूँढो" या "calendar event बनाओ", इसलिए agent सिर्फ़ बात नहीं, काम भी कर सकता है। Text को classify करने, fields को structured data में निकालने और summarise करने के लिए सरल nodes भी हैं।

**Credentials** एक बार save होते हैं और दोबारा use होते हैं, इसलिए API keys कभी workflows के अंदर नहीं बैठतीं।

**इसे चलाना।** जल्दी शुरू करने के लिए n8n Cloud use करो, या छोटे server पर Docker से self-host करो। Sample data से test करो, फिर workflow को activate करो ताकि वो अपने-आप चले।

| Building block | किसलिए है | Example |
|---|---|---|
| Schedule trigger | तय समय पर चलना | सुबह 8 बजे daily sales summary |
| Webhook | दूसरे app पर तुरंत react करना | Payment gateway का success event |
| HTTP Request | कोई भी API call करना | Exchange rates लाना |
| IF / Switch | conditions पर branch करना | Enquiries को type के हिसाब से route करना |
| AI Agent | tools के साथ reason करना और काम करना | Price sheet से FAQs का जवाब देना |
| Information Extractor | text को fields में बदलना | Invoice से amount और date पढ़ना |
| Wait / approval | इंसान के लिए रुकना | Reply भेजने से पहले approve करना |
| Error workflow | failures पकड़ना | Run fail हो तो Slack पर alert |

**भरोसा करने से पहले testing।** n8n में आप workflow हाथ से चला सकते हो, trigger पर sample data pin कर सकते हो ताकि हर test में वही input रहे, और हर node का output step-by-step देख सकते हो। असली जैसे बिखरे data से test करो: Hinglish में लिखी enquiry, खाली field, तीन attachments वाला email। ज़्यादातर automation bugs उन inputs से आते हैं जिन्हें किसी ने आज़माया ही नहीं।

**किस खर्च पर नज़र रखें।** हर AI step हर call पर थोड़ा खर्च करता है, और n8n Cloud plans हर महीने workflow runs की संख्या सीमित करते हैं। Client को monthly cost का वादा करने से पहले providers की sites पर मौजूदा limits और model prices देखो।

## एक example से समझो

Arvind जयपुर में 600 students वाला coaching institute चलाते हैं। Enquiries एक Google Form से हर समय आती हैं, और front desk अगले दिन reply करता है, तब तक कई parents किसी competitor को call कर चुके होते हैं।

वो एक दोपहर में एक workflow बनाते हैं:

1. **Google Forms trigger** हर नई enquiry पर।
2. **AI Agent**, जिसके prompt में batch timings, fees और demo-class schedule हैं। वो enquiry को fees, timings, demo या other में classify करता है, और parent ने जिस भाषा में लिखा, Hindi या English, उसी में reply draft करता है।
3. **IF node:** demo requests सीधे Google Calendar tool पर जाती हैं जो अगला खाली slot book कर देता है।
4. **Google Sheets** हर enquiry, उसकी category और draft को log करता है।
5. **Gmail** draft बनाता है, भेजा हुआ mail नहीं। Front-desk manager उसे अपने phone से approve करती हैं।

पहले महीने में median reply time 14 घंटे से घटकर 25 मिनट हो जाता है, और demo bookings एक तिहाई बढ़ जाती हैं। दो हफ़्ते तक लगभग बिना edit के drafts approve करने के बाद, Arvind "timings" category को automatically भेजने देते हैं और fees के लिए approval रखते हैं, जहाँ गलतियाँ महँगी पड़ती हैं।

जब एक रात Sheets API थोड़ी देर के लिए fail होती है, तो उनका error workflow Slack alert भेजता है और run दोबारा चलता है, इसलिए कोई enquiry नहीं खोती।

## आम गलतियाँ

**गड़बड़ process को automate करना।** पहले steps लिखो और सरल बनाओ; automation खराब process को और तेज़ी से fail कराता है।

**शुरू में AI को बिना review के भेजने देना।** Drafts और human approval से शुरू करो। Approval सिर्फ़ उन categories से हटाओ जिनका अच्छे output का लंबा record हो।

**Error handling न होना।** APIs fail होती हैं। Retries, error workflow और alerts जोड़ो, वरना failures हफ़्तों तक पता नहीं चलते।

**Keys और values को code में ही लिख देना।** Keys के लिए credentials और prices जैसी बदलने वाली values के लिए settings node या sheet use करो।

**एक विशाल workflow।** बड़े automations को छोटे workflows में बाँटो जो एक-दूसरे को call करें। उन्हें test और ठीक करना आसान होता है।

**Data protection को नज़रअंदाज़ करना।** Prompts और logs में customer data personal data है। सिर्फ़ उतना लो जितना चाहिए और जानो कि हर service उसे कहाँ store करती है।
