## ये क्या है

लगभग हर automation और AI application apps के बीच data भेजता है, और वो data लगभग हमेशा **JSON** (JavaScript Object Notation) में जाता है: एक text format जिससे apps structured data का आदान-प्रदान करते हैं। अगर आप JSON पढ़ और बदल सकते हो, तो लगभग किसी भी चीज़ को किसी से भी जोड़ सकते हो।

JSON के तीन building blocks हैं:

| Building block | कैसा दिखता है | Example |
| --- | --- | --- |
| **Object** | Curly braces में नाम वाले fields | नाम, phone और शहर वाला एक customer |
| **Array** (list) | Square brackets में items | Order lines की list |
| **Value** | Quotes में text, number, true या false, या null (खाली) | "Mysuru", 2, true, null |

Objects और arrays एक-दूसरे के अंदर nest होते हैं। Payment webhook में payment का एक object हो सकता है, उसके अंदर customer का object, और उसके अंदर notes की array।

```flow
title: एक order, nested JSON के रूप में
order (object) -> id: "ORD-88213"
order (object) -> customer (object)
customer (object) -> name: "Nisha Rao"
customer (object) -> phone: "9845012345"
customer (object) -> email: null
order (object) -> lines (array)
lines (array) -> [0] sku, qty, price
lines (array) -> [1] sku, qty, price
order (object) -> shipping (object)
shipping (object) -> city: "Mysuru"
shipping (object) -> pin: "570001"
```

इस lesson में हम एक online tea store के order webhook को देखेंगे कि वो dispatch sheet की rows और customer को SMS कैसे बनता है। Lesson के अंत तक आप किसी अनजान JSON payload से वही निकाल पाओगे जो workflow को चाहिए।

## ये काम कैसे करता है

### Path पढ़ना

Nested field तक पहुँचने के लिए बाहर से अंदर नाम follow करो, dots से जोड़कर। Array के items square brackets में **0** से गिने जाते हैं।

| आपको क्या चाहिए | Path |
| --- | --- |
| Order id | `order.id` |
| Customer का phone | `order.customer.phone` |
| पहली line की price | `order.lines[0].price` |
| दूसरी line का SKU | `order.lines[1].sku` |
| Delivery का PIN code | `order.shipping.pin` |

### असली samples देखो

सिर्फ़ documentation देखकर path का अंदाज़ा कभी मत लगाओ। असली या test event trigger करो और जो JSON आया उसे ठीक से देखो। n8n में output panel हर item को table, raw JSON या schema के रूप में दिखाता है; इसी से सही path ढूँढो और copy करो।

### चुनो और नाम बदलो

ज़्यादातर workflows को बड़े payload में से कुछ ही fields चाहिए। "Edit Fields" या "Set" step से उन्हें चुनो और साफ़ नाम दो: `payment.notes.contact_no` की जगह `customer_phone`। आगे के steps पढ़ना और संभालना बहुत आसान हो जाता है।

### Lists से items, और वापस

अगर कोई field list रखता है, जैसे order lines या attachments, तो उसे **split** करो ताकि हर element आगे के steps के लिए अपना अलग item बन जाए। तब हर line अपनी sheet row बन सकती है। वापस जाने के लिए items को एक list में **aggregate** करो।

```flow
1 item | lines [A, B] वाला एक order -[lines को split करो]-> Item 1 | order id, line A
1 item -[lines को split करो]-> Item 2 | order id, line B
Item 1 -> हर एक की एक sheet row
Item 2 -> हर एक की एक sheet row
```

जो fields आगे भी चाहिए, जैसे order id और city, उन्हें हर split item पर रखो।

### Types

Values अक्सर गलत type में आती हैं:

| मिली हुई value | समस्या | Fix |
| --- | --- | --- |
| `"1,250.00"` | Comma वाला text, number नहीं | Commas हटाओ, फिर number में convert करो |
| `"03/11/2026"` | ये 3 November है या 11 March? | Provider जो format बताए उसी से parse करो |
| `9845012345` number के रूप में | ठीक है, पर `0123` number बनने पर zero खो देता है | Phone numbers, PIN codes और ids को text रखो |
| `"true"` | Text है, true या false नहीं | Text की तरह compare करो, या convert करो |

### Missing values

कुछ records में fields गायब या `null` हो सकते हैं। पहले से तय करो: default use करो, कोई step छोड़ो, या record किसी इंसान को भेजो। "अगर `customer.email` null है, तो email step छोड़ो और SMS भेजो" एक rule है; जो workflow crash हो जाए वो rule नहीं है।

### APIs और AI steps के लिए JSON बनाना

जब आप किसी API या AI step को data भेजते हो, तो आपको वही shape बनाना होता है जो वो चाहता है। **JSON schema** उस shape का description है: कौन-से fields, उनके types और कौन-से ज़रूरी हैं। अपना output API के documentation से मिलाओ, और AI structured outputs के लिए उस schema से जो आप model को दो।

### Power tools

`jq` और JSONata JSON को query और reshape करने की छोटी languages हैं। कई automation tools मिलते-जुलते expressions support करते हैं। शुरू करने के लिए इनकी ज़रूरत नहीं, पर पेचीदा payloads में ये मदद करते हैं।

## एक example से समझो

बेंगलुरु का एक online tea store, order होने पर ये webhook (छोटा करके) पाता है:

```json
{
  "order": {
    "id": "ORD-88213",
    "created_at": "2026-11-03T10:42:00+05:30",
    "customer": { "name": "Nisha Rao", "phone": "9845012345", "email": null },
    "lines": [
      { "sku": "TEA-ASSAM-250", "qty": 2, "price": "349.00" },
      { "sku": "MUG-STEEL", "qty": 1, "price": "1,199.00" }
    ],
    "shipping": { "city": "Mysuru", "pin": "570001" }
  }
}
```

Goal: dispatch sheet में हर order line की एक row, और customer को एक SMS।

1. `order.lines` को items में **split** करो, और हर item पर `order.id`, `customer.name`, `shipping.city` और `shipping.pin` रखो।
2. `price` को commas हटाकर text से number में **convert** करो, फिर line total = qty × price निकालो।
3. `pin` को text ही **रखो**, ताकि "570001" जैसा है वैसा रहे।
4. **SMS:** `customer.phone` के आगे +91 जोड़कर use करो। `email` `null` है, इसलिए इस order के लिए email step छोड़ दो।

Dispatch sheet में दो rows बनती हैं:

| Order | Customer | SKU | Qty | Price | Line total | City | PIN |
| --- | --- | --- | --- | --- | --- | --- | --- |
| ORD-88213 | Nisha Rao | TEA-ASSAM-250 | 2 | 349 | 698 | Mysuru | 570001 |
| ORD-88213 | Nisha Rao | MUG-STEEL | 1 | 1,199 | 1,199 | Mysuru | 570001 |

Conversion step से पहले दूसरी line का total error दिखा रहा था, क्योंकि "1,199.00" text था। Null check से पहले, workflow हर उस customer के लिए fail होता था जिसका email नहीं था, यानी लगभग पाँच में से एक order।

## आम गलतियाँ

- **Path का अंदाज़ा लगाना।** असली samples देखो और सही path copy करो।
- **List होने पर भी एक item मान लेना।** Lists को items में split करो।
- **Numbers को text छोड़ देना।** "1,199.00" convert होने तक जुड़ेगा नहीं।
- **शुरू के zeros खो देना।** PIN codes, phone numbers और ids को text रखो।
- **Missing fields पर fail हो जाना।** Null और गायब fields के लिए rule पहले से बनाओ।
- **ये भूल जाना कि array 0 से शुरू होती है।** पहला item `[0]` है, `[1]` नहीं।

नीचे link किया MDN का JSON guide और n8n का data के साथ काम करने वाला page पढ़ो।

1. **Paths।** ऊपर के sample या किसी असली webhook sample से पाँच fields के path लिखो, जिनमें एक list के अंदर का भी हो।
