## ये क्या है

Programs लिखने से पहले आपको उन्हें लिखने की एक जगह और चलाने का एक तरीका चाहिए। First-year student से लेकर किसी बड़ी company के AI engineer तक, हर Python programmer इन्हीं तीन tools के साथ काम करता है:

| Tool | ये क्या है | उदाहरण |
| --- | --- | --- |
| **Python** | वो program जो आपका code पढ़ता और चलाता है (**interpreter**) | Python 3, python.org से |
| **एक code editor** | जहाँ आप code लिखते हो; ये आपके code को रंग देता है, छोटी गलतियाँ पकड़ता है और type करने में मदद करता है | Visual Studio Code (VS Code), free |
| **एक terminal** | एक text window जहाँ आप commands type करते हो, उनमें वो command भी जो आपकी file चलाता है | VS Code के अंदर वाला terminal |

Setup तब पूरा होता है जब तीनों **एक राय पर** हों: terminal Python को ढूँढ पाए, editor वही Python इस्तेमाल करे, और terminal उसी folder में खुला हो जिसमें आपकी file है। Beginners की लगभग हर problem इन्हीं में से किसी एक के मेल न खाने से होती है।

जब ये मेल खा जाएँ, तो आप वो loop शुरू करते हो जिसमें हर programmer रोज़ रहता है:

```flow
dir: LR
File लिखो -> Save करो
Save करो -> Terminal में चलाओ
Terminal में चलाओ -> Output या error पढ़ो
Output या error पढ़ो -> ठीक करो
ठीक करो -[फिर से]-> File लिखो
```

ये lesson Madurai के commerce graduate Karthik के साथ चलता है, जो अपने Windows laptop पर Python set up करता है और उन problems से टकराता है जो beginners को सबसे ज़्यादा आती हैं। इसका check एक छोटा project है: आपकी अपनी पहली file, terminal से चलाई गई और online share की गई।

## ये काम कैसे करता है

### Version चुनो

सबसे नया Python 3 install करो। Python 3.15.0, 9 October 2026 को आया, bugfix releases 3.15.1 और 3.15.2 October में ही आ गए, और लगभग हर दो महीने में और आते हैं, तो आपको जो आख़िरी number दिखे वो इससे ज़्यादा हो सकता है। Python 3.14 भी ठीक है। तीन नियम:

- **Python 3, Python 2 कभी नहीं।** अगर कोई tutorial bracket के बिना `print "hello"` लिखता है, तो वो Python 2 के लिए है; कोई नया tutorial ढूँढो।
- **एक Python काफ़ी है।** "Safe रहने के लिए" कई Python install करना, editor और terminal में मतभेद पैदा करने का सबसे तेज़ तरीका है।
- **भारी libraries पीछे रह सकती हैं।** कुछ बड़ी data और AI libraries को नया version support करने में हफ़्ते लग जाते हैं। अगर कोई install होने से मना करे, तो उस project के लिए 3.14 इस्तेमाल करो।

### Python install करो

| Computer | कैसे |
| --- | --- |
| Windows 10 या 11 | python.org/downloads से या Microsoft Store से **Python install manager** install करो। इससे आपको `python` और `py` commands मिलते हैं। जब कुछ भी install न हो और आप पहली बार Python चलाओ, तो ये latest release download कर लेता है; आप `py install 3.15` भी type कर सकते हो। |
| Mac | python.org से macOS installer download करो और उसे चलाओ। `python3` command इस्तेमाल करो। |
| Linux | Python 3 आम तौर पर पहले से होता है। `python3` इस्तेमाल करो; कई systems पर सिर्फ़ `python` command होता ही नहीं। |

Install manager अब Windows पर Python install करने का official तरीका है। पुराना full installer (एक अकेली `.exe`) Python 3.15 के लिए अभी भी है, पर Python 3.16 से python.org इसे देना बंद कर देगा। अगर आप इसे इस्तेमाल करो, तो इसकी पहली screen पर **"Add python.exe to PATH"** पर tick करो। **PATH** उन folders की list है जिनमें Windows तब ढूँढता है जब आप कोई command type करते हो। अगर Python का folder उस list में नहीं है, तो Python install होने के बावजूद `python` type करना fail हो जाता है।

### Install check करो

एक **नया** terminal खोलो और type करो:

```text
python --version
```

Mac और Linux पर `python3 --version` type करो। आपको 3 से शुरू होने वाला version दिखना चाहिए, जैसे `Python 3.15.0`। Windows पर `py list` हर वो Python दिखाता है जिसके बारे में install manager जानता है।

नया terminal क्यों? Terminal PATH को एक ही बार पढ़ता है, जब वो खुलता है। जो terminal install के दौरान खुला था, उसके पास अभी भी पुरानी list है और वो Python को नहीं ढूँढ पाता। VS Code का terminal PATH को ख़ुद VS Code से copy करता है, इसलिए सिर्फ़ terminal tab नहीं, VS Code को पूरी तरह बंद करके फिर से खोलो।

### जब Windows को Python नहीं मिलता

Windows learners को सबसे ज़्यादा ये तीन messages मिलते हैं:

| आपको दिखता है | इसका मतलब | Fix |
| --- | --- | --- |
| `The term 'python' is not recognized...` (PowerShell) या `'python' is not recognized as an internal or external command` (Command Prompt) | Python install नहीं है, या उसका folder PATH पर नहीं है | Install manager install करो, या पुराना installer PATH box पर tick लगाकर फिर से चलाओ। फिर नया terminal खोलो। |
| `Python was not found; run without arguments to install from the Microsoft Store...`, या Store app खुल जाता है | Python install नहीं है। Windows में **app execution alias** नाम का एक shortcut आता है जो `python` को Store पर भेज देता है। | Python ठीक से install करो। अगर पुराना installer इस्तेमाल किया था, तो Start menu में "Manage app execution aliases" ढूँढो और python.exe और python3.exe वाली दोनों App Installer entries बंद करो। |
| ऐसा version जिसकी आपको उम्मीद नहीं थी | एक से ज़्यादा Python install हैं, और PATH पर जो पहले आता है वही जीतता है | `py list` और `where.exe python` सब दिखा देते हैं। फ़ालतू वाले uninstall करो। |

```flow
title: Terminal को Python नहीं मिल रहा
python --version type करो -[Python 3 दिखाता है]-> Code लिखने के लिए तैयार
python --version type करो -[not recognized]-> Install करो या PATH ठीक करो
python --version type करो -[Microsoft Store खुलता है]-> Install करो या alias बंद करो
Install करो या PATH ठीक करो -> VS Code बंद करके फिर खोलो
Install करो या alias बंद करो -> VS Code बंद करके फिर खोलो
VS Code बंद करके फिर खोलो -> python --version type करो
```

### Mac पर: पक्का करो कि सही python3 चल रहा है

macOS का अपना `python3` होता है, `/usr/bin/python3` पर। ये Apple के developer tools का हिस्सा है और आम तौर पर पुराना होता है; इसे चलाने पर ये Command Line Tools install करने को कह सकता है। python.org का installer अपने `python3` को सबसे पहले रखता है। Check करने के लिए नया terminal खोलो और `which python3` type करो। `/Library/Frameworks/Python.framework` या `/usr/local/bin` के अंदर का path python.org वाला है; `/usr/bin/python3` Apple वाला है।

### Editor install करो और उसे Python पर point करो

VS Code और उसका **Python extension** (Microsoft वाला) install करो। अपने काम के लिए `python-practice` जैसा एक folder बनाओ और उसे File, Open Folder से खोलो। हर project को उसके अपने folder में रखने से बाद में बहुत सारी उलझन बचती है।

फिर VS Code को बताओ कि कौन-सा Python इस्तेमाल करना है। Ctrl+Shift+P (Mac पर Cmd+Shift+P) दबाओ, **Python: Select Interpreter** type करो और वो Python चुनो जो आपने अभी install किया। चुना हुआ version नीचे status bar में दिखता है। अगर VS Code ने कोई दूसरा Python चुन लिया, तो अजीब नतीजे आते हैं: file terminal में चल जाती है, पर editor आपके imports के नीचे लाल लाइन लगा देता है, या Run button ऐसा version इस्तेमाल करता है जो आपने जान-बूझकर install नहीं किया। Interpreter बदलने से पहले से खुले terminals नहीं बदलते, इसलिए उसके बाद नया terminal खोलो।

आख़िर में, **File, Auto Save** चालू करो। File के tab पर dot का मतलब है कि उसमें changes save नहीं हुए। Python disk पर पड़ी file चलाता है, आपकी screen पर जो है वो नहीं, इसलिए बिना save किया fix कुछ नहीं करता।

### अपनी पहली file लिखो

उस folder में `hello.py` नाम की एक file बनाओ:

```python
from datetime import date

name = "Priya"
print("Hello, my name is", name)
print("Today is", date.today())
```

Line 1 Python के built-in `datetime` module से `date` लाती है। Line 3 `name` नाम के variable में text रखती है। Lines 4 और 5 print करती हैं, और `date.today()` आपके computer से आज की date पूछता है।

`.py` ending Python और आपके editor को बताती है कि ये Python code है। Windows default रूप से file endings छुपा देता है, तो जिस file को आप `hello.py` समझ रहे हो वो असल में `hello.py.txt` हो सकती है। File Explorer में View menu खोलो और file name extensions चालू करो, ताकि सच दिख सके।

### इसे terminal से चलाओ

VS Code के अंदर View, Terminal से terminal खोलो। Terminal हमेशा किसी एक folder "में" काम करता है, और prompt आम तौर पर दिखाता है कि कौन-से, जैसे `PS C:\Users\karthik\python-practice>`। पक्का करो कि ये वही folder है जिसमें आपकी file है:

| Command | Windows | Mac और Linux |
| --- | --- | --- |
| मैं कहाँ हूँ? | PowerShell में `pwd` (VS Code का default), Command Prompt में `cd` | `pwd` |
| यहाँ की files की list | `dir` | `ls` |
| किसी folder में जाओ | `cd python-practice` | `cd python-practice` |
| एक folder ऊपर जाओ | `cd ..` | `cd ..` |
| File चलाओ | `python hello.py` | `python3 hello.py` |

`python hello.py` type करो और Enter दबाओ। Output नीचे दिखता है। Tip: Tab file names पूरे कर देता है, और Up arrow पिछला command दोहरा देता है।

VS Code का Run button (ऊपर दाईं तरफ़ वाला triangle) आपके लिए यही command type कर देता है। फिर भी typed command सीखो: servers, options और remote machines, सबमें इसकी ज़रूरत पड़ती है।

### `>>>` prompt एक अलग जगह है

अगर आप बिना file name के सिर्फ़ `python` (या `python3`) type करो, तो आप **interactive shell** में पहुँच जाते हो, जो `>>>` prompt दिखाता है। ये एक बार में Python की एक line चलाता है, जो `2 + 3` या `len("Madurai")` जैसे छोटे experiments के लिए काम का है। पर ये सिर्फ़ Python समझता है, terminal commands नहीं। वहाँ `python hello.py` type करने पर ये आता है:

```text
>>> python hello.py
  File "<python-input-0>", line 1
    python hello.py
           ^^^^^
SyntaxError: invalid syntax
```

`exit()` type करो और Enter दबाकर terminal पर वापस जाओ, फिर वहाँ से अपनी file चलाओ।

### Error messages पढ़ो

जब कुछ गड़बड़ होती है, Python एक error message print करता है, अक्सर लाल रंग में। **आख़िरी line पहले** पढ़ो: वो error का नाम बताती है। फिर उसके ऊपर file name और line number देखो, और आपके code की वो copy जिसमें Python जिस हिस्से की तरफ़ इशारा कर रहा है उसके नीचे `^` के निशान हैं।

मान लो आप line 5 का आख़िरी bracket मिटा देते हो। Python कुछ भी चलाने से पहले पूरी file check करता है, तो कोई output नहीं आता, line 4 का भी नहीं:

```text
  File "C:\Users\priya\python-practice\hello.py", line 5
    print("Today is", date.today()
         ^
SyntaxError: '(' was never closed
```

`^` उस bracket के नीचे है जो खोला गया और कभी बंद नहीं हुआ। बाकी गलतियाँ program चलते वक़्त ही सामने आती हैं। अगर आप line 5 पर `date.todya()` type करो, तो Python के रुकने तक line 4 print हो चुकी होती है। पूरी report को **traceback** कहते हैं:

```text
Hello, my name is Priya
Traceback (most recent call last):
  File "C:\Users\priya\python-practice\hello.py", line 5, in <module>
    print("Today is", date.todya())
                      ^^^^^^^^^^
AttributeError: type object 'datetime.date' has no attribute 'todya'. Did you mean '.today' instead of '.todya'?
```

ये Python 3.15 के शब्द हैं; पुराने versions hint को थोड़ा अलग ढंग से लिखते हैं। Python अक्सर fix ख़ुद सुझा देता है, इसलिए line के आख़िर तक पढ़ो। एक gotcha: line number वो जगह है जहाँ Python ने problem को **नोटिस** किया, जो हमेशा गलती वाली जगह नहीं होती। मसलन, किसी `if` line के बाद indent छूट जाए, तो वो उसके नीचे वाली line पर report होता है, इसलिए एक line ऊपर भी देखो।

| Error | आम वजह |
| --- | --- |
| `SyntaxError` | कोई bracket, quote या colon छूट गया, या `>>>` पर terminal command type कर दिया |
| `IndentationError` | कोई line indent हो गई जबकि नहीं होनी चाहिए थी, या tabs और spaces मिला दिए |
| `NameError` | किसी variable की spelling गलत, या variable बनाने से पहले ही इस्तेमाल कर लिया |
| `AttributeError` | Dot के बाद किसी function या method के नाम की spelling गलत |
| `ModuleNotFoundError` | ऐसा package जो उस Python में install नहीं है जिसे आप चला रहे हो |
| `can't open file` | Terminal गलत folder में है, या file का नाम गलत है |

### Packages install करना: अभी से एक आदत

जल्द ही आप `requests` या `pandas` जैसे packages install करोगे। उन्हें उसी Python से install करो जो आपकी files चलाता है:

```text
python -m pip install requests
```

Mac पर `python3 -m pip` इस्तेमाल करो। सिर्फ़ `pip install` किसी दूसरे Python का हो सकता है, यही वजह है कि learners को उस package के लिए `ModuleNotFoundError` दिखता है जो उन्होंने "अभी तो install किया था"। Ubuntu और Debian के हाल के versions पर system Python में install करने पर `error: externally-managed-environment` आकर रुक जाता है। इसे ज़बरदस्ती पार मत करो; इसका fix virtual environment है, जो "Packages and virtual environments" lesson (B3) में है। बाद में "Project tooling" lesson (B3) uv दिखाता है, जो environments बनाता है और आपके लिए Python भी install कर सकता है। आपकी `hello.py` को किसी package की ज़रूरत नहीं है।

### Python चलाने के दूसरे तरीके

**Google Colab** और **Kaggle** जैसे online notebooks बिना कुछ install किए browser में Python चलाते हैं। ये तब काम आते हैं जब आपका computer locked हो, पुराना हो या कई लोगों में shared हो। दो सावधानियाँ: वहाँ बनाई files session खत्म होने पर गायब हो सकती हैं, इसलिए अपना काम download कर लो; और notebook वो terminal और folder skills छुपा देता है जिनकी हर असली project को ज़रूरत होती है। शुरुआत के लिए इन्हें इस्तेमाल करो, local setup की जगह नहीं।

## एक worked example

Madurai के commerce graduate Karthik एक शाम अपने Windows 11 laptop पर Python set up करते हैं।

**Step 1: Store वाला surprise.** कुछ भी install करने से पहले वो PowerShell खोलते हैं और `python` type करते हैं। Microsoft Store खुल जाता है। वो इस lesson वाला Windows shortcut पहचान लेते हैं, Store बंद करते हैं और उसकी जगह Python ठीक से install करते हैं।

**Step 2: install.** python.org/downloads से वो Python install manager install करते हैं, नई PowerShell window खोलते हैं और `py install 3.15` type करते हैं। ये latest Python 3.15 download करके install कर देता है।

**Step 3: नए terminal में check.** वो VS Code और उसका Python extension install करते हैं। VS Code के terminal में `python --version` से `Python 3.15.2` print होता है। वो एक `python-practice` folder बनाते हैं, उसे File, Open Folder से खोलते हैं, और Python: Select Interpreter से 3.15 चुनते हैं।

**Step 4: पहली error.** वो `C:\Users\karthik\python-practice` में अपने नाम के साथ `hello.py` लिखते हैं। उसे चलाने के लिए वो Step 2 वाली अलग PowerShell window में `python hello.py` type करते हैं, जो उनके home folder में खुली थी, और ये fail हो जाता है। Message का आख़िरी हिस्सा ये है:

```text
can't open file 'C:\\Users\\karthik\\hello.py': [Errno 2] No such file or directory
```

दोहरे backslashes बस Python का Windows path print करने का तरीका है। Path बताता है कि Python ने कहाँ ढूँढा: उनके home folder में, `python-practice` में नहीं। वो `cd python-practice` type करते हैं, फिर `dir` से पक्का करते हैं कि `hello.py` वहाँ है, और command फिर से चलाते हैं:

```text
Hello, my name is Karthik
Today is 2026-11-03
```

**Step 5: बिना save का change.** वो एक line जोड़ते हैं जो उनका नाम Tamil script में print करती है, और file चलाते हैं। Output वैसा ही रहता है। फिर उनकी नज़र `hello.py` के tab पर dot पर पड़ती है: उन्होंने save ही नहीं किया था। वो Ctrl+S दबाते हैं, फिर से चलाते हैं, और Tamil वाली line आ जाती है, क्योंकि VS Code files को UTF-8 में save करता है, जिसमें कोई भी script आ सकती है। वो Auto Save चालू कर देते हैं।

**Step 6: तोड़ो और ठीक करो.** जान-बूझकर वो line 5 का आख़िरी bracket मिटाते हैं और file चलाते हैं। कोई output नहीं आता; आख़िरी line कहती है `SyntaxError: '(' was never closed` और `^` `print` के बाद वाले bracket की तरफ़ इशारा करता है। वो bracket वापस लगाते हैं और ये चल जाती है।

**Step 7: share.** वो एक GitHub account बनाते हैं और `hello.py` को एक नए gist में paste करते हैं, जिससे उन्हें share करने के लिए एक link मिलता है। वही link इस lesson का check है।

एक ही शाम में उनका सामना Store shortcut, गलत folder और बिना save की file से हुआ, और उन्होंने हर एक को reinstall करने की जगह message पढ़कर ठीक किया।

## आम गलतियाँ

- **पहली error पर ही reinstall करना।** ज़्यादातर errors folder, PATH या बिना save की file की होती हैं, टूटे हुए install की नहीं। आख़िरी line पहले पढ़ो।
- **पुराने terminal में test करना।** Python install करने या PATH बदलने के बाद, VS Code पूरी तरह बंद करो और नया terminal खोलो।
- **Store shortcut को Python समझ लेना, या पुराने installer में PATH वाला tick छोड़ देना।** Install manager इस्तेमाल करो।
- **गलत folder से चलाना।** चलाने से पहले `pwd` और `dir` या `ls` से check करो।
- **बिना save की file चलाना।** Tab पर dot का ध्यान रखो, या Auto Save चालू करो।
- **`>>>` prompt पर terminal commands type करना।** पहले `exit()` type करो।
- **File को `hello.py.txt` के रूप में save करना।** File Explorer में file name extensions चालू करो।
- **कई Python, और VS Code किसी दूसरे को इस्तेमाल कर रहा है।** एक ही Python रखो और उसे Python: Select Interpreter से चुनो।
- **सिर्फ़ `pip install` इस्तेमाल करना।** `python -m pip install` इस्तेमाल करो, ताकि package उसी Python में जाए जो आपका code चलाता है।
