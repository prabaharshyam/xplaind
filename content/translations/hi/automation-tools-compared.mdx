## ये क्या है

जब आप अपने लिए या किसी client के लिए workflow automate करते हो, तो पहला असली फ़ैसला होता है **कौन-सा tool**। Indian businesses में आपको मिलने वाला ज़्यादातर automation का काम चार tools cover करते हैं:

| Tool | एक line में | Usage किसमें गिनता है | आम user |
| --- | --- | --- | --- |
| **Zapier** | सबसे जाना-माना no-code tool: बहुत आसान, app connectors का बहुत बड़ा catalogue, workflows ("Zaps") ज़्यादातर सीधी line में, थोड़ी branching के साथ | Tasks (हर action step) | छोटे businesses और non-technical teams |
| **Make** (पहले Integromat) | Data, routers, loops और error handling पर ज़्यादा control वाला visual canvas, फिर भी no-code | Credits (हर module, हर item पर) | Operations teams जो Zapier से आगे निकल जाती हैं |
| **n8n** | ज़्यादा technical users के लिए visual tool, जिसमें code nodes, किसी भी API के लिए HTTP node और मज़बूत AI agent features हैं। Source-available और self-host हो सकता है | Executions (हर पूरा run) | Developers, startups, सख़्त data rules वाली companies |
| **Microsoft Power Automate** | Microsoft के Power Platform का हिस्सा, Microsoft 365, Teams और SharePoint से गहराई से जुड़ा, पुराने Windows apps के लिए desktop RPA के साथ | User और bot licences | पहले से Microsoft पर चलने वाली, IT team वाली companies |

**Consultants के लिए एक ज़रूरी licence fact।** n8n को अक्सर open source कहा जाता है। ये है नहीं। ये n8n का अपना **Sustainable Use License** use करता है (n8n इसे "fair-code" कहता है): आप code देख और बदल सकते हो और अपने business के लिए use कर सकते हो। पैसे देने वाले client के लिए workflows बनाना allowed है। n8n को इस तरह host करना कि clients log in करके उस पर build करें, या उसे अपने brand के नाम से बेचना, इसके लिए n8n के साथ commercial agreement चाहिए। इसके आसपास कोई service design करने से पहले मौजूदा licence पढ़ लो।

और भी tools हैं, जैसे Workspace के लिए Google के tools और enterprise integration platforms, लेकिन सबसे ज़्यादा यही चार सामने आते हैं।

आम तौर पर कोई एक best tool नहीं होता। **किसी ख़ास client के लिए** एक best tool होता है, और ये lesson जो skill सिखाता है वो है उसे आदत से नहीं, evidence से चुनना।

```flow
title: Client से पूछने वाले पहले सवाल
Start -> पहले से Microsoft 365 पर IT team के साथ?
पहले से Microsoft 365 पर IT team के साथ? -[हाँ]-> Power Automate
पहले से Microsoft 365 पर IT team के साथ? -[नहीं]-> क्या data आपके अपने servers में ही रहना चाहिए?
क्या data आपके अपने servers में ही रहना चाहिए? -[हाँ, और developers हैं]-> Self-hosted n8n
क्या data आपके अपने servers में ही रहना चाहिए? -[नहीं]-> इसे कौन maintain करेगा?
इसे कौन maintain करेगा? -[non-technical staff]-> Zapier
इसे कौन maintain करेगा? -[no-code operations वाला बंदा]-> Make
इसे कौन maintain करेगा? -[developers]-> n8n Cloud
```

इसे rule नहीं, पहला sketch मानो। आगे आने वाले volume और cost इसे पलट सकते हैं।

## ये काम कैसे करता है

Tools को सात factors पर compare करो। पहले तीन तय करते हैं कि build करना कितना आरामदायक है। आख़िरी चार तय करते हैं कि client एक साल बाद भी ख़ुश है या नहीं।

### 1. Ease of use

शुरू करने के लिए Zapier सबसे आसान है। Make flexibility में एक कदम आगे है, और इसका learning curve मध्यम है। n8n उन लोगों के लिए है जो JSON (वो text format जिससे apps data आगे भेजते हैं) और थोड़े code में comfortable हैं। Power Automate सीधे-सादे Microsoft 365 flows के लिए आसान है और advanced flows में complex हो जाता है।

### 2. Connectors

**Connector** किसी app के साथ पहले से बना integration है। Popular SaaS apps के लिए Zapier और Make के catalogues सबसे बड़े हैं। n8n में भी बहुत हैं, साथ में एक HTTP Request node जो API वाली किसी भी चीज़ से बात कर सकता है। Power Automate Microsoft products के साथ सबसे मज़बूत है; इसमें कई दूसरे apps के connectors भी हैं, लेकिन कुछ **premium** connectors हैं जिनके लिए paid Power Automate licence चाहिए।

**Gotcha।** सिर्फ़ app का logo नहीं, वो exact action check करो जो आपको चाहिए। Connector मौजूद हो सकता है, लेकिन उसमें वो एक action न हो जो client को चाहिए, जैसे "update a row" या "attach a file"।

### 3. AI features

चारों अब AI steps देते हैं: models को call करना, data निकालना, classify करना और agent जैसे features। Custom AI agents बनाने के लिए n8n ख़ास तौर पर मज़बूत है। Power Automate Microsoft की AI services और Copilot से जुड़ता है।

**Gotcha।** AI step data को model provider के पास भेजता है। जो client कहता है "data हमारे पास ही रहना चाहिए", उसका मतलब आमतौर पर model call से भी होता है, सिर्फ़ workflow tool से नहीं।

### 4. Pricing model: हर tool की unit में गिनो

हर tool usage अलग unit में गिनता है, इसलिए पहले workflow के एक run को उस unit में बदलो:

| Tool | Unit | एक trigger और चार actions का एक run | किस बात का ध्यान रखें |
| --- | --- | --- | --- |
| Zapier | Task: हर successful action step | 4 tasks (trigger, Filter और Formatter steps free हैं) | लंबे Zaps गिनती कई गुना कर देते हैं |
| Make | Credit: हर module, हर उस item के लिए जिसे वो handle करता है | 5 credits (trigger भी एक लेता है) | Items पर loops, AI modules, और polling triggers |
| n8n | Execution: एक पूरा run, चाहे कितने भी steps हों | 1 execution | बहुत सारे छोटे workflows जुड़कर बढ़ जाते हैं |
| Power Automate | हर user या हर bot के लिए licence | User के licence में cover, daily action limits के अंदर | Premium connectors और desktop RPA के लिए paid licences चाहिए |

**Make में polling trap।** **Polling** trigger एक timer पर किसी app में नए items check करता है। Make हर check पर एक credit लेता है, चाहे कुछ नया न हो। हर 15 मिनट पर check करने वाला trigger 30 दिन के महीने में 4 × 24 × 30 = 2,880 बार चलता है, यानी कोई काम होने से पहले ही 2,880 credits ख़र्च हो जाते हैं। **Instant** trigger (एक webhook, जिसमें app data आते ही भेज देता है) इससे बचाता है।

**Prices बदलते हैं।** Prices हमेशा live price pages से लो, उसी currency में जो दिखाई गई है, और check करने की तारीख लिख लो। Zapier prices US dollars में दिखाता है, n8n euros में, और Microsoft India rupees में, GST अलग। Compare करने से पहले एक बताए गए exchange rate पर convert करो।

### 5. Data control

जानो कि हर tool अपने से गुज़रने वाला data कहाँ रखता है:

| Tool | Vendor के मुताबिक data कहाँ process होता है |
| --- | --- |
| Zapier | United States में Amazon servers पर; आप कोई दूसरा region नहीं चुन सकते |
| Make | US या EU data centre में, जिसे आप हर organisation के लिए चुनते हो और बाद में बदल नहीं सकते; कुछ AI features कहीं और route होते हैं |
| n8n Cloud | n8n की site कहती है कि hosted plans data Frankfurt, Germany में store करते हैं |
| Self-hosted n8n | जहाँ भी आप इसे चलाओ, India के किसी cloud region समेत |
| Power Automate | Client के Power Platform environment वाले region में; India भी एक region है |

**India में।** Digital Personal Data Protection Act, 2023 (DPDP Act) client को उसके customers के personal data का **Data Fiduciary** बनाता है। जो भी tool client के लिए वो data process करता है, वो **Data Processor** है, और Act fiduciary को processor use करने की इजाज़त सिर्फ़ valid contract के तहत देता है। इसलिए Zapier, Make या n8n Cloud के लिए client को vendor का data processing agreement accept करना चाहिए और उसकी copy रखनी चाहिए। DPDP Rules November 2025 में notify हुए, और ज़्यादातर duties May 2027 से लागू होंगी। Act आम तौर पर ये नहीं माँगता कि data India में ही रहे, लेकिन कोई sector regulator, जैसे payment data के लिए Reserve Bank of India, या client के अपने contracts ये माँग सकते हैं। कौन-सा लागू होता है, ये client की compliance team से पूछो; ख़ुद तय मत करो।

### 6. Lock-in और debugging

**Lock-in।** एक tool में बना workflow दूसरे tool में नहीं ले जाया जा सकता। n8n और Make workflow को JSON file के रूप में save कर सकते हैं, और Power Automate .zip package के रूप में, लेकिन हर file सिर्फ़ उसी tool में वापस import होती है। बाद में switch करने का मतलब है दोबारा build करना, इसलिए ऐसे चुनो जैसे ये चुनाव लंबा चलेगा।

**Debugging।** Workflows fail होते हैं: कोई API down है, कोई field खाली है, कोई password expire हो गया। चारों एक run history रखते हैं जिसमें हर step का input और output दिखता है, और हर एक किसी न किसी तरह fail हुए runs को retry कर सकता है। Zapier fail हुए steps replay कर सकता है। Make एक **incomplete execution** store कर सकता है ताकि आप data ठीक करके उसे resume कर सको। n8n में आप एक **error workflow** जोड़ सकते हो जो run fail होने पर किसी को alert करता है। Power Automate run history दिखाता है और run को resubmit करने देता है। Hand over करने से पहले एक alert set up करो जो किसी तय इंसान तक पहुँचे; ऐसी failure जिसे कोई नहीं देखता, automations के चुपचाप ख़त्म होने का सबसे आम तरीका है।

### 7. Fit और maintenance

अक्सर सबसे मज़बूत factor ये होता है कि client के पास पहले से क्या है। IT governance वाली, Microsoft 365 पर चलने वाली company आमतौर पर Power Automate पसंद करेगी और हो सकता है उसके पैसे पहले से दे रही हो। SaaS apps पर चलने वाला startup Zapier या Make पसंद कर सकता है। सख़्त data rules या ज़्यादा AI ज़रूरतों वाली company self-hosted n8n पसंद कर सकती है।

और हमेशा पूछो: **आपके जाने के बाद इसे कौन maintain करेगा?** सबसे अच्छा tool वो है जिसे client के अपने लोग चलाते रह सकें।

### Total cost of ownership

सब कुछ जोड़कर **TCO**, यानी total cost of ownership निकालो:

```text
  TCO per month = licence or usage fees
                + servers (if self-hosted)
                + setup time, spread over the first year
                + maintenance hours each month x hourly cost
                + training for the people who will run it
```

जिस tool की कोई licence fee नहीं है, उसका भी TCO सबसे ज़्यादा हो सकता है, अगर client की तरफ़ से कोई उसे maintain न कर सके।

## एक example से समझो

तीन clients, तीन अलग चुनाव, और एक पूरा cost check।

**Chennai की एक chartered accountancy firm।** 25 staff, Gmail, Google Sheets और कुछ SaaS tools। जब कोई नया client intake form भरता है, तो workflow एक Drive folder बनाता है, एक task बनाता है, client sheet में एक row जोड़ता है और welcome email भेजता है: एक trigger और चार actions। महीने में लगभग 150 runs। कोई technical staff नहीं। **चुनाव: Zapier।** इसे build करना सबसे तेज़ है और उनके office manager के लिए इसे maintain करना सबसे आसान।

**Pune का एक manufacturer।** Microsoft 365 पर, पाँच लोगों की IT team के साथ। उन्हें Teams में purchase approvals चाहिए, और data एक पुरानी Windows inventory application में copy होना चाहिए जिसका कोई API नहीं है। **चुनाव: Power Automate।** Cloud flows Teams में approvals संभालते हैं, और desktop RPA inventory app संभालता है। सब कुछ मौजूदा Microsoft governance के अंदर रहता है।

**Bengaluru का एक health-tech startup।** ये AI extraction के साथ महीने में 20,000 patient intake forms process करता है, और इसके data rules कहते हैं कि patient data इसके अपने cloud account में ही रहना चाहिए। इसके developers tools को code से extend करना पसंद करते हैं। **चुनाव: self-hosted n8n**, उनके अपने cloud account में, और AI model भी उसी account के अंदर चलता है। कोई per-run fees नहीं, data उनके environment में रहता है, और developers custom nodes जोड़ सकते हैं।

| Factor | Chennai CA firm | Pune manufacturer | Bengaluru health-tech |
| --- | --- | --- | --- |
| Volume | महीने में लगभग 150 runs | महीने में लगभग 2,000 runs | महीने में लगभग 20,000 runs |
| Apps | Google Workspace, SaaS | Microsoft 365, पुराना Windows app | अपना cloud, custom apps |
| Data rules | सामान्य | Company की IT policy | Patient data in-house ही रहना चाहिए |
| Maintainer | Office manager | IT team | Developers |
| Tool | Zapier | Power Automate | Self-hosted n8n |

### Step 1: Chennai workflow के units गिनो

ऊपर की unit table से, एक run 4 Zapier tasks, 5 Make credits (instant trigger के साथ) या 1 n8n execution है। अब volume से multiply करो:

| महीने में runs | Zapier tasks | Make credits | n8n executions |
| --- | --- | --- | --- |
| 150 (आज) | 600 | 750 | 150 |
| 2,000 | 8,000 | 10,000 | 2,000 |
| 20,000 | 80,000 | 100,000 | 20,000 |

### Step 2: fit होने वाला plan ढूँढो (28 November 2026 के prices)

- **Zapier।** Professional plan $19.99 महीने से शुरू होता है, yearly billing पर, 750 tasks के लिए। आज के 600 tasks fit हो जाते हैं।
- **n8n Cloud।** Starter plan €20 महीना है, yearly billing पर, 2,500 executions के लिए। आज के 150 executions fit हो जाते हैं, और 2,000 भी हो जाते।
- **Make।** जब हमने check किया तब Make के plans और credit tiers बदल रहे थे, और छपे हुए figures आपस में मेल नहीं खाते थे, इसलिए हम यहाँ Make का कोई price नहीं दे रहे। जिस दिन quote करो, उसी दिन make.com का price page पढ़ो।

150 runs पर दोनों entry plans की cost लगभग बराबर है, इसलिए फ़ैसला इस पर टिकता है कि maintain कौन करेगा, और Zapier जीतता है। 2,000 runs पर तस्वीर बदल जाती है: Zapier को अपने entry task allowance से दस गुना से ज़्यादा चाहिए, जबकि n8n का Starter plan अब भी fit होता है। 20,000 runs पर, n8n के बड़े cloud plans को self-hosting से compare करो। इसीलिए prices compare करने से पहले units गिनते हैं।

### Step 3: Pune का licence चुनाव

Teams approvals standard connectors (Teams, Approvals, SharePoint, Outlook) use करते हैं, जिन्हें staff के Microsoft 365 licences पहले से cover करते हैं। पैसा RPA वाले हिस्से में है, और वो एक फ़र्क पर टिका है:

- **Attended RPA** ऐसे computer पर चलता है जिस पर कोई इंसान signed in हो, आमतौर पर वही काम करते हुए इसे शुरू करता है।
- **Unattended RPA** ऐसी machine पर अपने आप चलता है जिस पर कोई signed in न हो, जैसे हर रात 11 p.m. पर।

Microsoft India के list prices, yearly billing, GST अलग, 28 November 2026 को check किए:

| Option | Licence | Cost |
| --- | --- | --- |
| तीन storekeepers हर purchase enter करने के बाद "run" click करते हैं | Power Automate Premium (attended RPA शामिल), ₹1,250 प्रति user महीना | 3 × ₹1,250 = ₹3,750 महीने का, ₹45,000 साल का |
| एक bot हर रात client के अपने PC पर दिन की entries copy करता है | Power Automate Process (unattended), ₹12,480 प्रति bot महीना | ₹1,49,760 साल का |
| वही bot, Microsoft के चलाए virtual machine पर | Power Automate Hosted Process, ₹17,885 प्रति bot महीना | ₹2,14,620 साल का |

अगर storekeepers को "run" click करने में दिक्कत नहीं है, तो attended RPA कहीं ज़्यादा सस्ता है। अगर copy बिना किसी के मौजूद हुए होनी है, तो Process licence का budget रखो। Microsoft कहता है कि दिखाए गए prices marketing के लिए हैं और असली price checkout पर दिखता है, इसलिए client के Microsoft partner से confirm करो।

### Step 4: Bengaluru का TCO

Self-hosted n8n में हर run की कोई fee नहीं है, लेकिन ये free नहीं है। सिर्फ़ उदाहरण के लिए मान लो, एक cloud server ₹3,000 महीने का है और एक developer updates, backups और fail हुए runs पर महीने में 4 घंटे लगाता है, ₹1,000 प्रति घंटे पर। TCO लगभग ₹3,000 + ₹4,000 = ₹7,000 महीना है, setup और AI model की अपनी cost जोड़ने से पहले। लोगों का समय पहले से बड़ा हिस्सा है, और यही वो हिस्सा है जिसे clients भूल जाते हैं।

फिर हर client के लिए आप एक पेज की recommendation लिखते हो: tool, expected volume पर cost और हर price check करने की तारीख, data कहाँ process होता है, और उसे कौन maintain करता है।

## आम गलतियाँ

- **अपनी पसंद से चुनना।** Client के apps, skills, volume और data rules से चुनो।
- **Units की जगह headline prices compare करना।** पहले एक run को tasks, credits या executions में बदलो, फिर plan ढूँढो।
- **भूल जाना कि Make के polling triggers credits खाते हैं।** 15 मिनट का check, एक भी नया item न होने पर भी, महीने में लगभग 2,880 credits लेता है। जहाँ हो सके instant trigger use करो।
- **n8n को open source कहना।** ये source-available है। Clients के use के लिए इसे host करने के लिए n8n से deal चाहिए।
- **AI step का data path भूल जाना।** अगर model call data बाहर भेजता है, तो workflow को self-host करने से कोई फ़ायदा नहीं।
- **जब attended से काम चल जाए तब unattended RPA ख़रीदना।** Per-bot licence की cost per-user licence से लगभग दस गुना है।
- **मौजूदा licences को नज़रअंदाज़ करना।** कई business Microsoft 365 plans में standard connectors वाले cloud flows पहले से शामिल हैं।
- **बिना owner के self-host करना।** Servers को security updates, backups और monitoring चाहिए।
- **कोई failure alert नहीं।** अगर fail हुआ run किसी तय इंसान तक नहीं पहुँचता, तो automation चुपचाप काम करना बंद कर देगा।
- **पुराने prices quote करना।** मौजूदा price pages check करो और तारीख record करो।

## Practice करो

नीचे link किया Power Automate पर एक Microsoft Learn module करो, और Zapier के guides देखो; n8n के बारे में जो जानते हो उससे compare करो।

1. **दो बार build करो।** एक ही simple workflow, जैसे form से sheet से email, दो tools में बनाओ। लगा समय, कोई भी दिक्कत, और fail हुआ run आपको कैसे दिखाया जाता है, ये note करो।
2. **गिनो, फिर cost निकालो।** एक trigger और पाँच actions वाला workflow लो। एक run को Zapier tasks, Make credits और n8n executions में बदलो। फिर आज के price pages से, दो tools पर महीने में 200, 2,000 और 20,000 runs पर fit होने वाला plan ढूँढो। Check करने की तारीख लिख लो।
3. **Recommend करो।** अपनी पसंद के किसी client के लिए एक पेज की recommendation लिखो, जिसमें fit, expected volume पर cost, data कहाँ process होता है, lock-in और इसे कौन maintain करेगा, ये सब हो।

**आपका काम पूरा है जब आप** किसी बताए गए client के लिए tool recommend कर सको और cost, data और maintenance के आधार पर उस चुनाव का बचाव कर सको, और आपके quote किए हर number के साथ तारीख वाला price हो।
