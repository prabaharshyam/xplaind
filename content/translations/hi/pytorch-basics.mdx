## ये क्या है

**PyTorch** एक open-source Python library है, neural networks बनाने और train करने के लिए। इसके building blocks:

- **Tensors**: multi-dimensional arrays, NumPy arrays जैसे, जो CPU या GPU पर रह सकते हैं और gradients track कर सकते हैं।
- **Autograd**: tensors पर होने वाले operations record करता है और gradients अपने-आप निकालता है।
- **nn.Module**: models की base class। Layers और models, दोनों modules हैं।
- **Dataset** और **DataLoader**: data load करते हैं और उसे shuffled batches में देते हैं।
- **Optimisers**: gradients से weights update करते हैं (SGD, Adam)।

```flow
images और labels की CSV -> Dataset | __getitem__(i) से (tensor 3x224x224, label 4) मिलता है
Dataset -> DataLoader | 64 के batches, shuffled, .to(device)
DataLoader -> nn.Module | forward(x) से 6 classes के scores मिलते हैं
nn.Module -> loss_fn -> loss.backward() -> opt.step()
opt.step() -[अगला batch]-> DataLoader
opt.step() -[हर epoch पर]-> Validate | model.eval() + no_grad(), सबसे अच्छा checkpoint save करो
```

इस lesson में हम Pune की एक textile manufacturer के engineer के साथ चलेंगे, जो अपने पहले PyTorch project के तौर पर fabric-defect classifier बना रहे हैं।

## ये काम कैसे करता है

**Tensors और devices.** Data से tensors बनाओ, `.shape` और `.dtype` देखो, और model और data दोनों को एक ही device पर भेजो (GPU के लिए `"cuda"`, वरना `"cpu"`)। Devices का mismatch beginners की सबसे बड़ी गलतियों में से है।

**Data.** `Dataset` index देने पर एक example और उसका label लौटाता है। `DataLoader` उन्हें batches में बाँटता और shuffle करता है। Training और prediction में एक ही preprocessing लगाओ।

**Model.** `nn.Module` को subclass करो, layers `__init__` में define करो, और forward computation `forward` में।

**Training loop.** PyTorch का दिल:

```python
model.to(device)
opt = torch.optim.AdamW(model.parameters(), lr=1e-3)
loss_fn = nn.CrossEntropyLoss()

for epoch in range(epochs):
    model.train()
    for x, y in train_loader:
        x, y = x.to(device), y.to(device)
        opt.zero_grad()              # clear old gradients
        loss = loss_fn(model(x), y)  # forward pass and loss
        loss.backward()              # backpropagation
        opt.step()                   # update weights

    model.eval()                     # switch off dropout etc.
    with torch.no_grad():            # no gradients needed for evaluation
        val_loss = evaluate(model, val_loader)
    save_if_best(model, val_loss)
```

**Evaluation mode.** `model.eval()` dropout और batch normalisation जैसी layers को inference वाले behaviour पर ले आता है। `torch.no_grad()` memory और time बचाता है। `eval()` भूल गए तो validation के numbers गलत आते हैं। `no_grad()` भूल गए तो memory बेकार जाती है।

**Saving.** Model का `state_dict` (उसके weights) save करो, साथ में वो settings और preprocessing भी जो उसे दोबारा बनाने के लिए चाहिए। Validation score के हिसाब से सबसे अच्छा checkpoint save करो, सिर्फ़ आखिरी वाला नहीं।

**Reproducibility.** Random seeds set करो, settings और library versions log करो।

**Higher-level tools.** PyTorch Lightning या fastai जैसी libraries loop को logging, checkpoints और multi-GPU support के साथ wrap कर देती हैं। पहले सादा loop सीखो, ताकि wrappers को debug कर सको।

**एक minimal model और dataset:**

```python
import torch
from torch import nn
from torch.utils.data import Dataset, DataLoader

class DefectData(Dataset):
    def __init__(self, rows, label_map, transform):
        self.rows, self.label_map, self.transform = rows, label_map, transform
    def __len__(self):
        return len(self.rows)
    def __getitem__(self, i):
        path, label = self.rows[i]
        return self.transform(load_image(path)), self.label_map[label]

class SmallNet(nn.Module):
    def __init__(self, classes=6):
        super().__init__()
        self.body = nn.Sequential(
            nn.Conv2d(3, 16, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
            nn.Conv2d(16, 32, 3, padding=1), nn.ReLU(), nn.AdaptiveAvgPool2d(1),
        )
        self.head = nn.Linear(32, classes)
    def forward(self, x):
        return self.head(self.body(x).flatten(1))
```

`label_map` एक बार बनता है और training और validation, दोनों datasets को दिया जाता है। Worked example में ठीक यही fix चाहिए था।

**आगे बढ़ते हुए shapes check करना.** PyTorch के कई errors shape के errors होते हैं। Training से पहले एक batch model से गुज़ारो और हर layer के बाद shape print करो। 224 pixel की 64 colour images के batch का shape `[64, 3, 224, 224]` होता है, और model का output `[64, 6]` होना चाहिए। जब error में "mat1 and mat2 shapes cannot be multiplied" दिखे, तो इसका मतलब है कि किसी layer को जितने inputs की उम्मीद थी, उससे अलग मिले।

**GPU use करना.** `torch.cuda.is_available()` check करो और script के ऊपर एक बार `device = "cuda" if torch.cuda.is_available() else "cpu"` set करो, फिर हर जगह `device` ही use करो। इस path के projects के लिए Google Colab या Kaggle notebooks के free GPUs काफ़ी हैं। GPU हर layer के बड़े matrix multiplications को अक्सर दस गुना या उससे ज़्यादा तेज़ कर देता है, पर धीमे data loading में उससे कुछ नहीं बदलता। अगर loop चलते समय GPU खाली बैठा है, तो DataLoader में `num_workers` बढ़ाओ, ताकि images parallel में पढ़ी और resize हों।

**Loop से आदत तक.** Loop को एक बार हाथ से लिखो और उसे template की तरह रख लो: ऊपर seeds और device, फिर datasets और loaders, model, optimiser और loss, और फिर epoch loop जिसमें validation और checkpoint saving हो। ज़्यादातर नए projects में बस dataset और model बदलते हैं।

**पूरी, चलने लायक training script.** Synthetic tabular data, ताकि ये कहीं भी CPU पर चल जाए। इसमें अपना `Dataset` लगा दो:

```python
import torch
from torch import nn
from torch.utils.data import TensorDataset, DataLoader, random_split

torch.manual_seed(0)
device = "cuda" if torch.cuda.is_available() else "cpu"

N, D, C = 6000, 20, 3
X = torch.randn(N, D)
true_w = torch.randn(D, C)
y = (X @ true_w + 0.5 * torch.randn(N, C)).argmax(1)

mean, std = X.mean(0), X.std(0)                      # save these with the model
ds = TensorDataset((X - mean) / std, y)
train_ds, val_ds = random_split(ds, [5000, 1000], generator=torch.Generator().manual_seed(0))
train_dl = DataLoader(train_ds, batch_size=128, shuffle=True)
val_dl = DataLoader(val_ds, batch_size=512)

model = nn.Sequential(nn.Linear(D, 64), nn.ReLU(), nn.Dropout(0.2), nn.Linear(64, C)).to(device)
opt = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-4)
loss_fn = nn.CrossEntropyLoss()

def evaluate():
    model.eval(); correct = total = 0; loss_sum = 0.0
    with torch.no_grad():
        for xb, yb in val_dl:
            xb, yb = xb.to(device), yb.to(device)
            out = model(xb)
            loss_sum += loss_fn(out, yb).item() * len(yb)
            correct += (out.argmax(1) == yb).sum().item(); total += len(yb)
    return loss_sum / total, correct / total

best, patience, bad = float("inf"), 5, 0
for epoch in range(100):
    model.train()
    for xb, yb in train_dl:
        xb, yb = xb.to(device), yb.to(device)
        opt.zero_grad()
        loss_fn(model(xb), yb).backward()
        opt.step()
    val_loss, val_acc = evaluate()
    if val_loss < best - 1e-4:
        best, bad = val_loss, 0
        torch.save({"state_dict": model.state_dict(), "mean": mean, "std": std,
                    "epoch": epoch, "val_acc": val_acc, "torch": str(torch.__version__)}, "best.pt")
    else:
        bad += 1
        if bad >= patience:
            break
print(f"stopped at epoch {epoch}, best val loss {best:.3f}")
```

**अलग script में load करके predict करना.** वही architecture दोबारा बनाओ, weights load करो, saved preprocessing लगाओ और eval mode पर जाओ:

```python
ckpt = torch.load("best.pt", map_location="cpu", weights_only=True)   # never unpickle untrusted files
model2 = nn.Sequential(nn.Linear(D, 64), nn.ReLU(), nn.Dropout(0.2), nn.Linear(64, C))
model2.load_state_dict(ckpt["state_dict"]); model2.eval()
new_rows = torch.randn(5, D)
with torch.no_grad():
    probs = model2((new_rows - ckpt["mean"]) / ckpt["std"]).softmax(1)
print(probs.round(decimals=2), "from epoch", ckpt["epoch"], "val acc", round(ckpt["val_acc"], 3))
```

Prediction के समय saved mean और standard deviation भूल जाना सबसे आम silent bugs में से एक है।

**GPUs पर और तेज़.** Mixed precision (forward pass के चारों ओर `torch.autocast(device_type="cuda", dtype=torch.bfloat16)`) कम memory लेता है और modern GPUs पर तेज़ चलता है। `torch.compile(model)` training को और तेज़ कर सकता है। इन्हें तब जोड़ो जब सादा loop सही चल रहा हो, और check करो कि validation scores बदले नहीं।

**Data loading अक्सर bottleneck होती है.** अगर GPU का use कम है, तो `DataLoader` में `num_workers` बढ़ाओ, data को तेज़ local disk पर रखो, और GPU पर train करते समय `pin_memory=True` set करो।

## आम गलतियाँ

- **Model और data अलग devices पर होना।**
- **`zero_grad()` भूल जाना।** Gradients batches के पार जमा होते हैं।
- **Validation में `model.eval()` और `torch.no_grad()` भूल जाना।**
- **Training और prediction में अलग preprocessing।**
- **सिर्फ़ आखिरी epoch save करना।** Validation के हिसाब से सबसे अच्छा checkpoint रखो।
- **Shapes कभी print न करना।** एक batch को model से गुज़ारकर shapes print करने से error messages पढ़ने का एक घंटा बच जाता है।
- **Preprocessing के statistics को weights के साथ save न करना।**
- **सबसे अच्छे की जगह आखिरी epoch रख लेना**, validation के हिसाब से।
- **Correctness से पहले speed optimise करना**: पहले सादा loop सही करो।

## जब PyTorch लिखने की ज़रूरत नहीं होती

- **Tabular problems**, जिन्हें scikit-learn या gradient-boosting libraries अच्छे से संभाल लेती हैं।
- **Standard models को fine-tune करना**, जहाँ Hugging Face का Trainer या ऐसे tools आपके लिए loop wrap कर देते हैं।
- **API से hosted models use करना**, जिसमें training बिल्कुल नहीं होती।

## Demo से production तक

- **पूरे checkpoints save करो**: weights, settings, preprocessing, label map, versions।
- **Training और serving में library versions pin करो।**
- **हर run log करो**: settings, metrics और data version के साथ।
- **Loading को test करो**, CI के हिस्से के तौर पर, एक fresh process में।
- **Serving के लिए export** (TorchScript या ONNX) तभी करो जब check कर लो कि outputs original से मिलते हैं।
