## ये क्या है

अब कई AI engineering interviews में एक **design round** होता है। आपसे पूछा जा सकता है "किसी bank के लिए customer-support assistant design करो", "10 million documents पर सवालों के जवाब देने वाला system design करो" या "travel book करने वाला agent कैसे बनाओगे?"। आपको 30 से 45 मिनट और एक whiteboard या shared document मिलता है, और interviewer बीच में "what if...?" पूछकर टोकेगा।

वो किसी एक tool की जानकारी से ज़्यादा structured सोच, सही trade-offs और production की समझ को परखते हैं।

| मिनट | Step | क्या cover करना है |
|---|---|---|
| 0-5 | Clarify | Users, scale, latency, cost, languages, data rules, success |
| 5-10 | High level | Boxes और arrows: channel, API, routing, tools या RAG, model, reply |
| 10-28 | Deep dives | इस problem के लिए सबसे ज़रूरी 2-3 हिस्से |
| 28-31 | Failures | Hallucination, injection, outage, cost, privacy |
| 31-34 | Evals और ops | Test set, metrics, launch bar, monitoring, rollout |
| 34-35 | Trade-offs | ज़्यादा time मिले तो, और 10x scale पर |

जब interviewer "what if...?" पूछे, तो उसे नई requirement मानो और design को बदलो।

## ये काम कैसे करता है

**एक भरोसेमंद structure।**

1. **Clarify (3 से 5 मिनट)।** Users, task, scale (users, documents, requests per second), latency और cost की सीमाएँ, languages, data sensitivity, success का मतलब। पूछो, फिर assumptions ज़ोर से बोलो।
2. **High-level design (5 मिनट)।** गहराई में जाने से पहले main components और request flow का sketch बनाओ।
3. **Deep dives (15 से 20 मिनट)।** इस problem के सबसे ज़रूरी हिस्से: आमतौर पर retrieval (ingestion, chunking, hybrid search, reranking, permissions), generation (prompting, grounding, model choice), tools या agents, और evaluation।
4. **Failure modes और safety (5 मिनट)।** Hallucination, injection, outages, cost spikes, privacy।
5. **Evaluation और operations (5 मिनट)।** Test sets, metrics, launch bar, monitoring, rollout।
6. **Trade-offs और next steps (2 मिनट)।** ज़्यादा time मिले या दस गुना scale हो तो आप क्या करोगे।

**अच्छे score वाली आदतें।**

- सोचते हुए बोलो; trade-offs का नाम लो ("hybrid search थोड़ा महँगा है पर policy numbers पकड़ लेता है")।
- Numbers use करो: मोटे token counts, costs, latency budgets।
- सादा शुरू करो, फिर complexity वहीं जोड़ो जहाँ requirements माँगें।
- Interruptions को हमला नहीं, नई requirements समझकर जवाब दो।
- Time पर नज़र रखो; chunking पर 25 मिनट मत लगाओ।

**Practice के लिए आम सवाल।** Company documents पर RAG; actions वाला customer-support assistant; लंबे documents का summary; coding assistant; भारत के लिए multilingual chatbot; tools वाला agent; model upgrade को evaluate करना; cost आधी करना।

**ज़ोर से practice करो।** खुद को record करो या किसी दोस्त के साथ practice करो। Design को बोलना उसे जानने से अलग skill है।

**Interviewers जो signals देखते हैं:**

| Strong signal | Weak signal |
| --- | --- |
| पहले users, scale और data rules के बारे में पूछना | Tools के नाम लेने लगना |
| Numbers के साथ assumptions बताना | Numbers से बचना |
| समझाना कि हर choice इस problem में क्यों फ़िट है | Technologies की list बनाना |
| Failure modes और evaluation cover करना | Happy path पर रुक जाना |
| "What if" पर शांति से adapt होना | पहले design का अड़कर बचाव करना |
| सारे हिस्सों में time संभालना | ज़्यादातर time एक box पर लगाना |

**Partner के साथ practice।** हर session में roles बदलो। Interviewer एक ऐसा prompt चुनता है जो candidate ने नहीं देखा, हर phase को time करता है, और दो बार "what if" सवालों से टोकता है, जैसे outage, नई language या दस गुना traffic। बाद में interviewer तीन notes देता है: एक चीज़ जो अच्छी हुई, एक gap, एक आदत जो बदलनी है। Interviewer बनकर आपको समझ आता है कि साफ़ जवाब कैसा सुनाई देता है।

**Estimates जल्दी लगाना।** कुछ back-of-the-envelope numbers तब तक practice करो जब तक वो बिना सोचे न आने लगें। एक page text में कितने tokens, daily users से requests per second, tokens और prices से cost per request, और किसी model size को कितनी GPU memory चाहिए, ये पता होना चाहिए। Interviewers को सटीक आँकड़े नहीं चाहिए; वो देखना चाहते हैं कि आप orders of magnitude में reason करते हो।

## एक example से समझो

Prompt: "एक राज्य बिजली बोर्ड के लिए WhatsApp assistant design करो जो billing और outage के सवालों के जवाब Tamil और English में दे।"

एक मज़बूत candidate का जवाब, संक्षेप में:

- *Clarify*: 2 million consumers; bills जारी होने के बाद और outages के दौरान peaks; tariffs पर जवाब सटीक होने चाहिए; outage data एक internal system में; account सवालों के लिए consumer number; data भारत में ही रहना चाहिए।
- *Design*: एक provider के ज़रिए WhatsApp Business Platform → API service → intent routing (billing, outage, tariff FAQ, complaint) → bill lookup और outage status के tools (consumer number OTP से verify) → दोनों languages में tariff orders और FAQs पर RAG → भारतीय region में model → reply।
- *Deep dive*: Tamil और English chunks के साथ bilingual retrieval; tariff tables ध्यान से extract करना; outage के जवाब सिर्फ़ live tool से, कभी generate नहीं; complaints reference number के साथ log होकर लोगों को सौंपी जाएँ।
- *Failures*: outage spikes (हर area का outage status cache करो, scale out), गलत tariffs (citations, refusal, साप्ताहिक review), injection (complaint logging के अलावा कोई write tool नहीं), provider outage (helpline के साथ fallback message)।
- *Evaluation*: दोनों languages में 300 असली सवाल, intent के हिसाब से accuracy; पहले एक district में launch।
- *Cost*: हर conversation का मोटा estimate और अपेक्षित volume पर महीने का total।

Interviewer पूछता है, "अगर outage system down हो तो?" Candidate जवाब देता है: आख़िरी जानी हुई status timestamp और helpline के साथ दिखाओ, और on-call को alert करो।

| Phase | बिजली बोर्ड के जवाब में क्या cover हुआ |
| --- | --- |
| Clarify | 2 million consumers, bill-day और outage peaks, भारत में data residency |
| Design | WhatsApp provider, intent routing, OTP-verified tools, bilingual RAG |
| Deep dive | Outage के जवाब सिर्फ़ live tool से; tariff tables ध्यान से extract |
| "अगर outage system down हो?" | आख़िरी जानी हुई status timestamp और helpline के साथ, और on-call alert |

## आम गलतियाँ

- **Clarify किए बिना details में कूद जाना।**
- **Choices समझाने के बजाय tools के नाम लेना।**
- **Evaluation और operations को नज़रअंदाज़ करना।**
- **Numbers का न होना।**
- **एक component पर time खत्म कर देना।**
