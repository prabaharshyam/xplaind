## ये क्या है

आम ML engineer loops में ये होते हैं:

- **ML fundamentals**: bias और variance, overfitting, regularisation, metrics, cross-validation, खास models कैसे काम करते हैं (trees, logistic regression, neural networks, transformers)।
- **Coding**: Python और pandas में data manipulation, कोई सादा algorithm implement करना, कभी-कभी standard data-structure problems।
- **ML system design**: "UPI payments के लिए fraud detection system design करो", "grocery app के लिए recommendations design करो"।
- **Case या project deep-dive**: आपने जो project बनाया उसे समझाना, choices और results पर follow-up सवालों के साथ।
- **Behavioural**: ownership, collaboration, नाकामी से निपटना।

```flow
title: 40 मिनट में ML system design
1 Goal और metric -> 2 Framing और label -> 3 Data -> 4 Features | करीब 15 मिनट
4 Features -> 5 Baseline, फिर model -> 6 Evaluation | offline और A/B, करीब 12 मिनट
6 Evaluation -> 7 Serving | batch या real time, fallback के साथ -> 8 Monitoring | करीब 8 मिनट
8 Monitoring -> 9 Risks | fairness, abuse, failure; करीब 5 मिनट
```

Numbers ज़ोर से बोलो: latency budget, label delay, class balance और alert capacity।

ये lesson "UPI merchant transactions के लिए fraud detection design करो" के एक model जवाब को follow करता है, जो Indian payments companies में आम सवाल है।

## ये काम कैसे करता है

**Fundamentals।** इन्हें सादे शब्दों में और एक example के साथ समझा पाना चाहिए:

- bias-variance trade-off और learning curves से underfitting बनाम overfitting कैसे पहचानें;
- imbalanced data पर accuracy क्यों फेल होती है और उसकी जगह क्या use करें;
- gradient boosting और random forests में क्या फ़र्क है;
- leakage क्या है और आप उसे कैसे ढूँढोगे;
- attention कैसे काम करता है, ऊपरी स्तर पर।

**ML system design के लिए एक structure।**

1. *Goal* और business metric साफ़ करो; constraints (latency, scale, regulation)।
2. *ML problem frame करो*: क्या predict करना है, किसके लिए, कब; label और वो कैसे मिलता है।
3. *Data*: sources, labels, volume, freshness, biases, privacy।
4. *Features*: मुख्य groups, prediction के समय तक के हिसाब से निकाले हुए।
5. *Model*: पहले सादा baseline, फिर कारणों के साथ एक मज़बूत model।
6. *Evaluation*: offline metrics, असलियत से मेल खाते splits, segments; online A/B test और guardrails।
7. *Serving*: batch या real-time, latency budget, fallback।
8. *Monitoring और iteration*: drift, feedback loops, retraining।
9. *Risks*: fairness, abuse, failure modes।

**Project deep-dives।** एक-दो projects गहराई से तैयार रखो: problem, data, baseline, क्या आज़माया, numbers के साथ results, क्या गलत हुआ, आगे क्या करोगे। "X क्यों नहीं?" वाले सवालों की उम्मीद रखो।

**Coding।** Pandas groupbys, joins और window-style calculations की practice करो, time के हिसाब से train-validation split लिखना, और सादे metrics या k-means को scratch से implement करना।

**Behavioural।** किसी भी engineering role की तरह numbers वाली STAR stories।

**सबसे ज़्यादा आने वाले fundamentals:**

| Topic | क्या कह पाना चाहिए |
| --- | --- |
| Bias और variance | Learning curves underfitting बनाम overfitting कैसे दिखाते हैं, और हर एक का इलाज क्या है |
| Imbalanced data | Accuracy क्यों भ्रमित करती है; PR AUC, एक threshold पर precision और recall |
| Trees | Random forests और gradient boosting में क्या फ़र्क है |
| Leakage | ये क्या है, ज़रूरत से अच्छा score कैसे पहचानें, splits और features कैसे ठीक करें |
| Attention | Queries, keys और values, ऊपरी स्तर पर |

**ज़ोर से practice करना।** System design बोलने का skill है। 40 मिनट का timer लगाओ, एक अनदेखा सवाल चुनो, और एक सादा diagram बनाते हुए नौ steps बोलते जाओ। खुद को record करो, फिर सुनकर कमियाँ पकड़ो: क्या label define किया, latency budget बताया, baseline का नाम लिया, time से मेल खाता split चुना, और बताया कि monitor कैसे करोगे? ये हफ़्ते में एक बार दोस्त के साथ करो और roles बदलो, क्योंकि interviewer बनने से दिखता है कि साफ़ जवाब सुनने में कैसा लगता है।

**"X क्यों नहीं?" को संभालना।** Interviewers choices पर दबाव डालते हैं। Trade-off के साथ जवाब दो: "Deep model मदद कर सकता है, पर tabular features और label delays के साथ gradient boosting करीब-करीब वही accuracy देता है, मिनटों में train होता है और risk team को समझाना भी आसान है। अगर error analysis में ऐसे patterns दिखें जो trees से छूट रहे हैं, तो baseline के बाद उसे आज़माऊँगा।"

## एक example से समझो

सवाल: "किसी payments company के लिए fraudulent UPI merchant transactions पकड़ने का system design करो।"

एक मज़बूत रूपरेखा:

1. *Goal*: सीमित analyst capacity के साथ fraud के नुकसान घटाना; blocking के लिए 100 ms के अंदर real-time फ़ैसला, साथ में एक review queue।
2. *Framing*: हर transaction पर binary classification; labels chargebacks और पक्की हुई investigations से, 30 से 60 दिन बाद आते हैं।
3. *Data*: transactions, merchant profiles, device और network signals, पुराने fraud; भारी imbalance (fraud एक प्रतिशत का छोटा हिस्सा है; जो rate मानते हो वो बताओ)।
4. *Features*: velocity (प्रति merchant प्रति घंटे transactions), merchant के इतिहास के मुकाबले amount, नया device, दिन का समय, merchant category; सब feature store से transaction के समय तक के हिसाब से निकाले हुए।
5. *Model*: rules baseline; class weights के साथ gradient-boosted trees; बाद में merchants और devices को जोड़ने वाले graph features।
6. *Evaluation*: time-based split; PR AUC; analysts जितना alert volume संभाल सकें उस पर recall; merchant category और region के हिसाब से; traffic के एक हिस्से पर A/B test।
7. *Serving*: rules के fallback के साथ real-time scoring; दो thresholds (बहुत ऊँची precision पर auto-block, उसके नीचे review queue)।
8. *Monitoring*: key features पर drift, alert-rate में बदलाव, blocked transactions से feedback loop (random holdout), मासिक retraining।
9. *Risks*: असली छोटे merchants को block करना (appeal का रास्ता), adversaries का ढलना (बार-बार retraining), regions में fairness।

| Step | Fraud जवाब का मुख्य बिंदु |
| --- | --- |
| Goal | Block करने के लिए 100 ms से कम, साथ में analysts के हिसाब की review queue |
| Label | Chargebacks और investigations, 30 से 60 दिन देर से |
| Model | Rules baseline, फिर class weights के साथ boosted trees |
| Evaluation | Time split; analysts जितना alert volume संभालें उस पर recall |
| Monitoring | Drift, alert rates, blocked transactions के लिए random holdout |

## आम गलतियाँ

- **सीधे deep learning पर कूद जाना।** Baseline से शुरू करो और complexity को सही ठहराओ।
- **Label को नज़रअंदाज़ करना।** Labels कहाँ से आते हैं और कितनी देर से, ये सब कुछ तय करता है।
- **Time-based problems में random splits।**
- **Serving या monitoring का plan न होना।** Interviewers production वाली सोच चाहते हैं।
- **उथली project कहानियाँ।** अपने numbers और अपनी गलतियाँ जानो।
