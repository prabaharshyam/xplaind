## ये क्या है

रोज़ के code में तीन structures सबसे ज़्यादा काम करते हैं।

**Array** items को क्रम से, memory में एक-दूसरे के बगल में रखता है। Python में `list` एक array है। Items बगल-बगल हैं, इसलिए item 5 पढ़ो या item 5 लाख, समय बराबर लगता है। अंत में जोड़ना सस्ता है; सबसे आगे insert करने का मतलब है बाकी सबको खिसकाना।

**String** characters का array है। Python और Java में string एक बार बनने के बाद बदली नहीं जा सकती, इसलिए हर edit एक नई string बनाता है।

**Hash map** key और value के जोड़े रखता है और key से value ढूँढ लेता है, चाहे उसमें कितने भी जोड़े हों, समय लगभग उतना ही लगता है। Python के `dict` और `set` hash maps हैं। गिनना, duplicates हटाना और match करना, इन सबका ये मुख्य tool है।

| | Array (list) | Hash map (dict) |
|---|---|---|
| कैसे रखता है | Values numbered slots में: 0 Pune, 1 Goa, 2 Agra, 3 Pune | Key `hash()` से गुज़रकर एक slot पाती है: "Pune" से slot 7, value 1,240 orders |
| पढ़ना | Position से: O(1) | Key से: औसतन O(1) |
| Value से ढूँढना | O(n): हर slot check करो | ज़रूरत नहीं: key से lookup करो |
| क्रम | Position से तय | Position से कोई क्रम नहीं |

## ये काम कैसे करता है

**Arrays** items को memory के एक ही block में रखते हैं। Computer साधारण हिसाब से निकाल लेता है कि item i कहाँ है, इसीलिए position से पढ़ना O(1) है। किसी value को ढूँढना फिर भी एक-एक item देखने जैसा है, O(n), जब तक array sorted न हो।

Python lists अपने आप बढ़ती हैं। जब block भर जाता है, Python एक बड़ा block बनाता है और सब कुछ वहाँ copy कर देता है। वो copy O(n) है, पर कभी-कभार ही होती है, इसलिए append औसतन O(1) ही रहता है।

**Hash maps** एक **hash function** use करते हैं जो key, जैसे text "Pune", को एक number में बदलता है। वो number अंदर के array में एक slot चुनता है, और value वहीं रखी जाती है। वापस पढ़ने के लिए map key को फिर hash करता है और सीधे उस slot पर पहुँच जाता है। कभी-कभी दो keys एक ही slot पर आ जाती हैं, इसे **collision** कहते हैं; map दोनों रखता है और keys मिलाकर सही वाली ढूँढता है। अच्छे hash function और काफ़ी slots हों, तो lookup, insert और delete औसतन O(1) में होते हैं।

Trade-off memory और क्रम का है। Hash map list से ज़्यादा memory लेता है, और वो position से पढ़ने के लिए नहीं बना।

| Operation | List (array) | Dict / set (hash map) |
|---|---|---|
| Position से पढ़ना | O(1) | supported नहीं |
| Value या key ढूँढना | O(n) | औसतन O(1) |
| अंत में जोड़ना / key insert करना | औसतन O(1) | औसतन O(1) |
| सबसे आगे insert या delete करना | O(n) | औसतन O(1) |
| Insertion order रखता है | हाँ | Python 3.7+ में हाँ |

Arrays पर आधारित ज़्यादातर interview problems कुछ ही patterns में आते हैं: **frequency count** (dict में items गिनो), **seen set** (जो देख चुके हो वो याद रखो ताकि repeats पकड़ सको), **complement lookup** (values store करो ताकि "target minus ये" तुरंत check हो जाए) और **grouping** (कोई calculate की हुई key, जैसे sorted letters, को items की list से map करो)।

## एक example से समझो

Rahul interviews की तैयारी कर रहा है और Jaipur की एक छोटी bakery के order data पर practice कर रहा है। उसके पास एक दिन के order amounts की list है, और वो जानना चाहता है कि कोई दो orders मिलकर ठीक ₹1,000 बनाते हैं या नहीं, क्योंकि bakery का उसी price पर एक combo है।

सीधा जवाब हर pair try करता है:

```python
def pair_for(amounts, target):
    for i in range(len(amounts)):
        for j in range(i + 1, len(amounts)):
            if amounts[i] + amounts[j] == target:
                return i, j
    return None
```

ये O(n²) है। 20 orders के लिए ठीक है, 2 लाख के लिए slow।

Hash map वाला version एक ही बार scan करता है। हर amount के लिए वो पूछता है: क्या मैं वो amount पहले देख चुका हूँ जो ₹1,000 पूरा करेगा?

```python
def pair_for(amounts, target):
    seen = {}                     # amount -> position
    for i, a in enumerate(amounts):
        need = target - a
        if need in seen:          # O(1) on average
            return seen[need], i
        seen[a] = i
    return None
```

Amounts `[250, 400, 600, 120]` और target 1,000 के साथ: 250 पर उसे 750 चाहिए (देखा नहीं); 400 पर उसे 600 चाहिए (देखा नहीं); 600 पर उसे 400 चाहिए, जो position 1 पर देखा जा चुका है, इसलिए वो `(1, 2)` लौटाता है। एक pass, O(n) time और O(n) space।

फिर वो सबसे popular item गिनता है। Sort करने की जगह वो frequency count use करता है:

```python
from collections import Counter
items = ["bun", "cake", "bun", "puff", "bun", "cake"]
Counter(items).most_common(1)   # [('bun', 3)]
```

`Counter` अंदर से एक dict है: एक pass, O(n)।

## आम गलतियाँ

**Loop के अंदर list में membership check करना।** `if x in some_list` हर बार O(n) है। n items के loop के अंदर ये O(n²) बन जाता है। पहले उसे set में बदल लो।

**Loop में += से string बनाना।** हर `+=` पूरी string की copy बनाता है। Pieces को list में इकट्ठा करो और एक बार `"".join(pieces)` बुला लो।

**Unhashable keys use करना।** Python में lists dict की key नहीं बन सकतीं, क्योंकि वो बदल सकती हैं। Tuple use करो, या कोई string, जैसे किसी शब्द के sorted letters।

**Keys को normalise करना भूल जाना।** "+91 98450 12345" और "9845012345" एक ही customer हैं पर अलग keys हैं। गिनने या match करने से पहले keys साफ़ कर लो।

**ये मान लेना कि dict हमेशा O(1) है।** वो औसतन O(1) हैं। बहुत खराब hashing हो, या कोई attacker अपनी चुनी keys डाले, तो वो slow हो सकते हैं। Interview में बोलो "O(1) on average"।

**List पर loop चलाते हुए उसी को बदलना।** Iterate करते हुए items हटाओगे तो कुछ छूट जाएँगे। उसकी जगह नई list बनाओ।
