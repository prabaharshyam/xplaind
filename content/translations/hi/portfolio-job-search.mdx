## ये क्या है

**Portfolio** इस बात का सबूत है कि आप ये काम कर सकते हो। AI engineering और FDE roles के लिए इसका मतलब आमतौर पर होता है:

- **एक GitHub profile** जो आपके तीन से पाँच सबसे अच्छे projects से शुरू होता है, हर एक का साफ़ README के साथ।
- **Case-study write-ups** एक या दो projects के, end-to-end case study की तरह लिखे: problem, numbers, फ़ैसले, results, क्या गलत हुआ।
- **एक resume** एक पन्ने का (अनुभवी engineers के लिए ज़्यादा से ज़्यादा दो), जिसमें duties नहीं, results हों।
- **चाहो तो**, छोटे demo videos और कुछ public posts जो बताएँ कि आपने क्या सीखा।

**Job search** वो plan है जो इस सबूत को सही लोगों के सामने रखता है।

```flow
title: एक link, 60 seconds: github.com/you
Profile README -> Pinned: enterprise RAG assistant | "recall at 5: 60 सवालों पर 68% से 93%"
Profile README -> Pinned: approvals वाला operations agent | "200 test runs में 0 unapproved actions"
Profile README -> Pinned: document QA API | "96% field accuracy; हर file पर 4 s"
Profile README -> Case study: hospital chain capstone | 3 पन्ने + 2 मिनट का video
```

```flow
dir: LR
title: Search
40 target companies -> 15 में contacts -> खास notes -> Sheet में track
```

Resume: एक पन्ना, duties नहीं results, tools context के साथ।

ये lesson कोयंबटूर की backend developer Nandhini को follow करता है, इस path को पूरा करने से लेकर offers मिलने तक।

## ये काम कैसे करता है

**Job से मेल खाते projects चुनो।** FDE roles के लिए: realistic client problem, गड़बड़ data, evals, deployment और governance वाले projects। इस path के छह stage projects इसी के लिए बने हैं। दस tutorials से बेहतर हैं तीन मज़बूत, पूरे किए हुए projects।

**READMEs जो बेचें।** हर README की शुरुआत problem पर एक वाक्य और एक screenshot या 60-second video से करो। फिर number के साथ result दो ("300 real-style documents पर field accuracy 96%; हर file पर 4 seconds"), architecture एक छोटे diagram में, और इसे चलाने का तरीका। फिर details। इन repositories को अपने profile पर pin करो और अपने case studies से जुड़ा एक profile README जोड़ो।

**Results वाले resume bullets।** Pattern: action, क्या, नापा जा सकने वाला result। "4,000 पन्नों की insurance policies पर hybrid search और reranking के साथ RAG assistant बनाया; 60-सवाल के golden set पर retrieval recall at 5 को 68% से 93% तक बढ़ाया।" AI, cloud और tools को context में रखो, लंबी keyword list की तरह नहीं।

**Target companies।** भारत में और remote: enterprise customers वाली AI labs और AI-first startups, data और AI platform companies, बड़ी firms के global capability centres जो AI teams बना रही हैं, और AI practices वाली IT services और consulting firms। Job posts ध्यान से पढ़ो: कुछ "forward deployed" कहते हैं, बाकी "solutions engineer", "AI engineer, customer-facing" या "applied AI engineer" कहते हैं।

**Referrals और बातचीत पाओ।** Target companies के engineers को एक खास note और एक relevant project के link के साथ message करो। जिन open-source tools का आपने इस्तेमाल किया, उनमें contribute करो। जो बनाया और सीखा उसके छोटे write-ups share करो।

**Track करो।** Applications, contacts, stages और follow-ups की एक सादी sheet। कई rejections की उम्मीद रखो; हर दस applications के बाद देखो कि क्या जवाब ला रहा है और अपने materials बदलो।

**कमज़ोर और मज़बूत portfolio pieces:**

| Piece | कमज़ोर | मज़बूत |
| --- | --- | --- |
| Project | किसी video से बना PDF पर chatbot | Real problem, गड़बड़ data, golden set, deployed |
| README की शुरुआत | "pip install ..." | Problem, visual, number के साथ result |
| Resume bullet | "Worked on RAG" | "60-सवाल के golden set पर recall at 5 को 68% से 93% किया" |
| Outreach note | "Please refer me" | "आपके customers जैसी problems के लिए मैंने X बनाया; link ये रहा" |

**Outreach note लिखना।** इसे चार वाक्यों में रखो: आप कौन हो, उनकी company से जुड़ा वो एक project और उसका result, एक खास सवाल या request, और शुक्रिया। जैसे: "मैं कोयंबटूर का backend developer हूँ और AI engineering में आ रहा हूँ। मैंने एक claims-document assistant बनाया जिसकी 300 test files पर field accuracy 96% है, जो आपकी team के insurers को बेचे जाने वाले product के काफ़ी करीब है। क्या आपके पास 15 मिनट होंगे ये बताने के लिए कि आपकी FDE team कैसे काम करती है? धन्यवाद।" खास notes पर जवाब आते हैं; आम referral requests पर शायद ही कभी।

**हर दस applications के बाद review।** Replies और first rounds गिनो। Replies कम हों तो resume का ऊपरी एक तिहाई और अपने READMEs की पहली पंक्तियाँ दोबारा लिखो। First rounds बुरे जाएँ तो जो round फ़ेल हुआ उसकी practice करो। एक बार में एक ही चीज़ बदलो, ताकि पता रहे कि क्या काम आया।

## एक example से समझो

Nandhini, कोयंबटूर की backend developer, जिसके पास दो साल का Java अनुभव है, ये path सात महीने में पूरा करती है।

उसके portfolio में चारों projects में से हर एक का repository pinned है, और हर एक की पहली पंक्ति में result है। वो हैं document QA API, eval report के साथ enterprise RAG assistant, approval gates वाला operations agent, और एक काल्पनिक hospital chain का capstone। उसका capstone case study तीन पन्नों का है और उसके साथ दो मिनट का video है।

उसका resume Java का काम छोटे bullets में समेटता है और numbers के साथ एक "Projects" section जोड़ता है। वो 40 target companies की list बनाती है, उनमें से 15 में engineers ढूँढती है, और हर company के customers के सबसे relevant project का link लगाकर छोटे notes भेजती है।

आठ हफ़्तों के results: 31 applications, 9 replies, 6 first rounds, 3 final loops और 2 offers। एक offer hospitals को बेचने वाली एक startup में forward deployed role का था, जिसने कहा कि capstone case study ही उनके call करने की वजह थी।

## आम गलतियाँ

- **Tutorial clones।** किसी video से बना PDF पर chatbot बहुत कम दिखाता है। Real problem, evals और deployment जोड़ो।
- **Installation से शुरू होने वाले READMEs।** Problem और result से शुरू करो।
- **Results की जगह duties।** "Worked on RAG" कुछ नहीं कहता; numbers कहते हैं।
- **एक ही resume से हर जगह apply करना।** हर role के लिए ऊपरी एक तिहाई tailor करो।
- **"Ready" होने तक रुकना।** आख़िरी projects पूरे करते हुए ही apply करो; interviews सिखाते हैं कि क्या सुधारना है।

## Practice करो

GitHub की profile READMEs की guide और Tech Interview Handbook की resume guide पढ़ो।

इस lesson का check आपका portfolio है। एक GitHub profile README publish करो और इस path के कम से कम तीन projects pin करो, हर एक का README problem, एक visual और नापे हुए result से शुरू हो। कम से कम चार result-based bullets के साथ अपना resume लिखो। 20 target companies की list बनाओ, हर एक में संपर्क करने के लिए एक व्यक्ति के साथ।

**आपका काम पूरा जब:** आप किसी अजनबी को एक link भेज सको जो 60 seconds के भीतर दिखा दे कि आपने क्या बनाया और उससे क्या हासिल हुआ।
