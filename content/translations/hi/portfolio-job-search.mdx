## ये क्या है

**Portfolio** इस बात का सबूत है कि आप ये काम कर सकते हो। AI engineering और forward deployed engineer (FDE) roles के लिए इसके आम तौर पर पाँच हिस्से होते हैं:

- **एक GitHub profile** जो आपके तीन से पाँच सबसे अच्छे projects से शुरू हो, हर एक की साफ़ README के साथ।
- एक या दो projects की **case-study write-ups**: problem, numbers, decisions, results और क्या गलत हुआ।
- **एक resume**, एक page का (experienced engineers के लिए ज़्यादा से ज़्यादा दो), जो duties नहीं, results बताए।
- **एक LinkedIn profile** जो वही कहानी कहे, क्योंकि कई Indian recruiters वहीं search करते हैं।
- **चाहो तो**, छोटे demo videos और आपने जो सीखा उस पर कुछ public posts।

**Job search** वो plan है जो इस सबूत को सही लोगों के सामने, सही समय पर, सही pay पर पहुँचाता है।

```flow
title: एक link, 60 seconds: github.com/you
Profile README -> Pinned: enterprise RAG assistant | "recall at 5: 68% to 93% on my 60-question golden set"
Profile README -> Pinned: operations agent with approvals | "0 unapproved actions in 200 scripted test runs"
Profile README -> Pinned: document QA API | "96% field accuracy on 300 synthetic files; 4 s per file"
Profile README -> Case study: hospital chain capstone | 3 pages और एक 2-minute video
```

```flow
dir: LR
title: Search कैसे चलती है
40 target companies -> 15 पर referrals या contacts -> Coding test और interviews -> Fixed pay पर offers की तुलना -> Notice पूरा, फिर join
```

ये lesson Coimbatore की backend developer Nandhini को follow करता है, इस path को पूरा करने से लेकर offers में से एक चुनने तक।

## ये काम कैसे करता है

### Job से मेल खाते projects चुनो

FDE roles के लिए ऐसे projects चुनो जिनमें realistic client problem, messy data, evals, deployment और governance हो, जैसे इस path के stage projects में हैं। दस tutorials से तीन पूरे किए projects बेहतर हैं, क्योंकि interviewers एक project उठाते हैं और आधे घंटे तक उस पर सवाल पूछते हैं।

### READMEs जो आपको sell करें

हर README को problem पर एक sentence और एक screenshot या 60-second video से शुरू करो। फिर number के साथ result, एक छोटा architecture diagram और उसे run कैसे करें, ये दो। इन repositories को pin करो और एक profile README जोड़ो जो आपकी case studies से link करे।

इसे वैसे test करो जैसे reviewer करेगा। किसी friend से कहो कि एक project clone करे और सिर्फ़ README के सहारे उसे run करे। अगर 10 minutes से ज़्यादा लगें, या आपको message करना पड़े, तो README ठीक करो या एक hosted demo जोड़ो।

### Numbers जिनका बचाव कर सको

आपके portfolio का हर number सवाल पूछे जाने का न्योता है। Interviewers पूछते हैं: "ये किस पर मापा गया? दिखा सकते हो?" तीन rules follow करो:

1. **Test set का नाम और size बताओ।** "96% field accuracy" एक दावा है। "मेरी बनाई 300 synthetic insurance files पर 96% field accuracy" सबूत है।
2. **Data कहाँ से आया, ये ईमानदारी से बताओ।** एक काल्पनिक hospital chain के लिए capstone ठीक है। उसे "discharge delays 30% कम किए" कहना ठीक नहीं, क्योंकि किसी hospital ने उसे use नहीं किया। वो बताओ जो आपने मापा: accuracy, latency, हर request की cost।
3. **Eval को चलने लायक रखो।** Golden set और eval script repository में ही रखो, ताकि पूछे जाने पर आप उसे live दोबारा चला सको।

एक मामूली number जिसे आप समझा सको, उस बड़े number से बेहतर है जिसे आप नहीं समझा सकते।

### Resume, screening software और LinkedIn

**Results वाले bullets।** Pattern है action, आपने क्या बनाया, और एक मापा हुआ result। जैसे: "Built a RAG assistant over 4,000 pages of insurance policies with hybrid search and reranking; raised retrieval recall at 5 from 68% to 93% on a 60-question golden set."

**पहली नज़र छोटी होती है।** 2018 की एक eye-tracking study में job site Ladders ने पाया कि recruiters हर resume पर पहली नज़र में लगभग 7.4 seconds लगाते थे। वो ज़्यादातर titles, companies और dates देखते थे। साफ़ headings वाले simple layouts ने ध्यान बाँधे रखा; भरे-भरे, multi-column layouts का हाल बुरा रहा। इसका sample size नहीं बताया गया, पर सबक वही है: अपना सबसे strong result top third में रखो।

**Applicant tracking systems।** कई employers resumes को एक applicant tracking system (ATS) में डालते हैं, ये software applications store करता है और recruiters को keyword से filter करने देता है। Two-column templates, images में लिखा text और icons बिगड़कर आ सकते हैं, इसलिए एक column, standard headings (Experience, Projects, Skills, Education) और text-based PDF use करो। एक छोटी skills line जोड़ो जो job post के exact terms ("RAG", "LangGraph", "AWS") दोहराए, बशर्ते वो सच हों। बाकी जगह, tools की लंबी keyword list की जगह उन्हें अपने result bullets के अंदर context के साथ रखो।

**LinkedIn।** वही headline use करो जो आपकी GitHub profile पर है, जैसे "Backend engineer building RAG and agent systems for healthcare"। Featured section में एक project pin करो और अपने दो सबसे अच्छे results के साथ एक छोटा About section लिखो। LinkedIn आपको खुद को open to work mark करने देता है, चाहो तो सिर्फ़ recruiters को दिखे।

### India में AI jobs कहाँ post होती हैं

| Channel | किसके लिए best | किस बात का ध्यान रखें |
| --- | --- | --- |
| Naukri | Volume: IT services, GCCs, बड़ी firms; recruiters इसके resume database में search करते हैं | अपनी profile और notice period updated रखो; recruiters दोनों पर filter करते हैं |
| LinkedIn | Product companies, GCCs, AI startups; hire करने वाले लोगों को ढूँढना | हर post पर बहुत applications; इसे सिर्फ़ Apply button के लिए नहीं, contacts ढूँढने के लिए use करो |
| Instahyre, foundit | Tech roles (Instahyre); हर तरह के roles (foundit) | Skills और expected pay ध्यान से भरो; matching उन्हीं पर depend करती है |

| Company careers pages | GCCs और बड़ी firms | हर company जो titles use करती है, उनसे search करो |

Titles ध्यान से पढ़ो। FDE जैसे काम को "forward deployed engineer", "solutions engineer", "AI engineer, customer-facing" या "applied AI engineer" कहा जा सकता है।

### Referrals और outreach

India में किसी इंसान से आपका resume पढ़वाने का सबसे तेज़ रास्ता अक्सर referral होता है। कई companies employee referral programmes चलाती हैं, तो आपके hire होने पर referrer को bonus मिल सकता है। इसलिए ये एक जायज़ request है, एहसान नहीं। पर referrer आप पर अपना नाम लगाता है, तो उसके लिए इसे आसान और safe बनाओ:

- **पहले उनसे पूछो जो आपको जानते हैं:** college alumni, पुराने colleagues, seniors, open-source projects और meetups से मिले लोग।
- **सब कुछ एक साथ भेजो:** job link या ID, अपना resume, और अपने सबसे relevant project और उसके result पर दो lines।
- **अनजान लोगों से referral नहीं, बातचीत माँगो।** चार sentences use करो: आप कौन हो, एक relevant project और उसका result, एक specific सवाल, और धन्यवाद। जैसे: "मैं Coimbatore में backend developer हूँ और AI engineering में आ रही हूँ। मैंने एक claims-document assistant बनाया है जिसकी 300 synthetic test files पर field accuracy 96% है, जो आपकी team insurers को बेचती है उसके काफ़ी करीब। क्या आप 15 minutes निकालकर बता सकते हैं कि आपकी FDE team कैसे काम करती है? धन्यवाद।" अच्छी बातचीत के बाद अक्सर referral मिल जाता है।

बिना context के "Please refer me" का जवाब कम ही आता है।

### Coding round

कई Indian product companies, GCCs और IT services firms HackerRank या HackerEarth जैसे किसी platform पर online coding test से शुरुआत करती हैं। Candidates की reports में अक्सर एक से दो घंटे और data structures and algorithms (DSA) के दो या तीन easy-to-medium problems बताए जाते हैं: arrays, strings, hash maps, two pointers, sorting, trees और graph search, कभी-कभी basic dynamic programming। Candidates cut-off scores की भी बात करते हैं, इसलिए अगर आप ये step fail कर गए तो हो सकता है आपका strong portfolio कोई देखे ही नहीं।

FDE और AI-startup loops practical coding की तरफ़ ज़्यादा झुकते हैं: messy data साफ़ करना, किसी API को call करना, validation और tests जोड़ना (lesson "The FDE interview loop" देखो)। Decision rule:

- **Prepare करने से पहले recruiter से round one का format पूछो।**
- **अगर DSA test है,** तो random तरीके से 400 नहीं, pattern के हिसाब से लगभग 60 से 80 common problems practise करो। Time लगाकर करो, और अपना approach बोलकर बताओ।
- **अगर practical coding है,** तो tests के साथ messy CSVs और JSON पर practise करो, और trade-offs पर बात करो।
- **दोनों हालात में, practice जारी रखो:** search के दौरान रोज़ 30 minutes, एक panic week से बेहतर है।

### Notice periods और timing

आपका **notice period** वो समय है जितना resign करने के बाद आपको काम करते रहना होता है। इसे आपका appointment letter और company policy तय करते हैं, कोई national rule नहीं। बड़ी IT services firms आम तौर पर 90 दिन रखती हैं। कई product companies और startups छोटे periods रखते हैं। Plan करने से पहले तीन clauses पढ़ो: notice कितना लंबा है, क्या आप **buyout** कर सकते हो (जो दिन serve नहीं करोगे उनकी जगह salary देना), और training costs का कोई bond या recovery।

लंबा notice आपकी पूरी search को बदल देता है:

- **Resign करने से पहले interview करो,** ताकि आप तीन महीने बिना pay या options के न रहो।
- **अपना notice शुरू में ही बताओ,** Naukri पर भी और recruiters को भी। कुछ posts ऐसे लोग चाहती हैं जो 30 दिन या उससे कम में join कर सकें; 90 दिन का notice छुपाने से सबका समय बर्बाद होता है।
- **नए employer से दो सवाल पूछो:** क्या वो wait कर सकते हैं, और क्या वो buyout reimburse करेंगे? कुछ करते हैं; आपका employer buyout से मना कर सकता है।
- **लंबे notice के दौरान offers को risk में मानकर चलो।** Join करने तक अपने नए manager से संपर्क में रहो, और दूसरे offer के बारे में झूठ मत बोलो।

### Salary research

उस role का band research करो जिसके लिए आप apply कर रहे हो, अपनी current job का नहीं। Xplaind का Jobs page Glassdoor, AmbitionBox, Instahyre और job posts से typical yearly CTC bands, lakh rupees में, इकट्ठा करता है, **2 November 2026 को check किए गए**। ये बीच के bands हैं, offers नहीं, और अगर Jobs page इस table से अलग हो तो Jobs page ही सही माना जाएगा।

| Role | 0 से 2 साल | 3 से 5 साल | 6+ साल |
| --- | --- | --- | --- |
| AI Engineer | 6 से 12 | 12 से 25 | 25 से 50 |
| Generative AI Engineer | 8 से 15 | 18 से 35 | 35 से 65 |
| Forward Deployed Engineer | 12 से 25 | 25 से 50 | 50 से 90 |

इसे कैसे use करें:

- **Band को छोटा करो।** Big tech, global AI labs और Bengaluru ज़्यादा pay करते हैं; IT services और छोटे शहर कम। शुरुआती FDE band शायद ही कभी fresher job होता है।
- **उस specific company को** Glassdoor और AmbitionBox पर check करो, और जिन लोगों से मिलो उनसे पूछो कि band क्या है।
- **"Current and expected CTC" का जवाब ध्यान से दो।** Indian recruiters आम तौर पर दोनों जल्दी पूछते हैं। अपना current CTC ईमानदारी से बताओ, क्योंकि उसे payslips से check किया जा सकता है। अपना expected figure नए role के band और अपने सबूत पर रखो, current pay पर किसी fixed percentage के हिसाब से नहीं।

### Offers की तुलना

CTC (cost to company) take-home pay नहीं है। हर offer को fixed pay, variable pay, joining bonus (अक्सर एक साल के अंदर छोड़ने पर लौटाना पड़ता है), stock या ESOPs (जिनसे शायद कभी पैसा न मिले) और benefits में तोड़ो। पहले साल में जो cash पक्का मिलेगा उसकी तुलना करो, फिर काम, learning, team और नए notice period की। Accept करने से पहले कोई भी बदलाव लिखित में लो।

### Remote roles और विदेश में jobs

Foreign companies Indian engineers को remote तरीके से एक employer of record (एक firm जो उनकी तरफ़ से आपको India में employ करती है) के ज़रिए या contractors के रूप में hire करती हैं। Competition global है, इसलिए आपका portfolio और लिखी हुई English और भी ज़्यादा मायने रखते हैं। Contractor के तौर पर आप self-employed हो: आप invoices भेजते हो और अपना tax खुद संभालते हो, इसलिए sign करने से पहले किसी chartered accountant से बात करो। विदेश जाने के लिए work visa चाहिए। Juniors के लिए sponsorship कम ही मिलती है, और US work-visa rules 2025 में बहुत बदले और अब भी बदल रहे हैं, इसलिए उनके हिसाब से plan करने से पहले official government source check करो।

### Track करो और review करो

एक simple sheet रखो: company, role, channel (cold, referral, recruiter), date, stage और अगला follow-up। हर दस applications के बाद देखो कि लोग किस stage पर बाहर हो रहे हैं, और एक बार में एक ही चीज़ बदलो:

| कहाँ रुकता है | संभावित वजह | क्या बदलें |
| --- | --- | --- |
| कोई reply नहीं | गलत roles, कमज़ोर top third, referrals नहीं, notice छुपाया या बहुत लंबा | Top third tailor करो; referrals की तरफ़ जाओ; बेहतर मेल खाते roles target करो |
| Coding test में fail | Format की practice नहीं | Format पूछो; pattern के हिसाब से, time लगाकर practise करो |
| First rounds में fail | Project deep dive कमज़ोर | अपने project के decisions और numbers बोलकर rehearse करो |
| Final loops में fail | कमज़ोर design या client role-play | वो rounds किसी friend के साथ practise करो |
| Offers हाथ से निकल जाते हैं | Pay mismatch या notice period | Bands पहले research करो; पहली call में ही notice की बात करो |

"Ready" महसूस करने से पहले ही apply करो: interviews दिखाते हैं कि क्या ठीक करना है।

## एक example से समझो

Coimbatore की backend developer Nandhini, जिनके पास दो साल का Java experience है, ये path सात महीने में पूरा करती हैं। नीचे के numbers एक illustration हैं, benchmark नहीं। आपका अपना funnel काफ़ी अलग दिख सकता है।

**Portfolio।** वो चार projects pin करती हैं, हर एक की पहली lines में result और उसका test set: document QA API, अपनी eval report के साथ enterprise RAG assistant, approval gates वाला operations agent, और एक काल्पनिक hospital chain के लिए capstone। Capstone case study तीन pages की है, साथ में दो minute का video। उसकी README साफ़ कहती है कि hospital काल्पनिक है और data synthetic। एक friend RAG assistant को उसकी README से आठ minutes में run कर लेता है।

**Resume और LinkedIn।** वो one-column resume पर आ जाती हैं, Java वाले काम को छोटे bullets में समेटती हैं और numbers के साथ एक "Projects" section जोड़ती हैं। उनकी LinkedIn headline उनकी GitHub profile से मेल खाती है।

**Timing और pay।** उनका appointment letter कहता है 90 दिन का notice, buyout company की मर्ज़ी पर। वो ये अपनी Naukri profile पर डालती हैं। उनका current CTC ₹7 lakh है। जो role वो चाहती हैं, उसके लिए 0 से 2 साल का FDE band ₹12 से 25 lakh है। AI काम में नई और Bengaluru से बाहर होने की वजह से वो खुद को band के निचले आधे हिस्से में रखती हैं, तो अपना expected CTC ₹15 से 17 lakh रखती हैं।

**दस हफ़्तों की search।** वो 40 target companies की list बनाती हैं और उनमें से 15 में alumni या contacts ढूँढती हैं।

| Channel | Applications | Replies | First rounds | Final loops | Offers |
| --- | --- | --- | --- | --- | --- |
| Cold (Naukri, LinkedIn) | 30 | 2 | 1 | 0 | 0 |
| Referral या contact | 15 | 6 | 5 | 3 | 2 |
| कुल | 45 | 8 | 6 | 3 | 2 |

उनकी sheet दो बातें दिखाती है। आठ में से छह replies referrals से आए। और तीसरे हफ़्ते में वो अपना पहला DSA online test fail हो गईं, तो उन्होंने हर recruiter से format पूछना शुरू किया और रोज़ 30 minutes, time लगाकर pattern के हिसाब से problems practise किए। अगले दोनों में वो pass हुईं।

**दो offers।** Hospitals को बेचने वाला एक AI startup एक forward deployed role offer करता है। Hiring manager कहते हैं कि उन्होंने capstone case study की वजह से ही call किया।

| Offer का हिस्सा | Startup, FDE | GCC, applied AI engineer |
| --- | --- | --- |
| Fixed pay | ₹15 lakh | ₹16 lakh |
| Variable pay | ₹1.5 lakh, अगर targets पूरे हों | कोई नहीं |
| Joining bonus | कोई नहीं | ₹1 lakh, एक साल के अंदर छोड़ने पर लौटाना होगा |
| Stock | ₹1.5 lakh सालाना के ESOPs | कोई नहीं |
| लिखा हुआ CTC | ₹18 lakh | ₹17 lakh |
| पहले साल में पक्का मिलने वाला cash | ₹15 lakh | ₹17 lakh |

Startup का CTC ज़्यादा है, पर पक्के cash में GCC ₹2 lakh ज़्यादा देता है। फिर भी Nandhini startup चुनती हैं, उस client-facing काम के लिए जो वो करना चाहती हैं, और ₹16 lakh fixed माँगती हैं। वो मान जाते हैं, लिखित में। उनकी handover पूरी होने पर उनकी company उन्हें 60 दिन बाद release कर देती है, और startup wait करने को तैयार हो जाता है।

## आम गलतियाँ

- **Tutorial clones।** Video देखकर बनाया PDF पर chatbot बहुत कम दिखाता है। एक real problem, evals और deployment जोड़ो।
- **Installation से शुरू होने वाली READMEs।** Problem और result से शुरुआत करो।
- **Numbers जिनका बचाव न कर सको।** बिना test set का result, या किसी काल्पनिक client का "business impact", project deep dive में टिकता नहीं।
- **Fancy two-column templates।** Screening software में ये बिगड़ सकते हैं। एक column use करो।
- **सिर्फ़ cold applications।** Referrals और बातचीत से आम तौर पर लगाए गए हर घंटे पर कहीं ज़्यादा replies मिलते हैं।
- **Coding practice छोड़ देना।** अगर आप पहले आने वाला online test fail कर गए तो strong portfolio काम नहीं आता।
- **अपना notice period छुपाना।** ये बाद में सामने आता है और offer खत्म कर देता है।
- **सिर्फ़ CTC पर offers की तुलना।** Variable pay, joining bonuses और stock पक्का cash नहीं हैं।

## Practice करो

Profile READMEs पर GitHub की guide और Tech Interview Handbook की resume guide पढ़ो।

**Check (इसे submit करो)।** एक GitHub profile README publish करो, इस path के कम से कम तीन projects pin करो और एक case-study write-up लिखो। हर project README problem, एक screenshot या छोटे video, और ऐसे result से शुरू हो जो अपना test set और उसका size बताए। एक reviewer को कम से कम एक project उसकी README से 10 minutes से कम में run कर पाना चाहिए। अपनी profile का link submit करो।

**अपनी search के लिए (check नहीं होगा, पर करो)।**

1. अपना resume एक column में, कम से कम चार result-based bullets के साथ दोबारा लिखो, और अपनी LinkedIn headline को अपनी GitHub profile से मिलाओ।
2. अपना appointment letter पढ़ो और अपना notice period और buyout terms लिख लो।
3. अपने target role के लिए Jobs page का band देखो और एक line की वजह के साथ अपना expected CTC लिखो।
4. 20 target companies की list बनाओ, हर एक में contact करने के लिए एक इंसान के साथ, और एक tracking sheet शुरू करो।

**आपका काम पूरा है जब आप** किसी अनजान इंसान को एक link भेज सको जो 60 seconds में दिखा दे कि आपने क्या बनाया, उससे क्या हासिल हुआ और वो number किस पर मापा गया।
