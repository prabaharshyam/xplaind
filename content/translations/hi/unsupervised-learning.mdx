## ये क्या है

**Unsupervised learning** उस data में patterns ढूँढता है जिस पर कोई labels नहीं होते। तीन common काम:

- **Clustering**: मिलते-जुलते records को group करना, जैसे customer segments या एक जैसे stores।
- **Dimensionality reduction**: कई features को कुछ ऐसे features में compress करना जो ज़्यादातर information बचाए रखें, visualisation, speed या simpler models के लिए। **PCA** इसका classic तरीका है।
- **Anomaly detection**: ऐसे records ढूँढना जो बाकियों से अलग दिखते हैं, जैसे unusual transactions या खराब sensors।

यहाँ मिलाने के लिए कोई "सही जवाब" नहीं होता, इसलिए नतीजा काम का है या नहीं, ये परखना भी काम का हिस्सा है।

```text
  basket size (scaled)
   ^
   |        o o              x x
   |      o  o o           x  x x      o = weekly family stock-up
   |       o o               x x       x = premium packaged
   |                                   + = daily fresh shoppers
   |   + + +                           * = a possible anomaly
   |  + + + +            *
   |   + +
   +----------------------------------> visits per month (scaled)
```

इस lesson में हम Kochi की एक supermarket chain के साथ चलेंगे, जो marketing के लिए अपने 400,000 loyalty-card customers को segments में बाँट रही है।

## ये काम कैसे करता है

**Features तैयार करो।** Unsupervised methods इस पर बहुत निर्भर करते हैं कि आप कौन-से features use करते हो और उन्हें कैसे scale करते हो। Numeric features को standardise करो; ध्यान से सोचो कि business के लिए "मिलता-जुलता" का मतलब क्या होना चाहिए।

**k-means clustering।** k चुनो, यानी clusters की संख्या। Algorithm k centres रखता है, हर record को सबसे पास वाले centre को देता है, centres को उनके records के बीच में ले जाता है, और दोहराता है। ये लगभग गोल, बराबर size वाले groups पर सबसे अच्छा चलता है। k को elbow method या silhouette scores से चुनो, पर ज़्यादातर इस पर कि clusters business के हिसाब से समझ में आते हैं या नहीं।

**दूसरे clustering methods।** DBSCAN किसी भी shape के clusters ढूँढता है और बिखरे points को noise label करता है; hierarchical clustering groupings का एक tree बनाता है; Gaussian mixtures soft memberships देते हैं।

**PCA।** नए axes ढूँढता है (original features के combinations) जो सबसे ज़्यादा variation पकड़ते हैं। पहले दो components का plot अक्सर groups या outliers दिखा देता है। जो components, मान लो, 90% variance समझाते हैं, उन्हें रखने से 50 features घटकर 10 हो सकते हैं।

**Anomaly detection।** Isolation Forest जैसे methods score देते हैं कि कोई record बाकियों से कितनी आसानी से अलग किया जा सकता है। Scores को review की priority तय करने में use करो, final फ़ैसले की तरह नहीं।

**नतीजे परखना।** हर cluster को उसके features के averages और असली examples से describe करो; उसे ऐसा नाम दो जो business user समझे; stability check करो (अलग sample के साथ दोबारा चलाने पर क्या clusters मिलते-जुलते रहते हैं?); और usefulness test करो (क्या segment के हिसाब से targeting करने से campaign सुधरता है?)।

**Method चुनना:**

| काम | Method | किसके लिए अच्छा |
| --- | --- | --- |
| बराबर size और shape वाले segments | k-means | Customer और store segments |
| अनियमित shapes, noise | DBSCAN | Location data, dense areas ढूँढना |
| Groupings का tree | Hierarchical clustering | छोटे datasets, structure explore करना |
| Soft membership | Gaussian mixtures | ऐसे customers जो आंशिक रूप से दो segments में आते हैं |
| Compress और visualise करना | PCA | कई features, quick plots |
| Unusual records ढूँढना | Isolation Forest | Transactions, sensors, data quality |

**मुश्किल हिस्सा है मतलब निकालना।** Algorithms हमेशा clusters दे देते हैं, random data में भी। असली काम है हर एक को averages और असली examples से describe करना, business team के साथ उसे नाम देना, और test से साबित करना कि वो काम का है। जिस cluster को कोई describe नहीं कर सकता या जिस पर action नहीं ले सकता, वो segment नहीं है।

**k को सिर्फ़ elbow से नहीं, सबूत से चुनो।**

```python
import numpy as np
from sklearn.datasets import make_blobs
from sklearn.preprocessing import StandardScaler
from sklearn.cluster import KMeans
from sklearn.metrics import silhouette_score, adjusted_rand_score

X, _ = make_blobs(n_samples=3000, centers=4, n_features=6, cluster_std=1.6, random_state=8)
Xs = StandardScaler().fit_transform(X)

for k in range(2, 8):
    labels = KMeans(n_clusters=k, n_init=10, random_state=8).fit_predict(Xs)
    print(k, "silhouette", round(silhouette_score(Xs, labels, sample_size=2000, random_state=8), 3))
```

**Segments को नाम देने से पहले stability check करो।**

```python
def stability(Xs, k, runs=5, frac=0.8, seed=0):
    rng = np.random.default_rng(seed)
    ref = KMeans(n_clusters=k, n_init=10, random_state=0).fit(Xs)
    scores = []
    for r in range(runs):
        idx = rng.choice(len(Xs), int(frac * len(Xs)), replace=False)
        other = KMeans(n_clusters=k, n_init=10, random_state=r + 1).fit(Xs[idx])
        scores.append(adjusted_rand_score(ref.predict(Xs[idx]), other.labels_))
    return round(float(np.mean(scores)), 3)

print("stability at k=4:", stability(Xs, 4), " at k=7:", stability(Xs, 7))
```

Adjusted Rand index 1 के पास हो तो मतलब वही records बार-बार साथ आ रहे हैं; बहुत कम values का मतलब है कि segments सिर्फ़ एक run का नतीजा हैं।

**Clusters को business की भाषा में describe करो।** Cluster labels को वापस original, unscaled columns से जोड़ो और summarise करो:

```python
import pandas as pd

def describe(df, labels):
    d = df.assign(cluster=labels)
    summary = d.groupby("cluster").agg(["mean", "median"]).round(1)
    summary["size"] = d.cluster.value_counts().sort_index()
    return summary
```

फिर हर cluster से दस असली records पढ़ो, उसके बाद उसे "weekend family shoppers" जैसा कोई नाम दो।

**Review queue के लिए anomaly scores।**

```python
from sklearn.ensemble import IsolationForest

iso = IsolationForest(n_estimators=300, contamination="auto", random_state=8).fit(Xs)
scores = -iso.score_samples(Xs)                  # higher = more unusual
queue = np.argsort(-scores)[:20]
print("top anomaly scores:", scores[queue][:5].round(3))
```

Top cases किसी इंसान को भेजो, उन features के साथ जो उन्हें अलग दिखाते हैं (जैसे हर value median से कितने standard deviations दूर है), और जो वो तय करें उसे record करो। वही फ़ैसले आगे चलकर supervised model के labels बनते हैं।

**पहली नज़र के लिए PCA।** `PCA(n_components=2).fit_transform(Xs)` plot करने के लिए coordinates देता है; `explained_variance_ratio_` बताता है कि दोनों axes variation का कितना हिस्सा पकड़ते हैं। अगर वो छोटा है, तो तस्वीर असली structure छिपा सकती है।

## एक example से समझो

Kochi की एक supermarket chain के 400,000 loyalty-card customers हैं, और उसे marketing के लिए segments चाहिए।

12 महीनों में हर customer के features: महीने में visits, rupees में औसत basket, fresh produce, packaged foods और household items पर खर्च का हिस्सा, weekend visits का हिस्सा और promotion पर हुई purchases का हिस्सा। सब standardised।

k-means, k को 3 से 10 तक चलाया; silhouette scores 6 और 7 के आसपास सबसे ऊँचे रहे। सात clusters बने, जिन्हें marketing team के साथ मिलाकर छह किया और नाम दिए:

1. Weekly family stock-up (बड़े baskets, weekends)
2. Daily fresh shoppers (बार-बार आने वाले, छोटे baskets, produce ज़्यादा)
3. Deal hunters (promotion का हिस्सा ज़्यादा)
4. Occasional top-up (कभी-कभार, छोटे baskets)
5. Premium packaged (बड़ा basket, imported brands)
6. Lapsing (पिछले महीनों में visits तेज़ी से घट रही हैं)

तीन महीने के test में हर segment के आधे लोगों को segment के हिसाब से offers भेजे गए। Response overall 3.1% से बढ़कर 4.6% हुआ, और "lapsing" segment के offers से उन customers में से 12% वापस आए। Segment label churn model के लिए भी एक काम का feature बन गया।

| Measure | Segments से पहले | Segment-specific offers के साथ |
| --- | --- | --- |
| Offer response rate | 3.1% | 4.6% |
| वापस लाए गए lapsing customers | नापा नहीं गया | 12% |
| अतिरिक्त use | कोई नहीं | Segment label churn model में feature बना |

**Marketing के साथ clusters को नाम देना।** k = 7 का पहला output सात columns के averages थे, जिन्हें data team के बाहर कोई पढ़ नहीं सकता था। एक घंटे की workshop में team ने marketing को हर cluster के averages के साथ उसमें से पाँच असली, anonymised customers दिखाए। Marketing ने segments को अपने शब्दों में नाम दिए और जहाँ ज़रूरी था वहाँ आपत्ति भी की। उन्होंने दो clusters मिला दिए जिन्हें algorithm ने weekend visits के एक छोटे से फ़र्क पर अलग किया था, क्योंकि वो दोनों groups के साथ एक जैसा ही बर्ताव करते। उस बातचीत के बाद ही छह clusters final segments बने। Team ने clustering एक नए तीन महीने के sample पर दोबारा भी चलाई। छह में से पाँच segments मिलते-जुलते sizes में फिर आए। छठा और सबसे छोटा segment छोटा होकर आया, इसलिए team उसे हर quarter दोबारा check करती है।

## आम गलतियाँ

- **Unscaled features।** बड़ी values वाले features distances पर हावी हो जाते हैं।
- **k सिर्फ़ एक score से चुनना।** Business meaning मायने रखता है।
- **Clusters को सच मान लेना।** वो एक काम का नज़रिया हैं, customers के बारे में कोई तथ्य नहीं।
- **Stability check न करना।** अस्थिर clusters हर बार दोबारा चलाने पर बदलते हैं।
- **Anomaly scores को फ़ैसला मानना।** इन्हें human review की priority तय करने में use करो।

- **ऐसे features पर clustering जिन पर action नहीं लिया जा सकता।** जिन segments की definition ऐसे data से बनी हो जिसे business targeting में use ही नहीं कर सकता, वो शायद ही कुछ बदलते हैं।
- **k सिर्फ़ elbow से चुनना**, stability या business meaning देखे बिना।
- **सिर्फ़ averages से clusters को नाम देना**, असली records पढ़े बिना।
- **Anomaly scores को फ़ैसला मान लेना**, जबकि वो बस review का order हैं।

## Unsupervised methods कब use न करें

- **जिस चीज़ की आपको परवाह है उसके labels आपके पास हैं**: supervised models सवाल का जवाब सीधे देते हैं।
- **Segments को fixed rules follow करने हों**, जैसे regulatory customer categories।
- **Records या features बहुत कम हैं** कि मतलब वाले groups बन सकें।

## Demo से production तक

- **Seeds fix करो और settings record करो**, ताकि segments दोबारा बन सकें।
- **नए segments release करने से पहले stability check करो।**
- **Schedule पर re-cluster करो** और नए clusters को पुराने नामों से सोच-समझकर map करो।
- **समय के साथ cluster sizes track करो**; बड़े बदलाव का मतलब है कि behaviour या data बदल गया।
- **Anomalies पर review के फ़ैसले** labels की तरह वापस feed करो।
