## ये क्या है

लोग अक्सर maths की वजह से machine learning टालते रहते हैं। आपको mathematician होने की ज़रूरत नहीं है। आपको तीन हिस्सों की **समझ** चाहिए, और जब कोई formula सामने आए तो उसे follow कर पाने की क्षमता:

| हिस्सा | मुख्य idea | ML में कहाँ दिखता है |
| --- | --- | --- |
| **Linear algebra** | Data को **vectors** (numbers की lists) और **matrices** (numbers की tables) की तरह देखना, और उन पर operations | Customer features का एक vector है; dataset एक matrix है; model के weights matrices हैं |
| **Calculus** | Input को थोड़ा हिलाने पर कोई quantity कैसे बदलती है | Models **gradient** के पीछे चलकर सीखते हैं, यानी उस दिशा में जिसमें error सबसे तेज़ी से गिरता है |
| **Probability** | Uncertainty को बताना | Models probabilities देते हैं; data के distributions होते हैं; evaluation पूछता है कि नतीजे टिकने की कितनी संभावना है |

```flow
dir: LR
Linear algebra | data और weights vectors और matrices की तरह: model क्या compute करता है -> Calculus | weights हिलने पर error कैसे बदलता है (gradients): वो कैसे सीखता है
Calculus -> Probability | हम कितने sure हैं? Outputs, base rates, Bayes: उसके output को कैसे पढ़ें और उस पर भरोसा करें
```

इस lesson में हम Hyderabad की एक fintech के साथ चलेंगे, जो एक simple loan-default model train करती है और मुश्किल तरीके से सीखती है कि scale और base rates क्यों मायने रखते हैं। Lesson के अंत तक आप एक sketch से gradient descent समझा पाओगे और बता पाओगे कि दुर्लभ घटनाओं पर ज़्यादातर false alarms क्यों आते हैं।

## ये काम कैसे करता है

### Vectors और similarity

**Vector** किसी एक चीज़ को बताने वाले numbers की list है। एक जैसी दिशा में इशारा करने वाले दो vectors मिलती-जुलती चीज़ें बताते हैं। **Dot product** मिलते हुए entries को गुणा करके जोड़ देता है:

```text
  a = (3, 1, 2)      b = (2, 0, 4)
  a . b = 3*2 + 1*0 + 2*4 = 6 + 0 + 8 = 14
```

बड़ा dot product मतलब मिलती-जुलती दिशा। **Cosine similarity** vectors की लंबाइयों से भाग देती है, ताकि सिर्फ़ दिशा गिनी जाए, size नहीं। Recommendation systems और embedding search इसी तरह "similar" नापते हैं।

### Matrices जो transform करते हैं

किसी vector को matrix से गुणा करने से वो transform होता है: घूमता है, खिंचता है या features मिल जाते हैं। Neural network की एक layer एक matrix multiplication होती है, जिसके बाद एक simple non-linear function आता है।

**Shapes मेल खानी चाहिए।** 100 rows और 20 columns वाला matrix, 20 weights के vector से गुणा होकर 100 predictions देता है:

```text
   data X            weights w        predictions
  (100 x 20)    x     (20 x 1)    =    (100 x 1)
       ^^                ^^
       these must be equal
```

Code में ज़्यादातर matrix bugs shape mismatch होते हैं। Shapes print करो।

### Derivatives और gradients

**Derivative** बताता है कि एक input थोड़ा बदलने पर output कितना बदलता है। कई inputs हों, तो **gradient** उन सब derivatives को एक vector में इकट्ठा कर देता है जो ऊपर की तरफ़ इशारा करता है।

**Gradient descent** model को **loss**, यानी error की माप, पर छोटे-छोटे कदम नीचे की ओर रखकर, बार-बार तब तक train करता है जब तक वो सुधरना बंद न कर दे:

```text
   loss
    |  *
    |    *                        too-large steps bounce around:
    |      *                          *       *
    |        *  *                    *   *   *   *
    |            * * * * --           (never settles)
    +--------------------------> steps
          small, steady steps
```

**Learning rate** कदम का size है। बहुत बड़ा हो तो training इधर-उधर उछलती है या फट जाती है; बहुत छोटा हो तो रेंगती है। Loss curve देखो और adjust करो।

### Chain rule और backpropagation

Neural networks कई functions को एक-पर-एक रखते हैं। **Chain rule** बताता है कि बीच की सारी layers से होते हुए आखिरी error शुरुआती weights पर कैसे निर्भर करता है। **Backpropagation** chain rule को कुशलता से लगाना है, जिससे बड़े networks को train करना संभव होता है।

### Probability

- **Probability distribution** बताता है कि हर value कितनी likely है।
- **Expected value** लंबे समय का औसत है।
- **Conditional probability**, जैसे "income ₹25,000 से कम होने पर default की probability", classification का दिल है।
- **Bayes' rule** सबूत के साथ अपनी मान्यताएँ update करता है, और समझाता है कि सही tests के साथ भी दुर्लभ घटनाएँ बहुत सारे false alarms क्यों देती हैं।

### Scaling

अगर एक feature 400 तक जाता है और दूसरा 1 से नीचे रहता है, तो gradient descent टेढ़ा-मेढ़ा चलता है और धीमी या अस्थिर training करता है। Features को **standardise** करना, ताकि हर एक की range मिलती-जुलती हो, कई models को तेज़ और बेहतर train होने में मदद करता है।

| Feature | कच्ची range | Standardise करने के बाद |
| --- | --- | --- |
| Income में EMI का हिस्सा | 0.05 से 0.9 | लगभग -2 से +2 |
| पिछले साल छूटी payments | 0 से 12 | लगभग -2 से +2 |
| मौजूदा नौकरी में महीने | 1 से 400 | लगभग -2 से +2 |

## एक example से समझो

Hyderabad की एक fintech एक simple model से monthly EMI default risk predict करती है:

```text
score = w1 x (EMI / income) + w2 x (missed payments last year)
      + w3 x (months at current job) + b
```

**Vectors और weights।** हर applicant तीन features का एक vector है। Weights w1, w2, w3 और b मिलकर model बनाते हैं।

**Training।** वो random weights से शुरू करता है, 50,000 पुराने loans के लिए predict करता है, loss नापता है (predictions असल में जो हुआ उससे कितनी दूर हैं), gradient निकालता है (हर weight के साथ loss कैसे बदलता है), और हर weight को नीचे की ओर थोड़ा खिसकाता है। कुछ सौ steps के बाद loss गिरना बंद हो जाता है।

**पहली problem: scale।** शुरू में training अस्थिर थी: loss इधर-उधर उछल रहा था। "Months at job" 400 तक जाता था, जबकि EMI ratio 1 से नीचे था, इसलिए एक weight को बहुत छोटे कदम चाहिए थे और दूसरे को बड़े। तीनों features को standardise करने से ये ठीक हो गया।

**दूसरा सबक: base rates।** मान लो 2% applicants default करते हैं, model 90% defaulters पकड़ता है, और 10% अच्छे applicants को गलती से flag करता है। 1,000 applicants में:

| | Default करेंगे | Default नहीं करेंगे | कुल |
| --- | --- | --- | --- |
| Count | 20 | 980 | 1,000 |
| Model से flag हुए | 18 (20 का 90%) | 98 (980 का 10%) | 116 |
| Flag नहीं हुए | 2 | 882 | 884 |

Flag हुए 116 applicants में से सिर्फ़ 18, लगभग छह में से एक, असल में default करेंगे। ज़्यादातर flags झूठे alarms हैं, बस इसलिए कि अच्छे applicants कहीं ज़्यादा आम हैं। इसीलिए bank score को **review की प्राथमिकता तय करने** के लिए use करता है, अपने-आप reject करने के लिए नहीं।

## आम गलतियाँ

- **पहले सारी maths में महारत पाने की कोशिश करना।** पहले समझ बनाओ, फिर ज़रूरत के हिसाब से गहरे जाओ।
- **Shapes को नज़रअंदाज़ करना।** ज़्यादातर matrix bugs shape mismatches होते हैं; shapes print करो।
- **Learning rate का अंदाज़ा लगाना।** Loss curve देखो और adjust करो।
- **Unscaled features।** Gradient-based models के लिए standardise करो।
- **Base rates को नज़रअंदाज़ करना।** दुर्लभ घटनाएँ और अधूरे models मिलकर बहुत सारे false alarms देते हैं।
- **Probability को पक्की बात समझना।** 0.8 score का मतलब likely है, पक्का नहीं।
