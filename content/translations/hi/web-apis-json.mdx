## ये क्या है

आपके program को सब कुछ खुद जानने की ज़रूरत नहीं। **Web API** उसे internet पर किसी दूसरी service से data या actions माँगने देता है: आज का मौसम, map का route, किसी payment का status, सरकारी open data, या किसी AI model का जवाब। हर AI model provider इसी तरह काम करता है, इसलिए Python से API call करना वो मुख्य skill है जिस पर आगे language models को call करना टिका है।

आप किसी URL पर एक **HTTP request** भेजते हो। Service जवाब में देती है:

- एक **status code**: काम हुआ या नहीं?
- आमतौर पर **JSON** में एक body: यानी data।

```flow
dir: LR
आपका Python program | requests.get(...) -[GET /weather?city=Chennai, header X-API-Key]-> Weather service
Weather service -[200 OK, JSON body]-> r.json() | city: "Chennai", temp_c: 31.5
```

इस lesson में हम Anita के साथ चलेंगे, जो अपने शहर के लिए एक छोटा air-quality dashboard बना रही है। Lesson के अंत तक आप public API call कर पाओगे, status check कर पाओगे और nested JSON सुरक्षित तरीके से पढ़ पाओगे।

## ये काम कैसे करता है

### requests library

```python
import requests

r = requests.get("https://api.example.com/weather",
                 params={"city": "Chennai"}, timeout=10)
print(r.status_code)
data = r.json()          # JSON text becomes Python dictionaries and lists
print(data["temp_c"])
```

`params` URL में query parameters जोड़ता है, इसलिए ये request `.../weather?city=Chennai` पर जाती है।

### Status codes

| Code | मतलब | क्या करें |
| --- | --- | --- |
| `200` | OK: काम हो गया | Data use करो |
| `400` | Bad request: आपकी request में कुछ गलत है | Parameters और body check करो |
| `401` / `403` | Sign in नहीं है, या इजाज़त नहीं | API key और permissions check करो |
| `404` | नहीं मिला | URL या item id check करो |
| `429` | बहुत ज़्यादा requests | धीमे चलो; रुककर retry करो |
| `500` से `504` | Server फ़ेल हो गया | अक्सर अस्थायी; बाद में retry करो |

Data use करने से पहले check करो। `r.raise_for_status()` 4xx और 5xx codes पर error उठाता है, ताकि आपका code error reply को data समझकर आगे न बढ़े।

### Python में JSON

`r.json()` reply को dictionaries (JSON objects के लिए) और lists (JSON arrays के लिए) में बदल देता है। Nested values को एक-एक step में पढ़ो:

```python
data["current"]["temp_c"]          # an object inside an object
data["results"][0]["location"]     # the first item of a list
```

जो code reply पढ़ेगा उसे लिखने से पहले, हमेशा पूरा reply एक बार print करो, ताकि उसकी असली shape दिखे।

### Parameters, headers और bodies

| Part | किसलिए | Example |
| --- | --- | --- |
| `params` | URL पर query parameters | `params={"city": "Pune"}` |
| `headers` | Keys, content type और बाकी metadata | `headers={"Authorization": "Bearer ..."}` |
| `json` | आपकी भेजी हुई JSON body, आमतौर पर POST के साथ | `requests.post(url, json={"text": "..."})` |

### Timeouts

`timeout=` के बिना, किसी धीमे या टूटे server की request **हमेशा के लिए** अटक सकती है, और आपका program या पूरा automation freeze हो सकता है। हमेशा एक लगाओ, और `requests.Timeout` को संभालो।

### Keys और secrets

API keys कभी उस code में मत लिखो जिसे share या commit करो। उन्हें environment variable से पढ़ो:

```python
import os
key = os.environ["AQ_KEY"]
```

### सुरक्षित तरीके से retry करना

कुछ failures अपने आप ठीक हो जाते हैं। `429` या `503` अक्सर कुछ seconds बाद चल जाता है। एक सीधा, शिष्ट retry ऐसा दिखता है:

```python
import time

for attempt in range(3):
    r = requests.get(url, params=params, timeout=10)
    if r.status_code not in (429, 500, 502, 503, 504):
        break
    retry_after = r.headers.get("Retry-After", "")
    wait = int(retry_after) if retry_after.isdigit() else 2 ** attempt
    time.sleep(wait)
```

ये सिर्फ़ उन errors को retry करता है जो likely अस्थायी हैं, हर बार ज़्यादा इंतज़ार करता है, और server अगर `Retry-After` header भेजे तो उसे मानता है। `401` या `404` को कभी retry मत करो: request ही गलत है, और दोहराने से कुछ नहीं बदलता।

### API documentation पढ़ना

हर API की documentation इन्हीं सवालों के जवाब देती है, आमतौर पर इसी क्रम में: **base URL**, **authenticate** कैसे करें (कौन-सा header key ले जाता है), **endpoints** (`/latest` या `/holidays` जैसे paths), हर endpoint के **parameters**, एक **example response**, उसके **error codes**, और **rate limits**। Code लिखने से पहले ये sections पढ़ो, और example response को एक file में copy कर लो ताकि हर बार API call किए बिना अपना parsing test कर सको। आगे किसी AI model की API call करना बिल्कुल यही process है: endpoint ढूँढो, header में key भेजो, JSON body post करो और JSON reply पढ़ो।

### Limits और cost

ज़्यादातर APIs प्रति मिनट requests की limit रखती हैं और कुछ हर call पर पैसे लेती हैं। Documentation का limits वाला section पढ़ो, और `429` मिले तो server पर हथौड़ा चलाने की जगह बढ़ते delays के साथ रुककर retry करो।

## एक example से समझो

Anita अपने शहर की air quality का एक छोटा dashboard बना रही है। वो एक public API use करती है जो किसी location की current readings देती है।

```python
import os, requests

url = "https://api.airquality.example/v1/latest"
r = requests.get(url, params={"city": "Delhi"},
                 headers={"X-API-Key": os.environ["AQ_KEY"]}, timeout=10)

if r.status_code == 200:
    for reading in r.json()["results"][:5]:
        print(reading["location"], reading["parameter"], reading.get("value", "no reading"))
elif r.status_code == 429:
    print("Rate limited; try again in a minute")
else:
    print("Request failed:", r.status_code, r.text[:200])
```

(यहाँ URL सिर्फ़ समझाने के लिए है; lesson का resource असली, चलने वाले examples दिखाता है।)

| Run | क्या हुआ | कारण | Fix |
| --- | --- | --- | --- |
| 1 | `401 Unauthorized` | नए terminal में उसकी key set नहीं थी | चलाने से पहले `export AQ_KEY=...` |
| 2 | `200`, फिर एक location पर `KeyError: 'value'` | कुछ locations में `value` field नहीं है | पूरा JSON print किया; `.get("value", "no reading")` use किया |
| 3 | कई मिनट अटका रहा | Testing के दौरान उसने `timeout=` हटा दिया था | `timeout=10` वापस लगाया |
| 4 | पाँच readings print हुईं | चल रहा है | Dashboard के लिए तैयार |

दूसरे run में पूरा JSON एक बार print करने से उसका एक घंटे का अंदाज़ा लगाना बच गया।

## आम गलतियाँ

- **Status code check न करना।** फिर code error replies पर उलझाने वाले ढंग से fail होता है।
- **Timeout न लगाना।** धीमा server आपका program अटका सकता है।
- **JSON की shape का अंदाज़ा लगाना।** पहले उसे print करके पढ़ो।
- **Code में API keys।** Environment variables use करो।
- **Rate limits को अनदेखा करना।** उन्हें मानो, वरना block हो जाओगे।
- **ये मान लेना कि हर field हमेशा मौजूद होगी।** Optional fields के लिए default के साथ `.get()` use करो।
