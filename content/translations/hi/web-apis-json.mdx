## ये क्या है

एक **web API** आपके program को internet पर किसी दूसरी service से data या actions माँगने देता है: air quality, map का route, किसी payment का status, सरकारी open data, या किसी AI model का जवाब। हर AI model provider तक इसी तरह पहुँचा जाता है, इसलिए आगे language models को call करने के पीछे यही core skill है।

आपका program एक URL पर एक **HTTP request** भेजता है। Service इसके साथ reply करती है:

- एक **status code**, तीन अंकों का एक number जो बताता है कि काम हुआ या नहीं;
- आमतौर पर **JSON** में एक **body**, यानी objects (`{"key": value}`) और lists (`[1, 2, 3]`) वाला एक text format, जिसे Python dictionaries और lists में बदल देता है।

```flow
title: एक API call, शुरू से आख़िर तक
dir: LR
आपका code | session.get(url, params, timeout) -[GET, key X-API-Key header में]-> API server
API server -[status code और JSON body]-> Status check करो
Status check करो -[2xx]-> r.json() | dicts और lists
Status check करो -[429 या 5xx]-> Wait करो और retry करो
Status check करो -[बाकी 4xx]-> Request ठीक करो
```

इस lesson में हम Delhi की एक student, Anita, के साथ चलेंगे, जो एक छोटा air-quality dashboard बना रही है। वो **OpenAQ** use करती है, एक non-profit platform जो दुनिया भर से, Indian monitoring stations समेत, air-quality readings इकट्ठा करता है। इसके API के लिए एक free key चाहिए, इसलिए पूरा routine practise करने के लिए ये एक अच्छी जगह है: key, timeout, status, JSON, retries और pages।

## ये काम कैसे करता है

### Request के हिस्से

हर API की documentation requests को इन्हीं हिस्सों में बताती है:

| हिस्सा | ये क्या है | `requests` में | OpenAQ example |
| --- | --- | --- | --- |
| Base URL | वो address जिससे सारी calls शुरू होती हैं | URL का हिस्सा | `https://api.openaq.org/v3` |
| Endpoint | एक तरह के data का path | URL का हिस्सा | `/locations/8118/latest` |
| Query parameters | URL में `?` के बाद जोड़े गए filters | `params={...}` | `iso=IN`, `limit=100`, `page=2` |
| Headers | Metadata, key समेत | `headers={...}` | `X-API-Key: your key` |
| Body | आपका भेजा हुआ data, आमतौर पर POST के साथ | `json={...}` | data पढ़ने के लिए ज़रूरी नहीं |

`params={"iso": "IN"}` URL पर `?iso=IN` बन जाता है; `requests` spaces और special characters को escape भी करता है। JSON body भेजने के लिए `json=` use करो (`data=` नहीं): ये आपकी dictionary को convert करता है और सही content type set करता है।

### आपकी पहली call

```python
import os
import requests

BASE = "https://api.openaq.org/v3"
key = os.environ["OPENAQ_API_KEY"]

r = requests.get(f"{BASE}/locations/8118/latest",
                 headers={"X-API-Key": key}, timeout=(5, 20))
print(r.status_code)          # 200 if it worked
r.raise_for_status()          # stop here on any 4xx or 5xx
data = r.json()               # JSON text becomes dicts and lists
print(list(data))             # ['meta', 'results']
```

Location 8118 New Delhi का एक station है जिसे OpenAQ अपने quick start में ख़ुद use करता है। इस छोटे-से block में पहले से तीन आदतें हैं:

- **Key एक environment variable से आती है**, इसलिए वो code में कभी नहीं दिखती।
- **Timeout है।** `(5, 20)` का मतलब है connect होने के लिए 5 seconds तक और server के data भेजने के लिए 20 seconds तक wait करो।
- **`raise_for_status()`, `r.json()` से पहले चलता है।** Error reply data नहीं है, और उसे data मानने से तीन lines बाद confusing failures आते हैं।

### Status codes

पहला अंक बताता है कि problem किसकी है: **2xx** काम हो गया, **4xx** आपकी request गलत है, **5xx** server fail हुआ।

| Code | मतलब | क्या करें | Retry? |
| --- | --- | --- | --- |
| `200` | OK | Data use करो | — |
| `400` | Bad request | Parameters और body check करो | नहीं |
| `401` | Unauthorized: key नहीं है, गलत है या expire हो गई | Key और वो header check करो जिसमें वो जाती है | नहीं |
| `403` | Forbidden: key valid है पर इसकी permission नहीं | अपना plan या permissions check करो | नहीं |
| `404` | Not found | URL path और item id check करो | नहीं |
| `422` | Unprocessable: request validation में fail हुई | Body में error detail पढ़ो | नहीं |
| `429` | Too many requests | Wait करो, फिर और धीरे retry करो | हाँ |
| `500`, `502`, `503`, `504` | Server या कोई proxy fail हुआ | Wait करो, फिर retry करो | हाँ |

याद रखने का एक काम का तरीका: **401 पूछता है "आप कौन हो?", 403 कहता है "मुझे पता है आप कौन हो, और जवाब है ना।"** 401 का fix key है; 403 का fix आपका account या plan है। कई Python APIs, जिनमें FastAPI framework से बने APIs भी हैं, कोई field missing हो या उसका type गलत हो तो 422 return करते हैं, और body बताती है कि कौन-सा field।

### JSON पढ़ना

Reply को पढ़ने वाला code लिखने से पहले, उसे एक बार अच्छे से format करके print करो:

```python
import json
print(json.dumps(data, indent=2)[:1500])
```

Latest-readings endpoint से आए एक reply को छोटा करें तो उसका shape ऐसा होता है (shape OpenAQ की documentation के हिसाब से है; values बनाई हुई हैं):

```json
{
  "meta": {"name": "openaq-api", "page": 1, "limit": 100, "found": 2},
  "results": [
    {"datetime": {"utc": "2026-11-28T05:00:00Z", "local": "2026-11-28T10:30:00+05:30"},
     "value": 182.0, "sensorsId": 1001, "locationsId": 8118,
     "coordinates": {"latitude": 28.63, "longitude": 77.2}},
    {"datetime": {"utc": "2026-11-28T05:00:00Z", "local": "2026-11-28T10:30:00+05:30"},
     "value": 301.0, "sensorsId": 1002, "locationsId": 8118,
     "coordinates": {"latitude": 28.63, "longitude": 77.2}}
  ]
}
```

इसे बाहर से अंदर की तरफ़ पढ़ो। Curly braces एक dictionary हैं, इसलिए आप string key use करते हो। Square brackets एक list हैं, इसलिए आप 0 से गिनती करके एक number use करते हो।

```python
data["results"][0]["value"]               # 182.0
data["results"][0]["datetime"]["local"]   # '2026-11-28T10:30:00+05:30'
[row["value"] for row in data["results"]] # [182.0, 301.0]
```

जो दो errors आपको सबसे ज़्यादा दिखेंगे, उनमें से हर एक किसी एक गलती की तरफ़ इशारा करता है:

- `TypeError: list indices must be integers or slices, not str` का मतलब है आपने list पर string key लगाई। जैसे, `data["results"]["value"]` fail होता है क्योंकि `results` एक list है। कोई item चुनो (`[0]`) या loop करो।
- `KeyError: 'value'` का मतलब है उस dictionary में ऐसी कोई key नहीं है। Spelling check करो, या फिर वो field optional है।

Optional fields के लिए, key **missing** हो तो `row.get("value", 0)` `0` return करता है। पर कई APIs key को `null` के साथ भेजते हैं, जिसे Python `None` पढ़ता है, और तब `.get` आपका default नहीं, `None` return करता है। दोनों cases cover करने के लिए `row.get("value") or 0` लिखो। ध्यान रहे: `or` एक असली `0` को भी replace कर देता है, इसलिए जिन numbers में zero का मतलब होता है, वहाँ इसकी जगह `is None` test करो।

### जब body JSON न हो

जब body JSON नहीं होती तो `r.json()` `requests.JSONDecodeError` raise करता है, और ऐसा आपकी उम्मीद से ज़्यादा होता है। `502` या `503` अक्सर API के आगे लगे किसी proxy या load balancer से आता है, और उसकी body एक HTML error page होती है। कुछ services `200` के साथ HTML maintenance page return करती हैं। Decoding fail हो तो `r.text` के पहले 200 characters print करो ताकि दिखे क्या आया; worked example का helper यही करता है।

### Timeouts

Default में `requests` का कोई timeout नहीं होता, इसलिए कभी जवाब न देने वाले server को की गई call हमेशा wait कर सकती है और nightly job को freeze कर सकती है। हमेशा `timeout=` दो। `timeout=10` जैसा एक single number दोनों limits set करता है। `(5, 20)` जैसा pair **connect** limit (server तक पहुँचना) और **read** limit (data का wait करना) अलग-अलग set करता है।

एक gotcha: read limit अगले data के टुकड़े के लिए सबसे लंबा wait है, पूरे download की limit नहीं। जो server हर कुछ seconds में थोड़ा-सा data भेजता रहे, वो एक call को 20 seconds से कहीं ज़्यादा देर तक ज़िंदा रख सकता है। जब timeout सच में fire होता है, तो `requests` `requests.Timeout` raise करता है; उसे catch करो और retry करो या साफ़-साफ़ report करो।

### Keys और secrets

जो code आप share या commit करते हो उसमें API keys कभी मत लिखो। Key अपने terminal में set करो (Linux या macOS पर `export OPENAQ_API_KEY=...`; Windows PowerShell में `$env:OPENAQ_API_KEY="..."`) और उसे `os.environ["OPENAQ_API_KEY"]` से पढ़ो।

अगर वो line `KeyError: 'OPENAQ_API_KEY'` raise करे, तो कोई request भेजी ही नहीं गई: variable **इस** terminal में set नहीं है। नया terminal वो variable याद नहीं रखता जो आपने किसी दूसरे terminal में set किया था। इसके उलट, `401` का मतलब है request गई और server ने key reject कर दी या उसे ढूँढ नहीं पाया। दो और rules: key को कभी print या log मत करो, और अगर वो कभी किसी public repository में पहुँच जाए, तो तुरंत नई key बनाओ और पुरानी delete करो।

### सुरक्षित तरीके से retry करना

कुछ failures कुछ seconds बाद ख़ुद ठीक हो जाते हैं: timeouts, टूटे connections, `429` और `5xx`। बाकी कभी ठीक नहीं होंगे: `401` या `404` को बिना कुछ बदले retry करने से बस वही गलती दोहराई जाती है। एक अच्छा retry:

- सिर्फ़ उन failures को retry करता है जिनके temporary होने की संभावना ज़्यादा है;
- हर बार ज़्यादा देर wait करता है (**exponential backoff**: 1, 2, 4 seconds), और server `Retry-After` header भेजे तो उसका पालन करता है;
- कुछ tries के बाद हार मानकर एक साफ़ error raise करता है, error reply के साथ आगे नहीं बढ़ता।

**GETs को खुलकर retry करो, पर POST को retry करने से पहले सोचो।** GET सिर्फ़ पढ़ता है, इसलिए उसे दोहराने में कोई नुकसान नहीं। POST अक्सर कुछ *बनाता* है: एक payment, एक order, एक message। अगर पहली attempt server तक पहुँच गई पर reply वापस आते हुए खो गया, तो बिना सोचे किया गया retry उसे दो बार बना देता है। Stripe जैसे payment APIs इसे एक **idempotency key** से हल करते हैं: एक unique id जो आप एक बार बनाते हो और उसी request के हर retry के साथ header में भेजते हो, ताकि server को पता चले कि ये repeat है।

```python
import uuid

key = str(uuid.uuid4())                       # make it once, before the first try
headers = {"Idempotency-Key": key}            # send the same key on every retry
```

अगर कोई API ऐसी key नहीं देता, तो उसकी POSTs को auto-retry मत करो; दोबारा try करने से पहले check करो कि पहली वाली काम कर गई या नहीं।

### Pagination

List endpoint शायद ही कभी सब कुछ एक साथ return करता है। वो एक बार में एक **page** return करता है, और आप अगला माँगते हो। OpenAQ `page` और `limit` parameters use करता है (default `limit` 100 है) और total `meta.found` में बताता है। दूसरे APIs इसकी जगह एक `next` URL या cursor return करते हैं; documentation बताती है कौन-सा।

चुपचाप होने वाला failure है सिर्फ़ page 1 पढ़ना। Code चलता है, 100 results दिखाता है और सही लगता है। अगर कोई count 100 या 1000 जैसे round number में आए, तो सबसे पहले pagination पर शक करो।

अपनी loop condition के लिए total पर भरोसा मत करो। बड़े sets के लिए OpenAQ का `found` `">1000"` जैसी string हो सकता है, जिससे arithmetic टूट जाता है। इसकी जगह, जब कोई page `limit` से छोटा या खाली आए तब रुको, और safety net के तौर पर pages की गिनती पर cap लगाओ (नीचे `get_all` देखो)।

### Limits और cost

ज़्यादातर APIs प्रति minute या प्रति दिन requests limit करते हैं, और paid APIs, language-model APIs समेत, use के पैसे लेते हैं। कई APIs ऐसे headers भेजते हैं जो बताते हैं कि आप कहाँ खड़े हो; OpenAQ `x-ratelimit-remaining` और `x-ratelimit-reset` भेजता है, और limit पार करने पर `429` return करता है। 500 cities पर loop करने से पहले documentation का limits page पढ़ो, calls के बीच एक छोटा `time.sleep` जोड़ो, और जो results दोबारा use करोगे उन्हें फिर से fetch करने की जगह cache करो।

### API documentation पढ़ना

Code लिखने से पहले documentation में ये ढूँढो: **base URL**, **authenticate** कैसे करना है, **endpoints** और उनके **parameters**, एक **example response**, **error codes**, **pagination** और **rate limits**। Example response को एक file में save कर लो ताकि हर बार API call किए बिना अपनी parsing test कर सको। आगे AI model को call करना भी यही routine है।

## एक example से समझो

Anita को दो चीज़ें चाहिए: हर उस Indian station की list जो OpenAQ को पता है, और Delhi के एक station की latest readings। वो एक छोटा helper बनाती है जिससे होकर हर call जाती है, ताकि timeout, retries, logging और error checks एक ही जगह रहें।

```python
import logging
import os
import time

import requests

logging.basicConfig(level=logging.INFO)
log = logging.getLogger("aq")

BASE = "https://api.openaq.org/v3"
RETRYABLE = {429, 500, 502, 503, 504}

session = requests.Session()                      # reuses connections
session.headers["X-API-Key"] = os.environ["OPENAQ_API_KEY"]

def get_json(path, params=None, tries=4):
    for attempt in range(tries):
        last = attempt == tries - 1
        wait = 2 ** attempt                       # 1, 2, 4 seconds
        try:
            r = session.get(BASE + path, params=params, timeout=(5, 20))
        except (requests.Timeout, requests.ConnectionError) as e:
            log.warning("%s: %s (try %d)", path, type(e).__name__, attempt + 1)
            if last:
                raise
            time.sleep(wait)
            continue
        if r.status_code in RETRYABLE and not last:
            ra = r.headers.get("Retry-After", "")
            wait = int(ra) if ra.isdigit() else wait
            log.warning("%s: %d, retry in %ds", path, r.status_code, wait)
            time.sleep(min(wait, 60))
            continue
        r.raise_for_status()                      # 4xx, or still failing
        try:
            return r.json()
        except requests.JSONDecodeError:
            raise RuntimeError(f"not JSON: {r.text[:200]!r}") from None
```

हर हिस्सा क्यों है:

- **`Session`** connection को reuse करता है, जो बहुत सारी calls के लिए ज़्यादा तेज़ है, और key वाला header रखता है ताकि कोई call उसे भूले नहीं।
- **Timeouts और connection errors catch करके retry किए जाते हैं**, क्योंकि यही सबसे आम temporary failure हैं। आख़िरी try पर error raise होता है, छिपाया नहीं जाता।
- **आख़िरी try के बाद कोई sleep नहीं**, और wait 60 seconds पर cap है, ताकि कोई अजीब `Retry-After` value job को एक घंटे तक न रोक दे।
- **जो reply retry नहीं होता, उस हर reply पर `raise_for_status()` चलता है**, ताकि `401`, `404`, या कभी ठीक न हुआ `503` program को एक साफ़ message के साथ रोक दे।
- **हर failure path और status के साथ log होता है**, जो आपको तब चाहिए जब कोई nightly job रात 3 बजे fail हो।

फिर दोनों tasks:

```python
def get_all(path, params, limit=100, max_pages=50):
    rows = []
    for page in range(1, max_pages + 1):
        data = get_json(path, {**params, "limit": limit, "page": page})
        batch = data["results"]
        rows.extend(batch)
        if len(batch) < limit:                    # short or empty page
            break
    return rows

stations = get_all("/locations", {"iso": "IN"})
print(len(stations), "stations")
for s in stations[:3]:
    print(s["id"], s["name"])

latest = get_json("/locations/8118/latest")
for row in latest["results"]:
    print(row["sensorsId"], row["value"], row["datetime"]["local"])
```

हर `sensorsId` station का एक instrument है, जैसे उसका PM2.5 या NO2 sensor। एक अलग endpoint, `/locations/8118/sensors`, बताता है कि हर एक कौन-सा pollutant measure करता है। ऐसे दो endpoints को जोड़ना API का आम काम है।

उसके पहले runs ऐसे गए:

| Run | उसे क्या दिखा | वजह | Fix |
| --- | --- | --- | --- |
| 1 | `KeyError: 'OPENAQ_API_KEY'`, कोई request नहीं गई | उसने नया terminal खोला था और वहाँ variable set नहीं था | उस terminal में variable set किया, फिर दोबारा चलाया |
| 2 | `401 Client Error: Unauthorized` | उसने किसी दूसरे API के tutorial से `Authorization: Bearer ...` copy किया था | Key को `X-API-Key` में भेजा, जैसा OpenAQ के docs कहते हैं |
| 3 | `TypeError: list indices must be integers or slices, not str` | उसने `latest["results"]["value"]` लिखा; `results` एक list है | Shape print किया, फिर list पर loop किया |
| 4 | पूरे India के लिए ठीक 100 stations | उसने `/locations` को एक बार call किया और सिर्फ़ page 1 पढ़ा | Pages पर loop करने के लिए `get_all` लिखा |
| 5 | एक log line `429, retry in 1s`, फिर पूरी list | तेज़ी से paging करने पर rate limit लग गई | कुछ नहीं: helper ने wait किया और आगे बढ़ गया |

Runs 1 से 3 में हर एक ने अलग error type दिया, और हर type सीधे अपनी वजह की तरफ़ इशारा करता था। Code दोबारा पढ़ने से पहले error का पहला शब्द पढ़ो।

जब script बड़ी हो जाए, तो retry का काम उस library को दे सकते हो जिस पर `requests` बना है। ये एक आम production setup है:

```python
import requests
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

retry = Retry(total=4, backoff_factor=1,
              status_forcelist=[429, 500, 502, 503, 504],
              allowed_methods=["GET"])        # never auto-retry POST
session = requests.Session()
session.mount("https://", HTTPAdapter(max_retries=retry))
```

ये back off करता है, 429 और 503 पर `Retry-After` का पालन करता है, और connection errors आपके लिए retry करता है। जब किसी listed status पर tries ख़त्म हो जाएँ, तो ये आख़िरी reply return करने की जगह `requests.exceptions.RetryError` raise करता है, इसलिए उसे भी catch करो। हर call पर timeout, एक JSON check और एक page loop आपको अब भी चाहिए।

## आम गलतियाँ

- **Status check करने से पहले data पढ़ना।** तब error reply कुछ lines बाद confusing तरीके से fail होता है। पहले `raise_for_status()` call करो।
- **कोई timeout नहीं।** एक चुप server पूरा program hang कर देता है।
- **JSON का shape अंदाज़े से मानना।** एक बार `json.dumps(data, indent=2)` से print करो, फिर access path लिखो।
- **List पर string key।** यही ऊपर वाला `TypeError` है; कोई index चुनो या loop करो।
- **`null` values के साथ `.get(key, default)` पर भरोसा करना।** Key `null` के साथ मौजूद हो तो ये `None` return करता है।
- **सिर्फ़ page 1 पढ़ना।** 100 जैसा round count ख़तरे का निशान है।
- **सब कुछ retry करना, या बहुत तेज़ी से करना।** `401` या `404` को retry करने से calls बर्बाद होती हैं, tight loop आपको block करवा देता है, और idempotency key के बिना POST retry करने से customer से दो बार पैसे कट सकते हैं।
- **Code, screenshots या logs में keys।** Environment variables use करो, और key leak हो तो तुरंत बदल दो।

## Practice करो

नीचे linked requests library का quickstart पढ़ो, फिर इनमें से कोई एक असली API use करो (दोनों November 2026 तक check किए गए):

- **OpenAQ**: Indian शहरों का air-quality data। इसके लिए इसकी website से एक free key चाहिए, जो `X-API-Key` header में भेजी जाती है।
- **Open-Meteo**: weather और air-quality forecasts। इसे key नहीं चाहिए और non-commercial use के लिए free है, इसलिए पहली call के लिए ये सबसे तेज़ रास्ता है।

1. **Call करो और देखो।** एक endpoint call करो, reply को `json.dumps(data, indent=2)` से print करो, और तीन values के access paths लिखो, जिनमें से कम से कम एक किसी list के अंदर हो।
2. **जान-बूझकर fail करवाओ।** गलत key, गलत path और `timeout=0.001` भेजो। हर एक का exact error note करो, और check करो कि आपका code `r.json()` पर crash होने की जगह एक साफ़ message print करता है।
3. **Helper जोड़ो।** हर call के आगे `get_json` helper लगाओ और confirm करो कि वो log और retry करता है।
4. **हर page पढ़ो।** किसी list endpoint के लिए page cap के साथ सारे pages fetch करो, और अपना count सिर्फ़ page 1 वाले count से compare करो।
5. **Key secure करो।** उसे environment variable में ले जाओ, नया terminal खोलो और confirm करो कि आपको पता है कि उसके set न होने पर क्या होता है।

**आपका काम पूरा है जब आप** key और timeout के साथ API call कर सको, सिर्फ़ error देखकर बता सको कि failure आपका है या server का, nested JSON बिना अंदाज़े के पढ़ सको, हर page fetch कर सको, और समझा सको कि आप कौन-से failures retry करते हो और क्यों।
