## ये क्या है

**n8n** ("n-eight-n" बोला जाता है) visual editor वाला workflow automation tool है। आप canvas पर **nodes** रखते हो और उन्हें arrows से जोड़ते हो। **Trigger** node workflow शुरू करता है, और उसके बाद का हर node एक काम करता है: sheet पढ़ना, app को call करना, data बदलना, किसी condition पर branch करना या AI model को बुलाना।

Data एक node से दूसरे node तक **items** की list की तरह बहता है। हर item एक छोटा JSON record है, spreadsheet की एक row जैसा:

```flow
Trigger: नई sheet row | name "Rohan", phone "98xx", course "JEE" -> Edit Fields: data ठीक करो | phone बन जाता है "+9198xx"
Edit Fields: data ठीक करो -> If: course JEE है?
If: course JEE है? -[हाँ]-> Gmail: JEE welcome
If: course JEE है? -[नहीं]-> Gmail: NEET welcome
Gmail: JEE welcome -> Telegram: counsellors को बताओ
Gmail: NEET welcome -> Telegram: counsellors को बताओ
```

आप n8n का hosted cloud version use कर सकते हो या उसे खुद चला सकते हो, जैसे Docker से, जो कई companies पसंद करती हैं ताकि उनका data अपने servers पर रहे।

इस lesson में हम Shalini के साथ चलेंगे, जो जयपुर के एक coaching institute में admissions संभालती हैं और अपना पहला workflow बना रही हैं। Lesson के अंत तक आप अपना एक workflow बनाओगे, test करोगे और publish करोगे।

## ये काम कैसे करता है

### Triggers

हर workflow एक trigger से शुरू होता है। एक workflow में एक से ज़्यादा हो सकते हैं, पर हर run उनमें से बस एक से शुरू होता है। आम triggers:

| Trigger | कब चलता है | Example use |
| --- | --- | --- |
| Schedule | तय समय आने पर | रोज़ सुबह 9 बजे daily report भेजना |
| Webhook | कोई दूसरा app किसी URL को call करे | Payment app नए payment की खबर दे |
| Email (IMAP या Gmail) | नया email आए | accounts@ पर आए invoices process करना |
| Form या Sheets | नया submission या row आए | नई admission enquiry |
| Manual | आप "Execute workflow" click करो | बनाते और test करते समय |

### Nodes

Nodes की तीन families हैं:

- **App nodes:** Gmail, Google Sheets, Slack, Telegram, WhatsApp Business, HubSpot और सैकड़ों और।
- **Core nodes:** किसी भी API के लिए HTTP Request, छोटी scripts के लिए Code, data बदलने के लिए Edit Fields (जिसे Set भी कहते हैं), branch करने के लिए If और Switch, जोड़ने के लिए Merge, batches में process करने के लिए Loop।
- **AI nodes:** language model को बुलाकर extract, classify, summarise या draft करना, या agent बनाना।

### Credentials

हर app node को एक **credential** चाहिए: उस app तक saved access, आमतौर पर OAuth से sign in करके या API key paste करके। n8n credentials को encrypted रखता है और आपको उन्हें कई workflows में दोबारा use करने देता है। अपने personal admin account की जगह एक अलग account use करो, जिसे सिर्फ़ उतना access हो जितना workflow को चाहिए।

### Nodes के बीच data mapping

Node की settings में आप चुनते हो कि पिछले nodes का कौन-सा data use करना है। आप input panel से field drag कर सकते हो, या double curly braces में **expression** लिख सकते हो, जैसे `{{ $json.email }}` मौजूदा item का email field देता है। Output panel ठीक-ठीक दिखाता है कि हर node ने क्या बनाया, जिससे गलतियाँ आसानी से दिख जाती हैं।

### Testing

Editor से sample data के साथ workflow चलाओ। हर node पर click करके उसका input और output देखो, और mapping की problems एक-एक node करके ठीक करो। Trigger का test data **pin** करो ताकि हर बार नया email भेजे या नई row जोड़े बिना पूरा workflow दोबारा चला सको।

### Publishing

जब ये चल जाए, workflow को **publish** करो। (n8n 2.0 से पहले ये एक Active toggle था।) फिर production triggers अपने-आप चलते हैं। **Executions list** हर run उसके data और errors के साथ दिखाती है।

```flow
dir: LR
Build -> Pinned data से test करो -> Fix -> Publish -> Executions देखो
Fix -[दोबारा test करो]-> Build
```

## एक example से समझो

Shalini जयपुर के एक coaching institute में admissions संभालती हैं। Enquiries एक Google Form से आती हैं जिसके responses एक sheet में जाते हैं। आज counsellors दिन में एक बार sheet देखते हैं और अगली सुबह students को call करते हैं। वो अपना पहला workflow बनाती हैं:

| # | Node | क्या करता है |
| --- | --- | --- |
| 1 | Google Sheets trigger | Responses sheet में नई row जुड़ने पर चलता है |
| 2 | Edit Fields | Spaces हटाता है, phone में +91 लगाता है, name को capitalise करता है |
| 3 | If | Course "JEE" है या "NEET"? |
| 4 | Gmail (दो branches) | Student का नाम लेकर, brochure link के साथ course के हिसाब से welcome email भेजता है |
| 5 | Telegram | Counsellors के group में "New JEE enquiry: Rohan Sharma, +91 98xxxxxx45, prefers evening batch" post करता है |

**Testing।** वो तीन sample rows pin करके workflow चलाती हैं। दो सही निकलती हैं। तीसरी, जिसमें एक student ने "jee" lower case में लिखा था, गलत branch में जाती है और उसे NEET वाला email मिल जाता है। वो If node को lower case में compare करने वाला बना देती हैं, और तीनों pass हो जाती हैं।

वो खाली phone number भी आज़माती हैं। Telegram message में "phone: undefined" आता है, जो counsellors को उलझा देगा। वो एक default जोड़ती हैं: "phone not given, reply by email"।

**Publishing।** वो workflow publish करती हैं। अगली सुबह executions list में 14 सफल runs दिखते हैं, और counsellors ने अगले दिन की जगह एक घंटे के अंदर नए students को call कर लिया।

| Measure | पहले | बाद में |
| --- | --- | --- |
| Enquiry से welcome email तक का समय | अगला दिन, हाथ से | एक मिनट से कम |
| Counsellor की call तक का समय | अगली सुबह | एक घंटे के अंदर |
| छूटी हुई enquiries | हफ़्ते में कुछ | पहले हफ़्ते में कोई नहीं |

## आम गलतियाँ

- **सिर्फ़ happy path test करना।** खाली fields, अजीब spellings, फ़ालतू spaces और duplicates आज़माओ।
- **Credentials के लिए अपना personal admin account use करना।** सीमित access वाला अलग account use करो।
- **बदलने वाली values को code में ही लिख देना।** Email templates, chat IDs और prices एक ऐसी जगह रखो जहाँ से आप उन्हें edit कर सको।
- **Publish करना भूल जाना।** जो workflow सिर्फ़ test mode में चलता है, वो किसी के काम का नहीं।
- **Error alert न होना।** Workflow पर निर्भर होने से पहले एक error workflow जोड़ो जो run fail होने पर आपको message करे।
- **Item counts को नज़रअंदाज़ करना।** जो node अचानक शून्य items देने लगे, वो चुपचाप फेल होने की आम वजह है; counts देखो।

## Practice करो

n8n का quickstart करो, फिर नीचे link किया उसका N8N101 Essentials course।

1. **Build करो।** एक trigger, कम से कम एक data ठीक करने वाले node, एक branch और दो app actions वाला workflow बनाओ, pinned test data के साथ।
2. **तोड़ो।** उसे तीन गलत inputs दो: एक गायब field, एक अजीब spelling और एक duplicate। हर एक को ठीक करो।
3. **Publish करो।** उसे publish करो और कुछ असली या simulated runs के बाद executions list देखो।

**आपका काम पूरा जब:** आप अपने workflow के हर node का input और output समझा सको और एक सफल automatic run दिखा सको।
