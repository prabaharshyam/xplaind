## ये क्या है

**n8n** (बोलते हैं "n-eight-n") एक workflow automation tool है जिसमें visual editor है। आप canvas पर **nodes** रखते हो और उन्हें arrows से जोड़ते हो। एक **trigger** node हर run शुरू करता है, और उसके बाद का हर node एक काम करता है: sheet पढ़ना, data साफ़ करना, किसी condition पर branch करना, email भेजना।

Data एक node से दूसरे node तक **items** की list के रूप में चलता है। हर item एक छोटा JSON record होता है, जैसे spreadsheet की एक row। ज़्यादातर nodes जितने items मिलते हैं, हर एक के लिए एक बार चलते हैं। तो अगर trigger तीन नई rows output करता है, तो उसके बाद वाला Gmail node तीन emails भेजता है। ये rule याद रखो, क्योंकि beginners को होने वाले ज़्यादातर surprises इसी से आते हैं।

```flow
title: Shalini का admissions workflow
नई form row | Google Sheets trigger -> Tidy enquiry | Edit Fields
Tidy enquiry -> Repeats हटाओ | Remove Duplicates
Repeats हटाओ -> Course JEE है?
Course JEE है? -[हाँ]-> JEE welcome | Gmail
Course JEE है? -[नहीं]-> NEET welcome | Gmail
JEE welcome -> Counsellors को alert | Telegram
NEET welcome -> Counsellors को alert
कोई भी failure -> Error workflow | Shalini को message
```

ये lesson mechanics के बारे में है: n8n चालू करना, items, expressions, testing और publishing। Lesson "Automation with n8n" इसी पर AI steps के साथ आगे बनता है। आप Shalini को follow करोगे, जो Jaipur के एक coaching institute में admissions संभालती हैं, जब वो ऊपर वाला workflow बनाती हैं।

शुरू करने से पहले दो बातें। पहली, n8n **open source नहीं है**। ये अपना खुद का **Sustainable Use License** use करता है, जो आपको इसे अपने internal business के लिए, या personal और non-commercial use के लिए, use करने और बदलने देता है। पैसे देने वाले clients के लिए workflows बनाना ठीक है। n8n को host करना ताकि clients उस पर अपने workflows बना सकें, इसके लिए n8n के साथ commercial agreement चाहिए। दूसरी, **n8n 2.0** से, save करना (अब automatic) सिर्फ़ एक draft रखता है। Triggers चलाने के लिए आप **Publish** click करते हो। कई पुराने tutorials अब भी Active toggle दिखाते हैं।

## ये काम कैसे करता है

### n8n चालू करो

आपके पास तीन practical choices हैं:

| Option | कैसे शुरू करो | क्या खर्च है | Google sign-in | किसके लिए best |
| --- | --- | --- | --- | --- |
| n8n Cloud | Free trial के लिए sign up करो | Trial, November 2026 के हिसाब से: 14 days, Pro features, 1,000 executions; फिर एक paid plan | एक click, "Sign in with Google" | आपका पहला workflow, सबसे तेज़ |
| आपके laptop पर Docker | एक command, नीचे है | Free software; सिर्फ़ तब चलता है जब laptop on हो | आपका अपना Google OAuth client | सीखने के लिए, data local रखने के लिए |
| किराए के server पर Docker | Docker Compose | Server का किराया, साथ में आपका समय | आपका अपना OAuth client और एक domain | Self-hosted production |

Cloud plans की कीमत **executions** से तय होती है, यानी पूरे workflow runs, अलग-अलग nodes नहीं। किसी को quote देने से पहले current plans के लिए n8n का pricing page check करो।

n8n को local चलाने के लिए Docker Desktop install करो, फिर ये चलाओ:

```bash
docker volume create n8n_data
docker run -it --rm --name n8n -p 5678:5678 \
  -e GENERIC_TIMEZONE="Asia/Kolkata" -e TZ="Asia/Kolkata" \
  -v n8n_data:/home/node/.n8n \
  n8nio/n8n
```

`http://localhost:5678` खोलो और owner account बनाओ। Container रुकने पर भी volume आपके workflows और credentials बचाकर रखता है। Time zone ज़रूरी है: इसके बिना self-hosted instance America/New_York use करता है, और "9 am" वाला schedule भारत में शाम को चलता है। पुराने tutorials n8n को `npx n8n` से शुरू करते हैं। n8n 3.0, जो November 2026 के हिसाब से early access में है, वो रास्ता हटा देता है और सिर्फ़ Docker support करता है, इसलिए Docker वाला तरीका सीखो।

Laptop की एक limit: internet पर मौजूद apps `localhost` तक नहीं पहुँच सकते। जो triggers **poll** करते हैं, जैसे Google Sheets trigger, वो फिर भी काम करते हैं, क्योंकि पूछने का काम n8n करता है। जो triggers किसी call का इंतज़ार करते हैं, जैसे Webhook, उन्हें एक public address चाहिए (lesson "Webhooks" देखो)।

### Triggers

हर workflow एक trigger से शुरू होता है। एक workflow में कई triggers हो सकते हैं, पर हर run किसी एक से शुरू होता है।

| Trigger | कब चलता है | उसे कैसे पता चलता है |
| --- | --- | --- |
| Manual | जब आप "Execute workflow" click करते हो | आप, build करते समय |
| Schedule | जब तय समय आता है | n8n की clock, workflow के time zone में |
| Webhook या Form Trigger | जब कोई दूसरा app या कोई इंसान किसी URL पर data submit करता है | तुरंत: भेजने वाला n8n को call करता है |
| Google Sheets, Gmail | जब नई row या email आता है | Polling: default रूप से n8n हर minute check करता है |

Google Forms trigger node नाम की कोई चीज़ नहीं है। अगर आप Google Form use करते हो, तो उसके answers एक responses sheet में जाते हैं, और आप उस sheet की नई rows पर trigger करते हो।

Sheets trigger की तीन आदतें जानने लायक हैं। ये rows गिनता है। Publish के बाद पहला check सिर्फ़ ये record करता है कि कितनी rows हैं, इसलिए पुराने responses कभी fire नहीं होते। Responses sheet में rows delete या sort करने से गिनती गड़बड़ा जाती है, इसलिए उस sheet को मत छेड़ो और एक copy में काम करो। और जब आप editor में "Execute workflow" click करते हो, तो ये sheet की **सारी** rows लौटाता है, सिर्फ़ सबसे नई नहीं।

### Nodes

Nodes तीन families में आते हैं:

- **App nodes:** Google Sheets, Gmail, Telegram, Slack, HubSpot और सैकड़ों और।
- **Core nodes:** fields का नाम बदलने और साफ़ करने के लिए **Edit Fields** (जिसे Set भी कहते हैं), branch करने के लिए **If** और **Switch**, **Remove Duplicates**, दो inputs जोड़ने के लिए **Merge**, किसी भी API के लिए **HTTP Request**, और छोटी scripts के लिए **Code**।
- **AI nodes:** classify, extract या draft करने के लिए language model को call करते हैं। ये "Automation with n8n" का विषय हैं।

### Credentials

हर app node को एक **credential** चाहिए: उस app का saved access, OAuth sign-in या API key के ज़रिए। n8n credentials को encrypt करके store करता है और कई workflows को एक ही credential reuse करने देता है। अपने personal admin account की जगह automation के लिए बनाया गया account use करो, जिसमें सिर्फ़ ज़रूरी access हो।

n8n Cloud पर Google credentials एक click का काम है। Self-hosted n8n पर यही वो step है जहाँ ज़्यादातर beginners अटकते हैं, क्योंकि आपको अपना खुद का **OAuth client** बनाना पड़ता है:

1. Google Cloud Console में एक project बनाओ और ज़रूरी APIs enable करो। Google Sheets node को Sheets API और Drive API दोनों चाहिए; Gmail को Gmail API चाहिए।
2. OAuth consent screen set up करो। Google Workspace use करते हो तो **Internal** चुनो, वरना **External**। External app testing में शुरू होता है, इसलिए अपना Google account **test user** के तौर पर add करो। इसके बिना Google "access denied" दिखाता है।
3. **Web application** type का OAuth client ID बनाओ। n8n की credential screen जो **OAuth Redirect URL** दिखाती है, उसे paste करो। Laptop पर ये `http://localhost:5678/rest/oauth2-credential/callback` जैसा दिखता है।
4. Client ID और Client Secret को n8n में copy करो, फिर Sign in with Google click करो।

एक trap: n8n के docs चेतावनी देते हैं कि जो External app अभी testing में है, उसके consent और tokens सात दिन में expire हो जाते हैं। अगर एक हफ़्ते बाद workflow sheet पढ़ना बंद कर दे, तो credential दोबारा connect करो, या app को testing से बाहर निकालने के बारे में Google की guidance पढ़ो।

### Expressions: current item और पिछले nodes

Node की settings में आप input panel से कोई field drag कर सकते हो, या double curly braces के अंदर एक **expression** type कर सकते हो। Expressions JavaScript के छोटे टुकड़े होते हैं।

- `{{ $json.email }}` **current item** का email field पढ़ता है, जैसा इस node का direct input उसे देखता है।
- `{{ $json['Phone number'] }}` ऐसा field पढ़ता है जिसके नाम में space है। Google Form sheets सवाल के text को ही column name बनाती हैं, और fields का नाम जल्दी बदलने की ये एक वजह है।
- `{{ $('Tidy enquiry').item.json.name }}` "Tidy enquiry" नाम के node में उस item से name पढ़ता है जिससे ये item आया है।

दूसरा तरीका जितना दिखता है उससे ज़्यादा मायने रखता है। हर node `$json` को अपने output से बदल देता है। Gmail node के बाद `$json` में अभी भेजे गए email की details होती हैं, जैसे message id, student की row नहीं। इसलिए Gmail के बाद रखे Telegram node को पिछले node का नाम लेना पड़ता है। Nodes को साफ़ नाम दो, क्योंकि नाम expression का हिस्सा है; किसी node का नाम बदलो तो उसे use करने वाले expressions check करो।

दो और defaults लोगों को उलझा देते हैं। **Edit Fields** सिर्फ़ वही fields output करता है जो आप set करते हो, जब तक आप **Include Other Input Fields** on न करो, इसलिए जो field भूल गए वो गायब हो जाता है। और नया **If** node text को case-sensitive तरीके से compare करता है: जब तक आप **Ignore Case** option add नहीं करते, "neet" और "NEET" बराबर नहीं हैं।

### Pinned data से testing

Editor से workflow चलाओ और हर node पर click करके उसका input और output देखो। Problems एक-एक node करके ठीक करो, उस पहले node से शुरू करके जिसका output गलत दिखे।

Trigger का output **Pin** करो, ताकि हर test run नए items fetch करने की जगह वही sample items reuse करे। Production runs pinned data को ignore करते हैं। Pinning ऊपर बताई Sheets trigger की आदत से भी बचाता है: 300 पुराने responses वाली sheet पर unpinned test run सारे 300 items आगे भेज देगा, और Gmail node 300 असली students को email कर देगा। Messages भेजने वाला कोई भी node जोड़ने से पहले तीन-चार rows pin करो, या trigger को sheet की एक test copy पर point करो।

### Publishing, alerts और duplicates

जब हर node अपने tests pass कर ले, तो **Publish** click करो। तब से trigger अपने आप चलता है, और **executions list** हर run को उसके data और किसी भी error के साथ दिखाती है। Workflow को अकेला छोड़ने लायक safe बनाने के लिए दो और चीज़ें चाहिए:

- **एक error workflow।** एक अलग workflow बनाओ जो **Error Trigger** node से शुरू हो और आपको message भेजे। Error Trigger को fail हुए workflow का नाम `workflow.name` में, आखिरी चला node `execution.lastNodeExecuted` में, error `execution.error.message` में और एक link `execution.url` में मिलता है। इसे publish करो, फिर main workflow की settings में **Error workflow** के नीचे इसे select करो। ये सिर्फ़ automatic runs के लिए चलता है, editor से आपके चलाए runs के लिए नहीं, इसलिए इसे किसी published workflow को जानबूझकर तोड़कर test करो।
- **Duplicate protection।** Students forms दो बार submit कर देते हैं, और parents उस बच्चे के लिए form भर देते हैं जो पहले ही भर चुका है। एक **Remove Duplicates** node जो **Remove Items Processed in Previous Executions** पर set हो, और **Value Is New** वाले items रखे, पिछले runs की values याद रखता है और repeats हटा देता है। ये एक ही run के अंदर items compare नहीं करता, इसलिए एक ही poll में पकड़ी गई दो copies दोनों निकल जाती हैं; double-clicks के लिए इसके आगे एक दूसरा Remove Duplicates लगाओ जो **Remove Items Repeated Within Current Input** पर set हो। Dedupe उस value पर करो जिसे आप पहले ही normalise कर चुके हो। "+91 98765 43210" और "09876543210" एक ही phone हैं, पर सिर्फ़ tidy करने के बाद।

```flow
dir: LR
Build -> Awkward samples pin करो -> चलाओ और जाँचो -> Fix
Fix -[फिर से test]-> चलाओ और जाँचो
चलाओ और जाँचो -[सब pass]-> Publish -> Executions पर नज़र रखो
```

## एक worked example

Shalini Jaipur के एक coaching institute में admissions संभालती हैं। Enquiries एक Google Form से आती हैं जिसमें सवाल हैं "Full name", "Phone number", "Email" और "Course"। Google हर answer को responses sheet में एक row के रूप में लिखता है, जिसमें सबसे पहले एक Timestamp column होता है। आज counsellors दिन में एक बार sheet पढ़ते हैं और अगली सुबह students को call करते हैं, और कुछ enquiries छूट जाती हैं।

वो n8n Cloud trial के लिए sign up करती हैं, ताकि Google sign-in एक click का हो, और ये बनाती हैं:

| # | Node | क्या करता है |
| --- | --- | --- |
| 1 | Google Sheets trigger, Row Added | हर minute responses sheet में नई rows check करता है |
| 2 | Edit Fields, नाम "Tidy enquiry" | name, phone, email और course को simple नामों से set करता है |
| 3 | Remove Duplicates | किसी पिछले run में देखा गया phone या email हटा देता है |
| 4 | If | Course JEE है, Ignore Case add करके |
| 5 | Gmail, हर branch के लिए एक | Brochure link के साथ course के हिसाब से welcome email |
| 6 | Telegram | Enquiry को counsellors के group में post करता है |

"Tidy enquiry" के fields:

```text
name    {{ $json['Full name'].trim().toTitleCase() }}
phone   {{ $json['Phone number'] ? '+91' + String($json['Phone number']).replace(/\D/g, '').slice(-10) : '' }}
email   {{ $json['Email'].trim().toLowerCase() }}
course  {{ $json['Course'].trim() }}
```

Phone वाली line सिर्फ़ digits रखती है, आखिरी दस लेती है और +91 जोड़ती है, तो "98765 43210", "+91 9876543210" और "09876543210" सब "+919876543210" बन जाते हैं। `String()` इसलिए है क्योंकि trigger सिर्फ़ digits वाले cell को number के रूप में दे सकता है। Cell खाली हो तो result खाली होता है, अकेला "+91" नहीं। दस से कम digits में लिखे number को बाद में phone की length check करने वाला एक If पकड़ लेगा; Shalini इसे version two के लिए note कर लेती हैं।

Remove Duplicates में dedupe करने वाली value `{{ $json.phone || $json.email }}` है। सिर्फ़ phone पर dedupe करने से हर वो student जिसने phone खाली छोड़ा, एक ही इंसान माना जाता, और पहले वाले को छोड़कर सब हट जाते।

**Testing।** Shalini चार sample rows pin करती हैं, जानबूझकर awkward चुनी हुई, और editor से workflow चलाती हैं:

1. **Lower case में "jee"।** Ignore Case add करने से पहले ये row NEET branch में गई। अब ये JEE में जाती है।
2. **Phone number नहीं है।** Phone खाली है, जैसा plan था। पर Telegram message में "Phone: " के बाद कुछ नहीं था। वो उस line को `{{ $('Tidy enquiry').item.json.phone || 'not given, reply by email' }}` में बदल देती हैं।
3. **Telegram में खाली names।** चारों alerts में name खाली था। Telegram, Gmail के बाद है, इसलिए `$json.name` Gmail का output पढ़ रहा था। ऊपर वाली line की तरह "Tidy enquiry" का नाम लेने से हर field ठीक हो गया।
4. **एक ही student दो बार,** एक बार "98765 43210" और एक बार "+91 9876543210"। Remove Duplicates सिर्फ़ पिछले runs की values याद रखता है, इसलिए वो दोनों rows दो अलग runs में भेजकर इसे test करती हैं। दूसरी हट जाती है। Editor runs भी values record करते हैं, इसलिए उन्हीं pinned rows को दोबारा चलाने पर सब repeats मानकर हट जाती हैं। बाकी tests के लिए वो हर rerun से पहले node के **Clear Deduplication History** operation से उसकी memory खाली करती हैं, और samples में बनावटी numbers use करती हैं ताकि कोई असली student कभी block न हो।

**Publishing।** वो एक error workflow बनाती हैं, Error Trigger फिर खुद को Telegram, उसे publish करती हैं और admissions workflow की settings में select करती हैं। फिर admissions workflow publish करती हैं। Sheet में पहले से मौजूद rows fire नहीं होतीं, और वो यही चाहती हैं: उन students को पहले ही call किया जा चुका है।

मिसाल के तौर पर, मान लो पहला हफ़्ता ऐसा दिखता है। ये numbers इस बात की मिसाल हैं कि क्या measure करना है, कोई measured result नहीं:

| Measure | पहले | बाद में |
| --- | --- | --- |
| Enquiry से welcome email तक | अगले दिन, हाथ से | एक-दो minute के अंदर |
| Enquiry से counsellor के call तक | अगली सुबह | उसी दिन, working hours में |
| दो बार email हुई repeat enquiries | अक्सर | बहुत कम: पिछले runs के repeats हट जाते हैं |
| चुपचाप failures | पता नहीं चलता | हर एक Shalini को link के साथ alert भेजता है |

जो trade-off वो मानती हैं: जो student सच में दो बार enquire करता है, जैसे पहले JEE और फिर NEET के लिए, वो दूसरी बार हट जाता है। अगर counsellors ऐसे students देखना चाहें, तो वो If node से पहले एक log sheet check करके duplicates को हटाने की जगह एक "repeat enquiry" Telegram message में भेज सकती हैं।

## आम गलतियाँ

- **बिना pin किए live responses sheet पर testing।** Sheets trigger का editor run हर row लौटाता है, और Gmail node सबको email कर देता है। Samples pin करो या copy use करो।
- **किसी ऐसे node के बाद `$json` पढ़ना जिसने उसे बदल दिया।** Gmail या Telegram के बाद पिछले node का नाम लो: `$('Tidy enquiry').item.json`।
- **भूल जाना कि Edit Fields वो हटा देता है जो आपने set नहीं किया।** आगे के nodes को जो भी field चाहिए वो set करो, या Include Other Input Fields on करो।
- **Case-sensitive comparisons।** If node का Ignore Case option add करो, या tidy की हुई, lower-case values compare करो।
- **Tidy करने से पहले dedupe करना, या ऐसे field पर जो खाली हो सकता है।** पहले normalise करो, और fallback के लिए दूसरा field रखो।
- **Responses sheet edit करना।** Rows delete या sort करने से trigger की row count बिगड़ जाती है, जिससे नई enquiries छूट सकती हैं।
- **Publish की जगह save करना।** n8n 2.0 में saved workflow एक draft होता है। अगर कोई production run नहीं दिख रहा, तो check करो कि आपने Publish click किया था।
- **कोई error workflow नहीं।** इसके बिना fail हुआ run executions list में तब तक पड़ा रहता है जब तक कोई इत्तफ़ाक से न देखे।
- **Self-hosted instance पर time zone default पर छोड़ देना।** Asia/Kolkata set करो।

## Practice करो

Watch & learn panel में Kevin Stratvert का beginner video देखो, n8n का "Build your first workflow" quickstart करो, फिर नीचे linked n8n का free N8N101 Essentials course लो।

1. **चलाओ।** n8n start करो, Cloud trial या ऊपर वाली Docker command से, और एक Google account connect करो।
2. **बनाओ।** एक Google Form बनाओ और Shalini का workflow build करो, या अपने case के लिए एक: एक trigger, एक Edit Fields node, Remove Duplicates, एक If branch और दो app actions। हर node को नाम दो।
3. **तोड़ो।** चार awkward rows pin करो: lower-case course, खाली phone, spaces वाला phone और एक repeat। हर node का output पहले से बताओ, चलाओ, और हर failure ठीक करो, उन्हीं rows को दोबारा चलाने से पहले Remove Duplicates की history clear करते हुए।
4. **Safely publish करो।** एक error workflow जोड़ो, दोनों publish करो, फिर main workflow को जानबूझकर तोड़ो और confirm करो कि alert एक working link के साथ आता है।

**आपका काम पूरा है जब आप** हर node का input और output समझा सको, executions list में एक automatic run दिखा सको, और fail हुए run का alert दिखा सको।
