## ये क्या है

**Vibe coding** का मतलब है AI coding agent को बताना कि आपको क्या चाहिए, फिर उसके काम को steer और check करना, ज़्यादातर code खुद टाइप करने की जगह। ये शब्द 2025 में चल पड़ा और अब कई founders, product managers, analysts और students अपने पहले tools इसी तरह बनाते हैं।

**Claude Code** Anthropic का coding agent है। सिर्फ़ code suggest करने वाले chatbot से अलग, ये आपके project में काम करता है: files पढ़ता है, उन्हें लिखता और edit करता है, tests और builds जैसे commands चलाता है, errors देखता है और फिर कोशिश करता है। आप इसे terminal में, VS Code या JetBrains के अंदर, Claude desktop app में, या claude.ai पर browser में use कर सकते हो।

असली skill prompts टाइप करना नहीं है। ये वही skill है जो एक अच्छा engineering lead किसी नए team member के साथ use करता है: goal साफ़ समझाओ, काम को steps में तोड़ो, जो वापस आए उसे review करो, और बताओ कि क्या बदलना है।

```flow
title: छोटे steps में दोहराओ; हर चलते हुए step के बाद commit करो
You: एक idea और एक spec -> Claude Code plan बनाता है
Claude Code plan बनाता है -[आप approve करते हो]-> Claude Code files edit करता है
Claude Code files edit करता है -> Claude Code tests और app चलाता है
Claude Code tests और app चलाता है -> Changes, errors और output का summary
Changes, errors और output का summary -> आप diff review करते हो, try करते हो, feedback देते हो
आप diff review करते हो, try करते हो, feedback देते हो -> You: एक idea और एक spec
```

## ये काम कैसे करता है

**1. Set up।** Official docs से Claude Code install करो, किसी खाली folder में terminal खोलो और `claude` चलाओ। इसके लिए Claude subscription या API account चाहिए। Folder को git repository बना दो ताकि हर change दिखे और undo हो सके।

**2. छोटी spec लिखो।** Code से पहले आधा page लिखो: app क्या करता है, कौन use करता है, तीन से पाँच ज़रूरी features, phone पर कैसा दिखना चाहिए, और क्या scope से बाहर है। Claude से कहो कि इसे पढ़े और आपसे सवाल पूछे। सिर्फ़ ये एक आदत ज़्यादातर बुरे नतीजे खत्म कर देती है।

**3. CLAUDE.md से उसे memory दो।** Claude हर session की शुरुआत में `CLAUDE.md` पढ़ता है। उसमें stack, app को चलाने और test करने का तरीका, और आपके rules डालो, जैसे "mobile first", "कोई paid API नहीं" या "secrets कभी commit मत करो"। पहला version `/init` से Claude से लिखवा सकते हो।

**4. पहले plan, फिर छोटे steps में build।** पहले plan माँगो (Claude Code में plan mode है जो सिर्फ़ पढ़ता और propose करता है)। उसे approve करो या सुधारो। फिर एक बार में एक feature बनवाओ: layout, फिर data, फिर calculations, फिर saving, फिर deployment।

**5. हर change review करो।** Summary पढ़ो और diff पर नज़र डालो। App खुद चलाकर देखो। कुछ अजीब लगे तो पूछो "तुमने ऐसा क्यों किया?" जब कोई step चल जाए तो commit करो।

**6. उसे test और fix करने दो।** Claude से important logic के tests लिखवाओ और चलवाओ। कुछ टूटे तो error paste करो या सही steps बताओ; सबूत मिलने पर वो bug ढूँढने में बहुत अच्छा है।

| Stage | आप क्या कहते हो | क्या check करें |
|---|---|---|
| Spec | "SPEC.md पढ़ो और जो साफ़ नहीं है वो पूछो" | उसके सवाल दिखाते हैं कि उसने समझा |
| Plan | "पहले feature का plan बनाओ; अभी code मत लिखो" | कौन-सी files छुएगा, approach, कुछ फ़ालतू नहीं |
| Build | "Plan का step 1 implement करो" | चलता है; diff छोटा और पढ़ने लायक है |
| Test | "Split calculation के tests जोड़ो और चलाओ" | tests सिर्फ़ आसान case नहीं, edge cases भी cover करते हैं |
| Fix | "360 px चौड़ाई पर table बाहर निकल जाता है। ठीक करो" | fix, और ये कि बाकी कुछ नहीं हिला |
| Ship | "Vercel पर deployment set up करो और steps समझाओ" | code में कोई secrets नहीं; environment variables use हुए |

## एक example से समझो

Nisha पुणे में तीन दोस्तों के साथ एक flat share करती है और WhatsApp chat में bills बाँटते-बाँटते थक चुकी है। वो product designer है, developer नहीं।

वो `SPEC.md` लिखती है: "एक page का web app। किसने भरा और कौन-कौन share करता है, इसके साथ bill जोड़ो। दिखाओ कि कौन किसे कितना देगा, कम से कम payments में हिसाब बराबर करके। Phone पर चले। Browser में save हो; कोई login नहीं। Rupees में।" वो नए folder में `claude` चलाती है और उससे spec पढ़कर सवाल पूछने को कहती है। Claude पूछता है कि क्या bills असमान बाँटे जा सकते हैं और क्या payments के लिए UPI link चाहिए। वो कहती है असमान split बाद में, UPI links हाँ।

वो plan माँगती है और मिलता है: एक Next.js app, एक form, bills की list, एक settlement function, local storage, और settlement की maths के tests। वो सिर्फ़ पहला step approve करती है: page और form। वो चल जाता है। वो commit करती है।

तीसरा step settlement की maths है। वो Claude से पहले tests लिखवाती है, एक ऐसे case के साथ जिसका जवाब उसे पता है: तीन दोस्त, एक ने groceries के ₹3,000 दिए। एक test fail होता है क्योंकि rounding से ₹1 का हिसाब नहीं मिलता। Claude कारण समझाता है और बचा हुआ रुपया payer को देकर ठीक करता है। ये वो आँख से कभी नहीं पकड़ पाती।

शाम को वो Claude से Vercel पर deployment set up करवाती है। अगली सुबह उसके flatmates app use कर रहे होते हैं। कुल समय: लगभग पाँच घंटे, जिसमें ज़्यादातर ये तय करने में गया कि उसे चाहिए क्या।

## आम गलतियाँ

**पूरा app एक ही message में माँगना।** आपको एक बड़ा, बिना test का उलझा ढेर मिलता है। एक बार में एक feature माँगो।

**Spec छोड़ देना।** इसके बिना Claude अंदाज़ा लगाता है, और आपको गलत अंदाज़ा तब पता चलता है जब वो उसके ऊपर बहुत कुछ बना चुका होता है।

**जो changes समझ नहीं आए उन्हें accept कर लेना।** समझाने को कहो। Code, उसके bugs और उसकी security के मालिक आप हो।

**Git न होना।** Commits के बिना आप देख नहीं सकते कि क्या बदला या वापस नहीं जा सकते। हर चलते हुए step के बाद commit करो।

**API keys को code में डालना।** Secrets को environment variables और `.env` file में रखो जिसे git ignore करे। Push से पहले Claude से secrets check करवाओ।

**"Fix it" के अंतहीन loops।** अगर वही bug तीन कोशिशों के बाद भी बचा रहे, तो रुक जाओ। सही steps, उम्मीद और असली नतीजा बताओ, और कुछ बदलने से पहले Claude से कारण समझाने को कहो।
