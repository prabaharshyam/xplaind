## ये क्या है

हर developer रोज़ दो tools use करता है:

- **Terminal**: commands चलाने की text window। इसी से आप folders में घूमते हो, programs चलाते हो, packages install करते हो और Git जैसे tools use करते हो।
- **Git**: एक version control system जो आपके project के snapshots record करता है, जिन्हें **commits** कहते हैं, ताकि आप देख सको क्या बदला, गलतियाँ undo कर सको और code share कर सको। **GitHub** Git repositories को online रखता है ताकि दूसरे उन्हें देख सकें और आपके साथ काम कर सकें।

```flow
dir: LR
आपका folder | hello.py, expenses.py, README.md: आप files edit करते हो -[git add, git commit]-> आपके computer पर Git | commits 1, 2, 3: history जिसे undo कर सकते हो
आपके computer पर Git -[git push]-> GitHub | आपकी public repository: share करने वाला link
```

Employers GitHub profiles देखते हैं। साफ़ commits और अच्छे README वाली repository इस बात का सबसे आसान सबूत है कि आप code लिख और organise कर सकते हो, और interviewers अक्सर interview के दौरान उसे खोलते हैं।

इस lesson में हम Nagpur में Python सीख रहे Ravi के साथ चलेंगे, जब वो exercise scripts के folder को GitHub portfolio बनाता है। इसका check एक छोटा project है: आपकी अपनी repository, कम से कम तीन साफ़ commits और एक README के साथ।

## ये काम कैसे करता है

### Terminal की basics

| Command | क्या करता है |
| --- | --- |
| `pwd` | दिखाता है कि आप किस folder में हो (Mac, Linux; Windows पर सिर्फ़ `cd`) |
| `ls` | Files की list दिखाता है (Windows Command Prompt में `dir`) |
| `cd projects` | किसी folder के अंदर जाता है |
| `cd ..` | एक folder ऊपर जाता है |
| `mkdir python-practice` | नया folder बनाता है |
| `python hello.py` | Program चलाता है |

**Up arrow** पुराने commands दोहराता है, और **Tab** file और folder के नाम पूरे कर देता है, जिससे बहुत type करना और typos बचते हैं।

### Git एक बार set up करो

Git install करो, फिर उसे बताओ कि आप कौन हो:

```bash
git config --global user.name "Priya Raman"
git config --global user.email "priya@example.com"
```

### Repository शुरू करो और commits बनाओ

```bash
cd python-practice
git init                         # start tracking this folder
git status                       # what has changed?
git add hello.py                 # choose changes for the next commit
git commit -m "Add hello script that prints name and date"
git log --oneline                # see the history
```

`git add` changes को **staging area** में रखता है: उन चीज़ों की list जो अगले snapshot में जाएँगी। `git commit` उस snapshot को message के साथ save करता है। इस दो-step design से आप related changes को साथ commit कर सकते हो और बाकी बाद के लिए छोड़ सकते हो।

### अच्छे commit messages

| कमज़ोर | मज़बूत |
| --- | --- |
| "update" | "Add expense totals by category" |
| "fixed stuff" | "Handle missing amounts in expense CSV" |
| "final" | "Add README with usage examples" |

Present tense में लिखो, बताओ कि क्या बदला, और पहली लाइन छोटी रखो। कुछ टूटने पर आपका future self यही messages पढ़ेगा।

### Git से undo करना

| स्थिति | Command |
| --- | --- |
| आखिरी commit के बाद क्या बदला, देखना | `git diff` |
| किसी एक file के changes फेंकना | `git restore expenses.py` |
| गलती से add की हुई file को unstage करना | `git restore --staged expenses.py` |
| पुराना version देखना | `git log --oneline`, फिर `git show <commit>` |

### GitHub पर push करना

GitHub पर एक खाली repository बनाओ, फिर connect करके push करो:

```bash
git remote add origin https://github.com/priya-raman/python-practice.git
git branch -M main
git push -u origin main
```

GitHub आपसे sign in करने को कहेगा; उसके prompts follow करो या SSH key set up करो। पहले push के बाद सिर्फ़ `git push` नए commits भेज देता है।

### README और .gitignore

`README.md` बताता है कि project क्या है और उसे कैसे चलाएँ। GitHub उसे repository के front page पर दिखाता है।

`.gitignore` file उन चीज़ों की list होती है जिन्हें Git track न करे:

```text
.venv/
__pycache__/
.env
```

`.env` वाली लाइन सबसे ज़रूरी है: `.env` files में अक्सर API keys होती हैं। `.gitignore` अपने पहले `git add` से **पहले** बनाओ, क्योंकि secret एक बार commit हो गया तो file को बाद में delete करने पर भी वो history में रहता है। अगर कभी कोई key push हो जाए, तो उसे तुरंत revoke करो और नई बनाओ।

## एक example से समझो

Nagpur में Python सीख रहे Ravi के पास exercise scripts का एक folder है: एक expense tracker, एक marks calculator और एक weather fetcher जो API key use करता है। वो इसे GitHub portfolio में बदलता है।

| Step | वो क्या करता है | क्यों |
| --- | --- | --- |
| 1 | Folder में `git init` | History track करना शुरू |
| 2 | `.venv/` और `.env` के साथ `.gitignore` बनाता है | Environment और अपनी API key को Git से बाहर रखना |
| 3 | Commit: "Add expense tracker with category totals" | एक साफ़, मतलब वाला step |
| 4 | Commit: "Handle missing amounts in expense CSV" | दूसरा, अलग सुधार |
| 5 | Commit: "Add README with usage examples" | आने वालों को project समझाना |
| 6 | नई public repository पर `git push` | Share करने के लिए एक link |

उसके README में एक लाइन का summary है, हर script कैसे चलाएँ, और output का एक नमूना।

**एक गलती, undo की हुई।** एक हफ़्ते बाद, एक feature जोड़ते हुए वो expense tracker बिगाड़ देता है। `git diff` ठीक वही lines दिखा देता है जो उसने बदली थीं। `git restore expenses.py` एक second में आखिरी committed version वापस ले आता है, और वो feature दोबारा ज़्यादा ध्यान से try करता है।

**इसका फ़ायदा।** अगले महीने एक interview में panel उसकी repository खोलता है और उससे commit "Handle missing amounts in expense CSV" के बारे में पूछता है। वो bug, उसे कैसे ढूँढा और कैसे ठीक किया, सब समझाता है। Interview का सबसे अच्छा हिस्सा यही रहता है।

## आम गलतियाँ

- **आखिर में एक विशाल commit।** काम करते हुए छोटे, मतलब वाले steps commit करो।
- **"update" जैसे messages।** बताओ कि क्या बदला।
- **Secrets commit करना।** Keys `.env` में रखो, पहले commit से पहले उसे `.gitignore` में डालो, और जो भी key कभी push हो जाए उसे revoke करो।
- **Virtual environments और caches commit करना।** उन्हें ignore करो।
- **README न होना।** आने वाले समझ नहीं पाते कि project क्या करता है या कैसे चलाएँ।
- **`git status` के बिना काम करना।** उसे अक्सर देखो; वो ठीक बताता है कि आप कहाँ हो।
