## ये क्या है

**Triage** का मतलब है तय करना कि हर आने वाला message क्या है, कितना urgent है और उसे कौन संभाले। AI triage पहला pass automate करता है:

- **Classify**: ये किस तरह का message है (billing, delivery, technical issue, complaint, sales enquiry, spam)?
- **Extract**: team को जो details चाहिए (order number, account id, product, location)।
- **Prioritise**: urgent है या नहीं (service down, payment failed, legal threat, VIP customer)।
- **Route**: सही team या इंसान को, सही tool में।
- **Draft**: एक suggested reply, जिसे इंसान check करके भेजे।

```flow
Incoming email or ticket -> AI step, structured output | category, priority, fields, summary, unsure?
AI step, structured output -> Rules on top | key account? legal words? data deletion?
Rules on top -[a rule matches]-> Force the priority, route to a senior or the privacy contact
Rules on top -> Unsure?
Unsure? -[yes]-> General queue | a person sorts it
Unsure? -[no]-> Route in the help desk | team, priority, summary, draft reply
Route in the help desk -> An agent checks the draft, edits, sends
```

ये lesson Chennai के एक broadband provider के साथ चलता है, जिसके support inbox में रोज़ लगभग 2,500 emails आते हैं।

## ये काम कैसे करता है

**Categories team के साथ तय करो।** वही categories use करो जिनके साथ आपकी support या operations team पहले से काम करती है, हर एक की एक लाइन की definition और दो-तीन example messages के साथ। "Other / unclear" भी रखो।

**Structured output से classify करो।** AI step एक fixed shape में category, priority, extracted fields, एक लाइन का summary और confidence या "unsure" flag लौटाता है।

**AI के चारों ओर rules।** कुछ फ़ैसले rules होने चाहिए, AI का judgement नहीं: key accounts की list से आए messages हमेशा high priority होते हैं; legal action, police या consumer court का ज़िक्र करने वाला कोई भी message किसी senior इंसान के पास जाता है; data deletion की कोई भी बात privacy contact के पास जाती है।

**Route।** Help desk में ticket बनाओ या update करो, team assign करो, priority set करो और extracted fields व summary जोड़ो। Unsure cases किसी general queue में जाते हैं, जहाँ इंसान उन्हें छाँटता है।

**Replies draft करो, भेजो नहीं (शुरू में)।** Customer के message, extracted details और अपने knowledge base से reply draft बनाओ और उसे ticket में रख दो, ताकि agent edit करके भेजे। हफ़्तों तक quality नापने के बाद ही सरल, low-risk replies (जैसे "हमें आपकी request मिल गई है") अपने आप भेजो।

**भाषाएँ।** भारतीय customers English, Hindi, Tamil, Hinglish और भी बहुत कुछ में लिखते हैं। आपको जिन भाषाओं में messages आते हैं, उनमें असली messages पर triage को test करो।

**नापो।** हफ़्ते के sample पर classification accuracy, पहली बार में सही route हुए messages का हिस्सा, पहले response का समय, और agents drafts में कितना बदलाव करते हैं।

**Category की ऐसी definition जिसे AI और team दोनों समझें:**

| Category | Definition | Example messages |
| --- | --- | --- |
| Outage | बिल्कुल internet नहीं, शायद पूरे area पर असर | "Net not working since morning", "Wi-Fi light red" |
| Slow speed | Connected है पर plan से धीमा | "Getting 5 Mbps on a 100 Mbps plan" |
| Billing | Charges, payments, refunds | "Charged twice this month" |
| Relocation | Connection को नए address पर ले जाना | "Shifting to Velachery next week" |
| Other or unclear | बाकी सब, या पक्का नहीं | "Hi", forwarded newsletters |

ये definitions सीधे prompt में जाती हैं। जब team किसी category को बदलती है, तो definition एक ही जगह बदलती है, और test set में उसके नए examples जुड़ते हैं।

**Drafts से क्यों शुरू करें।** 92% classification accuracy पर भी, किसी नाराज़ customer को गलत automatic reply जाए तो असली नुकसान होता है। Drafts से agents बाकी 8% ठीक कर लेते हैं और 92% पर समय बचता है। नापो कि agents हर draft में कितना बदलाव करते हैं: जब किसी category के ज़्यादातर drafts कई हफ़्तों तक बिना बदले जाएँ, तो वो category automatic sending के लिए candidate है, सरल acknowledgements से शुरू करके।

**Code में पहले rules, फिर model।** Fixed rules किसी भी model call से पहले चलते हैं, इसलिए उन्हें बातों में फुसलाकर टाला नहीं जा सकता:

```python
from typing import Literal
from pydantic import BaseModel

Category = Literal["outage", "slow_speed", "billing", "relocation", "other"]

class Triage(BaseModel):
    category: Category
    priority: Literal["p1", "p2", "p3"]
    account_id: str | None = None
    summary: str
    unsure: bool

KEY_ACCOUNTS = {"ACC-1001", "ACC-2040"}
LEGAL_WORDS = ("legal notice", "consumer court", "police complaint", "lawyer")

def triage(message, sender_account, classify):
    text = message.lower()
    if any(w in text for w in LEGAL_WORDS):
        return {"queue": "senior", "priority": "p1", "reason": "legal words"}
    if "delete my data" in text or "erase my data" in text:
        return {"queue": "privacy", "priority": "p2", "reason": "data request"}
    t: Triage = classify(message)                 # structured output from the model
    if t.unsure or t.category == "other":
        return {"queue": "general", "priority": t.priority, "reason": "unsure"}
    priority = "p1" if sender_account in KEY_ACCOUNTS else t.priority
    return {"queue": t.category, "priority": priority, "summary": t.summary, "account": t.account_id}
```

**नापो कि गलती कहाँ होती है।** कुल accuracy ये छिपा देती है कि कौन-सी categories उलझ रही हैं। अपने labelled set से एक confusion table बनाओ:

```python
from collections import Counter

def confusion(pairs):
    """pairs: list of (true_category, predicted_category)."""
    counts = Counter(pairs)
    cats = sorted({c for p in pairs for c in p})
    print("true \\ predicted".ljust(14) + "".join(c[:9].ljust(10) for c in cats))
    for t in cats:
        print(t[:13].ljust(14) + "".join(str(counts[(t, p)]).ljust(10) for p in cats))
    acc = sum(counts[(c, c)] for c in cats) / len(pairs)
    print(f"accuracy {acc:.0%}")
```

अगर "slow_speed" को अक्सर "outage" predict किया जा रहा है, तो दोनों definitions कसो और boundary के पास हर एक के examples जोड़ो। Accuracy भाषा के हिसाब से भी बताओ: examples जोड़ने तक Hinglish messages अक्सर English से खराब चलते हैं।

**गलतियों की कीमत अलग-अलग होती है।** Outage को billing में भेजने से पूरे area का fix देर से होता है; billing को general में भेजने पर कुछ मिनट जाते हैं। Team के साथ तय करो कि कौन-सी confusions सबसे ज़्यादा मायने रखती हैं, और average की जगह table के उन्हीं cells पर नज़र रखो।

**Inbox के बदलाव पर नज़र रखो।** हर category और "other" का हिस्सा हर हफ़्ते track करो। नया plan launch, festival sale या outage mix बदल देता है। "Other" का बढ़ना आमतौर पर बताता है कि नई category चाहिए।

## एक example से समझो

Chennai के एक broadband provider के support inbox में रोज़ लगभग 2,500 emails आते हैं। पहले दो staff सुबह उन्हें छाँटने में लगाते थे; urgent outages घंटों इंतज़ार करते थे।

Automation हर email को आठ categories में classify करती है (outage, slow speed, billing, plan change, new connection, relocation, complaint, other), customer id और area निकालती है, और priority तय करती है। Rules उन areas के "outage" पर high priority थोप देते हैं जहाँ network incident खुला है, और "consumer forum" या "legal notice" के हर ज़िक्र पर भी। Tickets summary और reply draft के साथ help desk में सही team को जाते हैं।

English, Tamil और Tanglish के 400-email test set पर classification accuracy 92% है; मुख्य उलझन "slow speed" और "outage" के बीच है, जिन्हें team एक ही network queue में route करने का फ़ैसला करती है। Launch के बाद, पहले response का median समय 5 घंटे से घटकर 40 मिनट हो जाता है, और agents 60% drafts हल्के बदलाव के साथ भेजते हैं।

| नाप | पहले | Launch के बाद |
| --- | --- | --- |
| दो staff का सुबह छाँटने में लगा समय | हर एक का लगभग 3 घंटे | कुछ नहीं |
| पहले response का median समय | 5 घंटे | 40 मिनट |
| Classification accuracy, English, Tamil और Tanglish के 400-email test पर | लागू नहीं | 92% |
| हल्के बदलाव के साथ भेजे गए drafts | लागू नहीं | 60% |

मुख्य उलझन, slow speed बनाम outage, बेहतर model से नहीं बल्कि एक product फ़ैसले से सुलझी: दोनों अब एक ही network queue में जाते हैं।

## आम गलतियाँ

- **ऐसी categories गढ़ना जो team use नहीं करती।** उनकी अपनी categories use करो।
- **Legal या safety escalations अकेले AI पर छोड़ना।** इनके लिए rules use करो।
- **Replies बहुत जल्दी अपने आप भेजना।** Drafts से शुरू करो और नापो।
- **सिर्फ़ English में test करना।** उन भाषाओं में test करो जिनमें customers सच में लिखते हैं।
- **"Unsure" path न होना।** हर message पर category थोपने से errors छिप जाती हैं।
- **सिर्फ़ कुल accuracy देखना।** देखो कि कौन-सी categories उलझ रही हैं, और भाषा के हिसाब से भी।
- **Legal और privacy routing model पर छोड़ना।** Model चलने से पहले fixed rules लगाओ।

## AI triage कब ज़रूरी नहीं

- **कम volume**: एक इंसान का हर message पढ़ना तेज़ भी है और सही भी।
- **Help desk के अपने rules पहले से काम कर रहे हैं**, जैसे customer के भरे form fields से route करना।
- **Categories हर हफ़्ते बदलती हैं**, तो सीखने के लिए कुछ टिकाऊ है ही नहीं।

## Demo से production तक

- **हर हफ़्ते 50 messages का sample label करो** और accuracy व confusion table track करो।
- **Category definitions एक ही file में रखो**, जिसे prompt, help desk और test set share करें।
- **हर फ़ैसले को log करो**, उस rule या model output के साथ जिसने वो फ़ैसला किया।
- **किसी भी category में spike पर alert लगाओ**, खासकर outages में।
- **Automatic replies को हर महीने review करो**, उन्हें और categories तक बढ़ाने से पहले।
