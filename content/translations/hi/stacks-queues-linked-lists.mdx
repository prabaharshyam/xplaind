## ये क्या है

ये तीनों structures इस बारे में हैं कि **items कैसे अंदर जाते हैं और बाहर आते हैं**।

**Stack** प्लेटों के ढेर जैसा है: आप ऊपर रखते हो और ऊपर से ही उठाते हो। जो item आख़िर में गया, वो सबसे पहले निकलता है, इसे **LIFO** कहते हैं। Undo buttons, browser के back buttons और programs जिस तरह function calls का हिसाब रखते हैं, ये सब stacks हैं।

**Queue** रेलवे के टिकट काउंटर की line जैसी है: लोग पीछे जुड़ते हैं और आगे से निकलते हैं। जो item पहले गया, वही पहले निकलता है, इसे **FIFO** कहते हैं। Print jobs, customer support tickets और background tasks queues हैं।

**Linked list** nodes की एक chain है। हर node में एक value और अगले node का pointer होता है। आप बाकी को खिसकाए बिना, दो pointers बदलकर कहीं भी node जोड़ या हटा सकते हो।

| Structure | कैसे काम करता है | Example |
|---|---|---|
| Stack (LIFO) | ऊपर push करो, ऊपर से pop करो: last in, first out | A, B, C push करो; pop करने पर C मिलता है |
| Queue (FIFO) | पीछे enqueue करो, आगे से dequeue करो: first in, first out | A, B, C enqueue करो; dequeue करने पर A मिलता है |
| Linked list | हर node में एक value और अगले का pointer | 9 के बाद 7 insert करो: सिर्फ़ दो pointers बदलते हैं |

## ये काम कैसे करता है

**Stacks** को दो operations चाहिए: `push` (ऊपर जोड़ना) और `pop` (ऊपर से हटाना)। Python में एक आम list अच्छे से चलती है: `append` push करता है और `pop()` pop करता है, दोनों O(1)। आप ऊपर वाले item को हटाए बिना `peek` भी कर सकते हो।

**Queues** को `enqueue` (पीछे जोड़ना) और `dequeue` (आगे से हटाना) चाहिए। Python की list खराब queue है, क्योंकि `pop(0)` हर item को खिसकाता है, O(n)। `collections.deque` use करो, जो एक double-ended queue है, जिसके `append` और `popleft` दोनों O(1) हैं। Threads या programs के बीच साझा काम के लिए आप queue library या message queue service use करते हो, जो आपको system design track में मिलेगी।

**Linked lists** हर item को अपने node object में रखती हैं जो अगले को point करता है। जो node आपके हाथ में है, उसके बाद insert करने के लिए, नए node को पुराने अगले node की तरफ़ point करो और पुराने node को नए की तरफ़: O(1)। कीमत ये है कि position से पढ़ना धीमा है। Item 500 तक पहुँचने के लिए आपको 500 pointers follow करने होंगे, O(n)। Python में कोई built-in linked list type नहीं है क्योंकि lists और deques ज़्यादातर ज़रूरतें पूरी कर देते हैं, पर ये idea interview problems में और दूसरे structures के अंदर दिखता है।

| Structure | जोड़ना | हटाना | Item k पढ़ना | किसके लिए use करें |
|---|---|---|---|---|
| Stack (list) | push O(1) | pop O(1) | सिर्फ़ ऊपर वाला | undo, bracket matching, DFS |
| Queue (deque) | append O(1) | popleft O(1) | सिर्फ़ आगे वाला | tasks को क्रम से, BFS |
| Linked list | जाने हुए node पर O(1) | जाने हुए node पर O(1) | O(n) | बीच में बार-बार edits, LRU caches |
| Array (list) | आख़िर में O(1) | आगे से O(n) | O(1) | position से पढ़ना |

**Interviews में** ये structures दूसरे सवालों में छिपे होते हैं। "सबसे हाल का", "undo", "nested" या "matching pairs" stack का इशारा हैं। "आने के क्रम में", "level by level" या "tasks को निष्पक्ष तरीके से process करो" queue का इशारा हैं। Linked list के सवाल आमतौर पर pointers की सावधानी परखते हैं: list को उलटना, slow और fast pointer से उसका बीच ढूँढना, या loop पकड़ना। पहले काग़ज़ पर nodes और तीर बनाओ; linked list के ज़्यादातर bugs खोए हुए pointers होते हैं जो एक छोटा-सा sketch पकड़ लेता।

## एक example से समझो

Ananya कोटा के coaching centres में use होने वाले एक maths quiz app के लिए छोटा expression checker बना रही हैं। Students `(2+3)*[4-(1+1)]` जैसे answers type करते हैं, और app को evaluate करने की कोशिश से पहले ही बेमेल brackets वाले answers reject कर देने चाहिए।

Stack यहाँ बिल्कुल फ़िट बैठता है। हर opening bracket को मेल खाते closing bracket से बंद होना चाहिए, और सबसे हाल में खुला वाला सबसे पहले बंद होना चाहिए, जो ठीक LIFO है।

```python
PAIRS = {")": "(", "]": "[", "}": "{"}

def balanced(text):
    stack = []
    for ch in text:
        if ch in "([{":
            stack.append(ch)                 # push
        elif ch in PAIRS:
            if not stack or stack.pop() != PAIRS[ch]:
                return False                 # nothing to close, or wrong type
    return not stack                         # anything left open?
```

`[(])` को trace करो: `[` push, `(` push, फिर `]` पर `(` pop होता है, जो `[` से match नहीं करता, इसलिए ये `False` लौटाता है। `{[()()]}` के लिए हर pop match करता है और stack आख़िर में खाली होता है, इसलिए `True` लौटता है। Function एक ही pass बनाता है: O(n) time और O(n) तक space।

अब, app को live test के दौरान submitted answers को उसी क्रम में mark करना है जिसमें वो आए, चाहे सैकड़ों एक साथ आएँ। Ananya queue use करती हैं:

```python
from collections import deque
pending = deque()
pending.append("answer-101")       # enqueue
pending.append("answer-102")
first = pending.popleft()          # "answer-101", O(1)
```

निष्पक्षता मुफ़्त में मिल जाती है: किसी student का answer line नहीं तोड़ता।

## आम गलतियाँ

**list.pop(0) को queue की तरह use करना।** छोटे data पर चलता है और लंबे चलने पर O(n²) बन जाता है। `deque.popleft()` use करो।

**खाली stack को pop करना।** खाली list पर `pop()` call करने से error आती है। पहले `if stack` check करो, जैसा bracket checker करता है।

**आख़िरी check भूल जाना।** `((` जैसी bracket string कभी pop में फ़ेल नहीं होती, पर balanced नहीं है। हमेशा check करो कि आख़िर में stack खाली है।

**आदतन linked list उठा लेना।** Python में lists और deques लगभग हर चीज़ के लिए तेज़ हैं। Linked list तब use करो जब आपको सच में उन nodes पर सस्ते inserts और removals चाहिए जो आपके हाथ में हैं।

**Linked list का बाकी हिस्सा खो देना।** Insert करते समय, पुराने node का pointer बदलने से पहले नए node को अगले node की तरफ़ point करो, वरना chain टूट जाती है।

**Graph search में stack और queue को मिला देना।** Depth-first search stack (या recursion) use करता है; breadth-first search queue। इन्हें बदल दो तो traversal अलग हो जाता है।
