## ये क्या है

Claude **animated explainer videos** बना सकता है: slide होकर आते titles, step by step बनते diagrams, बढ़ते charts, किसी path पर चलते icons। ये ऐसा **code लिखकर** करता है जो हर element को draw और animate करता है। ये कुछ film नहीं करता और camera footage generate नहीं करता। इसलिए ये **motion graphics** के लिए बढ़िया है, यानी animated text, shapes और charts जो किसी idea, process या कुछ numbers को समझाते हैं।

क्योंकि video code है, ये recording की तरह नहीं, document की तरह behave करता है: एक शब्द, number या timing बदलो और फिर से render करो। आप इसे data भी दे सकते हो और सौ versions पा सकते हो।

### तीन routes, November 2026 के हिसाब से

- **एक Claude artifact।** एक आम chat में animated HTML, CSS या SVG scene माँगो। ये chat में तुरंत play होता है। Video file चाहिए तो उसे screen-record करो या Remotion में ले जाओ। एक scene या किसी idea के quick test के लिए सबसे अच्छा।
- **Remotion के साथ Claude Code।** Remotion React code से videos बनाने का एक framework है। Claude Code (Pro जैसे paid Claude plans में शामिल, Free plan में नहीं) आपके computer पर project लिखता है, और Remotion असली MP4 render करता है। एक scene से लंबी किसी भी चीज़, narration वाली किसी भी चीज़, और series या data-driven videos के लिए सबसे अच्छा।
- **Claude Motion।** Anthropic ने इसे 8 October 2026 को beta में announce किया। आप explainer describe करते हो, या कोई report या data paste करते हो, और Claude एक छोटा animation बनाता है जिसे आप edit कर सकते हो और MP4 के तौर पर download कर सकते हो। ये सिर्फ़ **Team और Enterprise plans** पर है; Free, Pro, Max या Ultra पर नहीं है। Team workspaces में ये default से on होता है, और Enterprise पर किसी owner को इसे on करना पड़ता है। लंबे animations आपके plan की usage limit का ज़्यादा हिस्सा use करते हैं।

ज़्यादातर learners personal plan use करते हैं, इसलिए ये lesson **Claude Code और Remotion** से बनाता है और quick tests के लिए artifacts use करता है। अगर आपका employer आपको Motion देता है, तो scripting, style और accessibility वाली advice उस पर भी वैसे ही लागू होती है।

**Work में use करने से पहले licence check।** Remotion individuals, non-profit organisations और 3 employees तक वाली for-profit companies के लिए free है, commercial काम समेत। इससे बड़ी for-profit company को paid company licence चाहिए, और गिनती company के total headcount की होती है, Remotion use करने वाले लोगों की नहीं। Prices बदलते रहते हैं, तो work में use करने से पहले remotion.dev पर licence और pricing pages check करो।

```flow
title: Idea से MP4 तक
Idea -> Script | scenes, timings, on-screen words
Script -> Narration record करो
Narration record करो -[sentence timestamps]-> Claude animation code लिखता है | Remotion, एक artifact या Motion
Claude animation code लिखता है -> Preview
Preview -[बहुत तेज़, text बहुत छोटा]-> Revise
Revise -> Preview
Preview -[सही लग रहा है]-> Captions और music जोड़ो
Captions और music जोड़ो -> MP4 render करो -> Phone पर check करो -> Publish
```

## ये काम कैसे करता है

### 1. Prompt से नहीं, script से शुरू करो

हर scene एक line में लिखो: उसकी लंबाई seconds में, क्या दिखता है, क्या move होता है, और screen पर या narration में आने वाले शब्द। एक idea के लिए तीस से नब्बे seconds काफ़ी हैं। एक line का prompt Claude से इनमें से हर choice का अंदाज़ा लगवाता है, और वो अंदाज़े generic होते हैं।

Prompt करने से पहले दो checks। Timer लगाकर narration ज़ोर से पढ़ो: अगर 12-second वाले scene को बोलने में 17 seconds लगते हैं, तो script अभी ठीक करो। और हर scene को एक ही काम दो; अगर उसे describe करने में दो बार "और" लगता है, तो उसे तोड़ दो।

### 2. Visual style एक बार set करो

दो-तीन colours (brand colours हों तो hex codes के साथ), एक font, background, और motion style बताओ, जैसे "smooth ease-in-out, 0.4 s moves, no bouncing"। Claude से कहो कि ये सब एक style file या constants block में रखे। फिर हर scene उसी से पढ़ता है, तो बाद में brand colour बदलना एक ही edit है।

### 3. Route चुनो

| आपकी situation | Route | कौन सा plan चाहिए | आपको क्या मिलता है |
|---|---|---|---|
| एक scene, या test करना कि idea अच्छे से animate होता है या नहीं | Claude artifact | कोई भी Claude plan | Chat में play होने वाला HTML; उसे screen-record करो |
| Narration के साथ पूरा video, personal plan पर | Claude Code + Remotion | Claude Code वाला paid plan | Rendered MP4, दोबारा use होने वाला project |
| किसी sheet या list से कई versions | Claude Code + Remotion | Claude Code वाला paid plan | एक template से हर row का एक MP4 |
| Report से एक quick explainer, ऐसी company में जिसके पास Motion है | Claude Motion | Team या Enterprise | Edit होने वाला animation, MP4 download |
| Realistic लोग, जगहें या products | Veo जैसा video model | Veo और Flow guide देखो | Generated clips |

एक simple rule: अगर आप इसे एक से ज़्यादा बार छुओगे, या इसे voice-over से match करना है, तो Remotion use करो। अगर सिर्फ़ ये देखना है कि कोई idea animation के तौर पर काम करता है या नहीं, तो artifact use करो।

### 4. Claude Code क्या लिखता है, और उसे कैसे पढ़ें

आप Claude Code से कह सकते हो "हर scene के लिए एक component वाला नया Remotion project बनाओ", और वो एक set up कर देगा (official starter है `npx create-video@latest`)। आपको खुद React लिखने की ज़रूरत नहीं, लेकिन उसे पढ़ पाना चाहिए, क्योंकि इसी से आप गलत number पकड़ते हो या सटीक change माँगते हो। चार ideas इसका ज़्यादातर हिस्सा cover करते हैं:

- **Frames और fps।** Video still pictures की एक series है, जिन्हें frames कहते हैं। 30 frames per second (fps) पर, 5-second scene 150 frames का होता है।
- **Current frame।** `useCurrentFrame()` उस frame का number देता है जो अभी draw हो रहा है। Scene के अंदर ये उस scene के start से गिनता है, तो हर scene अपना animation 0 से शुरू कर सकता है।
- **Interpolate।** `interpolate()` एक frame range को एक value range से map करता है: "frame 0 और frame 15 के बीच, invisible से पूरी तरह visible हो जाओ"।
- **Composition।** एक `Composition` video की width, height, fps और frames में लंबाई (`durationInFrames`) set करता है।

ये नीचे वाले worked example से Sneha का title card है, अकेला एक 5-second scene:

```tsx
import { AbsoluteFill, Composition, interpolate, useCurrentFrame, useVideoConfig } from "remotion";

// Scene 6, the title card: the text fades in and rises over half a second.
export const TitleCard = ({ text }: { text: string }) => {
  const frame = useCurrentFrame(); // 0, 1, 2 ... counted from the start of this scene
  const { fps } = useVideoConfig(); // 30 in this project
  const opacity = interpolate(frame, [0, 0.5 * fps], [0, 1], { extrapolateRight: "clamp" });
  const y = interpolate(frame, [0, 0.5 * fps], [40, 0], { extrapolateRight: "clamp" });
  return (
    <AbsoluteFill style={{ backgroundColor: "#ffffff", justifyContent: "center", alignItems: "center", padding: 80 }}>
      <h1 style={{ fontSize: 96, color: "#5b2a86", textAlign: "center", opacity, transform: `translateY(${y}px)` }}>
        {text}
      </h1>
    </AbsoluteFill>
  );
};

// The video's settings: size, frame rate and length in frames.
export const RemotionRoot = () => (
  <Composition
    id="TitleCard"
    component={TitleCard}
    width={1080}
    height={1920}
    fps={30}
    durationInFrames={150} // 5 seconds x 30 fps
    defaultProps={{ text: "RAG = search first, then answer" }}
  />
);
```

इसे line by line पढ़ो। आधा second है `0.5 * fps`, यानी 15 frames, तो `opacity` frames 0 से 15 में 0 से 1 तक जाती है। दूसरा `interpolate` text को उसकी जगह से 40 pixels नीचे से ऊपर ले आता है। `extrapolateRight: "clamp"` का मतलब है "frame 15 के बाद, final value पर ही रहो"; इसके बिना text screen से ऊपर निकलता चला जाएगा, जो Remotion code का एक common bug है। `Composition` बताता है कि video 1080 wide, 1920 tall (एक phone screen), 30 fps और 150 frames लंबा है।

ध्यान दो कि timing raw frame numbers में नहीं, seconds times `fps` में लिखी है। Claude से कहो कि इसे ऐसे ही रखे। फिर बाद में frame rate बदलने से हर animation नहीं टूटेगा।

### 5. Timestamps से narration के साथ sync करो

Claude आपका audio सुन नहीं सकता, तो "voice-over से match करो" ऐसा काम नहीं जो वो खुद कर सके। उसकी जगह उसे numbers दो:

1. पहले narration record करो और उसे एक file में save करो।
2. निकालो कि हर sentence किस second पर शुरू होता है। Timestamps देने वाला transcription tool ये करता है, जैसे Whisper; Remotion में इसके लिए helper packages हैं। छह scenes के लिए आप file play करके times खुद भी लिख सकते हो।
3. Claude Code को वो list दो और उससे कहो कि seconds को frames में बदले और उससे हर scene की लंबाई set करे।

```tsx
// Second at which each narration sentence starts, from the transcript, then the end.
const cues = [0, 6.2, 18.5, 30.9, 46.0, 55.4, 60.0];
const fps = 30;
const starts = cues.map((s) => Math.round(s * fps)); // [0, 186, 555, 927, 1380, 1662, 1800]
const lengths = starts.slice(1).map((f, i) => f - starts[i]); // [186, 369, 372, 453, 282, 138]
```

फिर हर scene एक `Series.Sequence` के अंदर जाता है, जिसका `durationInFrames` उसकी लंबाई पर set होता है, और narration उन सबके नीचे play होता है। पूरा video एक दूसरा `Composition` है, id `RagVideo` और `durationInFrames={1800}` के साथ। एक expert detail: **start times** को frames में round करो, फिर subtract करो। अगर आप हर scene की लंबाई अलग-अलग round करोगे, तो छोटी rounding errors जुड़ती जाएँगी और आख़िरी scenes आवाज़ से दूर drift हो जाएँगे।

### 6. बात करके refine करो

क्योंकि video code है, सटीक changes सस्ते हैं: "scene 3 में arrows बाईं तरफ़ से आएँ", "38% को 41% करो"। सिर्फ़ वही element बदलता है। दो आदतें मदद करती हैं:

- **Stills माँगो।** Claude Code भी video देख नहीं सकता। Full render से पहले उससे कहो कि `npx remotion still` से key moments के still frames render करे और उन्हें देखे, या खुद check करो।
- **Remotion Studio में preview करो** (`npx remotion studio`)। ये आपके browser में video play करता है और frame by frame scrub करने देता है।

### 7. Sound और captions जोड़ो

समझाने का काम narration करता है; on-screen text सिर्फ़ key words होने चाहिए। Mute पर देखने वालों के लिए captions जोड़ो। एक अच्छा rule of thumb: हर caption को हर तीन शब्दों के लिए कम से कम एक second screen पर रखो, और कभी भी लगभग डेढ़ second से कम नहीं। आवाज़ के नीचे हल्का music track तभी डालो जब वो मदद करे, और आख़िर में उसे fade out करो।

### 8. Render और export

Remotion आपके computer पर CLI से render करता है, जैसे `npx remotion render RagVideo out/rag.mp4`। इसके लिए Node.js install होना चाहिए, और ये हर frame एक headless browser (जिसकी कोई window नहीं होती) में draw करता है, जिसे Remotion आपके लिए set up करता है। कितना time लगेगा ये आपके computer पर और हर frame कितना draw करता है उस पर depend करता है, तो सौ videos का batch plan करने से पहले अपने पहले render का time नापो।

| कहाँ play होगा | Size (width x height) | Frame rate | कम से कम text size |
|---|---|---|---|
| WhatsApp, Reels, Shorts (phone first) | 1080 x 1920 (9:16) | 30 fps | लगभग 48 px |
| Classroom projector, YouTube, slides | 1920 x 1080 (16:9) | 30 fps | लगभग 36 px |
| ऐसी feed post जो दोनों तरह काम करे | 1080 x 1080 (1:1) | 30 fps | लगभग 44 px |

ये sensible defaults हैं, platform rules नहीं। Motion graphics के लिए 30 fps काफ़ी है; 60 fps render का काम दोगुना कर देता है और text के लिए शायद ही कभी बेहतर दिखता है। Messaging apps अक्सर videos को फिर से compress करते हैं, जिससे छोटा text blur हो जाता है, तो अपने phone पर एक test भेजो। Length और size limits हर app में अलग होती हैं और बदलती रहती हैं, तो जहाँ post करोगे वहाँ की current limit check करो।

### Data से videos

Remotion video एक program है, तो ये data को props के तौर पर ले सकता है, यानी वो inputs जो एक component को मिलते हैं। एक sales team एक spreadsheet से हर region का एक personalised video render कर सकती है; एक teacher scripts की list से हर chapter का एक video render कर सकता है। Claude Code वो loop लिख सकता है जो हर row पढ़ता है और एक file render करता है। 40 versions render करने से पहले, सबसे मुश्किल दो rows (सबसे लंबा नाम, सबसे बड़ा number) render करो और check करो कि कुछ overflow न हो।

## एक example से समझो

Sneha Nagpur के एक college में computer science पढ़ाती हैं। उनके students को RAG (retrieval-augmented generation, जिसमें chatbot पहले documents में search करता है और फिर जवाब देता है) confusing लगता है, तो वो अपने class WhatsApp group के लिए 60-second animation चाहती हैं। वो इसे खुद, एक individual teacher के तौर पर बना रही हैं, और Remotion का free licence individuals के लिए ही है। अगर college इसे officially use करना चाहे, तो college check करेगा कि वो free licence के लिए qualify करता है या उसे company licence चाहिए।

वो एक script लिखती हैं, जिसकी planned timings जुड़कर 60 seconds बनती हैं:

1. (6 s) एक student chat box में "What is the exam syllabus?" type करता है।
2. (12 s) सवाल numbers की एक row, यानी एक "embedding", में बदलता है और documents के एक stack की तरफ़ जाता है।
3. (12 s) मिलते-जुलते तीन paragraphs light up होते हैं और stack से slide होकर बाहर आते हैं।
4. (15 s) सवाल और तीनों paragraphs "LLM" label वाले एक box में flow होते हैं।
5. (10 s) एक जवाब आता है, जिसके नीचे source document का नाम होता है।
6. (5 s) Title card: "RAG = search first, then answer"।

वो timer लगाकर narration ज़ोर से पढ़ती हैं; fit हो जाता है। वो इसे एक शांत कमरे में अपने phone पर record करती हैं और timestamps देने वाले transcription tool से चलाती हैं। उनके असली sentences 0, 6.2, 18.5, 30.9, 46.0 और 55.4 seconds पर शुरू होते हैं, और file 60.0 पर ख़त्म होती है। (ये इस lesson के लिए example numbers हैं, कोई measurement नहीं।) तो उनके असली scene lengths 6.2, 12.3, 12.4, 15.1, 9.4 और 4.6 seconds हैं, plan के करीब लेकिन बराबर नहीं।

Claude Code को उनका prompt:

```text
Create a Remotion project for a 60-second explainer, 1080 x 1920, 30 fps.
Six scenes, one component each, following the attached script.
Narration: public/narration.mp3. Scene start times in seconds:
0, 6.2, 18.5, 30.9, 46.0, 55.4; the video ends at 60.0.
Round start times to frames, then take differences for scene lengths.
Style: flat, white background, purple #5b2a86, one sans-serif font,
0.4 s ease-in-out moves, no bouncing. Text at least 48 px.
Captions under each scene with the key words only.
Keep all colours and sizes in one style file.
```

Claude Code इसे बनाता है, और वो Remotion Studio में preview करती हैं। पहला draft करीब है। वो दो changes माँगती हैं। Scene 2 में embedding के numbers आधे second के अंदर उड़कर आ गए, follow करने के लिए बहुत तेज़, तो वो कहती हैं कि वे 3 seconds में एक-एक करके आएँ। Scene 3 में वो कहती हैं कि हर paragraph अपने document का नाम दिखाए। हर change एक ही component को छूता है।

वो `out/rag.mp4` render करती हैं, ये check करने के लिए कि captions अब भी sharp हैं उसे WhatsApp पर खुद को भेजती हैं, फिर class group में post करती हैं।

अगले semester वो project दोबारा use करती हैं: हर topic के लिए नया script, नया narration और नए start times, उसी style file और scene structure के साथ।

## आम गलतियाँ

**Audio sync का अंदाज़ा लगाना।** Claude से "मेरे voice-over से match करो" कहना fail होता है क्योंकि वो file सुन नहीं सकता। उसे sentence start times दो और उन्हें frames में बदलने दो।

**Clamp करना भूल जाना।** `extrapolateRight: "clamp"` के बिना `interpolate` अपनी range ख़त्म होने के बाद भी चलता रहता है, तो text screen से बाहर drift हो जाता है या zero से आगे fade हो जाता है।

**Screen पर बहुत ज़्यादा text।** लोग एक साथ paragraph पढ़ और सुन नहीं सकते। हर scene में on-screen text कुछ key words तक रखो और detail narration को सँभालने दो।

**बहुत जल्दी गायब होने वाले captions।** हर caption को हर तीन शब्दों के लिए कम से कम एक second रखो। Normal speed पर साथ-साथ पढ़कर check करो।

**Low contrast और flashing।** धूप में phone पर white पर हल्का grey पढ़ा ही नहीं जाता; light background पर dark text use करो या उल्टा। किसी भी चीज़ को एक second में तीन बार से ज़्यादा flash मत होने दो; तेज़ flashing photosensitive epilepsy वाले लोगों में seizures trigger कर सकती है।

**सिर्फ़ motion के लिए motion।** Spinning और bouncing ध्यान भटकाते हैं। Diagram उसी order में बनाओ जिसमें आप समझाते हो, और बाकी कुछ animate मत करो।

**गलत shape।** WhatsApp पर 16:9 video tiny text वाली एक पतली strip की तरह दिखता है। पहले prompt से पहले 9:16 या 16:9 तय करो, क्योंकि बाद में बदलने का मतलब है हर scene का layout फिर से बनाना।

**Numbers check न करना।** Claude आपकी table का कोई figure गलत type कर सकता है। Data video publish करने से पहले हर number पर रुको और उसे source से compare करो।

**Realistic scenes के लिए इसे use करना।** Camera पर लोगों, जगहों और products के लिए Veo जैसा video model use करो।

**Licences को ignore करना।** Royalty-free music और अपनी या licensed images use करो। 3 से ज़्यादा employees वाली company में पहले Remotion का company licence check करो।
