## Idhu enna

Oru **chat assistant** website-layo oru messaging app-layo chat window-la customers-kku badhil sollum. Nalla assistant naalu vishayangalai seiyum:

- general knowledge-la irundhu illaama, business-oda sondha information-la (FAQs, price list, policies, timings) irundhu badhil sollum;
- customer confirm panna appuram, business-oda systems moolamaa common tasks-a (order status, booking) seiyum;
- udhava mudiyalai-nna, vishayam sensitive-aa irundhaa, allathu customer kettaa **oru aalkitta hand over pannum**;
- personal data pathina sattathaiyum messaging platform-oda rules-aiyum follow pannum.

WhatsApp-la oru business **WhatsApp Business Platform**-a use pannum: idhu Meta-voda API, podhuvaa oru provider (Business Solution Provider) moolamaa, illanna neradiyaa Meta-voda Cloud API moolamaa access pannuvaanga. Idhu phone-la irukkura free WhatsApp Business app illa. Platform-la consent, templates, AI use, pricing pathi strict rules irukku, adhai meerinaa oru number limit aagalaam allathu block aagalaam.

```flow
title: Oru incoming WhatsApp message-kku enna aagudhu
Customer message -> Webhook | signature check, dedupe, seekkiramaa 200
Webhook -> Router | model-kku munnaadi code-la run aagum
Router -[emergency vaarthaigal]-> Fixed safe message | koodave staff alert
Router -[complaint allathu aalai kettaa]-> Hand-over | oru summary kooda
Router -[routine]-> Assistant
Assistant -> Retrieval | business-oda sondha sheet
Assistant -> Tools | booking, order status, confirmation-kku appuram
Retrieval -> Customer-oda mozhiyila reply
Tools -> Customer-oda mozhiyila reply
```

## Idhu eppadi work aagudhu

### Knowledge: business-oda sources-la irundhu mattum badhil sollunga

FAQs, fees, doctor schedules, policies ellaathaiyum business-kku sondhamaana oru sheet-la vainga, adhai yaar eppo update panraanga-nnu thelivaa mudivu pannunga (udhaaranamaa, receptionist, dhinamum kaalaiyila). Ovvoru badhilum andha source-la oru row-la irundhu varra maadhiri retrieval use pannunga, endha row use aachu-nnu log pannunga, relevant-aa edhuvum kidaikkalai-nna refuse pannunga: "Andha information enkitta illa; team-a reply panna solliyirukken." WhatsApp-la pora oru thappaana fee-a screenshot eduthu share pannuvaanga, adhanaala guess panradhai vida refuse panradhu eppavume malivu.

### Actions: seiyuradhukku munnaadi confirm pannunga

Unmaiyaana velaiya tools thaan seiyum: oru order-a paarkkuradhu, free slots check panradhu, oru booking create panradhu. Edhaavadhu onnai maathura endha action-kkum munnaadi, details-a thirumba solli oru yes-kkaaga kaathirunga: "Dr Meena, Tuesday 6:30 pm, Lakshmi R-kku. Book pannattumaa?" Prices, discounts, refunds-a model orubodhum mudivu pannaadhu; adhellaam business-oda systems-la irundho oru aalkitta irundho thaan varanum.

### Routing-um hand-over-um: mudhalla code-la mudivu pannunga

"Emergencies-kku hand over pannu"-nnu solra oru prompt mattum podhaadhu: model oru message-a thappaa purinjukkalaam, illanna yaaraavadhu pesi pesi andha rule-a vida vachudalaam. Customers unmaiyila type panra mozhigalla, retrieval-kku munnaadi run aagura code-la andha mudivai vainga:

```python
import re

# Reception staff extend this list from real chats: English, Hinglish, Hindi, Tamil.
URGENT = [r"chest pain", r"can'?t breathe", r"bleed", r"unconscious", r"faint",
          r"seene? me(i?n)? dard", r"saa?ns", r"behosh", r"khoon",
          r"सीने में दर्द", r"सांस", r"बेहोश", r"खून",
          r"nenju ?vali", r"mayakkam", r"ratham", r"நெஞ்சு வலி", r"மயக்கம்", r"ரத்தம்"]
URGENT_RE = re.compile("|".join(URGENT), re.IGNORECASE)
HANDOVER_WORDS = {"complaint", "refund", "lawyer", "consumer court", "chargeback"}

def route(text, state, classify_urgent):
    """Returns 'emergency', 'person' or 'bot'. Runs before any retrieval."""
    if URGENT_RE.search(text):
        return "emergency"
    try:
        if classify_urgent(text):     # a small model call that may answer only yes or no
            return "emergency"
    except Exception:
        return "person"               # if the check fails, fail towards a human
    t = text.lower()
    if (any(w in t for w in HANDOVER_WORDS) or state["failed_answers"] >= 2
            or state.get("asked_for_person")):
        return "person"
    return "bot"
```

Indha list common phrasings-a vegamaa, free-aa pidikkum; adhu miss panradhai classifier pidikkum, udhaaranamaa "kaalaiyila irundhu en paiyanukku udambu sariyilla". Launch-kku munnaadi rendaiyum ovvoru mozhikkum kurainjadhu 20 unmaiyaana phrasings vachu test pannunga. False alarms paravaayilla; aanaa oru emergency miss aaga koodaadhu.

"emergency" vandhaa, ambulance (108), clinic emergency numbers kooda oru fixed, munnaadiye approve panna message-a anuppunga, staff inbox-la andha chat-a urgent-nu flag pannunga, andha chat-kku bot-a pause pannunga. "person" vandhaa, bot-a pause panni, conversation-aiyum oru vari summary-yaiyum staff-kku post panni, eppo badhil varum-nu customer-kitta sollunga.

### Conversation state

Ovvoru message-um thaniyaa thaan varum, adhanaala ovvoru customer-kkum idhai store pannunga: avanga kadaisi message-oda neram (24-hour window-kku), avanga mozhi, fail aana badhilgaloda ennikkai, bot pause-la irukkaa, yes-kkaaga kaathirukkura action edhaavadhu, kadaisi sila turns. Idhai phone number vachu mattum illaama WhatsApp user id vachu key pannunga: 2026-la irundhu, WhatsApp username vachirukkura oru customer business-scoped user id (`from_user_id`) kooda, `from` illaama varalaam. Adhai store panradhu pathiyum, oru `recipient` field moolamaa reply panradhu pathiyum Meta-voda business-scoped user ID guide solludhu.

### Unga number thappikkumaa illaiyaa-nnu mudivu panra WhatsApp rules

**24-hour window.** Customer service window-a Meta oru 24-hour timer-nu vivarikkudhu: customer business-kku message allathu call pannumbodhellaam adhu start aagum, allathu restart aagum. Adhukkulla neenga free-form messages anuppalaam (Meta adhai service messages-nu solludhu). Adhukku veliye, approve aana template mattum thaan anuppa mudiyum. Idhai ovvoru send-kkum munnaadi oru check-aa code pannunga:

```python
WINDOW = 24 * 3600

def can_send_free_form(last_customer_msg_ts, now):
    # WhatsApp timestamps are Unix seconds; compare in UTC, never in local time
    return now - last_customer_msg_ts < WINDOW
```

Offers-kku thaniyaa kelunga, appo oru patient promotions illaama reminders mattum vaangalaam.

**Quality-um limits-um.** Meta ovvoru number-oda quality-aiyum high, medium, low-nu rate pannum, mukkiyamaa customers eppadi react panraanga-nnu vachu: blocks-um reports-um adhai keezhe izhukkum, niraiya per block panra oru template pause aagalaam. Oru rolling 24 hours-la oru business ethanai vevveru customers kooda conversations start pannalaam-nu messaging limit cap pannum. October 2025-la irundhu idhu ovvoru business portfolio-kkum set aagudhu: pudhu portfolios 250-la start aagum, appuram 2,000-kku erum (udhaaranamaa, business verification-kku appuram), appuram 10,000, 100,000, unlimited varai erum, messages high quality-aa irundhu, kadaisi 7 naalla unga limit-la kurainjadhu paadhiya use panniyirundhaa. Samibathula niraiya messages vaanguna oruthharukku pora marketing message-a Meta niruthi vaikkavum koodum (error 131049); adhai udane resend pannaadheenga.

**Platform-la AI.** 15 January 2026-la irundhu ellaa businesses-kkum amalukku vandha Meta-voda WhatsApp Business Solution Terms, AI thaan offer panra primary function-aa (incidental allathu ancillary illaama) irundhaa, Meta mudivu panrapadi, "AI Providers"-a thadai pannudhu, sattam vera maadhiri sonnaa thavira. Thangaloda sondha customers-kku serve panna AI use panra businesses-a idhu baadhikkaadhu-nnu Meta reporters-kitta solluchu. Oru clinic-oda booking, FAQ assistant paravaayilla; "WhatsApp-la yaarukku venumnaalum ChatGPT" koodaadhu.

### Privacy-um DPDP Act-um

Digital Personal Data Protection Act, 2023 ovvoru patient chat-kkum porundhum. Data-va yen, eppadi use panradhu-nnu clinic thaan mudivu pannudhu, adhanaala duties adhukku thaan; neenga, provider, model API ellaarum contract-padi adhukkaaga velai seiyureenga. DPDP Rules November 2025-la notify aachu, notice, security safeguards, breach reporting maadhiri perumbaalaana duties May 2027-la irundhu porundhum. Clients erkanave idhai pathi kekkuraanga, adhanaala ippove idhukku etha maadhiri build pannunga:

- **Mudhal reply-laye notice:** neenga enna collect panreenga, yen, eppadi withdraw panradhu, yaarai contact panradhu.
- **Thanithani consents:** service-um offers-um thanithani. Meta-voda opt-in-um DPDP consent-um rendu thanithani checks, marketing-kku munnaadi rendum venum.
- **Easy-aa withdraw pannalaam:** consent kudukkura alavukke withdraw panradhum easy-aa irukkanum-nu Act solludhu. "STOP"-a code-la, udane handle pannunga.
- **Konjamaa collect pannunga, konjamaa vachukkonga:** card numbers, OTPs, passwords-a orubodhum kekkaadheenga; lab results-a chat-la orubodhum anuppaadheenga; logs-la phone numbers, names-a mask pannunga; chats-oda purpose mudinjadhum adhai delete pannunga.
- **Kuzhandhaigal:** 18 vayasukku keezha irukkura patient-kku, Act-padi oru parent-oda verifiable consent venum (treatment-kke Rules exemption kudukkudhu), adhanaala parent-a contact-aa vachukkonga.

### Website-la

Web chat widget-um idhe maadhiri thaan work aagum, moonu vithiyaasangaloda. Visitors anonymous, adhanaala ovvoru browser-kkum oru random session id kudunga, endha personal record-aiyum kaatturadhukku munnaadi identity-a verify pannunga (registered phone-kku oru OTP). ### Code-la webhook

Meta unga URL-a verify panna oru thadavai call pannum, appuram ovvoru incoming message-aiyum status update-aiyum (sent, delivered, read) post pannum. Unga server seekkiramaa 200 return pannalai-nna, Meta poga poga idaiveliya koottikitte 7 naal varai retry pannum, adhanaala ore message rendu thadavai varalaam. Mudhalla 200 reply pannunga, slow velaiya appuram seiyunga. Oru minimal FastAPI version:

```python
import asyncio, hashlib, hmac, json, os
import httpx
from fastapi import FastAPI, Request, Response, BackgroundTasks, HTTPException

app = FastAPI()
GRAPH_VERSION = "v26.0"          # current when checked, November 2026; see Meta's changelog
VERIFY_TOKEN = os.environ["WA_VERIFY_TOKEN"]
APP_SECRET = os.environ["WA_APP_SECRET"].encode()
TOKEN, PHONE_ID = os.environ["WA_TOKEN"], os.environ["WA_PHONE_NUMBER_ID"]
SEEN = set()                     # use Redis SET NX or a unique column in production

@app.get("/whatsapp")
def verify(request: Request):
    q = request.query_params
    if q.get("hub.mode") == "subscribe" and q.get("hub.verify_token") == VERIFY_TOKEN:
        return Response(q.get("hub.challenge"))
    raise HTTPException(status_code=403)

@app.post("/whatsapp")
async def receive(request: Request, tasks: BackgroundTasks):
    raw = await request.body()
    sig = request.headers.get("X-Hub-Signature-256", "")
    expected = "sha256=" + hmac.new(APP_SECRET, raw, hashlib.sha256).hexdigest()
    if not hmac.compare_digest(sig, expected):
        raise HTTPException(status_code=401)
    for entry in json.loads(raw).get("entry", []):
        for change in entry.get("changes", []):
            for msg in change["value"].get("messages", []):   # status updates have none
                if msg["id"] in SEEN:
                    continue                                  # a repeat delivery
                SEEN.add(msg["id"])
                who = msg.get("from") or msg.get("from_user_id")  # username users: no phone
                if msg.get("type") == "text":
                    tasks.add_task(handle, who, msg["text"]["body"])
    return {"ok": True}          # a fast 200; the slow work runs after this

async def handle(wa_id, text):
    try:                         # a blocking model call must not freeze the server
        answer = await asyncio.wait_for(asyncio.to_thread(assistant_reply, wa_id, text), 20)
    except Exception:
        answer = "Sorry, I could not answer that. I have asked the team to reply."
    async with httpx.AsyncClient() as http:
        await http.post(f"https://graph.facebook.com/{GRAPH_VERSION}/{PHONE_ID}/messages",
                        headers={"Authorization": f"Bearer {TOKEN}"},
                        json={"messaging_product": "whatsapp",
                              ("to" if wa_id.isdigit() else "recipient"): wa_id,
                              "type": "text", "text": {"body": answer[:4000]}})
```

`assistant_reply` ungaloda sondha function: adhu `route`-a run pannum, appuram retrieval, tools. Graph API versions release aagi sumaar rendu varushathula retire aagum (v21.0, 21 January 2027-la remove aagudhu), adhanaala version-a ore constant-la vachu, ovvoru quarter-um Meta-voda changelog-a check pannunga. Ovvoru raw payload-aiyum save pannunga: Meta retry panradhai niruthittaa, tholanja message thirumba kidaikkaadhu.

### Ovvoru maatrathukkum munnaadi evaluate pannunga

## Oru worked example

Madurai clinic-kku dhinamum noottrukkanakkaana WhatsApp messages varudhu: timings, doctor availability, fees, lab report status, bookings. Oru provider kooda n8n-la build panna assistant, patient-kku etha maadhiri Tamil-layo English-layo reply pannum. Adhu:

- reception dhinamum kaalaiyila update panra sheet-la irundhu timings, fees, doctor schedules-kku badhil sollum;
- booking system-a check panni, mudhalla name, doctor, date, time-a confirm panni book pannum;
- registered phone-kku oru OTP-kku appuram, lab report ready-aa illaiyaa-nnu sollum, aanaa results-a chat-la orubodhum anuppaadhu;
- endha model call-kkum munnaadi symptoms, emergencies-a fixed emergency message-kku route pannum.

**Nadaimuraiyila.** "Appa ku nenju vali" (appaavukku nenju vali) Tamil rule kooda match aagum. Bot 108, clinic-oda emergency line kooda fixed message-a anuppi, chat-a urgent-nu mark panni, staff adhai close panra varai amaidhiyaa irukkum. Bill thappu-nnu ninaikkura oru patient-kku idhu varum: "Rendu working hours-kkulla oru staff member reply pannuvaanga." ## Podhuvaa panra thappugal

**Product**

- **General knowledge-la irundhu badhil solradhu.** Model nambura maadhiri oru fee-a karpanai pannidum. Badhilgalai ground pannunga; edhuvum match aagalai-nna refuse pannunga.
- **Sheet-kku owner illaadhadhu.** Pazhaiya timings, prices ellaarum paarkkura idathula thappaana badhilgalaa maarum.
- **Oru aalkitta poga easy-aana vazhi illaadhadhu.** Frustrate aana customers vittu poyiduvaanga, publicly complain pannuvaanga.
- **Neelamaana, email maadhiri replies.** Makkal phones-la padikkiraanga; sila varigalla mudichu "innum details venumaa?"-nu offer pannunga.
- **Medical, legal, financial advice kudukkuradhu.** Hand over pannunga.

**Platform-um sattamum**

- **Opt in pannaadhavangalukku message panradhu**, allathu reminders-kku mattum othukkittavangalukku offers anuppuradhu. Blocks quality-a keezhe izhukkum.
- **Oru promotion-a "utility"-nu solradhu.** Meta adhai recategorise pannum, business-a restrict pannalaam.
- **24-hour window-kku veliye free-form messages.** Adhu fail aagum; oru template use pannunga.
- **Business Platform-la oru general AI chatbot-a pitch panradhu.**
- **Meta opt-in-a DPDP consent-aa ninaikkiradhu.** Rendum thanithani checks.

**Code**

- **Hand-over rules prompt-la mattum**, allathu English-la mattum.
- **Signature check-a skip panradhu.**
- **200-kku munnaadi slow velai**, idhanaala retries-um duplicate answers-um varum.
- **Async handler-kkulla oru blocking model call**, idhu matha ellaa messages-aiyum niruthi vachudum.
- **Phone number mela mattum state-a key panradhu**, username use panra customers-kku idhu udainjudum.
