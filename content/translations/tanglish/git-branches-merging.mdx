## Idhu enna

Git-la oru **branch**-na oru commit-a suttikkaattura label. Oru branch-la pudhu commit pannumbodhu, label adhukku munnaadi nagarum. Branch-na adhu mattum thaan, adhanaala uruvaakkuradhu udanadi, teams ovvoru change-kkum onnu uruvaakkuvaanga: bug fix, feature, experiment.

Shared branch, perumbaalum **main**-nu solluvaanga, eppavum work aaganum, yen-na ellarum adhu mela thaan build panraanga, adhu thaan deploy aagum. Adhanaala main-la neradiyaa velai seiyaadheenga. Oru branch uruvaakki, angaiye unga change-a build panni test panni, ready aanadhum thirumba konduvaanga.

Velaiya thirumba konduvara rendu vazhi irukku:

- **Merge** rendu history lines-a serkkum. Neenga branch pannadhukku appuram main nagarndhirundhaa, Git rendu parents-oda oru **merge commit** uruvaakkum. History enna nadandhudhu-nu exact-aa kaattum, side branch-um serthu.
- **Rebase** unga commits-a vera oru branch-oda mela replay pannum, adhoda latest commit-la irundhu aarambichadhu maadhiri. History oru nerana line-aagum, padikka easy, aana unga commits-ku pudhu ids kidaikkum.

Rendum mudivula ore code-la thaan mudiyum. History eppadi irukku-nu, yaarukku safe-nu thaan difference.

## Idhu eppadi work aagudhu

Oru team-la rojaa panra loop ippadi irukkum:

```flow
title: Oru feature branch, aarambam-la irundhu merge varaikkum
Update main | git switch main, git pull -> New branch | git switch -c feature/otp
New branch -> Commit small steps | git add, git commit
Commit small steps -> Push the branch | git push -u origin feature/otp
Push the branch -> Pull request | review and checks
Pull request -[main moved on]-> Bring main in | merge main, or rebase onto main
Bring main in -> Pull request
Pull request -[approved, green]-> Merge into main
Merge into main -> Delete the branch
```

**Uruvaakki switch panradhu.** `git switch -c feature/otp` neenga irukkura idathula oru branch-a uruvaakki, ungala adhuku konduvarum. `git switch main` thirumba kootittu pogum. `git branch` branches-a list pannum; ippo irukkura branch-ku star irukkum.

**Merge panradhu.** Main-la irundhu, `git merge feature/otp` branch-a konduvarum. Neenga branch pannadhukku appuram main nagaralannaa, Git **fast-forward** pannum: main-oda label-a unga kadaisi commit-ku nagarthidum. Main nagarndhirundhaa, Git oru merge commit uruvaakkum.

**Conflicts.** Rendu pakkamum oru file-la ore lines-a maathirundhaa, Git nindru file-a mark pannum:

```text
<<<<<<< HEAD
OTP_EXPIRY_SECONDS = 300
=======
OTP_EXPIRY_SECONDS = 120
>>>>>>> feature/otp
```

`=======`-ku mela irukkuradhu unga current branch-la irukkuradhu; keezha irukkuradhu varra change. File-a neenga venum-nu ninaikkura version-ku edit pannunga, markers-a delete pannunga, adhula `git add` odunga, commit pannunga. Conflict error illa. Git thaniyaa answer panna mudiyaadha oru kelvi-a ungakitta kekkuradhu.

**Rebase panradhu.** Unga branch-la, `git rebase main` unga commits-a edhuthu pakkathula vechidum, unga branch-a main-oda tip-ku nagarthi, avatha onnu onnaa replay pannum. Edhavadhu conflict aanaa Git nikkum; neenga file-a fix panni, `git add` panni `git rebase --continue` odunga. `git rebase --abort` ellaathaiyum munnaadi irundha maadhiri thirumba vechidum.

| | Merge | Rebase |
| --- | --- | --- |
| History | Rendu lines-aiyum vechukkum, merge commit serkkum | Oru nerana line |
| Commit ids | Maaradhu | Unga commits-ku pudhu ids |
| Shared branches-la safe | Aama | Illa: yaarukkum illaadha commits-ku mattum |
| Conflicts | Merge-la oru thadavai resolve pannuveenga | Ovvoru commit-kum resolve pannanum |
| Edhukku nallaadhu | Mudinja branch-a main-ku konduvara | Review-ku munnaadi unga branch-a update panna |

Neraya teams rendaiyum serthu use pannuvaanga: velai seiyum podhu unga branch-a current-aa vechukka rebase, pull request main-ku pogum podhu merge (perumbaalum **squash merge**, adhu branch-a oru commit-aa maathidum).

## Oru worked example

Priya Bengaluru-la oru fintech startup-la login service-la velai seiyraanga. Avanga ticket: OTP expiry-a ayndhu nimishathula irundhu rendu nimishama kuraikkanum.

Avanga fresh main-la irundhu aarambichu oru branch uruvaakkuraanga:

```bash
git switch main
git pull
git switch -c feature/otp-expiry
```

`config.py`-la `OTP_EXPIRY_SECONDS`-a maathi, test-a update panni, rendu thadavai commit pannuraanga: oru commit change-ku, oru commit test-ku. Branch-a push panni oru pull request open pannuraanga.

Avangaloda pull request review-ku kaathirukkum podhu, avanga teammate Arjun adhe line-la oru change merge pannitaanga: oru regulator guideline pathi comment-oda value-va 300 seconds-ku maathitaanga. Priya-oda pull request ippo "This branch has conflicts"-nu kaattudhu.

Avanga branch avangaloda sondham, yaarum adha pull pannala, adhanaala rebase pannuraanga:

```bash
git fetch origin
git rebase origin/main
```

Git avanga mudhal commit-a replay panni nikkudhu: `config.py`-la conflict. Arjun-oda comment-a padichu, avanga lead-kitta check panni, indha flow-ku regulator 120 seconds allow pannum-nu theriyuthu. Avanga value-va vechukittu, Arjun-oda comment-aiyum vechukittu, markers-a neekki continue pannuraanga:

```bash
git add config.py
git rebase --continue
git push --force-with-lease
```

`--force-with-lease` GitHub-la avanga branch-a replace pannum, aana idaiyila yaarum adhula push pannalannaa mattum. Rebase-ku appuram push panna idhu thaan safe vazhi. Pull request green-aa, conflict illaama irukku; approve aagi, oru clean commit-aa main-la squash-merge aagudhu, avanga branch-a delete pannuraanga.

## Podhuvaa panra thappugal

- **Main-la neradiyaa velai seiyradhu.** Oru bad commit ellaroda base-aiyum udaikkum. Oru line fix-kum branch panunga.
- **Romba naal irukkura branches.** Moonu vaaram irukkura branch vedhanaiyaana conflicts-a serthukkum. Sinna changes-a adikkadi merge pannunga.
- **Shared branch-a rebase panradhu.** Teammates already pull panna commits-a rewrite pannaa, avanga kitta match aagaadha copies thaan irukkum. Unga sondha, share pannaadha velaiya mattum rebase pannunga.
- **Simple `git push --force`.** Adhu teammate-oda commits-a azhichidum. `--force-with-lease` use pannunga, unga sondha branch-la mattum.
- **Conflicts-a kannai moodikkittu resolve panradhu.** Rendaiyum padikkaama "mine", "theirs" pick pannaa yaaroda fix-aiyaavadhu silent-aa undo pannidum. Rendu pakkathaiyum padinga, apram tests odunga.
- **Conflict markers-a commit panradhu.** Commit pannuradhukku munnaadi `<<<<<<<`-a search pannunga. Neraya teams idhukku CI-la oru check serppaanga.

## Practice pannunga

1. Oru file irukkura oru practice repository uruvaakkunga. Rendu branches-a uruvaakki, rendum line 3-a maathunga, onnu main-la merge pannunga, apram matha onnu merge panni conflict-a resolve pannunga.
2. Moonu sinna commits irukkura oru branch uruvaakkunga. Adhu irukkum podhu, main-la oru commit serkkunga. Unga branch-a main mela rebase panni, munnaadiyum pinnaadiyum `git log --oneline --graph --all` paarunga.
3. Oru rebase nadukkula `git rebase --abort` try pannunga, ellaam munnaadi irundha maadhiri thirumba vandhudhaa-nu confirm pannunga.
4. Interview-la solra maadhiri, eppo merge pannuveenga, eppo rebase pannuveenga-nu oru nimishathukkulla sathamaa sollunga.
