## Idhu enna

**Agent SDK**-na oru library, adhikka oru model provider-kitta irundhu varum, adhu ready-aana agent loop tharum: messages anuppu, model ketkura tools-a odu, results-a thirumba kudu, thirumba thirumba seiyyu. Perumbaalaana SDKs-la tracing, guardrails, session storage, oru agent velaiya innoru agent-kitta hand off panra vazhigal irukkum. Examples: OpenAI-oda Agents SDK, Anthropic-oda Claude Agent SDK; Google-um matha-vangalum idhe maadhiri kits tharaanga.

**Sub-agent**-na innoru agent start panna agent, oru task-oda oru pagudhiya adhoda sondha pudhu context-la seidhu, oru summary mattum thirumba kudukkum. **Multi-agent system**-na pala agents serndhu velai seiyura entha design-um: oru lead agent workers-kku delegate panradhu, agents oru conversation-a nadula maathi kudukkuradhu, illa specialists oruththar velaiya innoruththar review panradhu.

```flow
Lead agent | 5 research areas plan pannum -> Financials | filings tool
Lead agent -> Legal | court search
Lead agent -> Management | news search
Lead agent -> Market | reports tool
Lead agent -> ESG | news search
Financials -[oru summary, adhigamaa 400 words, sources-oda]-> Lead merges, spots conflicts, asks one follow-up
Legal -> Lead merges, spots conflicts, asks one follow-up
Management -> Lead merges, spots conflicts, asks one follow-up
Market -> Lead merges, spots conflicts, asks one follow-up
ESG -> Lead merges, spots conflicts, asks one follow-up
Lead merges, spots conflicts, asks one follow-up -> Brief
```

Ovvoru sub-agent-um adhoda sondha pudhu context-oda parallel-aa odum.

Indha lesson-la Hyderabad-la oru consulting firm mid-sized manufacturers pathi due-diligence briefs produce panradha follow pannuvom.

## Idhu eppadi work aagudhu

**SDKs ungalukku enna meechu pannum.** Loop-ae irubadhu line thaan; payan adha sutthi irukkura ellaam: retries, streaming, parallel tool calls, ovvoru step-aiyum tracing, input-layum output-layum guardrails, hand-offs, sessions. Sila SDKs file editing, shell commands, web search maadhiri built-in tools-aiyum, oru permission system-oda tharum.

**Choose panradhu.** Moonu podhuvaana vazhigal:

- *Ungaloda sondha loop*: task narrow-aa irundhaa, full control venum, dependencies kammiyaa venum-naa.
- *Vendor SDK*: client andha vendor-oda commit aagi, pilot-a vegamaa venum-naa, especially adhoda built-in tools set aanaa.
- *Graph framework* (LangGraph maadhiri): explicit control flow, approval-ku durable pauses, model-vendor independence venum-naa.

SDK oru vendor-oda models-oda evvalavu lock-in aagi irukku, sessions-a eppadi store pannudhu, adhoda traces client-oda observability tools-ku export aagudha-nu check pannunga.

**Sub-agents.** Adhoda unmaiyaana payan context isolation. Oru market-a research panra lead agent aindhu sub-agents-a start pannalaam, ovvonnum oru competitor-a adhoda sondha muzhu context window-la search pannum, lead aindhu oru-page summaries vaangum. Lead padicha nooru pages-a paakkavae paakkaadhu, adhanaala adhoda sondha context clean-aa irukkum. Sub-agents parallel-aavum odalaam, wall-clock time kuraiyum.

**Selavu.** Ovvoru sub-agent-kum adhoda sondha prompt, tools, history irukku, adhanaala token use perugum, adhikka oru agent-a vida pala madangu. Coordination-um fail aagalaam: rendu workers oru velaiya rendu thadava pannalaam, illa oru summary mukkiyamaana detail-a vittudalaam. Multi-agent designs research maadhiri broad, parallel, read-heavy tasks-ku payan tharum; oru codebase-a edit panradhu, oru form-a fill panradhu maadhiri, ovvoru step-um munnaadi step-a sarndhu irukkura tightly coupled tasks-ku adhikka help panna maattaanga.

**Moonu vazhigal compare:**

| Vazhi | Eppo nallaa | Edhukku jaakkirathai |
| --- | --- | --- |
| Ungaloda sondha loop | Narrow task, full control, kammi dependencies | Tracing, retries, sessions-a neengalae build pannanum |
| Vendor SDK | Oru vendor-oda commit, vegamaana pilot, built-in tools set | Lock-in; trace export-a check pannunga |
| Graph framework | Explicit control flow, durable approval pauses, vendor independence | Kathukka innum concepts |

**Delegation brief ezhudhuradhu.** Ovvoru sub-agent-oda instructions-layum area-vum adhoda boundaries-um irukkanum ("2020-la irundhu Indian courts-la legal cases; regulatory filings illa, adha innoru agent paakkum"), adhoda tools, headings-oda output format, oru word limit, ovvoru claim-kum oru source link serkkanum-nu oru rule. Mudivula oru sinna "open questions" list kelunga, appadi irundhaa edhu uncertain-nu lead-ku theriyum. Theliva irukkura briefs rendu romba common failures-a thadukkum: overlapping velai, mukkiyamaana oru detail-a thavara vidura summaries.

**Pirichadhu payan thandhucha-nu measure panradhu.** Adhe paththu requests-a rendu vazhilayum odunga. Wall-clock time, mothha tokens, cost, oru reviewer fixed rubric-la kudukkura quality score record pannunga. Vegamaa, nallaa irundhu, aana naalu madangu cost-aa irundhaalum adhu sariyaa irukkalaam, inga maadhiri, ovvoru brief-um naalu analyst neraththa maathumbodhu. Mudivu numbers-oda ezhudhappadanum.

**Plain code-la oru lead-um sub-agents-um.** Pattern-a paaka framework thevai illa. Lead briefs ezhudhum, sub-agents adhoda sondha pudhu context-oda parallel-aa odum, lead avanga sinna reports-a mattum paakkum:

```python
import asyncio
import anthropic

client = anthropic.AsyncAnthropic()
LEAD, WORKER = "claude-opus-5-5", "claude-sonnet-5-5"     # check the docs for current names

async def sub_agent(brief, max_tokens=1200):
    try:
        r = await asyncio.wait_for(client.messages.create(
            model=WORKER, max_tokens=max_tokens,
            system="You research one narrow area. Report in at most 200 words with a source link per claim, "
                   "then list open questions.",
            messages=[{"role": "user", "content": brief}]), timeout=120)
        return "".join(b.text for b in r.content if b.type == "text")
    except Exception as err:
        return f"FAILED: {type(err).__name__}"

async def research(question, areas):
    briefs = [f"Question: {question}\nYour area: {a}. Stay inside it; other agents cover the rest."
              for a in areas]
    reports = await asyncio.gather(*(sub_agent(b) for b in briefs))
    joined = "\n\n".join(f"## {a}\n{r}" for a, r in zip(areas, reports))
    final = await client.messages.create(
        model=LEAD, max_tokens=1500,
        messages=[{"role": "user", "content": f"Write a brief answering: {question}\n"
                   "Use only these reports. Say plainly if any area FAILED.\n\n" + joined}])
    return "".join(b.text for b in final.content if b.type == "text")

# asyncio.run(research("EV subsidy policies", ["Maharashtra", "Karnataka", "Tamil Nadu"]))
```

Unmaiyaana system-la ovvoru sub-agent-um oru single call-ku badhila adhoda sondha tool loop-a (search, fetch, read) odum, aana shape adhe thaan: briefs veliya pogum, sinna reports thirumba varum, lead-oda context sinnadhaave irukkum.

**Token bill.** Ovvoru sub-agent-um adhoda sondha instructions, tool definitions, reading-a sumakkum. Anthropic-oda multi-agent research system oru normal chat-a vida kittathatta 15 madangu tokens use pannudhu-nu report pannaanga. Oru analyst-oda rendu naala meechu panra research brief-ku adhu worth aagalaam; oru support reply-ku adhu adhikka worth illa.

**SDK-a concrete-aa pick panradhu.** Vendor SDKs (OpenAI-oda Agents SDK, Anthropic-oda Claude Agent SDK, Google-oda Agent Development Kit, matha-vai) mukkiyamaa naalu idathula maarum. Commit panradhukku munnaadi ovvondraiyum oru naal spike-la check pannunga:

| Kelvi | Yen mukkiyam |
| --- | --- |
| Matha vendors-oda models-a use panna mudiyuma? | Appuram rewrite illaama maaralam |
| Sessions-um state-um enga irukku? | Data residency, restarts |
| Traces OpenTelemetry-ku illa ungaloda tracing tool-ku export aagudha? | Systems-a sutthi oru view |
| Built-in tools-ku permissions-um approvals-um eppadi set aagudhu? | Production-la safety |

**Context isolation rendu pakkamum vettum.** Oru sub-agent adhoda brief-a mattum paakkum, adhanaala lead pass pannaama, innoru sub-agent kandupidichadha adhu use panna mudiyaadhu. Oru area-la velai innoru area-va sarndhu irundhaa, andha steps-a vandha ordera odunga, illa lead-ku follow-up briefs anuppa rendaavadhu round kudunga.

**Browser-la try pannunga.** Sub-agents parallel-aa odum, adhanaala mothha neram migavum neram edukkura onnoda neram, kootturadhu illa. Delays-a maathunga.

```python
import asyncio, time

async def sub_agent(area, seconds):
    await asyncio.sleep(seconds)              # pretend research
    return f"{area}: 3 findings"

async def lead():
    t0 = time.perf_counter()
    reports = await asyncio.gather(sub_agent("Maharashtra", 0.3), sub_agent("Karnataka", 0.5), sub_agent("Tamil Nadu", 0.2))
    print(reports)
    print(f"took {time.perf_counter() - t0:.1f} s, not {0.3 + 0.5 + 0.2:.1f} s")

await lead()
```

## Oru worked example

Hyderabad consulting firm mid-sized Indian manufacturers pathi due-diligence briefs venumnu virumbudhu: financials, legal cases, management, market, ESG news.

Oru single agent 40 nimisham edukkudhu, legal research nadula adhikka context theerndhu, munnaadi eduththa financial notes-a ilakkudhu. Neenga redesign pannareenga:

- Oru **lead agent** request-a padichu, aindhu research areas-oda oru plan ezhudhi, ovvoru area-kum oru **sub-agent**-a parallel-aa start pannum.
- Ovvoru sub-agent-kum adhukku thevaiyaana tools mattum: legal-kku court-records search, financial-kku filings tool. Ovvonnum adhigamaa 400 words summary-yai source links-oda thirumba kudukkum.
- Lead summaries-a merge pannum, conflicts-a kandupidikkum (rendu sources revenue pathi maaruthal), financial sub-agent-kitta oru follow-up kelvi kekkum.

Wall-clock time 9 nimishama kuraiyudhu, coverage-um nalla aagudhu. Token use 3.5 madangu aagudhu, firm adha ethukkudhu, yenna ovvoru brief-um rendu naal analyst velaiya maathudhu. Firm-kku andha provider-oda already oru enterprise contract irukku, adhoda tracing ovvoru sub-agent-oda steps-aiyum kaattudhu, adhu avanga quality team-ku thevai, adhanaala vendor-oda SDK-a use pannareenga.

| Measure | Single agent | Lead + aindhu sub-agents |
| --- | --- | --- |
| Oru brief-ku neram | Sumaar 40 nimisham | Sumaar 9 nimisham |
| Context overflow | Adhikka, legal research-la | Illai |
| Token use | Baseline | Sumaar 3.5 madangu |
| Aindhu areas-oda coverage | Samamillaadhadhu | Muzhumaiyaanadhu |

## Podhuvaa panra thappugal

- **Default-aa multi-agent.** Oru agent-oda aarambinga. Context overflow-vo parallelism-o measure panna problem-aa irundhaa mattum piringa.
- **Theliva illaadha delegation.** "Legal side-a research pannu" overlap-a tharum. Ovvoru sub-agent-kum precise scope, output format, length limit kudunga.
- **Token cost-a ignore panradhu.** Task-ku cost-a munnaadiyum pinnaadiyum measure pannunga; multi-agent adha perukkalaam.
- **Gavanikkaama lock-in aagradhu.** Client model vendors-a maaralaam-na, ungaloda code evvalavu oru SDK-a sarndhu irukku-nu check pannunga.
- **Agents-ku naduvula traces illaadhadhu.** Oru answer thappaa irundhaa, edhu sub-agent edhu claim-a kudutthuchu-nu paakka mudiyanum.
- **Ovvoru sub-agent-kum limits illaadhadhu.** Oru maattikkitta worker muzhu budget-aiyum saapidum.
- **Oru pagudhi fail aanaa muzhu task-aiyum fail panradhu.** Gap-a report pannunga, meedhiya deliver pannunga.

## Oru agent better-aa irukkura neram

- **Tightly coupled velai**, oru codebase-a edit panradhu, oru form-a fill panradhu maadhiri, ovvoru step-um munnaadi step-a sarndhu irukkum.
- **Sinna tasks**, oru agent konjam steps-la mudikkum.
- **Tight budgets**: pala agents token cost-a perukkum.
- **Strict latency needs**, parallelise panna konjam thaan irukkum.

## Demo-la irundhu production-ku

- **Lead-aiyum ovvoru sub-agent-aiyum** oru run id-kku keezha trace pannunga.
- **Per-agent, muzhu-task budgets** tokens, neram, panam-kku set pannunga.
- **Briefs-a versioned templates-aa vainga**, prompts maadhiri test pannunga.
- **Maatrangalukku munnaadiyum pinnaadiyum** cost-layum quality-layum single-agent baseline-oda compare pannunga.
- **Partial failure-kku plan pannunga**: oru area-a cover panna mudiyaama pona theliva user messages.
