## Idhu enna

**Software design**-na oru program-a parts-aa eppadi pirikkiradhu, andha parts onnukkonnu eppadi pesikkum-nu mudivu panradhu. Perumbaalaana nalla designs-kku adiyila rendu ideas irukku:

- **Cohesion**: oru part-kkulla irukkuradhellaam evvalavu nerukkamaa onnaa serudhu-ngradhu. High cohesion-na ovvoru part-um oru velai seiyudhu, adhukkulla irukkura ellaamae andha velaikkaaga thaan.
- **Coupling**: oru part innonnoda details-a evvalavu saarndhirukku-ngradhu. Loose coupling-na mathadhai thodaamalae oru part-a maathalaam.

Nalla design-na high cohesion-um loose coupling-um. Oru chinna maatram paravumbodhu bad design-a neenga unaralaam: email template-a maathanum-na, eppadiyo model-a call panra code-aiyum edit panna vendiyirukku.

Perumbaalaana software-a vida AI velaiyila idhu innum adhigamaa mukkiyam. Orae varushathula oru team model providers-a maathalaam, privacy-sensitive-aana oru customer-kkaaga oru self-hosted model serkkalaam, vector store-aiyum maathalaam. Model call irubadhu idangalla pudhainjirundhaa, ovvoru maatramum risk-aana oru rewrite. Oru chinna boundary-kku pinnaadi irundhaa, ovvoru maatramum oru pudhu file-um oru test-um thaan.

Anga poi serradhukkaana anju pirabalamaana guidelines thaan **SOLID principles**. Robert C. Martin idhai object-oriented code-kkaaga thoguthaaru, aanaa indha ideas saadhaarana Python functions-kkum modules-kkum kooda velai seiyum. Idhai manappaadamaa oppikka vendiyadhilla. Idhu thadukkura problems-a unmaiyaana code-la kandupidikka therinjaa podhum.

## Idhu eppadi velai seiyudhu

### Anju principles, saadhaarana vaarthaigalla

| Principle | Saadhaarana vaarthaigalla | Neenga idhai meerureenga-nnu kaattura adaiyaalam |
| --- | --- | --- |
| **S**ingle responsibility | Oru module allathu class, maarradhukku orae kaaranam | PDFs padikkura, model-a call panra, email anuppura orae file |
| **O**pen-closed | "Open for extension, closed for modification": aerkanavae velai seiyura code-a edit pannaama, pudhu code serthu behaviour serkkanum | Ovvoru pudhu provider-kkum business logic-kkulla innoru `elif` |
| **L**iskov substitution | Oru interface-oda endha implementation-um, andha interface edhirpaarkkappadura ellaa idathulayum velai seiyanum | Matha clients text return panra idathula oru client `None` return pannudhu |
| **I**nterface segregation | Orae oru periya interface illaama, niraiya chinna, focused interfaces | Ovvoru part-um rendu methods thaan use pannaalum, ellaa part-um saarndhirukkura oru periya `Storage` class |
| **D**ependency inversion | High-level logic oru kurippitta library-a illaama, thanakku sondhamaana oru interface-a saarndhirukku | Business logic-kkulla aazhamaa `openai`-a import panni call panradhu |

**Open-closed-na "oru file-aiyum edit pannavae koodaadhu"-nu artham illa.** Adikkadi maarura code (endha provider, endha output format) pudhu pieces-aa serkkappadanum, velai seiyura core asaiyaama irukkanum-ngradhu thaan artham. Engayaavadhu oru idam endha piece-a use panradhu-nnu innum therndhedukkanum. Andha choice-a logic muzhukka parappaama, program-oda orathula orae idathula vainga.

**Liskov promises pathinadhu, class names pathinadhu illa.** Oru interface-na oru promise: "Enakku oru prompt string kudunga, naan oru text string return panren". Adhai udaikkura oru client idho:

```python
class CheapClient:
    def complete(self, prompt: str) -> str | None:
        try:
            return self._call_api(prompt)
        except TimeoutError:
            return None   # every caller now has to check for None
```

Idhukku sariyaana method name irukku, adhanaala swap pannalaam-nu thonum. Aanaa matha clients-kkaaga ezhudhina code `reply.splitlines()` pannudhu, indha client mudhal thadavai time out aagumbodhae adhu `AttributeError`-oda crash aagum. Oru implementation kammiyaa aethukkumbodhum (mathavai aethukkura neelamaana prompts-a idhu marukkudhu) allathu adhoda paadhi methods-kku "not supported" raise pannumbodhum idhae trap varum. Promise-a kaappaathunga: caller aerkanavae handle panra oru error-a raise pannunga, allathu client-kkullaye retry pannunga.

### Dependency injection

SOLID-la perumbaalaanadhukku pinnaadi irukkura practical tool **dependency injection** thaan. Oru function thanakku thevaiyaanadhai thaanae create panradhukku badhilaa, veliyila irundhu vaangikkudhu:

```python
from typing import Protocol

class ModelClient(Protocol):
    def complete(self, prompt: str) -> str: ...

def summarise(text: str, client: ModelClient) -> str:
    return client.complete(f"Summarise in 3 bullet points:\n{text}")
```

`Protocol` oru shape-a vivarikkudhu. Porundhura `complete` method irukkura endha class-um, edhula irundhum inherit pannaamalae fit aagum, mypy maadhiri oru type checker ungalukkaaga adhai check pannum. Ippo `summarise`-kku adhu endha provider-a use pannudhu-nnu theriyaadhu, adhai pathi kavalaiyum illa. Production oru real client-a pass pannudhu, tests oru fake-a pass pannudhu, provider maathuradhu-nnaa `summarise`-a edit panradhu illa, oru pudhu class ezhudhuradhu thaan.

Direction-a gavaninga. Interface business logic-kku sondhamaanadhu: `summarise` thanakku enna venum-nu solludhu. Provider library velippakkam thallappadudhu. Dependency inversion-la irukkura "inversion" adhu thaan.

### Model interface evvalavu thin-aa irukkanum?

Mela irukkura code-a paarthu oru experienced engineer kekkura kelvi idhu thaan. Unmaiyaana provider APIs ellaam orae maadhiri illa. Messages eduthukkuradhu, tools call panradhu, structured JSON return panradhu, tokens stream panradhu, prompts cache panradhu, idhulellaam avai vithiyaasappadudhu. Orae method irukkura `complete(prompt) -> str` interface idhu ellaathaiyum maraichidudhu. Adhanaala neenga oru unmaiyaana trade-off-a sandhikkireenga:

- **Romba thin**-aa irundhaa, features-a izhappeenga. Unga product-kku tool calling venum-naa, oru plain text interface-aala adhai solla mudiyaadhu.
- **Romba wide**-aa irundhaa, provider details veliyae kasiyum. `messages`, `tools`, `response_format`, `stream` irukkura oru interface unmaiyila oru provider-oda API-a copy pannadhu thaan, adutha provider adhula fit aagaadhu.

Perumbaalaana cases-a moonu rules handle pannum:

1. **Interface-a oru chat call-a vechu illa, unga product-kku enna venumo adhai vechu shape pannunga.** Unga app invoice fields-a extract pannudhu-nnaa, interface `extract_invoice(text) -> Invoice`-aa irukkalaam, idhula `Invoice` ungaloda sondha typed class. Appo ovvoru adapter-um ullukkulla structured output-kku adhoda provider-oda best feature-a use pannum, unga core logic-kku oru clean, typed result kidaikkum.
2. **Provider-specific features adapter-kkullaye irukkattum.** Prompt caching allathu oru special retry header adapter-oda vishayam. Unga product-kku thevaiyaana edho onnai oru provider unmaiyilaeyae seiya mudiyalai-nnaa, adhu oru product decision; "not supported" error-kku pinnaadi maraikka vendiya vishayam illa.
3. **Oru gateway-a yosinga.** LiteLLM maadhiri libraries-um, OpenAI-style chat format-la pesura servers-um (udhaaranamaa vLLM) niraiya models-a orae maadhiri theriya vaikkudhu, adhanaala unga adapter chinnadhaavae irukkum. Appo neenga gateway-aiyum, adhoda ellaa models-um share panra features-aiyum saarndhiruppeenga. *LLM gateways* lesson idhai cover pannudhu.

Oru summariser-kku, `complete(prompt) -> str` thaan sariyaana size.

```flow
title: Oru AI app-la ports and adapters
Wiring at start-up | settings-a padikkudhu, adapters-a create pannudhu -[oru client-a ulla pass pannudhu]-> Core logic | prompts, parsing, rules
Core logic -[call pannudhu]-> ModelClient port | core-kku sondhamaana interface
ModelClient port -[idhula implement aagudhu]-> HostedClient | provider SDK-a wrap pannudhu
ModelClient port -[idhula implement aagudhu]-> SelfHostedClient | HTTP moolamaa vLLM-a call pannudhu
ModelClient port -[idhula implement aagudhu]-> FakeClient | tests-la use aagudhu
```

### Ports and adapters

Idhae idea-a muzhu codebase-kkum apply pannaa, adhukku oru peyar irukku: **ports and adapters**, idhai **hexagonal architecture**-num solluvaanga. Alistair Cockburn idhai vivarichaaru. Interviewers rendu peyaraiyum use pannuvaanga.

- **Core logic**-na product enna seiyudho adhu: oru ticket-a classify panradhu, oru prompt-a build panradhu, oru answer-a score panradhu. Idhu veliyila irundhu edhaiyum import pannaadhu.
- **Ports**-na core-kku thevaiyaana chinna interfaces: oru model client, oru document store, oru notifier.
- **Adapters** unmaiyaana services vechu ports-a implement pannudhu: oru provider-oda SDK, oru vector database, email allathu WhatsApp.
- **Wiring** orathula irukku (web app-oda start-up, command-line entry point): adhu settings-a padichu, real adapters-a create panni, avatrai ulla pass pannudhu.

Unga design-kku oru quick test: network illaama, API key illaama, database illaama core logic-a oru unit test-la otta mudiyumaa? Mudiyum-naa, boundaries sariyaana idathula irukku.

### Inheritance-a vida composition

Retries, logging, cost tracking maadhiri behaviour serkkanum-naa, udanae thonura vazhi oru subclass: `RetryingOpenAIClient(OpenAIClient)`. Appuram `RetryingSelfHostedClient`, `LoggingRetryingOpenAIClient` ellaam venum, ovvoru combination-kkum classes ennikkai valarndhutae pogum. **Composition**-na adhukku badhilaa wrap panradhu:

```python
import time

class RetryingClient:
    """Wraps any ModelClient and retries failed calls."""

    def __init__(self, inner: ModelClient, attempts: int = 3):
        self._inner, self._attempts = inner, attempts

    def complete(self, prompt: str) -> str:
        for i in range(self._attempts):
            try:
                return self._inner.complete(prompt)
            except Exception:
                if i == self._attempts - 1:
                    raise
                time.sleep(2 ** i)
```

`RetryingClient` thaanae oru `ModelClient`, adhanaala endha provider koodavum velai seiyum, wiring step-la wrappers-a adukkalaam: `RetryingClient(HostedClient(...))`. Idhu thaan seyalla open-closed: pudhu behaviour, irukkura clients-la endha edit-um illa. (Real code-la, ovvoru `Exception`-kkum illa, timeouts-kkum rate limits-kkum mattum retry pannunga; *Errors, retries and cost* lesson-a paarunga.)

### Functions-aa, classes-aa?

Ellaa idathulayum classes thevaiyilla. Thelivaana inputs-um outputs-um irukkura saadhaarana functions thaan pala neram ellaathaiyum vida clean-aana Python design, oru dependency-a parameter aakkuradhu moolamaavae oru function-kkulla inject pannalaam. Pala calls share panra state allathu settings edhaavadhu onnu vechirukkumbodhu, udhaaranamaa API key-um timeout-um irukkura oru client, allathu orae interface-kku onnukku badhilaa innonnu podakkoodiya pala implementations venumbodhu, class-a edunga.

### Eppo refactor panradhu

**Refactoring**-na code enna seiyudho adhai maathaama adhoda structure-a maathuradhu. Andha code-a neenga eppadiyum maathappoureenga, andha maatram kashtamaa irukku-nnaa appo pannunga. Mudhalla maatram easy-aa aagura maadhiri code-a reshape pannunga, appuram andha easy-aana maatrathai pannunga. Safe-aana vazhi:

1. **Mudhalla tests.** Edhaiyum thodradhukku munnaadi, innaikku irukkura behaviour-a, asingamaana behaviour-aa irundhaalum, pin panra tests ezhudhunga. Neenga edhaiyaavadhu udaichaa avai sollum.
2. **Chinna steps.** Oru function-a move pannunga, tests ottunga, commit pannunga. Oru branch-la oru vaaram edukkura refactor podhuvaa oru valiyaana merge-la thaan mudiyum.
3. **Structure-aiyum behaviour-aiyum thanithaniyaa vainga.** Oru commit onnu code-a reshape pannum, illanna adhu enna seiyudhu-nnu maathum, orupodhum rendum illa; appo oru reviewer ovvonnaiyum check pannalaam.

Velai seiyura, yaarukkum maatha thevaiyillaadha code-a refactor pannaadheenga. Oru unmaiyaana rendaavadhu case (rendaavadhu provider, rendaavadhu output format) allathu fake thevaippadura oru test varra varaikkum interface serkkaadheenga.

### Low-level design interviews

Niraiya Indhiya product companies oru **low-level design** (LLD) round nadathuraanga. Rate limiter allathu parking lot maadhiri chinna onnukku classes-um interfaces-um design panna solluvaanga. (Oru **system design** round adhukku badhilaa muzhu services eppadi onnaa serudhu-nnu kekkum.)

"Ovvoru user-kkum oru nimishathukku N requests allow panra oru rate limiter design pannunga"-ngradhukku oru model answer interfaces-la aarambikkum, appuram oru simple strategy:

```python
from typing import Protocol

class Clock(Protocol):
    def now(self) -> float: ...

class RateLimiter(Protocol):
    def allow(self, user_id: str) -> bool: ...

class FixedWindow:
    def __init__(self, limit: int, window_s: float, clock: Clock):
        self.limit, self.window_s, self.clock = limit, window_s, clock
        self.counts: dict[str, tuple[int, int]] = {}  # user -> (window number, count)

    def allow(self, user_id: str) -> bool:
        window = int(self.clock.now() // self.window_s)
        seen, n = self.counts.get(user_id, (window, 0))
        n = n if seen == window else 0
        if n >= self.limit:
            return False
        self.counts[user_id] = (window, n + 1)
        return True
```

Appuram trade-offs-a sathamaa sollunga. Clock inject pannappadudhu, adhanaala oru test oru nimisham kaathirukkaama fake clock vechu nerathai set pannudhu. Fixed window-kku therinja oru balaveenam irukku: oru user 0:59-la N requests-um 1:00-la innum N-um pannalaam, rendu seconds-la limit-oda rettippu. Oru user-oda allowance-a neram poga poga seeraa refill panra **token bucket** idhai smooth aakkudhu, adhu adhae `RateLimiter` interface-kku pinnaadi oru rendaavadhu class, adhanaala `allow()`-a call panra API code maaravae maaraadhu. Pala servers-la, counts Redis maadhiri oru shared store-kku pogum: innum oru adapter.

## Oru worked example

Delhi-la oru legal-tech startup-la irukkura Rohit-oda team oru vaarathula oru contract summariser build pannaanga. Ellaamae 300 lines irukkura orae file-la irundhuchu: adhu PDF-a padichudhu, oru hosted model provider-a neradiyaa call pannuchu, Markdown format pannuchu, result-a email pannuchu.

Rendu maasam kazhichu, moonu requests orae nerathula varudhu. Oru periya client thannoda contracts-a than sondha cloud account-la odura oru model process pannanum-nu kekkuraanga. Sales team-kku summaries Word documents-aa venum. Appuram tests oda sumaar naalu nimisham aagudhu, yenna ovvoru test-um oru real API call pannudhu, kaasum selavaagudhu.

Rohit chinna steps-la refactor panraaru, mudhalla innaikku irukkura behaviour-a suthi tests vechu.

**1. Maarradhukkaana kaaranathai vechu piringa.** Avar `reader.py` (PDF-la irundhu text), `summariser.py` (prompt-um parsing-um), `formatters.py` (Markdown, ippo Word-um), `delivery.py` (email), `llm.py` (model clients) create panraaru. Ovvoru file-kkum maarradhukku orae kaaranam.

**2. Oru port-um rendu adapters-um.** `llm.py`-la:

```python
import httpx
from openai import OpenAI

# ModelClient is the Protocol shown earlier, defined in this file.

class HostedClient:
    """A hosted provider, reached through its own SDK."""
    def __init__(self, api_key: str, model: str):
        self._sdk = OpenAI(api_key=api_key, timeout=30)
        self._model = model

    def complete(self, prompt: str) -> str:
        resp = self._sdk.chat.completions.create(
            model=self._model,
            messages=[{"role": "user", "content": prompt}],
        )
        return resp.choices[0].message.content or ""

class SelfHostedClient:
    """A model served with vLLM inside the customer's own cloud."""
    def __init__(self, base_url: str, model: str):
        self._http = httpx.Client(base_url=base_url, timeout=60)
        self._model = model

    def complete(self, prompt: str) -> str:
        r = self._http.post("/v1/chat/completions", json={
            "model": self._model,
            "messages": [{"role": "user", "content": prompt}],
        })
        r.raise_for_status()
        return r.json()["choices"][0]["message"]["content"] or ""
```

Rendumae oru string-a return pannudhu, orupodhum `None`-a illa, adhanaala rendumae orae promise-a kaappaathudhu. Rendumae failure-la error raise pannudhu, adhai caller aerkanavae handle pannudhu.

**3. Port-a mattum therinja core logic.** `summariser.py` `ModelClient`-a import pannudhu, veliyila irundhu vera edhaiyum illa:

```python
from llm import ModelClient

PROMPT = "Summarise this contract in 5 bullet points. Flag any termination clause.\n\n{text}"

def summarise(text: str, client: ModelClient) -> list[str]:
    reply = client.complete(PROMPT.format(text=text))
    return [line.lstrip("-* ").strip() for line in reply.splitlines() if line.strip()]
```

**4. Orathula wiring.** `main.py` ovvoru customer-oda settings-a padichu client-a therndhedukkudhu. Endha providers irukku-nnu therinja, codebase-oda orae idam idhu thaan:

```python
from dataclasses import dataclass

from llm import HostedClient, ModelClient, SelfHostedClient

@dataclass
class Settings:
    model_host: str      # "hosted" or "self_hosted"
    model: str
    api_key: str = ""
    base_url: str = ""

def make_client(s: Settings) -> ModelClient:
    if s.model_host == "self_hosted":
        return SelfHostedClient(s.base_url, s.model)
    return HostedClient(s.api_key, s.model)
```

**5. Oru fake vechu vegamaana tests.** `test_summariser.py`-la:

```python
from summariser import summarise

class FakeClient:
    def __init__(self, reply: str):
        self.reply = reply
        self.prompts: list[str] = []

    def complete(self, prompt: str) -> str:
        self.prompts.append(prompt)
        return self.reply

def test_summarise_returns_clean_bullets():
    fake = FakeClient("- Term: 2 years\n\n- Notice period: 90 days\n")
    assert summarise("CONTRACT TEXT", fake) == ["Term: 2 years", "Notice period: 90 days"]
    assert "CONTRACT TEXT" in fake.prompts[0]
```

Reply bullets-aa clean pannappadudhaa, contract text prompt-kku poi serndhuchaa-nnu test check pannudhu, network-um API key-um illaamalae. Ovvoru unit test-um fakes use panna aarambicha appuram, Rohit-oda suite nimishangalukku badhilaa seconds-la odudhu. Real providers-a call panra rendu moonu slow tests-a avar vechirukkaaru, avai ovvoru release-kkum munnaadi odum; oru fake pidikka mudiyaadha vishayangalai avai pidikkum: maarina response shape, allathu thappaana model name.

Self-hosted client oru pudhu class, `summarise()` konjam kooda maarala. Word output oru pudhu formatter. Ovvoru request-um oru rewrite-kku badhilaa sumaar oru naal eduthuchu.

Enga niruthanum-num avarukku theriyum. PDF reader-kku avar interface serkkala, yenna orae oru reader thaan irukku, innonnukku plan-um illa.

## Podhuvaana thappugal

- **Logic-kkulla aazhamaa external services-a call panradhu.** Network illaama code-a test panna mudiyaadhu, provider maathanum-naa ovvoru file-laiyum thedanum.
- **Promise-a kaappaathaadha oru fake.** Real clients oru string return panra idathula fake oru list return pannaa, unga tests pass aagum, production fail aagum. Fakes real onnoda adhae interface-a follow pannanum.
- **Oru provider-oda API-a copy panra interface.** General-aa theriyum, aanaa andha provider-kku mattum thaan fit aagum. Caller pakkathula irundhu design pannunga: core logic-kku unmaiyila enna venum?
- **Romba seekkiramae romba adhigamaana abstraction.** 100 lines script-kku interfaces, factories, layers ellaam vechaa padikka kashtamaagum. Unmaiyaana rendaavadhu case-kko oru test-kko thaan abstraction serunga.
- **Behaviour serkka subclass panradhu.** Retries, logging, caching-a subclasses-aa vechaa, ovvoru combination-kkum oru class-aa perugidum. Adhukku badhilaa wrap pannunga.
- **Tests illaama, allathu orae periya step-la refactor panradhu.** Neenga edhai udaicheenga-nnu solla mudiyaadhu. Tests vechu behaviour-a pin pannunga, appuram chinna commits-la nagarunga.
- **Interviews-la SOLID-a oppikkiradhu.** Unmaiyaana code-la problem-a kandupidichu, trade-off-a solli, adhai fix panna mudiyumaa-nnu thaan interviewers paappaanga.

## Practice

Keezha link panniyirukkura, Python-la SOLID principles pathina ArjanCodes video-va paarunga, ovvoru principle-kku appuramum pause panni unga sondha code-la oru example kandupidinga.

Appuram indha lesson-oda project check-a pannunga, Rohit panna maadhiriyae unga sondha chinna app-a refactor panni: mudhalla innaikku irukkura behaviour-kku oru test, appuram interface, rendaavadhu implementation, start-up-la oru `make_client` function. Submit panradhukku munnaadi, neengalae mark pannunga:

| Check | Idhu pass aagum, eppo-nnaa |
| --- | --- |
| Boundary | Core logic file endha provider SDK-aiyum import pannaadhu; adapter file-um wiring-um mattum thaan pannum |
| Tests | Kurainjadhu rendu unit tests oru fake client use pannum, network-um API key-um illaama odum, `pytest`-la pass aagum |
| Swappable | Rendaavadhu implementation-kku maarradhu settings-aiyo wiring-aiyo mattum maathum, core logic-a illa |

Idhukku munnaadi pytest vechu tests ezhudhinadhillai-nnaa, mudhalla *Writing tests with pytest* lesson-a pannunga; oru project-oda pagudhiyaa avatrai otturadhai *Project tooling* cover pannudhu.

**Mudinjadhu-nnu eppo sollalaam:** unmaiyaana code-la single-responsibility, Liskov problems-a kandupidikka mudiyum, oru model provider-a unga product-kku aetha size-la irukkura oru interface-kku pinnaadi vaikka mudiyum, adhai start-up-la inject panna mudiyum, logic-a oru fake vechu test panna mudiyum, oru rate limiter maadhiri oru chinna low-level design-a adhoda trade-offs udpada pesi vilakka mudiyum.
