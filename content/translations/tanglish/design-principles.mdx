## Idhu enna

**Software design**-na oru program-a parts-aa eppadi pirikkanum, andha parts eppadi onnoda onnu pesanum-nu mudivu panradhu. Nalla perumbaalaana designs-oda adiyila rendu ideas irukku:

- **Cohesion**: ovvoru part-um oru velai thaan seiyum, ullaa irukkura ellaamae andha velaiku thaan.
- **Coupling**: parts onnoda details-a innonnu evvalavu depend panradhu. Loose coupling-na, oru part-a maathinaalum matha-vangala thodaama irukkalaam.

Nalla design-na high cohesion-um loose coupling-um. Mosamaana design-la, email template-a maathanum-na, model-a call panra code-a kooda edit pannanum.

**SOLID principles** adha adaiya irukkura aindhu well-known guidelines. Idhu object-oriented programming-la irundhu vandhadhu, aana ideas simple Python functions, modules-kum poruntum. Idha ozhunga sollanum-nu avasiyam illa; idhu thadukkura problems-a kandupidikka theriyanum.

## Idhu eppadi work aagudhu

Aindhu principles, simple-aa:

| Principle | Simple-aa | Neenga idha break panraanga-nu kaattum sign |
| --- | --- | --- |
| **S**ingle responsibility | Oru module illa class-ku oru maara kaaranam | Data padikkuradhu, model-a call panradhu, email anuppuradhu ellaam seiyura file |
| **O**pen for extension | Pudhu behaviour-a code serthu add pannunga, work aagura code-a edit panna vendaam | Ovvoru pudhu provider-kum oru neenda chain-la innoru `elif` |
| **L**iskov substitution | Oru interface-oda edhu implementation-um, interface edhirpaakkura edathula work aagum | Pathi methods-ku "not supported"-nu raise panra oru "provider" |
| **I**nterface segregation | Chinna, focus-aana interfaces | Ellaa parts-um depend aagura oru periya `Storage` class |
| **D**ependency inversion | Oru specific library-a illa, interface-a depend aagunga | Business logic-oda ullae aazhama `openai.chat...` call panradhu |

**Dependency injection** thaan idhula perumbaalaanadhu pinnaadi irukkura practical tool. Oru function-ku thevai-yaanadha adhuve create panradhukku badhil, adhu receive pannum:

```python
from typing import Protocol

class ModelClient(Protocol):
    def complete(self, prompt: str) -> str: ...

def summarise(text: str, client: ModelClient) -> str:
    return client.complete(f"Summarise in 3 bullet points:\n{text}")
```

Ippo `summarise`-ku edhu provider-nu kavalai illa. Production-la unmaiyaana client-a pass pannum, tests-la fake-a pass pannum, provider-a maathanum-na oru pudhu class ezhudhina podhum, `summarise`-a edit panna vendaam.

```flow
title: Business logic oru chinna interface-a depend aagum, provider-a illa
summarise() -> ModelClient interface | complete(prompt) -> str
ModelClient interface -> Provider A client
ModelClient interface -> Provider B client
ModelClient interface -> Tests-ku fake client
```

Oru AI application-a organise panra oru common vazhi, adhe idea-va muzhu codebase-layum use panradhu:

- **Core logic** (product enna seiyudhu: oru ticket-a classify panradhu, prompt build panradhu, oru answer-a score panradhu) veliyila edhaiyum depend aagaadhu.
- **Adapters** (model client, vector store, database, email) chinna interfaces-a implement pannum.
- **Wiring** oram-la (API startup, CLI) unmaiyaana adapters-a create panni ullae pass pannum.

**Functions-aa classes-aa?** Ellaa edathulayum classes thevai illa. Python-la clear inputs-um outputs-um irukkura simple functions thaan perumbaalum romba clean-aana design. Pala functions share panra state illa settings-a oru vishayam vachirundha, example ku API key-um timeout-um irukkura oru client, illa oru interface-oda palavidha maatha koodiya implementations venum-na, appo oru class eduthukkunga.

**Interviews-la.** Low-level design rounds-la, oru rate limiter illa parking lot maadhiri chinna vishayatha classes-um interfaces-um design panna sollvaanga. System design rounds-la services eppadi serndhu work aagum-nu kepaanga. Rendu-layum oru idea thaan: parts-ku peru podunga, ovvonnukkum oru velai kudunga, matha-vangala thodaama oru part-a eppadi maathuveenga illa test panuveenga-nu kaattunga.

## Oru worked example

Delhi-la oru legal-tech startup-la Rohit-oda team oru contract summariser-a oru vaaraththula build pannaanga. Ellaam oru 300-line file-la irundhudhu: PDF padikkum, oru model provider-a directly call pannum, Markdown format pannum, result-a email pannum.

Rendu maadham kazhichu, moonu requests orae neraththula varudhu: oru client avanga data-va avanga own cloud-la host panna model-la process pannanum-nu kekkuraanga, sales team summaries-a Word documents-aa vendum-nu kekkuraanga, ovvoru test-um unmaiyaana API calls panradhaala tests-ku nimishangal aagudhu.

Rohit steps-la refactor panraanga, mudhalla innaiku irukkura behaviour-a suththi tests ezhudhi:

1. **Single responsibility.** File-a `reader.py` (PDF-la irundhu text), `summariser.py` (prompt-um parsing-um), `formatters.py` (Markdown, ippo Word-um), `delivery.py` (email)-nu pirikkiraanga.
2. **Model-ku oru interface.** `summariser.py` ippo oru `ModelClient`-a edukkum. `ProviderAClient`-um `SelfHostedClient`-um ezhudhuraanga, rendumae `complete()` irukkura chinna classes.
3. **Oram-la injection.** API startup customer-oda settings-a padichu, sariyaana client-um formatter-um pass pannum.
4. **Vegamaana tests.** Unit tests oru fixed summary-a tharura `FakeClient`-a pass pannum. Test suite naalu nimisham-la irundhu moonu second-ku varudhu.

Self-hosted client oru pudhu class, adhukku own tests; `summarise()` oru maattramum illa. Word output oru pudhu formatter; vera edhuvum maaralai. Ovvoru request-um rewrite illaama oru naal-la mudinjudhu.

Avanga innum munnaadi pogaama irukkaraanga: PDF reader-ku interface serkala, yenna oru reader thaan irukku, innoru plan illa. Unmaiyaana rendavadhu case-o, test thevaiyo irukkum podhu thaan abstraction serkanum.

## Podhuvaa panra thappugal

- **Logic-oda aazhaththula external services-a call panradhu.** Network illaama code-a test panna mudiyaadhu, provider-a maatharadhum kashtam.
- **Romba mundhiyae romba abstraction.** 100-line script-ku interfaces, factories, layers serthaa padikka easy illa, kashtam thaan.
- **Periya "utils" illa "manager" modules.** Oru module-oda peru adhu enna seiyudhu-nu sollalana, adhu pala velaigal seiyudhu-nu artham.
- **Oru implementation-ku suit aaga interface-a maathradhu.** Appo matha ellaa implementations-um, callers-um maaranum.
- **SOLID-a ozhunga sollra rules-aa nenaikkiradhu.** Interviewers paakkradhu, unmaiyaana code-la problem-a kandupidichu fix panna mudiyumaa-ngradha thaan.
