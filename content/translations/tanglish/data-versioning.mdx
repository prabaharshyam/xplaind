## Idhu enna

**Data versioning**, Git code-a track panra maadhiri, datasets-oda versions-aiyum (adhai uruvaakkura steps-aiyum) track pannum. Ovvoru training run-um entha data version use pannichu-nu record pannum, adhanaala:

- entha pazhaya model-aiyum exact-aa reproduce pannalaam;
- rendu dataset versions-ku idaila enna maarichu-nu paakkalaam;
- pudhusu odanju irundhaa, munnaadi dataset-ku rollback pannalaam;
- auditors-ku oru decision-oda pinnaadi irukkura data-va kaattalaam.

Periya files Git-la direct-aa irukka koodaadhu. DVC maadhiri tools data-va cloud storage-la vechu, Git-la chinna pointer files-a vechukkum. Data lakes, warehouses-um table versioning ("time travel") tharum.

```flow
Sources-la irundhu raw data -> Dataset-a build pannunga
Pipeline code | Git commit a1b2c3 -> Dataset-a build pannunga
Dataset-a build pannunga -> Data v2026-10-01 | manifest: rows, hash, query, commit
Data v2026-10-01 -> Training run 412 | data, code versions-a log pannudhu
Training run 412 -> Model registry: fraud-model v7 -> Production predictions
```

Lineage adhukku ethirmaiyaa pogum: entha prediction-um → model v7 → run 412 → data v2026-10-01 → commit a1b2c3.

Indha lesson, Chennai-la oru health-insurance company-a follow pannum; avanga fraud model retrain pannadhukku apram mosamaagiduchu.

## Idhu eppadi work aagudhu

**Inputs-a snapshot pannunga.** Training datasets-a oru id-oda immutable snapshots-aa paarunga: content hash, date-stamp potta path, illa tool manage panra version. Oru dataset-a eppavumae adhae idathula overwrite pannaadheenga.

**Pipeline-aiyum version pannunga.** Raw data-va training data-vaa maathura code (filters, joins, labels, feature computation) Git-la versioned-aa irukkanum. Oru data version-na, oru specific raw data-la run aana oru specific pipeline version-oda output.

**Lineage-a record pannunga.** Ovvoru training run-um data version id-a log pannum; registry-la ovvoru model-um adhoda run-oda link aagum. Oru production prediction-la irundhu exact data varaikkum thirumba nadakkalaam.

**Versions-a compare pannunga.** Versions-ku idaila row counts, label balance, feature distributions, schema maatrangal, sample diffs. Periya maatrangala code maatrangal maadhiri review pannunga.

**Labels-um maarum.** Correct panna labels, pudhu labelling guidelines, late-aa varra outcomes datasets-a maathum. Avatrai version pannunga, yen-nu note pannunga.

**Privacy, deletion.** Versioned data-vula innum personal data irukku. DPDP Act-oda retention rules-um erasure requests-um pazhaya versions-kum porundhum; deletion eppadi paravum-nu plan pannunga, ex: affected versions-a nikkapatta records illaama marubadiyum build panni, adhai document pannunga.

**Practical-aa vechukkunga.** Chinna teams-ku, cloud storage-la dated folders, oru manifest-oda (row counts, hash, source query, pipeline commit), ovvoru run-layum path-a log pannaa podhum. Volume-um team size-um valara valara oru tool-a adopt pannunga.

**Ovvoru dataset version-kum oru manifest:**

| Field | Example |
| --- | --- |
| Version id | `claims-train-2026-10-01` |
| Content hash | `sha256:9f2c...` |
| Rows | 812,440 |
| Positive label share | 2.3% |
| Source query illa tables | `claims_v3 joined with investigations` |
| Pipeline commit | `a1b2c3d` |
| Yaar, eppo uruvaakkinaanga | `pipeline-bot, 2026-10-01` |
| Notes | "Relabelled 1,200 claims after the audit of July" |

Dataset build aagum podhu manifest-a automatic-aa ezhudhunga, data pakkathulayae store pannunga, build-a trigger panna pull request-la munnaadi manifest-oda comparison-a print pannunga. "positive label share: 2.3% to 1.1%"-nu paakkura reviewer, training aarambikkum munnaadiyae sariyaana kelvi kepaanga.

**Tool-a choose panradhu.** Rendu moonu perukku, dated folders-um oru manifest-um podhum. DVC Git-la pointer files-aiyum, data-va pull, push panra commands-aiyum serkkum, pala per models train panna aarambicha help pannum. Delta Lake, Apache Iceberg maadhiri lakehouse table formats "time travel" serkkum, appo oru table-a oru kuripitta date-la irundha maadhiri query pannalaam, training data already warehouse-la irukkura teams-ku porundhum. Edhai choose pannaalum rule onnu thaan: oru training run entha data version use pannichu-nu exact-aa record pannanum, andha version apram eppavumae maaraadhu.

**Manifest-a automatic-aa ezhudhunga.** Dataset build mudiyum podhu sila lines:

```python
import hashlib, json, subprocess
from datetime import datetime
from zoneinfo import ZoneInfo
from pathlib import Path

def file_hash(path, chunk=1 << 20):
    h = hashlib.sha256()
    with open(path, "rb") as f:
        while block := f.read(chunk):
            h.update(block)
    return "sha256:" + h.hexdigest()

def write_manifest(data_path, df, label_col, notes=""):
    commit = subprocess.run(["git", "rev-parse", "--short", "HEAD"], capture_output=True, text=True).stdout.strip()
    manifest = {
        "version": Path(data_path).stem,
        "hash": file_hash(data_path),
        "rows": int(len(df)),
        "positive_share": round(float(df[label_col].mean()), 4),
        "columns": list(df.columns),
        "pipeline_commit": commit,
        "created": datetime.now(ZoneInfo("Asia/Kolkata")).isoformat(timespec="seconds"),
        "notes": notes,
    }
    Path(data_path).with_suffix(".manifest.json").write_text(json.dumps(manifest, indent=2))
    return manifest
```

**Munnaadi version-oda compare panni, surprises-ku fail pannunga.**

```python
def compare(old, new, max_share_change=0.3, max_row_change=0.2):
    problems = []
    if set(old["columns"]) != set(new["columns"]):
        problems.append(f"columns changed: {set(old['columns']) ^ set(new['columns'])}")
    if abs(new["rows"] - old["rows"]) / old["rows"] > max_row_change:
        problems.append(f"rows {old['rows']} -> {new['rows']}")
    rel = abs(new["positive_share"] - old["positive_share"]) / max(old["positive_share"], 1e-9)
    if rel > max_share_change:
        problems.append(f"positive share {old['positive_share']:.2%} -> {new['positive_share']:.2%}")
    return problems
```

Data-va build panna pull request-la comparison-a print pannunga. Oru failure eppavum thappu illa, aana training-ku munnaadi yaaraavadhu notes-la adhai explain pannanum.

**DVC naalu commands-la.** Data cloud storage-la irukkum; Git chinna pointer files-a track pannum:

```bash
dvc init
dvc remote add -d store s3://my-bucket/dvc       # or Azure, GCS, a shared drive
dvc add data/claims-train-2026-10-01.parquet     # writes a .dvc pointer file
git add data/*.dvc .gitignore && git commit -m "Training data 2026-10-01" && dvc push
```

Appuram yaaraavadhu oru commit-a `git checkout` panni, `dvc pull` pannaa, exact andha data kidaikkum.

**Lakehouse-la time travel.** Training data Delta Lake tables-la irundhaa, ovvoru run-oda table version-a record panni, adhai exact-aa thirumba padikkalaam:

```sql
SELECT * FROM claims_train VERSION AS OF 42;
SELECT * FROM claims_train TIMESTAMP AS OF '2026-10-01T00:00:00+05:30';
```

Pazhaya versions oru retention period-ku apram cleanup jobs-aala neekkapadum, adhanaala models-a reproduce panna thevaiyaana varaikkum vida andha period-a neenda vechukkunga, illa mukkiyamaana snapshots-a export pannunga.

**Versions muzhukka erasure.** Oru aal erasure kettaa, avanga records irukkura ovvoru dataset version-aiyum kandupidinga (ovvoru version-kum record ids-oda oru index vechukkunga), andha versions-a avanga illaama marubadiyum build pannunga, ovvoru manifest-layum note pannunga. Pazhaya versions-la train aana models-a retrain pannanumaa-nu privacy lead-oda sertthu decide pannunga.

## Oru worked example

Chennai-la oru health-insurance company, adhoda claim-fraud model-a retrain pannaa, recall 0.72-la irundhu 0.61-ku kurainjadhai kandupidikkudhu.

Data DVC-la versioned-aa irukkradhunaala, team pudhu dataset-a munnaadi dataset-oda compare pannudhu:

- 14% kammiyaana positive labels, fraud cases kurayalanaalum;
- label query maarirundhuchu: pipeline refactor ippo investigation-la irukkura claims-a ozhikkudhu, avai thaan sameepaththa fraud-la perumbaagam.

Pipeline-a fix panni, dataset-a pudhu version-aa rebuild panni, retrain pannaa recall 0.73-ku meendudhu. Mudhal refactor-oda pull request-la, versions-ku idaila positive label share 20%-ku mela, explanation illaama maarinaa fail aagura oru data check serkkapadudhu.

Apram oru customer-oda erasure request, avanga records-a delete panna solludhu. Team affected training versions-a avanga illaama rebuild panni, maatrathai record panni, rebuild aana model-oda metrics maaralai-nu confirm pannudhu.

**Team enna vechirundhaanga.** Fix oru naal aachu, yen-naa evidence aarambathulayae irundhuchu: rendu manifests pakkathula pakkathula label share maatrathai kaattuchu, ovvoru manifest-layum irundha pipeline commit nerae refactor-ai kaattuchu. Versioning illana, idhae investigation pala vaarangal oothi paarkka vendiyirukkum, illa nadakkavae nadakkaadhu, weak model amaidhiyaa ship aagum.

## Podhuvaa panra thappugal

- **Datasets-a adhae idathula overwrite panradhu.** Compare, reproduce panra thiramai poidum. Oru row fix-ku kooda eppavum pudhu id-oda pudhu version ezhudhunga.
- **Data-va version panni pipeline-a version pannaadhadhu.** Data eppadi uruvaachu-nu explain panna mudiyaadhu.
- **Model-la irundhu data-vukku link illaama.** Ovvoru run-layum data version-a log pannunga.
- **Label maatrangala ignore panradhu.** Feature maatrangala vida ivai model-a maathum.
- **Pazhaya versions-la privacy-a marakkradhu.** Retention, erasure ovvoru copy-kum porundhum.
- **Kaiyaala ezhudhina manifests**, unmaiyaana data-vodu maarum.
- **Versions-ku idaila label share, row counts-ku check illaama irukkuradhu.**
- **Erasure requests-la pazhaya versions-a marakkradhu.**

## Versioning simple-aa irukkalaam-naa

- **Training data illaadha, prompt-only AI apps**: adhukku badhila prompts, test sets, indexes-a version pannunga.
- **Oru aal, oru chinna dataset**: oru manifest-oda dated folder podhum.
- **Eppavumae maaraadha data**, fixed public benchmark maadhiri: adhoda peyar, hash-a oru thadavai record pannunga.

## Demo-la irundhu production-ku

- **Dataset versions-a immutable-aa aakki**, ovvoru training run-oda version-a log pannunga.
- **CI-la manifests-a automatic-aa ezhudhi compare pannunga.**
- **Model registry-la models-a data versions-oda link pannunga.**
- **Ovvoru version-kum record ids-a index pannunga**, appo erasure requests-a nadathalaam.
- **Pazhaya versions-ku retention-a**, ungaloda reproducibility thevaigala vida neenda set pannunga.

## Practice pannunga

DVC-oda get-started guide-aiyum Made With ML-oda data versioning lesson-aiyum follow pannunga.

1. Oru dataset-a DVC-la (illa hash potta dated folders-um manifest-um) version control-la podunga, oru training run-oda link pannunga.
2. Data-va maathunga (rows serunga, labels-a fix pannunga), pudhu version uruvaakkunga, versions-ku idaila oru comparison report ezhudhunga.
3. Label share oru threshold-a thaandi maarinaa fail aagura oru data check serunga.
4. Ungaloda dataset-oda rendu versions-a build pannunga, onnula oru relabelled slice irukkattum, compare function label-share maatrathukku fail aagura maadhiri pannunga.

**Mudinjadhu-nu eppo sollalaam:** Oru pazhaya model-a, adhoda record panna code, data versions-la irundhu reproduce panna mudiyum, rendu dataset versions-ku idaila difference-a explain panna mudiyum.
