## Idhu enna

Standard RAG kelvikku similar-aa irukkura passages-a retrieve pannum. Rendu vagai kelvigal adha thorkadikkum:

- Links-a follow panra **multi-hop kelvigal**: "Delay aana Chennai metro package-oda oru contractor-a share panra projects edhu?" Facts vera vera documents-la irukkum, entha oru passage-um kelvikku similar-aa irukkaadhu.
- Oru muzhu collection pathiya **global kelvigal**: "Pona varusha customer complaints-la thirumba thirumba varra problems enna?" Entha passage-lum answer illa; neraya-la irundhu thaan varum.

**Graph RAG** oru **knowledge graph**-a serkkum: entities (people, companies, products, places, events) nodes-aa, avatrukku idaiyila relationships edges-aa, documents-la irundhu extract pannapadum. Appo retrieval relationships-a follow pannalaam, related entities-oda groups-oda munnaadiyae ezhudhina summaries-aiyum use pannalaam. Microsoft-oda open-source GraphRAG oru nalla theriyura implementation; Neo4j maadhiri graph databases innoru vazhi.

```flow
Documents -> Chunks -> Model entities-aiyum relationships-aiyum extract pannum -> Knowledge graph
Knowledge graph -> Communities kandupidichu summarise pannapadum
Kelvi -[local search]-> Entities + neighbours + source chunks
Kelvi -[global search]-> Community summaries-la map, apram reduce
```

```flow
dir: LR
title: Graph-oda oru paguthi
Project: Metro Pkg 4 | overrun 27% -[contractor]-> ABC Infra
ABC Infra -[also on]-> Project: Pune Ring Road
ABC Infra -[sub-contracts to]-> XYZ Steel
```

Indha lesson-la Mumbai-la oru infrastructure finance company-a follow pannuvom, avanga analysts nooru-kanakkaana project documents-a thaandi kelvigal kekkuraanga.

## Idhu eppadi work aagudhu

**Indexing (GraphRAG style).**

1. Documents-a vazhakkam pola chunk pannunga.
2. Ovvoru chunk-lirundhum entities-aiyum relationships-aiyum, sinna descriptions-oda ("ABC Infra, contractor; Package 4-ku steel supply pannum") extract panna oru model use pannunga.
3. Duplicates-a merge pannunga ("ABC Infra Ltd", "ABC Infrastructure").
4. **Communities** kandupidinga: nerungi connect aana entities-oda clusters.
5. Ovvoru community-yodaya summary-a pala level of detail-la oru model ezhudha vaiyunga.

**Querying.**

- Specific entities pathiya kelvigalukku *local search*: kelvila irukkura entities-a kandupidichu, avatroda neighbours, relationships, source chunks-a serthu, adhula irundhu answer pannunga.
- Collection-muzhukka kelvigalukku *global search*: kelvi-a community summaries mela map pannunga, apram paadhi answers-a onna reduce pannunga.

**Selavugal.** Indexing ovvoru chunk-kum ovvoru community-kum oru model-a call pannum, adhanaala embedding mattum-a vida pala madangu selavaagum, documents maarum podhu thirumba run panna illa update panna vendiyum irukkum. Entity extraction thappu pannum; merges thaniyaa irukka vendiyadha serthudalaam. Queries, especially global-aanavai, neraya tokens use pannum.

**Eppo worth-aa irukkum.** Entities-um relationships-um adhigamaa irukkura collections (contracts, investigations, research literature, supplier networks, case files), multi-hop illa global kelvigal adhigamaa, mukkiyamaa varum idathula. Perumbaalaana FAQ-style illa policy-lookup assistants-ku, nalla metadata-oda hybrid search sellavu kammi, podhum.

**Lighter alternatives.** Extract panna entities-a metadata-vaa store panni adhula filter pannunga; mukkiya relationships-oda oru sinna structured table vachukkunga; document groups-ku summaries generate pannunga. Idhu perumbaalum benefit-la perumbaalaanadha tharum.

**Standard RAG vs Graph RAG:**

| Aspect | Hybrid RAG | Graph RAG |
| --- | --- | --- |
| Single-document kelvigal | Strong | Nallaa illa |
| Multi-hop kelvigal | Weak | Strong |
| Collection-muzhukka kelvigal | Weak | Community summaries-oda strong |
| Indexing cost | Embeddings mattum | Ovvoru chunk-kum community-kum model calls |
| Updates | Maarina chunks-a thirumba embed | Thirumba extract, thirumba merge |
| Failure risk | Miss aana passages | Thappaana extractions-um merges-um |

**Rendukkum naduvula routing.** Konjam teams thaan hybrid RAG-a replace pannuvaanga; adhaala answer panna mudiyaadha kelvigalukku oru graph serppaanga. Oru sinna classifier, illa oru model call, kelvi entities-ukku naduvula relationships pathi solludhaa ("entha contractors-um ... la work pannuraanga", "vera yaar ... oda link aagi irukkaanga") illa muzhu collection pathiyaa ("thirumba thirumba varra ...")-nu decide pannum. Avai graph search-ku pogum; meedhi ellaam hybrid RAG-ku. Ovvoru kelvikkum route-a log pannunga, appo test set-la router-oda thappugala check pannalaam.

**Citations-a vachukkradhu.** Ovvoru entity-yum, relationship-um, community summary-yum, adhu vandha chunks-ku links-a vachirukkanum. Appo answers unmaiyaana documents-a cite pannum, analysts oru extract panna relationship unmaiyaave sollappattirukkaa illa extraction-la invent aachaa-nu check pannalaam.

**Code-la oru sinna graph.** Oru model-oda triples-a (structured output-aa) extract panni, NetworkX-la load panni, neighbourhoods-la irundhu local kelvigalukku answer pannunga:

```python
import networkx as nx
from pydantic import BaseModel

class Triple(BaseModel):
    subject: str
    relation: str
    object: str

class Extraction(BaseModel):
    triples: list[Triple]

def normalise(name):
    n = name.lower().replace("limited", "ltd").replace("infrastructure", "infra")
    return " ".join(w for w in n.replace(".", "").split() if w not in {"ltd", "pvt", "private"})

def build_graph(chunks, extract):
    """extract(text) -> Extraction, via structured output from a model."""
    g = nx.MultiDiGraph()
    for c in chunks:
        for t in extract(c["text"]).triples:
            s, o = normalise(t.subject), normalise(t.object)
            g.add_node(s, label=t.subject); g.add_node(o, label=t.object)
            g.add_edge(s, o, relation=t.relation, source=c["id"])
    return g

def local_context(g, entities, hops=2, limit=40):
    nodes = set()
    for e in map(normalise, entities):
        if e in g:
            nodes |= set(nx.ego_graph(g.to_undirected(as_view=True), e, radius=hops))
    facts = [f'{g.nodes[u]["label"]} —{d["relation"]}→ {g.nodes[v]["label"]} [{d["source"]}]'
             for u, v, d in g.subgraph(nodes).edges(data=True)]
    return facts[:limit]
```

Facts-oda source chunk ids-um sernthae varum, adhanaala answer unmaiyaana documents-a cite panna mudiyum. `normalise` rules entity resolution-ku oru mothalaana aarambam; mukkiyamaana entities-ku merges-a kaiyaala check pannunga, ennaikkum merge aagaadha peyargal-oda oru list-aiyum vachukkunga.

**Global kelvigalukku communities.** Nerungi link aana entities-a group pannunga, ovvoru group-aiyum oru thadavai summarise pannunga:

```python
from networkx.algorithms.community import louvain_communities

def communities(g, seed=7):
    groups = louvain_communities(g.to_undirected(), seed=seed)
    return sorted(groups, key=len, reverse=True)
```

Oru model ovvoru community-kum oru summary ezhudhum (adhu eduthukkitta chunk ids-oda). "Ellaa packages-layum thirumba thirumba varra delay kaaranangal enna?" maadhiri kelvikku, ovvoru community summary-kittayum andha kelvi-a kelunga, apram paadhi answers-a serkkunga.

**Graph-a nambradhukku munnaadi extraction-a check pannunga.** 50 extract panna triples-a sample eduthu, ovvonnayum source-la sollapattadhu, implied, illa thappu-nu mark pannunga. Konjam percent-a vida adhigam thappaa irundhaa, adhukku mela edhaiyum build panradhukku munnaadi extraction prompt-a improve pannunga (allowed entity types-um relations-um kudunga).

**Indexing bill-a mudhalla estimate pannunga.** Chunks × (extraction prompt + chunk + output tokens), koodavae ovvoru community-kum oru summary call. Collection-oda 5%-la run panni, measure panni, muzhusaiyum edukkradhukku munnaadi perukkunga.

## Oru worked example

Mumbai infrastructure finance company aayirakkanakkaana project reports, contractor agreements, site inspection notes-a review pannudhu. Analysts "20%-ku mela cost overruns irukkura projects-la entha contractors irukkaanga, avanga vera enga work pannuraanga?" maadhiri kelvigal kekkuraanga.

Hybrid RAG single-project kelvigalukku nallaa answer pannum, aana idhula thorkkum: facts nooru-kanakkaana documents-la paravi irukku.

Oru pilot 3,000 documents-la irundhu projects, contractors, sub-contractors, locations, inspection findings-oda oru graph build pannudhu. Indexing embedding-only pipeline-a vida sumaar 25 madangu selavaagudhu, oru thadavai selavu, koodavae vaaram-oru update. Entity merging-ku company name variants-oda oru kaiyaala ezhudhina list thevai, yenna orae contractor pala spellings-la varraanga.

Multi-hop, global kelvigal-oda 40-kelvi test set-la, graph approach 70% nallaa answer pannudhu, hybrid RAG 30%. Single-document kelvigalla adhu nallaa illa. Company rendaiyum vechirukkudhu: kelvigal projects-ukku idaiyila relationships pathi solla pattaa graph search-ku, illaina hybrid RAG-ku route aagudhu.

| Measure | Hybrid RAG | Graph approach |
| --- | --- | --- |
| 40-la multi-hop, global kelvigal nallaa answer aanadhu | 30% | 70% |
| Single-document kelvigal | Nalladhu | Nallaa illa |
| Indexing cost | Baseline | Sumaar 25 madangu, koodavae vaaram-oru updates |
| Extra velai | Illa | Contractor name variants-oda oru kaiyaala ezhudhina list |

## Podhuvaa panra thappugal

- **Simple lookups-ku Graph RAG.** Benefit illaama selavu mattum serkkum.
- **Entity resolution-a ignore panradhu.** Duplicate illa thappaa merge aana entities, adhai use panra ovvoru answer-aiyum keduthidum.
- **Updates-a marakkradhu.** Oru thadavai build panna graph pazhasaagum.
- **Comparison illaama irukkradhu.** Mukkiyamaana kelvigalla hybrid RAG-oda ottippaarunga.
- **Citations-a izhakkradhu.** Entities-um summaries-um source chunks-ku thirumba links vachukkunga.
- **Extract panna relationships-a source text-oda sample panni paakkaama nambradhu.**
- **Free-form relation names.** Extractor-ku oru fixed list kudunga, illaina graph near-duplicates-aala nirambidum.
- **Muzhu collection-aiyum index panradhukku munnaadi cost estimate-a skip panradhu.**

## Eppo Graph RAG worth illa

- **Kelvigal perumbaalum oru document illa oru fact pathi**: hybrid RAG adha sellavu kammiyaa answer pannum.
- **Documents thodarndhu maarittae irukku**, re-extraction sellavaana vishayam.
- **Konjam entities-um relationships-um thaan mukkiyam**: makkal maintain panra mukkiya facts-oda oru sinna table podhumaa irukkalaam.

## Demo-la irundhu production-ku

- Ovvoru entity, relationship, summary-lum **source chunk ids-a vachukkunga.**
- Ovvoru prompt illa model maatratha aprom sample-la **extraction accuracy-a measure pannunga.**
- **Incremental-aa update pannunga**: maarina documents-a thirumba extract pannunga, community summaries-a oru schedule-la thirumba run pannunga.
- Graph-kum hybrid search-kum naduvula **kelvigala route pannunga**, route-a log pannunga.
- Ordinary RAG-a vida thaniyaa **indexing-aiyum query cost-aiyum track pannunga.**
