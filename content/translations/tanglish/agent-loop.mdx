## Idhu enna

**Agent**-na tools-oda oru loop-la odura model: adutha enna seiyyanum-nu adhuvae mudivu pannum, oru tool-a call pannum, result-a padikkum, thirumba mudivu pannum, task mudiyura varaikkum illa nirutha vendi irukkura varaikkum. Loop ezhudha sirusu; adha reliable-aa aakkuradhu thaan kashtam.

Anthropic-oda "Building effective agents" article seiyra maadhiri rendu designs-a pirichu paarkkalaam:

- **Workflow**: steps-a ungaloda code mudivu pannum (mudhalla classify, apram retrieve, apram draft). Model ovvoru step-aiyum nirappum. Predictable, test panna easy.
- **Agent**: steps-um, ethanai steps-um model mudivu pannum, pogum podhu tools-a select pannum. Open-ended tasks-ku flexible, predict panna kashtam.

Steps theriyum-na workflow use pannunga; theriyaadhunna agent use pannunga.

```flow
Model | task + history + tool list -> Tool venumaa?
Tool venumaa? -[illa]-> Final answer, nirutthu
Tool venumaa? -[aama]-> Ungaloda code tool-a run pannum -> Step count limit-a thaandiducha?
Step count limit-a thaandiducha? -[illa: result-a serunga]-> Model
Step count limit-a thaandiducha? -[aama]-> Clean-aa nirutthi, oru aal-kitta hand over pannunga
```

Indha lesson Bengaluru-la oru travel startup-a follow pannum. Avanga weekend trips plan panra assistant build panraanga.

## Idhu eppadi work aagudhu

**Core loop.**

```python
messages = [{"role": "user", "content": task}]
for step in range(MAX_STEPS):
    reply = call_model(messages, tools=TOOLS)
    messages.append({"role": "assistant", "content": reply.content})
    if not reply.tool_calls:                 # the model is done
        return reply.text
    results = [run_tool(c.name, c.args) for c in reply.tool_calls]
    messages.append({"role": "user", "content": results})
raise RuntimeError("Step limit reached; hand over to a person")
```

Ovvoru round-layum: model task-a, ippo varaikkum nadandha ellathaiyum, tool list-aiyum paakkum; adhu answer pannum illa tools kekkum; ungaloda code avatha run panni results-a serkkum.

**Nirutharadhu.** Model tools kekkaama answer sollum podhu loop mudiyum. Eppovum oru **maximum steps** vainga, appo kuzhambina agent endrum loop aagi, panatha selavu pannaadhu, actions-a thirumba seiyyaadhu; adha thaandina, clean-aa nirutthi hand over pannunga.

**Nalla tools, nalla agents-a undaakkum.** Konjam, clear-aa describe panna, udhavi seiyyura errors-oda irukkura tools, clever prompting-a vida mukkiyam.

**System prompt** agent-ku adhoda goal-a, tools edhukku-nu, mudinjadhunnu eppadi mudivu pannanum-nu, confirmation illaama enna seiyyavae koodaadhu-nu solludhu.

**Simple-aa aarambinga.** Neraya tasks, retrieval-oda oru single model call-oda illa oru short workflow-oda work aagum. Steps-oda ennikkaiyum order-um unmaiyaa maarum podhu agent loops serunga.

**Workflow vs agent:**

| Vishayam | Workflow | Agent |
| --- | --- | --- |
| Steps-a yaaru mudivu pannuvaanga | Ungaloda code | Model |
| Predictability | Adhigam | Kammi |
| Testing | Ovvoru step-aiyum test pannunga | Pala runs-la outcomes-a test pannunga |
| Oru task-ku cost | Fixed, estimate panna easy | Steps ennikkai-a poruthu maarum |
| Edhukku best | Therinja, thirumba seiyyura processes | Steps maarura open-ended tasks |

**Reliability yen kashtam.** Errors serndhu perukkum. Ovvoru step-um 95% neram sariyaa ponaa, patthu-step task-oda patthu steps-um sariyaa pogura chance sumaar 60% thaan (0.95 power 10). Adhanaalthaan kuttaiyaana plans, nalla tools, vazhila checks romba mukkiyam, adhunaalaye moonu fixed steps-oda oru workflow, oru free agent-a vida aduthadhu jeyikkum.

**Planning.** Rendu common styles:

- **Maari maari yosikkradhu, seiyradhu** (ReAct pattern): ovvoru step-layum model konjam yosikkum, oru action edukkum, result-a padikkum, thirumba mudivu pannum. Mela irukkura loop idhu thaan, perumbaalaana agents idha use pannum.
- **Mudhalla plan, apram execute**: model muzhu plan-aiyum ezhudhum, ungaloda code adha check pannum (tools unmaiyaanavaiya, arguments sariyaa irukkaa, budget-kulla irukkaa), apram thaan run pannum. Act pannradhukku munnadi plan-a check pannradhu, actions-a undo pannradhai vida cheap, high-stakes tasks-ku oru aal plan-a approve pannalaam.

**Reflection.** Agent sariyaana neraththula adhoda velaiyai check pannaa nallaa seiyum: request seiya mudiyumaa, plan sariyaa irukkaa, indha step work aachaa, task unmaiyaa mudinjucha. Check-a adhe model-ku oru prompt-aa, oru reviewer-aa vera model-aa, illa generated code-ku tests run panra maadhiri plain code-aa vachukkalaam. Reflection-ku extra tokens-um neramum aagum, adhanaala thappugal expensive-aa irukkura idathula serunga.

**Run panna koodiya loop.** Indha version Anthropic-oda Python SDK-a use pannum, tool errors-a crash aagaama model-kitta thirumba kudukkum, step limit, budget illa onnu pola irukkura calls-ku nirutthum, ovvoru step-aiyum log pannum:

```python
import json
import anthropic

client = anthropic.Anthropic()
MODEL = "claude-sonnet-5-5"          # check the docs for current model names
MAX_STEPS, MAX_TOKENS_TOTAL = 10, 60_000

def run_agent(task, tools, handlers, system):
    messages = [{"role": "user", "content": task}]
    seen, used = {}, 0
    for step in range(1, MAX_STEPS + 1):
        reply = client.messages.create(model=MODEL, max_tokens=1000, system=system,
                                       tools=tools, messages=messages)
        used += reply.usage.input_tokens + reply.usage.output_tokens
        messages.append({"role": "assistant", "content": reply.content})
        calls = [b for b in reply.content if b.type == "tool_use"]
        if not calls:
            return "".join(b.text for b in reply.content if b.type == "text"), step
        results = []
        for call in calls:
            key = call.name + json.dumps(call.input, sort_keys=True)
            seen[key] = seen.get(key, 0) + 1
            try:
                if seen[key] > 2:
                    raise RuntimeError("Same call made twice already; try something different or stop.")
                if call.name not in handlers:
                    raise RuntimeError(f"No tool named {call.name}; use one of {sorted(handlers)}.")
                output, is_error = handlers[call.name](**call.input), False
            except Exception as err:                        # unknown tool, bad arguments, tool failure
                output, is_error = f"Error: {err}", True
            print(f"step {step}: {call.name}({call.input}) -> {str(output)[:80]}")
            results.append({"type": "tool_result", "tool_use_id": call.id,
                            "content": str(output), "is_error": is_error})
        messages.append({"role": "user", "content": results})
        if used > MAX_TOKENS_TOTAL:
            break
    return None, step                                       # hand over to a person
```

`handlers` ovvoru tool name-aiyum oru Python function-oda map pannum. Therinjaadha tool name, thappaana arguments, fail aagura tool ellaam run-a crash pannaama oru clear error-aa model-kitta thirumbi pogum, appo adhu thannaiye sari panna mudiyum. Tools-a eppadi define pannradhu-nu tool-calling lesson kaattum.

**Agents eppadi fail aagum, adha eppadi measure pannradhu.** Sadharana thappaana answers-oda mela agents-ku thanga failure modes irukku. Avatha peru vachu, test tasks-oda oru set-la ovvonnum evvalavu thadava nadakkudhu-nu count pannunga:

| Failure | Example | Eppadi kandupidikkradhu |
| --- | --- | --- |
| Invalid tool | Illaadha `book_hotel`-a call pannudhu | Logs-la therinjaadha tool names-a count pannunga |
| Invalid arguments | Thevaiyaana `dates`-a vittudhu | Ovvoru tool-kum validation errors |
| Thappaana argument values | Coorg-ku thappaana weekend search pannudhu | Test tasks-la expected values-oda compare pannunga |
| Goal failure | ₹25,000 budget-la ₹31,000 selavu aagura plan | Run mudinja apram code-la constraints-a check pannunga |
| Poi "done" | 12 guests-um book aachu-nu sollum, 9 per thaan aagirukku | Agent-oda claim-a illa, final state-a check pannunga |
| Tool failure | Stays API paazhaiya prices tharudhu | Ovvoru tool-aiyum thaniya test pannunga |
| Inefficiency | 5 podhum-nu irukkura idathula 14 steps | Oru task-ku steps, tokens, time, cost |

20 la irundhu 50 realistic test tasks vachukkunga, ovvonnukkum success-na enna-nu kooda, ovvoru prompt, tool, model maatrathukkum apram run pannunga, success rate, average steps, oru task-ku cost-a track pannunga.

**Ovvoru step-layum context valarum.** Ovvoru tool result-um conversation-la irukkum, adhanaala neenda runs mella aagum, expensive-aagum, model track-a izhakkalaam. Short, relevant tool results thaarunga (top five stays, ainnooru illa), neenda runs-la pazhaya results-a summarise pannunga illa drop pannunga.

**Common workflow shapes.** Agent-a eduppadharkku munnadi, idhula onnu set aagudhaanu paarunga. **Chain** fixed steps-a order-la run pannum, example extract, apram check, apram draft. **Router** request-a classify panni, pala specialised prompts-la onnukku anuppum. **Parallel** calls task-a independent parts-aa pirichu results-a merge pannum. **Evaluator loop**-la oru call draft pannum, innoru call criteria-vukku ethiraa check pannum, fixed ennikkai thadava thirumba seiyum. Agents-nu solla padura neraya products unmaiyaa indha shapes-la onnu thaan, avai test panna easy.

**Aarambathula runs-la enna gavanikkanum.** Irubadhu real tasks-ku ovvoru step-oda tool-aiyum arguments-aiyum print pannunga. Sirya maatrangalodu thirumba varra calls, model eppovume use pannaadha tools, model oru result-a thappaa padikkura steps-a paarunga. Ovvoru pattern-um oru tool-oda description-la, adhoda error messages-la illa system prompt-la irukkura stop condition-la oru fix-a kaattum.

## Oru worked example

Bengaluru-la oru travel startup "Bengaluru-la irundhu rendu perukku, ₹25,000-kulla, Coorg-la 3-naal weekend plan pannunga"-nu kekkura kelvikku badhil solla oru assistant vendum-nu virumbudhu.

Tools: `search_stays(location, dates, budget)`, `get_travel_options(from, to, date)`, `get_weather(location, dates)`.

Oru run:

1. Model andha dates-ku Coorg-ku `get_weather`-a call pannudhu: lesaa mazhai varum.
2. `get_travel_options`-a call pannudhu: 6-mani neram drive illa bus.
3. Rendu raathiri-kku ₹14,000 budget-oda `search_stays`-a call pannudhu: moonu homestays vandhudhu.
4. Oru plan-oda badhil sollum: drive, mazhai-nala covered sit-out irukkura homestay, rendu indoor-friendly activities, sumaar ₹22,000 cost breakdown.

Naalu model calls, moonu tool calls. 10 steps cap-oda, onnum match aagaadha podhu oru run `search_stays`-a konjam konjam maaritha budgets-oda loop aachu; adhu cap-la nindrudhu, app "We couldn't find stays in that budget; try other dates"-nu kaattichu. Team apram tool-a "no stays under ₹X; cheapest is ₹Y"-nu tharura maadhiri improve pannaanga, loop nindruduchu.

| Run | Steps | Outcome | Panna maatram |
| --- | --- | --- | --- |
| Typical | 4 model calls, 3 tool calls | Sumaar ₹22,000-la plan | Onnum illa |
| Budget-la stays illa | 10-step cap-a thottudhu | User-ku clean message | Tool ippo "cheapest is ₹Y"-nu solludhu |
| Adhe case, maatrathukku apram | 5 steps | Vera dates suggest pannichu | Loop poiduchu |

## Podhuvaa panra thappugal

- **Workflow podhumaana idathula agent use panradhu.**
- **Step limit illaama.**
- **Vague tools-um errors-um.** Appo agent guess pannum illa loop aagum.
- **Instructions-la stop condition illaama.**
- **Ovvoru step-aiyum log pannaama.** Paakka mudiyaadhadha debug panna mudiyaadhu.

- **Fail aana tool-a endrum retry panradhu.** Clear message-oda error-a model-kitta thirumba kudunga, onnu pola irukkura rendu moonu failures-ku apram nirutthunga.
- **Agent-oda "done"-a nambradhu.** Mudinja idathula result-a code-la check pannunga.
- **Agent-ku ungalitta irukkura ella tools-aiyum kudukkradhu.** Adhigam tools-na adhigam thappaana choices-um, neenda prompts-um.
- **Rendu happy-path tasks-la test panradhu.** Agents-ku pala vidhamaana tasks-oda oru set venum, oru thadavaikku mela run pannanum, yenna results ovvoru run-kum maarum.

## Agent build panna vendaam-nu eppo

- **Steps therinjaa**: fixed workflow cheap, vegam, test panna easy.
- **Thappugal selavu, undo panna kashtam-na**, example payments illa customers-ku messages, ovvoru action-aiyum oru aal approve pannaadha varaikkum.
- **Latency mukkiyam-na**: rendu second-kulla reply venumna, pala model calls-ku idam irukkaadhu.
- **Retrieval-oda oru nalla call munnamae work aagudhunna**: mudhalla andha baseline-a measure pannunga.

## Demo-la irundhu production-ku

- **Limits-a code-la vainga**: ovvoru task-kum steps, tokens, time, panam, edhu thottaalum clean handover.
- **Ovvoru run-aiyum trace pannunga**: ovvoru step-oda tool, arguments, result, tokens, time.
- **Tasks-oda oru test set vachukkunga**, success rate, steps, oru task-ku cost-a neram pogum podhu track pannunga.
- **Write actions-a gate pannunga**: read-only tools thaarumaaraa run aagalaam; data-va maathura illa makkala contact panra edhukkum approval illa tight rules vendum.
- **Mudhalla narrow-aa ship pannunga**: oru task type, konjam tools, oru clear stop rule, apram numbers allow panna maadhiri widen pannunga.
