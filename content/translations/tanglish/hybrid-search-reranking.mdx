## Idhu enna

Vector search similar meaning irukkura passages-a kandupidikkum. Keyword search ore words irukkura passages-a kandupidikkum. Onnu fail aagura idathula innonnu jeyikkum:

- "How do I claim for a cracked phone screen?" Vector search accidental damage clause-a kandupidikkum, adhu "breakage of display"-nu irundhaalum. Keyword search miss pannalaam.
- "What does clause 7.3(b) say?" illa "error E-4012" Keyword search sariyaa pidikkum. Vector search konjam kittathula irukkura clauses-a tharum.

**Hybrid search** rendaiyum odi results-a merge pannum. **Reranking** merge aana top 20 mudhal 50 results-a eduthu, slow-aana, innum accurate-aana oru model-oda thirumba order pannum. **Metadata filters** search-a mudhalla sariyaana slice-kku kuraikkum, oru product, oru state, illa oru date-ku aprom amalla irukkura documents maadhiri.

```flow
Query -> BM25 keyword search | top 40, filtered by product, state, in force
Query -> Vector search | top 40, same filters
BM25 keyword search -> Fusion: reciprocal rank | top 40
Vector search -> Fusion: reciprocal rank
Fusion: reciprocal rank -> Cross-encoder reranker | reads the query and passage together
Cross-encoder reranker -[top 5]-> Prompt
```

Indha lesson-la Chennai-la oru insurance company-a follow pannuvom, avanga agents policy wordings pathi vivaramaana kelvigal kekkuraanga.

## Idhu eppadi work aagudhu

**Keyword pakkam.** Perumbaalaana systems BM25 use pannum, query-oda words, especially rare words, irukkura passage-ku adhigam score kudukkum, neenda passages-ku adhigam reward kodukkaadhu. Elasticsearch, OpenSearch, neraya vector databases idha tharum. PostgreSQL-oda built-in full-text search BM25 illa, adhoda sondha functions-oda (`ts_rank`) rank pannum; extensions BM25-a serkkum.

**Vector pakkam.** Query-a embed panni, kittathula irukkura chunk embeddings-a kandupidinga.

**Fusion.** Rendu scores-um vera vera scales-la irukku, adhanaala veruma serkka mudiyaadhu. Rendu common vazhigal: ovvonnayum 0 mudhal 1-ku normalise panni weighted sum edukkalaam (0.5 "alpha" rendaiyum samamaa weight pannum), illa raw scores-a madhikkaama, rendu lists-la edhuvaa irundhaalum mela rank aana items-ku reward tharum reciprocal rank fusion use pannalaam. RRF simple, udaikka kashtam, adhanaala nalla default.

**Reranking.** Embedding model query-yaiyum passage-aiyum thaniyaa encode pannum, vegam, aana detail poidum. **Cross-encoder** rendaiyum serthu padichi relevance-a neradiyaa score pannum. Oru million passages-la odikka romba slow, aana 40-la nallaa irukkum. Hybrid search-la wide-aa retrieve pannunga, rerank pannunga, prompt-ku top 5-a vechukkunga.

**Filters.** Ovvoru chunk-odayum `doc_type`, `state`, `effective_from`, `access_group` maadhiri fields-a store pannunga. Sambandham illaadha, pazhaya documents compete pannaadha maadhiri, query-laye apply pannunga. Per-user permissions-um filters-la thaan enforce aagum, adha pinnaadi oru lesson-la paapom.

**Reciprocal rank fusion oru varila.** Oru passage vara ovvoru list-layum 1 / (60 + adhoda rank) score kidaikkum, scores serkkappadum. BM25-la 1-aavadhum vectors-la 3-aavadhum rank aana passage-ku approx 1/61 + 1/63; ore list-la mattum 2-aavadhu rank aanadhukku 1/62. Rendu methods-um virumbura passages mela varum, raw score scales-a edhuvum sarndhirukkaadhu.

**Settings choose panradhu:**

| Setting | Typical value | Eppo adhigam pannanum |
| --- | --- | --- |
| Ovvoru search-la irundhu candidates | 20 mudhal 50 | Sariyaana passage adikkadi list-ku veliya irundhaa |
| Reranker-ku anuppura candidates | 20 mudhal 50 | Recall at 50, recall at 5-a vida romba adhigam-naa |
| Prompt-ku vechukkura passages | 3 mudhal 8 | Kelvigalukku pala passages serthu thevai-naa |
| Weighted fusion-la weight | 0.5 | Ungaloda golden set oru pakkam adhigam help pannudhunnu kaattunaa |

Idhai feel-la illa, golden set-la tune pannunga, ovvoru thadavaiyum recall-oda latency-aiyum record pannunga.

**Postgres-kulla hybrid search.** Full-text search-um pgvector-um oru table-la irundhaa, oru query reciprocal rank fusion-oda rendaiyum fuse pannum:

```sql
WITH kw AS (
  SELECT id, row_number() OVER (ORDER BY ts_rank(tsv, q) DESC) AS r
  FROM chunks, websearch_to_tsquery('english', $1) q
  WHERE tsv @@ q AND access_group = ANY($3) AND effective_from <= current_date
  ORDER BY ts_rank(tsv, q) DESC LIMIT 40
), vec AS (
  SELECT id, row_number() OVER (ORDER BY embedding <=> $2) AS r
  FROM chunks
  WHERE access_group = ANY($3) AND effective_from <= current_date
  ORDER BY embedding <=> $2 LIMIT 40
)
SELECT c.id, c.section, c.body,
       coalesce(1.0 / (60 + kw.r), 0) + coalesce(1.0 / (60 + vec.r), 0) AS score
FROM chunks c
LEFT JOIN kw ON kw.id = c.id
LEFT JOIN vec ON vec.id = c.id
WHERE kw.id IS NOT NULL OR vec.id IS NOT NULL
ORDER BY score DESC LIMIT 30;
```

`tsv` chunk text-la irundhu build panna, store aana `tsvector` column. Ore permission, date filters rendu pakkathukum poradhunaala, user paaka koodaadhadhu edhuvum candidate-aa varaadhu.

**Oru pakkam adhigam mukkiyam-naa weighted fusion.** Ovvoru list-oda scores-aiyum 0 mudhal 1-ku normalise pannunga, appuram mix pannunga:

```python
import re

def minmax(scores):
    lo, hi = min(scores.values()), max(scores.values())
    return {k: (v - lo) / (hi - lo) if hi > lo else 1.0 for k, v in scores.items()}

def looks_exact(query):
    return bool(re.search(r"\b[A-Z]{2,}-?\d{2,}\b|\b\d{6,}\b", query))     # codes, long numbers

def weighted(query, kw_scores, vec_scores):
    alpha = 0.7 if looks_exact(query) else 0.4                            # weight on keywords
    kw, vec = minmax(kw_scores), minmax(vec_scores)
    ids = set(kw) | set(vec)
    return sorted(ids, key=lambda i: alpha * kw.get(i, 0) + (1 - alpha) * vec.get(i, 0), reverse=True)
```

Weights-a golden set-la irundhu set pannunga: ovvoru query vagaikkum 0.3, 0.5, 0.7 try panni, edhu jeyikkudho adha vechukkunga.

**Indian-language text.** Keyword search words-a spaces-la pirikkum, English-ku mattum stem pannalaam. Hindi illa Tamil-ku, "simple" text configuration (stemming illa) use pannunga, "biryani"-yum "बिरयानी"-yum match aaga key fields-oda transliterated copies-a yosinga, multilingual embedding model-a adhigam nambunga.

**Latency budget.** Rendu searches-um oru reranker-um serndhu aagum. Keyword, vector searches-a parallel-aa odunga, candidates-a recall-ku thevaiyaana alavukku cap pannunga, ovvoru stage-oda p95 latency-aiyum measure pannunga. Reranker thaan slow-naa, adha vidradhukku munnaadi sinna one-a illa kammi candidates-a try pannunga.

## Oru worked example

Chennai-la oru insurance company-ku 4,000 pages policy wordings, endorsements, circulars irukku. Agents "Is flood covered under HOME-PLUS for Chennai after the 2026 revision?" maadhiri kelvigal kekkuraanga.

Ungaloda golden set-la therinja source passages-oda 60 kelvigal irukku. Recall at 5-a measure pannureenga (top aindhula sariyaana passage irukkura kelvigalin pagudhi):

- vector search mattum: 68%
- BM25 mattum: 61%
- RRF-oda hybrid: 79%
- hybrid, appuram top 40-la cross-encoder reranker: 88%
- adhe, `product = HOME-PLUS`-kum revision-ku aprom `effective_from`-kum filter pannina: 93%

Failures-a paartha yen-nu puriyum. "END-17" maadhiri endorsement codes pera sonna kelvigala vector search miss pannudhu. BM25 paraphrases-a miss pannudhu. Sariyaana passage 8-aavadhu rank aana cases-a reranker fix pannudhu. Filter, ippo irukkura wording-a vida mela rank aagitu irundha maathappatta 2024 wording-a remove pannudhu.

Reranking ovvoru query-kum around 180 milliseconds serthudhu. Recall-la 9-point gain-ku client adha othukkittaanga, rendu numbers-aiyum eval report-la ezhudhureenga.

| Set-up | Recall at 5 | Serndha latency |
| --- | --- | --- |
| Vector mattum | 68% | Baseline |
| BM25 mattum | 61% | Kammi |
| RRF-oda hybrid | 79% | Around 20 ms |
| Hybrid + 40-la reranker | 88% | Around 180 ms |
| Product, effective date filters-um serthu | 93% | Extra illa |

Ovvoru step-um vera vagai failure-a fix pannudhu, adhanaala totals-a pola failed kelvigala padikkuradhum mukkiyam.

## Podhuvaa panra thappugal

- **Raw scores-a serkkradhu.** BM25-yum cosine scores-um vera scales; periya score amaidhiyaa dominate pannum. Normalise pannunga illa RRF use pannunga.
- **Romba kammiya rerank panradhu.** Sariyaana passage candidate list-la illaina reranker-aala kaapaatha mudiyaadhu. 20 mudhal 50 retrieve pannunga, 3 mudhal 8 vechukkunga.
- **Golden set illa.** Measure panna recall illaama, hybrid search help pannucha illa nallaa irukku-nu thonuchaa-nu solla mudiyaadhu.
- **Retrieval-kku aprom filter panradhu.** Top 5-a eduthu, scope-ku veliya irukkuradhai thookina onnume micham irukkaadhu. Search-kulla filter pannunga.
- **Indian text-ku tokenisation-a marakkradhu.** Tamil illa Hindi-la keyword search andha scripts-a handle panra analyser vendum, illaina matches amaidhiyaa fail aagum.
- **Indian-language text-la English stemming.** Simple configuration-um multilingual embeddings-um use pannunga.
- **Keyword-kum vector pakkathukum vera vera filters,** adhanaala oru pakkam innoru pakkam thavirkkura documents-a tharum.

## Plain vector search podhumaana idangal

- **Natural language-la kelvigal,** codes, numbers, rare names illaama.
- **Sinna collections,** sariyaana passage perumbaalum mela thaan irukkum.
- **Tight latency budgets,** ungaloda golden set hybrid konjam thaan add pannudhu-nu kaattura idam.

Test pannunga: hybrid-um reranking-um recall at 5-a konjam kooda nagarthalainaa, simple system-a vechukkunga.

## Demo-la irundhu production-ku
