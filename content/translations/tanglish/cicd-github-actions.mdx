## Idhu enna

**Continuous integration (CI)** ovvoru pull request-layum checks run pannum: lint, type checks, unit tests, AI systems-kku oru chinna eval. Branch protection irukkaradhaala fail aagura change merge aagavae mudiyaadhu.

**Continuous delivery (CD)** merge aana ovvoru change-aiyum environments vazhiyaa thaanaa kondu pogum: oru image build pannum, staging-la deploy pannum, smoke test pannum, appuram oruthar approve pannadhum production-kku promote pannum. Andha approval step illanna adhukku **continuous deployment**-nu per. Banking, insurance, health-la irukkura perumbaalaana client teams approval-a thaan virumbuvaanga.

Rendaiyum panna GitHub Actions oru common vazhi. GitLab CI, Azure DevOps, Jenkins-um idhe ideas-a vera syntax-la use pannudhu; oru client-kku avangaloda sondha choice irukkum.

```flow
title: Pull request-la irundhu production varai
Pull request -> CI: lint, types, tests, smoke eval -> Pass aachaa?
Pass aachaa? -[illa]-> Merge block aagum
Pass aachaa? -[aamaa]-> Review panni main-kku merge
Review panni main-kku merge -> Ore oru image build | tag = commit hash
Ore oru image build -> Staging-la deploy -> Staging-la smoke test -> Per sonna reviewer-oda approval
Per sonna reviewer-oda approval -> Adhe image-a production-kku promote -> Healthy-aa irukkaa?
Healthy-aa irukkaa? -[illa]-> Kadaisi nalla tag-a redeploy
```

Indha lesson, Kochi-la oru insurer-oda engineering team-kku oru claims assistant-a handover panradhai follow pannudhu.

## Idhu eppadi work aagudhu

### Oru workflow-oda parts

| Part | Adhu enna | Indha lesson-la |
| --- | --- | --- |
| Workflow | `.github/workflows/`-la oru YAML file | `ci-cd.yml`, `rollback.yml` |
| Event | Adhai start panradhu edhu | Oru pull request, main-kku oru push, oru manual run |
| Job | Oru fresh machine-la (runner) odura steps-oda group | test, smoke-eval, build, deploy-staging, deploy-production |
| Step | Oru command, illanna oru ready-made **action** | `uv run pytest`, `docker/build-push-action` |
| Environment | Sondha secrets, rules irukkura per vacha oru deploy target | staging, production |

Oru job innonnai `needs` pannalai-nna jobs parallel-aa odum. Ovvoru job-um oru clean machine-la start aagum, adhanaala adhukku enna venumo (code, tools, credentials) adhai adhuve fetch pannanum.

### Edhu enga odudhu, evvalavu thadavai

| Check | Eppo | Vazhakkamaana neram | Build-a fail pannumaa? |
| --- | --- | --- | --- |
| Lint, format, type checks | Ovvoru pull request-layum | Oru nimishathukkulla | Aamaa |
| Fake model vachu unit tests | Ovvoru pull request-layum | 1 mudhal 3 nimisham | Aamaa |
| Smoke eval, 50 golden questions | Prompts, retrieval allathu evals-a thodura pull requests | 2 mudhal 4 nimisham | Aamaa, main-a vida theliva keezha ponaa |
| Staging smoke test | Ovvoru staging deploy-kkum appuram | Oru nimishathukkulla | Aamaa, production-a block pannum |
| Full eval, noottrukkanakkaana cases | Ovvoru raathiriyum | 10 mudhal 60 nimisham | Team-kku alert pannum |

Indha nerangal vazhakkamaana ranges thaan, measurements illa. Table-kku pinnaadi irukkura rule: oru check evvalavu fast-aa, cheap-aa irukko, avvalavu seekkiram adhu odanum.

### Flake aagaadha oru smoke eval

Oru model perfect-aa repeat aagaadhu, adhanaala oru chinna eval adhe code-la pass-um aagalaam, fail-um aagalaam. 20 questions irundhaa, ovvoru question-um 5 points: oru answer maarinaa score 0.85-la irundhu 0.80-kku poyidum. Rerun pannaa maarura oru gate, green varra varai "Re-run" amukka aalungalukku kathukudukkum, appuram unmaiyaana failures-aiyum ignore pannuvaanga. Naalu pazhakkangal idhai sari pannum:

- **Sumaar 50 cases use pannunga.** Appo ovvoru case-um 5 illa, 2 points thaan.
- **Temperature 0 use pannunga**, unga model support pannaa; koodave oru fixed retrieval index.
- **Fail aana case-a oru thadavai retry pannunga.** Unmaiyaana regression rendu thadavaiyum fail aagum; noise podhuvaa appadi aagaadhu.
- **Fixed number kooda illa, main kooda compare pannunga.** Main-oda score-a `evals/baseline.json`-la store pannunga (oru nightly job adhai refresh pannalaam), pull request 2 cases-kku mela mosamaa irundhaa mattum fail pannunga. Koodave oru hard floor-um vachukkonga, appo medhuvaana drift pass aagaadhu.

Keezha irukkura `expected in answer` check oru crude smoke test thaan: andha phrase-a tharseyalaa vachirukkura neelamaana answers-kku adhu reward kudukkum. Nightly full eval innum strict-aana grading use pannanum. Script adhoda exit code vachu mudivu pannum; non-zero exit edhuvaa irundhaalum job fail aagum.

```python
import argparse, json, sys
from app.answer import answer   # your pipeline, called with temperature 0

p = argparse.ArgumentParser()
p.add_argument("--baseline", default="evals/baseline.json")
p.add_argument("--tolerance", type=int, default=2)   # cases, not percent
p.add_argument("--floor", type=float, default=0.80)
args = p.parse_args()

def ok(case):
    return case["expected"].lower() in answer(case["question"]).lower()

cases = [json.loads(line) for line in open("evals/smoke.jsonl")]
correct = sum(ok(c) or ok(c) for c in cases)          # one retry per failed case
base = json.load(open(args.baseline))["correct"]
print(f"smoke: {correct}/{len(cases)} correct, main has {base}")
failed = correct < base - args.tolerance or correct / len(cases) < args.floor
sys.exit(1 if failed else 0)
```

### Secrets, environments, OIDC

**Secrets** repository allathu environment settings-la irukkum, encrypt aagi, logs-la mask aagi; repository-kkulla eppavum illa. Ovvoru environment-kkum sondha secrets kudunga, appo oru staging key production-a eppavum ettaadhu. Required reviewer job-a approve panra varai oru environment-oda secrets lock-aa irukkum.

**Required reviewers.** Aaru per allathu teams varai per sollalaam; oru approval podhum. Deploy-a start pannavare adhai approve panradhaiyum thadukkalaam. GitHub Free, Pro, Team-la required reviewers public repositories-la mattum thaan work aagum; private repositories-kku GitHub Enterprise venum. Approval gate-a promise panradhukku munnaadi client-oda plan-a check pannunga.

**Forks-la irundhu varra pull requests-kku secrets kidaikkaadhu** (limited-aana oru `GITHUB_TOKEN` thavira). Adhanaala thaan keezha irukkura smoke eval fork pull requests-a skip pannudhu; adhai oru maintainer kaiyaala evaluate pannuvaaru. Workaround-aa `pull_request_target` trigger-a use pannaadheenga: adhu unga secrets kooda odum, adhanaala oru fork-oda code-a adhula run pannaa oru anniyar avattrai padikka mudiyum.

**Keys-kku badhilaa OIDC.** `id-token: write` irundhaa, oru job GitHub kitta repository, environment per irukkura oru signed token kekkalaam, udhaaranamaa `repo:kochi-insure/claims-assistant:environment:production`. Cloud sariyaa andha per-oda match aagura tokens-a mattum nambi, expire aagura credentials-a thiruppi kudukkum; AWS-la default-aa oru mani nerathukku appuram. Leak aaga long-lived key edhuvum illa. Azure, Google Cloud-layum idhe pattern irukku.

**Registry.** GitHub-oda registry-kku (GHCR) push panna `GITHUB_TOKEN` mattum podhum. Aanaa AWS-la irukkura oru service private GHCR image-a pull pannanum-naa oru stored pull credential venum. Client AWS-la run pannaa, avanga ECR registry-kku push panradhu perumbaalum simple, yenna IAM role erkanave pull access kudukkudhu.

### Supply chain: ovvoru action-aiyum pin pannunga

Oru third-party action unga code, secrets-kku access kooda odum. `@v4` maadhiri oru version tag oru pointer thaan, adhoda owner (allathu oru attacker) adhai move pannalaam. March 2025-la attackers prabalamaana `tj-actions/changed-files` action-oda tags-a build logs-la secrets-a print panra malicious code-kku move pannaanga (CVE-2025-30066). Munnaadi irundha commit SHA-kku pin pannina workflows safe code-aiye thodarndhu run pannuchu.

Adhanaala ovvoru third-party action-aiyum adhoda full 40-character commit SHA-kku pin pannunga, version-a oru comment-la podunga, Dependabot updates propose pannattum (`.github/dependabot.yml`-la `package-ecosystem: "github-actions"` add pannunga). Oru update-a merge panradhukku munnaadi diff-a padinga. 28 November 2026 annaikku check pannappo rendu notes:

- `astral-sh/setup-uv` v7-kku appuram moving major tags publish panradhilla, adhanaala `@v10` resolve aagaadhu. Adhoda sondha README-ye oru SHA-va pin pannudhu.
- GitHub ippo workflow lockfiles-a (`.github/workflows/actions.lock`, `gh actions-lock` vachu uruvaakkinadhu) document pannudhu; adhu unga actions use panra actions-aiyum pin pannum. Adhoda setup guide GitHub Enterprise Cloud-kku thaan list aagiyirukku; matha plans-la SHA pins use pannunga.

### Speed, cost, safety switches

- **Caching.** GitHub-hosted runners-la `setup-uv` default-aa packages-a cache pannum. Matha tools-kku lock file vachu cache pannunga. Fast CI-a aalunga use pannuvaanga; slow CI-a bypass pannuvaanga.
- **Concurrency.** Adhe pull request-kku yaaraavadhu thirumba push pannaa pazhaya run-a cancel pannunga. Main-la odura run-a eppavum cancel pannaadheenga: adhu oru deploy-oda paadhiyila irukkalaam. Ovvoru deploy target-kkum sondha concurrency group kudunga, appo rendu deploys eppavum overlap aagaadhu.
- **Timeouts.** Oru job-oda default timeout 360 nimisham. Ovvoru job-layum `timeout-minutes` set pannunga, appo maattikitta oru model call aaru mani nera runner time-a veenaakkaadhu.
- **Path filters job-kkulla.** `on.pull_request.paths` vachu mottha workflow-aiyum skip pannaa, adhula irundhu varra required check "Pending"-aave irundhu merge-a block pannum. Adhanaala smoke eval job eppavum odum, adhoda steps enna maarichu-nnu check pannum.
- **Least privilege.** Mela `permissions: {contents: read}` set pannunga, oru job-kku enna venumo adhai mattum add pannunga, udhaaranamaa `packages: write` allathu `id-token: write`.

### Branch protection

Main-kkaana repository rules-la, merge panradhukku munnaadi test, smoke-eval checks pass aaganum, kuranjadhu oru review venum-nu require pannunga. Idhu illanna CI verum advice thaan.

### Muzhu workflow

Action versions 28 November 2026 annaikku check pannadhu. Aarume Node 24 runtime-a declare pannudhu.

```yaml
name: ci-cd
on:
  pull_request:
  push:
    branches: [main]

permissions: {contents: read}
concurrency:                       # cancels old pull request runs only
  group: ${{ github.workflow }}-${{ github.head_ref || github.run_id }}
  cancel-in-progress: true
env:
  IMAGE: ${{ vars.IMAGE_REPO }}:${{ github.sha }}   # registry names must be lowercase

jobs:
  test:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: astral-sh/setup-uv@1db35dd8eee11c5894872e0b383ae6c406cf738d # v10.4.0
      - run: uv sync --frozen
      - run: uv run ruff check . && uv run mypy src && uv run pytest -q

  smoke-eval:
    if: github.event_name == 'pull_request' && github.event.pull_request.head.repo.full_name == github.repository
    runs-on: ubuntu-latest
    timeout-minutes: 10
    permissions: {contents: read, pull-requests: read}
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: dorny/paths-filter@ceb8a2b8f2d89434be7ff52d3de7ec3738c5cc9d # v4.0.3
        id: changed
        with:
          filters: |
            ai: ['prompts/**', 'src/retrieval/**', 'evals/**']
      - if: steps.changed.outputs.ai == 'true'
        uses: astral-sh/setup-uv@1db35dd8eee11c5894872e0b383ae6c406cf738d # v10.4.0
      - if: steps.changed.outputs.ai == 'true'
        run: uv sync --frozen && uv run python evals/smoke.py --tolerance 2
        env:
          ANTHROPIC_API_KEY: ${{ secrets.EVAL_API_KEY }}

  build:
    needs: test
    if: github.event_name == 'push'
    runs-on: ubuntu-latest
    timeout-minutes: 20
    permissions: {contents: read, packages: write}
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: docker/login-action@8aa5831fb8d48d8f76594c7ddde61ae58019f550 # v4.8.0
        with: {registry: ghcr.io, username: "${{ github.actor }}", password: "${{ secrets.GITHUB_TOKEN }}"}
      - uses: docker/build-push-action@c3c9e263c25d99ce0380d002d59b67737d91b0dc # v7.4.0
        with: {context: ., push: true, tags: "${{ env.IMAGE }}"}

  deploy-staging:
    needs: build
    environment: staging
    concurrency: {group: deploy-staging}
    runs-on: ubuntu-latest
    timeout-minutes: 15
    permissions: {contents: read, id-token: write}
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: aws-actions/configure-aws-credentials@45666896f5d8e0f10ae255413f3a4cdd03bdc8f5 # v6.3.1
        with: {role-to-assume: "${{ vars.DEPLOY_ROLE_ARN }}", aws-region: ap-south-1}
      - run: ./scripts/migrate.sh && ./scripts/deploy.sh "$IMAGE"
      - run: ./scripts/smoke_test.sh "${{ vars.BASE_URL }}"   # health check plus five real questions

  deploy-production:
    needs: deploy-staging
    environment: production          # required reviewers; its own role and secrets
    concurrency: {group: deploy-production}
    runs-on: ubuntu-latest
    timeout-minutes: 15
    permissions: {contents: read, id-token: write}
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: aws-actions/configure-aws-credentials@45666896f5d8e0f10ae255413f3a4cdd03bdc8f5 # v6.3.1
        with: {role-to-assume: "${{ vars.DEPLOY_ROLE_ARN }}", aws-region: ap-south-1}
      - run: ./scripts/migrate.sh && ./scripts/deploy.sh "$IMAGE"   # same image, no rebuild
      - run: ./scripts/smoke_test.sh "${{ vars.BASE_URL }}"
```

`vars.DEPLOY_ROLE_ARN`, `vars.BASE_URL` rendum environment variables, adhanaala adhe lines oru job-la staging-aiyum innonnula production-aiyum point pannum.

### Rollback, adhu work aagumaa-nnu migrations yen mudivu pannudhu

Ovvoru image-um adhoda commit vachu tag aagiyirukkaradhaala, rollback-na kadaisi nalla tag-a redeploy panradhu thaan. Adhai adhe production environment, approval use panra oru manual workflow-aa aakkunga:

```yaml
name: rollback
on:
  workflow_dispatch:
    inputs:
      sha: {description: "Commit of the last good image", required: true}
permissions: {contents: read, id-token: write}
jobs:
  rollback:
    environment: production
    concurrency: {group: deploy-production}
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: aws-actions/configure-aws-credentials@45666896f5d8e0f10ae255413f3a4cdd03bdc8f5 # v6.3.1
        with: {role-to-assume: "${{ vars.DEPLOY_ROLE_ARN }}", aws-region: ap-south-1}
      - run: ./scripts/deploy.sh "${{ vars.IMAGE_REPO }}:$SHA"
        env: {SHA: "${{ inputs.sha }}"}   # passed as a variable, not pasted into the script
```

App-a roll back pannaa database roll back aagaadhu. Release 42 oru column-a rename pannaa, release 41-oda image pudhu schema-la crash aagum. Adhanaala migrations-a deploy-kku munnaadi thani step-aa run pannunga, schema-va **expand and contract** steps-aa maathunga: release onnu pudhu column-a add panni rendukkum write pannum; release rendu pudhusai read pannum; release moonu, vaarangal kazhichu, pazhaya column-a drop pannum. Endha point-layum mundhaiya image innum work aagum.

**Unga browser-laye try pannunga.** Indha checker timeouts illaadha jobs-aiyum, commit SHA-kku pin pannaadha actions-aiyum kandupidikkum. Unga sondha workflow-a paste panni run pannunga.

```python
import re, yaml

workflow = yaml.safe_load("""
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: some-org/setup-thing@v2
      - run: pytest -q
""")
for name, job in workflow["jobs"].items():
    if "timeout-minutes" not in job:
        print(f"{name}: add timeout-minutes (the default is 360)")
    for step in job.get("steps", []):
        ref = step.get("uses", "")
        if ref and not ref.startswith("./") and not re.fullmatch(r"[0-9a-f]{40}", ref.split("@")[-1]):
            print(f"{name}: pin {ref} to a full commit SHA")
```

## Podhuvaa panra thappugal

- **Main-la mattum CI.** Problems merge aanadhukku appuram thaan theriyum. CI-a pull requests-la run panni required check aakkunga.
- **Fixed threshold kooda oru kutti eval.** Adhu flake aagum, aalunga green varra varai rerun panna pazhagiduvaanga. Sumaar 50 cases, temperature 0, oru retry use panni, main kooda compare pannunga.
- **Ovvoru push-layum paid evals.** Prompts, retrieval allathu evals maarumbodhu mattum smoke eval run pannunga; full suite-a raathiri run pannunga.
- **Path filter vachu mottha workflow-aiyum skip panradhu.** Adhoda required checks Pending-aave irukkum. Job-kkulla filter pannunga.
- **Files-la secrets, allathu long-lived cloud keys-a secrets-aa vachirukkaradhu.** Environment secrets use pannunga, cloud access-kku OIDC.
- **Ovvoru environment-kkum rebuild panradhu.** Oru thadavai build panni, adhe image-a promote pannunga.
- **Tag vachu pin pannina third-party actions.** Tags move aagum. Full SHAs-a pin panni, Dependabot updates propose pannattum.
- **Workflow muzhukka cancel-in-progress.** Oru pudhu merge oru deploy-a paadhiyila konnudum. Pull request runs-a mattum cancel pannunga.
- **Timeouts illa.** Maattikitta oru job aaru mani neram varai odum.
- **Yaarume try pannaadha rollback, allathu adhai udaikkura migration.** Rollback-a practice pannunga, expand and contract use pannunga.
- **Flaky tests-a appadiye vidradhu.** Seekkiramaa fix pannunga illanna remove pannunga, illaatti unmaiyaana failures-aiyum ignore pannuvaanga.
