## Idhu enna

**Continuous integration (CI)** ovvoru change-kum checks-a run pannum: lint, type checks, unit tests, AI systems-ku oru chinna eval suite. Fail aagura change merge aagaadhu.

**Continuous delivery (CD)** merge aana oru change-a environments vazhiyaa thaanaave konduponum: oru image build pannunga, staging-ku deploy pannunga, smoke tests run pannunga, apram production-ku deploy pannunga, perumbaalum oru aal approve pannadhukku apram.

GitHub Actions rendayum pannura oru common vazhi. Workflows `.github/workflows/`-la YAML files, pull request illa main-ku push maadhiri events-la run aagum. GitLab CI, Azure DevOps, Jenkins-um ippadiye work aagum; clients-ku avangaloda sondha choice irukkum.

```flow
Pull request -> CI: lint, types, tests, smoke eval -> Pass?
Pass? -[illa]-> Block aachu
Pass? -[aamaa]-> Merge pannalaam -> Main-ku merge
Main-ku merge -> Image-a build pannunga | tag = commit hash
Image-a build pannunga -> Staging-ku deploy -> Smoke tests -> Peyar kudutha reviewer-oda approval -> Ade image-a production-ku deploy -> Problem?
Problem? -[aamaa]-> Munna tag-a thirumba deploy pannunga
```

Indha lesson Kochi-la oru insurer-oda engineering team-ku oru claims assistant-a handover panradha follow pannum.

## Idhu eppadi work aagudhu

**Triggers-um jobs-um.** Oru workflow events-la (`pull_request`, main-ku `push`, oru tag, oru manual dispatch) run aagum. Adhula jobs irukkum; ovvoru job-um pudhu machine-la steps-a run pannum, adhukku runner-nu peyar.

**CI job** code-a checkout pannum, dependencies-a install pannum (caching-oda), lint, types, tests-a run pannum. AI app-ku, oru chinna, vegamaana eval serunga: oru fixed retrieval index-ku ethiraa 20 golden questions, accuracy oru threshold-ku keezha pona build-a fail pannunga. Mellaana, selavaana evals-a oru nightly job-ku vainga.

**Build job** Docker image-a build pannum, commit hash-oda tag pannum, client-oda registry-ku push pannum.

**Deploy jobs** **environments**-a use pannum. `staging` environment thaanaave deploy aagum; `production` environment-ku peyar kudutha reviewer-oda approval thevai, adhukku thanoda secrets-um irukkum. Secrets CI system-la store aagum illa run neraththula cloud-la irundhu eduppaanga; repository-la eppovum illa. Innum nalladhu, stored keys-ku badhila, OpenID Connect vazhiyaa runner kurugiya aayul credentials-oda cloud-la sign in pannattum.

**Rollback.** Ovvoru deploy-um oru commit-oda tag panna image-a use pannradhaala, roll back-na munna tag-a thirumba deploy panradhu. Adha oru button illa command-aa aakkunga, practice pannunga.

**Enga edhu run aagum, evvalavu thadavai:**

| Check | Eppo | Typical neram | Build-a fail pannumaa? |
| --- | --- | --- | --- |
| Lint-um format-um | Ovvoru PR | Seconds | Aamaa |
| Type checks | Ovvoru PR | Oru nimishathukku kammi | Aamaa |
| Fake model-oda unit tests | Ovvoru PR | 1 mudhal 3 nimisham | Aamaa |
| Smoke eval, 20 golden questions | Prompts illa retrieval-a thodura ovvoru PR | 1 mudhal 2 nimisham | Aamaa, oru threshold-ku keezha |
| Full eval, nooru kanakkaana cases | Nightly | 10 mudhal 60 nimisham | Team-ku alert |
| Load test | Periya releases-ku munnaadi | Maarum | Romba mellaa irundhaa release-a thadukkum |

**Caching.** Ovvoru run-lum dependencies-a install panradhu mellaa irukkum. Lock file-a vachchu cache pannunga, appo CI pathu nimisham illa, konja nimisham edukkum. Vegamaana CI use aagum; mellaana CI-a thavirppaanga.

**Branch protection.** Repository settings-la, main-ku merge panradhukku munnaadi CI job pass aaganum, kuraindha pakshathula oru review vennum-nu vainga. Idhu illaama, CI verum yosanai mattum thaan.

**Nijathula secrets.** Workflow-ku sila secrets thevai: smoke eval-ku oru model API key, images push panna credentials, deploy panna credentials. Adhai repository illa environment-oda secret settings-la store pannunga, angu avai encrypt aagi logs-la maraikkappadum. Ovvoru environment-kum thani secrets kudunga, appo staging key production-a eppovum thodaadhu. Cloud access-ku, OpenID Connect-a virumbunga: cloud kuripitta repository-yaiyum branch-aiyum nambum, konja neraththula, perumbaalum oru manineram, expire aagura oru credential-a tharum. Appo leak aaga neenda aayul key-ae illa.

**Oru muzhu workflow.** Ovvoru pull request-lum CI, AI files maarumbodhu mattum smoke eval, main-la build-um deploy-um:

```yaml
name: ci
on:
  pull_request:
  push:
    branches: [main]

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v5
        with: {enable-cache: true}
      - run: uv sync --frozen
      - run: uv run ruff check . && uv run mypy src && uv run pytest -q

  smoke-eval:
    runs-on: ubuntu-latest
    if: github.event_name == 'pull_request'
    steps:
      - uses: actions/checkout@v4
      - uses: dorny/paths-filter@v3
        id: changed
        with:
          filters: |
            ai: ['prompts/**', 'src/retrieval/**', 'evals/**']
      - uses: astral-sh/setup-uv@v5
        if: steps.changed.outputs.ai == 'true'
      - if: steps.changed.outputs.ai == 'true'
        run: uv sync --frozen && uv run python evals/smoke.py --min-accuracy 0.85
        env:
          ANTHROPIC_API_KEY: ${{ secrets.EVAL_API_KEY }}

  build:
    needs: test
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    permissions: {contents: read, packages: write}
    steps:
      - uses: actions/checkout@v4
      - uses: docker/login-action@v3
        with: {registry: ghcr.io, username: "${{ github.actor }}", password: "${{ secrets.GITHUB_TOKEN }}"}
      - uses: docker/build-push-action@v6
        with: {push: true, tags: "ghcr.io/${{ github.repository }}:${{ github.sha }}"}

  deploy-production:
    needs: build
    runs-on: ubuntu-latest
    environment: production                    # requires a reviewer's approval
    permissions: {id-token: write, contents: read}
    steps:
      - uses: aws-actions/configure-aws-credentials@v4
        with: {role-to-assume: "${{ vars.DEPLOY_ROLE_ARN }}", aws-region: ap-south-1}
      - run: ./scripts/deploy.sh ghcr.io/${{ github.repository }}:${{ github.sha }}
```

Production job cloud access-a OIDC vazhiyaa (`id-token: write`-um cloud nambura oru role-um) vaangudhu, adhanaala GitHub-la neenda aayul cloud keys illa. Azure-kum Google Cloud-kum idhe maadhiri login actions irukku.

**Smoke eval script thanoda exit code-aala mudivu pannum.** Edhaavadhu non-zero exit job-a fail pannum:

```python
import argparse, json, sys
from app.answer import answer                 # your pipeline

p = argparse.ArgumentParser(); p.add_argument("--min-accuracy", type=float, default=0.85)
args = p.parse_args()
cases = [json.loads(l) for l in open("evals/smoke.jsonl")]
correct = sum(c["expected"].lower() in answer(c["question"]).lower() for c in cases)
acc = correct / len(cases)
print(f"smoke accuracy {acc:.0%} on {len(cases)} cases")
sys.exit(0 if acc >= args.min_accuracy else 1)
```

**Actions-a pin pannunga.** Third-party actions unga repository access-oda run aagum. Avai oru version-ku (illa innum kaduppaana setups-ku, oru muzhu commit hash-ku) pin panni, updates-a review pannunga, appo compromise aana action unga pipeline-ku ulla varaadhu.

**Mundhaiya runs-a cancel pannunga.** `concurrency` block, ade branch-ku thirumba push pannum podhu pazhaya run-a cancel pannum, adhu runner minutes-aiyum model calls-aiyum migaikkum.

**Unga browser-la try pannunga.** Oru workflow-la pin pannaadha actions-aiyum illaadha timeouts-aiyum check pannunga. YAML-a maathi run pannunga.

```python
import yaml

workflow = yaml.safe_load("""
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: some-org/setup-thing@main
      - run: pytest -q
""")
for name, job in workflow["jobs"].items():
    if "timeout-minutes" not in job:
        print(f"{name}: add timeout-minutes so a stuck job cannot run for hours")
    for step in job["steps"]:
        ref = step.get("uses", "")
        if ref and ref.split("@")[-1] in ("main", "master"):
            print(f"{name}: pin {ref} to a version, not a branch")
```

## Oru worked example

Neenga oru claims-assistant-a Kochi insurer-oda engineering team-ku handover panreenga. Avanga lead Anjali, ovvoru change-um test aaganum, avanga team sign-off illaama production-la edhuvum varakkoodaadhu-nu virumburaanga.

```yaml
name: ci-cd
on:
  pull_request:
  push:
    branches: [main]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v6
      - run: uv sync --frozen
      - run: uv run ruff check . && uv run mypy src && uv run pytest -q
      - run: uv run python evals/smoke.py --min-accuracy 0.85
  deploy-staging:
    if: github.event_name == 'push'
    needs: test
    environment: staging
    runs-on: ubuntu-latest
    steps:
      - run: ./scripts/build_push_deploy.sh staging ${{ github.sha }}
  deploy-production:
    needs: deploy-staging
    environment: production        # requires approval from the insurer's leads
    runs-on: ubuntu-latest
    steps:
      - run: ./scripts/deploy.sh production ${{ github.sha }}   # same image, no rebuild
```

Oru vaaram kazhichu oru teammate prompt-a maathuraanga, smoke eval 0.89-la irundhu 0.78-ku kuraiyudhu; CI fail aagudhu, PR merge aagaadhu. Konja naal kazhichu, oru production deploy mellaana responses-a undaakkudhu; Anjali workflow page-la irundhu munna commit-oda image-a rendu nimishathula thirumba deploy panraanga, perumbaalaana users-ku theriyaradhukku munnaadiyae.

**Insurer-oda team-ku enna maarudhu.** Pipeline-ku munnaadi, yaarukkavadhu gnaabagam vandhaa, oru laptop-la irundhu deploys nadandhadhu, edhu version live-nu yaarukkum urudhiyaa theriyaadhu. Adhukku apram, ovvoru production version-um workflow page-la kaattura oru commit hash, ovvoru deploy-kum peyar kudutha oru approver, smoke eval irandu maadhathula moonu prompt changes-a thadukkirukku, ovvonnum answer quality-a kuraichirukkum. Anjali solraanga, romba useful-aana vishayam vegam illa, urudhi: oru claims manager oru mosamaana answer-a report panna, edhu code-um prompt-um adha undaakkuchu-nu team-aala sariyaa sollamudiyum.

## Podhuvaa panra thappugal

- **Main-la mattum tests.** Merge-kku apram problems kandupidikkappadum. Pull requests-la CI run pannunga.
- **Prompt changes-ku CI-la eval illaadhadhu.** Prompt edits code changes; adhai test pannunga.
- **Workflow files-la secrets.** CI system-oda secrets illa kurugiya aayul cloud credentials use pannunga.
- **Ovvoru environment-kum veru images build panradhu.** Oru thadavai build pannunga, staging-la irundhu production-ku ade image-a promote pannunga.
- **Yaarum try pannaadha oru rollback.** Thevai padra munnaadi practice pannunga.

- **Flaky tests-a appadiyae vittirukkiradhu.** Thaanaave fail aagura oru test, pass aagura varaikkum CI-a thirumba run panna makkalukku kathu tharum, apram unmaiyaana failures-um ignore aagum. Flaky tests-a vegamaa fix illa remove pannunga.
- **Budget illaama ovvoru PR-lum live model-a call panra evals.** PR eval-a chinnadhaa, selavu kammiyaa vainga, mudiyuradha cache pannunga, muzhu suite-a oru schedule-la run pannunga.
- **OIDC irukkum podhu, long-lived cloud keys-a secrets-aa store panradhu.**
- **Ovvoru push-lum kaasu selavaagura evals-a run panradhu**, sambandhappatta changes-ku mattum illa.
- **Pin pannaadha third-party actions.**

## Practice pannunga

GitHub-oda Actions quickstart-aiyum deployment environments pathina page-aiyum follow pannunga.

1. Ungalukku irukkura oru repository-la, ovvoru pull request-lum lint-um tests-um run panra oru workflow serunga.
2. Main-ku merges-la, unga Docker image-a build panni commit hash-oda tag panni push panra oru job serunga.
3. Staging-um production-um environments create pannunga, production-ku unga sondha approval vennum-nu vainga, munna image-ku oru rollback practice pannunga.
4. Prompts illa retrieval code maarumbodhu mattum unga smoke eval run aaga paths filter-a serunga, onnu run aagiradhaiyum onnu skip aagiradhaiyum kaatta rendu pull requests open pannunga.

**Mudinjadhu-nu eppo sollalaam:** CI-aala block aana oru failing PR-a, production-ku munnaadi oru approval gate-a, neenga seidha oru rollback-a kaatta mudiyum.
