## Idhu enna

Unga laptop-la velai seyyura code aarambam dhaan, mudivu illa. **Project tooling**-na unga code-a suthi irukkura ellaame: adhu innoruthar adha run panna, safe-aa maatha, raathiri 2 manikku debug panna udhavudhu. Ovvoru pagudhiyum oru pudhu aal kekkappora oru kelvikku badhil solludhu:

| Pudhu aal kekkuradhu | Badhil solra file illana tool | Adhu illainna |
| --- | --- | --- |
| Endha Python, endha packages? | `pyproject.toml`, `uv.lock`, `.python-version` | "En machine-la velai seyyudhu" |
| Code enga irukku, adha eppadi import panradhu? | `.venv`-la install aana oru `src` layout | Ore oru folder-la irundhu mattum velai seyyura imports |
| En change edhaiyaavadhu udachudha? | pytest tests | Users kandupidikkura bugs |
| Indha code tidy-aa, obvious thappugal illaama irukkaa? | ruff | Ovvoru review-layum style sandaigal |
| API key enga pogum? | `.env` (ignored), `.env.example` (committed) | git-la leak aana keys |
| Production-la enna nadanduchu? | Ore thadavai configure panna `logging` | Oogam |
| Clean machine-layum innum velai seyyudhaa? | Ovvoru push-layum CI | "En laptop-la pass aachu" |
| Mudhalla enna type pannanum? | Exact commands irukkura README | Ungalukku oru WhatsApp message |

Idhula edhuvume glamorous illa. Aana illaadhappo ellaame gavanikkappadum, podhuvaa neenga handover panna adutha vaaram, client-oda engineer-aala.

Indha lesson-la Coimbatore-la oru textile exporter-kku neenga build panna invoice extractor-a, avanga engineer Karthik adha eduthukkumbodhu follow panrom. Idhu **uv**-a use pannudhu: Astral-oda oru fast tool, adhu environment-a create pannum, packages-a install pannum, lock file-a ezhudhum, Python-aiye install pannavum mudiyum. Saadhaarana `venv`, `pip`-um velai seyyum; ovvoru section-um vithyaasatha kaattum.

```flow
title: Clone-la irundhu nambagamaana change varai
dir: LR
Repository-a clone pannu -> Locked versions-a install pannu | uv sync
Locked versions-a install pannu -> Secrets-a ser | .env.example-a .env-aa copy pannu
Secrets-a ser -> Lint-um test-um | ruff-um pytest-um
Lint-um test-um -> Code-a maathu
Code-a maathu -> Push
Push -> CI oru clean machine-la checks-a marupadi ottum
```

## Idhu eppadi work aagudhu

### Layout

```text
invoice-extractor/
  pyproject.toml          # what the project is and needs
  uv.lock                 # exact versions of everything (commit it)
  .python-version         # the Python version the team uses
  .gitignore              # .venv, .env, __pycache__
  .env.example            # variable names, no real values
  README.md
  .github/workflows/ci.yml
  src/invoice_extractor/
      __init__.py
      cli.py              # entry point: configures logging, builds the client
      extract.py
      models.py
      llm.py              # the real model client
  tests/
      conftest.py         # shared fixtures, including a fake model client
      test_extract.py
      fixtures/sample_invoice.txt
```

`uv init --package invoice-extractor` idhula perumbaalaanadha ungalukkaaga create pannidum, oru `src` folder, oru `.python-version`, oru git repository udpada.

### pyproject.toml

Idho oru muzhusaana file, naanga uv 0.13.10, pytest 9.2.0, ruff 0.17.6 (28 November 2026 nilavarappadi miga pudhiya releases) vachu ottina maadhiriye:

```toml
[project]
name = "invoice-extractor"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = [
    "pydantic>=2.10",
]

[project.scripts]
invoice-extractor = "invoice_extractor.cli:main"

[dependency-groups]
dev = ["pytest>=9.0", "ruff>=0.17"]

[build-system]
requires = ["uv_build>=0.13.10,<0.14.0"]
build-backend = "uv_build"

[tool.pytest]
testpaths = ["tests"]
addopts = ["-ra", "--strict-markers"]

[tool.ruff.lint]
select = ["E", "F", "I", "B", "UP"]
```

Ovvoru pagudhiyum enna pannudhu:

- **`[project]`** package-kku per vaikkudhu, adhu run aaga enna thevainnu list pannudhu. Inga exact pins vendaam, ranges (`>=2.10`) use pannunga; exact versions-a lock file vachukkum.
- **`[project.scripts]`** oru command-a create pannudhu, adhanaala `uv run invoice-extractor` `cli.py`-la irukkura `main()`-a call pannum.
- **`[dependency-groups]`** developers-kku mattum thevaippadura tools-a vachukkudhu. `uv sync` default-aa `dev` group-a install pannum; `uv sync --no-dev` adha production image-la serkkaama vittudum.
- **`[build-system]`** `src/`-a install pannakkoodiya package-aa eppadi maathuradhunnu solludhu. Adhu illainna, uv andha folder-a scripts-oda oru loose collection-aa dhaan paarkkum, unga package-a install pannaadhu.
- **`[tool.pytest]`** pytest 9-la serththa native TOML table. Pazhaiya pytest-la, adhe keys-oda `[tool.pytest.ini_options]` use pannunga.

**Python-a pin panradhu.** `requires-python` neenga support panradhaa promise panra range. `.python-version` ellaarum, CI udpada, unmaiyaa use panra ore version; adhu illainna uv adha download pannidum. Python 3.15 9 October 2026-la vanduchu, aana mudhal naale maaranumnu avasiyam illa: `.python-version`-a ethuradhukku munnaadi, unga ganamaana libraries pudhu version-kku wheels publish panraangalaannu check pannunga, appuram CI adha prove pannattum.

### src layout, ellaarum marakkura install step

Code `src/`-la irukkumbodhu, neenga project folder-la nikkureenganguradhukkaaga mattum Python `invoice_extractor`-a import panna mudiyaadhu. Adhu dhaan point: oru user maadhiriye, oru install vazhiyaa dhaan tests unga package-a reach panna mudiyum. Package-la oru file missing-aa irundhaalo, `pyproject.toml`-la oru thappaana setting irundhaalo, adhu client-oda server-la illaama unga laptop-laye therinjudum.

Idhoda vilaivu kittathatta ovvoru beginner-aiyum thadukki vizha vaikkudhu. Package install aagalainna, tests aarambikkuradhukku munnaadiye fail aagum:

```text
E   ModuleNotFoundError: No module named 'invoice_extractor'
```

`uv sync` project-a `.venv`-la **editable** mode-la install pannudhu, adhanaala reinstall pannaamale unga edits effect-kku varum. Saadhaarana pip-la, idhaiye kaiyaala pannunga: oru venv create panni activate pannunga, appuram `pip install -e . --group dev` ottunga (`--group`-kku pip 25.1 illana adhukku appuram vandha version venum). `PYTHONPATH`-la `src`-a serthoo, `conftest.py`-la `sys.path` hacks pottoo indha error-a "fix" pannaadheenga; adhu layout thara paadhukaappaiye eduthudum.

### Lock files, --locked

`uv add httpx` ore step-la range-a `pyproject.toml`-la serthu `uv.lock`-a update pannudhu. Lock ovvoru package-oda exact version-aiyum file hash-aiyum record pannudhu, unga packages depend panra packages udpada. Neenga deploy panra endha application illana service-kkum adha commit pannunga. Mathavangalukkaaga publish panra oru library innum `pyproject.toml`-la loose ranges-a dhaan vachukkum, appo dhaan adhu adhoda users mela versions-a thinikkaadhu; aanaalum unga sondha CI-kkaaga adhoda lock-a commit panradhu useful dhaan.

CI, Dockerfiles, README-la `uv sync --locked` vachu install pannunga. Yaaraavadhu `pyproject.toml`-a kaiyaala edit pannittu `uv lock` otta marandhutta, adhu udane ninnudum:

```text
error: The lockfile at `uv.lock` needs to be updated, but `--locked` was provided.
  cause: Requirements for `invoice-extractor==0.1.0` differ; added: httpx>=0.28
```

Saadhaarana `uv sync` adhukku badhilaa sathamillaama lock-a marupadi ezhudhidum, appo neenga test panra versions neenga ship panra versions-la irundhu vilagi poyidum. Venumne, oru thadavaikku oru package-aa upgrade pannunga: `uv lock --upgrade-package pydantic`, tests ottunga, rendu files-aiyum commit pannunga. pip-la lock-kku samamaanadhu pip-tools maadhiri oru tool uruvaakkura fully pinned requirements file; `pip freeze`-um velai seyyum, aana appo install aagiyirukkura matha edhaiyum adhu kooda kalandhudum.

### ruff vachu lint, format

**Ruff** rendu velai seyyura ore fast tool. `ruff check` oru **linter**: bugs aaga vaaippulladhaiyum bad patterns-aiyum kandupidikkum. `ruff format` oru **formatter**: spacing-aiyum line breaks-aiyum ore house style-la marupadi ezhudhum, adhanaala reviews commas pathi illaama logic pathi irukkum.

```text
uv run ruff check --fix    # find problems, fix the safe ones
uv run ruff format         # rewrite layout
```

ruff 0.16-la irundhu, default set perusu: pala groups-la irundhu 400-kkum mela rules. Oru `select` line andha default-a neekkittu, neenga peru solra groups-a mattum exact-aa vaikkum. Mela irukkuradhu adha vida chinna, predictable set tharudhu: `E`, `F` (pycodestyle, Pyflakes), `I` (sorted imports), `B` (bugbear: mutable default argument maadhiri podhuvaana bug patterns), `UP` (unga Python version-kkaana pudhiya, simple-aana syntax). Rule groups-a oru thadavaikku onnaa serunga; oru pazhaiya codebase-la ellaathaiyum ore thadavai on panna noothukkanakkaana warnings varum, team linter-aiye off pannidum.

### Secrets, settings

Code secrets-a environment variables-la irundhu mattum dhaan padikkum, vera engeyum illa:

```python
client = ModelClient(api_key=os.environ["MODEL_API_KEY"])
```

Variable illainna, idhu start-up-laye `KeyError: 'MODEL_API_KEY'` raise pannum, mudhal invoice-la vara kuzhappamaana failure-a vida idhu evvalavo nalladhu. Local-aa, values-a oru `.env` file-la vachu `uv run --env-file .env` vachu load pannunga. Unmaiyaana values illaama perungala mattum list panra oru `.env.example`-a commit pannunga:

```text
MODEL_API_KEY=
LOG_LEVEL=INFO
```

Unga `.gitignore`-a check pannunga: `uv init` ezhudhuradhu `.venv`-a cover pannum, aana `.env`-a illa, adhanaala neengale adha serthu `git check-ignore .env` vachu confirm pannunga. Eppavaavadhu oru unmaiyaana key oru commit-kkulla poyiduchunna, adutha commit-la file-a delete panradhu udhavaadhu, yenna adhu git history-la irundhudum. Mudhalla key-a revoke panni rotate pannunga, appuram clean up pannunga.

### Logging

Logging-a **ore thadavai**, entry point-la configure pannunga, vera engeyum illa:

```python
# cli.py
import logging
import os


def main() -> None:
    logging.basicConfig(
        level=os.environ.get("LOG_LEVEL", "INFO").upper(),
        format="%(asctime)s %(levelname)s %(name)s %(message)s",
    )
```

Matha ovvoru module-um than perula oru logger-a kettu vaanguradhu mattum dhaan, oru pudhu aal act pannakkoodiya facts-a log pannum:

```python
# extract.py
log = logging.getLogger(__name__)

log.warning(
    "invoice=%s field=total model_value=%r error=%s",
    data.get("id"),
    data["total"],
    err,
)
```

Mela irukkura maadhiri, oru f-string build panradhukku badhilaa values-a arguments-aa pass pannunga; appo logging module unmaiyaa emit panra messages-a mattum dhaan format pannum. Unga log platform JSON fields-la search panna mudinjaa, format-a oru line-kku oru JSON object-aa maathunga; ids, fields, timings-a log panra pazhakkam adhe dhaan. Oru command-oda unmaiyaana output-kku, adhaavadhu extract panna JSON maadhiri, `print` innum OK dhaan; program enna pannudhungura messages-kku adhu thappu.

| Level | Edhukku use panradhu | Production-la |
| --- | --- | --- |
| DEBUG | Developers-kkaana detail: prompts, raw replies | Off |
| INFO | Saadhaarana events: process aana oru file, adhu edutha nerathoda | On |
| WARNING | Vithyaasamaa irundhaalum handle aanadhu: success aana oru retry, skip panna oru bad input | On |
| ERROR | Edho fail aayiduchu, oru aal paakkanum | On, alerts-um |

API keys, passwords, muzhu documents, customer phone numbers illana PAN numbers maadhiri personal data-va eppavume log pannaadheenga. Adhukku badhilaa ids, sizes, timings-a log pannunga.

### Tests, oru fake model client

pytest, fixtures, parametrised tests, mocking ellaam "Writing tests with pytest" lesson-la (B3) irukku. Project structure-kku mukkiyam edhu enga irukkungradhu dhaan. Shared fixtures `tests/conftest.py`-la pogum, adha pytest thaanaave load pannum. Model-a call panra code-kku, ellaathaiyum vida clean-aana design client-a ulla pass panradhu dhaan, appo oru test adhukku oru fake-a kudukkalaam:

```python
# tests/conftest.py
import json
from pathlib import Path

import pytest

FIXTURES = Path(__file__).parent / "fixtures"


class FakeModelClient:
    """Returns a fixed reply and records each prompt. No network, no cost."""

    def __init__(self, reply: dict):
        self.reply = json.dumps(reply)
        self.prompts: list[str] = []

    def complete(self, prompt: str) -> str:
        self.prompts.append(prompt)
        return self.reply


@pytest.fixture
def sample_invoice() -> str:
    return (FIXTURES / "sample_invoice.txt").read_text(encoding="utf-8")


@pytest.fixture
def fake_client() -> FakeModelClient:
    return FakeModelClient(
        {
            "id": "INV-0001",
            "gstin": "33ABCDE1234F1Z5",
            "total": "1500.00",
            "items": [
                {"description": "Cotton yarn", "amount": "1000.00"},
                {"description": "Dyeing", "amount": "500.00"},
            ],
        }
    )
```

Indha unit tests unga sondha logic-a check pannum, ovvoru push-layum oru second-kkum romba kuraivaana nerathula odidum. Unmaiyaana model-oda answers-a judge panradhu vera velai, adha fixed-aana, label panna unmaiyaana examples set mela odura oru evaluation run seyyum; "Test sets and evals" lesson (P1) 30-la irundhu 100 cases vachu aarambikkalaamnu suggest pannudhu.

### Ovvoru push-layum CI

CI (continuous integration) ovvoru push-kkum pull request-kkum adhe checks-a oru clean machine-la ottum, adhanaala "en laptop-la pass aachu"-ngradhu inime oru argument illa. Oru muzhusaana GitHub Actions workflow:

```yaml
# .github/workflows/ci.yml
name: ci
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: astral-sh/setup-uv@v10.4.0
      - run: uv sync --locked
      - run: uv run ruff check
      - run: uv run ruff format --check
      - run: uv run pytest
```

uv `.python-version`-a padichu runner-la andha Python-a install pannum. Oru gotcha: `setup-uv`-kku adhoda pudhu releases-kku `@v10` maadhiri short tag illa, adhanaala muzhu version-a ezhudhunga (illana, innum strict-aa, commit hash-a). Branch protection-a on pannunga, appo CI red-aa irukkumbodhu oru pull request merge aaga mudiyaadhu.

### README

Nalla README oru pudhu aala ungakitta edhuvume kekkaama clone-la irundhu passing tests varai poga vidum:

```text
git clone <repository-url> && cd invoice-extractor
uv sync --locked
cp .env.example .env          # then put your own key in .env
uv run pytest
uv run --env-file .env invoice-extractor tests/fixtures/sample_invoice.txt
```

Adha ezhudhunga, appuram `/tmp`-la oru fresh clone-la neengale adha follow pannunga. Perumbaalaana READMEs rendaavadhu line-laye udanjudum.

## Oru worked example

Coimbatore exporter-kkaaga neenga invoice extractor-a build panneenga. Adutha maasam Karthik neenga illaamale adha run panni maintain pannanum.

**Mudhal naal.** Avar repository-a clone panni README-a follow panraaru. `uv sync --locked` neenga test panna adhe exact versions-a install pannudhu, `uv run pytest` 12 passed-nu report pannudhu. Andha pannirandula rendu tests:

```python
import pytest
from pydantic import ValidationError

from invoice_extractor.extract import parse_amount, parse_invoice
from invoice_extractor.models import Invoice


def test_total_matches_line_items(sample_invoice, fake_client):
    inv = parse_invoice(sample_invoice, client=fake_client)
    assert inv.total == sum(i.amount for i in inv.items)
    assert "Cotton yarn" in fake_client.prompts[0]


def test_rejects_gstin_with_wrong_length():
    with pytest.raises(ValidationError):
        Invoice(gstin="33ABCDE1234", total=100, items=[])
```

Mudhal test `parse_invoice`-kku `conftest.py`-la irukkura fake client-a kudukkudhu, adhanaala network call illaamale parsing logic-aiyum, invoice text prompt-kku poi serndhuchaannum check pannudhu. Oru GSTIN eppavume 15 characters, adhanaala `Invoice` model andha 11-character GSTIN-a reject pannudhu.

- **System Python-la install panradhu.** Unga laptop-la velai seyyum, vera engeyum seyyaadhu. Ovvoru project-kkum adhukkunnu oru `.venv` venum.

- **Ovvoru module-layum, illana library code-kkulla `basicConfig`-a call panradhu.** Logging-a ore thadavai, entry point-la configure pannunga.
- **Secrets illana personal data-va log panradhu.** Ids, sizes, timings-a log pannunga, keys, muzhu documents, phone numbers-a eppavume illa.
- **Production-la DEBUG-a on-laye viduradhu.** Adhu disks-a nirappum, paid log platforms-la kaasu selavaagum, adikkadi customer data irukkura raw prompts-a print pannum.
- **Unmaiyaana model-a call panra unit tests.** Avai slow, kaasu selavaagum, random-aa fail aagum. Oru fake client-a pass pannunga; quality-a oru thani evaluation-la measure pannunga.
