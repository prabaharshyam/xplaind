## Idhu enna

Oru deployment-a operate panna paadhugaappaa aakkura moonu palakkangal:

- **Thani environments.** Build panna development, production maadhiri settings-oda test panna staging, real users-ku production. Ovvonnukkum thani database, keys, settings.
- **Secrets management.** Passwords, API keys, tokens secret store-la irukkum, run time-la app-ku varum, code, images, logs, chat-la eppavum varaadhu.
- **Infrastructure as code (IaC).** Servers, databases, networks, permissions files-la describe aagum, code maadhiri review aagum, console-la click panni serkkaama Terraform maadhiri tool-aal apply aagum.

```flow
Terraform files, reviewed -> Plan -> Apply
Apply -> Development | own database, own model key, 1 instance
Apply -> Staging | masked data, own model key, 1 instance
Apply -> Production | real data, own model key with a spend limit, 3 instances
The same container image -> Development
The same container image -> Staging
The same container image -> Production
```

Ovvoru environment-um adhoda settings-a environment-la irundhum, secrets-a vault-la irundhum edukkum.

Indha lesson-la Chandigarh-la oru lending company, avasaramaa senja pilot-a production-ku ready panradhu-a follow pannuvom.

## Idhu eppadi work aagudhu

**Environment-la config.** Ore image ellaa idathulayum odum; settings mattum maarum. Avatrai environment variables-la (`DATABASE_URL`, `MODEL_NAME`, `LOG_LEVEL`) irundhu padinga, start-up-la oru settings model-la validate pannunga. Appo oru value illainaa, 2 am-la mudhal real request-la illa, boot aagum podhae sathama fail aagum.

**Environments-kku idaiyila enna maarum.** Thani databases (staging-a production data-vaa point pannaadhinga, masked-aa irundha thavira), thani spend limits-oda thani model API keys, production-ku veliya kammiyaana instance counts, production-ku strict access.

**Secret stores.** Cloud secret managers (AWS Secrets Manager, Azure Key Vault, Google Secret Manager) illa HashiCorp Vault maadhiri tools secrets-a vechukkum, ovvonnai yaar padikkalaam-nu control pannum, ovvoru access-aiyum log pannum. App adha start-up-la service identity vazhiyaa padikkum. Schedule-padi rotate pannunga, yaaraavadhu velaiya vittu poonaalum, leak sandhegam vandhaalum udane rotate pannunga. Keys repository-ku pogaama pidikka CI-la secret scanner odunga.

**Terraform.** HCL-la resources-a describe panra files ezhudhuveenga:

```hcl
resource "azurerm_postgresql_flexible_server" "db" {
  name                          = "claims-${var.env}-db"
  resource_group_name           = azurerm_resource_group.main.name
  location                      = "centralindia"
  version                       = "16"
  sku_name                      = var.env == "prod" ? "GP_Standard_D2s_v3" : "B_Standard_B1ms"
  public_network_access_enabled = false
}
```

`terraform plan` enna maarum-nu exact-aa kaattum; reviewer plan-a pull request-la padikkaar; `terraform apply` adha nadathum. Terraform edha manage pannudhu-nu oru **state** file-la record pannum, adha remote-aa (locking-oda storage bucket) store pannanum, laptop-la eppavum illa, adhula sensitive values irukkalaam-nu paadhukaakkanum. Ovvoru environment-kum oru variable-oda ore set files staging-um production-um shape-la onna irukka vaikkum.

**Ovvoru vagai value-um enga irukkanum:**

| Value | Example | Enga irukkum |
| --- | --- | --- |
| Secret illaadha setting | `LOG_LEVEL`, `MODEL_NAME` | Environment variables, ovvoru environment-kum set pannunga |
| Secret | Database password, model API key | Secret store, app-oda identity vazhiyaa padikkanum |
| Infrastructure | Database size, network rules | Git-la irukkura Terraform files |
| Infrastructure state | Terraform edhellaam manage pannudhu | Remote, locked, access-controlled storage |
| Test data | Masked customer records | Staging database-la mattum |

**Review loop.** Infrastructure maatram Terraform files-a edit panra pull request-aa aarambikkum. CI `terraform plan` odi, "1 to add, 0 to change, 0 to destroy" maadhiri output-a post pannum. Reviewer code mattum illa, plan-aiyum padikkanum, yenna plan thaan unmaiyila enna nadakkum-nu kaattum. Approve aana aprom, thani identity irukkura pipeline `terraform apply` odum. Routine maatrangalukku yaarukkum production console access thevai illa, adhanaala production-la thappu panna mudiyura aalgal ennikkai kurayum.

**Code-la validated settings.** `pydantic-settings` environment variables-a padichi fast-aa fail aagum:

```python
from typing import Literal
from pydantic import Field, SecretStr
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", extra="ignore")
    env: Literal["dev", "staging", "prod"]
    database_url: SecretStr
    model_api_key: SecretStr
    model_name: str = "claude-sonnet-5-5"            # check the docs for current names
    daily_budget_inr: int = Field(gt=0)
    log_level: Literal["DEBUG", "INFO", "WARNING"] = "INFO"

settings = Settings()        # raises a clear error listing every missing or invalid value
```

`SecretStr` secrets-a logs-layum error messages-layum varaama paathukum: print pannaa `**********` nu kaattum.

**Locking-oda remote state.** Ovvoru Terraform project-um oru backend-oda aarambikkum, appo state share aagum, rendu perala ore neram apply panna mudiyaadhu:

```hcl
terraform {
  required_version = ">= 1.6"
  backend "azurerm" {
    resource_group_name  = "tfstate-rg"
    storage_account_name = "claimstfstate"
    container_name       = "state"
    key                  = "claims/staging.tfstate"
    use_azuread_auth     = true
  }
  required_providers {
    azurerm = { source = "hashicorp/azurerm", version = "~> 4.0" }
  }
}
```

Ovvoru environment-kum oru state file vainga (vera `key`), `env/staging.tfvars`, `env/prod.tfvars` maadhiri thani variable files-um vainga.

**Terraform-la store pannaama secrets.** Terraform vault-a create panni, app-oda identity-ku access kudukkattum; secret values-a vault vazhiyaave podunga, appo adhu code-layum state-layum varaadhu:

```hcl
resource "azurerm_key_vault" "kv" {
  name                      = "claims-${var.env}-kv"
  location                  = "centralindia"
  resource_group_name       = azurerm_resource_group.main.name
  tenant_id                 = data.azurerm_client_config.current.tenant_id
  sku_name                  = "standard"
  enable_rbac_authorization = true
}

resource "azurerm_role_assignment" "app_reads_secrets" {
  scope                = azurerm_key_vault.kv.id
  role_definition_name = "Key Vault Secrets User"
  principal_id         = azurerm_container_app.api.identity[0].principal_id
}
```

**Schedule-la drift-a kandupidinga.** Sila samayam makkal console-la maathuvaanga. Oru raathiri job adha kandupidikkum:

```bash
terraform plan -var-file=env/prod.tfvars -detailed-exitcode -lock=false > plan.txt
case $? in
  0) echo "no drift" ;;
  2) echo "DRIFT: production differs from code"; exit 1 ;;   # alert the team
  *) echo "plan failed"; exit 1 ;;
esac
```

**Code-a scan pannunga.** `tflint`, Checkov maadhiri tools public storage, open firewall rules, missing encryption-a pull requests-laye, edhuvum apply aagurathukku munnaadi, flag pannum.

**Browser-la try pannunga.** Start-up-la check panna settings vegamaavum clear-aavum fail aagum. Oru value-a remove panni run pannunga.

```python
from pydantic import BaseModel, SecretStr, ValidationError

class Settings(BaseModel):
    env: str
    database_url: SecretStr
    daily_budget_inr: int

environment = {"env": "staging", "database_url": "postgresql://app:secret@db/app", "daily_budget_inr": "500"}
try:
    s = Settings.model_validate(environment)
    print(s.env, s.daily_budget_inr, s.database_url)     # the secret prints as stars
except ValidationError as err:
    print("start-up stopped:", [e["loc"][0] for e in err.errors()])
```

## Oru worked example

Chandigarh lending company-oda pilot avasaramaa build aachu. Testing-kum real data-kum ore database, maadhangalukku munnaadi commit aana `.env` file-la model key, console-la kaiyaala create panna resources.

Production-ku munnaadi neenga:

1. Leak aana key-a rotate panni, CI-la secret scanner serkkureenga. Adhu history-la innum rendu pazhaya keys-a kandupidikkudhu; rendum rotate aagudhu.
2. Network, database, storage, container app, Key Vault-kku Terraform ezhudhureenga, `env` oru variable-aa. `terraform apply` oru clean staging-a build pannum; review panna plan production-a build pannum.
3. Ellaa secrets-aiyum Key Vault-ku maathureenga; app adha managed identity vazhiyaa padikkudhu. Staging-kum production-kum thani monthly limits-oda thani model keys.
4. Staging-la kadandha maadha applications-oda masked copies load aagudhu: names, PAN, phone numbers maathappattirukku.

Client-oda auditor "production database password-a yaar padikkalaam?"-nu kettaa, Key Vault access policy-yum adhoda access log-aiyum vechu badhil solreenga. Region outage drill nadakkum podhu, team ore Terraform-la irundhu 40 nimidathula vera region-la staging-a thirumba build pannudhu.

| Auditor-oda kelvi | Munnaadi badhil | Aprom badhil |
| --- | --- | --- |
| Secrets enga store aagudhu? | ".env file-la" | Key Vault, access log-oda |
| Production-a yaar maathalaam? | Console vazhiyaa pala per | Review-ku aprom, deployment pipeline |
| System-a thirumba build panna mudiyumaa? | Therila | Mudiyum, Terraform-la irundhu, 40 nimidathula |
| Test data real-aa? | Aam | Illa, masked copies |

## Podhuvaa panra thappugal

- **Production data-vukku ethiraa test panradhu.** Oru mosamaana script-ae real customers-a paadhikkum. Pirichu vainga, test data-va mask pannunga.
- **Secrets Git-la, konjam neram irundhaalum.** History adha vechukkum. Ethaavadhu oru thadavai commit aana key-yum rotate pannunga.
- **Laptop-la Terraform state.** Adhu kaanaama poidum illa out of date aagidum, secrets-um irukkalaam. Remote, locked state use pannunga.
- **Terraform-oda sernthu console changes.** Adutha apply adha revert pannum illa conflict aagum. Code-a maathunga.
- **Environment-ku environment vera shape.** Production-la irukkura private network staging-la illaina, staging tests romba onnum nirubikkaadhu.
- **Terraform files-la ezhudhina secret values,** adhu state-layum vandhidum.
- **Ellaa environments-kum ore state file,** adhanaala staging maatram production-a thodalaam.
- **Yaarum record pannaadha console maatrangal,** maadhangal kazhichu drift-aa kandupidikkappadum.

## Terraform thevaiyilladha idangal

- **Infrastructure-a unga-ku manage panra platform-la** oru sinna service.
- **Adutha maadham delete panna pora** short-lived prototype.
- **Thani infrastructure team-um tool-um irukkura client** (Bicep, CloudFormation, Pulumi maadhiri): avanga tool-a use pannunga.

Environment variables, validated settings, secret store ithellaam romba sinna project-la kooda irukka vendiyadhu.

## Demo-la irundhu production-ku

- **Ovvoru environment-kum remote, locked state vainga,** access restricted-aa.
- **Pull requests-la plan pannunga,** review-ku aprom CI-la irundhu mattum apply pannunga.
- **Production-la raathiri drift checks odunga.**
- **CI-la Terraform-a scan pannunga,** risky settings-ku.
- **Start-up-la settings-a validate pannunga,** secrets `SecretStr`-aa, app-oda identity vazhiyaa padikkanum.

## Practice pannunga

Neenga choose panna cloud-ku Terraform-oda getting-started tutorials-a follow panni, config pathi Twelve-Factor page-a padinga.

1. `env = "staging"`-ku oru storage bucket-um oru sinna managed database-um create panra Terraform ezhudhunga, database publicly reachable-aa irukka koodaadhu. Apply pannunga, plan-a padinga, apram destroy pannunga.
2. Ungaloda app-oda settings-a environment variables-la irundhu padikkira validated settings model-ku maathunga, ethaavadhu illainaa start-up clear-aa fail aagura maadhiri pannunga.
3. Oru secret-a ungaloda cloud-oda secret manager-la store panni, app adha identity vazhiyaa padikka vainga.
4. Cloud console-la oru setting-a kaiyaala maathunga, apram drift check odi, adhu difference-a report pannudhunu confirm pannunga.

**Mudinjadhu-nu eppo sollalaam:** Ungaloda staging environment-a code-la irundhu thirumba build panna mudiyum, ungaloda repository-la entha idathulayum secret illa-nu kaattamudiyum.
