## Idhu enna

**Decision tree** features pathi oru kelvi varisaiya kettu predict pannum: "EMI-to-income ratio 0.45-ku mela irukka? Irundha, applicant kadandha oru varushathula oru payment miss pannaangala?" Ovvoru badhilum oru branch-la kootitu poi, oru leaf-la prediction tharum. Trees indha kelvigala data-la irundhu thaan kathukkum.

Thaniya oru tree easy-aa overfit aagum. Rendu ensemble methods idha sari pannum:

- **Random forest**: neraya trees, ovvonnum rows, features-oda random sample-la train aagum, predictions-oda average edukkuvaanga. Nambikkaiyaanadhu, udaikkarathu kashtam.
- **Gradient boosting**: trees onnu pinnaadi onnu build aagum, ovvoru pudhu tree-yum ippo varaikkum irukkura ensemble-oda errors-a sari pannum. XGBoost, LightGBM, CatBoost popular implementations. Tabular data-la usually romba accurate.

```flow
EMI / income above 0.45? -[yes]-> Missed a payment in the last 12 months?
EMI / income above 0.45? -[no]-> Credit history under 2 years?
Missed a payment in the last 12 months? -[yes]-> Risk 0.41
Missed a payment in the last 12 months? -[no]-> Risk 0.18
Credit history under 2 years? -[yes]-> Risk 0.12
Credit history under 2 years? -[no]-> Risk 0.03
```

Boosting idhu maadhiri neraya trees add pannum: tree 1, apram tree 2-oda chinna correction, appadiye tree 640 varaikkum.

Indha lesson Gurugram-la irukkura oru digital lender-a follow pannum, avanga personal loans-la 90-day defaults predict panraanga.

## Idhu eppadi work aagudhu

**Trees business data-ku yen set aagum.** Mixed feature types-a handle pannum, feature scaling thevai illa, non-linear effects-um interactions-um thaanaagavae pudichikkum ("self-employed applicants-ku high EMI ratio innum mukkiyam"), missing values-a samaalikkum (perumbaalaana boosting libraries natively handle pannum).

**Boosting-oda mukkiya settings.**

- *Trees ennikkai*-yum *learning rate*-um: neraya chinna steps (low learning rate, adhigam trees) usually nallaa generalise aagum; validation error improve aagala-na trees add panradha niruthura early stopping-a validation set-la use pannunga.
- *Tree depth*: shallow trees (depth 3 to 8) complexity-a kammi pannum.
- Ovvoru tree-kum rows-um columns-um *subsampling*: randomness serthu overfitting-a kuraikkum.
- *Oru leaf-ku minimum samples*-um regularisation terms-um: model chinna groups-a fit pannaama thadukkum.

**Categorical features.** Konjam categories-ku one-hot encoding work aagum; neraya irundha (city, product) leakage varaama careful-aa target encoding use pannunga, illa categories-a nerae handle panra library use pannunga.

**Predictions-a explain panradhu.** Feature importance model overall-aa edha nambichu-nu kaattum, aana correlated features irundha mislead pannalaam. SHAP values individual predictions-a explain pannum: indha applicant-oda risk-a ovvoru feature evvalavu mela illa keezha thallichu. Regulated decisions-ku perumbaalum idhu maadhiri explanations thevai.

**Limits.** Trees paartha target values-a thaandi extrapolate panna mudiyaadhu, raw images, audio, text-ku sariyaana tool-um illa; adhula neural networks jeikkum.

**Boosting-a tune panra order:**

| Setting | Ethula start pannalaam | Effect |
| --- | --- | --- |
| Learning rate | 0.03 to 0.1 | Kammi-na mella aagum, aana usually nallaa generalise aagum |
| Trees ennikkai | Neraya, early stopping-oda | Early stopping sariyaana ennikkai-a neengalae pick pannum |
| Max depth | 4 to 8 | Deeper trees adhigam interactions pudikkum, adhigam overfit aagum |
| Row, column subsampling | 0.7 to 0.9 | Randomness overfitting-a kuraikkum |
| Oru leaf-ku minimum samples | 20 to 100 | Model chinna groups-a fit pannaama thadukkum |

Time vachu split panna validation set-la tune pannunga, apram oru later test period-la oru thadava confirm pannunga. Training-kum validation scores-kum gap valarndhutte irundha, adhu thaan overfitting-oda romba clear-aana sign.

**Oru split-la moonu models, code-la.**

```python
import numpy as np
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import RandomForestClassifier, HistGradientBoostingClassifier
from sklearn.metrics import roc_auc_score

X, y = make_classification(n_samples=12_000, n_features=20, n_informative=10, flip_y=0.03, random_state=4)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.25, random_state=4)

models = {
    "single tree": DecisionTreeClassifier(max_depth=6, random_state=4),
    "random forest": RandomForestClassifier(n_estimators=300, min_samples_leaf=5, n_jobs=-1, random_state=4),
    "boosting": HistGradientBoostingClassifier(learning_rate=0.05, max_iter=2000, max_depth=6,
                                               early_stopping=True, validation_fraction=0.15,
                                               n_iter_no_change=30, random_state=4),
}
for name, m in models.items():
    m.fit(X_tr, y_tr)
    tr = roc_auc_score(y_tr, m.predict_proba(X_tr)[:, 1])
    te = roc_auc_score(y_te, m.predict_proba(X_te)[:, 1])
    print(f"{name:<14} train {tr:.3f}  test {te:.3f}")
print("trees used by boosting:", models["boosting"].n_iter_)
```

Early stopping 2,000 varaikkum-la irundhu trees ennikkai-a choose pannudhu. Train-kum test scores-kum irukkura gap overfitting-a oru paarvaila kaattum.

**Real use-a kaattura importance.**

```python
from sklearn.inspection import permutation_importance

r = permutation_importance(models["boosting"], X_te, y_te, scoring="roc_auc", n_repeats=5, random_state=4)
top = np.argsort(-r.importances_mean)[:5]
for i in top:
    print(f"feature {i}: drop in AUC {r.importances_mean[i]:.3f} ± {r.importances_std[i]:.3f}")
```

Correlated features importance-a pirichukkum, adhanaala oru feature, adhoda twin signal-a edukkura-naala mattum, importance illaadha maadhiri theriyalaam. Rendaiyum serthu drop panni check pannunga.

**Common sense-oda match aagura constraints.** EMI-to-income ratio ethunaalum risk kuraiya koodaadhu-nu irundha, adha model-kitta sollunga. `HistGradientBoostingClassifier(monotonic_cst=[...])` ovvoru feature-kum 1, -1 illa 0 edukkum; idhu model-a credit committees-kitta defend panna easy-aakkum, pudhu data-layum neraya time robust-aa irukkum.

**Native categorical support.** pandas categorical columns-oda `categorical_features="from_dtype"` kudunga, boosting model one-hot encoding illaama categories-la nerae split pannum. LightGBM, XGBoost, CatBoost-um idhae tharum, adhigam tuning options-oda; neraya categories irukkura data-la CatBoost-oda defaults strong-nu per.

**Konjam, careful-aa tune pannunga.** Learning rate, depth, oru leaf-ku minimum samples-la oru chinna search, time-based validation set-la score pannina, perumbaalum gain-a pidichidum. Periya searches validation set-ye overfit pannidum.

## Oru worked example

Gurugram digital lender 120 features-la irundhu personal loans-oda 90-day default predict panraanga: bureau data, bank-statement summaries, application details, app usage.

- Logistic regression baseline: ROC AUC 0.71.
- Random forest: 0.75.
- Early stopping-oda LightGBM, depth 6, learning rate 0.03, row, column subsampling: 0.79, training-a vida later quarter-la irundha loans-la test pannadhu.

**Model-la irundhu rejection letter varaikkum.** Lending-la, reject aana applicant-ku mukkiya reasons sollanum; RBI-oda fair practices rules lenders-a adha ezhuthula kudukka solludhu. Ovvoru rejection-kum, team risk-a mela thalluradha SHAP values periya moonu features-a eduthu, ovvonnayum compliance team-oda agree panna plain sentence-ku map pannum: "Kadandha aaru maadhathula pala EMI payments bounce aachu", "Ungaloda ippo irukkura EMIs ungal income-la adhigam share", "Ungal credit history rendu varushathukku kammi". Engineers indha sentences-a appo appo ezhudha maattaanga; adhu review panna list-la irundhu varum, adhanaala wording consistent-aa, accurate-aa, fair-aa irukkum.
