## Idhu enna

Ovvoru AI product idea-vum aarambathulaye rendu kelvigalai sandhikkum. Idha thappaa pannaa selavu adhigam:

1. **Feasibility.** Namma real data-la, ethukkakkoodiya cost-layum speed-layum AI indha velaiya podhumaana alavu nallaa pannumaa?
2. **Build vs buy.** Oru ready product-a vaanganumaa, erkanave use panra platform-la oru AI feature-a configure pannanumaa, illa sondhamaa build pannanumaa?

Teams perumbaalum mudhal kelviya skip pannittu, rendaavadhai pathi maasakkanakkaa vivaadhippaanga. Idha vida nalla varisai: sila naalla feasibility-a test pannunga, work aaga mudiyaadha options-a thallunga, appuram micham irukkuradhai cost, risk vachu oppidunga.

```flow
title: Idea-la irundhu delivery mudivu varai
Idea -> 20-50 real examples-la prototype | maasangal illa, naatkal
20-50 real examples-la prototype -[romba dhooram]-> Innum feasible illa | context illa data serunga, illanna kaathirunga
20-50 real examples-la prototype -[nerukkam]-> Options-a screen pannunga
Options-a screen pannunga -[fit illa compliance-la fail]-> Thallappattadhu
Options-a screen pannunga -[pass]-> Rendu varusha cost-a oppidunga
Rendu varusha cost-a oppidunga -> Thernthedu, review date vainga
Thernthedu, review date vainga -> Go-live-kku munnaadi periya evaluation
```

Indha lesson, Hyderabad-la oru hospital chain-la product manager-aa irukkura Sana-va follow pannudhu. AI discharge summaries-a draft pannumaa-nnu avanga test panni, appuram adha eppadi deliver panradhu-nnu numbers vachu mudivu panraanga. Kadaisiyila oru quick feasibility test ottavum, mudivoda rendu pakkathukkum cost podavum, oru buy, configure illa build therva niyaayappaduthavum ungalaala mudiyum.

## Idhu eppadi work aagudhu

### Step 1: sila naalla prototype pannunga

20 mudhal 50 **real** examples edunga; personal data irundhaa mask pannunga. Oru capable model-odayum oru simple prompt-odayum andha velaiya try pannunga, kaiyaalayo oru notebook-layo. Idhu dhaan **proof of concept**: chinnadhu, vegamaanadhu, nermaiyaanadhu. Suthamaana cases mattum illaama, mosamaana scans, kalandha mozhigal, neelamaana records maadhiri kashtamaana cases-aiyum use pannunga.

Appuram outputs-a oru **domain expert** judge pannattum, prompt ezhudhina engineers illa. Onna build pannavanga page-la enna irukku-nnu paakka maattaanga, thaanga enna ninaichaangalo adha dhaan paappaanga. Ovvoru output-aiyum oru simple scale-la rate pannunga:

| Rating | Artham |
| --- | --- |
| Usable | Sari, adhigapatcham chinna edits podhum |
| Needs work | Idea sari, periya edits venum |
| Unsafe illa wrong | Use pannaa harm varum |

- Results romba dhoorathula irundhaa, andha velai innum feasible illaama irukkalaam. Adhukku koodudhal context, nalla data, illa pinnaadi varra oru nalla model thevaippadalaam.
- Results nerukkamaa irundhaa, feasibility irukka vaaippu adhigam. Ippo nija velai reliability, integration, safety, evaluation dhaan; model idha pannave mudiyumaa-ngaradhu illa.

Indha 20 mudhal 50 examples-aiyum avattroda ratings-aiyum vachukkonga. Adhu dhaan unga mudhal evaluation set; ovvoru vendor-aiyum, pinnaadi varra ovvoru model-aiyum idhe set-la dhaan ottuveenga.

### Oru chinna sample enna sollum, enna sollaadhu

Oru prototype "thodaralaamaa?"-ngara kelvikku badhil sollum, "launch panradhu safe-aa?"-ngaradhukku illa. Chinna samples aridhaana failures-a maraichudum.

40 outputs-la 2 unsafe-nu vachukkonga. Adhu 5% maadhiri theriyum. Aanaa 40 examples mattum irundhaa, unmaiyaana unsafe rate 1%-kku keezha irundhu sumaar 17% varai edhuvaa venumnaalum irukkalaam (oru exact 95% confidence interval). 300-la 0 unsafe-na kooda, unmaiyaana rate perumbaalum sumaar 1.2%-kku keezha irukku-nnu mattum dhaan adhu sollum.

Adhanaala rule idhu dhaan: feasibility-a oru chinna sample vachu mudivu pannunga, aanaa go-live-a idha vida romba periya oru evaluation vachu mudivu pannunga, adhula ellaathaiyum vida serious-aana failure type-a thaniyaa count pannunga.

### Step 2: cost, speed-a estimate pannunga

Prototype-la irundhu, ovvoru request-um ethana tokens use pannudhu, ovvoru badhilukkum evvalavu neram aagudhu-nnu note pannunga. Appuram volume-aala perukkunga. Udhaaranamaa, vilakkathukkaaga karpanaiyaa vacha prices-oda:

- Oru request 12,000 input tokens-um 1,000 output tokens-um use pannudhu-nnu vachukkonga.
- Model-oda vilai oru million input tokens-kku ₹250, oru million output tokens-kku ₹1,000-nu vachukkonga.
- Appo oru request-oda cost 12,000 × ₹250 ÷ 1,000,000 + 1,000 × ₹1,000 ÷ 1,000,000 = ₹3 + ₹1 = ₹4.

Nija prices adikkadi maarum. Avattrai provider-oda pricing page-la irundhu eduthu, check panna thedhiya pakkathulaye ezhudhunga. Retries-kkum evaluation runs-kkum oru margin serunga, udhaaranamaa 25%.

User-oda porumaikku speed porundhudhaa-nnum paarunga. Oru doctor oru draft-kku pathu seconds kaathiruppaaru, rendu nimisham illa.

### Step 3: moonu options-a therinjukkonga

| Option | Enna adhu | Balam | Balaveenam |
| --- | --- | --- | --- |
| **Product vaangurathu** | Andha use case-kkaana oru ready tool, udhaaranamaa oru document-processing service | Ellaathaiyum vida vegam; updates-aiyum model maatrangalaiyum vendor paathuppaanga | Customisation kuraivu; vendor-oda roadmap; unga data vendor-kitta pogum |
| **Platform-a configure panrathu** | Erkanave use panra software-kkulla oru AI feature, udhaaranamaa unga CRM, help desk illa hospital system | Vegam; irukkura data-vaiyum permissions-aiyum use pannum | Flexibility kuraivu; andha platform-oda kattuppattirukkum |
| **Build** | Oru model API illa open-weight model mela unga sondha system | Fit, safety checks, data mela ellaathaiyum vida adhiga control | Engineers, evaluation, thodarndha maintenance venum |

"Build"-kkulla innoru mudivu olinjirukku; regulated Indian sectors-la perumbaalum adhu dhaan mudiva theermaanikkum:

| Build route | Mukkiya cost drivers | Thevaiyaana skills | Data control |
| --- | --- | --- | --- |
| Hosted model API, mudinjaa oru Indian cloud region-la | Token kanakkula pay panrathu; set-up konjam dhaan | Prompting, evaluation, integration | Unga contract-padi data cloud provider-kitta pogum; region-aiyum retention-aiyum check pannunga |
| Oru open-weight model-a self-host panrathu | Idle-aa irundhaalum neenga pay panra GPUs, avattrai nadatha aatkal | Model serving, scaling, security patching | Data unga sondha account-layo data centre-layo irukkum, aanaa ovvoru failure-um unga poruppu |

Oru niyaayamaana default: hosted API-la aarambinga. Unga rules data-va unga systems-a vittu veliye poga vidaadhapodhu, illa GPUs aridhaa dhaan idle-aa irukkura alavukku volume adhigamaavum nilaiyaavum irukkumbodhu mattum self-host pannunga. Ovvoru model-um kidaikkiradhu cloud region-a poruthu maarum, adhanaala oru model-a suthi design panradhukku munnaadi region-a check pannunga.

### Step 4: screen pannunga, appuram oppidunga

Sila factors pass illa fail dhaan. Avattrai mudhalla check pannunga, yenna endha vilaiyum fail aagura oru option-a ethukkakkoodiyadhaa aakkaadhu:

1. **Fit.** Unga languages, document formats, templates, workflows-a adhu handle pannumaa? Vendor-oda demo data-la illa, unga sondha evaluation set-la test pannunga.
2. **Data, compliance.** Data enga pogalaam? Adhu unga security, privacy, sector rules-a poorthi pannudhaa?

Appuram meedhiya edai podunga:

3. **Total cost of ownership**, rendu moonu varushathukku (keezha paarunga).
4. **Speed.** Evvalavu seekkiram value venum? Maasakkanakkaana delay-kkum oru cost irukku, udhaaranamaa michappaduthaama pona doctor hours.
5. **Differentiation.** Idha neenga nallaa panradhaala customers oru competitor-a vittu ungalai thernthedupaangalaa? Unga sector-la ellaa firms-kkum idhu ore maadhiri thevai-nna, adhu commodity. "Idhu engalukku mukkiyam"-nu solradhu test illa: kittathatta ellaame mukkiyam dhaan.
6. **Lock-in.** Pinnaadi veliye varradhu evvalavu kashtam?

### Vendor due-diligence checklist

Endha vendor koodavum sign panradhukku munnaadi, indha ezhu kelvigalukku ezhuthula badhil vaangunga:

1. **Location.** Backups, support access utpada, data enga store aagudhu, enga process aagudhu?
2. **Training.** Vendor-o avanga model provider-o unga data-la train panraangalaa? Contract-la "illa"-nu vaangunga.
3. **Retention.** Data evvalavu naal vachiruppaanga, delete pannadhai confirm pannuvaangalaa?
4. **Sub-processors.** Vera yaarellaam data-va thodraanga, udhaaranamaa product-kku pinnaadi irukkura model provider?
5. **Security evidence.** ISO 27001 maadhiri certifications illa oru SOC 2 report, koodave sameebathula panna oru penetration test.
6. **Breach notice.** Evvalavu seekkiram ungalukku solluvaanga? DPDP Act, CERT-In-oda rules-padi ungalukkum sondha kadamaigal irukkalaam.
7. **Exit.** Unga data-vaiyum outputs-aiyum use pannakkoodiya format-la export panna mudiyumaa? Price illa model maatrangalukku munnaadi evvalavu notice kidaikkum?

### Total cost of ownership

Rendu pakkathaiyum muzhusaa kanakku pannunga. Vaangradhu-nnaa licence fee mattum illa: integration, oru internal owner, quality checks, veliye varradhoda cost ellaam irukku. Build panradhu-nnaa tokens mattum illa: engineers, evaluation, hosting, maintenance irukku. Ellaa option-layum ore maadhiri irukkura costs, udhaaranamaa ovvoru output-aiyum review panra expert neram, onnaiyonnu cancel pannidum, adhanaala avattrai oppeettula irundhu vittudalaam.

Experienced teams-a kooda rendu gotchas maattividum:

- **Tokens-a vida aatkalukku dhaan adhiga cost.** Oru build-oda total-la model usage perumbaalum oru chinna pagudhi dhaan. Appadiye assume panradhukku munnaadi unga sondha split-a check pannunga.
- **Sunk costs kelviyaiye maathidum.** Oru thadavai build pannittaa, selavaana panam ponadhu ponadhu dhaan. Pinnaadi oru review-la future costs-a mattum oppidunga: unga build-a otturadhu vs oru vendor-kku maarradhu.

Unga finance team kooda tax-aiyum check pannunga. IT, cloud services mela GST 18% (November 2026 nilavarappadi). Perumbaalaana healthcare services-kku GST-la irundhu exemption irukku, adhanaala oru hospital perumbaalum andha tax-a thirumba claim panna mudiyaadhu; idhu ovvoru vendor, cloud bill-oda nija cost-aiyum koottudhu.

### Maatrathukku plan pannunga

Perumbaalaana organisations kadaisiyila kalandhu dhaan pannuvaanga: commodity velaigalukku vaanguvaanga, edhuvume porundhaadha idathulayo thaanga vithiyaasappadura idathulayo build pannuvaanga. Neenga edha thernthedutthaalum, models-um vendors-um unga kaalukku keezhaye maarikkittu irukkum.

Model providers pazhaiya models-a retire pannuvaanga. Udhaaranamaa, November 2026 nilavarappadi, publicly release aana oru model-a retire panradhukku munnaadi kuranjadhu 60 naal notice tharuvom-nu Anthropic urudhi tharudhu; adhukku appuram andha model-kku pora requests fail aagum. Amazon Bedrock maadhiri partner clouds thangaloda sondha retirement schedules-a vaikkiraanga. Adhanaala kuranjadhu oru model migration-kku budget vainga, replacement-a test panna unga evaluation set-a ready-aa vachirunga. Vaangumbodhu, idhe problem-a avanga eppadi handle panraanga-nnu vendor-kitta kelunga.

## Oru worked example

Hyderabad-la oru hospital chain, doctors-oda notes-aiyum lab reports-aiyum vachu discharge summaries-a AI draft pannanum-nu ninaikkudhu. Neenda shifts-oda kadaisiyila, ovvoru summary-kkum doctors 20 mudhal 30 nimisham selavazhikkiraanga. Chain maasathukku sumaar 6,000 discharges handle pannudhu. Indha example-la irukkura ellaa numbers-um illustrative, kathukkudukkiradhukkaaga karpanaiyaa vachadhu.

### Feasibility

Sana, identity neekkina 40 patient records-a segarikkiraanga. Oru capable model-aiyum hospital-oda summary template-aiyum use panni 40 drafts uruvaakkuraanga. Moonu senior doctors avattrai rate panraanga:

| Rating | Drafts | Notes |
| --- | --- | --- |
| Chinna edits-oda usable | 31 | Perumbaalum vaarthai maatrangal |
| Periya edits venum | 7 | Mundhaiya notes-la irundha context miss aachu |
| Unsafe | 2 | Rendulayum oru medication maatram miss aachu |

Mudivu: thodarra alavukku feasible, aanaa doctor sign-off kattaayamaa irundhu, draft-la irukkura ovvoru medication-aiyum pharmacy record kooda automatic-aa check pannaa mattum. 40-la 2 unsafe drafts-na unmaiyaana rate 1%-kku keezha irundhu sumaar 17% varai edhuvaa venumnaalum irukkalaam, adhanaala Sana launch-kku munnaadi 400 records-la oru evaluation plan panraanga, adhula medication errors-a thaniyaa count pannuvaanga.

### Options-a screen panrathu

Adhe 40 records-a avanga ovvoru option-layum otti, ovvonnaiyum hospital-oda data policy kooda check panraanga:

| Option | Sana kandupidichadhu | Mudivu |
| --- | --- | --- |
| Product A vaangurathu | Drafts nallaa irukku, aanaa avanga hospital information system kooda integrate aagala | Fit kaaranamaa thallappattadhu |
| Product B vaangurathu | Data-va India-kku veliye process pannudhu; hospital-oda data policy-padi hospital-oda legal team adha reject pannudhu | Compliance kaaranamaa thallappattadhu |
| Hospital system-oda add-on-a configure panrathu | Avanga template-a follow pannavo medication check-a ottavo mudiyala | Fit, safety kaaranamaa thallappattadhu |
| Avanga existing cloud-oda Indian region-la oru hosted model API mela build panrathu | Hospital system kooda integrate aagudhu, medication check-um doctor sign-off-um irukku | Micham irukkura ore option |

Build yen jeyichadhu-nnu nermaiyaa irunga. Discharge summaries draft panradhu indha hospital-a vithiyaasappaduthura vishayam illa: ellaa hospital-kkum idhu kittathatta ore maadhiri thevai. Vera edhuvume fit-layum compliance-layum pass aagaadhadhaala dhaan build jeyichadhu. Adhanaala dhaan indha mudivukku oru review date irukku.

Indha tool medical device software-aa kanakku aagumaa-nnu team regulatory counsel-kittayum kekkudhu. India-voda drug regulator CDSCO, Medical Devices Rules, 2017-n keezh medical device software pathi guidance veliyittirukku; oru software device-aa illaiyaa-ngaradhu adhoda intended medical purpose-a poruthadhu. Adhanaala team intended purpose-a kavanamaa ezhudhi vaikkudhu, build aarambikkiradhukku munnaadiye counsel-oda karuthai ezhuthula vaangudhu.

### Build panradhoda rendu varusha cost

Build panna moonu maasam aagum, appuram rendu varusha window-kkulla 21 maasam odum-nu Sana estimate panraanga: 6,000 × 21 = 126,000 summaries.

| Illustrative cost item | Eppadi kanakku pottadhu | Rendu varusha cost |
| --- | --- | --- |
| Build team | 3 per × 3 maasam × maasathukku ₹2.5 lakh | ₹22.5 lakh |
| Pre-launch clinical evaluation | Doctors 400 drafts-a rate panraanga | ₹3 lakh |
| Security, compliance review | Oru thadavai mattum | ₹3 lakh |
| Model usage | Oru summary-kku ₹5 (₹4 kooda 25%) × 126,000 | ₹6.3 lakh |
| Hosting, logging, monitoring | Maasathukku ₹40,000 × 21 | ₹8.4 lakh |
| Maintenance | Oru engineer paadhi neram, maasathukku ₹1.25 lakh × 21 | ₹26.25 lakh |
| Ongoing quality sampling | Doctors oru sample-a review panraanga, maasathukku ₹25,000 × 21 | ₹5.25 lakh |
| Oru model migration | Model retire aagumbodhu re-test panni adjust panrathu | ₹4 lakh |
| **Total** | | **₹78.7 lakh, oru summary-kku sumaar ₹62** |

Doctor sign-off neram idhula serkkala: hospital endha option-a use pannaalum adhu ore maadhiri dhaan. Figures-la GST serkkala.

### Numbers Sana-vukku enna solludhu

- **Aatkal dhaan dominate panraanga.** Total-la model usage sumaar 8% dhaan. Aatkal (build panrathu, evaluate panrathu, maintain panrathu, migrate panrathu) sumaar 78%. Token price rettippaanaa sumaar 8% dhaan koodum. System-a maintain panra engineer poyittaa adha vida romba adhigamaa baadhikkum.
- **Volume build-kku saadhagam.** Perumbaalaana cost fixed. Maasathukku 12,000 summaries-na, illustrative total sumaar ₹85 lakh varai dhaan koodum (adhe team-oda), adhaavadhu oru summary-kku sumaar ₹34. Oru vendor-oda per-summary fee volume koodave serndhu valarum.
- **Innaikku vaangradhukkaana bar.** Build aarambikkiradhukku munnaadi, fit-layum compliance-layum pass aagura oru vendor vandhirundhaa-nnu vachukkonga. Adhoda costs integration (₹4 lakh), quality checks-oda oru internal owner (maasathukku ₹50,000); oru maasathukku appuram adhu go live aagalaam. Rendu varushathula, oru summary-kku sumaar ₹45-kku keezha irukkura endha illustrative fee-layum adhu build-a jeyikkum: (₹78.7 lakh − ₹4 lakh − ₹12 lakh) ÷ 138,000 summaries (23 live maasathula) = sumaar ₹45.
- **Pinnaadi switch panradhukkaana bar.** Build aanadhukku appuram, adhoda ₹22.5 lakh sunk. Appo adha otta maasathukku sumaar ₹2.37 lakh aagum, future migrations-kkaana oru reserve utpada. Switch panna integration, re-evaluation-kku sumaar ₹7 lakh aagum, adhaavadhu 24 maasathukku parappinaa maasathukku sumaar ₹0.29 lakh. Adhanaala switch panradhu worth-aa irukkanum-naa, compliant-aana oru vendor ippo oru summary-kku illustrative ₹26-kku keezha charge pannanum: (₹2.37 lakh − ₹0.5 lakh − ₹0.29 lakh) ÷ 6,000 = sumaar ₹26.

### Mudivu

Leadership build-a approve pannudhu, self-hosted model-la illaama oru hosted API mela, yenna GPUs otturra alavukku volume illa. Model-a maatha mudiyanum-nu, Sana prompts, medication check, 400-record evaluation set ellaathaiyum hospital-oda sondha kaiyilaye vachirukkaanga. Varushaandhira market review-kku oru concrete trigger irukku: oru product fit-layum compliance-layum pass aagi, oru summary-kku sumaar ₹26-kku keezha vandhaa (illustrative switching bar), illa volume-o rules-o maarinaa, marupadi paarunga.

## Podhuvaana thappugal

- **Prototype-a skip panrathu.** Feasibility pathina guesses perumbaalum rendu pakkamum thappaa pogum.
- **Oru prototype-a launch evidence-aa edukkradhu.** 40-la 2 unsafe-na, adhu periya alavula evaluate panradhukkaana kaaranam, alandha oru 5% rate illa.
- **Build pannavangale thanga outputs-a judge panrathu.** Ezhudhi vacha oru rubric vachu domain experts-a kelunga.
- **Vendors-a avanga demo data vachu judge panrathu.** Ovvoru option-aiyum unga sondha evaluation set-la ottunga.
- **Ungalukku mukkiyam-ngaradhaala onna differentiating-nu solradhu.** Adhanaala customers ungalai thernthedupaangalaa-nnu kelunga.
- **Oru licence fee-a token costs kooda mattum oppidradhu.** Build panradhoda cost-la perumpagudhi aatkal, evaluation, maintenance, migrations dhaan.
- **Review nerathula sunk costs-a kavanikkaama vidradhu.** Build aanadhukku appuram, future costs-a mattum oppidunga.
- **Exit-a marakkiradhu.** Sign panradhukku munnaadi data export, notice terms-a othukkonga, unga evaluation set-a unga kaiyilaye vachukkonga.

## Practice

Keezha link panniyirukkura SVPG-oda four big risks-aiyum, Hamel Husain-oda field guide-aiyum padinga.

1. **Prototype.** 20 real examples-la oru AI velaiya try pannunga. Andha domain therinja oruthar outputs-a usable, needs work, illa unsafe-nu rate pannattum. Andha sample edha sollaadhu-nnu ezhudhi vainga.
2. **Screen.** Ore velaiya solve panrom-nu solra rendu products-aiyum oru platform feature-aiyum kandupidinga. Unga examples-a ovvonnulayum ottunga, adhula onnukku ezhu due-diligence kelvigalukkum badhil ezhudhunga.
3. **Cost.** Build route-kku, Sana-voda style-la oru rendu varusha cost table podunga; ovvoru figure-aiyum estimate-nu mark pannunga. Oru unit-kku vendor fee evvalavaa irundhaa vaangradhu jeyikkum-nu kanakku pannunga.
4. **Recommend.** Oru review date-um, mudiva marupadi thirakka oru concrete trigger-um irukkura oru pakka buy, configure illa build parindhurai-ya ezhudhunga.

**Mudinjadhu-nnu eppo sollalaam:** expert rate panna prototype results-aiyum, costing panna oru rendu varusha oppeettaiyum, fit, compliance, cost, lock-in vachu niyaayappaduthakkoodiya oru therva-yum kaatta mudiyumbodhu.
