## Idhu enna

**Human approval step** oru action effect-ku varradhukku munnadi oru agent-a pause pannum, agent enna seiya virumbudhu, yen-nu oru aal-ku kaattum, avanga approve, edit illa reject pannaa mattum thodarum. Production agents-la human-in-the-loop-oda romba common vadivam idhu.

Approval selavu aagura, irreversible, external illa regulated actions-ku: refunds, payments, customers-ku emails, messages, records-la maatrangal, edhai delete panradhum, legal illa medical decisions-a thodura edhuvum. Data-va padikkradhukku approval perumbaalum thevai illa.

```flow
Agent propose panraan: order 7781-ku ₹2,499 refund -> Risk rules
Risk rules -[read, illa sirusu, reversible]-> Run pannu
Risk rules -[limit-ku mela refund]-> Pause | state-a checkpoint-aa save pannu; run "interrupted"-nu mudiyum
Pause -> Approval card | action, reason, evidence: Approve, Edit amount, Reject with a reason
Approval card -[4 mani-la reply illa]-> Nyaabagappaduthu, apram escalate pannu
Approval card -[decision]-> Checkpoint-la irundhu resume pannu -> Act pannu -> Customer-kitta sollu
Customer-kitta sollu -> Log | decision, edit, reason, mudivu panna aagiya seconds
```

Indha lesson Jaipur-la oru e-commerce company-oda returns, refunds agent-a follow pannum.

## Idhu eppadi work aagudhu

**Actions-a risk-vaaripaa piringa.** Ovvoru tool-aiyum list panni rate pannunga: read-only, reversible internal maatram, irreversible illa external. Oru simple rule set edhukku approval vendum-nu mudivu pannum: irreversible illa external actions-ku eppovum; matha-vatrukku oru threshold-ku mela (refunds ₹1,000-ku mela maadhiri); reads-ku eppovum illa.

**Durable-aa pause pannunga.** Agent nirutthi kaathirukkanum, oru vela mani neraththukku, oru server process-a thirandhu vachirukkaama. Checkpoints irukkura frameworks idha seiyum: state save aagum, run "interrupted" state-la mudiyum, apram oru call andha aal-oda mudivoda adhe idathula irundhu resume pannum.

**Sariyaana information-a kaattunga.** Approval screen-la proposed action plain words-la ("Refund ₹4,500 to UPI ID ...@okaxis for order 7781"), agent-oda reason, adhu use panna evidence (order, policy clause), oru click approve, edit, reject kaattanum. Approver mudivu pannanum-na vera moonu systems-a thirakkanum-na, avanga kannai moodikkittu approve panna aarambippaanga.

**Edit, feedback.** Approver parameters-a maatha vidunga (₹4,500-la irundhu ₹3,000), oru note serkka vidunga. Rendum agent-oda state-ku pogum, appo adhu customer-ku andha maatratha explain pannalaam, ungaloda logs-ukkum training, eval data-vaa pogum.

**Measure pannunga.** Approval rate, edit rate, rejection reasons, mudivu panna aagura neram-a track pannunga. Maadha kanakkula rejection rate kittathatta zero-na, kurainja risk cases-ku indha step-a loosen pannalaam-nu artham irukkalaam. Edits illaama decision neram kuraiyradhu rubber-stamping-a kaattalaam.

**Timeouts, escalation.** Yaarum badhil sollalannaa enna aagum-nu mudivu pannunga: nyaabagappaduthu, innoru approver-ku escalate pannu, illa safe-aa cancel pannu. Eppovum "approve"-ku default aagaadheenga.

**Oru agent-ku oru risk table:**

| Tool | Type | Rule |
| --- | --- | --- |
| `read_order` | Read-only | Approval eppovum thevai illa |
| `issue_return_label` | Reversible | Auto-approved |
| `refund` ₹1,000 varaikkum, 30 naatkalukku kammi order | Panam, sirusu | Auto-approved |
| `refund`, matha ethavadhu case | Panam | Support lead approve pannuvaanga |
| Legal action-a pathi peasura edhavadhu message | Legal risk | Muzhusaa oru aal-kitta poradhu |

**Card-a design pannradhu.** Decision-a mudhalla vainga, amount-yum recipient-yum oru vaakkiyathula. Adhukku keezha agent sonna reason-aiyum evidence-aiyum kudunga, example customer-oda photo, policy clause adhoda number-oda. Buttons-a perusaa, outcomes-a label pannunga. "Reject" oru short list-la irundhu oru reason-aiyum free text-aiyum kekkanum, yenna andha reasons thaan neenga apram analyse pannuveenga. Card-a unmaiyaana approvers-oda test pannunga: avanga mudivu panna vera system-a thirandhaa, card-la edhaavadhu missing.

**Evidence-oda loosen pannradhu.** Approval permanent illa. Oru rendu maadha data-vukku apram, ovvoru rule-oda approval, edit, rejection rates-a paarunga. Makkal kittathatta ellaathaiyum edits illaama approve pannum idathula, threshold-a konjam uyarthi complaints-a paarunga. Avanga adikkadi edit pannum idathula, mudhalla agent-oda examples-a improve pannunga.

**Policy-a oru pure function-aa.** Rules-a prompt-la irundhu veliya, test panna koodiya code-la vainga:

```python
from dataclasses import dataclass

@dataclass
class Decision:
    route: str            # "auto", "approve" or "handover"
    approver: str | None = None
    reason: str = ""

def policy(tool, args, context):
    if tool in {"read_order", "track_shipment"}:
        return Decision("auto", reason="read-only")
    if tool == "issue_return_label":
        return Decision("auto", reason="reversible")
    if tool == "refund":
        amount, age = args["amount_inr"], context["order_age_days"]
        if amount <= 1000 and age <= 30:
            return Decision("auto", reason="small refund within 30 days")
        if amount <= 25000:
            return Decision("approve", "support_lead", "refund above auto limit")
        return Decision("approve", "finance_manager", "large refund")
    if context.get("mentions_legal_action"):
        return Decision("handover", reason="legal risk")
    return Decision("approve", "support_lead", "unknown tool: default to a person")

assert policy("refund", {"amount_inr": 800}, {"order_age_days": 12}).route == "auto"
assert policy("refund", {"amount_inr": 40000}, {"order_age_days": 3}).approver == "finance_manager"
```

Theriyaadha tools eppovum oru aal-kitta pogum, "auto"-ku illa. Agent loop entha tool-aiyum run pannradhukku munnadi `policy`-a call pannum; "approve" oru pending action-a save panni run-a pause pannum.

**Oru durable pending action.** Ovvoru request-aiyum approver-ku thevaiyaana ellaathodayum, oru idempotency key-vodayum store pannunga, appo oru double click illa retry adha rendu thadava run pannaadhu:

```python
import sqlite3, time, uuid

db = sqlite3.connect("approvals.db")
db.execute("""CREATE TABLE IF NOT EXISTS pending (
    id TEXT PRIMARY KEY, run_id TEXT, tool TEXT, args TEXT, summary TEXT,
    approver TEXT, status TEXT DEFAULT 'waiting', decided_by TEXT, note TEXT,
    created REAL, decided REAL)""")

def request(run_id, tool, args_json, summary, approver):
    pid = uuid.uuid4().hex
    db.execute("INSERT INTO pending (id, run_id, tool, args, summary, approver, created) VALUES (?,?,?,?,?,?,?)",
               (pid, run_id, tool, args_json, summary, approver, time.time()))
    db.commit()
    return pid

def decide(pid, user, approve, note="", new_args_json=None):
    cur = db.execute("""UPDATE pending SET status=?, decided_by=?, note=?, decided=?, args=COALESCE(?, args)
                        WHERE id=? AND status='waiting'""",
                     ("approved" if approve else "rejected", user, note, time.time(), new_args_json, pid))
    db.commit()
    return cur.rowcount == 1        # False if already decided: the second click does nothing
```

`decide` success aanaa, ungaloda code pause aana run-a andha mudivoda resume pannum. `decide`-la, request-la peru sollapatta approver role `user`-kitta irukkaanu check pannunga; agent-a kettavanga avanga sonthamaana periya refund-a approve pannakoodaadhu.

**Timeouts-a oru scheduled job-aa.** Ovvoru sila nimidangalukkum, limit-a thaandi kaathirukkura requests-a kandupidinga: 30 nimidathula nyaabagappaduthunga, 2 mani neraththula adutha approver-ku escalate pannunga, 24 mani neraththula customer-ku oru message-oda safe-aa cancel pannunga. Cancel pannradhu thaan default end state, approve pannradhu eppovum illa.

**Approvers-aiyum test pannunga.** Aprama aprama, queue-la veendumne thappaana request-a podunga, example antha customer-ku eppovume deliver aagaadha order-ku oru refund. Adhu approve aanaa, cards-ku nalla evidence vendum, illa careful review-ku queue romba neenda.

## Oru worked example

Jaipur-la oru e-commerce company, return, refund requests-a handle panna oru agent-a deploy panradhu.

Risk rules: orders-a padikkradhukku approval thevai illa; return label kudukkradhu reversible, auto-approved; 30 naatkalukku kammiyaana orders-ku ₹1,000-ku keezha refunds auto-approve aagum; matha ella refunds-kum support lead-oda approval vendum; legal action-a pathi peasura edhavadhu message muzhusaa oru aal-kitta pogum.

Approval card ippadi padikkum: "Refund ₹2,499 for order 7781 (blue kurta, size M). Customer says it arrived torn; photo attached. Policy 4.2 allows full refund for damage reported within 7 days; reported on day 3." Approve, Edit amount, Reject with reason.

Mudhal maadhathula, leads 91% approve pannaanga, 6% edit pannaanga (perumbaalum oru set-la oru item mattum damage aana partial refunds), 3% reject pannaanga (damage illaadha photos). Median decision neram 40 seconds. Edit cases-a agent-oda examples-la serkkureenga, adhukku apram edits 2%-ku kuraiyudhu. Andha evidence-oda, client auto-approve threshold-a ₹1,500-ku uyarthuraanga, adhu complaints-a adhigam pannaama approvals-la moonaa ondra kuraikkudhu.

| Measure, mudhal maadham | Value | Eduththa action |
| --- | --- | --- |
| Propose panna madhiri approve aachu | 91% | Onnum illa |
| Edit aachu | 6%, perumbaalum partial refunds | Edit cases examples-la serkkappattu; edits 2%-ku kuraindhudhu |
| Reject aachu | 3%, damage illaadha photos | Reasons vaaraa vaaram review aagum |
| Median time to decide | 40 seconds | Card podhumaana alavu clear-nu mudivu |
| Auto-approve threshold | ₹1,000-la irundhu ₹1,500-ku uyarthinaanga | Moonaa ondru kammi approvals, complaints-la yeththam illa |

## Podhuvaa panra thappugal

- **Ellaathaiyum illa onnaiyum approve pannradhu.** Ovvoru read-kum approval makkal neratha veen pannum; payments-ku illaadhaa kavalaiyillaadhadhu. Actions-a risk-vaaripaa rate pannunga.
- **Kaathirukkum podhu oru process-a thirandhu vachirukkaradhu.** Approvals mani kanakkula aagalaam. State-a save panni apram resume pannunga.
- **Evidence illaadha approval screens.** Makkal judge panna mudiyaadhu, adhanaala approve click pannuvaanga.
- **Timeout-la approve-ku default aaradhu.** Mounam sammadham illa. Escalate illa cancel pannunga.
- **Edits-la irundhu kathukkaadhadhu.** Agent enga thappunnu ungalukku irukkura nalla data edits-um rejections-um thaan.
- **Approval rules-a prompt-la mattum ezhudhuradhu.** Model avatha skip pannalaam; code pannaadhu.
- **Requester approve panna vidradhu.** Panam, data maatrangalukku kekkuravanga-yum approve panravanga-yum piringa.
- **Approvals-la idempotency illaama.** Oru double click action-a rendu thadava run pannum.

## Approval steps thevai illaadha idam

- **Read-only agents**, adhavadhu paarthu badhil mattum solravai.
- **Muzhusaa reversible, kammi cost actions**, undo-oda, example oru note illa tag serkkradhu.
- **Code-la already tight limits-kulla irukkura actions**, example oru customer-ku maadhathukku oru sirya cap-kulla refunds, review-a vida thappugal selavu kammi.

Approvals-ku thaamadham-um staff neram-um cost. Oru thappu expensive-aa, irreversible-aa, illa company-ku veliya irukkura makkalukku theriyum-nu irukkura idathula use pannunga.

## Demo-la irundhu production-ku

- **Policy-a tests-oda code-la vachukkunga**, business owners-oda oru table-aa review pannunga.
- **Ovvoru request-aiyum decision-aiyum store pannunga**, yaaru, eppo, enna maathunaanga, yen-nu.
- **Queue-oda vayasu mela alert pannunga**, oru agent-ku requests spike aagum podhum.
- **Maadhaa maadham rates-a review pannunga**, ovvoru rule-ku: approval, edit, rejection, time to decide.
- **Aprama aprama test requests-a plant pannunga**, approvers padikkiraangalaanu check panna.
