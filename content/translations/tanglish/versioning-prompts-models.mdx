## Idhu enna

Oru AI system-oda behaviour code-a vida neraya vishayangalai poruthadhu:

- **prompts** (system prompts, templates, few-shot examples);
- **model** (provider, model peru, snapshot illa version);
- temperature, maximum tokens maadhiri **settings**;
- model paarkkura **tool definitions**;
- **retrieval configuration** (index version, chunking, top-k, reranker).

Versioning-na idhula ovvonnukkum oru identifier irukku, maatrangal review-um tests-um vazhiyaa pogum, live combination ovvoru request-oda record aagum, munnaadiya entha combination-aiyum thirumba restore panna mudiyum.

```flow
Release assistant-2026.11.3 | prompts support-system v12, refund-rules v4; oru pinned, dated model snapshot; temperature 0.2; tools lookup_order v3, create_ticket v2; index 2026-11-01 -[ovvoru trace-layum audit event-layum record aagum]-> Oru maatram
Oru maatram -> CI-la golden set -> Staging -> Production alias
Production alias -[rollback: alias-a thirumba nagarthunga]-> Munnaadiya release
```

Oru release-oda ovvoru pagudhikkum adhoda sondha version irukku, adhanaala entha answer-aiyum adha uruvaakkinadhu-ngra exact vishayatha varaikkum trace panna mudiyum.

Indha lesson-la Gurugram-la oru fintech-oda support assistant-a follow pannuvom, angae moonu teams production-la neradiyaa prompts-a edit pannittu irundhaanga.

## Idhu eppadi work aagudhu

**Prompts version control-la.** Prompts-a repository-la files-aa (illa prompt registry-la) store pannunga, code-la sidhari irukkura strings-aa illa dashboard-la edit panra maadhiri illa. Maatrangal pull requests vazhiyaa, CI-la evals-oda pogum.

**Prompt registries.** MLflow-oda prompt registry, Langfuse, matra tools aliases-oda ("production", "staging") peru kodutha, numbered prompt versions-a store pannum. Application prompt-a alias vachu kekkum; alias-a nagarthina code release illaama deploy illa rollback aagum. Engineers illaadhavanga prompts-a edit panra podhu payanulladhu, maatrangal innum evals-a pass pannanum.

**Models-a pin pannunga.** Providers tharum idathula dated model snapshots use pannunga, sathamillaama maarum aliases-a illa. Neenga ungaloda gateway-oda aliases ("chat-default") use pannina, gateway configuration thaane versioned-aa, reviewed-aa irukkanum.

**Oru release identifier.** Prompt version, model, settings, index version-a oru release-la serthukkunga (example "assistant-2026.11.3"), ovvoru trace-layum audit event-layum record aagum.

**Promote panradhukku munnaadi test pannunga.** Ovvoru maatramum golden set-a odum. Ippo irukkura release-oda quality, cost, latency-la compare pannunga. Staging vazhiyaa production-ku promote pannunga.

**Provider deprecations.** Providers announce panna dates-la models-a retire pannuvaanga. Oru calendar vechukkunga, replacement-a seekirama test pannunga, switch-a oru release-aa plan pannunga.

**Rollback.** Munnaadiya release-a ready-aa vechukkunga. Rollback oru action-aa irukkanum: alias-a nagarthunga illa munnaadiya tag-a thirumba deploy pannunga.

**Enna version pannanum, eppadi:**

| Pagudhi | Eppadi version panradhu | Typical maatram |
| --- | --- | --- |
| Prompts | Git-la files illa numbered versions-oda registry | Wording, examples, rules |
| Model | Pinned dated snapshot, illa reviewed gateway alias | Pudhu model-ku upgrade |
| Settings | Git-la config file | Temperature, max tokens |
| Tool definitions | Git-la code | Pudhu parameter illa tool |
| Retrieval | Git-la index version-um config-um | Chunk size, top-k, reranker |

**Oru thadavai oru vishayatha maathunga.** Oru release prompt-aiyum model-aiyum index-aiyum serndhu maathi quality kuraijaa, edhu pannadhu-nu yaarum solla mudiyaadhu. Mudinjaa avatrai thani releases-aa ship pannunga, ovvonnum golden set vazhiyaa. Neraya onnu serndhu ship aaganum-na, example prompt adjustments thevaipadura model switch, staging-la ovvoru step-layum golden set-a odunga, production-ku munnaadiye ovvoru pagudhiyin vilaivum theriyum.

**Model switches.** Pudhu model-a oru release candidate-aa treat pannunga: muzhu golden set-a odunga, cost-aiyum latency-aiyum compare pannunga, neenga serve panra ovvoru language-layum sample conversations-la refusals-aiyum tone-aiyum check pannunga, mella mella roll out pannunga. Oru model-ku tune panna prompts-ku aduthadhukku sila sinna maatrangal thevai padum.

**Prompts files-aa, releases oru manifest-aa.**

```text
prompts/
  answer.v13.md
  answer.v14.md
  rewrite.v4.md
release.yaml
```

```yaml
# release.yaml
release: assistant-2026.11.3
model: claude-sonnet-5-5-YYYYMMDD     # a dated snapshot where the provider offers one
settings: {max_tokens: 600}
prompts: {answer: v14, rewrite: v4}
index: policies-2026-11-01
tools: tools-v7
```

```python
import hashlib, json, yaml
from pathlib import Path

def load_release(path="release.yaml"):
    rel = yaml.safe_load(open(path))
    rel["prompt_text"] = {name: Path(f"prompts/{name}.{ver}.md").read_text()
                          for name, ver in rel["prompts"].items()}
    blob = json.dumps({k: rel[k] for k in ("model", "settings", "prompts", "index", "tools")}, sort_keys=True)
    rel["fingerprint"] = hashlib.sha256(blob.encode()).hexdigest()[:10]
    return rel

RELEASE = load_release()     # log RELEASE["release"] and RELEASE["fingerprint"] on every trace
```

Yaaraavadhu release-a rename pannaama edit pannina fingerprint maarum, adhu "chinna" track aagaadha maatrangalai pidikkum.

**CI-la checks.** Release edhaavadhu illaadha illa risky-aana onna point pannina, build-a fail pannunga:

```python
import re
from datetime import date

RETIREMENTS = yaml.safe_load(open("model-retirements.yaml"))     # {model_id: "YYYY-MM-DD"}

def check_release(rel):
    problems = []
    for name, ver in rel["prompts"].items():
        if not Path(f"prompts/{name}.{ver}.md").exists():
            problems.append(f"missing prompt file {name}.{ver}")
    if not re.search(r"\d{8}$", rel["model"]):
        problems.append("model is not pinned to a dated snapshot")
    retire = RETIREMENTS.get(rel["model"])
    if retire and (date.fromisoformat(retire) - date.today()).days < 60:
        problems.append(f"{rel['model']} retires on {retire}; plan the switch")
    return problems
```

Provider dated names tharaadha idathula, ungalaal mudinjadha pin pannunga (ungaloda gateway-oda alias, reviewed), sathamillaama nadakkura maatrangalai pidikka golden set-a schedule-la odunga.

**Promotion-um rollback-um.** Production deploy panna commit-la irundhu `release.yaml`-a padikkum, adhanaala promote panradhu oru pull request-a merge panradhu, rollback panradhu munnaadiya commit-a thirumba deploy panradhu. Adhukku badhila prompt registry use pannina, adhe rule: app oru alias-a padikkum, golden set pass aanadhum promotion alias-a nagarthum.

**Manushangal padikkura oru changelog.** `release.yaml`-oda pakkathula oru sinna `CHANGELOG.md` vechukkunga: release id, date, enna maarichu, munnaadiya release-oda compare panna eval results, yaaru approve pannaanga. Clients-oda reviewers perumbaalum idhaiye kekkuvaanga.

## Oru worked example

Gurugram-la oru fintech-oda support assistant-oda prompts-a moonu teams admin panel-la neradiyaa edit pannittu irundhaanga. Oru Friday, complaint volume irandu madangu aachu. Enna maarichu-nu yaarukkum theriyala; traces model peru-a mattum kaattichu.

Fix:

- Prompts repository-kku files-aa pochu, ovvoru prompt-kum owners-oda.
- Oru prompt registry published versions-a vechirukku; production alias `support-prod`-a use pannudhu.
- Ovvoru trace-um release-a record pannudhu: prompt versions, model snapshot, temperature, index version.
- CI ovvoru prompt change-layum 120-kelvi golden set-a odudhu, oru point-a vida adhigamaana veezhchi-a block pannudhu.
- Gateway model aliases pull request vazhiyaa mattum maarum.

Rendu maadham kazhichu oru pudhu prompt version evals-a pass pannudhu, aana Hindi conversations-la customer feedback kuraiyudhu. Kuraivu release 2026.12.2-la aarambichadhu-nu traces kaattudhu. Team oru nimidathula alias-a thirumba 2026.12.1-ku nagarthuraanga, apram golden set-la 25 Hindi cases-a serkkuraanga, adhu problem-a veliya kondu varudhu. Sari panna version adutha naal ship aagudhu.

| Event | Versioning-ku munnaadi | Versioning-ku aprom |
| --- | --- | --- |
| Complaint spike | Enna maarichu-nu yaarukkum theriyala | Traces release 2026.12.2-a kaattichu |
| Rollback | Mani neram ooghippu | Alias oru nimidathula thirumba pochu |
| Root cause | Theriyala | 25 pudhu Hindi golden cases kandupidichudhu |
| Fix ship aachu | Theliva illa | Adutha naal, CI vazhiyaa |

## Podhuvaa panra thappugal

- **Production dashboards-la review illaama prompts-a edit panradhu.** Maatrangal theriyaama poidum.
- **Floating model aliases.** Provider model-a update pannum, ungaloda behaviour solladhe maarum.
- **Traces-la versions illaama irukkradhu.** Quality maatrathai oru release-oda inaikka mudiyaadhu.
- **Golden-set gate illaama irukkradhu.** Prompt changes-um code changes thaan; test pannunga.
- **Deprecation dates-a ignore panradhu.** Kadaisi nimida kattaaya switch oru risky release.
- **Oru release-la neraya pagudhigalai maathuradhu.** Quality kuraijaa, edhu kaaranam-nu solla mudiyaadhu.
- **Ovvoru prompt-kum owner illaama irukkradhu.** Yaaraavadhu ovvoru maatrathaiyum approve panni, adhoda vilaivukku badhil sollanum.
- **Pudhu version serkkaama, prompt file-a appadiye edit panradhu.**
- **Oru fixed peru-kku keezha sathamillaama maarum model aliases.**
- **Retirement calendar illaama irukkradhu**, adhanaala deprecation oru emergency aagidum.

## Light-aana versioning podhum-na

- **Oru prompt-oda prototype**: Git-la vechukkunga, entha model use pannineenga-nu note pannunga.
- **Personal tools**, matravanga consistent behaviour-a nambi illaadha idathula.
- **Oru thadavai odura fixed batch jobs**, angae output-la prompt-aiyum model-aiyum record pannina podhum.

## Demo-la irundhu production varaikkum

- **Ella pagudhiyaiyum oru release file-la pin pannunga**, ovvoru trace-layum release id-aiyum fingerprint-aiyum log pannunga.
- **Ovvoru release change-layum CI-la golden set-a odunga.**
- **Model retirement dates-a track pannunga**, replacements-a seekirama test pannunga.
- **Eval results-um approvals-um serthu oru changelog vechukkunga.**
- **Munnaadiya release-a thirumba deploy panni rollback pannunga.**

## Practice pannunga

MLflow-oda prompt registry docs-a padinga.

1. Ungaloda app-oda prompts-a versioned files-kku illa aliases-oda registry-kku maathunga.
2. Ovvoru trace-layum oru release identifier (prompt versions, model snapshot, settings, index version) record pannunga.
3. Oru prompt-a maathi, CI-la ungaloda golden set-a odi, promote panni, apram oru action-la rollback pannunga.
4. CI-la check_release-a serunga, apram release.yaml-a illaadha oru prompt version-a point pannunga, build fail aagudhu-nu confirm pannunga.

**Mudinjadhu-nu eppo sollalaam:** Entha pazhaya request-kum "indha answer-a exact-aa edhu uruvaakkichu?"-nu badhil solla mudiyum, anju nimidathukku kammiyaa rollback panna mudiyum.
