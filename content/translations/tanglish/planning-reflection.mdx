## Idhu enna

Oru agent loop oru step oru step-aa mudivu edukkum. Moonu patterns andha mudivugal eppadi edukkapadudhu-nu shape pannum:

- **ReAct** (reason, act): konjam yosinga, oru tool-a call pannunga, result-a padinga, thirumba yosinga. Flexible-aa, simple-aa; perumbaalaana frameworks-la default.
- **Plan-then-execute**: mudhalla steps-oda muzhu plan ezhudhunga, apram avatrai seiyunga, edhaavadhu edhirpaaraadhadhu nadandhaa mattum plan-a maathunga.
- **Reflection**: oru result-a produce panna aprom (illa avvappo), agent adha goal illa checklist-ku ethiraa critique panni, kammiyaa irukkuradha sari seiyum.

Avai serndhum varum: oru plan, ReAct-style steps-aa odum, final answer-kku munnaadi oru reflection pass.

```flow
dir: LR
title: ReAct: vegamaa adapt aagum, aana drift aagalaam
Think -> Act -> Observe -> Think
```

```flow
title: Plan-then-execute, reflection-oda
Planner, a strong model | 1 website, 2 funding, 3 founders, 4 competitors, 5 red flags, 6 write -> Each step: a short ReAct loop | at most 5 tool calls, a small model
Each step: a short ReAct loop -> Draft -> Checks | code: totals add up; model: every claim sourced
Checks -[fail]-> One revision -> Final
Checks -[pass]-> Final
```

Indha lesson-la Bengaluru-la oru venture fund, oru-page startup briefs ezhudhura agent build panradha follow pannuvom.

## Idhu eppadi work aagudhu

**ReAct.** Ovvoru turn-layum model oru chinna thought ezhudhum ("badhil sollurathukku munnaadi order status venum"), apram oru tool call, apram observation-a paakkum. Adhu kandupidikkiradhukku vegamaa adapt aagum. Adhoda weakness neenda tasks-la drift: pathinaindhu steps aprom original goal-a marakkalaam illa adhae seiyalaam.

**Plan-then-execute.** Model, perumbaalum oru strong model, oru numbered plan-a oru thadava ezhudhum. Oru selavu kammiyaana model illa saadhaa code ovvoru step-aiyum odum. Plans neenda tasks-a innum predictable aakkum, user illa approver-ku kaattura easy ("idhu thaan naan seiya pora"), strong model oru thadava thaan odradhaala cost-um kammi aagum. Weakness rigidity: step 3 pudhusaa edhaavadhu kaattunaa, agent adha gavanichu thirumba plan pannanum, appadiyae poga koodaadhu.

**Reflection.** Rendaavadhu pass kekkum: indha result requirements-a meet pannudha? Numbers consistent-aa irukka? Ovvoru pagudhikkum badhil sonnena? Adhu adhe model-a critique prompt-oda irukkalaam, vera model, illa deterministic checks (tests pass, totals add up, JSON validate). Deterministic checks romba selavu kammi, nambagamaanadhu; rules-aala judge panna mudiyaadha idathula mattum model critique use pannunga.

**Cost-um limits-um.** Ovvoru pattern-um calls-a serkkum. Reflection loops-ku oru cap venum (example, rendu revision rounds), illaina model meet panna mudiyaadha requirement-kaaga eppavum loop aagalaam.

**Patterns-a compare panradhu:**

| Pattern | Strengths | Weaknesses | Edhukku nallaa |
| --- | --- | --- | --- |
| ReAct | Simple, ovvoru result-kum adapt aagum | Neenda tasks-la drift aagum | Short tasks, konjam tool calls |
| Plan-then-execute | Ovvoru pagudhiyum cover aagum, selavu kammi steps, plan theriyum | Re-plan pannaadhaa rigid | Theriyura pagudhigal irukkura neenda tasks |
| Reflection | Users-ku theriyura munnaadi errors-a pidikkum | Extra calls; loop aagalaam | Check panna mudiyura requirements irukkura outputs |

**Eppo re-plan pannanum.** Rule-a executor-kulla ezhudhunga: oru step-oda result plan-la irukkura oru assumption-oda mothinaa, nirutthi, andha idathula irundhu maathina plan-ku planner-a kelunga. Example, step 2-la startup kazhindha varusham acquire aachu-nu theriyuthu-naa, brief-ku vera shape venum, original plan-a thodarnthaa steps-a veenaakkum, thappaana document varum. Ovvoru re-plan-aiyum log pannunga, adikkadi re-plan aagudhunaa planner-oda mudhal plans mosam-nu artham.

**Reflection-a useful aakkradhu.** "Idha improve pannu" maadhiri vague critique prompt vague changes-a tharum. Critic-ku oru specific checklist kudunga, ovvoru item-kum oru reason-oda pass illa fail kelunga. Fail aana items-a mattum thirumba revision-ku anuppunga. Idhu revisions-a focused-aa vachirukkum, edhu checks adhigam fail aagudhu-nu alakka easy-aakkum, adhu main prompt-la edha improve pannanum-nu kaattum.

**Check panna plan-oda plan-then-execute.** Plan-a structured data-vaa kelunga, code-la check pannunga, apram mattum odunga:

```python
from pydantic import BaseModel, Field

TOOLS = {"web_search", "fetch_page", "compare_table"}
MAX_STEPS, MAX_SEARCHES = 8, 5

class Step(BaseModel):
    tool: str
    purpose: str
    inputs: dict

class Plan(BaseModel):
    goal: str
    steps: list[Step] = Field(min_length=1)

def check_plan(plan: Plan):
    problems = []
    if len(plan.steps) > MAX_STEPS:
        problems.append(f"{len(plan.steps)} steps; the limit is {MAX_STEPS}")
    unknown = {s.tool for s in plan.steps} - TOOLS
    if unknown:
        problems.append(f"unknown tools: {sorted(unknown)}")
    if sum(s.tool == "web_search" for s in plan.steps) > MAX_SEARCHES:
        problems.append("too many searches")
    if plan.steps[-1].tool != "compare_table":
        problems.append("the plan must end by building the comparison table")
    return problems
```

Model-kitta plan-a structured output-aa vaanga (structured-output lesson eppadi-nu kaattum), `check_plan`-a odunga, edhaavadhu problems irundhaa oru revision-ku anuppunga. Appavum fail aanaa, nirutthi oru aal-a kelunga. Odikka munnaadi check panna plan-a user-ku kaattuvadhum nambikkaiya valarkkum: "Naan moonu makers-a search pannuven, avanga spec pages-a padippen, oru table build pannuven. Aarambikkalaama?"

**Planning-a natural language-la illa calls-la.** Oru plan exact function calls-a per solla mudiyum (`web_search(query="Ather 450X range")`) illa steps-a vaarthaigalla describe pannalaam ("ovvoru maker-oda real-world range-a kandupidi"), adha rendaavadhu step calls-aa maathum. Exact calls check panna easy; vaarthai plans tool names maarinaalum thaanguvadhu, makkal padikka easy. Neraya teams plan-ku vaarthaigalum, execution-ku exact calls-um use pannuvaanga.

**Checklist-oda reflection.** Critic-kitta oru rewrite illa, ovvoru item-kum oru verdict kelunga:

```python
CHECKLIST = [
    "Every maker has price, range and service network filled in",
    "Every number has a source link",
    "Prices are in rupees and say ex-showroom or on-road",
    "No maker is missing from the final table",
]

CRITIC_PROMPT = (
    "Check the draft against each item. Reply as JSON: "
    '[{"item": ..., "pass": true or false, "reason": ...}]. Do not rewrite the draft.\n\n'
    "Checklist:\n" + "\n".join(f"- {c}" for c in CHECKLIST)
)
```

Fail aana items-a mattum writer-kku thirumba anuppunga, oru illa rendu revision rounds allow pannunga, edhu items adhigam fail aagudhu-nu log pannunga. Oru rule-a code-la check panna mudinjaa (ovvoru row-kum moonu numbers, ovvoru number-kum oru link), adha code-la check panni, andha item-ku model critic-a vittudunga.

**Fail aana attempt-la irundhu kathukkradhu.** Reflexion approach-la, oru attempt check-la fail aanaa, agent yen-nu oru chinna note ezhudhum ("launch prices use pannen; brief ippo irukkura on-road prices kettaanga"), adutha attempt andha note-oda aarambikkum. Idhu serkka selavu kammi, tests pass aaganum maadhiri clear pass illa fail irukkura tasks-ku romba help pannum.

**Sathathoda yosikkura selavu.** Thoughts, plans, critiques ellaam tokens. Prompt-la format-oda examples innum serkkum. Ovvoru addition-oda-um illaama-yum ovvoru task-kum tokens-um neramum alandhu, thanoda selavai eedu kattura alavukku results-a improve panradhu mattum vachukkunga.

## Oru worked example

Bengaluru-la oru venture fund, public sources-la irundhu oru startup-ku one-page brief ready panra oru agent virumbudhu: funding history, founders, product, competitors, red flags.

*Version 1, pure ReAct.* Adhu search pannum, padikkum, thirumba search pannum. Paadhi companies-la funding news-ku 25 steps selavu panni competitors-a eppavum thodamaattaadhu. Briefs samamaa illa.

*Version 2, plan-then-execute.* Oru planning call idha produce pannum:

```text
1. Find the company's website and product description.
2. Find funding rounds (amount, date, lead investor) from news and filings.
3. Identify founders and their backgrounds.
4. List three to five competitors.
5. Look for red flags: lawsuits, layoffs, regulatory action.
6. Write the brief in the template.
```

Ovvoru step-um aindhu tool calls cap-oda oru chinna ReAct loop-a odum. Ippo ovvoru section-um cover aagudhu, steps oru chinna model use pannradhaala average cost moonril onnu kuraiyudhu.

*Version 3, reflection-a serkkradhu.* Analysts funding totals list panna rounds-oda match aagala-nu kandupidikkiraanga. Oru reflection step draft-a oru checklist-ku ethiraa check pannum: totals rounds-oda kooduthalukku saman, ovvoru claim-kum source link, ovvoru section-um nirappi irukku. Code arithmetic-a check pannum; model source illaadha claims-a check pannum. Failures oru revision-ku thirumba pogum. Source illaadha claims, sentences-la 11%-la irundhu 2%-ku kuraiyudhu.

| Version | Cover aana sections | Source illaadha claims | Relative cost |
| --- | --- | --- | --- |
| 1: ReAct mattum | Samamaa illa; competitors aksar missing | Sentences-la 11% | 1.0 |
| 2: Plan-then-execute | Aaru-um | Sumaar 11% | Sumaar 0.67 |
| 3: Plus reflection, oru revision | Aaru-um | 2% | Sumaar 0.75 |

## Podhuvaa panra thappugal

- **Trivial tasks-ku planning.** Rendu-step lookup-ku plan thevai illa; adhu oru call-a mattum serkkum.
- **Eppavum maaraadha plans.** Oru step-oda result plan-oda mothinaa, agent kannai moodi thodaraama thirumba plan pannanum.
- **Mudiyaadha self-critique.** Reflection rounds-a cap pannunga, critique thirumba thirumba adhae sollumbodhu nirutthunga.
- **Code pothum idathula model critique.** Oru rule-aala check panna mudinjaa (sums, schemas, tests), rule-a use pannunga.
- **Plan-a maraikkradhu.** Users-ku plan-a kaattuvadhu nambikkaiya valarkkum, saekkiramaave course-a sari seiya vidum.
- **Yaarum check pannaadha plans.** Check pannaadha plan illaadha tools-a per solalaam illa budget-a odachidalaam.
- **Rewrite panra critics.** Ovvoru item-kum pass illa fail kelunga; rewrite panradhu enna thappu-nu maraichidum.

## Planning-um reflection-um eppo thevai illa

- **Oru illa rendu tool calls irukkura short tasks**: saadhaa ReAct pothum.
- **Tight latency budgets**: ovvoru planning-um critique call-um seconds-a serkkum.
- **Use panna munnaadi oru aal eppavum review panra outputs**, critic konjam thaan serkkum.
- **Check panna mudiyura requirements illaadha tasks**, critic-ku urudhiyaa judge panna onnum illa.

## Demo-la irundhu production-ku

- **Ovvoru plan-aiyum, re-plan-aiyum, critique-aiyum** run trace-la store pannunga.
- **Re-plan rate-aiyum critique failure rate-aiyum item-pada track pannunga**; rendumae prompt fixes-ku vazhi kaattum.
- **Revision rounds-a code-la cap pannunga**, cap-a thotta aprom aal-kitta handover pannunga.
- **Neenda illa selavaana tasks-ku plans-a users-ku kaattunga**, edit illa cancel panna vidunga.
- **Ovvoru pattern-aiyum vachukka munnaadi, adhoda-um illaama-yum ovvoru task-oda cost-a alandhu paarunga.**
