## Idhu enna

Oru agent-a evaluate panradhu-na, adha tasks set-la run panni, enna nadandhadhu-nu score panradhu. Rendu vishayam score aagum:

- **Outcome**: goal achieve aachaa? Refund sariyaa kudukkapattadha, report accurate-aa irundhadha, ticket sariyaana team-ku poyiducha?
- **Trajectory**: eppadi poi serndhadhu? Entha tools, evvalavu steps, edhaavadhu unsafe illa waste-aana actions, thevai irundha idathula approval kettaanga-la?

Agents deterministic illa, neraya steps edukkuraanga, adhanaala **consistency**-yaiyum measure pannuveenga: ovvoru task-aiyum palamurai run panni, evvalavu thadavai success aagudhu-nu paarunga.

```flow
Task | "refund my course, I joined 5 days ago"; seeded sandbox: student 812, payment ₹3,499 -> Agent run 1
Task -> Agent run 2
Task -> Agent run 3
Agent run 1 -> Graders | outcome code-la: student 812-ku ₹3,499 refund-a? trajectory rules-la: refund-ku munnaadi quote, payment-ku munnaadi approval, adhigamaa 10 steps; quality calibrate panna model grader-la
Agent run 2 -> Graders
Agent run 3 -> Graders
Graders -> Metrics | success, 3 runs-lum success, steps, cost, safety violations (0-a irukkanum)
```

Ovvoru run-um pudhu sandbox-la irundhu aarambikkum.

Indha lesson-la Hyderabad-la oru edtech company-oda course-refund agent-a follow pannuvom.

## Idhu eppadi work aagudhu

**Tasks.** 30 la irundhu 100 varaikkum unmaiyaana tasks ezhudhunga, define panna starting state-oda (fake customer account, sandbox database, documents set) theliva oru success condition-oda. Common cases, kashtamaana cases, refuse illa escalate panna vendiya tasks, traps irukkura tasks (error kudukkura tool, kelvi kekka vendiya missing information) ellaam cover pannunga.

**Graders.** Ovvoru check-kum romba reliable-aana, sellavu kammiyaana grader use pannunga:

- End state-la *code checks*: refund row database-la sariyaana amount-oda irukkaa? File create aachaa? Idhu precise-um sellavu kammiyum.
- Trajectory-la *rules*: munnaadi `get_cancellation_quote` call illaama `issue_refund` call illa; 12 steps-ku mela illa; entha payment-kum munnaadi approval keta.
- Open-ended quality-ku (customer reply accurate-aa, polite-aa irundhucha?) *model graders*, rubric-oda, human grades-oda check pannittu.
- Oru sample-ku *human review*, especially aarambathula.

**Metrics.** Success rate; palamurai run panna ella runs-lum success (reliability-a romba kaduminaa measure panradhu); oru task-ku average steps, tokens, cost, time; safety violations (zero-a irukkanum); escalation correctness.

**Environment.** Evals-a task-kum idaiyila reset aagura sandbox-la run pannunga: fake APIs illa seed data-oda test database. Production systems-ku ethiraa evals run pannaadheenga.

**Neraththoda track pannunga.** Ovvoru prompt, tool, model change-kum suite-a run panni, history vechukkunga. Interesting-aana ovvoru production failure-aiyum pudhu task-aa serunga.

**Transcripts-a padinga.** Numbers edho maarirukku-nu kaattum; pathu failed trajectories padicha yen-nu theriyum.

**Metrics-um, adhu enna solludhu-nu:**

| Metric | Definition | Enna solludhu |
| --- | --- | --- |
| Success rate | Success condition-a meet panna runs-oda share | Average capability |
| All-runs success | Ovvoru run-lum success aagura tasks-oda share | Users feel panra reliability |
| Steps, tokens, cost per task | Runs-la average | Efficiency |
| Safety violations | Forbidden actions, missing approvals | Adha nambavae mudiyumaa |
| Escalation correctness | Escalate pannanum-nu irukkum podhu mattum escalate pannadhu | Edge cases-la judgement |

**Sandbox build panradhu.** Tools-a boundary-la fake pannunga: konjam students-um payments-um seed panna test database, oru thadavai fail aagura fake payment API, test script-la irundhu answer panra approval tool. Ovvoru run-kum munnaadi ellathaiyum reset pannunga. Seed data-va repository-la vachikkunga, appo yaarum oru failure-a reproduce pannalaam. Sandbox-la thaan traps-aiyum vaikkalaam, example oru student message-la maraichu vacha instruction, unmaiyaana systems-ku risk illaama.

**Transcripts-a fixes-aa maathradhu.** Oru task fail aana, adhoda trajectory-a padichu fail aana step-a peru sollunga: thappaana tool, thappaana argument, skip panna check, illa mosamaana final reply. Adhukku kaaranamaana tool, description, prompt-a fix pannunga, andha task-a palamurai thirumba run pannunga, apram vera edhuvum odayala-nu paaka muzhu suite-a run pannunga.

**Code-la oru eval harness.** Ovvoru task-um adhoda seed data-vum, success check-aiyum, follow panna vendiya trajectory rules-aiyum kondu varum:

```python
from dataclasses import dataclass, field
from typing import Callable

@dataclass
class Task:
    id: str
    prompt: str
    seed: dict                                   # starting state for the sandbox
    success: Callable[[dict], bool]              # checks the final sandbox state
    rules: list[Callable[[list], str | None]] = field(default_factory=list)

def no_refund_without_quote(trace):
    names = [s["name"] for s in trace if s["type"] == "tool"]
    if "issue_refund" in names and ("get_quote" not in names or names.index("get_quote") > names.index("issue_refund")):
        return "refund issued before a quote"

def at_most(n):
    return lambda trace: f"{len(trace)} steps" if len(trace) > n else None

def run_suite(tasks, run_agent, make_sandbox, k=3):
    results = []
    for t in tasks:
        outcomes = []
        for _ in range(k):
            box = make_sandbox(t.seed)           # fresh state every run
            trace = run_agent(t.prompt, box)
            broken = [msg for rule in t.rules if (msg := rule(trace))]
            outcomes.append({"ok": t.success(box.state) and not broken, "broken": broken,
                             "steps": len(trace)})
        results.append({"task": t.id, "outcomes": outcomes})
    n = len(results)
    any_ok = sum(any(o["ok"] for o in r["outcomes"]) for r in results) / n
    all_ok = sum(all(o["ok"] for o in r["outcomes"]) for r in results) / n
    print(f"pass@{k} {any_ok:.0%}   pass^{k} {all_ok:.0%}")
    return results
```

**Success-a count panna rendu vazhi.** **pass@k** k runs-la edhavadhu onnu success aanaalum task solve aagiduchu-nu eduthukkum; agent-aala *enna mudiyum*-nu measure pannum. **pass^k** ella k runs-lum success aanaa mattum eduthukkum; users *nambi irukka mudiyura*-dhai measure pannum. Oru run-ku 90% irukkura agent-ku, runs independent-aa irundhaa pass^3 sumaar 73%. Customer-service tasks-ku agent benchmarks pass^k-a report pannuradhu idhae kaaranathukku thaan.

**Model graders-a calibrate pannunga.** Open-ended checks-ku (reply accurate-aavum polite-aavum irundhucha?), 50 transcripts-a kaiyaala grade pannunga, adhey 50-la model grader-a run pannunga, agreement-a count pannunga. Sumaar 85% cases-ku kammiyaa orumichaa, rubric-a improve pannunga illa andha check-a human-kitta vachukkunga. Grader-oda prompt illa model maarum podhellaam thirumba check pannunga.

**Oru task-ku cost-um neramum.** Ovvoru run-kum success-oda sernthu tokens, cost, wall-clock time-aiyum record pannunga. Success-a 3 points yethi cost-a rendu madangaakkura change-a vaanga vendiyadhu illa; success-a vachi cost-a paadhiyaakkura change-a vaangalaam.

**Production-la irundhu suite-a valarunga.** Ovvoru vaaramum, traces-la irukkura unmaiyaana failures-la irundhu illa vidhyaasamaana requests-la irundhu rendu moonu tasks-a serunga, customer-oda details-a seed data-vaala maathittu.

## Oru worked example

Hyderabad-la oru ed-tech company-ku course-refund requests-a handle panra oru agent irukku: enrolment-a check pannudhu, refund policy-a apply pannudhu, ₹5,000-ku kammiyaana refunds-a approval-ku aprom kudukkudhu, meedhiya escalate pannudhu.

Eval suite-la, seed panna students-um payments-um irukkura sandbox-la 60 tasks:

- 30 routine refunds (success aaganum),
- 10 policy window-ku veliya (nayamaa decline pannanum),
- 10 ₹5,000-ku mela (escalate pannanum),
- 5 payment API oru thadavai error kudukkura (retry pannanum, apram escalate pannanum),
- 5 student-oda message-la prompt injection irukkura (ignore pannanum).

Graders: refunds table-la code checks; trajectory rules (refund-ku munnaadi quote, payment-ku munnaadi approval, adhigamaa 10 steps); reply tone-ku oru model grader, human grade panna 40 replies-la calibrate pannadhu (88% agreement).

Ovvoru task-um moonu thadavai run aagum. Baseline: 82% success, moonu runs-lum 71% success, oru safety violation (approval tool timeout aanapo approval illaama refund kudukkapattadhu). Fix: timeout-a "approve aagala"-nu eduthukkradhu. Changes-ku aprom suite 93% success, moonu runs-lum 88%, violations zero-nu kaattudhu. Adhey suite ippo ovvoru change-kum CI-la run aagudhu.

| Measure | Baseline | Fixes-ku aprom |
| --- | --- | --- |
| Success | 82% | 93% |
| Moonu runs-lum success | 71% | 88% |
| Safety violations | 1: timeout-ku aprom approval illaama refund | 0: timeout ippo approve aagala-nu count aagudhu |

## Podhuvaa panra thappugal

- **Final message mattum score panradhu.** Agent vazhiyila edhaavadhu unsafe-aa pannirukkalaam.
- **Oru task-ku oru run mattum.** Agents maaruvaanga; consistency-a measure pannunga.
- **Unmaiyaana systems-ku ethiraa evals.** Reset panna mudiyura sandbox use pannunga.
- **Happy paths mattum.** Refusals, escalations, tool failures, injection attempts-aiyum serunga.
- **Transcripts-a padikkaama irukkradhu.** Fail aachu-nu scores solludhu, yen-nu solladhu.
- **Oru task-ku oru run-a report panradhu.** Palamurai run panni pass@k-yum pass^k-yum report pannunga.
- **Yaarum check pannaadha model grader-a nambradhu**, human grades-oda ottippaakkaama.
- **Runs-kku idaiyila shared sandbox.** Oru run-la meedhi irukkura state, adutha run-a thaanaagavae pass illa fail aakkidum.

## Edhu lighter evaluation podhum

- **Konjam tools-oda read-only agents**: expected answers irukkura kelvigal set-um step limit check-um podhumaa irukkalaam.
- **Aarambathula prototypes**: kaiyaala padicha pathu tasks, neenga thirumba thirumba ezhudhura harness-a vida adhigam solludhu.
- **Fixed workflows**: ovvoru step-aiyum saadharana code maadhiri test pannunga, koodavae sila end-to-end cases.

Agents unmaiyaana systems-la act pannum podhu illa neraya users avangala nambum podhu, sandboxes, trajectory rules, repeated runs-la invest pannunga.

## Demo-la irundhu production-ku

- **Ovvoru prompt, tool, model change-kum suite-a run pannunga**, history vechukkunga.
- **Releases-a safety violations-ku (zero allowed), critical tasks-ku pass^k-ku gate pannunga.**
- **Seed data-vum sandboxes-um repository-la vachukkunga**, appo yaarum oru failure-a reproduce pannalaam.
- **Model graders-a** ovvoru quarter-um pudhu human grades-oda **thirumba calibrate pannunga.**
- **Production failures-a** ovvoru vaaramum pudhu tasks-aa **serunga.**
