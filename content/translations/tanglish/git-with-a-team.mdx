## Idhu enna

Git oru codebase-la nadakkura ovvoru change-aiyum record pannum. Thaniyaa irukkum podhu, neenga perumbaalum commit panni push pannuveenga. Team-la, **main** branch shared, eppavum work aaganum, yen-na vera makkal, perumbaalum oru live product, adha nambi irukkaanga. Adhanaala teams oru routine follow pannuvaanga:

```flow
dir: LR
main | always works -> Your branch | small commits
Your branch -[push]-> Pull request | review and automated checks
Pull request -> Teammates comment, you fix -> Pull request
Pull request -[merge]-> main, updated
```

1. Oru velaikku oru **branch** uruvaakkunga.
2. Thelivaana messages-oda sinna **commits** pannunga.
3. Push panni oru **pull request** (PR) open pannunga.
4. Teammates **review** pannuvaanga; automated checks odum.
5. Avanga flag pannadha fix panni, apram **merge** pannunga.

Rendu per ore lines-a maathumpodhu, Git **merge conflict** raise pannum, oru aal result-a mudivu pannuvaanga.

Indha lesson-la Mumbai-la oru brokerage-ku oru project-la moonu vaaram aana ungala follow pannuvom, neenga oru market-data client-la retries serkkureenga, review aagureenga, oru teammate-oda change-oda conflict-a resolve pannureenga. Mudiyum podhu ovvoru step-layum comfortable-aa irupeenga.

## Idhu eppadi work aagudhu

### Branches

Branches oru commit-a suttikkaattura selavu illaadha labels. `git switch -c fix/gst-rounding` onnu uruvaakki ungala adhuku konduvarum. Branches-a avatha enna pannudhu-nu peyar vainga:

| Prefix | Edhukku | Example |
| --- | --- | --- |
| `feat/` | Pudhu feature | `feat/retry-market-data` |
| `fix/` | Bug fix | `fix/gst-rounding` |
| `docs/` | Documentation | `docs/setup-guide` |
| `chore/` | Tooling, dependencies | `chore/update-pandas` |

Mudhal branch-ku munnaadi client-oda naming convention-a check pannunga.

### Commits

Ovvoru commit-um oru vishayam seiyanum, yen-nu sollanum:

| Weak | Strong |
| --- | --- |
| "fix" | "Fix GST rounding to two decimals for invoices over ₹1 lakh" |
| "wip" | "Add retry wrapper for market data client (no callers yet)" |
| "changes" | "MD-214: retry market data calls with backoff on 429 and 503" |

Neraya teams messages-ku munnaadi ticket id serppaanga. Aaru maadham kazhichu, thelivaana history thaan ungala serthu yaaraavadhu code yen ippadi irukku-nu purinjukka vazhi.

### Pull requests

Oru PR reviewer-ku thevaiyaana context-a eduthukittu pogum:

- Enna **maathuchu**, **yen**.
- Neenga **eppadi test pannineenga**.
- **Edhavadhu risky**: performance, security, behaviour changes.
- Ticket-ku link, kaanra edhukkum screenshots.

PRs-a sinnadhaa vainga. 200-line PR kavanamaa review aagum; 3,000-line PR rubber stamp vaangi bugs-a olikkum.

### Review rendu pakkamum

**Review panrappo**, style-a vida mudhalla behaviour-aiyum risk-aiyum paarunga: sariyaana vishayam seiyudhaa, enna udayalaam, test pannirukkaanga-laa? **Review aagumbodhu**, ovvoru comment-kkum badhil sollunga, code-a maathi illa yen maathala-nu explain panni, personal-aa edukkaadheenga. Review code pathi, ungala pathi illa.

### Current-aa irukkradhu, conflicts-a resolve panradhu

Unga PR kaathirukkum podhu, main nagarndhukkitte pogum. Pudhu main-a unga branch-la `git merge main` vechu konduvaanga, team rebase virumbinaa `git rebase main`. Rendu pakkamum ore lines maathirundhaa, Git file-la conflict-a mark pannum:

```text
<<<<<<< HEAD
TAX_RATE = 0.18
=======
TAX_RATE = Decimal("0.18")
>>>>>>> main
```

Mela irukkuradhu unga branch; keezha irukkuradhu main. (Rebase-la pakkangal maaridum: HEAD main, keezha irukkuradhu unga commit.) File-a sariyaana **final** version-ku edit pannunga, adhu perumbaalum rendaiyum serthadhaa irukkum, markers-a neekkunga, tests odunga, apram `git add` panni commit pannunga.

### Protected branches, history

Clients perumbaalum main-a **protect** pannuvaanga: neradi push illa, review-um passing checks-um thevai. Idhai orupodhum suththi pogaadheenga. Matroruvar use panra branch-a orupodhum **force-push** pannaadheenga: adhu avanga kaalukku keezha history-a rewrite pannum, avanga velaiya izhakkalaam.

### Secrets

Git-la commit panna API key, file-a delete pannina appuramum history-la irukkum. Secrets-a environment variables-la vainga, secret files-a `.gitignore`-la list pannunga, oru key leak aanaa udanae **rotate pannunga**, apram clean pannunga.

## Oru worked example

Mumbai-la oru brokerage-oda project-la moonu vaaram aagudhu. Unga ticket, MD-214: market-data client-la retries serkkanum, adhu market open-la sila samayam rate-limit aagudhu.

```text
git switch main && git pull
git switch -c feat/retry-market-data
# edit, test
git add src/marketdata/client.py tests/test_client.py
git commit -m "MD-214: retry market data calls with backoff on 429 and 503"
git push -u origin feat/retry-market-data
```

**PR.** Unga description enna maathuchu-nu sollum, rendu thadavai 429 tharura fake server-oda test pannineenga-nu sollum, oru risk-a flag pannum: worst case-la retries 7 seconds varaikkum serkkum, dashboard 10 seconds-la time out aagudhu.

**Review.** Reviewer Farhan, total retry time-a 3 seconds-la cap pannunga-nu kekkuraanga. Neenga maathi, cap-ku oru test serthu, "Done, capped at 3s total, test added"-nu badhil sollitu, push pannureenga.

**Conflict.** Idhukkulla Priya adhe client-la oru configurable timeout serkkura change-a merge pannitaanga. Unga branch ippo conflict aagudhu. Neenga main-a merge panni, rendu pakkaththaiyum padichu, avanga pudhu timeout setting-aiyum unga retry wrapper-aiyum **rendaiyum** vechukittu, tests odi, push pannureenga.

| Step | Command illa action | Result |
| --- | --- | --- |
| Aarambam | `git switch -c feat/retry-market-data` | Ungaloda sondha branch |
| Velaiya save panna | `git commit -m "MD-214: ..."` | Oru thelivaana commit |
| Share panna | `git push -u origin ...` panni PR open pannunga | Review-um checks-um aarambikkum |
| Review fix | Retries-a 3 s-la cap panra pudhu commit | Farhan-oda comment resolve |
| Conflict | `git merge main`, edit, test, commit | Rendu changes-um irukku |
| Mudikka | Checks green, approval, merge, branch delete | Main-la unga feature irukku |

Checks green aagudhu, Farhan approve pannuraanga, neenga merge panni branch-a delete pannureenga.

## Podhuvaa panra thappugal

- **Perisaana pull requests.** Velaiya pirichukkunga; neelamaana diffs-la reviewers bugs-a miss pannuvaanga.
- **"wip", "changes" maadhiri commit messages.** Appuram yaarukkum yen-nu theriyaadhu.
- **Secrets-a commit panradhu.** Environment variables, `.gitignore` use pannunga; leak aana key-a udanae rotate pannunga.
- **Conflicts-a kannai moodikkittu resolve panradhu.** Ovvoru conflict-kum "mine"-a accept pannaa, teammate-oda fix poidum. Rendu pakkaththaiyum padinga.
- **Shared branches-a force-push panradhu.** Yaarum use pannaadha branches-la mattum history-a rewrite pannunga.
- **Oru branch-a vaara kanakkula stale-aa vidradhu.** Conflicts sinnadhaa irukka main-a adikkadi merge pannunga.

## Practice pannunga

Keezha link panni irukkura GitHub flow-vum, Pro Git-la basic branching, merging chapter-aiyum padinga.

1. **Oru unmaiyaana PR.** Ungaloda sondha repository-la, oru branch, rendu sinna commits, sariyaana description-oda oru pull request uruvaakkunga.
2. **Oru conflict.** Venumnae onnu uruvaakkunga: main-lum unga branch-lum ore line-a maathunga, apram merge panni resolve pannunga.
3. **Review.** Oru friend-oda PR-a, illa open-source onna review pannunga, rendu useful comments vainga.

**Mudinjadhu-nu eppo sollalaam:** Bayam illaama oru merge conflict-a resolve panna mudiyum, oru stranger review panna mudiyura PR description ezhudha mudiyum.
