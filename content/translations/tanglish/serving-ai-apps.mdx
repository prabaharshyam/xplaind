## Idhu enna

Serve panradhu-na unga application-a real users nambura maadhiri odavaikkradhu. Adhu thaanaa start aagum, crash aanaa restart aagum, orey neraththula neraya requests-a kaiyaalum, model mella irundhaalum vegamaa edhaavadhu kaattum.

Oru Python AI service-ku, usual stack app-ku FastAPI-um, adha odavaikkura server-aa **Uvicorn**-um, parallelism-ku neraya worker processes-um. Munnaadi load balancer, ingress, illa Cloud Run maadhiri platform, HTTPS-a kaiyaala, traffic-a pirikka.

AI services-ku rendu special gunangal. Requests mella irukkum, pala neram 2 mudhal 30 seconds, yen-naa model calls-ku kaathirukkum. Users adha progress paartha mattum thaan poruththukkuvaanga, adhanaala thaan **streaming** mukkiyam.

```flow
Users -[HTTPS]-> Load balancer | timeout 30 s, checks /ready
Load balancer -> Container 1 | 4 workers, Uvicorn + FastAPI
Load balancer -> Container 2 | 4 workers
Container 1 -> Model API | timeout 25 s, tokens streamed to the user
Container 1 -> Background queue | OCR, indexing; a job id and status
```

Indha lesson-la Lucknow-la oru edtech company-oda doubt-solving assistant-a follow pannuvom, adhu ovvoru saayangaalamum uuruvadhu pola mella aagum.

## Idhu eppadi work aagudhu

**Workers-um concurrency-yum.** Async endpoints-oda oru Uvicorn process, network-ku kaathirukkura neraya requests-a pidichukkum. PDF parse panradhu, local embedding model odradhu maadhiri CPU-heavy velai andha process-a block pannum. Adhanaala neraya workers odunga, perumbaalum oru CPU core-ku onnu illa rendu, illa heavy velaiya background queue-ku nagarthunga.

**Ellaa idathulayum timeouts.** Ovvoru model, tool call-layum, request muzhusaa-layum, load balancer-layum timeout set pannunga, ulle irukkuradhu veliya irukkuradha vida chinnadhaa irukkanum. Thongarathukku badhila theliva 503 illa 504-a thirumbi kudunga.

**Streaming.** `StreamingResponse`-um server-sent events-um vachu, model tokens-a produce panra maadhiri client-ku forward pannalaam. Mudhal token varra neram, muzhu generation neraththula irundhu oru second-kku romba kezhe varum. Client disconnect-a kaiyaalunga, appo yaarum padikkaadha tokens-ku kaasu kudukka maatteenga.

**Health checks.** Sutthamaana `/health` endpoint (process up) -um `/ready` endpoint-um (database maadhiri dependencies reach aagudhu) platform-a udanja instances-a restart pannavum, ready-aa irukkuravatrukku mattum traffic anuppavum vidum. Health check-la model-a koopudaadheenga.

**Graceful shutdown.** Deploy-kaaga platform oru instance-a nirutthum podhu, pudhu requests-a edukkradha nirutthi, nadandhukkittu irukkuravatra oru grace period-kulla mudikka viddanum. Neelamaana streaming responses-ku, unga usual generation-a vida neelamaana grace period thevai.

**Background velai.** 500-page PDF-a index panradhu maadhiri nimishangal edukkura jobs, oru request-kulla varaadhu. Job-a eduthukkittu, udane oru id-a thirumbi kuduthu, oru worker queue-la process pannunga, client poll pannalaam illa webhook varalaam.

**Oru streaming endpoint:**

```python
from fastapi import FastAPI, Request
from fastapi.responses import StreamingResponse

app = FastAPI()

# Question is your Pydantic request model; model_stream is your async model client.
@app.post("/answer")
async def answer(req: Request, body: Question):
    async def tokens():
        async for text in model_stream(body.text, timeout=25):
            if await req.is_disconnected():
                break                     # stop paying for unread tokens
            yield f"data: {text}\n\n"
    return StreamingResponse(tokens(), media_type="text/event-stream")
```

**Munnaadiyum pinnaadiyum alakkradhu.** Ovvoru request-kum moonu numbers record pannunga: mudhal token varra neram, mothama neram, timeout aanadha. Average illa, 95th percentile-a paarunga, yen-naa romba mella irukkura requests thaan users puhar panradhu. Launch-ku munnaadi, edhir paarkkura saayangaala peak-la Locust maadhiri tool-oda load-test pannunga, ovvoru maatraththukkum aprom thirumbavum.

**Oru nijamaana streaming endpoint.** Model-la irundhu tokens-a server-sent events-aa, oru timeout-oda, oru concurrency cap-oda, disconnect handling-oda forward pannunga:

```python
import asyncio, json
import anthropic
from fastapi import FastAPI, Request, HTTPException
from fastapi.responses import StreamingResponse
from pydantic import BaseModel

app = FastAPI()
client = anthropic.AsyncAnthropic(timeout=30, max_retries=2)
SLOTS = asyncio.Semaphore(50)                     # at most 50 model calls at once per process

class Question(BaseModel):
    text: str

@app.post("/answer")
async def answer(req: Request, body: Question):
    if SLOTS.locked():
        raise HTTPException(status_code=429, detail="Busy, please retry in a few seconds")
    async def events():
        async with SLOTS:
            try:
                async with client.messages.stream(
                        model="claude-sonnet-5-5", max_tokens=600,         # check the docs for current names
                        messages=[{"role": "user", "content": body.text}]) as stream:
                    async for text in stream.text_stream:
                        if await req.is_disconnected():
                            return                                         # stop paying for unread tokens
                        yield f"data: {json.dumps({'text': text})}\n\n"
                yield "data: [DONE]\n\n"
            except anthropic.APIError:
                yield f"data: {json.dumps({'error': 'The AI service is unavailable. Please try again.'})}\n\n"
    return StreamingResponse(events(), media_type="text/event-stream")

@app.get("/health")
async def health():
    return {"ok": True}
```

Ovvoru chunk-aiyum JSON-aa encode panna, text-kulla irukkura newlines event format-a udaikkaadhu. `async with`-a vittu veliya vandhaa stream close aagum, adhu user disconnect aanaa generation-a nirutthum.

**Odavaikkradhu.** Neraya worker processes, neelamaana stream-a vida neelamaana graceful timeout:

```bash
gunicorn app.main:app -k uvicorn.workers.UvicornWorker --workers 4 \
  --bind 0.0.0.0:8000 --timeout 120 --graceful-timeout 90
```

**Queue-oda background jobs.** Neelamaana velai oru worker-ku pogum; request udane oru job id-a thirumbum. Redis Queue-oda:

```python
from redis import Redis
from rq import Queue

queue = Queue("ingest", connection=Redis.from_url("redis://redis:6379"))

@app.post("/documents")
async def upload(doc_id: str):
    job = queue.enqueue("workers.index_pdf", doc_id, job_timeout=1800, retry=None)
    return {"job_id": job.id, "status_url": f"/jobs/{job.id}"}

@app.get("/jobs/{job_id}")
async def job_status(job_id: str):
    job = queue.fetch_job(job_id)
    return {"status": job.get_status() if job else "unknown"}
```

Celery, Arq, cloud task queues-um adhe pattern-a thaan follow pannum.

**Unmaiya sollura readiness.** `/ready` database-aiyum vector store-aiyum oru vegamaana query-yum chinna timeout-yum vechu check pannanum, models illa indexes load aagura varaikkum start-up-la 503 thirumbi kudukkanum. Appo platform nijamaave badhil solla mudiyura instances-ku mattum traffic anuppum.

**Unga browser-la try pannunga.** Concurrency cap yen mukkiyam-nu paarunga: adhai thaandi varra requests kaathirukkum. Numbers-a maathi odunga.

```python
import asyncio, random, time

async def model_call(i, slots):
    async with slots:
        await asyncio.sleep(random.uniform(0.05, 0.15))     # pretend model latency
        return i

async def main(cap, n=40):
    slots = asyncio.Semaphore(cap)
    t0 = time.perf_counter()
    await asyncio.gather(*(model_call(i, slots) for i in range(n)))
    print(f"cap {cap:>2}: {n} requests in {time.perf_counter() - t0:.2f} s")

random.seed(0)
for cap in (2, 10, 40):
    await main(cap)
```

## Oru worked example

Lucknow edtech-oda doubt-solving assistant oru Uvicorn process-aa odichu. Saayangaala padikkura neraththula, students-ku edhaavadhu text varra munnaadi 12 seconds aachu. Moondril oru pangu requests load balancer-oda 30-second limit-la timeout aachu, kaiyezhuththu notes-a OCR-ku upload panradhu ellaarukkum server-a freeze pannuchu.

Maatrangal:

- Answers stream aagum: mudhal vaarthaigal sumaar 700 milliseconds-la therium.
- Ovvoru container-kum naalu Uvicorn workers, rendu containers, load balancer-kku pinnaadi.
- Timeouts: model call 25 s, request 28 s, load balancer 30 s. Timeout aanaa, app blank error-ku badhila "Idhu vazhakkatha vida neram edukkudhu; thirumba try pannunga"-nu anuppum.
- OCR oru background queue-ku poyichu. Upload oru job id-a thirumbum; page "Unga notes-a padikkaren..."-nu kaattum, ready aanadhum result-a eduthukkum.
- `/ready` database-aiyum queue-vaiyum check pannum; udanja container 20 seconds-kulla traffic edukkradha nirutthum.

Saayangaala peak-la timeouts 33%-la irundhu 1%-kku kezhe vizhundhuchu, answer paakkaama vittu pona students ennikkai rendu paththil moonu pangu kuraindhadhu.

| Saayangaala peak-la alavu | Munnaadi | Aprom |
| --- | --- | --- |
| Mudhal text varra neram | Sumaar 12 s | Sumaar 0.7 s |
| Timeout aana requests | 33% | 1%-kku kezhe |
| OCR uploads-aala server freezes | Dhinam | Illa |
| Answer-ku munnaadi poiduravanga | Baseline | Rendu paththil moonu pangu kuraivu |

## Podhuvaa panra thappugal

- **Production-la oru worker.** Oru block aana request ellaarayum nirutthum. Neraya odunga, alandhu paarunga.
- **Timeouts illaama.** Oru thongura model call oru worker-a ennaikkum pidichu vechukkum.
- **Muzhu answer-kku kaathirukkradhu.** Streaming illaina, users spinner-a paathu poiduvaanga.
- **Model-a koopura health checks.** Adhu kaasu selavu, provider mella irukkum podhu fail aagi, healthy instances-a veliya edukkum.
- **Requests-kulla neelamaana jobs.** Konjam seconds-ku mela CPU edukkura edhukkum queue use pannunga.
- **Launch-ku munnaadi load test illaama.** Mudhal saayangaala peak thaan service-oda mudhal real traffic-a irukkakoodaadhu.
- **Orey neraththula model calls-ku cap illaama**, adhanaala oru burst provider rate limits-a adichu, ovvoru request-um mella aagum.
- **SSE events-la raw text**, answer-kulla oru newline stream-a udaikkum.
- **Process uyiroda irukku-nu mattum solra ready checks.**

## Simple-aa serve panna podhumaana idangal

- **Konjam users-oda internal tools**: oru process, timeouts, oru health check podhum.
- **Users-a ethir kollaadha batch jobs**: oru web service-a vida scheduled script nalladhu.
- **Platform-hosted functions**, serverless routes maadhiri, platform workers-aiyum shutdown-aiyum paarthukkum.

## Demo-la irundhu production-ku

- Oru process-ku **concurrency-a cap pannunga**, theliva 429-oda load-a shed pannunga.
- Ulle-la irundhu veliya varaikkum **timeouts set pannunga**: model call, request, load balancer.
- **Disconnect handling-oda stream pannunga**, graceful shutdown-a neelamaana stream-a vida neelamaa vainga.
- Job ids-um status-um irukkura queue-ku **neelamaana velaiya nagarthunga**.
- p95-la **mudhal token neram, mothama neram, timeouts-a track pannunga**.
