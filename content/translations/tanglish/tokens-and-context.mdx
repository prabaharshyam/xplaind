## Idhu enna

Language models **tokens**-a padikkum, ezhudhum, chinna text thundugal: perumbaalum oru muzhu podhuvaana vaarthai, sila neram vaarthaiyoda oru paagam, oru number, oru punctuation mark. Models-a use panra ellaa vishayamum tokens-la alakkapadum:

- **Price**: providers ovvoru million input tokens-kum, ovvoru million output tokens-kum charge pannuvaanga; output tokens perumbaalum pala madangu adhigam cost.
- **Limits**: **context window**-na oru call-la maximum tokens, anuppina ellaathaiyum reply-yum serthu count pannum.
- **Speed**: adhigam output tokens generate aaga adhigam neram edukkum.

| Oru API call-oda context window-oda paagam | Tokens | Note |
|---|---|---|
| System prompt | 1,200 | Ovvoru call-layum orey maadhiri |
| Conversation history | 3,000 | Ovvoru turn-layum valarum |
| Retrieved passages | 800 | |
| Pudhu user message | 150 | Tamil text adhigam tokens use pannum |
| Reply, max_tokens varaikkum | 300 | |

Ovvoru call-layum ellaam count aagum, input muzhukkavum paṇam kattanum.

```flow
dir: LR
title: Oru call, aarambam-la irundhu mudivu varaikkum
System prompt + history + passages + pudhu message -[input tokens, ovvoru call-kum panam]-> Model
Model -[output tokens, max_tokens varaikkum]-> Reply
```

Indha lesson Chennai-la oru e-learning company, Tamil-layum English-layum doubt-solving chatbot build panradhai follow pannum.

## Idhu eppadi work aagudhu

**Token-na enna.** Oru tokenizer text-a oru fixed vocabulary-la irundhu thundugala pirikkum. English-la 100 tokens kittathatta 75 vaarthaigal. Hindi, Tamil, matha Indian scripts-ku adhey artham-ku perumbaalum adhigam tokens thevai, adhanaala adhey message-ku adhigam cost aagalaam, window-la adhigam edam edukkalaam. Numbers-um code-um kooda neraya tokens-aa pirium.

**Counting.** Provider dashboards-um replies-um ovvoru call-oda token usage-a report pannum, anuppradhukku munnaadi count panna providers token-counting endpoints illa libraries-um tharuvaanga.

**Context window-a edhu nirappum.** Oru chat app-la, ovvoru call-layum anuppappadura ellaamum count aagum:

- system prompt;
- ippo varaikkum muzhu conversation (API-ku memory illa; neenga thirumba anuppuveenga);
- edhaavadhu documents illa retrieved passages;
- tool definitions-um tool results-um;
- apram `max_tokens` varaikkum reply.

Conversation valara valara, ovvoru turn-um adhigam history-a thirumba anuppum, adhanaala ovvoru turn-oda cost-um ethum.

**Cost-a estimate panradhu.** Cost = input tokens × input price + output tokens × output price. Udhaaranam: 2,000 input tokens-um 500 output tokens-um, ovvoru token-ku output, input-oda aindhu madangu price. Input 2,000 units-aa count aagum; output 500 × 5 = 2,500 units. Output naalil oru paagam neelam thaan, aanaalum adhigam cost.

**Window-kulla irukkradhu.** Pazhaya conversation turns-a trim illa summarise pannunga; muzhu documents-ku badhila relevant passages mattum retrieve pannunga; oru podhumaana `max_tokens` set pannunga; romba periya inputs-a warning-oda truncate pannunga. Romba neenda contexts, nadula pudhaindha details-ku answer quality-a kuraikka-um seiyum.

**Caching.** Neraya calls orey maadhiri irukkura neenda aarambathai (periya system prompt illa oru document) share pannaa, prompt caching thirumba varra input-a romba cheap-aa, vegamaa aakkum. Oru adutha lesson-la idha paapeenga.

**Conversation neelam valara cost eppadi valarudhu** (1,200-token system prompt, 100-token questions, 250-token answers, history thirumba anuppappadum):

| Turn | Anuppina input tokens | Adhula history |
| --- | --- | --- |
| 1 | 1,300 | 0 |
| 3 | 2,000 | 700 |
| 6 | 3,050 | 1,750 |
| 10 | 4,450 | 3,150 |

Turn 10-kulla, neenga kattura panathula perumbaalaanadhu history. Pazhaya turns-a oru chinna paragraph-aa summarise pannaa input kittathatta oru maadhiri irukkum, system prompt-a cache pannaa, mudhal call-ku apram ovvoru call-layum adhoda 1,200 tokens romba cheap-aa irukkum.

**Anuppradhukku munnaadi count pannunga.** Oru user paste panna mudiyura edhuvaa irundhaalum, oru document illa neenda message maadhiri, model-a call pannradhukku munnaadi tokens-a count pannunga. Romba neelamaa irundhaa, relevant paagathai mattum retrieve pannunga, mudhalla summarise pannunga, illa user-kitta adhu romba neelam-nu theliva sollunga. Sathamilaama cut-off aagradhu illa edhirpaaradha bill-a vida, clear message-oda fail aagradhu romba nalladhu.

**Code-la tokens-a count pannunga.** User periyadhaakka mudiyura edhaiyum anuppradhukku munnaadi count pannunga. Anthropic-oda SDK-la, model use panna pora adhe tokenizer-a count use pannum:

```python
import anthropic

client = anthropic.Anthropic()
MODEL = "claude-sonnet-5-5"                  # check the docs for current names

def count(system, messages):
    return client.messages.count_tokens(model=MODEL, system=system, messages=messages).input_tokens

english = [{"role": "user", "content": "Please send the electricity bill for October."}]
hindi = [{"role": "user", "content": "कृपया अक्टूबर का बिजली का बिल भेजें।"}]
print(count("Be brief.", english), count("Be brief.", hindi))   # the Hindi line usually costs more
```

Open models-ku, Hugging Face-la irundhu model-oda sondha tokenizer-um (`AutoTokenizer.from_pretrained(...)`) offline-la exact counts kudukkum. "Ovvoru token-ku 4 characters" maadhiri rough rules English-ku mattum thaan work aagum.

**Oru context budget.** Window-a eppadi pirichukkum-nu munnaadiye decide pannunga, appo oru paagam matha-vatrai nerukka mudiyaadhu:

| Paagam | Budget (example, 16,000-token target) | Budget thaandinaa |
| --- | --- | --- |
| System prompt, tools | 2,000 | Surukkunga; adikkadi use aagaadha rules-a retrieval-ku nagathunga |
| Conversation history | 4,000 | Pazhaya turns-a summarise pannunga |
| Retrieved passages | 6,000 | Kammiyaana, nalla chunks |
| Tool results | 2,000 | Thevaiyaana fields mattum return pannunga |
| Reply (`max_tokens`) | 2,000 | Surukkamaana answers kelunga |

Target perumbaalum model-oda maximum-a vida romba kammiyaa irukkum, yen-na ovvoru token-kum cost-um delay-um valarum, limit-ku munnaadiye quality-um kuraiyum.

**History-a budget-kulla vechchirukkradhu.** Latest turns-a vaarthai vaarthaiyaa vechchirukkunga, pazhaya-vatrai oru odikkitte irukkura summary-kulla madiyunga:

```python
def fit_history(history, summary, budget_tokens, count_fn, keep_last=6):
    """history: list of {"role", "content"} turns, oldest first."""
    recent = history[-keep_last:]
    older = history[:-keep_last]
    if older:
        summary = summarise(summary, older)       # one cheap model call, done rarely
    prefix = [{"role": "user", "content": f"Summary of the earlier conversation: {summary}"},
              {"role": "assistant", "content": "Understood."}] if summary else []
    msgs = prefix + recent
    while count_fn(msgs) > budget_tokens and len(recent) > 2:
        recent = recent[2:]                       # drop the oldest user-assistant pair
        msgs = prefix + recent
    return msgs, summary
```

`summarise` unga sondha function: pazhaya summary-yum madikkira turns-aiyum serkkura oru chinna model call. History budget-a thaandum podhu mattum summarise pannunga, ovvoru turn-layum illa.

**Neenda context-la attention free illa.** Models neenda input-oda ovvoru paagathaiyum orey alavu nallaa use pannaadhu. Neenda document-la oru fact-a olichu vekkura tests (perumbaalum "needle in a haystack"-nu solluvaanga), nadula irukkura facts aarambathula, mudivula irukkuradha vida kuraivaa nambikkaiyaa kandupidikkapaduvadhaa kaattum. Mukkiyamaana instructions-a aarambathula, kelvi-a mudivula vechchirukkunga, retrieved passages-a relevance padi order pannunga.

**Maximum-um effective context-um.** Oru model 200,000 tokens illa adhukku mela edhukkalaam, aanaa avatrai evvalavu nallaa use pannudhu-nu task-ku task maarum. Unga case-a test pannunga: oru realistic document-la theriyura oru fact-a vera vera idangalla olichu vechchu, answers sariyaa irukkaanu paarunga.

## Oru worked example

Chennai-la oru e-learning company Class 10 students-ku Tamil-layum English-layum doubt-solving chatbot build pannudhu.

Oru vaara testing-la irundhu alavugal:

- Syllabus guidance-oda system prompt: 1,200 tokens.
- Oru saadharana question: English-la 60 tokens, Tamil-la sumaar 150.
- Oru saadharana answer: 250 tokens.
- Paththu turns-ku apram, history ovvoru call-kum sumaar 3,000 tokens serkkum.

Avanga model-oda prices-la, paththu-turn chat rendu-turn chat-a vida sumaar naalu madangu cost aachu, perumbaalum thirumba anuppappatta history-aala. Moonu vishayam maathinaanga: aaru turns-ku apram history-a summarise pannaanga, system prompt-a cache pannaanga, answers-a 300 tokens-ku cap pannaanga. Oru conversation-ku average cost 55% kuraiyudhu, neenda sessions-la Tamil users app-oda per-call input cap-a ippo thodardhu thottarathu illa.

**Tamil users yen mudhalla limit-a thottaanga.** Adhey kelvi English-la irundhadhai vida Tamil-la sumaar rendarai madangu tokens edutthudhu, Tamil answers-um tokens-la neelamaa irundhadhu. Cost-a control panna team ovvoru call-kum 16,000 input tokens-ku cap vechchaanga. Neenda revision sessions-la, Tamil conversations sumaar 30 turns-ku apram andha cap-a thottadhu, English-la arudhaa thaan. Aaru turns-ku apram history-a summarise pannadhu rendukkum idha sari pannichu, bot vegamaa badhil solla-um vechchudhu, yen-na surukkamaana inputs vegamaa process aagum. Team ippo ovvoru prompt maatraththaiyum Tamil, English conversations rendulayum test pannum, ovvoru language-kum conversation-ku cost-a thaniyaa report pannum, adhanaala English-la cheap-aa irundhu Tamil-la expensive-aa irukkura maatram ship aagradhukku munnaadiye pidikkapadum.

## Podhuvaa panra thappugal

- **Tokens-ku badhila vaarthaigala count panradhu.** Prices-um limits-um tokens-la, Indian languages adhigam use pannum.
- **History thirumba anuppappadum-nu marakkradhu.** Neenda chats cost-aa aagum.
- **Output price-a ignore panradhu.** Output tokens perumbaalum adhigam cost.
- **`max_tokens` illaama irukkradhu.** Replies neelamaa, cost-aa irukkalaam.
- **Muzhu documents-a thinikkradhu.** Relevant-a retrieve pannunga.

- **Periya context window ellaathaiyum sari pannum-nu ninaikkradhu.** Romba neenda inputs-ku adhigam cost, mella, nadula irukkura details-a adikkadi miss pannum. Relevant-a anuppunga, ungakitta irukkura ellaathaiyum illa.
- **Indian-language tokens-a English rules-la estimate panradhu.** Unmaiyaana tokenizer-oda count pannunga.
- **Window irukkunu adhai nirappradhu.** Ovvoru extra token-um cost-aiyum delay-aiyum serkkum, accuracy-a kuraikkalaam.

## Context-a kavanamaa paarkka thevai illaadha idangal

- **Chinna, single-turn calls**, oru message-a classify panra maadhiri: design-pannumbodhu oru thadava count pannitu aduththa velaikku ponga.
- **Kammiyaana volume internal tools**, engineering neraththa vida periya bill cheap-aa irukkura idangal.
- **Chinna records-la batch jobs**, ovvoru input-um kittathatta orey size-la irukkum.

Neenda chats, paste panna documents, neraya tool results irukkura agents, scale-la Indian languages-la irukkura edhaiyum kavanamaa paarunga.

## Demo-la irundhu production-ku

- **Ovvoru call-layum input, output tokens-a log pannunga**, mudiyum-naa paagam-padi: system, history, retrieved, tools.
- **Budgets-a code-la enforce pannunga**, prompt-la mattum illa.
- **User input length-a cap pannunga**, clear message-oda, anuppradhukku munnaadi count pannunga.
- **Token valarchiya alert pannunga**: average input size ethittae irundhaa, history illa retrieval trim aagala-nu artham.
- **Models maathumbodhu budgets-a thirumba check pannunga**, yen-na tokenizers-um prices-um vera vera.
