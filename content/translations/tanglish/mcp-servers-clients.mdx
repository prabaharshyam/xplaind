## Idhu enna

Munnaadi ovvoru AI app-kum ovvoru tool-kum adhoda sondha custom code thevaippattudhu: chat app-la ticketing system-ku oru integration, coding assistant-la vera onnu, agent-la vera onnu. **Model Context Protocol** (MCP) idha sari panra oru open standard. Oru system-a oru thadava **MCP server**-aa wrap pannunga; desktop assistant, IDE, illa unga sondha agent maadhiri entha **MCP client**-um adha kandupidichu use pannalaam.

Oru MCP server moonu vagai vishayam tharalaam:

- **Tools**: Model call panna actions, example `search_tickets` illa `create_invoice`.
- **Resources**: App context-kulla padikkura data, example oru file, oru record, oru schema.
- **Prompts**: User select panna reusable prompt templates.

```flow
dir: LR
title: Oru server, pala hosts: ovvoru app-kum pudhu integration illa
IDE assistant, a host -[client]-> Maintenance-log server | tools: find_machine, get_maintenance_history, log_observation
Chat assistant, a host -[client]-> Maintenance-log server
Chat assistant, a host -[client]-> Spare-parts server
```

Indha lesson-la Pune-la oru manufacturing company-a follow pannuvom, avanga engineers adhe maintenance data-la rendu vera AI assistants use panraanga.

## Idhu eppadi work aagudhu

**Roles.** *Host*-na user velai seiyra AI application. Adhukkulla oru MCP *client* ovvoru *server*-kum oru connection-a pidichukkum. Client oru server-a "nee enna tharuva"-nu kekkum, tool list-a model-ku kudukkum, model oru tool-a call pannaa, client andha call-a sariyaana server-ku anuppi result-a thirumba kondu varum.

**Transports.** Local server adhe machine-la oru process-aa odum, standard input and output vazhiyaa pesum, idhu desktop tools-ku, developer machines-ku set aagum. Remote server oru web service-aa odum, HTTP vazhiyaa pesum, idhu shared company systems-ku set aagum, sariyaana authentication thevai, perumbaalum OAuth.

**Server build panradhu.** Python, TypeScript, vera languages-ku official SDKs irukku. Python-la oru minimal server konjam lines thaan:

```python
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("tickets")

@mcp.tool()
def search_tickets(query: str, status: str = "open") -> list[dict]:
    """Search support tickets by keywords. status is 'open' or 'closed'. Returns up to 10."""
    return ticket_db.search(query, status=status, limit=10)

if __name__ == "__main__":
    mcp.run()
```

Function-oda per, type hints, docstring thaan tool-oda schema aagudhu, adhanaala mundhaiya lesson-la sonna tool design advice neraa apply aagum.

**Security.** MCP server-na nijamaana systems-ku access irukkura code. Kelunga: yaaru ezhudhunaanga, edhellaam reach pannum, entha credentials use pannum, user-a pola (avanga permissions-a madhichu) act pannudha, illa ella adhikaaramum irukkura service account-a pola act pannudha? Tool descriptions-um results-um model-kulla pogudhu, adhanaala malicious server illa poison panna record-la prompt injection irukkalaam. Least privilege use pannunga, third-party servers-a install panna munnaadi review pannunga, ovvoru call-aiyum log pannunga.

**Local vs remote servers:**

| Vishayam | Local (standard input and output) | Remote (HTTP) |
| --- | --- | --- |
| Enga odum | User-oda machine-la | Company server illa cloud-la |
| Edhukku nallaa | Developer tools, local files | Shared company systems |
| Authentication | User-oda sondha machine access | OAuth, idealaa single sign-on vazhiyaa |
| Updates | Ovvoru user-um avanga copy-a update pannanum | Ellaarukkum oru thadava update |
| Logging | Machine-ku machine | Central audit log |

**Entha server-ku-um ketka vendiya security kelvigal:**

| Kelvi | Yen mukkiyam |
| --- | --- |
| Yaaru ezhudhunaanga, code-a padikka mudiyumaa? | Server neenga kudukkura access-oda odum |
| Edhellaam systems-um data-vum reach panna mudiyum? | Thappa pona, attack nadandha damage-a limit pannum |
| User-aa act pannudha, service account-aa? | User permissions apply aagumaa-nu mudivu pannum |
| Edhellaam tools write illa send pannum? | Adhukku tight limits illa approval thevai |
| Calls user, tool, arguments-oda log aagudha? | Incidents-a investigate panna thevai |

**Tools-a design panradhu.** Entha agent tool-kum sonna adhe advice thaan: kammiyaana, task-shaped tools, clear descriptions, useful errors. Pala hosts oru server-a use pannradhaala, nalla descriptions innum mukkiyam; oru vague tool-a ettukka ovvoru host-layum prompt-a tune panna mudiyaadhu. Write tools-a narrow-aa vainga, example `log_observation` oru notes table-ku mattum ezhudhum, adhanaala kuzhambina illa manipulate panna model kooda konjam thaan damage pannum.

**Tools-a thavira innum.** Oru server moonu vagai vishayam tharalaam. **Tools** model call pannalaam-nu irukkura functions. **Resources** host padichu kaattura illa attach panna data, example oru file, oru ticket, oru database row, URI-aala address pannum. **Prompts** user oru menu-la select panna reusable templates, example "summarise this ticket thread". Tools model-driven; resources-um prompts-um perumbaalum app illa user choose pannuvaanga.

```python
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("tickets")

@mcp.resource("ticket://{ticket_id}")
def ticket(ticket_id: str) -> str:
    """The full text of one ticket."""
    t = ticket_db.get(ticket_id)
    return f"{t.title}\n\n{t.body}"

@mcp.prompt()
def summarise_ticket(ticket_id: str) -> str:
    return f"Summarise ticket {ticket_id} in five bullets and list open questions."
```

**Unga sondha client ezhudhuradhu.** Desktop assistants, code editors maadhiri hosts-la already clients irukku, aana adhe SDK-vodu unga sondha Python code-la irundhum connect pannalaam:

```python
import asyncio
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

async def main():
    server = StdioServerParameters(command="python", args=["tickets_server.py"])
    async with stdio_client(server) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()
            tools = await session.list_tools()
            print([t.name for t in tools.tools])
            result = await session.call_tool("search_tickets", {"query": "refund", "status": "open"})
            print(result.content[0].text)

asyncio.run(main())
```

Unga app `tools.tools`-a tool definitions-aa model-ku kudukkum, model-oda tool calls-a `session.call_tool`-ku route pannum, tool-calling lesson-la paatha adhe round trip.

**Model-a connect panna munnaadi server-a test pannunga.** `npx @modelcontextprotocol/inspector`-la odura MCP Inspector oru page-a thirakkum; adhula server-oda tools-a list pannalaam, unga sondha arguments-oda call pannalaam, raw results-a paakkalaam. Perumbaalaana bugs chat vazhiyaa paakkradha vida inga vegamaa theriyum.

**MCP-ku thaniyaa irukkura threats.**

- **Tool poisoning**: oru tool description illa result model-kitta vera edhaavadhu seiya sollum, example `~/.ssh`-a padikka, illa oru URL-ku data anuppa. Third-party servers-oda descriptions-a padinga, results-a data-vaa nenachukkunga.
- **Approval-ku aprom maarradhu**: neenga approve panna server aprom adhoda tool descriptions-a update pannalaam. Versions-a pin pannunga, changes-a review pannunga.
- **Name clashes**: rendu servers onnu pola per irukkura tool tharaa, edhu run aagum-nu model kuzhambalaam. Tool names-ku server-oda purpose-a prefix-aa podunga.
- **Romba adhigam reach**: oru company-wide token irukkura oru server ellathaiyum expose pannalaam. Signed-in user-aa act panra servers-a prefer pannunga, OAuth scopes task-ku evvalavu narrow-aa mudiyumo avvalavu.

**Browser-la try pannunga.** MCP messages JSON-RPC. Idhu client anuppura tool call-a build panni, reply shape-a check pannum.

```python
import json

request = {"jsonrpc": "2.0", "id": 7, "method": "tools/call",
           "params": {"name": "search_tickets", "arguments": {"query": "refund", "status": "open"}}}
reply = {"jsonrpc": "2.0", "id": 7,
         "result": {"content": [{"type": "text", "text": "T-1042: refund delayed"}], "isError": False}}

print(json.dumps(request, indent=2))
assert reply["id"] == request["id"], "replies must match the request id"
print("tool said:", reply["result"]["content"][0]["text"])
```

## Oru worked example

Pune-la oru manufacturing company-oda engineers avanga IDE-la oru AI assistant-um, chat tool-la vera onnum use panraanga. Rendukkum maintenance log database-ku access venum.

Rendu integrations-ku badhila, moonu tools-oda oru remote MCP server build pannuveenga: `find_machine` (tag illa per-aala), `get_maintenance_history` (oru machine-oda last N events), `log_observation` (oru note serkkum; notes table-ku mattum ezhudhum). Adhu ovvoru user-aiyum company-oda single sign-on vazhiyaa authenticate panni, adhe user-oda sondha permissions-oda database-a query pannum, adhanaala oru contractor avanga plant-a mattum paarpaanga.

Rendu assistants-um adhe server-oda connect aagum. Oru engineer chat-la kekkuraanga: "CNC-14-oda spindle last eppo service aachu, apram yaaravadhu vibration report pannaangala?" Assistant `find_machine`-a call pannum, apram `get_maintenance_history`-a, dates-oda log-la irukkura per-oda badhil solum. Ovvoru call-um server-oda audit log-la user, tool, arguments-oda varum.

IT apram oru pudhu spare-parts system-a serkkum podhu, rendaavadhu MCP server-a serkkuraanga, assistants-la entha maatramum illaama rendu assistants-kum andha tools kidaikkum.

| Event | Enna nadandhudhu |
| --- | --- |
| Engineer CNC-14 pathi kekkuraanga | Chat assistant find_machine-a, apram get_maintenance_history-a call pannudhu |
| Contractor vera plant pathi kekkuraanga | Server-oda per-user permissions onnum return pannala |
| Audit review | Ovvoru call-um user, tool, arguments-oda list aagi irundhudhu |
| Pudhu spare-parts system | Rendaavadhu server serkkapattudhu; rendu assistants-kum adhoda tools kidaichudhu |

## Podhuvaa panra thappugal

- **Theriyaadha servers-a install panradhu.** Third-party server neenga kudukkura entha access-oda-um odum. Code-a padinga illa nambikkaiyaana sources use pannunga.
- **Oru super-user credential.** Server user-oda sondha permissions-a ignore pannaa, ovvoru user-um ellathaiyum reach pannalaam.
- **Muzhu database-a expose panradhu.** Users database administrators-a irundhaa thavira, `run_sql` tool-a vida task-shaped tools kudunga.
- **Tool results-a nambikkaiyaana-nu nenaikkradhu.** Oru ticket illa document-la irukkura text-la injected instructions irukkalaam; host adha data-vaa paakkanum.
- **Logging illaama irukkradhu.** Tool calls-oda record illaama, assistant enna senjuchu-nu investigate panna mudiyaadhu.
- **Third-party servers-oda tool descriptions-aiyum code-aiyum padikkaama install panradhu.**
- **Pin pannaadha server versions.** Aprom varra update tools enna seiyum, enna solludhu-nu maathidalaam.
- **Ellaarukkum oru service-account token.** User permissions apply aagaadhu.

## MCP eppo thevai illa

- **Konjam tools irukkura, adhu mattum use panra oru app**: code-la saadhaa tool definitions easy-aa irukkum.
- **Fixed workflows**, unga code functions-a neraa call pannum, entha model-um tools-a choose pannaadha idathula.
- **Ovvoru pudhu connection-kum security review thevaippadura strict environments**: oru in-process tool set-oda aarambinga, tools share aana aprom MCP-ku pogunga.

Pala hosts illa agents-kku adhe tools thevaippattaa, illa users avanga ippo irukkura assistants-a unga systems-la plug panna virumbunaa MCP payan tharum.

## Demo-la irundhu production-ku

- **Remote servers-a OAuth-ku pinnaadi odunga**, narrow scopes-oda, idealaa company-oda single sign-on vazhiyaa.
- **Ovvoru call-aiyum central-aa log pannunga**, user, tool, arguments, result size-oda.
- **Server versions-a pin panni review pannunga**, tool descriptions-la varra maatrangal-um serthu.
- **Company-kku approved-server list vainga**, matha-vatrai block pannunga.
- **Ovvoru tool-kum rate-limit-um timeout-um podunga**, write tools-ku approval vaanga.
