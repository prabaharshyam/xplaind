## Idhu enna

MCP-ku munnaadi, ovvoru AI app-kum ovvoru system-kum thani code thevaippattuchu. Moonu assistants, naalu systems-naa pannirendu integrations. **Model Context Protocol** (MCP) idha sari panra oru open standard. Ovvoru system-aiyum oru thadava **MCP server**-aa wrap pannuveenga, ovvoru AI app-layum entha server-odayum pesa mudiyura oru **MCP client** irukkum: moonu perukkal naalu illa, moonu koottal naalu paagangal thaan.

Anthropic MCP-a 25 November 2024 annaikku release pannuchu. December 2025-la adha Agentic AI Foundation-kitta koduthuchu; adhu Linux Foundation-ku keezha Anthropic, Block, OpenAI serndhu aarambicha oru fund, anga adhoda maintainers adha open-aa develop panraanga. Versions-ku date thaan per. Ippodhaiya version **2026-07-28**, idhu anjaavadhu release; adhukku mundhaiyadhu 2025-11-25. Oru tutorial entha version-ku ezhudhappattadhu-nu eppavume check pannunga.

Oru server moonu vagaiyaana vishayangala offer pannalaam. Romba mukkiyamaanadhu, ovvonnaiyum use pannalaam-nu yaar mudivu panraanga-ngiradhu thaan:

| Feature | Adhu enna | Yaar use panna mudivu panraanga | Udhaaranam | Messages |
| --- | --- | --- | --- | --- |
| Tools | JSON schema irukkura functions | Model, oru task nadakkumbodhu | `search_tickets(query, status)` | `tools/list`, `tools/call` |
| Resources | Oru URI vachu mugavari idappatta data | App illa user adha attach pannuvaanga | `ticket://T-1042` | `resources/list`, `resources/read` |
| Prompts | Reusable prompt templates | User oru menu-la irundhu onna therndheduppaanga | "Indha ticket thread-a summarise pannu" | `prompts/list`, `prompts/get` |

## Idhu eppadi work aagudhu

### Host, client, server

**Host**-naa user velai seiyura AI app. Adhukkulla, oru **client** oru **server**-oda connection-a vachirukkum, adhanaala moonu servers irukkura oru host-la moonu clients irukkum. Client than server-oda tools-a model-ku list pannum. Model oru tool-a kettaa, client andha call-a andha server-ku anuppi result-a thiruppi kodukkum. Model eppavume oru server-oda neraa pesaadhu, adhanaala control host kaiyila thaan irukkum.

```flow
dir: LR
title: Oru system-ku oru server, ella hosts-um share pannum
IDE assistant | ovvoru server-kum oru client irukkura host -> Maintenance-log server | find_machine, get_maintenance_history, log_observation
Chat assistant | ovvoru server-kum oru client irukkura host -> Maintenance-log server
Chat assistant -> Spare-parts server
```

### Wire-la pora messages

MCP messages JSON-RPC 2.0: oru request-la oru `id`, oru `method`, `params` irukkum, reply-layum adhe `id` varum. 2026-07-28-la irundhu protocol **stateless**. Pazhaiya versions oru `initialize` handshake-oda aarambichu oru session-a vachirundhuchu. Ippo ovvoru request-um protocol version, client name, capabilities-a `_meta`-la kondu varum, adhanaala server-oda entha copy-um adhukku badhil sollalaam. Oru client modhalla `server/discover`-a call pannalaam, aanaa kattaayam illa. Innum upgrade pannaadha hosts-kitta SDKs pazhaiya handshake-laye pesum.

Failures rendu vagai:

- **Tool error**-naa `isError: true`-oda varra oru saadhaarana result. Model adha padichu thirumba try pannalaam, adhanaala enna thappaachu, badhilaa enna pannanum-nu sollunga.
- **Protocol error**-naa oru code-oda varra JSON-RPC `error`, udhaaranam oru malformed request-ku. Adha client handle pannum; model perumbaalum adha paarkkave paarkkaadhu.

**Browser-laye try pannunga.** Idhu worked example-oda server-la irundhu record panna oru request, rendu replies, idathukkaaga trim pannadhu. Code oru reply-a model paarkkura vadivathukku maathudhu.

```python
import json

request = {"jsonrpc": "2.0", "id": 7, "method": "tools/call",
           "params": {"name": "get_maintenance_history", "arguments": {"tag": "CNC-14", "limit": 1},
                      "_meta": {"io.modelcontextprotocol/protocolVersion": "2026-07-28"}}}

ok = {"jsonrpc": "2.0", "id": 7, "result": {"resultType": "complete", "isError": False,
      "content": [{"type": "text", "text": "{\"date\": \"2026-11-18\", \"note\": \"Vibration at high RPM\"}"}]}}
refused = {"jsonrpc": "2.0", "id": 7, "result": {"resultType": "complete", "isError": True,
      "content": [{"type": "text", "text": "Error executing tool get_maintenance_history: No machine 'CNC-14' in your plant."}]}}

def for_the_model(reply):
    assert reply["id"] == request["id"], "a reply must match its request id"
    if "error" in reply:  # protocol error: the host deals with it
        raise RuntimeError(reply["error"]["message"])
    text = "\n".join(c["text"] for c in reply["result"]["content"] if c["type"] == "text")
    return {"tool_result": text, "is_error": reply["result"]["isError"]}

print(json.dumps(for_the_model(ok)))
print(json.dumps(for_the_model(refused)))
```

### Transports: local, remote

| Amsam | stdio (local) | Streamable HTTP (remote) |
| --- | --- | --- |
| Eppadi odum | Host server-a oru child process-aa start panni standard input, output vazhiyaa pesum | Server ore URL-la irukkura oru web service, udhaaranam `https://mcp.example.in/maintenance` |
| Edhukku nalladhu | Files, local databases, developer tools | Shared company systems, ore idathula update, log pannalaam |
| User yaaru | Andha machine-la host-a otturavanga | Sign-in pannavanga: ovvoru request-layum oru OAuth token |

**Streamable HTTP**-la, client ovvoru message-aiyum andha ore URL-ku POST pannum, server JSON-oda badhil sollum, illa modhalla progress anuppumbodhu events-oda oru stream-aa badhil sollum. 2026-07-28-la, `Mcp-Method`, `Mcp-Name` headers body-la irundhu method-aiyum tool name-aiyum copy pannum, adhanaala oru gateway tool vaariyaa route pannalaam, rate-limit pannalaam; headers-um body-um othupogaadha request-a server reject pannum. Session id illaadhadhaala, oru saadhaarana load balancer-ku pinnaadi pala copies odalaam. Oru workflow-ku state venumnaa, oru tool `draft_id` maadhiri oru handle-a return pannum, model adha thirumba pass pannum.

Rendu gotchas. Pazhaiya tutorials **HTTP+SSE** transport-a (`transport="sse"`) use pannudhu, adhu deprecated: pudhusaa edhaiyum adhula aarambikkaadheenga. Appuram, oru stdio server standard output-la MCP messages-a mattum thaan ezhudhanum: thevaiyillaadha oru `print` kooda connection-a udaichidum, adhanaala standard error-ku log pannunga.

### Python-la oru server build panradhu

Official Python SDK `mcp` package, November 2026 nilavarappadi version 2.x (`pip install "mcp[cli]"`). Adhoda main class `MCPServer`. SDK 1.x tutorials `mcp.server.fastmcp`-la irundhu `FastMCP`-a import pannudhu, adhu 2.x-la fail aagum: code-a update pannunga, illa `mcp<2`-nnu pin pannunga.

```python
# tickets_server.py
from mcp.server import MCPServer
from mcp.server.mcpserver.exceptions import ToolError

mcp = MCPServer("tickets")

@mcp.tool()
def search_tickets(query: str, status: str = "open") -> list[dict]:
    """Search support tickets by keywords. status is 'open' or 'closed'. Returns up to 10."""
    if status not in ("open", "closed"):
        raise ToolError("status must be 'open' or 'closed'.")
    return ticket_db.search(query, status=status, limit=10)

@mcp.resource("ticket://{ticket_id}")
def ticket(ticket_id: str) -> str:
    """The full text of one ticket."""
    return ticket_db.get(ticket_id).body

@mcp.prompt()
def summarise_ticket(ticket_id: str) -> str:
    return f"Summarise ticket {ticket_id} in five bullets."

if __name__ == "__main__":
    mcp.run()  # stdio; use mcp.run(transport="streamable-http") for a remote server
```

Function-oda per, type hints, docstring thaan tool-oda name, input schema, description aagum, adhanaala tool-design lesson inga neraa porundhum. `ToolError`-a raise pannaa unga message-oda oru `isError: true` result return aagum.

**Model-a connect panradhukku munnaadi test pannunga.** MCP Inspector (`npx @modelcontextprotocol/inspector`, illa `mcp dev tickets_server.py`) vachu ovvoru tool-aiyum unga sondha arguments-oda, thappaana arguments utpada, call panni raw results-a paarkkalaam. Perumbaalaana bugs oru chat-la paarkkuradha vida inga seekiram therinjidum.

**Unga sondha client.** Assistants-layum code editors-layum clients erkanave irukku; unga sondha agent SDK-a use pannalaam:

```python
import asyncio
from mcp import Client, StdioServerParameters

async def main():
    server = StdioServerParameters(command="python", args=["tickets_server.py"])
    async with Client(server) as client:  # or Client("https://.../mcp") for a remote server
        tools = await client.list_tools()
        print([t.name for t in tools.tools])
        result = await client.call_tool("search_tickets", {"query": "refund"})
        print(result.is_error, result.structured_content)

asyncio.run(main())
```

Ovvoru tool-oda `name`, `description`, `input_schema`-a model-ku kodunga, adhoda calls-a `client.call_tool`-ku anuppunga, oru call fail aachu-nu model-ku theriyura maadhiri `is_error`-a thirumba pass pannunga.

### Oru server client-kitta enna kekkalaam

**Elicitation** oru tool call naduvula user-kitta edhaavadhu kekka vidum: vidupatta oru detail, illa oru bulk change-ku munnaadi "40 tickets-aiyum close pannalaamaa?". 2026-07-28-la idhu rounds-aa work aagum: server than kelvigaloda `resultType: "input_required"`-a return pannum, host user-kitta kekkum, client badhilgaloda call-a thirumba pannum. AI app vazhiyaa pogakkoodaadha oru password illa payment-ku, server user-a oru web page-ku anuppum (URL mode).

Pazhaiya material **sampling** (server host-oda model-kitta text ezhudha solradhu), **roots** (entha folders-a use pannanum-nu host server-kitta solradhu) pathiyum sollum. Rendume 2026-07-28-la deprecated aachu; kuranjadhu pannirendu maasam work aagum, aanaa pudhusaa edhaiyum adhumela build pannaadheenga. Neenda neram odura jobs (**tasks**), interactive screens (**MCP Apps**) ippo optional extensions.

### Tools-ku context selavaagum

Connect aana ovvoru tool-oda name, description, schema-um ovvoru turn-layum model-oda context-la irukkum. Anthropic-oda documentation (November 2026-la check pannadhu) solludhu: oru saadhaarana anju-server setup entha velaiyum aarambikkiradhukku munnaadiye definitions-kke sumaar 55,000 tokens use pannalaam, 30 mudhal 50 tools-ku mela ponaa tool thervu mosamaagum. Adhanaala:

- Kammiyaana, task vadiva, thanithani per irukkura tools-a offer pannunga; rendu servers-layum `search` irukkalaam-naa, system per-a prefix pannunga (`maint_search`).
- Results-ku cap vainga: oru `limit` argument, chinna fields, muzhu documents-ku badhilaa IDs.
- Host support pannaa tools-a thevaippadumbodhu load pannunga. Udhaaranamaa, Claude-oda tool search tool `defer_loading`-nnu mark panna tools-a model avatra search panra varaikkum context-ku veliyave vachirukkum.

### Surukkamaa security

Oru server unmaiyaana systems-ku access irukkura code, adhoda output model-kkulla pogum. Mukkiya risks: **tool poisoning** (descriptions illa results-la maraichu vacha instructions), **approve pannadhukku appuram maaradhu** (versions-a pin pannunga), servers-ku naduvula **per modhalgal**, **romba adhiga reach** (ore company-wide token). Adutha varra lesson, Securing agent tools and MCP servers, innum aazhamaa pogum; worked example builder pakkathai kaattudhu.

## Oru worked example

Pune-la oru manufacturing company-ku PUN-1, PUN-2-nnu rendu plants irukku. Engineers thanga IDE-la oru AI assistant-aiyum, chat-la innonnaiyum use panraanga, rendukkume maintenance log venum. Contractors thanga sondha plant-a mattum thaan paarkkanum.

Neenga moonu tools-oda oru remote MCP server build pannureenga: `find_machine`, `get_maintenance_history`, `log_observation`. Remote MCP OAuth-a use pannudhu: company-oda single sign-on (SSO) thaan tokens-a issue panra **authorization server**, unga MCP server avatra check panra **resource server**.

```flow
title: Remote server-oda modhal connection
Assistant token illaama server-a call pannudhu -> Server metadata link-oda 401 reply
Server metadata link-oda 401 reply -> Entha sign-in service-nu assistant padikkudhu
Entha sign-in service-nu assistant padikkudhu -> Engineer company SSO-la sign in panraanga
Engineer company SSO-la sign in panraanga -> SSO indha server-ku mattum token kodukkudhu | user, plant, scopes
SSO indha server-ku mattum token kodukkudhu -> Assistant token-oda call-a thirumba pannudhu
Assistant token-oda call-a thirumba pannudhu -> Server token-a check panni, andha user-aa tool-a ottudhu
```

SDK metadata-va serve panni 401-a ungalukkaaga anuppidum. Unga code tokens-a check panni user-oda limits-a apply pannum:

```python
# maintenance_server.py
import json, sqlite3
from mcp.server import MCPServer
from mcp.server.auth.middleware.auth_context import get_access_token
from mcp.server.auth.provider import AccessToken
from mcp.server.auth.settings import AuthSettings
from mcp.server.mcpserver.exceptions import ToolError

db = sqlite3.connect("maintenance.db", check_same_thread=False)
audit = open("audit.jsonl", "a", buffering=1)  # one JSON line per call

def verify_with_sso(token: str) -> dict | None:
    """Your SSO library checks signature, expiry and issuer; returns the claims or None."""
    ...

class SSOTokenVerifier:
    async def verify_token(self, token: str) -> AccessToken | None:
        claims = verify_with_sso(token)
        if claims is None:
            return None
        return AccessToken(token=token, client_id=claims["azp"], subject=claims["sub"],
                           scopes=claims["scope"].split(), resource=claims["aud"],
                           claims={"plant": claims["plant"]})

mcp = MCPServer("maintenance", token_verifier=SSOTokenVerifier(), auth=AuthSettings(
    issuer_url="https://sso.example.in",
    resource_server_url="https://mcp.example.in/maintenance",
    required_scopes=["maintenance.read"],
    validate_token_resource=True,  # refuse tokens issued for any other service
))

def caller(tool: str, args: dict) -> tuple[str, str, list[str]]:
    """Who is calling, from the checked token, never from the model. Writes the audit line."""
    tok = get_access_token()
    audit.write(json.dumps({"user": tok.subject, "client": tok.client_id, "tool": tool, "args": args}) + "\n")
    return tok.subject, tok.claims["plant"], tok.scopes

@mcp.tool()
def get_maintenance_history(tag: str, limit: int = 5) -> list[dict]:
    """Latest maintenance events for one machine in your plant, newest first. limit is 1 to 20."""
    user, plant, _ = caller("get_maintenance_history", {"tag": tag, "limit": limit})
    rows = db.execute(
        "SELECT e.done_on, e.kind, e.note, e.by_user FROM events e JOIN machines m ON m.id = e.machine_id "
        "WHERE m.tag = ? AND m.plant_id = ? ORDER BY e.done_on DESC LIMIT ?",
        (tag, plant, max(1, min(limit, 20)))).fetchall()
    if not rows:
        raise ToolError(f"No machine '{tag}' in your plant. Call find_machine to search by name.")
    return [{"date": d, "kind": k, "note": n, "by": b} for d, k, n, b in rows]

@mcp.tool()
def log_observation(tag: str, note: str) -> str:
    """Add a short note (max 500 characters) to a machine's log. Writes only to the notes table."""
    user, plant, scopes = caller("log_observation", {"tag": tag, "note": note[:80]})
    if "maintenance.write" not in scopes:
        raise ToolError("Your sign-in does not allow writing notes. Ask your supervisor to add it.")
    row = db.execute("SELECT id FROM machines WHERE tag = ? AND plant_id = ?", (tag, plant)).fetchone()
    if row is None:
        raise ToolError(f"No machine '{tag}' in your plant.")
    db.execute("INSERT INTO notes (machine_id, note, by_user) VALUES (?, ?, ?)", (row[0], note[:500], user))
    db.commit()
    return f"Note added to {tag}."

if __name__ == "__main__":
    mcp.run(transport="streamable-http", host="0.0.0.0", port=8000,
            streamable_http_path="/maintenance")  # serve behind HTTPS in production
```

Moonu design choices thaan security-a thaangudhu:

1. **Plant token-la irundhu varudhu, model-la irundhu illa.** Entha tool-layum `plant_id` argument illa, adhanaala entha prompt-um vera plant-a kekka mudiyaadhu. Ovvoru query-um SSO token-la potta plant vachu filter pannum.
2. **Token indha server-kaagave irukkanum.** `validate_token_resource=True` irundhaa, vera service-ku issue aana oru unmaiyaana token-kkum 401 thaan kidaikkum.
3. **Writes-ku oru scope venum.** Padikka `maintenance.read` venum; `log_observation`-ku `maintenance.write`-um venum.

Indha server-a rendu users-kaana stand-in tokens vachu test pannom (`find_machine`-um adhe pattern thaan, mela vittuttom). PUN-1-la engineer-aa irukkura Anita chat-la kekkuraanga: "CNC-14-oda spindle kadaisiyaa eppo service aachu, adhukkappuram yaaraavadhu vibration report pannaangalaa?" Assistant `get_maintenance_history`-a call panni rendu rows vaangudhu: 2 October 2026 annaikku suresh.p bearings-a maathinadhu, 18 November 2026 annaikku meera.d potta "Vibration at high RPM". Rendaiyum vachu badhil sollittu, appuram `log_observation` vachu avanga note-a log pannudhu.

Ravi oru contractor, avaroda token-la PUN-2-um `maintenance.read` mattum thaan irukku; avar than IDE-la irundhu adhe kelviya kekkuraar. Adhe query `plant_id = 'PUN-2'`-oda odi, edhuvum kidaikkaama, "No machine 'CNC-14' in your plant." return pannudhu. Avaroda `log_observation` call-ku "Your sign-in does not allow writing notes." kidaikkudhu. Rendume `isError: true` results, adhanaala assistant avatra explain pannudhu. Audit log-la ovvoru call-kum oru line irukku, udhaaranam `{"user": "ravi.contractor", "client": "ide-assistant", "tool": "get_maintenance_history", "args": {"tag": "CNC-14", "limit": 2}}`.

Idha production-grade aakka innum rendu layers venum. Server-oda database account machines, events-a padikkavum notes-la insert pannavum mattum thaan mudiyanum, appo unga filter-la oru bug irundhaalum edhaiyum delete panna mudiyaadhu. Appuram server **Anita-oda token-a eppavume** vera API-ku **forward pannakkoodaadhu**. Adhu token passthrough, MCP security guidance adha thadai pannudhu; oru downstream API-ku user venumnaa, andha API-kaagave issue aana oru thani token vaangunga.

Pinnaadi IT oru spare-parts system-a serkkumbodhu, adhe sign-in-oda oru rendaavadhu server-a deploy panraanga, rendu assistants-kkum entha maatramum illaama adhoda tools kidaichidum.

## Podhuvaana thappugal

- **Oru pazhaiya tutorial-a varikku vari follow panradhu.** `FastMCP` imports, `transport="sse"`, session ids, `initialize` handshake ellaam 2024, 2025-odadhu. Modhalla versions-a check pannunga.
- **Ellaarukkum ore super-user credential.** Yaar kekkuraanga-nu server kandukkalainnaa, ovvoru user-um ellaathaiyum thoda mudiyum. Sign-in panna user-aa act pannunga.
- **Identity-a oru tool argument-la irundhu edukkuradhu.** Oru `user_id` illa `plant_id` parameter irundhaa, model-o, adhukkulla inject aana text-o vera oruthharoda data-va therndhedukkalaam. Check panna token-la irundhu identity-a padinga.
- **Token passthrough.** Unga server-kaaga issue aagaadha tokens-a accept panradhu, illa user-oda token-a vera services-ku forward panradhu audit-aiyum scope checks-aiyum udaikkum.
- **Muzhu database-aiyum thirandhu viduradhu.** Users database administrators illainnaa, `run_sql` vendaam, task vadiva tools-a offer pannunga.
- **Periya results.** Aayirakkanakkaana rows context-a nirappi adutha ovvoru turn-aiyum slow pannum. Cap pannunga, paginate pannunga, summarise pannunga.
- **Timeouts illaadhadhu.** Oru slow ERP-kaaga kaathirukkura tool agent-a block pannum. Server-oda sondha calls-ku timeout vainga, oru client read timeout-um set pannunga (Python `Client`-la `read_timeout_seconds`).
- **Servers-aiyum results-aiyum nambradhu.** Theriyaadha illa pin pannaadha servers, instructions-aa nadathappadura ticket text, idhellaam tool poisoning-aiyum prompt injection-aiyum koopidum.
- **Logging illaadhadhu.** Ovvoru call-kum user, tool, arguments illaama, oru incident-a investigate panna mudiyaadhu.

## Ungalukku MCP thevaiyillaadha idangal

- **Sila tools irukkura ore app**, andha tools-a adhu mattum thaan use pannum: unga code-la saadhaarana tool definitions simple.
- **Fixed workflows**, anga unga code functions-a neraa call pannum, entha model-um tools-a therndhedukkaadhu.
- **Strict environments**, anga ovvoru pudhu network service-kum review venum: in-process tools-oda aarambinga, rendaavadhu app-ku thevaippadumbodhu MCP-ku maarunga.

Pala hosts illa agents-ku adhe tools venumbodhu, illa makkal erkanave use panra assistants-a unga systems-la plug panna virumbumbodhu MCP payan tharum.

## Demo-la irundhu production-ku

- **Company sign-in vazhiyaa OAuth**, narrow scopes, indha server-kaagave check panna tokens, token-la irundhu identity, oru least-privilege database account.
- **Oru central audit log**: user, client, tool, arguments, result size.
- **Oru approved-server list**, pin panna versions, tool descriptions maarumbodhellaam oru review.
- **Ovvoru tool-kum limits:** timeouts, result caps, rate limits, writes-ku user confirmation.

## Practice pannunga

Anthropic-oda ilavasa Introduction to Model Context Protocol course-a edunga, illa official introduction-aiyum Python SDK-oda get-started guide-aiyum padinga.

1. Ungalukku pidicha oru chinna SQLite database (books, fees, appointments) mela rendu tools-oda oru local stdio server-a `MCPServer` vachu build pannunga.
2. Adha MCP Inspector-la thirandhu, ovvoru tool-aiyum thappaana arguments-oda call pannunga, model recover aaga udhavaadha ovvoru error message-aiyum thirumba ezhudhunga.
3. Adha oru MCP-capable assistant-oda connect panni, rendu tools-um thevaippadura kelvigala kelunga. Oru table-la mattum insert panra oru write tool-a serunga, ovvoru call-aiyum log pannunga, oru record-la oru prompt injection-a maraichu vachu enna aagudhu-nu paarunga.
4. Adha `transport="streamable-http"`-oda ottunga, rendu users-ku rendu test tokens-a accept panra oru `TokenVerifier`-a serunga, ovvoru user-um than sondha rows-a mattum paarkkuraanga-nu kaattunga.
