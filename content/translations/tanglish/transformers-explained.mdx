## Idhu enna

**Transformer**-na 2017-la arimugamaana oru neural network architecture; **attention**-nu oru mechanism-a suththi build aanadhu. Idhu oru sequence-a (vaarththaigal, image patches, audio frames) process pannum. Ovvoru layer-layum, ovvoru position-um matha positions-la irundhu evvalavu edukkanum-nu mudivu pannum.

Moonu families idha use pannudhu:

- **Decoder-only** models oru neraththula oru token-aa text generate pannum. Llama family maadhiri innaiku irukkura open chat, coding models ippadi thaan build aagiyirukku.
- **Encoder-only** models muzhu text-aiyum ore neraththula padichu representations uruvaakkum: classifiers, search-kkaana neraya embedding models. Qwen3-Embedding (June 2025) maadhiri sila pudhu embedding models idhukku badhilaa decoder models-la irundhu build aanadhu.
- **Encoder-decoder** models oru sequence-a padichu innonna ezhudhum: translation, summarisation.

Vision transformers oru image-a patches-aa vetti, ovvoru patch-aiyum oru token maadhiri nadaththum.

Keezha irukkura table, oru head-la "it" vaarththaiyila irundhu varra attention-a kaattudhu. Indha numbers vilakkaththukkaaga mattum thaan, oru nija model-la irundhu eduththadhu illai.

| Token | The | bank | approved | the | loan | because | it | trusted | the | applicant |
|---|---|---|---|---|---|---|---|---|---|---|
| Encoder (rendu pakkamum paarkkum) | 0.02 | **0.61** | 0.05 | 0.01 | 0.18 | 0.02 | 0.04 | 0.03 | 0.01 | 0.03 |
| Decoder (munnaadi vandhadha mattum paarkkum) | 0.03 | **0.45** | 0.06 | 0.02 | 0.36 | 0.03 | 0.05 | 0 | 0 | 0 |

Encoder-aala "trusted"-a paarkka mudiyum; "it"-na bank thaan-nu adhu thaan solludhu (oru loan yaaraiyum trust pannaadhu). Decoder-aala pinnaadi varra vaarththaigala paarkka mudiyaadhu, adhanaala "it"-la nikkumbodhu "bank"-aa "loan"-aa-nu innum mudivaagala. "trusted" maadhiri pinnaadi varra tokens thirumbi paarththu adha mudivu pannum. Ovvoru row-oda koottuththogaiyum 1.

## Idhu eppadi work aagudhu

### Tokens, embeddings

Oru **tokenizer** text-a tokens-aa split pannum: muzhu vaarththaigal, vaarththaigaloda thundugal, alladhu thani bytes. Neraya chat-model tokenizers byte-pair encoding use pannum: bytes-la aarambichu, adikkadi pakkaththu pakkaththula varra pairs-a thirumba thirumba merge panni pudhu tokens aakkum. Apram ovvoru token id-um kathukkitta oru table-la irundhu oru row-a select pannum; adhu oru vector (oru **embedding**) tharum. Udhaaranamaa, Llama 3 8B-kku 128,256 tokens vocabulary irukku, vectors 4,096 numbers agalam.

Tokenizers thangaloda merges-a training text-la irundhu kathukkum; adhanaala andha text-la aridhaa irundha languages adhiga thundugalaa udaiyum. OpenAI-oda pazhaiya `cl100k_base`, pudhu `o200k_base` tokenizers vachu oru sentence-a naanga count pannom (November 2026):

| Sentence | cl100k_base | o200k_base |
| --- | --- | --- |
| The bank approved the loan. | 6 | 6 |
| Bank ne loan approve kar diya. | 8 | 7 |
| बैंक ने लोन मंज़ूर कर दिया। | 31 | 11 |

Pudhu tokenizer-layum Hindi sentence-kku English sentence-a vida kittaththatta rendu madangu tokens thevaippadudhu. Adhiga tokens-na adhiga bill, slow-aana replies, context-la kuraivaana idam. Indian languages-la AI pathina lesson idha innum aazhamaa paarkkudhu.

### Position

Attention thaanaa order-a kandukkaadhu: vaarththaigala shuffle pannaalum ovvoru token-kkum adhe mix thaan kidaikkum. Adhanaala model-kku position information venum. 2017 transformer-um BERT-um ovvoru embedding-odayum oru position vector-a **serththuchu**. BERT ippadi 512 vectors kathukkichu; adhanaala thaan adhaala 512 tokens-a thaandi padikka mudiyaadhu.

Llama-family models-um ModernBERT-um idhukku badhilaa **rotary position embeddings (RoPE)** use pannudhu. Ovvoru attention layer-kkullayum, ovvoru query-aiyum key-aiyum adhoda position-a poruththa oru angle-la rotate pannum. Appo rendu tokens-kku idaiyilaana score avai evvalavu dhooraththula irukku-nguradha poruththu irukkum. Konjam extra training koduththaa, model mudhalla paarththadha vida neelamaana contexts-kku rotary embeddings-a stretch pannalaam; context windows valarndhadhukku idhuvum oru vazhi.

### Attention

Ovvoru token-um kathukkitta moonu matrices-a use panni, thannoda embedding-la irundhu moonu vectors kanakkidum:

- oru **query**: naan edha thedurein?
- oru **key**: ennai edha vachu match pannalaam?
- oru **value**: ennai select pannaa naan enna kadaththuvein?

Model oru token-oda query-kkum ovvoru key-kkum dot product edukkum. Periya dot product-na "relevant". Apram scores-a key size-oda square root-aala vagukkum; yenna vector size kooda kooda dot products-um koodum, romba periya scores vandhaa softmax ore oru token-a mattum pick pannittu kathukkuradha niruththidum. Oru **softmax** scores-a koottuththogai 1 varra weights-aa maathum. Output-na values-oda weighted sum: andha token attend pannadha kalandhu uruvaana oru pudhu vector.

Oru decoder-la, softmax-kku munnaadi oru **causal mask** edhirkaala tokens-oda scores-a minus infinity-aa set pannum, adhanaala avattroda weights sariyaa 0 aagum. Adhu illainaa, training-la ovvoru position-um adhu predict panna vendiya token-aiye paarththudum.

Mask-oda oru head, NumPy-la:

```python
import numpy as np

def softmax(z, axis=-1):
    z = z - z.max(axis=axis, keepdims=True)
    e = np.exp(z)
    return e / e.sum(axis=axis, keepdims=True)

def attention(Q, K, V, causal=True):
    d = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d)                  # relevance of every token to every other
    if causal:                                     # hide future tokens
        future = np.triu(np.ones_like(scores), k=1) == 1
        scores = np.where(future, -np.inf, scores)
    weights = softmax(scores)                      # each row sums to 1
    return weights @ V, weights

rng = np.random.default_rng(0)
tokens = ["Priya", "paid", "the", "bill", "because", "she"]
x = rng.normal(size=(len(tokens), 16))             # one 16-number vector per token
Wq, Wk, Wv = (rng.normal(0, 0.3, (16, 8)) for _ in range(3))
out, w = attention(x @ Wq, x @ Wk, x @ Wv)
print(out.shape)                                   # (6, 8): one new vector per token
print(np.round(w, 2))                              # zeros above the diagonal
```

Mudhal row `[1, 0, 0, 0, 0, 0]`: "Priya" thannai mattum thaan attend panna mudiyum. Inga weights random. Train aana oru model-la, "she"-kkaana row "Priya" mela adhiga weight podum.

### Multi-head attention, layer

Pala heads pakkaththula pakkaththula oodum, ovvonnukkum thaniyaa query, key, value matrices irukkum; adhanaala ovvonnum vera oru relationship-a kathukkalaam. Width 768, 12 heads-na, ovvoru head-um 64 numbers-la velai seiyum; outputs thirumba 768-aa serkkappattu, innoru matrix-aala kalakkappadum. PyTorch-la idhu built-in-aave irukku:

```python
import torch
mha = torch.nn.MultiheadAttention(embed_dim=768, num_heads=12, batch_first=True)
seq = torch.randn(2, 10, 768)                      # batch of 2, 10 tokens each
mask = torch.triu(torch.ones(10, 10, dtype=torch.bool), diagonal=1)   # True = hidden
out, weights = mha(seq, seq, seq, attn_mask=mask)
print(out.shape, weights.shape)                    # (2, 10, 768) and (2, 10, 10)
```

Oru layer-na attention, adhukku apram ovvoru token-layum thaniththaniyaa velai seiyura oru **feed-forward** network. Shortcut connections ovvoru block-oda input-aiyum adhoda output-oda thirumba serkkum, adhanaala deep stacks-aiyum train panna mudiyum. 2017 model ovvoru block-kkum apram normalise pannuchu; Llama-style models ovvoru block-kkum munnaadi normalise pannum (RMSNorm vachu), idhu innum stable-aa train aagum. Periya models indha maadhiri dozen kanakkaana layers-a stack pannum.

```flow
dir: TB
title: Llama style-la oru decoder layer, ovvoru layer-layum thirumba varudhu
Token vectors -> Normalise
Normalise -> Masked multi-head attention | queries, keys-kku rotary positions apply aagum
Masked multi-head attention -> Input-a thirumba serkkum
Input-a thirumba serkkum -> Marupadi Normalise
Marupadi Normalise -> Feed-forward | gated, kittaththatta 3.5 madangu agalam
Feed-forward -> Marupadi serkkum
Marupadi serkkum -> Adutha layer
```

### Generation, KV cache, sampling

Oru decoder kadaisi position-oda vector-a adhoda vocabulary-la irukkura ovvoru token-kkum oru score-aa maaththi, apram onna pick pannum. **Temperature** softmax-kku munnaadi scores-a vagukkum: 1-kku keezha irundhaa choice safe-aa irukkum, 1-kku mela irundhaa variety adhigamaa irukkum. **Top-p** probabilities-oda koottuththogai p (udhaaranamaa 0.9) varra varai romba likely aana tokens-a mattum vachu, adhula irundhu sample pannum. Choose aana token serkkappadum, loop marupadi oodum.

Ovvoru step-layum muzhu text-kkum keys, values-a marupadi kanakkidradhu waste, adhanaala model avatra store panni vaikkum: adhu thaan **KV cache**. Ovvoru pudhu token-um thannoda query, key, value-a mattum kanakkittu cache-a attend pannum. Idhanaala generation fast-aa irukkum, aanaa ovvoru token-odayum ovvoru user-odayum cache valarum.

### Neelamaana context-oda moonu costs

| Cost | Edhoda valarum | Ungalukku idhukku enna arththam |
| --- | --- | --- |
| API bill | Tokens, linear-aa | Prompt-la irukkura ovvoru extra token-kkum, ovvoru call-layum kaasu kattanum |
| KV cache memory | Tokens × users | Neelamaana chats-um neraya users-um GPU memory-a nirappidum |
| Attention compute | Length-oda square | Context neelamaana piragu thaan idhu mukkiyam |

Llama 3 8B shape-kku, ovvoru pudhu token-um ovvoru layer-layum weight matrices-la sumaar 218 million multiply-adds pannum, adhu attend panra munnaadi irukkura ovvoru token-kkum innum sumaar 8,000 (config-la irundhu potta rough kanakku). 2,000 tokens-la attention velaiyila paththula oru pangukkum kuraivu; kittaththatta 27,000 tokens-la thaan adhu samamaa varum. Muzhu sequence-kkum paarththaa, attention velai square-aa valarum: 8,000 tokens-kku 1,000 tokens-a vida sumaar 64 madangu attention velai. **FlashAttention** adhe exact result-a slow GPU memory-kku romba kuraivaana trips-la kanakkidum, adhanaala fast-aa irukkum, aanaa comparisons ennikkai appadiye thaan irukkum.

### Pudhu variations: oru 2026 model card-a padikkiradhu

| Idea | Adhu enna maaththudhu | Config-la enga theriyum |
| --- | --- | --- |
| Rotary positions | Position attention-kkullaye varum; contexts-a stretch pannalaam | `rope_theta`, `rope_scaling` |
| Grouped-query attention | Query heads-oda groups oru key-value head-a share pannum: KV cache chinnadhu, quality loss konjam thaan | `num_attention_heads`-a vida kuraivaana `num_key_value_heads` |
| Gated feed-forward | Rendukku badhilaa moonu matrices | `intermediate_size`, `hidden_act` |
| Mixture of experts | Neraya feed-forward "experts"; oru router ovvoru token-aiyum sila experts-kku mattum anuppum | `num_local_experts`, `num_experts_per_tok` |
| Local attention | Sila layers pakkaththula irukkura tokens-a mattum attend pannum, neelamaana input cost-a kuraikkum | sliding-window settings |

Mixture of experts rendu numbers-a pirikkudhu. **Total** parameters ellaame memory-la irukkanum; **active** parameters oru token-kkaana compute-a mudivu pannum. Mixtral 8x7B-kku moththam 46.7 billion, oru token-kku 12.9 billion use pannum; DeepSeek-V3-kku moththam 671 billion, active 37 billion. Hardware size panradhukku munnaadi rendu numbers-aiyum padinga.

### Parameters enga irukku

```python
def params(width, layers, vocab, ffn, heads, kv_heads, gated=True, tied=False):
    head = width // heads
    attn = 2 * width * width + 2 * width * kv_heads * head   # Q and output, then K and V
    ff = (3 if gated else 2) * width * ffn                     # gated layers use 3 matrices
    emb = vocab * width * (1 if tied else 2)                   # input table, output layer
    return layers * (attn + ff) + emb

# Llama 3 8B, from its published config
print(params(width=4096, layers=32, vocab=128_256, ffn=14_336, heads=32, kv_heads=8) / 1e9)
# about 8.03, matching the published 8B size
```

Ovvoru layer-oda weights-la sumaar anjula naalu pangu attention-la illa, feed-forward block-la thaan irukku. Oru number-kku 2 bytes-la (16-bit), 8 billion parameters-kku endha KV cache-um illaamaleye sumaar 16 GB GPU memory thevai.

### Pre-training, adaptation

Models-a periya alavu text-la adutha token-a (decoders) alladhu maraicha tokens-a (encoders) predict panna pre-train pannuvaanga. Grammar, facts, reasoning patterns ellaame prediction-kku udhavum, adhanaala model avatra kathukkum. Apram chat models-a instruction tuning, preference training vachu vadivamaippaanga. Unga sondha tasks-kku fine-tune pannalaam, alladhu prompts, retrieval-oda model-a appadiye use pannalaam.

Transformers jeyichadhukku kaaranam: attention dhooraththula irukkura tokens-a neradiyaa inaikkum, ella positions-um GPUs-la parallel-aa train aagum; adhanaala romba periya models-kkum datasets-kkum scale panna mudinjudhu.

## Oru worked example

Chennai-la oru legal-tech startup-kku Indian court judgments mela moonu velaigal irukku.

**1. Area of law vaariyaa classify panradhu** (property, family, criminal, tax, labour). Avangakitta 12,000 labelled judgment summaries irukku. Oru chinna fine-tuned encoder thaan thelivaana choice: cheap, fast, labels-aiyum use panna mudiyum. Avanga test set-la idhu 91% accuracy, keyword counts-la gradient-boosted model 82%-nu vachukkonga (vilakkaththukkaana numbers). Indha gain context-la irundhu varudhu: "the appellant's claim to ancestral property"-nguradhu, "property"-ngura vaarththai illaadhappo kooda property law thaan.

Muzhu judgments avangaloda BERT-style encoder-oda 512-token limit-a thaandi pogum. Andha limit, adhu train aana 512 learned position vectors-la irundhu varudhu, attention cost-la irundhu illa. Avangalukku rendu options irukku:

- Ovvoru judgment-aiyum chunks-aa pirichu, ovvonnaiyum classify panni, votes-a combine panradhu.
- 8,192 tokens padikkakkoodiya ModernBERT maadhiri oru long-context encoder-a use panradhu. Muzhu window, short inputs-a vida slow-aa irukkum-nu adhoda model card warn pannudhu, adhanaala speed-aiyum test panraanga.

**2. Semantic search.** Oru embedding model ovvoru paragraph-aiyum oru thadavai vector-aa maathum; queries vector search moolamaa match aagum.

**3. Summaries.** Privacy-kkaaga, oru GPU-la oru 8B open model-a self-host pannalaamaa-nu yosikkiraanga. Edhaiyum vaangradhukku munnaadi config-la irundhu size panraanga:

```python
def kv_cache_gb(tokens, layers=32, kv_heads=8, head_dim=128, bytes_per_number=2, users=1):
    per_token = 2 * layers * kv_heads * head_dim * bytes_per_number   # one key and one value
    return per_token * tokens * users / 1e9

print(kv_cache_gb(1))                     # 0.000131 GB, about 0.13 MB per token
print(kv_cache_gb(6_500, users=10))       # 8.5 GB for 10 judgments at once
print(kv_cache_gb(6_500, users=10, kv_heads=32))   # 34 GB without grouped-query attention
```

| Item | Memory |
| --- | --- |
| Weights, 2 bytes-la 8 billion | Sumaar 16 GB |
| KV cache, 6,000 tokens-oda 10 judgments, summary-kku innum 500 | Sumaar 8.5 GB |
| Runtime overhead-kku munnaadi total | Sumaar 25 GB |

Runtime overhead serththaa, ore neraththula 10-kku oru 24 GB GPU-la headroom illa; 40 alladhu 48 GB GPU-la idam irukkum, illainaa ore neraththula 5 process pannalaam. Idhu fit aaguradhukku kaaraname grouped-query attention thaan: ovvoru query head-kkum oru key-value head irundhaa cache naalu madangu perusaa irukkum.

## Podhuvaa panra thappugal

- **Ella transformer-aiyum chatbot-nu ninaikkiradhu.** Encoders, decoders, encoder-decoders vera vera velaikku porundhum; classification-la oru chinna encoder adikkadi periya chat model-a jeyikkum.
- **Weights-a mattum vachu hardware size panradhu.** KV cache context length-odayum users-odayum valarum; neelamaana contexts-kkum neraya users-kkum weights-a vida adhiga memory thevaippadalaam.
- **Encoder-oda 512-token limit-a attention cost-nu kuzhappikkiradhu.** Adhu model train aana position table-la irundhu varudhu.
- **Attention maps-a explanations-aa padikkiradhu.** Oru head-la information enga flow aachu-nu thaan attention weights kaattum, model yen andha mudivu eduththuchu-nu illa.
- **Thappaana chat template alladhu tokenizer-a use panradhu.** Oru template-oda fine-tune aana model innoru template-la mosamaa behave pannum; document panna adhe template-a use pannunga.
- **Mixture-of-experts model-oda total parameters-a adhoda speed-aa solradhu.** Memory total parameters-a follow pannum; oru token-kkaana compute active parameters-a follow pannum.
- **Tokenisation-a marandhudradhu.** Hindi alladhu Tamil text-kku English-a vida pala madangu tokens thevaippadalaam; adhu cost, speed, context-la irukkura idam ellaaththaiyum maathum.

## Transformer internals thevai illaadha nerangal

- **API vazhiyaa models-a use panradhu**: dhinasari velaiyila prompts, retrieval, evals thaan adhigam mukkiyam.
- **Tabular prediction**, anga boosted trees perumbaalum sirandha tool.
- **Chinna text tasks**, oru keyword rule alladhu chinna classifier-e erkanave nallaa kaiyaalum.

Models-a therndhedukkumbodhu, GPUs-a size pannumbodhu, long-context behaviour-a debug pannumbodhu, fine-tune pannumbodhu internals therinjirundhaa palan tharum.

## Demo-la irundhu production-kku

- **Hardware vaangradhukku munnaadi memory-a estimate pannunga**: weights, adhoda unga nija context length-layum users ennikkaiyilayum KV cache.
- **Prompts-a thevaikku mela neelamaa vaikkaadheenga**: ovvoru token-um bill aagum, cache aagum, attend pannappadum.
- **Model-oda sondha tokenizer-aiyum chat template-aiyum** document panna maadhiriye use pannunga.
- **Long-context accuracy-a unga sondha documents-la benchmark pannunga**, vilambarappaduththuna window-a mattum nambaama.
- **Language vaariyaa tokens-a count pannunga**, unga users ezhudhura languages-kku.
- **Ovvoru deployment-odayum model, version, config-a record pannunga**.
