## Idhu enna

**Evals**-na oru AI application-ku repeatable tests. Unmaiyaana inputs-oda oru fixed **test set**-la app-a run panni, ovvoru output-aiyum score pannuveenga. Adhanaala ovvoru change-kum (pudhu prompt, model, illa retrieval setting) munnaadi irundhadhoda ottippaakka oru number kidaikkum. Evals illaina, teams prompts-a feel-la maathuvaanga, nallaa aachaa kettaa aachaa-nu solla mudiyaadhu.

```flow
Unmaiyaana inputs | logs, tickets -> Test set: 60 cases | routine 35, claims 10, complaints 8, must escalate 7
Kashtamaana cases -> Test set: 60 cases
Munnaadi nadandha failures -> Test set: 60 cases
Test set: 60 cases -> App version N -> Outputs -> Scorers | code checks, apram model judge, apram human sample
Scorers -> Version-vaariyaavum category-vaariyaavum results -> Edhuvum category kettu pogalaina mattum ship pannunga
```

Indha lesson-la Pune-la oru insurance broker-oda policyholder email assistant-a follow pannuvom. Angae team "edhu nalla prompt"-nu vaadhaadittu irundhaanga.

## Idhu eppadi work aagudhu

**Test set-a reality-la irundhu build pannunga.** Mudinja varaikkum unmaiyaana user inputs-a (logs, support tickets, sample documents) serunga, koodavae kashtamaanadhu-nu theriyura cases-aiyum. Mudhalla 30 la irundhu 100 varaikkum cover pannunga:

- common, dhinamum varra cases;
- edge cases (neelamaana inputs, vidhyaasamaana formats, mixed languages);
- refuse illa escalate panna vendiya cases;
- munnaadi nadandha failures (ovvoru bug-um oru test case).

**Ovvoru case-kum "nallaa"-na enna-nu define pannunga.** Task-a poruthu:

- oru exact expected value (category, extract panna field, number);
- answer-la irukka vendiya facts illa citations;
- answer panna koodaadha vishayangal (refund promise panradhu, medical advice kudukkuradhu);
- oru aal illa model judge apply panra rubric (correct, complete, polite).

**Romba reliable-aana, sellavu kammi method-la score pannunga.** Mudhalla code checks: exact match, JSON validity, required keywords, length limits, correct citations. Open-ended quality-ku model judges, adhoda agreement-a human grades-oda check pannittu. Oru sample-ku human review, especially aarambathula.

**Data-va paarunga.** Scorers ezhudhuradhukku munnaadi, 50 la irundhu 100 unmaiyaana outputs-a padichu, adhu eppadi fail aagudhu-nu note pannunga. Romba useful-aana evals paartha failure patterns-la irundhu varum, generic metrics-la irundhu illa.

**Ovvoru change-lum run panni compare pannunga.** Versions-um scores-um case category-vaariyaa oru table-la vechikkunga. Average-a yethi, refusals-a odachirukkura change improvement illa.

**Unmaiyum vaazhanum.** Users pudhu problems kandupidikkum podhu pudhu cases serunga; ippo unmaiya kaattaadha cases-a neekkunga; set-la romba tune pannidaatheenga, appuram adhu users-a represent pannaama poiduchu-na prechanai.

**Vaadhatha mudikkura oru results table:**

| Version | Judge score | Escalations pidichadhu | Policy number irundhadhu | Approval promise pannadhu |
| --- | --- | --- | --- | --- |
| Pazhaya prompt | 71% | 4 of 7 | 58 of 60 | 0 |
| Pudhu prompt | 78% | 3 of 7 | 59 of 60 | 0 |
| Escalation rules-oda | 80% | 7 of 7 | 60 of 60 | 0 |

**Mudhalla outputs-a padinga.** Oru scorer kooda ezhudhuradhukku munnaadi, app-a 50 la irundhu 100 unmaiyaana inputs-la run panni, ovvoru output-aiyum padinga. Ovvoru kettadhukkum sinna note ezhudhunga: "rendaavadhu kelvi-a ignore pannidhu", "oru policy clause-a invent pannidhu", "complaint-ku romba formal-aa irundhudhu". Notes-a group pannunga. Periya groups thaan unga mudhal evals, mudinjaa code checks-aa ezhudhunga. Idhu pala neram oru mathiyaanam edukkum, aana thappaana vishayatha measure pannura vaaraakkanakka kaappaathum.

**Idha oru command-aa aakkunga.** Yaarum run pannaadha eval, eval-ae illa. Test set-a repository-la podunga, ovvoru case-aiyum run panni table-a print panra script ezhudhunga, ovvoru prompt, model, illa retrieval change-kum CI-la run pannunga. Ovvoru run-oda results-aiyum version-oda save pannunga, appo entha rendu-a venumnaalum compare pannalaam.

**Evvalavu cases.** Nalla select panna muppadhu cases perumbaalaana periya regressions-a pidikkum; nooru cases category-vaariyaa stable numbers tharum. Size-a vida mukkiyam coverage: users-ku mukkiyamaana ovvoru category-yum, escalations maadhiri critical categories-la oru miss theriyura alavukku podhumaana cases-um. Yezhu escalation cases-la oru miss-na 14-point drop, adha yaarum ignore panna mudiyaadhu. Product valara valara set-a valarunga, work panna panna seekiram run aagura, sumaar pathu cases-oda sinna "smoke" set-a thaniyaa pirichu vechikkunga.

**Kadaisi output mattum illa, ovvoru step-aiyum evaluate pannunga.** Oru app email-la irundhu details extract panni, apram reply draft pannudhu-na, extraction-a thaniyaavum test pannunga. Final score kuraindha, per-step scores edhu step odanjudhu-nu solludhu.

**Oru periya set illa, neraya sinna sets vachirukkunga.** Unmaiyaana traffic maadhiri irukkura oru set, app overall eppadi irukku-nu solludhu. Kashtamaana cases-oda oru set, app maruthuttu vidanum-ra out-of-scope inputs-oda oru set, unmaiyaana users anuppura typos, mixed languages, Romanised text irukkura oru set-aiyum serunga. Edhu pathi kavalai-nu irukko, adhukku oru test set kudunga.

**Difference unmaiyaanadhaa?** 60 cases-la 4-point gain noise-aa irukkalaam. OpenAI-oda oru podhuvaana vidhi: oru version nallaa irukku-nu sumaar 95% sure-aa irukka, 30-point difference-ku sumaar 10 cases, 10 points-ku 100, 3 points-ku 1,000, 1 point-ku 10,000 thevai. 3 madangu sinna difference-ku sumaar 10 madangu adhiga cases thevai. Adhanaala sinna sets-a periya regressions pidikka use pannunga, sinna gains-a nambradhukku munnaadi periya sets use pannunga.

**Bootstrap panni stability check pannunga.** Unga cases-a replacement-oda re-sample pannunga, ovvoru re-sample-aiyum score pannunga, score evvalavu aadudhu-nu paarunga. Oru re-sample 90% tharudhu, innonnu 70% tharudhu-na, versions-a compare panna set romba sinnadhu.

```python
import json, random, statistics
from collections import defaultdict

def run_eval(cases, app, checks):
    """cases: dicts with 'input', 'category' and expectations. checks: functions(case, output) -> bool."""
    rows = []
    for case in cases:
        out = app(case["input"])
        rows.append({"category": case["category"], "passed": all(check(case, out) for check in checks)})
    return rows

def report(rows, bootstraps=1000, seed=7):
    by_cat = defaultdict(list)
    for r in rows:
        by_cat[r["category"]].append(r["passed"])
    for cat, results in sorted(by_cat.items()):
        print(f"{cat:<12} {sum(results)}/{len(results)}")
    rng = random.Random(seed)
    scores = [statistics.mean(rng.choice(rows)["passed"] for _ in rows) for _ in range(bootstraps)]
    scores.sort()
    print(f"overall {statistics.mean(r['passed'] for r in rows):.0%}, "
          f"95% of re-samples between {scores[25]:.0%} and {scores[-26]:.0%}")

# report(run_eval(cases, my_app, [no_dosage_advice, keeps_policy_number, escalates_when_needed]))
```

Kadaisiyila print aagura range romba agalamaa irundhaa, sinna differences pathi vaadhaadradhukku munnaadi innum cases serunga.

**Misleading-aana averages-a gavanamaa irunga.** Categories-oda sizes romba maarupattaa, version A ellaa category-layum version B-a jeichaalum overall thorkalaam. Idhu Simpson's paradox. Total mattum illa, scores-a category-vaariyaa padikkanum-nu solla idhu innoru kaaranam.

**Model judge-a calibrate panradhu.** Rendu perai ore rubric vechu 30 outputs-a grade panna sollunga, apram judge-a grade panna sollunga. Ottippaarunga. Agreement kammi-na, rubric pereum clear-aa illa: pass, fail examples-oda rewrite panni, thirumba test pannunga. Judge-oda model illa prompt-a maathum podhellaam agreement-a thirumba check pannunga, judge-a temperature 0-la run pannunga, appo ore answer-ku ore grade kidaikkum. LLM judges pathiyum open-ended answers-a score panradhu pathiyum lessons innum aazhama pogum.

## Oru worked example

Pune insurance broker-oda assistant policyholder emails-ku replies draft panradhu. Pudhu prompt nalladhaa-nu team vaadhaadudhu.

Avanga oru eval build pannaanga:

- 60 unmaiyaana emails (anonymise panninadhu): 35 routine kelvigal, 10 claims-status queries, 8 complaints, 7 oru human thevaippadura (legal threats, medical details).
- Code checks: email-la policy number irundhaa reply-la irukkanum; entha reply-um claim approval promise pannakoodaadhu; yezhu escalation cases-um "needs human"-nu mark aagirukkanum.
- Rubric-oda oru model judge (policy wording-ku accurate-aa, ovvoru kelviyaiyum answer pannanum, polite-aa irukkanum), 30 replies-la rendu staff members-oda grades-oda calibrate pannadhu (85% agreement).

Results: pazhaya prompt judge-la 71% edukkudhu, 7-la 3 escalations-a miss pannudhu; pudhu prompt 78% edukkudhu, aana 4 escalations miss pannudhu. Rendumae ettukka mudiyaadhu. Moonaavadhu version-la explicit escalation rules serthaanga: 80%, 7-la 7 escalations-um pidichaachu. Oru mathiyaanathula table vaadhatha mudichudhu.

**Broker enna vechukittaanga.** Ippo team, ovvoru bad reply complaint-aiyum adhoda category-oda pudhu case-aa serkkuraanga. Moonu maadham kazhichu set 60-la irundhu 140 cases-aa valarndhuduchu, prompts pathi vaadhangal table-aala, perumbaalum nimishangalla mudinjudhu.

## Podhuvaa panra thappugal

- **Test set illaama irukkradhu.** Changes-a rendu moonu examples vechu judge panradhu.
- **Poi-aa ezhudhina test cases mattum.** Unmaiyaana inputs use pannunga.
- **Averages mattum paakkradhu.** Categories-a paarunga, especially safety cases.
- **Check pannaadha model judges.** Human grades-oda ottippaarunga.
- **Maaraama irukkura set.** Ovvoru pudhu failure-aiyum serunga.

## Oru small eval podhumaana neram

- **Aarambathula prototypes**: neenga kaiyaala padikkura 20 la irundhu 30 cases, oru complicated pipeline-a vida nalladhu.
- **Periya, theliva theriyura changes**, example oru pudhu model nallaa illa kettaa-nu thelivaa irundhaa, sinna set-lae theriyum.
- **Closed tasks**, example classification, judge illaama code-aalaeyae score pannalaam.

## Demo-la irundhu production-ku

- **Oru command, CI-la**: ovvoru prompt, model, retrieval, code change-kum eval-a run pannunga, oru critical category kettaa release-a block pannunga.
- **Results-oda sernthu ellathaiyum version pannunga**: test set, rubric, judge prompt-um model-um, app prompt-um settings-um, appo entha rendu runs-aiyum compare pannalaam.
- **Eval-a ae check pannunga**: adhiga scores, users-um reviewers-um nalladhu-nu solradhoda match aagudhaa? Rendu metrics eppavum serndhu moovaa irundhaa onna vittudunga; eppavumae oththu varalaina investigate pannunga.
- **Selavai gavanamaa irunga**: velai seiyum podhu quick smoke set-a, release-ku munnaadi full set-a run pannunga.
- **Production-a thirumba ulla kudunga**: logs, complaints, online evals-la irundhu varra failures ovvoru vaaramum pudhu cases aagum.
