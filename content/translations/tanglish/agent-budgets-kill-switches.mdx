## Idhu enna

Agents evvalavu steps edukkanum-nu avangalae mudivu pannuvaanga. Pothuva idhu avangaloda strength. Sila neram agent loop-la maattikkum: oru tool thirumba thirumba fail aagum, adhu thirumba thirumba retry pannum; rendu agents velaiya matha matha thirumba kudukkum; illa oru draft-a "improve" pannittae irukkum. Limits illaina, loop tokens-a eriyum, downstream systems mela bharam podum, actions-a thirumba seiyum.

Moonu controls idha thadukkum:

- **Loop limits**: oru task-ku maximum steps illa tool calls.
- **Budgets**: tokens, neram, panam mela caps; oru task-ku, oru user-ku, oru naalaikku, muzhu feature-kum.
- **Kill switches**: operator oru agent-a, tool-a, illa muzhu feature-a deploy illaama niruththura vegamaana, nambikkaiyaana vazhi.

```flow
Every task | 15 steps varai, 60,000 tokens varai, 90 s varai -> Shared store | database illa cache
Every tool call | kill switch on-aa? adhe call 3 thadava? niruththu; idempotency key set -> Shared store
Every day | user selavu ₹15 varai, feature ₹40,000 varai, ₹30,000-la alert -> Shared store
Shared store -> Provider spend limit | backstop
```

Indha lesson-la Bengaluru-la oru edtech company-oda homework-help agent-a follow pannuvom; adhu oru raathirila oru vaara budget-oda paththu madangu selavu pannuchu.

## Idhu eppadi work aagudhu

**Per-task limits.** Loop-la steps-um tool calls-um count pannunga, real runs-la irundhu choose pannina cap-la niruthunga (95% tasks 12 steps-la mudinjaa, cap 25). Tokens-um, aana neramum track pannunga. Limit-a thottaa neatta niruthunga: state-a save pannunga, enna mudinjadhu, enna micham-nu user-kitta sollunga, adha investigate panna vendiya failure-aa log pannunga.

**Repetition checks.** Adhe tool adhe arguments-oda thodarndhu pala thadava call aanaa, illa adhe error thirumba thirumba vandha, kandupidichu seekkiram niruthunga.

**Per-user, daily budgets.** Oru user-oda oru naal selavu-a count pannunga, cap-a thaandina nallaa maryaadhaiyaa maruththidunga. Muzhu feature-kum oru daily cap vainga, example 80%-la alert-oda. Idhellaam shared store-la (database illa cache) vainga, agent-oda memory-la illa, appadinaa ella servers-layum work aagum.

**Provider-side limits.** Perumbaalaana model providers oru key-ku illa project-ku spend limits, alerts set panna vidraanga. Idha kadaisi paadhukaappaa use pannunga, thaniyaa onnaa illa.

**Kill switches.** Ovvoru task-ku munnaadi, mudinjaa ovvoru tool call-ku munnaadiyum, ungaloda code check panra oru configuration flag, pala levels-oda: oru tool-a off panradhu (ella refunds-um niruththu), agent-a off panradhu (human queue-ku illa simple form-ku maaru), feature-a off panradhu. Redeploy illaama admin screen-la illa config service-la irundhu flip pannunga. Fire drill maadhiri adikkadi test pannunga.

**Actions-ku idempotency.** Ovvoru action-kum oru unique key kudunga, appadi irundhaa adhe key-oda retry aana, illa loop-la thirumba vandha "send refund" oru thadava mattum nadakkum.

**Control layers:**

| Layer | Example | Edhai niruththum |
| --- | --- | --- |
| Per task | 15 steps, 60,000 tokens, 90 seconds | Oru control illaama ooduradha task |
| Repetition | 3 adhe errors vandha task mudiyum | Retry loops |
| Per user per day | ₹15 model selavu | Oru user, illa oru script, budget-a kaali panradhu |
| Feature per day | ₹40,000, ₹30,000-la alert | Pala users-a paadhikkura oru fault |
| Kill switch | Ovvoru tool-kum agent-kum toggle | Edhaiyum, seconds-la |
| Provider limit | API project-la monthly hard cap | Matha ellaam fail aanaa |

**Kill-switch drill nadathuradhu.** Maasaththukku oru thadava, mudhalla staging-la, appuram production-la amaidhiyaana neraththula, ovvoru switch-aiyum flip panni moonu vishayam check pannunga: tasks seconds-kulla nikkudha, users-ku error illaama theliva oru message theriyudha, matha app work aagudha. Neram note pannunga, yaar pannaanga-nu ezhudhunga, thirumba on pannunga. Eppavum practice pannaadha teams, nijamaana incident-la thaan switch start-up-la mattum check aagudhu, illa on-call-la irukkura yaarukkum adhu enga irukku-nu theriyaadhu-nu kandupidippaanga.

**User-ku message-a choose panradhu.** Niruththappatta task crash maadhiri theriyakkoodaadhu. Enna nadandhudhu, user ippo enna seiyalaam-nu simple vaarthaila sollunga, example "Idha ennaala solve panna mudiyala; ungaloda teacher help pannuvaanga", illa "Homework help ippo rest-la irukku; naalaikku thirumba try pannunga." Ovvoru stop-aiyum reason-oda log pannunga, appadi irundhaa limits romba tight-aa-nu team paakkalaam.

**Code-la oru budget.** Atomic update-oda oru user-ku oru naal selavu-a count pannunga, appadi irundhaa rendu servers-um adhe user-a cap-a thaandi vida mudiyaadhu:

```python
import sqlite3
from datetime import datetime
from zoneinfo import ZoneInfo

db = sqlite3.connect("budgets.db", isolation_level=None)
db.execute("CREATE TABLE IF NOT EXISTS spend (user_id TEXT, day TEXT, paise INTEGER, PRIMARY KEY (user_id, day))")
DAILY_CAP_PAISE = 1500                                   # ₹15 per user per day

def today():
    return datetime.now(ZoneInfo("Asia/Kolkata")).date().isoformat()

def can_spend(user_id, estimate_paise):
    row = db.execute("SELECT paise FROM spend WHERE user_id=? AND day=?", (user_id, today())).fetchone()
    return (row[0] if row else 0) + estimate_paise <= DAILY_CAP_PAISE

def record_spend(user_id, paise):
    db.execute("""INSERT INTO spend (user_id, day, paise) VALUES (?, ?, ?)
                  ON CONFLICT(user_id, day) DO UPDATE SET paise = paise + excluded.paise""",
               (user_id, today(), paise))
```

Ovvoru model call-ku munnaadi estimate-oda `can_spend`-a check pannunga, appuram usage report-la irundhu unmaiyaana cost-a record pannunga. Panatha muzhu paise-la count pannunga, floating-point rupees-la illa. Postgres illa Redis-la idhe pattern `INSERT ... ON CONFLICT` illa expiry-oda `INCRBY`.

**Code-la oru kill switch.** Flags-a oru short cache-oda shared store-la irundhu padinga, appadi irundhaa maatram ellaa idathulayum seconds-kulla work aagum:

```python
import json, time

_cache = {"at": 0.0, "flags": {}}

def flags():
    if time.time() - _cache["at"] > 5:                   # refresh every 5 seconds
        _cache["flags"] = json.loads(config_store.get("agent_flags") or "{}")
        _cache["at"] = time.time()
    return _cache["flags"]

def allowed(agent, tool=None):
    f = flags()
    if f.get("all_agents_off") or f.get(f"{agent}_off"):
        return False
    return not (tool and f.get(f"tool_{tool}_off"))

# In the loop, before every model call and every tool call:
if not allowed("homework_helper", tool="send_email"):
    stop_cleanly("Homework help is resting; try again tomorrow.")
```

`config_store`-na ungalukku already irukkura edhaavadhu shared store: oru database row, Redis, illa feature-flag service. Store-a reach panna mudiyaala-naa, fail safe-aa irukkunga: write tools-a off-aa eduthukkunga.

**Numbers-a choose panradhu.** Limits-a real runs-la irundhu set pannunga, guess-la illa. Oru vaaraththula oru task-ku steps, tokens, cost distribution-a paarunga: 95% tasks 12 steps-llayum ₹2-llayum mudinjaa, 25 steps-um ₹6-um cap runaways-a niruththum, normal use-a paadhikkaadhu. Models illa prompts maatha podhu numbers-a thirumba paarunga, rendumae typical costs-a maathum.

**Wall-ku munnaadi alert.** Feature-wide budget, naal cap-oda 50%-layum 80%-layum team-a eccharikkanum, alert-la spend-padi top users-um top task types-um irukkanum, appadi irundhaa cap ellaarayum cut panradhukku munnaadi yaaraavadhu action edukkalaam.

## Oru worked example

Bengaluru edtech-oda homework-help agent oru maasam nallaa odiyadhu. Appuram oru Sunday raathiri, oru maths tool-la oru maatram, oru vagai kelvikku error kudukka vechudhu. Agent sinna variations-oda retry pannuchu, sila students "try again" press pannittae irundhaanga. Monday kaalaila oru feature ₹1.8 lakh selavu pannirundhudhu, oru normal vaarathoda paththu madangu.

Fixes:

- Per task: adhigamaa 15 steps, 60,000 tokens, 90 seconds. Moonu adhe tool errors thodarndhu vandha, "Idha ennaala solve panna mudiyala; ungaloda teacher help pannuvaanga"-nu task mudiyum.
- Per student: oru naalaikku ₹15 model selavu, adhu oru friendly "naalaikku vaanga" message-aa kaattum.
- Feature: oru naal cap ₹40,000, ₹30,000-la on-call engineer-oda phone-ku alert.
- Kill switch: ovvoru tool-kum muzhu agent-kum admin toggle, ovvoru task-ku munnaadi check aagum. Agent-a off pannaa "homework help rest-la irukku" banner theriyum, matha app odittae irukkum.
- Provider: backstop-aa API project-la oru hard monthly spend limit.

Rendu vaaram kazhichu oru ottha maadhiri tool fault, repetition check-naala nimishangal-la niruththappattu, ₹600 mattum selavaachu, edhavadhu student complain panradhukku munnaadiyae alert team-ku sollidhu.

| Incident | Cost | Eppadi mudinjadhu |
| --- | --- | --- |
| Limits illaama mudhal tool fault | Oru raathirila ₹1.8 lakh | Monday kaalaila thaan theriyum |
| Rendu vaaram kazhichu ottha maadhiri fault | ₹600 | Repetition check nimishangal-la niruthuchu; alert on-call-ku poyiduchu |

## Podhuvaa panra thappugal

- **Step cap illaama irukkuradhu.** Romba cheap-aana paadhukaappu; mudhalla idha serunga.
- **Budgets memory-la vachirukkuradhu.** Ovvoru server-um thaniyaa count pannum, unmaiyaana mothham cap-a vida romba thaandum. Shared store use pannunga.
- **Deploy venum-ra kill switch.** Incident-la seconds thevai, build pipeline illa.
- **Silent-aa niruththuradhu.** User-kitta enna nadandhuchu-nu sollunga, log pannunga; niruththappatta task oru bug, fix pannanum.
- **Non-idempotent actions-a retry panradhu.** Idempotency keys use pannunga, appadi irundhaa loops payments-a illa messages-a thirumba seiya mudiyaadhu.
- **Oru server-oda memory-la budgets.** Servers-la pirinju irukkura users cap-a pala madangu vaangiduvaanga.
- **Floating-point money.** Paise-a integers-aa count pannunga.
- **Start-up-la mattum padikkura kill switch.** Adutha restart varaikkum adhu onnum seiyaadhu.
- **Fail open aagradhu.** Flag store down-naa, risky tools-a off-aa eduthukkunga.

## Simple limits podhumaana neram

- **Ungaloda sondha team use panra prototype**: oru step cap-um provider-oda spend alert-um podhum.
- **Oru illa rendu model calls irukkura fixed workflows**, cost per request predict panna mudiyum.
- **Konjam users irukkura read-only internal tools.**

Veliyaal agent runs-a trigger panna mudiyum-nu irundhaa, illa agents action edukka mudiyum-nu irundhaa thaan per-user budgets, feature caps, layered kill switches mukkiyam.

## Demo-la irundhu production-ku

- **Budgets-um flags-um shared storage-la vainga**, ovvoru model, tool call-ku munnaadiyum check pannunga.
- **Daily limits-ku Asia/Kolkata days use pannunga**, appadi irundhaa users edhir paakkura neraththula reset aagum.
- **Feature budgets-la 50%-layum 80%-layum alert pannunga**, top spenders list-oda.
- **Kill switches-a maasam oru thadava drill pannunga**, ovvondrukkum evvalavu neram aachu-nu record pannunga.
- **Ovvoru stop-aiyum log pannunga**, reason-oda, limits sariyaa set aagirukka-nu review pannunga.

## Practice pannunga

OWASP-oda unbounded consumption entry-a padinga.

1. Neenga build panna oru agent-la step, token, time caps serunga, oru clean stop message-oda.
2. Moonu adhe tool errors-ku appuram task-a mudikkura oru repetition check serunga, oru kavanamaa udaicha tool-oda trigger pannunga.
3. Oru sinna database table-la per-user daily budget-um, config file-la irundhu padikkura oru kill switch-um serunga, rendum work aagradha kaattunga.
4. Ungaloda server-oda rendu copies odunga, oru user-ku rendu-layum requests anuppunga, shared budget innum cap-la niruththudhunnu prove pannunga.

**Mudinjadhu-nu eppo sollalaam:** Oru tool-a kavanamaa udaichu, agent ungaloda limits-kulla niruththuradhai, oru log entry-yum alert-yum-oda kaattalaam.
