## Idhu enna

**Sorting**-na items-a order-la vaikkiradhu. Data sort aanadhum, duplicates pakkathu pakkathula irukkum, extremes munaigalla irukkum, edhaiyum seekiram kandupidikkalaam.

**Binary search** sorted data-la oru item-a kandupidikka naduvula check panni, andha item irukka mudiyaadha paadhiya thookki podum. Ovvoru check-um meedhi irukkuradha paadhiyaakkum, adhanaala sumaar log₂ n checks podhum: 10 lakh items-ku 20, 1 crore-ku 24. Innum podhuvaa sonnaa, oru yes/no test "no"-la irundhu "yes"-ku enga flip aagudhu-nnu idhu kandupidikkum, udhaaranamaa "`a[i]` kuranjadhu x-aa?". Possible answers-oda oru range-a ippadi search panradhu thaan **binary search on the answer**.

**Two pointers** oru array vazhiyaa rendu positions-a nagarthi, nested loops-ku badhilaa ore pass-la pair, range problems-a solve pannum. **Sliding window**-na best contiguous stretch-kaana two-pointer pattern.

Appuram kaattappora `first_at_least` code vachchu 42-ku binary search (`lo = 0`, `hi = 10`-la aarambichu):

## Idhu eppadi work aagudhu

### Sorting algorithms-um avattroda cost-um

| Algorithm | Average time | Worst time | Extra space | Stable-aa? | Eppo idhu sariyaana choice |
|---|---|---|---|---|---|
| Insertion sort (bubble sort-um) | O(n²) | O(n²) | O(1) | aamaa | romba chinna alladhu kittathatta sorted lists; anga insertion sort O(n)-ku kitta irukkum |
| Merge sort | O(n log n) | O(n log n) | O(n) | aamaa | predictable time; linked lists; memory-ku romba perusaana files |
| Quicksort | O(n log n) | O(n²) | O(log n) | illa | memory-la vegam, random alladhu median-of-three pivot-oda |
| Heap sort | O(n log n) | O(n log n) | O(1) | illa | extra memory illaama oru guaranteed bound |
| Python-oda `sorted`, `list.sort` | O(n log n) | O(n log n) | O(n) varai | aamaa | real data, adhula adikkadi already order-la irukkura runs irukkum |
| Counting sort (radix sort idha vachchu build aagudhu) | O(n + k) | O(n + k) | O(n + k) | aamaa | chinna range k irukkura integer keys, 100-ku marks maadhiri |

**Merge sort** ovvoru piece-layum oru item varra varaikkum list-a paadhi paadhiyaa pirikkum, appuram munnaadi irukkura chinna item-a thirumba thirumba eduthu sorted pieces-a merge pannum: sumaar log₂ n levels, ovvonnulayum O(n) merging, adhanaala O(n log n).

**Quicksort** oru pivot-a eduthu, chinna items-a idadhu pakkamum perusaanadha valadhu pakkamum nagarthi, ovvoru pakkathaiyum sort pannum. Samamaana splits-na O(n log n). Already sorted data-la "eppavume mudhal item-a edu"-nnaa, ovvoru thadavaiyum n items 0, n − 1-aa split aagum, cost O(n²), adhanaala real implementations oru random pivot-aiyo median of three-aiyo edukkum.

**Python-oda sort**, podhuvaa Timsort-nu solluvaanga, merge sort-um insertion sort-um serndha oru hybrid. Already order-la irukkura runs-a kandupidichu, chinna runs-a insertion sort vachchu neetti, avattrai merge pannum, adhanaala already sorted-aa irukkura list-ku ore O(n) pass thaan. Python 3.11-la irundhu, merges-oda order-a Powersort strategy vachchu thernthedukkudhu.

**Comparison sorts yen O(n log n)-a beat panna mudiyaadhu.** n items n! orders-la irukkalaam, sort avattrai pirichu adaiyaalam kaananum. Ovvoru comparison-um best case-la possibilities-a paadhiyaakkum, adhanaala worst case-ku kuranjadhu log₂(n!) comparisons venum, thoraayamaa n log₂ n. 10 items-ku 10!-na 36,28,800, adhanaala kuranjadhu 22 comparisons. Counting sort compare pannave pannaadhadhaala indha limit-la irundhu thappikkudhu: 0-la irundhu 100 varai irukkura 10 lakh marks-a 101 counters vachchu ore pass-la sort pannum.

### Stability-um sort keys-um

Equal keys irukkura items avattroda original order-a vachchukkittaa andha sort **stable**. Multi-key sorts-ku idhu mukkiyam. Ovvoru city-kkulleyum dates order-la irukkura maadhiri orders-a city-padi list panna, mudhalla date-padi sort panni appuram city-padi sort pannalaam: rendaavadhu sort stable-aa irukkuradhaala mattum thaan ore city irukkura items-kkulla date order appadiye irukkum. Python-la ore step-la `sorted(orders, key=lambda o: (o.city, o.date))` adhe result-a tharum. `reverse=True` irundhaa kooda Python stability-a guarantee pannudhu; C++ `std::sort`, heap sort, oru typical quicksort guarantee pannaadhu.

### Full sort venumaa?

- **Miga chinnadhu alladhu miga perusu mattum venum-naa:** `min()` alladhu `max()`, ore O(n) pass.
- **1 crore scores-la top 10:** `heapq.nlargest(10, scores)` 10 items irukkura oru heap-a vachchukkum, k = 10-oda sumaar O(n log k).
- **Exact lookups mattum-naa,** "Indha PAN list-la irukkaa?" maadhiri: oru thadavai `set` build pannunga, appuram ovvoru lookup-um average-la O(1). Order venumbodhu sort pannunga: ranges, "idhukku alladhu idhukku appuram varra mudhal", miga kittathula irukkura value, ranks.

### Off-by-one bugs illaama binary search

Perumbaalaana bugs conventions-a kalakkuradhaala thaan varudhu. Nambagamaana oru convention **half-open range**: answer eppavume `lo`-la irundhu `hi` varai engayaavadhu irukkum, rendum sandhikkumbodhu niruthuveenga.

```python
def first_at_least(a, x):
    """Index of the first item that is at least x; len(a) if there is none."""
    lo, hi = 0, len(a)            # the answer is always in lo..hi
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < x:
            lo = mid + 1          # mid and everything left of it is too small
        else:
            hi = mid              # mid might be the answer, so keep it
    return lo

marks = [10, 20, 20, 20, 30]
print(first_at_least(marks, 20))   # 1
print(first_at_least(marks, 99))   # 5, which is len(marks): not found
```

Ovvoru pass-um range-a surukkum, adhanaala loop mudiyum. 20-ku adhu indices 2, 1, 0-a check panni 1-a return pannum, adhaavadhu moonu 20-galla mudhal onnu. Python-oda `bisect.bisect_left` panradhum idhaith thaan, adhanaala real code-la library-a call pannunga:

| Call | Enna return pannum | `[10, 20, 20, 20, 30]`-la |
|---|---|---|
| `bisect_left(a, x)` | item kuranjadhu x-aa irukkura mudhal index | `bisect_left(a, 20)`-na 1 |
| `bisect_right(a, x)` | item x-a vida perusaa irukkura mudhal index | `bisect_right(a, 20)`-na 4 |
| `bisect_right(a, x) - bisect_left(a, x)` | x-ku equal-aa etthana items | 4 − 1 = 3 |
| result `len(a)`-ku equal | edhuvume qualify aagala | `bisect_left(a, 99)`-na 5 |

Adhanaala x irundhaa, adhu mudhalla `bisect_left`-layum kadaisiyaa `bisect_right(a, x) - 1`-layum varum.

32-bit integers irukkura Java alladhu C++-la, `lo + hi` sumaar 2.1 billion-a thaandinadhum `(lo + hi) / 2` overflow aagalaam; Java-voda sondha library-laye indha bug irundhadha 2006-la Joshua Bloch vivarichaaru. Anga `lo + (hi - lo) / 2`-nu ezhudhunga. Python integers overflow aagaadhu.

### Binary search on the answer

Neraya problems "work aagura miga chinna value"-a kekkum: oru capacity, oru daily limit, miga mundhaiya naal. "v work aagumaa?" test **monotonic**-aa irundhaa (oru thadavai yes-na, adha vida periya ella v-kkum yes), possible answers-oda range-a binary search pannunga. `first_at_least` template-a use pannunga, `a[mid] < x`-ku badhilaa "mid work aagaadhu"-nu maathunga. Idhukku sumaar log₂(range-oda size) checks aagum, ovvonnum test-oda oru run.

Precondition thaan ellathaiyum vida mukkiyam. "Day d-kkulla cumulative sign-ups 50,000-a reach pannidichaa?" monotonic, yenna totals eppavume kuraiyaadhu. "Andha naaloda sales ₹1 lakh-ukku melayaa?" yes, no, yes-nu pogalaam, binary search endha error-um illaama oru thappaana naala return pannum.

Oru rate maadhiri real-valued answer-ku, floats sandhikkaamale pogalaam: fixed ennikkaiyila halvings run pannunga, udhaaranamaa 60, illanna `hi - lo` ungalukku venum-ngura precision-a vida kuranjadhum niruthunga.

### Two pointers-um sliding windows-um

**Pair method yen sariyaa irukku.** Meedhi irukkura miga chinna item-um miga periya item-um koottinaa romba kuraivaa varudhu-nnu vachchukkonga. Miga chinna item-oda meedhi irukkura vera edha koottinaalum innum chinnadhaa thaan varum, adhanaala adhu endha answer-layum irukka mudiyaadhu, adha viduradhu safe. Sum romba perusaa irukkumbodhu idhe logic miga periya item-a vidum. Ovvoru step-um oru item-a eduthudum, adhanaala adhigabatcham n − 1 steps thaan.

```python
def has_pair(prices, target):
    left, right = 0, len(prices) - 1
    while left < right:
        total = prices[left] + prices[right]
        if total == target:
            return prices[left], prices[right]
        if total < target:
            left += 1             # need a bigger sum
        else:
            right -= 1            # need a smaller sum
    return None

print(has_pair([5, 12, 18, 25, 30, 38, 45], 56))   # (18, 38)
```

Unsorted data-ku, mudhalla sort pannunga (O(n log n)), illanna oru set vachchu ore pass pannunga, `target - p` already paarthaachaa-nnu check pannunga (O(n) time-um memory-um).

**Sliding window** adhoda right edge-a oru thadavaikku oru step valarkkum, rule udainjirukkura varaikkum left edge-a surukkum. Surukkuradhu eppavume rule-a meet panradha easy-aakkinaa mattum thaan idhu sari. "Total budget-kkulla" rule-ku andha property ovvoru value-um zero alladhu adhukku mela irundhaa mattum thaan irukkum.

### Pattern-a adaiyaalam kaanuradhu

```flow
title: Endha pattern porundhum?
Contiguous stretch-aa? -[aamaa]-> Sliding window | O(n); surukkuradhu udhavanum
Contiguous stretch-aa? -[illa]-> Oru target-oda pair-aa?
Oru target-oda pair-aa? -[aamaa, sorted]-> Two pointers | O(n) time, O(1) memory
Oru target-oda pair-aa? -[aamaa, unsorted]-> Hash set | O(n) time-um memory-um
Oru target-oda pair-aa? -[illa]-> Work aagura mudhal, kadaisi alladhu miga chinnadhaa?
Work aagura mudhal, kadaisi alladhu miga chinnadhaa? -[test monotonic]-> Binary search | O(log n) checks
Work aagura mudhal, kadaisi alladhu miga chinnadhaa? -[test munnum pinnum flip aagudhu]-> Scan pannu alladhu marubadi yosi
```

Interview-la, code panradhukku munnaadi pattern-aiyum adhoda precondition-aiyum (sorted, monotonic alladhu non-negative) sollunga.

## Oru worked example

Sneha, Hyderabad-la oru online coaching platform-ku analytics paarkkuraanga. Numbers udhaaranathukkaaga mattum thaan.

### 1. Budget-kkulla irukkura miga neelamaana naatkal run

Thodarchiyaana naatkalla total ad spend ₹1 lakh-ukkulla irundha miga neelamaana run edhu? Oru varushathula 66,795 possible runs irukku (365 × 366 ÷ 2), adhanaala ellathaiyum check pannaa O(n²). Oru sliding window ore pass-la mudikkum:

```python
def longest_within(spend, budget):
    best = total = left = 0
    for right, amount in enumerate(spend):
        total += amount                   # grow: day `right` joins
        while total > budget:             # shrink until within budget
            total -= spend[left]
            left += 1
        best = max(best, right - left + 1)
    return best

week = [30, 20, 40, 10, 25, 60, 15]       # spend in thousands of rupees
print(longest_within(week, 100))          # 4
```

Oru vaarathukkaana trace, budget 100 (₹1 lakh):

| Naal | Spend | Surukkinadhukku appuram window | Total | Idhuvarai best |
|---|---|---|---|---|
| 1 | 30 | naal 1 mudhal 1 | 30 | 1 |
| 2 | 20 | naal 1 mudhal 2 | 50 | 2 |
| 3 | 40 | naal 1 mudhal 3 | 90 | 3 |
| 4 | 10 | naal 1 mudhal 4 | 100 | 4 |
| 5 | 25 | naal 2 mudhal 5 (naal 1 drop aachu) | 95 | 4 |
| 6 | 60 | naal 4 mudhal 6 (naal 2, 3 drop aachu) | 95 | 4 |
| 7 | 15 | naal 5 mudhal 7 (naal 4 drop aachu) | 100 | 4 |

Answer 4 naal (naal 1 mudhal 4). Ovvoru naalum oru thadavai join aagum, adhigabatcham oru thadavai veliye pogum, adhanaala adhigabatcham 2n steps: O(n). Naal 6-la oru shrink step podhala, adhanaala thaan code `if` illaama `while` use pannudhu.

Spend eppavume negative aagaadhadhaala mattum thaan idhu safe. Figures-la net refunds-a serthaa idhu udaiyum: `[80, 30, -50]`-um budget 100-um irundhaa, total 110-a thodumbodhu window naal 1-a drop panni 2-nu report pannum, aanaa moonu naalum serthu total 60, adhanaala unmaiyaana answer 3. Negative values irundhaa, prefix sums maadhiri vera method use pannunga.

### 2. Sign-ups oru target-a reach panra mudhal naal

Finance kekkudhu: cumulative sign-ups endha naalla mudhal thadavaiyaa oru target-a reach pannuchu? Sign-ups eppavume negative illa, adhanaala "day d-kkulla reach aachaa?" no, no, appuram adhukku appuram varra ovvoru naalukkum yes. Adhu monotonic:

```python
from bisect import bisect_left
from itertools import accumulate

def first_day_reaching(daily, target):
    totals = list(accumulate(daily))      # running totals, O(n)
    i = bisect_left(totals, target)       # first day whose total is at least target
    return i if i < len(totals) else -1   # len(totals) means never reached

print(first_day_reaching([120, 90, 200, 150, 80], 400))   # 2
print(first_day_reaching([120, 90, 200, 150, 80], 9999))  # -1
```

Idhu `first_at_least` template thaan, library pannudhu. Totals moonaavadhu naalla, adhaavadhu index 2-la, 410-a reach pannudhu.

`totals` build panradhe oru O(n) pass, adhanaala ore oru target-ku oru saadhaarana scan-um adhe alavu nalladhu thaan. Avanga neraya targets-ku badhil sollumbodhu thaan search laabam: oru varusha daily data-ku ovvonnukkum sumaar 9 checks, pathu varusha hourly data-ku (87,600 hours) sumaar 17.

### 3. Endha list-layum illaadha oru answer-a search panradhu

Mentors assignment batches-a submission order-la grade panraanga. Indha vaarathoda ezhu batches-la 40, 25, 35, 50, 20, 30, 45 pages irukku, ellathaiyum 3 naalla grade pannanum, ovvoru naaloda batches-um oru daily page limit-kkulla irukkanum. Work aagura miga chinna limit edhu?

Answer 50 (miga periya batch fit aaganum)-kkum 245 (ellaame ore naalla)-kkum naduvula irukku, periya limit-ku eppavume adhiga naatkal thevaippadaadhu, adhanaala test monotonic:

```python
def days_needed(pages, limit):
    days, today = 1, 0
    for p in pages:
        if today + p > limit:             # today is full; start a new day
            days, today = days + 1, 0
        today += p
    return days

def smallest_limit(pages, max_days):
    lo, hi = max(pages), sum(pages)       # smallest and largest sensible answers
    while lo < hi:
        mid = (lo + hi) // 2
        if days_needed(pages, mid) <= max_days:
            hi = mid                      # mid works; try smaller
        else:
            lo = mid + 1                  # too small; go bigger
    return lo

print(smallest_limit([40, 25, 35, 50, 20, 30, 45], 3))    # 95
```

Answer oru naalaikku 95 pages: 40 + 25, appuram 35 + 50, appuram 20 + 30 + 45. 94 limit-ku 4 naal venum. Search 196 possible limits-a 7 checks-la cover pannudhu, ovvoru check-um oru O(n) pass.

## Podhuvaana thappugal

**Unsorted data-layo monotonic illaadha test-layo binary search panradhu.** Thappaana answer varum, error edhuvum varaadhu. Test "no, appuram yes"-nu pogudhu, thirumbi varave varaadhu-nnu prove pannunga.

**Off-by-one bounds.** Inclusive `hi`-yaiyum exclusive `hi`-yaiyum kalakkuradhu, illanna `mid` round down aagumbodhu `lo = mid`-nu ezhudhuradhu, rendu items meedhi irukkumbodhu loop-a nikkaama oda vaikkum. Half-open template maadhiri ore convention-a use pannunga, lengths 0, 1, 2-a test pannunga. Java alladhu C++-la `lo + (hi - lo) / 2`-num ezhudhunga.

**bisect-oda result-a check pannaama use panradhu.** Edhuvume qualify aagalai-nnaa `bisect_left` `len(a)`-a return pannum, adhanaala adha vachchu index pannaa `IndexError` varum.

**Loop-kkulla sort panradhu.** Loop-ku veliye oru thadavai sort pannunga. Full order-a vida kuraivaa venumbodhu `min()`, `heapq.nlargest` alladhu oru set use pannunga.

**Ella sort-um stable-nu nenaikkiradhu.** C++ `std::sort`, heap sort, perumbaalaana quicksorts stable illa, adhanaala two-step multi-key sort thappaa varalaam.

**Unsorted data-la two pointers use panradhu.** Mudhalla sort pannunga, illanna hash set use pannunga.

**Negative values irukkumbodhu sum-based sliding window use panradhu.** Refunds alladhu losses adha sathamillaama udaichudum. Ovvoru value-um zero alladhu adhukku mela-nnu check pannunga.

**Window-a `while`-ku badhilaa `if` vachchu surukkuradhu.** Trace-la naal 6 kaatura maadhiri, oru step podhaama pogalaam.
