## Idhu enna

**Total cost of ownership (TCO)**-naa oru system-kku oru kaalathula, podhuvaa onnula irundhu moonu varushathula, aagura ella selavum, model bill mattum illa. Idhoda velai options-a niyaayamaa compare panna udhavuradhum, client-kku oru nermaiyaana budget kudukkuradhum dhaan.

| Cost line | Adhula enna varum | Makkal enna marandhudraanga |
|---|---|---|
| Model | API moolamaa tokens, illa self-host pannaa GPUs (vaadagaikku illa vaanginadhu) | Maranjirukkura reasoning tokens; idle-aa irukkumbodhum bill aagura GPUs |
| Infrastructure | App compute, databases, vector store, storage, gateways, monitoring | Log, trace storage, staging environments |
| People | Build, operate, on-call, evaluations, upgrades | On-call cover-kku thevaippadura rendaavadhu engineer |
| Data | Connectors, pipelines, golden sets, documents-a clean-up panradhu | Embedding model maarumbodhu re-embedding |
| Compliance | Audits, penetration tests, security, legal reviews | Ovvoru periya maatrathukku appuramum marupadi reviews |
| Change | Model upgrades, oru provider model-a retire pannumbodhu prompt-a marupadi velai paarkkuradhu | Ovvoru pudhu model-layum evals-a marupadi run panradhu |
| India-specific | Cloud, API bills mela GST, dollar prices mela exchange rate | GST oru nija cost-aa, illa thirumba claim panna mudiyumaa |

```flow
dir: LR
title: Alandha usage-la irundhu oru mudivu varai
Alandha usage | traces, load tests -> API option | tokens, infra, people
Alandha usage -> Self-hosted option | nija utilisation-la GPUs, infra, people
API option -> Sensitivity, crossover
Self-hosted option -> Sensitivity, crossover
Sensitivity, crossover -> Oru claim-kku cost vs oru claim-kku value
```

## Idhu eppadi velai seiyudhu

### Alandha usage-la irundhu aarambinga

Users, oru user-kku oru naalaikku requests, peak vs average, varushathula growth idhaiyellaam collect pannunga. Appuram makkal podhuvaa oogikkura moonu vishayangala traces-la irundhu alanga:

- **Oru user action-kku calls.** Oru agent illa oru retrieval pipeline oru kelvikku moonula irundhu aaru model calls pannalaam: query-a rewrite panradhu, retrieve panradhu, answer panradhu, check panradhu. Cost oru call-kku dhaan, oru kelvikku illa.
- **Oru call-kku input tokens.** Retrieve aana passages perumbaalum input-a user-oda kelviya vida pala madangu perisaakkidum.
- **Reasoning udpada, oru call-kku output tokens.** Reasoning models answer panradhukku munnaadi yosikkum. Andha thinking maranjirukkum, aanaa output tokens-aa bill aagum (OpenAI-oda documentation idha velippadaiyaa solludhu). Oru chinna visible answer-kku pinnaadi oru neelamaana invisible bill irukkalaam.

### API option

Oru call-kku cost = input tokens × input price + output tokens × output price. Appuram moonu adjustments pannunga:

- **Prompt caching.** Ovvoru call-layum marupadi padikkappadura oru fixed system prompt illa shared document prefix, caching kudukkura providers-kitta saadhaarana input price-oda oru chinna pangukku bill aagum.
- **Batch discounts**: overnight summaries maadhiri, manikkanakkaa kaathirukkakkoodiya velaikku.
- **Tiering.** Simple requests-a (lookups, classification) oru malivaana, chinna model-kku anuppunga, kashtamaanadhukku periya model-a vachukkonga.

Perumbaalaana API prices US dollars-la irukku, adhanaala rupee rate-um oru input dhaan. Prices-a provider-oda page-layum Artificial Analysis maadhiri oru independent comparison-layum padinga, ovvonnu pakkathulayum check panna date-a ezhudhunga.

### Self-hosted option

GPUs-a oru spare-oda **peak**-kku size pannanum, unga latency target-la unga sondha prompts-a vachu panna oru load test-la irundhu. Appuram busy-aa irundhaalum illannaalum maasathoda ovvoru mani nerathukkum kaasu kudukkureenga. Case-a decide panra number **utilisation**:

utilisation = serve panna requests ÷ maasathula fleet serve panniyirukkakkoodiya requests

Working days-la oru naalaikku onbadhu mani neram use aagura, month-end peak-kku size panna oru office tool perumbaalum 10% illa adhukkum kuraivaana utilisation-la dhaan odum. 10% utilisation-la ovvoru request-um full use-la aaguradha vida pathu madangu GPU cost-a sumakkum.

Rendu pricing choices mukkiyam:

- **On-demand** GPUs-kku oru mani nerathukku aagura cost dhaan miga adhigam, aanaa adhai release pannidalaam.
- **Reserved** GPUs (oru varusham illa moonu varusha commitment) oru mani nerathukku kuraivaana cost, aanaa usage koranjaalum API prices irangunaalum neenga kaasu kuduthe aaganum.

Serving stack-a run panna, patch panna, models-a upgrade panna, pager-a sumakka thevaiyaana aalungalaiyum, unga evals-la open model kuraivaa score pannaa andha quality gap-aiyum serunga.

### India-specific lines

- **GST.** Cloud, API services-kku podhuvaa 18% GST varum (November 2026 nilavarappadi IT, cloud services-kkaana vazhakkamaana rate). Oru foreign provider-kitta vaangura oru GST-registered business podhuvaa adha reverse charge-la kattum, adha input tax credit-aa thirumba claim pannalaam. Credit claim panna mudiyaadha oru organisation-kku adhu nija cost. Endha case porundhum-nu client-oda finance team-kitta kelunga; indha lesson-la irukkura figures ellaam GST-kku munnaadi.
- **Exchange rate.** Rupee irangumbodhu dollar-la price aana oru API bill erum. November 2026 naduvula rupee oru vaarathukkulla oru dollar-kku sumaar ₹94.2-la irundhu sumaar ₹93.5-kku nagarndhuchu; ₹100-kku ponaa model line-la sumaar 7% koodum. Rate-a sensitivity table-la podunga.
- **Region.** Data rules oru Indian cloud region-a kattaayamaakkalaam. Neenga price panna model illa GPU type anga kidaikkudhaa, andha region-oda price-la, check pannunga.

### Sensitivity-um crossover-um

Oru nerathula oru assumption-a mattum maathi rendu options-aiyum marupadi kanakku podunga: usage paadhiyaa, rendu madangaa; outputs rendu madangu neelamaa; API prices 30% kuraivaa; weak-aana rupee; load test-la irundhu kuraivaana GPU throughput. Ore oru exact number-la mattum nikkura mudivu fragile.

**Crossover**-naa endha usage-kku mela innoru option thodarndhu malivaa irukkumo andha usage. Rendu traps:

- **Steps.** GPUs muzhu units-aa dhaan varum, adhanaala ovvoru thadavai onnu serkkumbodhum self-hosted line jump aagum. Oru spreadsheet oru volume-la self-hosting jeyikkura maadhiriyum adhukku konjam mela thokkura maadhiriyum kaattalaam. Endha volume-kku mela adhu thodarndhu jeyikkudho adha report pannunga.
- **Thin margins.** Oru extra request-kku API-kkum GPU-kkum kittathatta ore cost-naa, chinna maatrangalukke crossover bayangaramaa aadum. Adha velippadaiyaa sollunga.

### Price trends

Oru kurippitta quality level-kkaana API prices vegamaa koranjirukku. Oru fixed benchmark score-a ettura models-oda per-token price varushathukku 9-la irundhu 900 madangu varai koranjadhu-nnu Epoch AI March 2025-la estimate pannuchu; endha performance level alakkappattuchu-ngaradha poruthu adhu maarum. Avai oru token-kkaana prices, reasoning models oru task-kku innum niraiya tokens use pannalaam. Moonu varusha GPU commitment indha trend-kku edhiraa pandhayam kattudhu, adhanaala adha oru "prices 30% kuraivu" row-oda test pannunga.

### Marupadi run pannakkoodiya oru cost model

Ella assumptions-aiyum ore idathula, check panna date-oda vachukkonga. Keezha irukkura ovvoru number-um illustrative, worked example-kku match aagura maadhiri therndheduthadhu:

```python
import math

# Every number is illustrative. Replace each with your own dated quote or measurement.
P = {"rate_date": "2026-11-19", "usd_to_inr": 93.5,        # rupees per US dollar, about mid-November 2026
     "in_per_m": 3.0, "out_per_m": 15.0,                    # USD per million tokens, a mid-tier API model
     "cache_ratio": 0.1,                                    # cached input billed at 10% of the input price
     "gpu_month": 250_000,                                  # one rented GPU, on demand, all 730 hours
     "gpu_rps": 1.2,                                        # requests per second per GPU, from YOUR load test
     "engineer_month": 200_000,                             # loaded monthly cost of one engineer
     "busy_seconds": 22 * 9 * 3600,                         # 22 working days of 9 busy hours
     "peak_factor": 2.0}                                    # month-end peak against the busy-hour average

def api_month(req, p=P, in_tok=3000, out_tok=300, cached=0.4, small_share=0.4, small_ratio=0.25):
    in_usd = in_tok * (1 - cached + cached * p["cache_ratio"]) * p["in_per_m"] / 1e6
    per_req = (in_usd + out_tok * p["out_per_m"] / 1e6) * (1 - small_share + small_share * small_ratio)
    return req * per_req * p["usd_to_inr"] + 120_000 + 0.3 * p["engineer_month"]   # + infra + 0.3 engineer

def gpus(req, p=P):
    peak_rps = req / p["busy_seconds"] * p["peak_factor"]
    return math.ceil(peak_rps / p["gpu_rps"]) + 1                                   # + one spare

def self_month(req, p=P):
    return gpus(req, p) * p["gpu_month"] + 150_000 + 1.5 * p["engineer_month"]       # + infra + 1.5 engineers

def utilisation(req, p=P):
    return req / (gpus(req, p) * p["gpu_rps"] * 730 * 3600)

def crossover(p=P, limit=30_000_000, step=100_000):
    """Volume above which self-hosting stays cheaper, or None if it never does up to the limit."""
    last_api_win = 0
    for r in range(step, limit + 1, step):
        if self_month(r, p) >= api_month(r, p):
            last_api_win = r
    return None if last_api_win == limit else last_api_win + step

base = 1_100_000
print(f"Illustrative prices, rupee rate of {P['rate_date']}")
print(f"measured: API ₹{api_month(base)/1e5:.1f} lakh, self-hosted ₹{self_month(base)/1e5:.1f} lakh, "
      f"{gpus(base)} GPUs at {utilisation(base):.0%} utilisation")
scenarios = {"as measured": {}, "reserved GPUs at ₹1.6 lakh": {"gpu_month": 160_000},
             "load test gives 1.0 req/s": {"gpu_rps": 1.0}, "API prices 30% lower": {"in_per_m": 2.1, "out_per_m": 10.5},
             "rupee at ₹100": {"usd_to_inr": 100},
             "reserved, API 30% lower": {"gpu_month": 160_000, "in_per_m": 2.1, "out_per_m": 10.5}}
for name, change in scenarios.items():
    p = {**P, **change}
    c = crossover(p)
    print(f"{name:<27} API ₹{api_month(base, p)/1e5:4.1f} lakh  self ₹{self_month(base, p)/1e5:4.1f} lakh  "
          f"crossover {'none below 30M' if c is None else f'{c/1e6:.1f}M'}")
```

## Oru worked example

Oru Kolkata insurance company 2,000 staff-kku oru claims-document assistant-a roll out panna plan pannudhu. Pilot-la alandhadhu: 22 working days-la oru user-kku oru working day-kku 25 requests, oru request-kku 3,000 input tokens (perumbaalum retrieve aana passages), 300 output tokens, oru request-kku oru model call. Adhu 2,000 × 25 × 22 = maasathukku 1.1 million requests. Month-end traffic saadhaarana busy-hour rate-a vida rendu madangu. Ella prices-um code-la irukkura illustrative prices dhaan.

**Option A, avanga cloud moolamaa API.** Oru request-kku: 3,000 × $3 ÷ 1,000,000 + 300 × $15 ÷ 1,000,000 = $0.0135, ₹93.5-la sumaar ₹1.26. 1.1 million requests-kku adhu maasathukku sumaar ₹13.9 lakh. Fixed system prompt-aiyum instructions-aiyum (input tokens-la 40%) cache pannaa adhu sumaar ₹10.6 lakh-kku varum. 40% requests-a, adhaavadhu simple lookups-a, kaalvaasi price-la irukkura oru model-kku anuppunaa adhu sumaar ₹7.4 lakh-kku, adhaavadhu oru request-kku ₹0.67-kku varum. ₹1.2 lakh infrastructure-um oru engineer-oda 30%-um serthaa: sumaar **maasathukku ₹9.2 lakh**.

**Option B, self-hosted open model.** Oru GPU latency target-la oru second-kku 1.2 requests serve pannudhu-nnu load test kaattudhu. Month-end peak oru second-kku sumaar 3.1 requests, adhanaala moonu GPUs kooda oru spare: naalu GPUs, ovvonnum ₹2.5 lakh, mothham ₹10 lakh. ₹1.5 lakh infrastructure-um, serving, upgrades, on-call-kku onnara engineers-um (₹3 lakh) serthaa: sumaar **maasathukku ₹14.5 lakh**. Evals-la accuracy 2 points kuraivu. Fleet 9% utilisation-la odudhu, yenna adhu month-end-kku size pannappattu, ovvoru raathirikkum weekend-kkum kaasu kudukkappadudhu.

| Maasathukku (illustrative) | Option A: API | Option B: self-hosted |
| --- | --- | --- |
| Model | Caching, tiering-kku appuram sumaar ₹7.4 lakh | 9% utilisation-la naalu GPUs-kku ₹10 lakh |
| Infrastructure | ₹1.2 lakh | ₹1.5 lakh |
| People | 0.3 engineer, ₹0.6 lakh | 1.5 engineers, ₹3 lakh |
| Evals-la quality | Baseline | 2 points kuraivu |
| Maasathukku mothham | Sumaar ₹9.2 lakh | Sumaar ₹14.5 lakh |
| Varushathukku mothham | Sumaar ₹1.1 crore | Sumaar ₹1.74 crore |

**Crossover enga?** API-la ovvoru extra request-kkum sumaar ₹0.67 aagum. Average-a vida rendu madangukku size panna oru GPU-la adhu sumaar ₹0.58. Vithiyaasam verum onbadhu paise dhaan, adhanaala spare GPU-vaiyum extra engineers-aiyum eedu katta self-hosting-kku romba periya volume venum. On demand-la, maasathukku sumaar 8.3 million requests-kku mela dhaan adhu thodarndhu jeyikkum, adhaavadhu innaikku volume-a vida ezhula irundhu ettu madangu. ₹1.6 lakh-la reserved GPUs-naa, adhu sumaar 1.9 million-kku irangudhu: nerukkamaa irukku. Aanaa load test 1.2-kku badhilaa oru second-kku 1.0 request-nu kaattiyirundhaalo, API prices 30% koranjirundhaalo, on-demand crossover-e irundhirukkaadhu. Andha fragility dhaan finding.

**Decision.** A-va therndhedunga. Plan-la rendu review triggers ezhudhunga: monthly volume 1.5 million-a thaandumbodhu, oru reserved GPU quote vaangi load test-a marupadi run pannunga; API price, rupee rate illa oru data rule eppo maarinaalum, model-a marupadi run pannunga. API prices podhuvaa kuraiyura pokkula irukkumbodhu oru varusha reservation cost-a lock pannidum-nu recommendation-la note pannunga; API prices 30% koranjaa, reserved crossover sumaar 6.1 million varai thalli pogum.

**Value side.** Maasathukku 40,000 claims-la oru claim-kku 9 nimisham micham-nu pilot kaattuchu, adhaavadhu sumaar 6,000 staff hours. Oru mani nerathukku ₹400 illustrative loaded staff cost-la, adhu oru claim-kku ₹60 madhippulla neram, oru claim-kku sumaar ₹23 AI cost-kku edhiraa (₹9.2 lakh ÷ 40,000). Leadership team nyaabagam vachukkapporadhu andha ratio dhaan, token bill illa.

## Podhuvaana thappugal

- **Token price-a GPU rent kooda compare panradhu.** Rendu pakkathulayum ella lines-aiyum ennunga: people, infrastructure, evals, change. Rendu options-layum romba adikkadi vidupadura line people dhaan.
- **Usage-a oogikkuradhu.** Retrieve aana context-um maranjirukkura reasoning tokens-um serthu, oru user action-kku calls, oru call-kku tokens-a traces-la irundhu alanga.
- **Average-kku size panradhu, illa full utilisation-nu ninaikkuradhu.** GPUs peak-a cover pannanum, maasam muzhukka bill aagum. Utilisation-a model-la podunga.
- **Mudhal crossover-a namburadhu.** Muzhu-GPU steps lines-a cross pannavum uncross pannavum vaikkum. Stable point-aiyum adhu evvalavu nagarudhu-nnum report pannunga.
- **Price-fall row illaama GPUs-a reserve panradhu.** API prices irangumbodhu oru neenda commitment pazhasaagi nashtam tharalaam.
- **Rupee-yaiyum GST-yaiyum kandukkaama viduradhu.** Oru dollar bill exchange rate kooda nagarum, thirumba claim panna mudiyalainnaa GST nija cost.
- **Date illaadha prices.** Sila maasangalukkulla avai sathamillaama thappaagidum.
- **Value side illaadhadhu.** Michamaana hours illa errors illaadha oru cost model edhaiyum justify panna mudiyaadhu.

## Oru detailed cost model eppo thevaiyilla

- **Oru chinna, fixed budget-kkulla irukkura pilot**: oru spend cap-um vaarathukku oru thadavai bill-a paarkkuradhum podhum.
- **Nijamaana alternative illaadhappo**, udhaaranamaa data rules on-premises hosting-a kattaayamaakkumbodhu: cost-a budgeting-kkaaga model pannunga, choose panradhukkaaga illa.
- **Romba chinna usage**, value pakkathula cost oru rounding error maadhiri irukkumbodhu.
