## Idhu enna

LangGraph oru open-source Python, JavaScript framework. Agents-aiyum multi-step AI workflows-aiyum **graphs**-aa build panna idhu udhavudhu. Oru graph-kku naalu pagudhigal:

- **State**: run-kku therinja ellaathaiyum vachirukkura oru typed dictionary, udhaaranamaa messages, ticket id, propose panna oru credit.
- **Nodes**: state-a padichu, avai maathura fields-a mattum thirumbi kudukkura functions. Oru node oru model-a call pannalaam, oru tool-a call pannalaam, illainna plain code ottalaam.
- **Edges**: aduthu endha node odanum. Oru **conditional edge**-na state-a padichu aduththa node-oda pera thirumbi kudukkura oru function.
- **Checkpointer**: ovvoru step-kku appuramum state-a oru `thread_id` keezha save pannum. Adhanaala oru run pause aagalaam, resume aagalaam, restart aanaalum thappikkalaam, replay pannalaam.

Oru agent loop-na oru chinna graph: oru model node, oru tool node, model tools kekkuradhai niruthura varai rendukkum naduvula loop panra oru conditional edge. Oru workflow-na fixed edges irukkura oru graph. LangGraph rendaiyum orae system-la kalakka vidudhu.

Indha lesson orae graph-a aarambathula irundhu mudivu varai build pannudhu. Chennai-la oru broadband provider-kku support tickets varudhu. Billing tickets-la service illaadha naatkalukku oru credit kidaikkalaam, ovvoru credit-um billing system-kku poradhukku munnaadi oru supervisor adhai approve pannanum.

```flow
title: Support-ticket graph (ovvoru step-kku appuramum state save aagum, ovvoru thread_id-kkum thaniyaa)
START -> classify
classify -[billing]-> billing_agent | outage naatkalai paarthu, oru credit-a propose pannum
classify -[outage]-> outage_agent
billing_agent -[credit zero mela]-> approve_credit | interrupt: oru supervisor mudivu panraanga
billing_agent -[credit illai]-> reply
approve_credit -[approve aachu]-> apply_credit | billing system-a orae oru thadavai call pannum
approve_credit -[reject aachu]-> reply
apply_credit -> reply
outage_agent -> END
reply -> END
```

### Muzhu graph

Mela irundhu keezha varai oru thadavai padinga. Model-kkum billing system-kkum badhilaa chinna stand-ins irukku, adhanaala API key illaamale idhu odum. Idhai `ticket_graph.py`-aa save pannunga; aduthu varra blocks idhoda pergalai use pannudhu.

```python
from typing import Annotated, TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import interrupt, Command

class Ticket(TypedDict, total=False):
    messages: Annotated[list, add_messages]  # reducer: new messages are appended
    ticket_id: str
    category: str              # "billing" or "outage"
    outage_days: int
    proposed_credit_inr: int
    approved_credit_inr: int   # 0 means the supervisor said no
    credit_ref: str

# Stand-ins for real systems, so the graph runs with no API key.
OUTAGE_DAYS = {"TKT-4471": 3}     # the network status tool
CREDITS = {}                      # the billing system, keyed by idempotency key

def add_credit(key: str, amount_inr: int) -> str:
    return CREDITS.setdefault(key, f"CR-{len(CREDITS) + 1:04d}")  # same key, one credit

def classify(state: Ticket) -> dict:
    text = state["messages"][-1].content.lower()   # a model call in real life
    return {"category": "billing" if "bill" in text else "outage"}

def route_ticket(state: Ticket) -> str:
    return "billing_agent" if state["category"] == "billing" else "outage_agent"

def billing_agent(state: Ticket) -> dict:
    days = OUTAGE_DAYS.get(state["ticket_id"], 0)
    return {"outage_days": days, "proposed_credit_inr": min(days * 100, 500)}

def outage_agent(state: Ticket) -> dict:
    return {"messages": [("ai", "There is a fibre cut in your area. We will update you by 6 pm.")]}

def approve_credit(state: Ticket) -> dict:
    decision = interrupt({                          # the run pauses here
        "ticket_id": state["ticket_id"],
        "proposed_credit_inr": state["proposed_credit_inr"],
        "reason": f"{state['outage_days']} days without service",
    })
    # On resume this node runs again from the top, and interrupt() returns the decision.
    return {"approved_credit_inr": decision["credit_inr"] if decision["approved"] else 0}

def apply_credit(state: Ticket) -> dict:
    ref = add_credit(key=state["ticket_id"], amount_inr=state["approved_credit_inr"])
    return {"credit_ref": ref}

def reply(state: Ticket) -> dict:
    amount = state.get("approved_credit_inr", 0)
    text = (f"We have added a ₹{amount} credit to your next bill (ref {state['credit_ref']})."
            if amount else "We checked your account. No credit applies this time.")
    return {"messages": [("ai", text)]}

g = StateGraph(Ticket)
for node in (classify, billing_agent, outage_agent, approve_credit, apply_credit, reply):
    g.add_node(node)                                # the node is named after the function
g.add_edge(START, "classify")
g.add_conditional_edges("classify", route_ticket, ["billing_agent", "outage_agent"])
g.add_conditional_edges("billing_agent",
    lambda s: "approve_credit" if s["proposed_credit_inr"] > 0 else "reply",
    ["approve_credit", "reply"])
g.add_conditional_edges("approve_credit",
    lambda s: "apply_credit" if s["approved_credit_inr"] > 0 else "reply",
    ["apply_credit", "reply"])
g.add_edge("apply_credit", "reply")
g.add_edge("outage_agent", END)
g.add_edge("reply", END)
app = g.compile(checkpointer=InMemorySaver())
```

Credit policy (service illaadha ovvoru naalukkum ₹100, adhigabatcham ₹500) indha lesson-kkaana oru udhaaranam thaan, endha unmaiyaana provider-oda rule-um illa. Oru real system-la, `classify` oru label-a thirumbi kudukkura oru model call-aa irukkum, `billing_agent` oru chinna model-and-tool loop-aa irukkum (keezha irukkura prebuilt agent-a paarunga). Ovvoru `add_conditional_edges` call-oda kadaisiyila irukkura list, route thirumbi kudukkakkoodiya nodes-oda pergalai solludhu. `app.get_graph().draw_mermaid()` graph-a oru Mermaid diagram-aa print pannum; edges neenga ninaicha maadhiri irukkaa-nnu vegamaa check panna idhu oru vazhi.

### State updates eppadi merge aagudhu

Oru node adhu maathura fields-a mattum thirumbi kudukkum, LangGraph adhai state-la merge pannum. Perumbaalaana fields-kku, pudhu value pazhaiya value-a replace pannum. Oru **reducer** irukkura field, udhaaranamaa `add_messages` irukkura `messages`, replace aagaama combine aagum: pudhu messages kadaisiyila serum. Adhanaala thaan `reply` orae oru message-a thirumbi kuduthaalum customer-oda message appadiye irukku. Reducer-a marandhaa, `messages`-la ezhudhura ovvoru node-um conversation-a azhichudum. Aarambathula varra bugs-laye idhu thaan romba common.

### Pause, approve, resume

Ovvoru run-um oru thread-a kurippidudhu. Inga thread-na ticket thaan, adhanaala TKT-4471 pathina ellaame orae idathula irukkum:

```python
config = {"configurable": {"thread_id": "TKT-4471"}, "recursion_limit": 20}
first = {"ticket_id": "TKT-4471",
         "messages": [("user", "Net was down 3 days. Why is my bill the full ₹799?")]}
out = app.invoke(first, config)
print(out["__interrupt__"][0].value)
# {'ticket_id': 'TKT-4471', 'proposed_credit_inr': 300, 'reason': '3 days without service'}

# Hours later, the supervisor's dashboard resumes the same thread:
out = app.invoke(Command(resume={"approved": True, "credit_inr": 300}), config)
print(out["messages"][-1].content)
# We have added a ₹300 credit to your next bill (ref CR-0001).
```

Approval-a safe aakkura moonu rules:

- **Resume aagumbodhu node thirumba odum.** LangGraph `interrupt()`-kku aduththa line-la irundhu thodaraadhu; adhu `approve_credit`-a adhoda mudhal line-la irundhu thirumba ottum, indha thadavai `interrupt()` mudivai thirumbi kudukkum. Oru test-la, `interrupt()`-kku munnaadi vacha oru counter rendu thadavai yeruchu. Adhanaala `interrupt()`-kku munnaadi irukkura edhukkum side effects irukkakkoodaadhu.
- **Action-a aduththa node-la vainga.** Credit `approve_credit`-la illa, `apply_credit`-la thaan apply aagudhu. Andha node ticket id-a oru idempotency key-aa use pannudhu, adhanaala adhu rendu thadavai odinaalum customer-kku orae oru credit thaan kidaikkum.
- **Supervisor edit pannalaam.** Resume value-na unga dashboard anuppura edhuvo adhu thaan. `{"approved": True, "credit_inr": 250}` anuppinaa ₹250 apply aagum.

Checkpointer illainnaalum `interrupt()` run-a niruthum, aanaa `Command(resume=...)` "Cannot use Command(resume=...) without checkpointer"-nu fail aagum. `compile(interrupt_before=["apply_credit"])`-um pause pannum, aanaa oru node-kkulla `interrupt()` vachaa supervisor-kku thevaiyaana data-va mattum sariyaa anuppa mudiyum.

### Checkpoints: inspect, replay, fork

Ovvoru step-um save aagradhaala, oru thread-oda history-a padikkalaam, romba pudhusaanadhu mudhalla:

```python
for snap in app.get_state_history(config):
    print(snap.metadata["step"], snap.next, snap.values.get("credit_ref"))
```

"Agent ₹200 propose panniyirundhu, supervisor vendaam-nu solliyirundhaa enna aagum?"-nu kekka, approval-kku sariyaa munnaadi irukkura checkpoint-la irundhu fork pannunga:

```python
past = next(s for s in app.get_state_history(config) if s.next == ("approve_credit",))
fork = app.update_state(past.config, {"proposed_credit_inr": 200})
out = app.invoke(None, fork)                       # runs on and pauses again, now at ₹200
out = app.invoke(Command(resume={"approved": False}), config)
print(out["messages"][-1].content)
# We checked your account. No credit applies this time.
```

`invoke(None, ...)`-na "pudhu input illaama indha checkpoint-la irundhu thodaru". Fork thaan latest state aagum; original steps history-la appadiye irukkum.

### Oru database checkpointer

`InMemorySaver` orae Python process-kkulla thaan irukkum. Oru restart allathu deploy aanaa pause aana ellaa tickets-um poyidum. Production-la checkpoints-a Postgres-la store pannunga, saver-a ovvoru request-kkullayum illaama, server start aagumbodhu oru thadavai create pannunga:

```python
# pip install "langgraph-checkpoint-postgres==3.2.1" "psycopg[binary,pool]"
import os
from psycopg_pool import ConnectionPool
from langgraph.checkpoint.postgres import PostgresSaver

pool = ConnectionPool(os.environ["CHECKPOINT_DB_URL"],
                      kwargs={"autocommit": True, "prepare_threshold": 0}, open=True)
saver = PostgresSaver(pool)
saver.setup()                       # creates the checkpoint tables if missing
app = g.compile(checkpointer=saver)
```

Andha rendu connection settings, `PostgresSaver.from_conn_string` use panra settings-la rendu (row factory-a saver thaane set pannikkum). Andha helper oru `with` block, adhoda mudivula connection-a close pannidum; oru script-kku adhu sari, oru web server-kku sari illa. Connection string-a oru environment variable-la vainga, shutdown-la `pool.close()`-a call pannunga.

Indha saver vachu, naanga TKT-4471-a oru process-la pause panni, andha process-a mudichu, oru pudhu process-la irundhu approve pannom: thread appavum `approve_credit`-la kaathuttu irundhuchu, saadhaaranamaa mudinjudhu.

**Crash-um pause-um vera vera.** Naanga `apply_credit`-kkulla irukkumbodhu process-a kill-um pannom. Thread-a edhuvum thaanaa restart pannala. Oru pudhu process adhai `approve_credit`-la kandupidichudhu, yenna default mode ovvoru step-aiyum background-la save pannum, kadaisi step innum ezhudhappadala. `app.invoke(None, config)` save aana mudivoda `approve_credit`-a thirumba ottuchu, appuram `apply_credit`, `reply`. `invoke`-kku `durability="sync"` kuduthaa, aduththa step aarambikkiradhukku munnaadi ovvoru step-um save aagum, adhanaala appo thread `apply_credit`-laye kaathirundhuchu. Idhula irundhu rendu paadangal: kadaisiyaa save aana step-kku appuram irukkura oru node rendu thadavai odalaam, adhanaala side effects-a idempotent aakkunga; mudiyaama nikkura threads-a thodara oru chinna job ungalukku venum.

### Progress-a stream panradhu

Ovvoru step nadakkumbodhe paarkka `invoke`-kku badhilaa `stream`-a use pannunga:

```python
demo = {"configurable": {"thread_id": "TKT-4471-demo"}, "recursion_limit": 20}
for update in app.stream(first, demo, stream_mode="updates"):
    print(update)
# {'classify': {'category': 'billing'}}
# {'billing_agent': {'outage_days': 3, 'proposed_credit_inr': 300}}
# {'__interrupt__': (Interrupt(value={...}, ...),)}
```

Ovvoru item-um oru node-oda update, adhanaala oru chat screen neenda amaidhikku badhilaa "Checking your connection…"-nu kaattalaam.

### Model illaama test panradhu

Routes-um nodes-um plain functions, adhanaala perumbaalaana tests-kku model-ae thevaiyilla:

```python
def test_billing_ticket_goes_to_billing_agent():
    assert route_ticket({"category": "billing"}) == "billing_agent"

def test_credit_waits_for_approval_then_applies():
    config = {"configurable": {"thread_id": "test-1"}, "recursion_limit": 20}
    out = app.invoke({"ticket_id": "TKT-4471",
                      "messages": [("user", "Why is my bill the full amount?")]}, config)
    assert out["__interrupt__"][0].value["proposed_credit_inr"] == 300
    out = app.invoke(Command(resume={"approved": True, "credit_inr": 300}), config)
    assert out["credit_ref"].startswith("CR-")
```

Model-a call panra nodes-kku, fixed replies irukkura oru fake model-a kudunga, appuram save panni vacha sila real tickets-a CI-la muzhu graph vazhiyaa ottunga.

### Prebuilt agent

Pazhaiya tutorials `langgraph.prebuilt.create_react_agent`-a use pannudhu. LangGraph 1.0-la irundhu adhu deprecated: adhai call pannaa adhu "has been moved to `langchain.agents`"-nu warn pannum. Ippodhaiya prebuilt model-and-tools loop LangChain-oda `create_agent`, adhu LangGraph mela odudhu:

```python
# pip install "langchain==1.5.2" plus your model provider's package
from langchain.agents import create_agent

def outage_days(ticket_id: str) -> int:
    """Days without service on this ticket's connection."""
    return OUTAGE_DAYS.get(ticket_id, 0)

billing_helper = create_agent(chat_model, tools=[outage_days],
                              system_prompt="You answer broadband billing questions.")
out = billing_helper.invoke({"messages": [("user", "Ticket TKT-4471: why is my bill high?")]})
```

`chat_model`-na tool calling-a support panra endha LangChain chat model-um. Result oru compiled graph, adhanaala adhu innum periya oru graph-oda oru node-aa irukkalaam. Adhu thaan **sub-graph**. Oru plain tool loop-kku `create_agent`-la aarambinga. Routing, approvals allathu pala specialists thevaippadumbodhu unga sondha `StateGraph`-a ezhudhunga.

### Ovvoru run-kkum limit vainga

`recursion_limit` oru run-la irukkura steps-oda ennikkaiya cap pannudhu. Oru run adhai thottaa, LangGraph `GraphRecursionError`-a raise pannum; adhai catch panni oru aalkitta handover-aa maathalaam. Ovvoru call-layum adhai neengale set pannunga: default LangGraph 1.0.5 varai 25, 1.0.6-la irundhu 1.1.3 varai 10,000, 1.1.4-la irundhu (1.2.24 udpada) 10,007. Adhanaala thannaiye thirupthi paduthikkave mudiyaadha oru draft-and-check loop, default adhai niruthuradhukku munnaadi aayirakkanakkaana model calls pannalaam.

### Basics-kku appaal

- **Parallel branches.** Oru conditional edge pala `Send("node", data)` objects-a thirumbi kuduthu orae node-a pala thadavai parallel-aa ottalaam, udhaaranamaa pathu connections-a orae nerathula check panradhu; oru reducer results-a merge pannum.
- **Long-term memory.** Checkpoints oru thread-kku mattum sondham. "Tamil-la pesa virumburaanga" maadhiri, oru customer koodave ellaa tickets-layum poga vendiya facts, `compile(store=...)`-oda kudukkura oru **store**-la poganum, udhaaranamaa `InMemoryStore` allathu oru Postgres store.
- **Functional API.** `langgraph.func`-la irukkura `@entrypoint`-um `@task`-um, graph varaiyaamale saadhaarana Python functions-kku checkpoints-aiyum interrupts-aiyum kudukkum.
- **Tracing.** `LANGSMITH_TRACING=true`-um oru LangSmith API key-um irundhaa, ovvoru node-oda input-um output-um record aagum, adhanaala "bot edho vithiyaasamaa solluchu"-ngradhu neenga thirakkakkoodiya oru link aagidum.

**Ellaa pagudhigalum orae paarvaiyila:**

| Pagudhi | Ticket graph-la | Gotcha |
| --- | --- | --- |
| Reducer irukkura state | `messages` `add_messages`-a use pannudhu | Reducer illainna, ovvoru reply-um history-a azhichudum |
| Conditional edge | `route_ticket`-um rendu lambdas-um | Adhoda possible nodes list-la irukkura oru pera thaan thirumbi kudukkanum |
| Checkpointer | `InMemorySaver`, appuram `PostgresSaver` | In memory-na restart-la pause aana tickets poyidum |
| `interrupt()` | `approve_credit`-kkulla | Resume-la node adhoda mudhal line-la irundhu thirumba odum |
| Idempotency key | `add_credit`-la ticket id | Idhu illainna, oru rerun rendaavadhu credit-a apply pannum |
| `recursion_limit` | Ovvoru config-layum 20 | Default ippo ungalai kaappaatha mudiyaadha alavukku romba adhigam |

## Oru worked example

Chennai-la TKT-4471 ticket varudhu: "Net was down 3 days. Why is my bill the full ₹799?" Checkpointer enna save pannuchu-nnu table kaattudhu; mela irukkura code-oda oru real run-la irundhu `get_state_history` vachu padichadhu.

| Step | Aduththa node | State-la enna maaruchu |
| --- | --- | --- |
| 0 | classify | Customer-oda message-um `ticket_id`-um ulla vandhaachu |
| 1 | billing_agent | `category` = billing |
| 2 | approve_credit | `outage_days` = 3, `proposed_credit_inr` = 300. Run inga pause aagum, dashboard proposal-a kaattum |
| 3 | apply_credit | Supervisor approve pannadhukku appuram: `approved_credit_inr` = 300 |
| 4 | reply | `credit_ref` = CR-0001 |
| 5 | (mudinjadhu) | Reply message serndhadhu; ippo rendu messages irukku |

Moonu vishayangalai gavaninga. Pause-kku-nnu thaniyaa checkpoint edhuvum serala: step 2 aduththa node `approve_credit`-nu mattum solludhu. Approval-um side effect-um thanithani steps, adhanaala `approve_credit` thirumba odinaalum adhaala oru credit-a apply panna mudiyaadhu. Oru auditor kekkakkoodiya ovvoru value-um (yen ₹300, endha credit reference) oru prompt-kkulla maranju illaama, save aana oru state-la irukku.

Adhe ticket-la rendu variations:

- **Supervisor reject panraanga.** `approve_credit`-kku appuram route neraa `reply`-kku pogum, `apply_credit` odave odaadhu, credit edhuvum illai-nnu customer-kku sollappadum.
- **Oru vaaram kazhichu customer complain panraanga.** Neenga TKT-4471 thread-a thirandhu, ovvoru step-aiyum padichu, original history-a thodaamale, vera credit kuduthirundhaa enna aayirukkum-nu test panna step 2-la irundhu fork pannalaam.

## Podhuvaa panra thappugal

- **Orae periya node.** Classify panradhu, look up panradhu, approve panradhu, reply panradhu ellaathaiyum orae function-la vachaa, oru graph-oda mukkiya payanaana visibility, testability, safe pause points ellaam poyidum.
- **`interrupt()`-kku munnaadi side effects.** Resume-la node mela irundhu thirumba odum, adhanaala anga vacha oru SMS, email allathu credit rendu thadavai nadakkum.
- **Idempotent illaadha actions.** Resumes-um crash recovery-um oru node-a thirumba ottalaam. Ovvoru payment, credit allathu message API-kkum ticket id maadhiri oru idempotency key-a kudunga.
- **Production-la in-memory checkpoints.** Ovvoru restart allathu deploy-layum pause aana runs-um conversations-um poyidum. Oru database checkpointer use panni, adhai backup pannunga.
- **Ovvoru message-kkum pudhu `thread_id`.** Appo assistant ovvoru thadavaiyum conversation-a marandhudum. Oru conversation-kku allathu oru ticket-kku oru thread use pannunga, rendu customers-kku naduvula oru thread-a eppavume share pannaadheenga.
- **Limit illaama valarra state.** Ovvoru tool result-aiyum eppavum serthutte irundhaa prompts neelamaavum selavaavum aagum. Oru node-la trim pannunga allathu summarise pannunga.
- **Default `recursion_limit`-a namburadhu.** 1.2.24-la adhu 10,007 steps. Oru chinna limit-a set panni, `GraphRecursionError`-a catch pannunga.
- **Pazhaiya tutorials-a copy panradhu.** Niraiya tutorials innum deprecated aana `create_react_agent`-aiyo, ippo `InMemorySaver`-kku oru alias-aa irukkura `MemorySaver`-aiyo use pannudhu. Versions-a pin pannunga, upgrade panradhukku munnaadi changelog-a padinga.

## LangGraph thevaiyillaadha nerangal

- **Oru simple tool loop**: agent-loop lesson-la irukkura chinna loop, `create_agent`, allathu oru model provider-oda sondha agent SDK podhumaa irukkalaam.
- **Pauses-um branching-um illaadha oru fixed pipeline**: varisaiyaa call panra saadhaarana functions padikkavum debug pannavum innum easy.
- **Erkanave vera oru framework-la irukkura oru team**, andha framework saved state, pauses, tracing-a cover pannaa.

Ovvoru conversation-kkum saved state, aalungalukkaaga pauses, branching, oru run-a inspect panni replay panra vasadhi idhellaam thevaippadumbodhu thaan LangGraph-kku arththam irukku.

## Demo-la irundhu production-kku

- **Oru database checkpointer use pannunga**, start-up-la oru thadavai create panni, matha production data maadhiriye adhaiyum backup pannunga.
- **Durability-a yosichu thernthedunga.** Default background-la save pannum; `durability="sync"` ovvoru aduththa step-kkum munnaadi save pannum, payments, credits pakkathula andha extra neram worth thaan.
- **Maattikkitta threads-a recover pannunga.** Crash-kku appuram paadhiyila ninna threads-a kandupidichu, `invoke(None, config)` vachu avatrai thodarra oru chinna job-a ottunga.
- **Ovvoru run-layum `recursion_limit`-um oru timeout-um set pannunga**, `GraphRecursionError`-a oru aalkitta handover-aa maathunga.
- **Graph-a version pannunga.** Pause aana oru thread, appo endha graph deploy aagiyirukko adhula thaan resume aagum. Pudhu state fields-a optional-aa serunga, pause aana threads kaathirukkakkoodiya oru node-a rename-o remove-o pannaadheenga. Oru breaking change-kku, pazhaiya graph-oda pause aana threads mudiyura varai adhai oda vidunga, illainna avatrai mudhalla approve allathu cancel pannunga.
- **Ovvoru node-aiyum thread id-oda trace pannunga**, appo oru support ticket neraa adhoda run-kku koottittu pogum.
- **Routes, nodes, sila muzhu tickets-a** fake models vachu CI-la test pannunga.

## Practice pannunga

LangChain Academy-oda free Introduction to LangGraph-a edunga, kuranjadhu mudhal moonu modules.

1. Mela irukkura ticket graph-a neenga thernthedukkura rendu categories-kku thirumba build pannunga, model thevaiyillaadha routing tests-oda.
2. Adhe `thread_id`-la rendaavadhu message anuppi, state-la mudhal message innum irukku-nnu kaattunga.
3. `interrupt()`-kku munnaadi oru counter vachu adhu rendu thadavai oduradhai paarunga; appuram side effect-a aduththa node-kku maathi oru idempotency key serunga.
4. `PostgresSaver` vachu oru run-a pause panni, unga Python process-a niruthi, oru pudhu process-la irundhu adhai approve pannunga.
5. Mudinja oru thread-a approval-kku mundhaiya step-la irundhu `update_state` vachu fork panni, vera oru mudivoda resume pannunga.

**Mudinjadhu-nnu eppo sollalaam:** unga graph-a varaiya mudiyum, state enga save aagudhu-nnu kaatta mudiyum, approval node yen thirumba odudhu-nnu explain panna mudiyum, unga program-a restart pannadhukku appuram pause aana oru run-a resume panna mudiyum.
