## Idhu enna

Oru **scope of work (SOW)**-ngiradhu discovery-a rendu pakkamum sign panra oru plan-aa maathura document. Neenga enna deliver pannuveenga, enna panna maatteenga, eppo varaikkum, ovvoru deliverable-um eppadi accept aagum, client enna tharanum, changes-um panamum eppadi handle aagum-nu adhu sollum. Sila firms idhai statement of work-nu solluvaanga. Rendu perum adikkadi ore document-kku use aagudhu, aanaa sila firms scope of work-a statement of work-oda oru section-aa paarkkuraanga.

Oru SOW podhuvaa oru **master services agreement (MSA)**-kku keezha irukkum. MSA oru thadavai sign aagum, adhula podhuvaana legal terms irukkum: confidentiality, liability, data protection, rendu pakkathula yaar venumnaalum contract-a eppadi mudikkalaam. Appuram ovvoru project-kkum adhoda specifics-oda thani SOW varum. SOW-um MSA-vum muranpatta, edhu jeyikkum-nu contract podhuvaa sollum, adhanaala check pannunga. MSA illainna, andha legal terms SOW-kkullayo oru thani contract-layo poganum, client-oda legal team avatrai review panna virumbuvaanga.

Oru nalla AI SOW-la indha pagudhigal irukkum:

- **Objective**: prachanai, appuram baseline, target-oda primary KPI.
- **In scope**, **out of scope**: neenga enna build pannuveenga, seiveenga, enna seiya maatteenga, rendaiyum sama alavu thelivaa.
- **Deliverables**: ovvoru urudhiyaana output-um, udhaaranamaa deploy panna oru service, oru eval report, oru runbook, training sessions.
- **Milestones**: thedhigal, proof of concept (POC), pilot, production-kku idaiyila irukkura stage gates-oda.
- **Acceptance criteria**: ovvoru deliverable-um pass panna vendiya test.
- **Assumptions, dependencies**: neenga client-a edhukkellaam nambiyirukkeenga, thedhigaloda.
- **Roles**: yaar mudivu panraanga, yaar accept panraanga, yaar review panraanga, yaar support panraanga.
- **Change process**: pudhu requests eppadi size pannappattu approve aagudhu.
- **Risks**: therinja risks, ovvonnukkum oru owner-oda.
- **Commercial terms**: price, payments, model, cloud costs-a yaar katturaanga, edhu yaarukku sondham.

Idho copy panni fill pannakkoodiya oru pakka skeleton. Oru section chinnadhaa irundhaalum headings-a vechukkonga; kaaliyaa irukkura oru heading-na neenga innum badhil sollaadha oru kelvi.

```markdown
# Scope of work: [project name]
Under MSA [reference], dated [date]

1. Objective
   KPI: [measure], baseline [x], target [y], by [date]
   Guardrail: [measure] must not pass [z]
2. In scope: [features, users, documents, languages]
3. Out of scope: [named exclusions]
4. Deliverables: [service, eval report, runbook, training]
5. Milestones and gates
   Gate 1 (POC), week [n]: criteria in section 6
   Gate 2 (pilot), week [n]: criteria in section 6
6. Acceptance
   Test set: [size], held out from build work
   Ground truth checked by: [names or roles]
   Bar: [measure and threshold]
   Applies to model version: [provider, model, version]
   If a gate is missed: extend, narrow or stop
7. Dependencies (client): [item, owner, date, effect of delay]
8. Roles: decides [name]; accepts [name]; supports [name]
9. Change process: logged, sized in [n] days, approved by [name]
10. Risks: [risk, owner, mitigation]
11. Commercial
    Price model: [fixed / time and materials / mix]
    Payments: [share] on signing, [share] at each gate
    Model and cloud costs: [who pays, monthly cap]
    IP: [code, prompts, golden sets, eval harness]
    Data protection: [DPA reference]
12. Signatures: [client signatory], [acceptance authority], [your side]
```

## Idhu eppadi work aagudhu

### Vera yaaro run pannakkoodiya oru test-aa acceptance-a ezhudhunga

"Assistant sariyaa badhil solludhu"-ngiradhai accept-um panna mudiyaadhu, reject-um panna mudiyaadhu. Test pannakkoodiya oru criterion-kku naalu pagudhigal irukku:

1. **Per sonna oru test set.** Endha files alladhu questions, ethanai, yaar thernthedutthaanga.
2. **Oru bar.** Udhaaranamaa, 10 critical fields-la kuranjadhu 95% field accuracy.
3. **Oru judge.** Sariyaana answer edhu-nu yaar mudivu panraanga, karuthu verupaadugal eppadi theerkkappadum.
4. **Oru version.** Result endha model, configuration-kku porundhudhu.

Mudhal, moonaavadhu pagudhigalukkulla rendu traps irukku. Mudhalla, **test set held out-aa irukkanum**. Oru proof of concept nadakkumbodhu team failures-a study panni fix pannum. Adhu study panna adhe files-la judge pannappatta, andha files-kku etha maadhiri fit panniye gate-a pass pannidalaam, appuram pudhu files-la moshamaa pannum. Adhanaala data-va piringa: oru pagudhi build pannavum debug pannavum, innoru held-out pagudhi, build team-kitta irundhu pootti vechadhu, adhu thaan gate-a mudivu pannum. Oru useful rule: held-out set-a thernthedukkuravar client pakkathu aalaa irukkanum.

Rendaavadhu, **pazhaya process thaanaave sariyaana answer aagidaadhu**. Ground truth-na neenga score panradhukku use panra sariyaana answers-oda set. Neenga kuraikka muyarchi panra rework-kku staff figures-a thirumba type panradhu thaan kaaranam-naa, avangaloda original entries-layum adhe errors irukkum. Avatrai vechu AI-a score panna, AI sariyaa irundhu avanga thappaa irundhappo AI-kku thandanai kidaikkum. Ovvoru test item-aiyum client pakkathu anubavam ulla rendu staff check pannattum, karuthu verupaadu vandhaa moonaavadhu oruthar adhai eppadi theerppaaru-nu munnaadiye othukkonga.

### AI-oda nichayaminmai pathi nermaiyaa irunga

Model outputs maarum, client-oda unmaiyaana documents-a paarkkuradhukku munnaadi yaaraalayum 95%-nu promise panna mudiyaadhu. Idhai maraikkaadheenga; ezhudhi vainga. Define panna test set-la bar enna, acceptance-kku appuramum thodarndhu irukkura human review enna, oru gate miss aanaa enna nadakkum-nu sollunga. Moonu options irukku: oru fix plan-oda oru chinna extension, work aaguradhukku mattum scope-a surukkuradhu, illainna oru ezhuthuppoorva report-oda niruthuradhu. Ellaarum nambikkaiyaa irukkumbodhe idhai othukkitta, appuram varra oru kashtamaana pechu amaidhiyaavum seekkiramaavum mudinjudum.

### Model version-a fix pannunga

Oru engagement nadakkumbodhe model providers models-a update pannuvaanga, retire pannuvaanga. Udhaaranamaa, November 2026 nilavarappadi, Anthropic-oda model deprecations page, publicly release aana oru model-a retire panradhukku munnaadi kuranjadhu 60 naal notice tharradhaa promise pannudhu, retire aana model-kku anuppura requests fail aagum-nu solludhu. Matha providers-um cloud platforms-um avangaloda sondha schedules-a vechirukkaanga. Oru model-la accept aana system, adhukku badhilaa varra model-la vera maadhiri behave pannalaam.

Adhanaala SOW ippadi sollanum: acceptance oru per sonna model version-kku porundhum. Provider adhai maathinaalo retire pannaalo, pudhu version-la acceptance test-a thirumba run pannuveenga. System bar-kku keezha vizhundhaa, fixes-kku yaar panam kattanum-nu SOW sollum. Oru common split: unga support period-kkulla varra fixes ungalodadhu, adhukku appuram avai change requests.

### Edhu out-nu per sollunga, neenga nambiyirukkuradhukku thedhi podunga

"Out of scope: core banking system kooda integration; Tamil-language documents; mobile app; customer-facing use." Perumbaalaana disputes yaarume ezhudhi vaikkaadha vishayangalla irundhu thaan varudhu.

Dependencies-kku oru owner, oru thedhi, oru vilaivu venum: "10 July-kkulla client document store-kku read access tharuvaanga; ovvoru vaara thaamadhamum milestone 2-a oru vaaram thallum." Vilaivu ezhudhalainna, client panra thaamadham sathamillaama neenga miss panna deadline aayidum.

### Sariyaana aal accept pannattum

Niraiya Indhiya enterprises-la SOW-la procurement alladhu IT sign pannuvaanga, yenna vendor budget avangakitta irukku. Aanaa "Aamaa, idhu mudinjadhu"-nu sollakkoodiyavar podhuvaa business owner thaan, udhaaranamaa head of operations. Avanga vera vera aalungalaa irundhaa, SOW-la business owner-a **acceptance authority**-aa per podunga. Appuram sign panradhukku munnaadi acceptance criteria-kku avangaloda ezhuthuppoorva oppudhalai vaangunga; oru email reply podhum. Illainna document-la irukkura ovvoru test-aiyum pass pannittum "Engalukku thevaippattadhu idhu illa"-nu kekka vendi varum.

### Commercial terms-a mudivu pannunga

Clients mudhalla edhirkkuradhu commercial terms-a thaan, adhanaala technical pagudhigalukku kudukkura adhe kavanathoda idhaiyum draft pannunga. Inga neenga legal advice tharala. Unga velai ovvoru kelviyaiyum ezhuppuradhu, oru sensible default-a propose panradhu, appuram client-oda legal, procurement teams-um unga sondha teams-um wording-a review panna viduradhu.

- **Pricing model.** Size pannakkoodiya velaikku **fixed price** sariyaa irukkum, udhaaranamaa define panna oru test-oda naalu vaara POC. Unmaiyaana nichayaminmai irukkura velaikku **time and materials** (effort-kku etha maadhiri panam, adikkadi oru cap-oda) sariyaa irukkum, udhaaranamaa users changes kekkappora oru pilot. Niraiya AI projects rendaiyum kalakkum: POC-kku fixed, pilot-kku cap potta time and materials.
- **Gates-oda inaicha payments.** Udhaaranamaa, sign pannumbodhu oru share, pass aagura ovvoru gate-layum oru share. Idhu panathai evidence-oda inaikkum, gate 1-la niruthura client senja velaikku mattum thaan kattuvaanga.
- **Model, cloud costs.** Model API calls-kkum hosting-kkum yaar katturaanga-nu sollunga. Adikkadi ivai client-oda sondha cloud account-la odum, client neradiyaa kattuvaanga. Neenga katti avangakitta pass on panna, oru monthly cap podunga; adhai thaanda ezhuthuppoorva approval venum. Oru pilot success aanadhum usage seekkiramaa valaralaam.
- **Intellectual property (IP).** Code, prompts, golden sets, eval harness (tests-a run panra scripts) yaarukku sondham-nu sollunga. Golden sets client-oda data-vaiyum experts-oda nerathaiyum vechu build aaguradhaala, clients adikkadi avai thangalukku sondham-nu edhirpaarppaanga. Project-kku munnaadiye neenga build panna reusable tools-a neenga vechukka virumbalaam. Rendaiyum ezhudhi vainga.
- **Data protection.** Indhiyaavoda Digital Personal Data Protection Act, 2023-padi, personal data yen, eppadi use aaganum-nu mudivu panra client thaan **Data Fiduciary**. Avanga saarbaa adhai process panra neenga oru **Data Processor**; oru valid contract-kku keezha mattum thaan oru processor-a engage pannalaam-nu Act solludhu. Andha contract podhuvaa oru data processing agreement (DPA). DPDP Rules November 2025-la notify aachu, perumbaalaana duties May 2027-la irundhu apply aagum, adhanaala ippo sign aagura contracts avatrukku keezha thaan odum.
- **Confidentiality, liability.** Ivai podhuvaa MSA-la irukkum. AI-kku oru point-a check pannunga: system-oda output-a use panni edukkura oru decision-kku yaar poruppu? Suthamaana badhil: oru manusha decision-maker-a loop-la vechukkittu, AI edukkura decisions-a out of scope-la poduradhu, worked example-la panra maadhiri.

### Surukkamaa vainga, appuram oru pudhu aalkitta test pannunga

Business owner main SOW-a padhinanju nimishathula padikka mudiyanum. Field lists, test-set design maadhiri technical details-a oru appendix-la podunga.

Sign panradhukku munnaadi, discovery meetings-la illaadha oruthar-kitta draft-a kudunga. Moonu kelvigal kelunga: sariyaa enna deliver aagum, enna aagaadhu, ovvoru deliverable-um eppadi accept aagum? Ovvoru thayakkamum oru ambiguity-a kaattum, ovvoru ambiguity-um acceptance nerathula varappora oru vaakkuvaadham.

## Oru worked example

Chennai lender-oda credit-file assistant-kkaana SOW-la irundhu oru pagudhi. Vendor budget vechirukkura lender-oda IT head idhula sign panraaru; idhu head of operations-a acceptance authority-aa per podudhu.

> **Objective.** 20 pilot officers-kku oru loan file-kkaana median officer nerathai 41 nimishathula (baseline, June) irundhu 22 nimishamaa kuraikkanum, credit committee rework-a 7%-kku mela ethaama.
>
> **In scope.** Bank statements, salary slips, bureau reports-la irundhu (English, PDF, phone photos) othukkitta 24 fields-a extract panradhu; lender-oda template-la oru draft credit summary; officers-kku oru review screen; lender-oda Azure tenancy-la deployment; eval, pilot reports; runbook; rendu training sessions.
>
> **Out of scope.** Credit decisions, avai officers-kittayum credit committee-kittayum thaan irukkum; customer-facing features; English thavira vera mozhigalla irukkura documents; oru file export-a thaandi loan origination system kooda integration.
>
> **Acceptance (proof of concept, week 4).** Lender-oda credit team thernthedutha 300 masked pazhaya files. 100 development-kkaaga build team-kitta share pannappadum. 200 held out: build team-kitta orupodhum kaattappadaadhu, gate-a score panna use aagum. Held-out files-kkaana ground truth-a rendu senior credit officers check pannuvaanga, karuthu verupaadugalai credit manager theerppaaru. Bar: 10 critical fields-la kuranjadhu 95% field accuracy, ovvoru summary-um adhoda source pages-a cite pannanum. Appendix-la per sonna model version-kku acceptance porundhum.
>
> **Dependencies.** 10 July-kkulla rendu varusha masked files-kku read access; vaarathukku 4 mani neram oru senior credit officer. Ovvoru vaara thaamadhamum milestone 2-a oru vaaram thallum.
>
> **Change process.** Pudhu requests log pannappattu, moonu working days-kkulla size pannappattu, velai aarambikkuradhukku munnaadi head of operations ezhuthuppoorvamaa approve pannanum.
>
> **Commercial.** POC oru fixed fee-la; pilot oru cap-oda time and materials-la; payments signing-layum rendu gates-layum pirikkappadum. Model, hosting costs lender-oda Azure account-la odum, lender kattuvaanga. Golden sets, prompts, project code lender-kku sondham; engaloda pre-existing tools-a naanga vechukkuvom. DPDP Act-kku keezha oru data processing agreement attach pannappattirukku.

Ovvoru clause-um edhai thadukkudhu-nu kavaninga. Held-out split, team debug panna files-kku fit panni gate-a pass panradhai thadukkudhu. Rendu senior officers, pazhaya retyping errors-kku test reward kudukkuradhai thadukkuraanga. Production-la usage valarumbodhu thideer-nu oru bill varradhai cost clause thadukkudhu.

**Idhu eppadi palan thandhuchu.** Week 7-la, pilot nadakkumbodhu, collections head borrower correspondence-kku summaries kettaaru. SOW scope-aiyum change process-aiyum per solliyirundhadhaala, andha request log pannappattu kittathatta naalu vaaram-nu size pannappattuchu. Adhukku pudhu document types, pudhu users, oru pudhu golden set thevaippattuchu. Head of operations adhai production gate-kku appuram phase 2-aa approve pannaaru; credit-file velaiya adhu sathamillaama thaamadhappaduththa vidala. Phase 2 appuram rendaavadhu contract aachu. Scope creep-a manage panradhu pathina lesson andha vaarathai virivaa follow pannudhu.

## Podhuvaa panra thappugal

- **Mangalaana acceptance.** "Nallaa work aagudhu"-ngiradhu mudivillaadha vaakkuvaadhathukku vazhi vaikkum. Test set, bar, judge, model version-a per sollunga.
- **Tuning set-laye test panradhu.** Team debug panna files-la measure panna acceptance, quality-a irukkuradhai vida adhigamaa kaattum. Build team orupodhum paarkkaadha oru pagudhiyai held out-aa vainga.
- **Pazhaya process-a answer key-aa namburadhu.** Neenga sari panra errors original entries-laye irukkum. Experts ground truth-a check pannattum.
- **Edhu out-nu sollaama irukkuradhu.** Ezhudhaadha assumptions disputes aagum.
- **Thedhi illaadha dependencies.** Appo client thaamadhangal neenga miss panna deadlines aayidum.
- **Gate miss aanaa enna panradhu-nu plan illaama irukkuradhu.** Velai aarambikkuradhukku munnaadiye extend, narrow, illainna stop-nu othukkonga.
- **Model changes-a kandukkaama irukkuradhu.** Acceptance-kku appuram varra oru provider update quality-a maathalaam. Version-a fix pannunga, re-acceptance eppadi nadakkum-nu othukkonga.
- **Mudivillaadha velaikku fixed price.** Theriyaadha vishayangal niraincha oru pilot-kku fixed fee potta, corners cut pannavo ovvoru request-kkum vaakkuvaadham pannavo thallappaduveenga.
- **Yaarukkum sondhamillaadha model costs.** API bill-kku yaarum owner illainna, mudhal periya invoice oru dispute aayidum.
- **IP pathi pesaama irukkuradhu.** Neenga reuse panna plan panna golden sets udpada ellaame thangalukku sondham-nu clients ninaichukkuvaanga. Ownership-a ezhudhi vainga.
- **Sign panravar accept panravar illa.** Procurement sign pannum, operations reject pannum. Acceptance authority-a per solli, criteria-kku avanga oppudhalai vaangunga.

## Practice pannunga

Atlassian-oda project scope guide-aiyum GOV.UK-oda user stories guide-aiyum padinga. Appuram:

1. Mela irukkura skeleton-a copy panni, unga discovery, KPI exercises-la vandha use case-kku fill pannunga. Main document-a rendu pakkathukkulla vainga.
2. Moonu deliverables-kku acceptance criteria ezhudhunga. Ovvonnum test set-aiyum adhu eppadi held out-aa irukku-nnum, bar, judge, model version-aiyum per sollanum.
3. Commercial section-a ezhudhunga: ovvoru stage-kkum fixed price-aa time and materials-aa-nu thernthedutthu, yen-nu oru vaakkiyathula sollunga. Model costs-a yaar katturaanga, golden set yaarukku sondham-nu sollunga.
4. Unga discovery notes-a paarkkaadha oru friend kooda swap pannunga. Moonu stranger questions-a avangakitta kettu, avanga kandupidikkura ovvoru ambiguity-aiyum fix pannunga.

**Mudinjadhu-nnu eppo sollalaam:** room-la illaadha oruthar-kitta unga SOW-a kuduthu, enna deliver aagum, enna aagaadhu, ovvoru pagudhiyum eppadi accept aagum, edhukku yaar katturaanga-nu avangalai sariyaa solla vaikka mudiyum.
