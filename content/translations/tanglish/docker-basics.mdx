## Idhu enna

**Container**-na, adhukku thevaiyaana ellaathaiyum serthu package panna oru odum program: Python version, libraries, unga code, adhoda start command. Idhu unga laptop-la, oru colleague-oda machine-la, oru client-oda server-la, illa oru cloud service-la orae maadhiri odum.

Neenga oru **image**-la irundhu container-a build pannuveenga, oru **Dockerfile**-la irundhu image-a build pannuveenga, adhu steps-oda oru chinna recipe. **Docker Compose** oru file-la irundhu pala containers-a serthu start pannum, example unga API, pgvector-oda PostgreSQL database, Redis cache, production-la irukkura maadhiri wire panni.

Containers virtual machines illa. Avanga host-oda Linux kernel-a share pannuvaanga, adhanaala seconds-la start aagi, konjam memory thaan use pannuvaanga.

```flow
dir: LR
Dockerfile -[docker build]-> Image | claims-api:1.4.0-nu tag panniyathu
Image -[docker push]-> Registry | Docker Hub, GHCR, oru cloud registry
Image -[docker run, compose up]-> Containers | laptop, server, cloud-la odudhu
```

| | Virtual machine | Container |
|---|---|---|
| Ovvoru app-um enna sumandhu varum | App, adhoda libraries, oru hypervisor-la muzhu guest OS | App, adhoda libraries, host kernel-a share panra container runtime-la |
| Start aagura neram | Nimishangal | Seconds |
| Memory | Gigabytes | Megabytes |

Indha lesson, Jaipur-la oru bank-oda IT team-ku oru document-search API-a handover panradhu, avanga ellaathaiyum avangaloda own servers-la run pannuvaanga.

## Idhu eppadi work aagudhu

**Dockerfile.** Ovvoru line-um oru layer-a serkkum:

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY pyproject.toml uv.lock ./
RUN pip install uv && uv sync --frozen --no-dev --no-install-project
COPY src ./src
USER 1000
CMD [".venv/bin/uvicorn", "app.main:app", "--app-dir", "src", "--host", "0.0.0.0", "--port", "8000"]
```

Docker layers-a cache pannum. Code-ku munnaadi dependency files-a copy panna, oru code change-ku ellaa packages-aiyum marubadiyum install panna vendaam, adhanaala rebuilds seconds-la mudiyum.

**Build-um run-um.** `docker build -t claims-api:1.4.0 .` oru image-a build panni tag pannum. `docker run -p 8000:8000 --env-file .env claims-api:1.4.0` adha run pannum, container-oda port-a ungaloda port-ku map panni, settings-a environment variables-aa pass pannum. `docker ps`, `docker logs`, `docker exec -it name bash` ullae paaka help pannum.

**Data.** Oru container-oda own filesystem, adha remove panna poidum. Database-oda files, model cache maadhiri azhiyaama irukkanum-nu irukkura data, oru **volume**-la poga vendum.

**Compose.** Oru `compose.yaml` services, avanga images illa build folders, ports, environment, volumes, edhu edhai depend aagudhu-nu list pannum. `docker compose up` ellaathaiyum start pannum; services onnoda onnu peru vachu pesum, adhanaala unga API `postgres:5432`-a connect aagum.

**Registries.** Images oru registry-ku (Docker Hub, GitHub Container Registry, illa client-oda cloud registry) push aagum, servers angirundhu pull pannum. Ovvoru image-aiyum `latest` mattum illaama oru version-oda tag pannunga, apothaan edhu odudhunnu theriyum, rollback-um pannalaam.

**Dhinam use panra commands:**

| Command | Enna seiyum |
| --- | --- |
| `docker build -t name:tag .` | Inga irukkura Dockerfile-la irundhu oru image build panradhu |
| `docker run -p 8000:8000 name:tag` | Oru port-a map panni run panradhu |
| `docker ps` | Odikittu irukkura containers-a list panradhu |
| `docker logs -f name` | Oru container-oda logs-a follow panradhu |
| `docker exec -it name bash` | Odikittu irukkura container-kulla oru shell open panradhu |
| `docker images` | Images-um adhoda sizes-um list panradhu |
| `docker compose up -d` | compose.yaml-la irukkura ella services-aiyum background-la start panradhu |
| `docker compose down` | Avangala stop panni remove panradhu (volumes irukkum) |

**Start aagaadha container-a debug panradhu.** Mudhalla adhoda `docker logs` paarunga: perumbaalum failures-ku kaaranam, oru environment variable illaama irukkradhu, thappaana start command, illa oru port ippo-vae use-la irukkradhu. Udane exit aana, normal command-ku badhil oru shell-oda run panni suththi paarunga. Start aagi, aana database-a reach panna mudiyalana, Compose-kulla database adhoda service name-la irukkum, example `db`, `localhost` illa, yenna ovvoru container-kum thani network address irukku.

**AI apps-ku images.** AI images vegamaa periya aagum: machine learning libraries, model files, system packages serndhu serum. Mudinja, model weights-a image-kku veliyila vachu, start-up-la oru volume-ku download pannunga, illa oru hosted model-a call pannunga. Packages install panna mattum compilers thevai-na, multi-stage builds use pannunga: oru stage-la build panni, results-a oru slim final stage-ku copy pannunga. Sinna images vegamaa pull aagum, vegamaa start aagum, security scanners-ku complain panna kammiyaa irukkum.

**Production-ku suit aana Dockerfile.** Rendu stages, oru health check, image-la secrets illa:

```dockerfile
# syntax=docker/dockerfile:1
FROM python:3.12-slim AS build
WORKDIR /app
RUN pip install --no-cache-dir uv
COPY pyproject.toml uv.lock ./
RUN uv sync --frozen --no-dev --no-install-project
COPY src ./src

FROM python:3.12-slim
WORKDIR /app
COPY --from=build /app/.venv ./.venv
COPY --from=build /app/src ./src
ENV PATH="/app/.venv/bin:$PATH" PYTHONUNBUFFERED=1
RUN useradd --uid 1000 --create-home app
USER app
EXPOSE 8000
HEALTHCHECK --interval=30s --timeout=3s --retries=3 \
  CMD python -c "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8000/health')" || exit 1
CMD ["uvicorn", "app.main:app", "--app-dir", "src", "--host", "0.0.0.0", "--port", "8000"]
```

Adhukku pakkathula oru `.dockerignore`:

```text
.env
.git
__pycache__/
data/
models/
*.ipynb
```

**Database-kku kaathirukkura Compose.** `depends_on` mattum container start aagura varaikkum thaan kaaththirukkum, Postgres connections-a edukkura varaikkum illa:

```yaml
services:
  api:
    build: .
    ports: ["8000:8000"]
    env_file: .env
    depends_on:
      db: {condition: service_healthy}
  db:
    image: pgvector/pgvector:pg16
    environment: {POSTGRES_PASSWORD: devonly, POSTGRES_DB: app}
    volumes: [pgdata:/var/lib/postgresql/data]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      retries: 10
volumes:
  pgdata:
```

`devonly` password oru local machine-ku mattum thaan; unmaiyaana environments credentials-a oru secret store-la irundhu edukkum.

**Containers-la GPUs.** Host-la NVIDIA-oda container toolkit install aagi irundha, `docker run --gpus all ...` oru container-ku GPUs-a tharum. Compose-la, `deploy.resources.reservations.devices`-la kekkalaam. Host driver-ku porundhura CUDA base image-a use pannunga, image sinnadhaa irukka model weights-a oru mounted volume-la vachukkunga.

**Scan-um pin-um.** CI-la, Trivy illa Docker Scout maadhiri tool vachu images-la theriyura vulnerabilities-a scan pannunga, serious findings irundha fail pannunga. Base images-a oru version-ku (illa digest-ku) pin pannunga, adhanaala adutha maadham rebuild panna, Python-a illa system libraries-a oru therinjikaama maathaadhu.

**AI apps-ku size mukkiyam.** Ovvoru change-ku appuramum `docker images` paarunga. Oru hosted model irukkura Python app konjam nooru megabytes irukkanum; PyTorch-um CUDA-vum irukkuradhu pala gigabytes irukkalaam, adhu ovvoru deploy-aiyum autoscale-aiyum mella aakkum. Periya model serving-a adhoda own image-la pirichunga, API image sinnadhaa irukkum.

**Browser-laye try pannunga.** Oru sinna Dockerfile linter: moonu common mistakes-a flag pannum. Dockerfile text-a edit panni run pannunga.

```python
dockerfile = """FROM python:latest
COPY . /app
RUN pip install -r /app/requirements.txt
CMD ["python", "/app/main.py"]"""

lines = [l.strip() for l in dockerfile.splitlines() if l.strip()]
if any(l.startswith("FROM") and (":latest" in l or ":" not in l) for l in lines):
    print("Pin the base image version instead of latest.")
if not any(l.startswith("USER") for l in lines):
    print("Add a USER line so the app does not run as root.")
if lines.index(next(l for l in lines if l.startswith("COPY"))) < lines.index(next(l for l in lines if l.startswith("RUN pip"))):
    print("Copy requirements first and install before copying the code, so builds reuse the cache.")
```

## Oru worked example

Neenga Jaipur bank-oda IT team-ku oru document-search API-a handover panreenga, avanga ellaathaiyum avangaloda own servers-la run pannuvaanga. Avangalukku try panna oru command venum.

```yaml
services:
  api:
    build: .
    ports: ["8000:8000"]
    env_file: .env
    depends_on: [db]
  db:
    image: pgvector/pgvector:pg16
    environment:
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes: ["pgdata:/var/lib/postgresql/data"]
volumes:
  pgdata:
```

Avanga `.env.example`-a `.env`-ku copy panni, model key-yum database password-um fill panni, `docker compose up -d` run panni, `localhost:8000/docs`-a open pannuraanga. API database-a `db:5432`-la reach pannum. Machine-a restart pannum podhu, documents innum indexed-aa irukkum, yenna database `pgdata` volume-la irukku.

Avanga security team image-a scan panni, adhu root-aa odudhu-nu flag panraanga. `USER 1000` line adha fix pannum. Image size-um kekkuraanga: `python:3.12-slim` adha full Python image-la 1 GB-ku mela irukkradhukku badhil 250 MB pakkathula vaikkum.

| Bank-oda review point | Munnaadi | Pinnaadi |
| --- | --- | --- |
| Root-aa odudhu | Aam | Illa: `USER 1000` |
| Image size | Full Python image-la 1 GB-ku mela | `python:3.12-slim`-la 250 MB around |
| Image-la secrets | Illa, run time-la `.env` vazhiya pass aagudhu | Avanga scanner confirm pannudhu |
| Restart-ku appuram data | Irukku, `pgdata` volume-la | Irukku |
| Edhu version odudhu | `1.4.0`-nu tag panniyathu | `1.3.2`-ku rollback test panniyaachu |

## Podhuvaa panra thappugal

- **Secrets-a image-kulla serthu vaikkiradhu.** Image irukkura yaarum adha padikkalaam. Secrets-a run time-la pass pannunga.
- **Production-la `latest` use panradhu.** Edhu odudhu-nu theriyaadhu, rollback-um panna mudiyaadhu. Versions-a tag pannunga.
- **Data-va container-kulla store panradhu.** Adutha deploy-la adhu poidum. Volumes illa managed database use pannunga.
- **Root-aa odradhu.** Neraya client security reviews idha reject pannum. Oru non-root user serkkunga.
- **Mudhalla muzhu folder-a copy panradhu.** Appuram ovvoru code change-um ella packages-aiyum marubadiyum install pannum. Dependency files-a copy panni install pannunga, apram code-a copy pannunga. `.git`, `.env`, data folders-ku `.dockerignore` serkkunga.

- **Ellaathukkum oru periya container.** API, database, cache-a thani services-aa vachukkunga, appo ovvonnaiyum thaniyaa restart, scale, upgrade pannalaam.
- **.dockerignore illaama irukkradhu**, adhanaala .env files-um data folders-um images-kulla poidum.
- **Model weights-a image-kulla serthu vaikkiradhu**, adhu gigabytes aagi deploy mella aagum.
- **Health condition illaama depends_on**, adhanaala database ready aagaradhukku munnaadi app start aagidum.

## Docker thevai illaama irukkalaam eppo

- **Serverless platforms**, unga code-la irundhu directly build pannum, example Next.js app-ku Vercel.
- **Notebooks-um one-off scripts-um**, neengalae run panradhu.
- **Managed AI platforms**, neenga configuration-um prompts-um mattum tharuveenga.

Pala per illa servers orae vishayatha orae maadhiri run panna vendiya podhu thaan containers value aagum.

## Demo-la irundhu production-ku

- **Images-a commit hash-oda tag pannunga**, `latest` mattum illa.
- **CI-la images-a scan pannunga**, serious vulnerabilities irundha fail pannunga.
- **Non-root user-aa run pannunga**, oru health check-oda.
- **Secrets-a images-kku veliyila vainga**; run time-la inject pannunga.
- **Image size-a paathukkunga**, periya model serving-a adhoda own image-la pirichunga.
