## Idhu enna

Sernthu velai seiyura moonu cost levers:

- **Model tiering** (alladhu routing). Ovvoru request-kkum romba capable-aana model thevaiyilla. Classify panradhu, extract panradhu, simple kelvigalukku badhil solradha oru chinna, cheap, fast model vachu pannunga; kashtamaanadha mattum oru periya model-kku anuppunga.
- **Reasoning effort.** Ippodhaiya models badhil solradhukku munnaadi yosikkudhu, andha thinking tokens-kku output tokens-aa thaan bill pannuvaanga, andha text-a neenga paakkave illainaalum. Model evvalavu yosikkanum-nu oru effort setting control pannum. Easy-aana, adhiga volume velaikku default arithaa thaan thevaippadum.
- **Batching.** Sila nodigalla answer thevaiyillaadha velai oru provider-oda **batch API** vazhiyaa pogum: niraiya requests-a ore nerathula upload panni, results-a appuram periya discount-oda vaanguveenga. Udhaaranangal: iravula documents-a tag panradhu, nethaiya tickets-a summarise panradhu, oru archive-a re-score panradhu.

Vaarthaigal pathi oru note. Indha lesson-la "batching"-naa provider-oda discount ulla, asynchronous product. **Continuous batching** vera vishayam: vLLM maadhiri oru serving engine unga sondha GPUs-la ore nerathula niraiya requests-a eppadi adukkudhu-ngradhu adhu. "Inside LLM inference: prefill, decode and the KV cache" lesson adha cover pannudhu.

Moonu levers-um unga traffic therinjirukkiradha saarndhavai: requests-la evvalavu share easy, evvalavu share kaathirukkalaam.

```flow
title: Ovvoru request-um enga pogudhu
Incoming work -> Mani nerakkanakkaa kaathirukkalaamaa?
Mani nerakkanakkaa kaathirukkalaamaa? -[aamaa]-> Paadhi vilaiyila Batch API | unga id vachu results-a match pannu, failures-a retry pannu
Mani nerakkanakkaa kaathirukkalaamaa? -[illa]-> Chinna model, low effort -> Validator pass aachaa?

```

## Idhu eppadi work aagudhu

### Moonu tiering patterns

- **Task vaariyaa fixed.** Ovvoru feature-um adhoda evals-a pass panra romba cheap-aana model-a use pannum. Oru standard form-la irundhu extraction-kku oru chinna model podhumaa irukkalaam; oru legal summary-kku periya model thevaippadalaam. Idhu thaan romba simple-aana, romba common-aana pattern. Inga aarambinga.
- **Cascade.** Mudhalla chinna model-a try pannunga, adhoda output-a check pannunga, check fail aanaa mattum periya model-kku escalate pannunga. Structured extraction maadhiri, oru cheap check nalla output-aiyum mosamaana output-aiyum pirichu paakka mudiyura tasks-kku idhu porundhum.
- **Router.** Oru classifier, alladhu oru chinna model, kashtatha kanichu munnaadiye model-a thernthedukkum. RouteLLM maadhiri research systems idha preference data-la irundhu kathukkudhu. Router chat-kku porundhum: anga rendu calls-a onnu pinnaadi onnaa panna mudiyaadhu, check panna innum output-um irukkaadhu.

Ovvoru route-kkum adhoda sondha eval venum. Unmaiyaana kelvi "chinna model nalladhaa?" illa, "naama adhukku anuppura requests-la adhu podhumaana alavu nalladhaa?"

### Cascade cost formula

Ovvoru item-kkum, oru cascade-kku chinna call-oda cost aagum, kooda escalate aagura share-kku periya call-oda cost:

`cost per item = small cost + escalation rate × large cost`

Escalate aana items rendu calls-kkum pay pannum. Adhanaala pathula oru pangu vilaiyulla oru chinna model, 40% escalation-oda, periya model thaniyaa aaguradhula 0.1 + 0.4 = 0.5 thaan aagum: quality nilaichaa paadhi vilai. Haiku 5.5-kkum Sonnet 5.5-kkum naduvula irukkura maadhiri 20 madangu alladhu adhukku mela price gap irundhaa, kittathatta ella item-um escalate aagura varai cascade cheap-aave irukkum. Panam arithaa thaan risk. Rendu vishayangal thaan risk: check ulla vidura thappaana answers, escalate aana requests-kku varra extra kaathiruppu.

### Validators-um avatroda miss rate-um

Edhu escalate aagum-nu check thaan mudivu pannudhu, adhanaala adha vera endha model-aiyum pola test pannunga. Cheap checks-a layers-aa use pannunga:

1. **Format.** Output schema-padi parse aagudhaa?
2. **Range.** Values nambakkoodiyadhaa irukkaa? Udhaaranamaa, years of experience 0-la irundhu 50-kkulla, kurainjadhu oru skill.
3. **Grounding.** Answer source-la irukkaa? Udhaaranamaa, candidate-oda per, list panna perumbaalaana skills, kadaisi employer resume text-la irukkanum. Pakkaavaa format aana, aanaa karpanaiyaa uruvaakkuna values-a idhu pidikkum.
4. **Call-la irundhu varra signals.** `max_tokens`-a thottadhaala ninna oru response, alladhu oru refusal, oru failure, answer illa.

Appuram label pannuna oru golden set-la chinna model-a otti **miss rate**-a ennunga: thappaa irundha outputs-la, ethana ella checks-aiyum pass pannuchu? Format checks sathamaana failures-a pidikkum. Amaidhiyaana errors (nambakkoodiya, aanaa thappaana employer) avatra pass pannidum. Free text-kku, model thaane solra "unsure" alladhu oru cheap judge model innoru signal-a serkkalaam, aanaa adhoda miss rate-aiyum idhe maadhiri alanga.

### Reasoning effort-um thinking tokens-um

Claude models-la, `output_config.effort` `low`, `medium`, `high`, `xhigh` alladhu `max` edukkum. Thinking udpada ella output tokens-aiyum idhu shape pannum. November 2026 nilavarappadi, default Claude Haiku 5.5-laiyum Claude Opus 5.5-laiyum `medium`, Claude Sonnet 5.5-la `high`. Simple, adhiga volume velaikku Anthropic `low`-a suggest pannudhu.

Moonu gotchas:

- **Thinking `max_tokens`-la serum.** Romba tight-aana `max_tokens` oru reply-a paadhi answer-laiye vettidalaam. Idam vidunga, `stop_reason == "max_tokens"`-a oru failure-aa nadathunga.
- **Thinking switches model-kku model maarum.** Haiku 5.5-la `high` effort alladhu adhukku keezha `thinking: {"type": "disabled"}` anuppalaam. Sonnet 5.5-um Opus 5.5-um adha oru error-oda reject pannum, adhanaala adhukku badhilaa effort-a kuraiyunga.
- **Effort-um oru naalaavadhu tier.** Oru cascade build panradhukku munnaadi, periya model-aiyum kuraivaana effort-la test pannunga. Sila neram adhu ore model, ore cache vachey quality-a nilaikka vaikkum.

Ovvoru route-kkum `usage.output_tokens`-a padinga. Output tokens kannukku theriyura reply-a vida romba adhigamaa irundhaa, unga panam thinking-la thaan pogudhu.

### Batching: idhu eppadi nadandhukkum

Ivai 28 November 2026 nilavarappadi Anthropic-oda Message Batches rules; matha providers details-la maarupaduvaanga.

- **Price:** input, output tokens-la 50% off. OpenAI-um Google-um discount ulla batch modes kudukkuraanga; avangaloda ippodhaiya terms-a check pannunga.
- **Speed:** perumbaalaana batches oru mani nerathukkulla mudiyum, aanaa 24 mani nerathukkulla process aagaadha endha request-um expire aagum. Yaaraavadhu kaathirukkura velaiya batch pannave pannaadheenga.
- **Size:** oru batch-kku 100,000 requests alladhu 256 MB varai. Results 29 naal kidaikkum.
- **Results:** avai endha order-laiyum varalaam. Unga sondha `custom_id` vachu match pannunga. Ovvoru item-um `succeeded`, `errored`, `canceled` alladhu `expired`; kadaisi moonukku ungalukku bill panna maattaanga.
- **Limits:** batches-kku ella models-kkum share aagura thani rate limits irukku: oru nimishathukku requests, kooda queue-la kaathirukkura requests-kku oru cap (Build tier-la 300,000). Ivai real-time limits-la irundhu thani, batches-kku ramp limits kidaiyaadhu. Adhanaala oru periya overnight job, pagalla recruiters nambiyirukkura per-minute token limits-a kaali pannaadhu.
- **Batch-la allow illaadhavai:** streaming, fast mode, server-side fallbacks.

### Indha picture-kkulla caching

Prompt caching, tiering, batching kooda sernthe velai seiyum. Stable-aana pagudhiya mudhalla vainga (instructions, appuram job description), adha `cache_control` vachu mark pannunga. Claude Opus 5.5, Sonnet 5.5, Haiku 5.5 kurainjadhu 512 tokens ulla prefixes-a cache pannum; adha vida kuttiyaana prefix endha error-um illaama saadhaaranamaa process aagum. Oru 5-minute cache write-kku input price-oda 1.25 madangu aagum, oru 1-hour write-kku 2 madangu. Reads romba cheap. Batches-la requests endha order-laiyum odradhaala cache hits best effort thaan. 1-hour cache-a use pannunga, Anthropic suggest panra maadhiri, meedhiya submit panradhukku munnaadi prefix-a write panna mudhalla oru request anuppunga.

### Code-la oru cascade

Low effort-la chinna model, layers-aa checks, oru check fail aanaa mattum periya model:

```python
import anthropic
from pydantic import BaseModel, ValidationError

client = anthropic.Anthropic()
SMALL, LARGE = "claude-haiku-5-5", "claude-sonnet-5-5"   # check the models page for current names

PROMPT = ("Return only JSON with name, years_experience, skills and "
          "last_employer (null if absent). Copy names exactly as written.\n\n")

class Resume(BaseModel):
    name: str
    years_experience: float
    skills: list[str]
    last_employer: str | None = None

def extract(model, effort, text):
    r = client.messages.create(
        model=model, max_tokens=2000,              # thinking counts toward max_tokens
        output_config={"effort": effort},
        messages=[{"role": "user", "content": PROMPT + text}])
    if r.stop_reason != "end_turn":                # cut off or refused: treat as a failure
        return None, r.usage
    return "".join(b.text for b in r.content if b.type == "text"), r.usage

def valid(raw, text):
    if raw is None:
        return None
    try:
        item = Resume.model_validate_json(raw)
    except ValidationError:
        return None
    page = text.lower()
    words = item.name.lower().split()
    if not words or not all(w in page for w in words):          # name must be in the resume
        return None
    if not 0 <= item.years_experience <= 50 or not item.skills:
        return None
    found = sum(s.lower() in page for s in item.skills)
    if found < 0.8 * len(item.skills):                          # most skills must be in the text
        return None
    if item.last_employer and item.last_employer.lower() not in page:
        return None
    return item

def cascade(text, stats):
    raw, _ = extract(SMALL, "low", text)
    stats["small"] += 1
    if item := valid(raw, text):
        return item
    stats["escalated"] += 1
    raw, _ = extract(LARGE, "high", text)
    return valid(raw, text)                                      # None goes to a person
```

Oru empty name `if not words` check-la fail aagi, crash aagaama escalate aagum. Escalation rate-a dhinamum track pannunga. Adhu eruna, oru pudhu vagai input vandhirukku, savings surungudhu.

### Fit summary, cache panni batch pannadhu

Oru hiring drive-la ovvoru resume-kkum job description ore maadhiri thaan, adhanaala adhu mudhalla pogum, caching-kku mark pannappadum:

```python
import time

def run_batch(items, job_description):
    batch = client.messages.batches.create(requests=[
        {"custom_id": it["id"],                                  # your id: 1-64 letters, digits, - or _
         "params": {"model": LARGE, "max_tokens": 4000,
                    "output_config": {"effort": "medium"},
                    "system": [{"type": "text",
                                "text": "You screen resumes for this role.\n\n" + job_description,
                                "cache_control": {"type": "ephemeral", "ttl": "1h"}}],
                    "messages": [{"role": "user",
                                  "content": "Write a five-line fit summary.\n\n" + it["text"]}]}}
        for it in items])
    while client.messages.batches.retrieve(batch.id).processing_status != "ended":
        time.sleep(60)
    done, retry = {}, []
    for r in client.messages.batches.results(batch.id):         # any order: key by custom_id
        if r.result.type == "succeeded":
            m = r.result.message
            done[r.custom_id] = "".join(b.text for b in m.content if b.type == "text")
        else:                                                    # errored, expired or canceled
            retry.append(r.custom_id)
    return done, retry
```

`retry`-a oru pudhu, chinna batch-kku anuppunga, alladhu kaalaikkulla recruiters-kku thevainaa real-time path-kku anuppunga. Batch outputs-a real-time outputs-a maadhiriye validate pannunga. Oru sample-la `usage.cache_read_input_tokens`-a check pannunga: adhu zero-laiye irundhaa, prefix-la edho onnu maarikkitte irukku.

Oru reviewer padikkira maadhiri table-a padinga:

- **Lever 1:** escalations-kku aagura selavu, ella chinna-model calls-aiyum serthadha vida rendu madangukku mela. Escalation rate-la ovvoru point-um bill-la theriyum.
- **Lever 2:** effort maatrathukku adhoda sondha eval thevaippattuchu. Recruiters rendu settings-laiyum 100 summaries-a blind-rate panni endha vidhyaasamum paakkala. Andha check illainaa, adhu verum guess thaan.
- **Lever 3:** batching adhukku munnaadi irukkura ellaathaiyum 0.6-aala perukkudhu (80% paadhi vilaiyila, 20% muzhu vilaiyila).
- **Lever 4:** inga caching-aala varra micham chinnadhu, yenna 5,000 input tokens-la prefix 2,000 thaan. 400-token extraction instructions cache aagave aagaadhu: avai 512-token minimum-kku keezha.

Bill maasathukku kittathatta ₹14.3 lakh-la irundhu kittathatta ₹3.45 lakh-kku kuraiyudhu, thoraayamaa 76% kuraivu, golden-set accuracy-um recruiter ratings-um maaraama. Pagal uploads real time-laiye irukkum. Anga, escalate aagura 7% resumes rendu calls-kku kaathirukkum, adhanaala team andha path-kku p95 latency-a thaniyaa track pannudhu.

## Podhuvaa panra thappugal

- **Vibe vachu chinna model-a thernthedukkuradhu.** Ovvoru route-kkum evals ottunga. Cheap-aa irundhu thappaa irundhaa adhu expensive thaan.
- **Low escalation rate-a namburadhu.** Format mattum check panra validator, nallaa format aana aanaa thappaana answers-a pass pannidum. Adhoda miss rate-a oru golden set-la alanga.
- **Cost per successful task-kku badhilaa cost per call-a ennuradhu.** Escalations, retries, manushanga panra fixes ellaathaiyum serunga.
- **Thinking tokens-a kandukkaama viduradhu.** Oru periya model-la default effort, reasoning-a bill-la romba periya line aakkidalaam. Ovvoru route-kkum effort-a set panni evals kooda check pannunga.
- **`max_tokens`-a romba tight-aa vaikkiradhu.** Thinking adhula serum, adhanaala replies vettappattu model failures maadhiri theriyum.
- **Users-kku neradiyaa pora velaiya batch panradhu.** Batches podhuvaa oru mani nerathukkulla mudiyum, aanaa 24 mani neram varai aagalaam.
- **Fail aana batch items-a tholaichidradhu.** `custom_id` vachu match pannunga, errored, expired items-a retry pannunga, reruns duplicates uruvaakkaadha maadhiri writes-a idempotent-aa vainga.
- **Escalation-oda latency-a marandhuduradhu.** Chat-la, oru cascade romba kashtamaana kelvigala romba slow aakkum. Oru router alladhu ore oru model users-kku nallaa serve pannalaam.
- **Cache aaga mudiyaadha prefix-a cache panradhu.** Adhu romba kuttiyaa irukku, ovvoru request-laiyum maarudhu, alladhu pagal uploads-kku naduvula 5-minute cache expire aagidudhu.

## Tiering, batching eppo worth illa

- **Kuraivaana volume.** Savings, engineering nerathai vida kuraivu.
- **Ovvoru request-um avasaram**, adhanaala batching porundhaadhu.
- **Chinna model unga evals-la fail aagudhu**, neenga anuppa pora traffic-la, periya model-la kuraivaana effort setting-um udhavala.
- **Cascade escalate panna nambagamaana check edhuvum illa**, router-kku thelivaana signal-um illa.

## Demo-la irundhu production-ku

- **Escalation rate, validator miss rate, cost per successful task-a track pannunga**, ovvoru feature-kkum, ovvoru vaaramum.
- **Golden set-a marubadi ottunga**, ovvoru model, prompt alladhu effort maatrathukkum. Models-a maathumbodhu effort-a marubadi sweep pannunga, yenna levels model-kku model vera maadhiri nadandhukkum.
- **Batch failures-a handle pannunga**, id vachu, retries, oru report, deadline-kku munnaadi oru real-time fallback-oda.
- **Avasara velaiyaiyum batch velaiyaiyum thaniyaa vainga.** Batch-kku thani limits irukku; kattuppaadu illaama odura oru job real-time quota-va kaali pannaama irukka workspace limits use pannunga.
- **Prices-a thedhiyoda padhivu pannunga**, ovvoru cost comparison-laiyum, ovvoru review-kkum munnaadi avatra marubadi check pannunga.

## Practice pannunga

Unga provider-oda batch processing guide-aiyum RouteLLM post-aiyum padinga.

1. Oru feature-a thernthedutthu 50 golden cases-la oru chinna model-aiyum oru periya model-aiyum ottunga. Ovvonnukkum accuracy, output tokens (thinking udpada), oru case-kku cost-a record pannunga.
2. Format, range, grounding checks-oda oru cascade build pannunga. Escalation rate-aiyum validator-oda miss rate-aiyum report pannunga.
3. Adhe 50 cases-la periya model-a rendu effort levels-la otti, quality-aiyum output tokens-aiyum compare pannunga.
4. Avasaram illaadha 100 requests-a oru batch-aa submit panni, fail aana items-a `custom_id` vachu retry panni, cost-a real-time calls kooda compare pannunga.
5. Worked example-la irukkura maadhiri oru lever-by-lever table ezhudhunga, unga sondha `usage` numbers-aiyum thedhi potta prices-aiyum vachu.
