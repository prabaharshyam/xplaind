## Idhu enna

Oru **web API** unga program-a internet vazhiyaa innoru service-kitta data allathu actions kekka vidudhu: air quality, oru map route, oru payment-oda status, arasaanga open data, allathu oru AI model-oda badhil. Ovvoru AI model provider-aiyum indha vazhiyila thaan anugurom, adhanaala pinnaadi language models-a call panradhukku adippadaiyaana core skill idhu thaan.

Unga program oru URL-kku oru **HTTP request** anuppudhu. Service idhoda reply pannudhu:

- oru **status code**, adhu velai senjudhaannu solra oru moonu ilakka ennu;
- perumbaalum **JSON**-la oru **body**, adhaavadhu objects (`{"key": value}`), lists (`[1, 2, 3]`) irukkura oru text format; adhai Python dictionaries, lists-aa maathudhu.

```flow
title: Oru API call, aarambam mudhal mudivu varai
dir: LR
Unga code | session.get(url, params, timeout) -[GET, X-API-Key header-la key]-> API server
API server -[status code, JSON body]-> Status-a check pannunga
Status-a check pannunga -[2xx]-> r.json() | dicts, lists
Status-a check pannunga -[429 allathu 5xx]-> Wait panni retry pannunga
Status-a check pannunga -[maththa 4xx]-> Request-a fix pannunga
```

Indha lesson-la Delhi-la oru chinna air-quality dashboard build panra student Anita kooda porom. Avanga **OpenAQ** use panraanga; idhu ulagam muzhukka irundhu, Indhiya monitoring stations utpada, air-quality readings-a segarikkira oru non-profit platform. Adhoda API-kku oru free key venum, adhanaala muzhu routine-aiyum practise panna idhu oru nalla idam: key, timeout, status, JSON, retries, pages.

## Idhu eppadi work aagudhu

### Oru request-oda pagudhigal

Ovvoru API-oda documentation-um requests-a idhe pagudhigalaa thaan vivarikkudhu:

| Pagudhi | Adhu enna | `requests`-la | OpenAQ udhaaranam |
| --- | --- | --- | --- |
| Base URL | Ellaa calls-um aarambikkira address | URL-oda oru pagudhi | `https://api.openaq.org/v3` |
| Endpoint | Oru vagai data-kkaana path | URL-oda oru pagudhi | `/locations/8118/latest` |
| Query parameters | URL-la `?`-kku appuram serkkira filters | `params={...}` | `iso=IN`, `limit=100`, `page=2` |
| Headers | Key utpada metadata | `headers={...}` | `X-API-Key: your key` |
| Body | Neenga anuppura data, perumbaalum POST kooda | `json={...}` | data padikka thevaiyillai |

`params={"iso": "IN"}` URL-la `?iso=IN`-aa maarudhu; `requests` spaces, special characters-aiyum escape pannum. Oru JSON body anuppa `json=` use pannunga (`data=` illai): adhu unga dictionary-a convert panni, sariyaana content type-a set pannum.

### Unga mudhal call

```python
import os
import requests

BASE = "https://api.openaq.org/v3"
key = os.environ["OPENAQ_API_KEY"]

r = requests.get(f"{BASE}/locations/8118/latest",
                 headers={"X-API-Key": key}, timeout=(5, 20))
print(r.status_code)          # 200 if it worked
r.raise_for_status()          # stop here on any 4xx or 5xx
data = r.json()               # JSON text becomes dicts and lists
print(list(data))             # ['meta', 'results']
```

Location 8118 oru New Delhi station, OpenAQ thannoda quick start-laye idhai use pannudhu. Indha chinna block-laye moonu pazhakkangal irukku:

- **Key oru environment variable-la irundhu varudhu**, adhanaala adhu code-la eppavume theriyaadhu.
- **Oru timeout irukku.** `(5, 20)`-na connect aaga 5 seconds varai, server data anuppa 20 seconds varai wait pannum.
- **`raise_for_status()`, `r.json()`-kku munnaadi run aagudhu.** Oru error reply data illai, adhai data-vaa nadaththinaa moonu lines-kku appuram kuzhappamaana failures varum.

### Status codes

Mudhal ilakkam yaaroda prachanainnu sollum: **2xx** velai senjudhu, **4xx** unga request thappu, **5xx** server fail aayiduchu.

| Code | Arththam | Enna pannanum | Retry? |
| --- | --- | --- | --- |
| `200` | OK | Data-va use pannunga | — |
| `400` | Bad request | Parameters, body-a check pannunga | Illai |
| `401` | Unauthorized: key illai, thappu allathu expire aayiduchu | Key-aiyum adhu pora header-aiyum check pannunga | Illai |
| `403` | Forbidden: key valid, aanaa idhukku anumadhi illai | Unga plan allathu permissions-a check pannunga | Illai |
| `404` | Not found | URL path-aiyum item id-aiyum check pannunga | Illai |
| `422` | Unprocessable: request validation-la fail aayiduchu | Body-la irukkura error detail-a padinga | Illai |
| `429` | Too many requests | Wait panni, innum medhuvaa retry pannunga | Aamaa |
| `500`, `502`, `503`, `504` | Server allathu oru proxy fail aayiduchu | Wait panni retry pannunga | Aamaa |

Nyaabagam vechukka oru useful vazhi: **401 "Neenga yaaru?"nnu kekkudhu, 403 "Neenga yaarunnu theriyum, aanaa mudiyaadhu"nnu solludhu.** 401-kku fix key; 403-kku fix unga account allathu plan. Niraiya Python APIs, FastAPI framework vechu build pannadhu utpada, oru field illainnaa allathu adhu thappaana type-la irundhaa 422 return pannum, endha field-nu body sollum.

### JSON-a padikkiradhu

Adhai padikkira code ezhudhuradhukku munnaadi, reply-a oru thadavai azhagaa format panni print pannunga:

```python
import json
print(json.dumps(data, indent=2)[:1500])
```

Latest-readings endpoint-la irundhu varra oru reply-a trim pannaa adhukku indha shape irukkum (shape OpenAQ-oda documentation-a follow pannudhu; values karpanaiyaanavai):

```json
{
  "meta": {"name": "openaq-api", "page": 1, "limit": 100, "found": 2},
  "results": [
    {"datetime": {"utc": "2026-11-28T05:00:00Z", "local": "2026-11-28T10:30:00+05:30"},
     "value": 182.0, "sensorsId": 1001, "locationsId": 8118,
     "coordinates": {"latitude": 28.63, "longitude": 77.2}},
    {"datetime": {"utc": "2026-11-28T05:00:00Z", "local": "2026-11-28T10:30:00+05:30"},
     "value": 301.0, "sensorsId": 1002, "locationsId": 8118,
     "coordinates": {"latitude": 28.63, "longitude": 77.2}}
  ]
}
```

Veliyila irundhu ulla nokki padinga. Curly braces oru dictionary, adhanaala string key use pannuveenga. Square brackets oru list, adhanaala 0-la irundhu enni oru number use pannuveenga.

```python
data["results"][0]["value"]               # 182.0
data["results"][0]["datetime"]["local"]   # '2026-11-28T10:30:00+05:30'
[row["value"] for row in data["results"]] # [182.0, 301.0]
```

Neenga ellaaththaiyum vida adhigamaa paarkkappora rendu errors, ovvonnum oru kurippitta thappai kaattum:

- `TypeError: list indices must be integers or slices, not str`-na neenga oru list mela string key use pannirukkeenga. Udhaaranamaa, `data["results"]["value"]` fail aagum, yennaa `results` oru list. Oru item-a edunga (`[0]`) allathu loop pannunga.
- `KeyError: 'value'`-na andha dictionary-la appadi oru key illai. Spelling-a check pannunga, illainnaa andha field optional.

Optional fields-kku, key **illainnaa** `row.get("value", 0)` `0`-a return pannum. Aanaa niraiya APIs key-a `null` kooda anuppum, adhai Python `None`-aa padikkum, appo `.get` unga default-a illaama `None`-a return pannum. Rendu cases-aiyum cover panna `row.get("value") or 0` ezhudhunga. Kavanam: `or` oru unmaiyaana `0`-aiyum replace pannidum, adhanaala zero-kku arththam irukkura numbers-kku, adhukku badhilaa `is None` test pannunga.

### Body JSON illaadhappo

Body JSON illainnaa `r.json()` `requests.JSONDecodeError`-a raise pannum, idhu neenga ninaikkiradhai vida adhigamaa nadakkum. Oru `502` allathu `503` perumbaalum API-kku munnaadi irukkura oru proxy allathu load balancer-la irundhu varum, adhoda body oru HTML error page. Sila services oru `200` kooda oru HTML maintenance page-a return pannum. Decoding fail aanaa, enna vandhuchunnu paarkka `r.text`-oda mudhal 200 characters-a print pannunga; worked example-la irukkura helper idhai thaan pannudhu.

### Timeouts

Default-aa `requests`-kku timeout illai, adhanaala badhile sollaadha oru server-kku pora call mudivillaama wait panni oru nightly job-a freeze pannidalaam. Eppavum `timeout=` kudunga. `timeout=10` maadhiri oru single number rendu limits-aiyum set pannum. `(5, 20)` maadhiri oru pair **connect** limit-aiyum (server-a adaiyuradhu) **read** limit-aiyum (data-kkaaga wait panradhu) thanithaniyaa set pannum.

Oru gotcha: read limit-na adutha data thundukkaaga wait panra adhigapatcha neram, muzhu download-kkaana limit illai. Ovvoru sila seconds-kkum konjam data anuppura oru server, oru call-a 20 seconds-a vida romba adhiga neram uyirodu vechirukka mudiyum. Oru timeout unmaiyileye fire aanaa, `requests` `requests.Timeout`-a raise pannum; adhai catch panni retry pannunga allathu thelivaa report pannunga.

### Keys, secrets

Neenga share allathu commit panra code-la API keys-a orupodhum ezhudhaadheenga. Key-a unga terminal-la set pannunga (Linux allathu macOS-la `export OPENAQ_API_KEY=...`; Windows PowerShell-la `$env:OPENAQ_API_KEY="..."`), adhai `os.environ["OPENAQ_API_KEY"]` vechu padinga.

Andha line `KeyError: 'OPENAQ_API_KEY'`-a raise pannaa, endha request-um anuppappadave illai: variable **indha** terminal-la set aagalai. Innoru terminal-la neenga set panna variable-a oru pudhu terminal nyaabagam vechukkaadhu. Aanaa oru `401`-na request poyiduchu, server key-a reject panniduchu allathu adhai kandupidikka mudiyalai. Innum rendu rules: key-a orupodhum print allathu log pannaadheenga; adhu eppavaavadhu oru public repository-la poi serndhuttaa, udane oru pudhu key create panni pazhaya key-a delete pannunga.

### Paadhukaappaa retry panradhu

Sila failures sila seconds-kku appuram thaanaave sariyaayidum: timeouts, drop aana connections, `429`, `5xx`. Maththadhu orupodhum sariyaagaadhu: oru `401` allathu `404`-a edhaiyum maaththaama retry pannaa adhe thappu thirumba nadakkum, avvalavu thaan. Oru nalla retry:

- thaatkaaligamaa irukka vaaippulla failures-a mattum retry pannum;
- ovvoru thadavaiyum innum adhigamaa wait pannum (**exponential backoff**: 1, 2, 4 seconds), server `Retry-After` header anuppinaa adhai follow pannum;
- sila tries-kku appuram vittuttu oru thelivaana error-a raise pannum, oru error reply-a vechukkittu thodarndhu pogaadhu.

**GETs-a thaaraalamaa retry pannunga, aanaa oru POST-a retry panradhukku munnaadi yosinga.** Oru GET padikka mattum thaan seiyum, adhanaala adhai repeat panradhula prachanai illai. Oru POST perumbaalum edhaavadhu onnai *create* pannum: oru payment, oru order, oru message. Mudhal attempt server-a adainju, aanaa reply thirumbi varra vazhiyila tholainjuttaa, kanmoodiththanamaana oru retry adhai rendu thadavai create pannidum. Stripe maadhiri payment APIs idhai oru **idempotency key** vechu theerkkudhu: neenga oru thadavai uruvaakki, adhe request-oda ovvoru retry-layum oru header-la anuppura oru unique id; adhanaala idhu repeat-nu server-kku theriyum.

```python
import uuid

key = str(uuid.uuid4())                       # make it once, before the first try
headers = {"Idempotency-Key": key}            # send the same key on every retry
```

Oru API appadi oru key kudukkalainnaa, adhoda POSTs-a auto-retry pannaadheenga; thirumba try panradhukku munnaadi mudhal POST velai senjudhaannu check pannunga.

### Pagination

Oru list endpoint ellaaththaiyum ore thadavaiyila return panradhu aridhu. Adhu oru thadavaikku oru **page** return pannum, neenga aduththadhai kekkanum. OpenAQ `page`, `limit` parameters use pannudhu (default `limit` 100), mothha ennikkaiyai `meta.found`-la solludhu. Maththa APIs idhukku badhilaa oru `next` URL allathu oru cursor-a return pannum; edhunnu documentation sollum.

Saththamillaama nadakkura failure-na page 1-a mattum padikkiradhu. Code run aagum, 100 results kaattum, sariyaa irukkura maadhiri theriyum. Oru count 100 allathu 1000 maadhiri oru round number-aa vandhaa, mudhalla pagination-a sandhegappadunga.

Unga loop condition-kku mothha ennikkaiyai nambaadheenga. Periya sets-kku OpenAQ-oda `found` `">1000"` maadhiri oru string-aa irukkalaam, adhu arithmetic-a udaichudum. Adhukku badhilaa, oru page `limit`-a vida kuraivaa allathu kaaliyaa vandhaa niruththunga, oru safety net-aa pages ennikkaikku oru cap vainga (keezha irukkura `get_all`-a paarunga).

### Limits, cost

Perumbaalaana APIs oru nimishaththukku allathu oru naalaikku requests-a limit pannum, paid APIs, language-model APIs utpada, use-kku charge pannum. Niraiya APIs neenga enga nikkireenganu kaattura headers anuppum; OpenAQ `x-ratelimit-remaining`, `x-ratelimit-reset` anuppum, neenga limit-a thaandinaa `429` return pannum. 500 cities mela loop panradhukku munnaadi documentation-oda limits page-a padinga, calls-kku naduvula oru chinna `time.sleep` serunga, thirumba use pannappora results-a thirumba fetch pannaama cache pannunga.

### API documentation-a padikkiradhu

Code ezhudhuradhukku munnaadi, documentation-la idhaiyellaam kandupidinga: **base URL**, eppadi **authenticate** panradhu, **endpoints**, avatroda **parameters**, oru **example response**, **error codes**, **pagination**, **rate limits**. Ovvoru thadavaiyum API-a call pannaamale unga parsing-a test panna, example response-a oru file-la save pannunga. Pinnaadi oru AI model-a call panradhum idhe routine thaan.

## Oru worked example

Anita-kku rendu vishayangal venum: OpenAQ-kku therinja ellaa Indhiya stations-oda list, oru Delhi station-oda latest readings. Avanga oru chinna helper build panraanga, ovvoru call-um adhu vazhiyaa thaan pogum, adhanaala timeout, retries, logging, error checks ellaam ore idaththula irukkum.

```python
import logging
import os
import time

import requests

logging.basicConfig(level=logging.INFO)
log = logging.getLogger("aq")

BASE = "https://api.openaq.org/v3"
RETRYABLE = {429, 500, 502, 503, 504}

session = requests.Session()                      # reuses connections
session.headers["X-API-Key"] = os.environ["OPENAQ_API_KEY"]

def get_json(path, params=None, tries=4):
    for attempt in range(tries):
        last = attempt == tries - 1
        wait = 2 ** attempt                       # 1, 2, 4 seconds
        try:
            r = session.get(BASE + path, params=params, timeout=(5, 20))
        except (requests.Timeout, requests.ConnectionError) as e:
            log.warning("%s: %s (try %d)", path, type(e).__name__, attempt + 1)
            if last:
                raise
            time.sleep(wait)
            continue
        if r.status_code in RETRYABLE and not last:
            ra = r.headers.get("Retry-After", "")
            wait = int(ra) if ra.isdigit() else wait
            log.warning("%s: %d, retry in %ds", path, r.status_code, wait)
            time.sleep(min(wait, 60))
            continue
        r.raise_for_status()                      # 4xx, or still failing
        try:
            return r.json()
        except requests.JSONDecodeError:
            raise RuntimeError(f"not JSON: {r.text[:200]!r}") from None
```

Ovvoru pagudhiyum yen irukku:

- Oru **`Session`** connection-a reuse pannum, niraiya calls-kku adhu innum vegam; key header-aiyum adhu vechirukkum, adhanaala endha call-um adhai marakkaadhu.
- **Timeouts, connection errors catch pannappattu retry aagudhu**, yennaa avai thaan ellaaththaiyum vida adhigamaa varra thaatkaaliga failure. Kadaisi try-la error maraikkappadaama raise aagudhu.
- **Kadaisi try-kku appuram sleep illai**, wait 60 seconds-kku cap pannappattirukku, adhanaala oru visiththiramaana `Retry-After` value job-a oru mani neram niruththi vaikka mudiyaadhu.
- **Retry aagaadha ovvoru reply-layum `raise_for_status()` run aagudhu**, adhanaala oru `401`, oru `404`, allathu sariyaagave aagaadha oru `503` oru thelivaana message kooda program-a niruththum.
- **Ovvoru failure-um path, status kooda log aagudhu**; oru nightly job 3 a.m.-kku fail aagumbodhu ungalukku thevaippadradhu idhu thaan.

Appuram rendu tasks:

```python
def get_all(path, params, limit=100, max_pages=50):
    rows = []
    for page in range(1, max_pages + 1):
        data = get_json(path, {**params, "limit": limit, "page": page})
        batch = data["results"]
        rows.extend(batch)
        if len(batch) < limit:                    # short or empty page
            break
    return rows

stations = get_all("/locations", {"iso": "IN"})
print(len(stations), "stations")
for s in stations[:3]:
    print(s["id"], s["name"])

latest = get_json("/locations/8118/latest")
for row in latest["results"]:
    print(row["sensorsId"], row["value"], row["datetime"]["local"])
```

Ovvoru `sensorsId`-um station-la irukkura oru instrument, udhaaranamaa adhoda PM2.5 allathu NO2 sensor. Oru thani endpoint, `/locations/8118/sensors`, ovvonnum endha pollutant-a measure pannudhunnu sollum. Ippadi rendu endpoints-a join panradhu saadhaarana API velai thaan.

Avangaloda mudhal runs ippadi pochu:

| Run | Avanga enna paarththaanga | Kaaranam | Fix |
| --- | --- | --- | --- |
| 1 | `KeyError: 'OPENAQ_API_KEY'`, endha request-um anuppappadalai | Avanga oru pudhu terminal-a thirandhaanga, anga variable set aagalai | Andha terminal-la variable-a set panni, thirumba run pannaanga |
| 2 | `401 Client Error: Unauthorized` | Innoru API-oda tutorial-la irundhu `Authorization: Bearer ...`-a copy pannirundhaanga | OpenAQ-oda docs solra maadhiri key-a `X-API-Key`-la anuppinaanga |
| 3 | `TypeError: list indices must be integers or slices, not str` | Avanga `latest["results"]["value"]` ezhudhinaanga; `results` oru list | Shape-a print panni, appuram list mela loop pannaanga |
| 4 | Muzhu Indhiyaavukkum sariyaa 100 stations | `/locations`-a oru thadavai call panni page 1-a mattum padichaanga | Pages mela loop panna `get_all` ezhudhinaanga |
| 5 | `429, retry in 1s`-ngura oru log line, appuram muzhu list | Vegamaa page pannadhaala rate limit-a thottuchu | Edhuvum illai: helper wait panni thodarndhuchu |

Runs 1-la irundhu 3 varai ovvonnum oru vera error type kuduththuchu, ovvoru type-um neraa adhoda kaaranaththai kaattuchu. Code-a thirumba padikkiradhukku munnaadi error-oda mudhal vaarththaiyai padinga.

Script perusaagumbodhu, retry velaiyai `requests` endha library mela build aayirukko adhukitta kuduththudalaam. Idhu oru common production setup:

```python
import requests
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

retry = Retry(total=4, backoff_factor=1,
              status_forcelist=[429, 500, 502, 503, 504],
              allowed_methods=["GET"])        # never auto-retry POST
session = requests.Session()
session.mount("https://", HTTPAdapter(max_retries=retry))
```

Adhu back off pannum, 429, 503-la `Retry-After`-a follow pannum, connection errors-a ungalukkaaga retry pannum. List-la irukkura oru status-la tries theerndhuttaa, kadaisi reply-a return pannaama `requests.exceptions.RetryError`-a raise pannum, adhanaala adhaiyum catch pannunga. Ovvoru call-kkum timeout, oru JSON check, oru page loop innum ungalukku venum.

## Podhuvaa panra thappugal

- **Status-a check panradhukku munnaadi data-va padikkiradhu.** Appo oru error reply sila lines-kku appuram kuzhappamaa fail aagum. Mudhalla `raise_for_status()`-a call pannunga.
- **Timeout illai.** Badhil sollaadha oru server muzhu program-aiyum hang pannidum.
- **JSON shape-a guess panradhu.** `json.dumps(data, indent=2)` vechu oru thadavai print panni, appuram access path-a ezhudhunga.
- **Oru list mela string key.** Adhu thaan mela sonna `TypeError`; oru index-a edunga allathu loop pannunga.
- **`null` values irukkumbodhu `.get(key, default)`-a nambradhu.** Key `null` kooda irundhaa adhu `None`-a return pannum.
- **Page 1-a mattum padikkiradhu.** 100 maadhiri oru round count thaan echcharikkai adaiyaalam.
- **Ellaaththaiyum retry panradhu, allathu romba vegamaa panradhu.** `401` allathu `404`-a retry pannaa calls veenaagum, oru tight loop ungalai block aakkidum, idempotency key illaama oru POST-a retry pannaa oru customer-kitta rendu thadavai charge aagalaam.
- **Code, screenshots allathu logs-la keys.** Environment variables use pannunga, oru key leak aanaa udane adhai replace pannunga.

## Practice pannunga

Keezha link pannirukkura requests library-oda quickstart-a padinga, appuram indha unmaiyaana APIs-la onnai use pannunga (rendume November 2026 nilavarappadi check pannappattadhu):

- **OpenAQ**: Indhiya nagarangalukkaana air-quality data. Adhukku adhoda website-la irundhu oru free key venum, adhu `X-API-Key` header-la anuppappadum.
- **Open-Meteo**: weather, air-quality forecasts. Adhukku key vendaam, non-commercial use-kku free, adhanaala idhu thaan ellaaththaiyum vida vegamaana mudhal call.

1. **Call panni paarunga.** Oru endpoint-a call panni, `json.dumps(data, indent=2)` vechu reply-a print panni, moonu values-kku access paths ezhudhunga; kurainjadhu onnaavadhu oru list-kkulla irukkanum.
2. **Venumne fail panna vainga.** Oru thappaana key, oru thappaana path, `timeout=0.001` anuppunga. Ovvonnukkum varra sariyaana error-a note pannunga, `r.json()`-la crash aagaama unga code oru thelivaana message print pannudhaannu check pannunga.
3. **Helper-a serunga.** Ovvoru call-kkum munnaadi `get_json` helper-a vechu, adhu log panni retry pannudhaannu confirm pannunga.
4. **Ellaa page-aiyum padinga.** Oru list endpoint-kku, oru page cap kooda ellaa pages-aiyum fetch panni, unga count-a page 1-la mattum varradhoda compare pannunga.
5. **Key-a secure pannunga.** Adhai oru environment variable-kku maaththi, oru pudhu terminal-a thirandhu, adhu set aagalainnaa enna nadakkumnu ungalukku theriyumaannu confirm pannunga.

**Mudinjadhu-nnu eppo sollalaam:** oru key, oru timeout kooda oru API-a call panna mudiyum, oru failure ungaloda-thaa server-oda-thaannu error-a mattum vechu solla mudiyum, guess pannaama nested JSON-a padikka mudiyum, ellaa page-aiyum fetch panna mudiyum, endha failures-a retry panreenga yennu explain panna mudiyum.
