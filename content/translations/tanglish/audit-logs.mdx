## Idhu enna

**Audit log** mukkiyamaana events-oda record: yaaru enna pannaanga, eppo, edha data-la, enna result-oda. Idhu application logs-um traces-um-la irundhu veru:

- **Application logs** engineers debug panna help pannum. Avai noisy, short-lived, format-a saadharanamaa maathalaam.
- **Traces** engineering, quality velaikku, oru request-oda internal steps-a vivaramaa kaattum.
- **Audit logs** accountability kelvigalukku badhil solluvaanga: "3 March-la account 4471 pathi assistant-kitta yaaru kettaanga, adhu avanga-kitta enna kaattuchu, refund-a yaaravadhu approve pannaangala?" Avai complete-aa, consistent-aa, tampering-la irundhu paadhukaakkapattu, oru define panna kaalam varaikkum vechirukkanum.

AI systems-ku, audit events-la usually sign-ins-um ovvoru kelvi-yum answer-um, illa avai-yoda reference-um irukkum. Retrieve aana documents, edutha tool actions, approvals, rejections, configuration changes (prompt, model, permissions), admin actions-um serum.

| | Application logs | Traces | Audit logs |
|---|---|---|---|
| Yaarukku | Engineers | Quality, debugging | Compliance, disputes |
| Enna vechirukkum | Format maarura noisy, short lines | Oru request-oda ovvoru internal step-um | Yaaru enna, eppo, edhukku, result enna |
| Shape | Free text | Spans | Fixed shape, append-only |
| Evvalavu kaalam | Naatkal | Vaarangal | Varushangal, policy-padi |

```flow
dir: LR
title: Request id-um trace id-um vachu link aagirukku
Application logs -[request id]-> Traces
Traces -[trace id]-> Audit logs
```

## Idhu eppadi work aagudhu

**Oru fixed event shape.** Ovvoru event-um oru solla pattu time zone-la timestamp-aiyum actor-aiyum record pannum: user id, oru service, illa "agent on behalf of user X". Action, target (document illa record ids), outcome, vivaram-ku link aagura request illa trace id, amalla irukkura app, prompt, model versions-um record pannum.

**Edha record pannakoodaadhu.** Passwords, tokens, muzhu card numbers-a eppavum log pannaadheenga. Personal data pathi veendumae mudivu pannunga: perumbaalum audit log-la ids-um hashes-um store pannuvaanga, muzhu text-a thaniyaa, adhigam restrict panna, kammi retention-oda oru store-la vechu, id vachu link pannuvaanga. Client-oda retention policy-yum sattamum follow pannunga; India-oda DPDP Act, personal data thevaiyaana neram-ku mela vechirukka koodaadhu-nu solludhu.

**Tamper resistance.** Audit events-a, application code-aala edit illa delete panna mudiyaadha append-only store-la ezhudhunga: retention locks-oda write-once storage bucket, managed audit service, illa thaniya log account. Yaaru log-a padikkalaam-nu restrict pannunga, log-ku varra access-aiyum log pannunga.

**Queryable-aa aakkunga.** Investigations-ku nimishangalla badhil thevai: "March-la indha customer record-la ellaa actions", "oru aal approve panna, agent propose panna ovvoru refund-um". Events-a unga client-oda tools search panna mudiyura format-la store pannunga.

**Clock-um identity-yum.** Synchronise panna clocks-aiyum sign-on-la irundhu verify aana identity-yum use pannunga, user type panna peru eppavum illa.

**Oru audit event, field vaariyaa:**

| Field | Example | Yen |
| --- | --- | --- |
| Timestamp | `2026-05-03 11:02:14 IST` | Eppo, solla pattu time zone-la |
| Actor | `user=emp-2213` or `agent (on behalf of emp-2213)` | Yaaru, sign-on-la verify aanadhu |
| Action | `ask`, `retrieve`, `propose`, `approve` | Enna nadandhadhu |
| Target | `customer=CUST-4471`, document ids | Edhukku |
| Outcome | `success`, `rejected`, `error` | Enna result-oda |
| Links | `request=req-88a1 trace=tr-71f0` | Vivaram enga kidaikkum |
| Versions | `prompt=v12 model=...` | Edhu configuration idha uruvaakkunadhu |

**Retention-um access-um nadaimuraila.** Launch-ku munnaadi client-oda compliance team-oda retention-a agree pannunga. Example, financial record rules-oda match aaga audit events-a 8 varushathukku, muzhu question-um answer text-um 180 naatkalukku oru restrict panna store-la, application logs-a 30 naatkalukku vainga. Audit log-ku read access-a compliance, security maadhiri oru chinna peyar solla patta group-ku kudunga, muzhu engineering team-ku illa, andha list-a ovvoru quarter-um review pannunga.

**Postgres-la oru insert-only table.** Permissions plus oru trigger, adhanaala app-aalum, kavanamilla admin script-aalum history-a maathi ezhudha mudiyaadhu:

```sql
CREATE TABLE audit_events (
  id bigserial PRIMARY KEY,
  at timestamptz NOT NULL DEFAULT now(),
  actor text NOT NULL, action text NOT NULL, target text,
  outcome text NOT NULL, request_id text, versions jsonb,
  detail jsonb, prev_hash text, hash text NOT NULL
);

CREATE FUNCTION audit_no_change() RETURNS trigger AS $$
BEGIN
  RAISE EXCEPTION 'audit_events is append-only';
END $$ LANGUAGE plpgsql;

CREATE TRIGGER audit_lock BEFORE UPDATE OR DELETE ON audit_events
  FOR EACH ROW EXECUTE FUNCTION audit_no_change();

GRANT INSERT, SELECT ON audit_events TO app;
GRANT USAGE ON SEQUENCE audit_events_id_seq TO app;
```

**Code-la oru hash chain.** Ovvoru event-um munnaadi irundhadhoda hash-a serthukkum, adhanaala maathina illa kaanaama poana row, neenga verify panna theriyum:

```python
import hashlib, json

def event_hash(event, prev_hash):
    body = json.dumps({k: event[k] for k in sorted(event) if k not in ("hash", "prev_hash")},
                      sort_keys=True, default=str, ensure_ascii=False)
    return hashlib.sha256((prev_hash or "").encode() + body.encode()).hexdigest()

def append(db, event):
    with db.transaction():
        last = db.fetchone("SELECT hash FROM audit_events ORDER BY id DESC LIMIT 1 FOR UPDATE")
        prev = last[0] if last else None
        event["prev_hash"], event["hash"] = prev, event_hash(event, prev)
        db.insert("audit_events", event)

def verify(rows):
    prev = None
    for r in rows:                                 # ordered by id
        if r["prev_hash"] != prev or event_hash(r, prev) != r["hash"]:
            return f"chain broken at event {r['id']}"
        prev = r["hash"]
    return "ok"
```

`verify`-a ovvoru raathiriyum odunga, latest hash-a application ezhudha mudiyaadha edathula copy pannunga, thaniya account illa compliance-ku daily email maadhiri. Appo database access irukkura yaaraalayum chain-a amaidhiyaa maathi ezhudha mudiyaadhu.

**Exports-ku write-once storage.** Cloud object stores, retention kaalam varaikkum objects-a delete aagaama lock panna mudiyum (example S3 Object Lock compliance mode-la). Audit events-a ovvoru naalum compressed files-aa angae export pannunga. Idhu main database-a chinnadhaavum vechukkum.

**Investigators-ku thevaiyaana queries, munnaadiyae ready-aa.**

```sql
-- Everything that touched one customer in a date range, in IST:
SELECT at AT TIME ZONE 'Asia/Kolkata', actor, action, outcome, request_id
FROM audit_events WHERE target = 'customer=CUST-4471'
  AND at >= '2026-03-01 00:00+05:30' AND at < '2026-04-01 00:00+05:30' ORDER BY at;

-- Agent proposals approved by one manager:
SELECT a.at, a.target, a.detail->>'amount_inr' AS amount
FROM audit_events a WHERE a.action = 'approve' AND a.actor = 'emp-1180' ORDER BY a.at;
```

Idhai compliance team-ku named queries illa dashboard views-aa save pannunga.

**Log-ku varra access-aiyum log pannunga.** Audit events-a padikkuradhu kooda record pannanum-nu oru event: yaaru edha customer-a, eppo search pannaanga.

## Oru worked example

Kochi cooperative bank, staff loan-restructuring requests-ku responses draft panna oru AI agent use panludhu. Aaru maadham kazhichu oru borrower avanga request-a anyaayamaa reject pannaanga-nu complain panraanga, bank-oda ombudsman office muzhu history kekkudhu.

Ovvoru event-um audit aanadhaala, bank-oda compliance officer oru manineram-la idha tara mudiyum:

```text
2026-05-03 11:02:14 IST  user=emp-2213 (branch: Aluva)  action=ask
    request=req-88a1 trace=tr-71f0 customer=CUST-4471 prompt=v12 model=alias:chat-default(2026-04)
2026-05-03 11:02:19 IST  agent(on behalf of emp-2213)  action=retrieve
    docs=[policy-restructuring-v6#s4, cust-4471-statement-2026-04]
2026-05-03 11:02:31 IST  agent(on behalf of emp-2213)  action=propose  type=reject_restructuring  reason_ref=tr-71f0
2026-05-03 11:09:47 IST  user=emp-0457 (manager)  action=approve  proposal=req-88a1
```

Use aana policy version appuram revise aagirundhadhum, oru manager AI-oda recommendation-a ezhu nimishathula approve pannadhum history-la theriyudhu. Bank case-a thirumba thirandhu, restructuring rejections-ku approver-oda ezhuthula oru note thevai-nu oru rule serkkudhu. Audit log thappa thadukkala, aana adha therinjadhaa, sari panna mudiyuradhaa, ombudsman-kku explain panna mudiyuradhaa aakkichu.

**Bank apram enna maatchu.** Ezhuthula note rule-oda, bank rendu checks serthuchu. Oru manager high-impact AI recommendation-a rendu nimishathukkulla approve pannina alert varum, adhu rubber-stamping-oda sign. Oru maadhaandhira report, managers agent-oda proposals-a evvalavu thadavai override pannaanga-nu kaattum.

## Podhuvaa panra thappugal

- **Debug logs-a audit trail-aa use panradhu.** Avai incomplete, edit panna mudiyum, rotate aagi poidum.
- **Ellaathaiyum muzhusaa record panradhu.** Neenda retention log-la personal data-oda muzhu prompts, pudhu privacy risk-a uruvaakkum. References-a store panni, muzhu text-a kammi retention-oda thaniya vainga.
- **Edit panna mudiyura storage.** Oru administrator amaidhiyaa entries-a delete panna mudinja, log konjam thaan prove pannum.
- **Version information illa.** Prompt, model versions illaama, system andha neram yen appadi nadandhukkichu-nu explain panna mudiyaadhu.
- **Agent-a actor-aa log panradhu.** Edhu yaaroda behalf-la seiyuthu-nu, yaaru approve pannaanga-nu eppavum record pannunga.
- **Failures-a mattum audit panradhu.** Disputes perumbaalum "work aana" decisions pathi thaan. Successful actions-aiyum approvals-aiyum kooda record pannunga.
- **Application update illa delete panna mudiyura audit rows.** Permissions-um trigger-um vachu lock pannunga.
- **Tampering-a kandupidikka vazhi illa.** Hash chain use pannunga, latest hash-a vera idathula vainga.
- **Incident nadakkum podhu investigation queries-a build panradhu.** Munnaadiyae ezhudhi test pannunga.

## Ordinary logs podhumaana idangal

- **Veru users illaadha prototypes, personal tools.**
- **Public information-la read-only assistants**, yaarudaiya records-um maaraadha idathula.
- **Customer data-va thodaadha short-lived internal experiments.**

System records-la act panna, personal illa financial data-va handle panna, illa oru client-oda compliance team "yaaru enna panninaanga, eppo?"-nu kekkum podhu formal audit logs thevai.

## Demo-la irundhu production-ku

- **Verify aana identities, IST timestamps, versions-oda oru fixed event schema use pannunga.**
- **Audit storage-a append-only aakkunga**, ovvoru raathiri hash-chain check-oda.
- **Agree aana retention-oda ovvoru naalum write-once storage-ku export pannunga.**
- **Read access-a oru peyar solla patta group-ku restrict panni log pannunga**, quarter-ku oru thadava review pannunga.
- **Investigation queries-a save panni, test panni vainga.**

## Practice pannunga

OWASP Logging Cheat Sheet-a padinga, mukkiyamaa edha log pannanum, edha vilakkanum-nu solra sections-a.

1. Mela irukkura fields-oda unga AI app-ku oru audit event schema define panni, ask, retrieve, tool action, approval, configuration change-ku events emit pannunga.
2. Avai-a oru append-only store-la ezhudhunga (example object lock-oda oru cloud bucket, illa insert-only permissions-oda thani database table).
3. Oru investigator-ku thevaiyaana rendu queries ezhudhunga: oru customer id-ku oru date range-la ellaa events-um, oru kuripitta manager approve panna ovvoru agent action-um.
4. Hash chain-oda pathu events-a insert pannunga, oru admin-aa trigger-a disable panni oru row-a maathunga, verify idha break-nu report panradha kaattunga.

**Mudinjadhu-nu eppo sollalaam:** Application logs-a padikkaama, unga audit log-la mattum irundhu oru request-oda muzhu kadhaiya reconstruct panna mudiyum.
