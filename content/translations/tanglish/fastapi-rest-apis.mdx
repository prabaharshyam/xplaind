## Idhu enna

REST API, vera programs unga system-a HTTP vazhiyaa use panna vaikkum. Ovvoru **endpoint**-um oru URL-um oru method-um: `POST /tickets` oru ticket create pannum, `GET /tickets/42` onna padikkum. Caller JSON anuppum, JSON thirumbi varum, eppadi nadandhudhu-nu sollura oru **status code**-oda.

FastAPI-na idhumaadhiri APIs build panna oru Python framework. Type hints-um Pydantic models-um vachu saadharana functions ezhudhuveenga; FastAPI adha input-a validate panra, output-a JSON-aa maathura, `/docs`-la interactive documentation publish panra endpoints-aa maathidum. Adhu async code-a native-aavum odum, model APIs-a kaathirukkura services-ku adhu nalla poruthama irukkum.

```flow
Caller | vera team-oda app: POST /claims/triage -> FastAPI body-a Pydantic-la validate pannum
FastAPI body-a Pydantic-la validate pannum -[fail aana]-> 422 | thappaana fields-oda list
FastAPI body-a Pydantic-la validate pannum -[ok]-> Model client-a inject pannu | Depends
Model client-a inject pannu -> Unga function model API-a call pannum
Unga function model API-a call pannum -[model down]-> 503 | "konjam neram kazhichu try pannunga"
Unga function model API-a call pannum -[ok]-> response_model output-a filter pannum
response_model output-a filter pannum -> 200 | category: "motor", summary: "Rear bumper damage"
```

Indha lesson-la Kochi-la oru insurance broker-a follow pannuvom, avanga vera teams oru claims-triage service-a call panna virumburaanga.

## Idhu eppadi work aagudhu

**Methods.** GET padikkum, edhayum maathakoodaadhu. POST create illa velaiya trigger pannum. PUT replace pannum, PATCH konjam update pannum, DELETE remove pannum. Indha arthangalukku kattupaadaa irundha, caches-um retries-um vera engineers-um sariyaa ooga mudiyum.

**Status codes.** Success-ku 200 OK-um 201 Created-um. Malformed request-ku 400, caller sign in pannala-na 401, sign in pannirundhum idha panna kudaadhunaa 403, adhu illaina 404, body validation-la fail aanaa 422 (FastAPI-oda default), avanga romba adhigama anuppuraanga-na 429. 500-na unga code udainjirukku, 503-na model provider maadhiri oru dependency down.

**Models.** Request body-la oru Pydantic model irundhaa, unga function odradhukku munnaadi FastAPI thappaana input-a 422-oda, entha fields fail aachu-nu oru list-oda reject pannum. `response_model` thirumbi enna pogudhu-nu control pannum, appo cost figure maadhiri internal field thaetchaiyaa leak aagaadhu.

**Dependencies.** FastAPI-oda `Depends` database session, current user, model client maadhiri shared vishayangala ovvoru endpoint-kullayum inject pannum. Tests-la adha fakes-a maathikkalaam.

**Testing.** `TestClient` unga app-a memory-la, server illaama call pannum, adhanaala endpoint tests milliseconds-la odum.

**Callers nambura status codes:**

| Code | Artham | Caller-oda saadharana reaction |
| --- | --- | --- |
| 200, 201 | Success, illa created | Result-a use pannu |
| 400 | Malformed request | Request-a sari pannu; retry pannaadha |
| 401 | Sign in pannala | Sign in pannu, apram retry pannu |
| 403 | Anumadhi illa | Niruththu; access kelu |
| 404 | Kidaikkala | Id-a check pannu |
| 422 | Body validation-la fail | Peru solla pattadha fields-a sari pannu |
| 429 | Romba requests | Kaathiru, apram retry pannu |
| 500 | Unga code udaindhudhu | Report pannu |
| 503 | Oru dependency down | Backoff-oda apram retry pannu |

**Kaalam kadandhum nikkura endpoints design panradhu.** Resources-ku nouns (`/claims`, `/claims/{id}`), actions-ku methods use pannunga. Path-la illa header-la oru version vainga (`/v1/claims`), appo callers-a udaikkaama API-a apram maathalaam. Ella idathulayum ore error shape-a thirumbi tharunga, example `{"detail": "..."}`, appo callers errors-a oru idathulaye handle pannalaam. Ovvoru endpoint-a code-layae oru summary-yum examples-um vachu document pannunga; FastAPI avatrai `/docs`-la thaanaagavae kaattum, perumbaalum vera teams padikkura ore documentation adhu thaan.

**Browser-la try pannunga.** Request validation thaan nalla API-oda uyir. Dictionary-a maathi oru thappaana body anuppi paarunga.

```python
from pydantic import BaseModel, Field, ValidationError

class NewOrder(BaseModel):
    item_id: str = Field(pattern=r"^SKU-\d{4}$")
    quantity: int = Field(gt=0, le=20)
    pin_code: str = Field(pattern=r"^[1-9]\d{5}$")

body = {"item_id": "SKU-0042", "quantity": 0, "pin_code": "56001"}
try:
    print(NewOrder.model_validate(body))
except ValidationError as err:
    for e in err.errors():
        print("422:", e["loc"][0], "-", e["msg"])
```

## Oru worked example

Kochi-la oru insurance broker-ku, vera teams claim descriptions anuppi, oru category-yum oru summary-yum thirumbi vaanga venum.

```python
from fastapi import FastAPI, HTTPException, Depends
from pydantic import BaseModel, Field

app = FastAPI(title="Claims triage")

class ClaimIn(BaseModel):
    policy_no: str = Field(pattern=r"^[A-Z]{3}\d{7}$")
    description: str = Field(min_length=20, max_length=5000)

class ClaimOut(BaseModel):
    category: str
    summary: str

@app.post("/claims/triage", response_model=ClaimOut, status_code=200)
async def triage(claim: ClaimIn, llm=Depends(get_llm)):
    try:
        result = await llm.classify(claim.description)
    except ProviderDown:
        raise HTTPException(503, "Triage is unavailable; try again shortly")
    return ClaimOut(category=result.category, summary=result.summary)
```

Policy number "abc123"-oda oru request model-a kooda pogaadhu: FastAPI field-a peru solli 422 tharum. Model provider down-aa irundhaa, callers-ku kuzhappamaana 500 illa, retry panna koodiya 503 kidaikkum.

Test model-a fake pannum:

```python
from fastapi.testclient import TestClient

def test_triage_returns_category():
    app.dependency_overrides[get_llm] = lambda: FakeLLM("motor", "Rear bumper damage")
    r = TestClient(app).post("/claims/triage",
        json={"policy_no": "MOT1234567", "description": "Car was hit from behind at a signal"})
    assert r.status_code == 200 and r.json()["category"] == "motor"
```

`/docs`-a thirandhaa, broker-oda vera teams endpoint-a browser-laye try pannalaam, request schema-vum already ezhudhi irukkum.

**Vera teams mudhalla gavanicha vishayam.** Broker-oda mobile team oru naalaiyilaye integrate pannidaanga, perumbaalum `/docs` ovvoru field-yum, adhoda rules-um, oru example-um kaattinadhaala, thappaana requests entha field-nu peru solli 422-oda thirumbi vandhadhaalayum. Model provider-ku konjam neram outage aana podhu, avanga app crash aagaama 503-ku "Triage is busy, try again in a minute"-nu kaattudhu, yen-na entha vagai failure-nu status code adhukku sonnadhu.

## Podhuvaa panra thappugal

- **Errors-ku 200 thirumbi tharadhu.** Status 200-oda `"error": true`-nu body sonna, ella retry, monitoring tools-um udaiyum. Sariyaana code use pannunga.
- **Database rows-a nera thirumbi tharadhu.** Internal fields leak aagum. Eppavum oru response model set pannunga.
- **Async endpoints-la blocking calls.** `async def`-kulla synchronous model client server-a freeze pannum. Async client use pannunga, illa endpoint-a simple `def`-oda declare pannunga, appo FastAPI adha thread pool-la odavaikkum.
- **Model call-la timeout illa.** Oru hang aana request oru worker-a eppovum pidichu vechukkum. Timeouts set panni 503 illa 504 thirumbi tharunga.
- **Input limits-a thavara vidradhu.** Maximum length illanaa, yaaraavadhu 300-page document-a paste pannuvaanga, unga token bill yerum.
