## Idhu enna

Unga mudhal n8n workflow-la oru trigger-um sila nodes-um irundhuchu. Oru business nambiyirukkura workflows innum adhigamaa pogum. Avai aayirakkanakkaana records-a process pannum, strict limits irukkura APIs-a call pannum, othuppogaadha rendu systems-la irundhu data-va serkkum, yaarum paakkaadha raathiri 3 manikku edhaavadhu fail aanaalum velai senjukittae irukkanum.

Idhu ovvonnukkum n8n-la oru building block irukku:

| Building block | Edhukku |
| --- | --- |
| **Sub-workflows** | Niraiya workflows call panra podhuvaana steps, functions maadhiri |
| **Paging, batches, waits** | Oru API-oda limits-a meeraama data-va fetch panradhu, anuppuradhu |
| **Merge** | Oru shared id vachu rendu sources-a serkkuradhu, match aagaadha items-aiyum serthu |
| **Code nodes** | Visual nodes cover pannaadha logic-kku chinna JavaScript allathu Python snippets |
| **AI nodes** | Emails maadhiri kuzhappamaana text-a padichu, rules check pannakkoodiya fields-aa maathuradhu |
| **Error workflows** | Oru automatic run fail aanaa oru aalukku alert anuppuradhu |

Indha lesson, Bengaluru-la oru skincare brand than daily payment reconciliation-a automate panradhai follow pannudhu; adhaavadhu ovvoru prepaid order-kkum payment gateway unmaiyilaeye panathai pay out pannuchaa-nnu check panra velai.

```flow
title: Dhinasari payment reconciliation
Schedule: kaalai 6 mani IST -> Shopify: prepaid orders, kadaisi 10 naal
Schedule: kaalai 6 mani IST -> Gateway: settle aana payments, kadaisi 3 naal | page panni, vegam kattuppaduthi
Shopify: prepaid orders, kadaisi 10 naal -> Payment id-la Merge | rendu pakkathula irundhum match aagaadha items-a vachukkum
Gateway: settle aana payments, kadaisi 3 naal -> Payment id-la Merge
Payment id-la Merge -> Code: ovvoru row-aiyum flag pannu -> Sub-workflow: sheet-kku upsert -> Slack: summary
Endha failure-um -> Error workflow | execution link-oda finance-ops-kku alert
```

## Idhu eppadi velai seiyudhu

### Items: ellaathukkum adiyila irukkura idea

Ovvoru node-um **items**-oda oru list-a vaangi, oru list-a aduthadhukku anuppum. Ovvoru item-um oru JSON record, oru sheet-oda oru row maadhiri. Perumbaalaana nodes ovvoru item-kkum oru thadavai odum: Gmail-kku pathu items ponaa pathu emails. `{{ $json.email }}` maadhiri oru **expression** ippodhaiya item-oda oru field-a padikkum. Munnaadi irukkura oru node-la irundhu oru field-a padikka, andha node-oda perai sollunga: `{{ $('Get orders').item.json.order_name }}`.

### Structure: oru workflow-kku oru job

Ovvoru workflow-aiyum ore job-oda vachukkonga. Podhuvaana steps-a oru **sub-workflow**-la vainga: **When Executed by Another Workflow** trigger-la start aagura, **Execute Sub-workflow** node vachu call panra oru thani workflow. Trigger-la endha data vandhaalum yethukkaama, neenga edhirpaakkura input fields-a define pannunga, udhaaranamaa `payment_id`, `flag`. Appo call panra node endha fields-a fill pannanum-nu sariyaa list pannum, onnu missing-aa irundhaa easy-aa kandupidikkalaam.

Nodes-kku avai enna pannudho adhai vachu per vainga, "HTTP Request 3" illaama "Get prepaid orders" maadhiri; appo yaar venumnaalum canvas-a padikkalaam.

### Volume-um rate limits-um

Perumbaalaana APIs results-a oru thadavaikku oru **page**-aa return pannum, oru second-kko oru nimishathukko ethana requests anuppalaam-nu limit vaikkum. Moonu tools serndhu velai seiyum:

- **Pagination** inime pages illai-ngra varaikkum page mela page-aa fetch pannum. HTTP Request node-la oru pagination option irukku, niraiya app nodes-la ungalukkaaga page panra "Return All" switch irukku.
- **Batching** neenga evvalavu vegamaa anuppureenga-nnu kattuppaduthum. HTTP Request node-la oru Batching option irukku (oru batch-kku ethana items, batches-kku naduvula oru pause). Innum control venumnaa, oru batch size kooda **Loop Over Items**-aiyum, loop-kkulla oru **Wait** node-aiyum use pannunga.
- **Retry On Fail**, ovvoru node-oda settings-layum irukku, fail aana call-a thirumba pannum. Adhu adhigapatcham anju tries-aiyum, tries-kku naduvula adhigapatcham anju seconds-aiyum thaan allow pannum, adhanaala adhu oru chinna blip-a handle pannum; pacing-aiyum illa, neenda outage-aiyum illa.

Pacing rule simple kanakku thaan. Limit oru nimishathukku L requests, ovvoru batch-um B requests anuppudhu-nnaa, batches-kku naduvula kuranjadhu B × 60 ÷ L seconds wait pannunga. Oru batch-kku 20 requests, oru nimishathukku 60 limit-na, adhu 20 seconds. Konjam margin serunga, yenna oru batch-kkulla irukkura requests ore nerathula kilambalaam.

```flow
dir: LR
Oru page-a request pannu | 100 rows -> Rows-a process pannu -> Innum pages irukkaa?
Innum pages irukkaa? -[aamaa, oru pause-kku appuram]-> Oru page-a request pannu
Innum pages irukkaa? -[illa]-> Adutha step
```

### Data-va merge panradhu, match aagaadhadhai vachukkuradhu

**Merge** node rendu inputs-a position vacho, **matching fields** vacho combine pannum, udhaaranamaa rendulayum varra oru payment id. Matching fields-kku, edhu minjum-nu output setting thaan mudivu pannum:

| Output choice | Enna veliya varum | Idhu maadhiri |
| --- | --- | --- |
| Keep Matches | Rendu inputs-layum irukkura items mattum | Oru inner join |
| Keep Non-Matches | Partner illaadha items mattum | Micham irukkuravai |
| Keep Everything | Rendu inputs-la irundhum matches-um non-matches-um | Oru full outer join |
| Enrich Input 1 or 2 | Oru input muzhusaa, kooda innonnula irundhu match aagura data | Oru left allathu right join |

Mela irukkura labels recent versions-la irukkuravai; unga version-la dropdown-a check pannunga. Oru reconciliation-la match aagaadha items thaan findings, adhanaala Keep Matches ovvoru problem-aiyum maraichidum. Keep Everything-a thernthedunga; Keep Non-Matches mattum use pannaa, amounts-a innum check panna vendiya matched rows-um drop aayidum. Innum rendu traps: rendu inputs-layum `amount`-ngra field irundhaa onnu innonnai overwrite panniddum, adhanaala mudhalla oru **Edit Fields** node vachu fields-a rename pannunga. Appuram, rendu pakkathulayum unique-aa irukkura oru key-la match pannunga, payment id maadhiri; customer-oda phone number maadhiri repeat aagakkoodiya onnula illa.

### Code nodes

Oru **Code** node JavaScript allathu Python-a ottum. Default-aana "Run Once for All Items" mode-la, adhu `$input.all()` vachu ella items-aiyum padikkum, `$('Node name').all()` vachu innoru node-oda items-a padikkalaam, objects-oda oru list-a return pannanum, ovvonnulayum oru `json` key irukkanum. Idhu Indhiya muraiyila ezhudhina oru amount-a serkkudhu:

```js
// Mode: Run Once for All Items
return $input.all().map((item) => ({
  json: {
    ...item.json,
    amount_text: (item.json.amount / 100).toLocaleString('en-IN', { style: 'currency', currency: 'INR' }),
  },
}));
```

12500000 paise amount-kku `amount_text` "₹1,25,000.00". Python thevaippattaa thavira JavaScript-aiyae prefer pannunga: n8n 2.0-la irundhu Code node native Python-a ottudhu, adhu items-a `_items`-aa padikkum, n8n-oda matha built-in helpers edhuvum adhula illa. Code nodes-a chinnadhaa, comments kooda vainga. Onnu oru screen-a thaandi valarndhaa, adhu oru node-kkulla olinjirukkura oru chinna service, anga adhai test panradhu kashtam.

### Schedules-um time zones-um

Oru Schedule trigger workflow-oda time zone-la fire aagum. `GENERIC_TIMEZONE` variable-a set pannalainnaa self-hosted instance default-aa America/New_York-la irukkum, adhanaala oru "kaalai 6 mani" job Indhiya madhiyathula odalaam. Workflow-oda settings-la time zone-a Asia/Kolkata-vaa set pannunga, appuram executions list-la run times-a check pannunga. `$now` maadhiri expressions-um adhe setting-a follow pannum, adhanaala "nethu"-na India-la nethu.

### Eppo AI use pannanum, eppo koodaadhu

Rules-aala velai seiya mudiyaadha idathula mattum AI node-a use pannunga: free text-a padikkuradhu. Oru nalla udhaaranam: oru wholesale buyer-oda email "paid ₹48,300 against invoices 112 and 118, less TDS"-nu solludhu. Structured output kooda oru **Information Extractor** adhai invoice numbers-aavum oru amount-aavum maathalaam, appuram oru aal confirm panradhukku munnaadi oru IF node adhai unga invoice list kooda check pannum. Rule: oru IF, Switch allathu Code node mudivu panna mudinjaa, model-kitta kekkaadheenga. Pana mismatches-kku "reasons" ezhudhura oru model selavai koottum, sariyaa thonura oru kaaranathai karpanai panniyum sollalaam. Adutha tool call mundhaiya call enna return pannuchu-ngradhai poruthu irukkura tasks-kku mattum AI Agent-a vachukkonga, "Automation with n8n" lesson-la sonna safeguards kooda.

### Reliability

| Practice | Yen |
| --- | --- |
| API nodes-la Retry On Fail | Chinna network errors rendaavadhu try-la thaanaa sariyaayidum |
| Idempotent writes | Oru unique id-la upsert, adhanaala oru rerun rows-a duplicate pannaama update pannum |
| Overlap aagura time windows | Nethu mattum illaama sila naal data-va fetch pannunga, appo oru missed run adutha naale thaanaa sariyaayidum |
| Oru error workflow | Oru Error Trigger-la start aagi, workflow, fail aana node, execution link-a team-kku post pannum |
| Item-count checks | Rows return panna vendiya oru step edhuvumae return pannalainnaa alert; zero items oru branch-a niruthidum, adhanaala mudhalla Always Output Data-va on pannunga |

Error workflow-a main workflow-oda settings-la set pannunga, error workflow-aiyum publish pannunga. Adhu automatic runs-kku mattum thaan fire aagum, editor-la neengalae kaiyaala start panra runs-kku illa, adhanaala oru short schedule vachu test pannunga.

### Pinned data vachu testing

Gateway call maadhiri oru node-oda output-a **Pin** pannunga, editor API-a thirumba call pannaama adhaiye reuse pannum. Production runs pinned data-va ignore pannum. Oru refund, vazhakkathukku maaraana paise-la oru amount, payment id illaadha oru order maadhiri sikkalaana pinned cases-oda oru set vachukkonga, ovvoru maatrathukku appuramum avatrai rerun pannunga.

### Maintainability

November 2026 nilavarappadi, n8n-oda built-in Git source control adhoda Business, Enterprise plans-la irukku. Matha plans-la workflows-a JSON-aa export panni neengalae Git-la commit pannunga. Thani credentials kooda oru thani test instance allathu project vachukkonga, oru test run pass aana piragu thaan production-a maathunga.

### Self-hosting basics

n8n open source illa. Adhoda Sustainable Use License unga sondha business-kku self-host panna allow pannudhu; client work pathi "Automation with n8n" lesson solludhu. Udhaaranamaa Docker vachu self-host pannaa, neenga thaan operator:

- **Encryption key.** Save panna credentials-a n8n thaanae generate panra oru key vachu encrypt pannum. Data volume-a vachukkalainnaa, rebuild panna container oru pudhu key-a uruvaakkum, ovvoru credential-um padikka mudiyaadhadhaa aayidum. `N8N_ENCRYPTION_KEY`-a neengalae set panni, database kooda adhaiyum backup pannunga.
- **Disk.** Execution data default-aa 14 naal allathu 10,000 executions-kku appuram prune aagum. Pruning-a on-laye vainga, oru busy workflow-oda ovvoru successful run-kkum full data-va save pannaadheenga.
- **Database-um scale-um.** Serious-aana edhukkum Postgres use pannunga. High volume-kku, **queue mode** Redis vachu runs-a thani worker processes-kku kudukkum.
- **Updates.** n8n-la critical security flaws irundhirukku, January 2026-la onnu udpada. Security releases-a sila naatkalukkulla apply pannunga.

## Oru worked example

Bengaluru-la oru D2C skincare brand Shopify-la oru naalaikku sumaar 1,500 orders vikkudhu. Udhaaranamaa, sumaar 60% Razorpay moolamaa prepaid, meedhi cash on delivery-nnu vachukkonga. Ovvoru kaalaiyum, finance-la irukkura Kavya ovvoru prepaid order-um pay out aachaa-nnu check panna rendu mani neram selavu panraanga. Gateway pathina moonu facts design-a theermaanikkudhu:

- **Settlements late-aa varum.** Razorpay-oda standard domestic cycle capture-la irundhu T+2 working days, adhu merchant-kku merchant maarum. Nethaiya orders innum settle aagala, adhanaala nethai nethoda match pannaa ellaamae flag aagum.
- **Rows payment id vachu key pannappattirukku.** Ovvoru settlement row-layum oru `entity_id` (`pay_`-la start aagura oru payment id), `amount`, `fee`, `tax`, `credit` irukku. Adhoda `order_id` Razorpay-oda sondha order id, Shopify order number illa. Adhanaala store checkout-laye ovvoru order-layum Razorpay payment id-a save pannanum; adhu enga irukkum-ngradhu unga checkout app-a poruthadhu.
- **Amounts paise-la irukku, fees kazhikkappadum.** `amount` paise-la gross payment. `tax` kaattura GST yerkanavae `fee`-la serndhirukku, `credit`-na `amount`-la irundhu `fee`-a kazhichadhu. `credit`-a order total kooda compare pannaa ovvoru order-um flag aagum. Adhukku badhilaa `amount`-a compare pannunga, fee-a thaniyaa check pannunga.

Kavya-voda workflow, adhoda time zone Asia/Kolkata-vaa set panni:

| # | Node | Enna pannum |
| --- | --- | --- |
| 1 | Schedule trigger, Sheets | IST kaalai 6 manikku odum; mel branch-la irukkura oru Sheets node, adhanaala adhu mudhalla odi, results sheet-a "Read results"-aa padikkum |
| 2 | Shopify, appuram Filter | Return All vachu kadaisi 10 naal orders-a edukkum, prepaid aanavatrai vachukkum |
| 3 | HTTP Request | Kadaisi 3 naalukkaana settlement rows-a page by page edukkum, sumaar oru second-kku oru request |
| 4 | Filter, Edit Fields | Payment rows-a vachukkum (refunds-kku thani type irukku), edhuvum clash aagaama fields-a rename pannum |
| 5 | Merge | `payment_id`-la match pannum, Keep Everything |
| 6 | Code | Yerkanavae ok-nnu mark aana payments-a skip pannum, meedhiyai flag pannum (keezha paarunga) |
| 7 | Sub-workflow "Upsert result" | Sheets Append or Update Row, `payment_id`-la match panni |
| 8 | IF, Slack | Oru working day-la step 3-kku endha rows-um kidaikkalainnaa alert; illainnaa counts-aiyum sheet link-aiyum post pannum |
| + | Error workflow | Execution link-oda finance-ops-kku alert |

Step 6-la irukkura Code node:

```js
// Mode: Run Once for All Items. Each item is one merged row.
const done = new Set($('Read results').all()
  .filter((i) => i.json.flag === 'ok').map((i) => i.json.payment_id));
const out = [];
for (const item of $input.all()) {
  const r = item.json;
  if (done.has(r.payment_id)) continue; // never downgrade an ok row
  const orderPaise = Math.round(Number(r.order_total) * 100);
  let flag = 'ok';
  if (!r.order_name) {
    flag = 'settled, no order found';
  } else if (!r.settlement_id) {
    const days = $now.diff(DateTime.fromISO(r.paid_at), 'days').days;
    flag = days > 5 ? 'settlement overdue' : 'waiting';
  } else if (r.gateway_amount !== orderPaise) {
    flag = 'amount differs';
  } else if (r.gateway_fee > Math.ceil(r.gateway_amount * 0.0236)) {
    flag = 'fee above contract'; // 2% plus 18% GST; use your rate
  }
  const paise = r.gateway_amount ?? orderPaise;
  const amount_text = (paise / 100).toLocaleString('en-IN', { style: 'currency', currency: 'INR' });
  out.push({ json: { ...r, flag, amount_text } });
}
return out;
```

Shopify "1499.50" maadhiri text-aa anuppura order total-a `Math.round` muzhu paise-aa maathum, adhanaala ₹1.15-kku 114.99999 maadhiri chinna decimal errors oru false alarm-a uruvaakka mudiyaadhu. `Math.ceil` fee rounding-kku idam kudukkum. 2% rate oru udhaaranam mattum thaan; unga contract-la irukkura rate-a use pannunga. Udhaaranamaa, 2%-la oru ₹1,000 UPI payment-kku fee ₹20, kooda ₹3.60 GST, adhanaala `fee` 2360 paise, `credit` 97640.

Ovvoru flag-um oru thelivaana action-kku kondu pogum; adhai ezhudhuradhu oru template, model illa:

| Flag | Podhuvaa enna artham | Yaar action eduppaanga |
| --- | --- | --- |
| waiting | Pay aayiduchu, normal settlement window-kkulla irukku | Ippodhaikku yaarum illa |
| settlement overdue | 5 naalukku mela aachu, innum settle aagala | Finance adhai gateway kitta ezhuppum |
| amount differs | Payment-kku appuram order edit aachu, allathu oru part refund | Finance order history-a check pannum |
| settled, no order found | Innoru channel-la irundhu vandha payment, allathu missing payment id | Store team order record-a sari pannum |
| fee above contract | Thappaana pricing plan apply aagiyirukku | Finance adhai gateway kitta ezhuppum |

Writes `payment_id`-la upserts-ngradhaala, oru row duplicates-aa kuviyaama, pinnaadi oru naal kaalaiyila "waiting"-la irundhu "ok"-kku maarum. Skip mukkiyam: oru settlement 3-day window-la irundhu veliya ponadhum, skip illainnaa adhoda order settle aagaadha maadhiri therinju thirumba "overdue"-nnu flag aagum. 10-day order window late-aa settle aagura payments-a cover pannum. 5-day limit oru trade-off: oru neenda bank-holiday weekend sila false alarms-a uruvaakkalaam; oru unmaiyaana problem-a miss panradhukku badhilaa team adhai yethukkudhu.

**Oru mosamaana kaalai.** Oru naal kaalai 6 manikku gateway-oda API errors return pannuchu. Retries fail aachu, error workflow execution link-oda alert-a post pannuchu. Kavya kaalai 9 manikku adhai rerun pannaanga. Upserts-aala duplicates illa, ovvoru run-um moonu naal data-va fetch panradhaala, oru naal muzhusaa miss aayirundhaalum adutha naal kaalaiyila cover aayirukkum.

## Podhuvaana thappugal

- **Ore oru raatchasa workflow.** Podhuvaana steps-a defined inputs kooda, per vacha sub-workflows-aa piringa.
- **Rate limits-a kandukkaama viduradhu.** Page, batch, wait pannunga; retries-na pacing illa.
- **Reconciliation-kku Keep Matches vachu merge panradhu.** Neenga thedura problems-aiyae adhu sathamillaama drop panniddum.
- **Net-a gross kooda, allathu rupees-a paise kooda compare panradhu.** Ore maadhiriyaanadhai ore maadhiriyaanadhoda, muzhu paise-la compare pannunga.
- **Nethai nethoda match panradhu.** Settlements late-aa varum; overlap aagura windows-a use pannunga.
- **Idempotent illaadha writes.** Plain appends ovvoru rerun-layum duplicates-a uruvaakkum.
- **Time zone-a default-laye viduradhu.** Workflow settings-la Asia/Kolkata-va set pannunga.
- **Oru rule podhumaana idathula AI-a use panradhu.** Panathai explain panna oru model-a vidavae vidaadheenga.
- **Error workflow-a kaiyaala test panradhu.** Adhu automatic runs-kku mattum thaan fire aagum.
- **Encryption key-a tholaikkuradhu.** Thevaippadradhukku munnaadiye database kooda adhai backup pannunga.
