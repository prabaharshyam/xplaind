## Idhu enna

Niraiya Indian businesses innum vera edhodavum pesa mudiyaadha software-la thaan odudhu: 15 varusha pazhaya oru desktop ERP, oru bank-oda back-office screens, API illaadha oru government portal. Aalunga naal muzhukka oru screen-la irundhu innoru screen-kku values-a copy panni-kittu irukkaanga. **Robotic process automation (RPA)** andha copy velaiya eduthukkudhu.

RPA software "robots"-a use pannudhu; avai oru aal panra maadhiriyae applications-a adhoda **user interface** vazhiyaa iyakkum: programs-a open panradhu, buttons-a click panradhu, fields-la type panradhu, screens-la irundhu values-a padikkiradhu, reports-a download panradhu. API illaadha systems-kku, illanna oru integration build panna romba naal aagum-naa, idhu thaan tool.

Mukkiyamaana idea: API-na software-kkaaga kattina oru kadhavu; RPA-na aalungalukkaaga kattina kadhavu vazhiyaa software nadandhu poradhu. Andha kadhavu robots-kkaaga design pannadhae illa. Oru button-oda peyar maarunaalo, oru screen slow-aa irundhaalo, thideer-nu oru pop-up vandhaalo robot ninnudum. Adhanaala RPA powerful thaan, aanaa elidhaa udaiyum; skill-la perumbagudhi andha udaiyura thanmaiya manage panradhu thaan.

```flow
dir: LR
title: API automation: vegam, urudhi, idhuvae mudhal choice
System A, API irukku -[data, neradiyaa]-> System B, API irukku
```

```flow
dir: LR
title: RPA: oru aal velai seiyura endha idathulayum work aagum, aanaa elidhaa udaiyum
Robot | UiPath, Power Automate Desktop -[screen-la click-um typing-um]-> Pazhaya desktop app, API illa
```

Munnani RPA tools-la **UiPath**, **Automation Anywhere**, **Microsoft Power Automate Desktop** irukku. Steps-a oru studio app-la design pannuveenga, appuram avaigalai oru schedule-la allathu thevaippadumbodhu, oru desktop-layo server-layo ottuveenga. Power Automate for desktop, Windows 11-oda extra cost illaama varudhu, adhanaala practice panna idhu oru easy-aana idam; aanaa flows-a unattended-aa ottavo cloud-la irundhu trigger pannavo paid licence venum.

Indha lesson, Kolkata-la oru general insurer-oda claims team-a follow pannudhu; oru pazhaya claims system-la data entry velaiya oru AI step-um oru RPA robot-um eduthukkudhu. Kadaisiyila RPA eppo sariyaana tool-nu, duplicates create pannaadha, sathamillaama fail aagaadha robot-a eppadi build panradhu-nnu, adhu potta kaasa thirumba edukkudhaa-nnu eppadi check panradhu-nnu ungalukku theriyum.

## Idhu eppadi work aagudhu

### Attended, unattended robots

| Type | Enga, eppo odum | Udhaaranam |
| --- | --- | --- |
| **Attended** | Oru aaloda computer-la, avanga start pannumbodhu | Agent "Go"-va click pannadhum 40 fields irukkura oru form-a fill panra robot |
| **Unattended** | Thani machines-la thaanaa, oru queue-la irundhu items-a eduthu | Raathiri muzhukka 300 claims-a enter panra robot |

Attended robots oru aal vegamaa velai seiya help pannum; ovvoru run-aiyum oru aal paarthuttu iruppaanga. Unattended robots oru shift velaiyaiyae replace pannum, yaarum avaigalai paarkka maattaanga. Keezha irukkura ovvoru design rule-um unattended robots-kku thaan romba mukkiyam.

### Production model: queue, orchestrator, robot

Oru demo robot oru spreadsheet-la rows-a loop pannum. Oru production robot oru **queue**-la irundhu velai seiyum. Ovvoru velaiyum, udhaaranamaa oru claim email, adhoda data-vum oru status-um ulla oru **queue item** aagum; status new, in progress, successful allathu failed maadhiri irukkum. Oru **orchestrator**, adhaavadhu RPA platform-oda control centre (UiPath adhai Orchestrator-nu solludhu), queues-a vechirukkum, schedules-la robots-a start pannum, credentials-a store pannum, logs-a vechukkum.

Oru spreadsheet loop tharaadha moonu vishayangalai queues tharum. Pala robots velaiya pagirndhukkalaam. Oru crash aanaa, muzhu batch illa, appo nadandhuttu irundha item mattum thaan pogum. Ethana items wait pannudhu, mudinjudhu, maattikittu irukku-nnu business orae paarvaiyila paarkkalaam.

### Business, system exceptions

Vishayangal rendu romba vera vera vazhigalla thappaa pogum, robot avaigalai pirichu paarkkanum.

| | Business exception | System exception |
| --- | --- | --- |
| **Enna nadandhuchu** | Data oru rule-a meerudhu: policy expire aayiduchu, GSTIN match aagala, oru required field missing | Technical-aa edho fail aachu: app crash aachu, oru screen time out aachu, network poyiduchu |
| **Retry pannaa help aagumaa?** | Illa. Adutha thadavaiyum data adhe maadhiri thappaa thaan irukkum | Perumbaalum aagum. Adhe item rendaavadhu try-la adikkadi work aagum |
| **Enna pannanum** | Item-a failed-nu mark panni, kaaranathoda oru aal kitta anuppunga | App-a close panni restart pannunga, appuram retry, moonu thadavai maadhiri oru limit varai |

Ellaathaiyum retry panradhu thaan classic thappu. Oru business exception-a moonu thadavai retry pannaa moonu runs veenaagum, kadaisiyila adhu oru aal kitta thaan pogum. Oru system exception-a neraa oru aal kitta anuppunaa, oru restart sari panniyirukkakkoodiya manual velaiya create pannudhu. UiPath-oda REFramework maadhiri templates indha pirivai erkanavae ulla vechirukku. Tools-oda exact retry settings vera vera, adhanaala unga version-oda documentation-a check pannunga.

### Retries-um duplicates-um: idempotency

RPA-la romba aabathaana failure-a create panradhu retries thaan. Yosichu paarunga: robot oru claim-a type panni, Save-a click pannudhu, pazhaya app rendu nimisham freeze aagudhu. Robot time out aagi oru system exception-a report pannudhu. Queue andha item-a retry pannudhu. Aanaa mudhal Save unmaiyaavae poyiduchu. Retry andha claim-a rendaavadhu thadavai enter pannudhu, ippo oru accident-kku insurer kitta rendu claims irukku.

Idhukku fix **idempotency**: oru item-a rendu thadavai ottunaalum oru thadavai ottuna adhe result thaan varanum. Nadaimuraiyila:

1. **Pazhaya system search pannakkoodiya oru unique key-a thaerndhedunga**, udhaaranamaa policy number plus date of loss.
2. **Create panradhukku munnaadi search pannunga.** Ovvoru item-oda aarambathulayum, target system-la andha key-a thedunga. Record erkanavae irundhaa, adhoda reference-a eduthukittu adutha step-kku ponga.
3. **Kadaisiyila mattum thaan item-a successful-nu mark pannanum**, pudhu reference tracking sheet-la thirumba ezhudhunadhukku appuram; Save-a click pannadhum udanae illa.

```flow
title: Oru idempotent queue item
Adutha queue item-a edu -> Erkanavae claims system-la irukkaa?
Erkanavae claims system-la irukkaa? -[aamaa]-> Irukkura claim number-a padi
Erkanavae claims system-la irukkaa? -[illa]-> Form-a fill panni save pannu | appuram pudhu claim number-a padi
Irukkura claim number-a padi -> Claim number-a tracking sheet-la ezhudhu
Form-a fill panni save pannu -> Claim number-a tracking sheet-la ezhudhu
Claim number-a tracking sheet-la ezhudhu -> Item-a successful-nu mark pannu
```

Sila orchestrators adhe reference ulla rendaavadhu queue item-a ethukka marukkavum mudiyum. Adhu duplicate velai queue-kkulla varradhai thadukkum, aanaa oru retry target app-la rendu thadavai save panradhai thadukkaadhu. Adhai search-before-create step mattum thaan thadukkum.

### Robots screen-la vishayangalai eppadi kandupidikkudhu: selectors

Nalla RPA fixed screen positions-la click pannaadhu. Ovvoru element-aiyum adhoda properties vechu kandupidikkum: window-oda title, oru field-oda label, adhoda type. Indha description-a **selector**-nu solraanga. Adhe Policy number box-kku, UiPath use panra style-la, simplify panna rendu selectors idho:

```text
Brittle:  <wnd app='claims.exe' title='Claims v4.2 - User RKUMAR' />
          <ctrl automationid='txt_4471' idx='7' />

Robust:   <wnd app='claims.exe' title='Claims*' />
          <ctrl name='Policy No*' role='editable text' />
```

Brittle selector moonu kaaranangalaala udaiyum. Window title-la oru version number-um oru user name-um irukku, rendum maarum. `txt_4471`-ngira id-a app thaanaa generate pannudhu, adutha build-la adhu maaralaam. `idx='7'` oru box-a adhe maadhiri irukkura boxes-la adhoda order vechu edukkudhu: adhukku mela oru field serthaa robot thappaana box-la type pannum. Matha attributes velaiya seiya mudiyumbodhu `idx`-a thavirkkanum-nu UiPath-oda sondha guidance solludhu. Robust selector oru aal adaiyaalam kandupidikkakkoodiya vishayangalai use pannudhu: app, window title-oda aarambam, field-oda label. `*` oru **wildcard**, endha characters-aiyum match pannum, adhanaala "Claims v4.3" kooda match aagum. `?` sariyaa orae oru character-a match pannum.

Rendu pazhakkangal selectors-a needikka vaikkum. Position-a vida label-a prefer pannunga. Type pannadhukku appuram, adutha step-kku poradhukku munnaadi value-va thirumba padinga, illanna edhirpaartha adutha screen vandhuchaa-nnu check pannunga.

### Remote desktops-um Citrix-um

Sila organisations pazhaya apps-a **Citrix** allathu oru remote desktop vazhiyaa publish panraanga. Appo robot-kku screen-oda oru padam mattum thaan theriyum, element properties edhuvum illa. Adhu **image matching**-kku, adhaavadhu oru button eppadi irukku-nnu paarthu kandupidikkiradhukku, allathu **OCR**-kku, adhaavadhu padathula irundhu text-a padikkiradhukku, thirumbum. Theme, font, screen resolution allathu display scaling maarunaa rendumae udaiyalaam.

Mudhalla RPA vendor-oda remote component-a install pannalaamaa-nnu IT team kitta kelunga. Udhaaranamaa, UiPath-kku oru Remote Runtime irukku; adhu Citrix server-la odi, robot-oda machine-la irukkura oru extension-oda velai seiyum, appo robot-kku thirumba unmaiyaana selectors kidaikkum. Adhu allow illanna, robot machine-oda resolution-aiyum scaling-aiyum fix pannunga, ovvoru image-aiyum pakkathula irukkura oru text label-oda anchor pannunga, ovvoru step-aiyum text-a thirumba padichu verify pannunga.

### RPA, computer-use agent, illa API?

**Computer-use agents**-na screenshots-la irundhu screens-a iyakkura AI models; ovvoru click-aiyum pora pokkula mudivu pannum. Idhuvarai paarkkaadha screens-aiyum avai samaalikkum, aanaa ovvoru step-kkum oru model call selavaagum, avai slow-aa irukkum, adhe screen-la vera action-a thaerndhedukkavum seiyalaam. Robot oru claims allathu banking system-la ezhudhumbodhu andha kanikka mudiyaadha thanmaiya ethukkiradhu kashtam.

| Nilaimai | Best choice | Yen |
| --- | --- | --- |
| System-kku use pannakkoodiya API irukku | API integration | Romba vegam, romba urudhi, clear errors |
| Nilaiyaana screens, adhiga volume, API illa | RPA | Oru item-kku selavu kammi, kanikkalaam, audit pannalaam |
| Maarura allathu pazhakkamillaadha screens, kammi volume | Computer-use agent, ovvoru maatrathaiyum oru aal approve pannanum | RPA-va adikkadi fix panna vendiya idathula flexible |

Oru nalla pattern ivaigalai serkkum: nilaiyaana steps-kku RPA, edhirpaaraadha oru screen-la irundhu meela mattum oru agent, edhaiyum save panradhukku munnaadi oru aal approve pannanum.

### RPA plus AI

RPA screens vazhiyaa data-va nagarthum; AI documents-a padikkum, emails-a classify pannum, fields-a extract pannum. Rendum serndhaa, thaniyaa edhuvum handle panna mudiyaadha processes-a cover pannum. AI step kuzhappamaana input-a clean fields-aa maathum; validation avaigalai unga sondha data-voda check pannum; robot validate aana fields-a mattum thaan type pannum. Oru AI guess-a robot neraa oru system of record-la key panna vidavae koodaadhu.

### Kaasu thirumba varumaa? Oru break-even check

Robots free illa. Onnai build panradhukku munnaadi compare pannunga:

- **Maasathukku saving** = maasathukku save aagura hours × staff-oda loaded hourly cost (salary plus overheads).
- **Maasathukku cost** = licences + robot machines + AI calls, irundhaa + maintenance hours × developer rate.

Appuram oru thadavai build panra cost-a maasathukku net saving-aala divide pannaa payback period kidaikkum. Oru nermaiyaana rule: free aana hours unmaiyaavae vera velaikku use aanaa mattum thaan saving-aa kanakku podanum. Illanna robot cost-a mattum thaan koottum.

### Robots-a safe-aavum odittum vaikkiradhu

Screens maarumbodhu, passwords expire aagumbodhu, pop-ups varumbodhu robots udaiyum. Mudhal naalla irundhae adhukku plan pannunga:

- **Monitoring.** Oru run fail aanaalo queue nagaraama ninnaalo, peyar solli niyamicha oru owner-kku alert pannunga. Ninnupona robot satham podaadhu; mudhal arigurai perumbaalum kobamaana oru customer thaan.
- **Oru robot register.** Ovvoru robot-oda owner, adhu thodura systems, adhu use panra accounts-a record pannunga.
- **Least-privilege accounts-um oru vault-um.** Ovvoru robot-kkum adhukku thevaiyaana access mattum ulla thani account kudunga. Adhoda password-a orchestrator-oda sondha store allathu CyberArk maadhiri oru credential vault-la vainga, script-la eppavumae vaikkaadheenga.
- **Audit logs.** Ovvoru item-oda key, ovvoru step, result-a log pannunga, appo robot enna pannuchu-nnu prove pannalaam. Phone numbers maadhiri personal data-va logs-la mask pannunga.
- **Target app maaruradhukku munnaadi test pannunga.** App team kitta release dates-a kelunga. Ovvoru pudhu version live aaguradhukku munnaadi adhoda test copy-la robot-a ottunga, appo idam maaruna fields production-la illa, testing-layae theriyum.

## Oru worked example

Idhu typical numbers vechu build panna oru illustrative case, alandhu paartha deployment illa.

Kolkata-la oru general insurer-kku motor claim intimations email-la varudhu: oru naalaikku sumaar 300. Claims team ovvoru email-la irundhum adhoda attachments-la irundhum details-a, API illaadha oru pazhaya desktop claims system-kku copy panraanga. Ovvoru claim-kkum sumaar 6 nimisham aagudhu, adhanaala 300 × 6 = 1,800 nimisham, adhaavadhu oru naalaikku 30 mani nera velai.

**Design:**

```flow
Claim ulla email -> AI extraction step | policy no., vehicle no., loss nadandha thedhi, idam
AI extraction step -> Policy database-oda validate pannu
Policy database-oda validate pannu -[ok]-> Queue item | key: policy no. plus date of loss
Policy database-oda validate pannu -[ok illa]-> Oru aaloda queue | kaaranamum oru screenshot-um
Queue item -> Unattended robot | mudhalla search, kidaikkalanna create
Unattended robot -[app crash]-> App-a restart panni retry | system exception, 3 tries varai
App-a restart panni retry -> Unattended robot
Unattended robot -[screen adaiyaalam theriyala]-> Oru aaloda queue
Unattended robot -> Claim number thirumba tracking sheet-kku
```

1. Oru **AI extraction step** ovvoru email-aiyum attachment-aiyum padichu fields-a tharum: policy number, vehicle number, loss nadandha thedhi, idam, description.
2. Fields policy database-oda **validate** aagum: policy irukkaa, active-aa irukkaa, vehicle match aagudhaa? Fail aanavai business exceptions, kaaranathoda oru aal kitta pogum.
3. Valid claims, policy number plus date of loss-a key-aa vechu **queue items** aagum.
4. Oru **unattended robot** claims system-la andha key-a search pannum. Claim illanna, "New intimation"-a open panni, fields-a fill panni, save panni, pudhu claim number-a padichu, adhai tracking sheet-la ezhudhum. Adhukku appuram thaan item successful-nu mark aagum.
5. App crashes system exceptions: restart panni retry, moonu thadavai varai. Robot-kku adaiyaalam theriyaadha endha screen-um oru screenshot-oda oru aal kitta pogum.

**Mudhal quarter eppadi irukkalaam:**

| Alavu | Munnaadi | Appuram |
| --- | --- | --- |
| Data entry-la staff neram | Oru naalaikku sumaar 30 mani neram | Oru naalaikku sumaar 6 mani neram, perumbaalum exceptions |
| Adhe naalla enter aana claims | Sumaar 70% | Sumaar 98% |
| Robot outages | Porundhaadhu | 2, rendumae system updates fields-a idam maathunadhukku appuram |
| Retries-aala vandha duplicate claims | Porundhaadhu | 0, search-before-create-naala |

**Kaasu thirumba varumaa?** Indha assume panna figures-a use pannunga; mudivu panradhukku munnaadi unmaiyaana quotes-a vaangunga.

- Save aana hours: 30 − 6 = oru naalaikku 24. 25 working days-la, adhu maasathukku 600 hours.
- Loaded staff cost oru mani nerathukku ₹400-nu vechukkunga. Saving: 600 × ₹400 = maasathukku ₹2,40,000.
- Running costs maasathukku licences, robot machines-kku ₹1,00,000, AI extraction-kku ₹15,000, oru mani nerathukku ₹1,000-la 20 maintenance hours (₹20,000)-nu vechukkunga. Motham: ₹1,35,000.
- Net saving: ₹2,40,000 − ₹1,35,000 = maasathukku ₹1,05,000. Build panna ₹6,00,000 aanaa, payback-kku sumaar 6 maasam aagum.

Ippo idhai thiruppi paarunga. Ovvoru claim-um 6 nimisham × 24/30 = 4.8 nimisham, adhaavadhu 0.08 hours save pannudhu, adhanaala oru claim-oda madhippu 0.08 × ₹400 = ₹32. 25 naalla maasathukku ₹1,35,000-a cover panna, robot-kku ₹1,35,000 ÷ (25 × ₹32), adhaavadhu oru naalaikku sumaar 170 claims venum. Indha assumptions-padi, oru naalaikku sumaar 170 claims-kku keezha ponaa robot nashtam thaan. Case-a mudivu panradhu volume thaan, robot evvalavu buddhisaali-nnu illa.

Claims system upgrade aagumbodhu robot-a oru direct API integration-aala replace panna insurer plan panraanga. Adhuvarai robot thaan paalam; ella logic-um document panna orae queue process-la irukkuradhaala, adhai retire panradhum selavu kammi.

## Podhuvaa panra thappugal

- **API irukkura idathula RPA-va use panradhu.** API vegam, urudhi, clear errors-um tharum. Build panradhukku munnaadi vendor allathu IT team kitta kelunga.
- **Positions, generated ids allathu index numbers-oda kattina selectors.** Labels-um wildcards-um use pannunga, type pannadhukku appuram values-a thirumba padinga.
- **Ellaathaiyum retry panradhu, illanna edhaiyumae retry pannaama irukkuradhu.** Business exceptions-a oru aal kitta anuppunga; system exceptions-a oru fixed ennikkai varai retry pannunga.
- **Create panradhukku munnaadi search illa.** Save-kku appuram orae oru timeout podhum, retry oru duplicate record-a create pannidum.
- **Oru item-a romba seekkiramaa done-nu mark panradhu.** Reference thirumba ezhudhunadhukku appuram mattum thaan successful-nu mark pannunga.
- **Maarikittae irukkura oru process-a automate panradhu.** Mudhalla process-a fix pannunga allathu nilaippaduthunga; oru robot innaikku irukkura kuzhappathai appadiyae uraiya vechidum.
- **Owner illa, alerts illa.** Udainja unattended robots sathamillaama fail aagum, velai kuvinjukittae pogum.
- **Admin accounts ulla robots, allathu scripts-la passwords.** Least-privilege accounts-um oru vault-um use pannunga.
- **Kanakku podaamalae build panradhu.** Kammi volume-la, save aagura nerathai vida licences-um maintenance-um adhigamaa selavaagalaam.
