## Idhu enna

Oru **connector**-na oru business system-kkum unga AI system-kkum naduvula data-va nagarthura code. Oru nalla connector naalu velai pannum: ellaathaiyum oru thadavai copy pannum, andha copy-a current-aa vachirukkum, delete aanadha neekkum, ovvoru item-aiyum yaaru padikkalaam-ngra thagavalaiyum koodave kondu varum. Perumbaalaana enterprise AI projects-kku pala connectors thevaippadum:

- **Documents**: SharePoint, OneDrive (Microsoft Graph vazhiyaa), Google Drive, Confluence, network file shares, cloud storage buckets.
- **Records**: Salesforce maadhiri CRM systems, SAP maadhiri ERPs, Jira allathu ServiceNow maadhiri ticketing, koodave client-oda sondha databases.
- **Messages**: email, chat; privacy kaaranamaa gavanamaa use pannanum.

Connectors-a neengale build pannalaam, oru integration platform-a use pannalaam (Airbyte, Fivetran matrum sila platforms niraiya ready-made connectors kudukkudhu), allathu oru search allathu AI platform kooda bundled-aa varra connectors-a use pannalaam. Edha use pannaalum, avai enna pannudhu-nnu neenga purinjukkanum.

```flow
title: A connector feeding an assistant
SharePoint -[Graph, OAuth, delta]-> Connector | pages, backs off, resumes
Salesforce -[REST, SystemModstamp, get deleted]-> Connector
Jira, SAP, file shares -> Connector
Connector -> Items, metadata, permissions, deletions -> Parse, chunk, embed -> Index for the assistant
Parse, chunk, embed -> Run log | read 312, added 12, changed 41, unchanged 253, deleted 6, failed 0
```

Indha lesson, SharePoint, Salesforce mela build pannina oru Gurugram sales assistant-a follow pannudhu.

## Idhu eppadi velai seiyudhu

### Authentication

Podhuvaa client-oda IT team register pannina oru app-oda OAuth; read-only-kkum, othukkitta sites, objects allathu projects-kkum mattum scope pannappattadhu. Sila systems API keys allathu service users use pannum; avatrai oru secret manager-la vainga, code-la orupodhum vaikkaadheenga.

Neenda runs-a rendu vishayangal udaikkum. Mudhalla, access tokens expire aagum: Microsoft avatrukku default-aa 60 mudhal 90 nimisham aayul kudukkudhu, adhanaala rendu raathiri odura oru first load ore token-a use panna mudiyaadhu. Ovvoru request-kku munnaadiyum unga auth library-oda cache-kitta (udhaaranamaa MSAL) oru token kelunga; expiry nerungumbodhu adhu pudhu token-a eduthukkum. Rendaavadhu, client secrets, certificates-um expire aagum. Andha date-a runbook-la podunga, oru maasam munnaadiye alert pannunga.

### Pages-aa padikkuradhu

APIs results-a pages-aa return pannum. Ovvoru page-um oru cursor allathu oru "next" link-oda mudiyum. Adutha page illaadha varaikkum loop pannunga. Mukkiyamaana rule: **ovvoru page-um muzhusaa process aana piragu unga position-a save pannunga**, munnaadi illa, kadaisiyila mattum illa. Process panradhukku munnaadi save pannaa, crash aanaa items skip aagum; kadaisiyila mattum save pannaa, page 9,000-la oru crash aanaa page 1-la irundhu restart aagum.

### Rate limits

Ovvoru API-um calls-a limit pannum. Microsoft Graph oru `Retry-After` header-oda 429 Too Many Requests return pannum, retry panradhukku munnaadi avvalavu neram wait panna sollum; header illainaa exponential-aa back off pannunga. HTTP standard-padi, `Retry-After` oru seconds ennikkaiyaavum irukkalaam, oru date-aavum irukkalaam, adhanaala rendaiyum parse pannunga. Parallel workers ellaam ore nodiyila retry panni marupadiyum throttle aagaama irukka, sumaar oru nodi alavukku random jitter serunga.

### Incremental sync-um change detection-um

Mudhal run ellaathaiyum copy pannum; aduthadutha runs maarinadha mattum edukkum. 200,000 documents-a ovvoru raathiriyum muzhusaa thirumba padikkuradhu slow, selavu adhigam, throttle-um aaga vaikkum.

| Method | Udhaaranam | Deletions-a report pannumaa? | Gavanikka vendiyadhu |
| --- | --- | --- | --- |
| Delta token | Microsoft Graph delta | Aamaa | Links velai seiyaama pogalaam (410 Gone); oru full re-scan vazhiya vachirunga |
| Modified-since filter | Salesforce `SystemModstamp`, Jira `updated` | Illa | Oru deletion feed kooda serunga; windows-a sila nimisham overlap pannunga |
| Deletion feed | Salesforce get-deleted resource | Deletions mattum | Salesforce adhigabatcham 15 naal thaan vachirukkum |
| Webhooks | Jira `jira:issue_deleted` | Andha event irundhaa | Deliveries tholaiyalaam; adha mattume source-aa vaikkaadheenga |
| Full id comparison | Unga weekly reconciliation | Aamaa, vithiyaasam moolamaa | Periya sets-la slow; safety net-aa vaaraa vaaram run pannunga |

Graph delta-la rendu gotchas: ore item ore feed-la oru thadavaikku mela varalaam (kadaisiyaa varradhu thaan kanakku, adhanaala source id vachu upsert pannunga), delete aana oru item oru `deleted` marker-oda, content illaama thirumba varum, adhanaala download panradhukku munnaadi adha check pannunga.

### Deletions

Ippo illaadha oru record-a oru modified-since query paarkka mudiyaadhu, adhanaala delete aana documents quote aagitte irukkum. Ovvoru connector-kkum deletions-a report panra oru feed allathu oru periodic id comparison venum, mudinjaa rendume.

### Permissions

Ellaathaiyum vida kashtamaana pagudhi idhu thaan: permissions-a kandukkaadha oru assistant, oru junior employee-kku salary review deck-a kaattidum.

- **Ovvoru item-odaiyum access rights-a padinga.** Graph-oda permissions endpoint oru file-oda effective sharing-a return pannum, folders-la irundhu inherit aana access udpada. Anumadhi irukkura user, group ids-a ovvoru chunk-laiyum store pannunga.
- **Groups-a groups-aave vainga.** Index time-la "Sales North"-a 400 user ids-aa expand pannaadheenga. Query time-la user-oda ippodhaiya groups-a (avanga sign-in token-la irundho oru directory call moolamo) lookup panni, adha vachu filter pannunga. Appo oru group-a vittu pora oruthar, unga group lookup maatrathai paartha udane access-a izhappaanga, re-index illaamale.
- **Permission mattum maarinaa paarkkuradhu kashtam.** Oru file-a share panradhu adhoda content-a maathaadhu. `Prefer: deltashowsharingchanges` header-a, Microsoft thevai-nnu solra `deltashowremovedasdeleted`, `deltatraversepermissiongaps` kooda serthu anuppinaa, sharing maarina items-a Graph delta mark pannalaam. Aanaa content allathu metadata maarina items-aiyum avatroda parent folders-aiyum mattum thaan delta return pannum-nu Microsoft document panniyirukku, adhanaala access-a inherit mattum panra files varaama pogalaam. Permissions-a sariyaa process panna `Sites.FullControl.All` app permission venum-num Microsoft solludhu; security teams adha adikkadi maruppaanga. Marker-a oru hint-aa mattum paarunga. Client sensitive-nu mark panra sites, folders-la permissions-a schedule panni thirumba padikkuradha adhukku backup-aa vainga.
- **Fail closed.** Oru item-oda permissions-a padikka mudiyalainaa, adha index pannaadheenga.

### Code-la oru incremental connector

Oru SharePoint library-kkaana indha sync mela sonna rules-a follow pannudhu. Ovvoru page-kkum position-a save pannudhu, fail aana items-kku oru retry list vachirukku, tokens-a refresh pannudhu, throttling-aiyum udainja delta link-aiyum handle pannudhu:

```python
import email.utils, hashlib, json, random, time
from pathlib import Path        # client below is an httpx.Client

GRAPH = "https://graph.microsoft.com/v1.0"
STATE = Path("state/sharepoint-delta.json")

class StopRun(Exception): pass    # fatal: stop now, leave saved state as it is
class Resync(Exception): pass     # 410 Gone: the saved link no longer works

def wait_for(r, attempt):
    value = r.headers.get("Retry-After", "")
    if value.isdigit():
        delay = int(value)                                  # seconds
    elif value:
        when = email.utils.parsedate_to_datetime(value)     # an HTTP date
        delay = max(0, when.timestamp() - time.time())
    else:
        delay = min(60, 2 ** attempt)                       # no header: back off
    return delay + random.uniform(0, 1)                     # jitter

def get(client, url, token, prefer=None):
    headers = {"Authorization": f"Bearer {token()}"}  # token() reads a cache
    if prefer:
        headers["Prefer"] = prefer
    for attempt in range(6):
        r = client.get(url, headers=headers)
        if r.status_code in (429, 503):
            time.sleep(wait_for(r, attempt)); continue
        if r.status_code == 410:
            raise Resync(r.headers.get("Location"))
        if r.status_code in (401, 403):
            raise StopRun(f"access refused: {r.status_code}")
        r.raise_for_status()
        return r.json()
    raise StopRun("still throttled after 6 tries")

def process(client, token, drive_id, item, index, counts, retry):
    if "deleted" in item:
        index.delete_doc(item["id"])        # must not fail if already gone
        if item["id"] in retry:
            retry.remove(item["id"])
        counts["deleted"] += 1
        return
    if "file" not in item:
        return                              # folders carry no text
    perms = get(client, f"{GRAPH}/drives/{drive_id}/items/{item['id']}/permissions", token)
    acl = acl_from(perms)                   # user and group ids allowed to read
    text = download_and_parse(item)         # your parser
    digest = hashlib.sha256(text.encode()).hexdigest()
    if index.hash_of(item["id"]) == digest:
        index.update_meta(item["id"], meta_from(item), acl)  # renamed or reshared: no re-embed
        counts["unchanged"] += 1
    else:
        new = index.upsert_doc(item["id"], text, digest, meta_from(item), acl)
        counts["added" if new else "changed"] += 1

def save(state):
    STATE.parent.mkdir(exist_ok=True)
    tmp = STATE.with_suffix(".tmp")
    tmp.write_text(json.dumps(state))
    tmp.replace(STATE)                      # atomic: never half-written

def sync(client, token, drive_id, index):
    state = json.loads(STATE.read_text()) if STATE.exists() else {}
    retry = state.get("retry", [])
    counts = dict.fromkeys(["read", "added", "changed", "unchanged", "deleted", "failed"], 0)
    for item_id in list(retry):             # last run's failures first
        try:
            item = get(client, f"{GRAPH}/drives/{drive_id}/items/{item_id}", token)
            process(client, token, drive_id, item, index, counts, retry)
            if item_id in retry:
                retry.remove(item_id)
        except StopRun:
            raise
        except Exception:
            counts["failed"] += 1           # stays listed; alert if it stays for days
    url = (state.get("next_link") or state.get("delta_link")
           or f"{GRAPH}/drives/{drive_id}/root/delta")
    while True:
        try:
            page = get(client, url, token, prefer="deltashowremovedasdeleted, "
                       "deltatraversepermissiongaps, deltashowsharingchanges")
        except Resync as e:
            state = {"retry": retry, "reconcile": True}   # full listing, then compare ids
            url = e.args[0] or f"{GRAPH}/drives/{drive_id}/root/delta"
            continue
        for item in page.get("value", []):
            counts["read"] += 1
            try:
                process(client, token, drive_id, item, index, counts, retry)
            except StopRun:
                raise
            except Exception:
                counts["failed"] += 1
                if item["id"] not in retry:
                    retry.append(item["id"])
        state["retry"] = retry
        if "@odata.nextLink" in page:       # page done: save where to resume
            url = state["next_link"] = page["@odata.nextLink"]
            save(state)
        else:                               # last page: save the link for next time
            state.pop("next_link", None)
            state["delta_link"] = page["@odata.deltaLink"]
            save(state)
            break
    print(counts)
    return counts
```

Yen ippadi build panniyirukku:

- **Position-um failures-um serndhe save aagudhu**, ovvoru page-kku appuramum ore atomic write-la. Page naduvula crash aanaa andha page replay aagum; upserts, deletes source id vachu key pannappattadhaala adhu safe. Fail aana oru item orupodhum skip aagaadhu: succeed aagura varaikkum retry list-la irukkum.
- **Oru ketta file feed-a freeze pannaadhu.** Edhaavadhu oru item fail aagumbodhu munnera marukkuradhu safe-aa theriyum, aanaa appo oru corrupt PDF edhirkaala maatrangal ellaathaiyum block pannidum.
- **Metadata text koodave pogudhu.** Citations, filters-kkaaga `meta_from` source id, URL, title, path, author, modified time, owner-a vachirukku. Oru rename ivatrai maathum, text-a maathaadhu, adhanaala re-embed pannaamale ivai update aagudhu.
- **Fatal errors save pannaamale run-a niruthudhu.** Oru access error allathu mudivillaadha throttling oru item failure illa; adha item failure-aa count pannaa, muzhu library-um retry list-kku poyidum.
- **Udainja oru link oru full listing-a trigger pannudhu.** 410 Gone vandhaa, Graph-oda `Location` header oru pudhu enumeration-a start pannum. Adhu ippo enna irukku-nnu list pannum, idaiyila enna delete aachu-nnu illa, adhanaala `reconcile` flag aduthathaa id comparison-a run panna scheduler-kitta solludhu.

### Oru weekly reconciliation

Nalla change feeds-um sila vishayangala miss pannum. Source-kitta irukkura ids-a index-kitta irukkura ids kooda compare pannunga:

```python
def reconcile(source_ids: set, index_ids: set, index):
    stale = index_ids - source_ids
    for doc_id in stale:
        index.delete_doc(doc_id)
    missing = source_ids - index_ids
    return {"removed_stale": len(stale), "missing_to_fetch": len(missing)}
```

`removed_stale` oru kaippidi alavai vida adhigamaa irundhaa, unga change feed-la oru bug irukku; adha sari pannunga.

### Records: Salesforce, Jira, SAP

- **Salesforce.** Maarina records-a `LastModifiedDate` mela illaama `SystemModstamp` mela filter pottu query pannunga, yenna automated processes oru record-a maathumbodhum `SystemModstamp` nagarum. Late-aa commit aana records miss aagaama irukka, kadaisi run time-la irundhu sila nimisham kazhichukkonga. Deletions-kku, ovvoru object-kkum UTC-la oru start, end time-oda get-deleted REST resource-a call pannunga. Adhu adhigabatcham kadaisi 15 naala thaan cover pannum, nimisha alavukku thaan velai seiyum, adhanaala connector adha vida adhiga naal down-aa irundhaa, oru full id comparison mattum thaan sarikatta mudiyum. Adhoda, integration user paarkka mudinja deletions-a mattum thaan adhu kaattum.
- **Jira Cloud.** `search/jql` endpoint vazhiyaa JQL-oda search pannunga; adhu pazhaiya `startAt` offset-kku badhilaa oru `nextPageToken`-oda page pannum. `updated >= "last run time"`-oda filter pannunga. Delete aana issues search-la irundhu appadiye marainjidum, adhanaala `jira:issue_deleted` webhook-kku subscribe pannunga, webhooks miss aagalaam-ngradhaala appavum ids-a reconcile pannunga.
- **SAP.** Direct table access aridhaa thaan kidaikkum. Client-oda SAP team data-va expose pannum, podhuvaa OData services-aa (adikkadi CDS views mela build panninadhu), sila neram pazhaiya BAPI allathu RFC calls moolamaa, allathu avanga integration middleware moolamaa. Sila OData services delta tokens-a support pannum; illainaa oru changed-on date field-aiyum oru reconciliation-aiyum use pannunga. Mukkiya gotcha neram thaan: oru service build aagi approve aaga unga code-a vida adhiga neram aagum, adhanaala mudhal vaarathulaye kelunga.
- **Schema drift.** Admins fields-a serppaanga, picklist values-a rename pannuvaanga, objects-a retire pannuvaanga. Unga URLs-la API version-a pin pannunga, othukkitta fields-a mattum map pannunga, ellaathaiyum sathamillaama index panradhukku badhilaa, oru describe call pudhu allathu kaanaama pona fields-a kaattumbodhu alert pannunga.
- **Record permissions.** Salesforce access owners, roles, sharing rules-la irundhu varudhu; avatrai appadiye copy panradhu kashtam. Oru safe first release, ellaa sales users-um padikka koodiya objects-a mattum index pannum, allathu oru record-a kaatturadhukku munnaadi user-oda sondha login vachu live-aa access-a check pannum.

### Build, buy allathu borrow

Airbyte, Fivetran maadhiri integration platforms podhuvaana systems-kku vaarakkanakkaana nerathai michappaduthum. Onna nambradhukku munnaadi, adhu deletions-a report pannudhaa, access rights-a kondu varudhaa, neenga alert panna koodiya run counts-a expose pannudhaa-nnu check pannunga. Oru in-house database maadhiri asaadhaaranamaana systems-kku, allathu client-oda security team oru third-party tool-a approve pannaadhappo, unga sondha connector-a ezhudhunga.

## Oru worked example

Gurugram-la oru consumer-goods company, SharePoint (product sheets, trade-scheme circulars), Salesforce (accounts, opportunities) mela oru sales assistant venum-nu kekkudhu. Keezhe irukkura figures illustrative thaan, velai eppadi irukkum-nu kaatta.

**SharePoint.** Aaru sites-kku read access-oda oru app registration. 38,000 files-oda mudhal full sync, throttling limits-kku nallaa keezhe irukka rendu raathirikku pirichu panradhaa vachukkonga; save pannina next link innum velai senjaa rendaavadhu raathiri adhula irundhu thodarum, Graph 410 badhil sonnaa listing thirumba aarambathula irundhu start aagum. Adhukku appuram ovvoru 15 nimishamum oru delta run sila nooru changed allathu deleted items-a return panni, sumaar oru nimishathula mudiyum. Ovvoru run-um changed items-kku permissions-aiyum thirumba padikkum, pricing, HR files irukkura rendu sites-la oru nightly job permissions-a thirumba padikkum.

**Salesforce.** Account, Opportunity, Product-kku mattum limit pannina oru read-only integration user. Ovvoru 30 nimishamum, `SystemModstamp` kadaisi run time-la anju nimisham kazhichadhukku appuram irukkura records-a connector query panni, ovvonnaiyum record id, owner-a metadata-vaa vachu oru chinna text summary-aa maathi, adhe window-kku get-deleted resource-a call pannudhu. Oru sales manager 11:10-kku oru duplicate account-a delete pannaa, adhu sumaar 11:30-kkulla index-la irundhu poyidum.

**Nadandha incident.** Moonaavadhu vaarathula oru delta request 410 Gone return pannudhu-nnu vachukkonga. Connector `Location` header-a follow panni, raathiri muzhukka library-a re-list panni, appuram id comparison-a run panni, link udainjirundha nerathula delete aana 14 files-a neekkudhu. Client gavanikkuradhukku munnaadiye alert on-call engineer-kitta poyiduchu, runbook-um indha case-a erkanave cover panniyirundhadhu.

| Alavu | Munnaadi | Appuram |
| --- | --- | --- |
| SharePoint sync | Ovvoru raathiriyum full re-read, sumaar 6 mani neram, adikkadi throttle aagum | Ovvoru 15 nimishamum delta, sumaar 1 nimisham |
| Salesforce sync | Daily export, deletions orupodhum neekkappadala | Ovvoru 30 nimishamum, deletions oru run-kkulla |
| Delete aana documents innum search-la varudhu | Dozen kanakkula | Weekly check-la onnum illa |
| Fail aana sync-a gavanikka aagura neram | Naatkal | Nimishangal, alerts moolamaa |

## Podhuvaana thappugal

- **Ovvoru thadavaiyum full re-sync.** First load-kku appuram delta tokens allathu modified-since queries use pannunga.
- **Deletions-a kandukkaama vidradhu.** Oru modified-since query delete aana records-a orupodhum return pannaadhu; oru deletion feed-aiyum oru weekly id comparison-aiyum serunga.
- **Thappaana nerathula cursor-a save panradhu.** Process panradhukku munnaadi save pannaa crash-kku appuram items skip aagum; kadaisiyila mattum save pannaa page 1-la irundhu restart aagum. Ovvoru page-kku appuramum save pannunga.
- **Fail aana items-a vizhungidradhu.** Oru failure-a count pannittu aduthadhukku ponaa andha item nirandharamaa tholainjidum. Oru retry list vachirunga.
- **Neenda run-kku ore token.** Adhu 60 mudhal 90 nimishathula expire aagum, job adhikaalai 3 manikku sethudum.
- **Index time-la groups-a users-aa expand panradhu.** Appo membership maatrangal effect-kku vara oru full re-index thevaippadum.
- **Alavukku meerina access.** Muzhu tenant-kku illaama, per sonna sites, objects-kku mattum read-only access kelunga.
- **Sathamillaadha connectors.** Oru sync ninnaa yaarukkum alert pogalainaa, assistant sathamillaama stale aagidum.
- **Modified aana ovvoru file-aiyum re-embed panradhu**, adhoda metadata mattum maariyirundhaalum.

## Custom connector eppo thevaiyilla

- **Oru one-off load**, oru fixed set of files-kku: oru thadavai export panni ingest pannunga.
- **Oru platform connector erkanave andha system-a cover pannudhu**, deletions-a report pannudhu, permissions-a padikkudhu.
- **Users-kku thevaiyaana sila documents-a avangale** neradiyaa upload panna mudiyum.

## Demo-la irundhu production-kku

Client-oda IT team kooda ezhuthuppoorvamaa othukkitta starting defaults:

- **Schedules:** document delta ovvoru 15 nimishamum, record queries ovvoru 30 nimishamum, permission re-read ovvoru raathiriyum, full id comparison vaaraa vaaram. Periya first loads client-oda time zone-la raathiri mattum, kuraivaana concurrency-oda.
- **Alerts:** oru run fail aagudhu allathu rendu intervals-kkulla start aagala; padicha items vazhakkamaa varradhula paadhikku keezhe pogudhu; edhaavadhu oru item oru naalukku mela retry list-la irukku; oru secret 30 naalukkulla expire aagudhu.
- **Runbook:** 410 Gone vandhaa, oru access error vandhaa, oru site, object allathu field rename aanaa enna pannanum.

## Practice pannunga

Microsoft Graph overview-a padinga, appuram free-aa use panna koodiya, paging irukkura edhaavadhu oru API-a eduthukkonga (GitHub issues, oru public dataset API, allathu oru developer tenant-oda Graph).

1. Paging-oda ellaa items-aiyum edukkura, `Retry-After`-a madhikkura, resume panna mudiyura maadhiri ovvoru page-kku appuramum position-a save panra oru connector-a ezhudhunga.
2. First load paadhiyila irukkumbodhu adha kill panni restart pannunga. Adhu save pannina page-la irundhu thodarudhu, thirumba aarambikkala-nnu confirm pannunga.
3. Kadaisi run-la irundhu maarina items-a mattum edukkura oru incremental mode-aiyum, delete aana items-a detect panra oru check-aiyum serunga.
4. Ovvoru run-kkum counts-a (read, added, changed, unchanged, deleted, failed) record panni, oru one-line summary-a print pannunga.
5. Source-la oru item-a delete panni, rerun panni, adhoda chunks index-la irundhu poyiduchu-nnu confirm pannunga.

**Mudinjadhu-nnu eppo sollalaam:** unga connector-a thodarndhu rendu thadavai run panni, rendaavadhu run oru deletion udpada maarinadha mattum edukkudhu-nnu kaatta mudiyum, crash aana oru run sariyaana page-la irundhu resume aagudhu-nnum kaatta mudiyum.
