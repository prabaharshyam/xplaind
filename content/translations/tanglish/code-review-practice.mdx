## Idhu enna

**Code review**-na, unga change merge aaga munnaadi oru teammate adha padikkuradhu. GitHub, GitLab-la idhu oru **pull request** (illa merge request)-la nadakkum: change, adhoda description, automated checks, specific lines-la comments-oda oru thread.

Reviews moonu velai seiyum. Users kandupidikkaradhukku munnaadi bugs-a pidikkum. Codebase-a consistent-aa vachukkum, adhanaala adhu pala styles-oda oru patchwork aagaadhu. Knowledge-a share pannum: review-kku apram oruthar-ku illa, rendu perukku change purium.

Review-na code pathina oru conversation, aal pathina judgement illa. Nallaa review panra teams vegamaa ship pannum, yenna problems-a fix panna selavu kammiyaa irukkum podhae pidichiduvaanga.

## Idhu eppadi work aagudhu

```flow
title: Open aagura nerathula irundhu merge varaikkum oru pull request
Author oru sinna pull request open pannuvaar | enna, yen, eppadi test pannaanga -> Automated checks | tests, linter, build
Automated checks -[fail]-> Author fix pannuvaar -> Automated checks
Automated checks -[pass]-> Reviewer padikkiraar | mudhalla correctness, apram design, apram style
Reviewer padikkiraar -[changes thevai]-> Comments: specific, kind, label-oda
Comments: specific, kind, label-oda -> Author reply pannuvaar illa fixes push pannuvaar -> Reviewer padikkiraar
Reviewer padikkiraar -[nallaa irukku]-> Approve panni merge
```

**Author-aa**, unga change-a review panna easy-aa aakkunga:

- Sinnadhaa, oru vishayatha pathi mattum vaanga. 200-line pull request-ku careful-aana review kidaikkum; 2,000-line pull request-a skim thaan pannuvaanga.
- Description ezhudhunga: enna maariyadhu, yen, eppadi test pannaanga. Ticket-a link pannunga. Kaattura edhukkum screenshots serunga.
- Mudhalla unga own diff-a review pannunga. Meedhi irukkura prints-um typos-um yaarum paakkaradhukku munnaadi neengalae pidichiduveenga.
- Review kekkuradhukku munnaadi checks pass aagura maadhiri pannunga.

**Reviewer-aa**, mukkiyam adhigam irukkura vishayatha, ippadi order-la paarunga:

| Order | Edha paakkanum | Examples |
| --- | --- | --- |
| 1 | Correctness | Thappaana logic, handle pannaadha errors, edge cases, security, data leaks |
| 2 | Tests | Pudhu behaviour-ku test irukka? Change illaama test fail aagumaa? |
| 3 | Design | System-ku porundhudha? Edhavadhu duplicate aagudha? Maathradhu easy-aa irukkumaa? |
| 4 | Readability | Names, neenda functions, kuzhappamaana logic, "yen" comments illaama |
| 5 | Style | Formatting-um import order-um, ideal-aa oru aal illa linter fix pannanum |

Specific-aana (enna, enga), yen mukkiyam-nu sollura, oru fix suggest panra comments ezhudhunga. Optional-a irukkradha "nit:" illa "optional:"-nu label pannunga. Theriyaadhappo assert panradhukku badhil kelvi kelunga. Nallaa irukkradhayum sollunga; author edha thodarndhu seiyanum-nu adhu solludhu.

**Comments vaangura author-aa**, nalla ennathoda sonnaanga-nu eduthukkunga. Nandri sollunga, fix pannunga, ovvoru thread-layum reply pannunga. Neenga othukkalana, evidence-oda explain pannunga. Oru thread rendu thadavaikku mela pogudhunna, oru call-la pesi theerthukkunga.

**Theriyaadha area-la review panradhu.** Nallaa review panna muzhu codebase-um theriyanum-nu avasiyam illa. Mudhalla description-um ticket-um padinga, change enna seiyanum-nu theriyum. Mudinja local-la code-a illa tests-a run pannunga. Neenga judge panna mudiyura vishayangal, example error handling, edge cases, tests, readability, adhula focus pannunga, ethu assess panna mudiyalannu clear-aa sollunga, author vera yaar kitta kekkalaam.

**AI changes-a review panradhu.** Oru prompt, model, retrieval settings-a maathuradhum code change thaan, aana adhoda effect outputs-la theriyum, diff-la theriyaadhu. Munnaadi, pinnaadi category-wise eval results-um, maariya sila example outputs-um kelunga. Oru-vaarthai prompt edit, oru vagai kelviya sari pannittu, matroru vagaiya amaidhiyaa udaichidalaam.

**Vegam mukkiyam.** Moonu naal review-kaaga kaathirukkura pull request pazhasaagidum: main munnaadi poidum, conflicts serum, author-ku context poidum. Neraya teams oru velai naal-kulla first review kudukka try pannum. Neram-la sariyaa review panna mudiyalana, sollidunga, author vera yaaraiyavadhu kandupidikkalaam.

**Browser-laye try pannunga.** Indha function-a run pannunga, apram review pannunga: keezha irukkura tests oru bug-a kaattum. Adha fix panni marubadiyum run pannunga.

```python
def average_rating(ratings):
    """Average of 1 to 5 star ratings, ignoring missing ones (None)."""
    total = sum(r for r in ratings if r is not None)
    return total / len(ratings)            # review: is this the right count?

print(average_rating([5, 4, None, 3]))     # expected 4.0
print(average_rating([2, 4]))              # expected 3.0
```

## Oru worked example

Gurugram-la oru food-delivery startup-la junior engineer Aditya, "reorder last meal" button-a add panra pull request open panraanga. App, API, database muzhukka 640 lines maaridhu.

Avanga reviewer Meera, adha pirikka sollraanga: API endpoint-ku tests-oda oru pull request, button-ku innoru pull request. Mudhalaavadhu 180 lines. Pathinaindhu nimishathula review panni, naalu comments podraanga:

- "The endpoint takes the user id from the request body, so anyone could reorder for another user. Could we use the id from the logged-in session instead?" (correctness-um security-um, blocking)
- "There is no test for a user with no past orders. What should it return?" (tests, blocking)
- "Could `get_last()` reuse `OrderRepository.latest_for_user()`? It looks like the same query." (design)
- "nit: `res` could be `last_order`. Not blocking."

Mudikkum podhu: "The error handling for a closed restaurant is really clear, nice."

Aditya security issue-a fix panraanga, test-a add panraanga, irukkura query-a reuse panraanga, variable-a rename panraanga. Ovvoru thread-layum enna maathunaanga-nu reply panraanga. Meera approve panraanga; change anne naalae merge aagudhu. Button-ku irukkura rendavadhu pull request innum vegamaa pogudhu, yenna API munnaadiyae review aayiduchu.

## Podhuvaa panra thappugal

- **Periya pull requests.** Reviewers skim pannuvaanga, bugs thappichidum. Step-wise pirichunga.
- **Style-la mattum comment panradhu.** Formatting-a tools paathukkattum; manushanoda gavanam logic, tests, security-la irukkanum.
- **Vague comments.** "This is wrong" author-a oohikka vaikkum. Enna, yen, oru suggestion sollunga.
- **Comments-a personal-aa eduthukkiradhu.** Comment code pathi thaan. Kashtamaa theriyudhunna kelvi kelunga.
- **Padikkaama approve panradhu.** Rubber stamp review illaama irukkradha vida mosam, yenna makkal adha nambuvaanga.
- **Preferences-ku block panradhu.** Idhu oru taste-na, optional-nu mark panni author decide pannattum.

## Practice pannunga

1. Unga kadaisi pull request-a open panni, adhoda description-a enna, yen, eppadi test pannunga-nu maathi ezhudhunga.
2. Neenga use panra open-source project-la oru pull request-a review panni, mukkiyathuvam order-la aindhu comments draft pannunga.
3. Neenga vaangina illa ezhudhina moonu vague comments-a specific, kind-aa maathi ezhudhunga.
4. Behavioural interviews-ku, unga manasa maathina oru code review pathina STAR story-a ready pannunga.
