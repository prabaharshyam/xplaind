## Idhu enna

**Open-weight models** thanga weights-a veliyidum, adhanaala avathoda licence-padi unga sondha hardware-la run pannalaam. **vLLM** appadippatta models-a GPUs-la thiramaiyaa serve panra oru open-source engine. Rendu ideas thaan adha vegamaa aakkudhu.

- **PagedAttention.** Oru model badhil ezhudhumbodhu, munnaadi vandha ovvoru token-oda memory-aiyum vachirukkum; adhukku per **KV cache**. Pazhaya servers ovvoru request-kkum, varakkoodiya miga neelamaana badhilukkaaga oru neelamaana block-a reserve pannum, adhula perumbagudhi kaaliyaave irukkum. vLLM cache-a chinna pages-la vachirukkum, oru request valarumbodhu mattum pages serum, oru operating system memory-a manage panra maadhiri. Veenaagradhu konjam thaan, adhanaala oru GPU-la romba adhigamaana requests porundhum.
- **Continuous batching.** Ore nerathula niraiya requests-la velai seiyumbodhu thaan oru GPU miga efficient-aa irukkum. Oru muzhu batch mudiyura varaikkum kaathirukkaama, mathavai mudiya mudiya, ovvoru step-layum pudhu requests batch-la sera vLLM vidum.

vLLM oru **OpenAI-compatible API**-a expose pannum, adhanaala perumbaalaana client code-um gateways-um maaraama adhoda velai seiyum.

```flow
title: Oru request vLLM server vazhiyaa poradhu
dir: LR
Client or gateway -[OpenAI-style API, oru key-oda]-> vLLM server
vLLM server -> Scheduler | continuous batching: ovvoru step-layum requests serum, veliyerum
Scheduler -> KV cache in pages | PagedAttention; prompts-oda podhuvaana thodakkam reuse aagum
KV cache in pages -> GPU memory | weights-um cache-um idha share pannum
vLLM server -> Metrics | queue length, cache usage, time to first token
```

Indha lesson, claim documents-a thanga sondha servers-laye vachirukka vendiya Chennai-la irukkura oru insurance company-a follow pannudhu.

## Idhu eppadi work aagudhu

### Model-a thernthedukkuradhu

Leaderboard-la irundhu illa, task-layum unga sondha evals-layum irundhu aarambinga. Appuram naalu vishayangala check pannunga.

- **Licence.** Qwen3.5 family, Gemma 4 utpada ippo irukkura niraiya models Apache 2.0-la release aagiyirukku. Matha siladhu conditions serkkum; Meta-voda Llama community licence oru udhaaranam. Neenga download panra adhe weights kooda varra licence file-a padinga.
- **Size, type.** 4 mudhal 14 billion parameters irukkura models oru GPU-la odum, extraction, classification, grounded RAG answers-kku pala neram adhuve podhum. Qwen3.5-35B-A3B (35 billion parameters, oru token-kku sumaar 3 billion active) maadhiri oru **mixture-of-experts (MoE)** model-kku adhoda ellaa parameters-kkum memory venum, aanaa oru chinna model-oda kittathatta adhe vegathula generate pannum.
- **Context length.** Long-context models useful thaan, aanaa neelamaana contexts-kku cache memory-la vilai kodukkanum.
- **Mozhigal.** Models-kku idaiyila matha ellaathaiyum vida idhu thaan adhigamaa maarupadum. Adutha section-a paarunga.

November 2026 nilavarappadi, podhuvaana starting points-la ivaiyum adangum: Qwen3.5 (0.8B mudhal 397B varai sizes, February, March 2026-la release aanadhu), Qwen3.6 (April 2026), Qwen3.8-27B (August 2026), Gemma 4 (E2B mudhal 31B varai), OpenAI-oda gpt-oss-20b, gpt-oss-120b. Ovvoru maasamum pudhu models varudhu, adhanaala idha test panna vendiya oru shortlist-aa paarunga, oru ranking-aa illa.

### Indhiya mozhigalukku oru model-a thernthedukkuradhu

Endha benchmark-a vidavum indha moonu checks adhigamaa sollum.

1. **Oru word-kku tokens (fertility).** Perumbaalum English text-la build aana oru tokenizer, Malayalam illa Odia words-a niraiya chinna thundugalaa pirikkum. Oru model-kku oru word-kku moonu madangu tokens thevaippattaa, ovvoru request-kkum moonu madangu compute selavaagum, adhiga neram edukkum, adhe context-la kuraivaana text thaan porundhum. Unga users-oda 200 unmaiyaana sentences-la idha alanga:

```python
from transformers import AutoTokenizer

sentences = open("malayalam_sample.txt", encoding="utf-8").read().splitlines()
words = sum(len(s.split()) for s in sentences)
for name in ["Qwen/Qwen3.5-9B", "google/gemma-4-E4B-it"]:   # add every candidate
    tok = AutoTokenizer.from_pretrained(name)
    tokens = sum(len(tok.encode(s, add_special_tokens=False)) for s in sentences)
    print(f"{name}: {tokens / words:.2f} tokens per word")
```

2. **Native speakers review panna oru golden set.** Native script, romanised text (Manglish, Hinglish), code-mixed messages ellaathaiyum serunga, yenna unmaiyaana users idhaiyellaam kalandhu thaan ezhudhuvaanga. Machine-translate panna test sets, weak models-a avai unmaiyaa irukkuradhai vida nalladhaa kaattum.
3. **Ovvoru mozhikkum quantized quality.** Quantization pala neram English-a vida lower-resource mozhigalla adhiga quality-a kuraikkum. Neenga unmaiyaa serve pannappora quantized checkpoint-laye Indhiya mozhi evals-a run pannunga.

Test-la serkka vendiya candidates:

- **Podhuvaana multilingual models.** Qwen3.5, 201 languages, dialects-a support panradhaa solludhu; Gemma 4-um multilingual velaikku paravalaa use aagudhu.
- **Indhiyaavukkaaga build aana models.** Sarvam AI, February 2026-la Sarvam-30B, Sarvam-105B-a launch pannuchu; rendume Indhiya mozhigala manasula vachu train panna mixture-of-experts models, Sarvam solrapadi Apache 2.0-la. BharatGen-oda Param2-17B-A2.4B-Thinking-um vLLM-oda supported models-la list aagiyirukku.
- **Oru translation step.** AI4Bharat-oda IndicTrans2 (MIT licence) English-kkum 22 scheduled Indhiya mozhigalukkum idaiyila translate pannum. Translate panni, oru strong English model-a run panni, thirumba translate panra oru pipeline sila neram nallaa irukkum, sila neram mosamaa irukkum. Matha option maadhiriye idhaiyum test pannunga.

Gotcha: unga vLLM version andha exact checkpoint-a support pannudhaa-nnu check pannunga. Sarvam-oda models launch aanappo, avanga model card oru pending vLLM pull request-a kaattuchu; ippo v0.34.0 supported-models list-la Sarvam-oda architectures irukku.

### Memory-a kanakku panradhu

**Weights.** 16-bit-la oru parameter-kku sumaar 2 bytes, 8-bit-la 1 byte, 4-bit-la arai byte-a vida konjam adhigam. Oru 27B model-kku 16-bit-la sumaar 54 GB, 4-bit-la sumaar 15 GB venum.

**KV cache.** Oru standard transformer-la, ovvoru token-kkum `2 × layers × KV heads × head size × bytes` venum. Andha 2, keys-kkum values-kkum. Indha naalu numbers-aiyum model-oda `config.json`-la padinga. Appuram in flight-la irukkura tokens-aala perukkunga: concurrent requests × avathoda average length.

**Unga browser-laye try pannunga.** Idhu oru podhuvaana 8B model-oda shape-a (32 layers, 8 KV heads, head size 128) 16-bit-la use pannudhu:

```python
layers, kv_heads, head_dim, bytes_per = 32, 8, 128, 2
per_token = 2 * layers * kv_heads * head_dim * bytes_per      # 131,072 bytes
for users, context in [(10, 4000), (40, 4000), (40, 16000)]:
    gb = per_token * users * context / 1e9
    print(f"{users} users x {context} tokens: {gb:.1f} GB of KV cache")
```

Idhu sumaar 5, 21, 84 GB-nu print pannum. Oru GPU ethana users-kku serve pannum-nu podhuvaa model illa, context length thaan mudivu pannum.

Rendu gotchas. Qwen3.5 maadhiri pudhu **hybrid** models, sumaar naalu layers-la onnula mattum thaan full attention use pannum, adhanaala avathoda cache indha formula solradhai vida romba chinnadhu. Cache-a 8-bit-la (`--kv-cache-dtype fp8`) store pannaa adhu paadhiyaagum, aanaa neenga alakka vendiya oru quality cost irukku.

### Quantization

Weights-a 8 illa 4 bits-la store pannaa weight memory sumaar paadhi illa mukkaalvaasi kuraiyum, pala neram generation-um vegamaagum, konjam quality loss-oda. Podhuvaana formats **AWQ**, **GPTQ** (4-bit), **FP8** (8-bit). Yerkanave quantize aana oru checkpoint-a download pannunga, udhaaranamaa model maker veliyittadhu; vLLM adhoda config-la irundhu method-a padichukkum. `--quantization` flag oru 16-bit model-a AWQ-aa maathaadhu. Vidhivilakku `--quantization fp8_per_tensor` (verum `fp8` ippo idha panradhilla): L40S, H100 maadhiri FP8 support irukkura GPUs-la idhu load time-laye quantize pannum.

| Setting | Udhaaranam | Unmaiyaa enna pannudhu |
| --- | --- | --- |
| `--max-model-len` | 8192 | Oru request-oda length-kku cap vaikkum. Appadi oru request cache-la porundhudhaa-nnu vLLM start-up-la check pannum; ovvoru request-kkum ivlo reserve pannaadhu |
| `--gpu-memory-utilization` | set pannaama vidunga | v0.34.0-la irundhu, set pannalai-nnaa 1.0-nu artham. Innoru process GPU-va share pannumbodhu mattum set pannunga, udhaaranamaa 0.5-aa |

| `--speculative-config` | JSON | Speculative decoding: oru vegamaana guesser tokens-a draft pannum, model avatha check pannum; kuraivaana load-la latency-a kuraikkum |

**v0.34.0-la memory maatram.** Vera edhum sollalai-nnaa, pazhaya releases GPU memory-la 90%, appuram 92% use pannuchu. v0.34.0, NVIDIA, AMD GPUs-la oru **extensible KV cache**-a on pannudhu: warm-up-kku appuram unmaiyaa free-aa irukkura memory-la irundhu cache-a size pannum, set pannaadha `--gpu-memory-utilization` ippo 1.0-nu artham. Perumbaalaana configs-la irundhu indha flag-a eduthudunga-nnu release notes solludhu. Idhanaala rendu gotchas. Adhe GPU-la irukkura irandaavadhu process, udhaaranamaa oru embedding model, ovvonnukkum oru share set pannalai-nnaa ippo memory-ye kidaikkaadhu. Appuram, sila models-la per-token latency koodalaam-nu notes solludhu; opt out panna `--gpu-memory-utilization 0.9` illa `--no-enable-extensible-kv-cache` pass pannunga. Default `--block-size`-um 16-la irundhu 64-aa maariduchu.

**Reasoning models.** Ippo irukkura niraiya models badhil solradhukku munnaadi "think" pannum. Andha model-kku thevaiyaana reasoning-parser, tool-call-parser flags-kku, GitHub-la vLLM-oda recipes repository-la adhoda page-a paarunga. Avai illai-nnaa, thinking text badhilukkulla vandhu JSON parsing-a udaichudum.

### Structured output-oda idha call panradhu

```python
import os
from openai import OpenAI
from pydantic import BaseModel

class Claim(BaseModel):
    policy_number: str
    amount_inr: int
    reason: str

client = OpenAI(base_url="http://localhost:8000/v1", api_key=os.environ["VLLM_API_KEY"])
r = client.chat.completions.create(
    model="chat-local",
    messages=[{"role": "user", "content": "Extract: Policy HX-22981, claim of Rs 18,400 for a cracked windscreen."}],
    response_format={"type": "json_schema", "json_schema": {"name": "claim", "schema": Claim.model_json_schema()}},
)
print(Claim.model_validate_json(r.choices[0].message.content))
```

Server generation-a schema-kkulla kattuppaduthum, adhanaala reply parse aagum. Aanaalum values-a check pannunga, structured-output lesson vilakkura maadhiri.

### Endpoint-a secure panradhu

`--api-key` (illa `VLLM_API_KEY` variable) `/v1`-kku keezha irukkura routes-aiyum innum sila prefixes-aiyum mattum thaan paadhukaakkum. `/invocations` maadhiri matha routes open-aave irukkum-nu vLLM docs echarikkudhu. Adhanaala vLLM-a neradiyaa expose pannave pannaadheenga. Adha unga gateway-kku pinnaadi vainga, gateway mattum adha reach panra maadhiri oru Kubernetes network policy use pannunga.

### Go-live-kku munnaadi load testing

Unmaiyaana maadhiri prompts-a yerikkitte pora concurrency-la anuppi, time to first token-aiyum total time-aiyum record pannunga:

```python
import asyncio, time
from openai import AsyncOpenAI

aclient = AsyncOpenAI(base_url="http://localhost:8000/v1", api_key="your-key")

async def one(prompt):
    t0 = time.perf_counter(); first = None
    stream = await aclient.chat.completions.create(model="chat-local", stream=True, max_tokens=300,
                                                   messages=[{"role": "user", "content": prompt}])
    async for chunk in stream:
        if first is None and chunk.choices and chunk.choices[0].delta.content:
            first = time.perf_counter() - t0
    return first, time.perf_counter() - t0

async def run(prompts, concurrency):
    sem = asyncio.Semaphore(concurrency)
    async def limited(p):
        async with sem:
            return await one(p)
    results = await asyncio.gather(*(limited(p) for p in prompts))
    ttft = sorted(r[0] for r in results if r[0]); total = sorted(r[1] for r in results)
    print(f"c={concurrency}: p95 first token {ttft[int(0.95 * (len(ttft) - 1))]:.2f}s, "
          f"p95 total {total[int(0.95 * (len(total) - 1))]:.2f}s")

# for c in (1, 8, 32, 64): asyncio.run(run(sample_prompts, c))
```

p95 first-token time unga budget-kkulla irukkura miga adhigamaana concurrency thaan oru replica-voda capacity.

### Idha operate panradhu

vLLM `/metrics`-la Prometheus metrics-a expose pannum. CPU mela illa, `vllm:num_requests_waiting` (queue), `vllm:kv_cache_usage_perc` (cache evlo full) mela alert pannunga, scale pannunga. Prefix caching default-aa on: ore system prompt illa document-oda thodangura requests adhoda cache-a reuse pannum. Shared content-a prompts-oda aarambathula vainga, `vllm:prefix_cache_hits`-a `vllm:prefix_cache_queries`-aala vaguthu hit rate-a track pannunga. Oru failure illa upgrade service-a niruthaama irukka oru spare replica vainga, weights-a oru internal volume-la vainga, yenna start-up-la downloads medhuvaa irukkum, locked-down networks-la pala neram block aagum.

## Oru worked example

Chennai-la oru insurance company claim documents-a thanga sondha servers-laye vachirukkanum. Claim forms-la irundhu 20 fields extract pannanum, claims staff-kku chinna grounded answers venum; oru naalaikku sumaar 30,000 requests. Keezha irukkura ellaa numbers-um method-a kaatturadhukkaana udhaaranangal mattum thaan.

**Model.** Tamil forms utpada 300 unmaiyaana forms-la evals, moonu open-weight models-a oru frontier API kooda compare pannudhu. Idhula sirandhadhu oru 27B dense model: API-oda 97%-kku edhiraa 95% field accuracy. Data-va thanga premises-laye vachirukka company andha gap-a yethukkudhu.

**Memory.** 16-bit-la weights-kku 54 GB venum, oru 48 GB L40S-kku idhu adhigam. Maker-oda 4-bit AWQ checkpoint-kku sumaar 15 GB podhum, evals 94.5%-kku mattum thaan irangudhu. Runtime overhead sumaar 7 GB edukkudhu-nnu vachukkuvom, appo cache-kku sumaar 26 GB minjum. Model-oda config 64 layers, 8 KV heads, head size 128-nu solludhu, adhanaala ovvoru token-kkum 2 × 64 × 8 × 128 × 2 bytes, sumaar 0.26 MB venum. Adhu sumaar 99,000 tokens-kku idam, adhaavadhu average 3,000 tokens irukkura sumaar 33 requests.

**Traffic.** 10 mani nera working day-la 30,000 requests-naa oru second-kku sumaar 0.8; peak idhoda rettippu-nnu vachukkuvom, oru second-kku sumaar 1.7. Ovvoru request-um sumaar 6 seconds eduthaa, in flight-la irukkura requests = arrival rate × ovvonnum edukkura neram (Little's law) = 1.7 × 6, sumaar 10. Oru GPU 33-a thaangum, adhanaala adhu peak-a samaalikkum. Irandaavadhu GPU headroom kudukkum, failures, upgrades nerathulayum service-a oda vaikkum. 30 concurrent requests-la p95 first-token time 2 seconds-kku keezha irukku-nnu oru load test urudhippaduthudhu.

**Cost.** Ovvoru GPU-kkum oru mani nerathukku ₹100-nu vachukkuvom; idhu oru quote illa, udhaaranathukkaana figure. 730 mani nera maasathukku rendu GPUs-kku ₹1,46,000, adhaavadhu oru maasathukku 9,00,000 requests-la 1,000 requests-kku sumaar ₹162. API oru million input tokens-kku ₹100, oru million output tokens-kku ₹400 charge pannudhu-nnu vachukkuvom, idhuvum udhaaranam thaan. 3,000 input, 300 output tokens irukkura ovvoru request-kkum ₹0.42, adhaavadhu 1,000-kku ₹420. Break-even ₹1,46,000 ÷ ₹0.42, oru maasathukku sumaar 3,48,000 requests illa oru naalaikku 11,600. Oru naalaikku 3,000 requests-naa, self-hosting-kku 1,000-kku sumaar ₹1,620 aagum. Rendu figure-layum GST-o, adha run panra engineer-oda neramo serkkala.

## Podhuvaa panra thappugal

- **Leaderboard-la irundhu model-a edukkuradhu.** Unga sondha data-la, unga users-oda mozhigal, scripts-la test pannunga.
- **Sizing-la KV cache-a marandhuduradhu.** Weights porundhidum, appuram load-la server medhuvaagum illa ninnudum. In flight-la irukkura tokens-kku size pannunga.
- **`--max-model-len`-a model-oda maximum-kku set panradhu.** Oru 262,144-token limit oru GPU-la start-up-laye fail aagalaam. Unga traffic-kku thevaiyaana alavukku set pannunga.
- **Pazhakkathula `--gpu-memory-utilization 0.9`-a thodarndhu vachirukkuradhu.** v0.34.0-la adhu cache-kku poga vendiya memory-a thaduthu vaikkum. Oru GPU-va share pannumbodhu mattum set pannunga.
- **Alakkaama quantize panradhu,** mukkiyamaa Indhiya mozhigalla, avai English-a vida adhiga quality-a izhakkalaam.
- **Licences-a kandukkaama viduradhu.** Andha exact weights-kkaana licence file-a padinga.
- **Pin pannaadha image, engine illa model revision,** adhanaala oru restart sathamillaama outputs-a maathidum.
- **vLLM-a neradiyaa expose panradhu,** `--api-key` mattum vachu; sila routes open-aave irukkum.

## vLLM-oda self-host panna koodaadha idangal

- **Kuraivaana illa thideernu yeri irangura volume,** appo idle GPUs-kku API calls-a vida adhigamaa selavaagum; break-even-a kanakku pannunga.
- **Ungalukku miga strong-aana models venum,** avai APIs-aa mattum thaan kidaikkalaam.
- **Operate panna yaarum illa.** GPUs, drivers, upgrades, on-call ellaam unmaiyaana velai.

## Demo-la irundhu production varai

- **Image, vLLM version, model revision-a pin pannunga,** weights-a volumes-la cache panni.
- Ovvoru model illa setting maatrathukku appuramum **load test pannunga**, oru replica-voda capacity-a record pannunga.
- **Queue length, KV cache usage mela alert pannunga, scale pannunga.**
- Oru alias, oru fallback, oru network policy-oda **gateway-kku pinnaadi vainga**.
- Failures-kkum rolling upgrades-kkum **oru spare replica vainga**.
