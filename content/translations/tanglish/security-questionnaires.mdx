## Idhu enna

Oru **security questionnaire**, adha vendor risk assessment-nnum solluvaanga, oru supplier-kku data alladhu systems access kudukkuradhukku munnaadi oru enterprise adha check pannra vazhi. Adhu client-oda sondha spreadsheet-aa irukkalaam; Cloud Security Alliance-oda **CAIQ** (Consensus Assessments Initiative Questionnaire), AI systems-kkaana adhoda pudhu **AI-CAIQ**, alladhu Shared Assessments-oda **SIG** maadhiri oru standard set-aa irukkalaam; illainnaa neenga badhilgalai type panni evidence upload pannra oru vendor-risk portal-aa irukkalaam.

Kelvigal kittathatta ovvoru thadavaiyum adhe vishayangalai dhaan cover pannum: policies, reports, access control, encryption, penetration tests, logging, incident response, backups, data location, retention, sub-processors. Ippo oru AI section-um irukku: client data-va vechu training, model providers, prompt injection, human oversight, change testing.

### Oru reviewer per solli kekkura reports, standards

- **SOC 2**-naa unga controls pathi oru independent auditor kudukkura report. **Type I**, oru kurippitta nerathula avai sariyaa design pannappattirundhuchu-nnu sollum; **Type II**, pala maasam needikkira oru review period muzhukka avai work-um aachu-nnu sollum, adhanaala reviewers adha dhaan virumbuvaanga. Andha period romba naalaikku munnaadiye mudinjirundhaa, adhukkappuram irukkura nerathai cover pannra oru "bridge letter" keppaanga-nnu edhirpaarunga. SOC 2 oru attestation report, certificate illa: "naanga SOC 2 certified"-nnu ezhudhaama, "engakitta SOC 2 Type II report irukku"-nnu ezhudhunga.
- **ISO/IEC 27001** oru information security management system-a certify pannum; **ISO/IEC 42001** oru AI management system-a certify pannum, adhaavadhu oru company thaan build pannra alladhu use pannra AI-a eppadi govern pannudhu-nnu.
- **NIST AI Risk Management Framework** oru voluntary US framework. Adhukku edhiraa yaarum certify aaguradhu illa; unga process adhukku eppadi map aagudhu-nnu neenga kaattalaam.


## Idhu eppadi work aagudhu

### Oru answer library build pannunga

Perumbaalaana kelvigal clients-kku idaiyila repeat aagum. Approved answers-oda review pannina oru library vechukkunga; ovvonnukkum oru **owner** (podhuvaa andha control-a nadathuravanga), oru **last-reviewed date**, **evidence links** (policies, SOC 2 report, penetration test summary, architecture diagrams, test results) irukkanum. Ovvoru pudhu questionnaire-kkum library-la irundhu badhil sollunga, appuram pudhu badhilgalai thirumba adhula serunga. Architecture maarumbodhu, udhaaranamaa oru pudhu model provider alladhu tracing tool vandhaa, baadhikkappadura ovvoru badhilaiyum adhe vaarathula sari pannunga. Pona varusha system pathina badhil oru thappaana badhil dhaan.

Repeat velaiya innum kuraikka, CAIQ maadhiri oru standard questionnaire-a oru thadavai fill panni, client thannodhadha anuppuradhukku munnaadiye adha offer pannunga. Appuram oru **trust centre** nadathunga: oru public security summary, koodave approved clients oru non-disclosure agreement-n keezha SOC 2 report-aiyum matha evidence-aiyum download pannra oru gated area.

### Oru follow-up-a thaangura badhilgalai ezhudhunga

Verum "Yes" follow-ups-a kooppidum, oru overclaim contract breach aagidalaam. Oru nalla badhil enna, eppadi, enga-nnu sollum. Oru control paadhi dhaan irundhaa "Partially"-nnu sollunga: enna irukku, enna illa, meedhikku date enna. Ellaam irukku-nnu claim pannra vendor-a vida, "innum illa, idho plan"-nguradha reviewers romba romba adhigamaa nambuvaanga.

| Kelvi | Weak badhil | Strong badhil |
| --- | --- | --- |
| Encryption at rest irukkaa? | "Yes" | "AES-256, keys Azure Key Vault-la, Central India region; keys varushaa varusham rotate aagum" |
| Data-va training-kku use pannreengalaa? | "No" | "Provider X-oda enterprise terms enga API data-va vechu training pannradha exclude pannudhu; abuse checks-kkaaga adhu requests-a 30 naal vechirukkum; clause attach panniyirukkom" |
| Prompt injection? | "Naanga industry-standard AI security use pannrom" | "Naanga risk-a kuraikkurom: least-privilege tools, outbound actions-kku approval, CI-la run aagura injection test set; latest results attach panniyirukkom" |
| Pen testing? | "Yes" | "Web app-kku varushathukku oru external test; 15 January 2027-kku book aana test-la AI endpoints irukku" |

Inga irukkura provider, retention period, dates ellaam udhaaranangal dhaan; ungalodhadha unga sondha contracts-la irundhu ezhudhunga.

### AI section

Kittathatta ovvoru AI questionnaire-layum indha kelvigalai edhirpaarunga, badhilgalai current-aa vechukkunga:

- **Providers, terms:** endha providers, regions, training pathiyum requests-a evvalavu naal vechiruppaanga-nnum contract enna solludhu. Ovvoru provider-oda terms-aiyum kadaisiyaa eppo padichcheenga-nnu date-a record pannunga, yenna terms maarum.
- **Anuppura data:** endha fields model-kku pogudhu, personal data mudhalla mask aagudhaa.
- **Ella idathulayum retention:** prompts app-la mattum illa, provider-kittayum, unga tracing tool, logs, backups-layum irukkum. Ellaathukkum badhil sollunga.
- **Prompt injection, actions:** model endha tools-a call panna mudiyum, enna permissions-oda, endha actions-kku oru aaloda approval venum.
- **Guardrails, audit logs, kill switches,** test results-oda.
- **Change control:** oru pudhu model alladhu prompt-a release-kku munnaadi eppadi test pannreenga.

### Sub-processors, data flows

Client data-va thodura ovvoru third party-yaiyum list pannunga: cloud, model provider, vector database, tracing tool, email service, badhilgalai draft panna neenga use pannra endha AI tool-um. Ovvonnukkum purpose-um data location-um kudunga. Oru pudhu sub-processor-a client edhirkkalaam-nu contracts pala neram anumadhikkum, adhanaala onnu serkkanum-naa mudhalla client-kitta sollanum. Oru pakka **data flow map** (data enga ulla varudhu, adhu pora ovvoru store, service, ovvonnoda region, adha yaaru paakka mudiyum) thaniyaave niraiya kelvigalukku badhil sollidum.

### Indhiya regulatory kelvigal

Oru Indhiya bank-oda sondha rules dhaan adhoda questionnaire-la niraiya paguthiya vadivamaikkudhu. Perumbaalaana legal duties bank mela dhaan irukku, adha contract moolamaa adhu ungakitta pass pannudhu.

| Rule | Yaarai kattuppaduthudhu | Bank podhuvaa ungakitta enna kekkum | Thayaar panna vendiya evidence |
| --- | --- | --- | --- |
| RBI (Commercial Banks – Managing Risks in Outsourcing) Directions, 2025, 28 November 2025-la veliyaanadhu, IT outsourcing-kku thani chapter irukku | Bank; adhu unga kooda podura contract-la terms serkkanum | Bank pannra audits-aiyum RBI pannra inspection-aiyum ethukkuveengalaa? Unga subcontractors yaaru? Eppadi exit panni data-va thiruppi tharuveenga? | Othukitta audit, inspection clauses, subcontractor list, continuity, exit plan |
| Commercial banks-kkaana RBI-oda cybersecurity, technology risk directions, 31 July 2026-la veliyaanadhu | Bank; adhu cyber incidents-a detect pannina 6 mani nerathukkulla RBI-oda DAKSH platform-la report pannanum | Oru incident pathi engakitta evvalavu vegamaa solluveenga? Unga penetration test report-aiyum fixes-aiyum naanga paakkalaamaa? | Mani nera kanakkula sonna incident notice clause, latest test summary, fix tracker |
| CERT-In directions, 28 April 2022, IT Act-oda section 70B(6)-n keezha | Neradiyaa ungalai, bank-aiyum: service providers, data centres, body corporates innum palarai idhu cover pannudhu | List-la irukkura incidents-a kavanicha 6 mani nerathukkulla CERT-In-kku report pannreengalaa, ICT logs-a Indhiya jurisdiction-kkulla rolling 180 naal vechirukkeengalaa, clocks-a NIC alladhu NPL time servers-oda sync pannreengalaa? Unga point of contact yaaru? | CERT-In step irukkura incident runbook, log retention settings, time server settings, per kurippitta contact |
| Digital Personal Data Protection Act, 2023-um DPDP Rules, 2025-um | Bank, Data Fiduciary-aa; neenga adhoda Data Processor-aa, valid contract-n keezha mattum engage aanavanga | Neenga enna personal data process pannreenga, yen? Enna security safeguards use pannreenga? Oru personal data breach pathi engakitta evvalavu vegamaa solluveenga? Naanga sonnaa data-va erase pannuveengalaa? | Data processing agreement, data inventory, safeguard list, erasure procedure |
| Storage of Payment System Data pathina RBI circular, 6 April 2018 | Payment system providers, avanga engage pannra vendors | Unga system-kku payment data varudhaa? Adhu enga store aagudhu? | Payment data Indhiyaavukkullaye irukku-nnu, alladhu ungakitta varave illai-nnu kaattura data flow map |
| RBI-oda FREE-AI committee report, 13 August 2025 | Innum yaaraiyum illa: idhu 7 principles ("sutras"), 26 recommendations irukkura oru committee report, binding direction illa | Enga AI inventory-kkum AI policy-kkum neenga support panna mudiyumaa? Oru decision-a explain panni trace panna mudiyumaa? Loop-la oru aal enga irukkaanga? | Model card, eval results, audit log schema, approval steps |

Anubavamulla reviewers-kku therinja anju gotchas:

- **Ella bank data-vum Indhiyaavukkulla dhaan irukkanum-nu endha RBI rule-um sollala.** Thelivaana legal rule payment system data-va dhaan cover pannudhu. DPDP Act, anumadhicha countries-a list pannradhukku badhilaa, arasaangam per solra countries-kku transfers-a restrict panna anumadhikkudhu. Irundhaalum perumbaalaana banks policy-padi Indhiya hosting-a kekkum, adhanaala adha edhirpaarunga, aanaa "velinaattula endha data-vum irukka koodaadhu-nnu RBI thadai pannudhu"-nnu ezhudhave ezhudhaadheenga.
- **Act-oda sondha vaarthaigalai use pannunga.** DPDP Act **Data Fiduciary** (bank), **Data Processor** (neenga), **Data Principal** (customer), **personal data breach** pathi pesudhu. "Sub-processor", "controller" rendum niraiya questionnaires copy pannra GDPR-style contracts-la irundhu varudhu. Ketta maadhiriye kelvikku badhil sollunga, aanaa legal positions-a Act-oda terms-la sollunga.
- **Dates therinjukkunga.** DPDP Rules November 2025-la notify aachu; security safeguards, breach intimation udpada perumbaalaana duties May 2027-la irundhu apply aagum. Ippo sign pannra contracts andha date-a thaandiyum odum, adhanaala banks ippave kekkuraanga.
- **Clocks vera vera aalungalodhadhu.** Bank-oda 6-mani nera RBI report, bank incident-a detect pannina nerathula irundhu odum, adhanaala neenga lateaa sonnaa bank adhoda deadline-a miss pannidum. Unga on-call team oru Gnaayitrukkizhamai raathiri 2 manikkum meet panna mudiyura notice window-kku mattum othukkunga. DPDP Act-n keezha Data Fiduciary dhaan Data Protection Board-kkum baadhikkappattavangalukkum sollum; unga velai bank-kku vegamaa solradhu.
- **Versions maarupadum.** Small finance banks, NBFCs, matha regulated entities-kku avangalukku-nnu thani versions irukku, pazhaiya questionnaires IT services outsourcing pathina 2023 Master Direction-a cite pannalaam. Substance-kku badhil sollunga, bank confirm pannra version-a cite pannunga, endha compliance claim-aiyum unga legal adviser approve pannattum. CERT-In-empanelled auditor pannra penetration tests-a banks pala neram keppaanga, adhanaala book pannradhukku munnaadi kettukkunga.

### Evidence, drafting, follow-up calls

Muzhu SOC 2 report maadhiri sensitive evidence-a non-disclosure agreement-n keezha, expire aagura oru link moolamaa mattum share pannunga. Pazhasaagi pora text-a paste pannradhukku badhilaa living documents-kku link kudunga. Injection, permission tests-oda CI results-a oru chinna PDF-aa export pannra maadhiri vechukkunga: reviewers ellaathaiyum vida kammiyaa paathirukkiradhu AI evidence dhaan.

Oru model unga library, design notes-la irundhu badhilgalai draft pannalaam. Moonu rules. Adhu library-yaiyum attach pannina documents-aiyum mattum dhaan use pannanum, use pannina library ids-a cite pannanum. Per kurippitta oruthar ovvoru badhilaiyum approve pannanum, appo dhaan ittukkattina endha control-um veliya pogaadhu. Appuram client-oda questionnaire confidential: unga sub-processor list-la erkanave irukkura approved provider, region-oda mattum draft pannunga. Oru bank-oda questionnaire-a personal chatbot account-la paste pannradhe oru data-handling failure dhaan.

Follow-up calls-kku, system therinja engineer-aiyum data flow map-aiyum koottittu ponga, ungalukku therinjadhukku mattum badhil sollunga, check panna vendiyirundha edhaiyum adhe naalla anuppunga.

```python
import yaml
from datetime import date, timedelta

def load(path="security-answers.yaml"):
    with open(path) as f:
        return yaml.safe_load(f)

def stale(answers, today=None, max_age_days=180):
    today = today or date.today()
    cutoff = today - timedelta(days=max_age_days)
    return [(a["id"], a["owner"]) for a in answers
            if a["reviewed"] < cutoff or not a.get("evidence")]

def suggest(question, answers, top=3):
    words = set(question.lower().split())
    def overlap(a):
        text = a["question"] + " " + " ".join(a["tags"])
        return len(words & set(text.lower().split()))
    return [a["id"] for a in sorted(answers, key=overlap, reverse=True)[:top]]

answers = load()
print(stale(answers, today=date(2026, 11, 28)))
print(suggest("Are prompts retained in logs?", answers, top=1))
```

28 November 2026-la run pannaa, `stale` idha print pannum: `[('prompt-retention', 'ml-lead')]`. Andha badhil 180 naalukku mela pazhasu, adhukku evidence illa, adikkadi maarura tracing settings-a cover pannudhu. `suggest` idha print pannum: `['prompt-retention']`. `stale`-a maasaa maasam run panni, ovvoru owner-kkum avanga list-a anuppunga. Candidates-a kandupidikka `suggest`-a, alladhu periya library-kku embeddings-a use pannunga, aanaa ovvoru match-aiyum oru aal check pannanum: kittathatta sariyaa irukkura oru badhil kooda thappaa irukkalaam.

## Oru worked example

Indha example oru vilakkathukku dhaan: counts, dates method-a kaattudhu, unmaiyaana deal-a illa.

Oru successful pilot-kku appuram, Bengaluru-la oru AI startup-kku oru periya private bank-la irundhu 240 kelvi spreadsheet varudhu, rendu vaarathula kudukkanum. FDE Meera coordinate pannraanga.

**Day 1: triage.** Library 170 kelvigalukku match aagudhu. Meedhi 70-la 40 AI-specific, 30 bank-specific. Ovvoru group-kkum oru owner-um due date-um kidaikkudhu.

**Days 2 mudhal 6: AI kelvigal.** Avanga unmaiyaana design documents-la (data flow map, gateway configuration, masking rules, guardrail tests, approval step, audit log schema) irundhu badhil solraanga, ovvoru badhilum oru document section-a cite pannudhu.

"Prompts-a retain pannreengalaa?"-ngura kelviya check pannumbodhu, tracing tool muzhu prompts-aiyum Indhiyaavukku veliya vechirukku-nnu kandupidikkuraanga; library-la irundha badhil pazhasaagiyirundhuchu. Team tracing-a oru Indhiya region-kku maathi, account numbers-a mudhalla mask pannudhu. Meera badhil, sub-processor list, data flow map moonaiyum adhe naal update pannraanga.

**Days 3 mudhal 9: bank-specific kelvigal.** Startup-oda legal adviser kooda serndhu, avanga andha kelvigalai mela irukkura table-la irukkura rules-kku map pannraanga:

- **Outsourcing:** startup audit, inspection clauses-a ethukkudhu, adhoda cloud, model provider, tracing tool-a subcontractors-aa list pannudhu.
- **Incident notice:** bank 2 mani nerathukkulla notice kekkudhu. Meera on-call lead kooda confirm pannittu, runbook-la CERT-In step pakkathulaye oru "bank-kitta sollu" step serkkuraanga.
- **Logs:** retention Indhiya region-la 180 naalaa set aagudhu.
- **DPDP:** badhilgal startup-a bank-oda Data Processor-aa vivarikkudhu, draft data processing agreement-aiyum erasure procedure-aiyum attach pannudhu.

**Days 10 mudhal 12: gaps, review.** Rendu unmaiyaana gaps theriyudhu: AI endpoints-kku penetration test illa, model misbehaviour-kku incident plan illa. Rendukkum avanga "Partially"-nnu badhil solraanga, oru CERT-In-empanelled firm kooda book pannina test-aiyum oru draft runbook-aiyum attach pannraanga. Per kurippitta oruthar ovvoru badhilaiyum review pannraanga.

**Outcome.** Bank rendu conditions-oda ethukkudhu: 60 naalukkulla test report, go-live-kku munnaadi final runbook. 70 pudhu badhilgalum owners, dates-oda library-kku pogudhu, adhanaala aduththa bank innum adhiga matches-oda aarambikkum.

## Podhuvaana thappugal

- **Overclaiming.** Poiyaana oru "Yes" legal problem aagidalaam. "Partially"-nnu solli plan-a kudunga.
- **Thelivillaadha AI badhilgal.** "Naanga industry-standard AI security use pannrom"-kku endha arthamum illa. Providers, regions, terms, controls-a per sollunga.
- **Oru sub-processor-aiyo data-voda oru copy-yaiyo vittudradhu,** pona maasam sertha, prompts-a vechirukkura oru tracing tool maadhiri, alladhu badhilgalai draft panna use panna AI tool maadhiri.
- **Owner alladhu review date illaadha badhilgal,** adhanaala oru badhil unmai illaama pogumbodhu yaarum kavanikka maattaanga.
- **AI draft pannina badhilgalai check pannaama anuppuradhu.**
- **"SOC 2 certified" alladhu "NIST AI RMF certified"-nnu solradhu.** SOC 2 oru audit report, NIST framework-kku certification-e kidaiyaadhu.
- **Indhiya law-a loosaa solradhu.** "Naanga RBI compliant" romba vague, "RBI ella data-vum Indhiyaavula irukkanum-nu solludhu" thappu. Endha rule, neenga enna pannreenga, endha evidence adha kaattudhu-nnu sollunga.
- **On-call team meet panna mudiyaadha oru notice window-a promise pannradhu.**

## Muzhu library thevaiyillaadha nerangal

- **Unga mudhal onnu rendu questionnaires**: adhukku kavanamaa badhil sollunga, appuram andha badhilgalai library-aa maathunga.
- Sila kelvigalai email-la kekkura **chinna clients**: neradiyaa badhil sollunga, adhe alavu thulliyamaa.
- Company-oda sondha security review process cover pannra **internal projects**.

## Demo-la irundhu production-kku

- **Library-a version control-la vechukkunga**, pazhasaana badhilgalai maasaa maasamum ovvoru architecture maatrathappavum flag pannunga.
- **Sub-processor list-aiyum data flow map-aiyum serthe maintain pannunga**, ovvoru service-kkum purpose, location-oda.
- **Oru Indhiya rules sheet vechukkunga** (rule, date, yaarai kattuppaduthudhu, unga evidence), regulators pudhu directions veliyidumbodhu legal-a adha review panna vainga.
- **Ovvoru questionnaire-aiyum track pannunga**: date, anuppina answer version, promise pannina follow-ups.
