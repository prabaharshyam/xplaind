## Idhu enna

**Experiment tracking** ovvoru training run-aiyum thaanaa log pannum: code version (oru Git commit), data version, parameters, metrics, environment (library versions), plots maadhiri artefacts, train aana model. Ovvoru run-um sort panna, compare panna, reproduce pannakkoodiya oru row aagudhu.

**Model registry**-na thernthedutha model versions-oda oru shelf. Ovvoru version-kkum notes, tags (udhaaranamaa, yaaru approve pannaanga) irukkum, adhu oru **alias**-aiyum vachirukkalaam: sariyaa orae oru version-a point panra `champion` maadhiri nagarthakkoodiya oru peru. Production alias-a thaan load pannum, file path-a orupodhum illa, adhanaala deploy aana model edhu-nnu eppavume theriyum.

Podhuvaana tools: MLflow (open source), Weights & Biases, cloud ML platforms-laye built-in-aa irukkura tracking. Indha lesson MLflow 3-a use pannudhu. MLflow-la, pazhaiya fixed stages (Staging, Production)-kku badhilaa aliases vandhuduchu: version 2.9-la irundhae stages deprecated, MLflow 3.18-la avattrai call pannaa avai remove aagappogudhu-nnu oru warning print aagum.

```flow
title: From training run to production
Training run 412 | commit a1b2c3d, data claims-2026-09, val PR AUC 0.46
Training run 412 -[team picks it and registers it]-> claims-fraud v14
claims-fraud v14 -[gate on October claims, then owner signs off]-> Alias champion
Alias champion -[loaded at start-up]-> Claim scoring service
Alias champion -[rollback: point it back]-> claims-fraud v13
```

Indha lesson, Hyderabad-la maasaa maasam claim-fraud model-a retrain panra oru insurer-oda ML team-a follow pannudhu.

## Idhu eppadi work aagudhu

### Oru run-a define panra ellaathaiyum log pannunga

| Item | Example | Yen mukkiyam | Yaaru record panradhu |
| --- | --- | --- | --- |
| Parameters | `max_depth=6`, `learning_rate=0.05` | Runs-kku naduvula irukkura vithiyaasangalai explain pannum | Neenga, allathu autologging |
| Metrics | Overall-aavum region vaariyaavum PR AUC | Winner-a thernthedukkum, adhu yaarukku fail aagudhu-nnu kaattum | Neenga (segments eppavume) |
| Code version | Git commit, clean tree | Training logic-a reproduce pannum | MLflow, oru Git repo-la script-aa run pannumbodhu |
| Data version | `claims-2026-09` kooda oru hash | Inputs-a reproduce pannum | Neenga |
| Environment | `requirements.txt`, Python version | "En machine-la work aagudhu" prachanaiya thavirkkum | MLflow, log aagura ovvoru model koodavum |
| Model-um schema-vum | Model file, input columns, types | Thappaana inputs-a serving reject panna udhavum | Neenga, `log_model` moolamaa |
| Seed | `random_state=42` | Rerun pannaa adhe model varumpadi pannum | Neenga |

Indha rendu rules thaan idhai nambakkoodiyadhaa aakkudhu.

- **Commit, run aana code-a thaan describe pannanum.** Oru Git repository-kkulla script-a run pannumbodhu MLflow commit-a `mlflow.source.git.commit` tag-aa record pannum, aanaa uncommitted edits-a adhu gavanikkaadhu. Paadhi edit aana oru file-la irundho notebook-la irundho varra run, adhai orupodhum uruvaakkaadha oru commit-a point pannum. Adhanaala keezhe irukkura script, uncommitted changes irundhaa run aaga marukkum. Notebook-la, mudhalla commit pannunga, illai-nnaa training code-a oru script-kku maathunga.
- **Data-voda peru data version illa.** `claims-2026-09` verum oru label thaan; adhukku pinnaadi irukkura file-a yaaraavadhu overwrite pannalaam. Adhe idathula orupodhum edit aagaadha snapshots-a store pannunga, file-oda hash-a log pannunga, appo sathamillaama nadakkura maatram veliya theriyum. DVC maadhiri tools, allathu Delta Lake maadhiri table formats-la irukkura time travel, pazhaiya versions-a ungalukkaaga vachirukkum (data versioning lesson-a paarunga).

**Autologging** (`mlflow.autolog()`) scikit-learn, XGBoost maadhiri libraries-kku perumbaalaana parameters-aiyum metrics-aiyum orae line-la capture pannum. Unga data version-o segments-o adhukku theriyaadhu, adhanaala avattrai neengale serunga.

### Oru training run-a track panradhu

Indha script fraud model-a train panni oru run-a log pannudhu. Claims table-la oru `region` column, oru `region_code` feature, oru `is_fraud` label irukku-nnu idhu assume pannudhu.

```python
import hashlib, subprocess, sys
import mlflow
import pandas as pd
from mlflow.models import infer_signature
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import average_precision_score
from sklearn.model_selection import train_test_split

DATA = "data/claims-2026-09.parquet"
FEATURES = ["claim_amount", "days_since_policy_start", "prior_claims", "garage_claims_90d", "region_code"]

def git(*args):
    return subprocess.run(["git", *args], capture_output=True, text=True, check=True).stdout.strip()

if git("status", "--porcelain", "--untracked-files=no"):   # ignores mlflow.db and mlruns/
    sys.exit("Uncommitted changes: commit first, or this run cannot be reproduced.")

with open(DATA, "rb") as f:
    data_sha = hashlib.file_digest(f, "sha256").hexdigest()[:12]   # Python 3.11 or newer

df = pd.read_parquet(DATA)
df[FEATURES] = df[FEATURES].astype("float64")      # floats can hold missing values at serving time
train, val = train_test_split(df, test_size=0.2, stratify=df["is_fraud"], random_state=42)
params = {"max_depth": 6, "learning_rate": 0.05, "max_iter": 300, "random_state": 42}

mlflow.set_experiment("claims-fraud")
with mlflow.start_run() as run:
    mlflow.set_tags({"data_version": "claims-2026-09", "data_sha256": data_sha})
    mlflow.log_input(mlflow.data.from_pandas(train, source=DATA, targets="is_fraud"), context="training")
    mlflow.log_params(params)

    model = HistGradientBoostingClassifier(**params).fit(train[FEATURES], train["is_fraud"])
    proba = model.predict_proba(val[FEATURES])
    mlflow.log_metric("val_pr_auc", average_precision_score(val["is_fraud"], proba[:, 1]))
    for region, part in val.groupby("region"):
        s = model.predict_proba(part[FEATURES])[:, 1]
        mlflow.log_metric(f"val_pr_auc_{region}", average_precision_score(part["is_fraud"], s))

    mlflow.sklearn.log_model(
        model, name="model",
        signature=infer_signature(val[FEATURES], proba),
        input_example=val[FEATURES].head(3),
        pyfunc_predict_fn="predict_proba",
        skops_trusted_types=["sklearn.ensemble._hist_gradient_boosting.predictor.TreePredictor"],
    )
    print("run", run.info.run_id)
```

Ovvoru MLflow 3 detail-um enna pannudhu (MLflow 3.18-la check pannadhu, November 2026):

- **`name="model"`** pazhaiya `artifact_path` argument-kku badhilaa varudhu; adhu innum work aagum, aanaa ippo oru deprecation warning log pannum.
- **`registered_model_name` illa.** Training script-kkullaye register pannaa ovvoru experiment-kkum oru registry version uruvaagum. Ovvoru run-aiyum log pannunga; winner-a mattum register pannunga.
- **`signature`-um `input_example`-um** input columns-aiyum types-aiyum model koodave store pannum, adhanaala oru column missing-aavo spelling thappaavo irukkura request-a serving reject panna mudiyum. Features mudhalla floats-aa cast pannappadudhu: integer-aa infer aana oru column-la serving time-la oru value missing-aa irundhaa check fail aagum. Appuram ovvoru caller-um floats-aiye anuppanum; integer columns-a check reject pannum. (MLflow innum integer columns pathi oru hint print pannalaam: adhu logged dataset-la irukkura `is_fraud` label-a pathinadhu, model-a illa.) MLflow model pakkathulaye `requirements.txt`, `conda.yaml`-aiyum ezhudhum.
- **`log_input`** run-a dataset kooda link panni, adhoda oru chinna digest-a store pannum; unga sondha hash-a thavira idhu innoru check.
- **`pyfunc_predict_fn="predict_proba"`** generic loader-a hard-aana 0 allathu 1 labels-a illaama, fraud probabilities-a return panna vaikkum.
- **`skops_trusted_types`.** MLflow ippo scikit-learn models-a skops-la save pannudhu; idhu pickle-a vida safe-aana format, yenna oru pickle-a load pannaa file-la olinjirukkura endha code-aiyum run panna mudiyum. Trust panna sollaadha object types-a skops ethukkaadhu, `HistGradientBoostingClassifier`-kku indha onnu thevai. Neenga check panna types-a mattum, neengale train panna models-kku mattum trust pannunga.

Default-aa MLflow 3.18 runs-a neenga run panra folder-la `mlflow.db`-ngra oru local SQLite file-la ezhudhum. Avattrai browse panna angeye `mlflow ui` run pannunga.

### Runs-a compare pannunga, appuram winner-a register pannunga

```python
import mlflow
from mlflow import MlflowClient

runs = mlflow.search_runs(experiment_names=["claims-fraud"],
                          order_by=["metrics.val_pr_auc DESC"], max_results=10)
print(runs[["run_id", "params.max_depth", "params.learning_rate",
            "metrics.val_pr_auc", "metrics.val_pr_auc_east"]].to_string(index=False))

client = MlflowClient()
run_id = runs.loc[0, "run_id"]        # in real life: the run the team chose after reading the table
model_id = client.get_run(run_id).outputs.model_outputs[0].model_id
mv = mlflow.register_model(f"models:/{model_id}", "claims-fraud")
client.update_model_version("claims-fraud", mv.version,
    description="Adds the claim-within-30-days feature; trained on claims-2026-09.")

```

Pazhaiya `runs:/` form innum work aagum, aanaa andha run-la model files illai-nnu ippo warn pannum. Version-oda description-um tags-um oru chinna **model card** maadhiri velai seiyum: enna maaruchu, adhu endha data-va paarthuchu, therinja limits, yaaru approve pannaanga.

### Promotion check: adhe data, unmaiyaana gains, ovvoru segment-um

Inga thaan trap irukku. Champion-oda logged PR AUC pona maasa validation split-la irundhu vandhadhu; candidate-odadhu indha maasathula irundhu. Fraud patterns-um fraud-oda share-um maasathukku maasam maarum, adhanaala andha rendu numbers-a compare panradhu, models-a compare panra alavukku data-vaiyum compare pannudhu. Fair test-na **rendu models-aiyum adhe fresh holdout-la** score panradhu, adhula edhuvume train aagiyirukkak koodaadhu: inga, October-oda claims.

Insurer-oda rule-kku moonu parts irukku:

1. **Overall gain noise-a thaandi thelivaa irukkanum.** Holdout claims-a pala thadavai resample panni (oru bootstrap) ovvoru thadavaiyum PR AUC gain-a recompute pannunga. Gain-oda 90% interval zero-kku melaye irundhaa mattum promote pannunga.
2. **Endha region-um fraud-catching recall-a izhakkak koodaadhu.** Investigators maasathukku top 5% claims-a mattum thaan check panna mudiyum. Ovvoru region-kkum, adhoda fraud cases-la evvalavu share andha top 5%-kkulla varudhu-nnu measure pannunga. Endha region-um 2 points-kku mela kuraiyak koodaadhu.
3. **Check-oda report-a padichappuram oru owner sign off pannanum.**

```python
import numpy as np
import pandas as pd
import mlflow
from mlflow import MlflowClient
from sklearn.metrics import average_precision_score

NAME = "claims-fraud"
FEATURES = ["claim_amount", "days_since_policy_start", "prior_claims", "garage_claims_90d", "region_code"]
REVIEW_RATE = 0.05        # investigators can check the top 5% of claims each month
MAX_RECALL_DROP = 0.02    # no region may lose more than 2 points of recall
client = MlflowClient()

def scores_of(version, X):
    model = mlflow.pyfunc.load_model(f"models:/{NAME}/{version}")
    return model.predict(X)[:, 1]          # column 1 = probability of fraud

def recall_by_region(y, s, region):
    flagged = np.zeros(len(s), dtype=bool)
    flagged[np.argsort(-s)[: int(len(s) * REVIEW_RATE)]] = True   # the claims investigators open
    return {r: flagged[(region == r) & (y == 1)].mean() for r in np.unique(region)}

def pr_auc_gain_interval(y, s_new, s_old, n=500, seed=0):
    rng = np.random.default_rng(seed)
    gains = []
    for _ in range(n):
        i = rng.integers(0, len(y), len(y))   # resample claims with replacement
        gains.append(average_precision_score(y[i], s_new[i]) - average_precision_score(y[i], s_old[i]))
    return np.percentile(gains, [5, 95])

def check(candidate, holdout):
    champion = client.get_model_version_by_alias(NAME, "champion").version
    X = holdout[FEATURES].astype("float64")      # match the logged signature, or loading code rejects it
    y, region = holdout["is_fraud"].to_numpy(), holdout["region"].to_numpy()
    s_new, s_old = scores_of(candidate, X), scores_of(champion, X)

    low, high = pr_auc_gain_interval(y, s_new, s_old)
    problems = []
    if low <= 0:
        problems.append(f"PR AUC gain not clear: 90% interval {low:+.3f} to {high:+.3f}")
    r_new, r_old = recall_by_region(y, s_new, region), recall_by_region(y, s_old, region)
    for r in r_old:
        if r_new[r] < r_old[r] - MAX_RECALL_DROP:
            problems.append(f"{r}: recall {r_old[r]:.2f} -> {r_new[r]:.2f}")
    return champion, problems

holdout = pd.read_parquet("data/claims-2026-10.parquet")    # last month: neither model trained on it
champion, problems = check(candidate="14", holdout=holdout)
print("blocked:" if problems else "passed: ready for owner sign-off", problems)
```

Moonu echarikkaigal. Holdout oru judge-aa irukkanum, coach-aa illa: October claims-la pass aagura varai aalunga models-a tune panniitte irundhaa, October fresh-aa irukkaadhu. 2-point limit oru business decision; results-a yaaraavadhu paarkkuradhukku munnaadiye fraud team kooda adhai othukkonga. Appuram sumaar 150 fraud cases irukkura oru region-la verum moonu cases pakkam maarinaale 2 points nagarum, adhanaala indha guardrail venumne noisy-aa irukku: appappo oru nalla model-aiyum block pannum, rendu thappula adhu thaan selavu kammiyaanadhu. Block aana model oru aalkitta pogum, kuppaikku illa.

### Aliases-a nagarthi promote, roll back pannunga

```python
from mlflow import MlflowClient
NAME = "claims-fraud"
client = MlflowClient()

def promote(candidate, champion, approver):
    client.set_model_version_tag(NAME, candidate, "approved_by", approver)
    client.set_registered_model_alias(NAME, "previous", champion)
    client.set_registered_model_alias(NAME, "champion", candidate)

def rollback():
    previous = client.get_model_version_by_alias(NAME, "previous").version
    client.set_registered_model_alias(NAME, "champion", previous)
```

Serving code `mlflow.pyfunc.load_model("models:/claims-fraud@champion")`-a load pannum. Odikkittu irukkura server model-a orae oru thadavai, start-up-la, load pannuchu, adhanaala service reload allathu restart aagura varai alias-a nagarthuradhaala edhuvume maaraadhu. Reload-a promotion, rollback steps-oda oru pagudhiyaa aakkunga, ovvoru prediction koodavum served version-a log pannunga, appo lineage oru thani decision varaikkum poi serum.

### Gain unmaiyaa? Unga browser-laye try pannunga

Rendu models adhe 6,000 claims-a score pannudhu, adhula sumaar 3% fraud. Candidate nallaa theriyudhu, aanaa idhe maadhiri claims irukkura vera oru maasathulaiyum gain nilaikkumaa-nnu bootstrap kekkudhu.

```python
import numpy as np
from sklearn.metrics import average_precision_score

rng = np.random.default_rng(7)
n = 6000                                    # one month of claims, about 3% of them fraud
y = (rng.random(n) < 0.03).astype(int)
signal = 2.5 * y + rng.normal(0, 1, n)      # the pattern both models learned
champion = signal + rng.normal(0, 0.60, n)  # each model adds its own errors
candidate = signal + rng.normal(0, 0.55, n) # slightly fewer errors

print("champion PR AUC ", round(average_precision_score(y, champion), 3))
print("candidate PR AUC", round(average_precision_score(y, candidate), 3))

gains = []
for _ in range(200):                        # resample the same claims for both models
    i = rng.integers(0, n, n)
    gains.append(average_precision_score(y[i], candidate[i]) - average_precision_score(y[i], champion[i]))
low, high = np.percentile(gains, [5, 95])
print(f"90% interval for the gain: {low:+.3f} to {high:+.3f}")
print("promote" if low > 0 else "too close to call: keep the champion")
```

Idhu PR AUC 0.439-aiyum 0.472-aiyum print pannum, aanaalum interval sumaar -0.02-la irundhu +0.07 varai pogudhu: 200-kkum kuraivaana fraud cases-la oru 0.03 gain innum proof illa. Candidate-oda `0.55`-a `0.30`-aa maathi thirumba run pannunga: ippo promote panra alavukku gain perusaa irukkum.

### LLM apps-kkum idhe idea

Oru prompt allathu retrieval change-a oru experiment-aa paarunga. Prompt version, model name, top-k, chunk size, category vaariyaana eval scores-a oru run-aa log pannunga. Appo "prompt-oda version 13 Hindi questions-kku udhavuchaa?"-ngradhu oru sorted table aagum, nyaabagam illa. Adhe noise rule ingaiyum porundhum: 50 eval questions-la oru 2-point gain perumbaalum chance thaan.

## Podhuvaa panra thappugal

- **Spreadsheets-la kaiyaala track panradhu.** Adhu muzhusaa irukkaadhu, pazhasaayidum, data version-a orupodhum record pannaadhu.
- **Data-voda perai data version-aa ninaikkiradhu.** Adhe perula overwrite aana oru file sathamillaama reproducibility-a udaikkum; oru hash-a log pannunga, snapshots-a read-only-aa vachukkonga.
- **Commit aagaadha code-kku oru commit-a log panradhu.** Notebook edits-um uncommitted changes-um commit tag-a poyyaa aakkidum.
- **Vera vera maasangaloda logged metrics-a compare panradhu.** Champion-aiyum candidate-aiyum adhe fresh holdout-la score pannunga.
- **Romba chinna gain-a vachu promote panradhu.** Sila nooru positive cases irundhaa, 0.01-la irundhu 0.03 varaiyaana maatram chance-aa irukkalaam.
- **Overall score-a mattum vachu promote panradhu.** Overall gain, oru region allathu customer group-kku nadakkura loss-a maraikkalaam.
- **Models-a thernthedukka test set-a thirumba thirumba use panradhu.** Adhukku edhiraa tune panna aarambichadhume, adhu future-a measure pannaadhu.
- **Ovvoru run-aiyum register panradhu.** Registry experiments-aala nirambidum; ship panna vaaippu irukkuradhai mattum register pannunga.
- **Production-la oru file path-a load panradhu.** Oru registry alias-la irundhu serve pannunga, oru `previous` alias-a vachukkonga, alias nagarumbodhu service-a reload pannunga.
- **Empty-aa irukkakkoodiya integer input columns.** Infer aana signature avattrai integers-aa mark pannum, adhanaala serving time-la oru missing value schema check-a fail aakkum; andha maadhiri columns-kku floats use pannunga.
- **Fail aana runs-a delete panradhu, allathu orae laptop-la track panradhu.** Fail aana runs edhu work aagaadhu-nnu kaattum; orae laptop-la irukkura history andha laptop koodave poyidum.

## Tracking-a eppo ilaguvaa vachukkalaam

- **Orae oru quick experiment**: results-a ezhudhi vacha oru notebook podhumaa irukkalaam.
- **Prompt mattum irukkura prototypes**: prompt versions, scores-oda oru spreadsheet nalla aarambam thaan, oruthharukku mela prompts-a maatha aarambikkura varai.
- **Oru thadavai train panni, aridhaa maarura model**: adhoda lineage-a oru thadavai, gavanamaa record pannunga, appavum adhai oru registry-la irundhu thaan serve pannunga.

## Demo-la irundhu production-kku

- **Oru shared tracking server-a run pannunga**: database backend, artefacts-kku cloud storage, company-oda sign-in-kku pinnaadi; udhaaranamaa `mlflow server --backend-store-uri postgresql://... --artifacts-destination s3://...`. Adhai back up pannunga: adhu thaan ovvoru model decision-oda history.
- **Pipeline-la tracking-a automatic aakkunga**, appo log aagaama oru run nadakkave mudiyaadhu.
- **Promotion-a code-la gate pannunga**: adhe fresh holdout-la, noise checks, segment checks-oda; appuram oru owner-oda sign-off-a kattaayamaakkunga.
- **Oru alias-la irundhu serve pannunga**, ovvoru prediction koodavum served version-a log pannunga, thevaippadradhukku munnaadiye oru rollback-a rehearse pannunga.
- **Prompt, retrieval experiments-a** training runs maadhiriye track pannunga.

## Practice pannunga

MLflow-oda tracking guide-aiyum, Made With ML-oda experiment tracking, versioning lessons-aiyum padinga.

1. Oru training script-la tracking serunga: parameters, per-segment metrics, oru clean commit, oru data hash, signature-oda model. Uncommitted edit irundhaa script run aaga marukkudhaa-nnu check pannunga.
2. Rendu settings-a maathi maathi pathu experiments run panni, `mlflow ui`-la compare pannunga. Overall-aa jeyichu oru segment-la thokkura oru run-a kandupidinga.
3. Best-aana rendai register panni, onna `champion`-aa set panni, rendume train aagaadha oru holdout-la innonnukku edhiraa promotion check-a run pannunga.
4. Promote pannunga, appuram roll back pannunga, pudhusaa start panna oru prediction script pazhaiya version-a load pannudhaa-nnu confirm pannunga.

**Mudinjadhu-nnu eppo sollalaam:** oru thani prediction-a, adhai uruvaakkuna model version, run, code commit, data snapshot varai trace panna mudiyumbodhu thaan.
