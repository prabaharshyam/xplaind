## Idhu enna

**Regression**-na oru maatramukku aprom, munnaadi work aanadhu ippo work aagaama pogradhu. LLM apps-la regressions romba common, aana amaidhiyaa nadakkum. Oru case-a fix panra prompt tweak, vera moonu cases-a udaikkum. Oru model upgrade output format-a maathum. Pudhu chunking setting perumbaalaana questions-a nallaa aakkum, aana oru mukkiyamaana document-a miss pannum.

**Regression tests** ovvoru maatramukkum unga eval set-a automatic-aa thirumba ottum; adhanaala users paakkuradhukku munnaadiye indha udaivugal pidipadum.

```flow
Pull request | oru prompt, model, retrieval illa code maatram -> Fast tier, ovvoru push-layum, kittathatta 90 s | app start aagudhu, JSON valid, 4 options 1 answer, duplicates illa, must-refuse cases, 15 critical cases
Fast tier, ovvoru push-layum, kittathatta 90 s -[fail aachu]-> Merge block aachu
Fast tier, ovvoru push-layum, kittathatta 90 s -[pass aachu]-> Full tier, deploy-ku munnaadi illa nightly | 120 cases, production baseline-ku edhiraa category vaariyaa judge scores
Full tier, deploy-ku munnaadi illa nightly -> Tolerance-kulla, edhu critical category-yum irangala?
Tolerance-kulla, edhu critical category-yum irangala? -[aama]-> Deploy
Production bugs -> Pudhu test cases -> Fast tier, ovvoru push-layum, kittathatta 90 s
```

Indha lesson, Noida-la oru edtech company-oda quiz-generation feature pathi; adhu chapter text-a multiple-choice questions-aa maathudhu.

## Idhu eppadi work aagudhu

**Rendu tiers tests.**

- *Ovvoru push-layum fast checks* (seconds-la irundhu konjam minutes varaikkum): code level-la, sulabamaana, deterministic checks. App start aagudhaa? Output valid JSON-aa parse aagudhaa? Required fields irukkaa? Theriyunda must-refuse inputs refuse aagudhaa? Konjam critical cases innum pass aagudhaa?
- *Mukkiyamaana changes-ku illa nightly fuller evals*: muzhu test set-a model judges-oda, ippo irukkura production version-oda scores-a category vaariyaa compare pannum.

**Baseline-oda compare pannunga.** Ippo irukkura production version-oda scores-a store pannunga. Overall quality set pannina tolerance-ku mela irangala, edhu critical category-yum (safety, refusals, mukkiya customers-oda cases) konjam kooda irangala-naa, andha change pass.

**Non-determinism-a handle pannunga.** Model outputs ovvoru run-layum maarum. Mudinja idathula tests-ku low temperature use pannunga, exact text-a vida criteria-vechu judge pannunga, borderline cases-a onnukku mela oru dhadava ottunga.

**Model upgrades-um oru change thaan.** Provider pudhu model release pannaalum, nee maaralaam-nu yosichaalum, full eval ottunga. Release notes-a vida results paathu decide pannunga: pudhu model overall nallaa irundhaalum, unga specific cases-la mosamaa irukkalaam.

**CI-la wire pannunga.** Ovvoru pull request-layum fast checks ottunga; fail aanaa merge-a block pannunga. Prompt illa model change-a deploy panradhukku munnaadi fuller eval ottunga. Trends paakka results-a store pannunga.

**Ovvoru bug-yum serunga.** Ovvoru production failure-um oru regression test case aagum.

**Ovvoru tier-layum enna irukkum:**

| Tier | Eppo odum | Contents | Neram |
| --- | --- | --- | --- |
| Fast | Ovvoru push-layum | Sirusaana set-la code checks, critical cases, must-refuse inputs | Seconds-la irundhu minutes |
| Full | Deploy-ku munnaadi, nightly | Muzhu test set, judges, category vaariyaa comparison | Minutes-la irundhu oru manineram |
| Model candidate | Pudhu model vandhaa | Full tier, adhoda downstream use panra format checks | Evvalavu neram thevaiyo avvalavu |

**Oru CI workflow, vaarthaigalla.** Ovvoru pull request-layum dependencies install pannunga, test settings-oda app-a start pannunga, fast tier-a ottunga, edhaavadhu check fail aanaa job-a fail pannunga. Main branch-ku merge aagum podhu, illa "run full eval" maadhiri label irundhaa, full tier-a ottunga. Scores-a store pannina production baseline-oda category vaariyaa compare pannunga, pull request-la oru table post pannunga, critical category irangina fail pannunga. Ovvoru run-oda results-yum commit-oda store pannunga; appo quality-a neram-vaariyaa chart pannalaam, mella mella kuraiyuradhaiyum kandupidikkalaam.

**Tolerances set panradhu.** Adhe version-la full tier-a pala dhadava ottunga; randomness-aala mattum scores evvalavu aadudhu-nu paarunga. Overall tolerance-a andha noise-ku konjam mela set pannunga. Safety, refusals maadhiri critical categories-ku konjam kooda irangaama paarunga, adhukku adhigam cases serunga; appo oru failure kooda nalla theriyum.

**Fast tier, code-la.** Property checks saadhaarana tests thaan. Idhu pytest use panni, konjam saved chapters-la quiz generator-a ottum:

```python
import json, pytest
from quiz import generate_quiz             # your app's function

CHAPTERS = json.load(open("tests/fast_chapters.json"))   # 15 saved chapters

@pytest.mark.parametrize("chapter", CHAPTERS, ids=lambda c: c["id"])
def test_quiz_shape(chapter):
    quiz = json.loads(generate_quiz(chapter["text"]))
    assert 3 <= len(quiz["questions"]) <= 10
    for q in quiz["questions"]:
        assert len(q["options"]) == 4
        assert len(set(q["options"])) == 4, "duplicate options"
        assert q["answer"] in q["options"]

def test_refuses_out_of_scope():
    out = generate_quiz("Write me a poem about cricket.")
    assert json.loads(out).get("error") == "not_a_chapter"
```

**Baseline comparison, code-la.** Full tier ovvoru case-kum oru score-a, adhoda category-yoda ezhudhum; idha script, candidate run-a store pannina production run-oda compare pannum:

```python
import json
from collections import defaultdict

CRITICAL = {"safety", "refusals"}

def by_category(path):
    scores = defaultdict(list)
    for line in open(path):
        r = json.loads(line)
        scores[r["category"]].append(r["score"])
    return {c: sum(v) / len(v) for c, v in scores.items()}

def compare(baseline_path, candidate_path, tolerance=0.02):
    base, cand = by_category(baseline_path), by_category(candidate_path)
    problems = []
    for cat, b in base.items():
        drop = b - cand.get(cat, 0)
        limit = 0 if cat in CRITICAL else tolerance
        if drop > limit:
            problems.append(f"{cat}: {b:.2f} -> {cand.get(cat, 0):.2f}")
    return problems

problems = compare("evals/production.jsonl", "evals/candidate.jsonl")
print("PASS" if not problems else "FAIL\n" + "\n".join(problems))
raise SystemExit(1 if problems else 0)       # a non-zero exit fails the CI job
```

**Oru drop-a namburadhukku munnaadi noise-a alandhu paarunga.** Maaraadha production version-la full tier-a moonu-la irundhu anju dhadava ottunga. History accuracy thaanaave 0.84-la irundhu 0.87 varaikkum aadudhu-naa, 0.85 irukkura candidate regress aagala. Sirusaana categories-ku cases serunga: 20 cases irundhaa, oru failure 5-point swing.

**Flaky cases.** Sila cases oru run-la pass aagi, adutha run-la fail aagum. Avatrai moonu dhadava ottitu, rendu dhadava pass aanaa podhum-nu vechukkalaam, illa case-a fix pannalaam: pala dhadava expected answer thaan kuzhappamaa irukkum. Purinjukkaama oru flaky case-a summaa delete pannaadheenga.

**Bill-a sirusaa vechukkunga.** Judge-oda full evals ovvoru run-kum selavu. Maaraadha inputs-ku, prompts-ku outputs-a cache pannunga, routine runs-ku selavu kammi judge-a, releases-ku munnaadi strong judge-a use pannunga, full tier-a ovvoru push-layum illaama label-la illa nightly-la ottunga.

**Test panradhai pin pannunga.** Ovvoru run-oda exact model version, prompt version, retrieval settings, judge prompt-a record pannunga. Oru score, adhe maadhiri panna innoru score-oda thaan compare panna mudiyum.

## Oru worked example

Noida-la oru ed-tech company-oda quiz-generation feature, chapter text-la irundhu multiple-choice questions-a JSON-aa uruvaakkudhu.

Avanga setup:

- *Ovvoru push-layum*: 15 chapters app-oda poguthu; ovvoru output-um valid JSON, naalu options, oru sariyaana answer, duplicate options illa-nu check pannuraanga, sensitive historical content irukkura rendu chapters-um disallowed phrasing illaama output tharanum. 90 seconds aagum.
- *Deploy-ku munnaadi*: 120 chapters-a factual accuracy-kum difficulty-kum oru judge score pannum, production-oda subject vaariyaa compare pannuvaanga.

Oru developer cost kammi panna prompt-a surukkuraanga. Fast checks pass. Full eval-la science accuracy maaralai, aana history 9 points kuraiyudhu, yen-na surukkina prompt-la "chapter-la irukkura facts-a mattum use pannu" nu irundha instruction poiduchu. Release-ku munnaadi andha change-a thirumba velai seiyuraanga.

Sila maadhangal kazhichu, provider-oda pudhu model overall 3 points adhigam score pannudhu, aana JSON fields-a vera order-la tharudhu, oru pazhaya client parser-a handle panna mudiyala. Fast checks idha pidikkudhu, switch panradhukku munnaadi parser-a fix pannuraanga.

| Change | Fast tier | Full tier | Decision |
| --- | --- | --- | --- |
| Cost-ku prompt-a surukkinadhu | Pass aachu | History accuracy 9 points kuraindhuchu | Release-ku munnaadi thirumba velai |
| Provider-oda pudhu model | Pazhaya parser-a udaikkura JSON field-order maatrathai pidichudhu | Overall 3 points adhigam | Parser-a fix pannitu apram switch |

## Podhuvaa panra thappugal

- **Prompts-ku automated tests illaama irukkradhu.** Prompt changes-um code changes thaan.
- **Exact-text comparisons.** Outputs maarum; properties-yum criteria-yum check pannunga.
- **Averages mattum paakkradhu.** Critical categories-a thaniyaa protect pannunga.
- **Evals ottaama models-a upgrade panradhu.**
- **Production bugs-a test set-la serkkaama irukkradhu.**
- **Fast tier-a slow aaga vidradhu.** Konjam minutes-ku mela aanaa makkal skip pannuvaanga. Slow cases-a full tier-ku nagarthunga.
- **Judge-um app-um oru neraththula maathradhu.** Edhu score-a nagarthuchu-nu theriyaadhu.
- **Green aaganum-nu failing cases-a delete panradhu.** App-a fix pannunga illa case-a fix pannunga, yen-nu ezhudhi vechukkunga.

## Light-aa test pannaa podhum-ngira idangal

- **Daily maarura prototype**: ethir ethirkkaama rewrite panra muzhu suite-a vida, konjam smoke checks nallaa irukkum.
- **Konjam expert users-a mattum kondha internal tools**, avanga problems-a vegamaa sollruvaanga: fast tier-a vechukkunga, perusu maatrangalukku munnaadi mattum full tier-a ottunga.
- **Maaraadha, deterministic steps**, ex: therinja file format-a parse panradhu: saadhaarana unit tests podhum.

Unmaiyaana users output-a nambi irukkum podhu full tier, baselines, critical categories-a serunga.

## Demo-la irundhu production-ku

- **Fast tier-la merges-a block pannunga**, adhai konjam minutes-ku kizha vechukkunga.
- **Ovvoru prompt, model, retrieval release-kum munnaadi full tier-a ottunga**, category table-a pull request-la post pannunga.
- **Ovvoru run-yum** commit, versions-oda store pannunga, mella kuraiyuradha pidikka scores-a neram-vaariyaa chart pannunga.
- **Test set-a quarter-ku oru dhadava review pannunga**: pazhaya cases-a nikkunga, pudhu user patterns-um ovvoru production bug-yum serunga.
- **Model upgrade checklist vechukkunga**: full tier, ovvoru downstream consumer-ku format checks, cost-um latency-yum compare pannunga.
