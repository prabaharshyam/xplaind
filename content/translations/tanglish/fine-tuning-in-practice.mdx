## Idhu enna

Fine-tuning lessons fine-tuning enna maathudhu, LoRA memory-a eppadi migaikkudhu-nu solludhu. Indha lesson, onna nallaa run panradhu pathi: aarambathula neenga edukkura choices, romba mukkiyamaana sila settings, loss curves-la irundhu adhu work aagudhaa-nu eppadi therinjukkalaam.

Ovvoru fine-tune-um moonu choices-oda aarambikkum:

1. **Oru base model.** Task mudiyumaa-nu mudhal test-ku, ungalaala mudinja romba strong model use pannunga: adhaalae task-a kathukka mudiyalaina, weak models kathukkaadhu. Apram selavu kuraikka sinna models try pannunga.
2. **Oru method.** **LoRA** illa vera light method-la aarambinga. Adhukku kammi memory-um kammi data-vum podhum, serve panra podhu neraya adapters oru base model-a share pannum. Ungakitta aayirakkanakkula examples irundhu LoRA podhalaina, apram full fine-tuning try pannunga.
3. **Oru tool.** Romba easy-aanadhu provider-oda fine-tuning service: data upload pannunga, model thirumba kidaikkum, aana kammi settings-um avangaloda models-um mattum. Hugging Face TRL-um PEFT-um, Unsloth, Axolotl, LLaMA-Factory, LitGPT maadhiri open-source frameworks ungaloda sondha GPUs-la run aagum, ellaa settings-um kudukkum.

Rendu podhuvaana development paths:

- **Progression path.** Code-a romba sellavu kammi model-la test pannunga, data-va naduthara model-la test pannunga, quality-a best model-la thallunga, apram best price-um performance-um kandupidikka pala sizes-a compare pannunga.
- **Distillation path.** Oru strong model-a sinna, arumaiyaana dataset-la fine-tune pannunga, adha vechu innum training data generate pannunga, apram oru sellavu kammi model-a adhula train pannunga.

```flow

Romba sinna model-la smoke test -> 20 examples-a overfit pannunga | loss kuraiyudhaa illa-a?

Loss healthy-aa? -[validation yerudhu]-> Kammi epochs, best checkpoint-a vachukkunga
Loss healthy-aa? -[aamaa]-> Prompt baseline-oda test set-la evaluate pannunga
Learning rate-a kuraiyunga -> LoRA-oda unmaiyaana run

Kammi epochs, best checkpoint-a vachukkunga -> Prompt baseline-oda test set-la evaluate pannunga
```

## Idhu eppadi work aagudhu

**Learning rate**-na weights update aagum podhu ovvoru step-oda size. Oru run-a nallaa aakkavum, kedukkavum romba vaaippu irukkura setting idhu thaan.

- Romba adhigam: loss thaavum illa melae pogum, outputs nonsense-aa maarum.
- Romba kammi: loss konjamdhaan kuraiyum, model kooda maaradhu.
- Useful values romba agalamaa irukkum, sumaar 1e-7 la irundhu 1e-3 varaikkum. LoRA runs podhuvaa 1e-4 la irundhu 2e-4 sutthi aarambikkum; full fine-tuning romba sinna values use pannum, pre-training mudiyumbodhu irundha rate-oda pathil oru bagam illa adhukkum kammi.
- Oru **schedule** podhuvaa konjam neram warm up panni, kadaisila rate-a kuraikkum.

**Batch size**-na ovvoru update-um evvalavu examples-la irundhu kathukkum-nu. Romba sinna batches (sumaar 8-ku kammi) training-a unstable aakkalaam; periya batches stable updates tharum, aana adhiga memory thevai. Memory thaan kammiyaa irukkum podhu, **gradient accumulation** ovvoru update-kum munnaadi neraya sinna batches-a serkkum, memory illaama periya batch-oda stability kidaikkum.

**Epochs**-na training data muzhukka poradhu. Romba periya datasets-ku onnu rendu podhum; konjam aayiram examples-ku neraya epochs-la improve aagitte irukkalaam. Validation loss-a decide pannattum: adhu kuraiyum varaikkum train pannunga, yera aarambichaa niruthunga.

**Prompt loss weight**, ovvoru example-oda prompt paguthi evvalavu count aagudhu-nu control pannum. Inference-la user prompt ezhudhuvaaru, model response ezhudhum, adhanaala perumbaalaana setups response-a muzhusaa count pannum, prompt-a konjam illa vae count pannaadhu (neraya tools prompt-a default-aa mask pannum; sila tools sumaar 10% use pannum).

**Curves-a padikkradhu.** Ovvoru sila dozen steps-kum aprom training loss-aiyum validation loss-aiyum plot pannunga.

| Neenga paarkkuradhu | Kaaranam | Enna pannanum |
| --- | --- | --- |
| Loss spike aagudhu illa NaN aagudhu | Learning rate romba adhigam, illa mosamaana data | Rate-a kuraiyunga; empty illa periya examples irukkaa-nu paarunga |
| Aarambathulayae loss flat | Rate romba kammi, thappaana labels, illa thappaana tokens-la loss | Rate-a yethunga; data format-aiyum masking-aiyum check pannunga |
| Training kuraiyudhu, validation yerudhu | Overfitting | Kammi epochs, adhiga data, mundhaiya checkpoint-a vachukkunga |
| Mudiyumbodhum rendumae kuraiyudhu | Undertrained | Innum epochs illa innum data |
| Loss nallaa irukku, outputs mosam | Data thappaana vishayatha kathukkudhu, illa inference-la prompt format maarudhu | Examples-a padinga; training-lum use-lum adhey chat template-a use pannunga |

**Naal-a migaikkura habits.**

- Muzhu pipeline-a oru romba sinna model-lum konjam examples-lum **smoke test** pannunga: load, train, save, reload, generate.
- **Venumnae overfit pannunga**: 20 examples-la model adha thirumba solra varaikkum train pannunga. Mudiyalaina, edho odanjirukku.
- **Checkpoints-a** irukkura oru folder-la save pannunga, crash aanaa maniyakkanakkula illa, nimishangal thaan selavaagura alavukku adikkadi.
- Training-lum use-lum **adhey chat template-a use pannunga**. Mismatch amaidhiyaa results-a keduthudum.
- Ovvoru run-oda **ovvoru setting-aiyum** data version-aiyum **log pannunga**.

Ungaloda loss logs-a padikka oru sinna helper:

```python
def diagnose(train_loss, val_loss):
    """Lists of loss values measured at the same steps."""
    if any(x != x or x > 10 * train_loss[0] for x in train_loss):   # NaN or blow-up
        return "Unstable: lower the learning rate and check for bad examples."
    if train_loss[-1] > 0.95 * train_loss[0]:
        return "Not learning: raise the learning rate or check data and masking."
    best = val_loss.index(min(val_loss))
    if best < len(val_loss) - 1:
        return f"Overfitting after step {best}: keep that checkpoint or use fewer epochs."
    return "Both still falling: more epochs or more data may help."

print(diagnose([2.1, 1.6, 1.2, 0.9, 0.7], [2.0, 1.6, 1.4, 1.5, 1.7]))
```

## Oru worked example

Chennai-la oru ed-tech company oru open 8B model-a LoRA-la fine-tune panni, English, Tamil short answers-a correct, partly correct, wrong-nu oru-line reason-oda grade panna vaikkuraanga. Avangakitta 2,400 graded answers irukku, 300-a locked test set-aavum 200-a validation-kum vechirukkaanga.

Mudhalla 0.5B model-la 20 examples-oda smoke test: run, saving, reloading ellaam work aagudhu, model andha 20 examples-a memorise pannudhu. Apram unmaiyaana runs:

| Run | Learning rate | Epochs | Curves enna kaattunadhu | Test accuracy |
| --- | --- | --- | --- | --- |
| 1 | 2e-3 | 3 | Loss thaavi, apram vedichudhu; outputs gibberish | Use panna mudiyaadhu |
| 2 | 1e-6 | 3 | Loss konjamdhaan nagarndhudhu; outputs base model maadhiri | 61% |
| 3 | 2e-4 | 3 | Epoch 2 mudiyumbodhu validation best, apram yerichu | 84% (epoch-2 checkpoint) |
| Prompt-only baseline | n/a | n/a | n/a | 72% |

Numbers illustration-ku mattum. Run 3-oda epoch-2 checkpoint prompt baseline-a 12 points vida jeikkudhu. Tamil accuracy English-a vida 6 points kammi, adhanaala adutha step innum Tamil examples, innum tuning illa.

## Podhuvaa panra thappugal

- **Oru periya model-la full fine-tune-oda aarambikkradhu.** Mudhalla LoRA-la task-a prove pannunga.
- **Smoke test-a skip panradhu.** Save path-la oru typo oru raathiri training-a waste aakkidum.
- **Training loss-a vachi mattum judge panradhu.** Validation-um test results-um thaan unmaiyaana learning-a kaattum.
- **Ellaa epochs-aiyum kannai moodikkittu use panradhu.** Validation best-aa irundha checkpoint-a vachukkunga.
- **Orae neraththula neraya settings-a maathradhu.** Onna maathi, compare panni, apram adutha onnu.
- **Production-la vera prompt format.** Model oru template kathukittadhu; adhukku adhaye kudunga.

## Eppo settings tune panradha niruthanum

- **Sensible settings-la validation results stable-aa irukku.** Innum gains data-la irundhu varum, knobs-la irundhu illa.
- **Oru segment pinnaadi irukku**, example oru language illa oru question type: adhukku examples serunga.
- **Prompt baseline kitta irukku.** Fine-tuning onnu rendu points-la mattum jeichaa, upkeep worth-aa irukkaadhu.

## Demo-la irundhu production-ku

- **Ovvoru run-aiyum record pannunga**: data version, base model, method, ovvoru setting, curves, test scores.
- **Best checkpoint-aiyum adhoda exact template-aiyum vachukkunga**, deploy panna model-a adhey test set-la test pannunga.
- **Base model illa data maarumbodhu recipe-a thirumba run pannunga**; record panna recipe adha routine aakkum.
- **Launch-ku aprom monitor pannunga**, yenaa unmaiyaana inputs training data-la irundhu maarum.

## Practice pannunga

1. Edhaavadhu oru task-ku 50 examples-la oru sinna open model-a free notebook-la fine-tune pannunga. Moonu learning rates try panni, loss curves-a plot pannunga.
2. Venumnae 20 examples-a overfit pannunga, model adha thirumba solludhu-nu confirm pannunga.
3. Ungaloda curves-la diagnose helper-a use panni, entha checkpoint-a vachukkuveenga, yen-nu ezhudhunga.

Innum aazhama paarka, Chip Huyen-oda *AI Engineering* (O'Reilly, 2025)-la chapter 7 fine-tuning methods, frameworks, hyperparameters-a solludhu.

**Mudinjadhu-nu eppo sollalaam:** oru fine-tuning project-ku oru safe order-a solla mudiyum, oru starting learning rate, batch size, epochs set panna mudiyum, oru run-a adhoda loss curves-la irundhu diagnose panna mudiyum.
