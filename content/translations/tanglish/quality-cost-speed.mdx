## Idhu enna

Ovvoru LLM app-um moonu vishayangalai onnukkonnu trade pannudhu:

- **Quality**: badhilgal evvalavu adikkadi sariyaa, muzhusaa, safe-aa irukku.
- **Cost**: oru request-kkum oru maasathukkum aagura panam.
- **Speed**: users evvalavu naeram kaathirukkaanga, mudhal vaarthaigalukkum muzhu reply-kkum.

Periya models, adhigamaa retrieve panna context, rerankers, reflection steps, agent loops podhuvaa quality-a koottum. Adhe naeram cost-aiyum latency-aiyum koottum. Nalla engineering indha trade-offs-a velippadaiyaa kaattudhu, nermaiyaa alakkudhu, product-a own panravanga yosichu mudivu edukka vidudhu.

Kashtamaana pagudhi ennannaa, table-la endha differences unmaiyaanadhu-nnu therinjukkiradhu. Oru test set oru sample thaan, adhanaala ovvoru accuracy figure-kkum oru margin of error irukku. 150 questions-la 86%-um 88%-um orae result thaan. Oru test set-la oru system-oda failures-a padichu adha improve pannaa, andha set-la varra adhoda score inimae oru fair estimate illa.

```flow
title: Mudivu edukkura method
Tuning set-la options-a alanga | category vaariyaa quality, cost, p95
Tuning set-la options-a alanga -> Dominated options-a drop pannunga
Dominated options-a drop pannunga -> Budgets-a apply pannunga | latency, cost ceilings
Budgets-a apply pannunga -> Margin-kkulla irukkura gaps-a tie-aa edunga
Margin-kkulla irukkura gaps-a tie-aa edunga -> Thernthedutha option-a tune pannunga
Thernthedutha option-a tune pannunga -> Fresh questions-la gate-a pass pannunga | oru thadavai ottunga
Fresh questions-la gate-a pass pannunga -> Recommend panni date podunga
```

Indha example Hyderabad-la irukkura oru health-insurance company-a follow pannudhu; avanga call-centre agents live calls nadakkumbodhu oru assistant-a use panraanga.

## Idhu eppadi work aagudhu

### Moonaiyum adhe questions-la alanga

Ovvoru option-kkum idha record pannunga:

- unga eval-la irundhu quality, category vaariyaa pirichu (udhaaranamaa exclusions, claims, premiums, general questions);
- oru request-kku cost: input, output tokens × price, kooda aedhaavadhu reranker alladhu router call;
- median-layum 95th percentile-layum (p95) latency, kooda time to first token.

Ovvoru option-kkum adhe questions-a, adhe order-la use pannunga, appo thaan keezha irukkura paired check panna mudiyum.

### Difference unmaiyaanadhaa?

n questions-la alandha oru accuracy oru estimate thaan. Rough-aa oru 95% margin of error:

**margin ≈ 2 × √(p × (1 − p) / n)**

| Accuracy | Questions | Thoraayamaana margin |
| --- | --- | --- |
| 88% | 150 | ±5.3 points |
| 86% | 200 | ±4.9 points |
| 88% | 470 | ±3.0 points |
| 88% | 1,060 | ±2.0 points |

Margin n-oda square root-oda vigidhathula kuraiyudhu: adha paadhiyaakka naalu madangu questions venum. Adhanaala 150 questions-la oru two-point gap thaniyaa edhaiyum sollaadhu.

**Thanithaniyaa illaama, paired-aa compare pannunga.** Rendu margins overlap aaguradhaala kelvi theerndhudaadhu, yennaa rendu options-um adhe questions-a thaan sandhichudhu. Rendu numbers-a ennunga: A mattum sariyaa sonna questions, B mattum sariyaa sonna questions. Rendumae sariyaa sonna alladhu rendumae thappaa sonna questions difference pathi endha information-um tharaadhu. Rendu counts-kku naduvula irukkura gap 2 × √(avatroda sum)-a vida chinnadhaa irundhaa, difference niroobikkappadalai. Udhaaranamaa, 8-kku 4 flips-naa gap 4, aanaa 2 × √12 sumaar 7, adhanaala adhu tie. 18-kku 3-naa gap 15, threshold sumaar 9: andha difference unmaiyaanadhu. (Idhu McNemar test-oda oru rough version.)

**Noise floor-a alanga.** Adhe option-a adhe questions-la rendu thadavai ottunga. LLM outputs ovvoru run-kkum maarum, LLM judges-um maarum. Oru rerun 6 answers-a flip pannaa, 6 answers-a flip panra oru pudhu option edhaiyum niroobikkalai.

**Chinna categories uyarndha floors-a niroobikka mudiyaadhu.** Oru category-la irukkura 30 questions-aiyum oru option sariyaa sonnaalum, unmaiyaana error rate innum sumaar 30-la 3, adhaavadhu 10%, aaga irukkalaam. Idhu thaan "rule of three": n questions-la zero errors irundhaalum error rate sumaar 3/n varai irukka vaaippu irukku. "Claims-la korainjadhu 85%" maadhiri oru floor-a kaatta, ethanai claims questions venum-nu munnaadiyae kanakku pottu, athanaiyaiyum build pannunga.

### Oru set-la tune pannunga, innonnula gate-a pass pannunga

Oru test set-la failures-a padichu, avatrai sari panna prompts, routing rules alladhu thresholds-a maathumbodhu, andha fixes andha set-oda quirks-kku fit aayidum. Andha set-la score unmaiyaana quality-a vida adhigamaa aerum. Orae set-la pala options-la irundhu best-a thernthedukkuradhum adhe effect thaan: jeyichadhoda score-la oru pagudhi luck.

Adhanaala rendu sets vachukkonga:

- oru **tuning set**: options-a compare pannavum failures-a kandupidikkavum idha thaaraalamaa paarunga;
- oru **gate set**: build pannumbodhu yaarum padikkaadha fresh questions (udhaaranamaa, sameebathiya calls-la irundhu sample pannadhu). Sign-off naerathula idha oru thadavai ottunga. Option fail aanaa, tuning set-la sari pannunga, adutha attempt-kku munnaadi gate-a pudhu questions-oda refresh pannunga. Neenga padicha gate inimae gate illa.

### Vilaivai vachu weight kudunga

Saadhaarana accuracy ovvoru thappaana badhilaiyum orae maadhiri paarkkudhu. Oru policy exclusion pathina thappaana badhil oru complaint-aiyum refund-aiyum undaakkalaam; office hours pathina thappaana badhilukku selavu kammi. Ovvoru category-kkum oru error-oda business cost-a vachu oru weight kudunga; adhu client-oda sondha data-la irundhu eduthadhaa, product owner othukkittadhaa irukkanum. Udhaaranamaa, insurer-oda records-padi oru thappaana exclusion alladhu claims badhil sumaar ₹1,500 selavaagura oru escalation-kku kondu pogudhu, oru premiums error sumaar ₹1,000, oru general error sumaar ₹500-nu vachukkonga: weights 3, 3, 2, 1 aagum. Weights-aiyum avatroda source-aiyum comparison pakkathulayae ezhudhunga, yennaa weights ranking-aiyae maathalaam.

### Yaarum thernthedukkak koodaadha options-a drop pannunga

Quality, cost, speed-la innoru option korainjadhu adhe alavu nalladhaa irundhu, korainjadhu onnula maelaa irundhaa, andha option **dominated**. Dominated options-a drop pannaa **Pareto frontier** minjum: adhu thaan unmaiyaana choices. Quality-a margin-a manasula vachu padinga. Rendu options quality-la noise-kkulla irundhaa, avatrai tie-aa eduthukkonga, cost-um speed-um mudivu pannattum. Margin-a vida chinna quality gap mela mudivu ninnaa, badhil innum adhiga questions thaan, confident-aana oru guess illa.

| Lever | Quality | Cost | Speed |

| Innum periya model | koodum | koodum | innum medhuvaa |
| Adhiga reasoning alladhu effort setting | Kashtamaana tasks-la koodum | koodum (adhiga tokens) | innum medhuvaa |

Niraiya reasoning models-kku oru effort setting irukku (udhaaranamaa, OpenAI-oda `reasoning.effort`). Adhu orae model-kkulla quality-a cost, latency kooda trade pannudhu, adhanaala rendu moonu settings-a thanithani options-aa test pannunga. November 2026 nilavarappadi, OpenAI, Anthropic-oda Batch APIs kaathirukkakkoodiya requests-kku normal vilaiyila paadhi thaan charge pannudhu: nightly summaries-kko pazhaiya tickets-a re-score panradhukko nalladhu, live call-la payanilla. Kadaisi row-a Caching and speed, Cost control, Latency budgets and load testing lessons cover pannudhu; edhukkaavadhu panam katturadhukku munnaadi andha free wins-a apply pannunga.

### Router-a alanga, adhoda sondha cost-aiyum serthu

Oru router easy requests-a oru malivaana model-kkum, hard requests-a oru strong model-kkum anuppudhu. Adhu nallaa route pannaa mattum thaan panam michamaagum, adhukku sondha costs-um irukku:

- **Misroutes.** Oru sample-a easy alladhu hard-nu label panni, router-a otti, small model-kku anuppappatta hard questions-aiyum (ivai quality-a baadhikkum) large model-kku anuppappatta easy questions-aiyum (ivai panathai veenaakkum) ennunga. Mudhal vagai thaan adhiga mukkiyam. Oru high-risk category-la adhu adikkadi nadandhaa, andha muzhu category-aiyum strong model-kku anuppunga.
- **Overhead.** Routing decision ovvoru request-layum odudhu. Oru language-model call-a router-aa use pannaa adhu thannoda sondha price-aiyum delay-aiyum serkkum; simple rules alladhu oru chinna embedding classifier adha vida rombavae malivaanadhu, vaegamaanadhu. Eppadi irundhaalum overhead-a alanga.
- **Tail.** 30% traffic 3.9 s p95 irukkura oru model-kku ponaa, router-oda p95 small model-odadhu illa. Ellaathaiyum vida medhuvaana 5% requests-la kittathatta ellaamae slow path-la irundhu thaan varudhu, adhanaala blended p95 andha path-oda distribution-kkulla thaan vizhum.

### Code-la oru comparison

```python
import math

WEIGHTS = {"exclusions": 3.0, "claims": 3.0, "premiums": 2.0, "general": 1.0}

def weighted_quality(results):
    """results: list of (category, correct) pairs; correct is True or False."""
    num = sum(WEIGHTS[c] * ok for c, ok in results)
    den = sum(WEIGHTS[c] for c, _ in results)
    return num / den

def margin(p, n):
    """Rough 95% margin of error for an accuracy p measured on n questions."""
    return 2 * math.sqrt(p * (1 - p) / n)

def paired(a, b):
    """a, b: True/False per question for two options, same questions, same order."""
    a_only = sum(x and not y for x, y in zip(a, b))
    b_only = sum(y and not x for x, y in zip(a, b))
    real = abs(a_only - b_only) > 2 * math.sqrt(a_only + b_only)
    return a_only, b_only, real

def frontier(options):
    """options: dicts with quality, cost_inr and p95_s. Drops dominated options."""
    def dominates(a, b):
        no_worse = (a["quality"] >= b["quality"] and a["cost_inr"] <= b["cost_inr"]
                    and a["p95_s"] <= b["p95_s"])
        better = (a["quality"] > b["quality"] or a["cost_inr"] < b["cost_inr"]
                  or a["p95_s"] < b["p95_s"])
        return no_worse and better
    return [o for o in options if not any(dominates(x, o) for x in options if x is not o)]
```

`margin(0.88, 150)` sumaar 0.053 return pannum, adhaavadhu 5 points.

### Mudhalla budgets, appuram quality-a maximise pannunga

Results-a paarkkuradhukku munnaadiyae product owner kooda rendu ceilings-a othukkonga: oru latency budget (udhaaranamaa, p95-la mudhal vaarthaigal 1 s-kkulla, muzhu reply 4 s-kkulla), oru request-kku oru cost. Rendukkullayum irukkura options-aa frontier-a filter pannunga, appuram adhula best quality-a thernthedunga, ties-a ties-aavae padinga. Safety-critical categories-kku, endha saving-kkaagavum adhukku keezha irangak koodaadha oru minimum quality-aiyum othukkonga.

## Oru worked example

Hyderabad insurer-oda assistant live calls-la irukkura agents-kku policy questions-kku badhil solludhu. Keezha irukkura ella numbers-um illustrative, method-a kaatturadhukkaaga thernthedutthadhu.

Othukkitta budgets: p95-la mudhal vaarthaigal 1 s-kkulla, muzhu reply 4 s-kkulla, oru request-kku adhigabatcham ₹0.40.

**Round 1, 150 questions irukkura oru tuning set-la:**

| Option | Accuracy | Oru request-kku cost | p95 latency |
| --- | --- | --- | --- |
| Small model | 76% | ₹0.08 | 1.6 s |
| Large model | 85% | ₹0.60 | 3.9 s |
| Large model + reranker | 89% | ₹0.64 | 4.3 s |
| Router (70% small, 30% large) | 86% | ₹0.24 | 3.0 s |

Router-oda cost adhoda traffic split-la irundhu varudhu: 0.7 × ₹0.08 + 0.3 × ₹0.60, kooda adhoda classifier-kku sumaar ₹0.002, mottham sumaar ₹0.24. Adhoda p95 3.0 s, small model-odadha vida kittathatta rendu madangu, yennaa ellaathaiyum vida medhuvaana 5% requests perumbaalum large model-la irundhu thaan varudhu.

Team enna mudivukku varalaam, enna mudivukku vara mudiyaadhu:

- Large model thaniyaa dominated: router adhoda accuracy-kku samamaa irukku, adha vida malivaavum vaegamaavum irukku. Adha drop pannunga.
- Small model router-a vida thelivaa mosam. Paired check-la, router miss panna 3 questions-a adhu sariyaa sonnuchu, adhu miss panna 18-a router sariyaa sonnuchu. Andha gap unmaiyaanadhu.
- Large model plus reranker rendu budgets-aiyum meerudhu (4.3 s, ₹0.64). Router-a vida adhukku irukkura lead-um ±5-point margin-kkulla thaan: paired check 4-kku 8 flips kaattudhu, tie.

Router-oda thappugalai padichappo, avai exclusions, claims-la koottamaa irukkuradha team paarthaanga. Design-a maathunaanga: ella exclusions, claims questions-um reranker kooda large model-kku pogudhu, meedhiyai router handle pannudhu. Ippo 38% traffic strong path-la pogudhu. Adhe 150 questions-la adhu 88% score pannuchu, aanaa avanga andha questions-la thaan tune pannaanga, adhanaala andha figure optimistic.

Ella idathulayum reranker kooda large model use pannaa, 400 questions-la naanga alakkakkoodiya endha quality difference-um theriyalai, adhukku rendu madangu cost aagudhu, 4 s budget-aiyum meerudhu. Streaming mudhal vaarthaigalai 1 s-kkulla vachirukku. Prices-um results-um November 2026-la alandhadhu, test set version 2; oru provider prices-a maathumbodho pudhu model ship pannumbodho comparison-a thirumba ottuvom."

## Podhuvaa panra thappugal

- **Oru dimension-a mattum sathamillaama optimise panradhu.** Quality, cost, speed-a serthae kaattunga.
- **Noise-a win-nu solradhu.** 150 questions-la 86%-kku edhiraa 88% oru tie. Margin-aiyum paired flips-aiyum kudunga, illannaa questions serunga.
- **Tuning set-la gate-a pass panradhu.** Oru set-kku fit panna fixes adhoda score-a oodhip perusaakkum. Oru fresh gate set vachu, adha oru thadavai ottunga.
- **Overall accuracy mattum.** Category vaariyaa pirichu, errors-oda cost vachu weight kudunga.
- **Engineer thaanaa karpanai panna weights.** Avatrai client-oda data-la irundhu eduthu, avatroda source-a record pannunga.
- **Average latency mattum.** p95-aiyum time to first token-aiyum report pannunga.
- **Router-oda sondha costs-a marakkuradhu.** Adhoda call, misroutes, tail ellaamae kanakkula varum.
- Meeting-la **dominated options-a vachirukkuradhu**, anga avai naerathai veenaakkum.
- Comparison-la **date, prices, test-set version illaadhadhu**, adhanaala yaarukkum theriyaama adhu pazhasaayidum.
- **Product owner illaama mudivu edukkuradhu.** Trade-off oru business decision; table-a kaatti avangalae edai podattum.

## Muzhu trade-off study thevai illaadha naerangal

- **Kuraivaana volume.** Unga traffic-la ellaathaiyum vida strong-aana model maasathukku sila nooru rupees thaan aagudhu-nnaa, adhaiyae use pannunga, appuram optimise pannunga.
- **Oru option ella targets-aiyum** niraiya idam micham vachu clear pannumbodhu, adhoda margin-oda low end udpada.
- **Early prototypes**, anga task work aagudhaa-nnu therinjukkiradhu thaan mudhalla. Irundhaalum neenga saegarikkura questions-a vachukkonga: avai thaan unga tuning set aagum.

## Demo-la irundhu production-ku

- **Comparison table-a vachukkonga**: dates, prices, weights, tuning set, gate set rendukkumaana test-set versions-oda.
- Production-la feature, category vaariyaa **quality, oru request-kku cost, p95 latency-a track pannunga**.
- Ovvoru sign-off-kkum munnaadi sameebathiya traffic-la irundhu **gate set-a refresh pannunga**, appo thaan users ippo kekkuradhukku adhu match aagum.
- High-risk categories-kku, endha routing change-um keezha irakka mudiyaadha **minimum quality-a hold pannunga**.
- Ovvoru maasamum category vaariyaa **router-oda thappugalai alanga**.
- Price changes, pudhu models, periya traffic changes varumbodhu **comparison-a thirumba ottunga**.

## Practice pannunga

Keezha link panniyirukkura Chip Huyen-oda production article-a thirumba padinga, cost, latency mela gavanam vachu.

1. Unga app-la rendu moonu options-kku, adhe questions-la, category vaariyaa quality, oru request-kku cost, p95 latency-oda oru table build pannunga.
2. Best-aana rendu options-kku `paired` otti, flip counts-aiyum gap unmaiyaanadhaa-nnum report pannunga. Unmaiyaanadhu illannaa, ethanai questions 3 points margin tharum-nu kanakku podunga.
3. Oru option-a adhe questions-la rendu thadavai otti flips-a ennunga: adhu thaan unga noise floor.
4. Unga table-a `frontier`-kku kuduthu, drop aana ovvoru option-um yen dominated-nu oru sentence ezhudhunga.
5. Neenga padikkaadha oru gate set-a pirichu vachu, maela irukkura style-la oru paragraph recommendation ezhudhi, gate-a oru thadavai pass pannunga.

Innum aazhamaa therinjukka, Chip Huyen-oda *AI Engineering* (O'Reilly, 2025) chapter 4 cost, latency-a criteria-vaa vachu model selection-a cover pannudhu, chapter 9 inference performance metrics-a cover pannudhu.
