## Idhu enna

Oru public cloud, computers, storage, networks, ready-made services-a ungalukku vaadagaikku tharudhu, use panradhukku aetha maadhiri bill varum. AWS, Microsoft Azure, Google Cloud kittatthatta orae building blocks-a vera vera pergalla tharudhu. Enterprises perumbaalum group muzhukka orae choice-a follow pannuvaanga; banks, insurers, pharma companies adikkadi data enga irukkalaam-nu rules-um serppaanga.

Indha lesson Azure-a aazhamaa paakkudhu, yenna course resources Microsoft Learn paths. Ovvoru step-kkum matha clouds-la nerukkamaana match irukku, keezha irukkura table-la adha kaattiyirukkom.

Oru AI deployment sumaar ezhu vagai service-a use pannum:

- **Compute**: unga code enga run aagudhu.
- **Storage**: files, documents.
- **Databases**: structured data, perumbaalum embeddings-kku pgvector extension-oda PostgreSQL.
- **Networking**: virtual networks, private endpoints, orae oru public entry point.
- **Identity and access**: yaar, edhu, endha actions-a seiyalaam.
- **Managed models**: hosted model APIs; prompts enga process aagudhu-nu idhula deployment type thaan mudivu pannum.
- **Monitoring**: logs, metrics, alerts, enna nadandhuchu-nu neenga paakka mudiyura maadhiri.

**Shared responsibility.** Buildings, hardware, managed services-a provider secure pannum. Neenga configure panradhu unga poruppu: unga data, adha yaar access pannalaam, endha endpoints public, neenga evvalavu selavu panreenga. "Cloud security basics" lesson idha innum aazhamaa paakkudhu.

```flow
title: Central India-la, orae virtual network-kulla document assistant
Staff | Entra ID sign-in -> Application Gateway | orae public entry, HTTPS
Application Gateway -> Container Apps | internal-only environment, managed identity
Container Apps -[private endpoint]-> Blob Storage
Container Apps -[private access]-> PostgreSQL with pgvector
Container Apps -[secret reference]-> Key Vault
Container Apps -[private endpoint]-> Foundry model | regional Standard deployment
Container Apps -> Log Analytics
```

Indha lesson-la Hyderabad-la oru pharma company-kku Azure-la avanga document assistant-a design panradha follow panna porom.

## Idhu eppadi work aagudhu

### Regions, zones

Region-na oru pagudhiyila irukkura data centres-oda oru kuzhu. Azure-kku India-la naalu irukku: Central India (Pune), South India (Chennai), West India (Mumbai), India South Central (Hyderabad); kadaisiyadhu August 2026-la launch aachu. AWS-kku Mumbai, Hyderabad; Google Cloud-kku Mumbai, Delhi.

Sila regions-la availability zones irukkum: thani power, cooling-oda irukkura thani data centres; adhanaala zones muzhukka parappi vecha replicas, onnu fail aanaalum thaangum. Ella region-layum zones-o ella service-o irukkaadhu, adhanaala neenga use panna pora ovvoru service-kkum Azure-oda products-by-region page-a check pannunga.

Region-a indha varisaiyila select pannunga:

1. **Residency**: client-oda policy, contracts, regulators enna kekkuraanga.
2. **Availability**: unga ella services-um, sariyaana deployment type-oda model-um anga kidaikkudhaa?
3. **Latency**: users-kku irukkura dhooram. Oru chat app-kku ella Indian region-um podhumaana alavu pakkathula thaan.
4. **Price**: regions-kku idaiyila prices konjam maarum; idhu thaan kadaisi mukkiyathuvam.

Kaaranangala ezhudhi vainga; client-oda cloud team keppaanga.

### Compute choices

| Ungalukku vendiyadhu | Select pannunga | Yen |
| --- | --- | --- |
| Oru container-la HTTP API (perumbaalaana AI apps) | Container Apps | Replicas, scaling, HTTPS, revisions ellaam built-in |
| Events illa timer trigger panra kutti jobs | Container Apps jobs illa Azure Functions | Job run aagura nerathukku mattum pay pannuveenga |
| Client-oda existing platform-oda porundha | AKS (managed Kubernetes) | Avanga platform team aerkanavae run panna mattum |
| GPUs illa machine-oda muzhu control | Virtual machines | Patch, scale ellaam neengalae pannanum |

Container Apps, run aagura replicas-oda CPU, memory-kku bill pannum. `--min-replicas 0` idle-aa irukkumbodhu zero-kku scale pannum, aanaa konja neram amaidhiyaa irundhadhukku appuram vara mudhal request oru cold start-kkaaga kaathirukkum. Oru staff tool-kku, oru warm replica niyaayamaana trade.

### Storage, databases

Documents-kku Blob Storage, records-kkum vectors-kkum Azure Database for PostgreSQL (flexible server) use pannunga; backups, patching, failover ellaam built-in. Rendu details makkala maatti vidum:

- pgvector-a create panradhukku munnaadi allow-list pannanum: server parameter `azure.extensions`-a `vector`-aa set pannunga, appuram `CREATE EXTENSION vector;` run pannunga. Extension-oda per `vector`, `pgvector` illa.
- Server-a create pannumbodhae **private access** (`--vnet`, `--subnet`) select pannunga. Idha aarambathulaye mudivu pannunga: appuram maathanumna downtime-oda oru migration venum.

### Networking, private endpoints

Ellaamae oru virtual network-kulla irukkum. Container Apps environment-kku thani subnet kidaikkum, adhu internal-only, adhanaala app-kku public address illa. Orae public entry oru Application Gateway, illana client-oda existing gateway.

Blob Storage, Key Vault, Foundry-a **private endpoints** vazhiyaa reach pannuveenga: unga network-kulla andha service-kku oru private IP address. Appuram ovvoru service-oda public network access-aiyum off pannunga. Classic failure: endpoint irukku, aanaa endha private DNS zone-um (udhaaranam, `privatelink.blob.core.windows.net`) network-oda link aagala. Name innum public address-kku thaan resolve aagum, adha neenga ippo thaan moodineenga, adhanaala ovvoru call-um fail aagum.

### Identity

App-kku oru **managed identity** kudunga: Azure adhukku short-lived tokens-a kudukkum, adhanaala store pannavo leak aagavo endha key-um illa. Velai seiyura miga kurugiya scope-la adhukku roles kudunga:

- **Storage Blob Data Reader** oru blob container-la, muzhu subscription-la illa.
- **Key Vault Secrets User** oru vault-la.
- **Cognitive Services OpenAI User** Foundry resource-la.
- **AcrPull** container registry-la.

Rendu gotchas. Owner, Contributor maadhiri management roles oru resource-a maatha vidum, aanaa unga sondha token vachu adhoda data-va padikka vidaadhu; adhukku oru data role venum. Adhoda role assignments apply aaga sila nimishangal aagalaam, adhanaala grant pannina udanae vara 403 thaanaa sariyaagalaam.

Makkal company-oda Microsoft Entra ID vazhiyaa thaan sign in aavaanga, shared accounts-la orupodhum illa.

### Managed models, residency trap

Microsoft Foundry (November 2025-la Azure AI Foundry-la irundhu rename aachu) client-oda Azure contract-kulla models-a host pannudhu. Prompts enga process aagudhu-nu resource-oda region illa, **deployment type** thaan mudivu pannum:

| Deployment type | Prompts enga process aagalaam | Eppo use pannanum |
| --- | --- | --- |
| Global (Standard illa provisioned) | Model run aagura endha Azure region-layum | Residency rule illa; adhigapatcha quota venum |
| Data Zone | Microsoft varaiyarutha oru zone-kulla: US, EU illa Asia Pacific | Oru multi-country zone-a rule anumadhikkudhu |
| Standard illa provisioned, regional | Deployment-oda sondha region | Data India-laye process aaganum |

Store panna data ella type-kkum resource-oda geography-laye irukkum; maarradhu ovvoru request-um enga process aagudhu-ngradhu thaan. Central India resource-la irukkura oru Global deployment kooda oru prompt-a velinaattukku anuppalaam. Pudhu models perumbaalum aarambathula Global-aa mattum thaan kidaikkum, adhanaala residency-a promise panradhukku munnaadi region-availability table-aiyum, portal-la irukkura deployment dialog-aiyum check pannunga. AWS-layum idhae switch irukku: oru India inference profile (`in.`-la aarambikkura model IDs) Mumbai, Hyderabad-kku idaiyila mattum route pannum, aanaa oru `global.` profile enga venumnaalum route pannalaam.

App thannoda managed identity vachu adhoda deployment-a call pannum, adhanaala API key-yae illa:

```python
from azure.identity import DefaultAzureCredential, get_bearer_token_provider
from openai import OpenAI

token = get_bearer_token_provider(DefaultAzureCredential(), "https://ai.azure.com/.default")
client = OpenAI(base_url="https://docassist-ai.openai.azure.com/openai/v1/", api_key=token)
reply = client.chat.completions.create(
    model="docassist-chat",  # your deployment's name, not a model ID
    messages=[{"role": "user", "content": "Summarise this stability report: ..."}])
```

### Quotas

Model throughput-a oru quota limit pannum: tokens per minute-la, ovvoru model, region, subscription-kkum thaniyaa. Oru pudhu subscription-la GPU virtual machine quota perumbaalum zero-la thaan aarambikkum. Increases udanae kidaikkaadhu, refuse-um aagalaam, adhanaala quota-va launch week-la illa, mudhal vaarathulaye request pannunga.

### Command line-la irundhu deploy pannunga

Diagram kaatturadha indha commands build pannum; `$` variables mundhaiya steps-la irundhu vara IDs-a vachirukkum.

```bash
# 1. Create the identity first, so it can be granted access before the app exists.
az identity create -g rg-docassist -n id-docassist -l centralindia
ID=$(az identity show -g rg-docassist -n id-docassist --query id -o tsv)
PRINCIPAL=$(az identity show -g rg-docassist -n id-docassist --query principalId -o tsv)
CLIENT_ID=$(az identity show -g rg-docassist -n id-docassist --query clientId -o tsv)

# 2. Least privilege. Repeat for Key Vault Secrets User, AcrPull and Cognitive Services OpenAI User.
az role assignment create --assignee-object-id "$PRINCIPAL" --assignee-principal-type ServicePrincipal \
  --role "Storage Blob Data Reader" --scope "$STORAGE_ID/blobServices/default/containers/source-pdfs"

# 3. An internal-only environment on your own subnet, sending logs to Log Analytics.
az containerapp env create -g rg-docassist -n env-docassist -l centralindia \
  --infrastructure-subnet-resource-id "$APPS_SUBNET_ID" --internal-only true \
  --logs-destination log-analytics --logs-workspace-id "$WORKSPACE_GUID" --logs-workspace-key "$WORKSPACE_KEY"

# 4. The app: ingress reachable only inside the network, secrets by reference, a hard ceiling on replicas.
az containerapp create -g rg-docassist -n docassist-api --environment env-docassist \
  --image acrdocassist.azurecr.io/docassist-api:3f9c2e1 \
  --registry-server acrdocassist.azurecr.io --registry-identity "$ID" --user-assigned "$ID" \
  --secrets "db-url=keyvaultref:https://kv-docassist.vault.azure.net/secrets/db-url,identityref:$ID" \
  --env-vars DATABASE_URL=secretref:db-url AZURE_CLIENT_ID="$CLIENT_ID" \
  --ingress external --target-port 8000 --cpu 1 --memory 2Gi --min-replicas 1 --max-replicas 5
```

`AZURE_CLIENT_ID`, endha user-assigned identity-a use pannanum-nu `DefaultAzureCredential`-kku sollum; adhu illana token requests fail aagalaam. Compute selavukku unmaiyaana cap `--max-replicas` thaan.

### Logs, metrics, cost

Container Apps console logs-a oru Log Analytics workspace-kku anuppum. Request times, errors-kku Application Insights serunga, error rate-kkum slow responses-kkum alert vainga. Logs ingest aagura ovvoru gigabyte-kkum bill aagum, adhanaala muzhu prompts-aiyo documents-aiyo log pannaadheenga: adhu kaasu selavu, sensitive data-vaiyum copy pannum.

Oru AI app-oda bill-la podhuvaa model tokens thaan munnaadi, appuram database, compute, logs, cloud-a vittu veliya pora data. Bill-a pirikka mudiyura maadhiri ovvoru resource-kkum project, environment tag podunga. Mudhal naalae alerts-oda oru budget set pannunga:

```bash
az consumption budget create-with-rg -g rg-docassist -n docassist-pilot \
  --amount 125000 --category Cost --time-grain Monthly --time-period start-date=2026-12-01 \
  --notifications "{at80:{enabled:true,operator:GreaterThan,threshold:80,contact-emails:[cloud-alerts@example.com]}}"
```

Start date oru maasathoda mudhal thedhiyaa irukkanum, moonu maasathukku mela munnaadi irukkakoodaadhu. Amount subscription-oda billing currency-la irukkum. Oru budget alert mattum thaan pannum: adhu edhaiyum niruthaadhu, cost data sila mani neram thaamadhamaa varalaam. Alerts-a oru shared mailbox illa channel-kku anuppunga, oruthar-kku illa.

## Oru worked example

Azure-la irukkura oru Hyderabad pharma company, avanga regulatory team-kku oru document assistant venum-nu kekkuraanga. Requirements: data India-laye store-um process-um aaganum, public database koodaadhu, company accounts vachu sign-in, oru naalaikku sumaar 1,500 kelvigaloda oru pilot.

**1. Region.** Hyderabad-la irukkura India South Central thaan pakkathula, aanaa adhu August 2026-la thaan thirandhuchu, Microsoft konjam konjamaa services serthuttu irukku. Design-kku thevaiyaana ellaamae Central India-la irukku-nu products-by-region page kaattudhu-nu vachukkonga: neenga adha select panni, Hyderabad-a pinnaadikku note panni vaikkureenga.

**2. Model.** Team-oda mudhal choice model India-la Global Standard-aa mattum thaan kidaikkudhu-nu vachukkonga. Adhu processing rule-a fail pannudhu. Innoru model Central India-la regional Standard-aa kidaikkudhu, team-oda 40 test questions-layum pass aagudhu-nu vachukkonga: neenga adha deploy panreenga. Adhoda tokens-per-minute quota-va adhae naalla request panreenga.

**3. Network, identity.** Design diagram-a follow pannudhu: company-oda Application Gateway-kku pinnaadi oru internal Container Apps environment; Blob Storage, Key Vault, Foundry ellaam avangaloda DNS zones-oda private endpoints vazhiyaa; PostgreSQL private access-oda. Orae oru user-assigned identity, munnaadi sonna naalu roles-aiyum vachirukku, ovvonnum miga kurugiya scope-la.

**4. Cost.** Build panradhukku munnaadi estimate pannunga. Keezha irukkura ovvoru price-um vilakkathukkaaga vachukkitta oru figure, quote illa; neenga check panra naalla unga region-kku Azure pricing calculator kaattura number-a vachu ovvonnaiyum maathunga. Idha indha page-laye run pannalaam.

```python
# Illustrative prices only. Replace each with the Azure pricing calculator's figure.
replica_rupees_per_hour = 8           # suppose: one replica, 1 vCPU and 2 GiB
replica_hours = (2 * 12 + 1 * 12) * 30  # 2 replicas by day, 1 at night
fixed = {"PostgreSQL": 12_000, "Blob, Key Vault, private endpoints": 3_000,
         "Log Analytics": 4_000, "Data transfer out": 500}

questions = 1_500 * 30                 # per month
input_tokens, output_tokens = 4_000, 500  # per question, with retrieved chunks
rupees_per_m_in, rupees_per_m_out = 250, 1_000  # suppose

compute = replica_rupees_per_hour * replica_hours
infra = compute + sum(fixed.values())
tokens = questions * (input_tokens * rupees_per_m_in + output_tokens * rupees_per_m_out) / 1e6
print(f"compute ₹{compute:,}  infrastructure ₹{infra:,}  tokens ₹{tokens:,.0f}")
print(f"total ₹{infra + tokens:,.0f} a month, ₹{(infra + tokens) / questions:.2f} per question")
```

Idhu infrastructure ₹28,140, tokens ₹67,500-nu print pannum: maasathukku ₹95,640, adhaavadhu oru kelvikku ₹2.13. Mothha infrastructure-a vida tokens-kku thaan adhiga selavu, adhanaala mudhalla adha optimise pannunga.

| Vari (vilakkathukku) | Maasathukku | Adha edhu theermaanikkudhu | Eppadi kuraikkalaam |
| --- | --- | --- | --- |
| Model tokens | ₹67,500 | Kelvigal × oru kelvikkaana tokens | Kammiyaana, chinna retrieved chunks; repeat aagura answers-a cache pannunga |
| PostgreSQL | ₹12,000 | Server size, storage | Chinnadhaa aarambinga; alandha load padi resize pannunga |
| Container Apps | ₹8,640 | Replica-hours | Iravula oru replica; dev-kku zero-kku scale pannunga |
| Log Analytics | ₹4,000 | Ingest aagura logs-oda gigabytes | Prompts illa, metadata-va log pannunga |
| Blob, Key Vault, endpoints | ₹3,000 | Store panna data, mani nerathukku endpoints | Pazhaiya versions-a archive pannunga |
| Data transfer out | ₹500 | Azure-a vittu veliya pora data | Traffic-a region-kkullaye vachukkonga |

Client-kku rupees-la bill aagudhu, adhanaala budget maasathukku 1,25,000; appo adhoda 80% alert, ₹95,640 estimate-kku konjam mela varum. `--max-replicas 5`-um, oru user-kku mani nerathukku 60 kelvigal-ngra limit-um, budget email varradhukku romba munnaadiyae kattuppaadu illaama odura oru loop-a cap pannidum.

**5. Review.** Cloud teams podhuvaa veli designs-a public endpoints, stored keys, velinaattu regions, thelivillaadha model processing-kkaaga reject pannuvaanga. Indha design naalaiyum thavirkkudhu, avanga aerkanavae run panra services-a use pannudhu, diagram-odayum region, deployment type pathina oru page note-odayum varudhu. Avanga panra orae maatram avanga naming convention thaan.

## Podhuvaa panra thappugal

- **Moonu clouds-a melottamaa kathukkuradhu.** Onna ozhungaa kathukkonga, appuram translate pannunga.
- **Model residency-kku resource-oda region-a namburadhu.** Global, Data Zone deployments prompts-a India-kku veliya process pannalaam. Deployment type-a check pannunga.
- **Public databases, storage.** Private access, private endpoints use pannunga, public network access-a off pannunga.
- **Private DNS zone illaadha private endpoint.** Name moodina public address-kku resolve aagum, ovvoru call-um fail aagum.
- **Code illa settings-la keys.** Portal-la irundhu copy panna storage account keys-um idhula adangum. Managed identities, Key Vault references use pannunga, shared-key access-a off pannunga.
- **Data role-kku badhilaa Owner illa Contributor**, illana "velai seiyattum"-nu subscription scope-la roles kudukkuradhu.
- **Budget-a oru cap-aa ninaikkuradhu.** Adhu alert mattum thaan pannum. `--max-replicas`-um rate limits-um set pannunga.
- **Compute-a kanakku panni, tokens-aiyum logs-aiyum vidradhu**; AI apps-la perumbaalum adhu thaan periya varigal.
- **Launch week-la quota request panradhu.** Increases udanae kidaikkaadhu.
- **Tag pannaadha resources**, adhanaala endha project-kku evvalavu cost-nu yaaraalayum solla mudiyaadhu.

## Kammiyaana cloud podhum-ngradhu eppo

- **Oru prototype illa demo**: Vercel, Render, Railway maadhiri oru platform-um oru hosted database-um vegamaanadhu. Unmaiyaana data varumbodhu move pannunga.
- **Client ellaathaiyum on-premises-la run panraanga**: adhukku badhilaa avanga platform-a kathukkonga.
- **Sensitive data illaadha oru chinna internal tool**: built-in sign-in-oda oru Container App podhumaa irukkalaam; muzhu private network overkill.

## Demo-la irundhu production-kku

- **Ellaamae code-aa.** Repository-la Bicep illa Terraform, pull requests-la review aaganum; production-la manual portal changes koodaadhu.
- **Thanithani environments.** Dev, prod-kku vera vera resource groups illa subscriptions, ovvonnukkum thani budget.
- **Policy moolamaa guardrails.** Indian regions-a mattum anumadhikkura oru Azure Policy, yaaraavadhu thappu pannaalum residency-a enforce pannum; innoru policy public network access-a deny pannalaam.
- **Resilience.** Region-la zone redundancy irundhaa use pannunga, oru database restore-a test pannunga, client-kku thevaina disaster recovery-kku rendaavadhu Indian region-a select pannunga.
- **Makkal act panra alerts.** Error rate, slow responses, oru naalaikku token use, quota use; oru named owner irukkura shared channel-kku anuppunga.
- **Oru design record.** Region, deployment type, network boundaries, identities, ovvonnukkumaana kaaranathoda, client-oda review-kku ready-aa.
