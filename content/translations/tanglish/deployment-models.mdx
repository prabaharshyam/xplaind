## Idhu enna

Oru **deployment model** rendu kelvigalukku badhil solludhu: model-um application-um enga odudhu, adha yaaru control panraanga? Mukkiya options, kammi control-la irundhu adhigam control varaikkum:

1. **Vendor API (multi-tenant SaaS)**: model provider-oda public endpoint-a neenga call panreenga. Aarambikka vegam, pudhu models, kammi control.
2. **Client-oda cloud vazhiyaa model**: client-oda sondha cloud account-layum region-layum (Amazon Bedrock, Azure AI Foundry, Google Vertex AI), avangaloda already irukkura cloud contract-kku kezha, adhe illa ottha models-a tharuvaanga.
3. **Dedicated illa private capacity**: reserved capacity illa oru private endpoint, sila neram private networking-oda, adhanaala traffic public internet-a thaandaadhu.
4. **Client-oda cloud-la self-hosted open-weight models**: Llama, Qwen, Mistral, Gemma variants maadhiri models-a avangaloda account-la GPU machines-la neenga odureenga.
5. **On-premises**: adhe, client-oda sondha data centre-la.
6. **Air-gapped**: veliya networks-oda connection-e illa. Models, code, updates oru controlled transfer-la varum.

Application-um (API, retrieval, database) model-a vittu thaniyaa, adhe choices-a follow pannalaam.

```flow
dir: LR
title: Kammi control-um vegamaana aarambamum-la irundhu, adhigam control-um adhigam velaiyum varaikkum
Vendor API | vaarangal -> Client's cloud | approve panna tenancy-um region-um
Client's cloud -> Dedicated | private network
Dedicated -> Self-hosted | avangaloda GPUs, neenga operate pannureenga
Self-hosted -> On-prem | avangaloda data centre
On-prem -> Air-gapped | network illa, transfers mattum
```

App-um, retrieval-um, logs-um model-a vida vera rung-la irukkalaam.

Indha lesson, Bengaluru, Mumbai, Hyderabad-la irukkura moonu clients-a follow pannum, ovvoruthar-kum vera deployment thevai pattadhu.

## Idhu eppadi work aagudhu

**Choice-a mudivu panradhu edhu.**

- *Data rules*: data enga pogalaam-nu regulation, contracts, internal policy. Indian regulators-um neraya enterprises-um data India-laye irukkanum-nu solluvaanga; sila data premises-a vittu veliya povae koodaadhu.
- *Thevaiyaana model quality*: romba strong models perumbaalum APIs-aa illa cloud partners vazhiyaa mattum kidaikkum. Open-weight models neraya tasks-ku romba pinnaadi illa, extraction, classification, nalla scope panna documents mela RAG-ku nallaa irukkum.
- *Cost, volume*: APIs token-ku charge pannum; self-hosting-ku periya fixed GPU cost irukku, adhu adhigam, steady volume-la mattum payan tharum.
- *Skills*: self-hosting-ku GPUs, serving engines, monitoring, upgrades odura aalgal thevai.
- *Latency, availability*: on-premises network delay-a kuraikkalaam, aana uptime-a client-oda team mela vechudum.

**Mudhalle kekka vendiya kelvigal.** Data enga process aagalaam? Edhaavadhu provider already approve aagi irukkaa? Ippovae oru cloud contract irukkaa? Handover-ku aprom system-a yaaru operate pannuvaanga? Model-a upgrade panna vendiya podhu enna aagum?

**Hybrid common.** Sensitive requests-a self-hosted model-ku, matha-vai API-ku anuppunga; illa embeddings-ku self-hosted model-um generation-ku cloud model-um use pannunga.

**Air-gapped sila vishayangal.** Package downloads illa, model downloads illa, SaaS monitoring illa, internet-la licence checks illa. Ellaam (container images, model weights, Python packages) bundle panni, scan panni, transfer aagum. Updates-a scheduled releases-aa plan pannunga.

**Options-a score panradhu:**

| Factor | Vendor API | Client's cloud | Self-hosted | Air-gapped |
| --- | --- | --- | --- | --- |
| Data control | Romba kammi | Adhigam, avangaloda tenancy-la | Romba adhigam | Muzhusaa |
| Model quality | Romba strong | Strong | Nalla open-weight | Nalla open-weight |
| Kammi volume-la cost | Romba kammi | Kammi | Adhigam: idle GPUs | Romba adhigam |
| Launch panna neram | Naatkal mudhal vaarangal | Vaarangal | Maadhangal | Maadhangal |
| Thevaiyaana skills | Konjam | Cloud skills | GPU serving, monitoring | Adhellaam, offline-la |

**Mudhal meeting kelvigal.** Indha data enga process aagalaam, edhaavadhu provider already approve aagi irukkaa? Ippo irukkura oru cloud contract-um region-um irukkaa? Entha data, irundhaa, premises-a vittu povae koodaadhu? Handover-ku aprom system-a yaaru odavaanga, avangalukku GPU skills irukkaa? Model-a evvalavu adikkadi upgrade pannanum, adha yaaru approve pannuvaanga? Badhilgal perumbaalum aaru options-a oru manikkulla onnu illa rendu-aa kuraikkum.

**Offline sites-ku bill of materials.** Oru air-gapped build-ku, ovvoru artefact-aiyum list pannunga: pin panna versions-oda container images, checksums-oda model weights, Python, system packages, vector database, offline-la velai seira monitoring tools, documentation. Client-oda security team avai-a scan panni transfer pannum. Oru package miss aanaa oru release vaarakkanakkula late aagalaam, adhanaala mudhalla disconnected test machine-la install-a rehearse pannunga.

**API illa self-hosted, numbers-la.** Real quotes vechu neenga thirumba pannalaam oru mudhal comparison (ovvoru price-oda date-aiyum record pannunga):

```python
def monthly_costs(tokens_in_m, tokens_out_m, api_in_usd, api_out_usd,
                  gpu_hour_inr, gpus, hours=730, ops_people=0.5, ops_cost_inr=250_000, usd_to_inr=84):
    """tokens in millions per month; API prices in USD per million tokens."""
    api = (tokens_in_m * api_in_usd + tokens_out_m * api_out_usd) * usd_to_inr
    self_host = gpu_hour_inr * gpus * hours + ops_people * ops_cost_inr
    return {"API ₹/month": round(api), "self-hosted ₹/month": round(self_host),
            "cheaper": "API" if api < self_host else "self-hosted"}

print(monthly_costs(tokens_in_m=900, tokens_out_m=120, api_in_usd=0.8, api_out_usd=4,
                    gpu_hour_inr=250, gpus=2))
```

GPUs use aanaalum aagaatthaalum ovvoru manikkum selavu pannum, adhanaala self-hosting adhigam, steady volume-la illa data rules vera vazhi vidaadha podhu mattum jeyikkum. Aalgalaiyum serunga: yaaraavadhu serving stack-a patch panni, monitor panni, upgrade pannanum.

**Sensitivity vechu route pannunga.** Oru hybrid design-la, ovvoru request-um enga pogum-nu oru chinna rule mudivu pannum:

```python
SENSITIVE_FIELDS = {"aadhaar", "pan", "medical_history", "bank_account"}

def route(request):
    if request.get("classification") == "restricted" or SENSITIVE_FIELDS & set(request.get("fields", [])):
        return "self_hosted"            # stays on the client's servers
    return "cloud_model"                # stronger model, client's cloud region
```

Rule-a client-oda data owner-oda serndhu ezhudhunga, ovvoru data class-la irundhum examples-oda test pannunga, ovvoru request-kum route-a log pannunga.

**Oru air-gapped bundle build panradhu.** Connected build machine-la, ellaathaiyum versions-oda checksums-oda serthu, client approve panna process vazhiyaa transfer pannunga:

```bash
mkdir -p bundle/{images,models,wheels}
docker pull vllm/vllm-openai:v0.10.1 && docker save vllm/vllm-openai:v0.10.1 | gzip > bundle/images/vllm.tar.gz
docker save claims-api:1.4.0 | gzip > bundle/images/claims-api.tar.gz
huggingface-cli download org/model-8b-instruct --revision <commit> --local-dir bundle/models/model-8b
pip download -r requirements.txt -d bundle/wheels
(cd bundle && find . -type f -exec sha256sum {} \; > SHA256SUMS)
```

Offline pakkathula, `sha256sum -c SHA256SUMS` transit-la onnum maaralanu prove pannum, `docker load` images-a restore pannum, `pip install --no-index --find-links wheels -r requirements.txt` internet illaama install pannum. Unmaiyaana visit-ku munnaadi, networking disable panna machine-la muzhu install-a rehearse pannunga.

**Aarambathulayae upgrades-a plan pannunga.** Ovvoru option-kum pudhu model versions-ku oru vazhi thevai: oru API thaanaa maarum (pin panni test pannunga), client-oda cloud thanoda schedule-la models-a serkkum, self-hosted illa offline setups-ku thirumba seiyakkoodiya bundle-and-test process thevai.

## Oru worked example

Moonu clients, moonu badhilgal:

- *Bengaluru D2C brand*: customer-support assistant, public-facing data mattum, chinna team. Oru gateway vazhiyaa **vendor API**, kidaikkura idathula Indian region. Moonu vaarathula live.
- *Mumbai private bank*: confidential documents-oda internal policy assistant. Bank-oda risk team, Central India-la irukkura avangaloda Azure tenancy-a already approve pannirukkaanga. Private networking-oda, bank-oda keys-oda **client-oda cloud vazhiyaa models**. Pudhusa edhuvum approve panna vendiyadhu illaadhaala, approval aaru maadhathuku badhila naalu vaaram aachu.
- *Hyderabad defence electronics supplier*: classified network-la engineering-document search. **Air-gapped self-hosting**: rendu on-premises GPU servers-la vLLM-oda serve panna oru open-weight model, adhe network-la embeddings-um vector database-um, client-oda security team scan panni transfer panra images-um weights-um adangina oru quarterly update package. Model frontier APIs-a vida kammi capable, adhanaala scope-a retrieval, summarisation-ku narrow pannaanga, evals adhu nalla perform pannum-nu kaattura idam.

| Client | Deployment | Yen | Outcome |
| --- | --- | --- | --- |
| Bengaluru D2C brand | Gateway vazhiyaa vendor API | Public data, chinna team | Moonu vaarathula live |
| Mumbai private bank | Avangaloda approve panna Azure tenancy-la models | Confidential documents, ippo irukkura approval | Naalu vaarathula approve aachu |
| Hyderabad defence supplier | Local GPUs-la air-gapped vLLM | Classified network | Scope retrieval, summaries-ku narrow aachu |

## Podhuvaa panra thappugal

- **Data rules pathi kekkaama oru public API-a propose panradhu.** Vaarangal-aiyum nambikkaiyaiyum izhappeenga.
- **Self-hosting cheap-nu ninaikkradhu.** Kammi volume-la, idle GPUs tokens-a vida romba adhigam selavaagum.
- **Yaaru operate pannuvaanga-nu ignore panradhu.** Client-la yaarumae upgrade panna mudiyaadha oru self-hosted model oru liability aagidum.
- **"Open-weight"-a "licence terms illa"-nu eduthukkuradhu.** Ovvoru model-oda licence-a commercial use limits-ku padinga.
- **Matha stack-a marakkuradhu.** Traces, logs, vector stores model maadhiri adhe rules-a follow pannanum.
- **Idle hours-aiyum adha odura aalgalaiyum ennaama, GPU cost-a API cost-oda compare panradhu.**
- **Offline-la rehearse pannaadha air-gapped installs,** mudhal miss aana package-la fail aagum.
- **Self-hosted illa offline setups-la models-ku upgrade path illa.**

## Choice simple-aa irukkura neramgal

- **Kammi illa theriyaadha volume, strict data rules illa**: oru API illa client-oda cloud model service-oda aarambinga.
- **Data premises-a vittu povae koodaadhu**: self-hosted illa air-gapped, cost enna aanaalum.
- **Value-va prove panna oru pilot**: allow panna vegamaana option-a use pannunga, scale panna munnaadi thirumba paarunga.

## Demo-la irundhu production-ku

- **Data rules-aiyum mudivaiyum** dates-oda, othukkitta aalgaloda record pannunga.
- Mudhal sila maadham aprom, real volumes-oda **cost comparison-a thirumba pannunga**.
- Hybrid setups-la ovvoru request-kum **route-a log pannunga**.
- Offline, self-hosted upgrades-ku **test panna bundle process-a** vechirunga.
- Entha option-a select pannaalum, **model versions-a pin panni test pannunga**.
