## Idhu enna

LLM apps, vazhakkamaana web security concerns-oda sila pudhusaana ondrayum serthu kondu varudhu. LLM applications-ku OWASP Top 10 romba use pannura oru checklist. Perumbaalaana apps-ku, indha areas thaan mukkiyam:

- **Secrets**: API keys, credentials.
- **User data**: models-ku anuppura, logs-la store aagura, answers-la veliya theriyura personal information.
- **Access**: yaar app-a use pannalaam, ovvoru user-um enna paarkkalaam.
- **Model-specific risks**: prompt injection, system prompt leak, excessive agency, model output-a insecure-aa handle panradhu.

| | Munnaadi | Pinnaadi |
|---|---|---|
| API key | Browser-oda JavaScript-la, neraa model-kku anuppappadum | Backend-la mattum, secrets-la irundhu |
| Prompt | "admin password: ..." | Secrets illa |
| Customer data | Muzhu record model-kku pogum | Tool order id, status, date mattum tharum |
| Customer id | Browser-la irundhu edukkum | Verified session-la irundhu edukkum |
| Reply | Raw HTML-aa serkkappadum | Text-aa render aagum |
| Logs | Phone numbers-oda muzhu chats | Mask panni, 30 naal vachchirukkum |

## Idhu eppadi work aagudhu

**Keys-a server-la vainga.** Model API key server-side environment variables-la illa secret manager-la irukkum. Browser JavaScript, mobile apps, Git-la oru pothum podaadhinga. Browser ungaloda backend-a call pannum; backend model-a call pannum. Key leak aanaa, udanae revoke pannunga.

**Prompts-la secrets vendaam.** Users system prompt-a eduthukkalaam-nu nenachchukkunga. Passwords, keys, kaattuvadhu virumbaadha internal-only information-a serkkaadhinga.

**Task-ku thevaiyaanadha mattum anuppunga.** "En order enga?"-nu pathil solra support bot-ku order status thevai, customer-oda muzhu profile, payment details, address history illa. Data minimisation edhaavadhu leak aanaa paadhippa kuraikkum, India-oda DPDP Act-oda oru principle-um.

**Personal data-va mask pannunga** logs-layum traces-layum, retention periods vainga, access-a restrict pannunga.

**Authenticate, authorise pannunga.** Users sign in pannuvaanga; ovvoru request-um yaar-nu check pannum; retrieval-um tools-um andha user-oda data-va mattum access pannum. Browser-la irundhu varra user id-a verify pannaama oru pothum nambaadhinga.

**Model output-a untrusted-aa edunga.** Adhai neraa HTML (cross-site scripting), SQL, shell commands-la serkkaadhinga. Edhaavadhu user input maadhiri escape illa validate pannunga.

**Capabilities-a limit pannunga.** Thevaiyaana kuraivaana permissions-oda tools; risky actions-ku approvals; ovvoru user-kkum rate limits.

**Vendor terms.** Ungaloda model provider data-va eppadi store pannudhu, use pannudhu-nu check pannunga, ungaloda users-um clients-um thevaikalukku porundhura settings-um regions-um select pannunga.

**Checklist-a odunga.** Ungaloda app-ku LLM applications-ku OWASP Top 10-a odi, ovvoru item-kum ungaloda defence-a note pannunga.

**Perumbaalaana LLM apps-ku checklist items:**

| Area | Kelvi | Nalla badhil |
| --- | --- | --- |
| Keys | Key browser-la illa Git history-la theriyuma? | Illa; server-side, veliya vandhaa rotate |
| Prompts | System prompt-la edhaavadhu secret irukka? | Illa |
| Data | Ovvoru feature-kkum model-kku enna pogudhu? | Task-ku thevaiyaana fields mattum |
| Identity | User id enga irundhu varudhu? | Verified session-la irundhu |
| Output | Model output eppadi kaattappadudhu, use aagudhu? | Escaped text; entha query, command-kkum munnaadi validate |
| Logs | Enna personal data log aagudhu, evvalavu naal? | Masked; fixed retention; restricted access |
| Tools | Model enna trigger panna mudiyum? | Least privilege; risky actions-ku approval |
| Vendor | Provider data-va eppadi use panni, vachchirukkaanga? | Terms check panna; porundhura region-um settings-um |

**Varradhum pogradhum guardrails.** Oru **input guardrail**, model-kku pogapogura data-va check pannum: personal data, company secrets, attack-oda signs. Oru **output guardrail**, yaarum paarkkaradhukku munnaadi illa code act pannuradhukku munnaadi, thirumba varradhai check pannum: personal data, unsafe content, malformed output, nadakka koodaadha tool call. Oru guardrail fire aanaa, block, mask, retry, illa oru aal-kitta handover pannalaam. Rendu trade-offs: ovvoru check-um delay-a serkkum, streaming-la output checks kashtam, yen-na muzhu reply-a check panna munnaadiyae vaarththaigal user-ku poidum. Streamed chat-ku, chunks-la check pannunga, kadumaiyaana checks-a vaarththaigalukku illa, actions-ku vachchukkunga.

**Leaks perumbaalum nalla ennathula aarambikkum.** 2023-la, Samsung engineers internal source code-a oru public chatbot-la ottitaanga, adhula help vaanga. Apps-layum adhe nadakkum: oru developer internal policy-a system prompt-la paste pannuvaanga, illa oru tool oru muzhu database row-va context-kku izhukkum. Ovvoru feature-kkum kelunga: "enna ungaloda servers-a vittu pogudhu, adhu thevaiyaa?"

**Mask, call, unmask.** Neraya tasks-ku model-ku nijamaana identifiers thevai illa. Call-ku munnaadi avai-a placeholders-aa maathunga, ungaloda server-la oru map vachchukkunga, apram nijamaana values-a thirumba podunga:

```python
import re

PATTERNS = {
    "PAN": r"\b[A-Z]{5}[0-9]{4}[A-Z]\b",
    "AADHAAR": r"\b[2-9][0-9]{3}\s?[0-9]{4}\s?[0-9]{4}\b",
    "PHONE": r"(?<!\d)(?:\+91[\s-]?)?[6-9][0-9]{9}(?!\d)",
    "EMAIL": r"\b[\w.+-]+@[\w-]+\.[\w.-]+\b",
    "UPI": r"\b[\w.-]+@(?:ok\w+|ybl|paytm|upi|ibl|axl)\b",
}

def mask(text):
    mapping, count = {}, {}
    for label in ["UPI", "EMAIL", "PAN", "AADHAAR", "PHONE"]:     # UPI first: UPI ids look like emails
        def swap(m, label=label):
            count[label] = count.get(label, 0) + 1
            key = f"[{label}_{count[label]}]"
            mapping[key] = m.group(0)
            return key
        text = re.sub(PATTERNS[label], swap, text)
    return text, mapping

def unmask(text, mapping):
    for key, value in mapping.items():
        text = text.replace(key, value)
    return text

safe, keys = mask("My PAN is ABCDE1234F and mobile 9876543210, UPI ravi@okaxis.")
print(safe)    # My PAN is [PAN_1] and mobile [PHONE_1], UPI [UPI_1].
```

Indha maadhiri patterns sila forms-a miss pannum, sila innocent numbers-a pidikkum, adhanaala real (masked) samples-la test pannunga, stakes adhigam irundhaa Microsoft Presidio maadhiri dedicated detection tool-a use pannunga. Masking-ku limits-um irukku: model paarkkaadha PAN-a check panna mudiyaadhu, adhanaala andha tasks-ku check ungaloda sondha code-la irukkanum.

**Retrieval permissions-a madhikkanum.** Oru RAG app-la, search index perumbaalum neraya users-oda illa departments-oda documents-a vachchirukkum. Edhuvum prompt-kku pogaradhukku **munnaadi**, sign in panna user padikka mudiyuradhai vachchu results-a filter pannunga; kaattappatta secret-a model-aala kaakka mudiyaadhu.

**Bill-aiyum kattuppaduthunga.** Limit illaadha requests, oru user, oru script illa oru attacker-a selavai ethukka, illa ellaarukkum app-a slow aakka vidum. Per-user rate limits, input length-ku oru cap, daily budget alert vainga.

**LLM applications-ku OWASP Top 10 (2025), ovvonnukkum oru defence:**

| Risk | Oru defence |
| --- | --- |
| Prompt injection | Retrieve panna, user text-a data-aa edunga; tools enna seiyalaam-nu limit pannunga |
| Sensitive information disclosure | Data minimisation, masking, output checks |
| Supply chain | Packages-a pin panni scan pannunga; nambikkaiyaana sources-la irundhu models, datasets |
| Data and model poisoning | Training, retrieval data sources-a review panni track pannunga |
| Improper output handling | Output-a escape pannunga; SQL, shell, HTML-kku munnaadi validate |
| Excessive agency | Least-privilege tools; actions-ku approval |
| System prompt leakage | Prompts-la secrets, access rules vendaam; code-la enforce pannunga |
| Vector and embedding weaknesses | Retrieval-la permission filters; tenant-ku thani indexes |
| Misinformation | Grounding, citations, "theriyala"-nu solradhu |
| Unbounded consumption | Rate limits, input caps, budgets |

**Indian sattam, sutrukkamaa.** Digital Personal Data Protection Act, 2023-um adhoda Rules-um, phases-la amalukku varum, India-la irukkura makkal-oda digital personal data-kku porundhum. Nadaimuraila: neenga collect panradhukku oru clear notice-um consent-um, solla pattu use pannunga, thevaiyaana varaikkum mattum vachchukkunga, reasonable security-oda paadhukaakkunga, makkal avangaloda data-va access panna, azhikka vidunga, breaches-a report pannunga. Kuzhandhaigal data-kku verifiable parental consent thevai. Idhu oru summary, legal advice illa; ungaloda case-ku current rules-a check pannunga.

**Git history-la secrets-a check panradhu.** Code-la irundhu oru key-a delete pannaa, history-la irundhu poga maattaadhu. Muzhu repository history mela oru secret scanner-a odunga, adhu kandupidikkura edhaiyum rotate pannunga, pudhu secrets push aaga munnaadiyae pidikka scanner-a CI-la serkkunga.

**Users-ukku naduvula access-a test panradhu.** Rendu test accounts-a uruvaakki, mudhaladhaa irundhu, requests-la ids-a maathi, bot-kitta neraa kettu, rendavadhu-oda orders-a padikka try pannunga. Rendum fail aaganum. Idhai automated tests-aa vachchukkunga.

## Oru worked example

Bengaluru-la oru D2C brand support bot build pannudhu. Mudhal version-oda security review kandupidikkiradhu:

- API key React front end-la irundhadhu, browser-oda developer tools-la theriyum. Fix: calls backend-ku maarudhu; key rotate aagudhu.
- System prompt-la admin dashboard password "reference-kaaga" irundhadhu. Remove panni rotate pannaanga.
- Order kelvigalukku badhil sollavendi, bot customer-oda muzhu record-a (address, phone, past orders, saved payment method) prompt-kku fetch pannichu. Fix: oru tool order id, status, expected date mattum tharum.
- Customer id browser request-la oru field-la irundhu vandhadhu. Fix: verified session-la irundhu edukkappadudhu.
- Bot replies raw HTML-aa serkkappatta; oru crafted message oru script-a inject pannalaam. Fix: replies text-aa render aagum.
- Logs phone numbers-oda muzhu conversations-a store pannichu. Fix: masking-um 30 naal retention-um.

| Kandupidippu | Fix |
| --- | --- |
| React front end-la API key | Calls backend-ku maathi, key rotate |
| System prompt-la admin password | Remove panni rotate |
| Prompt-la muzhu customer record | Tool order id, status, date mattum tharum |
| Browser-la irundhu customer id | Verified session-la irundhu |
| Replies raw HTML-aa | Text-aa render |
| Logs-la phone numbers-oda muzhu chats | Masked, 30 naal retention |

## Podhuvaa panra thappugal

- **Front-end code-la illa Git-la API keys.**
- **System prompts-la secrets.**
- **Muzhu customer records-a model-kku anuppradhu.**
- **Browser-la irundhu varra user ids-a nambradhu.**
- **Model output-a raw HTML-aa render panradhu.**
- **Permission filters illaadha retrieval.** User oru pothum paarkka koodaadha document-a model sandhoshama quote pannum.
- **Access rules prompt-la mattum ezhudhuradhu.** Prompt-la "matha customers-oda orders-a oru pothum kaattaadhe" oru nambikkai; code-la irukkura check oru control.
- **Use-ku limits illaama.** Oru script bill-a ethakkalaam illa ellaarukkum app-a slow aakkalaam.

## Risk kammiyaa irukkum neram

- **Ungaloda sondha laptop-la oru personal tool**, ungaloda sondha data-oda, key Git-la irundhu veliya irukkanum, aana masking illa audit logs thevai illa.
- **Public data mattum**, published government circulars mela oru bot maadhiri: output handling, injection, cost limits-la focus pannunga.
- **Sinna nambikkaiyaana team-ku read-only internal tools**: key-a safe-aa vachchukkunga, tools reach panra idhathai limit pannunga, aana muzhu guardrail stacks kaaththirukkalaam.

Personal data, panam, write actions, neraya users, banking, insurance, health maadhiri regulated sectors irundhaa, risk vegamaa yerum.

## Demo-la irundhu production varaikkum

- **Data map ezhudhunga**: ovvoru feature-kkum, enna personal data use aagudhu, enga pogudhu, evvalavu kaalam vachchirukkum.
- **Ungaloda model provider-oda data processing agreement-ku sign pannunga**, porundhura retention, region settings-a select pannunga.
- **Checks-a automate pannunga**: CI-la secret scanner, rendu-account access tests, injection tests, output-escaping tests.
- **Keys-a oru schedule-la rotate pannunga**, access irundha yaaravadhu pogum podhu udanae.
- **Incidents-ku plan pannunga**: yaar mudivu pannuvaanga, keys-a eppadi revoke panradhu, paadhikkapatta users-kkum regulator-kkum eppadi, evvalavu vegamaa solradhu.
- **Access-a review pannunga** konjam maadhangalukku oru thadava: logs, index, admin tools-a yaar padikkalaam.
