## Idhu enna

Ella automation-um ennaikkaavadhu fail aagum. Oru API down aagum, oru token expire aagum, oru customer than phone number-a thappaa type pannuvaanga, evvalavu vegamaa anuppalaam-nu oru provider limit vaippaanga. Fail **aagumaa**-ngradhu kelvi illa, **eppadi** fail aagudhu-ngradhu thaan. Nallaa build panna automation paadhugaappaa fail aagum: edhuvum tholaiyaadhu, edhuvum rendu thadavai nadakkaadhu, enna pannanum-nu sariyaana aalukku theriyum.

**Error handling**-na oru step fail aagumbodhu, allathu oru step "success" aanaalum thappaana edho onnai return pannumbodhu, automation panra ellaame:

| Velai | Adhoda artham |
| --- | --- |
| **Retry** | Temporary-aa irukka vaaippulla errors-a marupadiyum try panradhu, medhuvaa, kurippitta thadavaigal mattum |
| **Stop** | Thaanaa sariyaagaadha errors-a thirumbath thirumba try pannaama irukkiradhu; avatrai record panradhu |
| **Alert** | Oru aalukku, oru thadavai, act panna podhumaana details-oda solradhu |
| **Recover** | Kaaranam sariyaanadhum, edhaiyum rendu thadavai pannaama, paadhugaappaa marupadiyum process panradhu |
| **Record** | Review-kkum reruns-kkum, ovvoru item-kkum enna nadandhadhu-nnu oru history vachirukkiradhu |

Indha anju velaigalukkum keezha rendu ideas irukku. Mudhalla, sariyaana response **retry pannaa enna maarum**-ngradhai poruthadhu: busy-aa irukkura server adutha thadavai badhil sollalaam, thappaana phone number eppavume sariyaagaadhu. Rendaavadhu, "send" allathu "pay"-kkaana oru call fail aanaa, edhuvume anuppappadalai allathu pay aagalai-nnu eppavum artham illa. Perumbaalaana nija duplicates adhai marakkiradhaala thaan varudhu.

Indha lesson, Bengaluru-la oru logistics startup-a follow pannudhu; avanga delivery updates rendu thadavai pochu, rate limits-la maattichu, oru thadavai oru naal muzhukka ninnupochu. Example tool n8n.

## Idhu eppadi work aagudhu

### Retry pannaa enna maarum-nu vachu error-a vagaippaduthunga

```flow
Oru error varudhu -> Step data-va padikka mattum senjudhaa?
Step data-va padikka mattum senjudhaa? -[aamaa]-> Temporary error-aa? | timeout, 429, 500 mudhal 504
Step data-va padikka mattum senjudhaa? -[illai]-> Outcome theriyalaiyaa? | send, pay allathu create-la timeout allathu 500 mudhal 504
Outcome theriyalaiyaa? -[aamaa]-> Unga key vachu status-a check pannu | appuram adhe key-oda retry pannu
Outcome theriyalaiyaa? -[illai]-> Temporary error-aa?
Temporary error-aa? -[aamaa]-> Backoff-oda retry pannu | innum fail aanaa needs attention
Temporary error-aa? -[illai]-> Oru record pathinadhaa? | 400, 404, invalid data
Oru record pathinadhaa? -[aamaa]-> Needs attention list | meedhiya thodaru
Oru record pathinadhaa? -[illai]-> Run-a niruthu | 401, 403, expire aana token; owner-kku alert pannu
```

| Vagai | Examples | Enna pannanum |
| --- | --- | --- |
| **Temporary** | Network blips, rate limits (HTTP 429), oru read-la server errors (500 mudhal 504) | Throttle pannunga, appuram backoff-oda, oru cap vachu retry pannunga |
| **Outcome theriyaadhu** | Edhaiyaavadhu send, pay allathu create panra oru step-la timeout allathu 500 mudhal 504 | Mudhalla check pannunga, appuram adhe key-oda mattum retry pannunga |
| **Permanent, oru record** | Bad input (400), illaadha oru record (404), "12345" maadhiri oru phone number | Reason-oda record pannunga, mathavatrai thodarunga |
| **Permanent, muzhu workflow** | Thappaana allathu expire aana credentials (401, 403), delete aana oru sheet | Udane niruthi owner-kku alert pannunga |
| **Logic** | Run success aagudhu, aanaa thappaa edho pannudhu, udhaaranamaa thappaa map aana oru field | Validation-um monitoring-um mattum thaan ivatrai pidikkum |

Status codes oru aarambam thaan. Rendu patterns innum adhigamaa sollum:

- **Matha records pogumbodhu, adhe record ovvoru attempt-laiyum fail aagudhu.** Appo prachanai andha record-la thaan, code 500-nu sonnaalum kooda. Sila APIs bad input-la crash aagi server error-nu report pannum. Vazhakkamaana retries-kku appuram, adhai "needs attention"-kku anuppunga.
- **Onnukku appuram onnaa, ella record-um fail aagudhu.** Appo prachanai service-la allathu unga credentials-la, records-la illa. 2,000 items-a ovvonnaa fail aaga vidaama, seekkirame niruthunga.

### Timeouts-kku thelivaana artham illa

Timeout-na neenga wait panradhai niruthitteenga-nnu artham, provider edhuvume pannalai-nnu illa. SMS poyirukkalaam, reply mattum tholainjirukkalaam. Kanmoodithanamaa retry pannaa customer-kku adhu rendu thadavai pogum. Udhaaranamaa, oru 500-aiyum idhe maadhiri eduthukkanum-nu Stripe-oda docs solludhu: panam poyirukkalaam, pogaamalum irukkalaam.

Paadhugaappaana pattern-la moonu pagudhigal irukku:

1. **Call panradhukku munnaadi attempt-a record pannunga.** Oru unique key-oda, "sending" status-oda oru send-log row ezhudhunga; appuram adhai "sent" allathu "failed"-aa update pannunga.
2. **Provider support pannaa oru idempotency key anuppunga.** Idempotency key-na request kooda neenga anuppura oru unique value, adhai vachu provider oru repeat-a adaiyaalam kandukkum. Udhaaranamaa, Stripe oru `Idempotency-Key` header-a ethukkum: adhe key-odaiyum adhe details-odaiyum retry pannaa, marupadiyum charge pannaama mudhal result-aiye return pannum. Adhoda v1 API docs adhe key-oda 24 hours-kkulla retry panna solludhu (November 2026 nilavarappadi). Unga provider-oda docs-a check pannunga; silar idhai tharuvaanga, silar thara maattaanga.
3. **Timeout aanaa, retry panradhukku munnaadi paarunga.** Provider-kitta status API irundhaa, message allathu payment irukkaa-nnu kelunga. Illai-nnaa mattum retry pannunga. Retry-kku orunaalum pudhu key generate pannaadheenga: pudhu key provider-kitta "idhu oru pudhu request"-nu sollum.

Provider-kitta idempotency key-um illa, status lookup-um illai-nnaa, ovvoru action-kkum endha thappu malivu-nnu mudivu pannunga. Rendu thadavai pona delivery update erichal thaan; rendu thadavai kudutha refund nija panam. Panam sambandhappatta edhukkum, outcome theriyaadha onnai auto-retry pannaadheenga: oru aal check panna "needs attention"-la podunga.

### Retry panradhukku munnaadi throttle pannunga

Therinja oru daily peak-la varra rate limits (HTTP 429) ketta neram illa: unga plan anumadhikkiradhai vida vegamaa anuppureenga. **Provider-oda documented limit-a vida vegamaa anuppaadheenga**, appo 429s aridhaa thaan varum; retries-a oru safety net-aa vachukkonga.

Udhaaranamaa, plan oru second-kku 10 messages anumadhikkudhu-nnu vachukkonga. Oru second gap-oda 8 messages-aa batches anuppunga: adhe account-a use panra matha workflows-kku adhu 20 percent headroom vidum. Appo 3,000 evening messages-kku sumaar 375 seconds aagum, aaru nimishathukku konjam mela. n8n-la idhai HTTP Request node-oda **Batching** option (Items per Batch, Batch Interval) vachu pannalaam, allathu oru **Loop Over Items** node-um loop-kkulla oru **Wait** node-um vachu pannalaam.

### Backoff, jitter-oda retry

Temporary errors-a sila thadavai retry pannunga, ovvoru thadavaiyum innum adhiga neram wait pannunga. Appuram **jitter** serunga, adhaavadhu ovvoru wait-laiyum oru random extra neram. Adhu illai-nnaa, 7 pm-la 500 items fail aagumbodhu, 500-um sariyaa adhe second-la retry panni, marupadiyum onnaa fail aagum.

```flow
dir: LR
Attempt 1 -[fail aagudhu]-> 5 mudhal 10 s wait -> Attempt 2 -[fail aagudhu]-> 10 mudhal 20 s wait -> Attempt 3 -[fail aagudhu]-> 20 mudhal 40 s wait -> Attempt 4 -[fail aagudhu]-> Needs attention, alert
```

Oru niyaayamaana default: ovvoru thadavaiyum wait-a double pannunga, oru random 0 mudhal 100 percent serunga, 3 mudhal 5 attempts-kku appuram niruthunga. Oru 429 kooda oru **Retry-After** header varalaam, seconds-aa allathu oru date-aa. Unga sondha number-kku badhilaa adhai use pannunga.

**n8n ungalukku enna tharudhu.** Ovvoru node-laiyum **Max Tries**, **Wait Between Tries (ms)**-oda oru **Retry On Fail** setting irukku. November 2026 nilavarappadi, Max Tries adhigapatcham 5, wait adhigapatcham 5,000 ms-nu n8n-oda docs solludhu, HTTP Request node ungalukkaaga Retry-After-a padikkaadhu. Ore oru wait setting thaan irukku, adhanaala wait valaraadhu. Oru network blip-kku adhu paravaayilla. Neelamaana, valarra waits-kku, retry-a neengale build pannunga: node-oda error output-a oru Wait node-kku route panni thirumba loop pannunga, adhu nikkiradhukku oru counter vachu.

### Idempotency: rendu thadavai run pannaalum safe

Oru step-a rendu thadavai run pannaa, oru thadavai run panna adhe effect thaan varum-naa, adhu **idempotent**. Retries-um reruns-um steps-a repeat pannum, adhanaala edhaiyaavadhu create panra ovvoru step-kkum idhu thevai.

Ovvoru action-kkum oru **unique key**-oda oru send log vachukkonga. Act panradhukku munnaadi, andha key erkanave "sent"-nu mark aagiyirukkaa-nnu check pannunga; aagiyirundhaa skip pannunga. Key-a **action edhai pathinadho adhula irundhu** thernthedunga, appo adhe real-world action-kku eppavum adhe key varum:

| Action | Nalla key | Bad key, yen |
| --- | --- | --- |
| Delivery update SMS | Order id plus status, udhaaranamaa ORD-4471 plus "out for delivery" | Run id: ovvoru rerun-kkum pudhusaa onnu varum, adhanaala edhuvume skip aagaadhu |
| Monthly fee reminder | Member id plus billing month | Member id mattum: adhu adutha maasa reminder-a block pannidum |
| Ledger-la invoice | Supplier-oda invoice number | Process panna neram: ovvoru thadavaiyum unique, adhanaala edhaiyum pidikkaadhu |

Rendu runs overlap aaga mudiyum-naa, oru check-kku appuram oru action vandhaalum race aagalaam: rendu runs-um check pannum, rendukkum edhuvum theriyaadhu, rendum anuppum. Adhe key-oda rendaavadhu row-a marukkira oru store-la (udhaaranamaa unique constraint irukkura oru database table), "sending" row-a mudhalla ezhudhinaa, andha gap moodidum.

### Thirumba varradhai validate pannunga

Green tick-na call return aachu-nnu mattum thaan artham. Response arthamulladhaa-nnu check pannunga: edhirpaartha list kaaliyaa illa, thevaiyaana fields irukku, oru "200 OK" body-la error message illa. Vazhakkamaa 8,000 rows irukkura oru export-la onnume illai-nnaa, "successfully" edhuvum pannaama irukkiradhukku badhilaa, adhai error-aa eduthu niruthunga. n8n-la, oru IF node bad responses-a oru **Stop and Error** node-kku route pannalaam, adhu venumne run-a fail pannum.

### Bad records-a thaniyaa piringa, aanaa ellaame fail aanaa niruthunga

300-la oru bad item meedhi 299-a niruthak koodaadhu. Items-a thanithaniyaa process panni, ovvoru failure-aiyum adhoda reason-oda oru "needs attention" list-la ezhudhunga; idhai sila samayam **dead-letter queue**-nu solvaanga. n8n-la, node-oda **On Error**-a **Continue (using error output)**-aa set panni, andha output-a list kooda connect pannunga. Yaaraavadhu andha records-a sari panni, appuram reprocess pannuvaanga. Edhuvum satham illaama tholaiyaadhu.

Edhir case-kku oru **circuit breaker** thevai: failures kuviyumbodhu run-a pause panra oru rule, udhaaranamaa thodarndhu 20 failures, allathu kadaisi 50 items-la paadhikku mela. Adhu illai-nnaa, oru outage 2,000 dead-letter rows-aavum 2,000 alerts-aavum maaridum.

### Udhavura alerts

| Weak alert | Useful alert |
| --- | --- |
| "Workflow failed." | "Delivery SMS workflow, step 'Send SMS', order ORD-4471: 401 Unauthorized. SMS provider token expire aayiduchu. Settings, Credentials, SMS provider-la adhai renew pannittu rerun pannunga; anuppina messages skip aagum. Run link: ..." |

Owner unmaiyile paarkkura idathukku anuppunga, udhaaranamaa email, Slack, Teams allathu WhatsApp. Repeats-a group pannunga, appo oru outage-kku 500 illa, ore oru message thaan pogum.

n8n-la, oru **Error Trigger** node-la start aagura oru thani **error workflow** create panni, ovvoru workflow-oda Settings-laiyum adhai thernthedunga. Oru automatic execution fail aagumbodhu adhu run aagum. Neenga kaiyaala test pannumbodhu adhu run aagaadhu, adhanaala oru nija scheduled allathu webhook run vachu test pannunga.

### Errors mattum illa, volume-aiyum monitor pannunga

Ellaathaiyum vida adhiga aabathaana failure-la error-e irukkaadhu. Oru naalaikku process aana items-aiyum failures-aiyum track pannunga. "1,000-kku kuraivu" maadhiri oru fixed threshold ovvoru amaidhiyaana Sunday-laiyum fire aagum, paadhi udainja oru naalai miss pannum. Adhukku badhilaa **adhe weekday-oda sameebathiya average** kooda compare pannunga, udhaaranamaa "8 pm-kkulla kadaisi naalu Tuesdays-oda average-la paadhikku kuraivaa anuppiyirundhaa alert pannu", andha rule-a maasaa maasam review pannunga.

### Ownership-um oru runbook-um

Ovvoru automation-kkum per sollappatta oru owner-um, oru chinna runbook-um irukkanum: adhu enna pannudhu, podhuvaana failures, ovvonnaiyum eppadi sari panradhu, paadhugaappaa eppadi rerun panradhu.

## Oru worked example

Bengaluru-la oru logistics startup, customers-kku SMS-la delivery updates anuppi, order system-a update panra oru automation-a run pannudhu: oru naalaikku sumaar 8,000 messages, adhula perumbaalaanadhu 6 pm-la irundhu 9 pm varai. Keezha irukkura numbers oru typical mudhal maasathoda illustration thaan, alandha results illa.

**Mudhal maasam moshamaa pochu:**

| Prachanai | Kaaranam |
| --- | --- |
| Evening peaks-la messages fail aachu | Workflow mudinja varai vegamaa anuppuchu, SMS provider adhai rate-limit pannuchu (HTTP 429) |
| Sila customers-kku rendu messages pochu | Fail aana oru run-a kaiyaala rerun pannaanga, adhu munnaadi anuppina messages-a marupadiyum anuppuchu; timeout aana sends kanmoodithanamaa retry aachu |
| Oru naal edhuvume pogala, error-um illa | Order system-kkaana oru login token expire aayirundhuchu; export step sathamaa fail aagaama oru kaali list-a return pannuchu |

**Fixes:**

1. **Plan-oda limit-kku throttle:** provider-oda documented rate-kku keezha batches, naduvula oru wait.
2. 429s-la **backoff, jitter-oda retries**, Retry-After irundhaa adhai use panni, adhigapatcham naalu attempts, appuram "needs attention" sheet. Oru send-la timeout allathu 500 mudhal 504 vandhaa, adhu mudhalla fix 3-la irukkura status check vazhiyaa pogum.
3. **Order id plus status vachu key panna oru send log.** Ovvoru message-um call-kku munnaadi "sending"-aa ezhudhappadum. Oru rerun "sent"-nu mark aana edhaiyum skip pannum. Timeout-kku appuram, marupadiyum anuppuradhukku munnaadi workflow andha key vachu provider-oda delivery status-a check pannum.
4. **Export-a validate panradhu.** Kaaliyaana allathu romba chinna export ippo green-aa mudiyaama, "order export 0 rows return pannuchu; order system login-a check pannunga"-nu solli run-a niruthum. Satham illaadha andha naalai pidichirukkak koodiya fix idhu thaan.
5. **Credentials errors run-a udane niruthum**, token-a enga renew pannanum-nu solli owner-kku alert pannum.
6. **Oru circuit breaker:** thodarndhu 20 failed sends vandhaa run pause aagi, oru alert anuppum.
7. **8 pm-la oru volume check**, adhe weekday-oda kadaisi naalu naatkaloda average kooda compare panni, 50 percent-kku keezha ponaa alert pannum.

**Adutha maasam (illustrative):**

## Podhuvaa panra thappugal

- **Ellaathaiyum retry panradhu.** Permanent errors-a sari pannanum; ovvoru thadavaiyum fail aagura record "needs attention"-la thaan irukkanum.
- **Timeout aana send-a kanmoodithanamaa retry panradhu.** Mudhal attempt work aayirukkalaam. Mudhalla unga key vachu check pannunga.
- **Ovvoru attempt-kkum oru pudhu key.** Oru run id allathu timestamp ovvoru retry-aiyum pudhusaa kaattum, adhanaala edhuvume skip aagaadhu.
- **Throttling-kku badhilaa retries.** Dhinamum adhe mani nerathula 429s vandhaa, vegathai kurainga; innum kadumaiyaa retry mattum pannaadheenga.
- **Jitter-um cap-um illaadha fixed waits.** Ellaame ore nerathula retry aagum, outage innum moshamaagum, neenga block aagalaam.
- **Green run-a nambradhu.** Kaaliyaana allathu vichithiramaana "successful" responses-a validate pannunga.
- **Oru bad item batch-a niruthudhu, allathu oru dead service ovvoru item-aiyum fail pannudhu.** Records-a thaniyaa piringa, aanaa failures kuviyumbodhu run-a niruthunga.
- **Details illaadha alerts, allathu 500 alerts.** Enna udainjudhu, enna pannanum-nu oru thadavai sollunga.

## Practice pannunga

Keezha link panniyirukkura n8n-oda error handling guide-a padinga, N8N102 course-la error-handling pagudhiya marupadiyum paarunga.

1. **Retries.** Venumne fail aagura oru endpoint-kku oru HTTP Request node-a point pannunga (udhaaranamaa 503 return panra unga sondha chinna webhook workflow). Retry On Fail-a on panni, retries unmaiyile run aachaa-nnu execution log-la confirm pannunga. Appuram error output, oru Wait node, oru counter vachu oru neelamaana retry-a build pannunga.
2. **Throttle.** 50 test items-a timed batches-aa anuppi, timing unga plan kooda match aagudhaa-nnu check pannunga.
3. **Duplicates, dead letters.** Oru unique key-oda oru send log, "sending" appuram "sent" status, oru "needs attention" sheet serunga. Workflow-a rendu thadavai run panni, edhuvum rendu thadavai pogalai-nnu kaattunga.
4. **Alerts, checks.** Error Trigger node-oda oru error workflow-aiyum oru useful alert-aiyum, oru empty-result check-aiyum, oru same-weekday volume check-aiyum create pannunga.

**Mudinjadhu-nnu eppo sollalaam:** oru temporary error, oru permanent error, oru bad item, oru kaali input vachu unga workflow-a naalu vazhiyila udaikka mudiyum, ovvonnukkum sariyaana behaviour-a kaatta mudiyum, duplicates illaama adhai rerun panna mudiyum.
