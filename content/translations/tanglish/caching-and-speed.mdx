## Idhu enna

LLM apps-la cost-aiyum kaathirukkura nerathaiyum moonu techniques kuraikkudhu. Ivai vera vera layers-la velai seiyudhu, ivatrai kuzhappikkiradhu thaan perumbaalaana caching bugs-kku kaaranam.

- **Prompt caching** model provider pakkam nadakkudhu. Unga prompt-oda aarambap pagudhiyoda (instructions, tool definitions, oru neelamaana document) processed form-a provider vechukkudhu. Sariyaa adhe content-oda aarambikkira adutha request andha velaiya skip pannudhu, adhanaala cost kuraivu, mudhal token-um seekkiramaa varum. Aanaalum model ovvoru thadavaiyum pudhu answer thaan ezhudhudhu.
- **Response caching** unga sondha app-la nadakkudhu. Mudinja answers-a neenga store panni, adhe request marupadi vandhaa adhula onna return panreenga, model call-ae illaama. Idha neengale build panradhaala, store panna ovvoru answer-aiyum yaar paarkkalaam-nu neenga thaan mudivu panreenga.
- **Streaming** delivery-a maathudhu, velaiya illa. Reply generate aaga aaga konjam konjamaa screen-kku varudhu, adhanaala user onnu rendu seconds-la padikka aarambikkiraanga.

Moonaiyum use panra oru request ippadi irukkum:

```flow
title: Oru request, moonu layers
Kelvi varudhu -> En response cache-la irukkaa?
En response cache-la irukkaa? -[hit, adhe scope]-> Store panna answer-a return pannu | model call illa
En response cache-la irukkaa? -[miss]-> Model-a call pannu -> Provider cache aana prefix-a padikkudhu | instructions, documents
Provider cache aana prefix-a padikkudhu -> Tokens-a screen-kku stream pannu -> Mudinja answer-a store pannu | reuse panna safe-na mattum
```

Indha lesson Chennai-la oru legal-tech company-oda contract assistant-a follow pannudhu. Lawyers oru agreement-a upload panni, adhu mela sumaar patthu kelvigal kekkuraanga.

## Idhu eppadi velai seiyudhu

### Neram enga pogudhu

Oru reply-kku rendu phases. Mudhalla model muzhu input-aiyum padikkudhu (**prefill**). Appuram reply-a oru thadavaikku oru token-aa ezhudhudhu (**decode**). Neelamaana input mudhal token-a slow pannum. Neelamaana output adhukku appuram varra ellaathaiyum slow pannum. Adhanaala oru 30,000-token contract perumbaalum **time to first token** (TTFT)-a baadhikkum, oru 1,000-token answer perumbaalum mottha nerathai baadhikkum. Prompt caching mudhalaavadha thaakkudhu; streaming rendaavadha maraikkudhu; chinna answers-um chinna models-um adha kuraikkudhu.

### Prompt caching

Cache oru **exact prefix**-a match pannudhu: sameebathula paartha oru request-oda adhe bytes-la, adhe order-la request aarambikkanum. Oru character maarinaa, adhukku appuram irukkura ellaame invalid aagidum. Adhanaala prompt-a ellaathaiyum vida stable-aanadhula irundhu ellaathaiyum vida kuraivaa stable-aanadhu varai order pannunga:

1. tool definitions, oru fixed order-la;
2. system instructions;
3. neelamaana reference documents (contract, policy, codebase);
4. per-user allathu per-session data;
5. latest kelviyum conversation turns-um.

Timestamp, request id allathu user-oda name-a mela eppavume vaikkaadheenga. Model-kku innaikku date thevainna, adha kadaisi pakkathula vainga.

**Laabamaa illaiyaa-nnu mudivu panra numbers.** Claude-oda API-la, November 2026 nilavarappadi (28 November 2026 annaikku check pannadhu; keezha link panna pricing page-a paarunga):

| Item | Value |
| --- | --- |
| Cache write, 5-minute lifetime (default) | Normal input price-oda 1.25x |
| Cache write, 1-hour lifetime (`"ttl": "1h"`) | Normal input price-oda 2x |
| Cache read | Perumbaalaana models-la 0.1x; Sonnet 5.5, Opus 5.5-la 0.05x; Fable 5.1, 5.2-la 0.025x |
| Lifetime | Entry-a write allathu read panna kadaisi request aarambicha nerathula irundhu kanakku; ovvoru read-um extra cost illaama clock-a marupadi aarambikkudhu |
| Minimum cacheable prefix | Ippodhaiya models-la 512 tokens (sila pazhaiya models-la 1,024-la irundhu 4,096); idha vida chinna prefixes cache aagaadhu, error-um varaadhu |
| Oru request-kku breakpoints | 4 varai |
| Oru entry-a yaar share panraanga | Unga workspace mattum; vera organisation eppavume illa |

Idhula irundhu rendu rules varudhu. 5-minute cache oru read-laye than cost-a thirumba eduthudum; 1-hour cache-kku rendu read venum. Appuram price-a vida lifetime thaan mukkiyam: oru prefix-a share panra requests lifetime-a vida adhiga idaiveliya vandhaa, ovvoru request-um write premium kodukkum, edhukkum read discount kidaikkaadhu, adhu caching illaadhadha vida adhiga cost aagum.

Prefix-a share panra requests-kku naduvula irukkura gap-a vechu lifetime-a choose pannunga. 5 nimishathukkulla-na default-a use pannunga; steady traffic-ae adha warm-aa vechukkum. 5-la irundhu 60 nimisham-na 1-hour cache. Oru mani nerathukku mela-na, onnu mudhal request cold-aa irukkuradha ethukkonga, illainna **pre-warm** pannunga: traffic varum-nu edhirpaarkkuradhukku konjam munnaadi (worker start, mudhal lawyer-oda login), shared prefix-a `max_tokens`-a 0-aa set panni oru thadavai anuppunga. Appo Claude-oda API cache-a write pannittu, edhaiyum generate pannaama return aagum.

**Innum write aagittirukkura cache-a parallel requests share pannaadhu.** Mudhal response aarambicha piragu thaan oru entry readable aagum. Ore nerathula patthu requests anuppinaa, patthume muzhu vilai kodukkum. Mudhalla onna anuppi, adhoda mudhal token-kku wait pannittu, appuram meedhiya anuppunga.

**Matha providers.** OpenAI maadhiri sila providers, prompt oru minimum length-a thottavudane (avanga documentation-padi, model-a poruthu kurainjadhu 1,024 tokens) thaanaave cache pannudhu. Claude automatic caching allathu explicit breakpoints kudukkudhu. Stable content mudhalla-ngradhu ella idathulaiyum velai seiyum; minimums, lifetimes, prices vera vera, adhanaala savings-a estimate panradhukku munnaadi unga provider-oda page-a padinga.

**Code-la prompt caching.** Anthropic-oda Python SDK-la stable pagudhiyoda mudiva mark panreenga, cache-la irundhu enna read aachu-nnu usage report kaattum:

```python
import anthropic

client = anthropic.Anthropic()
POLICY = open("returns_policy.md").read()          # long, rarely changes

def ask(question):
    reply = client.messages.create(
        model="claude-sonnet-5-5", max_tokens=2000,  # check the docs for current model names
        system=[
            {"type": "text", "text": "You answer questions about our returns policy. Be brief."},
            {"type": "text", "text": POLICY,
             "cache_control": {"type": "ephemeral"}},  # cache up to here; add "ttl": "1h" for slow traffic
        ],
        messages=[{"role": "user", "content": question}],   # changing part goes last
    )
    u = reply.usage
    print(f"cache write {u.cache_creation_input_tokens}, cache read {u.cache_read_input_tokens}, "
          f"uncached {u.input_tokens}")
    return reply

ask("Can I return a kurta after 10 days?")       # first call writes the cache
ask("Do you refund shipping charges?")           # later calls read it
```

**Velai seiyudhaa-nnu check panradhu.** Ovvoru call-laiyum moonu usage numbers-aiyum log pannunga. Varisaiyaa anju requests anuppunga: mudhalaavadhula oru cache write theriyanum, meedhila kittathatta adhe size-la cache reads. Reads zero-laye irundhaa, prefix-la edho onnu innum maarudhu: oru timestamp, oru request id, vera order-la build aana tools, keys sort pannaadha JSON, minimum-kku keezha irukkura prefix, allathu maarina model allathu thinking setting. Reads prefix-a vida romba chinnadhaa irundhaa, breakpoint thappaana idathula irukku.

### Response caching, user-kku scope panni

Oru response cache-na oru key-value store, dictionary allathu Redis maadhiri. Key-la **answer-a maathura ellaame** irukkanum: normalise panna kelvi, document allathu data version, prompt version, model, appuram **scope**, adhaavadhu answer-a yaar paarkka allowed-ngradhu.

Teams marandhudura pagudhi scope thaan, adha marandhaa data leak aagum. Key-la kelvi mattum irukku-nnu vechukkonga. Asha "En order enga irukku?"-nu kekkuraanga, avanga address-oda answer store aagudhu. Ravi adhe vaarthaigala kekkuraaru, cache-la irundhu Asha-voda answer avarukku kidaikkudhu, milliseconds-la, endha log-laiyum error illaama. Provider-oda prompt cache idha panna mudiyaadhu, yenna model ovvoru thadavaiyum pudhu answer ezhudhudhu. Unga response cache panna mudiyum, yenna adhu store panna text-a return pannudhu.

Moonu scopes use pannunga. **Public**: ellaarukkum onnu thaan, product FAQs, fixed help text maadhiri. **Tenant**: oru company-kkulla onnu thaan, oru law firm-oda sondha standard NDA maadhiri, aanaa vera firm-kku eppavume kaattakkoodaadhu. **User**: personal allathu permission-a poruthadhu; user id-aala key pannunga, illainna cache-ae pannaadheenga. Yaarum marakka mudiyaadha maadhiri scope-a oru required argument aakkunga:

```python
import hashlib, json, time

CACHE, TTL_SECONDS = {}, 24 * 3600
PROMPT_VERSION, MODEL = "faq-v3", "claude-sonnet-5-5"

def cache_key(scope, question, doc_version):
    norm = " ".join(question.lower().split())
    raw = json.dumps([scope, norm, doc_version, PROMPT_VERSION, MODEL])
    return hashlib.sha256(raw.encode()).hexdigest()

def cached_answer(scope, question, doc_version, compute):
    # scope: "public", "firm:<id>" or "user:<id>"; there is no default on purpose
    key = cache_key(scope, question, doc_version)
    hit = CACHE.get(key)
    if hit and time.time() - hit["at"] < TTL_SECONDS:
        return hit["answer"]
    answer, complete = compute(question)          # complete: the reply finished normally
    if complete:                                  # never cache errors or cut-off replies
        CACHE[key] = {"answer": answer, "at": time.time()}
    return answer
```

Ship panradhukku munnaadi oru two-account test ottunga: user A oru personal kelvi kekkuraanga, user B adhe vaarthaigala kekkuraanga, B-kku A-voda answer kidaikkakkoodaadhu. Stable answers-kku kooda oru expiry vainga, source maarumbodhu entries-a clear pannunga; cache aana oru thappaana answer yaaraavadhu kavanikkira varaikkum repeat aagitte irukkum.

### Semantic caching, kavanamaa

**Semantic caching** embeddings use panni kelvigala arthathai vechu match pannudhu, adhanaala "Namma NDA-la notice period?" kelvi "NDA notice period enna?"-kkaana answer-a reuse pannalaam. Idhu hit rates-a ethum, aanaa ovvoru thappaana match-um confident-aana oru thappaana answer-a kudukkum. Moonu guards:

- **Similarity search-kku munnaadiye scope-aala filter pannunga**, appo kekkuravar paarkka allowed-aana answers-la irundhu mattum thaan match vara mudiyum.
- **Numbers, names-la exact-aa othuppoganum-nu require pannunga.** "Order 41-kku refund", "order 14-kku refund" text-aa kittathatta onnu thaan, kelvigalaa muzhukka vera:

```python
import re

def numbers_match(new_q, cached_q):
    return re.findall(r"\d+", new_q) == re.findall(r"\d+", cached_q)
```

- **Similarity threshold-a unga sondha data-va vechu set pannunga.** Ella idathukkum safe-aana oru universal number illa. Candidate matches-a log pannunga, adhula 200-a oruthar sariyaa thappaa-nnu label pannattum, andha feature-kku neenga set panna target-kku keezha wrong-match rate varra varaikkum threshold-a ethunga.

### Streaming

Streaming mottha generation time-aiyo cost-aiyo maathaadhu. Adhu experience-a maathudhu: text onnu rendu seconds-kkulla aarambikkudhu, meedhi vandhuttirukkumbodhe user padikkiraanga, seekkiramaave Stop amukkalaam. Chat-la eppavume stream pannunga. TTFT-a measure pannunga:

```python
import time
import anthropic

client = anthropic.Anthropic()

def stream_answer(question):
    start, first = time.perf_counter(), None
    with client.messages.stream(model="claude-sonnet-5-5", max_tokens=2000,
                                messages=[{"role": "user", "content": question}]) as stream:
        for text in stream.text_stream:
            if first is None:
                first = time.perf_counter() - start
            print(text, end="", flush=True)     # in a web app, send each piece to the browser
        final = stream.get_final_message()
    print("\nfirst text after", round(first, 2) if first else None,
          "s; total", round(time.perf_counter() - start, 2), "s; stop:", final.stop_reason)
```

Server timing mattum muzhu kadhai illa: browser-la, user Send amukkumbodhum mudhal vaarthaigal paint aagumbodhum `performance.now()`-a record pannunga, real users-la irundhu p50, p95-a report pannunga. Moonu gotchas. Sila proxies, compression layers, hosting platforms response-a buffer pannudhu, adhanaala local-la velai seiyura stream production-la mothamaa ore thadavaiyaa varum; real path vazhiyaa test pannunga. Oru stream paadhila fail aagalaam, adhanaala partial text-a thelivaana "answer interrupted, try again" message-oda kaattunga, adha eppavume cache pannaadheenga. Appuram answer mudiyaradhukku munnaadiye text screen-la irukkum, adhanaala safety filter allathu JSON validation maadhiri muzhu answer thevaippadura endha check-um ovvoru piece-laiyum odanum, illainna text kaatta aarambikkiradhukku munnaadiye odanum.

### Matha speed levers

Chinna outputs, yenna generation time length-oda serndhu valarum. Simple steps-kku chinna models. Varisaiyaa kuraivaana calls. Onna onnu saaraadha calls-a parallel-aa (udhaaranamaa `asyncio.gather` vechu), appo kaathiruppu ellaathoda koottuthogai illa, ellaathaiyum vida slow-aana call alavu thaan; rate limits-a kavaninga, oru burst 429 errors-a return pannalaam. Kuraivaana, nalla retrieved chunks.

## Oru worked example

Chennai contract assistant oru 40-page agreement pathina kelvigalukku badhil solludhu. Keezha irukkura numbers November 2026 nilavarappadi Claude Sonnet 5.5 list prices-a vechu build panna oru **illustration** thaan (oru million input tokens-kku $2, oru million output-kku $10, cache writes 5 nimishathukku $2.50 allathu 1 mani nerathukku $4, cache reads $0.10), indha assumptions-oda: instructions-um contract-um 30,000 tokens, ovvoru kelviyum 100 tokens, adhu thaniyaa anuppappadudhu, ovvoru answer-um 300 output tokens use pannudhu, oru contract-kku 10 kelvigal. Indha figures-a reuse panradhukku munnaadi ippodhaiya prices-a check pannunga.

**Munnaadi.** Ovvoru kelviyum muzhu 30,100 tokens-aiyum muzhu vilaila anuppudhu: $0.0602 input, $0.003 output, adhanaala oru kelvikku $0.0632, **oru contract-kku $0.63**. Edhuvum stream aagala, adhanaala lawyer-kku sumaar 9 seconds edhuvum theriyaadhu.

**Appuram, mudhal muyarchi.** Team contract-aiyum instructions-aiyum munnaadi nagarthi, oru breakpoint serthu, default 5-minute cache-aiye vechukkudhu. Kelvigal 5 nimishathukkum kuraivaana idaiveliya vandhirundhaa, kelvi 1-kku $0.078 aagiyirukkum (write premium adha munnaadiya vida adhiga vilaiyaakkudhu), adhukku appuram ovvoru kelvikkum $0.0062, adhanaala **oru contract-kku $0.13, 79% kuraivu**. Aanaa logs kittathatta ovvoru call-laiyum cache writes-a kaattudhu. Lawyers adutha kelvi kekkuradhukku munnaadi ovvoru answer-aiyum clause kooda vechu padikkiraanga, adikkadi 5-la irundhu 15 nimisham kazhichu. Ovvoru entry-um expire aagudhu, ovvoru kelviyum write price kodukkudhu, bill eri **oru contract-kku $0.78 aagudhu, caching illaadhadha vida 24% adhigam**.

**Appuram, sari pannadhu.** Avanga 1-hour cache-kku maaruraanga. Ippo kelvi 1-kku write-kkaaga $0.12, adutha onbadhukku ovvonnukkum $0.0062: **oru contract-kku $0.18, munnaadiya vida sumaar 72% kuraivu**. Oru dollar-kku sumaar ₹94-la (mid-November 2026), adhu oru contract-kku kittathatta ₹59-la irundhu ₹17-kku irangudhu. Kavaninga, output tokens (oru answer-kku $0.003) ippo cache aana oru kelviyoda cost-la paadhi, adhanaala adutha saving chinna answers thaan.

Firm-kitta adhoda sondha standard templates pathina kelvigalukku oru response cache-um irukku ("Namma standard NDA-la notice period enna?"). Adhu firm-oda id, template version, prompt version-aala key pannappattirukku, adhanaala firm A-voda template answers firm B-kku eppavume pogaadhu. Upload panna contract pathina answers response-cache pannappadave illa: ovvoru contract-um adhukku-nnu access list irukkura oru matter-kku sondham.

Mudhal kelviyaiyum vegamaakka, oru contract upload aagi mudinjavudane, lawyer innum type pannittirukkumbodhe, team `max_tokens`-a 0-aa set panni cache-a pre-warm pannudhu.

## Podhuvaana thappugal

- **Prompt-oda mela edho maarura onnu.** Oru date, request id allathu user name ovvoru cache read-aiyum udaikkum. Kandupidikka: repeat calls-la `cache_read_input_tokens` 0-laye irukkum.
- **Traffic-kku thappaana lifetime.** Cache lifetime-a vida neelamaana gaps caching-a oru surcharge aakkidum. Kandupidikka: perumbaalaana calls-la cache writes, konjam reads.
- **Scope illaadha response cache keys.** Oru user-oda order, salary allathu contract innoru user-kku pogum. Kandupidikka: launch-kku munnaadiyum ovvoru cache change-kku appuramum ottura oru two-account test.
- **Maarura data-la irundhu varra answers-a, key-la expiry allathu version illaama cache panradhu.** Pazhaiya prices-um pazhaiya rules-um thodarndhu serve aagum. Kandupidikka: oru update-kku appuram source kooda othuppogaadha answers.
- **Failures-a cache panradhu.** Oru timeout, oru refusal allathu `max_tokens`-aala paadhila vettappatta reply store aagi ellaarukkum replay aagum. Normal-aa mudinja replies-a mattum store pannunga.
- **Cold cache-kku parallel requests anuppuradhu.** Ellaame muzhu vilai kodukkum. Kandupidikka: ore second-la oru burst cache writes.
- **Streaming generation-a vegamaakkum-nu namburadhu.** Adhu kaathiruppa kuraivaa feel panna vaikkudhu; cost-um mottha neramum maaraadhu.
- **Averages-a mattum measure panradhu.** Time to first token-kkum mottha nerathukkum p50, p95-a report pannunga, server-la mattum illaama browser-laiyum measure panni.

## Caching eppo udhavaadhu

- **Ovvoru request-um vera maadhiri**, neelamaana shared prefix illa, repeat aagura kelvigalum konjam thaan.
- **Traffic kuraivaa, paravalaa irukku**, adhanaala 1 hour-laiyum kooda, adutha request varradhukku munnaadiye cache aana prefixes expire aagidum.
- **Shared pagudhi chinnadhu**, minimum cacheable length-kku keezha.
- **Ovvoru thadavaiyum answers fresh-aa irukkanum**, live prices allathu stock levels maadhiri.
- **Slow pagudhi vera idathula irukku**: retrieval, oru slow tool allathu unga sondha server. Model call-a optimise panradhukku munnaadi measure pannunga.

## Demo-la irundhu production-kku

- Ovvoru call-laiyum **cache read, write tokens-a log pannunga**, ovvoru feature-kkum hit rate-a track pannunga.
- Browser-la irundhu, feature, model vaariyaa, p50, p95-la **time to first token-aiyum mottha nerathaiyum track pannunga**.
- Prompt, model, data-va vechu **cache keys-a version pannunga**, ella idathulaiyum expiries vainga, release-appo allathu source data maarumbodhu response caches-a clear pannunga.
- **Ovvoru response cache key-laiyum scope-a oru required pagudhi aakkunga**, two-account test-a unga test suite-la vechukkonga.

## Practice

Keezha link panna prompt caching guide-aiyum streaming guide-aiyum padinga.

1. Unga prompts-la onna stable content mudhalla varra maadhiri restructure panni, oru breakpoint serunga. Anju requests anuppi, ovvonnukkum cache write, cache read, uncached tokens-a record pannunga.
2. Unga real traffic-la requests-kku naduvula irukkura gap-a kandupidinga, 5 minutes-aa 1 hour-aa-nnu choose pannunga, unga provider-oda ippodhaiya prices-la irundhu oru session-kkaana cost-a rendu vazhiyilaiyum calculate pannunga.
3. Oru chat interface-kku streaming serthu, munnaadiyum appuramum browser-la time to first token-a measure pannunga.
4. Repeat aagura oru kelvi type-kku oru scoped response cache serunga, appuram two-account test-a ezhudhi, scope-a eduthaa adhu fail aaguradha paarunga.
