## Idhu enna

LLM apps-la selavaiyum kaathirukkura neraththaiyum moonu techniques kammi pannum:

- **Prompt caching**: oru prompt-oda neenda, maaraadha aarambathai (system prompt, oru document, tool definitions) provider processed form-la store pannum, adhanaala adhae madhiri aarambikkura adutha requests selavum kammi, vegamum.
- **Response caching**: unga app answers-a store panni, adhae (illa equivalent) request thirumba vandhaa model call-a muzhusaa thaandi adhaiye thirumba kudukkum.
- **Streaming**: reply-a generate aagura madhiriyae token token-aa user-ku anuppradhu, adhanaala avanga almost udane padikka aarambikkalaam.

```flow
dir: LR
title: Prompt caching: maaraadha pagudhi mudhalla
Maaraadha prefix | instructions, tools, 40-page contract: mudhal call-ku apram cache aagum -> Kelvi | ovvoru request-um maarum
```

Kelvi 1 muzhu price kudukkum, 9 s edukkum; kelvi 2-la irundhu, cached prefix mudhal token-a sumaar 2 s-ku konduvarum.

```flow
title: Response cache: key = normalise panna kelvi + template version + model version
Kelvi -> Response cache-la irukka?
Response cache-la irukka? -[hit]-> Udane answer, model call illa
Response cache-la irukka? -[miss]-> Model -> Tokens-a screen-ku stream pannum
```

Indha lesson Chennai-la oru legal-tech company-oda contract assistant-a follow pannum, angae lawyers upload panna ovvoru agreement-kum sumaar paththu kelvigal kekkuraanga.

## Idhu eppadi work aagudhu

**Prompt caching.** Cache-la irundhu padikkura input tokens-ku providers kammiyaa, pala neram romba kammiyaa, charge pannuvaanga, adhai process panradhum vegam. Cache exact prefix-la velai seiyum: request adhae content-oda, adhae order-la aarambikkanum. Adhanaala:

- maaraadha content mudhalla vainga: system prompt, tool definitions, neenda reference documents;
- maarura content kadaisila vainga: user-oda kelvi, latest conversation turns;
- mela maarura edhaiyum (timestamp, user name) serkkaadheenga.

Konjam neram use pannaama irundhaa caches expire aagum; minimum length, lifetime, pricing pathi unga provider-oda rules-a paarunga.

**Response caching.** Normalise panna request-a (prompt, model version-um serthu) key-aa vechu answer-a store pannunga. Thirumba thirumba varra, ore madhiri kelvigalukku nalladhu: FAQ answers, product descriptions, maaraadha text-oda translations. Expiry neram vainga, adippadai data maarina invalidate pannunga, answers-la personal illa permission-a poruthu maarura data irundhaa, cached answers-a users-ukkulla share pannadheenga. "Semantic caching" ore madhiri illaama similar-aa irukkura kelvigala match pannum; jaakkirathaiyaa use pannunga, yen-na konjam ore madhiri theriyura kelvigalukku vera answers thevai padalaam.

**Streaming.** Total generation neram maaradhu, aana users muzhu reply-kku kaathirukkaama, sirppaaga oru, rendu second-kulla mudhal vaarthaigala paarppaanga. Perceived speed romba nallaa aagum, users padikkuradha niruthalaam illa seekkiram cancel pannalaam. Stream pathila varra errors-aiyum disconnections-aiyum handle pannunga.

**Vera speed levers.** Chinna outputs (length-oda generation neram adhigam aagum); simple steps-ku chinna models; kammiyaana sequential model calls; independent calls-a parallel-aa odikkradhu; kammiyaana, nalla chunks-a retrieve panradhu.

**Moonu techniques-a oppidu:**

| Technique | Edhai save pannum | Eppo work aagum | Enna paakkanum |
| --- | --- | --- | --- |
| Prompt caching | Input cost-um mudhal token varra neramum | Neenda ore madhiri prefixes sikkiram thirumba use aagum podhu | Prefix maaradhu; cache expiry |
| Response caching | Muzhu model call-aiyum | Ore madhiri kelvigal thirumba varum podhu | Personal data; pazhaya answers |
| Streaming | Kaathirukkura neram feel aagura vidham | Chat-um neenda answers-um | Stream pathila errors, disconnects |

**Cache work aagudhaannu check panradhu.** Providers ovvoru response-oda usage data-vula cached input tokens-a sollum. Adhai log pannunga. Prompt-a reorder panna aprom, aindhu requests-a thodarndhu anuppi, rendavadhu request-la irundhu cached count yerudha-nu paarunga. Zero-vulaiyae irundhaa, prefix-la innum edho maarura vishayam irukku, perumbaalum timestamp, request id, illa maarura order-la irukkura tool definitions.

**Response caches-a invalidate panradhu.** Answer-a maathura ovvoru input-aiyum key-la serkkanum: kelvi, template illa document version, prompt version, model. Maaraadha answers-kum expiry vainga, source maarina entries-a clear pannunga. Thappaana cached answer, mella aana sariyaana answer-a vida mosam, yen-na yaaraavadhu kavanikkira varaikkum adhu thirumba thirumba varum.

**Neram engae pogudhu.** Oru reply-ku rendu phases irukku. Mudhalla model muzhu input-aiyum padikkum (**prefill**); apram reply-a oru oru token-aa ezhudhum (**decode**). Neenda inputs mudhal token-a slow pannum; neenda outputs adhukku apram ellaathaiyum slow pannum. Adhanaala 20,000-token document perumbaalum time to first token-a paadhikkum, 1,000-token answer perumbaalum total time-a paadhikkum. Caching mudhal onnukku udhavum; chinna answers-um chinna models-um rendavadhukku udhavum.

**Code-la prompt caching.** Anthropic API-la maaraadha prefix enga mudiyudhu-nu mark pannuveenga, usage report cache-la irundhu enna padichaachu-nu sollum:

```python
import anthropic

client = anthropic.Anthropic()
POLICY = open("returns_policy.md").read()          # long, rarely changes

def ask(question):
    reply = client.messages.create(
        model="claude-sonnet-5-5", max_tokens=400,  # check the docs for current names
        system=[
            {"type": "text", "text": "You answer questions about our returns policy. Be brief."},
            {"type": "text", "text": POLICY, "cache_control": {"type": "ephemeral"}},   # cache up to here
        ],
        messages=[{"role": "user", "content": question}],   # changing part goes last
    )
    u = reply.usage
    print(f"cache write {u.cache_creation_input_tokens}, cache read {u.cache_read_input_tokens}, "
          f"uncached {u.input_tokens}")
    return reply

ask("Can I return a kurta after 10 days?")       # first call writes the cache
ask("Do you refund shipping charges?")           # later calls read it, cheaper and faster
```

Cache-la ezhudhuradhu normal input-a vida konjam adhigam selavu; padikkuradhu romba kammi. Cache lifetime-kulla ore prefix-a pala thadavai use panna paying off aagum. Matha providers automatic-aa illa vera settings-oda cache pannuvaanga; principle, maaraadha content mudhalla, adhae thaan.

**Code-la response cache.** Ore madhiri thirumba varra requests-ku, answer-a paadhikkura ellaathaiyum key-aa vechu oru dictionary illa Redis store:

```python
import hashlib, json, time

CACHE, TTL_SECONDS = {}, 24 * 3600
PROMPT_VERSION, MODEL = "faq-v3", "claude-sonnet-5-5"

def cache_key(question, doc_version):
    norm = " ".join(question.lower().split())
    raw = json.dumps([norm, doc_version, PROMPT_VERSION, MODEL])
    return hashlib.sha256(raw.encode()).hexdigest()

def cached_answer(question, doc_version, compute):
    key = cache_key(question, doc_version)
    hit = CACHE.get(key)
    if hit and time.time() - hit["at"] < TTL_SECONDS:
        return hit["answer"]
    answer = compute(question)
    CACHE[key] = {"answer": answer, "at": time.time()}
    return answer
```

Ella users-kum ore answer-a irukkura answers-a mattum cache pannunga. User-oda account, orders, permissions-a poruthu irukkura edhuvum cache-a thaandanum illa key-la user id-a serkkanum.

**Independent calls-a parallel-aa odikkradhu.** Oru page-ku ore review-la irundhu oru summary, oru sentiment label, moonu tags thevai-na, calls-a ore neraththula odunga. Total wait kadaisi sum illa, romba slow-aana call aagum:

```python
import asyncio
import anthropic

aclient = anthropic.AsyncAnthropic()

async def one(instruction, text):
    r = await aclient.messages.create(model="claude-haiku-5-5", max_tokens=150,
                                      messages=[{"role": "user", "content": f"{instruction}\n\n{text}"}])
    return "".join(b.text for b in r.content if b.type == "text")

async def analyse(review):
    return await asyncio.gather(
        one("Summarise in one line:", review),
        one("Answer positive, negative or mixed:", review),
        one("Give three topic tags, comma-separated:", review),
    )
```

Fan out panna rate limits-a madhiyunga; parallel calls-oda burst 429 errors-a trigger pannalaam.

**Semantic caching, jaakkirathaiyaa.** Embedding vechu similar kelvigala match pannaa hit rate adhigamaagalaam, aana ovvoru thappaana match-um thappaana answer-a serve pannum. High similarity threshold vainga, personal illa numeric details illaadha general kelvigalukku mattum vechukkunga, adhai nambradhukku munnaadi evvalavu thadavai matches thappa irukku-nu measure pannunga.

## Oru worked example

Chennai legal-tech company-oda contract assistant, lawyer upload panra 40-page agreement pathi kelvigalukku badhil solludhu, oru contract-ku sumaar 10 kelvigal.

Munnaadi: ovvoru kelvi-kkum muzhu contract-um (sumaar 30,000 tokens) kelvi-yum anuppinaanga. Ovvoru answer-kum 9 seconds aachu, input tokens ovvoru thadavaiyum muzhusaa bill aachu.

Aprom:

- Contract-um instructions-um mudhalla varum, cache aagum; kelvigal kadaisila. Rendavadhu kelvi-la irundhu, perumbaalaana input tokens cache-la irundhu price-oda oru siru pagudhikku padikkapadum, mudhal token sumaar 2 seconds-la varum.
- Answers screen-ku stream aagum.
- Firm-oda sonda standard template pathi common kelvigal ("Namma standard NDA-la notice period enna?") template version-a key-aa vecha response cache-la irundhu answer aagum.

Oru contract session-oda cost sumaar 70% kurayudhu, lawyers tool slow-nu pugaar solradhai niruthuraanga.

| Contract session-ku measure | Munnaadi | Aprom |
| --- | --- | --- |
| Time to first token, aduththa kelvigal | Muzhu answer-ku sumaar 9 s | Sumaar 2 s, apram stream |
| Muzhusaa bill aana input tokens | Ovvoru kelvi-kum | Mudhal kelvikku apram perumbaalum cached |
| Cost | Baseline | Sumaar 70% kammi |

**Lawyers-ku enna maarichu.** Pudhu contract-la mudhal kelvikku innum muzhu neram aagum, yen-na cache kaali. Adhukku apram varra ovvoru kelvi-yum vegamum, selavum kammi, stream aana text-naala lawyers udane padikka aarambikkuraanga. Team mudhal answer-ku keezha "Indha contract pathi aduththa kelvigal vegamaa irukkum"-nu oru chinna note serthaanga, adhu makkal tool-a adhoda romba slow neraththa vechu judge pannuradhai niruthuchu.

## Podhuvaa panra thappugal

- **Prompt-oda aarambathula maarura content.** Adhu cache-a odaikkum.
- **User-a poruthu illa maarura data-va poruthu irukkura answers-a cache pannuradhu.**
- **Response caches-ku expiry illa invalidation illaama irukkradhu.**
- **Chat interfaces-la stream pannaama irukkradhu.**
- **Streaming generation-a vegamaakkum-nu nenaikkiradhu.** Adhu kaathirukkura neram kammiyaa theriya vaikkum.
- **Per-user answers-a global-aa cache pannuradhu.** Oru user-oda order details innoru user-ku poi serum.
- **Averages mattum measure panradhu.** Time to first token-ukkum total time-kum p50, p95 sollunga.

## Caching eppo udhavaadhu

- **Ovvoru request-um vera madhiri**, neenda shared prefix illa, thirumba varra kelvigal kammi.
- **Traffic kammi, parandhu irukku**, adhanaala adutha request-kku munnaadiyae cached prefixes expire aaidum.
- **Ovvoru thadavaiyum fresh answers thevai**, live prices illa stock levels maadhiri.
- **Slow-aana pagudhi vera edathula**: retrieval, slow tool, illa unga sonda server. Model call-a optimise panradhukku munnaadi measure pannunga.

## Demo-la irundhu production-ku

- **Ovvoru call-layum cache read, write tokens-a log pannunga**, ovvoru feature-kum hit rate-a track pannunga.
- **Time to first token-um total time-um** p50, p95-la, feature, model vaaraiyaa track pannunga.
- **Cache keys-a version pannunga**, prompt, model, data-vodu, release-la caches-a clear pannunga.
- **Ellaa idathulayum expiry vainga**, source data maarina explicit invalidation vazhi vainga.
- **Rendu accounts vechu cache-a test pannunga**, edhuvum personal answer users-ukkulla kadakkala-nu prove panna.
