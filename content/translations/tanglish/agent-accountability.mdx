## Idhu enna

**Accountability**-na oru agent edukkura entha action-kum, yaaravadhu naalu kelvikku badhil sollalaam: Yaaru poruppu? Agent-ku enna seiya anumadhi irundhudhu? Adhu seidhadha yen seidhudhu? Oru thappu eppadi sari seiyappadum? Agents poruppu edukkaadhu; makkalum organisations-um edukkum.

Governance frameworks idha nadula vaikkum. NIST AI Risk Management Framework-oda "govern" function clear-aana roles-um responsibilities-um kekkudhu. EU AI Act high-risk systems-oda providers-kum deployers-kum human oversight-um, record-keeping-um, per solla pattha duties-um kattaayam aakkudhu.

```flow
title: The accountability chain
Business owner | decides the scope, answers for results -> Agent card | purpose, tools, may do alone, needs approval, never, limits, evals
Technical owner | runs it, keeps records -> Agent card
Compliance reviewer | checks against the rules -> Agent card
Agent card -> Action -> Approval | who, when, what they saw
Approval -> Audit record | steps and versions
Complaint -> A person reviews the records -> Refund, fix or a new eval case -> Report
Audit record -> A person reviews the records
```

Indha lesson-la Delhi-la oru insurance broker-oda motor-insurance renewal agent-a follow pannuvom.

## Idhu eppadi work aagudhu

**Owners-a per sollunga.** Ovvoru agent-kum: adhu enna seiyalaam-nu mudivu panni adhoda results-ku badhil solra oru business owner, adha odura oru technical owner, oru risk illa compliance reviewer. Avanga per-a agent-oda documentation-la ezhudhunga.

**Scope-a document pannunga.** Oru short "agent card": purpose, users, tools-um permissions-um, thaaniyaa edukkalaam-nu actions, approval thevaiyaana actions, eppavum seiya koodaadha actions, theriyura limits, adhu pass panna evals. Agent maarum podhu adha review pannunga.

**Identity-oda approvals.** Oru aal oru action-a approve pannum podhu, yaaru, eppo, enna paathaanga-nu record pannunga. Avanga approval accountability chain-oda oru pagudhi, adhanaala approval screen oru nijamaana mudivu edukka pothumaana alavu kaattanum.

**Records.** Ovvoru action-aiyum thirumba kattura audit logs: request, agent-oda steps, arguments-oda tool calls, approvals, prompt, model, tools-oda versions. Othukkitta kaalam varaikkum vachukkunga.

**Disclosure.** Makkal oru agent-oda pesuraanga-nu, content illa decisions AI-assisted-nu, sattam illa nalla palakkam ketkura maadhiri, solunga.

**Redress.** Paadhikkapatta makkal oru problem-a report panni oru aal-a reach panna oru clear vazhi, records vechu investigate panna oru process, sari seiya, kathukka oru urudhi (andha case-a eval suite-la serunga).

**Review.** Agent enna senjudhu-nu avvappo paarunga: actions-oda samples, overrides, complaints, incidents. Evidence appadi sollum podhu, rendu pakkamum scope-a maathunga.

**Practice-la oru agent card:**

| Section | Example entry |
| --- | --- |
| Purpose | Motor policies-a renew pannunga: quotes edunga, recommend pannunga, confirmation-ku aprom purchase pannunga |
| Users | App-la renew panra retail customers |
| Tools | get_vehicle, get_quotes, purchase_policy |
| Thaaniyaa seiyalaam | Quotes edukkalaam, reasons-oda recommend pannalaam |
| Approval thevai | Purchase, customer thelivaa confirm panna aprom mattum |
| Eppavum seiya koodaadhu | Confirmation illaama cover type illa add-ons-a maatha koodaadhu |
| Theriyura limits | Commercial vehicles support illa |
| Owners | Head of retail operations; platform lead; compliance officer |
| Last reviewed | 2026-10-01 |

**Chain-a test panradhu.** Kadandha vaaraththula oru nijamaana action-a pick pannunga. Documents-aiyum records-aiyum mattum vechu, aindhu kelvikku badhil solla try pannunga: yaaru kettaanga, agent-ku enna seiya anumadhi irundhudhu, adhu step by step enna senjudhu, yaaru approve pannaanga, avanga enna paathaanga, entha versions odindhirundhuchu. Evvalavu neram aagudhu-nu alandhu paarunga. Entha badhil-kum yaarodavo ninaivu thevai-na, illa oru mani neraththukku mela aanaa, regulator illa oru santhoshamillaadha customer kandupidikka munnaadi andha gap-a sari pannunga.

**Vendors-ku accountability.** Oru agent oru third-party model illa tool-a use pannum podhu, contract-la yaaru enna handle pannuvaanga-nu solanum: incident notification, data use, record retention, model-la maatrangal. Unga organisation innum customers-ku badhil sollanum, adhanaala agent card vendor-oda perum, contract enna cover pannudhu-nu-m sollum.

**Agent card-a code-kku pakkathula vainga.** Adha repository-la oru file-aa store panni test pannunga, appo agent nijamaa enna seiyudho adhula irundhu adhu maara mudiyaadhu:

```yaml
# agents/renewals.card.yaml
purpose: Renew motor policies after the customer confirms
owners: {business: Head of retail operations, technical: Platform lead, risk: Compliance officer}
tools:
  get_vehicle: {kind: read}
  get_quotes: {kind: read}
  purchase_policy: {kind: write, approval: customer_confirmation}
never: [change cover type without confirmation, add add-ons without confirmation]
last_reviewed: 2026-10-01
```

```python
import yaml
from datetime import date, timedelta
from agents.renewals import TOOLS          # the tool definitions the agent really uses

def test_card_matches_code():
    card = yaml.safe_load(open("agents/renewals.card.yaml"))
    assert set(card["tools"]) == {t["name"] for t in TOOLS}, "card and code list different tools"
    for name, spec in card["tools"].items():
        if spec["kind"] == "write":
            assert "approval" in spec, f"{name} writes but has no approval rule"

def test_card_reviewed_recently():
    card = yaml.safe_load(open("agents/renewals.card.yaml"))
    assert date.today() - card["last_reviewed"] < timedelta(days=180), "card review overdue"
```

Card-a update pannaama oru tool-a serthaa ippo build fail aagum, adhu owners-oda pesa vaikkum.

**Aindhu kelvikkum badhil solra audit record.** Oru append-only table, platform ezhudhum, agent-oda service account eppavum edit panna mudiyaadhu:

```sql
CREATE TABLE agent_audit (
  id bigserial PRIMARY KEY,
  run_id text NOT NULL,
  at timestamptz NOT NULL DEFAULT now(),
  actor text NOT NULL,           -- the customer, the agent, or the approver's staff id
  kind text NOT NULL,            -- request, tool_call, approval, result
  detail jsonb NOT NULL,         -- tool name and arguments, what the approver saw, the outcome
  prompt_version text, model text, tool_versions jsonb
);
-- Reconstruct one run in order:
SELECT at AT TIME ZONE 'Asia/Kolkata', actor, kind, detail FROM agent_audit WHERE run_id = $1 ORDER BY at;
```

Application role-ku `INSERT`-um `SELECT`-um mattum kudunga. Unga sector ketkura kaalam varaikkum records-a vainga, mundhiye delete pannaama kammi selavaana storage-ku export pannunga.

**India-la sector edhirpaarpugal.** Regulators thanga sectors-la AI-kitta enna edhirpaarkkuraanga-nu solli varuraanga. Example RBI, financial services-la responsible AI-kku governance, per solla pattha accountability, audit trails-a vali-yurutha oru framework publish panniyirukku. Launch-ku aprom illa, design panna munnaadi unga client-oda sector-ku ippo irukkura guidance-a padinga.

**Poruppu vendor-kitta pogaadhu.** Oru model provider-oda update behaviour-a maathinaa, unga organisation innum customer-ku badhil sollanum. Adhanaala thaan card pin panna model version-aiyum adhu pass panna evals-aiyum per sollum, model maatrangal code maatrangal maadhiri adhe review-la pogum.

**Browser-la try pannunga.** Oru agent card-a agent-kitta nijamaave irukkura tools-oda check pannunga. Oru tool-a serthu odunga.

```python
card = {"tools": {"get_vehicle": "read", "get_quotes": "read", "purchase_policy": "write"},
        "approvals": {"purchase_policy": "customer confirmation"}}
tools_in_code = ["get_vehicle", "get_quotes", "purchase_policy", "cancel_policy"]

missing = set(tools_in_code) - set(card["tools"])
if missing:
    print("tools missing from the card:", sorted(missing))
for name, kind in card["tools"].items():
    if kind == "write" and name not in card["approvals"]:
        print(f"{name} writes but has no approval rule")
print("check done")
```

## Oru worked example

Delhi-la oru insurance broker motor policies-a renew panra oru agent-a deploy pannudhu. Adhu vehicle-oda details-a check pannum, moonu insurers-la irundhu quotes edukkum, onna recommend pannum. Customer confirm pannina aprom, insurer-oda API vazhiyaa purchase-a mudikkum.

Accountability set-up:

- **Owners**: head of retail operations (business), platform lead (technical), compliance officer (review).
- **Agent card**: quotes edukkalaam, recommend pannalaam; app-la customer thelivaa confirm panna aprom mattum purchase pannalaam; confirmation illaama cover type illa add-ons-a eppavum maatha koodaadhu; adhu oru automated assistant-nu disclose pannanum.
- **Records**: ovvoru quote-um, recommendation reason-um, confirmation message-um, purchase call-um, versions-oda.
- **Redress**: ovvoru screen-layum "talk to a person" option; complaints vaaram oru thadava review aagum.

Moonu maadham kazhichu, oru customer renewal-la zero-depreciation cover vittu poiduchu-nu complain pannuraanga. Records kaattudhu, agent andha add-on illaadha oru cheaper quote-a recommend pannudhu, confirmation screen andha maatratha highlight pannala. Accountability clear: customer-oda thappu illa, design thaan thappu. Broker difference-a refund pannuraanga, confirmation screen-a ethavadhu cover maatrathaiyum highlight panna maathuraanga, cover maatrangal-ku explicit consent venum-nu oru rule serkkuraanga, appadi paththu cases-a evals-la serkkuraanga. Compliance officer-oda board report-la incident-um fix-um irukku.

| Complaint-ku aprom step | Broker enna senjaanga |
| --- | --- |
| Investigation | Records, add-on illaadha cheaper quote recommend aanadha kaattichu |
| Finding | Confirmation screen cover maatratha highlight pannala |
| Redress | Customer-ku difference-a refund pannaanga |
| Fix | Cover maatrangal highlight; explicit consent thevai |
| Learning | Appadi paththu cases evals-la serkkapattudhu; incident board-ku report aachu |

## Podhuvaa panra thappugal

- **Per solla patta owner illa.** "AI team" outcomes-ku badhil solla mudiyaadhu.
- **Scope makkal manasula mattum.** Agent card-a ezhudhi, current-aa vainga.
- **Context illaama approvals.** Kanna moodikittu approve panravanga oversight tharala.
- **Query panna mudiyaadha records.** Investigations-ku mani neraththula badhil venum.
- **Paadhikkapattavangalukku vazhi illa.** Report panna vazhi illaadha harm oru public complaint aagum.
- **Slide deck-la vaazhra agent card.** Adha repository-la vachu test pannunga.
- **Agent-oda service edit illa delete panna koodiya audit tables.**
- **Audit records-la versions illa.** Entha prompt illa model oru mudivai edutthuchu-nu solla mudiyaadhu.

## Practice pannunga

NIST AI Risk Management Framework-oda overview-a, EU AI Act summary-la high-risk obligations section-aiyum padinga.

1. Neenga build panna oru agent-ku oru agent card ezhudhunga: purpose, users, tools, anumadhi panna, thadai panna actions, approvals, theriyura limits, owners.
2. Unga audit records badhil solla mudiyuma-nu check pannunga: yaaru kettaanga, agent enna senjudhu, yaaru approve pannaanga, entha versions use-la irundhuchu.
3. Redress path-a design pannunga: paadhikkapatta aal oru problem-a eppadi report pannuvaanga, apram enna nadakkum, oru time limit-oda.
4. Card-matches-code test-a unga agent-oda repository-la serunga, apram card-a update pannaama oru pudhu tool-a serthu build fail aagudhu-nu confirm pannunga.

**Mudinjadhu-nu eppo sollalaam:** Unga agent seidha oru action-a eduthu, documents-aiyum records-aiyum mattum vechu, adhukku yaaru accountable-nu, adhu yen nadandhudhu-nu kaatta mudiyum.
