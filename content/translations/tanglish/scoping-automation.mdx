## Idhu enna

"Enga WhatsApp orders-a automate panna mudiyumaa?"-nnu kekkuradhu ore kelvi maadhiri theriyum. Adhukkulla dozen kanakkaana kelvigal olinjirukku. Voice notes-um serthaa? List-la illaadha oru product vandhaa? Result-a yaar check pannuvaanga? Messages-a yaar paakkalaam? Aaru maasam kazhichu idhai yaar sari pannuvaanga? Oru **automation scope** velai aarambikkaradhukku munnaadiye idhukkellaam badhil solludhu, adhanaala enna kidaikkudhu, edhukku panam kudukkurom-nu rendu pakkathukkum theriyum.

Scope-na oru chinna written agreement, podhuvaa onnu rendu pakkam, technical design illa: owner ovvoru variyaiyum padichu yes-o no-vo solla mudiyanum. Adhula padhinoru pagudhigal irukku:

| Pagudhi | Badhil solra kelvi |
| --- | --- |
| **Process-um boundaries-um** | Enga aarambikkudhu, enga mudiyudhu? |
| **Inputs-um volumes-um** | Enna varudhu, endha formats-la, oru naalaikku ethanai? |
| **Steps** | System enna pannudhu, aalunga innum enna panraanga? |
| **Exceptions** | System handle panna mudiyaadha cases-kku enna aagum? |
| **Systems-um access-um** | Endha accounts thevai, yaarkitta irundhu, eppo varaikkulla? |
| **Data-vum risks-um** | Enna personal data enga pogudhu? Enna thappaa pogalaam? |
| **Assumptions** | Price maaraama irukka edhu unmaiyaa irukkanum? |
| **Success measures** | Endha baseline-kku edhiraa edhu improve aagudhu? |
| **Acceptance-um sign-off-um** | Endha test, endha data-la, "accepted"-nu yaar solraanga? |
| **Support-um changes-um** | Fixes evvalavu naal free, edhu change-aa count aagum? |
| **Price, payments, timeline** | Evvalavu, eppo pay pannanum, endha dates-kkulla? |

**In scope**-na neenga promise panra velai. **Out of scope**-na panna maatten-nu neenga ezhuthula sonna velai. Oru **change request**-na scope-a maatha oru written proposal, adhu time-laiyum price-laiyum enna effect pannum-nu serthu.

```flow
Discovery | process map, samples -> Draft scope -[client reads]-> Questions, edits
Questions, edits -> Draft scope
Draft scope -> Signed scope | in, out, acceptance, support, price
Signed scope -> Build -> Acceptance test -> Handover -> Support period -> Change requests
```

Indha lesson Indore-la irukkura freelance automation specialist Ritika-vai follow pannudhu. Oru distributor avangakitta "WhatsApp-la varra orders-a automate pannunga"-nnu kettirukkaanga. Lesson mudiyumbodhu, oru owner sign panra scope-a, neenga defend pannakkoodiya oru price-oda, ungalaala ezhudha mudiyum.

## Idhu eppadi work aagudhu

### Process map-la irundhu aarambinga

Discovery-la vandha map-a use pannunga. Keezha irukkura worked example-la irukkura maadhiri, start-aiyum end-aiyum concrete events-aa ezhudhunga. Appuram ovvoru step-aiyum **automated**, **assisted** (system draft pannudhu, oru aal approve panraanga) allathu **manual**-nu mark pannunga. Map-um indha decisions-um serndhadhu thaan scope.

Mudhal version-kku oru useful default: oru step-a undo panradhu kashtam-naa, adhai automated aakkaama assisted aakkunga. Pinnaadi, adhu safe-nu data kaattinadhum, oru human check-a edukkuradhu easy; oru costly thappu nadandhadhukku appuram onnai serkkuradhu easy illa.

### Samples-a collect panni count pannunga

Saadhaarana naatkalla irundhu sumaar 40 real inputs kelunga (20-la irundhu 50 varai podhum), messy ones-um serthu, client-kku pidicha examples illa. Appuram count pannunga:

| Input type | 40 samples-la count | Decision |
| --- | --- | --- |
| Typed text orders | 22 | In scope |
| Kaiyaala ezhudhina lists-oda photos | 12 | In scope, staff review-oda |
| Voice notes | 5 | Ippodhaikku out of scope; phase 2 |
| Vera apps-la irundhu forward panna PDFs | 1 | Oru exception-aa staff-kku anuppappadum |

Indha sample size-la counts thoraayamaanadhu thaan. 40-la pannirendu photos-na, velaiyilaiyum risk-laiyum photos oru periya share-nu solludhu; oru PDF-na PDFs irukku-nnu mattum solludhu, adhu evvalavu common-nu illa. Adhanaala staff-kittayum kelunga: "Aridhaa irundhaalum vera enna varum?"

Ovvoru exception-kkum choose pannunga: automatic-aa handle panradhaa, oru aalkitta anuppuradhaa, illa exclude panradhaa, andha choice-a ezhudhi vainga. "Oru aalkitta anuppuradhu"-kku per sonna oru queue-um per sonna oru aalum venum.

Samples-la real customers-oda details irukku: adhai client control panra oru folder-la vainga, kadaisiyila ungakitta irukkura copies-a delete pannidunga.

### Human checkpoints-a othukkonga

Payments, customers-kku pora messages, deletions idhukkellaam podhuvaa approval thevai. Yaar approve panraanga, endha tool-la-nnu per sollunga. Yaarukkum neram illaadha oru checkpoint oru vaarathukkulla skip aagidum, adhanaala adhai vegamaa aakkunga: original message-kku pakkathula extract panna result, confirm panna ore oru button.

### Access-a oru dependency-aa aakkunga

Ovvoru system-aiyum, thevaiyaana account-aiyum, adhai yaar kuduppaanga, eppo varaikkulla-nnum list pannunga. Technical problems-a vida access delays thaan pala neram projects-a adhigamaa niruthi vaikkudhu.

WhatsApp oru common example. Oru automation-kku **WhatsApp Business Platform** thevai, adhu Meta-voda API, podhuvaa oru provider vazhiyaa; phone-la irukkura free WhatsApp Business app podhaadhu. Meta mudhalla business-kitta business verification-a mudikka sollalaam. Providers report panrapadi review-kku sila mani nerathula irundhu sumaar rendu vaaram varai aagudhu, sila samayam adhukku melaiyum, guaranteed time edhuvum illa, adhanaala client adhai mudhal vaarathulaye aarambikkanum. Adhe number API-la serndhadhukku appuram staff adhe number-la phone app-a thodarndhu use panna mudiyumaa-nnum provider-kitta kelunga; Meta sila cases-la, conditions-oda, idhai allow pannudhu.

Scope-la idhai ezhudhunga: "Access late-aa vandhaa, ethanai naal late aacho athanai naal go-live thallip pogum."

### Data-vaiyum risks-aiyum ezhudhi vainga

Perumbaalaana automations personal data-vai nagarthudhu: pergal, phone numbers, order history. India-la, Digital Personal Data Protection Act, 2023 (DPDP Act) idhai cover pannudhu. Data edhukku use aagudhu-nnu mudivu panra business thaan **data fiduciary**. Neenga, messaging provider, AI provider ellaarum adhoda saarbaa data-vai process panreenga, **data processors**-aa; oru valid contract-oda mattum thaan oru fiduciary oru processor-a use pannalaam-nu Act solludhu. DPDP Rules November 2025-la notify aachu, adhoda perumbaalaana duties May 2027-la irundhu apply aagum, adhanaala clients ippove idhai pathi kekkuraanga. Idhu legal advice illa; asaadhaaranamaana edhukkum, client oru lawyer-kitta kekkanum.

Scope-la, saadhaarana vaarthaigalla badhil sollunga:

- System-kkulla enna personal data varudhu, yaarkitta irundhu;
- Adhu enga store-um process-um aagudhu, endha AI provider, endha region udpada;
- Raw messages-um photos-um delete aaguradhukku munnaadi evvalavu naal vachirukkappadum;
- Adhai yaar paakkalaam;
- Business API data-la AI provider train pannudhaa (adhoda ippodhaiya terms-a check panni date-a note pannunga).

Mukkiyamaana moonula irundhu anju risks-a list pannunga, ovvonnukkum oru mitigation-um oru owner-um.

### Assumptions-a sollunga

Assumption-na neenga nambi irukkura aanaa check pannaadha oru vishayam, udhaaranamaa "client product list-a update-aa vachiruppaanga" allathu "billing import format maaraadhu". Adhula onnu fail aana, extra work oru change request. Idhu oru fixed price-a niyaayamaa vachirukkum.

### Mudhalla baseline-a measure pannunga, appuram targets vainga

Measure pannaadha oru saving-a neenga claim panna mudiyaadhu. Sila saadhaarana naatkalukku ippo irukkura process-a time pannunga, innaikku varra errors-a count pannunga, appuram adhukku edhiraa targets vainga (ROI-a measure panra lesson adhai roobaayaa maathum).

### Acceptance-a oru test-aa define pannunga

"System nallaa work aagudhu"-ngaradhu oru test illa. Test pannakkoodiya oru acceptance-kku anju pagudhigal irukku:

1. **Data:** endha items, endha period-la irundhu, yaar choose pannadhu. Client thaan choose pannanum, in-scope items-la irundhu mattum.
2. **Answer key:** ovvoru item-kkum sariyaana result, test-kku munnaadiye client pakkathula thayaar pannadhu.
3. **Correct-kku definition:** udhaaranamaa, product code-um quantity-um rendume bill panna invoice kooda match aaganum.
4. **Threshold:** reach panna vendiya number.
5. **Sign-off:** accept panra authority irukkura aal, reply panna avarukku evvalavu neram.

Rendu gotchas. Mudhalla, line accuracy-um order accuracy-um onnu illa. 90% lines sariyaa irundhu, oru order-la anju lines irundhu, errors samamaa paraviyirundhaa, sumaar 59% orders thaan muzhusaa sariyaa irukkum (0.9-oda power 5 sumaar 0.59). Neenga edhai measure panreenga, human review-kku adhu enna arththam-nu sollunga. Rendaavadhu, office manager test-a run pannalaam, aanaa owner mattum thaan adhai accept panna mudiyum. Owner-oda perai solli oru reply window serunga, udhaaranamaa: "Anju working days-kkulla failures-oda written list edhuvum varalai-nnaa, test pass aanadhaa kanakku."

### Support-um changes-um

Support period-a sollunga, udhaaranamaa go-live-kku appuram 30 naal fixes, oru fix-kkum oru change-kkum naduvula kodu podunga:

- **Oru fix:** scope solradhai system pannala. Support nerathula free.
- **Oru change:** pudhusaa allathu vera maadhiriyaa irukkura edhuvum, udhaaranamaa oru pudhu input format, field allathu system, illanna billing software upgrade maadhiri client pakkathula nadakkura oru change. Oru change request-aa price pannappadum.

Time-aiyo price-aiyo maathaama project naduvula serkkappadura requests thaan **scope creep**. Adhai absorb-um pannaadheenga, refuse-um pannaadheenga: ovvonnaiyum oru chinna quote-oda phase 2 list-la podunga.

### Effort-a estimate pannunga

Velaiyai arai naal kanakkula estimate pannakkoodiya tasks-aa pirichu koottunga. Neenga paakkaadhadhukku oru contingency serunga, udhaaranamaa 15-la irundhu 25%, samples kuraivaa irundhaa innum adhigam, appuram unga day rate-aala multiply pannunga. Oru pagudhiyai estimate pannave mudiyalai-nnaa, adhu fixed price-kku ready illa: mudhalla oru chinna paid prototype-a sell pannunga.

### Oru pricing model-aiyum payment milestones-aiyum choose pannunga

| Model | Eppo best | Surprises-a yaar thaangguraanga |
| --- | --- | --- |
| Fixed price | Scope thelivaa irukku, samples-a paathaachu | Neenga |
| Time and materials | Scope thelivilla allathu exploratory | Client |
| Monthly retainer | Support-kku appuram maintenance-um chinna changes-um | Rendu perum, oru monthly hours cap-kkulla |

Mudhal client-kku oru sensible default: milestones-la pay panra fixed price, udhaaranamaa sign pannumbodhu 40%, acceptance-la 40%, support mudiyumbodhu 20%. Advance commitment-a kaattudhu, unga aarambha naatkalukku pay pannudhu; acceptance-la pay panradhu client-a paadhukaakkudhu; kadaisi pagudhi support nerathula neenga responsive-aa irukka vaikkudhu. Prices-la GST serndhirukkaa-nnu sollunga.

Monthly running costs-aiyum scope-la podunga (messaging provider, AI usage, hosting), mudinjavarai client neradiyaa pay pannanum.

## Oru worked example

Sanjay Jain-kku sondhamaana Indore distributor-la Ritika panna discovery-la therinjadhu: 300 retailers-kitta irundhu oru naalaikku sumaar 150 orders, maasathukku 26 working days. Adhu WhatsApp-la typed text-aa, voice notes-aa, Hindi-laiyum English-laiyum kaiyaala ezhudhina lists-oda photos-aa, appappo vera app-la irundhu forward panna oru PDF-aa varudhu. Rendu staff ovvoru order-aiyum CSV files-a import panra oru billing software-la type panraanga. Avangaloda rendu vaara baseline: oru order-kku sumaar 3 nimisham, 2% orders thappaana quantity-oda ship aagudhu.

### Avanga anuppura scope

**WhatsApp order entry, version 1, 2 December 2026**

- **Process:** oru order message business WhatsApp number-kku varumbodhu aarambikkudhu; andha naaloda confirm aana orders billing software import panra oru CSV file-la varumbodhu mudiyudhu.
- **In:** Business number-kku varra text, photo orders; retailer, products, quantities-a AI extract panni product list kooda match panradhu; staff ovvoru order-aiyum confirm allathu correct panra oru review screen; oru daily CSV export.
- **Out:** Voice notes (phase 2), payments-um payment reminders-um, stock checks, retailers-kku automatic replies, billing software-la endha change-um.
- **Exceptions:** theriyaadha products allathu retailers, padikka mudiyaadha photos, forward panna PDFs original message-oda review queue-kku pogum.
- **Access (client kudukkanum):** oru provider vazhiyaa WhatsApp Business Platform account, Meta business verification 4 December-kkulla aarambichu 14 December-kkulla ready; codes-oda product, retailer lists, 4 December-kkulla; billing software ethukkitta oru CSV file.
- **Data:** Retailer pergal, phone numbers, orders ellaam provider, automation server (India-la host pannadhu), AI provider-oda API vazhiyaa pogum. Raw messages-um photos-um 90 naalukku appuram delete aagum. Rendu order staff-um owner-um mattum thaan log in panna mudiyum. Rendu providers koodavum processor terms go-live-kku munnaadi confirm aagum.
- **Risks:** Verification delay aagudhu (owner: client; adhuvaraikkum oru test number-la build panradhu). Photos padikka mudiyala (owner: Ritika; adhai review-kku anuppi, rate-a vaaraa vaaram report panradhu). Staff check panradhai niruthiduraanga (owner: Sanjay Jain; ovvoru order-kkum oru confirm click venum, koodave oru weekly spot check).
- **Assumptions:** Client product list-a update-aa vachiruppaanga; CSV format maaraadhu; volumes oru naalaikku 250 orders-kku keezha irukkum.
- **Success:** Entry time oru order-kku sumaar 3 nimishathula irundhu sumaar 1 nimisham; thappaana quantities innaikku irukkura 2%-a vida adhigamaagak koodaadhu, target 1%.
- **Acceptance:** October 2026-la irundhu client choose panna 200 in-scope text, photo orders. Client-oda accountant bill panna invoices-la irundhu answer key-a 7 December-kkulla thayaar pannuvaaru. Product code-um quantity-um rendume invoice kooda match aana oru line correct. Pass: staff review-kku munnaadi kurainjadhu 90% lines correct, ovvoru exception-um review queue-la. Sign-off: Sanjay Jain, ezhuthula, test mudinju anju working days-kkulla.
- **Support:** Go-live-kku appuram 30 naal fixes. Pudhu formats, fields allathu systems, client pakkathula nadakkura changes, idhellaam oru naalaikku ₹7,500-la change requests.
- **Price-um timeline-um:** ₹90,000 fixed, GST thani, sign pannumbodhu ₹36,000, acceptance-la ₹36,000, support mudiyumbodhu ₹18,000. Maasathukku sumaar ₹9,000 running costs-a client pay pannuvaanga. Acceptance test 28 December vaarathula; WhatsApp access 14 December-kkulla ready aana go-live 4 January 2027, illanna delay evvalavo avvalavu late.

### Rendu vaaram kazhichu

Owner retailers-kku automatic payment reminders kekkuraaru. Scope adhai out-nu list panniyirukku, adhanaala Ritika adhai oru quote-oda phase 2 list-la poduraanga, adhu yen chinna vishayam illai-nnum explain panraanga. Kadaisi 24 mani nerathula message pannaadha oru retailer-kku pora reminder oru Meta-approved template-a use pannanum, deliver aagura ovvonnukkum charge undu. Udhaaranamaa, 300 retailers × 4 reminders-na maasathukku 1,200 utility messages; onnukku sumaar ₹0.115-la (India-kku third-party reports kudukkura figure, November 2026-la check pannadhu; Meta-voda rate card-la confirm pannunga), adhu GST-kku munnaadi sumaar ₹138. Panam chinnadhu; velai chinnadhu illa: template approval, retailers-oda consent, erkanave pay panna oru kadaikku reminder anuppura risk. Indha conversation rendu nimisham thaan aagum.

### Go-live aagi moonu vaaram kazhichu

Rendu requests varudhu. Oru order-la 20 items-kku mela irundhaa CSV lines-a vittududhu: system scope-a break pannudhu, adhanaala adhu oru free fix. Upgrade aana billing software pudhu columns-a edhirpaarkkudhu: adhu client pakka change, adhanaala arai naalukku oru change request.

## Podhuvaa panra thappugal

- **Samples illaadha scope,** allathu nallaa theriyanum-nu therndhedutha samples-oda scope.
- **Edhu out-nu sollaama irukkuradhu.** Ezhudhaadha exclusions free work-aa maarum.
- **Access-a kadaisiyila yosikkuradhu.** Meta verification mattume build-oda sila pagudhigalai vida adhiga neram edukkalaam.
- **Answer key-um named signer-um illaadha acceptance.** Test oru opinion-aa maaridum.
- **Lines-a measure panni orders-a promise panradhu.** 90% lines correct-aa irundhaalum, niraiya orders-a innum fix panna vendiyirukkum.
- **Data section illaama irukkuradhu.** Mudhal privacy kelviye go-live-a niruthidum.
- **Fix-kkum change-kkum naduvula kodu illaadhadhu.** Ovvoru request-um "broken-aa irukku"-nu thaan varum.
- **Running costs-a maraikkiradhu,** allathu owner padikka mudiyaadha oru scope ezhudhuradhu.

## Practice pannunga

Keezha link panniyirukkura project scope pathina Atlassian-oda guide-aiyum, user stories pathina GOV.UK-oda guide-aiyum padinga.

1. **Samples.** Unga process map-la irukkura oru idea-kku, 20-la irundhu 40 real allathu realistic inputs-a collect panni count pannunga, ovvoru type-kkum oru decision-oda.
2. **Scope.** Padhinoru pagudhigalaiyum onnu rendu pakkathula saadhaarana vaarthaigalla ezhudhunga, Ritika-vodadhai kooda compare pannunga.
3. **Acceptance.** Anju-pagudhi test-a ezhudhi, adhai eppadi run pannuvaanga-nnu vera oruthar-kitta kelunga. Avangalukku oru kelvi irundhaa, adhu innum mudiyala.
4. **Price.** Contingency-oda oru effort table-aiyum oru running-cost table-aiyum build pannunga, ovvoru price-kkum date pottu.

**Mudinjadhu-nnu eppo sollalaam:** unga scope-a business owner kitta kuduthu, edhu in, edhu out, success eppadi measure aagum, evvalavu cost aagum-nu avangalai ezhuthula othukka vaikka mudiyum.
