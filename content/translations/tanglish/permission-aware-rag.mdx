## Idhu enna

Oru RAG system pala sources-la irundhu text-a oru index-kku copy pannum. Andha sources-kku access rules irundhuchu: HR-ku mattum thirandha oru SharePoint site, oru project team-oda share panna drive, oru customer-oda account manager-ku mattum theriyura ticket. Neenga seiyaama index andha rules-a vechukkaadhu.

**Permission-aware RAG** (security trimming illa document-level access control-nu-um solluvaanga) retrieval, kekkura user original system-la paakka allowed-aana passages-a mattum eppavum return pannum-nu urudhi pannum. SharePoint-la user andha document-a open panna mudiyalana, assistant adha quote panna mudiyaadhu.

```flow
title: Ingestion
SharePoint file + adhoda permissions -> Chunk text + allowed_groups, allowed_users | illa-na? yaarukkum theriyaadhu
SharePoint file + adhoda permissions -[ovvoru 10 nimishathukkum thirumba sync]-> Chunk text + allowed_groups, allowed_users
```

```flow
title: Query
User sign in aagum -> Verified token | user, groups
Verified token -> Filter-oda search | allowed_groups user-oda oru group-a share pannum, search-kulla, ranking-kku munnaadi
Filter-oda search -> Permitted chunks mattum model-kku pogum
```

Indha lesson Mumbai-la oru asset management company-oda assistant-a follow pannum, research notes, HR policies, board papers, client agreements mela.

## Idhu eppadi work aagudhu

**Ingestion-la rights-a capture pannunga.** Oru document-a index panna podhu, yaar padikkalaam-nu-um fetch pannunga: source system-oda permissions-la irundhu users-um groups-um. Ovvoru chunk-layum metadata-aa store pannunga, example `allowed_groups: ["hr-core", "leadership"]`, `allowed_users: [...]`.

**Search-kulla filter pannunga.** Query time-la, user-oda identity-yaiyum groups-aiyum avanga verified sign-on token-la irundhu eduthu, oru filter serunga: `allowed_groups` user-oda groups-oda overlap aagura, illa `allowed_users` avangala kondirukkura chunks mattum. Filter vector illa keyword search-kulla, ranking-kku munnaadi run aaganum, appo restricted chunks candidate list-ku varavae maattaanga. Retrieval-kku apram filter pannina scores, counts, timing vazhiyaa leak aagum, user-ku results-e illaama pogavum vaippu irukku.

**Deny by default.** Permission data illaadha chunk, fix aagura varaikkum yaarukkum theriyaadhu. "Rule illa"-nu sonna adha "public"-nu eppavum eduthukkaadheenga.

**Rights-a sync-la vechukkunga.** Permissions daily maarum: makkal teams-la serraanga, files share aagudhu, sites lock aagudhu. Rights-a content-a vida thaniyaa, oru schedule-la illa change events-la irundhu thirumba sync pannunga. Lag-a measure panni client-oda ottukkunga ("permission changes 15 nimishathukkulla effect aagum").

**Groups periya aagum.** Users nooru kanakkana groups-la irukkalaam, onnukkulla onnu nest aagi. Nested groups-a sign-in illa index time-la resolve pannunga, sensible-aa cache pannunga.

**Alternative: source-la check pannunga.** Sinna result sets-ku, candidates-a retrieve panni, apram ovvoru document-aiyum user-a vechu open panna mudiyumaa-nu source system-a kekkalaam. Idhu eppavum current, aana slow, edhuvum model-kku pogradhukku munnaadi nadakkanum.

**Test pannunga.** Vera vera roles irukkura test users-aiyum "must not see" questions-oda oru set-aiyum build panni, CI-la run pannunga.

**Access-a enga enforce pannalaam:**

| Approach | Eppadi work aagum | Strengths | Weaknesses |
| --- | --- | --- | --- |
| Index-la filter | Chunks-la permissions store aagum; search-la filter | Fast, scale aagum | Permission sync thevai; sinna lag |
| Source-la check | Ovvoru candidate-kkum source system-a kekkum | Eppavum current | Slow; neraya calls |
| Group-ku thani indexes | Ovvoru audience-kkum oru index | Konja groups-ku simple | Neraya groups-la udaiyum |
| Retrieval-kku apram filter | Mudivula restricted results-a drop pannum | Edhuvum illa | Leaks-um empty results-um |

**CI-la persona tests.** Ovvoru role-kkum test users-a create pannunga, example analyst, HR staff, director, contractor, therinja group memberships-oda. Ovvoruthar-kkum, avanga paakkanum-nu documents-um eppavum paakkakoodaadhu-nu documents-um irukkura questions ezhudhunga. Model-oda answer-la illa, retrieved chunk ids-la assert pannunga, yenna aabathu oru restricted chunk prompt-kulla varradhu thaan. Ingestion, search, illa permission sync-la ovvoru change-kkum indha tests-a run pannunga.

**Sync window-a ottukkradhu.** Index-la permission changes udane effect aagaadhu. Unmaiyaana lag-a measure panni, client-oda security team-oda ezhudhula ottukkunga, sync fail aanaalum late-aa odinaalum alert pannunga. Romba sensitive sources-ku, example board papers, ranandaavadhu layer-aa source-la check pannradhai yosinga.

**Schema-la deny by default.** Access data illaama oru chunk-a index panna mudiyaadha maadhiri aakkunga:

```sql
CREATE TABLE chunks (
  id text PRIMARY KEY,
  doc_id text NOT NULL,
  body text NOT NULL,
  embedding vector(384) NOT NULL,
  allowed_groups text[] NOT NULL CHECK (cardinality(allowed_groups) > 0)
);
CREATE INDEX ON chunks USING gin (allowed_groups);

-- The search, with the user's groups from the verified token as $2:
SELECT id, body FROM chunks
WHERE allowed_groups && $2
ORDER BY embedding <=> $1
LIMIT 20;
```

`&&`-na "rendu arrays-um kuraintha oru value-vaiyaavadhu share pannum". Groups illaadha oru chunk-a insert-ae panna mudiyaadhu.

**Row-level security-oda ranandaavadhu pootu.** Application database session-la user-oda groups-a set pannina, yaaraavadhu `WHERE`-a marandhaalum Postgres adhe rule-a enforce pannum:

```sql
ALTER TABLE chunks ENABLE ROW LEVEL SECURITY;
CREATE POLICY read_by_group ON chunks FOR SELECT
  USING (allowed_groups && string_to_array(current_setting('app.user_groups', true), ','));
-- per request, inside a transaction:
-- SELECT set_config('app.user_groups', 'hr-core,all-staff', true);
```

Table-a own pannaadha oru role-a vechu connect pannunga, yenna table owners policies-a skip pannuvaanga, neenga `ALTER TABLE chunks FORCE ROW LEVEL SECURITY`-um run pannina thavira.

**Nested groups-a flatten pannunga.** Directories groups-kulla groups-a vaikkum. Cycles-ku oru guard-oda, onnu thaan resolve pannunga:

```python
def expand_groups(user_groups, parents_of):
    """parents_of: dict mapping a group to the groups that contain it."""
    seen, stack = set(), list(user_groups)
    while stack:
        g = stack.pop()
        if g in seen:
            continue
        seen.add(g)
        stack.extend(parents_of.get(g, []))
    return sorted(seen)
```

Result-a session-ku cache pannunga, user thirumba sign in pannina illa directory maarina refresh pannunga.

**Answers-a illa, ids-a check panra persona tests.**

```python
import pytest

PERSONAS = {
    "analyst":    {"groups": ["all-staff"],             "never": {"board-2026-q3-c1", "salaries-c4"}},
    "hr_staff":   {"groups": ["all-staff", "hr-core"],  "never": {"board-2026-q3-c1"}},
    "contractor": {"groups": ["contractors"],           "never": {"handbook-c2", "salaries-c4"}},
}
QUESTIONS = ["What did the board decide about the Pune office?", "What is the salary band for level 5?",
             "What is the leave policy?"]

@pytest.mark.parametrize("persona", PERSONAS)
def test_never_retrieves_restricted(persona, search):
    p = PERSONAS[persona]
    for q in QUESTIONS:
        ids = {c["id"] for c in search(q, groups=p["groups"])}
        assert not ids & p["never"], f"{persona} retrieved {ids & p['never']} for: {q}"
```

Oru forbidden chunk retrieve aanaalae test fail aagum, oru model adha repeat panradhukku romba munnaadiyae.

**Caches, summaries, memories-um leak aagum.** Restricted documents-la irundhu build panna oru cached answer, oru stored conversation summary, illa agent memory-kkum adhe access rules irukkanum, illa ovvoru user-kkum thaniyaa key pannanum. Retrieval-kku apram retrieved text store aagura ovvoru idatthaiyum check pannunga.

## Oru worked example

Mumbai-la oru asset management company research notes, HR policies, board papers, client agreements mela oru assistant vennum-nu kekkudhu.

Ingestion-la, oru connector ovvoru SharePoint file-aiyum adhoda permissions-aiyum padichu, groups-a expand panni, ovvoru chunk-layum `allowed_groups`-a store pannudhu. Query time-la, API user-oda groups-a avanga OIDC token-la irundhu padichu, filter-a hybrid search-la serkkudhu.

Aindhu personas-oda test pannum bodhu:

- Oru analyst "Last board meeting-la merger pathi enna pesinaanga?"-nu kekkaraanga. Board-paper chunks onnum retrieve aagala; assistant andha topic-la accessible documents onnum kidaikkala-nu solludhu.
- Oru director adhe question-a kekkaraanga, board minutes-a cite panna oru answer kidaikkudhu.
- Oru analyst "Senior managers-ku notice period enna?"-nu kekkaraanga. Ella employees-kum thirandhu irukkura HR policy retrieve aagudhu; confidential salary bands file aagala.

Pilot-la, HR team oru draft policy-a restrict pannudhu. Permission sync ovvoru pathu nimishathukkum run aagudhu, adhanaala pathu nimisham varaikkum pazhaya rights apply aagum. Client-oda security team indha window-a ezhudhula accept pannudhu, sync fail aana alert venum-nu kekkudhu.

| Persona | Question | Result |
| --- | --- | --- |
| Analyst | "Last board meeting-la merger pathi enna pesinaanga?" | Board-paper chunks illa; accessible documents illa-nu solludhu |
| Director | Adhe question | Board minutes-a cite panna answer |

## Podhuvaa panra thappugal

- **Retrieval-kku apram filter panradhu.** Restricted chunks results-a influence pannum, leak aagalaam. Search-kulla filter pannunga.
- **Permissions illaadhadha public-nu eduthukkradhu.** Deny by default.
- **Content-a sync panni rights-a sync pannaadhadhu.** Innaiku lock panna document index-la theriyum.
- **Request body-la irundhu identity-a nambradhu.** User-aiyum groups-aiyum verified token-la irundhu mattum edunga.
- **Negative tests illa.** Ovvoru persona-vum paakka vendiyadhai mattum illa, paakkakoodaadhadhaiyum test pannunga.
- **Restricted documents-la irundhu build panna answers-a users-kulla cache pannradhu.**
- **Permission tests-la model-oda answer-la assert panradhu, retrieved ids-la illa.**
- **Nested groups expand aagala**, adhanaala users paakkanum-nu irukkura documents-a miss pannuvaanga, illa tests thappaana kaaranathukkaaga pass aagum.

## Permission-aware retrieval vendaam-na eppo

- **Ellarum ellaathayum padikkalaam**, public policies illa publish panna handbook maadhiri.
- **Oru user-oda sondha documents mattum**, index ovvoru user-kkum thaniyaa irukkum bodhu.
- **Konjam clear audiences**, audience-ku thani indexes simple-aa irukkum.

## Demo-la irundhu production-ku

- **Access-a query-layum database-layum enforce pannunga**, deny by default.
- **Persona tests-a CI-la run pannunga**, ingestion, search, sync-la ovvoru change-kkum.
- **Permission sync lag-a measure pannunga**, ottukkitta window-ku edhiraa alert pannunga.
- **Caches, summaries, memories-a user-vaareeya illa access group-vaareeya scope pannunga.**
- **Ovvoru search-kkum use panna groups-a log pannunga**, audits-ku.

## Practice pannunga

Microsoft-oda security filter pattern-aiyum, access control-oda RAG pathi Pinecone-oda article-aiyum padinga.

1. Unga RAG index-la ovvoru chunk-kum `allowed_groups` field serunga, unga documents-la kuraintha moonu groups irukkura maadhiri.
2. User-oda groups-a oru (real illa simulated) verified token-la irundhu padichu search-kulla filter pannunga.
3. Moonu personas-kku aindhu "must not see" tests ezhudhi, unga test suite-la run pannunga.
4. Row-level security policy-a serthu, venumae unga search-la irundhu WHERE clause-a remove panni, restricted chunks innum varalanu confirm pannunga.

Innum depth-ku, Chip Huyen-oda *AI Engineering* (O'Reilly, 2025) chapter 10 private information leak aagaama irukka guardrails-a cover pannudhu, chapter 6 retrieval-a cover pannudhu.

**Mudinjadhu-nu eppo sollalaam:** rendu users adhe question-a kettu, vera vera sariyaana answers vaanguradha kaattalaam, oru restricted document model-kku eppavum pogaadhu-nu prove panra oru test-um irukkum.
