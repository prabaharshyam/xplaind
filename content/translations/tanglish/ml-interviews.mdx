## Idhu enna

Oru ML engineer interview loop-na pala rounds-oda set, ovvoru round-um oru skill-a test pannum. Oru round-la brilliant-aa irukkuradhaala illa, ella round-layum solid-aa irundhaa thaan pass aaveenga. ML-la strong-aana aalungalum, DSA coding maadhiri avanga thayaar pannaadha round-la fail aagalaam.

| Round | Enna test panraanga | Oru strong candidate enna kaattuvaanga |
| --- | --- | --- |
| Online assessment allathu DSA coding | Oru timed problem-la data structures, algorithms | Sariyaana, test panna solution, adhoda time, space complexity |
| ML coding | Pandas, NumPy, oru metric allathu oru chinna algorithm-a scratch-la irundhu | Ties, empty inputs maadhiri edge cases-a handle panra clean code |
| ML fundamentals | Models, losses, metrics, validation eppadi work aagudhu | Mechanism, trade-off, oru default choice |
| ML system design | Oru thelivillaadha business problem-a deploy aana system-aa maathuradhu | Thelivaana structure, sathamaa solra numbers, production thinking |
| LLM allathu GenAI design | RAG, evals, prompting vs fine-tuning, cost, latency | Mudhalla measurement, appuram adhai meet panra simplest design |
| Project deep-dive | Unga oru project, aazhamaa | Numbers, decisions, thappugal, enna maathuveenga |
| Behavioural allathu hiring manager | Ownership, conflict, failure | Real numbers-oda chinna STAR stories |

Mix company-kku company maarum. Google, Meta maadhiri periya product companies-la ML roles-kku pona sila candidates, ML design, behavioural rounds koodave standard algorithm coding rounds irundhadhaa solraanga. Sila companies adhukku badhilaa oru take-home allathu practical ML coding task kudukkuraanga. Adhanaala rounds list-a recruiter-kitta kelunga; andha kelviya avanga edhirpaarppaanga.

```flow
title: 40 nimishathula ML system design
1 Goal, metric -> 2 Framing, label -> 3 Data -> 4 Features | sumaar 15 nimisham
4 Features -> 5 Baseline, appuram model -> 6 Evaluation | offline, A/B, sumaar 12 nimisham
6 Evaluation -> 7 Serving | batch allathu real time, oru fallback-oda -> 8 Monitoring | sumaar 8 nimisham

```

Keezha, ovvoru round-aa paakkalaam, appuram "UPI merchant payments-kku fraud detection design pannunga"-ngra kelvikku oru muzhu badhil.

## Idhu eppadi work aagudhu

### DSA round

Indha round perumbaalum software engineers-kku irukkura maadhiriye thaan. Role ML-ngradhaala easy problems varum-nu edhirpaarkkaadheenga; indha round mattume oru loop-a kavizhkkalaam-nu therinjukkonga. Big-tech ML roles-kku pona sila candidates medium, sila neram hard problems vandhadhaa solraanga.

**Enna test panraanga.** Manappaadam panna answers illa, indha patterns-a kathukkonga.

- Hash maps, two pointers, sliding windows-oda arrays, strings.
- Sorting, binary search, intervals (merge, overlap).
- Stacks, queues, heaps (top k, running median).
- Trees, graphs: BFS, DFS, shortest paths, topological sort.
- Basic level-la dynamic programming (onnu, rendu dimensions).

**Sathamaa pesikkitte solve pannunga.** Interviewers code-a mattum illa, process-aiyum score pannuvaanga.

1. Problem-a unga vaarthaigalla thirumba sollunga, inputs, sizes, edge cases pathi kelunga.
2. Oru chinna example-a kaiyaala work pannunga.
3. Oru brute-force solution-aiyum adhoda cost-aiyum sollunga.
4. Adhai improve pannunga, pudhu idea yen work aagudhu-nnu sollunga.
5. Thelivaana names-oda code pannunga.
6. Unga example-layum oru edge case-layum test pannunga, appuram time, space complexity sollunga.

ML interviewers oru DSA problem-a data mozhiyila pottu kekkalaam. Udhaaranamaa: "Time order-la `(merchant_id, timestamp)` pairs-aa UPI payments kuduthirukku, endha 60-second window-layaavadhu `k`-a vida adhiga payments irukkura merchants-a flag pannunga." Idhu hash map-oda oru sliding window:

```python
from collections import defaultdict, deque

def flag_bursts(events, k, window_s):
    """events: (merchant_id, unix_seconds) sorted by time.
    Return merchants with more than k payments inside any window_s seconds."""
    recent = defaultdict(deque)          # merchant -> timestamps still in the window
    flagged = set()
    for merchant, t in events:
        q = recent[merchant]
        q.append(t)
        while q[0] <= t - window_s:      # drop payments older than the window
            q.popleft()
        if len(q) > k:
            flagged.add(merchant)
    return flagged

events = [("m1", 0), ("m2", 5), ("m1", 10), ("m1", 20), ("m1", 70), ("m2", 80)]
print(flag_bursts(events, k=2, window_s=60))   # {'m1'}
```

Ovvoru timestamp-um adhoda queue-kkulla adhigapatcham oru thadavai varum, oru thadavai pogum, adhanaala n events-kku time O(n). Appuram follow-up risk-a sollunga: idhuvarai vandha ovvoru merchant-kkum memory valarum, yenna idle merchants-oda queues-a yaarum remove panradhilla.

**Thayaarippu.** `collections`, `heapq`, `bisect` vechu Python-la practice pannunga. Ovvoru pattern-kkum sila problems solve pannunga, fail aanadhai oru vaaram kazhichu thirumba pannunga, adhuvum muzhukka pesikkitte timed mocks-la. Sathamaa yosikkuradhu, amaidhiyaa solve panradhai vida vera skill, test panradhum adhai thaan.

### ML coding round

Inga puzzles illa, data code ezhuduveenga: oru pandas groupby, join allathu rolling window; time vechu oru split; scratch-la irundhu oru metric; NumPy-la k-means allathu logistic regression. Indha example rendu favourites-a serkkudhu: label delay-a madhikkura oru time split, k-la precision, recall.

```python
import numpy as np
import pandas as pd

def split_with_gap(df, test_start, test_end, delay_days, labels_pulled_on):
    delay = pd.Timedelta(days=delay_days)
    test_start, test_end = pd.Timestamp(test_start), pd.Timestamp(test_end)
    # Test labels must have matured too, or late fraud looks like "not fraud".
    assert test_end + delay <= pd.Timestamp(labels_pulled_on), "test labels not mature"
    train = df[df["txn_time"] < test_start - delay]   # what you could know on test_start
    test = df[(df["txn_time"] >= test_start) & (df["txn_time"] < test_end)]
    return train, test

def precision_recall_at_k(y_true, scores, k):
    y_true = np.asarray(y_true)
    top_k = np.argsort(-np.asarray(scores))[:k]     # the k highest scores
    caught = y_true[top_k].sum()
    return caught / k, caught / y_true.sum()

df = pd.DataFrame({"txn_time": pd.date_range("2026-01-01", "2026-06-30", freq="D")})
train, test = split_with_gap(df, "2026-05-01", "2026-06-01", 60, "2026-08-01")
print(train["txn_time"].max().date(), len(train), len(test))   # 2026-03-01 60 31

y = [1, 0, 0, 1, 0, 0, 0, 1, 0, 0]
s = [0.9, 0.8, 0.1, 0.7, 0.3, 0.2, 0.6, 0.4, 0.05, 0.15]
p, r = precision_recall_at_k(y, s, 3)
print(round(p, 2), round(r, 2))   # 0.67 0.67
```

Gap yen? Fraud labels vara 60 naal varai aagudhu-nnu vechukkonga. 1 May annaikku deploy aana oru model, final labels irukkura transactions-la mattum thaan train aagiyirukka mudiyum, adhaavadhu sumaar 2 March-kku munnaadi irundhavai. Late-aa edutha labels-oda March, April rows-la train pannaa, appo ungalukku therinjirukka mudiyaadha knowledge-a use pannureenga, adhanaala test score romba optimistic-aa varum. Oru real retraining job-la, delay-a vida pudhusaana rows unlabelled, negatives illa. Kekkaamaleye idhai sonnaa adhu oru strong signal.

### ML fundamentals: mechanism, trade-off, default-oda badhil sollunga

Oru strong badhil mechanism, trade-off, unga default choice moonaiyum sollum. Rendu model answers:

**"Random forests-kkum gradient boosting-kkum enna vithiyaasam?"** "Rendume niraiya decision trees-a serkkudhu. Oru random forest aazhamaana trees-a thanithaniyaa train pannudhu, ovvonnum oru bootstrap sample-la, ovvoru split-layum features-oda oru random subset-la irundhu therndheduthu, appuram ellaathaiyum average pannudhu. Adhu mukkiyamaa variance-a kuraikkudhu, adhanaala konjam thaan tuning venum, mosamaa overfit aagradhu aridhu. Gradient boosting aazhamillaadha trees-a onnukku appuram onnaa train pannudhu, ovvonnum idhuvarai irukkura trees-oda errors-a fit pannudhu. Adhu bias-a kuraikkudhu, tabular data-la perumbaalum adhu thaan jeyikkum, aanaa overfit aagalaam, adhanaala learning rate, depth-a tune panni early stopping use pannuven. Tabular data-kku en default boosting, udhaaranamaa LightGBM allathu XGBoost, oru quick baseline-aa random forest."

**"Data leakage-a eppadi kandupidippeenga?"** "Leakage-na prediction time-la model-kku kidaikkaadha information-a adhu paakkudhu. En mudhal signal, problem-kku romba adhigamaa nallaa irukkura oru score. Appuram moonu idangalai check pannuven. Features: oru top feature outcome-kku appuram record aagudhaa, churn model-la `refund_issued` maadhiri? Split: ore customer allathu kittathatta duplicate rows train-layum test-layum irukkaa, allathu training data test data-kku appuram varudhaa? Preprocessing: scaling allathu target encoding ella data-layum fit aachaa? Fix: ovvoru feature-aiyum prediction time annaikku irundhapadi compute pannunga, time allathu customer vechu split pannunga, preprocessing-a training data-la mattum fit pannunga."

Ovvonnum oru mechanism, oru concrete example, oru decision-a solludhu; edhuvum definition-a oppikkala. Indha topics-kkum idhe shape-la thayaar pannunga.

| Topic | Oru nalla badhiloda core |
| --- | --- |
| Bias, variance | Training, validation error rendume high-na underfitting; rendukkum naduvula periya gap-na overfitting. Learning curves-la irundhu padinga |
| Regularisation | L2 ella weights-aiyum surukkum; L1 siladhai sariyaa zero-kku thallum, adhu features-a select pannum. Rendume konjam bias-a kuduthu variance-a kuraikkum |
| Imbalanced data | Accuracy emaathum. PR AUC use pannunga, business act panna mudiyura threshold allathu capacity-la precision, recall paarunga |
| Cross-validation | Independent rows-kku K-fold; rows time order-la irundhaa allathu ore customer-a share pannaa time-based allathu grouped folds |
| Logistic regression | Oru linear score-a sigmoid vazhiyaa anuppuradhu, log loss-oda train panradhu. Fast, explain panna easy, oru strong baseline |
| Attention | Ovvoru token-oda query-yum ovvoru token-oda key kooda compare aagum; scores-oda softmax avangaloda values-kku weight kudukkum |

Adhigamaa kekkura topics-la I1 lessons "Cross-validation and leakage", "Choosing a metric" innum aazhamaa pogum.

### ML system design

Diagram-la irukkura onbadhu steps-a varisaippadi use pannunga, numbers-a sathamaa sollunga. Moonu steps-kku adhiga gavanam venum. *Framing*-la, label enga irundhu varudhu, evvalavu late-aa varudhu-nnu sollunga. *Evaluation*-la, reality-kku match aagura oru split-aiyum, operating point-la oru metric-aiyum, segment vaariyaa therndhedunga. *Serving*-la, latency budget-aiyum oru fallback-aiyum sollunga.

**Offline vs online.** Oru nalla offline score nalla business result-a guarantee pannaadhu, yenna live users model-kku react pannuvaanga. Oru primary metric-um, complaint rate allathu latency maadhiri guardrails-um irukkura oru A/B test-a plan pannunga. Pitfalls-a therinjukkonga. Result significant-aa therinja udane niruthuradhu ("peeking") poiyaana wins-a adhigamaakkum. Oru muzhu vaarathai vida kuraivaana test, weekday, weekend patterns-a miss pannum. Vishayangalai block panra allathu maraikkura oru model, enna nadandhirukkum-nu paakka vidaadhu, adhanaala oru chinna random holdout vechukkonga.

**"Why not X?"-a handle panradhu.** Trade-off-oda badhil sollunga. Udhaaranamaa: "Oru deep model udhavalaam, aanaa tabular features, late-aana labels irukkumbodhu, gradient boosting perumbaalum kittathatta adhe accuracy kudukkum, sila nimishangalla train aagum, risk team-kku explain pannavum easy. Trees miss panra patterns irukku-nnu error analysis kaattinaa oru deep model try pannuven."

### LLM, GenAI design kelvigal

Sila ML loops-la ippo oru large language model mela build panna product pathi oru kelvi varudhu, udhaaranamaa:

- "Support tickets-a 40 categories-aa pirikka prompting use pannanumaa, RAG-aa, fine-tuning-aa?"

Goal-aiyum, thappaana badhiloda cost-aiyum clarify pannunga, appuram work aagakkoodiya simplest approach-a therndhedunga: answers maarikkitte irukkura documents-la irundhu varanum, citations venum-naa RAG; task simple-aa irundhaa sila examples-oda prompting; volume adhigam, cost allathu latency mukkiyam-naa oru chinna model-a fine-tune panradhu. Niraiya labelled history irukkura ticket sorting-kku, oru classic classifier-aiyum baseline-aa sollunga. Appuram measurement-a mudhalla vainga: real kelvigaloda oru eval set, answers-la irundhu thaniyaa score panna retrieval, relevant-aa edhuvum kidaikkalai-nnaa enna panradhu-nnu oru plan. "Build a RAG app", "Test sets and evals", "Prompting, RAG or fine-tuning", "The design interview" lessons ovvoru pagudhiyaiyum cover pannudhu.

### Project deep-dive, behavioural

**Project deep-dive.** Onnu rendu projects-a aazhamaa thayaar pannunga: problem, data, baseline, enna try panneenga, numbers-oda results, enna thappaa pochu, adutha enna. Oru team project-la neengale enna panneenga-nnu thelivaa sollunga.

**Behavioural.** STAR (situation, task, action, result) use pannunga, numbers-odavum oru lesson-odavum. Oru illustrative failure story (unga sondha real story-a use pannunga):

- *Situation*: "Pune-la oru insurance sales team-kku naan panna lead-scoring model live aachu. Rendu vaarathula, top-scored leads-la conversion testing-la irundha sumaar 9%-la irundhu sumaar 4%-kku vizhundhuchu."
- *Task*: "Model ennodadhu, cause-a seekkiram kandupidikkanum."
- *Action*: "Training, live feature values-a compare pannen. Oru 'last call outcome' field, training data-la call mudinja appuram fill aagiyirundhuchu, aanaa scoring time-la blank-aa irundhuchu. Adhu leakage. Features-a scoring time annaikku irundhapadi rebuild pannen, training, live features-a compare panra oru pre-launch check-a serthen."
- *Result*: "Offline AUC 0.91-la irundhu 0.78-kku vizhundhuchu, aanaa top leads-la live conversion sumaar 7%-kku thirumba vandhuchu. Ippo training-kku munnaadi ovvoru feature-um prediction time-la irukkaa-nnu check panren."

## Oru worked example

Kelvi: "Oru payments company-kku fraudulent UPI merchant payments-a detect panra oru system-a design pannunga." Keezha irukkura numbers interview-la neenga solra assumptions, real figures illa.

1. **Goal**: kuraivaana analyst nerathoda fraud losses-a kuraikkanum. Latency pathi kelunga; payment flow block panna sumaar 100 ms kudukkudhu, koodave oru review queue irukku-nnu vechukkonga.
2. **Framing**: ovvoru payment-kkum binary classification. Labels chargebacks-la irundhum confirm aana investigations-la irundhum varudhu. Avai 60 naalukkulla varudhu-nnu assume pannunga.
3. **Data**: payments, merchant profiles, device, network signals, pazhaya fraud. Fraud aridhu; payments-la 0.05%-nu assume pannunga.
4. **Features**: kadaisi oru mani nerathula oru merchant-kku ethana payments, merchant-oda vazhakkamaana amounts kooda compare panna amount, pudhu device, naaloda neram, merchant category. Ellaame oru feature store-la irundhu payment time annaikku irundhapadi compute aagum, adhanaala training-um serving-um match aagum.
5. **Model**: oru rules baseline, appuram class weights-oda gradient-boosted trees. Pinnaadi, merchants, devices, accounts-a inaikkura graph features.
6. **Evaluation**: mela irukkura code maadhiri 60-day gap-oda oru time split. Analysts handle panna mudiyura alert volume-la PR AUC, precision, recall-a merchant category, region vaariyaa measure pannunga. Appuram traffic-oda oru pangula oru A/B test ottunga.
7. **Serving**: Real-time scoring, model time out aanaa rules-kku fallback. Rendu thresholds: romba high score-kku mela auto-block, adhukku keezha review queue.
8. **Monitoring**: Key features-la drift, alert rate-la maatrangal, monthly retraining. Block aana payments fraud-aa illaiyaa-nnu orubodhum theriyavaraadhu, adhanaala block aagappora payments-la oru chinna random sample-a block pannaama analysts-kitta anuppunga.
9. **Risks**: unmaiyaana chinna merchants-a block panradhu (oru appeal route kudunga), fraudsters maarikkiradhu (adikkadi retrain pannunga), regions muzhukka samamillaadha error rates.

Ippo numbers-a sathamaa sollunga. Accuracy yen thappaana metric-nu avai kaattum.

| Quantity (assumed) | Value |
| --- | --- |
| Oru naalukku payments | 20 lakh |
| Fraud rate | 0.05%, adhaavadhu oru naalukku 1,000 frauds |
| "Never fraud"-oda accuracy | 99.95%, pidicha fraud zero |
| Analysts review panna mudiyura alerts | Oru naalukku 2,000 |
| Top 2,000 alerts-la frauds (example) | 600 |
| 2,000-la precision | 600 / 2,000 = 30% |
| 2,000-la recall | 600 / 1,000 = 60% |

Appuram kelunga: "30% precision-la 60% fraud-a pidikkuradhu analyst cost-kku worth-aa, oru naalukku innum 500 reviews avangalukkaana selavai thirumba edukkumaa?" Adhu oru model-a oru business decision-aa maathudhu.

## Podhuvaa panra thappugal

- **DSA thayaarippai skip panradhu.** Periya product companies-la ML loops-la oru standard coding round irundhadhaa sila candidates solraanga, adhu oru strong ML candidate-aiyum kavizhkkalaam.
- **Neraa deep learning-kku thaavuradhu.** Oru baseline-la aarambinga, complexity-la ovvoru step erradhukkum kaaranam sollunga.
- **Label-a kandukkaama vidradhu.** Labels enga irundhu, evvalavu late-aa varudhu-ngradhu data, split, metric, retraining ellaathaiyum shape pannum.
- **Time-based problems-kku random allathu gap illaadha splits.** Rendume future information-a leak panni scores-a ethividum.
- **Imbalanced data-la accuracy-a quote panradhu.** Business act panna mudiyura capacity-la precision, recall sollunga.
- **Oru offline win-a launch-aa ninaikkuradhu.** A/B test, guardrails, holdout-a plan pannunga.
- **Serving allathu monitoring plan illaama irukkuradhu.** Latency budget, fallback, edhu retraining-a trigger pannum-nu sollunga.
- **Aazhamillaadha project stories.** Unga numbers, unga sondha contribution, unga thappugal therinjirukkanum.
