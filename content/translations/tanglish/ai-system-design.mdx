## Idhu enna

**AI system design**-na, build panradhukku munnaadi illa build pannum podhu, oru AI product-a paper-la plan panradhu. Adhu yaarukku, success eppadi measure pannapadum, adhoda components, oru request avai vazhiyaa eppadi pogudhu, enga fail aagalaam, production-la eppadi evaluate pannapadudhu, cover pannum. Oru short design document, team mudivugalla orumichchu oppukka, risks-a mudhalla pidikka, clients-ukkum reviewers-ukkum system-a explain panna help pannum.

```flow
User, an underwriter -> Web app -> API service -> Input guardrails
Input guardrails -> Hybrid search | department filter + effective date
Hybrid search -> Reranker -[top 5]-> Model in the insurer's cloud region
Model in the insurer's cloud region -[outage]-> Fallback model
Model in the insurer's cloud region -> Output guardrails -> Answer with citation links
Fallback model -> Output guardrails
```

Idhai sutthi: masked tracing, CI-la evals, latency, cost, feedback, refusals-ku dashboards.

Indha lesson, Mumbai-la oru general insurer-oda internal underwriting assistant-oda design-a follow pannum.

## Idhu eppadi work aagudhu

Oru practical design document, rendu-la irundhu naalu pages, cover panradhu:

**1. Users and goals.** Yaar use panraanga, entha task-ku, baseline-oda success metric (example-ku, "policy questions-ku median answer neram 6 nimishathula irundhu 2-kku keezha kuraikkanum").

**2. Requirements and constraints.** Volume, peak load, latency budget, oru request-ku cost, languages, data residency, privacy, compliance rules, yaar entha data paakkalaam.

**3. Components.** Interface; API service; retrieval (document ingestion, parsing, chunking, embeddings, index, hybrid search, reranking); prompt, model choices (oru fallback model-um); tools; guardrails; human review points; logging, tracing, evaluation.

**4. Request flow.** Oru request-ku enna nadakkudhu-nu step by step, ovvoru step-layum pogura data-oda. Oru simple diagram help pannum.

**5. Failure modes and guards.** Ovvoru component-kkum enna thappaa pogalaam, adhai edhu pidikkum:

- retrieval misses → hybrid search, metadata filters, recall evaluation;
- hallucination → grounding, citations, sources onnum sollaadhappo refusal;
- injection → least privilege, data marking, approvals;
- provider outage → retries, fallback model, graceful error;
- runaway cost → caps, budgets, alerts;
- stale data → re-indexing pipeline, freshness alerts.

**6. Evaluation.** Test set (size, sources, categories), retrieval-kum answers-kum metrics, launch bar, regressions CI-la eppadi pidikkapadum.

**7. Operations.** Deployment, monitoring signals, alerts, on-call, release process, data retention.

**8. Open questions and trade-offs.** Innum mudivu pannaadhadhu, adhoda options.

Interview-ku illa, build panreenga-naa, mudhal naalae ella boxes-aiyum varaiyaama, oru layer-a oru layer-aa valarkkunga. AI app-a layers-la (context, guardrails, router and gateway, caches, agents) valarkkura lesson andha order-a cover pannum.

**Failure-mode table:**

| Component | Enna thappaa pogalaam | Guard |
| --- | --- | --- |
| Parsing | Scanned tables kuzhambum | Table extraction; flag panna pages review |
| Retrieval | Superseded circulars mudhalla rank aagum | Effective-date filter |
| Retrieval | Sariyaana passage miss aagum | Hybrid search, reranker, recall track |
| Generation | Support illaadha claims | Citations thevai; sources onnum sollaadhappo refusal |
| Documents | Upload panna files-la injection | Write tools illa; content data-aa edukkapadum |
| Provider | Outage illa rate limits | Retries, fallback model, clear message |
| Cost | Kattuppadu illaadha usage | Per-user caps, daily budget alert |

**Design-a review panradhu.** User tap pannadhula irundhu answer varaikkum oru request-a walk through pannunga. Ovvoru box-layum moonu kelvigal kelunga: inga enna data irukku, yaar paakkalaam, indha pagudhi fail aanaalum slow aanaalum enna aagum. Security illa compliance reviewer-a mudhalla walk-through-ku kooptukkunga. "Indha data enga store aagudhu?" maadhiri kelvigal week one-la selavae illa, week ten-la romba selavaagum.

**Current-aa vachchukkradhu.** Document-a uyirulla ondrunu paarunga. Oru mudivu maarunaa, page-a update panni, date-um reason-um kadaisila oru short decision log-la note pannunga. Pudhu team members-um client reviewers-um chat threads-la irundhu history-a reconstruct pannaama, oru sariyaana page-a padippaanga.

**Code-la back-of-envelope numbers.** Capacity, rate limits, cost neraya design choices-a mudivu pannum; boxes varaiyum munnaadi adhai kanakku pannunga:

```python
def estimate(daily_requests, busy_hours=8, peak_factor=2.5,
             in_tokens=3_500, out_tokens=350, price_in=3, price_out=15, usd_to_inr=84,
             tpm_limit=400_000):
    """Prices in USD per million tokens; check current prices and note the date."""
    peak_per_min = daily_requests / (busy_hours * 60) * peak_factor
    tokens_per_min = peak_per_min * (in_tokens + out_tokens)
    cost_day = daily_requests * (in_tokens * price_in + out_tokens * price_out) / 1e6 * usd_to_inr
    return {
        "peak requests per minute": round(peak_per_min, 1),
        "peak tokens per minute": round(tokens_per_min),
        "within rate limit": tokens_per_min < tpm_limit,
        "cost per day ₹": round(cost_day),
        "cost per month ₹": round(cost_day * 30),
    }

print(estimate(daily_requests=20_000))
```

Peak tokens per minute provider limit-a thaandinaa, design-ku oru higher tier, caching, sila steps-ku sinna model, illa oru queue thevai. Maadhaanthira cost client-a achchariyappaduthinaa, ippo kandupidinga, launch-ku apram illa.

**Latency budget, step by step.** Oru target-um, ovvoru step-kkum oru allowance-um ezhudhi, adhukku ethiraa measure pannunga:

| Step | Allowance (p95) |
| --- | --- |
| Auth, request-a parse panradhu | 50 ms |
| Query rewrite (sinna model) | 400 ms |
| Hybrid search | 150 ms |
| 30 candidates-a reranking | 250 ms |
| Model, first token varra neram | 1,200 ms |
| First token varaikkum total | sumaar 2 s |

Ippo ovvoru component owner-kkum oru number irukku. Total vazhukkina, trace entha step allowance-a meeriyadhu-nu kaattum.

**Layers-la architecture.** Parts serkka oru useful order, avasiyamaanadhula irundhu optional varaikkum: nalla context-oda model call (retrieval, tools); inputs, outputs-ku guardrails; router, gateway (pala models, fallbacks, keys, budgets); caching; kadaisiyaa write actions-oda agent patterns. Ovvoru layer-um capability-yum pudhu failure modes-um serkkum, adhanaala measure panna thevai therinjaa thaan oru layer-a serunga.

**Design decisions records-aa.** Document-la oru short decision log vachchukkunga: date, decision, paartha options, reason, yaar oppukkittaanga. Example: "2026-11-02: reranker-oda hybrid search; vector-only policy codes-a miss pannichu (recall 71% vs 89%); client IT-oda orumichchu." Pinnaadi varra reviewers-um pudhu team members-um enna-nu mattum illa, yen-nu paapaanga.

**Aarambikka oru template.** Design document-a repository-la Markdown-aa, indha lesson-la irukkura enmu headings-oda, estimate output, latency budget, failure-mode table, decision log-oda store pannunga. Code maadhiri pull requests-la review pannunga.

## Oru worked example

Mumbai-la oru general insurer-oda internal assistant-ku design summary, 2,000 policy wordings, circulars, underwriting guidelines-la irundhu underwriters-oda kelvigalukku badhil sollum:

- *Goal*: underwriters-oda lookup neram 6 nimishathula irundhu 2-kku; 120-question test set-la citations-oda 85% correct, "documents-la illa" kelvigal 100% refuse.
- *Constraints*: 300 users, peak-la nimishathukku 40 requests, first token 2 s-kku keezha, data India-la, department-vaaripaa access.
- *Components*: layout-aware parsing, pazhaya circulars-ku OCR; section paths-oda 400-token chunks; department filters-oda hybrid search-um reranker-um; insurer-oda cloud region vazhiyaa mid-sized model-um oru fallback-um; links-aa render aagura citations; masked logs-oda tracing.
- *Failure modes*: superseded circulars (effective-date filter), scanned tables (table extraction, flag panna pages), upload panna documents vazhiyaa injection (write tools illa), outage (fallback, apram oru clear message).
- *Evaluation*: recall at 5, calibrated judge-aal answer correctness, maadhathukku 30 answers-ku underwriter review; CI-la fast checks.
- *Operations*: container service, latency, cost, feedback, refusal rate-ku dashboards, raathiri re-indexing.

Document-ku rendu naal aachu, week one-la compliance team data residency pathi kettapo oru maadha rework-a thadukkichu.

| Design element | Decision |
| --- | --- |
| Goal | Lookup neram 6 nimishathula irundhu 2-kku |
| Launch bar | 120 questions-la citations-oda 85% correct; out-of-scope-ku 100% refusal |
| Constraints | 300 users, peak-la nimishathukku 40 requests, first token 2 s-kku keezha, data India-la |
| Payoff | Compliance-oda week-one residency kelvikku document-la irundhu badhil, oru maadha rework thavirppu |

## Podhuvaa panra thappugal

- **User-um metric-um illaama model-la irundhu aarambikkradhu.**
- **Failure analysis illaama irukkradhu.** Ovvoru component-um edhaavadhu vazhila fail aagum.
- **Evaluation plan illaama irukkradhu.** "Paarkkalaam enna aagudhu-nu" plan illa.
- **Constraints-a ignore panradhu.** Latency, cost, data rules design-a shape pannum.
- **Yaarum padikkaadha neenda documents.** Rendu-la irundhu naalu clear pages.
- **Capacity, cost estimate-a vittudradhu**, apram launch-ku aprom rate limits-um bill-um kandupidikkradhu.
- **Muzhu system-kkum oru latency target** mattum, ovvoru step-kkum allowance illaama.
- **Reason record panna design decisions illaama**, adhanaala maadham-oru thadava thirumba vaadhaadappadum.

## Muzhu design document overkill-aa irukkum neram

- **Oru idea-va test panna oru vaara prototype**: goal, data, success measure-oda arai page note podhum.
- **Kammiyaana users-um sensitive data-vum illaadha sinna internal tool.**
- **Irukkura system-kkulla oru maatram**, adhukku pudhu document illa, adhoda design document-oda update thevai.

## Demo-la irundhu production varaikkum

- **Design document-a repository-la vachchukkunga**, ovvoru periya maatramum update pannunga.
- **Traffic, models, prices maarum podhu capacity, cost estimate-a thirumba odunga.**
- **Ovvoru step-ayum adhoda latency allowance-kku ethiraa traces-la irundhu measure pannunga.**
- **Decision log-a date-um reason-um oda maintain pannunga.**
- **Ovvoru incident-kum apram failure modes-a review panni pudhu rows serkkunga.**
