## Idhu enna

**AI system design**-na oru AI product edhellaam vachu seiyappattirukku-nnu paper-laye mudivu panni, adhu work aagum-nu numbers vachu niroobikkiradhu. Oru nalla design aaru kelvigalukku badhil sollum: parts enna, ovvoru arrow-vaiyum endha data thaandudhu, oru request-kku evvalavu cost, user evvalavu neram kaathirukkanum, edhu udaiyum, adhu namakku eppadi theriyum, quality-a eppadi measure pannuvom?

"Design interview" lesson oru design-a nerak kattuppaattukkulla present panradhai pathi pesudhu; adhukkulla enna irukkanum-nu indha lesson pesudhu.

Documents-la irundhu badhil solra oru product-kku rendu pipelines irukku: **ingestion** offline-aa odi documents-a oru index-aa maathudhu; **request path** ovvoru kelvikkum odudhu. Perumbaalaana quality problems ingestion-la thaan aarambikkudhu, adhanaala rendaiyum varainga.

```flow
title: Underwriting assistant, request path
Underwriter-oda kelvi -> API service | login, department, oru user-kkaana cap
API service -> Input checks | personal data-va mask pannum, injection-a flag pannum
Input checks -> Query rewrite | small model
Query rewrite -> Hybrid search | department, effective-date filters
Hybrid search -[top 40]-> Reranker
Reranker -[top 6]-> Main model | passages-la irundhu mattum badhil, citations kooda
Main model -[outage]-> Fallback model
Main model -> Citation check
Fallback model -> Citation check
Citation check -[pass aanaa]-> Clauses-kkaana links kooda badhil
Citation check -[fail aanaa]-> Badhil maruppu, oru senior underwriter-kku route
```

```flow
dir: LR
title: Ingestion pipeline, ovvoru raathiriyum
Pudhu wordings-um circulars-um -> Parser and OCR | tables-a tables-aave vachukkum -> Chunker | section path kooda 400 tokens -> Embeddings and keyword index -> Index | version, effective date, department
```

Indha lesson ore oru design-a follow pannudhu: Mumbai-la irukkura oru general insurer-la 300 underwriters-kkaana oru assistant, 2,000 policy wordings, circulars, guidelines-la irundhu badhil solludhu. Ella volumes, token counts, timings-um indha design-oda assumptions thaan, oru nija insurer-la edutha measurements illa.

## Idhu eppadi work aagudhu

### User-la irundhum constraints-la irundhum aarambinga

Goal-a oru baseline kooda oru metric-aa ezhudhunga: "Oru policy kelvikku badhil kandupidikka aagura median time, 6 minutes-la irundhu 2-kku keezha." Appuram oru box-aiyo oru number-aiyo maathura constraints-a list pannunga.

- **Badhila yaar padikkiraanga, thappaana badhilukku enna vilai?** Train aana oru underwriter thaan, aanaa oru thappaana exclusion oru policy-kku thappaana price poda vachudum. Adhanaala ovvoru badhilum oru clause-a cite pannum.
- **Volume-um peaks-um.** 300 users, ovvorutharum oru working day-kku sumaar 25 kelvigal, perumbaalum 8 busy hours-kkulla.
- **Data rules.** Documents, index, logs India-kkullaye irukkum. Model calls India-kku veliye process aagalaamaa-nnu compliance team thaan mudivu pannanum; oru provider-a neradiyaa call panradhaa, allathu thernthedutha model-a India-la kudukkura oru cloud provider-oda regional endpoint irundhaa adhai use panradhaa-nnu andha mudivu thaan theermaanikkum. Mudhal vaarathulaye kelunga.
- **Access.** Motor underwriters health reinsurance treaties-a paarkkak koodaadhu; indha rule search-oda vadivathaiye theermaanikkudhu.

### Ovvoru design-um solla vendiya decisions

Boxes-oda oru list design aagaadhu. Periya choices-aiyum ovvonnukkaana kaaranathaiyum sollunga.

| Decision | Indha design-oda choice | Idhai eppo maathanum |
| --- | --- | --- |
| Prompt mattum, retrieval allathu fine-tuning | Retrieval: documents maasaa maasam maarudhu, badhilgalukku citations venum | Thevai knowledge illa, volume-la format allathu style-na ("Prompting, RAG illa fine-tuning" paarunga) |
| Long context allathu retrieval | Retrieval: sumaar 25 million tokens documents, oru 1-million-token window-kku edhiraa | Corpus chinnadhaa, nilaiyaa irundhu, caching adhai malivaa vachaa |
| Model tier | Badhilgalukku mid-sized model; query rewriting-kku small model | Oru muzhu category-kku small model launch bar-a thottaa |
| Hosted API allathu self-hosted open weights | Hosted, region-a compliance mudivu pannum | Data unga servers-a vittu pogak koodaadhu-nnaa, allathu nilaiyaana volume GPUs-a busy-aa vachaa |
| Vector store | Vector extension kooda Postgres | Index oru machine-a vida perusaanaa |
| Streamed allathu batch | Streamed: oru aal kaathirukkaanga | Yaarum kaathirukkalai-nnaa: batch API-kku paadhi cost thaan |

Database-a thernthedukkiradhukku munnaadi index-a size pannunga. 2,000 documents, ovvonnum saraasariyaa 25 pages, oru page-kku sumaar 500 tokens-nu vachukkonga: 25 million tokens, adhaavadhu 400 tokens-oda 62,500 chunks. Oru embedding-kku 1,024 numbers, ovvonnum 4 bytes-na, adhu sumaar 256 MB vectors; oru saadharana server-oda memory-laye adangidum. Oru distributed vector database endha laabamum illaama cost-a mattum koottum.

### Oru request-a trace pannunga, ovvoru step-laiyum irukkura data kooda

Ovvoru step-um edhai vaangudhu, edhai aduthadhukku anuppudhu-nnu note pannunga; privacy, cost problems inga thaan theriyavarum.

1. **API service.** Kelvi, user id, department-a vaangudhu; daily cap-a thaandina users-a reject pannudhu.
2. **Input checks.** Log panradhukku munnaadi policy, phone numbers-a mask pannudhu; model-kku instructions kudukka muyarchi panra text-a flag pannudhu.
3. **Query rewrite.** Oru small model "does the fire one cover riots" maadhiri oru kelviya policy name kooda oru query-aa maathudhu: sumaar 300 tokens ulla, 40 veliya.
4. **Hybrid search.** Keyword search-um vector search-um parallel-aa odudhu, department, effective date vaariyaa filter panni. Embeddings adikkadi miss panra policy codes, clause numbers maadhiri exact strings-a keyword search pidichudum.
5. **Reranker.** Top 40 candidates-kku score pottu 6-a vachukkudhu.
6. **Main model.** Sumaar 1,500 tokens fixed instructions (ovvoru call-laiyum appadiye irukkum, adhanaala cache aagum), 2,700 pudhu tokens vaangudhu: 400 tokens-oda aaru passages-um kelviyum. Adhu sumaar 350 tokens ezhudhudhu.
7. **Citation check.** Saadharana code: cite panna ovvoru clause id-um anuppina passages-la irukkanum; illai-nnaa badhil refuse aagi oru aalukku route aagum.

Access control step 4-la irukku. Badhil vandhadhukku appuram filter panna, user paarkkak koodaadha text-a model yerkanave padichirukkum.

### Boxes-kku munnaadi numbers: load, limits, cost

```python
# Anthropic list prices, US dollars per million tokens, checked 28 November 2026
SONNET = {"in": 2.00, "cache_read": 0.10, "out": 10.00}   # Claude Sonnet 5.5
HAIKU = {"in": 0.10, "out": 0.50}                          # Claude Haiku 5.5, prompts up to 100,000 tokens

def estimate(users=300, questions_per_user=25, work_days=22, busy_hours=8, peak_factor=2.5,
             cached_in=1_500, fresh_in=2_700, out=350,   # main model, tokens per question
             rewrite_in=300, rewrite_out=40,             # small model rewrites the query
             usd_to_inr=94, fixed_inr_month=60_000):     # suppose: search, hosting, tracing
    daily = users * questions_per_user
    peak_per_min = daily / (busy_hours * 60) * peak_factor
    usd = ((fresh_in * SONNET["in"] + cached_in * SONNET["cache_read"] + out * SONNET["out"])
           + (rewrite_in * HAIKU["in"] + rewrite_out * HAIKU["out"])) / 1e6
    month_inr = daily * work_days * usd * usd_to_inr + fixed_inr_month
    return {
        "peak questions a minute": round(peak_per_min),
        "peak uncached input tokens a minute": round(peak_per_min * fresh_in),
        "peak output tokens a minute": round(peak_per_min * out),
        "model cost per question (rupees)": round(usd * usd_to_inr, 2),
        "model spend a month (US dollars)": round(daily * work_days * usd),
        "total a month (rupees)": round(month_inr),
        "per user a month (rupees)": round(month_inr / users),
    }

print(estimate())
# {'peak questions a minute': 39, 'peak uncached input tokens a minute': 105469,
#  'peak output tokens a minute': 13672, 'model cost per question (rupees)': 0.86,
#  'model spend a month (US dollars)': 1502, 'total a month (rupees)': 201141,
#  'per user a month (rupees)': 670}
```

Oru dollar-kku ₹94-um, ₹60,000 fixed costs-um udhaaranathukku mattum thaan. Idhai published limits kooda compare pannunga. Claude API-la, November 2026 nilavarappadi, migak kuraindha standard tier (Start) Sonnet 5.5-kku oru minute-kku 2,000,000 input tokens-um 400,000 output tokens-um anumadhikkudhu. Cache reads input limit-la count aagaadhu. Adhanaala peak load adhula sumaar 5% thaan use pannudhu: rate limit pirachanai illa.

Monthly bill thaan pirachanai. Ovvoru tier-kkum oru monthly spend cap irukku: Start-kku $500, Build-kku $1,000, Scale-kku $200,000. Maasathukku sumaar $1,500-na, keezha irukkura rendu tiers-la edhulaiyum indha design maasathoda naduvulaye ninnudum, retries-aala sari panna mudiyaadha errors kooda. Design endha tier allathu cloud contract-nu sollanum, cap-a vida kuraivaana alavula oru budget alert-a set pannanum. Cloud platforms avangaloda sondha quotas-a vaikkiraanga; Anthropic-oda pricing page-padi, avangaloda regional, multi-region endpoints global endpoints-a vida 10% adhigam cost aagum. Adhanaala compliance thernthedukkura route-kku kanakkai thirumba podunga.

Fresh input thaan migap periya cost: oru kelvikkaana $0.0091-la $0.0054 (oru million-kku $2-la 2,700 tokens). 6 passages-kku badhilaa 4 anuppinaa sumaar 18% micham, eval set-la recall kuraiyaama irundhaa. Cache writes-a kanakkula serkkala: indha traffic-la cached prefix aridhaa thaan expire aagum. Fixed costs total-la 30%, adhanaala usage kooda kooda oru user-kkaana cost kuraiyum.

### Oru latency budget, step by step

Underwriters badhil stream aagumbodhe padikkiraanga, adhanaala target: 100 kelvigalla 95-kku (p95) mudhal text 2 seconds-kkulla theriyanum.

| Step | Allowance (p95) |
| --- | --- |
| Login, cap, input checks | 50 ms |
| Query rewrite, small model | 300 ms |
| Hybrid search, keyword-um vector-um parallel-aa | 150 ms |
| 40 candidates-a rerank panradhu | 200 ms |
| Main model, mudhal token varra neram | 1,000 ms |
| Total, sumaar 300 ms micham vachu | 1.7 s |

p95-kalai koottinaa unmaiyaana p95-a vida adhigamaa kaattum, yenna ella steps-um ore nerathula slow aagradhu aridhu; adhanaala indha budget safe thaan, exact illa. Model, udhaaranamaa, oru second-kku 60 tokens stream pannaa, 350-token badhilukku innum sumaar 6 seconds aagum. Total thaandumbodhu, endha step adhoda allowance-a meerichu-nnu trace kaattum. Mudhalla cut panna vendiya step query rewrite thaan.

### Failure modes, avatrai eppadi detect panradhu, guard

Oru failure row-kku payan irukkanum-naa, yaaraavadhu andha failure-a gavanikkanum; adhanaala ovvoru row-kkum oru detection signal kudunga.

| Component | Enna thappaa pogum | Ungalukku eppadi theriyum | Guard |
| --- | --- | --- | --- |
| Parsing | Scan panna tables kuzhambina text-aa maarum | Ovvoru document-kkum parse score | Table extraction; flag aana pages indexing-kku munnaadi check aagum |
| Index | Pazhasaagippona (superseded) oru circular mudhal rank-la varum | Eval set-la irukkura dated trap questions fail aagum | Effective-date filter; pazhaiya versions vachirukkappadum, aanaa mark panni |
| Search | Sariyaana clause miss aagum | Eval set-la recall at 5, vaaraa vaaram track panni | Hybrid search, reranker, query rewrite |
| Access | Oru user innoru department-oda treaty-a paarppaanga | Ovvoru department-la irundhum oru user vachu CI test | Search-kkullaye permission filter |
| Model | Passages support pannaadha oru claim | Citation check failures; sample panna traffic-la judge score | Passages-la irundhu mattum badhil, illai-nnaa refuse |
| Documents | Upload panna oru file-la olinjirukkura instructions | Traces-la injection flags | Write tools illa; passages instructions illa, data-nu mark pannappadum |
| Provider | Outage, rate limit allathu ramp limit errors (429) | Error rate, fallback share | Backoff kooda retries, fallback model, thelivaana message |
| Cost | Usage kattuppaadu illaama egirum | Budget-kku edhiraa daily spend | Oru user-kkaana caps, budget-oda 80%-la oru alert |

### Human review: enga, evvalavu

Model migavum balaveenamaa irukkura, thappugal miga adhigamaa selavu vaikkura idangalla aalungalai vainga. Inga, refuse aana, low score vaangina badhilgal oru senior underwriter-kitta pogum, pudhu circulars indexing-kku munnaadi check aagum, maasathukku 30 badhilgal sample pannappadum.

Appuram adhai size pannunga. Oru naalaikku 7,500 kelvigalla 4% route aanaa, adhu 300 reviews. Ovvonnukkum 3 minutes-na, oru naalaikku 15 mani neram, sumaar rendu full-time reviewers. Client-aala andha alavu aalungalai poda mudiyalai-nnaa, retrieval-a sari pannunga, allathu kuraivaana vagai kelvigalai route pannunga. Aal illaadha oru queue guard aagaadhu.

### Evaluation-um launch bar-um

Test set-a nija kelvigalla irundhu, category vaariyaa build pannunga; udhaaranamaa 60 single-document kelvigal, rendu documents thevaippadra 25, 15 superseded-circular traps, documents cover pannaadha 20 (ivai kandippaa refuse aaganum). Retrieval-aiyum (recall at 5: sariyaana clause top five-la irukkaa?), badhilgalaiyum (sariyaa, cite pannappattirukkaa; underwriter labels kooda check panna oru model judge score podum) measure pannunga.

Oru chinna set enna kaatta mudiyum-nu therinjukkonga: 120 kelvigalla 85% sari-nnaa, 95% margin rendu pakkamum sumaar 6 points. Adhanaala rendu models-kku naduvula 2-point vithiyaasam verum noise. 20-kku 20 refusals irundhaalum, unmaiyaana failure rate sumaar 15% irukka vaaippu irukku. Nija traffic vara vara traps-a koottunga. Ovvoru prompt allathu model maatrathukkum CI-la fast checks ottunga: 120 kelvigal, ovvonnum sumaar ₹0.86-na, oru run-kku sumaar ₹100, adhoda judge cost-um.

### Document-a uyiroda vachirunga

Adhai repository-la Markdown-aa vachu, pull requests-la review pannunga; kadaisiyila open questions-um oru decision log-um irukkattum: date, decision, options, reason, yaar othukkittaanga. | Open questions | Model calls India-va vittu pogalaamaa? Maasathukku sumaar $1,500-a endha API tier allathu cloud contract cover pannum? |

Endha code-um ezhudhuradhukku munnaadiye numbers enna maathichu:

1. **Spend cap.** Bill rendu tiers-oda monthly caps-a vida adhigam, adhanaala moonaavadhu vaarathula service ninnu poradhukku badhilaa, oru contract decision plan-laye serndhuchu.
2. **Review queue.** Client "eppodhaavadhu" review-nu ninaichirundhaanga; rendu peroda mani nerangalai paarthadhum retrieval velaikkum oru rota-kkum fund pannaanga.
3. **Vector store.** 256 MB vectors insurer-kitta yerkanave irukkura Postgres-laye adangudhu: review panna vendiya vendor onnu kuraivu.
4. **Compliance kelvi.** Mudhal vaarathulaye ezhuppinadhaala, gateway build aagradhukku munnaadiye model route mudivaachu.

Ippo oru maatrathai vachu test pannunga. Adutha varusham 2,700 claims staff serraanga-nnu vachukkonga. Users pathu madangaanaa, peak-la oru minute-kku sumaar 390 kelvigal, oru minute-kku sumaar 1.05 million uncached input tokens: innum Start tier-oda input limit-kku keezha thaan, aanaa maasathukku sumaar $15,000. Fixed costs pagirndhukkappadradhaala, oru user-kkaana cost sumaar ₹490-kku kuraiyum. Mudhalla udaiyuradhu review queue thaan: 75,000-la 4% oru naalaikku 3,000 reviews, adhanaala route aagura share-a mudhalla kuraikkanum.

## Podhuvaa panra thappugal

- **Numbers illaadha boxes.** Arikuri: endha box-kkum owner-o, latency allowance-o, failure row-o illa, adhanaala reviewers adhai challenge panna mudiyaadhu.
- **Request path-a mattum varaiyuradhu.** Arikuri: parsing, versions, effective dates edhuvum illa, oru pazhaiya circular oru user-a adaiyura varaikkum.
- **Rate limit-a check panni spend cap-a vittudradhu.** Arikuri: "Namma tokens-per-minute limit-a vida romba keezha", aanaa monthly bill-um illa, price check date-um illa.
- **Generation-kku appuram access-a filter panradhu.** Arikuri: "restricted badhilgalai UI maraichudum". Restricted text-a model yerkanave padichuduchu.
- **Detection column illaadha failure table.** Arikuri: yaarume gavanikkaadha failures-kku guards.
- **Size pannaadha human review.** Arikuri: "urudhiyilladha badhilgal oru aalkitta pogum", aanaa share-um, minutes-um, team-um illa.
- **Oru chinna eval set-a nambradhu.** Arikuri: 120 kelvigalla 2-point gain-a vachu oru model-a thernthedukkiradhu, allathu 20-kku 20 refusals-a proof-nu solradhu.
- **Yaarum padikkaadha oru neelamaana document.** Rendula irundhu naalu pages, summary table mudhalla.

## Eppo muzhu design document adhigam

- **Oru vaara prototype:** goal, data, success measure, oru request-kku thoraayamaana cost kooda arai page podhum.
- **Oru chinna internal tool**, kuraivaana users, sensitive data illaama.
- **Yerkanave irukkura oru system-kkulla oru maatram:** adhukku badhilaa adhoda document-aiyum decision log-aiyum update pannunga.

## Demo-la irundhu production-kku

- Traffic, models, token counts allathu prices maarumbodhellaam **estimate-a thirumba ottunga**, prices-kku date podunga.
- Vaaraa vaaram **traces-a latency budget kooda compare pannunga**.
- Fallback use, spend, refusal rate-kku alerts kooda, **ovvoru detection signal-aiyum dashboard-la podunga**.
- **Ovvoru incident-kku appuramum oru failure row serunga.**
- **Maasaa maasam human review-a re-size pannunga.**

## Practice pannunga

Keezha link panniyirukkura, LLM-based systems-kkaana Eugene Yan-oda patterns-a padinga. Aazhamaa poga, Chip Huyen-oda *AI Engineering* (O'Reilly, 2025) pusthagathoda chapter 10 AI application architecture-a layer by layer cover pannudhu; chapter 9 latency, cost-a cover pannudhu.

Indha lesson-oda check oru project: neenga thernthedukkura oru AI product-kku rendula irundhu naalu pages-la oru design document. Indha ezhum irundhaa pass:

1. Oru baseline kooda oru success metric.
2. Oru peak-load, cost-per-user estimate, adhoda assumptions, neenga prices check panna date kooda.
3. Ovvoru component vazhiyaavum trace panna oru request, ovvoru step-laiyum irukkura data kooda.
4. Ovvoru step-kkum oru allowance kooda oru latency budget.
5. Kuranjadhu aaru rows irukkura oru failure table, ovvonnukkum oru detection signal, oru guard kooda.
6. Category vaariyaa oru test set, oru launch bar kooda.
7. Open questions-um oru chinna decision log-um.

Appuram, worked example-la panna maadhiri, oru assumption-a pathaala multiply panni, mudhalla edhu udaiyudhu-nnu note pannunga.

**Mudinjadhu-nnu eppo sollalaam:** unga design-a pathu minutes-la orutharukku walk through pannavum, ovvoru component-kkum "Idhukku enna cost, idhu evvalavu slow-aa irukkalaam, idhu fail aanaa enna aagum?"-ngra kelvikku badhil sollavum ungalaala mudiyumbodhu.
