## Idhu enna

Niraiya automations **edhaavadhu nadakkura nimishamae** react pannanum: oru payment succeed aagudhu, oru order podappadudhu, oru form submit aagudhu. **Webhook** adha saathiyamaakkudhu.

Webhook-na oru event nadandha udane, neenga kodutha web address (URL)-kku oru app anuppura message. Idhu oru doorbell maadhiri. Ovvoru sila nimishamum kadhava poi paarkkuradhukku badhilaa (adhukku peru **polling**), yaaraavadhu vandhaa ungalukku sollidum.

```flow
dir: LR
title: Polling: medhuvu, niraiya veenaana requests
Unga app -[pudhusaa edhaavadhu irukkaa?]-> Store
Store -[illa ... illa ... irukku, oru order]-> Unga app
```

```flow
dir: LR
title: Webhook: nadakkumbodhae sollidum, vegam, veenaana checks illa
Store -[event-a POST pannum]-> Unga URL (n8n)
Unga URL (n8n) -[200 OK]-> Store
```

Message podhuvaa oru HTTP **POST** request, adhula event-a vivarikkira oru **JSON** body irukkum. Oru payment gateway-oda event maadhiriyaana, simplify pannina oru example:

```json
{"event":"payment.captured","payload":{"payment":{"entity":{"id":"pay_771","amount":420000,"currency":"INR","status":"captured"}}}}
```

Indha sample-la amount paise-la irukku, adhanaala 420000-na ₹4,200.

**Webhook-aa API-aa?** API-la, *neenga* provider-a call panni kekkureenga. Webhook-la, edhaavadhu maarinaa provider *ungala* call pannudhu. Nalla automations rendaiyum use pannum: edho nadanduchu-nnu webhook sollum, details-a check pannavum gaps-a nirappavum API udhavum.

Indha lesson Jaipur-la irukkura oru handicrafts store-a follow pannudhu; oru payment succeed aana udane invoice email aaganum-nu avanga virumbraanga.

## Idhu eppadi work aagudhu

### Oru delivery-oda vaazhkkai

Ovvoru delivery-um adhe loop-a thaan follow pannum. Sender unga reply-a mattum thaan paarkkum.

```flow
title: Oru webhook delivery
Event nadakkudhu | udhaaranamaa oru payment capture aagudhu -> Sender unga secret vachu JSON-a sign pannudhu
Sender unga secret vachu JSON-a sign pannudhu -> Unga URL-kku POST
Unga URL-kku POST -> Unga reply
Unga reply -[timeout-kkulla 2xx]-> Delivered | sender niruthidum
Unga reply -[error allathu nerathukkulla reply illa]-> Appuram retry | adhe event, adhe id
Appuram retry -> Unga URL-kku POST
```

Adhanaala oru `2xx` reply sender-kku "mudinjadhu"-nu artham, adutha second-laye unga workflow fail aanaalum kooda. Endha failure-um adhe event-a thirumba kondu varum.

### Receive panradhu: test, production URLs

Unga automation tool ungalukku oru URL kodukkum, udhaaranamaa n8n-oda **Webhook** node-la irundhu. Adha sending app-oda settings-la paste panni, endha events anuppanum-nu thaerndhedunga. Niraiya tools rendu URLs kodukkum:

| URL | Eppo work aagum | Edhukku use panradhu |
| --- | --- | --- |
| Test URL | Neenga editor-la listen pannittu irukkumbodhu | Build pannavum debug pannavum |
| Production URL | Workflow publish (active) aanadhum | Real events-kku |

Beginners panra oru podhuvaana thappu: sender-oda settings-la test URL-aiyae vittudradhu. Neenga paarthuttu irukkumbodhu ellaam work aagum, appuram ninnudum.

Inga rendu Webhook node settings mukkiyam. **Raw Body**, sender post pannina exact bytes-a appadiye vachukkum; signature-a check panna adhu thevai. **Respond**, n8n eppo reply pannanum-nu control pannum: udane, kadaisi node mudinjadhum, allathu neenga sariyaa venum-ngra idathula vaikkira oru **Respond to Webhook** node-la.

### Real events varradhukku munnaadi test pannunga

Field peyargal provider-kku provider maarum, adhanaala mappings-a oru real sample-la irundhu build pannunga. `curl` vachu neengalae onnu anuppalaam: n8n-la "Listen for test event"-a click pannunga, appuram unga sondha test URL-oda idha run pannunga:

```bash
curl -X POST "https://your-n8n.example.com/webhook-test/payments" \
  -H "Content-Type: application/json" \
  -d '{"event":"payment.captured","payload":{"payment":{"entity":{"id":"pay_771","amount":420000,"currency":"INR","status":"captured"}}}}'
```

Niraiya beginners-a oru trap niruthidum. n8n unga laptop-la run aanaa, adhoda URL `localhost`-la aarambikkum, internet-la irukkura oru gateway-aala adha reach panna mudiyaadhu. Oru public n8n (n8n Cloud, allathu HTTPS irukkura oru server), unga laptop-kku oru public address kodukkura ngrok allathu Cloudflare Tunnel maadhiri oru **tunnel**, allathu provider enna anuppudhu-nnu paarkka mattum webhook.site-a use pannunga.

Perumbaalaana gateways-la real panam illaadha oru **test mode**-um irukkum. Test mode-kkum live mode-kkum podhuvaa thanithani webhooks, thanithani secrets irukkum.

### Unga reply sender-kku enna solludhu

Sender unga reply-oda status code-a mattum thaan padikkum, sila seconds mattum thaan kaathirukkum. Razorpay, oru Indian payment gateway, 5 seconds-kkulla oru `2xx` reply edhirpaarkkum. Vera endha code-aiyum, allathu nerathukkulla reply varaadhadhaiyum failure-aa eduthukkittu, event uruvaana nerathula irundhu 24 mani nerathukku, idaiveliya koottikkittae retry pannum. Andha 24 mani neramum deliveries fail aagittae irundhaa, webhook-a disable pannidum (idhellaam November 2026 nilavarappadi). Matha providers-kku vera windows irukkum, adhanaala avanga docs-a padinga.

| Unga reply | Sender enna mudivu pannum | Eppo anuppanum |
| --- | --- | --- |
| `200` (allathu vera oru `2xx`) | Delivered; thirumba anuppavae anuppaadhu | Event save aayiduchu, allathu aerkanavae ungakitta irukkura oru duplicate |
| `401` | Failed; podhuvaa retry aagum | Signature match aagala |
| `500` | Failed; appuram retry aagum | Event-a save panna mudiyala, udhaaranamaa unga database down |
| Nerathukkulla reply illa | Failed; appuram retry aagum | Unga workflow romba medhuvaa irundhuchu allathu server down |

### Mudhalla save, appuram reply, appuram velai

Indha lesson-la ellaathaiyum vida mukkiyamaana idea idhu thaan. Saathiyamaana moonu orders-la, rendu fail aagum.

| Order | Enna thappaa pogum |
| --- | --- |
| Ella velaiyaiyum pannittu, appuram reply | PDF uruvaakkura maadhiri medhuvaana velai timeout-a thaandidum. Neenga velai pannittu irukkumbodhae sender retry pannum, ungalukku duplicates varum. |
| Mudhalla reply, appuram velai | `200`-kku appuram n8n crash allathu restart aanaa, sender thirumba anuppavae anuppaadhu, event tholainjidum. |
| Save, reply, appuram save pannina copy-la irundhu velai | Sender "mudinjadhu"-nu kekkuradhukku munnaadiye event safe-aa irukku. Fail aana velai unga copy-la irundhu retry aagum. |

**Durable-aa save panradhu**-na restart-a thaangura oru idathula event-a ezhudhuradhu: oru database table (udhaaranamaa Postgres allathu Supabase) allathu oru message queue. Oru insert vegamaa nadakkum, timeout-kkullayae nallaa mudinjidum. Raw body, event id, receive pannina neram, oru **status** idhaiyellaam store pannunga: save aanadhum `received`, velai mudinjadhum `done`.

```flow
title: Save, reply, appuram velai
Webhook varudhu -> Signature match aagudhaa?
Signature match aagudhaa? -[illa]-> 401 reply panni niruthu
Signature match aagudhaa? -[aamaa]-> Event id-a insert pannu | status received
Event id-a insert pannu -[aerkanavae irukku]-> 200 reply panni niruthu | oru duplicate
Event id-a insert pannu -[save aachu]-> 200 reply pannu
200 reply pannu -> Invoice uruvaakki email pannu
Invoice uruvaakki email pannu -> Status-a done-nu mark pannu
```

Reply-kku appuram workflow crash aanaa, row `received`-aavae irukkum. Oru **sweep**, adhaavadhu sumaar ovvoru 15 nimishathukkum run aagura oru scheduled workflow, 10 nimishathukku appuramum `received`-aa irukkura rows-a eduthu velaiya thirumba run pannum. Adhanaala velai repeat panna safe-aa irukkanum: ovvoru sub-step-aiyum (invoice uruvaachu, email pochu) record pannunga, appo rerun missing aanadha mattum pannum.

### Duplicates, idempotency

Perumbaalaana senders **at-least-once delivery** promise pannuvaanga: oru event-a tholaikkuradha vida rendu thadavai anuppuradhaiyae virumbuvaanga. Idhukkaana defence **idempotency**: oru event-a rendu thadavai process pannaalum, oru thadavai process pannina adhe effect thaan irukkum.

Rendu vera vera velaigalukku rendu ids use pannunga:

- **Event id** oru delivery-a identify pannum. Andha event-oda ovvoru retry-laiyum adhoda value adhe thaan, adhanaala "indha delivery-a munnaadiye paarthirukken"-nu adhu sollum. Udhaaranamaa Razorpay adha `x-razorpay-event-id` header-la anuppum.
- **Business id**, payment id maadhiri, real-world vishayathai identify pannum. Rendu *vera vera* events orae payment-a vivarikkalaam (udhaaranamaa `payment.captured`, `order.paid`), adhanaala invoice-a payment id-a key-aa vachu pannunga.

**Experts-aiyae maatta vaikkira race.** "Sheet-la id-a thedu; illainnaa saer"-ngra design aasaiyaa thonum. Oru medhuvaana reply-kku appuram, original vandha oru second kazhichu retry varalaam. Rendu copies-um `pay_771`-a thedum, rendukkum edhuvum kidaikkaadhu, rendumae invoice uruvaakkum, yenna check-kkum write-kkum naduvula innoru copy nuzhainjiduchu.

Idhukkaana fix **duplicate vandhaa fail aagura orae oru step**. `event_id` column-kku oru unique key koduthu, verumanae insert pannunga. Sariyaa orae oru insert thaan succeed aagum; innonnukku "duplicate key" error varum, adha unga workflow "aerkanavae irukku, 200 reply panni niruthu"-nu eduthukkum. Invoice-oda `payment_id`-kkum oru unique key podunga.

Google Sheet-la unique key kidaiyaadhu. Eppavaavadhu oru double invoice vandhaa paravaayillai-nnu aethukkura, chinna, kuraivaana volume irukkura shop-kku mattum thaan sheet lookup okay. Oru sale-kku munnaadi database table-kku maaridunga.

### Events order maari varalaam

Delivery order guarantee kidaiyaadhu; Razorpay-oda webhook guidance idha naeradiyaavae solludhu (November 2026 nilavarappadi). Mundhaiya attempt-la irundhu retry aana oru `payment.failed`, success aana `payment.captured`-kku *appuram* varalaam; "kadaisi event thaan jeyikkum"-nu vachaa, pay pannina order-a failed-nu mark pannidum. Idha rendu rules handle pannum:

- **States-a munnaadi mattum nagarthunga.** Oru order `created`-la irundhu `paid`-kku pogalaam, aanaa `paid`-la irundhu `failed`-kku thirumba pogavae koodaadhu. Adha pinnaadi nagarthura events-a ignore pannunga.
- **Mukkiyamaana nerathula, current state-a kelunga.** Ship allathu refund panradhukku munnaadi, ippo status enna-nnu provider-oda API-a call pannunga.

### Security

Unga URL therinja yaar venumnaalum oru fake "payment captured"-a post panni, oru real shipment-a trigger pannalaam. Adha layers-aa protect pannunga.

**Signature-a verify pannunga.** Neengalum provider-um oru **webhook secret**-a share panreenga. Ovvoru delivery-kkum, provider oru **HMAC**-a compute pannum, adhaavadhu secret vachu uruvaakkuna body-oda oru fingerprint, adha oru header-la anuppum. Udhaaranamaa Razorpay oru HMAC-SHA256 hex value-a `X-Razorpay-Signature`-la anuppum (November 2026 nilavarappadi). Neenga receive pannina body mela adhe HMAC-a compute panreenga; rendum match aanaa, sender-kku secret theriyum, body maarala. Webhook-oda sondha secret-a use pannunga, unga API key secret-a illa.

Check work aagumaa illaiyaa-nnu moonu details thaan mudivu pannum:

1. **Raw body-a use pannunga.** Signature anuppuna exact bytes-a cover pannum. JSON-a parse panni thirumba text-aa maathinaa, spaces allathu key order maaralaam, adhanaala oru genuine event kooda fail aagum. n8n-la **Raw Body**-a on pannunga.
2. **Constant time-la compare pannunga.** Saadhaarana comparison mudhal thappaana character-laye ninnudum, adhu timing clues-a leak pannalaam. n8n-oda **Crypto** node HMAC-a compute pannum, aanaa IF node comparison constant-time illa. High-value flows-kku, Node-oda `crypto.timingSafeEqual` vachu oru **Code** node-la compare pannunga; self-hosted n8n-la, mudhalla `NODE_FUNCTION_ALLOW_BUILTIN` environment variable vachu `crypto` module-a allow pannunga.
3. **Provider oru timestamp-a sign pannum idathula, pazhaya messages-a reject pannunga.** Oru signature message-a yaar anuppinaanga-nnu prove pannum, eppo-nnu illa, adhanaala pidipatta oru request-a appuram replay pannalaam. Stripe maadhiri sila providers oru timestamp-a sign pannuvaanga, adhanaala sila nimishathai vida pazhasaana edhaiyum reject pannalaam. Adhu illaadha idathula, unga unique event id oru replay-a harmless aakkidum.

Standard library mattum use panra indha Python script, raw-body trap-a kaattudhu:

```python
import hmac, hashlib, json

SECRET = b"test_secret_123"

def is_genuine(raw_body: bytes, signature: str) -> bool:
    expected = hmac.new(SECRET, raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)  # constant-time

raw = b'{"event":"payment.captured","payload":{"payment":{"entity":{"id":"pay_771","amount":420000,"currency":"INR","status":"captured"}}}}'
sig = hmac.new(SECRET, raw, hashlib.sha256).hexdigest()

print(is_genuine(raw, sig))                          # True
print(is_genuine(json.dumps(json.loads(raw)).encode(), sig))  # False: spaces were added
```

Rendaavadhu thadavai fail aagradhu yenna `json.dumps` spaces-a saerkkudhu: adhe data, vera bytes.

**Matha layers:** HTTPS-um neelamaana, random URL path-um use pannunga (rendumae signature-kku badhilaa aagaadhu). Porutkalai ship panradhukku munnaadi, provider-oda API-la irundhu payment-a thirumba fetch pannunga; Razorpay-yae webhooks-kku oru backstop-aa adhoda fetch APIs-a use panna solludhu, udhaaranamaa time-sensitive aana oru flow webhook varra varaikkum kaathirukka mudiyaadha bodhu.

### Thavarina events, reconciliation

Retries chinna outages-a cover pannum, neenda outages-a illa. Retry window-a thaandinaa, endha error-um illaama events tholainjidum, sila providers webhook-a off panniduvaanga. Mukkiyamaana flows-kku rendu safety nets irukkum:

- **Sweep**, neenga save panni aanaa mudikkaadha events-kkaana velaiya retry pannum.
- **Reconciliation**, udhaaranamaa nightly, annaikku capture aana ella payments-aiyum provider-oda API-kitta kettu, unga invoices kooda compare pannum. Missing aana edhuvum appo process aagum.

Oru alert-um set pannunga: business hours-la oru mani nerathukku endha webhook-um varalainnaa, allathu oru webhook disable aayiduchu-nnu provider sonnaa, annaikkae yaaraavadhu paarkkanum.

## Oru worked example

Jaipur-la irukkura oru handicrafts store Razorpay use pannudhu, oru payment succeed aana andha nimishamae invoice email aaganum-nu virumbudhu. Oru typical order ₹4,200. Gateway details November 2026 nilavarappadi. Avanga n8n-la idha build panraanga:

| # | Step | Yen |
| --- | --- | --- |
| 1 | Webhook node: production URL, Raw Body on, oru Respond to Webhook node vazhiyaa reply pannum. Razorpay dashboard-la `payment.captured`-kku saerkkappattadhu. | Exact bytes-oda events-a udane receive panna |
| 2 | Raw body-oda HMAC-SHA256-a webhook secret vachu compute panni, oru Code node-la `X-Razorpay-Signature` kooda compare pannu. Mismatch-na `401` reply pannu. | Fake requests-a reject panna |
| 3 | `x-razorpay-event-id`, payment id, raw body-a `webhook_events`-la insert pannu (unique event id, status `received`). Duplicate key-na: `200` reply panni niruthu. Vera endha failure-naalum: `500` reply pannu. | Gateway "mudinjadhu"-nu kekkuradhukku munnaadiye event safe; copies ingayae ninnudum |
| 4 | Respond to Webhook: `200`. | 5-second limit-kkulla nallaa mudinjidum |
| 5 | Unique payment id irukkura oru `invoices` table-la invoice PDF-a uruvaakki, email panni, appuram event-oda status-a `done`-aa set pannu. | Medhuvaana velai, repeat panna safe |
| 6 | Ovvoru 15 nimishamum: 10 nimishathukku appuramum `received`-aa irukkura rows-kku step 5-a thirumba run pannu. | Crash aana velaiya mudikka |
| 7 | Nightly: annaikku capture aana payments-a Razorpay API-la irundhu fetch panni invoices kooda compare pannu. | Vandhu seravae seraadha edhaiyum pidikka |

**Thiruvizhaa sale (oru illustration).** Diwali sale-oda bodhu, sila seconds-kku oru thadavai orders varudhu.

- PDF service hang aagudhu, oru payment-oda invoice paadhiyila irukkumbodhu n8n restart aagudhu. Andha event aerkanavae save aagi reply aayiduchu, adhanaala Razorpay adha thirumba anuppaadhu. Pathu nimisham kazhichu, row innum `received`-aa irukkuradha sweep kandupidichu invoice-a anuppum.
- Innoru restart server-a rendu nimisham down aakkudhu. Andha payments-kku Razorpay-kku reply kidaikkala, server thirumba vandhadhum avatrai retry pannum.
- Andha restart-kku konjam munnaadi pay_771 save aayiduchu, aanaa `200` server-a vittu pogavae illa. Razorpay adha retry pannum; step 3-la insert duplicate key-la maattum, workflow `200` reply panni ninnudum.

## Podhuvaa panra thappugal

- **Production-la test URL-a use panradhu.** Editor-a close pannadhum events varradhu ninnudum.
- **Event save aagradhukku munnaadiye reply panradhu.** `200`-kku appuram oru crash vandhaa event tholainjidum, yenna sender adha thirumba anuppaadhu.
- **Reply panradhukku munnaadi medhuvaana velaiya panradhu.** Sender timeout aagi retry pannum, duplicates uruvaagum.
- **Duplicate check-aa "thedu, appuram ezhudhu".** Onnaa varra rendu copies-um pass aayidum. Oru unique key use pannunga.
- **Oru duplicate-kku error-oda reply panradhu.** Aerkanavae ungakitta irukkura oru event-a sender retry pannittae irukkum. `200` reply pannunga.
- **Parse pannina JSON mela signature-a check panradhu, allathu URL-a mattum nambradhu.** Raw body-a use pannunga; oru secret URL leak aagalaam.
- **Events order-la varum-nu ninaikkiradhu.** States-a munnaadi mattum nagarthunga, panam sambandhappatta action-kku munnaadi thirumba fetch pannunga.
- **Test, live secrets-a kalakkuradhu.** Ovvoru mode-kkum podhuvaa adhoda sondha webhook, secret irukkum.
- **Sweep illa, reconciliation illa, alert illa.** Crashes-um neenda outages-um sathamillaama events-a tholaichidum.
- **Secrets-a log panradhu.** Webhook secret-aiyum muzhu payment details-aiyum shared logs-la irundhu veliyae vainga.

## Practice pannunga

Keezha link panniyirukkura Zapier-oda webhooks explanation-aiyum, n8n-oda Webhook node docs-aiyum padinga.

1. **Receive pannunga.** n8n-la oru Webhook workflow build pannunga, mela irukkura `curl` command-a unga test URL-kku anuppunga, vandha JSON-a study pannunga. n8n oru laptop-la run aanaa, oru tunnel vazhiyaa veliyila irundhu reach pannunga.
2. **Reply panradhukku munnaadi save pannunga.** Unique event id-um oru status column-um irukkura oru `webhook_events` table uruvaakkunga. Ovvoru event-aiyum insert pannunga, appuram oru Respond to Webhook node vachu reply pannunga. Reply-kku appuram venumnae workflow-a niruthi, row `received`-aavae irukkuradha kaattunga.
3. **Duplicates.** Adhe event-a orae nerathula rendu thadavai anuppunga (`&` vachu join pannina rendu `curl` commands). Oru row, oru invoice, rendu copies-kkum oru `200` irukkuradha kaattunga.
4. **Security.** Oru test secret vachu body-a sign pannunga (`openssl dgst -sha256 -hmac "test_secret_123"`, allathu mela irukkura Python script), adha oru signature header-la anuppi raw body mela verify pannunga. Body-la oru character-a maathi oru `401`-a kaattunga.
5. **Sweep, reconcile.** 15-nimisha sweep-a build pannunga, unga provider-kku oru nightly reconciliation eppadi work aagum-nu moonu sentences-la vivaringa.

**Mudinjadhu-nnu eppo sollalaam:** "mudhalla reply" yen events-a tholaikkudhu-nnu explain panna mudiyum, rendu copies onnaa varumbodhu unga duplicate check thaangradha kaatta mudiyum, tamper pannina oru request reject aagradha kaatta mudiyum, rendu naal outage-la miss aana events-a eppadi pidippeenga-nnu solla mudiyum.
