## Idhu enna

Neraya automations **edhaavadhu nadakkura nimishathulaye** react pannanum: payment succeed aagudhu, order podapaduthu, form submit aagudhu, support ticket close aagudhu. **Webhook** adha possible aakkudhu.

Webhook-na, event nadakkura udanae, neenga kudukkura web address (URL)-ku oru app anuppura message. Idhu doorbell maadhiri. Ovvoru sila nimishathukkum kadhava paarkkama, adhukku **polling**-nu peyar, yaaraavadhu vandhaa unga-ku solluvaanga.

```flow
dir: LR
title: Polling: slow, neraya waste aana requests
Unga app -[edhaavadhu pudhusaa irukka?]-> Store
Store -[illa ... illa ... irukku, oru order]-> Unga app
```

```flow
dir: LR
title: Webhook: nadakkum podhae solludhu, fast, waste check illa
Store -[event-a POST pannum]-> Unga URL (n8n)
Unga URL (n8n) -[200 OK]-> Store
```

Message perumbaalum oru HTTP **POST** request, event-a describe panra **JSON** body-oda: enna nadandhuchu, eppo, details.

Indha lesson Jaipur-la oru handicrafts store-a follow pannum. Payment succeed aana udanae invoice email aaganum-nu avanga virumburaanga. Mudiyum podhu, webhooks-a receive panni, test panni, secure panni, safe-aa repeat panna mudiyum.

## Idhu eppadi work aagudhu

### Receive panradhu

Unga automation tool-la irundhu oru URL kidaikkum, n8n-oda **Webhook** node-la irundhu maadhiri. Adha anuppura app-oda settings-la paste panni, endha events anuppanum-nu choose pannunga. Event nadandha, sender unga URL-ku JSON-a post pannum, andha data-oda unga workflow aarambikkum.

### Test URL vs production URL

Neraya tools rendu URLs tharum:

| URL | Eppo work aagum | Edhukku use panradhu |
| --- | --- | --- |
| Test URL | Editor-la neenga listen panra podhu | Build panna, debug panna |
| Production URL | Workflow publish (active) aanadhum | Real events-ku |

Beginners-ku varra oru common thappu, sender settings-la test URL-a appadiyae vittudradhu. Neenga paarkkum podhu ellam work aagum, editor-a mooduna udanae nindrudum.

### Payload-a inspect pannunga

Oru test event-a trigger panni, vandha exact JSON-a paarunga. Field names-um nesting-um provider-padi maarum. Mappings-a nyaabagathula irundhu illa, real sample-la irundhu build pannunga.

### Vegamaa respond pannunga

Senders vega success reply edhirpaarkkuvaanga, perumbaalum konja nimishathukkulla oru HTTP `200 OK`. Unga workflow modhalla PDF generate panra maadhiri slow velai pannina, sender time out aagi **retry** pannalaam. So: udanae reply pannunga, apram velaiya pannunga.

### Retries, duplicates

Unga endpoint fail aanaalum slow-aa irundhaalum, perumbaalaana senders retry pannuvaanga, sila neram pala maninerangala neraya thadavai. Sila design-ae "at least once" deliver pannum. Ethuvaanaalum, **ore event-a onnukku mela thadavai receive pannalaam.**

Idhukku defence **idempotency**: unga actions-a thirumba seiyyavum safe-aa aakkradhu. Event illa payment-oda id vechchu, already process pannittingala-nu check pannunga:

```flow
Webhook varudhu | payment id = pay_771 -> pay_771 already namma sheet-la irukkaa?
pay_771 already namma sheet-la irukkaa? -[irukku]-> Nirutthu | duplicate: edhuvum pannaadheenga
pay_771 already namma sheet-la irukkaa? -[illa]-> Invoice create pannu, email pannu, pay_771-oda oru row serthuko
```

Oru duplicate "payment captured" ethaiyum rendu invoices-a, rendu emails-a create pannakoodaadhu.

### Security

Unga URL-a therinjukkittavanga yaaraavadhu fake events-a post pannalaam, real shipment-a trigger panra fake "payment captured" maadhiri. Adha protect pannunga:

| Protection | Enna pannum |
| --- | --- |
| **Signature-a verify pannunga** | Neraya providers ovvoru webhook-aiyum shared secret vechu sign pannuvaanga; data-va nambradhukku munnaadi unga workflow signature-a check pannum |
| **HTTPS, neenda guess panna mudiyaadha path** | URL-a kandupidikka kashtam aakkum, transit-la data-va padikka mudiyaadha maadhiri pannum |
| **Provider-oda API-la irundhu thirumba edunga** | Mukkiyamaana events-ku, payment unmaiyaave succeed aanadha-nu provider-a nerlaye kelunga |

### Miss aana events

Unga endpoint, sender-oda retry window-a vida neram down-aa irundhaa, events sattham illaama lose aagalaam. Mukkiyamaana flows-ku, **reconciliation** run pannunga, raathiri maadhiri, adhu unga records-a provider-oda API-oda compare panni gaps-a niraikkum.

## Oru example

Jaipur-la oru handicrafts store oru payment gateway use pannudhu. Payment succeed aana udanae invoice email aaganum, accounts sheet-la oru row serkkanum-nu virumburaanga.

Avanga n8n-la idha build panraanga:

| # | Step | Yen |
| --- | --- | --- |
| 1 | Gateway dashboard-la "payment captured" events-ku serkkapatta production URL-oda Webhook node | Events-a udanae receive panna |
| 2 | Gateway-la irundhu copy panna webhook secret vechu signature-a verify pannunga | Fake requests-a reject panna |
| 3 | Udanae `200 OK` reply pannunga | Gateway time out aagi retry pannaama irukka |
| 4 | Payment id-a sheet-oda check pannunga; irundha nirutthunga | Duplicates edhuvum pannaadhu |
| 5 | Invoice PDF create panni, email pannu, payment id-oda row serkkunga | Real velai |
| 6 | Raathiri: andha naal captured payments-a gateway API-la irundhu eduthu sheet-oda compare pannunga | Miss aanadha pidikka |

**Festival sale.** Diwali sale-la, n8n server restart aagi rendu nimishathukku down aagudhu. Server thirumba vandhadhum gateway miss aana events-a retry pannudhu. Andha events-la rendu, restart-ku konjam munnaadi process aagiduchu, aana adhoda replies gateway-ku pogala, adhanaala rendu thadavai varudhu. Duplicate check rendayum nirutthudhu.

| Situation | Enna nadandhuchu | Edhu handle pannuchu |
| --- | --- | --- |
| Theriyaadha sender-la irundhu fake request | Signature match aagala | Step 2: reject aachu |
| Restart-ku apram event rendu thadavai vandhuchu | Payment id already sheet-la irundhuchu | Step 4: nindruchu |
| 2 nimisha outage-la anuppina events | Gateway apram retry pannuchu | Steps 1 la irundhu 5 varaikkum, konja nimisham late-aa |
| Oru vaara raathiri reconciliation | Missing payments edhuvum kidaikkala | Step 6 |

Step 4 illa-na, rendu customers-kum thalaa rendu invoices poyirukkum, accounts sheet-la nadakkaadha ₹8,400 sales kaattirukkum.

## Podhuvaa panra thappugal

- **Production-la test URL use panradhu.** Editor-a mooduna udanae events varaadhu.
- **Sign pannaadha requests-a nambradhu.** Act panradhukku munnaadi signatures-a verify pannunga.
- **Slow responses.** Senders retry pannuvaanga, duplicates varum. Modhalla reply pannunga, apram velai.
- **Duplicate check illama irukkradhu.** Retries rendu invoices, emails, orders-a create pannum.
- **Reconciliation illama irukkradhu.** Neenda outages-la events sattham illaama lose aagum.
- **Secrets-a log panradhu.** Webhook secret-a, muzhu payment details-a mathavanga padikkura logs-la ezhudhaadheenga.

## Practice pannunga

Keezha link panni irukkura Zapier-oda webhooks explanation-a, n8n-oda Webhook node docs-a padinga.

1. **Receive.** n8n-la oru webhook workflow create panni, oru form tool illa curl maadhiri command-la irundhu test request vechchu trigger pannunga.
2. **Duplicates.** Ore event-a rendu thadavai anuppi, rendaavadhu edhuvum pannaadha maadhiri duplicate check serkkunga.
3. **Security.** Shared-secret check serthu, thappaana secret-oda oru request reject aagradha kaattunga.

**Mudinjadhu-nu eppo sollalaam:** webhooks yen retry pannum-nu explain panna mudiyum, unga duplicate check work aagradha kaatta mudiyum, outage-la miss aana events-a eppadi pidippeenga-nu solla mudiyum.
