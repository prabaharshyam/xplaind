## Idhu enna

Neenga velai seiyappora kittathatta ellaa company-yum thannoda customers, orders, tickets, payments-a PostgreSQL, MySQL, SQL Server maadhiri oru relational database-la vechirukkum. Andha databases-kitta kelvi kekkura mozhi thaan **SQL**. Oru AI engineer-kku SQL optional illai. Idhukkaaga use pannuveenga:

- AI system-kku thevaiyaana **data-va edukka**, udhaaranam: resolutions-oda pazhaya tickets;
- Build pannradhukku munnaadi **baseline alakka**: "Innaikku refunds-kku evvalavu neram aagudhu?";
- System ship aanadhukku appuram **adhu udhavuchaa-nu check panna**.

Naalu idea indha velaiyila perumbagaththai cover pannum:

| Idea | Enna pannum | Vazhakkamaana use |
| --- | --- | --- |
| **Joins** | Match aagura column-la tables-a serkkum | Orders-a avanga customers-oda cities-oda serkka |
| **GROUP BY** | Oru group-kku oru row, totals illa averages-oda | City vaariyaa refunds |
| **Window functions** | Ellaa rows-aiyum vechukittu, thodarbulla rows muzhukka calculate pannum | Ovvoru customer-oda mudhal ticket; moving averages |
| **Indexes** | Lookups-a vegamaakkum | 40 vinaadi query-a 2 vinaadiyaa maatha |

```flow
dir: LR
title: "city vaariyaa refunds" badhil solla, poruntthum ids-la join pannadhu
refunds | id, order_id, created_at -[order_id = orders.id]-> orders | id, customer_id
orders -[customer_id = customers.id]-> customers | id, city
```

Oru AI assistant build pannradhukku munnaadi, Hyderabad-la oru food delivery company-yoda refund baseline-a alakkirappo indha lesson avangalai follow pannum. Lesson mudiyumbodhu joins, grouping, window functions vechu business kelvigalukku badhil sollavum, oru slow query-a vegamaakkavum mudiyum.

## Idhu eppadi work aagudhu

### Joins

Join, match aagura oru column-la tables-a serkkum.

| Join | Edhai vechukkum | Edhukku use panradhu |
| --- | --- | --- |
| `JOIN` (inner) | Rendu pakkamum match aagura rows mattum | Customer irukkura orders |
| `LEFT JOIN` | Idadhu table-la irukkura ellaa rows; valadhu pakkam match illanna blank | Orders illaadha customers; reply illaadha tickets |

```sql
-- customers who have never ordered
SELECT c.id, c.city
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.id IS NULL;
```

### GROUP BY

`GROUP BY` rows-a oru group-kku oru row-aa surukki aggregates calculate pannum: `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`. Grouping-kku **munnaadi** rows-a `WHERE`-la filter pannunga; **appuram** groups-a `HAVING`-la filter pannunga:

```sql
SELECT city, COUNT(*) AS refunds
FROM refunds r JOIN orders o ON o.id = r.order_id
JOIN customers c ON c.id = o.customer_id
WHERE r.created_at >= DATE '2026-07-01'
GROUP BY city
HAVING COUNT(*) > 100;
```

### Window functions

Window functions thodarbulla rows muzhukka calculate pannum, aana rows-a surukkaadhu:

| Function | Example | Enna tharum |
| --- | --- | --- |
| `ROW_NUMBER()` | `OVER (PARTITION BY customer_id ORDER BY created_at)` | Ovvoru customer-oda rows-kkum nera varisaiyila 1, 2, 3 |
| `LAG(col)` | `OVER (PARTITION BY customer_id ORDER BY created_at)` | Mundhina row-oda value, row-kku row compare panna |
| `SUM(col)` | `OVER (ORDER BY day)` | Odikkittirukkura total |
| `AVG(col)` | `OVER (ORDER BY day ROWS 6 PRECEDING)` | Yezhu naal moving average |

`PARTITION BY`, `GROUP BY` maadhiriyae rows-a groups-aa pirikkum, aana ovvoru row-um result-la irukkum.

### Indexes-um query plans-um

Index illanna, match-a kandupidikka database ovvoru row-aiyum padikkum: idhu **sequential scan**. `refunds(created_at)`-la oru index irundhaa, adhu neraa sariyaana rows-kku poidum.

```flow
dir: LR
title: 3 kodi rows-la July refunds-a kandupidikkiradhu
Index illai -> 30,000,000 rows-aiyum padichu, 2,000,000-a vechukkum -> 40 s
created_at-la Index -> 1 July-kku neraa poi, munnokki padikkum -> 2 s
```

Indexes reads-a vegamaakkum, writes-a konjam medhuvaakkum. Adhanaala neenga adhigamaa filter, join panra columns-kku mattum podunga. Oru query-kku munnaadi `EXPLAIN ANALYZE` potu run pannaa, database index use pannuchaa, muzhu table-aiyum scan pannuchaa, ovvoru step-kkum evvalavu neram aachu-nu paarkkalaam.

## Oru worked example

Hyderabad-la oru food delivery company refund requests-kku oru AI assistant venum-nu ninaikkudhu. Edhaiyum build pannradhukku munnaadi baseline thevai: innaikku oru refund-kku evvalavu neram aagudhu, city vaariyaa?

```sql
SELECT c.city,
       COUNT(*) AS refunds,
       ROUND(AVG(EXTRACT(EPOCH FROM r.resolved_at - r.created_at) / 3600), 1) AS avg_hours
FROM refunds r
JOIN orders o    ON o.id = r.order_id
JOIN customers c ON c.id = o.customer_id
WHERE r.created_at >= DATE '2026-07-01'
GROUP BY c.city
ORDER BY avg_hours DESC;
```

Adutha, assistant-oda training examples-kku, thirumba thirumba complain panravanga dominate pannaama irukka, ovvoru customer-oda **mudhal** refund request-a mattum edukkanum:

```sql
SELECT *
FROM (
  SELECT r.*,
         ROW_NUMBER() OVER (PARTITION BY o.customer_id ORDER BY r.created_at) AS n
  FROM refunds r JOIN orders o ON o.id = r.order_id
) t
WHERE n = 1;
```

**Slow query.** Baseline query 3 kodi rows-la 40 vinaadi edukkudhu. `EXPLAIN ANALYZE` date filter-kku `refunds`-la sequential scan nadakkuradhai kaattudhu. Client-oda data team-kitta kekkureenga; avanga amaidhiyaana neraththula primary database-la `CREATE INDEX CONCURRENTLY ON refunds (created_at)` run panraanga; andha index neenga query panra read replica-kkum varudhu. Ippo query rendu vinaadikku keezha mudiyudhu.

| City | July-la irundhu refunds | Resolve aaga sarasari mani neram |
| --- | --- | --- |
| Hyderabad | 48,200 | 31.4 |
| Vijayawada | 9,800 | 27.9 |
| Warangal | 4,100 | 22.6 |

Numbers-aiyum query nerangalaiyum unga notes-la ezhudhikkureenga. Indha table thaan unga assistant mundha vendiya baseline; andha index oru quick win, client-oda data team-kitta nalla peyarum vaangith tharum.

## Podhuvaa panra thappugal

- **Join panni perukkiduradhu.** Orders-a order items-oda join panni, apparam order totals-a sum pannaa, ovvoru order-um ovvoru item-kkum oru thadava ennappadum. Join panradhukku munnaadi sariyaana level-la aggregate pannunga.
- **Left join vendiya idaththula inner join poduradhu.** Orders illaadha customers report-la irundhu saththamillaama maraindhu povaanga.
- **Aggregates-a WHERE-la filter panradhu.** `WHERE COUNT(*) > 5` fail aagum; `HAVING` use pannunga.
- **Production database-la heavy queries run panradhu.** Read replica illa export kelunga. Client-oda live app-a medhuvaakkuradhu mudhal vaaraththukku nalladhu illai.
- **Ellaaththukkum index poduradhu.** Ovvoru index-um storage-aiyum write speed-aiyum saappidum. Real-aana slow queries-kku mattum podunga, `EXPLAIN ANALYZE`-la urudhi pannunga.
- **Dates-a text-oda compare panradhu.** Sariyaana date types-aiyum `DATE '2026-07-01'` maadhiri literals-aiyum use pannunga.
