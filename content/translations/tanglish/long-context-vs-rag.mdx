## Idhu enna

Oru kelvikku badhil solla model-kku thevaiyaana information-a kudukka moonu vazhigal irukku:

- **Long context**: muzhu documents-a prompt-la pottu, appuram kelunga.
- **Retrieval (RAG)**: oru index mela oru thadavai search panni, best-aana sila passages-a mattum prompt-la podunga.
- **Agentic search**: model-kku search tools kudunga (keyword search, oru metadata filter, "open document", oru database query), edhai thedanum-nu adhuve mudivu panni, results-a padichu, badhil solla mudiyura varai thirumba theda vidunga.

28 November 2026 nilavarappadi, Anthropic-oda latest Claude models ovvonnukkum 1-million-token context window irukku, Anthropic-oda kanakkuppadi adhu sumaar 555,000 vaarthaigal. Adhanaala long context perumbaalum possible thaan. Adhu buthisaalithanamaa-nnu accuracy, cost, latency, scale thaan mudivu pannum.

| | Long context | RAG | Agentic search |
| --- | --- | --- | --- |
| Model enna padikkudhu | Muzhu documents | Oru search-la irundhu 3 mudhal 10 passages | Pala steps-la adhoda searches enna kudukkudho adhu |
| Palam | Ellaathaiyum paakkudhu; cross-reference pannalaam | Cheap, fast, millions of documents varai scale aagum | Multi-step kelvigalaiyum exact identifiers-aiyum follow pannum |
| Palaveenam | Length kooda kooda cost-um delay-um koodum; neelamaana inputs-la accuracy kuraiyum | Oru search miss panradhai idhuvum miss pannum | Adhiga calls, slow, predict panradhu kashtam |
| Engineering | Kuraivu | Chunking, indexing, tuning | Nalla tools, step limits, logging |

```flow
title: Measure panradhukku munnaadi, oru mudhal mudivu
Unga documents -[window-la adangum, adikkadi reuse aagum]-> Caching-oda long context
Unga documents -[romba adhigam, chinna factual kelvigal]-> RAG
Unga documents -[romba adhigam, badhilukku pala lookups venum]-> Agentic search
RAG -[kelvigalukku muzhu documents venum]-> Document-level retrieval, appuram long context
```

## Idhu eppadi velai seiyudhu

### Inputs perusaaga accuracy kuraiyudhu

Neelamaana input-la irukkura ella position-aiyum models ore maadhiri nallaa use panradhilla.

- **Lost in the middle.** Liu-vum colleagues-um (2023) models-kku niraiya documents kuduthu paathaanga: badhil aarambathukko kadaisikko pakkathula irundhappo accuracy ellaathaiyum vida adhigamaa irundhuchu, naduvula irundhappo ellaathaiyum vida kuraivaa irundhuchu: oru U-shaped curve.
- **Context rot.** Chroma-voda report (July 2025) 18 models-a test pannuchu; input perusaaga perusaaga performance-a namba mudiyaama pochu, simple tasks-layum kooda. Kelvikkum badhilukkum vaarthaiyilayum arthathulayum otrumai kuraivaa irundhappo, adhaavadhu model match pannaama infer panna vendiyirundhappo, innum vegamaa kurainjudhu. Badhil maadhiriye theriyura aanaa badhil illaadha, nambathagundha ore oru distractor sentence kooda accuracy-a kuraichudhu, distractors kooda kooda innum kurainjudhu.

Idhai ippadi yosichu paarunga: badhilai suthi ore maadhiri theriyura sentences evvalavu adhigamaa irukko, model thappaanadhai edukka avvalavu vaaippu adhigam.

Adhanaala **advertised window**-aiyum (API evvalavu edutthukkudhu) **effective context**-aiyum thanithaniyaa paarunga: effective context-naa *unga* task accurate-aa irukkura length. Oru "needle in a haystack" test, adhaavadhu plant panna oru sentence-a kandupidikkuradhu, romba easy-aana case, ippodhaiya models perumbaalum adhai pass pannidum. Adhu pass aanaalum, clauses-a compare panra, figures-a koottura, allathu oru rule-oda pazhaiya version-a ignore panna vendiya kelvigal pathi adhu perusaa edhuvum sollaadhu.

### Cost: ovvoru call-layum ovvoru token-kkum kaasu

Document cache aagalai-nnaa, ovvoru kelviyum adhai muzhusaa thirumba anuppi, muzhusukkum thirumba kaasu kattudhu. Claude Sonnet 5.5 list prices, 28 November 2026 annaikku Anthropic-oda pricing page-la check pannadhu:

| Item | Million tokens-kku USD | Input price-oda madangu |
| --- | --- | --- |
| Input | $2.00 | 1x |
| Cache write, 5-minute lifetime | $2.50 | 1.25x |
| Cache write, 1-hour lifetime | $4.00 | 2x |
| Cache read | $0.10 | 0.05x |
| Output | $10.00 | 5x |

Cache-read madangu model-kku model maarum: Claude Fable 5.2-la 0.025x, Claude Opus 5.5, Sonnet 5.5-la 0.05x, Claude Haiku 5.5 udpada matha perumbaalaanadhula 0.1x. Sila models neelamaana prompts-kku oru token-kku adhigamaavum charge pannum: Claude Haiku 5.5 input, prompt 100,000 tokens varai irundhaa million tokens-kku $0.10, adhai vida neelamaa irundhaa muzhu request-kkum $0.50 (adhe check date). Matha providers caching-kku vera maadhiri price panraanga, adhanaala unga provider-oda page-a padichu, date-a ezhudhi vainga.

### Prompt caching: adhu enna maathudhu, eppo fail aagudhu

**Eppadi velai seiyudhu.** Unga prompt-oda process panna aarambha pagudhiya (prefix) provider store panni vachukkudhu. Appuram byte-for-byte adhe prefix-oda varra request adhai cache-la irundhu padikkudhu: cheap-aavum, first token-kku vegamaavum. Adhanaala neelamaana, maaraadha pagudhiya mudhalla podunga, kelviya kadaisiyila podunga; idhanaala model ezhudha aarambikkura idathukku pakkathulaye kelviyum irukkum.

**Lifetime.** Default-aa oru cache entry 5 minutes irukkum, ovvoru hit-um clock-a reset pannum. 1-hour lifetime-kku write panna 2x aagum. Anthropic docs solrapadi, 5-minute cache oru read-laye thannoda selavai meettudum, 1-hour cache rendu reads-la.

**Experts check panra gotchas:**

- **Lifetime-a vida neelamaana idaiveligal.** 5-minute cache-oda 15 minutes-kku oru thadavai kelvigal vandhaa, ovvoru call-um 1.25x write-a thirumba kattum, adhanaala cache illaama irukkuradhai vida *adhigamaa* kaasu katturveenga.
- **Maarura prefix.** Document-kku munnaadi oru timestamp, oru user name, allathu order maathina oru tool list irundhaa, adhukku appuram varra ellaathukkum match udainjudum.
- **Parallel calls.** Mudhal response aarambicha piragu thaan oru cache entry available aagum, adhanaala ore nerathula anuppura pathu kelvigalum miss aagum.
- **Oru user-kku oru document.** 500 users ovvorutharum avanga sondha contract-a upload pannaa, adhu 500 thanithani cache writes. Caching ovvoru session-kkum udhavum, mothha system-kku illa.
- **Isolation.** Caches organisations naduvula eppavume share aagaadhu, Anthropic-oda API-la workspaces naduvulayum illa.

Velai senjudhaa-nnu check pannunga: response-oda `usage` `cache_creation_input_tokens`-aiyum `cache_read_input_tokens`-aiyum report pannum. Reads zero-laye irundhaa, edho onnu prefix-a udaikkudhu.

### Latency-yum scale-um

Input length kooda kooda time to first token koodum, adhanaala romba neelamaana uncached prompts chat-a slow-aa feel panna vaikkum. Agentic search ovvoru step-kkum oru model round trip serkkum. Appuram window-kku oru limit irukku; oru company-yoda documents-kku illa. Udhaaranamaa, ovvonnum sumaar 30,000 tokens irukkura 18,000 manuals mothham 540 million tokens, adhaavadhu 1-million-token window-oda 540 madangu. Corpus window-a vida perusaanadhum, edhai anuppanum-nu edhaavadhu onnu thernthedukkanum.

### Agentic search, moonaavadhu option

Unga code thernthedukkura oru search-kku badhilaa, model-e search-a ottudhu. Anthropic thannoda context engineering guide-la (September 2025) indha "just in time" approach-a vivarikkudhu: Claude Code, files thevaippadumbodhu avatrai kandupidikka glob, grep maadhiri tools-a use pannudhu, sila files mattum munnaadiye load aagum. Guide trade-off-a neradiyaa solludhu: run time-la explore panradhu, munnaadiye compute panna retrieval results-a padikkuradhai vida slow.

```flow
dir: LR
title: Oru kelvikku agentic search
Kelvi -> Client vachu contracts-a thedu | filters-oda keyword search
Client vachu contracts-a thedu -> Master agreement-a thira | clause 9-a padikkudhu
Master agreement-a thira -> Clause 9 references-a thedu
Clause 9 references-a thedu -> Citations-oda badhil
```

**Enga jeyikkum:** adutha lookup pona result-a poruthu irukkura kelvigal, embeddings mazhungadikkura exact identifiers (clause numbers, error codes, part numbers), re-index panradhukku badhilaa live-aa query pannakkoodiya vegamaa maarura data. Tools ovvoru user-oda permissions-aiyum enforce pannalaam.

**Enna selavaagum:** ovvoru step-um innoru model call, adhu valarndhukitte irukkura conversation-a thirumba anuppudhu. Udhaaranamaa, instructions-um tools-um 2,000 tokens, ovvoru step-layum 3,000 tokens results serudhu-nnaa, aaru steps 2,000 + 5,000 + ... + 17,000 = 57,000 input tokens anuppum; oru RAG call-kku sumaar 3,000 thaan. Mundhaiya turns-a cache pannaa idhu konjam kuraiyum.

**Eppadi fail aagum:** romba seekkiram niruthidum, adhe search-laye loop aagum, allathu tool output-aala thannoda context-a nirappidum. Nalla defaults: steps-kku oru cap vainga (udhaaranamaa, 8), tools muzhu files-kku badhilaa document IDs-oda chinna snippets-a return pannattum, failures-a padikka ovvoru tool call-aiyum log pannunga.

### Innum rendu patterns

- **Document-level retrieval.** Titles, summaries allathu metadata mela search panni sariyaana sila muzhu documents-a thernthedunga, appuram long context avatrai padikkattum. Contracts, policies, reports-kku idhu porundhum.
- **Map-reduce.** "40 board meetings-aiyum summarise pannu" maadhiri velaikku, ovvoru document-aiyum thaniyaa summarise pannunga (map), appuram summaries-a serunga (reduce). Endha corpus size-kkum porundhum, aanaa detail poyidum, adhanaala ovvoru summary-layum citations-a vachukka sollunga.

```python
def doc_level_prompt(question, search_docs, load_doc, max_docs=3):
    docs = search_docs(question, k=max_docs)    # over titles, summaries and metadata
    context = "\n\n".join(f"<document title='{d['title']}'>\n{load_doc(d['id'])}\n</document>" for d in docs)
    return context + f"\n\nAnswer from the documents above. Cite titles and clause numbers.\nQuestion: {question}"
```

### Privacy

Long context muzhu documents-a model provider-kku anuppudhu; RAG passages-a mattum anuppudhu. Documents-la personal data irundhaa, client-oda data agreement-aiyum Indiavoda data-protection obligations-aiyum check pannunga, task-kku thevaiyillaadhadhai redact pannunga.

### Decision rules

- Onnu allathu sila documents, oru session-la niraiya kelvigal, muzhu text thevaippadura badhilgal: **long context, cached**.
- Periya allathu valarndhukitte irukkura collection, chinna factual kelvigal, niraiya users: **RAG**.
- Onnai onnu saarndha pala lookups allathu exact identifiers thevaippadura badhilgal: **agentic search**, step limits-oda.
- Muzhu documents venum, aanaa thernthedukka noothukkanakkula irukku: **document-level retrieval, appuram long context**.

### Unga sondha documents-la position-aiyum distractors-aiyum test pannunga

Publish aana studies echarikkaigalai thaan kudukkum, badhilgalai illa. Indha harness karpanaiyaana audit notes-a (avai real edhodayum modhaadhu) pala depths-la plant pannudhu, ore maadhiri theriyura distractors-a serkkudhu, oru two-hop kelviya test pannudhu:

```python
import random

FACT = "Audit note: the Hosur warehouse inspection code is HW-7319."
DISTRACTORS = ["Audit note: the Hosur office inspection code is HO-7391.",
               "Audit note: the 2019 Hosur warehouse code, now withdrawn, was HW-1973."]
HOPS = ["Audit note: the Hosur warehouse audit is led by Farida Sheikh.",
        "Audit note: Farida Sheikh's desk extension is 4826."]
CODE_Q = "What is the current inspection code for the Hosur warehouse?"
TESTS = {   # name: (where to insert notes, question, expected answer)
    "single fact": (lambda d: [(d, FACT)], CODE_Q, "HW-7319"),
    "distractors": (lambda d: [(d, FACT)] + [(random.random(), s) for s in DISTRACTORS], CODE_Q, "HW-7319"),
    "two hops": (lambda d: [(d, HOPS[0]), ((d + 0.5) % 1, HOPS[1])],
                 "Which extension reaches the person who leads the Hosur warehouse audit?", "4826"),
}

def build(doc, inserts):
    paras = doc.split("\n\n")                        # insert between paragraphs, never mid-sentence
    for depth, note in sorted(inserts, reverse=True):
        paras.insert(int(len(paras) * depth), note)
    return "\n\n".join(paras)

def run(doc, ask, depths=(0.05, 0.25, 0.5, 0.75, 0.95), runs=3):
    for name, (inserts, question, expected) in TESTS.items():
        for d in depths:
            ok = sum(expected in ask(build(doc, inserts(d)) + "\n\nAnswer from the document only. " + question)
                     for _ in range(runs))
            print(f"{name:12} depth {d:4.0%}: {ok}/{runs} correct")
```

`ask`-naa oru prompt-a anuppi text-a return panra endha function-um. Anthropic SDK-oda:

```python
import anthropic

client = anthropic.Anthropic()

def ask(prompt):
    r = client.messages.create(model="claude-opus-5-5", max_tokens=2000,   # the model you will deploy
                               output_config={"effort": "low"},
                               messages=[{"role": "user", "content": prompt}])
    return "".join(b.text for b in r.content if b.type == "text")
```

Single-fact row kittathatta perfect-aa irukkum-nu edhirpaarunga; distractor, two-hop rows thaan unmaiyaa edhaavadhu sollum. Appuram sections naduvula comparisons maadhiri unga real kelvi vagaigalai serunga.

### Neenga maathakkoodiya oru cost model

```python
# Claude Sonnet 5.5 list prices in USD per million tokens, checked 28 November 2026
# (platform.claude.com/docs/en/about-claude/pricing). Re-check before you use them.
PRICE_IN, PRICE_OUT = 2.00, 10.00
WRITE_X, READ_X = 1.25, 0.05   # 5-minute cache write and cache read, as multiples of PRICE_IN

def call_usd(fresh_in, out, cache_write=0, cache_read=0):
    """Cost of one call. fresh_in: normal input tokens; cache_write/cache_read: cached prefix tokens."""
    inp = fresh_in + cache_write * WRITE_X + cache_read * READ_X
    return (inp * PRICE_IN + out * PRICE_OUT) / 1e6

Q, DOC, ASK, OUT, RAG_IN = 12, 40_000, 100, 300, 3_000

no_cache = Q * call_usd(DOC + ASK, OUT)
cached = call_usd(ASK, OUT, cache_write=DOC) + (Q - 1) * call_usd(ASK, OUT, cache_read=DOC)
expired = Q * call_usd(ASK, OUT, cache_write=DOC)   # every gap longer than the cache lifetime
rag = Q * call_usd(RAG_IN + ASK, OUT)

for name, usd in [("long context, no cache", no_cache), ("long context, cached", cached),
                  ("long context, cache always expired", expired), ("RAG, 3,000 tokens", rag)]:
    print(f"{name:36} ${usd:.3f}")
```

Idhu no cache-la $0.998, cached-la $0.182, cache eppavum expire aanaa $1.238, RAG-kku $0.110-nu print pannum. Caching long-context bill-a 80%-kku mela kuraikkudhu, adhu adhai RAG-kku kitta kondu varudhu; expire aana cache adhai ellaathaiyum vida expensive option aakkudhu. Annaikku rate-la dollars-a convert pannunga, tokenizers vera vera-ngradhaala unga documents-oda tokens-a unga provider-oda counter vachu ennunga.

## Oru worked example

Chennai-la oru law firm-kku oru contract assistant venum. Keezha irukkura numbers illustrative, team record panra maadhiriyaanavai; costs 28 November 2026 annaikku check panna Claude Sonnet 5.5 prices-a vachu pottadhu.

**1. Oru contract-a review panradhu.** Oru lawyer 60-page agreement-a (sumaar 40,000 tokens) upload panni sumaar 12 kelvigal kekkuraaru: termination rights, indemnity caps, conflict aagura clauses. Niraiya badhilgalukku muzhu document venum, adhanaala team long context use pannudhu, contract cached, kelvi kadaisiyila. Lawyers kelvigalukku naduvula adikkadi 5 minutes-kku mela niruthuvaanga, adhanaala 1-hour cache-a thernthedukkuraanga. Appo pannirendu kelvigalukku sumaar $0.24 aagum, uncached-aa sumaar $1.00. Oru 30-question test-la long context 27 sariyaa solludhu, chunk-based RAG 22 solludhu-nnu vachukkonga, RAG miss pannadhu perumbaalum clauses naduvula irukkura cross-references. Team distractor test-aiyum ottudhu, yenna avanga contracts-la adhe clause-oda pazhaiya, maathappatta versions irukku.

**2. Precedent library-la theduradhu.** 25,000 pazhaiya contracts, endha window-aiyum vida romba perusu. Lawyers kekkuraanga: "IT services contracts-la, kadandha 12 months-la kattina fees alavukku cap panna indemnity clauses-a kandupidi". Team metadata filters (contract type, year) kooda hybrid retrieval use panni best 20 clauses-a kandupidikkudhu, appuram oru model avatrai citations-oda summarise pannudhu. Avanga recall-a measure panraanga: 50 test kelvigalla 46-kku sariyaana clause top 20-la irukku-nnu vachukkonga.

**3. Cross-references-a follow panradhu.** Oru partner kekkuraaru: "Indha client kooda irukkura namma contracts-la edhellaam, 2025 amendment-la maarina oru master agreement clause-a saarndhirukku?" Oru search-aala idhukku badhil solla mudiyaadhu: system amendment-a kandupidichu, endha clause maaruchu-nnu padichu, appuram andha clause-a cite panra contracts-a kandupidikkanum. Team moonu tools (client vachu search, document-a open panradhu, clause number vachu search), 8 steps cap kooda agentic search use pannudhu. Oru typical badhilukku 5 tool calls-um sumaar 30 seconds-um aagudhu-nnu vachukkonga: chat-kku romba slow, oru research task-kku paravaayilla.

## Podhuvaana thappugal

- **Advertised window-a namburadhu.** 1 million tokens edutthukkura oru model avatrai nallaa use pannum-nu illa. Unga sondha kelvi vagaigalla effective context-a measure pannunga.
- **Ore oru planted fact vachu mattum test panradhu.** Adhu thaan romba easy-aana case. Distractors, two-hop kelvigal, badhile illaadha kelvigalai serunga.
- **Caching illaama costs-a compare panradhu**, allathu hit aagave aagaadha oru cache-a namburadhu (mela irukkura gotchas-a paarunga).
- **Kelvi, oru timestamp allathu oru user name-a document-kku munnaadi poduradhu.** Adhu cache-a udaikkum, accuracy-aiyum baadhikkum.
- **"RAG sethuduchu" maadhiri yosikkuradhu.** Periya, maarikitte irukkura collections-kku innum retrieval venum, kurainjapatcham documents-a thernthedukkavaavadhu.
- **One-hop lookups-kku oru agent-a use panradhu.** Oru search-laye badhil kidaichaa, agent calls-aiyum delay-aiyum thaan serkkum.
- **Step limit allathu logs illaama oru agent-a otturadhu.** Paakka mudiyaadha failures-a sari panna mudiyaadhu.
- **Personal data niranja muzhu documents-a anuppuradhu**, passages-laye kelvikku badhil kidaikkumbodhu.

## Choice obvious-aa irukkumbodhu

- **Oru chinna document**: adhai appadiye prompt-la podunga.
- **Millions of documents**: edhaavadhu oru vagai retrieval venum, kurainjapatcham documents-a thernthedukkavaavadhu.
- **Records, tables maadhiri structured data-la irundhu badhilgal**: idhula edhaiyum use pannaama, oru tool moolamaa database-a query pannunga.

## Demo-la irundhu production-kku

- **Thernthedutha approach-kku accuracy, cost, latency-a record pannunga**, unga golden set-la, ovvoru model change-layum thirumba check pannunga.
- **Cache hit rate-a track pannunga**, `cache_read_input_tokens`-la irundhu, adhu kurainjaa alert pannunga.
- **Ovvoru request-oda input tokens-aiyum log pannunga**, edhirpaaraadha valarchikku alert pannunga.
- **Position, distractor tests-a thirumba ottunga**, models maathumbodho documents perusaagumbodho.
- **Agents-kku, ovvoru tool call-aiyum log pannunga**, oru badhilukku ethanai steps-nu paarunga; andha count koodradhu oru early warning.
- **Prices-a avatroda date kooda thirumba check pannunga**, kurainjadhu moonu maasathukku oru thadavai.

## Practice

Lost in the Middle abstract-aiyum figures-aiyum, Chroma-voda context rot report-aiyum, unga provider-oda prompt caching guide-aiyum padinga.

1. Oru neelamaana document-a (oru annual report allathu oru policy) eduthu 15 kelvigal ezhudhunga: sila single facts, sila dhoorathula irukkura rendu sections thevaippaduravai, onnu document-la badhile illaadhadhu.
2. Avatrukku long context-layum unga RAG pipeline-layum badhil vaangunga. Ovvonnukkum accuracy, latency, cost-a record pannunga.
3. Long-context run-a prompt caching-oda thirumba pannunga. `cache_read_input_tokens` zero-kku mela irukku-nnu confirm panni, appuram cost-aiyum time to first token-aiyum compare pannunga.
4. Mela irukkura harness-a unga document-la anju depths-la otti, ovvoru test type-kkum depth-kku edhiraa accuracy-a plot pannunga.
5. Two-section kelvigalla rendukku, document mela oru keyword search tool-a oru model-kku kuduthu, adhu ethanai steps edukkudhu-nnu ennunga.

Innum aazhamaa poga, Chip Huyen-oda *AI Engineering* (O'Reilly, 2025) puthagathula chapter 5 context length pathiyum models neelamaana inputs-a evvalavu nallaa use pannudhu-ngradhu pathiyum solludhu, chapter 6 RAG, agents pathi solludhu.

**Mudinjadhu-nnu eppo sollalaam:** oru kurippitta use case-kku long context, RAG allathu agentic search-a, unga sondha accuracy, cost, latency numbers-oda recommend panna mudiyumbodhu.
