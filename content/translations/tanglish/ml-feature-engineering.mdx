## Idhu enna

**Feature engineering**-na raw data-la irundhu model inputs uruvaakkuradhu. Oru manushan padikkura maadhiri oru model-aala transactions table-a padikka mudiyaadhu. Neenga edhai pathi predict panreengalo andha ovvonnukkum oru row venum (inga, oru date-la oru customer), past-a summarise panra columns venum: "kadaisi 30 naalla orders", "kadaisi order-la irundhu ethana naal", "sameebathiya orders-la late-aa deliver aanadhoda share".

Nalla features, oru domain expert edhai paarppaangalo adhai model use pannakkoodiya form-la capture pannum. Tabular data-la pala neram accuracy-la perumbagudhi inga irundhu thaan varudhu.

Ovvoru feature-kkum oru **prediction time** irukku: model-kitta kelvi kekkappadura andha neram. Adhukku munnaadi irukkura ellaathaiyum use pannalaam. Adhukku appuram irukkuradhu ellaam edhirkaalam, label anga thaan irukku.

```flow
dir: LR
title: Prediction time: 00:00 IST, 1 November
1 Nov-kku munnaadi nadandha events | orders, ratings, tickets -> 1 Nov nilavarappadi features | counts, trends, recency
1 Nov nilavarappadi features -[model]-> Label: 1 mudhal 14 Nov varai order pannaangalaa | endha feature-layum use aagaadhu
```

Indha lesson-la Bengaluru-la irukkura oru food-delivery company, endha customers 14 naalukkulla marubadi order pannuvaanga-nnu predict panradhai follow pannuvom.

## Idhu eppadi work aagudhu

### Ore rule: ellaathaiyum prediction time nilavarappadi compute pannunga

**Leakage**-na prediction time-la model-kitta irukkaadha thagaval oru feature-kkulla irukkuradhu. Idhu validation scores-a brilliant-aa kaattum, production results emaathum. Moonu pazhakkangal idhula perumbagudhiyai thadukkum.

1. **Cutoff-kku kandippaa munnaadi irukkuradhai mattum filter pannunga.** `<=` illa, `ts < cutoff` use pannunga. Cutoff nerathoda stamp aana oru event, prediction-kku appuram nadandhirukkalaam.
2. **Medhuvaa maarura tables-a cutoff nilavarappadi join pannunga.** Ratings, loyalty tier, credit limit maadhiriyaanadhukku, innaikku irukkura latest value illa, cutoff-kku munnaadi irundha latest value-a edunga. Pandas-la `merge_asof` idhai seiyum:

```python
import pandas as pd

labels = pd.DataFrame({"customer": [1, 1, 2], "cutoff": pd.to_datetime(["2026-09-01", "2026-10-01", "2026-10-01"])})
ratings = pd.DataFrame({"customer": [1, 1, 2, 2],
                        "rated_at": pd.to_datetime(["2026-08-20", "2026-10-01", "2026-09-15", "2026-10-03"]),
                        "rating": [5, 2, 4, 1]})
joined = pd.merge_asof(labels.sort_values("cutoff"), ratings.sort_values("rated_at"),
                       left_on="cutoff", right_on="rated_at", by="customer",
                       allow_exact_matches=False)     # strictly before the cutoff
print(joined)
```

Customer 1-oda 1 October cutoff-kku, 20 August-la kudutha 5 rating kidaikkudhu. 1 October annaikke kudutha 2 rating vilakkappadudhu, customer 2-oda 3 October rating-um appadithaan.

3. **Oru pindhaiya time period-la validate pannunga.** Pala cutoffs-la (maasathukku onnu) training rows build pannunga, mundhaiyadhula train panni pindhaiyadhula test pannunga. Random split edhirkaala rows-a training-kkulla kalandhudum, adhanaala leaks-um konja naal mattum irukkura patterns-um skill maadhiri theriyum.

### Feature families

| Raw data | Udhaarana features | Yen udhavudhu |
| --- | --- | --- |
| Orders | Kadaisi 7, 30, 90 naalla orders, spend; kadaisi order-la irundhu ethana naal | "Thirumba varuvaangalaa"-kku habit-um recency-um thaan miga strong-aana signals |
| Changes | 30 naal average basket vs 90 naal average; indha maasam vs pona maasam | Medhuvaa vilagi pora customers-a pidikkudhu |
| Ratios | EMI vs income, oru order-kku returns, category average kooda oppitta price | Vera vera aalungalukku idaiyila amounts-a oppidakkoodiya scale-kku kondu varudhu |
| Service | Kadaisi 30 naalla late deliveries-oda share; kadaisi rating; sameebathiya tickets | Aalungalai competitors pakkam thallura mosamaana anubavangalai pidikkudhu |
| Calendar | Vaarathoda naal, salary week, adutha festival-kku ethana naal | Indian demand-um payments-um festivals-aiyum pay cycles-aiyum follow pannudhu |
| Categories | City tier, channel, PIN code | Groups vera vera maadhiri nadandhukkum; encoding venum (keezha paarunga) |
| Text, location | Keyword flags, text embeddings; romba pakkathula irukkura kitchen-kku dhooram | Unstructured data-va numbers-aa maathudhu |

**Experts-la irundhu aarambinga.** Business-a nadathuravangakitta kelunga: "Oru customer vittu pogap poraanga-nnu ungalukku edhai vachu thonudhu?" Delivery managers late deliveries-a solluvaanga; finance payday timing-a sollum. Appuram ovvoru idea-vaiyum measure pannunga, yenna oru sensible idea-vum edhaiyume serkkaama pogalaam (worked example-la appadi onnu varudhu).

### Numeric transforms

- **Missing values.** Oru gap-kku enna arthamnu mudivu pannunga. "30 naalla orders illa"-na adhu unmaiyaana zero; "eppavume orders illa"-na average undefined aagidum. Unmaiyaana zeros-a 0-aala fill pannunga, illaadhadhe oru thagavalaa irukkura idathula oru missing flag (`never_ordered = 1`) serunga. scikit-learn-la irukkura `HistGradientBoostingClassifier` missing values-a neradiyaa yethukkum.
- **Skewed amounts.** Rupees-la spend long-tailed: perumbaalaana customers sila aayirangal selavazhippaanga, oru silar latchangal. Linear models, neural networks-kku `log1p(amount)` use pannunga.
- **Scaling.** Linear models, k-nearest neighbours, neural networks-kku standardise pannunga. Tree models order-a vachu split pannudhu, adhanaala scaling avatrukku edhaiyum maathaadhu.
- **Interactions.** Trees interactions-a thaanaave kandupidikkum. Linear models-kku avatrai ezhudhik kudukkanum, udhaaranamaa `late_share × orders_30d`.

### Categories

- **Konjam values** (city tier, channel): one-hot encoding, aridhaana values-a "other"-aa group panni.
- **Niraiya values** (PIN code, restaurant ID): frequency encoding, target encoding, allathu **hashing trick** (`FeatureHasher` ovvoru value-vaiyum oru fixed ennikkai columns-la onnukku map pannum; collisions konjam accuracy-a kuraikkum, aanaa memory fixed-aa irukkum). Millions kanakkula IDs irundhaa, deep models ovvoru ID-kkum oru **embedding** kathukkum.

**Target encoding** ovvoru category-aiyum adhoda average label-aala replace pannum. Idhu powerful, leak aagradhum easy. Averages-a ella rows-layum compute panna, ovvoru row-oda sondha label-um adhoda feature-kkullaye irukkum. Keezha irukkura demo-la PIN codes-kku unmaiyaana signal edhuvume illa:

```python
import numpy as np, pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import TargetEncoder
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.metrics import roc_auc_score

rng = np.random.default_rng(0)
df = pd.DataFrame({"pin_code": rng.integers(0, 2000, 6000).astype(str),
                   "y": rng.random(6000) < 0.3})          # pin code carries NO real signal

# Wrong: encode with means from ALL rows, then split
df["pin_mean"] = df.groupby("pin_code").y.transform("mean")
tr, te = train_test_split(df, test_size=0.3, random_state=0)
m = LogisticRegression().fit(tr[["pin_mean"]], tr.y)
print("encoded before split:", round(roc_auc_score(te.y, m.predict_proba(te[["pin_mean"]])[:, 1]), 2))

# Right: the encoder lives inside the pipeline and is fitted on training rows only
pipe = make_pipeline(TargetEncoder(), LogisticRegression()).fit(tr[["pin_code"]], tr.y)
print("encoded after split :", round(roc_auc_score(te.y, pipe.predict_proba(te[["pin_code"]])[:, 1]), 2))
```

Thappaana vazhikku 0.85, sariyaana vazhikku sumaar 0.5 print aagum (exact value ovvoru run-kkum konjam maarum): suthamaana noise oru strong feature maadhiri score aagudhu. scikit-learn-oda `TargetEncoder` `fit_transform`-kkulla cross-fit-um pannudhu, adhanaala training rows kooda avatroda sondha label-a paarkkave paarkkaadhu. Scalers, imputers, feature selection-kkum idhe rule thaan: split-kku appuram, pipeline-kkulla fit pannunga. Data-kku time order illaadhadhaala mattum thaan indha demo random split use pannudhu.

### Calendar features

```python
import pandas as pd

# In production this is a reviewed data file, one row per festival, year and region
festivals = pd.DataFrame([
    ("onam", "2026-08-26", "kerala"),          # Thiruvonam day
    ("dussehra", "2026-10-20", "all"),
    ("diwali", "2026-11-08", "all"),
], columns=["festival", "date", "region"]).assign(date=lambda d: pd.to_datetime(d.date))

def calendar_features(dates, region):
    d = pd.Series(pd.to_datetime(dates))
    fest = festivals[festivals.region.isin([region, "all"])].date
    gap = d.apply(lambda x: min(((f - x).days for f in fest if f >= x), default=60))
    return pd.DataFrame({"date": d, "dow": d.dt.day_of_week, "salary_week": (d.dt.day <= 7).astype(int),
                         "days_to_festival": gap.clip(upper=60)})

print(calendar_features(["2026-08-20", "2026-10-15", "2026-11-03"], "kerala"))
```

Festival dates ovvoru varushamum maarum, sila (Eid maadhiri) nilaa paarkkuradhai poruthadhu, adhanaala official lists-kku idaiyila dates oru naal vithiyaasappadalaam. Oru region column vachu, ovvoru varushamum official holiday lists-la irundhu table-a update pannunga.

### Training-serving consistency

**Training-serving skew**-na production oru feature-a training-la irundhu vera maadhiri compute panradhu. Podhuvaana kaaranangal: serving-la UTC days, training-la IST days; "active customer"-kku vera definition; illanna data-voda kadaisi oru mani nerathai miss panra oru serving query. Model crash aagaadhu; sathamillaama mosamaagitte pogum.

```flow
dir: LR
title: Oru feature function, rendu callers
Raw events -> features_as_of | test panna ore function
features_as_of -[niraiya past cutoffs]-> Training rows
features_as_of -[cutoff = now]-> Live features
```

Feature code-a ore thadavai ezhudhi rendu idathula irundhum call pannunga, encoders-a model pipeline-kkullaye vainga, appo fit panna objects model koodave pogum. Periya scale-la, Feast (open source) maadhiri oru **feature store** idhai ungalukku pannum. Adhu oru point-in-time join vachu training sets build pannum (ovvoru label-oda timestamp-layo adhukku munnaadiyo irundha latest feature value), fresh values-a oru fast online store-kku copy pannum (idhukku materialisation-nnu peru), prediction time-la andha values-a serve pannum.

### Features-a therndhedukkuradhu

Adhiga features eppavume nalladhu illa. Ovvonnukkum maintain panna oru pipeline selavu, leak aaga oru vaaippu. Groups-aa measure pannunga (counts, recency, service, calendar), rendu vazhiyila: ovvoru group-aiyum oru simple baseline-la serthu, ovvoru group-aiyum full set-la irundhu eduthu. Features pala neram overlap aagum, adhanaala oru group-a thaniyaa serthaa udhavinaalum, adhai edukkuradhaala perusaa izhappu illaama pogalaam. Pala test months-la gain repeat aagura groups-a vachukkonga.

## Oru worked example

Bengaluru team-oda kelvi: ovvoru monthly cutoff-kku appuram varra 14 naalla oru customer order pannuvaangalaa? Keezha irukkura code synthetic data use pannudhu, adhanaala neenga run panni, numbers-a paarthu, break panniyum paarkkalaam. Rendu effects plant panniyirukku: paadhi customers edho oru kattathula medhuvaa vilaga aarambippaanga (mudhalla chinna baskets, appuram rendu maasam kazhichu kuraivaana orders), oru maasathula rendu late deliveries oru customer-a vera app-kku maatha vaikkalaam.

```python
import numpy as np, pandas as pd
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import roc_auc_score

# 1. Synthetic orders for 3,000 customers, January to October 2026, with two planted effects
rng = np.random.default_rng(7)
N, days = 3000, pd.date_range("2026-01-01", "2026-10-31")
base = rng.gamma(2, 0.06, N)                             # usual daily chance of ordering
late_p = np.where(rng.random(N) < 0.3, 0.3, 0.05)        # 30% live where deliveries run late
drift = np.where(rng.random(N) < 0.5, rng.integers(30, 270, N), 9999)  # day a customer starts drifting
late_log, left, rows = np.zeros((len(days), N), bool), np.zeros(N, bool), []
for t, day in enumerate(days):
    shrink = np.clip(1 - (t - drift) / 60, 0.4, 1)       # drifters first buy smaller baskets,
    fade = np.clip(1 - (t - drift - 60) / 20, 0.05, 1)   # then two months later stop ordering
    left |= (late_log[max(0, t - 30):t].sum(0) >= 2) & (rng.random(N) < 0.03)  # 2 late orders: may switch apps
    ordered = rng.random(N) < base * fade * np.where(left, 0.1, 1)
    late_log[t] = ordered & (rng.random(N) < late_p)
    for c in np.flatnonzero(ordered):
        rows.append((c, day, round(rng.gamma(4, 100) * shrink[c]), late_log[t, c]))
orders = pd.DataFrame(rows, columns=["customer", "ts", "amount", "late"])

# 2. Features as of a cutoff, from orders strictly before it
def features_as_of(orders, cutoff):
    past, out = orders[orders.ts < cutoff], {}
    for d in (7, 30, 90):
        g = past[past.ts >= cutoff - pd.Timedelta(days=d)].groupby("customer")
        out[f"orders_{d}d"], out[f"spend_{d}d"] = g.size(), g.amount.sum()
        if d == 30: out["late_share_30d"] = g.late.mean()
    out["days_since_last"] = (cutoff - past.groupby("customer").ts.max()).dt.days
    f = pd.DataFrame(out).reindex(range(N))
    f = f.fillna({c: 0 for c in f if c.startswith(("orders_", "spend_"))})
    f["basket_change"] = (f.spend_30d / f.orders_30d) / (f.spend_90d / f.orders_90d)  # NaN if no orders
    return f                                              # trees accept NaN; it means "no recent orders"

# 3. One row per customer per monthly cutoff; label = ordered in the 14 days after it
def labelled(cutoff):
    X = features_as_of(orders, cutoff)
    nxt = orders[(orders.ts >= cutoff) & (orders.ts < cutoff + pd.Timedelta(days=14))]
    X["leaky_orders_7d"] = features_as_of(orders, cutoff + pd.Timedelta(days=7)).orders_7d  # bad join
    return X, X.index.isin(nxt.customer).astype(int)

def stack(months):
    parts = [labelled(pd.Timestamp(f"2026-{m:02d}-01")) for m in months]
    return pd.concat([x for x, _ in parts]), np.concatenate([y for _, y in parts])

Xtr, ytr = stack(range(4, 9))     # train on April to August cutoffs
Xte, yte = stack([9, 10])         # test on later months, never a random split

def auc(cols):
    m = HistGradientBoostingClassifier(random_state=0).fit(Xtr[cols], ytr)
    return round(roc_auc_score(yte, m.predict_proba(Xte[cols])[:, 1]), 3)

full = [c for c in Xtr if c != "leaky_orders_7d"]
print("orders_30d only     ", auc(["orders_30d"]))
for name, extra in [("+ 7 and 90 day counts", ["orders_7d", "orders_90d"]), ("+ recency", ["days_since_last"]),
                    ("+ basket change", ["basket_change"]), ("+ late share", ["late_share_30d"])]:
    print(name.ljust(20), auc(["orders_30d"] + extra))
print("all features        ", auc(full))
print("all + leaky feature ", auc(full + ["leaky_orders_7d"]))
```

Leaky column oru unmaiyaana bug-a copy pannudhu: vaarathoda kadaisi naalai key-aa vacha oru weekly table-a, adhoda mudhal naal key maadhiri ninachu cutoff kooda join pannadhu, adhanaala "kadaisi 7 naal" sathamillaama "adutha 7 naal"-aa maariduchu.

Adhu print panradhu (September, October cutoffs-la test AUC; synthetic data, adhanaala idhai illustrations-aa mattum paarunga):

| Features | Test AUC |
| --- | --- |
| Kadaisi 30 naalla orders mattum | 0.803 |
| + 7 naal, 90 naal counts | 0.832 |
| + kadaisi order-la irundhu ethana naal | 0.818 |
| + basket change | 0.807 |
| + late-delivery share | 0.805 |
| Ella honest features | 0.848 |
| Ellaam, + leaky join | 0.935 |

Vera anju seeds-la marubadi run pannaalum idhe pattern thaan varudhu, ovvoru number-um sumaar 0.01 alavukku nagarum.

**Indha numbers enna kathukkudukkudhu.**

- **Periya velaiyai windows-um recency-um thaan pannudhu.** Ore oru 30 naal count-aala "pona vaaram rendu thadavai order pannaanga"-vaiyum "oru maasam munnaadi rendu thadavai order pannaanga"-vaiyum pirichu solla mudiyaadhu. 7 naal, 90 naal windows serthaa model-kku oru trend kidaikkudhu, kadaisi order-la irundhu ethana naal-ngradhu timing-a kudukkudhu.
- **Oru unmaiyaana kaaranamum konjam thaan serkkalaam.** Indha data-la late deliveries unmaiyaave customers-a virattudhu, yenna simulation appadithaan solludhu. Aanaalum late-share feature thaniyaa kittathatta edhaiyume serkkala: endha 14 naal window-layum adhu konja customers-a thaan baadhikkudhu, yerkanave vittu ponavanga kuraivaana orders-aave therinjudraanga. Basket change-um adhe maadhiri thaan. Meeting-la sensible-aa thonura ideas-um oru test-la thangaloda idathai sambaadhikkanum.
- **Leak sathamaa theriyum.** Ore column-aala 0.85-la irundhu 0.93-kku jump vandhaa adhu thaan warning. Kadaisiyaa sertha columns-a ovvonnaa remove panni kandupidinga, appuram andha winner-a uruvaakkuna join-a padinga.

## Podhuvaana thavarugal

- **Cutoff nerathulayo adhukku appuramo nadandha events-a use panradhu.** `ts < cutoff` vachu filter pannunga, medhuvaa maarura tables-a "innaikku irukkura latest value" vachu illa, as-of join vachu join pannunga.
- **Time-ordered data-la random splits.** Ore customer pala cutoffs-la varuvaanga, edhirkaalam training-kkulla leak aagum. Mundhaiya maasangalla train pannunga, pindhaiya maasangalla test pannunga.
- **Split-kku munnaadiye encoders, scalers, imputers-a fit panradhu.** Avatrai pipeline-kkulla vainga, appo training rows-la mattum fit aagum.
- **Training-kkum serving-kkum thanithani feature code.** Rendu versions-um vilagi pogum (UTC vs IST, "active"-kku rendu definitions). Ore function-a share pannunga, illanna oru feature store use pannunga.
- **Festival dates-a hard-code panradhu.** Avai ovvoru varushamum maarum, region-kku region verupadum. Dates irukkura oru table vainga.
- **Oru jump-a investigate pannaama kondaaduradhu.** Oru feature-aalayo oru join-aalayo varra periya gain, vera maadhiri prove aagura varaikkum leak thaan.
- **Ore nerathula noothukkanakkaana features serkkuradhu.** Groups-aa serthu ovvoru group-aiyum measure pannunga, appo endha features avatroda maintenance-kku thagundha palan tharudhu-nnu theriyum.

## Adhigamaana feature engineering eppo thevaiyilla

- **Unstructured data**: images, audio, long text maadhiri, anga neural networks thangaloda features-a thaangale kathukkum.
- **Oru strong pretrained model allathu embeddings** ungalukku vendiyadhai yerkanave capture panniyirukkumpodhu.
- **Romba kammiyaana data**: anga nooru engineered features-a vida sila expert features-um oru simple model-um thaan jeyikkum.

## Demo-la irundhu production-kku

- **As-of rule-a test pannunga**: oru edhirkaala event-a serthu, endha feature-um maarala-nnu check panra oru unit test.
- **Training, serving outputs-a compare pannunga**: launch-kku munnaadi customers-oda oru sample-kku, adhukku appuram oru schedule-la.
- **Feature distributions-aiyum missing rates-aiyum track pannunga**, ovvoru source-kkum, appo oru udainja upstream table medhuvaana accuracy drop-aa illaama oru alert-aa theriyum.
- **Ovvoru retrain-layum feature groups-a marubadi measure pannunga**, udhavuradhai niruthunadhai drop pannunga.

## Practice

Kaggle-oda Feature Engineering course-a mudichu, Google-oda Rules of ML-la feature engineering section-a padinga. Appuram worked example code-a use pannunga:

1. Ungaloda sondha moonu features serunga (udhaaranamaa, orders-la weekend share, illanna adutha festival-kku ethana naal), ovvonnaiyum baseline-la serthum full set-la irundhu eduthum measure pannunga.
2. Oru cutoff-kku oru nimisham appuram date potta oru order-a serthu, `features_as_of` maarunaa fail aagura oru test ezhudhunga.
3. Time split-a ella rows-layum oru random 80/20 split-aa maathunga. Inga adhu scores-a yethaadhu, yenna simulation-la maasathukku maasam shifts illa. Oru random split-a over-optimistic aakkura rendu unmaiyaana maatrangalai sollunga (oru price rise, oru pudhu competitor).
4. April-la irundhu June varai train panni, August-la irundhu October varai test pannunga. Table-la irukkura feature groups-oda ranking innum appadiye irukkaa-nnu check pannunga.

**Mudinjadhu-nnu eppo sollalaam:** ovvoru feature-kkum, adhu prediction time nilavarappadi eppadi compute aagudhu, oru pindhaiya period-la adhai eppadi validate panneenga, production adhai eppadi adhe maadhiri compute pannudhu-nnu solla mudiyumpodhu thaan.
