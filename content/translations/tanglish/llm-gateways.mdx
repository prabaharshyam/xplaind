## Idhu enna

**LLM gateway**-na unga applications-ukkum model providers-ukkum naduvula irukkura oru service. Applications oru API format-la gateway-a call pannum; gateway ovvoru request-aiyum sariyaana provider, model-ku forward pannum, cross-cutting concerns-a oru thadavai handle pannum:

- **Routing**: indha request-ku entha model, provider.
- **Fallbacks**: provider error, timeout, rate-limit aanaa enna try pannanum.
- **Keys, access**: teams-ku gateway keys kidaikkum; nijamaana provider keys gateway-la mattum irukkum.
- **Limits, budgets**: per team, per key, per user.
- **Logging, cost**: ovvoru request-um, adhoda tokens-um cost-um, oru idathula.
- **Caching**: ore maadhiri requests-a optional-aa thirumba use panradhu.

LiteLLM maadhiri open-source options, commercial gateways, cloud providers-oda API management services ellaam indha role-a fill pannum.

```flow
Chatbot -[key A]-> Gateway, 2 instances
Extraction -[key B]-> Gateway, 2 instances
Summariser -[key C]-> Gateway, 2 instances
Search -[key D]-> Gateway, 2 instances
Gateway, 2 instances -[alias chat-default]-> Model X, Mumbai
Model X, Mumbai -[fails]-> Fallback 1: model X, second region
Fallback 1: model X, second region -[fails]-> Fallback 2: approved model Y, provider 2
```

Gateway ovvoru key-kum 75%-la alerts-oda budgets, retries, timeouts, masked logs (team, feature, model, tokens, cost, latency) serkkum. Provider keys inga mattum, oru secret store-la irukkum, rotate aagum.

Indha lesson Bengaluru-la oru fintech-a follow pannum, anga naalu teams-oda aindhu AI features ovvonnum direct-aa providers-a call pannudhu.

## Idhu eppadi work aagudhu

**Oru interface.** Perumbaalaana gateways OpenAI-compatible illa adhu maadhiri request format-a edhukkum, ovvoru provider-kum translate pannum, adhanaala oru feature-a oru model-la irundhu innoru model-ku maathradhu configuration change, code change illa.

**Routing rules.** Model alias-la route pannunga (`summariser-default` neenga central-aa maathura oru specific model-a point pannum), team-la, region-la (Indian user data-va Indian-region endpoints-ku mattum anuppunga), illa request features-la. Smart routers easy requests-a cheap models-ku anuppum; adutha lesson idha pesum.

**Fallbacks.** Idhu maadhiri oru chain: Mumbai region-la primary model; timeout illa 5xx vandha, vera region-la adhe model; thirumba fail aanaa, vera provider-oda comparable model. Fallbacks-la jaakkirathai thevai: fallback model andha task-ku pothumaana alavu nallaa irukkanum, data rules-la allow aagi irukkanum.

**Retries, timeouts.** 429s, transient errors-ku gateway backoff-oda retry pannum, timeouts-a enforce pannum, adhanaala ovvoru application-um idha thirumba implement panna vendaam.

**Budgets.** Ovvoru key-kum monthly illa daily budget irukkum; adhu thaandina requests refuse illa downgrade aagum. Thresholds-la alerts varum.

**Gateway-oda cost.** Idhu odanum, secure pannanum, available-aa vaikkanum-nu innoru service; adhu down aanaa ella AI feature-um down aagum. Kuraindhadhu rendu instances, health checks, own monitoring-oda odunga.

**Gateway features-um adhu theerkkura problems-um:**

| Feature | Theerkkura problem |
| --- | --- |
| Oru request format | Ovvoru team-um ovvoru provider-kum code ezhudhuradhu |
| Model aliases | Neraya apps-la hard-code panna model names |
| Fallbacks | Oru provider outage oru feature-a down pannuradhu |
| Central keys | Teams, laptops-la sidharuna provider keys |
| Budgets per key | Oru feature amaidhiyaa perumbaalaana selavu-a use panradhu |
| Unified logs | Features muzhukka cost, latency, errors-a paarkka mudiyaadhu |
| Caching | Ore maadhiri requests-ku thirumba panam kudukkuradhu |

**Fallbacks-a test panradhu.** Ovvoru thadavaiyum fire aagaadha fallback work aagaama irukkalaam. Staging-la, thappaana key illa block panna endpoint-oda primary-a venumnae udaichi, requests adutha option vazhiyaa success aagudhaa, latency acceptable-aa irukkudhaa, ovvoru request-a entha model actual-aa serve pannuchu-nu logs record pannudhaa-nu paarunga. Chain-la ovvoru maatram-kum aprom thirumba pannunga. Ovvoru fallback model-layum feature-oda evals-a odunga, outage-la users-ku enna quality kidaikkum-nu theriyum.

**Gateway-a roll out panradhu.** Mudhalla oru low-risk feature-a maathunga, adhoda errors, latency, cost-a munnaadi irundhadhoda compare pannunga, apram matha-vangala onnu onnaa migrate pannunga. Ovvoru team-oda pazhaya direct keys-a konjam overlap-ku vechirunga, apram revoke pannunga, adhanaala providers-ku gateway thaan oru-ae vazhi.

**Oru gateway configuration.** LiteLLM-oda proxy oru common open-source choice; matha gateways-um ade ideas follow pannum. Oru file aliases, nijamaana models, fallbacks, admin key-a define pannum:

```yaml
# litellm-config.yaml
model_list:
  - model_name: chat-default                 # the alias apps use
    litellm_params:
      model: anthropic/claude-sonnet-5-5     # check the docs for current names
      api_key: os.environ/ANTHROPIC_API_KEY
      timeout: 30
  - model_name: chat-backup
    litellm_params:
      model: bedrock/<model id from your Bedrock console>
      aws_region_name: ap-south-1
  - model_name: fast
    litellm_params:
      model: anthropic/claude-haiku-5-5

litellm_settings:
  num_retries: 2
  fallbacks: [{"chat-default": ["chat-backup"]}]

general_settings:
  master_key: os.environ/LITELLM_MASTER_KEY
  database_url: os.environ/GATEWAY_DB_URL     # stores keys, budgets and spend
```

Load balancer-ku pinnaadi rendu illa adhukku mela instances-oda odunga: `litellm --config litellm-config.yaml --port 4000`.

**Apps alias-a call pannum, provider-a illa.** Entha OpenAI-compatible client-um work aagum:

```python
import os
from openai import OpenAI

client = OpenAI(base_url="https://gateway.internal.example.in", api_key=os.environ["TEAM_CLAIMS_KEY"])
reply = client.chat.completions.create(model="chat-default",
                                       messages=[{"role": "user", "content": "Summarise this claim: ..."}])
```

Ella apps-aiyum oru pudhu model-ku maathradhu ippo gateway config-la oru line, code maadhiri review panni, mudhalla golden set-la test pannalaam.

**Ovvoru team-kum budgets-oda keys.** Admin ovvoru feature-kum oru virtual key create pannuvaanga:

```bash
curl -s https://gateway.internal.example.in/key/generate \
  -H "Authorization: Bearer $LITELLM_MASTER_KEY" -H "Content-Type: application/json" \
  -d '{"models": ["chat-default", "fast"], "max_budget": 50, "budget_duration": "30d",
       "metadata": {"team": "claims", "owner": "platform-lead"}}'
```

Team provider keys-a paakkaadhu; avangaloda virtual key-a revoke pannina vera edhaiyum rotate pannaama cut off aaidum. Budgets gateway-oda currency setting-la irukkum (perumbaalum US dollars), adhanaala convert panni rate-a note pannunga.

**Region-aware routing.** Indian personal data-ku, andha features use panra aliases-a Indian-region endpoints-ku mattum point pannunga, vera regions use panna allowed features-ku thani alias vainga. Ovvoru call-oda region-aiyum log pannunga, audit-la rule nilladuchu-nu confirm panna mudiyum.

**Gateway oru critical infrastructure.** Adhoda latency (millisecond mattum serkkanum), error rate, database health-a monitor pannunga, unga apps kitta vainga, oru documented emergency path vainga, example oru critical feature-a adhoda provider-ku direct-aa anuppura feature flag.

**Browser-la try pannunga.** Gateway-oda fallback chain simulate panna: primary fail aanaa adutha model badhil solludhu.

```python
import random

random.seed(5)
def call(model):
    if model == "primary" and random.random() < 0.3:
        raise TimeoutError("primary timed out")
    return f"answer from {model}"

def gateway(chain=("primary", "backup")):
    for model in chain:
        try:
            return call(model)
        except TimeoutError as err:
            print("  fell back:", err)
    return "all models failed"

for i in range(5):
    print(i, gateway())
```

## Oru worked example

Bengaluru fintech-la naalu teams build panna aindhu AI features irukku. Ovvoru team-kum own provider keys; finance oru periya monthly bill-a paakkudhu. Kadandha maadham oru provider outage customer chatbot-a 50 nimisham down pannuchu.

Neenga avanga Kubernetes cluster-la rendu instances-oda oru gateway deploy panreenga:

- Ovvoru team-kum team, feature tag-oda gateway key kidaikkum; provider keys gateway-oda secret store-ku poi, rotate aagum.
- Model aliases: `chat-default`, `extract-default`, `embed-default`, ovvonnum oru specific model-a point pannum, adhanaala evals pass aana aprom upgrades central-aa nadakkum.
- `chat-default`-ku fallbacks: second region-la adhe model, apram compliance team approve panna second provider-oda comparable model.
- Budgets: ovvoru feature-kum monthly cap-um 75%-la alert-um.
- Logs: team, feature, model, tokens, cost, latency-oda ovvoru request-um avanga analytics store-ku pogum.

Adutha provider incident-la, 50 nimisham errors-ku badhila, fallback edukkum podhu 90 second slower responses mattum. Finance mudhal thadavaiyaa feature-wise monthly cost report paakkudhu, oru internal summarisation job selavu-la 40% use pannudhu-nu kaattudhu. Andha team adha batch job-aa maathi cheaper model-ku kondu pogudhu.

| Measure | Gateway-ku munnaadi | Aprom |
| --- | --- | --- |
| Provider incident-oda effect | 50 nimisham chatbot errors | 90 second slower responses |
| Provider keys | Naalu teams-kitta | Gateway-la mattum, rotate aagum |
| Cost visibility | Oru monthly bill | Team, feature-wise report |
| Periya kandupidippu | Theriyaadhu | Oru summary job 40% selavu, batch-um cheaper model-um-ku maathinom |

## Podhuvaa panra thappugal

- **Oru gateway instance mattum.** Neenga pudhu single point of failure-a create pannitteenga. Neraya odunga.
- **Approve aagaadha models, regions-ku fallbacks.** Oru outage data-va allow illaadha idathukku silent-aa anuppa koodaadhu.
- **Apps-la hard-code panna model names.** Aliases use pannunga, upgrades-um swaps-um central-aa irukkum.
- **Per-feature attribution illa.** Provider-wise mattum cost reports edha fix pannanum-nu solladhu.
- **Masking illaama full prompts irukkura gateway logs.** Gateway ungakitta irukkura periya sensitive data store aaidum.
- **Oru gateway instance mattum** adhu fail aanaa ella AI feature-aiyum down pannum.
- **Test pannaadha fallbacks**, mudhal thadavai fire aagum podhu output formats-a, quality-a udaichidum.
- **Gateway aliases-ku badhila application code-la model names.**

## Gateway overkill-aa irukkura neram

- **Oru app, oru provider**: retries-um budget alert-um irukkura provider SDK pothum.
- **Sinna team**, gateway odradhukku selavu pannura neram, adhu micham pannura neraththa vida adhigam.
- **Keys, budgets, routing-a already tharra managed platform.**

Neraya teams illa apps providers, keys, budgets-a share panna aarambichaa gateway payan tharum.

## Demo-la irundhu production-ku

- **Kuraindhadhu rendu instances odunga**, health checks, own monitoring-oda.
- **Config-a Git-la vainga**, review pannunga, model changes-ku golden set-la test pannunga.
- **Ovvoru team-kum virtual keys kudunga**, budgets, owners-oda.
- **Personal data-va approved regions-ku mattum route pannunga**, regions-a log pannunga.
- **Fallbacks-a drill pannunga**, staging-la primary-a udaichu.
