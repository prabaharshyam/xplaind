## Idhu enna

**Metadata**-na oru chunk-oda text illaama, adha pathi irukkura information. RAG-la idhu aindhu velaigal pannum:

- **Filters**: product, region, document type, language, date-padi searches-a restrict pannum.
- **Citations**: oru answer enga irundhu vandhadhu-nu (document, section, page, link) sariyaa solludhu.
- **Freshness**: current versions-a virumbum illa thevaippadum, superseded-a vittudum.
- **Permissions**: oru chunk-a yaar paakkalaam-nu mudivu pannum.
- **Nalla matching**: document title, section path maadhiri chunk text-la illaadha context-a serkkum.

```flow
Chunk text | "This limit is 45 days." Hard to find on its own -> Stored with metadata | doc: Leave Policy 2026 (v4), section: Earned leave > Carry forward, page 4, state KA, access: all-employees
Stored with metadata -> Embedded text | "Leave Policy 2026 > Earned leave > Carry forward: This limit is 45 days."
Stored with metadata -> Query filter | the user's state, not superseded, access in the user's groups
```

Indha lesson-la Bengaluru-la oru IT company-la, aindhu states-la irukkura employees-ku serve panra HR assistant-a follow pannuvom.

## Idhu eppadi work aagudhu

**Ingestion-la collect pannunga.** Ovvoru chunk-kum kuraindha pakshama store pannunga:

- document id, title, source system, link;
- section path ("Leave Policy > Earned leave > Carry forward"), page;
- document type (policy, circular, FAQ, contract);
- dates: published, effective from, effective to, last modified;
- language;
- owner illa department;
- access groups.

**Contextual text.** "This limit is 45 days"-nu solra chunk-a retrieve panradhu kashtam. Embed aagura text-oda mudhalla title-um section path-um serunga ("Leave Policy v4 > Earned leave > Carry forward: This limit is 45 days"), illa ovvoru chunk-kum oru vaakkiya context-a model ezhudha vainga. Indha maadhiri contextual enrichment retrieval failures-a kavanikkura alavukku kuraikkum.

**Generated metadata.** Ovvoru chunk-um badhil solra sinna summary, keywords, illa questions-a oru model serkkalaam. Users documents-a vida romba vera maadhiri pesumbodhu, likely questions-a embed panna help aagum. Ingestion-la ovvoru chunk-kum oru model call selavu, adhanaala mudhalla unga golden set-la gain-a alandhu paarunga.

**Query-la irundhu filters.** Sila filters user-oda context-la irundhu varum (avanga region, access groups). Matha sila-va oru sinna model vachu kelvi-la irundhu infer pannalaam ("2026-la irundhu Karnataka-ku leave rules" region = KA, effective after 2026-01-01 aagum). Conservative-aa infer pannunga: thappaana filter sariyaana answer-a maraichidum.

**Freshness rules.** Effective dates-um "superseded by" link-um store pannunga. User history pathi kekkaama irundhaa, superseded documents-a default-aa filter pannunga.

**Consistency.** Filters match aaga, fixed vocabularies (department names, document types, region codes) use pannunga. Metadata-va ingestion-la, vera endha data-vayum maadhiri, validate pannunga.

**Practice-la oru chunk record:**

| Field | Example | Edhukku use |
| --- | --- | --- |
| `doc_id`, `title`, `url` | `HR-LP-2026`, Leave Policy 2026 | Citations-um links-um |
| `section_path`, `page` | Earned leave, Carry forward; page 4 | Thulliyamaana citations, contextual text |
| `doc_type` | `policy` | Filters |
| `state` | `KA` | User profile-la irundhu filters |
| `effective_from`, `effective_to` | 2026-01-01, open | Freshness |
| `superseded_by` | none | Pazhaya versions-a vilakkradhu |
| `language` | `en` | Filters, analysers-a choose panradhu |
| `access_groups` | `all-employees` | Permissions |

**Metadata-va validate panradhu.** Metadata-va vera endha data-vayum maadhiri nadathunga. Ingestion-la, thevaiyaana fields irukkaa, values fixed lists-la irundhu varudhaa, effective dates logic-aa irukkaa (end date start date-ku aprom) nu check pannunga. Fail aagura chunks-a reject illa quarantine panni, ovvoru run-kum counts report pannunga. "KA"-ku badhila "Karnatka"-nu tag aana oru document, ovvoru Karnataka employee-oda search-la irundhum amaidhiyaa maraindhidum.

**Code-la metadata-va validate pannunga.** Edhuvum index aagura munnaadi, fixed vocabularies-um date rules-um check aagum:

```python
from datetime import date
from typing import Literal
from pydantic import BaseModel, field_validator, model_validator

State = Literal["KA", "TN", "MH", "DL", "ALL"]
DocType = Literal["policy", "circular", "faq", "contract"]

class ChunkMeta(BaseModel):
    doc_id: str
    title: str
    section_path: str
    page: int
    doc_type: DocType
    state: State
    language: Literal["en", "hi", "ta", "kn", "mr"]
    effective_from: date
    effective_to: date | None = None
    superseded_by: str | None = None
    access_groups: list[str]

    @field_validator("access_groups")
    @classmethod
    def not_empty(cls, v):
        if not v:
            raise ValueError("every chunk needs at least one access group")
        return v

    @model_validator(mode="after")
    def dates_in_order(self):
        if self.effective_to and self.effective_to < self.effective_from:
            raise ValueError("effective_to is before effective_from")
        return self
```

Ovvoru chunk-aiyum `ChunkMeta.model_validate` vazhiyaa anuppunga, pass aanadha index pannunga, failures-a error-oda oru quarantine table-la ezhudhunga. "Karnatka" ippo maraiyaama, satthama fail aagum.

**Kelvi-la irundhu filters-a, paadhugaappaa infer pannunga.** Oru sinna model-kitta filters-a structured output-aa, oru confidence-oda kelunga, kelvi-la theliva sonnaa mattum apply pannunga:

```python
class Filters(BaseModel):
    state: State | None = None
    year_from: int | None = None
    doc_type: DocType | None = None
    explicit: bool        # true only if the user named these in the question

def apply_filters(f: Filters, user_state):
    filters = {"state": [user_state, "ALL"], "current": True}    # from the profile, always safe
    if f.explicit:
        if f.state:
            filters["state"] = [f.state, "ALL"]
        if f.year_from:
            filters["effective_from_gte"] = date(f.year_from, 1, 1)
        if f.doc_type:
            filters["doc_type"] = f.doc_type
    return filters
```

Filter panna search edhuvum tharaadhunaa, infer panna filters illaama oru thadavai thirumba try pannunga, logs-la adha solliyum vainga.

**Oru document-a supersede panradhu.** Pudhu version varum podhu, pazhayadha adhe transaction-la mark pannunga:

```sql
BEGIN;
UPDATE chunks SET superseded_by = 'HR-LP-2026', effective_to = '2025-12-31' WHERE doc_id = 'HR-LP-2025';
INSERT INTO chunks (...) VALUES (...);   -- the new version's chunks
COMMIT;
```

Default searches `superseded_by IS NULL`-a filter pannum; history kelvigal ("2024-la rule enna?") andha filter-a vittu, dates-a use pannum.

**Payoff-a check pannunga.** Ovvoru metadata piece-kum (contextual text, generated questions, inferred filters) irukkum podhum illaama podhum, unga golden set-la recall at 5-a alandhu paarunga, help pannuradha mattum vechukkonga.

## Oru worked example

Bengaluru-la oru IT company-oda HR assistant aindhu states-la employees-ku serve pannudhu. Leave-um holiday rules-um state-ku state maarum, policies varushaa varusham revise aagum.

Munnaadi: chunks-la file name mattum thaan irundhuchu. Assistant Karnataka-vum Maharashtra-vum holiday lists-a kalandhu, sila neram pona varusha policy-a quote pannum.

Re-ingestion-ku aprom, ovvoru chunk-layum state, policy type, effective dates, version, section path, access groups irukku. Employee-oda state avanga sign-on profile-la irundhu eduthu filter-aa apply aagum, avanga vera state pathi kekkaama irundhaa. Superseded versions default-aa vilaga. Embed aagura text-oda title-um section path-um mudhalla varum.

100-kelvi golden set-la, correct answers 71%-la irundhu 90%-ku ezhumbudhu. Citations ippo "Leave Policy 2026, Karnataka, section 3.2, page 4"-nu padikkum, HR staff seconds-la check pannalaam.

| 100 kelvigal-la alavu | Munnaadi | Aprom |
| --- | --- | --- |
| Correct answers | 71% | 90% |
| Thappaana state-a quote panna answers | 9 | 0 |
| Pona varusha policy-a quote panna answers | 7 | 1 |
| Citation format | File name mattum | Document, state, section, page |

**Filter mudivu eppadi work aagudhu.** Bengaluru-la irukkura oru employee "October-la ethanai holidays?"-nu kettaa, assistant avanga sign-on profile-la irundhu `state = KA`-va apply pannum. "Pune office-la October holidays"-nu kettaa, oru sinna model vera state-a kandupidichu, assistant filter panra munnaadi "Maharashtra holiday list-a solreengala?"-nu kekkum. Kekkuradhu oru tap selavu; amaidhiyaana thappaana filter oru thappaana answer-a tharum.

## Podhuvaa panra thappugal

- **File name mattum.** Filter panna, sariyaa cite panna, versions-a kaiyaala mudiyaadhu.
- **Free-text metadata values.** "HR", "Human Resources", "hr dept" filters-a udaikkum. Fixed lists use pannunga.
- **Effective dates illaama.** Pazhaya versions thirumba thirumba jeikkum.
- **Aggressive-aana inferred filters.** Thappaa infer aana filter sariyaana answer-a maraichidum; user context-a virumbunga, theriyalana kelunga.
- **Alakkaama metadata-va generate panradhu.** Ingestion-la kaasu selavu; adhu help pannudhu-nu nirupinga.
- **Free-text metadata values.** Fixed lists use panni validate pannunga.
- **Fallback illaama inferred filters-a apply panradhu.** Results kaaliyaa irundhaa, avai illaama thirumba try pannunga.

## Demo-la irundhu production-ku

- Ingestion-la **ovvoru chunk-oda metadata-vayum validate pannunga**, ovvoru run-kum quarantine counts-a report pannunga.
- **Transactions-la supersede pannunga**, superseded documents-a default-aa filter pannunga.
- Infer panna filters kooda, ovvoru search-layum **apply aana filters-a log pannunga**.
- Content owners-oda **vocabularies-a (states, document types, departments) review pannunga**.
- Ovvoru metadata feature-oda **value-va golden set-la alandhu paarunga**.
