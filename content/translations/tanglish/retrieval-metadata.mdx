## Idhu enna

**Metadata**-na oru chunk-oda text illaama, andha chunk pathina thagaval. RAG-la adhu anju velaigal seiyudhu:

- **Filters**: oru search-a state, document type, language allathu date vechu surukkudhu.
- **Citations**: oru answer sariyaa enga irundhu vandhuchu-nnu solludhu (document, section, page, link).
- **Freshness**: pona varushathoda version illaama, in force-aa irukkura version-la irundhu answer pannudhu.
- **Permissions**: oru chunk-a yaar paakkalaam-nu mudivu pannudhu.
- **Better matching**: document title allathu section path maadhiri, chunk text-la illaadha context-a serkkudhu.

```flow
Chunk text | "This limit is 45 days." Hard to find on its own -> Stored with metadata | doc: Leave Policy 2026, section: Earned leave > Carry forward, page 4, state KA, access: all-employees
Stored with metadata -> Embedded text | "Leave Policy 2026 > Earned leave > Carry forward: This limit is 45 days."
Stored with metadata -> Query filter | user's groups, user's state, in force today
Stored with metadata -> Citation | Leave Policy 2026, Karnataka, section 3.2, page 4
```

Prachanai ennanna, metadata sathamillaama fail aagum. Oru thappaana date allathu thappaa spell panna oru state, kelvi kekkura nerathula endha error-aiyum kaattaadhu; sariyaana chunk thirumba varavae varaadhu, model thappaana chunk-la irundhu confident-aa answer sollum.

Indha lesson, anju states-ku serve panra oru Bengaluru IT company-oda HR assistant-a follow pannudhu. Exercise idhae ideas-a government orders-ku kondu pogudhu, anga versions-um amendments-um innum kashtam.

## Idhu eppadi work aagudhu

### Ingestion-laye collect pannunga

Ovvoru chunk-kkum kurainjadhu idhaiyellaam store pannunga:

| Field | Example | Edhukku use aagudhu |
| --- | --- | --- |
| `doc_id`, `title`, `url` | `HR-LP-2026`, Leave Policy 2026 | Citations, links |
| `doc_group` | `LP` (ellaa versions-um translations-um) | Versions-aiyum language copies-aiyum link panna |
| `section_id`, `section_path`, `page` | 3.2; Earned leave, Carry forward; page 4 | Precise citations, amendments, contextual text |
| `doc_type` | `policy` | Filters |
| `state` | `KA` | User-oda profile-la irundhu filters |
| `issued_on` | 2025-12-10 | "The 2019 order" maadhiri kelvigal |
| `effective_from`, `effective_to` | 2026-01-01, kaali | Freshness, history kelvigal |
| `superseded_by` | kaali | Answers-la "replaced by" notes |
| `language` | `en` | Filters, endha copy-a kaattanum-nu therndhedukka |
| `access_groups` | `all-employees` | Permissions |

Ippave collect pannunga; appuram serkkanum-naa ovvoru file-aiyum thirumba parse pannanum.

**PDFs-la irundhu idhai edukkiradhu.** Sila fields source system-la irundhu varum (link, owner, access groups). Mathadhai document-laye padikkanum: headers-la irukkura order numbers, issue dates, section numbers. Clean-aana digital PDFs-ku rules ("No."-kkum dates-kkum regular expressions) work aagum; scanned files-ku OCR-um oru model-um venum, rendume thappu pannum. Extract panna fields-a nambradhukku munnaadi, sumaar 50 documents irukkura oru sample-a kaiyaala check panni, ovvoru field-kkum errors-a ennunga. Dates-a kavanamaa paarunga: "03/12/2019" India-la 3 December, aanaa US defaults irukkura oru parser-ku adhu 12 March, adhanaala format-a velippadaiyaa sollunga.

### Contextual text

"This limit is 45 days"-nu solra oru chunk-a retrieve panradhu kashtam, yenna adhu *endha* limit-nu adhula edhuvume illai. Neenga embed panra text-ku munnaala title-aiyum section path-aiyum serunga: "Leave Policy 2026 > Earned leave > Carry forward: This limit is 45 days". Idhukku selavae illai.

Innum strong-aana version: ovvoru chunk-um adhoda document-la enga varudhu-nnu onnu rendu vaakkiyangalla ezhudha oru model-kitta kelunga. Anthropic indha "contextual retrieval"-a adhoda sondha datasets-la test panni, adhu top-20 retrieval failure rate-a 35% kuraichadhaavum, keyword (BM25) search-layum apply pannumbodhu 49%, reranking-um serthaa 67% kuraichadhaavum report pannuchu. Ovvoru chunk-kkum oru model call selavaagum, adhanaala unga sondha golden set-la measure pannunga.

### Generated metadata

Oru model oru chinna summary, keywords, allathu oru chunk badhil solra questions-aiyum ezhudhalaam. Users documents-la irundhu romba vithiyaasamaa kekkumbodhu generated questions udhavum ("can I carry over my leave?" vs "Carry forward of earned leave").

Ovvoru generated question-aiyum **parent chunk-oda id kooda, adhukku-nnu oru thani vector-aa** store pannunga. Oru question vector match aanaa, parent chunk-a return pannunga, question text-a orubodhum illai, yenna model unmaiyaana document-la irundhu thaan answer pannanum. Rendu gotchas: generated questions chunk solradhai vida adhigamaa promise pannalaam, adhanaala oru sample-a spot-check pannunga; adhoda avai pazhasaayidum, adhanaala chunk text-oda oru hash-a store panni, adhu maarumbodhu thirumba generate pannunga.

### Fixed vocabularies, code-la validate pannadhu

Filters exact values-a compare pannum. Oru filter-ku "HR", "Human Resources", "hr dept" moonum moonu vera vera departments. Departments, document types, states, languages-ku fixed lists use pannunga, ovvoru chunk-aiyum index aagradhukku munnaadi check pannunga:

```python
from datetime import date
from typing import Literal
from pydantic import BaseModel, field_validator, model_validator

State = Literal["KA", "TN", "MH", "TS", "GJ", "ALL"]   # the client's five states, plus ALL
DocType = Literal["policy", "circular", "faq", "contract"]

class ChunkMeta(BaseModel):
    doc_id: str
    doc_group: str               # same for every version and translation
    title: str
    section_id: str              # stable id such as "3.2"
    section_path: str
    page: int
    doc_type: DocType
    state: State
    language: Literal["en", "hi", "ta", "kn", "mr", "te", "gu"]
    issued_on: date
    effective_from: date
    effective_to: date | None = None
    superseded_by: str | None = None
    access_groups: list[str]

    @field_validator("access_groups")
    @classmethod
    def not_empty(cls, v):
        if not v:
            raise ValueError("every chunk needs at least one access group")
        return v

    @model_validator(mode="after")
    def dates_in_order(self):
        if self.effective_to and self.effective_to < self.effective_from:
            raise ValueError("effective_to is before effective_from")
        return self
```

Ovvoru chunk-aiyum `ChunkMeta.model_validate` vazhiyaa anuppunga, pass aanadhai index pannunga, fail aanadhai error kooda oru quarantine table-la ezhudhunga. Ovvoru run-layum quarantine counts-a report pannunga. "Karnatka"-nu tag panna oru document ippo sathamaa fail aagum; ovvoru Karnataka employee-oda search-la irundhum kaanaama pogaadhu. State list client-oda unmaiyaana list-oda sariyaa match aaganum; serkka marandha oru state-oda ellaa documents-um quarantine-ku poyidum.

### Freshness: orae oru "in force" rule

Oru simple "current" flag use pannaadheenga. Ellaa idathulayum orae date rule use pannunga: oru chunk **oru period-la in force**-na, `effective_from` andha period-oda mudivu naal annaikko adhukku munnaadiyo irukkanum, `effective_to` kaaliyaa irukkanum allathu period-oda thodakka naal annaikko adhukku appuramo irukkanum.

- **Default kelvigal** ("how many leave days can I carry forward?"): period innaikku, Asia/Kolkata time-la.
- **"What was the rule in 2024?"**: period 1 January-la irundhu 31 December 2024 varai. 2023-la irundhu 2025 varai in force-aa irundha oru policy thirumba varum, adhu 2024-ku munnaadiye aarambichu, ippo superseded aagiyirundhaalum kooda.
- **"What did the 2019 order say?"**: idhu 2019-la *issue* aana order pathi kekkudhu, adhanaala `issued_on`-oda year vechu filter pannunga, adhu innum in force-aa irukkaa illaiyaa-nnu paakkaadheenga.

Oru gotcha: December-la 1 January-kku-nnu announce panna oru policy innum in force illai. "Next year's policy" pathina oru kelvikku adutha varusham thaan period-aa irukkanum, illai-nnaa default rule adhai maraichudum.

Oru pudhu version muzhu document-aiyum replace pannumbodhu, pazhasai adhae transaction-la close pannunga, appo endha search-um rendaiyum paakkaadhu, rendume illaamalum irukkaadhu:

```sql
BEGIN;
UPDATE chunks SET superseded_by = 'HR-LP-2026', effective_to = '2025-12-31'
WHERE doc_id = 'HR-LP-2025';
INSERT INTO chunks (...) VALUES (...);   -- the new version's chunks
COMMIT;
```

Filtering-a date rule thaan seiyudhu. Answer "replaced by Leave Policy 2026"-nu solradhukkaaga thaan `superseded_by` vechirukkom.

### Partial amendments

Unmaiyaana documents perumbaalum oru nerathula oru pagudhiyaa thaan maarum. Oru government order "in paragraph 4 of order 112/2019, for 'Rs 300' substitute 'Rs 450'"-nu solli, matha ellaa paragraphs-aiyum in force-aave vidalaam. Muzhu document-kkaana oru "superseded" flag-aala idhai solla mudiyaadhu. Pazhaiya order-a superseded-nu mark pannaa adhoda matha paragraphs kaanaama poyidum; appadiye vittaa pazhaiya rate thaan jeyichukkittae irukkum.

Amendments-a section level-la model pannunga:

- Ovvoru chunk-layum oru stable `section_id` irukkanum (paragraph 4, clause 3.2).
- Oru amendments table `amending_doc`, `amended_doc`, `section_id`, adhu effect-ku varra date-a record pannum.
- Oru amendment effect-ku varumbodhu, amend aana section-oda `effective_to`-a mattum mudinga, mathadhai appadiye vidunga.
- Query time-la, oru base section retrieve aagumbodhu, adhukkaana ellaa amendments-aiyum date varisaiyila eduthu, rendaiyum model-ku kudunga.

Idhu mukkiyam, yenna endha chunk-um thaniyaa work aagaadhu. Amendment "substitute 'Rs 450'"-nu sollum, edhukku badhilaa-nnu sollaadhu; base paragraph pazhasaayiduchu. Answer rendaiyum cite pannanum: "order 112/2019, paragraph 4, as amended by order 37/2022". Department consolidated versions publish pannaa, adhaiyum index pannunga, aanaa citations-kkaaga chain-a vechukkonga.

Amendment links-um extract panra metadata thaan. "in partial modification of" allathu "in supersession of" maadhiri phrases, adhai thodarndhu oru order number vandhaa, adhu nalla starting rules; aanaa extract panra endha field maadhiriyum oru sample-la check pannunga.

### Translations

Oru Hindi order-um adhoda English copy-yum rendu documents illai, rendu languages-la irukkura orae document. Rendukkum orae `doc_group`, `section_id` kudunga. Results-la oru document group, section-ku oru chunk mattum vechukkonga, user-oda language-la irukkura copy-a kaattunga. Illai-nnaa top five results-la rendu idam, adhae paragraph rendu thadavai vandhu veenaagum. Rendum verupadumbodhu endha copy authoritative-nu department-kitta kelunga, adhai record panni, adhaiye cite pannunga.

### Permissions, sync-la vechukkiradhu

Chunks mela user ids illaama **group ids** store pannunga (`finance`, `all-employees`), filter-a search-ku ullaye apply pannunga, appo anumadhi illaadha chunk model-a orubodhum reach pannaadhu. Rendu syncs-ku thanithani schedules venum:

- **Document permissions** source system-la maarum (oru file-a thirumba share panraanga). Adhai adikkadi re-sync pannunga, oru metadata update-aa; text-a re-embed panna vendaam.
- **User groups** aalunga teams maarumbodhu maarum. User-oda groups-a query time-la identity system-la irundhu padinga, allathu naatkal illaama nimishangalukku mattum cache pannunga. Cache panna oru group list-aala thaan, Finance-a vittu pona oruthar innum Finance circulars-a paathukkittu irukkaaru.

### Kelviyila irundhu filters

Sila filters user-oda profile-la irundhu varum (avanga state, avanga groups). Mathadhai oru small model kelviyila irundhu infer pannum. Thappaa infer panna filter sariyaana answer-a maraichudum, adhanaala avatrai kavanamaa apply pannunga:

```python
STATE_NAMES = {"KA": "Karnataka", "TN": "Tamil Nadu", "MH": "Maharashtra",
               "TS": "Telangana", "GJ": "Gujarat"}

class Filters(BaseModel):            # structured output from a small model
    state: Literal["KA", "TN", "MH", "TS", "GJ"] | None = None  # a real state, never ALL
    state_named: bool = False         # true only if the question names the state itself
    in_force_year: int | None = None  # "what was the rule in 2024?"
    issued_year: int | None = None    # "the 2019 order on transfers"
    doc_type: DocType | None = None

def in_force(start: date, end: date) -> dict:
    """In force at any time from start to end."""
    return {"effective_from": {"$lte": end},
            "$or": [{"effective_to": None}, {"effective_to": {"$gte": start}}]}

def build_filters(f: Filters, user, today: date):
    if f.state and f.state != user.state and not f.state_named:
        return None, f"Do you mean the {STATE_NAMES[f.state]} documents?"
    where = {"access_groups": {"$in": user.groups},           # never dropped
             "state": {"$in": [f.state or user.state, "ALL"]}}
    if f.in_force_year:
        y = f.in_force_year
        where |= in_force(date(y, 1, 1), date(y, 12, 31))
    elif f.issued_year:
        y = f.issued_year
        where["issued_on"] = {"$gte": date(y, 1, 1), "$lte": date(y, 12, 31)}
    else:
        where |= in_force(today, today)                       # default
    if f.doc_type:
        where["doc_type"] = f.doc_type
    return where, None
```

Filter syntax generic thaan; adhai unga vector store-oda syntax-ku maathikkonga. `today`-a server-oda UTC date illaama, Asia/Kolkata-la irukkura date-aa pass pannunga. Oru filtered search edhuvume return pannalai-nnaa, access filter, user-oda state mattum vechu oru thadavai retry pannunga, adhu cite panradhoda dates-a kaattunga, empty search-a log pannunga. Oru retry-la access filter-a orubodhum drop pannaadheenga.

### Filters-um search speed-um

Filters approximate vector indexes kooda interact pannum. Udhaaranamaa pgvector-la, default-aa filter index scan-ku *appuram* thaan apply aagum. Adhoda documentation 10% rows-a match panra oru filter-a example-aa kudukkudhu: oru HNSW index-um default `hnsw.ef_search` 40-um irundhaa, average-aa sumaar 4 rows thaan minjum, adhanaala neenga kettadhai vida kuraivaana results thaan kidaikkum. Version 0.8.0-la irundhu iterative index scans-a on pannalaam (`SET hnsw.iterative_scan = relaxed_order`); adhu podhumaana rows pass aagura varai allathu oru scan limit (`hnsw.max_scan_tuples`) varra varai index-oda innum adhigamaana pagudhiya scan pannum. Konjame distinct values irukkura oru field-ku, ovvoru value-kkum oru partial index-a pgvector suggest pannudhu. Matha stores vera maadhiri irukkum, adhanaala ungakitta irukkuradhulaye adhiga selective-aana filter-a (oru chinna state, oru aridhaana document type) test panni, adhu innum muzhu top-k-a return pannudhaa-nnu check pannunga.

### Payoff-a check pannunga

Ovvoru addition-kkum (contextual text, generated questions, inferred filters), adhu irundhum illaamalum unga golden set-la recall at 5-a measure pannunga, udhavuradhai mattum vechukkonga. History kelvigalaiyum vera state kelvigalaiyum serunga, yenna anga thaan filters thappaa pogum.

## Oru worked example

Bengaluru IT company-oda HR assistant Karnataka, Tamil Nadu, Maharashtra, Telangana, Gujarat-la irukkura employees-ku serve pannudhu. Leave, holiday rules state-ku state maarum, policies ovvoru varushamum revise aagum.

**Munnaadi:** chunks-la file name mattum thaan irundhuchu. Assistant Karnataka, Maharashtra holiday lists-a kalandhuchu, sila neram pona varusha policy-a quote pannuchu. Mudhal fix oru `current = true` filter-a serthuchu, appuram "what was the carry-forward limit in 2024?" edhaiyume return pannalai.

**Re-ingestion-ku appuram:** ovvoru chunk-layum mela irukkura table-la ulla fields irukku. State-um groups-um employee-oda sign-on profile-la irundhu varudhu. Date rule default-aa innaikku; oru varushathai per solli kettaa andha varushathukku maarum. Embed panra text title, section path-la irundhu aarambikkudhu. Keezha irukkura numbers edhirpaarkkakkoodiya maadhiriyaana maatrathukku oru illustration thaan, measure panna result illai:

| 100 golden questions-la, ippadi-nnu vechukkonga | Munnaadi | Appuram |
| --- | --- | --- |
| Sariyaana answers | 71 | 90 |
| Thappaana state-a quote panna answers | 9 | 0 |
| Pona varusha policy-a quote panna answers | 7 | 1 |
| Matha thappaana answers | 13 | 9 |
| Citation format | File name mattum | Document, state, section, page |

Ippo citations "Leave Policy 2026, Karnataka, section 3.2, page 4"-nu varudhu, HR staff avatrai sila nodigalla check pannalaam.

**Filter mudivugal eppadi work aagudhu.** Bengaluru-la irukkura Priya "how many holidays in October?"-nu kekkuraanga. Assistant avanga profile-la irundhu `state = KA`-aiyum, innaikku in force-aiyum apply pannudhu. Appuram avanga "holidays in Pune office in October"-nu kekkuraanga. Small model Pune-a Maharashtra-vukku map pannudhu, aanaa avanga state-a per sollalai, adhanaala `build_filters` oru kelviya return pannudhu: "Do you mean the Maharashtra documents?" Kekkuradhukku oru tap thaan selavu; sathamillaadha oru thappaana filter-ku oru thappaana answer thaan vilai. Avanga "Maharashtra holidays"-nu type panniyirundhaa, filter neradiyaa apply aagiyirukkum.

Avanga "what was the carry-forward limit in 2024?"-nu kekkumbodhu, model `in_force_year = 2024`-a return pannudhu. January 2026-la irundhu superseded aana 2023-la irundhu 2025 varaiyaana policy, date rule-oda match aagi, "replaced by Leave Policy 2026"-ngra note kooda thirumba varudhu.

## Podhuvaa panra thappugal

- **File name mattum.** Filter panna mudiyaadhu, sariyaa cite panna mudiyaadhu, versions-a handle panna mudiyaadhu.
- **Free-text metadata values.** "HR", "Human Resources", "hr dept" filters-a udaikkum. Fixed lists use panni avatrai validate pannunga.
- **Oru unmaiyaana value-a vittuppona vocabulary.** Marandhupona oru state adhoda ellaa documents-aiyum quarantine pannum, illai-nnaa adhai vida mosamaa, state illaamale index pannum.
- **Ovvoru search-layum oru "current only" filter.** Appo history kelvigal edhaiyume return pannaadhu. Kelvi kekkura period kooda in-force rule-a use pannunga.
- **Partial amendments-ku muzhu document supersession.** Adhu innum in force-aa irukkura paragraphs-a maraikkum, illai-nnaa pazhaiya values-a vechukkum. Amendments-a section vaariyaa track pannunga.
- **Translations-a thani documents-aa vekkiradhu.** Duplicate paragraphs matha results-a veliye thallum.
- **Aggressive-aana inferred filters.** User-oda profile-kku munnurimai kudunga, inferred filter adhai maathinaa kelunga.
- **Access filter-a drop panra oru fallback.** Oru empty result, oru user paakkakkoodiyadhai orubodhum virivaakka koodaadhu.
- **Pazhaiya group lists.** Query time-la irukkura user-oda groups thaan access-a mudivu pannum, adhanaala avatrai fresh-aa padinga.
- **Measure pannaama metadata generate panradhu.** Ovvoru chunk-kkum oru model call selavaagum; adhu udhavudhu-nnu prove pannunga.

## Konjam metadata podhum-nu irukkura idangal

- Ovvoru document-kkum orae version irukkura **oru chinna, orae topic collection**.
- **Ellaarum ellaathaiyum paakkalaam**, edhuvum pazhasaagaadhu.
- Retrieval udhavudhaa-nnae test panra **oru prototype**.

Appo kooda document id, section, page-a store pannunga: citations-ku avai thevai, adhukku selavae illai. Niraiya document types, versions, regions allathu permission groups vandha udane rich metadata-ku palan kidaikkum.

## Demo-la irundhu production-ku

- Parser allathu document format maarumbodhellaam **extract panna fields-a oru sample-la kaiyaala check pannunga**.
- Ovvoru search-kkum **apply aana filters-a log pannunga**, inferred filters, fallbacks udpada.
- Re-embedding-la irundhu thaniyaa, adhoda sondha schedule-la **permissions-a re-sync pannunga**.
- Content owners kooda serndhu **vocabularies-a review pannunga** (states, document types, departments).

## Practice pannunga

Metadata extraction pathina LlamaIndex-oda page-aiyum Microsoft-oda security filter pattern-aiyum padinga.

1. Unga RAG documents-a, ovvoru chunk-layum title, section id, path, type, dates, language, access groups kooda re-ingest pannunga.
2. Embed panra text-ku munnaala title, section path-a serthu, munnaadiyum appuramum recall at 5-a compare pannunga.
3. Oru document-ku pona varusham mudinja oru pazhaiya version kudunga. Default kelvikku pudhu version-um, pona varushathai per solli kekkura kelvikku pazhaiya version-um kidaikkudhu-nnu kaattunga.
4. Oru document-oda oru section-a innoru document amend panra maadhiri vechukkonga. Answer rendaiyum cite pannudhu-nnu kaattunga.
5. Venumnae thappaana metadata irukkura anju chunks-a `ChunkMeta` vazhiyaa anuppi, ovvonnum thelivaana error kooda quarantine-la poi serudhu-nnu confirm pannunga.
