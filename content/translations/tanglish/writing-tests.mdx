## Idhu enna

**Test**-na neenga therndhedukkura oru input-oda unga code-a run panni, result neenga edhirpaakkura maadhiri irukkaa-nu check panra oru chinna code thundu. **Unit test** oru chinna pagudhiya, perumbaalum oru function-a, thaniyaa check pannum. Result thappaa irundhaa test fail aagi enga-nu sollum.

Innaikku neenga ezhudhura code-kku vida, adhukku appuram varra ovvoru change-kkum dhaan tests adhigam mukkiyam. Aaru maasam kazhichu neengalo unga teammate-o oru function-a maathuveenga. Tests illanna, edhuvum udaiyala-nu therinjukka ore vazhi app-la click panni paathuttu nallaa irukkum-nu namburadhu dhaan. Tests irundhaa, oru command run panna sila vinaadigallaye therinjudum.

**pytest** dhaan Python-kkaana standard testing tool. `test_`-la aarambikkura per ulla saadhaarana functions ezhudhi, saadhaarana `assert` statements use pannuveenga. pytest avattha kandupidichu run pannum; onnu fail aana endha values vidhyaasappattuchu-nu sariyaa kaattum.

Aarambathula irundhe oru limit-a manasula vechukkonga: neenga check pannanum-nu nenachadha mattum dhaan oru test pidikkum. Endha cases-nu therndhedukkuradhu dhaan unmaiyaana skill; indha lesson-la perumbaalaanadhu andha thervai pathi dhaan.

## Idhu eppadi work aagudhu

### Unga mudhal tests

Oru test-la moonu steps irukkum, idha perumbaalum **arrange, act, assert**-nu solvaanga: inputs-a thayaar pannunga, code-a oru thadavai call pannunga, result-a check pannunga.

Idho oru GST helper. Idhu Python-oda exact decimal type-aana `Decimal`-a use pannudhu, yenna money drift aagak koodaadhu (yen-nu adutha pagudhi kaattum). Indha example-kku, finance team-oda rule idhu-nu vechukkonga: paisa-kku round pannanum, arai paisa mela pogum. Andha rule oru business mudivu, adhanaala unga sondha finance team kitta confirm pannikkonga.

```python
# gst.py
from decimal import Decimal, ROUND_HALF_UP

PAISA = Decimal("0.01")

def gst(amount: Decimal, rate: Decimal = Decimal("0.18")) -> Decimal:
    """GST on an amount, rounded to the paisa, half a paisa rounded up."""
    if amount < 0:
        raise ValueError("amount must not be negative")
    return (amount * rate).quantize(PAISA, rounding=ROUND_HALF_UP)
```

```python
# test_gst.py
from decimal import Decimal as D
import pytest
from gst import gst

def test_default_rate_is_18_percent():
    assert gst(D("100")) == D("18.00")

def test_half_paisa_rounds_up():
    # 100.25 x 0.18 = 18.045 exactly, so it must round up to 18.05
    assert gst(D("100.25")) == D("18.05")

def test_negative_amount_is_refused():
    with pytest.raises(ValueError, match="negative"):
        gst(D("-1"))
```

Folder-la `pytest` run panna adhu `3 passed`-nu print pannum. Ovvoru per-um adhu edhirpaakkura behaviour-a solludhu, adhanaala failure report oru vaakkiyam maadhiri padikkum. `match=` error message-aiyum check pannum, adhanaala vera edho oru `ValueError`-naala test tharchayalaa pass aagaadhu.

Neenga work panra loop:

```flow
dir: LR
Code ezhudhu illa maathu -> pytest run pannu
pytest run pannu -[oru test fail aagudhu]-> Failure-a padi | endha values vidhyaasappattuchu
Failure-a padi -> Code ezhudhu illa maathu
pytest run pannu -[ellaam pass]-> Commit
```

### Money-yum floats-um

Yen saadhaarana floats vendaam? Adhe function-a `round(amount * rate, 2)`-oda ezhudhunga, rounding test fail aagum:

```
>       assert gst(100.25) == 18.05
E       assert 18.04 == 18.05
E        +  where 18.04 = gst(100.25)
```

Oru float numbers-a binary-la store pannum, perumbaalaana decimal fractions-kku exact binary vadivam kidaiyaadhu. `100.25 * 0.18` 18.044999999999998...-aa store aagudhu, nadupulliku konjam keezha, adhanaala adhu keezha round aagudhu. Indha error 15-vadhu digit-la olinjirukkala: customer oru paisa thappaa irukkura bill-a paappaanga. Idhula irundhu moonu rules varudhu:

- **Money:** strings-la irundhu build panna `Decimal` use pannunga (`Decimal("100.25")`), illa muzhu paise-a integers-aa store pannunga. `Decimal(0.1)`-nu eppavum ezhudhaadheenga: adhu float-oda error-a copy panni 0.1000000000000000055511151231257827.... tharum.
- **Money illaadha floats** (oru model-oda confidence score, oru average, oru similarity): `pytest.approx`-oda compare pannunga; default-aa adhu pathu latchathula onnu alavukku relative difference-a anumadhikkum.
- **Compute panna floats mela `==` eppavum vendaam.** Inputs maarura varaikkum dhaan adhu unga laptop-la velai seyyum.

```python
def test_mean_score_needs_approx():
    # (0.1 + 0.2) / 2 is 0.15000000000000002, so == 0.15 alone fails
    assert (0.1 + 0.2) / 2 == pytest.approx(0.15)
```

### Copy panradhukku badhilaa parametrise pannunga

22 September 2025-la irundhu, GST-kku rendu main slabs irukku, 5%, 18%; adhoda sugary fizzy drinks, periya cars maadhiri oru chinna set of goods-kku oru special 40% rate. (Pazhaya 12%, 28% slabs edukkappattuchu, aanaa sila special rates innum irukku.) Ore parametrised test slabs-aiyum zero edges-aiyum cover pannum:

```python
@pytest.mark.parametrize("amount, rate, expected", [
    (D("1000"), D("0.05"), D("50.00")),
    (D("1000"), D("0.18"), D("180.00")),
    (D("1000"), D("0.40"), D("400.00")),
    (D("1000"), D("0"), D("0.00")),
    (D("0"), D("0.18"), D("0.00")),
], ids=["5-percent", "18-percent", "40-percent", "zero-rate", "zero-amount"])
def test_rates(amount, rate, expected):
    assert gst(amount, rate) == expected
```

Ovvoru row-um thani test-aa report aagum, udhaaranamaa `test_rates[40-percent]`, adhanaala failure case-oda per-a sollum. `ids` illanna pytest indha rows-kku `amount0-rate0-expected0` maadhiri per vaikkum, adhu padikka kashtam.

### Fixtures-um conftest.py-um

**Fixture**-na oru test adhoda per-a parameter-aa kuduthu kekkura shared setup. Pala test files use panra fixtures-a `conftest.py`-la vainga; pytest andha file-a thaanaave load pannum, import thevaiyilla.

```python
# invoice.py
from decimal import Decimal
from gst import gst

def invoice_total(invoice: dict) -> Decimal:
    subtotal = sum((price for _, price in invoice["items"]), Decimal("0"))
    return subtotal + gst(subtotal, invoice["rate"])
```

```python
# conftest.py
from decimal import Decimal as D
import pytest

@pytest.fixture
def invoice():
    return {"items": [("Charger", D("999.00")), ("Cable", D("299.00"))],
            "rate": D("0.18")}
```

```python
# test_invoice.py
from decimal import Decimal as D
from invoice import invoice_total

def test_total_adds_gst_to_subtotal(invoice):
    assert invoice_total(invoice) == D("1531.64")   # 1298.00 + 233.64

def test_empty_invoice_totals_zero(invoice):
    invoice["items"] = []          # changes only this test's copy
    assert invoice_total(invoice) == D("0")
```

Default-aa oru fixture ovvoru test-kkum marubadiyum run aagum, adhanaala oru test adha maathinaa innoru test udaiyaadhu. Mellaa irukkura, eppavum maaraadha setup-kku mattum (oru periya sample file-a load panradhu maadhiri) wider scope (`scope="session"`) use pannunga. Oru fixture adhoda value-a `yield` panni, `yield`-kku appuram clean up pannalaam. Built-in `tmp_path` fixture, files ezhudhura code-kkaaga, ovvoru test-kkum oru pudhu temporary folder tharum.

### Model, API calls-kku fakes

Unmaiyaana model calls mellaa irukkum, kaasu selavaagum, ovvoru thadavaiyum vera reply tharalaam. Unit tests-la, avattha oru fixed reply return panra **fake**-aala maathunga. Ippadi oru pagudhiya maathuradhukku **mocking**-nu per.

Code-a neengale ezhudhureenga-naa, client-a oru parameter-aa pass panradhu dhaan cleanest design. Idhukku **dependency injection**-nu per:

```python
# triage.py
import json

def classify(ticket: str, client) -> str:
    reply = client.complete(f"Classify this support ticket as JSON: {ticket}")
    return json.loads(reply)["category"]
```

```python
# test_triage.py
from triage import classify

class FakeClient:
    def complete(self, prompt: str) -> str:
        return '{"category": "refund"}'

def test_classify_reads_category():
    assert classify("Money not returned", client=FakeClient()) == "refund"
```

Neenga inherit panra perumbaalaana code, adhukku badhilaa, client-a module level-la oru thadavai create pannum. Appo pytest-oda `monkeypatch`-oda adha swap pannunga; test mudinjadhum adhu original-a thirumba vechidum. `unittest.mock.Mock` fake-a build panni, adhu eppadi call aachu-nu record pannum. Indha version bad replies-aiyum handle pannudhu; AI projects-la ellaathaiyum vida test panna thagudhiyaana code idhu dhaan:

```python
# llm.py
class ModelClient:
    """Stands in for a real model SDK client."""
    def complete(self, prompt: str) -> str:
        raise RuntimeError("this would make a real, paid network call")
```

```python
# tickets.py
import json
from llm import ModelClient

client = ModelClient()          # created once, when the module is imported
CATEGORIES = {"refund", "delivery", "other"}

def classify(ticket: str) -> str:
    reply = client.complete(f"Classify this support ticket as JSON: {ticket}")
    try:
        category = json.loads(reply)["category"]
    except (json.JSONDecodeError, KeyError, TypeError):
        return "needs_review"
    return category if category in CATEGORIES else "needs_review"
```

```python
# test_tickets.py
from unittest.mock import Mock
import pytest
import tickets
from llm import ModelClient

def fake_client(reply: str) -> Mock:
    fake = Mock(spec=ModelClient)    # only methods the real client has
    fake.complete.return_value = reply
    return fake

def test_reads_category_and_sends_ticket(monkeypatch):
    fake = fake_client('{"category": "refund"}')
    monkeypatch.setattr(tickets, "client", fake)
    assert tickets.classify("Money not returned") == "refund"
    fake.complete.assert_called_once()
    assert "Money not returned" in fake.complete.call_args.args[0]

@pytest.mark.parametrize("reply", [
    "Sure! This looks like a refund.",   # prose, not JSON
    '{"label": "refund"}',               # wrong key
    '{"category": "lottery"}',           # unknown category
    "null",                              # valid JSON, wrong shape
    "",                                  # empty reply
])
def test_bad_reply_goes_to_review(monkeypatch, reply):
    monkeypatch.setattr(tickets, "client", fake_client(reply))
    assert tickets.classify("Where is my parcel?") == "needs_review"
```

Anubavamulla engineers-aiyum maattividura rendu gotchas:

- **Per enga use aagudho anga patch pannunga, enga define aagudho anga illa.** `tickets.py` `from llm import client`-nu ezhudhiyirundhaa, adhukku andha per-oda sondha copy irukkum; adhanaala `llm.client`-a patch panna edhuvum maaraadhu, unmaiyaana call innum run aagum. `tickets.client`-a patch pannunga.
- **Saadhaarana `Mock()` endha attribute-aiyum ethukkum.** Oru typo, illa unmaiyaana client-la rename aana oru method, test-la innum "velai seyyum", bug production-kku poyidum. `Mock(spec=ModelClient)` unmaiyaana class-la illaadha edhukkum `AttributeError` raise pannum.

Edha use panradhu:

| Nilaimai | Use pannunga | Yen |
| --- | --- | --- |
| Neenga ezhudhura pudhu code | Client-a pass pannunga (dependency injection) | Patching illa; code-kku enna thevai-nu test sariyaa kaattum |
| Module-level client ulla inherited code | Adha use panra module mela `monkeypatch.setattr` | Oru test-kku oru per-a swap panni, appuram restore pannum |
| Enna anuppuchu-nu (prompt maadhiri) check panniye aaganum | `Mock(spec=...)`, `call_args` | Ovvoru call-aiyum record pannum; spec typos-a pidikkum |
| Files ezhudhura code | Built-in `tmp_path` fixture | Ovvoru test-kkum oru pudhu folder, edhuvum micham irukkaadhu |
| Unmaiyaana model-oda behaviour | Golden set mela oru evaluation run, unit test illa | Unit tests badhiloda quality-a judge panna mudiyaadhu |

### Unit tests vs evaluations

AI projects-la rendu vagai test-a thanithaniyaa vainga. Vegamaana unit tests unga sondha logic-a check pannum: prompts build panradhu, replies-a parse panradhu, validation, scoring. Avai ovvoru commit-laiyum run aagum. Mellaana **evaluations** oru fixed golden set of inputs-a unmaiyaana model-kku anuppi badhilgala score pannum; oru prompt change illa model update results-a mosamaakkiduchaa-nu pidikka. Avattha eppadi build panradhu-nu "Test sets and evals" lesson (P1) sollum. Rendaiyum kalandhaa dhinasari tests mellaa, selavaa, flaky-aa aayidum.

Oru **marker** avattha thaniyaa vaikkum. Adha `pyproject.toml`-la register pannunga; `--strict-markers` thappaa type panna marker-a warning-aa illaama error-aa maathum:

```toml
[tool.pytest.ini_options]
addopts = "--strict-markers"
markers = ["eval: calls the real model on the golden set; run on a schedule"]
```

Ovvoru evaluation test-kkum `@pytest.mark.eval` tag podunga, ovvoru commit-laiyum `pytest -m "not eval"` run pannunga.

### Dhinamum tests run panradhu

| Command | Enna pannum |
| --- | --- |
| `pytest -x` | Mudhal failure-laye niruthum |
| `pytest -k rounding` | Per-la "rounding" irukkura tests-a mattum run pannum |
| `pytest test_gst.py::test_half_paisa_rounds_up` | Oru test-a run pannum |
| `pytest --lf` | Pona thadavai fail aana tests-a mattum marubadi run pannum |
| `pytest -m "not eval"` | `eval`-nu mark panna tests-a skip pannum |
| `pytest --cov=. --cov-report=term-missing` | Coverage-a kaattum, endha test-um run pannaadha line numbers-oda (`pytest-cov` package thevai) |

**Coverage**-na tests nadakkumbodhu unga code-la evvalavu pangu run aachu-ngiradhu. "Missing" column-a padinga: endha test-um run pannaadha lines-a adhu list pannum, avai dhaan unga blind spots. Oru `if`-oda true illa false side eppavume run aagalai-naa adhaiyum paakka `--cov-branch` serunga. Aanaa coverage, code run aachu-nu mattum dhaan nirubikkum, edhaavadhu result-a check pannuchu-nu illa: `assert` illaama `gst(D("100"))`-a call panra oru test-um kanakkula varum. Gaps-a kandupidikka adha use pannunga, 100% adaiya vendiya score-aa illa.

**Continuous integration (CI)** ovvoru push illa pull request-kkum adhe command-a oru clean machine-la run pannum; adhu fail aana team merging-a block pannum. Unga laptop-la pass aagura rendu vishayangal anga udaiyum. Mudhalla, CI machine-la unga project list panra packages mattum dhaan irukkum, adhanaala oru missing dependency veliya therinjudum. Rendaavadhu, CI machines perumbaalum UTC use pannum, idhu India-va vida ainthara mani neram pinnaadi. Appo "innaikku" pathina oru test, IST nalliravu 12-la irundhu kaalai 5:30 varaikkum run aana fail aagalaam. Date illa clock-a unga code-kkulla pass pannunga, machine-oda setting-a nambaama time zone-a per solli kudunga (`ZoneInfo("Asia/Kolkata")`).

### Edha mudhalla test panradhu

Tests illaadha oru project-la, bug vandhaa enga ellaathaiyum vida adhiga nashtam aagumo anga aarambinga:

1. **Money-yum legal sambandhappatta edhuvum:** totals, tax, refunds, limits.
2. **Matha systems padikkura data:** unga API return panra JSON, neenga export panra CSV.
3. **Neenga maathappora code:** mudhalla adhoda ippodhaiya behaviour-a pin panra tests ezhudhunga, appuram maathunga.
4. **Neenga fix panra ovvoru bug-um:** mudhalla adha reproduce panra oru test, appuram fix. Idhu oru **regression test**; adhe bug thirumba varradha idhu thadukkum.

Project-la tests enga irukkum-nu (oru `tests/` folder, oru `src` layout, README commands) "Project tooling: environments, tests and logs" lesson-la paarunga.

## Oru worked example

Sneha, Chennai-la oru logistics company-la oru invoice-extraction service-a maintain panraanga. Indha service oru scan panna invoice-a padichu, line amounts-aiyum print aana total-aiyum eduthu, rendum othupogalanna invoice-a reject pannum. Oru unmaiyaana invoice reject aachu-nu oru customer report panraanga. Adhoda lines: freight ₹1,040.37, loading ₹128.98, toll ₹10.65; ivattha koottinaa ₹1,180.00, aanaa print aana total ₹1,180.50. Business ₹1 varaikkum rounding difference-a anumadhikkudhu (indha example-kkaaga vecha oru illustrative rule).

**Mudhalla, fail aagura oru test.** Code-a thoduradhukku munnaadi, bug-a reproduce panni, invoice accept aaganum-nu edhirpaakkura oru test-a ezhudhuraanga. pytest run panraanga, pudhu test fail aagudhu. Test unmaiyileye bug-a pidikkudhu-nu adhu nirubikkudhu; fix-kku munnaadiye pass aagura test edhaiyum nirubikkaadhu.

**Appuram edges.** Oru limit-kku rendu edges irukku, adhanaala parametrise panraanga: sariyaa ₹1 melayum sariyaa ₹1 keezhayum accept aaganum, endha pakkamaa irundhaalum ₹1.01 reject aaganum. Python 3.12 illa adhukku appuram vandha versions-la, moonu lines-oda `sum()` 1180 illa, `1179.9999999999998` tharudhu (pazhaya versions-la, illa `+`-oda koottinaa, tharchayalaa 1180.0 varudhu); adhanaala 1181.00-la irundhu difference `1.0000000000002274`, limit-kku konjam mela. Extractor amounts-a text-aa kudukkavum, check `Decimal` use pannavum maathuraanga:

```python
# validate.py
from decimal import Decimal

TOLERANCE = Decimal("1.00")          # business rule: up to Rs 1 of rounding

def total_is_valid(line_amounts: list[str], printed_total: str) -> bool:
    lines_total = sum((Decimal(a) for a in line_amounts), Decimal("0"))
    return abs(lines_total - Decimal(printed_total)) <= TOLERANCE
```

```python
# test_validate.py
import pytest
from validate import total_is_valid

LINES = ["1040.37", "128.98", "10.65"]      # add up to exactly 1180.00

@pytest.mark.parametrize("printed, expected", [
    ("1180.50", True),    # the customer's bug: 50 paise of rounding
    ("1181.00", True),    # exactly Rs 1 over: allowed
    ("1179.00", True),    # exactly Rs 1 under: allowed
    ("1181.01", False),   # just over the limit
    ("1178.99", False),   # just under the limit
], ids=["50-paise", "plus-1", "minus-1", "plus-1.01", "minus-1.01"])
def test_rounding_tolerance(printed, expected):
    assert total_is_valid(LINES, printed) is expected
```

## Podhuvaa panra thappugal

- **Happy path-a mattum test panradhu.** Bugs edges-la dhaan irukkum: zero, empty lists, negatives, sariyaana limit, romba periya values, missing fields.
- **Pathu vishayangala check panra ore test.** Adhu fail aana edhu-nu solla mudiyaadhu. Oru test-kku oru behaviour, ennannu solra per-oda.
- **Onnukkonnu illa order-a saarndhirukkura tests.** Ovvoru test-um thanakku thevaiyaanadha set up panni, thaniyaa run pannaalum pass aaganum. Module level-la irukkura shared lists illa dictionaries dhaan vazhakkamaana kaaranam.
- **Unit tests-la unmaiyaana network illa model calls.** Avai mellaa irukkum, kaasu selavaagum, tests-a flaky aakkum. Avattha fake pannunga, unmaiyaana model-a oru scheduled evaluation run-oda judge pannunga.
- **Floats-a `==`-oda compare panradhu, illa float-la irundhu `Decimal` build panradhu.** Money-kku `Decimal("1.10")`, matha floats-kku `pytest.approx` use pannunga.
- **Thappaana idathula patch panradhu, illa `spec` illaama `Mock` use panradhu.** Unmaiyaana call innum run aagum, illa oru typo sathamillaama pass aagum.
- **Code enna pannudhu-nu illaama, adhu eppadi work aagudhu-nu test panradhu.** Endha private helper call aachu-nu check panra test, ovvoru harmless refactor-laiyum udaiyum. Outputs-aiyum veliya theriyura effects-aiyum check pannunga.
- **Fail aaguradha neenga oru thadavai kooda paakkaadha test.** Adha fix-kku munnaadi ezhudhunga, illa oru thadavai venumne code-a udaichu paarunga. Fail aagave mudiyaadha test edhaiyum paadhugaakkaadhu.
- **Clock illa machine-oda time zone-a saarndhirukkuradhu.** Dates-a pass pannunga, naal mukkiyam-naa `Asia/Kolkata`-nu per sollunga.
- **100% coverage-kku pinnaadi oduradhu.** Coverage enna run aachu-nu kaattum, adhu check aachaa-nu illa. Mukkiyamaana behaviour-a test pannunga.
