## Idhu enna

Agent edhaavadhu thappaa pannum podhu, yen-nu therinjukkanum: entha step vazhi thavari pochu, model enna paathuchu, entha tool enna thandhuchu. **Agent logs** (adhigam traces-nu solluvaanga) ovvoru run-oda ovvoru step-aiyum record pannum:

- ovvoru model call: input messages, reply, tokens, time;
- ovvoru tool call: tool, arguments, result illa error, time;
- final outcome, user, prompt-oda, model-oda versions.

| Step | Type | Input | Output | Time |
|---|---|---|---|---|
| 1 | model | Question + tools | Calls get_tracking | 1.1 s |
| 2 | tool | get_tracking(SHP-77812) | "Nagpur hub, 3 Nov" | 0.4 s |
| 3 | model | ... + tracking result | Calls get_eta | 0.9 s |
| 4 | tool | get_eta(SHP-77812) | **ERROR: timeout** | 5.0 s |
| 5 | model | ... + the error | **"Arrives 5 November"**: kattu kadhai | 0.8 s |

Run 9c1f, user cust-2231, prompt v6, model chat-default.

Indha lesson Hyderabad-la oru logistics company-a follow pannum. Avanga shipment agent sila samayam customers-ku thappaana delivery dates sonnadhu.

## Idhu eppadi work aagudhu

**Ovvoru step-aiyum structured data-vaa record pannunga**, loose print statements-a illa. Oru simple shape: run id, step number, type (model illa tool), inputs, outputs, start, end time, tokens, cost. Runs-a JSON lines-aa illa oru tracing tool-la store pannunga.

**Mudinja podhu oru tracing tool use pannunga.** LLM apps-ku kattuna tools (Langfuse, Arize Phoenix, LangSmith, innum sila, neraya OpenTelemetry mela) ovvoru run-aiyum steps-oda oru tree-yaa kaattum, adha expand pannalaam, timings, costs-oda.

**Ellathaiyum link pannunga.** Ovvoru run-kum oru id kudunga, adha tool logs-kum application logs-kum pass pannunga, appo oru request-a ella systems vazhiyaavum follow pannalaam.

**Failed runs-a padinga.** Kadaisila irundhu (enna thappu) aarambichu pinnaadi poga: tool result thappaa irundhadha? Model adha thappaa purinjukkichaa? Munnaadi thappaana tool-a select pannichaa? Information varavae illaiyaa?

**Failures-a tests-aa maathunga.** Ovvoru interesting failure-oda input-aiyum oru test case-aa save panni, maatrangalukku apram thirumba run pannunga.

**Privacy-a gavanichukkunga.** Logs-la user messages-um tool data-vum irukkum. Personal data-va mask pannunga, access-a restrict pannunga, retention periods set pannunga.

**Measure pannunga.** Logs-la irundhu success rates, oru task-ku steps, oru task-ku cost, romba mella irukkura steps, romba common-aana errors kidaikkum.

**JSON lines-la oru step record:**

```text
{"run":"9c1f","step":4,"type":"tool","name":"get_eta","args":{"id":"SHP-77812"},
 "error":"timeout after 5 s","start":"2026-11-03T21:52:10+05:30","ms":5004}
```

**Logs seekkiram badhil sollanum-nu kelvigal:**

| Kelvi | Thevaiyaana fields |
| --- | --- |
| Indha answer yen thappaachu? | Ovvoru step-oda inputs, outputs, order-la |
| Entha tool adhigam fail aagudhu? | Ovvoru step-ku tool name, error |
| Oru task-ku evvalavu selavu? | Ovvoru model call-kum tokens, cost, run-ku sum pannadhu |
| Pudhu prompt help pannichaa? | Ovvoru run-layum prompt version, kooda outcome |
| Entha user-ku indha problem vandhuchu? | Pseudonymous user id, run id |

**Regular-aa review panra palakkam.** Vaaraththukku oru thadava, patthu runs padinga: aindhu fail aana illa poor feedback vandhadhu, aindhu random-aa select panna. Random runs mukkiyam, yenna adhula yaarum innum complain pannaadha problems theriyum, example moonu steps podhum-nu irukkum idathula agent ettu steps edukkradhu. Ovvoru run-kum enna sariyaa, enna thappaa-nu oru line ezhudhunga. Oru maadhathula, indha notes entha dashboard-a vida nallaa, adutha fix edhu-nu kaattum.

**Volume valarum podhum logs-a useful-aa vachirukkradhu.** Error, refusal, negative feedback irukkura ovvoru run-aiyum, kooda matha-vatrula oru sample-aiyum store pannunga. Ungaloda release cycle-a cover panra alavukku vachirunga, appo oru maatratha munnaadiyum pinnaadiyum compare pannalaam.

**Neengalae ezhudha koodiya oru sirya tracer.** Oru tool-a adopt pannradhukku munnadi, sila lines ovvoru step-kum run id, timing, structured record kudukkum:

```python
import json, time, uuid
from contextlib import contextmanager
from contextvars import ContextVar

RUN_ID = ContextVar("run_id", default=None)
STEP = ContextVar("step", default=0)

def start_run(user, prompt_version, model):
    rid = uuid.uuid4().hex[:8]
    RUN_ID.set(rid); STEP.set(0)
    write({"run": rid, "type": "run_start", "user": user, "prompt": prompt_version, "model": model})
    return rid

def write(record):
    record["at"] = time.strftime("%Y-%m-%dT%H:%M:%S%z")
    with open("traces.jsonl", "a") as f:
        f.write(json.dumps(record, ensure_ascii=False) + "\n")

@contextmanager
def step(kind, name, **inputs):
    STEP.set(STEP.get() + 1)
    rec = {"run": RUN_ID.get(), "step": STEP.get(), "type": kind, "name": name, "inputs": inputs}
    t0 = time.monotonic()
    try:
        yield rec                           # the caller sets rec["output"], tokens, cost
    except Exception as err:
        rec["error"] = f"{type(err).__name__}: {err}"
        raise
    finally:
        rec["ms"] = round((time.monotonic() - t0) * 1000)
        write(rec)

# Use it around every model and tool call:
start_run("cust-2231", "v6", "chat-default")
with step("tool", "get_tracking", id="SHP-77812") as rec:
    rec["output"] = "Nagpur hub, 3 Nov 21:40"
```

**Oru run-a thirumba padikkradhu.** Adhe file "run 9c1f-la enna nadandhuchu?"-nu badhil solludhu:

```python
def show(run_id, path="traces.jsonl"):
    rows = [json.loads(l) for l in open(path) if json.loads(l)["run"] == run_id]
    for r in sorted(rows, key=lambda r: r.get("step", 0)):
        what = r.get("error") or str(r.get("output", ""))[:60]
        print(f'{r.get("step", "-"):>2} {r["type"]:<9} {r.get("name", ""):<14} {r.get("ms", ""):>6} ms  {what}')
```

Oru tracing tool-ku poga podhum, adhe fields-a vachukkunga. Perumbaalaana tools OpenTelemetry spans-a eduthukkum, adhanaala records enga anuppudhu-nu maathuradhu thaan perumbaalum maatram.

**Behaviour-a maathura ellaathaiyum log pannunga.** Model name, version, sampling settings, prompt template version, nijamaa anuppina final prompt, tool versions, retrieval settings. Vaaraalkalukku apram oru bug vandhaa, kelvi eppovum "indha run-la enna vera maadhiri irundhuchu?"-nu thaan irukkum, log panna settings mattum thaan adhukku badhil sollum.

**Data-va paakkuradhu ungaloda ennatha maathum.** Real runs-a regular-aa padikkira teams-ku, oru nalla answer-na enna-nu avanga ennam maarudhu-nu kandupidikkiraanga: avanga yosikkaadha failure types-um, yaarum ezhudhi vaikkaadha requirements-um theriyum. Adha prompt-layum eval set-layum serunga.

**Traces-la irundhu agent metrics.** Run-vaaripaa group panni compute pannunga: success rate, oru run-ku steps, oru run-ku cost, tool error irukkura runs-oda share, adhukku apram adhigam failure varra tools. Oru run-ku steps ethaina neram yeruna, adhu prompt illa tool maatram agent-a kuzhappichuchu-nu mudhal arikuri aagum.

## Oru worked example

Hyderabad-la oru logistics company-oda agent "Where is my shipment?"-nu kekkum podhu tracking, delay-reason, ETA tools-a call panni badhil solludhu. Customers sila samayam thappaana delivery dates varudhunnu report panraanga.

Report panna run-oda trace-a team thirakkudhu:

```text
run 9c1f  user=cust-2231  prompt=v6  model=chat-default  5 steps  6.2 s  Rs 0.38
 1 model      -> calls get_tracking("SHP-77812")
 2 tool       get_tracking: last scan "Nagpur hub, 3 Nov 21:40"
 3 model      -> calls get_eta("SHP-77812")
 4 tool       get_eta: ERROR timeout after 5 s
 5 model      -> "Your shipment will arrive on 5 November."
```

ETA tool timeout aachu, model "theriyaadhu"-nu sollaama oru date-a kattu kadhaiyaa sonnadhu. Fixes: tool ippo clear error message tharum ("ETA unavailable right now"); `get_eta` tharaadha varaikkum oru date-a sollaadhe-nu prompt solludhu; run-la ETA result illaadha podhu final answer-la dates-a oru check block pannum. Andha trace oru test case aagudhu.

| Fix | Effect |
| --- | --- |
| ETA tool "ETA unavailable right now"-nu tharum | Model silence-a illa, clear error-a paakkum |
| Prompt: get_eta tharaadha varaikkum date sollaadhe | Kammiyaana kattu kadhai dates |
| ETA result illaadha podhu answers-la dates-a check block pannum | Customers paakkradhukku munnadiyae kattu kadhai dates pidikkappadum |
| Run oru test case-aa save aachu | Ovvoru maatramum apram case thirumba test aagum |

**Trace yen idha seekkiram aakkuchu.** Step logs illaama, team final message-a mattum paathirukkum, "Your shipment will arrive on 5 November", ETA service-a illa model-a random-aa kuttam solli irukkalaam. Trace rendaiyum oru neraththula kaattuchu: tool timeout aachu, model andha silence-a nirappichuchu. Ovvoru fix-um andha rendu karanangalula onna target pannichu, save panna test rendum sari-aagi irukkunnu uruthi pannum.

## Podhuvaa panra thappugal

- **Final answers-a mattum log panradhu.**
- **Unstructured print statements.** Search pannavum analyse pannavum kashtam.
- **Run ids illaama.** Systems-oda steps-a connect panna mudiyaadhu.
- **Personal data-va mask pannaama log panradhu.**
- **Complaints vandha appuram mattum logs-a padikkiradhu.** Oru sample-a regular-aa review pannunga.

- **Runs-la versions illaama.** Prompt, model versions illaama, oru maatram nallaa pannuchaa mosamaa pannuchaa-nu solla mudiyaadhu.
- **Late-aa varra logs.** Event nadandhu 15 nimidam kazhichu traces vandhaa, live debugging adhukku kaathirukkum.
- **Prompt template-a log panni, final prompt-a log pannaama irukkiradhu.** Bugs perumbaalum nirappina idhulayae olinjirukkum.

## Simple logging podhum-nu eppo

- **Tools illaadha oru model call**: oru request-ku tokens, time, outcome-oda oru log line podhum.
- **Neengalae run panra prototype**: matha aalgal use panra varaikkum ovvoru step-aiyum console-la print panradhu work aagum.
- **Rendu moonu steps irukkura fixed workflows**: shared request id-oda sadharana application logs podhum.

Runs-la neraya steps irundhaa, tools mukkiyamaana vidhathula fail aanaa, illa pala perum ore system-a debug panna vendi irundhaa full traces-ku maarunga.

## Demo-la irundhu production-ku

- **Ovvoru run-aiyum trace pannunga**, ella failures-aiyum, negative-feedback runs-aiyum store pannunga, matha-vatrula sample edunga.
- **Ezhudhuradhukku munnadiyae personal data-va mask pannunga**, access-a restrict pannunga, ungaloda release cycle-a cover panra alavukku retention set pannunga.
- **Support ticket-la irundhu oru run-a open panna easy-aa aakkunga**: user-ku theriyura error message-la run id-a podunga.
- **Trace metrics-la alert vainga**: tool error rate, oru run-ku steps, oru run-ku cost.
- **Interesting runs-a test cases-aa maathunga**, oru click illa oru command-la.
