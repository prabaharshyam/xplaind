## Idhu enna

Machine learning-na data-la irundhu kathukkiradhu; data-vo noisy-aa, skewed-aa, muzhumaiyillaama irukkum. **Statistics**-na uncertainty-kkulla ungalai neengalae yemaaththikkaama data-la irundhu kathukka udhavura toolkit. ML engineering-la ovvoru vaaramum varra ainthu pagudhigal:

| Pagudhi | Entha kelvikku badhil solludhu | Entha vazhakkamaana thappai thadukkudhu |
| --- | --- | --- |
| **Data-va describe panradhu** | Typical enna, evvalavu paraviyirukku? | Misleading average-a report panradhu |
| **Sampling** | Naama kavalaippadura makkalai namma data represent pannudhaa? | Tier-3 towns-la fail aagura model |
| **Uravugal** | Idhellaam serndhu nagarudhaa, onnu innonnukku kaaranamaa? | Oru feature thaan outcome-kku kaaranam-nu claim panradhu |
| **Uncertainty** | Indha number-la evvalavu urudhi? | Noise-aa irukkura 1-point gain-a kondaadaradhu |
| **Experiments** | Namma change unmaiyilaeyae udhavuchaa? | Festival sale-oda credit-a pudhu model-kku kudukkuradhu |

## Idhu eppadi work aagudhu

### Averages-um spread-um

**Mean** ellaaththaiyum kootti, ennikkaiyaala vagukkum. Extreme values adhai izhukkum. **Median**-na sort pannaa naduvula varra value. Adhu izhukkappadaadhu.

**Standard deviation** (SD) spread-a alakkum: kittathatta, oru typical value mean-la irundhu evvalavu dhooraththula irukku-nu. Bell-shaped data-la, sumaar 68% values mean-la irundhu oru SD-kkullaiyum, sumaar 95% rendu SD-kkullaiyum varum.

Perumbaalaana values sinnadhaa, sila romba perusaa irukkura **skewed** data-la indha rule udainjidum. Indhiya incomes, order values, insurance claims, app latencies ellaamae skewed thaan. Anga "mean plus two SDs" tail-a thappaa kanikkum; percentiles thaan adhai naermaiyaa describe pannum. 90th percentile-na 90% cases adhukku keezha varra value.

| Data shape | Entha average use pannanum | Entha spread use pannanum |
| --- | --- | --- |
| Kittathatta symmetric, bell-shaped | Mean | Standard deviation |
| Skewed, neelamaana tail | Median | 90th, 99th maadhiri percentiles |

Summarise panradhukku munnaadi eppavum oru histogram plot pannunga.

### Neenga sandhikkappora distributions

Oru **probability distribution** ovvoru value-um varradhukku evvalavu vaaippu-nu describe pannum. Shape therinjaa entha summaries, tests, models arththamulladhu-nu theriyum. Perumbaalaana ML vaelaikku naalu shapes podhum:

| Distribution | Idhu edhai ennudhu | ML-la enga varum |
| --- | --- | --- |
| **Binomial** | n yes-or-no trials-la successes | n test questions-la sariyaana answers; n visitors-la buyers |
| **Poisson** | Events independent-aa irukkumbodhu, oru fixed window-kku events | Oru nimishaththukku orders, oru mani naeraththukku support tickets; asaadhaarana spikes-kku alerting |
| **Normal** | Pala sinna effects-oda sum alladhu average-aa irukkura values | Periya samples-oda averages; adhanaala thaan accuracy, means-kkaana intervals work aagudhu |
| **Long-tailed** (log-normal maadhiri) | Panam, naeram, size | Order values, latency, session length: medians, percentiles use pannunga, modelling-kku munnaadi perumbaalum log edunga |

**Base rates.** Neenga thaedurathu rare-aa irundhaa, nalla classifier kooda perumbaalum false alarms thaan pannum. Udhaaranamaa, 1 latcham UPI transactions-la 0.5% fraud-nu vechukkonga (500 cases). Oru model 90% fraud-a pidikkudhu, 5% genuine payments-a thappaa flag pannudhu. Adhu 450 frauds-aiyum 4,975 genuine payments-aiyum flag pannum, adhanaala adhoda alerts-la 8% mattum thaan fraud. Precision-a judge panradhukku munnaadi eppavum base rate-a kelunga.

### Sampling-um selection bias-um

Oru model adhu kathukitta sample alavukku thaan nallaa irukkum. Kelunga: **Indha data-la yaar missing?** Sila cases-kku saadhagamaana muraiyila collect panna data **selection bias**-a uruvaakkum. Udhaaranangal: complain panna customers mattum, alladhu approve aana loans mattum; appo reject aana applicants eppadi repay panniyiruppaanga-nu ungalukku theriyavae theriyaadhu.

Selection bias launch-kku appuram saththamillaama models-a udaikkum. Unga training data-la irukkura segment shares-a sameebaththiya live traffic-oda compare panni, launch-kku munnaadiyae adhai kandupidinga. City tier, device, language, new vs returning users use pannunga. Udhaaranamaa, training rows-la 72% metros-la irundhu varudhu, aanaa pona maasa users-la 48% thaan metros-naa, model romba kammiyaana small-town users-a thaan paarththirukku. Innum data collect pannunga, reweight pannunga, alladhu kurainjadhu segment vaariyaa accuracy-a report pannunga.

### Correlation, causation, Simpson's paradox

Rendu vishayangal serndhu nagarndhaa, onnu innonnukku kaaranam-nu arththam illai. Ice-cream sales-um neeril moozhgura sambavangalum kodaiyila rendumae adhigamaagum: veyil thaan rendaiyum iyakkudhu. Oru model correlations-a vechu **predict** pannalaam. Oru **cause**-a claim panna, udhaaranamaa oru discount retention-a adhigamaakkuchu-nu solla, oru randomised experiment alladhu kavanamaana causal methods vaenum.

Groups-a kalandhaa oru mudivae thalaikeezhaa maaralaam. Idhu thaan **Simpson's paradox**. Oru support bot perumbaalum Hindi users-kku roll out aagudhu-nu vechukkonga; avanga questions kashtamaanavai:

| Queries | Pazhaya bot resolve pannadhu | Pudhu bot resolve pannadhu |
| --- | --- | --- |
| English | 900-la 720 (80%) | 300-la 255 (85%) |
| Hindi | 100-la 50 (50%) | 700-la 385 (55%) |
| **Ellaam** | **1,000-la 770 (77%)** | **1,000-la 640 (64%)** |

Pudhu bot ovvoru language-laiyum better, aanaa moththamaa paarththaa mosamaa theriyudhu, yennaa kashtamaana queries adhukku thaan adhigamaa vandhuchu. Orae maadhiriyaanadhai orae maadhiriyaanadhoda, segment vaariyaa compare pannunga, alladhu yaarukku entha version-nu randomise pannunga.

### Standard error-um confidence intervals-um

SD thanith-thani values-a describe pannum. **Standard error** (SE), oru mean alladhu accuracy maadhiri oru estimate, oru sample-la irundhu innoru sample-kku evvalavu aadum-nu describe pannum. Sample size-oda square root-oda adhu kuraiyum: naalu madangu data SE-a paadhiyaakkum. n examples-la alandha oru accuracy p-kku, SE-na p × (1 − p) ÷ n-oda square root.

Oru **95% confidence interval** kittathatta estimate plus or minus 2 SE. Unmaiyaana number-kku nambakkoodiya values-oda oru range-a adhu tharum; 95% thadavai unmaiyaana value-a pidikkura oru method vechu adhu uruvaakkappadudhu. 200 test examples-la, alandha 87%-kku pinnaadi irukkura unmaiyaana accuracy sumaar 82% mudhal 92% varai enga vaenumnaalum irukkalaam.

| Test examples | Alandha 87%-a suththi 95% interval |
| --- | --- |
| 200 | sumaar ± 4.7 points |
| 1,000 | sumaar ± 2.1 points |
| 5,000 | sumaar ± 0.9 points |

F1 alladhu median utpada entha metric-kkum interval edukka oru seekkiramaana vazhi **bootstrapping**. Unga test set-a replacement-oda pala thadavai resample pannunga, ovvoru thadavaiyum metric-a marupadi calculate pannunga, results-oda nadu 95%-a edunga.

### Orae test set-la rendu models-a compare panradhu

Adhae 200 questions-la model A 87% score pannudhu, model B 88%. Rendu intervals overlap aagudhaa-nu check panradhu oru podhuvaana pazhakkam. Andha rule misleading: vithiyaasam unmaiyaa irundhaalum rendu 95% intervals overlap aagalaam. Rendu models-um *adhae* questions-kku badhil sonnadhaiyum adhu kandukkaadhu; rendumae sariyaa sonna, alladhu rendumae thappaa sonna questions cancel aagidum, disagreements mattum thaan mukkiyam.

Adhukku badhilaa, **vithiyaasaththai naeradiyaa, question vaariyaa pair panni** alanga:

```text
  Same 200 questions (illustrative):
  A right, B wrong:   7      B right, A wrong:   9      net: B +2 questions
  Paired bootstrap of B minus A:  +1 point, 95% interval -3 to +5 points
                                  includes 0: no clear winner
```

```python
import numpy as np

# 1 = answered correctly, 0 = wrong; the same 200 questions in the same order
a = np.array([1]*167 + [1]*7 + [0]*9 + [0]*17)   # model A: 174 right, 87%
b = np.array([1]*167 + [0]*7 + [1]*9 + [0]*17)   # model B: 176 right, 88%

rng = np.random.default_rng(0)
idx = rng.integers(0, len(a), size=(10_000, len(a)))   # resample questions
diffs = b[idx].mean(axis=1) - a[idx].mean(axis=1)      # B minus A on the same draw
low, high = np.percentile(diffs, [2.5, 97.5])
print(f"B minus A: {b.mean() - a.mean():+.1%}, 95% interval {low:+.1%} to {high:+.1%}")
# B minus A: +1.0%, 95% interval -3.0% to +5.0%
```

Idhukku classic alternative **McNemar's test**; models disagree panra questions-a mattum thaan adhu paarkkum. Inga adhu p = 0.80 tharudhu. Oru useful gotcha: net gain 3 questions alladhu adhukku kammiyaa irundhaa, eththanai questions irundhaalum McNemar's test-la p eppavumae 0.05-kku keezha vara mudiyaadhu.

### p-values-um significance-um, simple-aa

Oru **p-value** orae oru kelvikku badhil sollum: change unmaiyilaeyae edhuvumae pannalai-naa, verum random noise mattumae kurainjadhu ivvalavu periya vithiyaasaththai evvalavu adikkadi uruvaakkum? 0.03 p-value-na sumaar 3% thadavai. Vazhakkappadi, p 0.05-kku keezha irukkura result-a **statistically significant**-nu solvaanga.

p-value-na change work aaguradhukkaana chance *illai*; sinna p-value-na periya effect-nnum arththam illai. Sample podhumaana alavu perusaa irundhaa, ship panra alavukku worth illaadha romba sinna gain kooda significant aagidum. p-value mattum illaama, effect-oda size-a adhoda confidence interval-oda serththu eppavum report pannunga.

### A/B tests

Oru change udhavudhaa-nu therinjukka, users-a **randomly** piringa: silar pazhaya version-a (control) paarppaanga, silar pudhusai (treatment). Rendaiyum adhae naatkalla run panni, munnaadiyae thaerndheduththa oru metric-a compare pannunga.

Primary metric-a kavanamaa thaerndhedunga. **Average order value** vaanguna users-a mattum thaan ennum. Pudhu model *yaar* vaanguraanga-ngaradhaiyae maaththuchu-naa, rendu groups-laiyum irukkura buyers vaera vaera aatkal, adhanaala comparison biased aagum. **Revenue per user** moththa revenue-a group-la irukkura ellaa users-aalaiyum vagukkum, avanga vaangunaalum vaangalai-naalum; adhanaala adhu nyaayamaa irukkum. Adhai primary metric-aa vainga, order value-aiyum conversion-aiyum secondary metrics-aa vechukkonga.

| Rule | Yen |
| --- | --- |
| Oru primary metric, sample size, duration ellaam munnaadiyae fix pannunga | Change edhuvumae pannalai-naa, 20 independent metrics-a check pannaa kurainjadhu onnu luck-aala "win" panna 64% chance irukku |
| Yaar entha version paarkkanum-nu randomise pannunga | Appo thaan groups change-aala mattum vaerupadum |
| Sample ratio-va check pannunga | 10 latcham users-oda plan panna 50/50 split 5,03,000 vs 4,97,000-aa vandhaa, assignment alladhu logging-la bug irukku-nu arththam; result-a nambaadheenga |
| Muzhu vaarangalukku run pannunga | Weekday, weekend behaviour vaera vaera |
| Nallaa theriyudhu-nu seekkiramae niruththaadheenga | Edhuvumae pannaadha oru change-a naanga simulate pannappo, 14 naal dhinamum check panni mudhal thadavai p 0.05-kku keezha vandhavudanae niruththunaa, 5% illai, 22% thadavai oru "winner"-a arivichchadhu |
| Novelty effects-a kavaninga | Pudhu design pudhusaa irukkuradhaala users click pannuvaanga; rendaavadhu vaaraththula gain manggudhaa-nu check pannunga |
| Guardrail metrics-a kavaninga | Revenue-la gain vandhaa, koodavae returns, complaints adhigamaagak koodaadhu |

### Eththanai users vaenum?

Test-kku munnaadi, naalu inputs vechu sample size-a mudivu pannunga:

1. **Baseline**: ippo irukkura value, udhaaranamaa 3.4% conversion rate.
2. **Minimum detectable effect (MDE)**: kandupidikka worth-aana migach sinna gain, udhaaranamaa 10% relative lift, 3.4%-la irundhu 3.74%-kku.
3. **Significance level**: podhuvaa 5%; change edhuvumae pannaadhappo neenga aeththukkura false-alarm rate.
4. **Power**: podhuvaa 80%; MDE alavulla oru unmaiyaana effect-a kandupidikkira chance.

Indha inputs-oda ungalukku **oru group-kku sumaar 46,700 users** vaenum. MDE-a paadhiyaakki 5% lift-aa vechaa, oru group-kku sumaar 1.83 latcham vaenum: effect-a paadhiyaakkunaa users kittathatta naalu madangaagum. Python-la, `statsmodels.stats.power.NormalIndPower().solve_power` indha calculation-a pannum.

Revenue per user-kku conversion-a vida romba adhigamaana users vaenum, yennaa sila romba periya orders adhai romba noisy aakkidum. Rendu standard fixes udhavum. Average panradhukku munnaadi ovvoru user-oda revenue-aiyum 99th maadhiri oru uyarndha percentile-la cap pannunga. Alladhu CUPED maadhiri oru variance-reduction method use pannunga; test-kku munnaadi ovvoru user-um evvalavu spend pannaanga-nu vechu adhu adjust pannum.

## Oru worked example

Mumbai-la oru e-commerce company-yoda data team, pudhu recommendation model average order value-va ₹1,240-la irundhu ₹1,310-kku uyarththuchu-nu report panraanga: ₹70 gain. Leadership kondaada ready-aa irukkaanga. Neenga adhai check panreenga. Keezha irukkura test numbers illustrative thaan, oru simulated test-la irundhu generate pannadhu, aanaa unmaiyaana tests maadhiriyae behave pannum.

**Step 1: averages.** Order values skewed. Sila periya electronics orders mean-a nagarththuchu. Median order ₹780-la irundhu ₹790-kku mattum thaan uyarndhuchu.

**Step 2: timing.** Comparison pona maasam (pazhaya model) vs indha maasam (pudhu model). Indha maasam oru festival sale irundhuchu. Rendu maasangalaiyum compare panna mudiyaadhu, adhanaala andha ₹70 model paththi edhuvumae sollala.

**Step 3: sariyaana test-a design pannunga.** Aarambikkiradhukku munnaadi, team idhaiyellaam fix pannudhu:

- **Primary metric:** revenue per user; ovvoru user-oda revenue-um order values-oda 99th percentile-la (sumaar ₹7,300) cap pannadhu.
- **Secondary metrics:** conversion, mean, median order value. **Guardrail:** return rate.
- **Size:** capped revenue per user-la 5% lift-a kandupidikka oru group-kku sumaar 3.9 latcham users vaenum. Rendu muzhu vaara traffic oru group-kku sumaar 5 latcham tharum, adhanaala test sariyaa rendu vaaram run aagudhu.

**Step 4: split-a check pannunga.** Groups-la 5,00,212, 4,99,788 users irukkaanga. Indha counts-la chi-square test p = 0.67 tharudhu, adhanaala split oru nyaayamaana 50/50-oda oththuppogudhu.

**Step 5: results-a padinga.**

| Measure | Pazhaya model | Pudhu model | Vithiyaasam (95% interval) |
| --- | --- | --- | --- |
| Revenue per user, capped (primary) | ₹40.61 | ₹42.16 | +₹1.55 (+₹0.29 mudhal +₹2.81) |
| Conversion rate | 3.38% | 3.45% | +0.07 points (sumaar 0 mudhal +0.14) |
| Mean order value | ₹1,237 | ₹1,258 | +₹21 (−₹12 mudhal +₹54) |

| Return rate (guardrail) | 6.28% | 6.15% | −0.13 points (−0.64 mudhal +0.38) |

**Step 6: mudivu pannunga.** Primary metric-oda interval zero-va exclude pannudhu, adhanaala model unmaiyilaeyae udhavudhu: revenue per user-la sumaar +3.8%. Gain konjam adhigamaa vaangaradhulaiyum konjam periya orders-laiyum irundhu varudhu; rendumae thaniyaa paarththaa thelivaa illai. Returns-la entha harm-um illai. Mudhal report-la irundha ₹70 festival maasaththula irundhum sila periya orders-la irundhum vandhadhu. Mean order value-a mattum paarththirundhaa inconclusive-aa therinjirukkum-nu kavaninga.

10 latcham users-kku, indha gain-oda madhippu sumaar ₹15.5 latcham; nambakkoodiya range ₹2.9 latcham mudhal ₹28 latcham. Leadership indha naermaiyaana numbers-oda model-a roll out panraanga. Team thanga launch checklist-la "Impact-a claim panradhukku munnaadi A/B test" saerkkudhu.

## Podhuvaa panra thappugal

- **Skewed data-oda mean-a report panradhu.** Median, percentiles, oru histogram paarunga.
- **Base rate-a kandukkaama vidradhu.** 95% accurate-aana fraud model kooda adhoda perumbaalaana alerts-la thappaa irukkalaam.
- **Vaera vaera kaalangalai compare panradhu.** Seasons, festivals ellaaththaiyum maaththidum; adhukku badhilaa randomise pannunga.
- **Data-la yaar missing-nu kandukkaama vidradhu.** Launch-kku munnaadi training segments-a live traffic-oda compare pannunga.
- **Correlation-a causation-aa ninaikkiradhu.** Prediction cause-kku proof illai, pooled numbers thalaikeezhaa maaralaam (Simpson's paradox).
- **Overlapping intervals vechu rendu models-a judge panradhu.** Adhae test set-la paired bootstrap alladhu McNemar's test use pannunga.
- **Buyers-only metric-a primary metric-aa use panradhu.** Order value illai, revenue per user use pannunga.
- **Peek panradhu, seekkiramae niruththuradhu, alladhu niraiya metrics-a check panradhu.** Oru primary metric, sample size, duration-a munnaadiyae fix pannunga.
- **Sample ratio check-a skip panradhu.** Samamillaadha split-na udainja test, result illai.

## Practice pannunga

Keezha link panniyirukkura p-values, confidence intervals, bootstrapping paththina StatQuest videos-aiyum, Google-oda Machine Learning Crash Course-la irukkura data module-aiyum paarunga.

1. **Mean vs median.** Panam alladhu naeram column irukkura edhaavadhu oru public dataset-a load pannunga. Oru histogram plot panni, mean, median, 90th, 99th percentiles-a compare pannunga.
2. **Paired bootstrap.** Rendu models-a, alladhu rendu prompts-a, adhae 200 test examples-la score pannunga. Mela irukkura code use panni vithiyaasaththukku 95% interval edunga, appuram McNemar's test run panni rendu mudivugalaiyum compare pannunga.
3. **Oru test design pannunga.** Ungalukku mukkiyamaana oru change-kku A/B test design pannunga: primary metric, guardrails, MDE, `statsmodels` vechu sample size, muzhu vaarangalla duration.

**Mudinjadhu-nu eppo sollalaam:** 200 examples-la 1-point accuracy gain yen convincing illai-nu explain panna mudiyum, paired test vechu rendu models-a compare panna mudiyum, oru nyaayamaana A/B test-a size panni design panna mudiyum.
