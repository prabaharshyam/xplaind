## Idhu enna

**Document extraction** oru unstructured document-a structured fields-aa maathum: oru invoice PDF-la irundhu vendor name, GSTIN, invoice number, date, line items, tax amounts, total. Oru automation, varra ovvoru document-kum idha seiyum, apram result-a check panni, oru sheet, accounting system, illa approval step-ku anuppum.

Modern AI models, ovvoru supplier-kum oru template thevai pattha pazhaya template-based tools-a vida, vera vera layouts-a romba nallaa handle pannum.

```flow
Email, WhatsApp illa oru folder -> 1 Receive, original-a store pannunga -> 2 Content edunga | text, OCR, illa vision model-ku image
2 Content edunga -> 3 Schema vachu extract pannunga | supplier, GSTIN, number, date, lines, CGST, SGST, total
3 Schema vachu extract pannunga -> 4 Validate | formats, arithmetic, business rules
4 Validate -> Ellaam pass-aa?
Ellaam pass-aa? -[aam]-> 5 Accounting-la post pannunga -> 6 Record-um audit trail-um
Ellaam pass-aa? -[illa]-> 5 Review screen | image fields pakkathula, fail aana checks red-la
5 Review screen -[oru aal correct pannuvaar]-> Final record-um oru pudhu test case-um
```

Indha lesson, Surat-la oru textile trader, maadham sumaar 900 supplier invoices-a process panradhu, adha follow pannum.

## Idhu eppadi work aagudhu

**1. Receive.** Documents email attachment, upload form, shared folder, illa WhatsApp vazhiya varum. Trigger avangala edukkum, original-a store pannum.

**2. Content edukkuradhu.** Digital PDFs: text-a extract pannunga. Scans-um phone photos-um: OCR, illa image-a neradiyaa vision-capable model-ku anuppunga. Page reference-a vachukkunga.

**3. Schema vachu extract panradhu.** Content-a model-ku, oru clear instruction-oda, oru fixed output shape-oda (field names, types, edhu required) anuppunga. Tool-oda structured-output feature illa oru JSON schema use pannunga, adhanaala ovvoru thadavaiyum exact-aa andha fields kidaikkum. Oru field illa-na, guess-ku badhila null kelunga.

**4. Rules vachu validate pannunga.** Extraction-a kannai moodikittu nambaadheenga. Check pannunga:

- formats: GSTIN sariyaana pattern-la 15 characters; dates valid; PIN codes-ku aaru digits;
- arithmetic: line totals subtotal-oda serndhu pogum; subtotal plus tax total-ku samam;
- business rules: vendor unga master list-la irukkaanga; PO number oru open order-oda match aagudhu; amount expected range-kulla irukku.

**5. Route.** Ellaa checks-um pass aanaa, automatic-aa thodarungal. Edhavadhu fail aanaa, illa oru required field illa-na, document-oda, fail aana check highlight-aagi, oru aal-kitta anuppunga. Avanga correction final record-um, oru useful test case-um aagum.

**6. Record.** Extract panna data, checks, yaar approve pannaanga-nu audit-ku vachukkunga.

**Measure.** Straight-through rate (manushan thodaadha share), aatkal check panna sample-la field accuracy, neram migundhadha track pannunga.

**Indian invoices-ku validation rules:**

| Field | Check | Edha pidikkum |
| --- | --- | --- |
| GSTIN | 15 characters, valid pattern, state code address-oda match, supplier master-la irukkaradhu | Thappaa padikkiradhu, thappaana supplier |
| Invoice date | Valid date, future-la illa, accounting period-kulla | 31 February, typos |
| Line items | Quantity × rate = amount; lines subtotal-oda serum | Miss aana illa merge aana lines |
| Tax | Intra-state-ku CGST-um SGST-um samam; inter-state-ku IGST; amounts rates-oda match | Thappaana tax type, thappaa padicha amounts |
| Total | Subtotal + taxes = total | Entha arithmetic misread-aiyum |
| Invoice number | Indha supplier-ku ippovae record aagala | Duplicate payments |

**Model choice-a vida rules yen mukkiyam.** Romba capable model kooda, appo appo oru blurry digit-a thappaa padikkum. Arithmetic-um format checks-um, selavu illaama, perumbaalaana andha errors-a pidikkum, yenna thappaa padicha digit totals-a consistent-aa vachirukka koodiya vaaippu kidaiyaadhu. Model padikkum; padichadha nambalaamaa-nu rules mudivu pannum.

**Confidence-um review queues-um.** Reviewers ovvoru field-aiyum marubadiyum check panna vendaam. Oru rule fail aana fields-a mudhalla kaattunga, apram model uncertain-nu mark panna illa null-aa vitta fields, meedhi-a reviewers oru action-la approve pannalaam. Reviews evvalavu neram edukkudhu-nu track pannunga; oru reviewer ovvoru document-kum oru nimishathukku mela edukkaraanga-na, screen-a than sari pannanum, reviewer-a illa.

**Code-la validation rules.** Indha checks extraction-ku apram odum, oru document neradiyaa pogumaa-nu mudivu pannum:

```python
import re
from datetime import date
from decimal import Decimal

GSTIN_RE = re.compile(r"^[0-3][0-9][A-Z]{5}[0-9]{4}[A-Z][1-9A-Z]Z[0-9A-Z]$")
CHARS = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ"

def gstin_ok(g):
    if not GSTIN_RE.match(g or ""):
        return False
    total = 0
    for i, ch in enumerate(g[:14]):
        p = CHARS.index(ch) * (1 if i % 2 == 0 else 2)
        total += p // 36 + p % 36
    return CHARS[(36 - total % 36) % 36] == g[14]

def check_invoice(inv, supplier_state, our_state, seen_numbers):
    problems = []
    if not gstin_ok(inv["supplier_gstin"]):
        problems.append("supplier GSTIN fails format or check digit")
    elif inv["supplier_gstin"][:2] != supplier_state:
        problems.append("GSTIN state code does not match the supplier's state")
    if inv["invoice_date"] > date.today():
        problems.append("invoice date is in the future")
    lines = [Decimal(l["qty"]) * Decimal(l["rate"]) for l in inv["lines"]]
    if any(abs(c - Decimal(l["amount"])) > Decimal("0.01") for c, l in zip(lines, inv["lines"])):
        problems.append("a line amount is not quantity × rate")
    subtotal = sum(lines)
    if abs(subtotal - Decimal(inv["subtotal"])) > Decimal("0.01"):
        problems.append("lines do not add up to the subtotal")
    tax = Decimal(inv.get("cgst") or 0) + Decimal(inv.get("sgst") or 0) + Decimal(inv.get("igst") or 0)
    if supplier_state == our_state and inv.get("igst"):
        problems.append("IGST charged on an intra-state supply")
    if supplier_state != our_state and (inv.get("cgst") or inv.get("sgst")):
        problems.append("CGST/SGST charged on an inter-state supply")
    if abs(subtotal + tax - Decimal(inv["total"])) > Decimal("1.00"):      # allow rupee rounding
        problems.append("subtotal plus tax does not equal the total")
    if (inv["supplier_gstin"], inv["invoice_number"]) in seen_numbers:
        problems.append("duplicate invoice number for this supplier")
    return problems
```

Oru empty list-na straight through; vera edhuvum review-ku pogum, problems mudhalla list aagi. Panatha `Decimal` vachu handle pannunga, floats-a ennaikkum illa.

**Field accuracy-a sariyaa measure pannunga.** Aatkal 50-la irundhu 100 documents-a kaiyaala key panni oru gold set-aa vainga. Ovvoru field-kum, normalise panna apram (dates-a orae format-ku, amounts-a rendu decimals-ku) extraction-kum gold value-kum exact matches-a count pannunga. Oru overall number illa, field-wise report pannunga: 98% overall score invoice dates-la 80%-a maraikkalaam.

**Straight-through rate vs error rate.** Rules-a loosen pannaa, neraya documents neradiyaa pogum, aana neraya errors books-kulla varum. Rendaiyum track pannunga. Oru nalla target finance team-oda set aagum: example, kurainjadhu 70% straight through, ledger-ku varra thappaana fields 500-la 1-ku kammi.

**Corrections-a thirumbi kudunga.** Ovvoru reviewer correction-um oru labelled example. Kashtamaanadhai unga test set-la serunga, oru supplier-oda layout thirumba thirumba mistakes-a kondu vandhaa, prompt-la oru chinna supplier-specific hint illa oru dedicated rule serkkunga.

## Oru worked example

Surat-la oru textile trader, maadham sumaar 900 supplier invoices-a PDFs-aavum, WhatsApp, email-la phone photos-aavum vaangaraanga.

Automation:

- Oru dedicated email address-lerndhum, oru WhatsApp Business number-lerndhum attachments-a collect pannum.
- Ovvoru page-aiyum, oru schema-oda vision-capable model-ku anuppum: supplier name, supplier GSTIN, invoice number, invoice date, line items (description, HSN code, quantity, rate, amount), CGST, SGST, IGST, total.
- Validate pannum: GSTIN pattern-um supplier master-oda match-um; lines serum; tax amounts rates-oda consistent; invoice number andha supplier-ku ippovae record aagala.
- Pass aana invoices-a accounting import sheet-la ezhudhum; failures-a, image fields pakkathula irukkura review screen-la accounts assistant-kku anuppum.

Mudhal maadham: 71% straight through; perumbaalaana failures blurry photos-um kai-ezhuthu corrections-um. Adikkadi vara suppliers-a PDFs email panna sollitu, photo prompt-a improve pannina apram, straight-through 84% aagudhu. Invoice entry-la accounts staff neram maadham sumaar 60 mani-la irundhu 15-ku kuraiyudhu, duplicate-invoice check ₹2.3 lakh mathippulla naalu duplicate payments-a pidikkudhu.

| Measure | Maadham 1 | Maadham 3 |

## Podhuvaa panra thappugal

- **Free-form output.** Schema use pannunga, fields eppovum irukkum, type-oda irukkum.
- **Validation rules illa.** Arithmetic-um format checks-um perumbaalaana extraction errors-a pidikkum.
- **Model miss aana fields-a guess panna vidradhu.** Null kelunga, oru aal-kitta route pannunga.
- **Original document-a ilakkiradhu.** Check-ku, audit-ku adha record-oda link panni vainga.
- **Edhaiyum measure pannaama irukkiradhu.** Straight-through rate-um sample accuracy-yum track pannunga.

- **Ovvoru page-aiyum romba vilai-yaana model-ku anuppradhu.** Digital PDFs-ku text extraction use pannunga, vision models-a scans-ku, photos-ku vainga; cost-a romba kuraikkum.
- **Panatha float arithmetic-la seiyradhu.** Paise-a integers-aa illa `Decimal` use pannunga.
- **Ella fields-kum oru accuracy number.** Ovvoru field-aiyum thaniyaa measure pannunga.
- **Duplicates-a check pannaama irukkiradhu.** Marubadiyum anuppina invoice rendu thadava pay aagum.

## Extraction automation worth illaadha edathula

- **Maadhathukku konjam documents**: avangala type panradhu, oru pipeline-a build panni check panradhai vida sulabam.
- **Structured data ippovae irukku**: e-invoices, bank statement exports, supplier-oda API, PDFs-a padikkradhai vida nalladhu.
- **Ovvoru document-kum expert judgement ippovae thevai**, example legal contracts-a clause by clause review panradhu.

## Demo-la irundhu production-ku

- **Kaiyaala key panna documents-oda oru gold set vainga**, ovvoru change-kum field-wise accuracy-a measure pannunga.
- **Original-a, extraction-a, checks-a, approver-a** audit-ku store pannunga.
- **Straight-through rate kuraiyum podhu alert pannunga**, adhu perumbaalum oru supplier layout maathunaanga-nu artham.
- **Thevai illaadha edathula logs-layum review screens-layum** personal, bank details-a mask pannunga.
- **Ovvoru quarter-um finance-oda rules-a review pannunga**, mukkiyamaa GST changes-ku apram tax rules.
