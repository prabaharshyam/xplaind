## Idhu enna

Fine-tuning oru model-a maathudhu. **Model merging** rendu alladhu adhukku mela models-oda weights-a kalandhu ore model-aa serkkudhu. Training run edhuvum thevaiyilla: merge-na weight files mela panra arithmetic thaan.

Models **ore base model**-la irundhu fine-tune aanappo thaan merging nallaa work aagum. Yen? Fine-tuning weights-a aarambicha idathula irundhu konja dhooram thaan nagarthum. Ore base-la irundhu fine-tune aana rendu models innum adhukku pakkathulayum onnukkonnu pakkathulayum irukkum, weight number 1,000-ku rendulayum kittathatta ore artham thaan. Scratch-la irundhu train aana rendu models avatrooda features-a vera vera order-la kathukkum, adhanaala avatrai average panna sambandhamillaadha numbers kalakkum, perumbaalum rendume udainjudum.

Yen merge pannanum?

- **Mixed requests-ku ore model.** Oru request-ku rendu skills thevaippattaa (oru complaint-a classify panni reply-a draft panradhu), merged model adhai ore call-la handle pannum, models-ku naduvula thernthedukka router edhuvum vendaam.
- **Ship panna ore file.** Merged model oru saadhaarana model thaan. Endha runtime-um adhai load pannalaam, adapter support illaadhavai kooda.
- **Varisaiyaa train panradhai vida kuraivaana forgetting.** Task A-la train panni appuram task B-la train panna, model perumbaalum A-a marandhudum. Ovvoru task-aiyum thaniyaa train panni merge panna andha risk kuraiyum, aanaa adhukku-nnu oru prachanai varum: tasks-oda maatrangal onnoda onnu interfere pannum, adhanaala ovvoru task-aiyum thirumba test pannanum.
- **GPUs vendaam.** Simple merges CPU-laye run aagum. Models-ku disk space-um memory-um thaan venum, GPU illa.

Inputs LoRA adapters-aa irukkumbodhu, merging ungalukku memory-a michappaduthi **tharaadhu**. LoRA adapter chinnadhu. Udhaaranamaa, Llama-3-8B shape-la irukkura oru model-oda ovvoru linear layer-layum rank 16-na sumaar 42 million parameters, 16-bit-la sumaar 84 MB; base 16-bit-la sumaar 16 GB. Moonu adapters base-ku sumaar 1.6% thaan serkkum. Avatrai merge panna kittathatta edhuvum michamaagaadhu.

Merging oru **ensemble**-la irundhum vera. Ensemble ovvoru request-kum pala models-a run panni avatrooda badhilgalai serkkudhu, adhanaala ovvoru request-kum pala calls selavaagum. Merge weights-a ore thadavai serkkudhu; adhukkappuram ore model-a saadhaarana cost-la serve pannuveenga.

Reputation pathi oru note. 2024-la Hugging Face-oda Open LLM Leaderboard-oda top muzhukka merges thaan irundhuchu. Avatrooda scores perumbaalum real use-la appadiye varalai-nnu solli, leaderboard team merges-a default-aa hide pannaanga. Leaderboard-e March 2025-la retire aayiduchu. Paadam appadiye irukku: oru merge-oda public scores unga tasks pathi konjam thaan sollum.

```flow
title: Merging fine-tuned models
Base model -> Fine-tune for task A | adapter or full
Base model -> Fine-tune for task B
Fine-tune for task A -> Task vector A | A minus base
Fine-tune for task B -> Task vector B | B minus base
Task vector A -> Combine | average, SLERP, TIES, DARE
Task vector B -> Combine
Combine -> Merged model
Merged model -> Test every task and safety
Test every task and safety -[pass the bar]-> Ship one model
Test every task and safety -[miss the bar]-> Keep separate models
```

## Idhu eppadi work aagudhu

### Task vectors

Fine-tuned model-oda weights-la irundhu base model-oda weights-a kazhicha ungalukku oru **task vector** kidaikkum: fine-tuning panna maatram. Task vectors-a base-la koottinaa skills serum. Onnai kazhicha oru behaviour kuraiyum. Task vectors-ku per vecha paper (Ilharco and others, ICLR 2023), toxic text-la irundhu kathukkitta oru task vector-a kazhichu, GPT-2 romba kuraivaana toxic outputs-a kudukkura maadhiri pannuchu.

LoRA-la, adapter task vector-a factored form-la store pannudhu: A, B-ngura rendu melliya matrices, avatrooda product B times A thaan ovvoru layer-layum varra maatram. Indha detail pinnaadi mukkiyamaagum. A matrices-aiyum B matrices-aiyum thanithaniyaa serkkuradhum, unmaiyaana maatrangalai serkkuradhum onnu illa.

### Weighted average-um task arithmetic-um

Romba simple merge-na task vectors-oda oru weighted sum-a base-la kootturadhu. Weights 0.5, 0.5-na adhu oru average; weights 1.0, 1.0-na adhu plain **task arithmetic**. Ore base-la irundhu varra models-ku averaging aacharyappadura alavukku nallaa work aagum. "Model soups" paper (Wortsman and others, ICML 2022) oru model-oda niraiya fine-tuned versions-a average panni, perumbaalum best single version-aiye thaanduchu, extra running cost edhuvum illaama.

Balaveenam interference. Ore oru task panna maatrathai average paadhiyaakkidum, rendu tasks oru weight-a edhir dhisaila thallumbodhu avai onnai onnu cancel pannidum.

### SLERP

**Spherical linear interpolation** rendu models-a ner kottukku badhilaa oru arc vazhiyaa blend pannudhu. Yen arc? Rendu weight vectors vera vera dhisaila point panna, avatrukku naduvula irukkura ner kottoda midpoint rendaiyum vida chinnadhaa irukkum. Model-oda weights surungum, adhu rendu models-aiyum mazhungadikkalaam. Arc size-a kaappaathum. 0-la irundhu 1 varai irukkura oru factor `t` blend-a set pannum: 0-na mudhal model, 1-na rendaavadhu. SLERP sariyaa rendu models-a thaan edukkum; moonaavadhukku thirumba merge pannunga.

### TIES-um DARE-um

Fine-tuning kittathatta ella weights-aiyum maathum, aanaa perumbaalaana maatrangal romba chinnavai. Indha chinna maatrangal konjam thaan serkkum, aanaalum merge pannumbodhu modhum. **TIES** (Yadav and others, NeurIPS 2023) ovvoru task vector-aiyum moonu steps-la clean pannudhu:

1. **Trim.** Ovvoru task vector-layum periya maatrangalai mattum vachukkonga. `density` setting-na vachukkura share: 0.3-na top 30%-a vachukkum.
2. **Oru sign-a elect pannunga.** Ovvoru weight-kum, kept changes-a koottunga. Mottha maatram adhigamaa irukkura dhisai jeyikkum.
3. **Disjoint mean.** Jeyicha sign kooda othuppora kept changes-a mattum average pannunga. Ore oru task panna maatram adhoda muzhu size-oda irukkum.

**DARE** (Yu and others, 2023) trim step-a replace pannudhu. Adhu ovvoru task vector-oda maatrangalla oru random share-a drop panni, mottha effect kittathatta adhe alavula irukka micham irukkuradhai scale up pannudhu. Idhai TIES kooda `dare_ties`-aa serkkalaam: DARE-oda random drop, appuram TIES-oda sign election.

Rendu methods-aiyum arimugappaduthina papers, plain averaging-a vida gains-a report panraanga. Idhai unga sondha tasks-la check pannunga. Model Breadcrumbs, DELLA maadhiri pudhu variants irukku, mergekit avatrai support pannudhu. Oru evolutionary search nalla merge recipes-a thaanaa kandupidikka mudiyum-nu Sakana AI 2024-la kaattuchu. Mudhalla TIES-a nallaa kathukkonga.

**Unga browser-laye try pannunga.** Rendu task vectors: weight 0-la oru conflict, weight 3-la rendum othuppogudhu, weights 4, 5-la ore oru task mattum panna maatrangal.

```python
import numpy as np

# Changes two fine-tunes made to the same 8 weights (their task vectors).
# Weight 0: the tasks disagree. Weight 3: they agree. Weights 4 and 5: only one task cares.
# The rest are tiny changes, mostly noise.
task_a = np.array([ 0.90, 0.02, -0.03, 0.80, 0.01, -0.70,  0.02, 0.00])
task_b = np.array([-0.85, 0.03,  0.02, 0.75, 0.60,  0.01, -0.02, 0.01])

def ties(vectors, density=0.4):
    stacked = np.stack(vectors)
    # 1. Trim: in each vector, keep only the largest changes (the top `density` share).
    trimmed = []
    for v in stacked:
        cut = np.quantile(np.abs(v), 1 - density)
        trimmed.append(np.where(np.abs(v) >= cut, v, 0.0))
    trimmed = np.stack(trimmed)
    # 2. Elect a sign per weight: the direction with more total change wins.
    sign = np.where(trimmed.sum(axis=0) >= 0, 1.0, -1.0)
    # 3. Disjoint mean: average only the kept changes that agree with that sign.
    agree = (np.sign(trimmed) == sign) & (trimmed != 0)
    count = np.maximum(agree.sum(axis=0), 1)
    return (trimmed * agree).sum(axis=0) / count

average = (task_a + task_b) / 2
merged = ties([task_a, task_b])
for name, v in [("task A ", task_a), ("task B ", task_b), ("average", average), ("TIES   ", merged)]:
    print(name, v.round(2) + 0.0)
```

```text
task B  [-0.85  0.03  0.02  0.75  0.6   0.01 -0.02  0.01]
average [ 0.03  0.02  0.    0.78  0.3  -0.34  0.    0.  ]
TIES    [ 0.9   0.    0.    0.78  0.6  -0.7   0.    0.  ]
```

Weight by weight-aa padinga. Average weight 0-a kittathatta onnume illaadha alavukku cancel pannidudhu, adhanaala rendu tasks-um adhai izhakkudhu; weights 4, 5-a paadhiyaakkidudhu. TIES 4, 5-a muzhu size-la vachu, noise-a clear pannudhu. Aanaa weight 0-a paarunga: TIES task A-oda 0.9-a vachukittu, task B-oda maatrathai muzhusaa thookki podudhu. TIES conflicts-a maraiya vaikkaadhu. Adhu oru winner-a thernthedukkudhu, thotha task adhukku vilai kudukkudhu. Adhanaala thaan oru merge-ku appuram oru precise task perumbaalum drop aagudhu.

### Layer stacking

Weights-a kalakkuradhukku badhilaa, vera vera models-oda layers-la irundhu oru model-a build pannalaam, idhai sila samayam "frankenmerge"-nu solvaanga. Idhu oru model-a perisaakkalaam. SOLAR 10.7B (Kim and others, 2023) oru 32-layer 7B model-oda rendu copies-a eduthu, ovvonnulayum 8 layers-a neekki, avatrai 48 layers-aa serthuchu. Nallaa work aaga adhukku further pretraining thevaippattuchu, perumbaalaana stacked models-kum appadi thaan.

### PEFT vachu LoRA adapters-a merge panradhu

```python
from peft import PeftModel
from transformers import AutoModelForCausalLM

base = AutoModelForCausalLM.from_pretrained("base-model-id")
model = PeftModel.from_pretrained(base, "adapters/complaints", adapter_name="complaints")
model.load_adapter("adapters/replies", adapter_name="replies")

# ties_svd applies TIES to the real change (B times A) of each layer, then compresses it back to a LoRA.
model.add_weighted_adapter(
    adapters=["complaints", "replies"], weights=[1.0, 1.0],
    adapter_name="merged", combination_type="ties_svd", density=0.5,
)
model.set_adapter("merged")
merged = model.merge_and_unload()   # one plain model, no adapter needed at run time
merged.save_pretrained("merged-model")
```

PEFT-la gavanikka vendiyavai (version 0.22-oda check pannadhu):

- Plain `linear`, `ties`, `dare_*` types A, B matrices-a thanithaniyaa serkkum. PEFT-oda sondha documentation `linear`-a oru rough approximation-nu solludhu. Unmaiyaana maatrathu mela work panra `_svd` types-a prefer pannunga.
- Plain types-ku ella adapters-um ore rank `r`-la irukkanum. `_svd` types-ku adhu thevaiyilla.
- `cat` adapters-a pakkam pakkamaa serkkum. Adhu maatrangaloda exact sum-a kudukkum, aanaa pudhu adapter-oda rank ella ranks-oda koottuthogaiyaa irukkum.
- DoRA adapters support aagaadhu.

### mergekit vachu full models-a merge panradhu

Full fine-tunes-ku, open-source tool mergekit oru chinna YAML file-la irundhu merge-a run pannudhu:

```yaml
merge_method: ties
base_model: ./base-8b
models:
  - model: ./complaints-8b
    parameters: {density: 0.5, weight: 1.0}
  - model: ./replies-8b
    parameters: {density: 0.5, weight: 1.0}
dtype: bfloat16
```

`mergekit-yaml merge.yml ./merged` vachu run pannunga. TIES-ku, mergekit default-aa mottha weight-aala divide pannum (`normalize`), adhanaala weights 1.0, 1.0 oru sama blend maadhiri act pannum.

### Settings-a thernthedukkuradhu

Measure panra varaikkum merge settings verum guesses thaan. Oru chinna search malivu, yenna oru merge-ku training run thevaiyilla.

1. Ovvoru task-kum oru chinna **dev set**-a thaniyaa vachukkonga, udhaaranamaa 100-la irundhu 200 examples, final test set-la irundhu thaniyaa.
2. Sama weights-la aarambichu density 0.2, 0.5, 0.8-a try pannunga. SLERP-ku, `t` 0.3, 0.5, 0.7-a try pannunga.
3. Oru task drop aanaa, adhoda weight-a yethunga, udhaaranamaa 1.0-la irundhu 1.5-ku, thirumba try pannunga.
4. Average score-a vachu illa, unga acceptance bar-a vachu best setting-a vachukkonga. Appuram test set-a ore oru thadavai run pannunga.
5. Endha merge-aiyum thirumba build panna mudiyura maadhiri, ovvoru config-aiyum adhoda scores kooda save pannunga.

| Method | Eppadi serkkudhu | Balam | Gavanikka vendiyadhu |
| --- | --- | --- | --- |
| Weighted average | Task vectors-oda weighted sum | Simple baseline, perumbaalum nalladhu | Single-task maatrangalai paadhiyaakkum; conflicts cancel aagum |
| SLERP | Rendu models-a oru arc vazhiyaa blend pannum | Weight size-a kaappaathum; smooth blend | Oru thadavaikku rendu models |
| TIES | Trim, sign elect, disjoint mean | Pala tasks-ku innum nalladhu | Conflict-la oru task thokkum; density-a tune pannunga |
| DARE | Random drop, appuram rescale | TIES kooda nallaa serum | Random: sila seeds-a compare pannunga |
| Layer stacking | Layers-a serkkum, size-a perisaakkalaam | Periya model-a uruvaakkalaam | Podhuvaa further training thevai |

## Oru worked example

Mumbai-la oru bank-kitta moonu LoRA adapters irukku, ellaame ore open 8B base model mela rank 16: complaint classification, English-layum Hindi-layum reply drafting, KYC field extraction. Branch staff oru muzhu customer letter-a paste panraanga, niraiya letters reply-um thevaippadura complaints. Bank-oda IT team approve panna offline app oru thadavaikku oru model file-a thaan load pannum, ovvoru request-kum oru adapter-a thernthedukka mudiyaadhu. KYC scanning app-la oru thani screen, oru naalaikku sila thadavai thaan use aagum.

Inga merge panna kaaranam memory illa. 16-bit-la sumaar 16 GB irukkura base-ku moonu adapters sumaar 250 MB thaan serkkum. Kaaranangal: ore model file, oru mixed letter-ku ore call.

Merge panradhukku munnaadi, team test sets-aiyum bar-aiyum ezhudhi vaikkudhu:

- **Complaints:** label panna 400 letters; accuracy.
- **Replies:** 150 letters; rendu reviewers ovvoru draft-kum oru rubric vachu 1-la irundhu 5 varai score podraanga, andha scores average pannappadum.
- **KYC:** scan panna 300 documents; sariyaa exact-aa extract aana fields-oda share.
- **Safety:** assistant refuse panna vendiya 200 prompts, udhaaranamaa innoru customer-oda account details kekkura requests.
- **Bar:** endha task-um adhoda thani adapter-a vida 2 points-ku mela keezha pogakoodaadhu (replies-ku 0.2), refusals kuraiyakoodaadhu.

Avanga thani dev sets-la tune panni, appuram test sets-a run panraanga. Keezha irukkura numbers illustration-ku thaan, measure panna results illa.

| Model | PEFT setting | Complaints | Replies (5-ku) | KYC | Bar-a meet pannudhaa? |
| --- | --- | --- | --- | --- | --- |
| Thani adapters (target) | edhuvum illa | 93% | 4.3 | 96% | target |
| Moonoda average | `svd`, ovvonnukkum weights 1/3 | 89% | 4.0 | 84% | illa |
| Moonoda TIES | `ties_svd`, density 0.5, weights 1.0 | 92% | 4.2 | 88% | illa: KYC |
| TIES, KYC weight yethinadhu | mela ulla maadhiri, KYC weight 1.5 | 91% | 4.1 | 91% | illa: KYC |
| Complaints, replies-oda TIES | `ties_svd`, density 0.5 | 92% | 4.2 | n/a | aamaa |

Plain average ovvoru skill-aiyum moonula oru pangaa dilute pannudhu, adhanaala ella idathulayum fail aagudhu. TIES innum nallaa pannudhu, aanaa romba precise task-aana KYC extraction, adhu thaanga mudiyaadha conflicts-la thokkudhu. Adhoda weight-a yethinaa KYC-ku udhavudhu, aanaa matha tasks-a baadhikka aarambikkudhu.

Adhanaala team rendu files-a ship pannudhu. Letter screen, merged complaints-and-replies model-a use pannudhu, adhu oru mixed letter-a ore call-la handle pannum. Scan screen, oru document scan aagumbodhu mattum, KYC adapter-a ulla fold panna base-aana rendaavadhu model-a load pannudhu. Safety set adhe refusal count-oda pass aagudhu. Endha adapter-um train aagaadha behaviour-a kooda merging balaveenappaduthalaam-nguradhaala avanga adhai thirumba run pannaanga.

## Podhuvaa panra thappugal

- **Vera vera bases-la irundhu varra models-a merge panradhu.** Inputs ore tokenizer-aiyum chat template-aiyum share pannudhaa-nnum check pannunga. Vera vera prompt formats-a edhirpaarkkura models-a merge panna udainja replies varalaam.
- **Memory michappaduthha LoRA adapters-a merge panradhu.** Adapters chinnavai; michamaaguradhu romba konjam.
- **Average score-a vachu judge panradhu.** Oru task mosamaa drop aanaalum average-la merge sariyaa theriyalaam. Ovvoru task-aiyum adhoda sondha target kooda compare pannunga.
- **Test set-la tune panradhu.** Test set-la density-yaiyum weights-aiyum thernthedutha, real use-la varradhai vida test score nallaa theriyum. Dev set-a use pannunga.
- **LoRA adapters mela plain `linear` alladhu `ties`-a use panni exact sum-a edhirpaarkkuradhu.** Indha types A, B matrices-a thanithaniyaa serkkum. Exact sum-ku `cat`-a use pannunga; `svd_rank` ranks-oda koottuthogaikku samamaa alladhu adhukku mela irukkumbodhu mattum thaan `_svd` types exact.
- **Safety checks-a skip panradhu.** Oru 2024 study (Hammoud and others, Findings of EMNLP), merging oru model-oda balaveenamaana safety behaviour-a merged model-kulla kondu varalaam-nu kandupidichudhu.
- **Public merges-a nambuvadhu.** Download panna merge-a unga sondha data-la test pannunga.
- **Licence-a marakkuradhu.** Oru merge adhula irukkura ovvoru model-oda terms-aiyum follow pannanum. Oru non-commercial input, merge-a neenga eppadi use pannalaam-nu limit pannalaam, adhanaala ovvoru licence-aiyum padinga. Sila licences naming rules-aiyum serkkum: Llama 3.1-oda licence, adhula irundhu build panni share panra model-oda per "Llama"-la aarambikkanum-nu kekkudhu.

## Eppo merge pannakoodaadhu

Indha kelvigalai varisaiyaa kelunga:

1. **Adapters-a thanithaniyaa serve panna mudiyumaa?** LoRA adapters-ku idhu podhuvaa best choice. vLLM maadhiri servers ore base model-a GPU memory-la vachukittu, ovvoru request-kum vera adapter-a apply pannum, ore batch-la kooda. Udhaaranamaa: `vllm serve base-model-id --enable-lora --lora-modules complaints=./adapters/complaints replies=./adapters/replies --max-loras 4`. Ovvoru request-um adhoda adapter-a name pannum. Runtime-aala idhai panna mudiyaadhappo, alladhu oru request-ku ore nerathula pala skills thevaippadumbodhu thaan mukkiyamaa LoRA adapters-a merge pannunga.
2. **Oru task romba precise-aa?** Extraction, maths, strict formats perumbaalum merge-la thokkum. Adhai thaniyaa vachukkonga.
3. **Oru multi-task fine-tune panna ungalaala mudiyumaa?** Ovvoru task-kum data irundhaa, mix-la train panradhu perumbaalum merge-a vida nalladhu, yenna model tasks-a balance panna kathukkum.
4. **Models vera vera bases-la irundhu varudhaa?** Merge pannaadheenga.

## Demo-la irundhu production-ku

- **Merges-a models maadhiriye version pannunga.** Config file, input model versions, scores, test set versions ellaathaiyum onnaa vachukkonga.
- **Thani models-a vachukkonga**, fallback-aavum comparison point-aavum.
- **Ovvoru task-aiyum, koodave general, safety checks-aiyum test pannunga**, ovvoru release-ku munnaadiyum, neenga munnaadiye fix panna bar-oda.
- **Endha input maarinaalum re-merge panni re-test pannunga.** Pudhu adapter version-na pudhu merge.
- **Ovvoru input-oda licence-aiyum record pannunga**, merged model-oda card-la.

## Practice pannunga

1. Hugging Face-la oru merged model-a kandupidichu adhoda card-a padinga. Endha models, endha method, endha settings use pannaanga? mergekit config serkkappattirukkaa?
2. Mela irukkura browser example-a run pannunga. Task B-oda weight 0-a -0.85-la irundhu -0.95-ku maathi, run panradhukku munnaadi TIES-oda output-a predict pannunga. Appuram density 0.2, 0.8-a try pannunga.
3. Ore base mela irukkura rendu chinna LoRA adapters-a, `svd` vachu weights 0.5, 0.5-la (oru average) merge pannunga, `ties_svd` vachu moonu densities-layum merge pannunga. Ovvonnaiyum oru task-ku 20 examples-la score panni, endha setting-a ship pannuveenga, yen-nu ezhudhunga.
4. Unga sondha field-la oru merge-ku test plan ezhudhunga: tasks, test sets, safety checks, acceptance bar.

Innum aazhamaa therinjukka, Chip Huyen-oda *AI Engineering* (O'Reilly, 2025) chapter 7 model merging-aiyum multi-task fine-tuning-aiyum cover pannudhu.

**Mudinjadhu-nnu eppo sollalaam:** merging-a ensembling koodavum multi-adapter serving koodavum compare panni explain panna mudiyum, TIES-um DARE-um enna pannudhu, adhukku enna vilai-nnu vivarikka mudiyum, oru merge method-a thernthedutthu tune panna mudiyum, oru merged model-a eppadi test panradhu-nnu plan panna mudiyum.
