## Idhu enna

Moonu numbers oru language model evvalavu periya, adhukku evvalavu pottu irukkaanga-nu solludhu.

1. **Parameters**: training maathura model-kulla irukkura numbers. "Llama 3 8B"-la sumaar 8 billion irukku. Adhiga parameters model-ku kathukka adhiga capacity tharum, odradhukku adhiga memory, compute thevai.
2. **Training tokens**: adhu evvalavu text-la irundhu kathukkichu. Meta-oda Llama models 1.4 trillion tokens (Llama 1)-la irundhu 2 trillion (Llama 2)-ku, apram sumaar 15 trillion (Llama 3)-ku pochu.
3. **Training compute**: training evvalavu arithmetic operations edukkuchu, FLOPs (floating-point operations)-la measure panna. Oru common estimate **6 × parameters × training tokens**.

**Scaling law** experiments-la irundhu, indha ellaam valarum podhu quality eppadi improve aagudhu-nu solludhu. Aachariyamaana kandupidippu, improvement smooth-aa, predictable-aa irukku, adhanaala labs sinna models-a train panni, oru curve fit panni, pala madangu periya model eppadi pannum-nu panam selavu pannradhukku munnaadiyae forecast pannalaam.

```flow
title: Oru model evvalavu nalla-nu edhu mudivu pannudhu
Compute budget -> Model size | parameters
Compute budget -> Training data | tokens, quality, variety
Model size -> Quality
Training data -> Quality
Model size -> Running cost | memory, oru token-ku speed
Quality -> Unga bar-a meet panra sinna model-a choose pannunga
Running cost -> Unga bar-a meet panra sinna model-a choose pannunga
```

## Idhu eppadi work aagudhu

**Size-um memory-yum.** Oru model-a oda, adhoda weights GPU memory-la fit aaganum: parameters times bytes per parameter. 16-bit precision (2 bytes)-la, 7B model-ku sumaar 14 GB, 70B-ku sumaar 140 GB, KV cache-um matha overhead-um illaama. GPU lesson sonna maadhiri, 8 illa 4 bits-ku quantisation idha kammi pannum.

**Dense-um sparse-um.** Dense model-la ovvoru token-kum ovvoru parameter-um use aagum. **Mixture-of-experts** (MoE) model layers-a "experts"-aa pirichchu, oru sinna router ovvoru token-kum konjam experts-a pick pannum. Mixtral 8x7B-la mothama 46.7 billion parameters irukku, aana ovvoru token-kum sumaar 12.9 billion mattum active, adhanaala adhu 13B model-oda cost, speed-la odum, aana adhiga knowledge vachirukkum. Ella experts-aiyum vachirukka memory innum thevai.

**Chinchilla rule.** 2022-la DeepMind vera vera sizes-la, vera vera alavu data-la 400-ku mela models-a train panni kettaanga: oru fixed compute budget-ku, size-yum data-vum entha mix nalla model tharum? Badhil: sumaar **oru parameter-ku 20 training tokens**, rendaiyum serthu valarthunga. Munnaadi irundha neraya periya models undertrained: GPT-3-ku 175 billion parameters irundhuchu, aana 300 billion training tokens mattum, oru parameter-ku 2-ku kammi. DeepMind-oda 70-billion-parameter Chinchilla, 1.4 trillion tokens-la train aagi, romba periya models-a thorkadichuchu.

**Chinchilla-ku appaal.** Indha rule *training* cost-a optimise pannum. Aana oru popular model millions thadavai *use* aagum, sinna model odradhukku cheaper. Adhanaala labs ippo sinna models-a parameter-ku 20 tokens-a vida romba adhigama train pannuraanga: Llama 3 8B sumaar 15 trillion tokens paathuchu, oru parameter-ku sumaar 1,900. Training adhiga selavu, aana ovvoru user-oda request-um kammi selavu, adhiga data-oda quality valarndhukittae irukku.

**Diminishing returns.** Quality oru power law follow pannum, adhanaala ovvoru step-um munnaadi-yoda vida adhigam selavu. Language modelling-la, training loss-a sumaar 3.4-la irundhu 2.8-ku kuraikka sumaar pathu madangu adhiga data thevai. Oru task-la 90%-la irundhu 95%-ku pogradhu, 60%-la irundhu 90%-ku pogradha vida romba adhigam selavaagalaam.

**Bottlenecks.** Rendu limits varudhu: nalla public text theerndhukittu irukku, ennanna training sets pudhu ezhuthaiya vida vegamaa valarudhu, training runs-ku romba electricity thevai. Synthetic data, nalla data selection, innum efficient models-la aarvam irukkradhukku idhu oru reason.

Planning-ku oru quick calculator:

```python
def weights_gb(params_billion, bytes_per_param=2):
    return params_billion * bytes_per_param           # 1B params x 2 bytes = 2 GB

def training_gpu_hours(params, tokens, gpu_flops=312e12, utilisation=0.4):
    flops = 6 * params * tokens                       # common estimate
    return flops / (gpu_flops * utilisation) / 3600

print(weights_gb(8))                                  # 16 GB at 16-bit
print(round(training_gpu_hours(1e9, 20e9)))           # 1B model, 20B tokens: about 267 GPU-hours
print(round(training_gpu_hours(8e9, 15e12)))          # 8B model, 15T tokens: about 1.6 million GPU-hours
```

Inga GPU speed oru high-end data-centre GPU-oda 16-bit precision-la peak; nijamaana utilisation perumbaalum 30% la irundhu 50%.

| Model | Parameters | Training tokens | Parameter-ku tokens |
| --- | --- | --- | --- |
| GPT-3 (2020) | 175 billion | 300 billion | 1.7 |
| Chinchilla (2022) | 70 billion | 1.4 trillion | 20 |
| Llama 2 70B (2023) | 70 billion | 2 trillion | 29 |
| Llama 3 8B (2024) | 8 billion | sumaar 15 trillion | sumaar 1,900 |

## Oru worked example

Bengaluru-la oru startup Kannada-la nallaa ezhudhura oru model-a virumbudhu. Oru founder 1-billion-parameter model-a avanga own Kannada text-la scratch-la pre-train panna solraanga.

Avanga kanakku pannraanga:

1. **Thevaiyaana data.** 1B parameters-ku Chinchilla sumaar 20 billion tokens suggest pannum. Avangakitta sumaar 3 billion tokens nalla Kannada text irukku, oru typical web crawl-la Kannada sumaar 0.01% thaan.
2. **Compute.** 6 × 1 billion × 20 billion = 1.2 × 10²⁰ operations, oru high-end GPU-la sumaar 270 manineram, illa ettu GPUs-la oru naal-um paadhi. Afford panna mudiyum.
3. **Nijamaana limit data.** 3 billion tokens-a pala thadavai repeat panni train panradhu, pudhu data-vai vida kammiyaa kathukkum, 1B model-ku general knowledge-ae illaama aarambikkum.

200 nijamaana Kannada writing tasks-la moonu plans-a compare pannaanga:

| Plan | Quality score (10-la, native reviewers) | Build cost | 1,000 replies-ku run cost |
| --- | --- | --- | --- |
| Scratch-la pre-train panna 1B model | 4.1 | Adhigam: data velai plus compute | Romba kammi |
| 8B open model, appadiyae use panradhu | 6.2 | Illa | Kammi |
| 8B open model, avanga Kannada text-la continued training | 7.6 | Naduthara | Kammi |

Numbers oru illustration-kaaga. Compute eppavum bottleneck illa; data-vum, irukkura model-oda mundhaya aarambamum thaan. Avanga open model-oda continued training-a choose pannuraanga.

## Podhuvaa panra thappugal

- **Generations-kku idaiyila parameter counts-a compare panradhu.** Oru pudhu 8B model pazhaya 70B-a thorkadikkalaam.
- **MoE models-ku total parameters-a mattum ennuradhu.** Speed, cost active parameters-a follow pannum; memory total-a follow pannum.
- **Parameter counts-la irundhu GPUs size panna, KV cache-aiyum overhead-aiyum marakkradhu.**
- **Oru product model-ku Chinchilla-va goal-aa edukkradhu.** Idhu training cost-a optimise pannum; adhigam use aagura models romba neram train aagum.
- **Data quality-a ignore panradhu.** Ade ennikkai tokens nalla text-a irundhaa nalla model tharum.
- **Pothumaana data illaama scratch-la pre-train panradhu.** Oru open model-la irundhu aarambikkradhu perumbaalum romba nalladhu.

## Periyadhu nalladhu illaadha neram

- **Classification, extraction maadhiri narrow tasks** perumbaalum sinna models-laeyae bar-a meet pannum.
- **Adhiga volume**-la periya model-oda running cost thaan athigam aagum.
- **Latency budgets** sinna models-a virumbum, avai ovvoru token-aiyum vegamaa ezhudhum.
- **On-device illa private deployments**-la sinna models mattum thaan fit aagalaam.

## Demo-la irundhu production-ku

- **Velai seiyalaam-nu thonura sinna model-la aarambinga**, unga test set sonna aprom mattum mela pogunga.
- **Hardware-a total parameters, precision, KV cache-la irundhu size pannunga**, headroom-oda.
- **Model choices-a adikkadi thirumba paarunga.** Pudhu sinna models gap-a moodikkittae irukku.
- **Entha training project-kum compute-ku munnaadi data-va plan pannunga**, unga kitta nijamaa evvalavu useful data irukku-nu measure pannunga.
