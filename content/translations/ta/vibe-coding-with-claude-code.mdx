## இது என்ன

**Vibe coding**-னா பெரும்பாலான code-ஐ நீங்களே type பண்றதுக்கு பதிலா, என்ன வேணும்னு ஒரு AI coding agent-கிட்ட விவரிச்சு, அது பண்றதை வழி நடத்தி, check பண்ணி software build பண்றது. இந்த வார்த்தை 2025-ல பிரபலமாச்சு, இப்போ நிறைய founders, product managers, analysts, students தங்களோட முதல் tools-ஐ இப்படித்தான் build பண்றாங்க.

**Claude Code** Anthropic-ஓட coding agent. Code-ஐ மட்டும் suggest பண்ற chatbot மாதிரி இல்லாம, இது உங்க project-க்குள்ளயே வேலை செய்யும்: files-ஐ படிக்கும், எழுதும், edit பண்ணும், tests, builds மாதிரி commands run பண்ணும், errors-ஐ பார்த்து மறுபடி try பண்ணும். இதை terminal-ல, VS Code அல்லது JetBrains-க்குள்ள, Claude desktop app-ல, அல்லது claude.ai-ல browser-ல use பண்ணலாம்.

Skill-ங்குறது prompts type பண்றது இல்ல. ஒரு நல்ல engineering lead புது team member-ஓட use பண்ற அதே skill தான்: goal-ஐ தெளிவா சொல்லணும், வேலையை steps-ஆ பிரிக்கணும், திரும்ப வர்றதை review பண்ணணும், என்ன மாத்தணும்னு சொல்லணும்.

```flow
title: சின்ன steps-ல திரும்ப திரும்ப பண்ணுங்க; ஒவ்வொரு working step-க்கு அப்புறமும் commit பண்ணுங்க
நீங்க: ஒரு idea, ஒரு spec -> Claude Code plan பண்ணும்
Claude Code plan பண்ணும் -[நீங்க approve பண்ணுவீங்க]-> Claude Code files-ஐ edit பண்ணும்
Claude Code files-ஐ edit பண்ணும் -> Claude Code tests-ஐயும் app-ஐயும் run பண்ணும்
Claude Code tests-ஐயும் app-ஐயும் run பண்ணும் -> Changes, errors, output-ஓட summary
Changes, errors, output-ஓட summary -> நீங்க diff-ஐ review பண்ணி, try பண்ணி, feedback கொடுப்பீங்க
நீங்க diff-ஐ review பண்ணி, try பண்ணி, feedback கொடுப்பீங்க -> நீங்க: ஒரு idea, ஒரு spec
```

## இது எப்படி work ஆகுது

**1. Set up.** Official docs-ல இருந்து Claude Code-ஐ install பண்ணுங்க, ஒரு காலி folder-ல terminal திறந்து `claude` run பண்ணுங்க. அதுக்கு ஒரு Claude subscription அல்லது API account வேணும். Folder-ஐ ஒரு git repository ஆக்குங்க; அப்போ ஒவ்வொரு change-ஐயும் பார்க்கவும் undo பண்ணவும் முடியும்.

**2. ஒரு சின்ன spec எழுதுங்க.** எந்த code-க்கும் முன்னாடி அரை page எழுதுங்க: app என்ன பண்ணும், யாரு use பண்ணுவாங்க, முக்கியமான மூணு முதல் அஞ்சு features, phone-ல எப்படி தெரியணும், எது scope-க்கு வெளியில. Claude-ஐ அதை படிச்சு உங்ககிட்ட கேள்விகள் கேக்க சொல்லுங்க. இந்த ஒரு பழக்கமே பெரும்பாலான bad results-ஐ நீக்கிடும்.

**3. CLAUDE.md-ஆல அதுக்கு memory கொடுங்க.** ஒவ்வொரு session ஆரம்பத்துலயும் Claude `CLAUDE.md`-ஐ படிக்கும். Stack, app-ஐ எப்படி run, test பண்றது, உங்க rules எல்லாம் அதுல போடுங்க: "mobile first", "no paid APIs", "never commit secrets" மாதிரி. முதல் version-ஐ `/init` வச்சு Claude-ஐயே எழுத சொல்லலாம்.

**4. Plan பண்ணுங்க, அப்புறம் சின்ன steps-ல build பண்ணுங்க.** முதல்ல ஒரு plan கேளுங்க (Claude Code-ல plan mode இருக்கு; அது படிச்சு propose மட்டும் பண்ணும்). Approve பண்ணுங்க அல்லது திருத்துங்க. அப்புறம் ஒரு நேரத்துல ஒரு feature build பண்ணுங்க: layout, அப்புறம் data, அப்புறம் calculations, அப்புறம் saving, அப்புறம் deployment.

**5. ஒவ்வொரு change-ஐயும் review பண்ணுங்க.** Summary-ஐ படிங்க, diff-ஐ skim பண்ணுங்க. App-ஐ நீங்களே run பண்ணி பாருங்க. ஏதாவது வித்தியாசமா தெரிஞ்சா "ஏன் இப்படி பண்ணே?"ன்னு கேளுங்க. ஒரு step work ஆனதும் commit பண்ணுங்க.

**6. Test பண்ணி fix பண்ண விடுங்க.** முக்கியமான logic-க்கு tests எழுதி run பண்ண Claude-கிட்ட சொல்லுங்க. ஏதாவது உடைஞ்சா, error-ஐ paste பண்ணுங்க அல்லது exact steps-ஐ விவரிங்க; evidence இருந்தா bug-ஐ trace பண்றதுல அது ரொம்ப நல்லது.

| Stage | என்ன சொல்லணும் | என்ன check பண்ணணும் |
|---|---|---|
| Spec | "Read SPEC.md and ask me anything unclear" | அதோட கேள்விகள் அதுக்கு புரிஞ்சதுன்னு காட்டும் |
| Plan | "Plan the first feature; don't write code yet" | எந்த files-ல மாத்துது, approach என்ன, தேவையில்லாதது எதுவும் இல்லை |
| Build | "Implement step 1 of the plan" | Run ஆகுது; diff சின்னதா, படிக்க easy-ஆ இருக்கு |
| Test | "Add tests for the split calculation and run them" | Tests happy path மட்டுமில்ல, edge cases-ஐயும் cover பண்ணுது |
| Fix | "On 360 px wide the table overflows. Fix it" | Fix, அதோட வேற எதுவும் நகரல |
| Ship | "Set up deployment to Vercel and explain the steps" | Code-ல secrets இல்ல; environment variables use ஆகுது |

## ஒரு worked example

Nisha Pune-ல மூணு friends-ஓட ஒரு flat-ஐ share பண்றாங்க, WhatsApp chat-ல bills-ஐ பிரிக்கிறது அவங்களுக்கு அலுத்துப்போச்சு. அவங்க ஒரு product designer, developer இல்ல.

அவங்க `SPEC.md` எழுதுறாங்க: "ஒரு one-page web app. யார் pay பண்ணாங்க, யார் share பண்றாங்கன்னு ஒரு bill சேர்க்கணும். யார் யாருக்கு எவ்வளவு தரணும்னு, குறைஞ்ச payments-ல settle ஆகுற மாதிரி காட்டணும். Phone-ல வேலை செய்யணும். Browser-ல save ஆகணும்; login வேண்டாம். Rupees." புது folder-ல `claude` run பண்ணி, spec-ஐ படிச்சு கேள்விகள் கேக்க சொல்றாங்க. Bills-ஐ சமமில்லாம பிரிக்க முடியுமான்னும், payments-க்கு UPI link வேணுமான்னும் Claude கேக்குது. சமமில்லாத splits அப்புறம், UPI links வேணும்னு சொல்றாங்க.

Plan கேக்குறாங்க, இது கிடைக்குது: ஒரு Next.js app, ஒரு form, bills-ஓட list, ஒரு settlement function, local storage, settlement maths-க்கு tests. முதல் step-ஐ மட்டும் approve பண்றாங்க: page-உம் form-உம். அது run ஆகுது. Commit பண்றாங்க.

மூணாவது step settlement maths. Tests-ஐ முதல்ல எழுத சொல்றாங்க, தனக்கு பதில் தெரிஞ்ச ஒரு case-ஓட: மூணு friends, ஒருத்தர் groceries-க்கு ₹3,000 கொடுத்தாங்க. Rounding காரணமா ₹1 கணக்குல வராம போறதால ஒரு test fail ஆகுது. காரணத்தை Claude explain பண்ணி, மீதியை pay பண்ணவங்களுக்கு கொடுத்து fix பண்ணுது. இதை அவங்க கண்ணால பார்த்து கண்டுபிடிச்சிருக்கவே மாட்டாங்க.

சாயங்காலம் Vercel-ல deployment set up பண்ண Claude-கிட்ட கேக்குறாங்க. மறுநாள் காலையிலயே flatmates app-ஐ use பண்றாங்க. மொத்த நேரம்: சுமார் அஞ்சு மணி நேரம், அதுல பெரும்பகுதி தனக்கு என்ன வேணும்னு முடிவு பண்றதுலயே போச்சு.

## பொதுவா பண்ற தப்புகள்

**ஒரே message-ல முழு app-ஐயும் கேக்குறது.** Test பண்ணாத பெரிய குழப்பம் தான் கிடைக்கும். ஒரு நேரத்துல ஒரு feature கேளுங்க.

**Spec-ஐ skip பண்றது.** இல்லன்னா Claude guess பண்ணும், அதுமேல அது build பண்ணின பிறகுதான் தப்பான guess-ஐ கவனிப்பீங்க.

**புரியாத changes-ஐ accept பண்றது.** Explanation கேளுங்க. Code-க்கும், அதோட bugs-க்கும், security-க்கும் நீங்க தான் owner.

**git இல்லாம இருக்குறது.** Commits இல்லன்னா என்ன மாறுச்சுன்னு பார்க்கவும், திரும்ப போகவும் முடியாது. ஒவ்வொரு working step-க்கு அப்புறமும் commit பண்ணுங்க.

**API keys-ஐ code-ல போடுறது.** Secrets-ஐ environment variables-லயும், git ignore பண்ற `.env` file-லயும் வைங்க. Push பண்றதுக்கு முன்னாடி secrets இருக்கான்னு check பண்ண Claude-கிட்ட சொல்லுங்க.

**முடிவில்லாத "fix it" loops.** அதே bug மூணு முயற்சிக்கு அப்புறமும் இருந்தா, நிறுத்துங்க. Exact steps, எதிர்பார்த்த result, உண்மையான result-ஐ விவரிச்சு, எதையாவது மாத்துறதுக்கு முன்னாடி காரணத்தை explain பண்ண சொல்லுங்க.
