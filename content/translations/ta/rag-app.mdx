## இது என்ன

**RAG app** (retrieval-augmented generation) உங்க சொந்த documents-ல இருந்து கேள்விகளுக்கு பதில் சொல்லும். ஒவ்வொரு கேள்விக்கும் இது:

1. உங்க documents-ஓட index-ல இருந்து மிகவும் தொடர்புடைய passages-ஐ **retrieve** பண்ணும்;
2. அந்த passages-ஐ prompt-ல சேர்க்கும் (**augment**);
3. அந்த passages-ஐ மட்டும் use பண்ணி, அவற்றை cite பண்ணி பதிலை **generate** பண்ணும்.

Companies தங்களோட சொந்த data மேல language models-ஐ use பண்ற வழிகள்ல இதுதான் ரொம்ப பொதுவானது. ஏன்னா model training தேவையில்லை, documents மாறும்போது தானா current-ஆ இருக்கும்.

```flow
title: Ingestion: ஒரு தடவை, அப்புறம் updates வரும்போது
PDFs -> Text எடுக்கறது, OCR -> Heading வச்சு chunk பண்றது | சுமார் 400 tokens, title, section-ஓட
Heading வச்சு chunk பண்றது -> Embed பண்றது -> Index (pgvector) | metadata: doc, page, section, dates
```

```flow
title: Query நேரம்
கேள்வி -> Hybrid search | vectors + keywords -[top 20]-> Rerank
Rerank -[top 5]-> Prompt | instructions + sources-ஓட passages [1] முதல் [5] வரை + கேள்வி
Prompt -> Model -> Citations [2][4]-ஓட பதில் | அல்லது "இது எனக்கு கிடைக்கலை..."
```

இந்த lesson-ல Coimbatore-ல ஒரு college regulations, fees, exams, scholarships பத்தி students கேக்குற கேள்விகளுக்கு ஒரு assistant build பண்றதை follow பண்ணுவோம்.

## இது எப்படி work ஆகுது

**Ingestion (ஒரு தடவை, அப்புறம் updates வரும்போது).** Documents-ஐ load பண்ணுங்க, clean text எடுங்க, titles, page numbers-ஓட chunks-ஆ பிரிங்க, ஒவ்வொரு chunk-ஐயும் embed பண்ணி அதோட metadata-ஓட ஒரு index-ல store பண்ணுங்க.

**Query நேரம்.**

- கேள்வியை embed பண்ணுங்க. Top candidates-ஐ retrieve பண்ணுங்க (vector search, முடிஞ்சா keyword search-ஓட hybrid). விரும்பினா rerank பண்ணி, best அஞ்சை வச்சுக்கோங்க.
- Prompt build பண்ணுங்க: instructions, ஒவ்வொண்ணுக்கும் id, source label இருக்குற passages, அப்புறம் கேள்வி.
- Model-க்கு சொல்லுங்க: passages-ல இருந்து மட்டும் பதில் சொல்லணும்; passage ids-ஐ cite பண்ணணும்; passages-ல பதில் இல்லைன்னா அதை சொல்லணும்.
- பதிலை citations-ஓட திருப்பி கொடுங்க. அவை source documents-க்கு link ஆகணும்.

**Contextual retrieval.** Chunks-ல பெரும்பாலும் context இருக்காது ("limit 45 நாள்"). Chunk அந்த document-ல எங்க இருக்குன்னு ஒரு சின்ன description-ஐ முன்னாடி சேர்த்து, embeddings-ஐ keyword search-ஓட combine பண்ணா, retrieval failures அளக்கக்கூடிய அளவுக்கு குறையும்.

**"எனக்கு தெரியாது"ன்னு சொல்றது.** நம்பகமான RAG app-ல documents-ல பதில் இல்லைன்னா மறுக்கணும். உங்க tests-ல பதில் இல்லாத கேள்விகளையும் சேர்த்துக்கோங்க.

**Evaluation.** Expected sources, answers இருக்குற ஒரு fixed கேள்விகள் set வச்சுக்கோங்க. Retrieval-ஐ (recall at k), answers-ஐ (correctness, faithfulness) தனித்தனியா அளந்து, ஒவ்வொரு மாற்றத்துக்கு அப்புறமும் மறுபடி run பண்ணுங்க.

**Freshness, access.** மாறின documents-ஐ re-index பண்ணுங்க. Superseded ஆனதை filter பண்ணுங்க. Users-க்கு வேற வேற permissions இருந்தா, ஒவ்வொரு user-ம் பார்க்க அனுமதி இருக்குறதை வச்சு retrieval-ஐ filter பண்ணுங்க.

**ஒரு minimal query function:**

```python
def answer(question, user):
    hits = hybrid_search(question, k=20, filters={"access": user.groups})
    top = rerank(question, hits)[:5]
    passages = "\n\n".join(
        f"[{i+1}] {h.title}, section {h.section}, page {h.page}\n{h.text}"
        for i, h in enumerate(top)
    )
    prompt = (
        "Answer using only the passages. Cite like [2] after each sentence. "
        "If the passages do not answer the question, say so and name the office to contact.\n\n"
        f"Passages:\n{passages}\n\nQuestion: {question}"
    )
    return call_model(prompt), top
```

பதிலோட `top`-ஐயும் திருப்பி கொடுக்கறதால, interface ஒவ்வொரு citation-ஐயும் அதோட document, page-க்கு link பண்ண முடியும். ஒரு பதில் தப்பா போனா, என்ன retrieve ஆச்சுன்னு உங்க logs-ல பார்க்கவும் முடியும்.

**முதல்ல எதை அளக்கணும்:**

| Measure | இது என்ன கேள்விக்கு பதில் | Target |
| --- | --- | --- |
| Recall at 5 | சரியான passage retrieve ஆகுதா? | Golden set-ல 85%-க்கு மேல |
| Correctness | பதில் சரியா? | Client-ஓட சேர்ந்து ஒத்துக்கிட்டது |
| Faithfulness | ஒவ்வொரு claim-க்கும் ஒரு passage support இருக்கா? | 0.9-க்கு மேல |
| பதில் இல்லாத கேள்விகள்ல refusal rate | Documents-ல பதில் இல்லைன்னா ஒத்துக்குதா? | 75%-க்கு மேல |
| Latency | போதுமான வேகமா இருக்கா? | முதல் வார்த்தைகள் 2 seconds-குள்ள |

**தப்பான பதிலை debug பண்றது.** முதல்ல retrieve ஆன passages-ஐ பாருங்க. சரியான passage இல்லைன்னா, பிரச்சனை ingestion அல்லது retrieval-ல: parsing, chunking, filters அல்லது search. Passage இருந்தும் பதில் தப்புன்னா, பிரச்சனை prompt அல்லது model-ல. இந்த ஒரு check நிறைய guess பண்றதை மிச்சப்படுத்தும்.

**நீங்க run பண்ணக்கூடிய ஒரு சின்ன RAG app.** இது ஒரு open embedding model, keywords-க்கு BM25, அதை merge பண்ண reciprocal rank fusion, citations-ஓட பதில் சொல்ல Anthropic-ஓட API-ஐ use பண்ணுது. `sentence-transformers rank_bm25 anthropic` install பண்ணுங்க:

```python
import numpy as np
from rank_bm25 import BM25Okapi
from sentence_transformers import SentenceTransformer
import anthropic

embedder = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")   # small, English
client = anthropic.Anthropic()

def ingest(chunks):
    """chunks: list of {"id", "title", "page", "text"}."""
    texts = [f"{c['title']}. {c['text']}" for c in chunks]
    vectors = embedder.encode(texts, normalize_embeddings=True)
    bm25 = BM25Okapi([t.lower().split() for t in texts])
    return {"chunks": chunks, "vectors": vectors, "bm25": bm25}

def search(index, question, k=5, pool=20):
    q = embedder.encode([question], normalize_embeddings=True)[0]
    by_vector = np.argsort(-(index["vectors"] @ q))[:pool]
    by_keyword = np.argsort(-index["bm25"].get_scores(question.lower().split()))[:pool]
    fused = {}
    for ranking in (by_vector, by_keyword):
        for rank, i in enumerate(ranking):
            fused[int(i)] = fused.get(int(i), 0) + 1 / (60 + rank)      # reciprocal rank fusion
    best = sorted(fused, key=fused.get, reverse=True)[:k]
    return [index["chunks"][i] for i in best]

def answer(index, question):
    hits = search(index, question)
    passages = "\n\n".join(f"[{n}] {h['title']}, page {h['page']}\n{h['text']}" for n, h in enumerate(hits, 1))
    reply = client.messages.create(
        model="claude-sonnet-5-5", max_tokens=500,          # check the docs for current names
        system="Answer only from the passages. Cite like [2] after each sentence. "
               "If they do not contain the answer, say so and suggest who to ask.",
        messages=[{"role": "user", "content": f"Passages:\n{passages}\n\nQuestion: {question}"}])
    return "".join(b.text for b in reply.content if b.type == "text"), hits
```

சில ஆயிரம் chunks வரைக்கும் இது laptop-ல memory-லயே ஓடும். அதுக்கு மேல போனா, vectors-ஐ ஒரு vector database அல்லது pgvector-க்கு மாத்திட்டு, அதே functions-ஐ வச்சுக்கோங்க.

**Search பண்றதுக்கு முன்னாடி follow-ups-ஐ rewrite பண்ணுங்க.** ஒரு chat-ல "ITI students-க்கு என்ன?"ன்னு கேட்டா பயனுள்ள எதுவும் retrieve ஆகாது. Retrieval-க்கு முன்னாடி, ஒரு சின்ன, வேகமான model-கிட்ட கடைசி சில turns-ஐ வச்சு, latest message-ஐ ஒரு standalone கேள்வியா rewrite பண்ணச் சொல்லுங்க ("ITI students-க்கு fee waiver limit என்ன?"). அதை வச்சு search பண்ணுங்க. ரெண்டு versions-ஐயும் log பண்ணுங்க.

**Retrieval-ஐ சில lines-ல அளக்கலாம்.** ஒவ்வொரு golden கேள்விக்கும், எந்த chunk ids கிடைக்கணும்னு record பண்ணுங்க:

```python
def recall_at_k(index, golden, k=5):
    """golden: list of (question, set_of_correct_chunk_ids)."""
    hits = 0
    for q, correct in golden:
        found = {h["id"] for h in search(index, q, k=k)}
        hits += bool(found & correct)
    return hits / len(golden)
```

Chunking, embedding model, filters அல்லது fusion settings-ல எதை மாத்துனாலும் அதுக்கு முன்னாடியும் பின்னாடியும் இதை run பண்ணுங்க. நீங்க கையால try பண்ண மூணு கேள்விகள்ல பதில் நல்லா வந்தாலும், recall 88%-ல இருந்து 79%-க்கு விழுந்தா, அது பின்னடைவு தான்.

**Retrieval quality-ல ரெண்டு வகை.** **Context recall**: தேவையானது passages-ல இருந்துச்சா? **Context precision**: retrieve ஆனதுல எவ்வளவு உண்மையிலேயே தொடர்புடையது? Recall குறைவா இருந்தா தப்பான பதில் அல்லது "எனக்கு தெரியாது" வரும். Precision குறைவா இருந்தா tokens வீணாகும், model-ஐயும் distract பண்ணலாம்.

## ஒரு நாள், ஒரு example

Coimbatore-ல ஒரு college 25 PDFs-ல இருந்து, academic regulations, fees, exams, scholarships பத்தி students-ஓட கேள்விகளுக்கு ஒரு assistant build பண்றாங்க.

- Ingestion: page numbers-ஓட text எடுக்கப்பட்டு, headings வச்சு சுமார் 400-token chunks-ஆ பிரிக்கப்பட்டு, document title, section முன்னாடி சேர்க்கப்பட்டு, embed ஆகி pgvector-ல store ஆச்சு.
- Retrieval: hybrid search (vectors + keywords), top 20 rerank ஆகி 5 ஆச்சு.
- Prompt: "Passages-ஐ மட்டும் use பண்ணி பதில் சொல்லு. [2] மாதிரி cite பண்ணு. பதில் passages-ல இல்லைன்னா, 'college regulations-ல இது எனக்கு கிடைக்கலை'ன்னு சொல்லி, தொடர்பு கொள்ள வேண்டிய office-ஐ suggest பண்ணு."
- Interface: பதில்ல citations இருக்கும். அவை சரியான page-ல PDF-ஐ திறக்கும்.

50 கேள்விகளோட testing (பதில் இல்லாத எட்டு உட்பட): பதில் இருக்குற 42 கேள்விகள்ல 40 சரியான citations-ஓட சரியா வந்தது, பதில் இல்லாத 8-ல 6 சரியா மறுத்தது. ரெண்டு failures ஒரு scanned image-ஆ இருந்த fee circular-ல இருந்து வந்தது. ## பொதுவா பண்ற தப்புகள்

- **Citations இல்லாம இருக்கறது.** Users check பண்ண முடியாது, errors கவனிக்கப்படாம போகும்.
- **Refusal path இல்லாம இருக்கறது.** Documents-ல பதில் இல்லாதப்போ model guess பண்ணும்.
- **Retrieval evaluation-ஐ skip பண்றது.** பெரும்பாலான failures retrieval failures தான்.
- **Scanned documents, tables-ஐ கண்டுக்காம விடறது.** அவைக்கு OCR-உம் table-aware parsing-உம் வேணும்.
- **ஒரு தடவை index பண்ணிட்டு மறந்துடுறது.** Documents மாறும், re-index பண்ணுங்க.
- **Raw follow-up message-ஐ வச்சே search பண்றது.** முதல்ல அதை standalone கேள்வியா rewrite பண்ணுங்க.
- **ஒரே நேரத்துல நிறைய retrieval settings-ஐ மாத்துறது.** ஒண்ணை மாத்தி, recall-ஐ மறுபடி run பண்ணுங்க.

## RAG தேவையில்லாத நேரங்கள்

- **Documents முழுசா context-குள்ள பொருந்தும்**, அடிக்கடி மாறாது: அவற்றை prompt-ல போடுங்க, cache பண்ணி.
- **பதில் ஒரு database-ல இருக்கு**, உதாரணம் order status அல்லது கட்டின fees: text search இல்லாம ஒரு tool அல்லது query use பண்ணுங்க.
- **முழு collection மேல reasoning தேவைப்படுற கேள்விகள்**, உதாரணம் "எந்த policies ஒண்ணுக்கொண்ணு முரண்படுது?": RAG துண்டுகளை கண்டுபிடிக்கும், overview-வை இல்லை.

## Demo-ல இருந்து production-க்கு

- Expected chunks, answers இருக்குற **golden set-ஐ வச்சுக்கோங்க**. ஒவ்வொரு மாற்றத்துக்கும் recall, answer checks-ஐ run பண்ணுங்க.
- ஒவ்வொரு பதிலோடயும் **rewrite பண்ண query, retrieve ஆன ids, scores-ஐ log பண்ணுங்க**.
- **Document மாறும்போது re-index பண்ணுங்க**, superseded versions-ஐ நீக்குங்க.
- Ranking-க்கு முன்னாடியே **permissions வச்சு filter பண்ணுங்க**. Model text-ஐ பார்த்ததுக்கு அப்புறம் இல்லை.
- **Topic வாரியா "எனக்கு தெரியாது" rate-ஐ track பண்ணுங்க.** Missing documents எங்கன்னு அது காட்டும்.
