## இது என்ன

**Sorting**-னா items-ஐ order-ல வைக்கிறது. Data sorted ஆனதும் நிறைய கேள்விகள் சுலபமாயிடும்: duplicates பக்கத்துல பக்கத்துல இருக்கும், சின்னதும் பெருசும் முனைகள்ல இருக்கும், எதையும் சீக்கிரம் கண்டுபிடிக்கலாம்.

**Binary search** sorted data-ல நடுவுல இருக்கிறதை பார்த்து, அது இருக்க முடியாத பாதியை தூக்கிப் போடும். ஒவ்வொரு step-உம் மீதமுள்ளதை பாதியாக்குறதால, சுமார் log₂ n steps போதும்: 10 லட்சம் items-க்கு 20.

**Two pointers** ஒரு array-ல ரெண்டு positions-ஐ நகர்த்தும், பெரும்பாலும் ரெண்டு முனையில இருந்தோ, ஒண்ணு இன்னொண்ணுக்கு பின்னாடியோ. Nested loops இல்லாம, pair, range problems-ஐ ஒரே pass-ல solve பண்ண. **Sliding window** சிறந்த contiguous stretch-ஐ கண்டுபிடிக்கிற two-pointer pattern.


## இது எப்படி work ஆகுது

**Sorting algorithms** வேகத்துலயும் behaviour-லயும் வித்தியாசப்படும்:

| Algorithm | Average time | Extra space | குறிப்புகள் |
|---|---|---|---|
| Bubble / insertion sort | O(n²) | O(1) | simple; insertion sort கிட்டத்தட்ட sorted data-ல வேகம் |
| Merge sort | O(n log n) | O(n) | பாதி பாதியா பிரிச்சு, sorted halves-ஐ merge பண்ணும்; stable |
| Quicksort | O(n log n), worst O(n²) | O(log n) | ஒரு pivot-ஐ எடுத்து partition பண்ணும்; practice-ல வேகம் |
| Heap sort | O(n log n) | O(1) | heap use பண்ணும்; stable இல்ல |
| Timsort (Python-ஓட `sorted`) | O(n log n) | O(n) | merge sort + insertion sort; real data-ல ரொம்ப வேகம் |

Practice-ல built-in sort-ஐ call பண்ணுவீங்க. ஆனா comparison sorting average-ல O(n log n)-ஐ தாண்ட முடியாதுன்னு தெரிஞ்சிருக்கணும், interview-ல merge sort அல்லது quicksort-ஐ explain பண்ணவும் தெரியணும்.

**Binary search** `lo`-ல இருந்து `hi` வரை ஒரு range-ஐ வச்சிருக்கும். நடுவுல இருக்கிறதை பார்க்கும்; target பெருசுன்னா `lo`-ஐ நடுவுக்கு அப்புறம் நகர்த்தும்; சின்னதுன்னா `hi`-ஐ நடுவுக்கு முன்னாடி நகர்த்தும். Target கிடைச்சா அல்லது range காலியானா நிக்கும். இதே idea எந்த **monotonic** yes/no கேள்விக்கும் work ஆகும், உதாரணம்: "day d-க்குள்ள cumulative sales target-ஐ எட்டிடுச்சா?" இதுக்கு **binary search on the answer**-ன்னு பேரு.

**Two pointers** sorted order-ஐ use பண்ணும். Target-க்கு sum ஆகுற pair-ஐ கண்டுபிடிக்க, ரெண்டு முனையிலயும் ஆரம்பிங்க: sum ரொம்ப சின்னதுன்னா, அதை கூட்ட left pointer-ஐ வலது பக்கம் நகர்த்துங்க; ரொம்ப பெருசுன்னா right pointer-ஐ இடது பக்கம் நகர்த்துங்க. ஒவ்வொரு நகர்வும் நிறைய pairs-ஐ ஒரே நேரத்துல நீக்கிடும், அதனால O(n).

**Sliding window**-ல ஒரு left edge-உம் right edge-உம் இருக்கும். Window-ஐ வளர்க்க right edge-ஐ நகர்த்துங்க; அது ஒரு rule-ஐ மீறினா (உதாரணம் budget-ஐ தாண்டினா), சுருக்க left edge-ஐ நகர்த்துங்க. போகப் போக best window-ஐ track பண்ணுங்க.

**Interviews-ல** clues-ஐ கவனிங்க. "Sorted array", "முதல் அல்லது கடைசி position-ஐ கண்டுபிடி", "வேலை செய்யுற minimum value" இதெல்லாம் binary search-ஐ காட்டும். Sorted data-ல "pair", "triplet", "sum உள்ள subarray" இதெல்லாம் two pointers-ஐ காட்டும். "நீளமான அல்லது குறுகிய contiguous stretch" sliding window-ஐ காட்டும். Code எழுதுறதுக்கு முன்னாடி pattern-ஐ சத்தமா சொல்லுங்க; நீங்க எப்படி யோசிக்கிறீங்கன்னு interviewer-க்கு அது காட்டும்.

## ஒரு worked example

Sneha, Hyderabad-ல ஒரு online coaching platform-க்கு analytics பார்க்குறாங்க. அவங்ககிட்ட ஒரு வருஷத்தோட தினசரி ads spend இருக்கு, ஒரு மாசாந்திர budget கேள்வியும்: மொத்த ad spend ₹1 லட்சத்துக்குள்ள இருந்த தொடர்ச்சியான நாட்கள்ல மிக நீளமான run எது?

ஒவ்வொரு start, end நாளையும் try பண்ணா O(n²). Sliding window ஒரே pass-ல பண்ணும்:

```python
def longest_within(spend, budget):
    best = total = left = 0
    for right, amount in enumerate(spend):
        total += amount                   # grow the window
        while total > budget:             # shrink until within budget
            total -= spend[left]
            left += 1
        best = max(best, right - left + 1)
    return best
```

ஒவ்வொரு நாளும் window-க்குள்ள ஒரு தடவை வரும், அதிகபட்சம் ஒரு தடவை வெளிய போகும், அதனால O(n).

அடுத்து finance கேக்குது: எந்த நாள்ல cumulative sign-ups முதல் தடவை 50,000-ஐ எட்டுச்சு? Cumulative totals ஏறிக்கிட்டே தான் போகும், அதனால "d நாளுக்குள்ள எட்டிடுச்சா?"ங்குற கேள்வி false, false, ..., அப்புறம் அதுக்கு பின்னாடி எல்லா நாளுக்கும் true. இது monotonic, அதனால அவங்க answer-ஐ binary search பண்றாங்க:

```python
from itertools import accumulate

def first_day_reaching(daily, target):
    totals = list(accumulate(daily))
    lo, hi = 0, len(totals) - 1
    answer = -1
    while lo <= hi:
        mid = (lo + hi) // 2
        if totals[mid] >= target:
            answer, hi = mid, mid - 1     # works; look for an earlier day
        else:
            lo = mid + 1
    return answer
```

ஒரு வருஷ data-க்கு இது சுமார் 9 checks, 365 வரை போறதுக்கு பதிலா. 10 வருஷ hourly data-க்கு சுமார் 17 checks, கிட்டத்தட்ட 90,000-க்கு பதிலா. Python-ஓட `bisect` module இதே விஷயத்தை ஒரே call-ல பண்ணும்: `bisect.bisect_left(totals, target)`.

## பொதுவான தவறுகள்

**Unsorted data-ல binary search.** அது சத்தமில்லாம தப்பான answers கொடுக்கும். முதல்ல sort பண்ணுங்க, இல்லன்னா yes/no கேள்வி monotonic-ஆ இருக்கான்னு பாருங்க.

**Off-by-one bounds.** Inclusive, exclusive `hi`-ஐ கலக்குறது, அல்லது `lo = mid + 1`-க்கு பதிலா `lo = mid` எழுதுறது infinite loops-ஐ உண்டாக்கும். ஒரு convention-ஐ தேர்ந்தெடுத்து, நீளம் 0, 1, 2 இருக்குற lists-ல test பண்ணுங்க.

**Real வேலைக்கு சொந்த sort எழுதுறது.** Built-in sorts நல்லா test ஆனவை, வேகமானவை. கத்துக்க மட்டும், அல்லது interview-ல கேட்டா மட்டும் சொந்தமா எழுதுங்க.

**Loop-க்குள்ள மறுபடி sort பண்றது.** Loop-க்கு வெளியே ஒரு தடவை sort பண்ணுங்க. உள்ளே பண்ணா O(n log n) வேலை n தடவை நடக்கும்.

**Unsorted data-ல pair sums-க்கு two pointers.** இந்த method order-ஐ நம்பியிருக்கு. Sort பண்ணாம இருந்தா, hash map use பண்ணுங்க.

**Window-ஐ while-க்கு பதிலா if வச்சு சுருக்குறது.** Rule-குள்ள திரும்பி வர ஒரு step போதாம இருக்கலாம். Rule மீறப்பட்டிருக்கிற வரை சுருக்கிட்டே இருங்க.

1. Watch & learn panel-ல இருக்குற video lessons-ஐ பாருங்க, அவை sorting, binary search-ஐ visual-ஆ காட்டும்.
2. மேல இருக்குற exercise-ஐ பண்ணுங்க.
