## இது என்ன

**Sorting**-னா items-ஐ order-ல வைக்கிறது. Data sort ஆனதும், duplicates பக்கத்து பக்கத்துல இருக்கும், extremes முனைகள்ல இருக்கும், எதையும் சீக்கிரம் கண்டுபிடிக்கலாம்.

**Binary search** sorted data-ல ஒரு item-ஐ கண்டுபிடிக்க நடுவுல check பண்ணி, அந்த item இருக்க முடியாத பாதியை தூக்கிப் போடும். ஒவ்வொரு check-உம் மீதி இருக்குறதை பாதியாக்கும், அதனால சுமார் log₂ n checks போதும்: 10 லட்சம் items-க்கு 20, 1 கோடிக்கு 24. இன்னும் பொதுவா சொன்னா, ஒரு yes/no test "no"-ல இருந்து "yes"-க்கு எங்க flip ஆகுதுன்னு இது கண்டுபிடிக்கும், உதாரணமா "`a[i]` குறைஞ்சது x-ஆ?". Possible answers-ஓட ஒரு range-ஐ இப்படி search பண்றது தான் **binary search on the answer**.

**Two pointers** ஒரு array வழியா ரெண்டு positions-ஐ நகர்த்தி, nested loops-க்கு பதிலா ஒரே pass-ல pair, range problems-ஐ solve பண்ணும். **Sliding window**-னா best contiguous stretch-க்கான two-pointer pattern.

அப்புறம் காட்டப்போற `first_at_least` code வச்சு 42-க்கு binary search (`lo = 0`, `hi = 10`-ல ஆரம்பிச்சு):

```flow
dir: LR
title: [3 8 15 21 27 33 42 50 61 77]-ல 42-க்கு binary search
Check 1: index 5-ல 33 -[42-ஐ விட சின்னது: வலது பக்கம் போ]-> Check 2: index 8-ல 61
Check 2: index 8-ல 61 -[சின்னது இல்ல: வச்சுக்கோ, இடது பக்கம் போ]-> Check 3: index 7-ல 50
Check 3: index 7-ல 50 -[சின்னது இல்ல: வச்சுக்கோ, இடது பக்கம் போ]-> Check 4: index 6-ல 42
Check 4: index 6-ல 42 -[சின்னது இல்ல: lo-வும் hi-யும் சந்திக்குது]-> Answer: index 6
```

நாலு checks; இடது பக்கத்துல இருந்து scan பண்ணா ஏழு checks வேணும்.

56 sum வர்ற ஒரு pair-ஐ two pointers தேடுது:

```flow
dir: LR
title: Two pointers: sorted [5 12 18 25 30 38 45]-ல sum 56 வர்ற pair
L 5-ல, R 45-ல: sum 50 -[ரொம்ப சின்னது: L-ஐ வலது பக்கம் நகர்த்து]-> L 12-ல, R 45-ல: sum 57
L 12-ல, R 45-ல: sum 57 -[ரொம்ப பெருசு: R-ஐ இடது பக்கம் நகர்த்து]-> L 12-ல, R 38-ல: sum 50
L 12-ல, R 38-ல: sum 50 -[ரொம்ப சின்னது: L-ஐ வலது பக்கம் நகர்த்து]-> L 18-ல, R 38-ல: sum 56, கிடைச்சுது
```

எல்லா 21 pairs-ஐயும் பார்க்குறதுக்கு பதிலா நாலு steps.

## இது எப்படி work ஆகுது

### Sorting algorithms-உம் அவற்றோட cost-உம்

| Algorithm | Average time | Worst time | Extra space | Stable-ஆ? | எப்போ இது சரியான choice |
|---|---|---|---|---|---|
| Insertion sort (bubble sort-உம்) | O(n²) | O(n²) | O(1) | ஆமா | ரொம்ப சின்ன அல்லது கிட்டத்தட்ட sorted lists; அங்க insertion sort O(n)-க்கு கிட்ட இருக்கும் |
| Merge sort | O(n log n) | O(n log n) | O(n) | ஆமா | predictable time; linked lists; memory-க்கு ரொம்ப பெருசான files |
| Quicksort | O(n log n) | O(n²) | O(log n) | இல்ல | memory-ல வேகம், random அல்லது median-of-three pivot-ஓட |
| Heap sort | O(n log n) | O(n log n) | O(1) | இல்ல | extra memory இல்லாம ஒரு guaranteed bound |
| Python-ஓட `sorted`, `list.sort` | O(n log n) | O(n log n) | O(n) வரை | ஆமா | real data, அதுல அடிக்கடி ஏற்கனவே order-ல இருக்குற runs இருக்கும் |
| Counting sort (radix sort இதை வச்சு build ஆகுது) | O(n + k) | O(n + k) | O(n + k) | ஆமா | சின்ன range k இருக்குற integer keys, 100-க்கு marks மாதிரி |

**Merge sort** ஒவ்வொரு piece-லயும் ஒரு item வர்ற வரைக்கும் list-ஐ பாதி பாதியா பிரிக்கும், அப்புறம் முன்னாடி இருக்குற சின்ன item-ஐ திரும்ப திரும்ப எடுத்து sorted pieces-ஐ merge பண்ணும்: சுமார் log₂ n levels, ஒவ்வொண்ணுலயும் O(n) merging, அதனால O(n log n).

**Quicksort** ஒரு pivot-ஐ எடுத்து, சின்ன items-ஐ இடது பக்கமும் பெருசானதை வலது பக்கமும் நகர்த்தி, ஒவ்வொரு பக்கத்தையும் sort பண்ணும். சமமான splits-னா O(n log n). ஏற்கனவே sorted data-ல "எப்பவுமே முதல் item-ஐ எடு"ன்னா, ஒவ்வொரு தடவையும் n items 0, n − 1-ஆ split ஆகும், cost O(n²), அதனால real implementations ஒரு random pivot-ஐயோ median of three-ஐயோ எடுக்கும்.

**Python-ஓட sort**, பொதுவா Timsort-னு சொல்லுவாங்க, merge sort-உம் insertion sort-உம் சேர்ந்த ஒரு hybrid. ஏற்கனவே order-ல இருக்குற runs-ஐ கண்டுபிடிச்சு, சின்ன runs-ஐ insertion sort வச்சு நீட்டி, அவற்றை merge பண்ணும், அதனால ஏற்கனவே sorted-ஆ இருக்குற list-க்கு ஒரே O(n) pass தான். Python 3.11-ல இருந்து, merges-ஓட order-ஐ Powersort strategy வச்சு தேர்ந்தெடுக்குது.

**Comparison sorts ஏன் O(n log n)-ஐ beat பண்ண முடியாது.** n items n! orders-ல இருக்கலாம், sort அவற்றை பிரிச்சு அடையாளம் காணணும். ஒவ்வொரு comparison-உம் best case-ல possibilities-ஐ பாதியாக்கும், அதனால worst case-க்கு குறைஞ்சது log₂(n!) comparisons வேணும், தோராயமா n log₂ n. 10 items-க்கு 10!-னா 36,28,800, அதனால குறைஞ்சது 22 comparisons. Counting sort compare பண்ணவே பண்ணாததால இந்த limit-ல இருந்து தப்பிக்குது: 0-ல இருந்து 100 வரை இருக்குற 10 லட்சம் marks-ஐ 101 counters வச்சு ஒரே pass-ல sort பண்ணும்.

### Stability-உம் sort keys-உம்

Equal keys இருக்குற items அவற்றோட original order-ஐ வச்சுக்கிட்டா அந்த sort **stable**. Multi-key sorts-க்கு இது முக்கியம். ஒவ்வொரு city-க்குள்ளயும் dates order-ல இருக்குற மாதிரி orders-ஐ city-படி list பண்ண, முதல்ல date-படி sort பண்ணி அப்புறம் city-படி sort பண்ணலாம்: ரெண்டாவது sort stable-ஆ இருக்குறதால மட்டும் தான் ஒரே city இருக்குற items-க்குள்ள date order அப்படியே இருக்கும். Python-ல ஒரே step-ல `sorted(orders, key=lambda o: (o.city, o.date))` அதே result-ஐ தரும். `reverse=True` இருந்தா கூட Python stability-ஐ guarantee பண்ணுது; C++ `std::sort`, heap sort, ஒரு typical quicksort guarantee பண்ணாது.

### Full sort வேணுமா?

- **மிகச் சின்னது அல்லது மிகப் பெருசு மட்டும் வேணும்னா:** `min()` அல்லது `max()`, ஒரே O(n) pass.
- **1 கோடி scores-ல top 10:** `heapq.nlargest(10, scores)` 10 items இருக்குற ஒரு heap-ஐ வச்சுக்கும், k = 10-ஓட சுமார் O(n log k).
- **Exact lookups மட்டும்னா,** "இந்த PAN list-ல இருக்கா?" மாதிரி: ஒரு தடவை `set` build பண்ணுங்க, அப்புறம் ஒவ்வொரு lookup-உம் average-ல O(1). Order வேணும்போது sort பண்ணுங்க: ranges, "இதுக்கு அல்லது இதுக்கு அப்புறம் வர்ற முதல்", மிகக் கிட்டத்துல இருக்குற value, ranks.

### Off-by-one bugs இல்லாம binary search

பெரும்பாலான bugs conventions-ஐ கலக்குறதால தான் வருது. நம்பகமான ஒரு convention **half-open range**: answer எப்பவுமே `lo`-ல இருந்து `hi` வரை எங்கயாவது இருக்கும், ரெண்டும் சந்திக்கும்போது நிறுத்துவீங்க.

```python
def first_at_least(a, x):
    """Index of the first item that is at least x; len(a) if there is none."""
    lo, hi = 0, len(a)            # the answer is always in lo..hi
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < x:
            lo = mid + 1          # mid and everything left of it is too small
        else:
            hi = mid              # mid might be the answer, so keep it
    return lo

marks = [10, 20, 20, 20, 30]
print(first_at_least(marks, 20))   # 1
print(first_at_least(marks, 99))   # 5, which is len(marks): not found
```

ஒவ்வொரு pass-உம் range-ஐ சுருக்கும், அதனால loop முடியும். 20-க்கு அது indices 2, 1, 0-ஐ check பண்ணி 1-ஐ return பண்ணும், அதாவது மூணு 20-கள்ல முதல் ஒண்ணு. Python-ஓட `bisect.bisect_left` பண்றதும் இதைத் தான், அதனால real code-ல library-ஐ call பண்ணுங்க:

| Call | என்ன return பண்ணும் | `[10, 20, 20, 20, 30]`-ல |
|---|---|---|
| `bisect_left(a, x)` | item குறைஞ்சது x-ஆ இருக்குற முதல் index | `bisect_left(a, 20)`-னா 1 |
| `bisect_right(a, x)` | item x-ஐ விட பெருசா இருக்குற முதல் index | `bisect_right(a, 20)`-னா 4 |
| `bisect_right(a, x) - bisect_left(a, x)` | x-க்கு equal-ஆ எத்தனை items | 4 − 1 = 3 |
| result `len(a)`-க்கு equal | எதுவுமே qualify ஆகல | `bisect_left(a, 99)`-னா 5 |

அதனால x இருந்தா, அது முதல்ல `bisect_left`-லயும் கடைசியா `bisect_right(a, x) - 1`-லயும் வரும்.

32-bit integers இருக்குற Java அல்லது C++-ல, `lo + hi` சுமார் 2.1 billion-ஐ தாண்டினதும் `(lo + hi) / 2` overflow ஆகலாம்; Java-வோட சொந்த library-லயே இந்த bug இருந்ததை 2006-ல Joshua Bloch விவரிச்சாரு. அங்க `lo + (hi - lo) / 2`-னு எழுதுங்க. Python integers overflow ஆகாது.

### Binary search on the answer

நிறைய problems "work ஆகுற மிகச் சின்ன value"-ஐ கேக்கும்: ஒரு capacity, ஒரு daily limit, மிக முந்தைய நாள். "v work ஆகுமா?" test **monotonic**-ஆ இருந்தா (ஒரு தடவை yes-னா, அதை விட பெரிய எல்லா v-க்கும் yes), possible answers-ஓட range-ஐ binary search பண்ணுங்க. `first_at_least` template-ஐ use பண்ணுங்க, `a[mid] < x`-க்கு பதிலா "mid work ஆகாது"-னு மாத்துங்க. இதுக்கு சுமார் log₂(range-ஓட size) checks ஆகும், ஒவ்வொண்ணும் test-ஓட ஒரு run.

Precondition தான் எல்லாத்தையும் விட முக்கியம். "Day d-க்குள்ள cumulative sign-ups 50,000-ஐ reach பண்ணிடுச்சா?" monotonic, ஏன்னா totals எப்பவுமே குறையாது. "அந்த நாளோட sales ₹1 லட்சத்துக்கு மேலயா?" yes, no, yes-னு போகலாம், binary search எந்த error-உம் இல்லாம ஒரு தப்பான நாளை return பண்ணும்.

ஒரு rate மாதிரி real-valued answer-க்கு, floats சந்திக்காமலே போகலாம்: fixed எண்ணிக்கையில halvings run பண்ணுங்க, உதாரணமா 60, இல்லன்னா `hi - lo` உங்களுக்கு வேணும்ங்குற precision-ஐ விட குறைஞ்சதும் நிறுத்துங்க.

### Two pointers-உம் sliding windows-உம்

**Pair method ஏன் சரியா இருக்கு.** மீதி இருக்குற மிகச் சின்ன item-உம் மிகப் பெரிய item-உம் கூட்டினா ரொம்ப குறைவா வருதுன்னு வச்சுக்கோங்க. மிகச் சின்ன item-ஓட மீதி இருக்குற வேற எதை கூட்டினாலும் இன்னும் சின்னதா தான் வரும், அதனால அது எந்த answer-லயும் இருக்க முடியாது, அதை விடுறது safe. Sum ரொம்ப பெருசா இருக்கும்போது இதே logic மிகப் பெரிய item-ஐ விடும். ஒவ்வொரு step-உம் ஒரு item-ஐ எடுத்துடும், அதனால அதிகபட்சம் n − 1 steps தான்.

```python
def has_pair(prices, target):
    left, right = 0, len(prices) - 1
    while left < right:
        total = prices[left] + prices[right]
        if total == target:
            return prices[left], prices[right]
        if total < target:
            left += 1             # need a bigger sum
        else:
            right -= 1            # need a smaller sum
    return None

print(has_pair([5, 12, 18, 25, 30, 38, 45], 56))   # (18, 38)
```

Unsorted data-க்கு, முதல்ல sort பண்ணுங்க (O(n log n)), இல்லன்னா ஒரு set வச்சு ஒரே pass பண்ணுங்க, `target - p` ஏற்கனவே பார்த்தாச்சான்னு check பண்ணுங்க (O(n) time-உம் memory-உம்).

**Sliding window** அதோட right edge-ஐ ஒரு தடவைக்கு ஒரு step வளர்க்கும், rule உடைஞ்சிருக்குற வரைக்கும் left edge-ஐ சுருக்கும். சுருக்குறது எப்பவுமே rule-ஐ meet பண்றதை ஈஸியாக்கினா மட்டும் தான் இது சரி. "Total budget-க்குள்ள" rule-க்கு அந்த property ஒவ்வொரு value-உம் zero அல்லது அதுக்கு மேல இருந்தா மட்டும் தான் இருக்கும்.

### Pattern-ஐ அடையாளம் காணுறது

```flow
title: எந்த pattern பொருந்தும்?
Contiguous stretch-ஆ? -[ஆமா]-> Sliding window | O(n); சுருக்குறது உதவணும்
Contiguous stretch-ஆ? -[இல்ல]-> ஒரு target-ஓட pair-ஆ?
ஒரு target-ஓட pair-ஆ? -[ஆமா, sorted]-> Two pointers | O(n) time, O(1) memory
ஒரு target-ஓட pair-ஆ? -[ஆமா, unsorted]-> Hash set | O(n) time-உம் memory-உம்
ஒரு target-ஓட pair-ஆ? -[இல்ல]-> Work ஆகுற முதல், கடைசி அல்லது மிகச் சின்னதா?
Work ஆகுற முதல், கடைசி அல்லது மிகச் சின்னதா? -[test monotonic]-> Binary search | O(log n) checks
Work ஆகுற முதல், கடைசி அல்லது மிகச் சின்னதா? -[test முன்னும் பின்னும் flip ஆகுது]-> Scan பண்ணு அல்லது மறுபடி யோசி
```

Interview-ல, code பண்றதுக்கு முன்னாடி pattern-ஐயும் அதோட precondition-ஐயும் (sorted, monotonic அல்லது non-negative) சொல்லுங்க.

## ஒரு worked example

Sneha, Hyderabad-ல ஒரு online coaching platform-க்கு analytics பார்க்குறாங்க. Numbers உதாரணத்துக்காக மட்டும் தான்.

### 1. Budget-க்குள்ள இருக்குற மிக நீளமான நாட்கள் run

தொடர்ச்சியான நாட்கள்ல total ad spend ₹1 லட்சத்துக்குள்ள இருந்த மிக நீளமான run எது? ஒரு வருஷத்துல 66,795 possible runs இருக்கு (365 × 366 ÷ 2), அதனால எல்லாத்தையும் check பண்ணா O(n²). ஒரு sliding window ஒரே pass-ல முடிக்கும்:

```python
def longest_within(spend, budget):
    best = total = left = 0
    for right, amount in enumerate(spend):
        total += amount                   # grow: day `right` joins
        while total > budget:             # shrink until within budget
            total -= spend[left]
            left += 1
        best = max(best, right - left + 1)
    return best

week = [30, 20, 40, 10, 25, 60, 15]       # spend in thousands of rupees
print(longest_within(week, 100))          # 4
```

ஒரு வாரத்துக்கான trace, budget 100 (₹1 லட்சம்):

| நாள் | Spend | சுருக்கினதுக்கு அப்புறம் window | Total | இதுவரை best |
|---|---|---|---|---|
| 1 | 30 | நாள் 1 முதல் 1 | 30 | 1 |
| 2 | 20 | நாள் 1 முதல் 2 | 50 | 2 |
| 3 | 40 | நாள் 1 முதல் 3 | 90 | 3 |
| 4 | 10 | நாள் 1 முதல் 4 | 100 | 4 |
| 5 | 25 | நாள் 2 முதல் 5 (நாள் 1 drop ஆச்சு) | 95 | 4 |
| 6 | 60 | நாள் 4 முதல் 6 (நாள் 2, 3 drop ஆச்சு) | 95 | 4 |
| 7 | 15 | நாள் 5 முதல் 7 (நாள் 4 drop ஆச்சு) | 100 | 4 |

Answer 4 நாள் (நாள் 1 முதல் 4). ஒவ்வொரு நாளும் ஒரு தடவை join ஆகும், அதிகபட்சம் ஒரு தடவை வெளியே போகும், அதனால அதிகபட்சம் 2n steps: O(n). நாள் 6-ல ஒரு shrink step போதல, அதனால தான் code `if` இல்லாம `while` use பண்ணுது.

Spend எப்பவுமே negative ஆகாததால மட்டும் தான் இது safe. Figures-ல net refunds-ஐ சேர்த்தா இது உடையும்: `[80, 30, -50]`-உம் budget 100-உம் இருந்தா, total 110-ஐ தொடும்போது window நாள் 1-ஐ drop பண்ணி 2-னு report பண்ணும், ஆனா மூணு நாளும் சேர்த்து total 60, அதனால உண்மையான answer 3. Negative values இருந்தா, prefix sums மாதிரி வேற method use பண்ணுங்க.

### 2. Sign-ups ஒரு target-ஐ reach பண்ற முதல் நாள்

Finance கேக்குது: cumulative sign-ups எந்த நாள்ல முதல் தடவையா ஒரு target-ஐ reach பண்ணுச்சு? Sign-ups எப்பவுமே negative இல்ல, அதனால "day d-க்குள்ள reach ஆச்சா?" no, no, அப்புறம் அதுக்கு அப்புறம் வர்ற ஒவ்வொரு நாளுக்கும் yes. அது monotonic:

```python
from bisect import bisect_left
from itertools import accumulate

def first_day_reaching(daily, target):
    totals = list(accumulate(daily))      # running totals, O(n)
    i = bisect_left(totals, target)       # first day whose total is at least target
    return i if i < len(totals) else -1   # len(totals) means never reached

print(first_day_reaching([120, 90, 200, 150, 80], 400))   # 2
print(first_day_reaching([120, 90, 200, 150, 80], 9999))  # -1
```

இது `first_at_least` template தான், library பண்ணுது. Totals மூணாவது நாள்ல, அதாவது index 2-ல, 410-ஐ reach பண்ணுது.

`totals` build பண்றதே ஒரு O(n) pass, அதனால ஒரே ஒரு target-க்கு ஒரு சாதாரண scan-உம் அதே அளவு நல்லது தான். அவங்க நிறைய targets-க்கு பதில் சொல்லும்போது தான் search லாபம்: ஒரு வருஷ daily data-க்கு ஒவ்வொண்ணுக்கும் சுமார் 9 checks, பத்து வருஷ hourly data-க்கு (87,600 hours) சுமார் 17.

### 3. எந்த list-லயும் இல்லாத ஒரு answer-ஐ search பண்றது

Mentors assignment batches-ஐ submission order-ல grade பண்றாங்க. இந்த வாரத்தோட ஏழு batches-ல 40, 25, 35, 50, 20, 30, 45 pages இருக்கு, எல்லாத்தையும் 3 நாள்ல grade பண்ணணும், ஒவ்வொரு நாளோட batches-உம் ஒரு daily page limit-க்குள்ள இருக்கணும். Work ஆகுற மிகச் சின்ன limit எது?

Answer 50 (மிகப் பெரிய batch fit ஆகணும்)-க்கும் 245 (எல்லாமே ஒரே நாள்ல)-க்கும் நடுவுல இருக்கு, பெரிய limit-க்கு எப்பவுமே அதிக நாட்கள் தேவைப்படாது, அதனால test monotonic:

```python
def days_needed(pages, limit):
    days, today = 1, 0
    for p in pages:
        if today + p > limit:             # today is full; start a new day
            days, today = days + 1, 0
        today += p
    return days

def smallest_limit(pages, max_days):
    lo, hi = max(pages), sum(pages)       # smallest and largest sensible answers
    while lo < hi:
        mid = (lo + hi) // 2
        if days_needed(pages, mid) <= max_days:
            hi = mid                      # mid works; try smaller
        else:
            lo = mid + 1                  # too small; go bigger
    return lo

print(smallest_limit([40, 25, 35, 50, 20, 30, 45], 3))    # 95
```

Answer ஒரு நாளைக்கு 95 pages: 40 + 25, அப்புறம் 35 + 50, அப்புறம் 20 + 30 + 45. 94 limit-க்கு 4 நாள் வேணும். Search 196 possible limits-ஐ 7 checks-ல cover பண்ணுது, ஒவ்வொரு check-உம் ஒரு O(n) pass.

## பொதுவான தப்புகள்

**Unsorted data-லயோ monotonic இல்லாத test-லயோ binary search பண்றது.** தப்பான answer வரும், error எதுவும் வராது. Test "no, அப்புறம் yes"-னு போகுது, திரும்பி வரவே வராதுன்னு prove பண்ணுங்க.

**Off-by-one bounds.** Inclusive `hi`-யையும் exclusive `hi`-யையும் கலக்குறது, இல்லன்னா `mid` round down ஆகும்போது `lo = mid`-னு எழுதுறது, ரெண்டு items மீதி இருக்கும்போது loop-ஐ நிக்காம ஓட வைக்கும். Half-open template மாதிரி ஒரே convention-ஐ use பண்ணுங்க, lengths 0, 1, 2-ஐ test பண்ணுங்க. Java அல்லது C++-ல `lo + (hi - lo) / 2`-னும் எழுதுங்க.

**bisect-ஓட result-ஐ check பண்ணாம use பண்றது.** எதுவுமே qualify ஆகலைன்னா `bisect_left` `len(a)`-ஐ return பண்ணும், அதனால அதை வச்சு index பண்ணா `IndexError` வரும்.

**Loop-க்குள்ள sort பண்றது.** Loop-க்கு வெளியே ஒரு தடவை sort பண்ணுங்க. Full order-ஐ விட குறைவா வேணும்போது `min()`, `heapq.nlargest` அல்லது ஒரு set use பண்ணுங்க.

**எல்லா sort-உம் stable-னு நினைக்கிறது.** C++ `std::sort`, heap sort, பெரும்பாலான quicksorts stable இல்ல, அதனால two-step multi-key sort தப்பா வரலாம்.

**Unsorted data-ல two pointers use பண்றது.** முதல்ல sort பண்ணுங்க, இல்லன்னா hash set use பண்ணுங்க.

**Negative values இருக்கும்போது sum-based sliding window use பண்றது.** Refunds அல்லது losses அதை சத்தமில்லாம உடைச்சுடும். ஒவ்வொரு value-உம் zero அல்லது அதுக்கு மேலன்னு check பண்ணுங்க.

**Window-ஐ `while`-க்கு பதிலா `if` வச்சு சுருக்குறது.** Trace-ல நாள் 6 காட்டுற மாதிரி, ஒரு step போதாம போகலாம்.
