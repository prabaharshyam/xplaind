## இது என்ன

AI-யோடயோ இல்லாமலோ, எதையாவது automate பண்றதுக்கு முன்னாடி, வேலை உண்மையில எப்படி நடக்குதுன்னு தெரிஞ்சுக்கணும். **Process map**-னா ஒரு ஆரம்ப event-ல இருந்து ஒரு outcome வரைக்கும் வேலை எப்படி ஓடுதுன்னு காட்டுற diagram. ஒவ்வொரு step-க்கும் இது காட்டுறது:

- **என்ன** நடக்குது;
- **யார்** செய்றாங்க;
- **எந்த system** அல்லது tool: email, Tally, ஒரு portal, WhatsApp, Excel;
- காத்திருப்பு உட்பட **எவ்வளவு நேரம்** ஆகுது;
- தப்புகள், மறுவேலை, தாமதங்கள் **எங்க** நடக்குது;
- "amount ₹50,000-ஐ தாண்டுதா?" மாதிரி **decision points**.

```flow
dir: LR
Invoice வருது | யார்: mail room, system: email -> Excel-ல type பண்றது | யார்: accounts, 4 நிமிஷம்
Excel-ல type பண்றது -> Approve ஆச்சா? | யார்: manager, 2 நாள் காத்திருப்பு: bottleneck
Approve ஆச்சா? -[ஆமா]-> Payment முடிஞ்சது | யார்: accounts, system: Tally, 3 நிமிஷம்
```

இதை paper-லயோ whiteboard-லயோ ஒரு free diagram tool-லயோ வரையலாம். Boxes-உம் arrows-உம் போதும். மதிப்பு வரைபடத்துல இல்ல; அதுக்குள்ள போற பேச்சுலயும் numbers-லயும் தான் இருக்கு.

இந்த lesson-ல Ludhiana-ல ஒரு textile exporter-ஓட accounts team, supplier invoices எப்படி pay ஆகுதுன்னு map பண்றதை follow பண்றோம். முடிவுல, ஒரு real process-ஐ map பண்ணவும், தோராயமா அளக்கவும், முதல்ல என்ன மாத்தணும்னு முடிவு பண்ணவும் தெரிஞ்சுக்கலாம்.

## இது எப்படி work ஆகுது

### 1. தெளிவான எல்லைகள் இருக்குற ஒரு process-ஐ எடுங்க

தெளிவான தொடக்கமும் முடிவும் இருக்குற ஒரு flow-ஐ எடுங்க: "accounts"ன்னு இல்ல, "supplier invoice வந்ததுல இருந்து payment முடியுற வரை". பெரிய, தெளிவில்லாத processes பெரிய, தெளிவில்லாத maps-ஐ தரும், அதை யாரும் use பண்ண மாட்டாங்க.

### 2. Official process-ஐ இல்ல, real process-ஐ map பண்ணுங்க

Manager சொல்றது பெரும்பாலும் official version. வேலை செய்றவங்களுக்கு அவங்களோட workarounds-ஓடயும் காத்திருப்போடயும் real version தெரியும். அவங்க கூட உட்கார்ந்து, **கடைசியா நடந்த real case**-ஐ படி படியா சொல்ல சொல்லுங்க: "நேத்து invoices-ஐ வச்சு என்ன பண்ணீங்கன்னு காட்டுங்க." அவங்க சொல்லும்போதே ஒவ்வொரு step-ஐயும் ஒரு sticky note-லயோ box-லயோ எழுதுங்க.

உதவுற கேள்விகள்:

- "அடுத்து என்ன பண்றீங்க?"
- "அந்த information-ஐ எங்க இருந்து எடுக்குறீங்க?"
- "அதுக்கு எவ்வளவு நேரம் ஆகுது? எவ்வளவு நேரம் காத்திருக்கீங்க?"
- "தப்பா போனா என்ன ஆகும்?"

### 3. Details-ஐ சேருங்க, குறிப்பா exceptions

ஒவ்வொரு step-க்கும் யார், என்ன system, எவ்வளவு நேரம், எத்தனை தடவை தப்பு ஆகுதுன்னு note பண்ணுங்க. அப்புறம் exceptions பத்தி கேளுங்க: "GSTIN இல்லைன்னா என்ன ஆகும்? Amount PO-ஓட பொருந்தலைன்னா?" Exceptions அரிது, ஆனா மெதுவானவை, பெரும்பாலும் மொத்த நேரத்துல பெரும்பகுதியை எடுக்கும்.

### 4. தோராயமா அளங்க

உங்களுக்கு perfect data தேவையில்ல. Priority போடவும், பின்னாடி பலனை நிரூபிக்கவும் தோராய numbers போதும்:

| Measure | எப்படி எடுக்கிறது | Example |
| --- | --- | --- |
| Volume | போன மாசம் cases-ஐ எண்ணுங்க | மாசத்துக்கு 600 invoices |
| ஒரு item-க்கு கையால செய்ற நேரம் | சில real cases-ஐ நேரம் பாருங்க | ஒண்ணை type பண்ண 4 நிமிஷம் |
| காத்திருப்பு நேரம் | Emails அல்லது system-ல தேதிகளை ஒப்பிடுங்க | Approval-க்கு 2 நாள் |
| Exception rate | கூடுதல் வேலை தேவைப்பட்ட cases-ஐ எண்ணுங்க | 15%-க்கு PO number இல்லை |
| Error அல்லது rework rate | திருத்தங்களை எண்ணுங்க | 3% தப்பா type ஆனது |

இந்த numbers தான் உங்க **baseline**.

### 5. Waste-ஐ கண்டுபிடிங்க

பொதுவான அடையாளங்கள்:

- ஒரே data ரெண்டு அல்லது அதுக்கு மேல இடங்கள்ல type பண்றது;
- approvals அல்லது பதில்களுக்கு காத்திருக்கிறது;
- emails அல்லது folders-ல information-ஐ தேடுறது;
- ஒரே விஷயத்தை ரெண்டு தடவை check பண்றது;
- ஒண்ணோடொண்ணு பேசக்கூடிய systems இடையில கையால copy பண்றது.

### 6. Step by step-ஆ decide பண்ணுங்க

வீணான ஒவ்வொரு step-க்கும் அஞ்சு options-ல ஒண்ணை எடுங்க:

```flow
இந்த step அவசியமா? -[இல்ல]-> Remove பண்ணுங்க
```

## ஒரு நாள், ஒரு example

Ludhiana-ல ஒரு textile exporter-ஓட accounts team-ல ரெண்டு assistants-உம் ஒரு manager-உம் இருக்காங்க. மாசத்துக்கு சுமார் 600 supplier invoices-ஐ process பண்றாங்க. ஒரு invoice-க்கு "ஒரு சில நிமிஷம்" ஆகும்னு manager நினைக்கிறார்.

கடந்த செவ்வாய் invoices-ஐ வச்சு, team சேர்ந்து real process-ஐ map பண்றாங்க:

| Step | யார் | System | நேரம் | பிரச்சனைகள் |
| --- | --- | --- | --- | --- |
| 1. Invoice email, WhatsApp, courier வழியா வருது; paper ones-ஐ scan பண்றாங்க | Assistant | Email, phone, scanner | ஒவ்வொரு paper invoice-க்கும் 5 நிமிஷம் | பார்க்க வேண்டிய மூணு channels |
| 2. Details-ஐ Excel-ல type பண்றது | Assistant | Excel | 4 நிமிஷம் | Typing errors சுமார் 3% |
| 3. Purchase order check | Assistant | Tally | 3 நிமிஷம் | 15%-க்கு PO number இல்ல: purchase team-க்கு phone call, சுமார் 20 நிமிஷம் |
| 4. Manager approve பண்றார் | Manager | Email | காத்திருப்பு: சராசரி 2 நாள் | பெரிய தாமதம் |
| 5. Payment-க்காக details-ஐ மறுபடி type பண்றது | Assistant | Tally | 3 நிமிஷம் | Double data entry |
| 6. Payment வாராந்திரம் schedule ஆகுது | Assistant | Bank portal | 1 நிமிஷம் | இன்னும் ஒரு வாரம் வரை காத்திருக்கலாம் |

**கண்டுபிடிப்புகள்.** Exceptions-ஐயும் paper invoices-ஐயும் சேர்த்து எண்ணுனா, ஒரு invoice-க்கு சராசரி 15 நிமிஷம் கையால வேலை, அதாவது மாசத்துக்கு தோராயமா 150 மணி நேரம். Data ரெண்டு தடவை type ஆகுது. பெரிய தாமதம் typing-ல இல்லவே இல்ல: approval-க்காக ரெண்டு நாள் காத்திருக்கிறது தான்.

**Decisions.**

| Waste | Decision |
| --- | --- |
| மூணு வரவு channels | Simplify: suppliers-ஐ ஒரே address-க்கு invoices-ஐ email பண்ண சொல்லுங்க |
| Invoice details-ஐ type பண்றது | Fields-ஐ படிக்குற AI step-ஓடயும், assistant-ஓட check-ஓடயும் automate பண்ணுங்க |
| Tally-ல மறுபடி type பண்றது | Remove: check பண்ண data-வை ஒரு தடவை Tally-க்கு push பண்ணுங்க |
| Approval-க்கு காத்திருக்கிறது | Simplify: ₹1 lakh-க்கு கீழ உள்ள amounts-க்கு WhatsApp-ல ஒரு-tap approval |
| PO numbers இல்லாதது | Exception-ஐ remove பண்ணுங்க: முக்கிய suppliers-கிட்ட PO numbers-ஐ கட்டாயமாக்குங்க |

Map, owner-கிட்ட வாதத்தை வைக்குது, baseline numbers மூணு மாசத்துல பலனை நிரூபிக்கும்.

## பொதுவா பண்ற தப்புகள்

- **Manager-ஓட விளக்கத்துல இருந்து map பண்றது.** வேலை செய்றவங்ககிட்ட, சமீபத்திய ஒரு real case-ஐ வச்சு பேசுங்க.
- **Exceptions-ஐ புறக்கணிக்கிறது.** நேரம் பெரும்பாலும் அங்கதான் ஒளிஞ்சிருக்கு.
- **Numbers இல்லாம இருக்கிறது.** Volumes-உம் நேரங்களும் இல்லாம, priority போடவோ improvement-ஐ நிரூபிக்கவோ முடியாது.
- **Waste-ஐ automate பண்றது.** Automate பண்றதுக்கு முன்னாடி remove, simplify பண்ணுங்க.
- **ரொம்ப பெரிய process-ஐ map பண்றது.** தெளிவான தொடக்கமும் முடிவும் இருக்குற ஒரு flow-ஐ எடுங்க.
- **காத்திருப்பு நேரத்தை மறக்கிறது.** Steps-க்கு இடையில இருக்குற தாமதங்கள், steps-ஐ விட முக்கியமா இருக்கும்.

## Practice பண்ணுங்க

கீழே link பண்ணியிருக்குற Atlassian-ஓட process mapping guide-ஐயும், GOV.UK-ஓட discovery phase guide-ஐயும் படிங்க.

1. **Interview பண்ணுங்க.** உங்களுக்கு தெரிஞ்ச ஒரு process-ஐ எடுங்க: coaching centre-ல fee collection, leave approvals, stock reorder மாதிரி. அதை செய்ற ஒருத்தரை, கடைசியா நடந்த real case பத்தி interview பண்ணுங்க.
2. **Map-ஐ வரையுங்க.** ஒவ்வொரு step-க்கும் யார், system, நேரம், fail ஆகுற இடங்களோடயும், volume, exceptions-க்கு தோராய numbers-ஓடயும் வரையுங்க.
3. **Decide பண்ணுங்க.** மூணு பெரிய waste ஆதாரங்களை mark பண்ணி, ஒவ்வொண்ணுக்கும் decide பண்ணுங்க: remove, simplify, rules வச்சு automate, AI + check வச்சு automate, அல்லது விட்டுடுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** உங்க map-ஐ numbers-ஓட காட்டலாம், முதல்ல எந்த மாற்றத்தை பண்ணுவீங்க, ஏன்னு explain பண்ணலாம்.
