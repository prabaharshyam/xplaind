## இது என்ன

Git உங்க வேலையை மூணு இடத்துல வச்சிருக்கு, ஒவ்வொண்ணுக்கும் தனி undo இருக்கு:

- **Working folder**: நீங்க இப்போ edit பண்ணிட்டு இருக்குற files.
- **Staging area**: அடுத்த commit-ல போகணும்னு `git add` வச்சு mark பண்ணது.
- **History**: commits-ஏ; முதல்ல உங்க laptop-ல மட்டும், push பண்ணதும் shared server-லயும்.

எந்த undo சரின்னு தப்பு எங்க இருக்கு, எல்லாத்துக்கும் மேல, வேற யார்கிட்டயாவது அது ஏற்கனவே இருக்கான்னு பொறுத்தது. கிட்டத்தட்ட எல்லாத்தையும் முடிவு பண்ற rule: **வேற யார்கிட்டயும் இல்லாத history-ஐ நீங்க rewrite பண்ணலாம்; மத்தவங்க ஏற்கனவே pull பண்ண history-ஐ rewrite பண்ணக்கூடாது.**

## இது எப்படி work ஆகுது

```flow
title: தப்பு எங்க இருக்கு?
தப்பு -> எங்க இருக்கு?
எங்க இருக்கு? -[edit பண்ணது, stage ஆகல]-> git restore file | edit-ஐ தூக்கி எறியுங்க
எங்க இருக்கு? -[stage ஆயிடுச்சு, commit ஆகல]-> git restore --staged file | edit-ஐ வச்சுக்கிட்டு unstage பண்ணுங்க
எங்க இருக்கு? -[commit ஆயிடுச்சு, push ஆகல]-> git reset அல்லது git commit --amend | உங்க சொந்த history-ஐ rewrite பண்ணுங்க
எங்க இருக்கு? -[shared branch-க்கு push ஆயிடுச்சு]-> git revert commit | அதை undo பண்ற ஒரு commit-ஐ சேர்ங்க
git reset அல்லது git commit --amend -[தப்பா போச்சு]-> git reflog | பழைய commit-ஐ கண்டுபிடிச்சு திரும்ப போங்க
```

**Restore** files-ல வேலை செய்யும். `git restore app.py` stage பண்ணாத edits-ஐ தூக்கி எறிஞ்சு, கடைசியா commit பண்ண version-ஐ திருப்பி கொண்டு வரும். `git restore --staged app.py` ஒரு file-ஐ staging area-ல இருந்து எடுக்கும், ஆனா உங்க edits-ஐ வச்சுக்கும்.

**Reset** உங்க branch label-ஐ ஒரு பழைய commit-க்கு பின்னாடி நகர்த்தும். நீங்க தாண்டி போற commits-ல இருந்த changes-க்கு என்ன ஆகும்ங்குறது mode-ஐ பொறுத்தது:

| Command | Branch பின்னாடி நகருமா | அந்த commits-ல இருந்த changes | எப்போ use பண்றது |
| --- | --- | --- | --- |
| `git reset --soft HEAD~1` | ஆமா | வச்சுக்கப்படும், staged-ஆ | கடைசி commit-ஐ வேற மாதிரி திரும்ப பண்ணணும்னா |
| `git reset HEAD~1` (mixed) | ஆமா | வச்சுக்கப்படும், unstaged-ஆ | எதை commit பண்றதுன்னு பிரிக்கணும் அல்லது திரும்ப தேர்வு பண்ணணும்னா |
| `git reset --hard HEAD~1` | ஆமா | உங்க files-ல இருந்து delete ஆகும் | வேலையே வேண்டாம்னா (உறுதியா இருங்க) |
| `git revert <id>` | இல்லை | ஒரு புது commit அவற்றை undo பண்ணும் | Commit ஏற்கனவே share ஆயிடுச்சுன்னா |

`HEAD~1`-னா "நான் இருக்குற இடத்துக்கு ஒரு commit முன்னாடி". `HEAD~3`-னா மூணு.

**Amend** கடைசி commit-க்கான ஒரு சின்ன reset: ஒரு fix-ஐ stage பண்ணி `git commit --amend` ஓட்டினா, கடைசி commit திருத்தின ஒண்ணால replace ஆகும். Push பண்றதுக்கு முன்னாடி message-ல typo அல்லது மறந்த file-க்கு இது perfect.

**Revert** எதையும் rewrite பண்ணாது. `git revert a1b2c3d` அந்த commit என்ன மாத்துச்சுன்னு பார்த்து, அதை திருப்பி மாத்துற ஒரு புது commit-ஐ உருவாக்கும். History வளரும்; எல்லாரோட copy-உம் இன்னும் ஒத்து போகும். Main-ல நீங்க வேண்டியது இந்த undo தான்.

**Stash** வேலையை commit பண்ணாம ஒரு பக்கம் வச்சுடும். `git stash` உங்க முடிக்காத edits-ஐ save பண்ணி, folder-ஐ clean-ஆ தரும்; உதாரணமா வேற branch-ல ஒரு அவசர bug-ஐ fix பண்ண. `git stash pop` edits-ஐ திருப்பி கொண்டு வரும். Commit பண்ணாத changes-ஐ தூக்கி எறியுற எந்த command-க்கும் முன்னாடி இது safe-ஆன move; ஏன்னா edits stash ஆயிட்டா, அடுத்த step தப்பா போனாலும் மீட்டெடுக்கலாம்.

**Reflog** உங்க safety net. உங்க branch நுனி நகரும் ஒவ்வொரு முறையும், commit, reset, rebase, checkout எதனாலயும், Git அதை reflog-ல கிட்டத்தட்ட 90 நாள் குறிச்சு வைக்கும். `git reflog` அந்த positions-ஐ list பண்ணும், அதுல எதுக்கும் நீங்க திரும்ப குதிக்கலாம்.

## ஒரு example

Rahul, Hyderabad-ல ஒரு e-commerce company-க்கு recommendation API-ல வேலை செய்றாங்க. Friday சாயங்காலம்.

**தப்பு ஒண்ணு: ஒரு debug print.** `ranker.py`-ல `print(user)` எல்லா இடத்துலயும் இருக்கு, stage பண்ணல. `git restore ranker.py` உடனே clean பண்ணிடும்.

**தப்பு ரெண்டு: ஒரு commit-ல secret.** அவங்க கடைசி commit, இன்னும் push ஆகாதது, ஒரு API key இருக்குற `.env`-ஐ சேர்த்திருக்கு. இதை ஓட்டுறாங்க:

```bash
git reset --soft HEAD~1
git restore --staged .env
echo ".env" >> .gitignore
git add .gitignore ranker.py
git commit -m "Add category boost to ranker"
```

Commit secret இல்லாம திரும்ப build ஆகுது. அது ஒருபோதும் push ஆகாததால rewrite பண்றது safe. இருந்தாலும் key-ஐ rotate பண்றாங்க; ஏன்னா history-ல disk-ல இருந்த secret leak ஆகியிருக்கலாம்னு நினைக்கிறதுதான் எச்சரிக்கையான வழி.

**தப்பு மூணு: main-ல ஒரு மோசமான change.** Monday அன்னைக்கு, ஒரு teammate merge பண்ண commit புது users-க்கு ranker காலி lists-ஐ தர வைக்குது. அது main-ல ஒரு நாளா இருக்கு, எல்லாரும் pull பண்ணிட்டாங்க. Main-ஐ reset பண்ணா எல்லா copies-உம் உடையும். அதுக்கு பதிலா:

```bash
git switch main
git pull
git revert 7f3e9c1
git push
```

"Revert 'Boost recent items'"ங்குற ஒரு புது commit சாதாரண pull request, pipeline வழியா போகுது. Bug போயிடுச்சு, history அப்படியே இருக்கு, original change-ஐ team பின்னாடி ஒழுங்கா fix பண்ணும்.

**தப்பு நாலு: தொலைஞ்சு போன மதியம்.** தன் branch-ஐ clean பண்ணும்போது Rahul `git reset --hard HEAD~3` ஓட்டுறாங்க; அந்த மூணு commits-ல ஒண்ணு தனக்கு தேவையான test-னு அப்புறம் புரியுது. `git reflog` ஓட்டுறாங்க, `e41d2aa HEAD@{1}: commit: Add tests for cold-start users`-ஐ பார்க்குறாங்க, `git cherry-pick e41d2aa` வச்சு திருப்பி கொண்டு வராங்க. எப்பவாவது commit ஆயிருந்தா, எதுவும் உண்மையிலேயே தொலையாது.

## பொதுவா பண்ற தப்புகள்

- **Shared branch-ஐ reset பண்றது.** Main-ல `git reset` + force push எல்லாரோட history-ஐயும் rewrite பண்ணும். Share ஆன எதுக்கும் `git revert` use பண்ணுங்க.
- **Revert secret-ஐ நீக்கும்னு நினைக்கிறது.** Revert secret-ஐ history-ல விட்டுடும். Key-ஐ rotate பண்ணுங்க; history-ல இருந்து நீக்க special tools-உம் எல்லாரும் சேர்ந்து rewrite பண்றதும் தேவை.
- **Check பண்ணாம --hard use பண்றது.** முதல்ல `git status`, `git stash`. `--hard` delete பண்ண commit ஆகாத edits reflog-ல இருக்காது.
- **Push பண்ண commit-ஐ amend பண்றது.** அது commit-ஐ ஒரு புதுசால replace பண்ணும்; பழசை pull பண்ண teammates diverge ஆயிடுவாங்க.
- **Reflog இருக்குறதை மறக்கிறது.** "என் வேலை போயிடுச்சு"ங்குற பெரும்பாலான பதட்டங்கள் `git reflog`-ல முடியும்.

## Practice பண்ணுங்க

1. ஒரு practice repository-ல மூணு commits பண்ணுங்க. ஒவ்வொரு reset mode-ஐயும் வரிசையா use பண்ணி, ஒவ்வொண்ணுக்கு அப்புறமும் `git status`-ஐ பாருங்க.
2. ஒரு commit-ஐ revert பண்ணி, புது commit-ஓட diff-ஐ `git show` வச்சு படிங்க.
3. `git reset --hard HEAD~2` ஓட்டி, அப்புறம் `git reflog` வச்சு தொலைஞ்ச commits-ஐ மீட்டெடுங்க.
4. எதிர்கால உங்களுக்கு ஒரு வரி rule எழுதுங்க: share பண்ணாத வேலைக்கு எந்த undo, share பண்ணதுக்கு எந்த undo.
