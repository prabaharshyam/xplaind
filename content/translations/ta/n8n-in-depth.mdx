## இது என்ன

உங்க முதல் n8n workflow-ல ஒரு trigger-உம் சில nodes-உம் இருந்துச்சு. Real business automations இன்னும் தூரம் போகும்: ஆயிரக்கணக்கான records-ஐ process பண்ணும், கடுமையான limits இருக்குற APIs-ஐ call பண்ணும், பல systems-ல இருந்து data-வை சேர்க்கும், AI steps இருக்கும், விடியற்காலை 3 மணிக்கு ஏதாவது fail ஆனாலும் வேலை செய்யணும்.

இதுக்கெல்லாம் n8n-ல building blocks இருக்கு:

| Building block | எதுக்கு |
| --- | --- |
| **Sub-workflows** | மத்த workflows-ல இருந்து call பண்ணக்கூடிய, functions மாதிரி reusable workflows |
| **Loops and batches** | API limits-ஐ மதிக்க, items-ஐ groups-ஆ process பண்றது |
| **Merge and split** | ரெண்டு sources-ல இருந்து data-வை சேர்க்கிறது, அல்லது lists-ஐ items-ஆ பிரிக்கிறது |
| **Code nodes** | Visual nodes cover பண்ணாத logic-க்கு சின்ன JavaScript அல்லது Python snippets |
| **AI nodes** | Model calls, structured output parsers, tools வச்சிருக்குற agent nodes |
| **Error workflows** | தங்க settings-ல இதை பேர் சொல்லியிருக்குற ஒரு workflow fail ஆகும்போது run ஆகி, யாருக்காவது alert அனுப்பும் |

```flow
Schedule: காலை 6 மணி -> Shopify: orders, page by page
Schedule: காலை 6 மணி -> Gateway: settlements, batch and wait
Shopify: orders, page by page -> Order id-ல Merge
Gateway: settlements, batch and wait -> Order id-ல Merge
Order id-ல Merge -> Code: mismatches-ஐ flag பண்ணு -> Sub-workflow: புதுசா இருந்தா row எழுது -> AI: ஒவ்வொரு mismatch-யையும் விளக்கு -> Slack: summary
எந்த failure-உம் -> Error workflow | execution link-ஓட finance-ops-க்கு alert
```

இந்த lesson-ல Bengaluru-ல ஒரு skincare brand, தினசரி order reconciliation-ஐ automate பண்றதை follow பண்றோம். Lesson முடியும் போது, volume, limits, AI, failure எல்லாத்தையும் handle பண்ற workflows build பண்ண முடியும்.

## இது எப்படி work ஆகுது

### Structure

ஒவ்வொரு workflow-ம் ஒரே வேலையில focus-ஆ இருக்கட்டும். "customer-ஐ look up பண்ணு", "alert அனுப்பு" மாதிரி பொதுவான logic-ஐ, மத்த workflows call பண்ற **sub-workflows**-ல போடுங்க. Nodes-க்கு தெளிவா பேர் வைங்க: "HTTP Request 3"-னு இல்லாம "Get open orders from Shopify". ஒரு colleague, அல்லது மூணு மாசம் கழிச்சு நீங்களே, canvas-ஐ பார்த்தே workflow-ஐ புரிஞ்சுக்க முடியணும்.

### Volume and rate limits

நிறைய APIs, வினாடிக்கு அல்லது நிமிஷத்துக்கு எத்தனை requests பண்ணலாம்னு limit வைக்கும், ஒரு நேரத்துல ஒரு page results தான் தரும். இதெல்லாம் use பண்ணுங்க:

- **pagination**: எல்லாத்தையும் ஒரே தடவையில இல்லாம, results-ஐ page by page எடுக்க;
- **Loop Over Items**, ஒரு batch size-ஓட: items-ஐ groups-ஆ process பண்ண;
- batches-க்கு நடுவுல ஒரு **Wait** node: limit-க்கு கீழயே இருக்க.

```flow
dir: LR
3,000 items -> 100-ஓட ஒரு batch -> API calls -> Wait 1 s
Wait 1 s -[அடுத்த batch]-> 100-ஓட ஒரு batch
```

### Data-வை merge பண்றது

**Merge** node, ரெண்டு branches-ல இருந்து வர்ற items-ஐ position அடிப்படையிலயோ, ஒரு matching field அடிப்படையிலயோ சேர்க்கும்; உதாரணம், sheet rows-ஐ CRM contacts-ஓட email வச்சு match பண்றது, அல்லது orders-ஐ payments-ஓட order id வச்சு match பண்றது.

### Code nodes

வித்தியாசமான formats-ஐ parse பண்ண, date maths-க்கு, amounts-ஐ இந்திய முறையில format பண்ண (₹1,25,000) இது பயன்படும். சின்னதா வச்சு, comments போடுங்க. Code node-க்குள்ள சிக்கலான logic-ஐ test பண்ணவும் maintain பண்ணவும் கஷ்டம்; அது வளர்ந்துச்சுன்னா ஒரு சரியான service-க்கு மாத்திடுங்க.

### AI steps

தெளிவான prompt-ஓட ஒரு model node-ஐயும், ஒரு **structured output parser**-ஐயும் use பண்ணுங்க; அப்போ அடுத்த nodes-க்கு free text-க்கு பதிலா நம்பகமான, பேர் இருக்குற fields கிடைக்கும். **Agent nodes** பல-step tasks-க்கு, மத்த nodes அல்லது sub-workflows மாதிரி tools-ஐ call பண்ண முடியும். மத்த agent மாதிரியே இதையும் நடத்துங்க: தேவையான tools-ஐ மட்டும் கொடுங்க, steps எண்ணிக்கையை limit பண்ணுங்க, payments மாதிரி risky actions-க்கு approval கேளுங்க.

### Reliability

| Practice | ஏன் |
| --- | --- |
| நிலையில்லாத nodes-ல retries | தற்காலிக API errors ரெண்டாவது முயற்சியில தானா சரியாகும் |
| Idempotent writes | Record-ஐ உருவாக்குறதுக்கு முன்னாடி ஏற்கனவே இருக்கான்னு check பண்ணுங்க; அப்போ reruns duplicates உருவாக்காது |
| ஒரு error workflow | Workflow பேர், fail ஆன node, execution link-ஓட உங்க team chat-ல post பண்ணும் |
| Item-count checks | அமைதியா எதுவுமே process பண்ணாத runs-ஐ பிடிக்கும் |

### Maintainability

Workflows-ஐ JSON-ஆ export பண்ணி Git-ல போடுங்க, அல்லது கிடைச்சா n8n-ஓட source control features-ஐ use பண்ணுங்க. தனித்தனி development, production instances அல்லது projects வச்சிருங்க; credentials-ஐ ஒவ்வொரு environment-க்கும் தனியா store பண்ணுங்க. Production-ஐ தொடுறதுக்கு முன்னாடி development-ல changes-ஐ test பண்ணுங்க.

### Self-hosting basics

n8n-ஐ நீங்களே, உதாரணத்துக்கு Docker-ல, run பண்ணா, data மேல உங்களுக்கு control கிடைக்கும். அப்போ அதோட database-க்கு backups, updates, security, scaling எல்லாம் உங்க பொறுப்பு. அதிக volume-க்கு, **queue mode** தனி worker processes-ல executions-ஐ run பண்ணும்.

## ஒரு உதாரணம்

Bengaluru-ல ஒரு D2C skincare brand தன் Shopify store மூலமா ஒரு நாளைக்கு சுமார் 1,500 orders விக்குது. ஒவ்வொரு காலையும், finance team ரெண்டு மணி நேரம் orders-ஐ payment gateway settlements-ஓடயும் accounting sheet-ஓடயும் match பண்றாங்க. இதை automate பண்றாங்க:

| # | Node | என்ன பண்ணும் |
| --- | --- | --- |
| 1 | Schedule trigger | காலை 6 மணிக்கு run ஆகும் |
| 2 | Shopify | நேத்து orders-ஐ 250 250-ஆ pages-ல fetch பண்ணும் |
| 3 | Loop-ல HTTP Request | Payment gateway API-ல இருந்து settlements-ஐ batches-ல, அதோட limit-ஐ மதிக்க 1 வினாடி wait-ஓட fetch பண்ணும் |
| 4 | Merge | Orders-ஐயும் settlements-ஐயும் order id-ல join பண்ணும் |

| 6 | Sub-workflow "write to accounting sheet" | சேர்க்குறதுக்கு முன்னாடி அந்த order-க்கு ஒரு row இருக்கான்னு check பண்ணும்; அதனால reruns safe |

## பொதுவா பண்ற தப்புகள்

- **ஒரே ராட்சச workflow.** தெளிவான பேர்களோட sub-workflows-ஆ பிரிங்க.
- **Rate limits-ஐ கண்டுக்காம விடுறது.** Paginate, batch, wait பண்ணுங்க.
- **Idempotent இல்லாத writes.** Reruns duplicates உருவாக்கும்.
- **பெரிய code nodes-க்குள்ள புதைஞ்ச logic.** Code-ஐ சின்னதா வச்சு, சிக்கலான logic-ஐ ஒரு service-க்கு நகர்த்துங்க.
- **Version control-உம் test instance-உம் இல்லாதது.** Production-ல பண்ற changes அமைதியா எல்லாத்தையும் உடைக்கும்.
- **AI output-ஐ free text-ஆ விடுறது.** அடுத்த steps-க்கு நம்பகமான fields கிடைக்க, structured output parser use பண்ணுங்க.

## Practice பண்ணுங்க

கீழே link பண்ணியிருக்குற n8n-ஓட N8N102 Integrations course-ஐ முடிச்சு, hosting overview-ஐ படிங்க.

1. **Volume.** ஒரு API அல்லது sheet-ல இருந்து குறைஞ்சது 100 items-ஐ batches-ல, batches-க்கு நடுவுல ஒரு wait-ஓட process பண்ற ஒரு workflow build பண்ணுங்க.
2. **Merge, write, AI.** ரெண்டு data sources-ஓட ஒரு merge-ஐயும், ஏற்கனவே இருக்குற rows-ஐ check பண்ணி records எழுதுற ஒரு sub-workflow-வையும், structured output-ஓட ஒரு AI step-ஐயும் சேருங்க.
3. **Failure.** உங்களுக்கு alert அனுப்புற ஒரு error workflow-ஐ சேர்த்து, ஒரு node-ஐ வேணும்னே உடைச்சு, alert-ஐயும் சுத்தமான rerun-ஐயும் confirm பண்ணுங்க. Manual test runs-க்கு error workflows run ஆகாது; அதனால workflow-ஐ அதோட trigger-ல run ஆக விடுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** உங்க workflow-ஐ தொடர்ச்சியா ரெண்டு தடவை duplicates உருவாக்காம rerun பண்ணவும், fail ஆன execution-க்கு ஒரு link-ஓட ஒரு error alert-ஐ காட்டவும் முடியும்.
