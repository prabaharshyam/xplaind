## இது என்ன

உங்க முதல் n8n workflow-ல ஒரு trigger-உம் சில nodes-உம் இருந்துச்சு. ஒரு business நம்பியிருக்குற workflows இன்னும் அதிகமா போகும். அவை ஆயிரக்கணக்கான records-ஐ process பண்ணும், strict limits இருக்குற APIs-ஐ call பண்ணும், ஒத்துப்போகாத ரெண்டு systems-ல இருந்து data-வை சேர்க்கும், யாரும் பாக்காத ராத்திரி 3 மணிக்கு ஏதாவது fail ஆனாலும் வேலை செஞ்சுக்கிட்டே இருக்கணும்.

இது ஒவ்வொண்ணுக்கும் n8n-ல ஒரு building block இருக்கு:

| Building block | எதுக்கு |
| --- | --- |
| **Sub-workflows** | நிறைய workflows call பண்ற பொதுவான steps, functions மாதிரி |
| **Paging, batches, waits** | ஒரு API-ஓட limits-ஐ மீறாம data-வை fetch பண்றது, அனுப்புறது |
| **Merge** | ஒரு shared id வச்சு ரெண்டு sources-ஐ சேர்க்குறது, match ஆகாத items-ஐயும் சேர்த்து |
| **Code nodes** | Visual nodes cover பண்ணாத logic-க்கு சின்ன JavaScript அல்லது Python snippets |
| **AI nodes** | Emails மாதிரி குழப்பமான text-ஐ படிச்சு, rules check பண்ணக்கூடிய fields-ஆ மாத்துறது |
| **Error workflows** | ஒரு automatic run fail ஆனா ஒரு ஆளுக்கு alert அனுப்புறது |

இந்த lesson, Bengaluru-ல ஒரு skincare brand தன் daily payment reconciliation-ஐ automate பண்றதை follow பண்ணுது; அதாவது ஒவ்வொரு prepaid order-க்கும் payment gateway உண்மையிலேயே பணத்தை pay out பண்ணுச்சான்னு check பண்ற வேலை.

```flow
title: தினசரி payment reconciliation
Schedule: காலை 6 மணி IST -> Shopify: prepaid orders, கடைசி 10 நாள்
Schedule: காலை 6 மணி IST -> Gateway: settle ஆன payments, கடைசி 3 நாள் | page பண்ணி, வேகம் கட்டுப்படுத்தி
Shopify: prepaid orders, கடைசி 10 நாள் -> Payment id-ல Merge | ரெண்டு பக்கத்துல இருந்தும் match ஆகாத items-ஐ வச்சுக்கும்
Gateway: settle ஆன payments, கடைசி 3 நாள் -> Payment id-ல Merge
Payment id-ல Merge -> Code: ஒவ்வொரு row-ஐயும் flag பண்ணு -> Sub-workflow: sheet-க்கு upsert -> Slack: summary
எந்த failure-உம் -> Error workflow | execution link-ஓட finance-ops-க்கு alert
```

## இது எப்படி வேலை செய்யுது

### Items: எல்லாத்துக்கும் அடியில இருக்குற idea

ஒவ்வொரு node-உம் **items**-ஓட ஒரு list-ஐ வாங்கி, ஒரு list-ஐ அடுத்ததுக்கு அனுப்பும். ஒவ்வொரு item-உம் ஒரு JSON record, ஒரு sheet-ஓட ஒரு row மாதிரி. பெரும்பாலான nodes ஒவ்வொரு item-க்கும் ஒரு தடவை ஓடும்: Gmail-க்கு பத்து items போனா பத்து emails. `{{ $json.email }}` மாதிரி ஒரு **expression** இப்போதைய item-ஓட ஒரு field-ஐ படிக்கும். முன்னாடி இருக்குற ஒரு node-ல இருந்து ஒரு field-ஐ படிக்க, அந்த node-ஓட பேரை சொல்லுங்க: `{{ $('Get orders').item.json.order_name }}`.

### Structure: ஒரு workflow-க்கு ஒரு job

ஒவ்வொரு workflow-ஐயும் ஒரே job-ஓட வச்சுக்கோங்க. பொதுவான steps-ஐ ஒரு **sub-workflow**-ல வைங்க: **When Executed by Another Workflow** trigger-ல start ஆகுற, **Execute Sub-workflow** node வச்சு call பண்ற ஒரு தனி workflow. Trigger-ல எந்த data வந்தாலும் ஏத்துக்காம, நீங்க எதிர்பாக்குற input fields-ஐ define பண்ணுங்க, உதாரணமா `payment_id`, `flag`. அப்போ call பண்ற node எந்த fields-ஐ fill பண்ணணும்னு சரியா list பண்ணும், ஒண்ணு missing-ஆ இருந்தா ஈஸியா கண்டுபிடிக்கலாம்.

Nodes-க்கு அவை என்ன பண்ணுதோ அதை வச்சு பேர் வைங்க, "HTTP Request 3" இல்லாம "Get prepaid orders" மாதிரி; அப்போ யார் வேணும்னாலும் canvas-ஐ படிக்கலாம்.

### Volume-உம் rate limits-உம்

பெரும்பாலான APIs results-ஐ ஒரு தடவைக்கு ஒரு **page**-ஆ return பண்ணும், ஒரு second-க்கோ ஒரு நிமிஷத்துக்கோ எத்தனை requests அனுப்பலாம்னு limit வைக்கும். மூணு tools சேர்ந்து வேலை செய்யும்:

- **Pagination** இனிமே pages இல்லைங்குற வரைக்கும் page மேல page-ஆ fetch பண்ணும். HTTP Request node-ல ஒரு pagination option இருக்கு, நிறைய app nodes-ல உங்களுக்காக page பண்ற "Return All" switch இருக்கு.
- **Batching** நீங்க எவ்வளவு வேகமா அனுப்புறீங்கன்னு கட்டுப்படுத்தும். HTTP Request node-ல ஒரு Batching option இருக்கு (ஒரு batch-க்கு எத்தனை items, batches-க்கு நடுவுல ஒரு pause). இன்னும் control வேணும்னா, ஒரு batch size கூட **Loop Over Items**-ஐயும், loop-க்குள்ள ஒரு **Wait** node-ஐயும் use பண்ணுங்க.
- **Retry On Fail**, ஒவ்வொரு node-ஓட settings-லயும் இருக்கு, fail ஆன call-ஐ திரும்ப பண்ணும். அது அதிகபட்சம் அஞ்சு tries-ஐயும், tries-க்கு நடுவுல அதிகபட்சம் அஞ்சு seconds-ஐயும் தான் allow பண்ணும், அதனால அது ஒரு சின்ன blip-ஐ handle பண்ணும்; pacing-ஐயும் இல்ல, நீண்ட outage-ஐயும் இல்ல.

Pacing rule simple கணக்கு தான். Limit ஒரு நிமிஷத்துக்கு L requests, ஒவ்வொரு batch-உம் B requests அனுப்புதுன்னா, batches-க்கு நடுவுல குறைஞ்சது B × 60 ÷ L seconds wait பண்ணுங்க. ஒரு batch-க்கு 20 requests, ஒரு நிமிஷத்துக்கு 60 limit-னா, அது 20 seconds. கொஞ்சம் margin சேருங்க, ஏன்னா ஒரு batch-க்குள்ள இருக்குற requests ஒரே நேரத்துல கிளம்பலாம்.

```flow
dir: LR
ஒரு page-ஐ request பண்ணு | 100 rows -> Rows-ஐ process பண்ணு -> இன்னும் pages இருக்கா?
இன்னும் pages இருக்கா? -[ஆமா, ஒரு pause-க்கு அப்புறம்]-> ஒரு page-ஐ request பண்ணு
இன்னும் pages இருக்கா? -[இல்ல]-> அடுத்த step
```

### Data-வை merge பண்றது, match ஆகாததை வச்சுக்குறது

**Merge** node ரெண்டு inputs-ஐ position வச்சோ, **matching fields** வச்சோ combine பண்ணும், உதாரணமா ரெண்டுலயும் வர்ற ஒரு payment id. Matching fields-க்கு, எது மிஞ்சும்னு output setting தான் முடிவு பண்ணும்:

| Output choice | என்ன வெளிய வரும் | இது மாதிரி |
| --- | --- | --- |
| Keep Matches | ரெண்டு inputs-லயும் இருக்குற items மட்டும் | ஒரு inner join |
| Keep Non-Matches | Partner இல்லாத items மட்டும் | மிச்சம் இருக்குறவை |
| Keep Everything | ரெண்டு inputs-ல இருந்தும் matches-உம் non-matches-உம் | ஒரு full outer join |
| Enrich Input 1 or 2 | ஒரு input முழுசா, கூட இன்னொண்ணுல இருந்து match ஆகுற data | ஒரு left அல்லது right join |

மேல இருக்குற labels recent versions-ல இருக்குறவை; உங்க version-ல dropdown-ஐ check பண்ணுங்க. ஒரு reconciliation-ல match ஆகாத items தான் findings, அதனால Keep Matches ஒவ்வொரு problem-ஐயும் மறைச்சிடும். Keep Everything-ஐ தேர்ந்தெடுங்க; Keep Non-Matches மட்டும் use பண்ணா, amounts-ஐ இன்னும் check பண்ண வேண்டிய matched rows-உம் drop ஆயிடும். இன்னும் ரெண்டு traps: ரெண்டு inputs-லயும் `amount`-ங்குற field இருந்தா ஒண்ணு இன்னொண்ணை overwrite பண்ணிடும், அதனால முதல்ல ஒரு **Edit Fields** node வச்சு fields-ஐ rename பண்ணுங்க. அப்புறம், ரெண்டு பக்கத்துலயும் unique-ஆ இருக்குற ஒரு key-ல match பண்ணுங்க, payment id மாதிரி; customer-ஓட phone number மாதிரி repeat ஆகக்கூடிய ஒண்ணுல இல்ல.

### Code nodes

ஒரு **Code** node JavaScript அல்லது Python-ஐ ஓட்டும். Default-ஆன "Run Once for All Items" mode-ல, அது `$input.all()` வச்சு எல்லா items-ஐயும் படிக்கும், `$('Node name').all()` வச்சு இன்னொரு node-ஓட items-ஐ படிக்கலாம், objects-ஓட ஒரு list-ஐ return பண்ணணும், ஒவ்வொண்ணுலயும் ஒரு `json` key இருக்கணும். இது இந்திய முறையில எழுதின ஒரு amount-ஐ சேர்க்குது:

```js
// Mode: Run Once for All Items
return $input.all().map((item) => ({
  json: {
    ...item.json,
    amount_text: (item.json.amount / 100).toLocaleString('en-IN', { style: 'currency', currency: 'INR' }),
  },
}));
```

12500000 paise amount-க்கு `amount_text` "₹1,25,000.00". Python தேவைப்பட்டா தவிர JavaScript-ஐயே prefer பண்ணுங்க: n8n 2.0-ல இருந்து Code node native Python-ஐ ஓட்டுது, அது items-ஐ `_items`-ஆ படிக்கும், n8n-ஓட மத்த built-in helpers எதுவும் அதுல இல்ல. Code nodes-ஐ சின்னதா, comments கூட வைங்க. ஒண்ணு ஒரு screen-ஐ தாண்டி வளர்ந்தா, அது ஒரு node-க்குள்ள ஒளிஞ்சிருக்குற ஒரு சின்ன service, அங்க அதை test பண்றது கஷ்டம்.

### Schedules-உம் time zones-உம்

ஒரு Schedule trigger workflow-ஓட time zone-ல fire ஆகும். `GENERIC_TIMEZONE` variable-ஐ set பண்ணலைன்னா self-hosted instance default-ஆ America/New_York-ல இருக்கும், அதனால ஒரு "காலை 6 மணி" job இந்திய மதியத்துல ஓடலாம். Workflow-ஓட settings-ல time zone-ஐ Asia/Kolkata-வா set பண்ணுங்க, அப்புறம் executions list-ல run times-ஐ check பண்ணுங்க. `$now` மாதிரி expressions-உம் அதே setting-ஐ follow பண்ணும், அதனால "நேத்து"-னா இந்தியால நேத்து.

### எப்போ AI use பண்ணணும், எப்போ கூடாது

Rules-ஆல வேலை செய்ய முடியாத இடத்துல மட்டும் AI node-ஐ use பண்ணுங்க: free text-ஐ படிக்குறது. ஒரு நல்ல உதாரணம்: ஒரு wholesale buyer-ஓட email "paid ₹48,300 against invoices 112 and 118, less TDS"-னு சொல்லுது. Structured output கூட ஒரு **Information Extractor** அதை invoice numbers-ஆவும் ஒரு amount-ஆவும் மாத்தலாம், அப்புறம் ஒரு ஆள் confirm பண்றதுக்கு முன்னாடி ஒரு IF node அதை உங்க invoice list கூட check பண்ணும். Rule: ஒரு IF, Switch அல்லது Code node முடிவு பண்ண முடிஞ்சா, model-கிட்ட கேக்காதீங்க. பண mismatches-க்கு "reasons" எழுதுற ஒரு model செலவை கூட்டும், சரியா தோணுற ஒரு காரணத்தை கற்பனை பண்ணியும் சொல்லலாம். அடுத்த tool call முந்தைய call என்ன return பண்ணுச்சுங்குறதை பொறுத்து இருக்குற tasks-க்கு மட்டும் AI Agent-ஐ வச்சுக்கோங்க, "Automation with n8n" lesson-ல சொன்ன safeguards கூட.

### Reliability

| Practice | ஏன் |
| --- | --- |
| API nodes-ல Retry On Fail | சின்ன network errors ரெண்டாவது try-ல தானா சரியாயிடும் |
| Idempotent writes | ஒரு unique id-ல upsert, அதனால ஒரு rerun rows-ஐ duplicate பண்ணாம update பண்ணும் |
| Overlap ஆகுற time windows | நேத்து மட்டும் இல்லாம சில நாள் data-வை fetch பண்ணுங்க, அப்போ ஒரு missed run அடுத்த நாளே தானா சரியாயிடும் |
| ஒரு error workflow | ஒரு Error Trigger-ல start ஆகி, workflow, fail ஆன node, execution link-ஐ team-க்கு post பண்ணும் |
| Item-count checks | Rows return பண்ண வேண்டிய ஒரு step எதுவுமே return பண்ணலைன்னா alert; zero items ஒரு branch-ஐ நிறுத்திடும், அதனால முதல்ல Always Output Data-வை on பண்ணுங்க |

Error workflow-ஐ main workflow-ஓட settings-ல set பண்ணுங்க, error workflow-ஐயும் publish பண்ணுங்க. அது automatic runs-க்கு மட்டும் தான் fire ஆகும், editor-ல நீங்களே கையால start பண்ற runs-க்கு இல்ல, அதனால ஒரு short schedule வச்சு test பண்ணுங்க.

### Pinned data வச்சு testing

Gateway call மாதிரி ஒரு node-ஓட output-ஐ **Pin** பண்ணுங்க, editor API-ஐ திரும்ப call பண்ணாம அதையே reuse பண்ணும். Production runs pinned data-வை ignore பண்ணும். ஒரு refund, வழக்கத்துக்கு மாறான paise-ல ஒரு amount, payment id இல்லாத ஒரு order மாதிரி சிக்கலான pinned cases-ஓட ஒரு set வச்சுக்கோங்க, ஒவ்வொரு மாற்றத்துக்கு அப்புறமும் அவற்றை rerun பண்ணுங்க.

### Maintainability

November 2026 நிலவரப்படி, n8n-ஓட built-in Git source control அதோட Business, Enterprise plans-ல இருக்கு. மத்த plans-ல workflows-ஐ JSON-ஆ export பண்ணி நீங்களே Git-ல commit பண்ணுங்க. தனி credentials கூட ஒரு தனி test instance அல்லது project வச்சுக்கோங்க, ஒரு test run pass ஆன பிறகு தான் production-ஐ மாத்துங்க.

### Self-hosting basics

n8n open source இல்ல. அதோட Sustainable Use License உங்க சொந்த business-க்கு self-host பண்ண allow பண்ணுது; client work பத்தி "Automation with n8n" lesson சொல்லுது. உதாரணமா Docker வச்சு self-host பண்ணா, நீங்க தான் operator:

- **Encryption key.** Save பண்ண credentials-ஐ n8n தானே generate பண்ற ஒரு key வச்சு encrypt பண்ணும். Data volume-ஐ வச்சுக்கலைன்னா, rebuild பண்ண container ஒரு புது key-ஐ உருவாக்கும், ஒவ்வொரு credential-உம் படிக்க முடியாததா ஆயிடும். `N8N_ENCRYPTION_KEY`-ஐ நீங்களே set பண்ணி, database கூட அதையும் backup பண்ணுங்க.
- **Disk.** Execution data default-ஆ 14 நாள் அல்லது 10,000 executions-க்கு அப்புறம் prune ஆகும். Pruning-ஐ on-லயே வைங்க, ஒரு busy workflow-ஓட ஒவ்வொரு successful run-க்கும் full data-வை save பண்ணாதீங்க.
- **Database-உம் scale-உம்.** Serious-ஆன எதுக்கும் Postgres use பண்ணுங்க. High volume-க்கு, **queue mode** Redis வச்சு runs-ஐ தனி worker processes-க்கு குடுக்கும்.
- **Updates.** n8n-ல critical security flaws இருந்திருக்கு, January 2026-ல ஒண்ணு உட்பட. Security releases-ஐ சில நாட்களுக்குள்ள apply பண்ணுங்க.

## ஒரு worked example

Bengaluru-ல ஒரு D2C skincare brand Shopify-ல ஒரு நாளைக்கு சுமார் 1,500 orders விக்குது. உதாரணமா, சுமார் 60% Razorpay மூலமா prepaid, மீதி cash on delivery-ன்னு வச்சுக்கோங்க. ஒவ்வொரு காலையும், finance-ல இருக்குற Kavya ஒவ்வொரு prepaid order-உம் pay out ஆச்சான்னு check பண்ண ரெண்டு மணி நேரம் செலவு பண்றாங்க. Gateway பத்தின மூணு facts design-ஐ தீர்மானிக்குது:

- **Settlements லேட்டா வரும்.** Razorpay-ஓட standard domestic cycle capture-ல இருந்து T+2 working days, அது merchant-க்கு merchant மாறும். நேத்தைய orders இன்னும் settle ஆகல, அதனால நேத்தை நேத்தோட match பண்ணா எல்லாமே flag ஆகும்.
- **Rows payment id வச்சு key பண்ணப்பட்டிருக்கு.** ஒவ்வொரு settlement row-லயும் ஒரு `entity_id` (`pay_`-ல start ஆகுற ஒரு payment id), `amount`, `fee`, `tax`, `credit` இருக்கு. அதோட `order_id` Razorpay-ஓட சொந்த order id, Shopify order number இல்ல. அதனால store checkout-லயே ஒவ்வொரு order-லயும் Razorpay payment id-ஐ save பண்ணணும்; அது எங்க இருக்கும்ங்குறது உங்க checkout app-ஐ பொறுத்தது.
- **Amounts paise-ல இருக்கு, fees கழிக்கப்படும்.** `amount` paise-ல gross payment. `tax` காட்டுற GST ஏற்கனவே `fee`-ல சேர்ந்திருக்கு, `credit`-னா `amount`-ல இருந்து `fee`-ஐ கழிச்சது. `credit`-ஐ order total கூட compare பண்ணா ஒவ்வொரு order-உம் flag ஆகும். அதுக்கு பதிலா `amount`-ஐ compare பண்ணுங்க, fee-ஐ தனியா check பண்ணுங்க.

Kavya-வோட workflow, அதோட time zone Asia/Kolkata-வா set பண்ணி:

| # | Node | என்ன பண்ணும் |
| --- | --- | --- |
| 1 | Schedule trigger, Sheets | IST காலை 6 மணிக்கு ஓடும்; மேல் branch-ல இருக்குற ஒரு Sheets node, அதனால அது முதல்ல ஓடி, results sheet-ஐ "Read results"-ஆ படிக்கும் |
| 2 | Shopify, அப்புறம் Filter | Return All வச்சு கடைசி 10 நாள் orders-ஐ எடுக்கும், prepaid ஆனவற்றை வச்சுக்கும் |
| 3 | HTTP Request | கடைசி 3 நாளுக்கான settlement rows-ஐ page by page எடுக்கும், சுமார் ஒரு second-க்கு ஒரு request |
| 4 | Filter, Edit Fields | Payment rows-ஐ வச்சுக்கும் (refunds-க்கு தனி type இருக்கு), எதுவும் clash ஆகாம fields-ஐ rename பண்ணும் |
| 5 | Merge | `payment_id`-ல match பண்ணும், Keep Everything |
| 6 | Code | ஏற்கனவே ok-ன்னு mark ஆன payments-ஐ skip பண்ணும், மீதியை flag பண்ணும் (கீழ பாருங்க) |
| 7 | Sub-workflow "Upsert result" | Sheets Append or Update Row, `payment_id`-ல match பண்ணி |
| 8 | IF, Slack | ஒரு working day-ல step 3-க்கு எந்த rows-உம் கிடைக்கலைன்னா alert; இல்லைன்னா counts-ஐயும் sheet link-ஐயும் post பண்ணும் |
| + | Error workflow | Execution link-ஓட finance-ops-க்கு alert |

Step 6-ல இருக்குற Code node:

```js
// Mode: Run Once for All Items. Each item is one merged row.
const done = new Set($('Read results').all()
  .filter((i) => i.json.flag === 'ok').map((i) => i.json.payment_id));
const out = [];
for (const item of $input.all()) {
  const r = item.json;
  if (done.has(r.payment_id)) continue; // never downgrade an ok row
  const orderPaise = Math.round(Number(r.order_total) * 100);
  let flag = 'ok';
  if (!r.order_name) {
    flag = 'settled, no order found';
  } else if (!r.settlement_id) {
    const days = $now.diff(DateTime.fromISO(r.paid_at), 'days').days;
    flag = days > 5 ? 'settlement overdue' : 'waiting';
  } else if (r.gateway_amount !== orderPaise) {
    flag = 'amount differs';
  } else if (r.gateway_fee > Math.ceil(r.gateway_amount * 0.0236)) {
    flag = 'fee above contract'; // 2% plus 18% GST; use your rate
  }
  const paise = r.gateway_amount ?? orderPaise;
  const amount_text = (paise / 100).toLocaleString('en-IN', { style: 'currency', currency: 'INR' });
  out.push({ json: { ...r, flag, amount_text } });
}
return out;
```

Shopify "1499.50" மாதிரி text-ஆ அனுப்புற order total-ஐ `Math.round` முழு paise-ஆ மாத்தும், அதனால ₹1.15-க்கு 114.99999 மாதிரி சின்ன decimal errors ஒரு false alarm-ஐ உருவாக்க முடியாது. `Math.ceil` fee rounding-க்கு இடம் குடுக்கும். 2% rate ஒரு உதாரணம் மட்டும் தான்; உங்க contract-ல இருக்குற rate-ஐ use பண்ணுங்க. உதாரணமா, 2%-ல ஒரு ₹1,000 UPI payment-க்கு fee ₹20, கூட ₹3.60 GST, அதனால `fee` 2360 paise, `credit` 97640.

ஒவ்வொரு flag-உம் ஒரு தெளிவான action-க்கு கொண்டு போகும்; அதை எழுதுறது ஒரு template, model இல்ல:

| Flag | பொதுவா என்ன அர்த்தம் | யார் action எடுப்பாங்க |
| --- | --- | --- |
| waiting | Pay ஆயிடுச்சு, normal settlement window-க்குள்ள இருக்கு | இப்போதைக்கு யாரும் இல்ல |
| settlement overdue | 5 நாளுக்கு மேல ஆச்சு, இன்னும் settle ஆகல | Finance அதை gateway கிட்ட எழுப்பும் |
| amount differs | Payment-க்கு அப்புறம் order edit ஆச்சு, அல்லது ஒரு part refund | Finance order history-ஐ check பண்ணும் |
| settled, no order found | இன்னொரு channel-ல இருந்து வந்த payment, அல்லது missing payment id | Store team order record-ஐ சரி பண்ணும் |
| fee above contract | தப்பான pricing plan apply ஆகியிருக்கு | Finance அதை gateway கிட்ட எழுப்பும் |

Writes `payment_id`-ல upserts-ங்குறதால, ஒரு row duplicates-ஆ குவியாம, பின்னாடி ஒரு நாள் காலையில "waiting"-ல இருந்து "ok"-க்கு மாறும். Skip முக்கியம்: ஒரு settlement 3-day window-ல இருந்து வெளிய போனதும், skip இல்லைன்னா அதோட order settle ஆகாத மாதிரி தெரிஞ்சு திரும்ப "overdue"-ன்னு flag ஆகும். 10-day order window லேட்டா settle ஆகுற payments-ஐ cover பண்ணும். 5-day limit ஒரு trade-off: ஒரு நீண்ட bank-holiday weekend சில false alarms-ஐ உருவாக்கலாம்; ஒரு உண்மையான problem-ஐ miss பண்றதுக்கு பதிலா team அதை ஏத்துக்குது.

**ஒரு மோசமான காலை.** ஒரு நாள் காலை 6 மணிக்கு gateway-ஓட API errors return பண்ணுச்சு. Retries fail ஆச்சு, error workflow execution link-ஓட alert-ஐ post பண்ணுச்சு. Kavya காலை 9 மணிக்கு அதை rerun பண்ணாங்க. Upserts-ஆல duplicates இல்ல, ஒவ்வொரு run-உம் மூணு நாள் data-வை fetch பண்றதால, ஒரு நாள் முழுசா miss ஆயிருந்தாலும் அடுத்த நாள் காலையில cover ஆயிருக்கும்.

## பொதுவான தப்புகள்

- **ஒரே ஒரு ராட்சத workflow.** பொதுவான steps-ஐ defined inputs கூட, பேர் வச்ச sub-workflows-ஆ பிரிங்க.
- **Rate limits-ஐ கண்டுக்காம விடுறது.** Page, batch, wait பண்ணுங்க; retries-னா pacing இல்ல.
- **Reconciliation-க்கு Keep Matches வச்சு merge பண்றது.** நீங்க தேடுற problems-ஐயே அது சத்தமில்லாம drop பண்ணிடும்.
- **Net-ஐ gross கூட, அல்லது rupees-ஐ paise கூட compare பண்றது.** ஒரே மாதிரியானதை ஒரே மாதிரியானதோட, முழு paise-ல compare பண்ணுங்க.
- **நேத்தை நேத்தோட match பண்றது.** Settlements லேட்டா வரும்; overlap ஆகுற windows-ஐ use பண்ணுங்க.
- **Idempotent இல்லாத writes.** Plain appends ஒவ்வொரு rerun-லயும் duplicates-ஐ உருவாக்கும்.
- **Time zone-ஐ default-லயே விடுறது.** Workflow settings-ல Asia/Kolkata-வை set பண்ணுங்க.
- **ஒரு rule போதுமான இடத்துல AI-ஐ use பண்றது.** பணத்தை explain பண்ண ஒரு model-ஐ விடவே விடாதீங்க.
- **Error workflow-ஐ கையால test பண்றது.** அது automatic runs-க்கு மட்டும் தான் fire ஆகும்.
- **Encryption key-ஐ தொலைக்குறது.** தேவைப்படுறதுக்கு முன்னாடியே database கூட அதை backup பண்ணுங்க.

## Practice

கீழ link பண்ணியிருக்குற n8n-ஓட N8N102 Integrations course-ஐ முடிங்க, hosting overview-ஐ படிங்க.

1. **Volume.** ஒரு API அல்லது sheet-ல இருந்து குறைஞ்சது 300 rows-ஐ page பண்ணி, ஒரு Wait கூட batches-ஆ process பண்ற ஒரு workflow-ஐ build பண்ணுங்க. Limit-ல இருந்து wait-ஐ கணக்கு போட்டு, அந்த கணக்கை ஒரு sticky note-ல எழுதுங்க.
