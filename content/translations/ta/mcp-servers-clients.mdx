## இது என்ன

முன்னாடி ஒவ்வொரு AI app-க்கும் ஒவ்வொரு tool-க்கும் தனி custom code தேவைப்பட்டுச்சு: chat app-ல ticketing system-க்கு ஒரு integration, coding assistant-ல இன்னொண்ணு, agent-ல வேற ஒண்ணு. **Model Context Protocol** (MCP) இதை சரி பண்ற ஒரு open standard. ஒரு system-ஐ ஒரு தடவை **MCP server**-ஆ wrap பண்ணுங்க; அப்புறம் எந்த **MCP client**-உம், அதாவது ஒரு desktop assistant, ஒரு IDE, இல்ல உங்க சொந்த agent, அதை கண்டுபிடிச்சு use பண்ணலாம்.

ஒரு MCP server மூணு வகையான விஷயங்களை offer பண்ணலாம்:

- **Tools**: model call பண்ணக்கூடிய actions, உதாரணம் `search_tickets`, `create_invoice`.
- **Resources**: app context-க்குள்ள படிக்கக்கூடிய data, உதாரணம் ஒரு file, ஒரு record, ஒரு schema.
- **Prompts**: user தேர்ந்தெடுக்கக்கூடிய reusable prompt templates.

```flow
dir: LR
title: ஒரு server, பல hosts: ஒவ்வொரு app-க்கும் புது integration வேண்டாம்
IDE assistant, ஒரு host -[client]-> Maintenance-log server | tools: find_machine, get_maintenance_history, log_observation
Chat assistant, ஒரு host -[client]-> Maintenance-log server
Chat assistant, ஒரு host -[client]-> Spare-parts server
```

இந்த lesson-ல Pune-ல இருக்குற ஒரு manufacturing company-ஐ follow பண்றோம். அங்க engineers ஒரே maintenance data-ல ரெண்டு வேற AI assistants use பண்றாங்க.

## இது எப்படி work ஆகுது

**Roles.** *Host*-னா user வேலை செய்யுற AI application. அதுக்குள்ள ஒரு MCP *client* ஒவ்வொரு *server*-க்கும் ஒரு connection வச்சிருக்கும். Client ஒரு server-கிட்ட அது என்ன offer பண்ணுதுன்னு கேக்கும், tool list-ஐ model-க்கு கொடுக்கும். Model ஒரு tool-ஐ call பண்ணும்போது, client அந்த call-ஐ சரியான server-க்கு அனுப்பி, result-ஐ திருப்பி கொண்டு வரும்.

**Transports.** Local server அதே machine-ல ஒரு process-ஆ ஓடி, standard input, output வழியா பேசும்; desktop tools-க்கும் developer machines-க்கும் இது பொருந்தும். Remote server ஒரு web service-ஆ ஓடி HTTP வழியா பேசும்; shared company systems-க்கு இது பொருந்தும், முறையான authentication வேணும், பெரும்பாலும் OAuth.

**Server build பண்றது.** Python, TypeScript, மத்த languages-க்கு official SDKs இருக்கு. Python-ல ஒரு minimal server சில வரிகள் தான்:

```python
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("tickets")

@mcp.tool()
def search_tickets(query: str, status: str = "open") -> list[dict]:
    """Search support tickets by keywords. status is 'open' or 'closed'. Returns up to 10."""
    return ticket_db.search(query, status=status, limit=10)

if __name__ == "__main__":
    mcp.run()
```

Function-ஓட பேர், type hints, docstring எல்லாம் tool-ஓட schema ஆகிடும். அதனால முந்தைய lesson-ல சொன்ன tool design advice இங்கயும் நேரா பொருந்தும்.

**Security.** MCP server உண்மையான systems-க்கு access இருக்குற code. கேளுங்க: யார் எழுதினது, எதை தொட முடியும், எந்த credentials use பண்ணுது, user-ஓட பேர்ல (அவங்க permissions-ஐ மதிச்சு) act பண்ணுதா, இல்ல எல்லா அதிகாரமும் இருக்குற service account-ஆ? Tool descriptions-உம் results-உம் model-க்குள்ள போகுது, அதனால ஒரு தீய server அல்லது விஷமாக்கப்பட்ட record prompt injection-ஐ சுமக்கலாம். Least privilege use பண்ணுங்க, third-party servers-ஐ install பண்றதுக்கு முன்னாடி review பண்ணுங்க, ஒவ்வொரு call-ஐயும் log பண்ணுங்க.

**Local vs remote servers:**

| அம்சம் | Local (standard input, output) | Remote (HTTP) |
| --- | --- | --- |
| எங்க ஓடும் | User-ஓட machine-ல | ஒரு company server அல்லது cloud-ல |
| எதுக்கு நல்லது | Developer tools, local files | Shared company systems |
| Authentication | User-ஓட சொந்த machine access | OAuth, முடிஞ்சா single sign-on வழியா |
| Updates | ஒவ்வொரு user-உம் தன் copy-ஐ update பண்ணணும் | எல்லாருக்கும் சேர்த்து ஒரு தடவை update |
| Logging | ஒவ்வொரு machine-லயும் | Central audit log |

**எந்த server-க்கும் கேக்க வேண்டிய security கேள்விகள்:**

| கேள்வி | ஏன் முக்கியம் |
| --- | --- |
| யார் எழுதினது, code-ஐ படிக்க முடியுமா? | நீங்க கொடுக்குற access-ஓட தான் server ஓடும் |
| எந்த systems, data-வை தொட முடியும்? | தப்பு அல்லது attack-ஓட சேதத்தை வரம்பிடும் |
| User-ஓட பேர்ல act பண்ணுதா, service account-ஆ? | User permissions apply ஆகுமான்னு முடிவு பண்ணும் |
| எந்த tools எழுதும் அல்லது அனுப்பும்? | அவற்றுக்கு tight limits அல்லது approval வேணும் |
| Calls user, tool, arguments-ஓட log ஆகுதா? | Incidents-ஐ investigate பண்ண தேவை |

**Tools-ஐ design பண்றது.** எந்த agent tool-க்கும் சொன்ன அதே advice: கம்மியான, task வடிவ tools, தெளிவான descriptions, உதவுற errors. பல வேற hosts ஒரே server-ஐ use பண்றதால, நல்ல descriptions இன்னும் முக்கியம்; ஒரு மங்கலான tool-ஐ ஈடுகட்ட ஒவ்வொரு host-லயும் ஒரு prompt-ஐ tune பண்ண முடியாது. Write tools-ஐ narrow-ஆ வையுங்க, உதாரணம் `log_observation` ஒரு notes table-ல மட்டும் எழுதணும், அப்போ குழம்பிப்போன அல்லது manipulate ஆன model-ஆலயும் அதிக தீமை பண்ண முடியாது.

**Tools தவிர மத்தது.** ஒரு server மூணு வகை விஷயங்களை offer பண்ணலாம். **Tools** model call பண்ணக்கூடிய functions. **Resources** host படிச்சு காட்டக்கூடிய அல்லது attach பண்ணக்கூடிய data, உதாரணம் ஒரு file, ஒரு ticket, ஒரு database row, ஒரு URI-ஆ முகவரி இடப்பட்டவை. **Prompts** user ஒரு menu-ல இருந்து தேர்ந்தெடுக்கக்கூடிய reusable templates, "இந்த ticket thread-ஐ summarise பண்ணு" மாதிரி. Tools model-ஆல இயக்கப்படும்; resources, prompts-ஐ பெரும்பாலும் app அல்லது user தேர்ந்தெடுப்பாங்க.

```python
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("tickets")

@mcp.resource("ticket://{ticket_id}")
def ticket(ticket_id: str) -> str:
    """The full text of one ticket."""
    t = ticket_db.get(ticket_id)
    return f"{t.title}\n\n{t.body}"

@mcp.prompt()
def summarise_ticket(ticket_id: str) -> str:
    return f"Summarise ticket {ticket_id} in five bullets and list open questions."
```

**உங்க சொந்த client எழுதுறது.** Desktop assistants, code editors மாதிரி hosts-ல clients ஏற்கனவே இருக்கும், ஆனா அதே SDK வச்சு உங்க சொந்த Python code-ல இருந்தும் connect பண்ணலாம்:

```python
import asyncio
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

async def main():
    server = StdioServerParameters(command="python", args=["tickets_server.py"])
    async with stdio_client(server) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()
            tools = await session.list_tools()
            print([t.name for t in tools.tools])
            result = await session.call_tool("search_tickets", {"query": "refund", "status": "open"})
            print(result.content[0].text)

asyncio.run(main())
```

உங்க app `tools.tools`-ஐ tool definitions-ஆ model-க்கு கொடுத்து, model-ஓட tool calls-ஐ `session.call_tool`-க்கு route பண்ணும்; tool-calling lesson-ல இருந்த அதே round trip.

**Model-ஐ connect பண்றதுக்கு முன்னாடி server-ஐ test பண்ணுங்க.** `npx @modelcontextprotocol/inspector` வச்சு ஓட்டுற MCP Inspector ஒரு page-ஐ திறக்கும்; அங்க ஒரு server-ஓட tools-ஐ list பண்ணலாம், உங்க சொந்த arguments-ஓட call பண்ணலாம், raw results-ஐ பார்க்கலாம். பெரும்பாலான bugs ஒரு chat வழியா பார்க்குறதை விட இங்க சீக்கிரம் தெரிஞ்சிடும்.

**MCP-க்கே உரிய threats.**

- **Tool poisoning**: ஒரு tool description அல்லது result, `~/.ssh`-ஐ படிக்கிறது, ஒரு URL-க்கு data அனுப்புறது மாதிரி வேற ஏதோ பண்ண model-கிட்ட சொல்லும். Third-party servers-ஓட descriptions-ஐ படிங்க, results-ஐ data-வா நடத்துங்க.
- **Approve பண்ணதுக்கு அப்புறம் மாறுறது**: நீங்க approve பண்ண server பின்னாடி தன் tool descriptions-ஐ update பண்ணலாம். Versions-ஐ pin பண்ணி, மாற்றங்களை review பண்ணுங்க.
- **பேர் மோதல்கள்**: ஒரே பேர்ல tool offer பண்ற ரெண்டு servers, எது ஓடுதுங்கிறதுல model-ஐ குழப்பலாம். Tool பேர்களுக்கு முன்னாடி server-ஓட நோக்கத்தை prefix-ஆ வையுங்க.
- **ரொம்ப அதிக reach**: ஒரு company-wide token இருக்குற ஒரு server எல்லாத்தையும் வெளிய காட்டலாம். Signed-in user-ஓட பேர்ல act பண்ற servers-ஐ, task-க்கு ஏத்த narrow OAuth scopes-ஓட விரும்புங்க.

**Browser-லயே try பண்ணுங்க.** MCP messages JSON-RPC. இது ஒரு client அனுப்புற tool call-ஐ build பண்ணி, reply-ஓட வடிவத்தை check பண்ணுது.

```python
import json

request = {"jsonrpc": "2.0", "id": 7, "method": "tools/call",
           "params": {"name": "search_tickets", "arguments": {"query": "refund", "status": "open"}}}
reply = {"jsonrpc": "2.0", "id": 7,
         "result": {"content": [{"type": "text", "text": "T-1042: refund delayed"}], "isError": False}}

print(json.dumps(request, indent=2))
assert reply["id"] == request["id"], "replies must match the request id"
print("tool said:", reply["result"]["content"][0]["text"])
```

## ஒரு worked example

Pune-ல ஒரு manufacturing company-ஓட engineers தங்க IDE-ல ஒரு AI assistant-ஐயும், chat tool-ல இன்னொண்ணையும் use பண்றாங்க. ரெண்டுக்கும் maintenance log database-க்கு access வேணும்.

ரெண்டு integrations-க்கு பதிலா, மூணு tools இருக்குற ஒரு remote MCP server-ஐ build பண்றீங்க: `find_machine` (tag அல்லது பேர் வச்சு), `get_maintenance_history` (ஒரு machine-ஓட கடைசி N events), `log_observation` (ஒரு note சேர்க்கும்; ஒரு notes table-ல மட்டும் எழுதும்). அது ஒவ்வொரு user-ஐயும் company-ஓட single sign-on வழியா authenticate பண்ணி, அந்த user-ஓட சொந்த permissions-ஓட database-ஐ query பண்ணும்; அதனால ஒரு contractor தன் plant-ஐ மட்டும் பார்ப்பார்.

ரெண்டு assistants-உம் அதே server-ஓட connect ஆகும். ஒரு engineer chat-ல கேக்குறார்: "CNC-14-ஓட spindle கடைசியா எப்போ service பண்ணாங்க, அதுக்கு அப்புறம் யாராவது vibration report பண்ணாங்களா?" Assistant `find_machine`, அப்புறம் `get_maintenance_history`-ஐ call பண்ணி, log-ல இருக்குற dates-ஓடயும் பேர்களோடயும் பதில் சொல்லும். ஒவ்வொரு call-உம் server-ஓட audit log-ல user, tool, arguments-ஓட தெரியும்.

பின்னாடி IT ஒரு புது spare-parts system-ஐ சேர்க்கும்போது, ரெண்டாவது MCP server-ஐ சேர்க்குறாங்க; assistants-ல எந்த மாற்றமும் இல்லாம, ரெண்டுக்கும் அந்த tools கிடைக்குது.

| நடந்தது | என்ன ஆச்சு |
| --- | --- |
| Engineer CNC-14 பத்தி கேக்குறார் | Chat assistant find_machine, அப்புறம் get_maintenance_history-ஐ call பண்ணுச்சு |
| Contractor வேற plant பத்தி கேக்குறார் | Server-ஓட per-user permissions எதுவும் திருப்பல |
| Audit review | ஒவ்வொரு call-உம் user, tool, arguments-ஓட list ஆச்சு |
| புது spare-parts system | ரெண்டாவது server சேர்த்தாங்க; ரெண்டு assistants-உம் அதோட tools-ஐ பெற்றுச்சு |

## பொதுவா பண்ற தப்புகள்

- **தெரியாத servers-ஐ install பண்றது.** Third-party server நீங்க கொடுக்குற எந்த access-ஓடயும் ஓடும். Code-ஐ படிங்க அல்லது நம்பகமான sources-ஐ use பண்ணுங்க.
- **ஒரே super-user credential.** Server user-ஓட சொந்த permissions-ஐ புறக்கணிச்சா, ஒவ்வொரு user-உம் எல்லாத்தையும் தொடலாம்.
- **முழு database-ஐயும் திறந்து விடுறது.** Users database administrators இல்லன்னா, `run_sql` tool இல்லாம task வடிவ tools-ஐ offer பண்ணுங்க.
- **Tool results-ஐ நம்பிக்கையானதா எடுத்துக்கிறது.** ஒரு ticket அல்லது document-ல இருக்குற text-ல injected instructions இருக்கலாம்; host அதை data-வா நடத்தணும்.
- **Logging இல்லாம இருக்கிறது.** Tool calls-ஓட பதிவு இல்லாம, assistant என்ன பண்ணுச்சுன்னு investigate பண்ண முடியாது.
- **Third-party servers-ஓட tool descriptions-ஐயும் code-ஐயும் படிக்காம install பண்றது.**
- **Pin பண்ணாத server versions.** பின்னாடி வர்ற update tools என்ன பண்ணுது அல்லது என்ன சொல்லுதுன்னு மாத்தலாம்.
- **எல்லாருக்கும் ஒரே service-account token.** User permissions apply ஆகாம போயிடும்.

## MCP தேவையில்லாத நேரங்கள்

- **ஒரு app, அதுக்கு மட்டும் சில tools**: code-ல சாதாரண tool definitions இன்னும் simple.
- **Fixed workflows**, உங்க code functions-ஐ நேரா call பண்ணும், எந்த model-உம் tools-ஐ தேர்ந்தெடுக்காது.
- **ஒவ்வொரு புது connection-க்கும் security review தேவைப்படுற கடுமையான environments**: ஒரே in-process tool set-ஓட ஆரம்பிச்சு, tools shared ஆனப்புறம் MCP-க்கு மாறுங்க.

பல hosts அல்லது agents-க்கு ஒரே tools தேவைப்படும்போது, அல்லது users தங்க இருக்குற assistants-ஐ உங்க systems-ஓட plug பண்ணணும்னு நீங்க நினைக்கும்போது MCP பலன் தரும்.

## Demo-ல இருந்து production-க்கு

- **Remote servers-ஐ OAuth-க்கு பின்னாடி ஓட்டுங்க**, narrow scopes-ஓட, முடிஞ்சா company-ஓட single sign-on வழியா.
- **ஒவ்வொரு call-ஐயும் central-ஆ log பண்ணுங்க**: user, tool, arguments, result size-ஓட.
- **Server versions-ஐ pin பண்ணி review பண்ணுங்க**, tool descriptions-ஓட மாற்றங்கள் உட்பட.
- **Company-க்கு approved-server list வச்சிருங்க**, மத்ததை block பண்ணுங்க.
- **ஒவ்வொரு tool-க்கும் rate-limit, timeout வையுங்க**, write tools-க்கு approval கட்டாயமாக்குங்க.

## Practice பண்ணுங்க

Anthropic-ஓட இலவச Introduction to Model Context Protocol course-ஐ எடுங்க, இல்லன்னா official introduction-ஐயும் ஒரு server quickstart-ஐயும் படிங்க.

1. நீங்க விரும்புற ஒரு சின்ன SQLite database-ஐ (books, fees, appointments) வச்சு, ரெண்டு tools இருக்குற ஒரு local MCP server-ஐ build பண்ணுங்க.
2. அதை ஒரு MCP-capable client-ஓட connect பண்ணி, ரெண்டு tools-உம் தேவைப்படுற கேள்விகளை கேளுங்க.
3. ஒரு table-ல மட்டும் insert பண்ற ஒரு write tool-ஐ சேர்த்து, ஒவ்வொரு call-ஐயும் ஒரு file-ல log பண்ணுங்க; ஒரு record-ல ஒரு prompt injection-ஐ மறைச்சு வச்சு, உங்க client அதை எப்படி handle பண்ணுதுன்னு பாருங்க.
4. உங்க server-ஐ MCP Inspector-ல திறந்து, ஒவ்வொரு tool-ஐயும் தப்பான arguments-ஓட call பண்ணி, model recover ஆக உதவாத ஒவ்வொரு error message-ஐயும் சரி பண்ணுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** host, client, server-ஐ explain பண்ண முடியும், உங்க server ஒரு உண்மையான client-ல வேலை செய்யுறதை காட்ட முடியும், எந்த MCP server-க்கும் நீங்க கேக்குற மூணு security கேள்விகளை சொல்ல முடியும்.
