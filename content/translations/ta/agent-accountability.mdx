## இது என்ன

**Accountability**-னா, ஒரு agent எடுக்குற எந்த action-க்கும், யாராவது நாலு கேள்விகளுக்கு பதில் சொல்ல முடியணும். யார் பொறுப்பு? Agent என்ன செய்ய அனுமதி இருந்துச்சு? அது ஏன் அப்படி செஞ்சுது? தப்பை எப்படி சரி பண்ணுவோம்? Agents பொறுப்பை சுமக்காது; மனுஷங்களும் organisations-உம் தான் சுமக்கணும்.

Governance frameworks இதை மையத்துல வைக்கும். NIST AI Risk Management Framework-ஓட "govern" function தெளிவான roles, responsibilities-ஐ கேக்குது. EU AI Act, high-risk systems-ஓட providers, deployers-க்கு human oversight, record-keeping, பெயர் போட்ட கடமைகளை கட்டாயமாக்குது.

```flow
title: Accountability chain
Business owner | scope-ஐ முடிவு பண்ணி, results-க்கு பதில் சொல்றாங்க -> Agent card | purpose, tools, தானா செய்யலாம், approval வேணும், செய்யவே கூடாது, limits, evals
Technical owner | run பண்ணி, records வச்சிருக்காங்க -> Agent card
Compliance reviewer | rules-ஓட check பண்றாங்க -> Agent card
Agent card -> Action -> Approval | யார், எப்போ, என்ன பார்த்தாங்க
Approval -> Audit record | steps, versions
Complaint -> ஒரு மனுஷன் records-ஐ review பண்றாங்க -> Refund, fix அல்லது ஒரு புது eval case -> Report
Audit record -> ஒரு மனுஷன் records-ஐ review பண்றாங்க
```

இந்த lesson-ல, Delhi-ல ஒரு insurance broker-ஓட motor-insurance renewal agent-ஐ follow பண்றோம்.

## இது எப்படி work ஆகுது

**Owners-க்கு பெயர் போடுங்க.** ஒவ்வொரு agent-க்கும்: அது என்ன செய்யலாம்னு முடிவு பண்ணி results-க்கு பதில் சொல்ற ஒரு business owner, அதை run பண்ற ஒரு technical owner, ஒரு risk அல்லது compliance reviewer. அவங்க பெயர்களை agent-ஓட documentation-ல எழுதுங்க.

**Scope-ஐ document பண்ணுங்க.** ஒரு சின்ன "agent card": purpose, users, tools, permissions, தானா எடுக்கலாம்னு சொன்ன actions, approval வேணும்னு சொன்ன actions, எப்பவும் எடுக்கக்கூடாத actions, தெரிஞ்ச limits, pass பண்ண evals. Agent மாறும்போது இதை review பண்ணுங்க.

**Identity-ஓட approvals.** ஒரு ஆள் ஒரு action-ஐ approve பண்ணும்போது, யார், எப்போ, என்ன பார்த்தாங்கன்னு record பண்ணுங்க. அவங்க approval-ம் accountability chain-ஓட ஒரு பகுதி, அதனால approval screen ஒரு உண்மையான decision எடுக்க போதுமானதை காட்டணும்.

**Records.** ஒவ்வொரு action-ஐயும் மறுபடி கட்டி எடுக்குற audit logs: request, agent-ஓட steps, arguments-ஓட tool calls, approvals, prompt, model, tools-ஓட versions. ஒத்துக்கிட்ட காலம் வரைக்கும் வச்சிருங்க.

**Disclosure.** ஒரு agent-ஓட பேசுறாங்கன்னு, content அல்லது decisions AI-assisted-ன்னு மக்களுக்கு சொல்லுங்க; சட்டம் அல்லது நல்ல practice கேக்குறபடி.

**Redress.** பாதிக்கப்பட்டவங்க ஒரு problem-ஐ report பண்ணி ஒரு மனுஷனை அணுக ஒரு தெளிவான வழி, records வச்சு investigate பண்ற ஒரு process, fix பண்ணவும் கத்துக்கவும் ஒரு commitment (அந்த case-ஐ eval suite-ல சேர்க்கணும்).

**Review.** Agent என்ன செஞ்சுதுன்னு அடிக்கடி பாருங்க: actions-ஓட samples, overrides, complaints, incidents. Evidence சொல்றப்போ, ரெண்டு பக்கமும், அதோட scope-ஐ மாத்துங்க.

**ஒரு agent card practice-ல:**

| Section | Example entry |

**Chain-ஐ test பண்ணுங்க.** கடந்த வாரம் நடந்த ஒரு உண்மையான action-ஐ எடுங்க. Documents, records மட்டும் வச்சு அஞ்சு கேள்விகளுக்கு பதில் சொல்ல பாருங்க: யார் கேட்டாங்க, agent என்ன செய்ய அனுமதி இருந்துச்சு, அது step by step என்ன செஞ்சுது, யார் approve பண்ணாங்க, அவங்க என்ன பார்த்தாங்க, எந்த versions ஓடிக்கிட்டு இருந்துச்சு. எவ்வளவு நேரம் ஆகுதுன்னு time பண்ணுங்க. எந்த பதிலுக்கும் யாரோ ஒருத்தரோட ஞாபகம் தேவைன்னா, அல்லது ஒரு மணி நேரத்துக்கு மேல ஆச்சுன்னா, ஒரு regulator அல்லது கோவமான customer கண்டுபிடிக்கறதுக்கு முன்னாடி அந்த இடைவெளியை சரி பண்ணுங்க.

**Vendors-க்கான accountability.** ஒரு agent third-party model அல்லது tool use பண்ணா, contract-ல யார் எதை பார்த்துக்குவாங்கன்னு இருக்கணும்: incident notification, data use, record retention, model-ல வர்ற changes. உங்க organisation தான் customers-க்கு இன்னும் பதில் சொல்லணும், அதனால agent card vendor-ஐயும், contract என்ன cover பண்ணுதுன்னும் சொல்லும்.

**Agent card-ஐ code பக்கத்துலயே வைங்க.** அதை repository-ல ஒரு file-ஆ store பண்ணி test பண்ணுங்க, அப்போ agent உண்மையா செய்யுறதுல இருந்து அது விலகாது:

```yaml
# agents/renewals.card.yaml
purpose: Renew motor policies after the customer confirms
owners: {business: Head of retail operations, technical: Platform lead, risk: Compliance officer}
tools:
  get_vehicle: {kind: read}
  get_quotes: {kind: read}
  purchase_policy: {kind: write, approval: customer_confirmation}
never: [change cover type without confirmation, add add-ons without confirmation]
last_reviewed: 2026-10-01
```

```python
import yaml
from datetime import date, timedelta
from agents.renewals import TOOLS          # the tool definitions the agent really uses

def test_card_matches_code():
    card = yaml.safe_load(open("agents/renewals.card.yaml"))
    assert set(card["tools"]) == {t["name"] for t in TOOLS}, "card and code list different tools"
    for name, spec in card["tools"].items():
        if spec["kind"] == "write":
            assert "approval" in spec, f"{name} writes but has no approval rule"

def test_card_reviewed_recently():
    card = yaml.safe_load(open("agents/renewals.card.yaml"))
    assert date.today() - card["last_reviewed"] < timedelta(days=180), "card review overdue"
```

இப்போ card-ஐ update பண்ணாம ஒரு tool சேர்த்தா build fail ஆகும், அது owners-ஓட பேச வைக்கும்.

**அஞ்சு கேள்விகளுக்கும் பதில் சொல்ற ஒரு audit record.** ஒரே append-only table, platform எழுதும், agent-ஓட service account எப்பவும் edit பண்ண முடியாது:

```sql
CREATE TABLE agent_audit (
  id bigserial PRIMARY KEY,
  run_id text NOT NULL,
  at timestamptz NOT NULL DEFAULT now(),
  actor text NOT NULL,           -- the customer, the agent, or the approver's staff id
  kind text NOT NULL,            -- request, tool_call, approval, result
  detail jsonb NOT NULL,         -- tool name and arguments, what the approver saw, the outcome
  prompt_version text, model text, tool_versions jsonb
);
-- Reconstruct one run in order:
SELECT at AT TIME ZONE 'Asia/Kolkata', actor, kind, detail FROM agent_audit WHERE run_id = $1 ORDER BY at;
```

Application role-க்கு `INSERT`, `SELECT` மட்டும் கொடுங்க. உங்க sector கேக்குற காலம் வரைக்கும் records-ஐ வச்சிருங்க; சீக்கிரம் delete பண்றதுக்கு பதிலா மலிவான storage-க்கு export பண்ணுங்க.

**இந்தியால sector expectations.** Regulators தங்க sectors-ல AI-க்கிட்ட என்ன எதிர்பார்க்குறாங்கன்னு எழுதிக்கிட்டு இருக்காங்க. உதாரணமா RBI, financial services-ல responsible AI-க்கு ஒரு framework publish பண்ணியிருக்கு; அது governance, பெயர் போட்ட accountability, audit trails-ஐ வலியுறுத்துது. உங்க client-ஓட sector-க்கான இப்போதைய guidance-ஐ launch-க்கு அப்புறம் இல்லை, design-க்கு முன்னாடியே படிங்க.

**பொறுப்பு vendor-க்கு போகாது.** ஒரு model provider-ஓட update behaviour-ஐ மாத்துனா, உங்க organisation தான் customer-க்கு பதில் சொல்லணும். அதனாலதான் card pin பண்ண model version-ஐயும், அது pass பண்ண evals-ஐயும் சொல்லுது, model changes-ஐ code changes மாதிரியே அதே review-வுக்கு அனுப்புறோம்.

**Browser-லயே try பண்ணுங்க.** ஒரு agent card-ஐ agent-க்கு உண்மையா இருக்குற tools-ஓட check பண்ணுங்க. ஒரு tool சேர்த்து run பண்ணுங்க.

```python
card = {"tools": {"get_vehicle": "read", "get_quotes": "read", "purchase_policy": "write"},
        "approvals": {"purchase_policy": "customer confirmation"}}
tools_in_code = ["get_vehicle", "get_quotes", "purchase_policy", "cancel_policy"]

missing = set(tools_in_code) - set(card["tools"])
if missing:
    print("tools missing from the card:", sorted(missing))
for name, kind in card["tools"].items():
    if kind == "write" and name not in card["approvals"]:
        print(f"{name} writes but has no approval rule")
print("check done")
```

## ஒரு example

Delhi-ல ஒரு insurance broker, motor policies-ஐ renew பண்ற ஒரு agent-ஐ deploy பண்றாங்க. அது vehicle details-ஐ check பண்ணும், மூணு insurers-ஓட quotes எடுக்கும், ஒண்ணை recommend பண்ணும். Customer confirm பண்ணதுக்கு அப்புறம், insurer-ஓட API வழியா purchase-ஐ முடிக்கும்.

Accountability set-up:

- **Owners**: head of retail operations (business), platform lead (technical), compliance officer (review).
- **Agent card**: quotes எடுக்கவும் recommend பண்ணவும் செய்யலாம்; customer app-ல தெளிவா confirm பண்ணதுக்கு அப்புறம் மட்டும் purchase பண்ணலாம்; confirmation இல்லாம cover type அல்லது add-ons-ஐ எப்பவும் மாத்தக்கூடாது; தான் ஒரு automated assistant-ன்னு சொல்லணும்.
- **Records**: ஒவ்வொரு quote, recommendation காரணம், confirmation message, purchase call, versions-ஓட.
- **Redress**: ஒவ்வொரு screen-லயும் "ஒரு ஆளோட பேசணும்" option; complaints வாரா வாரம் review ஆகும்.

மூணு மாசம் கழிச்சு, ஒரு customer renewal-ல zero-depreciation cover விடுபட்டுடுச்சுன்னு complaint பண்றாங்க. Records என்ன காட்டுது: agent அந்த add-on இல்லாத ஒரு மலிவான quote-ஐ recommend பண்ணியிருக்கு, confirmation screen அந்த மாற்றத்தை highlight பண்ணல. Accountability தெளிவு: தப்பு design-ல, customer-ல இல்லை. Broker வித்தியாசத் தொகையை refund பண்ணுது, எந்த cover மாற்றத்தையும் highlight பண்ணும்படி confirmation screen-ஐ மாத்துது, cover changes-க்கு தெளிவான consent வேணும்னு ஒரு rule சேர்க்குது, இது மாதிரி பத்து cases-ஐ evals-ல சேர்க்குது. Compliance officer-ஓட board report-ல இந்த incident-ம் fix-ம் இருக்கு.

| Complaint-க்கு அப்புறம் step | Broker என்ன செஞ்சாங்க |
| --- | --- |
| Investigation | Add-on இல்லாத ஒரு மலிவான quote recommend ஆனதை records காட்டுச்சு |
| Finding | Confirmation screen cover மாற்றத்தை highlight பண்ணல |
| Redress | வித்தியாசத் தொகையை customer-க்கு refund பண்ணாங்க |

| Learning | இது மாதிரி பத்து cases evals-ல சேர்ந்தது; incident board-க்கு report ஆச்சு |

## பொதுவா பண்ற தப்புகள்

- **பெயர் போட்ட owner இல்லாம இருக்கிறது.** "AI team"-ஆல outcomes-க்கு பதில் சொல்ல முடியாது.
- **Scope மக்களோட மனசுல மட்டும் இருக்கிறது.** Agent card-ஐ எழுதி, current-ஆ வச்சிருங்க.
- **Context இல்லாம approvals.** கண்ணை மூடிக்கிட்டு approve பண்றவங்க oversight கொடுக்கல.
- **Query பண்ண முடியாத records.** Investigations-க்கு மணி நேரத்துல பதில்கள் வேணும்.
- **பாதிக்கப்பட்டவங்களுக்கு route இல்லாம இருக்கிறது.** Report பண்ண வழி இல்லாத harm, public complaint-ஆ மாறும்.
- **Slide deck-ல மட்டும் இருக்குற agent card.** அதை repository-ல வச்சு test பண்ணுங்க.
- **Agent-ஓட service edit அல்லது delete பண்ணக்கூடிய audit tables.**
- **Audit records-ல versions இல்லாம இருக்கிறது.** எந்த prompt அல்லது model decision எடுத்துச்சுன்னு சொல்ல முடியாது.

Agent customers சார்பா செயல்படும், பணம் அல்லது personal data-ஐ கையாளும், அல்லது regulated sector-ல வேலை செய்யும்போது முழு cards, approval identity, append-only audits, redress paths தேவைப்படும்.

## Practice பண்ணுங்க

NIST AI Risk Management Framework-ஓட overview-ஐயும், EU AI Act summary-ல high-risk obligations section-ஐயும் படிங்க.

1. நீங்க build பண்ண ஒரு agent-க்கு agent card எழுதுங்க: purpose, users, tools, allowed, forbidden actions, approvals, தெரிஞ்ச limits, owners.
2. உங்க audit records இதுக்கு பதில் சொல்லுமான்னு check பண்ணுங்க: யார் கேட்டாங்க, agent என்ன செஞ்சுது, யார் approve பண்ணாங்க, எந்த versions use ஆச்சு.
3. Redress path-ஐ design பண்ணுங்க: பாதிக்கப்பட்ட ஒருத்தர் ஒரு problem-ஐ எப்படி report பண்ணுவாங்க, அதுக்கு அப்புறம் என்ன நடக்கும், ஒரு time limit-ஓட.
4. Card-matches-code test-ஐ உங்க agent-ஓட repository-ல சேர்த்து, அப்புறம் card-ஐ update பண்ணாம ஒரு புது tool சேர்த்து, build fail ஆகுதுன்னு confirm பண்ணுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** உங்க agent செஞ்ச ஒரு action-ஐ எடுத்து, documents, records மட்டும் வச்சு, அதுக்கு யார் accountable, அது ஏன் நடந்துச்சுன்னு காட்ட முடியும்.
