## இது என்ன

ஒரு AI system சில groups-க்கு: gender, caste, religion, region, language, age, disability, income அல்லது மத்த பண்புகளால, மோசமா வேலை செய்யும்போது அல்லது அவங்களை நியாயமில்லாம நடத்தும்போது அது **biased**. **Fairness**-னா, நியாயப்படுத்த முடியாத இடத்துல அந்த வித்தியாசங்களை கண்டுபிடிச்சு குறைக்குற வேலை.

AI-ல bias பெரும்பாலும் வேணும்னே நடக்காது. "இந்த district-ல இருந்து வர்ற applicants-ஐ reject பண்ணு"ன்னு யாரும் rule எழுதல. அது பொதுவா ரெண்டு இடங்கள்ல இருந்து வரும்: **system கத்துக்கிட்ட data**, **system எப்படி use ஆகுது**ங்குறது.

```flow
dir: LR
title: நியாயமில்லாத வரலாறு உள்ள போனா, நியாயமில்லாத predictions வெளிய வரும்
கடந்த கால decisions | engineering roles-க்கு பெரும்பாலும் ஆண்கள் hire ஆனாங்க -> Model கத்துக்குது | "ஆண்கள் = நல்ல engineers": ஒரு pattern, fact இல்ல
Model கத்துக்குது -> Model திரும்ப செய்யுது | புது engineering roles-க்கு பெண்களை கீழ rank பண்ணுது
```

Loans, jobs, school admissions, insurance, welfare பத்தின decisions-ஐ AI எடுக்கும்போதும், shape பண்ணும்போதும் இது இன்னும் முக்கியம். Biased spell-checker எரிச்சலூட்டும். Biased loan model வாழ்க்கையை மாத்தும்.

இந்த lesson-ல, தன் resume-screening tool நியாயமில்லாததுன்னு கண்டுபிடிச்சு அதை சரி பண்ற ஒரு Bengaluru startup-ஐ follow பண்ணுவோம். Lesson முடியும்போது, bias எங்க இருந்து வருதுன்னு explain பண்ணி, இந்திய சூழல்ல அதை அடையாளம் கண்டு, எப்படி test பண்றதுன்னு சொல்ல முடியும்.

## இது எப்படி work ஆகுது

### Bias எங்க இருந்து வருது

| Source | என்ன நடக்குது | இந்திய example |
| --- | --- | --- |
| **Historical data** | Model கடந்த கால நியாயமில்லாத decisions-ஐ copy பண்ணுது | கடந்த கால hiring சில colleges-ஐயும் பெரும்பாலும் ஆண்களையும் ஆதரிச்சது, அதனால model-உம் அப்படியே பண்ணுது |
| **Missing data** | குறைவான examples இருக்குற groups-க்கு மோசமான results | நகர்ப்புற English பேசுறவங்கள்ல train ஆன speech system, கிராமத்து accents-ல திணறுது |
| **Proxies** | வேற features ஒரு sensitive trait-க்கு பதிலா நிக்குது | Surname, PIN code, college, caste, religion, income-ஐ காட்டிடும் |
| **Language** | Model அதிகம் பார்த்த மொழில தான் நல்லா வேலை செய்யும் | ஒரு chatbot English-ல நல்லா, Odia-ல மோசமா பதில் சொல்லுது |
| **Use** | ஒரு tool, அது design ஆகாத வேலைக்கு use ஆகுது | Suggest பண்ண வச்ச assistant, தானா gatekeeper ஆகிடுது |

### ஒரு field-ஐ நீக்குறது ஏன் போதாது

முதல்ல வர்ற பொதுவான idea: "Data-ல இருந்து gender, caste-ஐ delete பண்ணிடுங்க." அது அரிதா தான் work ஆகும், ஏன்னா மத்த features அதே தகவலை கொண்டு போகும். இந்தியால, ஒரு surname caste அல்லது religion-ஐ காட்டலாம்; PIN code income, community-ஐ காட்டலாம்; college ரெண்டையும் காட்டலாம். Model இந்த **proxies**-ஐ கண்டுபிடிச்சு, பழைய pattern-ஐ அப்படியும் கத்துக்கும்.

### Bias எப்படி தெரியுது

- ஒரு loan model, ஒரே மாதிரி repayment records இருந்தும், சில districts-ல இருந்து குறைவான applicants-ஐ approve பண்ணுது.
- ஒரு resume screener, engineering roles-க்கு பெண்களை கீழ rank பண்ணுது.
- ஒரு image generator, "a doctor"-னு கேட்டா ஆண்களை மட்டும், "a nurse"-னு கேட்டா பெண்களை மட்டும் காட்டுது.
- ஒரு chatbot, English-ஐ விட இந்திய மொழிகள்ல சின்ன, மோசமான பதில்களை தருது.
- ஒரு face-recognition system, கருப்பு தோல் நிறங்கள்ல அதிக தப்பு பண்ணுது.

### என்ன பண்ணலாம்

1. **Group வாரியா test பண்ணுங்க.** Overall மட்டும் இல்லாம, ஒவ்வொரு group-க்கும் accuracy, outcomes-ஐ அளவுங்க. Bias averages-க்குள்ள ஒளிஞ்சிருக்கும்.
2. **Data-வை சரி பண்ணுங்க.** இன்னும் representative examples-ஐ collect பண்ணுங்க, rebalance பண்ணுங்க, தீங்கான proxies-ஐ குறைங்க.
3. **ஆளுங்களை பொறுப்புல வைங்க.** வாழ்க்கையை பாதிக்கிற decisions-க்கு, model-ஐ மீறுற அதிகாரத்தோட human review use பண்ணுங்க.
4. **Explain பண்ணி appeal-க்கு விடுங்க.** பாதிக்கப்பட்டவங்க முக்கிய reasons-ஐ புரிஞ்சுக்கணும், decision-ஐ challenge பண்ணவும் முடியணும்.
5. **Launch-க்கு அப்புறமும் monitor பண்ணுங்க.** Users, data மாறும்; group tests-ஐ அடிக்கடி repeat பண்ணுங்க.

```flow
dir: LR
Build -> Group வாரியா test -> Data அல்லது rules-ஐ fix பண்ணு -> மறுபடி test
மறுபடி test -[use-ல monitor பண்ணு, ஒவ்வொரு quarter-உம்]-> Build
```

### Fairness-ல trade-offs உண்டு

Fairness-க்கு ஒரு definition மட்டும் இல்ல, அவை ஒண்ணுக்கொண்ணு முரண்படலாம்:

| Definition | அர்த்தம் | Trade-off |
| --- | --- | --- |
| Equal approval rates | ஒவ்வொரு group-உம் ஒரே விகிதத்துல approve ஆகும் | திருப்பி கட்ட கஷ்டப்படுவாங்கன்னு தோணுற ஆளுங்களையும் approve பண்ணலாம் |
| Equal error rates | Model ஒவ்வொரு group-க்கும் சம அளவு தப்பு பண்ணும் | Approval rates அப்படியும் வேறுபடலாம் |
| ஒரே மாதிரி ஆளுங்களுக்கு ஒரே நடத்தை | ஒரே record இருக்குற ரெண்டு பேருக்கு ஒரே result | "ஒரே மாதிரி"ன்னா என்னன்னு ஒத்துக்கணும் |

ஒண்ணை தேர்ந்தெடுக்குறது ஒரு value decision; பாதிக்கப்படுற மக்கள், சட்டம், organisation-ஓட நோக்கத்தை மனசுல வச்சு வெளிப்படையா எடுக்கணும். Model-ஐ train பண்ணுறவங்க யாரோ அவங்களுக்கே விட்டுடுற விஷயம் இல்ல.

## ஒரு worked example

ஒரு Bengaluru startup, ஒரு பெரிய IT client-க்கு resume-screening tool build பண்றாங்க. Client-ஓட ஐந்து வருஷ hiring decisions-ல model-ஐ train பண்றாங்க: எந்த resumes shortlist ஆச்சு, எது ஆகலை.

**Group வாரியா testing.** Launch-க்கு முன்னாடி, ஒரே மாதிரி skills, experience இருக்குற candidates-க்கு shortlist rates-ஐ team ஒப்பிடுது:

| Group (ஒரே மாதிரி skills, experience) | Fix-க்கு முன்னாடி shortlist ஆனது | Fix-க்கு அப்புறம் |
| --- | --- | --- |
| நல்ல பெயர் வாங்கின ஐந்து colleges-ஓட graduates | 48% | 31% |
| மத்த colleges-ஓட graduates | 14% | 27% |
| ஆண்கள், engineering roles | 33% | 29% |
| பெண்கள், engineering roles | 19% | 27% |

**காரணத்தை கண்டுபிடிக்கிறது.** கடந்த கால hiring அந்த ஐந்து colleges-ஐயும் பெரும்பாலும் ஆண்களையும் ஆதரிச்சிருந்தது, model அந்த pattern-ஐ கத்துக்கிட்டிருந்தது. College names-உம், resumes-ல இருக்குற "women's hostel secretary" மாதிரி gender சார்ந்த வார்த்தைகளும் proxies-ஆ வேலை செஞ்சது.

**Fix.** Model score பண்றதுல இருந்து names, photos, college names, gender சார்ந்த வார்த்தைகளை team நீக்குது, training examples-ஐ rebalance பண்ணுது, group வாரியா மறுபடி test பண்ணுது. Gaps கணிசமா குறையுது, ஆனா zero ஆகல.

**Model-ஐ மட்டும் இல்லாம product-ஐயும் மாத்துறது.** Tool இப்போ ஆளுங்களை தானா reject பண்றதுக்கு பதிலா, reasons-ஓட ஒரு shortlist-ஐ suggest பண்ணுது. ஒவ்வொரு rejection-ஐயும் recruiters review பண்றாங்க. Candidates human review கேக்கலாம். Team ஒவ்வொரு quarter-உம் group tests-ஐ repeat பண்ணி, results-ஐ client-க்கு report பண்ணுது.

Model நியாயமா ஆச்சு, ஆனா பெரிய மாற்றம் அது எப்படி use ஆகுதுங்குறதுல இருந்தது.

## பொதுவா பண்ற தப்புகள்

- **Overall accuracy-ஐ மட்டும் பார்க்கிறது.** ஒரு system சராசரியா accurate-ஆ இருந்துட்டு ஒரு group-க்கு நியாயமில்லாம இருக்கலாம். எப்பவும் results-ஐ பிரிச்சு பாருங்க.
- **Sensitive field-ஐ நீக்கினா bias போயிடும்னு நினைக்கிறது.** Surname, PIN code, college மாதிரி proxies இருக்கும்.
- **Maths-ங்குறதால AI neutral-னு நினைக்கிறது.** அது கத்துக்கிட்ட data, decisions-ஐ பிரதிபலிக்கும்.
- **English-ல மட்டும் test பண்றது.** இந்திய users பல மொழிகள் பேசுறாங்க; உங்க users பேசுறதுல test பண்ணுங்க.
- **Human review, appeal இல்லாம முக்கியமான decisions-ஐ automate பண்றது.** ஒரு ஆளை accountable-ஆ வைங்க.
- **ஒரு தடவை test பண்ணி மறந்துடுறது.** Data, users மாறுறதால launch-க்கு அப்புறமும் bias வரலாம்.

## Practice பண்ணுங்க

கீழே link பண்ணியிருக்குற இலவச Ethics of AI course-ல fairness chapter-ஐ எடுத்துக்கோங்க, EU AI Act summary-ல high-risk uses பத்தின பகுதியையும் படிங்க.

1. **ஒரு image generator-ஐ test பண்ணுங்க.** "a doctor", "a nurse", "an engineer", "a farmer"-னு ஒவ்வொண்ணுக்கும் பத்து தடவை கேளுங்க. கிடைக்குற genders, தோற்றங்களை note பண்ணுங்க.
2. **மொழிகளை ஒப்பிடுங்க.** ஒரு chat assistant-கிட்ட அதே கேள்வியை English-லயும் உங்களுக்கு தெரிஞ்ச ஒரு இந்திய மொழிலயும் கேட்டு, பதில்களோட quality, நீளத்தை ஒப்பிடுங்க.
3. **ஒரு bias test-ஐ plan பண்ணுங்க.** Hiring அல்லது lending-ல ஒரு AI use-க்கு, bias நுழையக்கூடிய மூணு வழிகளையும், ஒவ்வொண்ணுக்கும் ஒரு test-ஐயும் list பண்ணுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** ஒரு இந்திய example-ஓட proxies-ஐ explain பண்ணி, ஒரு system-ஐ group வாரியா bias-க்கு எப்படி test பண்ணுவீங்கன்னு சொல்ல முடியும்.
