## இது என்ன

ஒரு AI engagement பொதுவா மூணு stages வழியா போகும்:

- **Proof of concept (POC)**, 2 முதல் 6 வாரம்: இது client-ஓட real data-ல வேலை செய்யுமா? சீக்கிரமா உருவாக்கி, பழைய cases-ல offline-ஆ run பண்ணி, evals வச்சு மதிப்பிடுவாங்க. இன்னும் real users இல்லை.
- **Pilot**, 6 முதல் 12 வாரம்: இது real மக்களுக்கு அன்றாட வேலையில உதவுதா? ஒரு limited group safeguards-ஓட use பண்ணுவாங்க, நீங்க KPI, quality, adoption-ஐ அளப்பீங்க.
- **Production**: எல்லா target users-க்கும் rollout பண்ணி, ஒரு சாதாரண system மாதிரி run பண்ணி support பண்ணுவாங்க, client-ஓட team அதுக்கு சொந்தக்காரங்க.

ஒவ்வொரு stage-க்கும் நடுவுல ஒரு **stage gate** இருக்கு: ஒத்துக்கிட்ட evidence-ஐ review பண்ணி, client தொடரணுமா, திசை மாத்தணுமா, நிறுத்தணுமான்னு முடிவு பண்ற meeting.

```flow
dir: LR
POC, 2-6 வாரம் | பழைய cases offline-ஆ, ஒரு golden set, evals, ரொம்ப risky-ஆன assumption -> Gate 1: தொடரு, மாத்து, நிறுத்து?
Gate 1: தொடரு, மாத்து, நிறுத்து? -[தொடரு]-> Pilot, 6-12 வாரம் | safeguards-ஓட real users, KPI, guardrails, adoption; sign-on, logs, security முடிஞ்சிருக்கும்
Pilot, 6-12 வாரம் -> Gate 2: தொடரு, மாத்து, நிறுத்து?
Gate 2: தொடரு, மாத்து, நிறுத்து? -[தொடரு]-> Production | எல்லாருக்கும், waves-ஆ; runbooks, on-call, dashboards; தொடர்ந்து அளக்கணும்
```

இந்த lesson, சென்னையில ஒரு lender-ஓட credit-file assistant-ஐ, அதோட முதல் offline test-ல இருந்து 180 officers-க்கு rollout வரை பின்தொடருது.

## இது எப்படி work ஆகுது

**POC.** ரொம்ப risky-ஆன assumption-ஐ முதல்ல target பண்ணுங்க. Document extraction-க்கு, அது பொதுவா user interface இல்ல, "அவங்க real, குழப்பமான documents-ஐ துல்லியமா படிக்க முடியுமா?"-ங்கிறது தான். Real data use பண்ணுங்க (தேவைன்னா masked), client-ஓட experts-ஓட ஒரு golden set உருவாக்குங்க, accuracy, failure types, ஒரு case-க்கு cost, latency-ஐ report பண்ணுங்க. Polish-ஐ விட்டுடுங்க. Gate criteria SOW-ல இருந்து வரும்: உதாரணமா, critical fields-ல குறைஞ்சது 95% accuracy.

**Pilot.** ஆர்வமுள்ளவங்களை மட்டும் இல்லாம, பெரிய group-ஐ represent பண்ற users-ஐ தேர்ந்தெடுங்க. முடிவுகள் மனுஷங்க கைலயே இருக்கட்டும். Production-க்கு தேவையானதை அதுல இருந்து கத்துக்கற அளவுக்கு சீக்கிரமா சேருங்க: sign-on, logging, monitoring, feedback buttons. KPI-ஐ baseline-ஓட ஒப்பிட்டு, guardrail measures, adoption-ஐ வாரா வாரம் அளங்க. மாத்தங்கள் இருக்கும்னு எதிர்பாருங்க; அது தான் நோக்கமே. Gate: KPI நகர்ந்திருக்கு, guardrails தாக்குப்பிடிச்சிருக்கு, users இதை வச்சுக்க விரும்புறாங்க, support, security தயார்.

**Production.** Waves-ஆ rollout பண்ணுங்க (ஒரு region, அப்புறம் இன்னும் பல). Operations-ஐ handover பண்ணுங்க: runbooks, on-call, dashboards, training. ஒரு support period-ஐ ஒத்துக்கோங்க. தொடர்ந்து அளங்க; production-ஓட evaluation முடியாது.

**Stop பண்றது ஒரு சரியான outcome.** Documents படிக்கவே முடியாதுன்னு காட்டுற POC, அல்லது users tool-ஐ கண்டுக்காம விடுற pilot, மலிவா நிறுத்தி ஏன்னு விளக்கினா அது தன் வேலையை செஞ்சிருக்கு. அதை write up பண்ணுங்க; அந்த கத்துக்கிட்டது மதிப்புள்ளது.

**Pilot purgatory-ஐ தவிர்க்கணும்.** பொதுவான காரணங்கள்: ஒத்துக்கிட்ட gate criteria இல்ல, business owner இல்ல, production requirements (security, integration) pilot-க்கு அப்புறம் விட்டுட்டாங்க, rollout-க்கு budget plan பண்ணலை. நாலையும் SOW-லயே பேசிடுங்க.

**ஒவ்வொரு stage-க்கும் gate evidence:**

| Gate | Review பண்ற evidence | வழக்கமான criteria |
| --- | --- | --- |
| POC-ல இருந்து pilot-க்கு | Golden-set accuracy, failure types, ஒரு case-க்கு cost, latency | Critical fields-ல குறைஞ்சது 95%; தெரிஞ்ச failures handle ஆகிடுச்சு |
| Pilot-ல இருந்து production-க்கு | Baseline-ஓட KPI, guardrails, adoption, user feedback, security sign-off | KPI நகர்ந்திருக்கு; guardrails தாக்குப்பிடிச்சிருக்கு; users இதை விரும்புறாங்க; support தயார் |
| Production நடக்கும்போது | மாசாந்திர KPI, cost, incidents | Usage வளரும்போதும் results நிலைச்சிருக்கு |

**Gate meeting-ஐ நடத்துறது.** Evidence pack-ஐ ரெண்டு நாள் முன்னாடியே அனுப்புங்க: ஒத்துக்கிட்ட criteria, அவற்றுக்கு பக்கத்துல அளந்த results, முக்கிய failures, fixes, cost, ஒரு recommendation. Meeting-ல criteria-வை ஒண்ணு ஒண்ணா பார்த்து, business owner-ஐ தொடரு, மாத்து, நிறுத்துன்னு முடிவு பண்ண சொல்லுங்க. முடிவையும் நிபந்தனைகளையும் அன்னைக்கே எழுத்துல பதிவு பண்ணுங்க. முன்கூட்டியே criteria ஒத்துக்கிட்ட gate சின்னதா முடியும்; இல்லாத gate, வெற்றின்னா என்னன்னு ஒரு விவாதமா மாறிடும்.

**Stop-ஐ write up பண்றது.** Evidence நிறுத்த சொன்னா, ரெண்டு பக்கம் எழுதுங்க: என்ன test பண்ணுனோம், என்ன கண்டுபிடிச்சோம், இப்போ ஏன் வேலை செய்யாது, என்ன மாறணும் (நல்ல scans அல்லது வேற process மாதிரி). நேர்மையா, மலிவா நிறுத்துன team-ஐ clients நினைவுல வச்சுப்பாங்க, அடுத்த project-ஐயும் அடிக்கடி அவங்ககிட்டயே கொண்டு வருவாங்க.

## ஒரு worked example

சென்னை lender-ஓட credit-file assistant:

**POC, வாரம் 1 முதல் 4.** Masked பண்ண 300 பழைய files. Critical-field accuracy 93%, 95% gate-க்கு கீழ. Error analysis: பெரும்பாலான தப்புகள் நிழல் விழுந்த bank statements-ஓட phone photos-ல. நீங்க ஒரு image clean-up step-ஐயும் "low confidence, please check" flag-ஐயும் சேக்குறீங்க; accuracy 96.4%-க்கு ஏறுது. Gate pass ஆச்சு, confidence flag pilot design-ல சேர்க்கப்பட்டுச்சு.

**Pilot, வாரம் 5 முதல் 14.** ரெண்டு branches-ல 20 officers. வாராந்திர numbers: ஒரு file-க்கு median நேரம் 41-ல இருந்து 24 நிமிஷமா குறையுது; rework 5.1%, baseline 7%; adoption 88%. Document-ஐயும் extract பண்ண fields-ஐயும் பக்கம் பக்கமா பார்க்க ஒரு view வேணும்னு officers கேக்குறாங்க, வாரம் 8-ல சேக்குறீங்க. Security review, sign-on ரெண்டும் pilot-க்கு அப்புறம் இல்ல, pilot நடக்கும்போதே முடியுது. Gate pass ஆச்சு.

**Production, வாரம் 15-ல இருந்து.** 180 officers-க்கு, ஒவ்வொண்ணும் ஒரு மாசம் கொண்ட மூணு waves-ல rollout. Lender-ஓட IT team, உங்க runbook, dashboards வச்சு system-ஐ run பண்றாங்க; நீங்க எட்டு வாரம் support தர்றீங்க. மாசாந்திர KPI reports தொடருது.

| Stage | Result | முடிவு |
| --- | --- | --- |
| POC, வாரம் 1 முதல் 4 | Critical fields-ல 93%, image clean-up, confidence flag-க்கு அப்புறம் 96.4% | Gate pass; flag pilot-ல சேர்ந்துச்சு |
| Pilot, வாரம் 5 முதல் 14 | ஒரு file-க்கு 41-ல இருந்து 24 நிமிஷம்; rework 5.1%; adoption 88%; security, sign-on முடிஞ்சது | Gate pass |
| Production, வாரம் 15-ல இருந்து | 180 officers-க்கு மூணு மாசாந்திர waves; client IT எட்டு வாரம் support-ஓட run பண்றாங்க | மாசாந்திர KPI reports தொடருது |

## பொதுவா பண்ற தப்புகள்

- **சுத்தமான sample data-ல ஒரு polish பண்ண POC.** Real documents பத்தி அது ஒண்ணும் நிரூபிக்காது.
- **Gate criteria இல்லாத pilots.** அவை முடியவே முடியாது, scale-உம் ஆகாது.
- **Security, integration-ஐ pilot-க்கு அப்புறம் விடுறது.** மோசமான நேரத்துல மாசக்கணக்கான தாமதத்தை சேர்க்கும்.
- **Pilot-ல நண்பர்களான users மட்டும்.** மத்தவங்களுக்கு results பொருந்தாது.
- **"Stop"-ஐ தோல்வின்னு நினைக்கிறது.** மலிவான, நல்ல காரணத்தோட செய்த stop ஒரு நல்ல outcome.

## Practice பண்ணுங்க

GOV.UK-ஓட alpha, beta, live phases guides-ஐ படிச்சு, AI வேலைக்கு எது பொருந்துதுன்னு குறிச்சுக்கோங்க.

1. உங்க use case-க்கு POC plan எழுதுங்க: ரொம்ப risky-ஆன assumption, data, golden set, measures, gate criteria.
2. Pilot plan எழுதுங்க: users, safeguards, வாராந்திர measures, முடிவுக்குள்ள production-க்கு என்ன தயாரா இருக்கணும், gate criteria.
3. Rollout plan எழுதுங்க: waves, handover, support period, எது நடந்தா நிறுத்தி வைப்பீங்க.

**எப்போ முடிஞ்சதுன்னு சொல்லலாம்:** மூணு stages-ஐயும், ஒவ்வொரு gate-லயும் தேவையான evidence-ஐயும் கொண்ட ஒரு பக்க plan-ஐ காட்ட முடியும்.
