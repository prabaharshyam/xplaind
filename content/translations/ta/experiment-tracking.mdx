## இது என்ன

**Experiment tracking** ஒவ்வொரு training run-ஐயும் தானா log பண்ணும்: code version (Git commit), data version, parameters, நேரம் போக போக metrics, plots மாதிரி artefacts, train ஆன model. **Model registry** தேர்ந்தெடுத்த model versions-ஐ அவற்றோட metadata-ஓட, alias மாதிரி ஒரு label-ஓட ("production" போல) store பண்ணும். அதனால deployment எப்பவும் தெரிஞ்ச, approve ஆன model-ஐயே use பண்ணும்.

Tools-ல MLflow (open source), Weights & Biases, cloud ML platforms-ஓட built-in tracking இருக்கு. சமீபத்திய MLflow versions இதுக்கு நகர்த்தக்கூடிய aliases use பண்ணுது; பழைய fixed stages (Staging, Production) deprecated.

```flow
Training run 412 | params: depth=6, lr=0.05, features v3; code git a1b2c3d; data claims-2026-09; PR AUC 0.46 -[best run, approved]-> Model registry: fraud-model v14
Model registry: fraud-model v14 -[alias "production"]-> Production loads "fraud-model@production"
Production loads "fraud-model@production" -[rollback: move the alias]-> fraud-model v13, the previous one
```

இந்த lesson-ல Hyderabad-ல ஒரு insurer-ஓட ML team-ஐ follow பண்ணுவோம். அவங்க ஒவ்வொரு மாசமும் claim-fraud model-ஐ retrain பண்றாங்க.

## இது எப்படி work ஆகுது

**ஒரு run-ஐ define பண்ற எல்லாத்தையும் log பண்ணுங்க.** Parameters (learning rate, depth, use பண்ண features), metrics (validation, test scores, segment வாரியா), Git commit, dataset version அல்லது hash, environment (library versions), outputs (model file, confusion matrix, feature importance plot).

**Runs-ஐ compare பண்ணுங்க.** Tracking UI runs-ஐ அவற்றோட parameters, metrics-ஓட list பண்ணும், score வாரியா sort பண்ணும், runs முழுக்க metrics-ஐ plot பண்ணும். Depth 6 depth 8-ஐ தோற்கடிச்சுதுன்னு, அல்லது ஒரு புது feature ஒரு segment-ல மட்டும் உதவுச்சுன்னு உங்களால பார்க்க முடியும்.

**Reproduce பண்ணுங்க.** Code, data, parameters record ஆகியிருந்தா, யார் வேணும்னாலும் திரும்ப ஓட்டி அதே model-ஐ பெறலாம் (randomness-க்குள்ள, அது seeds-ஆல control ஆகும்).

**Winner-ஐ register பண்ணுங்க.** தேர்ந்தெடுத்த run-ஓட model-ஐ registry-ல ஒரு புது version-ஆ promote பண்ணுங்க, notes-ஓட: என்ன மாறுச்சு, evaluation results, யார் approve பண்ணாங்க. Production file path-ல இல்லாம, registry-ல இருந்து "production version"-ஐ load பண்ணும்.

**Promotion rules.** Promote பண்றதுக்கு முன்னாடி: model ஒத்துக்கிட்ட metrics-ல (முக்கிய segments உட்பட) இப்ப இருக்கும் production model-ஐ விட நல்லா இருக்கணும்; recent data-ல checks pass ஆகணும்; owner approve பண்ணணும். Rollback-க்காக முந்தைய version-ஐ ready-ஆ வச்சிருங்க.

**Lineage.** Audits, debugging-க்கு இந்த சங்கிலி தெளிவா இருக்கணும்: production model version → training run → code commit → data version → evaluation results.

**என்ன log பண்ணணும், ஏன்:**

| Item | Example | ஏன் முக்கியம் |
| --- | --- | --- |
| Parameters | `depth=6`, `learning_rate=0.05` | Runs-க்கு நடுவுல உள்ள வித்தியாசத்தை விளக்கும் |
| Metrics | PR AUC 0.46 overall, region வாரியா | Winner-ஐ நியாயமா தேர்ந்தெடுக்கும் |
| Code version | Git commit `a1b2c3d` | Training logic-ஐ reproduce பண்ணும் |
| Data version | `claims-2026-09`, hash-ஓட | Inputs-ஐ reproduce பண்ணும் |
| Environment | Library versions, Python version | "என் machine-ல work ஆகுது" பிரச்சனையை தவிர்க்கும் |
| Artefacts | Model file, plots, feature importance | Reviewers results-ஐ பார்க்க விடும் |
| Seed | `random_state=42` | Randomness-ஐ control பண்ணும் |

**Script-ல இதை சேர்க்கிறது.** MLflow-ல tracking சில வரிகள் தான்: ஒரு run ஆரம்பிங்க, compute பண்ணும்போதே parameters, metrics-ஐ log பண்ணுங்க, கடைசில model-ஐ log பண்ணுங்க, commit, data version-க்கு tags set பண்ணுங்க. Library அந்த run-ஐ ஒரு local folder-ல அல்லது team share பண்ற tracking server-ல record பண்ணும். scikit-learn, XGBoost மாதிரி libraries-க்கு autologging on பண்ணா, extra code இல்லாமலே பெரும்பாலான parameters, metrics வந்துடும். அப்புறம் data version, segment metrics-ஐ நீங்களே சேருங்க, ஏன்னா எந்த tool-ஆலும் அதை ஊகிக்க முடியாது.

**MLflow-ல ஒரு training run-ஐ track பண்றது.**

```python
import hashlib, subprocess
import mlflow
import mlflow.sklearn
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import average_precision_score

def data_hash(path):
    return hashlib.sha256(open(path, "rb").read()).hexdigest()[:12]

mlflow.set_experiment("claims-fraud")
params = {"max_depth": 6, "learning_rate": 0.05, "max_iter": 400}

with mlflow.start_run() as run:
    mlflow.set_tags({"git_commit": subprocess.getoutput("git rev-parse --short HEAD"),
                     "data_version": "claims-2026-09", "data_hash": data_hash("data/train.parquet")})
    mlflow.log_params(params)
    model = HistGradientBoostingClassifier(**params, random_state=42).fit(X_train, y_train)
    scores = model.predict_proba(X_val)[:, 1]
    mlflow.log_metric("pr_auc", average_precision_score(y_val, scores))
    for region in ["north", "south", "east", "west"]:
        m = val_region == region
        mlflow.log_metric(f"pr_auc_{region}", average_precision_score(y_val[m], scores[m]))
    mlflow.sklearn.log_model(model, artifact_path="model", registered_model_name="claims-fraud")
```

**Alias வச்சு promotion.** Production எப்பவும் `models:/claims-fraud@champion`-ஐ load பண்ணும்; ஒரு check-க்கு அப்புறம் alias-ஐ நகர்த்துறது தான் promotion:

```python
from mlflow import MlflowClient

client = MlflowClient()

def promote_if_better(name, candidate_version, metric="pr_auc", segments=("north", "south", "east", "west")):
    def metrics_of(version):
        run_id = client.get_model_version(name, version).run_id
        return client.get_run(run_id).data.metrics
    try:
        champ = client.get_model_version_by_alias(name, "champion").version
    except Exception:
        champ = None
    new = metrics_of(candidate_version)
    if champ:
        old = metrics_of(champ)
        if new[metric] < old[metric]:
            return f"rejected: {metric} {new[metric]:.3f} < {old[metric]:.3f}"
        worse = [s for s in segments if new[f"{metric}_{s}"] < old[f"{metric}_{s}"] - 0.02]
        if worse:
            return f"rejected: worse on {worse}"
    client.set_registered_model_alias(name, "champion", candidate_version)
    return f"version {candidate_version} is now champion (was {champ})"

model = mlflow.pyfunc.load_model("models:/claims-fraud@champion")    # in the serving code
```

Rollback-ங்கிறது `set_registered_model_alias`-ஐ முந்தைய version-க்கு திரும்ப set பண்றது தான்.

**LLM apps-க்கும் இதே idea.** Prompt அல்லது retrieval மாற்றத்தை ஒரு experiment-ஆ எடுத்துக்கோங்க: prompt version, model name, top-k, chunk size, category வாரியா eval scores-ஐ ஒரு run-ஆ log பண்ணுங்க. அப்புறம் "prompt-ஓட v13 Hindi கேள்விகளுக்கு உதவுச்சா?"ங்கிறது ஞாபகத்துல இல்லாம, sort பண்ண ஒரு table-ல தெரியும்.

**Tracking server-ஐ சரியா வைங்க.** Database backend, artefacts-க்கு cloud storage, company-ஓட sign-in-க்கு பின்னாடி இருக்குற shared tracking server, ஒரு laptop-ல இருக்குற files-ஐ விட நல்லது. அதை backup எடுங்க; ஒவ்வொரு model முடிவோட வரலாறும் அதுல தான் இருக்கு.

**Browser-லயே try பண்ணுங்க.** ஒரு குட்டி experiment log: runs-ஐ record பண்ணி, ஒரு metric வச்சு best-ஐ தேர்ந்தெடுங்க. உங்க சொந்த runs-ஐயும் சேருங்க.

```python
runs = []
def log_run(params, metrics, commit):
    runs.append({"params": params, "metrics": metrics, "commit": commit})

log_run({"depth": 4, "lr": 0.1}, {"pr_auc": 0.41}, "a1b2c3d")
log_run({"depth": 6, "lr": 0.05}, {"pr_auc": 0.46}, "a1b2c3d")
log_run({"depth": 8, "lr": 0.05}, {"pr_auc": 0.44}, "f9e8d7c")

best = max(runs, key=lambda r: r["metrics"]["pr_auc"])
for r in sorted(runs, key=lambda r: -r["metrics"]["pr_auc"]):
    print(r["metrics"]["pr_auc"], r["params"], r["commit"])
print("best:", best["params"])
```

## ஒரு example

MLflow வந்த பிறகு:

## பொதுவா பண்ற தப்புகள்

- **Spreadsheets-ல கையால track பண்றது.** அது முழுமையா இருக்காது, சீக்கிரம் பழசாகிடும்.
- **Data versions-ஐ log பண்ணாம இருக்குறது.** Code, parameters மட்டும் வச்சு ஒரு model-ஐ reproduce பண்ண முடியாது.
- **Production-ல model-ஐ file paths-ல இருந்து load பண்றது.** Registry use பண்ணுங்க, அப்போ deploy ஆன version தெளிவா தெரியும்.
- **Overall score-ஐ மட்டும் வச்சு promote பண்றது.** Segments-ஐயும் recent data-வையும் check பண்ணுங்க.
- **Rollback plan இல்லாதது.** முந்தைய version-ஐ ready-ஆ வச்சுக்கோங்க.
- **கடைசி run-ஐ மட்டும் log பண்றது.** தோத்துப்போன experiments எது work ஆகாதுன்னு team-க்கு சொல்லிக் கொடுக்கும்; அவற்றை வச்சுக்கோங்க.
- **Seed-ஐ மறக்கிறது.** அது இல்லைன்னா, அதே code, data-வோட ரெண்டு runs வேற வேற models தரலாம்.
- **Production registry alias-க்கு பதிலா ஒரு file path-ஐ load பண்றது.**
- **Overall metrics மட்டும் log பண்றது**, அதனால promotion முக்கிய segments-ஐ check பண்ண முடியாது.
- **ஒரு laptop-ல tracking**, அதோட சேர்ந்து history-உம் காணாம போகும்.

## Tracking இலகுவா இருக்கலாம் நேரங்கள்

- **ஒரே ஒரு quick experiment**: results எழுதி வச்ச ஒரு notebook போதும்.
- **Prompt-only prototypes**: prompt versions, scores உள்ள ஒரு spreadsheet நல்ல ஆரம்பம்.
- **ஒரு தடவை train பண்ணி அரிதா மாறுற model**: அதோட lineage-ஐ ஒரு தடவை கவனமா record பண்ணுங்க.

## Demo-ல இருந்து production-க்கு

- **ஒவ்வொரு run-க்கும் commit, data version, parameters, segment metrics-ஐ log பண்ணுங்க.**
- **Registry alias-ல இருந்து serve பண்ணுங்க**, automated check-உம் owner approval-உம் வச்சு promote பண்ணுங்க.
- **முந்தைய champion-ஐ** rollback-க்கு ready-ஆ வச்சிருங்க.
- **Prompt, retrieval experiments-ஐ** training runs மாதிரியே track பண்ணுங்க.
- **Access control உள்ள, backup எடுக்கப்பட்ட shared tracking server** ஓட்டுங்க.

## Practice பண்ணுங்க

MLflow-ஓட tracking guide-ஐயும் Made With ML-ஓட experiment tracking, versioning lessons-ஐயும் படிங்க.

1. ஒரு training script-ல tracking சேருங்க: parameters, metrics, Git commit, data hash, model.
2. ரெண்டு settings-ஐ மாத்தி பத்து experiments ஓட்டுங்க, tracking UI-ல compare பண்ணுங்க.
3. Best model-ஐ register பண்ணுங்க, "current production" model-ஓட compare பண்ற ஒரு promotion check எழுதுங்க, register ஆன model-ஐ தனி prediction script-ல load பண்ணுங்க.
4. உங்க registered versions-ல ரெண்டு மேல promote_if_better ஓட்டுங்க, அப்புறம் alias-ஐ rollback பண்ணி, serving code பழைய version-ஐ load பண்றதை confirm பண்ணுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** ஒரு prediction-ஐ, அதை உருவாக்கின model-ஓட run, code commit, data version வரை trace பண்ண முடியும்.
