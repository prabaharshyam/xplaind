## இது என்ன

**Regression** features-ல இருந்து ஒரு number-ஐ predict பண்ணும்: ஒரு delivery time, ஒரு price, அடுத்த வார demand. **Linear regression**, prediction-ஐ features-ஓட ஒரு weighted sum கூட ஒரு constant-னு assume பண்ணும்:

predicted delivery minutes = 6 + 2.1 × distance in km + 0.4 × items + 3 × (rain? 1 or 0)

ஒவ்வொரு weight-உம் ஒரு **coefficient**. மத்த features-ஐ fixed-ஆ வச்சுக்கிட்டு, அந்த feature-ல ஒரு unit மாறுனா prediction எவ்வளவு மாறும்னு அது சொல்லும். இங்க, ஒரு extra km 2.1 minutes சேர்க்கும், மழை 3 சேர்க்கும். Past data-ல predictions-ஐ actual values-க்கு எல்லாத்தையும் விட நெருக்கமா கொண்டு வர்ற weights-ஐ training கண்டுபிடிக்கும்.

மத்த regression models (decision trees, gradient boosting, neural networks) curves-ஐயும் interactions-ஐயும் follow பண்ண முடியும். இருந்தாலும் ஆரம்பிக்க வேண்டியது linear regression-ல தான்: அது fast, explain பண்ண ஈஸி, எந்த complex model-உம் beat பண்ண வேண்டிய baseline அது தான்.

```text
  price
   |                                  *
   |                          *   *
   |                 *    * /        <- fitted line: price = a + b x feature
   |          *    *   /  *
   |     *      /  *
   |   *    /                  residual = actual - predicted
   |    /  *                   (vertical gap from point to line)
   +-------------------------------- car age, km, ...
```

ஒரு real point-க்கும் line-க்கும் இடையில இருக்குற gap தான் **residual**. இந்த lesson-ல கிட்டத்தட்ட எல்லாமே residuals-ஐ நேர்மையா measure பண்றதையும் அதோட patterns-ஐ படிக்கிறதையும் பத்தி தான்.

Sellers-க்கு ஒரு suggested-price feature build பண்ற Chennai-ல இருக்குற ஒரு used-car marketplace-ஐ இந்த lesson follow பண்ணுது.

## இது எப்படி வேலை செய்யுது

```flow
dir: LR
title: Regression loop
Time வச்சு split -> Baseline
Baseline -> Linear model
Linear model -[residuals-ஐ படிங்க]-> Features அல்லது target-ஐ சரி பண்ணுங்க
Features அல்லது target-ஐ சரி பண்ணுங்க -> Tree model
Tree model -[latest months-ல compare பண்ணுங்க]-> Ship பண்ணி monitor பண்ணுங்க
```

### Fitting

வழக்கமான loss **mean squared error** (MSE): predicted values-க்கும் actual values-க்கும் இடையில இருக்குற gaps-ஓட squares-ஓட average. Square பண்றதால ஒரு ₹2 லட்சம் miss, ஒரு ₹1 லட்சம் miss-ஐ விட நாலு மடங்கு count ஆகும், அதனால line பெரிய errors பக்கம் வளையும். scikit-learn மாதிரி libraries இதை ஒரே call-ல fit பண்ணும்.

### Data-வை split பண்றது

Model train ஆகாத data-ல தான் எப்பவும் evaluate பண்ணணும். காலப்போக்குல மாறுற எதுக்கும் (prices, demand, delivery times), test set **latest** period-ஆ இருக்கணும்: பழைய months-ல train பண்ணுங்க, கடைசியா வந்த months-ல test பண்ணுங்க. Random split months-ஐ கலந்துடும், அதனால test months-ஓட price level-ஐ model ஏற்கனவே பார்த்துடுச்சு. அப்போ அதோட score, market நகர்ந்த பிறகு அடுத்த மாசம் இருக்கப்போறதை விட நல்லா தெரியும். இது ஒரு வகை data leakage.

### Error-ஐ measure பண்றது

- **MAE** (mean absolute error): errors-ஓட average size, original units-ல. "சராசரியா ₹59,000 தப்பு"-னு ஒரு business team-க்கு explain பண்றது ஈஸி.
- **RMSE** (root mean squared error): MSE-ஓட square root, இதுவும் original units-ல. இது எப்பவுமே குறைஞ்சது MAE அளவுக்காவது இருக்கும். ரெண்டுக்கும் இடையில பெரிய gap இருந்தா, சில predictions ரொம்ப மோசமா தப்பா இருக்குன்னு அர்த்தம்.
- **MAPE** (mean absolute percentage error): "சராசரியா 11% தப்பு". Values மலிவுல இருந்து விலை அதிகம் வரை இருக்கும்போது useful, ஆனா actual values zero-க்கு பக்கத்துல இருந்தா இது உடைஞ்சுடும்.
- **R²**: explain ஆன variation-ஓட share. இது அதிகபட்சம் 1. Test data-ல இது **negative**-ஆ கூட இருக்கலாம், அதாவது average-ஐ predict பண்றதை விட model மோசம். ஒரே data-ல models-ஐ compare பண்ண இது useful, ஆனா business users-க்கு இது intuitive-ஆ தோணுறது அரிது.

| Measure | எப்படி படிக்கலாம் | எப்போ use பண்ணணும் |
| --- | --- | --- |
| MAE | "சராசரியா ₹59,000 தப்பு" | Business users புரிஞ்சுக்குற ஒரு number வேணும்போது |
| RMSE | MAE மாதிரி தான், ஆனா பெரிய misses அதிகமா count ஆகும் | Refunds, buy-back guarantees மாதிரி, பெரிய errors-க்கு குறிப்பா cost அதிகமா இருக்கும்போது |
| MAPE | "சராசரியா 11% தப்பு" | Values எப்பவும் zero-க்கு பக்கத்துல வராம, percentage error தான் முக்கியமா இருக்கும்போது |
| R² | Explain ஆன variation-ஓட share | ஒரே test data-ல models-ஐ compare பண்ணும்போது |

**ஒரு decision rule.** ஒரு தப்போட cost-க்கு match ஆகுற metric-ஐ தேர்ந்தெடுங்க. Error-ஓட ஒவ்வொரு rupee-க்கும் ஒரே cost-னா, MAE use பண்ணுங்க. மூணு ₹1 லட்சம் misses-ஐ விட ஒரு ₹3 லட்சம் miss அதிகமா பாதிக்கும்னா, RMSE-ஐ கவனிங்க. ஒவ்வொரு தடவையும் model பக்கத்துலயே median baseline-ஐயும் report பண்ணுங்க.

### Coefficients-ஐ படிக்கிறது

Coefficients units-ஐயும் model-ல இருக்குற மத்த features-ஐயும் பொறுத்தது. ரெண்டு features ஒரே information-ஐ கொண்டு வந்தா (distance-உம் travel time-உம், அல்லது car age-உம் kilometres-உம்), model அதுக்கு இடையில weight-ஐ மாத்தி மாத்தி குடுக்கலாம். அப்போ predictions ஒரே மாதிரி இருந்தாலும், coefficients ஒரு sample-ல இருந்து அடுத்ததுக்கு ஆடிக்கிட்டே இருக்கும். இது தான் **multicollinearity**. இதை கண்டுபிடிக்க, features-க்கு இடையிலான correlations-ஐ check பண்ணுங்க, அல்லது ஒவ்வொண்ணுக்கும் variance inflation factor (VIF)-ஐ compute பண்ணுங்க. ஒரு common rule of thumb படி VIF 4-க்கு மேல இருந்தா பார்க்க வேண்டியது, 10-க்கு மேல இருந்தா serious. சரி பண்ண, overlap ஆகுற features-ல ஒண்ணை drop பண்ணுங்க அல்லது merge பண்ணுங்க.

Coefficients association-ஐ தான் சொல்லும், cause-ஐ இல்ல. அதுக்கு confidence intervals வேணும்னா, வழக்கமான formulas errors ஒண்ணுக்கொண்ணு independent-ஆவும், எல்லா இடத்துலயும் கிட்டத்தட்ட ஒரே spread-ஓடவும் இருக்கும்னு assume பண்ணும். ஒரே car-ஓட repeat sales, அல்லது price கூட கூட வளர்ற errors, அந்த assumptions-ஐ உடைச்சுடும்.

### Residual patterns, என்ன பண்ணணும்

ஒவ்வொரு feature-க்கு எதிராவும், predicted value-க்கு எதிராவும் residuals-ஐ plot பண்ணுங்க.

- **ஒரு random cloud:** model pattern-ஐ பிடிச்சுடுச்சு.
- **ஒரு curve:** ஒரு non-linear effect. ஒரு transformed feature (distance squared, age bands) சேருங்க, அல்லது ஒரு tree model-ஐ try பண்ணுங்க.
- **ஒரு funnel** (price வளர வளர errors-உம் வளரும்): errors proportional. Target-ஓட log-ஐ model பண்ணுங்க.
- **பெரிய errors-ஓட ஒரு cluster:** model மோசமா handle பண்ற ஒரு group, ஒரு brand மாதிரி, அல்லது ஒரு data problem.
- **சில extreme points:** squared error அவை line-ஐ இழுக்க விடும். முதல்ல அவற்றை investigate பண்ணுங்க. அவை data errors-ஆ இருந்தா மட்டும் remove பண்ணுங்க (ஒரு ₹50 listing, 9,99,999 km ஓடின ஒரு car); இல்லைன்னா ஒரு robust loss-ஐ யோசிங்க.

### Log targets, திரும்பி வர்ற வழி

Used-car prices skewed-ஆ இருக்கும்: நிறைய மலிவான cars, விலை அதிகமான cars-ஓட ஒரு நீளமான tail. log(price)-ல train பண்ணா model percentage errors-ஐ fit பண்ணும். அது "ஒவ்வொரு வருஷமும் price-ஐ 11% குறைக்குது"-ங்குறதை ஒரு straight line-ஆ மாத்தும், negative price-ஐ ஒருபோதும் predict பண்ணாது.

Gotcha திரும்பி வர்ற வழியில தான். Predicted log price-ஓட exp-ஐ எடுத்தா, அந்த features-க்கு கிட்டத்தட்ட **median** price தான் கிடைக்கும், mean இல்ல. Mean வேணும்னா, training data-ல exp(residual)-ஓட average-ஆல multiply பண்ணுங்க. இதுக்கு smearing correction-னு பேர். Log errors சின்னதா இருந்தா correction சின்னது, அவை பெருசா இருந்தா அது வளரும்.

### Regularisation, scaling

**Ridge**, **lasso** regression coefficients-ஓட size மேல ஒரு penalty சேர்க்கும். நிறைய features இருக்கும்போது அல்லது overlap ஆகுற features இருக்கும்போது இது overfitting-ஐ குறைக்கும். Lasso சில coefficients-ஐ சரியா zero ஆக்கலாம், அது அந்த features-ஐ remove பண்ணும். Penalty strength (alpha)-ஐ cross-validation வச்சு தேர்ந்தெடுப்பாங்க, `RidgeCV` இதை உங்களுக்காக பண்ணும்.

Penalty coefficient size மேல வேலை செய்யும், size units-ஐ பொறுத்தது. ஒரு kilometre-க்கான coefficient ரொம்ப சின்னது, ஒரு வருஷத்துக்கான coefficient பெருசு, அதனால scaling இல்லைன்னா அவை சமமில்லாம shrink ஆகும். ஒரு pipeline-ல ridge அல்லது lasso-க்கு முன்னாடி எப்பவும் ஒரு `StandardScaler` வைங்க. Tree models thresholds-ல split பண்ணும், அதனால அதுக்கு scaling தேவையில்ல.

### Linear regression-ஐ தாண்டி எப்போ போகணும்

Residual plots curves அல்லது interactions-ஐ (ஒரு effect இன்னொண்ணை பொறுத்து இருக்குறது) காட்டி, அதை சில features வச்சு சரி பண்ண முடியலைன்னா, அல்லது நிறைய mixed features இருந்தா, gradient boosting மாதிரி tree-based models-க்கு போங்க. இருந்தாலும் linear model-ஐ உங்க report-ல வச்சிருங்க. Complex model கொஞ்சமே ஜெயிச்சா, இன்னும் simple-ஆனது better product-ஆ இருக்கலாம்.

Prices-க்கு trees-ஓட ஒரு limit முக்கியம்: training-ல பார்த்த highest values-க்கு மேல அவை predict பண்ண முடியாது. ஒரு linear model ஒரு trend-ஐ extrapolate பண்ண முடியும், அது நல்லதுக்கோ கெட்டதுக்கோ.

### Code: baseline, linear, log target, boosting

24 months-க்கான synthetic used-car sales. Age கூட கூட prices குறையும், premium 2,000 cc cars இன்னும் வேகமா value இழக்கும், மொத்த market-உம் மெதுவா மேல drift ஆகும். Test set கடைசி 4 months.

```python
import numpy as np, pandas as pd
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.dummy import DummyRegressor
from sklearn.linear_model import RidgeCV
from sklearn.compose import TransformedTargetRegressor
from sklearn.ensemble import HistGradientBoostingRegressor
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score

rng = np.random.default_rng(5)
n = 8000
df = pd.DataFrame({
    "month": rng.integers(0, 24, n),      # sale month: 0 is the oldest
    "age": rng.uniform(0, 12, n),         # years
    "km": rng.uniform(5_000, 150_000, n),
    "engine_cc": rng.choice([1000, 1200, 1500, 2000], n),
    "metro": rng.integers(0, 2, n),       # 1 if sold in a metro city
})
rate = 0.10 + 0.06 * (df.engine_cc == 2000)   # premium cars lose value faster
price = (900_000 * np.exp(-rate * df.age) * (df.engine_cc / 1200)
         * (1 - df.km / 600_000) * (1 + 0.05 * df.metro) * (1 + 0.004 * df.month))
df["price"] = price * rng.lognormal(0, 0.12, n)

features = ["age", "km", "engine_cc", "metro"]
train, test = df[df.month < 20], df[df.month >= 20]   # older sales vs latest 4 months
X_tr, y_tr, X_te, y_te = train[features], train.price, test[features], test.price

alphas = np.logspace(-3, 3, 13)
models = {
    "median baseline": DummyRegressor(strategy="median"),
    "ridge": make_pipeline(StandardScaler(), RidgeCV(alphas=alphas)),
    "ridge, log target": TransformedTargetRegressor(
        make_pipeline(StandardScaler(), RidgeCV(alphas=alphas)), func=np.log, inverse_func=np.exp),
    "boosting": HistGradientBoostingRegressor(max_iter=300, random_state=5),
}
for name, m in models.items():
    pred = m.fit(X_tr, y_tr).predict(X_te)
    mae, rmse = mean_absolute_error(y_te, pred), mean_squared_error(y_te, pred) ** 0.5
    print(f"{name:<18} MAE ₹{mae:>9,.0f}  RMSE ₹{rmse:>9,.0f}  R² {r2_score(y_te, pred):6.2f}")
```

scikit-learn 1.9.1 கூட output:

```text
median baseline    MAE ₹  201,364  RMSE ₹  274,141  R²  -0.07
ridge              MAE ₹   97,976  RMSE ₹  129,071  R²   0.76
ridge, log target  MAE ₹   80,155  RMSE ₹  109,775  R²   0.83
boosting           MAE ₹   59,212  RMSE ₹   82,164  R²   0.90
```

Baseline-ஓட R² negative-ஆ இருக்குறதை கவனிங்க: பழைய sales-ல இருந்து எடுத்த ஒரு constant guess, test months-ஓட சொந்த average price-ஐ விட மோசமா பண்ணுது.

**Group வாரியா errors.** ஒரு average, model தப்பா பண்ற ஒரு segment-ஐ மறைச்சிடலாம். இங்க percentage error தான் இன்னும் fair, ஏன்னா விலை அதிகமான cars-க்கு rupee errors இன்னும் பெருசா இருக்கும்:

```python
lin, best = models["ridge, log target"], models["boosting"]
pct = pd.DataFrame({
    "ridge_log": np.abs(lin.predict(X_te) - y_te) / y_te,
    "boosting": np.abs(best.predict(X_te) - y_te) / y_te,
})
print((pct.groupby(X_te.engine_cc).mean() * 100).round(1))
```

```text

engine_cc
1000            12.0      10.6
1200            11.9      10.7
1500            18.1      10.4
2000            17.0      11.0
```

**Linear model-ஐ படிக்கிறது.** Scaled pipeline-ஓட coefficients ஒரு standard deviation-க்கு. அதை real units-ல திரும்ப பெற, scaler-ஓட spread-ஆல divide பண்ணுங்க:

```python
ridge = lin.regressor_
coef = ridge[-1].coef_ / ridge[0].scale_
print(f"per year: {np.expm1(coef[0]):.1%}   per 10,000 km: {np.expm1(coef[1] * 10_000):.1%}   "
      f"metro: {np.expm1(coef[3]):+.1%}   alpha chosen: {ridge[-1].alpha_:.2f}")
```

```text
per year: -10.8%   per 10,000 km: -1.8%   metro: +5.6%   alpha chosen: 0.32
```

**ஒரு point-க்கு பதிலா ஒரு price range.** Sellers-உம் buyers-உம் ஒரு number-ஐ விட ஒரு band-ஐ அதிகமா நம்புவாங்க:

```python
q = dict(loss="quantile", max_iter=300, random_state=5)
lo = HistGradientBoostingRegressor(quantile=0.1, **q).fit(X_tr, y_tr).predict(X_te)
hi = HistGradientBoostingRegressor(quantile=0.9, **q).fit(X_tr, y_tr).predict(X_te)
print(f"inside the 10-90% band: {((y_te >= lo) & (y_te <= hi)).mean():.0%}   "
      f"above the top: {(y_te > hi).mean():.0%}")
```

```text
inside the 10-90% band: 66%   above the top: 25%
```

நல்லா calibrate ஆன 10 முதல் 90% band real prices-ல சுமார் 80%-ஐ உள்ள வச்சிருக்கும், சுமார் 10% அதுக்கு மேல இருக்கும். இது 66% தான் வச்சிருக்கு, real prices-ல கால்வாசி top-க்கு மேல இருக்கு. இதுக்கு ரெண்டு காரணம். Random split-லயே இந்த band சுமார் 70% தான் வச்சிருக்கும், ஏன்னா quantile models அடிக்கடி ரொம்ப narrow-ஆ இருக்கும். Time split அதை இன்னும் மோசமாக்குது, ஏன்னா training months-க்கு அப்புறம் prices ஏறிடுச்சு. Users-க்கு ranges-ஐ காட்டுறதுக்கு முன்னாடி, ஒரு recent validation month வச்சு band-ஐ widen பண்ணுங்க, அடிக்கடி retrain பண்ணுங்க.

**Edges-ஐ பாதுகாங்க.** Training data-ல ஒவ்வொரு feature-ஓட range-ஐயும் record பண்ணுங்க. அதுக்கு வெளியே வர்ற requests-ஐ (ஒரு 25 வருஷ பழைய car, 4,00,000 km) confident-ஆ ஒரு price குடுக்குறதுக்கு பதிலா flag பண்ணுங்க.

## ஒரு worked example

Chennai marketplace team மேல இருக்குற code-ஐ தங்களோட முதல் experiment-ஆ use பண்ணுது. Data synthetic, அதனால numbers method-ஐ விளக்குற illustrations தான், ஒரு real market-ல இருந்து வந்த results இல்ல. Outputs-ஐ வரிசையா படிங்க.

1. **Baseline.** ஒவ்வொரு தடவையும் median price-ஐ predict பண்ணா MAE ₹2,01,364. எந்த useful model-உம் இதை பெரிய margin-ல beat பண்ணணும்.
2. **Linear regression** (scaled, ridge) error-ஐ பாதியா குறைச்சு ₹97,976 ஆக்குது. Cross-validation ஒரு சின்ன alpha-வை தேர்ந்தெடுத்துச்சு, அதனால இங்க penalty கிட்டத்தட்ட எதையும் மாத்தலை: நாலு features, ஆயிரக்கணக்கான rows இருக்கும்போது overfit ஆக பெருசா எதுவும் இல்ல.
3. **Log target.** Prices ஒவ்வொரு வருஷமும் ஒரு percentage குறையும்; அது rupees-ல ஒரு curve, ஆனா log price-ல ஒரு straight line. MAE ₹80,155-க்கு இறங்குது. Model படிக்க ஈஸியான ஒரு கதையையும் குடுக்குது: age-ல ஒவ்வொரு வருஷத்துக்கும் சுமார் 10.8% குறைவு, ஒவ்வொரு 10,000 km-க்கும் 1.8% குறைவு, metro cities-ல 5.6% அதிகம்.
4. **Error analysis.** 1,500 cc, 2,000 cc cars-க்கு linear model-ஓட percentage error சுமார் 12%-ல இருந்து 17 முதல் 18%-க்கு தாவுறதை group table காட்டுது. இதுக்கு ரெண்டு காரணம். Engine size-க்கு log price மேல straight-line effect இல்ல, premium cars இன்னும் வேகமா depreciate ஆகும்; இது ஒரு plain linear model represent பண்ண முடியாத ஒரு interaction.
5. **Gradient boosting** data-ல இருந்து ரெண்டு effects-ஐயும் கத்துக்குது. MAE ₹59,212-க்கு குறையுது, ஒவ்வொரு engine group-லயும் சுமார் 11% error, R² 0.90-க்கு ஏறுது.
6. **Honesty checks.** Training months-ல boosted model-ஓட MAE சுமார் ₹40,500, latest months-ல இருக்குற ₹59,212-ஐ விட ரொம்ப கம்மி. Time split-க்கு பதிலா random split பண்ணா சுமார் ₹55,000 வரும், அது reality-ஐ விட நல்லா தெரியுது. Price band real prices-ல 66%-ஐ தான் cover பண்ணுது, 80% இல்ல.

| Model | Test MAE | Test RMSE | Team-க்கு அது கத்துக்குடுத்தது |
| --- | --- | --- | --- |
| Median baseline | ₹2,01,364 | ₹2,74,141 | Beat பண்ண வேண்டிய அளவுகோல் |

**எது ship ஆகுது.** Boosted model suggested price-ஐ set பண்ணுது, அது widen பண்ண ஒரு range-ஆ காட்டப்படுது. Sellers-க்கு காட்டுற explanation-க்கு log-linear coefficients தான் feed பண்ணுது ("ஒவ்வொரு extra வருஷமும் பொதுவா price-ஐ சுமார் 11% குறைக்கும்"), approximate-னு தெளிவா label பண்ணி. ரெண்டு வேலைக்கு ரெண்டு models use பண்றது common: number-க்கு எல்லாத்தையும் விட accurate-ஆனது, நேர்மையான explanation-க்கு இன்னும் simple-ஆன ஒண்ணு. Team மாசா மாசம் retrain பண்ணுது, ஏன்னா போன quarter-ஓட prices பழசாகிடும்னு drift காட்டுச்சு.

## பொதுவான தவறுகள்

- **Baseline இல்லாதது.** உங்க model பக்கத்துல "எப்பவும் median-ஐ predict பண்றது" இல்லைன்னா, அது value சேர்க்குதான்னு சொல்ல முடியாது.
- **Training data-லயே evaluate பண்றது.** ₹40,500-க்கும் ₹59,212-க்கும் இடையில இருக்குற gap காட்டுற மாதிரி, errors reality-ஐ விட ரொம்ப சின்னதா தெரியும்.
- **Time order-ல இருக்குற data-ல random split.** Market prices drift ஆகும். முந்தைய months-ல train பண்ணி, latest months-ல test பண்ணுங்க.
- **Coefficients-ஐ causes-ஆ எடுத்துக்குறது.** Model-ஓட assumptions-க்கு கீழ அவை association-ஐ தான் சொல்லும், features overlap ஆனா அவை ஆடும்.
- **Scaling இல்லாம ridge அல்லது lasso.** அப்போ penalty ஒரு feature எவ்வளவு useful-ங்குறதை இல்லாம, units-ஐ பொறுத்து இருக்கும்.
- **Skewed targets-ஐ கண்டுக்காம விடுறது.** Log price-ஐ predict பண்றது அடிக்கடி இன்னும் நல்லா work ஆகும், ஆனா prediction-ஓட exp median-க்கு பக்கத்துல இருக்கும், mean இல்லைன்னு ஞாபகம் வச்சுக்கோங்க.
- **Extrapolations-ஐ நம்புறது.** Training range-க்கு வெளியே இருக்குற predictions guesses தான்.
- **R²-ஐ மட்டும், அல்லது overall MAE-ஐ மட்டும் report பண்றது.** Business users-க்கு "சராசரியா ₹59,000 தப்பு" புரியும், ஒரே ஒரு average பெரிய errors இருக்குற ஒரு segment-ஐ மறைச்சிடலாம்.
- **Range தேவைப்படுற decisions-க்கு point predictions**, price advice மாதிரி, அல்லது யாருமே coverage-ஐ check பண்ணாத ranges.

## Regression model தேவையில்லாத இடங்கள்

- **ஏற்கனவே ஒரு simple formula இருக்கு**, ஒரு tariff table அல்லது publish ஆன ஒரு rate card மாதிரி.
- **கத்துக்க ரொம்ப கம்மி data**: domain experts-ஓட ஒரு rule of thumb இன்னும் reliable-ஆ இருக்கலாம்.
- **கேள்வி ஒரு category**, number இல்ல, "இந்த வாரம் இது விக்குமா" மாதிரி: classification use பண்ணுங்க.

## Demo-ல இருந்து production-க்கு

- **ஒவ்வொரு report-லயும் baseline-ஐ வச்சிருங்க.**
- **Segment வாரியா errors-ஐ check பண்ணுங்க**, feature range வாரியாவும், ஒவ்வொரு retrain-லயும்.
- **Out-of-range inputs-ஐ flag பண்ணுங்க**, predict பண்றதுக்கு பதிலா.
- **Decisions uncertainty-ஐ பொறுத்து இருக்குற இடங்கள்ல ranges குடுங்க**, அதோட coverage-ஐ ஒவ்வொரு மாசமும் check பண்ணுங்க.
- **Real outcomes வர வர errors-ஐ monitor பண்ணுங்க**, market drift ஆனா retrain பண்ணுங்க.

## Practice பண்ணுங்க

Google-ஓட linear regression module-ஐயும் Kaggle-ஓட Intro to Machine Learning course-ஐயும் முடிங்க.

1. மேல இருக்குற நாலு code blocks-ஐயும் run பண்ணுங்க. அப்புறம் `month`-ஐ ஒரு feature-ஆ சேர்த்து திரும்ப run பண்ணுங்க. எந்த models improve ஆகுது, training months-ஐ தாண்டி trend-ஐ boosting ஏன் follow பண்ண முடியாது?
2. Date column இருக்குற ஒரு public housing அல்லது used-car dataset-ல linear regression fit பண்ணுங்க. Latest period-ல MAE, RMSE-ஐ report பண்ணி, ஒரு median baseline கூட compare பண்ணுங்க.
3. ரெண்டு features-க்கும் predicted value-க்கும் எதிரா residuals-ஐ plot பண்ணுங்க. ஒரு pattern-ஐ (curve, funnel அல்லது cluster) சொல்லி, நீங்க try பண்ணப்போற fix-ஐயும் சொல்லுங்க.
4. உங்க dataset-ல ஒவ்வொரு feature-க்கும் VIF-ஐ compute பண்ணி, எந்த pair எல்லாத்தையும் விட அதிகமா overlap ஆகுதுன்னு சொல்லுங்க.
5. 10%, 90% quantile models-ஐ fit பண்ணி, ஒவ்வொரு age band-க்கும் band-ஓட coverage-ஐ report பண்ணுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** உங்க best model-ஓட error-ஐ business terms-ல explain பண்ண முடியும், latest period-ல அது baseline-ஐ beat பண்ணுதுன்னு காட்ட முடியும், linear model ஏன் பின்தங்குச்சுன்னு ஒரு காரணம் சொல்ல முடியும்.
