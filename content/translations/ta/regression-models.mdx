## இது என்ன

**Regression** features-ல இருந்து ஒரு number-ஐ predict பண்ணும். **Linear regression**, prediction-ஐ features-ஓட weighted sum + ஒரு constant-ஆ எடுத்துக்கும்:

predicted delivery minutes = 6 + 2.1 × distance in km + 0.4 × items + 3 × (rain? 1 அல்லது 0)

Weights (coefficients) மத்த features அப்படியே இருக்கும்போது, ஒவ்வொரு feature-லயும் ஒரு unit மாறுனா prediction எவ்வளவு மாறும்ன்னு சொல்லும். Training, past data-ல predictions actual values-க்கு ரொம்ப பக்கத்துல இருக்கிற மாதிரி weights-ஐ கண்டுபிடிக்கும்.

மத்த regression models (decision trees, gradient boosting, neural networks) curves, interactions-ஐ capture பண்ணும். ஆனா linear regression தான் தாண்டி போகணும்கிற baseline, explain பண்ணவும் சுலபம்.

```text
  price
   |                                  *
   |                          *   *
   |                 *    * /        <- fitted line: price = a + b x feature
   |          *    *   /  *
   |     *      /  *
   |   *    /                  residual = actual - predicted
   |    /  *                   (vertical gap from point to line)
   +-------------------------------- car age, km, ...
```

இந்த lesson-ல Chennai-ல ஒரு used-car marketplace, sellers-க்கு suggested-price feature build பண்றதை follow பண்ணுவோம்.

## இது எப்படி work ஆகுது

**Fitting.** வழக்கமான loss mean squared error: predicted values-க்கும் actual values-க்கும் உள்ள வித்தியாசத்தோட squares-ஓட average. Square பண்றது பெரிய errors-ஐ கடுமையா தண்டிக்கும். scikit-learn மாதிரி libraries இதை ஒரே call-ல fit பண்ணும்.

**Evaluating.** எப்பவும் model train ஆகாத data-ல.

- **MAE** (mean absolute error): original units-ல errors-ஓட சராசரி அளவு ("average-ஆ 3.2 நிமிஷம் தப்பு"). Explain பண்ண சுலபம்.
- **RMSE** (root mean squared error): MAE மாதிரி தான், ஆனா பெரிய errors-ஐ அதிகமா தண்டிக்கும்.
- **R²**: explain ஆன variation-ஓட share, 0 (average-ஐ predict பண்றதை விட better இல்ல) முதல் 1 வரை. Useful தான், ஆனா business users-க்கு intuitive இல்ல.

ஒரு simple baseline-ஓட compare பண்ணுங்க, உதாரணம்: ஒவ்வொரு தடவையும் median-ஐ predict பண்றது. உங்க model அதை கொஞ்சம் தான் தாண்டுதுன்னா, அது பெருசா எதுவும் சேர்க்கல.

**Coefficients-ஐ படிக்கிறது.** Coefficients units-ஐயும், மத்த features-ஐயும் பொறுத்தது. Correlated features (distance, travel time) coefficients-ஐ நிலையில்லாம ஆக்கும். அவற்றை காரணங்களா படிக்காதீங்க.

**Non-linearity.** Real relationships வளையும்: delivery time 5 km வரை மெதுவா ஏறி, அப்புறம் தாவலாம். Transform பண்ண features சேருங்க (distance squared, buckets), அல்லது tree-based models use பண்ணுங்க.

**Outliers.** Squared error, சில extreme values fit-ஐ இழுக்க விடும். அவற்றை investigate பண்ணுங்க; data errors-ஐ cap பண்ணுங்க அல்லது நீக்குங்க; MAE-based அல்லது robust methods-ஐ யோசிங்க.

**Extrapolation.** Linear models தான் பார்த்த range-ஐ தாண்டியும் சந்தோஷமா predict பண்ணும் (training-ல அதிகபட்சம் 12 இருந்தப்போ 40 km deliveries). அந்த predictions நம்பகமானவை இல்ல.

**Regularisation.** Ridge, lasso regression, நிறைய features இருக்கும்போது overfitting-ஐ குறைக்க coefficients-ஐ சுருக்கும்; lasso சிலதை zero-ஆக்கலாம்.

**Error measure-ஐ தேர்ந்தெடுக்குறது:**

| Measure | எப்படி படிக்கிறது | எப்போ use பண்றது |
| --- | --- | --- |
| MAE | "Average-ஆ ₹29,000 தப்பு" | Business users-க்கு புரியுற number வேணும்னா |
| RMSE | MAE மாதிரி, ஆனா பெரிய misses அதிகம் எண்ணப்படும் | பெரிய errors-க்கு குறிப்பா செலவு அதிகம்னா |
| MAPE | "Average-ஆ 6% தப்பு" | Values ஒருபோதும் zero பக்கத்துல இல்லாதப்போ |
| R² | Explain ஆன variation-ஓட share | ஒரே data-ல models-ஐ compare பண்ணும்போது |

**Residuals-ஐ படிக்கிறது.** Errors-ஐ ஒவ்வொரு feature-க்கு எதிரா plot பண்ணுங்க. Random cloud-னா model pattern-ஐ capture பண்ணிடுச்சு. Curve, funnel, cluster-னா எதையோ miss பண்ணிடுச்சு: ஒரு non-linear effect, அது மோசமா கையாளுற ஒரு group, அல்லது data பிரச்சனை.

**Linear regression-ஐ தாண்டி எப்போ போகணும்.** Linear regression வேகமானது, explain பண்ணக்கூடியது, வலுவான baseline. Residual plots-ல line capture பண்ண முடியாத curves, interactions தெரிஞ்சா, mixed types-ல நிறைய features இருந்தா, அல்லது accuracy gain அதிக complexity-க்கு worth-ஆ இருந்தா gradient boosting மாதிரி tree-based models-க்கு போங்க. அப்படியும் linear model-ஐ உங்க evaluation-ல ஓடிக்கிட்டே வச்சுக்கோங்க: complex model அதை கொஞ்சம் தான் தாண்டுதுன்னா, simple-ஆனது தான் better product choice-ஆ இருக்கலாம்.

**Baseline, linear, log target, boosting பக்கத்துல பக்கத்துல.** வளையுற age effect இருக்குற synthetic used-car prices:

```python
import numpy as np, pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.dummy import DummyRegressor
from sklearn.linear_model import Ridge
from sklearn.compose import TransformedTargetRegressor
from sklearn.ensemble import HistGradientBoostingRegressor
from sklearn.metrics import mean_absolute_error, mean_squared_error

rng = np.random.default_rng(5)
n = 6000
df = pd.DataFrame({"age": rng.uniform(0, 12, n), "km": rng.uniform(5_000, 150_000, n),
                   "engine_cc": rng.choice([1000, 1200, 1500, 2000], n), "city_metro": rng.integers(0, 2, n)})
price = 900_000 * np.exp(-0.12 * df.age) * (df.engine_cc / 1200) * (1 - df.km / 600_000) * (1 + 0.05 * df.city_metro)
y = price * rng.lognormal(0, 0.12, n)
X_tr, X_te, y_tr, y_te = train_test_split(df, y, test_size=0.25, random_state=5)

models = {
    "median baseline": DummyRegressor(strategy="median"),
    "ridge": Ridge(alpha=1.0),
    "ridge, log target": TransformedTargetRegressor(Ridge(alpha=1.0), func=np.log, inverse_func=np.exp),
    "boosting": HistGradientBoostingRegressor(max_iter=300, random_state=5),
}
for name, m in models.items():
    pred = m.fit(X_tr, y_tr).predict(X_te)
    print(f"{name:<18} MAE ₹{mean_absolute_error(y_te, pred):>9,.0f}   RMSE ₹{mean_squared_error(y_te, pred) ** 0.5:>9,.0f}")
```

ஒவ்வொரு step-ஓட value-வையும் இந்த table காட்டும்: "எப்பவும் median-ஐ predict பண்றதை" model எவ்வளவு தாண்டுது, log target அல்லது tree model curve-ஐ better-ஆ capture பண்ணுதான்னு.

**Group வாரியா errors.** ஒரு average, model தப்பா பண்ற ஒரு segment-ஐ மறைச்சிடலாம்:

```python
best = models["boosting"]
err = pd.DataFrame({"abs_err": np.abs(best.predict(X_te) - y_te), "age_band": pd.cut(X_te.age, [0, 3, 6, 9, 12])})
print(err.groupby("age_band", observed=True)["abs_err"].mean().round(-2))
```

**Point-க்கு பதிலா price range.** Buyers-உம் sellers-உம் ஒரு band-ஐ நம்புவாங்க:

```python
lo = HistGradientBoostingRegressor(loss="quantile", quantile=0.1, max_iter=300).fit(X_tr, y_tr)
hi = HistGradientBoostingRegressor(loss="quantile", quantile=0.9, max_iter=300).fit(X_tr, y_tr)
inside = ((y_te >= lo.predict(X_te)) & (y_te <= hi.predict(X_te))).mean()
print(f"share of real prices inside the 10–90% band: {inside:.0%}")      # should be near 80%
```

Real prices-ல 80%-ஐ விட ரொம்ப குறைவானவை band-க்குள்ள விழுந்தா, intervals நம்புறதுக்கு ரொம்ப குறுகலா இருக்கு.

**Edges-ஐ பாதுகாங்க.** Training data-ல ஒவ்வொரு feature-ஓட range-ஐயும் record பண்ணி, அதுக்கு வெளியே வர்ற requests-ஐ (25 வயசு car, 400,000 km) confident price திருப்பி கொடுக்குறதுக்கு பதிலா flag பண்ணுங்க.

## ஒரு worked example

Chennai-ல ஒரு used-car marketplace listing prices-ஐ suggest பண்ண விரும்புது.

Data: car age, ஓடுன kilometres, brand, model, fuel type, city, owners எண்ணிக்கையோட 18,000 past sales.

1. Baseline: அந்த model, year-க்கான median price-ஐ predict பண்றது. MAE ₹68,000.
2. Features-ல linear regression (brand, model one-hot encode பண்ணி, prices skewed-ஆ இருக்குறதால price-ஓட log-ஐ target-ஆ வச்சு). MAE ₹41,000.
3. Error analysis: premium cars-லயும், 12 வருஷத்துக்கு மேல பழைய cars-லயும் errors பெரிசு. Age-க்கு எதிரா residuals plot ஒரு curve-ஐ காட்டுது.
4. அதே features-ல gradient-boosted trees. MAE ₹29,000.

Prices-க்கு boosted model-ஐ ship பண்றாங்க, ஆனா sellers-க்கு காட்டுற explanation-க்கு linear model-ஓட coefficients-ஐ வச்சிருக்காங்க ("இந்த model-க்கு ஒவ்வொரு கூடுதல் வருஷமும் price-ஐ சுமார் 9% குறைக்கும்"), approximate-ன்னு தெளிவா label பண்ணி.

| Model | MAE | குறிப்புகள் |
| --- | --- | --- |
| Model, year-க்கான median price | ₹68,000 | Baseline |
| Linear regression, log price | ₹41,000 | Explain பண்ணக்கூடிய coefficients |
| Gradient-boosted trees | ₹29,000 | பழைய, premium cars-க்கான curves-ஐ capture பண்ணுது |

ரெண்டு வேலைக்கு ரெண்டு models ship பண்றது common: number-க்கு மிகவும் accurate-ஆனதும், நேர்மையான, approximate explanation-க்கு simple-ஆனதும்.

## பொதுவான தவறுகள்

- **Baseline இல்லாதது.** அது இல்லாம ஒரு model-ஐ judge பண்ண முடியாது.
- **Training data-ல evaluate பண்றது.** Errors உண்மையை விட ரொம்ப சின்னதா தெரியும்.
- **Coefficients-ஐ காரணங்களா எடுத்துக்கிறது.** அவை model-ஓட assumptions-ல association-ஐ தான் சொல்லும்.
- **Skewed targets-ஐ கவனிக்காம விடுறது.** Prices-ஓட log-ஐ predict பண்றது பெரும்பாலும் better-ஆ work ஆகும்.
- **Extrapolations-ஐ நம்புறது.** Training range-க்கு வெளியே predictions ஊகங்கள் தான்.

- **R² மட்டும் report பண்றது.** "R² 0.87"-ஐ விட "average-ஆ ₹29,000 தப்பு"ங்குறது business users-க்கு ரொம்ப நல்லா புரியும். கூடவே rupees அல்லது minutes-ல MAE-ஐ report பண்ணுங்க.
- **Median baseline-ஓட ஒருபோதும் compare பண்ணாதது.** Model value சேர்க்குதான்னு உங்களால சொல்ல முடியாது.
- **Overall MAE மட்டும் report பண்றது**, பெரிய errors இருக்குற segment-ஐ மறைக்கும்.
- **Range தேவைப்படுற decisions-க்கு point predictions**, உதாரணம் price advice.

## Regression model தேவையில்லாத இடங்கள்

- **ஒரு simple formula ஏற்கனவே இருக்கு**, உதாரணம் tariff table அல்லது published rate card.
- **கத்துக்க ரொம்ப குறைவான data**: domain experts-ஓட rule of thumb இன்னும் நம்பகமா இருக்கலாம்.
- **கேள்வி ஒரு category, number இல்ல**, உதாரணம் "இந்த வாரம் விக்குமா": classification use பண்ணுங்க.

## Demo-ல இருந்து production-க்கு
