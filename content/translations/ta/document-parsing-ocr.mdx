## இது என்ன

**Document parsing**, files-ஐ ஒரு RAG system use பண்ணக்கூடிய text-ஆவும் structure-ஆவும் மாத்தும்: சரியான reading order-ல paragraphs, sections-ஐ குறிக்கிற headings, rows, columns உடையாத tables, citations-க்கு page numbers. மூணு approaches, பெரும்பாலும் சேர்த்து use ஆகும்:

- **Text extraction**: digital PDFs, Office files-ல இருந்து. வேகமானது, மலிவானது, ஆனா layout தெரியாது.
- **OCR** (optical character recognition): scans, photos-க்கு. Text-ஓட images-ஐ text-ஆ மாத்தும்.
- **Layout-aware parsing**: headings, columns, tables, figures, reading order-ஐ கண்டுபிடிச்சு, ஒவ்வொரு பகுதியையும் சரியா extract பண்ற models. Docling, Unstructured மாதிரி open-source tools-உம், cloud document services-உம் இதை பண்ணும். Vision-language models-உம் pages-ஐ நேரடியா படிக்கலாம்.

```flow
ஒரு file -> என்ன type? | digital PDF, scan, mixed, Word, slides, image
என்ன type? -[digital]-> Text extraction அல்லது layout-aware parser
என்ன type? -[scan]-> சரியான languages-ஓட OCR, அல்லது vision-language model
Text extraction அல்லது layout-aware parser -> Layout | columns reading order-ஆ, headings section path-ஆ, tables headers-ஓட rows-ஆ
சரியான languages-ஓட OCR, அல்லது vision-language model -> Layout
Layout -> சுத்தம் பண்றது | repeat ஆகுற headers, footers, page numbers, watermarks-ஐ நீக்குங்க
சுத்தம் பண்றது -> Metadata-ஓட chunks | document, section path, page, OCR confidence
```

இந்த lesson-ல Kochi-ல ஒரு insurance company-யோட assistant, சரியான pages-ஐ கண்டுபிடிச்சும் தப்பா பதில் சொன்னதை follow பண்ணுவோம்.

## இது எப்படி work ஆகுது

**முதல்ல document type-ஐ கண்டுபிடிங்க.** Digital PDF, scanned PDF, mixed, Word, slides, spreadsheet அல்லது image. Extract பண்ணக்கூடிய characters ரொம்ப குறைவா இருக்குற page அநேகமா ஒரு scan.

**Reading order.** Simple extraction ரெண்டு-column pages-ஐ line by line குறுக்கா படிக்கும், columns கலந்துடும். Layout analysis columns-ஐ கண்டுபிடிச்சு, ஒவ்வொண்ணையும் வரிசையா படிக்கும்.

**Tables.** தட்டையாகுற tables அர்த்தத்தை இழக்கும்: "Premium 12,450 Sum insured 5,00,000" rows முழுக்க குழப்பமா ஆகிடும். Tables-ஐ structured data-வா extract பண்ணி, ஒவ்வொண்ணையும் headers-ஐ values-ஓட வச்சிருக்குற text-ஆ மாத்துங்க (Markdown, அல்லது ஒரு row-க்கு ஒரு line: "Plan Gold: premium ₹12,450, sum insured ₹5,00,000"). முழு table-ஐயோ, headers-ஓட முழு rows-ஐயோ ஒரே chunk-ல வைங்க.

**Headings, sections.** ஒவ்வொரு chunk-ஓடவும் heading text-ஐயும் section path-ஐயும் ("Part B > Exclusions > 4.2") வச்சிருங்க. அது retrieval, filters, citations-க்கு உதவும்.

**OCR quality.** Image quality தான் accuracy-ஐ முடிவு பண்ணும்: resolution, skew, நிழல்கள், stamps, கையெழுத்து. இந்திய documents-ல English, Hindi, Tamil அல்லது வேற scripts கலந்து இருக்கும்; அவற்றை support பண்ற OCR-ஐ use பண்ணி, languages-ஐ set பண்ணுங்க. Images-ஐ pre-process பண்ணுங்க (நேராக்குங்க, contrast கூட்டுங்க), பலவீனமான pages-ஐ flag பண்ண OCR confidence scores-ஐ வச்சுக்கோங்க.

**Headers, footers, noise.** Repeat ஆகுற page headers, footers, page numbers, watermarks chunks-ஐ கெடுக்கும். பெரும்பாலான pages-ல repeat ஆகுற text-ஐ கண்டுபிடிச்சு நீக்குங்க.

**Output-ஐ check பண்ணுங்க.** Pages-ஓட ஒரு sample-ஐ originals-ஓட compare பண்ணுங்க, குறிப்பா tables, scanned pages. ஒவ்வொரு document-க்கும் track பண்ணுங்க: pages, ஒரு page-க்கு characters, கண்டுபிடிச்ச tables, OCR confidence.

**ஒவ்வொரு approach-உம் எதை handle பண்ணும்:**

| Problem | Text extraction | OCR | Layout-aware parsing |
| --- | --- | --- | --- |
| Digital text | ஆமா | தேவையில்லை | ஆமா |
| Scanned pages | இல்லை: text காலி | ஆமா | ஆமா, OCR உள்ளேயே இருக்கும் |
| ரெண்டு columns | பெரும்பாலும் கலந்துடும் | பெரும்பாலும் கலந்துடும் | சரியான reading order |
| Tables | தட்டையாகும் | தட்டையாகும் | Rows, columns அப்படியே இருக்கும் |
| Headings | சாதாரண text-ஆ தொலையும் | தொலையும் | கண்டுபிடிக்கப்படும் |
| Speed, cost | மிக வேகம், மிக மலிவு | மெதுவா | மிக மெதுவா, மிக accurate |

ஒரு practical pattern: முதல்ல மலிவான text extraction-ஐ run பண்ணுங்க. அப்புறம் checks-ல fail ஆகுற pages-ஐ மட்டும் (characters குறைவா இருக்குறது, tables கண்டுபிடிக்கப்பட்டது மாதிரி) layout-aware parsing அல்லது OCR-க்கு அனுப்புங்க. பெரிய document sets-ல இது cost-ஐ குறைக்கும்.

**Pages-ஐ மலிவானதுல இருந்து costly-க்கு route பண்ணுங்க.** Plain extraction-ஐ try பண்ணுங்க, பலவீனமான pages-ஐ மட்டும் OCR-க்கு அனுப்புங்க:

```python
import fitz                                       # PyMuPDF
import pytesseract
from PIL import Image
import io

def page_text(page, min_chars=200, langs="eng+hin+tam"):
    text = page.get_text("text")
    if len(text.strip()) >= min_chars:
        return text, "digital", None
    pix = page.get_pixmap(dpi=300)
    img = Image.open(io.BytesIO(pix.tobytes("png")))
    data = pytesseract.image_to_data(img, lang=langs, output_type=pytesseract.Output.DICT)
    words = [(w, int(c)) for w, c in zip(data["text"], data["conf"]) if w.strip() and int(c) >= 0]
    conf = sum(c for _, c in words) / len(words) if words else 0
    return " ".join(w for w, _ in words), "ocr", conf

def parse_pdf(path):
    pages = []
    for i, page in enumerate(fitz.open(path), start=1):
        text, how, conf = page_text(page)
        pages.append({"page": i, "text": text, "method": how, "ocr_conf": conf,
                      "needs_review": how == "ocr" and conf < 70})
    return pages
```

Hindi, Tamil, மத்த மொழிகளுக்கு Tesseract-க்கு அதோட language packs install ஆகியிருக்கணும். சராசரி confidence குறைவான pages, ஒரு review list-க்கோ, இன்னும் வலுவான OCR service அல்லது vision model-க்கோ போகும்.

**Tables-ஐ row-wise text-ஆ.** `pdfplumber`, digital PDFs-ல tables-ஐ கண்டுபிடிக்கும்; chunking-ஐ தாண்டி நிக்க, ஒவ்வொரு row-வையும் அதோட headers-ஓட எழுதுங்க:

```python
import pdfplumber

def tables_as_text(path):
    out = []
    with pdfplumber.open(path) as pdf:
        for n, page in enumerate(pdf.pages, start=1):
            for table in page.extract_tables():
                header, *rows = table
                for row in rows:
                    cells = [f"{h}: {v}" for h, v in zip(header, row) if h and v]
                    if cells:
                        out.append({"page": n, "text": "; ".join(cells)})
    return out

# "Plan: Gold; Premium: ₹12,450; Sum insured: ₹5,00,000"
```

இப்போ ஒவ்வொரு row-உம் ஒரு retriever match பண்ணக்கூடிய, ஒரு model quote பண்ணக்கூடிய, தானா நிக்கிற sentence.

**கஷ்டமான pages-க்கு layout-aware tools.** Docling, Unstructured மாதிரி open-source parsers-உம், cloud document services-உம் columns, headings, tables-ஐ சேர்த்து கண்டுபிடிக்கும். அவை மெதுவானவை, சில நேரம் paid-உம், அதனால மலிவான checks-ல fail ஆகுற pages-க்கு மட்டும் வச்சுக்கோங்க.

**Parsers-ஆ vision models.** குழப்பமான scans, forms, merged cells இருக்குற tables-க்கு, page image-ஐ ஒரு vision model-க்கு அனுப்பி Markdown output கேக்குறது, classic OCR-ஐ விட பெரும்பாலும் நல்லா இருக்கும். Numbers-ஐ கவனமா check பண்ணுங்க: vision models சில நேரம் digits-ஐ தப்பா படிக்கும். முடிஞ்ச இடத்துல totals-ஐ compare பண்ணுங்க.

**ஒவ்வொரு page-ம் எப்படி படிக்கப்பட்டதுன்னு record பண்ணுங்க.** ஒவ்வொரு page-க்கும் method, confidence, parser version-ஐ store பண்ணுங்க. Answers தப்பா போகும்போது, source text எப்பவாவது சரியா இருந்துச்சான்னு உடனே பார்க்கலாம்.

**உங்க browser-ல try பண்ணுங்க.** பெரும்பாலான pages-ல repeat ஆகுற lines-ஐ (headers, footers மாதிரி) கண்டுபிடிங்க, அப்போ chunking-க்கு முன்னாடி நீக்கலாம்.

```python
    "ACME Insurance - Confidential\nClaims process\nPage 2",
    "ACME Insurance - Confidential\nExclusions\nPage 3",
]
counts = Counter(line for p in pages for line in set(p.splitlines()))
repeated = {l for l, n in counts.items() if n >= 0.6 * len(pages)}
clean = ["\n".join(l for l in p.splitlines() if l not in repeated and not l.startswith("Page ")) for p in pages]
print("removed:", repeated)
print(clean)
```

## ஒரு worked example

Kochi-ல ஒரு insurance company-யோட RAG assistant, premiums, exclusions பத்தி தப்பான answers கொடுக்குது. சரியான pages கண்டுபிடிக்கப்படுதுன்னு retrieval logs சொல்லுது, ஆனா text குழம்பியிருக்கு.

அவங்களோட 600 policy documents-ஐ inspect பண்ணப்போ தெரிஞ்சது:

- ரெண்டு-column policy wordings columns குறுக்கா படிக்கப்பட்டு, சம்பந்தமில்லாத sentences கலந்துடுச்சு.
- Premium tables தட்டையாகி, model plans-ஐயும் ages-ஐயும் குழப்பிடுச்சு.
- 70 பழைய endorsements scans, text-ஏ இல்லை.
- ஒவ்வொரு page-லயும் repeat ஆகுற ஒரு header-உம், disclaimer footer-உம் இருந்துச்சு.

எல்லா PDFs-க்கும் ஒரு layout-aware parser-க்கு மாறுறீங்க, text குறைவா இருக்குற pages-ல English, Malayalam-க்கு OCR enable பண்ணி. Tables, column headers repeat ஆகுற மாதிரி ஒரு row-க்கு ஒரு line-ஆ மாற்றப்படுது. ஒவ்வொரு chunk-ஓடவும் section paths store ஆகுது, repeat ஆகுற headers, footers நீக்கப்படுது.

80-கேள்வி golden set-ல, retrieval அல்லது prompts-ல எந்த மாற்றமும் இல்லாம, சரியான answers 62%-ல இருந்து 84%-க்கு ஏறுது. பன்னிரண்டு pages-ல இன்னும் OCR confidence threshold-க்கு கீழ இருக்கு; அவற்றை client-க்கு list பண்றீங்க, அவங்க ஒன்பதுக்கு நல்ல scans தராங்க.

## பொதுவா பண்ற தப்புகள்

- **எல்லாத்துக்கும் ஒரே extractor.** Scans, digital PDFs, slides-க்கு வேற வேற handling வேணும்.
- **Tables-ஐ தட்டையாக்குறது.** Headers-ஐ values-ஓட வச்சுக்கோங்க, rows-ஐ சேர்த்தே வைங்க.
- **Reading order-ஐ கண்டுக்காம விடுறது.** Policies, circulars, reports-ல multi-column pages ரொம்ப common.
- **English-மட்டும் OCR.** உங்க documents use பண்ற மொழிகளை (Hindi, Tamil, Malayalam மாதிரி) set பண்ணுங்க, ஒவ்வொண்ணுலயும் ஒரு sample page-ஐ check பண்ணுங்க.
- **Output-ஐ page-ஓட ஒருபோதும் compare பண்ணாம இருக்கிறது.** எதையும் index பண்றதுக்கு முன்னாடி, parse ஆன சில pages-ஐ originals பக்கத்துல print பண்ணி பாருங்க. பத்து நிமிஷ spot checks பெரும்பாலான parsing bugs-ஐ கண்டுபிடிச்சிடும்.
- **Language packs இல்லாம இருக்கிறது**, அதனால Hindi அல்லது Tamil pages எந்த error-உம் இல்லாம குப்பையா வரும்.
- **Tables-ஐ running text-ஆ தட்டையாக்குறது.** ஒவ்வொரு row-வோடவும் headers-ஐ வச்சிருங்க.
- **எந்த pages OCR ஆச்சுன்னு record பண்ணாம இருக்கிறது**, அதனால பலவீனமான text-ஐ trace பண்ண முடியாது.

## Simple extraction போதும்னா

- **சுத்தமான digital PDFs**, single columns, குறைவான tables-ஓட.
- **Text sources**, HTML pages, Markdown அல்லது தெளிவான headings இருக்குற Word files மாதிரி.
- **Structured exports** (CSV, JSON, database dumps), இவைக்கு parsing-ஏ தேவையில்லை.

## Demo-ல இருந்து production-க்கு

- **Checks வச்சு pages-ஐ route பண்ணுங்க**: முதல்ல மலிவான extraction, பலவீனமான pages-க்கு மட்டும் OCR அல்லது layout tools.
- **ஒவ்வொரு page-க்கும் method, confidence, parser version-ஐ store பண்ணுங்க.**
- **வாரம் ஒரு தடவை parse ஆன pages-ஓட sample-ஐ originals-ஓட compare பண்ணுங்க**, குறிப்பா tables, scans.
- **Parser failures-ஐ பிடிக்க, ஒவ்வொரு document-க்கும் ஒரு page-க்கு characters, கண்டுபிடிச்ச tables-ஐ track பண்ணுங்க.**
