## இது என்ன

**Chat assistant** ஒரு website-ல இருக்குற chat window-லயோ messaging app-லயோ customers-ஓட கேள்விகளுக்கு பதில் சொல்லும். நல்லா build பண்ணா, அது:

- பொதுவான knowledge-ல இல்ல, business-ஓட சொந்த information-ல இருந்து (FAQs, price lists, policies, timings) பதில் சொல்லும்;
- business systems-ஓட connection மூலமா common tasks-ஐ (order status, appointment booking) handle பண்ணும்;
- உதவ முடியாதப்போ அல்லது customer கேக்கும்போது **person-கிட்ட hand over பண்ணும்**;
- privacy-யையும் messaging platform-ஓட rules-ஐயும் மதிக்கும்.

WhatsApp-ல businesses **WhatsApp Business Platform** (API)-ஐ use பண்ணுவாங்க, பெரும்பாலும் ஒரு provider மூலமா. இதுக்கு rules இருக்கு: customers opt in பண்ணியிருக்கணும், 24 மணி நேர customer-service window-க்கு வெளியே business ஆரம்பிக்குற messages-க்கு pre-approved templates வேணும், messages-க்கு WhatsApp-ஓட pricing model படி charge பண்ணுவாங்க.

```flow
WhatsApp-ல customer -> Provider webhook -> Assistant
Assistant -> Retrieval | FAQ sheet, price list
Assistant -> Tools | order status, booking, confirm பண்ணிட்டு
Assistant -> Person-கிட்ட hand-over | ஒரு summary-ஓட
Retrieval -> Customer-ஓட மொழில reply
Tools -> Customer-ஓட மொழில reply
```

இந்த lesson-ல Madurai-ல இருக்குற ஒரு multi-specialty clinic-ஐ follow பண்ணப் போறோம். அவங்க reception-ல WhatsApp messages குவிஞ்சு கிடக்கு.

## இது எப்படி work ஆகுது

**Knowledge.** Business-ஓட FAQs, price list, policies, timings-ஐ சேர்ங்க. Business-ஏ update பண்ணக்கூடிய ஒரு document அல்லது sheet-ல வச்சுக்கோங்க. இந்த sources-ல இருந்து பதில் வரணும்னு retrieval use பண்ணுங்க, தெரியலன்னா தெரியலன்னு assistant சொல்லணும்னு instruct பண்ணுங்க.

**Actions.** Order status, booking-க்கு tools-ஐ connect பண்ணுங்க: order number, phone வச்சு order-ஐ தேடுறது, slots check பண்றது, booking create பண்றது. Action எடுக்குறதுக்கு முன்னாடி details-ஐ customer-கிட்ட திருப்பி confirm பண்ணுங்க.

**Hand-over.** எந்த நேரத்துலயும் "talk to a person" option கொடுங்க. Complaints, payments disputes, medical அல்லது legal கேள்விகள், கோபமா இருக்குற customers, இல்லன்னா ரெண்டு தடவை பதில் சொல்லி fail ஆனா, automatic-ஆ hand over பண்ணுங்க. Conversation-ஐயும் ஒரு summary-யையும் அனுப்புங்க, அப்போ person மறுபடி கேக்க வேண்டியதில்ல; எப்போ reply வரும்னு customer-கிட்ட சொல்லுங்க.

**WhatsApp rules.**

- Business-ஓட messages வாங்குறதுக்கு customers opt in பண்ணியிருக்கணும்.
- Customer-ஓட கடைசி message-ல இருந்து 24 மணி நேரத்துக்குள்ள, business சுதந்திரமா reply பண்ணலாம். அதுக்கு அப்புறம் approved template messages மட்டும் தான் ஒரு conversation-ஐ ஆரம்பிக்கலாம்.
- எதை விக்கலாம், எதை promote பண்ணலாம்ங்கிறதுக்கு WhatsApp-ஓட commerce, business policies-ஐ follow பண்ணுங்க.

**மொழியும் tone-உம்.** முடிஞ்ச வரைக்கும் customer-ஓட மொழில பதில் சொல்லுங்க; உங்க customers use பண்ற Hindi, Tamil, Hinglish மாதிரி மொழிகளை test பண்ணுங்க. Messages சின்னதா இருக்கட்டும்; chat email இல்ல.

**Privacy.** Task-க்கு தேவையானதை மட்டும் collect பண்ணுங்க; full card numbers, passwords கேக்காதீங்க; DPDP consent and retention rules-ஐ follow பண்ணுங்க; logs-ல personal data-வை mask பண்ணுங்க.

**Measure.** Person இல்லாம resolve ஆன conversations-ஓட share, hand-over rate and reasons, customer ratings, தப்பான பதில் பத்தின reports.

**Assistant எதை handle பண்ணும், எதை ஒருபோதும் பண்ணாது:**

| Request வகை | Assistant-ஓட வேலை | உதாரணம் |
| --- | --- | --- |
| Information | Business-ஓட sources-ல இருந்து பதில் சொல்றது | Timings, fees, doctor schedules |
| Simple actions | Tool use பண்ணி, action எடுக்குறதுக்கு முன்னாடி confirm பண்றது | Appointment book பண்றது, order status check பண்றது |
| Sensitive அல்லது complex | Summary-ஓட hand over பண்றது | Complaints, refunds, disputes |
| Professional advice | ஒருபோதும் கொடுக்காது; hand over | Medical, legal, financial கேள்விகள் |
| Emergencies | Fixed safe message-ம் hand-over-உம் | "எங்க emergency number-க்கு call பண்ணுங்க..." |

**Message costs.** WhatsApp, message வகையையும் நாட்டையும் பொறுத்து அமையுற அதோட pricing model படி businesses-க்கு charge பண்ணுது. தற்போதைய pricing page-ஐ check பண்ணி, நீங்க check பண்ண தேதியோட, client-ஓட running-cost estimate-ல சேர்த்துடுங்க.

**Code-ல ஒரு WhatsApp Cloud API webhook.** Meta உங்க URL-ஐ verify பண்ண ஒரு தடவை call பண்ணும், அப்புறம் ஒவ்வொரு incoming message-ஐயும் post பண்ணும். ஒரு minimal FastAPI version; API version, fields-க்கு Meta-ஓட current docs-ஐ பாருங்க:

```python
import hashlib, hmac, os
import httpx
from fastapi import FastAPI, Request, Response, BackgroundTasks, HTTPException

app = FastAPI()
VERIFY_TOKEN = os.environ["WA_VERIFY_TOKEN"]
APP_SECRET = os.environ["WA_APP_SECRET"].encode()
TOKEN, PHONE_ID = os.environ["WA_TOKEN"], os.environ["WA_PHONE_NUMBER_ID"]
SEEN = set()                                     # use Redis or a table in production

@app.get("/whatsapp")
def verify(request: Request):
    q = request.query_params
    if q.get("hub.mode") == "subscribe" and q.get("hub.verify_token") == VERIFY_TOKEN:
        return Response(q.get("hub.challenge"))
    raise HTTPException(status_code=403)

@app.post("/whatsapp")
async def receive(request: Request, tasks: BackgroundTasks):
    raw = await request.body()
    sig = request.headers.get("X-Hub-Signature-256", "")
    expected = "sha256=" + hmac.new(APP_SECRET, raw, hashlib.sha256).hexdigest()
    if not hmac.compare_digest(sig, expected):
        raise HTTPException(status_code=401)
    for entry in (await request.json()).get("entry", []):
        for change in entry.get("changes", []):
            for msg in change["value"].get("messages", []):
                if msg["id"] in SEEN:
                    continue                     # a repeat delivery
                SEEN.add(msg["id"])
                if msg.get("type") == "text":
                    tasks.add_task(handle, msg["from"], msg["text"]["body"])
    return {"ok": True}                          # reply fast; work happens in the background

async def handle(wa_id, text):
    answer = assistant_reply(wa_id, text)        # retrieval, tools and hand-over rules
    async with httpx.AsyncClient() as http:
        await http.post(f"https://graph.facebook.com/v21.0/{PHONE_ID}/messages",
                        headers={"Authorization": f"Bearer {TOKEN}"},
                        json={"messaging_product": "whatsapp", "to": wa_id,
                              "type": "text", "text": {"body": answer[:4000]}})
```

Webhook-க்கு சில seconds-குள்ள பதில் சொல்லிடுங்க, model call-ஐ background-ல பண்ணுங்க. இல்லன்னா WhatsApp retry பண்ணும், duplicates வரும்.

**Hand-over rules prompt-ல மட்டும் இல்ல, code-லயும் இருக்கணும்.** Model-ஐ call பண்றதுக்கு முன்னாடியே, message-ஐயும் இதுவரை நடந்த conversation-ஐயும் வச்சு decide பண்ணுங்க:

```python
HANDOVER_WORDS = {"complaint", "refund", "lawyer", "consumer court", "chargeback"}

def needs_person(text, state):
    t = text.lower()
    return (any(w in t for w in HANDOVER_WORDS)
            or state["failed_answers"] >= 2
            or state.get("asked_for_person"))
```

இது true கொடுத்தா, அந்த chat-க்கு bot-ஐ நிறுத்திடுங்க, conversation-ஐயும் summary-யையும் staff inbox-ல post பண்ணுங்க, எப்போ reply வரும்னு customer-கிட்ட சொல்லுங்க.

**Code-ல 24-hour window.** ஒவ்வொரு customer-ஓட கடைசி message நேரத்தையும் store பண்ணுங்க. Send பண்றதுக்கு முன்னாடி அது 24 மணி நேரத்துக்குள்ளதான்னு check பண்ணுங்க; இல்லன்னா free text-க்கு பதிலா approved template அனுப்புங்க, இல்லன்னா அனுப்பவே வேண்டாம்.

**Grounded-ஆ இருக்கிறது.** Retrieval வச்சு business-ஓட சொந்த sheet அல்லது documents-ல இருந்து பதில் சொல்லுங்க, logs-ல source-ஐ சேர்த்துடுங்க, relevant-ஆ எதுவும் கிடைக்கலன்னா refuse பண்ணுங்க: "என்கிட்ட அந்த information இல்ல; team reply பண்ணணும்னு கேட்டிருக்கேன்." WhatsApp-ல போன தப்பான price அல்லது timing screenshot எடுத்து share ஆகும்.

## ஒரு worked example

Madurai-ல ஒரு multi-specialty clinic-க்கு ஒரு நாளைக்கு நூற்றுக்கணக்கான WhatsApp messages வருது: timings, doctor availability, fees, lab report status, appointment booking.

n8n-ல, ஒரு WhatsApp Business Platform provider வச்சு build பண்ண assistant:

- Reception staff தினமும் update பண்ற ஒரு sheet-ல இருந்து timings, fees, doctor schedules-க்கு பதில் சொல்லுது;
- clinic-ஓட booking system-ஐ check பண்ணி, book பண்றதுக்கு முன்னாடி name, doctor, date, time-ஐ confirm பண்ணி appointments-ஐ book பண்ணுது;
- lab reports ready-ஆன்னு patients-கிட்ட சொல்லுது (registered phone number-ஐ verify பண்ணப்புறம்), ஆனா results-ஐ chat-ல ஒருபோதும் share பண்றதில்ல;
- symptoms, medical கேள்விகள், emergencies-க்கு உடனே hand over பண்ணுது, emergency number கொடுக்குற ஒரு fixed message-ஓட;
- patient பேசுற மாதிரியே Tamil-லயோ English-லயோ reply பண்ணுது.

ஒரு மாசத்துக்கு அப்புறம், 68% conversations முழுசா handle ஆகுது, reception-ஓட phone calls மூணுல ஒரு பங்கு குறையுது, after-hours bookings கூடுது. ஒரு doctor-ஓட leave day பத்தின ரெண்டு தப்பான பதில்கள், schedule sheet update ஆகாததால வந்தது; clinic ஒரு daily check சேர்க்குது.

| ஒரு மாசத்துக்கு அப்புறம் measure | Result |
| --- | --- |
| Assistant முழுசா handle பண்ண conversations | 68% |
| Reception phone calls | சுமார் மூணுல ஒரு பங்கு குறைஞ்சது |
| After-hours bookings | கூடுச்சு |
| கண்டுபிடிச்ச தப்பான பதில்கள் | 2, ரெண்டுமே out-of-date schedule sheet-ல இருந்து |
| Fix | Schedule sheet update ஆச்சான்னு ஒரு daily check |

**Hand-over practice-ல எப்படி work ஆகுது.** ஒரு patient "my father has chest pain"ன்னு எழுதினா, assistant medical-ஆ உதவ try பண்ணாது. Ambulance, clinic emergency numbers இருக்குற fixed emergency message-ஐ அனுப்பும், staff inbox-ல அந்த conversation-ஐ urgent-ன்னு flag பண்ணும், அன்னைக்கு மீதி நாள் அந்த patient-க்கு automatic-ஆ reply பண்றதை நிறுத்தும், அதனால ஒரு person பொறுப்புல இருப்பாங்க. ஒரு patient தப்புன்னு நினைக்கிற bill பத்தி கேட்டா, assistant bill number-ஐ collect பண்ணி, ரெண்டு working hours-குள்ள ஒரு staff member reply பண்ணுவாங்கன்னு சொல்லி, bill-ஐ attach பண்ணி ஒரு one-line summary-ஐ அனுப்பும். இந்த மாற்றம் தான் தங்களுக்கு ரொம்ப பிடிச்சதுன்னு reception staff சொன்னாங்க: patient என்ன கேக்குறாருன்னு புரிஞ்சுக்க, நீளமான chat-ஐ திரும்ப scroll பண்ணி பார்க்க வேண்டியதில்ல.

## பொதுவா பண்ற தப்புகள்

- **General knowledge-ல இருந்து பதில் சொல்றது.** பதில்களை business-ஓட சொந்த information-ல grounding பண்ணுங்க.
- **Person-கிட்ட போக எளிதான வழி இல்லாதது.** Frustrate ஆன customers போயிடுவாங்க, public-ஆ complain பண்ணுவாங்க.
- **Platform rules-ஐ மீறுறது.** கேக்காத messages, approve ஆகாத templates numbers-ஐ block பண்ண வச்சிடும்.
- **Medical, legal, financial advice கொடுக்கிறது.** Hand over பண்ணுங்க.
- **Stale information.** Source-ஐ update பண்றதை யாரோட daily routine-லயாவது சேர்த்துடுங்க.

- **நீளமான, email மாதிரியான replies.** Chat users phone-ல படிக்கிறாங்க; பதில்களை சில வரிகளுக்குள்ள வச்சு, "more details?"ன்னு கேளுங்க.
- **Knowledge sheet-க்கு owner இல்லாதது.** Timings, prices, leave days-ஐ யார் எப்போ update பண்றாங்கன்னு ஒரு பெயரை வையுங்க.
- **Webhook-ல signature check-ஐ skip பண்றது.**
- **Webhook-க்கு reply பண்றதுக்கு முன்னாடி slow வேலை செய்யுறது.** இதனால retries-உம் duplicate பதில்களும் வரும்.
- **24-hour window-க்கு வெளியே free-text messages.** அவை fail ஆகும் அல்லது policy-ஐ மீறும்; approved templates use பண்ணுங்க.

## Chat assistant எப்போ worth இல்ல

- **ஒரு நாளைக்கு ரொம்ப கொஞ்சம் messages**: saved quick replies வச்சிருக்குற ஒரு person தான் மலிவு, warm-உம் கூட.
- **பெரும்பாலான கேள்விகளுக்கு judgement வேணும்**, உதாரணம்: custom quotes அல்லது complaints.
- **Business தன் information-ஐ up to date-ஆ வச்சுக்க முடியாது**: bot பழைய prices, timings-ஐயே சொல்லும்.
- **Customers பெரும்பாலும் call பண்றாங்க**, message பண்றதில்ல: ஒரு voice assistant அல்லது better IVR பொருத்தமா இருக்கலாம்.

## Practice பண்ணுங்க

WhatsApp Business Platform overview-வையும் n8n-ஓட AI docs-ஐயும் படிங்க.

1. உங்களுக்கு தெரிஞ்ச ஒரு small business-க்கு, 20 FAQs இருக்குற ஒரு sheet-ல இருந்து பதில் சொல்ற website அல்லது test chat assistant-ஐ build பண்ணுங்க; பதில் அதுல இல்லன்னா refuse பண்ணணும்.
2. ஒரு confirmation step-ஓட ஒரு action-ஐ (உதாரணம்: ஒரு sheet-ல booking) சேர்த்து, ஒரு hand-over path-ஐயும் சேர்ங்க.
3. ரெண்டு மொழிகள்ல 20 கேள்விகளோட test பண்ணுங்க; அதுல மூணு, hand over பண்ண வேண்டியவை.
4. ஒரே id-ஓட ஒரே message-ஐ உங்க webhook-க்கு ரெண்டு தடவை அனுப்பி, assistant ஒரு தடவை மட்டும் பதில் சொல்லுதுன்னு confirm பண்ணுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** சரியான grounded பதில்கள், action-க்கு முன்னாடி ஒரு confirmation, சுத்தமான hand-over மூணையும் உங்களால காட்ட முடியும்.
