## இது என்ன

**Triage**-னா வர்ற ஒவ்வொரு message-உம் என்னது, எவ்வளவு urgent, யார் handle பண்ணணும்னு முடிவு பண்றது. AI triage முதல் pass-ஐ automate பண்ணும்:

- **Classify**: இது என்ன வகை message (billing, delivery, technical issue, complaint, sales enquiry, spam)?
- **Extract**: team-க்கு தேவையான details (order number, account id, product, location).
- **Prioritise**: urgent-ஆ இல்லையா (service down, payment failed, legal threat, VIP customer).
- **Route**: சரியான tool-ல, சரியான team அல்லது ஆளுக்கு.
- **Draft**: ஒரு ஆள் check பண்ணி அனுப்ப ஒரு suggested reply.

```flow
வர்ற email அல்லது ticket -> AI step, structured output | category, priority, fields, summary, unsure?
AI step, structured output -> மேல rules | key account? legal words? data deletion?
மேல rules -[ஒரு rule match ஆகுது]-> Priority-ஐ force பண்ணு, ஒரு senior-க்கோ privacy contact-க்கோ route பண்ணு
மேல rules -> Unsure?
Unsure? -[yes]-> General queue | ஒரு ஆள் sort பண்றாங்க
Unsure? -[no]-> Help desk-ல route பண்ணு | team, priority, summary, draft reply
Help desk-ல route பண்ணு -> ஒரு agent draft-ஐ check பண்ணி, edit பண்ணி, அனுப்புறாங்க
```

இந்த lesson, தினமும் சுமார் 2,500 emails வர்ற support inbox இருக்குற Chennai-ஓட ஒரு broadband provider-ஐ follow பண்ணுது.

## இது எப்படி work ஆகுது

**Team-ஓட சேர்ந்து categories-ஐ define பண்ணுங்க.** உங்க support அல்லது operations team ஏற்கனவே வேலை செய்யுற categories-ஐ use பண்ணுங்க; ஒவ்வொண்ணுக்கும் ஒரு வரி definition, ரெண்டு மூணு example messages. "Other / unclear"-ஐயும் சேருங்க.

**Structured output வச்சு classify பண்ணுங்க.** AI step category, priority, extract பண்ண fields, ஒரு வரி summary, ஒரு confidence அல்லது "unsure" flag எல்லாத்தையும் ஒரு fixed shape-ல திருப்பி தரும்.

**AI-ஐ சுத்தி rules.** சில முடிவுகள் AI judgement-ஆ இல்லாம rules-ஆ இருக்கணும்: key accounts list-ல இருந்து வர்ற messages எப்பவும் high priority; legal action, police, consumer court பத்தி குறிப்பிடுற எந்த message-உம் ஒரு senior ஆளுக்கு போகும்; data deletion பத்தின எதுவும் privacy contact-க்கு போகும்.

**Route.** Help desk-ல ticket-ஐ create அல்லது update பண்ணி, team-ஐ assign பண்ணி, priority வச்சு, extract பண்ண fields, summary-ஐ சேருங்க. Unsure cases ஒரு ஆள் sort பண்ண ஒரு general queue-க்கு போகும்.

**Replies-ஐ draft பண்ணுங்க, அனுப்பாதீங்க (முதல்ல).** Customer-ஓட message, extract பண்ண details, உங்க knowledge base-ஐ வச்சு ஒரு reply draft-ஐ generate பண்ணி, ஒரு agent edit பண்ணி அனுப்ப ticket-ல வைங்க. வாரக்கணக்கா quality-ஐ அளந்த பிறகு தான், "உங்க request கிடைச்சுது" மாதிரி simple, low-risk replies-ஐ தானா அனுப்பலாம்.

**மொழிகள்.** இந்திய customers English, Hindi, Tamil, Hinglish இன்னும் பலதுல எழுதுவாங்க. உங்களுக்கு வர்ற ஒவ்வொரு மொழியிலயும் real messages-ல triage-ஐ test பண்ணுங்க.

**அளவிடுங்க.** வாராந்திர sample-ல classification accuracy, முதல் தடவையே சரியா route ஆன பங்கு, முதல் response-க்கான நேரம், agents drafts-ஐ எவ்வளவு edit பண்றாங்க.

**AI-க்கும் team-க்கும் ரெண்டு பேருக்கும் புரியுற ஒரு category definition:**

| Category | Definition | Example messages |
| --- | --- | --- |
| Outage | Internet முழுசா இல்லை, ஒரு area-வையே பாதிக்கலாம் | "Net not working since morning", "Wi-Fi light red" |
| Slow speed | Connect ஆகியிருக்கு, ஆனா plan-ஐ விட slow | "Getting 5 Mbps on a 100 Mbps plan" |
| Billing | Charges, payments, refunds | "Charged twice this month" |
| Relocation | Connection-ஐ புது address-க்கு மாத்துறது | "Shifting to Velachery next week" |
| Other or unclear | வேற எதுவும், அல்லது உறுதி இல்லை | "Hi", forward ஆன newsletters |

இந்த definitions நேரா prompt-க்குள்ள போகும். Team ஒரு category-ஐ மாத்தினா, ஒரே இடத்துல definition-ஐ மாத்துவாங்க, test set-க்கு அதுக்கான புது examples சேரும்.

**ஏன் drafts-ல ஆரம்பிக்கிறோம்.** 92% classification accuracy-ல கூட, கோவமா இருக்குற customer-க்கு ஒரு தப்பான automatic reply போனா நிஜமா சேதம் வரும். Drafts-ல agents அந்த 8%-ஐ சரி பண்ணுவாங்க, 92%-ல நேரத்தை மிச்சப்படுத்துவாங்க. ஒவ்வொரு draft-ஐயும் agents எவ்வளவு edit பண்றாங்கன்னு அளங்க: ஒரு category-க்கு பல வாரங்கள் பெரும்பாலான drafts மாறாம போனா, அந்த category தானா அனுப்புறதுக்கு candidate; simple acknowledgements-ல இருந்து ஆரம்பிங்க.

**Code-ல, முதல்ல rules, அப்புறம் model.** Fixed rules எந்த model call-க்கும் முன்னாடி run ஆகும், அதனால அவற்றை பேசி மாத்த முடியாது:

```python
from typing import Literal
from pydantic import BaseModel

Category = Literal["outage", "slow_speed", "billing", "relocation", "other"]

class Triage(BaseModel):
    category: Category
    priority: Literal["p1", "p2", "p3"]
    account_id: str | None = None
    summary: str
    unsure: bool

KEY_ACCOUNTS = {"ACC-1001", "ACC-2040"}
LEGAL_WORDS = ("legal notice", "consumer court", "police complaint", "lawyer")

def triage(message, sender_account, classify):
    text = message.lower()
    if any(w in text for w in LEGAL_WORDS):
        return {"queue": "senior", "priority": "p1", "reason": "legal words"}
    if "delete my data" in text or "erase my data" in text:
        return {"queue": "privacy", "priority": "p2", "reason": "data request"}
    t: Triage = classify(message)                 # structured output from the model
    if t.unsure or t.category == "other":
        return {"queue": "general", "priority": t.priority, "reason": "unsure"}
    priority = "p1" if sender_account in KEY_ACCOUNTS else t.priority
    return {"queue": t.category, "priority": priority, "summary": t.summary, "account": t.account_id}
```

**எங்க தப்பா போகுதுன்னு அளங்க.** Overall accuracy எந்த categories குழம்புதுன்னு மறைச்சிடும். உங்க labelled set-ல இருந்து ஒரு confusion table build பண்ணுங்க:

```python
from collections import Counter

def confusion(pairs):
    """pairs: list of (true_category, predicted_category)."""
    counts = Counter(pairs)
    cats = sorted({c for p in pairs for c in p})
    print("true \\ predicted".ljust(14) + "".join(c[:9].ljust(10) for c in cats))
    for t in cats:
        print(t[:13].ljust(14) + "".join(str(counts[(t, p)]).ljust(10) for p in cats))
    acc = sum(counts[(c, c)] for c in cats) / len(pairs)
    print(f"accuracy {acc:.0%}")
```

"slow_speed" அடிக்கடி "outage"-ஆ predict ஆனா, ரெண்டு definitions-ஐயும் இறுக்குங்க, எல்லைக்கு பக்கத்துல இருக்குற ஒவ்வொண்ணுக்கும் examples சேருங்க. மொழி வாரியாவும் accuracy-ஐ report பண்ணுங்க: examples சேர்க்குற வரை Hinglish messages பொதுவா English-ஐ விட மோசமா வரும்.

**தப்புகளுக்கு வேற வேற செலவு.** ஒரு outage-ஐ billing-க்கு அனுப்புனா, ஒரு area முழுசுக்கும் fix தாமதமாகும்; billing-ஐ general-க்கு அனுப்புனா சில நிமிஷம் தான் செலவு. எந்த confusions அதிக முக்கியம்னு team-ஓட முடிவு பண்ணுங்க; average-ஐ இல்லாம, table-ல அந்த cells-ஐ கவனிங்க.

**Inbox எப்படி மாறுதுன்னு கவனிங்க.** ஒவ்வொரு category-ஓட பங்கையும், "other"-ஓட பங்கையும் வாரா வாரம் track பண்ணுங்க. ஒரு புது plan launch, ஒரு festival sale, ஒரு outage எல்லாம் mix-ஐ மாத்தும். "Other" ஏறிட்டே போனா, பெரும்பாலும் ஒரு புது category தேவைன்னு அர்த்தம்.

## பொதுவா பண்ற தப்புகள்

- **Team use பண்ணாத categories-ஐ கண்டுபிடிக்கிறது.** அவங்களோடதையே use பண்ணுங்க.
- **Legal அல்லது safety escalations-ஐ AI மட்டுமே முடிவு பண்ண விடுறது.** இதுக்கு rules use பண்ணுங்க.
- **ரொம்ப சீக்கிரமே replies-ஐ தானா அனுப்புறது.** Drafts-ல ஆரம்பிச்சு அளங்க.
- **English-ல மட்டும் test பண்றது.** Customers உண்மையில எழுதுற மொழிகள்ல test பண்ணுங்க.
- **"Unsure" path இல்லாதது.** ஒவ்வொரு message-க்கும் ஒரு category-ஐ திணிச்சா errors மறைஞ்சிடும்.
- **Overall accuracy மட்டும் பார்க்கிறது.** எந்த categories குழம்புதுன்னும், மொழி வாரியாவும் பாருங்க.
- **Legal, privacy routing-ஐ model-க்கு விட்டுடுறது.** Model run ஆகுறதுக்கு முன்னாடி fixed rules use பண்ணுங்க.

## AI triage எப்போ தேவையில்லை

- **Volume கம்மி**: ஒரு ஆள் ஒவ்வொரு message-ஐயும் படிக்கிறது வேகமாவும் accurate-ஆவும் இருக்கும்.
- **Help desk-ஓட சொந்த rules ஏற்கனவே வேலை செய்யுது**, customer நிரப்புற form fields வச்சு route பண்றது மாதிரி.
- **Categories வாரா வாரம் மாறுது**, அதனால கத்துக்க நிலையா எதுவும் இல்லை.

## Practice பண்ணுங்க

n8n-ஓட AI docs-ஐயும் ஒரு prompting best-practices guide-ஐயும் படிங்க.

1. ஒரு support inbox-க்கு குறைஞ்சது ரெண்டு மொழிகள்ல 50 real அல்லது realistic messages-ஐ collect பண்ணி, அஞ்சு categories-ஓடயும் ஒரு priority-ஓடயும் label பண்ணுங்க.
