## இது என்ன

**Unsupervised learning** labels இல்லாத data-ல patterns-ஐ கண்டுபிடிக்கும். மூணு பொதுவான tasks:

- **Clustering**: ஒரே மாதிரி records-ஐ group பண்றது; உதாரணம், customer segments அல்லது ஒரே மாதிரி stores.
- **Dimensionality reduction**: நிறைய features-ஐ, பெரும்பாலான information-ஐ வச்சுக்கிட்டு கொஞ்ச features-ஆ compress பண்றது; visualisation, வேகம் அல்லது எளிமையான models-க்காக. **PCA** classic method.
- **Anomaly detection**: மத்தவங்க மாதிரி இல்லாத records-ஐ கண்டுபிடிக்கிறது; உதாரணம், வித்தியாசமான transactions அல்லது பழுதான sensors.

Check பண்ணிக்க "சரியான பதில்" எதுவும் இல்லாததால, பயனுள்ளதான்னு judge பண்றதும் வேலையோட ஒரு பகுதி.

## இது எப்படி work ஆகுது

**Features-ஐ தயார் பண்ணுங்க.** Unsupervised methods நீங்க எந்த features use பண்றீங்க, அவை எப்படி scale ஆகியிருக்குன்னதை ரொம்ப சார்ந்திருக்கு. Numeric features-ஐ standardise பண்ணுங்க; business-க்கு "ஒரே மாதிரி"ன்னா என்ன அர்த்தம்னு கவனமா யோசிங்க.

**k-means clustering.** k-ஐ, அதாவது clusters எண்ணிக்கையை தேர்ந்தெடுங்க. Algorithm k centres-ஐ வச்சு, ஒவ்வொரு record-ஐயும் பக்கத்துல இருக்குற centre-க்கு assign பண்ணி, centres-ஐ அவற்றோட records-ஓட நடுவுக்கு நகர்த்தி, திரும்ப திரும்ப பண்ணும். கிட்டத்தட்ட round-ஆன, ஒரே அளவு groups-க்கு இது நல்லா work ஆகும். k-ஐ elbow method அல்லது silhouette scores வச்சு தேர்ந்தெடுங்க, ஆனா முக்கியமா clusters business-க்கு அர்த்தமாகுதான்னு பார்த்து.

**மத்த clustering methods.** DBSCAN எந்த shape-ல இருக்குற clusters-ஐயும் கண்டுபிடிச்சு, sparse points-ஐ noise-ஆ label பண்ணும்; hierarchical clustering groupings-ஓட ஒரு tree-ஐ build பண்ணும்; Gaussian mixtures soft memberships கொடுக்கும்.

**PCA.** அதிக variation-ஐ பிடிக்குற புது axes-ஐ (original features-ஓட combinations) கண்டுபிடிக்கும். முதல் ரெண்டு components-ஐ plot பண்ணா, groups அல்லது outliers பெரும்பாலும் தெரியும். 90% variance-ஐ விளக்குற components-ஐ வச்சுக்கிட்டா, 50 features-ஐ 10-ஆ சுருக்கலாம்.

**Anomaly detection.** Isolation Forest மாதிரி methods, ஒரு record-ஐ மத்தவங்கள்ல இருந்து எவ்வளவு எளிதா பிரிக்க முடியும்னு score பண்ணும். Scores-ஐ review-க்கு priority வைக்க use பண்ணுங்க, final verdict-ஆ இல்ல.

**Results-ஐ judge பண்றது.** ஒவ்வொரு cluster-ஐயும் அதோட features-ஓட averages, real examples வச்சு describe பண்ணுங்க; business user-க்கு புரியுற ஒரு பேர் கொடுங்க; stability-ஐ check பண்ணுங்க (வேற sample-ல rerun பண்ணா clusters அதே மாதிரி இருக்கா?); பயன்பாட்டை test பண்ணுங்க (segment வச்சு target பண்ணா campaign improve ஆகுதா?).

**Method-ஐ தேர்ந்தெடுக்கிறது:**

| Task | Method | எதுக்கு நல்லது |
| --- | --- | --- |
| ஒரே அளவு, ஒரே shape இருக்குற segments | k-means | Customer, store segments |
| ஒழுங்கில்லாத shapes, noise | DBSCAN | Location data, அடர்த்தியான இடங்களை கண்டுபிடிக்க |
| Groupings-ஓட ஒரு tree | Hierarchical clustering | சின்ன datasets, structure-ஐ explore பண்ண |
| Soft membership | Gaussian mixtures | பாதி ஒரு segment-க்கும் பாதி இன்னொண்ணுக்கும் சேர்ந்த customers |
| Compress பண்ணி visualise பண்ண | PCA | நிறைய features, quick plots |
| வித்தியாசமான records-ஐ கண்டுபிடிக்க | Isolation Forest | Transactions, sensors, data quality |

**கஷ்டமான பகுதி அர்த்தம் தான்.** Algorithms random data-ல கூட clusters-ஐ கொடுக்கும். உண்மையான வேலை, ஒவ்வொண்ணையும் averages, real examples வச்சு describe பண்றது, business team-ஓட சேர்ந்து பேர் வைக்கிறது, ஒரு test வச்சு பயனுள்ளதுன்னு நிரூபிக்கிறது. யாராலயும் describe பண்ணவோ செயல்படவோ முடியாத cluster ஒரு segment இல்ல.

**Elbow மட்டும் இல்லாம, evidence வச்சு k-ஐ தேர்ந்தெடுக்கிறது.**

```python
import numpy as np
from sklearn.datasets import make_blobs
from sklearn.preprocessing import StandardScaler
from sklearn.cluster import KMeans
from sklearn.metrics import silhouette_score, adjusted_rand_score

X, _ = make_blobs(n_samples=3000, centers=4, n_features=6, cluster_std=1.6, random_state=8)
Xs = StandardScaler().fit_transform(X)

for k in range(2, 8):
    labels = KMeans(n_clusters=k, n_init=10, random_state=8).fit_predict(Xs)
    print(k, "silhouette", round(silhouette_score(Xs, labels, sample_size=2000, random_state=8), 3))
```

**Segments-க்கு பேர் வைக்கிறதுக்கு முன்னாடி stability-ஐ check பண்ணுங்க.**

```python
def stability(Xs, k, runs=5, frac=0.8, seed=0):
    rng = np.random.default_rng(seed)
    ref = KMeans(n_clusters=k, n_init=10, random_state=0).fit(Xs)
    scores = []
    for r in range(runs):
        idx = rng.choice(len(Xs), int(frac * len(Xs)), replace=False)
        other = KMeans(n_clusters=k, n_init=10, random_state=r + 1).fit(Xs[idx])
        scores.append(adjusted_rand_score(ref.predict(Xs[idx]), other.labels_))
    return round(float(np.mean(scores)), 3)

print("stability at k=4:", stability(Xs, 4), " at k=7:", stability(Xs, 7))
```

Adjusted Rand index 1-க்கு பக்கத்துல இருந்தா, அதே records தொடர்ந்து ஒண்ணா விழுது; ரொம்ப குறைவா இருந்தா, segments ஒரு run-ஓட artefacts தான்.

**Clusters-ஐ business வார்த்தைகள்ல describe பண்ணுங்க.** Cluster labels-ஐ original, scale பண்ணாத columns-ஓட திரும்ப join பண்ணி summarise பண்ணுங்க:

```python
import pandas as pd

def describe(df, labels):
    d = df.assign(cluster=labels)
    summary = d.groupby("cluster").agg(["mean", "median"]).round(1)
    summary["size"] = d.cluster.value_counts().sort_index()
    return summary
```

அப்புறம் "weekend family shoppers" மாதிரி ஒரு பேர் கொடுக்குறதுக்கு முன்னாடி, ஒவ்வொரு cluster-ல இருந்தும் பத்து real records-ஐ படிங்க.

**Review queue-க்கான anomaly scores.**

```python
from sklearn.ensemble import IsolationForest

iso = IsolationForest(n_estimators=300, contamination="auto", random_state=8).fit(Xs)
scores = -iso.score_samples(Xs)                  # higher = more unusual
queue = np.argsort(-scores)[:20]
print("top anomaly scores:", scores[queue][:5].round(3))
```

Top cases-ஐ, அவை தனியா தெரியுறதுக்கு காரணமான features-ஓட (உதாரணமா, ஒவ்வொரு value-உம் median-ல இருந்து எத்தனை standard deviations தள்ளி இருக்கு) ஒரு நபருக்கு அனுப்புங்க, அவங்க என்ன முடிவு பண்றாங்கன்னு record பண்ணுங்க. அந்த decisions தான் பின்னாடி ஒரு supervised model-க்கு labels ஆகும்.

**முதல் பார்வைக்கு PCA.** `PCA(n_components=2).fit_transform(Xs)` plot பண்ண coordinates கொடுக்கும்; `explained_variance_ratio_` அந்த ரெண்டு axes எவ்வளவு variation-ஐ பிடிச்சுதுன்னு சொல்லும். அது சின்னதா இருந்தா, picture உண்மையான structure-ஐ மறைக்கலாம்.

## ஒரு worked example

Kochi-ல ஒரு supermarket chain, 4,00,000 loyalty-card customers-ஓட marketing-க்கு segments வேணும்னு நினைக்குது.

12 மாசத்துக்கு ஒவ்வொரு customer-க்கும் features: மாசத்துக்கு visits, rupees-ல average basket, fresh produce, packaged foods, household items-ல செலவோட பங்கு, weekend visits-ஓட பங்கு, promotion-ல வாங்கினதோட பங்கு. எல்லாமே standardise பண்ணது.

k 3-ல இருந்து 10 வரை k-means; silhouette scores 6, 7 சுத்தி உச்சத்துக்கு போகுது. ஏழு clusters, marketing team-ஓட சேர்ந்து ஆறா merge பண்ணி பேர் வச்சாங்க:

1. Weekly family stock-up (பெரிய baskets, weekends)
2. Daily fresh shoppers (அடிக்கடி, சின்னது, produce அதிகம்)
3. Deal hunters (promotion பங்கு அதிகம்)
4. Occasional top-up (அரிதா, சின்ன baskets)
5. Premium packaged (பெரிய basket, imported brands)
6. Lapsing (சமீப மாசங்கள்ல visits கடுமையா குறையுது)

மூணு மாச test-ல ஒவ்வொரு segment-லயும் பாதி பேருக்கு segment-specific offers அனுப்புறாங்க. மொத்த response 3.1%-ல இருந்து 4.6%-க்கு ஏறுது; "lapsing" segment-ஓட offers அந்த customers-ல 12% பேரை திரும்ப கொண்டு வருது. Segment label churn model-க்கும் ஒரு பயனுள்ள feature ஆகுது.

| அளவீடு | Segments-க்கு முன்னாடி | Segment-specific offers-ஓட |
| --- | --- | --- |
| Offer response rate | 3.1% | 4.6% |
| திரும்ப வந்த lapsing customers | அளக்கப்படல | 12% |
| கூடுதல் use | இல்ல | Churn model-ல segment label ஒரு feature-ஆ சேர்ந்துச்சு |

**Marketing-ஓட சேர்ந்து clusters-க்கு பேர் வைக்கிறது.** k = 7-ஓட முதல் output, data team-க்கு வெளியே யாராலயும் படிக்க முடியாத ஏழு columns averages தான். ஒரு மணி நேர workshop-ல, team ஒவ்வொரு cluster-ஓட averages-ஐ, அதுல இருக்குற அஞ்சு real, anonymised customers-ஓட சேர்த்து marketing-கு காட்டுச்சு. Marketing தங்க வார்த்தைகள்ல segments-க்கு பேர் வச்சாங்க, முக்கியமான இடங்கள்ல மறுத்தும் சொன்னாங்க. Weekend visits-ல ஒரு சின்ன வித்தியாசத்தால algorithm பிரிச்ச ரெண்டு clusters-ஐ merge பண்ணாங்க, ஏன்னா ரெண்டு groups-ஐயும் அவங்க ஒரே மாதிரி தான் treat பண்ணுவாங்க. அந்த பேச்சுக்கு அப்புறம் தான் ஆறு clusters final segments ஆச்சு. Team ஒரு புது மூணு மாச sample-ல clustering-ஐ திரும்ப run பண்ணுச்சு. ஆறுல அஞ்சு segments ஒரே மாதிரி அளவுகள்ல திரும்ப வந்துச்சு. ஆறாவது, சின்னது, இன்னும் சின்னதா வந்துச்சு; அதனால team ஒவ்வொரு quarter-உம் அதை மறுபடி check பண்றாங்க.

## பொதுவா பண்ற தப்புகள்

- **Scale பண்ணாத features.** பெரிய values இருக்குற features distances-ஐ ஆக்கிரமிக்கும்.
- **k-ஐ ஒரு score வச்சு மட்டும் தேர்ந்தெடுக்கிறது.** Business meaning முக்கியம்.
- **Clusters-ஐ உண்மைன்னு நினைக்கிறது.** அவை ஒரு பயனுள்ள பார்வை, customers பத்தின fact இல்ல.
- **Stability-ஐ check பண்ணாம இருக்குறது.** Unstable clusters ஒவ்வொரு rerun-லயும் மாறும்.
- **Anomaly scores-ஐ verdicts-ஆ எடுத்துக்கிறது.** Human review-க்கு priority வைக்க use பண்ணுங்க.

- **செயல்படுத்த முடியாத features-ஐ வச்சு clustering பண்றது.** Targeting-க்கு business-ஆல use பண்ண முடியாத data-வால define ஆன segments-ஆல பெரும்பாலும் எதுவும் மாறாது.
- **Stability, business meaning இல்லாம, elbow-ஐ மட்டும் வச்சு k-ஐ தேர்ந்தெடுக்கிறது.**
- **Real records-ஐ படிக்காம, averages-ஐ மட்டும் வச்சு clusters-க்கு பேர் வைக்கிறது.**
- **Anomaly scores-ஐ review order-ஆ இல்லாம, verdicts-ஆ எடுத்துக்கிறது.**

## Unsupervised methods-ஐ use பண்ணக்கூடாத நேரங்கள்

- **உங்களுக்கு முக்கியமான விஷயத்துக்கு labels இருக்கு**: supervised models கேள்விக்கு நேரா பதில் சொல்லும்.

- **அர்த்தமுள்ள groups உருவாக்க records அல்லது features ரொம்ப குறைவு.**
