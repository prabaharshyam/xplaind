## இது என்ன

உங்க வேலை வாரத்துல மிகவும் போரடிக்கிற பகுதியை நினைச்சு பாருங்க: email-ல இருந்து details-ஐ spreadsheet-ல copy பண்றது, அதே reply-ஐ இருபது தடவை அனுப்புறது, messages-ஐ சரியான ஆளுக்கு forward பண்றது. **Workflow automation**-னா, நீங்க ஏற்கனவே use பண்ற apps முழுசும், இப்படி திரும்ப திரும்ப வர்ற steps-ஐ உங்களுக்காக software பண்றது.

ஒவ்வொரு automation-லயும் மூணு பகுதிகள் இருக்கு:

```flow
dir: LR
title: ஒவ்வொரு arrow வழியாவும் data போகுது
Trigger: புது email வருது -> Step: படிச்சு fields-ஐ எடு -> Step: sheet-ல ஒரு row சேர் -> Result: team-க்கு message அனுப்பு
```

- ஒரு **trigger**: இதை start பண்றது எது. புது email, submit ஆன form, sheet-ல புது row, நாளோட ஒரு நேரம், இல்லன்னா வேற app-ல இருந்து **webhook** வழியா வர்ற message. Webhook-னா ஏதாவது நடக்குற அதே நொடியில, ஒரு app இன்னொண்ணுக்கு data அனுப்ப call பண்ற web address.
- **Steps**: இவற்றை **nodes**, actions, modules-னும் சொல்வாங்க. அடுத்து என்ன நடக்கணும்ங்குறது: email-ஐ படிக்கிறது, invoice number-ஐ எடுக்குறது, customer-ஐ look up பண்றது, row சேர்க்குறது, message அனுப்புறது.
- **போற data**: ஒவ்வொரு step-ஓட output-உம் அடுத்த step-ஓட input ஆகுது.

**n8n**, **Zapier**, **Make**, **Microsoft Power Automate** மாதிரி tools-ல boxes-ஐ connect பண்ணி, code கம்மியா அல்லது இல்லாம, visual-ஆ இதை build பண்ணலாம்.

**AI steps** புதுசா ஒண்ணை சேர்க்குது: குழப்பமான text-ல judgement மாதிரி திறமை. ஒரு AI step structure இல்லாத email-ஐ படிச்சு fields-ஐ எடுக்கும், request-ஐ classify பண்ணும், document-ஐ summarise பண்ணும், reply-ஐ draft பண்ணும். இதனால automation, ஒழுங்கான, rules இருக்குற வேலையில இருந்து, பெரும்பாலான offices-ல நிறைஞ்சிருக்குற குழப்பமான, text அதிகமான வேலைக்கும் நீளுது.

இந்த lesson-ல Kochi-ல ஒரு travel agency தன்னோட booking enquiries-ஐ எப்படி automate பண்றாங்கன்னு பார்க்கப் போறோம். முடிக்கும் போது, எந்த automation-ஐயும் trigger, steps, checks-ன்னு விவரிக்கவும், நல்ல முதல் candidates-ஐ தேர்ந்தெடுக்கவும் முடியும்.

## இது எப்படி work ஆகுது

### Rule-based automation

Classic வகை: ஒவ்வொரு input-உம் எதிர்பார்க்கக்கூடியது, ஒவ்வொரு step-உம் ஒரு fixed rule.

> "Form submit ஆனா, sheet-ல ஒரு row சேர்த்து team-க்கு email அனுப்பு."

Rule-based automations நம்பகமானவை, run பண்ண செலவு கம்மி, test பண்றதும் ஈஸி. அதோட weakness: input குழப்பமா வந்தா உடைஞ்சிடும். வேற மாதிரி எழுதின email, இல்லாத field, ஒரு typo மாதிரி.

### AI-assisted automation

இங்க variety-ஐ AI step handle பண்ணுது, risk-ஐ rules-உம் மனுஷங்களும் handle பண்றாங்க:

```flow
accounts@-க்கு வந்த email -> AI step: இது என்ன?
AI step: இது என்ன? -[spam]-> Archive பண்ணு
AI step: இது என்ன? -[payment query]-> Accounts team-க்கு forward பண்ணு
AI step: இது என்ன? -[invoice]-> AI step: vendor, amount, GSTIN, due date-ஐ எடு
AI step: vendor, amount, GSTIN, due date-ஐ எடு -> எல்லா fields-உம் கிடைச்சதா, Rs 1 lakh-க்கு கீழயா?
எல்லா fields-உம் கிடைச்சதா, Rs 1 lakh-க்கு கீழயா? -[ஆமா]-> Sheet-ல ஒரு row சேர்
எல்லா fields-உம் கிடைச்சதா, Rs 1 lakh-க்கு கீழயா? -[இல்லை]-> ஒரு ஆளை check பண்ணச் சொல்லு
```

| | Rule-based steps | AI steps |
| --- | --- | --- |
| எதுல நல்லது | Fixed, எதிர்பார்க்கக்கூடிய input | குழப்பமான, பலவிதமான text |
| உதாரணம் | "Amount ₹50,000-க்கு மேல இருந்தா approval கேளு" | "இந்த email-ஐ படிச்சு invoice amount-ஐ கண்டுபிடி" |
| ஒரு run-க்கு செலவு | கிட்டத்தட்ட எதுவும் இல்லை | ஒரு சின்ன model charge |
| தப்பா போக வாய்ப்பு இருக்கா? | Rule தப்பா இருந்தா மட்டும் | ஆமா, சில நேரம்; checks சேருங்க |
| எதுக்கு best | Routing, calculations, data-வை நகர்த்துறது | படிக்கிறது, classify பண்றது, summarise பண்றது, draft பண்றது |

நல்ல automations ரெண்டையும் சேர்க்கும்: AI படிக்கும், rules முடிவு பண்ணும், ஆபத்தான பகுதிகளை மனுஷங்க check பண்ணுவாங்க.

### எதை automate பண்றது worth

இப்படி இருக்குற வேலையை தேடுங்க:

1. **அடிக்கடி வர்றது**: தினமும் அல்லது வாரத்துக்கு, வருஷத்துக்கு ரெண்டு தடவை இல்லை.
2. **திரும்ப திரும்ப ஒரே மாதிரி**: ஒவ்வொரு தடவையும் அதே steps.
3. **Rules இருக்கு அல்லது check பண்றது ஈஸி**: ஒரு ஆளால result-ஐ சீக்கிரம் confirm பண்ண முடியும்.
4. **Digital**: data ஏற்கனவே apps, emails, files-ல இருக்கு.
5. **கஷ்டமா இருக்கு**: மெதுவா, தப்பு வர வாய்ப்பு, இல்லன்னா போரடிக்குது.

அரிதா வர்ற, அதிக judgement வேண்டிய, அல்லது ரொம்ப sensitive-ஆன tasks பொதுவா முதல் candidates-ஆ சரியில்லை.

### Automation-க்கு என்ன வேணும்

- **Apps-க்கான access**, பொதுவா ஒவ்வொரு app-ஓட API-ஐ use பண்ற ready-made connectors வழியா.
- தேவையான இடத்துல படிக்கவும் எழுதவும் **permissions**, அதுக்கு மேல இல்லை.
- Steps-ஓட **தெளிவான definition**; அதனாலதான் process-ஐ முதல்ல map பண்றோம்.
- உடைஞ்சா கவனிச்சு சரி பண்ற **ஒரு owner**.

## ஒரு நாள், ஒரு example

Kochi-ல ஒரு சின்ன travel agency-க்கு email-ஆலயும் website form-ஆலயும் தினமும் சுமார் 40 booking enquiries வருது. இப்போ staff ஒவ்வொண்ணையும் spreadsheet-ல copy பண்ணி, ஒரு standard message-ஓட reply பண்ணி, சரியான agent-க்கு, அதாவது domestic, international அல்லது pilgrimage tours-க்கு, forward பண்றாங்க. Busy நாட்கள்ல enquiries மணிக்கணக்கா reply இல்லாம கிடக்குது, சில inbox-ல தொலைஞ்சும் போகுது.

அவங்க n8n-ல இந்த automation-ஐ build பண்றாங்க:

| # | Step | வகை |
| --- | --- | --- |
| 1 | Email அல்லது website form வழியா ஒரு புது enquiry வருது | Trigger |
| 2 | Enquiry-ஐ படிச்சு பேரு, phone, destination, dates, travellers எண்ணிக்கை, budget-ஐ எடு; domestic, international அல்லது pilgrimage-ன்னு classify பண்ணு | AI step |
| 3 | Bookings sheet-ல ஒரு row சேர் | Rule |
| 4 | எதிர்பார்க்கலாம்ங்குற response time-ஓட, customer-க்கு ஒரு மரியாதையான acknowledgement அனுப்பு | Rule, fixed template-ஓட |
| 5 | Details-ஓட, சரியான agent-க்கு team chat-ல notify பண்ணு | Rule, step 2-ல வந்த class-ஐ வச்சு |
| 6 | AI-ஆல phone number அல்லது travel dates கிடைக்கலன்னா, enquiry-ஐ front desk-க்கு அனுப்பி கையால handle பண்ண வை | Check |

**ஒரு மாசம் கழிச்சு results:**

| Measure | முன்னாடி | அப்புறம் |
| --- | --- | --- |
| Enquiries-க்கு staff நேரம் | தினமும் சுமார் 2.5 மணி நேரம் | தினமும் சுமார் 30 நிமிஷம், பெரும்பாலும் flag ஆனவை |
| முதல் reply-க்கு ஆகுற நேரம் | 2 முதல் 6 மணி நேரம் | 5 நிமிஷத்துக்கு கீழ |
| தொலைஞ்ச enquiries | வாரத்துக்கு சில | ஒண்ணும் கண்டுபிடிக்கல |
| தப்பா classify ஆன enquiries | Track பண்ணல | சுமார் 30-ல ஒண்ணு, agents பிடிச்சாங்க |

Automation-ஓட owner front-desk lead. Website form-ல ஒரு புது "special requests" field சேர்த்தப்போ, extraction step ஒரு நாள் dates-ஐ miss பண்ண ஆரம்பிச்சுது. Flag ஆன enquiries அதிகமானதை அவங்க கவனிச்சு, அந்த step-ஐ சரி பண்ணாங்க.

## பொதுவா பண்ற தப்புகள்

- **உடைஞ்ச process-ஐ automate பண்றது.** முதல்ல process-ஐ சரி பண்ணி எளிமையாக்குங்க, அப்புறம் automate பண்ணுங்க.
- **ரொம்ப கஷ்டமான, அரிதான task-ல இருந்து ஆரம்பிக்கிறது.** அடிக்கடி வர்ற, எளிமையான, check பண்ணக்கூடிய வேலையில ஆரம்பிங்க.
- **Owner இல்லாம இருக்கிறது.** ஒவ்வொரு automation-உம் எப்பவாவது உடையும்; யாராவது கவனிச்சு சரி பண்ணணும்.
- **ஆபத்தான actions-ஐ AI steps check இல்லாம செய்ய விடுறது.** Payments, deletions, sensitive messages-க்கு ஒரு மனுஷனை சேருங்க.
- **Data rules-ஐ மறக்குறது.** Automations-ல இருக்குற customer data-வுக்கும் privacy law பொருந்தும்.
- **Automation-க்கு தேவைக்கு அதிகமா access கொடுக்குறது.** ஒவ்வொரு step use பண்றதுக்கு மட்டும் permissions வைங்க.

## Practice பண்ணுங்க

கீழே link பண்ணியிருக்குற Zapier-ஓட automation basics guides-ஐ பாருங்க, n8n-ஓட quickstart page-ஐயும் படிங்க.

1. **List பண்ணுங்க.** நீங்க அல்லது உங்க team ஒவ்வொரு வாரமும் செய்யுற, திரும்ப திரும்ப வர்ற அஞ்சு tasks-ஐ எழுதுங்க. ஒவ்வொண்ணுக்கும் trigger, steps, data எங்க இருக்குன்னு note பண்ணுங்க.
2. **Score போடுங்க.** ஒவ்வொண்ணுக்கும் frequency, repetitiveness, check பண்றதோட ஈஸி, கஷ்டம்: இதுக்கு 1 முதல் 5 வரை score கொடுங்க. அதிக score வாங்குனதை எடுங்க.
3. **Design பண்ணுங்க.** அந்த task-ல எந்த steps simple rules, எதுக்கு AI step வேணும், எங்க ஒரு மனுஷன் check பண்ணணும்ன்னு mark பண்ணுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** உங்க சொந்த வேலையில இருந்து ஒரு automation-ஐ trigger, steps, checks-ன்னு விவரிக்க முடியும், அது ஏன் நல்ல முதல் candidate-ன்னும் சொல்ல முடியும்.
