## இது என்ன

**Voice agent**-னா phone line-ல அல்லது ஒரு web page-ல நீங்க பேசுற, திரும்ப பேசுற AI. உள்ளுக்குள்ள, ஒவ்வொரு வினாடிக்கும் பல தடவை மூணு systems-ஐ சங்கிலி மாதிரி இணைக்குது:

1. **Speech-to-text** (ஒரு transcriber) caller-ஓட audio-வை வார்த்தைகளா மாத்தும்.
2. ஒரு **language model** என்ன சொல்லணும், ஒரு tool use பண்ணணுமான்னு முடிவு பண்ணும்.
3. **Text-to-speech** (ஒரு voice) பதிலை இயல்பான audio-வா மாத்தும்.

இந்த loop-ஐ நீங்களே build பண்ணா, audio streams, interruptions, silence, phone networks, latency எல்லாத்தையும் handle பண்ணணும். **Vapi** இந்த plumbing-ஐ பண்ற ஒரு developer platform. நீங்க ஒரு **assistant**-ஐ configure பண்ணுவீங்க: transcriber, model, voice-ஐ தேர்ந்தெடுத்து, அதுக்கு instructions எழுதி, tools கொடுத்து, ஒரு phone number அல்லது web-call button-ஐ attach பண்ணுவீங்க. Vapi உரையாடலை real time-ல நடத்தும்.

```flow
dir: LR
title: Phone line, streaming audio, turn-taking, interruptions, call logs-ஐ Vapi பார்த்துக்கும்
Caller பேசுறாங்க -> Transcriber -[text]-> LLM + prompt -[பதில்]-> Voice -> Caller கேக்குறாங்க
LLM + prompt -[tool call]-> உங்க server அல்லது n8n webhook | slots check பண்றது, book பண்றது, order-ஐ பார்க்கிறது
உங்க server அல்லது n8n webhook -[result]-> LLM + prompt
```

## இது எப்படி work ஆகுது

**Assistant.** Vapi dashboard-ல ஒரு assistant-ஐ உருவாக்கி, இவற்றை set பண்ணுவீங்க:

- **Model மற்றும் system prompt:** agent யார், என்ன பண்ண முடியும், அதுக்கு தேவையான facts (timings, prices), உறுதியான rules (மருத்துவ advice ஒருபோதும் கொடுக்காதே, book பண்றதுக்கு முன்னாடி எப்பவும் confirm பண்ணு).
- **First message:** call connect ஆனதும் அது சொல்றது. அது ஒரு AI assistant-ங்குறதை சேருங்க.
- **Transcriber:** speech-to-text provider-உம் மொழியும். Indian English, Hindi, மத்த மொழிகள்ல providers-க்கு நடுவுல quality வேறுபடும், அதனால real பேசுறவங்கள வச்சு test பண்ணுங்க.
- **Voice:** text-to-speech provider-உம் voice-உம். உங்க callers-க்கு இயல்பா ஒலிக்கிறதை தேர்ந்தெடுத்து, உள்ளூர் பெயர்களோட உச்சரிப்பை test பண்ணுங்க.

**Tools.** Tools பேச்சை செயலா மாத்தும். `book_slot(date, time, name, phone)` மாதிரி ஒரு function-ஐ describe பண்ணி, Vapi call பண்ண ஒரு server URL கொடுப்பீங்க. எப்போ call பண்ணணும்னு model முடிவு பண்ணும்; உங்க server, அல்லது ஒரு webhook-க்கு பின்னாடி இருக்குற n8n workflow, வேலையை பண்ணி, agent பேசுற result-ஐ திருப்பி தரும்.

**Phone numbers.** Vapi வழியா ஒரு number வாங்கலாம், இல்லன்னா Twilio மாதிரி ஒரு telephony provider-ல இருந்து கொண்டு வரலாம். Inbound calls உங்க assistant-க்கு போகும்; reminders, follow-ups-க்கு API வழியா outbound calls-ஐயும் ஆரம்பிக்கலாம். ஒரு client-க்கு local number-ஐ promise பண்றதுக்கு முன்னாடி, இந்தியாவுக்கு எந்த countries, number types support ஆகுதுன்னு check பண்ணுங்க.

**உரையாடல் behaviour.** Settings இவற்றை control பண்ணும்: caller பேசி முடிச்சுட்டாங்கன்னு agent எப்போ முடிவு பண்றது (**endpointing**), caller இடையில புகுந்தா என்ன ஆகும், background noise handling, அதிகபட்ச call நீளம், எப்போ human-கிட்ட transfer பண்றது.

**Call முடிஞ்சதுக்கு அப்புறம்.** Vapi transcripts, recordings (enable பண்ணா), உங்க server-க்கு அனுப்பக்கூடிய end-of-call report-ஐ வச்சிருக்கும்: ஒரு summary, நீங்க கேட்ட structured data, success criteria. இப்படித்தான் quality-ஐ review பண்ணி, CRM-க்கு feed பண்றீங்க.

**Web calls-உம்.** அதே assistant-ஐ Vapi-ஓட web SDK வழியா ஒரு website அல்லது app-ல run பண்ணலாம்; அதனால "எங்ககிட்ட பேசுங்க" button, phone line எதுவும் இல்லாம browser-லயே ஒரு voice உரையாடலை ஆரம்பிக்கும். Numbers வாங்குறதுக்கு முன்னாடி prototype பண்ண இது மலிவான வழி.

**Code-ல ஒரு tool server.** Assistant ஒரு tool-ஐ call பண்ணும்போது, Vapi உங்க server URL-க்கு ஒரு POST request அனுப்பும்; உங்க server agent பேசுற results-ஓட பதில் சொல்லும். ஒரு சின்ன FastAPI handler; சரியான payload fields-க்கு Vapi-ஓட தற்போதைய docs-ஐ பாருங்க:

```python
import os
from fastapi import FastAPI, Request, HTTPException

app = FastAPI()
SECRET = os.environ["VAPI_SERVER_SECRET"]          # the secret you set on the assistant

@app.post("/vapi/tools")
async def tools(request: Request):
    if request.headers.get("x-vapi-secret") != SECRET:
        raise HTTPException(status_code=401)
    body = await request.json()
    results = []
    for call in body["message"].get("toolCallList", []):
        name, args = call["function"]["name"], call["function"]["arguments"]
        if name == "book_slot":
            result = book_slot(**args)             # your validation and booking code
        else:
            result = "Sorry, I can't do that on this call."
        results.append({"toolCallId": call["id"], "result": result})
    return {"results": results}

def book_slot(date, time, name, phone):
    if not (phone.isdigit() and len(phone) == 10):
        return "The phone number should be 10 digits. Please ask the caller to repeat it."
    slot = calendar.find(date, time)
    if not slot:
        return f"{time} on {date} is taken. The nearest free times are {calendar.nearest(date, time)}."
    calendar.book(slot, name, phone)
    return f"Booked {name} for {time} on {date}. Read the date and time back to the caller."
```

Results பேசுறதுக்காக எழுதப்படுது: சின்னதா, அடுத்து என்ன சொல்லணும்ங்கிறதோட. Validation prompt-ல மட்டுமில்ல, உங்க code-லயும் இருக்கு.

**ஒரு latency budget.** ஒரு வினாடிக்கு மேல gap இருந்தா callers கவனிப்பாங்க. பாகங்களை கூட்டி, ஒவ்வொண்ணையும் குறைங்க:

| பாகம் | வழக்கமான range | எப்படி குறைக்கிறது |
| --- | --- | --- |
| Caller நின்னுட்டாங்கன்னு முடிவு பண்றது | 0.2-ல இருந்து 0.8 s | Endpointing-ஐ tune பண்ணுங்க; quick பதில்களுக்கு குறைவா |
| Speech to text | 0.1-ல இருந்து 0.4 s | இந்தியாவுக்கு பக்கத்துல இருக்குற streaming transcriber |
| Model-ஓட first token | 0.3-ல இருந்து 1.5 s | சின்ன, வேகமான model; சின்ன prompt |
| Tool call | 0.1-ல இருந்து 2 s | வேகமான tools; மெதுவானதுக்கு முன்னாடி "let me check"ன்னு சொல்லுங்க |
| Text to speech, முதல் audio | 0.1-ல இருந்து 0.5 s | Streaming voice; சின்ன முதல் வாக்கியம் |

Dashboard-ஓட best case-ல இல்ல, real call logs-ல இருந்து அளந்து பாருங்க; average-ஐ மட்டும் இல்ல, ரொம்ப மெதுவான calls-ஐயும் பாருங்க.

**Live போறதுக்கு முன்னாடி calls-ஐ test பண்றது.** சாதாரண bookings, interruptions, தப்பான numbers, background noise, வாக்கியத்துக்கு நடுவுல Hindi அல்லது Tamil, scope-க்கு வெளியே இருக்குற requests இவற்றை உள்ளடக்கின 20 scripted calls எழுதுங்க. வேற வேற பேசுறவங்களை வச்சு phone-ல run பண்ணி, ஒவ்வொண்ணையும் score பண்ணுங்க: booking சரியா, facts சரியா, கற்பனை பதில்கள் இல்ல, handover பண்ண வேண்டிய இடத்துல பண்ணுச்சா.

**இந்தியாவில calling-க்கான rules.** ஒரு call-ஐ record பண்றதும், transcripts-ஐ store பண்றதும் personal data-வை process பண்றது: first message-லயும் உங்க privacy notice-லயும் அதை சொல்லுங்க, recordings-ஐ தேவையான நேரம் மட்டும் வச்சுக்கோங்க. Promotion அல்லது reminders-க்கான outbound calls, commercial communication-க்கான TRAI-ஓட rules-க்குள்ள வரும்; அவை registration, number series, consent-ஐ உள்ளடக்கும். எந்த outbound campaign-க்கு முன்னாடியும் தற்போதைய rules-ஐ check பண்ணுங்க.

**Browser-ல try பண்ணுங்க.** ஒரு voice agent-ஓட delay-ஐ step by step கூட்டுங்க. எந்த step-ஐ மாத்தினாலும் total-ஐ பாருங்க.

```python
steps_ms = {
    "caller stops talking (endpointing)": 400,
    "speech to text": 250,
    "model's first token": 700,
    "booking tool": 300,
    "text to speech, first audio": 200,
}
total = sum(steps_ms.values())
for step, ms in steps_ms.items():
    print(f"{step:<36} {ms:>5} ms")
print(f"{'total before the caller hears a reply':<36} {total:>5} ms", "(aim for about 1,000)")
```

## ஒரு worked example

Visakhapatnam-ல Dr Rao-வோட dental clinic வாரத்துக்கு சுமார் 40 calls-ஐ miss பண்ணுது; பெரும்பாலும் மாலை 7 மணிக்கு அப்புறம் வர்ற appointment requests. Faizan, ஒரு automation freelancer, ஒரு voice receptionist build பண்றாங்க.

அவங்க ஒரு சின்ன system prompt எழுதுறாங்க: clinic-ஓட பேர், hours, fixed consultation fees-ஓட மூணு services, treatment பத்தி பேசவே கூடாதுங்கிற ஒரு rule, book பண்றதுக்கு முன்னாடி date, time, phone number-ஐ confirm பண்ணணும்ங்கிற ஒரு rule. First message: "Hello, this is the AI assistant for Rao Dental. I can book or change appointments. How can I help?"

அவங்க n8n webhooks-ஐ சுட்டிக்காட்டுற ரெண்டு tools-ஐ உருவாக்குறாங்க. `check_slots` clinic-ஓட Google Sheet-ல இருந்து free slots-ஐ படிக்கும்; `book_slot` booking-ஐ எழுதி, patient-க்கு SMS confirmation அனுப்பும். n8n workflow clinic hours-க்கு வெளியே இருக்குற times-ஐ reject பண்றதால, குழம்பின model அதிகாலை 3 மணிக்கு book பண்ண முடியாது.

Testing-ல மூணு problems தெரியுது. Average response time 1.8 வினாடி; அதனால வேகமான model-க்கு மாறி, prompt-ஐ சுருக்கி, சுமார் 0.9 வினாடிக்கு கொண்டு வர்றாங்க. Transcriber "Gajuwaka"-வை தப்பா கேக்குது; அதனால அதை keyword-ஆ சேர்த்து, agent locations-ஐ திரும்ப சொல்ல வைக்குறாங்க. ஒரு tester பல் வலிக்கு மருந்து பத்தி கேக்குறாங்க; agent பதில் சொல்ல ஆரம்பிக்குது, அதனால rule-ஐ வலுப்படுத்தி, clinic-ஓட on-call number-க்கு ஒரு transfer-ஐ சேர்க்குறாங்க.

Launch-க்கு அப்புறம், end-of-call reports, receptionist ஒவ்வொரு காலையும் check பண்ற ஒரு sheet-க்கு போகும். தவறவிட்ட after-hours bookings கிட்டத்தட்ட இல்லாம போயிடுச்சு.

## பொதுவா பண்ற தப்புகள்

**நீளமான prompts.** ஒவ்வொரு கூடுதல் paragraph-உம் delay-ஐயும் குழப்பத்தையும் சேர்க்கும். Prompt-ஐ focused-ஆ வச்சு, reference data-வை tools-க்கு மாத்துங்க.

**Rules-ஐ model enforce பண்ணும்னு நம்புறது.** உங்க tools-லயும் validate பண்ணுங்க: business hours, prices, permissions.

**உங்க சொந்த குரலை வச்சு மட்டும் test பண்றது.** வேற வேற accents, background noise, interruptions, வாக்கியத்தின் நடுவுல மனசு மாத்துறவங்கள வச்சும் test பண்ணுங்க.

**AI-ங்குறதை சொல்லாம இருக்குறது.** AI-கிட்ட தான் பேசுறோம்னு callers-க்கு தெரியணும், recording-க்கு privacy rules படி consent வேணும். ரெண்டையும் தெளிவா சொல்லுங்க.

**வெளியேற வழி இல்லாம இருக்குறது.** எப்பவும் ஒரு human, ஒரு callback அல்லது ஒரு message-ஐ offer பண்ணுங்க. ஒரு bot-ல சிக்கிக்கிறது customer-ஐ இழக்குறதுக்கு வேகமான வழி.

**ஒரு நிமிஷத்துக்கான cost-ஐ கண்டுக்காம இருக்குறது.** Transcriber, model, voice, telephony ஒவ்வொண்ணும் நிமிஷத்துக்கோ token-க்கோ charge பண்ணும். Quote பண்றதுக்கு முன்னாடி மாசாந்திர minutes-ஐ estimate பண்ணி, தற்போதைய prices-ஐ check பண்ணுங்க.
- **Webhook secret-ஐ check பண்ணாம இருக்குறது.** URL-ஐ கண்டுபிடிக்கிற யாரும் உங்க tools-ஐ call பண்ணலாம்.
- **நீளமான, எழுத்து நடையில இருக்குற tool results.** சத்தமா படிக்கும்போது மெதுவாவும் விறைப்பாவும் ஒலிக்கும்.
- **உங்க சொந்த குரலை வச்சு மட்டும் test பண்றது.** Accents, noise, மொழிகள் accuracy-ஐ மாத்தும்.

## Voice agent தப்பான தேர்வா இருக்குற நேரங்கள்

- **Callers நிறைய options-ஐ compare பண்ணணும்**, நீளமான price lists மாதிரி: ஒரு WhatsApp message அல்லது web page ஈஸியா இருக்கும்.
- **ரொம்ப sensitive உரையாடல்கள்**, மருத்துவ results அல்லது கடன் வசூல் மாதிரி, அங்க ஒரு மனுஷன் பேசணும்.
- **உங்க callers-ஓட மொழிகளுக்கு transcription மோசமா இருக்கு**, tests-ல உறுதியானா.
- **ஒரு simple IVR menu ஏற்கனவே work ஆகுது**, callers-உம் அதுல சந்தோஷமா இருக்காங்க.
