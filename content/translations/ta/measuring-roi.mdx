## இது என்ன

ஒவ்வொரு automation project-உம் ஒரு கட்டத்துல ஒரு கேள்வியை சந்திக்கும்: **இது worth-ஆ இருந்துச்சா?** Business owners-உம் managers-உம் பணம் கொடுக்குறதுக்கு முன்னாடியும், launch-க்கு அப்புறமும் இதை கேப்பாங்க. **Return on investment (ROI)** ஒரு automation திருப்பிக் கொடுக்குறதை, அதுக்கு ஆகுற செலவோட ஒப்பிடுது.

| Gains | Costs |
| --- | --- |
| **மிச்சமான நேரம்**: இந்த task-க்கு staff இனி செலவழிக்காத hours | **Build**: உங்க நேரம் அல்லது fee |
| **தவிர்த்த errors**: தடுக்கப்பட்ட rework, penalties, தப்பான payments, இழந்த orders | **Running**: tool subscriptions, AI usage, messaging fees, hosting |
| **வேகம்**: வேகமான responses அல்லது processing; இது அதிக sales-ஆவும் சந்தோஷமான customers-ஆவும் மாறலாம் | **Maintenance**: automation-ஐ fix பண்ணி update பண்றது |
| **Capacity**: ஆள் எடுக்காம அதிக volume-ஐ handle பண்றது | **Human review**: இன்னும் மக்கள் check பண்ணவோ exceptions handle பண்ணவோ செலவழிக்கிற நேரம் |

| | Before (baseline) | After (அளந்தது) |
|---|---|---|
| ஒரு நாளைக்கு orders | 150 | 150 |
| ஒரு order-க்கு நேரம் | 3 min | 1.2 min |
| தப்பான quantity | 2% | 0.9% |

```flow
dir: LR
முன்னாடியும் பின்னாடியும் -> வித்தியாசம் x அதோட value = gains -> Gains மைனஸ் costs -> Net benefit
```

இந்த lesson-ல Indore-ல ஒரு distributor-ஓட WhatsApp order automation, தன் value-ஐ owner-க்கு நிரூபிக்கணும். Lesson முடியும் போது, தெளிவான assumptions-ஓட ஒரு ROI estimate-ஐ present பண்ணவும், அதை நிரூபிக்க என்ன அளக்கணும்னு தெரிஞ்சுக்கவும் முடியும்.

## இது எப்படி work ஆகுது

### 1. முதல்ல baseline-ஐ அளங்க

எதையும் மாத்துறதுக்கு முன்னாடி இதை அளங்க: மாசத்துக்கு volume, ஒரு item-க்கு நேரம், error rate, turnaround time. முடிஞ்சா real data use பண்ணுங்க: emails-ல இருக்குற timestamps, system logs, அல்லது staff ஒவ்வொரு item-க்கும் start, end நேரத்தை note பண்ற ரெண்டு வார sample. Baseline இல்லாம, அப்புறம் எதையும் நிரூபிக்கவே முடியாது.

### 2. Build பண்றதுக்கு முன்னாடி estimate பண்ணுங்க

```text
  Monthly hours saved  =  items per month  x  minutes saved per item  /  60

  Value of time        =  hours saved  x  loaded hourly cost

  Value of errors      =  errors avoided per month  x  cost per error

  Net monthly benefit  =  value of time + value of errors (+ careful revenue gains)
                          - running costs - maintenance

  Payback (months)     =  build cost  /  net monthly benefit
```

**Loaded hourly cost**-னா salary-யோட benefits, office, equipment மாதிரி overheads-ஐ சேர்த்து, வேலை நேரத்தால வகுக்கிறது. இது பெரும்பாலும் salary மட்டும் எடுக்குறதை விட நல்லா அதிகமா இருக்கும்.

**வேகத்துல இருந்து வர்ற revenue** பத்தி conservative-ஆ இருங்க. வேகமான replies அதிக orders-ஐ கொண்டு வரலாம், ஆனா அதை நிரூபிக்கிறது கஷ்டம்; அதனால தனியா காட்டுங்க, இல்லன்னா விட்டுடுங்க.

### 3. Assumptions பத்தி நேர்மையா இருங்க

- ஒவ்வொரு input-ஐயும் காட்டுங்க, மத்தவங்க check பண்ணி மாத்த முடியணும்.
- **Ranges** use பண்ணுங்க: low, expected, high.
- மிச்சமான staff நேரம், அது ஏதாவது உருப்படியான வேலைக்கு போனா அல்லது ஆள் எடுக்குறதை தவிர்த்தா தான் value-ஆனதுன்னு ஞாபகம் வச்சுக்கோங்க.

| Input | Low | Expected | High |
| --- | --- | --- | --- |
| ஒரு order-ல மிச்சமான நிமிஷங்கள் | 1.5 | 2 | 2.5 |
| Error குறைவு | 25% | 50% | 70% |
| மாசத்துக்கு running cost | ₹11,000 | ₹9,000 | ₹8,000 |

### ரூபாயில இல்லாத benefits

சில gains உண்மையானவை, ஆனா விலை போடுறது கஷ்டம்: month-end பத்தி இனி பயப்படாத staff, ஒரு நாள் காத்திருக்காம சில நிமிஷங்கள்ல பதில் கிடைக்கிற customers, owner-க்கு வர்ற இரவு நேர calls குறைவு. இதுக்கெல்லாம் ரூபாய் value-ஐ கற்பனை பண்ணாதீங்க. உங்க கிட்ட இருக்குற evidence-ஓட, உதாரணத்துக்கு complaints குறைஞ்சது, overtime hours குறைஞ்சது, "other benefits"ன்னு தனியா list பண்ணுங்க. பெரிய number-ஐ விட, இங்க நேர்மையைத் தான் முடிவு எடுக்குறவங்க அதிகமா மதிப்பாங்க; அளந்த numbers வரும்போது உங்க credibility-ஐயும் அது காப்பாத்தும்.

### 4. Launch-க்கு அப்புறம் அளங்க

ஒண்ணுல இருந்து மூணு மாசம் கழிச்சு, அதே measures-ஐ baseline-ஓட ஒப்பிடுங்க: தானா process ஆன items, exceptions-க்கும் reviews-க்கும் இன்னும் செலவாகுற human நேரம், error rates, இன்னும் estimates இல்லாம real invoices-ல இருந்து எடுத்த running costs.

### 5. Simple-ஆ report பண்ணுங்க

ஒரே page: baseline, இப்போ, savings, costs, net benefit, payback, அடுத்து எதை improve பண்ணுவீங்க. Owners ஒரு page படிப்பாங்க; பன்னிரண்டு pages படிக்க மாட்டாங்க.

## ஒரு உதாரணம்

Indore-ல ஒரு distributor 300 கடைகள்கிட்ட இருந்து WhatsApp-ல orders வாங்குறாங்க. ஒவ்வொரு order-ஐயும் staff கையால billing system-ல type பண்றாங்க. Automation WhatsApp orders-ஐ படிச்சு, AI step மூலமா items, quantities-ஐ எடுத்து, ஒரு quick human confirmation-க்காக billing system-ல போடுது.

**Baseline** (ரெண்டு வார sample): 26 வேலை நாட்கள்ல ஒரு நாளைக்கு 150 orders, ஒண்ணை type பண்ண சுமார் 3 நிமிஷம். 2% orders-ல quantity தப்பா இருந்துச்சு, ஒவ்வொண்ணுக்கும் returns, re-delivery-னு சுமார் ₹400 செலவு.

**Estimate:**

| Line | Calculation | மாசாந்திர value |
| --- | --- | --- |
| மாசத்துக்கு orders | 150 × 26 | 3,900 |
| மிச்சமான hours | 3,900 × (3 − 1) ÷ 60 | 130 hours |
| நேரத்தோட value | 130 × ₹250 loaded cost | ₹32,500 |
| தவிர்த்த errors | 3,900-ல 2%-ல இருந்து 1% = 39 குறைவு × ₹400 | ₹15,600 |
| Running costs | WhatsApp provider, AI usage, hosting | −₹9,000 |
| **Net benefit** | | **₹39,100** |
| Payback | ₹90,000 build fee ÷ ₹39,100 | **சுமார் 2.3 மாசம்** |

## பொதுவா பண்ற தப்புகள்

- **Baseline இல்லாம இருக்குறது.** அப்புறம் எதையும் நிரூபிக்க முடியாது.
- **Build cost-ஐ மட்டும் எண்ணுறது.** Running, maintenance costs ஒவ்வொரு மாசமும் தொடரும்.
- **மிச்சம் இருக்குற human வேலையை கண்டுக்காம விடுறது.** Reviews-க்கும் exceptions-க்கும் இன்னும் நேரம் ஆகும்.
- **ஒரே optimistic number.** Ranges-உம் conservative assumptions-உம் use பண்ணுங்க.
- **யாரும் use பண்ணாத savings-ஐ claim பண்றது.** மிச்சமான hours, valuable வேலைக்கு போனா அல்லது ஆள் எடுக்குறதை தவிர்த்தா தான் matter ஆகும்.
- **Loaded cost-க்கு பதிலா salary use பண்றது**, அல்லது தலைகீழா, எதை use பண்ணுனீங்கன்னு சொல்லாம.

## Practice பண்ணுங்க

கீழே link பண்ணியிருக்குற GOV.UK-ஓட measuring success guide-ஐ படிங்க; AI-cost line-க்காக இப்போதைய model prices-ஐ தேடி, எப்போ check பண்ணுனீங்கன்னு தேதியையும் note பண்ணுங்க.

1. **Baseline.** Automate பண்ணக்கூடிய ஒரு task-க்கு baseline அளங்க: ஒரு வாரத்துக்கு volume, ஒரு item-க்கு நிமிஷங்கள், error rate.
2. **Estimate.** Low, expected, high cases-ஓட, running costs, payback-ஐயும் சேர்த்து ஒரு ROI estimate build பண்ணுங்க.
3. **Report template.** Launch-க்கு அப்புறம் நீங்க நிரப்பப் போற one-page report-ஐ எழுதுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** தெளிவான assumptions-ஓட ஒரு ROI estimate-ஐ present பண்ணி, அதை நிரூபிக்க என்ன அளக்கப் போறீங்கன்னு சொல்ல முடியும்.
