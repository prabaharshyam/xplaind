## இது என்ன

Machine learning-னா data-ல இருந்து கத்துக்கிறது; data-வோ noisy-ஆ, skewed-ஆ, முழுமையில்லாம இருக்கும். **Statistics**-னா uncertainty-க்குள்ள உங்களை நீங்களே ஏமாத்திக்காம data-ல இருந்து கத்துக்க உதவுற toolkit. ML engineering-ல தினமும் வர்ற ஐந்து பகுதிகள்:

| பகுதி | எந்த கேள்விக்கு பதில் சொல்லுது | எந்த வழக்கமான தப்பை தடுக்குது |
| --- | --- | --- |
| **Data-வை describe பண்றது** | Typical என்ன, எவ்வளவு பரவியிருக்கு? | Misleading average-ஐ report பண்றது |
| **Sampling** | நாம கவலைப்படுற மக்களை நம்ம data represent பண்ணுதா? | Tier-3 towns-ல fail ஆகுற model |
| **உறவுகள்** | இதெல்லாம் சேர்ந்து நகருதா, ஒண்ணு இன்னொண்ணுக்கு காரணமா? | ஒரு feature தான் outcome-க்கு காரணம்னு claim பண்றது |
| **Uncertainty** | இந்த number-ல எவ்வளவு உறுதி? | Noise-ஆ இருக்குற 1-point gain-ஐ கொண்டாடுறது |
| **Experiments** | நம்ம change உண்மையிலேயே உதவுச்சா? | Festival sale-ஓட credit-ஐ புது model-க்கு கொடுக்குறது |

  count
   |  ####
   |  ########
   |  ##########
   |  ######
   |  ###
   |  #                                         #
   +----------------------------------------------- value
      ^ median ₹780                    ^ mean ₹1,240 pulled right by a few big orders

Mumbai-ல ஒரு e-commerce company-யோட data team-ஐ இந்த lesson follow பண்ணும். புது recommendation model "order value-வை ₹70 உயர்த்துச்சு"ங்குற claim, சரியான statistics-ல பார்த்தா ரொம்ப சின்ன, ஆனா உண்மையான gain-ஆ மாறுது. Lesson முடியும்போது ஒரு நியாயமான A/B test design பண்ணவும், சின்ன test sets ஏன் ஏமாத்தும்னு explain பண்ணவும் முடியும்.

## இது எப்படி work ஆகுது

### Averages-உம் spread-உம்

**Mean** எல்லாத்தையும் கூட்டி வகுக்கும். தீவிர values அதை இழுக்கும். **Median**-னா sort பண்ணா நடுவுல வர்ற value. அது இழுக்கப்படாது.

இந்தியாவுல income, order values, insurance claims பெரும்பாலும் **skewed**-ஆ இருக்கும்: பெரும்பாலான values சின்னது, சில மட்டும் ரொம்ப பெரியது. அதனால median தான் பெரும்பாலும் typical. Spread-க்கு:

| Data shape | எந்த average use பண்றது | எந்த spread use பண்றது |
| --- | --- | --- |
| கிட்டத்தட்ட symmetric, bell வடிவம் | Mean | Standard deviation |
| Skewed, நீளமான tail | Median | 90th, 99th மாதிரி percentiles |

Summarise பண்றதுக்கு முன்னாடி எப்பவும் ஒரு histogram plot பண்ணுங்க.

### Distributions

நிறைய அளவுகள் கிட்டத்தட்ட **normal** (bell வடிவம்), உதாரணம்: measurement errors. நிறைய business அளவுகள் skewed-ஆவோ நீளமான tails-ஓடவோ இருக்கும். அபூர்வமான events-ஓட counts வேற வடிவங்கள்ல இருக்கும். எந்த summaries, models பொருந்தும்னு shape தான் முடிவு பண்ணும்.

### Sampling

Metro customers-ல train பண்ண model tier-3 towns-ல fail ஆகலாம். கேளுங்க: **இந்த data-ல யார் missing?** சில cases-க்கு சாதகமா collect பண்ணாங்களா, உதாரணம்: complain பண்ண customers மட்டும், அல்லது approve ஆன loans மட்டும் (அதனால reject ஆனவங்க திருப்பி கட்டியிருப்பாங்களான்னு நீங்க பார்க்கவே மாட்டீங்க)? இந்த **selection bias** launch-க்கு அப்புறம் models-ஐ சத்தமில்லாம உடைக்கும்.

### Correlation-உம் causation-உம்

ரெண்டு விஷயங்கள் சேர்ந்து நகருறதால ஒண்ணு இன்னொண்ணுக்கு காரணம்னு அர்த்தம் இல்லை. Ice-cream sales-உம் நீரில் மூழ்கி இறக்குறதும் கோடையில ரெண்டுமே அதிகமாகுது: வெயில் தான் ரெண்டையும் இயக்குது. Model correlations-ஐ use பண்ணி **predict** பண்ணலாம், ஆனா ஒரு **cause**-ஐ claim பண்ண, உதாரணம்: discount retention-ஐ அதிகரிச்சுது, ஒரு experiment அல்லது கவனமான causal methods வேணும்.

### Confidence intervals

200 test examples-ல அளந்த 87% accuracy, வேற 200 examples sample-ல 82% அல்லது 92%-ஆ கூட வரலாம். **Confidence interval** இந்த range-ஐ சொல்லுது.

```text
  Accuracy on 200 examples, with 95% intervals:
  Model A  87%   |-------[====*====]-------|   about 82% to 92%
  Model B  88%    |-------[====*====]-------|  about 83% to 93%
                  heavily overlapping: no clear winner
```

சின்ன test sets அகலமான intervals தரும். 200 examples-ல 1-point gain-ஐ கொண்டாடாதீங்க. Interval-ஐ calculate பண்ண ஒரு practical வழி **bootstrapping**: test set-ஐ replacement-ஓட பல தடவை resample பண்ணி, ஒவ்வொரு தடவையும் metric-ஐ மறுபடி calculate பண்ணி, நடுவுல இருக்குற 95% results-ஐ பாருங்க.

### A/B tests

புது model உதவுதான்னு தெரிஞ்சுக்க, users-ஐ **randomly** பிரிங்க: பாதி பேர் பழைய version-ஐ, பாதி பேர் புது version-ஐ பார்ப்பாங்க. முன்னாடியே நீங்க தேர்ந்தெடுத்த ஒரு metric-ஐ compare பண்ணுங்க.

| Rule | ஏன் |
| --- | --- |
| Metric-ஐயும் sample size-ஐயும் முன்னாடியே முடிவு பண்ணுங்க | இல்லன்னா நல்லா தெரியுற number-ஐ தேர்ந்தெடுப்பீங்க |
| யார் எந்த version-ஐ பார்ப்பாங்கன்னு randomise பண்ணுங்க | அப்போ groups ரெண்டுக்கும் வித்தியாசம் change மட்டும் தான் |
| முழு வாரங்களுக்கு run பண்ணுங்க | Weekday, weekend behaviour வேற வேற |
| நல்லா தெரியுதுன்னு சீக்கிரம் நிறுத்தாதீங்க | ஆரம்ப results ஆடும்; உச்சத்துல நிறுத்துனா effect பெருசா தெரியும் |
| Guardrail metrics-ஐ கவனிங்க | Order value gain-ஓட returns, complaints அதிகமாகக்கூடாது |

## ஒரு worked example

Mumbai e-commerce company-யோட data team சொல்றாங்க, புது recommendation model சராசரி order value-வை ₹1,240-ல இருந்து ₹1,310-க்கு உயர்த்துச்சு: ₹70 gain. Leadership கொண்டாட தயாரா இருக்காங்க. நீங்க check பண்றீங்க.

**Averages.** Order values skewed. சில பெரிய electronics orders mean-ஐ நகர்த்திடுச்சு. Median ₹780-ல இருந்து ₹790-க்கு மட்டும் தான் உயர்ந்துச்சு.

**Sampling.** Compare பண்ணது போன மாசம் (பழைய model) vs இந்த மாசம் (புது model). இந்த மாசம் ஒரு festival sale இருந்துச்சு. அதனால ரெண்டு மாசங்களையும் compare பண்ண முடியாது.

**சரியான test.** Team ரெண்டு வாரம் A/B test run பண்றாங்க: ஒரு group-க்கு 2,00,000 users, randomly assign பண்ணது, median order value-வும் conversion rate-உம் முன்னாடியே metrics-ஆ தேர்ந்தெடுத்தது, returns guardrail-ஆ.

| Measure | பழைய model | புது model | வித்தியாசம் (95% interval) |
| --- | --- | --- | --- |
| Median order value | ₹781 | ₹799 | +₹18 (₹6 முதல் ₹30) |
| Conversion rate | 3.42% | 3.43% | தெளிவான மாற்றம் இல்லை |
| Return rate (guardrail) | 6.1% | 6.0% | தெளிவான மாற்றம் இல்லை |

Model உதவுது தான், ஆனா முதல் report claim பண்ணதுல கிட்டத்தட்ட கால் பங்கு தான். இந்த gain-ஏ roll out பண்ணுறதை justify பண்ணுதுன்னு leadership முடிவு பண்றாங்க, இப்போ நேர்மையான numbers-ஓட; team தன்னோட launch checklist-ல "Impact claim பண்றதுக்கு முன்னாடி A/B test"-ஐ சேர்த்துக்குது.

## பொதுவா பண்ற தப்புகள்

- **Skewed data-வோட mean-ஐ report பண்றது.** Median-ஐயும் histogram-ஐயும் பாருங்க.
- **வேற வேற காலங்களை compare பண்றது.** Seasons, festivals எல்லாத்தையும் மாத்தும்; அதுக்கு பதிலா randomise பண்ணுங்க.
- **Data-ல யார் missing-ன்னு கவனிக்காம இருக்கிறது.** Selection bias அப்புறம் models-ஐ உடைக்கும்.
- **Correlation-ஐ causation-ஆ எடுத்துக்கிறது.** Prediction-ங்குறது cause-க்கு proof இல்லை.
- **சின்ன test sets, சின்ன gains.** Improvement claim பண்றதுக்கு முன்னாடி confidence interval-ஐ check பண்ணுங்க.
- **A/B tests-ஐ எட்டிப்பார்த்து சீக்கிரம் நிறுத்துறது.** Duration-ஐ முன்னாடியே முடிவு பண்ணி அதுல நில்லுங்க.

## Practice பண்ணுங்க

கீழே link பண்ணியிருக்குற StatQuest-ஓட histograms, mean vs median, confidence intervals, A/B testing videos-ஐயும், Google-ஓட Machine Learning Crash Course-ல data module-ஐயும் பாருங்க.

1. **Mean vs median.** பணம் இருக்குற column உள்ள ஏதாவது ஒரு public dataset-ஐ load பண்ணுங்க. Histogram plot பண்ணி, mean-ஐயும் median-ஐயும் compare பண்ணுங்க.
2. **Bootstrap.** 200 test examples-ல ஒரு model-ஓட accuracy-க்கு, test set-ஐ 1,000 தடவை resample பண்ணி 95% confidence interval-ஐ calculate பண்ணுங்க.
3. **Test design பண்ணுங்க.** உங்களுக்கு முக்கியமான ஒரு change-க்கு ஒரு A/B test design பண்ணுங்க: metric, guardrails, sample size மதிப்பீடு, duration.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** 200 examples-ல 1-point accuracy gain ஏன் convincing இல்லைன்னு explain பண்ண முடியும், ஒரு நியாயமான A/B test-ஐ design பண்ண முடியும்.
