## இது என்ன

RAG system passages-ஐ retrieve பண்ணி, அதுல இருந்து பதில் சொல்லுன்னு model-கிட்ட கேக்குது. ஆனா அந்த passages-க்கு உள்ளயே இருக்கணும்னு model-ஐ எதுவும் கட்டாயப்படுத்தாது. அது training-ல கத்துக்கிட்டதை கலக்கலாம், gaps-ஐ நம்பும்படியான details வச்சு நிரப்பலாம், documents எப்பவுமே cover பண்ணாத கேள்விக்கும் பதில் சொல்லிடலாம். **Grounding**-னா பதிலை sources-ஓட கட்டி வைக்கிற techniques-ஓட தொகுப்பு:

- கொடுத்த passages-ஐ மட்டும் use பண்ணுன்னு சொல்ற instructions;
- ஒவ்வொரு claim-ஐயும் அதை support பண்ற passage-ஓட link பண்ற **citations**;
- Passages-ல பதில் இல்லைன்னா தெளிவான **refusal** வழி;
- பதில் தன் sources-க்கு **faithful**-ஆ இருக்கான்னு பார்க்கிற ஒரு check (automatic-ஆவோ human-ஆவோ).

```flow
Question -> Retrieve passages | [1] Leave Policy v4, 3.2, p.6; [2] Leave Policy v4, 3.4, p.7; [3] Travel Policy v2, 1.1, p.2
Retrieve passages -> Prompt | use only these, cite ids, refuse with a next step
Prompt -> Answer | "Earned leave carries forward up to 45 days [1]. The policies do not cover sick leave carry-forward; ask hr-help."
Answer -> Checks | ids exist? quotes match? every claim supported?
```

இந்த lesson-ல Bengaluru-ல ஒரு IT services firm-ஓட HR assistant pilot-ஐ follow பண்ணுவோம்.

## இது எப்படி work ஆகுது

**Sources-ஐ mark பண்ணுங்க.** Retrieve பண்ண ஒவ்வொரு passage-ஐயும் prompt-ல ஒரு id-ஓடும் அதோட origin-ஓடும் போடுங்க, உதாரணமா `[3] Leave Policy v4, section 2.1, page 6`. Ids இருந்தா citations சாத்தியம், debugging-உம் ஈஸி.

**தெளிவா instruct பண்ணுங்க.** Model-கிட்ட சொல்லுங்க: passages-ல இருந்து மட்டும் பதில் சொல்லு; ஒரு passage-ஐ use பண்ற ஒவ்வொரு வாக்கியத்துக்கு அப்புறமும் அதோட id-ஐ cite பண்ணு; passages கேள்விக்கு பதில் சொல்லலைன்னா அதை சொல்லி, யார்கிட்ட கேக்கலாம்னு suggest பண்ணு. Cite பண்ண பதிலுக்கு ஒரு குட்டி example, refusal-க்கு ஒரு example காட்டுங்க. Rules-ஐ விட examples-ஐ models நல்லா follow பண்ணும்.

**Built-in citations இருந்தா use பண்ணுங்க.** பல model APIs citations-ஐ structured data-வா தர முடியும்: quote பண்ண சரியான span-ஐயும் அது எந்த document-ல இருந்து வந்ததுன்னும். Text-ல bracketed numbers கேக்குறதை விட இது நம்பகமானது, ஏன்னா அந்த quote source-ல இருக்குன்னு API உறுதி தரும்.

**Generation-க்கு அப்புறம் check பண்ணுங்க.** மலிவானதுல இருந்து முழுமையானது வரை மூணு practical checks:

1. Cite பண்ண ஒவ்வொரு id-உம் அனுப்பின passages-ல இருக்கணும். அஞ்சு passages மட்டும் அனுப்பிட்டு `[7]`-ஐ cite பண்ற பதில்களை drop பண்ணுங்க அல்லது flag பண்ணுங்க.
2. Quote பண்ண spans source text-ல உண்மையிலேயே இருக்கணும் (string match).
3. ஒரு faithfulness score: இரண்டாவது model அல்லது RAGAS மாதிரி eval library பதிலை claims-ஆ பிரிச்சு, ஒவ்வொண்ணையும் passages-ஓட check பண்ணும். இதை உங்க golden set-ல offline-ஆவும், live traffic-ல ஒரு sample-லயும் ஓட்டுங்க.

**Refusal-ஐ design பண்ணுங்க.** "I could not find this in the HR policies. For leave encashment questions, contact hr-help@..." useful. வெறும் "I don't know" useful இல்லை. Refusal rate-ஐ track பண்ணுங்க: ரொம்ப அதிகம்னா retrieval fail ஆகுது; கஷ்டமான golden set-ல கிட்டத்தட்ட பூஜ்யம்னா model guess பண்ணுது.

**Checks-உம் அவை எதை பிடிக்கும்-உம்:**

| Check | செலவு | எதை பிடிக்கும் |
| --- | --- | --- |
| Cite பண்ண ids இருக்கு | Free, code மட்டும் | கற்பனையா போட்ட citation numbers |
| Quotes source-ல இருக்கு | Free, string match | கண்டுபிடிச்ச அல்லது மாத்தின quotes |
| ஒவ்வொரு வாக்கியத்துக்கும் citation இருக்கு | Free, code மட்டும் | Support இல்லாத வாக்கியங்கள் |
| இரண்டாவது model-ஓட faithfulness score | ஒரு extra call | ஒரு citation உண்மையில support பண்ணாத claims |
| ஒரு sample-ஓட human review | Staff நேரம் | நுணுக்கமான தப்புகள், tone பிரச்சனைகள் |

**Users-க்கு sources-ஐ காட்டுறது.** Citation-ஐ அது support பண்ற வாக்கியத்துக்கு பக்கத்துல போடுங்க, அதை click பண்ணா quote பண்ண passage-உம் அதோட section, page-உம் திறக்கணும். அப்போ users தங்களுக்கு முக்கியமான பதில்களை (நீண்ட விடுமுறைக்கு முன்னாடி leave rules மாதிரி) check பண்ணுவாங்க, mismatches-ஐ report பண்ணுவாங்க. அது golden set-க்கு திரும்ப feed ஆகும்.

**Code-ல built-in citations.** Anthropic-ஓட API, கொடுத்த documents-ஐ நேரடியா cite பண்ணும். ஒவ்வொரு passage-ஐயும் citations on பண்ணி ஒரு document-ஆ அனுப்புங்க:

```python
import anthropic

client = anthropic.Anthropic()

def cited_answer(question, passages):
    docs = [{"type": "document",
             "source": {"type": "text", "media_type": "text/plain", "data": p["text"]},
             "title": f"{p['title']}, section {p['section']}, page {p['page']}",
             "citations": {"enabled": True}} for p in passages]
    reply = client.messages.create(
        model="claude-sonnet-5-5", max_tokens=600,          # check the docs for current names
        system="Answer only from the documents. If they do not answer the question, say so "
               "and suggest who to contact.",
        messages=[{"role": "user", "content": docs + [{"type": "text", "text": question}]}])
    parts = []
    for block in reply.content:
        if block.type != "text":
            continue
        cites = [f'{passages[c.document_index]["title"]}: "{c.cited_text}"' for c in (block.citations or [])]
        parts.append({"text": block.text, "sources": cites})
    return parts
```

பதிலோட ஒவ்வொரு துண்டும் அது நம்பின சரியான text-ஓட வரும், வாக்கியத்துக்கு பக்கத்துல காட்ட ready-ஆ. Citations இல்லாத துண்டுகளை தான் பார்க்கணும்: ஒண்ணு அது பொதுவான வார்த்தைகள், இல்லன்னா support இல்லாத claim.

**Bracket-style citations-க்கான checks.** Plain text-ல `[n]` markers கேக்கும்போது, code-ல check பண்ணுங்க:

```python
import re

def check_citations(answer, n_passages, passages_text):
    problems = []
    sentences = [s for s in re.split(r"(?<=[.!?])\s+", answer.strip()) if s]
    for s in sentences:
        ids = [int(x) for x in re.findall(r"\[(\d+)\]", s)]
        if not ids and len(s.split()) > 5:
            problems.append(f"no citation: {s[:60]}")
        for i in ids:
            if not 1 <= i <= n_passages:
                problems.append(f"cites [{i}] but only {n_passages} passages were sent")
    for quote in re.findall(r'"([^"]{12,})"', answer):
        if not any(quote in p for p in passages_text):
            problems.append(f"quote not in any passage: {quote[:40]}")
    return problems
```

Problems உள்ள பதில்களை, stakes-ஐ பொறுத்து, ஒரு தடவை regenerate பண்ணலாம், warning-ஓட காட்டலாம், இல்லன்னா review-க்கு அனுப்பலாம்.

**Grounding-ங்கிறது உண்மை இல்லை.** Source பழசா இருந்தாலோ தப்பா இருந்தாலோ, சரியா cite பண்ண பதிலும் தப்பா இருக்கலாம். Retrieval-ல supersede ஆன documents-ஐ filter பண்ணுங்க, ஒவ்வொரு citation-கூடவும் document-ஓட date-ஐ காட்டுங்க, தப்பான source-ஐ users report பண்ண விடுங்க.

**பெரிய அளவுல faithfulness.** Golden set-க்கும் live traffic-ஓட ஒரு sample-க்கும், ஒவ்வொரு பதிலையும் claims-ஆ பிரிச்சு, ஒரு judge model வச்சு cite பண்ண passages-ஓட ஒவ்வொண்ணையும் check பண்ணுங்க. Support இல்லாத claims-ஓட பங்கை நேரம் போக போக, topic வாரியா track பண்ணுங்க.

## ஒரு example

Bengaluru-ல ஒரு IT services firm தங்களோட leave, travel, reimbursement policies மேல ஒரு HR assistant வேணும்னு நினைக்குது. Pilot-ல ஒரு employee கேக்குறார்: "Can I carry forward unused sick leave?"

Retrieve ஆன passages earned leave carry-forward பத்தி (45 நாள் வரை) சொல்லுது, sick leave பத்தி எதுவும் சொல்லல. முதல் version "Yes, you can carry forward up to 45 days of leave."ன்னு பதில் சொல்லுச்சு. Sick leave-க்கு அது தப்பு, அதுவும் உண்மை மாதிரி சொல்லப்பட்டிருக்கு.

நீங்க மூணு விஷயங்களை மாத்துறீங்க. Prompt இப்ப ஒவ்வொரு வாக்கியத்துக்கும் ஒரு citation கேக்குது, ஒரு refusal example-உம் இருக்கு. API-ஓட citation feature-க்கு மாறுறீங்க, அதனால ஒவ்வொரு claim-உம் quote பண்ண span-ஓட வருது. Citation இல்லாத claims உள்ள பதில்களை flag பண்ற ஒரு check-ஐயும் சேர்க்குறீங்க.

புது பதில்: "The policies I have cover carry-forward of earned leave: up to 45 days [Leave Policy v4, 3.2]. They do not say whether sick leave can be carried forward. Please check with HR at hr-help." Employee அந்த citation-ஐ click பண்ணி clause-ஐ படிக்கலாம்.

80-கேள்வி golden set-ல faithfulness 0.81-ல இருந்து 0.96 ஆகுது, பதிலளிக்க முடியாத கேள்விகள்ல refusal-ஓட பதில் சொன்ன பங்கு 30%-ல இருந்து 85% ஆகுது. பதிலளிக்க முடிஞ்ச கேள்விகளுக்கு சரியான பதில்கள் கிட்டத்தட்ட மாறல. இந்த மூணு numbers-ஐயும் client-கிட்ட report பண்றீங்க.

## பொதுவா பண்ற தப்புகள்

- **Passage-ஐ இல்லாம document-ஐ cite பண்றது.** "Source: HR Policies.pdf"-ஐ check பண்ண முடியாது. Section, page-ஐ cite பண்ணுங்க.
- **Golden set-ல பதிலளிக்க முடியாத கேள்விகள் இல்லாதது.** அப்புறம் guessing-ஐ நீங்க அளக்கவே மாட்டீங்க. Documents-ல இருந்து பதில் சொல்ல முடியாத கேள்விகள் set-ல குறைஞ்சது ஐந்துல ஒரு பங்கு இருக்கட்டும்.
- **Model எழுதின citation numbers-ஐ நம்பறது.** சில நேரம் claim-ஐ support பண்ணாத ஒரு passage-ஐ models cite பண்ணும். Citations-ஐ automatic-ஆ check பண்ணுங்க.
- **அடுத்த step இல்லாத refusals.** User-ஐ ஒரு நபர், ஒரு team, ஒரு form-கிட்ட அனுப்புங்க.
- **Users-கிட்ட இருந்து sources-ஐ மறைக்கிறது.** Quote பண்ண passage-ஐ காட்டினா trust வளரும், system miss பண்ண தப்புகளை users பிடிப்பாங்க.
- **Checks இல்லாம citations-ஐ parse பண்றது.** Ids இருக்கான்னு, quotes பொருந்துதான்னு verify பண்ணுங்க.
- **Citation இல்லாத வாக்கியங்களை மறைக்கிறது.** Support இல்லாம இருக்க வாய்ப்பு அதிகம் அவைக்கு தான்.
- **பழைய documents-ஐ cite பண்றது.** Dates காட்டுங்க, supersede ஆன versions-ஐ filter பண்ணுங்க.

## Citations அவ்வளவு முக்கியமில்லாத நேரங்கள்

- **Creative அல்லது drafting tasks**, அங்க model documents-ல இருக்குற facts-ஐ சொல்றதில்லை.
- **Database அல்லது tool-ல இருந்து வர்ற பதில்கள்**, order status மாதிரி, அங்க tool result தான் source.
- **Internal brainstorming**, அங்க output-ஐ facts-ஆ இல்லாம ideas-ஆ எடுத்துக்குவாங்க.

Users facts-ஐ வச்சு செயல்படுற எல்லா இடத்துலயும் citations அவசியம்: policies, prices, eligibility, health, legal, financial தகவல்.

## Demo-ல இருந்து production-க்கு

- **Provider தர்ற built-in citations-ஐ use பண்ணுங்க**, அவற்றை log பண்ணுங்க.

- **Refusal, support இல்லாத claims rates-ஐ** topic வாரியா track பண்ணுங்க.

## Practice பண்ணுங்க

கீழ link பண்ணியிருக்குற citations guide-ஐயும் faithfulness பத்தின RAGAS page-ஐயும் படிங்க.

1. உங்க RAG app அனுப்புற ஒவ்வொரு passage-க்கும் ids, source labels சேருங்க, ஒவ்வொரு வாக்கியத்துக்கும் ஒரு citation கட்டாயமாக்குங்க.
