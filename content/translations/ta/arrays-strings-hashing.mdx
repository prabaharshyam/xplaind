## இது என்ன

தினசரி code-ல பெரும்பாலான வேலையை மூணு structures தான் செய்யுது.

**Array** items-ஐ வரிசையா, memory-ல பக்கத்து பக்கத்துல வச்சிருக்கும். Python-ல `list` ஒரு array. Items பக்கத்துல இருக்கிறதால, item 5-ஐ படிச்சாலும் item 5 lakh-ஐ படிச்சாலும் ஒரே நேரம் தான். கடைசியில சேர்க்கிறது சுலபம்; முன்னாடி insert பண்ணினா எல்லாத்தையும் நகர்த்தணும்.

**String** என்பது characters-ஓட array. Python-லயும் Java-லயும் string-ஐ ஒருதடவை உருவாக்கினா மாத்த முடியாது, அதனால ஒவ்வொரு edit-உம் புது string உருவாக்கும்.

**Hash map** key-value pairs-ஐ store பண்ணும். Key வச்சு value-ஐ கண்டுபிடிக்க, எவ்வளவு pairs இருந்தாலும் கிட்டத்தட்ட ஒரே நேரம் தான் ஆகும். Python-ல `dict`, `set` ரெண்டும் hash maps. Counting, duplicates நீக்குறது, matching இதுக்கெல்லாம் இதுதான் முக்கியமான tool.

| | Array (list) | Hash map (dict) |
|---|---|---|
| எப்படி store பண்ணுது | Numbered slots-ல values: 0 Pune, 1 Goa, 2 Agra, 3 Pune | Key `hash()`-வழியா ஒரு slot-க்கு போகும்: "Pune" slot 7-க்கு, value 1,240 orders |
| படிக்க | Position வச்சு: O(1) | Key வச்சு: சராசரியா O(1) |
| Value வச்சு தேட | O(n): ஒவ்வொரு slot-ஐயும் check பண்ணணும் | தேவையில்ல: key-ஐ lookup பண்ணுங்க |
| Order | Position வச்சு order இருக்கும் | Position வச்சு order இல்ல |

## இது எப்படி work ஆகுது

**Arrays** items-ஐ memory-ல ஒரே block-ல store பண்ணும். Item i எங்க இருக்குன்னு computer சின்ன arithmetic-ல கண்டுபிடிச்சிடும். அதனாலதான் position வச்சு படிக்கிறது O(1). ஆனா ஒரு value-ஐ தேடணும்னா items-ஐ ஒண்ணொண்ணா பார்க்கணும், O(n). Array sorted-ஆ இருந்தா மட்டும் வேற.

Python lists தானா வளரும். Block நிரம்பினா, Python பெரிய block-ஐ allocate பண்ணி, எல்லாத்தையும் copy பண்ணும். அந்த copy O(n), ஆனா அது அரிதா தான் நடக்கும். அதனால append சராசரியா O(1)-ஆவே இருக்கும்.

**Hash maps** ஒரு **hash function** use பண்ணும். அது "Pune" மாதிரி ஒரு key-ஐ ஒரு number-ஆ மாத்தும். அந்த number உள்ளே இருக்குற array-ல ஒரு slot-ஐ தேர்ந்தெடுக்கும், value அங்க store ஆகும். திரும்ப படிக்கணும்னா, map அந்த key-ஐ மறுபடி hash பண்ணி நேரா அந்த slot-க்கு போகும். சில நேரம் ரெண்டு keys ஒரே slot-ல விழும், இதுக்கு **collision** னு பேரு. Map ரெண்டையும் store பண்ணி, keys-ஐ compare பண்ணி சரியானதை எடுக்கும். நல்ல hash function-உம் போதுமான slots-உம் இருந்தா, lookup, insert, delete எல்லாம் சராசரியா O(1).

Trade-off memory-யும் order-உம். Hash map list-ஐ விட அதிக memory எடுக்கும், position வச்சு படிக்கிறதுக்கு அது ஏத்தது இல்ல.

| Operation | List (array) | Dict / set (hash map) |
|---|---|---|
| Position வச்சு படிக்க | O(1) | support இல்ல |
| Value அல்லது key-ஐ கண்டுபிடிக்க | O(n) | சராசரியா O(1) |
| கடைசியில சேர்க்க / key insert பண்ண | சராசரியா O(1) | சராசரியா O(1) |
| முன்னாடி insert அல்லது delete | O(n) | சராசரியா O(1) |
| Insertion order-ஐ வச்சிருக்கா | ஆமா | Python 3.7+-ல ஆமா |

Arrays பத்தின பெரும்பாலான interview problems சில patterns-ல ஒண்ணை தான் use பண்ணும்: **frequency count** (dict-ல items-ஐ எண்ணுறது), **seen set** (பார்த்ததை நினைவு வச்சு repeats-ஐ கண்டுபிடிக்கிறது), **complement lookup** ("target minus இது" இருக்கான்னு உடனே check பண்ண values-ஐ store பண்றது), **grouping** (sorted letters மாதிரி ஒரு computed key-ஐ, items list-க்கு map பண்றது).

## ஒரு worked example

Rahul interviews-க்கு prepare பண்றாரு. Jaipur-ல ஒரு சின்ன bakery-ஓட order data-ல practice பண்றாரு. ஒரு நாளோட order amounts list அவர்கிட்ட இருக்கு. ரெண்டு orders சேர்ந்து சரியா ₹1,000 வருதான்னு தெரிஞ்சுக்கணும், ஏன்னா bakery அந்த விலைக்கு ஒரு combo கொடுக்குது.

முதல்ல தோணுற பதில் எல்லா pairs-ஐயும் try பண்றது:

```python
def pair_for(amounts, target):
    for i in range(len(amounts)):
        for j in range(i + 1, len(amounts)):
            if amounts[i] + amounts[j] == target:
                return i, j
    return None
```

இது O(n²). 20 orders-க்கு பரவாயில்ல, 2 lakh-க்கு slow.

Hash map version ஒரே தடவை scan பண்ணும். ஒவ்வொரு amount-க்கும் கேக்கும்: ₹1,000-ஐ முடிக்கிற amount-ஐ நான் ஏற்கனவே பார்த்திருக்கேனா?

```python
def pair_for(amounts, target):
    seen = {}                     # amount -> position
    for i, a in enumerate(amounts):
        need = target - a
        if need in seen:          # O(1) on average
            return seen[need], i
        seen[a] = i
    return None
```

Amounts `[250, 400, 600, 120]`, target 1,000 எடுத்துக்கோங்க: 250-ல அதுக்கு 750 வேணும் (பார்க்கல); 400-ல 600 வேணும் (பார்க்கல); 600-ல 400 வேணும், அது position 1-ல ஏற்கனவே பார்த்திருக்கு, அதனால `(1, 2)` return பண்ணும். ஒரே pass, O(n) time, O(n) space.

அடுத்து அவர் அதிகமா விக்குற item-ஐ எண்ணுறாரு. Sort பண்றதுக்கு பதிலா frequency count use பண்றாரு:

```python
from collections import Counter
items = ["bun", "cake", "bun", "puff", "bun", "cake"]
Counter(items).most_common(1)   # [('bun', 3)]
```

`Counter` உள்ளே ஒரு dict தான்: ஒரே pass, O(n).

## பொதுவான தப்புகள்

**Loop-க்குள்ள list-ல membership check பண்றது.** `if x in some_list` ஒவ்வொரு தடவையும் O(n). n items loop-க்குள்ள அது O(n²) ஆகிடும். முதல்ல set-ஆ மாத்துங்க.

**Loop-ல += வச்சு strings கட்டுறது.** ஒவ்வொரு `+=`-உம் முழு string-ஐயும் copy பண்ணும். துண்டுகளை ஒரு list-ல சேர்த்து, ஒரு தடவை `"".join(pieces)` call பண்ணுங்க.

**Unhashable keys use பண்றது.** Python-ல lists-ஐ dict keys-ஆ use பண்ண முடியாது, ஏன்னா அவை மாறும். Tuple use பண்ணுங்க, அல்லது ஒரு வார்த்தையோட sorted letters மாதிரி string use பண்ணுங்க.

**Keys-ஐ normalise பண்ண மறக்கிறது.** "+91 98450 12345"-உம் "9845012345"-உம் ஒரே customer, ஆனா வேற வேற keys. Count பண்றதுக்கு அல்லது match பண்றதுக்கு முன்னாடி keys-ஐ clean பண்ணுங்க.

**Dicts எப்பவும் O(1)-னு நினைக்கிறது.** சராசரியா தான் O(1). ரொம்ப மோசமான hashing இருந்தாலோ, attacker keys-ஐ தேர்ந்தெடுத்தாலோ slow ஆகலாம். Interview-ல "சராசரியா O(1)"ன்னு சொல்லுங்க.

**Loop பண்ணும்போதே list-ஐ மாத்துறது.** Iterate பண்ணும்போது items-ஐ நீக்கினா சிலது skip ஆகும். அதுக்கு பதிலா புது list கட்டுங்க.
