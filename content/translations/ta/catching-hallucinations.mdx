## இது என்ன

**Hallucination**-னா, facts-ஆலயோ model-க்கு கொடுத்த source-ஆலயோ ஆதரிக்கப்படாத, confident-ஆ சொல்லப்பட்ட ஒரு பதில் அல்லது அதோட ஒரு பகுதி. 2023-ல ஒரு law firm, chatbot கற்பனையா உருவாக்கின cases இருக்குற court filings-ஐ சமர்ப்பிச்சதுக்காக அபராதம் கட்டுச்சு. ஆபத்து model-க்கு உறுதி இல்லாததுல இல்லை; அது உறுதியா பேசுறதுல தான்.

சரியா இருக்குறதுக்கு ரெண்டு உபயோகமான வகை இருக்கு:

- **Local factual consistency**: பதில், கொடுத்த source-ஓட ஒத்துப்போகுதா, உதாரணம் retrieve பண்ண document, company policy, data? Summaries, support assistants, RAG apps-க்கு இது முக்கியம்.
- **Global factual consistency**: பரவலா ஏத்துக்கப்பட்ட facts-ஓட ஒத்துப்போகுதா? Open chat, research, fact-checking-க்கு இது முக்கியம்.

Source கையில இருக்குறதால, local consistency-ஐ check பண்றது ரொம்ப எளிது. Retrieval வழியா models-க்கு facts கொடுக்கணும்கிறதுக்கு இது இன்னொரு காரணம்.

**ஏன் நடக்குது.** ரெண்டு விளக்கங்கள் பரவலா பேசப்படுது:

1. **Self-delusion, அல்லது snowballing.** தனக்கு கொடுத்த text-ஐயும் தான் எழுதின text-ஐயும் model-ஆல பிரிச்சு பார்க்க முடியாது. ஆரம்பத்துல ஒரு வாக்கியம் கொஞ்சம் தப்பா இருந்தா, அடுத்த வாக்கியங்கள் அதை fact-ஆ எடுத்து அதன் மேல build பண்ணும்.
2. **Model-க்கு தெரிஞ்சதுக்கு அப்பால கத்துக் கொடுக்குறது.** Training-ல, model-க்கு தெரியாததை தெரிஞ்ச ஆட்கள் எழுதின answers-ஐ models copy பண்ணுது. அந்த அறிவு இல்லாமலே confident-ஆ பதில் சொல்ல அது கத்துக்குது.

Practice-ல hallucinations ரெண்டு இடத்துல குவியும்: model அரிதா பார்த்த **niche topics**, **இல்லாத விஷயங்கள் பத்தின கேள்விகள்** (RBI ஒண்ணுமே சொல்லாத X பத்தி "RBI X பத்தி என்ன சொன்னுச்சு?"ன்னு கேக்குறது).

## இது எப்படி work ஆகுது

**முதல்ல தடுங்க.** Detection, நழுவி வர்றதை பிடிக்கும்; prevention, அதோட அளவையே குறைக்கும்.

- Model-க்கு facts கொடுங்க: documents-க்கு retrieval, live data-க்கு tools.
- கொடுத்த sources-ல இருந்து மட்டும் பதில் சொல்லணும், இல்லைன்னா "எனக்கு தெரியலை" அல்லது "documents இதை cover பண்ணல"ன்னு சொல்லணும்னு சொல்லுங்க.
- ஒவ்வொரு claim-க்கும் source passage-ஓட citation கேளுங்க, அந்த cited passage உண்மையிலேயே இருக்கான்னு check பண்ணுங்க.
- Factual tasks-க்கு temperature-ஐ குறைவா வைங்க, பெரிய tasks-ஐ சின்ன steps-ஆ உடைங்க, அப்போ தப்புகள் snowball ஆகாது.

**உங்க model எங்க hallucinate பண்ணுதுன்னு கண்டுபிடிங்க.** Detectors build பண்றதுக்கு முன்னாடி, fail ஆன answers-ஐ படிச்சு group பண்ணுங்க. பலவீனமான இடங்களை குறி வச்ச test cases உருவாக்குங்க: அரிதான topics, தப்பான premise இருக்குற கேள்விகள், sources-ஆல பதில் சொல்ல முடியாத கேள்விகள். இவை இல்லாத test set, நிஜ users-க்கு தெரியாத ஒரு ஆறுதலான number-ஐ காட்டும்.

**Judge வச்சு detect பண்ணுங்க.** ஒரு judge model-க்கு source-ஐயும் answer-ஐயும் கொடுத்து, source ஆதரிக்காத எதுவும் answer-ல இருக்கான்னு கேளுங்க. Strong models இதை நல்லா பண்ணும், குறிப்பா சின்ன answers-ல. நம்புறதுக்கு முன்னாடி, ஒரு sample-ல human labels-ஓட அந்த judge-ஐ check பண்ணுங்க.

**Claim by claim detect பண்ணுங்க.** நீளமான answers-ல உண்மையான, தப்பான statements கலந்து இருக்கும், அதனால ஒரே verdict பிரச்சனைகளை மறைச்சிடும். Google DeepMind-ஓட SAFE method இந்த pattern-ஐ காட்டுது: answer-ஐ தனித்தனி claims-ஆ பிரிங்க, ஒவ்வொண்ணையும் தனியா நிக்கிற மாதிரி மாத்தி எழுதுங்க, evidence-க்கு search பண்ணுங்க, அப்புறம் ஒவ்வொரு claim-ஐயும் judge பண்ணுங்க. RAG apps-ல "search" step-ங்கிறது retrieve பண்ண passages தான்.

**Entailment model வச்சு detect பண்ணுங்க.** Natural language inference (NLI) models ஒரு premise-ஐயும் (source) ஒரு hypothesis-ஐயும் (ஒரு claim) எடுத்து, **entailment** (supported), **contradiction**, **neutral** (சொல்ல முடியாது)ன்னு சொல்லும். இதுக்காகவே train பண்ண சின்ன open models, ஒவ்வொரு claim-ல வேகமாவும் மலிவாவும் ஓடும்.

**மறுபடி sample பண்ணி detect பண்ணுங்க.** SelfCheckGPT, அதே கேள்விக்கு பல புது answers-ஐ sample பண்ணுது. அவை முதல் answer-ஓட claims-ஓட ஒத்துப்போகலைன்னா, அந்த claims கதை கட்டினதா இருக்க வாய்ப்பு அதிகம்; ஏன்னா model உண்மையிலேயே தெரிஞ்சதை திரும்ப சொல்லும், கற்பனை பண்றதை மாத்தி மாத்தி சொல்லும். இதுக்கு source வேணாம், ஆனா செலவு பல மடங்காகும், அதனால spot checks, high-stakes answers-க்கு மட்டும் use பண்ணுங்க.

Entailment model வச்சு ஒரு simple claim checker:

```python
def unsupported_claims(answer, sources, split_claims, entails):
    """split_claims(text) -> list of standalone claims.
    entails(premise, claim) -> 'entailment' | 'contradiction' | 'neutral'."""
    flagged = []
    for claim in split_claims(answer):
        verdicts = [entails(src, claim) for src in sources]
        if "entailment" not in verdicts:
            flagged.append({"claim": claim, "contradicted": "contradiction" in verdicts})
    return flagged
```

| --- | --- | --- | --- |
| முழு answer-ல judge model | ஆமா, அல்லது search | நடுத்தரம் | சின்ன answers, quick checks |
| Judge வச்சு claim-by-claim | ஆமா, அல்லது search | அதிகம் | நிறைய facts இருக்குற நீளமான answers |
| ஒவ்வொரு claim-க்கும் Entailment (NLI) model | ஆமா | குறைவு | RAG app-ல ஒவ்வொரு answer-க்கும் |
| மறுபடி sampling (self-consistency) | இல்லை | அதிகம் | Spot checks, open கேள்விகள் |
| Citation check | ஆமா | ரொம்ப குறைவு | Sources காட்டுற எந்த app-க்கும் |

## ஒரு worked example

Bengaluru-ல ஒரு fintech, Income Tax Act-ஓட retrieved sections-ஐயும் CBDT circulars-ஐயும் வச்சு freelancers-ஓட income tax கேள்விகளுக்கு பதில் சொல்ற ஒரு assistant நடத்துது. ஒரு tax lawyer 100 answers-ஐ review பண்ணி, 9-ல ஆதாரமில்லாத claim இருக்குறதை கண்டுபிடிக்கிறார். ஆறு அரிதான deductions பத்தி, மூணு இல்லாத circulars-ஐ விவரிக்குது.

அவங்க steps:

1. **குறி வச்ச test set.** 150 கேள்விகள்: பொதுவானவை, அரிதான deductions, தப்பான premise இருக்குற 30 கேள்விகள் ("section 44ADA-ல freelancer GST பத்தின 2025 circular என்ன சொல்லுது?").
2. **Prevention.** Prompt இப்போ, passages-ல இருந்து மட்டும் பதில் சொல்லணும், அவை கேள்வியை cover பண்ணலைன்னா தெளிவா சொல்லணும், ஒவ்வொரு claim-க்கும் section-ஐ cite பண்ணணும்னு சொல்லுது.
3. **ஒவ்வொரு answer-லயும் detection.** ஒரு entailment model ஒவ்வொரு claim-ஐயும் retrieved passages-ஓட check பண்ணுது. ஆதாரமில்லாத claims நீக்கப்படும்; core answer அவற்றை நம்பியிருந்தா, assistant தன்னால பதில் சொல்ல முடியலைன்னு சொல்லி ஒரு chartered accountant-ஐ பரிந்துரைக்கும்.
4. **வாராந்திர review.** ஒரு judge model ஒரு sample-ஐ score பண்ணுது, checks flag பண்ண எல்லாத்தையும் lawyer review பண்றார்.

| 150-கேள்வி set-ல அளவு | முன்னாடி | பின்னாடி |
| --- | --- | --- |
| ஆதாரமில்லாத claim இருக்குற answers | 11% | 2% |

இந்த numbers ஒரு உதாரணத்துக்கு தான். கடைசி row-ல இருக்குற trade-off-ஐ கவனிங்க: கடுமையான checks assistant-ஐ கொஞ்சம் அடிக்கடி மறுக்க வைக்கும். Team ரெண்டு numbers-ஐயும் track பண்றாங்க, ஏன்னா எல்லாத்தையும் மறுக்குற assistant-உம் ஒரு failure தான்.

## பொதுவா பண்ற தப்புகள்

- **Model-க்கு நல்லா தெரிஞ்ச கேள்விகளை மட்டும் test பண்றது.** அரிதான topics, தப்பான premise கேள்விகளை சேருங்க, இல்லன்னா உங்க score உங்களை ஏமாத்தும்.
- **நீளமான answer-க்கு ஒரே verdict.** Claims-ஐ ஒண்ணொண்ணா check பண்ணுங்க; ஒன்பது உண்மையான வாக்கியங்களுக்குள்ள ஒரு கற்பனை figure மறைஞ்சிருக்கலாம்.
- **Citations-ஐ check பண்ணாம நம்புறது.** Cited passage இருக்கா, அது claim-ஐ ஆதரிக்குதான்னு confirm பண்ணுங்க.
- **Source இருக்கும்போது general knowledge-ஓட check பண்றது.** RAG app-ல, retrieved passages-ஓட judge பண்ணுங்க.
- **Hallucinations-ஐ மட்டும் எண்ணுறது.** Refusals-ஐயும் track பண்ணுங்க, அப்போ fixes assistant-ஐ பயனில்லாததா ஆக்காது.
- **பெரிய model இதை சரி பண்ணிடும்னு நினைக்கிறது.** பெரிய models பொதுவான facts-ல குறைவா hallucinate பண்ணும், ஆனா niche, தப்பான premise கேள்விகள்ல இன்னும் கற்பனை பண்ணும்.

## Detection மட்டும் போதாத நேரங்கள்

- **High-stakes answers**, legal, medical, financial advice மாதிரியானவைக்கு, தகுதியான ஒரு ஆள் loop-ல இருக்கணும்.
- **நம்பகமான source எதுவும் இல்லை.** Facts என்னன்னே உங்களால சொல்ல முடியலைன்னா, எந்த checker-ஆலயும் முடியாது.
- **Real-time voice**-ல claim checks-க்கு நேரமே இருக்காது; அதுக்கு பதிலா, அதை பாதுகாப்பான, script பண்ண topics-க்கு மட்டும் வச்சுக்குங்க.

## Demo-ல இருந்து production-க்கு

- **மலிவான checks-ஐ (citations, entailment) ஒவ்வொரு answer-லயும் ஓட்டுங்க**, விலை அதிகமானவற்றை ஒரு sample-ல மட்டும்.
- **Flag பண்ண ஒவ்வொரு claim-ஐயும் source-ஓட log பண்ணுங்க**, reviewers retrieval-ஐயோ documents-ஐயோ fix பண்ணலாம்.
- **Topic வாரியா hallucination, refusal rates-ஐ track பண்ணுங்க**, model அல்லது prompt update-க்கு அப்புறம் திடீர் மாற்றம் வந்தா alert பண்ணுங்க.
- **உறுதிப்படுத்தப்பட்ட failures-ஐ test set-க்குள்ள போடுங்க**, அவை யாருக்கும் தெரியாம திரும்ப வராது.

## Practice பண்ணுங்க

1. ஏதாவது ஒரு chat assistant-கிட்ட இல்லாத ஒண்ணு பத்தி, உதாரணத்துக்கு ஒரு கற்பனையான government scheme பத்தி, மூணு கேள்விகள் கேளுங்க. எத்தனை தடவை அது கூட சேர்ந்து ஆடுது?
