## இது என்ன

**Synthetic data** என்பது உண்மையான மக்கள்கிட்ட இருந்து சேகரிக்காம, ஒரு model அல்லது program உருவாக்கின data. நீங்க ஒரு பெரிய model-கிட்ட 5,000 customer கேள்விகளை எழுத சொல்லலாம், English examples-ஐ Marathi-க்கு translate பண்ண சொல்லலாம், ஒரு குவியல் support tickets-ஐ label பண்ண சொல்லலாம், இல்ல ஒரு evaluation-க்கு test cases எழுத சொல்லலாம்.

**Distillation** அதோட ஒரு முக்கிய பயன். ஒரு சின்ன **student** model, ஒரு பெரிய **teacher** model-ஐ ஒரு task-ல copy பண்ண train ஆகும், teacher-ஓட answers-ஐ training data-ஆ வச்சு. நோக்கம்: அந்த task-ல teacher-க்கு கிட்டத்துல quality-ஓட, ரொம்ப மலிவான, வேகமான ஒரு model. ஆரம்ப காலத்தோட ஒரு பிரபல உதாரணம் DistilBERT; அது 40% சின்னதாவும் 60% வேகமாவும் இருந்து, தன் teacher-ஓட language-understanding திறமையில கிட்டத்தட்ட 97%-ஐ வச்சிருந்துச்சு.

Teams synthetic data-வை அஞ்சு முக்கிய காரணங்களுக்காக use பண்றாங்க:

- **Quantity.** உண்மையான labelled data சேகரிக்க மெதுவானது, செலவானது. ஒரு model ஒரு மணி நேரத்துல ஆயிரக்கணக்கான examples உருவாக்கும்.
- **Coverage.** அரிதான cases-க்கு வேணும்னே examples உருவாக்கலாம்: வழக்கத்துக்கு மாறான complaints, ரொம்ப நீளமான inputs, tricky edge cases அல்லது testing-க்கான attacks.
- **Quality.** சில நேரம் ஒரு வலுவான model, அவசரப்படுற மனித team-ஐ விட consistent-ஆன labels அல்லது கடினமான கேள்விகளை எழுதும்.
- **Privacy.** Patient files அல்லது insurance claims மாதிரி உண்மையான records use பண்ண முடியாதப்போ, realistic-ஆன கற்பனை records இடத்தை நிரப்பலாம்.
- **Distillation.** ஒரு மலிவான model, செலவான ஒண்ணுல இருந்து ஒரு task-ஐ கத்துக்கலாம்.

## இது எப்படி work ஆகுது

**Generate பண்ற வழிகள்.** பொதுவான methods, எளிமையானதுல இருந்து சிக்கலானது வரை:

1. **Templates, rules.** "I booked [service] on [date] and want a refund" மாதிரி ஒரு template-ஐ values list-ஆல நிரப்புங்க. மலிவு, predictable, ஆனா repetitive.
2. **Paraphrasing.** ஒரு model-கிட்ட ஒரு உண்மையான example-ஐ குடுத்து பல மாற்று வாக்கியங்களை கேளுங்க. "How do I cancel my ticket?" என்பது "I want to cancel my booking", "Ticket cancel kaise karu?" ஆகும். அரிதான classes-ஐ வளர்க்க இது நல்ல வழி.
3. **Translation.** நிறைய data இருக்குற ஒரு மொழியில இருந்து, உதாரணம் English, குறைவா இருக்குற ஒண்ணுக்கு, உதாரணம் Kannada, examples-ஐ translate பண்ணுங்க. **Back-translation**-ஓட quality-ஐ check பண்ணுங்க: result-ஐ வேற model-ஆல திரும்ப English-க்கு translate பண்ணி original-ஓட ஒப்பிடுங்க. ரொம்ப வித்தியாசப்பட்டா அந்த example-ஐ தூக்குங்க.
4. **Labelling.** உண்மையான, label இல்லாத data-வை label பண்ண ஒரு வலுவான model-கிட்ட கேளுங்க. இதுதான் பெரும்பாலும் சிறந்த value, ஏன்னா inputs உண்மையானதா இருக்கும், labels மட்டும் ஒரு model உருவாக்கினது.
5. **Simulation.** ஒரு model ஒரு customer-ஆவும் இன்னொண்ணு support agent-ஆவும் நடிச்சு, training அல்லது testing-க்கு முழு conversations-ஐ உருவாக்கும்.
6. **Instruction generation.** கையால எழுதின சின்ன tasks தொகுப்புல இருந்து ஆரம்பிச்சு, அதே style-ல புது tasks-ஐயும் answers-ஐயும் கண்டுபிடிக்க ஒரு model-கிட்ட கேளுங்க. பல ஆரம்ப open instruction datasets இப்படித்தான் build ஆச்சு.

**Train பண்றதுக்கு முன்னாடி verify பண்ணுங்க.** Model உருவாக்கின data-ல தப்புகள் இருக்கும், அதனால filtering optional இல்ல.

- **முடிஞ்சா run பண்ணுங்க.** Code-ஐ tests-க்கு எதிரா execute பண்ணலாம், SQL-ஐ ஒரு sample database-ல run பண்ணலாம். Run பண்ணி check பண்ணக்கூடிய data தான் generate பண்றதுக்கு பாதுகாப்பானது; அதனால தான் code, synthetic data-வோட மிக பொதுவான வகைகள்ல ஒண்ணு.
- **ஒரு judge use பண்ணுங்க.** ஒரு LLM judge ஒவ்வொரு example-ஐயும் எழுதின quality rules-க்கு எதிரா score பண்ணலாம், அல்லது topic-க்கு சம்பந்தமில்லாத அல்லது கற்பனை facts இருக்குறவற்றை flag பண்ணலாம்.
- **எளிய filters போடுங்க.** Exact, near duplicates-ஐ நீக்குங்க; ரொம்ப குறுகிய அல்லது நீளமான examples; output input-ஐ repeat பண்றவை; ஒரே கேள்விக்கு முரண்பட்ட answers இருக்குறவை.
- **ஒரு sample-ஐ நீங்களே படிங்க.** 100 random examples-ஐ படிக்க முப்பது நிமிஷம், எந்த filter-உம் பிடிக்காத பிரச்சனைகளை பிடிக்கும்.

ஒரு சின்ன filter script அடிப்படைகளை cover பண்ணும்:

```python
import json
from difflib import SequenceMatcher

def keep(ex, seen):
    q, a = ex["input"].strip(), ex["output"].strip()
    if not (5 <= len(q.split()) <= 120):        # too short or too long
        return False
    if a.lower() == q.lower() or q.lower() in a.lower():  # output repeats the input
        return False
    for s in seen[-500:]:                        # near-duplicate of a recent example
        if SequenceMatcher(None, q.lower(), s).ratio() > 0.9:
            return False
    seen.append(q.lower())
    return True

seen, kept = [], []
for line in open("generated.jsonl"):
    ex = json.loads(line)
    if keep(ex, seen):
        kept.append(ex)
print(f"kept {len(kept)} examples")
```

**ஒரு task-ஐ distil பண்றது.** உங்க task-ல இருந்து ஒரு பெரிய உண்மையான inputs தொகுப்புல teacher-ஐ run பண்ணுங்க, அதோட answers-ஐ (filter பண்ணின பிறகு) வச்சுக்கோங்க, அந்த pairs-ல ஒரு சின்ன model-ஐ fine-tune பண்ணுங்க. Student-ஐ அது பார்க்காத, கையால label பண்ணின உண்மையான data-ல test பண்ணி, அதே test-ல teacher-ஓட ஒப்பிடுங்க.

| Method | எதுக்கு நல்லது | முக்கிய risk |
| --- | --- | --- |
| Templates, rules | எளிய formats, விரைவான test cases | Repetitive, realistic இல்லாத text |
| Paraphrasing | அரிதான classes-ஐ வளர்க்க, மாறுபட்ட wording | Users உண்மையில எப்படி எழுதுறாங்களோ அதுல இருந்து விலகும் |
| Back-translation-ஓட translation | English-ல இருந்து இந்திய மொழி data | Users பேசாத, விறைப்பான, formal மொழி |
| உண்மையான inputs-ஐ model label பண்றது | Classification, extraction | Teacher-ஓட தப்புகள் student-ஓட தப்புகளாகும் |
| Simulation | Multi-turn conversations, agent testing | ரெண்டு பக்கமும் ஒரு model மாதிரியே ஒலிக்கும் |
| Distillation | ஒரு task-க்கு மலிவான, வேகமான model | திறமை இல்லாம style-ஐ copy பண்ணும் |

## ஒரு worked example

Gurugram-ல ஒரு travel company, மாசம் 50,000 support messages-ஐ refund, date change, baggage மாதிரி 20 intents-ஆ பிரிக்குது. ஒரு பெரிய model, கையால label பண்ணின 500 messages-ல 94% accuracy-ல பண்ணுது, ஆனா மாசம் ₹1.2 lakh செலவு.

20,000 உண்மையான பழைய messages-ஐ எடுத்து, பெயர்கள், phone numbers, booking IDs-ஐ mask பண்ணி, பெரிய model-ஆல label பண்ண வைக்கிறாங்க. ஒரு support lead 300 labels-ஐ check பண்ணி 93% சரின்னு கண்டுபிடிக்குறாங்க; பெரும்பாலான தப்புகள், guide மோசமா விவரிச்ச ரெண்டு intents-ல. Guide-ஐ சரிபண்ணி, அந்த ரெண்டு intents-ஐ மறுபடி label பண்ணி, மறுபடி check பண்றாங்க.

Visa refund உட்பட மூணு intents-க்கு ஒவ்வொண்ணுக்கும் 30-க்கும் குறைவான உண்மையான examples தான். இவற்றுக்கு, பெரிய model-ஐ ஒவ்வொரு உண்மையான example-ஐயும் English, Hindi, Hinglish-ல அஞ்சு விதமா paraphrase பண்ண சொல்லி, duplicates-ஐ filter பண்ணி, ஒரு sample-ஐ ஒரு நபர் check பண்றாங்க. இறுதி 21,500-ல synthetic examples கிட்டத்தட்ட 10%.

Labelled set-ல ஒரு சின்ன open-weight model-ஐ fine-tune பண்ணி, training-ல ஒருபோதும் use பண்ணாத original 500 messages-ல test பண்றாங்க.

| Option | 500 உண்மையான messages-ல accuracy | பலவீனமான intent | மாசாந்திர செலவு |
| --- | --- | --- | --- |
| Large model, prompt பண்ணினது | 94% | 85% (visa refund) | ₹1.2 lakh |
| Small model, உண்மையான labels மட்டும் | 90% | 52% (visa refund) | ₹9,000 |
| Small model, உண்மையான labels + synthetic அரிதான intents | 93% | 81% (visa refund) | ₹9,000 |

Numbers உதாரணத்துக்கு, எப்படி ஒப்பிடுறதுன்னு காட்ட. Synthetic examples முக்கியமா அரிதான intents-க்கு உதவுச்சு. சின்ன model-க்கு உறுதி இல்லாத messages-க்கு fallback-ஆ பெரிய model-ஐ team வச்சுக்குது, ஒவ்வொரு மாசமும் கையால check பண்ணின புது உண்மையான messages sample-ஐ training set-ல சேருது.

## பொதுவா பண்ற தப்புகள்

- **Check பண்ணாத output-ல train பண்றது.** Garbage in, garbage out. Filter பண்ணுங்க, verify பண்ணுங்க, ஒரு sample-ஐ படிங்க.
- **Synthetic data-ல test பண்றது.** இறுதி test, training-ல ஒருபோதும் use ஆகாத உண்மையான data-வா இருக்கணும். இல்லன்னா, student users-க்கு எவ்வளவு நல்லா சேவை பண்ணுதுங்கிறதை இல்ல, teacher-ஐ எவ்வளவு நல்லா copy பண்ணுதுங்கிறதை அளக்குறீங்க.
- **முழுக்க synthetic போறது.** Models-ஐ திரும்ப திரும்ப model உருவாக்கின data-ல train பண்றது **model collapse**-க்கு வழிவகுக்கும்: அரிதான cases மங்கி, தப்புகள் குவியும். Mix-ல உண்மையான data-வை வச்சுக்கோங்க.
- **Student teacher-ஐ மிஞ்சும்னு எதிர்பார்க்குறது.** Distil பண்ணின model அந்த task-ல தன் teacher-ஐ அரிதாத்தான் மிஞ்சும். Teacher பலவீனமா இருந்தா, முதல்ல அதை சரிபண்ணுங்க.
- **Terms of use-ஐ புறக்கணிக்குறது.** பல providers, தங்க outputs-ஐ போட்டி models-ஐ train பண்ண use பண்றதை அனுமதிக்குறதில்ல. Terms-ஐ படிங்க, எந்த model எந்த data-வை உருவாக்குச்சுன்னு பதிவு பண்ணுங்க.
- **Data எங்கிருந்து வந்துச்சுன்னு track இழக்குறது.** Teacher ஒரு benchmark-ல train ஆகியிருந்தா, அதுல உங்க student-ஓட score contaminate ஆகியிருக்கலாம்.

## Model உருவாக்கின data-ஓட limits

- **திறமை இல்லாம style.** வலுவான models-ஐ copy பண்ண train பண்ணின models பத்தின research, அவை style-ஐ நல்லா copy பண்ணுச்சு, ஆனா facts-லயும் புது tasks-லயும் பலவீனமா இருந்துச்சுன்னு கண்டுபிடிச்சது. தன்னால தீர்க்க முடியாத solutions-ல train ஆகுற ஒரு student, நம்பிக்கையான, தப்பான answers தர கத்துக்கலாம்.
- **Bias பெருகுறது.** Teacher சில answers-ஐ விரும்பினா, student அந்த bias-ஐ கத்துக்கும், சில நேரம் இன்னும் வலுவா.
- **தெரியாத lineage.** Model உருவாக்கின data, அறிவு எங்கிருந்து வந்துச்சுன்னு மறைக்குது; teacher-ஓட training data-ல இருக்கக்கூடிய copyright பிரச்சனைகள் உட்பட.
- **Realistic இல்லாத மொழி.** Generate பண்ணின Hindi, மக்கள் WhatsApp-ல உண்மையில எப்படி எழுதுறாங்களோ அதை விட பெரும்பாலும் formal-ஆ இருக்கும். உண்மையான seed examples அதை நிலத்துல வச்சிருக்கும்.

2. மேல இருக்குற filter script-ஐ நீங்க generate பண்ணின set-ல run பண்ணி, எத்தனை examples-ஐ ஏன் நீக்குச்சுன்னு குறிச்சுக்கோங்க.
3. Task-ஐ distil பண்றதுக்கு ஒரு சின்ன plan எழுதுங்க: teacher, inputs எண்ணிக்கை, labels-ஐ எப்படி check பண்ணுவீங்க, use பண்ற உண்மையான test set.
