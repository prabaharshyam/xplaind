## இது என்ன

**KPI** (key performance indicator) project வேலை செஞ்சுதான்னு சொல்ற number. ஒரு AI deployment-க்கு பொதுவா இவை வேணும்:

- **ஒரு primary KPI**, business result-ஓட இணைஞ்சது: ஒரு loan file-க்கு minutes, first-response time, ஒரு officer-க்கு ஒரு நாளைக்கு process பண்ண claims, தீர்க்கப்பட்ட ஒரு ticket-க்கு cost.
- **ஒரு baseline**: உங்க system வர்றதுக்கு முன்னாடி, அதே conditions-ல அளந்த KPI.
- **ஒரு target, ஒரு தேதி**: "pilot தொடங்கி எட்டு வாரத்துக்குள்ள ஒரு file-க்கு 40-ல இருந்து 20 minutes".
- **Guardrail measures**: மோசமாகக்கூடாத விஷயங்கள், error rate, customer complaints, compliance exceptions மாதிரி.
- **Adoption**: மக்கள் உண்மையில system-ஐ use பண்றாங்களான்னு, ஏன்னா யாரும் use பண்ணாத tool KPI-ஐ நகர்த்த முடியாது.

Accuracy, faithfulness மாதிரி model metrics inputs, KPI இல்ல. யாரோட நேரத்தையும் மிச்சப்படுத்தாத 95%-accurate extractor ஒரு தோல்வி.

| KPI plan, scope of work-ல கையெழுத்து போட்டது | |
|---|---|
| **Primary** | ஒரு loan file-க்கு officer-ஓட median minutes |
| **Baseline** | 41 min (loan-system timestamps, 4 வாரம், 6,200 files) |
| **Target** | Pilot தொடங்கி 10 வாரத்துக்குள்ள 22 min |
| **Guardrails** | Rework அதிகபட்சம் 7%; audit policy exceptions-ல உயர்வு இல்ல |
| **Adoption** | Officers தங்க files-ல குறைஞ்சது 80%-ல draft-ஐ use பண்ணுறாங்க |

## இது எப்படி work ஆகுது

**Problem statement-ல இருந்து தொடங்குங்க.** Discovery-ல officers ஒரு file-க்கு 40 minutes செலவழிக்கிறாங்கன்னு தெரிஞ்சா, KPI ஒரு file-க்கு நேரம், "AI accuracy" இல்ல.

**உங்களுக்கு கிடைக்குற data-ல இருந்து அளக்கக்கூடியதா ஆக்குங்க.** Surveys-ஐ விட, systems ஏற்கனவே record பண்ற numbers-ஐ (loan system-ல timestamps, ticket close times) விரும்புங்க. எதுவும் record பண்ணலன்னா, முதல்ல measurement-ஐ set up பண்ணுங்க: சில cases-ஓட start, end times-க்கு ஒரு simple log.

**Baseline-ஐ சரியா அளங்க.** அதே team, அதே மாதிரி cases, போதுமான volume (சில நூறு cases அல்லது ரெண்டுல இருந்து நாலு வாரம்). Seasonal effects-ஐ கவனிங்க: month-end நெரிசல் வழக்கமானது இல்ல.

**Guardrails-ஐ யோசிச்சு தேர்ந்தெடுங்க.** அதிக errors-ஓட வேகமான processing வெற்றி இல்ல. Client-ஓட risk owners-க்கு முக்கியமான ஒண்ணு ரெண்டு quality measures-ஐ எடுங்க.

**எழுத்துல ஒத்துக்கோங்க.** KPI, baseline method, target, guardrails, measurement period-ஐ scope of work-ல போடுங்க, business owner sign off பண்ணணும்.

**நியாயமா ஒப்பிடுங்க.** Pilot-ஓட போது, system உள்ள users-ஐ, அதே காலத்துல system இல்லாத ஒரே மாதிரி users-ஓட ஒப்பிடுங்க, அல்லது அதே users-ஐ முன்னாடி, பின்னாடி ஒப்பிடுங்க, தெளிவா தெரியுற வித்தியாசங்களை சரி பண்ணி.

**தொடர்ந்து report பண்ணுங்க.** வாராந்திர ஒரு-line update ("இந்த வாரம் ஒரு file-க்கு median 26 minutes, 41-ல இருந்து குறைஞ்சிருக்கு; rework 5.8%, baseline 7%; 82% officers active") எல்லாரையும் ஒரே பக்கத்துல வச்சிருக்கும்.

**Inputs vs outcomes:**

| Input (model அல்லது system) | Outcome (business) |
| --- | --- |
| Extraction accuracy | ஒரு loan file-க்கு minutes |
| Retrieval recall | ஒரு policy கேள்விக்கு பதில் சொல்ற நேரம் |
| Faithfulness score | Rework அல்லது complaint rate |
| Latency | ஒரு agent ஒரு மணி நேரத்துல handle பண்ற calls |
| Uptime | ஒரு நாளைக்கு process ஆகுற claims |

**நியாயமான ஒப்பீடுகள்.** முடிஞ்சா, pilot users-ஐ இன்னும் system use பண்ணாத ஒத்த users-ஓட, அதே வாரங்கள்ல ஒப்பிடுங்க, அப்போ month-end நெரிசல் மாதிரி seasonal மாற்றங்கள் ரெண்டு groups-ஐயும் பாதிக்கும். எல்லாருக்கும் tool ஒரே நேரத்துல கிடைச்சா, அதே users-ஐ முன்னாடி, பின்னாடி ஒப்பிடுங்க, வேற என்ன மாறிச்சுன்னும் (புது policy, staffing மாதிரி) குறிச்சு வைங்க. Pilot தொடங்குறதுக்கு முன்னாடியே இந்த method-ஐ measurement plan-ல எழுதிடுங்க, அப்போ பின்னாடி யாரும் தங்களுக்கு சாதகமான ஒப்பீட்டை தேர்ந்தெடுக்க முடியாது.

**வாராந்திர line.** KPI, guardrail, adoption-ஓட ஒரு வாக்கியம், ஒவ்வொரு வாரமும் அனுப்புங்க: "இந்த வாரம் ஒரு file-க்கு median 26 minutes, 41-ல இருந்து குறைஞ்சிருக்கு; rework 5.8%, baseline 7%; 82% officers active." இது business owner-ஐ தெரிஞ்சுக்கிட்டே வச்சிருக்கும், கடைசி review-ஐ ஒரு சம்பிரதாயமா ஆக்கும், ஏன்னா யாருக்கும் எந்த ஆச்சரியமும் இருக்காது.

## ஒரு worked example

Chennai lender-ஓட discovery-க்கு அப்புறம், நீங்க propose பண்றது:

- **Primary KPI**: file-ஐ திறக்குறதுல இருந்து credit note submit பண்றவரை ஒரு loan file-க்கு officer-ஓட median நேரம்.
- **Baseline**: pilot-க்கு முன்னாடி நாலு வாரத்துக்கு loan system-ஓட timestamps-ல இருந்து அளந்தது: 41 minutes median, 6,200 files.
- **Target**: 20 pilot officers-க்கு, pilot தொடங்கி பத்து வாரத்துக்குள்ள 22 minutes median.
- **Guardrails**: credit committee rework rate (baseline 7%) கூடக்கூடாது; audit flag பண்ற policy exceptions-ல உயர்வு இல்ல.
- **Adoption**: தங்க files-ல குறைஞ்சது 80%-ல draft summary-ஐ use பண்ற pilot officers-ஓட பங்கு.

Operations head முதல்ல "90% AI accuracy"-ஐ target-ஆ கேக்குறாரு. Accuracy ஒரு quality input-ஆ track ஆகும், ஆனா lender-ஓட business result officer நேரமும் rework-உம்ன்னு விளக்கி, ரெண்டுலயும் ஒத்துக்குறீங்க. பத்து வாரத்துக்கு அப்புறம் pilot காட்டுறது: 24 minutes median, 5.1% rework, 88% adoption. நேரத்துல target கொஞ்சம் தவறிச்சு, ஆனா quality-ல தாண்டிடுச்சு; measures முன்னாடியே ஒத்துக்கிட்டதால, பேச்சு rollout பத்தி, வெற்றின்னா என்னன்னு பத்தி இல்ல.

| Measure | Baseline | Target | Pilot result |
| --- | --- | --- | --- |
| ஒரு file-க்கு median minutes | 41 | 22 | 24 |
| Rework rate | 7% | 7%-க்கு மேல இல்ல | 5.1% |
| Adoption | பொருந்தாது | 80% files | 88% |
| முடிவுல பேச்சு | | | Rollout பத்தி, வெற்றின்னா என்னன்னு பத்தி இல்ல |

## பொதுவா பண்ற தப்புகள்

- **Model metrics-ஐ KPI-ஆ வைக்கிறது.** Accuracy ஒரு வழி; business-ல நேரம், cost அல்லது errors தான் இலக்கு.
- **Baseline இல்லாம இருக்குறது.** "Officers-க்கு வேகமா இருக்குற மாதிரி தோணுது"ங்கிறது budget review-ல நிக்காது.
- **ரொம்ப KPIs.** பத்து numbers, எது முக்கியம்ன்னு யாருக்கும் தெரியாது. ஒரு primary, சில guardrails.
- **Launch-க்கு அப்புறம் மட்டும் அளக்குறது.** System நடத்தையை மாத்துறதுக்கு முன்னாடியே baseline எடுக்கணும்.
- **Adoption-ஐ கண்டுக்காம விடுறது.** "AI உதவல"ன்னு வர்ற பெரும்பாலான results-க்கு குறைவான usage தான் காரணம்.

## Practice பண்ணுங்க

GOV.UK-ஓட measuring success guide-ஐ படிங்க.

1. உங்க discovery exercise-ஓட use case-க்கு, ஒரு primary KPI, ஒரு baseline method, தேதியோட ஒரு target, ரெண்டு guardrails, ஒரு adoption measure எழுதுங்க.
2. ஒவ்வொரு number-ம் எங்க இருந்து வரும், யார் report பண்ணுவாங்கன்னு சரியா விவரிங்க.
3. Pilot-ஓட நாலாவது வாரத்துல நீங்க அனுப்பப்போற ஒரு-line weekly update-ஐ draft பண்ணுங்க.

**நீங்க முடிச்சாச்சு, எப்போன்னா** accuracy ஏன் KPI இல்லைன்னு ஒரு client-க்கு explain பண்ணவும், அவங்க கையெழுத்து போடக்கூடிய ஒரு measurement plan-ஐ காட்டவும் முடியும்.
