## இது என்ன

Fine-tuning lessons, fine-tuning என்ன மாத்துதுன்னும், LoRA memory-ஐ எப்படி மிச்சப்படுத்துதுன்னும் சொல்லுது. இந்த lesson ஒண்ணை நல்லா run பண்றது பத்தி: ஆரம்பத்துல நீங்க எடுக்குற தேர்வுகள், ரொம்ப முக்கியமான சில settings, அது work ஆகுதான்னு loss curves-ல இருந்து எப்படி தெரிஞ்சுக்கிறது.

ஒவ்வொரு fine-tune-உம் மூணு தேர்வுகளோட ஆரம்பிக்குது:

1. **ஒரு base model.** Task சாத்தியமான்னு முதல்ல test பண்ண, உங்களால afford பண்ண முடிஞ்ச strongest model-ஐ use பண்ணுங்க: அது task-ஐ கத்துக்க முடியலைன்னா, பலவீனமானவை கத்துக்காது. அப்புறம் cost குறைக்க சின்ன models-ஐ try பண்ணுங்க.
2. **ஒரு method.** **LoRA** அல்லது வேற ஒரு light method-ல ஆரம்பிங்க. இதுக்கு memory-உம் data-வும் குறைவா போதும், serve பண்ணும்போது பல adapters ஒரே base model-ஐ share பண்ணலாம். ஆயிரக்கணக்கான examples அல்லது அதுக்கு மேல இருந்து, LoRA போதலைன்னா, அப்புறம் full fine-tuning try பண்ணுங்க.
3. **ஒரு tool.** எளிமையானது provider-ஓட fine-tuning service: data upload பண்ணுங்க, ஒரு model திரும்ப கிடைக்கும்; ஆனா settings கொஞ்சம் தான், அவங்க models மட்டும் தான். Hugging Face TRL, PEFT, Unsloth, Axolotl, LLaMA-Factory, LitGPT மாதிரி open-source frameworks உங்க சொந்த GPUs-ல run ஆகி, எல்லா settings-ஐயும் கொடுக்கும்.

ரெண்டு பொதுவான development paths:

- **Progression path.** Code-ஐ cheap-ஆன model-ல test பண்ணுங்க, data-வை ஒரு நடுத்தர model-ல test பண்ணுங்க, quality-ஐ best model-ல உயர்த்துங்க, அப்புறம் சிறந்த price, performance கண்டுபிடிக்க பல sizes-ஐ ஒப்பிடுங்க.
- **Distillation path.** ஒரு strong model-ஐ ஒரு சின்ன, சிறப்பான dataset-ல fine-tune பண்ணி, அதை வச்சு இன்னும் training data generate பண்ணி, அப்புறம் அதுல ஒரு cheap-ஆன model-ஐ train பண்ணுங்க.

## இது எப்படி work ஆகுது

**Learning rate**-னா weights update ஆகும்போது ஒவ்வொரு step-ஓட size. ஒரு run-ஐ ஜெயிக்க வைக்கவோ உடைக்கவோ அதிக வாய்ப்புள்ள setting இதுதான்.

- ரொம்ப அதிகம்: loss துள்ளும் அல்லது மேல பாயும், outputs அர்த்தமில்லாம போகலாம்.
- ரொம்ப குறைவு: loss கொஞ்சமாதான் குறையும், model கிட்டத்தட்ட மாறாது.
- பயனுள்ள values ரொம்ப பரந்தவை, சுமார் 1e-7 முதல் 1e-3 வரை. LoRA runs பொதுவா 1e-4 முதல் 2e-4 around ஆரம்பிக்கும்; full fine-tuning ரொம்ப சின்ன values use பண்ணும், பெரும்பாலும் pre-training முடிவுல use பண்ண rate-ஓட பத்துல ஒரு பங்கு அல்லது அதுக்கும் குறைவு.
- ஒரு **schedule** பெரும்பாலும் கொஞ்ச நேரம் warm up ஆகி, அப்புறம் கடைசியை நோக்கி rate-ஐ குறைக்கும்.

**Batch size**-னா ஒவ்வொரு update-உம் எத்தனை examples-ல இருந்து கத்துக்குதுன்னு. ரொம்ப சின்ன batches (சுமார் 8-க்கு கீழ) training-ஐ unstable ஆக்கலாம்; பெரிய batches சீரான updates கொடுக்கும், ஆனா அதிக memory வேணும். Memory இறுக்கமா இருக்கும்போது, **gradient accumulation** ஒவ்வொரு update-க்கு முன்னாடியும் பல சின்ன batches-ஐ கூட்டி, memory இல்லாமலே பெரிய batch-ஓட stability-ஐ கொடுக்கும்.

**Epochs**-னா training data மேல முழு passes. ரொம்ப பெரிய datasets-க்கு ஒண்ணு ரெண்டு போதும்; சில ஆயிரம் examples பல epochs-க்கு improve ஆகிட்டே இருக்கலாம். Validation loss-ஐ முடிவு பண்ண விடுங்க: அது குறையுற வரை training தொடருங்க, ஏற ஆரம்பிச்சா நிறுத்துங்க.

**Prompt loss weight**, ஒவ்வொரு example-லயும் prompt பகுதி எவ்வளவு count ஆகணும்னு control பண்ணுது. Inference-ல user prompt-ஐ எழுதுவாங்க, model response-ஐ எழுதும். அதனால பெரும்பாலான setups response-ஐ முழுசா count பண்ணி, prompt-ஐ கொஞ்சமா அல்லது அறவே count பண்ணாது (பல tools default-ஆ prompt-ஐ mask பண்ணும்; சில சுமார் 10% use பண்ணும்).

**Curves-ஐ படிக்கிறது.** ஒவ்வொரு சில டஜன் steps-க்கும் அப்புறம் training loss, validation loss-ஐ plot பண்ணுங்க.

| நீங்க பார்க்கிறது | சாத்தியமான காரணம் | என்ன பண்ணணும் |
| --- | --- | --- |
| Loss spike ஆகுது அல்லது NaN ஆகுது | Learning rate ரொம்ப அதிகம், அல்லது bad data | Rate-ஐ குறைங்க; empty அல்லது ரொம்ப பெரிய examples இருக்கான்னு check பண்ணுங்க |
| ஆரம்பத்துல இருந்தே loss flat | Rate ரொம்ப குறைவு, தப்பான labels, அல்லது தப்பான tokens மேல loss | Rate-ஐ ஏத்துங்க; data format, masking-ஐ check பண்ணுங்க |
| Training குறையுது, validation ஏறுது | Overfitting | குறைவான epochs, அதிக data, முந்தின checkpoint-ஐ வச்சுக்கோங்க |
| முடிவுல ரெண்டும் இன்னும் குறையுது | Undertrained | அதிக epochs அல்லது அதிக data |
| Loss நல்லா இருக்கு, outputs மோசம் | Data தப்பா கத்துக்கொடுக்குது, அல்லது inference-ல prompt format வேற | Examples-ஐ படிங்க; training-லயும் use-லயும் exact chat template-ஐ use பண்ணுங்க |

**நாள் கணக்கான நேரத்தை மிச்சப்படுத்துற பழக்கங்கள்.**

- முழு pipeline-ஐ ஒரு சின்ன model, சில examples-ல **smoke test** பண்ணுங்க: load, train, save, reload, generate.
- **வேணும்னே overfit பண்ணுங்க**: 20 examples-ல, model அவற்றை திரும்ப சொல்ற வரை train பண்ணுங்க. முடியலைன்னா, ஏதோ உடைஞ்சிருக்கு.
- **Checkpoints-ஐ** இருக்குற ஒரு folder-ல save பண்ணுங்க, crash ஆனா மணி நேரம் இல்ல, சில நிமிஷங்கள் தான் இழக்குற அளவுக்கு அடிக்கடி.
- Training-லயும் use-லயும் **ஒரே chat template-ஐ** use பண்ணுங்க. ஒத்துப்போகாதது அமைதியா results-ஐ கெடுக்கும்.
- ஒவ்வொரு run-ஓடவும் **ஒவ்வொரு setting-ஐயும்**, data version-ஐயும் log பண்ணுங்க.

உங்க loss logs-ஐ படிக்க ஒரு சின்ன helper:

```python
def diagnose(train_loss, val_loss):
    """Lists of loss values measured at the same steps."""
    if any(x != x or x > 10 * train_loss[0] for x in train_loss):   # NaN or blow-up
        return "Unstable: lower the learning rate and check for bad examples."
    if train_loss[-1] > 0.95 * train_loss[0]:
        return "Not learning: raise the learning rate or check data and masking."
    best = val_loss.index(min(val_loss))
    if best < len(val_loss) - 1:
        return f"Overfitting after step {best}: keep that checkpoint or use fewer epochs."
    return "Both still falling: more epochs or more data may help."

print(diagnose([2.1, 1.6, 1.2, 0.9, 0.7], [2.0, 1.6, 1.4, 1.5, 1.7]))
```

## ஒரு நாள், ஒரு example

Chennai-ல ஒரு ed-tech company, short answers-ஐ English-லயும் Tamil-லயும் correct, partly correct, wrong-னு ஒரு வரி காரணத்தோட grade பண்ண, ஒரு open 8B model-ஐ LoRA-ல fine-tune பண்றாங்க. அவங்ககிட்ட grade பண்ண 2,400 answers இருக்கு; 300-ஐ locked test set-ஆவும், 200-ஐ validation-க்கும் வச்சிருக்காங்க.

முதல்ல, 20 examples-ஓட 0.5B model-ல ஒரு smoke test: run, saving, reloading எல்லாம் work ஆகுது, model அந்த 20 examples-ஐயும் மனப்பாடம் பண்ணுது. அப்புறம் உண்மையான runs:

| Run | Learning rate | Epochs | Curves என்ன காட்டுச்சு | Test accuracy |
| --- | --- | --- | --- | --- |
| 1 | 2e-3 | 3 | Loss துள்ளி, அப்புறம் வெடிச்சுது; outputs குப்பை | Use பண்ண முடியாது |
| 2 | 1e-6 | 3 | Loss கொஞ்சம் கூட நகரல; outputs base model மாதிரி | 61% |
| 3 | 2e-4 | 3 | Epoch 2 முடிவுல validation best, அப்புறம் ஏறுச்சு | 84% (epoch-2 checkpoint) |
| Prompt-only baseline | பொருந்தாது | பொருந்தாது | பொருந்தாது | 72% |

Numbers புரிய வைக்க மட்டும். Run 3-ஓட epoch-2 checkpoint, prompt baseline-ஐ விட 12 points முன்னாடி இருக்கு. Tamil accuracy, English-ஐ விட 6 points குறைவு; அதனால அடுத்த step இன்னும் Tamil examples சேக்குறது, இன்னும் tuning இல்ல.

## பொதுவா பண்ற தப்புகள்

- **ஒரு பெரிய model-ல full fine-tune-ல ஆரம்பிக்கிறது.** முதல்ல LoRA-ல task-ஐ prove பண்ணுங்க.
- **Smoke test-ஐ skip பண்றது.** Save path-ல ஒரு typo, ஒரு இரவு training-ஐ வீணாக்கிடும்.
- **Training loss-ஐ மட்டும் வச்சு judge பண்றது.** Validation, test results தான் உண்மையான learning-ஐ காட்டும்.
- **எல்லா epochs-ஐயும் கண்ணை மூடிட்டு use பண்றது.** Validation best-ஆ இருந்த checkpoint-ஐ வச்சுக்கோங்க.
- **ஒரே நேரத்துல நிறைய settings-ஐ மாத்துறது.** ஒண்ணை மாத்தி, ஒப்பிட்டு, அப்புறம் அடுத்ததை மாத்துங்க.
- **Production-ல வேற prompt format.** Model ஒரு template-ஐ கத்துக்கிட்டுச்சு; அதுக்கு அதே template-ஐ கொடுங்க.

## எப்போ settings-ஐ tune பண்றதை நிறுத்தலாம்

- **நியாயமான settings முழுக்க validation results stable-ஆ இருக்கு.** இனி வர்ற gains data-ல இருந்து வரும், knobs-ல இருந்து இல்ல.
- **ஒரு segment பின்தங்குது**, உதாரணமா ஒரு மொழி அல்லது ஒரு question type: அதுக்கு examples சேருங்க.
- **Prompt baseline கிட்ட இருக்கு.** Fine-tuning ஒண்ணு ரெண்டு points-ல தான் ஜெயிக்குதுன்னா, அதை maintain பண்ற செலவு தகுதியா இல்லாம போகலாம்.

## Demo-ல இருந்து production-க்கு

- **ஒவ்வொரு run-ஐயும் record பண்ணுங்க**: data version, base model, method, ஒவ்வொரு setting, curves, test scores.
- **Best checkpoint-ஐயும் அதோட exact template-ஐயும் வச்சுக்கோங்க**, deploy பண்ண model-ஐ அதே test set-ல test பண்ணுங்க.
- **Base model அல்லது data மாறும்போது recipe-ஐ திரும்ப run பண்ணுங்க**; record பண்ண recipe அதை routine ஆக்கும்.
- **Launch-க்கு அப்புறம் monitor பண்ணுங்க**, ஏன்னா உண்மையான inputs training data-ல இருந்து விலகிப் போகும்.
