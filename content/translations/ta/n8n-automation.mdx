## இது என்ன

**n8n** ("n-eight-n"ன்னு சொல்லணும்) ஒரு workflow automation tool. ஒரு visual canvas-ல **nodes**-ஐ connect பண்ணி automations-ஐ build பண்றீங்க. ஒவ்வொரு node-உம் ஒரே வேலையை பண்ணும்: புது email-ஐ கவனிக்கிறது, spreadsheet-ஐ படிக்கிறது, API-ஐ call பண்றது, AI model-ஐ கேக்குறது, message அனுப்புறது. Data ஒரு node-ல இருந்து அடுத்ததுக்கு ஓடுது.

இது Zapier அல்லது Make மாதிரி தான், ஆனா மக்கள் மதிக்கிற ரெண்டு வித்தியாசங்கள் இருக்கு. உங்க சொந்த server-ல **self-host** பண்ணலாம்; அதனால data உங்க கையிலயே இருக்கும், volume-ல செலவும் கம்மி. அதோட strong **AI nodes** இருக்கு: reason பண்ணி, tools-ஐ use பண்ணி, ஒரு conversation-ஐ ஞாபகம் வச்சுக்க முடியுற AI Agent node உட்பட.

**Workflow automation**-னா business-ல இதோட use: ஒரு சின்ன team, ஏற்கனவே use பண்ற apps-க்கு நடுவுல data-வை software நகர்த்த விடுறதால, வாரா வாரம் மணிக்கணக்கான நேரத்தை திரும்ப பெறுது.

```flow
Trigger: form enquiry | ஒரு webhook -> AI Agent | classify பண்ணி reply draft பண்ணும்
Memory: பழைய chats -> AI Agent
Model, prompt, tools -> AI Agent
AI Agent -> Fees பத்தியா?
Fees பத்தியா? -[ஆமா]-> Sheet: log பண்ணு -> Gmail: approval-க்கு ஒரு draft
Fees பத்தியா? -[இல்லை]-> Slack: staff-க்கு alert
```

## இது எப்படி work ஆகுது

**Triggers தான் எல்லாத்தையும் ஆரம்பிக்கும்.** பொதுவானவை: ஒரு schedule (தினமும் காலை 9 மணிக்கு), ஒரு webhook (வேற app ஒரு URL-ஐ call பண்றது), app triggers (புது Gmail message, Google Sheets-ல புது row), chatbots-க்கு ஒரு chat trigger.

**Nodes வேலையை செய்யும்.** n8n-ல நூத்துக்கணக்கான integrations இருக்கு: Google Workspace, Slack, Notion, Airtable, HubSpot, databases, எந்த API-க்கும் HTTP requests, official Business API வழியா WhatsApp. IF, Switch, Merge, Loop மாதிரி **logic nodes** flow-ஐ கட்டுப்படுத்தும்.

**Data JSON-ஆ நகருது.** ஒவ்வொரு node-உம் items-ஐ output பண்ணும். அடுத்த nodes அவற்றை `{{ $json.email }}` மாதிரி **expressions** வச்சு படிக்கும். ஒவ்வொரு step-லயும் exact data-வை பார்க்கலாம்; அதனால code-ல விட debugging ரொம்ப ஈஸி.

**AI nodes.** AI Agent node ஒரு chat model (Claude, GPT, Gemini, இல்லன்னா ஒரு local model), ஒரு system prompt, **memory**, **tools**-ஐ சேர்க்குது. Tools "இந்த sheet-ஐ search பண்ணு" அல்லது "ஒரு calendar event உருவாக்கு" மாதிரி மத்த nodes-ஆ இருக்கலாம்; அதனால agent பேசுறதோட நிக்காம, செயலும் பண்ணும். Text-ஐ classify பண்ண, fields-ஐ structured data-வா extract பண்ண, summarise பண்ண எளிமையான nodes-உம் இருக்கு.

**Credentials** ஒரு தடவை store ஆகி, திரும்ப use ஆகும்; அதனால API keys workflows-குள்ள இருக்காது.

**ஓட்டுறது.** Quick-ஆ start பண்ண n8n Cloud-ஐ use பண்ணுங்க, இல்லன்னா ஒரு சின்ன server-ல Docker-ஓட self-host பண்ணுங்க. Sample data-வோட test பண்ணி, அப்புறம் workflow-ஐ activate பண்ணுங்க; அது தானா ஓடும்.

| Building block | எதுக்கு | உதாரணம் |
|---|---|---|
| Schedule trigger | set நேரங்கள்ல ஓட | காலை 8 மணிக்கு daily sales summary |
| Webhook | வேற app-க்கு உடனே react பண்ண | payment gateway success event |
| HTTP Request | எந்த API-யையும் call பண்ண | exchange rates-ஐ எடுக்க |
| IF / Switch | conditions-ஐ வச்சு branch பண்ண | enquiries-ஐ type படி route பண்ண |
| AI Agent | tools-ஓட reason பண்ணி செயல்பட | price sheet-ஐ வச்சு FAQs-க்கு பதில் சொல்ல |
| Information Extractor | text-ஐ fields-ஆ மாத்த | invoice-ல இருந்து amount, date-ஐ படிக்க |
| Wait / approval | ஒரு மனுஷனுக்காக pause பண்ண | reply அனுப்புறதுக்கு முன்னாடி approve பண்ண |
| Error workflow | failures-ஐ பிடிக்க | run fail ஆனா Slack-ல alert |

**நம்புறதுக்கு முன்னாடி testing.** n8n-ல workflow-ஐ கையால ஓட்டலாம், ஒரு trigger-ல sample data-வை pin பண்ணலாம் (அப்போ ஒவ்வொரு test-உம் அதே input-ஐ use பண்ணும்), ஒவ்வொரு node-ஓட output-ஐயும் step by step பார்க்கலாம். நிஜத்துல வர்ற மாதிரி குழப்பமான data-வோட test பண்ணுங்க: Hinglish-ல ஒரு enquiry, ஒரு empty field, மூணு attachments இருக்குற ஒரு email. பெரும்பாலான automation bugs யாரும் try பண்ணாத inputs-ல இருந்து தான் வரும்.

**கவனிக்க வேண்டிய செலவுகள்.** ஒவ்வொரு AI step-க்கும் ஒரு call-க்கு சின்ன செலவு இருக்கு; n8n Cloud plans மாசத்துக்கு எத்தனை workflow runs கிடைக்கும்ன்னு limit வச்சிருக்கும். ஒரு client-க்கு மாச செலவை சொல்றதுக்கு முன்னாடி, providers-ஓட sites-ல தற்போதைய limits-ஐயும் model prices-ஐயும் check பண்ணுங்க.

## ஒரு நாள், ஒரு example

Arvind Jaipur-ல 600 students இருக்குற ஒரு coaching institute நடத்துறார். Enquiries ஒரு Google Form வழியா எல்லா நேரத்துலயும் வருது; front desk அடுத்த நாள் தான் reply பண்ணுது, அதுக்குள்ள நிறைய parents ஒரு competitor-ஐ call பண்ணிடுறாங்க.

அவர் ஒரு மத்தியானத்துல ஒரு workflow-ஐ build பண்றார்:

1. ஒவ்வொரு புது enquiry-லயும் **Google Forms trigger**.
2. Batch timings, fees, demo-class schedule இருக்குற prompt-ஓட **AI Agent**. அது enquiry-ஐ fees, timings, demo, அல்லது other-ன்னு classify பண்ணி, parent பயன்படுத்துன மொழியில, Hindi அல்லது English-ல, ஒரு reply draft பண்ணும்.
3. **IF node:** demo requests நேரா ஒரு Google Calendar tool-க்கு போய், அடுத்த free slot-ஐ book பண்ணும்.
4. **Google Sheets** ஒவ்வொரு enquiry-ஐயும், அதோட category-யையும், draft-ஐயும் log பண்ணும்.
5. **Gmail** ஒரு draft-ஐ உருவாக்கும், அனுப்புன mail இல்லை. Front-desk manager அதை தன் phone-ல இருந்து approve பண்றாங்க.

முதல் மாசத்துல, median reply time 14 மணி நேரத்துல இருந்து 25 நிமிஷமா குறையுது, demo bookings மூணுல ஒரு பங்கு கூடுது. ரெண்டு வாரம் கிட்டத்தட்ட edits இல்லாம drafts-ஐ approve பண்ணதுக்கு அப்புறம், Arvind "timings" category-ஐ தானா அனுப்ப விடுறார்; தப்பு costly-ஆ இருக்குற fees-க்கு approval-ஐ வச்சுக்கிறார்.

ஒரு ராத்திரி Sheets API கொஞ்ச நேரம் fail ஆகுறப்போ, அவரோட error workflow ஒரு Slack alert அனுப்புது, run திரும்ப try ஆகுது; அதனால எந்த enquiry-யும் தொலையல.

## பொதுவா பண்ற தப்புகள்

**குழப்பமான process-ஐ automate பண்றது.** Steps-ஐ முதல்ல எழுதி எளிமையாக்குங்க; automation ஒரு மோசமான process-ஐ இன்னும் வேகமா fail ஆக்கும்.

**ஆரம்பத்துலயே review இல்லாம AI-ஐ அனுப்ப விடுறது.** Drafts, human approval-ஓட ஆரம்பிங்க. நல்ல output-ஓட நீண்ட track record இருக்குற categories-க்கு மட்டும் approval-ஐ எடுங்க.

**Error handling இல்லாம இருக்குறது.** APIs fail ஆகும். Retries, ஒரு error workflow, alerts சேருங்க; இல்லன்னா failures வாரக்கணக்கா கவனிக்கப்படாம போகும்.

**Keys, values-ஐ code-குள்ளயே எழுதுறது.** Keys-க்கு credentials-ஐயும், மாறுற prices மாதிரி values-க்கு ஒரு settings node அல்லது sheet-ஐயும் use பண்ணுங்க.

**ஒரு பெரிய workflow.** பெரிய automations-ஐ ஒண்ணை ஒண்ணு call பண்ற சின்ன workflows-ஆ பிரிங்க. Test பண்ணவும் fix பண்ணவும் ஈஸி.

**Data protection-ஐ கவனிக்காம விடுறது.** Prompts, logs-ல இருக்குற customer data personal data. தேவையானதை மட்டும் collect பண்ணுங்க, ஒவ்வொரு service-உம் எங்க store பண்ணுதுன்னு தெரிஞ்சுக்கோங்க.
