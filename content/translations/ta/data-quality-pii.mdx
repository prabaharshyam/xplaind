## இது என்ன

ஒவ்வொரு AI data pipeline-லயும் இருக்குற, தொடர்புடைய ரெண்டு வேலைகள்:

- **Data quality**: Data-வை index பண்றதுக்கு முன்னாடி அல்லது model-க்கு அனுப்புறதுக்கு முன்னாடி, அது complete, valid, consistent, current-ஆ இருக்கான்னு check பண்றது. விடுபட்ட fields, duplicate records, சாத்தியமில்லாத dates, குழம்பிய text எல்லாமே தப்பான answers-ஆ மாறும்.
- **Personal data handling**: Personal data-வை (names, phone numbers, emails, addresses, Aadhaar, PAN, bank account numbers, health details) கண்டுபிடிச்சு, அது போற ஒவ்வொரு இடத்துக்கும் அதை வச்சுக்கணுமா, mask பண்ணணுமா, pseudonymise பண்ணணுமா, இல்ல நீக்கணுமான்னு முடிவு பண்றது.

```flow
Raw records -> Quality checks
Quality checks -[fail ஆனா]-> Quarantine, block அல்லது warn
Quality checks -[pass ஆனா]-> Personal data-வை கண்டுபிடி | patterns + NER + context words
Personal data-வை கண்டுபிடி -[index-க்கு]-> Permissions வச்சு restrict பண்ணி வச்சுக்கோங்க
Personal data-வை கண்டுபிடி -[external model-க்கு]-> Task-க்கு தேவையில்லாததை mask பண்ணுங்க
Personal data-வை கண்டுபிடி -[logs, traces-க்கு]-> Default-ஆ mask பண்ணுங்க
Personal data-வை கண்டுபிடி -[staging, tests-க்கு]-> Realistic fakes-ஆ மாத்துங்க
```

இந்த lesson-ல Coimbatore-ல ஒரு hospital group, follow-up calls-க்காக discharge-note summariser build பண்றதை follow பண்ணுவோம்.

## இது எப்படி work ஆகுது

**Tests மாதிரி quality checks.** Data பூர்த்தி பண்ண வேண்டிய rules-ஐ எழுதி, ஒவ்வொரு batch-லயும் run பண்ணுங்க:

- தேவையான fields இருக்கணும் (ஒவ்வொரு claim-லயும் policy number-உம் date-உம் இருக்கணும்);
- values valid-ஆ இருக்கணும் (dates எதிர்காலத்துல இல்லை, amounts positive, PIN codes ஆறு digits);
- uniqueness (duplicate invoice numbers இல்லை);
- freshness (புது record ஒரு நாளுக்கு குறைவான பழசு);
- text sanity (parse ஆன pages-ல போதுமான characters இருக்கணும்; குழம்பிய symbols தொடர்ந்து வரக்கூடாது).

Great Expectations மாதிரி libraries அல்லது simple pytest-style checks work ஆகும். ஒவ்வொரு rule-க்கும், fail ஆனா batch-ஐ block பண்ணுமா, மோசமான records-ஐ quarantine பண்ணுமா, இல்ல warn மட்டும் பண்ணுமான்னு முடிவு பண்ணுங்க.

**Personal data-வை கண்டுபிடிக்கிறது.** இவற்றை சேர்த்து use பண்ணுங்க:

- structured identifiers-க்கு *patterns*: இந்திய mobile numbers, emails, PAN (ஐந்து letters, நாலு digits, ஒரு letter), Aadhaar (12 digits, முடிஞ்சா அதோட checksum-ஓட), IFSC codes, GSTINs;
- names, places, organisations-க்கு *named-entity recognition*, Presidio அல்லது spaCy மாதிரி tools-ல இருந்து;
- confidence-ஐ கூட்ட *context words* ("Aadhaar no.", "DOB").

எந்த detector-உம் perfect இல்லை. Real documents-ஓட label பண்ண ஒரு sample-ல அதோட recall-ஐ அளங்க, குறிப்பா இந்திய பெயர்கள், கலந்த மொழி text-ல.

**ஒவ்வொரு flow-க்கும் treatment-ஐ தேர்ந்தெடுக்கிறது.**

- *Index-க்குள்ள*: பெரும்பாலும் வச்சுக்கலாம் (staff-க்கு customer names தேவை), ஆனா permissions வச்சு restrict பண்ணுங்க.
- *External model-க்கு போற prompts-ல*: task-க்கு தேவையானதை மட்டும் அனுப்புங்க; answer-க்கு தேவையில்லாத identifiers-ஐ mask பண்ணுங்க.
- *Logs, traces-ல*: default-ஆ mask பண்ணுங்க.
- *Test, staging data-ல*: realistic fakes-ஆ மாத்துங்க (pseudonymise).

**Reversible masking.** சில tasks-க்கு, model call-க்கு முன்னாடி "Lakshmi Narayanan, 98400 12345"-ஐ "PERSON_1, PHONE_1"-ஆ மாத்தி, அப்புறம் answer-ல நிஜ values-ஐ திரும்ப போடுவீங்க. Model நிஜ data-வை பாக்கவே பாக்காது, ஆனாலும் user-க்கு முழுமையான reply கிடைக்கும்.

**இந்திய identifier patterns, வார்த்தைகள்ல:**

| Identifier | Pattern | Extra check |
| --- | --- | --- |
| Mobile number | 6 முதல் 9 வரை ஆரம்பிக்கிற 10 digits, பெரும்பாலும் +91-ஓட | "mob", "ph" மாதிரி context words |
| PAN | 5 letters, 4 digits, 1 letter | நாலாவது letter holder type-ஐ காட்டும் |
| Aadhaar | 12 digits, பெரும்பாலும் நாலு நாலா groups | Verhoeff checksum |
| IFSC | 4 letters, ஒரு zero, 6 letters அல்லது digits | Bank code list |
| GSTIN | 2-digit state code-ஓட ஆரம்பிக்கிற 15 characters | PAN-ஐ உள்ளடக்கியிருக்கும் |
| PIN code | 6 digits | Valid முதல் digit |

**Masking நடைமுறையில.** Reversible masking, PERSON_1-ல இருந்து நிஜ பெயருக்கான mapping-ஐ, request நடக்குற நேரம் வரைக்கும் memory-ல மட்டும் வச்சிருக்கும். Prompt "PERSON_1 was discharged on..."ன்னு சொல்லும், model "Call PERSON_1 to check..."ன்னு எழுதும், nurse பார்க்கிறதுக்கு முன்னாடி code நிஜ பெயரை திரும்ப போடும். External model-க்கு identity போகவே போகாது, mapping எப்பவும் log ஆகாது.

**Code-ல quality checks.** Fail ஆன rows-ஐ திருப்பி தர்ற simple functions. அதனால ஒவ்வொரு batch-ஐயும் clean, quarantined-ஆ பிரிக்கலாம்:

```python
import re
from datetime import date

RULES = {
    "policy number present": lambda r: bool(r.get("policy_no")),
    "claim date not in future": lambda r: r["claim_date"] <= date.today(),
    "amount positive": lambda r: r["amount_paise"] > 0,
    "PIN code 6 digits": lambda r: bool(re.fullmatch(r"[1-9]\d{5}", r.get("pin", ""))),
    "text long enough": lambda r: len(r.get("text", "")) > 200,
}

def check_batch(rows, unique_key="claim_id"):
    clean, quarantine, seen = [], [], set()
    for r in rows:
        failed = [name for name, ok in RULES.items() if not _safe(ok, r)]
        if r.get(unique_key) in seen:
            failed.append("duplicate id")
        seen.add(r.get(unique_key))
        (quarantine if failed else clean).append({**r, "_failed": failed} if failed else r)
    print(f"{len(clean)} clean, {len(quarantine)} quarantined")
    return clean, quarantine

def _safe(rule, row):
    try:
        return rule(row)
    except (KeyError, TypeError):
        return False
```

ஒவ்வொரு batch-லயும், ஒவ்வொரு rule-க்கும் failures-ஐ எண்ணுங்க. ஒரு rule-ல திடீர்னு பெரிய ஏற்றம் வந்தா, பெரும்பாலும் source-ஓட format மாறிடுச்சுன்னு அர்த்தம், data மோசமாயிடுச்சுன்னு இல்லை.

**Presidio வச்சு personal data-வை detect பண்றது.** Microsoft-ஓட open-source Presidio, patterns, context words, named-entity models-ஐ சேர்த்து use பண்ணும். சமீபத்திய versions-ல PAN, Aadhaar மாதிரி சில இந்திய identifiers-க்கு recognisers இருக்கு; மத்தவைக்கு நீங்களே சேர்த்துக்கோங்க:

```python
from presidio_analyzer import AnalyzerEngine, Pattern, PatternRecognizer

analyzer = AnalyzerEngine()
analyzer.registry.add_recognizer(PatternRecognizer(
    supported_entity="IN_IFSC",
    patterns=[Pattern("ifsc", r"\b[A-Z]{4}0[A-Z0-9]{6}\b", 0.6)],
    context=["ifsc", "branch", "bank"]))

text = "Refund to Lakshmi Narayanan, IFSC HDFC0001234, mobile 9840012345."
for r in analyzer.analyze(text=text, language="en"):
    print(r.entity_type, text[r.start:r.end], round(r.score, 2))
```

**Detector-ஐ type வாரியாவும், மொழி வாரியாவும் அளங்க.** 100 real snippets-ஐ கையால label பண்ணுங்க (labels-க்கு masked copies போதும்), அப்புறம்:

```python
def detector_recall(labelled, detect):
    """labelled: list of (text, set of (start, end, type)); detect returns the same shape."""
    found = total = 0
    for text, gold in labelled:
        hits = detect(text)
        total += len(gold)
        found += sum(any(abs(s - hs) < 3 and abs(e - he) < 3 for hs, he, _ in hits) for s, e, _ in gold)
    return found / total if total else 1.0
```

இந்திய பெயர்கள், transliterate பண்ண text, கலந்த scripts இங்க தான் detectors அதிகம் miss பண்ணும்; அவற்றுக்கு recall-ஐ தனியா report பண்ணுங்க.

**Staging-க்கு fake data.** Production data-வை staging-க்கு ஒருபோதும் copy பண்ணாதீங்க. அதை generate பண்ணுங்க:

```python
from faker import Faker
fake = Faker("en_IN")
print(fake.name(), fake.phone_number(), fake.address())
```

அதே shapes, edge cases-ஐ (நீளமான பெயர்கள், விடுபட்ட fields, Hindi text) வச்சிருங்க. அப்போ production-ல வர்ற bugs-ஐ staging பிடிக்கும்.

## ஒரு worked example

Coimbatore-ல ஒரு hospital group, follow-up calls-க்காக discharge notes-ஐ summarise பண்ற assistant வேணும்னு நினைக்குது. Notes-ல patient names, phone numbers, addresses, diagnoses, doctors' names இருக்கு.

Quality checks: discharge date இல்லாத notes-ஐ reject பண்ணுது, தெரிஞ்ச double-export bug-ல வந்த duplicates-ஐ (3% records) flag பண்ணுது, OCR text பெரும்பாலும் symbols-ஆ இருக்குற 40 scanned notes-ஐ quarantine பண்ணுது.

Personal data-க்கு, data protection officer இதை ஒத்துக்கிறாங்க:

- Summariser-க்கு clinical content தான் தேவை, identity இல்லை. Names, phone numbers, addresses, hospital ids model call-க்கு முன்னாடி mask ஆகும், nurse-க்கு காட்டுற summary-ல restore ஆகும்.
- Logs, traces-ல masked text மட்டும் இருக்கும்.
- Staging environment, templates-ல இருந்து generate பண்ண synthetic notes-ஐ use பண்ணும்.

200 hand-labelled notes-ல detector-ஐ test பண்ணப்போ, 97% phone numbers கிடைச்சுது, ஆனா 81% patient names தான். பல Tamil பெயர்கள் lowercase-ல எழுதப்பட்டிருந்ததால் miss ஆச்சு. Hospital-ஓட சொந்த patient-name list-ஐ lookup-ஆ சேர்த்ததும் அது 98%-க்கு ஏறுச்சு. DPO, அளந்த numbers design document-ல இருக்க, sign off பண்றாங்க.

| Check | Finding | Action |
| --- | --- | --- |
| Discharge date இல்லை | சில notes | Reject பண்ணாங்க |
| Duplicate exports | 3% records | Flag பண்ணி நீக்கினாங்க |
| குழம்பிய OCR text | 40 scanned notes | Re-scan-க்காக quarantine |
| Phone number detection | 97% கிடைச்சுது | ஒத்துக்கிட்டாங்க |
| Patient name detection | 81%, அப்புறம் hospital-ஓட name list-ஓட 98% | Fix-க்கு அப்புறம் ஒத்துக்கிட்டாங்க |

## பொதுவா பண்ற தப்புகள்

- **ஒரு தடவை கண்ணால பார்த்து quality check பண்றது.** Data மாறும்; ஒவ்வொரு batch-லயும் checks-ஐ automate பண்ணுங்க.
- **அளக்காம ஒரு detector-ஐ நம்புறது.** இந்திய data-ல name detection, vendors-ஓட English benchmarks-ஐ விட ரொம்ப பலவீனமா இருக்கலாம்.
- **எல்லா flows-க்கும் ஒரே rule.** Index, prompts, logs, test data-க்கு வேற வேற treatments வேணும்.
- **Task-ஐ உடைக்கிற masking.** Answer சொல்ல model-க்கு ஒரு date தேவைன்னா, அதை mask பண்ணா result கெட்டுப் போகும். ஒவ்வொரு field-க்கும் முடிவு பண்ணுங்க.
- **Free text-ஐ மறக்கிறது.** Personal data, பெயரிட்ட columns-ல மட்டுமில்ல, comments, notes, email bodies-லயும் ஒளிஞ்சிருக்கும்.
- **Production data-வை staging, tests-க்கு copy பண்றது.** பதிலா realistic fakes-ஐ generate பண்ணுங்க.
- **ஒரே ஒரு overall detector score.** Identifier type வாரியாவும் மொழி வாரியாவும் recall-ஐ அளங்க.
- **ஒரு field இல்லன்னா failure-ஐ record பண்ணாம crash ஆகுற rules.**

## Lighter checks போதும்னா

- **Public அல்லது synthetic data மட்டும்**, personal information இல்லாம: quality checks இன்னும் முக்கியம், PII detection ரொம்ப குறைவு.
- **ஒரு தடவை பண்ற analysis**, அதை run பண்ணி கையால check பண்றது.
- **தன்னோட contracts, checks இருக்குற நம்பகமான system-ல இருந்து ஏற்கனவே validate ஆகி வர்ற data.**

## Demo-ல இருந்து production-க்கு

- **ஒவ்வொரு batch-லயும் quality checks run பண்ணுங்க**, failures-ஐ quarantine பண்ணுங்க, ஒரு rule-ல திடீர் ஏற்றம் வந்தா alert பண்ணுங்க.
- **ஒவ்வொரு quarter-லயும், மாற்றங்களுக்கு அப்புறமும், label பண்ண sample-ல detector recall-ஐ அளங்க.**
- **Logs, traces-ல default-ஆ mask பண்ணுங்க**, ஒவ்வொரு exception-ஐயும் document பண்ணுங்க.
- **Staging, tests-ல generate பண்ண data-வை use பண்ணுங்க.**
- **புது document types அல்லது மொழிகள் வரும்போதெல்லாம் masking rules-ஐ review பண்ணுங்க.**

## Practice பண்ணுங்க

Presidio overview-ஐயும், Great Expectations introduction-ஐயும் படிங்க.

1. உங்களுக்கு பிடிச்ச ஒரு dataset-க்கு ஐந்து quality checks எழுதி run பண்ணுங்க, failures-ஐ ஒரு தனி file-க்கு quarantine பண்ணுங்க.
2. இந்திய mobile numbers, PAN, email-க்கு patterns-ஓட, ஒரு name detector-ஓட ஒரு masking function build பண்ணுங்க. நீங்க எழுதுற 30 sentences-ல test பண்ணுங்க, அதுல ரெண்டு மொழிகள்ல இந்திய பெயர்கள் இருக்கணும்.
3. ஒரு model call-ஐ சுத்தி reversible masking-ஐ implement பண்ணி, restore ஆன output-ஐ காட்டுங்க.
4. உங்க masking function-ஓட recall-ஐ 30 labelled sentences-ல அளங்க, English-ம் நீங்க use பண்ண ரெண்டாவது மொழியும்னு பிரிச்சு.

இன்னும் ஆழமா போக, Chip Huyen-ஓட *AI Engineering* (O'Reilly, 2025) புத்தகத்தோட chapter 8, data quality checks பத்தி சொல்லுது; chapter 10, sensitive data-வை detect பண்ணி mask பண்றதை பத்தி சொல்லுது.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** உங்க detector-ஓட அளந்த recall-ஐ ஒவ்வொரு personal data type-க்கும் report பண்ண முடியும், masked logs-ஐயும் சரியான unmasked answer-ஐயும் சேர்த்து காட்ட முடியும்.
