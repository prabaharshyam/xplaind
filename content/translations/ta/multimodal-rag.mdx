## இது என்ன

**Multimodal RAG**, plain text இல்லாத content-ல இருந்து retrieve பண்ணி பதில் சொல்லும்: slides, charts, tables, scanned pages, diagrams, photos. ரெண்டு முக்கிய approaches இருக்கு:

- **Text-ஆ மாத்தி, சாதாரண RAG use பண்றது.** Scans-ஐ OCR பண்ணி, images-ஐயும் charts-ஐயும் ஒரு vision-language model-ஆல describe பண்ண வச்சு, tables-ஐ text-ஆ extract பண்ணி, எல்லாத்தையும் text-ஆ index பண்ணுங்க. எளிது, இருக்குற pipelines-ஓட பொருந்தும்.
- **Images-ஐ நேரடியா retrieve பண்றது.** ஒரு multimodal embedding model-ஆல ஒவ்வொரு page-ஐயும் ஒரு image-ஆ index பண்ணுங்க (ColPali மாதிரி approaches OCR இல்லாம page images-ஐ embed பண்ணும்), மிகப் பொருத்தமான page images-ஐ retrieve பண்ணி, பதில் சொல்ல ஒரு **vision-language model**-க்கு அனுப்புங்க.

பல systems ரெண்டையும் சேர்த்து use பண்ணுது.

```flow
title: Text-ஆ மாத்து: மலிவு, சாதாரண RAG
Scan -[OCR]-> Text index
Chart -[ஒரு VLM describe பண்ணுது]-> Text index
Table -[extract]-> Text index
Text index -> ஒரு சாதாரண RAG பதில்
```

```flow
title: Images-ஐ retrieve பண்ணு
Page -[render]-> Image -[multimodal embedding]-> Image index
Question -[embed]-> Top 3 page images
Image index -> Top 3 page images
Top 3 page images -> ஒரு vision-language model images-ல இருந்து பதில் சொல்லுது
```

ஒரு hybrid, forms-க்கு OCR text-ஐயும், photos, diagrams, slides-க்கு image retrieval-ஐயும் use பண்ணி, ஒவ்வொரு பதிலோடவும் page thumbnail-ஐ காட்டும்; அதனால பதிலை check பண்ணலாம்.

இந்த lesson Vadodara-ல ஒரு chemicals manufacturer-ஐ follow பண்ணுது; அவங்க engineers scans, photos, diagrams நிறைஞ்ச 15 வருஷ maintenance reports-ஐ query பண்றாங்க.

## இது எப்படி work ஆகுது

**Text-ஆ மாத்துற route.**

- Charts, diagrams: ஒரு vision-language model-கிட்ட, axis labels, values, trends-ஓட ஒரு விரிவான description-ஐ கேளுங்க, page reference-ஓட சேமிங்க.
- Images-ல இருக்குற tables: அவற்றை structured text-ஆ extract பண்ணுங்க.
- Photos: use case-க்கு எது முக்கியமோ அதை வச்சு caption பண்ணுங்க ("flange joint-ல துரு, மேல இடது பக்கம்").

நன்மைகள்: queries மலிவு, எந்த text model-ஓடவும் வேலை செய்யும், filter பண்ணவும் cite பண்ணவும் எளிது. குறைகள்: descriptions-ல details தொலையும், எது முக்கியம்னு முன்னாடியே முடிவு பண்ணணும்.

**Image-retrieval route.**

- ஒவ்வொரு page அல்லது slide-ஐயும் ஒரு image-ஆ render பண்ணுங்க.
- ஒரு multimodal retrieval model-ஆல embed பண்ணுங்க.
- Query நேரத்துல, கேள்வியை embed பண்ணி, top pages-ஐ retrieve பண்ணி, images-ஐ கேள்வியோட ஒரு vision-language model-க்கு pass பண்ணுங்க.

நன்மைகள்: layout, charts, visual details-ஐ வச்சிருக்கும்; OCR errors இல்ல. குறைகள்: பெரிய indexes, image inputs அதிக tokens எடுக்கும், நேரமும் ஆகும், இதை support பண்ற tools குறைவு.

**Evaluation.** Visual content தேவைப்படுற கேள்விகளோட ஒரு golden set-ஐ build பண்ணி ("revenue chart-ல Q3 value என்ன?", "photo-ல எந்த valve திறந்திருக்கு?"), routes-ஐ ஒப்பிடுங்க.

**நடைமுறை எச்சரிக்கைகள்.** Vision models charts-ல சின்ன text-ஐயும் numbers-ஐயும் தப்பா படிக்கலாம்; page-ஐ cite பண்ணச் சொல்லுங்க, numbers முக்கியம்னா, underlying data இருந்தா அதோட check பண்ணுங்க. Images-ஐ போதுமான resolution-ல வச்சுக்கோங்க.

**Content type வாரியா தேர்ந்தெடுக்குறது:**

| Content | சிறந்த route | ஏன் |
| --- | --- | --- |
| Text அதிகமா இருக்குற scans, forms | OCR-ல இருந்து text | துல்லியமான wording, மலிவு, தேடலாம் |
| Tables | Structured text-ஆ extract | துல்லியமான பதில்களுக்கு rows-உம் headers-உம் இருக்கும் |
| Charts | Image route, அல்லது கவனமான description | Values-உம் trends-உம் படத்துலயே இருக்கு |
| Diagrams, drawings | Image route | Labels, positions, connections முக்கியம் |
| Photos | Image route | ஒரு caption-ல detail-ஐ கணிக்கிறது கஷ்டம் |
| Slides | Image route | Layout-க்கே அர்த்தம் இருக்கு |

**உதவுற descriptions எழுதுறது.** Visuals-க்கு text route use பண்ணா, ஒரு பொதுவான caption கேக்காம, users என்ன கேப்பாங்களோ அதை vision model-கிட்ட கேளுங்க. ஒரு chart-க்கு: title, axes, units, label பண்ணப்பட்ட ஒவ்வொரு value, முக்கிய trend. ஒரு piping diagram-க்கு: equipment tags, valve states, connections. ஒவ்வொரு description-ஓடவும் page number-ஐ சேமிங்க. Golden set-ல சில pages-ஓட test பண்ணின ஒரு focused description prompt, query cost-ல ஒரு சிறு பகுதியிலயே image route-ஓட இடைவெளியை பெருமளவு குறைக்கும்.

**ஆதாரத்தை காட்டுறது.** Visual content-ல, ஒரு citation, page அல்லது slide-ஓட thumbnail-ஆ இருந்தா இன்னும் பயனுள்ளது. Engineers-உம் analysts-உம் image-ஐ ஒரு பார்வை பாத்து பதிலை உறுதி பண்ணிக்கலாம்; இது சின்ன numbers-ஐ model எப்பவாவது தப்பா படிக்கிறதையும் பிடிக்கும்.

**Code-ல pages-ஐ render பண்ணி visuals-ஐ describe பண்றது.** PyMuPDF PDF pages-ஐ images-ஆ மாத்தும்; ஒரு vision model ஒரு focused prompt-ஓட அவற்றை describe பண்ணும்:

```python
import base64
import fitz                                      # PyMuPDF
import anthropic

client = anthropic.Anthropic()
CHART_PROMPT = ("Describe this page for search. For each chart: title, axes and units, every labelled value, "
                "and the main trend. For tables: headers and every row. Quote numbers exactly as shown.")

def page_images(pdf_path, dpi=150):
    doc = fitz.open(pdf_path)
    for i, page in enumerate(doc, start=1):
        yield i, page.get_pixmap(dpi=dpi).tobytes("png")

def describe(png_bytes):
    r = client.messages.create(
        model="claude-sonnet-5-5", max_tokens=800,           # check the docs for current names
        messages=[{"role": "user", "content": [
            {"type": "image", "source": {"type": "base64", "media_type": "image/png",
                                         "data": base64.b64encode(png_bytes).decode()}},
            {"type": "text", "text": CHART_PROMPT}]}])
    return "".join(b.text for b in r.content if b.type == "text")

# Text route: store describe(png) with the page number, and index it like any other chunk.
```

பதில் சொல்ற நேரத்துல, அதே image block format, image route-க்காக retrieve பண்ண top page images-ஐ கேள்வியோட அனுப்ப விடும்.

**Text queries-ஆ images-ஐ retrieve பண்றது.** ஒரு multimodal embedding model images-ஐயும் text-ஐயும் ஒரே space-ல வைக்கும்:

```python
from PIL import Image
from sentence_transformers import SentenceTransformer

clip = SentenceTransformer("clip-ViT-B-32")
img_vecs = clip.encode([Image.open(p) for p in photo_paths], normalize_embeddings=True)
q = clip.encode(["rust on a flange joint"], normalize_embeddings=True)[0]
best = (img_vecs @ q).argsort()[::-1][:5]
```

இந்த மாதிரி general models photos-க்கு வேலை செய்யும். Text-உம் charts-உம் நிறைஞ்ச document pages-க்கு, page retrieval-க்காக train பண்ண models (ColPali குடும்பம் ஒரு பிரபலமான உதாரணம்) ரொம்ப நல்லா செய்யும்; ரெண்டையும் உங்க golden set-ல test பண்ணுங்க.

**Image tokens-க்கு காசு ஆகும்.** ஒரு vision model-க்கு அனுப்புற page image, அதோட size-க்கு கிட்டத்தட்ட விகிதத்துல நிறைய tokens-ஆ bill ஆகும். பத்து இல்ல, top ரெண்டு அல்லது மூணு pages-ஐ மட்டும் அனுப்புங்க, முடிஞ்சா சம்பந்தப்பட்ட பகுதிக்கு crop பண்ணுங்க, சின்ன numbers இன்னும் படிக்க முடியுற resolution-ஐ தேர்ந்தெடுங்க. ஒவ்வொரு route-க்கும் ஒரு கேள்விக்கான cost-ஐ measure பண்ணுங்க.

**Images-ல இருந்து படிச்ச numbers-ஐ check பண்ணுங்க.** Vision models சில நேரம் charts-லயும் scans-லயும் சின்ன digits-ஐ தப்பா படிக்கும். Underlying data இருந்தா (ஒரு chart-க்கு பின்னாடி இருக்குற spreadsheet), அதுக்கு link பண்ணி ஒப்பிடுங்க; இல்லன்னா users check பண்ணிக்க, பதிலோட page thumbnail-ஐ காட்டுங்க.

**உங்க browser-லயே try பண்ணுங்க.** Image inputs, size-ஐ பொறுத்து tokens எடுக்கும். வெவ்வேற sizes-ல page images-ஐ அனுப்புறதோட cost-ஐ estimate பண்ணுங்க.

```python
def image_tokens(width, height):
    return (width * height) / 750                 # a common rule of thumb; check your provider's docs

for w, h in [(1600, 2000), (1000, 1250), (800, 1000)]:
    t = image_tokens(w, h)
    print(f"{w}x{h}: about {t:,.0f} tokens per page, {3 * t:,.0f} for three pages")
```

## ஒரு worked example

Vadodara-ல ஒரு chemicals manufacturer, தங்க plant engineers 15 வருஷ maintenance reports-ஐ query பண்ணணும்னு விரும்புது: scanned forms, equipment photos, piping diagrams, root-cause reviews-ஓட slide decks.

60 கேள்விகள்ல ரெண்டு routes-ஐயும் test பண்றீங்க:

- *Text-ஆ மாத்து*: forms-க்கு OCR, photos-க்கும் diagrams-க்கும் model எழுதின descriptions. 58% சரி. Failures: engineers கேட்ட detail-ஐ descriptions தவறவிட்டுச்சு, உதாரணம் எந்த valve tag-ஐ வட்டம் போட்டிருக்குன்னு.
- *Image retrieval*: ஒரு multimodal retriever-ஆல embed பண்ண page images; top மூணு pages ஒரு vision-language model-க்கு அனுப்பப்பட்டுச்சு. 79% சரி. Failures: scans-ல இருந்த சின்ன கையெழுத்து குறிப்புகள்.

ஒரு hybrid-ஐ ship பண்றீங்க: scanned forms OCR வழியா போகுது (அவற்றோட text fields தான் engineers தேடுறது), photos, diagrams, slides images-ஆ retrieve ஆகுது. Engineers check பண்ணிக்க, பதில்கள் page thumbnail-ஐ காட்டுது. Query cost text-only route-ஐ விட சுமார் நாலு மடங்கு; தங்களுக்கு மிக முக்கியமான கேள்விகள்ல accuracy-ல வந்த பெரிய முன்னேற்றத்துக்காக client இதை ஏத்துக்குது.

## பொதுவா பண்ற தப்புகள்

- **Visual content-ஐ புறக்கணிக்கிறது.** Text-only pipelines charts-ஐயும் photos-ஐயும் சத்தமில்லாம தாண்டிப் போயிடும்.
- **Chart readings-ஐ அளவுக்கு மீறி நம்புறது.** Vision models சின்ன numbers-ஐ தப்பா படிக்கும்; pages-ஐ cite பண்ணி, முக்கிய values-ஐ check பண்ணுங்க.
- **Low-resolution images.** Details மறைஞ்சுடும்; கேக்குற கேள்விகளுக்கு போதுமான resolution வச்சுக்கோங்க.
- **Golden set-ல visual கேள்விகள் இல்லாம இருக்குறது.** அப்போ multimodal வேலை உதவுச்சான்னு உங்களால சொல்ல முடியாது.
- **எல்லாத்துக்கும் image route.** Text அதிகமா இருக்குற documents text-ஆ இருக்கும்போது மலிவு, பெரும்பாலும் நல்லதும் கூட.
- **Charts, diagrams-க்கு பொதுவான captions.** Users-க்கு தேவைப்படுற values-ஐயும் labels-ஐயும் கேளுங்க.
- **ஒரு கேள்விக்கு நிறைய full-resolution pages-ஐ அனுப்புறது**, இது மெதுவு, காசு அதிகம்.
- **Document pages-க்கு ஒரு photo model-ஐ use பண்றது.** ஒரு page-retrieval model-ஐயும் test பண்ணுங்க.

## எப்போ text-only RAG போதும்

- **Visuals, text சொல்றதையே திருப்பி சொல்லுது**, charts சொல்லப்பட்ட numbers-ஐ விளக்குற பல reports மாதிரி.
- **PDF parser, tables-ஐ சுத்தமா text-ஆ extract பண்ண முடியுது.**
- **சில கேள்விகளுக்கு மட்டுமே visuals தேவை**, அதனால சில முக்கிய pages-ஐ கையால describe பண்றது மலிவு.

## Demo-ல இருந்து production-க்கு

- **ஒவ்வொரு description-ஓடவும் retrieve பண்ண image-ஓடவும் page numbers-ஐயும் thumbnails-ஐயும் வச்சுக்கோங்க.**
- **Route வாரியா ஒரு query-க்கான cost-ஐ track பண்ணுங்க**, image tokens-ஐயும் சேர்த்து.
- **Description prompt மேம்படும்போது pages-ஐ மறுபடி describe பண்ணி**, descriptions-ஐ version பண்ணுங்க.
- **ஒரு visual golden set-ஐ வச்சு**, models மாறும்போது மறுபடி run பண்ணுங்க.
- **தப்பா படிச்ச numbers-ஐ users flag பண்ண விடுங்க**, அவற்றை test set-ல சேருங்க.

## Practice பண்ணுங்க

Hugging Face-ஓட multimodal RAG notebook-ஐ பண்ணுங்க, text route-க்கு Docling அல்லது அது மாதிரி ஒரு tool-ஐ use பண்ணுங்க.

1. Charts, tables, photos இருக்குற 20 pages-ஐ சேகரிச்சு, visual content தேவைப்படுற 15 கேள்விகளை எழுதுங்க.
2. Text-ஆ மாத்துற route-ஐயும் image-retrieval route-ஐயும் build பண்ணுங்க.
3. ஒரு query-க்கான accuracy, latency, cost-ஐ ஒப்பிட்டு, எந்த content type எந்த route-ஐ use பண்ணணும்னு முடிவு பண்ணுங்க.
4. ஐந்து chart pages-ஐ focused prompt-ஓடவும், ஒரு சாதாரண 'describe this image' prompt-ஓடவும் describe பண்ணி, ஒவ்வொரு version-ஆலும் உங்க chart கேள்விகள்ல எத்தனைக்கு பதில் சொல்ல முடியுதுன்னு எண்ணுங்க.
