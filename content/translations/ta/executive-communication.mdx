## இது என்ன

Executives-கிட்ட நேரம் குறைவு, priorities நிறைய, பணம், risk-க்கு பொறுப்பு. அவங்ககிட்ட நல்லா communicate பண்றதுன்னா:

- **Answer first.** Conclusion-ஓட அல்லது தேவையான decision-ஓட ஆரம்பிச்சு, அப்புறம் support.
- **அவங்க மொழி.** Business results (time, cost, revenue, risk, customers), model names, architectures இல்ல.
- **Proof.** Baseline-க்கு எதிரா ஒரு number, ஒரு சின்ன demo, ஒரு user-ஓட வார்த்தைகள்.
- **Trade-offs, நேர்மையா.** அதுக்கு என்ன செலவாகும், என்ன தப்பாகலாம், நீங்க என்ன recommend பண்றீங்க.
- **தெளிவான ask.** அவங்ககிட்ட என்ன வேணும், எப்போவுக்குள்ள.

| ஒரு பக்க memo | |
|---|---|
| **Headline** | Recommendation: எல்லா 180 officers-க்கும் roll out பண்ணுங்க |
| **ஏன்** | மாசத்துக்கு சுமார் 1,700 officer hours விடுவிக்கப்படுது |
| **Evidence** | ஒரு file-க்கு 41-ல இருந்து 24 நிமிஷம்; rework 7%-ல இருந்து 5.1% |
| **Risks** | படம் எடுத்த documents; mitigations பேர் சொல்லியிருக்கு |
| **Ask** | Budget-ஐ approve பண்ணி ஒரு owner-ஐ சொல்லுங்க, இன்னைக்கே |

```flow
dir: LR
Headline -> ஏன் -> Evidence -> Risks -> Ask
```

ஒவ்வொரு number-உம் எப்படி calculate ஆச்சுன்னு ஒவ்வொண்ணுக்கும் ஒரு வரியில appendix காட்டும்.

சென்னையில ஒரு lender-ஓட CEO, CFO-ஓட pilot முடிவு meeting-ஐ இந்த lesson பின்தொடருது.

## இது எப்படி work ஆகுது

**Structure.** எந்த update அல்லது email-க்கும் ஒரு எளிய pattern:

1. *Headline*: முக்கிய point ஒரு வாக்கியத்துல.
2. *ஏன் முக்கியம்*: business effect.
3. *Evidence*: ரெண்டு அல்லது மூணு facts.
4. *Risks அல்லது trade-offs*: படத்தை மாத்தக்கூடியது என்ன.
5. *Ask*: தேவையான decision அல்லது உதவி, தேதியோட.

**அவங்களுக்கு தெரிஞ்ச numbers.** Scope of work-ல ஒத்துக்கிட்ட KPI, baseline-ஐ, ரூபாய், hours அல்லது customers-ல use பண்ணுங்க. "மாசத்துக்கு சுமார் 1,700 officer hours சேமிக்குது, இப்போதைய salary costs-ல வருஷத்துக்கு தோராயமா ₹50 lakh" சரியா போய் சேரும்; "field extraction-ல 96.4% F1" மாத்தி சொல்லலன்னா சேராது.

**Executives-க்கான demos.** ஐந்து நிமிஷம், ஒரே கதை: ஒரு உண்மையான case, before-after, user-ஓட பார்வை, ஒரு safeguard-ஐ காட்டுற ஒரு தருணம். Rehearse பண்ணுங்க. Network fail ஆனா ஒரு recorded backup வச்சிருங்க.

**வெளிப்படையான கேள்விகளுக்கு தயாரா இருங்க.** Full scale-ல என்ன செலவாகும்? தப்பா போனா என்ன ஆகும்? எங்க data பாதுகாப்பா இருக்கா? எங்க ஆட்கள் என்ன நினைக்கிறாங்க? Competitors பண்றதோட இது எப்படி ஒப்பிடுது? ஒரு வரி பதில்கள் ready-ஆ வச்சிருங்க, கேட்டா details.

**சின்ன documents.** Decisions-க்கு 30-slide deck-ஐ விட ஒரு பக்க memo ஜெயிக்கும். Slides கட்டாயம்னா, ஒரு slide-க்கு ஒரு idea, headline-ஐ slide title-ஆ.

**நிச்சயமின்மை பத்தி நேர்மையா இருங்க.** "Full rollout-ல ஒரு file-க்கு 20 முதல் 25 நிமிஷம் எதிர்பார்க்குறோம்; pilot branches சராசரியை விட நல்லா இருந்துச்சு, அதனால 25-க்கு plan பண்றோம்" ஒரே நம்பிக்கையான number-ஐ விட நம்பகமா இருக்கும்.

**Technical results-ஐ மாத்தி சொல்றது:**

| Technical statement | Executive version |
| --- | --- |
| "Critical fields-ல 96.4% accuracy" | "முப்பதுல ஒரு figure-ஐ officers திருத்துறாங்க; ஒவ்வொரு figure-க்கும் check பண்ண ஒரு source இருக்கு" |
| "p95 latency 2 seconds" | "மிக busy-ஆன மணி நேரத்துலயும் answers சுமார் ரெண்டு வினாடிகள்ல வருது" |
| "Caching-ஓட சின்ன model-க்கு மாறினோம்" | "Quality-ல மாற்றம் இல்லாம running cost மாசம் ₹14 lakh-ல இருந்து ₹9 lakh-ஆ குறைஞ்சுது" |
| "Recall at 5 of 0.91" | "பத்துல ஒன்பது தடவை சரியான document-ஐ கண்டுபிடிக்குது" |

**60 வினாடி version.** Recommendation-ஐயும் அதோட evidence-ஐயும் ஒரு நிமிஷத்துக்குள்ள சத்தமா சொல்ல practice பண்ணுங்க. நீங்க வேண்டுற decision, baseline-க்கு எதிரா முக்கிய result, scale-ல value, cost, மிகப்பெரிய risk, அதோட mitigation இவற்றை சேருங்க. ஒரு நிமிஷத்துல சொல்ல முடியலன்னா, memo இன்னும் தெளிவா இல்ல. Executives பெரும்பாலும் சொன்னதை விட குறைவான நேரம் தான் தருவாங்க, முதல் நிமிஷம் தான் மீதியை தீர்மானிக்கும்.

**கடினமான கேள்விகளை handle பண்றது.** கேட்ட கேள்விக்கு ஒரு வாக்கியத்துல பதில் சொல்லிட்டு, அப்புறம் details தர்றேன்னு சொல்லுங்க: "ஆமா, data இந்தியாவுல எங்க Azure region-லயே இருக்கு. உதவியா இருந்தா architecture page-ஐ காட்டுறேன்." தெரியலன்னா, தெரியலன்னு சொல்லி எப்போ பதில் சொல்லுவீங்கன்னு ஒரு நேரம் சொல்லுங்க. ஒரு CFO முன்னாடி ஊகிக்கிறது, ஒரு gap-ஐ ஒத்துக்கிறதை விட அதிக நம்பிக்கையை இழக்க வைக்கும்.

## ஒரு worked example

Pilot முடிஞ்சதும், lender-ஓட CEO, CFO உங்களுக்கு 15 நிமிஷம் தர்றாங்க. உங்க ஒரு பக்க memo:

> **Recommendation: credit-file assistant-ஐ மூணு மாசத்துல எல்லா 180 officers-க்கும் roll out பண்ணுங்க.**
>
> **Result.** 20 officers-ஓட 10 வார pilot-ல, ஒரு loan file-க்கு median time 41-ல இருந்து 24 நிமிஷமா குறைஞ்சுது; credit committee திருப்பி அனுப்புன files 7%-ல இருந்து 5.1%-ஆ குறைஞ்சுது.
>
> **Full scale-ல value.** மாசத்துக்கு சுமார் 1,700 officer hours விடுவிக்கப்படுது (6,000 files-ல ஒவ்வொண்ணுக்கும் 17 நிமிஷம்), வருஷத்துக்கு தோராயமா ₹50 lakh; புது hiring இல்லாம 25% அதிக applications-ஐ handle பண்ண operations head இதை use பண்ண திட்டமிடுறாரு.
>
> **Cost.** Full scale-ல run பண்ண மாசம் சுமார் ₹9 lakh, model costs, support உட்பட.
>
> **Risks.** படம் எடுத்த documents அதிகமா இருக்குற branches-ல adoption குறைவா இருக்கலாம்; image clean-up step, branch visits மூலமா சரி பண்றது. எல்லா credit decisions-உம் officers-கிட்டயே இருக்கும்.
>
> **இன்னைக்கு தேவையான decision:** rollout budget-ஐ approve பண்ணி operations-ல ஒரு owner-ஐ பேர் சொல்லுங்க.

Demo ஒரு உண்மையான file-ஐயும், officer-ஓட review screen-ஐயும், ஒரு low-confidence figure flag ஆகி திருத்தப்படுறதையும் காட்டுது. ₹50 lakh எப்படி calculate ஆச்சுன்னு CFO கேக்குறாரு; appendix-ல இருக்குற ஒரு வரி formula-வை காட்டுறீங்க. Approval பத்து நிமிஷத்துல வருது.

| Memo element | அது என்ன சொல்லுச்சு |
| --- | --- |
| Recommendation | மூணு மாசத்துல எல்லா 180 officers-க்கும் roll out |
| Result | ஒரு file-க்கு 41-ல இருந்து 24 நிமிஷம்; rework 7%-ல இருந்து 5.1% |
| Value | மாசத்துக்கு சுமார் 1,700 officer hours, வருஷத்துக்கு தோராயமா ₹50 lakh |
| Cost | Full scale-ல மாசம் சுமார் ₹9 lakh |
| Ask | Budget-ஐ approve பண்ணி இன்னைக்கே ஒரு owner-ஐ பேர் சொல்லுங்க; பத்து நிமிஷத்துல approve ஆச்சு |

## பொதுவா பண்ற தப்புகள்

- **Technology-ஓட ஆரம்பிக்கிறது.** Result-ஓடயும் decision-ஓடயும் ஆரம்பிங்க.
- **Translate பண்ணாத model metrics.** அவற்றை time, money, risk அல்லது customers-ஆ மாத்துங்க.
- **எளிய decisions-க்கு நீளமான decks.** ஒரு பக்கம் பெரும்பாலும் போதும்.
- **அதிகமா வாக்குறுதி தர்றது.** ஒரே best-case number-ஐ விட ranges-உம் downside plans-உம் better.
- **Ask இல்லாதது.** Decision-ஐ கேக்கலன்னா, அது அரிதா தான் கிடைக்கும்.

## Practice பண்ணுங்க

Google-ஓட இலவச technical writing course-ஓட குறைஞ்சது முதல் unit-ஐ எடுத்துக்கோங்க; அது executive writing-க்கு நேரடியா பொருந்தும்.

1. உங்க use case-க்கு, ஐந்து பகுதி structure-ல ஒரு பக்க recommendation memo எழுதுங்க; ஒவ்வொரு number-உம் ஒரு source-ஓட trace ஆகணும்.
2. ஐந்து நிமிஷ demo கதையை script பண்ணுங்க: ஒரு உண்மையான case, before-after, ஒரு safeguard.
3. ஒரு CFO கேக்குற ஐந்து கேள்விகளை list பண்ணி, ஒவ்வொண்ணுக்கும் ஒரு வரி பதில் எழுதுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** உங்க recommendation-ஐயும் அதோட முக்கிய evidence-ஐயும் slides இல்லாம, சத்தமா, 60 வினாடிக்குள்ள சொல்ல முடியும்.
