## இது என்ன

உங்களுக்கோ ஒரு client-க்கோ ஒரு workflow-ஐ automate பண்ணும்போது, முதல் உண்மையான முடிவு **எந்த tool**-ங்குறது தான். இந்திய businesses-ல நீங்க பார்க்குற பெரும்பாலான automation வேலையை நாலு tools cover பண்ணுது:

| Tool | ஒரு வரியில | Usage-ஐ எதுல count பண்ணுது | வழக்கமான user |
| --- | --- | --- | --- |
| **Zapier** | எல்லாத்தையும் விட பிரபலமான no-code tool: ரொம்ப ஈஸி, app connectors-ஓட பெரிய catalogue, workflows ("Zaps") பெரும்பாலும் நேர் கோட்டுல, கொஞ்சம் branching-ஓட | Tasks (ஒவ்வொரு action step-உம்) | சின்ன businesses, technical இல்லாத teams |
| **Make** (முன்னாடி Integromat) | Data, routers, loops, error handling மேல அதிக control இருக்குற ஒரு visual canvas, அதுவும் no-code தான் | Credits (ஒவ்வொரு module-உம், ஒவ்வொரு item-க்கும்) | Zapier-ஐ தாண்டி வளர்ந்த operations teams |
| **n8n** | அதிக technical users-க்கான ஒரு visual tool; code nodes, எந்த API-க்கும் ஒரு HTTP node, strong AI agent features இருக்கு. Source-available, self-host பண்ணலாம் | Executions (ஒவ்வொரு முழு run-உம்) | Developers, startups, கடுமையான data rules இருக்குற companies |
| **Microsoft Power Automate** | Microsoft-ஓட Power Platform-ஓட ஒரு பகுதி, Microsoft 365, Teams, SharePoint கூட நெருக்கமா இணைஞ்சது, பழைய Windows apps-க்கு desktop RPA இருக்கு | User, bot licences | ஏற்கனவே Microsoft-ல இருக்குற, IT team இருக்குற companies |

**Consultants-க்கு முக்கியமான ஒரு licence fact.** n8n-ஐ பெரும்பாலும் open source-னு சொல்லுவாங்க. அது இல்லை. அது n8n-ஓட சொந்த **Sustainable Use License**-ஐ use பண்ணுது (n8n இதை "fair-code"-னு சொல்லுது): code-ஐ பார்க்கலாம், மாத்தலாம், உங்க சொந்த business-க்கு use பண்ணலாம். பணம் தர்ற ஒரு client-க்கு workflows build பண்றது allowed. Clients log in பண்ணி அதுல build பண்றதுக்காக n8n-ஐ host பண்றதுக்கும், அல்லது உங்க சொந்த brand-ல அதை விக்குறதுக்கும் n8n கூட ஒரு commercial agreement வேணும். அதை சுத்தி ஒரு service-ஐ design பண்றதுக்கு முன்னாடி இப்போதைய licence-ஐ படிங்க.

மத்த tools-உம் இருக்கு, Workspace-க்கான Google-ஓட tools, enterprise integration platforms மாதிரி, ஆனா இந்த நாலு தான் எல்லாத்தையும் விட அதிகமா வரும்.

## இது எப்படி work ஆகுது

Tools-ஐ ஏழு factors-ல compare பண்ணுங்க. முதல் மூணும் build எவ்வளவு சுகமா இருக்கும்னு முடிவு பண்ணும். கடைசி நாலும் ஒரு வருஷம் கழிச்சும் client சந்தோஷமா இருப்பாங்களான்னு முடிவு பண்ணும்.

### 1. Ease of use

Start பண்ண Zapier தான் எல்லாத்தையும் விட ஈஸி. Flexibility-ல Make ஒரு படி மேல, learning curve நடுத்தரம். JSON (apps data-வை பரிமாற use பண்ற text format), கொஞ்சம் code-ல comfortable ஆனவங்களுக்கு n8n பொருந்தும். சாதாரண Microsoft 365 flows-க்கு Power Automate ஈஸி, advanced flows-ல complex ஆகிடும்.

### 2. Connectors

**Connector**-னா ஒரு app கூட ready-made integration. Popular SaaS apps-க்கு Zapier, Make-ல தான் எல்லாத்தையும் விட அகலமான catalogues இருக்கு. n8n-லயும் நிறைய இருக்கு, கூடவே API இருக்குற எதுகூடவும் பேசக்கூடிய ஒரு HTTP Request node இருக்கு. Power Automate Microsoft products கூட தான் எல்லாத்தையும் விட strong; மத்த நிறைய apps-க்கும் connectors இருக்கு, ஆனா சிலது paid Power Automate licence தேவைப்படுற **premium** connectors.

**Gotcha.** App-ஓட logo-வை மட்டும் பார்க்காம, உங்களுக்கு தேவையான சரியான action-ஐ check பண்ணுங்க. ஒரு connector இருக்கலாம், ஆனா client-க்கு வேண்டிய அந்த ஒரு action, "update a row" அல்லது "attach a file" மாதிரி, அதுல இல்லாம இருக்கலாம்.

### 3. AI features

நாலுமே இப்போ AI steps தருது: models-ஐ call பண்றது, data extract பண்றது, classify பண்றது, agent மாதிரியான features. Custom AI agents build பண்றதுக்கு n8n குறிப்பா strong. Power Automate Microsoft-ஓட AI services, Copilot கூட இணையுது.

**Gotcha.** ஒரு AI step data-வை ஒரு model provider-க்கு அனுப்புது. "Data எங்ககிட்டயே இருக்கணும்"-னு சொல்ற ஒரு client, பொதுவா workflow tool-ஐ மட்டும் இல்லாம model call-ஐயும் சேர்த்து தான் சொல்றாங்க.

### 4. Pricing model: ஒவ்வொரு tool-ஓட unit-ல count பண்ணுங்க

ஒவ்வொரு tool-உம் usage-ஐ வேற unit-ல count பண்ணுது, அதனால முதல்ல workflow-ஓட ஒரு run-ஐ அந்த unit-ஆ மாத்துங்க:

| Tool | Unit | ஒரு trigger, நாலு actions-ஓட ஒரு run | கவனிக்க வேண்டியது |
| --- | --- | --- | --- |
| Zapier | Task: ஒவ்வொரு successful action step-உம் | 4 tasks (trigger, Filter, Formatter steps free) | நீளமான Zaps count-ஐ பெருக்கும் |
| Make | Credit: ஒவ்வொரு module-உம், அது handle பண்ற ஒவ்வொரு item-க்கும் | 5 credits (trigger-உம் ஒண்ணு use பண்ணும்) | Items மேல loops, AI modules, polling triggers |
| n8n | Execution: எத்தனை steps இருந்தாலும் ஒரு முழு run | 1 execution | நிறைய சின்ன workflows கூடிடும் |
| Power Automate | ஒரு user-க்கு அல்லது ஒரு bot-க்கு licence | Daily action limits-க்குள்ள, user-ஓட licence-லயே cover ஆகும் | Premium connectors-க்கும் desktop RPA-க்கும் paid licences வேணும் |

**Make-ல polling trap.** ஒரு **polling** trigger ஒரு timer-ல ஒரு app-ஐ புது items-க்காக check பண்ணும். புதுசா எதுவும் இல்லைன்னாலும், ஒவ்வொரு check-க்கும் Make ஒரு credit charge பண்ணும். 15 நிமிஷத்துக்கு ஒரு தடவை check பண்ற trigger 30 நாள் மாசத்துல 4 × 24 × 30 = 2,880 தடவை ஓடும், அதனால எந்த வேலையும் நடக்குறதுக்கு முன்னாடியே 2,880 credits use ஆகிடும். ஒரு **instant** trigger (ஒரு webhook, data வந்த உடனே app அதை அனுப்பும்) இதை தவிர்க்கும்.

**Prices மாறும்.** எப்பவும் live price pages-ல இருந்து, அங்க காட்டுற currency-லயே prices-ஐ எடுங்க, நீங்க check பண்ண date-ஐ எழுதி வைங்க. Zapier US dollars-ல prices போடுது, n8n euros-ல, Microsoft India rupees-ல, GST தனி. Compare பண்றதுக்கு முன்னாடி, சொல்லப்பட்ட ஒரே exchange rate-ல convert பண்ணுங்க.

### 5. Data control

ஒவ்வொரு tool-உம் அது வழியா போற data-வை எங்க வச்சிருக்குன்னு தெரிஞ்சுக்கோங்க:

| Tool | Vendor சொல்றபடி data எங்க process ஆகுது |
| --- | --- |
| Zapier | United States-ல Amazon servers-ல; வேற region-ஐ தேர்ந்தெடுக்க முடியாது |
| Make | நீங்க ஒவ்வொரு organisation-க்கும் தேர்ந்தெடுக்குற ஒரு US அல்லது EU data centre-ல, அதை அப்புறம் மாத்த முடியாது; சில AI features வேற இடத்துக்கு route ஆகும் |
| n8n Cloud | Hosted plans data-வை Frankfurt, Germany-ல store பண்ணுதுன்னு n8n-ஓட site சொல்லுது |
| Self-hosted n8n | நீங்க எங்க ஓட்டுறீங்களோ அங்க, India-ல ஒரு cloud region உட்பட |
| Power Automate | Client-ஓட Power Platform environment இருக்குற region-ல; India-வும் ஒரு region |

**India-ல.** Digital Personal Data Protection Act, 2023 (DPDP Act) client-ஐ அவங்க customers-ஓட personal data-க்கு ஒரு **Data Fiduciary** ஆக்குது. Client-க்காக அந்த data-வை process பண்ற எந்த tool-உம் ஒரு **Data Processor**, ஒரு valid contract இருந்தா மட்டும் தான் fiduciary ஒரு processor-ஐ use பண்ணலாம்னு Act சொல்லுது. அதனால Zapier, Make அல்லது n8n Cloud-க்கு, client vendor-ஓட data processing agreement-ஐ accept பண்ணி அதோட ஒரு copy-ஐ வச்சிருக்கணும். DPDP Rules November 2025-ல notify ஆச்சு, பெரும்பாலான duties May 2027-ல இருந்து apply ஆகும். பொதுவா, data India-லயே இருக்கணும்னு Act கேக்கலை, ஆனா payment data-க்கு Reserve Bank of India மாதிரி ஒரு sector regulator, அல்லது client-ஓட சொந்த contracts அதை கேக்கலாம். எது apply ஆகும்னு client-ஓட compliance team-கிட்ட கேளுங்க; நீங்களே முடிவு பண்ணாதீங்க.

### 6. Lock-in, debugging

**Lock-in.** ஒரு tool-ல build பண்ண workflow-ஐ இன்னொரு tool-க்கு நகர்த்த முடியாது. n8n-உம் Make-உம் ஒரு workflow-ஐ JSON file-ஆ save பண்ணலாம், Power Automate ஒரு .zip package-ஆ, ஆனா ஒவ்வொரு file-உம் அதே tool-க்குள்ள மட்டும் தான் திரும்ப import ஆகும். அப்புறம் மாத்தணும்னா திரும்ப build பண்ணணும், அதனால இந்த தேர்வு நீடிக்கும்னு நினைச்சு தேர்ந்தெடுங்க.

**Debugging.** Workflows fail ஆகும்: ஒரு API down ஆகும், ஒரு field காலியா இருக்கும், ஒரு password expire ஆகும். நாலுமே ஒவ்வொரு step-ஓட input, output-ஐ காட்டுற run history வச்சிருக்கு, ஒவ்வொண்ணும் ஏதோ ஒரு வகையில fail ஆன runs-ஐ retry பண்ண முடியும். Zapier fail ஆன steps-ஐ replay பண்ண முடியும். Make ஒரு **incomplete execution**-ஐ store பண்ணும், நீங்க data-வை சரி பண்ணி அதை resume பண்ணலாம். ஒரு run fail ஆனா யாருக்காவது alert அனுப்புற ஒரு **error workflow**-ஐ attach பண்ண n8n விடுது. Power Automate run history-ஐ காட்டும், ஒரு run-ஐ resubmit பண்ணவும் விடும். Hand over பண்றதுக்கு முன்னாடி, பேர் சொல்லப்பட்ட ஒரு ஆளுக்கு போய் சேர்ற ஒரு alert-ஐ set up பண்ணுங்க; யாருமே பார்க்காத ஒரு failure தான், automations அமைதியா செத்துப் போறதுக்கு எல்லாத்தையும் விட பொதுவான வழி.

### 7. Fit, maintenance

பெரும்பாலும் எல்லாத்தையும் விட strong-ஆன factor, client-கிட்ட ஏற்கனவே என்ன இருக்குங்குறது தான். IT governance-ஓட Microsoft 365-ல இருக்குற ஒரு company பொதுவா Power Automate-ஐ தான் விரும்பும், ஏற்கனவே அதுக்கு பணம் கட்டிக்கிட்டும் இருக்கலாம். SaaS apps-லயே வாழுற ஒரு startup Zapier அல்லது Make-ஐ விரும்பலாம். கடுமையான data rules அல்லது அதிக AI தேவைகள் இருக்குற ஒரு company self-hosted n8n-ஐ விரும்பலாம்.

எப்பவும் கேளுங்க: **நீங்க போனதுக்கு அப்புறம் இதை யார் maintain பண்ணுவாங்க?** Client-ஓட சொந்த ஆளுங்களே ஓட வைக்க முடியுற tool தான் best tool.

### Total cost of ownership

எல்லாத்தையும் **TCO**-வா, அதாவது total cost of ownership-ஆ கூட்டுங்க:

```text
  TCO per month = licence or usage fees
                + servers (if self-hosted)
                + setup time, spread over the first year
                + maintenance hours each month x hourly cost
                + training for the people who will run it
```

Client பக்கம் யாராலயும் maintain பண்ண முடியலைன்னா, licence fee இல்லாத ஒரு tool-க்கும் எல்லாத்தையும் விட அதிக TCO இருக்கலாம்.

Technical staff இல்லை. **தேர்வு: Zapier.** Build பண்ண அது தான் எல்லாத்தையும் விட வேகமானது, அவங்க office manager maintain பண்ணவும் எல்லாத்தையும் விட ஈஸியானது.

**Pune-ல ஒரு manufacturer.** Microsoft 365-ல இருக்காங்க, அஞ்சு பேர் இருக்குற IT team இருக்கு. Teams-ல purchase approvals வேணும், API இல்லாத ஒரு பழைய Windows inventory application-க்குள்ள data copy ஆகணும். **தேர்வு: Power Automate.** Teams-ல approvals-ஐ cloud flows handle பண்ணும், inventory app-ஐ desktop RPA handle பண்ணும். எல்லாமே ஏற்கனவே இருக்குற Microsoft governance-க்குள்ளயே இருக்கும்.

**Bengaluru-ல ஒரு health-tech startup.** அது மாசத்துக்கு 20,000 patient intake forms-ஐ AI extraction மூலமா process பண்ணுது, patient data அதோட சொந்த cloud account-லயே இருக்கணும்னு அதோட data rules சொல்லுது. அதோட developers tools-ஐ code வச்சு extend பண்ண விரும்புறாங்க. **தேர்வு: self-hosted n8n**, அவங்க சொந்த cloud account-ல, AI model-உம் அந்த account-க்குள்ளயே ஓடும். Per-run fees இல்லை, data அவங்க environment-லயே இருக்கும், developers custom nodes சேர்க்கலாம்.

### Step 4: Bengaluru TCO

Self-hosted n8n-க்கு ஒரு run-க்கு fee இல்லை, ஆனா அது free இல்லை. ஒரு illustration-க்காக மட்டும், ஒரு cloud server மாசத்துக்கு ₹3,000 ஆகுது, ஒரு developer மாசத்துக்கு 4 மணி நேரம் updates, backups, fail ஆன runs-க்கு மணிக்கு ₹1,000 கணக்குல செலவு பண்றாருன்னு வச்சுக்கோங்க. Setup-ஐயும் AI model-ஓட சொந்த செலவையும் சேர்க்குறதுக்கு முன்னாடியே TCO சுமார் ₹3,000 + ₹4,000 = மாசத்துக்கு ₹7,000. ஆளுங்களோட நேரம் தான் ஏற்கனவே பெரிய பகுதி, clients மறக்குற பகுதியும் அது தான்.

அப்புறம் ஒவ்வொரு client-க்கும் ஒரு பக்க recommendation எழுதுவீங்க: tool, எதிர்பார்க்குற volume-ல cost (ஒவ்வொரு price-ஐயும் check பண்ண date-ஓட), data எங்க process ஆகுது, யார் maintain பண்றாங்க.

## பொதுவா பண்ற தப்புகள்

- **சொந்த விருப்பத்தை வச்சு தேர்ந்தெடுக்குறது.** Client-ஓட apps, skills, volume, data rules வச்சு தேர்ந்தெடுங்க.
- **Units-க்கு பதிலா headline prices-ஐ compare பண்றது.** முதல்ல ஒரு run-ஐ tasks, credits அல்லது executions-ஆ மாத்துங்க, அப்புறம் plan-ஐ கண்டுபிடிங்க.
- **Make-ஓட polling triggers credits use பண்ணும்ங்குறதை மறக்குறது.** 15 நிமிஷ check, புது items zero-வா இருந்தாலும் மாசத்துக்கு சுமார் 2,880 credits ஆகும். முடிஞ்ச இடத்துல ஒரு instant trigger use பண்ணுங்க.
- **n8n-ஐ open source-னு சொல்றது.** அது source-available. Clients use பண்றதுக்காக அதை host பண்ணணும்னா n8n கூட ஒரு deal வேணும்.
- **AI step-ஓட data path-ஐ மறக்குறது.** Model call data-வை வெளிய அனுப்புனா, workflow-ஐ self-host பண்றது உதவாது.
- **Attended போதும்போது unattended RPA வாங்குறது.** ஒரு per-bot licence, ஒரு per-user licence-ஐ விட சுமார் பத்து மடங்கு விலை.
- **ஏற்கனவே இருக்குற licences-ஐ கவனிக்காம விடுறது.** நிறைய business Microsoft 365 plans-ல standard connectors கூட cloud flows ஏற்கனவே இருக்கு.
- **Owner இல்லாம self-host பண்றது.** Servers-க்கு security updates, backups, monitoring வேணும்.
- **Failure alert இல்லாதது.** Fail ஆன ஒரு run பேர் சொல்லப்பட்ட ஒரு ஆளுக்கு போய் சேரலைன்னா, automation அமைதியா வேலை செய்யுறதை நிறுத்திடும்.
- **பழைய prices-ஐ quote பண்றது.** இப்போதைய price pages-ஐ check பண்ணி date-ஐ record பண்ணுங்க.

## Practice பண்ணுங்க

கீழ link பண்ணியிருக்குற Power Automate பத்தின ஒரு Microsoft Learn module-ஐ பண்ணுங்க, Zapier-ஓட guides-ஐ browse பண்ணுங்க; n8n பத்தி உங்களுக்கு தெரிஞ்சதோட compare பண்ணுங்க.

1. **ரெண்டு தடவை build பண்ணுங்க.** Form-ல இருந்து sheet, அப்புறம் email மாதிரி ஒரே simple workflow-ஐ ரெண்டு tools-ல build பண்ணுங்க. எடுத்த நேரம், வந்த கஷ்டங்கள், fail ஆன ஒரு run உங்களுக்கு எப்படி காட்டப்படுதுன்னு note பண்ணுங்க.
2. **Count பண்ணுங்க, அப்புறம் cost போடுங்க.** ஒரு trigger, அஞ்சு actions இருக்குற ஒரு workflow-ஐ எடுங்க. ஒரு run-ஐ Zapier tasks, Make credits, n8n executions-ஆ மாத்துங்க. அப்புறம் இன்னைக்கு price pages-ஐ use பண்ணி, ரெண்டு tools-ல மாசத்துக்கு 200, 2,000, 20,000 runs-ல பொருந்துற plan-ஐ கண்டுபிடிங்க. நீங்க check பண்ண date-ஐ எழுதி வைங்க.
3. **Recommend பண்ணுங்க.** நீங்க தேர்ந்தெடுக்குற ஒரு client-க்கு ஒரு பக்க recommendation எழுதுங்க: fit, எதிர்பார்க்குற volume-ல cost, data எங்க process ஆகுது, lock-in, யார் maintain பண்ணுவாங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** விவரிக்கப்பட்ட ஒரு client-க்கு ஒரு tool-ஐ recommend பண்ணி, cost, data, maintenance அடிப்படையில அந்த தேர்வை defend பண்ண முடியும், நீங்க quote பண்ற ஒவ்வொரு number-க்கும் date போட்ட ஒரு price-ஓட.
