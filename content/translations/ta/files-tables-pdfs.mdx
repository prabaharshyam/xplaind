## இது என்ன

Client சுத்தமான database-ஐ கொடுக்கிறது ரொம்ப அபூர்வம். ஒரு shared folder அனுப்புவாங்க: merged headers இருக்குற Excel sheets, பழைய billing system-ல இருந்து export பண்ண CSVs, ஒரு vendor-ஓட API-ல இருந்து JSON, அப்புறம் நூத்துக்கணக்கான PDFs; சில digital, சில scan. இதுல இருந்து நம்பகமா text, numbers-ஐ எடுக்கிறதுக்கு பேரு **document parsing**. பெரும்பாலான AI projects-ல இதுதான் முதல் உண்மையான வேலை. இந்த step தப்பா போனா, இதன் மேல build பண்ண எல்லா பதிலுமே தப்பாத்தான் இருக்கும்.

File type-ஐ பொறுத்து வேலை பிரியுது:

| File type | பொதுவா என்ன தப்பாகும் | முக்கிய tool |
| --- | --- | --- |
| **CSV, Excel** | Encodings, காணாம போற leading zeros, Indian number, date formats, banner rows | pandas |
| **JSON** | ரொம்ப ஆழமான nesting, records உள்ள lists | `json`, `pd.json_normalize` |
| **Digital PDF** | Columns கலந்துடும், headers, footers திரும்ப திரும்ப வரும், வார்த்தைகள் உடையும் | pypdf, pdfplumber |
| **Scanned PDF** | Text-ஏ இல்லை, images மட்டும் | OCR, Tesseract அல்லது cloud service மாதிரி |
| **PDF tables** | Table ஒரு குழப்பமான line-ஆ வரும் | pdfplumber, Camelot, அல்லது vision தெரிஞ்ச model |

```flow
Client folder -[.csv அல்லது .xlsx]-> தெளிவான options-ஓட pandas -> சுத்தமான table
Client folder -[.json]-> json + json_normalize -> Flat table
Client folder -[.pdf]-> ஒவ்வொரு page-க்கும் text எடுங்க
ஒவ்வொரு page-க்கும் text எடுங்க -[போதுமான text இருக்கு]-> Page numbers-ஓட வச்சுக்கோங்க
ஒவ்வொரு page-க்கும் text எடுங்க -[கிட்டத்தட்ட இல்லை]-> OCR -> Spot-check
ஒவ்வொரு page-க்கும் text எடுங்க -[tables இருக்கு]-> Table tool -> Rows-ஐ check பண்ணுங்க
```

இந்த lesson-ல Madurai-ல ஒரு hospital chain-ஐ follow பண்றோம். அவங்க policies-உம் pharmacy price list-உம் ஒரு assistant-க்கு போகணும். Lesson முடியும்போது messy tables-ஐ சரியா load பண்ணவும், எந்த PDFs-க்கு OCR வேணும்னு கண்டுபிடிக்கவும் தெரிஞ்சிருக்கும்.

## இது எப்படி work ஆகுது

### CSV, Excel

`pd.read_csv`, `pd.read_excel` பெரும்பாலான வேலையை பண்ணிடும், ஆனா அவங்க defaults சுத்தமான data-னு நினைச்சு எழுதினது. Real files-க்கு options வேணும்:

| பிரச்சனை | Option |
| --- | --- |
| Tamil அல்லது Hindi பெயர்கள் garble ஆகுது | `encoding="utf-8"`, Excel byte-order mark-க்கு `"utf-8-sig"`. Garble ஆகுதுன்னா பெரும்பாலும் UTF-8-ஐ `cp1252`-ஆ படிச்சிருக்காங்க; அதுல இந்திய scripts-ஐ வைக்க முடியாது |
| Item codes, branch codes, landline numbers-ல leading zeros போயிடுது | id மாதிரி columns-க்கு `dtype={"item_code": str}` |
| 05/11/2026 மாதிரி dates | `parse_dates`-ஓட `dayfirst=True` |
| Header-க்கு மேல banner rows | `skiprows` |
| உடைஞ்ச rows load-ஐயே crash பண்ணுது | அவற்றை பார்க்க `on_bad_lines="warn"` |

"1,25,000" மாதிரி Indian number formats-ஐ numbers-ஆ மாத்துறதுக்கு முன்னாடி commas-ஐ எடுக்கணும்.

### Excel-ஓட வித்தியாசமான குணங்கள்

Excel files-ல தனி surprises இருக்கு. ஒரு workbook-ல பல sheets இருக்கலாம்: ஒண்ணை `sheet_name="Rates"` வச்சு படிக்கலாம், எல்லாத்தையும் `sheet_name=None` வச்சு படிக்கலாம்; அப்போ tables-ஓட ஒரு dictionary கிடைக்கும். Merged header cells ஒரு நிரம்பின cell-ஆவும் சில காலி cells-ஆவும் வரும்; அதனால header-ஐ கையால rebuild பண்ணுங்க, இல்லன்னா ரெண்டு header rows-க்கு `header=[0, 1]`. Hidden rows, columns-உம் படிக்கப்படும்; formulas கடைசியா save பண்ண values-ஆ வரும், formulas-ஆ வராது. சந்தேகம் வந்தா code எழுதுறதுக்கு முன்னாடி file-ஐ திறந்து பாருங்க.

### JSON

`json.load` nested dictionaries, lists-ஐ தரும். `pd.json_normalize` records-ஓட list-ஐ ஒரு table-ஆ flatten பண்ணும்; nested fields-க்கு `customer.city` மாதிரி dotted column names கிடைக்கும்.

### PDFs

PDF-னா paragraphs இருக்குற document இல்ல; drawing instructions-ஓட ஒரு set. pypdf, pdfplumber மாதிரி libraries digital PDFs-ல இருந்து text எடுக்கும், ஆனா columns கலந்துடலாம், headers, footers ஒவ்வொரு page-லயும் repeat ஆகலாம், வார்த்தைகள் விசித்திரமா உடையலாம்.

**Text-ஏ வராத** PDF பெரும்பாலும் scan தான்: அதுல images மட்டும் இருக்கும், அதனால **OCR** (optical character recognition) வேணும். இந்திய மொழிகளுக்கு சரியான OCR language pack-ஐ install பண்ணுங்க. Tables-க்கு table தெரிஞ்ச tool அல்லது vision தெரிஞ்ச model வேணும்.

ஒவ்வொரு text துண்டோடயும் **page number**-ஐ எப்பவும் record பண்ணுங்க. பின்னாடி citations-உம் debugging-உம் அதை நம்பியிருக்கு.

### Checks

ஒவ்வொரு extraction-க்கு அப்புறமும் எண்ணிப் பாருங்க, ஒப்பிடுங்க: உள்ள போன rows vs வெளியே வந்த rows, text இல்லாத pages, ஒத்து வர வேண்டிய totals. அப்புறம் ஐஞ்சு random samples-ஐ print பண்ணி படிங்க. ஐஞ்சு நிமிஷம் படிக்கிறது எந்த count-உம் காட்டாத பிரச்சனைகளை கண்டுபிடிக்கும்.

## ஒரு example

Madurai-ல ஒரு hospital chain தங்க policies-மேலயும் pharmacy price list-மேலயும் ஒரு assistant வேணும்னு கேக்குறாங்க. ஒரு ZIP file அனுப்புறாங்க.

**Price list CSV.** பழைய loading script `encoding="cp1252"` வச்சதால Tamil drug names garble ஆகுது. உண்மையில அது Excel சேர்த்த byte-order mark-ஓட இருக்குற UTF-8 file, அதனால `encoding="utf-8-sig"` fix பண்ணிடும். "000412" மாதிரி item codes zeros-ஐ இழந்துடுச்சு; `dtype={"item_code": str}` அதை காப்பாத்தும். "1,250.00" மாதிரி prices commas-ஐ எடுத்ததும் numbers ஆகிடும்.

**Policy PDFs.** 140 PDFs-ல 122-ல இருந்து pypdf text எடுக்குது. ஒரு quick check, கிட்டத்தட்ட ஒண்ணுமே தராத 18-ஐ flag பண்ணுது:

```python
from pathlib import Path
from pypdf import PdfReader

pdfs = sorted(Path("policies").glob("*.pdf"))
needs_ocr, records = [], []

for path in pdfs:
    reader = PdfReader(path)
    pages = [p.extract_text() or "" for p in reader.pages]
    chars = sum(len(p) for p in pages)
    if chars < 200 * len(pages):
        needs_ocr.append(path)       # probably scanned
    else:
        for n, text in enumerate(pages, 1):
            records.append({"file": path.name, "page": n, "text": text})
```

அந்த 18-உம் scan பண்ண circulars. OCR அதை படிக்குது; மூணை images-ஓட ஒப்பிட்டு spot-check பண்ணா, Tamil OCR language pack சேர்க்குற வரைக்கும் Tamil headers தப்பா இருக்குன்னு தெரியுது.

| Item | எண்ணிக்கை | பிரச்சனை | Fix |
| --- | --- | --- | --- |
| Price list rows | 4,812 | Garble ஆன பெயர்கள், போன zeros, text prices | `utf-8-sig`, `dtype=str`, commas-ஐ எடுக்குறது |
| Digital PDFs | 122 | Repeat ஆகுற headers, footers | பெரும்பாலான pages-ல repeat ஆகுற lines-ஐ நீக்குறது |
| Scanned PDFs | 18 | Text இல்லை | English, Tamil packs-ஓட OCR |
| இன்னும் fail ஆன pages | 6 | மங்கலான photocopies | Client மறுபடி அனுப்ப list பண்ணது |

Client-க்கான notes-ல எந்த files-க்கு OCR வேண்டி வந்தது, எந்த pages fail ஆச்சுன்னு துல்லியமா இருக்கு. அதனால ஒரு மங்கலான circular பத்தின பதில் பலவீனமா இருந்தா யாருக்கும் அதிர்ச்சி இருக்காது.

## பொதுவா பண்ற தப்புகள்

- **Defaults-ஐ நம்புறது.** pandas types-ஐ guess பண்ணும்; 000412 மாதிரி item codes-ஐ numbers-ஆ மாத்தி leading zeros-ஐ விட்டுடும். id மாதிரி columns-க்கு types-ஐ நீங்களே set பண்ணுங்க.
- **Encodings-ஐ கவனிக்காம விடுறது.** இந்திய scripts-ல garble ஆன பெயர்கள் கிட்டத்தட்ட எப்பவும் தப்பான encoding-னு அர்த்தம், உடைஞ்ச file-னு இல்லை.
- **எல்லா PDF-லயும் text இருக்குன்னு நினைக்கிறது.** Scans சத்தமில்லாம empty strings-ஐ தரும். ஒரு page-க்கு characters-ஐ அளந்து பாருங்க.
- **Page number-ஐ இழக்கிறது.** அது இல்லாம source-ஐ cite பண்ணவோ, தப்பான பதிலை debug பண்ணவோ முடியாது.
- **Dates-ஐ month-first-ஆ படிக்கிறது.** இந்தியாவுல 05/11/2026 னா 5 November; `dayfirst=True` set பண்ணுங்க.
- **Output-ஐ படிக்கவே படிக்காம இருக்கிறது.** ஐஞ்சு random samples காட்டுற பிரச்சனைகளை counts தவறவிட்டுடும்.

## Practice பண்ணுங்க

கீழே link பண்ணியிருக்குற pandas IO page-ல CSV, Excel sections-ஐயும், pypdf-ஓட text extraction page-ஐயும் படிங்க.

1. **ஒரு messy CSV.** நீங்களே ஒண்ணு செய்ங்க: ஒரு banner row, Indian-format numbers, 05/11/2026 மாதிரி dates, leading zeros இருக்குற ஒரு item-code column, byte-order mark-ஓட save பண்ண Tamil அல்லது Hindi name column. அதை சரியா load பண்ணுங்க.
2. **மூணு PDFs.** ஒரு digital government circular, ஒரு scanned circular, tables இருக்குற ஒண்ணு, இந்த மூணையும் download பண்ணுங்க. Page numbers-ஓட text எடுங்க; scanned-ஐ தானா கண்டுபிடிங்க.
3. **ஒரு report.** சின்னதா ஒரு report எழுதுங்க: files, pages, text இல்லாத pages, ஒவ்வொண்ணுக்கும் என்ன பண்ணுவீங்கன்னு.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** ஒரு PDF ஏன் empty text தரலாம்னு explain பண்ண முடியும், leading zeros-ஐ வச்சுக்கிட்டு Indian dates-ஐ சரியான order-ல படிக்குற ஒரு CSV-ஐ load பண்ண முடியும்.
