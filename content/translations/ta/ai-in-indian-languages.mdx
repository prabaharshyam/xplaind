## இது என்ன

Language models web-ல இருக்குற text-ல இருந்து கத்துக்கும், web பெரும்பாலும் English. பரவலா use ஆகுற ஒரு training dataset-ல, text-ல சுமார் 46% English. அதோட ஒப்பிடும்போது இந்திய மொழிகள் ரொம்ப சின்னது:

| பஞ்சாபி | 113 | 0.006% | 230 மடங்கு |

கடைசி column, ஒவ்வொரு மொழியோட உலக மக்கள் தொகை பங்கையும், dataset-ல அதோட பங்கையும் ஒப்பிடுது. இந்த numbers Common Crawl web dataset பத்தின 2023 study-ல இருந்து, Chip Huyen-ஓட *AI Engineering*-ல குறிப்பிடப்பட்டது. எத்தனை பேர் பேசுறாங்கங்கிறதோட ஒப்பிடும்போது training text குறைவா இருக்குற இந்த மாதிரி மொழிகளை **low-resource languages**ன்னு சொல்றாங்க.

இது மூணு practical problems-ஐ உருவாக்குது:

1. **குறைவான quality.** பொது அறிவுக்கான ஒரு பிரபலமான test-ல, ஒரு முன்னணி model Telugu, Marathi, Punjabi-ல மோசமா score பண்ணுச்சு; test பண்ண மொழிகள்ல இவை தான் ரொம்ப குறைவா represent ஆனவை.
2. **அதிக cost, delay.** **Tokenizer** text-ஐ tokens-ஆ பிரிக்கும், பல tokenizers முக்கியமா English-க்காக design பண்ணப்பட்டவை. Hindi அல்லது Tamil-ல அதே வாக்கியத்துக்கு பல மடங்கு அதிக tokens தேவைப்படலாம். இதுக்கு பேரு அதிக **token fertility**. நீங்க ஒரு token-க்கு பணம் கட்டுறீங்க, models ஒரு நேரத்துல ஒரு token-ஐ தான் எழுதும்; அதனால அதே பதில் அதிகமா செலவாகி, மெதுவா வரும்.
3. **Real usage குழப்பமானது.** இந்தியர்கள் மொழிகளை கலப்பாங்க ("mera order kab aayega?"), scripts-ஐ மாத்துவாங்க, இந்திய மொழிகளை Roman letters-ல type பண்ணுவாங்க. சுத்தமான, formal text-ல மட்டும் செஞ்ச test sets இதெல்லாத்தையும் miss பண்ணும்.

நிலைமை மேம்படுது: புது tokenizers இந்திய scripts-ஐ ரொம்ப நல்லா handle பண்றாங்க, இந்திய குழுக்கள் இந்திய மொழிகளுக்கு models, data-வை build பண்றாங்க. ஆனாலும் உங்க users-க்கு, மொழி வாரியா அளந்து பார்க்கணும்.

## இது எப்படி work ஆகுது

**Token fertility-ஐ நீங்களே அளந்து பாருங்க.** நீங்க யோசிக்கிற ஒவ்வொரு model-ஓட tokenizer-ஐயும் வச்சு, அதே message-ஐ English-லயும் உங்க users-ஓட மொழிகள்லயும் tokens எண்ணுங்க. வார்த்தைக்கு வார்த்தை translation இல்லாம, அதே அர்த்தத்தை எழுதுங்க.

```python
# pip install tiktoken
import tiktoken

texts = {
    "English": "When will my order arrive? I paid yesterday.",
    "Hindi": "मेरा ऑर्डर कब आएगा? मैंने कल भुगतान किया था।",
    "Hinglish": "Mera order kab aayega? Maine kal payment kiya tha.",
    "Tamil": "என் ஆர்டர் எப்போது வரும்? நான் நேற்று பணம் செலுத்தினேன்.",
}
for name in ["cl100k_base", "o200k_base"]:          # an older and a newer tokenizer
    enc = tiktoken.get_encoding(name)
    counts = {lang: len(enc.encode(t)) for lang, t in texts.items()}
    base = counts["English"]
    print(name, {lang: f"{n} ({n / base:.1f}x)" for lang, n in counts.items()})
```

Run பண்ணா, புது tokenizer Hindi, Tamil counts-ஐ கணிசமா குறைக்கிறதை பொதுவா பார்ப்பீங்க; Romanised Hinglish English-க்கு பக்கத்துலயே இருக்கும். மத்த providers வேற tokenizers use பண்றாங்க, அதனால நீங்க யோசிக்கிற ஒவ்வொண்ணையும் check பண்ணுங்க.

**ஒரு மொழிக்கு service கொடுக்க மூணு வழிகள்.**

- **ஒரு general model, நேரா.** ரொம்ப எளிது. வலுவான சமீபத்திய models Hindi-ல பெரும்பாலும் நல்லா இருக்கும், குறைவான resource இருக்குற மொழிகள்ல பலவீனமா. நம்புறதுக்கு முன்னாடி test பண்ணுங்க.
- **Translate, பதில் சொல்லு, திரும்ப translate.** வலுவான இந்திய மொழி translation model-ஐ (AI4Bharat-ஓட open IndicTrans2 மாதிரி) வச்சு கேள்வியை English-க்கு translate பண்ணி, English-ல பதில் சொல்லி, திரும்ப translate பண்ணுங்க. பலவீனமான மொழிகளுக்கு quality-ஐ உயர்த்தலாம், ஆனா steps, delay, தப்புகளை சேர்க்கும், நுணுக்கத்தையும் இழக்கும்: *aap*, *tum* மாதிரி மரியாதை குறிப்புகள் "you"-ன்னு ஒண்ணா ஆயிடும், உள்ளூர் வார்த்தைகள் தப்பா translate ஆகலாம்.
- **இந்திய மொழிகளுக்காக build பண்ண ஒரு model.** இந்திய startups, research groups இன்னும் நிறைய இந்திய மொழி text-ல models, tokenizers-ஐ train பண்றாங்க. அரசாங்கத்தோட Bhashini platform translation, speech services தருது. இவை இந்திய மொழிகளுக்கு வலுவாவும் மலிவாவும் இருக்கலாம், ஆனா எந்த model-ஐயும் போல உங்க சொந்த test set-ல compare பண்ணுங்க.

**Speech-உம் முக்கியம்.** நிறைய users type பண்றதை விட பேசவே விரும்புவாங்க, குறிப்பா நகரங்களுக்கு வெளியே. Speech recognition quality மொழி, accent, background noise-ஐ பொறுத்து மாறும், அதனால உங்க users-ஓட real recordings வச்சு test பண்ணுங்க.

| Approach | பலவீனமான மொழிகள்ல Quality | Cost, வேகம் | முக்கிய risk |
| --- | --- | --- | --- |
| General model, நேரா | மாறும்; மொழி வாரியா check பண்ணுங்க | Tokenizers திறமையில்லாத இடங்கள்ல அதிகமா இருக்கலாம் | விறைப்பான மொழி, தப்பான உள்ளூர் வார்த்தைகள் |
| English-க்கு translate பண்ணி திரும்ப | பலவீனமான மொழிகளுக்கு பெரும்பாலும் better | கூடுதல் steps, delay | நுணுக்கம் போறது, பெயர்கள் தப்பா translate ஆகுறது |
| இந்திய மொழி model | இந்திய மொழிகள்ல பெரும்பாலும் வலுவானது | பெரும்பாலும் திறமையான tokenizers | பொது அறிவு குறுகலா இருக்கலாம்; check பண்ணுங்க |
| மேல இருக்குற எதோடவும் உள்ளூர் facts-ஐ retrieve பண்றது | Schemes, prices, பெயர்கள்ல better | சின்ன கூடுதல் cost | ஒவ்வொரு மொழியிலயும் sources-ஐ current-ஆ வச்சுக்கணும் |

**Browser-ல try பண்ணுங்க.** அதே message இந்திய scripts-ல அதிக bytes எடுக்கும், tokens பெரும்பாலும் bytes-ஐ தொடரும். உங்க சொந்த வாக்கியங்களை try பண்ணுங்க.

```python
samples = {
    "English": "Please send the electricity bill",
    "Hindi": "कृपया बिजली का बिल भेजें",
    "Tamil": "தயவுசெய்து மின்சார கட்டணத்தை அனுப்புங்கள்",
}
for lang, text in samples.items():
    chars, utf8 = len(text), len(text.encode("utf-8"))
    print(f"{lang:<8} {chars:>3} characters, {utf8:>3} UTF-8 bytes, {utf8 / chars:.1f} bytes per character")
```

## ஒரு worked example

Pune-ல ஒரு agritech company, மாசத்துக்கு சுமார் 50,000 கேள்விகளோட, chat, voice வழியா Marathi, Hindi-ல விவசாயிகளுக்கு ஒரு helpline build பண்றாங்க. நிறைய விவசாயிகள் Marathi-ஐ Roman script-ல type பண்றாங்க.

அவங்க 300 real கேள்விகளோட ஒரு test set build பண்றாங்க: Marathi, Hindi, Devanagari, Roman script, பயிர்கள், வானிலை, schemes பத்தி, தாய்மொழி பேசுற agronomists check பண்ணது. அப்புறம் மூணு options-ஐ compare பண்றாங்க.

| Option | சரியானது, இயல்பானது (Marathi) | சரியானது, இயல்பானது (Hindi) | ஒரு பதிலுக்கு average tokens | 1,000 பதில்களுக்கு cost |
| --- | --- | --- | --- | --- |
| General model, நேரா | 68% | 82% | 410 | ₹310 |
| English-க்கு translate பண்ணி, பதில் சொல்லி, திரும்ப translate | 76% | 81% | 190 (English) + translation | ₹260 |
| Retrieval-ஓட இந்திய மொழி model | 84% | 86% | 230 | ₹150 |

இந்த numbers compare பண்றது எப்படின்னு காட்ட மட்டும், உதாரணத்துக்கு. எல்லா options-லயும் scheme பெயர்கள் தான் தப்புகளோட பெரிய source, அதனால team Marathi, Hindi-ல அதிகாரப்பூர்வ scheme pages-ஐ retrieve பண்றதையும், சரியான பெயர்களுக்கு ஒரு glossary-யையும் சேர்க்குது. Quality-ஐ மொழி வாரியா தொடர்ந்து monitor பண்றாங்க, ஏன்னா ஒரு model update Hindi-ஐ மேம்படுத்தி, Marathi-ஐ அமைதியா பாதிக்கலாம்.

## பொதுவா பண்ற தப்புகள்

- **English-ல மட்டும் test பண்ணிட்டு**, அஞ்சு மொழிகள்ல launch பண்றது.
- **Formal, Devanagari text-ல மட்டும் test பண்றது.** Real users மொழிகளை கலப்பாங்க, Roman script-ல type பண்ணுவாங்க.
- **Token counts-ஐ கண்டுக்காம இருக்குறது.** English-ல மலிவான ஒரு feature, Tamil-ல பல மடங்கு அதிகமா செலவாகலாம்.
- **எல்லாத்தையும் வார்த்தைக்கு வார்த்தை translate பண்றது.** பெயர்கள், schemes, மரியாதை வடிவங்கள் பெரும்பாலும் உடையும்.
- **"இந்திய மொழிகள்"-ஐ ஒண்ணா நினைக்கிறது.** Hindi-ல quality, Odia அல்லது Assamese பத்தி எதுவும் சொல்லாது.
- **Evaluation-ல தாய்மொழி பேசுறவங்கள விட்டுடுறது.** சரளமா தெரியுற text கூட தப்பாவோ இயல்பில்லாததாவோ இருக்கலாம்.
