## இது என்ன

**Portfolio**-னா உங்களால அந்த வேலையை செய்ய முடியும்ங்குறதுக்கான evidence. AI engineering, forward deployed engineer (FDE) roles-க்கு அதுல பொதுவா அஞ்சு பகுதிகள் இருக்கும்:

- **ஒரு GitHub profile**, உங்க best மூணுல இருந்து அஞ்சு projects-ஓட ஆரம்பிக்கும், ஒவ்வொண்ணுக்கும் தெளிவான README இருக்கும்.
- ஒண்ணு ரெண்டு projects பத்தின **case-study write-ups**: problem, numbers, decisions, results, எது தப்பா போச்சுன்னு.
- **ஒரு resume**, ஒரு page (experienced engineers-க்கு அதிகபட்சம் ரெண்டு), duties இல்லாம results-ஐ list பண்ணும்.
- அதே கதையை சொல்ற **ஒரு LinkedIn profile**, ஏன்னா நிறைய இந்திய recruiters அங்க தான் தேடுறாங்க.
- **விருப்பப்பட்டா**, சின்ன demo videos, நீங்க கத்துக்கிட்டது பத்தி சில public posts.

**Job search**-னா இந்த evidence-ஐ சரியான ஆளுங்க முன்னாடி, சரியான நேரத்துல, சரியான சம்பளத்துக்கு கொண்டு போற plan.

```flow
title: ஒரே link, 60 seconds: github.com/you
Profile README -> Pinned: enterprise RAG assistant | "recall at 5: 68% to 93% on my 60-question golden set"
Profile README -> Pinned: operations agent with approvals | "0 unapproved actions in 200 scripted test runs"
Profile README -> Pinned: document QA API | "96% field accuracy on 300 synthetic files; 4 s per file"
Profile README -> Case study: hospital chain capstone | 3 pages, கூடவே ஒரு 2-minute video
```

```flow
dir: LR
title: Search எப்படி போகும்
40 target companies -> 15-ல referrals அல்லது contacts -> Coding test, interviews -> Fixed pay வச்சு offers compare -> Notice முடிச்சு join
```

## இது எப்படி work ஆகுது

### வேலைக்கு ஏத்த projects-ஐ தேர்ந்தெடுங்க

FDE roles-க்கு, இந்த path-ல இருக்குற stage projects மாதிரி, realistic client problem, குழப்பமான data, evals, deployment, governance இருக்குற projects-ஐ தேர்ந்தெடுங்க. பத்து tutorials-ஐ விட முடிச்ச மூணு projects better, ஏன்னா interviewers ஒண்ணை எடுத்து அரை மணி நேரம் அதைப் பத்தி கேள்வி கேப்பாங்க.

### Sell பண்ற READMEs

ஒவ்வொரு README-யையும் problem பத்தி ஒரு வாக்கியம், ஒரு screenshot அல்லது 60-second video-ல ஆரம்பிங்க. அப்புறம் number-ஓட result, ஒரு சின்ன architecture diagram, அதை எப்படி run பண்றதுன்னு குடுங்க. இந்த repositories-ஐ pin பண்ணுங்க, உங்க case studies-க்கு link பண்ற ஒரு profile README சேருங்க.

ஒரு reviewer test பண்ற மாதிரியே நீங்களும் test பண்ணுங்க. ஒரு friend-கிட்ட ஒரு project-ஐ clone பண்ணி README-ஐ மட்டும் வச்சு run பண்ண சொல்லுங்க. 10 நிமிஷத்துக்கு மேல ஆனா, அல்லது உங்களுக்கு message பண்ண வேண்டி வந்தா, README-ஐ சரி பண்ணுங்க அல்லது ஒரு hosted demo சேருங்க.

### Defend பண்ண முடியுற numbers

உங்க portfolio-ல இருக்குற ஒவ்வொரு number-உம் கேள்வி கேக்க ஒரு அழைப்பு. Interviewers கேப்பாங்க: "இது எதுல அளந்தது? காட்ட முடியுமா?" மூணு rules-ஐ follow பண்ணுங்க:

1. **Test set-ஓட பேரையும் size-ஐயும் சொல்லுங்க.** "96% field accuracy"-னா அது ஒரு claim. "நான் உருவாக்குன 300 synthetic insurance files-ல 96% field accuracy"-னா அது evidence.
2. **Data எங்க இருந்து வந்ததுன்னு நேர்மையா சொல்லுங்க.** கற்பனையான ஒரு hospital chain-க்கான capstone பரவாயில்ல. அதை "discharge delays-ஐ 30% குறைச்சுது"-னு சொல்றது சரியில்ல, ஏன்னா எந்த hospital-உம் அதை use பண்ணல. நீங்க என்ன அளந்தீங்களோ அதை சொல்லுங்க: accuracy, latency, ஒரு request-க்கு cost.
3. **Eval-ஐ run பண்ற மாதிரியே வச்சிருங்க.** Golden set-ஐயும் eval script-ஐயும் repository-லயே வைங்க, கேட்டா live-ஆ திரும்ப run பண்ணலாம்.

நீங்க explain பண்ண முடியாத பெரிய number-ஐ விட, explain பண்ண முடியுற சுமாரான number better.

### Resume, screening software, LinkedIn

**Results-ஓட bullets.** Pattern: action, நீங்க என்ன build பண்ணீங்க, அளந்த ஒரு result. உதாரணமா: "Built a RAG assistant over 4,000 pages of insurance policies with hybrid search and reranking; raised retrieval recall at 5 from 68% to 93% on a 60-question golden set."

**முதல் பார்வை ரொம்ப சின்னது.** 2018-ல ஒரு eye-tracking study-ல, Ladders-ங்குற job site, ஒவ்வொரு resume-வையும் முதல் தடவை பார்க்க recruiters சுமார் 7.4 seconds செலவழிச்சாங்கன்னு கண்டுபிடிச்சுது. அவங்க பெரும்பாலும் titles, companies, dates-ஐ தான் பார்த்தாங்க. தெளிவான headings உள்ள simple layouts கவனத்தை பிடிச்சு வச்சுது; நெரிசலான, multi-column layouts மோசமா போச்சு. அதோட sample size சொல்லப்படல, ஆனா பாடம் அப்படியே தான்: உங்க results-லயே strongest-ஆனதை top third-ல வைங்க.

**Applicant tracking systems.** நிறைய employers resumes-ஐ ஒரு applicant tracking system (ATS)-ல load பண்றாங்க; அது applications-ஐ store பண்ணி, recruiters keyword வச்சு filter பண்ண விடுற software. Two-column templates, images-ல இருக்குற text, icons எல்லாம் கலைஞ்சு வரலாம், அதனால ஒரு column, standard headings (Experience, Projects, Skills, Education), text-based PDF use பண்ணுங்க. Job post-ல இருக்குற exact terms-ஐ ("RAG", "LangGraph", "AWS") திரும்ப சொல்ற ஒரு சின்ன skills line சேருங்க, அவை உண்மையா இருக்குற வரை. மத்த இடங்கள்ல, நீளமான keyword list-க்கு பதிலா, tools-ஐ உங்க result bullets-க்குள்ள context-ஓட வைங்க.

**LinkedIn.** உங்க GitHub profile-ல இருக்குற அதே headline-ஐ use பண்ணுங்க, உதாரணமா "Backend engineer building RAG and agent systems for healthcare". Featured section-ல ஒரு project-ஐ pin பண்ணுங்க, உங்க best ரெண்டு results-ஓட ஒரு சின்ன About section எழுதுங்க. நீங்க open to work-னு mark பண்ண LinkedIn விடுது; வேணும்னா recruiters-க்கு மட்டும் தெரியுற மாதிரி வைக்கலாம்.

### Referrals, outreach

இந்தியால, ஒரு மனுஷன் உங்க resume-ஐ படிக்க வைக்க referral தான் பெரும்பாலும் fastest வழி. நிறைய companies employee referral programmes நடத்துறாங்க, அதனால நீங்க hire ஆனா referrer-க்கு bonus கிடைக்கலாம். அதனால இது நியாயமான request, favour இல்ல. ஆனா referrer உங்களுக்காக தன் பேரை வைக்குறாங்க, அதனால அவங்களுக்கு சுலபமாவும் safe-ஆவும் ஆக்குங்க:

- **முதல்ல உங்களைத் தெரிஞ்சவங்ககிட்ட கேளுங்க:** college alumni, பழைய colleagues, seniors, open-source projects, meetups-ல பழக்கமானவங்க.
- **எல்லாத்தையும் ஒரே தடவையில அனுப்புங்க:** job link அல்லது ID, உங்க resume, உங்க projects-லயே ரொம்ப relevant-ஆன ஒண்ணு பத்தியும் அதோட result பத்தியும் ரெண்டு lines.
- **தெரியாதவங்ககிட்ட referral கேக்காதீங்க, ஒரு conversation கேளுங்க.** நாலு வாக்கியங்கள்: நீங்க யாரு, relevant-ஆன ஒரு project-உம் அதோட result-உம், ஒரு குறிப்பான கேள்வி, நன்றி. உதாரணமா: "நான் Coimbatore-ல ஒரு backend developer, AI engineering-க்கு மாறிட்டு இருக்கேன். 300 synthetic test files-ல 96% field accuracy இருக்குற ஒரு claims-document assistant-ஐ build பண்ணேன், உங்க team insurers-க்கு விக்குறதுக்கு கிட்டத்தட்ட அதே மாதிரி. உங்க FDE team எப்படி work பண்ணுதுன்னு சொல்ல உங்களுக்கு 15 நிமிஷம் கிடைக்குமா? நன்றி." நல்ல conversation-க்கு அப்புறம் referrals பெரும்பாலும் தானா வரும்.

Context இல்லாத "Please refer me"-க்கு reply வர்றது அரிது.

### Coding round

நிறைய இந்திய product companies, GCCs, IT services firms, HackerRank அல்லது HackerEarth மாதிரி ஒரு platform-ல online coding test-ஓட ஆரம்பிக்குறாங்க. Candidates சொல்ற reports-ல பெரும்பாலும் ஒண்ணுல இருந்து ரெண்டு மணி நேரம், data structures and algorithms (DSA)-ல ரெண்டு மூணு easy-to-medium problems இருக்கும்: arrays, strings, hash maps, two pointers, sorting, trees, graph search, சில சமயம் basic dynamic programming. Cut-off scores இருக்குன்னும் candidates சொல்றாங்க, அதனால இந்த step-ல fail ஆனா உங்க strong portfolio-வை யாரும் பார்க்காமலே போகலாம்.

FDE, AI-startup loops practical coding பக்கம் அதிகமா சாயும்: குழப்பமான data-வை clean பண்றது, ஒரு API-ஐ call பண்றது, validation, tests சேர்க்குறது ("The FDE interview loop" lesson-ஐ பாருங்க). Decision rule:

- **Prepare பண்றதுக்கு முன்னாடி round one-ஓட format-ஐ recruiter-கிட்ட கேளுங்க.**
- **DSA test-னா,** random-ஆ 400 இல்லாம, pattern வாரியா சுமார் 60-ல இருந்து 80 common problems practise பண்ணுங்க. நேரம் வச்சு பண்ணுங்க, உங்க approach-ஐ சத்தமா சொல்லுங்க.
- **Practical coding-னா,** tests-ஓட குழப்பமான CSVs, JSON-ல practise பண்ணுங்க, trade-offs பத்தி பேசுங்க.
- **எதுவா இருந்தாலும், விடாம பண்ணுங்க:** search நடக்குற வரை தினமும் 30 நிமிஷம், ஒரு panic week-ஐ விட better.

### Notice periods, timing

உங்க **notice period**-னா resign பண்ணதுக்கு அப்புறம் எவ்வளவு நாள் வேலை செய்யணும்ங்குறது. அதை உங்க appointment letter-உம் company policy-யும் தான் முடிவு பண்ணுது, national rule இல்ல. பெரிய IT services firms பொதுவா 90 நாள் வைக்குறாங்க. நிறைய product companies, startups குறைவான periods வைக்குறாங்க. Plan பண்றதுக்கு முன்னாடி மூணு clauses படிங்க: notice எவ்வளவு நாள், **buyout** பண்ணலாமா (serve பண்ணாத நாட்களுக்கு பதிலா salary கட்டுறது), training costs-க்கு ஏதாவது bond அல்லது recovery இருக்கா.

நீளமான notice உங்க மொத்த search-ஐயும் மாத்தும்:

- **Resign பண்றதுக்கு முன்னாடியே interview பண்ணுங்க,** அப்போ மூணு மாசம் சம்பளமும் options-உம் இல்லாம இருக்க மாட்டீங்க.
- **உங்க notice-ஐ ஆரம்பத்துலயே சொல்லுங்க,** Naukri-லயும் recruiters-கிட்டயும். சில posts 30 நாள் அல்லது அதுக்கும் குறைவா join பண்ண முடியுறவங்களை எதிர்பார்க்குது; 90 நாள் notice-ஐ மறைச்சா எல்லாருடைய நேரமும் வீணாகும்.
- **புது employer-கிட்ட ரெண்டு கேள்வி கேளுங்க:** wait பண்ண முடியுமா, buyout-ஐ reimburse பண்ணுவாங்களா? சிலர் பண்ணுவாங்க; உங்க employer buyout-க்கு மறுக்கலாம்.
- **நீளமான notice நேரத்துல offers risk-ல இருக்கும்னு எதிர்பாருங்க.** Join பண்ற வரை உங்க புது manager கூட touch-ல இருங்க, இன்னொரு offer இருக்குன்னு பொய் சொல்லாதீங்க.

### Salary research

உங்க இப்போதைய job-க்கு இல்ல, நீங்க apply பண்ற role-க்கான band-ஐ research பண்ணுங்க. Xplaind-ஓட Jobs page, Glassdoor, AmbitionBox, Instahyre, job posts-ல இருந்து typical yearly CTC bands-ஐ, lakh rupees-ல, சேகரிக்குது, **2 November 2026 அன்னைக்கு check பண்ணது**. இவை நடுத்தரமான bands, offers இல்ல; இந்த table-ல இருந்து வேற மாதிரி இருந்தா Jobs page தான் சரி.

| Role | 0 முதல் 2 வருஷம் | 3 முதல் 5 வருஷம் | 6+ வருஷம் |
| --- | --- | --- | --- |
| AI Engineer | 6 முதல் 12 | 12 முதல் 25 | 25 முதல் 50 |
| Generative AI Engineer | 8 முதல் 15 | 18 முதல் 35 | 35 முதல் 65 |

இதை எப்படி use பண்றது:

- **Band-ஐ சுருக்குங்க.** Big tech, global AI labs, Bengaluru அதிகமா pay பண்றாங்க; IT services, சின்ன cities குறைவா pay பண்றாங்க. Early FDE band அரிதா தான் ஒரு fresher job.
- **குறிப்பிட்ட company-ஐ** Glassdoor, AmbitionBox-ல check பண்ணுங்க, நீங்க சந்திக்குறவங்ககிட்ட band என்னன்னு கேளுங்க.
- **"Current and expected CTC"-க்கு கவனமா பதில் சொல்லுங்க.** இந்திய recruiters பொதுவா ரெண்டையும் ஆரம்பத்துலயே கேப்பாங்க. உங்க current CTC-ஐ நேர்மையா சொல்லுங்க, ஏன்னா அதை payslips கூட check பண்ணலாம். உங்க expected figure-ஐ, current pay-க்கு மேல ஒரு fixed percentage வச்சு இல்லாம, புது role-ஓட band, உங்க evidence-ஐ வச்சு முடிவு பண்ணுங்க.

### Offers-ஐ compare பண்றது

CTC (cost to company)-னா take-home pay இல்ல. ஒவ்வொரு offer-ஐயும் fixed pay, variable pay, joining bonus (ஒரு வருஷத்துக்குள்ள விட்டுப் போனா பெரும்பாலும் திருப்பிக் குடுக்கணும்), stock அல்லது ESOPs (ஒருவேளை பணமாவே வராம போகலாம்), benefits-ஆ பிரிங்க. முதல் வருஷத்துல உறுதியா கிடைக்கப்போற cash-ஐ compare பண்ணுங்க, அப்புறம் வேலை, learning, team, புது notice period. Accept பண்றதுக்கு முன்னாடி எந்த மாற்றத்தையும் எழுத்துல வாங்குங்க.

### Remote roles, வெளிநாட்டு jobs

Foreign companies இந்திய engineers-ஐ ஒரு employer of record (அவங்க சார்பா இந்தியால உங்களை employ பண்ற ஒரு firm) மூலமா அல்லது contractors-ஆ remote-ஆ hire பண்றாங்க. Competition global, அதனால உங்க portfolio-வும் written English-உம் இன்னும் அதிகமா முக்கியம். Contractor-ஆ நீங்க self-employed: invoices அனுப்புவீங்க, உங்க tax-ஐ நீங்களே handle பண்ணுவீங்க, அதனால sign பண்றதுக்கு முன்னாடி ஒரு chartered accountant கிட்ட பேசுங்க. வெளிநாட்டுக்கு போக work visa வேணும். Juniors-க்கு sponsorship அரிது, US work-visa rules 2025-ல ரொம்ப மாறுச்சு, இன்னும் மாறிட்டே இருக்கு, அதனால அதை வச்சு plan பண்றதுக்கு முன்னாடி official government source-ஐ check பண்ணுங்க.

### Track பண்ணி review பண்ணுங்க

ஒரு simple sheet வச்சிருங்க: company, role, channel (cold, referral, recruiter), date, stage, அடுத்த follow-up. ஒவ்வொரு பத்து applications-க்கு அப்புறமும், எந்த stage-ல ஆளுங்க drop ஆகுறாங்கன்னு கண்டுபிடிச்சு, ஒரு தடவைக்கு ஒரு விஷயத்தை மட்டும் மாத்துங்க:

| எங்க நிக்குது | வாய்ப்புள்ள காரணம் | என்ன மாத்தணும் |
| --- | --- | --- |
| Replies இல்ல | தப்பான roles, weak top third, referrals இல்ல, notice மறைச்சது அல்லது ரொம்ப நீளம் | Top third-ஐ tailor பண்ணுங்க; referrals பக்கம் போங்க; இன்னும் பொருத்தமான roles-ஐ target பண்ணுங்க |
| Coding test-ல fail | Format-ஐ practise பண்ணல | Format-ஐ கேளுங்க; நேரம் வச்சு, pattern வாரியா practise பண்ணுங்க |
| First rounds-ல fail | Project deep dive-ல தடுமாற்றம் | உங்க project-ஓட decisions, numbers-ஐ சத்தமா rehearse பண்ணுங்க |
| Final loops-ல fail | Weak design அல்லது client role-play | அந்த rounds-ஐ ஒரு friend கூட practise பண்ணுங்க |
| Offers கைவிட்டுப் போகுது | Pay mismatch அல்லது notice period | Bands-ஐ முன்னாடியே research பண்ணுங்க; முதல் call-லயே notice பத்தி பேசுங்க |

"Ready"-னு தோணுறதுக்கு முன்னாடியே apply பண்ணுங்க: எதை சரி பண்ணணும்னு interviews காட்டும்.

## ஒரு worked example

Coimbatore-ல ரெண்டு வருஷ Java experience இருக்குற backend developer Nandhini, இந்த path-ஐ ஏழு மாசத்துல முடிக்குறாங்க. கீழ இருக்குற numbers ஒரு illustration தான், benchmark இல்ல. உங்க சொந்த funnel ரொம்பவே வேற மாதிரி இருக்கலாம்.

**Portfolio.** அவங்க நாலு projects-ஐ pin பண்றாங்க, ஒவ்வொண்ணுலயும் முதல் lines-லயே ஒரு result-உம் அதோட test set-உம்: document QA API, eval report-ஓட enterprise RAG assistant, approval gates-ஓட operations agent, கற்பனையான ஒரு hospital chain-க்கான capstone. Capstone case study மூணு pages, கூடவே ரெண்டு நிமிஷ video. அதோட README, hospital கற்பனையானது, data synthetic-னு வெளிப்படையா சொல்லுது. ஒரு friend RAG assistant-ஐ அதோட README-ஐ வச்சு எட்டு நிமிஷத்துல run பண்றாங்க.

**Resume, LinkedIn.** அவங்க one-column resume-க்கு மாறுறாங்க, Java வேலையை சின்ன bullets-ஆ சுருக்கி, numbers-ஓட ஒரு "Projects" section சேர்க்குறாங்க. அவங்க LinkedIn headline அவங்க GitHub profile-ஓட match ஆகுது.

**Timing, pay.** அவங்க appointment letter 90 நாள் notice-னு சொல்லுது, buyout company-ஓட விருப்பப்படி. இதை அவங்க Naukri profile-ல போடுறாங்க. அவங்க current CTC ₹7 lakh. அவங்களுக்கு வேணும்ங்குற role-க்கு, 0 முதல் 2 வருஷத்துக்கான FDE band ₹12 முதல் 25 lakh. AI வேலைக்கு புதுசு, Bengaluru-க்கு வெளியே இருக்காங்க, அதனால band-ஓட கீழ் பாதியில தன்னை வச்சு, expected CTC-ஐ ₹15 முதல் 17 lakh-னு வைக்குறாங்க.

**பத்து வாரத்துல search.** அவங்க 40 target companies-ஐ list பண்றாங்க, அதுல 15-ல alumni அல்லது contacts-ஐ கண்டுபிடிக்குறாங்க.

## பொதுவா பண்ற தப்புகள்

- **Tutorial clones.** ஒரு video பார்த்து build பண்ண, ஒரு PDF மேல chatbot கொஞ்சம் தான் காட்டும். ஒரு real problem, evals, deployment சேருங்க.
- **Installation-ல ஆரம்பிக்குற READMEs.** Problem-ஐயும் result-ஐயும் முதல்ல வைங்க.
- **Defend பண்ண முடியாத numbers.** Test set இல்லாத result, அல்லது கற்பனையான client-ஓட "business impact", project deep dive-ல உடைஞ்சு போகும்.
- **Fancy two-column templates.** Screening software-ல கலைஞ்சு போகலாம். ஒரு column use பண்ணுங்க.
- **Cold applications மட்டும்.** Referrals-உம் conversations-உம் பொதுவா செலவழிக்குற ஒவ்வொரு மணி நேரத்துக்கும் ரொம்ப அதிகமான replies வாங்கித் தரும்.
- **Coding practice-ஐ skip பண்றது.** முதல்ல வர்ற online test-ல fail ஆனா strong portfolio-வால ஒரு உதவியும் இல்ல.
- **Notice period-ஐ மறைக்குறது.** அது கடைசியில வெளிய வந்து offer-ஐ கெடுத்துடும்.
- **CTC-ஐ மட்டும் வச்சு offers-ஐ compare பண்றது.** Variable pay, joining bonuses, stock எல்லாம் உறுதியான cash இல்ல.

## Practice பண்ணுங்க

Profile READMEs பத்தின GitHub-ஓட guide-ஐயும், Tech Interview Handbook-ஓட resume guide-ஐயும் படிங்க.

**Check (இதை submit பண்ணுங்க).** ஒரு GitHub profile README-ஐ publish பண்ணுங்க, இந்த path-ல இருந்து குறைஞ்சது மூணு projects-ஐ pin பண்ணுங்க, ஒரு case-study write-up எழுதுங்க. ஒவ்வொரு project README-யும் problem, ஒரு screenshot அல்லது சின்ன video, அதோட test set-ஐயும் size-ஐயும் சொல்ற ஒரு result-ல ஆரம்பிக்கணும். குறைஞ்சது ஒரு project-ஐ அதோட README-ஐ வச்சு 10 நிமிஷத்துக்குள்ள ஒரு reviewer run பண்ண முடியணும். உங்க profile-ஓட link-ஐ submit பண்ணுங்க.

**உங்க search-க்கு (இதை check பண்ண மாட்டோம், ஆனா பண்ணுங்க).**

1. உங்க resume-ஐ ஒரு column-ல, குறைஞ்சது நாலு result-based bullets-ஓட திரும்ப எழுதுங்க, உங்க LinkedIn headline-ஐ உங்க GitHub profile-ஓட match பண்ணுங்க.
2. உங்க appointment letter-ஐ படிச்சு, உங்க notice period, buyout terms-ஐ எழுதி வைங்க.
3. உங்க target role-க்கான Jobs page band-ஐ பார்த்து, ஒரு line காரணத்தோட உங்க expected CTC-ஐ எழுதுங்க.
4. ஒவ்வொண்ணுலயும் contact பண்ண ஒரு ஆளோட 20 target companies-ஐ list பண்ணுங்க, ஒரு tracking sheet ஆரம்பிங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** தெரியாத ஒருத்தருக்கு ஒரே ஒரு link அனுப்பி, 60 seconds-க்குள்ள நீங்க என்ன build பண்ணீங்க, அது என்ன சாதிச்சுது, அந்த number எதுல அளந்ததுன்னு காட்ட முடியும்போது.
