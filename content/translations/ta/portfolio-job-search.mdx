## இது என்ன

**Portfolio**-னா, உங்களால இந்த வேலையை செய்ய முடியும்ங்கிறதுக்கான evidence. AI engineering, FDE roles-க்கு பொதுவா அது இதெல்லாம்:

- **ஒரு GitHub profile**, உங்க மூணு முதல் அஞ்சு சிறந்த projects-ஓட ஆரம்பிக்கும், ஒவ்வொண்ணுக்கும் தெளிவான README இருக்கும்.
- **Case-study write-ups**, ஒண்ணு அல்லது ரெண்டு projects-க்கு, end-to-end case study மாதிரி எழுதியது: problem, numbers, முடிவுகள், results, என்ன தப்பா போச்சு.
- **ஒரு resume**, ஒரு பக்கம் (அனுபவம் உள்ள engineers-க்கு அதிகபட்சம் ரெண்டு), கடமைகள் இல்ல, results இருக்கும்.
- **விருப்பப்பட்டா**, சின்ன demo videos, நீங்க என்ன கத்துக்கிட்டீங்கன்னு விளக்குற சில public posts.

**Job search**-னா அந்த evidence-ஐ சரியான ஆட்கள் முன்னாடி கொண்டு போற plan.

```flow
title: ஒரு link, 60 வினாடி: github.com/you
Profile README -> Pin பண்ணது: enterprise RAG assistant | "recall at 5: 60 கேள்விகள்ல 68%-ல இருந்து 93%"
Profile README -> Pin பண்ணது: approvals உள்ள operations agent | "200 test runs-ல 0 unapproved actions"
Profile README -> Pin பண்ணது: document QA API | "96% field accuracy; ஒரு file-க்கு 4 s"
Profile README -> Case study: hospital chain capstone | 3 பக்கம் + 2 நிமிஷ video
```

```flow
dir: LR
title: Search
40 target companies -> 15-ல contacts -> குறிப்பான notes -> ஒரு sheet-ல track
```

Resume: ஒரு பக்கம், கடமைகள் இல்ல results, tools context-ஓட.

இந்த lesson, கோயம்புத்தூர்ல இருக்குற backend developer Nandhini, இந்த path-ஐ முடிச்சதுல இருந்து offers வாங்குற வரை எப்படி போனாங்கன்னு பின்தொடருது.

## இது எப்படி work ஆகுது

**Job-க்கு பொருந்துற projects-ஐ தேர்ந்தெடுங்க.** FDE roles-க்கு: realistic client problem, குழப்பமான data, evals, deployment, governance உள்ள projects. இந்த path-ல இருக்குற ஆறு stage projects இதுக்காகவே வடிவமைக்கப்பட்டவை. பத்து tutorials-ஐ விட, முடிச்ச மூணு நல்ல projects சிறந்தது.

**விக்கிற READMEs.** ஒவ்வொரு README-யையும் problem-ஐ ஒரு வாக்கியத்துல சொல்லி, ஒரு screenshot அல்லது 60 வினாடி video-ஓட ஆரம்பிங்க. அப்புறம் result-ஐ ஒரு number-ஓட தாங்க ("300 real-style documents-ல field accuracy 96%; ஒரு file-க்கு 4 வினாடி"), architecture-ஐ ஒரு சின்ன diagram-ல, எப்படி run பண்றதுன்னு. அப்புறம் விவரங்கள். இந்த repositories-ஐ உங்க profile-ல pin பண்ணி, உங்க case studies-க்கு link தர்ற ஒரு profile README சேருங்க.

**Results உள்ள resume bullets.** Pattern: action, என்ன, அளக்கக்கூடிய result. "4,000 பக்க insurance policies மேல hybrid search, reranking-ஓட RAG assistant உருவாக்கினேன்; 60-கேள்வி golden set-ல retrieval recall at 5-ஐ 68%-ல இருந்து 93%-க்கு உயர்த்தினேன்." AI, cloud, tools-ஐ நீளமான keyword list-ஆ இல்லாம, context-ஓட போடுங்க.

**Target companies.** இந்தியால, remote-ஆவும்: enterprise customers உள்ள AI labs, AI-first startups, data, AI platform companies, AI teams உருவாக்குற பெரிய firms-ஓட global capability centres, AI practices உள்ள IT services, consulting firms. Job posts-ஐ கவனமா படிங்க: சிலது "forward deployed"-ன்னு சொல்லும், மத்தவை "solutions engineer", "AI engineer, customer-facing", "applied AI engineer"-ன்னு சொல்லும்.

**Referrals, conversations வாங்குங்க.** Target companies-ல இருக்குற engineers-க்கு, ஒரு குறிப்பான note-ஓட, பொருத்தமான ஒரு project-ஓட link-ஐ அனுப்புங்க. நீங்க use பண்ண open-source tools-க்கு contribute பண்ணுங்க. நீங்க உருவாக்கினதையும் கத்துக்கிட்டதையும் பத்தின சின்ன write-ups-ஐ share பண்ணுங்க.

**Track பண்ணுங்க.** Applications, contacts, stages, follow-ups-க்கான ஒரு எளிய sheet. நிறைய rejections வரும்னு எதிர்பாருங்க; ஒவ்வொரு பத்து applications-க்கும் எது பதில் வாங்குதுன்னு பார்த்து materials-ஐ மாத்துங்க.

**பலவீனமான, வலுவான portfolio பகுதிகள்:**

| பகுதி | பலவீனம் | வலுவானது |
| --- | --- | --- |
| Project | ஒரு video பார்த்து ஒரு PDF மேல chatbot | Real problem, குழப்பமான data, golden set, deploy பண்ணது |
| README தொடக்கம் | "pip install ..." | Problem, ஒரு visual, ஒரு number-ஓட result |
| Resume bullet | "Worked on RAG" | "60-கேள்வி golden set-ல recall at 5-ஐ 68%-ல இருந்து 93%-க்கு உயர்த்தினேன்" |
| Outreach note | "Please refer me" | "உங்க customers-க்கு இருக்குற மாதிரி problems-க்கு X உருவாக்கினேன்; link இதோ" |

**Outreach note எழுதுறது.** நாலு வாக்கியத்துல வச்சுக்கோங்க: நீங்க யாரு, அவங்க company-க்கு பொருத்தமான ஒரு project, அதோட result, ஒரு குறிப்பான கேள்வி அல்லது கோரிக்கை, நன்றி. உதாரணமா: "நான் கோயம்புத்தூர்ல இருக்குற ஒரு backend developer, AI engineering-க்கு மாறிக்கிட்டு இருக்கேன். 300 test files-ல 96% field accuracy இருக்குற ஒரு claims-document assistant உருவாக்கினேன், உங்க team insurers-க்கு விக்குறதுக்கு ரொம்ப கிட்ட. உங்க FDE team எப்படி வேலை செய்யுதுன்னு சொல்ல உங்களுக்கு 15 நிமிஷம் இருக்குமா? நன்றி." குறிப்பான notes-க்கு replies வரும்; பொதுவான referral கோரிக்கைகளுக்கு அரிதா தான் வரும்.

**ஒவ்வொரு பத்து applications-க்கு அப்புறமும் review பண்றது.** Replies, first rounds-ஐ எண்ணுங்க. Replies கம்மியா இருந்தா, resume-ஓட மேல மூணுல ஒரு பங்கையும், உங்க READMEs-ஓட முதல் வரிகளையும் மாத்தி எழுதுங்க. First rounds மோசமா போனா, fail ஆன round-ஐ practice பண்ணுங்க. ஒரு நேரத்துல ஒண்ணை மட்டும் மாத்துங்க, அப்போ தான் எது உதவுச்சுன்னு தெரியும்.

## ஒரு worked example

கோயம்புத்தூர்ல ரெண்டு வருஷ Java அனுபவம் உள்ள backend developer Nandhini, இந்த path-ஐ ஏழு மாசத்துல முடிக்கிறாங்க.

அவங்க portfolio, நாலு projects-ல ஒவ்வொண்ணுக்கும் ஒரு repository-ஐ pin பண்ணுது, ஒவ்வொண்ணுக்கும் முதல் வரியிலயே ஒரு result இருக்கு. அவை: document QA API, eval report-ஓட enterprise RAG assistant, approval gates உள்ள operations agent, ஒரு கற்பனை hospital chain-க்கான capstone. அவங்க capstone case study மூணு பக்கம், ரெண்டு நிமிஷ video-ஓட.

அவங்க resume, Java வேலையை சுருக்கமான bullets-ஆ மாத்தி, numbers-ஓட ஒரு "Projects" section-ஐ சேக்குது. 40 target companies-ஐ பட்டியல் போட்டு, அதுல 15-ல engineers-ஐ கண்டுபிடிச்சு, ஒவ்வொரு company-ஓட customers-க்கும் ரொம்ப பொருத்தமான project-ஐ link பண்ணி சின்ன notes அனுப்புறாங்க.

எட்டு வாரத்துல results: 31 applications, 9 replies, 6 first rounds, 3 final loops, 2 offers. ஒரு offer, hospitals-க்கு விக்குற ஒரு startup-ல forward deployed role; capstone case study தான் தங்க call-க்கு காரணம்னு அவங்க சொன்னாங்க.

| Applications | 31 |

| Final loops | 3 |

## பொதுவா பண்ற தப்புகள்

- **Tutorial clones.** ஒரு video பார்த்து ஒரு PDF மேல கட்டின chatbot கொஞ்சமே காட்டும். ஒரு real problem, evals, deployment சேருங்க.
- **Installation-ல ஆரம்பிக்குற READMEs.** Problem-ஐயும் result-ஐயும் முன்னாடி வைங்க.
- **Results-க்கு பதிலா கடமைகள்.** "Worked on RAG" ஒண்ணுமே சொல்லாது; numbers சொல்லும்.
- **ஒரே resume-ஓட எல்லா இடத்துக்கும் apply பண்றது.** ஒவ்வொரு role-க்கும் மேல மூணுல ஒரு பங்கை tailor பண்ணுங்க.
- **"Ready" ஆகுற வரை காத்திருக்கிறது.** கடைசி projects-ஐ முடிக்கும்போதே apply பண்ணுங்க; interviews எதை மேம்படுத்தணும்னு கத்துக்கொடுக்கும்.
