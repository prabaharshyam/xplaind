## இது என்ன

ஒரு model புது data-ல எப்படி perform பண்ணும்னு தெரிஞ்சுக்க, அது ஒருபோதும் கத்துக்காத data-ல, உண்மையான use மாதிரியான நிலைமைகள்ல test பண்ணணும்.

- **Train, validation, test**: ஒரு பகுதியில train பண்ணுங்க, ஒரு validation பகுதியில choices-ஐ tune பண்ணுங்க, கடைசி வரை தொடாம வச்ச ஒரு test பகுதியில final performance-ஐ ஒரே தடவை report பண்ணுங்க.
- **Cross-validation**: பல வேற வேற splits-ல (folds) training-ஐயும் validation-ஐயும் repeat பண்ணி average பண்றது; data குறைவா இருக்கும்போது இது இன்னும் stable-ஆன estimate-ஐ கொடுக்கும்.
- **Data leakage**: validation அல்லது test data-ல இருந்து, இல்லன்னா எதிர்காலத்துல இருந்து, information training-குள்ள போற எந்த வழியும்; அதனால results உண்மையில வர்றதை விட நல்லா தெரியும்.

| Split வகை | எப்படி work ஆகுது | எப்போ use பண்றது |
|---|---|---|
| Random k-fold | Fold 1 part 1-ல validate ஆகி மீதியில train ஆகும், fold 2 part 2-ல, இப்படியே; 5 scores-ஐ average பண்ணுங்க | Rows independent-ஆ இருக்கும்போது |
| Time-based | Jan-Jun train, Jul validate; Jan-Jul train, Aug validate; Jan-Aug train, Sep validate | Rows time order-ல இருக்கும்போது: எதிர்காலத்துல ஒருபோதும் train பண்ணாதீங்க |
| Grouped | Patient A-ஓட 4 admissions எல்லாம் fold 2-ல, Patient B-ஓட 2 எல்லாம் fold 5-ல | ஒரே நபர் அல்லது பொருள் பல rows-ல வரும்போது |

## இது எப்படி work ஆகுது

**k-fold cross-validation.** Data-வை k folds-ஆ (பெரும்பாலும் 5) பிரிங்க. k-1-ல train பண்ணி, மீதி ஒண்ணுல validate பண்ணுங்க; k தடவை repeat பண்ணுங்க. Classification-க்கு, stratified folds class proportions-ஐ சமமா வச்சிருக்கும்.

**Time-based splits.** Data-வுக்கு time order இருக்கும்போது (transactions, demand, churn), random splits எதிர்காலத்தை training-குள்ள leak பண்ணும். முந்தைய periods-ல train பண்ணி, பிந்தைய periods-ல validate பண்ணுங்க; time-series cross-validation இந்த window-ஐ முன்னோக்கி நகர்த்தும்.

**Grouped splits.** ஒரே customer, patient, store பல rows-ல வந்தா, அதோட எல்லா rows-ஐயும் ஒரே fold-ல வச்சுக்கோங்க. இல்லன்னா model தனி நபர்களை memorise பண்ணிடும், புது நபர்கள்ல உண்மையை விட நல்லா தெரியும்.

**Leakage-ஓட common sources.**

- *எல்லா data-லயும் preprocessing*: split பண்றதுக்கு முன்னாடியே compute பண்ற scaling, imputing, target encoding, validation rows-ஓட information-ஐ use பண்ணுது. Preprocessing-ஐ training fold-ல மட்டும் fit பண்ணுங்க; scikit-learn **pipelines** இதை cross-validation-க்குள்ள தானா பண்ணும்.
- *எதிர்கால features*: prediction time-க்கு அப்புறமான information வச்சு compute பண்ண features.
- *Target proxies*: outcome-ஓட விளைவா இருக்குற columns (churn-ஐ predict பண்ணும்போது ஒரு "closed reason" field).
- *Duplicates*: ஒரே record train-லயும் test-லயும் இருக்குறது.
- *Test set-ல tune பண்றது*: test score வச்சு models-ஐ தேர்ந்தெடுக்குறது, அதை ஒரு validation set ஆக்கிடும்; final results optimistic ஆயிடும்.

**Leakage-ஓட அறிகுறிகள்.** ஆச்சரியப்படுத்துற அளவு அதிகமான validation scores; அபரிமிதமான importance இருக்குற ஒரு feature; உண்மையிலேயே ஒரு புது period-ல score பண்ணும்போது பெரிய drop.

**கடைசி check.** Launch-க்கு முன்னாடி, model இதுவரை பார்க்காத மிக சமீபத்திய period-ல score பண்ணுங்க; முடிஞ்சா production-ல run ஆகப்போற அதே மாதிரி.

**எந்த split எந்த problem-க்கு:**

| Data | Use பண்ண வேண்டிய split | ஏன் |
| --- | --- | --- |
| Independent rows, time order இல்ல | Stratified k-fold | Stable estimate, class balance பாதுகாக்கப்படும் |
| Transactions, demand, churn | Time-based, முன்னோக்கி நகர்றது | Model எப்பவும் எதிர்காலத்தை predict பண்ணுது |
| ஒரு customer அல்லது patient-க்கு பல rows | Grouped k-fold | Model பார்க்கப்போறது புது customers |
| Time order-உம் groups-உம் ரெண்டும் | Time-based, groups boundary-ஐ தாண்டாம | ரெண்டு risks-ஐயும் இணைக்கும் |

**ஒவ்வொரு split-க்கும் பின்னால இருக்குற rule:** validation data, model உண்மையான use-ல சந்திக்கப்போற data மாதிரி இருக்கணும், training prediction time-ல கிடைக்குற information-ஐ மட்டும் use பண்ணணும். உங்க split production-ஐ எப்படி பிரதிபலிக்குதுன்னு உங்களால explain பண்ண முடிஞ்சா, நீங்க சரியா தேர்ந்தெடுத்திருக்கீங்கன்னு பொதுவா அர்த்தம்.

**ஒரு score-ஐ நம்புறதுக்கு முன்னாடி ஒரு leakage checklist.** ஒவ்வொரு feature-க்கும், "prediction பண்ற நேரத்துல இந்த value எனக்கு தெரியுமா?"ன்னு கேளுங்க. ஒவ்வொரு preprocessing step-ஐயும் ஒரு pipeline-குள்ள fit பண்ணுங்க. Splits-க்கு இடையில இருக்குற exact duplicates-ஐ நீக்குங்க. Feature importance-ஐ பார்த்து, ரொம்ப நல்லா தெரியுற எதையும் கேள்வி கேளுங்க. மிக சமீபத்திய, தொடாத period-ல கடைசியா score பண்ணுங்க.

**Feature engineering-ல இருந்து வர்ற leakage.** நிறைய leaks, event logs-ல இருந்து build பண்ற features வழியா நுழையுது: "number of support calls", "last status", "days since last payment". ஒவ்வொண்ணும் prediction moment-க்கு முன்னாடி நடந்த events-ல இருந்து மட்டும் compute ஆகணும். ஒரு safe பழக்கம்: ஒவ்வொரு row-க்கும் ஒரு "prediction time" column-ஐ fix பண்ணி, features build பண்ணும்போது ஒவ்வொரு source table-ஐயும் அதுக்கு முன்னாடி நடந்த events-க்கு filter பண்றது.

**Leakage நடக்குறதை நீங்களே பார்க்கலாம்.** Pure noise-ல signal இல்ல, அதனால நேர்மையான score சுமார் 0.5 இருக்கணும். முதல்ல எல்லா data-லயும் features-ஐ select பண்ணா noise predictive மாதிரி தெரியும்:

```python
import numpy as np
from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score, StratifiedKFold
from sklearn.pipeline import make_pipeline

rng = np.random.default_rng(0)
X = rng.normal(size=(200, 5000))                  # 5,000 random features
y = rng.integers(0, 2, 200)                       # random labels
cv = StratifiedKFold(5, shuffle=True, random_state=0)

X_leaky = SelectKBest(f_classif, k=20).fit_transform(X, y)          # chose features using every label
print("leaky:", cross_val_score(LogisticRegression(max_iter=1000), X_leaky, y, cv=cv).mean().round(2))

honest = make_pipeline(SelectKBest(f_classif, k=20), LogisticRegression(max_iter=1000))
print("honest:", cross_val_score(honest, X, y, cv=cv).mean().round(2))
```

Leaky version, random data-ல 0.5-ஐ விட ரொம்ப அதிகமா score பண்ணும்; ஒவ்வொரு training fold-க்குள்ளயும் features-ஐ select பண்ற pipeline version, chance level-க்கு விழும். Scaling, imputing, target encoding-க்கும் இதே தான்.

**Code-ல grouped, time splits.**

```python
from sklearn.model_selection import GroupKFold, TimeSeriesSplit

def grouped_score(model, X, y, customer_ids):
    return cross_val_score(model, X, y, cv=GroupKFold(n_splits=5), groups=customer_ids).mean()

def time_score(model, X_sorted, y_sorted, gap=0):
    """Rows must be sorted by time. gap leaves rows out between train and test."""
    return cross_val_score(model, X_sorted, y_sorted, cv=TimeSeriesSplit(n_splits=5, gap=gap)).mean()
```

Labels வர்றதுக்கு நேரம் ஆகும்போது `gap` முக்கியம்: churn 30 நாள் கழிச்சு judge ஆகுதுன்னா, 30 நாள் gap விடுங்க, அப்போ training labels test period-ஓட overlap ஆகாது.

**உங்களையே ஏமாத்திக்காம tune பண்றது.** Cross-validation score வச்சு settings-ஐ தேர்ந்தெடுத்து, அதே score-ஐ report பண்றது optimistic. Nested cross-validation உள்ள tune பண்ணி, வெளிய score பண்ணும்:

```python
from sklearn.model_selection import GridSearchCV
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.datasets import make_classification

Xc, yc = make_classification(n_samples=2000, n_features=20, random_state=1)
inner = GridSearchCV(HistGradientBoostingClassifier(random_state=1),
                     {"max_depth": [3, 6], "learning_rate": [0.05, 0.1]}, cv=3, scoring="roc_auc")
outer = cross_val_score(inner, Xc, yc, cv=5, scoring="roc_auc")
print("nested ROC AUC:", outer.mean().round(3), "±", outer.std().round(3))
```

Data நிறைய இருக்கும்போது, ஒரு எளிய வழி: கடைசியில ஒரே தடவை score பண்ற ஒரு தனி test period.

**Leaks-ஐ பிடிக்கிற ஒரு test.** ஒவ்வொரு feature-க்கும், ஒரே ஒரு feature வச்சு ஒரு model-ஐ train பண்ணுங்க; கிட்டத்தட்ட perfect accuracy வர்ற எந்த ஒரு feature-ஐயும் கூர்மையா பாருங்க. இந்த check-ஐ உங்க training pipeline-ல சேர்த்து, top five-ஐ print பண்ணுங்க.

## ஒரு worked example

Chennai-ல ஒரு hospital network, discharge records-ல இருந்து 30-day readmission-ஐ predict பண்றாங்க.

முதல் notebook, random 5-fold cross-validation-ல AUC 0.91-ன்னு report பண்ணுச்சு. கவலைகள்:

1. நிறைய patients-க்கு பல admissions இருக்கு. Random folds-ல ஒரே patient training-லயும் validation-லயும் வந்தாரு. **Patient வாரியா grouped folds**: AUC 0.83.
2. Missing lab values, split-க்கு முன்னாடி முழு dataset-ல compute பண்ண mean-ஆல நிரப்பப்பட்டிருந்தது. Imputation-ஐ ஒரு pipeline-குள்ள நகர்த்தினா: AUC 0.82.
3. "follow-up appointment cancelled"ங்கிற feature சில நேரம் readmission-க்கு அப்புறம் record ஆச்சு. அதை நீக்கினா: AUC 0.78.
4. 2023 முதல் 2025 admissions-ல train பண்ணி, 2026-ஓட முதல் பாதியில test பண்ணா: AUC 0.77.

நேர்மையான number, 0.77, தான் clinical team plan பண்ணி வச்சுக்கிட்டது. ஆறு மாச pilot-ல live AUC 0.76.

| Fix | Fix-க்கு அப்புறம் AUC |
| --- | --- |
| Random 5-fold (ஆரம்பம்) | 0.91 |
| Patient வாரியா grouped folds | 0.83 |
| Pipeline-குள்ள imputation | 0.82 |

0.91-ல இருந்து 0.77-க்கு விழுந்தது, model மோசமானது இல்ல. அளவீடு நேர்மையானது; அதனால தான் pilot-ல எந்த surprise-உம் இல்ல.

## பொதுவா பண்ற தப்புகள்

- **Time-ordered data-ல random splits.**
- **ஒரே entity train-லயும் test-லயும் இருக்கிறது.** Customer, patient, store வாரியா group பண்ணுங்க.
- **Split-க்கு முன்னாடி preprocessing.** Pipelines use பண்ணுங்க.
- **Test set-ஐ திரும்ப திரும்ப check பண்றது.** Final report-க்கு மட்டும் வச்சுக்கோங்க.
- **சந்தேகப்படுற அளவு நல்ல scores-ஐ புறக்கணிக்கிறது.** கொண்டாடுறதுக்கு முன்னாடி investigate பண்ணுங்க.

- **Cross-validation-ல tune பண்ணி, அந்த cross-validation score-ஐயே final-ஆ report பண்றது.** பல tuning rounds-க்கு அப்புறம், cross-validation score-ம் optimistic ஆயிடும். ஒரு தனி final test set-ஐ வச்சிருங்க.
- **Leakage அரிதுன்னு நினைக்கிறது.** Launch-க்கு அப்புறம் models fail ஆகுறதுக்கு இது மிக common-ஆன காரணங்கள்ல ஒண்ணு. ஒவ்வொரு தடவையும் check பண்ணுங்க, குறிப்பா logs அல்லது event tables-ல இருந்து build பண்ண features-ல.
- **Cross-validate பண்றதுக்கு முன்னாடி எல்லா data-லயும் features-ஐ select பண்றது அல்லது tune பண்றது.**
- **Labels தாமதமா வரும்போது, training-க்கும் test periods-க்கும் இடையில gap இல்லாதது.**
- **Best tuned score-ஐ, தொடாத estimate மாதிரி report பண்றது.**

## Simple splits போதுமானது எப்போ

- **நிறைய independent rows**, time order இல்ல, repeated entities இல்ல: ஒரு random hold-out set போதும்.
- **ஆரம்பத்துல quick comparisons**, ஒரு single validation split திசையை காட்டும்.
- **Pretrained models-ஐ அப்படியே use பண்ணும்போது**, உங்களுக்கு ஒரு clean test set மட்டும் தான் வேணும், cross-validation இல்ல.

## Demo-ல இருந்து production-க்கு

- **ஒவ்வொரு preprocessing step-ஐயும் ஒரு pipeline-ல வச்சு**, training folds-ல மட்டும் fit பண்ணுங்க.
- **Split-ஐ production-க்கு பொருத்துங்க**: time, groups அல்லது ரெண்டும், labels தாமதமா வந்தா gaps-ஓட.
- **ஒரு final test period-ஐ வச்சு**, ஒவ்வொரு model version-க்கும் ஒரே தடவை score பண்ணுங்க.
- **Training pipeline-ல single-feature leak checks-ஐ** run பண்ணுங்க.
- **Offline scores-ஐ production-ஓட முதல் சில வாரங்களோட compare பண்ணுங்க**; பெரிய drop leakage-ஐ காட்டும்.

## Practice பண்ணுங்க

scikit-learn-ஓட cross-validation guide-ஐயும் common pitfalls page-ஐயும் படிச்சு, Kaggle-ஓட Intermediate ML-ல cross-validation, leakage lessons-ஐ செய்யுங்க.

1. Repeated entities அல்லது time order இருக்குற ஒரு dataset-ல, random k-fold-ஐ grouped அல்லது time-based splits-ஓட compare பண்ணுங்க.
2. எல்லா data-லயும் ஒரு scaler-ஐ fit பண்றதால வர்ற leakage-ஐ காட்டி, அப்புறம் ஒரு pipeline வச்சு அதை fix பண்ணுங்க.
3. ஒரு final test set-ஐ ஒதுக்கி வச்சு, cross-validation-ல மட்டும் tune பண்ணி, test score-ஐ ஒரே தடவை report பண்ணுங்க.
4. Noise experiment-ஐ நீங்களே run பண்ணுங்க, அப்புறம் feature selection-க்கு பதிலா ஒரு StandardScaler வச்சு repeat பண்ணி, leak எவ்வளவு சின்னதுன்னு note பண்ணுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** உங்க use case-க்கு எந்த split பொருந்தும்னு explain பண்ணவும், ஒரு leak-ஐ நீக்கினப்போ score விழுந்ததை காட்டவும் முடியும்.
