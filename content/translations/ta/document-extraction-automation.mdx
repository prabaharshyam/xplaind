## இது என்ன

**Document extraction** ஒரு unstructured document-ஐ structured fields-ஆ மாத்துது: ஒரு invoice PDF-ல இருந்து vendor name, GSTIN, invoice number, date, line items, tax amounts, total. ஒரு automation வர்ற ஒவ்வொரு document-க்கும் இதை பண்ணி, result-ஐ check பண்ணி, ஒரு sheet-க்கோ accounting system-க்கோ approval step-க்கோ அனுப்பும்.

நவீன AI models பல மாதிரி layouts-ஐ பழைய template-based tools-ஐ விட ரொம்ப நல்லா handle பண்ணும்; அந்த tools-க்கு ஒவ்வொரு supplier-க்கும் ஒரு template வேணும்.

```flow
Email, WhatsApp அல்லது ஒரு folder -> 1 Receive, original-ஐ store பண்ணு -> 2 Content எடு | text, OCR, அல்லது image-ஐ vision model-க்கு
2 Content எடு -> 3 Schema வச்சு extract பண்ணு | supplier, GSTIN, number, date, lines, CGST, SGST, total
3 Schema வச்சு extract பண்ணு -> 4 Validate | formats, arithmetic, business rules
4 Validate -> எல்லாம் pass ஆச்சா?
எல்லாம் pass ஆச்சா? -[yes]-> 5 Accounting-ல post பண்ணு -> 6 Record, audit trail
எல்லாம் pass ஆச்சா? -[no]-> 5 Review screen | fields-க்கு பக்கத்துல image, fail ஆன checks சிவப்புல
5 Review screen -[ஒரு ஆள் correct பண்றாங்க]-> Final record, ஒரு புது test case
```

இந்த lesson, மாசத்துக்கு சுமார் 900 supplier invoices process பண்ற Surat-ஓட ஒரு textile trader-ஐ follow பண்ணுது.

## இது எப்படி work ஆகுது

**1. Receive.** Documents email attachment, upload form, shared folder, WhatsApp வழியா வரும். Trigger அவற்றை எடுத்து, original-ஐ store பண்ணும்.

**2. Content எடுக்குறது.** Digital PDFs: text-ஐ extract பண்ணுங்க. Scans, phone photos: OCR பண்ணுங்க, அல்லது image-ஐ நேரடியா vision-capable model-க்கு அனுப்புங்க. Page reference-ஐ வச்சுக்கோங்க.

**3. Schema வச்சு extract பண்றது.** Content-ஐ ஒரு தெளிவான instruction-ஓடயும், fixed output shape-ஓடயும் (field names, types, எது required) model-க்கு அனுப்புங்க. Tool-ஓட structured-output feature அல்லது ஒரு JSON schema-வை use பண்ணா, ஒவ்வொரு தடவையும் சரியா அதே fields கிடைக்கும். ஒரு field document-ல இல்லைன்னா guess பண்ணாம null-ஐ கொடுக்க சொல்லுங்க.

**4. Rules வச்சு validate பண்றது.** Extraction-ஐ கண்மூடித்தனமா நம்பாதீங்க. Check பண்ணுங்க:

- formats: GSTIN 15 characters, சரியான pattern-ல இருக்கணும்; dates valid-ஆ இருக்கணும்; PIN codes-ல ஆறு digits இருக்கணும்;
- arithmetic: line totals கூடி subtotal ஆகணும்; subtotal + tax = total ஆகணும்;
- business rules: vendor உங்க master list-ல இருக்கணும்; PO number ஒரு open order-ஓட match ஆகணும்; amount எதிர்பார்க்குற range-க்குள்ள இருக்கணும்.

**5. Route.** எல்லா checks-உம் pass ஆனா தானா continue ஆகும். எதுவும் fail ஆனா அல்லது ஒரு required field இல்லைன்னா, document-ஓடயும் fail ஆன check highlight ஆகியும் ஒரு ஆளுக்கு அனுப்புங்க. அவங்க correction தான் final record; அது ஒரு பயனுள்ள test case-உம் ஆகும்.

**6. Record.** Extract பண்ண data, checks, யார் approve பண்ணாங்கன்னு audit-க்காக வச்சுக்கோங்க.

**அளவிடுங்க.** Straight-through rate (யாரும் தொடாம process ஆனதோட பங்கு), மனுஷங்க check பண்ண ஒரு sample-ல field accuracy, மிச்சப்படுத்துன நேரம் இதையெல்லாம் track பண்ணுங்க.

**இந்திய invoices-க்கான validation rules:**

| Field | Check | எதை பிடிக்கும் |
| --- | --- | --- |
| GSTIN | 15 characters, valid pattern, state code address-ஓட match ஆகணும், supplier master-ல இருக்கணும் | தப்பா படிச்சது, தப்பான supplier |
| Invoice date | Valid date, future-ல இல்லை, accounting period-க்குள்ள | 31 February, typos |
| Line items | Quantity × rate = amount; lines கூடி subtotal ஆகணும் | விட்டுப்போன அல்லது merge ஆன lines |
| Tax | Intra-state-க்கு CGST = SGST; inter-state-க்கு IGST; amounts rates-ஓட match ஆகணும் | தப்பான tax type, தப்பா படிச்ச amounts |
| Total | Subtotal + taxes = total | எந்த arithmetic misread-உம் |
| Invoice number | இந்த supplier-க்கு ஏற்கனவே record ஆகியிருக்கக்கூடாது | Duplicate payments |

**Model தேர்வை விட rules ஏன் முக்கியம்.** ரொம்ப திறமையான model-உம் அப்பப்போ ஒரு blurry digit-ஐ தப்பா படிக்கும். Arithmetic, format checks இந்த errors-ல பெரும்பாலானதை செலவே இல்லாம பிடிக்கும்; ஏன்னா தப்பா படிச்ச digit totals-ஐ consistent-ஆ வச்சிருக்க வாய்ப்பு ரொம்ப கம்மி. Model படிக்கும்; அது படிச்சதை நம்பலாமான்னு rules முடிவு பண்ணும்.

**Confidence, review queues.** Reviewers ஒவ்வொரு field-ஐயும் மறுபடி check பண்ண வேண்டியதில்ல. ஒரு rule-ல fail ஆன fields-ஐ முதல்ல காட்டுங்க, அப்புறம் model உறுதி இல்லைன்னு mark பண்ண அல்லது null விட்ட fields; மிச்சத்தை reviewers ஒரே action-ல approve பண்ணட்டும். Review எவ்வளவு நேரம் எடுக்குதுன்னு track பண்ணுங்க; ஒரு document-க்கு ஒரு நிமிஷத்துக்கு மேல ஆகுதுன்னா, screen-ஐ தான் improve பண்ணணும், reviewer-ஐ இல்லை.

**Code-ல validation rules.** இந்த checks extraction-க்கு அப்புறம் run ஆகி, ஒரு document நேரா போகுமான்னு முடிவு பண்ணும்:

```python
import re
from datetime import date
from decimal import Decimal

GSTIN_RE = re.compile(r"^[0-3][0-9][A-Z]{5}[0-9]{4}[A-Z][1-9A-Z]Z[0-9A-Z]$")
CHARS = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ"

def gstin_ok(g):
    if not GSTIN_RE.match(g or ""):
        return False
    total = 0
    for i, ch in enumerate(g[:14]):
        p = CHARS.index(ch) * (1 if i % 2 == 0 else 2)
        total += p // 36 + p % 36
    return CHARS[(36 - total % 36) % 36] == g[14]

def check_invoice(inv, supplier_state, our_state, seen_numbers):
    problems = []
    if not gstin_ok(inv["supplier_gstin"]):
        problems.append("supplier GSTIN fails format or check digit")
    elif inv["supplier_gstin"][:2] != supplier_state:
        problems.append("GSTIN state code does not match the supplier's state")
    if inv["invoice_date"] > date.today():
        problems.append("invoice date is in the future")
    lines = [Decimal(l["qty"]) * Decimal(l["rate"]) for l in inv["lines"]]
    if any(abs(c - Decimal(l["amount"])) > Decimal("0.01") for c, l in zip(lines, inv["lines"])):
        problems.append("a line amount is not quantity × rate")
    subtotal = sum(lines)
    if abs(subtotal - Decimal(inv["subtotal"])) > Decimal("0.01"):
        problems.append("lines do not add up to the subtotal")
    tax = Decimal(inv.get("cgst") or 0) + Decimal(inv.get("sgst") or 0) + Decimal(inv.get("igst") or 0)
    if supplier_state == our_state and inv.get("igst"):
        problems.append("IGST charged on an intra-state supply")
    if supplier_state != our_state and (inv.get("cgst") or inv.get("sgst")):
        problems.append("CGST/SGST charged on an inter-state supply")
    if abs(subtotal + tax - Decimal(inv["total"])) > Decimal("1.00"):      # allow rupee rounding
        problems.append("subtotal plus tax does not equal the total")
    if (inv["supplier_gstin"], inv["invoice_number"]) in seen_numbers:
        problems.append("duplicate invoice number for this supplier")
    return problems
```

List காலியா இருந்தா straight through; வேற எதுவா இருந்தாலும், problems முதல்ல list ஆகி review-க்கு போகும். பணம் எப்பவும் `Decimal`-ல handle ஆகணும், floats-ல இல்லை.

**Field accuracy-ஐ சரியா அளக்குறது.** 50 முதல் 100 documents-ஐ மனுஷங்க கையால key பண்ணி ஒரு gold set-ஆ வச்சுக்கோங்க. ஒவ்வொரு field-க்கும், normalise பண்ணதுக்கு அப்புறம் (dates-ஐ ஒரே format-க்கு, amounts-ஐ ரெண்டு decimals-க்கு) extraction-உம் gold value-உம் exact-ஆ match ஆன எண்ணிக்கையை count பண்ணுங்க. ஒரே overall number இல்லாம, field வாரியா report பண்ணுங்க: 98% overall score invoice dates-ல 80%-ஐ மறைச்சிடலாம்.

**Straight-through rate-உம் error rate-உம்.** Rules-ஐ தளர்த்துனா அதிக documents நேரா போகும், ஆனா books-க்குள்ள அதிக errors-உம் போகும். ரெண்டையும் track பண்ணுங்க. Finance team-ஓட சேர்ந்து ஒரு target வைங்க: உதாரணமா, குறைஞ்சது 70% straight through, ledger-க்கு போற தப்பான fields 500-ல 1-க்கும் குறைவு.

**Corrections-ஐ திரும்ப feed பண்ணுங்க.** Reviewer-ஓட ஒவ்வொரு correction-உம் ஒரு labelled example. கஷ்டமானதை உங்க test set-ல சேருங்க; ஒரு supplier-ஓட layout திரும்ப திரும்ப தப்பு உண்டாக்குச்சுன்னா, prompt-ல ஒரு சின்ன supplier-specific hint-ஐயோ ஒரு dedicated rule-ஐயோ சேருங்க.

## ஒரு worked example

Surat-ஓட ஒரு textile trader-க்கு மாசத்துக்கு சுமார் 900 supplier invoices PDFs-ஆவும், WhatsApp, email-ல phone photos-ஆவும் வருது.

Automation:

- ஒரு dedicated email address-ல இருந்தும் ஒரு WhatsApp Business number-ல இருந்தும் attachments-ஐ collect பண்ணுது.
- ஒவ்வொரு page-ஐயும் ஒரு schema-ஓட vision-capable model-க்கு அனுப்புது: supplier name, supplier GSTIN, invoice number, invoice date, line items (description, HSN code, quantity, rate, amount), CGST, SGST, IGST, total.
- Validate பண்ணுது: GSTIN pattern, supplier master-ஓட match; lines கூடுதா; tax amounts rates-ஓட consistent-ஆ இருக்கா; அந்த supplier-க்கு invoice number ஏற்கனவே record ஆகலையா.
- Pass ஆன invoices-ஐ accounting import sheet-ல எழுதுது; fail ஆனவற்றை fields-க்கு பக்கத்துல image இருக்குற ஒரு review screen-ல accounts assistant-க்கு அனுப்புது.

முதல் மாசம்: 71% straight through; பெரும்பாலான failures blurry photos-உம் handwritten corrections-உம். அடிக்கடி invoices அனுப்புற suppliers-கிட்ட PDFs-ஐ email பண்ண சொல்லி, photo prompt-ஐ improve பண்ணதுக்கு அப்புறம், straight-through 84%-க்கு போகுது. Invoice entry-ல accounts staff நேரம் மாசத்துக்கு சுமார் 60 மணி நேரத்துல இருந்து 15-க்கு குறையுது, duplicate-invoice check ₹2.3 lakh மதிப்பு இருக்குற நாலு duplicate payments-ஐ பிடிக்குது.

| Measure | Month 1 | Month 3 |
| --- | --- | --- |
| Straight-through rate | 71% | 84% |
| முக்கிய failure காரணம் | Blurry photos, handwritten corrections | Handwritten corrections |
| Invoice entry-ல staff நேரம் | மாசத்துக்கு சுமார் 60 மணி நேரம் | மாசத்துக்கு சுமார் 15 மணி நேரம் |
| பிடிபட்ட duplicate payments | 4, ₹2.3 lakh மதிப்பு | தொடர்ந்து பிடிக்குது |

மிகப்பெரிய ஒரே improvement technical இல்லை: அடிக்கடி invoices அனுப்புற 30 suppliers-கிட்ட phone photos-க்கு பதிலா PDFs-ஐ email பண்ண சொன்னது.

## பொதுவா பண்ற தப்புகள்

- **Free-form output.** Fields எப்பவும் இருக்கணும், types-ஓட இருக்கணும்னா ஒரு schema use பண்ணுங்க.
- **Validation rules இல்லாதது.** Arithmetic, format checks தான் extraction errors-ல பெரும்பாலானதை பிடிக்கும்.
- **இல்லாத fields-ஐ model guess பண்ண விடுறது.** Null கேளுங்க, ஒரு ஆளுக்கு route பண்ணுங்க.
- **Original document-ஐ இழக்கிறது.** Checking, audit-க்காக அதை record-ஓட link பண்ணி வைங்க.
- **எதையும் அளக்காதது.** Straight-through rate-ஐயும் sample accuracy-ஐயும் track பண்ணுங்க.

- **ஒவ்வொரு page-ஐயும் மிக costly model-க்கு அனுப்புறது.** Digital PDFs-க்கு text extraction use பண்ணி, vision models-ஐ scans, photos-க்கு மட்டும் வச்சுக்கோங்க; செலவு நிறைய குறையும்.
- **பணத்துல float arithmetic.** Paise-ஐ integers-ஆ அல்லது `Decimal`-ஐ use பண்ணுங்க.
- **எல்லா fields-க்கும் ஒரே accuracy number.** ஒவ்வொரு field-ஐயும் தனியா அளங்க.
- **Duplicates-ஐ check பண்ணாதது.** திரும்ப அனுப்பின invoice ரெண்டு தடவை pay ஆகிடும்.

## Extraction automation எப்போ worth இல்லை

- **மாசத்துக்கு கொஞ்சம் documents மட்டும்**: ஒரு pipeline build பண்ணி check பண்றதை விட அவற்றை type பண்றது மலிவு.
- **Structured data ஏற்கனவே இருக்கு**: e-invoices, bank statement exports அல்லது supplier-ஓட API இருந்தா PDFs படிக்குறதை விட நல்லது.
- **ஒவ்வொரு document-க்கும் நிபுணரோட judgement தேவை**, clause by clause review பண்ற legal contracts மாதிரி.

## Demo-ல இருந்து production-க்கு

- **கையால key பண்ண documents-ஓட ஒரு gold set வச்சுக்கோங்க**, ஒவ்வொரு மாற்றத்துக்கும் field வாரியா accuracy-ஐ அளங்க.
- **Original, extraction, checks, approver எல்லாத்தையும் store பண்ணுங்க**, audit-க்காக.
- **Straight-through rate குறைஞ்சா alert பண்ணுங்க**; பெரும்பாலும் ஒரு supplier layout-ஐ மாத்திட்டாங்கன்னு அர்த்தம்.
- **Personal, bank details-ஐ mask பண்ணுங்க**, logs-லயும் review screens-லயும், தேவையில்லாத இடத்துல.
- **Rules-ஐ finance-ஓட review பண்ணுங்க**, ஒவ்வொரு quarter-லயும்; குறிப்பா GST மாற்றங்களுக்கு அப்புறம் tax rules-ஐ.

## Practice பண்ணுங்க

n8n-ஓட AI integration docs-ஐயும், ஒரு model provider-ஓட structured outputs guide-ஐயும் படிங்க.

1. பத்து invoices அல்லது receipts-ஐ collect பண்ணுங்க (உங்க சொந்த bills-ம் ஓகே), உங்களுக்கு தேவையான fields-க்கு ஒரு schema எழுதுங்க.
2. ஒரு AI step வச்சு fields-ஐ extract பண்ணி, arithmetic-ஐயும் ஒரு format rule-ஐயும் validate பண்ற ஒரு n8n workflow build பண்ணுங்க.
3. Failures-ஐ ஒரு review sheet-க்கு route பண்ணி, பத்துல எத்தனை straight through போச்சு, எத்தனை fields சரியா இருந்துச்சுன்னு அளங்க.
4. உங்க பத்து documents-ல check_invoice-ஐ run பண்ணுங்க; ஒரு GSTIN-ல ஒரு தப்பான digit-ஐயும், ஒரு line amount-ல ஒண்ணையும் வேணும்னே போட்டு, ரெண்டும் பிடிபடுதான்னு confirm பண்ணுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** உங்க straight-through rate-ஐயும், field accuracy-ஐயும், உங்க validation பிடிச்ச ஒரு error-ஐயும் காட்ட முடியும்.
