## இது என்ன

"AI job"-னா ஒரே job இல்ல. Companies roles-ஓட ஒரு family-க்கு ஆள் எடுக்குறாங்க, titles-உம் company-க்கு company மாறும். ஒரு firm-ல "GenAI developer" செய்யுறதை இன்னொரு firm-ல "AI engineer" செய்வாங்க; "AI engineer"-னு title வச்ச ஒரு post உண்மையில data analysis-ஆ இருக்கலாம். அதனால AI career-ஓட முதல் rule: **title-ஐ இல்ல, job description-ல இருக்குற duties-ஐ படிங்க.**

Roles-ஐ பிரிக்க ரொம்ப useful-ஆன வழி, ஒரு சாதாரண வாரத்துல நீங்க எவ்வளவு code எழுதுறீங்கங்குறது தான்:

```flow
dir: LR
title: Role-க்கு எவ்வளவு code வேணும்
Code வேணாம் | AI product manager, AI governance, உங்க field-ல AI -> கொஞ்சம் code | AI automation specialist, AI security engineer, AI evaluation
கொஞ்சம் code -> தினமும் code | AI, GenAI, agentic AI engineers, FDE, ML engineer, MLOps, data engineer
```

### தினமும் code எழுதுற roles

- **AI engineer** AI systems-ஐ end to end build பண்றாங்க. இந்தியால இந்த title பெரும்பாலும் language models மேல applications-ஐ தான் குறிக்கும், ஆனா பல posts classical machine learning basics-ஐயும் எதிர்பார்க்கும்.
- **Generative AI and LLM engineer** language models-ல ஆழமா போவாங்க: prompts, structured output, RAG, evals, serving costs.
- **Agentic AI engineer** plan பண்ணி, tools-ஐ call பண்ணி, actions எடுக்குற agents-ஐ build பண்ணி, அவை safe-ஆவும் observable-ஆவும் இருக்குற மாதிரி பாத்துக்குவாங்க.
- **Forward deployed engineer (FDE)** இதே systems-ஐ ஒரு customer-ஓட business-க்குள்ள build பண்றாங்க. வேலையில பாதி engineering; மீதி பாதி சரியான problem-ஐ கண்டுபிடிச்சு, ஆளுங்களை அந்த tool-ஐ use பண்ண வைக்குறது.
- **ML engineer** company-ஓட சொந்த prediction models-ஐ train பண்ணி deploy பண்றாங்க: fraud, credit risk, ranking, forecasting, vision. Labelled data, features, retraining தான் அடையாளம்.
- **MLOps engineer** production-ல models-ஐ ஓட்டுறாங்க: serving, drift-ஐயும் cost-ஐயும் monitor பண்றது, safe releases, shared platform.
- **Data engineer** ஒவ்வொரு model-உம் நம்பியிருக்குற data-வை நகர்த்தி clean பண்ற pipelines-ஐ build பண்றாங்க. இது இல்லாம எந்த AI system-உம் work ஆகாது, அதனால AI teams-க்குள்ள போக இது ஒரு common-ஆன, நிலையான வழி.
- **Data scientist, applied scientist** data-வை analyse பண்ணி, experiments ஓட்டி, புது models-ஐ design பண்றாங்க. Big tech, research labs-ல applied scientist roles-க்கு பெரும்பாலும் master's அல்லது PhD-யும் published work-உம் எதிர்பார்ப்பாங்க.

### கொஞ்சம் code வேணும்ங்குற roles

- **AI automation specialist** n8n, Make, Power Automate மாதிரி tools வச்சு business apps-ஐ connect பண்ணி, AI steps-ஐ சேர்க்குறாங்க. APIs, JSON படிப்பீங்க, சின்ன scripts எழுதுவீங்க.
- **AI security engineer** AI systems-ஐ பாதுகாக்குறாங்க, பாதுகாக்குறதுக்கு AI-ஐயும் use பண்றாங்க. ஒரு சாதாரண வாரத்துல ஒரு chatbot-க்கு threat model போடுறது, prompt injection, data leaks-க்கு அதை test பண்றது, ஒரு agent எதையெல்லாம் தொட அனுமதி இருக்குன்னு review பண்றது எல்லாம் இருக்கும். Security basics-உம் light Python-உம் மேல தான் இது நிக்குது; ரெண்டு skill sets-உம் இருக்குறவங்க ரொம்ப கம்மி.
- **AI evaluation, data quality roles** test questions, grading rubrics, labelling guidelines எழுதி, model answers-ஐ judge பண்றாங்க. பலர் annotation அல்லது rating வேலையா தான் ஆரம்பிக்குறாங்க. நிலையான entry point domain expertise: legal answers-ஐ rate பண்ற ஒரு lawyer, அல்லது Tamil output-ஐ judge பண்ற ஒரு Tamil speaker. Rating வேலை மட்டும் senior role-ஆ வளர்றது அரிது; ஒரு engineer-ஆ evals build பண்றது தான் வளரும்.

### Code வேணாத roles

- **AI product manager** எந்த AI features-ஐ build பண்ணணும், quality-ஐ எப்படி measure பண்ணணும், model தப்பா இருந்தா என்ன பண்ணணும்னு முடிவு பண்றாங்க.
- **AI governance and compliance specialist** AI safe-ஆ, fair-ஆ, சட்டப்படி இருக்கான்னு check பண்றாங்க: risk assessments, policies, audits, incident handling; இந்தியாவோட Digital Personal Data Protection (DPDP) Act மாதிரி laws-ஓட கீழ, EU customers-க்கு EU AI Act-ஓட கீழ.
- **உங்க இப்போதைய field, கூட AI.** AI தெரிஞ்ச marketers, HR staff, teachers, lawyers, doctors-க்கு title-ஐ மாத்தாமலேயே மதிப்பு இருக்கு.

பேர் சொன்ன பத்து roles ஒவ்வொண்ணுக்கும் Xplaind-ல ஒரு roadmap இருக்கு: AI Engineer, Generative AI and LLM Engineer, Agentic AI Engineer, Forward Deployed Engineer, ML Engineer, MLOps Engineer, AI Automation Specialist, AI Security Engineer, AI Product Manager, AI Governance and Compliance Specialist.

Nasscom-Zinnov India GCC Landscape report (May 2026) கணக்குப்படி FY26-ல 2,117 GCCs சுமார் 2.36 million பேருக்கு வேலை குடுத்துச்சு, அதுல Bengaluru தான் பெரிய hub. ஒரு bank-ஓட அல்லது retailer-ஓட GCC அவங்க சொந்த business-க்கு AI build பண்ண engineers-ஐ எடுக்குது, அதனால IT services firm-ஐ விட இங்க domain knowledge-க்கு அதிக மதிப்பு.

மொத்தமா AI hiring எவ்வளவு பெருசு? foundit-ஓட job-posting tracker 2025-ல இந்தியால 2,90,256 AI-linked job posts-ஐ கணக்கு போட்டுச்சு; IT-software, banking and finance முன்னாடி இருக்கு, Bengaluru top hub. 2026-ல 32% growth-னு forecast பண்ணுச்சு. இப்படிப்பட்ட numbers-ஐ கவனமா படிங்க: ஒரு post-னா ஒரு hire இல்ல, ஒரே opening பல தடவை post ஆகலாம், "AI-linked"-ல AI-ஐ வெறுமனே mention பண்ற jobs-உம் சேரலாம்.

### Hiring எப்படி நடக்குது

**எங்க தேடணும்.** Naukri, LinkedIn-ல ஆரம்பிங்க. Instahyre, foundit-உம் நிறைய use ஆகுது, Wellfound-ல நிறைய startups list ஆகியிருக்கு. GCCs பெரும்பாலும் அவங்க சொந்த careers pages வழியா ஆள் எடுக்குறாங்க. உள்ள இருக்குற ஒருத்தரோட referral தான் பெரும்பாலும் ஒரு மனுஷர் உங்க application-ஐ படிக்க வேகமான வழி; அதனால நூறு cold applications-ஐ விட alumni-உம் seniors-உம் முக்கியம்.

**ஒரு engineering role-க்கு வழக்கமான rounds.** Company-க்கு company steps மாறும், ஆனா பொதுவான pattern இது:

1. ஒரு online coding test அல்லது take-home task.
2. Python, APIs, AI basics பத்தி ஒரு technical round; உதாரணமா "இந்த RAG app பதில்களை கற்பனையா உருவாக்காம இருக்க என்ன பண்ணுவீங்க?"
3. ஒரு project deep dive. உங்க resume-ல இருந்து ஒரு project-ஐ எடுத்து, ஒவ்வொரு choice-ஐயும் ஏன் பண்ணீங்க, எப்படி measure பண்ணீங்க, எது fail ஆச்சுன்னு கேப்பாங்க. Fake அல்லது copy பண்ணின projects இங்க உடைஞ்சு போயிடும்.
4. Experienced hires-க்கு ஒரு design round: "ஒரு நாளைக்கு 10,000 users-க்கு ஒரு support assistant design பண்ணுங்க".
5. Teamwork, salary, notice period பத்தி ஒரு manager அல்லது HR round.

Product, governance, security roles-ல coding test-க்கு பதிலா case studies இருக்கும்: ஒரு spec எழுதுறது, ஒரு feature-ஓட risk-ஐ assess பண்றது, அல்லது ஒரு chatbot-ல இருக்குற weakness-ஐ கண்டுபிடிக்குறது.

### Employers என்ன எதிர்பார்க்குறாங்க

- **Engineering roles:** Python, APIs, Git, ஒரு cloud; prompting, RAG, agents, evals மாதிரி language-model skills; ஒரு notebook இல்ல, deploy பண்ணி measure பண்ணின system-ஐ காட்டுற projects.
- **Product, governance, automation roles:** AI என்ன செய்யும், என்ன செய்யாதுன்னு தெரிஞ்சிருக்குறது, problems-ஐ frame பண்றது, metrics define பண்றது, processes-ஐ map பண்றது, தெளிவா எழுதுறது.
- **எல்லாருக்கும்:** evidence. ஒரு test set-உம் ஒரு number-உம் இருக்குற project, அல்லது வேலையில நீங்க deliver பண்ணின ஒரு கதை, certificates list-ஐ விட பலம். Certificates பெரும்பாலும் IT services firms-லயும் cloud அதிகமா இருக்குற roles-லயும் தான் அதிகம் உதவும், ஒரு tiebreaker-ஆ; முக்கிய proof-ஆ இல்ல.

Big tech, global AI labs, Bengaluru அதிகமா pay பண்ணும்; IT services firms, சின்ன நகரங்கள் கம்மியா pay பண்ணும். ### Timelines, fresher market

தோராயமா சொன்னா, Xplaind roadmaps-க்கு சீரான படிப்பு இவ்வளவு ஆகும்: product, automation, governance paths-க்கு சுமார் மூணு மாசம், agentic AI-க்கு நாலு, FDE, MLOps, AI security-க்கு ஆறு, AI engineer, GenAI engineer, ML engineer-க்கு ஒன்பது. இது learning நேரம் மட்டும் தான். Job search-க்கு இன்னும் சில மாசம் ஆகும்னு plan பண்ணுங்க.

Freshers-க்கு தான் ரொம்ப கஷ்டம். பல posts ரெண்டு அல்லது அதுக்கு மேல வருஷ experience கேக்குது, juniors முன்னாடி கத்துக்கிட்ட routine வேலையில நிறைய இப்போ AI செய்யுது ("AI-யும் வேலைகளும்" lesson-ஐ பாருங்க). Freshers IT services hiring, convert ஆகுற internships, GCC graduate programmes, degree-ஐ விட projects-ஐ மதிக்குற சின்ன startups வழியா உள்ள நுழையுறாங்க. Experienced ஆளுங்க பெரும்பாலும் **அவங்க சொந்த company-க்குள்ளயே** ஒரு AI pilot-ல சேர்ந்து தான் வேகமா switch பண்றாங்க.

### ஒரு job description-ஐ எப்படி படிக்குறது

Title-ஐ இல்ல, duties-ல இருக்குற verbs, nouns-ஐ பாருங்க. ஒரு post உண்மையில எந்த role-னு இந்த signals சொல்லும்:

## ஒரு worked example

### ஒரு job post-ஐ decode பண்றது

Chennai-ல final-year B.Tech படிக்குற Sneha இந்த post-ஐ பாக்குறாங்கன்னு வச்சுக்கோங்க (கற்பனையான example, ஆனா வழக்கமான மாதிரி):

> **GenAI Engineer, fintech, Chennai, 0 to 2 years.** UPI transaction data-ல இருந்து features build பண்ணணும். Fraud-ஐ flag பண்ண gradient-boosted models-ஐ train பண்ணி tune பண்ணணும். Precision, recall-ஐ வாரா வாரம் track பண்ணி, மாசா மாசம் retrain பண்ணணும். Python, SQL, scikit-learn. LLMs-ல exposure இருந்தா plus.

Title GenAI-னு சொல்லுது. Duties features, training, precision, recall, retraining-னு சொல்லுது, LLMs வெறும் "plus" தான். Table-ஐ வச்சு பாத்தா இது ஒரு **ML engineer** job. நல்ல job தான், ஆனா Sneha மூணு RAG projects-ஓட apply பண்ணா, பொருந்தாத ஆளா தெரிவாங்க. அவங்க அதை "ML, ஒரு tabular project சேர்த்தா மட்டும் apply பண்ணு"-னு mark பண்ணிட்டு அடுத்ததுக்கு போறாங்க.

இப்படியே இருபது posts படிக்குறாங்க. பதினாலு உண்மையான AI engineer வேலை, நாலு ML engineer வேலை, ரெண்டு AI label ஒட்டின analyst jobs. அந்த பதினாலுலயும் திரும்ப திரும்ப வர்ற skills Python, RAG, evaluation, deployment; அது தான் அவங்க plan.

### Sneha-வோட switch, மாசா மாசம்

கீழ இருக்குற numbers ஒரு நடைமுறையான path-ஓட illustration தான், survey இல்ல.

- **மாசம் 1 முதல் 3:** AI Engineer roadmap-ல Git, APIs, அவங்களோட முதல் language-model calls. Python basics ஏற்கனவே தெரியும், அதனால முதல் stage-ல ஒரு பகுதியை skip பண்ணி, ஒன்பது மாசத்துக்கு பதிலா ஏழு மாசத்துலயே learning-ஐ முடிக்குறாங்க.
- **மாசம் 4 முதல் 7:** மூணு projects, ஒவ்வொண்ணும் deploy பண்ணது, ஒவ்வொண்ணுக்கும் ஒரு சின்ன evaluation report.
  1. **அவங்க university-ஓட 200 பக்க academic regulations மேல ஒரு question-answering assistant.** சரியான பதில்களோட 60 test questions எழுதுறாங்க. ஆரம்பத்துல answer accuracy 68%, பெரும்பாலும் ரெண்டு பக்கத்துல பிரிஞ்சு இருந்த rules தொலைஞ்சு போனதால. Text-ஐ split பண்ற முறையை மாத்தினதும் அது 85%-க்கு ஏறுது. Cite பண்ணின page உண்மையில பதிலை support பண்ணுதான்னு எவ்வளவு தடவைன்னும் measure பண்றாங்க.
  2. **ஒரு invoice extractor**, scan பண்ணின GST invoices-ஐ JSON-ஆ மாத்துது: GSTIN, date, total, tax. 100 invoices-ல field வாரியா accuracy-ஐ measure பண்றாங்க. ஒவ்வொரு GSTIN-உம் சரியா 15 characters-ஆ இருக்கான்னு ஒரு check சேர்த்ததும் நிறைய reading errors பிடிபடுது.
  3. **ஒரு support-ticket agent**, ஒரு complaint-ஐ படிச்சு, ஒரு tool call வச்சு order-ஐ தேடி, ஒரு reply-ஐ draft பண்ணுது. அது எவ்வளவு தடவை சரியான tool-ஐ தேர்ந்தெடுக்குது, ஒரு ticket-க்கு எவ்வளவு cost-னு measure பண்றாங்க.
- **மாசம் 8 முதல் 10:** applications. முதல் 30-க்கு கிட்டத்தட்ட reply-யே வரல. காரணம் அவங்க resume: அது results-ஐ இல்லாம tools-ஐ list பண்ணுது ("LangChain, FAISS, FastAPI"). ஒவ்வொரு bullet-ஐயும் ஒரு result-ஆ மாத்தி எழுதுறாங்க: "raised answer accuracy from 68% to 85% on a 60-question test set". அடுத்த 50 applications-லயும் அஞ்சு alumni referrals-லயும் எட்டு first rounds கிடைக்குது.
- **எது தப்பா போச்சு.** ஒரு project deep dive-ல, மீதி 15% questions-ல assistant ஏன் fail ஆச்சுன்னு interviewer கேக்குறார். அவங்க அதை பாக்கவே இல்ல, reject ஆகுறாங்க. அதுல இருந்து ஒவ்வொரு project-க்கும் failure cases-ஓட ஒரு எழுதின list வச்சுக்குறாங்க.
- **Result:** Chennai-ல ஒரு mid-size product company-ல ₹9 lakh CTC-க்கு AI engineer offer; 0 முதல் 2 வருஷத்துக்கான 6 to 12 band-க்குள்ள.

### இன்னும் ரெண்டு சின்ன cases

## பொதுவா பண்ற தப்புகள்

- **Title, hype அல்லது அதிக salary பாத்து தேர்ந்தெடுக்குறது.** Commit பண்றதுக்கு முன்னாடி இருபது real job descriptions படிச்சு, அந்த role-ல இருக்குற ஒருத்தர் கிட்ட பேசுங்க.
- **Title-ல "AI" இருக்குற எல்லா post-க்கும் apply பண்றது.** GenAI-னு label ஒட்டின ஒரு ML அல்லது analyst job உங்க application-ஐயும் recruiter-ஓட நேரத்தையும் வீணாக்கும்.
- **Projects-க்கு பதிலா certificates சேர்க்குறது.** Certificates நீங்க படிச்சீங்கன்னு காட்டும். Build அல்லது deliver பண்ண முடியும்ங்குற proof தான் employers-க்கு வேணும்.
- **Numbers இல்லாத projects.** Test set இல்லாத ஒரு deployed demo மத்த எல்லா resume மாதிரியும் தான் தெரியும். அதை measure பண்ணுங்க, எங்க fail ஆகுதுன்னு தெரிஞ்சுக்கோங்க.
- **ஏற்கனவே இருக்குற strengths-ஐ கவனிக்காம விடுறது.** AI skills சேர்த்துக்குற ஒரு security analyst, banker அல்லது nurse, இன்னொரு fresh GenAI engineer-ஐ விட அரிது.
- **எல்லாத்தையும் கத்துக்க முயற்சி பண்றது.** ஒரு roadmap-ஐ தேர்ந்தெடுத்து ஆழமா போங்க; அப்புறம் விரிவாக்கலாம்.
- **ராத்திரியோட ராத்திரி results எதிர்பார்க்குறது.** மாசக்கணக்கா learning, மாசக்கணக்கா searching-க்கு plan பண்ணுங்க.
- **பெரிய பெயர்களுக்கு மட்டும் apply பண்றது.** GCCs, mid-size product firms, IT services AI practices எல்லாம் சேர்ந்து பெரும்பாலும் அதிக ஆளுங்களை எடுக்குறாங்க.

## Practice பண்ணுங்க

Skills பத்தின பரந்த பார்வைக்கு Watch & learn panel-ல இருக்குற video lessons-ஐ பாருங்க.

1. **பத்து job descriptions-ஐ decode பண்ணுங்க.** Naukri அல்லது LinkedIn-ல இந்தியால பத்து AI posts கண்டுபிடிங்க. ஒவ்வொண்ணுக்கும் title, அதிகமா mention ஆகுற மூணு duties, அது உண்மையில எந்த role (மேல இருக்குற table-ஐ use பண்ணுங்க), coding வேணுமான்னு எழுதுங்க.
2. **உங்களை match பண்ணுங்க.** உங்க background-க்கு நல்லா பொருந்துற ரெண்டு roles-ஐ தேர்ந்தெடுங்க. ஒவ்வொண்ணுக்கும் உங்ககிட்ட ஏற்கனவே என்ன இருக்கு, என்ன இல்ல, Jobs page-ல salary band என்னன்னு list பண்ணுங்க.
3. **ஒரு evidence-ஐ plan பண்ணுங்க.** எட்டு வாரத்துல முடிக்கக்கூடிய ஒரு project அல்லது work pilot-ஐ தேர்ந்தெடுத்து, அதை எப்படி measure பண்ணுவீங்கன்னு எழுதுங்க.
4. **ஒருத்தர் கிட்ட பேசுங்க.** அந்த roles-ல ஒண்ணுல வேலை செய்யுற ஒருத்தருக்கு (ஒரு senior, alumnus அல்லது LinkedIn contact) message பண்ணி, ஒரு சாதாரண வாரம் எப்படி இருக்கும்னு கேளுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** உங்களுக்கு நல்லா பொருந்துற AI role-ஐ பேர் சொல்லி, hype இல்லாம job posts அடிப்படையில மூணு காரணங்கள் சொல்லி, நீங்க build பண்ணப்போற முதல் evidence-ஐ விவரிக்க முடிஞ்சா.
