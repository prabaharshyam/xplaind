## இது என்ன

ஒரு **workplace AI policy**, வேலையில AI tools-ஐ employees எப்படி use பண்ணலாம்னு சொல்லுது. AI assistants-ஐ use பண்றதும் ஈஸி, misuse பண்றதும் ஈஸி; அதனால தான் இது இருக்கு: customer phone numbers இருக்குற ஒரே ஒரு spreadsheet-ஐ paste பண்ணாலே ஒரு client contract-ஐயும், உங்க company-ஓட confidentiality duties-ஐயும் மீறலாம்; இந்தியாவோட data law முழுசா அமலுக்கு வர வர, law-வையும் மீறலாம்.

நல்ல policies சின்னதா, practical-ஆ இருக்கும். அவை பொதுவா ஏழு விஷயங்களை cover பண்ணும்:

| Section | என்ன சொல்லுது | Example rule |
| --- | --- | --- |
| **Approved tools** | எந்த assistants, features, extensions, notetakers allowed | "Company-licensed assistant-ஐ use பண்ணுங்க; வேலைக்கு personal accounts allowed இல்லை" |
| **Data rules** | ஒவ்வொரு tool-லயும் எதை போடலாம், எதை போடக்கூடாது | "CRM-ஓட built-in AI-க்கு வெளியே customer personal data கூடாது" |
| **Use cases** | AI எங்க encourage பண்ணப்படுது, எங்க restrict பண்ணப்படுது | "Drafting, summarising-க்கு encourage பண்றோம்; hiring decisions-க்கு கூடாது" |
| **Review, accuracy** | AI output-ஐ யார் check பண்றாங்க, யார் பொறுப்பு | "ஒவ்வொரு figure-ஐயும் நீங்க check பண்றீங்க; நீங்க அனுப்புறதுக்கு நீங்க தான் owner" |
| **Disclosure** | AI use ஆச்சுன்னு எப்போ மக்களுக்கு சொல்லணும் | "ஒரு report பெருமளவு AI-drafted-ஆ இருந்தா clients-கிட்ட சொல்லுங்க" |
| **Intellectual property** | AI உதவியோட பண்ண வேலைக்கு யார் owner, copy பண்றதை தவிர்க்கிறது | "மத்தவங்களோட copyrighted வேலையை rewrite பண்ண paste பண்ணாதீங்க" |
| **Reporting** | ஒரு தப்பையோ problem-ஐயோ எப்படி report பண்றது, எவ்வளவு வேகமா | "1 மணி நேரத்துக்குள்ள IT security-கிட்ட சொல்லுங்க; நேர்மையான reports-க்கு தண்டனை இல்லை" |

ஒரு employee-ஆ, policy-ஐ நீங்க மனப்பாடம் பண்ண வேண்டியதில்ல. ஒவ்வொரு task-க்கும் முன்னாடி மூணு கேள்விகளுக்கு பதில் சொல்லணும், ஒவ்வொரு பதிலும் policy-ல எங்க இருக்குன்னு தெரிஞ்சிருக்கணும்.

இந்த lesson-ல, Chennai-ல ஒரு manufacturer-கிட்ட sales-ல வேலை பண்ற Karthik, அவரோட company rules-க்குள்ள ஒரு proposal தயார் பண்றதை follow பண்றோம். முடிவுல, ஒரு நல்ல policy எதை cover பண்ணும், உங்க data-வை எப்படி sort பண்றது, தினமும் use பண்ற tools-ல built-in-ஆ இருக்குற AI-ஐ எப்படி handle பண்றது, ஒரு தப்புக்கு அப்புறம் என்ன பண்றது, உங்க company-ல policy-யே இல்லைன்னா என்ன பண்றதுன்னு தெரிஞ்சுப்பீங்க.

## இது எப்படி work ஆகுது

### Companies ஏன் கவலைப்படுறாங்க

ஒரு consumer AI tool-ல நீங்க type பண்ணும்போது, அந்த text store ஆகலாம், settings-ஐயும் vendor-ஓட terms-ஐயும் பொறுத்து service-ஐ improve பண்ண use ஆகலாம். அது மூணு வகையான risk-ஐ உருவாக்குது:

1. **Legal.** இந்தியாவோட Digital Personal Data Protection Act, 2023 (DPDP Act), personal data எப்படி use ஆகுது, share ஆகுதுன்னு limit பண்ணுது. அதோட Rules November 2025-ல notify ஆச்சு, businesses-க்கான பெரும்பாலான duties May 2027-ல இருந்து apply ஆகும். அதுவரைக்கும், financial details, passwords, health records மாதிரி sensitive personal data பத்தின IT Act-ஓட 2011 rules இன்னும் apply ஆகுது.
2. **Contractual.** Client contracts அவங்க information-ஐ third parties-கிட்ட share பண்றதை அடிக்கடி தடை பண்ணும், அல்லது குறிப்பிட்ட நாடுகள்ல மட்டும் allow பண்ணும். இது இன்னைக்கே apply ஆகுது.
3. **Confidentiality.** Strategy, release ஆகாத financial results, source code leak ஆகலாம். 2023-ல, engineers internal source code-ஐ ஒரு public chatbot-ல paste பண்ணதுக்கு அப்புறம், Samsung தன் staff public chatbots use பண்றதை restrict பண்ணுச்சு.

நீங்க ஒரு bank, NBFC, insurer அல்லது hospital-ல வேலை பண்ணா, உங்க regulator இதுக்கு மேல rules சேர்க்கும், அது உங்க compliance team-க்கு தெரியும். உதாரணமா, RBI-யோட FREE-AI committee report (August 2025), regulated firms-கிட்ட ஒரு board-approved AI policy இருக்கணும்னு recommend பண்ணுது. இது binding rule இல்ல, advice தான், ஆனா sector எந்த பக்கம் போகுதுன்னு காட்டுது.

ஒரு company licence, rules-ஐ யார் set பண்றாங்கன்னு மாத்துது:

| | Personal free account | Company-licensed tool |
|---|---|---|
| Terms | நீங்க click பண்ணி ஏத்துக்கிட்டீங்க | Company sign பண்ண ஒரு contract |
| உங்க data-ல training | உங்க settings-ஐயும் vendor-ஓட terms-ஐயும் பொறுத்தது | Company-ஓட contract set பண்ணுது; அது என்ன சொல்லுதுன்னு IT-கிட்ட கேளுங்க |
| Control | Admin control இல்லை | Single sign-on, admin settings, audit logs |
| ஏதாவது leak ஆனா | Company-ஆல அதை பார்க்கவோ fix பண்ணவோ முடியாது | Data எங்க போச்சுன்னு security team-க்கு தெரியும் |
| எதுக்கு use பண்ணலாம் | அதிகபட்சம் public material | Approved வேலை, data rules-க்குள்ள |

ஒரு licence blank cheque இல்ல. Company approve பண்ண tool, settings-க்கு, policy குறிப்பிடுற data-க்கு மட்டும் தான் அது பொருந்தும்.

### உங்க data-வை நாலு categories-ஆ sort பண்ணுங்க

| Category | Examples | Rule of thumb |
| --- | --- | --- |
| **Public** | Publish ஆன brochures, company website, public reports | பொதுவா எந்த tool-லயும் பரவாயில்லை |
| **Internal** | Process notes, templates, internal announcements | Approved tools மட்டும் |
| **Confidential** | Client contracts, release ஆகாத results, strategy, draft prices | Approved tools மட்டும், சில நேரம் அதுவும் கூடாது |
| **Personal, sensitive** | Phone numbers அல்லது emails கூட பெயர்கள், salaries, health, Aadhaar அல்லது PAN numbers, bank details | எல்லாத்தையும் விட strict; அடிக்கடி ஒரு குறிப்பிட்ட system-ல மட்டும் |

மக்கள் அடிக்கடி தப்பா sort பண்ற மூணு items:

- **ஒரு client-க்கான draft price list** confidential, public இல்ல. அது publish ஆனா, ஆகும்போது மட்டும் தான் public ஆகும்; ஒரு client quote பொதுவா எப்பவுமே publish ஆகாது.
- **உங்க CRM அல்லது inbox-ஓட ஒரு screenshot**, அதுல பெயர்கள், numbers அல்லது emails தெரிஞ்சா personal data தான், அந்த screenshot எதைக் காட்ட எடுத்ததா இருந்தாலும்.
- **உங்க சொந்த meeting notes**, அதுல இருக்குற எல்லாத்தையும் விட அதிக sensitive-ஆன விஷயத்தோட category-ஐ எடுத்துக்கும். ஒரு client call-ஓட notes பொதுவா confidential; அதுல யாரோட contact details-ஆவது இருந்தா personal.

சந்தேகம் இருந்தா, ஒரு document-ஐ ஒரு category அதிக strict-க்கு நகர்த்துங்க.

### நீங்க வேணும்னே open பண்ணாத AI

நிறைய leaks ஒரு chatbot-ஐ open பண்றதால வர்றதில்ல, மக்கள் ஏற்கனவே use பண்ற tools-ல built-in-ஆ இருக்குற AI-ல இருந்து தான் வருது. இது ஒவ்வொண்ணுக்கும் உங்க policy-ஐ check பண்ணுங்க; அது எதுவும் சொல்லலைன்னா, ஒண்ணை switch on பண்றதுக்கு முன்னாடி IT-கிட்ட கேளுங்க.

| Feature | அது என்ன பார்க்க முடியும் | Sensible default |
| --- | --- | --- |
| **Office suites, email-ல AI**, "summarise this thread" அல்லது "draft a reply" மாதிரி | அதை point பண்ற documents, sheets, mail, சில நேரம் உங்க முழு drive | உங்க company license பண்ணி switch on பண்ண version-ஐ மட்டும், data rules-க்குள்ள மட்டும் use பண்ணுங்க |
| Rewrite, summarise அல்லது translate பண்ற **browser extensions** | அடிக்கடி நீங்க open பண்ற ஒவ்வொரு page-உம், CRM, HR portal, webmail உட்பட | IT approve பண்ண extensions-ஐ மட்டும் install பண்ணுங்க; மத்ததை எடுத்துடுங்க |
| **AI meeting notetakers** | Call-ல எல்லாரும் பேசுற எல்லாமே, கூடவே பெயர்கள், share பண்ற screens | ஆரம்பத்துலயே எல்லார்கிட்டயும் சொல்லி, யார் வேணும்னாலும் மறுக்க விடுங்க; external calls-க்கு, முதல்ல மறுபக்கத்துகிட்ட கேளுங்க |
| **Coding assistants** | Open ஆன files, அடிக்கடி முழு repository, சில நேரம் keys இருக்குற configuration files | Approved assistant மட்டும், உங்க client allow பண்ற code-ல மட்டும்; அது படிக்கிற files-ல passwords, keys வைக்காதீங்க |

Notetakers-க்கு தனி கவனம் வேணும், ஏன்னா அவை உங்களை மட்டும் இல்ல, மத்தவங்களையும் record பண்ணுது. Recording rules நாட்டுக்கு நாடு மாறும். உதாரணமா California-ல, ஒரு confidential conversation-ஐ record பண்ண அதுல இருக்குற எல்லாரோட consent-உம் வேணும்; அதனால ஒரு US team கூட நடக்குற client call, மரியாதை சார்ந்த கேள்வி மட்டும் இல்ல, ஒரு legal கேள்வியையும் எழுப்பலாம். நிறைய client contracts recording-ஐயும் தடை பண்ணுது. ஒரு transcript-ஐ அந்த meeting மாதிரியே treat பண்ணுங்க: அதுக்கும் அதே category, அதே rules.

### தேவையில்லாததை எடுத்துடுங்க

அடிக்கடி sensitive பகுதி இல்லாமலே task-ஐ முடிக்கலாம். பெயர்களுக்கு பதிலா roles போடுங்க ("client-ஓட purchase head"), phone numbers, account numbers-ஐ எடுத்துடுங்க, முக்கியம் இல்லாத figures-ஐ round பண்ணுங்க, task-க்கு தேவையானதை மட்டும் வைங்க. உண்மையான company பத்தி எழுதுற அதே அளவு நல்லா "ஒரு பெரிய automotive client" பத்தியும் assistant எழுதும். Worked example-ல ஒரு முழு before, after இருக்கு.

### Review, disclosure, accountability

உங்க வேலையில உங்க பெயர் இருக்கு. ஒரு client report-ல தப்பான figure இருந்தா, "AI தான் எழுதுச்சு"-ங்குறது excuse இல்ல. Policies பொதுவா இதை வெளிப்படையா சொல்லும், managers-உம் clients-உம் எப்படியும் இதை தான் எடுத்துக்குவாங்க. இதுல இருந்து ரெண்டு பழக்கங்கள் வருது:

- **எல்லாத்தையும் விட முக்கியமானதை முதல்ல check பண்ணுங்க:** prices, dates, பெயர்கள், legal terms, நீங்க promise பண்ற எதுவும்.
- **Policy அல்லது படிக்கிறவங்க எதிர்பார்த்தா disclose பண்ணுங்க.** ஒரு deliverable பெருமளவு AI-drafted-ஆ இருந்தா சொல்லணும்னு சில clients கேப்பாங்க. நீங்க AI-ஐ எப்படி use பண்றீங்கன்னு உங்க manager-கிட்ட சொல்றது, ஏதாவது தப்பா போனா உங்களையும் பாதுகாக்கும்.

### தவறுதலா ஏதாவது paste பண்ணிட்டா

எல்லாரும் ஒரு தடவை இந்த தப்பை பண்ணுவாங்க: தப்பான file, தப்பான tab, இன்னும் sign in-ஆ இருக்குற ஒரு personal account. முக்கியம் அடுத்த ஒரு மணி நேரம் தான்.

1. **நிறுத்துங்க.** இன்னும் எதுவும் அனுப்பாதீங்க, அதை "மறந்துடு"-ன்னு chatbot-கிட்ட கேக்காதீங்க. ஏற்கனவே store ஆனதை அதால undo பண்ண முடியாது.
2. **Facts-ஐ note பண்ணுங்க:** எந்த tool, எந்த account, நேரம், சரியா என்ன உள்ள போச்சு.
3. **உடனே report பண்ணுங்க**, IT அல்லது security-கிட்ட, உங்க policy-ல இருக்குற channel வழியா. சில incidents-ஐ கவனிச்ச 6 மணி நேரத்துக்குள்ள, இந்தியாவோட cyber security agency-யான CERT-In-க்கு உங்க company report பண்ண வேண்டியிருக்கலாம்; அதனால ஒரு நாள் delay ஆனா, ஒரு சின்ன problem அந்த duty-ஐ மீறுனதா மாறிடலாம்.
4. Report பண்ணதுக்கு அப்புறம், அல்லது security சொல்றபடி, **chat-ஐ delete பண்ணுங்க**. Delete பண்றது உதவும், ஆனா service அதோட terms-படி ஒரு காலம் வரைக்கும் ஒரு copy-ஐ இன்னும் வச்சிருக்கலாம்; அதனால delete பண்றதும் fix பண்றதும் ஒண்ணு இல்ல.
5. நீங்க paste பண்ண **எந்த password, key அல்லது access token-ஐயும் மாத்துங்க**, அதே நாள்ல.

நேர்மையான, வேகமான reports-க்கு தண்டனை இல்லைன்னு நல்ல policies சொல்லும். ஒரு தப்பை மறைக்கிறது தான் அதை disciplinary matter-ஆ மாத்துது.

### Policy இல்லாதப்போ

நிறைய சின்ன companies-ல இன்னும் AI policy இல்ல. அதுக்கு rules இல்லைன்னு அர்த்தம் இல்ல: laws, contracts இன்னும் apply ஆகும். ஒரு policy வர்ற வரைக்கும்:

1. எந்த tools allowed-னு உங்க manager அல்லது IT team-கிட்ட கேளுங்க.
2. Public material அல்லது உங்க சொந்த confidential இல்லாத notes-ஐ மட்டும் use பண்ணுங்க.
3. பெயர்கள், numbers, identifiers-ஐ எடுத்துடுங்க.
4. Personal data, passwords அல்லது keys-ஐ எப்பவுமே paste பண்ணாதீங்க.
5. Use பண்றதுக்கு முன்னாடி எல்லாத்தையும் check பண்ணுங்க.
6. நீங்க AI-ஐ எப்படி use பண்றீங்கன்னு உங்க manager-கிட்ட சொல்லுங்க.

இன்னும் நல்லது, ஒரு one-page draft-ஐ நீங்களே குடுங்க. உங்களுக்கு ஏத்த மாதிரி மாத்திக்க ஒரு template இதோ. இது ஒரு ஆரம்பப் புள்ளி, legal advice இல்ல; final rules-ஐ IT, legal-க்கு பொறுப்பானவங்ககிட்ட விடுங்க.

```text
[Company] AI use policy (draft, version 1, [date])

1. Approved tools: [licensed assistant], with [settings]. No personal
   AI accounts for work. Ask IT before switching on any other AI
   feature, browser extension or notetaker.
2. Data: public and internal data in approved tools. Confidential
   client data only where the client contract allows it. Personal
   data only in [named systems]. Never passwords or keys.
3. Encouraged: drafting, summarising, research, formatting.
4. Needs approval: anything customer-facing, decisions about people
   (hiring, appraisal, credit), recording external calls.
5. Review: you check every fact and figure; [named role] reviews
   prices and anything sent to a client.
6. Disclosure: tell clients when a deliverable is largely AI-drafted,
   or when their contract asks.
7. Ownership: do not paste others' copyrighted work to rewrite it.
8. Mistakes: report to [contact] within 1 hour. Honest reports are
   not punished.
9. Owner: [name]. Reviewed every 6 months.
```

## ஒரு worked example

இது ஒரு illustrative case. Method-ஐ காட்டுறதுக்காக company, பெயர்கள், numbers எல்லாம் கற்பனையா உருவாக்கினது.

Karthik, Chennai-ல ஒரு mid-sized machine-tools manufacturer-கிட்ட sales-ல வேலை பண்றாரு. ஒரு புது plant-க்கு அஞ்சு CNC machines தேவைப்படுற ஒரு பெரிய automotive client-க்கு proposal தயார் பண்ண அவர் AI-ஐ use பண்ண விரும்புறாரு.

அவரோட company-ஓட one-page policy சொல்லுது:

- Company-licensed assistant internal, confidential information-க்கு approved. வேலைக்கு personal free accounts allowed இல்லை.
- பெயர்கள், phone numbers மாதிரி customer personal data, CRM-லயும் அதோட built-in AI features-லயும் மட்டும் தான் போகணும்.
- Video-call tool-ஓட AI notetaker internal calls-க்கு approved. External calls-க்கு, முதல்ல மறுபக்கத்துகிட்ட கேளுங்க.
- அனுப்புறதுக்கு முன்னாடி, pricing-ஐ finance team check பண்ணணும், client documents-ஐ account manager review பண்ணணும்.

**Step 1: Notes-ஐ clean பண்றது.** முதல் call-ல இருந்து அவரோட notes:

```text
Before: Spoke to Ramesh Natarajan (purchase head, 98765 43210) at
        Zentora Motors. Need 5 CNC machines for the new plant by March.
        Budget about Rs 2.6 crore. Unhappy with current vendor's
        service: engineers take 3 to 4 days to arrive.

After:  The client's purchase head needs 5 CNC machines for a new
        plant by March. Budget about Rs 2.6 crore. Unhappy with the
        current vendor's service: engineers take 3 to 4 days to arrive.
```

பெயரும் phone number-உம் personal data, அதனால அவை CRM-லயே இருக்கும். Budget-உம் client-ஓட தேவைகளும் confidential, அதுக்கு licensed assistant approved. Client-ஓட பெயர் draft-க்கு எதையும் சேர்க்கல, அதனால அதுவும் போயிடுது.

**Step 2: Limits கூட prompt பண்றது.** Licensed assistant-ல அவர் எழுதுறாரு:

```text
You are helping me draft a sales proposal for CNC machines. Using the
notes and our standard proposal sections below, draft three sections:
the client's needs, our proposed solution, and our service plan.
Formal Indian business English, under 600 words. Do not invent prices,
delivery dates or specifications. Write [CHECK] wherever a figure is
needed. Then build a pricing table from the price list below.
```

"Do not invent" line முக்கியம். அது இல்லைன்னா, யாருமே கேக்காத, நம்புற மாதிரி இருக்குற figures-ஆல assistants அடிக்கடி gaps-ஐ நிரப்பிடும்.

**Step 3: Review தப்பை பிடிக்குது.** Quote-ல ரெண்டு பகுதி இருக்கு: ₹2 crore மதிப்புள்ள அஞ்சு machines, அப்புறம் company எப்பவுமே discount குடுக்காத ₹50 lakh spares, installation. Assistant standard 8% discount-ஐ முழு ₹2.5 crore-க்கும் apply பண்ணிடுச்சு. Finance அதை கண்டுபிடிச்சாங்க: ₹2 crore-ல 8% ₹16 lakh, ஆனா draft ₹20 lakh-னு காட்டுச்சு. அந்த தப்பு ₹4 lakh-ஐ விட்டுக்குடுத்திருக்கும். அதை பிடிச்சது review step தான், AI இல்ல.

**Step 4: ஒரு notetaker கேள்வி.** Follow-up video call-ல, meeting tool அதோட AI notetaker-ஐ switch on பண்ணலாமான்னு கேக்குது. இது external call, அதனால Karthik ஆரம்பத்துலயே கேக்குறாரு. Purchase head வேண்டாம்னு சொல்றாரு: அவரோட சொந்த company supplier calls-ஐ record பண்றதை தடை பண்ணுது. Karthik கையால notes எடுத்து, அப்புறம் contact details-ஐ CRM-ல சேர்க்குறாரு.

அப்புறம் ஒரு colleague "அது வேகமா இருக்கும்"-னு ஒரு free personal account-ஐ suggest பண்றாரு. Licensed tool-ஐ எப்படி open பண்றதுன்னு Karthik அவருக்கு காட்டுறாரு, அதுக்கு ஒரு நிமிஷத்துக்கும் குறைவா தான் ஆகுது. Colleagues ஒருத்தருக்கொருத்தர் நினைவுபடுத்தும்போது தான் policies work ஆகுது.

## பொதுவா பண்ற தப்புகள்

- **வேலை data-க்கு personal accounts-ஐ use பண்றது.** பாதிப்பில்லாதது மாதிரி தோணினாலும், அது data-வை உங்க company-ஓட control-க்கு வெளியே வைக்குது.
- **ஒரு tool approved-னா அதோட ஒவ்வொரு feature-உம் approved-னு நினைக்கிறது.** Connectors, extensions, notetakers, agent modes ஒவ்வொண்ணும் data-வை ஒரு புது இடத்துக்கு அனுப்பலாம். ஒவ்வொண்ணையும் check பண்ணுங்க.
- **General assistants-ல customer personal data-வை paste பண்றது.** சொல்லப்பட்ட system-ஐ use பண்ணுங்க, அல்லது முதல்ல personal details-ஐ எடுத்துடுங்க.
- **கேக்காமலே ஒரு notetaker-ஐ switch on பண்றது.** அது call-ல இருக்குற எல்லாரையும் record பண்ணுது, மறுபக்கம் அதை allow பண்ணாம இருக்கலாம்.
- **தவறா paste பண்ணதை மறைக்கிறது, அல்லது chat-ஐ delete மட்டும் பண்றது.** உடனே report பண்ணுங்க; delete பண்றது அதை undo பண்ணாது, delay ஆனா ஒரு 6 மணி நேர reporting duty-ஐ மீறலாம்.
- **"Policy இல்லை"-னா "rules இல்லை"-னு நினைக்கிறது.** Data protection law, contracts, confidentiality இன்னும் apply ஆகும்.
- **AI "பொதுவா சரியா இருக்கும்"-னு review-ஐ skip பண்றது.** Pricing, contracts, customer data-க்கு "பொதுவா சரி" போதாது.
- **Policy-ஐ ஒரு தடவை படிச்சா போதும்னு நினைக்கிறது.** Tools மாற மாற policies-உம் மாறும்; updates-ஐ check பண்ணுங்க.

## Practice பண்ணுங்க

கீழ link பண்ணியிருக்குற AI Fluency course-ல responsible use பத்தின section-ஐ பண்ணுங்க, இந்தியாவோட DPDP law பத்தின PRS-ஓட summary-ஐ படிங்க. அது 2023-ல pass ஆன Act-ஐ cover பண்ணுது; Rules November 2025-ல வந்துச்சு.

1. **உங்க policy-ஐ கண்டுபிடிங்க.** உங்க organisation அல்லது college-ஓட AI policy-ஐ கண்டுபிடிச்சு, இந்த வாரம் நீங்க பண்ண ஒரு task-க்கு இந்த lesson-ஓட ஆரம்பத்துல இருக்குற மூணு கேள்விகளுக்கு பதில் சொல்லுங்க. Policy இல்லைன்னா, உங்க manager-கிட்ட கேக்கப்போற அஞ்சு கேள்விகளை எழுதுங்க.
2. **பத்து documents-ஐ classify பண்ணுங்க.** நீங்க அடிக்கடி use பண்ற பத்து documents-ஐ list பண்ணி, ஒவ்வொண்ணையும் public, internal, confidential அல்லது personal-னு classify பண்ணுங்க. ஒவ்வொண்ணுக்கும் எந்த tools use பண்ணலாம்னு note பண்ணுங்க.
3. **உங்க hidden AI-ஐ audit பண்ணுங்க.** உங்க work laptop, phone-ல இருக்குற ஒவ்வொரு AI feature, browser extension, notetaker-ஐயும் list பண்ணி, ஒவ்வொண்ணையும் approved, unapproved அல்லது unknown-னு mark பண்ணுங்க.
4. **Clean பண்ணி செய்யுங்க.** ஒரு உண்மையான task-ஐ எடுத்து, Karthik பண்ண மாதிரி எல்லா personal, confidential details-ஐயும் எடுத்துட்டு, ஒரு approved tool-ல அதை செய்யுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** உங்க workplace-ல AI-க்கு எந்த tools, features, data allowed-னும், தவறா paste பண்ணதுக்கு அப்புறம் முதல் ஒரு மணி நேரத்துல என்ன பண்ணணும்னும் ஒரு colleague-கிட்ட explain பண்ண முடியும்.
