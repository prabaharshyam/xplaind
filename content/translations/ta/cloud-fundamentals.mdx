## இது என்ன

ஒரு public cloud, computers, storage, networks, ready-made services-ஐ உங்களுக்கு வாடகைக்கு தருது, use பண்றதுக்கு ஏத்த மாதிரி bill வரும். AWS, Microsoft Azure, Google Cloud கிட்டத்தட்ட ஒரே building blocks-ஐ வேற வேற பேர்கள்ல தருது. Enterprises பெரும்பாலும் group முழுக்க ஒரே choice-ஐ follow பண்ணுவாங்க; banks, insurers, pharma companies data எங்க இருக்கலாம்னு rules-உம் சேர்ப்பாங்க.

இந்த lesson Azure-ஐ ஆழமா பாக்குது, ஏன்னா course resources Microsoft Learn paths. ஒவ்வொரு step-க்கும் மத்த clouds-ல நெருக்கமான match இருக்கு, கீழ இருக்குற table-ல அதைக் காட்டியிருக்கோம்.

ஒரு AI deployment சுமார் ஏழு வகை service-ஐ use பண்ணும்:

- **Compute**: உங்க code எங்க run ஆகுது.
- **Storage**: files, documents.
- **Databases**: structured data, பெரும்பாலும் embeddings-க்கு pgvector extension-ஓட PostgreSQL.
- **Networking**: virtual networks, private endpoints, ஒரே ஒரு public entry point.
- **Identity and access**: யார், எது, எந்த actions-ஐ செய்யலாம்.
- **Managed models**: hosted model APIs; prompts எங்க process ஆகுதுன்னு இதுல deployment type தான் முடிவு பண்ணும்.
- **Monitoring**: logs, metrics, alerts, என்ன நடந்துச்சுன்னு நீங்க பாக்க முடியுற மாதிரி.

**Shared responsibility.** Buildings, hardware, managed services-ஐ provider secure பண்ணும். நீங்க configure பண்றது உங்க பொறுப்பு: உங்க data, அதை யார் access பண்ணலாம், எந்த endpoints public, நீங்க எவ்வளவு செலவு பண்றீங்க. "Cloud security basics" lesson இதை இன்னும் ஆழமா பாக்குது.

```flow
title: Central India-ல, ஒரே virtual network-குள்ள document assistant
Staff | Entra ID sign-in -> Application Gateway | ஒரே public entry, HTTPS
Application Gateway -> Container Apps | internal-only environment, managed identity
Container Apps -[private endpoint]-> Blob Storage
Container Apps -[private access]-> PostgreSQL with pgvector
Container Apps -[secret reference]-> Key Vault
Container Apps -[private endpoint]-> Foundry model | regional Standard deployment
Container Apps -> Log Analytics
```

இந்த lesson-ல Hyderabad-ல ஒரு pharma company-க்கு Azure-ல அவங்க document assistant-ஐ design பண்றதை follow பண்ணப் போறோம்.

## இது எப்படி work ஆகுது

### Regions, zones

Region-னா ஒரு பகுதியில இருக்குற data centres-ஓட ஒரு குழு. Azure-க்கு இந்தியாவுல நாலு இருக்கு: Central India (Pune), South India (Chennai), West India (Mumbai), India South Central (Hyderabad); கடைசியது August 2026-ல launch ஆச்சு. AWS-க்கு Mumbai, Hyderabad; Google Cloud-க்கு Mumbai, Delhi.

சில regions-ல availability zones இருக்கும்: தனி power, cooling-ஓட இருக்குற தனி data centres; அதனால zones முழுக்க பரப்பி வச்ச replicas, ஒண்ணு fail ஆனாலும் தாங்கும். எல்லா region-லயும் zones-ஓ எல்லா service-ஓ இருக்காது, அதனால நீங்க use பண்ணப் போற ஒவ்வொரு service-க்கும் Azure-ஓட products-by-region page-ஐ check பண்ணுங்க.

Region-ஐ இந்த வரிசையில தேர்ந்தெடுங்க:

1. **Residency**: client-ஓட policy, contracts, regulators என்ன கேக்குறாங்க.
2. **Availability**: உங்க எல்லா services-உம், சரியான deployment type-ஓட model-உம் அங்க கிடைக்குதா?
3. **Latency**: users-க்கு இருக்குற தூரம். ஒரு chat app-க்கு எல்லா Indian region-உம் போதுமான அளவு பக்கத்துல தான்.
4. **Price**: regions-க்கு இடையில prices கொஞ்சம் மாறும்; இது தான் கடைசி முக்கியத்துவம்.

காரணங்களை எழுதி வைங்க; client-ஓட cloud team கேப்பாங்க.

### Compute choices

| உங்களுக்கு வேண்டியது | தேர்ந்தெடுங்க | ஏன் |
| --- | --- | --- |
| ஒரு container-ல HTTP API (பெரும்பாலான AI apps) | Container Apps | Replicas, scaling, HTTPS, revisions எல்லாம் built-in |
| Events அல்லது timer trigger பண்ற குட்டி jobs | Container Apps jobs அல்லது Azure Functions | Job run ஆகுற நேரத்துக்கு மட்டும் pay பண்ணுவீங்க |
| Client-ஓட existing platform-ஓட பொருந்த | AKS (managed Kubernetes) | அவங்க platform team ஏற்கனவே run பண்ணா மட்டும் |
| GPUs அல்லது machine-ஓட முழு control | Virtual machines | Patch, scale எல்லாம் நீங்களே பண்ணணும் |

Container Apps, run ஆகுற replicas-ஓட CPU, memory-க்கு bill பண்ணும். `--min-replicas 0` idle-ஆ இருக்கும்போது zero-க்கு scale பண்ணும், ஆனா கொஞ்ச நேரம் அமைதியா இருந்ததுக்கு அப்புறம் வர்ற முதல் request ஒரு cold start-க்காக காத்திருக்கும். ஒரு staff tool-க்கு, ஒரு warm replica நியாயமான trade.

### Storage, databases

Documents-க்கு Blob Storage, records-க்கும் vectors-க்கும் Azure Database for PostgreSQL (flexible server) use பண்ணுங்க; backups, patching, failover எல்லாம் built-in. ரெண்டு details மக்களை மாட்டி விடும்:

- pgvector-ஐ create பண்றதுக்கு முன்னாடி allow-list பண்ணணும்: server parameter `azure.extensions`-ஐ `vector`-ஆ set பண்ணுங்க, அப்புறம் `CREATE EXTENSION vector;` run பண்ணுங்க. Extension-ஓட பேர் `vector`, `pgvector` இல்ல.
- Server-ஐ create பண்ணும்போதே **private access** (`--vnet`, `--subnet`) தேர்ந்தெடுங்க. இதை ஆரம்பத்துலயே முடிவு பண்ணுங்க: அப்புறம் மாத்தணும்னா downtime-ஓட ஒரு migration வேணும்.

### Networking, private endpoints

எல்லாமே ஒரு virtual network-குள்ள இருக்கும். Container Apps environment-க்கு தனி subnet கிடைக்கும், அது internal-only, அதனால app-க்கு public address இல்ல. ஒரே public entry ஒரு Application Gateway, இல்லன்னா client-ஓட existing gateway.

Blob Storage, Key Vault, Foundry-ஐ **private endpoints** வழியா reach பண்ணுவீங்க: உங்க network-குள்ள அந்த service-க்கு ஒரு private IP address. அப்புறம் ஒவ்வொரு service-ஓட public network access-ஐயும் off பண்ணுங்க. Classic failure: endpoint இருக்கு, ஆனா எந்த private DNS zone-உம் (உதாரணம், `privatelink.blob.core.windows.net`) network-ஓட link ஆகல. Name இன்னும் public address-க்கு தான் resolve ஆகும், அதை நீங்க இப்போ தான் மூடினீங்க, அதனால ஒவ்வொரு call-உம் fail ஆகும்.

### Identity

App-க்கு ஒரு **managed identity** கொடுங்க: Azure அதுக்கு short-lived tokens-ஐ கொடுக்கும், அதனால store பண்ணவோ leak ஆகவோ எந்த key-உம் இல்ல. வேலை செய்யுற மிகக் குறுகிய scope-ல அதுக்கு roles கொடுங்க:

- **Storage Blob Data Reader** ஒரு blob container-ல, முழு subscription-ல இல்ல.
- **Key Vault Secrets User** ஒரு vault-ல.
- **Cognitive Services OpenAI User** Foundry resource-ல.
- **AcrPull** container registry-ல.

ரெண்டு gotchas. Owner, Contributor மாதிரி management roles ஒரு resource-ஐ மாத்த விடும், ஆனா உங்க சொந்த token வச்சு அதோட data-வை படிக்க விடாது; அதுக்கு ஒரு data role வேணும். அதோட role assignments apply ஆக சில நிமிஷங்கள் ஆகலாம், அதனால grant பண்ணின உடனே வர்ற 403 தானா சரியாகலாம்.

மக்கள் company-ஓட Microsoft Entra ID வழியா தான் sign in ஆவாங்க, shared accounts-ல ஒருபோதும் இல்ல.

### Managed models, residency trap

Microsoft Foundry (November 2025-ல Azure AI Foundry-ல இருந்து rename ஆச்சு) client-ஓட Azure contract-குள்ள models-ஐ host பண்ணுது. Prompts எங்க process ஆகுதுன்னு resource-ஓட region இல்ல, **deployment type** தான் முடிவு பண்ணும்:

| Deployment type | Prompts எங்க process ஆகலாம் | எப்போ use பண்ணணும் |
| --- | --- | --- |
| Global (Standard அல்லது provisioned) | Model run ஆகுற எந்த Azure region-லயும் | Residency rule இல்ல; அதிகபட்ச quota வேணும் |
| Data Zone | Microsoft வரையறுத்த ஒரு zone-குள்ள: US, EU அல்லது Asia Pacific | ஒரு multi-country zone-ஐ rule அனுமதிக்குது |
| Standard அல்லது provisioned, regional | Deployment-ஓட சொந்த region | Data இந்தியாவுலயே process ஆகணும் |

Store பண்ண data எல்லா type-க்கும் resource-ஓட geography-லயே இருக்கும்; மாறுறது ஒவ்வொரு request-உம் எங்க process ஆகுதுங்கிறது தான். Central India resource-ல இருக்குற ஒரு Global deployment கூட ஒரு prompt-ஐ வெளிநாட்டுக்கு அனுப்பலாம். புது models பெரும்பாலும் ஆரம்பத்துல Global-ஆ மட்டும் தான் கிடைக்கும், அதனால residency-ஐ promise பண்றதுக்கு முன்னாடி region-availability table-ஐயும், portal-ல இருக்குற deployment dialog-ஐயும் check பண்ணுங்க. AWS-லயும் இதே switch இருக்கு: ஒரு India inference profile (`in.`-ல ஆரம்பிக்குற model IDs) Mumbai, Hyderabad-க்கு இடையில மட்டும் route பண்ணும், ஆனா ஒரு `global.` profile எங்க வேணும்னாலும் route பண்ணலாம்.

App தன்னோட managed identity வச்சு அதோட deployment-ஐ call பண்ணும், அதனால API key-யே இல்ல:

```python
from azure.identity import DefaultAzureCredential, get_bearer_token_provider
from openai import OpenAI

token = get_bearer_token_provider(DefaultAzureCredential(), "https://ai.azure.com/.default")
client = OpenAI(base_url="https://docassist-ai.openai.azure.com/openai/v1/", api_key=token)
reply = client.chat.completions.create(
    model="docassist-chat",  # your deployment's name, not a model ID
    messages=[{"role": "user", "content": "Summarise this stability report: ..."}])
```

### Quotas

Model throughput-ஐ ஒரு quota limit பண்ணும்: tokens per minute-ல, ஒவ்வொரு model, region, subscription-க்கும் தனியா. ஒரு புது subscription-ல GPU virtual machine quota பெரும்பாலும் zero-ல தான் ஆரம்பிக்கும். Increases உடனே கிடைக்காது, refuse-உம் ஆகலாம், அதனால quota-வை launch week-ல இல்ல, முதல் வாரத்துலயே request பண்ணுங்க.

### Command line-ல இருந்து deploy பண்ணுங்க

Diagram காட்டுறதை இந்த commands build பண்ணும்; `$` variables முந்தைய steps-ல இருந்து வர்ற IDs-ஐ வச்சிருக்கும்.

```bash
# 1. Create the identity first, so it can be granted access before the app exists.
az identity create -g rg-docassist -n id-docassist -l centralindia
ID=$(az identity show -g rg-docassist -n id-docassist --query id -o tsv)
PRINCIPAL=$(az identity show -g rg-docassist -n id-docassist --query principalId -o tsv)
CLIENT_ID=$(az identity show -g rg-docassist -n id-docassist --query clientId -o tsv)

# 2. Least privilege. Repeat for Key Vault Secrets User, AcrPull and Cognitive Services OpenAI User.
az role assignment create --assignee-object-id "$PRINCIPAL" --assignee-principal-type ServicePrincipal \
  --role "Storage Blob Data Reader" --scope "$STORAGE_ID/blobServices/default/containers/source-pdfs"

# 3. An internal-only environment on your own subnet, sending logs to Log Analytics.
az containerapp env create -g rg-docassist -n env-docassist -l centralindia \
  --infrastructure-subnet-resource-id "$APPS_SUBNET_ID" --internal-only true \
  --logs-destination log-analytics --logs-workspace-id "$WORKSPACE_GUID" --logs-workspace-key "$WORKSPACE_KEY"

# 4. The app: ingress reachable only inside the network, secrets by reference, a hard ceiling on replicas.
az containerapp create -g rg-docassist -n docassist-api --environment env-docassist \
  --image acrdocassist.azurecr.io/docassist-api:3f9c2e1 \
  --registry-server acrdocassist.azurecr.io --registry-identity "$ID" --user-assigned "$ID" \
  --secrets "db-url=keyvaultref:https://kv-docassist.vault.azure.net/secrets/db-url,identityref:$ID" \
  --env-vars DATABASE_URL=secretref:db-url AZURE_CLIENT_ID="$CLIENT_ID" \
  --ingress external --target-port 8000 --cpu 1 --memory 2Gi --min-replicas 1 --max-replicas 5
```

`AZURE_CLIENT_ID`, எந்த user-assigned identity-ஐ use பண்ணணும்னு `DefaultAzureCredential`-க்கு சொல்லும்; அது இல்லன்னா token requests fail ஆகலாம். Compute செலவுக்கு உண்மையான cap `--max-replicas` தான்.

### Logs, metrics, cost

Container Apps console logs-ஐ ஒரு Log Analytics workspace-க்கு அனுப்பும். Request times, errors-க்கு Application Insights சேருங்க, error rate-க்கும் slow responses-க்கும் alert வைங்க. Logs ingest ஆகுற ஒவ்வொரு gigabyte-க்கும் bill ஆகும், அதனால முழு prompts-ஐயோ documents-ஐயோ log பண்ணாதீங்க: அது காசு செலவு, sensitive data-வையும் copy பண்ணும்.

ஒரு AI app-ஓட bill-ல பொதுவா model tokens தான் முன்னாடி, அப்புறம் database, compute, logs, cloud-ஐ விட்டு வெளிய போற data. Bill-ஐ பிரிக்க முடியுற மாதிரி ஒவ்வொரு resource-க்கும் project, environment tag போடுங்க. முதல் நாளே alerts-ஓட ஒரு budget set பண்ணுங்க:

```bash
az consumption budget create-with-rg -g rg-docassist -n docassist-pilot \
  --amount 125000 --category Cost --time-grain Monthly --time-period start-date=2026-12-01 \
  --notifications "{at80:{enabled:true,operator:GreaterThan,threshold:80,contact-emails:[cloud-alerts@example.com]}}"
```

Start date ஒரு மாசத்தோட முதல் தேதியா இருக்கணும், மூணு மாசத்துக்கு மேல முன்னாடி இருக்கக்கூடாது. Amount subscription-ஓட billing currency-ல இருக்கும். ஒரு budget alert மட்டும் தான் பண்ணும்: அது எதையும் நிறுத்தாது, cost data சில மணி நேரம் தாமதமா வரலாம். Alerts-ஐ ஒரு shared mailbox அல்லது channel-க்கு அனுப்புங்க, ஒருத்தருக்கு இல்ல.

## ஒரு worked example

Azure-ல இருக்குற ஒரு Hyderabad pharma company, அவங்க regulatory team-க்கு ஒரு document assistant வேணும்னு கேக்குறாங்க. Requirements: data இந்தியாவுலயே store-உம் process-உம் ஆகணும், public database கூடாது, company accounts வச்சு sign-in, ஒரு நாளைக்கு சுமார் 1,500 கேள்விகளோட ஒரு pilot.

**1. Region.** Hyderabad-ல இருக்குற India South Central தான் பக்கத்துல, ஆனா அது August 2026-ல தான் திறந்துச்சு, Microsoft கொஞ்சம் கொஞ்சமா services சேர்த்துட்டு இருக்கு. Design-க்கு தேவையான எல்லாமே Central India-ல இருக்குன்னு products-by-region page காட்டுதுன்னு வச்சுக்கோங்க: நீங்க அதை தேர்ந்தெடுத்து, Hyderabad-ஐ பின்னாடிக்கு note பண்ணி வைக்கிறீங்க.

**2. Model.** Team-ஓட முதல் choice model இந்தியாவுல Global Standard-ஆ மட்டும் தான் கிடைக்குதுன்னு வச்சுக்கோங்க. அது processing rule-ஐ fail பண்ணுது. இன்னொரு model Central India-ல regional Standard-ஆ கிடைக்குது, team-ஓட 40 test questions-லயும் pass ஆகுதுன்னு வச்சுக்கோங்க: நீங்க அதை deploy பண்றீங்க. அதோட tokens-per-minute quota-வை அதே நாள்ல request பண்றீங்க.

**3. Network, identity.** Design diagram-ஐ follow பண்ணுது: company-ஓட Application Gateway-க்கு பின்னாடி ஒரு internal Container Apps environment; Blob Storage, Key Vault, Foundry எல்லாம் அவங்களோட DNS zones-ஓட private endpoints வழியா; PostgreSQL private access-ஓட. ஒரே ஒரு user-assigned identity, முன்னாடி சொன்ன நாலு roles-ஐயும் வச்சிருக்கு, ஒவ்வொண்ணும் மிகக் குறுகிய scope-ல.

**4. Cost.** Build பண்றதுக்கு முன்னாடி estimate பண்ணுங்க. கீழ இருக்குற ஒவ்வொரு price-உம் விளக்கத்துக்காக வச்சுக்கிட்ட ஒரு figure, quote இல்ல; நீங்க check பண்ற நாள்ல உங்க region-க்கு Azure pricing calculator காட்டுற number-ஐ வச்சு ஒவ்வொண்ணையும் மாத்துங்க. இதை இந்த page-லயே run பண்ணலாம்.

```python
# Illustrative prices only. Replace each with the Azure pricing calculator's figure.
replica_rupees_per_hour = 8           # suppose: one replica, 1 vCPU and 2 GiB
replica_hours = (2 * 12 + 1 * 12) * 30  # 2 replicas by day, 1 at night
fixed = {"PostgreSQL": 12_000, "Blob, Key Vault, private endpoints": 3_000,
         "Log Analytics": 4_000, "Data transfer out": 500}

questions = 1_500 * 30                 # per month
input_tokens, output_tokens = 4_000, 500  # per question, with retrieved chunks
rupees_per_m_in, rupees_per_m_out = 250, 1_000  # suppose

compute = replica_rupees_per_hour * replica_hours
infra = compute + sum(fixed.values())
tokens = questions * (input_tokens * rupees_per_m_in + output_tokens * rupees_per_m_out) / 1e6
print(f"compute ₹{compute:,}  infrastructure ₹{infra:,}  tokens ₹{tokens:,.0f}")
print(f"total ₹{infra + tokens:,.0f} a month, ₹{(infra + tokens) / questions:.2f} per question")
```

இது infrastructure ₹28,140, tokens ₹67,500-னு print பண்ணும்: மாசத்துக்கு ₹95,640, அதாவது ஒரு கேள்விக்கு ₹2.13. மொத்த infrastructure-ஐ விட tokens-க்கு தான் அதிக செலவு, அதனால முதல்ல அதை optimise பண்ணுங்க.

| வரி (விளக்கத்துக்கு) | மாசத்துக்கு | அதை எது தீர்மானிக்குது | எப்படி குறைக்கலாம் |
| --- | --- | --- | --- |
| Model tokens | ₹67,500 | கேள்விகள் × ஒரு கேள்விக்கான tokens | குறைவான, சின்ன retrieved chunks; repeat ஆகுற answers-ஐ cache பண்ணுங்க |
| PostgreSQL | ₹12,000 | Server size, storage | சின்னதா ஆரம்பிங்க; அளந்த load படி resize பண்ணுங்க |
| Container Apps | ₹8,640 | Replica-hours | இரவுல ஒரு replica; dev-க்கு zero-க்கு scale பண்ணுங்க |
| Log Analytics | ₹4,000 | Ingest ஆகுற logs-ஓட gigabytes | Prompts இல்ல, metadata-வை log பண்ணுங்க |
| Blob, Key Vault, endpoints | ₹3,000 | Store பண்ண data, மணி நேரத்துக்கு endpoints | பழைய versions-ஐ archive பண்ணுங்க |
| Data transfer out | ₹500 | Azure-ஐ விட்டு வெளிய போற data | Traffic-ஐ region-குள்ளயே வச்சுக்கோங்க |

Client-க்கு rupees-ல bill ஆகுது, அதனால budget மாசத்துக்கு 1,25,000; அப்போ அதோட 80% alert, ₹95,640 estimate-க்கு கொஞ்சம் மேல வரும். `--max-replicas 5`-உம், ஒரு user-க்கு மணி நேரத்துக்கு 60 கேள்விகள்ங்கிற limit-உம், budget email வர்றதுக்கு ரொம்ப முன்னாடியே கட்டுப்பாடு இல்லாம ஓடுற ஒரு loop-ஐ cap பண்ணிடும்.

**5. Review.** Cloud teams பொதுவா வெளி designs-ஐ public endpoints, stored keys, வெளிநாட்டு regions, தெளிவில்லாத model processing-க்காக reject பண்ணுவாங்க. இந்த design நாலையும் தவிர்க்குது, அவங்க ஏற்கனவே run பண்ற services-ஐ use பண்ணுது, diagram-ஓடயும் region, deployment type பத்தின ஒரு page note-ஓடயும் வருது. அவங்க பண்ற ஒரே மாற்றம் அவங்க naming convention தான்.

## பொதுவா பண்ற தப்புகள்

- **மூணு clouds-ஐ மேலோட்டமா கத்துக்கிறது.** ஒண்ணை ஒழுங்கா கத்துக்கோங்க, அப்புறம் translate பண்ணுங்க.
- **Model residency-க்கு resource-ஓட region-ஐ நம்புறது.** Global, Data Zone deployments prompts-ஐ இந்தியாவுக்கு வெளிய process பண்ணலாம். Deployment type-ஐ check பண்ணுங்க.
- **Public databases, storage.** Private access, private endpoints use பண்ணுங்க, public network access-ஐ off பண்ணுங்க.
- **Private DNS zone இல்லாத private endpoint.** Name மூடின public address-க்கு resolve ஆகும், ஒவ்வொரு call-உம் fail ஆகும்.
- **Code அல்லது settings-ல keys.** Portal-ல இருந்து copy பண்ண storage account keys-உம் இதுல அடங்கும். Managed identities, Key Vault references use பண்ணுங்க, shared-key access-ஐ off பண்ணுங்க.
- **Data role-க்கு பதிலா Owner அல்லது Contributor**, இல்லன்னா "வேலை செய்யட்டும்"னு subscription scope-ல roles கொடுக்கிறது.
- **Budget-ஐ ஒரு cap-ஆ நினைக்கிறது.** அது alert மட்டும் தான் பண்ணும். `--max-replicas`-உம் rate limits-உம் set பண்ணுங்க.
- **Compute-ஐ கணக்கு பண்ணி, tokens-ஐயும் logs-ஐயும் விடுறது**; AI apps-ல பெரும்பாலும் அவை தான் பெரிய வரிகள்.
- **Launch week-ல quota request பண்றது.** Increases உடனே கிடைக்காது.
- **Tag பண்ணாத resources**, அதனால எந்த project-க்கு எவ்வளவு cost-னு யாராலயும் சொல்ல முடியாது.

## குறைவான cloud போதும்ங்கிறது எப்போ

- **ஒரு prototype அல்லது demo**: Vercel, Render, Railway மாதிரி ஒரு platform-உம் ஒரு hosted database-உம் வேகமானது. உண்மையான data வரும்போது move பண்ணுங்க.
- **Client எல்லாத்தையும் on-premises-ல run பண்றாங்க**: அதுக்கு பதிலா அவங்க platform-ஐ கத்துக்கோங்க.
- **Sensitive data இல்லாத ஒரு சின்ன internal tool**: built-in sign-in-ஓட ஒரு Container App போதுமா இருக்கலாம்; முழு private network overkill.

## Demo-ல இருந்து production-க்கு

- **எல்லாமே code-ஆ.** Repository-ல Bicep அல்லது Terraform, pull requests-ல review ஆகணும்; production-ல manual portal changes கூடாது.
- **தனித்தனி environments.** Dev, prod-க்கு வேற வேற resource groups அல்லது subscriptions, ஒவ்வொண்ணுக்கும் தனி budget.
- **Policy மூலமா guardrails.** Indian regions-ஐ மட்டும் அனுமதிக்குற ஒரு Azure Policy, யாராவது தப்பு பண்ணாலும் residency-ஐ enforce பண்ணும்; இன்னொரு policy public network access-ஐ deny பண்ணலாம்.
- **Resilience.** Region-ல zone redundancy இருந்தா use பண்ணுங்க, ஒரு database restore-ஐ test பண்ணுங்க, client-க்கு தேவைன்னா disaster recovery-க்கு ரெண்டாவது Indian region-ஐ தேர்ந்தெடுங்க.
- **மக்கள் act பண்ற alerts.** Error rate, slow responses, ஒரு நாளைக்கு token use, quota use; ஒரு named owner இருக்குற shared channel-க்கு அனுப்புங்க.
- **ஒரு design record.** Region, deployment type, network boundaries, identities, ஒவ்வொண்ணுக்குமான காரணத்தோட, client-ஓட review-க்கு ready-ஆ.
