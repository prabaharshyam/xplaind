## இது என்ன

**Recursion**-னா, ஒரு function ஒரு problem-ஐ solve பண்ண, அதோட சின்ன version-ல தன்னையே call பண்றது. நேரடியா பதில் சொல்ற அளவுக்கு சின்னதான **base case**-ஐ அடையுற வரைக்கும் இது தொடரும். ஒரு folder-ல இருக்குற files-ஐ எண்ணுறது இயல்பாவே recursive: இங்க இருக்குற files-ஐ எண்ணுங்க, அப்புறம் ஒவ்வொரு sub-folder-கிட்டயும் அதே கேள்வியை கேளுங்க.

**Dynamic programming** (DP)-னா, ஒரு recursion திரும்ப திரும்ப அதே சின்ன problems-ஐ solve பண்ணிட்டே இருக்கும்போது நீங்க பண்றது. அவற்றை திரும்ப compute பண்ணாம, ஒவ்வொண்ணையும் ஒரு தடவை solve பண்ணி, அந்த answer-ஐ திரும்ப use பண்றீங்க. Results-ஐ cache பண்ணியோ (**memoization**), மிகச்சின்ன case-ல இருந்து மேல நோக்கி ஒரு table-ஐ நிரப்பியோ (**tabulation**) இதை பண்ணலாம்.

```flow
title: Plain recursion-ல fib(5): அதே calls repeat ஆகுது (15 calls; fib(35)-க்கு கிட்டத்தட்ட 2.7 crore)
fib(5) -> fib(4)
fib(5) -> fib(3), மறுபடி compute ஆகுது
fib(4) -> fib(3)
fib(4) -> fib(2)
fib(3) -> fib(2), மறுபடியும்
fib(3) -> fib(1)
```

```flow
dir: LR
title: Memoization-ஓட: ஒவ்வொரு value-உம் ஒரு தடவை, அப்புறம் lookups
fib(0) -> fib(1) -> fib(2) -> fib(3) -> fib(4) -> fib(5)
```

## இது எப்படி work ஆகுது

ஒரு problem-க்கு DP பொருந்தணும்னா அதுக்கு ரெண்டு properties இருக்கணும். **Optimal substructure**: சிறந்த answer, சின்ன problems-ஓட சிறந்த answers-ல இருந்து உருவாகுது. **Overlapping subproblems**: அதே சின்ன problems பல தடவை வருது.

நம்பகமான method-ல ஐந்து steps இருக்கு:

1. **State-ஐ define பண்ணுங்க**: ஒரு subproblem-ஐ அடையாளம் காட்டுற ஒரு value, அல்லது சின்ன values தொகுப்பு என்ன? Coin change-ல, அது இன்னும் உருவாக்க வேண்டிய amount.
2. **Recurrence-ஐ எழுதுங்க**: ஒரு state-ஓட answer, சின்ன states-ல இருந்து எப்படி வருது.
3. **Base cases-ஐ set பண்ணுங்க**: நேரடியா பதில் சொல்லக்கூடிய states. உதாரணம்: amount 0-க்கு 0 coins போதும்.
4. **Order-ஐ தேர்ந்தெடுங்க**: memoization-ஓட top-down, அல்லது table-ஓட bottom-up.
5. **Answer-ஐ எடுங்க**, cost-ஐ check பண்ணுங்க: states எண்ணிக்கை × ஒரு state-க்கு ஆகுற வேலை.

**Top-down memoization**, இயல்பான recursive code-ஐ வச்சுக்கிட்டு ஒரு cache-ஐ சேர்க்கும். Python-ல `@functools.lru_cache(maxsize=None)` இதை ஒரே line-ல பண்ணிடும். **Bottom-up tabulation**, recursion-ஐ, base case-ல இருந்து மேல நோக்கி ஒரு array-ஐ நிரப்புற loop-ஆ மாத்தும். இது recursion-depth limits-ஐ தவிர்க்கும், பெரும்பாலும் கொஞ்சம் வேகமாவும் இருக்கும்.

| Approach | எப்படி தெரியும் | எதுக்கு நல்லது | எதை கவனிக்கணும் |
|---|---|---|---|
| Plain recursion | function தன்னையே call பண்ணும் | சின்ன inputs, தெளிவு | subproblems repeat ஆனா exponential time |
| Memoization (top-down) | recursion + cache | recurrence-ல இருந்து சீக்கிரம் எழுதலாம் | recursion depth; cache memory |
| Tabulation (bottom-up) | table-ஐ நிரப்புற loop | பெரிய inputs, கணிக்கக்கூடிய வேகம் | fill order-ஐ கண்டுபிடிக்கணும் |
| Greedy | இப்போ சிறந்த option-ஐ எடுக்கிறது | greedy choice நிரூபிக்கப்பட்ட problems | local best, global best இல்லன்னா தப்பான answers |

**Interviews-ல DP-ஐ கண்டுபிடிக்கிறது.** ஒரு sequence அல்லது grid மேல "number of ways", "minimum cost", "maximum value", "longest", "can you reach" மாதிரி வார்த்தைகள் வந்தா, அது பெரும்பாலும் DP-ஓட அறிகுறி. முதல்ல plain recursive version-ஐ எழுதி, அதோட cost-ஐ சத்தமா சொல்லுங்க; அப்புறம் repeat ஆகுற subproblems-ஐ காட்டி, ஒரு cache-ஐ சேருங்க. மனப்பாடம் பண்ண table-ஐ விட, மெதுவானதுல இருந்து வேகமானதுக்கு போற அந்த வழியை interviewers அதிகம் மதிப்பாங்க.

## ஒரு worked example

Arjun, Lucknow-ல ஒரு payments kiosk-க்கு cash-dispensing feature build பண்றார். ஒரு amount கொடுத்தா, kiosk அதை 1, 2, 5, 10, 20, 50, 100, 200, 500 coins, notes-ல குறைஞ்ச எண்ணிக்கையில கொடுக்கணும்.

இந்திய denominations-க்கு, பொருந்துற மிகப்பெரிய note-ஐ எப்பவும் எடுக்கிறது தற்செயலா work ஆகும். ஆனா அந்த product 1, 3, 4 tokens use பண்ற ஒரு canteen-லயும் run ஆகும். 6-க்கு, greedy 4 + 1 + 1 (மூணு tokens) எடுக்கும், ஆனா 3 + 3 ரெண்டு தான். அதனால Arjun DP use பண்றார்.

**State:** இன்னும் கொடுக்க வேண்டிய amount `a`. **Recurrence:** best(a) = 1 + பொருந்துற ஒவ்வொரு coin c-க்கும் best(a − c)-ல சின்னது. **Base case:** best(0) = 0.

அவரோட முதல் version plain recursion:

```python
def fewest(a, coins):
    if a == 0:
        return 0
    return 1 + min(fewest(a - c, coins) for c in coins if c <= a)
```

இந்திய coins-ஓட ₹30-க்கு இது சரி; ₹300-க்கு கிட்டத்தட்ட முடியவே முடியாது. ஏன்னா அதே amounts-ஐ எண்ணிக்கையில்லாம திரும்ப solve பண்ணுது.

ஒரு cache-ஐ சேர்த்தா fix ஆகிடும்:

```python
from functools import lru_cache

def fewest_coins(amount, coins):
    @lru_cache(maxsize=None)
    def best(a):
        if a == 0:
            return 0
        return 1 + min(best(a - c) for c in coins if c <= a)
    return best(amount)
```

இப்போ 0-ல இருந்து target வரைக்கும் ஒவ்வொரு amount-உம் ஒரு தடவை solve ஆகும்: கிட்டத்தட்ட amount × coins எண்ணிக்கை steps.

Kiosk-க்கு அவர் bottom-up version-ஐ use பண்றார், இது பெரிய amounts-ல recursion limits-ஐ தவிர்க்கும்:

```python
def fewest_coins_table(amount, coins):
    INF = float("inf")
    best = [0] + [INF] * amount
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a and best[a - c] + 1 < best[a]:
                best[a] = best[a - c] + 1
    return best[amount]
```

ஒன்பது denominations-ஓட ₹3,000-க்கு அது 27,000 simple steps, எந்த phone-லயும் உடனே முடியும். 1, 3, 4 tokens-ஓட, amount 6-க்கு அது சரியா 2-ஐ தருது.

## பொதுவா பண்ற தப்புகள்

**Base case இல்லாம, அல்லது தப்பான base case.** Recursion நிக்காது, இல்லன்னா அர்த்தமில்லாததை திருப்பி தரும். Base case-ஐ முதல்ல எழுதுங்க.

**ரொம்ப பெரிய state-ஐ தேர்ந்தெடுக்கிறது.** Answer-ஐ பாதிக்காத values-ஐ சேர்த்தா states எண்ணிக்கை பெருகிடும். எதிர்காலம் எதை சார்ந்திருக்கோ அதை மட்டும் வச்சுக்கோங்க.

**Mutable arguments-ல cache பண்றது.** `lru_cache`-க்கு hashable arguments வேணும். Lists-க்கு பதிலா tuples-ஐ pass பண்ணுங்க, அல்லது மேல பார்த்த மாதிரி list-ஐ cache ஆகுற function-க்கு வெளியே வச்சிருங்க.

**Recursion limit-ஐ தொடுறது.** Python கிட்டத்தட்ட 1,000 nested calls-ல நின்னுடும். பெரிய inputs-க்கு bottom-up-க்கு மாறுங்க, அல்லது limit-ஐ கவனமா உயர்த்துங்க.

**நிரூபிக்காம greedy-ஐ நம்புறது.** Greedy வேகமானது, பெரும்பாலும் சரி, ஆனா அந்த problem-க்கு அது work ஆகுதுன்னு நீங்க காட்டணும். 1, 3, 4 tokens example அது எப்படி fail ஆகும்னு காட்டுது.

**நேரா code-க்கு குதிக்கிறது.** பெரும்பாலான DP bugs, தெளிவில்லாத state அல்லது recurrence-ல இருந்து வரும். Code எழுதுறதுக்கு முன்னாடி ரெண்டையும் ஒரு sentence-ல எழுதுங்க.
