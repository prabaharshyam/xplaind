## இது என்ன

உங்க AI application உங்க laptop-ல வேலை செய்யுது. அப்புறம் அது ஒரு server-க்கு போகுது; ஒரு சாயங்காலம் client போன் பண்றாங்க: "Assistant பதில் சொல்றதை நிறுத்திடுச்சு." உங்க AI system ஓடுற கிட்டத்தட்ட எல்லா server-உம் **Linux**; அதை நீங்க ஒரு text **shell** வழியா, பெரும்பாலும் Bash, **SSH** மூலமா அடைவீங்க. Desktop இல்லை, mouse இல்லை, File Explorer இல்லை.

நீங்க Linux expert ஆகணும்னு இல்லை. சின்ன, நம்பகமான skills தொகுப்பு போதும்:

| Skill | Commands |
| --- | --- |
| சுத்தி வர, files-ஐ படிக்க | `pwd`, `ls -la`, `cd`, `cat`, `less`, `head`, `tail`, `grep` |
| என்ன ஓடுது, அது எதை use பண்ணுதுன்னு பார்க்க | `ps aux`, `top` அல்லது `htop`, `df -h`, `du -sh`, `free -h` |
| Logs வரும்போதே படிக்க | `tail -f`, `journalctl -u name -f`, `docker logs -f` |
| Settings, scripts | `export`, `env`, `chmod +x`, `set -euo pipefail` |
| பாதுகாப்பா connect பண்ண | `ssh-keygen`, `ssh`, `~/.ssh/config`, `ssh -J` |

```flow
dir: LR
உங்க laptop | private key இங்கேயே இருக்கும் -[SSH key]-> Bastion, jump host | உங்க public key-ஐ check பண்ணும்
Bastion, jump host -[SSH]-> App server | ai-assistant service, logs, disk, memory
```

இந்த lesson Pune-ல ஒரு logistics client-க்கான ஒரு உண்மையான outage வழியா உங்களை கூட்டிட்டு போகும்: connect பண்றதுல இருந்து, காரணத்தை கண்டுபிடிச்சு, fix பண்ணி, எழுதி வைக்குற வரை. Lesson முடியும்போது, நிரம்பின disk-ஐ diagnose பண்ணவும், SSH keys-ஓட நம்பிக்கையா connect பண்ணவும் முடியும்.

## இது எப்படி work ஆகுது

### Navigation, files

`pwd` நீங்க எங்க இருக்கீங்கன்னு காட்டும். `ls -la` hidden files உட்பட files-ஐ list பண்ணும். `cd` நகரும். `cat` ஒரு சின்ன file-ஐ print பண்ணும்; `less` நீளமான file-ஐ scroll பண்ண விடும்; `head`, `tail` ஆரம்பம், முடிவை காட்டும்.

`grep -i "timeout" app.log` case-ஐ பார்க்காம பொருந்துற lines-ஐ கண்டுபிடிக்கும்; `grep -c` அவற்றை எண்ணும்.

**Pipes** (`|`) சின்ன tools-ஐ சக்தி வாய்ந்ததா இணைக்கும்:

```bash
grep ERROR app.log | sort | uniq -c | sort -rn | head
```

இது error lines-ஐ கண்டுபிடிச்சு, ஒரே மாதிரி இருக்குறவற்றை group பண்ணி, ஒவ்வொண்ணையும் எண்ணி, count வச்சு sort பண்ணி, மேல இருக்குற பத்தை காட்டும்: ஒரே line-ல அதிகம் வர்ற errors.

### Processes, resources

| கேள்வி | Command |
| --- | --- |
| என் service ஓடுதா? | `ps aux \| grep uvicorn` அல்லது `systemctl status ai-assistant` |
| இப்போ CPU, memory-ஐ எது use பண்ணுது? | `top` அல்லது `htop` |
| Disks எவ்வளவு நிரம்பியிருக்கு? | `df -h` |
| எந்த folders பெருசு? | `du -sh *` அல்லது `sudo du -sh /var/* \| sort -h` |
| எவ்வளவு memory காலியா இருக்கு? | `free -h` |

நிரம்பின disk, புரியாத outages-ஓட பொதுவான காரணம்: logs, temporary files, model downloads சத்தமில்லாம அதை நிரப்பி, service-ஆல எதுவும் எழுத முடியாம போயிடும்.

### Logs

- `tail -f app.log` ஒரு log file வளரும்போதே follow பண்ணும்.
- **systemd** ஓட்டுற services journal-ல log பண்ணும்: `journalctl -u ai-assistant --since "1 hour ago"`.
- Containers: `docker logs -f container-name`.

### Environment variables

Programs `DATABASE_URL`, API keys மாதிரி settings-ஐ **environment**-ல இருந்து படிக்கும். `export NAME=value` உங்க session-க்கு ஒண்ணை set பண்ணும்; `env` அவற்றை list பண்ணும். Secrets-ஐ environment-லயோ secret manager-லயோ வைங்க; code-லயோ shell history-லயோ ஒருபோதும் வைக்காதீங்க.

### Scripts

Shell script-னா commands இருக்குற ஒரு file. ஒவ்வொரு script-ஐயும் இதோட ஆரம்பிங்க:

```bash
#!/usr/bin/env bash
set -euo pipefail
```

`set -euo pipefail` script-ஐ முதல் fail ஆன command-லயும், set பண்ணாத எந்த variable-லயும், pipe-ல fail ஆன எந்த step-லயும் நிக்க வைக்கும்; பாதி முடிஞ்ச வேலையோட தொடராது. `chmod +x script.sh` வச்சு executable ஆக்குங்க.

### SSH, keys

1. `ssh-keygen -t ed25519` உங்க machine-ல ஒரு key pair உருவாக்கும்.
2. Server-க்கு உங்க **public** key-ஐ கொடுக்குறீங்க. **Private** key உங்க machine-ஐ விட்டு போகவே போகாது.
3. `ssh deploy@10.0.4.12` password இல்லாம உங்களை login பண்ணும்.

`~/.ssh/config`-ல ஒரு entry servers-க்கு சின்ன பேர்களை தரும். நிறைய companies SSH-ஐ ஒரு **jump host** அல்லது **bastion** வழியா route பண்ணும்: `ssh -J bastion app-server` அதன் வழியா தாவி போகும்.

### Permissions

ஒவ்வொரு file-க்கும் owner, group, மத்தவங்களுக்கு permissions இருக்கு: read, write, execute. ஒரு private key-க்கு `chmod 600` வேணும், இல்லன்னா SSH அதை use பண்ண மறுக்கும். `sudo`-வை தேவைப்படுற தனித்தனி commands-க்கு மட்டும் use பண்ணுங்க; `rm -rf`-க்கு அப்புறம் Enter அழுத்துறதுக்கு முன்னாடி ரெண்டு தடவை யோசிங்க.

## ஒரு example

Pune-ல ஒரு logistics client, அவங்க delivery-query assistant 19:05-க்கு பதில் சொல்றதை நிறுத்திடுச்சுன்னு சொல்றாங்க. அவங்க bastion வழியா connect பண்றீங்க:

```bash
ssh -J bastion.client.in deploy@assistant-01
systemctl status ai-assistant        # active, but restarting every 30 seconds
journalctl -u ai-assistant --since "19:00" | tail -50
```

Log `OSError: [Errno 28] No space left on device`-ஐ காட்டுது. Disk-ஐ check பண்றீங்க:

```bash
df -h /                                # 100% used
sudo du -sh /var/* | sort -h | tail -3
```

`/var/log/ai-assistant`-ல 38 GB இருக்கு. ரெண்டு வாரத்துக்கு முன்னாடி ஒரு test-க்கு அப்புறம் debug logging-ஐ on-லயே விட்டுட்டாங்க, logs ஒருபோதும் rotate ஆகல.

| நேரம் | Step | கண்டுபிடிச்சது |
| --- | --- | --- |
| 19:08 | `systemctl status` | Service ஒவ்வொரு 30 seconds-க்கும் restart ஆகுது |
| 19:09 | `journalctl` | "No space left on device" |
| 19:10 | `df -h` | Disk 100% நிரம்பிடுச்சு |
| 19:11 | `du -sh` | 38 GB debug logs |
| 19:15 | பழைய logs-ஐ compress பண்ணி நீக்குங்க, level-ஐ INFO-க்கு set பண்ணுங்க, logrotate rule சேர்ங்க, restart பண்ணுங்க | Disk 34% |
| 19:20 | ஒரு query-ஐ test பண்ணுங்க | Assistant திரும்ப பதில் சொல்லுது |

உங்க incident note-ல காரணம், fix, ரெண்டு follow-ups எழுதுறீங்க: 80%-ல ஒரு disk-space alert, production-ல log level DEBUG இல்லைன்னு CI-ல ஒரு check.

## பொதுவா பண்ற தப்புகள்

- **பழக்கமா root-ஆ வேலை செய்றது.** தப்புகள் பேரழிவா மாறும். சாதாரண user-ஐயும், தனித்தனி commands-க்கு `sudo`-வையும் use பண்ணுங்க.
- **Secrets-ஐ command line-ல paste பண்றது.** அவை shell history-ல போய் உட்காரும். Restricted permissions உள்ள environment files அல்லது client-ஓட secret manager-ஐ use பண்ணுங்க.
- **Production-ஐ கையால edit பண்ணி யார்கிட்டயும் சொல்லாம இருக்குறது.** அடுத்த deploy உங்க fix-ஐ overwrite பண்ணும். Change-ஐ code அல்லது config-ல வைங்க, எழுதி வைங்க.
- **`set -euo pipefail` இல்லாத scripts.** ஒரு step fail ஆனது யாருக்கும் தெரியாது, அப்புறம் வர்ற steps data-வை சேதப்படுத்தும்.
- **Private keys-ஐ share பண்றது.** ஒவ்வொரு ஆளுக்கும் ஒவ்வொரு machine-க்கும் தனி key; அப்போ access-ஐ clean-ஆ நீக்கலாம்.
- **இடம் காலி பண்ண புரியாத files-ஐ delete பண்றது.** முதல்ல எது பெருசு, ஏன்னு கண்டுபிடிங்க.

1. **Top errors.** ஏதாவது ஒரு Linux machine-ல, அதாவது free cloud VM, Windows-ல WSL அல்லது Docker container-ல, சில ERROR lines இருக்குற 500-வரி fake log-ஐ உருவாக்கி, ஒரே pipeline-ல top மூணு error messages-ஐ list பண்ணுங்க.
2. **Keys.** ஒரு SSH key உருவாக்கி, ஒரு server-லயோ GitHub-லயோ சேர்த்து, password இல்லாம connect பண்ணுங்க.
3. **ஒரு script.** `set -euo pipefail`-ஓட disk usage-ஐ check பண்ணி, 80%-க்கு மேல இருந்தா ஒரு warning print பண்ற script எழுதுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** எந்த process அல்லது folder ஒரு disk-ஐ நிரப்புதுன்னு கண்டுபிடிக்க முடியும், private key உங்க machine-ஐ விட்டு ஏன் போகவே போகாதுன்னு explain பண்ண முடியும்.
