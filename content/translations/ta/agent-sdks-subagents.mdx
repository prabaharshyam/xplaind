## இது என்ன

**Agent SDK**-ங்கறது பெரும்பாலும் ஒரு model provider-ஓட library; அது உங்களுக்கு தயாரான agent loop-ஐ கொடுக்கும்: messages அனுப்பு, model கேக்குற tools-ஐ ஓட்டு, results-ஐ திரும்ப கொடு, repeat பண்ணு. பெரும்பாலானவை tracing, guardrails, session storage, ஒரு agent இன்னொரு agent-க்கு வேலையை hand பண்ற வழிகளையும் சேர்க்கும். OpenAI-ஓட Agents SDK, Anthropic-ஓட Claude Agent SDK உதாரணங்கள்; Google-உம் மத்தவங்களும் இதே மாதிரி kits கொடுக்குறாங்க.

**Sub-agent**-ங்கறது, ஒரு task-ஓட ஒரு பகுதியை தன்னோட புது context-ல செய்ய இன்னொரு agent தொடங்கி வைக்குற agent; அது ஒரு summary-ஐ மட்டும் திருப்பி கொடுக்கும். **Multi-agent system**-ங்கறது பல agents ஒத்துழைக்கிற எந்த design-உம்: ஒரு lead agent workers-க்கு delegate பண்றது, agents ஒரு conversation-ஐ தங்களுக்குள்ள hand பண்றது, அல்லது specialists ஒருத்தருக்கொருத்தர் வேலையை review பண்றது.

```flow
Lead agent | 5 research areas-ஐ plan பண்ணுது -> Financials | filings tool
Lead agent -> Legal | court search
Lead agent -> Management | news search
Lead agent -> Market | reports tool
Lead agent -> ESG | news search
Financials -[sources-ஓட, அதிகபட்சம் 400 words summary]-> Lead merge பண்ணி, conflicts-ஐ கண்டுபிடிச்சு, ஒரு follow-up கேக்குது
Legal -> Lead merge பண்ணி, conflicts-ஐ கண்டுபிடிச்சு, ஒரு follow-up கேக்குது
Management -> Lead merge பண்ணி, conflicts-ஐ கண்டுபிடிச்சு, ஒரு follow-up கேக்குது
Market -> Lead merge பண்ணி, conflicts-ஐ கண்டுபிடிச்சு, ஒரு follow-up கேக்குது
ESG -> Lead merge பண்ணி, conflicts-ஐ கண்டுபிடிச்சு, ஒரு follow-up கேக்குது
Lead merge பண்ணி, conflicts-ஐ கண்டுபிடிச்சு, ஒரு follow-up கேக்குது -> Brief
```

ஒவ்வொரு sub-agent-உம் தன்னோட புது context-ஓட parallel-ஆ ஓடும்.

இந்த lesson-ல, Hyderabad-ல ஒரு consulting firm நடுத்தர அளவு manufacturers பத்தின due-diligence briefs தயாரிக்கிறதை follow பண்றோம்.

## இது எப்படி work ஆகுது

**SDKs உங்களுக்கு என்ன சேமிக்குது.** Loop-ஏ இருபது வரி தான்; மதிப்பு அதை சுத்தி இருக்குற எல்லாத்துலயும் இருக்கு: retries, streaming, parallel tool calls, ஒவ்வொரு step-யையும் tracing, input, output-ல guardrails, hand-offs, sessions. சில SDKs file editing, shell commands, web search மாதிரி built-in tools-ஐயும், ஒரு permission system-ஓட கொடுக்கும்.

**தேர்ந்தெடுக்கிறது.** மூணு பொதுவான வழிகள்:

- *உங்க சொந்த loop*: task குறுகியதா இருக்கும்போது, முழு control-உம் குறைந்த dependencies-உம் வேணும்னா.
- *ஒரு vendor SDK*: client அந்த vendor-க்கு commit ஆகி, ஒரு pilot-ஐ வேகமா வேணும்னா, குறிப்பா அதோட built-in tools பொருந்தினா.
- *ஒரு graph framework* (LangGraph மாதிரி): தெளிவான control flow, approval-க்கு நிலையான pauses, model-vendor independence தேவைப்படும்போது.

SDK ஒரு vendor-ஓட models-ஓட எவ்வளவு lock ஆகியிருக்கு, sessions-ஐ எப்படி store பண்ணுது, அதோட traces client-ஓட observability tools-க்கு export ஆகுதான்னு check பண்ணுங்க.

**Sub-agents.** அவற்றோட உண்மையான பலன் context isolation. ஒரு market-ஐ research பண்ற lead agent அஞ்சு sub-agents-ஐ தொடங்கலாம்; ஒவ்வொண்ணும் ஒரு competitor-ஐ தன்னோட முழு context window-ஓட தேடும், lead-க்கு அஞ்சு ஒரு-பக்க summaries கிடைக்கும். படிச்ச நூற்றுக்கணக்கான pages-ஐ lead பார்க்கவே பார்க்காது, அதனால அதோட context சுத்தமா இருக்கும். Sub-agents parallel-ஆவும் ஓடலாம், அது wall-clock time-ஐ குறைக்கும்.

**Cost.** ஒவ்வொரு sub-agent-க்கும் சொந்த prompt, tools, history இருக்கு, அதனால token use பல மடங்கு கூடும், பெரும்பாலும் ஒரு single agent-ஓட பல மடங்கு. Coordination-ம் fail ஆகலாம்: ரெண்டு workers ஒரே வேலையை செய்யலாம், அல்லது ஒரு summary ஒரு முக்கிய detail-ஐ விட்டுடலாம். Research மாதிரி பரந்த, parallel, அதிகமா படிக்கிற tasks-ல multi-agent designs பலன் தரும்; ஒரு codebase-ஐ edit பண்றது அல்லது ஒரு form-ஐ நிரப்புறது மாதிரி, ஒவ்வொரு step-உம் முந்தினதை சார்ந்து இருக்குற இறுக்கமா இணைஞ்ச tasks-க்கு அவை அபூர்வமா தான் உதவும்.

**மூணு வழிகள் ஒப்பீடு:**

| Route | எப்போ best | எதை கவனிக்கணும் |
| --- | --- | --- |
| உங்க சொந்த loop | குறுகிய task, முழு control, குறைந்த dependencies | Tracing, retries, sessions-ஐ நீங்களே build பண்ணணும் |
| Vendor SDK | ஒரு vendor-க்கு commit ஆனப்போ, வேகமான pilot, built-in tools பொருந்துறப்போ | Lock-in; trace export-ஐ check பண்ணுங்க |
| Graph framework | தெளிவான control flow, நிலையான approval pauses, vendor independence | கத்துக்க நிறைய concepts |

**ஒரு delegation brief எழுதுறது.** ஒவ்வொரு sub-agent-ஓட instructions-ம் அதோட area-வையும் எல்லைகளையும் சொல்லணும் ("2020-ல இருந்து இந்திய courts-ல legal cases; regulatory filings இல்லை, அதை வேற agent பார்த்துக்கும்"), அதுக்கு இருக்குற tools, headings-ஓட output format, ஒரு word limit, ஒவ்வொரு claim-க்கும் ஒரு source link சேர்க்கணும்ங்குற rule. கடைசியில ஒரு சின்ன "open questions" list கேளுங்க, அப்போ எது நிச்சயமில்லன்னு lead-க்கு தெரியும். தெளிவான briefs ரெண்டு பொதுவான failures-ஐ தடுக்கும்: overlap ஆகுற வேலை, முக்கியமான ஒரு detail-ஐ விட்டுடுற summaries.

**பிரிச்சது பலன் தந்துச்சான்னு measure பண்றது.** அதே பத்து requests-ஐ ரெண்டு வழியிலயும் ஓட்டுங்க. Wall-clock time, மொத்த tokens, cost, ஒரு reviewer fixed rubric-ஓட கொடுத்த quality score-ஐ record பண்ணுங்க. வேகமான, சிறந்த, ஆனா நாலு மடங்கு cost உள்ள ஒரு split கூட, இங்க மாதிரி, ஒவ்வொரு brief-உம் நாள் கணக்கான analyst time-ஐ மாத்துறப்போ, சரியா இருக்கலாம். அந்த முடிவை numbers-ஓட எழுத்துல வைங்க.

**சாதாரண code-ல ஒரு lead-உம் sub-agents-உம்.** Pattern-ஐ பார்க்க framework தேவையில்ல. Lead briefs எழுதும், sub-agents தங்களோட புது context-ஓட parallel-ஆ ஓடும், lead அவற்றோட சின்ன reports-ஐ மட்டும் பார்க்கும்:

```python
import asyncio
import anthropic

client = anthropic.AsyncAnthropic()
LEAD, WORKER = "claude-opus-5-5", "claude-sonnet-5-5"     # check the docs for current names

async def sub_agent(brief, max_tokens=1200):
    try:
        r = await asyncio.wait_for(client.messages.create(
            model=WORKER, max_tokens=max_tokens,
            system="You research one narrow area. Report in at most 200 words with a source link per claim, "
                   "then list open questions.",
            messages=[{"role": "user", "content": brief}]), timeout=120)
        return "".join(b.text for b in r.content if b.type == "text")
    except Exception as err:
        return f"FAILED: {type(err).__name__}"

async def research(question, areas):
    briefs = [f"Question: {question}\nYour area: {a}. Stay inside it; other agents cover the rest."
              for a in areas]
    reports = await asyncio.gather(*(sub_agent(b) for b in briefs))
    joined = "\n\n".join(f"## {a}\n{r}" for a, r in zip(areas, reports))
    final = await client.messages.create(
        model=LEAD, max_tokens=1500,
        messages=[{"role": "user", "content": f"Write a brief answering: {question}\n"
                   "Use only these reports. Say plainly if any area FAILED.\n\n" + joined}])
    return "".join(b.text for b in final.content if b.type == "text")

# asyncio.run(research("EV subsidy policies", ["Maharashtra", "Karnataka", "Tamil Nadu"]))
```

ஒரு உண்மையான system-ல ஒவ்வொரு sub-agent-உம் ஒரு single call-க்கு பதிலா (search, fetch, read) தன்னோட சொந்த tool loop-ஐ ஓட்டும், ஆனா shape அதே தான்: briefs வெளிய போகும், சின்ன reports திரும்ப வரும், lead-ஓட context சின்னதாவே இருக்கும்.

**Token bill.** ஒவ்வொரு sub-agent-உம் தன்னோட instructions, tool definitions, படிக்குறதை சுமக்கும். Anthropic-ஓட multi-agent research system ஒரு சாதாரண chat-ஐ விட சுமார் 15 மடங்கு tokens use பண்ணுச்சுன்னு அவங்க report பண்ணாங்க. ஒரு analyst-ஓட ரெண்டு நாளை மிச்சப்படுத்துற research brief-க்கு அது worth ஆகலாம்; ஒரு support reply-க்கு அபூர்வமா தான் worth.

**ஒரு SDK-ஐ தேர்ந்தெடுக்கிறது, உறுதியா.** Vendor SDKs (OpenAI-ஓட Agents SDK, Anthropic-ஓட Claude Agent SDK, Google-ஓட Agent Development Kit, மத்தவை) முக்கியமா நாலு இடங்கள்ல வேறுபடுது. Commit பண்றதுக்கு முன்னாடி ஒவ்வொண்ணையும் ஒரு நாள் spike-ல check பண்ணுங்க:

| கேள்வி | ஏன் முக்கியம் |
| --- | --- |
| மத்த vendors-ஓட models-ஐ use பண்ண முடியுமா? | பின்னாடி rewrite இல்லாம மாறலாம் |
| Sessions, state எங்க இருக்கு? | Data residency, restarts |
| Traces OpenTelemetry அல்லது உங்க tracing tool-க்கு export ஆகுதா? | Systems முழுக்க ஒரே view |
| Built-in tools-க்கு permissions, approvals எப்படி set பண்றாங்க? | Production-ல பாதுகாப்பு |

**Context isolation ரெண்டு பக்கமும் வெட்டும்.** ஒரு sub-agent தன்னோட brief-ஐ மட்டும் தான் பார்க்கும், அதனால lead அதை pass பண்ணாத வரைக்கும் இன்னொரு sub-agent கண்டுபிடிச்சதை அது use பண்ண முடியாது. ஒரு area-ல வேலை இன்னொண்ணை சார்ந்து இருந்தா, அந்த steps-ஐ வரிசையா ஓட்டுங்க, அல்லது follow-up briefs அனுப்ப lead-க்கு ரெண்டாவது round கொடுங்க.

**Browser-லயே try பண்ணுங்க.** Sub-agents parallel-ஆ ஓடுறதால, மொத்த time மெதுவானதோட time, கூட்டுத்தொகை இல்லை. Delays-ஐ மாத்தி பாருங்க.

```python
import asyncio, time

async def sub_agent(area, seconds):
    await asyncio.sleep(seconds)              # pretend research
    return f"{area}: 3 findings"

async def lead():
    t0 = time.perf_counter()
    reports = await asyncio.gather(sub_agent("Maharashtra", 0.3), sub_agent("Karnataka", 0.5), sub_agent("Tamil Nadu", 0.2))
    print(reports)
    print(f"took {time.perf_counter() - t0:.1f} s, not {0.3 + 0.5 + 0.2:.1f} s")

await lead()
```

## ஒரு example

Hyderabad-ல ஒரு consulting firm, நடுத்தர அளவு இந்திய manufacturers பத்தின due-diligence briefs வேணும்னு நினைக்குது: financials, legal cases, management, market, ESG news.

ஒரு single agent 40 நிமிஷம் எடுத்துச்சு, legal research-ஓட பாதியிலயே context தீர்ந்து, முன்னாடி எடுத்த financial notes-ஐ இழந்துடுச்சு. நீங்க redesign பண்றீங்க:

- ஒரு **lead agent** request-ஐ படிச்சு, அஞ்சு research areas-ஓட ஒரு plan எழுதி, ஒவ்வொரு area-க்கும் ஒரு **sub-agent**-ஐ parallel-ஆ தொடங்குது.
- ஒவ்வொரு sub-agent-க்கும் அதுக்கு தேவையான tools மட்டும்: legal-க்கு ஒரு court-records search, financial-க்கு ஒரு filings tool. ஒவ்வொண்ணும் source links-ஓட அதிகபட்சம் 400 words summary-ஐ திருப்பி கொடுக்கும்.
- Lead summaries-ஐ merge பண்ணி, conflicts-ஐ கண்டுபிடிச்சு (revenue பத்தி ரெண்டு sources ஒத்துப்போகல), financial sub-agent-கிட்ட ஒரு follow-up கேள்வி கேக்குது.

Wall-clock time 9 நிமிஷத்துக்கு குறையுது, coverage-ம் மேம்படுது. Token use 3.5 மடங்கு கூடுது; ஒவ்வொரு brief-உம் ரெண்டு நாள் analyst வேலையை மாத்துறதால firm அதை ஏத்துக்குது. Firm-க்கு அந்த provider-ஓட ஏற்கனவே ஒரு enterprise contract இருக்கு, அவங்க tracing ஒவ்வொரு sub-agent-ஓட steps-ஐயும் காட்டுது, அது அவங்க quality team-க்கு தேவை, அதனால நீங்க vendor-ஓட SDK-ஐ use பண்றீங்க.

| Measure | Single agent | Lead + அஞ்சு sub-agents |
| --- | --- | --- |
| ஒரு brief-க்கு time | சுமார் 40 நிமிஷம் | சுமார் 9 நிமிஷம் |
| Context overflow | Legal research-ல அடிக்கடி | இல்லை |
| Token use | Baseline | சுமார் 3.5 மடங்கு |
| அஞ்சு areas-ஓட coverage | சீரில்லாம | முழுமையா |

## பொதுவா பண்ற தப்புகள்

- **Default-ஆ multi-agent.** ஒரு agent-ல தொடங்குங்க. Context overflow அல்லது parallelism தான் அளந்த problem-ஆ இருந்தா மட்டும் பிரிங்க.
- **தெளிவில்லாத delegation.** "Legal side-ஐ research பண்ணு"ன்னு சொன்னா overlap வரும். ஒவ்வொரு sub-agent-க்கும் துல்லியமான scope, output format, length limit கொடுங்க.
- **Token cost-ஐ புறக்கணிக்கிறது.** ஒரு task-க்கு cost-ஐ முன்னாடியும் பின்னாடியும் அளக்கணும்; multi-agent அதை பல மடங்கா ஆக்கலாம்.
- **கவனிக்காம lock-in ஆகுறது.** Client model vendors-ஐ மாத்தலாம்னா, உங்க code-ல எவ்வளவு ஒரு SDK-ஐ சார்ந்து இருக்குன்னு check பண்ணுங்க.
- **Agents முழுக்க traces இல்லாம இருக்கிறது.** ஒரு பதில் தப்பா இருந்தா, எந்த sub-agent எந்த claim-ஐ உருவாக்குச்சுன்னு நீங்க பார்க்கணும்.
- **ஒவ்வொரு sub-agent-க்கும் limits இல்லாம இருக்கிறது.** ஒரே ஒரு stuck worker முழு budget-ஐயும் சாப்பிடும்.
- **ஒரு பகுதி fail ஆனா முழு task-ஐயும் fail ஆக்குறது.** Gap-ஐ report பண்ணி, மிச்சத்தை deliver பண்ணுங்க.

## எப்போ ஒரு agent better

- **இறுக்கமா இணைஞ்ச வேலை**, ஒரு codebase-ஐ edit பண்றது அல்லது ஒரு form-ஐ நிரப்புறது மாதிரி, ஒவ்வொரு step-உம் முந்தினதை சார்ந்து இருக்கும்போது.
- **குறுகிய tasks**, ஒரு agent சில steps-ல முடிக்கக்கூடியவை.
- **இறுக்கமான budgets**: பல agents token cost-ஐ பெருக்கும்.
- **கடுமையான latency தேவைகள்**, parallel பண்ண எதுவும் இல்லாதப்போ.

## Demo-ல இருந்து production-க்கு

- **Lead-ஐயும் ஒவ்வொரு sub-agent-ஐயும்** ஒரே run id-ல trace பண்ணுங்க.
- **ஒவ்வொரு agent-க்கும் முழு task-க்கும் budgets** set பண்ணுங்க: tokens, time, பணம்.
- **Briefs-ஐ versioned templates-ஆ வச்சிருங்க**, prompts மாதிரி test பண்ணுங்க.
- **Changes-க்கு முன்னாடியும் பின்னாடியும் cost, quality-ல single-agent baseline-ஓட** compare பண்ணுங்க.
- **Partial failure-க்கு plan பண்ணுங்க**: ஒரு area-வை cover பண்ண முடியாதப்போ தெளிவான user messages.

## Practice பண்ணுங்க

Anthropic-ஓட multi-agent research system பத்தின write-up-ஐ படிங்க, ஒரு agent SDK-ஓட docs-ஐ ஓட்டி பாருங்க.

1. ஒரு research task-ஓட single-agent version-ஐ build பண்ணுங்க (உதாரணமா, "EV subsidies பத்தி மூணு இந்திய மாநிலங்களோட policies-ஐ summarise பண்ணு"), ஒரு vendor SDK அல்லது உங்க சொந்த loop-ஓட.
2. அதை ஒரு lead agent-ஓடயும், ஒவ்வொரு மாநிலத்துக்கும் ஒரு sub-agent-ஓடயும் திரும்ப build பண்ணுங்க; ஒவ்வொண்ணும் sources-ஓட அதிகபட்சம் 200 words-ஐ திருப்பி கொடுக்கும்.
3. Time, tokens, quality-ஐ compare பண்ணி, பிரிச்சது worth ஆச்சான்னு மூணு வாக்கியங்கள்ல எழுதுங்க.

இன்னும் ஆழமா படிக்க, Chip Huyen-ஓட *AI Engineering* (O'Reilly, 2025) புத்தகத்தோட chapter 6, agents, பல components-ஓட planning, கூடுதல் model calls-ஓட cost-ஐ பேசுது.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** sub-agents எப்போ உதவும், அவற்றுக்கு என்ன cost, அடிப்படை loop-ஐ தாண்டி ஒரு SDK என்ன கொடுக்குதுன்னு explain பண்ண முடியும்.
