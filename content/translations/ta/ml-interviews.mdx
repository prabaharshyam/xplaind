## இது என்ன

வழக்கமான ML engineer loops-ல இருப்பவை:

- **ML fundamentals**: bias, variance, overfitting, regularisation, metrics, cross-validation, குறிப்பிட்ட models எப்படி வேலை செய்யுது (trees, logistic regression, neural networks, transformers).
- **Coding**: Python, pandas-ல data manipulation, ஒரு சாதாரண algorithm-ஐ implement பண்றது, சில நேரம் standard data-structure problems.
- **ML system design**: "UPI payments-க்கு ஒரு fraud detection system-ஐ design பண்ணுங்க", "ஒரு grocery app-க்கு recommendations-ஐ design பண்ணுங்க".
- **Case அல்லது project deep-dive**: நீங்க build பண்ண ஒரு project-ஐ walk through பண்றது, தேர்வுகள், results பத்தின follow-up கேள்விகளோட.
- **Behavioural**: ownership, collaboration, தோல்வியை சமாளிக்கிறது.

```flow

1 Goal, metric -> 2 Framing, label -> 3 Data -> 4 Features | கிட்டத்தட்ட 15 நிமிஷம்
4 Features -> 5 Baseline, அப்புறம் ஒரு model -> 6 Evaluation | offline, A/B, கிட்டத்தட்ட 12 நிமிஷம்
6 Evaluation -> 7 Serving | batch அல்லது real time, ஒரு fallback-ஓட -> 8 Monitoring | கிட்டத்தட்ட 8 நிமிஷம்
8 Monitoring -> 9 Risks | fairness, abuse, failure; கிட்டத்தட்ட 5 நிமிஷம்
```

எண்களை சத்தமா சொல்லுங்க: latency budget, label delay, class balance, alert capacity.

இந்திய payments companies-ல ரொம்ப பொதுவா கேக்குற "UPI merchant transactions-க்கு fraud detection design பண்ணுங்க"-ங்குற கேள்விக்கான ஒரு model பதிலை இந்த lesson follow பண்ணும்.

## இது எப்படி work ஆகுது

**Fundamentals.** இதையெல்லாம் எளிய வார்த்தைகள்லயும் ஒரு உதாரணத்தோடயும் விளக்க முடியணும்:

- bias-variance trade-off, learning curves-ல இருந்து underfitting-ஐயும் overfitting-ஐயும் எப்படி diagnose பண்றது;
- imbalanced data-ல accuracy ஏன் தோத்துப் போகுது, அதுக்கு பதிலா என்ன use பண்றது;
- gradient boosting-உம் random forests-உம் எப்படி வேறுபடுது;
- leakage-னா என்ன, அதை எப்படி கண்டுபிடிப்பீங்க;
- attention எப்படி வேலை செய்யுது, உயர் மட்டத்துல.

**ML system design-க்கு ஒரு structure.**

1. *Goal-ஐயும்* business metric-ஐயும் தெளிவுபடுத்துங்க; constraints (latency, scale, regulation).
2. *ML problem-ஐ frame பண்ணுங்க*: எதை predict பண்றது, யாருக்கு, எப்போ; label-உம் அது எப்படி கிடைக்குதுங்குறதும்.
3. *Data*: sources, labels, volume, freshness, biases, privacy.
4. *Features*: முக்கிய groups, prediction நேரத்தின் நிலவரப்படி compute பண்ணினவை.
5. *Model*: முதல்ல ஒரு சாதாரண baseline, அப்புறம் காரணங்களோட ஒரு வலுவான model.
6. *Evaluation*: offline metrics, உண்மைக்கு பொருந்துற splits, segments; online A/B test, guardrails.
7. *Serving*: batch அல்லது real-time, latency budget, fallback.
8. *Monitoring, iteration*: drift, feedback loops, retraining.
9. *Risks*: fairness, abuse, failure modes.

**Project deep-dives.** ஒண்ணு ரெண்டு projects-ஐ ஆழமா தயார் பண்ணுங்க: problem, data, baseline, என்ன try பண்ணீங்க, எண்களோட results, என்ன தப்பாச்சு, அடுத்து என்ன பண்ணுவீங்க. "ஏன் X இல்ல?" கேள்விகளை எதிர்பாருங்க.

**Coding.** Pandas groupbys, joins, window-style calculations-ஐ practice பண்ணுங்க, time அடிப்படையில ஒரு train-validation split எழுதுங்க, சாதாரண metrics அல்லது k-means-ஐ scratch-ல இருந்து implement பண்ணுங்க.

**Behavioural.** எந்த engineering role-க்கும் மாதிரி, எண்களோட STAR stories.

**அதிகம் வர்ற fundamentals:**

| Topic | என்ன சொல்ல முடியணும் |
| --- | --- |
| Bias, variance | Learning curves underfitting-ஐயும் overfitting-ஐயும் எப்படி காட்டுது, ஒவ்வொண்ணுக்கும் என்ன சரி பண்ணும் |
| Imbalanced data | Accuracy ஏன் ஏமாத்துது; PR AUC, ஒரு threshold-ல precision, recall |
| Trees | Random forests-உம் gradient boosting-உம் எப்படி வேறுபடுது |
| Leakage | அது என்ன, ரொம்ப நல்ல score-ஐ எப்படி கண்டுபிடிக்கிறது, splits, features-ஐ எப்படி சரி பண்றது |
| Attention | Queries, keys, values, உயர் மட்டத்துல |

**சத்தமா practice பண்றது.** System design ஒரு பேசுற skill. 40 நிமிஷம் timer வைங்க, பார்த்திராத ஒரு கேள்வியை எடுங்க, ஒரு சாதாரண diagram வரைஞ்சுக்கிட்டே ஒன்பது steps-ஐயும் பேசிக்கிட்டே போங்க. உங்களையே record பண்ணி, அப்புறம் கேட்டு இடைவெளிகளை பாருங்க: label-ஐ define பண்ணீங்களா, ஒரு latency budget சொன்னீங்களா, ஒரு baseline-ஐ பேர் சொன்னீங்களா, time-க்கு பொருந்துற ஒரு split-ஐ தேர்ந்தெடுத்தீங்களா, எப்படி monitor பண்ணுவீங்கன்னு சொன்னீங்களா? இதை வாரத்துக்கு ஒரு தடவை ஒரு நண்பரோட செய்ங்க, role-ஐ மாத்திக்கோங்க, ஏன்னா interviewer-ஆ இருக்குறது ஒரு தெளிவான பதில் எப்படி கேக்கும்னு காட்டும்.

**"ஏன் X இல்ல?"-ஐ handle பண்றது.** Interviewers தேர்வுகள் மேல அழுத்துவாங்க. Trade-off-ஓட பதில் சொல்லுங்க: "ஒரு deep model உதவலாம், ஆனா tabular features-உம் label delays-உம் இருக்குறதால, gradient boosting கிட்டத்தட்ட அதே accuracy-ஐ தருது, நிமிஷங்கள்ல train ஆகுது, risk team-க்கு விளக்கவும் எளிது. Error analysis trees தவறவிடுற patterns-ஐ காட்டுச்சுன்னா, baseline-க்கு அப்புறம் அதை try பண்ணுவேன்."

## ஒரு worked example

கேள்வி: "ஒரு payments company-க்கு fraudulent UPI merchant transactions-ஐ கண்டுபிடிக்க ஒரு system-ஐ design பண்ணுங்க."

ஒரு வலுவான outline:

1. *Goal*: குறைந்த analyst capacity-ஓட fraud இழப்புகளை குறைக்கிறது; blocking-க்கு 100 ms-க்குள்ள real-time decision, கூடவே ஒரு review queue.
2. *Framing*: ஒவ்வொரு transaction-க்கும் binary classification; labels chargebacks-ல இருந்தும் உறுதி செய்யப்பட்ட investigations-ல இருந்தும், 30-ல இருந்து 60 நாள் கழிச்சு வரும்.
3. *Data*: transactions, merchant profiles, device, network signals, கடந்த fraud; கடுமையான imbalance (fraud ஒரு சதவீதத்தோட சின்ன பகுதி; நீங்க assume பண்ற rate-ஐ சொல்லுங்க).
4. *Features*: velocity (ஒரு merchant-க்கு ஒரு மணி நேரத்துல transactions), merchant-ஓட வரலாற்றுக்கு ஒப்பிட்ட amount, புது device, நாளின் நேரம், merchant category; எல்லாமே ஒரு feature store-ல இருந்து transaction நேரத்தின் நிலவரப்படி compute பண்ணினது.
5. *Model*: rules baseline; class weights-ஓட gradient-boosted trees; அப்புறம், merchants-ஐயும் devices-ஐயும் இணைக்குற graph features.
6. *Evaluation*: time-based split; PR AUC; analysts handle பண்ணக்கூடிய alert volume-ல recall; merchant category, region-வாரியா; traffic-ஓட ஒரு பங்கு மேல A/B test.
7. *Serving*: rules-க்கு fallback-ஓட real-time scoring; ரெண்டு thresholds (ரொம்ப உயர்ந்த precision-ல auto-block, அதுக்கு கீழ review queue).
8. *Monitoring*: முக்கிய features மேல drift, alert-rate மாற்றங்கள், blocked transactions-ல இருந்து feedback loop (random holdout), மாதாந்திர retraining.
9. *Risks*: உண்மையான சின்ன merchants-ஐ block பண்றது (appeal வழி), எதிரிகள் தகவமைக்குறது (அடிக்கடி retraining), regions முழுக்க fairness.

| Step | Fraud பதில்ல முக்கிய புள்ளி |
| --- | --- |
| Goal | Block பண்ண 100 ms-க்குள்ள, கூடவே analysts அளவுக்கு ஏத்த review queue |
| Label | Chargebacks, investigations, 30-ல இருந்து 60 நாள் தாமதம் |
| Model | Rules baseline, அப்புறம் class weights-ஓட boosted trees |
| Evaluation | Time split; analysts handle பண்ணக்கூடிய alert volume-ல recall |
| Monitoring | Drift, alert rates, blocked transactions-க்கு random holdout |

## பொதுவா பண்ற தப்புகள்

- **நேரா deep learning-க்கு குதிக்கிறது.** ஒரு baseline-ஓட ஆரம்பிச்சு, complexity-ஐ justify பண்ணுங்க.
- **Label-ஐ புறக்கணிக்கிறது.** Labels எங்கிருந்து வருது, எவ்வளவு தாமதமா வருதுங்குறது எல்லாத்தையும் தீர்மானிக்கும்.
- **Time-based problems-க்கு random splits.**
- **Serving, monitoring plan இல்லாம இருக்குறது.** Interviewers production சிந்தனையை எதிர்பார்க்குறாங்க.
- **மேலோட்டமான project கதைகள்.** உங்க எண்களையும் தப்புகளையும் தெரிஞ்சு வச்சிருங்க.

## Practice பண்ணுங்க

Chip Huyen-ஓட machine learning systems design notes-ஐயும் அவங்களோட ML interviews புத்தகத்தையும் படிங்க; behavioural rounds-க்கு Tech Interview Handbook-ஐ use பண்ணுங்க.

1. பத்து fundamentals கேள்விகளுக்கு, ஒவ்வொண்ணுக்கும் ஒரு இந்திய உதாரணத்தோட, ஒரு பத்தி எளிய மொழி பதில்களை எழுதுங்க.
2. ஒன்பது-step structure-ஓட, ரெண்டு ML system design கேள்விகளுக்கு, ஒவ்வொண்ணுக்கும் 40 நிமிஷத்துல சத்தமா பதில் சொல்லுங்க (உதாரணமா, ஒரு grocery chain-க்கு demand forecasting, ஒரு jobs app-க்கு ranking).
3. உங்க projects-ல ஒண்ணை deep-dive-க்கு தயார் பண்ணுங்க: எண்கள், முடிவுகள், தப்புகள், அடுத்த steps.

**இதுக்கு அப்புறம் உங்களால முடியணும்:** பார்த்திராத ஒரு ML system-ஐ 40 நிமிஷத்துல தெளிவான framing, evaluation, serving, monitoring-ஓட design பண்ணவும்.
