## இது எப்படி work ஆகுது

### DSA round

இந்த round பெரும்பாலும் software engineers-க்கு இருக்குற மாதிரியே தான். Role ML-ங்குறதால easy problems வரும்னு எதிர்பார்க்காதீங்க; இந்த round மட்டுமே ஒரு loop-ஐ கவிழ்க்கலாம்னு தெரிஞ்சுக்கோங்க. Big-tech ML roles-க்கு போன சில candidates medium, சில நேரம் hard problems வந்ததா சொல்றாங்க.

**என்ன test பண்றாங்க.** மனப்பாடம் பண்ண answers இல்ல, இந்த patterns-ஐ கத்துக்கோங்க.

- Hash maps, two pointers, sliding windows-ஓட arrays, strings.
- Sorting, binary search, intervals (merge, overlap).
- Stacks, queues, heaps (top k, running median).
- Trees, graphs: BFS, DFS, shortest paths, topological sort.
- Basic level-ல dynamic programming (ஒண்ணு, ரெண்டு dimensions).

**சத்தமா பேசிக்கிட்டே solve பண்ணுங்க.** Interviewers code-ஐ மட்டும் இல்ல, process-ஐயும் score பண்ணுவாங்க.

1. Problem-ஐ உங்க வார்த்தைகள்ல திரும்ப சொல்லுங்க, inputs, sizes, edge cases பத்தி கேளுங்க.
2. ஒரு சின்ன example-ஐ கையால work பண்ணுங்க.
3. ஒரு brute-force solution-ஐயும் அதோட cost-ஐயும் சொல்லுங்க.
4. அதை improve பண்ணுங்க, புது idea ஏன் work ஆகுதுன்னு சொல்லுங்க.
5. தெளிவான names-ஓட code பண்ணுங்க.
6. உங்க example-லயும் ஒரு edge case-லயும் test பண்ணுங்க, அப்புறம் time, space complexity சொல்லுங்க.

ML interviewers ஒரு DSA problem-ஐ data மொழியில போட்டு கேக்கலாம். உதாரணமா: "Time order-ல `(merchant_id, timestamp)` pairs-ஆ UPI payments குடுத்திருக்கு, எந்த 60-second window-லயாவது `k`-ஐ விட அதிக payments இருக்குற merchants-ஐ flag பண்ணுங்க." இது hash map-ஓட ஒரு sliding window:

```python
from collections import defaultdict, deque

def flag_bursts(events, k, window_s):
    """events: (merchant_id, unix_seconds) sorted by time.
    Return merchants with more than k payments inside any window_s seconds."""
    recent = defaultdict(deque)          # merchant -> timestamps still in the window
    flagged = set()
    for merchant, t in events:
        q = recent[merchant]
        q.append(t)
        while q[0] <= t - window_s:      # drop payments older than the window
            q.popleft()
        if len(q) > k:
            flagged.add(merchant)
    return flagged

events = [("m1", 0), ("m2", 5), ("m1", 10), ("m1", 20), ("m1", 70), ("m2", 80)]
print(flag_bursts(events, k=2, window_s=60))   # {'m1'}
```

ஒவ்வொரு timestamp-உம் அதோட queue-க்குள்ள அதிகபட்சம் ஒரு தடவை வரும், ஒரு தடவை போகும், அதனால n events-க்கு time O(n). அப்புறம் follow-up risk-ஐ சொல்லுங்க: இதுவரை வந்த ஒவ்வொரு merchant-க்கும் memory வளரும், ஏன்னா idle merchants-ஓட queues-ஐ யாரும் remove பண்றதில்ல.

**தயாரிப்பு.** `collections`, `heapq`, `bisect` வெச்சு Python-ல practice பண்ணுங்க. ஒவ்வொரு pattern-க்கும் சில problems solve பண்ணுங்க, fail ஆனதை ஒரு வாரம் கழிச்சு திரும்ப பண்ணுங்க, அதுவும் முழுக்க பேசிக்கிட்டே timed mocks-ல. சத்தமா யோசிக்குறது, அமைதியா solve பண்றதை விட வேற skill, test பண்றதும் அதைத் தான்.

### ML coding round

இங்க puzzles இல்ல, data code எழுதுவீங்க: ஒரு pandas groupby, join அல்லது rolling window; time வெச்சு ஒரு split; scratch-ல இருந்து ஒரு metric; NumPy-ல k-means அல்லது logistic regression. இந்த example ரெண்டு favourites-ஐ சேர்க்குது: label delay-ஐ மதிக்குற ஒரு time split, k-ல precision, recall.

```python
import numpy as np
import pandas as pd

def split_with_gap(df, test_start, test_end, delay_days, labels_pulled_on):
    delay = pd.Timedelta(days=delay_days)
    test_start, test_end = pd.Timestamp(test_start), pd.Timestamp(test_end)
    # Test labels must have matured too, or late fraud looks like "not fraud".
    assert test_end + delay <= pd.Timestamp(labels_pulled_on), "test labels not mature"
    train = df[df["txn_time"] < test_start - delay]   # what you could know on test_start
    test = df[(df["txn_time"] >= test_start) & (df["txn_time"] < test_end)]
    return train, test

def precision_recall_at_k(y_true, scores, k):
    y_true = np.asarray(y_true)
    top_k = np.argsort(-np.asarray(scores))[:k]     # the k highest scores
    caught = y_true[top_k].sum()
    return caught / k, caught / y_true.sum()

df = pd.DataFrame({"txn_time": pd.date_range("2026-01-01", "2026-06-30", freq="D")})
train, test = split_with_gap(df, "2026-05-01", "2026-06-01", 60, "2026-08-01")
print(train["txn_time"].max().date(), len(train), len(test))   # 2026-03-01 60 31

y = [1, 0, 0, 1, 0, 0, 0, 1, 0, 0]
s = [0.9, 0.8, 0.1, 0.7, 0.3, 0.2, 0.6, 0.4, 0.05, 0.15]
p, r = precision_recall_at_k(y, s, 3)
print(round(p, 2), round(r, 2))   # 0.67 0.67
```

Gap ஏன்? Fraud labels வர 60 நாள் வரை ஆகுதுன்னு வெச்சுக்கோங்க. 1 May அன்னைக்கு deploy ஆன ஒரு model, final labels இருக்குற transactions-ல மட்டும் தான் train ஆகியிருக்க முடியும், அதாவது சுமார் 2 March-க்கு முன்னாடி இருந்தவை. லேட்டா எடுத்த labels-ஓட March, April rows-ல train பண்ணா, அப்போ உங்களுக்கு தெரிஞ்சிருக்க முடியாத knowledge-ஐ use பண்றீங்க, அதனால test score ரொம்ப optimistic-ஆ வரும். ஒரு real retraining job-ல, delay-ஐ விட புதுசான rows unlabelled, negatives இல்ல. கேக்காமலேயே இதை சொன்னா அது ஒரு strong signal.

### ML fundamentals: mechanism, trade-off, default-ஓட பதில் சொல்லுங்க

ஒரு strong பதில் mechanism, trade-off, உங்க default choice மூணையும் சொல்லும். ரெண்டு model answers:

**"Random forests-க்கும் gradient boosting-க்கும் என்ன வித்தியாசம்?"** "ரெண்டுமே நிறைய decision trees-ஐ சேர்க்குது. ஒரு random forest ஆழமான trees-ஐ தனித்தனியா train பண்ணுது, ஒவ்வொண்ணும் ஒரு bootstrap sample-ல, ஒவ்வொரு split-லயும் features-ஓட ஒரு random subset-ல இருந்து தேர்ந்தெடுத்து, அப்புறம் எல்லாத்தையும் average பண்ணுது. அது முக்கியமா variance-ஐ குறைக்குது, அதனால கொஞ்சம் தான் tuning வேணும், மோசமா overfit ஆகுறது அரிது. Gradient boosting ஆழமில்லாத trees-ஐ ஒண்ணுக்கு அப்புறம் ஒண்ணா train பண்ணுது, ஒவ்வொண்ணும் இதுவரை இருக்குற trees-ஓட errors-ஐ fit பண்ணுது. அது bias-ஐ குறைக்குது, tabular data-ல பெரும்பாலும் அது தான் ஜெயிக்கும், ஆனா overfit ஆகலாம், அதனால learning rate, depth-ஐ tune பண்ணி early stopping use பண்ணுவேன். Tabular data-க்கு என் default boosting, உதாரணமா LightGBM அல்லது XGBoost, ஒரு quick baseline-ஆ random forest."

**"Data leakage-ஐ எப்படி கண்டுபிடிப்பீங்க?"** "Leakage-னா prediction time-ல model-க்கு கிடைக்காத information-ஐ அது பாக்குது. என் முதல் signal, problem-க்கு ரொம்ப அதிகமா நல்லா இருக்குற ஒரு score. அப்புறம் மூணு இடங்களை check பண்ணுவேன். Features: ஒரு top feature outcome-க்கு அப்புறம் record ஆகுதா, churn model-ல `refund_issued` மாதிரி? Split: ஒரே customer அல்லது கிட்டத்தட்ட duplicate rows train-லயும் test-லயும் இருக்கா, அல்லது training data test data-க்கு அப்புறம் வருதா? Preprocessing: scaling அல்லது target encoding எல்லா data-லயும் fit ஆச்சா? Fix: ஒவ்வொரு feature-ஐயும் prediction time அன்னைக்கு இருந்தபடி compute பண்ணுங்க, time அல்லது customer வெச்சு split பண்ணுங்க, preprocessing-ஐ training data-ல மட்டும் fit பண்ணுங்க."

ஒவ்வொண்ணும் ஒரு mechanism, ஒரு concrete example, ஒரு decision-ஐ சொல்லுது; எதுவும் definition-ஐ ஒப்பிக்கல. இந்த topics-க்கும் இதே shape-ல தயார் பண்ணுங்க.

| Topic | ஒரு நல்ல பதிலோட core |
| --- | --- |
| Bias, variance | Training, validation error ரெண்டுமே high-னா underfitting; ரெண்டுக்கும் நடுவுல பெரிய gap-னா overfitting. Learning curves-ல இருந்து படிங்க |
| Regularisation | L2 எல்லா weights-ஐயும் சுருக்கும்; L1 சிலதை சரியா zero-க்கு தள்ளும், அது features-ஐ select பண்ணும். ரெண்டுமே கொஞ்சம் bias-ஐ குடுத்து variance-ஐ குறைக்கும் |
| Imbalanced data | Accuracy ஏமாத்தும். PR AUC use பண்ணுங்க, business act பண்ண முடியுற threshold அல்லது capacity-ல precision, recall பாருங்க |
| Cross-validation | Independent rows-க்கு K-fold; rows time order-ல இருந்தா அல்லது ஒரே customer-ஐ share பண்ணா time-based அல்லது grouped folds |
| Logistic regression | ஒரு linear score-ஐ sigmoid வழியா அனுப்புறது, log loss-ஓட train பண்றது. Fast, explain பண்ண ஈஸி, ஒரு strong baseline |
| Attention | ஒவ்வொரு token-ஓட query-யும் ஒவ்வொரு token-ஓட key கூட compare ஆகும்; scores-ஓட softmax அவங்களோட values-க்கு weight குடுக்கும் |

அதிகமா கேக்குற topics-ல I1 lessons "Cross-validation and leakage", "Choosing a metric" இன்னும் ஆழமா போகும்.

### ML system design

Diagram-ல இருக்குற ஒன்பது steps-ஐ வரிசைப்படி use பண்ணுங்க, numbers-ஐ சத்தமா சொல்லுங்க. மூணு steps-க்கு அதிக கவனம் வேணும். *Framing*-ல, label எங்க இருந்து வருது, எவ்வளவு லேட்டா வருதுன்னு சொல்லுங்க. *Evaluation*-ல, reality-க்கு match ஆகுற ஒரு split-ஐயும், operating point-ல ஒரு metric-ஐயும், segment வாரியா தேர்ந்தெடுங்க. *Serving*-ல, latency budget-ஐயும் ஒரு fallback-ஐயும் சொல்லுங்க.

**Offline vs online.** ஒரு நல்ல offline score நல்ல business result-ஐ guarantee பண்ணாது, ஏன்னா live users model-க்கு react பண்ணுவாங்க. ஒரு primary metric-உம், complaint rate அல்லது latency மாதிரி guardrails-உம் இருக்குற ஒரு A/B test-ஐ plan பண்ணுங்க. Pitfalls-ஐ தெரிஞ்சுக்கோங்க. Result significant-ஆ தெரிஞ்ச உடனே நிறுத்துறது ("peeking") பொய்யான wins-ஐ அதிகமாக்கும். ஒரு முழு வாரத்தை விட குறைவான test, weekday, weekend patterns-ஐ miss பண்ணும். விஷயங்களை block பண்ற அல்லது மறைக்குற ஒரு model, என்ன நடந்திருக்கும்னு பாக்க விடாது, அதனால ஒரு சின்ன random holdout வெச்சுக்கோங்க.

**"Why not X?"-ஐ handle பண்றது.** Trade-off-ஓட பதில் சொல்லுங்க. உதாரணமா: "ஒரு deep model உதவலாம், ஆனா tabular features, லேட்டான labels இருக்கும்போது, gradient boosting பெரும்பாலும் கிட்டத்தட்ட அதே accuracy குடுக்கும், சில நிமிஷங்கள்ல train ஆகும், risk team-க்கு explain பண்ணவும் ஈஸி. Trees miss பண்ற patterns இருக்குன்னு error analysis காட்டினா ஒரு deep model try பண்ணுவேன்."

### LLM, GenAI design கேள்விகள்

சில ML loops-ல இப்போ ஒரு large language model மேல build பண்ண product பத்தி ஒரு கேள்வி வருது, உதாரணமா:

- "ஒரு bank-ஓட policy documents-ல இருந்து customer கேள்விகளுக்கு English-லயும் Hindi-லயும் பதில் சொல்ற ஒரு assistant-ஐ design பண்ணுங்க."
- "Support tickets-ஐ 40 categories-ஆ பிரிக்க prompting use பண்ணணுமா, RAG-ஆ, fine-tuning-ஆ?"

Goal-ஐயும், தப்பான பதிலோட cost-ஐயும் clarify பண்ணுங்க, அப்புறம் work ஆகக்கூடிய simplest approach-ஐ தேர்ந்தெடுங்க: answers மாறிக்கிட்டே இருக்குற documents-ல இருந்து வரணும், citations வேணும்னா RAG; task simple-ஆ இருந்தா சில examples-ஓட prompting; volume அதிகம், cost அல்லது latency முக்கியம்னா ஒரு சின்ன model-ஐ fine-tune பண்றது. நிறைய labelled history இருக்குற ticket sorting-க்கு, ஒரு classic classifier-ஐயும் baseline-ஆ சொல்லுங்க. அப்புறம் measurement-ஐ முதல்ல வைங்க: real கேள்விகளோட ஒரு eval set, answers-ல இருந்து தனியா score பண்ண retrieval, relevant-ஆ எதுவும் கிடைக்கலைன்னா என்ன பண்றதுன்னு ஒரு plan. ஒரு query-க்கு cost, latency, privacy, ஒரு human fallback-ஓட முடிங்க. "Build a RAG app", "Test sets and evals", "Prompting, RAG or fine-tuning", "The design interview" lessons ஒவ்வொரு பகுதியையும் cover பண்ணுது.

### Project deep-dive, behavioural

**Project deep-dive.** ஒண்ணு ரெண்டு projects-ஐ ஆழமா தயார் பண்ணுங்க: problem, data, baseline, என்ன try பண்ணீங்க, numbers-ஓட results, என்ன தப்பா போச்சு, அடுத்து என்ன. ஒரு team project-ல நீங்களே என்ன பண்ணீங்கன்னு தெளிவா சொல்லுங்க.

**Behavioural.** STAR (situation, task, action, result) use பண்ணுங்க, numbers-ஓடவும் ஒரு lesson-ஓடவும். ஒரு illustrative failure story (உங்க சொந்த real story-ஐ use பண்ணுங்க):

- *Situation*: "Pune-ல ஒரு insurance sales team-க்கு நான் பண்ண lead-scoring model live ஆச்சு. ரெண்டு வாரத்துல, top-scored leads-ல conversion testing-ல இருந்த சுமார் 9%-ல இருந்து சுமார் 4%-க்கு விழுந்துச்சு."
- *Task*: "Model என்னோடது, cause-ஐ சீக்கிரம் கண்டுபிடிக்கணும்."
- *Action*: "Training, live feature values-ஐ compare பண்ணேன். ஒரு 'last call outcome' field, training data-ல call முடிஞ்ச அப்புறம் fill ஆகியிருந்துச்சு, ஆனா scoring time-ல blank-ஆ இருந்துச்சு. அது leakage. Features-ஐ scoring time அன்னைக்கு இருந்தபடி rebuild பண்ணேன், training, live features-ஐ compare பண்ற ஒரு pre-launch check-ஐ சேர்த்தேன்."
- *Result*: "Offline AUC 0.91-ல இருந்து 0.78-க்கு விழுந்துச்சு, ஆனா top leads-ல live conversion சுமார் 7%-க்கு திரும்ப வந்துச்சு. இப்போ training-க்கு முன்னாடி ஒவ்வொரு feature-உம் prediction time-ல இருக்கான்னு check பண்றேன்."

## ஒரு worked example

கேள்வி: "ஒரு payments company-க்கு fraudulent UPI merchant payments-ஐ detect பண்ற ஒரு system-ஐ design பண்ணுங்க." கீழ இருக்குற numbers interview-ல நீங்க சொல்ற assumptions, real figures இல்ல.

1. **Goal**: குறைவான analyst நேரத்தோட fraud losses-ஐ குறைக்கணும். Latency பத்தி கேளுங்க; payment flow block பண்ண சுமார் 100 ms குடுக்குது, கூடவே ஒரு review queue இருக்குன்னு வெச்சுக்கோங்க.
2. **Framing**: ஒவ்வொரு payment-க்கும் binary classification. Labels chargebacks-ல இருந்தும் confirm ஆன investigations-ல இருந்தும் வருது. அவை 60 நாளுக்குள்ள வருதுன்னு assume பண்ணுங்க.
3. **Data**: payments, merchant profiles, device, network signals, பழைய fraud. Fraud அரிது; payments-ல 0.05%-னு assume பண்ணுங்க.
4. **Features**: கடைசி ஒரு மணி நேரத்துல ஒரு merchant-க்கு எத்தனை payments, merchant-ஓட வழக்கமான amounts கூட compare பண்ண amount, புது device, நாளோட நேரம், merchant category. எல்லாமே ஒரு feature store-ல இருந்து payment time அன்னைக்கு இருந்தபடி compute ஆகும், அதனால training-உம் serving-உம் match ஆகும்.
5. **Model**: ஒரு rules baseline, அப்புறம் class weights-ஓட gradient-boosted trees. பின்னாடி, merchants, devices, accounts-ஐ இணைக்குற graph features.
6. **Evaluation**: மேல இருக்குற code மாதிரி 60-day gap-ஓட ஒரு time split. Analysts handle பண்ண முடியுற alert volume-ல PR AUC, precision, recall-ஐ merchant category, region வாரியா measure பண்ணுங்க. அப்புறம் traffic-ஓட ஒரு பங்குல ஒரு A/B test ஓட்டுங்க.
7. **Serving**: Real-time scoring, model time out ஆனா rules-க்கு fallback. ரெண்டு thresholds: ரொம்ப high score-க்கு மேல auto-block, அதுக்கு கீழ review queue.
8. **Monitoring**: Key features-ல drift, alert rate-ல மாற்றங்கள், monthly retraining. Block ஆன payments fraud-ஆ இல்லையான்னு ஒருபோதும் தெரியவராது, அதனால block ஆகப்போற payments-ல ஒரு சின்ன random sample-ஐ block பண்ணாம analysts-கிட்ட அனுப்புங்க.
9. **Risks**: உண்மையான சின்ன merchants-ஐ block பண்றது (ஒரு appeal route குடுங்க), fraudsters மாறிக்கிறது (அடிக்கடி retrain பண்ணுங்க), regions முழுக்க சமமில்லாத error rates.

இப்போ numbers-ஐ சத்தமா சொல்லுங்க. Accuracy ஏன் தப்பான metric-னு அவை காட்டும்.

| Quantity (assumed) | Value |
| --- | --- |
| ஒரு நாளுக்கு payments | 20 lakh |
| Fraud rate | 0.05%, அதாவது ஒரு நாளுக்கு 1,000 frauds |
| "Never fraud"-ஓட accuracy | 99.95%, பிடிச்ச fraud zero |
| Analysts review பண்ண முடியுற alerts | ஒரு நாளுக்கு 2,000 |
| Top 2,000 alerts-ல frauds (example) | 600 |
| 2,000-ல precision | 600 / 2,000 = 30% |
| 2,000-ல recall | 600 / 1,000 = 60% |

அப்புறம் கேளுங்க: "30% precision-ல 60% fraud-ஐ பிடிக்குறது analyst cost-க்கு worth-ஆ, ஒரு நாளுக்கு இன்னும் 500 reviews அவங்களுக்கான செலவை திரும்ப எடுக்குமா?" அது ஒரு model-ஐ ஒரு business decision-ஆ மாத்துது.

## பொதுவா பண்ற தப்புகள்

- **DSA தயாரிப்பை skip பண்றது.** பெரிய product companies-ல ML loops-ல ஒரு standard coding round இருந்ததா சில candidates சொல்றாங்க, அது ஒரு strong ML candidate-ஐயும் கவிழ்க்கலாம்.
- **நேரா deep learning-க்கு தாவுறது.** ஒரு baseline-ல ஆரம்பிங்க, complexity-ல ஒவ்வொரு step ஏறுறதுக்கும் காரணம் சொல்லுங்க.
- **Label-ஐ கண்டுக்காம விடுறது.** Labels எங்க இருந்து, எவ்வளவு லேட்டா வருதுங்குறது data, split, metric, retraining எல்லாத்தையும் shape பண்ணும்.
- **Time-based problems-க்கு random அல்லது gap இல்லாத splits.** ரெண்டுமே future information-ஐ leak பண்ணி scores-ஐ ஏத்திவிடும்.
- **Imbalanced data-ல accuracy-ஐ quote பண்றது.** Business act பண்ண முடியுற capacity-ல precision, recall சொல்லுங்க.
- **ஒரு offline win-ஐ launch-ஆ நினைக்குறது.** A/B test, guardrails, holdout-ஐ plan பண்ணுங்க.
- **Serving அல்லது monitoring plan இல்லாம இருக்குறது.** Latency budget, fallback, எது retraining-ஐ trigger பண்ணும்னு சொல்லுங்க.
- **ஆழமில்லாத project stories.** உங்க numbers, உங்க சொந்த contribution, உங்க தப்புகள் தெரிஞ்சிருக்கணும்.

## Practice பண்ணுங்க

Chip Huyen-ஓட ML systems design notes-ஐயும் அவங்களோட ML interviews book-ஐயும் படிங்க; behavioural rounds-க்கு Tech Interview Handbook use பண்ணுங்க.

1. **DSA**: ஒவ்வொரு pattern-க்கும் சில medium problems-ஐ Python-ல, சத்தமா பேசிக்கிட்டே, timed-ஆ solve பண்ணுங்க.
2. **ML coding**: Notes இல்லாம, label-delay gap-ஓட ஒரு time split, k-ல precision, recall, NumPy-ல k-means எழுதுங்க. ஒவ்வொண்ணையும் ஒரு குட்டி example-ல test பண்ணுங்க.
3. **Fundamentals**: பத்து கேள்விகளுக்கு mechanism, trade-off, default shape-ல 60-ல இருந்து 90 வார்த்தை பதில்கள் எழுதுங்க, ஒவ்வொண்ணுலயும் ஒரு Indian example-ஓட.
4. **System design**: பாக்காத ரெண்டு கேள்விகளுக்கு ஒன்பது steps-ஓட தலா 40 நிமிஷத்துல பதில் சொல்லுங்க, record பண்ணுங்க. உதாரணமா, Hyderabad-ல ஒரு grocery chain-க்கு demand forecasting, அல்லது ஒரு jobs app-க்கு ranking. Table வெச்சு உங்களை நீங்களே score பண்ணுங்க.
5. **GenAI**: Bank assistant கேள்விக்கு பதில் சொல்லுங்க, அதோட eval set-ஐ சரியா எப்படி build பண்ணுவீங்கன்னு சொல்லுங்க.
6. **Deep-dive, behavioural**: ஒரு project deep-dive-ஐயும், ஒரு failure பத்தினது உட்பட மூணு STAR stories-ஐயும் தயார் பண்ணுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** பேசிக்கிட்டே ஒரு medium DSA problem-ஐ 30 நிமிஷத்துல solve பண்ண முடியும், பாக்காத ஒரு ML system-ஐ 40 நிமிஷத்துல தெளிவான label, நேர்மையான split, operating point-ல ஒரு metric, serving, monitoring-ஓட design பண்ண முடியும்.
