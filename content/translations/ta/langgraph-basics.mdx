## இது என்ன

LangGraph ஒரு open-source Python, JavaScript framework. Agents-ஐயும் multi-step AI workflows-ஐயும் **graphs**-ஆ build பண்ண உதவும்:

- **State**: ஒரு typed object, உதாரணம் messages, தற்போதைய ticket, ஒரு draft reply இருக்குற dictionary. இது graph முழுக்க கடந்து போகும்.
- **Nodes**: state-ஐ வாங்கி updates-ஐ திருப்புற functions. ஒரு node ஒரு model-ஐ call பண்ணலாம், ஒரு tool-ஐ call பண்ணலாம், இல்ல சாதாரண code-ஐ ஓட்டலாம்.
- **Edges**: அடுத்து எந்த node ஓடணும். Conditional edges state-ஐ பார்த்து தேர்ந்தெடுக்கும்: "model ஒரு tool கேட்டிருந்தா tool node-க்கு போ; இல்லன்னா முடிச்சிடு."
- **Checkpointer**: ஒவ்வொரு step-க்கு அப்புறமும் state-ஐ save பண்ணும். அதனால ஒரு run-ஐ pause, resume, inspect, replay பண்ணலாம்.

Agent loop ஒரு சின்ன graph தான்: model node, tool node, அவற்றுக்கு நடுவுல loop ஆகுற ஒரு conditional edge. Workflow-ன்னா fixed edges இருக்குற graph. LangGraph ரெண்டையும் ஒரே system-ல கலக்க விடும்.

```flow
title: ஒவ்வொரு node-க்கு அப்புறமும், ஒவ்வொரு thread_id-க்கும் state save ஆகும் (checkpointer)
START -> classify
classify -[billing]-> billing_agent | ஒரு tool loop
classify -[outage]-> outage_agent | ஒரு tool loop
billing_agent -[credit propose பண்ணும்]-> approve_credit | INTERRUPT: ஒரு supervisor முடிவு பண்ணுவார்
billing_agent -[credit இல்ல]-> reply
approve_credit -> apply_credit -> reply
outage_agent -> reply
reply -> END
```

இந்த lesson-ல Chennai-ல இருக்குற ஒரு broadband provider, credits-க்கு approval இருக்குற support-ticket assistant-ஐ build பண்றதை follow பண்றோம்.

## இது எப்படி work ஆகுது

State type-ஐ define பண்ணி, nodes-ஐ சேர்த்து, edges-ஐ connect பண்ணி, compile பண்ணுவீங்க:

```python
from typing import TypedDict, Annotated
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langgraph.checkpoint.memory import MemorySaver

class State(TypedDict):
    messages: Annotated[list, add_messages]   # new messages are appended, not replaced
    category: str | None

def classify(state: State) -> dict:
    label = llm_classify(state["messages"][-1].content)
    return {"category": label}

def route(state: State) -> str:
    return "billing" if state["category"] == "billing" else "general"

g = StateGraph(State)
g.add_node("classify", classify)
g.add_node("billing", billing_agent)
g.add_node("general", general_agent)
g.add_edge(START, "classify")
g.add_conditional_edges("classify", route, ["billing", "general"])
g.add_edge("billing", END)
g.add_edge("general", END)
app = g.compile(checkpointer=MemorySaver())
```

ஒவ்வொரு invocation-உம் ஒரு `thread_id`-ஐ அனுப்பும்; checkpointer ஒவ்வொரு thread-க்கும் state-ஐ store பண்ணும். அதனால அதே thread-ல அடுத்த message வந்தா, விட்ட இடத்துல இருந்து தொடரும். Production-ல `MemorySaver`-ஐ PostgreSQL மாதிரி database-backed checkpointer-ஆ மாத்துவீங்க.

**Interrupts** ஒரு node-க்கு முன்னாடி அல்லது உள்ள ஒரு run-ஐ pause பண்ணி, வெளிய இருந்து input வர்ற வரை காத்திருக்கும்; human approval-ஓட அடிப்படை இதுதான். **Streaming** node-by-node updates-ஐ UI-க்கு அனுப்பும். **Sub-graphs** ஒரு node-ஐயே முழு graph-ஆ ஆக்க விடும்; ஒரு பெரிய flow-க்குள்ள ஒரு specialist agent வைக்க உதவும்.

**LangGraph pieces-உம் அவை கொடுக்குறதும்:**

| Piece | அது என்ன | உங்களுக்கு என்ன கொடுக்கும் |
| --- | --- | --- |
| State | ஒரு typed dictionary | Run-க்கு தெரிஞ்ச எல்லாத்தையும் பார்க்க ஒரே இடம் |
| Node | Updates-ஐ திருப்புற ஒரு function | சின்ன, test பண்ணக்கூடிய steps |
| Edge | Fixed அடுத்த step | Predictable workflows |
| Conditional edge | அடுத்த node-ஐ தேர்ந்தெடுக்குற function | Routing, tool loops |
| Checkpointer | ஒவ்வொரு thread-க்கும் save ஆன state | Memory, pause-resume, replay |
| Interrupt | வெளிய இருந்து input-க்கான pause | Human approval |
| Sub-graph | ஒரு node-ஆ use ஆகுற graph | பெரிய flow-க்குள்ள specialist agents |

**State updates எப்படி work ஆகுது.** ஒரு node தான் மாத்துற fields-ஐ மட்டும் திருப்பும், LangGraph அவற்றை state-ல merge பண்ணும். பெரும்பாலான fields-ல புது value பழசை replace பண்ணும். `add_messages` மாதிரி ஒரு reducer குறிச்ச fields-ல, புது values சேர்ந்துக்கும். அதனால தான் ஒரு tool node புது tool message-ஐ மட்டும் திருப்பினாலும் history அப்படியே இருக்கும். Reducer-ஐ மறந்துடுறது ஒரு பொதுவான bug: அப்போ ஒவ்வொரு node-உம் conversation-ஐ ஒரே ஒரு message-ஆ overwrite பண்ணிடும்.

**Checkpoints வச்சு debug பண்றது.** ஒவ்வொரு step-உம் save ஆகுறதால, ஒரு thread-ஓட checkpoints-ஐ list பண்ணலாம், ஒவ்வொண்ணுலயும் state-ஐ படிக்கலாம், ஒரு முந்தைய checkpoint-ல இருந்து மாத்தின state-ஓட resume பண்ணி, என்ன நடந்திருக்கும்னு கூட பார்க்கலாம். ஒரு reply தப்பா போகும்போது, print statements சேர்த்து மறுபடி ஓட்டாமலே, எந்த node எந்த மாற்றத்தை உருவாக்குச்சுன்னு இது காட்டும்.

**Graphs-உம் சாதாரண code-உம் சேர்ந்து.** எல்லா step-க்கும் model வேண்டியதில்ல. Validation, database writes, formatting எல்லாம் model call இல்லாத சாதாரண nodes; அதனால வேகமா, மலிவா, test பண்ண easy-ஆ இருக்கும்.

**Interrupt, resume வச்சு approval.** ஒரு node-க்குள்ள `interrupt` run-ஐ pause பண்ணி, resume ஆகும்போது அந்த ஆள் திருப்பி அனுப்புற எதையும் திருப்பும்:

```python
from langgraph.types import interrupt, Command

def refund_node(state: State) -> dict:
    proposal = {"action": "refund", "amount_inr": state["amount"], "order": state["order_id"]}
    decision = interrupt(proposal)                 # the run stops here and state is saved
    if not decision.get("approved"):
        return {"messages": [("assistant", "A team member will contact you about the refund.")]}
    amount = decision.get("amount_inr", state["amount"])   # the approver may edit it
    issue_refund(state["order_id"], amount)
    return {"messages": [("assistant", f"Refund of ₹{amount} started.")]}

config = {"configurable": {"thread_id": "order-7781"}, "recursion_limit": 25}
result = app.invoke({"messages": [("user", "Refund my damaged kurta, order 7781")]}, config)
# result["__interrupt__"] holds the proposal; show it on the approval screen.

# Later, possibly hours later, from the approval page's handler:
app.invoke(Command(resume={"approved": True, "amount_inr": 3000}), config)
```

Resume ஆகும்போது node அதோட தொடக்கத்துல இருந்தே மறுபடி ஓடும். அதனால side effects-ஐ இங்க இருக்கிற மாதிரி `interrupt` call-க்கு அப்புறம் வச்சு, அவற்றை idempotent ஆக்குங்க.

**Database checkpointer.** `MemorySaver` restart-ல எல்லாத்தையும் இழக்கும். உண்மையான use-க்கு checkpoints-ஐ Postgres-ல store பண்ணுங்க:

```python
from langgraph.checkpoint.postgres import PostgresSaver

with PostgresSaver.from_conn_string("postgresql://app:***@db:5432/agents") as saver:
    saver.setup()                                  # creates the checkpoint tables once
    app = g.compile(checkpointer=saver)
    app.invoke({"messages": [("user", "Hi")]}, {"configurable": {"thread_id": "t-42"}})
```

Connection string-ஐ code-ல இல்லாம, environment variable-ல இருந்து படிங்க.

**Progress-ஐ stream பண்றது.** `app.stream(inputs, config, stream_mode="updates")` ஒவ்வொரு node-ம் முடியும்போது அதோட update-ஐ தரும். அதனால UI நீண்ட மௌனத்துக்கு பதிலா "Checking your order…", அப்புறம் "Looking up the refund policy…"-ன்னு காட்டலாம்.

**Nodes-ஐ தனியா test பண்றது.** Nodes state-ல இருந்து updates-க்கு போற சாதாரண functions, அதனால model இல்லாமலே unit-test பண்ணலாம்:

```python
def test_route_billing():
    assert route({"messages": [], "category": "billing"}) == "billing"

def test_route_unknown_goes_general():
    assert route({"messages": [], "category": None}) == "general"
```

ஒரு model-ஐ call பண்ற nodes-க்கு, tests-ல fixed replies திருப்புற ஒரு fake model-ஐ கொடுங்க. அப்புறம் சேமிச்சு வச்ச சில conversations வச்சு முழு graph-ஐ test பண்ணுங்க.

**Prebuilt agent.** சாதாரண tool-using loop-க்கு, `langgraph.prebuilt.create_react_agent(model, tools)` model-and-tools graph-ஐ உங்களுக்காக build பண்ணிடும். அங்கிருந்து ஆரம்பிச்சு, routing, approvals, அல்லது பல specialist nodes தேவைப்படும்போது உங்க சொந்த graph-ஐ எழுதுங்க.

**ஒவ்வொரு run-க்கும் limit வையுங்க.** Config-ல `recursion_limit`-ஐ set பண்ணுங்க. ஒரு conditional edge run-ஐ அதே node-க்கு திரும்ப திரும்ப அனுப்பிக்கிட்டே இருந்தா, அது நீங்க catch பண்ணக்கூடிய ஒரு error-ஓட நின்னுடும்; அதை நீங்க ஒரு clean handover-ஆ மாத்தலாம்.

## ஒரு worked example

Chennai-ல ஒரு broadband provider support tickets-க்கு ஒரு assistant வேணும்னு நினைக்குது. தேவைகள்: ஒவ்வொரு ticket-ஐயும் classify பண்ணணும், billing கேள்விகளை account tools வச்சு handle பண்ணணும், outage கேள்விகளை ஒரு status tool வச்சு handle பண்ணணும், எந்த credit-ஐ apply பண்றதுக்கு முன்னாடியும் ஒரு supervisor-ஓட approval வாங்கணும்.

Graph: `classify`, `billing_agent` அல்லது `outage_agent`-க்கு route பண்ணும்; ரெண்டும் சின்ன tool loops. Billing agent ஒரு credit-ஐ propose பண்ணா, graph `approve_credit`-க்கு route ஆகி interrupt ஆகும். Supervisor தன் dashboard-ல ticket-ஐயும், propose பண்ண ₹300 credit-ஐயும், agent-ஓட காரணத்தையும் பார்த்து approve அல்லது edit பண்ணுவார்; run checkpoint-ல இருந்து `apply_credit`, `reply`-க்கு resume ஆகும்.

ஒவ்வொரு node-க்கு அப்புறமும் state checkpoint ஆகுறதால, ஒரு ticket நடுவுல server restart ஆனாலும் எதுவும் போகாது. ஒரு customer ஒரு reply பத்தி complain பண்ணும்போது, அந்த thread-ஓட checkpoints-ஐ load பண்ணி, எந்த node எந்த state-ஓட என்ன பண்ணுச்சுன்னு சரியா பார்க்கலாம். Tests தனித்தனி nodes-ஐ கையால செஞ்ச state-ஓட call பண்ணும், அதனால routing logic model calls இல்லாமலே unit-test ஆகுது.

| நிலைமை | Graph என்ன பண்ணுச்சு |
| --- | --- |
| Billing கேள்வி | classify, billing_agent, reply |
| ₹300 credit propose பண்ணது | approve_credit-ல interrupt ஆச்சு; supervisor approve பண்ணப்புறம் resume ஆச்சு |
| Ticket நடுவுல server restart | கடைசி checkpoint-ல இருந்து resume ஆச்சு, எதுவும் போகல |
| Customer complaint | எந்த node எந்த state-ல இருந்து reply எழுதுச்சுன்னு thread checkpoints காட்டுச்சு |

## பொதுவா பண்ற தப்புகள்

- **எல்லாத்தையும் ஒரே பெரிய node-ல போடுறது.** Graph-ஓட நோக்கமே visibility-உம் testability-உம் தான்; அதை இழந்துடுவீங்க.
- **எல்லை இல்லாம வளருற state.** ஒவ்வொரு tool result-ஐயும் என்றென்றைக்கும் சேர்த்துக்கிட்டே இருந்தா prompts வீங்கும். ஒரு node-ல trim பண்ணுங்க அல்லது summarise பண்ணுங்க.
- **Production-ல in-memory checkpoints.** Restart ஆனா pause ஆன எல்லா runs-உம் போயிடும். Persistent checkpointer use பண்ணுங்க.
- **ஒரு function போதும்ங்கிற இடத்துல graph use பண்றது.** Fixed மூணு-step pipeline-க்கு framework தேவையில்ல.
- **Versions-ஐ புறக்கணிக்கிறது.** Library வேகமா மாறுது; pin பண்ணி, upgrade பண்ணுறதுக்கு முன்னாடி changelog-ஐ படிங்க.
- **`interrupt`-க்கு முன்னாடி side effects.** Resume-ல node தொடக்கத்துல இருந்து மறுபடி ஓடும், அதனால action ரெண்டு தடவை நடக்கும்.
- **Production-ல `MemorySaver`.** ஒவ்வொரு restart அல்லது deploy-லயும் state காணாம போயிடும்.
- **`recursion_limit` இல்லாம இருக்கிறது.** Loop ஆகுற graph வேற எதுவும் நிறுத்துற வரை cost-ஐ ஏத்திக்கிட்டே இருக்கும்.

## LangGraph தேவையில்லாத நேரங்கள்

- **சாதாரண tool loop**: agent-loop lesson-ல இருந்த இருபது வரி loop, அல்லது ஒரு provider-ஓட agent SDK போதுமா இருக்கலாம்.
- **Pauses-ஓ branching-ஓ இல்லாத fixed pipeline**: வரிசையா call பண்ற சாதாரண functions படிக்க easy.
- **State, pauses, tracing-ஐ cover பண்ற வேற framework-ல ஏற்கனவே இருக்குற teams.**

ஒவ்வொரு conversation-க்கும் saved state, ஆட்களுக்கான pauses, branching, ஒரு run-ஐ replay பண்ற திறன் தேவைப்படும்போது LangGraph தன் இடத்தை சம்பாதிக்கும்.

## Demo-ல இருந்து production-க்கு

- **Database checkpointer-ஐ use பண்ணுங்க**, மத்த production data மாதிரியே backup எடுங்க.
- **ஒவ்வொரு run-க்கும் recursion limits-உம் timeouts-உம் set பண்ணுங்க.**
- **ஒவ்வொரு node-ஐயும் thread id-ஓட trace பண்ணுங்க**, அப்போ ஒரு support ticket நேரா run-க்கு கூட்டிட்டு போகும்.
- **Graph-ஐ version பண்ணுங்க**: nodes மாறும்போது, பழைய version-ல pause ஆன threads-க்கு என்ன ஆகும்னு முடிவு பண்ணுங்க.
- **Nodes, routes, சில முழு conversations-ஐ** CI-ல fake models வச்சு test பண்ணுங்க.

## Practice பண்ணுங்க

LangChain Academy-ஓட இலவச Introduction to LangGraph-ஐ எடுங்க, குறைஞ்சது முதல் மூணு modules.

1. நீங்க விரும்புற ரெண்டு categories-க்கு, மேல இருக்குற classify-then-route graph-ஐ build பண்ணுங்க; tests-க்கு ஒரு fake model வைங்க.
2. ஒரு checkpointer சேர்த்து, அதே thread-ல ரெண்டாவது message முதல் message-ஐ பார்க்குதுன்னு காட்டுங்க.
3. ஒரு risky node-க்கு முன்னாடி interrupt சேர்த்து, ஒரு script-ல இருந்து approve பண்ணி resume பண்ணுங்க.
4. Interrupt வச்சு ஒரு run-ஐ pause பண்ணி, உங்க Python process-ஐ restart பண்ணி, Postgres checkpointer-ல இருந்து resume பண்ணி, pause தாங்குதுன்னு நிரூபிங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** உங்க graph-ஐ வரைய முடியும், state எங்க save ஆகுதுன்னு காட்ட முடியும், program-ஐ restart பண்ணின பிறகும் pause ஆன run-ஐ resume பண்ண முடியும்.
