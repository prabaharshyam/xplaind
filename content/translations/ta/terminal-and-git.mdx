## இது என்ன

ஒவ்வொரு developer-உம் தினமும் ரெண்டு tools use பண்றாங்க:

- **Terminal**: commands run பண்ற ஒரு text window. இதுல folders-க்கு நடுவுல நகரலாம், programs run பண்ணலாம், packages install பண்ணலாம், Git மாதிரி tools use பண்ணலாம்.
- **Git**: உங்க project-ஓட snapshots-ஐ, அதாவது **commits**-ஐ record பண்ற version control system. என்ன மாறுச்சுன்னு பார்க்கலாம், தப்புகளை undo பண்ணலாம், code-ஐ share பண்ணலாம். **GitHub** Git repositories-ஐ online-ல host பண்ணும்; மத்தவங்க அதை பார்க்கலாம், உங்ககூட சேர்ந்து வேலை செய்யலாம்.

```flow
dir: LR
உங்க folder | hello.py, expenses.py, README.md: நீங்க files-ஐ edit பண்றீங்க -[git add, git commit]-> உங்க computer-ல Git | commits 1, 2, 3: undo பண்ணக்கூடிய history
உங்க computer-ல Git -[git push]-> GitHub | உங்க public repository: share பண்ணக்கூடிய link
```

Employers GitHub profiles-ஐ பார்க்குறாங்க. தெளிவான commits-உம் நல்ல README-உம் இருக்குற repository தான், நீங்க code எழுதி organise பண்ண முடியும்ங்குறதுக்கு எளிமையான proof; interview-லயே interviewers அதை பெரும்பாலும் திறந்து பார்ப்பாங்க.

Nagpur-ல Python கத்துக்கிட்டிருக்குற Ravi, exercise scripts இருக்குற ஒரு folder-ஐ GitHub portfolio-வா மாத்துறதை இந்த lesson follow பண்ணும். இதோட check ஒரு சின்ன project: உங்களோட சொந்த repository, குறைஞ்சது மூணு தெளிவான commits-ஓட, ஒரு README-ஓட.

## இது எப்படி work ஆகுது

### Terminal basics

| Command | என்ன பண்ணும் |
| --- | --- |
| `pwd` | நீங்க இருக்குற folder-ஐ காட்டும் (Mac, Linux; Windows-ல `cd` மட்டும்) |
| `ls` | Files-ஐ list பண்ணும் (Windows Command Prompt-ல `dir`) |
| `cd projects` | ஒரு folder-க்குள்ள போகும் |
| `cd ..` | ஒரு folder மேல போகும் |
| `mkdir python-practice` | புது folder உருவாக்கும் |
| `python hello.py` | ஒரு program-ஐ run பண்ணும் |

**Up arrow** முந்தின commands-ஐ திரும்ப கொண்டு வரும், **Tab** file, folder பேர்களை complete பண்ணும்; இதனால type பண்றதும் typos-உம் ரொம்ப குறையும்.

### Git-ஐ ஒரு தடவை set up பண்ணுங்க

Git-ஐ install பண்ணுங்க, அப்புறம் நீங்க யாருன்னு சொல்லுங்க:

```bash
git config --global user.name "Priya Raman"
git config --global user.email "priya@example.com"
```

### Repository ஆரம்பிச்சு commits பண்ணுங்க

```bash
cd python-practice
git init                         # start tracking this folder
git status                       # what has changed?
git add hello.py                 # choose changes for the next commit
git commit -m "Add hello script that prints name and date"
git log --oneline                # see the history
```

`git add` changes-ஐ **staging area**-ல போடும்: அடுத்த snapshot-ல என்ன போகும்னு ஒரு list. `git commit` அந்த snapshot-ஐ ஒரு message-ஓட save பண்ணும். இந்த ரெண்டு-step design-னால தொடர்புடைய changes-ஐ சேர்த்து commit பண்ணவும், மத்ததை அப்புறம் பார்க்கவும் முடியும்.

### நல்ல commit messages

| பலவீனம் | வலிமை |
| --- | --- |
| "update" | "Add expense totals by category" |
| "fixed stuff" | "Handle missing amounts in expense CSV" |
| "final" | "Add README with usage examples" |

Present tense-ல எழுதுங்க, என்ன மாறுச்சுன்னு சொல்லுங்க, முதல் வரியை சின்னதா வைங்க. ஏதாவது உடைஞ்சா எதிர்காலத்துல நீங்களே இதை படிப்பீங்க.

### Git-ல Undo

| Situation | Command |
| --- | --- |
| கடைசி commit-க்கு அப்புறம் என்ன மாறுச்சுன்னு பார்க்க | `git diff` |
| ஒரு file-ல பண்ண changes-ஐ தூக்கி போட | `git restore expenses.py` |
| தப்பா add பண்ண file-ஐ unstage பண்ண | `git restore --staged expenses.py` |
| பழைய version-ஐ பார்க்க | `git log --oneline`, அப்புறம் `git show <commit>` |

### GitHub-க்கு push பண்ணுங்க

GitHub-ல ஒரு empty repository உருவாக்கி, அப்புறம் connect பண்ணி push பண்ணுங்க:

```bash
git remote add origin https://github.com/priya-raman/python-practice.git
git branch -M main
git push -u origin main
```

GitHub உங்களை sign in பண்ணச் சொல்லும்; அதன் prompts-ஐ follow பண்ணுங்க, இல்லன்னா ஒரு SSH key set up பண்ணுங்க. முதல் push-க்கு அப்புறம், `git push` மட்டும் போதும், புது commits போயிடும்.

### README-உம் .gitignore-உம்

`README.md` project என்ன, எப்படி run பண்றதுன்னு விளக்கும். GitHub அதை repository-ஓட முதல் page-ல காட்டும்.

`.gitignore` file Git track பண்ணக்கூடாத விஷயங்களை list பண்ணும்:

```text
.venv/
__pycache__/
.env
```

`.env` வரி தான் ரொம்ப முக்கியம்: `.env` files-ல பெரும்பாலும் API keys இருக்கும். உங்க முதல் `git add`-க்கு **முன்னாடியே** `.gitignore` உருவாக்குங்க, ஏன்னா ஒரு secret commit ஆயிட்டா, அப்புறம் file-ஐ delete பண்ணாலும் history-ல இருக்கும். ஒரு key எப்பவாவது push ஆயிட்டா, உடனே அதை revoke பண்ணி புது key உருவாக்குங்க.

## ஒரு worked example

Nagpur-ல Python கத்துக்கிட்டிருக்குற Ravi-கிட்ட exercise scripts இருக்குற ஒரு folder இருக்கு: ஒரு expense tracker, ஒரு marks calculator, API key use பண்ற ஒரு weather fetcher. அதை GitHub portfolio-வா மாத்துறாரு.

| Step | என்ன பண்றாரு | ஏன் |
| --- | --- | --- |
| 1 | Folder-ல `git init` | History-ஐ track பண்ண ஆரம்பிக்க |
| 2 | `.venv/`, `.env` இருக்குற `.gitignore` உருவாக்குறாரு | Environment-ஐயும் அவரோட API key-யையும் Git-ல இருந்து விலக்கி வைக்க |
| 3 | Commit: "Add expense tracker with category totals" | தெளிவான, அர்த்தமுள்ள ஒரு step |
| 4 | Commit: "Handle missing amounts in expense CSV" | தனியான ரெண்டாவது improvement |
| 5 | Commit: "Add README with usage examples" | வர்றவங்களுக்கு project-ஐ விளக்க |
| 6 | புது public repository-க்கு `git push` | Share பண்ண ஒரு link |

அவரோட README-ல ஒரு வரி summary, ஒவ்வொரு script-ஐயும் எப்படி run பண்றது, output-ஓட ஒரு sample இருக்கு.

**ஒரு தப்பு, undo ஆச்சு.** ஒரு வாரம் கழிச்சு ஒரு feature சேர்க்கும்போது expense tracker-ஐ உடைச்சுடுறாரு. `git diff` எந்த வரிகளை மாத்துனாருன்னு சரியா காட்டுது. `git restore expenses.py` கடைசியா commit பண்ண version-ஐ ஒரு வினாடியில திரும்ப கொண்டு வருது; அவர் feature-ஐ இன்னும் கவனமா மறுபடி try பண்றாரு.

**Payoff.** அடுத்த மாசம் ஒரு interview-ல, panel அவரோட repository-ஐ திறந்து "Handle missing amounts in expense CSV" commit பத்தி கேக்குறாங்க. Bug என்ன, எப்படி கண்டுபிடிச்சாரு, எப்படி fix பண்ணாருன்னு explain பண்றாரு. Interview-ல அதுதான் சிறந்த பகுதி.

## பொதுவா பண்ற தப்புகள்

- **கடைசியில ஒரே பெரிய commit.** போற வழியிலேயே சின்ன, அர்த்தமுள்ள steps-ஆ commit பண்ணுங்க.
- **"update" மாதிரி messages.** என்ன மாறுச்சுன்னு சொல்லுங்க.
- **Secrets-ஐ commit பண்றது.** Keys-ஐ `.env`-ல வைங்க, முதல் commit-க்கு முன்னாடியே அதை `.gitignore`-ல list பண்ணுங்க, எப்பவாவது push ஆன எந்த key-யையும் revoke பண்ணுங்க.
- **Virtual environments, caches-ஐ commit பண்றது.** அதை ignore பண்ணுங்க.
- **README இல்லாம இருக்கிறது.** வர்றவங்களுக்கு project என்ன பண்ணுது, எப்படி run பண்றதுன்னு தெரியாது.
- **`git status` இல்லாம வேலை செய்றது.** அடிக்கடி check பண்ணுங்க; நீங்க எங்க இருக்கீங்கன்னு அது சரியா சொல்லும்.

## Practice பண்ணுங்க

கீழே link பண்ணியிருக்குற MIT Missing Semester-ஓட shell, version control lectures-ஐ பாருங்க.

இந்த lesson-ஓட check ஒரு சின்ன project:

1. உங்க சொந்த Python exercises-க்கு ஒரு repository **உருவாக்குங்க**, முதல் commit-க்கு முன்னாடியே `.gitignore`-ஓட.
2. குறைஞ்சது மூணு அர்த்தமுள்ள steps-ஐ, ஒவ்வொண்ணும் தெளிவான message-ஓட **commit பண்ணுங்க**.
3. ஒவ்வொரு script-உம் என்ன பண்ணும், எப்படி run பண்றதுன்னு சொல்ற ஒரு README **எழுதுங்க**.
4. அதை GitHub-க்கு **push பண்ணி**, repository link-ஐ submit பண்ணுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** ஒரு repository உருவாக்க, தெளிவான messages-ஓட changes-ஐ commit பண்ண, GitHub-க்கு push பண்ண, Git-ல ஒரு தப்பை undo பண்ண முடியும்.
