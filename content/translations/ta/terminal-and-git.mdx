## இது என்ன

கிட்டத்தட்ட எல்லா software வேலைக்கும் அடியில ரெண்டு tools இருக்கு:

- **Terminal** (shell அல்லது command line-னும் சொல்லுவாங்க) ஒரு window, அதுல click பண்றதுக்கு பதிலா commands type பண்ணுவீங்க. அதுல இருந்தே folders-க்கு நடுவுல நகரலாம், programs run பண்ணலாம், packages install பண்ணலாம், Git மாதிரி tools use பண்ணலாம்.
- **Git** ஒரு version control system. அது உங்க project-ஓட snapshots-ஐ record பண்ணும், அதுக்கு **commits**-னு பேர், அதனால என்ன மாறுச்சுன்னு பார்க்கலாம், தப்புகளை undo பண்ணலாம், code-ஐ share பண்ணலாம். **GitHub** ஒரு website, Git repositories-ஓட copies-ஐ online-ல store பண்ணும், அதனால மத்தவங்க அவற்றை பார்க்கலாம், உங்க கூட வேலை செய்யலாம். GitHub இல்லாமலும் Git வேலை செய்யும்; உங்க history-ஐ அனுப்ப GitHub ஒரு இடம், அவ்வளவு தான்.

Git கிட்டத்தட்ட எல்லா இடத்துலயும் இருக்கு: Stack Overflow-ஓட 2022 developer survey-ல 93% developers அதை use பண்றதா சொன்னாங்க. Course material, take-home tasks, உங்க முதல் team-ஓட code எல்லாமே கிட்டத்தட்ட எப்பவுமே ஒரு Git repository-ஆ தான் வரும்.

Git-ஐ ஈஸி ஆக்குற ஒரே idea: உங்க changes நாலு இடங்கள்ல ஏதோ ஒண்ணுல இருக்கும், ஒவ்வொரு command-உம் அவற்றை ஒரு இடத்துல இருந்து அடுத்த இடத்துக்கு நகர்த்தும்.

```flow
title: உங்க changes எங்க இருக்கு
dir: LR
Working folder | நீங்க edit பண்ற files -[git add]-> Staging area | அடுத்த commit-ல என்ன இருக்கும்
Staging area -[git commit]-> Local repository | உங்க commits-ஓட history
Local repository -[git push]-> GitHub | online-ல இருக்குற shared copy
GitHub -[git clone, git pull]-> Working folder
```

Git-ல வர்ற பெரும்பாலான குழப்பம், ஒரு change எந்த இடத்துல இருக்குன்னு தெரியாததால தான். `git status` அதை சொல்லும், அதனால மத்த ஒவ்வொரு Git command-க்கும் முன்னாடியும் பின்னாடியும் அதை run பண்ணுங்க.

இந்த lesson, Nagpur-ல Python கத்துக்கிட்டிருக்குற Ravi-ஐ follow பண்ணுது; அவர் exercise scripts இருக்குற ஒரு folder-ஐ public repository-ஆ மாத்துறாரு. இதோட check உங்க சொந்த சின்ன project, கடைசில இருக்குற rubric வச்சு mark பண்ணப்படும்.

## இது எப்படி work ஆகுது

### Terminal basics

**முதல்ல உங்க terminal-ஐ தேர்ந்தெடுங்க.** Mac-ல Terminal app-ஐ திறங்க. Linux-ல எந்த terminal-உம் வேலை செய்யும். Windows-ல Git for Windows-ஐ install பண்ணுங்க, அது கூட **Git Bash** வரும்; இந்த course-க்கு Git Bash (அல்லது WSL, Windows-க்குள்ள Linux) use பண்ணுங்க, அப்போ ஒவ்வொரு command-உம் எழுதியிருக்குற மாதிரியே வேலை செய்யும். PowerShell-உம் `pwd`, `ls`, `cd`-ஐ ஏத்துக்கும்; பழைய Command Prompt வேற commands use பண்ணும், உதாரணமா `ls`-க்கு பதிலா `dir`.

| Command | இது என்ன பண்ணும் |
| --- | --- |
| `pwd` | நீங்க இருக்குற folder-ஐ print பண்ணும் |
| `ls` | இந்த folder-ல இருக்குற files-ஐ list பண்ணும் |
| `ls -a` | Hidden files-ஐயும் list பண்ணும்; அவற்றோட பேர் ஒரு dot-ல ஆரம்பிக்கும், உதாரணமா `.gitignore`, `.env` |
| `cd python-practice` | ஒரு folder-க்குள்ள போகும் |
| `cd ..` | ஒரு folder மேல போகும் |
| `cd ~` | உங்க home folder-க்கு போகும் |
| `mkdir python-practice` | ஒரு புது folder உருவாக்கும் |
| `python expenses.py` | ஒரு program-ஐ run பண்ணும் (சில Mac, Linux machines-ல `python3`) |

**Paths.** ஒரு absolute path disk-ஓட உச்சியில இருந்து ஆரம்பிக்கும், உதாரணமா `/home/ravi/python-practice` (Git Bash-ல C drive-னா `/c`, அதனால ஒரு Windows home folder `/c/Users/Ravi` மாதிரி இருக்கும்). ஒரு relative path நீங்க இப்போ இருக்குற இடத்துல இருந்து ஆரம்பிக்கும்: அந்த folder இப்போ இருக்குற folder-க்குள்ள இருந்தா மட்டும் தான் `python-practice` வேலை செய்யும். "No such file or directory"-னு வந்தா, கிட்டத்தட்ட எப்பவுமே நீங்க தப்பான folder-ல இருக்கீங்க: வேற எதுக்கும் முன்னாடி `pwd`, `ls` run பண்ணுங்க. Folder பேர்கள்ல spaces வேண்டாம்; ஏதாவது ஒண்ணுல இருந்தா, `cd "My Projects"` மாதிரி quotes-க்குள்ள வைங்க.

**Environment variables**-னா terminal தான் start பண்ற ஒவ்வொரு program-க்கும் அனுப்புற, பேர் இருக்குற values. `echo $HOME` ஒண்ணை print பண்ணும். `export CITY=Nagpur` ஒண்ணை set பண்ணும், ஆனா அந்த terminal window-க்கு மட்டும்; அதை close பண்ணா value போயிடும். அதனால projects API keys-ஐ program படிக்கிற ஒரு `.env` file-ல வச்சுக்கும், Git-க்கு ஒருபோதும் போகக் கூடாத file சரியா அது தான்.

மூணு keys மணிக்கணக்கான நேரத்தை மிச்சப்படுத்தும்: **up arrow** முன்னாடி run பண்ண commands-ஐ திரும்பக் கொண்டு வரும், **Tab** file, folder பேர்களை complete பண்ணும் (typos-ஐயும் தவிர்க்கும்), **Ctrl+C** run ஆகிட்டிருக்குற அல்லது stuck ஆன ஒரு program-ஐ நிறுத்தும்.

### Git-ஐ ஒரு தடவை set up பண்ணுங்க

Git install ஆகியிருக்கான்னு check பண்ணுங்க, அப்புறம் நீங்க யாருன்னு அதுக்கு சொல்லுங்க:

```bash
git --version
git config --global user.name "Ravi Deshmukh"
git config --global user.email "12345678+ravi-d@users.noreply.github.com"
git config --global init.defaultBranch main
```

உங்க பேரும் email-உம் ஒவ்வொரு commit-லயும் பதிவாகும், நீங்க push பண்ணதும் யார் வேணாலும் அவற்றை படிக்கலாம். உங்க personal email public ஆகக் கூடாதுன்னா, GitHub உங்களுக்கு ஒரு private "noreply" address குடுக்கும்: GitHub-ஓட email settings-ல "Keep my email address private"-ஐ tick பண்ணி, அது காட்டுற address-ஐ copy பண்ணுங்க. மேல இருக்குறது அதோட வடிவத்துக்கு ஒரு உதாரணம் மட்டும் தான்.

கடைசி line முதல் branch-க்கு `main`-னு பேர் வைக்கும், GitHub use பண்ற பேர் அது தான். அது இல்லன்னா, சில Git versions முதல் branch-ஐ `master`-னு கூப்பிட்டு அதைப் பத்தி ஒரு நீளமான hint-ஐ print பண்ணும்.

### தினசரி loop: status, add, commit

```bash
cd python-practice
git init                  # once per project: start tracking this folder
git status                # which files are new, changed or staged?
git add expenses.py       # stage this file for the next commit
git commit -m "Add expense tracker with category totals"
git log --oneline         # one line per commit, newest first
```

`git add` changes-ஐ **staging area**-ல வைக்கும், `git commit` staged ஆன எல்லாத்தையும் ஒரே snapshot-ஆ save பண்ணும். ஒரு commit-ல ஒரே ஒரு idea இருக்கணும்ங்குறதுக்காக தான் ரெண்டு steps இருக்கு. நீங்க ஒரு bug-ஐ fix பண்ணிட்டு ஒரு புது feature-ஐயும் ஆரம்பிச்சிருந்தா, bug fix-ஐ மட்டும் stage பண்ணி commit பண்ணுங்க, பாதி முடிஞ்ச feature-ஐ அப்புறம் பார்த்துக்கலாம்.

`git add .` folder-ல Git-கிட்ட ignore பண்ணச் சொல்லாத எல்லாத்தையும் stage பண்ணும். அது வேகமானது, ஆனா secrets-உம் குப்பையும் commit ஆகுறதும் இப்படி தான், அதனால முதல்ல `git status` run பண்ணி list-ஐ படிங்க. நீங்க இன்னும் stage பண்ணாத changes-ஐ `git diff` காட்டும்; commit ஆகப் போறதை `git diff --staged` காட்டும்.

### உதவுற commit messages

| பலவீனமானது | வலுவானது |
| --- | --- |
| "update" | "Add expense totals by category" |
| "fixed stuff" | "Handle missing amounts in expense CSV" |
| "final" | "Add README with usage examples" |

முக்கியமான rules:

- **ஒரு verb-ல, ஒரு instruction மாதிரி ஆரம்பிங்க:** "Add", "Fix", "Handle", "Remove". ஒரு useful test: message, "If applied, this commit will..." ங்குற sentence-ஐ முடிக்கணும்.
- **ஒரு commit-க்கு ஒரு change.** அதை விவரிக்க "and" தேவைப்பட்டா, அது அநேகமா ரெண்டு commits.
- **முதல் line-ஐ சின்னதா வைங்க.** ஒரு common convention சுமார் 50 characters. ஏன்னு விளக்கணும்னா, ஒரு blank line விட்டு அதுக்குக் கீழ இன்னும் எழுதுங்க.
- **Code run ஆகும்போது commit பண்ணுங்க.** அப்போ உங்க history-ல இருக்குற ஒவ்வொரு commit-உம் திரும்பப் போக ஒரு safe point.

### Secrets-ஐயும் குப்பையையும் வெளிய வைங்க: .gitignore

Project-ஓட top folder-ல இருக்குற `.gitignore`-ங்குற ஒரு file, Git எதை ஒருபோதும் track பண்ணக் கூடாதுன்னு list பண்ணும்:

```text
.venv/
__pycache__/
.env
```

`.venv/` உங்க virtual environment (பெரிசு, `requirements.txt`-ல இருந்து திரும்ப build பண்ணலாம்), `__pycache__/` Python-ஓட cache, `.env`-ல keys இருக்கு. எல்லாத்தையும் விட முக்கியமானது `.env` line தான்.

Beginners miss பண்ற rule: **`.gitignore` Git இன்னும் track பண்ணாத files-ஐ மட்டும் தான் பாதிக்கும்.** `.env` ஏற்கனவே ஒரு commit-ல இருந்தா, அப்புறம் அதை `.gitignore`-ல சேர்த்தா எதுவும் மாறாது, `git status` அதை காட்டிட்டே இருக்கும். இப்படி track பண்றதை நிறுத்துங்க:

```bash
git rm --cached .env      # stop tracking; the file stays on your disk
git commit -m "Stop tracking .env"
```

இது future commits-ல இருந்து மட்டும் தான் அதை நீக்கும். பழைய commit-ல இன்னும் key இருக்கு, repository-ஐ பார்க்க முடியுற யார் வேணாலும் அதை படிக்கலாம். அதனால key leak ஆயிடுச்சுன்னே எடுத்துக்கோங்க: provider-ஓட website-ல அதை revoke பண்ணி புது key ஒண்ணு உருவாக்குங்க. File-ஐ delete பண்றது மட்டும் போதாது.

GitHub ஒரு safety net சேர்க்குது. Public repositories-ல personal accounts-க்கு default-ஆ **push protection**-ஐ on பண்ணும்; அது தனக்கு தெரிஞ்ச format-ல ஒரு secret இருக்குற push-ஐ block பண்ணும், உதாரணமா நிறைய cloud, AI provider keys. எல்லா secret-ஐயும் அதால கண்டுபிடிக்க முடியாது, உதாரணமா நீங்களே உருவாக்குன ஒரு password, அதனால உண்மையான பாதுகாப்பு உங்க முதல் `git add`-க்கு முன்னாடியே `.gitignore`-ஐ உருவாக்குறது தான்.

### Commit ஆகுறதுக்கு முன்னாடியே undo பண்ணுங்க

| நிலைமை | Command |
| --- | --- |
| என்ன மாறியிருக்கு, இன்னும் stage ஆகலைன்னு பார்க்க | `git diff` |
| அடுத்த commit-க்கு என்ன stage ஆகியிருக்குன்னு பார்க்க | `git diff --staged` |
| ஒரு file-ல பண்ண உங்க edits-ஐ தூக்கிப் போட | `git restore expenses.py` |
| Edits-ஐ வச்சுக்கிட்டே ஒரு file-ஐ unstage பண்ண | `git restore --staged expenses.py` |
| ஒரு பழைய commit-ஐ பார்க்க | `git log --oneline`, அப்புறம் `git show a7d7b78` |

`git restore expenses.py`-ல கவனமா இருங்க: அது கடைசியா commit ஆன version-ஐ திரும்பக் கொண்டு வரும், நீங்க தூக்கிப் போடுற edits நிரந்தரமா போயிடும், ஏன்னா Git அவற்றை save பண்ணவே இல்ல. ஒரு commit-ஐ undo பண்றது, ஏற்கனவே push பண்ணதையும் சேர்த்து, Git-ல விஷயங்களை undo பண்றது பத்தின lesson-ஓட topic.

### GitHub-க்கு push பண்ணுங்க, வேலை செய்யுற sign-in-ஓட

GitHub-ல **New repository**-ஐ click பண்ணி, அதுக்கு `python-practice`-னு பேர் வைங்க, README, .gitignore, licence options-ஐ off-ஆவே விடுங்க, அப்போ repository காலியா ஆரம்பிக்கும். அப்புறம் உங்க folder-ஐ அதோட connect பண்ணி push பண்ணுங்க:

```bash
git remote add origin https://github.com/ravi-d/python-practice.git
git push -u origin main
```

`origin`-னா உங்க GitHub copy-க்கு வழக்கமா வைக்கிற செல்லப் பேர். `-u` உங்க `main`-ஐ அதோட link பண்ணும், அதனால அதுக்கப்புறம் வெறும் `git push`, `git pull` வேலை செய்யும்.

**பெரும்பாலான beginners மாட்டிக்கிறது sign in பண்ற இடத்துல தான்.** 13 August 2021-ல இருந்து, Git commands-க்கு உங்க account password-ஐ GitHub ஏத்துக்கறதில்ல. Terminal username, password கேட்டு நீங்க உங்க GitHub password-ஐ type பண்ணா, push fail ஆகும். அதுக்கு பதிலா இதுல ஒண்ணை தேர்ந்தெடுங்க:

| உங்க setup | என்ன பண்ணணும் |
| --- | --- |
| Git for Windows இருக்குற Windows | Git Credential Manager அது கூடவே வரும். முதல் push-ல ஒரு sign-in window திறக்கும்; browser-ஐ தேர்ந்தெடுத்து GitHub-ல sign in பண்ணுங்க, அது உங்களை ஞாபகம் வச்சுக்கும். |
| Mac அல்லது Linux | GitHub CLI-ஐ install பண்ணி `gh auth login` run பண்ணுங்க. GitHub.com, HTTPS-ஐ தேர்ந்தெடுங்க, உங்க GitHub credentials வச்சு Git-ஐ authenticate பண்ணவான்னு கேட்டா yes சொல்லுங்க, browser-ல முடிங்க. |
| வேற எதுவானாலும் | இந்த repository-க்கு Contents-ல read, write access இருக்குற ஒரு fine-grained personal access token-ஐ உருவாக்குங்க (GitHub Settings, அப்புறம் Developer settings), terminal password கேக்குற இடத்துல அதை paste பண்ணுங்க. அதை ஒரு password மாதிரியே பாதுகாப்பா வைங்க. |

SSH keys இன்னொரு option; Linux, shell, SSH பத்தின lesson அதை cover பண்ணும்.

**இன்னொரு trap.** GitHub-ல "Add a README"-ஐ tick பண்ணியிருந்தா, உங்க முதல் push refuse ஆகும், ஏன்னா உங்க computer-ல இல்லாத ஒரு commit GitHub-ல இருக்கு:

```text
 ! [rejected]        main -> main (fetch first)
error: failed to push some refs to 'https://github.com/ravi-d/python-practice.git'
```

ஒரு புது repository-க்கு எல்லாத்தையும் விட simple-ஆன fix: GitHub-ல அதை delete பண்ணுங்க (அதோட Settings page, கடைசில), திரும்ப காலியா உருவாக்கி push பண்ணுங்க. முதல்ல `git pull` run பண்றது உதவாது: Git "refusing to merge unrelated histories"-னு சொல்லி நின்னுடும்.

### மத்தவங்க கூட வேலை செய்யுறது: ஒரு முதல் பார்வை

Team work-உம் take-home tasks-உம் தலைகீழா ஆரம்பிக்கும்: repository ஏற்கனவே GitHub-ல இருக்கும்.

```bash
git clone https://github.com/example-team/expense-app.git
cd expense-app
git pull                          # bring in teammates' new commits
git switch -c add-monthly-report  # a new branch for your change
# edit files, then git add and git commit
git push -u origin add-monthly-report
```

ஒரு **branch**-னா commits-ஓட ஒரு தனி line, அதனால உங்க change ready ஆகுற வரைக்கும் `main`-ஐ தொடாது. Branch-ஐ push பண்ணதுக்கு அப்புறம், GitHub-ல ஒரு **pull request**-ஐ open பண்ணுவீங்க: உங்க changes-ஐ காட்டுற ஒரு page, அதனால அவை `main`-க்குள்ள merge ஆகுறதுக்கு முன்னாடி ஒரு teammate அவற்றை review பண்ணலாம்.

நீங்களும் ஒரு teammate-உம் அதே lines-ஐ மாத்தினா, உங்க ரெண்டு பேருக்கும் நடுவுல Git-ஆல தேர்ந்தெடுக்க முடியாது. அது ஒரு **merge conflict**-ஓட நின்னு file-ஐ mark பண்ணும்:

```text
<<<<<<< HEAD
print(sorted(totals.items()))
=======
print("Totals:", totals)
>>>>>>> 3c1dea94b5893015fb3b508cd578f48b684bd511
```

`=======`-க்கு மேல இருக்குறது உங்க version; கீழ இருக்குறது வர்ற version. நீங்க விரும்புற version-க்கு file-ஐ edit பண்ணுங்க, மூணு marker lines-ஐ delete பண்ணுங்க, அப்புறம் file-ஐ `git add` பண்ணி, Git-ஓட message-ஐ வச்சுக்க `git commit --no-edit` run பண்ணுங்க. `git pull` "Need to specify how to reconcile divergent branches"-னு சொல்லி நின்னா, நீங்க ரெண்டு பேருமே commits பண்ணியிருக்கீங்க; `git pull --no-rebase --no-edit` அவற்றை merge பண்ணும். Branches பத்தியும் team-ஓட Git use பண்றது பத்தியும் இருக்குற lessons இன்னும் ஆழமா போகும்.

## ஒரு worked example

Ravi-கிட்ட ஒரு expense tracker, ஒரு marks calculator, `.env`-ல இருந்து API key-ஐ படிக்கிற ஒரு weather fetcher இருக்குற ஒரு folder இருக்கு. இதோ அவரோட உண்மையான session, output-ஐ சுருக்கி. உங்க commit hashes (`81d3fe3` மாதிரி short codes) வேற மாதிரி இருக்கும்.

**1. Track பண்ண ஆரம்பிங்க, எதையும் add பண்றதுக்கு முன்னாடி பாருங்க.**

```text
$ cd ~/python-practice
$ git init
Initialized empty Git repository in /home/ravi/python-practice/.git/
$ git status
On branch main

No commits yet

Untracked files:
	.env
	.venv/
	__pycache__/
	expenses.py
	marks.py
	weather.py
```

ஆபத்து `.env` line தான்: இப்போ ஒரு `git add .` பண்ணா அவரோட key commit ஆயிடும்.

**2. `.gitignore`-ஐ உருவாக்கி திரும்ப check பண்ணுங்க.**

```text
$ printf '.venv/\n__pycache__/\n.env\n' > .gitignore
$ git status --short
?? .gitignore
?? expenses.py
?? marks.py
?? weather.py
```

`??`-னா untracked. `.env`, `.venv/`, `__pycache__/` list-ல இருந்து காணாம போயிடுச்சு, ignore file வேலை செய்யுதுங்குறதுக்கு அது தான் proof.

**3. முதல் commit: ஒரு script, கூட ignore file.**

```text
$ git add .gitignore expenses.py
$ git commit -m "Add expense tracker with category totals"
[main (root-commit) 81d3fe3] Add expense tracker with category totals
 2 files changed, 9 insertions(+)
```

**4. ஒரு bug fix, தனி commit-ஆ.** அவரோட CSV-ல இருந்த ஒரு blank amount tracker-ஐ crash பண்ணிடுச்சு. அவர் அந்த line-ஐ fix பண்ணிட்டு, சரியா என்ன மாத்தினாருன்னு check பண்றாரு:

```text
$ git diff
-        totals[row["category"]] = totals.get(row["category"], 0) + float(row["amount"])
+        totals[row["category"]] = totals.get(row["category"], 0) + float(row["amount"] or 0)
$ git add expenses.py
$ git commit -m "Handle missing amounts in expense CSV"
```

**5. மத்த scripts-உம் ஒரு README-உம், ஒவ்வொண்ணுக்கும் ஒரு commit.** அவரோட README:

```markdown
# Python practice
Small scripts from my first month of learning Python.

- expenses.py: reads expenses.csv and prints total spending per category
- marks.py: turns a list of marks into grades
- weather.py: prints today's weather for a city; needs WEATHER_API_KEY in a .env file

Run any script with: python expenses.py
```

```text
$ git log --oneline
e2c538a Add README with usage examples
cf4559b Add weather fetcher that reads its key from .env
812980e Add marks calculator with grade bands
a7d7b78 Handle missing amounts in expense CSV
81d3fe3 Add expense tracker with category totals
```

**6. Push.** அவர் GitHub-ல ஒரு காலியான repository-ஐ உருவாக்கி, அவரோட Ubuntu laptop-ல ஒரு தடவை `gh auth login` run பண்றாரு, அப்புறம்:

```text
$ git remote add origin https://github.com/ravi-d/python-practice.git
$ git push -u origin main
To https://github.com/ravi-d/python-practice.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.
```

**7. ஒரு தப்பு, undo பண்ணியாச்சு.** ஒரு வாரம் கழிச்சு tracker-ஐ crash பண்ற ஒரு line-ஐ அவர் சேர்க்குறாரு. எதையும் commit பண்றதுக்கு முன்னாடி:

```text
$ git status --short
 M expenses.py
$ git diff
+print(totals["food"])
$ git restore expenses.py
$ git status --short
```

`M`-னா modified. `git restore`-க்கு அப்புறம் `git status` எதையும் print பண்ணாது: file மறுபடியும் அவரோட கடைசி commit கூட match ஆகுது.

**8. கடைசி check.** `.env`-ஐ எப்பவாவது தொட்ட ஒவ்வொரு commit-ஐயும் `git log --all --oneline -- .env` list பண்ணும். Ravi-க்கு அது எதையும் print பண்ணல, அதனால அவரோட key அவரோட history-ல ஒருபோதும் இருந்ததே இல்ல.

அவரோட repository-ஐ திறக்குற யாரும், ஒரு reviewer-ஓ ஒரு interviewer-ஓ, இப்போ ஒரு நிமிஷத்துல மூணு விஷயங்களை பார்ப்பாங்க: ஒவ்வொரு script-ஐயும் எப்படி run பண்றதுன்னு சொல்ற ஒரு README, சின்ன, தெளிவா பேர் வச்ச steps-ஓட ஒரு history, `.env`, `.venv/` அல்லது cache files எதுவும் இல்லாதது.

## பொதுவா பண்ற தப்புகள்

- **தப்பான folder-ல Git run பண்றது.** "fatal: not a git repository"-னா நீங்க project-க்கு வெளிய இருக்கீங்க; உங்க home folder-ல `git init` run பண்ணா, `git status` உங்ககிட்ட இருக்குற ஒவ்வொரு file-ஐயும் list பண்ணும். முதல்ல `pwd` run பண்ணுங்க.
- **Push prompt-ல உங்க GitHub password-ஐ type பண்றது.** அது reject ஆகும். Git Credential Manager, `gh auth login` அல்லது ஒரு personal access token use பண்ணுங்க.
- **`.env` commit ஆனதுக்கு அப்புறம் `.gitignore`-ஐ சேர்க்குறது.** Track ஆகுற files மேல அதுக்கு எந்த effect-உம் இல்ல. `git rm --cached .env` use பண்ணி, commit பண்ணி, key-ஐ மாத்துங்க.
- **`git status`-ஐ படிக்காம `git add .`.** Keys, `.venv/`, பெரிய data files commit ஆகுறது இப்படி தான்.
- **ஒரு புது GitHub repository-ல "Add a README"-ஐ tick பண்ணிட்டு** அப்புறம் ஏற்கனவே இருக்குற ஒரு folder-ஐ push பண்றது. Push refuse ஆகும். புது repositories-ஐ காலியா உருவாக்குங்க.
- **ஒரே ஒரு பெரிய commit, அல்லது "update" மாதிரி messages.** முடிஞ்ச ஒவ்வொரு step-ஐயும் commit பண்ணுங்க, அது என்ன மாத்துதுன்னு சொல்லுங்க.
- **வச்சுக்கணும்னு நினைச்ச edits மேல `git restore`.** அந்த edits-ஐ திரும்ப எடுக்க முடியாது. முதல்ல `git diff`-ஐ check பண்ணுங்க.

அப்புறம் இந்த lesson-ஓட check-ஐ பண்ணுங்க: உங்க சொந்த Python exercises வச்சு Ravi-ஓட steps-ஐ follow பண்ணுங்க, ஒரு `.gitignore`-ல ஆரம்பிச்சு, repository-ஐ GitHub-க்கு push பண்ணுங்க. Link-ஐ submit பண்றதுக்கு முன்னாடி, நீங்களே mark பண்ணுங்க:

| Check | எப்போ pass ஆகும் |
| --- | --- |
| Secrets-உம் குப்பையும் இல்ல | `git log --all --oneline -- .env` எதையும் print பண்ணாது, GitHub-ஓட file list-ல `.venv/` அல்லது `__pycache__/` இல்ல |
| History | குறைஞ்சது மூணு commits, ஒவ்வொண்ணும் ஒரு change, ஒவ்வொரு message-உம் ஒரு verb-ல ஆரம்பிச்சு என்ன மாறுச்சுன்னு சொல்லுது |
