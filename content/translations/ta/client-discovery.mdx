## இது என்ன

**Discovery** ஒரு engagement-ஓட முதல் phase; பொதுவா ஒண்ணுல இருந்து மூணு வாரம், எதுவும் build பண்றதுக்கு முன்னாடி. இதோட இலக்கு பொதுவான புரிதல்:

- எந்த பிரச்சனை முக்கியம், யாருக்கு, எவ்வளவு?
- இன்னைக்கு வேலை எப்படி நடக்குது, step by step?
- நேரமும் செலவும் தப்புகளும் உண்மையில எங்க போகுது?
- என்ன data இருக்கு, எங்க, எந்த நிலைமையில?
- என்ன constraints இருக்கு: rules, systems, budgets, மக்கள்?
- AI தான் சரியான tool-ஆ, இல்ல ஒரு form, ஒரு report, ஒரு process மாற்றம் போதுமா?

Output சின்னதாவும் உறுதியாவும் இருக்கும்: ஒரு process map, numbers-ஓட ஒரு problem statement, value-வும் feasibility-யும் வச்சு rank பண்ணப்பட்ட use cases-ஓட shortlist, risks-உம் இன்னும் தீராத கேள்விகளும்.

```flow
title: Discovery, ரெண்டு வாரத்துல
Week 1: interviews-உம் shadowing-உம் | past tense-ல 5-10 interviews, அரை நாள் shadowing -> Process map | trigger, steps, outcome; யார், system, நிமிஷங்கள், failure points, judgement அல்லது rote
Process map -> Week 2: தோராயமான numbers | volume, ஒரு item-க்கு நேரம், rework -> Use cases-ஐ score பண்ணுங்க
Use cases-ஐ score பண்ணுங்க -> Play-back: "நாங்க கேட்டது இது" -> Client திருத்துறாங்க -> ஒத்துக்கிட்ட முதல் use case + baseline
```

இந்த lesson, Chennai-ல இருக்குற ஒரு non-banking lender-ஐ பின்தொடருது; அவங்க ஒரு customer chatbot கேட்டாங்க, ஆனா அவங்களுக்கு வேற ஒண்ணு தேவைப்பட்டுச்சு.

## இது எப்படி work ஆகுது

**வேலை செய்றவங்ககிட்ட பேசுங்க.** Leaders process-ஐ design பண்ணப்பட்ட மாதிரி சொல்வாங்க; front-line staff அது இருக்குற மாதிரி சொல்வாங்க. ரெண்டு பேரையும் interview பண்ணுங்க. பல roles-ல இருந்து, 30-ல இருந்து 45 நிமிஷம் நீளமா, அஞ்சுல இருந்து பத்து உரையாடல்களை இலக்கா வைங்க.

**கடந்த காலத்தை பத்தி கேளுங்க, எதிர்காலத்தை பத்தின அபிப்ராயங்களை இல்ல.** "இந்த AI assistant உங்களுக்கு உதவுமா?"-வை விட "நீங்க கடைசியா process பண்ண claim-ஐ பத்தி சொல்லுங்க" நல்லது. தாங்க எதை use பண்ணுவாங்கன்னு கணிக்கிறதுல மக்கள் மோசம், தாங்க செஞ்சதை விவரிக்கிறதுல நல்லவங்க.

**வேலையை பாருங்க.** ஒருத்தர் பக்கத்துல ஒரு மணி நேரம் உக்காருங்க. அவங்க திறக்குற ஒவ்வொரு system, ஒவ்வொரு copy-paste, சக ஊழியர்கிட்ட கேக்குற ஒவ்வொரு கேள்வி, ஒவ்வொரு காத்திருப்பையும் note பண்ணுங்க. Interviews தவறவிடுறதை shadowing கண்டுபிடிக்கும்.

**Process-ஐ map பண்ணுங்க.** Trigger-ல இருந்து outcome வரை steps-ஐ வரைங்க; ஒவ்வொண்ணையும் யார் பண்றாங்க, என்ன systems, எவ்வளவு நேரம், failure points எங்கன்னு சேர்த்து. எங்க judgement தேவை, எங்க வெறும் rote-ன்னு mark பண்ணுங்க.

**தோராயமா அளங்க.** மாசத்துக்கு volume, ஒரு item-க்கு நேரம், தப்பு அல்லது rework rates, backlog. முடிஞ்சா உண்மையான data கேளுங்க; staff-ஓட மதிப்பீடுகள் ஒரு ஆரம்பம்.

**Use cases-ஐ score பண்ணுங்க.** ஒவ்வொரு candidate-க்கும்: value (மிச்சமான மணி நேரம் அல்லது தப்புகள், revenue), feasibility (data கிடைக்குதா, இந்த வகை வேலையில AI நல்லா இருக்கா, தப்புகளை தாங்குற அளவு), risk (regulatory, reputational), effort. அடிக்கடி நடக்குற, வலி தர்ற, data நிறைய இருக்குற, output-ஐ ஒரு ஆள் check பண்ணக்கூடிய வேலைகளுக்கு முன்னுரிமை குடுங்க.

**Play it back.** நீங்க கேட்டதை client-ஓட வார்த்தைகள்லயே அவங்ககிட்ட present பண்ணி, உங்களை அவங்க திருத்த விடுங்க. நம்பிக்கை உருவாகுறது இங்க தான்.

| "உங்களுக்கு என்ன features வேணும்?" | "போன வாரம் ஒரு system-ல இருந்து இன்னொண்ணுக்கு எதை copy பண்ணீங்க?" |
| "தப்புகள் நடக்குதா?" | "கடைசியா எப்போ ஏதாவது திருப்பி அனுப்பப்பட்டுச்சு, ஏன்?" |

**Play-back-ஐ எழுதுறது.** ஒரு page: client-ஓட வார்த்தைகள்ல பிரச்சனை, process map, முக்கியமான மூணு numbers, காரணங்களோட rank பண்ணப்பட்ட use cases, risks-உம் தீராத கேள்விகளும், baseline-ஓட பரிந்துரைக்கப்பட்ட முதல் step. Meeting-க்கு முன்னாடியே அனுப்புங்க, அப்புறம் அதை படிச்சுக் காட்டி திருத்தங்களை வரவேற்குங்க. Client திருத்துன ஒரு play-back அவங்களுக்குச் சொந்தமானது.

## ஒரு worked example

Chennai-ஐ சேர்ந்த ஒரு non-banking lender "customers-க்கான ஒரு AI chatbot" கேக்குறாங்க. முதல்ல ரெண்டு வார discovery-ஐ நீங்க பரிந்துரைக்கிறீங்க.

Head of operations, ரெண்டு team leads, நாலு credit officers, ரெண்டு collections agents-ஓட interviews, loan-processing team-ஐ அரை நாள் shadow பண்ணது எல்லாம் சேர்த்து காட்டுறது:

- Customer queries-ஐ ஏற்கனவே இருக்குற call centre பெரும்பாலும் நல்லா handle பண்ணுது.
- உண்மையான வலி loan processing-ல: credit officers ஒரு application-க்கு சுமார் 40 நிமிஷம் bank statements, salary slips, bureau reports படிச்சு, figures-ஐ spreadsheet-ல திரும்ப type பண்ணி, ஒரு summary note எழுதுறாங்க. மாசத்துக்கு 6,000 applications-ன்னா, இது கிட்டத்தட்ட 4,000 officer-hours.
- Retype பண்ண figures-ல வர்ற தப்புகளால 7% applications credit committee-ஆல திருப்பி அனுப்பப்படுது.
- Documents PDFs-ஆவும் phone photos-ஆவும் வருது; lender-கிட்ட இறுதி முடிவுகளோட ரெண்டு வருஷ பழைய applications இருக்கு.

உங்க play-back, customer chatbot-ல இல்லாம, document extraction-ஓடயும் ஒரு draft credit summary-ஓடயும் ஆரம்பிக்க பரிந்துரைக்குது; ஒவ்வொரு figure-ஐயும் officer review பண்ணுவாங்க. Baseline 40 நிமிஷம், 7% rework. Head of operations ஒத்துக்குறாங்க, chatbot யோசனை பின்னாடி வர்ற list-க்கு போகுது.

| கண்டுபிடிப்பு | Evidence |
| --- | --- |
| Customer queries ஏற்கனவே நல்லா handle ஆகுது | Call-centre interviews-உம் data-வும் |
| Officers ஒரு application-க்கு சுமார் 40 நிமிஷம் செலவு பண்றாங்க | Shadowing-உம் team-lead மதிப்பீடுகளும் |
| மாசத்துக்கு 6,000 applications, சுமார் 4,000 officer-hours | Operations data |
| 7% applications retyping தப்புகளுக்காக திருப்பி அனுப்பப்படுது | Credit committee records |
| பரிந்துரை | Extraction-ஓடயும் ஒரு draft summary-ஓடயும் ஆரம்பிங்க; chatbot பின்னாடி வர்ற list-க்கு |

## பொதுவா பண்ற தப்புகள்

- **முதல் meeting-லயே solution சொல்றது.** முதல்ல கேளுங்க; evidence கிடைச்சதுக்கு அப்புறம் பரிந்துரைங்க.
- **Managers-ஓட மட்டும் பேசுறது.** காகிதத்துல இருக்குற process-உம் நடைமுறையில இருக்குற process-உம் வேறவேற.
- **கற்பனையான கேள்விகள் கேக்குறது.** கடைசி உண்மையான case-ஐ பத்தி கேளுங்க.
- **Numbers இல்லாம இருக்குறது.** Volume-உம் ஒரு item-க்கு நேரமும் இல்லன்னா, use cases-ஐ rank பண்ணவும், பின்னாடி value-ஐ நிரூபிக்கவும் முடியாது.
- **AI இல்லாத fixes-ஐ புறக்கணிக்குறது.** சில சமயம் ஒரு template அல்லது ஒரு database view தீர்த்துடும். அதை சொல்றது நம்பகத்தன்மையை உருவாக்கும்.

## Practice பண்ணுங்க

GOV.UK-ஓட discovery, user research guides-ஐ படிங்க.

1. நீங்க கவனிக்கக்கூடிய ஒரு process-ஐ தேர்ந்தெடுங்க (ஒரு college admission office, ஒரு கடையோட billing, ஒரு நண்பரோட வேலை). அதை செய்ற ரெண்டு பேரை past-tense கேள்விகளை மட்டும் use பண்ணி interview பண்ணுங்க.
2. Steps, மக்கள், systems, நேரம், failure points-ஓட process map-ஐ வரைங்க.
3. மூணு use cases-ஐ பட்டியல் போட்டு, ஒவ்வொண்ணையும் value, feasibility, risk, effort-க்கு score பண்ணி, ஒரு பக்க play-back-ஐ எழுதுங்க.

**இதை நீங்க முடிச்சுட்டீங்கன்னு எப்போ சொல்லலாம்:** ஒரு process map-ஐயும், ஒவ்வொரு use case-க்கும் குறைஞ்சது ஒரு number இருக்குற rank பண்ணப்பட்ட use-case list-ஐயும் present பண்ணி, முதல்ல இருக்குறது ஏன் முதல்லன்னு explain பண்ண முடியும்போது.
