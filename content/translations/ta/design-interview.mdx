## இது என்ன

நிறைய AI engineering interviews-ல இப்போ ஒரு **design round** இருக்கு. "ஒரு bank-க்கு customer-support assistant-ஐ design பண்ணுங்க", "10 million documents மேல questions-க்கு பதில் சொல்ற system-ஐ design பண்ணுங்க", "travel book பண்ற ஒரு agent-ஐ எப்படி build பண்ணுவீங்க?"-ன்னு கேப்பாங்க. 30 முதல் 45 நிமிஷம், ஒரு whiteboard அல்லது shared document கிடைக்கும், interviewer நடுவுல "what if...?"-ன்னு குறுக்கிடுவாரு.

அவங்க test பண்றது ஒரு tool பத்தின அறிவை விட, structured thinking, நல்ல trade-offs, production awareness.

| நிமிஷங்கள் | Step | என்ன cover பண்றீங்க |
|---|---|---|
| 0-5 | Clarify | Users, scale, latency, cost, languages, data rules, success |
| 5-10 | High level | Boxes, arrows: channel, API, routing, tools அல்லது RAG, model, reply |
| 10-28 | Deep dives | இந்த problem-க்கு அதிகம் முக்கியமான 2-3 பகுதிகள் |
| 28-31 | Failures | Hallucination, injection, outage, cost, privacy |
| 31-34 | Evals and ops | Test set, metrics, launch bar, monitoring, rollout |
| 34-35 | Trade-offs | இன்னும் time இருந்தா, 10x scale-ல |

Interviewer "what if...?"-ன்னு கேட்டா, அதை ஒரு புது requirement-ஆ எடுத்து design-ஐ adapt பண்ணுங்க.

"தமிழ்நாடு மின்சார வாரியத்துக்கு Tamil, English-ல ஒரு WhatsApp assistant design பண்ணுங்க"-ங்குற கேள்விக்கு ஒரு strong answer எப்படி இருக்கும்னு இந்த lesson பின்தொடருது.

## இது எப்படி work ஆகுது

**நம்பகமான structure.**

1. **Clarify (3 முதல் 5 நிமிஷம்).** Users, task, scale (users, documents, requests per second), latency, cost constraints, languages, data sensitivity, success-னா என்ன. கேளுங்க, அப்புறம் assumptions-ஐ சத்தமா சொல்லுங்க.
2. **High-level design (5 நிமிஷம்).** ஆழமா போறதுக்கு முன்னாடி main components-ஐயும் request flow-வையும் sketch பண்ணுங்க.
3. **Deep dives (15 முதல் 20 நிமிஷம்).** இந்த problem-க்கு அதிகம் முக்கியமான பகுதிகள்: பெரும்பாலும் retrieval (ingestion, chunking, hybrid search, reranking, permissions), generation (prompting, grounding, model choice), tools அல்லது agents, evaluation.
4. **Failure modes and safety (5 நிமிஷம்).** Hallucination, injection, outages, cost spikes, privacy.
5. **Evaluation and operations (5 நிமிஷம்).** Test sets, metrics, launch bar, monitoring, rollout.
6. **Trade-offs and next steps (2 நிமிஷம்).** இன்னும் time இருந்தா அல்லது பத்து மடங்கு scale-ல என்ன பண்ணுவீங்க.

**நல்ல score தர்ற பழக்கங்கள்.**

- சத்தமா யோசிங்க; trade-offs-ஐ பேர் சொல்லுங்க ("hybrid search கொஞ்சம் அதிகம் செலவாகும், ஆனா policy numbers-ஐ பிடிக்கும்").
- Numbers use பண்ணுங்க: தோராயமான token counts, costs, latency budgets.
- எளிமையா ஆரம்பிச்சு, requirements கேக்குற இடத்துல மட்டும் complexity சேருங்க.
- Interruptions-ஐ attack-ஆ இல்லாம புது requirements-ஆ எடுத்துக்கோங்க.
- Time-ஐ கவனிங்க; chunking-ல 25 நிமிஷம் செலவழிக்காதீங்க.

**Practice பண்ண வேண்டிய பொதுவான கேள்விகள்.** Company documents மேல RAG; actions உள்ள customer-support assistant; நீளமான documents-ஐ summarise பண்றது; coding assistant; இந்தியாவுக்கான multilingual chatbot; tools உள்ள agent; ஒரு model upgrade-ஐ evaluate பண்றது; cost-ஐ பாதியா குறைக்கிறது.

**சத்தமா practice பண்ணுங்க.** உங்களை record பண்ணுங்க, அல்லது ஒரு friend-ஓட practice பண்ணுங்க. ஒரு design-ஐ பேசுறது அதை தெரிஞ்சிருக்கிறதுல இருந்து வேற skill.

**Interviewers தேடுற signals:**

| Strong signal | Weak signal |
| --- | --- |
| முதல்ல users, scale, data rules பத்தி கேக்குறது | Tools பேர் சொல்ல ஆரம்பிக்கிறது |
| Numbers-ஓட assumptions சொல்றது | Numbers-ஐ தவிர்க்கிறது |
| ஒவ்வொரு choice-உம் இந்த problem-க்கு ஏன் பொருந்தும்னு விளக்குறது | Technologies-ஐ list பண்றது |
| Failure modes, evaluation-ஐ cover பண்றது | Happy path-ஓட நிறுத்திடுறது |
| "What if"-க்கு அமைதியா adapt ஆகுறது | முதல் design-ஐ பிடிவாதமா defend பண்றது |
| எல்லா பகுதிகள்லயும் time-ஐ manage பண்றது | பெரும்பாலான time-ஐ ஒரு box-ல செலவழிக்கிறது |

**Partner-ஓட practice.** ஒவ்வொரு session-லயும் roles-ஐ மாத்திக்கோங்க. Interviewer, candidate பார்க்காத ஒரு prompt-ஐ எடுத்து, ஒவ்வொரு phase-க்கும் time பண்ணி, outage, புது language, பத்து மடங்கு traffic மாதிரி ரெண்டு "what if" கேள்விகளால குறுக்கிடுவாரு. அப்புறம் மூணு notes சொல்லுவாரு: நல்லா பண்ண ஒண்ணு, ஒரு gap, மாத்திக்க வேண்டிய ஒரு பழக்கம். Interviewer-ஆ நடிச்சா, தெளிவான answer எப்படி இருக்கும்னு தெரிஞ்சுக்கலாம்.

**Estimates-ஐ சீக்கிரம் போடுறது.** சில back-of-the-envelope numbers யோசிக்காமலே வர்ற வரை practice பண்ணுங்க. ஒரு page text-ல எத்தனை tokens, daily users-ல இருந்து requests per second, tokens, prices-ல இருந்து cost per request, ஒரு model size-க்கு வேண்டிய GPU memory இவை தெரிஞ்சிருக்கணும். Interviewers-க்கு exact numbers தேவையில்ல; நீங்க orders of magnitude-ல reason பண்றீங்கன்னு பார்க்கணும்.

## ஒரு worked example

Prompt: "ஒரு மாநில மின்சார வாரியத்துக்கு, billing, outage கேள்விகளுக்கு Tamil, English-ல பதில் சொல்ற WhatsApp assistant-ஐ design பண்ணுங்க."

ஒரு strong candidate-ஓட answer, சுருக்கமா:

- *Clarify*: 2 million consumers; bills வந்ததுக்கு அப்புறமும் outages-ஓட போதும் peaks; tariffs-ல answers துல்லியமா இருக்கணும்; outage data ஒரு internal system-ல; account questions-க்கு consumer number; data இந்தியாவுக்குள்ளயே இருக்கணும்.
- *Design*: ஒரு provider வழியா WhatsApp Business Platform → API service → intent routing (billing, outage, tariff FAQ, complaint) → bill lookup, outage status-க்கான tools (consumer number OTP-ஓட verify ஆகும்) → ரெண்டு languages-லயும் tariff orders, FAQs மேல RAG → இந்திய region-ல model → reply.
- *Deep dive*: Tamil, English chunks-ஓட bilingual retrieval; tariff tables-ஐ கவனமா extract பண்றது; outage answers live tool-ல இருந்து மட்டும், ஒருபோதும் generate பண்ணாம; complaints reference number-ஓட log ஆகி ஆட்கள்கிட்ட handover ஆகும்.
- *Failures*: outage spikes (area வாரியா outage status-ஐ cache பண்ணி, scale out), தப்பான tariffs (citations, refusal, வாராந்திர review), injection (complaint logging தவிர write tools இல்ல), provider outage (helpline-ஓட fallback message).
- *Evaluation*: ரெண்டு languages-லயும் 300 உண்மையான கேள்விகள், intent வாரியா accuracy; முதல்ல ஒரு district-ல launch.
- *Cost*: ஒரு conversation-க்கு தோராயமான estimate, எதிர்பார்க்குற volume-ல மாச total.

Interviewer கேக்குறாரு, "outage system down-ஆ இருந்தா என்ன?" Candidate சொல்றாரு: கடைசியா தெரிஞ்ச status-ஐ timestamp-ஓட, helpline-ஓட காட்டணும், on-call-க்கு alert பண்ணணும்.

| Phase | மின்சார வாரிய answer என்ன cover பண்ணுச்சு |
| --- | --- |
| Clarify | 2 million consumers, bill-day, outage peaks, இந்திய data residency |
| Design | WhatsApp provider, intent routing, OTP-verified tools, bilingual RAG |
| Deep dive | Outage answers live tool-ல இருந்து மட்டும்; tariff tables கவனமா extract |
| "Outage system down-ஆ இருந்தா?" | கடைசியா தெரிஞ்ச status timestamp-ஓட, helpline, on-call alert |

## பொதுவா பண்ற தப்புகள்

- **Clarify பண்ணாம details-க்குள்ள குதிக்கிறது.**
- **Choices-ஐ விளக்காம tools பேர் சொல்றது.**
- **Evaluation, operations-ஐ புறக்கணிக்கிறது.**
- **Numbers இல்லாம பேசுறது.**
- **ஒரு component-ல time தீர்ந்து போறது.**
