## இது என்ன

பயனுள்ள Python-ல பெரும்பாலானது Python-ல இருந்தே வராது. மத்தவங்க எழுதுன **packages**-ல இருந்து வரும்: web APIs-க்கு `requests`, tables-க்கு `pandas`, arrays-க்கு `numpy`, AI model providers-ஓட official SDKs. இவற்றை Python-ஓட package installer-ஆன **pip** வச்சு install பண்றோம்.

இதுல ஒரு பிரச்சனை வருது. Project A-க்கு pandas version 2.1 வேணும்; project B-க்கு 2.3 வேணும். ரெண்டுமே ஒரே இடத்துல install ஆனா, ஒண்ணு உடையும். தீர்வு: **virtual environment**, அதாவது ஒரு project-க்கான, install பண்ண packages-ஓட தனிப்பட்ட folder.

```flow
title: Environments இல்லாம
System Python | pandas 2.3, project B-க்காக upgrade பண்ணது -> Project A உடையுது
```

```flow
title: Environments-ஓட: ஒவ்வொரு project-க்கும் தனியா, எதுவும் மோதாது
project-a/.venv | pandas 2.1, requests 2.32 -> Project A work ஆகுது
project-b/.venv | pandas 2.3, anthropic SDK -> Project B work ஆகுது
```

**requirements.txt** file, ஒரு project-க்கு தேவையான packages-ஐயும் versions-ஐயும் list பண்ணும்; அதனால யாரும், எந்த machine-லயும், அதே environment-ஐ மறுபடி உருவாக்கலாம்.

இந்த lesson-ல Pune-ல ஒரு student-ஆன Nikhil, ஒரு classmate-ஓட project-ஐ run பண்ணி, தன் சொந்த projects ஒண்ணை ஒண்ணு உடைக்காம பார்த்துக்கிறதை follow பண்றோம். Lesson முடியும் போது, எந்த project-க்கும் அதோட requirements file-ல இருந்து ரெண்டு நிமிஷத்துக்குள்ள ஒரு புது environment-ஐ set up பண்ண முடியும்.

## இது எப்படி work ஆகுது

### Environment-ஐ உருவாக்கி activate பண்றது

உங்க project folder-க்குள்ள:

```bash
python -m venv .venv
```

அப்புறம் activate பண்ணுங்க:

| System | Command |
| --- | --- |
| Windows (Command Prompt அல்லது PowerShell) | `.venv\Scripts\activate` |
| Mac அல்லது Linux | `source .venv/bin/activate` |

இப்போ உங்க terminal prompt `(.venv)`-ல தொடங்கும். நீங்க install பண்றது எல்லாமே இந்த project-க்கு மட்டும் போகும். வெளியே வர `deactivate` type பண்ணுங்க.

### Packages install பண்றது

```bash
pip install requests pandas
pip list                       # what is installed in this environment
pip show pandas                # details and version of one package
```

### Install பண்ணதை record பண்றது

```bash
pip freeze > requirements.txt
```

`pip freeze` ஒவ்வொரு package-ஐயும் `pandas==2.3.1` மாதிரி அதோட **சரியான** version-ஓட print பண்ணும்; அதனால மத்தவங்களும் அதே versions-ஐ install பண்ணுவாங்க. ஒரு requirements file இப்படி இருக்கும்:

```text
# shortened: pip freeze also lists every sub-dependency
certifi==2025.8.3
numpy==2.3.2
pandas==2.3.1
requests==2.32.5
```

### வேற machine-ல மறுபடி உருவாக்குறது

ஒரு project-ஐ clone பண்ணதுக்கு அப்புறம், ஒரு புது environment-ஐ உருவாக்கி activate பண்ணி, அப்புறம்:

```bash
pip install -r requirements.txt
```

### Version specifiers

ஒரு requirements file சரியா pin பண்ணலாம், இல்லன்னா ஒரு range-ஐ அனுமதிக்கலாம்:

| Line | அர்த்தம் |
| --- | --- |
| `pandas==2.3.1` | சரியா இந்த version: மிக reproducible |
| `pandas>=2.2` | இந்த version அல்லது புதுசு: புது major version வரும்போது உடையலாம் |
| `pandas>=2.2,<3` | 2.2-ல இருந்து எந்த 2.x-உம்: libraries-க்கு பொதுவான சமரசம் |
| `pandas` | இன்னைக்கு எது புதுசோ அது: மத்தவங்க run பண்ற projects-ல தவிருங்க |

Deploy பண்ற ஒரு application-க்கு, நீங்க test பண்ணதையே server-உம் பெறணும்னு சரியான versions-ஐ pin பண்ணுங்க. மத்தவங்க install பண்ற ஒரு library-க்கு, அவங்க மத்த packages-ஓட மோதாம இருக்க, நியாயமான ranges-ஐ அனுமதிங்க. Upgrade பண்ணும்போது, வேணும்னே பண்ணுங்க: version-ஐ மாத்தி, tests-ஐ run பண்ணி, புது file-ஐ commit பண்ணுங்க.

### AI வேலைக்கான packages

AI projects-ல இன்னும் சில பழக்கங்கள் சேரும். Anthropic, OpenAI-ஓட official Python packages மாதிரி model provider SDKs வேகமா மாறும்; அதனால அவற்றை pin பண்ணி, upgrade பண்றதுக்கு முன்னாடி release notes-ஐ படிங்க. இந்த SDKs உங்க API key-ஐ `ANTHROPIC_API_KEY` மாதிரி ஒரு environment variable-ல இருந்து படிக்கும்; அதை உங்க shell-லயோ, `.gitignore`-ல இருக்குற ஒரு `.env` file-லயோ set பண்ணுங்க, code-ல ஒருபோதும் வேண்டாம். PyTorch மாதிரி பெரிய packages நூற்றுக்கணக்கான megabytes இருக்கலாம், உங்க computer-ஓட graphics card-ஐயும் சார்ந்திருக்கும்; அதனால சாதாரண `pip install`-க்கு பதிலா project-ஓட சொந்த install instructions-ஐ follow பண்ணுங்க.

### Git-ல இருந்து விலக்கி வைங்க

`.venv/`-ஐ `.gitignore`-ல சேர்த்து, அதுக்கு பதிலா `requirements.txt`-ஐ commit பண்ணுங்க. Environments பெரிசு, நூற்றுக்கணக்கான megabytes, ஒரு machine-ஓட operating system-க்கு கட்டுப்பட்டவை.

### உங்க editor-ஓட interpreter-ஐ தேர்ந்தெடுங்க

VS Code-ல `.venv` Python interpreter-ஐ select பண்ணுங்க (Command Palette, "Python: Select Interpreter"). இல்லன்னா editor உங்க terminal-ஐ விட வேற Python-ஐ use பண்ணி, packages காணோம்னு சொல்லலாம்.

### புது tools

| Tool | என்ன சேர்க்குது |
| --- | --- |
| `pip` and `venv` | Built in; ஆரம்பிக்க போதும் |
| `uv` | ரொம்ப வேகமான installs, environment உருவாக்கம், ஒரு lock file |
| Poetry | ஒரு lock file-ஓட dependency management, packaging |

**Lock files**, நீங்க பேர் சொன்ன packages-ஐ மட்டும் இல்லாம எல்லா sub-dependency-யையும் pin பண்ணும். Ideas அதே தான்: ஒரு project-க்கு ஒரு environment, versions ஒரு file-ல record ஆகியிருக்கும்.

```bash
python -m venv .venv
source .venv/bin/activate

python main.py
```

## பொதுவா பண்ற தப்புகள்

- **System Python-ல install பண்றது.** அப்போ projects ஒண்ணை ஒண்ணு பாதிக்கும்.
- **Environment-ஐ activate பண்ண மறக்குறது.** Packages தப்பான இடத்துக்கு போகும், இல்லன்னா "காணோம்"னு தெரியும். உங்க prompt-ல `(.venv)` இருக்கான்னு பாருங்க.
- **`.venv`-ஐ Git-ல commit பண்றது.** அதுக்கு பதிலா `requirements.txt`-ஐ commit பண்ணுங்க.
- **Version pins இல்லாம இருக்குறது.** எதிர்கால release உங்க code-ஐ உடைக்கலாம்; `pip freeze` சரியான versions-ஐ record பண்ணும்.
- **Editor வேற interpreter-ஐ use பண்றது.** உங்க editor-ல project-ஓட `.venv`-ஐ select பண்ணுங்க.
- **`pip`-ஐயும் `python`-ஐயும் வேற வேற இடங்கள்ல இருந்து run பண்றது.** ரெண்டும் பொருந்துதுன்னு உறுதி பண்ண `python -m pip install ...` use பண்ணுங்க.

## Practice பண்ணுங்க

கீழே link பண்ணியிருக்குற Python Packaging User Guide-ஓட pip, virtual environments page-ஐ படிங்க.

1. **உருவாக்குங்க.** தனக்குன்னு ஒரு virtual environment இருக்குற ஒரு project folder-ஐ செய்து, `requests`-ஐ install பண்ணுங்க.
2. **மறுபடி build பண்ணுங்க.** `requirements.txt`-ஐ save பண்ணி, environment-ஐ delete பண்ணி, மறுபடி உருவாக்கி, file-ல இருந்து மறுபடி install பண்ணுங்க.
3. **Share பண்ணுங்க.** `.venv/`-ஐ `.gitignore`-ல சேர்த்து, அது இல்லாம project-ஐ GitHub-க்கு push பண்ணுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** எந்த project-க்கும் அதோட requirements file-ல இருந்து ரெண்டு நிமிஷத்துக்குள்ள ஒரு புது environment-ஐ set up பண்ண முடியும்.
