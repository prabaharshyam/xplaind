## இது என்ன

AI assistants research-ல மணிக்கணக்கான நேரத்தை மிச்சப்படுத்தும், ஆனா confident-ஆ ஒரு தப்பான பதிலை கொடுத்து, அதை நீங்க meeting-ல சொல்ற நிலைமைக்கும் கொண்டு வரலாம். Skill-னா "research-க்கு AI use பண்றது" இல்ல. **Research-க்கு AI use பண்ணி, அதை வேகமா check பண்றது** தான்.

Assistants மூணு வழில உதவும்:

- **ஒரு topic-ஐ explore பண்றது:** ஒரு overview, key terms, முக்கிய arguments, அடுத்து என்ன தேடணும்ங்குறது.
- **உங்க சொந்த material பத்தி கேள்வி கேக்குறது:** ஒரு report, policy, spreadsheet-ஐ upload பண்ணி அதை பத்தி கேக்குறது.
- **Compare பண்ணி யோசிக்கிறது:** options-ஐ எடை போடுறது, pros, cons list பண்றது, plan-ல இருக்குற ஓட்டைகளை கண்டுபிடிக்கிறது.

பதிலை எவ்வளவு நம்பலாம்ங்குறது அது **எங்க இருந்து வந்தது**ங்குறதை பொறுத்தது:

```flow
dir: LR
title: பதில் எங்க இருந்து வருது, எவ்வளவு check பண்ணலாம்
Model-ஓட memory மட்டும் -> கஷ்டம்: திறக்க source இல்ல
Links-ஓட web search -> நல்லது: links-ஐ திறங்க
நீங்க upload பண்ண document -> சிறந்தது: page-ஐ check பண்ணுங்க
Spreadsheet, calculation -> நல்லது: ஒரு sample-ஐ திரும்ப calculate பண்ணுங்க
```

இந்த lesson-ல Madurai-ல ஒரு சின்ன கடை நடத்துற Meena-வை follow பண்ணுவோம். ஒரு tax decision-ஐ புரிஞ்சுக்க அவங்க assistant-ஐ use பண்றாங்க. Lesson முடியும்போது AI-ஓட research-ஐ explore பண்ணவும், ground பண்ணவும், check பண்ணவும் தெரிஞ்சிருக்கும்.

## இது எப்படி work ஆகுது

### ஒரு topic-ஐ explore பண்றது

பெருசா தொடங்கி, அப்புறம் சுருக்குங்க. "சின்ன வியாபாரிக்கு GST input tax credit எப்படி work ஆகுதுன்னு, simple-ஆ, ஒரு example-ஓட explain பண்ணு"ன்னு கேட்டா ஒரு map கிடைக்கும். அப்புறம் "Official GST portal-ல நான் என்ன key terms-ஐ search பண்ணணும்?"னு கேளுங்க; அப்போ source-க்கே போகலாம். Overview-ஐ map-ஆ எடுத்துக்கோங்க, நிலப்பரப்பா இல்ல: எங்க பார்க்கணும்னு சொல்லும், எது உண்மைன்னு இல்ல.

### Sources இருக்குற பதில்கள்

Assistant web-ல search பண்ணும்போது links காட்டும். அதை திறங்க. ஒவ்வொண்ணுலயும் மூணு விஷயம் check பண்ணுங்க:

1. **அது இருக்கா?** Links உடைஞ்சதா அல்லது கற்பனையா இருக்கலாம்.
2. **அது reliable-ஆ?** Official sites (government portals, RBI, SEBI மாதிரி regulators, UPI-க்கு NPCI), நல்ல publishers, பேர் தெரியாத blogs-ஐ விட நம்பகமானவை.
3. **பதில் சொல்றதை அது சொல்லுதா?** Models சில நேரம் claim-ஐ support பண்ணாத ஒரு real page-ஐ cite பண்ணும்.

ஒரு page-ஐ விட்டு போய் மத்த sources என்ன சொல்லுதுன்னு பார்க்குற பழக்கத்தை fact-checkers **lateral reading**-னு சொல்றாங்க. ஒரே page-ஐ பார்த்து அதோட design வச்சு judge பண்றதை விட, இது வேகமானதும் நம்பகமானதும்.

### உங்க documents-ல grounding

Document upload பண்ணா, பதிலை அதுல **ground** பண்றீங்க. என்ன வேணும்னு சரியா சொல்லுங்க: "இந்த document-ல இருந்து மட்டும் பதில் சொல்லு, ஒவ்வொரு point-க்கும் page number கொடு." அப்புறம் cite பண்ண pages-ஐ check பண்ணுங்க. Document-ல பதில் இல்லன்னா, நல்ல assistant அதை சொல்லும். அப்படியும் பதில் சொன்னா, memory-ல இருந்து gap-ஐ நிரப்பிக்கிட்டு இருக்கலாம்.

### Spreadsheets

நிறைய assistants spreadsheets-ஐ பின்னணியில code எழுதி ஓட்டி analyse பண்ணும்: totals, averages, charts, trends. இது சக்தி வாய்ந்தது, ஆனா சலிப்பான வழிகள்ல fail ஆகும்:

| Problem | என்ன தப்பாகுது | எப்படி பிடிக்கிறது |
| --- | --- | --- |
| Column-ஐ தப்பா படிக்கிறது | "Amount"-க்கு பதிலா "invoice number"-ஐ கூட்டுது | எந்த column-ஐ use பண்ணுச்சுன்னு கேளுங்க |
| Merged cells அல்லது extra headers | Rows-ஐ skip அல்லது இரண்டு தடவை எண்ணுது | Row count-ஐ check பண்ணுங்க |
| இந்திய number formats | 1,00,000-ஐ தப்பா படிக்குது | பெரிய numbers-ஐ spot-check பண்ணுங்க |
| Returns அல்லது refunds positive-ஆ இருக்குறது | Totals ஊதிடும் | ஒரு மாசத்தை கையால திரும்ப calculate பண்ணுங்க |
| Number columns-ல text | Rows-ஐ சத்தமில்லாம விட்டுடும் | எத்தனை rows use பண்ணுச்சுன்னு கேளுங்க |

எப்பவும் "ஒவ்வொரு number-ஐயும் எப்படி calculate பண்ணுனேன்னு காட்டு"னு கேளுங்க; ரெண்டு, மூணை நீங்களே திரும்ப calculate பண்ணுங்க.

### ஒரு thinking partner

சில use-களுக்கு perfect facts வேணாம். "இது என் ரெண்டாவது கடை திறக்குற plan; என்ன தப்பா போகலாம்?" அல்லது "எதிர் கருத்தை வாதாடு"ன்னு கேட்டா, ஒரு point பலவீனமா இருந்தாலும், தெளிவா யோசிக்க உதவும்.

## ஒரு worked example

Meena, Madurai-ல ஒரு garments shop-ஓட owner. சின்ன businesses-க்கு simple filing தர்ற GST composition scheme-ல register பண்ணலாமான்னு தெரிஞ்சுக்க நினைக்கிறாங்க.

**Step 1: explore.** Scheme பத்தி ஒரு simple விளக்கம், யார் use பண்ணலாம், முக்கிய pros, cons கேக்குறாங்க. பதில் தெளிவா, நல்லா ஒழுங்கா இருக்கு. Tax rules மாறும்னு அவங்களுக்கு தெரியும், அதனால official sources கேக்குறாங்க. Web search on-ல, assistant GST portal-க்கும் ஒரு government FAQ-க்கும் link கொடுக்குது. ரெண்டையும் திறக்குறாங்க. பதில்ல இருந்த ஒரு turnover limit பழசு; official page-ல இப்போதைய figure இருக்கு. சரியானதை note பண்றாங்க.

**Step 2: தன் data-ல ground பண்றது.** போன வருஷ sales spreadsheet-ஐ upload பண்ணி, monthly turnover, yearly total-ஐ calculation காட்டி கேக்குறாங்க. ரெண்டு மாசத்தை கையால check பண்றாங்க. ஒரு total அதிகமா இருக்கு: customer returns-ஓட ஒரு row positive number-ஆ enter ஆகியிருக்கு. Sheet-ஐ சரி பண்ணி, analysis-ஐ மறுபடி ஓட்டுறாங்க.

**Step 3: யோசிக்கிறது.** "இந்த numbers வச்சு, switch பண்றதை பத்தி என் accountant கிட்ட என்ன கேள்விகள் கேக்கணும்?"னு கேக்குறாங்க. ஆறு useful கேள்விகள் கிடைக்குது; input tax credit-க்கு என்ன ஆகும், மத்த states-க்கு விற்க முடியுமா என்பதும் அதுல இருக்கு.

| Step | AI என்ன செய்தது | Meena என்ன check பண்ணாங்க | என்ன கண்டுபிடிச்சாங்க |
| --- | --- | --- | --- |
| Explore | Scheme-ஐ explain பண்ணுச்சு | Official GST pages | ஒரு limit பழசு |
| Ground | அவங்க sales-ஐ கூட்டுச்சு | ரெண்டு மாசத்தை கையால | Returns sales-ஆ எண்ணப்பட்டுச்சு |
| Think | கேள்விகளை list பண்ணுச்சு | எதுவும் தேவையில்ல | ஆறு நல்ல கேள்விகள் |

AI அவங்களுக்கு மணிக்கணக்கான படிக்கிற நேரத்தை மிச்சப்படுத்தி, accountant கூட இன்னும் நல்ல உரையாடலை கொடுத்துச்சு. Final call-ஐ எடுத்தது assistant இல்ல, accountant.

## பொதுவா பண்ற தப்புகள்

- **Sources இல்லாத பதில்களை நம்புறது.** Sources கேளுங்க, அதை திறந்து பாருங்க.
- **Citations-ஐ படிக்காம நம்புறது.** ஒரு real link கூட claim-ஐ support பண்ணாம இருக்கலாம்.
- **Source இல்லாத statistics-ஐ ஏத்துக்கிறது.** Source இல்லாம துல்லியமா தெரியுற numbers, hallucination-க்கு classic example.
- **Spreadsheet maths-ஐ check பண்ணாம இருக்கிறது.** Totals-ஐ கையால spot-check பண்ணுங்க, எந்த columns use பண்ணுச்சுன்னு கேளுங்க.
- **Tax, law, health-ல AI-ஐ final authority-ஆ எடுக்குறது.** தயாராக use பண்ணுங்க, அப்புறம் official sources அல்லது professionals கிட்ட confirm பண்ணுங்க.
- **Private documents-ஐ approve ஆகாத tools-ல upload பண்றது.** எந்த tools எந்த data-வை பார்க்கலாம்னு உங்க organisation-ஓட rules-ஐ follow பண்ணுங்க.

## Practice பண்ணுங்க

கீழே link பண்ணியிருக்குற OpenAI Academy-ஓட research sessions-ஐ பாருங்க, Civic Online Reasoning-ல lateral reading பத்தின ஒரு lesson-ஐ try பண்ணுங்க.

1. **Sources-ஓட research.** வேலைக்கோ படிப்புக்கோ தேவையான ஒரு topic-ஐ research பண்ணுங்க. Sources கேளுங்க, ஒவ்வொண்ணையும் திறந்து, எந்த claims நிலைச்சுது, எது பழசு, எதுக்கு support இல்லன்னு mark பண்ணுங்க.
2. **ஒரு document-ல ground பண்ணுங்க.** ஒரு public report-ஐ upload பண்ணி page references-ஓட ஐந்து கேள்விகள் கேளுங்க. ஒவ்வொரு reference-ஐயும் check பண்ணுங்க.
3. **ஒரு spreadsheet-ஐ check பண்ணுங்க.** ஒரு சின்ன spreadsheet-ஐ assistant-ஓட analyse பண்ணி, அதோட ரெண்டு numbers-ஐ கையால verify பண்ணுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** நீங்க தப்பா அல்லது பழசுன்னு பிடிச்ச ஒரு claim-ஐ காட்ட முடியும், அதை எப்படி கண்டுபிடிச்சீங்கன்னு சரியா explain பண்ண முடியும்.
