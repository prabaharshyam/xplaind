## இது என்ன

"எங்க WhatsApp orders-ஐ automate பண்ண முடியுமா?"ன்னு கேக்கும்போது ஒரே கேள்வி மாதிரி தெரியும். ஆனா உள்ள டஜன் கணக்கான கேள்விகள் மறைஞ்சிருக்கு: எந்த orders? Voice notes-உம் உண்டா? தெரியாத products வந்தா? யார் approve பண்ணுவாங்க? ஆறு மாசம் கழிச்சு யார் fix பண்ணுவாங்க? **Automation scope** வேலை ஆரம்பிக்கிறதுக்கு முன்னாடியே இதுக்கெல்லாம் பதில் சொல்லிடும். அதனால என்ன கிடைக்கப்போகுதுன்னு ரெண்டு பக்கத்துக்கும் தெரியும்.

Automation scope-ன்னா ஒரு சின்ன agreement, பெரும்பாலும் ஒரு பக்கம்:

| Section | என்ன சொல்லுது | Example |
| --- | --- | --- |
| **Process-உம் எல்லைகளும்** | எங்க ஆரம்பிக்குது (trigger), எங்க முடியுது (outcome) | Order message வர்றதுல இருந்து billing-க்கு CSV ready ஆகுற வரை |
| **Inputs** | Formats, sources, volumes | WhatsApp-ல text-உம் photos-உம், நாளைக்கு சுமார் 150 |
| **Automate ஆகுறதும் manual-ஆ இருக்குறதும்** | Automation என்ன பண்ணும், மக்கள் இன்னும் என்ன பண்ணுவாங்க | AI extract பண்ணும்; staff ஒவ்வொரு order-ஐயும் confirm பண்ணுவாங்க |
| **Exceptions** | வழக்கத்துக்கு மாறான cases-ல என்ன நடக்கும் | தெரியாத products original message-ஓட staff-கிட்ட போகும் |
| **Systems, access** | Apps, accounts, permissions, யார் எப்போ கொடுப்பாங்க | WhatsApp Business account, client December 10-க்குள்ள set up பண்ணணும் |
| **Success measures** | Baseline-ஓட என்ன improve ஆகணும் | Entry time 3 நிமிஷத்துல இருந்து 1 நிமிஷத்துக்கு கீழ |
| **Acceptance test** | வேலை பண்ணுதுன்னு ரெண்டு பக்கமும் எப்படி check பண்றது | 200 பழைய orders replay; 90% lines match ஆகணும் |
| **Ownership, support** | யார் maintain பண்றாங்க, support காலம், எது change-ஆ கணக்கு | 30 நாள் fixes; changes ஒத்துக்கிட்ட day rate-ல |
| **விலை, timeline** | Client வேலைக்கு | Fixed fee, கூடவே மாசாமாசம் running costs |

```flow
Discovery | process map, samples -> Draft scope -[client படிக்கிறாங்க]-> கேள்விகள், edits
கேள்விகள், edits -> Draft scope
Draft scope -> கையெழுத்தான scope | in, out, acceptance, support, விலை
கையெழுத்தான scope -> Build -> Acceptance test -> Handover -> Support காலம் -> Change requests
```

இந்த lesson-ல Indore-ல இருக்குற ஒரு freelance automation specialist-ஐ follow பண்ணுவோம். ஒரு distributor அவங்ககிட்ட "WhatsApp orders-ஐ automate பண்ணுங்க"ன்னு கேக்குறாங்க. Lesson முடியும்போது, ஒரு business owner எழுத்துல ஒத்துக்கக்கூடிய ஒரு பக்க scope-ஐ நீங்களே எழுத முடியும்.

## இது எப்படி work ஆகுது

### Process map-ல இருந்து ஆரம்பிங்க

Discovery-ல உருவாக்கின map-ஐ வச்சு எல்லைகளை முடிவு பண்ணுங்க. ஒவ்வொரு step-ஐயும் **automated**, **assisted** (AI draft பண்ணும், ஒரு ஆள் approve பண்ணுவாங்க) அல்லது **manual**-ன்னு mark பண்ணுங்க. Scope-ன்னா map-உம் அதோட decisions-உம் தான்.

### Inputs-ஐயும் exceptions-ஐயும் நேர்மையா list பண்ணுங்க

எதையும் ஒத்துக்குறதுக்கு முன்னாடி **20 முதல் 50 real samples** கேளுங்க. Formats-ஐயும் exceptions-ஐயும் எண்ணுங்க:

| Input வகை | Samples-ல எவ்வளவு | Decision |
| --- | --- | --- |
| Type பண்ண text orders | 55% | Scope-ல இருக்கு |
| கையால எழுதின lists-ஓட photos | 30% | Scope-ல இருக்கு, staff review-ஓட |
| Voice notes | 12% | இப்போ scope-ல இல்லை; phase 2 |
| வேற apps-ல இருந்து forward பண்ண PDFs | 3% | Exception-ஆ staff-கிட்ட அனுப்புறது |

ஒவ்வொரு exception-க்கும் முடிவு பண்ணுங்க: handle பண்றதா, ஒரு ஆள்கிட்ட அனுப்புறதா, விலக்குறதா. முடிவை எழுதி வைங்க.

### Human checkpoints-ஐ ஒத்துக்கோங்க

எந்த steps-க்கு approval வேணும்? Payments, customers-க்கு போற messages, deletions-க்கு பெரும்பாலும் வேணும். யார் approve பண்ணுவாங்க, எந்த tool-ல? யாருக்கும் நேரம் இல்லாத checkpoint-ஐ எல்லாரும் skip பண்ணிடுவாங்க.

### Access-ஐ ஒரு dependency-ஆ ஆக்குங்க

ஒவ்வொரு system-ஐயும், தேவையான account வகையையும், access கொடுக்க வேண்டிய தேதியையும் list பண்ணுங்க. Technical பிரச்சனைகளை விட access தாமதம் தான் projects-ஐ அதிகம் தடுக்குது. Access லேட்டா வந்தா timeline நகரும்; அதை scope-லயே எழுதணும்.

### Acceptance-ஐ ஒரு test-ஆ define பண்ணுங்க

தெளிவில்லாதது: "system நல்லா வேலை பண்ணணும்". Test பண்ணக்கூடியது: "போன மாசத்து 100 real invoices-ல குறைஞ்சது 85, மனுஷ தொடுதல் இல்லாம process ஆகி, எல்லா fields-உம் accountant-ஓட entries-ஓட பொருந்தணும்; fail ஆன ஒவ்வொண்ணும் review queue-ல வரணும்." நீங்க இல்லாத வேற ஒருத்தராலயும் இதை run பண்ண முடியணும்.

### Support-உம் changes-உம்

Support காலத்தை சொல்லுங்க, உதாரணம்: go-live-க்கு அப்புறம் 30 நாள் fixes. **Change request**-னா என்னன்னு define பண்ணுங்க: புது supplier format, புது system, புது feature. Changes-க்கு எப்படி விலை போடுவீங்கன்னு சொல்லுங்க. நேரத்தையும் விலையையும் மாத்தாம project நடுவுல வர்ற requests தான் **scope creep**; அதை quote-ஓட phase 2 list-ல போடுங்க.

| --- | --- | --- |
| Fixed price | Scope தெளிவா இருக்கு, samples பார்த்தாச்சு | எதிர்பாராததை நீங்க தாங்கணும் |
| Time and materials | Scope தெளிவில்லை அல்லது exploratory | எதிர்பாராததை client தாங்கணும் |
| Monthly retainer | தொடர்ந்து maintenance, சின்ன changes | தெளிவான மாத limit வேணும் |

Tool, AI usage costs-ஐ எப்பவும் சேர்த்து சொல்லுங்க, யார் கட்டுவாங்கன்னும் சொல்லுங்க.

## ஒரு worked example

Indore-ல ஒரு freelance automation specialist-கிட்ட ஒரு distributor "WhatsApp orders-ஐ automate பண்ணுங்க"ன்னு கேக்குறாங்க.

**Discovery-ல** தெரிஞ்சது: 300 retailers-ல இருந்து நாளைக்கு சுமார் 150 orders வருது. WhatsApp text, voice notes, கையால எழுதின lists-ஓட photos, Hindi-லயும் English-லயும். Staff அதை billing software-ல type பண்றாங்க; அந்த software CSV files import பண்ணும்.

**ஒரு பக்க scope:**

- **In:** business WhatsApp number-ல வர்ற text, photo orders; retailer, products, quantities-ஐ AI extract பண்ணி product list-ஓட match பண்றது; staff ஒவ்வொரு order-ஐயும் confirm பண்ற ஒரு review screen; billing software-க்கு daily CSV export.
- **Out:** voice notes (phase 2), payments, stock checks, retailers-க்கு automatic replies.
- **Exceptions:** தெரியாத products அல்லது retailers original message-ஓட staff-கிட்ட போகும்.
- **Access:** ஒரு provider வழியா WhatsApp Business Platform account, client December 10-க்குள்ள set up பண்ணணும்; product, retailer lists sheets-ஆ.
- **Success:** ஒரு order entry time சுமார் 3 நிமிஷத்துல இருந்து 1 நிமிஷத்துக்கு கீழ; அனுப்புற quantities-ல errors இன்னைக்கு இருக்குறதை விட அதிகம் இருக்கக்கூடாது.
- **Acceptance:** 200 பழைய orders replay; staff review-க்கு முன்னாடி குறைஞ்சது 90% lines சரியா match ஆகணும்.
- **Support:** 30 நாள் fixes; புது formats அல்லது features ஒத்துக்கிட்ட day rate-ல change requests-ஆ.
- **Price:** fixed fee, கூடவே WhatsApp provider, AI usage-க்கான மாதாந்திர running costs, client கட்டணும்.

**ரெண்டு வாரம் கழிச்சு**, owner retailers-க்கு automatic payment reminders சேர்க்கச் சொல்றாங்க. நல்ல idea தான், ஆனா scope-ல இல்லை. அதை அதுக்கான தனி quote-ஓட phase 2 list-ல போடுறாங்க. எது out-னு scope தெளிவா சொல்லியிருந்ததால, சண்டையா மாறாம ரெண்டு நிமிஷத்துல பேச்சு முடிஞ்சுடுச்சு.

## பொதுவா பண்ற தப்புகள்

- **Samples இல்லாம scope ஒத்துக்கிறது.** Real inputs தான் exceptions-ஐ காட்டும்.
- **எது out-னு சொல்லாம இருக்கிறது.** எழுதாத விலக்குகள் இலவச extra வேலையா மாறும்.
- **Access-ஐ கடைசியில யோசிக்கிறது.** தாமதத்துக்கு இது ரொம்ப common காரணம்.
- **தெளிவில்லாத acceptance.** Real data-ல numbers-ஓட ஒரு test define பண்ணுங்க.
- **Support terms இல்லாம இருக்கிறது.** காசு இல்லாத support-ஆ எப்பவும் நீங்களே இருப்பீங்க.
- **Running costs-ஐ மறைக்கிறது.** முதல் provider bill வரும்போது client ஏமாந்த மாதிரி feel பண்ணுவாங்க.

## Practice பண்ணுங்க

1. **Samples.** உங்க process map-ல இருந்து ஒரு automation idea எடுத்து, குறைஞ்சது 20 real அல்லது realistic input samples சேருங்க.
2. **Scope.** மேல இருக்குற ஒவ்வொரு section-ஓடயும் ஒரு பக்க scope எழுதுங்க.
3. **Acceptance.** Acceptance test-ஐ வேற ஒருத்தர் run பண்ணக்கூடிய மாதிரி எழுதுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** உங்க scope-ஐ business owner-கிட்ட கொடுத்து, எது in, எது out, success எப்படி அளக்கப்படும்னு எழுத்துல அவங்க ஒத்துக்க வைக்க முடியும்.
