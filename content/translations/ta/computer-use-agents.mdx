## இது என்ன

ஒரு **computer-use agent** software-ஓட அதோட screen வழியா வேலை செய்யும்: screenshots வாங்கி, எங்க click பண்ணணும், என்ன type பண்ணணும்னு முடிவு பண்ணி, திரும்ப திரும்ப பண்ணும். ஒரு **browser agent** அதையே ஒரு web browser-க்குள்ள பண்ணும்; சில நேரம் page-ஓட படத்தோட சேர்த்து அதோட structure-ஐயும் படிக்கும்.

இவை ஒரு உண்மையான இடைவெளியை நிரப்புது. ஒரு system-ல API இருந்தா, API-ஐ call பண்ணுங்க. இல்லைன்னா, நிறைய government portals, insurer, bank portals, பழைய desktop applications மாதிரி, ஒரு மனுஷன் இல்லாம automate பண்ண screen control மட்டுமே ஒரே வழியா இருக்கலாம்.

```flow

1. API | வேகமானது, மலிவானது, அதிக நம்பகமானது -[API இல்லையா?]-> 2. Scripted browser tool | Playwright, fixed steps, ஒரே tool-ஆ expose பண்ணது
2. Scripted browser tool -[steps மாறுதா?]-> 3. Agent-driven browsing | page structure-ஐ படிச்சு, actions-ஐ முடிவு பண்ணும்
3. Agent-driven browsing -[பயன்படுத்தக்கூடிய page structure இல்லையா?]-> 4. Full computer use | screenshot, முடிவு, click அல்லது type, screenshot: ரொம்ப மெதுவானது, குறைவான நம்பகத்தன்மை
```

Rungs 3, 4-க்கு, ஒரு safety box use பண்ணுங்க: isolated VM, dedicated account, site allow-list, submit, pay, delete-க்கு முன்னாடி approval, record பண்ண screenshots, captchas, OTPs ஒரு ஆள்கிட்ட போகணும்.

இந்த lesson, Pune-ல ஒரு chartered accountancy firm-ஐ follow பண்ணுது; அவங்க ஒவ்வொரு மாசமும் clients-ஓட tax documents-ஐ கையால download பண்ண மணிக்கணக்கா செலவழிச்சாங்க.

## இது எப்படி work ஆகுது

**நம்பகத்தன்மை அதிகத்துல இருந்து குறைவு வரைக்கும் options-ஓட ஒரு ladder:**

1. **ஒரு API**, இருந்தா அல்லது கேட்டு வாங்க முடிஞ்சா.
2. Playwright மாதிரி ஒரு library வச்சு **Scripted browser automation**: நீங்க எழுதுன fixed steps, agent-க்கு ஒரு tool-ஆ expose பண்ணது ("download_gst_return(gstin, period)"). வேகம், மலிவு, எதிர்பார்த்த மாதிரி நடக்கும்.
3. **Agent-driven browsing**: agent page structure-ஐ படிச்சு actions-ஐ முடிவு பண்ணும், மாறுற sites-க்கு.
4. Screenshots-ல இருந்து **Full computer use**, desktop apps-க்கும் மிகக் கஷ்டமான cases-க்கும். மிக மெதுவானது, மிக செலவானது, குறைவான நம்பகத்தன்மை.

வேலை செய்யுற மிக உயர்ந்த rung-ஐ use பண்ணுங்க, அவற்றை சேர்த்தும் use பண்ணுங்க: தெரிஞ்ச steps-க்கு scripted tools, pages கணிக்க முடியாத இடத்துல மட்டும் agent control.

**Loop.** Screenshot, ஒரு action-ஐ முடிவு பண்றது (ஒரு point-ல click, type, scroll, ஒரு key அழுத்தல்), செய்றது, திரும்ப screenshot. ஒவ்வொரு step-உம் ஒரு image-ஓட ஒரு model call, அதனால நீளமான tasks நிமிஷக்கணக்குல எடுக்கும், உண்மையான பணமும் செலவாகும்.

**Safety.**

- தேவையான apps, accounts மட்டும் இருக்குற isolated virtual machine அல்லது container-ல ஓட்டுங்க.
- எந்த websites-ஐ அடைய முடியும்னு கட்டுப்படுத்துங்க.
- பொது credentials-ஐ ஒருபோதும் கொடுக்காதீங்க; குறைந்தபட்ச permission இருக்குற ஒரு dedicated account use பண்ணுங்க.
- Screen-ல இருக்குற எல்லாத்தையும் நம்பாதது-ன்னு எடுத்துக்குங்க: web pages-ல agents-ஐ குறி வச்ச instructions இருக்கலாம்.
- Forms submit பண்றது, பணம் கட்டுறது, அனுப்புறது, delete பண்றதுக்கு முன்னாடி human approval கேளுங்க.
- Audit-க்காக ஒவ்வொரு session-ஓட screenshots அல்லது video-வை record பண்ணுங்க.

**Reliability.** Pages மாறும், pop-ups வரும், sessions expire ஆகும், captchas bots-ஐ தடுக்கும். Failures வரும்னு எதிர்பாருங்க, அவற்றை detect பண்ணுங்க (எதிர்பார்த்த confirmation வரலை), ஒரு ஆள்கிட்ட திருப்பி கொடுங்க.

**Failure-ஐ detect பண்றது.** Automate பண்ண ஒவ்வொரு step-உம் success எப்படி இருக்கும்னு தெரிஞ்சிருக்கணும்: ஒரு confirmation message, எதிர்பார்த்த size-ல ஒரு downloaded file, ஒரு list-ல ஒரு புது row. ஒவ்வொரு முக்கிய action-க்கு அப்புறமும் அதை check பண்ணுங்க. அது இல்லைன்னா, guess பண்றதுக்கு பதிலா நிறுத்துங்க, கடைசி screenshot-ஐயும் இதுவரை பண்ண steps-ஐயும் save பண்ணி, ஒரு தெளிவான note-ஓட ஒரு ஆள்கிட்ட கொடுங்க. ஒரு tax அல்லது banking portal-ல அமைதியா நடக்குற தப்பான action, நிறுத்தப்பட்ட task-ஐ விட பல மடங்கு செலவு வைக்கும்.

**Value-ஐ அளக்குறது.** மிச்சப்படுத்தின மணிநேரம், ஒவ்வொரு step-க்கும் success rate, ஒரு action-க்கான சராசரி நேரம், hand-backs எண்ணிக்கை இவற்றை track பண்ணுங்க. Hand-backs project-ஓட தோல்வி இல்லை; system design பண்ண மாதிரியே வேலை செய்யுதுன்னு அர்த்தம். அவை ஒரே page-ல குவிஞ்சா, அந்த page ஒரு scripted tool-க்கான candidate.

**Success check-ஓட ஒரு scripted browser tool.** இது Playwright-ஓட Python API-ஐ use பண்ணுது. Agent ஒரே ஒரு tool-ஐ தான் பார்க்கும், `download_notice`, ஒரே ஒரு argument-ஓட:

```python
from pathlib import Path
from playwright.sync_api import sync_playwright, TimeoutError as PWTimeout

ALLOWED = {"www.example-gov.in"}                       # the only site this tool may reach

def download_notice(notice_id: str) -> str:
    if not notice_id.isdigit():
        return "notice_id must be digits only."
    with sync_playwright() as p:
        browser = p.chromium.launch()
        page = browser.new_page(accept_downloads=True)
        page.route("**/*", lambda route: route.continue_()
                   if route.request.url.split("/")[2] in ALLOWED else route.abort())
        try:
            page.goto("https://www.example-gov.in/notices", timeout=20_000)
            page.get_by_label("Notice number").fill(notice_id)
            page.get_by_role("button", name="Search").click()
            with page.expect_download(timeout=20_000) as dl:
                page.get_by_role("link", name="Download PDF").click()
            path = Path("downloads") / f"notice-{notice_id}.pdf"
            dl.value.save_as(path)
            if path.stat().st_size < 1_000:                 # success check: a real PDF, not an error page
                return "Download looked empty; a person should check this notice."
            return f"Saved {path}"
        except PWTimeout:
            page.screenshot(path=f"downloads/failed-{notice_id}.png")
            return "The site did not respond as expected; screenshot saved for a person."
        finally:
            browser.close()
```

Labels, roles (`get_by_label`, `get_by_role`) CSS paths-ஐ விட layout மாற்றங்களை நல்லா தாங்கும். ஒவ்வொரு exit-உம் agent கடத்தக்கூடிய ஒரு வாக்கியத்தை return பண்ணுது.

**Screenshot loop, ஒரு sketch.** Computer-use models, உங்க code ஓட்டுற ஒரு loop-ல வேலை செய்யுது:

```python
for step in range(MAX_STEPS):

    history.append(action)
```

Providers தங்க சொந்த action formats-ஓட computer-use tools தர்றாங்க; மேல இருக்குற வடிவம் அப்படியே இருக்கும். `is_risky` check உங்க code, page address-ஐயும் click-க்கு கீழ இருக்குற element-ஐயும் வச்சு முடிவு பண்ணும், model-ஓட கருத்தை வச்சு இல்லை.

**Isolation, practice-ல.** Browser-ஐ உங்க internal network-க்கு access இல்லாத ஒரு container-ல, ஒரு outbound allow list-ஓட, ஒவ்வொரு task-க்கும் ஒரு புது profile-ஓட, ஒரு dedicated குறைந்த-permission account-ஓட ஓட்டுங்க. ஒவ்வொரு task-க்கு அப்புறமும் container-ஐ delete பண்ணுங்க, அப்போ cookies, downloads runs-க்கு இடையில leak ஆகாது.

**எவ்வளவு நல்லவை?** Web, desktop tasks-ஓட public benchmarks நிலையான முன்னேற்றத்தை காட்டுது, ஆனா மக்கள் சுலபமா முடிக்குற நிறைய தினசரி tasks-ல agents இன்னும் fail ஆகுது, குறிப்பா pop-ups, logins, வழக்கத்துக்கு மாறான layouts இருக்குற நீளமான tasks-ல. எதையும் வாக்குறுதி கொடுக்குறதுக்கு முன்னாடி உங்க சொந்த tasks-ல அளந்து பாருங்க.

## ஒரு worked example

Pune-ல ஒரு chartered accountancy firm, ஒவ்வொரு மாசமும் ஒரு government portal-ல இருந்தும், API இல்லாத ஒரு பழைய accounting desktop app-ல இருந்தும் clients-ஓட tax documents-ஐ download பண்ண மணிக்கணக்கா செலவழிக்குது.

Design:

- Portal-க்கு, ஒரு scripted Playwright tool, vault-ல இருந்து client-authorised credentials-ஓட login பண்ணி, தெரிஞ்ச pages-க்கு போய், files-ஐ download பண்ணுது. Agent அந்த tool-ஐ call பண்ணும்; சுதந்திரமா browse பண்ணாது. Portal-ஓட layout மாறும்போது, script சத்தமா fail ஆகும், ஒரு engineer fix பண்ணுவார்.
- Desktop accounting app-க்கு, file share-ஐ தவிர internet இல்லாத ஒரு Windows virtual machine-ல ஒரு computer-use agent ஓடுது. App-ஓட menus-ஐ follow பண்ணி ledgers-ஐ export பண்ணுது. எந்த file-ஐயும் overwrite பண்ணி save பண்றதுக்கு முன்னாடி ஒரு staff member-ஓட approval கேக்குது.
- Captchas, one-time passwords design-லயே ஒரு ஆள்கிட்ட போகும்.

Results: 120 clients-க்கு மாசாந்திர download வேலை சுமார் 60 staff hours-ல இருந்து 12 ஆக குறையுது, பெரும்பாலும் approvals, exceptions. Computer-use steps ஒரு action-க்கு சராசரி 40 seconds எடுத்து, 91% வெற்றி பெறுது; failures கடைசி screenshot-ஓட திருப்பி கொடுக்கப்படுது.

| அளவு | முன்னாடி | பின்னாடி |
| --- | --- | --- |
| மாசத்துக்கு staff hours, 120 clients | சுமார் 60 | சுமார் 12, பெரும்பாலும் approvals, exceptions |
| ஒரு action-க்கு computer-use நேரம் | பொருந்தாது | சுமார் 40 seconds |

## பொதுவா பண்ற தப்புகள்

- **API அல்லது script போதும்ங்கிற இடத்துல screen control.** மெதுவானது, செலவானது, நிலையற்றது.
- **உண்மையான logins-ஓட ஒரு real desktop-ல ஓட்டுறது.** ஒரு isolated machine-ஐயும் ஒரு dedicated account-ஐயும் use பண்ணுங்க.
- **Screen-ல இருக்குற text-ஐ நம்புறது.** Pages-ல புகுத்தப்பட்ட instructions இருக்கலாம்.
- **திரும்ப எடுக்க முடியாத actions-க்கு முன்னாடி மனுஷன் இல்லாம இருக்கிறது.** Submissions, payments-க்கு approval வேணும்.
- **Captchas-ஐ முறியடிக்க முயற்சி பண்றது.** அவற்றை மதிங்க; அந்த step-ஐ ஒரு ஆள்கிட்ட கொடுங்க.
- **Tasks-க்கு இடையில ஒரே browser profile-ஐ மறுபடி use பண்றது.** Cookies, sessions ஒரு வேலையில இருந்து அடுத்ததுக்கு leak ஆகும்.
- **Scripted tools-ல CSS-path selectors.** சின்ன layout மாற்றங்கள்ல உடையும்; labels, roles-ஐ விரும்புங்க.

## Computer-use agent-ஐ use பண்ணக்கூடாத நேரங்கள்

- **ஒரு API அல்லது export இருக்கு**, அல்லது vendor-கிட்ட கேட்டு வாங்க முடியும்.
- **Steps fixed-ஆ இருக்கு**: ஒரு scripted Playwright tool வேகம், மலிவு, அதிக நம்பகத்தன்மை.
- **Site தன்னோட terms-ல automation-ஐ தடை பண்ணுது**, அல்லது அதை தடுக்க captchas use பண்ணுது.
- **தப்புகள் செலவானவை, கண்டுபிடிக்க கஷ்டமானவை**, tax filings மாதிரி, ஒவ்வொரு submission-ஐயும் ஒரு ஆள் check பண்ணாதவரை.

## Demo-ல இருந்து production-க்கு

- **ஒவ்வொரு session-ஐயும்** ஒரு allow list-ஓட, ஒரு dedicated account-ஓட, ஒரு புது container-ல isolate பண்ணுங்க.
- **ஒவ்வொரு run-ஓட screenshots அல்லது video-வை record பண்ணுங்க**, audits-க்கு தேவையான வரை வச்சிருங்க.
- எந்த submit, pay, send, delete-க்கு முன்னாடியும் **approval கேளுங்க**.
- **ஒவ்வொரு step-க்கும் success, hand-back rate-ஐ track பண்ணுங்க**, அதிகம் fail ஆகுற pages-ஐ script பண்ணுங்க.
- **Site மாற்றங்களை monitor பண்ணுங்க**: ஒவ்வொரு portal-லயும் தினசரி scripted check, users-க்கு முன்னாடியே layout மாற்றங்களை பிடிக்கும்.

## Practice பண்ணுங்க

Computer-use tool docs-ஐயும் Playwright-ஓட getting-started page-ஐயும் படிங்க.

1. ஒரு public site-ல ஒரு browser task-ஐ Playwright-ல script பண்ணுங்க (உதாரணம், ஒரு government website-ல இருந்து சமீபத்திய notices-ஐ எடுக்குறது), அதை ஒரு agent-க்கு ஒரே tool-ஆ expose பண்ணுங்க.
2. ஒரு browser அல்லது computer-use agent-ஐ ஒரு container-ல, ஒரு பாதிப்பில்லாத task-ல, ஒவ்வொரு step-க்கும் screenshots save பண்ணி ஓட்டுங்க.
3. எந்த form submission-க்கும் முன்னாடி ஒரு approval step சேருங்க, ஒரு மறைஞ்ச instruction இருக்குற page-ல test பண்ணுங்க.
4. உங்க scripted tool-ல allow-list route-ஐ சேருங்க, அப்புறம் வேற site-ல இருந்து ஒரு script load பண்ற page-ஐ அதுக்கு காட்டி, அந்த request block ஆகுதான்னு confirm பண்ணுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** ஒவ்வொரு step-க்கும் ladder-ல எந்த rung-ஐ use பண்ணீங்க, ஏன்னு explain பண்ண முடியும்.
