## இது என்ன

Forward deployed engineers-ஐ hire பண்ற companies (AI labs, AI startups, data platforms, AI practices build பண்ற consultancies) வேற வேற loops use பண்ணுது, ஆனா பெரும்பாலானவற்றுல இந்த rounds சில இருக்கும்:

- **Coding**: puzzle-heavy-ஆ இல்லாம practical. ஒரு குழப்பமான file-ஐ parse பண்ணுங்க, ஒரு API-ஐ call பண்ணுங்க, ஒரு சின்ன service எழுதுங்க, code-ஐ debug பண்ணுங்க.
- **Problem decomposition**: ஒரு தெளிவில்லாத business problem ("ஒரு hospital discharge delays-ஐ குறைக்க விரும்புது") அதை கேள்விகள், ஒரு plan, ஒரு design-ஆ மாத்த 45 நிமிஷம்.
- **System design**: ஆரம்பம் முதல் முடிவு வரை ஒரு AI system: data, retrieval, models, evals, deployment, security, cost.
- **Client role-play அல்லது case**: ஒரு interviewer சந்தேகப்படுற, கோரிக்கை வைக்குற, requirements மாத்துற client-ஆ நடிப்பாரு; நீங்க கேட்கணும், clarify பண்ணணும், மறுக்கணும், next steps-ஐ ஒத்துக்கணும்.
- **Behavioural**: ownership, மோதல், தெளிவின்மை, failure, கத்துக்கிறதை காட்டுற கடந்த சூழ்நிலைகள்.
- **Take-home அல்லது work sample**: ஒரு சின்ன project அல்லது எழுத்துபூர்வ proposal, சில சமயம் present பண்ணுவீங்க.

| Round | எதை test பண்ணும் |
|---|---|
| Coding | Practical: parse, API call, ஒரு சின்ன service, structured output, tests |
| Decomposition | ஒரு தெளிவில்லாத problem: கேள்விகள், KPI, baseline, options, gate-ஓட ஒரு POC, risks |
| System design | Data, retrieval, models, evals, guardrails, deploy, cost |
| Client role-play | கேளுங்க, summarise பண்ணுங்க, கோரிக்கைக்கு பின்னாடி இருக்குற தேவை, options, next steps |
| Behavioural | 6-8 STAR கதைகள், ஒவ்வொண்ணுலயும் ஒரு number, ஒரு lesson |
| Take-home | ஒரு சின்ன project அல்லது proposal, சில சமயம் present பண்ணுவீங்க |

## இது எப்படி work ஆகுது

**Coding.** Python-ல யதார்த்தமான tasks practice பண்ணுங்க: மோசமான rows உள்ள CSV, JSON படிக்கிறது, validation-ஓட ஒரு FastAPI endpoint எழுதுறது, structured output, retries-ஓட ஒரு LLM API use பண்றது, tests எழுதுறது. வேலை செய்யும்போதே பேசுங்க; வேகத்தை போலவே தெளிவும் முக்கியம்.

**Problem decomposition.** Discovery mindset-ஐ சத்தமா use பண்ணுங்க:

1. Goal-ஐயும் அதை யார் முக்கியம்னு நினைக்கிறாங்கன்னும் clarify பண்ணுங்க.
2. இப்போதைய process, volumes, data பத்தி கேளுங்க.
3. அளக்கக்கூடிய ஒரு KPI, baseline-ஐ முன்மொழியுங்க.
4. Non-AI உட்பட options-ஐ list பண்ணி, காரணங்களோட ஒண்ணை தேர்ந்தெடுங்க.
5. Gate-ஓட ஒரு proof of concept-ஐ plan பண்ணுங்க.
6. Risks-ஐயும் அவற்றை எப்படி குறைப்பீங்கன்னும் சொல்லுங்க.

Interviewers தேடுறது structured thinking, நல்ல கேள்விகள்; ஒரு perfect answer இல்ல.

**System design.** முழு path-ஐயும் cover பண்ணுங்க: ingestion, retrieval, prompting, evals, guardrails, permissions, deployment model, observability, cost, failure handling. Trade-offs-ஐ வெளிப்படையா சொல்லுங்க ("இங்க hybrid search, ஏன்னா users policy codes-ஐ type பண்றாங்க").

**Client role-play.** முதல்ல கேட்டு, நீங்க என்ன கேட்டீங்கன்னு summarise பண்ணுங்க. ஒரு கோரிக்கைக்கு பின்னாடி இருக்குற அடிப்படை தேவையை கேளுங்க. அங்கேயே வாக்குறுதி தராதீங்க; options, trade-offs தாங்க. "Client" அழுத்தும்போது அமைதியா இருங்க. ஒத்துக்கிட்ட next steps-ஓட முடிங்க.

**Behavioural.** STAR (situation, task, action, result) use பண்ணி, numbers-ஓடயும் நீங்க கத்துக்கிட்டதோடயும் ஆறு முதல் எட்டு கதைகளை தயார் பண்ணுங்க. இவற்றை cover பண்ணுங்க: ஆரம்பம் முதல் முடிவு வரை நீங்க நடத்தின ஒரு project, ஒரு stakeholder-ஓட நீங்க முரண்பட்ட நேரம், ஒரு failure, நீங்க இல்லன்னு சொன்ன நேரம், தெளிவின்மையோட வேலை செய்தது, ஏதோ ஒண்ணை வேகமா கத்துக்கிட்டது.

**உங்க சொந்த கேள்விகள்.** FDEs எவ்வளவு நேரம் travel அல்லது on-site-ல செலவழிக்கிறாங்க, projects எப்படி தேர்ந்தெடுக்கப்படுது, FDEs product-க்கு எப்படி feedback தர்றாங்க, success எப்படி அளக்கப்படுதுன்னு கேளுங்க.

| --- | --- | --- |

| "இந்த feature-ஐயும் சேருங்க" | அங்கேயே ஒத்துக்கிறது | "நான் size பண்ணி வியாழக்கிழமைக்குள்ள options-ஓட வர்றேன்" |
| உங்க proposal-க்கு அப்புறம் அமைதி | தொடர்ந்து பேசுறது | நேரடியா ஒரு கேள்வி கேளுங்க: "இதுல எது உங்க board timeline-க்கு பொருந்தும்?" |

**Numbers-ஓட ஒரு STAR கதை.** Situation: "எங்க team-ஓட மாசாந்திர sales report-க்கு மூணு நாள் manual spreadsheet வேலை ஆச்சு." Task: "அதை வேகப்படுத்த சொன்னாங்க." Action: "Steps-ஐ map பண்ணி, data pulls, checks-ஐ Python-ல automate பண்ணி, analysts review பண்ற ஒரு validation step-ஐ சேர்த்தேன்." Result: "இப்போ நாலு மணி நேரம் ஆகுது, release-க்கு அப்புறம் கண்டுபிடிக்கப்பட்ட errors மாசம் ஐந்துல இருந்து மூணு மாசத்துல zero ஆச்சு." Lesson: "Analysts-ஐ முன்னாடியே ஈடுபடுத்தியிருக்கணும்; நான் தவறவிட்ட ரெண்டு edge cases அவங்க checks-ல பிடிபட்டுச்சு."

**Decomposition-க்கு தயாராகுறது.** இந்திய business problems-ஐ எடுத்து, 30 நிமிஷ timer வச்சு, எந்த solution-க்கும் முன்னாடி உங்க கேள்விகளை சத்தமா சொல்லுங்க. Record பண்ணி திரும்ப கேளுங்க: எதையாவது முன்மொழியுறதுக்கு முன்னாடி எத்தனை நிமிஷம் ஆச்சுன்னு எண்ணுங்க. அது ஐந்துக்கு கீழ இருந்தா, ரொம்ப வேகமா குதிச்சுட்டீங்க.

Decomposition-க்கு "ஒரு மாநில transport corporation குறைவான complaints வேணும்னு விரும்புது" மாதிரி prompts-ஓட practice பண்றாரு; தன் கேள்விகளை சத்தமா சொல்லி தனக்கே time பண்றாரு.

Client role-play-ல interviewer சொல்றாரு: "உங்க pilot ரொம்ப மெதுவா இருக்கு. எங்க MD அடுத்த வாரம் எல்லா branches-க்கும் live ஆகணும்னு விரும்புறாரு." Arjun கவலையை summarise பண்ணி, deadline-ஐ தூண்டினது என்னன்னு (ஒரு board meeting) கேட்டு, அடுத்த வாரம் full rollout என்ன risk தரும்னு (security review முடியல, ரெண்டு branches 50%-க்கு கீழ adoption) விளக்கி, options தர்றாரு: pilot results-ஓட அடுத்த வாரம் ஒரு board demo, மூணு-wave rollout plan, அல்லது நல்லா தயாரான ஐந்து branches-க்கு rollout. அவரு அடிபணியவும் இல்ல, மறுக்கவும் இல்ல; இது தன் loop-ல மிக வலுவான பகுதின்னு interviewer பின்னாடி சொல்றாரு.

அவரோட ஒவ்வொரு behavioural கதையிலயும் ஒரு number இருக்கு: "report preparation-ஐ 3 நாள்ல இருந்து 4 மணி நேரமா குறைச்சேன்", "failed jobs-ஐ 12%-ல இருந்து 1%-ஆ குறைச்சேன்".

| --- | --- |

| Decomposition | "ஒரு மாநில transport corporation குறைவான complaints வேணும்னு விரும்புது" மாதிரி prompts-ல timed practice |

## பொதுவா பண்ற தப்புகள்

- **Coding-க்கு மட்டும் தயாராகுறது.** FDE offers-ஐ பெரும்பாலும் தீர்மானிக்கிறது decomposition, role-play rounds.
- **Solution-க்கு குதிக்கிறது.** முதல்ல கேள்விகள் கேளுங்க, சத்தமா.
- **Role-play-ல எல்லாத்துக்கும் ஆமான்னு சொல்றது.** Expectations-ஐ manage பண்ண முடியுமான்னு interviewers test பண்றாங்க.
- **Results இல்லாத கதைகள்.** ஒவ்வொரு கதைக்கும் ஒரு number அல்லது தெளிவான outcome, ஒரு lesson வேணும்.
- **பொதுவான system designs.** ஒவ்வொரு choice-ஐயும் scenario-ஓட constraints-ஓட இணைங்க.

## Practice பண்ணுங்க

Tech Interview Handbook-ஓட behavioural guide-ஐயும் FDE role பத்தின a16z essay-ஐயும் படிங்க.

1. உங்க சொந்த வேலை அல்லது projects-ல இருந்து, ஒவ்வொண்ணுக்கும் ஒரு result, ஒரு lesson-ஓட ஆறு STAR கதைகளை எழுதுங்க.
2. நீங்க தேர்ந்தெடுக்குற இந்திய business problems-ல, சத்தமா பேசி உங்களை record பண்ணி, மூணு timed decomposition exercises (ஒவ்வொண்ணும் 30 நிமிஷம்) பண்ணுங்க.
3. இந்த path-ஓட lessons-ல இருக்குற ஒரு scenario-வை வச்சு, ஒரு friend-ஐ கடினமான client-ஆ நடிக்க சொல்லுங்க; கேட்கிறது, clarify பண்றது, options தர்றது, முடிக்கிறதை practice பண்ணுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** பார்த்திராத ஒரு business problem-ஐ 30 நிமிஷத்துல, சத்தமா, கேள்விகள், ஒரு KPI, ஒரு POC plan-ஆ உடைக்க முடியும்.
