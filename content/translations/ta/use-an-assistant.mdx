## இது என்ன

AI-ஐ கத்துக்க எல்லாத்தையும் விட வேகமான வழி, அதை தினமும் ஒரு real வேலைக்கு use பண்றது தான். ஒரு chat assistant-ஐ ஒரு **திறமையான புது colleague** மாதிரி நடத்தும்போது தான் அது எல்லாத்தையும் விட அதிகமா useful-ஆ இருக்கும்: அதுக்கு பொதுவா நிறைய தெரியும், ஆனா உங்க situation, உங்க customers, உங்க company பத்தி எதுவும் தெரியாது. நீங்க அதுக்கு brief பண்றீங்க, அதோட வேலையை review பண்றீங்க, முக்கியமான எதையும் check பண்றீங்க.

இதோட பகுதிகளை மத்த lessons விரிவா சொல்லுது: "Jargon இல்லாத prompting" brief எழுதுறதை சொல்லுது, "AI-ஆல என்ன பண்ண முடியாது" limits-ஐ சொல்லுது, "AI பதிலை check பண்றது" verification-ஐ சொல்லுது. இந்த lesson இவை எல்லாத்தையும் இணைக்குற **daily practice** பத்தினது:

- ஒரு assistant-ஐ தேர்ந்தெடுத்து அதோட controls-ஐ கத்துக்குறது,
- ஒவ்வொரு task-க்கும் சரியான feature-ஐ தேர்ந்தெடுக்குறது (new chat, web search, attach பண்ண ஒரு file, voice),
- Assistant drift ஆகாம இருக்க chats-ஐ ஒழுங்கா வெச்சுக்குறது,
- உங்க privacy settings எதை பாதுகாக்கும், எதை பாதுகாக்காதுன்னு தெரிஞ்சுக்குறது.

```flow
title: Assistant கூட ஒரு daily loop
dir: LR
தேர்ந்தெடு | new chat, search on அல்லது off, file attach பண்ணணுமா? -> Brief | யாருக்கு, task, context, format
Brief -> Review | நான் கேட்டது தானா?
Review -[குறிப்பான feedback]-> Brief
Review -> Check | யாராவது நம்பி use பண்ணப்போற claims
Check -> Save | Work ஆன prompt-ஐ வெச்சுக்கோ
```

இந்த lesson-ஓட check ஒரு சின்ன project. உங்க சொந்த வேலையில இருந்து ஒரு task-ஐ மூணு விதமா run பண்ணி, ஒவ்வொரு answer-லயும் ஒரு claim-ஐ check பண்ணி, நீங்க கத்துக்கிட்டதை எழுதுவீங்க. Chennai-ல ஒரு broadband company-ல customer support-ல வேலை பார்க்குற Rohit அதையே பண்றதை நீங்க follow பண்ணுவீங்க.

| --- | --- | --- |
| ChatGPT | OpenAI | Free plan-ல web search இருக்கு, ஆனா paid plans-ஐ விட file uploads-க்கும் voice-க்கும் limits குறைவு |

Free plans-ல இருக்குற limits அடிக்கடி மாறும், அதனால ஒரு பழைய article-ஐ நம்பாம app-க்குள்ள இருக்குற plan page-ஐ check பண்ணுங்க. ஒண்ணை தேர்ந்தெடுத்து, compare பண்றதுக்கு முன்னாடி ரெண்டு வாரம் அதை use பண்ணுங்க. இந்த lesson-ல வர்ற பழக்கங்கள் ஒரு assistant-ல இருந்து இன்னொண்ணுக்கு அப்படியே பொருந்தும்; நீங்க அதை எப்படி use பண்றீங்கங்குறதை விட brand ரொம்ப குறைவா தான் முக்கியம்.

Sign up பண்றதுக்கு முன்னாடி ரெண்டு எச்சரிக்கைகள்:

- **Free trials renew ஆகும்.** உதாரணமா, November 2025-ல OpenAI இந்தியால இருக்குற users-க்கு அதோட paid Go plan-ஐ ஒரு வருஷம் free-ஆ குடுத்துச்சு. இது மாதிரி offers, phone plans கூட bundle ஆகி வர்றதும் உட்பட, நீங்க cancel பண்ணலைன்னா normal விலைக்கு renew ஆகலாம். Sign up பண்ற அன்னைக்கே renewal date-ஐ note பண்ணிக்குங்க.
- **Work account-உம் personal account-உம் வேற வேற.** உங்க employer அல்லது college ஒரு approved assistant குடுத்தா, வேலைக்கு அதையே use பண்ணுங்க. Storage, training பத்தின அதோட terms உங்க சொந்த settings-ஆல இல்ல, ஒரு contract-ஆல முடிவாகுது. ஏன்னு "வேலையில AI-ஐ safe-ஆ use பண்ணுங்க" விளக்குது.

### முக்கியமான controls-ஐ கத்துக்குங்க

Daily use-ல இருக்குற skill-ல பெரும்பகுதி, எந்த control-ஐ எடுக்கணும்னு தெரிஞ்சுக்குறது தான். Assistant-க்கு assistant பேர்கள் மாறும், ஆனா கிட்டத்தட்ட எல்லாத்துலயும் இவை இருக்கு:

| Control | அது என்ன பண்ணும் | எப்போ use பண்ணணும் |
| --- | --- | --- |
| **New chat** | ஒரு clean slate-ல ஆரம்பிக்கும் | நீங்க வேற task ஆரம்பிக்கும்போது, அல்லது இப்போதைய chat drift ஆனப்போ |
| **Web search** | இப்போதைய pages-ஐ தேடி links-ஐ காட்டும் | Answer மாறிக்கிட்டே இருக்குற எதையாவது பொறுத்து இருந்தா: rates, prices, rules, dates, news |
| **File அல்லது photo attach பண்றது** | உங்க document, spreadsheet அல்லது screenshot-ஐ அதை படிக்க விடும் | Answer ஒரு குறிப்பிட்ட source-ஐ follow பண்ணணும்னா, உங்க company-யோட guide மாதிரி |
| **Voice input** | நீங்க பேசுறதை ஒரு prompt-ஆ மாத்தும் | Type பண்றது மெதுவா இருந்தா, அல்லது பேசும்போது இன்னும் நல்லா யோசிக்க முடிஞ்சா, உங்க சொந்த மொழியிலயும் கூட |
| **Thinking அல்லது reasoning mode** | Answer பண்றதுக்கு முன்னாடி ஒரு problem-ஐ அதிக நேரம் எடுத்து work out பண்ணும் | Multi-step problems, plans, calculations; ஒரு short email-க்கு தேவையில்ல |
| **Saved instructions அல்லது projects** | அதுக்கு எப்பவும் தெரிஞ்சிருக்க வேண்டிய background-ஐ வெச்சுக்கும் | உங்க role அல்லது உங்களுக்கு பிடிச்ச style மாதிரி ஒரே விஷயத்தை திரும்ப திரும்ப explain பண்ணிக்கிட்டே இருந்தா |
| **Temporary அல்லது incognito chat** | உங்க history-ல save ஆகாது, training-க்கு use ஆகாது | உங்க history-ல இருக்க வேண்டாம்னு நினைக்கிற ஒரு one-off கேள்வி |

ஒரு useful default: ஒவ்வொரு புது task-ஐயும் ஒரு new chat-ல ஆரம்பிங்க, facts சம்பந்தப்பட்ட எதுக்கும் search-ஐ on-லயே வெச்சிருங்க, source இருக்கும்போதெல்லாம் அதை attach பண்ணுங்க. Assistant-ஓட ஞாபகத்துல இருந்து build ஆன answer-ஐ விட, உங்க சொந்த source மேல build ஆன answer-ஐ check பண்றது ஈஸி.

### Brief பண்ணுங்க, அப்புறம் iterate பண்ணுங்க

ஒரு நல்ல **prompt**-ல நீங்க யார், அது யாருக்காக, என்ன task, assistant-க்கு தெரிய முடியாத context, உங்களுக்கு திரும்ப வேண்டிய format எல்லாம் இருக்கும். அப்புறம் முதல் answer-ஐ ஒரு draft-ஆ நினைச்சு குறிப்பான feedback குடுங்க, "cut it to 120 words and drop the second paragraph" மாதிரி. ஒரே ஒரு perfect prompt-ஐ எழுத முயற்சி பண்றதை விட ரெண்டு மூணு rounds பொதுவா நல்லா work ஆகும். "Jargon இல்லாத prompting" இதை முறையா சொல்லித் தருது; இங்க நீங்க அதை பண்ணா மட்டும் போதும்.

Daily வேலையில அடிக்கடி use பண்ண வேண்டிய ஒரு move இருக்கு: உங்க brief-ஐ "Before you start, ask me any questions you need answered."-னு முடிங்க. அப்போ assistant, இல்லைன்னா அது guess பண்ணியிருக்கக்கூடிய facts-ஐ உங்ககிட்ட கேக்கும்.

### Chats-ஐ ஒழுங்கா வெச்சுக்குங்க

ஒவ்வொரு assistant-க்கும் ஒரு **context window** இருக்கு: இதுவரைக்கும் நடந்த முழு conversation உட்பட, அது ஒரே நேரத்துல எடுத்துக்கக்கூடிய text-ஓட அளவு. ரொம்ப நீளமான chat-ல, ஆரம்பத்துல குடுத்த instructions நெரிசல்ல காணாம போகலாம், அதனால assistant அவற்றை ignore பண்ண ஆரம்பிக்கும். மூணு பழக்கங்கள் இதை தடுக்கும்:

- **ஒரு task, ஒரு chat.** உங்க CV-யும் உங்க current-affairs revision-உம் ஒரே conversation-ல இருக்கக் கூடாது.
- **ஒரு summary-ஓட restart பண்ணுங்க.** ஒரு chat drift ஆனா, "summarise what we agreed in five bullets"-னு கேட்டு, அதை ஒரு new chat-ல paste பண்ணுங்க.
- **திரும்ப திரும்ப சொல்றதை save பண்ணுங்க.** "I'm a final-year B.Com student; keep answers short" மாதிரி உங்க நிரந்தர background-ஐ saved instructions-லயோ ஒரு project-லயோ போடுங்க, அப்போ அதை திரும்ப type பண்ண வேண்டியதில்ல.

Work ஆன prompts-ஐ உங்க phone-ல ஒரு simple note-ஆ வெச்சுக்குங்க. ஒரு மாசம் கழிச்சு, அந்த note தான் உங்க personal toolkit.

### Files, photos, voice-ஐ கவனமா use பண்ணுங்க

**Files.** ஒரு document-ஐ attach பண்றது, answer உங்க source-ஐ follow பண்ண உதவும். ஆனா அதுக்கு guarantee இல்ல: document-ல இல்லாத, நம்பக்கூடிய மாதிரி தெரியுற ஒரு sentence-ஐ assistant இன்னும் சேர்க்கலாம். "say which section each step comes from"-னு கேளுங்க, அப்புறம் அந்த sections-ஐ நீங்களே spot-check பண்ணுங்க. Support இல்லாத அதோட சொந்த lines-ஐ assistant-ஏ flag பண்ணும்னு நம்பாதீங்க.

**Photos-உம் screenshots-உம்.** Names, phone numbers, account numbers, அதுக்கு தேவையில்லாத வேற எதையும் crop பண்ணி எடுத்துடுங்க. Assistants ஒரு photo-ல இருக்குற figures-ஐ தப்பா படிக்கலாம், அதனால numbers-ஐ original-ஓட ஒப்பிட்டு check பண்ணுங்க. Photos-ல இருந்து documents படிக்கிறதை "Images, voice, மத்த AI tools" இன்னும் விரிவா சொல்லுது.

**Voice-உம் Indian languages-உம்.** Voice input ஆரம்பிக்க ஒரு வேகமான வழி, நிறைய assistants Hindi-யையும் மத்த Indian languages-ஐயும் ஏத்துக்குது. உதாரணமா, June 2024-ல Google, Gemini app-ஐ இந்தியால ஒன்பது Indian languages-ஓட launch பண்ணுச்சு. அதை நம்புறதுக்கு முன்னாடி, நீங்க judge பண்ணக்கூடிய ஒரு task-ல உங்க மொழியில அதை test பண்ணுங்க, transcript-ஐ எப்பவும் படிங்க: speech recognition தடுமாறுறது names-லயும் numbers-லயும் தான்.

### உங்க privacy settings என்ன பண்ணும்னு தெரிஞ்சுக்குங்க

ஒவ்வொரு assistant-லயும், அதோட models-ஐ improve பண்ண உங்க chats use ஆகலாமான்னு control பண்ற ஒரு switch இருக்கு. November 2026 நிலவரப்படி, ChatGPT அதை "Improve the model for everyone"-னு சொல்லுது, Claude-ல அதோட privacy settings-ல ஒரு model-improvement setting இருக்கு, Gemini அதை அதோட Keep Activity setting-ல இருந்து ஒரு தனி training setting-க்கு மாத்திக்கிட்டு இருக்கு (Google இந்த மாற்றத்தை November 2026-ல announce பண்ணுச்சு, அதனால உங்க account-ல ரெண்டுல எதுவும் தெரியலாம்). அதை கண்டுபிடிச்சு, யோசிச்சு முடிவு பண்ணுங்க; default-க்கு விட்டுடாதீங்க.

இந்த settings என்ன பண்ணும்னு தெளிவா தெரிஞ்சுக்குங்க:

| Setting | அது எதை மாத்தும் | அது எதை மாத்தாது |
| --- | --- | --- |
| Model-improvement switch off | உங்க புது chats future models-ஐ train பண்ண use ஆகாது | Chats இன்னும் ஒரு காலம் வரைக்கும் store ஆகலாம், உதாரணமா safety checks-க்கு |
| Temporary அல்லது incognito chat | உங்க history-ல save ஆகாது, training-க்கு use ஆகாது | அது இன்னும் குறுகிய காலம் வெச்சிருக்கப்படும், அது இன்னும் ஒரு personal account தான் |

இந்த ரெண்டுல எதுவுமே, உங்க organisation approve பண்ணாத ஒரு tool-ல customer records, colleagues-ஓட personal details அல்லது confidential documents-ஐ paste பண்றதை சரின்னு ஆக்காது.

### எதை check பண்ணணும்னு முடிவு பண்ணுங்க

Assistants ஒரு **hallucination**-ஐ உருவாக்கலாம்: சரளமா, உறுதியா சொல்லப்படுற, ஆனா தப்பான ஒரு statement. எல்லாத்தையும் check பண்ண முடியாது, அதனால stakes-ஐ வெச்சு check பண்ணுங்க. ஒவ்வொரு claim பத்தியும் ரெண்டு கேள்வி கேளுங்க: "யாராவது இதை நம்பி use பண்ணுவாங்களா?", "இது தப்பா இருந்தா என்ன ஆகும்?" Numbers, dates, names, rules, prices, உங்க organisation-க்கே உரிய steps பொதுவா அந்த test-ல pass ஆகும்; பொதுவான wording-உம் ideas-உம் பொதுவா pass ஆகாது. "AI பதிலை check பண்றது" இன்னும் முழுமையான ஒரு method-ஐ குடுக்குது.

ஒரு இரண்டாவது assistant ideas-க்கும், கருத்து வேறுபாட்டை கண்டுபிடிக்கவும் useful. ரெண்டு assistants ஒரு fact-ல ஒத்துப்போகலைன்னா, அதை check பண்ணியே ஆகணும்னு உங்களுக்கு தெரியும். ஒத்துப்போனா, அது proof இல்ல: ரெண்டுமே ஒரே பழைய page-ல இருந்து கத்துக்கிட்டிருக்கலாம்.

## ஒரு worked example

Rohit, Chennai-ல ஒரு broadband company-ல customer support-ல வேலை பார்க்குறாரு. அவரோட manager ஒரு short help article கேக்குறாரு: "Why is my Wi-Fi slow?" அவரோட company customer data-க்கு எந்த AI tool-ஐயும் approve பண்ணல, அதனால அவரு தன்னோட personal free account-ஐயும், public material-ஐ மட்டும் use பண்றாரு: company website-ல இருக்குற router setup guide. Model-improvement switch-ஐ off-லயே வெச்சு, customer tickets-ஐ அதுல போடாம இருக்காரு.

அவரு task-ஐ மூணு விதமா run பண்றாரு, ஒவ்வொண்ணையும் ஒரு new chat-ல.

**Set-up 1: ஒரு line, features இல்ல.**

> "Write an article about slow Wi-Fi."

Result சுமார் 600 words, பொதுவானது, company விக்காத mesh Wi-Fi kits-ஐ recommend பண்ணுது.

**Set-up 2: ஒரு முழு brief.**

> "I work for a broadband provider in Chennai. Write a 250-word help article for home customers titled 'Why is my Wi-Fi slow?' Cover router placement, too many devices, and when to restart the router. Friendly, simple English, numbered steps, no brand names."

Result சரியான நீளம், சரியான tone. ஒரு line சொல்லுது: "Restart your router once a week to keep it fast."

**Set-up 3: அதே brief, கூட company-யோட guide attach பண்ணி.** அவரு இதை சேர்க்குறாரு:

> "Use only the attached setup guide for steps and settings, and say which section each step comes from."

இந்த version, router-ஓட ரெண்டு bands-க்கு இடையில switch பண்றதுக்கு guide-ஓட சொந்த steps-ஐ use பண்ணுது, weekly-restart line போயிடுச்சு. ஆனா அது இதை சேர்க்குது: "The 5 GHz band covers the whole house." Rohit cite பண்ண section-ஐ check பண்றாரு. Guide அதுக்கு நேர் எதிரா சொல்லுது: 5 GHz router-க்கு பக்கத்துல இன்னும் வேகமா இருக்கும், 2.4 GHz அதிக தூரம் போகும், அதனால தூரத்துல இருக்குற rooms-க்கு 2.4 GHz-ல இன்னும் நல்லா இருக்கலாம். அந்த section சொல்லாத ஒரு claim-க்கு assistant ஒரு real section-ஐ cite பண்ணியிருந்துச்சு.

**Check பண்றது.** Weekly restart பத்தி அவரு network team-கிட்ட கேக்குறாரு. ஏதாவது problem இருக்கும்போது மட்டும் தான் restart தேவை, weekly restarts தேவையில்லாத support calls-க்கு வழி வகுக்குதுன்னு அவங்க சொல்றாங்க.

அவரோட write-up இது; உங்க project write-up-உம் இதே வடிவத்துல தான் இருக்கணும்:

| Set-up | Check பண்ண claim | Source | Verdict | Use பண்ணாரா? |
| --- | --- | --- | --- | --- |
| 1. ஒரு line | Mesh kits-ஐ recommend பண்ணுது | Company product page | எங்களுக்கு தப்பு: நாங்க அதை விக்கிறதில்ல | இல்ல |
| 2. முழு brief | "Restart your router once a week" | Network team | தப்பு | கிட்டத்தட்ட |
| 3. Brief கூட guide | "The 5 GHz band covers the whole house" | Setup guide, cite பண்ண section | தப்பு: 2.4 GHz அதிக தூரம் போகும்னு guide சொல்லுது | ஆமா, check பண்ணதுக்கு அப்புறம் சரி பண்ணி |

**அவரு எடுத்த முடிவு:** "Help articles-க்கு எப்பவும் எங்க சொந்த guide-ஐ attach பண்ணுவேன், ஏன்னா அது restart error-ஐ நீக்கிச்சு, எங்க router-க்கு பொருந்துச்சு. ஆனா ஒவ்வொரு step-ஐயும் அது cite பண்ற section-ஓட ஒப்பிட்டு இன்னும் check பண்ணுவேன், ஏன்னா guide-ஐ attach பண்ணது அது ஒரு தப்பான line-ஐ சேர்க்குறதை தடுக்கல." Article review-க்கு அவரோட manager-கிட்ட போச்சு, அடுத்த வாரம் publish ஆச்சு.

எது வித்தியாசத்தை உண்டாக்குச்சுன்னு கவனிங்க. இன்னும் நல்ல prompt fit-ஐ சரி பண்ணுச்சு; attach பண்ண source பெரும்பாலான facts-ஐ சரி பண்ணுச்சு; மிச்சத்தை check பண்றது மட்டும் தான் பிடிச்சுது.

## பொதுவா பண்ற தப்புகள்

- **எல்லாத்தையும் ஒரே நீளமான chat-ல run பண்றது.** ஒவ்வொரு task-க்கும் ஒரு new chat start பண்ணுங்க, drift ஆனா ஒரு summary-ஓட restart பண்ணுங்க.
- **Search off-ல இருக்கும்போது current facts பத்தி கேக்குறது.** Rates, rules, prices-க்கு search வேணும், அதுக்கு அப்புறமும் நீங்க link-ஐ open பண்ணணும்.
- **ஒரு citation-ஐ proof-ஆ நினைக்கிறது.** Cite பண்ண page அல்லது section, assistant சொல்றதை சொல்லாம இருக்கலாம். அதை படிங்க.
- **Attach பண்ண file answer-ஐ சரியாக்கிடும்னு நினைக்கிறது.** அது உதவும்; சேர்க்கப்படுற claims-ஐ அது தடுக்காது.
- **Voice transcript-ஐ நம்புறது.** அதை வெச்சு மேல build பண்றதுக்கு முன்னாடி, படிச்சு names-ஐயும் numbers-ஐயும் சரி பண்ணுங்க.
- **Temporary chat confidential data-வை safe ஆக்கும்னு நினைக்கிறது.** அது history-ஐயும் training-ஐயும் தான் மாத்தும், நீங்க அந்த data-வை share பண்ணலாமாங்குறதை இல்ல.
- **Defaults-ஐ மாத்தவே மாத்தாம இருக்குறது.** Model-improvement switch-ஐ கண்டுபிடிச்சு யோசிச்சு முடிவு பண்ணுங்க.
- **ஒரு trial-ஓட renewal date-ஐ மறக்குறது.** Free offers அடிக்கடி paid plans-ஆ மாறும்.

## Practice பண்ணுங்க

கீழே link பண்ணியிருக்குற AI Fluency course-ஐ எடுங்க. அதோட delegation, description, discernment, diligence ideas இந்த lesson-ஓட daily loop-ஓட ஒத்துப்போகுது.

அப்புறம் இந்த lesson-ஓட project-ஐ பண்ணுங்க:

1. **Set up பண்ணுங்க.** ஒரு assistant-ஐ தேர்ந்தெடுங்க. அதோட new chat, web search, file upload, voice, model-improvement controls-ஐ கண்டுபிடிச்சு, உங்க privacy setting-ஐ முடிவு பண்ணுங்க.
2. **ஒரு task-ஐ எடுங்க**, உங்க சொந்த வேலையில இருந்தோ படிப்புல இருந்தோ: அதுல குறைஞ்சது ஒரு check பண்ணக்கூடிய fact இருக்கணும், personal அல்லது confidential data எதுவும் இருக்கக் கூடாது, நீங்களே judge பண்ணக்கூடியதா இருக்கணும்.
3. **அதை மூணு விதமா run பண்ணுங்க**, ஒவ்வொண்ணையும் ஒரு new chat-ல: ஒரு one-line prompt; ஒரு முழு brief; முழு brief கூட task-க்கு தேவையான feature (current facts-க்கு web search, உங்க சொந்த document attach பண்ணி, அல்லது "ask me questions first").
4. **ஒவ்வொரு answer-லயும் ஒரு claim-ஐ check பண்ணுங்க**, நீங்க நம்புற ஒரு source-ஓட: ஒரு official website, original document, அல்லது விஷயம் தெரிஞ்ச ஒருத்தர்.
5. **அதை எழுதுங்க**, Rohit-ஓடது மாதிரி ஒரு table-ஆ, ரெண்டு அல்லது மூணு sentence conclusion-ஓட.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** உங்க write-up இதையெல்லாம் காட்டும்போது:

- மூணு prompts-உம் வார்த்தைக்கு வார்த்தை, அவற்றோட answers-ஓட;
- ஒவ்வொரு answer-க்கும் check பண்ண ஒரு claim, source-ஓட பேரோடயும் ஒரு verdict-ஓடயும்: சரி, தப்பு, அல்லது confirm பண்ண முடியல;
- அடுத்த தடவை இந்த மாதிரி task-க்கு எந்த set-up-ஐ use பண்ணுவீங்கன்னு சொல்ற ஒரு conclusion; எந்த answer எல்லாத்தையும் விட நல்லா இருந்த மாதிரி தெரிஞ்சுதுங்குறதை வெச்சு இல்ல, உங்க checks கண்டுபிடிச்சதை வெச்சு.
