## இது என்ன

**n8n** ("n-eight-n"ன்னு உச்சரிக்கணும்) ஒரு visual editor இருக்குற workflow automation tool. ஒரு canvas-ல **nodes**-ஐ வச்சு arrows-ஆல connect பண்றீங்க. **Trigger** node workflow-ஐ start பண்ணும், அடுத்து வர்ற ஒவ்வொரு node-உம் ஒரு வேலையை பண்ணும்: sheet-ஐ படிக்கிறது, app-ஐ call பண்றது, data-வை மாத்துறது, ஒரு condition-ல branch ஆகுறது, இல்லன்னா AI model-ஐ call பண்றது.

Data, nodes-க்கு நடுவுல **items** list-ஆ ஓடுது. ஒவ்வொரு item-உம் ஒரு spreadsheet-ஓட ஒரு row மாதிரி, ஒரு சின்ன JSON record:

```flow
Trigger: புது sheet row | name "Rohan", phone "98xx", course "JEE" -> Edit Fields: data-வை tidy பண்ணு | phone "+9198xx" ஆகுது
Edit Fields: data-வை tidy பண்ணு -> If: course JEE-ஆ?
If: course JEE-ஆ? -[ஆமா]-> Gmail: JEE welcome
If: course JEE-ஆ? -[இல்லை]-> Gmail: NEET welcome
Gmail: JEE welcome -> Telegram: counsellors-க்கு சொல்லு
Gmail: NEET welcome -> Telegram: counsellors-க்கு சொல்லு
```

n8n-ஓட hosted cloud version-ஐ use பண்ணலாம், இல்லன்னா Docker மாதிரி ஏதாவது வச்சு நீங்களே ஓட்டலாம். நிறைய companies இதை விரும்புறாங்க, ஏன்னா data அவங்க சொந்த servers-ல இருக்கும்.

இந்த lesson Jaipur-ல ஒரு coaching institute-ல admissions-ஐ manage பண்ற Shalini, தன்னோட முதல் workflow-ஐ build பண்றதை follow பண்ணும். முடிக்கும் போது, உங்களுக்கான ஒரு workflow-ஐ build பண்ணி, test பண்ணி, publish பண்ணுவீங்க.

## இது எப்படி work ஆகுது

### Triggers

ஒவ்வொரு workflow-உம் ஒரு trigger-ல ஆரம்பிக்கும். ஒரு workflow-ல ஒண்ணுக்கு மேல trigger இருக்கலாம், ஆனா ஒவ்வொரு run-உம் அதுல ஒண்ணுல இருந்து தான் ஆரம்பிக்கும். பொதுவானவை:

| Trigger | எப்போ fire ஆகும் | உதாரண use |
| --- | --- | --- |
| Schedule | ஒரு set நேரம் வரும்போது | தினமும் காலை 9 மணிக்கு report அனுப்புறது |
| Webhook | வேற app ஒரு URL-ஐ call பண்ணும்போது | ஒரு payment app புது payment-ஐ report பண்றது |
| Email (IMAP அல்லது Gmail) | புது email வரும்போது | accounts@-க்கு வர்ற invoices-ஐ process பண்றது |
| Form அல்லது Sheets | புது submission அல்லது row வரும்போது | புது admission enquiry |
| Manual | நீங்க "Execute workflow"-ஐ click பண்ணும்போது | Build பண்ணவும் test பண்ணவும் |

### Nodes

Nodes மூணு குடும்பங்கள்:

- **App nodes:** Gmail, Google Sheets, Slack, Telegram, WhatsApp Business, HubSpot, இன்னும் நூத்துக்கணக்கானவை.
- **Core nodes:** எந்த API-க்கும் HTTP Request, சின்ன scripts-க்கு Code, data-வை மாத்த Edit Fields (Set-னும் சொல்வாங்க), branch பண்ண If, Switch, சேர்க்க Merge, batches-ல process பண்ண Loop.
- **AI nodes:** extract, classify, summarise, draft பண்ண language model-ஐ call பண்றது, இல்லன்னா ஒரு agent-ஐ build பண்றது.

### Credentials

ஒவ்வொரு app node-க்கும் ஒரு **credential** வேணும்: அந்த app-க்கு சேமிச்சு வச்ச access, பொதுவா OAuth-ல sign in பண்ணி அல்லது ஒரு API key-ஐ paste பண்ணி. n8n credentials-ஐ encrypt பண்ணி store பண்ணும், பல workflows-ல திரும்ப use பண்ண விடும். உங்க சொந்த admin account-ஐ இல்லாம, workflow-க்கு தேவையான access மட்டும் இருக்குற ஒரு தனி account-ஐ use பண்ணுங்க.

### Nodes-க்கு நடுவுல data-வை map பண்றது

ஒரு node-ஓட settings-ல, முந்தைய nodes-ல இருந்து எந்த data-வை use பண்றதுன்னு தேர்ந்தெடுக்குறீங்க. Input panel-ல இருந்து ஒரு field-ஐ drag பண்ணலாம், இல்லன்னா double curly braces-குள்ள ஒரு **expression** எழுதலாம். உதாரணம்: தற்போதைய item-ஓட email field-க்கு `{{ $json.email }}`. ஒவ்வொரு node-உம் என்ன உருவாக்குச்சுன்னு output panel சரியா காட்டும்; அதனால தப்புகளை பார்க்குறது ஈஸி.

### Testing

Sample data-வோட editor-ல இருந்து workflow-ஐ ஓட்டுங்க. ஒவ்வொரு node-ஐயும் click பண்ணி அதோட input, output-ஐ பாருங்க, mapping பிரச்சனைகளை ஒரு நேரத்துக்கு ஒரு node-ஆ சரி பண்ணுங்க. Trigger-ஓட test data-வை **pin** பண்ணுங்க; அப்போ ஒவ்வொரு தடவையும் புது email அனுப்பாம, புது row சேர்க்காம, முழு workflow-ஐயும் திரும்ப ஓட்டலாம்.

### Publishing

வேலை செய்யும்போது, workflow-ஐ **publish** பண்ணுங்க. (n8n 2.0-க்கு முன்னாடி இது ஒரு Active toggle.) அப்புறம் production triggers தானா ஓடும். **Executions list** ஒவ்வொரு run-ஐயும், அதோட data, errors-ஓடயும் காட்டும்.

```flow
dir: LR
Build பண்ணு -> Pinned data-வோட test பண்ணு -> Fix பண்ணு -> Publish பண்ணு -> Executions-ஐ கவனி
Fix பண்ணு -[திரும்ப test பண்ணு]-> Build பண்ணு
```

## ஒரு நாள், ஒரு example

Shalini Jaipur-ல ஒரு coaching institute-ஓட admissions-ஐ பார்க்குறாங்க. Enquiries ஒரு Google Form வழியா வருது; அதோட responses ஒரு sheet-குள்ள போகுது. இப்போ counsellors நாளுக்கு ஒரு தடவை sheet-ஐ பார்த்து, அடுத்த நாள் காலையில students-ஐ call பண்றாங்க. அவங்க தன்னோட முதல் workflow-ஐ build பண்றாங்க:

| # | Node | என்ன பண்ணும் |
| --- | --- | --- |
| 1 | Google Sheets trigger | Responses sheet-ல புது row சேர்க்கும்போது fire ஆகும் |
| 2 | Edit Fields | Spaces-ஐ trim பண்ணி, phone-ஐ +91-ஓட format பண்ணி, name-ஐ capitalise பண்ணும் |
| 3 | If | Course "JEE" அல்லது "NEET"-ஆ? |
| 4 | Gmail (ரெண்டு branches) | Student-ஓட பேரை use பண்ணி, brochure link-ஓட, course-க்கு ஏத்த welcome email அனுப்பும் |
| 5 | Telegram | "New JEE enquiry: Rohan Sharma, +91 98xxxxxx45, prefers evening batch"-ஐ counsellors-ஓட group-ல post பண்ணும் |

**Testing.** மூணு sample rows-ஐ pin பண்ணி workflow-ஐ ஓட்டுறாங்க. ரெண்டு சரியா போகுது. மூணாவதுல, ஒரு student "jee"-ன்னு lower case-ல type பண்ணிருக்காங்க; அது தப்பான branch-ல போய் NEET email வாங்குது. அவங்க If node-ஐ lower case-ல compare பண்ற மாதிரி மாத்துறாங்க, மூணும் pass ஆகுது.

Empty phone number-ஐயும் try பண்றாங்க. Telegram message "phone: undefined"ன்னு வருது; counsellors-ஐ குழப்பும். அதனால ஒரு default சேர்க்குறாங்க: "phone not given, reply by email".

**Publishing.** Workflow-ஐ publish பண்றாங்க. அடுத்த நாள் காலையில executions list 14 successful runs-ஐ காட்டுது; counsellors புது students-ஐ அடுத்த நாள் இல்லாம, ஒரு மணி நேரத்துக்குள்ள call பண்ணியிருக்காங்க.

| Measure | முன்னாடி | அப்புறம் |
| --- | --- | --- |
| Enquiry-ல இருந்து welcome email வரைக்கும் நேரம் | அடுத்த நாள், கையால | ஒரு நிமிஷத்துக்கு கீழ |
| Counsellor call வரைக்கும் நேரம் | அடுத்த நாள் காலை | ஒரு மணி நேரத்துக்குள்ள |
| Miss ஆன enquiries | வாரத்துக்கு சில | முதல் வாரத்துல எதுவும் இல்லை |

## பொதுவா பண்ற தப்புகள்

- **Happy path-ஐ மட்டும் test பண்றது.** Empty fields, வித்தியாசமான spellings, extra spaces, duplicates-ஐயும் try பண்ணுங்க.
- **Credentials-க்கு உங்க சொந்த admin account-ஐ use பண்றது.** Limited access இருக்குற ஒரு தனி account-ஐ use பண்ணுங்க.
- **மாறக்கூடிய values-ஐ code-குள்ளயே எழுதிடுறது.** Email templates, chat IDs, prices-ஐ edit பண்ணக்கூடிய ஒரே இடத்துல வைங்க.
- **Publish பண்ண மறக்குறது.** Test mode-ல மட்டும் ஓடுற workflow யாருக்கும் எதுவும் பண்ணாது.
- **Error alert இல்லாம இருக்குறது.** அதை நம்புறதுக்கு முன்னாடி, ஒரு run fail ஆகும்போது உங்களுக்கு message அனுப்புற error workflow-ஐ சேருங்க.
- **Item counts-ஐ கவனிக்காம விடுறது.** ஒரு node திடீர்னு zero items தர்றது அடிக்கடி வர்ற அமைதியான failure; counts-ஐ check பண்ணுங்க.

## Practice பண்ணுங்க

n8n-ஓட quickstart-ஐ பண்ணுங்க, அப்புறம் கீழே link பண்ணியிருக்குற அதோட N8N101 Essentials course-ஐ பண்ணுங்க.

1. **Build பண்ணுங்க.** Pinned test data-வோட, ஒரு trigger, குறைஞ்சது data-வை tidy பண்ற ஒரு node, ஒரு branch, ரெண்டு app actions இருக்குற ஒரு workflow-ஐ build பண்ணுங்க.
2. **உடைச்சு பாருங்க.** மூணு bad inputs கொடுங்க: missing field, வித்தியாசமான spelling, duplicate. ஒவ்வொண்ணையும் fix பண்ணுங்க.
3. **Publish பண்ணுங்க.** Publish பண்ணி, சில real அல்லது simulated runs-க்கு அப்புறம் executions list-ஐ பாருங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** உங்க workflow-ல ஒவ்வொரு node-ஓட input, output-ஐயும் explain பண்ணி, ஒரு வெற்றிகரமான automatic run-ஐ காட்ட முடியும்.
