## இது என்ன

**n8n** ("n-eight-n"-னு சொல்லணும்) ஒரு visual editor இருக்குற workflow automation tool. ஒரு canvas-ல **nodes**-ஐ வச்சு, arrows-ஆல அவற்றை இணைக்கிறீங்க. ஒரு **trigger** node ஒவ்வொரு run-ஐயும் ஆரம்பிக்கும், அதுக்கு அப்புறம் வர்ற ஒவ்வொரு node-உம் ஒரு வேலை செய்யும்: ஒரு sheet-ஐ படிக்கும், data-வை சுத்தம் பண்ணும், ஒரு condition-ஐ வச்சு branch பண்ணும், ஒரு email அனுப்பும்.

Data ஒரு node-ல இருந்து அடுத்த node-க்கு **items**-ஓட ஒரு list-ஆ நகரும். ஒவ்வொரு item-உம் ஒரு சின்ன JSON record, ஒரு spreadsheet-ஓட ஒரு row மாதிரி. பெரும்பாலான nodes தங்களுக்கு வர்ற ஒவ்வொரு item-க்கும் ஒரு தடவை ஓடும். அதனால ஒரு trigger மூணு புது rows-ஐ output பண்ணா, அதுக்கு அப்புறம் இருக்குற Gmail node மூணு emails அனுப்பும். இந்த rule-ஐ ஞாபகம் வச்சுக்குங்க, ஏன்னா beginners-க்கு வர்ற பெரும்பாலான ஆச்சரியங்கள் இதுல இருந்து தான் வருது.

```flow
title: Shalini-ஓட admissions workflow
புது form row | Google Sheets trigger -> Tidy enquiry | Edit Fields
Tidy enquiry -> Repeats-ஐ drop பண்ணு | Remove Duplicates
Repeats-ஐ drop பண்ணு -> Course JEE-யா?
Course JEE-யா? -[ஆமா]-> JEE welcome | Gmail
Course JEE-யா? -[இல்ல]-> NEET welcome | Gmail
JEE welcome -> Counsellors-க்கு alert | Telegram
NEET welcome -> Counsellors-க்கு alert
ஏதாவது failure -> Error workflow | Shalini-க்கு message
```

இந்த lesson mechanics பத்தினது: n8n-ஐ ஓட வைக்கிறது, items, expressions, testing, publishing. "n8n-ஓட automation" lesson இதுக்கு மேல AI steps-ஓட build பண்ணும். Jaipur-ல ஒரு coaching institute-ல admissions பாத்துக்குற Shalini, மேல இருக்குற workflow-ஐ build பண்றதை நீங்க follow பண்ணுவீங்க.

ஆரம்பிக்குறதுக்கு முன்னாடி ரெண்டு facts. முதல்ல, n8n **open source இல்ல**. அது தன்னோட சொந்த **Sustainable Use License**-ஐ use பண்ணுது, அது உங்க சொந்த internal business-க்கு, இல்லன்னா personal, non-commercial use-க்கு அதை use பண்ணவும் மாத்தவும் அனுமதிக்குது. பணம் குடுக்குற clients-க்கு workflows build பண்றது ok. Clients அவங்களோட சொந்த workflows-ஐ அதுல build பண்ற மாதிரி n8n-ஐ host பண்ணணும்னா, n8n கூட ஒரு commercial agreement வேணும். ரெண்டாவது, **n8n 2.0**-ல இருந்து, save பண்றது (இப்போ automatic) ஒரு draft-ஐ மட்டும் தான் வச்சிருக்கும். Triggers ஓட **Publish**-ஐ click பண்ணணும். நிறைய பழைய tutorials இன்னும் ஒரு Active toggle-ஐ காட்டுது.

## இது எப்படி work ஆகுது

### n8n-ஐ ஓட வைக்கிறது

உங்ககிட்ட நடைமுறைக்கு ஏத்த மூணு choices இருக்கு:

| Option | எப்படி ஆரம்பிக்குறது | என்ன செலவு | Google sign-in | எதுக்கு best |
| --- | --- | --- | --- | --- |
| n8n Cloud | Free trial-க்கு sign up பண்ணுங்க | Trial, November 2026 நிலவரப்படி: 14 days, Pro features, 1,000 executions; அப்புறம் ஒரு paid plan | ஒரு click, "Sign in with Google" | உங்க முதல் workflow, எல்லாத்தையும் விட வேகம் |
| உங்க laptop-ல Docker | ஒரு command, கீழ இருக்கு | Free software; laptop on-ஆ இருக்கும்போது மட்டும் தான் ஓடும் | உங்க சொந்த Google OAuth client | கத்துக்க, data-வை local-ஆ வச்சிருக்க |
| வாடகை server-ல Docker | Docker Compose | Server வாடகை, கூடவே உங்க நேரம் | உங்க சொந்த OAuth client-உம் ஒரு domain-உம் | Self-hosted production |

Cloud plans-க்கு **executions** வச்சு விலை வைக்கிறாங்க, அதாவது முழு workflow runs, தனித்தனி nodes இல்ல. யாருக்காவது quote பண்றதுக்கு முன்னாடி இப்போதைய plans-க்கு n8n-ஓட pricing page-ஐ check பண்ணுங்க.

n8n-ஐ local-ஆ ஓட்ட, Docker Desktop-ஐ install பண்ணிட்டு, இதை run பண்ணுங்க:

```bash
docker volume create n8n_data
docker run -it --rm --name n8n -p 5678:5678 \
  -e GENERIC_TIMEZONE="Asia/Kolkata" -e TZ="Asia/Kolkata" \
  -v n8n_data:/home/node/.n8n \
  n8nio/n8n
```

`http://localhost:5678`-ஐ open பண்ணி owner account-ஐ create பண்ணுங்க. Container நின்னாலும் volume உங்க workflows-ஐயும் credentials-ஐயும் வச்சிருக்கும். Time zone முக்கியம்: அது இல்லன்னா, ஒரு self-hosted instance America/New_York-ஐ use பண்ணும், ஒரு "9 am" schedule இந்திய நேரப்படி சாயங்காலம் fire ஆகும். பழைய tutorials n8n-ஐ `npx n8n` வச்சு ஆரம்பிக்கும். November 2026 நிலவரப்படி early access-ல இருக்குற n8n 3.0 அந்த வழியை நீக்கிட்டு Docker-ஐ மட்டும் தான் support பண்ணுது, அதனால Docker வழியை கத்துக்குங்க.

Laptop-ஓட ஒரு limit: internet-ல இருக்குற apps `localhost`-ஐ reach பண்ண முடியாது. Google Sheets trigger மாதிரி **poll** பண்ற triggers இன்னும் work ஆகும், ஏன்னா n8n தான் கேக்குது. ஒரு Webhook மாதிரி, ஒரு call-க்காக wait பண்ற triggers-க்கு ஒரு public address வேணும் ("Webhooks" lesson-ஐ பாருங்க).

### Triggers

ஒவ்வொரு workflow-உம் ஒரு trigger-ல ஆரம்பிக்கும். ஒரு workflow-ல பல triggers இருக்கலாம், ஆனா ஒவ்வொரு run-உம் ஒண்ணுல இருந்து தான் ஆரம்பிக்கும்.

| Trigger | எப்போ fire ஆகும் | அதுக்கு எப்படி தெரியும் |
| --- | --- | --- |
| Manual | நீங்க "Execute workflow"-ஐ click பண்ணும்போது | நீங்க, build பண்ணும்போது |
| Schedule | Set பண்ண நேரம் வரும்போது | n8n-ஓட clock, workflow-ஓட time zone-ல |
| Webhook அல்லது Form Trigger | இன்னொரு app அல்லது ஒரு ஆள் ஒரு URL-க்கு data submit பண்ணும்போது | உடனே: அனுப்புறவங்க n8n-ஐ call பண்றாங்க |
| Google Sheets, Gmail | ஒரு புது row அல்லது email வரும்போது | Polling: default-ஆ n8n ஒவ்வொரு நிமிஷமும் check பண்ணும் |

Google Forms trigger node-னு ஒண்ணு கிடையாது. நீங்க ஒரு Google Form use பண்ணா, அதோட answers ஒரு responses sheet-க்கு போகும், அந்த sheet-ல வர்ற புது rows-ல நீங்க trigger பண்ணுவீங்க.

Sheets trigger-க்கு தெரிஞ்சுக்க வேண்டிய மூணு பழக்கங்கள் இருக்கு. அது rows-ஐ எண்ணும். Publish பண்ணதுக்கு அப்புறம் முதல் check எத்தனை rows இருக்குன்னு மட்டும் record பண்ணும், அதனால பழைய responses எப்பவுமே fire ஆகாது. Responses sheet-ல rows-ஐ delete அல்லது sort பண்ணா count குழம்பிடும், அதனால அந்த sheet-ஐ தொடாம, ஒரு copy-ல வேலை பண்ணுங்க. அப்புறம் editor-ல "Execute workflow"-ஐ click பண்ணா, அது sheet-ல இருக்குற **எல்லா** rows-ஐயும் return பண்ணும், புதுசை மட்டும் இல்ல.

### Nodes

Nodes மூணு குடும்பங்களா வரும்:

- **App nodes:** Google Sheets, Gmail, Telegram, Slack, HubSpot, இன்னும் நூற்றுக்கணக்கானவை.
- **Core nodes:** fields-ஐ rename பண்ணி சுத்தம் பண்ண **Edit Fields** (Set-னும் சொல்லுவாங்க), branch பண்ண **If**, **Switch**, **Remove Duplicates**, ரெண்டு inputs-ஐ சேர்க்க **Merge**, எந்த API-க்கும் **HTTP Request**, சின்ன scripts-க்கு **Code**.
- **AI nodes:** classify பண்ண, extract பண்ண அல்லது draft பண்ண ஒரு language model-ஐ call பண்ணும். இவை தான் "n8n-ஓட automation" lesson-ஓட subject.

### Credentials

ஒவ்வொரு app node-க்கும் ஒரு **credential** வேணும்: OAuth sign-in அல்லது ஒரு API key மூலமா அந்த app-க்கு save பண்ண access. n8n credentials-ஐ encrypt பண்ணி store பண்ணும், பல workflows ஒரே credential-ஐ reuse பண்ண விடும். உங்க personal admin account-ஐ use பண்றதை விட, automation-க்குன்னே உருவாக்கின, தேவையான access மட்டும் இருக்குற ஒரு account-ஐ use பண்ணுங்க.

n8n Cloud-ல Google credentials ஒரு click தான். Self-hosted n8n-ல, பெரும்பாலான beginners மாட்டிக்கிற step இது தான், ஏன்னா நீங்க உங்க சொந்த **OAuth client**-ஐ create பண்ணணும்:

1. Google Cloud Console-ல ஒரு project create பண்ணி, உங்களுக்கு தேவையான APIs-ஐ enable பண்ணுங்க. Google Sheets node-க்கு Sheets API, Drive API ரெண்டுமே வேணும்; Gmail-க்கு Gmail API வேணும்.
2. OAuth consent screen-ஐ set up பண்ணுங்க. Google Workspace use பண்ணா **Internal**-ஐ தேர்ந்தெடுங்க, இல்லன்னா **External**. ஒரு External app testing-ல ஆரம்பிக்கும், அதனால உங்க சொந்த Google account-ஐ ஒரு **test user**-ஆ add பண்ணுங்க. அது இல்லன்னா, Google "access denied"-னு காட்டும்.
3. **Web application** type-ல ஒரு OAuth client ID create பண்ணுங்க. n8n credential screen காட்டுற **OAuth Redirect URL**-ஐ paste பண்ணுங்க. ஒரு laptop-ல அது `http://localhost:5678/rest/oauth2-credential/callback` மாதிரி இருக்கும்.
4. Client ID, Client Secret-ஐ n8n-க்குள்ள copy பண்ணிட்டு, Sign in with Google-ஐ click பண்ணுங்க.

ஒரு trap: இன்னும் testing-ல இருக்குற ஒரு External app-க்கு, consent-உம் tokens-உம் ஏழு நாள்ல expire ஆகும்னு n8n-ஓட docs எச்சரிக்குது. ஒரு வாரம் கழிச்சு workflow sheet-ஐ படிக்குறதை நிறுத்திட்டா, credential-ஐ மறுபடி connect பண்ணுங்க, இல்லன்னா app-ஐ testing-ல இருந்து வெளிய கொண்டு வர்றது பத்தின Google-ஓட guidance-ஐ படிங்க.

### Expressions: current item-உம் முந்தைய nodes-உம்

ஒரு node-ஓட settings-ல, input panel-ல இருந்து ஒரு field-ஐ drag பண்ணலாம், இல்லன்னா double curly braces-க்குள்ள ஒரு **expression**-ஐ type பண்ணலாம். Expressions-னா JavaScript-ஓட சின்ன துண்டுகள்.

- `{{ $json.email }}` **current item**-ஓட email field-ஐ படிக்கும், இந்த node-ஓட direct input பார்க்குற மாதிரி.
- `{{ $json['Phone number'] }}` பேர்ல ஒரு space இருக்குற field-ஐ படிக்கும். Google Form sheets கேள்வியோட text-ஐயே column names-ஆ use பண்ணும், fields-ஐ சீக்கிரமே rename பண்றதுக்கு இது ஒரு காரணம்.
- `{{ $('Tidy enquiry').item.json.name }}` "Tidy enquiry"-ங்குற node-ல, இந்த item எந்த item-ல இருந்து வந்துச்சோ அதுல இருந்து name-ஐ படிக்கும்.

ரெண்டாவது வடிவம் பார்க்குறதுக்கு தெரியுறதை விட முக்கியம். ஒவ்வொரு node-உம் `$json`-ஐ தன்னோட சொந்த output-ஆல replace பண்ணும். ஒரு Gmail node-க்கு அப்புறம், `$json`-ல அது இப்போ அனுப்பின email பத்தின details இருக்கும், உதாரணமா ஒரு message id, student-ஓட row இல்ல. அதனால Gmail-க்கு அப்புறம் வைக்கிற ஒரு Telegram node முந்தைய node-ஓட பேரை சொல்லணும். Nodes-க்கு தெளிவான பேர் வைங்க, ஏன்னா பேர் expression-ஓட ஒரு பகுதி; ஒரு node-ஓட பேரை மாத்தினா, அதை use பண்ற expressions-ஐ check பண்ணுங்க.

இன்னும் ரெண்டு defaults ஆளுங்களை தடுக்கி விடும். **Edit Fields** நீங்க set பண்ற fields-ஐ மட்டும் தான் output பண்ணும், **Include Other Input Fields**-ஐ on பண்ணா தவிர, அதனால நீங்க மறக்குற எந்த field-உம் காணாம போயிடும். அப்புறம் ஒரு புது **If** node text-ஐ case-sensitive-ஆ compare பண்ணும்: **Ignore Case** option-ஐ add பண்ற வரை "neet", "NEET"-க்கு equal இல்ல.

### Pinned data வச்சு testing

Editor-ல இருந்து workflow-ஐ ஓட்டி, ஒவ்வொரு node-ஐயும் click பண்ணி அதோட input, output-ஐ பாருங்க. Output தப்பா தெரியுற முதல் node-ல இருந்து ஆரம்பிச்சு, ஒரு தடவைக்கு ஒரு node-ஆ problems-ஐ fix பண்ணுங்க.

Trigger-ஓட output-ஐ **Pin** பண்ணுங்க, அப்போ ஒவ்வொரு test run-உம் புது items-ஐ fetch பண்ணாம அதே sample items-ஐ reuse பண்ணும். Production runs pinned data-வை கண்டுக்காது. மேல சொன்ன Sheets trigger பழக்கத்துல இருந்தும் pinning உங்களை காப்பாத்தும்: 300 பழைய responses இருக்குற ஒரு sheet-ல ஒரு unpinned test run, 300 items-ஐயும் உள்ள அனுப்பும், Gmail node 300 நிஜ students-க்கு email அனுப்பிடும். Messages அனுப்புற எந்த node-ஐயும் connect பண்றதுக்கு முன்னாடி, மூணு நாலு rows-ஐ pin பண்ணுங்க, இல்லன்னா trigger-ஐ sheet-ஓட ஒரு test copy-க்கு point பண்ணுங்க.

### Publishing, alerts, duplicates

ஒவ்வொரு node-உம் அதோட tests-ல pass ஆனதும், **Publish**-ஐ click பண்ணுங்க. அதுல இருந்து trigger தானா ஓடும், **executions list** ஒவ்வொரு run-ஐயும் அதோட data, ஏதாவது error இருந்தா அதோட சேர்த்து காட்டும். Workflow-ஐ கவனிக்காம விட்டாலும் பாதுகாப்பா இருக்க இன்னும் ரெண்டு பகுதிகள் வேணும்:

- **ஒரு error workflow.** ஒரு **Error Trigger** node-ல ஆரம்பிச்சு உங்களுக்கு ஒரு message அனுப்புற ஒரு தனி workflow-ஐ create பண்ணுங்க. Error Trigger-க்கு fail ஆன workflow-ஓட பேர் `workflow.name`-லயும், கடைசியா ஓடின node `execution.lastNodeExecuted`-லயும், error `execution.error.message`-லயும், ஒரு link `execution.url`-லயும் கிடைக்கும். அதை publish பண்ணிட்டு, main workflow-ஓட settings-ல **Error workflow**-க்கு கீழ அதை select பண்ணுங்க. அது automatic runs-க்கு மட்டும் தான் fire ஆகும், நீங்க editor-ல ஆரம்பிக்குற runs-க்கு இல்ல, அதனால வேணும்னே break பண்ண ஒரு published workflow வச்சு அதை test பண்ணுங்க.
- **Duplicate protection.** Students forms-ஐ ரெண்டு தடவை submit பண்ணுவாங்க, ஏற்கனவே fill பண்ண ஒரு பிள்ளைக்காக parents இன்னொரு தடவை fill பண்ணுவாங்க. **Remove Items Processed in Previous Executions**-க்கு set பண்ண, **Value Is New**-ஆ இருக்குற items-ஐ வச்சுக்குற ஒரு **Remove Duplicates** node, முந்தைய runs-ல இருந்து values-ஐ ஞாபகம் வச்சு repeats-ஐ drop பண்ணும். அது ஒரே run-க்குள்ள இருக்குற items-ஐ compare பண்ணாது, அதனால ஒரே poll-ல மாட்டின ரெண்டு copies-உம் pass ஆகும்; double-clicks-க்கு, **Remove Items Repeated Within Current Input**-க்கு set பண்ண இன்னொரு Remove Duplicates-ஐ அதுக்கு முன்னாடி வைங்க. ஏற்கனவே normalise பண்ண ஒரு value-ல dedupe பண்ணுங்க. "+91 98765 43210", "09876543210" ரெண்டும் ஒரே phone தான், ஆனா tidy பண்ணதுக்கு அப்புறம் தான்.

```flow
dir: LR
Build -> Awkward samples-ஐ pin பண்ணு -> Run பண்ணி inspect பண்ணு -> Fix
Fix -[மறுபடி test]-> Run பண்ணி inspect பண்ணு
Run பண்ணி inspect பண்ணு -[எல்லாம் pass]-> Publish -> Executions-ஐ கவனி
```

## ஒரு worked example

Shalini Jaipur-ல ஒரு coaching institute-க்கு admissions பாத்துக்குறாங்க. Enquiries "Full name", "Phone number", "Email", "Course" கேள்விகள் இருக்குற ஒரு Google Form வழியா வரும். Google ஒவ்வொரு answer-ஐயும் ஒரு responses sheet-ல ஒரு row-ஆ எழுதும், முதல்ல ஒரு Timestamp column இருக்கும். இப்போ, counsellors ஒரு நாளைக்கு ஒரு தடவை sheet-ஐ படிச்சு அடுத்த நாள் காலைல students-ஐ call பண்றாங்க, சில enquiries miss ஆகுது.

அவங்க n8n Cloud trial-க்கு sign up பண்றாங்க, அதனால Google sign-in ஒரு click தான், அப்புறம் இதை build பண்றாங்க:

| # | Node | என்ன பண்ணும் |
| --- | --- | --- |
| 1 | Google Sheets trigger, Row Added | ஒவ்வொரு நிமிஷமும் responses sheet-ல புது rows இருக்கான்னு check பண்ணும் |
| 2 | Edit Fields, "Tidy enquiry"-னு பேர் | name, phone, email, course-ஐ simple பேர்களோட set பண்ணும் |
| 3 | Remove Duplicates | முந்தைய ஒரு run-ல ஏற்கனவே பார்த்த phone அல்லது email-ஐ drop பண்ணும் |
| 4 | If | Course JEE-யா, Ignore Case add பண்ணி |
| 5 | Gmail, ஒவ்வொரு branch-க்கும் ஒண்ணு | Brochure link-ஓட, course-க்கு ஏத்த welcome email |
| 6 | Telegram | Enquiry-ஐ counsellors-ஓட group-ல post பண்ணும் |

"Tidy enquiry"-ல இருக்குற fields:

```text
name    {{ $json['Full name'].trim().toTitleCase() }}
phone   {{ $json['Phone number'] ? '+91' + String($json['Phone number']).replace(/\D/g, '').slice(-10) : '' }}
email   {{ $json['Email'].trim().toLowerCase() }}
course  {{ $json['Course'].trim() }}
```

Phone line digits-ஐ மட்டும் வச்சுக்கும், கடைசி பத்தை எடுத்து +91 சேர்க்கும், அதனால "98765 43210", "+91 9876543210", "09876543210" எல்லாமே "+919876543210" ஆகும். Trigger ஒரு all-digit cell-ஐ number-ஆ குடுக்கலாம்ங்குறதால தான் `String()` இருக்கு. Cell empty-ஆ இருந்தா, result empty-ஆ இருக்கும், தனியா ஒரு "+91" இல்ல. பத்துக்கு குறைவான digits-ஓட எழுதின ஒரு number-ஐ, பின்னாடி phone-ஓட length-ஐ check பண்ற ஒரு If வச்சா பிடிக்கலாம்; Shalini அதை version two-க்காக note பண்ணிக்கிறாங்க.

Remove Duplicates-ல, dedupe பண்ண வேண்டிய value `{{ $json.phone || $json.email }}`. Phone-ஐ மட்டும் வச்சு dedupe பண்ணா, phone-ஐ blank-ஆ விட்ட ஒவ்வொரு student-ஐயும் ஒரே ஆளா நினைச்சு, முதல் ஆளை தவிர எல்லாரையும் drop பண்ணிடும்.

**Testing.** Shalini awkward-ஆ இருக்கணும்னே தேர்ந்தெடுத்த நாலு sample rows-ஐ pin பண்ணி, editor-ல இருந்து workflow-ஐ ஓட்டுறாங்க:

1. **Lower case-ல "jee".** Ignore Case add பண்றதுக்கு முன்னாடி, இந்த row NEET branch-க்கு போச்சு. இப்போ JEE-க்கு போகுது.
2. **Phone number இல்ல.** Plan பண்ண மாதிரியே phone empty. ஆனா Telegram message "Phone: "-னு அதுக்கு அப்புறம் எதுவும் இல்லாம வந்துச்சு. அவங்க அந்த line-ஐ `{{ $('Tidy enquiry').item.json.phone || 'not given, reply by email' }}`-ஆ மாத்துறாங்க.
3. **Telegram-ல blank names.** நாலு alerts-லயும் name empty-ஆ இருந்துச்சு. Telegram Gmail-க்கு அப்புறம் இருக்கு, அதனால `$json.name` Gmail-ஓட output-ஐ படிச்சுட்டு இருந்துச்சு. மேல இருக்குற line-ல மாதிரி "Tidy enquiry"-ஓட பேரை சொன்னது எல்லா field-ஐயும் fix பண்ணுச்சு.
4. **ஒரே student ரெண்டு தடவை,** ஒரு தடவை "98765 43210"-ஆ, ஒரு தடவை "+91 9876543210"-ஆ. Remove Duplicates முந்தைய runs-ல இருந்து வர்ற values-ஐ மட்டும் தான் ஞாபகம் வச்சுக்கும், அதனால ரெண்டு rows-ஐயும் ரெண்டு தனித்தனி runs-ல அனுப்பி இதை test பண்றாங்க. ரெண்டாவது drop ஆகுது. Editor runs-உம் values-ஐ record பண்ணும், அதனால அதே pinned rows-ஐ மறுபடி ஓட்டினா எல்லாமே repeats-ஆ drop ஆகும். மத்த tests-க்கு, ஒவ்வொரு rerun-க்கும் முன்னாடி node-ஓட **Clear Deduplication History** operation வச்சு அதோட memory-ஐ காலி பண்றாங்க, எந்த நிஜ student-உம் எப்பவுமே block ஆகாம இருக்க samples-ல கற்பனை numbers-ஐ use பண்றாங்க.

**Publishing.** அவங்க ஒரு error workflow build பண்றாங்க, Error Trigger அப்புறம் தனக்கே ஒரு Telegram, அதை publish பண்ணி admissions workflow-ஓட settings-ல select பண்றாங்க. அப்புறம் admissions workflow-ஐ publish பண்றாங்க. Sheet-ல ஏற்கனவே இருக்குற rows fire ஆகாது, அவங்களுக்கு வேண்டியதும் அது தான்: அந்த students-ஐ ஏற்கனவே call பண்ணியாச்சு.

உதாரணமா, முதல் வாரம் இப்படி இருக்குன்னு வச்சுக்குவோம். இந்த numbers எதை measure பண்ணணும்ங்குறதுக்கான ஒரு illustration, measure பண்ண result இல்ல:

| Measure | முன்னாடி | அப்புறம் |
| --- | --- | --- |
| Enquiry-ல இருந்து welcome email வரைக்கும் | அடுத்த நாள், கையால | ஒண்ணு ரெண்டு நிமிஷத்துக்குள்ள |
| Enquiry-ல இருந்து counsellor-ஓட call வரைக்கும் | அடுத்த நாள் காலை | அதே நாள், working hours-ல |
| ரெண்டு தடவை email போன repeat enquiries | அடிக்கடி | அரிது: முந்தைய runs-ல இருந்து வர்ற repeats drop ஆகும் |
| Silent failures | கவனிக்கப்படல | ஒவ்வொண்ணும் ஒரு link-ஓட Shalini-க்கு alert அனுப்பும் |

அவங்க ஏத்துக்குற trade-off: நிஜமாவே ரெண்டு தடவை enquire பண்ற ஒரு student, உதாரணமா முதல்ல JEE-க்கு அப்புறம் NEET-க்கு, ரெண்டாவது தடவை drop ஆவாங்க. Counsellors அவங்களை பார்க்கணும்னா, If node-க்கு முன்னாடி ஒரு log sheet-ஐ check பண்ணி, duplicates-ஐ drop பண்றதுக்கு பதிலா ஒரு "repeat enquiry" Telegram message-ஆ அனுப்பலாம்.

## பொதுவா பண்ற தப்புகள்

- **Pin பண்ணாம live responses sheet-ல test பண்றது.** Sheets trigger-ஓட ஒரு editor run எல்லா row-ஐயும் return பண்ணும், Gmail node எல்லாருக்கும் email அனுப்பும். Samples-ஐ pin பண்ணுங்க, இல்லன்னா ஒரு copy use பண்ணுங்க.
- **`$json`-ஐ replace பண்ண ஒரு node-க்கு அப்புறம் அதை படிக்குறது.** Gmail அல்லது Telegram-க்கு அப்புறம், முந்தைய node-ஓட பேரை சொல்லுங்க: `$('Tidy enquiry').item.json`.
- **நீங்க set பண்ணாததை Edit Fields drop பண்ணும்ங்குறதை மறக்குறது.** அடுத்த nodes-க்கு தேவையான ஒவ்வொரு field-ஐயும் set பண்ணுங்க, இல்லன்னா Include Other Input Fields-ஐ on பண்ணுங்க.
- **Case-sensitive comparisons.** If node-ஓட Ignore Case option-ஐ add பண்ணுங்க, இல்லன்னா tidy பண்ண, lower-case values-ஐ compare பண்ணுங்க.
- **Tidy பண்றதுக்கு முன்னாடி dedupe பண்றது, அல்லது empty-ஆ இருக்கக்கூடிய ஒரு field-ல dedupe பண்றது.** முதல்ல normalise பண்ணுங்க, ஒரு ரெண்டாவது field-ஐ fallback-ஆ வைங்க.
- **Responses sheet-ஐ edit பண்றது.** Rows-ஐ delete அல்லது sort பண்ணா trigger-ஓட row count உடைஞ்சுடும், அதனால புது enquiries miss ஆகலாம்.
- **Publish பண்றதுக்கு பதிலா save பண்றது.** n8n 2.0-ல, save பண்ண ஒரு workflow ஒரு draft தான். Production runs எதுவும் தெரியலன்னா, Publish-ஐ click பண்ணீங்களான்னு check பண்ணுங்க.
- **Error workflow இல்லாதது.** அது இல்லன்னா, fail ஆன ஒரு run யாராவது தற்செயலா பார்க்குற வரைக்கும் executions list-ல காத்திருக்கும்.
- **ஒரு self-hosted instance-ல time zone-ஐ default-லயே விடுறது.** Asia/Kolkata-ஐ set பண்ணுங்க.

## Practice பண்ணுங்க

Watch & learn panel-ல Kevin Stratvert-ஓட beginner video-ஐ பாருங்க, n8n-ஓட "Build your first workflow" quickstart-ஐ பண்ணுங்க, அப்புறம் கீழ link பண்ணியிருக்குற n8n-ஓட free N8N101 Essentials course-ஐ எடுங்க.

1. **ஓட்டுங்க.** Cloud trial அல்லது மேல இருக்குற Docker command வச்சு n8n-ஐ start பண்ணுங்க, ஒரு Google account-ஐ connect பண்ணுங்க.
2. **Build பண்ணுங்க.** ஒரு Google Form உருவாக்கி Shalini-ஓட workflow-ஐ build பண்ணுங்க, இல்லன்னா உங்க சொந்த case-க்கு ஒண்ணு: ஒரு trigger, ஒரு Edit Fields node, Remove Duplicates, ஒரு If branch, ரெண்டு app actions. ஒவ்வொரு node-க்கும் பேர் வைங்க.
3. **உடைச்சு பாருங்க.** நாலு awkward rows-ஐ pin பண்ணுங்க: ஒரு lower-case course, ஒரு empty phone, spaces இருக்குற ஒரு phone, ஒரு repeat. ஒவ்வொரு node-ஓட output-ஐயும் predict பண்ணி, ஓட்டி, ஒவ்வொரு failure-ஐயும் fix பண்ணுங்க; அதே rows-ஐ மறுபடி ஓட்டுறதுக்கு முன்னாடி Remove Duplicates history-ஐ clear பண்ணுங்க.
4. **பாதுகாப்பா publish பண்ணுங்க.** ஒரு error workflow add பண்ணி, ரெண்டையும் publish பண்ணி, அப்புறம் main workflow-ஐ வேணும்னே break பண்ணி, வேலை செய்யுற ஒரு link-ஓட alert வருதான்னு confirm பண்ணுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** ஒவ்வொரு node-ஓட input, output-ஐயும் explain பண்ண முடியும், executions list-ல ஒரு automatic run-ஐ காட்ட முடியும், fail ஆன ஒரு run-ல இருந்து வந்த alert-ஐ காட்ட முடியும்.
