## இது என்ன

கிட்டத்தட்ட ஒவ்வொரு automation-உம் AI application-உம் apps-க்கு நடுவுல data-வை நகர்த்துது, அந்த data பெரும்பாலும் **JSON** (JavaScript Object Notation) வடிவத்துல தான் போகுது: apps structured data-வை பரிமாறிக்க use பண்ற ஒரு text format. JSON-ஐ படிச்சு reshape பண்ண தெரிஞ்சா, கிட்டத்தட்ட எதை வேணும்னாலும் எதோட வேணும்னாலும் connect பண்ணலாம்.

JSON-ல மூணு building blocks இருக்கு:

| Building block | எப்படி இருக்கும் | Example |
| --- | --- | --- |
| **Object** | Curly braces-க்குள்ள பெயர் இருக்குற fields | Name, phone, city இருக்குற ஒரு customer |
| **Array** (list) | Square brackets-க்குள்ள items | Order lines-ஓட list |
| **Value** | Quotes-ல text, ஒரு number, true அல்லது false, அல்லது null (காலி) | "Mysuru", 2, true, null |

Objects-உம் arrays-உம் ஒண்ணுக்குள்ள ஒண்ணு nest ஆகும். ஒரு payment webhook-ல payment-க்கு ஒரு object இருக்கலாம், அதுக்குள்ள customer-க்கு ஒரு object, அதுக்குள்ள notes-க்கு ஒரு array.

```flow
title: ஒரு order, nested JSON-ஆ
order (object) -> id: "ORD-88213"
order (object) -> customer (object)
customer (object) -> name: "Nisha Rao"
customer (object) -> phone: "9845012345"
customer (object) -> email: null
order (object) -> lines (array)
lines (array) -> [0] sku, qty, price
lines (array) -> [1] sku, qty, price
order (object) -> shipping (object)
shipping (object) -> city: "Mysuru"
shipping (object) -> pin: "570001"
```

இந்த lesson-ல ஒரு online tea store-ஓட order webhook, dispatch sheet-ல rows-ஆவும், customer-க்கு ஒரு SMS-ஆவும் மாறுறதை follow பண்றோம். Lesson முடியும்போது, தெரியாத ஒரு JSON payload-ஐ எடுத்து, ஒரு workflow-க்கு தேவையானதை சரியா வெளியில எடுக்க முடியும்.

## இது எப்படி work ஆகுது

### Path-ஐ படிக்கிறது

Nested field-ஐ அடைய, வெளியில இருந்து உள்ள பெயர்களை dots போட்டு இணைச்சு follow பண்ணுங்க. Array items square brackets-ல **0**-ல இருந்து number ஆகும்.

| உங்களுக்கு என்ன வேணும் | Path |
| --- | --- |
| Order id | `order.id` |
| Customer-ஓட phone | `order.customer.phone` |
| முதல் line-ஓட price | `order.lines[0].price` |
| ரெண்டாவது line-ஓட SKU | `order.lines[1].sku` |
| Delivery PIN code | `order.shipping.pin` |

### Real samples-ஐ பாருங்க

Documentation-ஐ மட்டும் வச்சு path-ஐ guess பண்ணாதீங்க. ஒரு real அல்லது test event-ஐ trigger பண்ணி, வந்த exact JSON-ஐ பாருங்க. n8n-ல output panel ஒவ்வொரு item-ஐயும் table-ஆ, raw JSON-ஆ, schema-வா காட்டும்; exact path-ஐ கண்டுபிடிச்சு copy பண்ண அதை use பண்ணுங்க.

### எடுங்க, பெயர் மாத்துங்க

பெரும்பாலான workflows-க்கு, பெரிய payload-ல இருந்து சில fields மட்டும் தான் வேணும். அவற்றை எடுத்து, தெளிவான பெயர் கொடுக்க "Edit Fields" அல்லது "Set" step use பண்ணுங்க: `payment.notes.contact_no`-க்கு பதிலா `customer_phone`. அப்போ அடுத்த steps படிக்கவும் maintain பண்ணவும் ரொம்ப easy.

### Lists-ல இருந்து items-க்கு, திரும்பவும்

ஒரு field-ல order lines, attachments மாதிரி ஒரு list இருந்தா, அதை **split** பண்ணுங்க; அப்போ ஒவ்வொரு element-உம் அடுத்த steps-க்கு தனி item ஆகும். அப்புறம் ஒவ்வொரு line-உம் தனி sheet row ஆகலாம். திரும்ப போக, items-ஐ ஒரே list-ஆ **aggregate** பண்ணுங்க.

```flow
1 item | [A, B] lines இருக்குற ஒரு order -[lines-ஐ split பண்ணு]-> Item 1 | order id, line A
1 item -[lines-ஐ split பண்ணு]-> Item 2 | order id, line B
Item 1 -> ஒவ்வொண்ணுக்கும் ஒரு sheet row
Item 2 -> ஒவ்வொண்ணுக்கும் ஒரு sheet row
```

Order id, city மாதிரி நீங்க இன்னும் தேவைப்படுற fields-ஐ, ஒவ்வொரு split item-லயும் வச்சுக்கோங்க.

### Types

Values அடிக்கடி தப்பான type-ல வரும்:

| வந்த value | Problem | Fix |
| --- | --- | --- |
| `"1,250.00"` | Comma இருக்குற text, number இல்ல | Commas-ஐ எடுத்து, அப்புறம் number-ஆ convert பண்ணுங்க |
| `"03/11/2026"` | 3 November-ஆ, 11 March-ஆ? | Provider documentation-ல சொன்ன format வச்சு parse பண்ணுங்க |
| number-ஆ `9845012345` | சரி தான், ஆனா number-ஆ `0123` தன் zero-வை இழக்கும் | Phone numbers, PIN codes, ids-ஐ text-ஆ வச்சுக்கோங்க |
| `"true"` | Text, true அல்லது false இல்ல | Text-ஆ compare பண்ணுங்க, அல்லது convert பண்ணுங்க |

### Missing values

சில records-ல fields இல்லாம இருக்கலாம் அல்லது `null`-ஆ இருக்கலாம். முன்னாடியே முடிவு பண்ணுங்க: default use பண்றது, ஒரு step-ஐ skip பண்றது, அல்லது record-ஐ ஒரு ஆளுக்கு அனுப்புறது. "`customer.email` null-ஆ இருந்தா, email step-ஐ skip பண்ணி SMS அனுப்பு" ஒரு rule; crash ஆகுற workflow rule இல்ல.

### APIs, AI steps-க்கு JSON build பண்றது

ஒரு API-க்கோ AI step-க்கோ data அனுப்பும்போது, அது எதிர்பார்க்குற exact shape-ஐ நீங்க build பண்ணணும். **JSON schema** அந்த shape-ஐ விவரிக்கும்: எந்த fields, அவற்றோட types, எது கட்டாயம். உங்க output-ஐ API-ஓட documentation-ஓட check பண்ணுங்க; AI structured outputs-ன்னா, model-க்கு நீங்க கொடுக்குற schema-வோட check பண்ணுங்க.

### Power tools

`jq`-உம் JSONata-உம் JSON-ஐ query பண்ணி reshape பண்ற சின்ன languages. நிறைய automation tools இதே மாதிரி expressions-ஐ support பண்ணும். ஆரம்பிக்க இது தேவையில்ல, ஆனா சிக்கலான payloads-க்கு உதவும்.

## ஒரு worked example

Bengaluru-ல ஒரு online tea store-க்கு, ஒரு order போடும்போது இந்த webhook (சுருக்கமா) வருது:

```json
{
  "order": {
    "id": "ORD-88213",
    "created_at": "2026-11-03T10:42:00+05:30",
    "customer": { "name": "Nisha Rao", "phone": "9845012345", "email": null },
    "lines": [
      { "sku": "TEA-ASSAM-250", "qty": 2, "price": "349.00" },
      { "sku": "MUG-STEEL", "qty": 1, "price": "1,199.00" }
    ],
    "shipping": { "city": "Mysuru", "pin": "570001" }
  }
}
```

Goal: dispatch sheet-ல ஒவ்வொரு order line-க்கும் ஒரு row, customer-க்கு ஒரு SMS.

1. `order.lines`-ஐ items-ஆ **split** பண்ணுங்க; `order.id`, `customer.name`, `shipping.city`, `shipping.pin`-ஐ ஒவ்வொண்ணுலயும் வச்சுக்கோங்க.
2. `price`-ஐ commas-ஐ எடுத்து text-ல இருந்து number-ஆ **convert** பண்ணுங்க, அப்புறம் line total = qty × price கணக்கு பண்ணுங்க.
3. `pin`-ஐ text-ஆவே **வச்சுக்கோங்க**, அப்போ "570001" அப்படியே இருக்கும்.
4. **SMS:** `customer.phone`-க்கு +91 சேர்த்து use பண்ணுங்க. `email` `null`-ஆ இருக்கிறதால, இந்த order-க்கு email step-ஐ skip பண்ணுங்க.

Dispatch sheet-க்கு ரெண்டு rows கிடைக்கும்:

| Order | Customer | SKU | Qty | Price | Line total | City | PIN |
| --- | --- | --- | --- | --- | --- | --- | --- |
| ORD-88213 | Nisha Rao | TEA-ASSAM-250 | 2 | 349 | 698 | Mysuru | 570001 |
| ORD-88213 | Nisha Rao | MUG-STEEL | 1 | 1,199 | 1,199 | Mysuru | 570001 |

Conversion step-க்கு முன்னாடி, "1,199.00" text-ஆ இருந்ததால ரெண்டாவது line-ஓட total error-ஆ காட்டுச்சு. Null check-க்கு முன்னாடி, email இல்லாத ஒவ்வொரு customer-க்கும் workflow fail ஆச்சு, அது அஞ்சு orders-ல ஒண்ணு.

## பொதுவா பண்ற தப்புகள்

- **Paths-ஐ guess பண்றது.** Real samples-ஐ பாருங்க, exact path-ஐ copy பண்ணுங்க.
- **List இருக்கும்போது ஒரு item தான்னு நினைக்கிறது.** Lists-ஐ items-ஆ split பண்ணுங்க.
- **Numbers-ஐ text-ஆவே விடுறது.** "1,199.00" convert பண்ணாத வரை கூடாது.
- **ஆரம்பத்துல இருக்குற zeros-ஐ இழக்கிறது.** PIN codes, phone numbers, ids-ஐ text-ஆ வச்சுக்கோங்க.
- **Missing fields-ல fail ஆகுறது.** Null, இல்லாத fields-க்கு ஒரு rule வச்சு plan பண்ணுங்க.
- **Array 0-ல ஆரம்பிக்குறதை மறக்குறது.** முதல் item `[0]`, `[1]` இல்ல.

## Practice பண்ணுங்க

கீழே link பண்ணியிருக்குற MDN-ஓட JSON guide-ஐயும், data-வோட வேலை செய்யுறதை பத்தின n8n page-ஐயும் படிங்க.

1. **Paths.** மேல இருக்குற sample அல்லது ஒரு real webhook sample வச்சு, list-க்குள்ள இருக்குற ஒண்ணு உட்பட அஞ்சு fields-க்கு path எழுதுங்க.
2. **Reshape.** n8n-ல order lines-ஐ items-ஆ split பண்ணி, prices-ஐ numbers-ஆ convert பண்ணி, line totals கணக்கு பண்ணுங்க.
