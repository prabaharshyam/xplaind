## இது என்ன

ஒரு **web API** உங்க program-ஐ internet வழியா இன்னொரு service-கிட்ட data அல்லது actions கேக்க விடுது: air quality, ஒரு map route, ஒரு payment-ஓட status, அரசாங்க open data, அல்லது ஒரு AI model-ஓட பதில். ஒவ்வொரு AI model provider-ஐயும் இந்த வழியில தான் அணுகுறோம், அதனால பின்னாடி language models-ஐ call பண்றதுக்கு அடிப்படையான core skill இது தான்.

உங்க program ஒரு URL-க்கு ஒரு **HTTP request** அனுப்புது. Service இதோட reply பண்ணுது:

- ஒரு **status code**, அது வேலை செஞ்சுதான்னு சொல்ற ஒரு மூணு இலக்க எண்;
- பெரும்பாலும் **JSON**-ல ஒரு **body**, அதாவது objects (`{"key": value}`), lists (`[1, 2, 3]`) இருக்குற ஒரு text format; அதை Python dictionaries, lists-ஆ மாத்துது.

```flow
title: ஒரு API call, ஆரம்பம் முதல் முடிவு வரை
dir: LR
உங்க code | session.get(url, params, timeout) -[GET, X-API-Key header-ல key]-> API server
API server -[status code, JSON body]-> Status-ஐ check பண்ணுங்க
Status-ஐ check பண்ணுங்க -[2xx]-> r.json() | dicts, lists
Status-ஐ check பண்ணுங்க -[429 அல்லது 5xx]-> Wait பண்ணி retry பண்ணுங்க
Status-ஐ check பண்ணுங்க -[மத்த 4xx]-> Request-ஐ fix பண்ணுங்க
```

இந்த lesson-ல Delhi-ல ஒரு சின்ன air-quality dashboard build பண்ற student Anita கூட போறோம். அவங்க **OpenAQ** use பண்றாங்க; இது உலகம் முழுக்க இருந்து, இந்திய monitoring stations உட்பட, air-quality readings-ஐ சேகரிக்கிற ஒரு non-profit platform. அதோட API-க்கு ஒரு free key வேணும், அதனால முழு routine-ஐயும் practise பண்ண இது ஒரு நல்ல இடம்: key, timeout, status, JSON, retries, pages.

## இது எப்படி work ஆகுது

### ஒரு request-ஓட பகுதிகள்

ஒவ்வொரு API-ஓட documentation-உம் requests-ஐ இதே பகுதிகளா தான் விவரிக்குது:

| பகுதி | அது என்ன | `requests`-ல | OpenAQ உதாரணம் |
| --- | --- | --- | --- |
| Base URL | எல்லா calls-உம் ஆரம்பிக்கிற address | URL-ஓட ஒரு பகுதி | `https://api.openaq.org/v3` |
| Endpoint | ஒரு வகை data-க்கான path | URL-ஓட ஒரு பகுதி | `/locations/8118/latest` |
| Query parameters | URL-ல `?`-க்கு அப்புறம் சேர்க்கிற filters | `params={...}` | `iso=IN`, `limit=100`, `page=2` |
| Headers | Key உட்பட metadata | `headers={...}` | `X-API-Key: your key` |
| Body | நீங்க அனுப்புற data, பெரும்பாலும் POST கூட | `json={...}` | data படிக்க தேவையில்லை |

`params={"iso": "IN"}` URL-ல `?iso=IN`-ஆ மாறுது; `requests` spaces, special characters-ஐயும் escape பண்ணும். ஒரு JSON body அனுப்ப `json=` use பண்ணுங்க (`data=` இல்லை): அது உங்க dictionary-ஐ convert பண்ணி, சரியான content type-ஐ set பண்ணும்.

### உங்க முதல் call

```python
import os
import requests

BASE = "https://api.openaq.org/v3"
key = os.environ["OPENAQ_API_KEY"]

r = requests.get(f"{BASE}/locations/8118/latest",
                 headers={"X-API-Key": key}, timeout=(5, 20))
print(r.status_code)          # 200 if it worked
r.raise_for_status()          # stop here on any 4xx or 5xx
data = r.json()               # JSON text becomes dicts and lists
print(list(data))             # ['meta', 'results']
```

Location 8118 ஒரு New Delhi station, OpenAQ தன்னோட quick start-லயே இதை use பண்ணுது. இந்த சின்ன block-லயே மூணு பழக்கங்கள் இருக்கு:

- **Key ஒரு environment variable-ல இருந்து வருது**, அதனால அது code-ல எப்பவுமே தெரியாது.
- **ஒரு timeout இருக்கு.** `(5, 20)`-னா connect ஆக 5 seconds வரை, server data அனுப்ப 20 seconds வரை wait பண்ணும்.
- **`raise_for_status()`, `r.json()`-க்கு முன்னாடி run ஆகுது.** ஒரு error reply data இல்லை, அதை data-வா நடத்தினா மூணு lines-க்கு அப்புறம் குழப்பமான failures வரும்.

### Status codes

முதல் இலக்கம் யாரோட பிரச்சனைன்னு சொல்லும்: **2xx** வேலை செஞ்சுது, **4xx** உங்க request தப்பு, **5xx** server fail ஆயிடுச்சு.

| Code | அர்த்தம் | என்ன பண்ணணும் | Retry? |
| --- | --- | --- | --- |
| `200` | OK | Data-வை use பண்ணுங்க | — |
| `400` | Bad request | Parameters, body-ஐ check பண்ணுங்க | இல்லை |
| `401` | Unauthorized: key இல்லை, தப்பு அல்லது expire ஆயிடுச்சு | Key-ஐயும் அது போற header-ஐயும் check பண்ணுங்க | இல்லை |
| `403` | Forbidden: key valid, ஆனா இதுக்கு அனுமதி இல்லை | உங்க plan அல்லது permissions-ஐ check பண்ணுங்க | இல்லை |
| `404` | Not found | URL path-ஐயும் item id-ஐயும் check பண்ணுங்க | இல்லை |
| `422` | Unprocessable: request validation-ல fail ஆயிடுச்சு | Body-ல இருக்குற error detail-ஐ படிங்க | இல்லை |
| `429` | Too many requests | Wait பண்ணி, இன்னும் மெதுவா retry பண்ணுங்க | ஆமா |
| `500`, `502`, `503`, `504` | Server அல்லது ஒரு proxy fail ஆயிடுச்சு | Wait பண்ணி retry பண்ணுங்க | ஆமா |

ஞாபகம் வெச்சுக்க ஒரு useful வழி: **401 "நீங்க யாரு?"ன்னு கேக்குது, 403 "நீங்க யாருன்னு தெரியும், ஆனா முடியாது"ன்னு சொல்லுது.** 401-க்கு fix key; 403-க்கு fix உங்க account அல்லது plan. நிறைய Python APIs, FastAPI framework வெச்சு build பண்ணது உட்பட, ஒரு field இல்லைன்னா அல்லது அது தப்பான type-ல இருந்தா 422 return பண்ணும், எந்த field-னு body சொல்லும்.

### JSON-ஐ படிக்கிறது

அதை படிக்கிற code எழுதுறதுக்கு முன்னாடி, reply-ஐ ஒரு தடவை அழகா format பண்ணி print பண்ணுங்க:

```python
import json
print(json.dumps(data, indent=2)[:1500])
```

Latest-readings endpoint-ல இருந்து வர்ற ஒரு reply-ஐ trim பண்ணா அதுக்கு இந்த shape இருக்கும் (shape OpenAQ-ஓட documentation-ஐ follow பண்ணுது; values கற்பனையானவை):

```json
{
  "meta": {"name": "openaq-api", "page": 1, "limit": 100, "found": 2},
  "results": [
    {"datetime": {"utc": "2026-11-28T05:00:00Z", "local": "2026-11-28T10:30:00+05:30"},
     "value": 182.0, "sensorsId": 1001, "locationsId": 8118,
     "coordinates": {"latitude": 28.63, "longitude": 77.2}},
    {"datetime": {"utc": "2026-11-28T05:00:00Z", "local": "2026-11-28T10:30:00+05:30"},
     "value": 301.0, "sensorsId": 1002, "locationsId": 8118,
     "coordinates": {"latitude": 28.63, "longitude": 77.2}}
  ]
}
```

வெளியில இருந்து உள்ள நோக்கி படிங்க. Curly braces ஒரு dictionary, அதனால string key use பண்ணுவீங்க. Square brackets ஒரு list, அதனால 0-ல இருந்து எண்ணி ஒரு number use பண்ணுவீங்க.

```python
data["results"][0]["value"]               # 182.0
data["results"][0]["datetime"]["local"]   # '2026-11-28T10:30:00+05:30'
[row["value"] for row in data["results"]] # [182.0, 301.0]
```

நீங்க எல்லாத்தையும் விட அதிகமா பார்க்கப்போற ரெண்டு errors, ஒவ்வொண்ணும் ஒரு குறிப்பிட்ட தப்பை காட்டும்:

- `TypeError: list indices must be integers or slices, not str`-னா நீங்க ஒரு list மேல string key use பண்ணிருக்கீங்க. உதாரணமா, `data["results"]["value"]` fail ஆகும், ஏன்னா `results` ஒரு list. ஒரு item-ஐ எடுங்க (`[0]`) அல்லது loop பண்ணுங்க.
- `KeyError: 'value'`-னா அந்த dictionary-ல அப்படி ஒரு key இல்லை. Spelling-ஐ check பண்ணுங்க, இல்லைன்னா அந்த field optional.

Optional fields-க்கு, key **இல்லைன்னா** `row.get("value", 0)` `0`-ஐ return பண்ணும். ஆனா நிறைய APIs key-ஐ `null` கூட அனுப்பும், அதை Python `None`-ஆ படிக்கும், அப்போ `.get` உங்க default-ஐ இல்லாம `None`-ஐ return பண்ணும். ரெண்டு cases-ஐயும் cover பண்ண `row.get("value") or 0` எழுதுங்க. கவனம்: `or` ஒரு உண்மையான `0`-ஐயும் replace பண்ணிடும், அதனால zero-க்கு அர்த்தம் இருக்குற numbers-க்கு, அதுக்கு பதிலா `is None` test பண்ணுங்க.

### Body JSON இல்லாதப்போ

Body JSON இல்லைன்னா `r.json()` `requests.JSONDecodeError`-ஐ raise பண்ணும், இது நீங்க நினைக்கிறதை விட அதிகமா நடக்கும். ஒரு `502` அல்லது `503` பெரும்பாலும் API-க்கு முன்னாடி இருக்குற ஒரு proxy அல்லது load balancer-ல இருந்து வரும், அதோட body ஒரு HTML error page. சில services ஒரு `200` கூட ஒரு HTML maintenance page-ஐ return பண்ணும். Decoding fail ஆனா, என்ன வந்துச்சுன்னு பார்க்க `r.text`-ஓட முதல் 200 characters-ஐ print பண்ணுங்க; worked example-ல இருக்குற helper இதைத் தான் பண்ணுது.

### Timeouts

Default-ஆ `requests`-க்கு timeout இல்லை, அதனால பதிலே சொல்லாத ஒரு server-க்கு போற call முடிவில்லாம wait பண்ணி ஒரு nightly job-ஐ freeze பண்ணிடலாம். எப்பவும் `timeout=` குடுங்க. `timeout=10` மாதிரி ஒரு single number ரெண்டு limits-ஐயும் set பண்ணும். `(5, 20)` மாதிரி ஒரு pair **connect** limit-ஐயும் (server-ஐ அடையுறது) **read** limit-ஐயும் (data-க்காக wait பண்றது) தனித்தனியா set பண்ணும்.

ஒரு gotcha: read limit-னா அடுத்த data துண்டுக்காக wait பண்ற அதிகபட்ச நேரம், முழு download-க்கான limit இல்லை. ஒவ்வொரு சில seconds-க்கும் கொஞ்சம் data அனுப்புற ஒரு server, ஒரு call-ஐ 20 seconds-ஐ விட ரொம்ப அதிக நேரம் உயிரோட வெச்சிருக்க முடியும். ஒரு timeout உண்மையிலேயே fire ஆனா, `requests` `requests.Timeout`-ஐ raise பண்ணும்; அதை catch பண்ணி retry பண்ணுங்க அல்லது தெளிவா report பண்ணுங்க.

### Keys-உம் secrets-உம்

நீங்க share அல்லது commit பண்ற code-ல API keys-ஐ ஒருபோதும் எழுதாதீங்க. Key-ஐ உங்க terminal-ல set பண்ணுங்க (Linux அல்லது macOS-ல `export OPENAQ_API_KEY=...`; Windows PowerShell-ல `$env:OPENAQ_API_KEY="..."`), அதை `os.environ["OPENAQ_API_KEY"]` வெச்சு படிங்க.

அந்த line `KeyError: 'OPENAQ_API_KEY'`-ஐ raise பண்ணா, எந்த request-உம் அனுப்பப்படவே இல்லை: variable **இந்த** terminal-ல set ஆகலை. இன்னொரு terminal-ல நீங்க set பண்ண variable-ஐ ஒரு புது terminal ஞாபகம் வெச்சுக்காது. ஆனா ஒரு `401`-னா request போயிடுச்சு, server key-ஐ reject பண்ணிடுச்சு அல்லது அதை கண்டுபிடிக்க முடியலை. இன்னும் ரெண்டு rules: key-ஐ ஒருபோதும் print அல்லது log பண்ணாதீங்க; அது எப்பவாவது ஒரு public repository-ல போய் சேர்ந்துட்டா, உடனே ஒரு புது key create பண்ணி பழைய key-ஐ delete பண்ணுங்க.

### பாதுகாப்பா retry பண்றது

சில failures சில seconds-க்கு அப்புறம் தானாவே சரியாயிடும்: timeouts, drop ஆன connections, `429`, `5xx`. மத்தது ஒருபோதும் சரியாகாது: ஒரு `401` அல்லது `404`-ஐ எதையும் மாத்தாம retry பண்ணா அதே தப்பு திரும்ப நடக்கும், அவ்வளவு தான். ஒரு நல்ல retry:

- தற்காலிகமா இருக்க வாய்ப்புள்ள failures-ஐ மட்டும் retry பண்ணும்;
- ஒவ்வொரு தடவையும் இன்னும் அதிகமா wait பண்ணும் (**exponential backoff**: 1, 2, 4 seconds), server `Retry-After` header அனுப்பினா அதை follow பண்ணும்;
- சில tries-க்கு அப்புறம் விட்டுட்டு ஒரு தெளிவான error-ஐ raise பண்ணும், ஒரு error reply-ஐ வெச்சுக்கிட்டு தொடர்ந்து போகாது.

**GETs-ஐ தாராளமா retry பண்ணுங்க, ஆனா ஒரு POST-ஐ retry பண்றதுக்கு முன்னாடி யோசிங்க.** ஒரு GET படிக்க மட்டும் தான் செய்யும், அதனால அதை repeat பண்றதுல பிரச்சனை இல்லை. ஒரு POST பெரும்பாலும் ஏதாவது ஒண்ணை *create* பண்ணும்: ஒரு payment, ஒரு order, ஒரு message. முதல் attempt server-ஐ அடைஞ்சு, ஆனா reply திரும்பி வர்ற வழியில தொலைஞ்சுட்டா, கண்மூடித்தனமான ஒரு retry அதை ரெண்டு தடவை create பண்ணிடும். Stripe மாதிரி payment APIs இதை ஒரு **idempotency key** வெச்சு தீர்க்குது: நீங்க ஒரு தடவை உருவாக்கி, அதே request-ஓட ஒவ்வொரு retry-லயும் ஒரு header-ல அனுப்புற ஒரு unique id; அதனால இது repeat-னு server-க்கு தெரியும்.

```python
import uuid

key = str(uuid.uuid4())                       # make it once, before the first try
headers = {"Idempotency-Key": key}            # send the same key on every retry
```

ஒரு API அப்படி ஒரு key குடுக்கலைன்னா, அதோட POSTs-ஐ auto-retry பண்ணாதீங்க; திரும்ப try பண்றதுக்கு முன்னாடி முதல் POST வேலை செஞ்சுதான்னு check பண்ணுங்க.

### Pagination

ஒரு list endpoint எல்லாத்தையும் ஒரே தடவையில return பண்றது அரிது. அது ஒரு தடவைக்கு ஒரு **page** return பண்ணும், நீங்க அடுத்ததை கேக்கணும். OpenAQ `page`, `limit` parameters use பண்ணுது (default `limit` 100), மொத்த எண்ணிக்கையை `meta.found`-ல சொல்லுது. மத்த APIs இதுக்கு பதிலா ஒரு `next` URL அல்லது ஒரு cursor-ஐ return பண்ணும்; எதுன்னு documentation சொல்லும்.

சத்தமில்லாம நடக்குற failure-னா page 1-ஐ மட்டும் படிக்கிறது. Code run ஆகும், 100 results காட்டும், சரியா இருக்குற மாதிரி தெரியும். ஒரு count 100 அல்லது 1000 மாதிரி ஒரு round number-ஆ வந்தா, முதல்ல pagination-ஐ சந்தேகப்படுங்க.

உங்க loop condition-க்கு மொத்த எண்ணிக்கையை நம்பாதீங்க. பெரிய sets-க்கு OpenAQ-ஓட `found` `">1000"` மாதிரி ஒரு string-ஆ இருக்கலாம், அது arithmetic-ஐ உடைச்சுடும். அதுக்கு பதிலா, ஒரு page `limit`-ஐ விட குறைவா அல்லது காலியா வந்தா நிறுத்துங்க, ஒரு safety net-ஆ pages எண்ணிக்கைக்கு ஒரு cap வைங்க (கீழ இருக்குற `get_all`-ஐ பாருங்க).

### Limits-உம் cost-உம்

பெரும்பாலான APIs ஒரு நிமிஷத்துக்கு அல்லது ஒரு நாளைக்கு requests-ஐ limit பண்ணும், paid APIs, language-model APIs உட்பட, use-க்கு charge பண்ணும். நிறைய APIs நீங்க எங்க நிக்கிறீங்கன்னு காட்டுற headers அனுப்பும்; OpenAQ `x-ratelimit-remaining`, `x-ratelimit-reset` அனுப்பும், நீங்க limit-ஐ தாண்டினா `429` return பண்ணும். 500 cities மேல loop பண்றதுக்கு முன்னாடி documentation-ஓட limits page-ஐ படிங்க, calls-க்கு நடுவுல ஒரு சின்ன `time.sleep` சேருங்க, திரும்ப use பண்ணப்போற results-ஐ திரும்ப fetch பண்ணாம cache பண்ணுங்க.

### API documentation-ஐ படிக்கிறது

Code எழுதுறதுக்கு முன்னாடி, documentation-ல இதையெல்லாம் கண்டுபிடிங்க: **base URL**, எப்படி **authenticate** பண்றது, **endpoints**, அவற்றோட **parameters**, ஒரு **example response**, **error codes**, **pagination**, **rate limits**. ஒவ்வொரு தடவையும் API-ஐ call பண்ணாமலே உங்க parsing-ஐ test பண்ண, example response-ஐ ஒரு file-ல save பண்ணுங்க. பின்னாடி ஒரு AI model-ஐ call பண்றதும் இதே routine தான்.

## ஒரு worked example

Anita-க்கு ரெண்டு விஷயங்கள் வேணும்: OpenAQ-க்கு தெரிஞ்ச எல்லா இந்திய stations-ஓட list, ஒரு Delhi station-ஓட latest readings. அவங்க ஒரு சின்ன helper build பண்றாங்க, ஒவ்வொரு call-உம் அது வழியா தான் போகும், அதனால timeout, retries, logging, error checks எல்லாம் ஒரே இடத்துல இருக்கும்.

```python
import logging
import os
import time

import requests

logging.basicConfig(level=logging.INFO)
log = logging.getLogger("aq")

BASE = "https://api.openaq.org/v3"
RETRYABLE = {429, 500, 502, 503, 504}

session = requests.Session()                      # reuses connections
session.headers["X-API-Key"] = os.environ["OPENAQ_API_KEY"]

def get_json(path, params=None, tries=4):
    for attempt in range(tries):
        last = attempt == tries - 1
        wait = 2 ** attempt                       # 1, 2, 4 seconds
        try:
            r = session.get(BASE + path, params=params, timeout=(5, 20))
        except (requests.Timeout, requests.ConnectionError) as e:
            log.warning("%s: %s (try %d)", path, type(e).__name__, attempt + 1)
            if last:
                raise
            time.sleep(wait)
            continue
        if r.status_code in RETRYABLE and not last:
            ra = r.headers.get("Retry-After", "")
            wait = int(ra) if ra.isdigit() else wait
            log.warning("%s: %d, retry in %ds", path, r.status_code, wait)
            time.sleep(min(wait, 60))
            continue
        r.raise_for_status()                      # 4xx, or still failing
        try:
            return r.json()
        except requests.JSONDecodeError:
            raise RuntimeError(f"not JSON: {r.text[:200]!r}") from None
```

ஒவ்வொரு பகுதியும் ஏன் இருக்கு:

- ஒரு **`Session`** connection-ஐ reuse பண்ணும், நிறைய calls-க்கு அது இன்னும் வேகம்; key header-ஐயும் அது வெச்சிருக்கும், அதனால எந்த call-உம் அதை மறக்காது.
- **Timeouts, connection errors catch பண்ணப்பட்டு retry ஆகுது**, ஏன்னா அவை தான் எல்லாத்தையும் விட அதிகமா வர்ற தற்காலிக failure. கடைசி try-ல error மறைக்கப்படாம raise ஆகுது.
- **கடைசி try-க்கு அப்புறம் sleep இல்லை**, wait 60 seconds-க்கு cap பண்ணப்பட்டிருக்கு, அதனால ஒரு விசித்திரமான `Retry-After` value job-ஐ ஒரு மணி நேரம் நிறுத்தி வைக்க முடியாது.
- **Retry ஆகாத ஒவ்வொரு reply-லயும் `raise_for_status()` run ஆகுது**, அதனால ஒரு `401`, ஒரு `404`, அல்லது சரியாகவே ஆகாத ஒரு `503` ஒரு தெளிவான message கூட program-ஐ நிறுத்தும்.
- **ஒவ்வொரு failure-உம் path, status கூட log ஆகுது**; ஒரு nightly job 3 a.m.-க்கு fail ஆகும்போது உங்களுக்கு தேவைப்படுறது இது தான்.

அப்புறம் ரெண்டு tasks:

```python
def get_all(path, params, limit=100, max_pages=50):
    rows = []
    for page in range(1, max_pages + 1):
        data = get_json(path, {**params, "limit": limit, "page": page})
        batch = data["results"]
        rows.extend(batch)
        if len(batch) < limit:                    # short or empty page
            break
    return rows

stations = get_all("/locations", {"iso": "IN"})
print(len(stations), "stations")
for s in stations[:3]:
    print(s["id"], s["name"])

latest = get_json("/locations/8118/latest")
for row in latest["results"]:
    print(row["sensorsId"], row["value"], row["datetime"]["local"])
```

ஒவ்வொரு `sensorsId`-உம் station-ல இருக்குற ஒரு instrument, உதாரணமா அதோட PM2.5 அல்லது NO2 sensor. ஒரு தனி endpoint, `/locations/8118/sensors`, ஒவ்வொண்ணும் எந்த pollutant-ஐ measure பண்ணுதுன்னு சொல்லும். இப்படி ரெண்டு endpoints-ஐ join பண்றது சாதாரண API வேலை தான்.

அவங்களோட முதல் runs இப்படி போச்சு:

| Run | அவங்க என்ன பார்த்தாங்க | காரணம் | Fix |
| --- | --- | --- | --- |
| 1 | `KeyError: 'OPENAQ_API_KEY'`, எந்த request-உம் அனுப்பப்படலை | அவங்க ஒரு புது terminal-ஐ திறந்தாங்க, அங்க variable set ஆகலை | அந்த terminal-ல variable-ஐ set பண்ணி, திரும்ப run பண்ணாங்க |
| 2 | `401 Client Error: Unauthorized` | இன்னொரு API-ஓட tutorial-ல இருந்து `Authorization: Bearer ...`-ஐ copy பண்ணிருந்தாங்க | OpenAQ-ஓட docs சொல்ற மாதிரி key-ஐ `X-API-Key`-ல அனுப்பினாங்க |
| 3 | `TypeError: list indices must be integers or slices, not str` | அவங்க `latest["results"]["value"]` எழுதினாங்க; `results` ஒரு list | Shape-ஐ print பண்ணி, அப்புறம் list மேல loop பண்ணாங்க |
| 4 | முழு இந்தியாவுக்கும் சரியா 100 stations | `/locations`-ஐ ஒரு தடவை call பண்ணி page 1-ஐ மட்டும் படிச்சாங்க | Pages மேல loop பண்ண `get_all` எழுதினாங்க |
| 5 | `429, retry in 1s`-ங்குற ஒரு log line, அப்புறம் முழு list | வேகமா page பண்ணதால rate limit-ஐ தொட்டுச்சு | எதுவும் இல்லை: helper wait பண்ணி தொடர்ந்துச்சு |

Runs 1-ல இருந்து 3 வரை ஒவ்வொண்ணும் ஒரு வேற error type குடுத்துச்சு, ஒவ்வொரு type-உம் நேரா அதோட காரணத்தை காட்டுச்சு. Code-ஐ திரும்ப படிக்கிறதுக்கு முன்னாடி error-ஓட முதல் வார்த்தையை படிங்க.

Script பெருசாகும்போது, retry வேலையை `requests` எந்த library மேல build ஆயிருக்கோ அதுகிட்ட குடுத்துடலாம். இது ஒரு common production setup:

```python
import requests
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

retry = Retry(total=4, backoff_factor=1,
              status_forcelist=[429, 500, 502, 503, 504],
              allowed_methods=["GET"])        # never auto-retry POST
session = requests.Session()
session.mount("https://", HTTPAdapter(max_retries=retry))
```

அது back off பண்ணும், 429, 503-ல `Retry-After`-ஐ follow பண்ணும், connection errors-ஐ உங்களுக்காக retry பண்ணும். List-ல இருக்குற ஒரு status-ல tries தீர்ந்துட்டா, கடைசி reply-ஐ return பண்ணாம `requests.exceptions.RetryError`-ஐ raise பண்ணும், அதனால அதையும் catch பண்ணுங்க. ஒவ்வொரு call-க்கும் timeout, ஒரு JSON check, ஒரு page loop இன்னும் உங்களுக்கு வேணும்.

## பொதுவா பண்ற தப்புகள்

- **Status-ஐ check பண்றதுக்கு முன்னாடி data-வை படிக்கிறது.** அப்போ ஒரு error reply சில lines-க்கு அப்புறம் குழப்பமா fail ஆகும். முதல்ல `raise_for_status()`-ஐ call பண்ணுங்க.
- **Timeout இல்லை.** பதில் சொல்லாத ஒரு server முழு program-ஐயும் hang பண்ணிடும்.
- **JSON shape-ஐ guess பண்றது.** `json.dumps(data, indent=2)` வெச்சு ஒரு தடவை print பண்ணி, அப்புறம் access path-ஐ எழுதுங்க.
- **ஒரு list மேல string key.** அது தான் மேல சொன்ன `TypeError`; ஒரு index-ஐ எடுங்க அல்லது loop பண்ணுங்க.
- **`null` values இருக்கும்போது `.get(key, default)`-ஐ நம்புறது.** Key `null` கூட இருந்தா அது `None`-ஐ return பண்ணும்.
- **Page 1-ஐ மட்டும் படிக்கிறது.** 100 மாதிரி ஒரு round count தான் எச்சரிக்கை அடையாளம்.
- **எல்லாத்தையும் retry பண்றது, அல்லது ரொம்ப வேகமா பண்றது.** `401` அல்லது `404`-ஐ retry பண்ணா calls வீணாகும், ஒரு tight loop உங்களை block ஆக்கிடும், idempotency key இல்லாம ஒரு POST-ஐ retry பண்ணா ஒரு customer-கிட்ட ரெண்டு தடவை charge ஆகலாம்.
- **Code, screenshots அல்லது logs-ல keys.** Environment variables use பண்ணுங்க, ஒரு key leak ஆனா உடனே அதை replace பண்ணுங்க.

## Practice பண்ணுங்க

கீழ link பண்ணிருக்குற requests library-ஓட quickstart-ஐ படிங்க, அப்புறம் இந்த உண்மையான APIs-ல ஒண்ணை use பண்ணுங்க (ரெண்டுமே November 2026 நிலவரப்படி check பண்ணப்பட்டது):

- **OpenAQ**: இந்திய நகரங்களுக்கான air-quality data. அதுக்கு அதோட website-ல இருந்து ஒரு free key வேணும், அது `X-API-Key` header-ல அனுப்பப்படும்.
- **Open-Meteo**: weather, air-quality forecasts. அதுக்கு key வேண்டாம், non-commercial use-க்கு free, அதனால இது தான் எல்லாத்தையும் விட வேகமான முதல் call.

1. **Call பண்ணி பாருங்க.** ஒரு endpoint-ஐ call பண்ணி, `json.dumps(data, indent=2)` வெச்சு reply-ஐ print பண்ணி, மூணு values-க்கு access paths எழுதுங்க; குறைஞ்சது ஒண்ணாவது ஒரு list-க்குள்ள இருக்கணும்.
2. **வேணும்னே fail பண்ண வைங்க.** ஒரு தப்பான key, ஒரு தப்பான path, `timeout=0.001` அனுப்புங்க. ஒவ்வொண்ணுக்கும் வர்ற சரியான error-ஐ note பண்ணுங்க, `r.json()`-ல crash ஆகாம உங்க code ஒரு தெளிவான message print பண்ணுதான்னு check பண்ணுங்க.
3. **Helper-ஐ சேருங்க.** ஒவ்வொரு call-க்கும் முன்னாடி `get_json` helper-ஐ வெச்சு, அது log பண்ணி retry பண்ணுதான்னு confirm பண்ணுங்க.
4. **எல்லா page-ஐயும் படிங்க.** ஒரு list endpoint-க்கு, ஒரு page cap கூட எல்லா pages-ஐயும் fetch பண்ணி, உங்க count-ஐ page 1-ல மட்டும் வர்றதோட compare பண்ணுங்க.
5. **Key-ஐ secure பண்ணுங்க.** அதை ஒரு environment variable-க்கு மாத்தி, ஒரு புது terminal-ஐ திறந்து, அது set ஆகலைன்னா என்ன நடக்கும்னு உங்களுக்கு தெரியுமான்னு confirm பண்ணுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** ஒரு key, ஒரு timeout கூட ஒரு API-ஐ call பண்ண முடியும், ஒரு failure உங்களோடதா server-ஓடதான்னு error-ஐ மட்டும் வெச்சு சொல்ல முடியும், guess பண்ணாம nested JSON-ஐ படிக்க முடியும், எல்லா page-ஐயும் fetch பண்ண முடியும், எந்த failures-ஐ retry பண்றீங்க ஏன்னு explain பண்ண முடியும்.
