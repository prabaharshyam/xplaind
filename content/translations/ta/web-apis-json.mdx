## இது என்ன

உங்க program எல்லாத்தையும் தானே தெரிஞ்சுக்க வேண்டியதில்லை. ஒரு **web API** இன்னொரு service-கிட்ட internet வழியா data அல்லது actions-ஐ கேக்க விடும்: இன்னைக்கு வானிலை, ஒரு map route, ஒரு payment-ஓட status, அரசாங்க open data, இல்லன்னா ஒரு AI model-ஓட பதில். ஒவ்வொரு AI model provider-உம் இப்படித்தான் வேலை செய்றாங்க, அதனால Python-ல இருந்து ஒரு API-ஐ call பண்றது தான், அப்புறம் language models-ஐ call பண்றதுக்கு அடிப்படை skill.

ஒரு URL-க்கு **HTTP request** அனுப்புறீங்க. Service இதோட reply பண்ணும்:

- ஒரு **status code**: வேலை செஞ்சுதா?
- பெரும்பாலும் **JSON**-ல ஒரு body: அதான் data.

```flow
dir: LR
உங்க Python program | requests.get(...) -[GET /weather?city=Chennai, header X-API-Key]-> Weather service
Weather service -[200 OK, JSON body]-> r.json() | city: "Chennai", temp_c: 31.5
```

தன்னோட ஊருக்கு ஒரு சின்ன air-quality dashboard build பண்ற Anita-வை இந்த lesson follow பண்ணும். Lesson முடியும்போது ஒரு public API-ஐ call பண்ணி, status-ஐ check பண்ணி, nested JSON-ஐ பாதுகாப்பா படிக்க முடியும்.

## இது எப்படி work ஆகுது

### requests library

```python
import requests

r = requests.get("https://api.example.com/weather",
                 params={"city": "Chennai"}, timeout=10)
print(r.status_code)
data = r.json()          # JSON text becomes Python dictionaries and lists
print(data["temp_c"])
```

`params` URL-ல query parameters-ஐ சேர்க்கும்; அதனால இந்த request `.../weather?city=Chennai`-க்கு போகும்.

### Status codes

| Code | அர்த்தம் | என்ன பண்றது |
| --- | --- | --- |
| `200` | OK: வேலை செஞ்சுது | Data-வை use பண்ணுங்க |
| `400` | Bad request: உங்க request-ல ஏதோ தப்பு | Parameters, body-ஐ check பண்ணுங்க |
| `401` / `403` | Sign in ஆகல, அல்லது அனுமதி இல்லை | API key-ஐயும் permissions-ஐயும் check பண்ணுங்க |
| `404` | கிடைக்கல | URL அல்லது item id-ஐ check பண்ணுங்க |
| `429` | ரொம்ப அதிகமான requests | மெதுவா போங்க; காத்திருந்து retry பண்ணுங்க |
| `500` முதல் `504` | Server fail ஆயிடுச்சு | பெரும்பாலும் temporary; அப்புறம் retry பண்ணுங்க |

Data-வை use பண்றதுக்கு முன்னாடி check பண்ணுங்க. `r.raise_for_status()` 4xx, 5xx codes-க்கு error raise பண்ணும்; அதனால உங்க code ஒரு error reply-ஐ data மாதிரி எடுத்துக்கிட்டு தொடராது.

### Python-ல JSON

`r.json()` reply-ஐ dictionaries (JSON objects-க்கு), lists (JSON arrays-க்கு)-ஆ மாத்தும். Nested values-ஐ step by step படிங்க:

```python
data["current"]["temp_c"]          # an object inside an object
data["results"][0]["location"]     # the first item of a list
```

அதை படிக்குற code எழுதுறதுக்கு முன்னாடி, முழு reply-ஐயும் ஒரு தடவை print பண்ணி, அதோட உண்மையான shape-ஐ பாருங்க.

### Parameters, headers, bodies

| பகுதி | எதுக்கு | Example |
| --- | --- | --- |
| `params` | URL-ல query parameters | `params={"city": "Pune"}` |
| `headers` | Keys, content type, மத்த metadata | `headers={"Authorization": "Bearer ..."}` |
| `json` | நீங்க அனுப்புற JSON body, பெரும்பாலும் POST-ஓட | `requests.post(url, json={"text": "..."})` |

### Timeouts

`timeout=` இல்லன்னா, மெதுவான அல்லது உடைஞ்ச server-க்கு போற request **எப்பவும்** தொங்கி, உங்க program-ஐயோ முழு automation-ஐயோ freeze பண்ணிடலாம். எப்பவும் ஒண்ணு set பண்ணுங்க, `requests.Timeout`-ஐ handle பண்ணுங்க.

### Keys-உம் secrets-உம்

நீங்க share அல்லது commit பண்ற code-ல API keys-ஐ எழுதவே எழுதாதீங்க. Environment variable-ல இருந்து படிங்க:

```python
import os
key = os.environ["AQ_KEY"]
```

### பாதுகாப்பா retry பண்றது

சில failures தானாவே சரியாகிடும். ஒரு `429` அல்லது `503` சில வினாடிகள் கழிச்சு பெரும்பாலும் வேலை செய்யும். ஒரு எளிய, மரியாதையான retry இப்படி இருக்கும்:

```python
import time

for attempt in range(3):
    r = requests.get(url, params=params, timeout=10)
    if r.status_code not in (429, 500, 502, 503, 504):
        break
    retry_after = r.headers.get("Retry-After", "")
    wait = int(retry_after) if retry_after.isdigit() else 2 ** attempt
    time.sleep(wait)
```

இது temporary-ஆ இருக்க வாய்ப்புள்ள errors-ஐ மட்டும் retry பண்ணும், ஒவ்வொரு தடவையும் அதிக நேரம் காத்திருக்கும், server `Retry-After` header அனுப்பினா அதை மதிக்கும். `401` அல்லது `404`-ஐ எப்பவும் retry பண்ணாதீங்க: request-லயே தப்பு, திரும்ப பண்ணாலும் எதுவும் மாறாது.

### API documentation-ஐ படிக்கிறது

ஒவ்வொரு API-ஓட documentation-உம் அதே கேள்விகளுக்கு பதில் சொல்லும், பெரும்பாலும் இந்த வரிசையில: **base URL**, எப்படி **authenticate** பண்றது (எந்த header-ல key போகும்), **endpoints** (`/latest`, `/holidays` மாதிரி paths), ஒவ்வொரு endpoint-ஓட **parameters**, ஒரு **example response**, அது use பண்ற **error codes**, அதோட **rate limits**. Code எழுதுறதுக்கு முன்னாடி இந்த sections-ஐ படிங்க, example response-ஐ ஒரு file-ல copy பண்ணி வச்சுக்கோங்க; அப்போ ஒவ்வொரு தடவையும் API-ஐ call பண்ணாம உங்க parsing-ஐ test பண்ணலாம். அப்புறம் ஒரு AI model-ஓட API-ஐ call பண்றதும் இதே process தான்: endpoint-ஐ கண்டுபிடிங்க, header-ல key-ஐ அனுப்புங்க, ஒரு JSON body-ஐ post பண்ணுங்க, JSON reply-ஐ படிங்க.

### Limits-உம் cost-உம்

பெரும்பாலான APIs நிமிஷத்துக்கு requests-ஐ limit பண்ணும், சில call-க்கு காசு வாங்கும். Documentation-ஓட limits section-ஐ படிங்க; `429` வந்தா server-ஐ போட்டு அடிக்காம, காத்திருந்து, அதிகமாகுற delay-ஓட retry பண்ணுங்க.

## ஒரு worked example

Anita தன்னோட ஊரோட air quality-க்கு ஒரு சின்ன dashboard build பண்றாங்க. ஒரு location-ஓட தற்போதைய readings-ஐ தர்ற ஒரு public API-ஐ use பண்றாங்க.

```python
import os, requests

url = "https://api.airquality.example/v1/latest"
r = requests.get(url, params={"city": "Delhi"},
                 headers={"X-API-Key": os.environ["AQ_KEY"]}, timeout=10)

if r.status_code == 200:
    for reading in r.json()["results"][:5]:
        print(reading["location"], reading["parameter"], reading.get("value", "no reading"))
elif r.status_code == 429:
    print("Rate limited; try again in a minute")
else:
    print("Request failed:", r.status_code, r.text[:200])
```

(இங்க இருக்குற URL ஒரு உதாரணம் தான்; lesson-ஓட resource-ல உண்மையான, வேலை செய்யுற examples இருக்கு.)

| Run | என்ன நடந்துச்சு | காரணம் | Fix |
| --- | --- | --- | --- |
| 1 | `401 Unauthorized` | புது terminal-ல அவங்க key set ஆகல | Run பண்றதுக்கு முன்னாடி `export AQ_KEY=...` |
| 2 | `200`, அப்புறம் ஒரு location-ல `KeyError: 'value'` | சில locations-ல `value` field இல்லை | முழு JSON-ஐ print பண்ணாங்க; `.get("value", "no reading")` use பண்ணாங்க |
| 3 | நிமிஷக்கணக்கா தொங்குச்சு | Test பண்றப்போ `timeout=`-ஐ எடுத்துட்டாங்க | `timeout=10`-ஐ திரும்ப போட்டாங்க |
| 4 | ஐந்து readings print ஆச்சு | வேலை செய்யுது | Dashboard-க்கு ready |

ரெண்டாவது run-ல முழு JSON-ஐ ஒரு தடவை print பண்ணது, அவங்களுக்கு ஒரு மணி நேர ஊகத்தை மிச்சப்படுத்துச்சு.

## பொதுவா பண்ற தப்புகள்

- **Status code-ஐ check பண்ணாம இருக்கிறது.** அப்புறம் error replies-ல code குழப்பமா fail ஆகும்.
- **Timeout இல்லாம இருக்கிறது.** மெதுவான server உங்க program-ஐ தொங்க வைக்கும்.
- **JSON shape-ஐ ஊகிக்கிறது.** முதல்ல print பண்ணி படிங்க.
- **Code-ல API keys.** Environment variables use பண்ணுங்க.
- **Rate limits-ஐ புறக்கணிக்கிறது.** மதிங்க, இல்லன்னா block ஆயிடுவீங்க.
- **எல்லா fields-உம் எப்பவும் இருக்கும்னு நினைக்கிறது.** Optional fields-க்கு default-ஓட `.get()` use பண்ணுங்க.

## Practice பண்ணுங்க

கீழே link பண்ணியிருக்குற requests library-ஓட quickstart-ஐ படிங்க.

1. **Call.** Public holidays API அல்லது ஒரு இந்திய open data API மாதிரி, ஒரு free public API-ஐ call பண்ணி, JSON-ல இருந்து மூணு values-ஐ print பண்ணுங்க.
2. **Errors-ஐ handle பண்ணுங்க.** 404, 429, ஒரு timeout-ஐ தெளிவான messages-ஓட handle பண்ணுங்க.
3. **Key-ஐ பாதுகாருங்க.** எந்த key-யையும் ஒரு environment variable-க்கு மாத்தி, code இன்னும் வேலை செய்யுதான்னு உறுதி பண்ணுங்க.

**முடிஞ்சதுன்னு எப்போ சொல்லலாம்:** ஒரு API-ஐ call பண்ண, status-ஐ check பண்ண, nested JSON-ஐ பாதுகாப்பா படிக்க, ஒவ்வொரு request-க்கும் ஏன் timeout வேணும்னு explain பண்ண முடியும்.
