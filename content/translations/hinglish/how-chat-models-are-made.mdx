## Ye kya hai

Jin chat assistants ko aap roz use karte ho, woh ek baar mein train nahi hue. Woh stages mein bante hain, aur har stage kuch alag jodta hai.

1. **Pre-training.** Model bahut saara text (web pages, books, code) padhta hai aur agla token predict karna seekhta hai. Isme zyadatar paisa aur compute lagta hai. Result ek **base model** hota hai. Use language aur duniya ke baare mein bahut kuch pata hota hai, par woh sirf text ko aage badhata hai.
2. **Supervised fine-tuning (SFT).** Base model ko prompt aur ideal answer ke examples par train kiya jaata hai, jo logon ne likhe ya check kiye. Woh instructions follow karna aur assistant ki tarah reply karna seekhta hai. Ise instruction tuning bhi kehte hain.
3. **Preference tuning.** Log ek hi prompt ke do answers compare karte hain aur behtar chunte hain. Phir model ko aise tune kiya jaata hai ki pasandida answers zyada sambhaavit ho jayein. Do aam methods hain **RLHF** (reinforcement learning from human feedback) aur **DPO** (direct preference optimisation).

Stage 2 aur 3 milkar aksar **post-training** kehlate hain. Ye total compute ka chhota hissa lete hain par model ke behaviour ko bahut badal dete hain. Jab koi provider kisi model ka "base" aur "instruct" ya "chat" dono version release karta hai, toh farak post-training ka hota hai.

```flow
title: Raw text se chat model tak
dir: LR
Huge text collection | web, books, code
Huge text collection -> Pre-training | predict the next token
Pre-training -> Base model | continues text
Base model -> Supervised fine-tuning | prompt and ideal answer
Supervised fine-tuning -> Instruct model | follows instructions
Instruct model -> Preference tuning | RLHF or DPO
Preference tuning -> Chat model | helpful, polite, safer
```

Ek kaam ki tasveer: pre-training model ko knowledge deti hai, SFT use helpful hone ka format sikhati hai, aur preference tuning is par uska judgement banati hai ki kai mumkin answers mein se log asal mein kaunsa chahte hain.

## Ye kaam kaise karta hai

**Stage 1: pre-training.** Training text ko tokens mein kaata jaata hai. Har position ke liye model agla token guess karta hai, apne guess ko asli token se compare karta hai, aur apne weights ko bahut thoda adjust karta hai. Trillions of tokens par dohrane se ye grammar, facts, reasoning patterns aur code sikhata hai. Model kya seekhta hai ye bahut kuch is par depend karta hai ki woh kya padhta hai. Agar koi language, jaise Odia ya Assamese, training text mein kam ho, toh model usmein kamzor hoga.

Base model ko "How do I reset my UPI PIN?" prompt do toh woh jawab de sakta hai, ya sawaalon ki ek aur list bana sakta hai, kyunki web par sawaalon se bhare pages aam hain. Woh jaanbujhkar unhelpful nahi hai. Woh sambhaavit text predict kar raha hai.

**Stage 2: supervised fine-tuning.** Trained log hazaaron prompts ke saath high-quality answers likhte hain: explanations, summaries, code, polite refusals. OpenAI ka InstructGPT kaam, ek shuruaati public example, aise lagbhag 13,000 demonstration examples use karta tha. Inhein likhna slow aur mehnga hai, kyunki ek mushkil sawaal ka achha jawab likhne mein kisi skilled insaan ko lamba samay lag sakta hai. SFT ke baad model sawaalon ko aage badhane ki jagah unka jawab deta hai.

Ek SFT example ek chhoti chat jaisa dikhta hai:

```json
{"messages": [
  {"role": "user", "content": "How do I reset my UPI PIN?"},
  {"role": "assistant", "content": "Open your UPI app, go to the bank account, choose Reset UPI PIN, and verify with your debit card details and the OTP sent to your phone."}
]}
```

**Stage 3: preference tuning.** Kisi bhi prompt ke kai acceptable answers hote hain, aur kuch doosron se behtar. Ek sabse achha answer likhna mushkil hai, par do answers compare karna aasaan. Isliye logon ko ek prompt aur model ke do answers dikhaye jaate hain aur poochha jaata hai ki kaunsa behtar hai. Har judgement ek **preference pair** ban jaata hai:

```json
{"prompt": "My order is late. What can I do?",
 "chosen": "Sorry about the delay. You can track it under My Orders. If it is more than 3 days late, you can ask for a refund there.",
 "rejected": "Orders are sometimes late. Please wait."}
```

In pairs se seekhne ke do mukhya tareeke hain.

- **RLHF.** Pehle pairs par ek alag **reward model** train karo, taaki woh kisi bhi answer ko score de sake ki log use kitna pasand karenge. Phir chat model ko reinforcement learning se aise answers dene ke liye train karo jo high scores kamayein, saath hi SFT model ke kareeb rehkar, taaki woh ajeeb text mein na bahe jo score achha le leta ho.
- **DPO.** Reward model chhod do. Chat model ko seedhe pairs par train karo, chosen answer ko zyada aur rejected ko kam sambhaavit banao, jahan se shuru kiya tha usse relative. Ye aam training code use karta hai, sasta hai aur chalaane mein zyada stable hai. Kai open model families DPO ya aise methods par aa gayi hain.

Ek teesra variant, **RLAIF**, kaunsa answer behtar hai ye judge karne ke liye logon ki jagah ek strong model use karta hai. Ye sasta hai par judge model ke blind spots virasat mein le leta hai.

| Stage | Training data | Kya jodta hai | Andaaza cost |
| --- | --- | --- | --- |
| Pre-training | Trillions of tokens raw text | Language, facts aur code ki knowledge | Zyadatar compute; sirf bade labs karte hain |
| Supervised fine-tuning | Hazaaron se das hazaar prompt aur ideal-answer pairs | Instructions follow karna, assistant ki tarah reply | Chhota compute; mehnga expert writing |
| Preference tuning (RLHF ya DPO) | Das hazaar se zyada chosen aur rejected pairs | Behtar judgement, tone aur safety | Chhota compute; sasti human comparisons |

Ye aankde mote patterns hain, exact numbers nahi. Har lab ki recipe alag hai aur samay ke saath badalti hai.

**Browser mein try karo.** Ek reward model preferences ko scores mein badalta hai. Dekho ki ek pairwise preference kaise probability ban jaati hai.

```python
import math

def prefer_probability(score_a, score_b):
    return 1 / (1 + math.exp(-(score_a - score_b)))      # the Bradley-Terry form used in reward modelling

pairs = [("helpful, cites the policy", 2.1, "vague answer", 0.4),
         ("polite refusal", 0.2, "unsafe instructions", -1.5),
         ("short and right", 1.0, "long and right", 0.9)]
for a, sa, b, sb in pairs:
    print(f"P({a!r} preferred over {b!r}) = {prefer_probability(sa, sb):.2f}")
```

## Ek example se samjho

Hyderabad ki ek team chhote dukaandaaron ko Telugu aur English mein bank statements samjhane waala bot bana rahi hai. Har stage kya jodta hai ye dekhne ke liye, woh ek hi open-weight model family ke teen versions ko ek prompt par compare karte hain, "Explain this ₹2,350 debit marked NACH".

| Version | Prompt ke saath kya kiya | Kyun |
| --- | --- | --- |
| Base model | Forum post jaisi teen aur lines likhi, phir ek alag sawaal | Woh sirf text aage badhata hai; forum posts aam hain |
| SFT ke baad | Samjhaya ki NACH ek automatic debit hai, aam taur par loan EMI ya subscription, ek lambe, formal paragraph mein | Usne helpful answer ka format seekha |
| Preference tuning ke baad | Wahi explanation teen chhoti lines mein di, bank app mein mandate list check karne ka suggestion diya, aur ek aur entry samjhane ka offer kiya | Logon ne agle kadam ke saath chhote, practical answers ko pasand kiya tha |

Team chat version ko apna starting point chunti hai. Phir unhein dikhta hai ki uske Telugu replies akade hue hain aur kabhi-kabhi English mein badal jaate hain. Ye gap pre-training se aata hai, jahan Telugu text kam tha. Kitni bhi prompting pre-training ke gap ko poori tarah theek nahi karti, isliye woh 200 real sawaalon par do options test karte hain: Telugu examples ke saath ek dhyaan se likha prompt, aur unke Telugu bolne waale support staff ke likhe 1,500 replies par ek chhoti SFT run. Jo unke apne test par behtar score kare, woh rakhte hain, public leaderboard par nahi.

## Aam galtiyaan

- **Base model ko chatbot ki tarah use karna.** Woh jawab dene ki jagah text aage badhata hai. Instruct ya chat version download karo, jab tak aap apni SFT plan nahi kar rahe.
- **Ye sochna ki post-training knowledge jodti hai.** Ye zyadatar behaviour badalti hai. Facts pre-training se ya run time par retrieval se aate hain.
- **Ye maan lena ki RLHF model ko sachcha banata hai.** Ye un answers ko reward deti hai jo log pasand karte hain, aur log confident, fluent par galat text bhi pasand kar sakte hain.
- **Refusals ko apne prompt ka bug samajhna.** Zyada savdhaani waale refusals aksar preference tuning se aate hain. Saaf prompt madad karta hai, par kuch behaviour andar hi baked hai.
- **Interview mein DPO aur RLHF ko mix karna.** Dono preference pairs se seekhte hain. RLHF pehle reward model train karta hai; DPO nahi.

## Chat models aisa behave kyun karte hain

Roz ki kai quirks inhi stages se judi hain.

- **Sycophancy.** Models aapse sehmat hone ki taraf jhukte hain, kyunki preference tuning ke dauran sehmat hone waale answers aksar pasand kiye gaye.
- **Lambe, bhare hue answers.** Agar reviewers ne thorough answers ko reward diya, toh model seekh leta hai ki lamba behtar dikhta hai.
- **Languages mein asamanta.** Hindi ya Tamil ki quality is par depend karti hai ki us language ka kitna hissa pre-training aur SFT examples mein tha.
- **Knowledge cut-off.** Model ko pre-training data collect hone ke baad ki koi cheez nahi pata, jab tak aap use taaza information na do.

## Demo se production tak

- **Model card padho.** Ye aam taur par batata hai ki model kin stages se guzra, kaunsa data use hua aur kaunsi languages cover hui.
- **Sahi version chuno.** Applications ke liye instruct ya chat versions use karo. Base model sirf tab jab aap apni SFT karoge, ya plain text completion ke liye.
- **Apni languages mein test karo.** Model ko apne users ki likhi har language mein real sawaalon par score karo, mixed Hinglish ya Tanglish samet.
- **Apne pairs sambhaal kar rakho.** Jab reviewers koi reply theek karein ya do drafts mein se chunein, use store karo. Ye baad mein SFT aur preference data ban jaate hain.
