## Ye kya hai

**Triage** ka matlab hai ye decide karna ki har incoming message kya hai, kitna urgent hai aur kise handle karna chahiye. AI triage pehla pass automate karta hai:

- **Classify**: ye kis tarah ka message hai (billing, delivery, technical issue, complaint, sales enquiry, spam)?
- **Extract**: woh details jo team ko chahiye (order number, account id, product, location).
- **Prioritise**: urgent hai ya nahi (service down, payment failed, legal threat, VIP customer).
- **Route**: sahi team ya insaan ko, sahi tool mein.
- **Draft**: ek suggested reply jise koi insaan check karke bheje.

```flow
Incoming email ya ticket -> AI step, structured output | category, priority, fields, summary, unsure?
AI step, structured output -> Upar se rules | key account? legal words? data deletion?
Upar se rules -[rule match ho]-> Priority force karo, senior ya privacy contact ko route karo
Upar se rules -> Unsure?
Unsure? -[haan]-> General queue | koi insaan sort karta hai
Unsure? -[nahi]-> Help desk mein route karo | team, priority, summary, draft reply
Help desk mein route karo -> Agent draft check karta hai, edit karta hai, bhejta hai
```

Is lesson mein hum Chennai ke ek broadband provider ke saath chalenge, jiske support inbox mein roz lagbhag 2,500 emails aate hain.

## Ye kaam kaise karta hai

**Categories team ke saath define karo.** Wahi categories lo jinke saath aapki support ya operations team pehle se kaam karti hai, har ek ki ek line ki definition aur do-teen example messages ke saath. "Other / unclear" zaroor rakho.

**Structured output ke saath classify karo.** AI step category, priority, extracted fields, ek line ka summary aur confidence ya "unsure" flag, ek fixed shape mein deta hai.

**AI ke aas-paas rules.** Kuch decisions rules hone chahiye, AI judgement nahi: key accounts ki list ke messages hamesha high priority; legal action, police ya consumer court ka zikr karne waala koi bhi message senior insaan ke paas jaata hai; data deletion ki koi bhi baat privacy contact ke paas jaati hai.

**Route karo.** Help desk mein ticket banao ya update karo, team assign karo, priority set karo aur extracted fields aur summary jodo. Unsure cases general queue mein jaate hain jahan koi insaan sort karta hai.

**Replies draft karo, bhejo mat (shuru mein).** Customer ke message, extracted details aur apne knowledge base se reply draft banao aur ticket mein rakh do taaki agent edit karke bheje. Hafton quality measure karne ke baad hi simple, low-risk replies (jaise "hamein aapki request mil gayi hai") automatic bheji jaayein.

**Languages.** India ke customers English, Hindi, Tamil, Hinglish aur aur bhi kai mein likhte hain. Jo bhi language aapko milti hai, har ek mein real messages par triage test karo.

**Measure karo.** Weekly sample par classification accuracy, pehli baar mein sahi route hone ka share, pehle response tak ka time, aur agents drafts ko kitna edit karte hain.

**Ek category definition jo AI aur team dono samjhein:**

| Category | Definition | Example messages |
| --- | --- | --- |
| Outage | Internet bilkul nahi, shaayad poore area par asar | "Net not working since morning", "Wi-Fi light red" |
| Slow speed | Connected hai par plan se slow | "Getting 5 Mbps on a 100 Mbps plan" |
| Billing | Charges, payments, refunds | "Charged twice this month" |
| Relocation | Connection ko naye address par shift karna | "Shifting to Velachery next week" |
| Other or unclear | Kuch aur, ya pakka nahi | "Hi", forwarded newsletters |

Ye definitions seedhe prompt mein jaati hain. Team kisi category ko badle toh definition ek hi jagah badalti hai, aur test set mein uske naye examples jud jaate hain.

**Drafts se shuru kyun karein.** 92% classification accuracy par bhi, gusse mein bhare customer ko galat automatic reply jaana sach mein nuksaan karta hai. Drafts se agents wo 8% theek kar lete hain aur 92% par time bachta hai. Measure karo ki agents har draft ko kitna edit karte hain: jab kisi category ke zyadatar drafts kai hafton tak bina badle chale jaayein, toh woh category automatic sending ki candidate hai, simple acknowledgements se shuru karke.

**Pehle rules, phir model, code mein.** Fixed rules kisi bhi model call se pehle chalte hain, isliye unhe baaton mein bahkaya nahi ja sakta:

```python
from typing import Literal
from pydantic import BaseModel

Category = Literal["outage", "slow_speed", "billing", "relocation", "other"]

class Triage(BaseModel):
    category: Category
    priority: Literal["p1", "p2", "p3"]
    account_id: str | None = None
    summary: str
    unsure: bool

KEY_ACCOUNTS = {"ACC-1001", "ACC-2040"}
LEGAL_WORDS = ("legal notice", "consumer court", "police complaint", "lawyer")

def triage(message, sender_account, classify):
    text = message.lower()
    if any(w in text for w in LEGAL_WORDS):
        return {"queue": "senior", "priority": "p1", "reason": "legal words"}
    if "delete my data" in text or "erase my data" in text:
        return {"queue": "privacy", "priority": "p2", "reason": "data request"}
    t: Triage = classify(message)                 # structured output from the model
    if t.unsure or t.category == "other":
        return {"queue": "general", "priority": t.priority, "reason": "unsure"}
    priority = "p1" if sender_account in KEY_ACCOUNTS else t.priority
    return {"queue": t.category, "priority": priority, "summary": t.summary, "account": t.account_id}
```

**Dekho kahan galat ho raha hai.** Overall accuracy chhupa deti hai ki kaunsi categories aapas mein mix hoti hain. Apne labelled set se confusion table banao:

```python
from collections import Counter

def confusion(pairs):
    """pairs: list of (true_category, predicted_category)."""
    counts = Counter(pairs)
    cats = sorted({c for p in pairs for c in p})
    print("true \\ predicted".ljust(14) + "".join(c[:9].ljust(10) for c in cats))
    for t in cats:
        print(t[:13].ljust(14) + "".join(str(counts[(t, p)]).ljust(10) for p in cats))
    acc = sum(counts[(c, c)] for c in cats) / len(pairs)
    print(f"accuracy {acc:.0%}")
```

Agar "slow_speed" aksar "outage" predict hota hai, toh dono definitions tight karo aur dono ke boundary ke paas ke examples jodo. Accuracy language ke hisaab se bhi batao: jab tak examples nahi jodte, Hinglish messages aksar English se kharab perform karte hain.

**Galtiyon ki cost alag-alag hoti hai.** Outage ko billing mein bhejne se poore area ka fix late hota hai; billing ko general mein bhejne se bas kuch minute jaate hain. Team ke saath decide karo ki kaunse confusions sabse zyada matter karte hain, aur average ki jagah table ke wahi cells dekho.

**Inbox ko badalte dekho.** Har hafte har category ka aur "other" ka share track karo. Naya plan launch, festival sale ya koi outage mix badal deta hai. "Other" badhna aksar batata hai ki nayi category chahiye.

## Ek example se samjho

Chennai ke ek broadband provider ke support inbox mein roz lagbhag 2,500 emails aate hain. Pehle do staff subah ka time unhe sort karne mein lagate the; urgent outages ghanton intezaar karte the.

Automation har email ko aath categories (outage, slow speed, billing, plan change, new connection, relocation, complaint, other) mein classify karta hai, customer id aur area extract karta hai aur priority set karta hai. Rules un areas mein "outage" ke liye jahan network incident khula hai, aur "consumer forum" ya "legal notice" ke har zikr ke liye high priority force karte hain. Tickets help desk mein sahi team ke paas summary aur reply draft ke saath jaate hain.

English, Tamil aur Tanglish mein 400-email test set par classification accuracy 92% hai; main confusion "slow speed" aur "outage" ke beech hai, jise team ek hi network queue mein route karne ka decide karti hai. Launch ke baad median time to first response 5 ghante se girkar 40 minute ho jaata hai, aur agents 60% drafts halke edits ke saath bhejte hain.

| Measure | Pehle | Launch ke baad |
| --- | --- | --- |
| Do staff ka subah sorting mein time | har ek ka lagbhag 3 ghante | Koi nahi |
| Median time to first response | 5 ghante | 40 minute |
| Classification accuracy, English, Tamil aur Tanglish ka 400-email test | Lagu nahi | 92% |
| Halke edits ke saath bheje gaye drafts | Lagu nahi | 60% |

Main confusion, slow speed vs outage, behtar model se nahi balki ek product decision se solve hua: ab dono ek hi network queue mein jaate hain.

## Aam galtiyaan

- **Aisi categories banana jo team use nahi karti.** Unki categories use karo.
- **Legal ya safety escalations akele AI par chhodna.** Inke liye rules use karo.
- **Replies bahut jaldi auto-send karna.** Drafts se shuru karo aur measure karo.
- **Sirf English mein test karna.** Un languages mein test karo jinmein customers sach mein likhte hain.
- **"Unsure" path na hona.** Har message par category thopne se errors chhup jaate hain.
- **Sirf overall accuracy dekhna.** Dekho kaunsi categories mix ho rahi hain, aur language ke hisaab se bhi.
- **Legal aur privacy routing model par chhodna.** Model chalne se pehle fixed rules use karo.

## AI triage kab zaroori nahi

- **Kam volume**: ek insaan har message padhe toh woh tez aur accurate hota hai.
- **Help desk ke apne rules pehle se kaam karte hain**, jaise customer ke bhare form fields ke hisaab se routing.
- **Categories har hafte badalti hain**, isliye seekhne ke liye kuch stable hai hi nahi.

## Demo se production tak

- **Har hafte 50 messages ka sample label karo** aur accuracy aur confusion table track karo.
- **Category definitions ek file mein rakho**, jo prompt, help desk aur test set teeno share karein.
- **Har decision log karo**, us rule ya model output ke saath jisne use liya.
- **Kisi bhi category mein spike par alert lagao**, khaaskar outages mein.
- **Automatic replies ko mahine mein ek baar review karo**, unhe aur categories tak failane se pehle.
