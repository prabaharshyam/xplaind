## Ye kya hai

**Data curation** ka matlab hai woh examples chunna, likhna, saaf karna aur balance karna jinse model seekhta hai. Fine-tuning ke liye ye zyadatar kaam hai: training run khud ek ghanta le sakta hai, lekin data mein hafte lagte hain.

Format is par nirbhar karta hai ki aap kya sikha rahe ho:

- **Supervised fine-tuning (SFT):** ek instruction ya chat, aur uska ideal response.
- **Preference tuning (DPO ya RLHF):** ek prompt, ek behtar response aur ek kharab.
- **Continued pre-training:** aapke field ka plain text, jaise legal judgements.
- **Ek reward model ya judge:** score ya label ke saath responses.

Har dataset ko teen cheezon par judge kiya jaata hai. Ek achhi tulna khana pakane ki hai:

- **Quality** taaza saamagri hai: har example sahi aur consistent hai.
- **Coverage** sahi mixture hai: examples un cases ko cover karte hain jo users sach mein laate hain.
- **Quantity** mez ke liye kaafi khana hai: task ke liye kaafi examples hain.

Curation data hataane ke baare mein bhi hai. Agar aapke model ki koi buri aadat hai, jaise har answer mein bina maange salah jodna, to wo training examples dhoondho jo ye aadat dikhate hain, unhein hatao, aur woh examples jodo jo aapka chaha hua behaviour dikhate hain.

## Ye kaam kaise karta hai

**Quality.** Ek example high quality tab hai jab woh:

1. Jis task ke liye train kar rahe ho, uske liye **relevant** ho.
2. Task ki zaroorat ke saath **aligned** ho. Agar task ko chhote answers chahiye, to examples chhote hon; agar har score ke saath ek wajah chahiye, to unmein ek ho.
3. Baaki examples ke saath **consistent** ho. Ek hi case ko label karne waale do log zyadatar sahmat hone chahiye.
4. **Sahi format mein** ho, bilkul waise jaise model ko produce karna hai, bina bhatke HTML ya tooti JSON ke.
5. **Unique** ho. Duplicates kuch cases ko zyada weight dete hain aur aapke test set mein leak ho sakte hain.
6. **Use karne ki ijaazat ho**: aisa personal data nahi jo aap use nahi kar sakte, aur aisa content nahi jis par train karne ka adhikaar nahi.

Is baat ka evidence mazboot hai ki quality volume se behtar hai. LIMA study ne ek bade model ko sirf 1,000 dhyaan se chune examples par fine-tune kiya aur aise answers paaye jinhein log aksar ek agrani commercial model jitna achha rate karte the. Yi models ke peechhe ki team ne paya ki 10,000 dhyaan se likhe examples lakhon noisy examples se behtar rahe.

**Labelling guide.** Koi bhi bade scale par label kare, usse pehle likho ki ek perfect output kaisa dikhta hai, mushkil cases ke examples aur unhein kaise sambhaalna hai uske saath. Phir ek pilot chalao: do log wahi 30 items label karte hain, aap compare karte ho, aur jahan woh asahmat the wahan guide theek karte ho. Jab tak agreement high na ho, dohrao. Ye sabse sasta quality step hai.

**Coverage.** Asli users alag-alag hote hain, isliye aapka data bhi hona chahiye. Likho ki inputs kaise alag hote hain, jaise language, length, topic, difficulty, format (typed ya scanned), aur single-turn ya multi-turn, aur dekho ki mix mein har ek ko jagah mili hai. Meta ne Llama 3 ke pichhle versions se zyada gains ka zyadatar shrey naye architecture ko nahi, behtar data quality aur variety ko diya. Zyada variety apne aap behtar nahi hoti, lekin: asambandhit data jodne se model aapke task par kharab ho sakta hai.

**Quantity.** Koi fixed number nahi hai. Ye nirbhar karta hai:

- **Task.** Reviews ko positive aur negative mein baantne ke liye financial filings ke sawaalon ka jawab dene se bahut kam examples chahiye.
- **Base model.** Woh pehle se jitna kareeb hai, utne kam examples chahiye. Kam data ho to ek strong model se shuru karo.
- **Method.** LoRA aur doosre halke methods sainkdon se kuch hazaar examples mein kaam karte hain; full fine-tuning aam taur par das hazaar ya zyada chahta hai.

Vyavaharik tareeka: **50 se 100 excellent examples** se shuru karo. Zyadatar cases mein ye dikhne waala sudhaar dete hain. Agar woh saaf madad karte hain, to aur data aur madad karega. Agar woh kuch nahi karte, to apna prompt format aur settings check karo; bada set shayad hi ek fail hue chhote set ko bachaata hai.

Phir **learning curve** naapo: jo aapke paas hai uske 25%, 50% aur 100% par train karo, aur har ek ko usi test set par score karo. Data jodte jaane par gains aam taur par ghatte hain. Abhi bhi tezi se badhta curve kehta hai aur jama karo; flat curve kehta hai quality par mehnat karo.

Ek chhoti script learning curve ke liye data baantti hai aur labeller agreement check karti hai:

```python
import json, random

def subsets(rows, fractions=(0.25, 0.5, 1.0), seed=7):
    rows = rows[:]
    random.Random(seed).shuffle(rows)       # same order every time, so subsets nest
    return {f: rows[: int(len(rows) * f)] for f in fractions}

def agreement(labels_a, labels_b):
    """Share of items two labellers marked the same way."""
    same = sum(a == b for a, b in zip(labels_a, labels_b))
    return same / len(labels_a)

train = [json.loads(line) for line in open("train.jsonl")]
for f, part in subsets(train).items():
    with open(f"train_{int(f * 100)}.jsonl", "w") as out:
        out.writelines(json.dumps(r) + "\n" for r in part)

print(agreement(["late_fee", "deposit", "lock_in"], ["late_fee", "deposit", "notice"]))  # 0.67
```

**Speed-ups.** Log scratch se likhne se draft ko check karke theek karna tez paate hain, isliye kai teams ek strong model se har answer draft karwati hain aur experts use theek karte hain. Bias par nazar rakho: log ek fluent draft ko bahut aasaani se maan lete hain, isliye theek kiye gaye items ka ek random sample khud check karo.

| Step | Achha kaisa dikhta hai | Aam failure |
| --- | --- | --- |
| Labelling guide | Likhe hue rules aur mushkil cases ke saath | "Samajhdaari se label karo" |
| Pilot | Do log, wahi 30 items, high agreement | Samay bachane ke liye chhod diya |
| Coverage plan | Target counts ke saath input types ki list | Jo files pehle aayi |
| Pehla set | 50 se 100 excellent, varied examples | 5,000 bina check kiye examples |
| Cleaning | Dedupe, ek format, personal data mask | Test items training mein copy ho gaye |
| Learning curve | 25%, 50% aur 100% par scores | Ek training run, koi compare nahi |

## Ek worked example

Hyderabad ka ek legal-tech startup ek model chahta hai jo residential rental agreements, English aur Telugu mein, padhe aur ek fixed summary lautaye: rent, deposit, lock-in period, notice period, saalana increase aur anokhe clauses. Unke paas 3,000 agreements, do hafte ke liye do lawyers, aur AI madad ke liye paise hain.

1. **Guide aur pilot.** Lawyers do-page ka guide likhte hain. 30 agreements ke pilot par woh 70% fields par sahmat hote hain, zyadatar is par asahmat ki "anokha" kya maana jaaye. Woh guide mein anokhe clauses ke baarah examples jodte hain; agla pilot 92% tak pahunchta hai.
2. **Coverage.** Woh users jo upload karte hain uske hisaab se agreements chunte hain: 60% English aur 40% Telugu, paanch mein se ek scanned, aur standard aur custom formats dono.
3. **Drafts aur review.** Ek strong model har summary ko fixed format mein draft karta hai, aur lawyers unhein theek karte hain. Woh 25 ki jagah har ek roz lagbhag 80 kar paate hain.
4. **Cleaning.** Duplicate templates hataye jaate hain, tenant aur owner names aur Aadhaar numbers mask hote hain, aur 120 agreements test set ke roop mein taale mein rakhe jaate hain.
5. **Learning curve.**

| Training examples | 120 test agreements par sahi fields |
| --- | --- |
| 150 | 68% |
| 300 | 76% |
| 600 | 81% |

Numbers samajhne ke liye hain. Curve abhi bhi badh raha hai, isliye aur 600 jama karna shayad worth hai. Telugu scores English se 9 points peeche hain, isliye agla batch Telugu agreements ki taraf jhukega.

## Aam galtiyan

- **Guide likhne se pehle labelling.** Log asahmat hote hain, aur model asahmati seekh leta hai.
- **Jo data aasaani se mile wahi le lena.** Coverage gaps production mein blind spots ban jaate hain.
- **Maan lena ki zyada hamesha behtar hai.** Ek hazaar noisy examples sau clean examples se haar sakte hain.
- **Test items ka training mein leak hona.** Split karne se pehle duplicates hatao, aur test set ko untouched rakho.
- **Expert workflows ko aankh band karke copy karna.** Experts jo steps obvious maante hain unhein chhod dete hain. Dekho woh kaise kaam karte hain aur har step likho.
- **Multi-turn cases ko bhool jaana.** Agar users conversations karte hain, to conversations par train karo, follow-ups aur corrections samet.

## Jab training dataset ki zaroorat nahi

- **Ek achha prompt pehle se bar paar kar leta hai.** Pehle ye naapo.
- **Samasya missing facts ki hai.** Retrieval ko dataset se tez update kiya ja sakta hai.
- **Test karne ka koi tareeka nahi.** Pehle test set banao; wahi batata hai ki training se madad mili ya nahi.

## Demo se production tak

- **Data ko version karo** guide aur cleaning script ke saath, taaki aap koi bhi model dobara bana sako.
- **Har example kahan se aaya, ye record karo**: kisi insaan ne likha, model ne draft kiya, ya asli use se liya.
- **Production se set badhao.** Reviewer corrections aur user feedback aapke sabse achhe naye examples hain.
- **Product badalne par guide dobara check karo**, taaki purane labels purane rules na sikhayein.
- **Deletion path rakho.** Agar koi apna data hataane ko kahe, to aapko use dhoondh kar hataana aur dobara train karna aana chahiye.
