## Ye kya hai

**Agent SDK** ek library hai, aam taur par model provider ki taraf se, jo aapko ready agent loop deti hai: messages bhejo, model jo tools maange unhein chalao, results wapas do, dohrao. Zyadatar SDKs tracing, guardrails, session storage aur ek agent ke doosre ko kaam hand off karne ke tareeke jodte hain. Examples mein OpenAI ka Agents SDK aur Anthropic ka Claude Agent SDK hain; Google aur doosre bhi aise kits dete hain.

**Sub-agent** ek aisa agent hai jo doosre agent dwara shuru kiya jaata hai, task ka ek hissa apne fresh context mein karne ke liye, aur sirf ek summary wapas deta hai. **Multi-agent system** koi bhi aisa design hai jismein kai agents milkar kaam karte hain: ek lead agent workers ko delegate karta hai, agents ek conversation aapas mein hand off karte hain, ya specialists ek-doosre ka kaam review karte hain.

```flow
Lead agent | 5 research areas plan karta hai -> Financials | filings tool
Lead agent -> Legal | court search
Lead agent -> Management | news search
Lead agent -> Market | reports tool
Lead agent -> ESG | news search
Financials -[ek summary, adhiktam 400 words, sources ke saath]-> Lead merges, spots conflicts, asks one follow-up
Legal -> Lead merges, spots conflicts, asks one follow-up
Management -> Lead merges, spots conflicts, asks one follow-up
Market -> Lead merges, spots conflicts, asks one follow-up
ESG -> Lead merges, spots conflicts, asks one follow-up
Lead merges, spots conflicts, asks one follow-up -> Brief
```

Har sub-agent apne fresh context ke saath parallel mein chalta hai.

Is lesson mein hum Hyderabad ki ek consulting firm ke saath chalenge jo mid-sized manufacturers par due-diligence briefs banati hai.

## Ye kaam kaise karta hai

**SDKs aapka kya bachate hain.** Loop khud bees line ka hai; kimat uske aas-paas ki har cheez mein hai: retries, streaming, parallel tool calls, har step ki tracing, input aur output par guardrails, hand-offs, sessions. Kuch SDKs file editing, shell commands ya web search jaise built-in tools bhi permission system ke saath dete hain.

**Chunaav.** Teen aam raaste:

- *Apna loop* jab task narrow ho, aap full control chahte ho aur dependencies kam chahiye.
- *Vendor SDK* jab client us vendor se committed ho aur pilot jaldi chahta ho, khaaskar agar uske built-in tools fit baithte hon.
- *Graph framework* (jaise LangGraph) jab aapko explicit control flow, approval ke liye durable pauses aur model-vendor independence chahiye.

Check karo ki SDK ek vendor ke models se kitna lock-in hai, sessions kaise store karta hai, aur kya uske traces client ke observability tools mein export hote hain.

**Sub-agents.** Unka asli faayda context isolation hai. Market research karne waala lead agent paanch sub-agents shuru kar sakta hai, har ek ek competitor ko apni poori context window ke saath search kare, aur paanch ek-page ki summaries paaye. Lead ko padhe gaye sainkdon pages kabhi dikhte nahi, isliye uska apna context saaf rehta hai. Sub-agents parallel mein bhi chal sakte hain, jisse wall-clock time ghatta hai.

**Keemat.** Har sub-agent ka apna prompt, tools aur history hota hai, isliye token use kai guna badh jaata hai, aksar ek agent se kai guna. Coordination bhi fail ho sakti hai: do workers ek hi kaam dohra dete hain ya koi summary ek zaroori detail chhod deti hai. Multi-agent designs research jaise broad, parallel, read-heavy tasks mein faayda dete hain; ek codebase edit karne ya ek form bharne jaise tightly coupled tasks mein shayad hi madad karte hain, jahan har step pichhle par nirbhar hai.

**Teen raaste compare:**

| Raasta | Kab behtar | Kis par nazar rakho |
| --- | --- | --- |
| Apna loop | Narrow task, full control, kam dependencies | Tracing, retries aur sessions aapko khud banane padte hain |
| Vendor SDK | Ek vendor se committed, tez pilot, built-in tools fit | Lock-in; trace export check karo |
| Graph framework | Explicit control flow, durable approval pauses, vendor independence | Seekhne ke liye aur concepts |

**Delegation brief likhna.** Har sub-agent ke instructions mein area aur uski seemayein hon ("2020 se Indian courts ke legal cases; regulatory filings nahi, unhein doosra agent dekhta hai"), uske tools, headings ke saath output format, ek word limit, aur har claim ke liye source link dene ka rule. Ant mein ek chhoti "open questions" list maango, taaki lead ko pata ho ki kya uncertain hai. Saaf briefs do sabse aam failures rokte hain: overlapping kaam aur woh summaries jo wahi ek detail chhod dein jo mayne rakhti thi.

**Naapna ki baantna kaam aaya ya nahi.** Wahi das requests dono tareeke se chalao. Wall-clock time, kul tokens, cost, aur ek reviewer ka fixed rubric se diya quality score record karo. Jo split tez aur behtar ho lekin cost chaar guna ho, woh phir bhi sahi ho sakta hai, jaise yahan, jab har brief din bhar ke analyst time ki jagah leta hai. Faisla numbers ke saath likhit hona chahiye.

**Plain code mein ek lead aur sub-agents.** Pattern dekhne ke liye framework ki zaroorat nahi. Lead briefs likhta hai, sub-agents apne fresh context ke saath parallel mein chalte hain, aur lead sirf unki chhoti reports dekhta hai:

```python
import asyncio
import anthropic

client = anthropic.AsyncAnthropic()
LEAD, WORKER = "claude-opus-5-5", "claude-sonnet-5-5"     # check the docs for current names

async def sub_agent(brief, max_tokens=1200):
    try:
        r = await asyncio.wait_for(client.messages.create(
            model=WORKER, max_tokens=max_tokens,
            system="You research one narrow area. Report in at most 200 words with a source link per claim, "
                   "then list open questions.",
            messages=[{"role": "user", "content": brief}]), timeout=120)
        return "".join(b.text for b in r.content if b.type == "text")
    except Exception as err:
        return f"FAILED: {type(err).__name__}"

async def research(question, areas):
    briefs = [f"Question: {question}\nYour area: {a}. Stay inside it; other agents cover the rest."
              for a in areas]
    reports = await asyncio.gather(*(sub_agent(b) for b in briefs))
    joined = "\n\n".join(f"## {a}\n{r}" for a, r in zip(areas, reports))
    final = await client.messages.create(
        model=LEAD, max_tokens=1500,
        messages=[{"role": "user", "content": f"Write a brief answering: {question}\n"
                   "Use only these reports. Say plainly if any area FAILED.\n\n" + joined}])
    return "".join(b.text for b in final.content if b.type == "text")

# asyncio.run(research("EV subsidy policies", ["Maharashtra", "Karnataka", "Tamil Nadu"]))
```

Asli system mein har sub-agent ek single call ki jagah apna tool loop (search, fetch, read) chalata, lekin shape wahi hai: briefs bahar, chhoti reports wapas, lead ka context chhota rehta hai.

**Token bill.** Har sub-agent apne instructions, tool definitions aur reading saath leke chalta hai. Anthropic ne report kiya ki uske multi-agent research system ne normal chat se lagbhag 15 guna tokens use kiye. Ye us research brief ke liye sahi ho sakta hai jo analyst ke do din bacha de; support reply ke liye shayad hi sahi hai.

**SDK chunna, concretely.** Vendor SDKs (OpenAI ka Agents SDK, Anthropic ka Claude Agent SDK, Google ka Agent Development Kit aur doosre) mukhya taur par chaar jagah alag hote hain. Commit karne se pehle har ek ko ek-din ke spike se check karo:

| Sawaal | Kyun zaroori hai |
| --- | --- |
| Kya woh doosre vendors ke models use kar sakta hai? | Baad mein bina rewrite ke badalna |
| Sessions aur state kahan rehte hain? | Data residency aur restarts |
| Kya traces OpenTelemetry ya aapke tracing tool mein export hote hain? | Systems bhar mein ek view |
| Built-in tools ke liye permissions aur approvals kaise set hote hain? | Production mein safety |

**Context isolation dono taraf kaatta hai.** Sub-agent sirf apna brief dekhta hai, isliye woh kisi doosre sub-agent ki mili cheez use nahi kar sakta jab tak lead use aage na de. Jab ek area ka kaam doosre par nirbhar ho, to un steps ko kram se chalao, ya lead ko follow-up briefs bhejne ka doosra round do.

**Browser mein try karo.** Sub-agents parallel mein chalte hain, isliye kul time sabse dheemi wale ka hota hai, jod nahi. Delays badlo.

```python
import asyncio, time

async def sub_agent(area, seconds):
    await asyncio.sleep(seconds)              # pretend research
    return f"{area}: 3 findings"

async def lead():
    t0 = time.perf_counter()
    reports = await asyncio.gather(sub_agent("Maharashtra", 0.3), sub_agent("Karnataka", 0.5), sub_agent("Tamil Nadu", 0.2))
    print(reports)
    print(f"took {time.perf_counter() - t0:.1f} s, not {0.3 + 0.5 + 0.2:.1f} s")

await lead()
```

## Ek worked example

Hyderabad ki ek consulting firm mid-sized Indian manufacturers par due-diligence briefs chahti hai: financials, legal cases, management, market aur ESG news.

Ek single agent 40 minute leta tha aur aksar legal research ke beech mein context khatam kar deta tha, pehle ke financial notes kho deta tha. Aap redesign karte ho:

- Ek **lead agent** request padhta hai, paanch research areas ka plan likhta hai aur har area ke liye ek **sub-agent** parallel mein shuru karta hai.
- Har sub-agent ke paas sirf zaroori tools hain: legal ke paas court-records search, financial ke paas filings tool. Har ek adhiktam 400 words ki summary source links ke saath lautata hai.
- Lead summaries merge karta hai, conflicts pakadta hai (do sources revenue par asahmat) aur financial sub-agent se ek follow-up sawaal poochta hai.

Wall-clock time 9 minute tak gir jaata hai aur coverage behtar hoti hai. Token use 3.5 guna badhta hai, jo firm maan leti hai kyunki har brief do din ke analyst kaam ki jagah leta hai. Aap vendor ka SDK use karte ho kyunki firm ka us provider ke saath pehle se enterprise contract hai aur uski tracing har sub-agent ke steps dikhati hai, jo unki quality team ko chahiye.

| Measure | Single agent | Lead aur paanch sub-agents |
| --- | --- | --- |
| Ek brief ka time | Lagbhag 40 minute | Lagbhag 9 minute |
| Context overflow | Aksar, legal research ke dauran | Nahi |
| Token use | Baseline | Lagbhag 3.5 guna |
| Paanch areas ki coverage | Asamaan | Poori |

## Aam galtiyan

- **Default mein multi-agent.** Ek agent se shuru karo. Tabhi baanto jab context overflow ya parallelism naapi gayi samasya ho.
- **Dhundhli delegation.** "Legal side research karo" overlap paida karta hai. Har sub-agent ko precise scope, output format aur length limit do.
- **Token cost ko ignore karna.** Task ki cost pehle aur baad mein naapo; multi-agent ise kai guna kar sakta hai.
- **Bina dhyaan diye lock-in ho jaana.** Agar client model vendors badal sakta hai, to check karo ki aapka kitna code ek SDK par nirbhar hai.
- **Agents ke beech traces nahi.** Jab answer galat ho, to dikhna chahiye ki kaunse sub-agent ne kaunsa claim banaya.
- **Har sub-agent ke liye limits nahi.** Ek atka hua worker poora budget kha jaata hai.
- **Ek hissa fail hone par poora task fail kar dena.** Gap report karo aur baaki deliver karo.

## Jab ek agent behtar ho

- **Tightly coupled kaam**, jaise ek codebase edit karna ya ek form bharna, jahan har step pichhle par nirbhar hai.
- **Chhote tasks** jo ek agent kuch steps mein khatam kar deta hai.
- **Tight budgets**: kai agents token cost badhate hain.
- **Sakht latency zarooratein** jahan parallelise karne ko kam ho.

## Demo se production tak

- **Lead aur har sub-agent ko** ek run id ke neeche trace karo.
- **Per-agent aur poore-task budgets** tokens, time aur paise ke liye set karo.
- **Briefs ko versioned templates ki tarah rakho**, aur prompts ki tarah test karo.
- **Badlaavon se pehle aur baad cost aur quality mein** single-agent baseline se compare karo.
- **Partial failure ke liye plan karo**: jab ek area cover na ho paaye to saaf user messages.
