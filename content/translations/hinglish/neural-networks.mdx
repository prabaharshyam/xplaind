## Ye kya hai

**Neural network** layers ka ek stack hai. Har layer numbers leti hai, unhe weights se multiply karti hai, bias jodti hai, aur result ko ek simple non-linear function se guzaarti hai jise **activation** kehte hain (jaise ReLU, jo negatives ko zero bana deta hai). Ek layer ka output agli layer ka input hota hai. Aakhri layer prediction deti hai: ek number, ya har class ki probabilities.

Kaafi layers aur units ho toh networks bahut complex patterns represent kar sakte hain. **Deep learning** ka matlab hai bahut saari layers wale networks.

```flow
dir: LR
Inputs | 64 features -[weights]-> Hidden layer 1 | 128 units, ReLU
Hidden layer 1 -[weights]-> Hidden layer 2 | 64 units, ReLU
Hidden layer 2 -[weights]-> Output | 5 units, softmax: leaf spot 0.81
Output -[backpropagation: a gradient for every weight]-> Inputs
```

Is lesson mein hum Bengaluru ke ek agritech startup ko follow karenge jo leaf photos ko disease ke hisaab se classify karta hai.

## Ye kaam kaise karta hai

**Forward pass.** Input features layers se guzarkar prediction banate hain.

**Loss.** Ek loss function naapta hai ki prediction kitna galat hai: numbers ke liye mean squared error, classes ke liye cross-entropy.

**Backpropagation.** Chain rule se network nikaalta hai ki har weight ne loss mein kitna yogdaan diya, output se peeche ki taraf layer-by-layer. Isse har weight ka gradient milta hai.

**Gradient descent.** Har weight apne gradient ke ulte chhota step chalta hai. Adam jaise variants har weight ke liye step size adapt karte hain aur aam taur par tez train hote hain. Training examples ke **batches** mein hoti hai; poore data par ek pass ek **epoch** hai.

**Non-linearity kyun matter karti hai.** Activations ke bina stacked layers ek linear model mein collapse ho jaati hain. Activations networks ko features modne aur jodne dete hain.

**Overfitting aur regularisation.** Bahut weights wale networks training data ratt sakte hain. Training aur validation loss ko saath dekho: agar training loss girta rahe aur validation loss badhe, toh network overfit kar raha hai. Upaay: zyada data, data augmentation, dropout (training mein units ko randomly off karna), weight decay, chhote networks aur early stopping.

**Practical settings.** Learning rate (sabse zaroori), batch size, layers aur units ki ginti, epochs. Apne problem type ke liye jaane-maane achhe defaults se shuru karo.

**Kab use karein.** Images, audio, text aur bahut bade datasets mein neural networks chhaaye rehte hain. Aam tabular business data par gradient-boosted trees kam mehnat mein aksar barabar ya behtar hote hain.

**Weights ginna.** Layers ke beech har connection ka ek weight hota hai, aur har unit ka ek bias. Leaf network mein, pehli hidden layer mein 64 × 128 weights aur 128 biases hain, yaani 8,320 numbers. Doosri mein 128 × 64 + 64 = 8,256, aur output layer mein 64 × 5 + 5 = 325. Total 16,901 numbers jo data se seekhe jaate hain. Modern language models mein arabon hote hain, par har layer ka hisaab wahi hai.

**Loss curves padhna:**

| Aap kya dekhte ho | Iska matlab | Kya try karein |
| --- | --- | --- |
| Loss uchhalta ya badhta hai | Learning rate bahut zyada | Use 10 gunaa kam karo |
| Loss bahut dheere girta hai | Learning rate bahut kam, ya inputs scale nahi hue | Badhao; inputs standardise karo |
| Training girta hai, validation badhta hai | Overfitting | Dropout, weight decay, early stopping, zyada data |
| Dono high rehte hain | Underfitting | Bada network, zyada epochs, behtar features |
| Dono saath girte hain aur level ho jaate hain | Healthy | Best validation epoch par ruk jao |

**Training loop shabdon mein.** Har epoch ke liye data shuffle karo aur batches mein baanto. Har batch ke liye forward pass chalao, loss compute karo, backpropagation se gradients nikaalo, aur optimiser ko weights update karne do. Har epoch ke baad weights update kiye bina validation loss compute karo, aur agar ab tak ka best ho toh model save karo. PyTorch se Keras tak har deep learning library isi pattern ko follow karti hai.

**NumPy mein scratch se ek network.** Ek chhota network haath se banane se forward pass, loss, backpropagation aur gradient descent concrete ho jaate hain. Ye XOR seekhta hai, jise koi seedhi line alag nahi kar sakti:

```python
import numpy as np

rng = np.random.default_rng(0)
X = np.array([[0, 0], [0, 1], [1, 0], [1, 1]], dtype=float)
y = np.array([[0], [1], [1], [0]], dtype=float)

W1, b1 = rng.normal(0, 1, (2, 8)), np.zeros((1, 8))
W2, b2 = rng.normal(0, 1, (8, 1)), np.zeros((1, 1))
sigmoid = lambda z: 1 / (1 + np.exp(-z))

def forward(X):
    h = np.tanh(X @ W1 + b1)              # hidden layer with a non-linearity
    return h, sigmoid(h @ W2 + b2)        # output probability

lr = 0.5
for step in range(3000):
    h, p = forward(X)
    loss = -np.mean(y * np.log(p + 1e-9) + (1 - y) * np.log(1 - p + 1e-9))    # cross-entropy
    d_out = (p - y) / len(X)                       # gradient at the output (sigmoid + cross-entropy)
    dW2, db2 = h.T @ d_out, d_out.sum(0, keepdims=True)
    d_h = (d_out @ W2.T) * (1 - h ** 2)            # chain rule through tanh
    dW1, db1 = X.T @ d_h, d_h.sum(0, keepdims=True)
    W2 -= lr * dW2; b2 -= lr * db2; W1 -= lr * dW1; b1 -= lr * db1
    if step % 1000 == 0:
        print(f"step {step}: loss {loss:.3f}")

print("predictions:", forward(X)[1].round(2).ravel())     # close to 0, 1, 1, 0
```

Har framework bilkul yahi steps karta hai, bas automatically aur bahut bade networks par.

**Backward pass ko numerically check karo.** Ek weight ko thoda hilao aur dekho loss kaise hilta hai; wo compute kiye gaye gradient se match karna chahiye:

```python
def loss_of(W1_):
    h = np.tanh(X @ W1_ + b1); p = sigmoid(h @ W2 + b2)
    return -np.mean(y * np.log(p + 1e-9) + (1 - y) * np.log(1 - p + 1e-9))

h, p = forward(X)
d_h = (((p - y) / len(X)) @ W2.T) * (1 - h ** 2)
analytic = (X.T @ d_h)[0, 0]
eps = 1e-5
W_plus, W_minus = W1.copy(), W1.copy(); W_plus[0, 0] += eps; W_minus[0, 0] -= eps
numeric = (loss_of(W_plus) - loss_of(W_minus)) / (2 * eps)
print(f"analytic {analytic:.6f}  numeric {numeric:.6f}")
```

**Initialisation aur scale matter karte hain.** Agar weights bahut bade shuru hon toh activations saturate ho jaate hain aur gradients gayab ho jaate hain; bahut chhote hon toh signals layer-by-layer phir faade hote jaate hain. Isliye frameworks Kaiming ya Xavier initialisation jaise dhyaan se chune defaults use karte hain. Inputs ko bhi standardise karo, taaki koi feature sirf apni units ki wajah se haavi na ho.

## Ek example se samjho

Bengaluru ka ek agritech startup leaf photos ko healthy ya chaar diseases mein se ek ke roop mein classify karta hai. Mechanics seekhne ke liye pehle step mein wo har image se nikaale 64-number features (colour aur texture statistics) par ek chhota fully connected network banate hain:

- 64 features ki input layer → ReLU ke saath 128 units ki hidden layer → ReLU ke saath 64 units ki hidden layer → softmax ke saath 5 units ki output layer (5 classes ki probabilities);
- cross-entropy loss, Adam optimiser, learning rate 0.001, 32 ke batches, 50 epochs tak.

Loss curves mein training loss steadily girta hai, jabki validation loss epoch 14 par sabse neeche jaata hai aur uske baad badhta hai. 0.3 ka dropout lagane aur best validation epoch par early stop karne se 78% validation accuracy milti hai. Wahi 64 features par gradient-boosted trees 80% tak pahunchte hain.

Unka seekha hua sabak: haath se banaye tabular features par network ko koi edge nahi hai. Unka agla step raw images par convolutional network hai, jo apne features khud seekhta hai aur aksar bahut behtar karta hai. CNN lesson mein ye kaise hota hai, wo hai.

| Model | Validation accuracy |
| --- | --- |
| Network, bina regularisation ke, 50 epochs | 74% |
| Dropout 0.3 aur epoch 14 par early stopping ke saath network | 78% |
| Wahi 64 features par gradient-boosted trees | 80% |
| Raw images par convolutional network (unka agla step) | Kaafi zyada hone ki ummeed |

## Aam galtiyaan

- **Learning rate bahut zyada ya bahut kam.** Loss curve dekho; sabse pehle yahi tune karna hota hai.
- **Sirf training loss dekhna.** Overfitting validation loss mein dikhti hai.
- **Bina scale kiye inputs.** Features normalise karo; warna training unstable ho jaati hai.
- **Chhote tabular datasets ke liye default mein neural networks.** Pehle boosted trees try karo.
- **Compare karte waqt random seeds fix na karna.** Runs ke beech results badalte hain; sahi tarah compare karo.
- **Bina scale kiye inputs**, jo training ko dheema ya unstable bana dete hain.
- **Baseline skip karna**: tables par network chunne se pehle gradient boosting se compare karo.
- **Haath se likhe backward pass par bina gradient check ke bharosa karna.**

## Neural network kab use na karein

- **Chhote tabular datasets**: boosted trees ya logistic regression aksar behtar aur simple hote hain.
- **Aise faisle jinhe simple explanations chahiye**, jaise reason codes ke saath credit approvals.
- **GPU budget na ho aur latency tight ho** jab bada network chahiye, jabki chhota model kaam kar deta.

## Demo se production tak

- Training se save kiye statistics ke saath **inputs standardise karo**, aur serving par bhi wahi lagao.
- Har run ke liye **training aur validation loss track karo**, aur best checkpoint rakho.
- Ship karne se pehle wahi split par ek strong baseline se **compare karo**.
- **Seeds fix karo aur settings record karo** taaki runs dohraaye ja sakein.
- **Input drift monitor karo**, kyunki networks anjaan inputs par chupchaap fail hote hain.
