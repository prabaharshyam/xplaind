## Ye kya hai

Ye ek engagement ki poori kahaani hai: is path ke baaki lessons mein chalta wahi case, kram se, un hisson ke saath jo wo lessons chhod dete hain. Client, Chennai ka ek kaalpanik mid-sized non-banking lender hai, jiske Tamil Nadu aur Karnataka mein 180 credit officers hain aur jo har mahine lagbhag 6,000 loan files sambhaalta hai. Saare figures isi case ke hain, method dikhaane ke liye banaaye gaye. Ise apne capstone write-up ke model ki tarah padho.

Week 1 contract ka pehla hafta hai. Discovery usse pehle hui.

| Hafte | Stage | Mukhya decision | Evidence |
| --- | --- | --- | --- |
| 2 hafte pehle | Discovery, KPI, scope | Chatbot nahi, ek credit-file assistant; credit decisions scope se bahar | Har file par lagbhag 40 minute, mahine mein 6,000 files, 7% rework; baseline 41 minute |
| 1 se 4 | Proof of concept | Image clean-up aur ek low-confidence flag | Critical fields par 93% se 96.4%; gate pass |
| 5 se 14 | Pilot | Tambaram mein accountability note; sasti model routing | 24 minute, 5.1% rework, 88% adoption; har file par ₹233 se ₹150 |
| 15 se 26 | Production | Teen monthly waves, net value ke aadhaar par approve | Planning figure par saal mein net lagbhag ₹16 lakh |
| 23 se 26 | Handover | Reverse shadowing, phir escalation-only support | Client engineers ne har core task khud kiya |

## Ye kaam kaise karta hai

### Discovery: maang hi galat thi

Maang thi "customers ke liye ek chatbot". Nau interviews aur aadha din loan team ko kaam karte dekhne se pata chala ki customer queries toh call centre pehle se achhe se sambhaal raha tha. Dard andar tha: officers har file par lagbhag 40 minute bank statements, salary slips aur bureau reports padhne, figures dobaara type karne aur ek credit note likhne mein lagaate the. Mahine ki 6,000 files par ye lagbhag 4,000 officer-hours hai. Retype karne ki galtiyon se 7% files credit committee se wapas aati thi.

Ye reframe isliye chala kyunki iske saath aise numbers the jinhe head of operations pehchaante the. Discovery ke numbers andaaze hote hain, isliye contract se pehle team ne loan-system timestamps se asli baseline naapa: chaar hafte aur 6,200 files par median 41 minute.

### KPI aur scope

- **KPI**: har file par median officer time, pilot shuru hone ke das hafte ke andar 41 se 22 minute.
- **Guardrail**: rework 7% se upar nahi jaana chahiye. **Adoption**: officers apni kam se kam 80% files par draft use karein.
- **Scope mein**: English PDFs aur phone photos se 24 fields, jinmein 10 critical; ek draft credit note; ek review screen.
- **Scope se bahar**: credit decisions, customer features, doosri bhaashaayein.

### Proof of concept: average ne kya chhupaaya

Golden set chhah branches ki 300 masked puraani files ka tha, jinhe do senior officers ne alag-alag label kiya. Jahaan dono ki raay alag thi, wahaan credit head ne faisla kiya. 300 files par das critical fields matlab score karne ko 3,000 values.

Har document ko ek structured-output model call padhti thi, aur har value ko ek schema pass karna hota tha. Ye ek hissa hai:

```python
from decimal import Decimal
from typing import Literal
from pydantic import BaseModel, Field, model_validator

class Source(BaseModel):
    page: int = Field(ge=1)
    text: str = Field(min_length=1)  # the exact words the value was read from

class Amount(BaseModel):
    rupees: Decimal | None  # None if the document does not show it
    source: Source | None
    confidence: Literal["high", "low"]

class SalarySlip(BaseModel):
    employer: str
    month: str = Field(pattern=r"^\d{4}-\d{2}$")  # for example 2026-06
    gross_pay: Amount
    net_pay: Amount  # critical field

    @model_validator(mode="after")
    def net_not_above_gross(self):
        g, n = self.gross_pay.rupees, self.net_pay.rupees
        if g is not None and n is not None and n > g:
            raise ValueError("net pay above gross pay: re-read or flag")
        return self
```

Teen choices copy karne laayak hain. Har value apna page aur wo shabd saath rakhti hai jinse wo padhi gayi, taaki officer use kuch seconds mein check kar sake. Jo value nahi hai wo `None` hai, kabhi andaaza nahi. Aur "net pay gross pay se zyada nahi ho sakta" jaise cross-checks wo galat readings pakadte hain jo format check se chhoot jaati hain. "Low" confidence model ki apne baare mein raay nahi thi, jo bharose laayak nahi hoti. Ye rules se tay hota tha: kharaab image-quality score, fail hua koi cross-check, ya do readings jo aapas mein mel nahi khaatin.

Pehla result 93% tha, 95% ke gate se neeche. Golden set ko document source ke hisaab se baantne par wajah dikhi:

| Slice | Score hui values | Pehla run | Image clean-up ke baad |
| --- | --- | --- | --- |
| Net banking aur HR systems se aayi PDFs (180 files) | 1,800 | 98.0% | 98.0% |
| Phone photos (120 files) | 1,200 | 85.5% | 94.0% |
| Saari files | 3,000 | 93.0% | 96.4% |

Zyaadatar misses wo phone photos thi jinke page par gehri parchhai thi. Ek image clean-up step (seedha karna, roshni baraabar karna) aur low-confidence flag ne inmein se zyaadatar theek kar diye. Expert waali baat par dhyaan do: overall figure pass ho gaya, par akele photos ab bhi pass nahi thi. Isliye gate note ne ye saaf likha:

> **Gate 1, week 4.** Criteria: 300 files par 10 critical fields mein kam se kam 95%; har summary apne source pages cite kare. Result: overall 96.4% (PDFs 98.0%, photos 94.0%); har summary par citations. Head of operations ka faisla: do conditions ke saath pilot par jaao. Low-confidence flag hamesha on rahega, aur photo slice har hafte alag se report hoga.

### Pilot ke liye engineering

Pilot system weeks 3 aur 4 mein bana, proof of concept ke aakhri hisse ke saath-saath. Lender ki risk team ne pehle hi ek Indian region mein apni Azure tenancy approve kar rakhi thi, isliye naya vendor approval shuru karne ki jagah models usi tenancy se use hue, ek fallback waale gateway ke peeche. Service containers mein chali, CI mein evals, Entra ID se sign-on, har officer ki branch ke hisaab se documents filter, har view aur edit ka audit log, aur traces mein personal data masked.

Risk team ke sawaal aapke apne kaam ke liye ek kaam ki list hain. Data kahaan store aur process hota hai? Kya provider ise models train karne mein use kar sakta hai? Kaun kin files ko dekh sakta hai? Kya log hota hai, aur kitne samay tak? Kisi customer ka data har jagah se, logs aur eval set samet, kaise mitaaya jaata hai? FDE ne har sawaal ka jawaab likhit mein diya, provider ki published data-privacy terms ko link ke saath quote karke, yaad se kabhi nahi.

### Pilot: log, scope aur ek der se hua review

Do branches, Anna Nagar aur Tambaram, ke bees officers ne ise das hafte use kiya, ek weekly demo aur ek risk log ke saath.

- **Week 6.** Production security review schedule hi nahi hua tha. Usi din CIO ke office tak escalate kiya, toh week 9 ke liye book ho gaya, yaani us samay se teen hafte pehle jab ye production gate ko block kar deta.
- **Week 7.** Adoption Anna Nagar mein 92% aur Tambaram mein 41% tha. Branch manager ne keh diya tha ki koi bhi figure galat hua toh galti officer ki hogi, "AI ho ya na ho", isliye officers safe rehne ke liye sab kuch dobaara type karte the. Head of operations ne likhkar diya ki officers kiske liye zimmedaar hain: flagged aur critical fields ko review karna, week 8 mein jodi gayi side-by-side review screen use karke. Dobaara training aur ek regional summary template ke saath Tambaram do hafte mein 85% par pahunch gaya.
- **Week 7.** Ek hi hafte mein teen change requests aayin. Collections summaries phase 2 mein gayin. PDF export ki jagah Tamil salary slips swap ki gayin aur week 9 mein ship huin. Approve-or-reject recommendations mana kar di gayin, kyunki credit decisions scope se bahar the.

Result: median 24 minute, 5.1% rework, 88% adoption. 22 minute ka target thode se miss hua. Kyunki measures pehle se tay the, client ne rollout par baat ki, is par nahi ki success ka matlab kya hai.

### Wo galat mod jismein do hafte gaye

Proof of concept mein har page sabse bada available model padh raha tha, kyunki uska score sabse achha tha. POC report ne 300 files par har file ki cost dikhaayi, jo chhoti lagi. Kisi ne ise mahine ki 6,000 files se guna nahi kiya, retries aur har page ke saath bheje jaane waale lambe fixed instructions samet.

Week 10 mein FDE ne business case ke liye full-volume projection banaaya aur ye pakda: mahine mein lagbhag ₹14 lakh, yaani har file par ₹233, jabki har file ki value lagbhag ₹173. Us keemat par rollout mein ghaata hota.

Usne head of operations ko usi hafte ke update mein, ek fix plan aur ek taareekh ke saath, risk ki tarah bataaya, koi memo likhe jaane se pehle. Weeks 11 aur 12 mein team ne typed PDFs ek chhote model ko bhejin aur bada model sirf photos aur low-confidence pages ke liye rakha. Fixed instructions cache kiye aur pehle se extract ho chuke pages dobaara padhna band kiya. Golden set dobaara chalaane par accuracy mein koi kami nahi aayi. Cost mahine mein lagbhag ₹9 lakh par, har file par ₹150 par aa gayi. Iski keemat do engineer-weeks rahi, jo FDE ki side ne uthaayi, aur ek audit-report export pehli rollout wave tak khisak gaya.

### Business case

CEO aur CFO ke liye memo ne value aur cost ko ek hi unit mein compare kiya, har file par 26 minute ke ek saavdhaan planning figure par. Officer time ki value lender ke apne HR figure se lagaayi gayi, lagbhag ₹600 prati ghanta, loaded.

| Line | Har mahine |
| --- | --- |
| Bacha samay: 6,000 files × 15 min = 1,500 hours × ₹600 | ₹9.0 lakh |
| Kam wapas aayi files: 114 × 2 hours × ₹600 | ₹1.4 lakh |
| Running cost, sab milaakar | ₹9.0 lakh |
| Net value | Mahine mein ₹1.4 lakh, saal mein lagbhag ₹16 lakh (pilot ke 24 minute par lagbhag ₹31 lakh) |
| Break-even | Har file par lagbhag 13 minute ki bachat |

Ye ek modest case hai, aur memo ne ye saaf kaha: Indian salaries par bacha samay mushkil se running cost cover karta hai, aur margin quality se aata hai. Pehle draft ne saal ke ₹50 lakh ki value ko mahine ke ₹9 lakh ki cost se compare kiya tha, jo saal mein ₹1.08 crore hai. Meeting se ek din pehle CFO ke analyst ne ise pakda. CFO ne teen monthly waves approve kin, is condition par ki break-even line monthly report mein aayegi.

### Production aur handover

Waves weeks 15 se 18, 19 se 22 aur 23 se 26 mein chalin, aakhri do mein FDE ne support kiya. Weeks 23 se 26 mein lender ke engineers, Karthik aur Divya, ne pehle dekha, phir har core task khud kiya jabki wo dekhti rahi: ek release, ek rollback, CI se evals ke saath ek prompt change, do simulated incidents. Phir sign-off, uska access hataana, gateway keys rotate karna aur teen mahine ka escalation-only support.

Aakhri wave ke teen mahine baad, sabhi 180 officers ke numbers the: median 25 minute, 5.3% rework, 84% adoption aur mahine mein ₹8.7 lakh running cost. Ye saal mein net lagbhag ₹25 lakh hai. Photos zyaada waali do rural branches 29 minute par thi, jo agla kaam hai.

## Aam galtiyaan

Ye portfolio case studies ko dubo deti hain, aur interviewers inhe turant pakad lete hain:

- **Banaaye hue numbers ko results bataana.** Kaalpanik client ke saath aapke discovery figures assumptions hain. Unhe label karo aur source do. Sirf aapke apne golden set ke numbers hi results hain.
- **"Efficiency 40% badhaayi".** Kiski, kis baseline se, kaise naapi, kitne cases par? Number ko uski unit, baseline aur sample ke saath likho.
- **Sirf average.** Ek accuracy figure fail hone waale slice ko chhupa deta hai. Document type ya source ke hisaab se breakdown dikhao.
- **Koi failure nahi, ya ek line mein hal hui failure.** Batao ki wo kaise mili, usmein kitna samay ya paisa gaya, aur aapne client ko kya bataaya.
- **Cost ke bina value.** Agar aapka system ek case par ₹150 mein chalta hai, toh ye uski bachat ke theek bagal mein, usi unit mein batao.
- **Code link nahi, ya aisa code jo koi chala na sake.** Reviewer ko README se aapke evals dobaara chala paane chahiye.
- **Har stage ko baraabar lambaai mein sunaana.** Apne shabd decisions aur evidence par kharch karo, process bataane par nahi.

## Practice karo

Business context ke liye FDE role par a16z ka essay padho.

Is lesson ka check capstone write-up hai. Ek public dataset chuno aur kisi aisi Indian industry mein ek kaalpanik client jise aap jaante ho, jaise hospital chain, logistics company, koi state department ya retailer. Is lesson ke shape mein do ya teen pages likho:

1. Numbers ke saath discovery findings, har ek ko uske source ke saath assumption label karke, jaise koi published guide, koi annual report ya wo kaam karne waale kisi insaan ke saath interview.
2. KPI, baseline, target, guardrail, aur exclusions ke saath scope.
3. Aapka golden set aur use kaise label kiya, kam se kam ek slice mein bante results, aur wo gate jise pass karna tha.
4. Governance choices ke saath architecture: access, logging, masking aur data kahaan jaata hai.
5. Assumed monthly volume par har case ki cost, har case ki value ke muqaabale.
6. Aapke build mein galat hui ek cheez, wo kaise mili aur usmein aapka kya gaya.
7. Koi doosra ise kaise chalaayega: ek README, ek runbook aur ek command jo evals dobaara chalaaye.

**Aapka kaam poora hai jab aap** apni case study do minute mein suna sako, bata sako ki kaun-se numbers aapne naape aur kaun-se assume kiye, aur "aap alag kya karte?" ka imaandaari se jawaab de sako.
