## Ye kya hai

LLM apps ko har request par paisa lagta hai, aur costs users, lambe prompts aur agent loops ke saath badhti hain. **Cost control** ka matlab hai ye jaanna ki paisa kahan jaata hai aur user experience bigaade bina use kam karna. Mukhya levers hain model choice, prompt size, output size, caching, batching aur limits.

| Feature (tagged logs se) | Mahine ke ₹6 lakh mein hissa | Fix |
|---|---|---|
| Nightly ticket summaries | 45% | Batch API par le jao |
| Live chat replies | 35% | Prompt trim aur cache karo, replies cap karo |
| Ticket classification | 20% | Ek chhota model (accuracy 94% se 93%) |

```flow
dir: LR
Har call ko feature se tag karo -> Sabse bada hissa dhoondho -> Ek fix lagao -> Caps jodo | per-agent daily cap, budget ke 80% par alert, provider hard limit
Caps jodo -> Agla mahina: ₹2.7 lakh | customer satisfaction wahi
```

Ye lesson Kolkata ke ek customer-service platform ko follow karta hai, jo apna model bill aadha karna chahta tha.

## Ye kaam kaise karta hai

**Pehle naapo.** Har call ke tokens aur cost ko feature, user aur model ke tag ke saath log karo. Phir aap jawab de sakte ho: kaunsa feature sabse mehenga hai? Kaunse users? Agent ka kaunsa step? Sirf monthly totals ye chhupa dete hain; cost per user aur per feature dikhati hai ki kahan action lena hai aur kya koi feature apna kharcha nikaal sakta hai.

**Model choice: sabse bada lever.** Chhote models sabse bade models se kai guna sasta ho sakte hain. Classification, saaf text se extraction, routing aur chhote replies jaise simple tasks mein, chhota model aksar bade ke barabar nikalta hai. Har task ko apne eval set par do ya teen model sizes ke saath test karo aur jo pass ho usmein se sabse sasta use karo. Sirf mushkil requests bade model ko bhejo.

**Prompt size.** Har request apne input ka paisa deti hai. System prompts trim karo, kam aur chhote retrieved chunks bhejo, lambi conversation history summarise karo, aur unused tool definitions hata do.

**Output size.** Output tokens aam taur par input se zyada mehenge hote hain. Concise formats maango aur `max_tokens` set karo.

**Caching.** Lambe shared prefixes ke liye prompt caching; repeated sawaalon ke liye response caching.

**Batching.** Jo kaam intezaar kar sakta hai (nightly summaries, bulk classification, corpus ko embed karna) woh batch APIs se ja sakta hai, jo providers aam taur par ghanton mein results ke badle bade discount par dete hain.

**Limits.** Per user daily caps, agents par step limits, spending alerts aur provider console mein hard limits.

**Hisaab jaano.** Ek request ki cost = input tokens x input price + output tokens x output price, jahan cached input aam taur par bahut kam bill hota hai. Ek chhota calculator estimates ko imaandaar rakhta hai:

```python
def cost_per_request_inr(input_tokens, output_tokens, in_price_usd_per_m, out_price_usd_per_m,
                         cached_share=0.0, cache_discount=0.9, usd_to_inr=85):
    """Prices are US dollars per million tokens. cached_share: fraction of input served from the prompt cache."""
    fresh = input_tokens * (1 - cached_share)
    cached = input_tokens * cached_share * (1 - cache_discount)
    usd = ((fresh + cached) * in_price_usd_per_m + output_tokens * out_price_usd_per_m) / 1e6
    return usd * usd_to_inr

def monthly_cost_inr(requests_per_month, **kw):
    return requests_per_month * cost_per_request_inr(**kw)

# A chat reply: 3,000 input tokens (60% cached), 250 output, $3 / $15 per million tokens
per = cost_per_request_inr(3000, 250, 3, 15, cached_share=0.6)
print(round(per, 2), round(monthly_cost_inr(300_000, input_tokens=3000, output_tokens=250,
      in_price_usd_per_m=3, out_price_usd_per_m=15, cached_share=0.6)))
```

Prices aur exchange rate badalte rehte hain, isliye unhe provider ke current page se padho, aur likh lo ki aapne kis date ko check kiya. Ye hisaab do cheezein jaldi dikhata hai: output tokens aam taur par input se kai guna mehenge hote hain, aur har call par repeat hone waale lambe prompts tezi se jodte jaate hain.

**Language bhi matter karti hai.** Tokenizer ke hisaab se ek hi reply Hindi, Tamil ya Bengali mein English se kai guna zyada tokens le sakta hai, isliye jis bhi language mein aap serve karte ho, uske liye per request tokens naapo. AI in Indian languages wala lesson ise cover karta hai.

**Mushkil ke hisaab se route karo.** Ek chhota, tez classifier ya rules aasan requests ko sasta model, scope se bahar ke sawaalon ko bina model call ke ek stock reply, aur sirf mushkil requests ko sabse strong model bhej sakte hain. AI app ko layers mein badhane wala lesson routers aur gateways cover karta hai.

**Surprises par nazar rakho.** Retry storms, loop mein phase agents, ek bahut bada document ya ek heavy user raat bhar mein costs ko kai guna kar sakte hain.

**Levers aur typical savings:**

| Lever | Typical effect | Risk |
| --- | --- | --- |
| Simple tasks ke liye chhota model | Us task par bada saving | Bina test kiye quality gir sakti hai |
| Intezaar kar sakne waale kaam ke liye batch API | Bada discount | Ghanton ki deri |
| Prompt caching | Repeated prefixes par input cost kam | Prefix badla toh toot jaati hai |
| Chhote prompts aur outputs | Anupaat mein saving | Context ya detail chhoot jaana |
| Response caching | Repeated calls hata deti hai | Purane ya share hue answers |
| Caps aur alerts | Surprises rokte hain | Users ka limits tak pahunchna |

**Aisa cost dashboard jo action karwaye.** Feature ke hisaab se roz ka spend, sabse heavy users ka cost per user, cost per successful task, aur top feature ke prompt ke har hisse se aane waale tokens ka share dikhao. Budget aur alert threshold ki ek line jodo. Har hafte review karo. Dashboard ko ek nazar mein batana chahiye ki agla kaunsa feature optimise karna hai aur pichhle hafte ka badlaav kaam kiya ya nahi.

**Surakshit tareeke se kaatna.** Ek baar mein ek lever badlo, aur pehle aur baad mein feature ke evals chalao. Cost aur quality ko saath-saath report karo. Jab koi badlaav paisa bachaye par quality thodi giraye, jaise yahan classifier mein, toh likh do ki team ne ye trade maana aur kyun.

**Launch se pehle feature ki pricing.** Pilot se per user per month cost ka andaaza lagao: per user requests, per request tokens aur model ki price. Use us se compare karo jo feature per user kamata ya bachata hai. Agar ek user ki monthly cost uski value se zyada ho sakti hai, toh pehle bade bill ke baad nahi, launch se pehle caps lagao. Real traffic ke pehle do hafton mein estimate dobara dekho, kyunki real users shaayad hi pilot group ki tarah behave karte hain.

## Ek example se samjho

Kolkata ka ek customer-service platform model calls par mahine ke ₹6 lakh kharch karta hai aur ise aadha karna chahta hai.

Feature ke hisaab se logging dikhati hai:

- 45% ek nightly job par, jo 10,000 support tickets ko team leads ke liye summarise karti hai, aur jise subah 10 baje se pehle koi nahi padhta;
- 35% live chat replies par;
- 20% ticket classification par.

Badlaav:

- Nightly summaries provider ke batch API par bade discount ke saath chali jaati hain, aur subah se kaafi pehle khatam ho jaati hain.
- Ticket classification bade model se chhote model par switch hota hai; 400 labelled tickets par accuracy 94% se 93% par aati hai, jise team maan leti hai.
- Live chat bade model par hi rehti hai, par system prompt 40% trim hokar cache hota hai, aur replies 200 tokens par cap hote hain.
- Per-agent daily cap aur budget ke 80% par spending alert jode jaate hain.

Agle mahine ka bill ₹2.7 lakh aata hai, aur customer satisfaction scores mein koi badlaav nahi.

| Badlaav | Cost effect | Quality check |
| --- | --- | --- |
| Nightly summaries batch par | Spend ke 45% par bada discount | Pehle ki tarah subah 10 baje tak ready |
| Classification chhote model par | Bahut sasta | 400 tickets par 94% se 93%, maana gaya |
| Chat prompt 40% trim aur cached; replies cap | Chat cost kam | Satisfaction wahi |

## Aam galtiyaan

- **Feature aur user ke hisaab se naape bina optimise karna.**
- **Sab kuch ke liye sabse bada model use karna.**
- **Jo kaam intezaar kar sakta hai, uske liye real-time prices dena.**
- **Lambe prompts aur unlimited outputs.**
- **Koi alerts ya caps nahi.**
- **Quality check kiye bina cost kaatna.** Har badlaav par evals chalao.

## Jab cost kaatna galat goal hai

- **Feature abhi kaam nahi kar raha.** Pehle apne evals par quality theek karo; optimise baad mein karo.
- **Bachat bahut chhoti hai.** Mahine ke ₹2,000 bachane ke liye hafton ki engineering ya naapne layak quality drop ka koi fayda nahi.
- **Latency ya bharosa zyada zaroori hai.** High-stakes task par ek sasta model jo slow ho ya zyada galtiyaan kare, support aur khoye users ki wajah se zyada mehenga pad sakta hai.

## Demo se production tak

- **Har call ko tag karo** feature, user, model aur prompt version ke saath, aur tokens aur cost store karo.
- **Har feature ke liye budgets set karo** alerts ke saath, aur provider par hard limits.
- **Cost dashboard ko har hafte review karo**, quality metrics ke saath, aur har model ya prompt badlaav ke baad dobara check karo.
- **Regularly re-price karo.** Providers prices kam karte hain aur sasta models release karte hain; chhe mahine pehle ka choice ab zyada paisa de raha ho sakta hai.
- **Sasta raasta tested rakho**, jaise chhota fallback model, taaki costs badhne par jaldi switch kar sako.
