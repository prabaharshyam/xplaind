## Ye kya hai

**Vibe coding** ka matlab hai code khud type karne ki jagah, ek AI agent ko describe karke software banana ki aapko kya chahiye. Andrej Karpathy, ek jaane-maane AI researcher, ne February 2025 mein ek post mein ye shabd banaya. Unhone ek aisa style bataya jismein aap vibes ke aage jhuk jaate ho, AI jo likhe use accept kar lete ho aur code ko mushkil se dekhte ho. Ye phrase itni tezi se phaila ki Collins Dictionary ne "vibe coding" ko 2025 ka Word of the Year bana diya.

Us original, bina review waale style ki bhi apni jagah hai. Weekend prototype ke liye, apne laptop par ek one-off script ke liye, ya phenk dene waale demo ke liye ye theek hai. Lekin jis bhi cheez mein doosre logon ka data, paisa, passwords ya private notes hon, uske liye ye risky hai, kyunki kisi ne check hi nahin kiya ki code karta kya hai. **Ye lesson review waala version sikhata hai**: zyadatar code Claude likhta hai, aur goal aap set karte ho, har step aap check karte ho aur kya ship hoga ye aap tay karte ho. Jab koi interviewer "vibe coding" kahe, to pata karo ki unka matlab kaun-sa hai.

**Claude Code**, Anthropic ka coding agent hai. **Agent** ek aisa AI hai jo sirf text replies nahin deta, balki ek loop mein actions leta hai. Ek chatbot aapko copy karne ke liye code suggest karta hai. Claude Code aapke project mein kaam karta hai: files padhta hai, likhta aur edit karta hai, tests aur builds jaise commands chalata hai, errors padhta hai aur phir se try karta hai. Ise aap terminal mein, VS Code ya kisi JetBrains IDE mein, Claude desktop app mein, ya browser mein claude.ai/code par use kar sakte ho.

Yahan skill chaalaak shabdon ki nahin hai. Ye wahi skill hai jo ek achha team lead ek tez naye colleague ke saath use karta hai: goal samjhaana, kaam ko chhote steps mein todna, jo wapas aaye use review karna, aur saaf-saaf batana ki kya badalna hai.

```flow
title: Har feature ke liye ek loop; har chalte hue step ke baad commit
Aap: ek spec aur ek feature -> Claude plan mode mein plan banata hai
Claude plan mode mein plan banata hai -[aap approve ya trim karte ho]-> Claude files edit karta hai
Claude files edit karta hai -> Claude tests aur app chalata hai
Claude tests aur app chalata hai -> Aap diff padhte ho aur app try karte ho
Aap diff padhte ho aur app try karte ho -[chal raha hai]-> Commit, agla feature
Aap diff padhte ho aur app try karte ho -[galat hai]-> Precise feedback ya rewind
Precise feedback ya rewind -> Claude plan mode mein plan banata hai
```

## Ye kaam kaise karta hai

### 1. Set up karo aur cost jaano

Official overview page par diye command se Claude Code install karo, phir ek naye folder mein terminal kholo aur `claude` chalao. Pehli baar ye login karne ko kahega. Usi folder mein `git init` bhi chalao, taaki har change dikh sake aur undo ho sake. Agar aapne kabhi terminal use nahin kiya, to docs mein ek chhota terminal guide hai.

Aapko ek paid Claude plan ya Claude Console par ek API account chahiye. Claude Code, Free plan mein shaamil nahin hai. Anthropic ke pricing page par 28 November 2026 ke hisaab se prices:

| Plan | US dollars mein price (28 Nov 2026 ko check kiya) | Usage |
|---|---|---|
| Free | $0 | Sirf chat; Claude Code shaamil nahin |
| Pro | $20 mahina, ya yearly billing par $17 mahina ($200 ek saath pehle) | Free se zyada, ek 5-hour aur ek weekly limit ke saath |
| Max | $100 mahina | Pro ka 5x usage |
| Ultra | $200 mahina | Ek hafte mein Pro ka 10x usage, verified accounts ke liye koi 5-hour limit nahin |

India mein plans ka bill rupees mein aata hai, aur rupee amount badal sakta hai, isliye jis din khareedo usi din claude.ai/upgrade check karo. Claude Code aapke plan ki limits chat ke saath share karta hai. Anthropic ka pricing page Pro ko "for everyday work" aur Max ko "for all-day work" batata hai. Agar build ke beech mein 5-hour limit lag jaaye, to reset ka intezaar karo ya paid usage credits on karo. Kitna use ho chuka hai ye dekhne ke liye session mein `/usage` type karo. Zyada pay karne se pehle, neeche jaisa ek chhota app ye test karne ka achha tareeka hai ki Pro aapke liye kaafi hai ya nahin.

### 2. Ek chhota spec likho

Koi bhi code likhne se pehle `SPEC.md` mein aadha page likho: app kya karta hai, use kaun use karega, teen se paanch features jo sach mein zaroori hain, phone par wo kaisa dikhna chahiye, aur kya scope se bahar hai. Out-of-scope list sabse zyada zaroori hai, kyunki ye Claude ko wo cheezein jodne se rokti hai jo aapne kabhi maangi hi nahin. Agar aapko pakka nahin pata ki aapko kya chahiye, to Claude se apna interview lene ko kaho: "Ask me questions one at a time until you could write SPEC.md, then write it."

### 3. CLAUDE.md se use memory do

Har session ek fresh context ke saath shuru hota hai. Claude har session ki shuruaat mein `CLAUDE.md` padhta hai, isliye usmein wo daalo jo wo code se khud nahin samajh sakta: app ko kaise chalana aur test karna hai, aur aapke rules, jaise "mobile first, 360 px wide", "no paid APIs" ya "never put keys in client code". Pehle draft ke liye `/init` chalao, phir lines delete karo. Anthropic ke docs har file ko 200 lines se kam rakhne ka sujhaav dete hain, kyunki har line har task par Claude ke attention ka kuch hissa leti hai. Agar aap Claude ko ek hi baat par do baar correct karte ho, to ek line jod do.

### 4. Wo controls jo aap use karoge

| Aap ye chahte ho | Ye karo |
|---|---|
| Bina edits ke plan lena | `/plan` aur task type karo, ya Shift+Tab tab tak dabao jab tak mode mein plan na dikhe |
| Har command khud approve karna | Auto mode se manual (default) mode mein jaane ke liye Shift+Tab dabao |
| Dekhna ki kya badla | `/diff` type karo, ya `git diff` chalao |
| Claude ke aakhiri edits undo karna | Khaali prompt par Esc do baar dabao, ya `/rewind` type karo |
| Ek naya, alag task shuru karna | `/clear` type karo (`/resume` se wapas aa sakte ho) |
| Lambe session ko chhota karna | Kya rakhna hai ye batate hue `/compact` type karo, jaise `/compact keep the test commands` |
| Claude ko kisi step ke beech mein rokna | Esc dabao |

**Permission modes** tay karte hain ki Claude aapse poochhe bina kya kar sakta hai. Naye terminal aur VS Code sessions **auto mode** mein shuru hote hain: Claude routine steps ke liye bina ruke kaam karta hai, aur ek alag safety model har action check karke risky actions block karta hai, jaise production deploy, force push ya kisi anjaan server par data bhejna. Anthropic saaf kehta hai ki auto mode prompts kam karta hai lekin safety ki guarantee nahin deta. Apne pehle project par manual mode ke baare mein socho, jismein Claude har command se pehle poochhta hai, taaki aap seekho ki wo kya chalata hai. Apne laptop par bypass mode kabhi use mat karo; docs ise sirf isolated containers tak seemit rakhte hain.

**Checkpoints backup nahin hain.** `/rewind` wo edits undo karta hai jo Claude ne apne file tools se kiye, lekin shell command se hua har change nahin. Aapki asli history Git hai: har chalte hue step ke baad commit karo.

### 5. Pehle plan, phir chhote steps mein build

Pehle plan maango, use padho, aur jo zaroori nahin use kaat do. Phir ek baar mein ek feature build karo: layout, phir data, phir calculations, phir saving, phir deployment. Chhota step matlab chhota diff, aur chhota diff hi wo hai jise aap sach mein padh sakte ho. Claude ko apna kaam khud check karne ka tareeka do: tests, ya "run the app and check it at 360 px wide". Built-in `/verify` command, Claude se app build karke chalaane aur result dekhne ko kehta hai.

### 6. Diff mein red flags padho

Achha review karne ke liye har line samajhna zaroori nahin. In cheezon ke liye skim karo aur jab koi dikhe to "kyun?" poochho:

- **Wo files jinka aapne zikr nahin kiya.** Layout fix ko settlement maths nahin chhoona chahiye.
- **Delete kiye gaye ya kamzor kiye gaye tests.** Dabaav mein ek agent kabhi-kabhi fail hote test ko uska expected result badalkar "fix" kar deta hai.
- **Naye packages** jinke liye aapne haan nahin kaha. Har package aisa code hai jis par ab aap depend karte ho.
- **Secret key** kisi bhi aisi file mein jo browser mein chalti hai.
- **Size jo task ke hisaab se bahut bada ho.** One-line bug ke liye 300-line diff ho to uska explanation chahiye.

### 7. Link share karne se pehle security check karo

AI se bane apps ko nuksaan pahunchne ka ek aam tareeka koi chaalaak hacking nahin hai. Ye khuli chhodi gayi key ya database hota hai. Kisi aur ko link milne se pehle:

- **Client code mein koi secret key nahin.** Next.js mein, jis bhi variable ka naam `NEXT_PUBLIC_` se shuru hota hai, wo har visitor ko bheje jaane waale JavaScript mein copy ho jaata hai. Ye prefix sirf un values ke liye use karo jinhein publish karna safe hai.
- **`.env`, `.gitignore` mein hai**, aur aapki git history mein koi key nahin hai.
- **Har Supabase table par row-level security.** Supabase ki browser key public hone ke liye hi bani hai; row-level security tay karti hai ki har user kaun-si rows padh ya badal sakta hai. Secret (service role) key in rules ko skip kar deti hai, isliye use server par hi rehna chahiye.
- **Input ko server par check karo**, sirf form mein nahin.
- Phir Claude se seedhe poochho: "Review this project for exposed secrets, tables without row-level security and unchecked input. List each problem with the file."

## Ek example se samjho

Ye ek udaaharan waali kahaani hai; samay bhi sirf udaaharan ke liye hain, measure nahin kiye gaye. Nisha, Pune mein teen doston ke saath ek flat share karti hai aur WhatsApp chat mein bills baante-baante thak chuki hai. Wo product designer hai, developer nahin.

**Spec.** Wo `SPEC.md` likhti hai: "Ek one-page web app. Ek bill jodo: amount, kisne pay kiya, kaun-kaun share karta hai (pay karne waala hamesha share karta hai). Dikhao ki kise kisko dena hai, sabse kam payments mein. Phone par chale. Browser mein save ho; koi login nahin. Rupees, poore numbers. Scope se bahar: accounts, baraabar na hone waale splits, payment links." Wo `claude` chalati hai, `/init` type karti hai, aur Claude se spec padhkar sawaal poochhne ko kehti hai. Claude poochhta hai ki kya koi bill sirf kuch flatmates mein share ho sakta hai. Haan, wo kehti hai: jab koi bahar gaya ho, to groceries teen logon mein bant-ti hain.

**Plan, aur uska push-back.** Plan mode mein Claude ek Next.js app propose karta hai, jismein ek server, ek form, ek bill list, ek settlement function, local storage aur tests hain. Nisha poochhti hai: "There is no login and no database. Is there a simpler stack?" Claude do options deta hai: plain HTML aur JavaScript, ya tests ke liye Vitest ke saath ek chhota Vite app. Wo Vite chunti hai, kyunki wo plain static files mein build hota hai jinhein Vercel host kar sakta hai, aur Vitest se maths test karna aasaan ho jaata hai. Wo sirf step one approve karti hai: page aur form. Ye uske phone par chalta hai. Wo commit karti hai.

**Wo bug jo tests ne pakda.** Step three, yaani settlement maths, ke liye wo pehle tests maangti hai. Ek test aisa case use karta hai jise wo haath se check kar sakti hai: Nisha, Aarti aur Meera mein share hone waali groceries ke liye Nisha ₹1,000 pay karti hai. ₹1,000 ko teen se bhaag do to ₹333.33 aata hai, isliye kisi ek ko ek rupee zyada dena hoga. Claude ek rule-based test bhi likhta hai: shares ka jod hamesha bill ke baraabar hona chahiye. Wo test fail hota hai. Pehle version ne sabko ₹333 diye, jinka jod ₹999 hota hai, yaani ek rupee gaayab ho jaata hai. Claude cause samjhaata hai aur bacha hua rupee pay karne waale ko dekar ise theek karta hai:

```js
export function splitBill(amount, payer, people) {
  const share = Math.floor(amount / people.length); // 1000 / 3 -> 333
  const shares = Object.fromEntries(people.map((p) => [p, share]));
  shares[payer] += amount - share * people.length; // payer is a sharer: 333 + 1 = 334
  return shares;
}
// splitBill(1000, "Nisha", ["Nisha", "Aarti", "Meera"])
// -> { Nisha: 334, Aarti: 333, Meera: 333 }; Aarti and Meera each owe Nisha 333
```

Khoya hua ek rupee wo aankhon se kabhi nahin pakad paati. Rule-based test ne use pakda, aur agar baad ka koi change yahi galti wapas laaye to ye use bhi pakad lega.

**Ek red flag.** 360 px screen par table theek karte samay Claude ka diff settlement file ko bhi edit karta hai. Nisha poochhti hai kyun. Wo ek aisa rename tha jiska is fix se koi lena-dena nahin tha. Wo Esc do baar dabati hai, rewind karti hai, aur "change only the CSS" jodkar phir se poochhti hai.

**Shipping.** Deploy karne se pehle wo step 7 waala security review maangti hai. Koi keys nahin hain aur koi server nahin hai, isliye ek hi finding nikalti hai ki `.env`, `.gitignore` mein nahin hai; Claude use jod deta hai. Shaam ko wo Vercel par deploy karti hai. Agli subah uske flatmates app use karte hain. Ismein lagbhag paanch ghante lage, jinmein se zyadatar samay ye tay karne mein gaya ki use kya chahiye.

## Aam galtiyaan

**Ek hi message mein poora app maangna.** Aapko ek bada, bina test kiya uljha hua dher milta hai jise aap review nahin kar sakte. Ek baar mein ek feature maango.

**Spec skip karna.** Spec ke bina Claude andaaza lagata hai, aur galat andaaza aapko tab dikhta hai jab wo uske upar build kar chuka hota hai. Kya scope se bahar hai, wo bhi likho.

**Zaroorat se zyada bada plan accept karna.** Agents aksar zaroorat se bada stack propose karte hain. Approve karne se pehle poochho "is there a simpler way?".

**Aise changes accept karna jo aapko samajh nahin aate.** Explanation maango. Code, uske bugs aur uski security ke owner aap ho.

**Auto mode ya checkpoints ko apna safety net maan lena.** Auto mode ek model ka judgement hai, guarantee nahin, aur checkpoints kuch changes miss kar dete hain. Har chalte hue step ke baad commit karo.

**Keys wahan rakhna jahan browser unhein dekh sake.** Client code mein ya kisi `NEXT_PUBLIC_` variable mein rakha secret public hi hai. Secrets ko server-side environment variables mein aur aisi `.env` file mein rakho jise git ignore karta hai.

**Database khula chhod dena.** Bina row-level security waali Supabase table ko koi bhi padh sakta hai, aur aksar badal bhi sakta hai, jiske paas aapke app ki public key hai, aur wo key har visitor ke paas hoti hai.

**Kabhi na khatam hone waale "fix it" loops.** Agar wahi bug do corrections ke baad bhi bacha rahe, to ruk jao. `/clear` chalao, phir exact steps, expected aur actual result, aur aapne kya seekha, inke saath ek naya prompt likho, aur kisi bhi change se pehle cause poochho.

## Practice karo

Ye guided task lagbhag 45 minute mein karo. Aapko ek paid plan ya API account chahiye.

1. Ek naya folder banao, `git init` chalao, phir `claude`.
2. Example waale Nisha ke bill splitter ke liye apne shabdon mein `SPEC.md` likho, ek out-of-scope list ke saath.
3. `/init` chalao, `CLAUDE.md` kholo aur run aur test commands ke saath apna ek rule jodo. Ise chhota rakho.
4. `/plan` type karo aur poore app ke liye plan maango. Kam se kam ek part reject ya simple karo, aur ek sentence mein likho ki kyun.
5. Sirf step one build karo. `/diff` se diff padho, page ko 360 px wide par try karo, aur commit karo.
6. `splitBill` ke liye tests maango jinmein teen logon mein share hua ₹1,000 bhi ho. Check karo ki unmein "shares add up to the bill" jaisa koi rule hai.
7. Upar waali "Prompt theek karo" exercise karo, phir apne answers ko model answers se compare karo.

Aur gehraai ke liye, Anthropic ka free Claude Code in Action course karo aur Watch and learn panel mein videos dekho. Phir project check karo: ek chhota app build, secure, deploy aur share karo jise aap sach mein use karoge.
