## Ye kya hai

ML engineer interview loop kai rounds ka set hota hai, aur har round ek skill test karta hai. Pass aap har round mein solid hokar hote ho, kisi ek mein brilliant hokar nahi. ML mein strong log bhi us round mein fail ho sakte hain jiski unhone taiyaari nahi ki, jaise DSA coding.

| Round | Kya test hota hai | Strong candidate kya dikhata hai |
| --- | --- | --- |
| Online assessment ya DSA coding | Ek timed problem mein data structures aur algorithms | Ek sahi, tested solution aur uski time aur space complexity |
| ML coding | Pandas, NumPy, koi metric ya chhota algorithm scratch se | Clean code jo ties aur empty inputs jaise edge cases sambhaale |
| ML fundamentals | Models, losses, metrics aur validation kaise kaam karte hain | Mechanism, trade-off aur ek default choice |
| ML system design | Ek dhundhle business problem ko deployed system mein badalna | Saaf structure, bolkar bataaye numbers, production thinking |
| LLM ya GenAI design | RAG, evals, prompting banaam fine-tuning, cost aur latency | Pehle measurement, phir sabse simple design jo us par khara utre |
| Project deep-dive | Aapka ek project, gehraai se | Numbers, decisions, galtiyaan aur aap kya badalte |
| Behavioural ya hiring manager | Ownership, conflict, failure | Asli numbers waali chhoti STAR stories |

Mix har jagah alag hota hai. Google aur Meta jaisi badi product companies mein ML roles ke kuch candidate reports, ML design aur behavioural rounds ke saath standard algorithm coding rounds bhi batate hain. Kuch companies iski jagah take-home ya practical ML coding task deti hain. Isliye recruiter se rounds ki list poochho; wo is sawaal ki ummeed karte hain.

```flow
title: 40 minute mein ML system design
1 Goal aur metric -> 2 Framing aur label -> 3 Data -> 4 Features | lagbhag 15 minute
4 Features -> 5 Baseline, phir model -> 6 Evaluation | offline aur A/B, lagbhag 12 minute
6 Evaluation -> 7 Serving | batch ya real time, fallback ke saath -> 8 Monitoring | lagbhag 8 minute
8 Monitoring -> 9 Risks | fairness, abuse, failure; lagbhag 5 minute
```

Neeche ek-ek karke har round, phir "UPI merchant payments ke liye fraud detection design karo" ka poora answer.

## Ye kaam kaise karta hai

### DSA round

Ye round aksar waisa hi hota hai jaisa software engineers ke liye. Role ML hai isliye aasaan problems ki ummeed mat karo, aur jaan lo ki akela yahi round poora loop duba sakta hai. Big-tech ML roles ke kuch candidate reports medium aur kabhi-kabhi hard problems batate hain.

**Kya test hota hai.** Ye patterns seekho, rate hue answers nahi.

- Hash maps, two pointers aur sliding windows ke saath arrays aur strings.
- Sorting, binary search aur intervals (merge, overlap).
- Stacks, queues aur heaps (top k, running median).
- Trees aur graphs: BFS, DFS, shortest paths, topological sort.
- Basic level par dynamic programming (ek aur do dimensions).

**Bolte-bolte solve karo.** Interviewers sirf code nahi, process ko bhi score karte hain.

1. Problem ko apne shabdon mein dohraao aur inputs, sizes aur edge cases ke baare mein poochho.
2. Ek chhota example haath se karke dekho.
3. Ek brute-force solution aur uski cost batao.
4. Use improve karo, aur batao ki naya idea kyun kaam karta hai.
5. Saaf names ke saath code karo.
6. Apne example aur ek edge case par test karo, phir time aur space complexity batao.

ML interviewers kisi DSA problem ko data ki bhaasha mein pooch sakte hain. Jaise: "Time order mein `(merchant_id, timestamp)` pairs ke roop mein UPI payments diye hain; un merchants ko flag karo jinke kisi bhi 60-second window mein `k` se zyada payments hon." Ye hash map waali sliding window hai:

```python
from collections import defaultdict, deque

def flag_bursts(events, k, window_s):
    """events: (merchant_id, unix_seconds) sorted by time.
    Return merchants with more than k payments inside any window_s seconds."""
    recent = defaultdict(deque)          # merchant -> timestamps still in the window
    flagged = set()
    for merchant, t in events:
        q = recent[merchant]
        q.append(t)
        while q[0] <= t - window_s:      # drop payments older than the window
            q.popleft()
        if len(q) > k:
            flagged.add(merchant)
    return flagged

events = [("m1", 0), ("m2", 5), ("m1", 10), ("m1", 20), ("m1", 70), ("m2", 80)]
print(flag_bursts(events, k=2, window_s=60))   # {'m1'}
```

Har timestamp apni queue mein zyada se zyada ek baar aata hai aur ek baar nikalta hai, isliye n events ke liye time O(n) hai. Phir follow-up risk batao: ab tak aaye har merchant ke saath memory badhti hai, kyunki idle merchants ki queues kabhi hataayi nahi jaatin.

**Taiyaari.** Python mein `collections`, `heapq` aur `bisect` ke saath practice karo. Har pattern ke kuch problems solve karo aur jo fail hue unhe ek hafte baad dobaara karo, aise timed mocks mein jahaan aap poore samay bolte raho. Bolkar sochna chupchaap solve karne se alag skill hai, aur test wahi hoti hai.

### ML coding round

Yahaan aap puzzles nahi, data code likhte ho: pandas groupby, join ya rolling window; time ke hisaab se split; scratch se koi metric; NumPy mein k-means ya logistic regression. Ye example do favourites ko jodta hai: label delay ka dhyaan rakhne waala time split, aur k par precision aur recall.

```python
import numpy as np
import pandas as pd

def split_with_gap(df, test_start, test_end, delay_days, labels_pulled_on):
    delay = pd.Timedelta(days=delay_days)
    test_start, test_end = pd.Timestamp(test_start), pd.Timestamp(test_end)
    # Test labels must have matured too, or late fraud looks like "not fraud".
    assert test_end + delay <= pd.Timestamp(labels_pulled_on), "test labels not mature"
    train = df[df["txn_time"] < test_start - delay]   # what you could know on test_start
    test = df[(df["txn_time"] >= test_start) & (df["txn_time"] < test_end)]
    return train, test

def precision_recall_at_k(y_true, scores, k):
    y_true = np.asarray(y_true)
    top_k = np.argsort(-np.asarray(scores))[:k]     # the k highest scores
    caught = y_true[top_k].sum()
    return caught / k, caught / y_true.sum()

df = pd.DataFrame({"txn_time": pd.date_range("2026-01-01", "2026-06-30", freq="D")})
train, test = split_with_gap(df, "2026-05-01", "2026-06-01", 60, "2026-08-01")
print(train["txn_time"].max().date(), len(train), len(test))   # 2026-03-01 60 31

y = [1, 0, 0, 1, 0, 0, 0, 1, 0, 0]
s = [0.9, 0.8, 0.1, 0.7, 0.3, 0.2, 0.6, 0.4, 0.05, 0.15]
p, r = precision_recall_at_k(y, s, 3)
print(round(p, 2), round(r, 2))   # 0.67 0.67
```

Gap kyun? Maan lo fraud labels aane mein 60 din tak lagte hain. 1 May ko deploy hua model sirf unhi transactions par train ho sakta tha jinke final labels the, yaani lagbhag 2 March se pehle waale. March aur April ki rows par baad mein nikaale gaye labels ke saath train karna aisi jaankaari use karna hai jo us samay aapke paas nahi hoti, isliye test score zaroorat se zyada achha dikhta hai. Kisi asli retraining job mein, delay se nayi rows unlabelled hoti hain, negatives nahi. Bina poochhe ye batana ek strong signal hai.

### ML fundamentals: mechanism, trade-off aur default ke saath jawaab do

Strong answer mein mechanism, trade-off aur aapki default choice hoti hai. Do model answers:

**"Random forests aur gradient boosting mein kya fark hai?"** "Dono bahut saare decision trees ko jodte hain. Random forest gehre trees ko alag-alag train karta hai, har ek ko ek bootstrap sample par, har split par features ke ek random subset mein se chunkar, aur phir unka average leta hai. Isse mukhya roop se variance ghatta hai, isliye tuning kam lagti hai aur buri tarah overfit kam hi hota hai. Gradient boosting chhote trees ko ek ke baad ek train karta hai, har tree ab tak ke trees ki errors ko fit karta hai. Isse bias ghatta hai aur tabular data par ye aksar jeetta hai, lekin overfit ho sakta hai, isliye main learning rate aur depth tune karta hoon aur early stopping use karta hoon. Tabular data ke liye mera default boosting hai, jaise LightGBM ya XGBoost, aur quick baseline ke taur par random forest."

**"Data leakage kaise pakdoge?"** "Leakage ka matlab hai model aisi jaankaari dekh raha hai jo prediction ke samay uske paas nahi hogi. Mera pehla signal hai problem ke hisaab se zaroorat se zyada achha score. Phir main teen jagah check karta hoon. Features: kya koi top feature outcome ke baad record hota hai, jaise churn model mein `refund_issued`? Split: kya ek hi customer ya lagbhag duplicate rows train aur test dono mein hain, ya training data test data ke baad ka hai? Preprocessing: kya scaling ya target encoding poore data par fit kiya gaya? Fix ye hai ki har feature prediction time ke hisaab se compute karo, time ya customer ke hisaab se split karo, aur preprocessing sirf training data par fit karo."

Har answer ek mechanism, ek thos example aur ek decision batata hai; koi bhi definition nahi rattaa. In topics ke liye bhi yahi shape taiyaar karo.

| Topic | Achhe answer ka core |
| --- | --- |
| Bias aur variance | Training aur validation error dono high hon toh underfitting; dono ke beech bada gap ho toh overfitting. Ise learning curves se padho |
| Regularisation | L2 saare weights chhote karta hai; L1 kuch ko theek zero tak dhakel deta hai, jisse features select hote hain. Dono thoda bias dekar variance kam karte hain |
| Imbalanced data | Accuracy dhokha deti hai. PR AUC use karo, aur us threshold ya capacity par precision aur recall jis par business action le sake |
| Cross-validation | Independent rows ke liye K-fold; rows time order mein hon ya ek customer share karti hon toh time-based ya grouped folds |
| Logistic regression | Ek linear score jo sigmoid se guzarta hai, log loss se train hota hai. Fast, samjhaane mein aasaan, ek strong baseline |
| Attention | Har token ki query har token ki key se compare hoti hai; scores ka softmax unki values ko weight deta hai |

Sabse zyada poochhe jaane waale topics par I1 ke lessons "Cross-validation and leakage" aur "Choosing a metric" aur gehraai mein jaate hain.

### ML system design

Diagram ke nau steps ko kram se use karo, aur numbers bolkar batao. Teen steps par sabse zyada dhyaan chahiye. *Framing* mein batao ki label kahaan se aata hai aur kitni der se aata hai. *Evaluation* mein aisa split chuno jo asliyat se mel khaaye, aur operating point par ek metric, segment ke hisaab se. *Serving* mein latency budget aur ek fallback batao.

**Offline banaam online.** Behtar offline score behtar business result ki guarantee nahi hai, kyunki live users model par react karte hain. Ek A/B test plan karo jismein ek primary metric ho aur complaint rate ya latency jaise guardrails hon. Pitfalls jaan lo. Result significant dikhte hi rok dena ("peeking") jhoothi jeet badhaata hai. Poore hafte se chhota test weekday aur weekend ke patterns miss kar deta hai. Aur jo model cheezein block karta hai ya chhupaata hai, wo aapko ye dekhne nahi deta ki warna kya hota, isliye ek chhota random holdout rakho.

**"Why not X?" ko handle karna.** Trade-off ke saath jawaab do. Jaise: "Deep model madad kar sakta hai, lekin tabular features aur der se aane waale labels ke saath gradient boosting aksar milti-julti accuracy deta hai, minutes mein train hota hai aur risk team ko samjhaana aasaan hai. Agar error analysis mein aise patterns dikhein jo trees miss karte hain, toh main deep model try karoonga."

### LLM aur GenAI design sawaal

Kuch ML loops mein ab large language model par bane product ke baare mein ek sawaal aata hai, jaise:

- "Ek assistant design karo jo bank ke policy documents se customers ke sawaalon ke jawaab English aur Hindi mein de."
- "Support tickets ko 40 categories mein baantne ke liye prompting use karein, RAG ya fine-tuning?"

Goal aur galat jawaab ki cost clear karo, phir sabse simple approach chuno jo kaam kar sakta hai: jab answers badalte rehne waale documents se aane hon aur citations chahiye, toh RAG; task simple ho toh kuch examples ke saath prompting; volume zyada ho aur cost ya latency maayne rakhe, toh ek chhote model ko fine-tune karna. Bahut saari labelled history waali ticket sorting ke liye ek classic classifier ko baseline ke roop mein bhi rakho. Phir measurement ko pehle rakho: asli sawaalon ka eval set, retrieval ko answers se alag score karna, aur kuch relevant na mile toh kya karna hai uska plan. Aakhir mein har query ki cost aur latency, privacy aur ek human fallback. "Build a RAG app", "Test sets and evals", "Prompting, RAG or fine-tuning" aur "The design interview" lessons har hissa cover karte hain.

### Project deep-dive aur behavioural

**Project deep-dive.** Ek ya do projects gehraai se taiyaar karo: problem, data, baseline, kya try kiya, numbers ke saath results, kya galat hua, aage kya. Team project mein aapne khud kya kiya, ye saaf batao.

**Behavioural.** STAR (situation, task, action, result) use karo, numbers aur ek seekh ke saath. Ek illustrative failure story (aap apni asli story use karo):

- *Situation*: "Pune mein ek insurance sales team ke liye mera lead-scoring model live hua. Do hafton mein top-scored leads par conversion testing ke lagbhag 9% se girkar lagbhag 4% reh gaya."
- *Task*: "Model mera tha aur mujhe cause jaldi dhoondhna tha."
- *Action*: "Maine training aur live feature values compare keen. Ek 'last call outcome' field training data mein call ke baad bhari jaati thi, lekin scoring ke samay khaali hoti thi. Wo leakage tha. Maine features ko scoring time ke hisaab se dobaara banaaya aur ek pre-launch check joda jo training aur live features compare karta hai."
- *Result*: "Offline AUC 0.91 se girkar 0.78 ho gaya, lekin top leads par live conversion wapas lagbhag 7% par aa gaya. Ab training se pehle main check karta hoon ki har feature prediction time par maujood hai."

## Ek example se samjho

Sawaal: "Ek payments company ke liye fraudulent UPI merchant payments detect karne ka system design karo." Neeche ke numbers wo assumptions hain jo aap interview mein bataoge, asli figures nahi.

1. **Goal**: seemit analyst time mein fraud losses ghataana. Latency ke baare mein poochho; maan lo payment flow block karne ke liye lagbhag 100 ms deta hai, saath mein ek review queue.
2. **Framing**: har payment par binary classification. Labels chargebacks aur confirmed investigations se aate hain. Maan lo wo 60 dinon ke andar aa jaate hain.
3. **Data**: payments, merchant profiles, device aur network signals, purana fraud. Fraud rare hai; maan lo payments ka 0.05%.
4. **Features**: pichhle ek ghante mein merchant ke payments, merchant ki aam amounts ke muqaable amount, naya device, din ka samay, merchant category. Sab payment time ke hisaab se ek feature store se compute kiye jaate hain, taaki training aur serving match karein.
5. **Model**: ek rules baseline, phir class weights ke saath gradient-boosted trees. Baad mein merchants, devices aur accounts ko jodne waale graph features.
6. **Evaluation**: upar ke code ki tarah 60-day gap waala time split. Analysts jitna alert volume sambhaal sakte hain us par PR AUC, precision aur recall measure karo, merchant category aur region ke hisaab se. Phir traffic ke ek hisse par A/B test chalao.
7. **Serving**: Real-time scoring, aur model time out ho toh rules par fallback. Do thresholds: bahut high score ke upar auto-block, usse neeche review queue.
8. **Monitoring**: Key features par drift, alert rate mein badlaav, aur monthly retraining. Block hue payments se kabhi pata nahi chalta ki wo fraud the ya nahi, isliye jo payments block hone waale the unka ek chhota random sample block karne ki jagah analysts ko bhejo.
9. **Risks**: asli chhote merchants ko block kar dena (appeal ka raasta do), fraudsters ka tareeka badal lena (baar-baar retrain karo), alag-alag regions mein asamaan error rates.

Ab numbers bolkar batao. Ye dikhate hain ki accuracy galat metric kyun hai.

| Quantity (assumed) | Value |
| --- | --- |
| Har din payments | 20 lakh |
| Fraud rate | 0.05%, yaani har din 1,000 frauds |
| "Never fraud" ki accuracy | 99.95%, aur pakda gaya fraud zero |
| Analysts kitne alerts review kar sakte hain | Har din 2,000 |
| Top 2,000 alerts mein frauds (example) | 600 |
| 2,000 par precision | 600 / 2,000 = 30% |
| 2,000 par recall | 600 / 1,000 = 60% |

Phir poochho: "30% precision par 60% fraud pakadna kya analyst cost ke laayak hai, aur kya har din 500 aur reviews apna kharcha nikaal lenge?" Isse model ek business decision ban jaata hai.

## Aam galtiyaan

- **DSA ki taiyaari chhod dena.** Kuch candidate reports badi product companies ke ML loops mein standard coding round batate hain, aur ye ek strong ML candidate ko bhi duba sakta hai.
- **Seedhe deep learning par koodna.** Baseline se shuru karo aur complexity ke har kadam ki wajah batao.
- **Label ko nazarandaaz karna.** Labels kahaan se aur kitni der se aate hain, yahi data, split, metric aur retraining ko tay karta hai.
- **Time-based problems mein random ya bina gap waale splits.** Dono future ki jaankaari leak karte hain aur scores badha dete hain.
- **Imbalanced data par accuracy batana.** Us capacity par precision aur recall batao jis par business action le sake.
- **Offline jeet ko launch maan lena.** A/B test, guardrails aur holdout plan karo.
- **Serving ya monitoring ka koi plan nahi.** Latency budget, fallback aur retraining kis baat se trigger hogi, ye batao.
- **Upari-upari project stories.** Apne numbers, apna khud ka contribution aur apni galtiyaan pata honi chahiye.
