## Ye kya hai

Typical ML engineer loops mein ye hote hain:

- **ML fundamentals**: bias aur variance, overfitting, regularisation, metrics, cross-validation, kuch khaas models kaise kaam karte hain (trees, logistic regression, neural networks, transformers).
- **Coding**: Python aur pandas mein data manipulation, koi simple algorithm implement karna, kabhi-kabhi standard data-structure problems.
- **ML system design**: "UPI payments ke liye fraud detection system design karo", "Grocery app ke liye recommendations design karo".
- **Case ya project deep-dive**: aapne jo project banaya uska walkthrough, choices aur results par follow-up sawaalon ke saath.
- **Behavioural**: ownership, collaboration, failure se nipatna.

```flow
title: 40 minute mein ML system design
1 Goal and metric -> 2 Framing and label -> 3 Data -> 4 Features | lagbhag 15 min
4 Features -> 5 Baseline, phir ek model -> 6 Evaluation | offline aur A/B, lagbhag 12 min
6 Evaluation -> 7 Serving | batch ya real time, fallback ke saath -> 8 Monitoring | lagbhag 8 min
8 Monitoring -> 9 Risks | fairness, abuse, failure; lagbhag 5 min
```

Numbers zor se bolo: latency budget, label delay, class balance aur alert capacity.

Ye lesson "UPI merchant transactions ke liye fraud detection design karo" ke ek model answer ko follow karta hai, jo Indian payments companies mein common sawaal hai.

## Ye kaam kaise karta hai

**Fundamentals.** Saaf shabdon mein aur ek example ke saath samjha paane chahiye:

- bias-variance trade-off aur learning curves se underfitting aur overfitting ko kaise diagnose karte hain;
- imbalanced data par accuracy kyun fail hoti hai aur uski jagah kya use karein;
- gradient boosting aur random forests mein kya farak hai;
- leakage kya hai aur aap use kaise dhundhoge;
- attention kaise kaam karta hai, high level par.

**ML system design ke liye ek structure.**

1. *Goal clarify karo* aur business metric; constraints (latency, scale, regulation).
2. *ML problem frame karo*: kya predict hota hai, kiske liye, kab; label aur woh kaise milta hai.
3. *Data*: sources, labels, volume, freshness, biases, privacy.
4. *Features*: mukhya groups, prediction time tak ke hisaab se compute kiye.
5. *Model*: pehle ek simple baseline, phir reasons ke saath ek strong model.
6. *Evaluation*: offline metrics, reality se match karte splits, segments; online A/B test aur guardrails.
7. *Serving*: batch ya real-time, latency budget, fallback.
8. *Monitoring aur iteration*: drift, feedback loops, retraining.
9. *Risks*: fairness, abuse, failure modes.

**Project deep-dives.** Ek ya do projects gehrai se taiyaar karo: problem, data, baseline, aapne kya try kiya, numbers ke saath results, kya galat hua, aage kya karoge. "X kyun nahi?" jaise sawaalon ki ummeed rakho.

**Coding.** Pandas groupbys, joins aur window-style calculations, time ke hisaab se train-validation split likhna, aur simple metrics ya k-means ko scratch se implement karne ki practice karo.

**Behavioural.** Numbers ke saath STAR stories, jaise kisi bhi engineering role ke liye.

**Fundamentals jo sabse zyada aate hain:**

| Topic | Kya bata paana chahiye |
| --- | --- |
| Bias aur variance | Learning curves underfitting aur overfitting kaise dikhati hain, aur har ek ka fix kya hai |
| Imbalanced data | Accuracy kyun gumraah karti hai; PR AUC, threshold par precision aur recall |
| Trees | Random forests aur gradient boosting mein kya farak hai |
| Leakage | Ye kya hai, bahut achha score kaise pakdein, splits aur features kaise theek karein |
| Attention | Queries, keys aur values, high level par |

**Zor se bolkar practice karna.** System design ek bolne ki skill hai. 40 minute ka timer lagao, koi unseen sawaal chuno, aur ek simple diagram banate hue nau steps sab bolo. Khud ko record karo, phir gaps suno: kya aapne label define kiya, latency budget bataya, baseline ka naam liya, time se match karta split chuna, aur monitoring kaise karoge ye bataya? Ye hafte mein ek baar kisi dost ke saath karo aur roles badlo, kyunki interviewer banne se pata chalta hai ki saaf answer kaisa sunai deta hai.

**"X kyun nahi?" ko sambhaalna.** Interviewers choices par dabaav daalte hain. Trade-off ke saath jawab do: "Deep model madad kar sakta hai, lekin tabular features aur label delays ke saath gradient boosting lagbhag barabar accuracy deta hai, minutes mein train hota hai aur risk team ko samjhana aasaan hai. Baseline ke baad, agar error analysis un patterns ko dikhaye jo trees miss karte hain, toh main use try karunga."

## Ek example se samjho

Question: "Ek payments company ke liye fraudulent UPI merchant transactions detect karne wala system design karo."

Ek strong outline:

1. *Goal*: limited analyst capacity ke saath fraud losses kam karna; blocking ke liye 100 ms ke andar real-time decision, saath mein ek review queue.
2. *Framing*: har transaction par binary classification; labels chargebacks aur confirmed investigations se, jo 30 se 60 din baad aate hain.
3. *Data*: transactions, merchant profiles, device aur network signals, past fraud; bahut zyada imbalance (fraud ek percent ka chhota hissa hai; jo rate maan rahe ho woh batao).
4. *Features*: velocity (har merchant ke ghante bhar mein transactions), merchant ki history ke mukable amount, naya device, din ka samay, merchant category; sab transaction time tak ke hisaab se feature store se compute kiye.
5. *Model*: rules baseline; class weights ke saath gradient-boosted trees; baad mein merchants aur devices ko jodne wale graph features.
6. *Evaluation*: time-based split; PR AUC; analysts jitna alert volume sambhaal sakte hain us par recall; merchant category aur region ke hisaab se; traffic ke ek hisse par A/B test.
7. *Serving*: rules ke fallback ke saath real-time scoring; do thresholds (bahut high precision par auto-block, uske neeche review queue).
8. *Monitoring*: key features par drift, alert-rate badlaav, blocked transactions se feedback loop (random holdout), maheene mein retraining.
9. *Risks*: asli chhote merchants ko block karna (appeal route), adversaries ka adapt karna (baar-baar retraining), regions ke beech fairness.

| Step | Fraud answer ka mukhya point |
| --- | --- |
| Goal | Block karne ke liye 100 ms ke andar, aur analysts ke hisaab se size ki hui review queue |
| Label | Chargebacks aur investigations, 30 se 60 din late |
| Model | Rules baseline, phir class weights ke saath boosted trees |
| Evaluation | Time split; analysts jitna alert volume sambhaal sakte hain us par recall |
| Monitoring | Drift, alert rates, blocked transactions ke liye random holdout |

## Aam galtiyaan

- **Seedha deep learning par kood jaana.** Baseline se shuru karo aur complexity ko justify karo.
- **Label ko ignore karna.** Labels kahan se aate hain aur kitni der se, ye sab kuch shape karta hai.
- **Time-based problems ke liye random splits.**
- **Serving ya monitoring ka plan na hona.** Interviewers production thinking chahte hain.
- **Chhichhli project stories.** Apne numbers aur apni galtiyaan jaano.
