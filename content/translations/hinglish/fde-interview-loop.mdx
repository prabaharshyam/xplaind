## Ye kya hai

Forward deployed engineers hire karne waali companies (AI labs, AI startups, data platforms aur AI practices banane waali consultancies) ke loops alag hote hain, par zyadatar mein ye kuch rounds hote hain:

- **Coding**: puzzle se zyada practical. Messy file parse karo, API call karo, chhoti service likho, code debug karo.
- **Problem decomposition**: ek vague business problem ("ek hospital discharge delays kam karna chahta hai") aur use sawaalon, plan aur design mein badalne ke 45 minute.
- **System design**: ek AI system shuru se end tak: data, retrieval, models, evals, deployment, security, cost.
- **Client role-play ya case**: interviewer ek sceptical, demanding ya requirements badalne waale client ka role karta hai; aapko sunna hai, clarify karna hai, push back karna hai aur next steps agree karne hain.
- **Behavioural**: pichli situations jo ownership, conflict, ambiguity, failure aur learning dikhayein.
- **Take-home ya work sample**: ek chhota project ya likhit proposal, kabhi kabhi present karna padta hai.

| Round | Kya test karta hai |
|---|---|
| Coding | Practical: parse, API call, chhoti service, structured output, tests |
| Decomposition | Vague problem: questions, KPI aur baseline, options, gate ke saath POC, risks |
| System design | Data, retrieval, models, evals, guardrails, deploy, cost |
| Client role-play | Suno, summarise karo, ask ke peeche ki zaroorat, options, next steps |
| Behavioural | 6-8 STAR stories, har ek mein ek number aur ek lesson |
| Take-home | Ek chhota project ya proposal, kabhi present karna |

## Ye kaam kaise karta hai

**Coding.** Python mein realistic tasks practice karo: bad rows waali CSV aur JSON padhna, validation ke saath FastAPI endpoint likhna, structured output aur retries ke saath LLM API use karna, tests likhna. Kaam karte hue bolte raho; clarity speed jitni hi zaroori hai.

**Problem decomposition.** Discovery mindset zor se use karo:

1. Goal clarify karo aur ye ki kisko iski parwaah hai.
2. Maujooda process, volumes aur data ke baare mein poochho.
3. Measurable KPI aur baseline propose karo.
4. Non-AI sahit options list karo aur wajah ke saath ek chuno.
5. Gate ke saath proof of concept plan karo.
6. Risks batao aur ye ki unhe kaise kam karoge.

Interviewers structured thinking aur achhe sawaal dekhte hain, perfect answer nahi.

**System design.** Poora path cover karo: ingestion, retrieval, prompting, evals, guardrails, permissions, deployment model, observability, cost, failure handling. Trade-offs explicit rakho ("yahan hybrid search kyunki users policy codes type karte hain").

**Client role-play.** Pehle suno aur jo suna uska summary do. Demand ke peeche ki asli zaroorat ke baare mein poochho. Wahin promise mat karo; options aur trade-offs do. Jab "client" push kare toh shaant raho. Agree hue next steps ke saath khatam karo.

**Behavioural.** STAR (situation, task, action, result) mein chhe se aath stories taiyaar karo, numbers aur aapne kya seekha ke saath. Cover karo: ek project jo aapne shuru se end tak drive kiya, ek baar jab aap kisi stakeholder se disagree hue, ek failure, ek baar jab aapne na kaha, ambiguity ke saath kaam karna, kuch jaldi seekhna.

**Aapke apne sawaal.** Poochho ki FDEs travel ya on-site mein kitna time lagate hain, projects kaise chune jaate hain, FDEs product ko feedback kaise dete hain, aur success kaise measure hota hai.

**Role-play ke moves jo achha score dete hain:**

| Situation | Weak response | Strong response |
| --- | --- | --- |
| "Agle hafte saari branches ke liye live karo" | "Sure, try karenge" ya "Mumkin nahi" | Poochho date kis wajah se hai; risks batao; board demo ya partial rollout offer karo |
| "AI ne galti ki; hum cancel kar rahe hain" | Model ka bachaav | Poochho kya hua, us case ko dekho, safeguards aur fix plan samjhao |
| "Ye feature bhi jodo" | Wahin haan kehna | "Main size karke Thursday tak options ke saath aata hoon" |
| Aapke proposal ke baad chuppi | Bolte rehna | Seedha sawaal poochho: "In mein se kaunsa aapke board timeline ke liye fit hai?" |

**Numbers ke saath ek STAR story.** Situation: "Hamari team ki monthly sales report mein teen din ka manual spreadsheet kaam lagta tha." Task: "Mujhe ise tez karne ko kaha gaya." Action: "Maine steps map kiye, data pulls aur checks ko Python mein automate kiya, aur ek validation step joda jo analysts review karte the." Result: "Ab ismein chaar ghante lagte hain, aur release ke baad milne waali galtiyan mahine mein paanch se teen mahine mein zero ho gayi." Lesson: "Mujhe analysts ko pehle involve karna chahiye tha; unke checks ne do edge cases pakde jo mujhse chhoot gaye the."

**Decomposition ki taiyaari.** Indian business problems chuno, 30 minute ka timer lagao aur koi bhi solution se pehle apne sawaal zor se bolo. Record karke wapas suno: kuch propose karne se pehle kitne minute nikle ginno. Agar paanch se kam the, toh aap bahut jaldi kood gaye.

## Ek example se samjho

Ek candidate, Arjun, Indian banks ko bechne waale ek AI startup ke FDE loop ki taiyaari karta hai.

Coding ke liye woh chaar timed tasks practice karta hai: ek statement parser, ek FastAPI endpoint, Pydantic validation aur retries ke saath extraction call, aur ek failing test theek karna.

Decomposition ke liye woh "ek state transport corporation kam complaints chahta hai" jaise prompts par practice karta hai, apne sawaal zor se bolta hai aur khud ko time karta hai.

Client role-play mein interviewer kehta hai: "Your pilot is too slow. Our MD wants it live for all branches next week." Arjun concern ka summary deta hai, poochta hai ki deadline ka trigger kya tha (ek board meeting), samjhata hai ki agle hafte full rollout mein kya risk hai (security review nahi hua, do branches mein 50% se kam adoption) aur options deta hai: agle hafte pilot results ke saath board demo aur teen-wave rollout plan, ya sabse achhi tarah taiyaar paanch branches mein rollout. Interviewer baad mein kehta hai ki ye uske loop ka sabse strong hissa tha: usne na jhuka, na mana kiya.

Uski har behavioural story mein ek number hai: "report preparation 3 din se 4 ghante kiya", "failed jobs 12% se 1% kiye".

| Preparation | Arjun ne kya kiya |
| --- | --- |
| Coding | Chaar timed tasks: statement parser, FastAPI endpoint, validation aur retries ke saath extraction, failing test fix |
| Decomposition | "Ek state transport corporation kam complaints chahta hai" jaise prompts par timed practice |

## Aam galtiyaan

- **Sirf coding ki taiyaari.** Decomposition aur role-play rounds aksar FDE offers decide karte hain.
- **Solution par kood jaana.** Pehle sawaal poochho, zor se.
- **Role-play mein sab par haan kehna.** Interviewers test karte hain ki aap expectations manage kar sakte ho.
- **Bina results ki stories.** Har story ko ek number ya clear outcome aur ek lesson chahiye.
- **Generic system designs.** Har choice ko scenario ke constraints se jodo.

## Practice karo

Tech Interview Handbook ki behavioural guide aur FDE role par a16z ka essay padho.

1. Apne kaam ya projects se chhe STAR stories likho, har ek mein ek result aur ek lesson.
2. Apne chune hue Indian business problems par teen timed decomposition exercises karo (har ek 30 minute), zor se bolte hue aur khud ko record karte hue.
3. Kisi dost se is path ke lessons ke scenarios mein se ek use karke mushkil client ka role karwao; sunna, clarify karna, options dena aur close karna practice karo.

**Aapka kaam poora jab:** aap ek anjaan business problem ko 30 minute mein, zor se, sawaalon, KPI aur POC plan mein decompose kar sako.
