## Ye kya hai

Forward deployed engineer (FDE) client ke organisation ke andar rehkar kaam karta hai aur kisi dhundhli business problem ko aise software mein badalta hai jise log sach mein use karte hain. Interview loop kuch ghanton mein aapko yahi karte hue dekhne ki koshish karta hai.

### Ye role aur loop kahaan se aaye

Palantir kehta hai ki ye role usi ne shuru kiya. Wo in engineers ko Forward Deployed Software Engineers kehta hai, nickname "Deltas", aur inki tulna "Devs" se karta hai jo core platform banate hain: ek Dev kai customers ke liye ek capability banata hai, ek Delta ek customer ko kai capabilities se serve karta hai. Candidate reports aur prep guides batate hain ki zyaadatar Palantir FDE onsites mein ek "decomposition" round hota hai: lagbhag 60 minute, code thoda ya bilkul nahi, aur interviewer aisa customer banta hai jiski problem dhundhli hai. Kuch log ek "learning" round bhi batate hain, jismein aapko koi anjaana concept, API ya system jaldi samajhkar us par build karna hota hai.

Ab AI labs aur AI startups bhi ye title use karte hain. OpenAI aur Anthropic dono aise FDEs hire karte hain jo bade customers ke saath embed hote hain. OpenAI ke loop par prep guides production-level coding aur system design, ek customer-facing exercise aur ek project deep-dive batate hain jismein aapko apni banaayi cheez ka har faisla defend karna hota hai. Bataaye gaye rounds ki ginti alag-alag hai, isliye kisi exact number par bharosa mat karo.

India mein ye title tezi se phail raha hai. July 2026 mein TCS ke chief executive K Krithivasan ne Reuters ko bataya ki company apne staff ka 1% se 1.5% hissa forward deployed roles mein chahti hai, jise Reuters ne lagbhag 5,900 se 8,900 log aanka; unhone ye nahi bataya ki ye log hire honge ya retrain. July 2026 mein khabar aayi ki Coforge apni FDE team ko lagbhag 20 se 100 tak badhaane ka plan kar raha hai. 2026 mein is title waali Bengaluru postings mein Google Cloud aur Nanonets shaamil the. Kuch firms isi kaam ke liye doosre titles use karti hain, isliye job description padho.

### Rounds aur har ek kya test karta hai

| Round | Kya test karta hai | Strong kaisa dikhta hai |
|---|---|---|
| Practical coding | Uljha data, APIs, validation, tests | Pehle data ke baare mein poochhta hai; kharaab rows report karta hai; edge cases test karta hai |
| Problem decomposition | Dhundhle goal ko plan mein badalna | Solutions se pehle sawaal; ek KPI, ek baseline aur gate waala pehla step |
| Learning (Palantir mein bataaya gaya) | Anjaane system ko jaldi samajhna | Achchhe sawaal; system ko tode bina extend karna |
| AI system design | Client constraints ke andar end-to-end design | Client ke data, rules, budget aur team se jude choices |
| Client role-play | Dabaav mein expectations sambhaalna | Na jhukta hai, na mana karta hai; options deta hai; ek owner aur ek taareekh ke saath khatam karta hai |
| Behavioural aur project deep-dive | Ownership, takraav, failure, seekhna | Naape gaye result aur ek lesson waali STAR kahaniyaan |
| Take-home ya work sample | Time box ke andar judgement | Chalta hua core path, imaandaar README, chhota eval, laga samay likha hua |

Har company har round nahi rakhti. FDE roles ke liye sabse khaas decomposition hai:

```flow
dir: LR
title: Decomposition round
Ek dhundhli problem -> Goal aur owner -> Process aur data -> KPI + baseline -> Non-AI samet options -> Proof of concept + gate -> Risks
```

Ye lesson Arjun ko follow karta hai, ek kaalpanik candidate jo Indian banks ko bechne waale ek AI startup ke FDE loop ki taiyaari kar raha hai.

## Ye kaam kaise karta hai

### Loop se pehle: recruiter se chaar sawaal poochho

1. Kaun-kaun se rounds hain, har ek kitna lamba hai, aur kaun-se case ya role-play hain?
2. Kya take-home hai? Bataaya gaya samay kitna hai, aur kya mujhe use present karna hoga?
3. Application mein aur coding round mein AI tools ke kya rules hain?
4. On-site kaam aur travel aam taur par kitna hota hai, aur FDE ki success kaise naapi jaati hai?

Teesra sawaal 2026 mein pehle se zyada maayne rakhta hai, kyunki policies alag-alag hain. Anthropic candidates ke liye guidance publish karta hai jo Claude ke kuch uses ki ijaazat deti hai, jaise apna resume job description se milaakar check karna, par usse apne jawaab likhwaane ki nahi. 2025 mein khabar aayi ki Meta aise coding interviews trial kar raha hai jinmein candidates AI assistant use kar sakte hain. Rules company se company badalte hain, aur kabhi-kabhi ek hi loop ke alag rounds mein bhi. Poochhna normal hai; galat andaaza loop khatam kar sakta hai.

### Practical coding

Kai FDE coding rounds asli client kaam jaise dikhte hain, halaanki kuch loops, jinmein candidates ke hisaab se Palantir ka loop bhi hai, algorithm jaise problems bhi dete hain; poochh lo ki kya aayega. Ek realistic 30 minute ka task: "Ek lender apne branch system se UPI collections CSV mein export karta hai. Kuch rows mein amount nahi hai, dates do formats mein hain, ya transaction ID repeat hai. Saaf records aur reasons ke saath rejected rows ki list return karo, phir ise ek API endpoint ke peeche rakho."

Pehle do minute sawaalon par lagao. Duplicate ko reject karna hai, ya doosri copy jeetegi? Negative amounts refunds hain ya errors? Kaun-se date formats aate hain? Phir core likho:

```python
from datetime import date, datetime
from decimal import Decimal
from pydantic import BaseModel, Field, ValidationError, field_validator

class Txn(BaseModel):
    txn_id: str = Field(min_length=1)
    amount: Decimal = Field(gt=0)
    paid_on: date

    @field_validator("paid_on", mode="before")
    @classmethod
    def parse_date(cls, v: str) -> date:
        for fmt in ("%Y-%m-%d", "%d/%m/%Y"):
            try:
                return datetime.strptime(str(v).strip(), fmt).date()
            except ValueError:
                pass
        raise ValueError(f"unknown date format: {v!r}")

def clean(rows):
    good, rejected, seen = [], [], set()
    for line, row in enumerate(rows, start=2):  # line 1 is the header
        try:
            txn = Txn(**row)
        except ValidationError as e:
            rejected.append((line, e.errors()[0]["msg"]))
            continue
        if txn.txn_id in seen:
            rejected.append((line, "duplicate txn_id"))
            continue
        seen.add(txn.txn_id)
        good.append(txn)
    return good, rejected
```

Chhah rows ka sample do (ek achchhi row, ek bina amount, ek `dd/mm/yyyy` date waali, ek repeat ID, ek negative amount aur ek "Nov 5" date waali), toh ye do rows rakhta hai aur chaar reject karta hai, har ek ke saath uska line number aur reason. `float` ki jagah `Decimal` jaanboojhkar hai: paise mein rounding errors nahi aane chahiye. Upload ki gayi file lene waale FastAPI endpoint mein `clean` ko wrap karne mein bas kuch minute aur lagte hain ("FastAPI se REST APIs" lesson dekho).

| Interviewers kya check karte hain | Weak | Strong |
|---|---|---|
| Sawaal | Turant type karna shuru | Poochhta hai ki kharaab row kise maanein aur duplicates ka kya karein |
| Kharaab data | Kharaab rows chupchaap skip | Har rejected row reason ke saath return |
| Types | Paise ke liye floats, dates ke liye strings | `Decimal`, asli dates, ek validation model |
| Tests | "Mere sample par chal raha hai" | Shuru mein bataaye edge cases ke liye do-teen tests |
| Bolna | Das minute chup | Har trade-off zor se bolna, jaise "abhi duplicates reject kar raha hoon; badalna aasaan hai" |

Agar task mein language model hai, toh bhi yahi aadatein: ek schema define karo, reply validate karo, validation error ke saath ek-do baar retry karo, phir saaf-saaf fail karo aur log karo. Ye pattern "Structured JSON output paao" lesson mein hai.

### Problem decomposition

"Ek hospital discharge delays kam karna chahta hai" jaisa prompt mile, toh score final answer par nahi, aapke sochne ke tareeke par hota hai. Chhah steps zor se bolte hue karo:

1. **Goal aur uska owner clarify karo.** Kaun poochh raha hai, aur uske liye kya badlega?
2. **Abhi ke process, volumes aur data ke baare mein poochho.** Samay asal mein kahaan jaata hai? Roz kitne discharges? Kya record hota hai, aur kahaan?
3. **Ek KPI aur ek baseline par sehmati banao**, jaise "fit for discharge" se bed chhodne tak ke median ghante, aaj naape hue.
4. **Non-AI samet options ki list banao**, jaise ek checklist ya pharmacy timing mein badlaav, phir ek chuno aur batao kyun.
5. **Gate ke saath ek proof of concept plan karo.** Proof of concept asli data par ek chhota, time-boxed test hai. Gate pehle se tay ek number hai jo batata hai ki aage badhna hai ya nahi, jaise "ek ward mein chaar hafte mein median delay 20% kam karna".
6. **Risks batao aur unhe kaise kam karoge**: patient data rules, staff adoption, galat outputs.

Agar interviewer koi numbers na de, toh assumptions zor se bolo ("maan lo teen hospitals mein roz 200 discharges"). Do failure modes aam hain: pehle paanch minute mein hi model propose kar dena, aur bas sawaal poochhte rehna. Aadhe samay tak board par ek KPI aur ek pehla option hona chahiye. Sawaalon par "Client discovery" lesson aur gehraai mein jaata hai.

### Learning round

Palantir ke loop par prep guides aur candidate reports ek interviewer ke baare mein batate hain jo aapka reference banta hai, jab aap koi anjaana concept, API ya system seekhte ho aur phir us par build karte ho. Score aapki learning curve hai: aap sateek sawaal poochhte ho ya nahi, summarise karke apni samajh check karte ho ya nahi, aur jo bataaya gaya us par build karte ho ya nahi. Practice ke liye kisi anjaani open-source repository ko 20 minute padho, phir ek module zor se samjhaao aur ek chhota feature jodo.

### AI system design

Structure "Design interview" lesson mein hai. FDE waala twist ye hai ki client ke constraints hi problem hain, noise nahi: aisa data jo India mein hi rehna chahiye, pehle se maujood vendor stack, fixed budget, ek chhoti team jo aapke jaane ke baad ise maintain karegi. Har choice ko inmein se kisi ek se jodo, aur evals, ek human fallback aur ek handover plan shaamil karo.

### Client role-play

Interviewer ek aisa client banta hai jo shak karta hai, besabr hai ya requirements badalta rehta hai. Paanch moves use karo:

1. Jo suna use ek vaakya mein **summarise karo**.
2. **Demand ke peeche ki zaroorat dhoondho.** Poochho ki taareekh ya request ke peeche kya hai.
3. **Risks ko facts ki tarah batao**, darr ki tarah nahi: kya untested hai, kya galat ho sakta hai, kis par asar padega.
4. **Trade-offs ke saath do options do** aur client ko chunne do.
5. Agle step, ek owner, ek taareekh aur likhit confirmation ke saath **khatam karo**.

| Situation | Weak response | Strong response |
| --- | --- | --- |
| "Agle hafte sabhi branches mein live kar do" | "Theek hai, try karenge" ya "Naamumkin" | Poochho ki taareekh ke peeche kya hai; risks batao; board demo ya partial rollout offer karo |
| "AI ne galti ki; hum cancel kar rahe hain" | Model ko defend karna | Poochho kya hua, case dekho, safeguards aur fix plan samjhaao |
| "Ye feature bhi jod do" | Mauke par haan keh dena | "Main ise size karke Guruvaar tak options ke saath aata hoon" |
| Aapke proposal ke baad chuppi | Bolte rehna | Seedha sawaal poochho: "Inmein se kaun-sa aapki board timeline mein fit hota hai?" |

Nayi request ko size karne par "Scope creep ko manage karna" lesson aur gehraai mein baat karta hai.

### Behavioural sawaal aur project deep-dive

STAR (situation, task, action, result) se chhah se aath kahaniyaan taiyaar karo, har ek mein naapa hua result aur ek lesson. Ye cover karo: ek project jo aapne shuru se aakhir tak chalaaya, kisi stakeholder se asehmati, ek failure, ek baar jab aapne mana kiya, dhundhli sthiti mein kaam karna, aur kuch jaldi seekhna. Jo aapne kiya uske liye "main" bolo aur "hum" sirf team ke kaam ke liye.

Ye rahi ek strong kahani. Situation: "Hamaari team ki monthly sales report mein teen din ka manual spreadsheet kaam lagta tha." Task: "Mujhse ise tez karne ko kaha gaya." Action: "Maine steps map kiye, data pulls aur checks Python mein automate kiye, aur ek validation step joda jise analysts review karte the." Result: "Agle teen monthly cycles mein har baar lagbhag chaar ghante lage, aur release ke baad milne waali errors mahine mein paanch se shunya ho gayin." Lesson: "Mujhe analysts ko pehle shaamil karna chahiye tha; unke checks ne do edge cases pakde jo mujhse chhoot gaye the." Is result mein ek before, ek after, ek samay aur naapne ka tareeka hai.

Project deep-dive mein har choice par "X kyun nahi?" ki ummeed rakho: jo alternative aapne reject kiya aur kyun, wo taiyaar rakho.

### Take-home

- **Time box ka samman karo.** Agar chaar ghante kaha hai, toh lagbhag chaar lagao aur README mein asli number likho. Bees ghante ki polish batati hai ki aap constraints ko nazarandaaz karte ho.
- **Breadth jodne se pehle ek path ko end to end chalao.**
- **README likho**: ek command mein kaise chalaayein, assumptions, trade-offs, aage aap kya karoge.
- **Evidence dikhao**: kuch tests, ya labelled examples par ek chhota eval, failures ki imaandaar list ke saath.
- **Agar present karo**, toh client ki problem aur result se shuru karo, phir design.
- **Jo AI-tool rules diye gaye, unhe follow karo**, aur batao ki allowed tools aapne kaise use kiye.

### Abhi tak client experience nahi hai

Is path par zyaadatar learners ka kabhi paise dene waala client nahi raha. Phir bhi aapke paas kahaniyaan hain. Ek professor, ek internship manager, ek hackathon judge, ek family business ya ek NGO "client" ho sakta hai. Har ek ke liye note karo ki unhone kya maanga, unhe kya chahiye tha, ek asehmati aur ek number. Isse bhi behtar, kisi asli insaan ke liye kuch chhota banao, jaise kisi kirana dukaan ke liye low-stock alert sheet, aur notes rakho. Aapki capstone case study ("Ek case study, shuru se aakhir tak" lesson dekho) ek project deep-dive de sakti hai.

## Ek example se samjho

Arjun ke paas loop se pehle ek hafta hai. Uska plan:

| Day | Focus | Output |
| --- | --- | --- |
| 1 | Recruiter sawaal; rounds ki list | Round list, timings aur AI-tool rules ek note mein |
| 2 | Coding | Do 30 minute ke tasks: upar waala CSV cleaner aur retries ke saath ek structured-output call |
| 3 | Decomposition | "Ek state transport corporation kam complaints chahta hai" par do timed, recorded attempts |
| 4 | Behavioural | Chhah STAR kahaniyaan likhin, har ek do minute se kam mein zor se padhi |
| 5 | Role-play | Do role-plays, ek dost client bana |
| 6 | System design | Bank branch staff ke liye policy assistant ka ek design |
| 7 | Full mock | Har type ka ek mock round; shaam ko aaraam |

Day 3 par uski pehli recording mein wo teen minute mein hi chatbot propose kar deta hai. Doosri attempt mein baarah minute sawaalon par lagaakar wo prati lakh passenger trips complaints waale KPI par pahunchta hai.

Asli loop mein role-play aise chalta hai. Interviewer Mumbai ke ek private bank ki branch operations head Meera banta hai. Pilot assistant bank ki 180 mein se 12 branches mein staff ke policy sawaalon ke jawaab deta hai.

> **Meera:** "Ye pilot bahut dheema chal raha hai. Hamaare MD chahte hain ki agle Shukravaar tak ye sabhi 180 branches mein live ho."
>
> **Arjun:** "Main check kar loon ki sahi samjha: pilot dheema lag raha hai, isliye MD chahte hain ki Shukravaar tak har branch live ho. Agle Shukravaar kya ho raha hai?"
>
> **Meera:** "Board meeting hai. Wo dikhaana chahte hain ki hum AI mein aage hain."

Aapka security review abhi poora nahi hua, aur do pilot branches mein abhi aadhe se kam staff assistant use karta hai. Agar review ke bina 180 branches chaalu kar deen, toh aapki security team ise rok sakti hai, aur board ko rollback ki khabar milegi."
>
> **Meera:** "Matlab aap mana kar rahe ho."
>
> **Arjun:** "Main keh raha hoon ki Shukravaar tak MD ko kuch asli dene ke do tareeke hain. Ek: live pilot numbers ke saath board demo aur taareekhon waala teen-wave rollout plan. Do: jo paanch pilot branches taiyaar hain unmein full use chaalu karna, agar aapki security team Somvaar tak ek fast review poora kar de. Pehla zyada safe hai; doosra zyada dikhata hai par review par nirbhar hai."
>
> **Meera:** "Board ko asli branches pasand aayengi. Option do try karte hain."
>

Paanchon role-play moves yahaan hain, saath mein ek fallback bhi. Jab Meera kehti hai "Matlab aap mana kar rahe ho", toh wo behas nahi karta; vaapas options par jaata hai.

Behavioural round mein wo upar waali sales-report kahani (teen din se lagbhag chaar ghante) use karta hai, aur ek doosri college project se, jahaan uske retries aur alerts jodne ke baad ek mahine mein nightly failed data jobs 12% se 1% par aa gayin.

## Aam galtiyaan

- **Sirf coding ki taiyaari.** Decomposition aur role-play ko bhi utni hi timed practice chahiye.
- **Seedhe solution par koodna.** Pehle goal, process aur data ke baare mein poochho, zor se.
- **Drive kiye bina bas sawaal poochhte rehna.** Decomposition round ke aadhe tak board par ek KPI aur ek pehla option rakho.
- **Har baat par haan, ya seedha na.** Interviewers ye test karte hain ki aap request ko size karke client ko asli choice de sakte ho ya nahi.
- **Bina results ki kahaniyaan.** Har kahani mein ek before aur ek after, kaise naapa, aapka apna hissa aur ek lesson chahiye.
- **Generic system designs.** Har choice ko client ke constraints se jodo.
- **Take-home ko overbuild karna.** Time box se bahut aage jaane se aapka judgement dikhta nahi, chhip jaata hai.
- **AI-tool rules ko nazarandaaz karna.** Har round mein poochho ki kya allowed hai aur use follow karo.

## Practice karo

2. Upar waala CSV-cleaning task tests ke saath 30 minute mein karo, karte hue zor se bolte raho.
3. Apni pasand ki Indian business problems par teen timed decomposition exercises (har ek 30 minute) karo. Khud ko record karo aur note karo ki pehle proposal se pehle kitne minute beete. Paanch se kam matlab aap kood gaye.
4. Kisi dost se is path ke lessons ke kisi scenario par mushkil client banne ko kaho. Paanchon role-play moves practice karo aur ek owner aur ek taareekh ke saath khatam karo.

**Aapka kaam poora hai jab aap** kisi andekhi business problem ko 30 minute mein, zor se bolte hue, sawaalon, ek KPI aur gate waale proof of concept mein tod sako, aur role-play client ki avyavahaarik demand ko bina jhuke ya mana kiye sambhaal sako.
