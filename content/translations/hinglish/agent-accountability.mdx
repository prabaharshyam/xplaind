## Ye kya hai

**Accountability** ka matlab hai ki agent jo bhi action le, uske liye koi chaar sawaalon ka jawab de sake. Zimmedaar kaun tha? Agent ko kya karne ki ijaazat thi? Usne jo kiya woh kyun kiya? Galti kaise theek hogi? Agents zimmedaari nahi uthate; log aur organisations uthate hain.

Governance frameworks ise beech mein rakhte hain. NIST AI Risk Management Framework ka "govern" function saaf roles aur responsibilities maangta hai. EU AI Act high-risk systems ke providers aur deployers ke liye human oversight, record-keeping aur naam wale duties ko zaroori banata hai.

```flow
title: The accountability chain
Business owner | decides the scope, answers for results -> Agent card | purpose, tools, may do alone, needs approval, never, limits, evals
Technical owner | runs it, keeps records -> Agent card
Compliance reviewer | checks against the rules -> Agent card
Agent card -> Action -> Approval | who, when, what they saw
Approval -> Audit record | steps and versions
Complaint -> A person reviews the records -> Refund, fix or a new eval case -> Report
Audit record -> A person reviews the records
```

Ye lesson Delhi ke ek insurance broker ke motor-insurance renewal agent ko follow karta hai.

## Ye kaam kaise karta hai

**Owners ke naam likho.** Har agent ke liye: ek business owner jo tay karta hai ki woh kya kar sakta hai aur uske results ka jawab deta hai, ek technical owner jo use chalata hai, aur ek risk ya compliance reviewer. Unke naam agent ke documentation mein likho.

**Scope document karo.** Ek chhota "agent card": purpose, users, tools aur permissions, jo actions woh akele le sakta hai, jinhe approval chahiye, jo woh kabhi nahi le sakta, jaani-pehchaani limits aur jo evals pass kiye. Agent badle toh ise review karo.

**Identity ke saath approvals.** Jab koi insaan kisi action ko approve kare, toh kisne, kab aur kya dekha record karo. Unki approval accountability chain ka hissa hai, isliye approval screen par itna dikhna chahiye ki asli decision liya ja sake.

**Records.** Audit logs jo har action dobara bana sakein: request, agent ke steps, arguments ke saath tool calls, approvals, aur prompt, model aur tools ke versions. Tay avadhi tak unhe rakho.

**Disclosure.** Logon ko batao jab woh kisi agent se baat kar rahe hain, aur jab content ya decisions AI-assisted the, jaisa kanoon ya achhi practice maange.

**Redress.** Prabhavit logon ke liye problem report karke kisi insaan tak pahunchne ka saaf raasta, records se jaanch karne ki process, aur theek karne aur seekhne ka vaada (us case ko eval suite mein jodo).

**Review.** Niyamit roop se dekho ki agent ne kya kiya: actions ke samples, overrides, complaints, incidents. Jab evidence kahe, toh scope badlo, kisi bhi disha mein.

**Practice mein ek agent card:**

| Section | Example entry |
| --- | --- |
| Purpose | Motor policies renew karo: quotes lo, recommend karo, confirmation ke baad purchase karo |
| Users | App mein renew karne waale retail customers |
| Tools | get_vehicle, get_quotes, purchase_policy |
| Akele kar sakta hai | Quotes lena, reasons ke saath recommend karna |
| Approval chahiye | Purchase, sirf customer ke saaf confirm karne ke baad |
| Kabhi nahi | Confirmation ke bina cover type ya add-ons badalna |
| Jaani-pehchaani limits | Commercial vehicles supported nahi |
| Owners | Head of retail operations; platform lead; compliance officer |
| Last reviewed | 2026-10-01 |

**Chain ko test karna.** Pichhle hafte ka ek asli action chuno. Sirf documents aur records se paanch sawaalon ka jawab dene ki koshish karo: kisne maanga, agent ko kya karne ki ijaazat thi, usne step-by-step kya kiya, kisne approve kiya aur unhone kya dekha, aur kaunse versions chal rahe the. Naapo ki kitna time lagta hai. Agar kisi jawab ke liye kisi ki yaaddaasht chahiye, ya ek ghante se zyada lagta hai, toh regulator ya naraaz customer ke dhoondhne se pehle gap theek karo.

**Vendors ke liye accountability.** Jab agent third-party model ya tool use kare, toh contract mein likha hona chahiye ki kaun kya sambhaalta hai: incident notification, data use, record retention aur model mein badlaav. Aapki organisation phir bhi customers ko jawabdeh hai, isliye agent card vendor ka naam aur contract kya cover karta hai likhta hai.

**Agent card ko code ke paas rakho.** Use repository mein ek file ki tarah store karo aur test karo, taaki woh agent asal mein jo karta hai usse alag na ho jaaye:

```yaml
# agents/renewals.card.yaml
purpose: Renew motor policies after the customer confirms
owners: {business: Head of retail operations, technical: Platform lead, risk: Compliance officer}
tools:
  get_vehicle: {kind: read}
  get_quotes: {kind: read}
  purchase_policy: {kind: write, approval: customer_confirmation}
never: [change cover type without confirmation, add add-ons without confirmation]
last_reviewed: 2026-10-01
```

```python
import yaml
from datetime import date, timedelta
from agents.renewals import TOOLS          # the tool definitions the agent really uses

def test_card_matches_code():
    card = yaml.safe_load(open("agents/renewals.card.yaml"))
    assert set(card["tools"]) == {t["name"] for t in TOOLS}, "card and code list different tools"
    for name, spec in card["tools"].items():
        if spec["kind"] == "write":
            assert "approval" in spec, f"{name} writes but has no approval rule"

def test_card_reviewed_recently():
    card = yaml.safe_load(open("agents/renewals.card.yaml"))
    assert date.today() - card["last_reviewed"] < timedelta(days=180), "card review overdue"
```

Card update kiye bina tool jodne se ab build fail hota hai, jo owners ke saath baatcheet ko majboor karta hai.

**Ek audit record jo paanchon sawaalon ka jawab de.** Ek append-only table, jise platform likhta hai aur agent ka service account kabhi edit nahi kar sakta:

```sql
CREATE TABLE agent_audit (
  id bigserial PRIMARY KEY,
  run_id text NOT NULL,
  at timestamptz NOT NULL DEFAULT now(),
  actor text NOT NULL,           -- the customer, the agent, or the approver's staff id
  kind text NOT NULL,            -- request, tool_call, approval, result
  detail jsonb NOT NULL,         -- tool name and arguments, what the approver saw, the outcome
  prompt_version text, model text, tool_versions jsonb
);
-- Reconstruct one run in order:
SELECT at AT TIME ZONE 'Asia/Kolkata', actor, kind, detail FROM agent_audit WHERE run_id = $1 ORDER BY at;
```

Application role ko sirf `INSERT` aur `SELECT` do. Records ko utne samay tak rakho jitna aapka sector maangta hai, aur jaldi delete karne ki jagah unhe sasti storage mein export karo.

**India mein sector ki ummeedein.** Regulators tay kar rahe hain ki woh apne sectors mein AI se kya ummeed rakhte hain. Jaise RBI ne financial services mein responsible AI ke liye ek framework publish kiya hai jo governance, naam wali accountability aur audit trails par zor deta hai. Apne client ke sector ki maujooda guidance design se pehle padho, launch ke baad nahi.

**Zimmedaari vendor ke paas nahi jaati.** Agar kisi model provider ka update behaviour badal de, toh bhi aapki organisation customer ko jawabdeh hai. Isi wajah se card pinned model version aur pass kiye gaye evals ka naam leta hai, aur isi wajah se model badlaav bhi code badlaav jaise hi review se guzarte hain.

**Browser mein try karo.** Ek agent card ko un tools se check karo jo agent ke paas asal mein hain. Ek tool jodo aur chalao.

```python
card = {"tools": {"get_vehicle": "read", "get_quotes": "read", "purchase_policy": "write"},
        "approvals": {"purchase_policy": "customer confirmation"}}
tools_in_code = ["get_vehicle", "get_quotes", "purchase_policy", "cancel_policy"]

missing = set(tools_in_code) - set(card["tools"])
if missing:
    print("tools missing from the card:", sorted(missing))
for name, kind in card["tools"].items():
    if kind == "write" and name not in card["approvals"]:
        print(f"{name} writes but has no approval rule")
print("check done")
```

## Ek example se samjho

Delhi ka ek insurance broker ek agent deploy karta hai jo motor policies renew karta hai. Woh vehicle ki details check karta hai, teen insurers se quotes laata hai aur ek recommend karta hai. Customer ke confirm karne ke baad, woh insurer ke API se purchase poora karta hai.

Accountability set-up:

- **Owners**: head of retail operations (business), platform lead (technical), compliance officer (review).
- **Agent card**: quotes la sakta hai aur recommend kar sakta hai; app mein customer ke saaf confirm karne ke baad hi purchase kar sakta hai; confirmation ke bina cover type ya add-ons kabhi nahi badal sakta; use batana hoga ki woh ek automated assistant hai.
- **Records**: har quote, recommendation reason, confirmation message aur purchase call, versions ke saath.
- **Redress**: har screen par "talk to a person" option; complaints har hafte review hoti hain.

Teen mahine baad, ek customer shikayat karta hai ki renewal mein zero-depreciation cover hat gaya. Records dikhate hain ki agent ne bina us add-on ke ek sasta quote recommend kiya aur confirmation screen ne badlaav ko highlight nahi kiya. Accountability saaf hai: galti design ki thi, customer ki nahi. Broker farak ka refund karta hai, confirmation screen ko badalta hai taaki koi bhi cover badlaav highlight ho, ek rule jodta hai ki cover badlaav ke liye explicit consent chahiye, aur aise das cases evals mein jodta hai. Compliance officer ki board ko report mein incident aur fix shaamil hain.

| Complaint ke baad ka step | Broker ne kya kiya |
| --- | --- |
| Investigation | Records ne dikhaya ki bina add-on ke sasta quote recommend hua |
| Finding | Confirmation screen ne cover badlaav ko highlight nahi kiya |
| Redress | Customer ko farak ka refund kiya |
| Fix | Cover badlaav highlight; explicit consent zaroori |
| Learning | Aise das cases evals mein jode; incident board ko report kiya |

## Aam galtiyaan

- **Koi naam wala owner nahi.** "AI team" nateeje ka jawab nahi de sakti.
- **Scope sirf logon ke dimaag mein.** Agent card likho aur use current rakho.
- **Context ke bina approvals.** Aankh band karke approve karne waale oversight nahi de rahe.
- **Aise records jinhe query nahi kar sakte.** Jaanch ke liye ghanton mein jawab chahiye.
- **Prabhavit logon ke liye koi raasta nahi.** Report karne ke raaste ke bina nuksaan public complaint ban jaata hai.
- **Slide deck mein rehne waala agent card.** Use repository mein rakho aur test karo.
- **Aise audit tables jinhe agent ki service edit ya delete kar sake.**
- **Audit records par versions nahi.** Aap nahi bata sakte ki kaunse prompt ya model ne decision liya.

## Jab halka process kaafi ho

- **Internal read-only assistants**, jaise staff ke liye policy search: ek naam wala owner, ek chhota card aur aam logs kaafi hain.
- **Prototypes** jo asli customers ya systems ko kabhi nahi chhute.
- **Personal productivity tools** jo ek insaan apne data par use kare.

Poore cards, approval identity, append-only audits aur redress paths tab zaroori ho jaate hain jab agent customers ke liye act kare, paisa ya personal data sambhaale, ya regulated sector mein kaam kare.

## Demo se production tak

- **Card ko CI mein test karo** agent ke asli tools ke against, aur overdue reviews par fail karo.
- **Audits ko append-only storage mein likho**, run ids aur versions ke saath.
- **Har mahine ek asli action par paanch-sawaal ka drill chalao** aur time naapo.
- **Redress cases ko band hone tak track karo**, aur har ek ko eval suite mein jodo.
- **Scope ko har quarter review karo** business owner ke saath, actions, overrides aur complaints ke numbers ke saath.

## Practice karo

NIST AI Risk Management Framework ka overview aur EU AI Act summary ka high-risk obligations waala section padho.

1. Apne banaye kisi agent ke liye ek agent card likho: purpose, users, tools, allowed aur forbidden actions, approvals, jaani-pehchaani limits, owners.
2. Check karo ki aapke audit records in sawaalon ka jawab de sakte hain ya nahi: kisne maanga, agent ne kya kiya, kisne approve kiya, aur kaunse versions use mein the.
3. Redress path design karo: prabhavit insaan problem kaise report karega aur phir kya hoga, ek time limit ke saath.
4. Card-matches-code test apne agent ke repository mein jodo, phir card update kiye bina ek naya tool jodo aur confirm karo ki build fail hota hai.

**Aapka kaam poora jab:** aap apne agent ka koi ek action lekar, sirf documents aur records se dikha sako ki uske liye kaun accountable tha aur woh kyun hua.
