## Ye kya hai

**KPI** (key performance indicator) woh number hai jo batata hai ki project kaam kiya ya nahi. AI deployment ke liye aam taur par aapko chahiye:

- Business result se juda **ek primary KPI**: har loan file ke minute, first-response time, har officer ke roz process hue claims, resolve hue ticket ki cost.
- **Ek baseline**: aapke system se pehle, usi conditions mein measure kiya hua KPI.
- **Ek target aur ek date**: "pilot start ke aath hafte ke andar har file par 40 se 20 minute".
- **Guardrail measures**: woh cheezein jo bigadni nahi chahiye, jaise error rate, customer complaints ya compliance exceptions.
- **Adoption**: log system ko sach mein use kar rahe hain ya nahi, kyunki jis tool ko koi use nahi karta woh KPI nahi hila sakta.

Accuracy ya faithfulness jaise model metrics inputs hain, KPI nahi. 95%-accurate extractor jo kisi ka time nahi bachata, woh failure hai.

| Scope of work mein sign hua KPI plan | |
|---|---|
| **Primary** | Har loan file par median officer minute |
| **Baseline** | 41 min (loan-system timestamps, 4 hafte, 6,200 files) |
| **Target** | Pilot start ke 10 hafte ke andar 22 min |
| **Guardrails** | Rework zyada se zyada 7%; audit policy exceptions mein badhoutri nahi |
| **Adoption** | Officers apni kam se kam 80% files par draft use karein |

## Ye kaam kaise karta hai

**Problem statement se shuru karo.** Agar discovery mein mila ki officers har file par 40 minute lagate hain, toh KPI har file ka time hai, "AI accuracy" nahi.

**Ise us data se measurable banao jo aapko mil sakta hai.** Surveys ki jagah un numbers ko prefer karo jo systems pehle se record karte hain (loan system mein timestamps, ticket close times). Agar kuch record nahi karta, toh pehle measurement set up karo: cases ke ek sample ke start aur end times ka simple log.

**Baseline sahi tareeke se measure karo.** Wahi team, wahi tarah ke cases, kaafi volume (kuch sau cases ya do se chaar hafte). Seasonal effects dekho: month-end ki bheed typical nahi hoti.

**Guardrails soch samajhkar chuno.** Zyada galtiyon ke saath tez processing jeet nahi hai. Client ke risk owners jinki parwaah karte hain, aise ek ya do quality measures chuno.

**Likhit mein agree karo.** KPI, baseline method, target, guardrails aur measurement period scope of work mein daalo, business owner ke sign ke saath.

**Nyay se compare karo.** Pilot ke dauran, system waale users ko usi period mein bina system waale similar users se compare karo, ya wahi users before aur after, saaf dikhne waale farak adjust karke.

**Regularly report karo.** Hafte ka ek-line update ("is hafte median 26 minute har file par, 41 se kam; rework 7% baseline ke against 5.8%; 82% officers active") sabko align rakhta hai.

**Inputs aur outcomes:**

| Input (model ya system) | Outcome (business) |
| --- | --- |
| Extraction accuracy | Har loan file ke minute |
| Retrieval recall | Policy question ka jawab dene ka time |
| Faithfulness score | Rework ya complaint rate |
| Latency | Har agent ke har ghante handle hue calls |
| Uptime | Roz process hue claims |

**Nyay se comparisons.** Ho sake toh pilot users ko usi hafton mein un similar users se compare karo jo abhi system use nahi kar rahe, taaki month-end ki bheed jaise seasonal badlaav dono groups ko affect karein. Agar sabko tool ek saath mil jaye, toh wahi users before aur after compare karo, aur note karo ki aur kya badla, jaise koi nayi policy ya staffing. Method ko pilot shuru hone se pehle measurement plan mein likh do, taaki baad mein koi fayde ka comparison na chun sake.

**Hafte ki ek line.** Ek sentence jisme KPI, guardrail aur adoption ho, har hafte bhejo: "Is hafte median 26 minute har file par, 41 se kam; rework 7% baseline ke against 5.8%; 82% officers active." Ye business owner ko informed rakhta hai aur final review ko formality bana deta hai, kyunki kisi ko surprise nahi hota.

## Ek example se samjho

Chennai ke lender mein discovery ke baad, aap propose karte ho:

- **Primary KPI**: har loan file par median officer time, file kholne se credit note submit karne tak.
- **Baseline**: pilot se pehle chaar hafte loan system ke timestamps se measure kiya: 41 minute median, 6,200 files.
- **Target**: 20 pilot officers ke liye pilot start ke das hafte ke andar 22 minute median.
- **Guardrails**: credit committee rework rate (baseline 7%) nahi badhna chahiye; audit dwara flag hue policy exceptions mein koi badhoutri nahi.
- **Adoption**: pilot officers ka share jo apni kam se kam 80% files par draft summary use karte hain.

Head of operations pehle "90% AI accuracy" ko target banana chahte hain. Aap samjhate ho ki accuracy quality input ki tarah track hogi, par lender ka business result officer time aur rework hai, aur dono par agree karte ho. Das hafte baad pilot 24 minute median, 5.1% rework aur 88% adoption dikhata hai. Target time par thodi se chuka, par quality mein beat hua; kyunki measures pehle se agree the, baat rollout ki hoti hai, ye nahi ki success ka matlab kya tha.

| Measure | Baseline | Target | Pilot result |
| --- | --- | --- | --- |
| Har file ke median minute | 41 | 22 | 24 |
| Rework rate | 7% | 7% se upar nahi | 5.1% |
| Adoption | Lagu nahi | Files ka 80% | 88% |
| End ki baat-cheet | | | Rollout ke baare mein, success ka matlab kya tha is par nahi |

## Aam galtiyaan

- **Model metrics ko KPI banana.** Accuracy ek zariya hai; business mein time, cost ya errors manzil hain.
- **Baseline na hona.** "Officers ko lagta hai ye tez hai" budget review mein nahi tikega.
- **Bahut saare KPIs.** Das numbers aur kisi ko pata nahi kaunsa matter karta hai. Ek primary, kuch guardrails.
- **Sirf launch ke baad measure karna.** Baseline tab lena hoga jab system ne behaviour nahi badla.
- **Adoption ko ignore karna.** Zyadatar "AI se madad nahi mili" results ki wajah kam usage hai.

3. Pilot ke chauthe hafte mein aap jo hafte ki ek-line update bhejoge, uska draft likho.
