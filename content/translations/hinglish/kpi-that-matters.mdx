## Ye kya hai

**KPI** (key performance indicator) wo ek number hai jo batata hai ki project kaam kiya ya nahi. Kisi AI deployment ke liye, ek poore KPI plan ke chhah hisse hote hain:

- Business result se juda **ek primary KPI**: har loan file par minutes, first-response time, har officer ke har din process kiye claims, har resolved ticket ki cost.
- **Ek baseline**: aapke system se pehle naapa gaya KPI, usi tareeke se, usi tarah ke logon aur cases ke liye.
- **Taareekh ke saath ek target**, aur pehle se tay bands ki met, close aur missed kise maanenge.
- **Guardrail measures**: wo cheezein jo kharaab nahi honi chahiye, jaise error rate, customer complaints ya compliance exceptions.
- **Adoption**: kya log sach mein system use kar rahe hain, kyunki jis tool ko koi use nahi karta wo KPI nahi hila sakta.
- **Ek method**: har number kahan se aata hai, kaun-se cases gine jaayenge, kaun-se hafte gine jaayenge aur kaun report karega.

Accuracy ya faithfulness jaise model metrics inputs hain, KPI nahi. Ek 95%-accurate extractor jis par officers bharosa nahi karte, aur isliye phir bhi dobaara type karte hain, kisi ka ek minute bhi nahi bachaata.

| Scope of work mein sign hua KPI plan | |
|---|---|
| **Primary** | Har loan file par median minutes, file kholne se credit note submit karne tak (loan-system timestamps) |
| **Baseline** | Poore lender par 41 min (June ke chaar hafte, 6,200 files); sirf 20 pilot officers ke liye 41 min (unmein se kareeb 690 files) |
| **Target** | Pilot shuru hone ke das hafton mein 22 min, pilot weeks 7 to 10 par judge hoga |
| **Bands** | Met: 22 ya kam. Close: 22 se upar, 26 tak. Missed: 26 se upar |
| **Guardrails** | Credit committee rework 7% se upar nahi; audit policy exceptions mein koi badhat nahi; bina edit ke accept hue drafts ki weekly spot check |
| **Adoption** | Kam se kam 80% pilot files par credit note draft se submit ho |
| **Comparison** | Unhi das hafton mein lender ki baaki branches |

## Ye kaise kaam karta hai

```flow
dir: LR
title: Evidence se verdict tak
Discovery timing -> Baseline -> Target aur bands -> Pilot, 10 hafte -> Verdict
```

### Number ko exact define karo

Us problem se shuru karo jo discovery mein mili. Agar officers har file par kareeb 40 minutes lagaate hain, toh KPI har file ka time hai, "AI accuracy" nahi. Phir use pakka karo, kyunki dheela-dhaala KPI har side ko result apne hisaab se padhne deta hai:

- **Start aur end events.** "File kholne se credit note submit karne tak", dono loan system stamp karta hai.
- **Kaun-se cases gine jaayenge.** Kisi pilot officer ki handle ki hui har file, chahe unhone draft use kiya ho ya nahi. Log naya tool pehle aasaan cases par try karte hain. Sirf un files ko ginoge jahan tool use hua, toh wo asal se zyada tez dikhega.
- **Kaun-sa statistic.** Median, mean nahi. Lunch ke dauraan ya raat bhar khuli chhodi gayi file hours mein dikhti hai. Aisi ek file mean ko bahut hila deti hai aur median ko lagbhag nahi. Data ki check ke taur par, do ghante se upar waali files ka share alag se report karo.
- **Elapsed time, working time nahi hai.** Timestamps ghadi naapte hain, mehnat nahi. Jab tak baseline aur pilot ek hi tarah naape jaayen, ye chalta hai.

Surveys ki jagah wo numbers lo jo systems pehle se record karte hain (timestamps, ticket close times). Agar koi system wo number record nahi karta, toh pehle measurement set up karo: kuch cases ke start aur end times ka ek simple log, pilot se pehle shuru kiya hua.

### Baseline sahi logon par naapo

Wahi team aur usi tarah ke cases, kaafi volume (kuch sau cases, kam se kam do se chaar hafte), aur ek aam samay use karo. Month-end rush, festival season ya nayi credit policy, ye sab use bigaad dete hain.

Do baselines naapo: poora organisation aur sirf pilot group. Pilot groups aksar isliye chune jaate hain kyunki wo utsaahi hain, achhe se chalte hain ya head office ke paas hain. Agar pilot officers pehle se 35 minutes lete the, toh unhe poore lender ke 41 se compare karne par tool ko wo chhah minutes ka credit mil jaata jo usne kabhi bachaaye hi nahi. Chennai lender par dono baselines 41 minutes aaye, isliye pilot comparison fair hai. Phir bhi pilot branches average se zyada utsaahi thi, isiliye business case ne baad mein full rollout ke liye ek zyada saavdhaan figure plan kiya (executives se baat karne waala lesson dekho).

### Target khwaahish se nahi, evidence se set karo

"Aadha kar do" ek khwaahish hai. Defend karne laayak target kaam se hi nikalta hai. Discovery mein team ne officers ke saath baithkar kuch files ka time naapa (case ke figures): kareeb 16 minutes documents padhne aur applicant ko judge karne mein gaye, aur kareeb 25 figures dobaara type karne aur credit note likhne mein. Assistant figures aur note draft karta hai, par officers ab bhi flagged aur critical fields check karte hain, jiska team ne kareeb 6 minutes ka andaaza lagaaya. Toh target tha 16 + 6 = 22 minutes.

Aise bana target do kaam karta hai. Client dekh sakta hai ki wo kahan se aaya. Aur agar pilot miss ho, toh aapko pata hai ki kaun-sa step dekhna hai: yahan, checking mein andaaze se zyada time laga.

### Met, close aur missed ka matlab pehle se tay karo

Weekly medians sanyog se hilte hain. June ke baseline hafton mein, kuch bhi badle bina, hafte ki kareeb 170 files par pilot group ka weekly median ek se do minutes tak hila. Isliye 22 ke target ke saamne 24 ka result aane par ek rule chahiye jo kisi ke dekhne se pehle tay ho.

| Band | Range | Kya hoga |
| --- | --- | --- |
| Met | 22 minutes ya kam | Rollout recommend karo |
| Close | 22 se upar, 26 minutes tak | Rollout recommend karo, ek saavdhaan planning figure aur gap ke liye fix plan ke saath |
| Missed | 26 minutes se upar | Ek chhote extension ya chhote scope ke saath fix plan, ya rok do |

Baad waale hafton par judge karo. Shuruaati hafton mein results dono taraf bigadte hain: officers abhi tool seekh rahe hote hain, aur kuch nayi cheez se excited hokar use baad se zyada use karte hain (novelty effect). Lender ne shuruaati problems theek hone ke baad, pilot weeks 7 to 10 par judge kiya.

Gap ka kitna hissa sanyog hai, ye dekhne ke liye median ki ek likely range nikaalo. Akeli files nahi, officers ko resample karo, kyunki ek officer ki files ek jaisi hoti hain:

```python
import numpy as np
import pandas as pd

df = pd.read_csv("pilot_files.csv", parse_dates=["opened_at", "submitted_at"])
df["minutes"] = (df["submitted_at"] - df["opened_at"]).dt.total_seconds() / 60

# Weekly median per branch: the numbers behind the weekly line
print(df.pivot_table(index="pilot_week", columns="branch",
                     values="minutes", aggfunc="median").round(1))

# Judge on pilot weeks 7 to 10, using every file, draft used or not
end = df[df["pilot_week"].between(7, 10)]
officers = [g.to_numpy() for _, g in end.groupby("officer_id")["minutes"]]

# Resample officers, not files: one officer's files are alike
rng = np.random.default_rng(7)
n = len(officers)
medians = [np.median(np.concatenate([officers[i] for i in rng.integers(0, n, n)]))
           for _ in range(2000)]
low, high = np.percentile(medians, [2.5, 97.5])
print(f"median {end['minutes'].median():.1f} min, likely range {low:.1f} to {high:.1f}")
```

Agar target likely range ke baahar hai, toh gap asli hai, noise nahi. Ye saaf-saaf kaho.

### Guardrails chuno, ek gaming ke khilaaf bhi

Zyada errors ke saath tez processing jeet nahi hai. Ek ya do quality measures chuno jinki client ke risk owners pehle se parwaah karte hain, jaise credit committee rework aur audit exceptions. Rework ek lagging measure hai: committee submission ke ek-do hafte baad files waapas bhejti hai, isliye use usi lag ke saath report karo aur aakhri hafte par use judge mat karo.

Gaming ke khilaaf ek guardrail jodo. Goodhart's law, jiska naam economist Charles Goodhart par hai, aksar aise kaha jaata hai: "jab koi measure target ban jaata hai, toh wo achha measure nahi rehta". 22 minutes chhoone ke dabaav mein ek officer draft bina padhe accept kar sakta hai. Number sudharta hai; asli result nahi. Isliye bina kisi edit ke accept hue drafts ka share track karo, aur ek senior officer se har hafte 20 random files spot-check karwaao. Zero-edit share 100% ki taraf badhta jaaye aur spot checks mein chhoote errors milein, toh matlab rubber-stamping ho rahi hai.

### Fair tareeke se compare karo

Pilot ke dauraan kuch aur hamesha badalta hai: nayi policy, chhutti par staff, koi seasonal rush. Ek comparison group ise pakad leta hai. Unhi hafton mein system ke bina waise hi logon ka KPI track karo; lender par baaki branches poore samay kareeb 41 minutes par rahin, isliye giraavat poore lender ka badlaav nahi thi. Agar sabko tool ek saath mile, toh unhi logon ko pehle aur baad mein compare karo, aur jo kuch bhi aur badla use likh lo. Method ko pilot shuru hone se pehle measurement plan mein daal do, taaki baad mein koi apne faayde waala comparison na chun sake.

### KPI ko rupees mein badlo

Executives rupees ko fund karte hain, minutes ko nahi. Lender ke apne HR figure se ek loaded officer hour kareeb ₹600 ka hai, toh har file par ek minute bachna matlab 6,000 files ÷ 60 = mahine ke 100 officer hours, jinki keemat mahine mein kareeb ₹60,000 hai. Pandrah minutes bachein toh mahine mein kareeb ₹9 lakh. Ye ek conversion kisi ko bhi har weekly result ko paise mein badalne deta hai.

| Input (model ya system) | Outcome (business) | Ye rupees kaise banta hai |
| --- | --- | --- |
| Extraction accuracy | Har loan file par minutes | Bache minutes × files × har minute ki cost |
| Faithfulness score | Rework rate | Waapas na bheji gayi files × dobaara karne ke hours × hourly cost |
| Retrieval recall | Policy waale sawaal ka jawaab dene ka time | Bache minutes × sawaal × har minute ki cost |
| Latency | Har agent ke har ghante handle kiye calls | Bina extra staff ke handle hui extra calls |

Running cost pata chalte hi break-even nikaalo: har file par wo sabse chhoti bachat jis par value aur cost baraabar ho jaayen. Lender par full-volume cost model der se, contract week 10 mein aaya (case study waala lesson dekho). Usse kareeb 13 minutes ka break-even nikla: bachat 13 minutes ya usse zyada rehni chahiye, yaani har file par 28 minutes ya kam. Cost model shuruaati hafton mein banao, taaki pilot judge hone se pehle ye floor pata ho.

### Har hafte report karo, group ke hisaab se baantkar

Har hafte KPI, guardrail aur adoption ke saath ek line bhejo. Pilot week 2 mein wo aisi thi: "Har file par median 27 minutes (baseline 41, target 22); rework 5.4%, limit 7%; 78% files par draft use hua."

Use branch ke hisaab se bhi baanto. Ek hafte baad split ne wo dikhaaya jo blended line ne nahi dikhaaya: Anna Nagar mein 92% files par draft use hua par Tambaram mein sirf 41% par, jahan median 37 minutes tha. Wahan ke officers ko AI errors ka dosh apne sir aane ka darr tha, isliye wo sab kuch dobaara type kar rahe the. Usi split se wo branch visit hui jisne ise theek kiya (change management waala lesson dekho). Blended number batata hai ki problem hai ya nahi. Split batata hai ki wo kahan hai.

## Ek worked example

Chennai lender par discovery ke baad, aap upar waali table ka plan propose karte ho. Head of operations pehle target ke taur par "90% AI accuracy" chahti hain. Aap golden set par accuracy ko ek quality input ki tarah track karne par haan kehte ho. Phir samjhaate ho ki ek accurate draft jis par officers bharosa nahi karte, kuch nahi bachaata. Lender paisa officer time aur rework ke liye deta hai, isliye wahi KPI aur guardrail hain. Wo maan jaati hain, aur plan scope of work mein chala jaata hai.

Pilot se pehle aap June ke timestamps do baar nikaalte ho: poore lender ke liye (41 minutes, 6,200 files) aur sirf 20 pilot officers ke liye (41 minutes, kareeb 690 files). Aap timed steps se target (22 minutes) set karte ho aur bands tay karte ho.

Pilot ke dauraan weekly line pilot week 3 mein Tambaram ko flag karti hai, aur do hafte baad wahan adoption waapas 85% par aa jaata hai. Phir pilot weeks 7 to 10 verdict dete hain:

| Measure | Baseline | Target | Pilot weeks 7 to 10 | Verdict |
| --- | --- | --- | --- | --- |
| Har file par median minutes | 41 | 22 | 24 (likely range 23 to 25) | Close |
| Rework rate | 7% | 7% se upar nahi | 5.1% | Tika raha, aur sudhra |
| Adoption | Laagu nahi | 80% files | 88% | Met |
| Baaki branches, wahi hafte | 41 | Koi badlaav apekshit nahi | Kareeb 41 | Baahar koi badlaav nahi |

Imaandaar summary ye hai: "Close, met nahi. Har file ka time 17 minutes ghata, 41 se 24. 22 ka target likely range ke baahar hai, isliye gap asli hai. Flagged fields check karne mein hamare andaaze ke 6 minutes se zyada time laga." Kyunki bands pehle se tay the, koi is par behas nahi karta ki 24 safalta hai ya nahi. End-of-pilot meeting rollout aur checking step ke baare mein hai, is baare mein nahi ki safalta ka matlab kya tha.

## Aam galtiyaan

- **Model metrics ko KPI banaana.** Accuracy ek zariya hai; business mein time, cost ya errors manzil hain.
- **Baseline na hona, ya galat group ka baseline.** "Officers ko lagta hai ki ye tez hai" budget review mein nahi tikega, aur poore lender ka baseline ek utsaahi pilot group ko asal se behtar dikha sakta hai.
- **Sirf un files ko ginna jahan tool use hua.** Log use pehle aasaan cases par use karte hain. Har pilot file gino.
- **Shuruaati hafton par judge karna.** Seekhna aur novelty effect unhe bigaadte hain. Jaisa tay hua, baad waale hafton par judge karo.
- **Thode se miss par baad mein behas karna.** Pilot shuru hone se pehle met, close aur missed bands tay karo.
- **Achha sunaai dene ke liye chuna target.** Use timed steps se banao, taaki miss hone par pata chale ki kahan dekhna hai.
- **Aise guardrails jo gaming nahi pakad sakte.** Akela rework der se aata hai; bina edit ke accept hue drafts ki spot checks jodo.
- **Sirf blended number.** Har hafte branch ya team ke hisaab se baanto, warna ruka hua group average ke andar chhip jaata hai.
- **Bahut saare KPIs.** Das numbers hon toh kisi ko nahi pata kaun-sa maayne rakhta hai. Ek primary, kuch guardrails, ek adoption measure.

## Practice karo

Measuring success par GOV.UK ki guide padho.

1. Apni discovery exercise waale use case ke liye ek poora KPI plan likho: start aur end events ke saath primary KPI, poore organisation aur pilot group dono ke liye baseline method, timed steps se bana target, met, close aur missed bands, do guardrails aur ek adoption measure.
2. Exact batao ki har number kahan se aata hai, kaun-se cases gine jaayenge aur kaun report karega.
3. Har case par bache ek minute ko mahine ke rupees mein badlo, aise cost figure se jise client apna maane.
4. Har guardrail ke liye ek tareeka likho jisse log asli result ke bina KPI hila sakte hain, aur aap use kaise pakadoge.
5. Pilot week 4 ki weekly line draft karo, team ke hisaab se baantkar.

**Aapka kaam poora hai jab aap** client ko samjha sako ki accuracy KPI kyun nahi hai, ek measurement plan dikha sako jis par wo sign kar sakein, aur pehle se bata sako ki kis result ko aap close kahoge.
