## Ye kya hai

**Handover** ka matlab hai kisi system ko un logon ko planned tareeke se saunpna jo use own karenge. Isme teen hisse hain:

- Har audience ke liye **Documentation**: users, operators, developers aur owners.
- **Knowledge transfer**: training, pairing aur ek period jisme client ki team system chalati hai aur aap abhi bhi available ho.
- **Formal close**: handover complete hone ke agreed criteria, access hatana, aur agar ho toh support arrangement.

AI systems ko extra handover material chahiye, kyunki unka behaviour sirf code par nahi, prompts, models, data aur evals par depend karta hai.

```flow
dir: LR
title: Chaar hafton mein handover
Week 1: shadow | woh aapko operate karte dekhte hain aur docs padhte hain -> Week 2: reverse shadow | woh prompt badalte hain aur simulated incident handle karte hain; aap dekhte ho
Week 2: reverse shadow -> Week 3: run alone | woh KPI report aur cost review chalate hain
Week 3: run alone -> Week 4: close | checklist sign-off, aapka access hata, secrets rotate, support terms
```

| Reader | Documents |
|---|---|
| Users | Ek guide |
| Operators | Runbooks |
| Developers | How-tos aur architecture |
| Owners | KPIs, costs, risks |
| Sabke liye | Decision records |

Ye lesson Chennai ke ek lender ke credit-file assistant ke handover ko follow karta hai.

## Ye kaam kaise karta hai

**Har reader ke liye likho.** Ek useful split (Diátaxis framework se): seekhne ke liye tutorials, tasks ke liye how-to guides, facts ke liye reference, aur wajah ke liye explanations.

- *Users*: system ko achhe se use karne ki chhoti guide, woh kisme achha aur kisme kharab hai, outputs kaise check karein aur feedback kaise dein.
- *Operators*: routine tasks aur jaane-pehchaane incidents ke liye **runbooks**, jaise "model provider errors de raha hai", "answers purane documents ka reference de rahe hain", "costs spike ho gaye", "connector ruk gaya". Har runbook mein: symptoms, checks, fix, escalation.
- *Developers*: architecture overview, locally kaise chalayein, deploy kaise karein, prompt safely kaise badlein, configuration kahan hai.
- *Owners*: system kya karta hai, uska KPI aur abhi ke numbers, risks, costs aur reasons ke saath liye gaye decisions.

**AI-specific zaroori cheezein.** Golden sets aur evals kaise chalayein; kaunse prompt aur model versions use ho rahe hain aur unhe kaise badlein; data pipeline aur re-index kaise karein; guardrails aur unke test sets; audit log schema; cost dashboard; jaane-pehchaane failure modes examples ke saath.

**Decision records.** Important choices ke chhote notes: kya decide hua, alternatives kya the aur kyun. Ye agli team ko achhe decisions undo karne ya bure experiments repeat karne se rokte hain.

**Shadow, phir reverse shadow.** Pehle client ke engineers aapko system operate karte aur badalte dekhte hain. Phir woh khud karte hain aur aap dekhte ho: ek deploy, CI ke through evals ke saath prompt change, runbook se ek simulated incident. Handover tab complete hota hai jab woh har core task khud kar chuke hon.

**Clean exit.** Apna access hatao, shared secrets rotate karo, accounts aur billing transfer karo aur support terms confirm karo.

**Ek runbook page:**

| Section | Example: "answers purane documents cite kar rahe hain" |
| --- | --- |
| Symptoms | Users purane rates bata rahe hain; refusal rate normal; feedback mein dates ka zikr |
| Checks | Index freshness dashboard; last pipeline run; effective-date filter setting |
| Fix | Affected source ke liye indexing job dobara chalao; superseded flags confirm karo |
| Verify | Golden set se current rates ke baare mein teen test questions poochho |
| Escalate | Agar source connector do baar fail ho, toh platform team lead ko contact karo |

**Handover checklist.** Sign-off se pehle har item ko us client engineer ke naam ke saath tick karo jisne woh kiya: ek release deploy kiya; ek rollback kiya; CI ke through evals ke saath prompt badla; ek source re-index kiya; runbooks se do simulated incidents handle kiye; monthly KPI aur cost report banayi; ek secret rotate kiya. Diye gaye documents aur hataye gaye accounts bhi jodo. Client ki team ka sign kiya hua checklist engagement ka end saaf kar deta hai aur is par disputes se bachata hai ki kya handover hua.

**Un logon ke liye likhna jo wahan nahi the.** Maan lo reader ek saal baad join karta hai aur aapki team se kabhi mila nahi. Samjhao ki cheezein aisi kyun hain, decision records ka link do, aur examples real rakho. Project ke bahar ke kisi insaan se har how-to guide bina madad ke follow karwao, aur jahan woh atke, har jagah fix karo.

## Ek example se samjho

Chennai ke lender ke credit-file assistant ka handover chaar hafte leta hai.

Hafta 1: lender ke do engineers, Karthik aur Divya, daily operations mein aapke saath pair karte hain aur developer docs padhte hain, 23 sawaal uthate hain jo doc fixes ban jaate hain.

Hafta 2: Divya ek naye regional format ke liye summary prompt badalti hain. Woh CI mein eval suite chalati hain, golden set par 1.5-point ki giraawat dekhti hain, ek instruction fix karke merge karti hain. Karthik runbook se ek simulated incident ("document store ka connector ruk gaya") 25 minute mein handle karte hain.

Hafta 3: woh monthly KPI report aur cost review khud chalate hain; operations team ka champion aapki user guide se naye officers ke liye training session leta hai.

Hafta 4: handover checklist ke against sign-off, aapke accounts ka removal, jo gateway keys aapne use ki thi unka rotation, aur sirf escalations ke liye teen mahine ka support agreement.

Chhe mahine baad, Karthik evals pass hone ke baad gateway ke peeche ka model aapko bulaye bina upgrade kar dete hain. Yahi successful handover hai.

| Hafta | Transfer ka saboot |
|---|---|
| 1 | Client engineers ke 23 sawaal doc fixes mein badle |
| 2 | Divya ke prompt change ne CI mein 1.5-point ki giraawat pakdi aur fix hui; Karthik ne simulated connector incident 25 minute mein solve kiya |
| 3 | KPI aur cost reviews client team ne chalaye; officer training unke champion ne ki |
| 4 | Checklist sign hua; accounts hataye gaye; gateway keys rotate hui; teen mahine ka escalation support |
| Chhe mahine baad | Karthik ne evals pass hone ke baad model upgrade kiya, bina bulaye |

## Aam galtiyaan

- **Ek bada sa document.** Alag readers ko alag documents chahiye.
- **Runbooks nahi.** Operators system ko apne pehle incident mein seekhte hain.
- **Evals chhod dena.** Golden sets aur eval scripts ke bina client prompts ya models safely nahi badal sakta.
- **Aakhri hafte mein handover.** Pilot se hi shuru karo; ismein time aur practice lagti hai.
- **Access bhool jaana.** Aapki keys aur accounts hatane aur secrets rotate karne zaroori hain.

## Practice karo

Agar abhi tak nahi padha, toh Diátaxis overview aur Google technical writing ki pehli unit padho.

1. Apne banaye kisi system ke liye ek page ka architecture overview, prompt safely badalne ki how-to guide aur mumkin incidents ke do runbooks likho.
2. Apne liye gaye do choices ke liye alternatives aur reasons ke saath do decision records likho.
3. Kisi dost se apni how-to guide aur ek runbook bina aapki madad ke follow karwao; unke har sawaal ko note karo aur docs fix karo.

**Aapka kaam poora jab:** aap kisi aur ko sirf apne documents se prompt badalte, evals chalate aur deploy karte dekh sako.
