## Ye kya hai

**Synthetic data** woh data hai jo asli logon se collect karne ki jagah kisi model ya program ne banaya ho. Aap bade model se 5,000 customer questions likhwa sakte ho, English examples ko Marathi mein translate karwa sakte ho, support tickets ka dher label karwa sakte ho, ya evaluation ke liye test cases likhwa sakte ho.

**Distillation** iska ek zaroori use hai. Ek chhota **student** model ek bade **teacher** model ko ek task par copy karna seekhta hai, teacher ke answers ko training data ki tarah use karke. Maqsad hai ek aisa model jo bahut sasta aur tez ho, aur us task par teacher ke kareeb quality de. Ek jaana-maana shuruaati example, DistilBERT, ne apne teacher ki language-understanding ability ka lagbhag 97% rakha, jabki woh 40% chhota aur 60% tez tha.

Teams synthetic data paanch mukhya kaarno se use karti hain:

- **Quantity.** Real labelled data collect karna dheema aur mehnga hai. Ek model ek ghante mein hazaaron examples bana sakta hai.
- **Coverage.** Aap rare cases ke examples jaan-boojhkar bana sakte ho: ajeeb complaints, bahut lambe inputs, mushkil edge cases ya testing ke liye attacks.
- **Quality.** Kabhi-kabhi ek strong model jaldbaazi mein kaam karti human team se zyada consistent labels ya mushkil sawaal likhta hai.
- **Privacy.** Jab real records use nahi ho sakte, jaise patient files ya insurance claims, tab realistic banaye gaye records unki jagah le sakte hain.
- **Distillation.** Ek sasta model ek mehnge model se ek task seekh sakta hai.

```flow
title: Synthetic data banana aur use karna
Real seed examples | kuch sau, check kiye hue
Real seed examples -> Strong model se generate karo | paraphrase, translate, label, create
Strong model se generate karo -> Filter karo aur verify karo | duplicates, length, judges, tests
Filter karo aur verify karo -> Sample kaafi achha hai?
Sample kaafi achha hai? -[nahi]-> Prompt ya seeds theek karo
Prompt ya seeds theek karo -> Strong model se generate karo
Sample kaafi achha hai? -[haan]-> Real data ke saath milao | kabhi poora synthetic nahi
Real data ke saath milao -> Student model train karo
Student model train karo -> Real, unseen data par test karo | final judge
```

## Ye kaam kaise karta hai

**Generate karne ke tareeke.** Aam methods, sabse simple se sabse involved tak:

1. **Templates aur rules.** "I booked [service] on [date] and want a refund" jaise template ko values ki lists se bharo. Sasta aur predictable, par repetitive.
2. **Paraphrasing.** Model ko ek real example do aur kai tareeke se dobara likhne ko kaho. "How do I cancel my ticket?" se "I want to cancel my booking" aur "Ticket cancel kaise karu?" ban jaata hai. Rare classes badhane ka achha tareeka.
3. **Translation.** Jis language mein bahut data hai, jaise English, usse jis mein kam hai, jaise Kannada, examples translate karo. Quality **back-translation** se check karo: result ko kisi alag model se wapas English mein translate karo aur original se compare karo. Bahut alag ho toh example hata do.
4. **Labelling.** Strong model se real, unlabelled data label karwao. Yeh aksar sabse achhi value hai, kyunki inputs real rehte hain aur sirf labels model banata hai.
5. **Simulation.** Ek model customer bane aur doosra support agent, jisse training ya testing ke liye poori conversations bante hain.
6. **Instruction generation.** Haath se likhe chhote tasks ke set se shuru karo aur model se usi style mein naye tasks aur answers gadhne ko kaho. Kai shuruaati open instruction datasets aise hi bane the.

**Train karne se pehle verify karo.** Model-made data mein galtiyaan hoti hain, isliye filtering optional nahi hai.

- **Ho sake toh chalakar dekho.** Code ko tests ke against chala sakte hain, aur SQL ko sample database par. Jis data ko chalakar check kiya ja sake, use generate karna sabse safe hai, isliye code synthetic data ke sabse common kisso mein se ek hai.
- **Judge use karo.** Ek LLM judge har example ko likhe quality rules ke against score kar sakta hai, ya woh examples flag kar sakta hai jo off-topic hain ya jinme gadhe hue facts hain.
- **Simple filters lagao.** Exact aur near duplicates hatao, bahut chhote ya bahut lambe examples, woh jinme output input ko dohrata hai, aur woh jinme sawaal wahi hai par answers aapas mein takrate hain.
- **Ek sample khud padho.** 100 random examples padhne mein tees minute lagte hain aur woh problems pakadte hain jo koi filter nahi pakad sakta.

Ek chhoti filter script basics cover kar leti hai:

```python
import json
from difflib import SequenceMatcher

def keep(ex, seen):
    q, a = ex["input"].strip(), ex["output"].strip()
    if not (5 <= len(q.split()) <= 120):        # too short or too long
        return False
    if a.lower() == q.lower() or q.lower() in a.lower():  # output repeats the input
        return False
    for s in seen[-500:]:                        # near-duplicate of a recent example
        if SequenceMatcher(None, q.lower(), s).ratio() > 0.9:
            return False
    seen.append(q.lower())
    return True

seen, kept = [], []
for line in open("generated.jsonl"):
    ex = json.loads(line)
    if keep(ex, seen):
        kept.append(ex)
print(f"kept {len(kept)} examples")
```

**Ek task distil karo.** Teacher ko apne task ke bahut saare real inputs par chalao, uske answers (filter karne ke baad) rakho, aur un pairs par ek chhota model fine-tune karo. Student ko real, hand-labelled data par test karo jo usne kabhi dekha nahi, aur usi test par teacher se compare karo.

| Method | Kis liye achha | Mukhya risk |
| --- | --- | --- |
| Templates aur rules | Simple formats, jaldi test cases | Repetitive, unrealistic text |
| Paraphrasing | Rare classes badhana, alag-alag wording | Users asal mein jaise likhte hain usse door ho jaata hai |
| Back-translation ke saath translation | English se Indian-language data | Akadi, formal language jo users bolte nahi |
| Real inputs ko model se label karwana | Classification aur extraction | Teacher ki galtiyaan student ki galtiyaan ban jaati hain |
| Simulation | Multi-turn conversations, agent testing | Dono taraf model jaisi awaaz |
| Distillation | Ek task ke liye sasta, tez model | Skill ke bina style copy karta hai |

## Ek example se samjho

Gurugram ki ek travel company mahine mein 50,000 support messages ko 20 intents mein baantti hai, jaise refund, date change aur baggage. Ek bada model 500 hand-labelled messages par 94% accuracy se karta hai, par mahine ka ₹1.2 lakh kharch hota hai.

Woh 20,000 real purane messages lete hain, naam, phone numbers aur booking IDs mask karte hain, aur bade model se label karwate hain. Ek support lead 300 labels check karta hai aur 93% sahi paata hai, zyadatar galtiyaan do intents mein jinhe guide ne kharab describe kiya tha. Woh guide theek karte hain, un do intents ko dobara label karte hain aur phir check karte hain.

Visa refund samet teen intents ke 30 se kam real examples hain. Inke liye, woh bade model se har real example ko English, Hindi aur Hinglish mein paanch tareeke se paraphrase karwate hain, duplicates filter karte hain, aur ek sample kisi insaan se check karwate hain. Final 21,500 mein synthetic examples lagbhag 10% hain.

Woh ek chhote open-weight model ko labelled set par fine-tune karte hain aur use original 500 messages par test karte hain, jo training mein kabhi use nahi hue.

| Option | 500 real messages par accuracy | Sabse kamzor intent | Mahine ka cost |
| --- | --- | --- | --- |
| Bada model, prompted | 94% | 85% (visa refund) | ₹1.2 lakh |
| Chhota model, sirf real labels | 90% | 52% (visa refund) | ₹9,000 |
| Chhota model, real labels plus synthetic rare intents | 93% | 81% (visa refund) | ₹9,000 |

Numbers sirf samjhane ke liye hain, yeh dikhane ke liye ki compare kaise karte hain. Synthetic examples ne mukhya roop se rare intents mein madad ki. Team un messages ke liye bade model ko fallback rakhti hai jahan chhota model unsure hota hai, aur har mahine real, hand-checked messages ka ek naya sample training set mein jodti hai.

## Aam galtiyaan

- **Bina check kiye output par train karna.** Garbage in, garbage out. Filter karo, verify karo aur ek sample padho.
- **Synthetic data par test karna.** Final test real data par hona chahiye jo training mein kabhi use nahi hua. Warna aap yeh naap rahe ho ki student teacher ko kitna achha copy karta hai, yeh nahi ki woh users ke kitna kaam aata hai.
- **Poora synthetic ho jaana.** Models ko baar-baar model-made data par train karne se **model collapse** ho sakta hai: rare cases ghat jaate hain aur galtiyaan jama hoti jaati hain. Mix mein real data rakho.
- **Student se teacher ko peechhe chhodne ki ummeed.** Distilled model us task par shaayad hi teacher se aage nikalta hai. Agar teacher kamzor hai toh pehle use theek karo.
- **Terms of use ko ignore karna.** Kai providers apne outputs ko competing models train karne mein use karne ki ijaazat nahi dete. Terms padho, aur record rakho ki kaunse model ne kaunsa data banaya.
- **Yeh bhool jaana ki data kahan se aaya.** Agar teacher kisi benchmark par train hua tha, toh us par aapke student ka score contaminated ho sakta hai.

## Model-made data ki seemayein

- **Skill ke bina style.** Mazboot models ki nakal karne ke liye train kiye gaye models par research ne paya ki woh style achhe se copy karte hain par facts aur naye tasks mein kamzor rehte hain. Jin solutions ko woh khud hal nahi kar sakta, unpar train hua student confident, galat answers dena seekh sakta hai.
- **Bias ka badhna.** Agar teacher kuch answers ko favour karta hai, toh student woh bias seekh leta hai, kabhi-kabhi aur zyada.
- **Anjaan lineage.** Model-made data chhupa deta hai ki knowledge kahan se aayi, jisme teacher ke training data ki possible copyright problems bhi shaamil hain.
- **Unrealistic language.** Generated Hindi aksar utni hi formal hoti hai jitni log WhatsApp par asal mein nahi likhte. Real seed examples use zameen se jode rakhte hain.
