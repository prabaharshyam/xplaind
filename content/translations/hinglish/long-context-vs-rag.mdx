## Ye kya hai

Kisi sawaal ka jawaab dene ke liye model ko zaroori jaankaari dene ke teen tareeke hain:

- **Long context**: poore documents prompt mein daalo, phir poochho.
- **Retrieval (RAG)**: ek index par ek baar search chalao aur sirf sabse achhe kuch passages prompt mein daalo.
- **Agentic search**: model ko search tools do (keyword search, ek metadata filter, "open document", ek database query) aur use tay karne do ki kya dhoondhna hai, results padhne do aur phir se search karne do, jab tak wo jawaab na de sake.

28 November 2026 tak, Anthropic ke har latest Claude model ki context window 1-million-token ki hai, Anthropic ke andaaze se lagbhag 555,000 shabd. Toh long context aksar possible hai. Wo samajhdaari hai ya nahi, ye accuracy, cost, latency aur scale par nirbhar hai.

| | Long context | RAG | Agentic search |
| --- | --- | --- | --- |
| Model kya padhta hai | Poore documents | Ek search se 3 se 10 passages | Kai steps mein uski searches jo bhi lautaayein |
| Taaqat | Sab kuch dekhta hai; cross-reference kar sakta hai | Sasta, tez, millions of documents tak scale karta hai | Multi-step sawaal aur exact identifiers follow karta hai |
| Kamzori | Length ke saath cost aur delay badhte hain; lambe inputs mein accuracy girti hai | Ek search jo miss kare, wo ye bhi miss karta hai | Zyada calls, dheema, kam predictable |
| Engineering | Kam | Chunking, indexing, tuning | Achhe tools, step limits, logging |

```flow
title: Measure karne se pehle, pehla faisla
Aapke documents -[window mein aa jaayein, aksar reuse hon]-> Caching ke saath long context
Aapke documents -[bahut zyada, chhote factual sawaal]-> RAG
Aapke documents -[bahut zyada, jawaab ko kai lookups chahiye]-> Agentic search
RAG -[sawaalon ko poore documents chahiye]-> Document-level retrieval, phir long context
```

Ye lesson Chennai ki ek law firm ko follow karta hai, jo teen bahut alag-alag uses ke liye ek contract assistant bana rahi hai.

## Ye kaise kaam karta hai

### Inputs badhne par accuracy girti hai

Models lambe input ki har position ko barabar achhi tarah use nahi karte.

- **Lost in the middle.** Liu aur saathiyon (2023) ne models ko kai documents diye aur paaya ki accuracy tab sabse zyada thi jab jawaab shuruaat ya aakhir ke paas tha, aur beech mein sabse kam: ek U-shaped curve.
- **Context rot.** Chroma ki report (July 2025) ne 18 models test kiye aur paaya ki input badhne ke saath performance kam bharosemand hoti gayi, simple tasks par bhi. Jab sawaal aur jawaab shabdon aur matlab mein kam milte-julte the, yaani model ko match karne ki jagah infer karna pada, toh ye aur tezi se giri. Ek bhi plausible distractor, yaani aisa sentence jo jawaab jaisa dikhe par ho nahi, accuracy ghata deta tha, aur zyada distractors use aur ghataate the.

Ise aise samjho: jawaab ke aaspaas jitne zyada milte-julte sentences honge, model ke galat waala uthaane ke utne zyada mauke honge.

Isliye **advertised window** (API jitna accept karti hai) ko **effective context** se alag rakho: wo length jis par *aapka* task accurate rehta hai. "Needle in a haystack" test, yaani ek planted sentence dhoondhna, sabse aasaan case hai, aur aajkal ke models ise aksar pass kar lete hain. Pass hone se un sawaalon ke baare mein kam pata chalta hai jo clauses compare karte hain, figures jodte hain ya kisi rule ke puraane version ko ignore karna maangte hain.

### Cost: har call par har token ke paise

Jab tak document cache na ho, har sawaal use poora dobaara bhejta hai aur poore ke paise dobaara deta hai. Claude Sonnet 5.5 ki list prices, 28 November 2026 ko Anthropic ke pricing page par check keen:

| Item | USD prati million tokens | Input price ka guna |
| --- | --- | --- |
| Input | $2.00 | 1x |
| Cache write, 5-minute lifetime | $2.50 | 1.25x |
| Cache write, 1-hour lifetime | $4.00 | 2x |
| Cache read | $0.10 | 0.05x |
| Output | $10.00 | 5x |

Cache-read ka guna model ke hisaab se badalta hai: Claude Fable 5.2 par 0.025x, Claude Opus 5.5 aur Sonnet 5.5 par 0.05x, aur Claude Haiku 5.5 samet baaki zyadatar par 0.1x. Kuch models lambe prompts ke liye prati token zyada charge bhi karte hain: Claude Haiku 5.5 ka input $0.10 prati million tokens hai jab prompt 100,000 tokens tak ho, aur usse lamba hone par poori request ke liye $0.50 (wahi check date). Doosre providers caching ka price alag tarah se rakhte hain, isliye apne provider ka page padho aur date likh lo.

### Prompt caching: ye kya badalti hai, aur kab fail hoti hai

**Kaise kaam karti hai.** Provider aapke prompt ki processed shuruaat (prefix) store kar leta hai. Baad ki koi request jiska prefix byte-for-byte wahi ho, use cache se padhti hai: sasta, aur first token tak tez. Isliye lamba, stable hissa pehle rakho aur sawaal aakhir mein, isse sawaal bhi wahin rehta hai jahaan se model likhna shuru karta hai.

**Lifetime.** Default mein ek cache entry 5 minutes rehti hai, aur har hit clock ko reset karta hai. 1-hour lifetime ka write 2x padta hai. Anthropic ke docs kehte hain ki 5-minute cache ek read ke baad apni keemat vasool kar leta hai aur 1-hour cache do ke baad.

**Gotchas jo experts check karte hain:**

- **Lifetime se lambe gaps.** Agar 5-minute cache ke saath sawaal har 15 minutes par aayein, toh har call phir se 1.25x write deti hai, yaani aap bina cache se *zyada* paise dete ho.
- **Badalta prefix.** Document se pehle ek timestamp, ek user name ya re-order ki gayi tool list uske baad aane waali har cheez ka match tod deti hai.
- **Parallel calls.** Cache entry tabhi available hoti hai jab pehla response shuru ho jaaye, isliye ek saath bheje gaye das sawaal sab miss karte hain.
- **Har user ka ek document.** Agar 500 users apna-apna contract upload karein, toh wo 500 alag cache writes hain. Caching har session ki madad karti hai, poore system ki nahi.
- **Isolation.** Caches organisations ke beech kabhi share nahi hote, aur Anthropic ki API par workspaces ke beech bhi nahi.

Check karo ki ye chala: response ka `usage` `cache_creation_input_tokens` aur `cache_read_input_tokens` report karta hai. Agar reads zero par hi rahein, toh kuch prefix ko tod raha hai.

### Latency aur scale

Input length ke saath time to first token badhta hai, isliye bahut lambe uncached prompts chat ko dheema mehsoos karaate hain. Agentic search har step par ek model round trip jodta hai. Aur window ki ek limit hai; kisi company ke documents ki nahi. Jaise, lagbhag 30,000 tokens waale 18,000 manuals kul 540 million tokens bante hain, yaani 1-million-token window ka 540 guna. Jab corpus window se bada ho jaaye, toh kisi cheez ko chunna padta hai ki kya bhejna hai.

### Agentic search, teesra option

Aapke code ke chune ek search ki jagah, model khud search chalaata hai. Anthropic apni context engineering guide (September 2025) mein is "just in time" approach ko samjhaata hai: Claude Code zaroorat padne par files dhoondhne ke liye glob aur grep jaise tools use karta hai, jabki kuch files pehle se load hoti hain. Guide trade-off saaf batati hai: run time par explore karna pre-computed retrieval results padhne se dheema hai.

```flow
dir: LR
title: Ek sawaal par agentic search
Sawaal -> Client se contracts search karo | filters ke saath keyword search
Client se contracts search karo -> Master agreement kholo | clause 9 padhta hai
Master agreement kholo -> Clause 9 ke references search karo
Clause 9 ke references search karo -> Citations ke saath jawaab
```

**Kahaan jeetta hai:** aise sawaal jahaan agla lookup pichhle result par nirbhar ho, exact identifiers (clause numbers, error codes, part numbers) jinhein embeddings dhundhla kar dete hain, aur tezi se badalta data jise re-index karne ki jagah live query kar sako. Tools har user ki permissions bhi laagu kar sakte hain.

**Kya cost hai:** har step ek aur model call hai jo badhti hui conversation dobaara bhejti hai. Jaise, 2,000 tokens ke instructions aur tools hon aur har step par 3,000 tokens ke results judein, toh chhah steps 2,000 + 5,000 + ... + 17,000 = 57,000 input tokens bhejte hain, jabki ek RAG call mein lagbhag 3,000. Pehle ke turns cache karne se ye kam hota hai.

**Kaise fail hota hai:** bahut jaldi ruk jaata hai, ek hi search par loop karta hai, ya tool output se apna context bhar leta hai. Samajhdaar defaults: steps par cap lagao (jaise, 8), tools poori files ki jagah document IDs ke saath chhote snippets lautaayein, aur har tool call log karo taaki failures padh sako.

### Do aur patterns

- **Document-level retrieval.** Titles, summaries ya metadata par search karke sahi kuch poore documents chuno, phir long context ko unhein padhne do. Ye contracts, policies aur reports ke liye theek hai.
- **Map-reduce.** "Saari 40 board meetings summarise karo" jaise kaam ke liye, har document ko alag se summarise karo (map), phir summaries ko jodo (reduce). Ye kisi bhi corpus size par chalta hai par detail kho deta hai, isliye har summary se citations rakhne ko kaho.

```python
def doc_level_prompt(question, search_docs, load_doc, max_docs=3):
    docs = search_docs(question, k=max_docs)    # over titles, summaries and metadata
    context = "\n\n".join(f"<document title='{d['title']}'>\n{load_doc(d['id'])}\n</document>" for d in docs)
    return context + f"\n\nAnswer from the documents above. Cite titles and clause numbers.\nQuestion: {question}"
```

### Privacy

Long context poore documents model provider ko bhejta hai; RAG sirf passages bhejta hai. Agar documents mein personal data hai, toh client ka data agreement aur Bharat ki data-protection obligations check karo, aur jo task ko nahi chahiye use redact karo.

### Decision rules

- Ek ya kuch documents, ek session mein kai sawaal, aise jawaab jinhein poora text chahiye: **long context, cached**.
- Bada ya badhta collection, chhote factual sawaal, kai users: **RAG**.
- Aise jawaab jinhein kai dependent lookups ya exact identifiers chahiye: **agentic search**, step limits ke saath.
- Poore documents chahiye par chunne ko saikdon hain: **document-level retrieval, phir long context**.

### Apne documents par position aur distractors test karo

Published studies chetaavni deti hain, jawaab nahi. Ye harness banaavati audit notes (jo kisi real cheez se takra nahi sakte) kai depths par plant karta hai, milte-julte distractors jodta hai aur ek two-hop sawaal test karta hai:

```python
import random

FACT = "Audit note: the Hosur warehouse inspection code is HW-7319."
DISTRACTORS = ["Audit note: the Hosur office inspection code is HO-7391.",
               "Audit note: the 2019 Hosur warehouse code, now withdrawn, was HW-1973."]
HOPS = ["Audit note: the Hosur warehouse audit is led by Farida Sheikh.",
        "Audit note: Farida Sheikh's desk extension is 4826."]
CODE_Q = "What is the current inspection code for the Hosur warehouse?"
TESTS = {   # name: (where to insert notes, question, expected answer)
    "single fact": (lambda d: [(d, FACT)], CODE_Q, "HW-7319"),
    "distractors": (lambda d: [(d, FACT)] + [(random.random(), s) for s in DISTRACTORS], CODE_Q, "HW-7319"),
    "two hops": (lambda d: [(d, HOPS[0]), ((d + 0.5) % 1, HOPS[1])],
                 "Which extension reaches the person who leads the Hosur warehouse audit?", "4826"),
}

def build(doc, inserts):
    paras = doc.split("\n\n")                        # insert between paragraphs, never mid-sentence
    for depth, note in sorted(inserts, reverse=True):
        paras.insert(int(len(paras) * depth), note)
    return "\n\n".join(paras)

def run(doc, ask, depths=(0.05, 0.25, 0.5, 0.75, 0.95), runs=3):
    for name, (inserts, question, expected) in TESTS.items():
        for d in depths:
            ok = sum(expected in ask(build(doc, inserts(d)) + "\n\nAnswer from the document only. " + question)
                     for _ in range(runs))
            print(f"{name:12} depth {d:4.0%}: {ok}/{runs} correct")
```

`ask` koi bhi function hai jo prompt bheje aur text lautaaye. Anthropic SDK ke saath:

```python
import anthropic

client = anthropic.Anthropic()

def ask(prompt):
    r = client.messages.create(model="claude-opus-5-5", max_tokens=2000,   # the model you will deploy
                               output_config={"effort": "low"},
                               messages=[{"role": "user", "content": prompt}])
    return "".join(b.text for b in r.content if b.type == "text")
```

Ummeed karo ki single-fact row lagbhag perfect hogi; distractor aur two-hop rows hi asli jaankaari deti hain. Phir apne real sawaalon ke types jodo, jaise sections ke beech comparisons.

### Ek cost model jise aap badal sakte ho

```python
# Claude Sonnet 5.5 list prices in USD per million tokens, checked 28 November 2026
# (platform.claude.com/docs/en/about-claude/pricing). Re-check before you use them.
PRICE_IN, PRICE_OUT = 2.00, 10.00
WRITE_X, READ_X = 1.25, 0.05   # 5-minute cache write and cache read, as multiples of PRICE_IN

def call_usd(fresh_in, out, cache_write=0, cache_read=0):
    """Cost of one call. fresh_in: normal input tokens; cache_write/cache_read: cached prefix tokens."""
    inp = fresh_in + cache_write * WRITE_X + cache_read * READ_X
    return (inp * PRICE_IN + out * PRICE_OUT) / 1e6

Q, DOC, ASK, OUT, RAG_IN = 12, 40_000, 100, 300, 3_000

no_cache = Q * call_usd(DOC + ASK, OUT)
cached = call_usd(ASK, OUT, cache_write=DOC) + (Q - 1) * call_usd(ASK, OUT, cache_read=DOC)
expired = Q * call_usd(ASK, OUT, cache_write=DOC)   # every gap longer than the cache lifetime
rag = Q * call_usd(RAG_IN + ASK, OUT)

for name, usd in [("long context, no cache", no_cache), ("long context, cached", cached),
                  ("long context, cache always expired", expired), ("RAG, 3,000 tokens", rag)]:
    print(f"{name:36} ${usd:.3f}")
```

Ye no cache par $0.998, cached par $0.182, cache hamesha expire hone par $1.238, aur RAG ke liye $0.110 print karta hai. Caching long-context bill ko 80% se zyada ghata deti hai, jisse wo RAG ke qareeb aa jaata hai; expire hua cache use sabse mehnga option bana deta hai. Dollars ko us din ke rate par convert karo, aur apne documents ke tokens apne provider ke counter se gino, kyunki tokenizers alag-alag hote hain.

## Ek worked example

Chennai ki ek law firm ko contract assistant chahiye. Neeche ke numbers illustrative hain, us tarah ke jo team record karegi; costs 28 November 2026 ko check ki gayi Claude Sonnet 5.5 prices par hain.

**1. Ek contract review karna.** Ek lawyer 60-page agreement (lagbhag 40,000 tokens) upload karta hai aur lagbhag 12 sawaal poochhta hai: termination rights, indemnity caps, conflict karne waale clauses. Kai jawaabon ko poora document chahiye, isliye team long context use karti hai, contract cached aur sawaal aakhir mein. Lawyers sawaalon ke beech aksar 5 minutes se zyada rukte hain, isliye wo 1-hour cache chunte hain. Tab baarah sawaalon ki cost lagbhag $0.24 hoti hai, uncached lagbhag $1.00 ke muqaable. Maan lo 30-question test par long context 27 sahi karta hai aur chunk-based RAG 22, aur RAG ki zyadatar galtiyaan clauses ke beech cross-references par hain. Team distractor test bhi chalaati hai, kyunki unke contracts mein usi clause ke puraane, badle ja chuke versions hain.

**2. Precedent library mein search karna.** 25,000 puraane contracts, kisi bhi window se bahut aage. Lawyers poochhte hain "IT services contracts mein aise indemnity clauses dhoondho jo pichhle 12 months mein di gayi fees tak capped hon". Team metadata filters (contract type, year) ke saath hybrid retrieval use karke sabse achhe 20 clauses dhoondhti hai, phir ek model unhein citations ke saath summarise karta hai. Wo recall measure karte hain: maan lo 50 test sawaalon mein se 46 ke liye sahi clause top 20 mein hai.

**3. Cross-references follow karna.** Ek partner poochhta hai: "Is client ke saath hamare kaun-se contracts us master agreement clause par nirbhar hain jo 2025 amendment mein badla?" Ek search iska jawaab nahi de sakta: system ko amendment dhoondhna hai, padhna hai ki kaun-sa clause badla, phir us clause ko cite karne waale contracts dhoondhne hain. Team teen tools (client se search, document kholna, clause number se search) aur 8 steps ke cap ke saath agentic search use karti hai. Maan lo ek typical jawaab mein 5 tool calls aur lagbhag 30 seconds lagte hain: chat ke liye bahut dheema, research task ke liye theek.

## Aam galtiyaan

- **Advertised window par bharosa karna.** 1 million tokens accept karne waala model unhein achhi tarah use kare, ye zaroori nahi. Apne sawaalon ke types par effective context measure karo.
- **Sirf ek planted fact se test karna.** Ye sabse aasaan case hai. Distractors, two-hop sawaal aur bina jawaab waale sawaal jodo.
- **Caching ke bina costs compare karna**, ya aise cache par bharosa karna jo kabhi hit nahi hoga (upar ke gotchas dekho).
- **Sawaal, timestamp ya user name ko document se pehle rakhna.** Isse cache tootta hai aur accuracy par bhi asar padta hai.
- **"RAG khatm ho gaya" waali soch.** Bade aur badalte collections ko ab bhi retrieval chahiye, kam se kam documents chunne ke liye.
- **One-hop lookups ke liye agent use karna.** Agar ek search se jawaab mil jaaye, toh agent bas calls aur delay jodta hai.
- **Bina step limit ya logs ke agent chalaana.** Jo failures dikhein hi nahi, unhein theek nahi kar sakte.
- **Personal data se bhare poore documents bhejna**, jab passages se hi sawaal ka jawaab mil jaata.

## Jab choice saaf ho

- **Ek chhota document**: bas use prompt mein daal do.
- **Millions of documents**: kisi na kisi tarah ka retrieval chahiye, kam se kam documents chunne ke liye.
- **Structured data se jawaab**, jaise records ya tables: inmein se kuch nahi, ek tool ke zariye database query karo.

## Demo se production tak

- **Chune hue approach ke liye accuracy, cost aur latency record karo** apne golden set par, aur har model change par phir check karo.
- **Cache hit rate track karo** `cache_read_input_tokens` se, aur girne par alert karo.
- **Har request ke input tokens log karo** aur achaanak badhne par alert karo.
- **Position aur distractor tests phir chalao** jab models badlo ya documents badhein.
- **Agents ke liye, har tool call log karo** aur har jawaab ke steps par nazar rakho; badhti ginti ek early warning hai.
- **Prices unki date ke saath phir check karo**, kam se kam har quarter.

## Practice

Lost in the Middle ka abstract aur figures, Chroma ki context rot report aur apne provider ki prompt caching guide padho.

1. Ek lamba document (annual report ya policy) chuno aur 15 sawaal likho: kuch single facts, kuch jinhein do door-door ke sections chahiye, ek jiska jawaab document mein hai hi nahi.
2. Unke jawaab long context se aur apni RAG pipeline se lo. Har ek ke liye accuracy, latency aur cost record karo.
3. Long-context run ko prompt caching ke saath dohraao. Confirm karo ki `cache_read_input_tokens` zero se upar hai, phir cost aur time to first token compare karo.
