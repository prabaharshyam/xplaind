## Ye kya hai

Har developer roz do tools use karta hai:

- **Terminal**: commands chalane ki text window. Isi se aap folders mein ghoomte ho, programs chalate ho, packages install karte ho aur Git jaise tools use karte ho.
- **Git**: ek version control system jo aapke project ke snapshots record karta hai, jinhe **commits** kehte hain, taaki aap dekh sako kya badla, galtiyaan undo kar sako aur code share kar sako. **GitHub** Git repositories ko online rakhta hai taaki doosre unhe dekh sakein aur aapke saath kaam kar sakein.

```flow
dir: LR
Aapka folder | hello.py, expenses.py, README.md: aap files edit karte ho -[git add, git commit]-> Aapke computer par Git | commits 1, 2, 3: history jise undo kar sakte ho
Aapke computer par Git -[git push]-> GitHub | Aapki public repository: share karne wala link
```

Employers GitHub profiles dekhte hain. Saaf commits aur achhe README wali repository is baat ka sabse aasaan saboot hai ki aap code likh aur organise kar sakte ho, aur interviewers aksar interview ke dauraan use kholte hain.

Is lesson mein hum Nagpur mein Python seekh rahe Ravi ke saath chalenge, jab woh exercise scripts ke folder ko GitHub portfolio banata hai. Iska check ek chhota project hai: aapki apni repository, kam se kam teen saaf commits aur ek README ke saath.

## Ye kaam kaise karta hai

### Terminal ki basics

| Command | Kya karta hai |
| --- | --- |
| `pwd` | Dikhata hai ki aap kis folder mein ho (Mac, Linux; Windows par sirf `cd`) |
| `ls` | Files ki list dikhata hai (Windows Command Prompt mein `dir`) |
| `cd projects` | Kisi folder ke andar jaata hai |
| `cd ..` | Ek folder upar jaata hai |
| `mkdir python-practice` | Naya folder banata hai |
| `python hello.py` | Program chalata hai |

**Up arrow** purane commands dohrata hai, aur **Tab** file aur folder ke naam poore kar deta hai, jisse bahut type karna aur typos bachte hain.

### Git ek baar set up karo

Git install karo, phir use batao ki aap kaun ho:

```bash
git config --global user.name "Priya Raman"
git config --global user.email "priya@example.com"
```

### Repository shuru karo aur commits banao

```bash
cd python-practice
git init                         # start tracking this folder
git status                       # what has changed?
git add hello.py                 # choose changes for the next commit
git commit -m "Add hello script that prints name and date"
git log --oneline                # see the history
```

`git add` changes ko **staging area** mein rakhta hai: un cheezon ki list jo agle snapshot mein jaayengi. `git commit` us snapshot ko message ke saath save karta hai. Is do-step design se aap related changes ko saath commit kar sakte ho aur baaki baad ke liye chhod sakte ho.

### Achhe commit messages

| Kamzor | Mazboot |
| --- | --- |
| "update" | "Add expense totals by category" |
| "fixed stuff" | "Handle missing amounts in expense CSV" |
| "final" | "Add README with usage examples" |

Present tense mein likho, batao ki kya badla, aur pehli line chhoti rakho. Kuch tootne par aapka future self yahi messages padhega.

### Git se undo karna

| Sthiti | Command |
| --- | --- |
| Aakhri commit ke baad kya badla, dekhna | `git diff` |
| Kisi ek file ke changes phenkna | `git restore expenses.py` |
| Galti se add ki hui file ko unstage karna | `git restore --staged expenses.py` |
| Purana version dekhna | `git log --oneline`, phir `git show <commit>` |

### GitHub par push karna

GitHub par ek khaali repository banao, phir connect karke push karo:

```bash
git remote add origin https://github.com/priya-raman/python-practice.git
git branch -M main
git push -u origin main
```

GitHub aapse sign in karne ko kahega; uske prompts follow karo ya SSH key set up karo. Pehle push ke baad sirf `git push` naye commits bhej deta hai.

### README aur .gitignore

`README.md` batata hai ki project kya hai aur use kaise chalayein. GitHub use repository ke front page par dikhata hai.

`.gitignore` file un cheezon ki list hoti hai jinhe Git track na kare:

```text
.venv/
__pycache__/
.env
```

`.env` wali line sabse zaroori hai: `.env` files mein aksar API keys hoti hain. `.gitignore` apne pehle `git add` se **pehle** banao, kyunki secret ek baar commit ho gaya toh file ko baad mein delete karne par bhi woh history mein rehta hai. Agar kabhi koi key push ho jaaye, toh use turant revoke karo aur nayi banao.

## Ek example se samjho

Nagpur mein Python seekh rahe Ravi ke paas exercise scripts ka ek folder hai: ek expense tracker, ek marks calculator aur ek weather fetcher jo API key use karta hai. Woh ise GitHub portfolio mein badalta hai.

| Step | Woh kya karta hai | Kyun |
| --- | --- | --- |
| 1 | Folder mein `git init` | History track karna shuru |
| 2 | `.venv/` aur `.env` ke saath `.gitignore` banata hai | Environment aur apni API key ko Git se bahar rakhna |
| 3 | Commit: "Add expense tracker with category totals" | Ek saaf, matlab wala step |
| 4 | Commit: "Handle missing amounts in expense CSV" | Doosra, alag sudhaar |
| 5 | Commit: "Add README with usage examples" | Aane walon ko project samjhana |
| 6 | Nayi public repository par `git push` | Share karne ke liye ek link |

Uske README mein ek line ka summary hai, har script kaise chalayein, aur output ka ek namoona.

**Ek galti, undo ki hui.** Ek hafte baad, ek feature jodte hue woh expense tracker bigaad deta hai. `git diff` theek wahi lines dikha deta hai jo usne badli thi. `git restore expenses.py` ek second mein aakhri committed version wapas le aata hai, aur woh feature dobara zyada dhyaan se try karta hai.

**Iska fayda.** Agle mahine ek interview mein panel uski repository kholta hai aur usse commit "Handle missing amounts in expense CSV" ke baare mein poochta hai. Woh bug, use kaise dhoondha aur kaise theek kiya, sab samjhata hai. Interview ka sabse achha hissa yahi rehta hai.

## Aam galtiyaan

- **Aakhir mein ek vishaal commit.** Kaam karte hue chhote, matlab wale steps commit karo.
- **"update" jaise messages.** Batao ki kya badla.
- **Secrets commit karna.** Keys `.env` mein rakho, pehle commit se pehle use `.gitignore` mein daalo, aur jo bhi key kabhi push ho jaaye use revoke karo.
- **Virtual environments aur caches commit karna.** Unhe ignore karo.
- **README na hona.** Aane wale samajh nahi paate ki project kya karta hai ya kaise chalayein.
- **`git status` ke bina kaam karna.** Use aksar dekho; woh theek batata hai ki aap kahan ho.
