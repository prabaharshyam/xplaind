## Ye kya hai

Lagbhag saare software kaam ke neeche do tools hote hain:

- **Terminal** (ise shell ya command line bhi kehte hain) ek window hai jahaan aap click karne ki jagah commands type karte ho. Isi se aap folders ke beech jaate ho, programs chalaate ho, packages install karte ho aur Git jaise tools use karte ho.
- **Git** ek version control system hai. Ye aapke project ke snapshots record karta hai, jinhe **commits** kehte hain, taaki aap dekh sako ki kya badla, galtiyaan undo kar sako aur code share kar sako. **GitHub** ek website hai jo Git repositories ki copies online rakhti hai, taaki doosre unhe dekh sakein aur aapke saath kaam kar sakein. Git, GitHub ke bina bhi chalta hai; GitHub to bas aapki history bhejne ki ek jagah hai.

Git lagbhag har jagah hai: Stack Overflow ke 2022 developer survey mein 93% developers ne kaha ki wo ise use karte hain. Course material, take-home tasks aur aapki pehli team ka code lagbhag hamesha ek Git repository ke roop mein hi aayega.

Wo ek idea jo Git ko aasaan bana deta hai: aapke changes chaar jagahon mein se kisi ek mein rehte hain, aur har command unhe ek jagah se agli jagah le jaati hai.

```flow
title: Aapke changes kahaan rehte hain
dir: LR
Working folder | wo files jinhe aap edit karte ho -[git add]-> Staging area | agle commit mein kya hoga
Staging area -[git commit]-> Local repository | aapke commits ki history
Local repository -[git push]-> GitHub | online shared copy
GitHub -[git clone, git pull]-> Working folder
```

Git mein zyaadatar confusion isi se aata hai ki pata nahi hota koi change kis jagah par hai. `git status` ye batata hai, isliye har doosri Git command se pehle aur baad mein ise chalaao.

Ye lesson Nagpur mein Python seekh rahe Ravi ke saath chalta hai, jo exercise scripts ke ek folder ko public repository banaata hai. Iska check aapka apna ek chhota project hai, jise aakhir mein diye rubric se mark kiya jaata hai.

## Ye kaam kaise karta hai

### Terminal basics

**Pehle apna terminal chuno.** Mac par Terminal app kholo. Linux par koi bhi terminal chalega. Windows par Git for Windows install karo, jiske saath **Git Bash** aata hai, aur is course ke liye Git Bash (ya WSL, yaani Windows ke andar Linux) use karo, taaki har command waise hi chale jaise likhi hai. PowerShell bhi `pwd`, `ls` aur `cd` samajhta hai; puraana Command Prompt alag commands use karta hai, jaise `ls` ki jagah `dir`.

| Command | Ye kya karta hai |
| --- | --- |
| `pwd` | Wo folder print karta hai jismein aap ho |
| `ls` | Is folder ki files ki list deta hai |
| `ls -a` | Hidden files bhi dikhaata hai, jinke naam dot se shuru hote hain, jaise `.gitignore` aur `.env` |
| `cd python-practice` | Ek folder ke andar jaata hai |
| `cd ..` | Ek folder upar jaata hai |
| `cd ~` | Aapke home folder mein jaata hai |
| `mkdir python-practice` | Ek naya folder banaata hai |
| `python expenses.py` | Ek program chalaata hai (kuch Mac aur Linux machines par `python3`) |

**Paths.** Absolute path disk ke sabse upar se shuru hota hai, jaise `/home/ravi/python-practice` (Git Bash mein C drive `/c` hai, isliye Windows ka home folder `/c/Users/Ravi` jaisa dikhta hai). Relative path wahaan se shuru hota hai jahaan aap abhi ho: `python-practice` tabhi chalega jab wo folder maujooda folder ke andar ho. Jab "No such file or directory" dikhe, to lagbhag hamesha aap galat folder mein ho: kuch bhi aur karne se pehle `pwd` aur `ls` chalaao. Folder ke naamon mein spaces mat rakho; agar kisi mein hain, to use quotes mein likho, jaise `cd "My Projects"`.

**Environment variables** naam waali values hain jo terminal apne shuru kiye har program ko deta hai. `echo $HOME` ek ko print karta hai. `export CITY=Nagpur` ek set karta hai, par sirf usi terminal window ke liye; window band ki aur value gayi. Isiliye projects API keys ko ek `.env` file mein rakhte hain jise program padhta hai, aur theek yahi wo file hai jo kabhi Git tak nahi pahunchni chahiye.

Teen keys ghanton bachaati hain: **up arrow** pichhli commands waapas laata hai, **Tab** file aur folder ke naam poore kar deta hai (aur typos se bachaata hai), aur **Ctrl+C** chal rahe ya atke hue program ko rok deta hai.

### Git ko ek baar set up karo

Check karo ki Git install hai, phir use batao ki aap kaun ho:

```bash
git --version
git config --global user.name "Ravi Deshmukh"
git config --global user.email "12345678+ravi-d@users.noreply.github.com"
git config --global init.defaultBranch main
```

Aapka naam aur email har commit par lag jaate hain, aur push karne ke baad koi bhi unhe padh sakta hai. Agar aap apna personal email public nahi karna chahte, to GitHub aapko ek private "noreply" address deta hai: GitHub ki email settings mein "Keep my email address private" tick karo aur jo address dikhe use copy karo. Upar waala bas uski shape ka ek example hai.

Aakhri line pehli branch ka naam `main` rakhti hai, jo naam GitHub use karta hai. Iske bina, kuch Git versions pehli branch ko `master` kehte hain aur uske baare mein ek lamba hint print karte hain.

### Roz ka loop: status, add, commit

```bash
cd python-practice
git init                  # once per project: start tracking this folder
git status                # which files are new, changed or staged?
git add expenses.py       # stage this file for the next commit
git commit -m "Add expense tracker with category totals"
git log --oneline         # one line per commit, newest first
```

`git add` changes ko **staging area** mein rakhta hai, aur `git commit` jo kuch staged hai use ek snapshot ke roop mein save karta hai. Do steps isliye hain taaki ek commit mein ek hi idea ho. Agar aapne ek bug fix kiya aur saath mein ek naya feature bhi shuru kar diya, to sirf bug fix stage karo, use commit karo, aur aadha bana feature baad ke liye rakho.

`git add .` folder ki wo har cheez stage karta hai jise ignore karne ko Git se nahi kaha gaya. Ye tez hai, aur secrets aur kachra commit hone ka tareeka bhi yahi hai, isliye pehle `git status` chalaao aur list padho. `git diff` wo changes dikhaata hai jo abhi stage nahi hue; `git diff --staged` dikhaata hai ki kya commit hone waala hai.

### Commit messages jo kaam aayein

| Kamzor | Mazboot |
| --- | --- |
| "update" | "Add expense totals by category" |
| "fixed stuff" | "Handle missing amounts in expense CSV" |
| "final" | "Add README with usage examples" |

Jo rules maayne rakhte hain:

- **Verb se shuru karo, ek instruction ki tarah:** "Add", "Fix", "Handle", "Remove". Ek kaam ka test: message ko ye sentence poora karna chahiye, "If applied, this commit will...".
- **Ek commit mein ek change.** Agar use bataane ke liye "and" lagaana pade, to shaayad wo do commits hain.
- **Pehli line chhoti rakho.** Ek aam convention kareeb 50 characters ki hai. Agar "kyun" samjhaana hai, to ek blank line chhodo aur uske neeche aur likho.
- **Tab commit karo jab code chalta ho.** Tab aapki history ka har commit waapas jaane ke liye ek safe point hota hai.

### Secrets aur kachre ko baahar rakho: .gitignore

Project ke top folder mein `.gitignore` naam ki ek file un cheezon ki list rakhti hai jinhe Git ko kabhi track nahi karna chahiye:

```text
.venv/
__pycache__/
.env
```

`.venv/` aapka virtual environment hai (bada, aur `requirements.txt` se dobaara ban jaata hai), `__pycache__/` Python ka cache hai, aur `.env` mein keys hain. Sabse zyada maayne `.env` waali line rakhti hai.

Wo rule jo beginners se chhoot jaata hai: **`.gitignore` sirf un files par asar karta hai jinhe Git abhi track nahi kar raha.** Agar `.env` pehle se kisi commit mein hai, to baad mein use `.gitignore` mein daalne se kuch nahi badalta, aur `git status` use dikhaata rehta hai. Use track karna aise band karo:

```bash
git rm --cached .env      # stop tracking; the file stays on your disk
git commit -m "Stop tracking .env"
```

Isse wo sirf aage ke commits se hatti hai. Puraane commit mein key ab bhi hai, aur jo bhi repository dekh sakta hai wo use padh sakta hai. Isliye key ko leak hua maano: provider ki website par use revoke karo aur nayi banao. File delete karna kaafi nahi hai.

GitHub ek safety net jodta hai. Public repositories par ye personal accounts ke liye default roop se **push protection** chaalu karta hai, jo aise push ko rok deta hai jismein uski pehchaani hui format ka secret ho, jaise kai cloud aur AI provider keys. Ye har secret nahi pehchaan sakta, jaise aapka khud banaaya koi password, isliye asli bachaav hai apne pehle `git add` se pehle `.gitignore` banaana.

### Commit banne se pehle undo karo

| Situation | Command |
| --- | --- |
| Dekho kya badla hai jo stage nahi hua | `git diff` |
| Dekho agle commit ke liye kya staged hai | `git diff --staged` |
| Ek file mein kiye apne edits phenk do | `git restore expenses.py` |
| File ko unstage karo par edits rakho | `git restore --staged expenses.py` |
| Koi puraana commit dekho | `git log --oneline`, phir `git show a7d7b78` |

`git restore expenses.py` se saavdhaan raho: ye aakhri committed version waapas laata hai, aur jo edits aap phenkte ho wo hamesha ke liye chale jaate hain, kyunki Git ne unhe kabhi save hi nahi kiya. Kisi commit ko undo karna, use bhi jo aap push kar chuke ho, Git mein cheezein undo karne waale lesson ka topic hai.

### GitHub par push karo, aise sign-in ke saath jo chale

GitHub par **New repository** click karo, uska naam `python-practice` rakho, aur README, .gitignore aur licence waale options off chhod do, taaki repository khaali shuru ho. Phir apne folder ko usse jodo aur push karo:

```bash
git remote add origin https://github.com/ravi-d/python-practice.git
git push -u origin main
```

`origin` aapki GitHub copy ka aam nickname hai. `-u` aapki `main` ko usse jod deta hai, taaki uske baad sirf `git push` aur `git pull` chal jaayein.

**Zyaadatar beginners sign in par hi atakte hain.** 13 August 2021 se GitHub, Git commands ke liye aapka account password nahi leta. Agar terminal username aur password maange aur aap apna GitHub password type karo, to push fail ho jaata hai. Iski jagah inmein se ek chuno:

| Aapka setup | Kya karna hai |
| --- | --- |
| Git for Windows waala Windows | Git Credential Manager iske saath aata hai. Pehle push par ek sign-in window khulti hai; browser chuno, GitHub mein sign in karo, aur ye aapko yaad rakhta hai. |
| Mac ya Linux | GitHub CLI install karo aur `gh auth login` chalaao. GitHub.com aur HTTPS chuno, apne GitHub credentials se Git ko authenticate karne ke liye yes kaho, aur browser mein poora karo. |
| Aur kuch bhi | Ek fine-grained personal access token banao (GitHub Settings, phir Developer settings) jismein is repository ke Contents ka read aur write access ho, aur jahaan terminal password maange wahaan use paste karo. Ise password ki tarah hi sambhaalo. |

SSH keys ek aur option hai; Linux, shell aur SSH waala lesson unhe cover karta hai.

**Ek aur trap.** Agar aapne GitHub par "Add a README" tick kar diya tha, to aapka pehla push refuse ho jaata hai, kyunki GitHub ke paas ek aisa commit hai jo aapke computer par nahi hai:

```text
 ! [rejected]        main -> main (fetch first)
error: failed to push some refs to 'https://github.com/ravi-d/python-practice.git'
```

Nayi repository ke liye sabse aasaan fix hai use GitHub par delete karna (uska Settings page, sabse neeche), phir se khaali banaana aur push karna. Pehle `git pull` chalaane se madad nahi milti: Git "refusing to merge unrelated histories" kehkar ruk jaata hai.

### Doosron ke saath kaam karna: pehli jhalak

Team ka kaam aur take-home tasks ulti taraf se shuru hote hain: repository pehle se GitHub par hoti hai.

```bash
git clone https://github.com/example-team/expense-app.git
cd expense-app
git pull                          # bring in teammates' new commits
git switch -c add-monthly-report  # a new branch for your change
# edit files, then git add and git commit
git push -u origin add-monthly-report
```

**Branch** commits ki ek alag line hai, taaki aapka change taiyaar hone tak `main` ko na chhuye. Branch push karne ke baad aap GitHub par ek **pull request** kholte ho: ek page jo aapke changes dikhaata hai taaki `main` mein merge hone se pehle koi teammate unhe review kar sake.

Agar aap aur koi teammate ek hi lines badalte ho, to Git aap dono mein se chun nahi sakta. Wo ek **merge conflict** ke saath ruk jaata hai aur file par nishaan laga deta hai:

```text
<<<<<<< HEAD
print(sorted(totals.items()))
=======
print("Totals:", totals)
>>>>>>> 3c1dea94b5893015fb3b508cd578f48b684bd511
```

`=======` ke upar waala hissa aapka version hai; neeche waala aane waala version hai. File ko us version mein edit karo jo aapko chahiye, teenon marker lines delete karo, phir file ko `git add` karo aur Git ka message rakhne ke liye `git commit --no-edit` chalaao. Agar `git pull` "Need to specify how to reconcile divergent branches" kehkar ruk jaaye, to aap dono ne commits kiye hain; `git pull --no-rebase --no-edit` unhe merge kar deta hai. Branches waale aur team ke saath Git waale lessons ismein aur gehraai tak jaate hain.

## Ek example se samjho

Ravi ke paas ek folder hai jismein ek expense tracker, ek marks calculator aur ek weather fetcher hai jo `.env` se API key padhta hai. Ye raha uska asli session, output chhota karke. Aapke commit hashes (`81d3fe3` jaise chhote codes) alag honge.

**1. Tracking shuru karo, aur kuch bhi add karne se pehle dekho.**

```text
$ cd ~/python-practice
$ git init
Initialized empty Git repository in /home/ravi/python-practice/.git/
$ git status
On branch main

No commits yet

Untracked files:
	.env
	.venv/
	__pycache__/
	expenses.py
	marks.py
	weather.py
```

Khatra `.env` waali line hai: abhi ek `git add .` uski key commit kar dega.

**2. `.gitignore` banao aur phir se check karo.**

```text
$ printf '.venv/\n__pycache__/\n.env\n' > .gitignore
$ git status --short
?? .gitignore
?? expenses.py
?? marks.py
?? weather.py
```

`??` ka matlab untracked hai. `.env`, `.venv/` aur `__pycache__/` list se gaayab ho gaye hain, yahi saboot hai ki ignore file kaam kar rahi hai.

**3. Pehla commit: ek script, saath mein ignore file.**

```text
$ git add .gitignore expenses.py
$ git commit -m "Add expense tracker with category totals"
[main (root-commit) 81d3fe3] Add expense tracker with category totals
 2 files changed, 9 insertions(+)
```

**4. Bug fix, apne alag commit mein.** Uski CSV mein ek khaali amount se tracker crash ho gaya. Wo line theek karta hai, phir check karta hai ki usne theek-theek kya badla:

```text
$ git diff
-        totals[row["category"]] = totals.get(row["category"], 0) + float(row["amount"])
+        totals[row["category"]] = totals.get(row["category"], 0) + float(row["amount"] or 0)
$ git add expenses.py
$ git commit -m "Handle missing amounts in expense CSV"
```

**5. Baaki scripts aur ek README, har ek ka apna commit.** Uska README:

```markdown
# Python practice
Small scripts from my first month of learning Python.

- expenses.py: reads expenses.csv and prints total spending per category
- marks.py: turns a list of marks into grades
- weather.py: prints today's weather for a city; needs WEATHER_API_KEY in a .env file

Run any script with: python expenses.py
```

```text
$ git log --oneline
e2c538a Add README with usage examples
cf4559b Add weather fetcher that reads its key from .env
812980e Add marks calculator with grade bands
a7d7b78 Handle missing amounts in expense CSV
81d3fe3 Add expense tracker with category totals
```

**6. Push.** Wo GitHub par ek khaali repository banaata hai, apne Ubuntu laptop par ek baar `gh auth login` chalaata hai, phir:

```text
$ git remote add origin https://github.com/ravi-d/python-practice.git
$ git push -u origin main
To https://github.com/ravi-d/python-practice.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.
```

**7. Ek galti, undo ho gayi.** Ek hafte baad wo ek line jodta hai jo tracker ko crash kar deti hai. Kuch bhi commit karne se pehle:

```text
$ git status --short
 M expenses.py
$ git diff
+print(totals["food"])
$ git restore expenses.py
$ git status --short
```

`M` ka matlab modified hai. `git restore` ke baad `git status` kuch print nahi karta: file phir se uske aakhri commit se match karti hai.

**8. Aakhri check.** `git log --all --oneline -- .env` har us commit ki list deta hai jisne kabhi `.env` ko chhua ho. Ravi ke liye ye kuch print nahi karta, yaani uski key kabhi uski history mein thi hi nahi.

Ab jo bhi uski repository kholta hai, chaahe reviewer ho ya interviewer, ek minute mein teen cheezein dekhta hai: ek README jo batata hai ki har script kaise chalaani hai, chhote aur saaf naam waale steps ki history, aur koi `.env`, `.venv/` ya cache files nahi.

## Aam galtiyaan

- **Galat folder mein Git chalaana.** "fatal: not a git repository" ka matlab hai aap project ke baahar ho; apne home folder mein `git init` chalaaya to `git status` aapki har file ki list dikhaayega. Pehle `pwd` chalaao.
- **Push prompt par apna GitHub password type karna.** Ye reject ho jaata hai. Git Credential Manager, `gh auth login` ya personal access token use karo.
- **`.env` commit hone ke baad `.gitignore` jodna.** Tracked files par iska koi asar nahi hota. `git rm --cached .env` use karo, commit karo, aur key badal do.
- **`git status` padhe bina `git add .`.** Keys, `.venv/` aur badi data files aise hi commit hoti hain.
- **Nayi GitHub repository par "Add a README" tick karna** aur phir ek maujooda folder push karna. Push refuse ho jaata hai. Nayi repositories khaali banao.
- **Ek bada-sa commit, ya "update" jaise messages.** Har poora hua step commit karo, aur batao ki wo kya badalta hai.
- **Un edits par `git restore` jo aapko rakhne the.** Wo edits waapas nahi mil sakte. Pehle `git diff` check karo.
