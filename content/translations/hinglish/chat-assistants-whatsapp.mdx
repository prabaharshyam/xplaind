## Ye kya hai

Ek **chat assistant** website par chat window mein ya messaging app mein customers ke sawaalon ke jawab deta hai. Achhi tarah bana ho toh wo:

- aam knowledge ki jagah business ki apni information (FAQs, price lists, policies, timings) se jawab deta hai;
- business systems se connections ke zariye common tasks (order status, appointment booking) handle karta hai;
- jab madad na kar sake ya customer maange, tab **insaan ko hand-over karta hai**;
- privacy aur messaging platform ke rules ka maan rakhta hai.

WhatsApp par businesses **WhatsApp Business Platform** (API) use karte hain, aam taur par kisi provider ke zariye. Iske rules hain: customers ko opt in karna padta hai, 24-hour customer-service window ke bahar business-started messages ke liye pehle se approved templates chahiye, aur messages WhatsApp ke pricing model ke hisaab se charge hote hain.

```flow
WhatsApp par customer -> Provider webhook -> Assistant
Assistant -> Retrieval | FAQ sheet, price list
Assistant -> Tools | order status, booking, confirmation ke saath
Assistant -> Insaan ko hand-over | summary ke saath
Retrieval -> Customer ki language mein reply
Tools -> Customer ki language mein reply
```

Ye lesson Madurai ke ek multi-specialty clinic ke saath chalta hai, jiski reception par WhatsApp messages ki baadh aayi hui hai.

## Ye kaam kaise karta hai

**Knowledge.** Business ke FAQs, price list, policies aur timings ikattha karo. Unhe aise document ya sheet mein rakho jise business update kar sake. Retrieval use karo taaki jawab inhi sources se aayein, aur assistant ko kaho ki jab use na pata ho toh bata de.

**Actions.** Order status ya booking ke liye tools jodo: order number aur phone se order dekhna, slots check karna, booking banana. Act karne se pehle details customer ko wapas confirm karo.

**Hand-over.** Kisi bhi waqt "insaan se baat karo" option do. Complaints, payments disputes, medical ya legal sawaalon, gusse waale customers, ya do galat jawab ke baad apne aap hand-over karo. Conversation aur ek summary pass karo taaki insaan ko dobara na poochna pade, aur customer ko batao ki jawab kab milega.

**WhatsApp rules.**

- Business se messages paane ke liye customers ne opt in kiya hona chahiye.
- Customer ke aakhri message ke 24 ghante ke andar business freely reply kar sakta hai. Uske baad sirf approved template messages hi conversation shuru kar sakte hain.
- Kya bechna ya promote karna allowed hai, is par WhatsApp ki commerce aur business policies follow karo.

**Language aur tone.** Jahan ho sake customer ki language mein jawab do; Hindi, Tamil, Hinglish aur baaki languages jo aapke customers use karte hain, test karo. Messages chhote rakho; chat email nahi hai.

**Privacy.** Sirf wahi collect karo jo task ko chahiye; poore card numbers ya passwords mat maango; DPDP consent aur retention rules follow karo; logs mein personal data mask karo.

**Measure karo.** Bina insaan ke suljhi conversations ka share, hand-over rate aur reasons, customer ratings, aur galat-jawab reports.

**Assistant kya handle karta hai, aur kya kabhi nahi karta:**

| Request ka type | Assistant ka kaam | Example |
| --- | --- | --- |
| Information | Business ke sources se jawab dena | Timings, fees, doctor schedules |
| Simple actions | Tool use karna, act karne se pehle confirm karna | Appointment book karna, order status check karna |
| Sensitive ya complex | Summary ke saath hand-over | Complaints, refunds, disputes |
| Professional advice | Kabhi nahi; hand-over | Medical, legal, financial sawaal |
| Emergencies | Fixed safe message aur hand-over | "Hamare emergency number par call karein..." |

**Message costs.** WhatsApp businesses se apne pricing model ke hisaab se charge karta hai, jo message ke type aur desh par depend karta hai. Current pricing page dekho aur use client ke running-cost estimate mein jodo, us date ke saath jab aapne dekha.

**Code mein ek WhatsApp Cloud API webhook.** Meta aapka URL ek baar verify karne ke liye call karta hai, phir har incoming message post karta hai. Ek minimal FastAPI version; API version aur fields ke liye Meta ke current docs dekho:

```python
import hashlib, hmac, os
import httpx
from fastapi import FastAPI, Request, Response, BackgroundTasks, HTTPException

app = FastAPI()
VERIFY_TOKEN = os.environ["WA_VERIFY_TOKEN"]
APP_SECRET = os.environ["WA_APP_SECRET"].encode()
TOKEN, PHONE_ID = os.environ["WA_TOKEN"], os.environ["WA_PHONE_NUMBER_ID"]
SEEN = set()                                     # use Redis or a table in production

@app.get("/whatsapp")
def verify(request: Request):
    q = request.query_params
    if q.get("hub.mode") == "subscribe" and q.get("hub.verify_token") == VERIFY_TOKEN:
        return Response(q.get("hub.challenge"))
    raise HTTPException(status_code=403)

@app.post("/whatsapp")
async def receive(request: Request, tasks: BackgroundTasks):
    raw = await request.body()
    sig = request.headers.get("X-Hub-Signature-256", "")
    expected = "sha256=" + hmac.new(APP_SECRET, raw, hashlib.sha256).hexdigest()
    if not hmac.compare_digest(sig, expected):
        raise HTTPException(status_code=401)
    for entry in (await request.json()).get("entry", []):
        for change in entry.get("changes", []):
            for msg in change["value"].get("messages", []):
                if msg["id"] in SEEN:
                    continue                     # a repeat delivery
                SEEN.add(msg["id"])
                if msg.get("type") == "text":
                    tasks.add_task(handle, msg["from"], msg["text"]["body"])
    return {"ok": True}                          # reply fast; work happens in the background

async def handle(wa_id, text):
    answer = assistant_reply(wa_id, text)        # retrieval, tools and hand-over rules
    async with httpx.AsyncClient() as http:
        await http.post(f"https://graph.facebook.com/v21.0/{PHONE_ID}/messages",
                        headers={"Authorization": f"Bearer {TOKEN}"},
                        json={"messaging_product": "whatsapp", "to": wa_id,
                              "type": "text", "text": {"body": answer[:4000]}})
```

Webhook ko kuch seconds ke andar jawab do aur model call background mein karo, warna WhatsApp retry kar sakta hai aur aapko duplicates dikhenge.

**Hand-over rules sirf prompt mein nahi, code mein bhi.** Model ko call karne se pehle, message aur ab tak ki conversation se decide karo:

```python
HANDOVER_WORDS = {"complaint", "refund", "lawyer", "consumer court", "chargeback"}

def needs_person(text, state):
    t = text.lower()
    return (any(w in t for w in HANDOVER_WORDS)
            or state["failed_answers"] >= 2
            or state.get("asked_for_person"))
```

Jab ye true ho, us chat ke liye bot ko rok do, conversation aur summary staff inbox mein post karo, aur customer ko batao ki jawab kab milega.

**Code mein 24-hour window.** Har customer ke aakhri message ka time store karo. Bhejne se pehle check karo ki wo 24 ghante ke andar tha ya nahi; agar nahi, toh free text ki jagah approved template bhejo, ya bilkul mat bhejo.

**Grounded rehna.** Retrieval ke saath business ki apni sheet ya documents se jawab do, logs mein source daalo, aur jab kuch relevant na mile toh mana kar do: "Mere paas ye information nahi hai; maine team se reply karne ko kaha hai." WhatsApp par bheji gayi galat price ya timing ka screenshot liya jaata hai aur share hota hai.

## Ek example se samjho

Madurai ke ek multi-specialty clinic ko rozana sainkdon WhatsApp messages aate hain: timings, doctor availability, fees, lab report status, appointment booking.

Assistant, jo n8n mein WhatsApp Business Platform provider ke saath banaya gaya hai:

- timings, fees aur doctor schedules ke jawab ek sheet se deta hai jise reception staff roz update karta hai;
- clinic ke booking system ko check karke appointments book karta hai aur book karne se pehle naam, doctor, date aur time confirm karta hai;
- patients ko batata hai ki lab reports ready hain ya nahi (registered phone number verify karne ke baad), par results kabhi chat mein share nahi karta;
- symptoms, medical sawaalon ya emergencies par turant hand-over karta hai, ek fixed message ke saath jisme emergency number hota hai;
- patient ke hisaab se Tamil ya English mein reply karta hai.

Ek mahine baad, 68% conversations poori tarah handle ho jaati hain, reception ke phone calls ek tihai kam ho jaate hain, aur office hours ke baad ki bookings badh jaati hain. Ek doctor ke leave day ke baare mein do galat jawab schedule sheet update na hone ki wajah se nikle; clinic ek daily check jod deta hai.

| Ek mahine baad ka measure | Result |
| --- | --- |
| Assistant ne poori tarah handle ki hui conversations | 68% |
| Reception phone calls | Lagbhag ek tihai kam |
| Office hours ke baad ki bookings | Badhi |
| Mile galat jawab | 2, dono purani schedule sheet se |
| Fix | Daily check ki schedule sheet update hui ya nahi |

**Hand-over practice mein kaise kaam karta hai.** Jab koi patient likhta hai "mere pitaji ko chest pain hai", toh assistant medical madad karne ki koshish nahi karta. Wo ambulance aur clinic emergency numbers ke saath fixed emergency message bhejta hai, staff inbox mein conversation ko urgent flag karta hai, aur us patient ko din bhar ke liye apne aap reply karna band kar deta hai, taaki ek insaan charge mein rahe. Jab koi patient aise bill ke baare mein poochta hai jo use galat lagta hai, toh assistant bill number collect karta hai, kehta hai ki staff member do working hours mein reply karega, aur bill attach karke ek line ki summary pass karta hai. Reception staff ne kaha ki ye badlaav unhe sabse zyada pasand aaya: ab unhe samajhne ke liye ki patient kya chahta hai, lambi chat ko peeche scroll nahi karna padta.

## Aam galtiyaan

- **Aam knowledge se jawab dena.** Jawab business ki apni information mein grounded rakho.
- **Insaan tak pahunchne ka aasaan raasta na hona.** Pareshaan customers chhod jaate hain aur public mein shikayat karte hain.
- **Platform rules todna.** Bina maange bheje messages aur unapproved templates se numbers block ho jaate hain.
- **Medical, legal ya financial advice dena.** Hand-over karo.
- **Purani information.** Source update karna kisi ki daily routine ka hissa banao.

- **Lambe, email jaise replies.** Chat users phone par padhte hain; jawab kuch lines tak rakho aur "aur details chahiye?" poochho.
- **Knowledge sheet ka koi owner nahi.** Naam batao ki timings, prices aur leave days kaun update karta hai, aur kab.
- **Webhook par signature check chhod dena.**
- **Webhook ko jawab dene se pehle slow kaam karna**, jisse retries aur duplicate jawab hote hain.
- **24-hour window ke bahar free-text messages.** Wo fail hote hain ya policy todte hain; approved templates use karo.

## Jab chat assistant worth nahi hota

- **Rozana bahut kam messages**: saved quick replies ke saath ek insaan sasta aur zyada garmjoshi waala hota hai.
- **Zyadatar sawaalon ko judgement chahiye**, jaise custom quotes ya complaints.
- **Business apni information ko up to date nahi rakh sakta**: bot purani prices aur timings dohrayega.
- **Customers zyadatar call karte hain**, message nahi: voice assistant ya behtar IVR zyada fit ho sakta hai.

## Demo se production tak

- **Har incoming message ke signatures verify karo aur deduplicate karo.**
- **Knowledge sheet business ke paas rakho**, har entry par date ke saath aur weekly check ke saath.
- **Har conversation log karo**, sources, call kiye gaye tools, hand-overs aur ratings ke saath, masked.
- **Hand-over reasons har hafte dekho** aur sabse common jawab sheet mein jodo.
- **Messaging costs ka budget banao** current WhatsApp pricing se, us date ke saath jab aapne dekha.
