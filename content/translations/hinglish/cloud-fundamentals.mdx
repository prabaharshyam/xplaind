## Ye kya hai

Ek public cloud aapko computers, storage, networks aur ready-made services ghante ya use ke hisaab se kiraye par deta hai. Teen bade providers, AWS, Microsoft Azure aur Google Cloud, lagbhag ek jaise building blocks alag naamon se dete hain. Indian enterprises aksar group-wide choice follow karte hain; banks aur government se jude clients Indian regions ya kisi specific provider ka sovereign offering bhi maang sakte hain.

Aapko har service ki zaroorat nahi. Ek AI deployment lagbhag chhe tarah ki services use karta hai:

- **Compute**: jahan aapka code chalta hai.
- **Storage**: files aur documents.
- **Databases**: structured data, aksar pgvector ke saath PostgreSQL.
- **Networking**: private networks, load balancers, DNS.
- **Identity and access**: kaun kya kar sakta hai.
- **Managed AI**: cloud se hosted model APIs, jo data agreements ke liye matter kar sakti hain.

```flow
title: Ek Indian region mein, jaise Mumbai, ek virtual network ke andar ek app
Users | company SSO -> Load balancer | HTTPS, public subnet mein
Load balancer -> Serverless containers | app, private subnet mein, least-privilege role ke saath
Serverless containers -> Managed PostgreSQL
Serverless containers -> Object storage
Serverless containers -> Managed model API
```

Ye lesson Hyderabad ki ek pharma company ko follow karta hai jab aap Azure par uska document assistant design karte ho.

## Ye kaam kaise karta hai

**Regions aur zones.** Har region (India mein provider ke hisaab se Mumbai, Hyderabad, Pune, Delhi aur kuch aur) mein kai zones hote hain, alag data centres. Resilience ke liye instances ko zones mein failao. Region users tak latency, data residency rules aur wahan kaun se models milte hain, ye dekhkar chuno.

**Compute choices**, sabse zyada managed se sabse kam tak: serverless containers (Cloud Run, Azure Container Apps, ya AWS ECS on Fargate, ECS Express Mode ke saath; AWS App Runner naye customers ke liye band hai) jahan aap image dete ho aur URL milta hai; managed Kubernetes (EKS, AKS, GKE) jab client ki platform team ek chalati ho; virtual machines jab GPUs ya poora control chahiye. Zyadatar AI APIs ke liye serverless containers sabse tez safe start hain.

**Storage aur databases.** Documents ke liye object storage (S3, Blob Storage, Cloud Storage). Relational data aur vectors ke liye managed PostgreSQL. Managed services use karo: backups, patches aur failover andar hi aate hain.

**Networking.** Resources private subnets ke saath ek virtual network mein rehte hain. Databases ka koi public address nahi hona chahiye; aapka app unhe privately reach karta hai. Bahar ka traffic HTTPS ke saath load balancer se aata hai.

**Identity.** Long-lived access keys store karne ki jagah har service ko apni identity (role ya managed identity) do, sirf zaroori permissions ke saath. Log company ke single sign-on se sign in karte hain.

**Managed models.** Har cloud major models resell karta hai (Amazon Bedrock, Azure OpenAI ke saath Microsoft Foundry, Google Vertex AI). Clients aksar inhe pasand karte hain kyunki data unke maujooda cloud contract aur region ke andar rehta hai.

**Cost.** Compute, managed databases, bahar jaane waala data transfer aur model tokens zyadatar bill banate hain. Build karne se pehle provider ka pricing calculator use karo, aur pehle din hi budget alert set karo.

**Ek jaise building blocks, teen naam:**

| Building block | AWS | Azure | Google Cloud |
| --- | --- | --- | --- |
| Serverless containers | ECS on Fargate (Express Mode) | Container Apps | Cloud Run |
| Managed Kubernetes | EKS | AKS | GKE |
| Object storage | S3 | Blob Storage | Cloud Storage |
| Managed PostgreSQL | RDS, Aurora | Azure Database for PostgreSQL | Cloud SQL, AlloyDB |
| Service identity | IAM role | Managed identity | Service account |
| Secrets | Secrets Manager | Key Vault | Secret Manager |
| Managed models | Bedrock | Microsoft Foundry (Azure OpenAI) | Vertex AI |

Ek cloud achhe se seekho, phir aise table se translate karo.

**Indian region mein container deploy karna.** Google Cloud par ek command apni identity aur Secret Manager ke secrets ke saath ek private service deploy kar deta hai:

```bash
gcloud run deploy claims-api \
  --image asia-south1-docker.pkg.dev/my-project/apps/claims-api:3f9c2e1 \
  --region asia-south1 \
  --service-account claims-api@my-project.iam.gserviceaccount.com \
  --no-allow-unauthenticated \
  --set-secrets MODEL_API_KEY=model-api-key:latest,DATABASE_URL=db-url:latest \
  --min-instances 1 --max-instances 10 --cpu 1 --memory 1Gi
```

`--no-allow-unauthenticated` ka matlab hai ki sirf permission waale callers (load balancer, gateway ya uske through sign-in kiye hue users) use reach kar sakte hain. Traffic spike hone par `--max-instances` cost ko cap karta hai. AWS (ECS on Fargate) aur Azure (Container Apps) wahi ideas alag syntax mein lete hain: ek image, ek region, ek identity, reference se secrets, aur scaling limits.

**Pehle din hi budget alert.**

```bash
gcloud billing budgets create --billing-account=XXXXXX-XXXXXX-XXXXXX \
  --display-name="claims-pilot" --budget-amount=20000INR \
  --threshold-rule=percent=0.5 --threshold-rule=percent=0.9 --threshold-rule=percent=1.0
```

Har cloud mein iska equivalent hota hai. Alerts ko ek shared channel mein bhejo, kisi ek insaan ke inbox mein nahi.

**Apne cloud ke through models.** Client ke cloud ke through model call karne se traffic unke contract aur identity controls ke andar rehta hai. Anthropic ke SDK ke saath, Bedrock client wahi message shape use karta hai:

```python
from anthropic import AnthropicBedrock

client = AnthropicBedrock(aws_region="ap-south-1")      # uses the service's IAM role, not a key
reply = client.messages.create(
    model="<the model id shown in your Bedrock console>", max_tokens=300,
    messages=[{"role": "user", "content": "Summarise this claim note: ..."}])
```

Data residency ka promise karne se pehle check karo ki har Indian region mein kaun se models aur features milte hain; kuch dusri jagahon ke mukable Indian regions mein der se aate hain.

**Paisa kahan jaata hai.** Ek typical AI app mein model tokens aur managed databases sabse zyada hote hain, phir compute, phir cloud se bahar jaane waala data transfer. Har resource ko project aur environment se tag karo taaki bill baanta ja sake, aur pehle mahine mein har hafte cost breakdown dekho.

**Default roop se private.** Databases aur vector stores ko private networks par rakho, bina public address ke, jahan mile wahan private endpoints se model services reach karo, aur sirf load balancer ya gateway ko internet par expose karo.

**Browser mein try karo.** Build karne se pehle ek mahine ke cloud bill ka estimate lagao. Inputs apne hisaab se badlo.

```python
requests_per_day = 20_000
instance_rupees_per_hour = 6        # one small container instance; check current prices
instances = 2
db_rupees_per_month = 4_000
egress_gb, egress_rupees_per_gb = 50, 8

compute = instance_rupees_per_hour * 24 * 30 * instances
total = compute + db_rupees_per_month + egress_gb * egress_rupees_per_gb
print(f"compute ₹{compute:,}, total ₹{total:,} a month")
print(f"about ₹{total / (requests_per_day * 30):.3f} per request before model costs")
```

## Ek example se samjho

Azure par Hyderabad ki ek pharma company apni regulatory team ke liye document assistant chahti hai. Requirements: data India mein rahe, koi public database nahi, company accounts se sign-in.

Aapka design:

- **Region**: sab kuch ke liye Central India, ye check karne ke baad ki zaroori model company ke Azure AI agreement ke through wahan milta hai.
- **Compute**: Azure Container Apps jo aapka FastAPI image chalata hai, 1 se 5 instances tak scale hota hai.
- **Storage**: source PDFs ke liye Blob Storage; chunks ke liye pgvector ke saath Azure Database for PostgreSQL, sirf app ke private network se reach hota hai.
- **Identity**: app ek managed identity use karta hai jiske paas ek storage container aur database ka read access hai, koi stored keys nahi. Users Microsoft Entra ID se sign in karte hain.
- **Cost**: calculator model tokens se pehle lagbhag ₹55,000 mahina estimate karta hai, aur tokens ka alag se expected usage se estimate hota hai. Budget alert 80% par set hai.

Client ki cloud team ek hi review mein approve kar deti hai, mukhya roop se isliye ki har choice unke maujooda patterns se match karti hai.

| Monthly estimate ki line | Kya drive karta hai | Kaise kam karein |
| --- | --- | --- |
| Container Apps | Instances aur chalne ke ghante | Raat ko ek instance par scale karo |
| PostgreSQL | Instance size, storage | Chhota shuru karo; measure kiye load ke saath scale karo |
| Blob Storage | Store kiye gigabytes | Purane versions archive karo |
| Data transfer | Cloud se bahar jaata data | Traffic ko region ke andar rakho |
| Model tokens | Requests × tokens | Chhote prompts, caching, aasaan sawaalon ko chhote model par route karna |

**Review smooth kyun gaya.** Client ki cloud team zyadatar bahar ke designs ko inhi teen points par reject karti hai: public endpoints, stored keys aur India ke bahar ke regions. Aapke design ne teeno se bacha liya, aise services use ki jo unki team pehle se chalati thi, aur ek diagram ke saath aaya jo har network boundary dikhata tha. Unka akela badlaav resources ke liye ek naming convention tha.

## Aam galtiyaan

- **Teen clouds ko upar-upar seekhna.** Ek achhe se seekho; naam doosre mein translate karne mein ek din lagta hai.
- **Public databases.** Public address waala database sabse common serious cloud galti hai.
- **Code mein long-lived access keys.** Service identities aur short-lived credentials use karo.
- **Data transfer aur model costs ko ignore karna.** Wo compute se zyada ho sakte hain. Estimate karo.
- **Sirf latency ke liye region chunna.** Pehle residency rules aur model availability check karo.

- **Budget alert nahi.** Bhoola hua GPU machine ya bhaagta hua loop ek weekend mein lakhon ka kharcha kar sakta hai. Pehle din hi alerts set karo.
- **Services publicly reachable chhod dena** jabki unhe gateway ya load balancer ke peeche hona chahiye.
- **Maximum instance count nahi**, isliye traffic spike ya bug bill ko bina limit ke badha deta hai.
- **Bina tag ke resources**, isliye koi nahi bata sakta ki kaun sa project kitna kharch kar raha hai.

## Jab aapko kam cloud chahiye

- **Prototype ya demo**: Vercel, Render ya Railway jaisa platform aur ek hosted database tez hai.
- **Client sab kuch on-premises chalata hai**: unka platform seekho.
- **Server function mein API key waali ek single static site**: poora virtual network zarurat se zyada hai.

## Demo se production tak

- **Regions chuno** users, data residency aur model availability ke liye, aur likho ki kyun.
- **Service identities aur secret references use karo**, stored keys kabhi nahi.
- **Data services ko private rakho**, sirf gateway public.
- **Budgets aur maximum instances set karo** pehle din se.
- **Resources ko tag karo** project aur environment se, aur shuru mein har hafte costs review karo.
