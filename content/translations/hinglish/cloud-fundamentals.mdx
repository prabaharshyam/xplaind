## Ye kya hai

Public cloud aapko computers, storage, networks aur ready-made services kiraaye par deta hai, aur bill use ke hisaab se aata hai. AWS, Microsoft Azure aur Google Cloud lagbhag ek jaise building blocks alag naamon se dete hain. Enterprises aam taur par poore group ki ek choice follow karte hain, aur banks, insurers aur pharma companies aksar ye rules bhi jodte hain ki data kahan reh sakta hai.

Ye lesson Azure ko gehraai se dekhta hai, kyunki course ke resources Microsoft Learn paths hain. Har step ka doosre clouds par kareebi match hai, jo neeche ki table mein dikhaaya gaya hai.

Ek AI deployment lagbhag saat tarah ki services use karta hai:

- **Compute**: jahan aapka code chalta hai.
- **Storage**: files aur documents.
- **Databases**: structured data, aksar embeddings ke liye pgvector extension ke saath PostgreSQL.
- **Networking**: virtual networks, private endpoints, aur ek hi public entry point.
- **Identity and access**: kaun aur kya, kaun-se actions kar sakta hai.
- **Managed models**: hosted model APIs, jahan deployment type tay karta hai ki prompts kahan process honge.
- **Monitoring**: logs, metrics aur alerts, taaki aap dekh sako ki kya hua.

**Shared responsibility.** Provider buildings, hardware aur managed services ko secure karta hai. Jo aap configure karte ho wo aapki zimmedaari hai: aapka data, use kaun access kar sakta hai, kaun-se endpoints public hain, aur aap kitna kharch karte ho. "Cloud security basics" lesson ismein aur gehraai se jaata hai.

```flow
title: Central India mein, ek virtual network ke andar document assistant
Staff | Entra ID sign-in -> Application Gateway | akela public entry, HTTPS
Application Gateway -> Container Apps | internal-only environment, managed identity
Container Apps -[private endpoint]-> Blob Storage
Container Apps -[private access]-> PostgreSQL with pgvector
Container Apps -[secret reference]-> Key Vault
Container Apps -[private endpoint]-> Foundry model | regional Standard deployment
Container Apps -> Log Analytics
```

Ye lesson Hyderabad ki ek pharma company ko follow karta hai, jab aap Azure par uska document assistant design karte ho.

## Ye kaam kaise karta hai

### Regions aur zones

Region ek ilaake mein data centres ka ek group hai. Azure ke India mein chaar hain: Central India (Pune), South India (Chennai), West India (Mumbai) aur India South Central (Hyderabad), jo August 2026 mein launch hua. AWS ke Mumbai aur Hyderabad hain; Google Cloud ke Mumbai aur Delhi.

Kuch regions mein availability zones hote hain: alag data centres jinki apni power aur cooling hai, isliye zones mein faile replicas ek ke fail hone par bhi bache rehte hain. Har region mein zones ya har service nahi hoti, isliye jo bhi service use karni hai, uske liye Azure ka products-by-region page check karo.

Region is kram mein chuno:

1. **Residency**: client ki policy, contracts aur regulators kya maangte hain.
2. **Availability**: kya aapki saari services, aur sahi deployment type waala model, wahan milte hain?
3. **Latency**: users se doori. Chat app ke liye har Indian region kaafi paas hai.
4. **Price**: regions ke beech prices thode alag hote hain; ye sabse kam maayne rakhta hai.

Wajahein likhkar rakho; client ki cloud team poochhegi.

### Compute ke choices

| Aapko chahiye | Chuno | Kyun |
| --- | --- | --- |
| Container mein HTTP API (zyaadatar AI apps) | Container Apps | Replicas, scaling, HTTPS aur revisions built-in hain |
| Events ya timer se chalne waale chhote jobs | Container Apps jobs ya Azure Functions | Sirf job chalne tak pay karo |
| Client ke maujooda platform mein fit hona | AKS (managed Kubernetes) | Tabhi, jab unki platform team pehle se ise chalaati ho |
| GPUs ya machine ka poora control | Virtual machines | Patch aur scale aapko khud karna hoga |

Container Apps chal rahe replicas ke CPU aur memory ka bill karta hai. `--min-replicas 0` idle hone par zero tak scale kar deta hai, lekin kuch der shaanti ke baad aane waali pehli request ko cold start ka intezaar karna padta hai. Staff tool ke liye ek warm replica theek sauda hai.

### Storage aur databases

Documents ke liye Blob Storage aur records aur vectors ke liye Azure Database for PostgreSQL (flexible server) use karo; backups, patching aur failover built-in aate hain. Do details logon ko phansa deti hain:

- pgvector ko create karne se pehle allow-list karna padta hai: server parameter `azure.extensions` ko `vector` par set karo, phir `CREATE EXTENSION vector;` chalao. Extension ka naam `vector` hai, `pgvector` nahi.
- Server banaate samay hi **private access** (`--vnet` aur `--subnet`) chuno. Ye shuru mein hi tay karo: baad mein badalne ke liye downtime waala migration karna padta hai.

### Networking aur private endpoints

Sab kuch ek virtual network mein rehta hai. Container Apps environment ko apna subnet milta hai aur wo internal-only hota hai, isliye app ka koi public address nahi hota. Akela public entry ek Application Gateway hai, ya client ka maujooda gateway.

Blob Storage, Key Vault aur Foundry tak **private endpoints** se pahunchte hain: aapke network ke andar us service ka ek private IP address. Phir har service ka public network access band karo. Classic galti: endpoint maujood hai, lekin koi private DNS zone (jaise `privatelink.blob.core.windows.net`) network se link nahi hai. Name ab bhi public address par resolve hota hai, jise aapne abhi band kiya, aur har call fail hoti hai.

### Identity

App ko ek **managed identity** do: Azure use short-lived tokens deta hai, isliye store ya leak hone ke liye koi key nahi hoti. Use sabse chhote scope par roles do jis par kaam chal jaaye:

- **Storage Blob Data Reader** ek blob container par, poori subscription par nahi.
- **Key Vault Secrets User** ek vault par.
- **Cognitive Services OpenAI User** Foundry resource par.
- **AcrPull** container registry par.

Do gotchas. Owner aur Contributor jaise management roles aapko resource badalne dete hain, lekin apne token se uska data padhne nahi dete; uske liye data role chahiye. Aur role assignments ko laagu hone mein kuch minutes lag sakte hain, isliye grant karne ke turant baad aaya 403 apne aap theek ho sakta hai.

Log company ke Microsoft Entra ID se sign in karte hain, shared accounts se kabhi nahi.

### Managed models aur residency ka jaal

Microsoft Foundry (November 2025 mein Azure AI Foundry se naam badla gaya) client ke Azure contract ke tahat models host karta hai. Prompts kahan process honge, ye resource ka region nahi, **deployment type** tay karta hai:

| Deployment type | Prompts kahan process ho sakte hain | Kab use karein |
| --- | --- | --- |
| Global (Standard ya provisioned) | Kisi bhi Azure region mein jahan model chalta hai | Koi residency rule nahi; sabse zyaada quota chahiye |
| Data Zone | Microsoft ke tay kiye zone ke andar: US, EU ya Asia Pacific | Rule ek multi-country zone ki ijaazat deta hai |
| Standard ya provisioned, regional | Deployment ka apna region | Data ko India mein hi process hona hai |

Har type mein stored data resource ki geography mein hi rehta hai; jo badalta hai wo ye hai ki har request kahan process hoti hai. Central India resource par Global deployment bhi prompt ko videsh bhej sakta hai. Naye models aksar shuru mein sirf Global ke roop mein milte hain, isliye residency ka vaada karne se pehle region-availability table aur portal ka deployment dialog check karo. AWS mein bhi yahi switch hai: India inference profile (`in.` se shuru hone waale model IDs) sirf Mumbai aur Hyderabad ke beech route karta hai, jabki `global.` profile kahin bhi route kar sakta hai.

App apni managed identity se apna deployment call karta hai, isliye koi API key hai hi nahi:

```python
from azure.identity import DefaultAzureCredential, get_bearer_token_provider
from openai import OpenAI

token = get_bearer_token_provider(DefaultAzureCredential(), "https://ai.azure.com/.default")
client = OpenAI(base_url="https://docassist-ai.openai.azure.com/openai/v1/", api_key=token)
reply = client.chat.completions.create(
    model="docassist-chat",  # your deployment's name, not a model ID
    messages=[{"role": "user", "content": "Summarise this stability report: ..."}])
```

### Quotas

Model throughput ek quota se limited hota hai, tokens per minute mein, har model, region aur subscription ke hisaab se. Nayi subscription par GPU virtual machine quota aksar zero se shuru hota hai. Increases turant nahi milte aur mana bhi ho sakte hain, isliye quota pehle hafte mein request karo, launch waale hafte mein nahi.

### Command line se deploy karo

Ye commands wahi banaate hain jo diagram dikhaata hai; `$` variables mein pichhle steps ke IDs hain.

```bash
# 1. Create the identity first, so it can be granted access before the app exists.
az identity create -g rg-docassist -n id-docassist -l centralindia
ID=$(az identity show -g rg-docassist -n id-docassist --query id -o tsv)
PRINCIPAL=$(az identity show -g rg-docassist -n id-docassist --query principalId -o tsv)
CLIENT_ID=$(az identity show -g rg-docassist -n id-docassist --query clientId -o tsv)

# 2. Least privilege. Repeat for Key Vault Secrets User, AcrPull and Cognitive Services OpenAI User.
az role assignment create --assignee-object-id "$PRINCIPAL" --assignee-principal-type ServicePrincipal \
  --role "Storage Blob Data Reader" --scope "$STORAGE_ID/blobServices/default/containers/source-pdfs"

# 3. An internal-only environment on your own subnet, sending logs to Log Analytics.
az containerapp env create -g rg-docassist -n env-docassist -l centralindia \
  --infrastructure-subnet-resource-id "$APPS_SUBNET_ID" --internal-only true \
  --logs-destination log-analytics --logs-workspace-id "$WORKSPACE_GUID" --logs-workspace-key "$WORKSPACE_KEY"

# 4. The app: ingress reachable only inside the network, secrets by reference, a hard ceiling on replicas.
az containerapp create -g rg-docassist -n docassist-api --environment env-docassist \
  --image acrdocassist.azurecr.io/docassist-api:3f9c2e1 \
  --registry-server acrdocassist.azurecr.io --registry-identity "$ID" --user-assigned "$ID" \
  --secrets "db-url=keyvaultref:https://kv-docassist.vault.azure.net/secrets/db-url,identityref:$ID" \
  --env-vars DATABASE_URL=secretref:db-url AZURE_CLIENT_ID="$CLIENT_ID" \
  --ingress external --target-port 8000 --cpu 1 --memory 2Gi --min-replicas 1 --max-replicas 5
```

`AZURE_CLIENT_ID` batata hai ki `DefaultAzureCredential` kaun-si user-assigned identity use kare; iske bina token requests fail ho sakti hain. Compute kharch par asli cap `--max-replicas` hai.

### Logs, metrics aur cost

Container Apps console logs ko Log Analytics workspace mein bhejta hai. Request times aur errors ke liye Application Insights jodo, aur error rate aur slow responses par alert lagao. Logs ka bill har ingest hue gigabyte par lagta hai, isliye poore prompts ya documents log mat karo: ismein paise lagte hain aur sensitive data ki copy banti hai.

AI app ke bill mein aam taur par sabse aage model tokens hote hain, phir database, compute, logs aur cloud se bahar jaane waala data. Har resource ko project aur environment se tag karo taaki bill baanta ja sake. Pehle din hi alerts ke saath budget set karo:

```bash
az consumption budget create-with-rg -g rg-docassist -n docassist-pilot \
  --amount 125000 --category Cost --time-grain Monthly --time-period start-date=2026-12-01 \
  --notifications "{at80:{enabled:true,operator:GreaterThan,threshold:80,contact-emails:[cloud-alerts@example.com]}}"
```

Start date kisi mahine ki pehli taareekh honi chahiye, aur teen mahine se zyaada aage ki nahi. Amount subscription ki billing currency mein hota hai. Budget sirf alert karta hai: ye kuch bhi nahi rokta, aur cost data ghanton der se aa sakta hai. Alerts kisi shared mailbox ya channel par bhejo, kisi ek insaan ko nahi.

## Ek example se samjho

Azure par Hyderabad ki ek pharma company apni regulatory team ke liye document assistant chahti hai. Requirements: data India mein store aur process ho, koi public database nahi, company accounts se sign-in, aur roz lagbhag 1,500 sawaalon ka ek pilot.

**1. Region.** Hyderabad ka India South Central sabse paas hai, lekin wo August 2026 mein khula aur Microsoft dheere-dheere services jod raha hai. Maan lo products-by-region page dikhaata hai ki design ko jo chahiye wo sab Central India mein hai: aap use chunte ho aur Hyderabad ko baad ke liye note kar lete ho.

**2. Model.** Maan lo team ka pehli pasand waala model India mein sirf Global Standard ke roop mein milta hai. Wo processing rule mein fail hota hai. Maan lo ek doosra model Central India mein regional Standard ke roop mein milta hai aur team ke 40 test sawaalon mein pass hota hai: aap use deploy karte ho. Usi din uska tokens-per-minute quota request karte ho.

**3. Network aur identity.** Design diagram ko follow karta hai: company ke Application Gateway ke peechhe ek internal Container Apps environment; Blob Storage, Key Vault aur Foundry unke DNS zones ke saath private endpoints se; PostgreSQL private access ke saath. Ek user-assigned identity ke paas upar bataaye chaaron roles hain, har ek sabse chhote scope par.

**4. Cost.** Banaane se pehle andaaza lagao. Neeche ka har price samjhaane ke liye maana hua figure hai, quote nahi; jis din check karo, har ek ko apne region ke liye Azure pricing calculator ke number se badlo. Aap ise isi page par chala sakte ho.

```python
# Illustrative prices only. Replace each with the Azure pricing calculator's figure.
replica_rupees_per_hour = 8           # suppose: one replica, 1 vCPU and 2 GiB
replica_hours = (2 * 12 + 1 * 12) * 30  # 2 replicas by day, 1 at night
fixed = {"PostgreSQL": 12_000, "Blob, Key Vault, private endpoints": 3_000,
         "Log Analytics": 4_000, "Data transfer out": 500}

questions = 1_500 * 30                 # per month
input_tokens, output_tokens = 4_000, 500  # per question, with retrieved chunks
rupees_per_m_in, rupees_per_m_out = 250, 1_000  # suppose

compute = replica_rupees_per_hour * replica_hours
infra = compute + sum(fixed.values())
tokens = questions * (input_tokens * rupees_per_m_in + output_tokens * rupees_per_m_out) / 1e6
print(f"compute ₹{compute:,}  infrastructure ₹{infra:,}  tokens ₹{tokens:,.0f}")
print(f"total ₹{infra + tokens:,.0f} a month, ₹{(infra + tokens) / questions:.2f} per question")
```

Ye infrastructure ₹28,140 aur tokens ₹67,500 print karta hai: mahine ke ₹95,640, yaani har sawaal par ₹2.13. Tokens ka kharch poore infrastructure se bhi zyaada hai, isliye pehle unhe optimise karo.

| Line (samjhaane ke liye) | Mahine ka | Kisse badhta hai | Kaise kam karein |
| --- | --- | --- | --- |
| Model tokens | ₹67,500 | Sawaal × har sawaal ke tokens | Kam aur chhote retrieved chunks; dohraaye jaane waale answers cache karo |
| PostgreSQL | ₹12,000 | Server size aur storage | Chhota shuru karo; naape hue load par resize karo |
| Container Apps | ₹8,640 | Replica-hours | Raat mein ek replica; dev ke liye zero tak scale |
| Log Analytics | ₹4,000 | Ingest hue logs ke gigabytes | Prompts nahi, metadata log karo |
| Blob, Key Vault, endpoints | ₹3,000 | Stored data, har ghante ke endpoints | Puraane versions archive karo |
| Data transfer out | ₹500 | Azure se bahar jaane waala data | Traffic ko region ke andar rakho |

Client ko rupees mein bill hota hai, isliye budget mahine ka 1,25,000 hai, taaki uska 80% alert ₹95,640 ke andaaze se thoda upar aaye. `--max-replicas 5` aur har user ke liye ghante mein 60 sawaalon ki limit, budget ka email aane se bahut pehle bekaabu loop par cap laga dete hain.

**5. Review.** Cloud teams bahar ke designs ko aam taur par public endpoints, stored keys, videshi regions ya saaf na bataayi gayi model processing ki wajah se reject karti hain. Ye design chaaron se bachta hai, wahi services use karta hai jo wo pehle se chalaate hain, aur diagram aur region aur deployment type par ek page ke note ke saath aata hai. Unka akela badlaav unki naming convention hai.

## Aam galtiyaan

- **Teen clouds upar-upar se seekhna.** Ek ko theek se seekho, phir translate karo.
- **Model residency ke liye resource ke region par bharosa karna.** Global aur Data Zone deployments prompts ko India ke bahar process kar sakte hain. Deployment type check karo.
- **Public databases aur storage.** Private access aur private endpoints use karo, aur public network access band karo.
- **Private DNS zone ke bina private endpoint.** Name band public address par resolve hota hai aur har call fail hoti hai.
- **Code ya settings mein keys.** Ismein portal se copy ki gayi storage account keys bhi aati hain. Managed identities aur Key Vault references use karo, aur shared-key access band karo.
- **Data role ki jagah Owner ya Contributor**, ya "kaam chalaane ke liye" subscription scope par roles dena.
- **Budget ko cap samajhna.** Ye sirf alert karta hai. `--max-replicas` aur rate limits set karo.
- **Compute ginna lekin tokens aur logs nahi**, jo AI apps mein aksar badi lines hoti hain.
- **Launch waale hafte mein quota request karna.** Increases turant nahi milte.
- **Bina tag ke resources**, jisse koi nahi bata sakta ki kis project ka kitna kharch hai.

## Kab kam cloud se kaam chal jaata hai

- **Prototype ya demo**: Vercel, Render ya Railway jaisa platform aur ek hosted database zyaada tez hai. Asli data aane par move karo.
- **Client sab kuch on-premises chalaata hai**: uski jagah unka platform seekho.
- **Bina sensitive data waala chhota internal tool**: built-in sign-in waala ek Container App kaafi ho sakta hai; poora private network zaroorat se zyaada hai.

## Demo se production tak

- **Sab kuch code mein.** Repository mein Bicep ya Terraform, pull requests mein review hua; production mein portal se haath se koi badlaav nahi.
- **Alag environments.** Dev aur prod ke liye alag resource groups ya subscriptions, har ek ka apna budget.
- **Policy se guardrails.** Sirf Indian regions ki ijaazat dene waali Azure Policy residency laagu rakhti hai, chaahe koi galti kar de, aur ek aur policy public network access ko deny kar sakti hai.
- **Resilience.** Jahan region mein zone redundancy ho wahan use karo, database restore test karo, aur client ko chahiye toh disaster recovery ke liye doosra Indian region chuno.
- **Aise alerts jin par log action lein.** Error rate, slow responses, roz ka token use aur quota use, ek named owner waale shared channel par bheje gaye.
- **Ek design record.** Region, deployment type, network boundaries aur identities, har ek ki wajah ke saath, client ke review ke liye taiyaar.
