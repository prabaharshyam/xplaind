## Ye kya hai

**Incident** koi bhi aisi ghatna hai jo users ya business ko nuksaan pahunchaye aur jise turant respond karna pade. AI systems aam outages mein naye prakaar jodte hain:

- **Availability**: provider outage, rate limits, toota hua pipeline.
- **Cost**: bekaabu agents ya traffic spikes jo budget jalate hain.
- **Quality**: model, prompt ya document badalne ke baad achanak galat answers.
- **Safety aur security**: harmful content, prompt injection, data leakage, unauthorised actions.
- **Fairness aur compliance**: unfair outputs ka ek pattern, ya personal data ka galat istemaal.

**Incident response** inhein sambhalne ka planned tareeka hai: detect, assess, contain, fix, communicate aur learn.

```flow
dir: LR
Detect | alerts, complaints -> Assess | severity 1, 2 ya 3; roles ke naam tay
Assess -> Contain | kill switch, rollback, remove, document, humans sambhalte hain
Contain -> Investigate | traces, logs, release ids
Investigate -> Communicate | client, users, zaroorat par regulators
Communicate -> Learn | blameless review, owners ke saath actions, naye eval cases
Learn -[monitoring behtar hui]-> Detect
```

Is lesson mein hum Chennai ki ek e-commerce company mein ek Saturday ke incident ke saath chalenge, jahan support assistant ne galat returns window ka vaada kar diya.

## Ye kaam kaise karta hai

**Detect.** Errors, latency, cost, guardrail triggers, refusal rates, negative feedback aur online eval scores par alerts. Ek saaf channel se users aur staff ki reports. Kai AI incidents pehle kuch complaints ki tarah dikhte hain; unhein gambhirta se lo.

**Severity assess karo.** Levels pehle se define karo. Jaise: data leakage, customers ko harmful output ya unauthorised actions ke liye severity 1; kai jagah galat answers ya poore outage ke liye severity 2; ek area mein ghatti quality ke liye severity 3. Severity tay karti hai ki kise kab jagana hai.

**Roles.** Ek incident commander jo coordinate aur faisle karta hai, koi hands-on fix karne waala, aur koi stakeholders se communicate karne waala. Chhoti team mein ek insaan kai roles rakh sakta hai, lekin commander ka role saaf hona chahiye.

**Pehle contain karo.** Wajah dhoondhne se pehle nuksaan rokko: ek tool ya feature ka kill switch palto, pichhle release par rollback karo, index se ek document disable karo, humans ko route karo. Containment options aapko zaroorat padne se pehle maujood aur test hue hone chahiye.

**Records ke saath investigate karo.** Traces, audit logs aur release identifiers dikhate hain ki kya hua. Unhein sambhaal kar rakho.

**Communicate karo.** Clients aur users ko samay par, imaandaar updates chahiye. Regulated clients ki notification duties ho sakti hain, jaise DPDP Act ke tahat personal data breach reporting; unki privacy aur legal teams ko turant shaamil karo.

**Seekho.** Ek blameless post-incident review: timeline, impact, root causes (aksar kai), kya achha gaya, kya badalna hai, owners aur dates ke saath. Trigger karne waale cases ko eval suite aur monitoring mein jodo.

**Severity levels aur responses:**

| Level | Examples | Response |
| --- | --- | --- |
| 1 | Data leakage, customers ko harmful output, unauthorised actions | On-call aur leads ko turant page karo; minutes mein contain karo |
| 2 | Kai jagah galat answers, poora outage | 15 minute mein on-call; ghanton mein client ko soochit karo |
| 3 | Ek area mein ghatti quality | Agle kaam ke din; band hone tak track |

**Har incident type ke liye ek runbook page.** Har tarah ke incident ke liye ek page likho: kaise detect hota hai, pehle teen containment actions switches ke links ke saath, kise batana hai, aur zaroori traces aur logs kahan hain. Use itna chhota rakho ki pressure mein padha ja sake. Tabletop exercise mein page ko bilkul follow karo aur har us jagah ko note karo jo saaf nahi thi ya purani thi, phir usi hafte theek karo.

**Incident ke dauran client ko likhna.** Tay intervals par chhote, factual updates bhejo: kya ho raha hai, users ne kya dekha hoga, kya kiya gaya hai, aur agla update kab aayega. Shuruaati updates mein wajah ka andaaza mat lagao. "Humne galat answers rok diye hain aur confirm kar rahe hain ki kitne customers prabhavit hue" kehna ek aatmavishwas bhari explanation se zyada bharosa banata hai jo baad mein galat nikle.

**Sirf hard limits nahi, normal se drift pakdo.** Kai AI incidents mein koi rate chupchaap badal jaati hai. Pichhle ghante ko pichhle dino ke usi ghante se compare karo:

```python
from statistics import mean, pstdev

def anomalous(current, history, min_sigma=3.0, min_abs=0.02):
    """current: rate this hour; history: same-hour rates from the last 14 days."""
    mu, sd = mean(history), pstdev(history) or 0.005
    return (current - mu) / sd > min_sigma and current - mu > min_abs

# e.g. refusal rate, guardrail triggers, thumbs-down rate, judge failure rate
if anomalous(0.11, [0.03, 0.04, 0.03, 0.05, 0.04, 0.03, 0.04]):
    page_on_call("Refusal rate 11% vs about 4% normal for this hour")
```

**Kharaab document ko ek step mein contain karo.** "Assistant galat price bol raha hai" ka sabse tez fix aksar ek source hata dena hota hai:

```python
def quarantine_document(doc_id, index, cache, audit, reason, who):
    index.set_flag(doc_id, quarantined=True)        # every search filters quarantined docs
    purged = cache.delete_where(source_doc=doc_id)  # cached answers built from it
    audit.write(actor=who, action="quarantine", target=doc_id, detail={"reason": reason, "cache_purged": purged})
```

Ise ek admin button banao, launch se pehle test karo, aur runbook mein shaamil karo.

**Traces se impact naapo.** Customers aur regulators poochte hain "kitne logon ne dekha?". Agar traces retrieved document ids record karte hain, to jawab ek query hai:

```sql
SELECT count(DISTINCT user_id) AS users, count(*) AS answers,
       min(created_at) AS first_seen, max(created_at) AS last_seen
FROM traces
WHERE 'pricing-2026-11' = ANY(retrieved_doc_ids)
  AND created_at BETWEEN '2026-11-06 09:00+05:30' AND '2026-11-07 14:30+05:30';
```

Trace data ke bina ye dinon ka andaaza ban jaata hai, jo pehle din se retrieved ids log karne ka achha tark hai.

**India mein reporting duties.** Ek personal data breach DPDP Act aur uske Rules ke tahat Data Protection Board aur prabhavit logon ko notice duties trigger kar sakta hai. Alag se, CERT-In ke 2022 directions kai tarah ke cyber security incidents ko 6 ghante ke andar report karne ko kehte hain. Pehle se tay karo ki kaun faisla karega ki incident reportable hai ya nahi (aksar client ka legal ya privacy lead) aur unka contact runbook mein rakho.

**Practice karo.** Har quarter alag scenario ke saath ek tabletop exercise chalao: ek leak hua document, social media par jailbreak screenshot, ek provider outage, ek model update jo formatting tod de. Detection aur containment ka time naapo, aur jo bhi dheema kar raha tha use theek karo.

## Ek worked example

Saturday, subah 11:40. Chennai ki ek e-commerce company ka support assistant customers ko bata raha hai ki ₹5,000 se upar ke orders par 60 din ke andar free returns milenge. Policy kehti hai 15 din.

11:55: returns sawaalon par negative feedback teen guna ho jaata hai; ek alert aata hai. On-call engineer incident commander ban jaata hai aur severity 2 declare karta hai.

12:05: traces dikhate hain ki answers ek "Diwali returns campaign" page ko cite kar rahe hain jo marketing ne subah publish kiya tha, aur usmein sirf ek product category ke liye 60 din likha tha. Containment: page index se hata diya jaata hai aur assistant ke returns answers ek fixed, approved policy message par switch ho jaate hain.

12:20: customer support leads ko bataya jaata hai; woh prabhavit customers ke liye 60-din ka vaada nibhane ki taiyaari karte hain. Audit logs 312 conversations pehchaante hain; company un orders ke liye statement nibhane ka faisla karti hai.

Monday ki blameless review teen causes dhoondhti hai: indexing se pehle marketing pages ka review nahi, campaign pages par effective-date aur scope metadata nahi, aur returns par golden-set questions nahi. Actions: marketing pages ek review step ke saath alag index mein jaayenge, scope metadata jodi jaayegi, 20 returns questions golden set mein jodi jaayengi, aur policy-related answers mein achanak badlaav par ek alert.

| Time | Event |
| --- | --- |
| 11:40 | Assistant 60-din returns ka vaada karne lagta hai |
| 11:55 | Feedback alert; severity 2 declare |
| 12:05 | Campaign page index se hata; fixed policy message on |
| 12:20 | Support leads ko bataya; 312 conversations pehchaani aur nibhayi gayi |
| Monday | Blameless review: teen causes, owners ke saath chaar actions |

## Aam galtiyan

- **Contain karne se pehle investigate karna.** Pehle nuksaan rokko.
- **Bina test kiye kill switches aur rollbacks.** Unka practice karo.
- **Severity levels nahi.** Har incident ya to panic ban jaata hai ya ignore ho jaata hai.
- **Client ke saath chuppi.** Buri khabar waise bhi pahunchti hai; jaldi aur imaandari se batao.
- **Blame-focused reviews.** Log galtiyan chhupate hain aur system behtar nahi hota.
- **Traces mein retrieved ids nahi**, isliye impact naapa nahi ja sakta.
- **Containment tools jo sirf kaagaz par hain.** Launch se pehle har switch aur quarantine test karo.
- **Root cause ka intezaar karke client ko batana.** Jo facts aapke paas hain woh bhejo.

## Jab halki process kaafi ho

- **Chand users waale internal prototypes**: ek naam wala owner, ek kill switch aur ek chat channel kaafi ho sakte hain.
- **Public data par read-only tools**, jahan sabse bura case ek galat answer hai jise log check kar sakte hain.

Jab customers, personal data, paise ya regulated decisions shaamil hon, to poore severity levels, on-call rotas, runbooks aur drills chahiye.

## Demo se production tak

- **Rate changes par alert karo**: refusals, guardrail triggers, feedback aur judge failures par, sirf errors par nahi.
- **Containment ko ek click door rakho**: kill switches, rollback aur document quarantine, sab test kiye hue.
- **Retrieved ids, versions aur users log karo**, taaki impact jaldi naapa ja sake.
- **Runbook mein DPDP aur CERT-In duties ke liye reporting decision-maker ka naam likho.**
- **Har quarter drill karo** aur har baar sabse dheemi step theek karo.
