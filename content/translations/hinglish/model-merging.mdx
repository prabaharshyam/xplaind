## Ye kya hai

Fine-tuning ek model ko badalti hai. **Model merging** do ya zyada models ko unke weights milakar ek model mein jodti hai. Ye aam taur par tab sabse achha kaam karti hai jab models ek hi **base model** se fine-tune kiye gaye hon, taaki unke weights match karein.

Ye sab kyun?

- **Ek model mein kai skills.** Agar aapne ek model complaints ke liye aur doosra replies ke liye fine-tune kiya, toh ek merge dono kar sakta hai.
- **Tasks ko ek ke baad ek train karne se forgetting nahi.** Task A par train karke phir task B par train karne se model aksar A bhool jaata hai. Har ek ko alag train karke merge karne se ye nahi hota.
- **GPUs ki zaroorat nahi.** Simple merges weights par arithmetic hain aur ek aam computer par chalte hain.
- **Chhote deployments.** Kai ki jagah ek model, jo phones, laptops aur kam memory waale doosre devices par, ya jahan data device se bahar nahi jaana chahiye, wahan kaam aata hai.

Merging **ensemble** se alag hai. Ensemble kai models chalata hai aur unke answers milata hai, jisme har request par kai calls lagti hain. Merge weights ko ek baar milati hai; uske baad aap normal cost par ek hi model serve karte ho.

Merging abhi bhi nayi aur kuch had tak experimental hai. Open model leaderboards ki kai top entries merges rahi hain, par results badalte hain, isliye har merge ko ek naya model samjho jise test karna hai.

```flow
title: Fine-tuned models ko merge karna
Base model -> Task A ke liye fine-tune | adapter ya full
Base model -> Task B ke liye fine-tune
Task A ke liye fine-tune -> Task vector A | A - base
Task B ke liye fine-tune -> Task vector B | B - base
Task vector A -> Combine | average, SLERP, TIES, DARE
Task vector B -> Combine
Combine -> Merged model
Merged model -> Har task, general skills, safety test karo
```

## Ye kaam kaise karta hai

**Task vectors.** Fine-tuned model ke weights mein se base model ke weights ghata do toh aapko ek **task vector** milta hai: fine-tuning ne jo badlaav kiya. LoRA mein adapter khud hi lagbhag task vector hota hai. Task vectors ko base mein jodne se skills judti hain, aur ek ko ghataane se koi behaviour kam ho sakta hai, jise researchers ne anchaahi abilities ya biases ko kamzor karne ke liye use kiya hai.

**Linear combination.** Sabse simple merge weights ya task vectors ka ek weighted average hai. Ye hairaan karne waali had tak achha kaam karta hai, khaaskar ek hi base ke models ke liye. "Model soups" ne ek hi model ke kai fine-tuned versions ko average kiya aur bina extra running cost ke accuracy badhayi. Weights ek model ko doosre se zyada count karwane dete hain.

**SLERP.** Spherical linear interpolation do models ko seedhi line ki jagah ek mudi hui raah par blend karta hai, jo ek plain average se behtar har model ka character bacha sakta hai. 0 se 1 ke beech ka interpolation factor tay karta hai ki kaunsa model zyada count hoga. Ye ek baar mein do models merge karta hai; teesra merge karne ke liye dohrao.

**TIES aur DARE.** Fine-tuning lagbhag har weight badalti hai, par zyadatar badlaav bahut chhote hote hain aur kam jodte hain. Alag tasks ke wo chhote badlaav merge hone par takra sakte hain. Dono methods pehle har task vector ko **prune** karte hain, sirf important badlaav rakhkar:

- **TIES** sabse bade badlaav rakhta hai, phir merge se pehle un conflicts ko sulajhaata hai jahan tasks ek weight ko ulti disha mein dhakelte hain.
- **DARE** zyadatar badlaav random tareeke se hata deta hai aur baaki ko rescale karta hai taaki unka overall effect bana rahe.

Dono aksar plain averaging se saaf behtar merges dete hain, aur jitne zyada models merge karo, faayda utna badhta hai.

**Layer stacking.** Weights milane ki jagah, alag-alag models ki layers se ek model banao, jise kabhi "frankenmerge" kehte hain. Ye chhote models se bada model bana sakta hai (ek team ne 7B model ki do copies se 10.7B model banaya), aur ye maujooda model se mixture-of-experts model shuru karne ka ek tareeka hai. Inhe achha kaam karne ke liye aam taur par aur training chahiye.

**Concatenation** adapters ko side by side jodta hai. Ye saare parameters rakhta hai, isliye memory nahi bachata aur shaayad hi worth hai.

PEFT ke saath do LoRA adapters ko merge karna aisa dikhta hai:

```python
from peft import PeftModel
from transformers import AutoModelForCausalLM

base = AutoModelForCausalLM.from_pretrained("base-model-id")
model = PeftModel.from_pretrained(base, "adapters/complaints", adapter_name="complaints")
model.load_adapter("adapters/replies", adapter_name="replies")

# Combine into a new adapter; TIES keeps the strongest changes (density) and resolves conflicts.
model.add_weighted_adapter(
    adapters=["complaints", "replies"], weights=[1.0, 1.0],
    adapter_name="merged", combination_type="ties", density=0.3,
)
model.set_adapter("merged")
```

Poore models ke liye, open-source tool mergekit ek chhoti configuration file se merges chalata hai.

| Method | Kaise combine karta hai | Strengths | Kis cheez se bachna hai |
| --- | --- | --- | --- |
| Weighted average | Weights ya task vectors ka average | Simple, aksar achha | Tasks takra sakte hain |
| SLERP | Do models ko ek curve par blend karta hai | Do ka smooth blend | Ek baar mein do models |
| TIES | Bade badlaav rakhta hai, sign conflicts sulajhaata hai | Kai tasks ke saath behtar | Density setting tune karni padti hai |
| DARE | Zyadatar badlaav random hata kar rescale karta hai | Robust, lagana simple | Randomness; ek se zyada baar test karo |
| Layer stacking | Layers jodta hai, size badha sakta hai | Upscale ya MoE bana sakta hai | Aam taur par aur training chahiye |

**Apne browser mein try karo.** Do task vectors ka average lo, phir ek TIES-style merge try karo jo sirf bade badlaav rakhta hai.

```python
import numpy as np

rng = np.random.default_rng(7)
base = rng.normal(size=10)
task_a = np.where(rng.random(10) < 0.3, rng.normal(0, 1, 10), rng.normal(0, 0.05, 10))
task_b = np.where(rng.random(10) < 0.3, rng.normal(0, 1, 10), rng.normal(0, 0.05, 10))

average = base + (task_a + task_b) / 2
def trim(v, keep=0.3):
    cut = np.quantile(np.abs(v), 1 - keep)
    return np.where(np.abs(v) >= cut, v, 0)
ties = base + trim(task_a) + trim(task_b)
print("average change:", (average - base).round(2))
print("TIES change:   ", (ties - base).round(2))
```

## Ek example se samjho

Mumbai ke ek bank ke paas ek hi open 8B base model par teen LoRA adapters hain: complaint classification, English aur Hindi mein reply drafting, aur KYC field extraction. Woh branch laptops par bina internet ke ek model chahte hain.

Woh teen merges try karte hain aur har ek ko har task ke apne test set par test karte hain:

| Model | Complaint accuracy | Reply quality (reviewer score, 5 mein se) | KYC extraction accuracy |
| --- | --- | --- | --- |
| Alag adapters (target) | 93% | 4.3 | 96% |
| Teeno ka weighted average | 89% | 4.0 | 84% |
| TIES, density 0.3 | 92% | 4.2 | 88% |
| Complaints aur replies ka TIES; KYC alag | 92% | 4.2 | 96% |

Numbers illustration ke liye hain. Extraction, sabse precise task, har poore merge mein sabse zyada prabhavit hua. Team complaints aur replies ke liye ek merged model ship karti hai aur KYC adapter ko alag rakhti hai, jo sirf tab load hota hai jab koi document scan hota hai. Dono laptops par fit ho jaate hain. Woh apne safety aur refusal checks bhi dobara chalate hain, kyunki merging us behaviour ko kamzor kar sakti hai jis par kisi bhi adapter ko train nahi kiya gaya tha.

## Aam galtiyaan

- **Alag bases ke models ko merge karna**, risks samjhe bina. Results aam taur par kharab hote hain.
- **Sirf ek task test karna.** Ek merge chupchaap kisi doosre task ya general abilities ko nuksaan pahuncha sakta hai.
- **Safety checks chhodna.** Merge ke baad refusal aur safety behaviour kamzor ho sakta hai.
- **Leaderboard merges par aankh mundkar bharosa karna.** Kuch benchmarks ke liye tune hote hain; apne data par test karo.
- **Memory bachane ke liye concatenation use karna.** Ye nahi bachati.
- **Licence bhool jaana.** Merge har us model ki licence terms inherit karta hai jo usmein hai.

## Jab merge nahi karna

- **Jin tasks ko high precision chahiye** unhe alag adapters ki tarah rakhna behtar ho sakta hai.
- **Aap har task ke liye kaafi data ke saath ek achha multi-task fine-tune afford kar sakte ho.**
- **Kai adapters serve karna pehle se sasta hai**, kyunki kai servers use efficiently support karte hain.
- **Models alag base models se aate hain.**

## Demo se production tak

- **Merges ko models ki tarah version karo**: inputs, method, weights aur settings ek config file mein.
- **Alag adapters ko** fallback aur comparison ke liye rakho.
- **Har release se pehle har task, saath mein general aur safety checks test karo.**
- **Koi bhi input model badle toh dobara merge karo**, aur dobara test karo.
