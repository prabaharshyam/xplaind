## Ye kya hai

Ek **web API** aapke program ko internet par kisi doosri service se data ya actions maangne deta hai: air quality, map ka route, kisi payment ka status, sarkaari open data, ya kisi AI model ka jawaab. Har AI model provider tak isi tarah pahuncha jaata hai, isliye aage language models ko call karne ke peeche yahi core skill hai.

Aapka program ek URL par ek **HTTP request** bhejta hai. Service iske saath reply karti hai:

- ek **status code**, teen ankon ka ek number jo batata hai ki kaam hua ya nahin;
- aamtaur par **JSON** mein ek **body**, yaani objects (`{"key": value}`) aur lists (`[1, 2, 3]`) waala ek text format, jise Python dictionaries aur lists mein badal deta hai.

```flow
title: Ek API call, shuru se aakhir tak
dir: LR
Aapka code | session.get(url, params, timeout) -[GET, key X-API-Key header mein]-> API server
API server -[status code aur JSON body]-> Status check karo
Status check karo -[2xx]-> r.json() | dicts aur lists
Status check karo -[429 ya 5xx]-> Wait karo aur retry karo
Status check karo -[baaki 4xx]-> Request theek karo
```

Is lesson mein hum Delhi ki ek student, Anita, ke saath chalenge, jo ek chhota air-quality dashboard bana rahi hai. Wo **OpenAQ** use karti hai, ek non-profit platform jo duniya bhar se, Indian monitoring stations samet, air-quality readings ikattha karta hai. Iske API ke liye ek free key chahiye, isliye poora routine practise karne ke liye ye ek achhi jagah hai: key, timeout, status, JSON, retries aur pages.

## Ye kaam kaise karta hai

### Request ke hisse

Har API ki documentation requests ko inhi hisson mein batati hai:

| Hissa | Ye kya hai | `requests` mein | OpenAQ example |
| --- | --- | --- | --- |
| Base URL | Wo address jisse saari calls shuru hoti hain | URL ka hissa | `https://api.openaq.org/v3` |
| Endpoint | Ek tarah ke data ka path | URL ka hissa | `/locations/8118/latest` |
| Query parameters | URL mein `?` ke baad jode gaye filters | `params={...}` | `iso=IN`, `limit=100`, `page=2` |
| Headers | Metadata, key samet | `headers={...}` | `X-API-Key: your key` |
| Body | Aapka bheja hua data, aamtaur par POST ke saath | `json={...}` | data padhne ke liye zaroori nahin |

`params={"iso": "IN"}` URL par `?iso=IN` ban jaata hai; `requests` spaces aur special characters ko escape bhi karta hai. JSON body bhejne ke liye `json=` use karo (`data=` nahin): ye aapki dictionary ko convert karta hai aur sahi content type set karta hai.

### Aapki pehli call

```python
import os
import requests

BASE = "https://api.openaq.org/v3"
key = os.environ["OPENAQ_API_KEY"]

r = requests.get(f"{BASE}/locations/8118/latest",
                 headers={"X-API-Key": key}, timeout=(5, 20))
print(r.status_code)          # 200 if it worked
r.raise_for_status()          # stop here on any 4xx or 5xx
data = r.json()               # JSON text becomes dicts and lists
print(list(data))             # ['meta', 'results']
```

Location 8118 New Delhi ka ek station hai jise OpenAQ apne quick start mein khud use karta hai. Is chhote-se block mein pehle se teen aadatein hain:

- **Key ek environment variable se aati hai**, isliye wo code mein kabhi nahin dikhti.
- **Timeout hai.** `(5, 20)` ka matlab hai connect hone ke liye 5 seconds tak aur server ke data bhejne ke liye 20 seconds tak wait karo.
- **`raise_for_status()`, `r.json()` se pehle chalta hai.** Error reply data nahin hai, aur use data maanne se teen lines baad confusing failures aate hain.

### Status codes

Pehla ank batata hai ki problem kiski hai: **2xx** kaam ho gaya, **4xx** aapki request galat hai, **5xx** server fail hua.

| Code | Matlab | Kya karein | Retry? |
| --- | --- | --- | --- |
| `200` | OK | Data use karo | — |
| `400` | Bad request | Parameters aur body check karo | Nahin |
| `401` | Unauthorized: key nahin hai, galat hai ya expire ho gayi | Key aur wo header check karo jismein wo jaati hai | Nahin |
| `403` | Forbidden: key valid hai par iski permission nahin | Apna plan ya permissions check karo | Nahin |
| `404` | Not found | URL path aur item id check karo | Nahin |
| `422` | Unprocessable: request validation mein fail hui | Body mein error detail padho | Nahin |
| `429` | Too many requests | Wait karo, phir aur dheere retry karo | Haan |
| `500`, `502`, `503`, `504` | Server ya koi proxy fail hua | Wait karo, phir retry karo | Haan |

Yaad rakhne ka ek kaam ka tareeka: **401 poochta hai "Aap kaun ho?", 403 kehta hai "Mujhe pata hai aap kaun ho, aur jawaab hai na."** 401 ka fix key hai; 403 ka fix aapka account ya plan hai. Kai Python APIs, jinmein FastAPI framework se bane APIs bhi hain, koi field missing ho ya uska type galat ho to 422 return karte hain, aur body batati hai ki kaun-sa field.

### JSON padhna

Reply ko padhne waala code likhne se pehle, use ek baar achhe se format karke print karo:

```python
import json
print(json.dumps(data, indent=2)[:1500])
```

Latest-readings endpoint se aaye ek reply ko chhota karein to uska shape aisa hota hai (shape OpenAQ ki documentation ke hisaab se hai; values banaayi hui hain):

```json
{
  "meta": {"name": "openaq-api", "page": 1, "limit": 100, "found": 2},
  "results": [
    {"datetime": {"utc": "2026-11-28T05:00:00Z", "local": "2026-11-28T10:30:00+05:30"},
     "value": 182.0, "sensorsId": 1001, "locationsId": 8118,
     "coordinates": {"latitude": 28.63, "longitude": 77.2}},
    {"datetime": {"utc": "2026-11-28T05:00:00Z", "local": "2026-11-28T10:30:00+05:30"},
     "value": 301.0, "sensorsId": 1002, "locationsId": 8118,
     "coordinates": {"latitude": 28.63, "longitude": 77.2}}
  ]
}
```

Ise baahar se andar ki taraf padho. Curly braces ek dictionary hain, isliye aap string key use karte ho. Square brackets ek list hain, isliye aap 0 se ginti karke ek number use karte ho.

```python
data["results"][0]["value"]               # 182.0
data["results"][0]["datetime"]["local"]   # '2026-11-28T10:30:00+05:30'
[row["value"] for row in data["results"]] # [182.0, 301.0]
```

Jo do errors aapko sabse zyada dikhenge, unmein se har ek kisi ek galti ki taraf ishaara karta hai:

- `TypeError: list indices must be integers or slices, not str` ka matlab hai aapne list par string key lagaayi. Jaise, `data["results"]["value"]` fail hota hai kyunki `results` ek list hai. Koi item chuno (`[0]`) ya loop karo.
- `KeyError: 'value'` ka matlab hai us dictionary mein aisi koi key nahin hai. Spelling check karo, ya phir wo field optional hai.

Optional fields ke liye, key **missing** ho to `row.get("value", 0)` `0` return karta hai. Par kai APIs key ko `null` ke saath bhejte hain, jise Python `None` padhta hai, aur tab `.get` aapka default nahin, `None` return karta hai. Dono cases cover karne ke liye `row.get("value") or 0` likho. Dhyaan rahe: `or` ek asli `0` ko bhi replace kar deta hai, isliye jin numbers mein zero ka matlab hota hai, wahaan iski jagah `is None` test karo.

### Jab body JSON na ho

Jab body JSON nahin hoti to `r.json()` `requests.JSONDecodeError` raise karta hai, aur aisa aapki ummeed se zyada hota hai. `502` ya `503` aksar API ke aage lage kisi proxy ya load balancer se aata hai, aur uski body ek HTML error page hoti hai. Kuch services `200` ke saath HTML maintenance page return karti hain. Decoding fail ho to `r.text` ke pehle 200 characters print karo taaki dikhe kya aaya; worked example ka helper yahi karta hai.

### Timeouts

Default mein `requests` ka koi timeout nahin hota, isliye kabhi jawaab na dene waale server ko ki gayi call hamesha wait kar sakti hai aur nightly job ko freeze kar sakti hai. Hamesha `timeout=` do. `timeout=10` jaisa ek single number dono limits set karta hai. `(5, 20)` jaisa pair **connect** limit (server tak pahunchna) aur **read** limit (data ka wait karna) alag-alag set karta hai.

Ek gotcha: read limit agle data ke tukde ke liye sabse lamba wait hai, poore download ki limit nahin. Jo server har kuch seconds mein thoda-sa data bhejta rahe, wo ek call ko 20 seconds se kahin zyada der tak zinda rakh sakta hai. Jab timeout sach mein fire hota hai, to `requests` `requests.Timeout` raise karta hai; use catch karo aur retry karo ya saaf-saaf report karo.

### Keys aur secrets

Jo code aap share ya commit karte ho usmein API keys kabhi mat likho. Key apne terminal mein set karo (Linux ya macOS par `export OPENAQ_API_KEY=...`; Windows PowerShell mein `$env:OPENAQ_API_KEY="..."`) aur use `os.environ["OPENAQ_API_KEY"]` se padho.

Agar wo line `KeyError: 'OPENAQ_API_KEY'` raise kare, to koi request bheji hi nahin gayi: variable **is** terminal mein set nahin hai. Naya terminal wo variable yaad nahin rakhta jo aapne kisi doosre terminal mein set kiya tha. Iske ulat, `401` ka matlab hai request gayi aur server ne key reject kar di ya use dhoondh nahin paaya. Do aur rules: key ko kabhi print ya log mat karo, aur agar wo kabhi kisi public repository mein pahunch jaaye, to turant nayi key banao aur puraani delete karo.

### Surakshit tareeke se retry karna

Kuch failures kuch seconds baad khud theek ho jaate hain: timeouts, toote connections, `429` aur `5xx`. Baaki kabhi theek nahin honge: `401` ya `404` ko bina kuch badle retry karne se bas wahi galti dohraayi jaati hai. Ek achha retry:

- sirf un failures ko retry karta hai jinke temporary hone ki sambhavna zyada hai;
- har baar zyada der wait karta hai (**exponential backoff**: 1, 2, 4 seconds), aur server `Retry-After` header bheje to uska paalan karta hai;
- kuch tries ke baad haar maankar ek saaf error raise karta hai, error reply ke saath aage nahin badhta.

**GETs ko khulkar retry karo, par POST ko retry karne se pehle socho.** GET sirf padhta hai, isliye use dohraane mein koi nuksaan nahin. POST aksar kuch *banaata* hai: ek payment, ek order, ek message. Agar pehli attempt server tak pahunch gayi par reply waapas aate hue kho gaya, to bina soche kiya gaya retry use do baar bana deta hai. Stripe jaise payment APIs ise ek **idempotency key** se hal karte hain: ek unique id jo aap ek baar banaate ho aur usi request ke har retry ke saath header mein bhejte ho, taaki server ko pata chale ki ye repeat hai.

```python
import uuid

key = str(uuid.uuid4())                       # make it once, before the first try
headers = {"Idempotency-Key": key}            # send the same key on every retry
```

Agar koi API aisi key nahin deta, to uski POSTs ko auto-retry mat karo; dobaara try karne se pehle check karo ki pehli waali kaam kar gayi ya nahin.

### Pagination

List endpoint shaayad hi kabhi sab kuch ek saath return karta hai. Wo ek baar mein ek **page** return karta hai, aur aap agla maangte ho. OpenAQ `page` aur `limit` parameters use karta hai (default `limit` 100 hai) aur total `meta.found` mein batata hai. Doosre APIs iski jagah ek `next` URL ya cursor return karte hain; documentation batati hai kaun-sa.

Chupchaap hone waala failure hai sirf page 1 padhna. Code chalta hai, 100 results dikhaata hai aur sahi lagta hai. Agar koi count 100 ya 1000 jaise round number mein aaye, to sabse pehle pagination par shak karo.

Apni loop condition ke liye total par bharosa mat karo. Bade sets ke liye OpenAQ ka `found` `">1000"` jaisi string ho sakta hai, jisse arithmetic toot jaata hai. Iski jagah, jab koi page `limit` se chhota ya khaali aaye tab ruko, aur safety net ke taur par pages ki ginti par cap lagao (neeche `get_all` dekho).

### Limits aur cost

Zyaadatar APIs prati minute ya prati din requests limit karte hain, aur paid APIs, language-model APIs samet, use ke paise lete hain. Kai APIs aise headers bhejte hain jo batate hain ki aap kahaan khade ho; OpenAQ `x-ratelimit-remaining` aur `x-ratelimit-reset` bhejta hai, aur limit paar karne par `429` return karta hai. 500 cities par loop karne se pehle documentation ka limits page padho, calls ke beech ek chhota `time.sleep` jodo, aur jo results dobaara use karoge unhein phir se fetch karne ki jagah cache karo.

### API documentation padhna

Code likhne se pehle documentation mein ye dhoondho: **base URL**, **authenticate** kaise karna hai, **endpoints** aur unke **parameters**, ek **example response**, **error codes**, **pagination** aur **rate limits**. Example response ko ek file mein save kar lo taaki har baar API call kiye bina apni parsing test kar sako. Aage AI model ko call karna bhi yahi routine hai.

## Ek example se samjho

Anita ko do cheezein chahiye: har us Indian station ki list jo OpenAQ ko pata hai, aur Delhi ke ek station ki latest readings. Wo ek chhota helper banaati hai jisse hokar har call jaati hai, taaki timeout, retries, logging aur error checks ek hi jagah rahein.

```python
import logging
import os
import time

import requests

logging.basicConfig(level=logging.INFO)
log = logging.getLogger("aq")

BASE = "https://api.openaq.org/v3"
RETRYABLE = {429, 500, 502, 503, 504}

session = requests.Session()                      # reuses connections
session.headers["X-API-Key"] = os.environ["OPENAQ_API_KEY"]

def get_json(path, params=None, tries=4):
    for attempt in range(tries):
        last = attempt == tries - 1
        wait = 2 ** attempt                       # 1, 2, 4 seconds
        try:
            r = session.get(BASE + path, params=params, timeout=(5, 20))
        except (requests.Timeout, requests.ConnectionError) as e:
            log.warning("%s: %s (try %d)", path, type(e).__name__, attempt + 1)
            if last:
                raise
            time.sleep(wait)
            continue
        if r.status_code in RETRYABLE and not last:
            ra = r.headers.get("Retry-After", "")
            wait = int(ra) if ra.isdigit() else wait
            log.warning("%s: %d, retry in %ds", path, r.status_code, wait)
            time.sleep(min(wait, 60))
            continue
        r.raise_for_status()                      # 4xx, or still failing
        try:
            return r.json()
        except requests.JSONDecodeError:
            raise RuntimeError(f"not JSON: {r.text[:200]!r}") from None
```

Har hissa kyun hai:

- **`Session`** connection ko reuse karta hai, jo bahut saari calls ke liye zyada tez hai, aur key waala header rakhta hai taaki koi call use bhoole nahin.
- **Timeouts aur connection errors catch karke retry kiye jaate hain**, kyunki yahi sabse aam temporary failure hain. Aakhiri try par error raise hota hai, chhipaaya nahin jaata.
- **Aakhiri try ke baad koi sleep nahin**, aur wait 60 seconds par cap hai, taaki koi ajeeb `Retry-After` value job ko ek ghante tak na rok de.
- **Jo reply retry nahin hota, us har reply par `raise_for_status()` chalta hai**, taaki `401`, `404`, ya kabhi theek na hua `503` program ko ek saaf message ke saath rok de.
- **Har failure path aur status ke saath log hota hai**, jo aapko tab chahiye jab koi nightly job raat 3 baje fail ho.

Phir dono tasks:

```python
def get_all(path, params, limit=100, max_pages=50):
    rows = []
    for page in range(1, max_pages + 1):
        data = get_json(path, {**params, "limit": limit, "page": page})
        batch = data["results"]
        rows.extend(batch)
        if len(batch) < limit:                    # short or empty page
            break
    return rows

stations = get_all("/locations", {"iso": "IN"})
print(len(stations), "stations")
for s in stations[:3]:
    print(s["id"], s["name"])

latest = get_json("/locations/8118/latest")
for row in latest["results"]:
    print(row["sensorsId"], row["value"], row["datetime"]["local"])
```

Har `sensorsId` station ka ek instrument hai, jaise uska PM2.5 ya NO2 sensor. Ek alag endpoint, `/locations/8118/sensors`, batata hai ki har ek kaun-sa pollutant measure karta hai. Aise do endpoints ko jodna API ka aam kaam hai.

Uske pehle runs aise gaye:

| Run | Use kya dikha | Wajah | Fix |
| --- | --- | --- | --- |
| 1 | `KeyError: 'OPENAQ_API_KEY'`, koi request nahin gayi | Usne naya terminal khola tha aur wahaan variable set nahin tha | Us terminal mein variable set kiya, phir dobaara chalaaya |
| 2 | `401 Client Error: Unauthorized` | Usne kisi doosre API ke tutorial se `Authorization: Bearer ...` copy kiya tha | Key ko `X-API-Key` mein bheja, jaisa OpenAQ ke docs kehte hain |
| 3 | `TypeError: list indices must be integers or slices, not str` | Usne `latest["results"]["value"]` likha; `results` ek list hai | Shape print kiya, phir list par loop kiya |
| 4 | Poore India ke liye theek 100 stations | Usne `/locations` ko ek baar call kiya aur sirf page 1 padha | Pages par loop karne ke liye `get_all` likha |
| 5 | Ek log line `429, retry in 1s`, phir poori list | Tezi se paging karne par rate limit lag gayi | Kuch nahin: helper ne wait kiya aur aage badh gaya |

Runs 1 se 3 mein har ek ne alag error type diya, aur har type seedhe apni wajah ki taraf ishaara karta tha. Code dobaara padhne se pehle error ka pehla shabd padho.

Jab script badi ho jaaye, to retry ka kaam us library ko de sakte ho jis par `requests` bana hai. Ye ek aam production setup hai:

```python
import requests
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

retry = Retry(total=4, backoff_factor=1,
              status_forcelist=[429, 500, 502, 503, 504],
              allowed_methods=["GET"])        # never auto-retry POST
session = requests.Session()
session.mount("https://", HTTPAdapter(max_retries=retry))
```

Ye back off karta hai, 429 aur 503 par `Retry-After` ka paalan karta hai, aur connection errors aapke liye retry karta hai. Jab kisi listed status par tries khatam ho jaayein, to ye aakhiri reply return karne ki jagah `requests.exceptions.RetryError` raise karta hai, isliye use bhi catch karo. Har call par timeout, ek JSON check aur ek page loop aapko ab bhi chahiye.

## Aam galtiyaan

- **Status check karne se pehle data padhna.** Tab error reply kuch lines baad confusing tareeke se fail hota hai. Pehle `raise_for_status()` call karo.
- **Koi timeout nahin.** Ek chup server poora program hang kar deta hai.
- **JSON ka shape andaaze se maanna.** Ek baar `json.dumps(data, indent=2)` se print karo, phir access path likho.
- **List par string key.** Yahi upar waala `TypeError` hai; koi index chuno ya loop karo.
- **`null` values ke saath `.get(key, default)` par bharosa karna.** Key `null` ke saath maujood ho to ye `None` return karta hai.
- **Sirf page 1 padhna.** 100 jaisa round count khatre ka nishaan hai.
- **Sab kuch retry karna, ya bahut tezi se karna.** `401` ya `404` ko retry karne se calls barbaad hoti hain, tight loop aapko block karwa deta hai, aur idempotency key ke bina POST retry karne se customer se do baar paise kat sakte hain.
- **Code, screenshots ya logs mein keys.** Environment variables use karo, aur key leak ho to turant badal do.

## Practice karo

Neeche linked requests library ka quickstart padho, phir inmein se koi ek asli API use karo (dono November 2026 tak check kiye gaye):

- **OpenAQ**: Indian shehron ka air-quality data. Iske liye iski website se ek free key chahiye, jo `X-API-Key` header mein bheji jaati hai.
- **Open-Meteo**: weather aur air-quality forecasts. Ise key nahin chahiye aur non-commercial use ke liye free hai, isliye pehli call ke liye ye sabse tez raasta hai.

1. **Call karo aur dekho.** Ek endpoint call karo, reply ko `json.dumps(data, indent=2)` se print karo, aur teen values ke access paths likho, jinmein se kam se kam ek kisi list ke andar ho.
2. **Jaan-boojhkar fail karwao.** Galat key, galat path aur `timeout=0.001` bhejo. Har ek ka exact error note karo, aur check karo ki aapka code `r.json()` par crash hone ki jagah ek saaf message print karta hai.
3. **Helper jodo.** Har call ke aage `get_json` helper lagao aur confirm karo ki wo log aur retry karta hai.
4. **Har page padho.** Kisi list endpoint ke liye page cap ke saath saare pages fetch karo, aur apna count sirf page 1 waale count se compare karo.
5. **Key secure karo.** Use environment variable mein le jaao, naya terminal kholo aur confirm karo ki aapko pata hai ki uske set na hone par kya hota hai.

**Aapka kaam poora hai jab aap** key aur timeout ke saath API call kar sako, sirf error dekhkar bata sako ki failure aapka hai ya server ka, nested JSON bina andaaze ke padh sako, har page fetch kar sako, aur samjha sako ki aap kaun-se failures retry karte ho aur kyun.
