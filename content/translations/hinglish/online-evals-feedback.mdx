## Ye kya hai

**Offline evals** ship karne se pehle ek fixed golden set test karte hain. **Online evals** ship karne ke baad real traffic par jo hota hai use score karte hain. Dono chahiye: offline evals jaane-pehchaane regressions rokte hain; online evals anjaane regressions dhoondhte hain.

Online signals chaar tarah ke hote hain:

- **Automatic checks** har response par: valid format, citations hain ya nahi, refusal hai ya nahi, length, latency, guardrail triggers.
- **Model-graded scores** ek sample par: sources ke prati faithfulness, relevance, tone, jo ek judge model score karta hai jise aapne human grades se check kiya ho.
- **User feedback**: thumbs up ya down, ek reason, unhone answer copy kiya, dobara poochha ya kisi insaan ko escalate kiya.
- **Human review**: ek expert har hafte ek sample padhta hai aur label karta hai ki kya galat hua.

```flow
Live request -[intezaar nahi]-> User ko answer
Live request -> Trace store hota hai
Trace store hota hai -> Har trace par rules | format, citations, refusal, length, latency
Trace store hota hai -> 10% sample + saare negative feedback par judge | faithfulness, relevance
Trace store hota hai -> User feedback | thumbs aur reason, dobara likha sawaal, escalation
Trace store hota hai -> Weekly human review | 50 traces wajah ke hisaab se label
Har trace par rules -> Din, version, topic, language ke hisaab se dashboard
10% sample + saare negative feedback par judge -> Din, version, topic, language ke hisaab se dashboard
User feedback -> Din, version, topic, language ke hisaab se dashboard
Weekly human review -> Din, version, topic, language ke hisaab se dashboard
Din, version, topic, language ke hisaab se dashboard -[achanak badlaav par alerts]-> Sabse badi wajah fix karo -> Offline golden set mein cases jodo
```

Ye lesson Chennai ke ek telecom ke customer assistant ke saath chalta hai, jiska negative feedback launch ke chhe hafte baad lagbhag double ho gaya.

## Ye kaam kaise karta hai

**Asynchronously score karo.** Response user ko chale jaane ke baad, traces se checks aur judges chalao, taaki latency na badhe.

**Samajhdaari se sample karo.** Sab traces ko rules se sasta score karo; judge ko random 5 se 10% par chalao, saath mein negative feedback waala har trace ya guardrail trigger waala har trace.

**Feedback ko aasaan aur specific banao.** Thumbs down ke baad teen quick reasons ("wrong", "incomplete", "not what I asked") sirf thumbs down se kaafi zyada dete hain. Implicit signals bhi madad karte hain: ek minute ke andar dobara likha gaya sawaal aksar matlab hota hai ki pehla answer chook gaya.

**Trends dekho, ek number nahi.** Din aur version ke hisaab se dashboards: faithfulness, refusal rate, negative feedback rate, escalations. Achanak badlaav par alert lagao, jaise document upload ke baad refusal rate double ho jaana, ya provider ke model update ke baad faithfulness gir jaana.

**Loop band karo.** Har hafte: sabse kam score waale aur negative rating waale traces padho, unhe wajah se group karo (retrieval miss, stale document, prompt gap, out-of-scope sawaal), sabse bade group ko fix karo, aur representative cases offline golden set mein jodo taaki fix theek rahe.

**Judge ko check karo.** Judge model ki apni galtiyaan hoti hain. Har kuch hafte mein ek insaan se 50 judged samples grade karwao aur agreement check karo. Agar agreement gire, toh uske numbers par bharosa karne se pehle judge prompt theek karo.

**Signals aur woh kya pakadte hain:**

| Signal | Cost | Kya pakadta hai |
| --- | --- | --- |
| Har trace par rule checks | Lagbhag free | Toote formats, missing citations, slow responses |
| Topic ke hisaab se refusal rate | Free | Missing documents, over-strict prompts |
| Sample par judge | Model calls | Unfaithful ya irrelevant answers |
| Thumbs aur reasons | Free | Users ko asal mein kya pasand nahi |
| Ek minute ke andar rephrase | Free | Jo answers sawaal chook gaye |
| Weekly human review | Staff time | Wajah jo koi automatic signal nahi batata |

**Weekly review chalana.** 50 traces nikalo: judge score mein sabse bure 20, negative feedback waale 20, aur random 10. Har ek ke liye chhoti list se ek wajah label likho: retrieval miss, stale ya missing document, prompt gap, out of scope, model error, ya fine. Labels gino. Sabse bada group agle hafte ka fix hai. Counts ko hafte-dar-hafte rakho, taaki aap aur client dekh sakein ki fixes aane par wajahein kaise ghat rahi hain.

**Client ko batana.** Sirf offline score nahi, online dashboard aur weekly cause counts bhi share karo. Clients us team par kahin zyada bharosa karte hain jo problem pakadti hai, samjhati hai aur fix hua dikhati hai, bajaye us team ke jo sirf ek high launch number report karti hai.

**Deterministic sampling.** Judge ke liye traces trace id ko hash karke chuno, taaki wahi trace hamesha sample mein ho ya bahar, aur reruns aur dashboards ek jaise rahein:

```python
import hashlib

def in_sample(trace_id, rate=0.08):
    h = int(hashlib.sha256(trace_id.encode()).hexdigest()[:8], 16)
    return h / 0xFFFFFFFF < rate

def should_judge(trace):
    return (in_sample(trace["id"])
            or trace.get("feedback") == "down"
            or trace.get("guardrail_triggered")
            or trace.get("stop_reason") == "max_tokens")
```

**Conversation se implicit signals.** Log thumbs down kam hi dabate hain, par unka behaviour bahut kuch kehta hai. Poori ho chuki conversations par chalne waala ek chhota detector:

```python
from difflib import SequenceMatcher

def implicit_signals(turns):
    """turns: list of {"role", "text", "at" (seconds), "stopped_early", "regenerated"}."""
    flags = []
    users = [t for t in turns if t["role"] == "user"]
    for a, b in zip(users, users[1:]):
        similar = SequenceMatcher(None, a["text"].lower(), b["text"].lower()).ratio() > 0.6
        if similar and b["at"] - a["at"] < 90:
            flags.append("rephrased within 90 s")
    if any(t.get("stopped_early") for t in turns):
        flags.append("stopped a reply")
    if any(t.get("regenerated") for t in turns):
        flags.append("regenerated")
    if any(w in t["text"].lower() for t in users for w in ("wrong", "not what i asked", "galat")):
        flags.append("said it was wrong")
    return flags
```

Explicit ratings ke saath-saath flags ko din aur version ke hisaab se gino. Jis version mein thumbs down kam hain par rephrasing zyada hai, woh shaayad behtar nahi hai.

**Feedback ko dhyaan se design karo.** Natural moments par poochho (answer ke baad, task ke beech mein nahi), ek tap rakho, aur thumbs down ke baad do-teen reasons do. Yaad rakho feedback kaun deta hai: naakhush users aur bahut khush users, isliye explicit ratings skewed hoti hain. Dikhaye gaye do options mein se pehle par feedback zyada hota hai, bas isliye ki woh pehla tha. Versions ko ek hi feedback design se compare karo, redesigns ke aar-paar nahi.

**Dashboard ke liye ek query.** Agar traces Postgres mein aate hain, toh version ke hisaab se daily view kuch lines ka hai:

```sql
SELECT date(created_at AT TIME ZONE 'Asia/Kolkata') AS day, app_version,
       count(*) AS requests,
       avg(CASE WHEN feedback = 'down' THEN 1.0 ELSE 0 END) AS thumbs_down_rate,
       avg(CASE WHEN judge_verdict = 'fail' THEN 1.0 END) AS judge_fail_rate,
       avg(CASE WHEN refused THEN 1.0 ELSE 0 END) AS refusal_rate
FROM traces
WHERE created_at > now() - interval '30 days'
GROUP BY 1, 2 ORDER BY 1, 2;
```

**Sankre hote loops se bacho.** Agar aap feedback se rank ya recommend karte ho, toh aap zyadatar usi ke baare mein seekhte ho jo aap pehle se dikha chuke ho. Traffic ka ek chhota hissa doosre options explore karne do, aur changes ko sirf clicks se nahi, offline evals se bhi judge karo.

## Ek example se samjho

Chennai ke ek telecom ka customer assistant apne offline golden set par 91% se pass hua. Launch ke chhe hafte baad negative feedback 6% se 11% tak chadh gaya.

Online data ne dikhaya:

- Faithfulness (10% sample par judge kiya gaya) 0.93 par steady: answers apne sources se match karte the.
- Refusal rate 8% se 17% tak chadha.
- Zyadatar negative feedback "not what I asked" reason ke saath aaya.

Un mein se 60 traces padhne par wajah saamne aayi: ek naya prepaid plan launch hua tha, customers ne Tamil aur English mein uske baare mein poochha, aur plan documents index mein nahi daale gaye the. Assistant ne sahi refuse kiya, aur customers naakhush the.

Fixes: marketing team ke plan launches ab ek indexing job trigger karte hain; kisi topic ka refusal rate achanak badhne par alert chalta hai; naye plans ke 25 sawaal golden set mein jude. Negative feedback ek hafte mein wapas 6% par aa gaya. Monthly review mein aapne client ko timeline dikhayi, jisne pehle 91% se zyada bharosa banaya.

| Hafta | Negative feedback | Refusal rate | Action |
| --- | --- | --- | --- |
| Launch | 6% | 8% | Kuch nahi |
| Hafta 6 | 11% | 17% | 60 traces padhe: naye plan documents missing |
| Hafta 7 | 6% | 8% | Plan launches indexing trigger karte hain; topic refusal alert; 25 golden cases jode |

## Aam galtiyaan

- **Online signals ke bina ship karna.** Aapko problems naraaz users se ya client ke boss se pata chalti hain.
- **Bina check kiye judge par bharosa.** Judge scores drift karte hain aur blind spots rakhte hain; human grades se baar-baar compare karo.
- **Feedback collect karke kabhi na padhna.** Weekly review schedule karo.
- **Sirf averages.** Steady average ek topic ya language ke bahut bigadne ko chhupa sakta hai. Topic, language aur version se slice karo.
- **Tests jode bina fix karna.** Agle change ke baad wahi failure laut aata hai.
- **Random sampling jo har run mein badal jaaye.** Trace id hash karo taaki samples stable rahein.
- **Sirf explicit ratings par bharosa.** Kam log dete hain, aur woh negative aur positive dono taraf skew hoti hain.
- **Sirf clicks ya thumbs ke liye optimise karna**, jo product ko usi taraf sankra kar sakta hai jo woh pehle se karta hai.

## Jab online evals ruk sakte hain

- **Launch se pehle**: ek achhe test set par offline evals pehle aate hain.
- **Bahut kam traffic**: sample karne ki jagah har conversation padho.
- **Kuch experts waale internal tools**, jo kuch galat ho toh seedhe bata dete hain.

## Demo se production tak

- **Traces se asynchronously score karo**, response path mein kabhi nahi.
- **Feedback aur implicit flags ko trace id aur version ke saath store karo.**
- **Achanak badlaav par alert lagao**, version aur topic ke hisaab se, ek kharab conversation par nahi.
- **Weekly cause review chalao** aur counts client ke saath share karo.
- **Judge ko dobara check karo** har kuch hafte mein human grades se.
