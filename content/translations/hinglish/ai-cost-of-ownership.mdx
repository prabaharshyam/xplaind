## Ye kya hai

**Total cost of ownership (TCO)** wo sab hai jo kisi system par ek tay samay mein kharch hota hai, aam taur par ek se teen saal, sirf model ka bill nahi. Iska kaam hai options ki imaandaar tulna karne dena aur client ko ek sachcha budget dena.

| Cost line | Ismein kya aata hai | Log kya bhool jaate hain |
|---|---|---|
| Model | API se tokens, ya self-host karne par GPUs (kiraaye par ya khareede hue) | Chhupe hue reasoning tokens; idle rehte hue bhi bill hote GPUs |
| Infrastructure | App compute, databases, vector store, storage, gateways, monitoring | Log aur trace storage, staging environments |
| Log | Build, operate, on-call, evaluations, upgrades | On-call cover ke liye zaroori doosra engineer |
| Data | Connectors, pipelines, golden sets, documents ki safaai | Embedding model badalne par re-embedding |
| Compliance | Audits, penetration tests, security aur legal reviews | Har bade badlaav ke baad dobaara reviews |
| Badlaav | Model upgrades, provider ke model retire karne par prompt par dobaara kaam | Har naye model par evals dobaara chalaana |
| India-specific | Cloud aur API bills par GST, dollar prices par exchange rate | GST asli cost hai ya waapas claim ho sakta hai |

```flow
dir: LR
title: Maape hue usage se faisle tak
Maapa hua usage | traces aur load tests -> API option | tokens, infra, log
Maapa hua usage -> Self-hosted option | asli utilisation par GPUs, infra, log
API option -> Sensitivity aur crossover
Self-hosted option -> Sensitivity aur crossover
Sensitivity aur crossover -> Har claim ki cost banaam har claim ki value
```

Ye lesson Kolkata ki ek insurance company ke saath chalta hai, jo 2,000 staff ke liye ek claims-document assistant ki yojana bana rahi hai.

## Ye kaise kaam karta hai

### Maape hue usage se shuru karo

Users, har user ki har din ki requests, peak banaam average, aur saal bhar ki growth ikattha karo. Phir traces se wo teen cheezein maapo jinka log aam taur par andaaza laga lete hain:

- **Har user action par calls.** Ek agent ya retrieval pipeline ek sawaal ke liye teen se chhah model calls kar sakti hai: query ko dobaara likhna, retrieve karna, jawaab dena, check karna. Cost har call ki hoti hai, har sawaal ki nahi.
- **Har call ke input tokens.** Retrieve hue passages aksar input ko user ke sawaal se kai guna bada kar dete hain.
- **Reasoning samet, har call ke output tokens.** Reasoning models jawaab dene se pehle sochte hain. Wo thinking chhupi rehti hai par output tokens ke roop mein bill hoti hai (OpenAI ka documentation ye saaf-saaf kehta hai). Ek chhote dikhne waale jawaab ke peeche ek lamba na dikhne waala bill ho sakta hai.

### API option

Har call ki cost = input tokens × input price + output tokens × output price. Phir teen adjustments karo:

- **Prompt caching.** Har call par dobaara padha jaane waala fixed system prompt ya shared document prefix, caching dene waale providers ke yahaan normal input price ke ek chhote hisse par bill hota hai.
- **Batch discounts** us kaam ke liye jo ghanton ruk sakta hai, jaise raat bhar mein banne waali summaries.
- **Tiering.** Simple requests (lookups, classification) ko ek saste, chhote model par bhejo aur mushkil waalon ke liye bada model rakho.

Zyaadatar API prices US dollars mein hoti hain, isliye rupee rate bhi ek input hai. Prices provider ke page se aur Artificial Analysis jaisi kisi independent comparison se padho, aur har price ke bagal mein check ki date likho.

### Self-hosted option

GPUs ko ek spare ke saath **peak** ke liye size karna hota hai, aapke latency target par aapke apne prompts waale load test ke hisaab se. Phir aap mahine ke har ghante unke paise dete ho, busy hon ya nahi. Faisla karne waala number hai **utilisation**:

utilisation = serve hui requests ÷ wo requests jo fleet mahine mein serve kar sakta tha

Working days par din mein nau ghante use hone waala, month-end peak ke liye size kiya gaya office tool aksar 10% ya usse kam par chalta hai. 10% utilisation par har request poore use ki tulna mein das guna GPU cost uthaati hai.

Do pricing choices maayne rakhti hain:

- **On-demand** GPUs ki har ghante ki cost sabse zyada hoti hai, par unhein chhoda ja sakta hai.
- **Reserved** GPUs (ek ya teen saal ka commitment) har ghante saste padte hain, par usage gire ya API prices girein, paise phir bhi dene padte hain.

Serving stack chalaane, patch karne, models upgrade karne aur pager sambhaalne waale log jodo, aur agar open model aapke evals par kam score karta hai toh quality ka gap bhi.

### India-specific lines

- **GST.** Cloud aur API services par aam taur par 18% GST lagta hai (November 2026 tak IT aur cloud services ka saamaanya rate). Kisi foreign provider se khareedne waala GST-registered business aam taur par ise reverse charge mein bharta hai aur input tax credit ke roop mein waapas claim kar sakta hai. Jo organisation credit claim nahi kar sakta, uske liye ye asli cost hai. Client ki finance team se poochho ki kaun-sa case laagu hota hai; is lesson ke figures GST se pehle ke hain.
- **Exchange rate.** Rupee girne par dollar mein priced API bill badh jaata hai. November 2026 ke beech mein rupee ek hafte ke andar lagbhag ₹94.2 se lagbhag ₹93.5 prati dollar par aaya, aur ₹100 tak jaane par model line mein lagbhag 7% jud jaata hai. Rate ko sensitivity table mein daalo.
- **Region.** Data rules kisi Indian cloud region ko zaroori bana sakte hain. Check karo ki jis model ya GPU type ki price aapne li, wo wahaan us region ki price par milta hai.

### Sensitivity aur crossover

Ek baar mein ek assumption badalkar dono options dobaara nikaalo: usage aadha aur doguna, outputs dogune lambe, API prices 30% kam, kamzor rupee, load test se kam GPU throughput. Jo faisla sirf ek exact number par tika ho, wo fragile hai.

**Crossover** wo usage hai jiske upar doosra option lagaataar sasta rehta hai. Do traps:

- **Steps.** GPUs poore units mein aate hain, isliye har baar ek jodne par self-hosted line uchhalti hai. Spreadsheet ek volume par self-hosting ko jeetta aur uske zara upar haarta dikha sakti hai. Wo volume report karo jiske upar ye lagaataar jeetta hai.
- **Thin margins.** Agar har extra request par API aur GPU ki cost lagbhag baraabar hai, toh chhote badlaavon se crossover bahut zyada jhoolta hai. Ye saaf batao.

### Price trends

Kisi tay quality level ke liye API prices tezi se giri hain. Epoch AI ne March 2025 mein andaaza lagaaya ki ek fixed benchmark score tak pahunchne waale models ki per-token price saal mein 9 se 900 guna tak giri, is par nirbhar karte hue ki kaun-sa performance level maapa gaya. Ye prices per token hain, aur reasoning models har task par kahin zyada tokens use kar sakte hain. Teen saal ka GPU commitment is trend ke khilaaf daanv hai, isliye ise "prices 30% kam" waali row se test karo.

### Ek cost model jise dobaara chala sako

Har assumption ek jagah rakho, check ki date ke saath. Neeche ka har number illustrative hai, worked example se mel khaane ke liye chuna gaya:

```python
import math

# Every number is illustrative. Replace each with your own dated quote or measurement.
P = {"rate_date": "2026-11-19", "usd_to_inr": 93.5,        # rupees per US dollar, about mid-November 2026
     "in_per_m": 3.0, "out_per_m": 15.0,                    # USD per million tokens, a mid-tier API model
     "cache_ratio": 0.1,                                    # cached input billed at 10% of the input price
     "gpu_month": 250_000,                                  # one rented GPU, on demand, all 730 hours
     "gpu_rps": 1.2,                                        # requests per second per GPU, from YOUR load test
     "engineer_month": 200_000,                             # loaded monthly cost of one engineer
     "busy_seconds": 22 * 9 * 3600,                         # 22 working days of 9 busy hours
     "peak_factor": 2.0}                                    # month-end peak against the busy-hour average

def api_month(req, p=P, in_tok=3000, out_tok=300, cached=0.4, small_share=0.4, small_ratio=0.25):
    in_usd = in_tok * (1 - cached + cached * p["cache_ratio"]) * p["in_per_m"] / 1e6
    per_req = (in_usd + out_tok * p["out_per_m"] / 1e6) * (1 - small_share + small_share * small_ratio)
    return req * per_req * p["usd_to_inr"] + 120_000 + 0.3 * p["engineer_month"]   # + infra + 0.3 engineer

def gpus(req, p=P):
    peak_rps = req / p["busy_seconds"] * p["peak_factor"]
    return math.ceil(peak_rps / p["gpu_rps"]) + 1                                   # + one spare

def self_month(req, p=P):
    return gpus(req, p) * p["gpu_month"] + 150_000 + 1.5 * p["engineer_month"]       # + infra + 1.5 engineers

def utilisation(req, p=P):
    return req / (gpus(req, p) * p["gpu_rps"] * 730 * 3600)

def crossover(p=P, limit=30_000_000, step=100_000):
    """Volume above which self-hosting stays cheaper, or None if it never does up to the limit."""
    last_api_win = 0
    for r in range(step, limit + 1, step):
        if self_month(r, p) >= api_month(r, p):
            last_api_win = r
    return None if last_api_win == limit else last_api_win + step

base = 1_100_000
print(f"Illustrative prices, rupee rate of {P['rate_date']}")
print(f"measured: API ₹{api_month(base)/1e5:.1f} lakh, self-hosted ₹{self_month(base)/1e5:.1f} lakh, "
      f"{gpus(base)} GPUs at {utilisation(base):.0%} utilisation")
scenarios = {"as measured": {}, "reserved GPUs at ₹1.6 lakh": {"gpu_month": 160_000},
             "load test gives 1.0 req/s": {"gpu_rps": 1.0}, "API prices 30% lower": {"in_per_m": 2.1, "out_per_m": 10.5},
             "rupee at ₹100": {"usd_to_inr": 100},
             "reserved, API 30% lower": {"gpu_month": 160_000, "in_per_m": 2.1, "out_per_m": 10.5}}
for name, change in scenarios.items():
    p = {**P, **change}
    c = crossover(p)
    print(f"{name:<27} API ₹{api_month(base, p)/1e5:4.1f} lakh  self ₹{self_month(base, p)/1e5:4.1f} lakh  "
          f"crossover {'none below 30M' if c is None else f'{c/1e6:.1f}M'}")
```

Ye model volume badhne par bhi logon aur infrastructure ko fixed rakhta hai, jisse zyaada volume par self-hosting asal se behtar dikhta hai: pandrah GPUs ke fleet ko dedh engineers se zyada chahiye. Kisi ko koi number dikhaane se pehle client ke traces, load test aur quotes daalo.

## Ek worked example

Kolkata ki ek insurance company 2,000 staff ke liye ek claims-document assistant roll out karne ki yojana bana rahi hai. Pilot mein maapa gaya: 22 working days mein har user har working day 25 requests, har request mein 3,000 input tokens (zyaadatar retrieve hue passages) aur 300 output tokens, har request par ek model call. Yaani 2,000 × 25 × 22 = mahine mein 1.1 million requests. Month-end traffic normal busy-hour rate ka doguna hai. Saari prices code waali illustrative prices hain.

**Option A, unke cloud ke zariye API.** Har request: 3,000 × $3 ÷ 1,000,000 + 300 × $15 ÷ 1,000,000 = $0.0135, ₹93.5 par lagbhag ₹1.26. 1.1 million requests par ye mahine mein lagbhag ₹13.9 lakh hai. Fixed system prompt aur instructions (input tokens ka 40%) cache karne se ye lagbhag ₹10.6 lakh par aata hai. 40% requests, yaani simple lookups, ko ek chauthaai price waale model par bhejne se ye lagbhag ₹7.4 lakh par aata hai, yaani har request ₹0.67. ₹1.2 lakh ka infrastructure aur ek engineer ka 30% jodo: lagbhag **₹9.2 lakh mahina**.

**Option B, self-hosted open model.** Load test dikhaata hai ki ek GPU latency target par har second 1.2 requests serve karta hai. Month-end peak lagbhag 3.1 requests prati second hai, toh teen GPUs aur ek spare: chaar GPUs, har ek ₹2.5 lakh, kul ₹10 lakh. ₹1.5 lakh ka infrastructure aur serving, upgrades aur on-call ke liye dedh engineers (₹3 lakh) jodo: lagbhag **₹14.5 lakh mahina**. Evals par accuracy 2 points kam hai. Fleet 9% utilisation par chalta hai, kyunki wo month-end ke liye size hai aur har raat aur har weekend ke paise diye jaate hain.

| Har mahine (illustrative) | Option A: API | Option B: self-hosted |
| --- | --- | --- |
| Model | Caching aur tiering ke baad lagbhag ₹7.4 lakh | 9% utilisation par chaar GPUs ke ₹10 lakh |
| Infrastructure | ₹1.2 lakh | ₹1.5 lakh |
| Log | 0.3 engineer, ₹0.6 lakh | 1.5 engineers, ₹3 lakh |
| Evals par quality | Baseline | 2 points kam |
| Mahine ka kul | Lagbhag ₹9.2 lakh | Lagbhag ₹14.5 lakh |
| Saal ka kul | Lagbhag ₹1.1 crore | Lagbhag ₹1.74 crore |

**Crossover kahaan hai?** API par har extra request lagbhag ₹0.67 ki padti hai. Average ke dogune ke liye size kiye GPU par ye lagbhag ₹0.58 hai. Farq sirf nau paise ka hai, isliye self-hosting ko apne spare GPU aur extra engineers ka kharch nikaalne ke liye bahut bada volume chahiye. On demand par ye sirf lagbhag 8.3 million requests prati mahine ke upar lagaataar jeetta hai, jo aaj ke volume ka saat se aath guna hai. ₹1.6 lakh waale reserved GPUs ke saath ye lagbhag 1.9 million par aa jaata hai: kareeb. Par agar load test ne 1.2 ki jagah 1.0 request prati second dikhaaya hota, ya API prices 30% gir jaatin, toh on-demand crossover hota hi nahi. Yahi fragility asli finding hai.

**Faisla.** A chuno. Plan mein do review triggers likho: jab monthly volume 1.5 million paar kare, toh reserved GPU ka quote lo aur load test dobaara chalao; aur jab bhi API price, rupee rate ya koi data rule badle, model dobaara chalao. Recommendation mein likho ki ek saal ka reservation cost ko lock kar deta hai, jabki API prices aam taur par girti rehti hain; API prices 30% kam hone par reserved crossover lagbhag 6.1 million tak khisak jaata hai.

**Value ki taraf.** Pilot ne dikhaaya ki mahine ke 40,000 claims par har claim mein 9 minute bachte hain, yaani lagbhag 6,000 staff hours. ₹400 prati ghante ki illustrative loaded staff cost par, ye har claim par ₹60 ka samay hai, jabki har claim par AI cost lagbhag ₹23 (₹9.2 lakh ÷ 40,000). Leadership team ko yahi ratio yaad rahega, token bill nahi.

## Aam galtiyaan

- **Token price ki tulna GPU kiraaye se karna.** Dono taraf har line gino: log, infrastructure, evals, badlaav. Dono options mein sabse zyada baar chhootne waali line log hain.
- **Usage ka andaaza lagaana.** Har user action par calls aur har call ke tokens traces se maapo, retrieve hue context aur chhupe reasoning tokens samet.
- **Average ke liye size karna, ya poora utilisation maan lena.** GPUs peak cover karte hain aur poore mahine bill hote hain. Utilisation ko model mein daalo.
- **Pehle crossover par bharosa karna.** Poore-GPU steps lines ko cross aur uncross karaate hain. Stable point report karo aur ye ki wo kitna khisakta hai.
- **Price-fall row ke bina GPUs reserve karna.** API prices girne par lamba commitment puraana hokar ghaata de sakta hai.
- **Rupee aur GST ko nazarandaaz karna.** Dollar bill exchange rate ke saath badalta hai, aur agar GST waapas claim nahi ho sakta toh wo asli cost hai.
- **Bina date ki prices.** Kuch hi mahinon mein wo chupchaap galat ho jaati hain.
- **Value ki taraf kuch nahi.** Bachaaye gaye ghanton ya errors ke bina cost model kuch bhi justify nahi kar sakta.

## Kab detailed cost model zaroori nahi

- **Chhote, tay budget waala pilot**: ek spend cap aur hafte mein ek baar bill dekhna kaafi hai.
- **Koi asli vikalp nahi**, jaise data rules on-premises hosting zaroori kar dein: cost ko budget banaane ke liye model karo, chunne ke liye nahi.
- **Bahut kam usage**, jahaan value ke saamne cost ek rounding error hai.

## Demo se production tak

- **Cost model ko repository mein rakho**, date waali prices, rupee rate aur maape hue usage ke saath.
- **Har mahine ise reconcile karo**, traces aur asli bill se, aur har farq samjhaao.
- **Har unit kaam ki cost track karo**, har unit ki value ke bagal mein, usi dashboard par.
- **Crossover dobaara chalao** jab usage, prices, rupee, models ya load-test results badlein.
- **API account par budget alerts lagao**, taaki bekaabu agent loop month end par nahi, kuch hi ghanton mein pakad mein aa jaaye.

## Practice

Artificial Analysis se teen models ki maujooda prices ikattha karo, har ek ke bagal mein check ki date likho, aur routing par RouteLLM ka post dobaara padho taaki dikhe ki tiering cost kaise ghataata hai.

1. Apne app ke traces se har user action par calls aur har call ke average input, output aur reasoning tokens maapo.
2. Cost model ko 100, 1,000 aur 10,000 daily users ke liye adapt karo, ek API option aur ek self-hosted option ke saath jismein utilisation, log aur infrastructure shaamil hon.
3. Ek sensitivity table (usage aadha aur doguna, output doguna, API prices 30% kam, rupee ₹100 par), stable crossover, aur mahine ki value ki ek line jodo.

Aur gehraai ke liye, Chip Huyen ki *AI Engineering* (O'Reilly, 2025) ka chapter 4 model APIs banaam self-hosting ki cost waala pehlu cover karta hai, aur chapter 9 inference cost cover karta hai.

**Aapka kaam poora hai jab aap** ek recommendation, crossover, sensitivity mein wo kitna khisakta hai, aur review triggers ke saath ek page ki cost comparison pesh kar sako.
