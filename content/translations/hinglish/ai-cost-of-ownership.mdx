## Ye kya hai

**Total cost of ownership (TCO)** woh sab kuch hai jo ek system ko ek avadhi mein, aam taur par ek se teen saal, kharch karta hai, sirf model bill nahi. AI system ke liye:

- **Model costs**: API par tokens, ya self-hosting ke liye GPUs (khareede ya kiraye par).
- **Infrastructure**: app ke liye compute, databases, vector stores, storage, networking, monitoring, gateways.
- **Log**: build karna, chalana, on-call, evaluate karna, upgrade karna. Aksar sabse bada item.
- **Data work**: connectors, pipelines, golden sets label karna, documents ki safai.
- **Compliance aur security**: audits, penetration tests, reviews.
- **Change**: model upgrades, re-embedding, jab providers models deprecate karte hain tab prompt rework.

Maqsad options ke beech fair comparison aur client ke liye imaandaar budget hai.

| Total cost of ownership, saal ka | Isme kya jaata hai |
|---|---|
| Model | API se tokens, ya self-hosted ho toh poora mahina chalne waale GPUs |
| Infrastructure | App compute, databases, vector store, monitoring |
| Log | Build, operate, on-call, evals, upgrades: **aksar sabse bada** |
| Data | Connectors, pipelines, golden sets, clean-up |
| Compliance | Audits, pen tests, reviews |
| Change | Model upgrades, re-embedding, prompt rework |

```flow
dir: LR
title: Options ko ek hi usage par compare karo
Model + infra + log + data + compliance + change -> Per claim cost
Per claim cost -> Per claim value se compare karo
```

Ye lesson Kolkata ki ek insurance company ko follow karta hai jo 2,000 staff ke liye claims-document assistant plan kar rahi hai.

## Ye kaam kaise karta hai

**Usage se shuru karo.** Users, har user ke roz ke requests, har request ke input aur output tokens (traces se naape, andaze se nahi), saal bhar mein growth, aur peak versus average.

**API option.** Cost per request = input tokens x input price + output tokens x output price, caching discounts, batch discounts aur model tiering ke hisaab se adjust karke. Mahine ke requests se guna karo. Maujooda price lists aur independent comparisons use karo; prices aksar badalti hain, aam taur par neeche.

**Self-hosted option.** Peak load ke liye headroom ke saath zaroori GPUs (load tests se), guna ghante ka price ya amortised purchase, jo poora mahina chalte hain busy ho ya na ho. Sath mein use chalane, monitor karne aur upgrade karne ka engineering time jodo, aur agar open model kamzor hai toh quality gap bhi.

**Sensitivity.** Dikhao ki cost kaise badalti hai agar usage estimate ka aadha ya double ho, output length badhe, ya prices 30% gir jaayein. Jo decisions sirf ek exact usage level par hi samajh aate hain woh nazuk hote hain.

**Unit economics.** Result ko us unit ke hisaab se batao jo client ko chahiye: cost per resolved ticket, per claim processed, per employee per month. Use value se compare karo: bachaaye ghante, tez processing, kam galtiyaan.

**Ek page par comparison (samjhane ke figures):**

| Mahine ka item | Option A: unke cloud se API | Option B: self-hosted open model |
| --- | --- | --- |
| Model | Caching aur tiering ke baad lagbhag ₹6.5 lakh | Chaar GPUs ke liye lagbhag ₹10 lakh |
| Infrastructure | Lagbhag ₹1.2 lakh | Lagbhag ₹1.5 lakh |
| Log | Ek engineer ka chhota hissa | Lagbhag 1.5 engineers, lagbhag ₹3 lakh |
| Evals par quality | Baseline | 2 points kam |
| Saal ka total | Lagbhag ₹1 crore | Lagbhag ₹1.75 crore |

**Sensitivity, practice mein.** Dono options ko naape gaye usage ke aadhe aur double par, outputs ke do guna lambe hone par, aur API prices 30% kam hone par dobara compute karo. Crossover point likh lo, woh usage jahan self-hosting sasta ho jaayega. Yahan woh lagbhag maujooda volume ka teen guna hai. Wahi ek number bahas ko review trigger mein badal deta hai: "agar mahine ke requests 3 million paar karein toh dobara dekho".

**Value waala hissa.** Akela cost kisi system ko justify nahi kar sakta. Use pilot se aayi value ke saath jodo: har task par bachaaye minutes x mahine ke tasks, bachi hui galtiyaan, customers ke liye tez turnaround. Cost aur value per unit saath-saath rakho, taaki leaders sirf bill nahi, margin dekh sakein.

**Ek cost model jo dobara chal sake.** Assumptions ko ek jagah rakho, har price ko check karne ki date ke saath:

```python
PRICES = {"checked": "2026-11-08", "usd_to_inr": 84,
          "in_per_m": 3.0, "out_per_m": 15.0, "cache_read_ratio": 0.1,      # USD per million tokens
          "gpu_hour_inr": 250, "engineer_month_inr": 250_000}

def api_month(requests, in_tok, out_tok, cached_share=0.5, small_share=0.0, small_ratio=0.25):
    p = PRICES
    per_req_usd = (in_tok * (1 - cached_share) * p["in_per_m"] + in_tok * cached_share * p["in_per_m"] * p["cache_read_ratio"]
                   + out_tok * p["out_per_m"]) / 1e6
    blended = per_req_usd * (1 - small_share + small_share * small_ratio)       # share sent to a cheaper model
    return requests * blended * p["usd_to_inr"]

def self_host_month(gpus, engineers=1.5, infra_inr=150_000):
    p = PRICES
    return gpus * p["gpu_hour_inr"] * 730 + engineers * p["engineer_month_inr"] + infra_inr

def table(base_requests, in_tok=3000, out_tok=400, gpus=4):
    print(f"prices checked {PRICES['checked']}")
    for label, mult in [("half usage", 0.5), ("measured", 1), ("double usage", 2)]:
        a = api_month(base_requests * mult, in_tok, out_tok, small_share=0.4) + 0.3 * PRICES["engineer_month_inr"]
        s = self_host_month(gpus if mult <= 1 else gpus * 2)
        print(f"{label:<13} API ₹{a/1e5:6.1f} lakh   self-hosted ₹{s/1e5:6.1f} lakh")

table(base_requests=600_000)
```

Client ka asli usage traces se aur maujooda quotes daal do. Print ki hui date sabko imaandaar rakhti hai ki prices kab sahi thi.

**Crossover dhoondho.** Usage badhate jao jab tak self-hosted line API line se neeche na aa jaye:

```python
def crossover(in_tok=3000, out_tok=400, gpus_per_million=2):
    for r in range(100_000, 20_000_001, 100_000):
        gpus = max(1, round(r / 1e6 * gpus_per_million))
        if self_host_month(gpus) < api_month(r, in_tok, out_tok, small_share=0.4):
            return r
    return None
```

`gpus_per_million` load test se aana chahiye, andaze se nahi. Agar crossover expected usage se bahut upar hai toh decision aasaan hai; agar kareeb hai toh usage badhne par dobara dekhne ka plan rakho.

**Har line gino.** Tokens aur GPUs ke alawa: embeddings aur re-embedding, vector database, tracing aur log storage, evaluation runs (judge calls jodte jaate hain), staging environments, security reviews, aur system ko chalane, monitor karne aur behtar banane waale log. Logon ko chhod dena in comparisons ki sabse aam galti hai.

**Cost ke saath value jodo.** Kaam ki har unit ke liye, naapi hui value ko cost ke saamne rakho: bachaaye minutes x loaded staff cost per minute, bachi hui galtiyaan, tez turnaround. Ek-line ratio ("₹4 AI cost per ticket, ₹60 staff time bachaaya") woh hai jo decision-makers ko yaad rehta hai.

## Ek example se samjho

Kolkata ki ek insurance company 2,000 staff ke liye claims-document assistant rollout karne ka plan karti hai. Pilot mein naapa gaya: har user ke roz ke working day mein 25 requests, har request mein 3,000 input tokens (zyadatar retrieved passages) aur 300 output tokens. Yeh mahine mein lagbhag 1.1 million requests hain.

**Option A, unke cloud se API.** Samjhane ke liye ₹0.25 per 1,000 input tokens aur ₹1.00 per 1,000 output tokens par: (3 x 0.25) + (0.3 x 1.00) = ₹1.05 per request, mahine ka lagbhag ₹11.5 lakh. Fixed system prompt par prompt caching aur simple lookups ko chhote model par tiering se yeh lagbhag ₹6.5 lakh ho jaata hai. Infrastructure ₹1.2 lakh. Operations ke liye ek engineer ka chhota hissa.

**Option B, self-hosted open model.** Load tests peak load ke liye teen GPUs plus ek spare dikhate hain, samjhane ke liye ₹2.5 lakh per GPU per month par: ₹10 lakh. Infrastructure ₹1.5 lakh. Sath mein serving stack chalane ke liye lagbhag derh engineers, mahine ka lagbhag ₹3 lakh. Evals mein 2 points kam accuracy dikhti hai.

Saal bhar mein A lagbhag ₹1 crore ka hai aur B lagbhag ₹1.75 crore ka. B tabhi jeetta hai jab usage teen guna ho ya data rules ki wajah se zaroori ho. Client A chunta hai, review ke saath agar volume mahine mein 3 million requests paar kare. Value ki taraf: pilot ne mahine ke 40,000 claims par har claim 9 minute bachte dikhaye, lagbhag 6,000 staff hours, jo cost se aaram se upar hai.

(Yahan prices samjhane ke liye hain. Model banane ke din providers aur comparisons ki maujooda prices use karo.)

| Pilot se measure | Value |
| --- | --- |
| Har claim par bachaya time | 9 minutes |
| Mahine ke claims | 40,000 |
| Mahine mein bachaaye staff hours | Lagbhag 6,000 |
| Decision | Option A, volume mahine mein 3 million requests paar kare toh review |

## Aam galtiyaan

- **Sirf tokens ya sirf GPUs ginna.** Log aur change ke costs aksar sabse bade hote hain.
- **Token counts ka andaaza lagana.** Real traces se naapo; retrieved context input tokens ko badha deta hai.
- **Average ke hisaab se size karna.** Self-hosted capacity ko peaks cover karne hote hain; APIs unhe jhel leti hain.
- **Price trends ko ignore karna.** API prices lagatar giri hain; teen saal ke GPU commitments achhe se purane na ho paayein.
- **Value waala hissa na hona.** Bachaaye hue ghanton ya galtiyon ke bina cost model kuch justify nahi kar sakta.
- **Logon ko** self-hosted (aur API) cost se bahar rakhna.
- **Bina date waali prices**, jo mahinon baad chupke se purani ho jaati hain.
- **GPU counts ka andaaza lagana**, load test se capacity naapne ki jagah.

## Jab detailed cost model ki zaroorat nahi

- **Chhote, fixed budget par ek pilot**: spend cap aur har hafte bill par ek nazar kaafi hai.
- **Koi asli alternative nahi**, jaise data rules on-premises hosting ko zaroori kar dein: choose karne ke liye nahi, budgeting ke liye cost model karo.
- **Bahut chhota usage**, jahan cost value ke saamne rounding error hai.

## Demo se production tak

- **Cost model ko repository mein rakho**, dated prices aur naape gaye usage ke saath.
- **Har mahine update karo** traces aur asli bill se, aur farak samjhao.
- **Kaam ki har unit ka cost track karo**, har unit ki value ke saath.
- **Crossover dobara compute karo** jab usage, prices ya models badlein.
- **Har line shaamil karo**: evals, tracing, storage, staging aur log.
