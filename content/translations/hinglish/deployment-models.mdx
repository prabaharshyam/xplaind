## Ye kya hai

Ek **deployment model** do sawaalon ka jawab deta hai: model aur application kahan chalte hain, aur unhe kaun control karta hai? Main options, kam se zyada control tak:

1. **Vendor API (multi-tenant SaaS)**: aap model provider ka public endpoint call karte ho. Shuru karne mein sabse tez, naye models, sabse kam control.
2. **Client ke cloud ke through model**: wahi ya milte-julte models client ke apne cloud account aur region ke andar (Amazon Bedrock, Azure AI Foundry, Google Vertex AI), unke pehle se maujood cloud contract ke under.
3. **Dedicated ya private capacity**: reserved capacity ya ek private endpoint, kabhi-kabhi private networking ke saath taaki traffic public internet se na guzre.
4. **Client ke cloud mein self-hosted open-weight models**: aap Llama, Qwen, Mistral ya Gemma variants jaise models unke account ke GPU machines par chalate ho.
5. **On-premises**: wahi, client ke apne data centre mein.
6. **Air-gapped**: bahar ke networks se koi connection nahi. Models, code aur updates controlled transfer se aate hain.

Application (API, retrieval, database) model se alag, wahi choices follow kar sakti hai.

```flow
dir: LR
title: Kam control aur tez shuruaat se, zyada control aur zyada kaam tak
Vendor API | hafte -> Client's cloud | approved tenancy aur region
Client's cloud -> Dedicated | private network
Dedicated -> Self-hosted | unke GPUs, aap operate karte ho
Self-hosted -> On-prem | unka data centre
On-prem -> Air-gapped | koi network nahi, sirf transfers
```

App, retrieval aur logs model se alag rung par ho sakte hain.

Ye lesson Bengaluru, Mumbai aur Hyderabad ke teen clients ke saath chalta hai, jinhe alag-alag deployment chahiye tha.

## Ye kaam kaise karta hai

**Choice kya tay karta hai.**

- *Data rules*: data kahan ja sakta hai, is par regulation, contracts aur internal policy. Indian regulators aur kai enterprises chahte hain ki data India mein rahe; kuch data premises se bahar ja hi nahi sakta.
- *Zaroori model quality*: sabse strong models aksar sirf APIs ya cloud partners ke through milte hain. Open-weight models kai tasks ke liye bahut peeche nahi hain aur extraction, classification aur achhe scope waale documents par RAG ke liye theek hain.
- *Cost aur volume*: APIs per token charge karti hain; self-hosting mein bada fixed GPU cost hota hai jo sirf zyada, steady volume par vasool hota hai.
- *Skills*: self-hosting ke liye aise log chahiye jo GPUs, serving engines, monitoring aur upgrades chala sakein.
- *Latency aur availability*: on-premises network delay kam kar sakta hai par uptime client ki team par daal deta hai.

**Pehle poochne ke sawaal.** Data kahan process ho sakta hai? Kya koi provider pehle se approved hai? Kya pehle se koi cloud contract hai? Handover ke baad system kaun chalayega? Jab model ko upgrade karna ho toh kya hoga?

**Hybrid common hai.** Sensitive requests ko self-hosted model par aur baaki ko API par bhejo; ya embeddings ke liye self-hosted model aur generation ke liye cloud model use karo.

**Air-gapped ki khaas baatein.** Koi package downloads nahi, model downloads nahi, SaaS monitoring nahi, internet par licence checks nahi. Sab kuch (container images, model weights, Python packages) bundle, scan aur transfer hota hai. Updates ko scheduled releases ki tarah plan karo.

**Options ko score karna:**

| Factor | Vendor API | Client's cloud | Self-hosted | Air-gapped |
| --- | --- | --- | --- | --- |
| Data control | Sabse kam | Zyada, unke tenancy mein | Bahut zyada | Poora |
| Model quality | Sabse strong | Strong | Achha open-weight | Achha open-weight |
| Kam volume par cost | Sabse kam | Kam | Zyada: idle GPUs | Sabse zyada |
| Launch ka time | Din se hafte | Hafte | Mahine | Mahine |
| Zaroori skills | Kam | Cloud skills | GPU serving, monitoring | Ye sab, offline |

**Pehli meeting ke sawaal.** Ye data kahan process ho sakta hai, aur kya koi provider pehle se approved hai? Kya pehle se cloud contract aur region hai? Kaunsa data, agar koi hai, premises se kabhi nahi ja sakta? Handover ke baad system kaun chalayega, aur kya unke paas GPU skills hain? Model ko kitni baar upgrade karna padega, aur use kaun approve karega? Jawab aam taur par chhe options ko ghante ke andar ek ya do tak le aate hain.

**Offline sites ke liye bill of materials.** Air-gapped build ke liye har artefact list karo: pinned versions waali container images, checksums ke saath model weights, Python aur system packages, vector database, offline kaam karne waale monitoring tools, aur documentation. Client ki security team inhe scan karke transfer karti hai. Ek package chhoot jaane se release hafton late ho sakti hai, isliye pehle disconnected test machine par install ka rehearsal karo.

**API ya self-hosted, numbers mein.** Ek pehli comparison jise aap asli quotes ke saath dobara kar sakte ho (har price ki date record karo):

```python
def monthly_costs(tokens_in_m, tokens_out_m, api_in_usd, api_out_usd,
                  gpu_hour_inr, gpus, hours=730, ops_people=0.5, ops_cost_inr=250_000, usd_to_inr=84):
    """tokens in millions per month; API prices in USD per million tokens."""
    api = (tokens_in_m * api_in_usd + tokens_out_m * api_out_usd) * usd_to_inr
    self_host = gpu_hour_inr * gpus * hours + ops_people * ops_cost_inr
    return {"API ₹/month": round(api), "self-hosted ₹/month": round(self_host),
            "cheaper": "API" if api < self_host else "self-hosted"}

print(monthly_costs(tokens_in_m=900, tokens_out_m=120, api_in_usd=0.8, api_out_usd=4,
                    gpu_hour_inr=250, gpus=2))
```

GPUs har ghante paisa kharchte hain chaahe use hon ya nahi, isliye self-hosting sirf zyada, steady volume par ya jab data rules koi choice na chhodein tab jeetta hai. Logon ko bhi jodo: kisi ko serving stack patch, monitor aur upgrade karna hoga.

**Sensitivity ke hisaab se route karo.** Hybrid design mein ek chhota rule tay karta hai ki har request kahan jaaye:

```python
SENSITIVE_FIELDS = {"aadhaar", "pan", "medical_history", "bank_account"}

def route(request):
    if request.get("classification") == "restricted" or SENSITIVE_FIELDS & set(request.get("fields", [])):
        return "self_hosted"            # stays on the client's servers
    return "cloud_model"                # stronger model, client's cloud region
```

Rule ko client ke data owner ke saath likho, har data class ke examples se test karo, aur har request ka route log karo.

**Air-gapped bundle banana.** Connected build machine par, sab kuch versions aur checksums ke saath jama karo, phir client ke approved process se transfer karo:

```bash
mkdir -p bundle/{images,models,wheels}
docker pull vllm/vllm-openai:v0.10.1 && docker save vllm/vllm-openai:v0.10.1 | gzip > bundle/images/vllm.tar.gz
docker save claims-api:1.4.0 | gzip > bundle/images/claims-api.tar.gz
huggingface-cli download org/model-8b-instruct --revision <commit> --local-dir bundle/models/model-8b
pip download -r requirements.txt -d bundle/wheels
(cd bundle && find . -type f -exec sha256sum {} \; > SHA256SUMS)
```

Offline side par, `sha256sum -c SHA256SUMS` saabit karta hai ki transit mein kuch nahi badla, `docker load` images restore karta hai, aur `pip install --no-index --find-links wheels -r requirements.txt` internet ke bina install karta hai. Asli visit se pehle networking band ki hui machine par poore install ka rehearsal karo.

**Upgrades ko shuru se plan karo.** Har option ko naye model versions ke liye ek raasta chahiye: API apne aap badalti hai (pin karo aur test karo), client ka cloud apne schedule par models jodta hai, aur self-hosted ya offline setups ko ek dohraane laayak bundle-and-test process chahiye.

## Ek example se samjho

Teen clients, teen jawab:

- *Bengaluru ka ek D2C brand*: customer-support assistant, sirf public-facing data, chhoti team. Gateway ke through **vendor API**, jahan mile wahan Indian region. Teen hafte mein live.
- *Mumbai ka ek private bank*: confidential documents ke saath internal policy assistant. Bank ki risk team Central India mein apna Azure tenancy pehle hi approve kar chuki hai. **Client ke cloud ke through models**, private networking aur bank ki keys ke saath. Approval chhe mahine ki jagah chaar hafte mein hua kyunki kuch naya approve nahi karna pada.
- *Hyderabad ka ek defence electronics supplier*: classified network par engineering-document search. **Air-gapped self-hosting**: do on-premises GPU servers par vLLM se serve hua ek open-weight model, wahi network par embeddings aur vector database, aur images aur weights ka ek quarterly update package jise client ki security team scan karke transfer karti hai. Model frontier APIs se kam capable hai, isliye scope retrieval aur summarisation tak narrow kiya gaya, jahan evals dikhate hain ki woh achha perform karta hai.

| Client | Deployment | Kyun | Nateeja |
| --- | --- | --- | --- |
| Bengaluru D2C brand | Gateway ke through vendor API | Public data, chhoti team | Teen hafte mein live |
| Mumbai private bank | Apne approved Azure tenancy mein models | Confidential documents, pehle se approval | Chaar hafte mein approved |
| Hyderabad defence supplier | Local GPUs par air-gapped vLLM | Classified network | Scope retrieval aur summaries tak narrow |

## Aam galtiyaan

- **Data rules poochhe bina public API propose karna.** Aap hafte aur saakh dono kho dete ho.
- **Maan lena ki self-hosting sasti hai.** Kam volume par idle GPUs tokens se kahin zyada kharchte hain.
- **Ye ignore karna ki ise kaun chalayega.** Self-hosted model jise client mein koi upgrade nahi kar sakta, ek liability ban jaata hai.
- **"Open-weight" ko "koi licence terms nahi" samajhna.** Har model ka licence commercial use limits ke liye padho.
- **Baaki stack bhool jaana.** Traces, logs aur vector stores par wahi rules lagne chahiye jo model par.
- **Idle ghante aur ise chalane waale logon ko ginti mein liye bina GPU cost ko API cost se compare karna.**
- **Offline rehearsal ke bina air-gapped installs,** jo pehle chhoote package par fail ho jaate hain.
- **Self-hosted ya offline setups mein models ke liye upgrade path nahi.**

## Jab choice simple hai

- **Kam ya anishchit volume aur koi strict data rules nahi**: API ya client ki cloud model service se shuru karo.
- **Data premises se kabhi nahi ja sakta**: self-hosted ya air-gapped, cost chaahe jo ho.
- **Value saabit karne ke liye pilot**: jo sabse tez option allowed hai use karo, scale karne se pehle dobara dekho.

## Demo se production tak

- **Data rules aur decision ko** dates aur sahmat hone waale logon ke saath record karo.
- Pehle kuch mahine ke baad asli volumes ke saath **cost comparison dobara karo**.
- Hybrid setups mein har request ka **route log karo**.
- Offline aur self-hosted upgrades ke liye **ek tested bundle process** rakho.
- Jo bhi option chuno, **model versions pin karo aur test karo**.
