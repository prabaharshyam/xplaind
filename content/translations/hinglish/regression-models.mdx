## Ye kya hai

**Regression** features se ek number predict karta hai: delivery ka samay, price, agle hafte ki demand. **Linear regression** maanta hai ki prediction features ka weighted sum aur ek constant hai:

predicted delivery minutes = 6 + 2.1 × distance in km + 0.4 × items + 3 × (rain? 1 or 0)

Har weight ek **coefficient** hai. Ye batata hai ki baaki features ko fixed rakhkar, us feature ki ek unit badalne par prediction kitna badalta hai. Yahaan ek extra km 2.1 minutes jodta hai aur baarish 3. Training wo weights dhoondhti hai jo puraane data mein predictions ko asli values ke sabse kareeb le aayein.

Doosre regression models (decision trees, gradient boosting, neural networks) curves aur interactions ko follow kar sakte hain. Phir bhi shuruaat linear regression se hi hoti hai: ye fast hai, samjhaana aasaan hai, aur yahi wo baseline hai jise kisi bhi complex model ko haraana hota hai.

```text
  price
   |                                  *
   |                          *   *
   |                 *    * /        <- fitted line: price = a + b x feature
   |          *    *   /  *
   |     *      /  *
   |   *    /                  residual = actual - predicted
   |    /  *                   (vertical gap from point to line)
   +-------------------------------- car age, km, ...
```

Kisi asli point aur line ke beech ka gap **residual** hai. Is lesson mein lagbhag sab kuch residuals ko imaandaari se maapne aur unke patterns padhne ke baare mein hai.

Ye lesson Chennai ke ek used-car marketplace ko follow karta hai jo sellers ke liye suggested-price feature bana raha hai.

## Ye kaam kaise karta hai

```flow
dir: LR
title: Regression loop
Samay ke hisaab se split -> Baseline
Baseline -> Linear model
Linear model -[residuals padho]-> Features ya target theek karo
Features ya target theek karo -> Tree model
Tree model -[latest months par compare karo]-> Ship karo aur monitor karo
```

### Fitting

Aam loss **mean squared error** (MSE) hai: predicted aur asli values ke gaps ke squares ka average. Square karne se ₹2 lakh ki galti ₹1 lakh ki galti se chaar guna gini jaati hai, isliye line badi errors ki taraf jhukti hai. scikit-learn jaisi libraries ise ek call mein fit kar deti hain.

### Data ko split karna

Hamesha us data par evaluate karo jis par model ne train nahi kiya. Jo bhi cheez samay ke saath badalti hai (prices, demand, delivery ka samay), uska test set **latest** period hona chahiye: puraane months par train karo, sabse haal ke months par test karo. Random split months ko mila deta hai, toh model test months ka price level pehle hi dekh chuka hota hai. Phir uska score usse behtar dikhta hai jo agle mahine hoga, jab market aage badh chuka hoga. Ye data leakage ka ek roop hai.

### Error maapna

- **MAE** (mean absolute error): errors ka average size, original units mein. "Ausatan ₹59,000 ki galti" business team ko samjhaana aasaan hai.
- **RMSE** (root mean squared error): MSE ka square root, ye bhi original units mein. Ye hamesha kam se kam MAE jitna bada hota hai. Dono ke beech bada gap ho toh matlab kuch predictions bahut zyada galat hain.
- **MAPE** (mean absolute percentage error): "ausatan 11% ki galti". Tab kaam ka hai jab values sasti se mehengi tak hon, lekin jab asli values zero ke paas hon toh ye toot jaata hai.
- **R²**: explain hue variation ka hissa. Ye zyada se zyada 1 hota hai. Test data par ye **negative** bhi ho sakta hai, yaani model average predict karne se bhi bura hai. Ek hi data par models ki tulna ke liye kaam ka hai, lekin business users ko ye kam hi samajh aata hai.

| Measure | Aise padho | Kab use karo |
| --- | --- | --- |
| MAE | "Ausatan ₹59,000 ki galti" | Jab aisa number chahiye jo business users samjhein |
| RMSE | MAE jaisa, lekin badi galtiyaan zyada gini jaati hain | Jab badi errors khaas taur par mehengi hon, jaise refunds ya buy-back guarantees |
| MAPE | "Ausatan 11% ki galti" | Jab values kabhi zero ke paas na hon aur percentage error hi maayne rakhta ho |
| R² | Explain hue variation ka hissa | Ek hi test data par models ki tulna karte samay |

**Ek decision rule.** Wo metric chuno jo galti ki keemat se mel khaaye. Agar error ke har rupee ki keemat baraabar hai, toh MAE use karo. Agar ₹3 lakh ki ek galti ₹1 lakh ki teen galtiyon se zyada chot karti hai, toh RMSE par nazar rakho. Har baar model ke bagal mein median baseline bhi report karo.

### Coefficients padhna

Coefficients units par aur model mein maujood baaki features par nirbhar karte hain. Jab do features ek hi jaankaari rakhte hain (distance aur travel time, ya car ki age aur kilometres), toh model unke beech weight idhar-udhar kar sakta hai. Tab predictions milti-julti rehti hain, phir bhi coefficients ek sample se doosre mein jhoolte rehte hain. Ise **multicollinearity** kehte hain. Ise pakadne ke liye features ke beech correlations check karo, ya har feature ka variance inflation factor (VIF) nikaalo. Ek aam rule of thumb mein VIF 4 se upar ho toh dekhne laayak, aur 10 se upar ho toh gambhir maana jaata hai. Theek karne ke liye overlap karne waale features mein se ek ko hatao ya unhe mila do.

Coefficients association batate hain, kaaran nahi. Agar un par confidence intervals chahiye, toh aam formulas maante hain ki errors ek-doosre se independent hain aur har jagah unka phailaav lagbhag baraabar hai. Ek hi car ki baar-baar bikri, ya price ke saath badhti errors, in assumptions ko tod deti hain.

### Residual patterns aur kya karein

Residuals ko har feature ke saamne aur predicted value ke saamne plot karo.

- **Ek random cloud:** model ne pattern pakad liya hai.
- **Ek curve:** non-linear effect. Ek transformed feature jodo (distance squared, age bands) ya tree model try karo.
- **Ek funnel** (price badhne ke saath errors badhti hain): errors anupaat mein hain. Target ka log model karo.
- **Badi errors ka ek cluster:** koi group jise model theek se nahi sambhaalta, jaise koi ek brand, ya koi data problem.
- **Kuch extreme points:** squared error unhe line ko kheenchne deta hai. Pehle unki jaanch karo. Unhe tabhi hatao jab wo data errors hon (₹50 ki listing, 9,99,999 km waali car); warna robust loss par vichaar karo.

### Log targets aur waapsi ka raasta

Used-car prices skewed hoti hain: bahut saari sasti cars aur mehengi cars ki ek lambi tail. log(price) par train karne se model percentage errors fit karta hai. Isse "har saal price 11% ghatta hai" ek seedhi line ban jaata hai, aur model kabhi negative price predict nahi karta.

Pench waapsi ke raaste mein hai. Predicted log price ka exp lene par un features ke liye lagbhag **median** price milta hai, mean nahi. Mean paane ke liye training data par exp(residual) ke average se multiply karo. Ise smearing correction kehte hain. Log errors chhoti hon toh correction chhota hota hai, aur badi hon toh badh jaata hai.

### Regularisation aur scaling

**Ridge** aur **lasso** regression coefficients ke size par penalty jodte hain. Isse overfitting ghatti hai jab features bahut hon ya overlap karte hon. Lasso kuch coefficients ko theek zero kar sakta hai, jisse wo features hat jaate hain. Penalty ki taakat (alpha) cross-validation se chuni jaati hai, aur `RidgeCV` ye aapke liye kar deta hai.

Penalty coefficient ke size par lagti hai, aur size units par nirbhar karta hai. Prati kilometre coefficient bahut chhota hota hai aur prati saal coefficient bada, isliye scaling ke bina wo baraabar nahi sikudte. Pipeline mein ridge ya lasso se pehle hamesha `StandardScaler` lagao. Tree models thresholds par split karte hain, isliye unhe scaling ki zaroorat nahi.

### Linear regression se aage kab jaayein

Gradient boosting jaise tree-based models par tab jaao jab residual plots mein curves ya interactions (ek effect doosre par nirbhar kare) dikhein jinhe kuch features se theek na kar sako, ya jab bahut saare mixed features hon. Phir bhi linear model ko apni report mein rakho. Agar complex model thode se hi jeetta hai, toh zyada simple waala behtar product ho sakta hai.

Prices ke liye trees ki ek limit maayne rakhti hai: wo training mein dekhi sabse oonchi values se upar predict nahi kar sakte. Linear model kisi trend ko extrapolate kar sakta hai, achhe ke liye ya bure ke liye.

### Code: baseline, linear, log target aur boosting

24 months ki synthetic used-car sales. Age ke saath prices girti hain, premium 2,000 cc cars zyada tezi se value khoti hain, aur poora market dheere-dheere upar drift karta hai. Test set aakhri 4 months hai.

```python
import numpy as np, pandas as pd
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.dummy import DummyRegressor
from sklearn.linear_model import RidgeCV
from sklearn.compose import TransformedTargetRegressor
from sklearn.ensemble import HistGradientBoostingRegressor
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score

rng = np.random.default_rng(5)
n = 8000
df = pd.DataFrame({
    "month": rng.integers(0, 24, n),      # sale month: 0 is the oldest
    "age": rng.uniform(0, 12, n),         # years
    "km": rng.uniform(5_000, 150_000, n),
    "engine_cc": rng.choice([1000, 1200, 1500, 2000], n),
    "metro": rng.integers(0, 2, n),       # 1 if sold in a metro city
})
rate = 0.10 + 0.06 * (df.engine_cc == 2000)   # premium cars lose value faster
price = (900_000 * np.exp(-rate * df.age) * (df.engine_cc / 1200)
         * (1 - df.km / 600_000) * (1 + 0.05 * df.metro) * (1 + 0.004 * df.month))
df["price"] = price * rng.lognormal(0, 0.12, n)

features = ["age", "km", "engine_cc", "metro"]
train, test = df[df.month < 20], df[df.month >= 20]   # older sales vs latest 4 months
X_tr, y_tr, X_te, y_te = train[features], train.price, test[features], test.price

alphas = np.logspace(-3, 3, 13)
models = {
    "median baseline": DummyRegressor(strategy="median"),
    "ridge": make_pipeline(StandardScaler(), RidgeCV(alphas=alphas)),
    "ridge, log target": TransformedTargetRegressor(
        make_pipeline(StandardScaler(), RidgeCV(alphas=alphas)), func=np.log, inverse_func=np.exp),
    "boosting": HistGradientBoostingRegressor(max_iter=300, random_state=5),
}
for name, m in models.items():
    pred = m.fit(X_tr, y_tr).predict(X_te)
    mae, rmse = mean_absolute_error(y_te, pred), mean_squared_error(y_te, pred) ** 0.5
    print(f"{name:<18} MAE ₹{mae:>9,.0f}  RMSE ₹{rmse:>9,.0f}  R² {r2_score(y_te, pred):6.2f}")
```

scikit-learn 1.9.1 ke saath output:

```text
median baseline    MAE ₹  201,364  RMSE ₹  274,141  R²  -0.07
ridge              MAE ₹   97,976  RMSE ₹  129,071  R²   0.76
ridge, log target  MAE ₹   80,155  RMSE ₹  109,775  R²   0.83
boosting           MAE ₹   59,212  RMSE ₹   82,164  R²   0.90
```

Dhyaan do ki baseline ka R² negative hai: puraani sales se liya ek constant andaaza test months ke apne average price se bhi bura karta hai.

**Group ke hisaab se errors.** Ek average us segment ko chhipa sakta hai jise model galat karta hai. Yahaan percentage error zyada fair hai, kyunki mehengi cars ki rupee errors zyada badi hoti hain:

```python
lin, best = models["ridge, log target"], models["boosting"]
pct = pd.DataFrame({
    "ridge_log": np.abs(lin.predict(X_te) - y_te) / y_te,
    "boosting": np.abs(best.predict(X_te) - y_te) / y_te,
})
print((pct.groupby(X_te.engine_cc).mean() * 100).round(1))
```

```text
engine_cc

```

**Linear model padhna.** Scaled pipeline ke coefficients prati standard deviation hote hain. Unhe waapas asli units mein laane ke liye scaler ke phailaav se divide karo:

```python
ridge = lin.regressor_
coef = ridge[-1].coef_ / ridge[0].scale_
print(f"per year: {np.expm1(coef[0]):.1%}   per 10,000 km: {np.expm1(coef[1] * 10_000):.1%}   "
      f"metro: {np.expm1(coef[3]):+.1%}   alpha chosen: {ridge[-1].alpha_:.2f}")
```

```text
per year: -10.8%   per 10,000 km: -1.8%   metro: +5.6%   alpha chosen: 0.32
```

**Ek point ki jagah price range.** Sellers aur buyers ek number se zyada ek band par bharosa karte hain:

```python
q = dict(loss="quantile", max_iter=300, random_state=5)
lo = HistGradientBoostingRegressor(quantile=0.1, **q).fit(X_tr, y_tr).predict(X_te)
hi = HistGradientBoostingRegressor(quantile=0.9, **q).fit(X_tr, y_tr).predict(X_te)
print(f"inside the 10-90% band: {((y_te >= lo) & (y_te <= hi)).mean():.0%}   "
      f"above the top: {(y_te > hi).mean():.0%}")
```

```text
inside the 10-90% band: 66%   above the top: 25%
```

Theek se calibrated 10 se 90% band mein lagbhag 80% asli prices aati hain, aur lagbhag 10% uske upar rehti hain. Is band mein 66% aati hain, aur asli prices ka ek chauthaai top se upar hai. Iski do wajahein hain. Random split par bhi ye band sirf lagbhag 70% pakadta hai, kyunki quantile models aksar bahut narrow hote hain. Time split ise aur bigaad deta hai, kyunki training months ke baad prices badh gayin. Users ko ranges dikhaane se pehle, haal ke ek validation month se band ko chauda karo, aur baar-baar retrain karo.

**Kinaaron ki hifaazat karo.** Training data mein har feature ki range record karo. Uske baahar ki requests (25 saal puraani car, 4,00,000 km) ko confident price dene ki jagah flag karo.

## Ek example se samjho

Chennai marketplace ki team upar waale code ko apne pehle experiment ki tarah use karti hai. Data synthetic hai, isliye numbers method ki misaal hain, kisi asli market ke nateeje nahi. Outputs ko kram se padho.

1. **Baseline.** Har baar median price predict karne par MAE ₹2,01,364 aata hai. Kisi bhi kaam ke model ko ise bade antar se haraana hoga.
2. **Linear regression** (scaled, ridge) error ko aadha karke ₹97,976 kar deta hai. Cross-validation ne chhota alpha chuna, isliye yahaan penalty ne mushkil se kuch badla: chaar features aur hazaaron rows ke saath overfit karne ko zyada kuch hai hi nahi.
3. **Log target.** Prices har saal ek percentage girti hain, jo rupees mein curve hai lekin log price mein seedhi line. MAE ghatkar ₹80,155 ho jaata hai. Model ek padhne laayak kahaani bhi deta hai: age ke har saal par lagbhag 10.8% kam, har 10,000 km par 1.8% kam, aur metro cities mein 5.6% zyada.
4. **Error analysis.** Group table dikhaati hai ki 1,500 cc aur 2,000 cc cars ke liye linear model ka percentage error lagbhag 12% se uchhalkar 17 se 18% ho jaata hai. Iski do wajahein hain. Engine size ka log price par seedhi line waala effect nahi hai, aur premium cars zyada tezi se depreciate hoti hain, jo ek interaction hai jise saada linear model represent nahi kar sakta.
5. **Gradient boosting** data se dono effects seekh leta hai. MAE ghatkar ₹59,212 ho jaata hai, har engine group mein lagbhag 11% error, aur R² badhkar 0.90 ho jaata hai.
6. **Imaandaari ke checks.** Training months par boosted model ka MAE lagbhag ₹40,500 hai, jo latest months ke ₹59,212 se kaafi kam hai. Time split ki jagah random split karne par lagbhag ₹55,000 aata hai, jo asliyat se behtar dikhta hai. Price band sirf 66% asli prices ko cover karta hai, 80% ko nahi.

| Model | Test MAE | Test RMSE | Team ne isse kya seekha |

| Median baseline | ₹2,01,364 | ₹2,74,141 | Haraane laayak paimaana |

**Kya ship hota hai.** Boosted model suggested price tay karta hai, jo chaudi ki gayi range ke roop mein dikhti hai. Sellers ko dikhne waali explanation log-linear coefficients se aati hai ("har extra saal aam taur par price lagbhag 11% ghataata hai"), saaf taur par approximate label ke saath. Do kaamon ke liye do models use karna aam hai: number ke liye sabse accurate waala, aur imaandaar explanation ke liye ek zyada simple waala. Team har mahine retrain karti hai, kyunki drift ne dikhaaya ki pichhli quarter ki prices puraani pad jaati hain.

## Aam galtiyaan

- **Koi baseline nahi.** Model ke bagal mein "hamesha median predict karo" na ho, toh aap nahi bata sakte ki wo value jodta hai ya nahi.
- **Training data par evaluate karna.** Errors asliyat se kaafi chhoti dikhti hain, jaisa ₹40,500 aur ₹59,212 ka gap dikhata hai.
- **Samay ke kram waale data par random split.** Market prices drift hoti hain. Pehle ke months par train karo aur latest months par test karo.
- **Coefficients ko kaaran maanna.** Wo model ki assumptions ke tahat association batate hain, aur features overlap karein toh jhoolte hain.
- **Scaling ke bina ridge ya lasso.** Tab penalty units par nirbhar karti hai, is par nahi ki feature kitna kaam ka hai.
- **Skewed targets ko nazarandaaz karna.** Log price predict karna aksar behtar kaam karta hai, lekin yaad rakho ki prediction ka exp median ke paas hai, mean ke nahi.
- **Extrapolations par bharosa karna.** Training range ke baahar ki predictions andaaze hain.
- **Sirf R², ya sirf overall MAE report karna.** Business users "ausatan ₹59,000 ki galti" samajhte hain, aur ek akela average badi errors waale segment ko chhipa sakta hai.
- **Jin decisions ko range chahiye unke liye point predictions**, jaise price ki salaah, ya aisi ranges jinki coverage kisi ne check nahi ki.

## Jab regression model ki zaroorat nahi

- **Koi simple formula pehle se maujood hai**, jaise tariff table ya chhapa hua rate card.
- **Seekhne ke liye bahut kam data**: domain experts ka rule of thumb zyada bharosemand ho sakta hai.
- **Sawaal ek category hai**, number nahi, jaise "kya ye is hafte bikegi": classification use karo.

- **Segment ke hisaab se errors check karo**, aur feature range ke hisaab se bhi, har retrain par.
- **Out-of-range inputs ko flag karo**, predict karne ki jagah.
- **Jahaan decisions uncertainty par nirbhar hon wahaan ranges do**, aur har mahine unki coverage check karo.
- **Asli nateeje aane ke saath errors monitor karo**, aur market drift ho toh retrain karo.

## Practice karo

Google ka linear regression module aur Kaggle ka Intro to Machine Learning course poora karo.

1. Upar ke chaaron code blocks chalao. Phir `month` ko feature ke roop mein jodo aur dobaara chalao. Kaun-se models behtar hote hain, aur boosting training months ke aage trend ko follow kyun nahi kar paata?
2. Date column waale kisi public housing ya used-car dataset par linear regression fit karo. Latest period par MAE aur RMSE report karo aur median baseline se tulna karo.
3. Residuals ko do features aur predicted value ke saamne plot karo. Ek pattern (curve, funnel ya cluster) ka naam batao aur wo fix jo aap try karoge.
4. Apne dataset mein har feature ka VIF nikaalo aur batao ki kaun-si jodi sabse zyada overlap karti hai.
5. 10% aur 90% quantile models fit karo aur har age band ke liye band ki coverage report karo.

**Aapka kaam poora hai jab aap** apne best model ki error ko business ki bhaasha mein samjha sako, dikha sako ki wo latest period par baseline ko haraata hai, aur ek wajah bata sako ki linear model kahaan peeche reh gaya.
