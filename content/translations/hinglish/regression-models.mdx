## Ye kya hai

**Regression** features se ek number predict karta hai. **Linear regression** maanta hai ki prediction features ka weighted sum plus ek constant hai:

predicted delivery minutes = 6 + 2.1 × distance in km + 0.4 × items + 3 × (rain? 1 or 0)

Weights (coefficients) batate hain ki baaki features ko fixed rakhne par, har feature ki ek unit par prediction kitna badalta hai. Training woh weights dhoondhti hai jo purane data par predictions ko actual values ke sabse kareeb laate hain.

Doosre regression models (decision trees, gradient boosting, neural networks) curves aur interactions pakad sakte hain, par linear regression woh baseline hai jise haraana hai aur jise samjhana sabse aasaan hai.

```text
  price
   |                                  *
   |                          *   *
   |                 *    * /        <- fitted line: price = a + b x feature
   |          *    *   /  *
   |     *      /  *
   |   *    /                  residual = actual - predicted
   |    /  *                   (vertical gap from point to line)
   +-------------------------------- car age, km, ...
```

Ye lesson Chennai ke ek used-car marketplace ko follow karta hai, jo sellers ke liye suggested-price feature bana raha hai.

## Ye kaam kaise karta hai

**Fitting.** Aam loss mean squared error hai: predicted aur actual values ke beech ke farak ke squares ka average. Square karne se bade errors ko bahut sazaa milti hai. scikit-learn jaisi libraries ise ek call mein fit kar deti hain.

**Evaluating.** Hamesha us data par jis par model ne train nahi kiya.

- **MAE** (mean absolute error): errors ka average size, original units mein ("average 3.2 minute ka farak"). Samjhana aasaan.
- **RMSE** (root mean squared error): MAE jaisa, par bade errors ko zyada sazaa deta hai.
- **R²**: kitni variation explain hui, 0 (average predict karne se behtar nahi) se 1 tak. Useful hai par business users ke liye intuitive nahi.

Ek simple baseline se compare karo, jaise har baar median predict karna. Agar aapka model usse bas thoda hi behtar hai, toh woh zyada kuch add nahi kar raha.

**Coefficients padhna.** Coefficients units aur doosre features par depend karte hain. Correlated features (distance aur travel time) coefficients ko unstable bana dete hain. Unhe causes ki tarah mat padho.

**Non-linearity.** Real relationships mudte hain: delivery time 5 km tak dheere badhta hai, phir achanak kood sakta hai. Transformed features (distance squared, buckets) jodo, ya tree-based models use karo.

**Outliers.** Squared error kuch extreme values ko fit ko kheench lene deta hai. Unki jaanch karo; data errors ko cap ya remove karo; MAE-based ya robust methods sochho.

**Extrapolation.** Linear models khushi-khushi us range ke bahar bhi predict kar dete hain jo unhone dekhi thi (training mein zyada se zyada 12 tha aur 40 km ki deliveries). Aisi predictions bharose ke laayak nahi hoti.

**Regularisation.** Ridge aur lasso regression bahut saare features hone par overfitting kam karne ke liye coefficients ko shrink karte hain; lasso kuch ko zero bhi kar sakta hai.

**Error measure chunna:**

| Measure | Kaise padhein | Kab use karo |
| --- | --- | --- |
| MAE | "Average ₹29,000 ka farak" | Aap business users ko samajh aane wala number chahte ho |
| RMSE | MAE jaisa, par bade misses zyada gine jaate hain | Bade errors khaas taur par mehnge hain |
| MAPE | "Average 6% ka farak" | Values kabhi zero ke paas nahi hoti |
| R² | Explain hui variation ka hissa | Same data par models compare karne ke liye |

**Residuals padhna.** Errors ko har feature ke saamne plot karo. Random cloud ka matlab model ne pattern pakad liya hai. Curve, funnel ya cluster ka matlab kuch chhoot gaya: non-linear effect, koi group jise model buri tarah handle karta hai, ya data problem.

**Linear regression se aage kab jaayein.** Linear regression fast hai, samjhane layak hai aur strong baseline hai. Tree-based models jaise gradient boosting par tab jao jab residual plots mein aise curves ya interactions dikhein jo line pakad nahi sakti, jab aapke paas mixed types ke bahut saare features hon, ya jab accuracy ka fayda extra complexity ke laayak ho. Phir bhi apne evaluation mein linear model chalate raho: agar complex model use bas thoda hi harata hai, toh simple wala product ke liye behtar choice ho sakta hai.

**Baseline, linear, log target aur boosting, ek saath.** Curved age effect wali synthetic used-car prices:

```python
import numpy as np, pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.dummy import DummyRegressor
from sklearn.linear_model import Ridge
from sklearn.compose import TransformedTargetRegressor
from sklearn.ensemble import HistGradientBoostingRegressor
from sklearn.metrics import mean_absolute_error, mean_squared_error

rng = np.random.default_rng(5)
n = 6000
df = pd.DataFrame({"age": rng.uniform(0, 12, n), "km": rng.uniform(5_000, 150_000, n),
                   "engine_cc": rng.choice([1000, 1200, 1500, 2000], n), "city_metro": rng.integers(0, 2, n)})
price = 900_000 * np.exp(-0.12 * df.age) * (df.engine_cc / 1200) * (1 - df.km / 600_000) * (1 + 0.05 * df.city_metro)
y = price * rng.lognormal(0, 0.12, n)
X_tr, X_te, y_tr, y_te = train_test_split(df, y, test_size=0.25, random_state=5)

models = {
    "median baseline": DummyRegressor(strategy="median"),
    "ridge": Ridge(alpha=1.0),
    "ridge, log target": TransformedTargetRegressor(Ridge(alpha=1.0), func=np.log, inverse_func=np.exp),
    "boosting": HistGradientBoostingRegressor(max_iter=300, random_state=5),
}
for name, m in models.items():
    pred = m.fit(X_tr, y_tr).predict(X_te)
    print(f"{name:<18} MAE ₹{mean_absolute_error(y_te, pred):>9,.0f}   RMSE ₹{mean_squared_error(y_te, pred) ** 0.5:>9,.0f}")
```

Table har step ki value dikhati hai: model "hamesha median predict karo" ko kitna harata hai, aur log target ya tree model curve ko behtar pakadta hai ya nahi.

**Group ke hisaab se errors.** Ek average aisa segment chhupa sakta hai jisme model galat hai:

```python
best = models["boosting"]
err = pd.DataFrame({"abs_err": np.abs(best.predict(X_te) - y_te), "age_band": pd.cut(X_te.age, [0, 3, 6, 9, 12])})
print(err.groupby("age_band", observed=True)["abs_err"].mean().round(-2))
```

**Ek point ki jagah price range.** Buyers aur sellers ek band par bharosa karte hain:

```python
lo = HistGradientBoostingRegressor(loss="quantile", quantile=0.1, max_iter=300).fit(X_tr, y_tr)
hi = HistGradientBoostingRegressor(loss="quantile", quantile=0.9, max_iter=300).fit(X_tr, y_tr)
inside = ((y_te >= lo.predict(X_te)) & (y_te <= hi.predict(X_te))).mean()
print(f"share of real prices inside the 10–90% band: {inside:.0%}")      # should be near 80%
```

Agar real prices ka 80% se bahut kam hissa band ke andar girta hai, toh intervals bharose ke liye bahut tang hain.

**Edges ki hifazat karo.** Training data mein har feature ki range record karo, aur range ke bahar ki requests (25 saal puraani car, 400,000 km) ko confident price lautane ke bajaay flag karo.

## Ek example se samjho

Chennai ka ek used-car marketplace listing prices suggest karna chahta hai.

Data: 18,000 purani sales, car age, chalaye gaye kilometres, brand, model, fuel type, city aur owners ki sankhya.

1. Baseline: model aur year ke liye median price predict karo. MAE ₹68,000.
2. Features par linear regression (brand aur model one-hot encoded, aur price ka log target kyunki prices skewed hain). MAE ₹41,000.
3. Error analysis: errors premium cars aur 12 saal se puraani cars mein sabse bade hain. Age ke saamne residuals ka plot ek curve dikhata hai.
4. Wahi features par gradient-boosted trees. MAE ₹29,000.

Team prices ke liye boosted model ship karti hai, par sellers ko dikhaye jaane waale explanation ke liye linear model ke coefficients rakhti hai ("is model ke liye har extra saal price ko lagbhag 9% kam karta hai"), jise saaf taur par approximate label kiya gaya hai.

| Model | MAE | Notes |
| --- | --- | --- |
| Model aur year ke liye median price | ₹68,000 | Baseline |
| Linear regression, log price | ₹41,000 | Samjhane layak coefficients |
| Gradient-boosted trees | ₹29,000 | Puraani aur premium cars ke curves pakadta hai |

Do kaamo ke liye do models ship karna common hai: number ke liye sabse accurate wala, aur ek imaandaar, approximate explanation ke liye simple wala.

## Aam galtiyaan

- **Baseline na hona.** Iske bina aap model ko judge nahi kar sakte.
- **Training data par evaluate karna.** Errors asliyat se bahut chhote dikhte hain.
- **Coefficients ko causes samajhna.** Ye model ki assumptions ke andar association batate hain.
- **Skewed targets ko ignore karna.** Prices ka log predict karna aksar behtar kaam karta hai.
- **Extrapolations par bharosa karna.** Training range ke bahar ki predictions andaaze hain.

- **Sirf R² report karna.** Business users "R² 0.87" se kaafi behtar "average ₹29,000 ka farak" samajhte hain. Uske saath rupees ya minutes mein MAE bhi report karo.
- **Median baseline se kabhi compare na karna.** Pata hi nahi chalta ki model value add karta hai ya nahi.
- **Sirf overall MAE report karna**, jo bade errors wale segment ko chhupa deta hai.
- **Aise decisions ke liye point predictions jahan range chahiye**, jaise price advice.

## Jab regression model ki zaroorat nahi

- **Simple formula pehle se hai**, jaise tariff table ya published rate card.
- **Seekhne ke liye data bahut kam hai**: domain experts ka rule of thumb zyada bharosemand ho sakta hai.
- **Sawaal category ka hai, number ka nahi**, jaise "kya ye is hafte bikega": classification use karo.

## Demo se production tak

- **Har report mein baseline rakho.**
- **Har retrain par segment aur feature range ke hisaab se errors check karo.**
- **Range ke bahar ke inputs ko predict karne ki jagah flag karo.**
- **Jahan decisions uncertainty par depend karte hain wahan ranges do**, aur unki coverage check karo.
- **Real outcomes aate hi errors monitor karo.**
