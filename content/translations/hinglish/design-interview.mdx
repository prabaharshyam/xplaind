## Ye kya hai

Kai AI engineering interviews mein ab ek **design round** hota hai. Aapse poocha ja sakta hai "Bank ke liye customer-support assistant design karo", "10 million documents par sawaalon ke jawab dene wala system design karo" ya "Travel book karne wala agent kaise banaoge?" Aapko 30 se 45 minute aur ek whiteboard ya shared document milta hai, aur interviewer beech mein "what if...?" bol kar interrupt karega.

Woh kisi ek tool ki knowledge se zyada structured thinking, sahi trade-offs aur production awareness test karte hain.

| Minutes | Step | Kya cover karna hai |
|---|---|---|
| 0-5 | Clarify | Users, scale, latency, cost, languages, data rules, success |
| 5-10 | High level | Boxes aur arrows: channel, API, routing, tools ya RAG, model, reply |
| 10-28 | Deep dives | Is problem ke liye sabse zaroori 2-3 hisse |
| 28-31 | Failures | Hallucination, injection, outage, cost, privacy |
| 31-34 | Evals aur ops | Test set, metrics, launch bar, monitoring, rollout |
| 34-35 | Trade-offs | Zyada time hota toh, aur 10x scale par |

Jab interviewer "what if...?" poochhe, use naya requirement maan kar design ko badlo.

## Ye kaam kaise karta hai

**Ek bharosemand structure.**

1. **Clarify (3 se 5 minute).** Users, task, scale (users, documents, requests per second), latency aur cost constraints, languages, data sensitivity, success ka matlab. Poochho, phir assumptions zor se bolo.
2. **High-level design (5 minute).** Gehraai mein jaane se pehle mukhya components aur request flow ka sketch banao.
3. **Deep dives (15 se 20 minute).** Is problem ke liye sabse zaroori hisse: aksar retrieval (ingestion, chunking, hybrid search, reranking, permissions), generation (prompting, grounding, model choice), tools ya agents, aur evaluation.
4. **Failure modes aur safety (5 minute).** Hallucination, injection, outages, cost spikes, privacy.
5. **Evaluation aur operations (5 minute).** Test sets, metrics, launch bar, monitoring, rollout.
6. **Trade-offs aur next steps (2 minute).** Zyada time ya das guna scale par aap kya karoge.

**Achhe score dilaane wali aadatein.**

- Zor se socho; trade-offs ka naam lo ("hybrid search thoda zyada kharcha karta hai, par policy numbers pakad leta hai").
- Numbers use karo: rough token counts, costs, latency budgets.
- Simple se shuru karo, aur complexity wahin jodo jahan requirements maangein.
- Interruptions ka jawab naye requirements ki tarah do, attack ki tarah nahi.
- Time par nazar rakho; chunking par 25 minute mat lagao.

**Practice ke liye common sawaal.** Company documents par RAG; actions wala customer-support assistant; lambe documents ka summary; coding assistant; India ke liye multilingual chatbot; tools wala agent; model upgrade evaluate karna; cost aadhi karna.

**Zor se practice karo.** Khud ko record karo ya kisi dost ke saath practice karo. Design bolna ek alag skill hai, design jaanne se.

**Interviewers kaunse signals dekhte hain:**

| Strong signal | Weak signal |
| --- | --- |
| Pehle users, scale aur data rules poochhta hai | Tools ke naam lena shuru kar deta hai |
| Assumptions numbers ke saath bolta hai | Numbers se bachta hai |
| Samjhata hai ki har choice is problem ko kyun suit karti hai | Technologies ki list deta hai |
| Failure modes aur evaluation cover karta hai | Happy path par ruk jaata hai |
| "What if" par shaanti se adapt karta hai | Pehle design ko ada kar defend karta hai |
| Saare hisson mein time baantta hai | Zyadatar time ek box par lagata hai |

**Partner ke saath practice.** Har session mein roles badlo. Interviewer ek aisa prompt chunta hai jo candidate ne nahi dekha, har phase ka time rakhta hai, aur do baar "what if" sawaalon se interrupt karta hai, jaise outage, nayi language ya das guna traffic. Baad mein interviewer teen notes deta hai: ek cheez jo achhi ki, ek gap, ek aadat jo badalni hai. Interviewer banne se pata chalta hai ki ek saaf jawab kaisa sunai deta hai.

**Estimates jaldi lagana.** Kuch back-of-the-envelope numbers tab tak practice karo jab tak woh bina socche na aane lagein. Jaano ki ek page text mein kitne tokens hote hain, daily users se requests per second, tokens aur prices se cost per request, aur kisi model size ke liye kitni GPU memory chahiye. Interviewers ko exact figures nahi chahiye; woh dekhna chahte hain ki aap orders of magnitude mein reason karte ho.

## Ek example se samjho

Prompt: "Ek state electricity board ke liye WhatsApp assistant design karo jo billing aur outage ke sawaalon ke jawab Tamil aur English mein de."

Ek achhe candidate ka summary:

- *Clarify*: 2 million consumers; bills issue hone ke baad aur outages ke dauraan peaks; tariffs par jawab accurate hone chahiye; outage data ek internal system mein; account sawaalon ke liye consumer number; data India mein hi rehna chahiye.
- *Design*: Provider ke zariye WhatsApp Business Platform → API service → intent routing (billing, outage, tariff FAQ, complaint) → bill lookup aur outage status ke tools (consumer number OTP se verify) → dono languages mein tariff orders aur FAQs par RAG → Indian region mein model → reply.
- *Deep dive*: Tamil aur English chunks ke saath bilingual retrieval; tariff tables dhyaan se extract karna; outage ke jawab sirf live tool se, kabhi generate nahi; complaints reference number ke saath log hoti hain aur logon ko di jaati hain.
- *Failures*: outage spikes (area ke hisaab se outage status cache karo, scale out), galat tariffs (citations, refusal, weekly review), injection (complaint logging ke alawa koi write tool nahi), provider outage (helpline ke saath fallback message).
- *Evaluation*: dono languages mein 300 real sawaal, intent ke hisaab se accuracy; pehle ek district mein launch.
- *Cost*: ek conversation ka rough estimate, aur expected volume par monthly total.

Interviewer poochhta hai, "agar outage system down ho toh?" Candidate jawab deta hai: last known status timestamp aur helpline ke saath dikhao, aur on-call ko alert karo.

| Phase | Electricity-board answer ne kya cover kiya |
| --- | --- |
| Clarify | 2 million consumers, bill-day aur outage peaks, Indian data residency |
| Design | WhatsApp provider, intent routing, OTP-verified tools, bilingual RAG |
| Deep dive | Outage ke jawab sirf live tool se; tariff tables dhyaan se extract |
| "Agar outage system down ho?" | Last known status timestamp ke saath, helpline, aur on-call alert |

## Aam galtiyaan

- **Clarify kiye bina details mein kood jaana.**
- **Choices samjhane ki jagah tools ke naam lena.**
- **Evaluation aur operations ko ignore karna.**
- **Numbers na dena.**
- **Ek component par time khatam kar dena.**
