## Ye kya hai

RAG system ke zyadatar galat answers retrieval se shuru hote hain: sahi passage mila hi nahi, isliye model use use nahi kar paya. **Retrieval check karna** ka matlab hai, test sawaalon ke ek fixed set se measure karna ki sahi passages wapas aa rahe hain ya nahi, aur ye final answer achha hai ya nahi usse alag dekhna.

```flow
Ek galat answer -> Kya sahi passage top k mein tha?
Kya sahi passage top k mein tha? -[nahi]-> Retrieval problem | chunking, embeddings, hybrid search, query rewriting, filters
Kya sahi passage top k mein tha? -[haan]-> Generation problem | prompt, grounding rules, citations, model choice
```

Ye lesson Kochi ke ek bank ko follow karta hai, jiska staff assistant apne circulars ke baare mein bahut galat answers de raha tha.

## Ye kaam kaise karta hai

**Test set banao.** 30 se 100 realistic sawaal collect karo, har ek ke saath woh passage ya passages jisme jawab hai. Jahan ho sake real user sawaal use karo, aur easy, hard, vague aur unanswerable sawaal bhi daalo. Set ko fixed rakho taaki changes ko fair tareeke se compare kar sako.

**Retrieval metrics.**

- **Recall at k**: kitne sawaalon ke liye kam se kam ek sahi passage top k results mein aata hai? Recall at 5 ek common headline number hai. Strictly, is "kam se kam ek" version ko hit rate bhi kehte hain; jab ek sawaal ke kai sahi passages ho, toh kuch tools recall at k ko unmein se mile hue passages ka hissa define karte hain.
- **Precision at k** ya **context precision**: retrieve kiye gaye k passages mein se kitne sach mein relevant hain? RAGAS ka context precision relevant wale ko upar rank karne ko bhi reward karta hai. Kam precision se prompts mein noise bhar jaata hai.
- **MRR** (mean reciprocal rank): sahi passage ko upar rakhne ko reward karta hai.

**Answer metrics**, alag se measure karo:

- **Faithfulness**: answer ke claims retrieve kiye gaye passages se support hote hain?
- **Answer correctness**: kya ye expected answer se match karta hai?

RAGAS jaise tools ye compute karte hain, aksar model ko judge banakar; ek sample haath se check karo.

**Split se diagnose karo.** Agar answer galat hai:

- sahi passage retrieve *nahi* hua → retrieval fix karo (chunking, embeddings, hybrid search, query rewriting, filters);
- sahi passage retrieve hua par answer galat → generation fix karo (prompt, grounding, model).

**Har change par run karo.** Chunk size, embedding model ya top-k badalne se kuch sawaalon ko help aur kuch ko hurt ho sakta hai. Fixed set net effect dikhata hai.

**Metrics ka ek chhota worked example.** Chaar test sawaal, har ek ke top 5 results; pehle sahi passage ki position dikhayi gayi hai:

| Sawaal | Pehla sahi passage kahan | Top 5 mein? | Reciprocal rank |
| --- | --- | --- | --- |
| Q1 | 1 | haan | 1.0 |
| Q2 | 3 | haan | 0.33 |
| Q3 | nahi mila | nahi | 0 |
| Q4 | 2 | haan | 0.5 |

Recall at 5 = 4 mein se 3 = 75%. MRR = (1.0 + 0.33 + 0 + 0.5) ÷ 4, lagbhag 0.46.

**Test set jaldi banana.** Support tickets, search logs ya chats ke real sawaalon se shuru karo. Har ek ke liye, documents jaanne wala koi insaan jawab wala passage dhoondhta hai aur uska document aur section record karta hai. 30 sawaal ek afternoon mein ho jaate hain. Aise sawaal bhi daalo jinka jawab documents mein nahi hai, expected passage "none" ke saath, taaki dekh sako ki system "mujhe nahi pata" kehta hai ya nahi. Jab bhi koi user galat answer report kare, ek naya sawaal jodo.

**Model ko judge banana.** RAGAS jaise tools faithfulness aur relevance ko bade scale par score karne ke liye model use karte hain. Kaam ke hain, par perfect nahi. 20 ka ek sample haath se score karke compare karo; agar judge insaanon se aksar alag nikle, toh uske numbers par bharosa karne se pehle uske instructions fix karo.

**Code mein metrics.** Har test case un passages ke ids list karta hai jo uska jawab dete hain; retriever ranked ids return karta hai:

```python
import math

def metrics(cases, retrieve, k=5):
    """cases: list of (question, set_of_relevant_ids). Empty set = unanswerable."""
    recall = precision = mrr = ndcg = 0.0
    answerable = [c for c in cases if c[1]]
    for q, relevant in answerable:
        ranked = retrieve(q)[:k]
        hits = [1 if r in relevant else 0 for r in ranked]
        recall += any(hits)
        precision += sum(hits) / k
        mrr += next((1 / (i + 1) for i, h in enumerate(hits) if h), 0)
        dcg = sum(h / math.log2(i + 2) for i, h in enumerate(hits))
        ideal = sum(1 / math.log2(i + 2) for i in range(min(len(relevant), k)))
        ndcg += dcg / ideal
    n = len(answerable)
    return {"recall@k": recall / n, "precision@k": precision / n, "mrr": mrr / n, "ndcg@k": ndcg / n}
```

Unanswerable cases jaanbujhkar in numbers se bahar rakhe gaye hain; unhe alag se check karo, ye dekhkar ki final answer "nahi pata" kehta hai ya nahi.

**Results ko todkar dekho.** Ek overall recall problems chhupa deta hai. Har sawaal ko tag karo (exact code, vague, Hindi, multi-part, recent policy) aur har tag ka recall report karo. Ingestion change ke baad "recent policy" sawaalon par recall girna aksar matlab hota hai ki naye documents index nahi hue.

```python
from collections import defaultdict

def by_tag(cases_with_tags, retrieve, k=5):
    groups = defaultdict(list)
    for q, rel, tag in cases_with_tags:
        groups[tag].append((q, rel))
    return {tag: metrics(cs, retrieve, k)["recall@k"] for tag, cs in groups.items()}
```

**Chhote sets noisy hote hain.** 30 sawaalon mein ek sawaal 3 points se zyada hota hai. 3-point ke change par na jashn manao na ghabrao; dekho kaunse sawaal palte aur kyun. Set ko waqt ke saath badhao, khaaskar un tags mein jo sabse zyada matter karte hain.

**Model se sawaal draft karwana.** Jaldi shuru karne ke liye, model ko ek passage do aur kaho ki woh do sawaal likhe jinka jawab usmein hai, waise words mein jaise user bolega. Phir koi insaan har ek ko edit ya reject kare, aur passage ko expected answer ki tarah record kare. Inhe synthetic mark karo aur logs se real sawaal jodte raho: models passage ke apne hi words reuse karte hain, jisse retrieval asal se aasaan dikhta hai.

**Retrieval aur answers saath mein.** Har case ke liye retrieved ids, answer aur verdicts store karo. Phir har galat answer ek nazar mein do buckets mein se ek mein girta hai: sahi passage missing tha (retrieval problem) ya maujood tha (generation problem).

## Ek example se samjho

Kochi ke ek bank ka internal assistant 900 circulars se staff ke sawaalon ke jawab deta hai. Staff shikayat karta hai ki answers aksar galat hote hain.

Team 60 sawaal likhti hai, har ek ke saath woh circular aur paragraph jisme jawab hai. Results:

- recall at 5: 63%;
- answers ki faithfulness: 0.92;
- correctness: 58%.

Faithfulness high hai, yaani model zyadatar wahi bolta hai jo retrieved passages bolte hain. Recall kam hai: sahi passages aksar aate hi nahi. Misses dekhne par pata chalta hai ki zyadatar mein circular numbers hain ("as per RBI/2026-27/41") aur haal hi mein revise hue circulars, jahan purane versions naye se upar rank hote hain.

Changes: circular numbers ke liye keyword matching wala hybrid search, aur superseded circulars ko hataane wala filter. Wahi 60 sawaalon par measure karne par recall at 5 87% aur correctness 81% tak badhti hai.

| Measure | Pehle | Hybrid search aur superseded filter ke baad |
| --- | --- | --- |
| Recall at 5 | 63% | 87% |
| Faithfulness | 0.92 | 0.93 |
| Correctness | 58% | 81% |

Model kabhi problem tha hi nahi; woh galat circulars se wafadari se jawab de raha tha.

**Misses padhna.** Team numbers par ruki nahi. Unhone un saare 22 sawaalon ko padha jinme top five mein sahi passage nahi tha, aur causes mein baanta: 9 mein circular numbers the jinhe embedding search exactly match nahi kar paya, 7 mein current circular se upar superseded circular retrieve hua, 4 vague sawaal the, aur 2 mein test set mein hi galat expected passage tha. Har cause ne alag fix ki taraf ishaara kiya, aur test set ki apni galtiyan theek karna is kaam ka normal hissa hai.

## Aam galtiyaan

- **Sirf final answers dekhna.** Aap nahi bata paoge ki retrieval fail hua ya generation.
- **Runs ke beech test set badalna.** Compare karne ke liye use fixed rakho.
- **Unanswerable sawaal na hona.** Refusals test karne ke liye unki zaroorat hai.
- **Automatic judges par aankh band karke bharosa karna.** Ek sample check karo.
- **Precision gir rahi ho aur sirf recall optimise karna.** Dono track karo.
- **Sirf easy sawaalon wale test sets.** Vague, multi-part aur unanswerable bhi daalo, jaise real users poochte hain.
- **Re-test se pehle kai cheezein badalna.** Ek setting badlo, set dobara run karo, numbers record karo, phir agla badlo.
- **Sirf synthetic sawaal**, jo documents ke apne words use karte hain aur retrieval ko achha dikhate hain.
- **Ek overall number.** Recall ko sawaal ke type ke hisaab se todkar dekho.
- **Unanswerable sawaalon ko recall mein milana**, jisse dono numbers chhup jaate hain.

## Jab halka check kaafi hai

- **Chhota prototype**: haath se check kiye gaye das sawaal bata dete hain ki retrieval mota-mota kaam kar raha hai ya nahi.
- **Aisa collection jo kam badalta hai**, jahan launch par ek careful test aur spot checks kaafi ho sakte hain.
- **Aise answers jinhe log use karne se pehle source se verify karte hain.**

## Demo se production tak

- **Test set ko repository mein rakho**, sawaal ke type se tag karke, aur har retrieval change par run karo.
- **Recall, precision, MRR aur nDCG record karo**, settings aur index version ke saath.
- **Har report hue galat answer ko** naye sawaal ke roop mein jodo.
- **Model-judged scores ko har mahine haath se spot-check karo.**
- **Kisi bhi important tag par recall girne par alert** lagao.
