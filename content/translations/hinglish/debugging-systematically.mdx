## Ye kya hai

**Debugging** ye pata lagana hai ki program woh kyun nahi kar raha jo aap expect karte ho, aur wajah ko fix karna. Bug program ko crash kar sakta hai, galat number de sakta hai, ya aapke laptop par chale aur server par fail ho.

Beginners aksar andaaze se debug karte hain: ek line badlo, dobara chalao, doosri badlo. Chhote bugs mein ye chal jaata hai aur asli bugs mein ghante barbaad karta hai. Experienced engineers method use karte hain. Aasaan bugs par ye tez nahi hai, par ye hamesha khatam hota hai, aur interviewers yahi sunna chahte hain jab poochhte hain ki aap kuch kaise dhoondhoge.

## Ye kaam kaise karta hai

```flow
title: Debugging ka loop
Reproduce karo | sabse chhota input jo har baar fail ho -> Error padho | traceback neeche se upar
Error padho -> Andaaza lagao | ye hone ke liye kya sach hona chahiye?
Andaaza lagao -> Scope chhota karo | print, breakpoint, search aadha karo
Scope chhota karo -[andaaza galat]-> Andaaza lagao
Scope chhota karo -[wajah mil gayi]-> Wajah fix karo, symptom nahi
Wajah fix karo, symptom nahi -> Aisa test jodo jo fix ke bina fail ho
```

**Reproduce.** Sabse chhota input dhoondho jo bug ko har baar trigger kare. "Kabhi-kabhi fail hota hai" ban jaata hai "jab CSV mein amount khaali ho tab fail hota hai". Bharosemand reproduction aadha kaam hai.

**Error padho.** Python traceback neeche se upar padhi jaati hai:

```text
Traceback (most recent call last):
  File "report.py", line 31, in <module>
    print(monthly_total(rows))
  File "report.py", line 12, in monthly_total
    total = total + row["amount"]
TypeError: unsupported operand type(s) for +: 'int' and 'str'
```

Aakhri line error hai: aapne ek number aur ek string ko jodne ki koshish ki. Uske upar ki line wahi hai jahan ye hua. Usse upar ki lines dikhati hain ki program wahan tak kaise pahuncha.

**Scope chhota karo.** Poochho ki ye error hone ke liye kya sach hona chahiye, phir use check karo. Teen tools, tez se thorough tak:

| Tool | Kaise | Kisme achha |
| --- | --- | --- |
| `print(repr(x))` | Key points par values print karo | Quick checks; `repr` quotes aur types dikhata hai |
| `breakpoint()` | Debugger mein rokkar inspect karo | Jis pal galat hota hai us pal saare variables dekhna |
| Editor debugger | Click karke breakpoints lagao, step karo, values watch karo | Lambi investigations |
| Logging | Context ke saath `logging.debug(...)` | Aise bugs jo sirf server par dikhte hain |
| `git bisect` | Commits mein binary search | "Pichhle hafte chal raha tha" |

**Debugger.** Kisi line par `breakpoint()` lagao aur program chalao. Wo wahin ruk jaata hai, aur aap `p row` se variable print kar sakte ho, `n` se agli line chala sakte ho, `s` se function ke andar ja sakte ho, aur `c` se continue kar sakte ho. Andaaze ki jagah aap us pal ki asli state dekhte ho jab woh matter karti hai.

**Search aadha karo.** Agar 200 line ki pipeline galat total deti hai, toh beech mein value check karo. Wahan sahi hai? Bug doosre aadhe mein hai. Galat hai? Pehle aadhe mein. Kuch checks mein line mil jaati hai. `git bisect` yahi commits ke across karta hai: ek achha commit aur ek kharab commit mark karo, aur Git aapko us change tak le jaata hai jisne use toda.

**Wajah fix karo.** Fail hoti line ko `try/except` mein lapetna symptom chhupata hai; kharab data wahin hai. Wahan fix karo jahan galat value aati hai.

**Saabit karo.** Aisa test likho jo aapke fix ke bina fail ho aur fix ke saath pass.

**AI apps ke bugs.** Jab koi LLM feature galat jawab de, toh wahi method lagta hai, traceback ki jagah trace ke saath. Us request ka trace kholo aur har step order mein check karo: kya sawaal sahi rewrite hua, kya retrieval ko sahi passage mila, kya prompt mein woh shamil tha, aur kya model ne use use kiya? Pehla step jo galat lage, wahin khodna hai.

## Ek example se samjho

Imran ki Pune mein pharmacies ki chain ke liye monthly sales report ek store ke liye ₹0 dikhati hai, jabki dashboard ₹4.2 lakh dikhata hai.

**Reproduce.** Woh wahi export file ke saath October ki report apne laptop par chalata hai. Wahi nateeja: Kothrud store ke liye ₹0. Reproducible hai.

**Padho.** Koi error hai hi nahi, jo khud ek clue hai: code chalta hai par data ko skip ya zero kar deta hai.

**Andaaza aur scope chhota.** Total zero hone ke liye kya sach hona chahiye? Ya toh store se koi row match nahi hoti, ya har amount zero hai. Woh loop ke andar `breakpoint()` lagata hai aur pehli kuch rows ke liye `row["store"]` print karta hai: `'Kothrud '`, aakhir mein ek space ke saath. Uska filter `'Kothrud'` se compare karta hai. Koi row match nahi hoti.

**Wajah fix karo.** Woh apne filter mein space jod sakta tha, par asli problem export ka bikhra data hai. Woh file padhte hi store names se whitespace hata deta hai, taaki aage ke har step ko saaf values mile.

**Saabit karo.** Woh aise store name ka test jodta hai jismein aakhir mein space ho aur check karta hai ki woh gina jaata hai. Woh ek aisa check bhi jodta hai jo warn kare jab master list ke kisi store ki koi row na ho, taaki aisa mismatch agli baar chupchaap ₹0 dikhane ki jagah zor se saamne aaye.

## Aam galtiyaan

- **Bug reproduce kiye bina code badalna.** Aap nahi jaan sakte ki fix chala.
- **Traceback ko upar se padhna.** Error aur fail hui line neeche hoti hain.
- **Symptom fix karna.** Error ko nigal jaane waala `try/except` agla bug dhoondhna mushkil kar deta hai.
- **Ek saath kai cheezein badalna.** Kaam karne lage toh pata nahi chalega ki kaunsa change matter kiya.
- **Debug prints aur breakpoints chhod dena.** Commit se pehle `breakpoint(` aur bikhre prints search karo.
- **Test na jodna.** Uske bina, agli baar koi us code ko chhue toh bug wapas aa sakta hai.

## Practice karo

1. Kisi chhoti script mein bug daalo (string amount, range mein off-by-one) aur use `breakpoint()` se dhoondho.
2. Apni purani galtiyon ki teen tracebacks padho aur aakhri line se batao ki kya galat hua.
3. Kisi practice repository mein das commits mein se ek mein kuch tod do aur use `git bisect` se dhoondho.
4. Apna debugging method ek minute mein zor se samjhao, jaise interview mein karte.
