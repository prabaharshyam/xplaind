## Ye kya hai

AI mein zyadatar paisa tab kharch hota hai jab aapne model dekha bhi nahi hota: use train karne mein. **Test-time compute** iska doosra pehlu hai. Iska matlab hai jawaab dete waqt zyada computing kharch karna, taaki jawaab ke sahi hone ki sambhaavna badhe. "Test time" inference ke liye research waala shabd hai, yaani wo waqt jab ek train ho chuka model use hota hai.

Ise karne ke teen aam tareeke hain.

1. **Usse step by step sochne ko kaho.** Ye **chain-of-thought** (CoT) prompting hai: model jawaab se pehle apni reasoning likhta hai. Iska ek kareebi rishtedaar hai **self-critique**, jismein model khatam karne se pehle apna draft khud check karta hai.
2. **Kai jawaab generate karo aur sabse achha rakho.** Ye **best-of-N** hai. Ek **verifier** (ek test, ek rule check ya ek scoring model) winner chunta hai, ya jawaab exact hon to majority vote chunta hai.
3. **Ek reasoning model use karo.** Ye models jawaab dene se pehle lamba sochne ke liye train hote hain. Wo kitna effort lagaayein, ye aap tay karte ho. Thinking aksar chhupi rehti hai: aapko sirf jawaab dikhta hai, par thinking ke paise phir bhi lagte hain.

Teenon accuracy ke badle paisa aur intezaar dete hain. Extra thinking tab faayda deti hai jab model sahi jawaab tak *pahunch sakta* hai par raaste mein aksar phisal jaata hai, jaise multi-step maths, code aur planning mein. Jab model ke paas facts hi nahi hain, tab ye madad nahi karti.

```flow
title: Kisi sawaal ko kitni thinking chahiye, ye chunna
Naya sawaal -> Plain model ke liye mushkil? | apna test set check karo
Plain model ke liye mushkil? -[nahi]-> Plain jawaab | tez aur sasta
Plain model ke liye mushkil? -[haan]-> Step-by-step prompt | pehle ye try karo
Step-by-step prompt -> Kaafi achha?
Kaafi achha? -[haan]-> Ship karo
Kaafi achha? -[nahi]-> Kya jawaab check ho sakte hain? | tests, rules, exact values
Kya jawaab check ho sakte hain? -[haan]-> N sample karo aur verify karo | best-of-N ya vote
Kya jawaab check ho sakte hain? -[nahi]-> Reasoning model | effort setting ke kai levels test karo
N sample karo aur verify karo -[samples asehmat]-> Reasoning model
```

## Ye kaam kaise karta hai

### Chain of thought

Sabse simple roop prompt mein bas ek line jodta hai: "Think step by step, then give only the final answer on the last line." Aap chaho to wo steps list kar sakte ho jo aapko chahiye, ya ek worked example dikha sakte ho. Jis 2022 paper ne is method ko naam diya (Wei and others, link neeche hai), usne bade models ke saath maths word problems par bade faayde dikhaaye. Aakhri line waala jawaab zaroori hai: aapke code ko use dhoondhna hota hai.

Pehla pech lambaai ka hai: reasoning waale jawaab mein bahut zyada tokens hote hain, aur har ek par paisa aur waqt lagta hai. Doosra pech chupchaap waala hai: **likhi hui reasoning ke jawaab ki asli wajah hone ki koi guarantee nahi hai.** 2025 ki ek Anthropic study mein models ko chupke se jawaab ka ek hint diya gaya. Jab unhonne hint use kiya, to Claude 3.7 Sonnet ne apni reasoning mein uska zikr sirf 25% baar kiya, aur DeepSeek R1 ne 39% baar. Pehle ke kaam (Turpin and others, 2023) mein chain-of-thought prompts ke saath bhi yahi pattern mila tha. Isliye dikhaayi gayi reasoning ko ek madadgaar draft maano, saboot nahi. Steps kitne convincing lagte hain ye nahi, final jawaab check karo.

### Best-of-N aur verifiers

Thodi variety ke saath (zero se upar ka temperature, ya thode alag prompts) kai jawaab maango, phir ek chuno.

- **Majority vote se**, jise **self-consistency** bhi kehte hain. Wahi maths sawaal paanch baar poochho aur sabse zyada baar aaya final number lo. Ye tabhi chalta hai jab jawaab exact hon: ek number, ek label, ek choice. Sehmati bhi ek signal hai: jab samples asehmat hon, to sawaal shaayad mushkil hai.
- **Ek outcome verifier ke saath**, jo final jawaab check karta hai. Generate hue code ko tests par chalao, generate hui SQL chalakar uska result pehle se pata kisi result se compare karo, ya check karo ki nikaali gayi taareekh asli hai. 2021 mein OpenAI ne bataya ki grade-school maths problems par, trained verifier waale ek 6-billion-parameter model ne ek fine-tuned 175-billion-parameter model ko thoda-sa hara diya, aur is faayde ki tulna unhonne model size mein 30 guna badhotari se ki.
- **Ek process verifier ke saath**, aamtaur par ek **process reward model** (PRM), jo sirf aakhir ko nahi balki har step ko score karta hai. OpenAI ke 2023 paper "Let's Verify Step by Step" mein paaya gaya ki competition maths par step-level feedback ne answer-level feedback ko haraaya, aur ek test subset ka 78% hal kiya. Hugging Face ke write-up ne, jo is lesson ka main resource hai, search ko guide karne ke liye ek PRM use kiya aur dikhaaya ki kaafi samples milne par MATH-500 benchmark par 1B aur 3B models ne apne 8B aur 70B bhaiyon ko hara diya.
- **Ek scoring model ke saath**, jaise ek LLM judge. Ye open-ended text ke liye chalta hai, par utna hi achha hai jitna judge.

N jawaab sample karne ki cost lagbhag N guna hoti hai, isliye N aamtaur par chhota rehta hai: products mein kareeb 3 se 8, research runs mein use hone waale saikdon se bahut kam.

Majority voting ke liye ek chhota helper. Normalising step par dhyaan do: "12.50", "25/2" aur "12.5" ek hi jawaab hain, aur ek plain text comparison vote ko teen hisson mein baant dega.

```python
from collections import Counter
from fractions import Fraction

def normalise(text):
    """Turn '12.50', ' 25/2 ' and '12.5' into the same vote. Non-numbers stay as text."""
    t = text.strip().lower().rstrip(".")
    try:
        return Fraction(t)  # exact, so rounding never splits a vote
    except (ValueError, ZeroDivisionError):
        return t

def majority_answer(ask, question, n=3):
    """ask(question) returns the model's final answer as a short string."""
    votes = Counter(normalise(ask(question)) for _ in range(n))
    best, count = votes.most_common(1)[0]
    unanimous = count == n
    # Accept only a unanimous answer. Anything else goes to the stronger model.
    return best, unanimous

# if not ok: answer = ask_reasoning_model(question)
```

Model se aakhri line par sirf ek number maango. "x = 6" jaisa jawaab text hi rehta hai aur "6" se match nahi karega.

### Reasoning models

Ye models jawaab dene se pehle lamba sochne ke liye train hote hain, aksar aisi problems par reinforcement learning se jinke jawaab check ho sakte hain. Ye maths, code aur planning mein chamakte hain; simple sawaalon par zyadatar cost aur deri hi jodte hain.

Aap inhein prompt se nahi, ek **effort setting** se steer karte ho. Misaal ke taur par, November 2026 ke hisaab se, OpenAI ki Responses API mein `reasoning.effort` hai, aur Anthropic ki API mein `output_config.effort` hai, jismein recent Claude models par levels `low` se `max` tak hain. Effort ek soft guidance hai, token count nahi: low effort par aasaan inputs ke liye model thinking skip kar sakta hai. Defaults model ke hisaab se alag hain (Anthropic ka default zyadatar Claude models par `high` hai aur kuch naye models par `medium`), isliye effort explicitly set karo aur do-teen levels ko alag options ki tarah test karo. Puraane tutorials ek fixed thinking budget (`budget_tokens`) dikhaate hain; Anthropic ne ise deprecate kar diya hai, aur Claude 4.7 aur uske baad ke models ise reject karte hain.

**Reasoning model par chain-of-thought prompts ka dher mat lagao.** Wo pehle se jawaab se pehle sochta hai. Jab OpenAI ne apne o1 reasoning models launch kiye, to uski prompting guide ne simple, direct prompts ki salaah di aur chain-of-thought instructions na dene ko kaha. Anthropic pehle effort level badalne ki salaah deta hai, aur uske baad hi, agar kisi task ko ab bhi zaroorat ho, "Think carefully before responding" jaisa ek chhota nudge. Steps ko script mat karo aur reply mein poori reasoning mat maango: aap chhupi thinking ke paise doge aur phir uski dikhne waali copy ke bhi.

### Aap kiske paise dete ho, aur user kiska intezaar karta hai

- **Thinking output tokens ki tarah bill hoti hai**, tab bhi jab aap use kabhi na dekho. Output tokens aamtaur par input tokens se mehenge hote hain.
- **Summary ki cost bhi poori thinking jitni.** Anthropic thinking ka ek chhota summary lauta sakta hai, par bill uske peechhe ki poori thinking ka hota hai, summary ki lambaai ka nahi.
- **Thinking output limit mein gini jaati hai.** Chhote replies ke hisaab se rakhi gayi output limit (Anthropic par `max_tokens`) thinking ke dauraan hi khatam ho sakti hai, aur reply thode-se jawaab ke saath ya bina jawaab ke ruk jaata hai. Dono ke liye jagah chhodo, ya effort kam karo.
- **Asli count padho.** Anthropic ise `usage.output_tokens_details.thinking_tokens` mein report karta hai; OpenAI apne usage data mein reasoning tokens ko `output_tokens_details` ke neeche report karta hai. Ise har request par log karo: yahi wo number hai jo aapka bill samjhaata hai.
- **Jab tak ye sochta hai, dikhne waala kuch bhi stream nahi hota.** Thinking chhupi ho (Anthropic ke Claude 5 models par yahi default hai), to pehla dikhne waala shabd thinking khatam hone ke baad hi aata hai. User ko dikhne waale pehle shabd tak ka waqt naapo, aur progress ke taur par ek status line ya ek thinking summary dikhao.
- **Multi-turn chats zyada mehengi padti hain.** Jo thinking conversation mein rehti hai, wo baad ke turns par input ki tarah bill hoti hai: kuch models par har pichhle turn se, kuch par sirf aakhri turn se. Conversation ke beech effort level badalne se prompt cache bhi toot sakta hai.

### Methods aamne-saamne

| Method | Extra cost | Extra intezaar | Sabse achha kab chalta hai | Kisse saavdhaan rahein |
| --- | --- | --- | --- | --- |
| Step-by-step prompt | Output tokens ka 2 se 5 guna | Seconds | Non-reasoning model par multi-step problems | Lambe replies; aisi reasoning jo sahi lage par ho nahi |
| 5 ka majority vote | Kareeb 5 guna | Parallel chalao to thoda | Exact jawaab: numbers, labels | Free-form text ke liye bekaar; sabke ek jaise blind spots |
| Verifier ke saath best-of-N | Kareeb N guna plus checks | Parallel ho to thoda | Code, SQL, aise formats jinhein aap test kar sako | Kamzor verifier bure jawaab chunta hai |
| Reasoning model | Aksar 3 se 10 guna | Seconds se minutes | Kathin maths, code, planning | Chhupi thinking ka bill; output limit bahut chhoti |

Ye multipliers options ki tulna ke liye mote patterns hain, daam nahi. Apne sawaalon par naapo.

## Ek example se samjho

Kota ki ek coaching company chahti hai ki AI JEE-style maths problems par students ke jawaab check kare aur galtiyaan samjhaaye, kareeb 300 problems roz. Teachers har din nayi practice problems likhte hain, aur students doosri kitaabon se bhi doubts upload karte hain, isliye zyadatar problems **bina answer key ke** aati hain. AI ko pehle sahi jawaab dhoondhna hai, phir use student ke jawaab se compare karna hai. (Jahan key hai, wahan ek plain comparison ye hissa kar deta hai aur kisi model ki zaroorat nahi.)

Options compare karne ke liye team 200 puraani problems ka ek test set banaati hai jinke jawaab teachers ne check kiye hain. Neeche "sahi" ka matlab hai ki option ne sahi jawaab dhoondha. Iske baad aane waala explanation step har option ke liye ek jaisi cost ka hai, isliye use chhod diya hai. Saare numbers misaal ke liye hain, method dikhaane ke liye chune gaye; ye naape hue daam nahi hain.

Testing se pehle tay hue targets: kam se kam 88% sahi, 100 problems par ₹150 se kam, aur zyadatar students ko 10 seconds ke andar result.

| Option | Sahi | 100 problems ki cost | Aam intezaar |
| --- | --- | --- | --- |
| Mid-size model, plain prompt | 71% | ₹20 | 3 s |
| Wahi model, step-by-step prompt | 81% | ₹55 | 8 s |
| Step-by-step, 5 ka majority | 88% | ₹275 | 9 s (parallel) |
| Reasoning model, low effort | 82% | ₹45 | 8 s |
| Reasoning model, medium effort | 90% | ₹120 | 20 s |
| Reasoning model, high effort | 91% | ₹260 | 45 s |
| Router: 3 plain jawaab, reasoning model (medium) sirf tab jab wo asehmat hon | 90.5% | ₹96 | 70% ke liye 3 s, 30% ke liye 23 s |

**Ise noise ko dhyaan mein rakhkar padho.** 200 problems par, 90% ke aaspaas margin of error dono taraf kareeb 4 points hai (lesson Quality, cost aur speed ke trade-offs dekho). Isliye quality mein 88%, 90%, 90.5% aur 91% baraabari par hain, aur faisla cost aur intezaar karte hain.

- Step-by-step prompt ek badi, sasti jeet thi: 100 par ₹35 zyada mein 10 points. Jo model khud reasoning nahi karta, us par ise pehle try karo.
- Low effort target se chook jaata hai. High effort ki cost medium se dogune se bhi zyada hai aur students ko 45 seconds intezaar karaata hai, us faayde ke liye jo noise ke andar hai. Effort sweep ki aam shape yahi hoti hai: shuru mein bade faayde, phir oonchi keemat par chhote faayde.
- 5 ka majority aur high effort budget tod dete hain. Medium effort quality aur cost paar kar leta hai, par har student 20 seconds intezaar karta hai, isliye wo intezaar waale target mein fail hota hai. Sirf router teenon poore karta hai.

**Router kaise kaam karta hai, aur uske numbers kahan se aate hain.** Har problem ko pehle teen jaldi waale plain-prompt jawaab milte hain, parallel mein, har ek 100 par ₹20: kul 100 par ₹60. Agar teenon sehmat hon, to wahi jawaab use hota hai. Agar nahi, to problem medium effort par reasoning model ke paas jaati hai.

- Test set par, 200 mein se 140 problems (70%) par teenon sehmat the. Unmein se 136 par sehmati waala jawaab sahi tha, yaani 97%. 100% nahi: jab model ka koi blind spot ho, jaise har baar wahi sign error, to teenon samples ek hi galat jawaab par sehmat ho jaate hain. Sehmati evidence hai, proof nahi.
- Baaki 60 problems (30%) reasoning model ke paas gayin, jisne 45 sahi kin, yaani 75%. Ye uske overall 90% se kaafi kam hai, kyunki yahi mushkil problems hain.
- Accuracy: 136 + 45 = 200 mein se 181, yaani 90.5%.
- Cost: samples ke liye ₹60, plus 30% problems × ₹120 = escalations ke liye ₹36, to 100 par ₹96.
- Intezaar: jo 70% sehmat hote hain unke liye 3 seconds, aur jo 30% escalate hote hain unke liye 3 + 20 = 23 seconds. Sabse zyada intezaar karne waale students akele reasoning model ki tulna mein 3 seconds zyada intezaar karte hain, aur 95th-percentile intezaar slow path tay karta hai.

Pehle stage mein plain jawaab kyun? Teen step-by-step jawaabon ki cost 100 par ₹165 hoti, akele reasoning model se zyada. Pehle stage ko bas difficulty ka ek sasta test hona hai.

**Faisla.** Unhonne router chuna: noise ke andar reasoning model jitni hi quality, 20% sasta, aur 10 mein se 7 students ko 20 ki jagah 3 seconds mein result. Escalate hui problems ke liye app ek progress bar ke saath "Checking your working carefully…" dikhaata hai, kyunki jab students dekh sakein ki kuch ho raha hai to wo chhota intezaar maan lete hain. Jo homework raat bhar mein check hota hai, wo ek batch API se jaata hai, jiski keemat OpenAI aur Anthropic normal rate ki aadhi rakhte hain, November 2026 ke hisaab se.

Wo har escalate hui problem ko ek naye test case ki tarah log karte hain, aur nayi problems par 97% waala figure har mahine dobaara check karte hain: router utna hi achha hai jitna wo number.

## Aam galtiyaan

- **Har cheez ke liye reasoning model use karna.** Greetings, lookups aur formatting ko iski zaroorat nahi. Aap aisi thinking ke paise dete ho jo kuch nahi jodti.
- **Sasta kadam chhod dena.** Jo model khud reasoning nahi karta, us par ek step-by-step prompt aksar cost ke chhote-se hisse mein faasle ka bada hissa paat deta hai.
- **Reasoning model mein step-by-step prompts jodna.** Wo pehle se sochta hai. Iski jagah effort level set karo.
- **Bina thinking ke hisaab se rakhi output limit.** Thinking usmein gini jaati hai, isliye jawaab beech mein kat jaate hain.
- **Free-form text par vote karna.** Do achhe paragraphs kabhi ek jaise nahi hote, isliye vote ko kuch nahi milta. Iski jagah verifier ya judge use karo.
- **Sehmati ko sach maan lena.** Ek model ke samples mein uske blind spots saajha hote hain. Naapo ki unanimous jawaab kitni baar sahi hote hain.
- **Kamzor verifier par bharosa karna.** Agar checker ko bewakoof banaana aasaan hai, to best-of-N wo jawaab chunta hai jo use sabse achhe se bewakoof banaaye.
- **Raw reasoning par bharosa karna ya use dikhaana.** Usmein wo baat chhoot sakti hai jisne asal mein jawaab tay kiya, aur usmein galat mod hote hain. Results check karo, aur users ko jawaab ek chhoti, checked explanation ke saath dikhao.

## Jab zyada sochna galat tool hai

- **Model ke paas facts nahi hain.** Zyada der sochne se knowledge nahi judti. Retrieval use karo.
- **Task simple ya creative hai.** Chhote replies, summaries aur tone badalna shaayad hi sudharte hain.
- **Ek chhote faayde se zyada latency maayne rakhti hai.** Ek voice agent ya autocomplete das seconds intezaar nahi kar sakta.
- **Aap faayda naap nahi sakte.** Test set ke bina aap zyada kharch karoge aur pata nahi chalega ki madad hui ya nahi.

## Demo se production tak

- **Difficulty ke hisaab se route karo.** Aasaan sawaal fast path par bhejo aur tabhi escalate karo jab koi check fail ho ya samples asehmat hon.
- **Kharch ki cap lagao.** Effort explicitly set karo, thinking ki jagah chhodkar output limit set karo, aur har request ki thinking tokens aur cost track karo.
- **Progress dikhao**, khaaskar jab thinking chhupi ho.
- **Effort sweep dobaara chalao** jab aap model ya uska version badlo, kyunki wahi level alag tarah se behave kar sakta hai.

## Practice karo

1. Jawaab pata waale das maths ya logic sawaal lo. Kisi bhi chat model par ek plain prompt aur phir ek step-by-step prompt score karo.
2. Jo sawaal usne galat kiye, unke liye har ek ke paanch jawaab sample karo aur majority lo. Vote ne kitne theek kiye? Kya koi unanimous hokar bhi galat tha?
3. Agar aapke paas kisi reasoning model ka API access hai, to wahi das sawaal do effort levels par chalao. Usage data se thinking tokens log karo aur har sawaal ki cost nikaalo.
4. Har method ke liye accuracy, cost aur intezaar likho, aur tay karo ki student app ke liye aap kaun-sa ship karoge.

Aur gehraai ke liye, Chip Huyen ki *AI Engineering* (O'Reilly, 2025) ke chapters 2 aur 5 test-time compute aur chain-of-thought prompting ko cover karte hain.

**Aapka kaam poora hai jab aap** test-time compute kharch karne ke teen tareeke samjha sako, bata sako ki majority vote kab chalta hai aur kab gumraah karta hai, aur reasoning ki cost aur intezaar ko kaabu mein rakhne ke teen tareeke bata sako.
