## Ye kya hai

Roz ke code mein teen structures zyadatar kaam sambhaalte hain.

**Array** items ko order mein, memory mein ek ke baad ek rakhta hai. Python mein `list` ek array hai. Items paas-paas hote hain, isliye item 5 padho ya item 5 lakh, time same lagta hai. End mein add karna sasta hai; front mein insert karna matlab sab kuch aage khiskana.

**String** characters ka array hai. Python aur Java mein strings ek baar ban gayi toh badli nahi ja sakti, isliye har edit ek nayi string banata hai.

**Hash map** key aur value ke pairs store karta hai, aur key se value dhoondhne mein lagbhag utna hi time lagta hai chahe usmein kitne bhi pairs hon. Python ke `dict` aur `set` hash maps hain. Counting, duplicates hatane aur matching ke liye ye sabse bada tool hain.

| | Array (list) | Hash map (dict) |
|---|---|---|
| Kaise store karta hai | Values numbered slots mein: 0 Pune, 1 Goa, 2 Agra, 3 Pune | Key `hash()` se ek slot tak jaati hai: "Pune" se slot 7, value 1,240 orders |
| Padhna | Position se: O(1) | Key se: average O(1) |
| Value se search | O(n): har slot check karo | Zaroorat nahi: seedha key lookup karo |
| Order | Position se bana rehta hai | Position ka koi order nahi |

## Ye kaam kaise karta hai

**Arrays** items ko memory ke ek hi block mein rakhte hain. Computer simple arithmetic se nikaal leta hai ki item i kahan hai, isliye position se padhna O(1) hai. Kisi value ko dhoondhna phir bhi ek-ek item dekhna hai, O(n), jab tak array sorted na ho.

Python lists apne aap badi ho jaati hain. Block bhar jaaye toh Python ek bada block leta hai aur sab kuch copy kar deta hai. Woh copy O(n) hai, par itni kam baar hoti hai ki append average O(1) hi rehta hai.

**Hash maps** ek **hash function** use karte hain jo key, jaise "Pune" text, ko ek number mein badalta hai. Woh number andar ke array mein ek slot chunta hai, aur value wahin store hoti hai. Wapas padhne ke liye map key ko dobara hash karta hai aur seedha us slot par pahunch jaata hai. Kabhi-kabhi do keys ek hi slot par aa jaati hain, ise **collision** kehte hain; map dono rakhta hai aur keys compare karke sahi wali dhoondhta hai. Achhe hash function aur kaafi slots ke saath lookup, insert aur delete average O(1) hote hain.

Trade-off memory aur order ka hai. Hash map list se zyada memory leta hai, aur position se padhne ke liye nahi bana hai.

| Operation | List (array) | Dict / set (hash map) |
|---|---|---|
| Position se padhna | O(1) | supported nahi |
| Value ya key dhoondhna | O(n) | average O(1) |
| End mein add karna / key insert karna | average O(1) | average O(1) |
| Front mein insert ya delete | O(n) | average O(1) |
| Insertion order rakhta hai | haan | haan, Python 3.7+ mein |

Arrays par zyadatar interview problems kuch patterns mein se ek use karte hain: **frequency count** (dict mein items ginna), **seen set** (jo mil chuka hai yaad rakhna taaki repeat pakdo), **complement lookup** (values store karo taaki "target minus ye" turant check ho jaaye) aur **grouping** (koi computed key, jaise sorted letters, items ki list se map karna).

## Ek example se samjho

Rahul interviews ki taiyaari kar raha hai aur Jaipur ki ek chhoti bakery ke order data par practice kar raha hai. Uske paas ek din ke order amounts ki list hai, aur woh jaanna chahta hai ki kya koi do orders milkar ek dum ₹1,000 bante hain, kyunki bakery us price par ek combo deti hai.

Seedha jawab har pair try karta hai:

```python
def pair_for(amounts, target):
    for i in range(len(amounts)):
        for j in range(i + 1, len(amounts)):
            if amounts[i] + amounts[j] == target:
                return i, j
    return None
```

Ye O(n²) hai. 20 orders ke liye theek, 2 lakh ke liye slow.

Hash map version ek hi baar scan karta hai. Har amount par woh poochta hai: kya woh amount pehle dekha ja chuka hai jo ₹1,000 poora kare?

```python
def pair_for(amounts, target):
    seen = {}                     # amount -> position
    for i, a in enumerate(amounts):
        need = target - a
        if need in seen:          # O(1) on average
            return seen[need], i
        seen[a] = i
    return None
```

`[250, 400, 600, 120]` amounts aur target 1,000 ke saath: 250 par use 750 chahiye (nahi mila); 400 par use 600 chahiye (nahi mila); 600 par use 400 chahiye, jo position 1 par dekha ja chuka hai, toh woh `(1, 2)` return karta hai. Ek pass, O(n) time aur O(n) space.

Phir woh sabse popular item ginta hai. Sort karne ki jagah woh frequency count use karta hai:

```python
from collections import Counter
items = ["bun", "cake", "bun", "puff", "bun", "cake"]
Counter(items).most_common(1)   # [('bun', 3)]
```

`Counter` andar se dict hi hai: ek pass, O(n).

## Aam galtiyaan

**Loop ke andar list mein membership check karna.** `if x in some_list` har baar O(n) hai. n items ke loop mein ye O(n²) ban jaata hai. Pehle set mein badal lo.

**Loop mein += se strings banana.** Har `+=` poori string copy karta hai. Pieces ko list mein jama karo aur ek baar `"".join(pieces)` bula do.

**Unhashable keys use karna.** Python mein lists dict key nahi ban sakti kyunki woh badal sakti hain. Tuple use karo, ya string, jaise kisi word ke sorted letters.

**Keys ko normalise karna bhool jaana.** "+91 98450 12345" aur "9845012345" ek hi customer hain par alag keys hain. Ginne ya match karne se pehle keys saaf karo.

**Ye maan lena ki dicts hamesha O(1) hain.** Ye average mein O(1) hain. Bahut kharab hashing ho, ya koi attacker keys chune, toh ye slow ho sakte hain. Interview mein bolo "average O(1)".

**List par loop karte hue use badalna.** Iterate karte waqt items hatane se kuch skip ho jaate hain. Uski jagah nayi list banao.
