## Ye kya hai

**Security questionnaire** (vendor risk assessment) woh tareeka hai jisse enterprise kisi supplier ko data ya systems ka access dene se pehle use check karta hai. Yeh client ki apni spreadsheet ho sakti hai, Cloud Security Alliance ka CAIQ ya SIG questionnaire jaisa standard, ya kisi vendor-risk platform ka portal. Sawaal in cheezon ko cover karte hain:

- company ka security programme, policies aur certifications (SOC 2, ISO 27001);
- access control, authentication aur staff vetting;
- transit aur rest mein encryption, key management;
- network security, vulnerability management aur penetration tests;
- logging, monitoring aur incident response;
- business continuity, backups aur disaster recovery;
- data handling: location, retention, deletion, sub-processors;
- aur, badhte hue, AI-specific sawaal: client data par training, model providers, prompt injection, output review, human oversight.

```flow
Questionnaire, 240 questions -> Answer library
Answer library -[170 match hue]-> Evidence links ke saath reviewed answers
Answer library -[40 AI-specific]-> Design docs se jawab | data flow map, gateway config, masking rules, guardrail tests, approval step, audit log schema
Answer library -[30 client-specific]-> Legal ke saath draft | RBI outsourcing, localisation
Design docs se jawab -> Gaps: 'Partially' + dated plan
Legal ke saath draft -> Gaps: 'Partially' + dated plan
Gaps: 'Partially' + dated plan -[naye answers wapas jode gaye]-> Answer library
```

Ye lesson Meera ko follow karta hai, jo Bengaluru ke ek AI startup mein FDE hai, ek safal pilot ke baad ek bade private bank ke questionnaire ka jawab de rahi hai.

## Ye kaam kaise karta hai

**Answer library banao.** Zyadatar sawaal clients ke beech repeat hote hain. Approved answers ki ek reviewed library rakho, har ek ke saath owner, last-checked date aur evidence ke links (policy documents, SOC 2 report, penetration test summary, architecture diagrams). Naye questionnaires ka jawab usi se do, aur review ke baad naye answers wapas jodo.

**Sahi-sahi aur sach jawab do.** Bina detail ke "Yes" follow-ups ko bulata hai; overclaim contract breach ban sakta hai. Achhe answers kya, kaise aur kahan batate hain: "Saara data rest mein AES-256 se encrypt hota hai, keys Central India ke Azure Key Vault mein hain; keys saal mein ek baar rotate hoti hain."

**Partial aur planned.** "Partially" explanation aur baaki ke liye date ke saath theek hai; jhootha "Yes" theek nahi.

**AI section.** Un jawabon ko pehle se taiyaar rakho jo baar-baar poochhe jaayenge:

- Kaunse model providers aur regions use hote hain, aur kin terms par (data par training, retention)?
- Model ko kaunsa data bheja jaata hai, aur kya personal data mask hota hai?
- Prompt injection ko kaise handle karte hain, aur kya risky actions ke outputs ko log review karte hain?
- Kaunse guardrails, audit logs aur kill switches hain?
- Model ya prompt changes release se pehle kaise test hote hain?

**Sub-processors.** Client data ko chhune waale har third party (cloud, model provider, tracing tool, email service) ko purpose aur location ke saath list karo. Clients ko aksar naye wale par objection karne ka haq hota hai.

**Evidence aur NDAs.** Poori SOC 2 report jaisi sensitive evidence non-disclosure agreement ke tahat, expire hone waale secure link se share karo.

**Kamzor aur mazboot answers:**

| Question | Kamzor | Mazboot |
| --- | --- | --- |
| Rest mein encryption? | "Yes" | "AES-256, Azure Key Vault keys, Central India; saal mein ek baar rotate" |
| Kya data training mein use hota hai? | "No" | "Provider X ka contract client data par training ko exclude karta hai; retention 30 days; clause 7.2 attached" |
| Prompt injection? | "Hum industry-standard AI security use karte hain" | "Least-privilege tools, outbound actions ke liye approval, CI mein chalne waala injection test set; latest results attached" |
| Pen testing? | "Yes" | "Web app ka saalana external test; AI endpoints agle mahine book hue test mein jode gaye" |

**Library ko zinda rakhna.** Har answer ko owner do, aam taur par woh insaan jo woh control chalata hai, aur ek review date. Jab architecture badle, jaise naya model provider ya naya tracing tool aaye, library mein prabhavit answers dhoondho aur usi hafte update karo. Har questionnaire ke baad naye sawaal aur unke reviewed answers jodo. Is tarah maintain ki gayi library do hafte ki bhaag-daud ko kuch din ke focused kaam mein badal deti hai.

**Client ke reviewers ke saath kaam karna.** Follow-up calls ki ummeed rakho. Jo engineer system jaanta hai, data flow map aur evidence saath laao. Sirf wahi batao jo aapko pata hai, jo check karna ho woh likh lo, aur usi din bhej do. Reviewers un vendors par zyada bharosa karte hain jo kehte hain "yeh hum abhi nahi karte, aur yeh plan hai", un par nahi jo sab kuch claim karte hain.

**Answer library data ki tarah.** Answers ko ek file mein rakho jise team code ki tarah review kare, aur hisaab-kitaab script se karwao:

```yaml
# security-answers.yaml
- id: enc-at-rest
  question: Is customer data encrypted at rest?
  answer: >
    Yes. Postgres and object storage use AES-256 with keys in Azure Key Vault (Central India), rotated yearly.
  owner: platform-lead
  evidence: [docs/architecture.pdf#storage, key-vault-policy.pdf]
  reviewed: 2026-09-14
  tags: [encryption, storage]
- id: ai-training
  question: Is our data used to train AI models?
  answer: >
    No. Our model provider's enterprise terms exclude training on API data; retention is 30 days for abuse
    monitoring (terms version and clause attached).
  owner: cto
  evidence: [provider-terms-2026-07.pdf]
  reviewed: 2026-07-30
  tags: [ai, vendor]
```

```python
import yaml
from datetime import date, timedelta

def load(path="security-answers.yaml"):
    return yaml.safe_load(open(path))

def stale(answers, max_age_days=180):
    cutoff = date.today() - timedelta(days=max_age_days)
    return [(a["id"], a["owner"]) for a in answers if a["reviewed"] < cutoff or not a.get("evidence")]

def suggest(question, answers, top=3):
    words = set(question.lower().split())
    scored = sorted(answers, key=lambda a: -len(words & set((a["question"] + " " + " ".join(a["tags"])).lower().split())))
    return [a["id"] for a in scored[:top]]
```

`stale` ko har mahine chalao aur har owner ko uski list bhejo. Naye questionnaire ke liye candidate answers dhoondhne ke liye `suggest` (ya bade libraries ke liye embeddings) use karo, par har answer bhejne se pehle ek insaan se check karwao: model ya keyword match aisa answer chun sakta hai jo kareeb hai par galat.

**AI se draft karna, savdhaani se.** Ek model aapki library aur architecture notes se answers draft kar sakta hai, jisse lambe questionnaires par time bachta hai. Rules: woh sirf library aur attached documents use kar sakta hai, har draft apne use kiye library ids cite karta hai, aur ek naamit insaan har answer approve karta hai. Model ko kabhi aisa control mat gadhne do jo aapke paas hai hi nahi.

**AI section, current rakhna.** Apne model providers ko unki terms check karne ki date ke saath list karo, use hone waale regions, kaunsa data bheja jaata hai aur kya woh masked hai, guardrails aur unke test results, kill switches, prompt aur model changes kaise test hote hain, aur sub-processor list. Isme kuch bhi badle toh usi hafte yeh section update karo.

**Evidence jo purani na ho.** Living documents (maujooda architecture diagram, latest eval aur penetration test summaries) ka link do, un texts ko paste karne ki jagah jo purane ho jaate hain. Injection tests aur permission tests ke CI results ko ek chhote PDF ki tarah export karne laayak rakho, kyunki AI-specific evidence woh hai jo reviewers ne sabse kam dekhi hoti hai.

## Ek example se samjho

Bengaluru ka ek AI startup, ek bade private bank ke saath safal pilot ke baad, do hafte ki deadline ke saath 240-sawaal ki spreadsheet paata hai. FDE Meera coordinate karti hai.

Woh answer library se shuru karti hai, jo 170 sawaal cover karti hai. Baaki mein se 40 AI-specific hain aur 30 bank-specific (jaise RBI outsourcing guidelines aur data localisation).

AI sawaalon ke liye woh system ke asli design documents use karti hai: data flow map, gateway configuration (sirf Indian region, model provider ka contract data par train na karne ka), masking rules, test results ke saath guardrail list, customer-facing messages ke liye human approval step, aur audit log schema. Har answer sambandhit document section cite karta hai.

Do sawaal asli gaps dikhate hain: AI endpoints ka koi formal saalana penetration test nahi, aur model ke galat behave karne ke liye koi documented incident plan nahi. Woh dono ke liye "Partially" kehti hai, agle mahine book hue external penetration test aur attached draft incident runbook ke saath. Bank ki security team plan ko conditions ke saath maan leti hai, aur contract aam taur par teen mahine ki jagah chaar hafte mein aage badh jaata hai.

| Questionnaire ka hissa | Ginti | Kaise handle hua |
| --- | --- | --- |
| Library se jawab diye | 170 | Checks ke saath dobara use |
| AI-specific | 40 | Citations ke saath design documents se jawab |
| Bank-specific | 30 | Legal ke saath draft |
| Gaps | 2 | Book hue pen test aur draft runbook ke saath "Partially" |
| Nateeja | | Teen mahine ki jagah chaar hafte mein contract |

## Aam galtiyaan

- **Overclaim karna.** Jhootha "Yes" baad mein legal problem ban sakta hai. "Partially" bolo aur explain karo.
- **Har baar shuru se shuru karna.** Owners aur dates ke saath answer library maintain karo.
- **Dhundhle AI answers.** "Hum industry-standard AI security use karte hain" ka koi matlab nahi. Providers, regions, terms aur controls ke naam batao.
- **Sub-processors bhool jaana.** Tracing ya email tool jo client data dekhta hai woh bhi ginta hai.
- **Library ko purana hone dena.** Pichhle saal ke architecture ke jawab galat jawab hain.
- **Bina owner ya review date waale answers.** Purane hone par kisi ko pata nahi chalta.
- **AI-draft kiye answers bina har ek ko kisi insaan se check karwaaye bhejna.**
- **Naye sub-processors bhool jaana**, jaise pichhle mahine jodha gaya tracing tool.

## Jab poori library overkill hai

- **Aapke pehle ek ya do questionnaires**: unhe dhyan se bharo, phir answers ko library bana lo.
- **Chhote clients** jo email par kuch sawaal poochte hain: seedha jawab do, wahi precision ke saath.
- **Internal projects** jo company ki apni security review process mein aate hain.

## Demo se production tak

- **Library ko version control mein rakho**, owners, dates aur evidence links ke saath.
- **Purane answers ko har mahine flag karo** aur har architecture change par.
- **Sub-processor list maintain karo**, har ek ke purpose aur location ke saath.
- **AI test results export karo** (injection, permissions, guardrails), evidence ke roop mein.
- **Har questionnaire track karo**: uski date, bheje gaye answers ka version aur kiye gaye follow-ups ke vaade.
