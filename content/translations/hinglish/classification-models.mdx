## Ye kya hai

**Classification** ek category predict karta hai: fraud ya genuine, churn karega ya rahega, paanch complaint types mein se kaun sa. Zyadatar classifiers ek **probability** ya score output karte hain; ek **threshold** use decision mein badal deta hai ("agar probability 0.3 se upar ho toh fraud flag karo").

Common models: **logistic regression** (probabilities output karne waala linear model, samjhana aasaan), decision trees, random forests, gradient boosting aur neural networks.

```flow
Features | amount, merchant, time, device -> Classifier -> 0.0 se 1.0 tak Score
0.0 se 1.0 tak Score -[0.3 se neeche, review threshold]-> Allow
0.0 se 1.0 tak Score -[0.3 aur 0.9 ke beech]-> Analyst review karta hai
0.0 se 1.0 tak Score -[0.9 se upar, block threshold]-> Block, tez appeal ke saath
```

Ye lesson Pune ki ek payments company ko follow karta hai jab wo fraud rules ko classifier se badalti hai.

## Ye kaam kaise karta hai

**Logistic regression.** Linear regression jaisa, par weighted sum ek function se guzarta hai jo use 0 aur 1 ke beech probability mein squeeze karta hai. Coefficients dikhate hain ki kaun se features har class ki taraf dhakelte hain.

**Confusion matrix.** Chune hue threshold ke liye true positives (fraud flag hua), false positives (genuine flag hua), false negatives (fraud chhoot gaya) aur true negatives gino. Har metric in chaar numbers se aata hai.

**Precision aur recall.** Precision: flag kiye cases mein se kitne sach mein positive the. Recall: saare asli positives mein se kitne flag hue. Threshold kam karne se recall badhta hai aur precision girti hai; badhane se ulta hota hai.

**Threshold chunna.** Errors par rupee values lagao. Agar chhoota hua fraud average ₹15,000 ka padta hai aur false alarm investigate karne mein analyst ka ₹200 ka time lagta hai, toh zyada fraud pakadne ke liye aapko bahut false alarms accept karne chahiye. Capacity bhi dekho: agar analysts din mein 500 cases review kar sakte hain, toh threshold lagbhag 500 flag karne ke hisaab se set ho sakta hai.

**Imbalanced classes.** Jab positives rare hon (0.5% fraud), accuracy bekaar hai: "kabhi fraud nahi" predict karne par 99.5% score milta hai. Precision, recall, precision-recall curve aur ROC AUC use karo. Techniques: class weights jo rare class ki errors ko zyada count karwate hain, sampling methods, aur training ke liye kaafi positive examples.

**Calibration.** Agar model 0.3 kehta hai, toh us score par kya fraud lagbhag 30% baar hota hai? Achhe calibrate kiye probabilities thresholds aur business rules ko bharosemand banate hain.

**Multi-class.** Do se zyada categories hon toh confusion matrix dekho ki kaun si classes kisse confuse ho rahi hain.

**Common classifiers ki tulna:**

| Model | Strengths | Weaknesses | Pehli choice kab achhi hai |
| --- | --- | --- | --- |
| Logistic regression | Tez, explainable, lagbhag calibrated probabilities | Complex interactions miss karta hai | Jab decisions samjhane padein, jaise credit |
| Decision tree | Draw karna aur samjhana aasaan | Overfit hota hai, unstable | Sikhane ya simple rules ke liye |
| Random forest | Robust, kam tuning | Bada, slow | Tables par ek strong baseline |
| Gradient boosting | Tables par aam taur par sabse accurate | Tuning chahiye, kam explainable | Tabular data par fraud, churn, risk |
| Neural network | Text, images, bahut bada data | Bahut data chahiye, samjhana mushkil | Unstructured inputs |

**Ek sahi workflow.** Ek simple baseline se shuru karo, jaise maujooda rules ya logistic regression, taaki pata ho "better" ka matlab kya hai. Data ko time se split karo. Class weights ke saath ek strong model train karo. Accuracy nahi, precision, recall aur PR AUC par compare karo. Costs aur capacity se threshold chuno. Calibration check karo. Phir result ko rupees mein aur operational terms mein report karo, jaise din ke alerts.

**Model ki galtiyan padhna.** Threshold chunne ke baad 50 false positives aur 50 false negatives haath se padho. Patterns jaldi dikhte hain: festival-season ke genuine spikes jo fraud flag hue, ya ek naya fraud pattern jo training data ne kabhi dekha hi nahi. Har pattern ek fix sujhata hai: "Diwali mein kitne din bache" jaisa feature, zyada recent training data, ya kisi specific case ke liye rule. Metrics batate hain ki model kitni baar galat hai; cases padhna batata hai kyun.

**Ek baseline aur ek strong model, sahi tareeke se compare.** 1% fraud waale synthetic transactions, time se split (pehle 80% training ke liye):

```python
import numpy as np
from sklearn.datasets import make_classification
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import average_precision_score, confusion_matrix

X, y = make_classification(n_samples=30_000, n_features=15, n_informative=8,
                           weights=[0.99], class_sep=1.0, random_state=3)
cut = int(0.8 * len(y))                                   # pretend rows are in time order
X_tr, X_te, y_tr, y_te = X[:cut], X[cut:], y[:cut], y[cut:]

logit = make_pipeline(StandardScaler(), LogisticRegression(class_weight="balanced", max_iter=2000))
gbm = HistGradientBoostingClassifier(class_weight="balanced", max_iter=300, learning_rate=0.05, random_state=3)
for name, model in [("logistic", logit), ("boosting", gbm)]:
    model.fit(X_tr, y_tr)
    print(name, "PR AUC", round(average_precision_score(y_te, model.predict_proba(X_te)[:, 1]), 3))
```

`class_weight="balanced"` training ke dauraan har fraud case ko kai genuine cases jitna count karwata hai, taaki model seedha "kabhi fraud nahi" na seekh le.

**Calibrate karo, phir threshold rupees mein chuno.** Class weights probabilities ko bigaad dete hain; calibration use theek karti hai:

```python
from sklearn.calibration import CalibratedClassifierCV

cal = CalibratedClassifierCV(HistGradientBoostingClassifier(max_iter=300, learning_rate=0.05, random_state=3),
                             method="isotonic", cv=3).fit(X_tr, y_tr)
p = cal.predict_proba(X_te)[:, 1]

COST_FN, COST_FP = 15_000, 200            # missed fraud, analyst review
t = COST_FP / (COST_FP + COST_FN)         # flag when expected loss from missing exceeds review cost
tn, fp, fn, tp = confusion_matrix(y_te, p >= t).ravel()
print(f"threshold {t:.3f}: caught {tp}, missed {fn}, false alarms {fp}")
print(f"cost of errors ₹{fn * COST_FN + fp * COST_FP:,}")
```

Calibrated probabilities ke saath, sabse achha threshold seedha costs se nikalta hai: case flag karo jab uske fraud hone ke chance ko ₹15,000 se guna karne par ₹200 se zyada aaye.

**Capacity limits rule badal dete hain.** Agar analysts din mein sirf 300 cases review kar sakte hain, toh score se sort karo aur top 300 lo; threshold par nahi, us budget par recall naapo.

**Individual decisions samjhao.** Logistic model mein har feature ka contribution uska coefficient guna uski (scaled) value hota hai. Boosted trees mein permutation importance dikhata hai ki kaun se features overall matter karte hain, aur SHAP jaise tools single predictions samjhate hain. Credit aur insurance decisions mein aksar customers aur regulators ke liye aisi explanations chahiye hoti hain.

## Ek example se samjho

Pune ki ek payments company ke paas mahine mein 2 million UPI merchant transactions hain, jinme se lagbhag 0.3% baad mein fraud confirm hote hain.

1. Baseline: unke rules mahine ke 6,000 alerts ke saath 40% fraud pakadte hain.
2. Class weights ke saath ek gradient-boosted classifier, chhe mahine ke data par train hua aur agle mahine par test hua.
3. Mahine ke 6,000 alerts waale threshold par (analysts ki capacity), wo 68% fraud pakadta hai.
4. Mahine ka fraud lagbhag 6,000 cases hai (2 million ka 0.3%). 68% pakadne ka matlab hai ki 6,000 alerts mein se lagbhag 4,080 asli fraud hain: precision lagbhag 68%, rules ke 40% ke muqable.
5. Business view: har mahine lagbhag 1,680 zyada fraud pakde jaate hain; ₹9,000 average loss par, usi analyst team ke saath mahine mein lagbhag ₹1.5 crore bachte hain.

Wo ek doosra, zyada threshold set karte hain jo transactions ko automatically tab block karta hai jab score bahut high ho aur precision 98% se upar ho, merchants ke liye tez appeal route ke saath.

**Risk committee ko samjhana.** Committee ne gradient boosting ke baare mein nahi poochha. Unhone teen sawaal poochhe: kya analysts par bojh padega, kya genuine merchants ko nuksaan hoga, aur kitna bachega? Team ne jawab diya: aaj jitne hi alerts, 40% ke bajaye lagbhag 68% precision taaki analysts ka time bahut kam waste ho, automatic block sirf us score ke upar jahan precision 98% se zyada ho aur appeals ka jawab chaar ghante mein, aur lagbhag ₹1.5 crore mahine ka fraud jo rules chhod dete the. Unhone merchant category aur city ke hisaab se model ki performance bhi dikhayi, kyunki jo model average mein achha ho par chhote kirana merchants ke liye bura, wo fairness aur business dono ki problem hota. Wo kam history waale naye merchants ke liye thoda kamzor nikla, isliye naye merchants ko pehle mahine automatic blocking ki jagah review mein bheja gaya.

## Aam galtiyaan

- **Imbalanced data par accuracy report karna.** Precision, recall aur PR curves use karo.
- **Default 0.5 threshold use karna.** Costs aur capacity se chuno.
- **Time-based data ke random rows par test karna.** Asli use ki tarah, baad ke period par test karo.
- **Calibration ignore karna.** Decisions ke liye use hone waale scores wahi kahein jo wo kehte hain.
- **Saare actions ke liye ek threshold.** Review aur automatic blocking ko alag precision chahiye.

- **Baseline nahi.** Maujooda rules ya simple model se compare kiye bina aap nahi dikha sakte ki naya model kaam ka hai.
- **Time-ordered data par random splits**, jo future ko leak karte hain.
- **Class-weighted probabilities ko bina calibrate kiye asli probabilities ki tarah use karna.**
- **Review capacity ignore karna**: teen logon ki team ke liye din ke 5,000 cases flag karne waala threshold solution nahi hai.

## Jab simple rule model ko hara de

- **Bahut kam positive examples**, seekhne ke liye kaafi nahi: expert rules se shuru karo aur labels jama karo.
- **Ek saaf rule pehle se kaam karta hai**, jaise chori hue cards ko block karna.
- **Decisions ek vaakya mein samjhane padein** aur ek chhota scorecard us level tak pahunch jaye.

## Demo se production tak

- **Time se split karo** aur sabse recent period par test karo.
- **Calibrate karo** costs se thresholds set karne se pehle.
- **Thresholds costs ya capacity se set karo**, business ke saath tay karke, aur dobara dekhte raho.
- **Precision aur recall monitor karo** jaise-jaise labels aate hain, segment ke hisaab se.
- **Har decision ke liye explanations rakho** jahan customers ya regulators pooch sakte hain.
