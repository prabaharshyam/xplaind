## Ye kya hai

Zyadatar useful Python khud Python se nahi aata. Woh doosron ke likhe **packages** se aata hai: web APIs ke liye `requests`, tables ke liye `pandas`, arrays ke liye `numpy`, aur AI model providers ke official SDKs. Inhe aap Python ke package installer **pip** se install karte ho.

Isse ek problem bante hai. Project A ko pandas version 2.1 chahiye; project B ko 2.3. Dono ek hi jagah install hon toh ek tut jaata hai. Iska solution hai **virtual environment**: ek project ke installed packages ka private folder.

```flow
title: Environments ke bina
System Python | project B ke liye pandas 2.3 upgrade hua -> Project A tut gaya
```

```flow
title: Environments ke saath: har project ka apna, kuch clash nahi
project-a/.venv | pandas 2.1, requests 2.32 -> Project A chalta hai
project-b/.venv | pandas 2.3, anthropic SDK -> Project B chalta hai
```

**requirements.txt** file project ko chahiye packages aur versions list karti hai, taaki koi bhi, kisi bhi machine par, wahi environment dobara bana sake.

Is lesson mein hum Pune ke ek student Nikhil ko follow karenge, jo apne classmate ka project chalata hai aur apne projects ko ek doosre ko todne se rokta hai. End tak aap kisi bhi project ke liye, uski requirements file se, do minute mein fresh environment set up kar paoge.

## Ye kaam kaise karta hai

### Environment banao aur activate karo

Apne project folder ke andar:

```bash
python -m venv .venv
```

Phir use activate karo:

| System | Command |
| --- | --- |
| Windows (Command Prompt ya PowerShell) | `.venv\Scripts\activate` |
| Mac ya Linux | `source .venv/bin/activate` |

Aapka terminal prompt ab `(.venv)` se shuru hota hai. Jo bhi install karoge woh sirf is project mein jaayega. Bahar nikalne ke liye `deactivate` type karo.

### Packages install karo

```bash
pip install requests pandas
pip list                       # what is installed in this environment
pip show pandas                # details and version of one package
```

### Jo install kiya use record karo

```bash
pip freeze > requirements.txt
```

`pip freeze` har package ko uske **exact** version ke saath print karta hai, jaise `pandas==2.3.1`, taaki doosre bhi wahi install karein. Requirements file kuch aisi dikhti hai:

```text
# shortened: pip freeze also lists every sub-dependency
certifi==2025.8.3
numpy==2.3.2
pandas==2.3.1
requests==2.32.5
```

### Doosri machine par dobara banao

Project clone karne ke baad, fresh environment banao aur activate karo, phir:

```bash
pip install -r requirements.txt
```

### Version specifiers

Requirements file exact pin kar sakti hai ya range allow kar sakti hai:

| Line | Matlab |
| --- | --- |
| `pandas==2.3.1` | Bilkul yehi version: sabse reproducible |
| `pandas>=2.2` | Ye version ya naya: naya major version aane par tut sakta hai |
| `pandas>=2.2,<3` | 2.2 se upar koi bhi 2.x: libraries ke liye aam compromise |
| `pandas` | Aaj jo sabse naya hai: jo projects doosre chalayenge unmein bachna |

Jis application ko aap deploy karoge uske liye exact versions pin karo, taaki server ko wahi mile jo aapne test kiya. Jis library ko doosre install karte hain uske liye sensible ranges allow karo, taaki woh unke doosre packages se clash na kare. Upgrade karte waqt soch-samajhkar karo: version badlo, tests chalao, phir nayi file commit karo.

### AI kaam ke liye packages

AI projects kuch aur habits jodte hain. Model provider SDKs, jaise Anthropic ya OpenAI ke official Python packages, tezi se badalte hain, isliye unhe pin karo aur upgrade se pehle release notes padho. Ye SDKs aapki API key ko `ANTHROPIC_API_KEY` jaise environment variable se padhte hain; use apne shell mein ya `.gitignore` mein listed `.env` file mein rakho, code mein kabhi nahi. PyTorch jaise bade packages sainkdon megabytes ke ho sakte hain aur aapke computer ke graphics card par depend karte hain, isliye plain `pip install` ki jagah unke apne install instructions follow karo.

### Ise Git se bahar rakho

`.venv/` ko `.gitignore` mein daalo aur `requirements.txt` commit karo. Environments bade hote hain, sainkdon megabytes ke, aur ek machine ke operating system se bandhe hote hain.

### Apne editor ka interpreter chuno

VS Code mein `.venv` waala Python interpreter select karo (Command Palette, "Python: Select Interpreter"). Warna editor aapke terminal se alag Python use kar sakta hai aur packages ko missing bata sakta hai.

### Naye tools

| Tool | Kya jodta hai |
| --- | --- |
| `pip` aur `venv` | Built in; shuru karne ke liye kaafi |
| `uv` | Bahut tez installs aur environment creation, lock file ke saath |
| Poetry | Lock file ke saath dependency management aur packaging |

**Lock files** sirf aapke naam liye packages hi nahi, har sub-dependency ko bhi pin karti hain. Ideas wahi rehte hain: ek project ke liye ek environment, versions ek file mein record.

## Ek example se samjho

Pune ka ek student Nikhil apne classmate ka project clone karta hai jo weather API call karke Indian cities ke temperatures plot karta hai. Woh use chalata hai:

```text
$ python main.py
ModuleNotFoundError: No module named 'requests'
```

Project ko aise packages chahiye jo uske paas nahi hain. Woh environment banata hai aur project ki file se install karta hai:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

Chal jaata hai, aur Chennai, Delhi aur Shimla ke temperatures ka chart aa jaata hai.

Baad mein woh ek feature jodta hai jise `matplotlib` chahiye. Use install karta hai, `pip freeze > requirements.txt` chalata hai, aur updated file commit karta hai. Uska classmate pull karta hai, `pip install -r requirements.txt` chalata hai, aur bilkul wahi version paata hai.

| Pehle | Baad mein |
| --- | --- |
| Sab kuch system Python mein install hua | Har project ka ek `.venv` |
| Ek assignment ke liye pandas upgrade karne se doosra tut gaya | Projects ek doosre ko affect nahi kar sakte |
| "Mere machine par chalta hai" | `requirements.txt` wahi setup kahin bhi dobara bana deta hai |
| `.venv` commit hone par 400 MB repositories | `.gitignore` mein `.venv/`; sirf chhoti text file share hoti hai |

Ek mahine pehle Nikhil ne sab kuch system Python mein install kiya tha, aur ek assignment ke liye pandas upgrade karne se doosra tut gaya tha. Alag environments ne wo problem hamesha ke liye khatam kar di.

## Aam galtiyaan

- **System Python mein install karna.** Phir projects ek doosre mein dakhal dete hain.
- **Environment activate karna bhool jaana.** Packages galat jagah jaate hain, ya "missing" dikhte hain. Prompt mein `(.venv)` dekho.
- **`.venv` ko Git mein commit karna.** `requirements.txt` commit karo.
- **Version pins nahi.** Aane waali koi release aapka code tod sakti hai; `pip freeze` exact versions record karta hai.
- **Editor ka alag interpreter use karna.** Editor mein project ka `.venv` select karo.
- **`pip` aur `python` ko alag-alag jagah se chalana.** Dono match karein, isliye `python -m pip install ...` use karo.

## Practice karo

Python Packaging User Guide ka pip aur virtual environments waala page padho, jo neeche link hai.

1. **Banao.** Apne virtual environment ke saath ek project folder banao aur `requests` install karo.
2. **Rebuild karo.** `requirements.txt` save karo, environment delete karo, dobara banao, aur file se reinstall karo.
3. **Share karo.** `.venv/` ko `.gitignore` mein daalo aur project ko uske bina GitHub par push karo.

**Aapka kaam poora jab:** aap kisi bhi project ke liye, uski requirements file se, do minute mein fresh environment set up kar sako.
