## Ye kya hai

Claude **animated explainer videos** bana sakta hai: slide hokar aate titles, step by step bante diagrams, badhte charts, kisi path par chalte icons. Ye aisa **code likhkar** karta hai jo har element ko draw aur animate karta hai. Ye kuch film nahi karta aur camera footage generate nahi karta. Isliye ye **motion graphics** ke liye badhiya hai, yaani animated text, shapes aur charts jo kisi idea, process ya kuch numbers ko samjhaate hain.

Kyunki video code hai, ye recording ki tarah nahi, document ki tarah behave karta hai: ek shabd, number ya timing badlo aur phir se render karo. Aap ise data bhi de sakte ho aur sau versions pa sakte ho.

### Teen routes, November 2026 ke hisaab se

- **Ek Claude artifact.** Ek aam chat mein animated HTML, CSS ya SVG scene maango. Ye chat mein turant play hota hai. Video file chahiye to use screen-record karo ya Remotion mein le jaao. Ek scene ya kisi idea ke quick test ke liye sabse achha.
- **Remotion ke saath Claude Code.** Remotion React code se videos banane ka ek framework hai. Claude Code (Pro jaise paid Claude plans mein shaamil, Free plan mein nahi) aapke computer par project likhta hai, aur Remotion asli MP4 render karta hai. Ek scene se lambi kisi bhi cheez, narration wali kisi bhi cheez, aur series ya data-driven videos ke liye sabse achha.
- **Claude Motion.** Anthropic ne ise 8 October 2026 ko beta mein announce kiya. Aap explainer describe karte ho, ya koi report ya data paste karte ho, aur Claude ek chhota animation banata hai jise aap edit kar sakte ho aur MP4 ke taur par download kar sakte ho. Ye sirf **Team aur Enterprise plans** par hai; Free, Pro, Max ya Ultra par nahi hai. Team workspaces mein ye default se on hota hai, aur Enterprise par kisi owner ko ise on karna padta hai. Lambe animations aapke plan ki usage limit ka zyada hissa use karte hain.

Zyadatar learners personal plan use karte hain, isliye ye lesson **Claude Code aur Remotion** se banata hai aur quick tests ke liye artifacts use karta hai. Agar aapka employer aapko Motion deta hai, to scripting, style aur accessibility wali advice us par bhi waise hi laagu hoti hai.

**Work mein use karne se pehle licence check.** Remotion individuals, non-profit organisations aur 3 employees tak wali for-profit companies ke liye free hai, commercial kaam samet. Isse badi for-profit company ko paid company licence chahiye, aur ginti company ke total headcount ki hoti hai, Remotion use karne wale logon ki nahi. Prices badalte rehte hain, to work mein use karne se pehle remotion.dev par licence aur pricing pages check karo.

```flow
title: Idea se MP4 tak
Idea -> Script | scenes, timings, on-screen words
Script -> Narration record karo
Narration record karo -[sentence timestamps]-> Claude animation code likhta hai | Remotion, ek artifact ya Motion
Claude animation code likhta hai -> Preview
Preview -[bahut tez, text bahut chhota]-> Revise
Revise -> Preview
Preview -[sahi lag raha hai]-> Captions aur music jodo
Captions aur music jodo -> MP4 render karo -> Phone par check karo -> Publish
```

## Ye kaam kaise karta hai

### 1. Prompt se nahi, script se shuru karo

Har scene ek line mein likho: uski lambaai seconds mein, kya dikhta hai, kya move hota hai, aur screen par ya narration mein aane wale shabd. Ek idea ke liye tees se nabbe seconds kaafi hain. Ek line ka prompt Claude se inmein se har choice ka andaaza lagwata hai, aur wo andaaze generic hote hain.

Prompt karne se pehle do checks. Timer lagakar narration zor se padho: agar 12-second wale scene ko bolne mein 17 seconds lagte hain, to script abhi theek karo. Aur har scene ko ek hi kaam do; agar use describe karne mein do baar "aur" lagta hai, to use tod do.

### 2. Visual style ek baar set karo

Do-teen colours (brand colours hon to hex codes ke saath), ek font, background, aur motion style batao, jaise "smooth ease-in-out, 0.4 s moves, no bouncing". Claude se kaho ki ye sab ek style file ya constants block mein rakhe. Phir har scene usi se padhta hai, to baad mein brand colour badalna ek hi edit hai.

### 3. Route chuno

| Aapki situation | Route | Kaun sa plan chahiye | Aapko kya milta hai |
|---|---|---|---|
| Ek scene, ya test karna ki idea achhe se animate hota hai ya nahi | Claude artifact | koi bhi Claude plan | Chat mein play hone wala HTML; use screen-record karo |
| Narration ke saath poora video, personal plan par | Claude Code + Remotion | Claude Code wala paid plan | Rendered MP4, dobara use hone wala project |
| Kisi sheet ya list se kai versions | Claude Code + Remotion | Claude Code wala paid plan | Ek template se har row ka ek MP4 |
| Report se ek quick explainer, aisi company mein jiske paas Motion hai | Claude Motion | Team ya Enterprise | Edit hone wala animation, MP4 download |
| Realistic log, jagahein ya products | Veo jaisa video model | Veo aur Flow guide dekho | Generated clips |

Ek simple rule: agar aap ise ek se zyada baar chhuoge, ya ise voice-over se match karna hai, to Remotion use karo. Agar sirf ye dekhna hai ki koi idea animation ke taur par kaam karta hai ya nahi, to artifact use karo.

### 4. Claude Code kya likhta hai, aur use kaise padhein

Aap Claude Code se keh sakte ho "har scene ke liye ek component wala naya Remotion project banao", aur wo ek set up kar dega (official starter hai `npx create-video@latest`). Aapko khud React likhne ki zaroorat nahi, lekin use padh paana chahiye, kyunki isi se aap galat number pakadte ho ya sateek change maangte ho. Chaar ideas iska zyadatar hissa cover karte hain:

- **Frames aur fps.** Video still pictures ki ek series hai, jinhe frames kehte hain. 30 frames per second (fps) par, 5-second scene 150 frames ka hota hai.
- **Current frame.** `useCurrentFrame()` us frame ka number deta hai jo abhi draw ho raha hai. Scene ke andar ye us scene ke start se ginta hai, to har scene apna animation 0 se shuru kar sakta hai.
- **Interpolate.** `interpolate()` ek frame range ko ek value range se map karta hai: "frame 0 aur frame 15 ke beech, invisible se poori tarah visible ho jaao".
- **Composition.** Ek `Composition` video ki width, height, fps aur frames mein lambaai (`durationInFrames`) set karta hai.

Ye neeche wale worked example se Sneha ka title card hai, akela ek 5-second scene:

```tsx
import { AbsoluteFill, Composition, interpolate, useCurrentFrame, useVideoConfig } from "remotion";

// Scene 6, the title card: the text fades in and rises over half a second.
export const TitleCard = ({ text }: { text: string }) => {
  const frame = useCurrentFrame(); // 0, 1, 2 ... counted from the start of this scene
  const { fps } = useVideoConfig(); // 30 in this project
  const opacity = interpolate(frame, [0, 0.5 * fps], [0, 1], { extrapolateRight: "clamp" });
  const y = interpolate(frame, [0, 0.5 * fps], [40, 0], { extrapolateRight: "clamp" });
  return (
    <AbsoluteFill style={{ backgroundColor: "#ffffff", justifyContent: "center", alignItems: "center", padding: 80 }}>
      <h1 style={{ fontSize: 96, color: "#5b2a86", textAlign: "center", opacity, transform: `translateY(${y}px)` }}>
        {text}
      </h1>
    </AbsoluteFill>
  );
};

// The video's settings: size, frame rate and length in frames.
export const RemotionRoot = () => (
  <Composition
    id="TitleCard"
    component={TitleCard}
    width={1080}
    height={1920}
    fps={30}
    durationInFrames={150} // 5 seconds x 30 fps
    defaultProps={{ text: "RAG = search first, then answer" }}
  />
);
```

Ise line by line padho. Aadha second hai `0.5 * fps`, yaani 15 frames, to `opacity` frames 0 se 15 mein 0 se 1 tak jaati hai. Doosra `interpolate` text ko uski jagah se 40 pixels neeche se upar le aata hai. `extrapolateRight: "clamp"` ka matlab hai "frame 15 ke baad, final value par hi raho"; iske bina text screen se upar nikalta chala jaayega, jo Remotion code ka ek common bug hai. `Composition` batata hai ki video 1080 wide, 1920 tall (ek phone screen), 30 fps aur 150 frames lamba hai.

Dhyaan do ki timing raw frame numbers mein nahi, seconds times `fps` mein likhi hai. Claude se kaho ki ise aise hi rakhe. Phir baad mein frame rate badalne se har animation nahi tootega.

### 5. Timestamps se narration ke saath sync karo

Claude aapka audio sun nahi sakta, to "voice-over se match karo" aisa kaam nahi jo wo khud kar sake. Uski jagah use numbers do:

1. Pehle narration record karo aur use ek file mein save karo.
2. Nikaalo ki har sentence kis second par shuru hota hai. Timestamps dene wala transcription tool ye karta hai, jaise Whisper; Remotion mein iske liye helper packages hain. Chhah scenes ke liye aap file play karke times khud bhi likh sakte ho.
3. Claude Code ko wo list do aur usse kaho ki seconds ko frames mein badle aur usse har scene ki lambaai set kare.

```tsx
// Second at which each narration sentence starts, from the transcript, then the end.
const cues = [0, 6.2, 18.5, 30.9, 46.0, 55.4, 60.0];
const fps = 30;
const starts = cues.map((s) => Math.round(s * fps)); // [0, 186, 555, 927, 1380, 1662, 1800]
const lengths = starts.slice(1).map((f, i) => f - starts[i]); // [186, 369, 372, 453, 282, 138]
```

Phir har scene ek `Series.Sequence` ke andar jaata hai, jiska `durationInFrames` uski lambaai par set hota hai, aur narration un sabke neeche play hota hai. Poora video ek doosra `Composition` hai, id `RagVideo` aur `durationInFrames={1800}` ke saath. Ek expert detail: **start times** ko frames mein round karo, phir subtract karo. Agar aap har scene ki lambaai alag-alag round karoge, to chhoti rounding errors judti jaayengi aur aakhri scenes awaaz se door drift ho jaayenge.

### 6. Baat karke refine karo

Kyunki video code hai, sateek changes saste hain: "scene 3 mein arrows baayin taraf se aayein", "38% ko 41% karo". Sirf wahi element badalta hai. Do aadatein madad karti hain:

- **Stills maango.** Claude Code bhi video dekh nahi sakta. Full render se pehle usse kaho ki `npx remotion still` se key moments ke still frames render kare aur unhe dekhe, ya khud check karo.
- **Remotion Studio mein preview karo** (`npx remotion studio`). Ye aapke browser mein video play karta hai aur frame by frame scrub karne deta hai.

### 7. Sound aur captions jodo

Samjhaane ka kaam narration karta hai; on-screen text sirf key words hone chahiye. Mute par dekhne walon ke liye captions jodo. Ek achha rule of thumb: har caption ko har teen shabdon ke liye kam se kam ek second screen par rakho, aur kabhi bhi lagbhag dedh second se kam nahi. Awaaz ke neeche halka music track tabhi daalo jab wo madad kare, aur aakhir mein use fade out karo.

### 8. Render aur export

Remotion aapke computer par CLI se render karta hai, jaise `npx remotion render RagVideo out/rag.mp4`. Iske liye Node.js install hona chahiye, aur ye har frame ek headless browser (jiski koi window nahi hoti) mein draw karta hai, jise Remotion aapke liye set up karta hai. Kitna time lagega ye aapke computer par aur har frame kitna draw karta hai us par depend karta hai, to sau videos ka batch plan karne se pehle apne pehle render ka time naapo.

| Kahaan play hoga | Size (width x height) | Frame rate | Kam se kam text size |
|---|---|---|---|
| WhatsApp, Reels, Shorts (phone first) | 1080 x 1920 (9:16) | 30 fps | lagbhag 48 px |
| Classroom projector, YouTube, slides | 1920 x 1080 (16:9) | 30 fps | lagbhag 36 px |
| Aisi feed post jo dono tarah kaam kare | 1080 x 1080 (1:1) | 30 fps | lagbhag 44 px |

Ye sensible defaults hain, platform rules nahi. Motion graphics ke liye 30 fps kaafi hai; 60 fps render ka kaam doguna kar deta hai aur text ke liye shaayad hi kabhi behtar dikhta hai. Messaging apps aksar videos ko phir se compress karte hain, jisse chhota text blur ho jaata hai, to apne phone par ek test bhejo. Length aur size limits har app mein alag hoti hain aur badalti rehti hain, to jahaan post karoge wahaan ki current limit check karo.

### Data se videos

Remotion video ek program hai, to ye data ko props ke taur par le sakta hai, yaani wo inputs jo ek component ko milte hain. Ek sales team ek spreadsheet se har region ka ek personalised video render kar sakti hai; ek teacher scripts ki list se har chapter ka ek video render kar sakta hai. Claude Code wo loop likh sakta hai jo har row padhta hai aur ek file render karta hai. 40 versions render karne se pehle, sabse mushkil do rows (sabse lamba naam, sabse bada number) render karo aur check karo ki kuch overflow na ho.

## Ek example se samjho

Sneha Nagpur ke ek college mein computer science padhaati hain. Unke students ko RAG (retrieval-augmented generation, jismein chatbot pehle documents mein search karta hai aur phir jawaab deta hai) confusing lagta hai, to wo apne class WhatsApp group ke liye 60-second animation chahti hain. Wo ise khud, ek individual teacher ke taur par bana rahi hain, aur Remotion ka free licence individuals ke liye hi hai. Agar college ise officially use karna chahe, to college check karega ki wo free licence ke liye qualify karta hai ya use company licence chahiye.

Wo ek script likhti hain, jiski planned timings judkar 60 seconds banti hain:

1. (6 s) Ek student chat box mein "What is the exam syllabus?" type karta hai.
2. (12 s) Sawaal numbers ki ek row, yaani ek "embedding", mein badalta hai aur documents ke ek stack ki taraf jaata hai.
3. (12 s) Milte-julte teen paragraphs light up hote hain aur stack se slide hokar baahar aate hain.
4. (15 s) Sawaal aur teenon paragraphs "LLM" label wale ek box mein flow hote hain.
5. (10 s) Ek jawaab aata hai, jiske neeche source document ka naam hota hai.
6. (5 s) Title card: "RAG = search first, then answer".

Wo timer lagakar narration zor se padhti hain; fit ho jaata hai. Wo ise ek shaant kamre mein apne phone par record karti hain aur timestamps dene wale transcription tool se chalaati hain. Unke asli sentences 0, 6.2, 18.5, 30.9, 46.0 aur 55.4 seconds par shuru hote hain, aur file 60.0 par khatam hoti hai. (Ye is lesson ke liye example numbers hain, koi measurement nahi.) To unke asli scene lengths 6.2, 12.3, 12.4, 15.1, 9.4 aur 4.6 seconds hain, plan ke kareeb lekin barabar nahi.

Claude Code ko unka prompt:

```text
Create a Remotion project for a 60-second explainer, 1080 x 1920, 30 fps.
Six scenes, one component each, following the attached script.
Narration: public/narration.mp3. Scene start times in seconds:
0, 6.2, 18.5, 30.9, 46.0, 55.4; the video ends at 60.0.
Round start times to frames, then take differences for scene lengths.
Style: flat, white background, purple #5b2a86, one sans-serif font,
0.4 s ease-in-out moves, no bouncing. Text at least 48 px.
Captions under each scene with the key words only.
Keep all colours and sizes in one style file.
```

Claude Code ise banata hai, aur wo Remotion Studio mein preview karti hain. Pehla draft kareeb hai. Wo do changes maangti hain. Scene 2 mein embedding ke numbers aadhe second ke andar udkar aa gaye, follow karne ke liye bahut tez, to wo kehti hain ki wo 3 seconds mein ek-ek karke aayein. Scene 3 mein wo kehti hain ki har paragraph apne document ka naam dikhaaye. Har change ek hi component ko chhoota hai.

Wo `out/rag.mp4` render karti hain, ye check karne ke liye ki captions ab bhi sharp hain use WhatsApp par khud ko bhejti hain, phir class group mein post karti hain.

Agle semester wo project dobara use karti hain: har topic ke liye naya script, naya narration aur naye start times, usi style file aur scene structure ke saath.

## Aam galtiyaan

**Audio sync ka andaaza lagaana.** Claude se "mere voice-over se match karo" kehna fail hota hai kyunki wo file sun nahi sakta. Use sentence start times do aur unhe frames mein badalne do.

**Clamp karna bhool jaana.** `extrapolateRight: "clamp"` ke bina `interpolate` apni range khatam hone ke baad bhi chalta rehta hai, to text screen se baahar drift ho jaata hai ya zero se aage fade ho jaata hai.

**Screen par bahut zyada text.** Log ek saath paragraph padh aur sun nahi sakte. Har scene mein on-screen text kuch key words tak rakho aur detail narration ko sambhaalne do.

**Bahut jaldi gaayab hone wale captions.** Har caption ko har teen shabdon ke liye kam se kam ek second rakho. Normal speed par saath-saath padhkar check karo.

**Low contrast aur flashing.** Dhoop mein phone par white par halka grey padha hi nahi jaata; light background par dark text use karo ya ulta. Kisi bhi cheez ko ek second mein teen baar se zyada flash mat hone do; tez flashing photosensitive epilepsy wale logon mein seizures trigger kar sakti hai.

**Sirf motion ke liye motion.** Spinning aur bouncing dhyaan bhatkaate hain. Diagram usi order mein banao jismein aap samjhaate ho, aur baaki kuch animate mat karo.

**Galat shape.** WhatsApp par 16:9 video tiny text wali ek patli strip ki tarah dikhta hai. Pehle prompt se pehle 9:16 ya 16:9 tay karo, kyunki baad mein badalne ka matlab hai har scene ka layout phir se banana.

**Numbers check na karna.** Claude aapki table ka koi figure galat type kar sakta hai. Data video publish karne se pehle har number par ruko aur use source se compare karo.

**Realistic scenes ke liye ise use karna.** Camera par logon, jagahon aur products ke liye Veo jaisa video model use karo.

**Licences ko ignore karna.** Royalty-free music aur apni ya licensed images use karo. 3 se zyada employees wali company mein pehle Remotion ka company licence check karo.
