## Ye kya hai

Ek **computer-use agent** software ke saath uski screen ke through kaam karta hai: screenshots leta hai, decide karta hai kahan click karna hai aur kya type karna hai, aur dohraata hai. Ek **browser agent** wahi web browser ke andar karta hai, kabhi-kabhi page ki picture ke saath uski structure bhi padhta hai.

Ye ek asli gap bharte hain. Jab system mein API ho, toh API call karo. Jab na ho, jaise kai government portals, insurer aur bank portals, aur purane desktop applications mein, tab bina insaan ke automate karne ka shaayad screen control hi ek raasta hota hai.

```flow
title: Ladder: jo sabse upar ka rung kaam kare, wahi use karo
1. API | sabse tez, sasta, sabse bharosemand -[API nahi hai?]-> 2. Scripted browser tool | Playwright, fixed steps, ek tool ki tarah expose kiya hua
2. Scripted browser tool -[steps badalte hain?]-> 3. Agent-driven browsing | page structure padhta hai, actions decide karta hai
3. Agent-driven browsing -[kaam ki page structure nahi?]-> 4. Full computer use | screenshot, decide, click ya type, screenshot: sabse slow, sabse kam bharosemand
```

Rung 3 aur 4 ke liye ek safety box use karo: ek isolated VM, ek dedicated account, ek site allow-list, submit, pay ya delete se pehle approval, record kiye gaye screenshots, aur captchas aur OTPs kisi insaan ko bheje jaate hain.

Ye lesson Pune ki ek chartered accountancy firm ke saath chalta hai jo har mahine clients ke tax documents haath se download karne mein ghante lagati thi.

## Ye kaam kaise karta hai

**Options ki ladder, sabse bharosemand se kam bharosemand tak:**

1. **Ek API**, agar ho ya maangi ja sake.
2. Playwright jaisi library se **scripted browser automation**: aapke likhe fixed steps, agent ko ek tool ki tarah expose kiye hue ("download_gst_return(gstin, period)"). Tez, sasta aur predictable.
3. **Agent-driven browsing**: agent page structure padhta hai aur actions decide karta hai, un sites ke liye jo badalti rehti hain.
4. Desktop apps aur sabse mushkil cases ke liye screenshots se **full computer use**. Sabse slow, sabse mehnga aur sabse kam bharosemand.

Jo sabse upar ka rung kaam kare wahi use karo, aur unhe milao: jaane-pehchaane steps ke liye scripted tools, agent control sirf wahan jahan pages predict nahi hote.

**Loop.** Screenshot, ek action decide karo (kisi point par click, type, scroll, key dabana), karo, phir screenshot. Har step ek image ke saath ek model call hai, isliye lambe tasks mein minutes lagte hain aur asli paisa kharch hota hai.

**Safety.**

- Ek isolated virtual machine ya container mein chalao jisme sirf zaroori apps aur accounts hon.
- Restrict karo ki kaunsi websites tak pahunch ho sakti hai.
- Kabhi general credentials mat do; sabse kam permission waala dedicated account use karo.
- Screen par jo bhi hai use untrusted maano: web pages mein agents ko target karne waale instructions ho sakte hain.
- Forms submit karne, payment karne, bhejne ya delete karne se pehle human approval maango.
- Audit ke liye har session ke screenshots ya video record karo.

**Reliability.** Pages badalte hain, pop-ups aate hain, sessions expire hote hain, captchas bots ko rokte hain. Failures ki umeed rakho, unhe detect karo (umeed ke mutabik confirmation nahi aaya) aur kisi insaan ko wapas do.

**Rungs ka comparison:**

| Rung | Per action speed | Cost | Kab break hota hai | Kiske liye best |
| --- | --- | --- | --- | --- |
| API | Milliseconds | Sabse kam | API badalti hai, kam hi | Jisme bhi API ho |
| Scripted tool | Ek second se kam | Kam | Page layout badalta hai; zor se fail hota hai | Stable portals |
| Agent browsing | Seconds | Medium | Ajeeb pages, pop-ups | Badalti hui sites |
| Computer use | Das-das seconds | Sabse zyada | Kai cheezon par | Desktop apps, aakhri raasta |

**Failure detect karna.** Har automated step ko pata hona chahiye ki success kaisa dikhta hai: ek confirmation message, umeed ke size ki downloaded file, list mein ek nayi row. Har important action ke baad use check karo. Agar woh nahi hai, toh andaaza lagane ki jagah ruko, aakhri screenshot aur ab tak ke steps save karo, aur ek saaf note ke saath task kisi insaan ko de do. Tax ya banking portal mein ek chupchaap galat action ek ruke hue task se kahin zyada mehnga padta hai.

**Value naapna.** Bache hue ghante, har step par success rate, har action ka average time aur hand-backs ki ginti track karo. Hand-backs project ki failure nahi hain; system design ke hisaab se kaam kar raha hai. Agar woh kisi ek page par jama ho jaayein, toh woh page scripted tool ka candidate hai.

**Success check ke saath ek scripted browser tool.** Ye Playwright ka Python API use karta hai. Agent ko sirf ek tool dikhta hai, `download_notice`, ek argument ke saath:

```python
from pathlib import Path
from playwright.sync_api import sync_playwright, TimeoutError as PWTimeout

ALLOWED = {"www.example-gov.in"}                       # the only site this tool may reach

def download_notice(notice_id: str) -> str:
    if not notice_id.isdigit():
        return "notice_id must be digits only."
    with sync_playwright() as p:
        browser = p.chromium.launch()
        page = browser.new_page(accept_downloads=True)
        page.route("**/*", lambda route: route.continue_()
                   if route.request.url.split("/")[2] in ALLOWED else route.abort())
        try:
            page.goto("https://www.example-gov.in/notices", timeout=20_000)
            page.get_by_label("Notice number").fill(notice_id)
            page.get_by_role("button", name="Search").click()
            with page.expect_download(timeout=20_000) as dl:
                page.get_by_role("link", name="Download PDF").click()
            path = Path("downloads") / f"notice-{notice_id}.pdf"
            dl.value.save_as(path)
            if path.stat().st_size < 1_000:                 # success check: a real PDF, not an error page
                return "Download looked empty; a person should check this notice."
            return f"Saved {path}"
        except PWTimeout:
            page.screenshot(path=f"downloads/failed-{notice_id}.png")
            return "The site did not respond as expected; screenshot saved for a person."
        finally:
            browser.close()
```

Labels aur roles (`get_by_label`, `get_by_role`) CSS paths se behtar layout changes jhelte hain. Har exit ek sentence return karta hai jo agent aage de sakta hai.

**Screenshot loop, sketch.** Computer-use models ek loop mein kaam karte hain jise aapka code chalata hai:

```python
for step in range(MAX_STEPS):
    shot = take_screenshot()
    action = model_decide(goal, history, shot)        # e.g. {"type": "click", "x": 412, "y": 300}
    if action["type"] == "done":
        break
    if is_risky(action, current_url()):               # submit, pay, send, delete
        if not ask_person(action, shot):
            break
    perform(action)
    history.append(action)
```

Providers apne action formats ke saath computer-use tools dete hain; upar ki shape wahi rehti hai. `is_risky` check aapka code hai, jo page address aur click ke neeche ka element use karta hai, model ki raay nahi.

**Isolation practice mein.** Browser ko aise container mein chalao jise aapke internal network ka access na ho, ek outbound allow list, har task ke liye naya profile aur ek dedicated low-permission account ke saath. Har task ke baad container delete kar do taaki cookies aur downloads runs ke beech leak na ho.

**Ye kitne achhe hain?** Web aur desktop tasks ke public benchmarks lagaataar progress dikhate hain, par agents ab bhi kai everyday tasks mein fail hote hain jo log aasaani se kar lete hain, khaaskar lambe tasks jisme pop-ups, logins ya ajeeb layouts hon. Kuch bhi promise karne se pehle apne tasks par measure karo.

## Ek example se samjho

Pune ki ek chartered accountancy firm har mahine ek government portal aur ek purane accounting desktop app se, jisme API nahi hai, clients ke tax documents download karne mein ghante lagati hai.

Design:

- Portal ke liye, ek scripted Playwright tool vault se client-authorised credentials se login karta hai, jaane-pehchaane pages par jaata hai aur files download karta hai. Agent tool call karta hai; woh azaadi se browse nahi karta. Jab portal ka layout badalta hai, script zor se fail hoti hai aur ek engineer use theek karta hai.
- Desktop accounting app ke liye, ek computer-use agent Windows virtual machine mein chalta hai jisme file share ke alawa internet nahi hai. Woh app ke menus follow karke ledgers export karta hai. Kisi bhi file ko overwrite karne se pehle woh ek staff member se approve karwata hai.
- Captchas aur one-time passwords design se hi kisi insaan ke paas jaate hain.

Results: 120 clients ka monthly download kaam lagbhag 60 staff hours se ghat kar 12 reh jaata hai, zyadatar approvals aur exceptions. Computer-use steps average 40 seconds per action lete hain aur 91% baar succeed hote hain; failures aakhri screenshot ke saath wapas de diye jaate hain.

| Measure | Pehle | Baad mein |
| --- | --- | --- |
| Staff hours per month, 120 clients | Lagbhag 60 | Lagbhag 12, zyadatar approvals aur exceptions |
| Computer-use time per action | Lagu nahi | Lagbhag 40 seconds |
| Computer-use success rate | Lagu nahi | 91%, failures screenshot ke saath wapas |

## Aam galtiyaan

- **Jahan API ya script se kaam chal jaata, wahan screen control.** Ye slow, mehnga aur kam bharosemand hai.
- **Asli desktop par asli logins ke saath chalana.** Isolated machine aur dedicated account use karo.
- **Screen par likhe text par bharosa karna.** Pages mein injected instructions ho sakte hain.
- **Jo wapas na ho sake us action se pehle insaan nahi.** Submissions aur payments ke liye approval chahiye.
- **Captchas ko haraane ki koshish.** Unka samman karo; woh step kisi insaan ko do.
- **Tasks ke beech browser profile dobara use karna.** Cookies aur sessions ek job se agle job mein leak hote hain.
- **Scripted tools mein CSS-path selectors.** Chhote layout changes par tootte hain; labels aur roles ko tarjeeh do.

## Computer-use agent kab use na karein

- **API ya export maujood hai**, ya vendor se maangi ja sakti hai.
- **Steps fixed hain**: scripted Playwright tool tez, sasta aur zyada bharosemand hai.
- **Site apne terms mein automation mana karti hai**, ya use rokne ke liye captchas lagati hai.
- **Galtiyaan mehngi aur pakadna mushkil hain**, jaise tax filings, jab tak koi insaan har submission check na kare.

## Demo se production tak

- **Har session ko isolate karo** allow list aur dedicated account waale naye container mein.
- **Har run ke screenshots ya video record karo**, jitni der audits ko chahiye utni der rakho.
- **Kisi bhi submit, pay, send ya delete se pehle approval maango.**
- **Har step par success aur hand-back rate track karo**, aur jo pages sabse zyada fail hote hain unhe script karo.
- **Site changes monitor karo**: har portal par ek daily scripted check users se pehle layout changes pakad leta hai.

## Practice karo

Computer-use tool docs aur Playwright ka getting-started page padho.

1. Kisi public site par Playwright se ek browser task script karo (jaise kisi government website se latest notices laana) aur use agent ko ek tool ki tarah expose karo.
2. Ek harmless task par container mein browser ya computer-use agent chalao, har step ke screenshots save karke.
3. Kisi bhi form submission se pehle approval step jodo, aur ek chhupa instruction waale page ke saath test karo.
4. Apne scripted tool mein allow-list route jodo, phir use aise page par point karo jo kisi doosri site se script load karta ho, aur confirm karo ki request block hoti hai.
