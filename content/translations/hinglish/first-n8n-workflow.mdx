## Ye kya hai

**n8n** (bolte hain "n-eight-n") ek workflow automation tool hai jismein visual editor hai. Aap canvas par **nodes** rakhte ho aur unhe arrows se jodte ho. Ek **trigger** node har run shuru karta hai, aur uske baad ka har node ek kaam karta hai: sheet padhna, data saaf karna, kisi condition par branch karna, email bhejna.

Data ek node se doosre node tak **items** ki list ke roop mein chalta hai. Har item ek chhota JSON record hota hai, jaise spreadsheet ki ek row. Zyaadatar nodes jitne items milte hain, har ek ke liye ek baar chalte hain. Toh agar trigger teen nayi rows output karta hai, toh uske baad waala Gmail node teen emails bhejta hai. Ye rule yaad rakho, kyunki beginners ko hone waale zyaadatar surprises isi se aate hain.

```flow
title: Shalini ka admissions workflow
Nayi form row | Google Sheets trigger -> Tidy enquiry | Edit Fields
Tidy enquiry -> Repeats hatao | Remove Duplicates
Repeats hatao -> Course JEE hai?
Course JEE hai? -[haan]-> JEE welcome | Gmail
Course JEE hai? -[nahi]-> NEET welcome | Gmail
JEE welcome -> Counsellors ko alert | Telegram
NEET welcome -> Counsellors ko alert
Koi bhi failure -> Error workflow | Shalini ko message
```

Ye lesson mechanics ke baare mein hai: n8n chaalu karna, items, expressions, testing aur publishing. Lesson "n8n se automation" isi par AI steps ke saath aage banta hai. Aap Shalini ko follow karoge, jo Jaipur ke ek coaching institute mein admissions sambhaalti hain, jab wo upar waala workflow banaati hain.

Shuru karne se pehle do baatein. Pehli, n8n **open source nahi hai**. Ye apna khud ka **Sustainable Use License** use karta hai, jo aapko ise apne internal business ke liye, ya personal aur non-commercial use ke liye, use karne aur badalne deta hai. Paise dene waale clients ke liye workflows banaana theek hai. n8n ko host karna taaki clients us par apne workflows bana sakein, iske liye n8n ke saath commercial agreement chahiye. Doosri, **n8n 2.0** se, save karna (ab automatic) sirf ek draft rakhta hai. Triggers chalaane ke liye aap **Publish** click karte ho. Kai puraane tutorials ab bhi Active toggle dikhaate hain.

## Ye kaam kaise karta hai

### n8n chaalu karo

Aapke paas teen practical choices hain:

| Option | Kaise shuru karo | Kya kharch hai | Google sign-in | Kiske liye best |
| --- | --- | --- | --- | --- |
| n8n Cloud | Free trial ke liye sign up karo | Trial, November 2026 ke hisaab se: 14 days, Pro features, 1,000 executions; phir ek paid plan | Ek click, "Sign in with Google" | Aapka pehla workflow, sabse tez |
| Aapke laptop par Docker | Ek command, neeche hai | Free software; sirf tab chalta hai jab laptop on ho | Aapka apna Google OAuth client | Seekhne ke liye, data local rakhne ke liye |
| Kiraaye ke server par Docker | Docker Compose | Server ka kiraaya, saath mein aapka samay | Aapka apna OAuth client aur ek domain | Self-hosted production |

Cloud plans ki keemat **executions** se tay hoti hai, yaani poore workflow runs, alag-alag nodes nahi. Kisi ko quote dene se pehle current plans ke liye n8n ka pricing page check karo.

n8n ko local chalaane ke liye Docker Desktop install karo, phir ye chalao:

```bash
docker volume create n8n_data
docker run -it --rm --name n8n -p 5678:5678 \
  -e GENERIC_TIMEZONE="Asia/Kolkata" -e TZ="Asia/Kolkata" \
  -v n8n_data:/home/node/.n8n \
  n8nio/n8n
```

`http://localhost:5678` kholo aur owner account banao. Container rukne par bhi volume aapke workflows aur credentials bachaakar rakhta hai. Time zone zaroori hai: iske bina self-hosted instance America/New_York use karta hai, aur "9 am" waala schedule India mein shaam ko chalta hai. Puraane tutorials n8n ko `npx n8n` se shuru karte hain. n8n 3.0, jo November 2026 ke hisaab se early access mein hai, wo raasta hata deta hai aur sirf Docker support karta hai, isliye Docker waala tareeka seekho.

Laptop ki ek limit: internet par maujood apps `localhost` tak nahi pahunch sakte. Jo triggers **poll** karte hain, jaise Google Sheets trigger, wo phir bhi kaam karte hain, kyunki poochhne ka kaam n8n karta hai. Jo triggers kisi call ka intezaar karte hain, jaise Webhook, unhe ek public address chahiye (lesson "Webhooks" dekho).

### Triggers

Har workflow ek trigger se shuru hota hai. Ek workflow mein kai triggers ho sakte hain, par har run kisi ek se shuru hota hai.

| Trigger | Kab chalta hai | Use kaise pata chalta hai |
| --- | --- | --- |
| Manual | Jab aap "Execute workflow" click karte ho | Aap, build karte samay |
| Schedule | Jab tay samay aata hai | n8n ki clock, workflow ke time zone mein |
| Webhook ya Form Trigger | Jab koi doosra app ya koi insaan kisi URL par data submit karta hai | Turant: bhejne waala n8n ko call karta hai |
| Google Sheets, Gmail | Jab nayi row ya email aata hai | Polling: default roop se n8n har minute check karta hai |

Google Forms trigger node naam ki koi cheez nahi hai. Agar aap Google Form use karte ho, toh uske answers ek responses sheet mein jaate hain, aur aap us sheet ki nayi rows par trigger karte ho.

Sheets trigger ki teen aadatein jaanne laayak hain. Ye rows ginta hai. Publish ke baad pehla check sirf ye record karta hai ki kitni rows hain, isliye puraane responses kabhi fire nahi hote. Responses sheet mein rows delete ya sort karne se ginti gadbada jaati hai, isliye us sheet ko mat chhedo aur ek copy mein kaam karo. Aur jab aap editor mein "Execute workflow" click karte ho, toh ye sheet ki **saari** rows lautaata hai, sirf sabse nayi nahi.

### Nodes

Nodes teen families mein aate hain:

- **App nodes:** Google Sheets, Gmail, Telegram, Slack, HubSpot aur saikdon aur.
- **Core nodes:** fields ka naam badalne aur saaf karne ke liye **Edit Fields** (jise Set bhi kehte hain), branch karne ke liye **If** aur **Switch**, **Remove Duplicates**, do inputs jodne ke liye **Merge**, kisi bhi API ke liye **HTTP Request**, aur chhoti scripts ke liye **Code**.
- **AI nodes:** classify, extract ya draft karne ke liye language model ko call karte hain. Ye "n8n se automation" lesson ka vishay hain.

### Credentials

Har app node ko ek **credential** chahiye: us app ka saved access, OAuth sign-in ya API key ke zariye. n8n credentials ko encrypt karke store karta hai aur kai workflows ko ek hi credential reuse karne deta hai. Apne personal admin account ki jagah automation ke liye banaaya gaya account use karo, jismein sirf zaroori access ho.

n8n Cloud par Google credentials ek click ka kaam hai. Self-hosted n8n par yahi wo step hai jahaan zyaadatar beginners atakte hain, kyunki aapko apna khud ka **OAuth client** banaana padta hai:

1. Google Cloud Console mein ek project banao aur zaroori APIs enable karo. Google Sheets node ko Sheets API aur Drive API dono chahiye; Gmail ko Gmail API chahiye.
2. OAuth consent screen set up karo. Google Workspace use karte ho toh **Internal** chuno, warna **External**. External app testing mein shuru hota hai, isliye apna Google account **test user** ke taur par add karo. Iske bina Google "access denied" dikhaata hai.
3. **Web application** type ka OAuth client ID banao. n8n ki credential screen jo **OAuth Redirect URL** dikhaati hai, use paste karo. Laptop par ye `http://localhost:5678/rest/oauth2-credential/callback` jaisa dikhta hai.
4. Client ID aur Client Secret ko n8n mein copy karo, phir Sign in with Google click karo.

Ek trap: n8n ke docs chetaavni dete hain ki jo External app abhi testing mein hai, uske consent aur tokens saat din mein expire ho jaate hain. Agar ek hafte baad workflow sheet padhna band kar de, toh credential dobaara connect karo, ya app ko testing se baahar nikaalne ke baare mein Google ki guidance padho.

### Expressions: current item aur pichhle nodes

Node ki settings mein aap input panel se koi field drag kar sakte ho, ya double curly braces ke andar ek **expression** type kar sakte ho. Expressions JavaScript ke chhote tukde hote hain.

- `{{ $json.email }}` **current item** ka email field padhta hai, jaisa is node ka direct input use dekhta hai.
- `{{ $json['Phone number'] }}` aisa field padhta hai jiske naam mein space hai. Google Form sheets sawaal ke text ko hi column name banaati hain, aur fields ka naam jaldi badalne ki ye ek wajah hai.
- `{{ $('Tidy enquiry').item.json.name }}` "Tidy enquiry" naam ke node mein us item se name padhta hai jisse ye item aaya hai.

Doosra tareeka jitna dikhta hai usse zyada maayne rakhta hai. Har node `$json` ko apne output se badal deta hai. Gmail node ke baad `$json` mein abhi bheje gaye email ki details hoti hain, jaise message id, student ki row nahi. Isliye Gmail ke baad rakhe Telegram node ko pichhle node ka naam lena padta hai. Nodes ko saaf naam do, kyunki naam expression ka hissa hai; kisi node ka naam badlo toh use use karne waale expressions check karo.

Do aur defaults logon ko uljha dete hain. **Edit Fields** sirf wahi fields output karta hai jo aap set karte ho, jab tak aap **Include Other Input Fields** on na karo, isliye jo field bhool gaye wo gaayab ho jaata hai. Aur naya **If** node text ko case-sensitive tareeke se compare karta hai: jab tak aap **Ignore Case** option add nahi karte, "neet" aur "NEET" baraabar nahi hain.

### Pinned data se testing

Editor se workflow chalao aur har node par click karke uska input aur output dekho. Problems ek-ek node karke theek karo, us pehle node se shuru karke jiska output galat dikhe.

Trigger ka output **Pin** karo, taaki har test run naye items fetch karne ki jagah wahi sample items reuse kare. Production runs pinned data ko ignore karte hain. Pinning upar bataayi Sheets trigger ki aadat se bhi bachaata hai: 300 puraane responses waali sheet par unpinned test run saare 300 items aage bhej dega, aur Gmail node 300 asli students ko email kar dega. Messages bhejne waala koi bhi node jodne se pehle teen-chaar rows pin karo, ya trigger ko sheet ki ek test copy par point karo.

### Publishing, alerts aur duplicates

Jab har node apne tests pass kar le, toh **Publish** click karo. Tab se trigger apne aap chalta hai, aur **executions list** har run ko uske data aur kisi bhi error ke saath dikhaati hai. Workflow ko akela chhodne laayak safe banaane ke liye do aur cheezein chahiye:

- **Ek error workflow.** Ek alag workflow banao jo **Error Trigger** node se shuru ho aur aapko message bheje. Error Trigger ko fail hue workflow ka naam `workflow.name` mein, aakhiri chala node `execution.lastNodeExecuted` mein, error `execution.error.message` mein aur ek link `execution.url` mein milta hai. Ise publish karo, phir main workflow ki settings mein **Error workflow** ke neeche ise select karo. Ye sirf automatic runs ke liye chalta hai, editor se aapke chalaaye runs ke liye nahi, isliye ise kisi published workflow ko jaanboojhkar todkar test karo.
- **Duplicate protection.** Students forms do baar submit kar dete hain, aur parents us bachche ke liye form bhar dete hain jo pehle hi bhar chuka hai. Ek **Remove Duplicates** node jo **Remove Items Processed in Previous Executions** par set ho, aur **Value Is New** waale items rakhe, pichhle runs ki values yaad rakhta hai aur repeats hata deta hai. Ye ek hi run ke andar items compare nahi karta, isliye ek hi poll mein pakdi gayi do copies dono nikal jaati hain; double-clicks ke liye isse pehle ek doosra Remove Duplicates lagao jo **Remove Items Repeated Within Current Input** par set ho. Dedupe us value par karo jise aap pehle hi normalise kar chuke ho. "+91 98765 43210" aur "09876543210" ek hi phone hain, par sirf tidy karne ke baad.

```flow
dir: LR
Build -> Awkward samples pin karo -> Chalao aur jaancho -> Fix
Fix -[phir se test]-> Chalao aur jaancho
Chalao aur jaancho -[sab pass]-> Publish -> Executions par nazar rakho
```

## Ek worked example

Shalini Jaipur ke ek coaching institute mein admissions sambhaalti hain. Enquiries ek Google Form se aati hain jismein sawaal hain "Full name", "Phone number", "Email" aur "Course". Google har answer ko responses sheet mein ek row ke roop mein likhta hai, jismein sabse pehle ek Timestamp column hota hai. Aaj counsellors din mein ek baar sheet padhte hain aur agli subah students ko call karte hain, aur kuch enquiries chhoot jaati hain.

Wo n8n Cloud trial ke liye sign up karti hain, taaki Google sign-in ek click ka ho, aur ye banaati hain:

| # | Node | Kya karta hai |
| --- | --- | --- |
| 1 | Google Sheets trigger, Row Added | Har minute responses sheet mein nayi rows check karta hai |
| 2 | Edit Fields, naam "Tidy enquiry" | name, phone, email aur course ko simple naamon se set karta hai |
| 3 | Remove Duplicates | Kisi pichhle run mein dekha gaya phone ya email hata deta hai |
| 4 | If | Course JEE hai, Ignore Case add karke |
| 5 | Gmail, har branch ke liye ek | Brochure link ke saath course ke hisaab se welcome email |
| 6 | Telegram | Enquiry ko counsellors ke group mein post karta hai |

"Tidy enquiry" ke fields:

```text
name    {{ $json['Full name'].trim().toTitleCase() }}
phone   {{ $json['Phone number'] ? '+91' + String($json['Phone number']).replace(/\D/g, '').slice(-10) : '' }}
email   {{ $json['Email'].trim().toLowerCase() }}
course  {{ $json['Course'].trim() }}
```

Phone waali line sirf digits rakhti hai, aakhiri das leti hai aur +91 jodti hai, toh "98765 43210", "+91 9876543210" aur "09876543210" sab "+919876543210" ban jaate hain. `String()` isliye hai kyunki trigger sirf digits waale cell ko number ke roop mein de sakta hai. Cell khaali ho toh result khaali hota hai, akela "+91" nahi. Das se kam digits mein likhe number ko baad mein phone ki length check karne waala ek If pakad lega; Shalini ise version two ke liye note kar leti hain.

Remove Duplicates mein dedupe karne waali value `{{ $json.phone || $json.email }}` hai. Sirf phone par dedupe karne se har wo student jisne phone khaali chhoda, ek hi insaan maana jaata, aur pehle waale ko chhodkar sab hat jaate.

**Testing.** Shalini chaar sample rows pin karti hain, jaanboojhkar awkward chuni hui, aur editor se workflow chalaati hain:

1. **Lower case mein "jee".** Ignore Case add karne se pehle ye row NEET branch mein gayi. Ab ye JEE mein jaati hai.
2. **Phone number nahi hai.** Phone khaali hai, jaisa plan tha. Par Telegram message mein "Phone: " ke baad kuch nahi tha. Wo us line ko `{{ $('Tidy enquiry').item.json.phone || 'not given, reply by email' }}` mein badal deti hain.
3. **Telegram mein khaali names.** Chaaron alerts mein name khaali tha. Telegram, Gmail ke baad hai, isliye `$json.name` Gmail ka output padh raha tha. Upar waali line ki tarah "Tidy enquiry" ka naam lene se har field theek ho gaya.
4. **Ek hi student do baar,** ek baar "98765 43210" aur ek baar "+91 9876543210". Remove Duplicates sirf pichhle runs ki values yaad rakhta hai, isliye wo dono rows do alag runs mein bhejkar ise test karti hain. Doosri hat jaati hai. Editor runs bhi values record karte hain, isliye unhi pinned rows ko dobaara chalaane par sab repeats maankar hat jaati hain. Baaki tests ke liye wo har rerun se pehle node ke **Clear Deduplication History** operation se uski memory khaali karti hain, aur samples mein banaavati numbers use karti hain taaki koi asli student kabhi block na ho.

**Publishing.** Wo ek error workflow banaati hain, Error Trigger phir khud ko Telegram, use publish karti hain aur admissions workflow ki settings mein select karti hain. Phir admissions workflow publish karti hain. Sheet mein pehle se maujood rows fire nahi hotin, aur wo yahi chaahti hain: un students ko pehle hi call kiya ja chuka hai.

Misaal ke taur par, maan lo pehla hafta aisa dikhta hai. Ye numbers is baat ki misaal hain ki kya measure karna hai, koi measured result nahi:

| Measure | Pehle | Baad mein |
| --- | --- | --- |
| Enquiry se welcome email tak | Agle din, haath se | Ek-do minute ke andar |
| Enquiry se counsellor ke call tak | Agli subah | Usi din, working hours mein |
| Do baar email hui repeat enquiries | Aksar | Bahut kam: pichhle runs ke repeats hat jaate hain |
| Chupchaap failures | Pata nahi chalta | Har ek Shalini ko link ke saath alert bhejta hai |

Jo trade-off wo maanti hain: jo student sach mein do baar enquire karta hai, jaise pehle JEE aur phir NEET ke liye, wo doosri baar hat jaata hai. Agar counsellors aise students dekhna chaahein, toh wo If node se pehle ek log sheet check karke duplicates ko hataane ki jagah ek "repeat enquiry" Telegram message mein bhej sakti hain.

## Aam galtiyaan

- **Bina pin kiye live responses sheet par testing.** Sheets trigger ka editor run har row lautaata hai, aur Gmail node sabko email kar deta hai. Samples pin karo ya copy use karo.
- **Kisi aise node ke baad `$json` padhna jisne use badal diya.** Gmail ya Telegram ke baad pichhle node ka naam lo: `$('Tidy enquiry').item.json`.
- **Bhool jaana ki Edit Fields wo hata deta hai jo aapne set nahi kiya.** Aage ke nodes ko jo bhi field chahiye wo set karo, ya Include Other Input Fields on karo.
- **Case-sensitive comparisons.** If node ka Ignore Case option add karo, ya tidy ki hui, lower-case values compare karo.
- **Tidy karne se pehle dedupe karna, ya aise field par jo khaali ho sakta hai.** Pehle normalise karo, aur fallback ke liye doosra field rakho.
- **Responses sheet edit karna.** Rows delete ya sort karne se trigger ki row count bigad jaati hai, jisse nayi enquiries chhoot sakti hain.
- **Publish ki jagah save karna.** n8n 2.0 mein saved workflow ek draft hota hai. Agar koi production run nahi dikh raha, toh check karo ki aapne Publish click kiya tha.
- **Koi error workflow nahi.** Iske bina fail hua run executions list mein tab tak pada rehta hai jab tak koi ittefaaq se na dekhe.
- **Self-hosted instance par time zone default par chhod dena.** Asia/Kolkata set karo.

## Practice karo

Watch & learn panel mein Kevin Stratvert ka beginner video dekho, n8n ka "Build your first workflow" quickstart karo, phir neeche linked n8n ka free N8N101 Essentials course lo.

1. **Chalao.** n8n start karo, Cloud trial ya upar waali Docker command se, aur ek Google account connect karo.
2. **Banao.** Ek Google Form banao aur Shalini ka workflow build karo, ya apne case ke liye ek: ek trigger, ek Edit Fields node, Remove Duplicates, ek If branch aur do app actions. Har node ko naam do.
3. **Todo.** Chaar awkward rows pin karo: lower-case course, khaali phone, spaces waala phone aur ek repeat. Har node ka output pehle se batao, chalao, aur har failure theek karo, unhi rows ko dobaara chalaane se pehle Remove Duplicates ki history clear karte hue.
4. **Safely publish karo.** Ek error workflow jodo, dono publish karo, phir main workflow ko jaanboojhkar todo aur confirm karo ki alert ek working link ke saath aata hai.

**Aapka kaam poora hai jab aap** har node ka input aur output samjha sako, executions list mein ek automatic run dikha sako, aur fail hue run ka alert dikha sako.
