## Ye kya hai

**Recursion** tab hoti hai jab koi function kisi problem ko solve karne ke liye uske chhote version par khud ko call karta hai, jab tak woh ek **base case** tak na pahunch jaaye jo seedha jawab dene layak chhota ho. Kisi folder mein files ginna natural recursive hai: yahan ki files gino, phir har sub-folder se wahi sawaal poochho.

**Dynamic programming** (DP) woh hai jo aap tab karte ho jab koi recursion wahi chhote problems baar-baar solve karti rehti hai. Unhe dobara compute karne ki jagah, aap har ek ko ek baar solve karte ho aur answer reuse karte ho, ya toh results cache karke (**memoization**) ya sabse chhote case se upar ki taraf ek table bharkar (**tabulation**).

```flow
title: fib(5) plain recursion se: wahi calls repeat hote hain (15 calls; fib(35) ke liye lagbhag 2.7 crore)
fib(5) -> fib(4)
fib(5) -> fib(3), dobara compute hua
fib(4) -> fib(3)
fib(4) -> fib(2)
fib(3) -> fib(2), phir se
fib(3) -> fib(1)
```

```flow
dir: LR
title: Memoization ke saath: har value ek baar, phir lookups
fib(0) -> fib(1) -> fib(2) -> fib(3) -> fib(4) -> fib(5)
```

## Ye kaam kaise karta hai

Koi problem DP ke liye tab fit hota hai jab usme do properties hon. **Optimal substructure**: sabse achha answer chhote problems ke sabse achhe answers se banta hai. **Overlapping subproblems**: wahi chhote problems kai baar aate hain.

Ek bharosemand method ke paanch steps hain:

1. **State define karo**: kaunsi ek value, ya values ka chhota set, ek subproblem ko pehchaanta hai? Coin change mein, abhi banana baaki amount.
2. **Recurrence likho**: ek state ka answer chhote states se kaise aata hai.
3. **Base cases set karo**: woh states jinka seedha jawab de sakte ho, jaise amount 0 ko 0 coins chahiye.
4. **Order choose karo**: memoization ke saath top-down, ya table ke saath bottom-up.
5. **Answer nikalo** aur cost check karo: states ki ginti guna har state ka kaam.

**Top-down memoization** natural recursive code rakhta hai aur ek cache jodta hai. Python mein `@functools.lru_cache(maxsize=None)` ye ek line mein kar deta hai. **Bottom-up tabulation** recursion ko ek loop se badal deta hai jo base case se upar ki taraf array bharta hai. Ye recursion-depth limits se bachata hai aur aksar thoda tez bhi hota hai.

| Approach | Kaisa dikhta hai | Kis kaam ka | Kis par dhyaan rakhein |
|---|---|---|---|
| Plain recursion | function khud ko call karta hai | chhote inputs, saaf code | subproblems repeat hone par exponential time |
| Memoization (top-down) | recursion + cache | recurrence se jaldi likh jaata hai | recursion depth; cache memory |
| Tabulation (bottom-up) | table bharne wala loop | bade inputs, predictable speed | fill order nikalna padta hai |
| Greedy | abhi sabse achha option chuno | jahan proven greedy choice ho | local best global best na ho toh galat answer |

**Interviews mein DP pehchanna.** Kisi sequence ya grid par "number of ways", "minimum cost", "maximum value", "longest" ya "can you reach" jaise phrases aksar DP ka sanket hote hain. Pehle plain recursive version likho aur uska cost zor se bolo; phir repeated subproblems dikhao aur ek cache jodo. Interviewers ratti hui table se zyada us dheemi se tez wale raaste ko reward karte hain.

## Ek example se samjho

Arjun Lucknow ke ek payments kiosk ke liye cash-dispensing feature bana raha hai. Ek amount di jaaye toh kiosk ko use 1, 2, 5, 10, 20, 50, 100, 200 aur 500 ke sabse kam coins aur notes se dena hai.

Indian denominations ke liye, hamesha sabse bada note lena jo fit ho, kaam kar jaata hai. Par product ek canteen mein bhi chalega jo 1, 3 aur 4 ke tokens use karti hai. 6 ke liye greedy 4 + 1 + 1 leta hai (teen tokens), jabki 3 + 3 do hain. Isliye Arjun DP use karta hai.

**State:** abhi dena baaki amount `a`. **Recurrence:** best(a) = 1 + har fit hone wale coin c par sabse chhota best(a − c). **Base case:** best(0) = 0.

Uska pehla version plain recursion hai:

```python
def fewest(a, coins):
    if a == 0:
        return 0
    return 1 + min(fewest(a - c, coins) for c in coins if c <= a)
```

Indian coins ke saath ₹30 ke liye ye theek hai; ₹300 ke liye ye asal mein kabhi khatam nahi hota, kyunki ye wahi amounts anginat baar dobara solve karta hai.

Ek cache jodne se fix ho jaata hai:

```python
from functools import lru_cache

def fewest_coins(amount, coins):
    @lru_cache(maxsize=None)
    def best(a):
        if a == 0:
            return 0
        return 1 + min(best(a - c) for c in coins if c <= a)
    return best(amount)
```

Ab 0 se target tak har amount ek baar solve hota hai: lagbhag amount × coins ki sankhya steps.

Kiosk ke liye woh bottom-up version use karta hai, jo bade amounts par recursion limits se bachata hai:

```python
def fewest_coins_table(amount, coins):
    INF = float("inf")
    best = [0] + [INF] * amount
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a and best[a - c] + 1 < best[a]:
                best[a] = best[a - c] + 1
    return best[amount]
```

Nau denominations ke saath ₹3,000 ke liye ye 27,000 simple steps hain, kisi bhi phone par turant. 1, 3 aur 4 ke tokens ke saath 6 ke amount ke liye ye sahi 2 return karta hai.

## Aam galtiyaan

**Base case na hona, ya galat hona.** Recursion kabhi rukti nahi ya bekaar value return karti hai. Pehle base case likho.

**Bahut bada state chunna.** Aisi values jodna jo answer ko affect nahi karti, states ki ginti guna kar deta hai. Sirf wahi rakho jis par aage ka kaam depend karta hai.

**Mutable arguments par cache karna.** `lru_cache` ko hashable arguments chahiye. Lists nahi, tuples pass karo, ya list ko cached function ke bahar rakho, jaise upar.

**Recursion limit se takrana.** Python lagbhag 1,000 nested calls par ruk jaata hai. Bade inputs ke liye bottom-up par jao, ya limit ko dhyaan se badhao.

**Bina proof ke greedy par bharosa.** Greedy tez hai aur aksar sahi, par aapko dikhana padta hai ki woh us problem ke liye kaam karta hai. 1, 3, 4 token wala example dikhata hai ki woh kaise fail hota hai.

**Seedhe code par kood jaana.** Zyadatar DP bugs ek dhundhle state ya recurrence se aate hain. Code se pehle dono ko ek sentence mein likho.
