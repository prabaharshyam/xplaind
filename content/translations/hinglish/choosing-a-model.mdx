## Ye kya hai

Model chunne ka matlab hai ye pick karna ki aapke application ka har hissa kaunsa language model, kis provider se aur kis size mein chalayega. Sainkdon options hain: API ke peeche hosted models, aur open-weight models jo aap khud chalate ho. Naye models har mahine aate hain, har ek ke saath record scores ka press release.

Scores **benchmarks** se aate hain: fixed public test sets jo ek skill naapte hain, jaise school maths, general knowledge ya code likhna. Ek **leaderboard** models ko chune hue benchmarks ke scores jodkar, ya logon ke do anonymous jawabon mein se ek ko vote karne se, rank karta hai.

Benchmarks kaam ke hain, par woh aapke sawaal se alag sawaal ka jawab dete hain. Woh poochte hain "in tests mein kaunsa model achha hai?" Aapko jaanna hai "mere task par, mere afford karne laayak price aur speed par, mere rules ke andar kaunsa model kaafi achha hai?" Chunne ke ek bharosemand tareeke ke chaar steps hain.

```flow
title: Chaar steps mein model chunna
Saare candidate models -> Hard requirements par filter karo | licence, data location, languages, price
Hard requirements par filter karo -> Public benchmarks se shortlist karo | 3 se 5 models
Public benchmarks se shortlist karo -> Apne data par test karo | aapke inputs, aapka rubric
Apne data par test karo -> Quality, cost aur speed meet hoti hai?
Quality, cost aur speed meet hoti hai? -[nahi]-> Design badlo | chhota task, behtar prompt, retrieval
Design badlo -> Apne data par test karo
Quality, cost aur speed meet hoti hai? -[haan]-> Launch karo aur monitor karo | models badlein toh dobara check karo
```

## Ye kaam kaise karta hai

**Step 1: hard requirements par filter karo.** Kuch cheezein prompting se theek nahi hoti. Pehle unhe likho, aur jo model ek bhi mein fail ho use hata do.

- **Licence aur terms.** Kya commercially use kar sakte ho? Kya uske outputs rakh sakte ho? Kuch open-weight licences badi companies par limits lagate hain.
- **Data location aur privacy.** Kya woh Indian cloud region mein ya aapke apne servers par chal sakta hai? India ke data protection law ke under, aur banks ke liye RBI rules ke under, ye kai options hata sakta hai.
- **Languages.** Kya woh un languages ko handle karta hai jinmein aapke users likhte hain, mixed Hinglish bhi?
- **Context length, speed aur price.** Kya woh aapka sabse lamba document padh sakta hai? Kya woh kaafi tez jawab deta hai? Kya per request cost aapke budget mein fit hoti hai?

**Step 2: public benchmarks se shortlist karo.** Benchmarks aur leaderboards ko test karne laayak 3 se 5 candidates chunne ke liye use karo, winner chunne ke liye nahi. Inhe in limits ko dhyaan mein rakh kar padho:

- **Leaderboards apne tests khud chunte hain.** Ek leaderboard hazaaron mein se kuch hi benchmarks cover karta hai, aur ye choice decide karti hai ki kaun jeetta hai. Zyadatar mein English aur general knowledge ka weight zyada hota hai.
- **Chhoti details scores badal deti hain.** Hugging Face ne ek baar paaya ki wahi model, wahi benchmark par, prompt kaise likha gaya aur score kaise hua, uske hisaab se bahut alag scores laaya. Scores ko tabhi compare karo jab woh ek hi tareeke se naape gaye hon.
- **Saturation.** Jab top models sab 100% ke paas score karte hain, toh benchmark unhe alag nahi karta. Leaderboards saturated benchmarks ko har ek-do saal mein badal dete hain.
- **Contamination.** Benchmark ke sawaal public hote hain, isliye woh web text mein aur phir training data mein leak ho jaate hain. Jis model ne sawaal dekhe hain woh yaaddaasht se achha score karta hai. Labs ise do common tareekon se check karte hain: test aur training data mein saajha lambi word sequences dhoondhna (n-gram overlap), aur dekhna ki kya model ko test questions shak karne laayak aasaani se predict hote hain (low perplexity). Purane, popular benchmarks ke scores ko saavdhaani se lo.
- **Vote-based rankings** woh dikhate hain jo bahut se log chhoti chats mein pasand karte hain, aksar fluent, confident aur achhe formatted jawab. Ye aapke task se match nahi karta ho sakta.

**Step 3: apne data par test karo.** Yahi woh step hai jo decide karta hai. 100 se 300 real inputs ka ek test set banao, personal data anonymise karke, har language aur har tarah ki request cover karte hue. Koi bhi output dekhne se pehle ek scoring rubric likho. Har shortlisted model ko same prompt ke saath chalao, aur quality, cost aur speed saath mein record karo. Test sets aur LLM judges ke lessons batate hain ki score kaise karein.

Ek chhota harness comparison ko fair rakhta hai:

```python
import json, time

def run(model_name, call_model, cases, score):
    """call_model(prompt) returns (text, cost_in_rupees). score(case, text) returns 0 to 1."""
    total, cost, slow = 0.0, 0.0, []
    for case in cases:
        start = time.time()
        text, rupees = call_model(case["input"])
        slow.append(time.time() - start)
        total += score(case, text)
        cost += rupees
    slow.sort()
    return {
        "model": model_name,
        "quality": round(total / len(cases), 3),
        "cost_per_1000": round(cost / len(cases) * 1000, 1),
        "p95_seconds": round(slow[int(len(slow) * 0.95) - 1], 2),
    }

cases = [json.loads(line) for line in open("helpdesk_test.jsonl")]
```

**Step 4: launch karo aur monitor karo.** Har hafte real conversations sample karke score karo. Jab provider model update kare, prices badlein, ya koi sasta model aaye, toh apna test set dobara chalao. Aapka test set hi switching ko safe banata hai.

**Build ya buy.** Hosted APIs shuru karne mein tez hain, aapke liye scale hote hain aur aksar sabse strong models hote hain. Open-weight models high volume par data aur cost par control dete hain, par servers aapko chalane padte hain. Kai teams API se shuru karti hain, phir jab unka test set prove kar de ki chhota open model kaafi achha hai, toh high-volume, simple steps us par shift kar deti hain.

## Ek example se samjho

Chennai ki ek lending company ko Tamil aur English mein loan sawaalon ke liye helpdesk assistant chahiye. Data India mein hi rehna hai, aur budget lagbhag ₹0.37 per conversation hai.

Woh aath candidates se shuru karte hain. Filter teen hata deta hai: ek Indian region mein nahi chal sakta, ek ka licence unke use ko mana karta hai, aur ek budget se bahut upar hai. Public leaderboards unhe ek aur model hatane mein madad karte hain jo instructions follow karne mein weak hai. Chaar bachte hain.

Woh 240 real sawaalon (120 Tamil, 120 English) ka test set banate hain, jisme names aur loan numbers hata diye gaye hain, aur ek rubric: policy se sahi facts, saaf next step, polite tone, sahi language.

| Model | Leaderboard rank | Apna test: Tamil | Apna test: English | Per conversation cost | p95 reply time |
| --- | --- | --- | --- | --- | --- |
| A, bada hosted | 1 | 81% | 93% | ₹0.62 | 3.1 s |
| B, medium hosted | 6 | 84% | 90% | ₹0.21 | 1.4 s |
| C, open-weight, self-hosted | 11 | 74% | 88% | ₹0.09 | 1.9 s |
| D, chhota hosted | 15 | 62% | 85% | ₹0.05 | 0.8 s |

Numbers sirf samjhane ke liye hain ki compare kaise karein. Leaderboard leader A English mein best hai par budget se upar hai, aur Tamil mein B se thoda kharab. B dono languages mein bar meet karta hai A ki teesri price par, isliye woh B chunte hain. C ko woh fallback rakhte hain jise baad mein Tamil replies par fine-tune kiya ja sakta hai, aur har baar jab naya model announce hota hai toh woh 240 sawaal dobara chalate hain.

## Aam galtiyaan

- **Headline score se chunna.** Leaderboard ki jeet ka matlab un tests mein achha hona hai, aapke task mein nahi.
- **Sirf English mein test karna.** Indian languages aur mixed-language text mein quality aksar gir jaati hai. Har us language mein test karo jisme aapke users likhte hain.
- **Alag tareeke se naape gaye scores compare karna.** Alag prompts aur scoring rules scores ko bahut hila sakte hain.
- **Launch tak cost aur speed ko ignore karna.** Jo model 2 points behtar hai par 3 guna price ka hai, woh galat choice ho sakta hai.
- **Kabhi dobara check na karna.** Prices girte hain aur models behtar hote hain. Chhe mahine purani choice ab overpriced ho sakti hai.
- **Purane benchmarks par bharosa karna.** Popular, purane test sets training data mein hone ki sambhaavna hai, isliye high scores yaaddaasht ho sakte hain.

## Jab benchmarks kaam aate hain

- **Jaldi shortlist banane mein.** Woh un models ko hata dete hain jo aapko chahiye us skill mein saaf kamzor hain, jaise coding ya lambe documents.
- **Field ko track karne mein.** Ek nayi, mushkil benchmark dikhati hai ki models kitni tezi se behtar ho rahe hain.
- **Kisi claim ko check karne mein.** Agar vendor kehta hai ki unka model maths mein best hai, toh test karne mein time lagane se pehle public benchmark ek pehla check deta hai.

## Practice karo

1. Aap jis AI feature ko jaante ho, uski hard requirements list karo: licence, data location, languages, context length, speed aur price.
2. Do public leaderboards kholo aur note karo ki har ek kaun se benchmarks use karta hai. Aisa ek model dhoondho jo dono par bahut alag rank hai.
3. Apne feature ke liye das real test inputs likho, saath mein ye ki achhe jawab mein kya hona chahiye. Do models un par chalao aur dono ko score karo.

Aur gehrai mein jaane ke liye, Chip Huyen ki *AI Engineering* (O'Reilly, 2025) ka chapter 4 model selection, public benchmarks aur contamination cover karta hai.

**Aapka kaam poora jab:** aap chaar steps list kar sako, public benchmarks ki teen limits bata sako, aur samjha sako ki final faisla aapka apna test set kyun karta hai.
