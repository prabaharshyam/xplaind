## Ye kya hai

**Experiment tracking** har training run ko apne aap log karta hai: code version (ek Git commit), data version, parameters, metrics, environment (library versions), plots jaise artefacts, aur trained model. Har run ek row ban jaata hai jise aap sort, compare aur reproduce kar sakte ho.

**Model registry** chune hue model versions ki ek shelf hai. Har version ke notes aur tags hote hain (jaise, kisne approve kiya), aur us par ek **alias** bhi lag sakta hai: `champion` jaisa ek khiskaaya ja sakne waala naam jo theek ek version ki or point karta hai. Production alias load karta hai, kabhi file path nahi, isliye deployed model hamesha pata rehta hai.

Aam tools hain MLflow (open source), Weights & Biases, aur cloud ML platforms mein built-in tracking. Ye lesson MLflow 3 use karta hai. MLflow mein aliases ne puraane fixed stages (Staging, Production) ki jagah le li hai: stages version 2.9 se deprecated hain, aur MLflow 3.18 mein unhe call karne par warning print hoti hai ki unhe hata diya jaayega.

```flow
title: From training run to production
Training run 412 | commit a1b2c3d, data claims-2026-09, val PR AUC 0.46
Training run 412 -[team picks it and registers it]-> claims-fraud v14
claims-fraud v14 -[gate on October claims, then owner signs off]-> Alias champion
Alias champion -[loaded at start-up]-> Claim scoring service
Alias champion -[rollback: point it back]-> claims-fraud v13
```

Ye lesson Hyderabad ke ek insurer ki ML team ke saath chalta hai jo har mahine apna claim-fraud model retrain karti hai.

## Ye kaam kaise karta hai

### Jo kuch ek run ko define karta hai, sab log karo

| Item | Example | Kyun zaroori hai | Kaun record karta hai |
| --- | --- | --- | --- |
| Parameters | `max_depth=6`, `learning_rate=0.05` | Runs ke beech ke farq samjhaata hai | Aap, ya autologging |
| Metrics | Overall aur har region ka PR AUC | Winner chunta hai aur dikhaata hai ki wo kiske liye fail hota hai | Aap (segments hamesha) |
| Code version | Git commit, clean tree | Training logic reproduce karta hai | MLflow, jab Git repo mein script ki tarah run ho |
| Data version | `claims-2026-09` aur saath mein ek hash | Inputs reproduce karta hai | Aap |
| Environment | `requirements.txt`, Python version | "Meri machine par to chalta hai" waali dikkat se bachaata hai | MLflow, har logged model ke saath |
| Model aur schema | Model file, input columns aur types | Serving ko galat inputs reject karne deta hai | Aap, `log_model` ke zariye |
| Seed | `random_state=42` | Rerun karne par wahi model deta hai | Aap |

Do rules ise bharosemand banaate hain.

- **Commit ko usi code ko describe karna chahiye jo run hua.** Jab aap Git repository ke andar script run karte ho, to MLflow commit ko tag `mlflow.source.git.commit` ke roop mein record karta hai, lekin uncommitted edits ko wo nahi pakadta. Aadhi edit hui file ya notebook se chala run aise commit ki or point karta hai jisne use kabhi banaaya hi nahi. Isliye neeche waala script uncommitted changes hone par run hone se mana kar deta hai. Notebook mein, pehle commit karo ya training code ko ek script mein le jaao.
- **Data ka naam data version nahi hai.** `claims-2026-09` sirf ek label hai; uske peechhe waali file koi bhi overwrite kar sakta hai. Aise snapshots store karo jo kabhi usi jagah edit na hon, aur file ka hash log karo taaki chupchaap hua badlaav saamne aa jaaye. DVC jaise tools, ya Delta Lake jaise table formats ka time travel, aapke liye puraane versions rakhte hain (data versioning lesson dekho).

**Autologging** (`mlflow.autolog()`) scikit-learn aur XGBoost jaisi libraries ke zyaadatar parameters aur metrics ek line mein capture kar leta hai. Use aapka data version ya aapke segments pata nahi ho sakte, isliye wo khud jodo.

### Ek training run ko track karna

Ye script fraud model train karta hai aur ek run log karta hai. Ye maankar chalta hai ki claims table mein ek `region` column, ek `region_code` feature aur ek `is_fraud` label hai.

```python
import hashlib, subprocess, sys
import mlflow
import pandas as pd
from mlflow.models import infer_signature
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import average_precision_score
from sklearn.model_selection import train_test_split

DATA = "data/claims-2026-09.parquet"
FEATURES = ["claim_amount", "days_since_policy_start", "prior_claims", "garage_claims_90d", "region_code"]

def git(*args):
    return subprocess.run(["git", *args], capture_output=True, text=True, check=True).stdout.strip()

if git("status", "--porcelain", "--untracked-files=no"):   # ignores mlflow.db and mlruns/
    sys.exit("Uncommitted changes: commit first, or this run cannot be reproduced.")

with open(DATA, "rb") as f:
    data_sha = hashlib.file_digest(f, "sha256").hexdigest()[:12]   # Python 3.11 or newer

df = pd.read_parquet(DATA)
df[FEATURES] = df[FEATURES].astype("float64")      # floats can hold missing values at serving time
train, val = train_test_split(df, test_size=0.2, stratify=df["is_fraud"], random_state=42)
params = {"max_depth": 6, "learning_rate": 0.05, "max_iter": 300, "random_state": 42}

mlflow.set_experiment("claims-fraud")
with mlflow.start_run() as run:
    mlflow.set_tags({"data_version": "claims-2026-09", "data_sha256": data_sha})
    mlflow.log_input(mlflow.data.from_pandas(train, source=DATA, targets="is_fraud"), context="training")
    mlflow.log_params(params)

    model = HistGradientBoostingClassifier(**params).fit(train[FEATURES], train["is_fraud"])
    proba = model.predict_proba(val[FEATURES])
    mlflow.log_metric("val_pr_auc", average_precision_score(val["is_fraud"], proba[:, 1]))
    for region, part in val.groupby("region"):
        s = model.predict_proba(part[FEATURES])[:, 1]
        mlflow.log_metric(f"val_pr_auc_{region}", average_precision_score(part["is_fraud"], s))

    mlflow.sklearn.log_model(
        model, name="model",
        signature=infer_signature(val[FEATURES], proba),
        input_example=val[FEATURES].head(3),
        pyfunc_predict_fn="predict_proba",
        skops_trusted_types=["sklearn.ensemble._hist_gradient_boosting.predictor.TreePredictor"],
    )
    print("run", run.info.run_id)
```

MLflow 3 ki har detail kya karti hai (MLflow 3.18 par check kiya, November 2026):

- **`name="model"`** puraane `artifact_path` argument ki jagah leta hai, jo ab bhi chalta hai lekin ab deprecation warning log karta hai.
- **Koi `registered_model_name` nahi.** Training script ke andar register karne se har experiment ke liye ek registry version ban jaayega. Har run log karo; register sirf winner ko karo.
- **`signature` aur `input_example`** input columns aur types ko model ke saath store karte hain, taaki serving kisi missing ya galat spelling waale column waali request ko reject kar sake. Features pehle floats mein cast kiye jaate hain: integer ke roop mein infer hua column serving time par koi value missing hone par check mein fail ho jaata hai. Phir har caller ko bhi floats hi bhejne honge; check integer columns ko reject karta hai. (MLflow phir bhi integer columns ke baare mein ek hint print kar sakta hai: wo logged dataset ke `is_fraud` label ke baare mein hai, model ke baare mein nahi.) MLflow model ke bagal mein `requirements.txt` aur `conda.yaml` bhi likhta hai.
- **`log_input`** run ko dataset se link karta hai aur uska ek chhota digest store karta hai, jo aapke apne hash ke alaava ek doosra check hai.
- **`pyfunc_predict_fn="predict_proba"`** generic loader se hard 0 ya 1 labels ki jagah fraud probabilities return karwaata hai.
- **`skops_trusted_types`.** MLflow ab scikit-learn models ko skops se save karta hai, jo pickle se zyaada safe format hai, kyunki pickle load karne par file mein chhupa koi bhi code chal sakta hai. Skops un object types ko mana kar deta hai jin par trust karne ko use bataaya nahi gaya, aur `HistGradientBoostingClassifier` ko ye waala chahiye. Sirf unhi types par trust karo jo aapne check kiye hain, aur sirf un models ke liye jo aapne khud train kiye hain.

Default roop se MLflow 3.18 runs ko usi folder mein ek local SQLite file, `mlflow.db`, mein likhta hai jahaan se aap run karte ho. Unhe browse karne ke liye wahin `mlflow ui` chalaao.

### Runs compare karo, phir winner ko register karo

```python
import mlflow
from mlflow import MlflowClient

runs = mlflow.search_runs(experiment_names=["claims-fraud"],
                          order_by=["metrics.val_pr_auc DESC"], max_results=10)

            "metrics.val_pr_auc", "metrics.val_pr_auc_east"]].to_string(index=False))

model_id = client.get_run(run_id).outputs.model_outputs[0].model_id

```

MLflow 3 mein logged model apna alag object hai, `m-5f3a...` jaisi id ke saath, aur us run se linked hai jisne use banaaya, isliye aap use `models:/` aur us id se register karte ho. Puraana `runs:/` form ab bhi chalta hai lekin ab warning deta hai ki us run mein koi model files nahi hain. Version ka description aur tags ek chhote **model card** ka kaam karte hain: kya badla, usne kaun-sa data dekha, known limits, kisne approve kiya.

### Promotion check: wahi data, asli gains, har segment

Yahin trap hai. Champion ka logged PR AUC pichhle mahine ke validation split se aaya tha; candidate ka is mahine ke split se. Fraud patterns aur fraud ka share mahine-dar-mahine badalte hain, isliye un do numbers ki tulna jitni models ki hai utni hi data ki bhi hai. Fair test **dono models ko ek hi fresh holdout par** score karta hai jis par koi bhi train nahi hua: yahaan, October ke claims.

Insurer ke rule ke teen hisse hain:

1. **Overall gain noise se saaf upar hona chahiye.** Holdout claims ko kai baar resample karo (ek bootstrap) aur har baar PR AUC gain dobara nikaalo. Promote tabhi karo jab gain ka 90% interval zero se upar hi rahe.
2. **Kisi bhi region ka fraud-catching recall nahi girna chahiye.** Investigators har mahine sirf top 5% claims check kar sakte hain. Har region ke liye naapo ki uske fraud cases ka kitna share us top 5% mein aata hai. Koi bhi region 2 points se zyaada nahi girna chahiye.
3. **Check ki report padhne ke baad ek owner sign off karta hai.**

```python
import numpy as np
import pandas as pd
import mlflow
from mlflow import MlflowClient
from sklearn.metrics import average_precision_score

NAME = "claims-fraud"
FEATURES = ["claim_amount", "days_since_policy_start", "prior_claims", "garage_claims_90d", "region_code"]
REVIEW_RATE = 0.05        # investigators can check the top 5% of claims each month
MAX_RECALL_DROP = 0.02    # no region may lose more than 2 points of recall
client = MlflowClient()

def scores_of(version, X):
    model = mlflow.pyfunc.load_model(f"models:/{NAME}/{version}")
    return model.predict(X)[:, 1]          # column 1 = probability of fraud

def recall_by_region(y, s, region):
    flagged = np.zeros(len(s), dtype=bool)
    flagged[np.argsort(-s)[: int(len(s) * REVIEW_RATE)]] = True   # the claims investigators open
    return {r: flagged[(region == r) & (y == 1)].mean() for r in np.unique(region)}

def pr_auc_gain_interval(y, s_new, s_old, n=500, seed=0):
    rng = np.random.default_rng(seed)
    gains = []
    for _ in range(n):
        i = rng.integers(0, len(y), len(y))   # resample claims with replacement
        gains.append(average_precision_score(y[i], s_new[i]) - average_precision_score(y[i], s_old[i]))
    return np.percentile(gains, [5, 95])

def check(candidate, holdout):
    champion = client.get_model_version_by_alias(NAME, "champion").version
    X = holdout[FEATURES].astype("float64")      # match the logged signature, or loading code rejects it
    y, region = holdout["is_fraud"].to_numpy(), holdout["region"].to_numpy()
    s_new, s_old = scores_of(candidate, X), scores_of(champion, X)

    low, high = pr_auc_gain_interval(y, s_new, s_old)
    problems = []
    if low <= 0:
        problems.append(f"PR AUC gain not clear: 90% interval {low:+.3f} to {high:+.3f}")
    r_new, r_old = recall_by_region(y, s_new, region), recall_by_region(y, s_old, region)
    for r in r_old:
        if r_new[r] < r_old[r] - MAX_RECALL_DROP:
            problems.append(f"{r}: recall {r_old[r]:.2f} -> {r_new[r]:.2f}")
    return champion, problems

holdout = pd.read_parquet("data/claims-2026-10.parquet")    # last month: neither model trained on it
champion, problems = check(candidate="14", holdout=holdout)
print("blocked:" if problems else "passed: ready for owner sign-off", problems)
```

Teen saavdhaaniyaan. Holdout ko judge rehna chahiye, coach nahi: agar log models ko tab tak tune karte rahein jab tak wo October ke claims par pass na ho jaayein, to October fresh nahi rehta. 2-point limit ek business decision hai; kisi ke results dekhne se pehle hi fraud team ke saath use tay kar lo. Aur kareeb 150 fraud cases waale region mein sirf teen cases ke idhar-udhar hone se 2 points hil jaate hain, isliye ye guardrail jaanboojhkar noisy hai: ye kabhi-kabhaar ek theek model ko bhi block kar deta hai, aur ye dono mein se sasti galti hai. Block hua model kisi insaan ke paas jaata hai, koodedaan mein nahi.

### Aliases khiskaakar promote aur roll back karo

```python
from mlflow import MlflowClient
NAME = "claims-fraud"
client = MlflowClient()

def promote(candidate, champion, approver):
    client.set_model_version_tag(NAME, candidate, "approved_by", approver)
    client.set_registered_model_alias(NAME, "previous", champion)
    client.set_registered_model_alias(NAME, "champion", candidate)

def rollback():
    previous = client.get_model_version_by_alias(NAME, "previous").version
    client.set_registered_model_alias(NAME, "champion", previous)
```

Serving code `mlflow.pyfunc.load_model("models:/claims-fraud@champion")` load karta hai. Chalte hue server ne model ek baar, start-up par, load kiya tha, isliye jab tak service reload ya restart na ho, alias khiskaane se kuch nahi badalta. Reload ko promotion aur rollback steps ka hissa banaao, aur har prediction ke saath served version log karo taaki lineage ek-ek decision tak pahunche.

### Kya gain asli hai? Apne browser mein try karo

Do models unhi 6,000 claims ko score karte hain, jinmein se kareeb 3% fraud hain. Candidate behtar dikhta hai, lekin bootstrap poochhta hai ki kya ye gain aise hi claims waale kisi doosre mahine mein bhi tikega.

```python
import numpy as np
from sklearn.metrics import average_precision_score

rng = np.random.default_rng(7)
n = 6000                                    # one month of claims, about 3% of them fraud
y = (rng.random(n) < 0.03).astype(int)
signal = 2.5 * y + rng.normal(0, 1, n)      # the pattern both models learned
champion = signal + rng.normal(0, 0.60, n)  # each model adds its own errors
candidate = signal + rng.normal(0, 0.55, n) # slightly fewer errors

print("champion PR AUC ", round(average_precision_score(y, champion), 3))
print("candidate PR AUC", round(average_precision_score(y, candidate), 3))

gains = []
for _ in range(200):                        # resample the same claims for both models
    i = rng.integers(0, n, n)
    gains.append(average_precision_score(y[i], candidate[i]) - average_precision_score(y[i], champion[i]))
low, high = np.percentile(gains, [5, 95])
print(f"90% interval for the gain: {low:+.3f} to {high:+.3f}")
print("promote" if low > 0 else "too close to call: keep the champion")
```

Ye PR AUC 0.439 ke muqaable 0.472 print karta hai, phir bhi interval kareeb -0.02 se +0.07 tak jaata hai: 200 se kam fraud cases par 0.03 ka gain abhi proof nahi hai. Candidate ka `0.55` badalkar `0.30` karo aur phir se run karo: ab gain itna bada hai ki promote kiya ja sake.

### LLM apps ke liye bhi yahi idea

Prompt ya retrieval ke badlaav ko ek experiment ki tarah dekho. Prompt version, model name, top-k, chunk size aur har category ke eval scores ko ek run ki tarah log karo. Phir "kya prompt ke version 13 se Hindi questions mein madad mili?" ek sorted table ban jaata hai, yaaddaasht nahi. Yahi noise rule yahaan bhi lagta hai: 50 eval questions par 2-point gain aamtaur par chance hota hai.

## Ek example se samjho

Hyderabad insurer ki ML team har mahine apna claim-fraud model retrain karti hai. Tracking se pehle models `final_v3_really_final.pkl` jaise naamon waali files the, aur jab ek auditor ne poochha ki production model ko kis data ne train kiya, to koi nahi bata paaya.

Ab har run apne parameters, commit, data snapshot aur hash, aur overall va har region ka validation PR AUC log karta hai. Neeche ke numbers sirf samjhaane ke liye hain.

| Run | Badlaav | Val PR AUC (apna split) | Sabse kamzor region | Faisla |
| --- | --- | --- | --- | --- |
| 398 | Pichhle mahine ka champion, v13, August data par trained | 0.41 | 0.33 | Baseline |
| 405 | Zyaada gehre trees | 0.42 | 0.31 | Drop kiya: sabse kamzor region gira |
| 409 | Naya feature: policy shuru hone ke 30 din ke andar claim | 0.45 | 0.38 | Ummeed jagaata hai |
| 412 | Naya feature, tuned learning rate | 0.46 | 0.39 | v14 ke roop mein registered |

Lubhaane waala nateeja hai "0.46 ne 0.41 ko hara diya, promote karo". Lekin run 398 ko August ke validation split par score kiya gaya tha aur run 412 ko September ke. Isliye gate v13 aur v14 ko October ke 20,000 claims par score karta hai, jinmein se kareeb 600 fraud hain:

- PR AUC: v13 0.40, v14 0.44. Gain ka 90% bootstrap interval +0.02 se +0.06 hai, to gain asli hai.
- Region ke hisaab se top 5% mein recall: north 0.52 se 0.55, south 0.48 se 0.53, east 0.44 se 0.47, west 0.50 se 0.49. West 1 point girta hai, jo 2-point limit ke andar hai.

## Aam galtiyaan

- **Spreadsheets mein haath se tracking karna.** Ye adhoori rehti hai, puraani pad jaati hai aur data version kabhi record nahi karti.
- **Data ke naam ko data version maan lena.** Usi naam se overwrite hui file chupchaap reproducibility tod deti hai; hash log karo aur snapshots read-only rakho.
- **Aise code ka commit log karna jo commit hi nahi hua.** Notebook edits aur uncommitted changes commit tag ko jhootha bana dete hain.
- **Alag-alag mahinon ke logged metrics compare karna.** Champion aur candidate ko ek hi fresh holdout par score karo.
- **Bahut chhote gain par promote karna.** Kuch sau positive cases ke saath 0.01 se 0.03 ka badlaav chance ho sakta hai.
- **Sirf overall score par promote karna.** Overall gain kisi ek region ya customer group ke nuksaan ko chhupa sakta hai.
- **Models chunne ke liye test set ko baar-baar use karna.** Ek baar us par tune kar liya, to wo future ko nahi naapta.
- **Har run ko register karna.** Registry experiments se bhar jaati hai; sirf wahi register karo jo aap shaayad ship karo.
- **Production mein file path load karna.** Registry alias se serve karo, ek `previous` alias rakho, aur alias khisakne par service reload karo.
- **Integer input columns jo khaali ho sakte hain.** Infer hua signature unhe integers mark karta hai, to serving time par missing value schema check mein fail ho jaati hai; aise columns ke liye floats use karo.
- **Failed runs delete karna, ya ek hi laptop par tracking karna.** Failed runs dikhaate hain ki kya kaam nahi karta, aur ek laptop par rakhi history usi ke saath chali jaati hai.

## Kab tracking halki ho sakti hai

- **Ek akela quick experiment**: notebook aur likhe hue results kaafi ho sakte hain.
- **Sirf prompt waale prototypes**: prompt versions aur scores ki spreadsheet achhi shuruaat hai, jab tak ek se zyaada log prompts badalna shuru na karein.
- **Ek baar train hua aur bahut kam badalne waala model**: uski lineage ek baar, dhyaan se record karo, aur phir bhi use registry se serve karo.

## Demo se production tak

- **Ek shared tracking server chalaao**, database backend aur artefacts ke liye cloud storage ke saath, company ke sign-in ke peechhe, jaise `mlflow server --backend-store-uri postgresql://... --artifacts-destination s3://...`. Uska backup rakho: ye har model decision ki history hai.
- **Pipeline mein tracking automatic banaao**, taaki koi run bina log hue ho hi na sake.
- **Promotion ko code mein gate karo**, usi fresh holdout par, noise aur segment checks ke saath, phir owner ka sign-off zaroori karo.
- **Alias se serve karo**, har prediction ke saath served version log karo, aur zaroorat padne se pehle rollback ki rehearsal kar lo.
- **Prompt aur retrieval experiments ko** training runs ki tarah hi track karo.

## Practice karo

MLflow ki tracking guide aur Made With ML ke experiment tracking aur versioning lessons padho.

1. Ek training script mein tracking jodo: parameters, per-segment metrics, ek clean commit, ek data hash, aur signature ke saath model. Check karo ki uncommitted edit hone par script run hone se mana karta hai.
2. Do settings badal-badalkar das experiments chalaao aur unhe `mlflow ui` mein compare karo. Aisa ek run dhoondho jo overall jeetta hai lekin kisi segment par haarta hai.
3. Sabse achhe do ko register karo, ek ko `champion` set karo, aur doosre ke khilaaf promotion check aise holdout par chalaao jis par dono mein se koi train nahi hua.
4. Promote karo, phir roll back karo, aur confirm karo ki naye sire se start hua prediction script puraana version load karta hai.

**Aapka kaam poora hai jab aap** kisi ek prediction ko us model version, run, code commit aur data snapshot tak trace kar sako jisne use banaaya.
