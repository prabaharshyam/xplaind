## Ye kya hai

**Experiment tracking** har training run ko apne aap log karta hai: code version (Git commit), data version, parameters, samay ke saath metrics, plots jaise artefacts, aur train hua model. **Model registry** chune hue model versions ko unke metadata aur alias jaise label ke saath (jaise "production") store karti hai, taaki deployment hamesha ek jaana-pehchaana, approved model use kare.

Tools mein MLflow (open source), Weights & Biases aur cloud ML platforms ki built-in tracking shaamil hain. Recent MLflow versions iske liye movable aliases use karte hain; uske purane fixed stages (Staging, Production) deprecated hain.

```flow
Training run 412 | params: depth=6, lr=0.05, features v3; code git a1b2c3d; data claims-2026-09; PR AUC 0.46 -[best run, approved]-> Model registry: fraud-model v14
Model registry: fraud-model v14 -[alias "production"]-> Production loads "fraud-model@production"
Production loads "fraud-model@production" -[rollback: move the alias]-> fraud-model v13, the previous one
```

Is lesson mein hum Hyderabad ke ek insurer ki ML team ke saath chalenge, jo apna claim-fraud model har mahine retrain karti hai.

## Ye kaam kaise karta hai

**Run ko define karne waali har cheez log karo.** Parameters (learning rate, depth, use hue features), metrics (validation aur test scores, segment ke hisaab se), Git commit, dataset version ya hash, environment (library versions), aur outputs (model file, confusion matrix, feature importance plot).

**Runs compare karo.** Tracking UI runs ko unke parameters aur metrics ke saath list karta hai, score se sort karta hai aur runs ke beech metrics plot karta hai. Aap dekh sakte ho ki depth 6 ne depth 8 ko haraya, ya ki ek naye feature ne sirf ek segment mein madad ki.

**Reproduce karo.** Code, data aur parameters record hone par koi bhi dobara chala kar wahi model pa sakta hai (randomness ke daayre mein, jise seeds control karte hain).

**Winner ko register karo.** Chune hue run ke model ko registry mein naye version ke roop mein promote karo, notes ke saath: kya badla, evaluation results, kisne approve kiya. Production file path ki jagah registry se "production version" load karta hai.

**Promotion rules.** Promote karne se pehle: model tay kiye metrics par maujooda production model ko haraye, key segments samet; recent data par checks pass kare; aur owner ki approval ho. Purana version rollback ke liye taiyaar rakho.

**Lineage.** Audits aur debugging ke liye chain saaf honi chahiye: production model version → training run → code commit → data version → evaluation results.

**Kya log karein, aur kyun:**

| Item | Example | Kyun maayne rakhta hai |
| --- | --- | --- |
| Parameters | `depth=6`, `learning_rate=0.05` | Runs ke beech ka farak samjhata hai |
| Metrics | PR AUC 0.46 overall, region ke hisaab se | Winner ko nishpaksh chunta hai |
| Code version | Git commit `a1b2c3d` | Training logic reproduce karta hai |
| Data version | `claims-2026-09`, hash ke saath | Inputs reproduce karta hai |
| Environment | Library versions, Python version | "Mere machine par chalta hai" se bachata hai |
| Artefacts | Model file, plots, feature importance | Reviewers ko results inspect karne deta hai |
| Seed | `random_state=42` | Randomness control karta hai |

**Script mein jodna.** MLflow ke saath tracking kuch hi lines hai: ek run shuru karo, compute karte waqt parameters aur metrics log karo, ant mein model log karo, aur commit aur data version ke tags set karo. Library run ko local folder ya team ke shared tracking server mein record karti hai. scikit-learn aur XGBoost jaisi libraries ke liye autologging on karo taaki zyadatar parameters aur metrics bina extra code ke capture ho jayein, phir data version aur segment metrics khud jodo, kyunki koi tool unhein guess nahi kar sakta.

**MLflow ke saath ek training run track karna.**

```python
import hashlib, subprocess
import mlflow
import mlflow.sklearn
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import average_precision_score

def data_hash(path):
    return hashlib.sha256(open(path, "rb").read()).hexdigest()[:12]

mlflow.set_experiment("claims-fraud")
params = {"max_depth": 6, "learning_rate": 0.05, "max_iter": 400}

with mlflow.start_run() as run:
    mlflow.set_tags({"git_commit": subprocess.getoutput("git rev-parse --short HEAD"),
                     "data_version": "claims-2026-09", "data_hash": data_hash("data/train.parquet")})
    mlflow.log_params(params)
    model = HistGradientBoostingClassifier(**params, random_state=42).fit(X_train, y_train)
    scores = model.predict_proba(X_val)[:, 1]
    mlflow.log_metric("pr_auc", average_precision_score(y_val, scores))
    for region in ["north", "south", "east", "west"]:
        m = val_region == region
        mlflow.log_metric(f"pr_auc_{region}", average_precision_score(y_val[m], scores[m]))
    mlflow.sklearn.log_model(model, artifact_path="model", registered_model_name="claims-fraud")
```

**Alias ke saath promotion.** Production hamesha `models:/claims-fraud@champion` load karta hai; promote karna ek check ke baad alias ko hilana hai:

```python
from mlflow import MlflowClient

client = MlflowClient()

def promote_if_better(name, candidate_version, metric="pr_auc", segments=("north", "south", "east", "west")):
    def metrics_of(version):
        run_id = client.get_model_version(name, version).run_id
        return client.get_run(run_id).data.metrics
    try:
        champ = client.get_model_version_by_alias(name, "champion").version
    except Exception:
        champ = None
    new = metrics_of(candidate_version)
    if champ:
        old = metrics_of(champ)
        if new[metric] < old[metric]:
            return f"rejected: {metric} {new[metric]:.3f} < {old[metric]:.3f}"
        worse = [s for s in segments if new[f"{metric}_{s}"] < old[f"{metric}_{s}"] - 0.02]
        if worse:
            return f"rejected: worse on {worse}"
    client.set_registered_model_alias(name, "champion", candidate_version)
    return f"version {candidate_version} is now champion (was {champ})"

model = mlflow.pyfunc.load_model("models:/claims-fraud@champion")    # in the serving code
```

Rollback matlab `set_registered_model_alias` ko wapas purane version par karna.

**LLM apps ke liye wahi idea.** Prompt ya retrieval ke badlaav ko ek experiment maano: prompt version, model name, top-k, chunk size aur category ke hisaab se eval scores ko ek run ki tarah log karo. Phir "kya prompt ke v13 ne Hindi sawaalon mein madad ki?" ek sorted table ban jaata hai, yaaddaasht nahi.

**Tracking server ko asli rakho.** Database backend aur artefacts ke liye cloud storage waala, company ke sign-in ke peeche shared tracking server, ek laptop par padi files se behtar hai. Uska backup lo; ye har model decision ka itihaas hai.

**Browser mein try karo.** Ek minimal experiment log: runs record karo, phir ek metric se best chuno. Apne khud ke runs jodo.

```python
runs = []
def log_run(params, metrics, commit):
    runs.append({"params": params, "metrics": metrics, "commit": commit})

log_run({"depth": 4, "lr": 0.1}, {"pr_auc": 0.41}, "a1b2c3d")
log_run({"depth": 6, "lr": 0.05}, {"pr_auc": 0.46}, "a1b2c3d")
log_run({"depth": 8, "lr": 0.05}, {"pr_auc": 0.44}, "f9e8d7c")

best = max(runs, key=lambda r: r["metrics"]["pr_auc"])
for r in sorted(runs, key=lambda r: -r["metrics"]["pr_auc"]):
    print(r["metrics"]["pr_auc"], r["params"], r["commit"])
print("best:", best["params"])
```

## Ek example se samjho

Hyderabad ke ek insurer ki ML team apna claim-fraud model har mahine retrain karti hai. Tracking se pehle, models `final_v3_really_final.pkl` jaise naam ki files the, aur jab auditor ne poochha toh koi nahi bata paaya ki production kaunsa data version use kar raha tha.

MLflow ke saath:

- Har training run parameters, Git commit, data snapshot id, overall aur per-region PR AUC, aur model log karta hai.
- Ek comparison view dikhata hai ki "claim filed within 30 days of policy start" jodne se PR AUC overall 0.41 se 0.46 hua, aur sabse zyada do regions mein.
- Best run version 14 ke roop mein notes aur reviewer ke naam ke saath register hota hai; production registry ka production alias load karta hai.
- Ek promotion check script candidate ko maujooda production version se pichhle mahine ke claims par compare karti hai aur agar kisi region ka recall do points se zyada gire toh promotion block karti hai.

Jab auditor chhe mahine baad wapas aata hai, team ek vivadit claim ko flag karne waale model ki poori lineage minutes mein dikha deti hai.

| Run | Badlaav | PR AUC overall | Sabse kamzor region | Faisla |
| --- | --- | --- | --- | --- |
| 398 | Pichhle mahine ka production model | 0.41 | 0.33 | Baseline |
| 405 | Gehre trees | 0.42 | 0.31 | Reject: sabse kamzor region gira |
| 409 | Naya feature: claim within 30 days of start | 0.45 | 0.38 | Ummeedwaar |
| 412 | Naya feature, tuned learning rate | 0.46 | 0.39 | Review ke baad v14 ke roop mein register |

Comparison view ne run 405 ki regional girawat ek nazar mein dikha di. Spreadsheet ke zamane mein, use overall score par promote kar diya jaata.

## Aam galtiyaan

- **Spreadsheets mein haath se track karna.** Woh adhoora hota hai aur purana pad jaata hai.
- **Data versions log na karna.** Sirf code aur parameters se model reproduce nahi ho sakta.
- **Production mein models ko file paths se load karna.** Registry use karo taaki deployed version saaf rahe.
- **Sirf overall score par promote karna.** Segments aur recent data check karo.
- **Rollback plan na hona.** Purana version taiyaar rakho.
- **Sirf final run log karna.** Fail hue experiments team ko sikhate hain ki kya kaam nahi karta; unhein rakho.
- **Seed bhool jaana.** Uske bina same code aur data ki do runs alag models de sakti hain.
- **Production ka registry alias ki jagah file path load karna.**
- **Sirf overall metrics log hona,** isliye promotion key segments check nahi kar paata.
- **Ek laptop par tracking,** jisse history uske saath hi gayab ho jaati hai.

## Jab tracking halki ho sakti hai

- **Ek akela quick experiment**: results likhi hui notebook kaafi ho sakti hai.
- **Sirf prompt waale prototypes**: prompt versions aur scores ki spreadsheet achhi shuruaat hai.
- **Ek baar train hua aur kam badalne waala model**: uski lineage ek baar dhyaan se record karo.

## Demo se production tak

- **Har run ke liye commit, data version, parameters aur segment metrics log karo.**
- **Registry alias se serve karo,** aur automated check plus owner ki approval ke saath promote karo.
- **Pichhla champion** rollback ke liye taiyaar rakho.
- **Prompt aur retrieval experiments ko** training runs ki tarah track karo.
- **Access control ke saath, backup waala shared tracking server** chalao.

## Practice karo

MLflow ki tracking guide aur Made With ML ke experiment tracking aur versioning lessons padho.

1. Ek training script mein tracking jodo: parameters, metrics, Git commit, data hash aur model.
2. Do settings badal-badal kar das experiments chalao aur tracking UI mein compare karo.
3. Best model register karo, ek "current production" model ke khilaaf promotion check likho, aur register hue model ko alag prediction script mein load karo.
4. Apne do registered versions par promote_if_better chalao, phir alias ko wapas roll karo aur confirm karo ki serving code purana version load karta hai.

**Aapka kaam poora jab:** aap kisi prediction ko us run, code commit aur data version tak trace kar sako jisne woh model banaya.
