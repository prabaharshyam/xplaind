## Ye kya hai

Language models web ke text se seekhte hain, aur web zyadatar English hai. Ek bahut use hone wale training dataset mein text ka lagbhag 46% English hai. Indian languages uske mukable bahut chhoti hain:

| Language | Speakers (millions) | Dataset mein hissa | Lagbhag kitna under-represented |
| --- | --- | --- | --- |
| Punjabi | 113 | 0.006% | 230 guna |
| Kannada | 64 | 0.012% | 66 guna |
| Telugu | 95 | 0.018% | 65 guna |
| Gujarati | 62 | 0.013% | 62 guna |
| Marathi | 99 | 0.021% | 58 guna |
| Bengali | 272 | 0.093% | 37 guna |
| English (tulna ke liye) | 1,452 | 45.9% | over-represented |

Aakhri column har language ke duniya ki aabaadi mein hisse ki tulna dataset mein uske hisse se karta hai. Ye figures Common Crawl web dataset ke 2023 ke ek study se hain, jo Chip Huyen ki *AI Engineering* mein cite hua hai. Jin languages ke bolne waalon ke mukable training text kam hota hai, unhe **low-resource languages** kehte hain.

Isse teen practical problems aati hain:

1. **Kam quality.** General knowledge ke ek jaane-maane test par, ek leading model ne Telugu, Marathi aur Punjabi mein sabse kharaab score kiya, jo test ki gayi languages mein sabse zyada under-represented hain.
2. **Zyada cost aur delay.** Ek **tokenizer** text ko tokens mein todta hai, aur kai tokenizers mukhya roop se English ke liye design hue the. Hindi ya Tamil mein same vaakya ke liye unhe kai guna zyada tokens lag sakte hain. Isi ko high **token fertility** kehte hain. Kyunki aap per token pay karte ho aur models ek waqt mein ek token likhte hain, wahi jawab zyada mehenga padta hai aur der se aata hai.
3. **Real usage ganda hota hai.** Indians languages milate hain ("mera order kab aayega?"), scripts badalte hain, aur Indian languages ko Roman letters mein type karte hain. Sirf saaf, formal text se bane test sets ye sab chhod dete hain.

Tasveer behtar ho rahi hai: naye tokenizers Indian scripts ko kahin behtar handle karte hain, aur Indian groups Indian languages ke liye models aur data banate hain. Phir bhi, aapko apne users ke liye language-by-language naapna padega.

```flow
title: Ek Indian language ke liye approach chunna
Real user questions in each language -> Score general models | quality, tokens, cost
Score general models -> Good enough?
Good enough? -[yes]-> Ship with monitoring per language
Good enough? -[no]-> Try translate to English and back | Indian translation model
Try translate to English and back -> Try an Indian-language model
Try an Indian-language model -> Pick the best on quality and cost
Pick the best on quality and cost -> Ship with monitoring per language
```

## Ye kaam kaise karta hai

**Token fertility khud naapo.** Aap jin models par vichar kar rahe ho, unke tokenizer se same message ke tokens English mein aur apne users ki languages mein gino. Wahi matlab likho, word-for-word translation nahi.

```python
# pip install tiktoken
import tiktoken

texts = {
    "English": "When will my order arrive? I paid yesterday.",
    "Hindi": "मेरा ऑर्डर कब आएगा? मैंने कल भुगतान किया था।",
    "Hinglish": "Mera order kab aayega? Maine kal payment kiya tha.",
    "Tamil": "என் ஆர்டர் எப்போது வரும்? நான் நேற்று பணம் செலுத்தினேன்.",
}
for name in ["cl100k_base", "o200k_base"]:          # an older and a newer tokenizer
    enc = tiktoken.get_encoding(name)
    counts = {lang: len(enc.encode(t)) for lang, t in texts.items()}
    base = counts["English"]
    print(name, {lang: f"{n} ({n / base:.1f}x)" for lang, n in counts.items()})
```

Chalao toh aksar dikhega ki naya tokenizer Hindi aur Tamil ki ginti ko tezi se ghataata hai, jabki Romanised Hinglish English ke kareeb rehti hai. Doosre providers alag tokenizers use karte hain, isliye jin par aap vichar kar rahe ho unmein se har ek check karo.

**Ek language ko serve karne ke teen tareeke.**

- **Ek general model, seedha.** Sabse simple. Haal ke strong models aksar Hindi mein achhe hote hain, aur kam-resource languages mein kamzor. Maanne se pehle test karo.
- **Translate karo, jawab do, wapas translate karo.** Sawaal ko ek strong Indian-language translation model (jaise AI4Bharat ka open IndicTrans2) se English mein translate karo, English mein jawab do, wapas translate karo. Kamzor languages ki quality badha sakta hai, par steps, delay aur galtiyan jodta hai, aur nuance kho deta hai: *aap* aur *tum* jaise respect markers "you" mein simat jaate hain, aur local terms galat translate ho sakte hain.
- **Indian languages ke liye bana model.** Indian startups aur research groups kahin zyada Indian-language text par models aur tokenizers train karte hain. Sarkaar ka Bhashini platform translation aur speech services deta hai. Ye Indian languages ke liye zyada strong aur sasta ho sakta hai, par kisi bhi model ki tarah ise apne test set par compare karo.

**Speech bhi matter karti hai.** Kai users type karne se bolna pasand karenge, khaaskar shehron ke bahar. Speech recognition ki quality language, accent aur background noise ke hisaab se badalti hai, isliye apne users ki real recordings se test karo.

| Approach | Kamzor languages mein quality | Cost aur speed | Mukhya risk |
| --- | --- | --- | --- |
| General model, seedha | Badalti hai; language ke hisaab se check karo | Jahan tokenizers inefficient hain wahan zyada ho sakti hai | Akdi bhasha, galat local terms |
| English mein translate karke wapas | Kamzor languages ke liye aksar behtar | Extra steps aur delay | Nuance kho jaata hai, names galat translate hote hain |
| Indian-language model | Indian languages mein aksar strong | Aksar efficient tokenizers | General knowledge kam; check karo |
| Upar ke kisi ke saath local facts ka retrieval | Schemes, prices, names par behtar | Chhoti extra cost | Har language mein sources ko current rakhna padega |

**Apne browser mein try karo.** Wahi message Indian scripts mein zyada bytes leta hai, aur tokens aksar bytes ko follow karte hain. Apne vaakya try karo.

```python
samples = {
    "English": "Please send the electricity bill",
    "Hindi": "कृपया बिजली का बिल भेजें",
    "Tamil": "தயவுசெய்து மின்சார கட்டணத்தை அனுப்புங்கள்",
}
for lang, text in samples.items():
    chars, utf8 = len(text), len(text.encode("utf-8"))
    print(f"{lang:<8} {chars:>3} characters, {utf8:>3} UTF-8 bytes, {utf8 / chars:.1f} bytes per character")
```

## Ek worked example

Pune ki ek agritech company Marathi aur Hindi mein kisaanon ke liye chat aur voice se ek helpline bana rahi hai, lagbhag 50,000 sawaal mahine ke. Kai kisaan Marathi Roman script mein type karte hain.

Wo 300 real sawaalon ka ek test set banate hain: Marathi aur Hindi, Devanagari aur Roman script, crops, mausam aur schemes ke baare mein, native-speaking agronomists dwara check kiye hue. Phir teen options compare karte hain.

| Option | Sahi aur natural (Marathi) | Sahi aur natural (Hindi) | Har answer ke average tokens | 1,000 answers ki cost |
| --- | --- | --- | --- | --- |
| General model, seedha | 68% | 82% | 410 | ₹310 |
| English mein translate, jawab, wapas translate | 76% | 81% | 190 (English) plus translation | ₹260 |
| Retrieval ke saath Indian-language model | 84% | 86% | 230 | ₹150 |

Ye numbers udaharan ke liye hain, ye dikhane ke liye ki compare kaise karein. Scheme names har option mein galtiyon ka sabse bada source the, isliye team Marathi aur Hindi mein official scheme pages ka retrieval aur exact names ka glossary jodti hai. Wo language-by-language quality monitor karte rehte hain, kyunki ek model update Hindi behtar karke chupchaap Marathi ko bigaad sakta hai.

## Aam galtiyaan

- **Sirf English mein test karna**, phir paanch languages mein launch karna.
- **Sirf formal, Devanagari text par test karna.** Real users languages milate hain aur Roman script mein type karte hain.
- **Token counts ko ignore karna.** English mein sasti feature Tamil mein kai guna mehengi ho sakti hai.
- **Sab kuch word for word translate karna.** Names, schemes aur respectful forms aksar toot jaate hain.
- **"Indian languages" ko ek maan lena.** Hindi mein quality se Odia ya Assamese ke baare mein bahut kam pata chalta hai.
- **Evaluation mein native speakers ko chhod dena.** Fluent dikhne wala text bhi galat ya unnatural ho sakta hai.

## Jab English theek hai

- **Jo professional users English mein kaam karte hain**, jaise developers ya analysts, wo use pasand kar sakte hain.
- **Bahut technical content**, jahan English terms standard hain, local-language explanations ke saath English mein reh sakta hai.
- **Shuruaati prototypes** ek language mein shuru ho sakte hain, bas baaki ke liye plan aur budget rakho.

## Demo se production tak

- **Har metric ko language aur script ke hisaab se report karo**, sirf overall nahi.
- **Har language ke liye budget banao**, naape hue tokens per answer se.
- **Har language mein product names, schemes aur terms ke glossaries rakho** aur unhe retrieve karo.
- **Users ko language chunne do**, aur jis mein unhone likha usi mein jawab do.
- **Har model badlaav ke baad dobara test karo**, kyunki gain aur loss language ke hisaab se alag hote hain.
