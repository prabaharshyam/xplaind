## Ye kya hai

Har AI product idea ke saamne shuru mein hi do sawaal aate hain, aur inmein galti mehengi padti hai:

1. **Feasibility.** Kya AI hamare real data par, theek-thaak cost aur speed par, ye task kaafi achhe se kar sakta hai?
2. **Build banaam buy.** Kya hum ek taiyaar product khareedein, pehle se use ho rahe platform mein ek AI feature configure karein, ya apna build karein?

Teams aksar pehla sawaal chhod deti hain aur doosre par mahinon bahas karti hain. Behtar kram ye hai: kuch dinon mein feasibility test karo, jo options kaam nahi kar sakte unhe chhaant do, phir bache hue options ki cost aur risk par tulna karo.

```flow
title: Idea se delivery ke faisle tak
Idea -> 20-50 real examples par prototype | mahine nahi, din
20-50 real examples par prototype -[bahut door]-> Abhi feasible nahi | context ya data jodo, ya intezaar karo
20-50 real examples par prototype -[kareeb]-> Options ko chhaanto
Options ko chhaanto -[fit ya compliance mein fail]-> Bahar
Options ko chhaanto -[pass]-> Do saal ki cost ki tulna karo
Do saal ki cost ki tulna karo -> Chuno aur review date tay karo
Chuno aur review date tay karo -> Go-live se pehle bada evaluation
```

Ye lesson Sana ke saath chalta hai, jo Hyderabad ki ek hospital chain mein product manager hain. Wo test karti hain ki kya AI discharge summaries draft kar sakta hai, phir numbers ke saath tay karti hain ki ise kaise deliver karein. Aakhir tak aap ek quick feasibility test chala paoge, faisle ke dono pehluon ki cost nikaal paoge, aur buy, configure ya build ke chunaav ka bachaav kar paoge.

## Ye kaise kaam karta hai

### Step 1: kuch dinon mein prototype banao

20 se 50 **real** examples lo, aur agar unmein personal data hai toh mask karo. Ek capable model aur ek simple prompt ke saath task try karo, haath se ya kisi notebook mein. Yahi **proof of concept** hai: chhota, tez aur imaandaar. Sirf saaf-suthre cases nahi, mushkil cases bhi lo, jaise kharaab scans, mili-juli bhaashaayein aur lambe records.

Phir outputs ko ek **domain expert** se judge karwao, prompt likhne waale engineers se nahi. Jinhone kuch banaaya hai, wo wahi dekhte hain jo unka matlab tha, wo nahi jo page par likha hai. Har output ko ek simple scale par rate karo:

| Rating | Matlab |
| --- | --- |
| Usable | Sahi, zyada se zyada chhote edits chahiye |
| Needs work | Idea sahi, bade edits chahiye |
| Unsafe ya wrong | Use kiya toh nuksaan hoga |

- Agar results bahut door hain, toh shaayad task abhi feasible nahi hai. Use zyada context, behtar data, ya aage chalkar ek behtar model chahiye ho sakta hai.
- Agar results kareeb hain, toh feasibility ki sambhaavna zyada hai. Ab asli kaam reliability, integration, safety aur evaluation hai, ye nahi ki model ye kar bhi sakta hai ya nahi.

Ye 20 se 50 examples aur unki ratings sambhaalkar rakho. Yahi aapka pehla evaluation set banega, aur har vendor aur aage aane waale har model ko aap isi set par chalaoge.

### Chhota sample kya bata sakta hai aur kya nahi

Prototype "kya hum aage badhein?" ka jawaab deta hai, "kya launch karna safe hai?" ka nahi. Chhote samples mein rare failures chhip jaate hain.

Maan lo 40 mein se 2 outputs unsafe hain. Ye 5% jaisa dikhta hai. Par sirf 40 examples ke saath, asli unsafe rate 1% se kam se lekar lagbhag 17% tak kuch bhi ho sakta hai (ek exact 95% confidence interval). 300 mein se 0 unsafe bhi sirf itna batata hai ki asli rate shaayad lagbhag 1.2% se kam hai.

Toh rule ye hai: feasibility ka faisla chhote sample par karo, par go-live ka faisla isse kahin bade evaluation par karo, jismein sabse gambhir failure type ko alag se gina jaaye.

### Step 2: cost aur speed ka andaaza lagao

Prototype se note karo ki har request kitne tokens use karti hai aur har jawaab mein kitna samay lagta hai. Phir use volume se guna karo. Misaal ke liye, samjhaane ke liye banaayi gayi prices ke saath:

- Maan lo ek request 12,000 input tokens aur 1,000 output tokens use karti hai.
- Maan lo model ki keemat ₹250 prati million input tokens aur ₹1,000 prati million output tokens hai.
- Toh ek request ki cost hai 12,000 × ₹250 ÷ 1,000,000 + 1,000 × ₹1,000 ÷ 1,000,000 = ₹3 + ₹1 = ₹4.

Asli prices aksar badalti hain. Unhe provider ke pricing page se lo aur saath mein wo taareekh likho jis din aapne check kiya. Retries aur evaluation runs ke liye ek margin jodo, misaal ke liye 25%.

Speed ko user ke sabr se bhi milaakar dekho. Ek doctor draft ke liye das seconds rukega, do minute nahi.

### Step 3: teen options ko jaano

| Option | Ye kya hai | Taakat | Kamzori |
| --- | --- | --- | --- |
| **Product khareedna** | Us use case ke liye ek taiyaar tool, jaise koi document-processing service | Sabse tez; updates aur model badlaav vendor sambhaalta hai | Customisation kam; vendor ka roadmap; aapka data vendor ke paas jaata hai |
| **Platform configure karna** | Pehle se use ho rahe software ke andar ek AI feature, jaise aapka CRM, help desk ya hospital system | Tez; maujooda data aur permissions use karta hai | Flexibility kam; usi platform se bandha |
| **Build** | Model API ya open-weight model par aapka apna system | Fit, safety checks aur data par sabse zyada control | Engineers, evaluation aur lagaataar maintenance chahiye |

"Build" ke andar ek doosra faisla chhipa hai, jo regulated Indian sectors mein aksar maamla tay kar deta hai:

| Build route | Cost ke mukhya kaaran | Zaroori skills | Data control |
| --- | --- | --- | --- |
| Hosted model API, ho sake toh kisi Indian cloud region mein | Har token ke hisaab se pay; set-up thoda | Prompting, evaluation, integration | Data aapke contract ke tahat cloud provider ke paas jaata hai; region aur retention check karo |
| Open-weight model self-host karna | GPUs jinka paisa idle rehne par bhi lagta hai, aur unhe chalaane waale log | Model serving, scaling, security patching | Data aapke apne account ya data centre mein rehta hai, par har failure aapki hai |

Ek samajhdaar default: hosted API se shuru karo. Self-host tabhi karo jab aapke rules data ko aapke systems se bahar jaane na dein, ya jab volume itna zyada aur sthir ho ki GPUs shaayad hi kabhi idle rahein. Har model ki availability cloud region ke hisaab se alag hoti hai, isliye kisi model ke ird-gird design karne se pehle region check karo.

### Step 4: chhaanto, phir tulna karo

Kuch factors pass ya fail waale hote hain. Inhe pehle check karo, kyunki koi bhi keemat ek fail hone waale option ko theek nahi bana sakti:

1. **Fit.** Kya ye aapki languages, document formats, templates aur workflows sambhaalta hai? Ise vendor ke demo data par nahi, apne evaluation set par test karo.
2. **Data aur compliance.** Data kahan ja sakta hai? Kya ye aapke security, privacy aur sector rules poore karta hai?

Phir baaki ko taulo:

3. **Total cost of ownership**, do se teen saal ke liye (neeche dekho).
4. **Speed.** Value kitni jaldi chahiye? Mahinon ki deri ki bhi cost hoti hai, misaal ke liye doctor hours jo bache nahi.
5. **Differentiation.** Kya customers kisi competitor ki jagah aapko isliye chunenge kyunki aap ye behtar karte ho? Agar aapke sector ki har firm ko ye ek hi tarah se chahiye, toh ye commodity hai. "Ye hamare liye zaroori hai" kehna test nahi hai: lagbhag sab kuch zaroori hota hai.
6. **Lock-in.** Baad mein chhodna kitna mushkil hoga?

### Vendor due-diligence checklist

Kisi bhi vendor ke saath sign karne se pehle, in saat sawaalon ke likhit jawaab lo:

1. **Location.** Data kahan store aur process hota hai, backups aur support access samet?
2. **Training.** Kya vendor ya uska model provider aapke data par train karta hai? Contract mein "nahi" likhwao.
3. **Retention.** Data kitne samay tak rakha jaata hai, aur kya wo deletion confirm karenge?
4. **Sub-processors.** Aur kaun data ko chhoota hai, misaal ke liye product ke peechhe ka model provider?
5. **Security evidence.** ISO 27001 jaise certifications ya ek SOC 2 report, aur haal ka ek penetration test.
6. **Breach notice.** Wo aapko kitni jaldi batayenge? DPDP Act aur CERT-In ke rules ke tahat aapki apni zimmedaariyaan bhi ho sakti hain.
7. **Exit.** Kya aap apna data aur outputs kisi usable format mein export kar sakte ho? Price ya model badalne se pehle kitna notice milega?

### Total cost of ownership

Dono taraf poora gino. Khareedna kabhi sirf licence fee nahi hota: integration, ek internal owner, quality checks aur chhodne ki cost bhi hoti hai. Build karna kabhi sirf tokens nahi hota: engineers, evaluation, hosting aur maintenance bhi hote hain. Jo costs har option mein ek jaisi hain, jaise har output ko review karne mein expert ka samay, wo ek-doosre ko cancel kar deti hain, isliye unhe tulna se bahar rakh sakte ho.

Do gotchas experienced teams ko bhi pakad lete hain:

- **Tokens se zyada logon ki cost hoti hai.** Build ke total mein model usage aksar chhota hissa hota hai. Ye maan lene se pehle apna split check karo.
- **Sunk costs sawaal hi badal deti hain.** Ek baar build kar liya, toh kharch hua paisa ja chuka. Baad ke review mein sirf future costs ki tulna karo: apna build chalaana banaam kisi vendor par switch karna.

Apni finance team ke saath tax bhi check karo. IT aur cloud services par GST 18% hai (November 2026 tak). Zyaadatar healthcare services GST se exempt hain, isliye hospital aksar wo tax wapas claim nahi kar paata, jisse har vendor aur cloud bill ki asli cost badh jaati hai.

### Badlaav ke liye plan karo

Zyaadatar organisations aakhir mein mila-jula raasta apnaate hain: commodity tasks ke liye khareedte hain, aur jahan kuch fit nahi hota ya jahan wo alag dikhte hain wahan build karte hain. Aap jo bhi chuno, models aur vendors aapke pairon tale badalte rahenge.

Model providers puraane models retire karte hain. Misaal ke liye, November 2026 tak, Anthropic vaada karta hai ki kisi publicly released model ko retire karne se pehle kam se kam 60 din ka notice dega, aur uske baad us model ko bheji gayi requests fail hoti hain. Amazon Bedrock jaise partner clouds apne retirement schedules khud tay karte hain. Isliye kam se kam ek model migration ka budget rakho, aur replacement ko test karne ke liye apna evaluation set taiyaar rakho. Khareedte samay vendor se poochho ki wo yahi problem kaise sambhaalte hain.

## Ek worked example

Hyderabad ki ek hospital chain chaahti hai ki AI doctors ke notes aur lab reports se discharge summaries draft kare. Lambi shifts ke aakhir mein doctors har summary par 20 se 30 minute lagaate hain. Chain mahine mein lagbhag 6,000 discharges sambhaalti hai. Is example ke saare numbers illustrative hain, sikhaane ke liye banaaye gaye.

### Feasibility

Sana 40 de-identified patient records ikattha karti hain. Ek capable model aur hospital ke summary template se wo 40 drafts banaati hain. Teen senior doctors unhe rate karte hain:

| Rating | Drafts | Notes |
| --- | --- | --- |
| Chhote edits ke saath usable | 31 | Zyaadatar shabdon ke badlaav |
| Bade edits chahiye | 7 | Pichhle notes ka context chhoot gaya |
| Unsafe | 2 | Dono mein ek medication badlaav chhoot gaya |

Faisla: aage badhne laayak feasible, par sirf tab jab doctor sign-off zaroori ho aur draft ki har medication ko pharmacy record se apne-aap check kiya jaaye. 40 mein se 2 unsafe drafts ka matlab ho sakta hai ki asli rate 1% se kam se lekar lagbhag 17% tak kuch bhi hai, isliye Sana launch se pehle 400 records ka evaluation plan karti hain, jismein medication errors alag se gine jaayenge.

### Options ko chhaantna

Wo wahi 40 records har option par chalaati hain aur har option ko hospital ki data policy se check karti hain:

| Option | Sana ko kya mila | Faisla |
| --- | --- | --- |
| Product A khareedna | Drafts achhe, par unke hospital information system se integrate nahi hota | Fit ki wajah se bahar |
| Product B khareedna | Data India ke bahar process karta hai; hospital ki legal team hospital ki data policy ke tahat ise reject karti hai | Compliance ki wajah se bahar |
| Hospital system ka add-on configure karna | Unka template follow nahi kar sakta, na medication check chala sakta hai | Fit aur safety ki wajah se bahar |
| Unke maujooda cloud ke Indian region mein hosted model API par build karna | Hospital system se integrate hota hai, medication check aur doctor sign-off ke saath | Akela bacha hua option |

Build kyun jeeta, is par imaandaar raho. Discharge summaries draft karna wo cheez nahi hai jo is hospital ko alag banaati hai: har hospital ko ye lagbhag ek hi tarah se chahiye. Build isliye jeeta kyunki aur kuch bhi fit aur compliance mein pass nahi hua. Theek isi wajah se is faisle ki ek review date hai.

Team regulatory counsel se ye bhi poochhti hai ki kya ye tool medical device software gina ja sakta hai. India ke drug regulator, CDSCO, ne Medical Devices Rules, 2017 ke tahat medical device software par guidance jaari ki hai, aur koi software device hai ya nahi, ye uske intended medical purpose par nirbhar karta hai. Isliye team intended purpose ko dhyaan se likhti hai, aur build shuru hone se pehle counsel ki raay likhit mein leti hai.

### Build karne ki do saal ki cost

Sana ka andaaza hai ki build mein teen mahine lagenge, phir do saal ki window mein 21 mahine chalega: 6,000 × 21 = 126,000 summaries.

| Illustrative cost item | Kaise nikaala | Do saal ki cost |
| --- | --- | --- |
| Build team | 3 log × 3 mahine × ₹2.5 lakh mahina | ₹22.5 lakh |
| Pre-launch clinical evaluation | Doctors 400 drafts rate karte hain | ₹3 lakh |
| Security aur compliance review | Ek baar | ₹3 lakh |
| Model usage | ₹5 prati summary (₹4 aur 25%) × 126,000 | ₹6.3 lakh |
| Hosting, logging, monitoring | ₹40,000 mahina × 21 | ₹8.4 lakh |
| Maintenance | Ek engineer aadha samay, ₹1.25 lakh mahina × 21 | ₹26.25 lakh |
| Ongoing quality sampling | Doctors ek sample review karte hain, ₹25,000 mahina × 21 | ₹5.25 lakh |
| Ek model migration | Model retire hone par re-test aur adjust | ₹4 lakh |
| **Total** | | **₹78.7 lakh, lagbhag ₹62 prati summary** |

Doctor sign-off ka samay ismein nahi gina gaya: hospital koi bhi option use kare, ye ek jaisa rehta hai. Figures mein GST shaamil nahi hai.

### Numbers Sana ko kya batate hain

- **Logon ki cost sabse bhaari hai.** Total mein model usage sirf lagbhag 8% hai. Log (build, evaluation, maintenance aur migration) lagbhag 78% hain. Token price doguna hone se total lagbhag 8% hi badhega. System maintain karne waala engineer chala jaaye toh isse kahin zyada nuksaan hoga.
- **Volume build ke paksh mein hai.** Zyaadatar cost fixed hai. 12,000 summaries mahina par, illustrative total sirf lagbhag ₹85 lakh tak badhta hai (usi team ke saath), yaani lagbhag ₹34 prati summary. Vendor ki per-summary fee volume ke saath-saath badhti hai.
- **Aaj khareedne ka bar.** Maan lo build shuru hone se pehle ek aisa vendor aa jaata jo fit aur compliance mein pass hota. Uski costs hotin integration (₹4 lakh) aur quality checks ke saath ek internal owner (₹50,000 mahina), aur wo ek mahine baad live ho sakta. Do saal mein wo build ko kisi bhi aisi illustrative fee par hara deta jo lagbhag ₹45 prati summary se kam ho: (₹78.7 lakh − ₹4 lakh − ₹12 lakh) ÷ 138,000 summaries (23 live mahinon mein) = lagbhag ₹45.
- **Baad mein switch karne ka bar.** Build ke baad uske ₹22.5 lakh sunk hain. Tab use chalaane mein lagbhag ₹2.37 lakh mahina lagta hai, future migrations ke reserve samet. Switch karne mein integration aur re-evaluation ke liye lagbhag ₹7 lakh lagenge, yaani 24 mahinon mein phailaayein toh lagbhag ₹0.29 lakh mahina. Toh switch karne laayak hone ke liye, ek compliant vendor ko ab illustrative ₹26 prati summary se kam charge karna hoga: (₹2.37 lakh − ₹0.5 lakh − ₹0.29 lakh) ÷ 6,000 = lagbhag ₹26.

### Faisla

Leadership build ko approve karti hai, self-hosted model ki jagah hosted API par, kyunki volume GPUs chalaane ko justify nahi karta. Sana prompts, medication check aur 400-record evaluation set hospital ke apne haath mein rakhti hain, taaki model badla ja sake. Saalaana market review ka ek thos trigger hai: agar koi product fit aur compliance mein pass ho aur lagbhag ₹26 prati summary se kam par mile (illustrative switching bar), ya volume ya rules badlein, toh phir se dekho.

## Aam galtiyaan

- **Prototype chhod dena.** Feasibility ke andaaze aksar dono taraf galat nikalte hain.
- **Prototype ko launch ka saboot maan lena.** 40 mein se 2 unsafe bade paimaane par evaluate karne ki wajah hai, koi naapa hua 5% rate nahi.
- **Banaane waalon se hi unke outputs judge karwana.** Domain experts se poochho, ek likhe hue rubric ke saath.
- **Vendors ko unke demo data par judge karna.** Har option ko apne evaluation set par chalao.
- **Kisi cheez ko differentiating kehna kyunki wo aapke liye zaroori hai.** Poochho ki kya customers iski wajah se aapko chunenge.
- **Licence fee ki tulna sirf token costs se karna.** Build ki zyaadatar cost log, evaluation, maintenance aur migrations hain.
- **Review ke samay sunk costs ko nazarandaaz karna.** Build ho jaane ke baad, sirf future costs ki tulna karo.
- **Exit bhool jaana.** Sign karne se pehle data export aur notice ki sharten tay karo, aur apna evaluation set apne paas rakho.

## Practice

Neeche linked SVPG ke four big risks aur Hamel Husain ki field guide padho.

1. **Prototype.** 20 real examples par ek AI task try karo. Domain jaanne waale kisi vyakti se outputs ko usable, needs work ya unsafe rate karwao. Likho ki ye sample kya nahi bata sakta.
2. **Screen.** Do products aur ek platform feature dhoondho jo ek hi task solve karne ka daava karte hain. Apne examples har ek par chalao, aur unmein se ek ke liye saaton due-diligence sawaalon ke jawaab do.
3. **Cost.** Build route ke liye Sana ki tarah ek do saal ki cost table banao, har figure ko estimate mark karke. Nikaalo ki prati unit kitni vendor fee par khareedna jeet jaayega.
4. **Recommend.** Ek page ki buy, configure ya build recommendation likho, jismein ek review date aur faisla dobaara kholne ka ek thos trigger ho.

**Aapka kaam poora hai jab aap** expert-rated prototype results, ek costed do saal ki tulna, aur ek aisa chunaav dikha sako jiska bachaav aap fit, compliance, cost aur lock-in par kar sako.
