## Ye kya hai

REST API doosre programs ko aapke system ko HTTP par use karne deti hai. Har **endpoint** ek URL aur ek method hota hai: `POST /tickets` ek ticket banata hai, `GET /tickets/42` ek ticket padhta hai. Caller JSON bhejta hai aur JSON wapas paata hai, ek **status code** ke saath jo batata hai ki kya hua.

FastAPI aisi APIs banane ke liye ek Python framework hai. Aap type hints aur Pydantic models ke saath aam functions likhte ho; FastAPI unhe endpoints mein badal deta hai jo input validate karte hain, output ko JSON mein convert karte hain aur `/docs` par interactive documentation publish karte hain. Ye async code bhi natively chalata hai, jo un services ke liye achha hai jo model APIs ka intezaar karti hain.

```flow
Caller | kisi aur team ki app: POST /claims/triage -> FastAPI body ko Pydantic se validate karta hai
FastAPI body ko Pydantic se validate karta hai -[fail ho]-> 422 | galat fields ki list
FastAPI body ko Pydantic se validate karta hai -[ok]-> Model client inject karo | Depends
Model client inject karo -> Aapka function model API ko call karta hai
Aapka function model API ko call karta hai -[model down]-> 503 | "thodi der mein try karo"
Aapka function model API ko call karta hai -[ok]-> response_model output filter karta hai
response_model output filter karta hai -> 200 | category: "motor", summary: "Rear bumper damage"
```

Is lesson mein hum Kochi ke ek insurance broker ke saath chalenge, jo chahta hai ki doosri teams ek claims-triage service call karein.

## Ye kaam kaise karta hai

**Methods.** GET padhta hai aur kuch badalna nahi chahiye. POST create karta hai ya kaam trigger karta hai. PUT replace karta hai, PATCH thoda update karta hai, DELETE hata deta hai. In matlabon par tike rehne se caches, retries aur doosre engineers sahi andaaza laga paate hain.

**Status codes.** Success ke liye 200 OK aur 201 Created. Malformed request ke liye 400, caller sign in nahi hai toh 401, sign in hai par ye karne ki ijaazat nahi toh 403, cheez exist nahi karti toh 404, body validation mein fail ho toh 422 (FastAPI ka default), bahut zyada bhej rahe hon toh 429. 500 ka matlab aapka code toot gaya, aur 503 ka matlab koi dependency, jaise model provider, down hai.

**Models.** Request body par Pydantic model ka matlab hai ki aapka function chalne se pehle FastAPI galat input ko 422 ke saath reject karta hai, aur batata hai ki kaunse fields fail hue. `response_model` control karta hai ki kya wapas jaata hai, taaki cost figure jaisa internal field galti se leak na ho.

**Dependencies.** FastAPI ka `Depends` shared cheezein, jaise database session, current user ya model client, har endpoint mein inject karta hai. Tests mein unhe fakes se badal dete ho.

**Testing.** `TestClient` aapki app ko memory mein call karta hai, bina server ke, isliye endpoint tests milliseconds mein chalte hain.

**Status codes jin par callers depend karte hain:**

| Code | Matlab | Caller ka aam reaction |
| --- | --- | --- |
| 200, 201 | Success, ya created | Result use karo |
| 400 | Malformed request | Request theek karo; retry mat karo |
| 401 | Sign in nahi hai | Sign in karo, phir retry |
| 403 | Ijaazat nahi | Ruk jao; access maango |
| 404 | Nahi mila | Id check karo |
| 422 | Body validation mein fail | Bataye gaye fields theek karo |
| 429 | Bahut zyada requests | Ruko, phir retry |
| 500 | Aapka code toota | Report karo |
| 503 | Dependency down hai | Backoff ke saath baad mein retry |

**Aise endpoints design karna jo purane na hon.** Resources ke liye nouns (`/claims`, `/claims/{id}`) aur actions ke liye methods use karo. Path ya header mein version rakho (`/v1/claims`) taaki baad mein callers ko tode bina API badal sako. Har jagah ek hi error shape return karo, jaise `{"detail": "..."}`, taaki callers errors ek hi jagah handle kar sakein. Aur har endpoint ko code mein hi summary aur examples ke saath document karo; FastAPI unhe `/docs` par khud dikhata hai, jo aksar akela documentation hota hai jo doosri teams padhti hain.

**Browser mein try karo.** Request validation achhi API ki jaan hai. Dictionary badalkar ek galat body bhejke dekho.

```python
from pydantic import BaseModel, Field, ValidationError

class NewOrder(BaseModel):
    item_id: str = Field(pattern=r"^SKU-\d{4}$")
    quantity: int = Field(gt=0, le=20)
    pin_code: str = Field(pattern=r"^[1-9]\d{5}$")

body = {"item_id": "SKU-0042", "quantity": 0, "pin_code": "56001"}
try:
    print(NewOrder.model_validate(body))
except ValidationError as err:
    for e in err.errors():
        print("422:", e["loc"][0], "-", e["msg"])
```

## Ek example se samjho

Kochi ka ek insurance broker chahta hai ki doosri teams claim descriptions bhejein aur ek category aur summary wapas paayein.

```python
from fastapi import FastAPI, HTTPException, Depends
from pydantic import BaseModel, Field

app = FastAPI(title="Claims triage")

class ClaimIn(BaseModel):
    policy_no: str = Field(pattern=r"^[A-Z]{3}\d{7}$")
    description: str = Field(min_length=20, max_length=5000)

class ClaimOut(BaseModel):
    category: str
    summary: str

@app.post("/claims/triage", response_model=ClaimOut, status_code=200)
async def triage(claim: ClaimIn, llm=Depends(get_llm)):
    try:
        result = await llm.classify(claim.description)
    except ProviderDown:
        raise HTTPException(503, "Triage is unavailable; try again shortly")
    return ClaimOut(category=result.category, summary=result.summary)
```

Policy number "abc123" waali request model tak pahunchti hi nahi: FastAPI field ka naam leke 422 return karta hai. Agar model provider down ho, toh callers ko confusing 500 ki jagah 503 milta hai jise woh retry kar sakte hain.

Test model ko fake karta hai:

```python
from fastapi.testclient import TestClient

def test_triage_returns_category():
    app.dependency_overrides[get_llm] = lambda: FakeLLM("motor", "Rear bumper damage")
    r = TestClient(app).post("/claims/triage",
        json={"policy_no": "MOT1234567", "description": "Car was hit from behind at a signal"})
    assert r.status_code == 200 and r.json()["category"] == "motor"
```

`/docs` kholo aur broker ki doosri teams endpoint ko browser mein hi try kar sakti hain, request schema pehle se likha hua.

**Doosri teams ne sabse pehle kya notice kiya.** Broker ki mobile team ne ek din mein integrate kar liya, zyadatar isliye ki `/docs` har field, uske rules aur ek example dikhata tha, aur galat requests 422 ke saath exact field ka naam leke wapas aati thin. Jab model provider ka thodi der ke liye outage hua, unki app crash hone ki jagah 503 par "Triage is busy, try again in a minute" dikha rahi thi, kyunki status code ne use bata diya tha ki ye kis tarah ka failure hai.

## Aam galtiyaan

- **Errors ke liye 200 return karna.** Status 200 ke saath `"error": true` waali body har retry aur monitoring tool ko tod deti hai. Sahi code use karo.
- **Apne database rows seedhe return karna.** Internal fields leak ho jaate hain. Hamesha response model set karo.
- **Async endpoints mein blocking calls.** `async def` ke andar synchronous model client server ko freeze kar deta hai. Async client use karo, ya endpoint ko simple `def` se declare karo taaki FastAPI use thread pool mein chalaye.
- **Model call par timeout na hona.** Ek atki hui request ek worker ko hamesha ke liye bandh kar leti hai. Timeouts set karo aur 503 ya 504 return karo.
- **Input limits chhod dena.** Maximum length ke bina koi 300-page ka document paste kar deta hai aur aapka token bill badh jaata hai.
