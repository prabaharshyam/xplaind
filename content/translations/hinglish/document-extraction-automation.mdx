## Ye kya hai

**Document extraction** ek unstructured document ko structured fields mein badalta hai: invoice PDF se vendor name, GSTIN, invoice number, date, line items, tax amounts aur total. Ek automation har aane waale document ke liye ye karti hai, phir result check karti hai aur use sheet, accounting system ya approval step tak pahunchati hai.

Modern AI models alag-alag layouts ko purane template-based tools se bahut behtar handle karte hain, jinhe har supplier ke liye ek template chahiye hota tha.

```flow
Email, WhatsApp ya ek folder -> 1 Receive, original store karo -> 2 Content nikaalo | text, OCR, ya vision model ko image
2 Content nikaalo -> 3 Schema ke saath extract karo | supplier, GSTIN, number, date, lines, CGST, SGST, total
3 Schema ke saath extract karo -> 4 Validate | formats, arithmetic, business rules
4 Validate -> Sab pass?
Sab pass? -[haan]-> 5 Accounting mein post karo -> 6 Record aur audit trail
Sab pass? -[nahi]-> 5 Review screen | image fields ke bagal mein, failed checks laal mein
5 Review screen -[insaan correct karta hai]-> Final record aur ek naya test case
```

Ye lesson Surat ke ek textile trader ko follow karta hai jo mahine mein lagbhag 900 supplier invoices process karta hai.

## Ye kaam kaise karta hai

**1. Receive.** Documents email attachment, upload form, shared folder ya WhatsApp se aate hain. Trigger unhe uthata hai aur original store karta hai.

**2. Content nikaalna.** Digital PDFs: text extract karo. Scans aur phone photos: OCR, ya image seedhe vision-capable model ko bhejo. Page reference rakho.

**3. Schema ke saath extract karna.** Content ko model ko ek saaf instruction aur fixed output shape (field names, types, kaun se required hain) ke saath bhejo. Tool ka structured-output feature ya JSON schema use karo taaki har baar bilkul wahi fields milein. Jab koi field na ho toh guess ki jagah null maango.

**4. Rules se validate karna.** Extraction par aankh moondkar bharosa mat karo. Check karo:

- formats: GSTIN sahi pattern mein 15 characters ka ho; dates valid hon; PIN codes mein chhe digits hon;
- arithmetic: line totals subtotal tak jodte hon; subtotal plus tax total ke barabar ho;
- business rules: vendor aapki master list mein ho; PO number ek open order se match kare; amount expected range mein ho.

**5. Route.** Agar har check pass ho, toh apne aap aage badho. Agar kuch fail ho ya koi required field missing ho, toh document aur fail hua check highlight karke ek insaan ko bhejo. Unka correction final record aur ek kaam ka test case ban jaata hai.

**6. Record.** Extract kiya hua data, checks aur kisne approve kiya, audit ke liye rakho.

**Measure.** Straight-through rate (bina insaani chhue ka hissa), logon ke check kiye sample par field accuracy, aur bachaya hua time track karo.

**Indian invoices ke validation rules:**

| Field | Check | Kya pakadta hai |
| --- | --- | --- |
| GSTIN | 15 characters, valid pattern, state code address se match, supplier master mein | Galat padhna, galat supplier |
| Invoice date | Valid date, future mein nahi, accounting period ke andar | 31 February, typos |
| Line items | Quantity × rate = amount; lines subtotal tak jodti hain | Chhooti ya mili hui lines |
| Tax | Intra-state mein CGST barabar SGST; inter-state mein IGST; amounts rates se match | Galat tax type, galat padhe amounts |
| Total | Subtotal + taxes = total | Koi bhi arithmetic misread |
| Invoice number | Is supplier ke liye pehle se record nahi | Duplicate payments |

**Rules model ki choice se zyada matter kyun karte hain.** Bahut capable model bhi kabhi-kabhi ek dhundhla digit galat padh leta hai. Arithmetic aur format checks bina kharche ke zyadatar un errors ko pakad lete hain, kyunki galat padha hua digit shaayad hi totals ko consistent rehne deta hai. Model padhta hai; rules tay karte hain ki jo padha use maanein ya nahi.

**Confidence aur review queues.** Reviewers ko har field dobara check nahi karna chahiye. Pehle wo fields dikhao jo koi rule fail hue, phir wo jinhe model ne uncertain mark kiya ya null chhoda, aur baaki ko reviewers ek action se approve karein. Track karo ki reviews mein kitna time lagta hai; agar reviewer ko har document par ek minute se zyada chahiye, toh screen par kaam karna hai, reviewer par nahi.

**Code mein validation rules.** Ye checks extraction ke baad chalte hain aur tay karte hain ki document seedha jaayega ya nahi:

```python
import re
from datetime import date
from decimal import Decimal

GSTIN_RE = re.compile(r"^[0-3][0-9][A-Z]{5}[0-9]{4}[A-Z][1-9A-Z]Z[0-9A-Z]$")
CHARS = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ"

def gstin_ok(g):
    if not GSTIN_RE.match(g or ""):
        return False
    total = 0
    for i, ch in enumerate(g[:14]):
        p = CHARS.index(ch) * (1 if i % 2 == 0 else 2)
        total += p // 36 + p % 36
    return CHARS[(36 - total % 36) % 36] == g[14]

def check_invoice(inv, supplier_state, our_state, seen_numbers):
    problems = []
    if not gstin_ok(inv["supplier_gstin"]):
        problems.append("supplier GSTIN fails format or check digit")
    elif inv["supplier_gstin"][:2] != supplier_state:
        problems.append("GSTIN state code does not match the supplier's state")
    if inv["invoice_date"] > date.today():
        problems.append("invoice date is in the future")
    lines = [Decimal(l["qty"]) * Decimal(l["rate"]) for l in inv["lines"]]
    if any(abs(c - Decimal(l["amount"])) > Decimal("0.01") for c, l in zip(lines, inv["lines"])):
        problems.append("a line amount is not quantity × rate")
    subtotal = sum(lines)
    if abs(subtotal - Decimal(inv["subtotal"])) > Decimal("0.01"):
        problems.append("lines do not add up to the subtotal")
    tax = Decimal(inv.get("cgst") or 0) + Decimal(inv.get("sgst") or 0) + Decimal(inv.get("igst") or 0)
    if supplier_state == our_state and inv.get("igst"):
        problems.append("IGST charged on an intra-state supply")
    if supplier_state != our_state and (inv.get("cgst") or inv.get("sgst")):
        problems.append("CGST/SGST charged on an inter-state supply")
    if abs(subtotal + tax - Decimal(inv["total"])) > Decimal("1.00"):      # allow rupee rounding
        problems.append("subtotal plus tax does not equal the total")
    if (inv["supplier_gstin"], inv["invoice_number"]) in seen_numbers:
        problems.append("duplicate invoice number for this supplier")
    return problems
```

Khaali list ka matlab straight through; kuch bhi aur review mein jaata hai, problems pehle list hokar. Paise ko `Decimal` se handle karo, floats se kabhi nahi.

**Field accuracy ko sahi se naapo.** Logon se 50 se 100 documents haath se key karwao, ek gold set ke roop mein. Har field ke liye, normalise karne ke baad (dates ek format mein, amounts do decimals tak) extraction aur gold value ke exact matches gino. Har field ka alag report karo, ek overall number nahi: 98% overall score invoice dates par 80% ko chhupa sakta hai.

**Straight-through rate aur error rate.** Rules dheele karne se zyada documents seedhe jaate hain par zyada errors books mein ghus jaati hain. Dono track karo. Ek achha target finance team ke saath tay hota hai: jaise kam se kam 70% straight through, aur ledger tak pahunchne waale galat fields 500 mein 1 se kam.

**Corrections ko wapas feed karo.** Har reviewer correction ek labelled example hai. Mushkil waale apne test set mein jodo, aur jab kisi supplier ka layout baar-baar galtiyaan karwaye, toh prompt mein ek chhota supplier-specific hint ya ek dedicated rule jodo.

## Ek example se samjho

Surat ka ek textile trader mahine mein lagbhag 900 supplier invoices PDFs ke roop mein aur WhatsApp aur email par phone photos ke roop mein paata hai.

Automation:

- Ek dedicated email address aur ek WhatsApp Business number se attachments jama karti hai.
- Har page ko ek schema ke saath vision-capable model ko bhejti hai: supplier name, supplier GSTIN, invoice number, invoice date, line items (description, HSN code, quantity, rate, amount), CGST, SGST, IGST, total.
- Validate karti hai: GSTIN pattern aur supplier master se match; lines jodti hain; tax amounts rates se consistent; invoice number us supplier ke liye pehle se record nahi.
- Pass hue invoices ko accounting import sheet mein likhti hai; failures ko review screen par accounts assistant ko bhejti hai, image fields ke bagal mein.

Pehla mahina: 71% straight through; zyadatar failures dhundhli photos aur haath se kiye corrections the. Baar-baar aane waale suppliers se PDFs email karne ko kehne aur photo prompt behtar karne ke baad, straight-through 84% tak pahunchta hai. Invoice entry par accounts staff ka time mahine ke lagbhag 60 ghante se girkar 15 ho jaata hai, aur duplicate-invoice check ₹2.3 lakh ke chaar duplicate payments pakadta hai.

| Measure | Mahina 1 | Mahina 3 |
| --- | --- | --- |
| Straight-through rate | 71% | 84% |
| Mukhya failure ki wajah | Dhundhli photos, haath se corrections | Haath se corrections |
| Invoice entry par staff ka time | mahine ke lagbhag 60 ghante | mahine ke lagbhag 15 ghante |
| Pakde gaye duplicate payments | 4, ₹2.3 lakh ke | Jaari |

Sabse bada akela sudhaar technical nahi tha: sabse zyada aane waale 30 suppliers se phone photos ki jagah PDFs email karne ko kehna.

## Aam galtiyaan

- **Free-form output.** Schema use karo taaki fields hamesha maujood aur typed hon.
- **Validation rules nahi.** Arithmetic aur format checks zyadatar extraction errors pakad lete hain.
- **Model ko missing fields guess karne dena.** Null maango aur insaan ko route karo.
- **Original document kho dena.** Check aur audit ke liye use record se jodkar rakho.
- **Kuch bhi measure na karna.** Straight-through rate aur sample accuracy track karo.

- **Har page sabse mehnge model ko bhejna.** Digital PDFs ke liye text extraction use karo aur vision models scans aur photos ke liye rakho; isse cost bahut kam hoti hai.
- **Paise par float arithmetic.** Paise ko integers ya `Decimal` mein use karo.
- **Saare fields ke liye ek accuracy number.** Har field ko alag se naapo.
- **Duplicates check na karna.** Dobara bheja hua invoice do baar pay ho jaata hai.

## Jab extraction automation kaam ki nahi

- **Mahine mein kuch hi documents**: unhe type karna pipeline banane aur check karne se sasta hai.
- **Structured data pehle se maujood hai**: e-invoices, bank statement exports ya supplier ka API PDFs padhne se behtar hain.
- **Har document ko expert judgement chahiye** waise bhi, jaise legal contracts jo clause-by-clause review hote hain.

## Demo se production tak

- **Haath se key kiye documents ka ek gold set rakho** aur har change par per-field accuracy naapo.
- **Original, extraction, checks aur approver store karo** audit ke liye.
- **Straight-through rate girne par alert karo**, jiska matlab aksar ye hota hai ki kisi supplier ne layout badla.
- **Jahan zaroori nahi wahan logs aur review screens mein personal aur bank details mask karo.**
- **Har quarter finance ke saath rules review karo**, khaaskar GST changes ke baad tax rules.
