## Ye kya hai

Ek language model ek **base model** ki tarah shuru hota hai, jo bahut bade text par agla token predict karne ke liye train hota hai. Phir companies use aage train karti hain taaki woh instructions follow kare aur ek helpful assistant ki tarah behave kare. **Fine-tuning** us cheez ka chhota version hai jo aap khud karte ho: aap ek maujooda model lete ho aur use apne examples par train karte rehte ho, taaki uske **weights** (model ke andar ke numbers) aapke task ki taraf khisak jayein.

Aage ki training ke teen kism aam hain:

- **Continued pre-training** model ko kisi field ka aur raw text deti hai, jaise legal ya medical documents. Ye mehenga hai aur application teams ke liye kam hi hota hai.
- **Supervised fine-tuning (SFT)** model ko ek prompt aur woh exact answer dikhati hai jo aap chahte ho, hazaaron baar. Ye aam taur par chuna jaane wala option hai.
- **Preference tuning** (RLHF, ya DPO naam ka ek simple method) model ko ek prompt ke do answers dikhati hai aur ye ki logon ne kaunsa pasand kiya. Ye tone aur judgement ko shape karti hai.

Isi wajah se ek chat model base model se alag behave karta hai: woh teeno se guzra hai. Zyadatar application teams sirf SFT karti hain, aur kabhi-kabhi preference tuning.

Fine-tuning model ko **kaise respond karna hai** sikhane mein sabse achhi hai: ek format, ek tone, ek sakht routine, ek sankeern classification. **Facts** sikhane ka ye kharab tareeka hai, kyunki facts badalte hain aur model phir bhi unhe galat yaad rakh sakta hai. Facts ke liye retrieval use karo. Prompting, RAG ya fine-tuning waala lesson inke beech chunne mein madad karta hai. Ye lesson us baare mein hai ki fine-tune karne ka faisla ho jaane ke baad kya hota hai.

```flow
title: Fine-tuning loop
Task aur ek test define karo | achha kise kehte hain?
Task aur ek test define karo -> Examples jama karo aur saaf karo | pehle quality
Examples jama karo aur saaf karo -> Train, validation aur test mein baanto | test locked rehta hai
Train, validation aur test mein baanto -> Kuch passes train karo | validation loss dekho
Kuch passes train karo -> Prompt baseline se behtar hai?
Prompt baseline se behtar hai? -[nahi]-> Data theek karo ya ruk jao | aksar problem data hi hota hai
Data theek karo ya ruk jao -> Examples jama karo aur saaf karo
Prompt baseline se behtar hai? -[haan]-> Purani abilities check karo | forgetting
Purani abilities check karo -> Deploy karo aur monitor karo | cheezein badlein toh retrain karo
```

Is lesson mein hum Pune ke ek insurer ko follow karenge jo claim emails ko 12 categories mein sort karna chahta hai.

## Ye kaam kaise karta hai

1. **Training set se pehle test likho.** Tay karo ki is task ke liye "achha" ka matlab kya hai, aur sahi answers ke saath asli examples ka ek chhota test set banao. Uske bina aap nahi bata sakte ki fine-tuning ne madad ki ya nahi.
2. **Examples jama karo.** Har ek ek input aur ideal output hai. Jahan ho sake asli purana kaam use karo, jise ek insaan ne check kiya ho. Kitne chahiye ye task par depend karta hai: kuch sau shaandaar examples ek format sikha sakte hain, aur mushkil task ko hazaaron chahiye ho sakte hain.
3. **Unhe saaf karo.** Duplicates hatao, galat labels theek karo, format sab examples mein ek jaisa rakho, aur personal data nikaal do. Model jo dekhta hai woh copy karta hai, galtiyaan bhi.
4. **Data baanto.** Zyadatar **training** mein jaata hai. Ek chhota hissa **validation** hai, jo training ke dauraan progress check karne ke kaam aata hai. Teesra hissa **test set** hai, jise aap end tak chhoote nahi.
5. **Train karo.** Model examples ko kuch baar padhta hai (har poora pass ek epoch hai) aur uske weights isliye khisakte hain ki ideal answers zyada sambhav ho jayein. Aap **loss** dekhte ho, ek number jo naapta hai ki model kitna galat hai. Training loss girna chahiye. Agar training loss girta rahe aur validation loss badhne lage, toh model examples ko ratt raha hai, ye **overfitting** hai. Wahin ruk jao.
6. **Ek strong baseline ke saamne test karo.** Sahi comparison base model ko ek aalsi prompt ke saath rakhna nahi hai. Wo hai base model ek achhe se likhe prompt aur kuch achhe examples ke saath. Fine-tuning ko ise saaf tareeke se harana hoga, tabhi rakhne laayak hai.
7. **Check karo ki woh kya bhool gaya.** Aise prompts try karo jo aapke task se jude na hon. Ek sankeern fine-tune model ko general instructions mein kharab bana sakta hai, ise **catastrophic forgetting** kehte hain.
8. **Deploy karo aur saare hisse sambhaal ke rakho.** Data, labelling guide, settings aur test set ko version karo, kyunki base model ya aapke rules badalne par aap retrain karoge.

Ek SFT example aam taur par JSON ki ek line ki tarah store hota hai, ek chhoti chat jaisa likha hua:

```json
{"messages": [
  {"role": "user", "content": "Classify this claim email.\n\nSubject: Hospital bill for my father\nBody: He was admitted on 3 March for 4 days at a Pune hospital. Please process the cashless request."},
  {"role": "assistant", "content": "health_cashless"}
]}
```

Ek chhota script data baantta hai aur test set ko surakshit rakhta hai:

```python
import json, random

random.seed(7)                       # same split every time
rows = [json.loads(line) for line in open("claims_clean.jsonl")]
random.shuffle(rows)

n = len(rows)
test = rows[: int(n * 0.05)]         # locked away until the end
valid = rows[int(n * 0.05): int(n * 0.15)]
train = rows[int(n * 0.15):]

for name, part in [("train", train), ("valid", valid), ("test", test)]:
    with open(f"{name}.jsonl", "w") as f:
        for r in part:
            f.write(json.dumps(r) + "\n")
print(len(train), len(valid), len(test))
```

Yahan duplicates matter karte hain. Agar wahi email training aur test dono mein ho, toh test score ko jhooti taareef milti hai. Split karne se pehle exact aur lagbhag-same duplicates hata do.

**Hosted ya open weights?** Kuch providers aapko apne models API se fine-tune karne dete hain aur result ko aapke liye host karte hain, jo simple hai par aapko unse bandh deta hai. Open-weight models mein aap khud model train aur serve karte ho, jo control deta hai par GPUs aur skills maangta hai. Availability aur prices badalte hain, isliye provider ki maujooda documentation check karo. Agla lesson batata hai ki bade GPU ke bina open models kaise train karein.

## Ek example se samjho

Pune ka insurer mahine mein 200,000 claim emails ko 12 categories mein sort karta hai. Ek bade model par chhe examples waala prompt 300 labelled emails par 78% score karta hai, aur is volume ke liye har call ka kharcha bahut zyada hai.

Unke paas agents ke pehle se label kiye 40,000 emails hain. Training se pehle woh 400 ka ek sample check karte hain aur paate hain ki lagbhag 10 mein se 1 label galat hai, zyadatar isliye ki do agents "health reimbursement" aur "health cashless" ko alag tareeke se use karte the. Woh ek-page ka labelling guide likhte hain, do senior agents se confusing categories dobara label karwate hain, aur 3,000 duplicate emails hata dete hain. Woh naam, phone numbers aur policy numbers mask karte hain, jo India ke data protection law ke tahat personal data hai.

Woh 30,000 saaf examples par ek chhote open-weight model ko fine-tune karte hain, 2,000 validation ke liye rakhte hain aur original 300 test emails ko untouched. Validation loss doosre pass ke baad sudharna band kar deta hai, isliye woh wahin ruk jaate hain.

| Option | 300 test emails par accuracy | Har email ka relative cost | Notes |
| --- | --- | --- | --- |
| Chhe-example prompt waala bada model | 78% | 1x (baseline) | Badalna aasan, is volume par mehenga |
| Wahi prompt, error review ke baad sudhara hua | 84% | 1x | Ek dopahar ka kaam |
| Fine-tuned chhota model | 91% | lagbhag 0.1x | Data upkeep aur retraining chahiye |

Is table ke numbers illustration ke liye hain, ye dikhane ke liye ki compare kaise karna hai. Asli baat tareeka hai: fine-tune ko *sudhre hue* prompt (84%) ke saamne judge kiya gaya hai, pehle waale (78%) ke saamne nahi.

Fine-tuned model is sankeern task ke liye cost aur accuracy dono mein saaf jeet jaata hai. Par jab kisi ne usmein ek general sawaal type kiya, toh jawab ajeeb tha, jo forgetting hai. Kyunki use sirf classify karne ke liye use kiya jaata hai, isliye isse farak nahi padta. Woh ek rule jodte hain ki woh kabhi customers se baat nahi karega.

## Aam galtiyaan

- **Test ki jagah training set se shuru karna.** Test ke bina aap nahi bata sakte ki aapne kuch behtar kiya ya nahi.
- **Ganday labels par train karna.** Model galtiyaan aur asehmatiyaan seekh leta hai.
- **Kamzor prompt se compare karna.** Pehle prompt behtar karo, phir dekho ki fine-tuning ab bhi jeetti hai ya nahi.
- **Test examples ko training mein leak hone dena.** Splits ke beech ke duplicates aisa score dete hain jo shaandaar dikhta hai aur matlab kuch nahi rakhta.
- **Facts jodne ke liye fine-tuning use karna.** Policies aur prices badalte hain, aur fine-tune ko update karna dheera hai. Retrieval use karo.
- **Forgetting ko ignore karna.** Model ko un tasks par test karo jinke liye use train nahi kiya, ya jahan use hota hai use restrict karo.
- **Training examples mein personal data daalna.** Model use dohra sakta hai, aur iska ek hi fix retraining hai.

## Jab fine-tuning galat tool hai

- Problem missing ya badalta knowledge hai. Retrieval ya tools use karo.
- Behtar prompt abhi try nahi kiya gaya. Uska kharcha minutes hai, hafte nahi.
- Aapke paas test set nahi hai, ya kuch sau se kam achhe examples hain.
- Task har mahine badalta hai. Aap lagataar retrain karte rahoge.
- Aapko dikhana hai ki answer kahaan se aaya. Fine-tuned model sources cite nahi kar sakta, retrieval kar sakta hai.
- Volume kam hai. Upkeep ka kharcha bachat se zyada hoga.

## Demo se production tak

- **Sab kuch version karo.** Data, cleaning script, labelling guide, settings aur test set ko version control mein rakho, aur note karo ki har result kaun se model se aaya.
- **Retraining ki planning karo.** Base models retire hote hain aur unki jagah naye aate hain, aur aapke rules badalte hain. Agar retraining dardnaak hai, toh project sad jaayega.
- **Launch ke baad dekho.** Har hafte asli inputs aur outputs ka sample lo, aur apne test set se compare karo. Agar email ka kism badal jaye, toh accuracy chupchaap girti hai.
- **Ek fallback rakho.** Agar fine-tuned model down hai ya confuse hai, toh prompt-based version par route karo.
- **Data ko document karo.** Kahaan se aaya, kisne label kiya, kya hataya gaya. Clients aur auditors poochte hain.

## Practice karo

Pehle ek paper exercise, phir ek chhota asli.

1. Apne kaam se ek task chuno. Likho ki "achha" ka matlab kya hai aur sahi answers ke saath das test examples.
2. Aapse jitna ho sake sabse achha prompt likho, teen examples ke saath, aur un das par score karo.
3. Likho ki aap asal mein kitne saaf examples jama kar sakte ho, aur unhe kaun check karega.
4. Tay karo: fine-tune, prompt behtar karo, ya retrieval. Ise justify karne ke liye teen lines likho.
