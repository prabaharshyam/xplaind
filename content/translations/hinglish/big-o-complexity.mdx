## Ye kya hai

**Big-O notation** batata hai ki input badhne par algorithm ka kaam kaise badhta hai. Ye exact seconds nahi batata; ye curve ka shape batata hai. Input double karo toh kaam same rehta hai, double hota hai, ya chaar guna ho jaata hai?

Ye isliye zaroori hai kyunki asli data badhta hai. Jo script 100 test orders ko palak jhapakte check kar leti hai, woh Flipkart seller ke Big Billion Days sale ke 10 lakh orders par poori raat le sakti hai. Big-O se aap code chalaane se pehle ye andaaza laga lete ho, aur aisi approach chunte ho jo scale kare.

| Growth | Naam | 1,000 items ka kaam | 10 lakh items ka kaam | Example |
|---|---|---|---|---|
| O(1) | Constant | 1 | 1 | Dict mein key lookup |
| O(log n) | Logarithmic | lagbhag 10 | lagbhag 20 | Sorted list mein binary search |
| O(n) | Linear | 1,000 | 10 lakh | Har order ko ek baar check karna |
| O(n log n) | Linearithmic | lagbhag 10,000 | lagbhag 2 crore | Orders ko sort karna |
| O(n²) | Quadratic | 10 lakh | 10 lakh crore | Har order ko baaki har order se compare karna |

```flow
title: Input double hone par kya hota hai
Input double -> O(1) | wahi kaam
Input double -> O(log n) | ek step aur
Input double -> O(n) | double kaam
Input double -> O(n²) | chaar guna kaam
```

Common classes, achhe se kharab ke order mein, ye hain: O(1), O(log n), O(n), O(n log n) aur O(n²). Isse bhi kharab hote hain, jaise O(2ⁿ), jo sirf bahut chhote inputs par chalte hain.

## Ye kaam kaise karta hai

Kisi code ka Big-O nikaalne ke liye gino ki n badhne par sabse zyada repeat hone waala step kitni baar chalta hai, phir sirf sabse bada term rakho aur constants hata do.

- n items par ek single loop apni body n baar chalata hai: **O(n)**.
- Ek hi items par loop ke andar loop n × n baar chalta hai: **O(n²)**.
- Har step mein problem ko aadha karna, jaise binary search karta hai, lagbhag log₂ n steps leta hai: **O(log n)**.
- Achha sort, jaise Python ka built-in `sorted`, lagbhag n × log n comparisons karta hai: **O(n log n)**.
- List ka item position se padhna, ya dict ki value key se, collection kitna bhi bada ho, same time leta hai: **O(1)**.

Constants isliye hatate hain kyunki woh shape nahi badalte. List par do baar loop karna O(2n) hai, jise hum phir bhi O(n) likhte hain: n double karo toh dono mein kaam double hota hai. Chhote terms bhi isi wajah se hatate hain: O(n² + n) matlab O(n²), kyunki jab n 10 lakh hai toh n² waala hissa baaki sab ko dabaa deta hai.

**Space complexity** memory ke liye wahi notation use karti hai. Har order ID ka set banane mein O(n) extra space lagta hai; amounts jodne mein sirf O(1).

Agar ek step ek microsecond leta ho, toh practice mein in classes ka matlab ye hai:

| Complexity | n = 1,000 | n = 10 lakh (1,000,000) | Typical example |
|---|---|---|---|
| O(1) | 1 µs | 1 µs | dict lookup |
| O(log n) | 10 µs | 20 µs | binary search |
| O(n) | 1 ms | 1 second | list par ek pass |
| O(n log n) | 10 ms | 20 seconds | sorting |
| O(n²) | 1 second | lagbhag 11.5 din | saare pairs par nested loops |

Aakhri row hi nuksaan karti hai. Jo O(n²) tareeka testing mein turant chalta lagta hai, woh production mein bekaar ho sakta hai.

## Ek example se samjho

Priya Bengaluru ki ek fintech ki payments team mein kaam karti hai. Har raat settlement se pehle use din ki file mein duplicate UPI transaction IDs flag karni hoti hain. Busy din par file mein lagbhag 20 lakh rows hoti hain.

Uska pehla version har transaction ko baaki har ek se compare karta hai:

```python
def has_duplicate(ids):
    for i in range(len(ids)):
        for j in range(i + 1, len(ids)):
            if ids[i] == ids[j]:
                return True
    return False
```

Ye O(n²) hai. 20 lakh IDs ke saath ye lagbhag 2 lakh crore comparisons karta hai. Ye settlement ki deadline se pehle kabhi khatam hi nahi hua.

Uska doosra version pehle list ko sort karta hai, taaki duplicates paas-paas aa jaayein, phir ek pass maarta hai:

```python
def has_duplicate(ids):
    ids = sorted(ids)
    for i in range(1, len(ids)):
        if ids[i] == ids[i - 1]:
            return True
    return False
```

Sorting O(n log n) hai aur pass O(n), toh poora O(n log n) hai. Ye kuch seconds mein chal gaya.

Uska teesra version set use karta hai, jo keys ka **hash map** hai:

```python
def has_duplicate(ids):
    seen = set()
    for t in ids:
        if t in seen:
            return True
        seen.add(t)
    return False
```

Har `in` check aur `add` average O(1) hai, toh poora function O(n) time ka hai. Set ke liye ye O(n) extra memory leta hai, jo server par theek thi. Ye version ek second se kam mein chala, aur duplicate milte hi pehle ruk jaata hai.

Priya ne apni team ke notes mein jo seekh likhi: code ko line-by-line optimise karne se pehle uska Big-O dekho. O(n²) se O(n) par jaana kisi bhi tuning se behtar nikla.

## Aam galtiyaan

**"Simple" call ke andar loop chhupa hona.** `if x in my_list` ek step jaisa dikhta hai, par list par ye har item scan karta hai: O(n). Isse loop ke andar daalo toh O(n²) ho gaya. Membership baar-baar check karni ho toh set ya dict use karo.

**Lines ginna, repetitions nahi.** Paanch lines jo ek-ek baar chalti hain, O(1) hain. Do nested loops ke andar ek line O(n²) hai. Dekho ki sabse busy line kitni baar chalti hai.

**Cheezein banane ka cost bhool jaana.** List ko set mein badalna O(n) hai. Ye tab sahi hai jab uske baad bahut saare lookups karne hon, tab nahi jab sirf ek karna ho.

**Average ko worst case samajhna.** Dict lookups average O(1) hain, par kharab hash function unhe slow bana sakta hai. Quicksort average mein O(n log n) hai aur worst case mein O(n²). Interviewers aksar dono poochhte hain.

**Memory ko ignore karna.** O(n) time waala solution jise O(n) extra memory chahiye, tab fit nahi ho sakta jab n crores of rows ho. Time ke saath space cost bhi bolo.

**Bahut jaldi optimise karna.** Agar n kabhi 50 se zyada nahi hoga, toh saaf O(n²) code clever O(n log n) code se behtar ho sakta hai. Big-O tab matter karta hai jab n bada ho.
