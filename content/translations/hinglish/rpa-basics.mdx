## Ye kya hai

Kai Indian businesses ab bhi aise software par chalte hain jo kisi aur se baat hi nahi kar sakta: 15 saal purana desktop ERP, bank ki back-office screens, bina API wala sarkaari portal. Log apne din ek screen se doosri screen mein values copy karne mein bitate hain. **Robotic process automation (RPA)** woh copying apne haath mein le leta hai.

RPA aise software "robots" use karta hai jo applications ko unke **user interface** se chalate hain, theek kisi insaan ki tarah: programs kholna, buttons par click karna, fields mein type karna, screens se values copy karna, reports download karna. Ise wahan use kiya jaata hai jahan systems mein API nahi hai, ya integration banane mein bahut samay lagega.

```flow
dir: LR
title: API automation: tez, mazboot, pehli pasand
System A, API wala -[data, seedhe]-> System B, API wala
```

```flow
dir: LR
title: RPA: wahan bhi chalta hai jahan insaan chal sakta hai, zyada naazuk
Robot | UiPath, Power Automate Desktop -[screen par click aur typing]-> Purana desktop app, bina API
```

Mukhya RPA tools mein **UiPath**, **Automation Anywhere** aur **Microsoft Power Automate Desktop** aate hain. Inmein aap steps record ya design karte ho, phir unhe schedule par ya jab chaho tab, desktop ya server par chalate ho.

Is lesson mein hum Kolkata ke ek general insurer ki claims team ke saath chalenge, jab ek AI step aur ek RPA robot milkar ek purane claims system mein data entry sambhaal lete hain. End tak aap jaan jaoge ki RPA kab sahi tool hai aur ise chalu rakhne mein kitna kharcha aata hai.

## Ye kaam kaise karta hai

### Attended aur unattended robots

| Type | Kab chalta hai | Example |
| --- | --- | --- |
| **Attended** | Kisi insaan ke computer par, jab woh shuru kare | Ek robot jo agent ke "Go" dabane ke baad 40 fields wala form bhar deta hai |
| **Unattended** | Apne aap, dedicated machines par, queue ke kaam nipatate hue | Ek robot jo raat bhar mein 300 claims enter karta hai |

### Robots screen par cheezein kaise dhoondhte hain

Achha RPA screen ki fixed positions par click nahi karta. Woh elements ko unki properties se pehchanta hai: button ka naam, field ka label, web page ki structure. In identifiers ko **selectors** kehte hain. Tab layout ke chhote badlaav robot ko nahi todte.

Purani applications ya remote desktops mein, jahan properties nahi milti, robots **image matching** ya **OCR** par laut sakte hain, jo zyada naazuk hain: rang ya font badalne se woh toot sakte hain.

### RPA kahan fit hota hai

- Legacy desktop applications, jaise purane ERPs aur banking back-office screens, aur bina API wale portals.
- High-volume, stable, rule-based kaam: systems ke beech data copy karna, roz ke reports banana aur download karna, orders enter karna.
- Ek pul ki tarah, jab tak proper integration ban raha ho.

### RPA kahan fit nahi hota

| Sthiti | Behtar chunaav |
| --- | --- |
| System mein achhi API hai | API use karo: tez aur mazboot |
| Process ya screens aksar badalti hain | Pehle process theek karo, ya ruko |
| Kaam mein alag-alag inputs par judgement chahiye | Ek AI step aur ek insaan, RPA sirf data entry ke liye |

### RPA ke saath AI

RPA data ko screens se guzarta hai; AI documents padhta hai, emails classify karta hai ya agla step tay karta hai. Saath milkar woh aise processes sambhalte hain jo koi akela nahi sambhaal sakta:

```flow
Claim wala email -> AI step | email aur attachment padho; policy no., vehicle no., tareekh, jagah nikalo
AI step -> Policy database se validate karo
Policy database se validate karo -[theek]-> RPA robot | use purane claims system mein type karta hai
Policy database se validate karo -[theek nahi]-> Insaan ki queue | screenshots ke saath
RPA robot -> Claim number wapas tracking sheet mein
```

**Computer-use agents**, yaani AI jo screenshots se screens chalata hai, naye aur zyada flexible hain, par design kiye hue RPA steps se dheemay, mehenge aur kam predictable hain. Ek aam pattern: stable steps ke liye RPA, aur AI sirf wahan jahan variation mein judgement chahiye.

### Running cost aur governance

Screens badalne, passwords expire hone ya achanak pop-ups aane par robots toot jaate hain. Inke liye budget rakho:

- RPA platform aur robot machines ke **licences**;
- **monitoring**, taaki ruke hue robot par alert aaye;
- **maintenance**, yaani koi jo selectors jaldi theek kar sake.

Har robot ka ek register rakho: uska owner, woh kin systems ko chhoota hai aur kaunse credentials use karta hai. Robots ko **least-privilege** accounts do, jinmein sirf utna access ho jitna chahiye, aur unke passwords ek vault mein rakho, robot ki script mein nahi.

## Ek example se samjho

Kolkata ke ek general insurer ko email par motor claim intimations milte hain: roz lagbhag 300. Claims team har email aur uske attachments se details ek purane desktop claims system mein copy karti hai jisme API nahi hai. Har claim mein lagbhag 6 minute lagte hain, yaani poori team ka roz ka lagbhag 30 ghante ka kaam.

**Hal:**

1. Ek **AI extraction step** har intimation email aur attachment padhta hai aur structured fields banata hai: policy number, vehicle number, nuksaan ki tareekh aur jagah, description.
2. Fields ko policy database se **validate** kiya jaata hai: kya policy maujood hai, active hai, aur vehicle match karta hai?
3. Ek **unattended RPA robot** claims system kholta hai, "New intimation" par jaata hai, validated fields bharta hai, save karta hai, aur naya claim number tracking sheet mein wapas likh deta hai.
4. Jo validations fail hon, aur koi bhi screen jise robot pehchan na paye, screenshots ke saath **kisi insaan ki queue** mein jaati hai.

**Pehli timahi ke results:**

| Measure | Pehle | Baad mein |
| --- | --- | --- |
| Data entry par staff ka samay | Roz lagbhag 30 ghante | Roz lagbhag 6 ghante, zyadatar exceptions |
| Usi din enter hue claims | lagbhag 70% | lagbhag 98% |
| Robot outages | Lagu nahi | 2, dono system updates ke baad fields hilne se |
| Har outage theek karne ka samay | Lagu nahi | Ek din se kam; monitoring ne RPA developer ko alert kiya |

Insurer ki yojana hai ki agle saal jab claims system upgrade ho, toh robot ki jagah seedha API integration laga diya jaaye. Tab tak robot hi pul hai.

## Aam galtiyaan

- **Jahan API hai wahan RPA.** APIs tez aur mazboot hoti hain.
- **Screen ki fixed positions.** Element properties use karo taaki chhote badlaav robots ko na todein.
- **Asthir processes ko automate karna.** Process ya screens badalte hi robots toot jaate hain.
- **Na monitoring, na koi owner.** Toote robots chupchaap fail hote hain, aur kaam bina dikhe jama hota jaata hai.
- **Admin credentials wale robots.** Vault mein rakhe least-privilege accounts use karo.
- **Exits ko bhool jaana.** Pehle se tay karo ki kaunse cases kisi insaan ke paas jaayenge, aur us queue ko chalana aasaan banao.

## Practice karo

Neeche link kiya UiPath Academy ka free beginner course karo, ya Microsoft Learn par Power Automate Desktop ke modules.

1. **Build karo.** Ek simple robot banao jo koi website ya desktop app khole, spreadsheet ki ek row se form bhare aur confirmation save kare.
2. **Use todo.** Layout thoda badlo, window ka size badalkar ya screen resolution badalkar, aur dekho ki woh ab bhi chalta hai ya nahi. Behtar selectors se theek karo.
3. **Chuno.** Apne organisation ke kisi ek process ke liye likho ki RPA, API integration ya AI agent mein se kaun sabse sahi baithta hai, aur kyun.

**Aapka kaam poora jab:** aap samjha sako ki API ya AI agent ki jagah RPA kab chunoge, aur ek aisa robot dikha sako jo layout ke chhote badlaav se toote nahi.
