## Ye kya hai

Prompt engineering ek achha instruction likhne ke baare mein hai. **Context engineering** us sab ke baare mein hai jo model ek call par dekhta hai: system prompt, tool definitions, examples, retrieved documents, memory, ab tak ki conversation aur pehle ke tool calls ke results. Ek one-shot sawaal ke liye ye chhote hote hain. Pachaas steps chalne waale agent ke liye ye jama ho jaate hain, aur sawaal ban jaata hai: abhi window mein kya hona chahiye aur kya nahi?

Context ek budget hai. Bahut lambi windows waale models bhi jab window irrelevant material se bharti hai toh kharab chalte hain: details miss karte hain, goal kho dete hain aur har step zyada mehnga padta hai.

| Step 37 par context | Pehle | Baad mein |
|---|---|---|
| System prompt | Rules, 6k tokens | Principles, 1.5k tokens |
| Tools | 12 definitions | 4 definitions |
| Data | Poora purchase register aur supplier filings | Notes: pages 1-2 resolved, INV-7781 aur INV-7790 open; 20 mismatches ka abhi ka page |
| Tool results | 36 purane, jab tak window bhar na jaaye | 2 taaze |
| Result | Suppliers mix up kiye, limit hit hui | Ek run mein 3,000 mismatches |

```flow
dir: LR
title: Har step par context ko chhota rakhna
Purane tool results -[notes mein summarise karo]-> Notes
Notes -> Agla model call
Abhi ka page + 2 taaze results -> Agla model call
```

Ye lesson Chennai ki ek consultancy ke GST reconciliation agent ke saath chalta hai.

## Ye kaam kaise karta hai

**Sahi altitude par system prompt.** Bahut vague ("be helpful") koi guidance nahi deta; bahut rigid (pages ke if-then rules) un cases par tootta hai jo aapne socha nahi tha. Saaf principles, main steps aur kuch examples ka target rakho, headings ke neeche organised.

**Lean tools.** Har tool definition har call par tokens kharch karti hai aur har overlapping tool accuracy ghatata hai. Sirf wahi tools do jo abhi ke task ko chahiye.

**Just-in-time retrieval.** Har document ko pehle se load karne ki jagah, agent ko cheezein look up karne ke tareeke do (search, open file, read record) aur use jab zaroorat ho tab jo chahiye woh kheenchne do. File paths ya record ids jaise halke references context mein rakho, aur content on demand fetch karo.

**Purane tool results clear karo.** Teen steps pehle use hua 5,000-token ka search result dead weight hai. Results use hone ke baad drop ya shrink kar do, ek line ka note rakhte hue ki kya mila.

**Compaction.** Jab context apni limit ke paas aaye, history ko ek chhote state mein summarise karo: goal, liye gaye decisions, open questions, key facts. Us summary ke saath naye sire se shuru karo.

**Structured notes.** Lambe tasks ke liye agent se context ke bahar ek notes file ya to-do list rakhwao aur use dobara padhwao, taaki compaction ke baad progress bachi rahe.

**Sub-agents.** Ek sub-task ek sub-agent ko do jiska apna saaf context ho aur sirf uski summary wapas lo.

**Tokens kahan jaate hain:**

| Hissa | Aam problem | Fix |
| --- | --- | --- |
| System prompt | Rare cases ke liye pages ke rules | Principles, steps, ek-do examples |
| Tool definitions | Kai overlapping tools | Sirf is task ke tools |
| Retrieved documents | Sab kuch pehle se load | Id se on demand fetch |
| Tool results | Hamesha ke liye rakhe | Use ke baad clear karo, ek line ka note rakho |
| History | Har turn badhti hai | State summary mein compact karo |

**Achhi compaction summary likhna.** Summary apne se pehle ki har cheez ki jagah leti hai, isliye usme woh sab hona chahiye jo agent ko aage badhne ke liye chahiye: original task aur constraints poore, liye gaye decisions aur kyun, ab tak ke results totals ke roop mein, open items unki ids ke saath, aur agla step. Har step kaise kiya gaya uski narration chhod do. Compaction ko test karo ek task ko uske saath aur uske bina chala kar aur dekh kar ki final results match karte hain; agar compacted run koi constraint bhool jaaye, toh summary prompt mein koi section missing hai.

**Asar naapna.** Kuch tasks ke liye har change se pehle aur baad mein har step par hisse ke hisaab se token counts log karo. Teen numbers dekho: tokens per task, cost per task aur task success. Jo change tokens kaate par success ghataye, usne woh kuch hata diya jo model ko chahiye tha.

**Code mein purane tool results clear karo.** Latest kuch results poore rakho aur purane ko ek line ke note se badal do:

```python
def clear_old_results(messages, keep_last=3, max_chars=400):
    """Anthropic-style messages: tool results are blocks of type 'tool_result' in user turns."""
    seen = 0
    for msg in reversed(messages):
        if msg["role"] != "user" or not isinstance(msg["content"], list):
            continue
        for block in msg["content"]:
            if block.get("type") != "tool_result":
                continue
            seen += 1
            text = str(block.get("content", ""))
            if seen > keep_last and len(text) > max_chars:
                block["content"] = f"[cleared: {len(text)} chars; first line: {text.splitlines()[0][:120]}]"
    return messages
```

Model ko ab bhi dikhta hai ki call hua aur lagbhag kya return hua, par uske 5,000 tokens nahi. Agar details dobara chahiye, toh woh tool dobara call kar sakta hai.

**Fixed sections waala compaction prompt.** Ek free-form "isse summarise karo" constraints kho deta hai. Wahi hisse maango jo agent ko aage badhne ke liye chahiye:

```python
COMPACT_PROMPT = """Summarise this work so another assistant can continue it with no other context.
Use exactly these headings:
TASK: the original request and every constraint, word for word where possible
DECISIONS: what was decided and why, one line each
RESULTS SO FAR: totals and key facts, with ids
OPEN ITEMS: what remains, with ids
NEXT STEP: the single next action
Leave out how each step was done."""
```

Ise tab chalao jab context ek threshold paar kare, system prompt plus summary ke saath ek nayi conversation shuru karo, aur dono token counts log karo.

**Context ke bahar notes.** Lambe tasks ke liye agent ko do chhote tools do aur use bolo ki har milestone ke baad apne notes update kare:

```python
from pathlib import Path

NOTES = Path("runs/notes-{run_id}.md")

def read_notes(run_id):
    p = Path(str(NOTES).format(run_id=run_id))
    return p.read_text() if p.exists() else "(no notes yet)"

def write_notes(run_id, text):
    p = Path(str(NOTES).format(run_id=run_id))
    p.parent.mkdir(exist_ok=True)
    p.write_text(text[:4000])                    # keep notes short
    return "saved"
```

Compaction ya restart ke baad agent pehle apne notes padhta hai aur aage badhta hai.

**Zyada context ka matlab kharab jawab ho sakta hai.** Lambe inputs par studies paati hain ki context badhne par accuracy girti hai, simple lookups ke liye bhi, aur lambe inputs ke beech ke facts kam bharose se use hote hain. Context engineering window bharne ke baare mein nahi, balki model ko tokens ka sabse chhota set dene ke baare mein hai jisse woh task achhe se kar sake.

**Order matter karta hai.** Stable content (system prompt, tool definitions) sabse pehle rakho taaki use cache kiya ja sake, working material beech mein, aur abhi ka sawaal aur latest results sabse aakhir mein, jahan models sabse achhe se dhyaan dete hain.

## Ek example se samjho

Chennai ki ek GST consultancy ka agent ek client ke purchase register ko supplier filings se reconcile karta hai: hazaaron invoices, samjhane waale mismatches aur ek final report.

Pehla version poora register, poora filing data aur baarah tools context mein load karta tha. Chaalis invoices ke baad woh window limit tak pahunch gaya, aur usse pehle bhi usne milte-julte naam waale suppliers ko mix up kiya.

Redesign:

- System prompt reconciliation rules aur report format ek worked mismatch ke saath samjhata hai.
- Sirf chaar tools: `list_mismatches(page)`, `get_invoice(id)`, `get_supplier_filing(gstin, period)` aur `write_note(text)`.
- Agent ek baar mein 20 mismatches ka ek page sambhaalta hai. Har ek ke baad woh ek note likhta hai ("Page 3: 14 timing differences ke roop mein resolved, 4 supplier not filed, 2 ko client input chahiye: INV-7781, INV-7790") aur purane tool results clear ho jaate hain.
- Har 100 mismatches par history totals aur open items ki summary mein compact ho jaati hai.

Agent ab ek run mein 3,000 mismatches sambhaalta hai. Per invoice cost 70% girti hai, aur supplier matching par error rate ghatta hai kyunki model sirf haath ke case ke records dekhta hai.

| Measure | Pehla version | Redesign |
| --- | --- | --- |
| Ek run mein sambhaale gaye mismatches | Lagbhag 40, phir window bhar gayi | 3,000 |
| Per invoice cost | Baseline | 70% kam |
| Supplier matching errors | Milte-julte naamon ka aksar confusion | Kam hi |

## Aam galtiyaan

- **Bas kisi bhi sambhaavna ke liye sab load kar dena.** Zyada context achha context nahi hota. On demand retrieve karo.
- **Har tool result ko hamesha rakhna.** Results use hone ke baad clear ya summarise karo.
- **Compaction mein goal hata dena.** Summary mein task, constraints aur open items rehne chahiye, sirf haal ke events nahi.
- **Paanch-tool ke task ke liye bees tools.** Har ek tokens kharchta hai aur galat choices ko bulaata hai.
- **Asli context ko kabhi na dekhna.** Fail hote steps par model ko jo mila use log karke padho; wajah aksar dikh jaati hai.
- **Free-form compaction summaries** jo constraints chhod dete hain. Fixed headings use karo.
- **Bina note ke results clear karna,** jisse model wahi call dobara karta hai.
- **Calls ke beech tool order badalna,** jo prompt caching tod deta hai.

## Context engineering kab ruk sakta hai

- **Chhote tasks** jo window ke andar kuch hi steps mein khatam ho jaate hain.
- **Single calls** ek fixed prompt aur ek input ke saath.
- **Kam volume,** jahan extra tokens ki cost kam hai aur quality pehle se theek hai.

Ye sabse zyada lambe agent runs, lambi chats, bade documents aur aise kisi bhi kaam ke liye matter karta hai jahan context badhne par cost ya accuracy girti hai.

## Demo se production tak

- Har step par **hisse ke hisaab se tokens log karo**: system, tools, history, results.
- Clearing aur compaction ke liye **thresholds set karo**, aur log karo ki har ek kab fire hota hai.
- Same tasks par uske saath aur bina results compare karke **compaction test karo**.
- **Har run ke notes** storage mein rakho, trace se linked.
- Caching ke liye **context order karo**, aur changes ke baad cache hit rates check karo.
