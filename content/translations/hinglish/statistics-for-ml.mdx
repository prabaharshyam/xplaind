## Ye kya hai

Machine learning ka matlab hai data se seekhna, aur data noisy, skewed aur adhoora hota hai. **Statistics** uncertainty ke beech, bina khud ko dhokha diye, data se seekhne ka toolkit hai. ML engineering mein har hafte paanch areas saamne aate hain:

| Area | Kis sawaal ka jawaab deta hai | Kaunsi aam galti rokta hai |
| --- | --- | --- |
| **Data describe karna** | Typical kya hai, aur kitna phaila hua hai? | Misleading average report karna |
| **Sampling** | Kya hamara data un logon ko represent karta hai jinki hamein parvaah hai? | Aisa model jo tier-3 towns mein fail ho |
| **Rishte** | Kya ye saath-saath badalte hain, aur kya ek doosre ki vajah hai? | Ye daava karna ki koi feature outcome ki vajah hai |
| **Uncertainty** | Is number par hum kitne pakke hain? | 1 point ke aise gain ka jashn manana jo noise hai |
| **Experiments** | Kya hamare change se sach mein fayda hua? | Festival sale ka credit naye model ko de dena |

```text
  Order values (skewed: most small, a few huge)

  count
   |  ####
   |  ########
   |  ##########
   |  ######
   |  ###
   |  #                                         #
   +----------------------------------------------- value
      ^ median ₹780                    ^ mean ₹1,240 pulled right by a few big orders
```

Ye lesson Mumbai ki ek e-commerce company ki data team ke saath chalta hai. Ek report daava karti hai ki naye recommendation model ne "average order value ₹70 badha di". Sahi statistics lagane par asli fayda lagbhag ₹1.55 per user nikalta hai: chhota, lekin asli. Aakhir tak aap do models ki fair tulna kar paoge, A/B test ka size tay karke use chala paoge, aur samjha paoge ki chhote test sets kyun dhokha dete hain.

## Ye kaam kaise karta hai

### Averages aur spread

**Mean** sab kuch jodkar count se bhaag deta hai. Extreme values ise kheench leti hain. **Median** sort karne par beech wali value hai. Ye nahi khinchta.

**Standard deviation** (SD) spread naapta hai: mote taur par, ek typical value mean se kitni door hai. Bell-shaped data mein lagbhag 68% values mean se ek SD ke andar aati hain aur lagbhag 95% do SD ke andar.

Ye rule **skewed** data par toot jaata hai, jahan zyadatar values chhoti hoti hain aur kuch bahut badi. Bhaarteeya incomes, order values, insurance claims aur app latencies sab skewed hain. Wahan "mean plus two SDs" tail ka galat andaaza deta hai, aur percentiles use imaandaari se describe karte hain. 90th percentile wo value hai jiske neeche 90% cases aate hain.

| Data shape | Kaunsa average use karein | Kaunsa spread use karein |
| --- | --- | --- |
| Lagbhag symmetric, bell-shaped | Mean | Standard deviation |
| Skewed, lambi tail | Median | Percentiles, jaise 90th aur 99th |

Summarise karne se pehle hamesha ek histogram plot karo.

### Jin distributions se aapka saamna hoga

**Probability distribution** batata hai ki har value kitni likely hai. Shape pata ho to samajh aata hai ki kaunse summaries, tests aur models sahi baithte hain. Zyadatar ML kaam ke liye chaar shapes kaafi hain:

| Distribution | Ye kya ginta hai | ML mein ye kahan milta hai |
| --- | --- | --- |
| **Binomial** | n yes-or-no trials mein successes | n test questions mein sahi answers; n visitors mein buyers |
| **Poisson** | Ek fixed window mein events, jab events independent hon | Har minute ke orders, har ghante ke support tickets; asaamaanya spikes par alerting |
| **Normal** | Aisi values jo kai chhote effects ka sum ya average hon | Bade samples ke averages, isiliye accuracy aur means ke intervals kaam karte hain |
| **Long-tailed** (jaise log-normal) | Paisa, samay aur size | Order values, latency, session length: medians aur percentiles use karo, aur aksar modelling se pehle log lo |

**Base rates.** Jab aap jo dhoondh rahe ho wo rare ho, to achha classifier bhi zyadatar false alarms deta hai. Jaise, maan lo 1 lakh UPI transactions mein se 0.5% fraud hain (500 cases). Ek model 90% fraud pakadta hai aur 5% genuine payments ko galti se flag karta hai. Ye 450 frauds aur 4,975 genuine payments flag karta hai, to iske alerts mein se sirf 8% fraud hain. Precision judge karne se pehle hamesha base rate poochho.

### Sampling aur selection bias

Model utna hi achha hota hai jitna wo sample jisse usne seekha. Poochho: **Is data se kaun gaayab hai?** Jo data kuch cases ki taraf jhuke tareeke se collect hua ho, wo **selection bias** paida karta hai. Examples: sirf wo customers jinhone complain kiya, ya sirf wo loans jo approve hue, to aap kabhi nahi dekh paate ki reject hue applicants kaise repay karte.

Selection bias launch ke baad chupchaap models tod deta hai. Ise launch se pehle pakdo: apne training data ke segment shares ki tulna haal ke live traffic se karo. City tier, device, language aur new banaam returning users use karo. Jaise, agar 72% training rows metros se hain lekin pichhle mahine ke sirf 48% users metros se hain, to model ne small-town users bahut kam dekhe hain. Aur data collect karo, reweight karo, ya kam se kam har segment ki accuracy report karo.

### Correlation, causation aur Simpson's paradox

Do cheezon ke saath-saath badalne ka matlab ye nahi ki ek doosre ki vajah hai. Ice-cream ki bikri aur doobne ki ghatnaayein dono garmi mein badhti hain: garmi dono ko chalati hai. Model correlations se **predict** kar sakta hai. **Cause** ka daava karne ke liye, jaise ki discount se retention badha, aapko randomised experiment ya saavdhaani wale causal methods chahiye.

Groups ko milaane se nateeja ulta bhi ho sakta hai. Ise **Simpson's paradox** kehte hain. Maan lo ek support bot zyadatar Hindi users ke liye roll out hota hai, jinke sawaal zyada mushkil hain:

| Queries | Purane bot ne resolve kiye | Naye bot ne resolve kiye |
| --- | --- | --- |
| English | 900 mein se 720 (80%) | 300 mein se 255 (85%) |
| Hindi | 100 mein se 50 (50%) | 700 mein se 385 (55%) |
| **Sab** | **1,000 mein se 770 (77%)** | **1,000 mein se 640 (64%)** |

Naya bot har language mein behtar hai lekin kul milaakar kharaab dikhta hai, kyunki mushkil queries zyada usi ko mileen. Ek jaise ki tulna ek jaise se karo, segment ke hisaab se, ya randomise karo ki kise kaunsa version mile.

### Standard error aur confidence intervals

SD alag-alag values ko describe karta hai. **Standard error** (SE) batata hai ki koi estimate, jaise mean ya accuracy, ek sample se doosre sample mein kitna hilega. Ye sample size ke square root ke saath ghatta hai: chaar guna data se SE aadha ho jaata hai. n examples par naapi gayi accuracy p ke liye, SE hai p × (1 − p) ÷ n ka square root.

**95% confidence interval** mote taur par estimate plus or minus 2 SE hai. Ye asli number ke liye mumkin values ki range deta hai, ek aise method se bani jo 95% baar asli value pakad leta hai. 200 test examples par, naapi gayi 87% ke peechhe ki asli accuracy lagbhag 82% se 92% ke beech kahin bhi ho sakti hai.

| Test examples | Naapi gayi 87% ke aaspaas 95% interval |
| --- | --- |
| 200 | lagbhag ± 4.7 points |
| 1,000 | lagbhag ± 2.1 points |
| 5,000 | lagbhag ± 0.9 points |

Kisi bhi metric ka interval nikaalne ka jaldi wala tareeka, F1 ya median ka bhi, **bootstrapping** hai. Apne test set ko replacement ke saath kai baar resample karo, har baar metric dobara nikaalo, aur results ka beech wala 95% lo.

### Ek hi test set par do models ki tulna

Model A ek hi 200 questions par 87% score karta hai aur model B 88%. Ek aam aadat hai ye check karna ki dono intervals overlap hote hain ya nahi. Ye rule misleading hai: difference asli hone par bhi do 95% intervals overlap ho sakte hain. Ye is baat ko bhi nazarandaaz karta hai ki dono models ne *wahi* questions ke jawaab diye, to jo questions dono sahi karte hain ya dono galat karte hain wo cancel ho jaate hain, aur sirf disagreements maayne rakhte hain.

Iske bajaay, **difference ko seedhe naapo, question ke hisaab se pair karke**:

```text
  Same 200 questions (illustrative):
  A right, B wrong:   7      B right, A wrong:   9      net: B +2 questions
  Paired bootstrap of B minus A:  +1 point, 95% interval -3 to +5 points
                                  includes 0: no clear winner
```

```python
import numpy as np

# 1 = answered correctly, 0 = wrong; the same 200 questions in the same order
a = np.array([1]*167 + [1]*7 + [0]*9 + [0]*17)   # model A: 174 right, 87%
b = np.array([1]*167 + [0]*7 + [1]*9 + [0]*17)   # model B: 176 right, 88%

rng = np.random.default_rng(0)
idx = rng.integers(0, len(a), size=(10_000, len(a)))   # resample questions
diffs = b[idx].mean(axis=1) - a[idx].mean(axis=1)      # B minus A on the same draw
low, high = np.percentile(diffs, [2.5, 97.5])
print(f"B minus A: {b.mean() - a.mean():+.1%}, 95% interval {low:+.1%} to {high:+.1%}")
# B minus A: +1.0%, 95% interval -3.0% to +5.0%
```

Classic alternative hai **McNemar's test**, jo sirf un questions ko dekhta hai jin par models alag jawaab dete hain. Yahan ye p = 0.80 deta hai. Ek kaam ka gotcha: agar net gain 3 questions ya usse kam hai, to McNemar's test mein p kabhi 0.05 se neeche nahi aa sakta, chahe aapke paas kitne bhi questions hon.

### p-values aur significance aasaan shabdon mein

**p-value** ek sawaal ka jawaab deta hai: agar change ne sach mein kuch nahi kiya, to sirf random noise kitni baar kam se kam itna bada difference paida karega? 0.03 ke p-value ka matlab hai lagbhag 3% baar. Convention se, p 0.05 se neeche wale result ko **statistically significant** kehte hain.

p-value is baat ka chance *nahi* hai ki change kaam karta hai, aur chhote p-value ka matlab bada effect nahi hai. Sample kaafi bada ho to itna chhota gain bhi significant ho jaata hai jo ship karne laayak hi nahi. Hamesha effect ka size uske confidence interval ke saath report karo, sirf p-value nahi.

### A/B tests

Ye jaanne ke liye ki koi change madad karta hai ya nahi, users ko **randomly** baanto: kuch purana version (control) dekhein, kuch naya (treatment). Dono ko unhin dinon mein chalao aur pehle se chune gaye metric ki tulna karo.

Primary metric soch-samajhkar chuno. **Average order value** sirf un users ko ginta hai jinhone khareeda. Agar naya model ye badal de ki *kaun* khareedta hai, to dono groups ke buyers alag log honge, aur tulna biased hogi. **Revenue per user** group ki poori revenue ko group ke saare users se bhaag deta hai, khareeda ho ya nahi, to ye fair rehta hai. Ise primary metric banao, aur order value aur conversion ko secondary metrics rakho.

| Rule | Kyun |
| --- | --- |
| Ek primary metric, sample size aur duration pehle se tay | Jab change kuch nahi karta, tab 20 independent metrics check karne par 64% chance hai ki kam se kam ek kismat se "jeet" jaaye |
| Randomise karo ki kaun kaunsa version dekhe | Taaki groups mein sirf change ka fark ho |
| Sample ratio check karo | 10 lakh users ka planned 50/50 split agar 5,03,000 banaam 4,97,000 aaye, to assignment ya logging mein bug hai; result par bharosa mat karo |
| Poore hafte chalao | Weekday aur weekend ka behaviour alag hota hai |
| Achha dikhne par jaldi mat roko | Humne ek aise change ka simulation chalaya jisne kuch nahi kiya: 14 din roz check karke pehli baar p 0.05 se neeche aate hi rokne par 22% baar "winner" ghoshit hua, 5% nahi |
| Novelty effects par nazar rakho | Users naye design par isliye click karte hain kyunki wo naya hai; check karo ki doosre hafte mein gain kam hota hai ya nahi |
| Guardrail metrics par nazar rakho | Revenue mein gain ke saath zyada returns ya complaints nahi aane chahiye |

### Kitne users?

Test se pehle, chaar inputs se sample size tay karo:

1. **Baseline**: abhi ki value, jaise 3.4% conversion rate.
2. **Minimum detectable effect (MDE)**: sabse chhota gain jo dhoondhne laayak hai, jaise 10% relative lift, 3.4% se 3.74%.
3. **Significance level**: aamtaur par 5%, wo false-alarm rate jo aap maante ho jab change kuch nahi karta.
4. **Power**: aamtaur par 80%, MDE ke size ke asli effect ko pakadne ka chance.

In inputs ke saath aapko **har group mein lagbhag 46,700 users** chahiye. MDE aadha karke 5% lift karo to har group mein lagbhag 1.83 lakh chahiye: effect aadha karne se users lagbhag chaar guna ho jaate hain. Python mein `statsmodels.stats.power.NormalIndPower().solve_power` ye calculation karta hai.

Revenue per user ke liye conversion se kahin zyada users chahiye, kyunki kuch bahut bade orders ise bahut noisy bana dete hain. Do standard fixes madad karte hain. Average nikaalne se pehle har user ki revenue ko ek oonche percentile par cap karo, jaise 99th. Ya CUPED jaisa variance-reduction method use karo, jo test se pehle ki har user ki spending ke hisaab se adjust karta hai.

## Ek example se samjho

Mumbai ki ek e-commerce company ki data team report karti hai ki naye recommendation model ne average order value ₹1,240 se badhakar ₹1,310 kar di: ₹70 ka fayda. Leadership jashn manane ko taiyaar hai. Aap ise check karte ho. Neeche ke test numbers illustrative hain, ek simulated test se banaaye gaye, lekin wo waise hi behave karte hain jaise asli tests.

**Step 1: averages.** Order values skewed hain. Kuch bade electronics orders ne mean ko hila diya. Median order sirf ₹780 se ₹790 hua.

**Step 2: timing.** Tulna pichhle mahine (purana model) ki is mahine (naya model) se thi. Is mahine ek festival sale tha. Dono mahinon ki tulna nahi ho sakti, to wo ₹70 model ke baare mein kuch nahi batata.

**Step 3: proper test design karo.** Shuru karne se pehle team ye tay karti hai:

- **Primary metric:** revenue per user, har user ki revenue ko order values ke 99th percentile (lagbhag ₹7,300) par cap karke.
- **Secondary metrics:** conversion, mean aur median order value. **Guardrail:** return rate.
- **Size:** capped revenue per user mein 5% lift pakadne ke liye har group mein lagbhag 3.9 lakh users chahiye. Do poore hafton ka traffic har group mein lagbhag 5 lakh deta hai, to test theek do hafte chalta hai.

**Step 4: split check karo.** Groups mein 5,00,212 aur 4,99,788 users hain. In counts par chi-square test p = 0.67 deta hai, to split ek fair 50/50 se mel khaata hai.

**Step 5: results padho.**

| Measure | Purana model | Naya model | Difference (95% interval) |
| --- | --- | --- | --- |
| Revenue per user, capped (primary) | ₹40.61 | ₹42.16 | +₹1.55 (+₹0.29 se +₹2.81) |
| Conversion rate | 3.38% | 3.45% | +0.07 points (lagbhag 0 se +0.14) |
| Mean order value | ₹1,237 | ₹1,258 | +₹21 (−₹12 se +₹54) |
| Median order value | ₹781 | ₹796 | +₹15 (−₹6 se +₹34) |
| Return rate (guardrail) | 6.28% | 6.15% | −0.13 points (−0.64 se +0.38) |

**Step 6: faisla karo.** Primary metric ka interval zero ko exclude karta hai, to model sach mein madad karta hai: lagbhag +3.8% revenue per user. Gain thodi zyada khareedaari aur thode bade orders se aata hai, aur dono mein se koi akele saaf nahi hai. Returns mein koi nuksaan nahi dikhta. Pehli report wale ₹70 festival wale mahine aur kuch bade orders se aaye the. Dhyaan do ki akele mean order value dekhte to nateeja inconclusive lagta.

Har 10 lakh users par ye gain lagbhag ₹15.5 lakh ka hai, mumkin range ₹2.9 lakh se ₹28 lakh. Leadership in imaandaar numbers ke saath model roll out karti hai. Team apni launch checklist mein "Impact ka daava karne se pehle A/B test" jodti hai.

## Aam galtiyaan

- **Skewed data ka mean report karna.** Median, percentiles aur histogram dekho.
- **Base rate ko nazarandaaz karna.** 95% accurate fraud model bhi apne zyadatar alerts par galat ho sakta hai.
- **Alag-alag time periods ki tulna karna.** Seasons aur festivals sab badal dete hain; iske bajaay randomise karo.
- **Ye nazarandaaz karna ki data se kaun gaayab hai.** Launch se pehle training segments ki tulna live traffic se karo.
- **Correlation ko causation maan lena.** Prediction cause ka saboot nahi hai, aur milaaye gaye numbers ulte ho sakte hain (Simpson's paradox).
- **Overlapping intervals se do models ko judge karna.** Ek hi test set par paired bootstrap ya McNemar's test use karo.
- **Buyers-only metric ko primary metric banana.** Order value nahi, revenue per user use karo.
- **Peek karna, jaldi rokna, ya bahut saare metrics check karna.** Ek primary metric, sample size aur duration pehle se tay karo.
- **Sample ratio check chhod dena.** Uneven split ka matlab toota hua test hai, result nahi.

## Practice karo

Neeche link kiye StatQuest ke p-values, confidence intervals aur bootstrapping wale videos dekho, aur Google ke Machine Learning Crash Course ka data module bhi.
