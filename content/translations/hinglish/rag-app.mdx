## Ye kya hai

**RAG app** (retrieval-augmented generation) aapke apne documents se sawaalon ke jawab deta hai. Har sawaal ke liye wo:

1. Aapke documents ke index se sabse relevant passages **retrieve** karta hai;
2. Prompt ko un passages se **augment** karta hai;
3. Aisa jawab **generate** karta hai jo sirf un passages ko use aur cite karta hai.

Companies ke liye apne data par language models use karne ka ye sabse common tareeka hai, kyunki isme model training nahi chahiye aur documents badalne par ye current rehta hai.

```flow
title: Ingestion: ek baar, phir updates par
PDFs -> Extract text, OCR -> Chunk by heading | about 400 tokens, with title and section
Chunk by heading -> Embed -> Index (pgvector) | metadata: doc, page, section, dates
```

```flow
title: Query ke waqt
Question -> Hybrid search | vectors + keywords -[top 20]-> Rerank
Rerank -[top 5]-> Prompt | instructions + passages [1] to [5] with sources + question
Prompt -> Model -> Answer with citations [2][4] | or "I could not find this..."
```

Is lesson mein hum Coimbatore ke ek college ko follow karenge jo regulations, fees, exams aur scholarships ke baare mein students ke sawaalon ke liye assistant bana raha hai.

## Ye kaam kaise karta hai

**Ingestion (ek baar, phir updates par).** Documents load karo, clean text nikaalo, titles aur page numbers ke saath chunks mein baanto, har chunk ko embed karo aur uske metadata ke saath ek index mein store karo.

**Query ke waqt.**

- Sawaal ko embed karo; top candidates retrieve karo (vector search, behtar hai keyword search ke saath hybrid); chaaho toh rerank karke best paanch rakho.
- Prompt banao: instructions, har passage ek id aur source ke saath label kiya hua, phir sawaal.
- Model ko instruct karo: sirf passages se jawab do; passage ids cite karo; agar passages mein jawab nahi hai toh wahi bolo.
- Jawab uske citations ke saath lautao, source documents se linked.

**Contextual retrieval.** Chunks mein aksar context nahi hota ("limit 45 days hai"). Chunk ke aage ek chhota description jodna ki wo document mein kahan hai, aur embeddings ko keyword search ke saath milana, naapne par retrieval failures kam karta hai.

**"Pata nahi" kehna.** Bharosemand RAG app tab mana kar deta hai jab documents chup hon. Apne tests mein aise sawaal bhi rakho jinka jawab nahi diya ja sakta.

**Evaluation.** Expected sources aur answers ke saath sawaalon ka ek fixed set rakho. Retrieval (recall at k) aur answers (correctness, faithfulness) ko alag-alag naapo, aur har badlaav ke baad dobara chalao.

**Freshness aur access.** Badle huye documents re-index karo; superseded wale filter karo; agar users ki permissions alag hain, toh retrieval ko is hisaab se filter karo ki har user kya dekh sakta hai.

**Ek minimal query function:**

```python
def answer(question, user):
    hits = hybrid_search(question, k=20, filters={"access": user.groups})
    top = rerank(question, hits)[:5]
    passages = "\n\n".join(
        f"[{i+1}] {h.title}, section {h.section}, page {h.page}\n{h.text}"
        for i, h in enumerate(top)
    )
    prompt = (
        "Answer using only the passages. Cite like [2] after each sentence. "
        "If the passages do not answer the question, say so and name the office to contact.\n\n"
        f"Passages:\n{passages}\n\nQuestion: {question}"
    )
    return call_model(prompt), top
```

Jawab ke saath `top` bhi lautane se interface har citation ko uske document aur page se link kar sakta hai, aur jab jawab galat jaaye toh aapke logs dikha sakte hain ki kya retrieve hua tha.

**Sabse pehle kya naapein:**

| Measure | Kis sawaal ka jawab deta hai | Kis target par jaana hai |
| --- | --- | --- |
| Recall at 5 | Kya sahi passage retrieve hua? | Golden set par 85% se upar |
| Correctness | Kya jawab sahi hai? | Client ke saath tay kiya hua |
| Faithfulness | Kya har claim kisi passage se support hota hai? | 0.9 se upar |
| Na-jawab-dene-layak sawaalon par refusal rate | Kya wo maanta hai jab documents chup hon? | 75% se upar |
| Latency | Kya ye kaafi tez hai? | Pehle shabd 2 seconds ke andar |

**Galat jawab debug karna.** Pehle retrieved passages dekho. Agar sahi passage gayab hai, toh problem ingestion ya retrieval mein hai: parsing, chunking, filters ya search. Agar wo maujood hai aur jawab phir bhi galat hai, toh problem prompt ya model mein hai. Ye ek check bahut andaaza lagane se bacha deta hai.

**Ek chhota RAG app jo aap chala sakte ho.** Ye ek open embedding model, keywords ke liye BM25, unhe milane ke liye reciprocal rank fusion, aur citations ke saath jawab dene ke liye Anthropic ka API use karta hai. `sentence-transformers rank_bm25 anthropic` install karo:

```python
import numpy as np
from rank_bm25 import BM25Okapi
from sentence_transformers import SentenceTransformer
import anthropic

embedder = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")   # small, English
client = anthropic.Anthropic()

def ingest(chunks):
    """chunks: list of {"id", "title", "page", "text"}."""
    texts = [f"{c['title']}. {c['text']}" for c in chunks]
    vectors = embedder.encode(texts, normalize_embeddings=True)
    bm25 = BM25Okapi([t.lower().split() for t in texts])
    return {"chunks": chunks, "vectors": vectors, "bm25": bm25}

def search(index, question, k=5, pool=20):
    q = embedder.encode([question], normalize_embeddings=True)[0]
    by_vector = np.argsort(-(index["vectors"] @ q))[:pool]
    by_keyword = np.argsort(-index["bm25"].get_scores(question.lower().split()))[:pool]
    fused = {}
    for ranking in (by_vector, by_keyword):
        for rank, i in enumerate(ranking):
            fused[int(i)] = fused.get(int(i), 0) + 1 / (60 + rank)      # reciprocal rank fusion
    best = sorted(fused, key=fused.get, reverse=True)[:k]
    return [index["chunks"][i] for i in best]

def answer(index, question):
    hits = search(index, question)
    passages = "\n\n".join(f"[{n}] {h['title']}, page {h['page']}\n{h['text']}" for n, h in enumerate(hits, 1))
    reply = client.messages.create(
        model="claude-sonnet-5-5", max_tokens=500,          # check the docs for current names
        system="Answer only from the passages. Cite like [2] after each sentence. "
               "If they do not contain the answer, say so and suggest who to ask.",
        messages=[{"role": "user", "content": f"Passages:\n{passages}\n\nQuestion: {question}"}])
    return "".join(b.text for b in reply.content if b.type == "text"), hits
```

Kuch hazaar chunks par ye laptop par memory mein chal jaata hai. Usse aage, vectors ko vector database ya pgvector mein le jao aur wahi functions rakho.

**Search se pehle follow-ups rewrite karo.** Chat mein "ITI students ke liye kya?" kuch kaam ka retrieve nahi karta. Retrieval se pehle ek chhote, tez model se pichhle kuch turns ke saath latest message ko ek standalone sawaal mein rewrite karwao ("ITI students ke liye fee waiver limit kya hai?") aur usse search karo. Dono versions log karo.

**Kuch lines mein retrieval naapo.** Har golden sawaal ke liye record karo ki kaunse chunk ids milne chahiye:

```python
def recall_at_k(index, golden, k=5):
    """golden: list of (question, set_of_correct_chunk_ids)."""
    hits = 0
    for q, correct in golden:
        found = {h["id"] for h in search(index, q, k=k)}
        hits += bool(found & correct)
    return hits / len(golden)
```

Chunking, embedding model, filters ya fusion settings mein har badlaav se pehle aur baad ise chalao. Jo badlaav haath se try kiye teen sawaalon par jawab behtar kare par recall 88% se 79% par gira de, wo ek kadam peeche hai.

**Retrieval quality ke do roop.** **Context recall**: kya passages mein wo tha jo chahiye tha? **Context precision**: jo retrieve hua uska kitna hissa sach mein relevant tha? Kam recall galat ya "pata nahi" jawab deta hai; kam precision tokens waste karta hai aur model ka dhyaan bhatka sakta hai.

## Ek example se samjho

Coimbatore ka ek college 25 PDFs se academic regulations, fees, exams aur scholarships ke baare mein students ke sawaalon ke liye assistant banata hai.

- Ingestion: page numbers ke saath text nikaala, headings ke hisaab se lagbhag 400-token ke chunks mein baanta, document title aur section aage jode, embed kiya aur pgvector mein store kiya.
- Retrieval: hybrid search (vectors plus keywords), top 20 ko rerank karke 5.
- Prompt: "Sirf passages se jawab do. [2] jaise cite karo. Agar jawab passages mein nahi hai toh bolo 'Ye mujhe college regulations mein nahi mila' aur contact karne ke liye office suggest karo."
- Interface: jawab citations dikhata hai jo sahi page par PDF kholte hain.

50 sawaalon ke saath testing (aath na-jawab-dene-layak sawaal milakar): 42 jawab-dene-layak sawaalon mein se 40 sahi citations ke saath sahi nikle, 8 na-jawab-dene-layak mein se 6 ko sahi tarah mana kiya gaya. Do failures ek fee circular se aayi jo scanned image thi; OCR ke baad dono theek ho gayi. Students ab office mein line lagane se pehle assistant se poochhte hain, aur staff ko kam repeat sawaalon ke jawab dene padte hain.

| 50 sawaalon ka test set | Result |
| --- | --- |
| Jawab-dene-layak sawaal jo sahi citations ke saath sahi nikle | OCR fix ke baad 42 mein se 42 |
| Na-jawab-dene-layak sawaal jinhe sahi mana kiya gaya | 8 mein se 6 |
| Scanned fee circular se judi failures | 2, OCR se theek hui |

**College ne kya seekha.** Sabse badi ek gain model se nahi, parsing se aayi: jab scanned fee circular padhne laayak hua, do galat jawab sahi ho gaye. Sahi page par PDF kholne wale citations ne office staff ko assistant par itna bharosa dilaya ki wo students ko uski taraf bhejne lage, aur isi se usage badha.

## Aam galtiyaan

- **Citations nahi.** Users check nahi kar sakte, aur galtiyaan dhyaan mein nahi aatin.
- **Refusal path nahi.** Documents chup hon toh model andaaza lagata hai.
- **Retrieval evaluation chhod dena.** Zyadatar failures retrieval failures hoti hain.
- **Scanned documents aur tables ko ignore karna.** Unhe OCR aur table-aware parsing chahiye.
- **Ek baar index karke bhool jaana.** Documents badalte hain; re-index karo.
- **Raw follow-up message se search karna.** Pehle use standalone sawaal mein rewrite karo.
- **Ek saath kai retrieval settings badalna.** Ek badlo aur recall dobara chalao.

## Jab RAG ki zaroorat nahi

- **Documents context mein fit ho jaate hain** aur kam badalte hain: unhe prompt mein daal do, cached.
- **Jawab database mein hai**, jaise order status ya bhari hui fees: tool ya query use karo, text search nahi.
- **Sawaalon ko poore collection par reasoning chahiye**, jaise "kaunsi policies ek doosre ka khandan karti hain?": RAG tukde dhoondhta hai, overview nahi.

## Demo se production tak

- Expected chunks aur answers ke saath **golden set rakho**, aur har badlaav par recall aur answer checks chalao.
- Har jawab ke saath **rewrite ki hui query, retrieved ids aur scores log karo**.
- Document badalne par **re-index karo**, aur superseded versions hata do.
- **Ranking se pehle permissions se filter karo**, model ke text dekhne ke baad kabhi nahi.
- Topic ke hisaab se **"pata nahi" rate track karo**, jo gayab documents ki taraf ishaara karta hai.
