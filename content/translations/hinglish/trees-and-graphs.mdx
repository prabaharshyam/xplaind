## Ye kya hai

**Graph** **edges** se jude **nodes** ka ek set hai. Tracks se jude metro stations, dosti se jude log aur links se jude web pages, ye sab graphs hain. Edges ki direction (one-way street) aur weight (distance ya price) ho sakte hain.

**Tree** ek special graph hai: connected, bina cycles ke, isliye kisi bhi do nodes ke beech bilkul ek hi path hota hai. Usme aam taur par upar **root** aur neeche **children** hote hain. Aapke laptop ke folders, company ka org chart aur web page ka HTML trees hain. **Binary tree** mein har node ke zyada se zyada do children hote hain; **binary search tree** mein chhoti values left aur badi right mein rehti hain.

```flow
title: Ek tree: koi cycle nahi, kisi bhi do nodes ke beech ek hi path
CEO -> CTO
CEO -> CFO
CTO -> Dev1
CTO -> Dev2
CFO -> Fin1
```

```flow
dir: LR
title: Ek graph: cycles allowed, kai paths, isliye "visited" track karo
Rajiv Chowk -> Kashmere Gate -> Civil Lines -> Vishwavidyalaya
Rajiv Chowk -> Mandi House -> ITO -> Central Secretariat
Rajiv Chowk -> Central Secretariat
```

Inhe explore karne ke do tareeke baar-baar aate hain: **breadth-first search** (BFS) aur **depth-first search** (DFS).

## Ye kaam kaise karta hai

Code mein graph aam taur par **adjacency list** hota hai: har node se uske neighbours tak ek dict.

```python
metro = {
    "Rajiv Chowk": ["Kashmere Gate", "Mandi House", "Central Secretariat"],
    "Kashmere Gate": ["Rajiv Chowk", "Civil Lines"],
    "Mandi House": ["Rajiv Chowk", "ITO"],
    "Central Secretariat": ["Rajiv Chowk", "ITO"],
    "ITO": ["Mandi House", "Central Secretariat"],
    "Civil Lines": ["Kashmere Gate", "Vishwavidyalaya"],
    "Vishwavidyalaya": ["Civil Lines"],
}
```

**BFS** rings mein explore karta hai. Woh ek node se shuru karta hai, uske saare neighbours dekhta hai, phir unke neighbours, aur aise hi aage, **queue** use karke taaki nodes usi order mein handle hon jisme mile. Kyunki woh ek baar mein ek edge bahar ki taraf badhta hai, BFS jab pehli baar kisi node tak pahunchta hai, woh sabse kam edges se hota hai. Isliye "fewest stops" ya "degrees of separation" ke liye yahi sahi tool hai.

**DFS** ek path par jitna ho sake utna gehra jaata hai, phir peeche aakar agli branch try karta hai. Ye **stack** use karta hai, aksar recursion ke through call stack. DFS reachable sab kuch explore karne, cycles detect karne aur trees ko ek khaas order mein chalne ke liye natural hai.

Graphs par dono ko **visited** set chahiye, warna cycles unhe hamesha ghumate rahenge. Dono O(V + E) time lete hain, jahan V nodes ki sankhya hai aur E edges ki.

| Sawaal | Kya use karo | Kyun |
|---|---|---|
| Do nodes ke beech sabse kam hops, unweighted | BFS | edges ki distance ke hisaab se explore karta hai |
| Ek node se reachable sab kuch | DFS ya BFS | dono sab visit karte hain; DFS likhna chhota hai |
| Cycle detect karna, ya dependencies wale tasks ko order karna | DFS | iska back-tracking cycles dikha deta hai; topological order deta hai |
| Network mein connected groups | Har unvisited node se DFS ya BFS | har run ek group mark karta hai |
| Weighted edges ke saath sabse sasta path | Dijkstra's algorithm | BFS weights ko ignore karta hai |
| Sorted tree mein value dhoondhna | binary search tree walk | har step mein search aadhi ho jaati hai |

## Ek example se samjho

Kabir Delhi ke commuters ke liye ek route helper bana raha hai. User do stations chunta hai aur app sabse kam stops wala route dikhata hai. Padosi stations ke beech har hop barabar gina jaata hai, isliye BFS fit hota hai.

```python
from collections import deque

def fewest_stops(graph, start, goal):
    queue = deque([[start]])          # each item is a path so far
    visited = {start}
    while queue:
        path = queue.popleft()
        station = path[-1]
        if station == goal:
            return path
        for nxt in graph[station]:
            if nxt not in visited:
                visited.add(nxt)
                queue.append(path + [nxt])
    return None
```

"Mandi House" se "Civil Lines" tak, BFS pehle Rajiv Chowk aur ITO dhoondhta hai (ek stop door), phir Kashmere Gate aur Central Secretariat (do door), phir Civil Lines (teen door). Woh `Mandi House → Rajiv Chowk → Kashmere Gate → Civil Lines` return karta hai, aur isse chhota koi route nahi hai, kyunki BFS ne pehle har do-stop wala route check kar liya tha.

App ko ye bhi batana hai ki maintenance ke dauran koi station kat gaya hai. Kabir band station ko graph se hata deta hai aur ek bade interchange se DFS chalata hai taaki jo stations abhi bhi reachable hain unki list mil jaaye:

```python
def reachable(graph, start, seen=None):
    seen = seen if seen is not None else set()
    seen.add(start)
    for nxt in graph[start]:
        if nxt not in seen:
            reachable(graph, nxt, seen)
    return seen
```

Jo station result mein nahi hai woh unreachable hai aur use warning banner milta hai.

Jab team baad mein fares jodti hai, toh sabse kam stops wale routes hamesha sabse sasta nahi hote. Ye weighted graph hai, aur Kabir Dijkstra's algorithm par chala jaata hai, jo total cost ke order wali priority queue ke saath BFS hai.

## Aam galtiyaan

**Visited set na hona.** Cycles wale graph par BFS aur DFS hamesha loop karte hain. Nodes ko queue mein daalte waqt visited mark karo, nikalte waqt nahi, warna aap wahi node kai baar daaloge.

**Shortest paths ke liye DFS use karna.** DFS ek path dhoondhta hai, sabse chhota nahi. Kam se kam edges ke liye BFS use karo.

**Weighted graphs par BFS use karna.** BFS edges gintata hai, cost nahi. Jab edges ke alag weights hon toh Dijkstra's algorithm use karo.

**Deep recursion limits.** Lambi chain par recursive DFS Python ki lagbhag 1,000 ki recursion limit paar kar sakta hai. Bahut gehre graphs ke liye explicit stack use karo.

**Maan lena ki har tree balanced hai.** Pehle se sorted data se bana binary search tree lambi chain ban jaata hai, aur searches O(n) par gir jaati hain. Real systems self-balancing trees use karte hain.

**Edge direction bhool jaana.** Instagram par follow one-way hota hai. Directed edges ko sirf usi direction mein store karo jisme woh jaati hain.
