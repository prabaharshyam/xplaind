## Ye kya hai

**Multimodal RAG** aise content se retrieve karke answer karta hai jo plain text nahi hai: slides, charts, tables, scanned pages, diagrams aur photos. Do main approaches hain:

- **Text mein badlo, phir normal RAG use karo.** Scans ko OCR karo, images aur charts ko vision-language model se describe karwao, tables ko text mein extract karo, aur sab kuch text ki tarah index karo. Simple hai aur maujooda pipelines ke saath compatible.
- **Images seedhe retrieve karo.** Har page ko multimodal embedding model se image ki tarah index karo (ColPali jaisi approaches page images ko bina OCR ke embed karti hain), sabse relevant page images retrieve karo, aur answer ke liye unhe **vision-language model** ko bhejo.

Kai systems dono ko milate hain.

```flow
title: Text mein badlo: sasta, normal RAG
Scan -[OCR]-> Text index
Chart -[VLM describe karta hai]-> Text index
Table -[extract]-> Text index
Text index -> Ek normal RAG answer
```

```flow
title: Images retrieve karo
Page -[render]-> Image -[multimodal embedding]-> Image index
Question -[embed]-> Top 3 page images
Image index -> Top 3 page images
Top 3 page images -> Vision-language model images se answer deta hai
```

Hybrid forms ke liye OCR text aur photos, diagrams aur slides ke liye image retrieval use karta hai, aur har answer ke saath page thumbnail dikhata hai taaki use check kiya ja sake.

Ye lesson Vadodara ke ek chemicals manufacturer ke saath chalta hai, jiske engineers 15 saal ki maintenance reports query karte hain jo scans, photos aur diagrams se bhari hain.

## Ye kaam kaise karta hai

**Text mein badalne ka route.**

- Charts aur diagrams: vision-language model se axis labels, values aur trends ke saath detailed description maango, aur use page reference ke saath store karo.
- Images mein tables: unhe structured text mein extract karo.
- Photos: use case ke liye jo zaroori hai uske saath caption likho ("rust on the flange joint, upper left").

Pros: queries sasti, kisi bhi text model ke saath chalta hai, filter aur cite karna aasaan. Cons: descriptions mein details kho jaati hain, aur pehle se decide karna padta hai ki kya zaroori hai.

**Image-retrieval route.**

- Har page ya slide ko image ki tarah render karo.
- Use multimodal retrieval model se embed karo.
- Query ke time sawaal embed karo, top pages retrieve karo aur images ko sawaal ke saath vision-language model ko do.

Pros: layout, charts aur visual details bachte hain; OCR errors nahi. Cons: indexes bade, image inputs zyada tokens lete hain aur zyada time, aur kam tools ise support karte hain.

**Evaluation.** Aise sawaalon ka golden set banao jinhe visual content chahiye ("revenue chart mein Q3 ki value kya thi?", "photo mein kaunsa valve open dikh raha hai?") aur routes compare karo.

**Practical savdhaaniyaan.** Vision models charts mein chhote text aur numbers galat padh sakte hain; page ka citation maango aur jahan numbers matter karte hain, underlying data ho toh usse check karo. Images ko kaafi resolution par rakho.

**Content type ke hisaab se chunna:**

| Content | Behtar route | Kyun |
| --- | --- | --- |
| Text-heavy scans aur forms | OCR se text | Exact wording, sasta, searchable |
| Tables | Structured text mein extract | Precise answers ke liye rows aur headers bachte hain |
| Charts | Image route, ya dhyaan se likha description | Values aur trends picture mein hote hain |
| Diagrams aur drawings | Image route | Labels, positions aur connections matter karte hain |
| Photos | Image route | Caption mein detail predict karna mushkil hai |
| Slides | Image route | Layout ka matlab hota hai |

**Madad karne waale descriptions likhna.** Visuals ke liye text route use karo toh vision model se general caption nahi, woh maango jo users poochenge. Chart ke liye: title, axes, units, har labelled value aur main trend. Piping diagram ke liye: equipment tags, valve states aur connections. Har description ke saath page number store karo. Kuch pages par golden set se test kiya gaya focused description prompt image route ke saath ka kaafi gap query cost ke ek hisse mein bhar sakta hai.

**Evidence dikhana.** Visual content ke saath citation page ya slide ke thumbnail ki shakl mein zyada useful hai. Engineers aur analysts image par nazar daal kar answer confirm kar sakte hain, aur isse model ki kabhi-kabhi chhote numbers galat padhne ki galti bhi pakdi jaati hai.

**Code mein pages render karo aur visuals describe karo.** PyMuPDF PDF pages ko images mein badalta hai; vision model unhe focused prompt se describe karta hai:

```python
import base64
import fitz                                      # PyMuPDF
import anthropic

client = anthropic.Anthropic()
CHART_PROMPT = ("Describe this page for search. For each chart: title, axes and units, every labelled value, "
                "and the main trend. For tables: headers and every row. Quote numbers exactly as shown.")

def page_images(pdf_path, dpi=150):
    doc = fitz.open(pdf_path)
    for i, page in enumerate(doc, start=1):
        yield i, page.get_pixmap(dpi=dpi).tobytes("png")

def describe(png_bytes):
    r = client.messages.create(
        model="claude-sonnet-5-5", max_tokens=800,           # check the docs for current names
        messages=[{"role": "user", "content": [
            {"type": "image", "source": {"type": "base64", "media_type": "image/png",
                                         "data": base64.b64encode(png_bytes).decode()}},
            {"type": "text", "text": CHART_PROMPT}]}])
    return "".join(b.text for b in r.content if b.type == "text")

# Text route: store describe(png) with the page number, and index it like any other chunk.
```

Answer ke time wahi image block format image route ke liye top retrieved page images ko sawaal ke saath bhejne deta hai.

**Text queries se images retrieve karo.** Ek multimodal embedding model images aur text ko ek hi space mein rakhta hai:

```python
from PIL import Image
from sentence_transformers import SentenceTransformer

clip = SentenceTransformer("clip-ViT-B-32")
img_vecs = clip.encode([Image.open(p) for p in photo_paths], normalize_embeddings=True)
q = clip.encode(["rust on a flange joint"], normalize_embeddings=True)[0]
best = (img_vecs @ q).argsort()[::-1][:5]
```

Is tarah ke general models photos ke liye kaam karte hain. Text aur charts se bhare document pages ke liye, page retrieval ke liye train kiye gaye models (ColPali family ek jaana-maana example hai) kaafi behtar karte hain; dono ko apne golden set par test karo.

**Image tokens ka paisa lagta hai.** Vision model ko bheji gayi page image kaafi tokens ke roop mein bill hoti hai, lagbhag apne size ke anupaat mein. Top do-teen pages bhejo, das nahi, jahan ho sake relevant region tak crop karo, aur aisi resolution chuno jahan chhote numbers abhi bhi padhe ja sakein. Har route ke liye cost per question napo.

**Images se padhe numbers check karo.** Vision models kabhi-kabhi charts aur scans mein chhote digits galat padh lete hain. Jahan underlying data ho (chart ke peeche ki spreadsheet), uska link do aur compare karo; warna answer ke saath page thumbnail dikhao taaki users check kar sakein.

**Browser mein try karo.** Image inputs size ke hisaab se tokens lete hain. Alag-alag sizes par page images bhejne ki cost ka andaaza lagao.

```python
def image_tokens(width, height):
    return (width * height) / 750                 # a common rule of thumb; check your provider's docs

for w, h in [(1600, 2000), (1000, 1250), (800, 1000)]:
    t = image_tokens(w, h)
    print(f"{w}x{h}: about {t:,.0f} tokens per page, {3 * t:,.0f} for three pages")
```

## Ek example se samjho

Vadodara ki ek chemicals manufacturer chahti hai ki uske plant engineers 15 saal ki maintenance reports query kar sakein: scanned forms, equipment ki photos, piping diagrams aur root-cause reviews ke slide decks.

Aap dono routes ko 60 sawaalon par test karte ho:

- *Text mein badlo*: forms ke liye OCR, photos aur diagrams ke liye model ke likhe descriptions. 58% sahi. Failures: descriptions ne woh detail miss kar di jo engineers ne poochi, jaise kaunsa valve tag circle kiya gaya tha.
- *Image retrieval*: page images multimodal retriever se embed hui; top teen pages vision-language model ko gayi. 79% sahi. Failures: scans par chhote handwritten notes.

Aap ek hybrid ship karte ho: scanned forms OCR se jaate hain (unke text fields hi engineers search karte hain), jabki photos, diagrams aur slides images ki tarah retrieve hote hain. Answers page thumbnail dikhate hain taaki engineers check kar sakein. Query cost text-only route se lagbhag chaar guna hai, jo client un sawaalon par accuracy ki chhalaang ke liye accept karta hai jo unke liye sabse matter karte hain.

| 60 sawaalon par route | Sahi | Main failures | Query cost |
| --- | --- | --- | --- |
| Text mein badlo | 58% | Circle kiye valve tags jaisi details miss | 1 |
| Image retrieval | 79% | Chhote handwritten notes | Lagbhag 4 |
| Content type ke hisaab se hybrid | Ship hua | Forms ke liye OCR, photos aur diagrams ke liye images | Dono ke beech |

## Aam galtiyaan

- **Visual content ko ignore karna.** Text-only pipelines charts aur photos ko chupchaap skip kar dete hain.
- **Chart readings par zyada bharosa.** Vision models chhote numbers galat padhte hain; pages cite karo aur key values check karo.
- **Low-resolution images.** Details gaayab ho jaati hain; poochhe gaye sawaalon ke hisaab se kaafi resolution rakho.
- **Golden set mein visual sawaal na hona.** Phir pata nahi chalta ki multimodal kaam se madad mili ya nahi.
- **Sab kuch ke liye image route.** Text-heavy documents text ki tarah sasta aur aksar behtar hote hain.
- **Charts aur diagrams ke liye generic captions.** Woh values aur labels maango jo users ko chahiye honge.
- **Har sawaal par kai full-resolution pages bhejna**, jo dheema aur mehnga hai.
- **Document pages ke liye photo model use karna.** Ek page-retrieval model bhi test karo.

## Jab text-only RAG kaafi hai

- **Visuals wahi dohraate hain jo text kehta hai**, jaise kai reports mein jahan charts bataye gaye numbers ko illustrate karte hain.
- **Tables ko PDF parser saaf-saaf** text mein extract kar sakta hai.
- **Kam sawaalon ko visuals chahiye**, toh kuch key pages ko haath se describe karna sasta hai.

## Demo se production tak

- **Har description aur retrieved image ke saath page numbers aur thumbnails rakho.**
- **Route ke hisaab se cost per query track karo**, image tokens shaamil karke.
- **Pages ko dobara describe karo** jab description prompt behtar ho, aur descriptions ko version karo.
- **Ek visual golden set rakho** aur models badalne par use dobara chalao.
- **Users ko galat padhe numbers flag karne do**, aur unhe test set mein jodo.
