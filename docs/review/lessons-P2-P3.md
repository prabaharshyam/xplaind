## Flagged for the owner

1. **executive-communication.mdx: value against cost.** After the correction, time saved is worth about ₹50 lakh a year. The memo's run cost is about ₹9 lakh a month, which is about ₹1.08 crore a year. On time saved alone, the system now costs more than it saves. The memo still works because the freed time lets the lender "handle 25% more applications without new hiring". That avoided hiring is the larger value, but the memo does not put a number on it. You need to decide whether to add an avoided-hiring figure, lower the ₹9 lakh cost (it also appears in fde-case-study.mdx), or reframe. I did not invent a new figure.
2. **The Chennai lender timeline differs between lessons.** poc-pilot-production.mdx has the POC in weeks 1–4, the pilot in weeks 5–14 and production from week 15. fde-case-study.mdx has discovery in weeks 1–2, the POC in weeks 3–6, the pilot in weeks 7–16 and production in weeks 17–26. scope-of-work.mdx says "POC gate wk 4 → pilot gate wk 14". One reading is that the weeks count from the start of the build rather than the engagement, but nothing says so. The collections request also arrives "three weeks in" (scope-of-work) and in "week 7" (managing-scope-creep). Please pick one timeline.
3. **The Chennai lender baseline wobbles.** client-discovery.mdx says 40 minutes per application, and the related check (client-discovery-2) also says 40. kpi-that-matters, fde-case-study, demos and executive-communication say 41. This can be read as a discovery estimate followed by a measured baseline, so I left it alone.
4. **ai-cost-of-ownership.mdx: the crossover point.** It says self-hosting becomes cheaper at "roughly three times current volume". The self-hosted option was sized at four GPUs for current peak load. At three times the volume it would need more GPUs, so the crossover is probably higher than stated or needs explaining. The figures are labelled illustrative, so I left them.
5. **Real public bodies in exercise setups.** "A Bhopal state health department" (ai-system-design exercise) and "a Lucknow exam board" (latency-load-testing exercise) point closely at real bodies. They are written as hypotheticals, not past events, so I left them. You may prefer neutral wording.
6. **vllm-open-weights.mdx: example model.** The code example uses `Qwen/Qwen2.5-7B-Instruct`. The model is real and the `vllm serve` flags shown (`--max-model-len`, `--gpu-memory-utilization`, `--tensor-parallel-size`, `--quantization`) are valid vLLM options, but by late 2026 this model is an older generation. Consider a newer small instruct model. I did not run the command.
7. **Batch-discount wording.** batching-model-tiering.mdx says "often around half the normal price" and "within hours". I confirmed that Anthropic's Message Batches API gives 50% off with results in under 24 hours (https://platform.claude.com/en/docs/build-with-claude/batch-processing). I found only second-hand sources for OpenAI's and Google's 50% batch discounts. "Within hours" is accurate but can mean up to 24 hours. The wording is durable enough, so I left it.
