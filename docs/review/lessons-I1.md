## Flagged for the owner

1. **cicd-github-actions.mdx**: the workflow pins `actions/checkout@v4` and `astral-sh/setup-uv@v6`. These still run but are older majors. The GitHub releases page showed checkout v7 as latest, and AWS's own docs use v6. A WebFetch summary reported setup-uv v10, which I could not confirm, because GitHub API access is blocked in this session. Decide whether to bump the pins or leave them.
2. **first-llm-api-call.mdx**: the flashcard "max_tokens caps how long the reply can be" and the `max_tokens=300` example. On current Claude models, thinking tokens count towards `max_tokens`, so a low cap can cut off a reply that has a thinking block. The lesson does not mention this. Consider one sentence, or a higher cap.
3. **first-llm-api-call.mdx** and **tokens-and-context.mdx**: the per-token rupee prices (₹0.0002 / ₹0.0008, ₹0.0003 / ₹0.0015) are labelled "assume". They are plausible against current list prices, for example Sonnet 5.5 at $2 / $10 per million tokens, but they are not real quotes. I left them as illustrative.
4. **cloud-fundamentals.mdx**: "RBI-regulated firms have strict rules" on data residency, in the exercise. RBI's hard localisation mandate (2018) is for payment system data. For other NBFC data the rules come through outsourcing and IT directions and are less absolute. The wording is vague, not wrong, but a person may want it tightened.
5. **trees-boosting.mdx**: I applied RBI's written-rejection-reasons rule to a digital lender, which is usually an NBFC. The circular I found is addressed to banks and financial institutions. I could not open the NBFC Scale Based Regulation text to confirm the same wording applies to NBFCs.
6. **errors-retries-cost.mdx** and question **errors-retries-cost-2**: "529 overloaded" is Anthropic-specific. The lesson presents it as generic ("provider overloaded errors"). It is fine, but other providers use 503.
